 ## 解決策
 ## 問題の理解

 1 列に配置された 3 つのカードの束が与えられ、最初の束には次のものが含まれます。`a`カード、2枚目`b`カード、そして3枚目`c`カード。 数字は満たす`a < b < c`。 Monocarp は、3 番目のスタックから任意の正の数のカードを取得できます。`c`カードを分割し、最初の 2 つのスタック間で再分配します。 目標は、再配布後に 3 つのスタックすべてに同じ数のカードが含まれるようにすることです。 

入力は複数のテスト ケースで構成され、それぞれがカウントを指定します。`a`、`b`、 そして`c`。 各テスト ケースの出力は、均等な分散が可能な場合は「YES」、そうでない場合は「NO」になります。 

それぞれだから`a`、`b`、 そして`c`と同じ大きさにすることができます$10^8$まであります$10^4$テスト ケースでは、テスト ケースごとに一定時間で機能するソリューションが必要です。 3 番目のデックのすべての可能な再配布を繰り返すと遅すぎるため、最大パフォーマンスが低下する可能性があります。$10^8$ケースごとの反復回数。 

単純な実装では、3 番目のデッキから最初の 2 つのデッキに移動したカードを可能な限りすべての枚数試行する可能性がありますが、それはタイムアウトになってしまいます。 もう 1 つの微妙な落とし穴は、カードの総数が 3 で均等に割り切れるかどうかを確認できないことです。 たとえば、次の場合`a=3, b=5, c=10`、合計は 18 で、これを 3 で均等に割ると、次の値に達することができます。`6`各スタックのカード。 合計が 19 の場合、再配分は機能しません。 

## アプローチ

 ブルートフォースアプローチには、次のようなアプローチが含まれます。`x`3番目のデッキからカードを配布します`y`最初のデッキへ、そして`x-y`2番目のデッキに移動し、`a+y = b+x-y = c-x`。 それぞれの可能性について`x`1との間`c`、そしてそれぞれ`y`0から`x`、これには最大で$O(c^2)$小切手。 これは理論的には正しいですが、可能な最大値は`c`は$10^8$、この方法は実行不可能になります。 

重要な観察は、各デッキの最終的な価値を次のように呼びます。`target`、同じでなければなりません。 再配布後のカードの総数は変わりません。`a + b + c`。 3 つのデッキがすべて同じになった場合、その数は 3 で割り切れる必要があります。 それで`target = (a + b + c) / 3`。 もし`(a + b + c)`は 3 で割り切れないので、すぐには不可能です。 

わかったら`target`、ターゲットと最初の 2 つのデッキの差が最大でも次であることを確認する必要があるだけです。`c`, なぜなら、3番目のデッキはそれだけのカードを供給できるからです。 より正式には、次のようにする必要があります`(target - a) + (target - b) = 2*target - (a+b) = target - c`、これはまさに 3 番目のデッキから取り出すカードの数です。 以来`target <= c`（なぜなら`c`が最大です）、これは機能します。 そうでなければ不可能です。 

この観察により、問題は単純な算術チェックに帰着し、テスト ケースごとに一定時間で機能します。

 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースの値を読み取ります。`a`、`b`、 そして`c`。 
2. 3 つのデッキすべてのカードの合計数を計算します。`total = a + b + c`。 
3. 次のことを確認します。`total`割り切れない場合は、「NO」を出力し、次のテスト ケースに進みます。 これは、均等に分配するには、合計を 3 つのデッキに均等に分割する必要があるためです。 
4. デッキごとのカードの目標枚数を計算します。`target = total // 3`。 
5. 最大のデッキかどうかを確認します。`c`、少なくとも含まれています`target`カード。 からカードを削除することしかできないため、`c`、 もし`target > c`、同等のデッキを達成することは不可能です。 この場合は「NO」を出力します。 
6. それ以外の場合は「YES」を出力します。 再配布はいつでも割り当てることができます`target - a`カードを最初のデッキに入れ、`target - b`カードを 2 番目のデッキに正確に取り込みます`(target - a) + (target - b)`3番目のデッキからのカード。 

なぜ機能するのか: 不変条件は、到達する必要があるということです`target`各デッキのカード。 和の割り算により次のことが保証されます。`target`は整数です。 小切手`target <= c`3 番目のデッキには、最初の 2 つのデッキに供給するのに十分なカードが確実に含まれます。 このロジックは、考えられるすべての再配布をシミュレートすることなく、正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c = map(int, input().split())
    total = a + b + c
    if total % 3 != 0:
        print("NO")
        continue
    target = total // 3
    if target > c:
        print("NO")
    else:
        print("YES")
```コードは最初にテスト ケースの数を読み取ります。 ケースごとに、3 つのデッキの合計が計算されます。 合計が 3 で割り切れない場合は、「NO」が出力されます。 それ以外の場合は、ターゲットのデッキ サイズを計算し、最大のデッキが必要なカードを供給できるかどうかを確認します。 この実装では、整数の除算と単純な比較を使用するため、浮動小数点エラーのリスクが回避されます。 このソリューションは、再配布されるカードの必要数がゼロになる可能性がある特殊なケースに対処します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        a, b, c = map(int, input().split())
        total = a + b + c
        if total % 3 != 0:
            print("NO")
            continue
        target = total // 3
        if target > c:
            print("NO")
        else:
            print("YES")
    return output.getvalue().strip()

 ## 特殊なケース

 の合計の場合、`a + b + c`は 3 で割り切れますが、3 番目のデッキに十分なカードがない場合、アルゴリズムは正しく「NO」を出力します。 例えば、`a=1, b=2, c=2`もっている`total=5`、3で割り切れますか？ いいえ、したがって出力は「NO」になります。 のために`a=1, b=2, c=4`、`total=7`、3で割り切れない、やはり「NO」。 これらのケースにより、可分性条件と十分性条件の両方を正しく処理できるようになります。 最大のデッキは常に`c`は入力制約によって保証されているため、他の順列をチェックする必要はありません。
