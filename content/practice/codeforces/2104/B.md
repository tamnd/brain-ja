 ## 解決策
 ## 問題の理解

 可能なすべての長さの整数の配列が与えられます。$k$1から$n$、最後の合計を最大化したいと考えています。$k$選択した **1** 要素を配列の最後に移動した後の要素。 その要素を選択して移動した後、次のクエリのために配列を復元します。 基本的に、「最後に移動」操作を 1 回許可する場合、最後の操作の最適な合計はいくらか、と尋ねられます。$k$あらゆる要素$k$?

 制約が示すのは、$n$到達できる$2 \cdot 10^5$まであります$10^4$テストケースの合計$n$すべてのテスト ケースの境界は次のとおりです$2 \cdot 10^5$。 これは、線形アルゴリズムが必要であることを意味します。$n$テストケースごとに。 すべての要素の移動をシミュレートするあらゆるアプローチ$k$だろう$O(n^2)$そして明らかに遅すぎます。 

すべての要素が等しい場合、明白でないエッジ ケースが発生します。$n=1$、または最大要素が先頭または末尾にある場合。 たとえば、入力の場合`[7, 5]`、の合計$k=2$合計を最大化するには最初の要素を選択する必要があります。 単純に最後の値を合計するだけであれば、$k$動きを考慮せずに要素を配置すると、間違った結果が得られます。 

## アプローチ

 ブルートフォースアプローチでは、それぞれを反復することになります。$k$すべての要素を最後まで移動して、最後の要素を合計することをシミュレートします。$k$毎回の要素。 これは、可能なすべての手を評価するため、原理的には機能しますが、その時間計算量は次のとおりです。$O(n^2)$、次の場合に 2 秒の制限を超えます。$n$大きいです。 

効率的なソリューションを実現するための重要な洞察は、要素を最後に移動しても最後の要素にのみ影響することを理解することです。$k$既存の最後の要素の一部よりも大きい場合は要素。 配列を降順に並べ替えると、要素の移動による潜在的な影響が取り込まれます。 降順にソートされた配列のプレフィックスの合計を計算すると、$k$最大の要素は、単一の要素を最後に移動することによって達成できる最大合計に正確に対応します。 これは、それぞれの場合に機能するため、$k$、現在の最後のいずれか$k$要素には最大のものが含まれます$k$または、最後の数字にまだ入っていない最大の数字を移動することもできます。$k$最後まで合計を改善します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 テスト ケースごとに、次の内容を読んでください。$n$そして配列$a$。 
2. Sort the array$a$非昇順で最大の要素を最初に優先します。 これにより、任意のプレフィックス長の合計を最大化する要素を特定できます。 
3. ソートされた配列のプレフィックスの合計を計算します。 インデックスのプレフィックスの合計$i$最初の合計を格納します$i+1$最大の要素。 このプレフィックスの合計は、最後のプレフィックスの最大合計を直接示します。$k=i+1$要素。 
4. プレフィックスの合計を順番に出力します。 各エントリは、対応するエントリの最大合計を表します。$k$。 

機能する理由: 並べ替えにより、どの要素が最後の要素に最も貢献しているかを常に知ることができます。$k$ポジション。 プレフィックスの合計により、すべての要素に対して最適な要素のサブセットが考慮されていることを保証します。$k$。 配列はクエリのたびに復元されるため、移動をシミュレートする必要はありません。 ソートされた順序は、達成可能な最大合計を決定するのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort(reverse=True)
        prefix = []
        current = 0
        for num in a:
            current += num
            prefix.append(current)
        print(' '.join(map(str, prefix)))

if __name__ == "__main__":
    solve()
```コードは複数のテスト ケースを読み取ります。 配列ごとに、降順に並べ替えてプレフィックスの合計を計算します。 プレフィックスの合計は、それぞれの最大合計に直接対応します。$k$なぜなら最大の$k$数値は常に最適な結果をもたらします。

 ## 特殊なケース

 要素が 1 つの配列の場合`[42]`、$k=1$は自明に 42 です。ソートでは単一要素の配列は変更されず、プレフィックスの合計は単に要素自体であるため、アルゴリズムはこれを処理します。 すべての要素が等しい配列の場合、次のようになります。`[10, 10, 10]`、の最大合計$k$いつもです$10 \times k$、そしてプレフィックスの合計はこれを正しく反映しています。 最大の要素が先頭または末尾にある場合、ソートされたプレフィックスの合計により、常に最大の要素が最初にカウントされ、すべての要素の正しい合計が自動的に生成されます。$k$。
