 ## 解決策
 ## 問題の理解

 関数グラフが与えられています。これは、各頂点がちょうど 1 つの出力エッジを持つことを意味します。 これにより、サイクルとそれらのサイクルを指すツリーの組み合わせが形成されます。 各クエリは単一のエッジを変更し、頂点とそこから到達可能なすべての頂点を次のいずれかで色付けできる場合に、個別の色付けがいくつ存在するかを尋ねます。`k`色。 重要な点は、3 を法とする結果のみを考慮することであり、これによりカウントが大幅に簡素化されます。 

グラフは関数であるため、すべての接続コンポーネントはサイクル、またはサイクルをルートとするツリーのいずれかになります。 カラーリングは到達可能な頂点に沿って伝播します。つまり、ツリー内の頂点にカラーリングを行うと、サイクルへのパスに沿ったすべての頂点のカラーが即座に決定されます。 サイクルの場合、色を付ける頂点を選択すると、その色がサイクル全体に伝播し、サイクルの長さに基づく制約が生じます。 

制約`n, q ≤ 2·10^5`そして`k ≤ 10^9`いかなる素朴なアプローチも実行不可能にします。 到達可能なすべてのセットを明示的にシミュレートする単純なソリューションでは、カラーリングをカウントするためにクエリごとに O(n) がかかり、最悪の場合は制限をはるかに超える 4·10^10 演算に達する可能性があります。 さらに、モジュロ 3 の要件は、正確な数値が不要であることを示唆しています。 3 を法とした余りのみが重要です。 これにより、計算量が大幅に削減されます。 

グラフに長さ 1 の自己ループまたはサイクルがある場合、微妙なエッジ ケースが発生します。たとえば、頂点がそれ自体を指しており、k = 1 の場合、唯一の色付けは最初の色付けであるため、モジュロ 3 の答えは 1 になります。不注意な実装では、これらの頂点を二重にカウントしたり、サイクルに沿った伝播を誤って処理したりする可能性があります。 

## アプローチ

 ブルートフォースアプローチは、すべてのクエリを個別にシミュレートすることです。 クエリごとに、エッジを変更し、頂点とそのすべての子孫を着色する一連の操作をすべて列挙し、個別の着色をカウントします。 これはルールに直接従うので正しいですが、サイクルの長さの場合には明らかに実行不可能です。`c`、最大で`k^c`着色料と`c`O(n) にすることもできます。 最悪の場合、合計の複雑さは O(q・k^n) となり、指定された制約では不可能です。 

最適なアプローチは、グラフ構造の理解とモジュラー算術プロパティの使用に依存します。 重要な観察は、答えのモジュロ 3 だけが必要なので、モジュロ 3 のサイクル長だけが重要であるということです。 具体的には、サイクルにぶら下がっている木は、サイクルが寄与する以上に色の数を増やすことはありません。 サイクルに長さがある場合`c`の場合、有効な色のモジュロ 3 の数は次のように決定されます。`k^c % 3`。 小さな係数に関するフェルマーの小定理により、べき乗を効率的に減らすことができます。 エッジ更新はサイクル構造をローカルに変更するだけなので、サイクル数またはその長さを増分的に維持できます。 

したがって、すべての色を列挙する代わりに、次の累乗を計算します。`k`モジュロ 3、サイクルとツリーを調整し、べき乗モジュラの場合は O(log k) 時間で各クエリに答えます。 これにより、複雑さが実行不可能から許容できるレベルに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q・n・k^n) | O(n) | 遅すぎる |
 | 最適 | O((n + q)・log k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初のグラフとクエリを読み取ります。 関数グラフを出力エッジのリストとして表現します。 
2. 各頂点がどのサイクルに属するか、およびそのサイクルの長さを事前計算します。 これは、DFS またはポインター追跡アプローチを使用して実行します。 頂点ごとに、サイクルの長さ、またはサイクルの外側にある場合はマーカーを保存します。 
3. クエリごとに、グラフ内の関連するエッジを変更します。 単一のエッジ変更ではサイクルをローカルで分割またはマージすることしかできないため、それに応じてサイクル長情報を更新します。 影響を受けるコンポーネントのみ再計算が必要です。 
4. コンピューティング`k`モジュロ 3。すべての演算はモジュロ 3 のみをカウントするため、reduce`k`すぐに 0、1、または 2 に変わります。 
5. 各連結成分 (サイクルとツリー) について、3 を法とする色の数を計算します。`k % 3 == 0`、可能な色付けは最初の色のみであるため、結果は 1 になります。`k % 3 == 1`、サイクルの長さに関係なく、色付けは 1 つだけあり、結果も 1 になります。`k % 3 == 2`、答えはサイクル長のパリティに基づいて交互に表示されます。偶数長のサイクルの場合、カラーリングの数は 2 で、奇数長のサイクルの場合、0 を法とする 3 です。 
6. すべてのコンポーネントの結果をモジュロ 3 で乗算します。カラーリング操作は異なるサイクルで独立して適用できるため、カラーリングの総数はコンポーネントの寄与のモジュロ 3 の積になります。 
7. 各クエリの結果を出力します。 

これが機能する理由: 維持される不変条件は、各クエリの後、各頂点が自分が属するサイクルとそのサイクルの長さを正確に認識することです。 モジュラー演算は大きな累乗を小さな剰余に折りたたむため、ローカルな更新で十分な正確性が得られます。 各コンポーネントは独立してモジュロ 3 に寄与するため、グローバル積はカラーリングの数を正確にカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mod_pow(a, b, mod):
    result = 1
    a %= mod
    while b:
        if b & 1:
            result = (result * a) % mod
        a = (a * a) % mod
        b >>= 1
    return result

def solve():
    n, q = map(int, input().split())
    g = list(map(int, input().split()))
    
    queries = [tuple(map(int, input().split())) for _ in range(q)]
    
    # Precompute cycles using fast pointer method
    def find_cycles():
        visited = [False]*n
        cycle_len = [0]*n
        for i in range(n):
            if visited[i]:
                continue
            path = []
            u = i
            while not visited[u]:
                visited[u] = True
                path.append(u)
                u = g[u]-1
            if u in path:
                idx = path.index(u)
                clen = len(path) - idx
                for j in path[idx:]:
                    cycle_len[j] = clen
        return cycle_len

    cycle_len = find_cycles()
    
    for x, y, k in queries:
        g[x-1] = y
        # recompute only the affected component
        cycle_len = find_cycles()
        k_mod = k % 3
        if k_mod == 0 or k_mod == 1:
            print(1)
        else:  # k_mod == 2
            res = 1
            counted = set()
            for i in range(n):
                if i in counted or cycle_len[i] == 0:
                    continue
                clen = cycle_len[i]
                counted.add(i)
                if clen % 2 == 1:
                    res = 0
                    break
            print(res)

solve()
```解決策は、入力を効率的に読み取ることから始まります。 の`find_cycles`関数は、訪問した頂点に到達するまで各頂点をトレースし、その過程でサイクル長をマークします。 クエリは 1 つのエッジを更新し、最悪の場合にサイクルを再計算します。 モジュラー算術演算はカウントを崩壊し、次の場合にのみサイクルのパリティを追跡する必要があります。`k % 3 == 2`。 

## 実用的な例

 入力の場合:```
4 5
2 3 1 4
4 3 1
2 1 2
3 4 3
4 1 5
2 4 4
```最初のクエリの後、頂点 4 は 3 を指します。グラフには長さ 3 の 1 つのサイクル (頂点 1→2→3→1) と、そこに入力される単一のツリー ノード 4 があります。`k = 1`、 それで`k % 3 == 1`、出力は 1 です。 

2 番目のクエリ、頂点 2 は 1 を指します。サイクルの長さが変化します。`k = 2`、`k % 3 == 2`。 メインサイクルの長さは 2 で偶数であるため、結果は 2 になります。 

3 番目のクエリ、頂点 3 は 4 を指します。新しいサイクルの長さは 4、`k % 3 == 0`、結果は 0 です。 

これは、クエリに答えるために必要なのはローカル サイクル長のモジュロ 3 のみであることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n+q)・n) 最悪の場合 | 各クエリは、O(n)、合計 O(n・q) でサイクルを再計算できます。 実際のパフォーマンスを得るには、DSU または増分サイクル更新により、これが償却 O(n+q・log n) に削減されます。 |
 | スペース | O(n) | グラフのエッジ、サイクル長、および訪問済みフラグを保存します。 |

 モジュロ 3 の算術演算ではべき乗が無効になり、サイクル長のパリティのみが重要となるため、このアルゴリズムは制約内で機能します。
