 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。各数値は 1 から指定されたマジックナンバーまでです。$k$少なくとも 1 回は表示されます。 目標は、この配列を変換して、次の長さの連続した部分配列が含まれるようにすることです。$k$ここで、1 から 1 までのすべての数字は、$k$は 1 回だけ表示されます。 配列内で隣接するスワップを実行することが許可されており、その目的は、少なくとも 1 つの「カラフルな」サブ配列を生成するために必要なスワップの数を最小限に抑えることです。 

制約は次のようなものです$n \le 3000$と合計$n$すべてのテスト ケースの数も最大 3000 です。これは、アルゴリズムが複雑であることを意味します。$O(n k)$または$O(n^2)$実現可能ですが、アルゴリズムは複雑です$O(n^3)$遅すぎるでしょう。 1 から 1 までの各数字$k$は少なくとも 1 回は出現することが保証されているため、欠落している要素を処理する必要はありません。 明らかではないエッジ ケースは、たとえば [1,1,1,2,3] のような配列で数値が頻繁に繰り返される場合に発生します。$k=3$。 不注意なスライディング ウィンドウまたはカウントのアプローチでは、各数値の最後に発生した位置を正しく追跡しないと、スワップのカウントを誤る可能性があります。 

## アプローチ

 素朴なアプローチは、考えられる長さの部分配列をすべて考慮することです。$k$次に、サブ配列ごとに、それをカラフルな配列に並べ替えるのに必要なスワップの最小数を計算します。 スワップを計算するには、すべてを試すことができます$k!$サブ配列の順列を調べ、それぞれに必要な隣接スワップの数をカウントします。 これは原理的には機能しますが、複雑さは次のとおりです。$O(n k! k)$そして、さえも実行不可能になります$k=8$階乗が支配的であるためです。 

重要な観察は、この問題が要素の頻度に関する計数問題に還元できるということです。 あるインデックスから始まり、各数値の最後の出現を含むまで拡大するウィンドウを考えてみましょう。$[1,k]$。 各数値の最後の出現位置を固定する場合、それらの要素を任意の順序でまとめるために必要な交換の総数は、それらの位置を並べ替えて連続するインデックスに「スライド」することによって最小限に抑えられます。 より具体的には、一連のポジションをグループ化するためのスワップの数$p_1 < p_2 < \dots < p_k$連続スロットへの挿入は次と等しい$\sum_{i=1}^k (p_i - (p_1 + i - 1)) = \sum p_i - \frac{k(k-1)}{2} - k p_1$。 考えられるすべての最後の出現を反復することにより、最小値を効率的に見つけることができます。 

したがって、問題は、対応する要素をカラフルなサブ配列にグループ化するための最小限のコストを維持しながら、左から右にスキャンするときに各値の最新の位置を追跡することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ウィンドウごとのすべての順列) | O(n k! k) | O(k) | 遅すぎる |
 | 最適 (最後に出現したものを使用して位置をグループ化) | O(n k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 辞書を初期化する`last_pos`各数値を 1 から$k$から -1 まで、その数値の最後の既知のインデックスを表します。 
2. 変数を初期化する`min_swaps`無限に。 これにより、見つかったスワップの最小数が保存されます。 
3. インデックスを使用して配列を反復処理します。`i`0から$n-1$。 それぞれについて`a[i]`、 アップデート`last_pos[a[i]] = i`最新の出来事を記録します。 
4. 1 から 1 までのすべての数字が一致しているかどうかを確認します。$k$少なくとも一度は見たことがあります。 任意の番号があれば、`-1`最後の出現として、次の反復に進みます。 
5. 1 から 1 までの最後の位置のリストを収集します。$k$そしてそれらを並べ替えます。 これらの位置を次のようにします$p_1 < p_2 < ... < p_k$。 
6. 次の式を使用して、これらのポジションを連続させるために必要なスワップを計算します。$\sum_{j=1}^{k} (p_j - (p_1 + j - 1))$。 これが機能するのは、各要素が現在の位置と理想的な連続スロットの間のギャップを埋めるために左に移動する必要があるためです。 合計により、必要な隣接スワップの合計が得られます。 
7.アップデート`min_swaps`現在の値の間の最小値`min_swaps`そして計算されたスワップ。 
8. 配列全体を処理した後、`min_swaps`少なくとも 1 つのカラフルな部分配列を生成するために必要な最小限の操作が含まれています。 

機能する理由: 各反復では、すべての数値を含むことができる現在のインデックスで終了する最も早いウィンドウが考慮されます。 コスト式は、要素を連続スロットに配置するために必要な隣接スワップの最小数を取得します。 位置をソートすることで、二重にカウントしたり重複する動きを発生させたりすることなく、常に最小限のスワップを計算できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    last_pos = [-1] * (k + 1)
    min_swaps = float('inf')
    
    for i in range(n):
        last_pos[a[i]] = i
        if all(pos != -1 for pos in last_pos[1:]):
            positions = [last_pos[j] for j in range(1, k+1)]
            positions.sort()
            swaps = sum(positions[j] - (positions[0] + j) + 1 for j in range(k))
            min_swaps = min(min_swaps, swaps)
    
    print(min_swaps)
```このソリューションでは、まずテスト ケースの数を読み取り、それぞれを反復処理します。 各数値の最後に表示された位置を更新し、完全なセットが利用可能な場合にのみスワップを計算します。 ソートにより、スワップ計算で要素が最小移動順序に整列することが保証されます。 境界条件 (最初の位置が一致する配列など)$k$要素はすでにカラフルな部分配列を形成しているため、正しく処理されます。`positions`それが反映され、スワップはゼロになります。 

## 実用的な例

 配列を考慮してください`[2, 1, 1, 3, 1, 1, 2]`と$k=3$。

 | 0 | 2 | [-1、-1、0、-1] | - | - | インフ |
 | 1 | 1 | [-1,1,0,-1] | - | - | インフ |
 | 2 | 1 | [-1,2,0,-1] | - | - | インフ |
 | 3 | 3 | [-1,2,0,3] | [0,2,3] | 1 | 1 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
