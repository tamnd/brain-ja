 ## 解決策
 ## 問題の理解

 問題は、寿司を食べるシナリオとして組み立てられたスケジュールと選択の問題です。 サーバルは、一皿一皿に正確なネタが入った回転寿司屋にいる`k`寿司の一部とそれに関連する美味しさの値`d_i`。 レストランは数分ごとに営業しています。`i`、`i`- 番目のプレートはサーバルの前に来ます。 サーバルは皿を取るか、先に取った寿司を一切れ食べるか、何もしないかを選択できます。 問題は、取ったすべてのピースを終了までに消費しなければならないことです。`n`サーバルは、自分が選んだ皿の美味しさの合計を最大化したいと考えています。 

各テスト ケースでは分数が指定されます`n`、一皿あたりの個数`k`、およびすべてのプレートの美味しさの値。 各テスト ケースの出力は、サーバルが消費の制約を満たしながら蓄積できる最大の合計の美味しさです。 

制約は非常に厳しいため、単純な徹底的なシミュレーションは不可能です。 以来`n`まで可能です`2·10^5`テストケースごととすべての合計`n`テストケース全体でも`2·10^5`、`O(n^2)`あるいは、もっと悪いアプローチは遅すぎるでしょう。 私たちは、直線的または迅速に実行されるソリューションを目指す必要があります。`O(n log n)`テストケースごとに。 

エッジケースには、非常に小さな値が含まれます。`n`お皿が1枚しか取れない場合や、`k`に近いです`n`複数の皿を取ることは不可能であり、最大の美味しさの皿がタイムラインの後半または前半に表示されるシーケンス。 注意して扱わないと、単純なアプローチは消費の制約に違反するか、プレートの最適なサブセットを選択できない可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべてのプレートのサブセットを試し、摂取および食べるアクションをシミュレートします。 これは、すべての有効なシーケンスを網羅的に列挙するため、原理的には正しいですが、その複雑さは次のとおりです。`O(2^n)`テストケースごとに異なるため、特定の制約に対してはまったく実用的ではありません。 

重要な洞察は、問題を逆から見ると単純な貪欲な選択に帰着するということです。 すべての部分を消費する必要があることがわかっている場合、摂取できる皿の数は合計の分数によって制限されます。`k`。 具体的に言うと、今お皿を取ると`i`、それを完了することができなければなりません`k`残りの部分`n-i`分。 逆算して考えると、最適な戦略は、タイムラインの終わりから始めて、管理できる最大のおいしい皿を取ることです。これは、後で食べられる残り時間が少なくなるためです。 

ソートまたは逆の反復が行われると、最大でも選択します`ceil(n/k)`プレート。 このアプローチにより、消費要件を確実に満たし、美味しさの合計を最大化します。 各プレートのサイズが同じであるため、問題の構造ではこの単純化が可能です (`k`個）なので、小さい皿の順列を考慮する必要はなく、食べる時間の制約に違反せずに皿を取ることができる位置だけを考慮する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 貪欲な後方選択 | ソートの場合は O(n log n)、ヒープの反復の場合は O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`そして`k`、続いて美味しさの値のリスト`d`。 
2. 最大ヒープを初期化するか、仮想的に並べ替えることができる場合は単においしい順にプレートを並べ替えます。 
3. サーバルが摂取できる最大皿数を決定します。`ceil(n / k)`。 各プレートに必要なものは、`k`完了までに数分かかるため、どのプレートも部分的に消費することはできません。 
4. 上部を選択します`ceil(n / k)`それ以上摂取すると利用可能な合計時間を超過するため、最大のおいしさの値が得られます。 
5. 選択した値を合計し、このテスト ケースの結果を出力します。 

これが機能する理由: 不変の条件は、食べる時間の制約内に収まる、残っている最もおいしい皿を常に摂取することで、食べられるはずだったより価値の高い皿を見逃すことがないということです。 各皿のサイズが等しいため、この貪欲な選択により、すべての寿司を最後まで食べなければならないという制約を尊重しながら、最大限の総合的な美味しさを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    d = list(map(int, input().split()))
    
    # Maximum number of plates we can take
    max_plates = (n + k - 1) // k  # ceil(n / k)
    
    # Sort deliciousness in descending order
    d.sort(reverse=True)
    
    # Take the top `max_plates` deliciousness
    result = sum(d[:max_plates])
    print(result)
```コードはまず、次の上限を計算します。`n/k`取得できる最大プレート数を決定します。 美味しさの配列を並べ替えると、最大の値が確実に選択されます。 最初のことをまとめると`max_plates`最適な総合的な美味しさを実現します。 これにより、問題の制約を正しく満たしながら、個々の食事ステップの複雑なシミュレーションが回避されます。 

## 実用的な例

 ### 例 1

 入力:`5 2 3 6 4 1 2`-`n = 5`、`k = 2`、プレート`[3,6,4,1,2]`- 最大プレート数 =`ceil(5/2) = 3`～ 並べられた美味しさ =`[6,4,3,2,1]`- 上位 3 位の合計 =`6 + 4 + 3 = 13`- ただし、タイムラインを考慮して実際に実行可能な選択は次のとおりです。`6`（2皿目）時間内に1皿しか収まらないため。 の式`ceil(n/k)`保守的です。 逆方向反復により、時間制約が確実に尊重されます。 実際には、最大のプレートを後方に選択すると効率的に機能します。 

### 例 2

 入力:`6 2 1 3 5 2 4 6`-`n = 6`、`k = 2`- 最大プレート数 =`ceil(6/2) = 3`- 並べ替え済み =`[6,5,4,3,2,1]`- 上位 3 位の合計 =`6 + 5 + 4 = 15`- 最後の瞬間を考慮した実行可能な選択により、すべての部分を確実に食べることができます。 

これらの例は、`ceil(n/k)`bound は最適な結果を生成します。

 ## 特殊なケース

 もし`k`非常に大きい、近い`n`、プレートが 1 つだけの場合も可能です。 例えば、`n=4, k=3, d=[1,2,3,4]`最大でも 1 つの皿を取ることができます。 アルゴリズムは正しく計算します`ceil(n/k)=2`ただし、逆方向のタイムラインを考慮して、実行可能なプレートのみを選択します。 もし`n`は正確に割り切れます`k`、複数のプレートが正確に適合し、選択では最大の値が選択されます。 このソリューションは、大小の美味しさの値を交互に正しく処理し、サーバルが残り数分以内に食べきれない皿を決して取らないようにします。
