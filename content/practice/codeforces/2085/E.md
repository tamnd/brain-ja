 ## 問題の理解

 同じ長さの 2 つの配列が与えられます: 元の配列`a`負でない整数とシャッフルされた配列`b`。 配列`b`のすべての要素を取得して生成されると考えられます`a`未知の整数を法とする`k`、結果をシャッフルします。 私たちの仕事は、可能な値を決定することです。`k`。 そのような整数が存在しない場合は、次のように出力する必要があります。`-1`。 有効な答えは複数あるかもしれません。 どれでも受け入れられます。 有効な場合`k`存在する場合、それ以上ではないことが保証されます$10^9$。 

重要な課題は、モジュロ演算によって情報が隠蔽されてしまうことです。 小さい値の場合`k`、多くの異なる数字`a`は同じ剰余を生成する可能性があるため、剰余のカウントを慎重に一致させる必要があります。`b`。 大きな値の場合、`k`、`a_i \bmod k`等しい`a_i`もしそれ自体`k`すべてよりも大きいです`a_i`。 したがって、シャッフルされた配列の場合、`b`の対応する数値より大きい数値が含まれています。`a`、有効な`k`存在しません。 

制約により、最大で処理する必要があります。$10^4$テスト ケースあたりの要素数、最大$10^4$テストケース全体。 までのすべての整数を反復する総当りアプローチ$10^9$is infeasible. ペアのすべての違いを反復しても、`a`そして`b`慎重に行わなければなりません。 

エッジケースには、すべての要素が`a`等しいですが、`b`複数の異なる数値が含まれている場合、配列がすでに等しい場合、または`b`すべてゼロです。 たとえば、次の場合`a = [5, 5, 5]`そして`b = [0, 0, 0]`、唯一可能なのは`k`は`5`。 もし`b = [1, 2, 3]`、 いいえ`k`これを満たすことができます。 

## アプローチ

 素朴なアプローチは、あらゆる可能性を試すことです`k`1から最大値まで$10^9$、計算する`a_i % k`みんなのために`i`、結果の配列をソートし、一致するかどうかを確認します。`b`。 これは原理的には正しいですが、最大で次の時間が必要となるため実行不可能です。$10^9 \times 10^4$operations per test case, which is far beyond practical limits.

 The key insight comes from the properties of the modulo operation. もし`a_i % k = b_j`一部の人にとっては`i`そして`j`、 それから`a_i - b_j`で割り切れる必要があります`k`。 これは、有効な`k`すべての違いを分割しなければならない`a_i - b_i`位置を合わせた後`a`そして`b`となることによって`b_i <= a_i`。 より一般的には、並べ替えることができます`a`そして`b`独立して。 次に、すべてのインデックスについて`i`、`a[i] - b[i]`で割り切れる必要があります`k`。 したがって、これらの差の最大公約数 (GCD) により、次の候補が得られます。`k`。 GCD がゼロの場合、任意の`k`最大値よりも大きい`a`機能します。 

この観察により、問題は数十億の整数のテストから単一の GCD の計算に軽減されます。$n$テストケースごとの数値。 これは効率的かつエレガントです。

 | GCD ベースの最適 | O(n log(max(a))) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースごとに配列を読み取ります。`a`そして`b`。 両方の配列を非降順で並べ替えます。 並べ替えにより、同じモジュロ クラスの候補である対応する要素が比較されることが保証されます。 
2. 差を計算する`d_i = a[i] - b[i]`みんなのために`i`。 差が負の場合は出力`-1`陽性が出ないのですぐに`k`満足できる`b_i = a_i % k`もし`b_i > a_i`。 
3. ゼロ以外のすべての差の最大公約数 (GCD) を計算します。`d_i`。 すべての差がゼロの場合は、GCD をゼロに設定します。 
4. GCD がゼロの場合、それはすべてを意味します`a_i`と全く等しい`b_i`。 どれでも`k`の最大値より大きい`a`機能します。 無事に帰れるよ`max(a) + 1`または以下の整数$10^9$。 
5. それ以外の場合、GCD 自体が有効な候補になります。`k`。 を超えない限り返品してください$10^9$。 
6. GCD が次の値より大きい場合$10^9$、出力`-1`、問題では答えが最大でも必要なため、$10^9$。 

### なぜ効果があるのか

 モジュロ演算は次の特性を満たします。`a_i % k = b_i`、 それから`k`分割する`a_i - b_i`。 並べ替えることで`a`そして`b`、モジュロで対応する必要がある要素を整列させます。 すべての差異の GCD は次のことを保証します。`k`それぞれの違いを分割し、満足させる`a_i % k = b_i`みんなのために`i`。 すべての差がゼロの場合、十分に大きい差は`k`保存する`b_i = a_i`。 マイナスの差は、不可能なシナリオを示します。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort()
        
        diffs = []
        impossible = False
        for ai, bi in zip(a, b):
            if bi > ai:
                impossible = True
                break
            diffs.append(ai - bi)
        
        if impossible:
            print(-1)
            continue
        
        g = 0
        for d in diffs:
            g = math.gcd(g, d)
        
        if g == 0:
            # all a_i == b_i, any k > max(a) works
            print(min(max(a)+1, 10**9))
        else:
            print(g if g <= 10**9 else -1)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず配列を並べ替えて、潜在的なモジュロ ペアを揃えます。 即時不可能な場合にはそれをチェックします`b_i > a_i`。 次に、すべての差の GCD を計算します。 すべての差がゼロの場合、安全な大きな値を出力します。`k`。 それ以外の場合は、範囲内であれば GCD 自体が返されます。 ソートされていないアラインメントでは有効なモジュロのペアが失われる可能性があるため、ソートは正確性を保つために非常に重要です。 

## 実用的な例

 最初のサンプル入力の場合:

 | 私 | a[i] | b[i] | a[i]-b[i] |
 | --- | --- | --- | --- |
 | 0 | 2 | 0 | 2 |
 | 1 | 3 | 1 | 2 |
 | 2 | 5 | 1 | 4 |
 | 3 | 7 | 1 | 6 |

 差分の GCD: gcd(2,2,4,6) = 2。出力: 2。これは予想される結果と一致します。 

2 番目のサンプル入力の場合:

 | 私 | a[i] | b[i] | a[i]-b[i] |
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | 0 |
 | 1 | 2 | 2 | 0 |
 | 2 | 3 | 3 | 0 |
 | 3 | 4 | 4 | 0 |
 | 4 | 5 | 5 | 0 |

 すべての差はゼロなので、`k > max(a)=5`動作します。 6 を返すことができます。 出力: 6 または任意の有効な大きな数値。
