 ## 解決策
 ## 問題の理解

 長さの 1 次元のストリップが与えられます$n$, ここで、各位置はすでに 3 色のいずれかでペイントされているか、空白のままになっています。 空白の位置は、隣接する 2 つの位置が同じ色を共有しないように、同じ 3 色を使用して埋める必要があります。 

このタスクは、すべての有効な完了をカウントすることではなく、ストリップ全体に少なくとも 2 つの別個の有効な完了が存在するかどうかを判断することだけです。 

2 つの補完の間で少なくとも 1 つの位置の色が異なる場合、2 つの補完は異なるものとみなされます。 

制約$n \le 100$3 次または 2 次動的計画法でも十分に高速であることがわかります。 ただし、すべての色を直接列挙しようとするものはすべて次のように成長します。$3^n$、中等度の人でも実行不可能になります$n$。 これにより、ソリューションはすぐに状態ベースの DP または小さな定常状態空間を使用したメモ化アプローチに向けて推進されます。 

単純ですがよくある落とし穴は、貪欲なフィルを試みることです。 空白の位置に有効な色をローカルで選択すると、有効な補完を生成できますが、代替の補完に関する情報は保持されません。 もう 1 つの落とし穴は、補完が 1 つ存在する場合、疑問符が多数ある場合には常に複数の補完が存在すると想定することです。制約により一意性が強制される可能性があるため、これは誤りです。 

貪欲な推論による具体的な失敗例は次のとおりです。 

入力:```
3
C?C
```有効な補完は 1 つだけあります。`CMC`。 自由な位置があっても、両方の隣接要素によって完全に制約されます。 

もう 1 つの微妙なケースは、次のような文字列がすでに無効である場合です。```
3
CCC
```これには有効な補完が 0 つあり、少なくとも 1 つはありません。 

本当に難しいのは、0、1、または少なくとも 2 つの有効な補完を効率的に区別することです。 

## アプローチ

 ブルートフォース手法では、疑問符へのすべての色の割り当てが試行されます。 あれば$k$疑問符、これは次のようになります$3^k$可能性。 各候補について、隣接制約をチェックします。$O(n)$、につながる$O(n \cdot 3^k)$。 最悪の場合$k = n = 100$、これは天文学的に大きく、まったく使用できません。 

問題の構造は、妥当性が隣接するペアにのみ依存し、決定が左から右に伝播するというものです。 これは、状態が前の色を記憶するだけでよいという動的プログラミングの定式化を示唆しています。 

完全な文字列を列挙する代わりに、有効な部分的なカラーリングがその位置までにいくつ存在するかを追跡します。$i$、可能な各色で終わります。 完全な解の数が少なくとも 2 に達するかどうかのみを考慮するため、すべてのカウントを 2 に制限できます。これにより、オーバーフローが防止され、不必要な計算が回避されます。 

重要な洞察は、状態空間が 3 色のみであるため、DP は位置ごとに一定のサイズのままであり、線形時間の解決策が得られるということです。

 | --- | --- | --- | --- |
 | ブルートフォース列挙 |$O(n \cdot 3^n)$|$O(n)$| 遅すぎる |
 | 上限付きカウントの DP |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 最後に使用した色で区切って、各位置までに有効なウェイがいくつ存在するかを追跡する DP を定義します。 

### ステップ

 1. 位置 0 の DP テーブルを初期化します。最初の文字が固定されている場合は、その色のみが許可されます。 それ以外の場合は、3 色すべてが可能です。 それぞれの有効な開始色は、正確に一方向に寄与します。 これは、長さ 1 のすべての有効なプレフィックスを表します。 
2. 位置 1 から位置 1 までを繰り返します。$n-1$、以前の状態から新しい DP 状態を更新します。 それぞれの位置について、考えられるすべての現在の色を考慮します。 
3. 現在の位置が色に固定されている場合、その色への遷移のみが許可されます。 「?」の場合は、3 色すべてを試します。 
4. 現在の色候補ごとに、前の色が現在の色と異なる前の位置からのすべての DP 値を合計します。 これにより、隣接性の制約が適用されます。 
5. 各更新後、すべての DP 値を 2 に制限します。いずれかの状態がすでに 2 に達している場合、正確なカウントは必要ありません。少なくとも 2 つの解が存在するという事実だけが必要です。 
6. すべての位置を処理した後、最後の位置の DP 値を合計します。 合計が2以上の場合は「Yes」、そうでない場合は「No」を出力します。 

### なぜ効果があるのか

 DP 状態は、最後の色のみを記憶しながら、プレフィックスに色を付ける有効なすべての方法をエンコードします。将来の有効性は隣接関係のみに依存するため、これで十分です。 すべての有効な完全なカラーリングは、これらの状態を通過する 1 つのパスに正確に対応します。 カウントの上限を 2 に設定しているため、正確な大きさを追跡することなく、最終決定の正確性、つまり、存在する解が 0、1、または複数であるかどうかを保持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    colors = ['C', 'M', 'Y']

    dp = {c: 0 for c in colors}

    if s[0] == '?':
        for c in colors:
            dp[c] = 1
    else:
        dp[s[0]] = 1

    for i in range(1, n):
        ndp = {c: 0 for c in colors}

        for cur in colors:
            if s[i] != '?' and s[i] != cur:
                continue

            ways = 0
            for prev in colors:
                if prev != cur:
                    ways += dp[prev]
                    if ways >= 2:
                        ways = 2
                        break

            ndp[cur] = min(2, ways)

        dp = ndp

    total = sum(dp.values())
    print("Yes" if total >= 2 else "No")

if __name__ == "__main__":
    solve()
```この実装では、サイズ 3 のローリング DP 辞書が維持されます。 各ステップで、次の位置の新しい辞書を構築します。 内側のループは、色が繰り返される遷移を除外することで隣接性制約を強制します。 

実装の重要な詳細は 2 の上限です。これがないとカウントが不必要に増加する可能性がありますが、より重要なのは、この問題では 0、1、および少なくとも 2 つの解を区別することだけが必要であるということです。

## 特殊なケース

 次のような単一文字列`"?"`は 3 つの有効な補完を生成し、「少なくとも 2 つ」の要件を即座に満たします。 DP は 3 つの状態すべてがアクティブな状態で開始されるため、最終的な合計はしきい値を超えます。 

次のような完全に固定された文字列`"CMCMCM"`有効な補完が 1 つだけあります。 DP は分岐しないため、最終的な合計は 1 のままで、正しく「いいえ」が生成されます。 

次のような完全に統一された無効な文字列`"CCC"`最初の遷移後のすべての DP 状態を削除します。 すべての状態がゼロになると、それらはゼロのままになり、アルゴリズムが不可能性を正しく報告するようになります。
