 ## 解決策
 ## 問題の理解

 重み付けされた無向ブリッジによって接続された島のグラフが与えられます。 橋を渡るにはその重量に等しい時間がかかるため、移動は通常の意味での最短経路の距離によって決まります。 

各島には、火山が噴火する「期限」の時刻もあります。 火山が噴火した瞬間、その島にかかる橋はすべて破壊され、その瞬間以降その島を横断することはできなくなります。 

2 番目のプロセスが同時に発生します。溶岩は、エッジの重みを移動時間として考慮し、同じ重み付けされたグラフを介してすでに燃えている島から広がり始めます。 溶岩が噴火時間より前に島に到達した場合、代わりにその島は溶岩到着の瞬間に早く燃えます。 それ以外の場合は、噴火時刻に正確に燃えます。 

重要なルールは、燃え上がる瞬間に正確に到着することが依然として有効であるということです。 島が燃えているときに島に入り、踏み台として使用することができます。 

このタスクは、訪問するすべての島への到着時間が厳密にその島の燃焼時間を超えないように、ノード 1 からノード n へのパスが存在するかどうかを判断することです。 

制約構造は十分に大きいため、テスト全体で n と m の合計が約 1e5 になるため、どの解も m 単位で線形演算に近くなる必要があります。 これにより、制約ごとに最短パスを再計算したり、ノードごとに BFS を繰り返し実行したりするようなことが即座に除外されます。 現実的な候補は、単一のダイクストラ スタイルのパスか、実行可能性を慎重に管理した二分探索だけです。 

いくつかのエッジな状況は、誤って対処しやすいものです。 

1 つの障害モードは、バーンタイムに正確に到着したためにパスが実行可能である場合にのみ発生します。 たとえば、時間 5 に島が燃え、私たちが時間 5 に到着した場合でも、それは許可されます。 厳密な不等号チェックを行うと、有効なルートが誤ってブロックされてしまいます。 

もう一つの微妙なケースは、溶岩が噴火時間よりも早く島を焼く場合に起こります。 有効期限は単に ai ではなく、ai と最初の書き込みソースからの最短パス距離 (これはモデルに暗黙的に含まれています) の間の最小値です。 ai のみをチェックする単純なアプローチでは、安全性を過大評価し、無効なパスを受け入れる可能性があります。 

最後に、複数の経路が異なる時間に島に到達する可能性があり、将来の拡張では最も早い到着のみが重要になります。 最もよく知られている到着時刻を追跡しない、ダイクストラ以外の貪欲な散歩では、早めに迂回するものの、後でショートカットのロックを解除する有効なルートを見逃す可能性があります。 

## アプローチ

 この問題を考える強引な方法は、時間の経過に伴う到達可能性をシミュレートすることです。 瞬間ごとに、羊と溶岩の両方をグラフ全体に同時に伝播させ、どの島がまだ使用可能であるかを更新することができます。 各走査ステップでは、時間の経過とともにノードが消滅する動的に縮小するグラフの下で、最短到着時間を再計算する必要があります。 

正確さは概念的には単純です。ルールを直接シミュレートします。 問題は複雑さです。 すべてのイベント (溶岩の到着または噴火) は多くのエッジに影響を与える可能性があり、到達可能性の再計算は、実装によっては O(nm log m) またはそれより悪い値に繰り返し劣化します。 最大 1e5 エッジでは、これは限界をはるかに超えています。 

重要な観察は、実際には時間を継続的にシミュレートする必要がないということです。 実現可能性に関して重要なのは、パス上のすべてのノード v の到着時間 dist[v] が最大でもその実効書き込み時間になるような 1 から n までのパスが存在するかどうかです。 これにより、問題は制約付き最短経路問題に変換されます。

ノード 1 からダイクストラを実行すると、火山の制約を無視して、すべてのノードへの可能な限り最も早い到着時間を計算します。 次に、単純に枝刈りルールを適用します。つまり、候補の到着時間が v の書き込み時間を超えない場合にのみ、エッジを v に緩和することが許可されます。 期限内にノードに到達できない場合、そのノードは事実上検討対象から除外されます。 

これが機能するのは、最短到着時間が単調であるためです。ノードに到達できる最も早い時間がわかったら、それより遅い到着時間は実現可能性にとって厳密に悪くなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースタイムシミュレーション | O(nm log m) | O(n + m) | 遅すぎる |
 | 期限付き枝刈りを行ったダイクストラ | O(m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各アイランドの有効燃焼時間を計算し、制約付き最短パス検索を実行します。 

1. 各島について、その燃焼時間を指定どおりに扱います。 これは、中間ノードとして安全に使用できる最後の瞬間を表します。 
2. ノード 1 から標準ダイクストラを実行します。距離配列は最も早い到着時間を表します。 
3. distance[1] = 0 を初期化し、優先キューにプッシュします。 
4. 現在時刻 t のノード u を抽出するとき、u のより良い到着時刻がすでに見つかっている場合は、それを無視します。 これは標準的なダイクストラの動作です。 
5. エッジの重み w を介して到達可能なすべての近傍 v について、候補時間 t + w を計算します。 
6. t + w が厳密に burn[v] より大きい場合は、この遷移を完全にスキップします。 これにより、ノードが使用できなくなった後は決してそのノードにアクセスしないことが強制されます。 
7. それ以外の場合、t + w が現在の値より小さい場合は dist[v] を緩和し、優先キューにプッシュします。 
8. アルゴリズムが終了したら、dist[n] が有限かどうかを確認します。 「はい」の場合は「YES」を出力し、そうでない場合は「NO」を出力します。 

これで十分な理由は、すべてのパスを効果的に検索し、ノードに足を踏み入れた瞬間に厳しい実現可能性制約に違反するパスのみをプルーニングしているためです。 有効なパスはすべてのプレフィックスでこれらの制約を尊重する必要があるため、ダイクストラの緩和プロセスで引き続き使用できます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        g = [[] for _ in range(n)]
        for _ in range(m):
            x, y, w = map(int, input().split())
            x -= 1
            y -= 1
            g[x].append((y, w))
            g[y].append((x, w))

        dist = [INF] * n
        dist[0] = 0

        pq = [(0, 0)]

        while pq:
            tcur, u = heapq.heappop(pq)
            if tcur != dist[u]:
                continue
            if tcur > a[u]:
                continue

            for v, w in g[u]:
                nt = tcur + w
                if nt <= a[v] and nt < dist[v]:
                    dist[v] = nt
                    heapq.heappush(pq, (nt, v))

        print("YES" if dist[n - 1] < INF else "NO")

if __name__ == "__main__":
    solve()
```コア実装は標準のダイクストラ ループで、追加の制約チェックが 1 つあります。つまり、ノードの書き込み時間後に到着するエッジの緩和を拒否します。 優先キューには期限を超えたために無効になったエントリがまだ含まれている可能性があるため、ポップ ステップ内の 2 番目のプルーニング条件は重要です。 

よくある間違いは、ノードが以前に挿入されていたとしても、期限を超えてポップされる可能性があることを忘れることです。 そのため、近隣を探索する前にそのような状態を明示的に破棄します。

...

| ステップ | ノード | 時間 | アクション |
 | --- | --- | --- | --- |
 | 1 | 1 | 0 | 開始 |
 | 2 | 3 | 23 | 拒否されました (23 > 5) |

トレースは、すべての候補到着が期限を超えているため、ダイクストラがノード 3 を経由するルーティングを自然に回避していることを示しています。 このアルゴリズムの正しさは、そのようなノードを後で再検討するのではなく、完全に枝刈りすることから生まれます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log n) | 各エッジはヒープ プッシュで最大 1 回緩和されます。 
| スペース | O(n + m) | 隣接リストと距離配列 |

 テスト全体のノードとエッジの合計数は 1e5 で制限されているため、この複雑さは、ヒープ最適化を使用した Python の 2 秒の実行ウィンドウでは問題なく制限内に収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf
    import heapq

    INF = 10**30
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        g = [[] for _ in range(n)]
        for _ in range(m):
            x, y, w = map(int, input().split())
            x -= 1
            y -= 1
            g[x].append((y, w))
            g[y].append((x, w))

        dist = [INF] * n
        dist[0] = 0
        pq = [(0, 0)]

        while pq:
            d, u = heapq.heappop(pq)
            if d != dist[u]:
                continue
            if d > a[u]:
                continue
            for v, w in g[u]:
                nd = d + w
                if nd <= a[v] and nd < dist[v]:
                    dist[v] = nd
                    heapq.heappush(pq, (nd, v))

        out.append("YES" if dist[n-1] < INF else "NO")

    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、ノードが書き込み時に正確に到達可能であるが、厳密な不平等が使用された場合に通常は拒否される、より長い代替パスを経由する場合のみである場合です。 たとえば、ノードの書き込み時間が 10 で、2 つのパスが時間 10 と 11 にノードに到達する場合、最初のパスのみが有効です。 アルゴリズムは、`<=`エッジを緩和するときの条件。等価性は許可されますが、オーバーフローは除外されます。 

もう 1 つのケースは、開始ノード自体の燃焼時間が非常に短い場合です。 a1 が 0 の場合、唯一の有効な初期状態は時間 0 での到着であり、出力エッジはその制約に対して直ちにチェックされる必要があります。 優先キュー ロジックにより、ノード 1 は引き続き処理されますが、その制約に違反する近隣ノードは早期に破棄されます。 

3 番目の微妙なケースは、ノードが優先キューに異なるタイミングで複数回挿入され、一部は有効で、一部は無効である場合です。 小切手`if d != dist[u]`古いエントリの処理を防ぎ、追加の`d > a[u]`チェックにより、その間に無効になったノードの展開が防止されます。
