 ## 問題の理解

 一辺の長さが連続する 3 つの自然数で、周囲の長さが指定された値に等しい三角形を形成できるかどうかを尋ねます。$p$。 

この設定で有効な三角形は、開始整数によって完全に決定されます。$a$。 側面は次のようになります。$a$、$a+1$、 そして$a+2$。 境界制約はそれらの合計を修正するため、整数が存在するかどうかを実際にチェックしています。$a \ge 1$そのような$$a + (a+1) + (a+2) = p.$$同時に、これら 3 つの値は三角不等式を満たす必要があります。これは、最大の辺が他の 2 つの値の合計より厳密に小さくなければならないことを意味します。 

入力は単一の整数です$p$、出力はバイナリです。そのようなトリプルが少なくとも 1 つ存在する場合は 1 を出力し、それ以外の場合は 0 を出力します。 

問題は幾何学的に見えますが、完全に算術構造に崩壊します。 主な制約は幾何学ではなく、単純な線形システムが正数性と三角不等式も考慮した整数解を持っているかどうかです。 

範囲$1 \le p \le 10^9$連続する整数のすべてのトリプルを試行する試みは直ちに除外されます。 それでも$a$せいぜい約くらいです$p/3$まで繰り返します$10^9$1秒制限では無理です。 解決策では、検索を一定時間に短縮する必要があります。 

周囲が非常に小さい場合、微妙なエッジケースが現れます。 例えば、$p = 1$または$p = 2$三角形をまったく形成できませんが、次のようなわずかに大きな値でも形成できます。$p = 4$または$p = 5$最小の連続トリプルは次のとおりであるため、これも失敗します。$1,2,3$、その周長はすでに 6 です。もう 1 つの失敗モードは、三角不等式を忘れることです。ただし、連続する整数の場合は、正が成立すると自動的に満たされることがわかります。 

## アプローチ

 直接的なアプローチでは、考えられるすべての開始値を試します。$a$、トリプルを計算します$(a, a+1, a+2)$、合計が等しいかどうかを確認します$p$、三角不等式を検証します。 これは正しいですが、非効率的です。 合計条件だけで強制される$3a + 3 = p$したがって、実際には候補は 1 つだけです$a$それぞれに$p$しかし、単純なアプローチでも概念的には繰り返しが行われます。$O(p)$可能な値$a$。 と$p$まで$10^9$、これは実現可能な限界をはるかに超えています。 

重要な観察は、側面の構造が周囲を完全に決定するということです。 連続する整数を仮定すると、組み合わせの選択肢はなくなります。 周囲の方程式が修正されました$a$一意に:$$a = \frac{p - 3}{3}.$$したがって、問題全体は、この値が整数であるかどうか、およびそれが少なくとも 1 であるかどうかをチェックすることに帰着します。三角不等式は、新しい制約を追加しません。$a$、$$a + (a+1) > a+2$$自動的に保持されます。 

したがって、問題は可分性と下限のチェックになります。

 ## アルゴリズムのチュートリアル

 1. コンピューティング$p - 3$。 これは、連続した構造内の固定オフセットの一定の寄与を除去することに対応します。 
2. かどうかを確認します。$p - 3$3 で割り切れない場合は、整数ではありません$a$が存在するため、有効な三角形を形成できません。 
3. 割り切れる場合は計算する$a = (p - 3) / 3$。 これが最小の辺として考えられる唯一の候補です。 
4. 次のことを確認します。$a \ge 1$。 これにより、辺が 1 以上で始まる有効な自然数であることが保証されます。 
5. 両方の条件が成立する場合、1 を出力します。 それ以外の場合は 0 を出力します。 

このロジックは、すべての有効な三角形が長さ 3 の 1 つの等差数列に正確に対応する必要があるという事実に基づいているため、検索する必要はありません。 

### なぜ効果があるのか

 有効な構成は次の形式である必要があります。$(a, a+1, a+2)$。 周長方程式により、一意の$a$。 どちら側を選択するかには自由がないので、存在の問題は、これが強制されたかどうかに帰着します。$a$は自然数の有効領域内にあります。 連続する整数は常に三角不等式を 1 回満たすため、三角不等式には追加の制限はありません。$a \ge 1$。 これにより、算術条件が必要かつ十分になります。 

## Python ソリューション```python

    if a >= 1:
        print(1)
    else:
        print(0)

よくある落とし穴はチェックを忘れることです$a \ge 1$、次のようなケースを誤って受け入れます。$p = 3$、生産$a = 0$、これは無効です。

 ## 特殊なケース

 次のような小さな周囲$p = 6$生成する$a = 1$、最小の三角形を与える$1,2,3$。 アルゴリズムは計算します$(6 - 3) = 3$、これは 3 で割り切れ、次の結果が得られます。$a = 1$, したがって、正しく受け入れられます。 

のために$p = 5$、計算により次のことが得られます。$p - 3 = 2$これは、3 で割り切れません。アルゴリズムは、連続する 3 つの正の整数の合計が 5 にならないという事実と一致して、これを即座に拒否します。 

のために$p = 3$、私たちは得ます$p - 3 = 0$、これは 3 で割り切れ、次の結果が得られます。$a = 0$。 最終チェック$a \ge 1$はそれを拒否し、正でない辺を持つ無効な三角形を防ぎます。
