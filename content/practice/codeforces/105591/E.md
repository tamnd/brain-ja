 ## 問題の理解

 小文字のラテン文字で構成される文字列が与えられます。 少なくとも同じ文字が出現する連続したブロックが文字列に含まれている場合、その文字列は「退屈」であるとみなされます。`m`何度も続けて。 私たちのタスクは、2 つの許可された操作 (コスト 1 で文字を削除するか、コスト 1 で任意の文字を挿入する) を使用して、文字列を退屈でない文字列に変換することです。`k`。 挿入は、任意の 2 つの既存の文字の間、または末尾に配置できます。 

目標は、総コストを最小限に抑え、すべての編集後に長さの中に文字が表示されないようにすることです。`m`またはそれ以上。 

この制約により、文字列の長さは最大 200,000 になることが許可されるため、二次関数となる解はすべて`n`失敗します。 本質的に線形時間または線形時間に近い時間で文字列を処理することが期待されています。これは、編集をグローバルにシミュレートするのではなく、問題を独立したローカル構造に帰着させる必要があることを強く示唆しています。 

重要な構造上の観察は、同一の文字の連続のみが重要であるということです。 条件違反は同じ文字の最大連続セグメントから発生するため、文字列は自然に独立したブロックに分解され、1 つのブロックに適用された操作は他のブロックに影響を与えません。 

微妙ですが重要な点は、削除によってランが同じキャラクターの複数のランに分割されないということです。 ラン内の文字を削除しても、そのランの残りの文字は依然として隣接しており、その文字の単一の連続ブロックを形成します。 これは、異なる文字の挿入のみがランを複数の安全な部分に分割できることを意味します。 

単純な間違いは、削除によって長期実行をより小さな実行に「分割」できると想定することです。 たとえば、`"aaaaaa"`、中間の文字を削除しても、複数の実行は作成されません。`'a'`、それでも単一の実行は短くなります。 

エッジケースは次の場合に発生します。`m`小さいです。 もし`m = 2`、隣接する等号文字は禁止されています。 のようなランニングのために`"aaaa"`、1 つのペアでもすでに条件に違反しています。 もう 1 つの例外的なケースは次のような場合です。`k`非常に大きいため、挿入が本質的に役に立たない、または`k = 1`、削除に比べて挿入のコストが非常に安くなります。 

## アプローチ

 文字列は、同一の文字の最大の連続に分解されます。 このような長さのランを考えてみましょう`L`。 もし`L < m`、すでに条件を満たしているため、変更する必要はありません。 

もし`L ≥ m`、同じ文字のセグメントが長さに達しないように、それを減らす必要があります。`m`。 

ブルートフォースアプローチでは、文字列全体にわたる削除と挿入の考えられるすべてのシーケンスをシミュレートし、実行を分割するさまざまな方法を検討し、コストを動的に支払います。 これはすぐに実行不可能になります。`L`挿入と削除をインターリーブする方法が指数関数的に多くあり、`n`最大 200,000 人に達すると、これは実現可能な国家空間をはるかに超えます。 

重要な洞察は、各実行を独立して処理できること、および 1 回の実行については、根本的に異なる 2 つの戦略を比較するだけでよいということです。 

最初の戦略は、ランレングスが長くなるまで文字を削除することです。`m - 1`。 これにより、挿入が完全に回避され、コストは純粋に削除の数だけになります。`L - (m - 1)`。 

2 番目の戦略は、すべての文字を保持し、同じ文字のセグメントが長さを超えないように区切り文字を挿入することです。`m - 1`。 挿入ごとに、長いランがより小さな有効な部分に分割されます。 一定の長さのランがある場合`L`、毎回の後に区切り文字を挿入する必要があります。`m - 1`文字、その結果、`floor((L - 1) / (m - 1))`挿入、それぞれの費用`k`。 

部分的な削除と挿入を混合しても、これらの極端な値を超えてコストが向上することはないため、最適な解決策は、実行ごとにこれら 2 つのコストの最小値を取ることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適 (分解を実行) | O(n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列内の同一文字の最大セグメントごとに、そのセグメントを有効にするための最小コストを計算し、それを答えに追加します。 

1. 文字列を左から右にスキャンし、連続する等しい文字を長さのあるランにグループ化します。`L`。 実行内の操作が他の実行に影響を与えることはないため、このステップでは独立した構造を分離します。 
2. もし`L < m`、すでに制約を満たしているため、この実行では何もしません。 
3. もし`L ≥ m`、削除コストを次のように計算します。`L - (m - 1)`。 これは、到達できない程度にランを減らすことに相当します。`m`連続した文字。 
4. 挿入コストを次のように計算します。`((L - 1) // (m - 1)) * k`。 これは、長さに達する前に同じ文字のすべてのブロックが分割されるように区切り文字を挿入することに対応します。`m`。 
5. これら 2 つのコストの最小値を合計の答えに加えます。 

このアルゴリズムは、現在のランレングスのみを維持しながら文字列を直線的に処理するため、文字列の前の部分を保存したり再訪したりする必要はありません。 

### なぜ効果があるのか

 1 つの文字タイプに対する操作は別の文字タイプの隣接性に影響を及ぼさないため、各実行は独立しています。 実行内では、削除によって長さが短縮されるだけで、実行が複数の安全なコンポーネントに分割されることはありません。そのため、削除による意味のある効果は全体の長さの短縮だけです。 挿入は、ラン内で分離を作成する唯一のメカニズムです。 したがって、実行の有効な最終構成は、削除によってしきい値以下に減らすか、挿入によって分割するかのいずれかによって達成可能でなければならず、これら 2 つのメカニズムは、すべての実現可能な結果を​​完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    s = input().strip()

    ans = 0
    i = 0

    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1

        L = j - i

        if L >= m:
            delete_cost = L - (m - 1)
            insert_cost = ((L - 1) // (m - 1)) * k
            ans += min(delete_cost, insert_cost)

        i = j

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、実行ベースの推論を直接翻訳したものです。 内側のループは、等しい文字の最大ブロックをそれぞれ抽出します。 各ブロックについて、その長さを計算し、2 つの候補コストを評価します。 

よくある実装の落とし穴は、挿入用のフロア分割の処理を誤ることです。 正しい数式は、文字をサイズの塊にグループ化するかどうかによって異なります。`m - 1`、セパレータの数は、そのようなチャンク間の完全な境界の数と正確に一致します。`(L - 1) // (m - 1)`。 

もう 1 つの微妙な点は、次の場合にのみコストを適用するようにすることです。`L ≥ m`。 より短い実行では、両方の式が正の値または無意味な値を誤って生成するため、明示的にスキップする必要があります。 

## 実用的な例

 サンプル入力を検討してください`6 4 2`紐付き`kaaarl`。 

実行を処理します。`"k"`長さ 1、`"aaa"`長さ3の、`"r"`長さ 1、`"l"`長さ1のランのみ`"aaa"`関連性があります。 

| 実行 | Ｌ | メートル | 削除コスト | 挿入コスト | 選ばれた |
 | --- | --- | --- | --- | --- | --- |
 | ああ | 3 | 4 | 0 | 0 | 0 |

 以来`L < m`、修正は必要なく、答えは 0 です。 

ここで考えてみましょう`6 3 2`と`kaaarl`。 

ランは再び`"k"`、`"aaa"`、`"r"`、`"l"`。 今`m = 3`、 それで`"aaa"`は無効です。 

| 実行 | Ｌ | 削除コスト | 挿入コスト | 選ばれた |
 | --- | --- | --- | --- | --- |
 | ああ | 3 | 1 | 1 | 1 |

 削除すると次のように減少します`"aa"`、コストは 1 です。挿入には 1 つのセパレータを挿入する必要があります (`(3-1)//2 = 1`）、コストも2ですか？ ちょっと待ってください: k=2 なので、挿入コストは 1 * 2 = 2 となり、削除の方が安くなります。 最適なコストは 1 です。 

これは、アルゴリズムが実行の縮小と挿入を使用した分割の間でどのように自然にバランスをとるかを示しています。

 ## 特殊なケース

 次のような単一の長い実行で構成される文字列の場合、`"aaaaaaa"`と`m = 2`の場合、アルゴリズムはそれを 1 つのブロックとして処理し、単一の文字まで削除する場合と、すべての文字の間に区切り文字を挿入する場合を比較します。 削除パスのコスト`L - 1`、挿入にはコストがかかりますが、`(L - 1) * k`。 と`k ≥ 1`、次の場合を除き、削除は常に最適です。`k = 1`この場合、両方が等しくなりますが、アルゴリズムは引き続き正しく選択します。 

次のような交互文字列の場合`"abababab"`、すべての実行の長さは 1 であるため、コストは発生せず、アルゴリズムは自然にすべての計算をスキップします。 

以下の場合については、`k`は非常に大きく、挿入は削除よりも優先されるため、挿入は決して選択されず、アルゴリズムはすべての長い実行を削除のみによって正しく削減します。
