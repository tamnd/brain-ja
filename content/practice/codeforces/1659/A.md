 ## 解決策
 ## 問題の理解

 合計試合数、赤の勝利数、青の勝利数を考慮して、赤と青の 2 つのチーム間の一連の試合結果を構築するように求められます。 目標は、同じチームによる連続勝利の最大数ができるだけ少なくなるように、R と B のシーケンスを作成することです。 概念的には、長い連勝を避けるために、赤の勝利をシーケンス全体に均等に分散させ、青の勝利をインターリーブしようとしています。 

入力により、テスト ケースごとに 3 つの整数が得られます。`n`合計一致数、`r`レッドの勝利、そして`b`青の勝利。厳密に赤が青より多くの勝利を収めていることが保証されます (`r > b`）そしてそれ`r + b = n`。 長さのテスト ケースごとに 1 つの文字列を生成する必要があります。`n`まさに`r`Rさんと`b`B は、R または B の最長連続実行を最小化します。 

制約を考慮すると、`n`テストケースの数は最大 100 です。`t`これは、ブルート フォース シナリオで実行できる合計操作数は約 100,000 になります。 ただし、R と B のあらゆる可能な置換を試みる素朴なアプローチは、次のように階乗的に増加します。`n`したがって、実現不可能です。 

明白ではないエッジケースは、たとえば、赤の数が青を大きく上回る場合に発生します。`r = n-1`そして`b = 1`。 その場合、R と B を厳密に交互にしようとする素朴な試みは、Red のシーケンスを分割するのに十分な B がないため失敗します。そのため、アルゴリズムは最大ストリークを最小限に抑えながら、より長い連続実行を許可する必要があります。 

## アプローチ

 ブルートフォース手法では、カウントを満たす R と B の考えられるすべてのシーケンスを生成し、それぞれの最大ラン長を計算します。 これは正しいですが、シーケンスの数が次のとおりであるため、実行できません。`C(n, r)`それは膨大なものになる可能性があります。 たとえば、次の場合`n = 100`そして`r = 51`、`C(100, 51)`おおよそです`1e29`、大きすぎます。 

重要な洞察は、ブロックの観点から考えることで、赤の勝利の最大実行を制御できるということです。 もし持っていれば`b`青の勝利、赤の勝利を次のように分けることができます。`b+1`連続したグループ。 各グループは少なくとも 1 つの B によって分離され、連続する R の各グループの長さは可能な限り均等になります。 これにより、R の勝利が可能な限り均一に分配されるため、最小限の最大ストリークが保証されます。 

たとえば、次の場合`r = 13`そして`b = 6`、レッドの勝利を 7 つのブロックに分割できます (`b+1 = 6+1`)、各ブロックは次のいずれかを持ちます。`13 // 7 = 1`または`2`Rさん。 次に、各ブロックの間に B を挿入します。 これにより、R の連続値が超過することがなくなります。`ceil(r / (b+1))`、これは明らかに最適です。 最終的な文字列は、B がインターリーブされたこれらのブロックを単純に連結したものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(n,r)) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`、`r`、`b`。 
2. R の勝利を分割するブロックの数を計算します。`blocks = b + 1`。 各ブロックには約`r // blocks`Rさん。 
3. 剰余を計算する`extra = r % blocks`。 これは、不均等な分割を考慮して 1 つの追加 R を取得するブロックの数を表します。 
4. 空の文字列を初期化する`res`。 各ブロックインデックスを反復処理します`i`0から`blocks - 1`。 
5. ブロックごとに、`base = r // blocks`Rさん。 もし`i < extra`、このブロックに R をもう 1 つ追加します。 これにより、最初の数ブロック間の余分な R のバランスがとれます。 
6. 青の勝利がまだ残っている場合は、ブロックの後に B を 1 つ追加します。 減少`b`それに応じて。 
7. すべてのブロックが処理されるまで続行します。 結果の文字列は正確に`r`Rさんと`b`B を使用し、連続する R の最大数を最小化します。 

これが機能する理由は、R を次のように分割することにより、`b+1`ブロックとインターリーブ B の場合、連続する R のシーケンスはこれを超えることはできません`ceil(r / (b+1))`、これは、R を分離するために利用できる B の数を考慮した最小の可能な最大ストリークです。 この特性は、R が可能な限り均等に分散されることを保証するため、r と b の特定の数に関係なく当てはまります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, r, b = map(int, input().split())
    blocks = b + 1
    base = r // blocks
    extra = r % blocks
    res = []
    for i in range(blocks):
        cnt = base + (1 if i < extra else 0)
        res.append('R' * cnt)
        if b > 0:
            res.append('B')
            b -= 1
    print(''.join(res))
```このソリューションでは、まず赤の勝ちを分割するブロックの数を計算します。 の`base`そして`extra`ロジックにより、R が可能な限り均等に分散されるようになります。 残りの保証がある場合にのみ B を追加するので、青の勝利を追加しすぎることはありません。 リストを使用して最後に結合すると、文字列連結の繰り返しによるオーバーヘッドが回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    t = int(input())
    for _ in range(t):
        n, r, b = map(int, input().split())
        blocks = b + 1
        base = r // blocks
        extra = r % blocks
        res = []
        for i in range(blocks):
            cnt = base + (1 if i < extra else 0)
            res.append('R' * cnt)
            if b > 0:
                res.append('B')
                b -= 1
        print(''.join(res))
    return out.getvalue().strip()
