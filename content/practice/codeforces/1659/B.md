 ## 解決策
 ## 問題の理解

 バイナリ文字列から始めます。 私たちは正確に実行しなければなりません\(k\)操作。 

1 回の操作でポジションを選択します\(i\)。 選択されたビットは変更されませんが、文字列内の他のビットはすべて反転されます。 結局\(k\)演算では、結果として得られる文字列を辞書編集的にできるだけ大きくする必要があります。 各ポジションが何回選択されたかも出力する必要があります。 

まず最初に理解するのは、繰り返しの操作による影響です。 位置を選択しても、その位置は直接変更されません。 代わりに、1 つおきの位置を変更します。 パリティのみが重要であるため、ポジションが何回選択されるかは気にせず、奇数回選択されるか偶数回選択されるかのみを気にします。 

制約により、操作のシミュレーションが即座に除外されます。 1 回の操作で影響を受ける\(n-1\)ポジション、そして\(k\)と同じ大きさにすることができます\(10^9\)。 一つ一つの操作を追跡することさえ不可能です。 すべての文字列の合計の長さは最大でも\(2 \cdot 10^5\)の場合、テスト ケースごとの \(O(n)\) または \(O(n \log n)\) の解がターゲットとなります。 

微妙なエッジケースが現れるのは、\(k\)奇数です。 考慮する：```text
1 1
0
```ポジションは1つだけです。 どこかで1回の手術を費やさなければなりません。 最後のビットは次のようになります\(1\)、 ない\(0\)。 未使用の操作のパリティを考慮せずに貪欲に 0 を 1 に変換するソリューションは失敗します。 

もう 1 つの重要なケースは、有用なポジションよりも多くの操作がある場合です。```text
3 10
111
```文字列を最大化した後も、いくつかの操作が残ります。 それらの操作は消えることはありません。 それらのパリティは最終的な文字列に影響を与えるため、どこかに割り当てる必要があります。 貪欲フェーズ中に明示的に使用された位置のみを追跡するソリューションでは、間違った答えが生成されます。 

3 番目のトラップは最後の位置です。 標準的な貪欲戦略では、残りのすべての操作を意図的に最後のインデックスにダンプします。 その特別な処理を忘れた場合、カウントは合計されません。\(k\)。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる操作をモデル化しようとします。 各ステップで位置を選択し、文字列を更新します。 たとえ最適な選択が何らかの方法でわかっていたとしても、各操作には \(O(n)\) のコストがかかり、 \(O(nk)\) の作業が発生します。 と\(k\)まで\(10^9\)、これは絶望的です。 

重要な観察は、パリティのみが重要であるということです。 

位置を仮定します\(i\)選ばれる\(f_i\)回。 させて$$
K = \sum_i f_i = k.
$$ちょっと位置的に\(i\)を選択した操作を除くすべての操作中に反転されます。\(i\)。 したがって反転されます$$
k - f_i
$$回。 

のパリティのみ\(k-f_i\)重要です。 最後のビットは$$
s_i \oplus ((k-f_i)\bmod 2).
$$ここで、問題は建設的なパリティ割り当ての問題になります。 

まず次の場合を考えてみましょう\(k\)奇数です。 を含むポジション\(0\)なることができる\(1\)一度そのポジションを選択すれば。 辞書編集上の順序は前の位置によって支配されるため、左から右への操作を費やして、できるだけ多くの初期の 0 を 1 に変換する必要があります。 

いつ\(k\) is even, the symmetric statement holds. A position containing \(1\)なることができる\(1\) in the final string if we choose it once. Again we greedily process from left to right.

After exhausting either useful positions or available operations, all remaining operations are dumped into the last position. Only their parity matters, so this preserves optimality while satisfying the requirement of using exactly \(k\)動きます。

 | 貪欲に最適な構築 | \(O(n)\) | \(O(n)\) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`cnt` of length \(n\)、最初はすべてゼロです。 これにより、各ポジションが選択された回数が保存されます。 

2. しましょう`rem = k`.

3. Scan positions from left to right, excluding the last position.

4. If \(k\) is odd and the current bit is `'0'`、この位置を一度選択すると、最終的な値は次のようになります。`'1'`. If `rem > 0`、 セット：$$
cnt[i] = 1
$$そして減少します`rem`。 

5. もし\(k\)は偶数で、現在のビットは`'1'`、この位置を一度選択すると、先頭が保持されます。`'1'`最終的な答えで。 もし`rem > 0`、 セット：$$
cnt[i] = 1
$$そして減少します`rem`。 

6. ポジション処理後\(1\)を通して\(n-1\)、残りのすべての操作を最後の位置に配置します。$$
cnt[n-1] = rem.
$$7. 最終的な文字列を構築します。 ポジションについて\(i\)、それに適用される反転の数は次となります。$$
k - cnt[i].
$$この量が奇数の場合は、元のビットを反転します。 それ以外の場合は、変更しないでください。 

8. 最終的な文字列と配列を出力します。`cnt`.

### Why it works

Lexicographic order is determined by the first position where two strings differ. Whenever an operation can turn an earlier position into `1`そうすることは、常にその操作を後の位置のために保存するのと少なくとも同じくらい効果的です。 貪欲スキャンは、まさにこの優先順位で位置を処理します。 

重要なのはパリティのみであるため、有効な位置ごとに必要な操作は 1 つだけです。 同じポジションに 3 つ、5 つ、または 7 つのオペレーションを費やしても、1 つを費やした場合と同じ効果があります。 したがって、貪欲フェーズでは、最も早いポジションを最大化するために必要な最小限の操作数が使用されます。 

貪欲フェーズの後に残った操作では、それ以前のポジションを改善することはできません。 それらすべてを最後のインデックスに割り当てると、最適なプレフィックスが保持され、正確に使用するという要件が満たされます。\(k\)動きます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, k = map(int, input().split())
        s = list(input().strip())

        cnt = [0] * n
        rem = k

        target = '0' if k % 2 else '1'

        for i in range(n - 1):
            if rem > 0 and s[i] == target:
                cnt[i] = 1
                rem -= 1

        cnt[-1] += rem

        ans = []

        for i in range(n):
            flips = (k - cnt[i]) & 1

            bit = int(s[i])

            if flips:
                bit ^= 1

            ans.append(str(bit))

        print("".join(ans))
        print(*cnt)

if __name__ == "__main__":
    solve()
```配列`cnt`正確な操作数を保存します。 変数`target`パリティ依存の貪欲ルールを捉えています。 いつ\(k\)ゼロをターゲットにするのは奇妙です。 いつ\(k\)私たちもターゲットにしています。 

最終的な再構成では、位置が正確に反転されるという式が使用されます。\(k-cnt[i]\)回。 パリティのみが重要なので計算します```python
flips = (k - cnt[i]) & 1
```必要に応じて反転を適用します。 

最後の位置は、未使用の操作をすべて受け取ります。 これにより保証されます$$
\sum_i cnt[i] = k.

 ## 特殊なケース

 次のことを考慮してください。```text
1
1 5
0
```ポジションは1つだけです。 最後のループの前にはポジションがないため、貪欲ループは実行されません。 5 つの操作すべてがその位置に割り当てられます。 以来$$
k-cnt[0]=5-5=0,
$$ビットは決して反転せずに残ります`0`。 カウントの合計はちょうど 5 です。 

考慮する：```text
1
3 10
111
```ここ\(k\)は均等です。 貪欲フェーズでは、最初の 2 つのポジションに対して 1 つの操作が費やされ、最後のポジションに対して 8 つの操作が残ります。 再構成はパリティのみに依存し、10 の大きさには依存しません。 このアルゴリズムは、辞書編集上で達成可能な最大の接頭辞を維持しながら、すべての移動を使用します。 

考慮する：```text
1
4 1
0000
```最初の位置は、可能な限り最良の先頭ビットに直ちに変換されます。 操作がなくなると、残りの位置は無関係になります。 これは、最も早い位置での貪欲な選択が常に最適であることを裏付けています。
