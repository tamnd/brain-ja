 ## 解決策
 ## 問題の理解

 未知のバイナリ配列から始めます$A$。 プレフィックス長ごとに$k$、最初に並べ替えます$k$の要素$A$、残りは変更しないままにします。 これにより、$n$配列$B_1, B_2, \dots, B_n$。 

これらの配列を直接見る代わりに、それらの列方向の合計が与えられます。$C$。 タスクはバイナリ配列を再構築することです$A$それは与えられたものを生成した可能性があります$C$。 

重要な観察は、存在を検証するように求められていないということです。 このステートメントは、少なくとも 1 つの有効な配列が存在することを保証します。 私たちの唯一の仕事は、1 つを回復することです。 

配列の長さは次のとおりです$2 \cdot 10^5$すべてのテストケースにわたって。 すべてを明示的に構築するソリューション$B_k$配列には必要になります$O(n^2)$あまりにも大きすぎる仕事。 テスト ケースごとに線形時間で実行される再構築手順が必要です。 

よくある間違いの原因は、変換によってどのような情報が保存されるかを誤解することです。 たとえば、次の 1 の合計数は、$A$失われていません。 ソートされたすべての配列$B_k$とまったく同じ数の 1 が含まれます$A$並べ替えによって要素数が変更されないためです。 以来$C$すべての合計です$B_k$、の合計$C$等しい$$n \cdot (\text{number of ones in } A).$$この事実が復興の出発点となる。 

別の微妙なケースは、多くの位置で発生する場合に発生します。$C$等しいです。 例えば、```
n = 3
C = [0,0,0]
```正しい答えは、```
0 0 0
```可能な限り貪欲に 1 を挿入する再構築手順は、すぐに失敗します。 

別のエッジケースは次のとおりです```
n = 4
C = [0,0,0,4]
```答えは```
0 0 0 1
```最後の位置だけでも、最後に 1 を強制するのに十分な情報が含まれています。 

## アプローチ

 最も直接的なアイデアは、すべてのバイナリ配列を試してみることです。$A$、すべてのソートされたプレフィックス配列を生成し、計算します$C$、入力と比較します。 

これは正しいですが、絶望的に遅いです。 がある$2^n$候補配列。 たとえ$n=40$、これはすでに 1 兆の可能性を超えています。 

本当のブレークスルーは、単一の配列が最終的な配列にどのように寄与するかを研究することから生まれます。$C$。 

答えを右から左に再構築するときに、配置すべきものがいくつ残っているかがわかっているとします。 位置に配置された 1 つ$i$非常に規則的な方法で、以前の位置の連続した範囲に影響を与えます。 並べ替えプロセスを直接シミュレートする代わりに、それらの効果を差分配列で表すことができます。 

これにより、再構成が右から左への貪欲なスキャンに変換されます。 各位置で、現在の要素を次のようにする必要があるかどうかを決定します。$0$または$1$、その決定の寄与を差分配列を通じて遅延的に適用し、続行します。 

結果として得られるアルゴリズムは線形です。

 ## アルゴリズムのチュートリアル

 ### 主な所見

 しましょう$$k = \frac{\sum C_i}{n}.$$すべての配列以来$B_j$とまったく同じ数の 1 が含まれます$A$、$k$は、まさに未知の配列内の 1 の数です。 

再構築します$A$右から左へ。 

させて`ones`まだ修正されていないものの数を示します。 

以前に選択したものの累積効果を保存する差分配列を維持します。 

### 再構築ルール

 位置で$i$、すべてのアクティブな更新を適用した後、調整された値を取得します$$v = C_i + \text{current\_effect}.$$次に:

 1. もし$v = \text{ones}$、現在位置は次でなければなりません$0$。 
2. それ以外の場合、現在位置は次のようになります。$1$。 

1 を配置すると:

 1. 設定します$A_i = 1$。 
2.減らす`ones`1つずつ。 
3. 差分配列を使用してその寄与を遅延的に追加します。 

### 比較が機能する理由

 右から左にスキャンする場合、すでに決定されているすべてのものが、予測可能な量で以前の位置に寄与します。 これらの寄与を削除した後、その位置に残っている値は、$i$元のビットがゼロの場合にのみ、配置されていないものの現在の数と一致します。 

一致しない場合、考えられる唯一の有効な可能性は、元のビットが 1 であったということです。 存在保証により、この決定があいまいにならないことが保証されます。 

### ステップバイステップのアルゴリズム

 1. コンピューティング$$\text{ones} = \frac{\sum C_i}{n}.$$2. 差分配列を作成する`diff`。 
3. 右から左に位置をスキャンします。 
4. 保留中の差分更新を適用して、現在の累積効果を取得します。 
5. しましょう$$v = C_i + \text{current\_effect}.$$6. もし`v == ones`、 セット$A_i = 0$。 
7. それ以外の場合は設定します$A_i = 1$、 減少`ones`を作成し、この新たに配置されたものの貢献度を差分構造に登録します。 
8. 再構築されたバイナリ配列を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、既に再構築された位置のすべての寄与が現在処理中のサフィックスから削除されているという不変条件を維持します。 

位置で$i$、調整された値は、説明されていない情報を正確に表します。 0 は残りの 1 の現在のカウントを変更しないままにし、1 は残り 1 を消費して既知の寄与間隔を作成します。 入力は有効であることが保証されているため、これらの選択肢のうちの 1 つが不変式と一致します。 

位置を右から左に処理することにより、すべての寄与間隔は後でアクセスされる位置のみに影響を与えるため、差分配列はすべての更新を一定時間で処理できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        c = list(map(int, input().split()))

        ones = sum(c) // n

        diff = [0] * (n + 1)
        cur = 0
        ans = [0] * n

        for i in range(n - 1, -1, -1):
            cur += diff[i]

            val = c[i] + cur

            if val == ones:
                ans[i] = 0
            else:
                ans[i] = 1

                ones -= 1

                cur -= 1

                pos = i - ones
                if pos >= 0:
                    diff[pos] += 1

        print(*ans)

solve()
```最初のステップでは、1 の合計数を計算します。 これは、すべてのソートされたプレフィックス配列が 1 の数を保持するという事実から直接得られます。 

変数`cur`現在の位置でのアクティブな貢献度の合計を保存します。 影響を受けるすべてのインデックスを個別に更新する代わりに、差分配列を使用し、左に移動しながらその値を累積します。 

1 が配置されると、その寄与は連続した範囲に広がります。 アップデート```
cur -= 1
```そのコントリビューションを即座にアクティブ化しますが、```
diff[pos] += 1
```貢献が将来のポジションに影響を与えなくなる瞬間をスケジュールします。 

実装の最もデリケートな部分は、```
pos = i - ones
```デクリメント後に計算する必要があります`ones`。 この順序を逆にすると、すべての間隔が 1 位置ずつシフトされ、再構築が中断されます。

 ## 特殊なケース

 検討してください```
n = 1
C = [0]
```1 の合計数はゼロです。 スキャンにより、調整された値が残りの 1 の数に等しいことがすぐにわかります。したがって、答えは次のようになります。`[0]`。 

考慮する```
n = 1
C = [1]
```これで、1 の合計数は 1 になります。 調整された値は残りのカウントと異なるため、唯一の位置が強制的に 1 になります。 

考慮する```
n = 4
C = [0,0,0,4]
```計算された 1 の数は 1 です。 右端の位置は強制的に 1 になります。 その寄与は差分配列を通じて伝播され、以前の位置はすべてゼロになります。 これにより、間隔更新ロジックで最も一般的なオフバイワンの間違いが検出されます。 

考慮する```
n = 3
C = [0,0,0]
```更新はアクティブ化されません。 差分配列はスキャン全体を通じて空のままであり、実装が特別な場合を除いて差分配列の不在を処理していることを確認します。
