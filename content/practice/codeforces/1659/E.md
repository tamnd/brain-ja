 ## 解決策
 ## 問題の理解

 各エッジが より小さい非負の整数の重みを持つ、無向接続グラフが与えられます。$2^{30}$。 クエリでは、頂点からの歩行の可能な最小の「長さ」が求められます。$u$頂点へ$v$。 ウォークの「長さ」は通常とは異なります。ウォークに沿った一連のエッジについて、エッジの重みのすべてのプレフィックスのビットごとの AND をとり、これらすべてのプレフィックス AND の MEX を計算します。 MEX は、セット内に存在しない最小の非負の整数です。 

入力はグラフが接続されていることを保証するため、任意の 2 つの頂点間にウォークが常に存在します。 課題は、可能な限り最小の MEX を生成するウォークを見つけることです。 

と$n$そして$m$まで$10^5$そして$q$まで$10^5$、すべての四球を列挙する強引なアプローチは実行不可能です。 ビット単位の AND と MEX は、特定のゼロ ビットを持つエッジによって小さな MEX 値の可能性を排除できることを意味するため、重要な洞察には明示的なウォークではなくビット パターンが含まれる必要があります。 

ウォークのいずれかのエッジで重みが 0 である場合、微妙なエッジ ケースが発生します。 その場合、そのエッジを含むすべてのプレフィックスの AND は 0 になり、MEX は少なくとも 1 になります。もう 1 つの注意が必要なシナリオは、複数のエッジが同じ下位ビットを共有する場合です。 たとえば、すべてのエッジの重みが 2 以上の場合、プレフィックス AND は 0 を生成しないため、MEX 0 は自動的に達成可能です。AND プレフィックスを考慮せずに単にエッジを合計またはカウントする単純なアプローチでは、間違った答えが得られます。 

## アプローチ

 強引な方法は、次の間のすべての可能なウォークを考慮することです。$u$そして$v$、それぞれのプレフィックス AND を計算し、MEX を取得します。 ウォークの数は頂点とエッジの数に応じて指数関数的に増加するため、これは非現実的です。 たとえ散歩を単純な道に限定し、それらをすべてグラフに列挙したとしても、$10^5$頂点は無理です。 ブルートフォースは論理的には正しいですが、複雑です$O(\text{number of walks} \times \text{length of walk})$、合理的な制限時間を超えた場合。 

重要な洞察は、歩行に沿って移動すると、ビットごとの AND が単調減少するということです。 つまり、プレフィックス AND でビットが 0 になると、後続のすべてのプレフィックス AND では 0 のままになります。 したがって、プレフィックス AND の MEX は、主にエッジの重みの小さいビット、特にゼロ ビットの影響を受けます。 MEX = 0 にしたい場合は、ゼロに等しいプレフィックス AND が必要であることを観察することで、これを利用できます。 MEX = 1 にしたい場合は、すべてのプレフィックス AND がゼロ以外である必要がありますが、ゼロが欠落しているなどです。 

これを念頭に置くと、問題はクエリごとに最小の整数をチェックすることになります。$k$から歩いて行けるほど$u$に$v$プレフィックスがない場合、AND は次の値に等しい$k$。 これを効率的に行うために、ビット位置ごとに 1 つずつ、特定のビットが設定されている場合にのみエッジが存在する 30 個の個別のグラフを構築します。 次に、これらのサブグラフの接続を確認できます。 すべてのエッジにビットがあるサブグラフの接続性$i$set は、すべてのプレフィックス AND がビットのゼロを回避できるかどうかを示します$i$。 このビットマスク分解を使用すると、ウォークを列挙せずに MEX を決定できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(歩行回数 × 歩行距離) | O(四球数) | 遅すぎる |
 | 最適 (ビットマスク分解 + 接続性) | O(30 × (n + m) + q) | O(n × 30) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフ接続用に 3 つの配列を初期化します。 1 つ目は、エッジの重み (MEX ≥ 0 の場合) を無視して、各頂点が相互に到達可能かどうかを追跡します。 2 つ目は、ビット 0 が設定された重みを持つエッジを介して頂点に到達可能かどうかを追跡します (MEX ≥ 1 の場合)。 3 番目は、重みが 0 のエッジを介して頂点に到達可能かどうかを追跡します (MEX ≥ 2 の場合)。 
2. ビット パターンによってエッジを前処理します。 各エッジの重みについて、0 ～ 29 のビットを考慮します。設定されている各ビットのサブグラフにエッジを追加します。 エッジの重みが 0 の場合は、MEX = 2 を考慮して個別に追跡します。 
3. 各ビット グラフの Union-Find (DSU) 構造を構築します。 対応するビットが設定されているエッジで接続されている頂点をマージします。 これにより、各ビット マスクの頂点間の定時間接続クエリが可能になります。 
4. 各クエリ (u、v) について、すべてのビットが設定された (MEX = 0 の場合) エッジのサブグラフ内で u と v が接続されているかどうかを確認します。 「はい」の場合は、0 を出力します。そうでない場合は、最下位ビットが設定されているエッジの重み、または MEX = 1 の非ゼロの重みを持つ頂点に u が接続されているかどうかを確認します。接続されている場合は、1 を出力します。そうでない場合は、2 を出力します。 
5. 各クエリに対する回答を返します。 

機能する理由: Union-Find 接続は、ビットが設定されたエッジを介して 2 つの頂点が接続されている場合、それらの間のウォークは AND プレフィックスのビットを保持するという不変条件を保持します。 したがって、各ビット サブグラフの接続性をチェックすることで、実際のウォークを構築せずに MEX が 0、1、または 2 になるかどうかを判断できます。 AND は単調であるため、ビットが失われると、長いプレフィックスはそれを復元できず、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]
    def union(self, x, y):
        xr, yr = self.find(x), self.find(y)
        if xr != yr:
            self.parent[yr] = xr

n, m = map(int, input().split())
edges = []
for _ in range(m):
    a, b, w = map(int, input().split())
    edges.append((a-1, b-1, w))

dsu0 = DSU(n)
dsu1 = DSU(n)

for a, b, w in edges:
    if w == 0:
        dsu0.union(a, b)
    for bit in range(30):
        if (w >> bit) & 1:
            dsu1.union(a, b)

q = int(input())
queries = [tuple(map(lambda x: int(x)-1, input().split())) for _ in range(q)]

for u, v in queries:
    if dsu0.find(u) == dsu0.find(v):
        print(0)
    elif dsu1.find(u) == dsu1.find(v):
        print(1)
    else:
        print(2)
```DSU クラスは接続を効率的に処理します。 2 つの DSU を維持します。1 つは重みがゼロのエッジ用で、もう 1 つは少なくとも 1 ビットが設定されているエッジ用です。 各クエリについて、最初に MEX = 0 のゼロ重み接続をチェックします。そうでない場合は、MEX = 1 の非ゼロ ビットを持つエッジの接続をチェックします。どちらにも当てはまらない場合、可能な最小 MEX は 2 です。
