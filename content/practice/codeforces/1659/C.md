 ## 解決策
 ## 問題の理解

 数直線上の位置 0 から始まる王があり、厳密に位置が増加しているいくつかの未征服の王国があります。 王は最小限の費用ですべての王国を征服したいと考えています。 彼には 2 つの作戦があります: 距離時間に比例したコストで既に征服された王国に首都を移動する`a`、距離時間に比例したコストで現在の首都から王国を征服します。`b`ただし、首都とターゲットの間に未征服の王国がない場合に限ります。 

入力により、王国の数、2 つのコスト、王国の位置がわかります。 出力は、すべての王国を征服するための最小総コストです。 制約により、すべてのテスト ケースにわたって最大 200,000 王国が許可されるため、ソリューションは王国数が線形またはほぼ線形である必要があります。 すべての王国ペアを考慮する二次アルゴリズムは直ちに除外されます。 

首都を征服するよりも移転コストが安い場合、微妙なエッジケースが発生します（`a < b`）。 そのシナリオでは、段階的に征服するのではなく、頻繁に首都を前進させることが最適である可能性があります。 もう一つは、首都を移転するよりも征服した方が安い場合です（`b < a`)、その場合、大幅なジャンプが必要になるまで首都の移転を遅らせたくなるかもしれません。 このようなシナリオでは、単純な左から右への移動なしの征服戦略では、最適なソリューションを簡単に超えてしまう可能性があります。 

たとえば、2 つの王国が 1 位と 5 位にある場合、`a=1`そして`b=10`、順番に征服するという単純な戦略はコストをもたらします`1*10 + 1*4=14`、最初に資本を1に移動し、次に5つのコストを征服しながら`1*1 + 10*4 = 41`間違って実行された場合。 首都をいつ移転するかを選択するには、慎重な分析が必要です。 

## アプローチ

 強引なアプローチは、資本移動と征服作戦のすべてのシーケンスを試みることです。 各王国について、現在の首都から直接征服することも、首都を前の王国に移動してそこから征服することもできます。 各ステップで考えられるすべての資本位置を追跡すると、サイズ O(n²) の動的計画表が得られます。 これは、考えられるすべての選択肢を列挙するので正しいですが、遅すぎます。n が 2×10⁵ までの場合、O(n²) の演算は不可能です。 

重要な洞察は、王国は厳密に線に沿って増加しているため、首都から隣接するセグメントを征服するコストは距離に比例し、首都の移動は以前に征服された王国にのみ発生するということです。 これは、どの王国でも単純な繰り返しを生み出します。`i`、資本を維持するための最小コスト`i`の最小資本コストを使用して表すことができます。`i-1`。 追跡する必要があるのは 2 つの状態だけです。最後に征服された王国で首都を取得するためのコスト、または最後から 2 番目の王国で首都を取得するためのコスト (さらに 1 つの未征服王国を移動せずに征服できる)。 これにより、DP が線形スイープに減少します。 

形式的には、`dp[i]`最初の条件を克服するための最小コストを表します`i`に首都を持つ王国`i`。 それから`dp[i]`から計算できます`dp[i-1]`次の王国を直接征服するか、前の王国に首都を移すかを検討します。 コスト関数は線形であり、ポジションは増加しているため、最も近い以前の資本のみが問題となります。 これにより、テスト ケースあたりの複雑さが O(n) に軽減されます。

 ## アルゴリズムのチュートリアル

 1. 首都を位置 0 から開始し、征服された王国はありません。 2 つの変数を初期化します。`cost_if_capital_at_last`前の王国までの首都を征服するための費用として、そして`cost_if_capital_before_last`前の王国の首都を前王国まで征服するための費用として。 当初は、`cost_if_capital_at_last = 0`そして`cost_if_capital_before_last = 0`。 
2. 最初から最後まで王国を繰り返します。 各王国で、現在の首都から直接征服するか、首都を前の王国に移動してから征服するかの 2 つのオプションを考慮して、征服するための最小コストを計算します。 
3. 直接征服するためのコストは次のとおりです。`b * distance_from_current_capital`。 首都を移転するのにかかる費用は、`a * distance_to_previous_capital`、 それから`b * distance_from_new_capital_to_target`。 これらのオプションのうち最小限のものを選択してください。 
4. 次の反復の新しい「最後」および「最後より前」の首都状態を表すように追跡変数を更新します。 
5. すべての王国を処理した後、最小総コストは、最後の王国で首都を獲得するために最後に計算された値になります。これは、最後の王国の征服はどこかの首都で終了する必要があり、それ以上の移動は必要ないためです。 

機能する理由: 不変条件は、各ステップで追跡されるコストがその状態 (最後の首都または最後から 2 番目の王国) に到達するための最小コストを表すということです。 ポジションは厳密に増加しており、コストは距離に対して線形であるため、隣接しない以前の資本はより良いコストを生み出す可能性はなく、最後の 2 つの状態のみを考慮する必要があります。 これにより、線形計算のみを使用しながら全体的な最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, a, b = map(int, input().split())
        x = list(map(int, input().split()))
        
        last_cost = 0
        capital_pos = 0
        
        for i in range(n):
            dist_from_capital = x[i] - capital_pos
            # conquer directly from current capital
            cost_conquer = last_cost + b * dist_from_capital
            # move capital to previous kingdom if not the first, then conquer
            if i > 0:
                dist_move = x[i] - x[i-1]
                cost_move_and_conquer = last_cost + a * dist_move + b * dist_from_capital
                cost_conquer = min(cost_conquer, cost_move_and_conquer)
            
            last_cost = cost_conquer
            # optionally move capital greedily if a < b
            if i == 0 or a < b:
                capital_pos = x[i]
        
        print(last_cost)

if __name__ == "__main__":
    solve()
```コードはランニング コストを維持し、2 つの操作を使用して王国ごとに更新します。 微妙な部分は、首都をいつ移動するかを決定することです。移動コストが征服コストよりも低い場合、首都を直ちに移動すると、将来の征服距離が短縮されます。 境界条件には首都の移動が不要な第一王国が含まれます。 ポジションは厳密に増加しているため、距離は常にプラスになります。
