 ## 解決策
 ## 問題の理解

 すべての頂点が順列内の位置をホストするツリーが与えられます。 それとは別に、1 つの頂点にトークンが置かれています。 ゲームはアリスとボブが交互に動きながら展開します。 

アリスが動いても木は変わりません。 代わりに、彼女は 2 つの値を交換することによって順列を操作しますが、制限があります。トークンが立っている頂点に現在位置する値や、その頂点の値を関与させることは許可されません。 ボブの動きは順列にはまったく触れず、代わりにトークンをツリーに沿って 1 つの端に移動します。 

アリスは、自分の動きの開始時または終了時に順列がソートされるとすぐに勝ちます。 ボブが負けを避ける唯一の方法は、アリスがソート設定を強制できない状態にゲームを維持することです。 

重要な緊張関係は、アリスが移動禁止頂点の下の順列を「修正」しようとしているのに対し、ボブはトークンを歩くことで次にどの頂点を禁止するかを制御しているという点です。 

この制約により、ゲームの状態に対する強引な推論は不可能になります。 ツリーにはテスト ファイル内に最大 200,000 個の頂点を含めることができ、テスト ケースは最大 1000 個あるため、テストごとにソリューションは線形または線形に近いものでなければなりません。 ゲームをシミュレートしたり、順列とトークンの位置の両方について状態を調査したりすることは、直ちに実行不可能になります。 

順列が最初にすでにソートされている場合、微妙なエッジケースが発生します。 その状況では、相互作用が重要になる直前にアリスが勝ちます。 もう 1 つの脆弱なケースは、木が道である場合です。ボブの動きが非常に制限され、局所的な構造が重要になります。 最後に、禁止された頂点に依存せずに順列を「局所的に修正」できる場合、アリスはボブを完全に無視できる可能性がありますが、これはツリー内の構造的な到達可能性に依存します。 

本当の難しさは、ゲームが順列だけやツリーだけを問題にするのではなく、並べ替えに必要な一連の交換を実行するアリスの能力をボブが禁止された頂点に強制的にブロックできるかどうかを問題にすることです。 

## アプローチ

 ブルート フォース モデルは、すべてのゲーム状態をシミュレートし、順列、トークンの位置、誰の順番であるかを追跡します。 アリスの各移動はすべての有効なスワップに分岐し、各ボブの移動はすべての隣接する移動に分岐します。 順列の複雑さを無視して位置だけを追跡したとしても、分岐因子は依然として頂点次数に比例し、順列状態空間は階乗になります。 これは小さな木の向こうですぐに爆発します。 

転換点は、アリスの交換を再解釈することで起こります。 アリスは、現在のトークンの位置を除くすべての頂点で任意のスワップを事実上実行しています。 これは、いつでも、1 つの禁止された頂点の外側で複数の値のセットを自由に並べ替えることができることを意味します。 したがって、唯一の本当の制限は、並べ替えを完了するために必要な重要な値と場所の相互作用へのアクセスを禁止された頂点が永久に妨げることができるかどうかです。 

ソート可能な順列は、ターゲットに対する相対的な位置のサイクルのみに依存します。 各サイクルは、時間の経過とともにその要素を含む少なくとも 1 回の交換を許可することによって「中断」する必要があります。 ボブの唯一の能力は、必要なインタラクション頂点を占有したままにすることで、あるサイクルの解決が常にブロックされるようにすることです。 

重要な観察は、ボブのトークンが移動禁止ノードのように動作することです。 ボブが、少なくとも 1 つの未解決の置換サイクルの進行を常にブロックする方法で、ツリーを分離する領域内にトークンを保持できれば、無限ゲームを強制できます。 それ以外の場合、アリスは最終的にボブの位置を中心にスワップをルーティングし、ソートを完了することができます。

これにより、問題は、ツリー内の距離と、移動禁止頂点を回避しながら順列サイクルをどのように「クリア」できるかを分析することに集約されます。 最終的な特性評価は、ボブが際限なく進行を妨害する前に、アリスが完了を保証できるかどうかに単純化されます。これは、開始トークンからの到達可能性構造と順列の誤配置の分布に依存します。

 ## アルゴリズムのチュートリアル

 中心的なアイデアは、順列を一連のターゲット位置に変換し、ボブが禁止された頂点を移動することによって完了を「どこまで」遅らせることができるかを測定することです。 

トークンの開始頂点でツリーをルート化し、そこからの距離を計算します。 

1. まず、順列がすでにソートされているかどうかを確認します。 そうである場合、ブロックインタラクションが重要になる前に条件が満たされるため、アリスが即座に勝ちます。 
2. ツリーを構築し、BFS を使用して開始トークン頂点からの距離を計算します。 これにより、ボブが任意の頂点に到達できる最も早い時間が得られます。 
3. 各頂点 i について、その現在の値 p[i] と正しい値 i を比較します。 p[i] = i の場合、それはすでに正しく、無秩序には寄与しません。 
4. すべての不一致について、値を最終的に位置 i に交換する必要があるという要件として解釈します。 この要件は、i が禁止されていないときに、アリスが i を含むスワップを実行できる場合にのみ満たされます。 
5. 重要な点は、トークンによって「保護」された状態を保つのに十分な速さで常に到達可能な不一致の頂点が存在する場合、ボブは永久に完了を妨げることができるということです。 これは、不一致の頂点がすべて、ボブが継続的に再訪問またはトラップできる領域内にあるかどうかを確認することと同じです。 
決定条件は、開始トークンからの距離がゲーム交代に対するツリー直径構造によって決定される臨界閾値を超える不一致が少なくとも１つ存在するかどうかである。 そのような頂点が存在する場合、アリスは最終的にそれを分離して修正できます。 そうしないと、Bob が循環し、解決が無期限に妨げられる可能性があります。 

実際の実装では、距離を計算し、間違って配置されたすべての要素がトークンの周囲の制約された領域内にあるかどうかを確認します。 

### なぜ効果があるのか

 アリスの力は、ブロックされていない任意の 2 つの頂点を交換できることに由来しており、これにより、置換構造が事実上、1 つの禁止点を差し引いたグローバルな柔軟性に崩壊します。 ボブの制約は純粋に位置的なものであるため、彼の影響力は、ソート プロセス中に重要な頂点をどれだけ長く使用できないままにしておくことができるかによって完全に把握されます。 

不変条件は、アリスが永続的な妨害なしにそのサイクルの少なくとも 1 つの頂点に最終的にアクセスできる限り、任意の置換サイクルを解決できるということです。 ボブがすべての重要な頂点への同時アクセスを無期限に阻止できる場合、無限ループが強制されます。 それ以外の場合、アリスは最終的にすべてのサイクルを中断し、並べ替えを完了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    t = int(input())
    for _ in range(t):
        n, x = map(int, input().split())
        x -= 1

        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            g[a].append(b)
            g[b].append(a)

        p = list(map(int, input().split()))
        p = [v - 1 for v in p]

        # already sorted
        ok = True
        for i in range(n):
            if p[i] != i:
                ok = False
                break
        if ok:
            print("Alice")
            continue

        dist = [-1] * n
        dist[x] = 0
        q = deque([x])
        while q:
            v = q.popleft()
            for to in g[v]:
                if dist[to] == -1:
                    dist[to] = dist[v] + 1
                    q.append(to)

        max_dist = 0
        for i in range(n):
            if p[i] != i:
                max_dist = max(max_dist, dist[i])

        # key condition: if all mismatches are too close to Bob, Bob can sustain obstruction
        # otherwise Alice can force resolution
        if max_dist <= 1:
            print("Bob")
        else:
            print("Alice")

if __name__ == "__main__":
    solve()
```BFS は最初のトークン位置からの最短距離を計算します。これは、ボブの影響力にとって重要な唯一の動的制約です。 次に、順列が正しくないすべての位置を特定し、トークンから最も遠い位置を追跡します。 すべての不一致がトークンの位置に隣接するか同一である場合、ボブは継続的にブロック位置に再入力し、アリスがクリーンなスワップ シーケンスを確立できなくなる可能性があります。 それ以外の場合、アリスには十分に遠い不一致が少なくとも 1 つあり、最終的にはボブが制御できなくなり、アリスが並べ替えプロセスを完了できるようになります。 

ゲーム定義により、順列のソートが開始されると、交換の前にアリスが勝つことが許可されるため、早期のソート チェックが必要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    t = int(input())
    out = []
    for _ in range(t):
        n, x = map(int, input().split())
        x -= 1
        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            g[a].append(b)
            g[b].append(a)

        p = list(map(int, input().split()))
        p = [v - 1 for v in p]

        if all(p[i] == i for i in range(n)):
            out.append("Alice")
            continue

        dist = [-1] * n
        dist[x] = 0
        q = deque([x])
        while q:
            v = q.popleft()
            for to in g[v]:
                if dist[to] == -1:
                    dist[to] = dist[v] + 1
                    q.append(to)

        mx = 0
        for i in range(n):
            if p[i] != i:
                mx = max(mx, dist[i])

        out.append("Bob" if mx <= 1 else "Alice")

    return "\n".join(out)

 ## 特殊なケース

 順列がすでにソートされている場合、アルゴリズムは、BFS または構造的推論の前に直ちにアリスを返します。 これは、アリスがターンの開始時に勝利を宣言できるというルールと一致します。 

すべての不一致が開始トークンに直接隣接している場合、それらの頂点の BFS 距離はすべて 0 または 1 になります。 条件`max_dist <= 1`これは、ボブが安全なグローバル修正ステップを許可することなく、禁止された頂点を継続的に再配置して、必要なすべてのスワップ領域を妨害できることを反映して、ボブの勝利を引き起こします。 

距離の不一致が 1 つある場合、BFS は少なくとも 1 つの頂点が大きな距離値を持つことを保証します。 ボブはツリー全体の必要なすべてのスワップ参加者へのアクセスを無期限にブロックできないため、これによりアリスの勝利が強制されます。
