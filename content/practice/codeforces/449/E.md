 ## 解決策
 ## 問題の理解

 サイズの長方形の中にすべての格子点があります$n \times m$。 4 つの頂点が格子点である正方形は、回転していても許可されます。 

このような正方形ごとに、その中に完全に含まれる単位グリッド セルを調べます。 含まれる各単位セルは 1 つのドットを受け取ります。 セルは多くの異なる正方形からドットを受け取ることがあります。 タスクは、ペイントされたドットの総数を数えるということです。 

入力には最大で次のものが含まれます$10^5$テストケース、両方とも$n$そして$m$と同じ大きさにすることができます$10^6$。 クエリごとに意味のある作業を実行するソリューションは、すでに危険にさらされています。 たとえ$O(\sqrt n)$最悪の場合、テストごとのソリューションは高価になりすぎます。 重い作業は前処理で 1 回実行する必要があり、その後は各クエリに一定時間内に応答する必要があります。 

難しいのは、正方形が軸に沿って配置されるように制限されていないことです。 単純な実装では、辺がグリッドに従う通常の正方形のみをカウントすることが多く、これではほとんどの答えが得られません。 

考慮する：```
n = 2, m = 2
```4つの単位正方形の他に、頂点を持つひし形の正方形もあります```
(1,0), (2,1), (1,2), (0,1)
```内部に 1 つの単位セルが完全に含まれているため、回転した正方形を無視すると、正しい値よりも小さな答えが生成されます。$8$。 

もう 1 つの簡単な間違いは、正方形の中に完全に含まれるセルではなく、正方形と交差するセルを数えることです。 上のひし形の場合、いくつかのセルが境界に触れていますが、完全に内側にあるのは中央のセルだけです。 

バグの 3 番目の原因は、正方形の説明を二重にカウントすることです。 辺ベクトルによって生成された正方形$(a,b)$によって生成されたものと同じ形状です$(b,a)$ただし、これらはグリッド内の異なる配置に対応しており、すべての有効な方向を合計する場合は両方を含める必要があります。 

## アプローチ

 最も直接的なアイデアは、すべての格子正方形を列挙することです。 

正方形の格子は開始頂点と辺ベクトルで記述できます。$(a,b)$。 2 番目の辺は、そのベクトルを次のように回転することによって取得されます。$90^\circ$、与える$(-b,a)$。 4 つの頂点がすべて長方形の内側に収まると、有効な正方形が得られます。 

正方形を生成した後、すべての単位セルをテストし、その中に完全に存在する単位セルの数を数えることができます。 

これは正しいですが、絶望的に遅いです。 すでにあります$O(n^2m^2)$頂点の組み合わせが考えられるため、すべてのセルの包含をチェックすると事態はさらに悪化します。 と$n,m \le 10^6$、ブルートフォースは遠隔からは実行可能ではありません。 

重要な観察は、格子正方形の幾何学形状はその側ベクトルのみに依存するということです。 

側ベクトルを取る$(a,b)$と$a,b \ge 0$。 格子正方形を含む軸に沿った最小の正方形の一辺の長さは$$L=a+b.$$同じ値を持つすべての正方形$L$は、まったく同じ数の可能な配置があります。$$(n-L+1)(m-L+1).$$したがって、最初に位置を考える代わりに、すべての格子正方形を次のように分類できます。$L$。 

次のステップは、によって生成された正方形の中に完全に含まれる単位セルの数を決定することです。$(a,b)$。 

幾何学的分解により、$$f(a,b)=a^2+b^2-2(a+b)+2\gcd(a,b).$$これにより、幾何学の問題が純粋な算術に変換されます。 

固定の場合$$L=a+b,$$定義する$$F(L)=\sum_{a=0}^{L-1} f(a,L-a).$$次に、境界サイズを持つすべての正方形$L$同じ価値観を通じて貢献する$F(L)$、そして答えは次のようになります$$\sum_{L=1}^{\min(n,m)} (n-L+1)(m-L+1)F(L).$$今では整数論だけが残っています。 

使用する$$\gcd(a,L-a)=\gcd(a,L),$$私たちは得る$$F(L) = \frac{2L^3+L}{3} -2L^2 + 2\sum_{a=0}^{L-1}\gcd(a,L).$$古典的なアイデンティティ$$\sum_{a=0}^{L-1}\gcd(a,L) = \sum_{d\mid L} d\,\varphi(L/d)$$のすべての値を許可します$F(L)$まで$10^6$除数ふるいで事前に計算されます。 

最後に拡張します$$(n-L+1)(m-L+1) = (n+1)(m+1) -(n+m+2)L +L^2.$$のプレフィックス合計を保存すると、$$F(L),\quad L F(L),\quad L^2 F(L),$$各クエリは$O(1)$式。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 有効グリッド サイズは指数関数的であり、それをはるかに超えています$O(n^2m^2)$| 巨大な | 遅すぎる |
 | 最適 | 前処理$O(N \log N)$、クエリ$O(1)$|$O(N)$| 承認済み |

 ここ$N = 10^6$。 

## アルゴリズムのチュートリアル

 1. オイラーの合計関数を事前計算する$\varphi(i)$みんなのために$i \le 10^6$直線ふるいを使用します。 
2. コンピューティング$$G(i)=\sum_{d\mid i} d\,\varphi(i/d).$$これは、すべての約数を反復処理することで実行できます。$$G(j) += i \cdot \varphi(j/i).$$全体の複雑さは次のとおりです。$O(N \log N)$。 

1. あらゆる人にとって$L$から$1$に$N$、計算する$$F(L) = \frac{2L^3+L}{3} -2L^2 + 2G(L).$$すべての算術は剰余として取得されます$10^9+7$。 

1. 3 つのプレフィックス配列を構築します。$$S_0(x)=\sum_{L\le x}F(L),$$

$$S_1(x)=\sum_{L\le x}L\,F(L),$$

$$S_2(x)=\sum_{L\le x}L^2F(L).$$1. クエリの場合、swap$n,m$必要に応じてそのように$n \le m$。 
2. しましょう$k=n$。 すべての有効な正方形は次の条件を満たさなければなりません$L \le k$。 
3. 拡張機能を使用する$$(n-L+1)(m-L+1) = (n+1)(m+1) -(n+m+2)L +L^2.$$1. プレフィックスの合計を次のように置き換えます。$$\text{ans} = (n+1)(m+1)S_0(k) -(n+m+2)S_1(k) +S_2(k).$$1. 結果のモジュロを出力します。$10^9+7$。 

### なぜ効果があるのか

 側ベクトルによって生成されたすべての格子正方形$(a,b)$～と一意に関連付けられています$L=a+b$、軸に揃えられた最小の境界正方形の辺の長さ。 

固定の場合$L$、そのような正方形はすべて正確に$(n-L+1)(m-L+1)$配置。 幾何学的公式は、各形状の完全に含まれる単位セルの数を計算し、すべてのペアの合計を計算します。$(a,L-a)$生成する$F(L)$。 

除数の恒等式は、gcd 寄与を乗算算術関数に変換し、すべての演算を可能にします。$F(L)$事前に計算される値。 すべての有効な正方形はちょうど 1 つの値に属するため、$L$、すべての配置は 1 回だけカウントされ、最終的な合計はペイントされたドットの総数に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007
MAXN = 1000000

phi = [0] * (MAXN + 1)
primes = []
is_comp = [False] * (MAXN + 1)

phi[1] = 1
for i in range(2, MAXN + 1):
    if not is_comp[i]:
        primes.append(i)
        phi[i] = i - 1
    for p in primes:
        v = i * p
        if v > MAXN:
            break
        is_comp[v] = True
        if i % p == 0:
            phi[v] = phi[i] * p
            break
        phi[v] = phi[i] * (p - 1)

g = [0] * (MAXN + 1)

for d in range(1, MAXN + 1):
    step = d
    for x in range(d, MAXN + 1, step):
        g[x] = (g[x] + d * phi[x // d]) % MOD

inv3 = pow(3, MOD - 2, MOD)

s0 = [0] * (MAXN + 1)
s1 = [0] * (MAXN + 1)
s2 = [0] * (MAXN + 1)

for L in range(1, MAXN + 1):
    l = L % MOD

    part = ((2 * l * l % MOD) * l + l) % MOD
    part = part * inv3 % MOD

    f = (part - 2 * l * l + 2 * g[L]) % MOD

    s0[L] = (s0[L - 1] + f) % MOD
    s1[L] = (s1[L - 1] + l * f) % MOD
    s2[L] = (s2[L - 1] + l * l % MOD * f) % MOD

t = int(input())

ans = []
for _ in range(t):
    n, m = map(int, input().split())

    if n > m:
        n, m = m, n

    k = n

    res = (
        (n + 1) * (m + 1) % MOD * s0[k]
        - (n + m + 2) % MOD * s1[k]
        + s2[k]
    ) % MOD

    ans.append(str(res))

sys.stdout.write("\n".join(ans))
```線形ふるいは、すべての合計を計算します。$O(N)$。 その後、除数ループは以下を評価します。$$G(x)=\sum_{d\mid x} d\varphi(x/d)$$あらゆる人にとって$x$。 

の式は、$F(L)$3 による除算が含まれます。 計算は素数を法として行われるため、通常の整数除算の代わりに 3 の逆剰余が使用されます。 

プレフィックス配列は、定数時間クエリ処理の中核です。 一度$$\sum F(L), \quad \sum L F(L), \quad \sum L^2F(L)$$が利用可能であれば、拡張された 2 次重みをすぐに評価できます。 

よくある実装上の間違いは、スワップを忘れることです$n$そして$m$。 合計は最大までしか実行されません$\min(n,m)$、境界サイズを持つ正方形であるため、$L$場合は適合しません$L$いずれかの次元を超えます。 

もう 1 つの簡単なバグは、剰余を取得した後に通常の整数の除算を使用することです。 3 次項には 3 の逆剰余を乗算する必要があります。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from math import gcd

MOD = 1000000007

def brute(n, m):
    ans = 0

    for x in range(n + 1):
        for y in range(m + 1):
            for a in range(-n, n + 1):
                for b in range(-m, m + 1):
                    if a == 0 and b == 0:
                        continue

                    pts = [
                        (x, y),
                        (x + a, y + b),
                        (x - b, y + a),
                        (x + a - b, y + a + b),
                    ]

                    ok = True
                    for px, py in pts:
                        if not (0 <= px <= n and 0 <= py <= m):
                            ok = False
                            break

                    if not ok:
                        continue

                    # avoid counting same square four times
                    if (a < 0) or (a == 0 and b < 0):
                        continue

                    minx = min(p[0] for p in pts)
                    maxx = max(p[0] for p in pts)
                    miny = min(p[1] for p in pts)
                    maxy = max(p[1] for p in pts)

                    def inside(cx, cy):
                        s = []
                        for i in range(4):
                            x1, y1 = pts[i]
                            x2, y2 = pts[(i + 1) % 4]
                            s.append(
                                (x2 - x1) * (cy - y1)
                                - (y2 - y1) * (cx - x1)
                            )
                        return all(v >= 0 for v in s) or all(v <= 0 for v in s)

                    for i in range(minx, maxx):
                        for j in range(miny, maxy):
                            corners = [
                                (i, j),
                                (i + 1, j),
                                (i, j + 1),
                                (i + 1, j + 1),
                            ]
                            if all(inside(cx, cy) for cx, cy in corners):
                                ans += 1

    return ans

def run(inp: str) -> str:
    data = inp.strip().split()
    t = int(data[0])

    out = []
    ptr = 1
    for _ in range(t):
        n = int(data[ptr])
        m = int(data[ptr + 1])
        ptr += 2
        out.append(str(brute(n, m)))
    return "\n".join(out)

# thin rectangle
assert run("1\n1 2\n") == "2", "no room for rotated squares"

# symmetric small case
assert run("1\n2 2\n") == "8", "rotated square contribution"

# off-by-one on bounding size
assert run("1\n2 3\n") == "14", "largest L fits exactly once"

 ## 特殊なケース

 次のことを考慮してください。```
1
1 2
```のみ$L=1$フィットします。 アルゴリズムが評価するのは、$$(1-1+1)(2-1+1)F(1)=2.$$これより大きな境界正方形は収まらないため、$L=2>\min(n,m)$。 答えはまさに 2 つの単位セルです。 

次に、次のことを考えてみましょう。```
1
2 2
```合計には次のものを使用します$L=1$そして$L=2$。 

のために$L=2$、ペア$(1,1)$菱形の正方形を表します。 その貢献は内部に含まれています$F(2)$、そのため、結果は次のようになります$8$の代わりに$4$。 

最後に、次のことを考慮してください。```
1
3 3
```単に正方形の境界と交差するセルをカウントする不注意な解決法では、カウントが過剰になってしまいます。 の式は、$f(a,b)$正方形の中に完全に含まれるセルに特化して導出されました。 gcd 項は境界上の格子点に由来し、部分的に覆われたセルを正確に削除します。 この幾何学的補正により、算術公式はすべての方向に対して正確なままになります。
