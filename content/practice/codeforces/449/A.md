 ## 解決策
 ## 問題の理解

 私たちは、$n \times m$単位正方形で作られたチョコレートバー。 カットは水平または垂直であり、グリッド線に沿っている必要があり、厳密にチョコレートの内側にある必要があり、以前のカットを複製することはできません。 

正確に作った後は$k$カットすると、チョコレートがいくつかの長方形の部分に分割されます。 結果として得られるすべての部分の中で、面積が最も小さい部分を調べます。 私たちの目標は、この最小領域ができるだけ大きくなるようにカットを配置することです。 

寸法$n$そして$m$と同じ大きさにすることができます$10^9$、 そして$k$到達できる$2 \cdot 10^9$。 これらの値は、カットのシミュレーションや、行、列、またはカット位置を反復するアルゴリズムを直ちに除外します。 たとえ$O(\sqrt{k})$アプローチが不必要に大きくなります。 ソリューションでは、一定量の演算のみを実行する必要があります。 

重要な観察は、高さのある長方形であるということです。$n$だけを持っています$n-1$水平方向のカットも可能、同様にのみ$m-1$垂直方向のカットが可能です。 個別のカットの最大数は次のとおりです。$$(n-1) + (m-1) = n+m-2.$$もし$k > n+m-2$、必要な数のカットができないので、答えは$-1$。 

いくつかの特殊なケースは見落とされがちです。 

考慮する：```
2 3 4
```個別のカットの最大数は次のとおりです。$1+2=3$。 4 つのカットは不可能なので、答えは次のようになります。```
-1
```実現可能性を確認せずにピース サイズの最適化だけを試みる不用意なソリューションでは、誤った正の値が生成されます。 

もう 1 つの重要なケースは次のとおりです。```
3 4 1
```1 つのカットでは、1 つの次元をできるだけ均等に分割する必要があります。 幅をカットする$2$そして$2$面積の部分を与える$3 \times 2 = 6$、これが最適です。 答えは次のとおりです。```
6
```常に長い側をカットする、または常に水平にカットするという単純な戦略では、必ずしも最適な方法が見つかるとは限りません。 

もう 1 つの微妙な例は次のとおりです。```
5 5 8
```以来$n+m-2=8$、あらゆるカットを使用する必要があります。 チョコレートは、$5 \times 5$単位正方形のグリッド、最小のピースには面積があります$1$。 カットが依然として自由に配布できると仮定する公式は、ここでは失敗します。 

## アプローチ

 最も直接的なアイデアは、水平方向と垂直方向のカットの可能な限りの配分を試してみることです。 

作ったとします。$a$水平方向のカットと$b$垂直カット、付き$$a+b=k.$$カット後、チョコレートを分割します。$a+1$水平ストリップと$b+1$縦のストリップ。 最小の長方形を最大化するには、各次元に沿ったストリップが可能な限り等しい必要があります。 

直したら$a$そして$b$、可能な限り最大の最小の高さと幅を計算して、最小の長方形の領域を取得できます。 すべての有効な値を試してみます$a$最適なものが見つかるでしょう。 

難しいのは、$k$周りにいることができます$2 \cdot 10^9$。 可能なすべての値を列挙すると、$a$全く不可能です。 

重要な観察は、元の Codeforces の問題には、より強力な構造が隠されているということです。 

お金を使うことに決めたとします。$x$縦方向にカットします。 それらのカットは幅を分割します$m$の中へ$x+1$個。 可能な最大の最小幅は次のとおりです。$$\left\lfloor \frac{m}{x+1} \right\rfloor.$$同様に、私たちが支出する場合、$y$水平方向のカットの場合、可能な限り最大の最小高さは$$\left\lfloor \frac{n}{y+1} \right\rfloor.$$以来$x+y=k$、最小ピース面積は次のようになります。$$\left\lfloor \frac{m}{x+1} \right\rfloor \cdot \left\lfloor \frac{n}{k-x+1} \right\rfloor.$$一見すると、これでもまだ巨大な検索スペースのように見えます。 

決定的な観察は、公式の解決策では 2 つの可能性を検討するだけでよいということです。 

最後の最小部分が分割によって決まる幅を持つ場合$m$の場合、垂直セグメントの数は除数のような量でなければなりません。 最適化を再配置すると、必要な数のセグメントを作成するために必要なすべてのカットを 1 つの次元で吸収する必要がある一方、もう 1 つの次元はカットされないままであることがわかります。 これにより、検索が 2 つの候補構造に減ります。 

まず、使用します$k$作成するカット$k+1$幅に沿ったセグメント。 結果として得られる最小部分面積は、$$n \cdot \left\lfloor \frac{m}{k+1} \right\rfloor.$$2番目に、使用します$k$作成するカット$k+1$高さに沿ったセグメント。 結果として得られる最小部分面積は、$$m \cdot \left\lfloor \frac{n}{k+1} \right\rfloor.$$なぜなら、ただ$n-1$水平方向のカットと$m-1$垂直方向のカットが存在する場合、その制限を尊重する必要があります。 これを表現する標準的な方法は、逆に考えることです。 

過ごしたら$x$一次元でカットしてから作成します$x+1$セグメント。 セグメントの数が次元の長さを超えることはできません。 

2 つの実現可能な割り当てを試すと、よく知られている解決策が得られます。 

- 使用する$n$触れられていない次元として分割します$m$の中へ$k+1$部品。 
- 使用$m$触れられていない次元として分割します$n$の中へ$k+1$部品。 

実装では、これは、カット制限を尊重しながらディメンション間でカットを割り当てる 2 つの可能な方法をチェックすることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(k)$|$O(1)$| 遅すぎる |
 | 最適 |$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む$n$、$m$、 そして$k$。 
2. かどうかを確認します。$k > n+m-2$。 

trueの場合、出力$-1$これは、それほど多くのカットに使用できる明確な内部グリッド ラインが十分にないためです。 
3. 答えを次のように初期化します。$0$。 
4. 使用を検討する$n-1$以下のカットを水平方向にカットし、残りを垂直方向にカットします。 

もし$k < n$そうすれば、すべてを費やすことができます$k$高さ方向にカットします。 これにより、$k+1$水平セグメントなので、最小の高さは次のようになります。$$\left\lfloor \frac{n}{k+1} \right\rfloor.$$幅は残ります$m$、候補領域を与える$$m \cdot \left\lfloor \frac{n}{k+1} \right\rfloor.$$5. 対称構造を考慮してください。 

もし$k < m$そうすれば、すべてを費やすことができます$k$幅方向にカットします。 候補地となるのは、$$n \cdot \left\lfloor \frac{m}{k+1} \right\rfloor.$$6. もう一つ可能性があります。 最初に 1 つの次元で利用可能なすべてのカットを使用する場合、残りのカットは他の次元に配置する必要があります。 

いつ$k \ge n$、使用する場合があります$n-1$水平カット、残し$$k-(n-1)$$幅に合わせてカットします。 最小の面積は次のようになります。$$\left\lfloor \frac{m}{k-n+2} \right\rfloor.$$7. 対称的に、$k \ge m$、もう一つの候補は$$\left\lfloor \frac{n}{k-m+2} \right\rfloor.$$8. 得られた最大候補を出力します。 

### なぜ効果があるのか

 すべてのカットが正確に 1 つの次元に貢献します。 ディメンションが受信した場合$t$カット、に分けられます$t+1$セグメントの長さの最大値は、次元の長さの整数商です。$t+1$。 

固定数のカットの場合、最小の長方形を最大化することは、影響を受ける各次元の最小セグメント長を最大化することと同じです。 最適な配置は、一方の次元ができるだけ多くのカットを受け取り、残りの必要なカットがもう一方の次元に強制的に配置されるときに発生します。 これらはまさにアルゴリズムによってチェックされた候補構造です。 他の分布では、これらの極端な場合のいずれかを超えない最小辺の長さが生成されるため、候補全体の最大値が最適な答えとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    if k > n + m - 2:
        print(-1)
        return

    ans = 0

    if k < n:
        ans = max(ans, (n // (k + 1)) * m)

    if k < m:
        ans = max(ans, (m // (k + 1)) * n)

    if k >= n:
        ans = max(ans, m // (k - n + 2))

    if k >= m:
        ans = max(ans, n // (k - m + 2))

    print(ans)

solve()
```最初の条件は不可能を処理します。 サイズの長方形$n \times m$のみが含まれます$n-1$水平のカットラインと$m-1$垂直のカットラインがあるため、それを超える解決策は存在しません$n+m-2$カット。 

次の 2 つの分岐は、すべてのカットを 1 つの次元で費やすことに対応します。 要因$k+1$表示されるため$k$カットを作成する$k+1$セグメント。 

最後の 2 つの分岐は、1 つの寸法で使用可能なカット位置が不足した場合を処理します。 たとえば、すべてを使用した後、$n-1$水平方向にカットした場合、残りのカットは幅方向にカットする必要があります。 分母は、$$k-(n-1)+1 = k-n+2.$$1 つずれることは、この問題で最もよくある実装上の間違いです。 

Python の整数は、次の値まで自動的に処理します。$10^{18}$したがって、オーバーフローの懸念はありません。

 ## 特殊なケース

 次のことを考慮してください。```
2 3 4
```アルゴリズムはまず次のことをチェックします。$$k > n+m-2.$$以来$$4 > 2+3-2 = 3,$$すぐに出力されます$-1$。 候補となる式は評価されません。 これにより、必要なカットを物理的に行うことができない場合に、無意味なポジティブ領域が生成されるのを防ぎます。 

考慮する：```
1 10 5
```水平方向のカットはありません。 アルゴリズムがブランチに入る$k \ge n$、与える$$10 // (5-1+2)=10//6=1.$$答えは$1$、これは垂直方向のカットのみが可能であるという事実と一致します。 

考慮する：```
5 5 8
```利用可能なすべてのカットラインを使用する必要があります。 アルゴリズムが評価するのは、$$5 // (8-5+2)=1,$$対称的な分岐と戻りの両方から$1$。 これは、すべての単位正方形が独自のピースになる状況を正確に捉えています。 

考慮する：```
3 4 1
```アルゴリズムは、考えられる両方の単一方向の分割を比較します。$$(3 // 2)\cdot4=4,$$そして$$(4 // 2)\cdot3=6.$$戻ります$6$, これは、必ずしも高い方の寸法をカットすることで最良の答えが得られるわけではないことを示しています。
