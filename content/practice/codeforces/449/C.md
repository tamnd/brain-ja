 ## 解決策
 ## 問題の理解

 私たちは～の番号が付けられたリンゴを持っています`1`に`n`。 各ペアの 2 つの数値の最大公約数が より大きいように、できるだけ多くの素のペアを作成したいと考えています。`1`。 

各リンゴは最大 1 つのペアで出現できます。 タスクは、ペアの最大数を数えることではなく、1 つの最適なペアを明示的に出力することです。 

制約`n ≤ 100000`が中心的な難しさです。 数値は最大 10 万個あるため、すべてのペアをチェックするアルゴリズムは不可能です。 可能なペアの数はおおよそ次のとおりです$$\frac{n(n-1)}{2} \approx 5 \cdot 10^9$$いつ`n = 100000`、これは 1 秒で処理できる量をはるかに超えています。 

状態の構造が本当の手がかりとなります。 2 つの数値は、素因数を共有する場合は常にペアになることがあります。 可分性と素因数が関係するため、ふるいに基づいた数論の構築が必要になる可能性があります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
1
```リンゴは 1 つしかないので、ペアを作ることはできません。 正しい答えは次のとおりです。```
0
```すべての数値が何らかの除数グループに属していると想定する実装は、ここで失敗します。 

考慮する：```
3
```数字は`{1,2,3}`。 番号`1`何とも組み合わせることができないので、`gcd(1,x)=1`あらゆる人にとって`x`。 正しい答えは次のとおりです。```
0
```残りのすべての番号をペアリングしようとする貪欲な戦略は、誤って使用しようとします。`1`。 

考慮する：```
6
```数字は`{1,2,3,4,5,6}`。 

不注意で貪欲なアプローチはペアになる可能性があります`(2,6)`まず出発`{3,4}`未使用。 以来`gcd(3,4)=1`、1 つのペアのみが取得されます。 

最適解では、たとえば次の 2 つのペアが生成されます。```
6 3
2 4
```課題は、単に有効なペアを見つけるだけではなく、ペアの総数が最大になるようにそれらを配置することです。 

## アプローチ

 最も直接的なアイデアは、グラフを作成することです。 次のすべての数値の頂点を作成します。`1`に`n`、gcd が より大きい場合は 2 つの頂点を接続します。`1`。 問題は、最大の一致を見つけることになります。 

これは正しいです。すべての有効なペアがエッジに対応し、互いに素なペアが一致するエッジに対応するからです。 

残念ながら、グラフは膨大です。 構築するにも大まかな検討が必要`n²/2`ペア。 のために`n = 100000`、つまり何十億もの gcd 計算が行われることを意味します。 一般的な最大一致アルゴリズムはまったく実行不可能です。 

重要な観察は、グラフが非常に特殊な構造をしているということです。 2 つの数値をペアにできるかどうかは、共有される素因数に依存します。 任意のエッジについて考えるのではなく、割り切れるようにグループ化された数値について考えてください。 

素数を最大から最小の順に処理するとします。 プライムの場合`p`、現在使用されていないすべての数値が次の数で割り切れると考えます。`p`。 

このセット内の 2 つの数値はすべて、少なくとも gcd を自動的に持ちます。`p`, したがって、セット内のどのペアも有効です。 

残りの課題は、異なる素数間の競合を回避することです。 のような数字`30`同時に多くの素数群に属します。 

従来の Codeforces ソリューションは、素数を降順で処理し、割り当てられた番号を使用済みとしてマークすることでこれを処理します。 素数処理時`p`、まだ使用されていないすべての倍数を収集します。`p`。 

カウントが偶数の場合は、単純に任意にペアにします。 

カウントが奇数の場合は、1 つの数値を除外する必要があります。 奇数の素数の場合、除外される数は次のとおりです。`2p`。 この選択は非常に意図的なものです。 以来`2p`偶数である場合、後でプライムで処理できるようになります`2`、そこではまだ別のペアに参加できます。 1つおきの倍数`p`より大きい`2p`含まれています`p`そうしないと永久に失われてしまいます。 

素数を最大から最小の順に処理すると、最大の素因数が考慮されたときに各数値が処理されることが保証されます。 これにより、将来の競合が防止され、可能な限り最大数のペアが生成されます。 

素数と最大素因数情報を効率的に生成するには、ふるいを使用します。

 | ふるい + 建設的なペアリング | O(n log log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ふるいを作ります。`n`そして、すべての数値の最大の素因数を計算します。 
2. すべての素数を抽出し、降順に処理します。 
3. ブール配列を維持する`used`、番号がすでにペアに割り当てられているかどうかを示します。 
4. 現在の素数の場合`p`、未使用の倍数をすべて収集します。`p`。 

これらはまさに、素因数を介して組み合わせることができる数値です。`p`。 
5. 収集された数が偶数の場合、連続する要素をペアにします。 

両方の数値が次で割り切れるため、すべてのペアは有効です。`p`。 
6. 収集されたカウントが奇数の場合、`p > 2`、番号を削除します`2p`リストから。 

残りカウントは偶数になります。 

選んだ理由`2p`後でプライムの処理に参加できるということです`2`、他の倍数を削除すると、最大の素因数が次のような数値が無駄になります。`p`。 
7. 残りの番号を一度に 2 つずつペアにして、すべての番号を使用済みとしてマークします。 
8. すべての素数が処理されるまで続行します。 
9. 構築されたすべてのペアを出力します。 

### なぜ効果があるのか

 最大の素因数が見つかったときに数値を処理します。 

数字を考えてみましょう`x`最大の素因数を持つ`p`。 素数がより大きいとき`p`加工されて、`x`は割り切れないため考慮されません。 プライムのとき`p`加工されて、`x`未使用の倍数の中に出現します`p`。 

カウントが偶数の場合、`x`すぐにペアリングされます。 

カウントが奇数の場合のみ`2p`延期される場合があります。 最大の素因数を持つ 1 つおきの数値`p`この段階でペアリングされます。 の特別な選択`2p`プライムの下で処理される偶数グループにも属するため、将来のペアリングの機会が保存されます。`2`。 

したがって、避けられない残りを除くすべての可能な数値が 1 回だけ一致します。 公式ソリューションで使用されている構造は、最大一致サイズを実現します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    lp = [0] * (n + 1)

    for i in range(2, n + 1):
        if lp[i] == 0:
            for j in range(i, n + 1, i):
                lp[j] = i

    primes = [i for i in range(2, n + 1) if lp[i] == i]

    used = [False] * (n + 1)
    ans = []

    for p in reversed(primes):
        cur = []

        for x in range(p, n + 1, p):
            if not used[x]:
                cur.append(x)

        if len(cur) & 1:
            if p == 2:
                cur.pop()
            else:
                cur.remove(2 * p)

        for i in range(0, len(cur), 2):
            a = cur[i]
            b = cur[i + 1]
            ans.append((a, b))
            used[a] = True
            used[b] = True

    print(len(ans))
    for a, b in ans:
        print(a, b)

if __name__ == "__main__":
    solve()
```ふるいには、すべての数値の最大の素因数が保存されます。 通常の最小素因数ふるいとは異なり、走査中に意図的に値を上書きするため、最後に保存された素数が最大の約数素数となります。 

素数は降順に処理されます。 この順序付けは、最大の素因数に達したときに各数値を処理できるようにするため、構築の中心です。 

プライムの場合`p`、リスト`cur`未使用のすべての倍数が含まれます`p`。 このリスト内のすべての要素は、同じリスト内の他の要素と安全に組み合わせることができます。 

奇数サイズのケースは微妙な部分です。 2 より大きい素数の場合は、`2p`最大値を維持します。 いつ`p = 2`、小さい素数は残っていないため、残った 1 つの数値は単に破棄する必要があります。 

ペアリング ループは、隣接する要素を次から取得します。`cur`。 リスト内のすべてのペアがすでに gcd 条件を満たしているため、特別なマッチング戦略は必要ありません。
