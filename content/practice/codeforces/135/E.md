 ## 問題の理解

 サイズのアルファベット上の有限の文字列を調べています`k`。 このような文字列ごとに、特別な値を定義します。 

文字列のすべての部分文字列を取得します。 それらの中には、一部の部分文字列が非連続的に部分列として現れることもあります。 このようなサブシーケンスは弱いサブシーケンスと呼ばれます。これは、連続して選択された位置間の少なくとも 1 つのギャップが 1 より大きくなければならないことを意味します。 

たとえば、`"abba"`、部分文字列`"ba"`ポジションをとることで弱い部分列としても現れます`2`そして`4`。 

この問題は、弱い部分列でもある最長の部分文字列の長さが正確に一致する文字列の数を求めます。`w`。 

無限に多くの文字列が条件を満たす場合、次のように出力します。`-1`。 

この制約により、文字列を直接構築することから即座に遠ざけられます。 アルファベットのサイズは次のようになります`10^6`、 そして`w`まで上がります`10^9`。 線形に依存するアルゴリズム`w`、または文字列を列挙しようとすることは不可能です。 閉じた形式の組み合わせ特性評価が必要です。 

最も難しいのは、どのような構造が弱い部分シーケンスの部分文字列の最大長を制御するかを理解することです。 その構造が特定されると、カウント自体が管理可能になります。 

見落としやすいエッジケースがいくつかあります。 

仮定する`k = 1`。 この場合、すべての文字列は完全に同じ文字で構成されます。 のために`"aaaaa"`、任意の部分文字列`"aaaa"`位置をスキップすることにより、弱いサブシーケンスとして再び表示されます。 実際、任意の長さの文字列は、任意の大きな弱部分列部分文字列とともに存在します。 もし`w ≥ 2`、有効な文字列は無限にあります。 素朴な有限の計数公式はここでは失敗します。 

もう 1 つの危険なケースは、隣接するブロックが繰り返される文字列です。 考慮する`"ababab"`。 部分文字列`"abab"`ポジションをとることで弱いサブシーケンスとして再び現れる`(1,2,5,6)`。 この現象は単に繰り返される文字によって制御されるわけではありません。 重なって繰り返されるパターンが重要です。 

答えがゼロの場合、微妙な境界ケースが現れます。 たとえば、次の場合`k = 2`そして`w = 1`、ステートメントが保証しているため、有効な文字列はありません。`w ≥ 2`。 さらに興味深いことに、一部の仮説的な定式化では、不用意な推論により、最大の弱い部分列部分文字列が次の値を超える不可能な構成がカウントされる可能性があります。`w`。 

重要な課題は、文字列を直接カウントすることではなく、まずどの文字列が境界の弱い部分シーケンスの動作を持つかを正確に特徴付けることです。

### なぜ効果があるのか

 ある長さの文字列の場合`w + 1`、任意の長さの部分文字列`w`文字列全体とは、削除された 1 文字だけ異なります。 このような部分文字列を弱い部分シーケンスとして実現するには、マッチング プロセスでいくつかの位置をスキップし、隣接する等しい文字を使用して補正する必要があります。 これは、隣接する 2 つの文字が等しい場合にのみ可能です。 

より長い文字列`w + 1`必然的に、より大きな弱い部分列の部分文字列が許可されるため、長さのみが許容されます`w + 1`重要です。 したがって、有効な文字列をカウントすると、正確に長さをカウントできます。`w + 1`少なくとも 1 つの等しい隣接ペアを含む文字列。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    k, w = map(int, input().split())

    if k == 1:
        print(-1)
        return

    total = pow(k, w + 1, MOD)
    bad = k * pow(k - 1, w, MOD)
    bad %= MOD

    ans = (total - bad) % MOD
    print(ans)

solve()
```実装は数学的導出に直接従います。 

最初のブランチは、無限応答のケースを処理します。 これはモジュラー演算の前に行う必要があります。`-1`はモジュロ結果の一部ではありません。 

表現```
pow(k, w + 1, MOD)
```Python の組み込み高速モジュラーべき乗を使用します。 以来`w`到達できる`10^9`、通常の繰り返し乗算ではタイムアウトになります。 2 進累乗により、これが対数的な複雑さに減ります。 

変数`bad`隣接する文字が常に異なる文字列の数を格納します。 の乗算`k`剰余も減らす必要があります`MOD`。 

最後の減算には次のものを使用します。```
(total - bad) % MOD
```モジュラー減算は正規化の前に負になる可能性があるためです。

# helper: run solution on input string, return output string
import sys
import io

MOD = 10**9 + 7

def solve():
    input = sys.stdin.readline

    k, w = map(int, input().split())

    if k == 1:
        print(-1)
        return

    total = pow(k, w + 1, MOD)
    bad = k * pow(k - 1, w, MOD)
    bad %= MOD

    print((total - bad) % MOD)

def run(inp: str) -> str:
    backup_stdin = sys.stdin

    sys.stdout = out

    solve()

    sys.stdout = backup_stdout
