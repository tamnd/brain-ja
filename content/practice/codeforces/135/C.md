 ## 解決策
 ## 問題の理解

 次の文字列が与えられます。`0`、`1`、 そして`?`。 各文字は列内のカードを表します。 ゲーム中、プレイヤーはカードが 2 枚だけになるまで交互に 1 枚のカードを取り除きます。 Masha が最初に動き、最後の 2 ビット 2 進数をできるだけ小さくしたいのに対し、Petya はそれをできるだけ大きくしたいと考えています。 

最終的な答えは単一の結果ではありません。 一部ポジションが不明のため、`?`、そしてすべての`?`独立してどちらかになる可能性があります`0`または`1`。 完成したバイナリ文字列ごとに、両方のプレイヤーが最適にプレイし、最終ペアを 1 つ作成します。`00`、`01`、`10`、 そして`11`。 の少なくとも 1 つの割り当てに現れる可能性のあるすべてのペアを出力する必要があります。`?`文字。 

届く長さは`10^5`, そのため、すべての割り当てにわたってゲームをシミュレートすることはできません。 疑問符が 30 個しかなかったとしても、すでに`2^30`可能性はありますが、それは完全に不可能です。 ソリューションは線形時間またはそれに近い時間で機能する必要があります。 

難しいのは、最適なプレイが実際に何を意味するのかを理解することです。 単純なシミュレーションでは、すべての動きに対してミニマックスを試みる可能性がありますが、最大で`10^5`カードなので、ゲームツリーは巨大です。 重要な観察は、0 と 1 の数だけが重要であり、誰のターンが最後に残ったカードを制御するかということです。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

次の入力を考えてみましょう。```
11
```すでにカードがちょうど 2 枚あるため、動きは起こりません。 結果はすぐに出ます`11`。 誰かが常に最初に動くことを想定した不用意な実装は、答えを誤って変更する可能性があります。 

別の微妙なケースは次のとおりです。```
101
```マーシャが行う動きは 1 つだけです。 彼女は先頭を削除します`1`、出発`01`。 過半数の数だけから推論する人は、残りのカードには 2 枚のカードが含まれているに違いないと誤って結論付ける可能性があります。 

3 番目の重要なケースはパリティです。 例えば：```
0001
```カードが 4 枚あるので、正確に 2 つの除去が発生します。 Masha が最初に削除し、Petya が 2 番目に削除します。 Petya が最後の動きをすることで、最終的な構成をコントロールするプレイヤーが変わります。 パリティを無視すると、多くの文字列で誤った結果が生じます。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 私たちは、あらゆる代替品を生成することができます。`?`文字を入力し、ミニマックスを使用して結果のゲームを解決します。 長さが固定されたバイナリ文字列の場合`n`、各移動が残りの 1 枚のカードを選択するため、ゲーム ツリーには膨大な数の状態が含まれます。 サブセットにわたるメモ化であっても、依然として指数関数的になるでしょう。 

あると仮定します`k`疑問符。 それから、`2^k`完成した文字列。 と`k = 10^5`、これはすぐに絶望的です。 疑問符のない固定文字列であっても、ミニマックス ゲームは大きすぎます。 

重要な点は、カードの正確な順序は重要ではないということです。 複数の数字セットのみが重要です。 プレイヤーはカードを取り除き、最終的にちょうど 2 人が生き残ります。 生き残るペアは、最適なプレイ後に残っている 0 と 1 の数によって完全に決まります。 

初期の長さを次のようにします`n`。 

その通り`n - 2`動きが行われます。 

Masha が最初に動き、最終的な 2 進数を最小化したいと考えています。 左側のビットの方が重要であるため、彼女は主に残りの最初の桁を次のようにしたいと考えています。`0`。 ペティアはその反対を望んでいます。 

恣意的な削除について考える代わりに、逆に考えることができます。 2枚のカードが生き残る。 1 つおきのカードはプレイヤーの 1 人によって取り除かれます。 各プレイヤーの手数はパリティによって固定されます。 

もし`n`互角の場合、Petya は最後の動きをします。 

もし`n`奇妙だ、マーシャは最後の行動を起こす。 

これにより、最後の 2 枚のカードに特定の数字を強制的に含めることができる人が完全に変わります。 

最適なプレイを分析した後、ゲームは 4 つの結果のそれぞれが疑問符の割り当てによって強制できるかどうかを確認することに移ります。 条件は、固定ゼロ、固定 1、および疑問符の数にのみ依存します。 

結果として得られるアルゴリズムは、各候補結果についていくつかの不等式のみを評価します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列内に出現する固定ゼロ、固定 1、および疑問符の数を数えます。 
2. しましょう`n`文字列の長さになります。 

正確に終了した後、残り 2 枚のカードでゲームが終了します。`n - 2`撤去。 
3. 各プレイヤーが何回移動するかを計算します。 

マーシャが最初に動くので、次のようになります。```
masha_moves = (n - 1) // 2
petya_moves = (n - 2) // 2
```4. 結果を確認する`00`可能です。 

最後の 2 枚のカードを両方ともゼロにするには、完成した文字列に十分な数のゼロが含まれている必要があり、Petya がそのうちの 1 枚を除いてすべてを削除することはできません。 

Petya は正確に削除します`petya_moves`カード。 ゼロの合計数が 2 を超える場合`petya_moves`の場合、少なくとも 2 つのゼロが存続できます。 

疑問符がゼロになる可能性があるため、次のことを確認します。```
zeros + questions > petya_moves
```5. 結果を確認する`11`可能です。 

対称的に、マーシャはそれらを削除しようとします。 彼女は正確に削除します`masha_moves`カード。 2 つを残すには、1 の合計数が次を超える必要があります。`masha_moves`。 

私たちは以下をチェックします:```
ones + questions > masha_moves
```6. 結果を確認する`01`可能です。 

つまり、残っているカードは`0`そして生き残った右のカードは`1`。 

最適なプレイの下では、完成した文字列に十分なゼロと十分な 1 が同時に含まれ、どちらのプレイヤーも 1 桁を完全に削除できない場合に、これが可能になります。 

私たちは以下をチェックします:```
zeros + questions > petya_moves
and
ones + questions > masha_moves
```7. 結果を確認する`10`可能です。 

これは対称です`01`ただし、左ビットの方が重要であり、マーシャが最初に動作するため、パリティの重要性は異なります。 

同じ実現可能条件が適用されますが、実際に達成可能な順序は移動パリティによって異なります。 ゲーム理論的な還元の後、条件は次のようになります。```
zeros + questions > masha_moves
and
ones + questions > petya_moves
```8. 実行可能なすべての結果を辞書順に出力します。 

### なぜ効果があるのか

 各プレイヤーは決められた数のカードのみを削除できます。 マーシャは最大でも削除できます`masha_moves`Petya が削除できるのは最大でも`petya_moves`ゼロ。 対戦相手が消去できる回数よりも多くの数字が出現した場合、少なくとも 1 つのコピーは何があっても生き残ります。 

最終的な 2 枚のカードの結果は、各プレイヤーが 1 桁のタイプを完全に除去できるかどうかによってのみ決まります。 除去の順序はこれらの生存条件とは無関係であるため、ゲームは明示的なミニマックス シミュレーションではなく、引数をカウントすることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    n = len(s)

    zeros = s.count('0')
    ones = s.count('1')
    questions = s.count('?')

    masha_moves = (n - 1) // 2
    petya_moves = (n - 2) // 2

    ans = []

    if zeros + questions > petya_moves:
        ans.append("00")

    if (zeros + questions > petya_moves and
            ones + questions > masha_moves):
        ans.append("01")

    if (zeros + questions > masha_moves and
            ones + questions > petya_moves):
        ans.append("10")

    if ones + questions > masha_moves:
        ans.append("11")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```実装はアルゴリズムのカウント ロジックに直接に従います。 

まず、固定ゼロ、固定 1、疑問符を数えます。 疑問符はどちらの数字にもなり得るため、テストする結果に柔軟に影響します。 

移動数はパリティから慎重に導出されます。 まさにあります`n - 2`合計で回転します。 マーシャは最初にスタートするため、除去の数が奇数の場合は 1 つ余分に手を受けます。 

不平等は厳しいです。 たとえば、チェックするとき、`00`、次のことが必要です。```
zeros + questions > petya_moves
```カウントが厳密に大きいのではなく等しい場合、Petya はおそらく 1 を除くすべてのゼロを消去できます。`00`不可能。 

出力の順序は重要です。 この問題には辞書編集的な順序が必要なので、結果を次の順序でテストします。```
00
01
10
11
```よくある間違いは、`>=`の代わりに`>`。 これにより、対戦相手が数字のコピーをすべて削除できるという結果が誤って許可されてしまいます。 

もう 1 つの頻繁なバグは、奇数の長さの移動数を誤って計算することです。 次のような小さな例をテストする`n = 3`式を検証するのに役立ちます。

import sys
import io

def solve():
    input = sys.stdin.readline

    s = input().strip()

    n = len(s)

    zeros = s.count('0')
    ones = s.count('1')
    questions = s.count('?')

    masha_moves = (n - 1) // 2
    petya_moves = (n - 2) // 2

    ans = []

    if zeros + questions > petya_moves:
        ans.append("00")

    if (zeros + questions > petya_moves and
            ones + questions > masha_moves):
        ans.append("01")

    if (zeros + questions > masha_moves and
            ones + questions > petya_moves):
        ans.append("10")

    if ones + questions > masha_moves:
        ans.append("11")

    print("\n".join(ans))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup

    return out.getvalue().strip()

# boundary condition with question marks

expected = "00\n01\n10\n11"
assert run(big + "\n") == expected, "maximum size input"
