 ## 解決策
 ## 問題の理解

 このプロセスでは、左から右への順列が構築されますが、各ステップでの選択は、すでに配置されている数字に基づいていません。 代わりに、ステップ i で、ジェネレーターはすべての位置をまだ空であるかのように評価し、すでに使用されている位置に到達する前に各インデックスが右にどれだけ拡張できるかに応じて「到達可能性スコア」を計算し、現在未使用の位置のみを最高スコアとみなします。 その中からどれでも選択可能です。 

重要な問題は、ポジションのスコアがローカルではないことです。 一部の位置がすでに占有されている場合、残りの各位置を「ポイント」する開始インデックスの数が変更されるため、すべてのステップは配列内の空きギャップの進化する構造に依存します。 

候補の順列が与えられ、このルールに基づいてそれを生成できる一連の有効な位置の選択が存在するかどうかを判断する必要があります。 

この制約により、テストごとに線形または線形に近い動作が強く求められます。 テスト全体の長さの合計は最大 100,000 であるため、単一のテストで二次関数となる解はすでに失敗します。 これにより、すべてのステップですべての位置のスコアを最初から再計算することが除外されます。これは、サイズ n の繰り返しスキャンと次数 n² の総コストにつながるためです。 

複数のポジションが同じスコアを共有する場合、微妙な問題が発生します。 ジェネレータは任意に同点を破ることができるため、有効な解決策は、一意の選択だけでなく、すべての最大スコア位置を考慮する必要があります。 決定論的な選択を仮定する単純なシミュレーションでは、正しいパスがタイブレークに依存する場合、有効な順列が誤って拒否されます。 

## アプローチ

 直接シミュレーションは文字通り定義に従います。 各ステップで、すべてのインデックス j について、その右側にある次の空き位置を再計算し、カウントを集計し、現在空いているすべての位置を最大カウントで識別し、順列からの必要な位置がそのセットに属しているかどうかを確認します。 これは概念的には正しいですが、計算コストが高くなります。 各ステップでは、配列全体をスキャンし、次の空きポインターを再構築する必要があり、すべてのステップにわたって 3 次またはよくても 2 次の動作が行われます。 

ボトルネックは、スコア構造が非常に制御された方法で変化することです。 スコアが実際に何を測定するのかを見てみると、それが空きポジションの連続したブロックのみに依存していることが明らかになります。 連続するフリー インデックスのブロック内では、ほとんどの位置が同じように動作し、これらのブロックの境界だけが最大スコアを達成できます。 

これにより、問題はインデックスごとの推論からセグメントごとの推論に軽減されます。 個々のスコアを追跡する代わりに、連続したフリー ポジションのセグメントを維持します。 各セグメントには、その端の 1 つという支配的な選択肢があります。 ジェネレーターは常に、利用可能な最大のセグメントのセグメント端の中から選択します。 

したがって、問題はセグメントに対する貪欲なプロセスになります。最大長のセグメントを繰り返し取得し、順列で次に必要な番号がその端のいずれかにあることを確認し、それに応じてセグメントを分割します。

 ## アルゴリズムのチュートリアル

 私たちはプロセスを直感的な複雑さとは逆に再解釈します。 スコアを再計算する代わりに、空き領域が集中している場所のみを追跡します。 

現在無料のインデックスはすべて、互いに素なセグメントとして維持されます。 各セグメントは、順列の選択された要素がまだ占有していない連続した間隔を表します。 

ジェネレーターは常に、セグメントの長さに対応する最大の「影響力」を持つセグメントを効果的に優先します。 

### ステップ

1. 1 から n までの範囲全体をカバーする単一セグメントを初期化します。 これは、最初はすべてのポジションが利用可能であり、同様に有効であることを表します。 
2. 常に最大長のセグメントを取得できる構造を構築します。 これが必要なのは、ジェネレーターが各ステップでローカルな候補ではなく、グローバルな最良の候補のみを考慮するためです。 
3. 構築された順序で順列を処理します。 ステップ i では、番号 i を位置 p[i] に配置する必要があります。 
4. 現在 p[i] を含むセグメントを見つけます。 p[i] が空きセグメント内にない場合、その位置はすでに占有されているため、置換は直ちに無効になります。 
5. すべてのセグメントの中で、最大の長さを持つセグメントを特定します。 このステップでは、このセグメント内の位置のみを選択できます。 
6. p[i] がこの最大セグメントの 2 つのエンドポイントの 1 つであるかどうかを確認します。 そうでない場合、スコアリング ルールの下では内部位置が決して最適にならないため、順列を生成することはできません。 
7. p[i] をセグメントから削除します。 これにより、セグメントが最大 2 つの小さなセグメントに分割され、構造に再挿入されます。 

分割を繰り返すことで、空き領域が常に素の間隔として正しく表現されるようになります。 

### なぜ効果があるのか

 任意の空きセグメント内では、境界位置のみが最大スコアを蓄積できます。これは、内部位置が常に隣接する位置と同一のローカル構造を持ち、寄与が最小限に抑えられるためです。 セグメントが進化するにつれて、エンドポイントのみが世界的に競争力を持つようになり、生成者の決定はセグメントの長さによって完全に決まります。 

不変条件は、自由位置のセットが常に互いに素なセグメントとして正確に表現され、各ステップでの選択の唯一の候補が最大セグメントの端点であることです。 これはスコアリング ルールの動作と一致するため、そのようなエンドポイントの選択からの逸脱はジェネレーターの定義と矛盾します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        # segments stored as (l, r)
        import bisect

        segs = [(1, n)]

        # helper: find segment containing x
        def find(x):
            lo, hi = 0, len(segs) - 1
            while lo <= hi:
                mid = (lo + hi) // 2
                l, r = segs[mid]
                if l <= x <= r:
                    return mid
                if x < l:
                    hi = mid - 1
                else:
                    lo = mid + 1
            return -1

        # helper: remove segment at idx
        def erase(i):
            segs.pop(i)

        # helper: insert segment and keep sorted
        def add(l, r):
            if l <= r:
                bisect.insort(segs, (l, r))

        ok = True

        for x in p:
            if not segs:
                ok = False
                break

            # find segment containing x
            idx = find(x)
            if idx == -1:
                ok = False
                break

            l, r = segs[idx]

            # find global max segment length
            mx_len = max(r2 - l2 + 1 for l2, r2 in segs)
            if (r - l + 1) != mx_len:
                ok = False
                break

            # must be endpoint of segment
            if x != l and x != r:
                ok = False
                break

            erase(idx)

            if l <= x - 1:
                add(l, x - 1)
            if x + 1 <= r:
                add(x + 1, r)

        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```コードは、空き領域をセグメントのソートされたリストとして維持します。 順列の値ごとに、選択した位置が現在どのセグメントに含まれているかがわかります。 次に、このセグメントが最大長のセグメントの中にあること、および選択された位置がその境界の 1 つにあることを検証します。 検証後、セグメントが分割されます。 

最もデリケートな部分は、セグメントの検索と更新の間の一貫性を確保することです。 位置が使用されるたびに、それをきれいに削除する必要があり、結果の間隔では並べ替えられた順序が維持される必要があります。 秩序の維持に失敗すると、封じ込め検索が中断されます。

    # simplified inline solution for testing
    def solve():
        import bisect
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            p = list(map(int, input().split()))
            segs = [(1, n)]

            def find(x):

                while lo <= hi:
                    mid = (lo + hi) // 2
                    l, r = segs[mid]
                    if l <= x <= r:
                        return mid
                    if x < l:
                        hi = mid - 1
                    else:

                return -1

            for x in p:
                idx = find(x)
                if idx == -1:
                    ok = False
                    break

            out.append("Yes" if ok else "No")
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 唯一のセグメントが常に最大スコアを持ち、唯一の位置が常にエンドポイントであるため、単一要素の配列は自明に動作します。 アルゴリズムはすぐに受け入れるようになります。 

1 2 3 ... n のような厳密に増加する順列は、各ステップで現在のセグメント全体のエンドポイントが削除され、有効性を維持しながら一方の側から繰り返し縮小されるため、セグメントのエンドポイント ルールに違反することはありません。 

失敗したケースでは、通常、まだ最大であるセグメントの中央での選択が強制されます。 たとえば、1 3 2 4 では、[1,4] から 1 を選択した後、セグメント [2,4] は最大値のままですが、3 を選択すると、その時点では 3 が最大セグメントの端点ではないため、誤って分割され、ジェネレーターのスコアリング システムの下で端点のみが最適になり得るという不変条件に違反します。
