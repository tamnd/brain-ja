 ## 解決策

 ## 問題の理解

 各値が括弧トークンを表す一連の整数が与えられます。 正の数値は特定のタイプの左括弧を意味し、対応する負の数値は同じタイプの対応する右括弧を意味します。 したがって、シーケンスは括弧文字列のように動作しますが、複数の括弧タイプがあり、符号付き整数としてエンコードされる点が異なります。 

このタスクは 2 つの操作をサポートします。 1 回の操作で、シーケンス内の 1 つの位置が新しいブラケット値に変更されます。 もう 1 つの操作では、指定されたサブセグメントが通常のネスト ルールに基づいて正しい括弧シーケンスを形成しているかどうかを確認します。つまり、括弧はタイプで一致する必要があり、開始の逆の順序で閉じる必要があり、スタックの有効性の観点から、すべてのプレフィックスが開始より多くの終了を持ってはなりません。 

制約は厳しく、最大 100,000 個の要素と 100,000 回の操作です。 クエリごとに有効性を最初から再計算するソリューションは、最悪の場合二次計算となり、時間内に終了しません。 これにより、対数または対数に近い時間でのポイント更新と範囲検証の両方をサポートする構造が即座に強制されます。 

単一のブラケット タイプを使用していないため、微妙な問題が発生します。 プレフィックス合計のような単純なバランス チェックでは、不一致な型を検出できません。 たとえば、シーケンス`1 2 -1 -2`は正味残高がゼロですが、括弧が正しく交差していないため無効です。 したがって、有効な構造はカウントだけでなく順序を追跡する必要があります。 

もう 1 つの失敗例は、更新後の部分文字列クエリです。 単純なアプローチでは、グローバル スタックを維持するか、最後の変更からのみ再計算する可能性がありますが、部分文字列の正確性はクエリ間隔ごとに独立しているため、任意の範囲の集計をサポートするデータ構造が必要です。 

エッジ ケースには、開始と終了のカウントが等しいがネスト順序が間違っているセグメントや、更新された位置から遠く離れた一致する構造を壊して有効なセグメントを無効なセグメントに変える更新が含まれます。 

## アプローチ

 ブルート フォース ソリューションは、各クエリを個別に処理します。 タイプ 2 クエリの場合、部分文字列を抽出してスタックをシミュレートします。つまり、開始括弧をプッシュし、終了括弧をスタックの先頭と照合します。 これにより、正しいブラケット シーケンスの定義が正確に反映されるため、正確さが正確に検証されます。 

ただし、これにはクエリごとに直線的な時間がかかります。 長さ 100,000 の配列に対して 100,000 のクエリがある場合、最悪のケースは次のようになります。$10^{10}$限界をはるかに超えた操作。 早期に停止した場合でも、敵対的な入力によってフル スキャンが強制される可能性があります。 

重要な観察は、括弧シーケンスの正しさは 2 つの条件によって表現できるということです。1 つはタイプごとの全体的なバランスが不十分ですが、構造化された方法で一致しないプレフィックスとサフィックスを追跡するセグメント表現を使用して妥当性をモデル化できるということです。 標準的なアプローチは、各ノードが連結されたときに内部の括弧がどのように相互作用するかを圧縮した表現を格納するセグメント ツリーを維持することです。 

各セグメント ツリー ノードは、2 つのセグメントをどのようにマージするかを決定するのに十分な情報 (内部一致後に残る一致しない左括弧、およびセグメント内で一致できない一致しない閉じ括弧) を保持します。 複数のブラケット型の場合、完全なスタックを保存できないため、マージ中に型が一致する場合にのみ貪欲に一致するキャンセル ルールを使用します。 これが機能するのは、有効なグローバル マッチングでは、マージ中に適用されるローカル ペアリング制約が尊重される必要があるためです。 

ポイントの更新によりリーフが変更され、祖先が再計算されます。 範囲クエリは、セグメント ツリー パスに沿ってノードを結合し、間隔の集約構造を生成します。 セグメントは、マージ後にすべての不一致カウントが 0 である場合にのみ有効です。

 | 構造化マージを使用したセグメント ツリー | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列上にセグメント ツリーを構築します。 各ノードは 2 つの順序付きマルチセット (または周波数マップ) を格納します。1 つは一致しない開始括弧用、もう 1 つは一致しない終了括弧用で、それぞれが括弧のタイプによってインデックス付けされます。 

1. リーフ ノードの場合、値が開始しているか終了しているかに応じて初期化します。 開始ブラケットはそのタイプの不一致の開始を 1 つ提供し、終了ブラケットはそのタイプの一致しない終了を 1 つ提供します。 これは、単一の括弧が内部的に一致できないという事実を表しています。 
2. 2 つの子ノードをマージする場合、最初に、同じタイプの左側の子からの開始と右側の子からの終了を一致させようとします。 これは、左側のセグメントで開かれたブラケットが右側のセグメントで閉じられる、境界を越えたマッチングを反映しています。 
3. タイプごとにキャンセルを貪欲に実行します。ブラケット タイプごとに、できるだけ多くの左開きと右閉じを一致させます。 残りのオープニングはマージされた左オープン セットに残り、残りのクロージングは​​マージされた右クローズ セットに残ります。 
4. キャンセル後、マージされたノードの不一致のオープニングは、左オープンのレフトオーバーと右オープンのレフトオーバーの結合であり、クローズの場合も同様です。 これは、セグメントの不一致構造をすべてコンパクトに要約したものです。 
5. 更新の場合、リーフを置換し、同じマージ操作を使用してルートへのパス上のすべてのノードを再計算します。 
6. クエリの場合、以下をカバーするセグメント ツリー セグメントを結合します。$[l, r]$順番に。 最終的な構造は部分文字列全体を表します。 一致しない開始マップと終了マップの両方が空の場合、部分文字列は正しい括弧シーケンスです。 

### なぜ効果があるのか

 このアルゴリズムは、セグメント内のすべての有効な内部ペアを完全に解決した後、一致しないブラケットのマルチセットをすべてのノードが正確に保存するという不変条件を保持します。 マッチングはツリー マージ内の隣接するセグメント間でのみ可能であるため、有効なグローバル ペアはマージ中にローカル キャンセルのシーケンスとして表示される必要があります。 不一致が存在する場合、少なくとも 1 つのマップ内に不一致の括弧が残って表示され、誤検知が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

class Node:
    __slots__ = ("open", "close")
    def __init__(self):
        self.open = defaultdict(int)
        self.close = defaultdict(int)

def merge(a, b):
    res = Node()

    # copy first
    for k, v in a.open.items():
        res.open[k] += v
    for k, v in a.close.items():
        res.close[k] += v
    for k, v in b.open.items():
        res.open[k] += v
    for k, v in b.close.items():
        res.close[k] += v

    # cancel left opens with right closes
    for t in list(res.open.keys()):
        if t in res.close:
            m = min(res.open[t], res.close[t])
            res.open[t] -= m
            res.close[t] -= m
            if res.open[t] == 0:
                del res.open[t]
            if res.close[t] == 0:
                del res.close[t]

    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.data = [Node() for _ in range(2 * self.size)]

        for i, x in enumerate(arr):
            self.data[self.size + i] = self.make_node(x)

        for i in range(self.size - 1, 0, -1):
            self.data[i] = merge(self.data[2 * i], self.data[2 * i + 1])

    def make_node(self, x):
        node = Node()
        if x > 0:
            node.open[x] = 1
        else:
            node.close[-x] = 1
        return node

    def update(self, idx, val):
        i = self.size + idx
        self.data[i] = self.make_node(val)
        i //= 2
        while i:
            self.data[i] = merge(self.data[2 * i], self.data[2 * i + 1])
            i //= 2

    def query(self, l, r):
        l += self.size
        r += self.size

        left_res = Node()
        right_res = Node()

        while l <= r:
            if l % 2 == 1:
                left_res = merge(left_res, self.data[l])
                l += 1
            if r % 2 == 0:
                right_res = merge(self.data[r], right_res)
                r -= 1
            l //= 2
            r //= 2

        return merge(left_res, right_res)

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))
    q = int(input())

    st = SegTree(arr)

    out = []
    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            st.update(tmp[1] - 1, tmp[2])
        else:
            l, r = tmp[1] - 1, tmp[2] - 1
            res = st.query(l, r)
            out.append("Yes" if not res.open and not res.close else "No")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、各ノードがタイプごとに残りの不一致の開始括弧と終了括弧を格納するセグメント ツリーを中心としています。 マージ関数は、2 つのセグメントの境界を越えてキャンセルを実行します。これは、セグメント間の一致が発生する唯一の場所です。 

更新操作では、単一のリーフを変更した後、ルートへのパスが再構築されます。 クエリ操作では標準の反復セグメント ツリー範囲マージが使用され、順序が確実に保持されます。 正確性チェックは、不一致の構造が残っていないことを確認することに要約されます。 

微妙な点は、マージでは方向を考慮する必要があることです。左側のセグメントの開始は、右側のセグメントの終了とのみ一致します。 この順序を逆にすると、無効な後方一致が可能になるため、正確性が失われます。

 ## 特殊なケース

 次のような単一の括弧セグメント`[1]`完全なシーケンスとしては常に無効です。 セグメント ツリーでは、これにより空ではない開いたマップを持つリーフ ノードが生成され、クエリによってその残差が返され、正しく「いいえ」が返されます。 

次のような逆の正しい順序`1 -1 2`部分的なクエリ境界により、順序に依存したマージの必要性が明らかになります。 この構造により、一致しない閉じ括弧が正しい方向にペアにならない場合、残った一致しない閉じ括弧が確実に保持され、誤った有効性が防止されます。 

完全にバランスが取れているが、ネストが間違っているマルチタイプ シーケンスは、有効な左から右へのマージ方向でのみキャンセルが発生し、交差が等しいカウント内に隠れることがないようにするため、拒否されます。
