 ## 解決策
 ## 問題の理解

 0 から n までの整数点としてモデル化された直線道路が与えられます。 これらのポイントの一部は、両方のエンドポイントを含むセーフティ アイランドと呼ばれる特別な位置です。 デニスは時間ゼロの 0 から開始し、できるだけ早く n に到達したいと考えています。 

時間は繰り返される信号機のサイクルによって制御されます。 g 秒間緑色に点灯し、r 秒間赤色に点灯し、これを繰り返します。 移動は緑色の秒間のみ可能で、移動ごとに位置が左右に 1 単位ずつ変わります。 

モーションを根本的に形成する追加の構造上の制限があります。デニスは安全な島にいる場合にのみ方向を反転できます。 島の外では、ある方向に移動し始めると、島に到着するまでその方向に進み続けることを余儀なくされます。 これにより、道路が、特定のノードでのみ方向変更が許可される制約されたグラフに変わります。 

2 番目の制限は信号に関連しています。赤の時間帯には、デニスは安全な島に立っていなければなりません。 赤がスタートするとき、または赤がアクティブである間、彼は「移動中」にいることは許可されません。 

タスクは、n に到達するまでに必要な最小時間を計算するか、それが不可能であると判断することです。 

この制約は、n は 10^6 まで大きくできるが、島の数 m は最大 10^4 であることを意味します。 これにより、あらゆる道路位置を明示的にモデル化するアプローチは即座に除外されます。 どのような解決策でも、問題を重要な位置、つまり島のみに圧縮し、それらの間の移動について推論する必要があります。 

グリーンタイム中は常に前に進むことを欲張って考えると、微妙な失敗例が現れます。 次の島に到達するには複数の緑のセグメントが必要だが、島が存在しない限り移動を途中で停止できない状況を考えてみましょう。 単純に「緑になるたびに移動する」という素朴なシミュレーションは、赤が始まるときにエッジの内側に到達してしまう可能性があるため、ここで破綻します。 

もう 1 つのよくある落とし穴は、方向制限を無視することです。 たとえば、両側から島に到達できる場合でも、その島にいない限り、自由に方向転換することはできません。 状態のないアイランド間の無向移動を想定した最短経路アプローチでは、不可能な遷移が過大に計算されます。 

最後に、タイミング調整が重要です。 2 つの島が近い場合でも、緑のフェーズの終わり近くで横断を開始すると待機が必要になる可能性があり、その待機は将来のサイクルと相互作用します。 

## アプローチ

 この強引なアイデアは、プロセス全体を秒ごとにシミュレートすることです。 各タイム ステップで、デニスの位置、方向、および現在移動ルールによって制約されているかどうかを追跡します。 各州から、許可されている場合は左右に移動し、信号機の制限を強制します。 これは正しいですが、すぐには実行不可能です。位置は 10^6 に達し、時間も大きくなる可能性があるため、状態空間は O(n · (g + r) · 2) のようなものに爆発し、遷移は毎秒発生します。 

重要な観察は、島だけが決定点として重要であるということです。 島間の移動は決定的です。方向を選択すると、デニスは直線的に移動します。 唯一の複雑さは、島以外の赤信号のルールに違反することなく、信号サイクル内でこの横断を合法的にスケジュールできるかどうかです。 

これにより、問題は、ノードが島である縮小されたグラフにわたる最短経路問題に変換されます。 問題は、エッジが静的なコストではないことです。 それらは現在時間のモジュロ (g + r) に依存します。 したがって、状態に時間相を含める必要があります。

これにより、島にいて信号サイクル内の現在時刻が分かることによって各州が定義されるグラフが得られます。 このような状態からは、待つか、隣接する島への横断を試みることができます。 横断は、赤色の期間に島から決して出ない方法で、完全に緑色のセグメント内で移動をスケジュールできる場合にのみ有効です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 位置と時間にわたる完全なシミュレーション | O(n · (g+r)) | O(n · (g+r)) | 遅すぎる |
 | time-mod 状態の島の最短経路 | O(m · (g+r) log (m · (g+r))) | O(m · (g+r)) | 承認済み |

 ## アルゴリズムのチュートリアル

 ソートされた島のリストのみに道路を圧縮します。 デニスは方向変更を可能にする方法で島以外の転換点を「ジャンプ」することができないため、この順序では連続する島の間でのみ移動が可能です。 

各状態は、交通サイクル内のアイランド インデックスと現在時刻で構成されるペアによって定義されます。 移行にはグリーンフェーズが揃うまでの待機時間に応じてコストが変動するため、これらの状態に対してダイクストラを実行します。 

1. 島の座標をソートします。 これにより、各島がそのすぐ隣の島に接続される線形グラフが定義されます。 構造は完全なグラフではなくパスになります。 
2. トラフィック サイクル長を T = g + r として定義します。 信号パターンはサイクルごとに正確に繰り返されるため、各状態は T を法とする時間を追跡します。 
3. 状態 (位置 0、時間 0 の島) から開始します。 信号が青になったときに安全な島から開始するため、これは常に有効です。 
4. 任意の状態 (i, t) から、緑にいるか赤にいるかを計算します。 t < g の場合、移動は許可されます。 それ以外の場合は赤色になり、時間 T に次のサイクルが始まるまで待機する必要があります。 
5. 赤の場合、唯一の遷移は時間が T になるまで待機します (モジュロが 0 にリセットされます)。 これにより、赤の間、デニスは島に留まらなければならないというルールが強制されます。 
6. 緑色の場合は、隣接する島 i-1 および i+1 への移動を試みることができます。 隣との距離を d とします。 デニスが時刻 t からこの距離を横断できるかどうかをシミュレーションしてみます。 
7. トラバーサルは、デニスがエッジの途中でレッドをヒットしない場合にのみ有効です。 これは、セグメント全体が利用可能な緑色のウィンドウに収まる必要があり、おそらく複数のサイクルにまたがる必要がありますが、すべての赤色の間隔がアイランドにあることと一致する必要があることを意味します。 この制約は、現在のサイクルで利用可能なグリーンタイムを計算し、可能な限り移動し、サイクルごとに繰り返すことによって適用されます。 
8. トラバースが成功するたびに、更新された時間モジュロ T と累積合計時間を含む目的の島の新しい状態が得られます。 ダイクストラではこのエッジを緩和します。 
9. 答えは、最後の島に到達するすべての州の中で最も短い時間です。 

### なぜ効果があるのか

 このアルゴリズムは、連続移動の問題を、方向変更が許可される唯一の点である島でのみの遷移に軽減します。 有効な軌道はどれも、島間のセグメントと、交通サイクルに合わせた島での待機期間に分解できます。 サイクルを法として時間を追跡することにより、完全な履歴を必要とせずに、将来の移動の実現可能性を判断するのに十分な情報が保存されます。 ダイクストラでは、常に時間の増加順に状態を展開するため、最初に目的地に到達する時点が最適になります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    pos = list(map(int, input().split()))
    g, r = map(int, input().split())

    pos.sort()
    idx = {x: i for i, x in enumerate(pos)}

    T = g + r
    INF = 10**18

    # dist[i][t] = minimum time to reach island i at time mod T = t
    dist = [[INF] * T for _ in range(m)]
    dist[0][0] = 0

    pq = [(0, 0, 0)]  # time, island, time_mod

    while pq:
        time, i, tmod = heapq.heappop(pq)
        if time != dist[i][tmod]:
            continue

        if i == m - 1:
            print(time)
            return

        # if red light: wait until next cycle
        if tmod >= g:
            nt = time + (T - tmod)
            ntmod = 0
            if nt < dist[i][ntmod]:
                dist[i][ntmod] = nt
                heapq.heappush(pq, (nt, i, ntmod))
            continue

        # try moving to neighbors
        for ni in (i - 1, i + 1):
            if 0 <= ni < m:
                d = abs(pos[ni] - pos[i])

                # simulate movement during green cycles
                cur_time = time
                cur_mod = tmod
                rem = d

                ok = True

                while rem > 0:
                    if cur_mod >= g:
                        ok = False
                        break

                    can = min(rem, g - cur_mod)
                    rem -= can
                    cur_time += can
                    cur_mod += can

                    if rem == 0:
                        break

                    # hit end of green, must wait for next cycle
                    cur_time += (T - cur_mod)
                    cur_mod = 0

                if ok:
                    if cur_time < dist[ni][cur_mod]:
                        dist[ni][cur_mod] = cur_time
                        heapq.heappush(pq, (cur_time, ni, cur_mod))

solve()
```このコードは、交通サイクル内の現在位置と組み合わせた島インデックスに対するダイクストラ検索を実装します。 主要な実装の詳細は、移動シミュレーション ループです。これは、緑色のフェーズ中にのみ距離を消費し、移動が完了する前に緑色のフェーズが終了するたびに待機時間を明示的に挿入します。 

よくある間違いは、待機後にモジュロ時間をリセットするのを忘れることです。 もう 1 つは、動きを距離に等しい単純なエッジの重みとして扱おうとするもので、動きの一部が赤のサイクルで強制的に一時停止される可能性があることを無視しています。

 ## 特殊なケース

 重要なエッジ ケースは、2 つの島が緑の持続時間に比べて遠く離れている場合に発生します。 原理的には動きは連続的ですが、赤信号によりアイランド間の移動が禁止されるため、エッジの途中で停止することなくセグメントをサイクル間で分割できない限り、強制的に失敗します。 

別のケースは、赤が始まると同時に島に到着する場合です。 この時点ではデニスは島にいるため状態はまだ有効ですが、すぐに移動しようとする試みは次の緑のフェーズまでブロックされます。 アルゴリズムは、移動を許可する前に状態を待機遷移にプッシュすることでこれを処理します。 

最後の微妙なケースは、最適な戦略にアイランド間を意図的に振動させることが含まれる場合です。 これは最短パスの直観からは明らかではありませんが、状態空間により異なるサイクル フェーズでアイランドを再訪することが可能であり、ダイクストラによってタイミングが向上する場合にはサイクルが探索されることが保証されるため、自然に処理されます。
