 ## 問題の理解

重要な点は、オカレンスの位置を独立して選択しているわけではないということです。 素朴な解釈は次のようになります。$k$のばらばらのコピー$s$残りの位置を任意に埋めますが、これでは重要な制約が欠けています。それは、意図しない追加の発生です。$s$境界を越えて出現する可能性があるため、これらも除外する必要があります。 

この制約は、単純な指数関数的構築や組み合わせ構築が不可能である理由を示唆しています。 長さ$n$到達できる$10^4$、 その間$k \le 10$そして$|s| \le 100$。 文字列の数が膨大であるため、文字列を列挙したり、一致するすべての配置を直接試行したりするアプローチは実行不可能です。$26^n$、さらには、のすべての配置についての推論も可能です。$k$間の出来事$n$遷移を注意深く構成しないと、位置の組み合わせが大きくなってしまいます。 唯一実行可能な方向は、パターンの一致にどの程度近づいているかを効率的に追跡しながら、文字列を左から右に構築する動的プログラミング アプローチです。

 ## アルゴリズムのチュートリアル

 まずパターンを前処理します$s$プレフィックス関数を使用して KMP オートマトンを構築します。 これにより、各状態が表す文字数がわかります。$s$現在、可能なすべての次の文字について、その文字を追加した後の次の状態と一致しています。 

次に、構築された文字列の長さにわたって動的プログラミングを実行します。 

1. ある長さのプレフィックスを構築できる方法が何通りあるかを表す DP 状態を定義します。$i$、特定のオートマトン状態で終了し、すでに完全に完了している$c$の完全一致$s$。 
2. DP を位置 0 で、一致する文字がゼロ、完了した出現がゼロの状態で初期化します。 これは空の文字列に相当しますが、当然ながら一致するものはありません。 
3. 0 から 0 までの各位置について$n-1$、現在のすべてのオートマトンの状態と、完了した一致のすべての有効な数を次の値まで反復します。$k$。 
4. 各状態について、「a」から「z」までの各文字を追加してみます。 これにより、事前に計算された遷移テーブルを使用して新しいオートマトン状態が生成されます。 
5. この移行により、$s$、一致カウンタを 1 つ増やします。 この増分が超える場合$k$、正確に必要なだけなので、トランジションを破棄します。$k$出来事。 
6. それ以外の場合は、それに応じて次のポジションの DP を更新します。 
7. すべての位置を処理した後、答えはその位置におけるすべてのオートマトン状態の合計になります。$n$まさに$k$完了した試合。 

正確さは、オートマトンが現在の文字列の接頭辞でもあるすべての接尾辞をエンコードするかどうかにかかっています。$s$。 これにより、すべての発生が保証されます。$s$完了時に正確に検出され、発生が見逃されたり二重にカウントされたりすることはありません。 将来の一致はこのサフィックスの状態のみに依存し、以前の文字には依存しないため、DP は完全な文字列を検査する必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def build_automaton(s):
    m = len(s)
    pi = [0] * m
    for i in range(1, m):
        j = pi[i - 1]
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
        pi[i] = j

    nxt = [[0] * 26 for _ in range(m + 1)]

    for state in range(m + 1):
        for c in range(26):
            if state < m and ord(s[state]) - 97 == c:
                nxt[state][c] = state + 1
            else:
                if state == 0:
                    nxt[state][c] = 0
                else:
                    nxt[state][c] = nxt[pi[state - 1]][c]

    return nxt

def solve():
    n, k = map(int, input().split())
    s = input().strip()
    m = len(s)

    nxt = build_automaton(s)

    dp = [[0] * (k + 1) for _ in range(m + 1)]
    dp[0][0] = 1

    for _ in range(n):
        ndp = [[0] * (k + 1) for _ in range(m + 1)]
        for state in range(m + 1):
            for cnt in range(k + 1):
                if dp[state][cnt] == 0:
                    continue
                val = dp[state][cnt]
                for c in range(26):
                    ns = nxt[state][c]
                    nc = cnt
                    if ns == m:
                        nc += 1
                        ns = nxt[ns][c] if m > 0 else 0
                    if nc <= k:
                        ndp[ns][nc] = (ndp[ns][nc] + val) % MOD
        dp = ndp

    print(sum(dp[state][k] for state in range(m + 1)) % MOD)

if __name__ == "__main__":
    solve()
```オートマトンの構築は、DP を実現可能にする核となる詳細です。 プレフィックス関数は、パターンのすべてのオーバーラップ情報を線形状態空間に圧縮します。 DP 配列は、現在一致しているパターンの量と、これまでに完了した完全な一致の数の両方を追跡します。 

完全一致状態に到達すると、すぐにカウントを増やし、フォールバック遷移の使用を継続します。これにより、手動による重複チェックを必要とせずに重複構造が一貫して処理されることが保証されます。 

文字列は完全に一致する限り有効でありながら、部分一致状態で終了する可能性があるため、すべての状態の最終的な合計が必要です。$k$フルマッチが見られました。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、パターンの長さが 1 の場合です。その状況では、すべての文字が自動的に一致し、DP は各位置をオートマトンの曖昧さなしに潜在的に出現を完了するものとして正しく解釈する必要があります。 オートマトンは単一の遷移状態に縮退しますが、一致カウンタは文字ごとに正確に 1 回ずつ正確にインクリメントする必要があります。 

別のエッジケースが発生するのは次の場合です。$k = 0$。 DP は引き続き正常に実行する必要がありますが、パターン長に達する一致状態を作成する遷移は慎重に除外する必要があります。 単純な実装では、一致が完了しない有効な状態の伝播を忘れ、代わりに誤ってゼロが生成される可能性があります。$26^n$パターンを含む無効な文字列をマイナスします。
