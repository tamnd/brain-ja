 ## 解決策
 ## 問題の理解

 それぞれ 2 の累乗である小さな数値のリストが与えられます。 つまり、すべての要素は次のように記述できます。$2^{k_i}$ここで指数は$k_i$負でない小さい整数です。 

タスクは、リスト内のすべての数値の積を調べ、それを定数 2024 の累乗と比較することです。最小の整数が必要です。$b$2024 の累乗$b$少なくとも指定されたすべての数値の積と同じ大きさです。 

したがって、概念的には、配列を 1 つの大きな積に圧縮し、その積を「カバー」するには 2024 を何回累乗する必要があるかを尋ねます。 

重要な制約は、$n \le 50$そして各指数$k_i \le 10$。 これは、製品が最大でも$2^{500}$これは、一般的な大きな整数の範囲に比べて天文学的に小さいため、問題はオーバーフローや大きな整数を扱うというよりも、指数の増加を理解することに完全に重点が置かれています。 

素朴だが重要なエッジ ケースは、すべての値が 1 の場合です。その場合、積は 1 となり、答えは 0 になるはずです。$2024^0 = 1$。 前提となるソリューション$b \ge 1$この場合、誤って 1 が返されてしまいます。 

もう 1 つの微妙なケースは、積がすでに 2024 より大きい場合です。たとえば、配列が$[1024, 1024]$、製品は$2^{20} = 1,048,576$、すでに 2024 年を超えているため、答えは少なくとも 2 でなければなりません。$2024^1 < 1,048,576$しかし$2024^2$で十分です。 

## アプローチ

 ブルートフォース解釈は簡単です。積を明示的に計算し、値が積を超えるか一致するまで 2024 年のカウンターを繰り返し乗算します。 ただし、製品は急激に成長します。$n$が小さいため、直接乗算は一部の言語で標準の整数型をオーバーフローしたり、不注意に実装すると非効率になる可能性があります。 Python では技術的には機能しますが、不必要な作業です。 

構造上の観察は、すべての数値は 2 の累乗であるということです。 これは、積も 2 のべき乗であることを意味します。$$\prod a_i = 2^{\sum k_i}$$したがって、大きな数を扱う代わりに、指数の合計だけが必要になります。 問題全体は最小のものを見つけることに帰着します$b$次のような:$$2^{S} \le 2024^b$$どこ$S = \sum k_i$。 

ここで重要な変換は、対数的な意味で成長率を比較することです。 両辺で 2 を底とする対数を取ると、次のようになります。$$S \le b \cdot \log_2(2024)$$それで：$$b \ge \frac{S}{\log_2(2024)}$$答えは単にこの値の上限です。 

これが中心的な単純化です。入力内の乗算構造は単一の加算和に崩壊し、指数比較は対数の後の除算に崩壊します。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、指数を抽出します$k_i$それぞれの値から$a_i = 2^{k_i}$。 これは、2 を底とする対数を取得するか、2 で割ることを繰り返して行うことができます。 
2. 合計を計算する$S = \sum k_i$。 2 の累乗を乗算すると指数が加算されるため、これは完全な積の指数を表します。 
3. 定数を計算する$c = \log_2(2024)$。 これは修正されており、一度だけ事前計算できます。 
4. 実際の値を計算する$b = S / c$。 
5. 天井を戻す$b$、不等式を満たす最小の整数が必要なので。 

各ステップは、拡大をシミュレートするのではなく、問題のサイズを縮小します。 重要な設計上の選択は、乗算構造を指数演算に圧縮することです。これにより、大きな数を構築することがなくなります。 

### なぜ効果があるのか

 正しさは 2 つの不変条件に基づいています。 まず、2 のべき乗の積は指数の合計によって正確に決定されるため、配列を次のように置き換えても情報が失われることはありません。$S$。 第 2 に、対数は単調変換であるため、指数形式間で変換するときに不等式が保持されます。 これにより、対数領域の不等式を解くとまったく同じしきい値が生成されることが保証されます。$b$元の指数関数的な条件として。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    total_exp = 0
    for x in arr:
        total_exp += x.bit_length() - 1  # since x is power of 2
    
    if total_exp == 0:
        print(0)
        return
    
    log2_2024 = math.log2(2024)
    
    b = total_exp / log2_2024
    print(math.ceil(b))

if __name__ == "__main__":
    solve()
```コードはまず、各入力数値をビット長を使用して指数に変換します。これは、各値が 2 の累乗であることが保証されているため、安全な整数方式です。 合計`total_exp`完全な製品を圧縮形式でキャプチャします。 

特別な場合`total_exp == 0`すべての要素が 1 であることに対応するため、積は 1 となり、2024 のべき乗はそれを超える必要はありません。$b = 0$。 

最後に、次を使用して対数変換が 1 回行われます。`math.log2(2024)`、そして上限により、必要な指数を過小評価しないことが保証されます。

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n = int(sys.stdin.readline())
    arr = list(map(int, sys.stdin.readline().split()))
    
    total_exp = 0
    for x in arr:
        total_exp += x.bit_length() - 1
    
    if total_exp == 0:
        return "0\n"
    
    b = math.ceil(total_exp / math.log2(2024))
    return str(b) + "\n"

# single large power
assert run("1\n1024\n") == "1\n"

# symmetric case
assert run("2\n1024 1024\n") == "1\n"

# stronger case
assert run("3\n1024 1024 1024\n") == "3\n"

# boundary mix
assert run("3\n1 2 4\n") == "1\n"

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての要素が 1 である場合です。この状況では、指数の合計は 0 であるため、積は 1 に等しくなります。アルゴリズムはこれを明示的にチェックし、0 を返します。これは、次の事実と一致します。$2024^0 = 1$。 

もう 1 つのエッジ ケースは、単一の値 2 など、指数の合計が小さいがゼロではない場合です。比率は 1 未満になりますが、上限により 1 が生成されます。これは正しいことです。1 より大きい値を超えるか一致するには、少なくとも 1 回の 2024 の乗算が必要だからです。 

最後の構造上のエッジ ケースは、合計が十分に大きいため、浮動小数点の精度が懸念される場合です。 以来$S \le 500$、比率$S / \log_2(2024)$安全な倍精度範囲内に十分に収まるため、精度の損失は整数の上限の結果に影響を与えません。
