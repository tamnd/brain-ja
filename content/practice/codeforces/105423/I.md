 ## 問題の理解

 私たちは、複数のハッシュ関数を使用してハッシュ フィルター処理されたセットのように動作する、簡素化されたメンバーシップ システムを構築しています。 システムは要素を次のサイズのバイナリ配列に格納します。`n`、最初はすべてゼロです。 要素が挿入されると、次のように計算されます。`k`そこからの決定論的なハッシュのような値を取得し、配列内のそれらの位置を次のようにマークします。`1`。 要素をクエリすると、同じ要素が再計算されます。`k`値を調べて、対応するすべての位置が既に設定されているかどうかを確認します。`1`。 「はい」の場合、要素が「存在する」と報告し、そうでない場合は、要素が「存在しない」と報告します。 

変換関数は非常に単純です: 各関数インデックスごとに`i`、値は次のようにマッピングされます。`h_i(x) = x^i mod n`。 これは、すべての要素が小さなインデックスのセットを生成することを意味します。`[0, n-1]`、これらのインデックスは挿入とクエリの両方を駆動するものです。 

制約は十分に小さいため、簡単なシミュレーションが可能です。 と`n, m, q ≤ 10000`そして`k ≤ 10`、各演算は最大 10 個のべき乗または乗算のモジュラーです。 クエリと挿入ごとに単純に検出力を計算したとしても、実行できるのは約`m + q`それぞれの操作にはわずかな一定のコストがかかります。 

微妙なエッジケースは、インデックスが剰余として取得されるという事実から生じます。`n`したがって、衝突は予期されており、正確さのために必要ですらあります。 もう 1 つの問題は、同じクエリまたは挿入内のインデックスの重複です。 以来`h_i(x)`等しいことができます`h_j(x)`さまざまな`i`そして`j`、マークまたはチェックでは、繰り返しを安全に処理する必要があります。 セットを使用するか、重複排除なしですべてのインデックスを単純に反復処理することは引き続き機能しますが、重複排除により不必要な繰り返しチェックが回避されます。 

単純な間違いは、べき乗をモジュラーリダクションなしで線形乗算として扱うか、それを忘れることです。`x^i`早く成長します。 ただし、以来、`i ≤ 10`、直接計算は安全です。 もう 1 つの落とし穴は、これが真の確率的なブルーム フィルターではなく、決定的な固定ハッシュのバリアントであるという誤解です。 

## アプローチ

 ブルートフォースの解釈は簡単です。挿入ごとに、すべてを計算します。`k`累乗し、配列内のそれらの位置を次のように設定します。`1`。 クエリごとに同じものを再計算します`k`位置を確認し、すべてが正しいかどうかを確認します`1`。 

このアプローチは正しいです。なぜなら、システム定義ではメンバーシップがそれらのポジションによってのみ決定されると直接述べられているからです。 配列自体以外には、隠れた状態や順序の依存性はありません。 

複雑さのボトルネックは演算の数ではなく、非効率的に実装された場合の累乗の繰り返しによって発生します。 再計算すると`x^i`ループ内で単純な乗算を使用するたびにゼロから作成すると、各演算にコストがかかります`O(i)`、最悪のケースを与える`O(k^2)`操作ごとではありますが、制約の下では依然として自明です。 より高価な方法でもまだ合格します。 

重要な観察は次のとおりです`k ≤ 10`は小さいため、高度な最適化は必要ありません。 事前計算によるべき乗`k`値ごとに計算するか、値を段階的に計算するだけで十分です。 計算できる`x^1`を繰り返し乗算します。`x`モジュロ`n`取得するため`x^2`、`x^3`、 等々。

 ## アルゴリズムのチュートリアル

 バイナリ配列を維持します`arr`サイズの`n`、最初はすべてゼロです。 

1.読む`n, k, m, q`そして初期化する`arr`ゼロ付き。 この配列は、各インデックスが少なくとも 1 つの挿入された要素によってアクティブ化されているかどうかを表します。 
2. 挿入された要素ごとに`x`、すべての値を計算します`x^1 mod n, x^2 mod n, ..., x^k mod n`。 これは、ランニングパワー値を維持することで繰り返し実行できます。 
3. 計算されたインデックスごとに、`arr[index] = 1`。 配列は冪等であるため、割り当てを繰り返しても無害です。 
4. 各クエリ要素について`y`、同じ反復指数法を使用して同じインデックスのシーケンスを計算します。 
5. すべてチェックする`k`インデックス。 のいずれかのポジションであれば、`arr`は`0`、出力`0`そのクエリに対してすぐに対応します。 
6. すべてのポジションが正しい場合`1`、出力`1`。 

キャッシュではなく要素ごとに累乗を個別に再計算する理由は、`m`そして`q`小さく、入力は独立しています。 共有キャッシュを使用すると、漸近的な複雑性が有意義に改善されずに実装が複雑になります。 

### なぜ効果があるのか

 各要素は、変換関数によって生成されたインデックスのセットによって完全に表されます。 挿入により、これらのインデックスが次のように設定されることが保証されます。`1`。 クエリは、クエリ要素に対応するすべてのインデックスが以前の挿入によって設定されている場合にのみ成功します。 配列は決してビットをリセットしないため、`1`に戻る`0`、挿入された要素の証拠が単調に蓄積されます。 したがって、クエリの完全なインデックス セットがアクティブ化された位置のセットに含まれている場合、それは以前に挿入されている必要があり (または、このハッシュ スキームでは区別できません)、問題のメンバーシップの定義と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def compute_indices(x, k, n):
    res = []
    val = x % n
    for i in range(1, k + 1):
        res.append(val)
        val = (val * x) % n
    return res

def main():
    n, k, m, q = map(int, input().split())
    arr = [0] * n

    insert_vals = list(map(int, input().split()))
    query_vals = list(map(int, input().split()))

    for x in insert_vals:
        for idx in compute_indices(x, k, n):
            arr[idx] = 1

    out = []
    for y in query_vals:
        ok = True
        for idx in compute_indices(y, k, n):
            if arr[idx] == 0:
                ok = False
                break
        out.append('1' if ok else '0')

    print(' '.join(out))

if __name__ == "__main__":
    main()
```実装の詳細の中心となるのは、反復電力計算です。 再計算する代わりに`x^i`ゼロからメンテナンスします`val = x^i mod n`そしてそれを次のように更新します`val = val * x % n`。 これにより、繰り返しの作業が減り、コードがクリーンで予測可能な状態に保たれます。 

配列`arr`唯一の永続的な状態として機能します。 挿入はビットを設定するだけであり、クエリはビットを読み取るだけです。 この単調な構造により、削除処理やロールバック ロジックが不要になります。

 ## 特殊なケース

 クエリによって生成されたすべてのインデックスが繰り返される場合、たとえば、`x = 1`、私たちは得ます`[1,1,1,...]`。 アルゴリズムは同じ位置を複数回チェックしますが、配列はバイナリで安定しているため、結果は影響を受けません。 

のために`n = 1`、すべての指数は次のようになります。`0`, したがって、すべての要素は同じインデックスにマップされます。 システムは単一ビットのレジスタになり、すべての挿入またはクエリはその位置に折りたたまれます。 アルゴリズムは正しく設定します`arr[0] = 1`挿入後、すべてのクエリが返される`1`少なくとも 1 つの要素が存在すると。 

大きな値の場合、`x`、モジュラー乗算では値が制限されたままになるため、オーバーフローやパフォーマンスの低下は発生しません。 反復的なべき乗計算により、高速なべき乗を必要とせずに正確さが保証されます。
