 ## 解決策
 ## 問題の理解

 ある有向グラフに適用された変換プロセスから得られるツリーが与えられます。 このプロセスは深さ優先検索を実行し、検出時間を割り当て、頂点のスタックを維持し、特定の低リンク条件が満たされるたびに新しい補助ノードを作成し、それに頂点のバッチをアタッチします。 結果は常にツリーと呼ばれます。$T$。 重要な点は、このツリーは任意のものではなく、DFS 中に元のグラフの頂点と「構造コンポーネント」がどのように結合されるかをエンコードしているということです。 

現在は、元のグラフを再構築するように求められることはありません。 代わりに、このツリー内のエッジのサブセットを削除することができます。$T$、森を生み出します。 そのフォレストの接続された各コンポーネントはスタンドアロン ツリーとして解釈され、そのコンポーネントが同じ DFS 構築ルールの下で「有効」である場合に限り、そのコンポーネントが何らかの有効な元のグラフに対応すると仮定するように指示されます。 この問題を解決するために、このステートメントは、妥当性がノード ラベルではなく、ツリーとしてのコンポーネントの形状のみに依存することを保証します。 

各クエリ値について$x$、2 つの条件が同時に成立するように、削除するエッジのセットを選択する方法が何通りあるかを数えなければなりません。 まず、結果として得られるすべてのコンポーネントは、上記の意味で有効なツリーでなければなりません。 次に、各コンポーネントが何らかのグラフからのものとして解釈される場合、そのグラフ内のアーティキュレーション ポイントの数を計算します。すべてのコンポーネントにわたるこれらのカウントの合計は等しくなければなりません。$x$。 答えはモジュロで計算されます$10^9+7$。 

この制約は、すべてのテスト ケースにわたるノードの合計数が最大 5000 である一方、クエリの数は最大 5000 であることを意味します。$5 \cdot 10^5$。 これにより、ソリューションはクエリ応答から負荷の高い前処理を即座に分離するようになります。 クエリごとのトラバーサルは不可能であるため、すべての関連情報をグローバルな組み合わせ構造 (通常はクエリ可能な多項式または DP テーブル) に圧縮する必要があります。$O(1)$または$O(\log n)$。 

微妙な問題は、コンポーネントの「スコア」がエッジに直接接続されていないことです。 それは、ノードがそのコンポーネント内のアーティキュレーション ポイントになるかどうかに依存し、さらに削除後のノードの次数に依存します。 これは、一方のエッジを切断すると両方のエンドポイントの寄与に非線形的に影響を与える可能性があることを意味するため、単純な独立性の仮定は当てはまりません。 

よくある失敗例は、各エッジが独立して答えに寄与していると想定している場合です。 たとえば、星形のツリーでは、単一のエッジを削除すると、中心の次数が少なくとも 2 かどうかが変化し、その寄与が完全に反転する可能性があります。 したがって、構造はグローバルに結合されています。 

## アプローチ

 ブルートフォースアプローチでは、エッジのすべてのサブセットを列挙し、それに応じてツリーを分割し、各コンポーネントの有効性をチェックし、アーティキュレーションカウントを計算し、周波数を蓄積します。 これは正しいですが、すぐには実行不可能です。$n-1$エッジはすでに持っています$2^{n-1}$サブセット、たとえ制限をはるかに超えています$n=20$。 

重要な観察は、削除後の構造は木の森のままであるため、コンポーネントは切断したエッジを介してのみ相互作用するということです。 ツリーをルート化してボトムアップで処理する場合、エッジの切断に関するあらゆる決定は、サブツリーをその親から分離するだけです。 これは、各ノードが子からの情報を集約するツリー DP を示唆しており、各エッジはコンポーネント内に保持するか切り取るかの二者択一を表します。 

主な問題は、スコアが各最終コンポーネント内のノードの次数に依存することです。 ただし、コンポーネント内の次数は、保持される入射エッジの数によって正確に決まります。 これにより、問題を「コンポーネントの妥当性」から「ローカル次数のカウント」に移すことができます。 

最終的に、サブツリーごとに、指定された数の保持エッジと、アーティキュレーション スコアへの指定された寄与がどのように寄与できるかをカウントする DP を構築することになります。 ツリーのサイズは合計でわずか 5000 であるため、子を慎重にナップザック スタイルでマージすると、次の結果が得られます。$O(n^2)$解決。

 ## アルゴリズムのチュートリアル

 任意のノードでツリーをルート化します。 このアイデアは、各サブツリーを処理し、その親へのエッジが維持されるか切断されるかに応じてサブツリーがどのように動作するかを計算することです。 

### 1. DP の定義

 各ノードについて$u$、エッジがエッジかどうかに応じて 2 つの DP 状態を維持します。$u$親への状態が維持される (状態 1) か、維持されない (状態 0)。 各状態について、サブツリー内の保持されたエッジの数とそのサブツリー内の合計アーティキュレーション寄与度の分布を保存します。 

DP エントリは次のように考えることができます。$$dp_u[a][k][s]$$どこ$a \in \{0,1\}$親エッジが保持されるかどうかを示します。$k$はサブツリー内で保持される子エッジの数であり、$s$は、サブツリー内のノードからの累積アーティキュレーション スコアです。$u$さん自身の最後の貢献です。 

### 2. 初期化

 リーフ ノードには子がありません。 唯一可能な次数は親エッジからのものです。 したがって、親エッジが保持されている場合、その次数は 1 になり、そうでない場合は 0 になります。どちらの場合も、少なくとも次数 2 に到達できないため、スコアに寄与するのは 0 になります。 

### 3. 子の結合

 ノードの場合$u$、その子を 1 つずつ繰り返します。 子を処理するとき$v$、エッジを維持するという 2 つのオプションがあります。$(u,v)$またはカットします。 維持すると度が上がります$u$そのコンポーネント内で 1 ずつ移動し、切断すると子が完全に分離されます。 

これは DP 状態に対する畳み込みステップになります。保持されたエッジの分布と子からの累積スコアを組み合わせます。 

重要な点は、すべての子を処理した後、インシデント エッジの数が正確にわかることです。$u$コンポーネント内に保持されます。 

### 4. の貢献を追加$u$維持される入射エッジの数が一定になると、$u$が決定されると、次のことを計算できます。$u$コンポーネント内の関節点になります。 これは、コンポーネント内の合計次数が少なくとも 2 である場合にのみ発生します。その次数は次のとおりです。$$deg(u) = (\text{kept child edges}) + (\text{parent edge if kept})$$そこで、次のように追加します。$$+1 \quad \text{if } deg(u) \ge 2$$### 5. 最終集計

 ルートの DP を計算した後、両方のルート状態を合計し、考えられる合計スコアごとにカウントを収集します。$x$。 これにより、すべてのクエリに直接応答するグローバル周波数配列が得られます。 

### なぜ効果があるのか

 正確さは、すべてのエッジの決定がノード次数を除いて独立しており、ノード次数は入射エッジの局所的な選択によって完全に決定されるという事実から得られます。 DP では、すべてのサブツリーに対してすべての一貫した構成が考慮され、サブツリーをマージするときに正確な次数が保持されます。 調音の寄与は最終次数のみに依存するため、隠れた大域的な依存関係は残りません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    sys.setrecursionlimit(1000000)

    parent = [-1] * n
    order = []

    def dfs(u, p):
        parent[u] = p
        for v in g[u]:
            if v == p:
                continue
            dfs(v, u)
        order.append(u)

    dfs(0, -1)

    dp = [None] * n

    def merge(a, b):
        na = len(a)
        nb = len(b)
        res = [0] * (na + nb)
        for i in range(na):
            if a[i] == 0:
                continue
            for j in range(nb):
                if b[j] == 0:
                    continue
                res[i + j] += a[i] * b[j]
                res[i + j] %= 1000000007
        return res

    def dfs2(u, p):
        dp0 = [1]
        dp1 = [0]

        for v in g[u]:
            if v == p:
                continue
            child = dfs2(v, u)
            new0 = merge(dp0, child)
            new1 = merge(dp1, child)
            dp0, dp1 = new0, new1

        size = len(dp0)
        add0 = [0] * size
        add1 = [0] * (size + 1)

        for k in range(size):
            ways0 = dp0[k]
            ways1 = dp1[k]
            if k >= 2:
                add0[k] = (add0[k] + ways0) % 1000000007
            if k + 1 >= 2:
                add1[k + 1] = (add1[k + 1] + ways1) % 1000000007

        dp0 = [(dp0[i] + add0[i]) % 1000000007 for i in range(size)]
        dp1 = [(dp1[i] + add1[i]) % 1000000007 for i in range(size + 1)]

        dp[u] = (dp0, dp1)
        return dp[u]

    dp_root = dfs2(0, -1)
    dp0, dp1 = dp_root

    q = int(input())
    freq = {}

    def add(arr, shift):
        for i, v in enumerate(arr):
            if v:
                freq[i + shift] = (freq.get(i + shift, 0) + v) % 1000000007

    add(dp0, 0)
    add(dp1, 0)

    for _ in range(q):
        x = int(input())
        print(freq.get(x, 0) % 1000000007)

if __name__ == "__main__":
    solve()
```実装はポストオーダー DFS を中心に構造化されています。 各ノードは、子を一度に 1 つずつマージし、各子エッジをバイナリ包含の選択肢として扱うことによって DP を構築します。 各ノードでの最終調整では、そのノードが最終次数しきい値に基づいて調音点になるかどうかが考慮されます。 

微妙な実装の詳細は、親エッジが含まれるかどうかについて個別の状態を保持する必要があることです。これは度合いに影響を与え、したがってアーティキュレーション条件に影響します。 最終的な回答は、ルート DP が完了した後にのみ集約されます。 

## 実用的な例

 3 つのノードからなる小さなチェーンを考えてみましょう$1-2-3$。 ルートは 1 です。 

ノード 3 では、可能な構成は 1 つだけです。すべての場合において次数が最大 1 であるため、何も寄与しません。 ノード 2 では、1 と 3 までのエッジが保持されるかどうかに応じて、その次数の範囲は 0 から 2 の範囲になり、両方のエッジが保持される場合のみ、アーティキュレーション寄与度 1 が生成されます。 

| ノード | サブツリー内のエッジを維持 | 程度の条件 | 貢献 |
 | --- | --- | --- | --- |
 | 3 | 0 または 1 | 決して ≥ 2 | 0 |
 | 2 | 0、1、2 | 依存します | 0 または 1 |
 | 1 | 依存します | 依存します | 0 または 1 |

 この例は、寄与がどのようにエッジに対してローカルではなく、結合されたサブツリー構造に依存するかを示しています。 

ここで、1 を中心とし、葉 2、3、4 を持つ星を考えてみましょう。 少なくとも 2 つのエッジが維持されている場合にのみ、中心がアーティキュレーション ポイントになります。 これにより、DP は独立したエッジの寄与ではなく、選択されたエッジのカウントを追跡するようになります。
