 ## 解決策
 ## 問題の理解

 私たちにはシグナルの集合が与えられています。 各信号には、エネルギー値と周波数値という 2 つの数値属性があります。 このタスクは、順序付けされた信号のペアをすべて考慮し、2 つの独立した部分の積によって定義されるコストを累積することです。 

最初の部分はエネルギーのみに依存し、単純に 2 つのエネルギー値間の絶対差です。 2 番目の部分は周波数のみに依存し、2 つの周波数値の gcd の 2 乗です。 すべてのペアはこれら 2 つの要素を掛け合わせたものであり、文字通り解釈すると次数と自己ペアの両方を含むすべてのペアにわたってこれを合計します。 

したがって、入力の直接解釈は、信号によってインデックス付けされた 2 つの配列になります。 1 つのアレイは、ペアのエネルギーの違いがどの程度強いかを制御し、もう 1 つのアレイは、それらの周波数が公約数によって相互にどの程度強く強化されるかを制御します。 

この制約により、二次アプローチは即座に除外されます。 最大 20 万の信号の場合、すべてのペアを反復処理すると、すでに 4 × 10^10 程度の演算が行われ、各演算には gcd と絶対値が含まれます。 最適化を行ったとしても、これは数秒で実行できる範囲をはるかに超えています。 

さらに微妙な問題は、この関数が単純な方法では分離できないことです。 gcd 項は 2 つのインデックスを非線形に結合しますが、差の絶対値は完全に異なる配列に依存します。 これにより、完全なペア セットに対する単純な畳み込みや並べ替えのトリックが防止されます。 

素朴な推論の落とし穴を暴露するような危険な状況もあります。 たとえば、すべての周波数が等しい場合、gcd 項は一定となり、問題は古典的な差の絶対和に帰着します。 この場合でも、gcd 処理をオーバーエンジニアリングするソリューションは正しく削減する必要があります。 逆に、すべてのエネルギーが等しい場合、周波数構造に関係なくすべての項がゼロになります。これは、正しさの健全性チェックに役立ちます。 

もう 1 つの特殊なケースは、周波数がペアごとに互いに素である場合です。 その場合、gcd は常に 1 であるため、問題は再び絶対差の純粋和に帰着し、周波数構造を過大に重み付ける解法は、存在しないところで誤って複雑さを導入することになります。 

## アプローチ

 ブルートフォース手法は簡単です。 インデックスの各ペアについて、周波数の gcd を計算し、二乗し、エネルギーの差の絶対値を計算し、その積を答えに加算します。 これは定義に直接従うため正しいですが、2 次の gcd 計算を実行します。 n が 200,000 までの場合、数百億回の演算が必要となり、これは実行不可能です。 

主な障害は gcd の 2 乗項です。 各ペアを個別に扱うのではなく、公約数構造によってペアをグループ化することを提案します。 2 つの周波数が gcd g を共有する場合、両方とも g の倍数でなければなりません。 この観察により、信号を直接ペアリングするのではなく、割り算によってグループ化することができます。 

視点を逆転させます。 最初にペアを作成して gcd を計算する代わりに、候補 gcd 値 g を固定し、周波数が両方とも g で割り切れるすべてのペアを調べます。 これらのペアはエネルギー差の g² 倍に寄与しますが、gcd が g と正確に等しいものは一部だけです。 これは、除数に対する典型的な包含/除外構造です。 

固定 g の場合、周波数が g で割り切れるすべてのインデックスを定義します。 これらの指標のうち、エネルギーの差の絶対値和はソートすることで効率的に計算できます。 ただし、これは、正確に g ではなく、gcd が g の倍数であるすべてのペアをカウントします。 正確な gcd 寄与を分離するために、除数格子にメビウス反転を適用します。

まず、g ごとに、正確な gcd に関係なく、周波数が g で割り切れるすべてのペアの合計寄与度を計算します。 次に、メビウス関数を使用して、より大きな gcd 倍数からの寄与を差し引きます。 各 gcd 値の正確なペアの寄与を取得した後、g² を乗算し、すべての g を合計します。 

残っている唯一の技術的タスクは、周波数が g で割り切れるインデックス間のエネルギーの絶対差のすべてのペアの合計を g ごとに計算することです。 これは、そのグループ内のエネルギーを収集し、それらを並べ替え、プレフィックス合計を使用して、並べ替え後に線形時間でペアごとの絶対差の合計を計算することによって実行できます。 

重要な効率観察は、各インデックスがその頻度の約数のみの割り切れるリストに表示され、2 × 10^5 までのすべての数値にわたる約数の合計数が平均して小さいことです。 これにより、作業全体を管理しやすくなります。

 ## アルゴリズムのチュートリアル

 1. 可能な最大周波数値までメビウス関数を事前計算します。 これにより、後で除数の倍数に対する包含/除外が可能になります。 
2. 可能な約数 g ごとに、b[i] が g で割り切れるようなインデックス i のリストを作成します。 これにより、各グループが周波数の公約数の候補に対応するように問題が再構成されます。 
3. 各 g について、絶対差の合計 |a[i] - a[j]| として定義される値 G(g) を計算します。 g で割り切れるインデックスのグループ内のすべてのペアにわたって。 これは、そのグループ内のエネルギーをソートし、プレフィックス合計を使用してペアごとの差を効率的に蓄積することによって行われます。 
4. g で割り切れるすべてのペアをカウントする G(g) を、周波数の gcd が正確に g であるペアのみをカウントする F(g) に変換します。 これは、メビウス反転を使用して g のすべての倍数から寄与を差し引き、mu(k) * G(gk) を合計することによって達成されます。 
5. それぞれの正確な gcd クラス g は、最終的な答えに g² * F(g) を与えます。 これをすべての g にわたって累積し、結果のモジュロ 998244353 を返します。 

正しさは 2 つの層の分解から得られます。 最初の層は gcd を除数制約に置き換え、ペアごとの gcd 条件を除数グループのメンバーシップに変換します。 2 番目の層は、メビウス反転を使用して共有倍数にわたる過剰カウントを削除し、正しい gcd クラスで各ペアが正確に 1 回カウントされるようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def build_mobius(n):
    mu = [1] * (n + 1)
    prime = []
    vis = [False] * (n + 1)
    for i in range(2, n + 1):
        if not vis[i]:
            prime.append(i)
            mu[i] = -1
        for p in prime:
            if i * p > n:
                break
            vis[i * p] = True
            if i % p == 0:
                mu[i * p] = 0
                break
            else:
                mu[i * p] = -mu[i]
    return mu

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    maxv = max(b)
    mu = build_mobius(maxv)

    divs = [[] for _ in range(maxv + 1)]
    for i, bi in enumerate(b):
        j = 1
        while j * j <= bi:
            if bi % j == 0:
                divs[j].append(i)
                if j * j != bi:
                    divs[bi // j].append(i)
            j += 1

    def pair_abs_sum(vals):
        vals.sort()
        res = 0
        pref = 0
        for i, x in enumerate(vals):
            res += x * i - pref
            pref += x
        return res

    G = [0] * (maxv + 1)

    for g in range(1, maxv + 1):
        idxs = divs[g]
        if not idxs:
            continue
        vals = [a[i] for i in idxs]
        G[g] = pair_abs_sum(vals)

    F = [0] * (maxv + 1)

    for g in range(maxv, 0, -1):
        if G[g] == 0:
            continue
        s = 0
        k = 1
        while g * k <= maxv:
            s = (s + mu[k] * G[g * k]) % MOD
            k += 1
        F[g] = s % MOD

    ans = 0
    for g in range(1, maxv + 1):
        if F[g]:
            ans = (ans + F[g] * (g * g % MOD)) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```この実装では、まずメビウス値を構築して、約数の反転を可能にします。 次に、周波数の割り算によってインデックスをグループ化します。これは、ペアごとの処理からの重要な構造的移行です。 各グループについて、エネルギーは線形時間でソートおよび処理され、合計絶対差の寄与が計算されます。 最後に、倍数に対する逆包含-除外により、2 乗 gcd 重みを適用する前に正確な gcd クラスが分離されます。 

実装上の微妙な点は、除数によるグループ化により重複するセットが作成されるため、生の合計 G(g) が意図的に過大にカウントされることです。 メビウス ステップは正確さを復元するもので、これを省略すると、ペアが共有する約数の数に応じてペアが複数回カウントされます。 

## 実用的な例

 周波数が構造 a = [1, 4, 2]、b = [2, 4, 6] を共有する小規模な構成を考えてみましょう。 

まず除数グループを構築します。 g = 1 の場合はすべてのインデックスが含まれ、g = 2 の場合はすべての周波数が偶数なのですべてのインデックスが含まれ、g = 3 の場合は最後の 2 つだけが 6 まで間接的に含まれます。 

| g | インデックス (b は g で割り切れます) | エネルギー | G(g) |
 | --- | --- | --- | --- |
 | 1 | [0,1,2] | [1,4,2] | すべてのペアから計算 |
 | 2 | [0,1,2] | [1,4,2] | 同じ構造 |
 | 3 | [2] | [2] | 0 |

 G(g) を計算した後、メビウス反転により寄与が分離され、gcd がちょうど 2 であるペアと gcd が 1 または 4 であるペアが区別されます。次に、各クラスは g² で重み付けされ、最終的な合計が生成されます。 

このトレースは、同じグループのインデックスが複数の除数レベルにどのように寄与するかを示しており、反転のみが真の gcd 分類を正しく分離します。 

ここで、縮退ケース a = [5, 5, 5]、b は任意であると考えてみましょう。 あらゆるエネルギー差はゼロです。 

| g | G(g) | F(g) |
 | --- | --- | --- |
 | 任意 | 0 | 0 |

 このアルゴリズムは、周波数構造について推論する必要がなく、正確にゼロを生成し、エネルギー成分が正確さを完全に支配していることを確認します。

 ## 特殊なケース

 すべての周波数が同一である場合、すべての除数グループが 1 つの完全なセットに折りたたまれます。 アルゴリズムは、すべてのインデックスをその周波数のすべての除数バケットに配置することでこれを処理し、メビウス反転は正しい gcd レベルを除くすべての寄与をキャンセルして、過剰カウントが残らないようにします。 

すべての周波数がペアごとに互いに素である場合、各非自明な除数バケットには最大 1 つの要素が含まれます。 その状況では、1 より大きいすべての g について G(g) はゼロとなり、g = 1 のみが寄与します。 逆変換ステップは簡単になり、アルゴリズムは 1² で重み付けされた純粋な絶対差分和に正しく還元されます。 

すべてのエネルギーが同一の場合、ソートされたプレフィックスの差が正確にキャンセルされるため、計算されたすべての G(g) はゼロになります。 これは反転を通じて伝播するため、すべての F(g) はゼロになり、最終的な答えは周波数構造に関係なくゼロになります。
