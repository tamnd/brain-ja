 ## 問題の理解

 長さのビットマスクによってインデックス付けされた 2 つの配列が与えられます。`n`、したがって、各インデックスは、`n`-要素ユニバースは 2 進数としてエンコードされます。`0`に`2^n - 1`。 マスクごとに`i`、値を計算する必要があります`c[i]`要素の組み合わせによって形成される`(j, k)`次のようなビット単位の OR`j`そして`k`等しい`i`、および次のビット単位の AND`j`そして`k`はゼロです。 言い換えると、`j`そして`k`和集合が正確に一致する素のサブセットでなければなりません`i`。 

有効な分割ごとに、`i`2 つの互いに素なサブマスクを乗算します。`a[j]`そして`b[k]`そしてそのようなすべてのペアを合計します。 最後に、必要なのは結果のモジュロだけです`4`、つまり、それぞれの下位 2 ビットのみを考慮します。`c[i]`。 

重要な構造上の詳細は、あらゆる部分が`i`に行くかどうかを独自に決定します`j`またはへ`k`、これはまさに存在することを意味します`3^n`すべての有効な割り当て`(i, j, k)`トリプル。 この分離可能性により、サブマスクの畳み込みが可能になります。 

制約は厳しいです:`n ≤ 21`, したがって、配列のサイズは最大約 200 万になります。 すべてのマスクにわたる二次畳み込みは不可能であり、`O(N^2)`と`N = 2^n`実現可能な限界をはるかに超えています。 したがって、解決策は次のようにする必要があります。`O(n * 2^n)`または同様のもの。 

モジュロ要件から微妙なエッジケースが発生します。 モジュロの答えだけが必要なので、`4`、中間値はすべてのステップで安全に減らすことができます。 ただし、これだけでは複雑さが軽減されるわけではありません。 算術が境界内にとどまることを保証するだけです。 もう 1 つの微妙な点は、すべてのビットが 3 つの状態のいずれかを選択するため、畳み込み条件は見た目は非対称ですが、実際には構造が対称であることです。`j`、に行きます`k`、またはどちらにもなりません (DP 状態を構築するときのサブ問題でのみ)。 

## アプローチ

 直接的な解釈は、すべてのペアを列挙することです。`(j, k)`あらゆる人にとって`i`そのような`j | k = i`そして`j & k = 0`。 それぞれについて`i`、すべてのサブマスクを反復処理します。`j ⊆ i`、 セット`k = i \ j`、蓄積します`a[j] * b[k]`。 これは正しいです。すべての有効な分解はサブセットの選択に一意に対応します。`j`。 ただし、これにより、全体的な複雑さがおおよそ次のようになります。$$\sum_i 2^{popcount(i)} = 3^n$$これはすでに天文学的な規模です`n = 21`。 

重要な観察は、これが古典的な「素のサブマスク畳み込み」であり、各ビットが左側のオペランドに寄与するか、右側のオペランドに寄与するか、またはどちらにも寄与しないかを個別に決定するということです。 この構造はまさに、サブセットに対するビット単位の変換で活用できるものです。 

これをビットごとの三項選択の畳み込みとして扱うことができ、サブセットに対する高速ゼータ状 DP を使用して計算できます。 アイデアは、ビットごとに寄与を増分的に構築することです。各ビット位置で、そのビットが割り当てられている状態を組み合わせます。`j`に割り当てられています`k`、または両方から除外されます。 これにより、SOS DP に似た動的プログラミング変換が行われますが、分岐は 2 方向ではなく 3 方向になります。 

この実装では、ビットの反復処理と DP 配列の更新が行われ、各状態がそのビットが寄与しているかどうかを考慮しながら、そのビットが異なるサブセットを持つ状態からの寄与を集約します。`a`、`b`、またはそのどちらでもない。

 ## アルゴリズムのチュートリアル

 配列を維持します`f[i]`から初期化されました`a[i]`、および別の配列`g[i]`から初期化されました`b[i]`。 目標は、ビットの素の割り当てを考慮した変換の下でそれらを結合することです。 

ターゲットを、各ビットが 3 つの可能性に分割される畳み込みを計算するものとして再解釈します。 これを効率的に行うために、サブセット全体にわたって DP 状態を維持し、貢献を少しずつ段階的にマージします。 

### ステップ

 1. 2 つの配列を初期化する`F`そして`G`サイズの`2^n`と`F[i] = a[i] mod 4`そして`G[i] = b[i] mod 4`。 

すべての演算は最終的にモジュロ 4 であるため、この削減は安全です。 
2. サブセット変換を実行します。`F`これにより、ビットごとの組み合わせが準備されます。 ビットごとに`bit`から`0`に`n-1`、すべてのマスクを反復処理します。`mask`。 ビットが設定されていない場合`mask`、マージ`F[mask ^ (1 << bit)]`の中へ`F[mask]`。 

このステップでは、制御された方法でスーパーセットにわたる寄与を蓄積します。 
3. 同じ変換を適用します`G`、同様に構造化された表現を生成します。 
4. マスクごとに点ごとに乗算します。`i`、計算する`H[i] = F[i] * G[i] mod 4`。 

この段階では、`F`に属する可能性のある要素のすべての可能な割り当てをエンコードします。`j`、 そして`G`に属するものをエンコードします`k`、変換された空間に整列します。 
5. 逆変換を適用します。`H`サブセット DP プロセスの逆を使用します。 これにより、正確な和集合マスクによってグループ化された値が再構築されます。 
6. 出力`H[i]`すべてのマスクに`i`。 

### なぜ効果があるのか

 インデックスの各ビットは、それが以下に属するかどうかを独立して選択します。`j`、`k`、またはそのどちらでもない。 DP 変換は、元の問題を、これらの独立したビットごとの選択が分離可能な線形演算になる空間に変換します。 順変換は、ビットを部分サブセットに除外または含めることができるすべての方法で集計し、ポイントワイズ乗算は、次の独立した寄与を結合します。`a`そして`b`。 次に、逆変換により、和集合が次と等しい構成が正確に分離されます。`i`そしてその交差点は空いています。 これらのビットごとの選択を通じて、すべての有効なトリプルが 1 つのパスに一意に対応するため、寄与が失われたり重複したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def fwht_like(arr, n, inv=False):
    # 3-state subset transform encoded via inclusion DP trick
    # We use standard SOS DP twice structure:
    # This is a known construction for disjoint subset convolution modulo small constants.
    for bit in range(n):
        step = 1 << bit
        for mask in range(1 << n):
            if mask & step:
                if not inv:
                    arr[mask] = (arr[mask] + arr[mask ^ step]) & 3
                else:
                    arr[mask] = (arr[mask] - arr[mask ^ step]) & 3
    return arr

def solve():
    n = int(input())
    N = 1 << n

    a = list(map(int, list(input().strip())))
    b = list(map(int, list(input().strip())))

    F = [x & 3 for x in a]
    G = [x & 3 for x in b]

    fwht_like(F, n, inv=False)
    fwht_like(G, n, inv=False)

    H = [(F[i] * G[i]) & 3 for i in range(N)]

    fwht_like(H, n, inv=True)

    print("".join(str(x & 3) for x in H))

if __name__ == "__main__":
    solve()
```この実装では、各ビットが独立して処理されるサブセット DP スタイルの変換が使用されます。 フォワード パスは、1 ビット異なるサブセットからの寄与を蓄積し、マスクを分解できるすべての方法を効果的にエンコードします。`j`そして`k`。 乗算ステップでは、2 つの変換された空間がマージされます。 逆パスは、正確な和集合マスクによってグループ化された値を復元し、順変換によって導入された過剰カウントをキャンセルします。 モジュロ 4 を使用すると、すべての中間加算と減算が小さなリング内で安定したままになります。 

実装の微妙な詳細は、減算が次を使用して実行されることです。`& 3`、値は常に に残るため安全です。`{0,1,2,3}`この変換の下で。 もう 1 つの重要な点は、各更新は同じ反復内の下位ビットの状態にのみ依存するため、ここではビットの増加順にマスクを反復する必要がないことです。

 ## 特殊なケース

 のために`n = 0`、マスクは 1 つだけあります`0`、唯一の有効なトリプルは`(0,0,0)`。 アルゴリズムは乗算に帰着します`a[0] * b[0] mod 4`、変換は恒等演算になるため、出力は正しくなります。

最大限に`n = 21`、メモリ使用量は、約 200 万の整数のサイズの 3 つの配列によって支配されます。これは、Python ints modulo 4 として格納される場合、64 MB の制限の下では安全です。これは、各値が小さく、Python のオーバーヘッドが競争上の制約の中で許容可能なままであるためです。
