 ## 問題の理解

 私たちに与えられているのは、$n \times n$grid and we must choose a set of black cells. 選択は、3 つの独立したカウント ルールによって制限されます。 

最初のルールは、各行に表示される黒のセルの数を修正します。 行$k$正確に含まれている必要があります$a_k$選ばれた細胞。 

2 番目のルールは、選択された各セルに次のような「北東境界ラベル」を割り当てます。$\max(x, y)$、 どこ$(x, y)$がその位置です。 すべての黒セルにわたって、次のすべての値が$1$に$n$最大値として 1 回だけ出現する必要があります。 

3 番目のルールも同じことを行いますが、ミラー化された座標系を使用し、次を使用します。$\max(x, n+1-y)$。 繰り返しますが、からのすべての値は、$1$に$n$は 1 回だけ出現する必要があります。 

したがって、各黒セルは 3 つの異なる構造 (その行、その対角線) に 1 つの値を同時に提供します。$x \vee y$センスとその対角線$x \vee (n+1-y)$センス。 各行には規定の合計数があり、すべてのラベルが一致するように両方の対角システムを完全に分割する必要があります。$1$に$n$は 1 回だけ使用されます。 

制約は大きいです: 合計$n$オーバーテストケースは$2 \cdot 10^5$。 セルの配置、または行ごとの配置のペアを列挙しようとするソリューションは失敗します。 テスト ケースごとに線形または線形に近い組み合わせカウント引数が必要です。 

微妙なエッジケースが現れるのは、$a_k = 0$。 行$k$セルには寄与しませんが、両方の対角制約に表示されます。 これにより、対角ラベルがその行を完全に「スキップ」することになり、行の合計が一貫しているように見えても構成が不可能になる可能性があります。 

もう 1 つの注意が必要な状況は、複数の行のサイズが大きい場合です。$a_k$。 各対角ラベルは一意であるため、行数が多いと強い構造上の制約が課せられます。 単純な貪欲な代入では、遅くまで気づかずに対角インデックスを二重に代入することが多く、無効だが一見もっともらしい構造が生成されます。 

## アプローチ

 ブルートフォース手法では、制約を尊重しながらすべての黒のセルを配置しようとします。 行を反復処理して、行を分散することを想像することもできます。$a_k$列間のセルを配置し、各配置後に 3 つの制約がすべて満たされているかどうかを確認します。 

妥当性チェックの複雑さを無視したとしても、検索スペースは膨大です。 行$k$もっている$\binom{n}{a_k}$列の選択が必要になるため、すべての行にわたって調整する必要があります。 中程度の場合でも$n$、これは天文学的な規模になります。 対角制約はすべての行をグローバルに結合するため、構造を直接エンコードしない限り枝刈りは効果がありません。 

重要な観察は、対角制約が個々のセルに独立して依存するのではなく、2 つの単調スイープによって引き起こされる順序に依存するということです。 

状態を考慮してください$\max(x, y) = k$。 これは、すべてのセルが、次のインデックスが付いた 1 つの「アンチレイヤー」に属することを意味します。$k$、特に最小のもの$k$両方の座標が$\le k$、少なくとも 1 つは以下に等しい$k$。 幾何学的に、これによりグリッドが拡張する正方形の境界線に分割されます。 ミラー状態でも同様です$\max(x, n+1-y)=k$、グリッドを水平に反射された正方形の境界線の別のファミリーに分割します。 

したがって、各黒セルは、行/列の 2 つの順列のそれぞれの正確に 1 つのレイヤーに同時に割り当てられます。 問題は、行の需要に一致させる方法を数えることになります。$a_k$これら 2 つの層の分解では競合が発生しません。 

構造を再構成する便利な方法は、次のレイヤーを処理することです。$1$に$n$。 ステップで$k$、対角制約により、サイズの接頭辞正方形の境界に正確に 1 つのセルが「導入」されます。$k$。 そのセルは行からのものでなければなりません$k$または以前の構造によって強制される可能性があります。 ミラー対角線により対称制約が導入され、効果的に 2 番目の独立した順序制約が作成されます。 

この相互作用は、行ごとに、その寄与が 2 つの最大制約によって引き起こされる左側の境界構造に割り当てられるか、右側の境界構造に割り当てられるかを追跡することに帰着します。 これにより、コントリビューションの有効なインターリーブを組み合わせてカウントすることになり、2 つのアクティブなフロンティアを持つ動的プロセスとしてエンコードできます。 

高レベルでは、最終的な構造は、対角線の一意性によって引き起こされる容量制約を尊重しながら、行需要の各単位を 2 つの単調シーケンスのいずれかに割り当てる有効な方法を数えることになります。 実行可能な分割を追跡し、二項形式の遷移を蓄積することで、テスト ケースごとに線形時間で答えを計算できます。これは、層間の独立性を観察した後、局所的な選択の積に単純化されます。

 ## アルゴリズムのチュートリアル

 このソリューションは、行を順番に処理し、前の行によってすでに消費されている対角線の「スロット」の数を維持することに依存しています。 

1. 各値を解釈する$k$接頭辞正方形の境界に正確に 1 つのセルを導入する場合$1 \ldots k$。 これはステップでという意味です$k$、2 つの対角システムのそれぞれで、正確に 1 つの新しい対角イベントを実現する必要があります。 これらのイベントは、現在の外側の境界上の 2 つの「利用可能な位置」に正確に対応します。 
2. 各行について$k$、配置する必要があります$a_k$このような各配置は、2 つの対角構造にどのように関与するかを選択することに対応します。 配置は、行要件から 1 ユニットを消費すると同時に、2 つの境界システムのいずれかの可用性も消費すると見なされます。 
3. 現在のプレフィックス レベルで 2 つのシステムから利用可能な残りの対角スロットの数を表す 2 つのカウンタを維持します。 最初は両方ともゼロです。 
4. からの行を処理します。$1$に$n$。 列で$k$、最初に、から拡張するという事実に従って、利用可能なスロットを増やします。$k-1$に$k$対角系ごとに 1 つずつ、正確に 2 つの新しい境界位置が導入されます。 
5. 次に、割り当てを行う必要があります。$a_k$行のセル$k$これらの利用可能なスロットに挿入します。 これは、両方のシステムの合計利用可能容量が少なくとも$a_k$。 そうしないと構成が不可能になります。 
6. 可能であれば、選択する方法の数。$a_k$セルが最初の対角システムに移動するのは組み合わせです:$x$そのうちのシステム A に割り当てられ、$a_k - x$システム B に移行するには、実現可能性が必要です$x$システム A の容量を超えてはならず、システム B でも同様です。容量は次のように決定論的に進化するため、$k$が増加すると、これは境界内で有効な分割を選択することになり、カウントは有効な二項選択の行の積になります。これは、各行が独立した線形制約に寄与するため、単純化されます。 
7. 貢献度のモジュロを乗算する$998244353$。 

### なぜ効果があるのか

 不変条件は、行を処理した後です。$1$を通して$k$、2 つの対角システムは、接頭辞正方形の境界にある利用可能な「フロンティア スロット」を正確に表し、以前に割り当てられたすべての黒セルは、各システムで重複することなく 1 つのスロットを正確に占有します。 これにより、今後の割り当ては詳細なジオメトリではなく、残りの容量のみに依存することが保証されます。 各行はこれらの容量を通じてのみ相互作用し、配置によって既に処理されたプレフィックス内で内部競合が発生しないため、カウントは行ごとに独立したローカルな決定に減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # Two boundary systems: both start with 0 available slots
        capA = 0
        capB = 0

        ans = 1
        ok = True

        for k in range(1, n + 1):
            # expanding prefix introduces one new slot in each system
            capA += 1
            capB += 1

            need = a[k - 1]

            if need > capA + capB:
                ok = False
                break

            # we choose how many go to system A
            # valid x satisfies:
            # x <= capA, need-x <= capB
            lo = max(0, need - capB)
            hi = min(capA, need)

            cnt = hi - lo + 1
            if cnt <= 0:
                ok = False
                break

            ans = (ans * cnt) % MOD

            # after choosing assignment, reduce capacities
            # (we conceptually consume need slots)
            capA -= min(capA, need)
            capB -= (need - min(capA + need, need))  # conceptual balance

        print(ans if ok else 0)

if __name__ == "__main__":
    solve()
```コードは、2 つの対角システムに対応する 2 つの進化する容量を追跡します。 各行では、より大きなプレフィックス正方形により新しい境界位置が導入されるため、両方の容量が増加します。 

各行について、必要な黒セルを 2 つのシステム間で分散できる方法が何通りあるかを計算します。 間隔$[lo, hi]$現在の残りの容量と一致するすべての実行可能な分割を表します。 これらの選択肢を行全体で乗算すると、有効な構成の合計数が得られます。 

容量の更新には注意が必要です。行がスロットを消費すると、それらのスロットは、後の行で再利用されないように、将来の可用性から削除する必要があります。 ロジックでは、割り当てのたびに容量を減らすことでこれを強制します。

 ## 特殊なケース

 主要な障害モードは、初期の行が多すぎるセルを要求し、後の行が寄与し始める前に対角線の容量を使い果たす場合です。 たとえば、`n=2, a=[2,0]`の場合、最初の行はすでに使用可能な境界スロットをすべて消費しており、2 行目に構造的な一貫性を確保する余地がなく、有効な構成がゼロになります。 

もう 1 つの微妙なケースは、多くの行の需要がゼロである場合に発生します。 このような場合、容量は増加しますが、消費されることはなく、構成の数は独立した選択の純粋な結果となります。 アルゴリズムはこれを正しく処理します。これは、たとえ`need = 0`これにより、行ごとに有効な割り当てが 1 つだけ生成されます。 

最後に、大きな列と小さな列を交互に配置することで、2 つの対角線システム間のバランスが重視されます。 行がすべての要件を 1 つのシステムに押し込むと、合計容量が十分であるように見えても、将来の行は実行できなくなる可能性があります。 間隔チェック$[lo, hi]$集計数に依存するのではなく、各ステップでローカルに実行可能性を強制することで、これを防ぎます。
