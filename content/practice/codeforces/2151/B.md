 ## 問題の理解

 1 から 1 までの番号が付けられたセルを持つ仮想ストリップが与えられます。$10^9$、一部のセルは最初は黒で、残りは白です。 複数の人がセル 1 から開始し、それぞれが 2 つの命令で構成されるコマンド文字列のプレフィックスを実行します。 最初の指示は、`A`、人を 1 セル前に移動します。 2番目、`B`、人を現在の白セルの次の白セルに移動します。 コマンドを実行した後、各人は着地したセルを黒に塗ります。 私たちの仕事は、全員がコマンドを実行した後に黒になっているすべてのセルを報告することです。 

重要な制約は、テスト ケースあたりのコマンド数が最大で 2 つまでであることです。$10^5$、初期の黒セルの数も最大です。$10^5$。 コマンドまたは最初の黒セルのすべてのテスト ケースの合計の上限は次のとおりです。$10^5$。 これは、より複雑なソリューションを意味します。$O(n + m)$テストケースごとにタイムアウトのリスクがあります。 10 億個のセルにわたるセルごとの動きを直接シミュレーションすることは不可能であり、メモリの制限により完全なアレイを使用してすべてのセルを追跡することは不可能です。 

エッジケースは、最初のセルが黒である場合、または複数のセルが存在する場合に発生します。`B`コマンドは連続する黒セルをスキップします。 一度に 1 セルずつ増分して次の白いセルにジャンプしようとする単純なシミュレーションは、大きなギャップが存在する可能性があるため失敗し、パフォーマンスが低下する可能性があります。 たとえば、セル 1 が黒で、最初のコマンドが`B`、セル 2 が白の場合はセル 2 に直接ジャンプし、後続のセルが黒の場合はさらにジャンプする必要があります。 不注意な解決策は、次のことのみを考慮する可能性があります。`x+1`次の白マスではなく。 

## アプローチ

 ブルートフォース ソリューションでは、セル 1 から開始して各人をシミュレートし、各コマンドを 1 つずつ実行し、白いセルが見つかるまで前方にスキャンして次の白いセルを見つけます。 これは概念的には正しいですが、遅すぎます。 あれば$n = 10^5$コマンドが実行され、黒いセルが全体にまばらに広がります。$10^9$ストリップ、それぞれをスキャン`B`操作には最大で時間がかかる場合があります$10^9$最悪の場合には、実行可能をはるかに超えた措置を講じます。 

重要な観察は、黒に変わる可能性のある唯一のセルは、最初の黒いセル、またはコマンドのプレフィックスを実行してすぐにアクセスしたセルのいずれかであるということです。 各人は接頭辞に従って最終的に到達するセルをペイントするだけであり、各人は 1 から開始するため、一連の動きは単調です。 の効果に焦点を当てることができます。`B`すべてのセルを反復せずにコマンドを実行します。 具体的には、プレフィックスごとに、ポインターを保持することで最終セルを決定できます。`cur`1 から開始します。コマンドを繰り返し、増分します。`cur`のために`A`、そしてのために`B`私たちは移動します`cur`その後、未訪問の最小の白セルに`cur`。 

ソートされた黒セルのセットを維持すると、次の白セルを効率的に見つけることができます。 を実行するたびに、`B`、またはその後の最後の黒セルを超えた次の位置にジャンプします。`cur`。 操作の数は、コマンドの数に黒のセルの数を加えたものに比例しますが、これは許容範囲内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * ギャップ) | O(10^9) | 遅すぎる |
 | 最適 | O((n + m) log m) | O(m) | 承認済み |

 の`log m`この要因は、ソートされたコンテナまたは二分探索を使用して次の白セルを効率的に見つける場合に発生します。 

## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。`n`コマンド、`m`最初の黒セル、コマンド文字列`s`、および黒セルのリスト`a`。 リストを変換する`a`効率的な検索のためにソートされたセットまたは配列に変換します。 
2. 変数を初期化する`cur`1 に設定され、シミュレートされた人物の現在のセルを表します。 
3. 文字列内の各コマンドを繰り返します。 コマンドが`A`、単純に増加します`cur`1つずつ。 コマンドが`B`、次の値以上の最初の黒セルを見つけます。`cur`二分探索を使用します。 セット`cur`その黒いセルより 1 つ多いセルに移動し、実質的に次の白いセルにジャンプします。 
4. 黒く塗られたすべてのセルをセットに保存して追跡します。 最初に、すべての黒いセルを含めます。 長さのプレフィックスの処理が完了するたびに`i`、 追加`cur`セットへ。 
5. テスト ケースのすべてのコマンドを処理した後、黒いセルのセットを並べ替え、そのサイズと要素を出力します。 

全体を通して維持される不変条件は、`cur`すでに黒になっているセルを考慮して、コマンドに従って常に正しい次の位置を指します。 各ジャンプ経由`B`常に、現在の黒セル構成に関連して次の白セルに着地します。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

def process_case(n, m, s, black_cells):
    black_cells.sort()
    black_set = set(black_cells)
    cur = 1
    painted = set(black_cells)

    for cmd in s:
        if cmd == 'A':
            cur += 1
        else:  # 'B'
            idx = bisect.bisect_left(black_cells, cur)
            if idx < len(black_cells) and black_cells[idx] == cur:
                cur = black_cells[idx] + 1
            else:
                if idx < len(black_cells):
                    cur = black_cells[idx] + 1
                # else cur remains as next white cell (beyond last black)
        painted.add(cur)
    res = sorted(painted)
    return res

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    s = input().strip()
    black_cells = list(map(int, input().split()))
    result = process_case(n, m, s, black_cells)
    print(len(result))
    print(' '.join(map(str, result)))
```このソリューションでは、最初の黒セルをソートし、二分探索を使用して次の黒セルを効率的に見つけます。`B`。 セットをメンテナンスしております`painted`新しく黒くなった細胞をすべて収集します。 場合の取り扱いには細心の注意が必要です。`cur`最後の黒セルを超えた位置にあり、次の白セルとして残される必要があります。
