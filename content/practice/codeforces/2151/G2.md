 ## 解決策
 ## 問題の理解

 長さの隠れたシーケンスが与えられます$2n-1$からのすべての数字が含まれています$1$に$n$1 回だけ出現する 1 つの特別な値を除いて、正確に 2 回。 したがって、マルチセットは、単一のペアになっていない要素を含む完全なペア構造のように見えます。 

配列を直接見ることはできません。 代わりに、次の形式のクエリのみを行うことができます: 値を選択してください$x$そして一連のポジション$S$少なくとも 1 つのインデックスが存在するかどうかを尋ねます$i \in S$そのような$a_i = x$。 応答はブール値です。つまり、クエリでは値が次のとおりであるかどうかのみがわかります。$x$選択したインデックスのサブセット内のどこかに表示されます。 

タスクは、どの値を特定するかです。$1 \le x \le n$はペアになっていないもので、そのようなサブセット メンバーシップ クエリを最大 925 個使用します。 

重要な制約は、$n = 300$したがって、配列の長さは次のようになります。$599$。 これは、ポジションに対する対数戦略または分割統治戦略が実行可能なほど十分小さいですが、各ポジションまたは各値を単純にテストするには大きすぎます。 

単純な解釈では、各値と位置の組み合わせを調査することによって配列を完全に再構築しようとすることになります。 それには必要になります$O(n^2)$または、制限の下では不可能なさらに悪いクエリ。 

この相互作用も非適応的です。つまり、隠し配列が事前に固定されているため、決定的な分割戦略を安全に設計できます。 

候補者を独立してテストしようとすると、単純なアプローチによる微妙な失敗例が現れます。 単純にそれぞれを検証してみると$x$重複しているかどうかに関係なく、サブセットを繰り返しスキャンすると、各検証に必要な位置チェックが多すぎるため、クエリのバジェットを超えてしまいます。 

## アプローチ

 最大の問題は、私たちが立場や価値観に直接アクセスできないことです。 値とインデックスのセットに限定された存在情報のみを取得します。 これは古典的な「隠れた周波数不均衡」の問題であり、分割を通じて構造を抽出する必要があります。 

ブルートフォース戦略では、あらゆる値が試行されます。$x$、それぞれの値について、両方の出現が分離されるまでインデックスの異なるサブセットを繰り返しクエリすることによって、その値が 2 回出現するか 1 回出現するかを判断しようとします。 各クエリでは存在について「はい」または「いいえ」の答えしか得られないため、両方の出現箇所を見つけるには配列全体を複数回スキャンする必要があります。 最悪の場合こうなります$O(n^2)$テスト ケースあたりのクエリ数は制限をはるかに超えています。 

重要な点は、完全な位置は必要なく、一意の値の ID のみが必要であるということです。 これにより、サブセット交差を介して値を「検出可能」として扱うことができます。 インデックスをグループに分割し、値がグループに含まれるかどうかを繰り返しテストすると、各値の位置空間に対して間接的に二分検索を実行できます。 ただし、これを値ごとに個別に行うのは依然としてコストがかかりすぎます。 

本当の改善は、視点を逆転することによってもたらされます。つまり、位置内の値を検索する代わりに、その出現がパーティション間でどのように分布するかを比較することによって一意の値を検索します。 すべての重複値は少なくとも 2 つの異なる位置に出現するため、インデックス セットを分割すると、重複値が両方の半分に出現する可能性が高くなりますが、ランダム化または構造化パーティションが繰り返されると、一意の値の動作が異なります。 

最適なソリューションでは、一意である可能性のある値の候補セットを維持しながら、インデックスに対して分割統治を使用します。 各分割ステップでは、両方の半分で重複して一貫して動作する値を破棄し、非対称を示す値のみを保持します。 これにより、単一の値が残るまで候補セットが徐々に縮小されます。

 | 分割統治フィルタリング |$O(n \log n)$クエリ |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まだ一意である可能性のある候補値の現在のセットを維持します。最初はすべての値が次のとおりです。$1$に$n$。 完全なインデックスセットも使用します$1 \dots 2n-1$。 

1. インデックス セットを 2 つに分割します。$L$そして$R$。 目的は、各候補値がこれら 2 つの領域でどのように動作するかを比較することです。 
2. 各候補値について$x$かどうかを尋ねます。$x$に登場する$L$。 表示されないが、表示される場合は、$R$、その分布に関して非対称性があることがすでにわかっています。 同様に、次の場所での存在をテストします。$R$。 

これが役立つ主な理由は、バランスの取れた分割では重複した値が高い確率で両方の半分に現れる傾向があるのに対し、一意の値は対称性に違反する可能性が高いためです。 
3. パーティション全体で「完全にバランスのとれた重複」のように動作しない値のみを保持することにより、候補をフィルタリングします。 具体的には、一貫した重複パターンの両方の半分に現れる値を削除します。 
4. 固有の構造シグナルがまだ含まれている半分を再帰的に調べます。 各再帰レベルでは、重複した値の少なくとも半分が一貫性制約によって除外されるため、候補セットが縮小します。 
5. 候補セットが小さくなったら、すべてのインデックスに対してターゲットを絞ったクエリを使用して、残りの各値を直接検証します。 

### なぜ効果があるのか

 不変条件は、各分割ステップの後、真の一意の値が決して破棄されないことです。 正確に 2 回出現する値は、インデックス セットの十分に大きなランダムまたは構造化された分割全体にわたって対称的な存在を維持する傾向があります。 一意の値は 1 つだけ出現するため、最終的に少なくとも 1 つのパーティション レベルで不均衡が生じ、完全に重複したすべての値と区別されます。 観察された動作が両方の半分で重複していると一致する値のみを削除するため、正確性が保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(x, S):
    # interactive query
    sys.stdout.write(f"? {x} {len(S)} " + " ".join(map(str, S)) + "\n")
    sys.stdout.flush()
    return int(input().strip())

def solve_case(n):
    indices = list(range(1, 2 * n))
    candidates = list(range(1, n + 1))

    while len(candidates) > 1 and len(indices) > 1:
        mid = len(indices) // 2
        L = indices[:mid]
        R = indices[mid:]

        new_candidates = []

        for x in candidates:
            in_L = ask(x, L)
            in_R = ask(x, R)

            # Keep values that show imbalance or uncertainty
            if in_L + in_R < 2:
                new_candidates.append(x)

        candidates = new_candidates if new_candidates else candidates
        indices = L if len(candidates) <= len(L) else R

    # final verification
    for x in candidates:
        if ask(x, indices):
            return x

    return candidates[0]

def main():
    t = int(input())
    for _ in range(t):
        n = int(input())
        ans = solve_case(n)
        sys.stdout.write(f"! {ans}\n")
        sys.stdout.flush()

if __name__ == "__main__":
    main()
```この実装は、インデックス空間に対する分割統治の考え方に従います。 分割ごとに、すべての候補値が両方の半分に存在するかどうかテストされます。 両方の半分に出現することが確認された値は、重複した値のように動作する可能性があり、候補リストから削除されます。 

再帰方向は、残りの候補の中から潜在的な非対称性をまだ保持している半分を選択することによって動的に決定されます。 これにより、すでに有益でないことが証明されている領域に対する無駄なクエリが回避されます。 

最終段階では、削減された候補セットに対して直接検証を使用します。 

## 実用的な例

 ### 例 1 (概念的な小さなインスタンス)

 仮定する$n = 3$、配列は$[1,2,3,1,2]$なので、3 はユニークです。 

インデックスを分割します。 

| ステップ | L インデックス | R インデックス | 候補 1 | 候補 2 | 候補 3 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1,2 | 3、4、5 | はい/はい | はい/はい | いいえ/はい |

 ここで 1 と 2 は両方の半分に表示されますが、3 は R にのみ表示されます。 

フィルタリング後:

 | ステップ | 残りの候補者 |
 | --- | --- |
 | 1 | {3} |

 アルゴリズムはすぐに 3 を特定します。 

これは、パーティションの存在の不均衡によって一意の値がどのように分離されるかを示しています。 

### 例 2 (重複した重い構造)

 仮定してください$n = 4$、配列は$[1,2,3,4,1,2,3]$、ユニークは4です。 

最初の分割:

 | × | Lで | Rで | 保管 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 削除されました |
 | 2 | 1 | 1 | 削除されました |
 | 3 | 1 | 1 | 削除されました |
 | 4 | 0 | 1 | 保管 |

 すぐに残るのは4つだけです。 

これは、一意の値が構造的に非対称であるにもかかわらず、重複が両方の半分で存続する傾向があることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、重複する値の両方が初期のパーティション間で不均等に分割され、一時的に非対称に見える場合です。 値が両方の半分に一貫して存在することが確認された場合にのみ削除が行われるため、アルゴリズムはそれらを誤って削除することを回避します。 

もう 1 つの微妙なケースは、最初の分割時に一意の値がたまたま 1 つのパーティション内に完全に存在する場合です。 この場合、フィルタリングしても自​​然に残りますが、重複した値は依然として両方の半分に表示され、削除されます。 

最後に、候補があまりにも積極的に崩壊した場合、フォールバックの最終検証ステップで、残りのインデックス セットに対して残りの値を明示的にクエリすることで正確性を保証し、答えが失われないことを保証します。
