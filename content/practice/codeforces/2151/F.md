 ## 解決策
 ## 問題の理解

 次のような 1 次元の直線が与えられます。$n$最初は役職に就いている人たち$1$を通して$n$、および各ポジション$i$価値がある$a_i$。 「アトラクション」を整数の位置に配置することができ、各アトラクションはすべての人々をその方向に 1 歩移動させます。つまり、左側の人々は右に移動し、右側の人々は左に移動し、アトラクションに乗っている人々はその場に留まります。 これを何度でも繰り返すと、ポジション上の人々の可能な最終構成が複数生成されます。 タスクは、すべての個別の構成にわたって、構成のスコアが次の合計であるスコアの合計を計算することです。$a_i$ポジションごとに$i$。 

なぜなら$n$まで可能です$2 \cdot 10^5$テスト ケースごとに、すべてのテスト ケースの合計が次を超えない$2 \cdot 10^5$、テスト ケースごとの線形時間を超えるソリューションは実行できません。 構成の数は指数関数的に増加するため、すべての位置配列をブルートフォースで列挙することは不可能です。$n$。 最終的な答えはモジュロで計算する必要があります$998,244,353$これは、中間合計が 32 ビット整数をオーバーフローする可能性があり、すべての算術演算はこの素数を法として実行する必要があることを意味します。 

エッジケースは微妙です。 すべての値が$a_i$平等であるため、最終的な順位に関係なく、すべての人が同じように貢献します。 もし$n = 1$、移動はできません。 もし$a_i$値は大きく異なりますが、最終的な合計は、考えられるすべてのアトラクション シーケンスの後に各位置に何人が座ることができるかによって決まります。 「誰がどこに到達できるか」を単純に数えると、重複を数え間違える可能性があるため、重複の可能性を組み合わせて推論する必要があります。 

## アプローチ

 ブルートフォースアプローチは、アトラクションのすべてのシーケンスを生成し、動きをシミュレートし、結果として得られる位置配列を記録し、それらのスコアを合計することです。 これはルールに直接従っているため正しいですが、明らかに実行不可能です。 のために$n = 20$、すでに以上のものがあります$2^{20}$可能な構成は、2 秒で計算できる範囲をはるかに超えています。 

重要な洞察は、各人を独立して扱うことです。 各人は独自の位置から開始し、各アトラクションはその位置を増加、減少、または維持します。 この問題は、アトラクションを繰り返し適用した場合に、各人が到達できる個別の位置の数を数えるというものとして再構成できます。 複数の人を一緒に考えると、移動の単調性により、到達可能な位置は連続した間隔を形成します。人は、ある点を通過すると、反対側に別のアトラクションを配置しない限り、その点を越えて戻ることはできません。 

数学的には、一連の方法の数は、$n$任意のアトラクションが整数のカウントシーケンスに対応した後、人々を複数の位置に分散させることができます$1 \le p_1 \le p_2 \le \dots \le p_n \le n$、人それぞれ$p_i$初期位置によって制限された間隔内の位置を占めることができます。 これは、弱く増加するシーケンスをカウントするのと同じです。$[1, n]$から始まる$p_i = i$。 スコアの合計は、すべてのシーケンスの合計になります。$a_{p_1} + \dots + a_{p_n}$これは、動的計画法を使用して、プレフィックスの合計を利用しながら寄与分を反復的に追加することで効率的に計算できます。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして配列$a$。 DP 配列を初期化する`dp`サイズの`n + 1`、 どこ`dp[i]`位置で終了するシーケンスのスコアの合計を表します`i`。 
2.初期化`dp[0] = 0`基本ケースとして。 次のプレフィックスの合計を計算します`a`高速範囲クエリを可能にします。 
3. 各人物を左から右に繰り返します。 人向け$i$、 アップデート`dp[i]`すべての合計として`dp[j] + a[i]`のために$j \le i$。 これは、その位置またはその前で終了するシーケンスの拡張を表します。$i$人を追加することで$i$位置で$i$。 
4. 合計を繰り返し再計算することを避けるために、累積プレフィックス合計を使用します。 させて`pref[i]`の合計を保存する`dp[0..i]`。 それから`dp[i] = pref[i-1] + a[i]`、モジュロ$998,244,353$。 
5. すべての人を処理した後、すべてを合計します`dp[i]`このテスト ケースのスコアの合計を取得します。 結果のモジュロを出力します$998,244,353$。 

重要な不変条件は、各ステップで、`dp[i]`位置で終わるすべてのシーケンスを正しく説明します`i`、およびプレフィックス合計により、前のシーケンスのすべての拡張子が 1 回だけ含まれることが保証されます。 左から右に移動し、プレフィックス合計を使用することにより、各個別の位置配列を 1 回だけカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    dp = [0] * n
    pref = [0] * n
    
    dp[0] = a[0]
    pref[0] = dp[0]
    
    for i in range(1, n):
        dp[i] = (pref[i - 1] + a[i]) % MOD
        pref[i] = (pref[i - 1] + dp[i]) % MOD
    
    print(pref[-1])
```DP アレイ`dp[i]`位置の人で終わるシーケンスのスコアの合計を保持します`i`。 プレフィックス配列`pref[i]`これにより、以前のすべてのシーケンスの合計を効率的に計算できます。 オーバーフローを防ぐために、モジュロはすべてのステップに適用されます。 Off-by-one エラーは、0 から始まるインデックスを使用し、ループを開始することで回避されます。`i = 1`。
