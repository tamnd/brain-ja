 ## 解決策
 ## 問題の理解

 私たちは、アリスとボブが交代で商品を選ぶ限定ショップをシミュレートするように求められましたが、ひねりが加えられています。誰が最初に行くか、どの順序で入るかを制御することはできません。 各アイテムには私たちによる価値があり、アリスとボブはそれぞれアイテムの個人的なランクを持っています。 この質問は、アリスに対して、アイテムを購入する可能性のあるすべての方法で最終的に得られる価値の最大合計はいくらになるかを尋ねます。 

各テスト ケースは項目値の配列を提供します`v`、アリスの好み`a`、およびボブの好み`b`。 各ターンで、行動している人が現在最も優先している入手可能なアイテムを取得することを考慮する必要があります。 私たちはターンの順序がわからないので、アリスが購入できるすべてのセットを推論する必要があります。 答えは、これらの可能なセットの最大合計です。 

制約は重要です。`n`200,000 に達する可能性があり、すべてのテスト ケースの合計も最大 200,000 になります。 これにより、すべてのターン順序の単純なシミュレーションが即座に除外され、最悪の場合は O(n!) になります。 代わりに、ボブが常に最も優先順位の高い残りのアイテムを取得することを考慮して、アリスがどのアイテムを取得できるかを効率的に推論する方法が必要です。 

エッジケースには負の値が含まれます。これは、アリスが自分の合計を減らすアイテムを取ることを避ける可能性があるためであり、また、ボブの最優先の好みがアリスの最も価値のあるアイテムと競合するケースも含まれます。 たとえば、アリスの価値の高いアイテムがすべてボブのお気に入りでもある場合、最終的には価値の低いアイテムやマイナスのアイテムしか手に入らない可能性があります。 単純な実装では、ボブの干渉を考慮せずにアリスの上位項目をすべて合計し、誤った最大値が得られる可能性があります。 

## アプローチ

 ブルートフォースアプローチは、アリスとボブのすべての可能な選択シーケンスを列挙し、それぞれをシミュレートし、アリスの合計を追跡することです。 これは正しいですが、計算上不可能です`n > 10`O(n!) 回の操作が必要になるためです。 ブルートフォースは、実行可能なすべてのシーケンスをチェックし、アリスの合計が最大化されることを保証するため、原理的に機能します。 n が大きい場合、階乗増加がすぐに実行可能な計算を超えるため、失敗します。 

重要な洞察は、選択の順序は、各アイテムを誰が最初に取得するかという点でのみ重要であることを認識することです。 ボブは常に自分の最も好む入手可能なアイテムを選択し、アリスも同じように自分のアイテムを選択します。 したがって、アリスがボブよりもそのアイテムを好み、ボブよりも先にそのアイテムに到達できる場合、そのアイテムは保証されます。 これは「ターン順序の優位性」という考え方を使って定式化できます。 

具体的には、項目ごとに、アリスの好みとボブの好みにおける順位を計算できます。 アリスのランクがボブのランクよりも優れている場合、すでに取得されているアイテムの数に応じて、アリスはボブよりも先にそのランクを確保できる可能性があります。 逆に、ボブのランクが優れていれば、いつでもアリスがそのランクを奪われるのを防ぐことができます。 これにより、問題はプリファレンスのプレフィックスに対する動的プログラミング、または同等の貪欲なアプローチに帰着します。つまり、アリスの順序で項目を反復処理し、ボブが以前に取得する項目をスキップして、アリスが要求できる項目のみを選択します。

 ## アルゴリズムのチュートリアル

 1. 各アイテムについて、アリスとボブの好みの配列内の位置を計算します。 これらの位置は、両方の「優先スコア」を定義します。 アリスの位置配列`posA[item]`ボブの場合と同様に、アイテムがリストに表示されるインデックスです。`posB[item]`。 
2. リストの初期化`alice_items`アリスが確保できる可能性のあるアイテムを追跡するため。 アリスの好みの順に項目を繰り返します。 
3. アリスの好みの各項目について、アリスの立場がボブの立場よりも優れているかどうかを確認します。 もし`posA[item] < posB[item]`、アリスはボブよりも先にアクセスできるため、利用可能であると考えられます。 
4. このルールに従ってアリスが要求できるすべてのアイテムの値を合計します。 この合計は、ターンの制約を考慮して、ボブよりも先に彼女が常にアイテムを選択するというシナリオを捉えているため、彼女が取得できる最大の合計です。 
5. テスト ケースに対してこの合計を出力します。 

機能する理由: このアルゴリズムが機能するのは、ボブが常に最適に行動してアリスをブロックすると仮定して、アリスが取得できるアイテムの「安全なセット」を効果的に計算するためです。 優先順位を比較することで、過大評価がないことを保証します。アリスのランクが高くなければ、ボブのランクが低いアイテムはブロックされる可能性があります。 したがって、アリスが確保できるアイテムを優先順に合計すると、達成可能な最大合計値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        v = list(map(int, input().split()))
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        posA = [0] * (n + 1)
        posB = [0] * (n + 1)
        for idx, item in enumerate(a):
            posA[item] = idx
        for idx, item in enumerate(b):
            posB[item] = idx

        result = 0
        for item in a:
            if posA[item] < posB[item]:
                result += v[item - 1]
        print(result)

if __name__ == "__main__":
    solve()
```最初の部分では、入力を読み取り、アリスとボブの位置配列を構築します。 ループオーバー`a`アリスの注文に基づいてアイテムが考慮されるようにします。 条件`posA[item] < posB[item]`アリスがボブより先にそれを選ぶことができることを保証します。 入力から 1 から始まるインデックスを使用して、次の値にアクセスします。`v[item-1]`。 累積合計を出力すると、各テスト ケースの答えが得られます。
