## アプローチ

 ブルートフォースの観点では、部屋を左から右に処理し、部屋ごとに直接接続するか何らかのルーターで接続するかを決定します。 

プレフィックスを介した DP を定義するとします。 部屋用`i`をカバレッジに含むすべてのルーターを検索できます。`i`そしてあらゆる可能性を試してみてください。 問題は、ルーターが将来の多くの部屋に同時に影響を与えることです。 考えられるすべてのカバレッジ状態を追跡すると、すぐに爆発的に増加します。 以前のすべての位置をチェックするさらに慎重な実装でも、`O(n²)`トランジションは遅すぎます`n = 200000`。 

重要な点は、これが実際にはプレフィックス上の最短パス スタイルの DP であるということです。 

させて`dp[i]`部屋を接続するための最小コストであること`1..i`。 

部屋なら`i`が直接接続されている場合:```
dp[i] = dp[i-1] + i
```興味深いのはルーターです。 

所定の位置にルーターがあると仮定します`p`。 

その適用範囲間隔は次のとおりです。```
[L, R]
```どこ```
L = max(1, p-k)
R = min(n, p+k)
```このルーターの代金を支払うことにした場合、すべての部屋が`L..R`一気につながります。 その間隔をカバーする前のコストは正確に`dp[L-1]`、支払い後`p`コインのプレフィックスの有効な状態をすぐに取得します`R`。 

これにより、次のような遷移が得られます。```
dp[R] = min(dp[R], dp[L-1] + p)
```これはすでに州の線上の最短経路に似ています。 

残りの課題は、左から右にスイープしているときに、一部のルーター遷移が右のエンドポイントに到達する前に利用可能になることです。 現在の部屋をカバーできるすべてのルーターを効率的に維持する方法が必要です。 

標準ソリューションでは優先キューを使用します。 位置を左から右に処理すると、すべてのルーターが候補値を提供します。```
dp[L-1] + p
```これは、カバー範囲内のすべての部屋に対して有効です。 ヒープには最小のアクティブな候補が保持されます。 それから：```
dp[i] = min(
    dp[i-1] + i,
    best active router candidate
)
```各ルーターはヒープに 1 回出入りし、`O(n log n)`解決。

 | --- | --- | --- | --- |
 | ブルートフォース DP | O(n²) | O(n) | 遅すぎる |
 | ヒープベースの DP | O(n log n) | O(n) | 承認済み |

### なぜ効果があるのか

 位置で`i`、部屋に有効なすべてのソリューション`1..i`2 つの方法のいずれかで終了する必要があります。 

どちらの部屋でも`i`直接接続されています。 その場合、前の部屋がプレフィックスの最適なソリューションを形成します。`i-1`、コストを与える`dp[i-1] + i`。 

または部屋`i`位置にあるルーターのカバレッジ間隔に属します`p`。 そのルーターが次からカバーを開始した場合`L`、その後すべての部屋の前に`L`すでに最適に接続されている必要があるため、コストがかかります`dp[L-1]`。 支払い中`p`ルーターの場合、次の内容を含む間隔全体が終了します。`i`、コストを与える`dp[L-1] + p`。 

ヒープには、現在その間隔がカバーされているすべてのルーターが含まれています。`i`したがって、最小ヒープ値が、可能な限り最良のルーターベースの移行となります。 直接接続の移行と最適なルーターの移行の間の最小値を取り、部屋に接続するためのあらゆる有効な方法を考慮します。`i`。 増加する接頭辞に対する帰納法により、`dp[i]`あらゆるものに最適です`i`、 含む`dp[n]`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from heapq import heappush, heappop

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    add = [[] for _ in range(n + 2)]

    for p in range(1, n + 1):
        if s[p - 1] == '1':
            L = max(1, p - k)
            R = min(n, p + k)
            add[L].append((R, p))

    dp = [0] * (n + 1)
    heap = []

    for i in range(1, n + 1):
        for R, p in add[i]:
            heappush(heap, (dp[i - 1] + p, R))

        while heap and heap[0][1] < i:
            heappop(heap)

        dp[i] = dp[i - 1] + i

        if heap:
            dp[i] = min(dp[i], heap[0][0])

    print(dp[n])

solve()
```前処理フェーズでは、すべてのルーターのカバレッジ間隔を計算します。 ルーターは、スイープがカバーする最初の部屋に到達した時点で使用可能になるため、左側のエンドポイントによってグループ化されます。 

ヒープにはペアが格納されます`(candidate_cost, right_endpoint)`。 候補コストは、ルーターがアクティブになった時点ですでに完全に計算されています。```
dp[L-1] + p
```よくある間違いは、この値を後で再計算しようとすることです。 移行は以下に依存します`dp[L-1]`, not on the current position.

 期限切れのルーターは、その右のエンドポイントが現在のルームの前にある場合は必ず削除されます。 クリーンアップ後、ヒープ内に残っているすべてのルーターが部屋を覆います`i`。 

直接接続の移行はいつでも利用できます。```
dp[i-1] + i
```ヒープを最小にすると、ルーターの移行が最も安価になります。 2 つの最小値を取ると、最適なプレフィックス値が得られます。 

All costs fit comfortably in Python integers. The largest possible answer is roughly:```
1 + 2 + ... + 200000
```それは約です`2 · 10^10`、Python の整数の範囲内に十分収まります。
