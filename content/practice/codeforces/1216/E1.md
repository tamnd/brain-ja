 ## 解決策
 ## 問題の理解

 数字のブロックを連結して形成された概念的な無限の文字列が与えられます。 最初のブロックは数字の「1」だけです。 2番目のブロックは「12」です。 3 番目のブロックは「123」で、一般に i 番目のブロックは、1 から i までのすべての整数を 10 進数で区切り文字なしで連結したものです。 

したがって、完全なシーケンスは成長する階段のように見えます。新しいブロックはそれぞれ、自然数の接頭辞を 1 つ増やすことによって前の文字列を拡張します。 

私たちの仕事は、この文字列を構築することではなく、複数のクエリに答えることです。 各クエリは位置 k を与え、この無限連結のインデックス k に現れる数字を返さなければなりません。 

制約により、直接的な構築は即座に除外されます。 各クエリは最大 10^9 で、最大 500 個のクエリが存在します。 完全な文字列は非常に急速に増加し、最大 10^9 文字の単一のプレフィックスですら、明示的に保存または反復できる量をはるかに超えます。 文字列を構築しようとしたり、k までのブロックをシミュレートしようとしたソリューションは失敗します。 

2 番目の微妙な問題は、インデックスの安定性です。 シーケンスはブロックにわたって定義され、数値の桁の長さが異なるため、各ブロックの長さは異なります。 各ブロックが整数ごとに予測可能な固定サイズに寄与すると仮定する単純なアプローチでは、桁の長さが変化する 9 から 10 のような遷移付近で問題が発生します。 

したがって、主な課題は、どのブロックに k 番目の文字が含まれているかを特定し、次にそのブロック内のどの数値がその文字に寄与しているかを特定し、最後にその数値内の正しい数字を抽出することです。 

## アプローチ

 ブルート フォース戦略では、ブロックを 1 つずつ構築し、クエリごとに k を超えるまで文字列「1」、「12」、「123」などを追加します。 単一のクエリの場合、最悪の場合、k に比例するサイズのプレフィックスを構築することがすでに必要になる場合があります。 複数のクエリでは、k が 10^9 に達する可能性があり、ブロック i の長さは 1 から i までの数値の桁長の合計に比例するため、構築される文字列はブロック数で二次関数的に増加するため、これは実行不可能になります。 

重要な点は、完全な文字列は決して必要ないということです。 各ブロックが寄与する桁数を知ることだけが必要で、その後、プレフィックスの合計によって正しいブロックを見つけます。 これにより、問題はブロック長に関するプレフィックス算術に変わります。 

ブロック i の長さを、1 から i までのすべての数値の合計桁数として計算します。 これは、i の桁長を加算することで増分的に計算できます。 次に、最大クエリ値を超えるまで、ブロック全体のプレフィックス合計を構築します。 k は最大でも 10^9 であるため、有用なブロックの数は少なくなります (最大でも数十万程度ですが、この構造では実際にははるかに少なくなります)。 

k を含むブロックがわかったら、プレフィックスの合計を減算して、そのブロック内のオフセットを見つけます。 次に、再び桁の長さを使用して 1 から i までの数値をスキャンし、ターゲットの桁を含む正確な数値を見つけます。 最後に、その数値の文字列表現にインデックスを付けます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(k) | O(k) | 遅すぎる |
 | ブロック上のプレフィックス シミュレーション | O(B + q・B) ここで、B は最大 k | までのブロックの数です。 O(B) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 整数の桁長を事前計算します。 任意の数値 x について、その桁の長さは固定されており、len(str(x)) として計算できます。 これは、ブロック サイズを効率的に蓄積するために繰り返し使用されます。 
2. prefix[i] が 1 から i までのすべてのブロックの合計桁数を表す配列 prefix を構築します。 prefix[i] = prefix[i-1] + 1 から i までの数値の桁長の合計を増分的に計算します。 このステップでは、無限文字列を二分探索が可能な単調構造に変換します。 
3. 各クエリ k に対して、i に対して二分検索を実行して、prefix[i] >= k となる最小のブロック インデックスを見つけます。 これにより、どのブロックに k 番目の数字が含まれているかが識別されます。 
4. そのブロック内のオフセットを offset = k - prefix[i-1] として計算します。 これにより、グローバル位置がブロック i 内のローカル位置に変換されます。 
5. 1 から i までの数値を反復処理し、現在の数値の桁長以下になるまでオフセットから桁長を減算します。 これにより、ターゲットの数字を含む正確な番号が識別されます。 
6. その数値を文字列に変換し、位置オフセット - 1 の数字を返します。 

これが機能する理由は、シーケンスの単調分割に基づいています。 各ブロックはプレフィックスの合計で完全に考慮され、ブロック内では番号が隙間なく順番に連結されます。 プレフィックス配列により、各クエリが明確に定義された間隔に短縮されることが保証され、ブロック内の 2 回目のスキャンでは順序が正確に保持されます。 どちらの層も厳密に順序付けされた累積であるため、桁がスキップされたり二重にカウントされたりすることはなく、位置特定の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

q = int(input())
queries = [int(input()) for _ in range(q)]

max_k = max(queries)

prefix = [0]
i = 1

def digits(x):
    return len(str(x))

while prefix[-1] < max_k:
    block_len = 0
    for x in range(1, i + 1):
        block_len += digits(x)
    prefix.append(prefix[-1] + block_len)
    i += 1

def solve_k(k):
    lo, hi = 1, len(prefix) - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if prefix[mid] >= k:
            hi = mid
        else:
            lo = mid + 1

    block = lo
    offset = k - prefix[block - 1]

    cur = 0
    for x in range(1, block + 1):
        d = digits(x)
        if cur + d >= offset:
            idx = offset - cur - 1
            return str(x)[idx]
        cur += d

for k in queries:
    print(solve_k(k))
```このソリューションでは、まず、最大のクエリに到達するまで、ブロックのプレフィックス長を構築します。 これにより、事前に計算された有限の構造にインデックスを付けることで、すべてのクエリに回答できることが保証されます。 二分探索は正しいブロックを効率的に分離し、クエリごとにすべてのブロックに対する線形スキャンを回避します。 

各ブロック内では、ブロック サイズがブロック数に比べて小さいため、線形スキャンは安全であり、各ブロックは i までの桁長の合計のみを必要とします。 

重要な実装の詳細は、プレフィックス境界を慎重に処理することです。 式 k - prefix[block - 1] により、各ブロックの最初の文字がオフセット 1 に正しくマッピングされます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(B² + q log B) | ビルディング ブロックの長さは最大 B までの桁の合計、クエリごとのバイナリ検索 |
 | スペース | O(B) | Prefix array over blocks |

 数値の桁長が増加するにつれてプレフィックスの増加が加速するため、必要なブロック B の数は少なくなります。 k が 10^9 までの場合、B は管理可能であり、q は最大 500 であるため、解は時間制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    q = int(input())
    max_k = 0
    queries = []
    for _ in range(q):
        k = int(input())
        queries.append(k)
        max_k = max(max_k, k)

    prefix = [0]
    i = 1

    def digits(x):
        return len(str(x))

    while prefix[-1] < max_k:
        block_len = 0
        for x in range(1, i + 1):
            block_len += digits(x)
        prefix.append(prefix[-1] + block_len)
        i += 1

    def solve_k(k):
        lo, hi = 1, len(prefix) - 1
        while lo < hi:
            mid = (lo + hi) // 2
            if prefix[mid] >= k:
                hi = mid
            else:
                lo = mid + 1

        block = lo
        offset = k - prefix[block - 1]

        cur = 0
        for x in range(1, block + 1):
            d = digits(x)
            if cur + d >= offset:
                idx = offset - cur - 1
                return str(x)[idx]
            cur += d

    out = []
    for k in queries:
        out.append(str(solve_k(k)))
    return "\n".join(out)

 ## 特殊なケース

 微妙なケースの 1 つは、k がブロックの境界に正確に到達する場合です。これは、k が prefix[i] に等しいことを意味します。 この場合、アルゴリズムは block = i を正しく割り当て、offset は正確にそのブロックの最後の桁になります。 たとえば、k = prefix[6] = 21 の場合、結果はブロック 6 の最後の桁、つまり「6」になる必要があります。 減算プレフィックス[block - 1] により、オフセットがブロックの先頭を基準にして計算され、off-by-one エラーが回避されます。 

別の特殊なケースは、桁の長さが均一な 1 桁のブロックに現れます。 ここで、内部スキャンは各整数を正確に 1 つの位置にマッピングするだけであり、アルゴリズムは単純なインデックス作成に還元され、一般的なロジックが最も単純な構造に正しく分解されることを確認します。 

3 番目のケースには、9 から 10 への遷移が含まれます。ブロック スキャン ステップ内で桁の長さが変更されますが、抽出には常に文字列変換を使用するため、固定幅の数値を想定することはなく、位置ずれは発生しません。
