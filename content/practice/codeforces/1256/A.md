 ## 問題の理解

 目標金額が達成できるかどうかを決定するように求められます。`S`2種類のコインを使用して構築できます。 1 つの型には値があります`n`そしてそこにあります`a`それのコイン、他のタイプには価値があります`1`そしてそこにあります`b`それのコイン。 各テスト ケースのタスクは、何らかの数値を選択できるかどうかを判断することです。`x`価値のあるコインの`n`そしていくつかの数字`y`価値のあるコインの`1`それらの合計値が等しくなるように`S`。 制約というのは、`x`超えることはできません`a`そして`y`超えることはできません`b`。 

入力サイズが大きい場合:`a`、`b`、`n`、 そして`S`まで行くことができます`10^9`、最大まであります`10^4`テストケース。 これにより、あらゆる組み合わせを試みる強引なアプローチが排除されます。`x`そして`y`反復回数が超過する可能性があるため、`10^9`テスト ケースごとに、1 秒で実行可能な計算をはるかに超えています。 

ターゲットが次の場合に微妙なエッジケースが発生します。`S`の倍数ではありません`n`しかし価値のあるコインはほとんどありません`1`。 たとえば、次の場合`a=1`、`b=1`、`n=3`、 そして`S=4`、価値 3 のコイン 1 枚と価値 1 のコイン 1 枚を使用して 4 に到達できます。`b=0`、 同じ`S`にも関わらず到達できない`S`を使用して可能な最大値より小さい`a`のコイン`n`。 確認するだけのいい加減なやり方`S <= a * n + b`この場合、誤って YES が返されてしまいます。 

## アプローチ

 単純なアプローチは、可能な限りすべての数を反復処理することです。`n`-バリューコイン`x`から`0`に`a`そしてそれぞれについて`x`があるかどうかを確認してください`y`そのような`x*n + y = S`そして`y <= b`。 これが機能するのは、到達可能なすべての方法を直接テストするためです。`S`、ただし、最大で必要です`a`テストケースごとの反復回数。 以来`a`まで可能です`10^9`、このアプローチは完全に非現実的です。 

最適な解決策につながる重要な観察は、すべてを試す必要はないということです。`x`。 からの最大の貢献は、`n`- バリューコインは、必要な残りの量を減らすために最初に使用する必要があります。`1`-価値のあるコイン。 単純に取ることができます`x = min(a, S // n)`価値のあるコイン`n`。 これにより、からの貢献が最大化されます。`n`- 価値を超えないコイン`a`またはオーバーシュート`S`。 その後、到達する残りの金額は`S`は`S - x * n`。 この余りが以下の場合`b`、それをカバーできます`1`-価値のあるコイン。 そうしないと、合計に到達できません。 この観察により、ソリューションはテスト ケースごとの一定時間のチェックに縮小されます。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースの値を読み取ります。`a`、`b`、`n`、`S`。 
2. の最大数を計算します。`n`- を超えずに使用できる価値のあるコイン`S`として`S // n`。 
3. この数を、実際に所有しているコインによって制限します。`x = min(a, S // n)`。 
4. 使用後の残りの合計を計算します。`x`価値のあるコイン`n`:`remaining = S - x * n`。 
5.次のことを確認します`remaining`以下である`b`。 「はい」の場合、印刷します`YES`; それ以外の場合は、印刷します`NO`。 

機能する理由: 目標を超過することなく、できるだけ多くの高額コインを獲得することで、残りの金額を最小限に抑えることができます。 1 価値コインは最大の金額をカバーできるため、`b`、剰余が ≤ b であるかどうかをチェックすることで、正確な合計が保証されます。`S`可能であれば形成可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

q = int(input())
for _ in range(q):
    a, b, n, S = map(int, input().split())
    max_n_coins = min(a, S // n)
    remaining = S - max_n_coins * n
    if remaining <= b:
        print("YES")
    else:
        print("NO")
```このソリューションでは、最初に最大数を計算します。`n`-私たちが受け取ることができる価値のあるコイン（`S // n`)、利用可能なコインによって制限します(`min(a, S // n)`）。 残りの合計がチェックされます`b`。 整数の除算と減算を使用すると、浮動小数点エラーが発生しないことが保証されます。 いくつかの変数を超える余分なスペースは使用されません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    q = int(input())
    for _ in range(q):
        a, b, n, S = map(int, input().split())
        max_n_coins = min(a, S // n)
        remaining = S - max_n_coins * n
        if remaining <= b:
            output.append("YES")
        else:
            output.append("NO")
    return "\n".join(output)

 ## 特殊なケース

 もし`a`0の場合、アルゴリズムは次のように設定します。`max_n_coins = 0`かどうかを確認します`S <= b`。 例えば、`a=0, b=5, n=3, S=4`につながる`max_n_coins=0`、`remaining=4`、 そして`remaining <= b`次の場合にのみ true です`b >= 4`。 もし`b`が小さい場合、アルゴリズムは正しく NO を出力します。 

もし`S`よりも小さいです`n`しかし、n 値のコインがいくつかあります。`S // n`は 0 であるため、n 値コインは使用されません。 のために`a=5, b=5, n=10, S=3`、`max_n_coins=0`、`remaining=3`、 そして`remaining <= b`1 価値のコインで十分であるため、YES と評価されます。 

もし`S`と全く同じです`a * n + b`、アルゴリズムはすべてを引き受けます`a`コインを発行し、残りを使用します`b`残りをカバーするコイン。 これにより、上限エッジが正しく処理されます。
