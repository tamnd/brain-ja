 ## 解決策

 ## 問題の理解

 学生のスキル値のリストが与えられ、すべての学生が 1 つのグループに属し、各グループに少なくとも 3 人の学生が含まれるように、これらの学生をグループに分割する必要があります。 各グループのコストは、そのグループ内の最大スキル値と最小スキル値の差として定義されます。 目的は、すべてのグループ コストの合計ができる限り小さくなるように配列を有効なグループに分割し、その最小値を達成するグループへの学生の有効な割り当てを出力することです。 

入力サイズは最大 200,000 に達するため、すべてのパーティション、さらにはすべてのセグメンテーションを明示的に試行するソリューションは即座に除外されます。 区間にわたる 2 次またはそれより悪い DP はタイムアウトになるため、解は O(n log n) または O(n) に近くなければなりません。 

重要な構造的観察は、グループのコストは位置ではなく最小値と最大値のみに依存するため、グループ化はソート後にのみ意味があるということです。 ただし、元のインデックスのラベルを出力する必要があるため、後で割り当てをマッピングし直します。 

単純な間違いは、固定サイズ 3 で左から右へ貪欲にグループを形成しようとすることです。 グループをわずかに拡張すると、新しいグループを開始するよりも総コストが削減される場合があるため、これは失敗します。 もう 1 つの失敗モードは、将来の節約を考慮せずに隣接する要素を貪欲にマージすることです。これは、わずかに大きなグループが高コストの要素を安価に吸収できるため、最適性が損なわれます。 

貪欲な失敗の例:

 入力:```
6
1 2 3 100 101 102
```サイズ 3 のグループを貪欲に形成すると、[1,2,3] コスト 2 と [100,101,102] コスト 2 の合計 4 が得られます。ここではこれが最適ですが、[1,2,3,10,11,100] などの他のパタ​​ーンでは、早期に分割を強制すると最適ではないグループ化が発生する可能性があります。 正しいソリューションでは、グループの境界をローカルではなくグローバルに決定する必要があります。 

## アプローチ

 効率を無視する場合は、ソートされた位置に対して動的プログラミングを試すことができます。 dp[i] が最初の i 個のソートされた生徒を分割するための最小コストを表すものとします。 i で終わる、サイズが少なくとも 3 の最後のグループをすべて試し、 j ≤ i - 3 の場合、 dp[j] + (a[i] - a[j+1]) という形式の遷移を与えます。これは正しいです。ソートされた順序では、セグメント内の最小値と最大値がその終点になるからです。 

ただし、各状態では最大 n 個の遷移が考慮されるため、このアプローチは O(n^2) になります。 n = 2e5 では、これは不可能です。 

重要な観察は、どの最適解でも、グループはソートされた順序で連続するセグメントに対応するということです。 ソートが完了すると、セグメント [l, r] のコストは単純に a[r] - a[l] になります。 したがって、DP は基本的にカット ポイントを選択しますが、最小セグメント サイズ 3 を強制する必要があります。 

貪欲な DP トリックを使用してトランジションを改善できます。 以前のすべての状態を考慮する代わりに、すべてのグループが位置 i で終了し、j ≤ i - 2 の位置で開始する必要があると主張します。コストは dp[j] + a[i] - a[j] になるため、dp[j] - a[j] を最小化したいと考えます。 これは、有効な j 値の実行最小値を維持することになり、O(n) が得られます。 

再構成も必要なので、各 i の以前の最良のカット ポイントを保存します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのセグメントにわたるブルート フォース DP | O(n²) | O(n) | 遅すぎる |
 | プレフィックスを最小限に抑えた最適化された DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、元のインデックスを思い出しながら、スキル値で生徒を並べ替えます。 ソートは、最適なグループがこの順序で連続セグメントに対応することを保証するため、必須です。 

次に、動的プログラミングを使用します。ここで、 dp[i] は、最初にソートされた生徒を分割するための最小総コストを表します。 また、状態 i の最後のグループがどこから始まるかを示すポインターchoice[i]も維持します。 

各グループのサイズが少なくとも 3 であることを強制するため、dp[i] を計算するとき、最後のグループはある位置 j ≤ i - 2 で開始する必要があります。 

この遷移では、グループ [j, i] のコストが a[i] - a[j] であるという事実を使用します。つまり、次のようになります。 

1. dp[0] = 0 を初期化し、他のすべての dp 値を無限大に設定します。 
2. 1 から n までの各 i について、i で終わる有効な最後のグループを形成できるかどうかを検討します。 
3. dp[j] - a[j] の有効な j にわたって実行中の最良の値を維持します。 
4. i ≥ 3 の場合、これまでに確認された最良の j を使用して dp[i] を更新します: dp[i] = a[i] + best。 
5. また、後でグループを再構築するために、どの j がこの最良の値を与えたかを保存します。 

dp を埋めた後、保存された分割点を使用して n から逆方向に歩くことによってグループを再構成します。 各セグメントは 1 つのチームに対応し、そのセグメント内のすべてのメンバーに一意のチーム ID が割り当てられます。 

機能する理由: 配列がソートされると、グループ間で要素を交換しても範囲の合計を減らすことができないため、すべての最適なグループは連続したセグメントであると想定できます。 DP は、すべてのエンドポイント i に対して、最適な有効な開始点 j を選択することを保証し、実行最小値により、サイズ制約を尊重しながらすべての実行可能な開始を効率的に考慮することを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # sort with original indices
    arr = sorted([(a[i], i) for i in range(n)])

    INF = 10**18
    dp = [INF] * (n + 1)
    parent = [-1] * (n + 1)

    dp[0] = 0

    best_val = INF
    best_idx = -1

    # we maintain dp[j] - arr[j]
    for i in range(3, n + 1):
        j = i - 3
        val = dp[j] - arr[j][0]
        if val < best_val:
            best_val = val
            best_idx = j

        dp[i] = best_val + arr[i - 1][0]
        parent[i] = best_idx

    # reconstruct groups
    res_groups = []
    i = n
    while i > 0:
        j = parent[i]
        res_groups.append((j, i))
        i = j

    res_groups.reverse()

    # assign team ids
    ans = [0] * n
    team_id = 1

    for l, r in res_groups:
        for k in range(l, r):
            ans[arr[k][1]] = team_id
        team_id += 1

    total = 0
    for l, r in res_groups:
        total += arr[r - 1][0] - arr[l][0]

    print(total, len(res_groups))
    print(*ans)

if __name__ == "__main__":
    solve()
```コードは最初に、元のインデックスを保持しながら学生を並べ替えます。 DP ループは、i で終わるセグメントの最良の開始点を表す dp[j] - a[j] のローリング最小値を維持することによって、最適なパーティションを構築します。 

再構成フェーズでは、親ポインターを使用して逆方向に進み、正確なセグメント境界を回復します。 最後に、各セグメントにチーム ID が割り当てられ、セグメントのエンドポイントから合計コストが計算されます。 

実装の微妙な詳細はインデックス付けです。dp はソートされた配列の位置に対して 1 から始まりますが、元のインデックスは個別に格納されます。 これら 2 つのスペースを誤って混合すると、エラーが発生する一般的な原因になります。
