 ## 問題の理解

 バイナリ文字列と隣接スワップのバジェットが与えられます。 各交換では 2 つの隣接するキャラクターが交換され、そのような交換ごとに 1 単位のバジェットが消費されます。 私たちの目標は、実行できるスワップの数の制限を尊重しながら、文字列を辞書編集順に可能な限り最小のバイナリ文字列に再配置することです。 

ここでの辞書順は通常の文字列比較です。先頭にはできるだけ多くの文字列が必要です。`0`可能な限り、同じプレフィックスを持つ文字列の中で、プッシュされる文字列を優先します。`1`できる限り右に移動します。 

操作を再解釈する便利な方法は、それぞれを移動することを考えることです。`0`左に渡って`1`s. 毎回、`0`を渡す`1`、ちょうど 1 回のスワップの費用がかかります。 これは、予算が許す限り貪欲にゼロを左に進めることが問題であることを直ちに示唆しています。 

制約は全体として大きくなります。すべてのテスト ケースの合計長は最大 100 万で、テストごとに許可されるスワップ数は最大 100 万になります。$n^2$。 これにより、スワップをシミュレートしたり、二次的な方法で文字列を繰り返しスキャンしたりするアプローチは除外されます。 たとえ$O(nk)$テストケースごとのシミュレーションは不可能であるため、$k$巨大になる可能性があります。 テストごとに線形または線形に近い戦略が必要です。 

複数のゼロが早い位置をめぐって競合する場合、微妙な落とし穴が現れます。 現在のゼロを常にできるだけ左に移動する単純な貪欲な戦略は、残りの予算をグローバルに考慮していないと失敗する可能性があります。 もう 1 つのよくある間違いは、スワップを段階的にシミュレートすることです。これは、中程度の入力であっても二次関数の動作に爆発的に影響します。 

## アプローチ

 ブルートフォースアプローチは文字通り貪欲にスワップを実行します。 文字列を繰り返しスキャンできます。`10`パターンが見つかったので、予算がまだ残っている場合は交換します。 各スワップによって順序が局所的に改善されるため、これにより正しい辞書編集上の改善がもたらされます。 ただし、最悪の場合、次のような文字列が発生する場合があります。`111...1000...0`、それぞれの 0 は多くの 1 と交差する必要があり、実行されるスワップの数は次のようになります。$n^2$。 各スワップには位置のスキャンまたは更新も必要であり、テスト ケースごとの複雑さが 2 次またはそれ以上になり、実行不可能です。 

重要な点は、スワップを明示的にシミュレートする必要がないということです。 代わりに、ゼロを左から右に処理し、現在その前にあるゼロの数と予算がどれだけ残っているかに基づいて、各ゼロが左にどこまで移動できるかを決定します。 各ゼロは、次の数に等しい予算の消費に貢献します。`1`■ それは飛び越えますが、残りの予算を減らすこと以外に、以前の決定を妨げることはできません。 

すでに配置されているゼロの数と、交差可能なゼロの数を追跡する構造を維持できます。 よりクリーンな観点は、保留中のゼロと利用可能なスワップの実行カウントのキューのような構造を維持しながら文字列を反復処理し、貪欲に配置することです。`0`予算が許す限り、可能な限り左にあります。 

同等で、より実装しやすいもう 1 つのアイデアは、左から右に答えを構築することをシミュレートすることです。 各ポジションで、私たちは、`0`将来の位置から現在のスロットに移動します。 最も早く到達可能なものを貪欲に選択します`0`残りのスワップを使用して現在の位置に移動できます。 

これにより、文字列をスキャンし、未使用のゼロの数を維持し、残りのコスト制約の下で各位置にゼロを「取り込む」ことができるかどうかを決定するプロセスが行われます。

 ## アルゴリズムのチュートリアル

 1. 文字列をスキャンしながら、すべての文字列の位置を事前計算します。`0`s. 出現順に左に移動することを検討します。 
2. ポインタを維持する`i`構築中の最終的な答えと、元の文字列のゼロに対する別のポインタを上に置きます。 変数も維持します`k`残りのスワップ予算を表します。 
3. ポジションごとに`i`左から右に、どの文字を配置するかを決定します。 私たちが欲しいのは`0`可能であれば、辞書編集上の順序が最小限に抑えられるためです。 
4. かどうかを決定するには`0`位置に配置できます`i`、次の未使用のものを移動するコストを計算します。`0`位置を決める`i`。 このコストは、元の位置と位置の間で移動されなかった文字の数です。`i`、これは事実上、クロス介入するために実行する必要があるスワップの数に等しくなります。`1`s.
 5. このコストが残りのコスト以下の場合`k`、置きます`0`位置で`i`、そのコストを消費し、ゼロポインターを進めます。 それ以外の場合は、`1`そして続けます。 
6. すべてのポジションが埋まるまで続けます。 

ステップ 4 の背後にある重要な考え方は、それぞれの`0`は左から右の構造で独立して移動し、その移動コストはスキップする位置の数のみに依存します。 手頃な価格のときに常に次に利用可能なゼロを選択することで、可能な限り前の位置がゼロを取得できるようにします。これはまさに辞書編集上の最小化に必要なことです。 

### なぜ効果があるのか

 アルゴリズムは、貪欲な不変条件を維持します。`0`残りのバジェット内で有効なスワップのシーケンスを使用すると、アルゴリズムがそれを実行します。 最適なソリューションには、`0`その場合は、次のように置き換えるので、`1`を押すだけです`0`辞書編集上の順序を早期に改善できる予算を節約せずに、さらに右に進みます。 スワップは相対的な順序とそれぞれにのみ影響するため、`0`早期のポジションに到達するには固定コストがかかり、利用可能な最も安いものを貪欲に消費します`0`ローカルおよびグローバルに最適性を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n, k = map(int, input().split())
        s = input().strip()

        zeros = []
        ones_before = 0

        for i, ch in enumerate(s):
            if ch == '0':
                zeros.append(i)

        z = 0
        used = [False] * n
        res = []

        for i in range(n):
            # cost to bring next zero here
            if z < len(zeros):
                pos = zeros[z]
                cost = pos - i
                if cost <= k:
                    res.append('0')
                    k -= cost
                    z += 1
                    continue
            res.append('1')

        print("".join(res))

if __name__ == "__main__":
    solve()

微妙な点は、スワップを明示的にシミュレートすることは決してないということです。 コスト計算では、必要なすべての隣接スワップが暗黙的に考慮されます。 これにより、ソリューションが線形に保たれます。

 ## 特殊なケース

 特殊なケースの 1 つは、文字列が複数の文字列で始まる場合に発生します。`1`s と少数の`0`ずっと右です。 最初のいくつかの位置は次の値でしか埋められないため、アルゴリズムは依然として正しく動作します。`1`を実行するのに十分な予算が蓄積されるまで`0`フォワード。 

もう 1 つのエッジケースは次のような場合です`k`非常に大きいです。 この場合、すべてのゼロは可能な限り早い位置で利用可能になり、アルゴリズムは縮退して、すべての値を含む完全にソートされた文字列を生成します。`0`前にいます。 

3 番目のケースは、終わり近くでゼロが密集している場合です。 複数のゼロが存在する場合でも、それぞれは 1 回だけ考慮され、コストは次のように減少します。`i`増加するため、ゼロが誤ってスキップされたり、二重にカウントされたりすることがなくなります。
