 ## 問題の理解

 エンティティのコレクションが与えられ、それぞれが「満たされる」ためには他のエンティティをいくつ選択する必要があるかという要件を課します。 タスクは、これらのエンティティのサブセットを選択して、選択されたすべてのエンティティが要件を満たすのに十分な最終セットの参加者を認識し、選択されていないすべてのエンティティが制約に無関係になるかどうかを判断することです。 

入力は、エンティティごとに 1 つの要件のリストを記述します。 通常、出力は実現可能性の決定、または 1 つの有効なサブセットの構築です。 

明示的な制約がない場合でも、このタイプの問題では、ほとんどの場合、最大約 10^5 の要素が許可されます。 このことは、n が約 25 を超えると 2^n 個の増加は不可能であるため、すべてのサブセットを試行する解決策を即座に排除します。また、O(n^2) アプローチは境界線にあり、通常は高度に最適化され、定数因子が小さい場合にのみ許容されることも示唆しています。 したがって、ターゲットは線形または線形算術解です。 

たとえ小さな例であっても要件が矛盾する場合、微妙なエッジケースが発生します。 たとえば、すべてのエンティティが少なくとも 3 つの他のエンティティを必要とするが、エンティティが合計 3 つしかない場合、すべての制約を同時に満たす選択はありません。 すべてを選択する素朴な貪欲なアプローチは、構築後に制約を検証しないため失敗します。 

もう 1 つの典型的な失敗ケースは、要件が順序や累積数に依存する場合に発生します。 アルゴリズムが並べ替えが無関係であると想定している場合、特定の順序のみが実現可能である構成を誤って受け入れる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは、エンティティのすべての可能なサブセットを試し、選択されたすべての要素がそのサブセット内で必要な条件を満たしているかどうかを確認することです。 これは概念的には簡単です。サブセットごとに、そのサイズを計算し、制約を検証します。 1 つのサブセットをチェックするコストは O(n) で、サブセットは 2^n 個あるため、合計の複雑さは O(n・2^n) となり、n = 40 の場合でも不可能になります。 

これらの問題における重要な観察点は、制約が ID ではなくカウントのみに依存するということです。 要件に基づいてエンティティを分類したら、問題を、安全に含めることができる数を段階的に決定するものとして扱うことができます。 最も制限の厳しいエンティティを最初に検討すると、新しいエンティティを追加しても以前に満たされたエンティティが無効にならないようにしながら、有効なソリューションを段階的に構築できます。 

これにより、問題はソートされた構造に対する貪欲な選択に変換され、選択された要素の実行カウントを維持し、そのカウントが与えられた制約に違反しない場合にのみエンティティを受け入れます。 

ブルートフォースは無関係な組み合わせを探索するため失敗します。 貪欲が機能するのは、実現可能性が単調であるためです。特定のサイズで制約が失敗すると、構造が慎重に順序付けされ、並べ替えによってその順序が明らかになるまで、要素を追加しても修正できません。

 ## アルゴリズムのチュートリアル

1. すべてのエンティティとその要件をペアのリストに読み込みます。 これにより、後で再構築が必要になった場合に、値と元の位置の両方が保存されます。 
2. エンティティを要件に従って昇順に並べ替えます。 これにより、最も制限の少ないエンティティが最初に考慮されるようになり、将来のすべての選択をブロックするような初期の無効な決定が防止されます。 
3. すでに選択したエンティティの数のカウンターを初期化します。 これは、構築されたサブセットの現在のサイズを表します。 
4. ソートされたリストを繰り返し処理します。 各エンティティについて、その要件がすでに選択したエンティティの数以下であるかどうかを確認します。 そうであれば、安全に含めることができます。 
5. 要件が現在選択されている数より大きい場合は、スキップします。 その理由は、今これを含めるとすぐにその制約に違反し、後の選択はカウントを増やすだけであるため、以前に再検討した場合にのみ有効であり、ソートによってすでに処理されているためです。 
6. 選択したすべてのエンティティを収集し、問題に必要な回答形式を再構築します。 

### なぜ効果があるのか

 正確さは、最初の k 個の並べ替えられた要素を処理した後、そのサイズに関するすべての制約を満たす、それらの要素の中から可能な最大のサブセットを選択したという不変式に依存します。 要件は減少しない順序で処理されるため、最初に選択された数を増やさない限り、拒否されたエンティティを後で有効にすることはできません。ただし、数の増加は、以前の制約に違反しない、すでに受け入れられた要素によってのみ行われます。 これにより、安定した単調な構造が作成されます。エンティティがスキップされると、以前の実現可能性を損なうことなく、その要件を同時に満たすことのできる後続のステップは存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = []
    for i in range(n):
        x = int(input())
        arr.append((x, i))

    arr.sort()

    chosen = [False] * n
    cnt = 0

    for req, idx in arr:
        if req <= cnt:
            chosen[idx] = True
            cnt += 1

    print("YES")
    print("".join("1" if chosen[i] else "0" for i in range(n)))

if __name__ == "__main__":
    solve()
```この実装は、貪欲な戦略を直接反映しています。 並べ替えにより、正しい処理順序が適用されます。 変数`cnt`すでに含まれている要素の数を追跡します。これが、実現可能性を判断するために必要な唯一の状態です。 

唯一の微妙な点は、スキップされた要素を決して再訪しないことです。 再訪は現在のカウントが増加した場合にのみ有効であるため、これは安全ですが、増加は以前の有効な包含によるものであり、それらの包含は実現可能性を損なわないことがすでに保証されています。
