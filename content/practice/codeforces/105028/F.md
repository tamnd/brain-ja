 ## 解決策
 ## 問題の理解

 常に同じ順序で二分探索ツリーに挿入される値の固定シーケンスが与えられ、次に多くのクエリで、それぞれがその固定シーケンスの前に最初に挿入される異なる値を導入します。 クエリ値ごとに、ルート挿入としてクエリ値を挿入し、標準の BST 挿入ルールを使用して配列のすべての要素を指定された順序で挿入することによって BST を構築します。 タスクは、各クエリの結果として得られる BST の高さを決定することです。 

重要な観察は、最初の挿入だけが全体的な方法で構造を変更するということです。 クエリ値を挿入した後は、それ以降の挿入はすべて、既存の値との比較のみに基づいて決定的なパスに従います。 各要素は、すでに挿入されているノードより小さいか大きいかに応じて左または右に進み、これにより、クエリが配列要素の並べ替え順序を分割する方法によって決定されるパスのような構造が構築されます。 

制約は非常に大きく、すべてのテスト ケースにわたって n と q の合計は最大 5 × 10^5 になります。 クエリごとに BST 挿入をシミュレートするソリューションでは、最悪の場合、最大 O(nq) の比較が実行されますが、これはまったく実行不可能です。 クエリあたり O(n log n) であっても制限を超える可能性があります。 目的のソリューションでは、クエリ全体で前処理を再利用し、ほぼ O(log n) または O(1) 時間で各クエリに応答する必要があります。 

素朴だが微妙な失敗例は、BST の形状が挿入されたすべての要素の相対的な順序のみに依存すると考えることから生じます。 それは本当ですが、重大な間違いは、実際に木を建てなければならないと想定していることです。 代わりに、挿入された各ノードの深さは、挿入順序内で最も近い大きい隣接ノードと小さいノードの観点から表現できますが、ルート セパレータとしてのクエリ値を基準にしています。 

たとえば、配列が [3, 1, 4, 2] でクエリが 3 の場合、挿入は 3 から開始され、3 より小さいものはすべて左のサブツリーに移動し、大きいものは右のサブツリーに移動します。 ただし、各辺の内側の形状は並べ替え順序ではなく元の挿入順序に依存するため、直接シミュレーションが困難になります。 

## アプローチ

 ブルート フォース アプローチでは、各クエリの BST を直接シミュレートします。 各 x_i に対して空のツリーを作成し、x_i を挿入してから、すべての a_j を 1 つずつ挿入します。 各挿入は、比較後のルートから派生します。 これは正しく機能しますが、歪んだツリーでは各挿入に O(n) 時間がかかる可能性があるため、1 つのクエリに O(n^2) かかる可能性があり、すべてのクエリでこれは O(nq) となり、あまりにも大きすぎます。 

重要な洞察は、BST を動的なポインター構造として考えるのをやめ、代わりに各挿入を、挿入順序内の最も近い大きい要素と最も近い小さい要素に基づいて親関係を定義するものとして見ることです。 挿入順序によって構築される BST に関する標準的な事実は、各新しいノードは、値の順序で以前に挿入された最も近いノードの子として、どちらが後で挿入されるかに応じて、先行または後続のいずれかに接続されるということです。 

Now fix a query value x. すべての要素は、x より小さい要素と x より大きい要素の 2 つのグループに分割されます。 最初に x を挿入した後、左側のサブツリーは x より小さい要素のみで形成され、右側のサブツリーは x より大きい要素のみで形成されます。 重要なのは、各サイドの構造は、元の挿入オーダーを使用してそのサブセットから BST を構築した場合とまったく同じであるということです。 

したがって、クエリごとに、2 つの独立した BST の結合の高さが必要です。1 つは要素 < x から構築され、もう 1 つは要素 > x から構築され、どちらも x の直下に接続されています。 最終的な高さは、1 に両側のすべてのノードの最大の深さを加えたものになります。 

したがって、すべての値 v について、すべての a_i を順番に挿入することによって形成される BST 内の v の深さを計算する方法が必要です。 次に、クエリ x について、すべての v < x およびすべての v > x の中から最大の深さを取得し、1 を加算します。

これを効率的にサポートするために、挿入順序で最も近い大きい要素に基づく単調スタック アプローチを使用してすべての a_i の深さを前処理します。これにより、BST 挿入によって誘発される暗黙的なデカルト ツリーのような構造が構築されます。 次に、ソートされた値に基づいてセグメント構造を構築し、プレフィックス/サフィックスの最大深さのクエリに答えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(nq) | O(n) | 遅すぎる |
 | 深さ + 範囲クエリを事前計算する | O((n+q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、要素を固定順序で BST に挿入すると、以前の挿入と値の順序付けの制約に基づいて各要素の一意の親が定義されるという事実に依存しています。 

### 段階的なプロセス

 1. まず、すべての a_i を順番に挿入するかのように、配列 a 内のすべての要素の BST 深さを計算します。 

前の要素を追跡する構造を維持し、単調スタックを使用して挿入順序で両側の最も近い大きい要素を決定します。 

各要素の親は、以前に挿入された最も近い値、つまり最も近い大きい値または小さい値によって決まります。 
2. すべての深さが計算されたら、要素をその値で並べ替えます。 

これが必要なのは、クエリが値空間を「x 未満」と「x より大きい」に分割するため、値に対する接頭辞と接尾辞のクエリが必要になるためです。 
3. ソートされた値に対して 2 つの配列を構築します。1 つは値の昇順で深さを格納します。 
4. prefix_max[i] が i までの値の最大の深さであるプレフィックス最大配列を構築します。 
5. suffix_max[i] が i 以降の値の最大深さである接尾辞最大配列を構築します。 
6. 各クエリ x について:

 二分探索を使用して、ソートされた配列内で x が挿入される位置を特定します。 

x が位置 p-1 と p の間に入る場合:

 max(prefix_max[p-1], suffix_max[p]) を取得し、ルート ノード x に 1 を加算します。 
7. この値を出力します。 

### なぜ効果があるのか

 x を挿入した後に形成された BST は、最初に他のすべてのノードを 2 つの独立した BST (x より小さいものと x より大きいもの) に分割します。 x はルートであるため、高さは 1 に、いずれかのサブツリーで到達可能なノードの最大深さを加えたものになります。 各サブセット内の挿入順序は元のシーケンスから変更されていないため、その深さは完全な挿入プロセスの深さと同じままであり、値の分割によってのみ制限されます。 プレフィックスとサフィックスの最大値は、各サイドの最も深いノードを正確にキャプチャします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_depths(a):
    n = len(a)
    parent = [-1] * n
    depth = [0] * n

    stack = []

    for i in range(n):
        last = -1

        while stack and a[stack[-1]] < a[i]:
            last = stack.pop()

        if stack:
            parent[i] = stack[-1]
        if last != -1:
            if parent[i] == -1 or a[last] < a[parent[i]]:
                parent[i] = last

        if parent[i] != -1:
            depth[i] = depth[parent[i]] + 1

        stack.append(i)

    return depth

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        xs = list(map(int, input().split()))

        depth = build_depths(a)

        arr = sorted(zip(a, depth))
        vals = [v for v, d in arr]
        dep = [d for v, d in arr]

        n = len(arr)

        pref = [0] * n
        suff = [0] * n

        pref[0] = dep[0]
        for i in range(1, n):
            pref[i] = max(pref[i - 1], dep[i])

        suff[-1] = dep[-1]
        for i in range(n - 2, -1, -1):
            suff[i] = max(suff[i + 1], dep[i])

        out = []
        import bisect

        for x in xs:
            import bisect
            p = bisect.bisect_left(vals, x)

            left = pref[p - 1] if p > 0 else 0
            right = suff[p] if p < n else 0

            out.append(str(max(left, right) + 1))

        print(" ".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、標準的な挿入ビルド BST に表示されるノードの深さを再構築することから始まります。 単調スタックは、ポインターベースの挿入をシミュレートすることなく、構造的な親関係を効率的に識別するために使用されます。 

深さを計算した後、クエリでセットを 2 つの連続する範囲に分割できるように、値が並べ替えられます。 プレフィックスとサフィックスの maxima を使用すると、クエリ分割のどちらかの側で最も深いノードを一定時間取得できます。 

二分探索により、各クエリ値の分割位置が特定され、最終的な高さは、どちらかの側の最大深さに 1 を加えたものとして計算されます。 

## 実用的な例

 小さな配列 a = [3, 1, 4, 2] とクエリ x = [2, 3] を考えてみましょう。 

まず、挿入順序で深さを計算します。 構造によって深さが得られると仮定します。 

3:0、1:1、4:1、2:2。 

次に、値で並べ替えます。 

値: [1、2、3、4]

 深さ: [1、2、0、1]

 ビルドプレフィックス最大:

 [1、2、2、2]

 ビルドサフィックスの最大値:

 [2、2、1、1]

 クエリ x = 2 の場合、分割位置 p = 1。 

左側の最大値 = pref[0] = 1

 右側の max = suff[1] = 2

 答え = max(1, 2) + 1 = 3

 クエリ x = 3 の場合、p = 2。 

左の最大値 = pref[1] = 2

 右の最大 = suff[2] = 1

 答え = 3

 | クエリ | 分割位置 | 左最大 | 右マックス | 結果 |
 | --- | --- | --- | --- | --- |
 | 2 | 1 | 1 | 2 | 3 |
 | 3 | 2 | 2 | 1 | 3 |

 このトレースは、前処理から再利用されたサブツリーの深さを使用して、各クエリがソートされた順序で境界分割にどのように還元されるかを示します。 

## 複雑さの分析

 この制約では合計要素数が最大 5 × 10^5 まで許可されるため、線形前処理と対数クエリ処理は制限内に問題なく収まります。

 ## 特殊なケース

 重要なエッジ ケースは、クエリ値がすべての配列要素よりも小さい場合です。 この状況では、ルートを除くツリー全体が右側のサブツリーにあり、答えは構造全体の最大の深さのみに依存します。 プレフィックス部分が空であり、サフィックスの最大値がすべての深さを正しく捕捉するため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、クエリ値がすべての要素より大きい場合です。 ここでは、すべてが左側のサブツリーに送られます。 二分検索では分割が最後に配置され、サフィックスが空になり、プレフィックスの最大値が構造全体を表します。 

3 番目のケースは、配列がほぼソートされたシーケンスを形成し、非常に偏った BST を生成する場合です。 各要素の親は、ソートされたような入力でチェーンを形成する最も近いより大きな要素によって決定されるため、単調スタックでも深さが正しく計算されます。 プレフィックスとサフィックスのクエリは、形状の再構築ではなく、保存された深さのみに依存するため、有効なままです。
