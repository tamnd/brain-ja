 ## 解決策
 ## 問題の理解

 すべてのノードが初期整数値を保持するツリーが与えられます。 唯一許可される操作は、エンドポイントが現在同じ値を持つエッジを選択し、それらの 2 つのエンドポイントを 1 つのノードにマージし、その新しいノードに 2 つの値の合計を割り当てることです。 新しいノードは、マージされたエッジ自体を除く、両方のエンドポイントのすべてのインシデント エッジを継承するため、ノードの数が少なくなるだけで、構造は常にツリーのままになります。 

このプロセスは、すべてのノードが 1 つのノードに折りたたまれるか、有効なマージがなくなるまで継続されます。 タスクは、ツリー全体を 1 つのノードに減らす有効なマージのシーケンスが存在するかどうかを判断することです。 

ツリー構造は最初は静的ですが、値は急速に均一性を失う形で変化します。 1 回のマージの後、別の場所で一致するマージが同じ合計を生成しない限り、新しい値は一意になります。 このため、単純なシミュレーションは非常に脆弱になります。プロセスの値は単調ではなく、マージ可能なエッジのセットは予期せず変化します。 

合計に関する制約$n \le 2 \cdot 10^5$すべてのテスト ケースで、マージ ステップのシミュレーションを除外します。 マージごとにノード数が 1 つずつ減るため、$O(n)$しかし、マージごとに隣接関係の更新と等しい値のエッジの追跡が必要になるため、操作ごとにほぼ線形または対数のオーバーヘッドがあり、遅すぎることがすでに示唆されています。 

貪欲なシミュレーションを試してみると、いくつかの失敗パターンがすぐに現れます。 まず、早期にマージすると値が変更されるため、その後の有効なマージがブロックされる可能性があります。 次に、2 つの同一の値が隣接していても、それらの値が合計を同期できない異なるマージ チェーンに属している場合は使用できません。 

ローカル グリードが失敗する小さな例は、3 つのノードのパスです。```
1 - 1 - 1
```最初の 2 つのノードを貪欲にマージすると、値 1 のノードに接続された値 2 のノードが生成され、最後の 2 つを最初にマージしても失敗しますが、プロセスは停止します。 実際、どの順序も機能しませんが、単純な戦略は柔軟性を誤って想定している可能性があります。 

本当の難しさは、マージが元のツリー上の単純なマッチング問題ではなく、各ステップでの隣接性と等価性によって制約されたバイナリ マージ ツリーを構築するように動作することです。 

## アプローチ

 強引なアイデアは、考えられるすべてのマージ シーケンスを明示的にシミュレートすることです。 各ステップで、すべてのエッジをスキャンし、有効なペアのマージを試みます。 マージごとにグラフが変更されるため、これは指数関数的に多くのシーケンスに対する動的検索になります。 積極的にプルーニングを行ったとしても、値が密な状況では分岐係数が大きいままであり、最悪のケースは実現可能な限界よりも速く成長します。$n = 2 \cdot 10^5$。 

重要な観察は、マージ後の実際の値は構造の決定にはほとんど無関係であるということです。 値を持つ 2 つのノードが存在すると$x$マージすると、値を持つノードが作成されます$2x$、構造的に同一のマージが同時に発生しない限り、この値が他の場所に現れる可能性は低いです。 これにより、価値伝播の長いチェーンに依存することができなくなります。 代わりに、マージは事実上、エッジに沿った 2 つの同一の値を消費するペアリング操作のように動作します。 

これにより、プロセスが再構成されます。各マージでは、同じ現在値を持つ 2 つの隣接ノードが消費され、アクティブ ノードのプールから削除され、別の場所で同一の構築が発生しない限り、それ以上参加しない新しいノードに置き換えられます。 したがって、問題は、すべてのノードが最終的に消費されるように、ツリーをエッジに沿った一連のローカルペアに分解できるかどうかということになります。 

これは構造的な条件につながります。同じ初期値を共有するノードの接続領域内では、何も残らないまでペアごとのエッジ除去を実行できなければなりません。 これは、各値クラスで誘導されたサブグラフが、一致しないノードを孤立させずに縮小できるエッジの素のペアに分解可能であることと同等です。 

唯一の障害は、値クラス コンポーネントに奇数のノードがある場合に発生します。これは、各操作により、値から変換される前にそのコンポーネントからちょうど 2 つのノードが削除されるためです。 残ったシングルトンはすぐにマージできなくなります。 

これにより、問題は、等しい値によって引き起こされるすべての連結成分について、そのサイズが偶数であるかどうかをチェックすることになります。

 ## アルゴリズムのチュートリアル

 1. 入力からツリーの隣接リストを構築します。 この表現により、接続されたコンポーネントを効率的に探索できるようになります。 
2. ツリーをたどって、値に基づいてノードをグループ化します。ただし、同じ値の接続されたコンポーネント内に限ります。 これは、訪問されていない各ノードから DFS または BFS を実行し、同じ値を持つ近隣ノードへのトラバーサルを制限することによって行われます。 この制限の理由は、マージは等しい値の隣接ノード間でのみ許可されるため、これらのエッジのみが実現可能性に関係するためです。 
3. 検出されたコンポーネントごとに、そのサイズを数えます。 このサイズは、他の値との相互作用の前に、その値クラス内の内部マージに参加できるノードの数を表します。 
4. コンポーネントのサイズが奇数である場合は、完全なマージは不可能であると直ちに結論付けます。 その理由は、すべての有効なマージが同じ値コンポーネントからちょうど 2 つのノードを消費するため、奇数サイズのコンポーネントにより、有効なパートナーを見つけることができずにノードが孤立することが保証されるためです。 
5. すべての値にわたるすべてのコンポーネントのサイズが均一である場合、単一ノードへの完全な縮小が可能であると結論付けます。 

### なぜ効果があるのか

 重要な不変条件は、マージの時点で値が同一でない限り、マージでは値が決して混合されないこと、および同一の構造が他の場所に現れない限り、マージでは結果として得られるノードの値がそれ以降の参加から隔離されるように即座に変更されるということです。 これにより、コンポーネント間の同期が妨げられます。 結果として、重要な安定した構造は、ツリーを元の状態で同じ値の連結コンポーネントに分割することだけになります。 このような各コンポーネント内では、マージごとに 2 つのノードが正確に削除されるため、実現可能性は、コンポーネントをペアで完全に使い果たせるかどうかによって決まります。これは、サイズが均等であることと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    vis = [False] * n

    def dfs(start):
        stack = [start]
        vis[start] = True
        val = a[start]
        cnt = 0

        while stack:
            u = stack.pop()
            cnt += 1
            for v in g[u]:
                if not vis[v] and a[v] == val:
                    vis[v] = True
                    stack.append(v)
        return cnt

    for i in range(n):
        if not vis[i]:
            if dfs(i) % 2 == 1:
                print("NO")
                return

    print("YES")

t = int(input())
for _ in range(t):
    solve()
```このソリューションはツリーを構築し、固定値に制限された各接続コンポーネントを探索します。 DFS は、歪んだツリーの下での再帰の深さの問題を回避するために反復されます。 

各コンポーネントのサイズは個別に計算されます。 コンポーネントのサイズが奇数であることが判明すると、それ以上の構造ではその不均衡を修正できないため、プログラムは早期に停止します。 

微妙な点は、トラバーサルが値の等しいことによって制約されるため、通常のツリー コンポーネントではなく、値に起因する接続コンポーネントが見つかることです。 

## 実用的な例

 値がすでにきれいなペア構造を形成している小さなツリーを考えてみましょう。```
n = 4
values = [1, 1, 2, 2]
edges:
1-2, 3-4, 2-3
```コンポーネントを処理します:

 | 開始 | 値 | 訪問したノード | コンポーネントのサイズ |
 | --- | --- | --- | --- |
 | 1 | 1 | {1,2} | 2 |
 | 3 | 2 | {3,4} | 2 |

 両方のコンポーネントのサイズは等しいため、答えは「YES」です。 

次に、障害物がある場合を考えてみましょう。```
n = 3
values = [1, 1, 1]
edges:
1-2, 2-3
```トラバーサル:

 | 開始 | 値 | 訪問したノード | コンポーネントのサイズ |
 | --- | --- | --- | --- |
 | 1 | 1 | {1,2,3} | 3 |

 コンポーネントのサイズが奇数であるため、答えは「NO」です。 

これは障害モードを直接示しています。値クラス内で 1 つのノードが常に不一致のままになり、完全な削減が妨げられます。

 ## 特殊なケース

 最小のエッジ ケースは、同じ値を持つ 2 つのノードからなるツリーです。 DFS はサイズ 2 の単一コンポーネントを見つけます。これは偶数であるため、アルゴリズムはそれを受け入れ、1 つのマージがすぐに可能であるという事実と一致します。 

より微妙なケースは、すべてのノードが同じ値を共有する星型ツリーです。 中心の次数が高くても、トラバースではコンポーネント全体が 1 つのグループとしてカウントされます。 ノードの数が奇数の場合、アルゴリズムはそれを即座に拒否し、マージ順序に関係なく 1 つのノードが常にペアになっていないことを正しく反映します。 

もう 1 つの重要なケースは、異なる値で区切られた等しい値のペアの 2 部構造のような、エッジに沿って値が交互に現れる場合です。 価値に起因する各コンポーネントは分離されているため、DFS が価値の境界を越えることはありません。 各コンポーネントは独立して評価されるため、互換性のないリージョン間での誤ったマージが防止されます。
