 ## 問題の理解

 2 つのシーケンスが与えられます。 最初のシーケンス`a`は照合したいパターンで、2 番目のシーケンスは`b`は無限に繰り返される塩基配列ですが、回数は有限です。 繰り返してみると`b`その通り`k`多くの場合、長いシーケンスが得られます。`k`～の連続コピー`b`。

サブシーケンスとは、左から右にスキャンして、並べ替えずに要素を選択することを意味し、場合によっては要素をスキップします。 

重要な難点は、`k`は与えられない。 フルパスを何回通過するかを決定する必要があります`b`のすべての要素を「消費」する必要があります`a`順番に。 

この制約により、すべてのテスト ケースにわたって合計最大 200,000 個の要素が許可されます。 これにより、明示的に構築しようとするアプローチは直ちに除外されます。`dup(b, k)`または、増大するコピーとのマッチングをシミュレートします。`b`の多くの候補値に対して`k`。 テストごとに線形または線形に近いものより悪いものは失敗します。 

何らかの要素が存在する場合、微妙なエッジケースが発生します。`a`決して登場しない`b`。 例えば、`a = [1]`、`b = [2, 3]`。 どれだけ繰り返しても役に立ちません。答えは次のとおりです。`-1`。 不正にリセットされた素朴な貪欲スキャンは、到達可能性を明示的にチェックしない限り、依然としてループし、進行が可能であると誤って想定する可能性があります。`b`。 

マッチング時に別の厄介なケースが発生します`a`のコピーの途中で再起動する必要があります`b`。 例えば、`b = [1, 2, 3]`、`a = [2, 3, 1, 2]`。 のフルパスを完了するかもしれません`b`完了する前に`a`したがって、複数のサイクルが必要であり、何回ラップアラウンドするかをカウントする必要があります。`b`。 

## アプローチ

 直接シミュレーションのアプローチは簡単です。 私たちは一致しようとします`a`に対して`b`、ポインタを中に移動します`a`一致する要素が見つかるたびに、`b`。 終わりに達したら`b`、使用した完全なコピーの数に応じてカウンターをインクリメントし、スキャンを再開します。`b`最初から。 どちらかになるまで続けます`a`完全に一致しているか、進行が不可能であることが検出されます。 

これが機能するのは、サブシーケンスのマッチングが本質的に貪欲であるためです。つまり、次の要素をマッチングできるときはいつでも、`a`の可能な限り早い位置で一致させる必要があります。`b`。 

ただし、単純な実装ではスキャンを再開すると非効率になります。`b`何度も最初からスキャンを繰り返します。 最悪の場合、各要素は、`a`完全な走査が必要になる場合があります`b`、両方の配列が大きい場合、O(nm) の動作が遅くなりすぎます。 

重要な観察は、各繰り返し内の動作が`b`同一です。 繰り返しスキャンする代わりに`b`で各値の位置を前処理できます。`b`二分検索を使用して、次の有効な出現箇所に「ジャンプ」します。 これにより、マッチングの各ステップが変わります`a`対数または償却定数演算に変換します。

これにより、巡回配列内の次の位置を効率的に見つけるという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。

### なぜ効果があるのか

 すべてのステップで、常に次の各要素を配置します。`a`繰り返し構造内の可能な限り最も早い有効な位置にあります。 この貪欲な配置により、人為的に試合を遅らせることがなくなり、必要な繰り返し回数が不必要に増加することがなくなります。 試合を遅らせるような代替配置は、我々をさらに追い込むだけです`b`潜在的には、より早い段階で追加のサイクルが必要になる可能性があり、決して少なくなることはありません。 

不変条件は、処理後のものです。`a[i]`、`pos`の位置です`a[i]`可能な限り初期のコピーで`b`有効なサブシーケンス構造と一致し、かつ`k`境界を越えた回数を正確に数えます`b`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from bisect import bisect_right

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pos_map = {}
        for i, x in enumerate(b):
            if x not in pos_map:
                pos_map[x] = []
            pos_map[x].append(i)

        # feasibility check
        for x in a:
            if x not in pos_map:
                print(-1)
                break
        else:
            k = 1
            pos = -1  # current index in b
            for x in a:
                lst = pos_map[x]
                idx = bisect_right(lst, pos)
                if idx < len(lst):
                    pos = lst[idx]
                else:
                    k += 1
                    pos = lst[0]
            print(k)

if __name__ == "__main__":
    solve()

の`pos`変数は、コピー内で最後に一致した場所を追跡します。`b`。 使用する`bisect_right`、次の有効な出現を効率的に見つけます。 何も存在しない場合は、インクリメントすることで次の繰り返しへの移動をシミュレートします。`k`そしてその値の最初の出現から再開します。

 ## 特殊なケース

 重大なエッジケースは、次の最初の要素が`a`には存在しません`b`。 例えば、`a = [5]`、`b = [1, 2, 3]`。 アルゴリズムチェック`pos_map`マッチングが開始される前に実行されるため、すぐに返されます`-1`。 このチェックを行わないと、単純なポインター手法では無限にループしたり、サイクルが誤ってリセットされたりする可能性があります。 

もう一つのケースは次のような場合です。`a`の 1 回の走査内に完全に含まれます`b`、 のような`a = [1, 3]`、`b = [1, 2, 3, 4]`。 ここ`k`残っている`1`なぜなら`pos`ラッピングは必要ありません。 アルゴリズムが増加することはありません`k`、次の出現はすべて現在のサイクルで見つかるためです。 

最後のケースは、次のような大量の繰り返しです。`a = [1, 1, 1, 1]`、`b = [1]`。 各要素は、同じインデックスの再利用またはサイクル増分のいずれかを強制します。 アルゴリズムは正しく増加します`k`前方オカレンスが存在しないたびに、`k = 4`、これは必要な繰り返し数と一致します。
