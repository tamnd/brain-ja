 ## 解決策
 ## 問題の理解

 (n) 個の頂点を持つツリーがあります。 すべての頂点には色があり、任意の 2 つの異なる頂点について、その一意のパスを調べ、そのパス上で発生する異なる色の数を数えます。 タスクは、すべての (\frac{n(n-1)}2) 個の順序のない頂点ペアにわたってこの値を合計することです。 入力にはいくつかのテスト ケースが含まれており、各テスト ケースは頂点カラーとそれに続く (n-1) 個のツリー エッジで構成されます。 必要な出力は、ケース番号が接頭辞として付けられた、各ケースの合計です。 公式の問題形式とサンプル出力は、Codeforces Gym 102253C によって提供されます。 

制約 (n\le 2\cdot10^5) により、二次時間に近いものは除外されます。 すでに最大サイズで約 (2\cdot10^{10}) 個の頂点ペアが存在するため、すべてのペアを 1 回列挙するだけでも、2 秒の制限が許容できる範囲をはるかに超えています。 意図したソリューションでは、各頂点とエッジを一定回数だけ処理する必要があり、(n) で線形複雑度が得られます。 色の値も最大 (n) であるため、色ごとの情報を通常の配列で維持できます。 

間違った答えを導き出す簡単な方法がいくつかあります。 繰り返される色はパスに 1 回だけ寄与する必要があります。 例えば、```
2
1 1
1 2
```にはパスが 1 つだけあり、そのパスには異なる色が 1 つだけ含まれているため、答えは次のようになります。`1`。 各頂点に 1 つの寄与を追加するソリューションでは、誤った取得が発生します。`2`。 

2 つのエンドポイントがパスに含まれています。 のために```
2
1 2
1 2
```唯一のパスには色 (1) と (2) が含まれているため、答えは次のようになります。`2`。 Treating a path as containing only its internal vertices would incorrectly give zero colors.

 The component on the root side of the tree cannot be forgotten when removing a color. 例えば、```
3
1 1 2
1 2
1 3
```パス値 (1,2,2) があり、答えが得られます`5`。 カラー (2) の場合、唯一の頂点を削除すると頂点 (1) と (2) が接続されたままになるため、1 つのパスがカラー (2) を回避します。 ある色の出現の下にある子サブツリーのみを調べる計算では、この残りのルート側コンポーネントが欠落します。 

## アプローチ

 直接的な解決策では、頂点のすべてのペアを列挙し、そのパスを見つけ、そのパス上の色をセットに挿入し、セットのサイズを追加できます。 これは正しいです。すべてのパスが 1 回だけ検査され、セットによって重複した色が削除されるからです。 問題は仕事量です。 チェーン上で、すべてのパス上で訪問する頂点の合計数は次のようになります。 

[
 \sum_{d=1}^{n-1}(n-d)(d+1)
 =\frac{n(n-1)(n+4)}6
 =\シータ(n^3)。 
】

 (n=2\cdot10^5) では、これはおよそ (1.3\cdot10^{15}) 回の頂点訪問となるため、総当り的なアプローチは実行可能とは言えません。 

視点を変えると便利なのは、各色の寄与を個別にカウントすることです。 カラー セットに (k) 色が含まれるパスは、それらの (k) 色のそれぞれの答えに (1) 寄与します。 したがって、最終的な答えは、各色 (c) の少なくとも 1 つの色の頂点を含むパスの数 (c) の合計です。 この貢献は、補完することで表現するのが簡単になります。 合計で (\binom n2) 個のパスがあるため、色の寄与 (c) は次のようになります。 

[
 \binom n2-\text{色を回避するパスの数}c.
 】

 次に、色 (c) を持つすべての頂点を削除します。 残りのグラフは森です。 両方のエンドポイントがそのフォレストの同じ接続コンポーネント内にある場合、パスは (c) を正確に回避します。 コンポーネントのサイズが (s_1,s_2,\ldots) の場合、(c) を回避するパスの数は次のようになります。 

[
 \sum_i \binom{s_i}{2}。 
】

 これにより、問題は、各色を除去することによって得られるすべてのコンポーネントのサイズを計算することに変換されます。 これを色ごとに独立して行うと、やはり二次関数になります。 重要な観察は、これらすべての計算を 1 つの DFS 中に同時にシミュレートできるということです。 標準ソリューションでは、これを、仮想ツリーを明示的に構築せずに仮想ツリーのアイデアを使用するものとして説明しています。 

頂点 (1) でツリーをルートします。 現在の頂点 (u)、色 (c)、および 1 つの子 (v) について考えてみましょう。 (v) のサブツリー内では、いくつかのノードは、色 (c) の最も高い出現をルートとするサブツリーに属します。 すべての color-(c) 頂点が削除されると、これらのノードは (u) から分離されます。 (v) のサブツリー内の 1 つおきのノードは、(u) に接続された 1 つの連結コンポーネントに属します。 サブツリーのサイズが (sz[v]) で、それらのノードの (x) がすでに上位の color-(c) 頂点によって占められている場合、コンポーネントのサイズは (sz[v]-x) となり、パスを回避する (\binom{sz[v]-x}{2}) に寄与します。 

明示的に何も構築しなくても (x) を取得できます。 各色 (c) について、`dom[c]`、DFS 中に現在最も関連性の高いカラー (c) 頂点にすでに関連付けられている量。 子(v)に降りる直前にセーブ`dom[c]`。 (v) から戻った後、新しい値と保存された値の差は、それらの高位カラー (c) 領域が占めるサブツリーの量とまったく同じになります。 この差は、(sz[v]) から減算される量です。 同じ漸進的なアイデアが、この問題に対して受け入れられているツリー DP 定式化の中核です。 

最後に、DFS が終了した後も、色にはその最も高い出現より上のコンポーネントがまだ含まれている可能性があります。 そのサイズは (n-\text{dom}[c]) なので、その色を避けるパスの数に (\binom{n-\text{dom}[c]}2) を加えます。 これは、純粋にローカルなサブツリー計算では見逃されるルート側コンポーネントです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | チェーン上の (O(n^3)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 異なる色が何個発生するかを数えます。 (\binom n2) 個のパスがあり、最初は、すべての異なる色がすべてのパスに寄与していると想像できます。 したがって、開始値は次のようになります。 

[
 \text{distinctColors}\cdot\binom n2。 
】

 各色を避けるパスを減算します。 

1. ツリーの頂点 (1) をルートとし、(sz[u]) を (u) のサブツリーの頂点の数として定義します。 DFS は、すべての子から返すときにこの値を必要とします。 
2. 配列を維持する`dom[c]`。 DFS 中に、これは現在最も高いカラー (c) 領域によってすでに吸収されている合計サイズを表します。 頂点(u)を色(c)で処理する場合、ローカル値を初期化する`added = 1`なぜなら、(u) 自体は色 (c) で表される新しい領域の一部になるからです。 
3. (u) の各子 (v) を一度に 1 つずつ処理します。 保存`before = dom[c]`(v) に入る直前。 (v) のサブツリーは、この子に対して他の処理が行われる前に完全に処理されます。 
4. (v)から戻ったら計算します。 

[
 x=dom[c]-前。 
】

 値 (x) は、より高い色 (c) 領域に属する (v) のサブツリーの部分をカウントします。 これらの領域にはカラー (c) の頂点が含まれており、カラー (c) が削除された後は (u) から切り離されます。 

1. 残りの部分

 [
 ブロック=sz[v]-x
 】

 は、まさに、カラー (c) 頂点を含まない (v) を含む連結コンポーネントです。 このコンポーネント内のすべての頂点のペアには、色 (c) を回避するパスが与えられるため、次の値を追加します。 

[
 \binom{ブロック}{2}
 】

 答えから減算されるパスの数に。 

1.追加`block`地元へ`added`(u) の値。 すべての子が処理された後、更新します

 [
 dom[c]\mathrel{+}=追加されました。 
】

 これにより、以前の最高の色 (c) 領域が (u) で表される領域に置き換えられます。これは、まさに (u) の親に必要な状態です。 

1. DFS 全体の後、実際に発生するすべての色を処理します。 残りのルート側コンポーネントにはサイズがあります

 [
 n-dom[c]。 
】

 追加

 [
 \binom{n-dom[c]}2
 】

 その色を回避するパスの数に応じて変化します。 

1. から回避パスの総数を引きます。`distinctColors * C(n, 2)`。 結果は、すべてのパスにわたる個別の色のカウントの必要な合計です。 

以下の実装では、Python 再帰ではなく明示的な DFS スタックを使用します。 ツリーは長さ (2\cdot10^5) のチェーンになる可能性があるため、再帰的 Python DFS はインタープリターの再帰スタックを超える危険があります。 明示的なスタックでは、再帰的反復とまったく同じ親子処理順序が保持されます。 

### なぜ効果があるのか

 色を固定します(c)。 色のすべての頂点を削除すると (c)、ツリーが接続されたコンポーネントに分割され、1 つのコンポーネント内の頂点ペアが (c) を回避するパスを持ちます。 色 (c) を持つ頂点 (u) のすべての子 (v) について、`dom[c] - before`(v) のサブツリーのうち、(v) の下の最も高い色 (c) の頂点によって既に分離されている部分を正確にカウントします。 これらの部分を削除すると、接続された 1 つの色 (c) のないサイズのコンポーネントが残ります。`sz[v] - (dom[c] - before)`, したがって、その (\binom{size}{2}) ペアは正確に 1 回カウントされます。 すべての子が処理された後、`dom[c]`は、最高の color-(c) 頂点によってすでに占められている領域を表します。 唯一の未処理のコンポーネントは、最も高いカラー (c) 頂点の上にあるコンポーネントであり、そのサイズは (n-dom[c]) であり、最後にカウントされます。 したがって、(c) を回避するすべてのペアは 1 回カウントされ、(c) を含むすべてのペアはその補数から除外されます。 すべての色にわたるこの寄与を合計すると、すべてのパス上の個別の色の数が正確に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    out = []
    case_no = 0

    while True:
        line = input()
        if not line:
            break
        line = line.strip()
        if not line:
            continue

        n = int(line)
        color = [0] + list(map(int, input().split()))

        graph = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            graph[u].append(v)
            graph[v].append(u)

        present = [False] * (n + 1)
        distinct = 0
        for u in range(1, n + 1):
            c = color[u]
            if not present[c]:
                present[c] = True
                distinct += 1

        # dom[c] is the amount already absorbed by the highest
        # color-c regions during the current DFS.
        dom = [0] * (n + 1)

        # sz[u] is the subtree size.
        sz = [0] * (n + 1)

        # Number of paths avoiding their corresponding colors.
        bad = 0

        # Frame:
        # [vertex, parent, next_edge_index, added, before]
        #
        # added is the local value that will be added to dom[color[u]]
        # when u finishes.
        # before stores dom[color[u]] immediately before entering
        # the currently processed child.
        sz[1] = 1
        stack = [[1, 0, 0, 1, 0]]

        while stack:
            frame = stack[-1]
            u = frame[0]
            p = frame[1]

            if frame[2] < len(graph[u]):
                v = graph[u][frame[2]]
                frame[2] += 1

                if v == p:
                    continue

                c = color[u]
                frame[4] = dom[c]

                sz[v] = 1
                stack.append([v, u, 0, 1, 0])
                continue

            # Finish u.
            c = color[u]
            dom[c] += frame[3]
            stack.pop()

            if stack:
                parent_frame = stack[-1]
                parent = parent_frame[0]
                pc = color[parent]

                added_in_child = dom[pc] - parent_frame[4]
                block = sz[u] - added_in_child

                bad += block * (block - 1) // 2
                parent_frame[3] += block
                sz[parent] += sz[u]

        # The component above the highest occurrence of each color.
        for c in range(1, n + 1):
            if not present[c]:
                continue
            block = n - dom[c]
            bad += block * (block - 1) // 2

        total = distinct * n * (n - 1) // 2
        answer = total - bad

        case_no += 1
        out.append(f"Case #{case_no}: {answer}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力フェーズでは、頂点番号と配列インデックスが一致するように、インデックスが 1 つの配列に色が格納されます。 の`present`配列は個別の色を同時にカウントするため、最初の寄与には実際に発生する色のみが使用されます。 

の`dom`配列は状態の中心部分です。 すべての色に対して同じ計算が一度に実行されるため、頂点ではなく色によってインデックスが付けられます。 子が終了すると、親は新しいものを比較します。`dom[color[parent]]`その子に入る前に保存された値を使用します。 差分のみがその子に属するため、この減算により、以前の兄弟サブツリーに蓄積された情報が再度カウントされるのを防ぎます。 

の`added`各 DFS フレームのフィールドは、現在の頂点の 1 から始まります。 すべての子は、その色のないブロックをこの値に寄与します。 頂点が終了したら、追加します`added`に`dom[color[u]]`新しく形成された最高色の領域全体をその親が利用できるようにします。 

最後のループは、各色の最も高い出現位置より上のツリーの部分を処理します。 ルートにその色がない場合、このステップを省略すると、誤った答えが発生する原因になります。 

すべてのパス数は Python 整数を使用するため、オーバーフローの心配はありません。 固定幅整数を使用する言語では、答えが (n^3) 程度になる可能性があるため、64 ビット整数が必要です。 

明示的なスタックも意図的です。 再帰的 DFS はチェーン上に (O(n)) の深さを持ちますが、反復バージョンでは (O(n)) のヒープ メモリが使用され、再帰の深さの障害はありません。 

## 実用的な例

 ### サンプル 1

 ツリーはチェーン (1-2-3)、色 (1,2,1) です。 3つの道があります。 初期寄与は 2 つの異なる色と 3 つのパスの積であり、(6) となります。 

DFS は、頂点 (3) を含む頂点 (2) のサブツリーを処理します。 頂点(3)が終了すると、色(1)は1つの頂点を吸収します。 頂点(2)が終了すると、色(2)は2つの頂点を吸収します。 頂点 (1) に戻ると、カラー (1) の領域がツリー全体を占めます。 

| 頂点 | 色 | 子供 | 子供のサイズ |`before`|`dom`子供の後 |`block`|`bad`追加しました |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 3 | 1 | なし | 0 | 0 | 1 | 0 | 0 |
 | 2 | 2 | 3 | 1 | 0 | 1 | 0 | 0 |
 | 1 | 1 | 2 | 2 | 0 | 1 | 1 | 0 |
 | 1 | 1 | 2 終了 | 2 | 0 | 3 | 0 | 0 |

 DFS後は、`dom[1] = 3`なので、色 (1) には根元側の成分が残りません。`dom[2] = 2`、サイズ (1) のコンポーネントが残り、回避パスに寄与しません。 したがって`bad = 0`、そして答えは(6)のままです。 

この例は、同じ色を頂点ごとに独立してカウントできない理由を示しています。 色 (1) の 2 つの出現は合わせて、すべてのパスに 2 つではなく、正確に 1 つのユニットに寄与します。 

### サンプル 2

 木は```
        1(1)
       /   \
    2(2)   3(1)
    /  \      \
 4(3) 5(2)    6(1)
```6 つの頂点と 3 つの異なる色があるため、初期値は次のようになります。 

[
 3\binom62=45。 
】

 関連する DFS 移行は次のとおりです。 

| 頂点 | 色 | 子供 | 子供のサイズ |`before`|`dom`子供の後 |`block`|`bad`追加しました |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 4 | 3 | なし | 1 | 0 | 1 | 0 | 0 |
 | 5 | 2 | なし | 1 | 0 | 1 | 0 | 0 |
 | 2 | 2 | 4 | 1 | 0 | 0 | 1 | 0 |
 | 2 | 2 | 5 | 1 | 0 | 1 | 0 | 0 |
 | 3 | 1 | 6 | 1 | 0 | 1 | 0 | 0 |
 | 1 | 1 | 2 | 3 | 0 | 0 | 3 | 3 |
 | 1 | 1 | 3 | 2 | 0 | 2 | 0 | 0 |

 DFS 後の 3 つの色に関連する値は次のとおりです。 

| 色 |`dom[color]`| 根元側サイズ | ルート側の回避パス |
 | --- | --- | --- | --- |
 | 1 | 6 | 0 | 0 |
 | 2 | 3 | 3 | 3 |
 | 3 | 1 | 5 | 10 |

 頂点 (2) につながる頂点 (1) の子は、サイズ (3) の色なしコンポーネント (1) を生成し、(3) パスの回避を考慮します。 色 (2) には、最も高い出現よりも大きいサイズ (3) の別のコンポーネントがあり、パス (3) を占めています。一方、色 (3) のルート側コンポーネントはサイズ (5) で、パス (10) を占めています。 

したがって、欠落している色の寄与の合計数は次のようになります。 

[
 3+3+10=16、
 】

 そして最終的な答えは

 [
 45-16=29。 
】

 トレースは、中心の不変条件を示しています。`dom[c]`は、色 (c) のより高い出現によってすでに分離されている部分を正確に保持します。`sz[v] - delta`は、その子サブツリーに残っている 1 つの色のないコンポーネントです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n)) | すべての頂点とすべての木のエッジが一定回数処理され、その後 (n) の可能な色が 1 回スキャンされます。 |
 | スペース | (O(n)) | 隣接リスト、サブツリー サイズ、色の状態、プレゼンス配列、および明示的な DFS スタックはすべてリニア メモリを使用します。 |

 最大 (n) は (2\cdot10^5) であるため、2 秒の制限時間には線形パスが適切です。 この実装では、頂点ペアの 2 次数と (n) に比例する再帰的 DFS 深さの両方が回避されます。 答えは 32 ビットの範囲を超える可能性がありますが、Python の整数は必要な値を直接処理します。

                present[c] = True
                distinct += 1

        dom = [0] * (n + 1)
        sz = [0] * (n + 1)
        bad = 0

        sz[1] = 1
        stack = [[1, 0, 0, 1, 0]]

        while stack:
            frame = stack[-1]
            u, p = frame[0], frame[1]

            if frame[2] < len(graph[u]):
                v = graph[u][frame[2]]
                frame[2] += 1

                if v == p:
                    continue

                frame[4] = dom[color[u]]
                sz[v] = 1
                stack.append([v, u, 0, 1, 0])
            else:
                c = color[u]
                dom[c] += frame[3]
                stack.pop()

                if stack:
                    parent_frame = stack[-1]
                    parent = parent_frame[0]
                    pc = color[parent]

                    delta = dom[pc] - parent_frame[4]
                    block = sz[u] - delta

                    bad += block * (block - 1) // 2
                    parent_frame[3] += block
                    sz[parent] += sz[u]

        for c in range(1, n + 1):
            if present[c]:
                block = n - dom[c]
                bad += block * (block - 1) // 2

        total = distinct * n * (n - 1) // 2
        answer = total - bad

        case_no += 1
        out.append(f"Case #{case_no}: {answer}")

    return "\n".join(out)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    try:
        sys.stdin = io.StringIO(inp)
        return solution()
    finally:
        sys.stdin = old_stdin

 ## 特殊なケース

 同じ色の頂点が 2 つある最小のツリーの場合、```
2
1 1
1 2
```初期寄与は (1\cdot\binom22=1) です。 DFS は両方の頂点を吸収します。`dom[1]`, したがって、ルート側コンポーネントのサイズは 0 になります。 色 (1) を回避するパスはありません。`bad = 0`そして最終的な答え`1`。 アルゴリズムは頂点ごとではなく色ごとに機能するため、繰り返されたカラーは 1 回カウントされます。 

異なる色の 2 つの頂点の場合、```
2
1 2
1 2
```パスが 1 つあり、両方の色が含まれています。 初期寄与は (2\cdot1=2) です。 各色は、その唯一の頂点が削除された後は非自明なコンポーネントを持たないため、回避パスは差し引かれません。 結果は`2`。 これにより、両方のエンドポイントがパスに属していることも確認されます。 

根元から離れたところに発色するカラーの場合、```
3
1 1 2
1 2
1 3
```パスは (1\leftrightarrow2)、(1\leftrightarrow3)、および (2\leftrightarrow3) で、値は (1,2,2) です。 それらの合計は`5`。 色 (2) の場合、頂点 (3) を削除するとサイズ (2) のコンポーネントが残るため、正確に (\binom22=1) のパスでそれを回避します。 色 (2) の最終的な寄与は (3-1=2) です。 同じ色の頂点 (1) と (2) は、2 つの別々の寄与ではなく 1 つの共通の色に寄与し、合計が得られます。`5`。
