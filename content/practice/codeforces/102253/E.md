 ## 解決策
 ## 問題の理解

 正の整数 (n>1) から始めます。 1 回の操作で、正の約数の 1 つを一様にランダムに選択し、現在の数値をその約数で置き換えます。 数値が最初に (1) になった時点でプロセスが停止します。 タスクは、予想される操作数を見つけることです。 

入力により、(n)、個別の素因数の数 (m)、およびそれらの素因数が与えられます。 重要な詳細は、(n) が (10^{24}) まで大きくなる可能性があるため、(n) までのすべての整数を状態として扱うことは不可能であるということです。 提供された素因数を使用すると、(n) の因数分解ですべての素数の指数を回復できます。 

期待値は有理数です。 分子と分母を出力する代わりに、分母のモジュロ (10^9+7) の逆モジュラを乗算した分子を出力します。 

元の編集では、同じ漸化式を導出し、状態空間を実際の整数から素数指数の複数セットに縮小します。 

境界 (n\le 10^{24}) が、標準除数 DP が不十分な理由です。 この範囲の数値には 100 万を超える約数が含まれる可能性があり、約 (2\times10^5) 個のテスト ケースが存在する可能性があります。 すべてのテスト ケースのすべての約数を列挙するには、利用可能な時間をはるかに超える時間が必要になります。 最初 (18 個) の素因数の積はすでに (10^{23}) 程度であるため、個別の素因数の数ははるかに少なく、最大 (18) 個です。 これにより、素数指数に基づく状態表現が可能になります。 

誤って対処しやすい特殊なケースがいくつかあります。 (n=2) の場合、約数は (1) と (2) となり、現在の状態を選択し直すことができます。 期待は満たされる

 [
 f(2)=1+\frac{f(1)+f(2)}2、
 】

 したがって (f(2)=2)、次のようになります。`Case #1: 2`。 適切な約数のみを平均する反復では、誤って (1) が得られます。 

(n=4) の場合、正しい値は (5/2) であり、これは次のようになります。`500000006`モジュロ (10^9+7)。 除数 (4) による自己遷移は漸化式に残らなければなりません。 

(n=6) の場合、適切な除数の期待値は (f(1)=0)、(f(2)=2)、および (f(3)=2) です。 (6) には約数が 4 つあるので、

 [
 f(6)=1+\frac{0+2+2+f(6)}4=\frac83。 
】

 そのモジュール表現は次のとおりです。`666666674`。 よくある間違いは、(p) を選択すること自体が自己ループを作成することを忘れて、素数 (p) に (f(p)=1) を使用することです。 

最後に、等しい指数は、区別可能な位置としてではなく、マルチセットとして扱われなければなりません。 数値 (12=2^2\cdot3) と (18=2\cdot3^2) は同じ指数マルチセット ({1,2}) を持ち、それらの期待値は等しいです。 順序付けられた素数リストによってキー付けされた状態は、この対称性を失います。 

## アプローチ

 直接的なアプローチは期待の再発に従います。 (f(n)) は、(f(1)=0) で、(n) からの予想される残りの操作数を表すものとします。 (\tau(n)) が正の約数の数である場合、約数を一様に選択すると、

 [
 f(n)=1+\frac1{\tau(n)}\sum_{d\mid n}f(d)。 
】

 (d=n) を選択すると数値が変化しないため、項 (f(n)) が合計に表示されます。 並べ替えると

 [
 f(n)=
 \frac{\tau(n)+\sum_{d\mid n,\ d<n}f(d)}
 {\tau(n)-1}。 
】

 ブルートフォース実装では、すべての約数 (d\mid n) を生成し、再帰的に計算 (f(d)) し、結果をメモ化できます。 すべての約数が次の可能な状態の 1 つであるため、これは正しいです。 問題は約数の数です。 (n\le10^{24}) の場合、1 つの数値には (1,290,240) 個の約数があり、関連するすべての状態にわたる約数の合計は (1.5\times10^{10}) 程度になります。 これだけ多くの操作を行うと、3 秒間のコンテスト制限には収まりません。 

最初の有益な観察は、実際の素数値は重要ではないということです。 仮定してください

 [
 x=\prod_i p_i^{e_i}
 】

 そして

 [
 y=\prod_i q_i^{e'_i}
 】

 同じ複数の指数セットを持ちます。 それらの約数は、(0) と各 (e_i) の間の指数を独立して選択することによって取得されます。 結果として得られるすべての約数の期待値は、それ自体の指数マルチセットのみに依存するため、数値の値の帰納法により (f(x)=f(y)) が示されます。 したがって、状態は、その正の素指数の順序付けされていないマルチセットによってのみ表現できます。 

たとえば、(12) と (18) の指数状態は両方とも ((2,1)) であるため、1 つのメモ化された値を共有します。 可能な最小の整数をもつ代表値は、最大の指数を最小の素数に割り当て、次に最大の指数を次に最小の素数に割り当てるというようにして取得されます。 これにより、正規の順序が与えられます。 

代表者のすべての約数を列挙することはまだできません。 2 番目の観察は、除数の合計を多次元の接頭辞の合計として計算することです。 定義する

 [
 h(n,k)=
 \sum_{d\mid\prod_{i=1}^k p_i^{e_i}}
 f\左(
 d\frac{n}{\prod_{i=1}^k p_i^{e_i}}
 \右）
 】

 また、(g(n,k)) をプレフィックスの適切な約数に限定した同じ和とする。 次に、(h(n,k)=f(n)+g(n,k))となります。 

(k) 番目の指数のすべての選択肢を列挙する代わりに、そのすべての指数が使用される場合と、少なくとも 1 つのコピーが削除される場合に分割します。 後者の部分は、まさに (n/​​p_k) の部分除数の合計です。 これにより、次元ごとに 1 つの小さな状態のみを必要とする遷移が得られます。 結果として得られる計算は、約数の数ではなく、関連する指数マルチセットの数とその個別の素数の積に比例します。 公式分析では、(n\le10^{24}) について、(172,513) 個の可能な指数マルチセットと約 (117) 万個の状態次元遷移が報告されています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(\sum \tau(n))) すべての状態 | (O(\text{状態の数})) | 遅すぎる |
 | 最適 | (O( | S | \omega(n)+T\log n)) | (O( | S | \omega(n))) | 承認済み |

 ここで、(S) は可能な指数マルチセットのセットであり、(\omega(n)) は個別の素因数の数です。 各入力数値の因数分解には、除算を繰り返すだけのコスト (O(m\log n)) がかかります。 

## アルゴリズムのチュートリアル

1. 指定された個別の素因数を使用して、指定された (n) を因数分解します。 指定されたすべての素数 (p) について、(n) を (p) で繰り返し割り、その指数を数えます。 結果として得られる指数リストは、完全な素因数分解です。 
2. 正の指数を非増加順に並べ替えます。 これにより、状態から素数のアイデンティティが削除されます。 同じ指数マルチセットを持つ 2 つの整数は、まったく同じ DP 状態を使用するようになりました。 
3. (F(E)) を指数の多重集合 (E) の期待値として定義し、(G(A,B)) を多重集合 (B) を固定したまま、多重集合 (A) によって表される素因数のみを変更することによって得られるすべての固有約数にわたる (F) の合計として定義します。 
4. (A) が空の場合、空のプレフィックスを変更しても適切な約数は生成されないため、(G(\varnothing,B)=0) となります。 これは、プレフィックスサム反復の基本ケースです。 
5. (A) から 1 つの指数 (a) を選択します。すべてのマルチセットが正規に保存されているため、できれば最大の指数を選択します。 (A_0) をその指数を除いた (A) とし、(A_1) を (a) を 1 減らしてゼロになった場合に取り除いた (A) とします。 
6. この特定の素数に対して選択された指数に従って、約数を分割します。 その指数が (a) に等しい場合、残りのプレフィックスの除数は適切である必要があり、(G(A_0,B\cup{a})) となります。 (a) より小さい場合、結果として得られるすべての約数はすでに適切であり、その和は (F(A_1\cup B)+G(A_1,B)) となります。 
7. これら 2 つのケースを組み合わせます。 

[
 G(A,B)=
 G(A_0,B\カップ{a})
 +
 F(A_1\カップB)
 +
 G(A_1,B)。 
】

 最初の再帰呼び出しにより、アクティブなプレフィックス要素の数が減少します。 2 番目の分岐では指数の合計が減少するため、再帰は非循環になります。 

1. 完全な指数マルチセット (E) の場合、値 (G(E,\varnothing)) は、すべての適切な約数 (d<E) にわたる (F(d)) の正確な合計です。 しましょう

 [
 \tau(E)=\prod_{e\in E}(e+1)。 
】

 期待再発は次のようになります。 

[
 F(E)=
 \frac{\tau(E)+G(E,\varnothing)}
 {\タウ(E)-1}。 
】

 すべての算術演算はモジュロ (10^9+7) で実行され、除算と乗算の代わりに逆モジュラが使用されます。 

1. (F(E)) と (G(A,B)) の両方をメモ化します。 (F) はソートされた指数マルチセットのみに依存するため、同じ指数パターンを持つすべてのテスト ケースで結果がすぐに再利用されます。 (A) と (B) の両方の正規ソートでは、同等の素因数の並べ替えによってのみ異なる状態もマージされます。 

### なぜ効果があるのか

 再帰では、合計される適切な約数のセットが正確に保存されます。 (G(A,B)) の場合、各約数は識別された素数の指数を選択します。 その指数が元の (a) である場合 (この場合、残りのプレフィックス自体が適切な約数である必要があります)、または最大でも (a-1) (この場合、約数は自動的に適切になります) のいずれかです。 これらの場合は互いに素であり、すべての適切な約数を 1 回だけカバーします。 再帰呼び出しにより、アクティブなプレフィックス因数の数または合計指数合計が減少するため、すべての必要な値は最終的に基本ケースに達します。 最後に、期待方程式は均一に選択された除数の条件付けから直接得られるため、計算された (F(E)) は正確に必要な期待値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

# f_cache[E] = expected value for the exponent multiset E.
# E is always a tuple sorted in non-increasing order.
f_cache = {(): 0}

# g_cache[(A, B)] = sum of F over proper divisors generated by A,
# with the exponents in B fixed.
g_cache = {}

def get_f(e):
    e = tuple(sorted((x for x in e if x), reverse=True))
    if not e:
        return 0

    cached = f_cache.get(e)
    if cached is not None:
        return cached

    proper = get_g(e, ())
    tau = 1
    for x in e:
        tau = tau * (x + 1) % MOD

    ans = (tau + proper) % MOD
    ans = ans * pow(tau - 1, MOD - 2, MOD) % MOD

    f_cache[e] = ans
    return ans

def get_g(A, B):
    A = tuple(A)
    B = tuple(B)

    key = (A, B)
    cached = g_cache.get(key)
    if cached is not None:
        return cached

    if not A:
        return 0

    # A and B are stored in non-increasing order.
    # We take the largest exponent from A.
    a = A[0]
    A0 = A[1:]

    # Case 1: the chosen prime keeps its full exponent a.
    B0 = tuple(sorted(B + (a,), reverse=True))
    part_full = get_g(A0, B0)

    # Case 2: its exponent is smaller than a.
    if a == 1:
        A1 = A0
    else:
        A1 = tuple(sorted((a - 1,) + A0, reverse=True))

    combined = tuple(sorted(A1 + B, reverse=True))
    part_reduced = (get_f(combined) + get_g(A1, B)) % MOD

    ans = (part_full + part_reduced) % MOD
    g_cache[key] = ans
    return ans

def solve_case(n, primes):
    exponents = []

    for p in primes:
        e = 0
        while n % p == 0:
            n //= p
            e += 1
        exponents.append(e)

    exponents.sort(reverse=True)
    return get_f(tuple(exponents))

def main():
    t = int(input())
    out = []

    for case_id in range(1, t + 1):
        n, m = map(int, input().split())
        primes = list(map(int, input().split()))

        ans = solve_case(n, primes)
        out.append(f"Case #{case_id}: {ans}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```因数分解ループは、試行除算ではなく、指定された素数を使用します。 指定されたすべての素数は元の (n) を除算するため、それで繰り返し除算すると、その正確な指数が回復されます。 供給されたすべての素数が処理された後、(n) の残りの値は (1) になります。`get_f`引数を検索する前に正規化します。 これは、たとえば (12) と (18) が同じ状態 ((2,1)) を共有するようにする対称性の縮小です。`get_g`プレフィックス繰り返しの 2 つのケースを実装します。 取る`A[0]`(A) 内の順序は無関係であるため、安全です。 指数を変更した後、結果のマルチセットはメモ化前に再度ソートされます。 並べ替えは単に表面的なものではなく、素因数の並べ替えによってのみ異なる状態を識別するものです。 

の表現`tau`は (\prod(e_i+1))、約数の数です。 分母は`tau - 1`元の状態自体が (f(n)) として除数の平均に寄与するためです。 (10^9+7) は素数であり、このステートメントは必要な分母が法を法として可逆であることを保証するため、逆モジュラーはフェルマーの定理を使用して計算されます。 

Python の整数は入力境界 (10^{24}) を安全に保持するため、特別な大きな整数表現は必要ありません。 モジュラー値自体は、遷移のたびにモジュラス未満に留まり、不必要な増大を防ぎます。 

漸化式は、約数ごとに評価されるのではなく、メモ化されます。 これは、実際の複雑さを、除数の数に依存するものから、はるかに小さい指数状態空間に依存するものに変える、中心的な実装の選択です。 状態の削減とプレフィックスサムのアイデアは、公式のソリューションで使用されているものと同じ構造の単純化です。
