 ## 解決策
 ## 問題の理解

 スーパーコンピューターは、以下のすべての整数を表現できます。`0`を通して`2^m - 1`。 しかし、この若者は、からの範囲でのみ作業したいと考えています。`1`を通して`10^k`。 最大のものが必要です`k`その 10 進数の範囲内のすべての数値が表現可能です。 

若者が使用する最大の数字は`10^k`、範囲全体が正確に一致する場合`10^k <= 2^m - 1`。 

したがって、各テストケースは次のようになります`m`、出力は最大の整数です`k`この不等式を満たすこと。 ケース番号も印刷する必要があります。`1`。 公式声明は、最大約約の制約を確認しています。`10^5`テストケースを使用した`1 <= m <= 10^5`。 

テスト ケースの数が十分に多いため、ソリューションは以下に比例して動作します。`m`どのケースもすでに高価すぎます。 と`10^5`ケースと`m`と同じくらい大きい`10^5`、それは周りに届く可能性があります`10^10`繰り返し。 各テスト ケースを一定時間に短縮する必要があります。 

一般的に間違いを引き起こす境界の詳細が 2 つあります。 まず、いつ`m = 1`、マシンはのみを表します`0`そして`1`、 それで`10^0 = 1`フィットしますが、`10^1 = 10`しません。 答えは、`0`、 ない`1`。```
Input:
1

Output:
Case #1: 0
```小数点以下の桁数を計算する不用意な実装`2^m`戻ってくるかもしれない`1`、ただしマシンの最大値は`2^m - 1`、 ない`2^m`。 

2 番目の境界は、以下の厳密な違いです。`2^m`そして`2^m - 1`。 のために`m = 10`、マシンは次の値をサポートします。`1023`。 以来`1000 <= 1023`、`k = 3`有効です。```
Input:
10

Output:
Case #1: 3
```誤って必要とする解決策`10^k < 2^m - 1`いくつかの正確な境界ケースがたまたま拒否される可能性があります。 これを回避するきれいな方法は、両辺が整数であるという事実を利用し、条件を以下を含む厳密な不等式に変換することです。`2^m`。 

## アプローチ

 直接的な解決策としては、次の値を試すことができます。`k`ゼロから始めて、`10^k <= 2^m - 1`。 これは正しいです。次の有効な値は次のとおりです。`k`はゼロから始まる連続した範囲を形成するため、最初に失敗した値は答えより 1 大きくなります。 のために`m = 100000`ただし、答えはそのあたりにあります`30102`したがって、1 つのテスト ケースには約`30103`候補者のチェック。 と`10^5`そのような場合、つまり`3,010,300,000`ますます大きくなる整数を操作するコストを考慮する前に、チェックを実行します。 これは 1 秒の制限がサポートできる範囲をはるかに超えています。 

有益な観察は、不等式には 2 と 10 のべき乗が含まれているため、対数は両方の指数を即座に削除するということです。 から始まる`10^k <= 2^m - 1`、

 両辺が整数なので、`10^k < 2^m`。 

10 を底とする対数を取ると、次のようになります。`k < m * log10(2)`。 

厳密に以下の最大整数`m * log10(2)`この値自体が整数ではない場合、その下限です。 正の整数は使用できません`m`。 もし`m * log10(2) = r`、 それから`2^m = 10^r`、 しかし`10^r`の係数が含まれています`5`その間`2^m`しません、それは不可能です。 

したがって、答えは非常に単純な形になります`answer = floor(m * log10(2))`。 

これにより、問題は、テスト ケースごとに潜在的に数万回の反復が必要となる問題から、1 つの浮動小数点乗算と 1 つのフロア演算に変更されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | 1 件あたり O(m) | お(1) | 遅すぎる |
 | 最適 | ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 番号を読み取ります`m`現在のテストケースの場合。 使用可能な最大 10 進累乗はマシンのビット幅に直接依存するため、必要な値はこの 1 つだけです。 
2. コンピューティング`m * log10(2)`。 これは、10 を底とする対数をとることによって得られる実数値の境界です。`2^m`。 
3. その値の下限値を取得します。 以来`m * log10(2)`正の整数は指定できません`m`、これはまさに最大の整数です`k`満足のいく`k < m * log10(2)`。 
4. 必要なコマンドを使用して結果を印刷します。`Case #x: y`形式。 

なぜそれが機能するのかは、等価な条件の連鎖として表現できます。 の値`k`はまさに次の場合に有効です`10^k <= 2^m - 1`。 両方の量が整数であるため、これは次と同等です。`10^k < 2^m`。 対数を取ると次のようになります`k < m log10(2)`。 この不等式を満たす最大の整数は次のとおりです。`floor(m log10(2))`。 コードはその量を正確に計算するため、出力されるすべての答えは最大かつ有効です。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

LOG10_2 = math.log10(2.0)

def solve():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        m = int(input())
        ans = int(m * LOG10_2)
        out.append(f"Case #{case}: {ans}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

`LOG10_2`は、テスト ケースごとに 1 回ではなく、1 回計算されます。 すべてのテスト ケースでは、乗算と整数変換が 1 つだけ実行されます。これは、アルゴリズムによる定数時間の式です。 

変換`int(m * LOG10_2)`値が正であるため、ここで必要なフロアを実行します。 パイソンの`int`ゼロに向かって切り捨てられます。これは、正の数の下位を取ることと同じです。 

の`2^m - 1`境界を明示的に構築する必要はありません`2^m`または`10^k`。 対数導関数はすでにその境界を処理しています。 Python の整数にも任意の精度がありますが、巨大な整数の構築を避けることで、実装がより簡単かつ高速になります。 

与えられた制約に対して`m <= 100000`、最大の結果は約`30102`。 倍精度は、この範囲に必要な精度よりもはるかに高い精度を持ちます。`m * log10(2)`は正の整数の整数ではありません`m`したがって、フロア演算を混乱させる正確な整数の対数境界はありません。 

公式サンプルには、`m = 1`生産する`0`そして`m = 64`生産する`19`、式と一致します。 

## 実用的な例

 最初のサンプルでは、`m = 1`。 

| メートル |`m * log10(2)`| 床 | 答え |
 | --- | --- | --- | --- |
 | 1 | 約`0.3010`| 0 | 0 |

 マシンが表現できる最大値は次のとおりです。`2^1 - 1 = 1`。 若者が使えるのは`1 = 10^0`が使えません。`10 = 10^1`、 それで`k = 0`は正しいです。 

2 番目のサンプルについては、`m = 64`。 

| メートル |`m * log10(2)`| 床 | 答え |
 | --- | --- | --- | --- |
 | 64 | 約`19.2659`| 19 | 19 |

 ここで、マシンは次の値をサポートします。`2^64 - 1`より大きい`10^19`ただし未満`10^20`。 したがって、からの全範囲は、`1`を通して`10^19`範囲内でフィットしますが、`10^20`しません。 結果は`19`。

## テストケース```python
import sys
import io
import math

LOG10_2 = math.log10(2.0)

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []

    for case in range(1, t + 1):
        m = int(input())
        ans = int(m * LOG10_2)
        out.append(f"Case #{case}: {ans}")

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided sample
assert run("2\n1\n64\n") == (
    "Case #1: 0\n"
    "Case #2: 19"
), "provided sample"

# Minimum input
assert run("1\n1\n") == "Case #1: 0", "m = 1"

# Boundary where 10^3 first becomes possible
assert run("2\n9\n10\n") == (
    "Case #1: 2\n"
    "Case #2: 3"
), "boundary around k = 3"

# Several equal values, checking case numbering as well
assert run("4\n10\n10\n10\n10\n") == (
    "Case #1: 3\n"
    "Case #2: 3\n"
    "Case #3: 3\n"
    "Case #4: 3"
), "repeated values"

# Maximum allowed m
assert run("1\n100000\n") == "Case #1: 30102", "maximum m"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1\n1\n`|`Case #1: 0`| 最小`m`そして`2^m - 1`境界 |
 |`2\n9\n10\n`|`Case #1: 2`、`Case #2: 3`| オフバイワントランジション`1000`表現可能になる |
 |`4\n10\n10\n10\n`| 4 つのケースと答え`3`| 繰り返し入力と正しいケース番号付け |
 |`1\n100000\n`|`Case #1: 30102`| 最大制約と大きな対数結果 |

 ## 特殊なケース

 のために`m = 1`、式は次のようになります`floor(log10(2)) = 0`。 アルゴリズムは決して構築しようとしません`10^1`, したがって、当然、可能な限り小さなマシンを処理します。 正確な入力は次のとおりです`1`、出力は次のようになります`Case #1: 0`。 

周囲の変遷`m = 10`最も可能性の高い off-by-one エラーをキャッチします。 のために`m = 9`、マシンの最大値は次のとおりです。`511`、 それで`100`フィットしますが、`1000`しません、与えます`2`。 のために`m = 10`、最大値は`1023`、 それで`1000`適合すると答えは`3`。 対数値はおよそ`2.7093`そして`3.0103`、まさにそれらのフロアを生成します。 

繰り返される値の場合 (たとえば、すべてに次の内容が含まれる 4 つのテスト ケース)`10`、すべての答えは次のようになります。`3`、しかし、症例数はさらに増加するはずです`1`を通して`4`。 各入力行は独立して処理され、ケース カウンタは反復ごとにインクリメントされるため、実装では両方のプロパティが保持されます。 

最大入力の場合`m = 100000`、式は次のようになります`floor(100000 * log10(2)) = 30102`。 アルゴリズムが構築されない`2^100000`これは大きな整数であり、30,000 個の 10 の累乗候補を反復処理しません。 の場合と同じ定数時間の計算を実行します。`m = 1`これが、ソリューションが全入力範囲に対応する主な理由です。
