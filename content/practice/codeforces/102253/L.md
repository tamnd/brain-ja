 ## 解決策
 ## 問題の理解

 すべての位置 (i) について、ペア ((l_i,r_i)) は、(p_i) が最小となる (i) を含む最大の連続区間を表します。 同様に、(p_i) は、(l_i) と (i-1) の間のすべての要素、(i+1) と (r_i) の間のすべての要素よりも小さく、間隔をどちらの方向にも 1 つずつ拡張することはできません。 

タスクは、これらの最小間隔を正確に持つ (1,\ldots,n) の順列が何個あるかを数えることです。 答えはモジュロ (10^9+7) で求められます。 公式の編集では、入力が有効な場合、結果の構造は一意のデカルト ツリーとして識別されます。 

制約が十分に大きいため、アルゴリズムは本質的に線形でなければなりません。 テスト ケースには (10^6) 個の位置を含めることができ、すべてのテスト ケースには最大で (3\cdot10^6) 個の位置が含まれます。 (O(n\log n)) ソリューションは、特に Python ではすでに必要以上に高価ですが、二次関数は完全に除外されています。 100 万個の整数からなる通常の Python リストはそれぞれ数十メガバイトを消費するため、128 MB というメモリ制限も重要です。 以下の実装では、Python のオブジェクトを多く含むリストと比較ソートではなく、コンパクトな整数配列とカウント ソートを使用します。 

不注意な実装が失敗する可能性はいくつかあります。 (n=1) の場合、可能な入力は次のとおりです。```
1
1
1
```答えは(1)です。 空の子間隔を無効として扱うと、唯一の有効なツリーが誤って拒否されます。 

重複または互換性のない間隔も拒否する必要があります。 例えば、```
3
1 1 1
3 3 3
```3 つの位置すべてに同じ間隔 ([1,3]) が与えられます。 これらの位置の 1 つをルートとして単純に選択する単純な実装は、あたかもツリーが有効であるかのように続行する可能性がありますが、3 つの位置すべてが同じ最大最小間隔を持つ方法はありません。 正しい出力は次のとおりです`Case #1: 0`。 

インターバルをまたぐこともよくある失敗です。 考慮する```
3
1 1 2
2 3 3
```これにより、([1,2])、([1,3])、([2,3]) が得られます。 間隔は、一方が他方を包含することなく重なり合います。 このような構成はデカルト ツリーから得られるものではないため、答えは次のようになります。`Case #1: 0`。 すべての (l_i\le i\le r_i) がそれを誤って受け入れるかどうかだけをチェックするソリューション。 

## アプローチ

 ブルートフォース ソリューションでは、(1,\ldots,n) のすべての順列を列挙し、すべての位置の最大最小間隔を計算し、結果を入力と比較できます。 (n!) 個の順列があります。 線形時間単調スタック手順を使用して各順列に対して最も近い小さい要素をすべて計算する場合でも、すべての順列をチェックするにはすでに (\Theta(n\cdot n!)) の演算が必要になります。 関連するすべての間隔を単純に直接スキャンすると、コスト (\Theta(n^2\cdot n!)) がかかります。 これは、実際の制約 (10^6) よりずっと前に、(n=10) あたりでも絶望的になります。 

有益な観察は、与えられた間隔が任意ではないということです。 順列については、その最小デカルト ツリーを考慮してください。 ルートは最小値を含む位置であり、その左側のサブツリーにはルートの左側の位置が含まれ、右側のサブツリーには右側の位置が含まれます。 すべてのノード (u) について、そのサブツリー内の位置は 1 つの連続した区間 (正確には ([l_u,r_u])) を形成します。 これは、公式ソリューションで使用されているのと同じ再帰構造です。 

いくつかのサブツリーが ([L,R]) を占め、そのルートが位置 (u) にあると仮定します。 次に、その左の子は正確に ([L,u-1]) を表す必要があり、その右の子は正確に ([u+1,R]) を表す必要があります。 したがって、どの入力間隔が現在必要な間隔に等しいかを繰り返し尋ねることによって、ツリー全体を再構築できます。 

これにより、直接カウントの公式も得られます。 (s(u)) を (u) をルートとするサブツリーのサイズとする。 サブツリーは正確に ([l_u,r_u]) であるため、

 [
 s(u)=r_u-l_u+1。 
】

 固定デカルト ツリーの場合、最小値をそのルートに割り当てる必要があります。 残りの値は、左と右のサブツリーに分割されます。 サイズが (a) と (b) の場合、

 [
 \binom{a+b}{a}
 】

 左側のサブツリーに属する値を選択する方法。 これを再帰的に乗算すると、

 [
 f(u)=\binom{s(v_L)+s(v_R)}{s(v_L)}f(v_L)f(v_R)。 
】

 階乗を展開すると、完全な積が次のように単純化されることがわかります。 

\frac{n!}{\prod_{i=1}^{n}(r_i-l_i+1)}。 
】

 公式社説では、まさにこれと同等の形式が示されています。 

残りの課題は、ルート間隔を効率的に見つけることです。 すべての間隔を増加 (l) で並べ替え、等しい (l) の場合は減少 (r) で並べ替えると、それらの順序はデカルト ツリーの事前順序になります。 どちらの座標も最大 (n) であるため、このソートは 2 つの安定したカウントソート パスで実行でき、(O(n\log n)) ではなく線形時間が得られます。 公式社説も同様に、再帰的分解の前に区間を基数ソートすることを推奨しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (\Theta(n\cdot n!)) 線形検証あり | (O(n)) | 遅すぎる |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 配列 (l) と (r) を読み取り、それらをコンパクトな整数配列に保ちます。 すべての位置 (i) について、([l_i,r_i]) をノード (i) の要求されたサブツリー間隔とみなします。 
2. (l_i) 昇順と (r_i) 降順で位置を並べ替えます。 安定したカウンティング ソートを 2 回使用します。最初は (n-r_i)、次に (l_i) です。 最初のパスでは、等しい (l_i) グループ内で減少する (r_i) が生成され、2 番目のパスではその順序が維持されます。 
3. 必要な間隔 ([1,n]) から開始します。 並べ替えられた事前順序の最初の間隔は、まさにこの間隔でなければなりません。 そうでない場合、入力はデカルト ツリーを記述することができないため、答えはゼロになります。 
4. 現在の間隔が ([L,R]) で、そのルートが位置 (u) にある場合、ルートの入力間隔が正確に ([L,R]) である必要があります。 この場合、可能な子のみが ([L,u-1]) と ([u+1,R]) を占めます。 最初に右の間隔をスタックにプッシュし、次に左の間隔をスタックにプッシュして、次に左のサブツリーが処理されるようにします。 空ではないすべてのサブツリーは、そのサイズ (R-L+1) を分母に与えます。 
5. 空ではない必要な間隔がすべて消費された後、すべて (n) の入力間隔も消費されたときにデータが有効になります。 (n!) モジュロ (10^9+7) を計算し、すべてのサブツリー サイズのモジュラー逆数を乗算して、次の結果を取得します。 

n!\prod_{i=1}^{n}(r_i-l_i+1)^{-1}
 \pmod {10^9+7}。 
]

 (1) から (10^6) までのすべての値の逆数は、次の関数を使用して 1 回事前計算されます。 

-\左\lfloor\frac{MOD}{i}\右\r床
 \オペレーター名{inv}(MOD\bmod i)
 \pmod {MOD}。 
]

 ### なぜ効果があるのか

 有効な順列では、その最小デカルト ツリーにはノードごとに 1 つのサブツリー間隔があり、そのサブツリー間隔は ([l_i,r_i]) です。 サブツリー ([L,R]) では、そのルート (u) が位置を必須の左区間 ([L,u-1]) と右区間 ([u+1,R]) に分割します。 したがって、すべての有効なツリーは、アルゴリズムによって実行されるすべての間隔チェックに合格する必要があります。 

逆に、必要なすべての間隔が正しい再帰順序で見つかった場合は、その順序トラバーサルが (1,2,\ldots,n) であるバイナリ ツリーが定義され、すべてのノードのサブツリーがその指定された間隔とまったく同じになります。 この最小ヒープ ツリーに沿って値を徐々に割り当てていくと、必要なデカルト ツリー構造が正確に生成されます。 順列には個別の値が含まれるため、有効な順列はすべて、そのようなラベル付けの 1 つに正確に対応します。 

固定ツリーの場合、再帰的インターリーブ数は上記の二項係数の積です。 各ノードは 1 つのサブツリー サイズの分母に寄与するため、すべての内部階乗はキャンセルされて残ります (n!/\prod s(u))。 (s(u)=r_u-l_u+1) であるため、アルゴリズムで使用される式は、有効な順列をすべて 1 回だけカウントします。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

MOD = 1000000007
MAX_N = 1000000

# Modular inverses for every possible subtree size.
inv = array('I', [0]) * (MAX_N + 1)
inv[1] = 1
for i in range(2, MAX_N + 1):
    inv[i] = MOD - (MOD // i) * inv[MOD % i] % MOD

def radix_order(l, r, n):
    """
    Return indices sorted by:
        l[index] ascending
        r[index] descending
    using two stable counting-sort passes.
    """
    order = array('i', range(n))
    tmp = array('i', [0]) * n

    # First pass: r descending, encoded as n - r.
    cnt = array('i', [0]) * (n + 1)

    for idx in order:
        cnt[n - r[idx]] += 1

    pos = 0
    for key in range(n + 1):
        c = cnt[key]
        cnt[key] = pos
        pos += c

    for idx in order:
        key = n - r[idx]
        p = cnt[key]
        tmp[p] = idx
        cnt[key] = p + 1

    # Second pass: l ascending.
    cnt = array('i', [0]) * (n + 1)

    for idx in tmp:
        cnt[l[idx]] += 1

    pos = 0
    for key in range(n + 1):
        c = cnt[key]
        cnt[key] = pos
        pos += c

    for idx in tmp:
        key = l[idx]
        p = cnt[key]
        order[p] = idx
        cnt[key] = p + 1

    return order

def solve_case(n, l, r):
    order = radix_order(l, r, n)

    # Each item is an expected subtree interval [L, R].
    # We process them in preorder.
    stack_l = [1]
    stack_r = [n]

    ptr = 0
    denominator = 1

    while stack_l:
        L = stack_l.pop()
        R = stack_r.pop()

        if L > R:
            continue

        if ptr >= n:
            return 0

        u = order[ptr]
        ptr += 1

        # The next preorder node must represent exactly [L, R].
        if l[u] != L or r[u] != R or not (L <= u <= R):
            return 0

        size = R - L + 1
        denominator = denominator * size % MOD

        # Push right first so that left is processed first.
        if u + 1 <= R:
            stack_l.append(u + 1)
            stack_r.append(R)

        if L <= u - 1:
            stack_l.append(L)
            stack_r.append(u - 1)

    # Every supplied interval must belong to the constructed tree.
    if ptr != n:
        return 0

    factorial = 1
    for x in range(2, n + 1):
        factorial = factorial * x % MOD

    return factorial * pow(denominator, MOD - 2, MOD) % MOD

def solve():
    case_no = 1
    output = []

    while True:
        line = input()
        if not line:
            break
        if not line.strip():
            continue

        n = int(line)

        l = array('i', map(int, input().split()))
        r = array('i', map(int, input().split()))

        ans = solve_case(n, l, r)
        output.append(f"Case #{case_no}: {ans}")
        case_no += 1

    sys.stdout.write("\n".join(output))

if __name__ == "__main__":
    solve()
```すべてのサブツリーのサイズは (1) と (n)、および (n\le10^6) の間にあるため、逆テーブルは 1 回作成されます。 再帰により、すべてのノードに対するべき乗剰余演算の実行が回避されます。 シングル`pow`実装では引き続き最終分母として使用されますが、乗算によって等価的に置き換えることもできます。`inv[size]`検証中にすべてのノードに対して。 後者は最後のべき乗を回避し、式との一貫性がわずかに高まります。 

2 つの配列 (l) と (r) は次を使用します。`array('i')`Python リストではなく。 Python 整数はかなりのオーバーヘッドを持つオブジェクトですが、すべての座標は最大 (10^6) であるため、32 ビット整数で十分です。 並べ替えバッファとカウント配列は、同じ理由で同じ表現を使用します。 

基数ソートでは、(n-r_i) が最初のキーとして使用されます。 昇順にカウントすることは、降順にソート(r_i)することと同じです。 2 番目のパスは (l_i) 昇順で並べ替えられ、安定しているため、等しい (l_i) 値は降順 (r_i) を保持します。 

再帰的なツリー分解は、明示的なスタックを使用して実装されます。 再帰的な Python 実装は、完全に歪んだデカルト ツリーの深さ (10^6) に達する可能性があり、再帰制限をオーバーフローします。 スタックにより、関数呼び出しのオーバーヘッドも回避されます。 

条件`l[u] != L or r[u] != R`コアの有効性チェックです。 ノードは、その境界がその指定された境界と正確に一致するサブツリーのルートのみにすることができます。 小切手`L <= u <= R`は元の入力制約によって暗示されますが、これを維持するとツリーの不変性が明示的になり、入力検証の前提が変更された場合にルーチンが保護されます。 

分母には​​、子のサイズではなく、サブツリーのサイズが含まれます。 たとえば、5 つの位置をカバーするルートは、その子のサイズが 1 と 3 であっても、(5) に寄与します。 これは、簡略化された (n!/\prod s(u)) 式に現れる量です。

## テストケース

 次のテストは次のことを前提としています。`solve()`上記のソリューションの関数。 ヘルパーは一時的にグローバルを置き換えます`input`関数を使用すると、同じソルバーをメモリ内の入力ストリームで実行できるようになります。```python
import sys
import io

# The solve() function and global input from the submitted solution
# are assumed to be available here.

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    try:
        sys.stdin = io.StringIO(inp)
        input = sys.stdin.readline
        solve()
        # solve() writes to stdout, so capture it through a second redirection.
    finally:
        sys.stdin = old_stdin
        input = old_input

def run_capture(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_stdout = sys.stdout
    old_input = input

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        input = sys.stdin.readline

        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout
        input = old_input

# Provided samples.
sample = """\
3
1 1 3
1 3 3
5
1 2 2 4 5
5 2 5 5 5
"""
assert run_capture(sample) == (
    "Case #1: 2\n"
    "Case #2: 3\n"
), "provided samples"

# Minimum size.
assert run_capture(
    "1\n"
    "1\n"
    "1\n"
) == "Case #1: 1\n", "single element"

# A valid two-element increasing Cartesian tree.
assert run_capture(
    "2\n"
    "1 2\n"
    "2 2\n"
) == "Case #1: 1\n", "two-element boundary case"

# All intervals are identical. No valid Cartesian tree exists.

# Crossing intervals. They cannot be nested as Cartesian-tree subtrees.
assert run_capture(

    "2 3 3\n"

# Maximum-size test. Every interval is a singleton, which is invalid

n = 1_000_000
l = " ".join(map(str, range(1, n + 1)))
r = l
maximum_case = f"{n}\n{l}\n{r}\n"

 ## 特殊なケース

 単一要素の場合```
1
1
1
```ソートされた順序には 1 つの間隔が含まれており、最初に必要な間隔も ([1,1]) です。 ノードのサブツリー サイズは (1) なので、分母は (1)、階乗は (1)、結果は (1) になります。 左または右の子はスタックにプッシュされません。 

すべて等間隔の場合```
3
1 1 1
3 3 3
```最初にソートされた間隔は ([1,3]) であるため、アルゴリズムは最初に 3 つのノードの 1 つを候補ルートとして受け入れます。 たとえば、そのノードが位置 (1) にある場合、次に必要な間隔は ([2,3]) ですが、次にソートされた入力間隔は依然として ([1,3]) です。 正確な間隔の比較は失敗し、答えはゼロになります。 同じ矛盾が他の候補ルートにも現れます。 

クロスケースの場合```
3
1 1 2
2 3 3
```ソートされた間隔は ([1,2])、([1,3])、([2,3]) です。 完全な配列のルートは ([1,3]) をカバーする必要がありますが、最初にソートされた間隔は ([1,2]) です。 アルゴリズムは入力を即座に拒否します。 これにより、カウントが実行される前に無効なオーバーラップが捕捉されます。 

2 要素境界の場合```
2
1 2
2 2
```ルート区間は ([1,2]) で、位置 (1) に属します。 その右側の子はシングルトン間隔 ([2,2]) です。 サブツリーのサイズは (2) と (1) です。 

[
 \frac{2!}{2\cdot1}=1。 
】

 唯一の有効な順列は増加であるため、境界チェックと子区間の構築は両方とも組み合わせカウントと一致します。 

(l_i=r_i=i) の最大サイズの入力の場合、最初の間隔は ([1,1]) ですが、配列全体にはルート カバー ([1,10^6]) が必要です。 最初の不一致に達した後、アルゴリズムはインスタンスを拒否しますが、基数ソートはまだすべての (10^6) 間隔を処理しています。 合計作業量は線形のままであり、再帰呼び出しが Python スタックをオーバーフローすることはありません。
