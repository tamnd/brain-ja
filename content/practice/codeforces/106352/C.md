 ## 解決策
 ## 問題の理解

 私たちは金庫の列に配置された一連の番号を与えられます。 各金庫には整数のラベルが付けられており、そのラベルはその素数によってのみ重要になります。 あらゆるクエリセグメントに対して$[l, r]$、単一の整数を構築する必要があります$d \ge 2$そのセグメント内のすべての金庫を開けることができるようになります。 金庫が開けられるのは、$d$まさにいつ$d$金庫の番号と共通の素因数を共有していないため、すべての$a_i$必要なセグメントで$\gcd(d, a_i) = 1$。 

タスクは有効なものを構築することではありません$d$ただし、クエリごとに可能な限り最小のものを見つける必要があります。 

この制約により、クエリごとに何も最初から再計算できないという解決策が求められます。 まで$2 \cdot 10^5$要素とクエリの場合、クエリごとの因数分解または配列のスキャンは、線形または線形に近いバジェットをすぐに超えてしまいます。 配列とクエリの数の両方が大まかに強制するには十分な大きさであるため、クエリごとに素数セットを再計算したり、候補を 1 つずつテストしたりするようなことは、最悪の場合非常に遅くなります。$10^{10}$単純なセットアップでのスケール操作。 

セグメントに小さな素数が多数含まれているものの、わずかに大きな素数が欠けている場合、微妙なエッジ ケースが発生します。 たとえば、セグメントに 2、3、5、7 で割り切れる数字が含まれているが、11 では割り切れない場合、9 や 25 などのより小さい合成数字がすべて存在しても、正解は 11 になります。 整数を順番に試してセグメントに対して gcd をチェックする単純な試みは失敗します。セグメント全体に対して各候補をチェックするのはコストが高すぎるためです。 

もう 1 つの落とし穴は、配列内のどこかに現れるすべての素数を避ける必要があると仮定していることです。 答えはセグメントのみに依存するため、これは不正解です。 素数はグローバルに出現しても、特定のクエリ範囲には存在しない場合があり、その場合、それがそのクエリに対する最適な答えになります。 

## アプローチ

 直接的なアプローチでは、各クエリを独立して処理します。 セグメントの場合$[l, r]$、すべての素因数をすべて集めることができます$a_i$そのセグメントで、素因数がこのセットを回避する整数が見つかるまで、2 から始まる整数をテストします。 これは正しいですが、各クエリが最大の影響を受ける可能性があるため、遅すぎます。$O(n)$値があり、各値には因数分解が必要です。 素早い因数分解でもこれを繰り返すと$2 \cdot 10^5$クエリは実行不可能です。 

重要な構造的観察は、数値が有効であるのは、そのすべての素因数がセグメント内に存在する素因数の結合を回避する場合に限り有効であるということです。 これにより、セグメント内でどの素数が「アクティブ」であるかを追跡するという問題が軽減されます。 任意の整数について推論する代わりに、素数について推論するだけで済みます。これは、合成候補は値の点でその最小の素因数よりも悪いためです。 

したがって、セグメントの答えは、そのセグメント内のどの数値も割り切れない最小の素数にすぎません。 

これにより、問題はダイナミック レンジ問題に変換されます。つまり、現在のセグメントに出現する素数のセットを維持し、そこに存在しない最小の素数を繰り返し求めます。 これは古典的な「グローバル最小クエリを使用してスライディング ウィンドウ全体で周波数を維持する」設定で、素数に対するセグメント ツリーと組み合わせた Mo のアルゴリズムに適合します。 

配列内の最大値までのすべての素数を事前計算し、ソートされた順序で各素数にインデックスを割り当て、アクティブなセグメントに現在素数が存在するかどうかを示す頻度カウンターを維持します。 素数上のセグメント ツリーには、素数の間隔ごとに、頻度が 0 である最小の素数が格納されます。 Mo ウィンドウを移動するときにトグル プライムを更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(q \cdot n \cdot \sqrt{A})$|$O(1)$番外編 | 遅すぎる |
 | Mo + 素数ツリー |$O((n+q)\sqrt{n} \log P)$|$O(n + P)$| 承認済み |

 ここ$P$最大値までの素数の数です$a_i$。 

## アルゴリズムのチュートリアル

 私たちは連携する 2 つの構造に依存しています。つまり、各数値を個別の素因数に分解する構造と、アクティブなクエリ セグメントに現在どの素数が存在するかを追跡する動的データ構造です。 

### 1. 最小の素因数を事前計算する

 まず、すべての数値をふるいにかけます。$10^7$各整数の最小の素因数を取得します。 これにより、任意の因数分解が可能になります$a_i$異なる素数の数にわたって線形時間で迅速に処理されます。 

### 2. 各位置の素数集合を抽出する

 あらゆるインデックスに対して$i$、因数分解します$a_i$SPF 配列を使用し、異なる素約数のみを保存します。 セグメント内の存在はバイナリであるため、プライムの繰り返しは無関係です。 

### 3. 素数のグローバルリストを作成する

 すべての素数を最大値まで列挙し、昇順にインデックスを割り当てます。 答えは利用可能な最小の素数に依存するため、この順序付けは非常に重要です。 

### 4. 素数に対するセグメント ツリーを初期化する

 各葉は素数に対応します。 現在アクティブなセグメントにプライムが存在しない場合、そのリーフにはその値が格納されます。 それ以外の場合は無限大を格納します。 内部ノードはその子の最小値を格納するため、ルートは常に最小の欠落素数を与えます。 

### 5. Mo の順序付けを使用してクエリを処理する

 クエリを Mo 順に並べ替え、スライディング ウィンドウを維持します$[L, R]$。 境界を移動すると、位置を追加または削除し、それに応じて素数周波数を更新します。 

### 6. 頻度構造を更新する

 位置が追加されると、そのすべての素因数が$a_i$カウントが増えます。 プライムが 0 から 1 に遷移すると、そのプライムはアクティブになり、セグメント ツリーで使用可能から削除されます。 削除したときにカウントが 0 に戻ると、再び使用できるようになります。 

### 7. 各質問に答えます

 クエリに一致するようにウィンドウを調整した後の答えは、単純にセグメント ツリー ルートに格納されている最小値になります。 

### なぜ効果があるのか

 いつでも、セグメント ツリーは、現在の範囲に現れない素数のセットを正確に表します。 有効な整数はセグメント内に存在するすべての素数を避ける必要があるため、存在しないとマークされた素数のみで構成されなければなりません。 すべての合成数はその素因数の少なくとも 1 つより大きいため、このようなすべての整数の中で最小のものは常に利用可能な最小の素数になります。 したがって、セグメント ツリーのルートは最適な答えを直接エンコードします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10**7

spf = list(range(MAXV + 1))
for i in range(2, int(MAXV ** 0.5) + 1):
    if spf[i] == i:
        step = i
        start = i * i
        for j in range(start, MAXV + 1, step):
            if spf[j] == j:
                spf[j] = i

def factorize(x):
    res = []
    while x > 1:
        p = spf[x]
        res.append(p)
        while x % p == 0:
            x //= p
    return res

class SegTree:
    def __init__(self, vals):
        self.n = len(vals)
        self.INF = 10**18
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.data = [self.INF] * (2 * self.size)
        for i, v in enumerate(vals):
            self.data[self.size + i] = v
        for i in range(self.size - 1, 0, -1):
            self.data[i] = min(self.data[2 * i], self.data[2 * i + 1])

    def update(self, idx, val):
        i = self.size + idx
        self.data[i] = val
        i //= 2
        while i:
            self.data[i] = min(self.data[2 * i], self.data[2 * i + 1])
            i //= 2

    def query_min(self):
        return self.data[1]

def main():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    primes = set()
    fac = []
    for x in a:
        ps = factorize(x)
        fac.append(ps)
        primes.update(ps)

    primes = sorted(primes)
    idx = {p: i for i, p in enumerate(primes)}

    cnt = [0] * len(primes)
    base = primes[:]
    seg = SegTree(base)

    def add(i):
        for p in fac[i]:
            j = idx[p]
            cnt[j] += 1
            if cnt[j] == 1:
                seg.update(j, 10**18)

    def remove(i):
        for p in fac[i]:
            j = idx[p]
            cnt[j] -= 1
            if cnt[j] == 0:
                seg.update(j, primes[j])

    BLOCK = int(n ** 0.5)
    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append((l - 1, r - 1, i))

    queries.sort(key=lambda x: (x[0] // BLOCK, x[1]))

    ans = [0] * q
    curL, curR = 0, -1

    for l, r, i in queries:
        while curL > l:
            curL -= 1
            add(curL)
        while curR < r:
            curR += 1
            add(curR)
        while curL < l:
            remove(curL)
            curL += 1
        while curR > r:
            remove(curR)
            curR -= 1
        ans[i] = seg.query_min()

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    main()
```実装では、まず最小の素因数を構築して、高速な分解を可能にします。 配列の各要素は個別の素約数のセットに還元されます。共素性制約にとって重要なのはこれだけです。 Mo の順序付けにより、各要素が制限された回数だけ追加または削除されることが保証されますが、セグメント ツリーは現在利用できない素数に対するグローバル最小値を維持します。 

微妙な詳細は、セグメント ツリー内のアクティブな素数に「無限」を格納して、最小値に影響を与えないようにしますが、非アクティブな素数は実際の値を格納します。 この反転により、ルートは常に最小の有効な候補を表すことができます。

 ## 特殊なケース

 重要なエッジ ケースは、すべての小さな素数がセグメント内のどこかに出現する場合です。 たとえば、セグメントに素数 2、3、5、7 をカバーする数値が含まれている場合、答えは 11 にジャンプする必要があります。これらすべての素数がアクティブとしてマークされ、セグメント ツリーのルートが自然に次に使用可能な素数を返すため、アルゴリズムがこれを処理します。 

もう 1 つのケースは、セグメントが 12 のような単一の要素であり、素数 {2, 3} に寄与する場合です。 有効な最小の整数は 4 や 6 ではなく 5 です。これは、両方の整数に少なくとも 1 つの禁止された素数が含まれているためです。 2 と 3 は使用不可としてマークされているため、構造体は正しく 5 を返します。 

最後に、クエリ ウィンドウを移動した後にプライムが消えると、すぐに再び有効になります。 これは、Mo のアルゴリズムでカウンターを減分し、その値をセグメント ツリーに復元することで処理され、遷移中の正確性が保証されます。
