 ## 解決策
 ## 問題の理解

 インタラクティブ バージョンでは、慎重に選択した最大 3 つの指示を聞き、生き残ったヘビを観察することができます。 ハッキングされたバージョンでは、速度は入力ですでに指定されており、私たちの仕事は、最適な対話型ソリューションが出力する答えを再現することです。 

各スネークは、個別の整数位置から始まります。 その速度は次の 1 つです。`0`、`1`、 または`2`。 

1秒命令を出したら`L`、すべてのヘビはその速度に従って左に移動します。 その秒の間に、二匹のヘビが出会ったときは、どちらかが早く消えます。 速度は最高なので、`2`すべての位置は整数であり、1 秒間の移動中に距離が である隣接するヘビのみが存在します。`1`または`2`対話することができます。 

重要な質問は「速度はどれくらいか?」ではありません。 ハッキングされた入力にはすでにそれらが含まれているためです。 本当の問題は、最大 3 つのクエリを使用する何らかの戦略によって速度を一意に回復できるかどうかです。 そうでない場合は、印刷する必要があります`-1`。 

の合計`n`せいぜい`10^5`したがって、ヘビごとに一定量の作業のみを実行するソリューションは、簡単に十分に高速です。 二次関数はすべて除外されます。 

微妙な部分は、3 つのクエリの可能な限り最良のシーケンスを使用したとしても、速度を決定できない場合を正確に特徴づけます。 

ある位置に 3 つの連続したヘビがあるとします。`x, x+1, x+2`スピードとともに`[0, 1, 0]`または`[0, 2, 0]`。 中央のヘビは、2 匹の静止したヘビの間に閉じ込められているため、有用な実験では必ず死んでしまいます。 許可されたクエリから取得できるすべての観測値は速度に関して同一です`1`そしてスピード`2`。 この 2 つの世界は区別できないため、答えは次のようになります。`-1`。 これが唯一の障害です。 

## アプローチ

 ブルート フォースの考え方では、次の長さの考えられるすべてのクエリ文字列をモデル化します。`4n`、スネーク システムをシミュレートし、すべての速度割り当てによって固有のトランスクリプトが生成されるかどうかを尋ねます。 それは明らかに不可能です。 可能な命令の数は指数関数的に増加し、単一のシミュレーションでさえ自明ではありません。 

公式ソリューションでは、代わりに 3 つの固定クエリを設計します。`L`

`LR`

`R`注目すべき点は、これら 3 つのクエリでほぼすべてが明らかになることです。 

1秒後`L`、生き残ったすべてのヘビは次の時点で終了します。`a_i - s_i`。 

次にクエリを見てみましょう`LR`。 最初の1秒は全く同じです`L`、同じヘビが生き残るということです。 2番目の秒は、すべての生存者を独自の速度で右に移動させ、元の位置に戻します。 したがって、次の出力は、`LR`単に、生き残ったヘビの元の位置のセットです。`L`クエリ。 

間の生存者をマッチングする`L`そして`LR`最初のクエリで生き残ったすべてのヘビの速度がすぐに得られます。 

残ったヘビは、まさにその際に排除されたものです。`L`。 それらの速度は、局所的な位置ギャップから再構築できます。`R`クエリ。 あいまいな設定が 1 つだけ残っています: 速度のある 3 つの連続した位置`0, x, 0`、 どこ`x`どちらかも知れません`1`または`2`。 このようなパターンが存在する場合、正解は次のとおりです。`-1`。 それ以外の場合、すべての速度は一意に決定されます。

 ## アルゴリズムのチュートリアル

 1. クエリに対する回答をシミュレーションする`L`。 

結果として得られる生存者の位置を次のようにします。`vl`。 
2. クエリに対する回答をシミュレーションする`LR`。 

結果の位置を次のようにします`vlr`。 

あらゆるポジションで`vlr`生き残ったヘビの本来の位置です`L`。 
3. マッチ`vlr`元の位置配列に対して。 

位置の場合`a[i]`に登場する`vlr`、 蛇`i`生き残った`L`クエリ。 
4. すべての生存者のスピードを回復します。 

ヘビだと仮定します`i`生き残った`L`。 

その位置`vl`は`a[i] - s[i]`。 

したがって、`s[i] = a[i] - vl[j]`。 
5. 生き残れなかったヘビもいた`L`。 

未解決のヘビごとに`i > 0`、ギャップを調べます`d = a[i] - a[i-1]`。 

もし`d = 2`、または`d = 1`以前の速度がゼロでないことがすでにわかっている場合、ヘビ`i`スピードがなければなりません`2`。 

これらはまさにスピードが必要な状況です。`2`ヘビは左方向に移動中に死ぬことを余儀なくされます。 
6. クエリをシミュレートする`R`。 

生存者の位置を次のようにします`vr`。 

残りの未解決のスネークをすべて照合できるようになりました`vr`、その速度は`vr[pos] - a[i]`。 
7. 固有の不可能なパターンを確認します。 

単位ギャップのある連続する 3 つのポジションごとに、`a[i+1] - a[i] = 1`そして`a[i+2] - a[i+1] = 1`。 

再構築された速度が次のようになった場合`[0, nonzero, 0]`その場合、中間の値は区別できません`1`そして`2`。 

出力`-1`。 
8. それ以外の場合は、再構築されたすべての速度を出力します。 

### なぜ効果があるのか

 クエリ`L`どのヘビが左方向に動いても生き残るのかを識別します。 クエリ`LR`すべての生存者が開始位置に戻るため、その情報が元のインデックスに変換されます。 これら 2 つのクエリを組み合わせると、すべての生存者の速度が正確に決定されます。 

まだ知られていない唯一のヘビは、`L`。 ギャップの局所形状`1`そして`2`一部を強制的に速度にする`2`。 クエリ`R`残りのすべての値を決定します。 

社説は、最大 3 つのクエリのシーケンス後に根本的にあいまいなままになる唯一の構成は、速度を備えた連続するスネークのトリプルであることを証明しています。`0, x, 0`、 どこ`x`多分`1`または`2`。 このようなパターンが存在する場合、どの戦略も 2 つの可能性を区別できません。 他のすべての構成では、上記の 3 つの固定クエリによってすべての速度が一意に決定されます。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def simulate(a, s, direction):
    n = len(a)

    if direction == 'L':
        pos = [a[i] - s[i] for i in range(n)]
    else:
        pos = [a[i] + s[i] for i in range(n)]

    alive = [True] * n

    for i in range(n - 1):
        d = a[i + 1] - a[i]

        if direction == 'L':
            if s[i + 1] > s[i] and d <= s[i + 1] - s[i]:
                alive[i + 1] = False
        else:
            if s[i] > s[i + 1] and d <= s[i] - s[i + 1]:
                alive[i] = False

    res = []
    for i in range(n):
        if alive[i]:
            res.append(pos[i])
    return res

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        s = list(map(int, input().split()))

        vl = simulate(a, s, 'L')
        vlr = [a[i] for i in range(n) if simulate(a, s, 'L').count(a[i] - s[i]) > 0]

        alive_after_l = [True] * n
        p = 0
        for i in range(n):
            if p < len(vlr) and vlr[p] == a[i]:
                p += 1
            else:
                alive_after_l[i] = False

        vr = simulate(a, s, 'R')

        ans = [-1] * n

        j = 0
        k = len(vlr)
        for i, x in enumerate(a):
            if j < k and vlr[j] == x:
                ans[i] = x - vl[j]
                j += 1

        for i in range(1, n):
            if ans[i] == -1:
                d = a[i] - a[i - 1]
                if d == 2 or (d == 1 and ans[i - 1] != 0):
                    ans[i] = 2

        for i, x in enumerate(a):
            if ans[i] == -1:
                j = bisect_left(vr, x)
                ans[i] = vr[j] - x

        bad = False
        for i in range(n - 2):
            if (
                a[i + 1] - a[i] == 1
                and a[i + 2] - a[i + 1] == 1
                and ans[i] == 0
                and ans[i + 1] != 0
                and ans[i + 2] == 0
            ):
                bad = True

        if bad:
            print(-1)
        else:
            print(*ans)

if __name__ == "__main__":
    solve()
```実装は再構築引数に直接続きます。 

最初のフェーズでは、3 つの固定クエリから取得した情報をエミュレートします。 第 2 フェーズでは、生き残ったヘビの速度を補充します。`L`。 3 番目のフェーズでは、スピードが必要なヘビを解決します。`2`ローカルギャップ制約から。 まだ解決されていないヘビは、`R`クエリ。 

最終スキャンでは、唯一不可能な構成がチェックされます。 このチェックを怠ると、そのようなインスタンスは返さなければならないため、公式テストで間違った答えが生成されます。`-1`入力にすでに具体的な速度の割り当てが含まれている場合でも。
