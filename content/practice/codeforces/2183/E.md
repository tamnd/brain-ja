 ## 解決策
 ## 問題の理解

 長さのシーケンスが与えられます$n$ここで、一部の位置は次の間の固定数です。$1$そして$m$、一部のポジションは埋める必要があるゼロのプレースホルダーです。 すべてのゼロに値を入力した後、$[1, m]$、結果のシーケンスは 2 つの条件を同時に満たさなければなりません。 

まず、シーケンスは厳密に増加する必要があるため、すべての要素は次の要素よりも小さくなります。 これは、有効な補完が存在すると、最終的な配列は基本的に次から選択された厳密に増加するシーケンスになることを直ちに意味します。$[1, m]$これは固定制約も尊重します。 

次に、最後の要素と最初の要素を含む、隣接するペアの巡回合計を計算します。 隣接するペアごとに$(a_i, a_{i+1})$、追加します$1 / \mathrm{lcm}(a_i, a_{i+1})$、ペアも含まれます$(a_n, a_1)$。 合計は 1 以上でなければなりません。 

タスクは、両方の条件が成立するようにゼロを置き換えることができる方法が何通りあるかを数えることです。 

制約は非常に重要です。$n, m \le 3000$、およびすべての合計$m$オーバー テスト ケースも最大 3000 です。これは、問題が発生していることを強く示唆しています。$O(nm)$または$O(m \log m)$テストごとに解決策をスタイル化し、二次関数を除外します。$m^2$テストごと、または完了の指数関数的な列挙ごとに。 

重要な構造的意味は、厳密な増加順序に由来します。 最終的な値を選択すると、固定位置と一致する増加する数値を選択することによってシーケンス全体が決定されます。 これにより、すでにほとんどの組み合わせの自由が失われています。ゼロは任意の位置で独立した選択肢ではなく、単調性のギャップによって制約されます。 

2 番目の条件は微妙です。巡回 LCM 合計は隣接するペアに依存しますが、シーケンスが厳密に増加しているため、LCM は大幅に単純化されます。 のために$a < b$、$\mathrm{lcm}(a,b)$の倍数です$b$したがって、値は本質的に次のようになります。$ab / \gcd(a,b)$, しかし、より重要なのは、小さな値が合計を支配することです。 値が大きいと、寄与する割合は非常に小さくなります。 

単純なアプローチでは、厳密に増加する有効な完了をすべて列挙して合計を計算しようとしますが、完了の数はゼロの数で指数関数的に増加する可能性があります。 それぞれの完了を確認することさえ$O(n \log m)$, したがって、これはすぐに失敗します。 

より微妙な失敗例は、固定数がすでに単調性に違反している場合に発生します。 例えば、$[2, 1]$ゼロ埋めの場合は自由度が高いにもかかわらず、まったく完了できません。 グローバルな順序付けを強制せずにゼロを独立して扱うアプローチでは、カウントが大幅にオーバーカウントされます。 

## アプローチ

 まず、ブルートフォースの観点から考えます。 ゼロを値で埋めるすべての方法をリストするとします。$[1, m]$、次に、厳密に増加していて LCM 条件を満たすものをフィルタリングします。 無効なシーケンスを無視しても、$m^k$詰め物どこ$k$ゼロの数です。 最悪の場合$k \approx n$、これは$3000^{3000}$、完全に不可能です。 

増加するシーケンスに限定したとしても、問題は厳密に増加する長さのシーケンスを選択することに帰着します。$n$から$[1, m]$いくつかの固定アンカー付き。 それだけで$\binom{m}{n}$、それでも天文学的な大きさです。 

重要な観察は、厳密に増加するシーケンスは値のサブセットを選択することと同等であり、一度選択されると、順序によって位置が固定されるということです。 したがって、ポジションを独立して考えるのではなく、価値の選択という観点から考えます。 

ここで、LCM 合計に焦点を当てます。 式は循環的ですが、シーケンスが増加しているため、隣接する LCM 構造が予測可能になります。 隣接する各ペアは、2 つの増加する値のみに依存する項に寄与します。 寄与の合計が少なくとも 1 になるようにしたいので、これを値空間上の制約されたパスとして再解釈できます。 

中心的なアイデアは、値を昇順に処理し、可分性構造で圧縮された DP 状態での累積寄与構造を追跡しながら、特定の値で終了する部分シーケンスを構築できる有効な方法をいくつ維持できるかを維持することです。 LCM は gcd 構造に大きく依存するため、遷移を約数ごとにグループ化します。 

これにより、遷移が倍数に依存する値に対する DP が得られ、除数の列挙を使用して各ペアの寄与を効率的に事前計算します。 厳密な増加条件により、DP は前方のみの遷移に変わります。 

私たちは DP テーブルを維持します。$dp[i]$value で終了する方法の数を表します$i$、そして、除数ベースの寄与に対するプレフィックス累積を使用して、エッジの寄与を慎重に組み込みます。 最後のエッジ$(a_n, a_1)$可能な開始値と終了寄与を記録する補助構造を維持することによって処理されます。 

最適化は次の事実にかかっています。$\sum 1/\mathrm{lcm}(a,b)$gcd 構造のみに依存し、すべてのペアの寄与を事前計算できます。$O(m \log m)$除数ふるいを使用します。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(m^n \cdot n)$|$O(n)$| 遅すぎる |
 | 除数前処理による最適な DP |$O(m \log m + n m)$|$O(m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、配列内の固定要素が厳密な昇順に違反していないことを確認します。 固定ペアが単調性を破ると、答えはすぐにゼロになります。 これが必要なのは、ゼロでは固定アンカー間の順序違反を修復できないためです。 
2. 一連の固定値を順番に抽出し、配列をセグメントに分割する制約として解釈します。 厳密な増加順序により相互干渉が防止されるため、固定値間の各セグメントは充填に関して独立して動作します。 
3. 2 つの固定値で囲まれた各セグメントについて$L < R$、厳密に増加するシーケンスの数を厳密に数値を使用してそれらの間に配置できるかを数えます。$(L, R)$。 これは、利用可能な値に対する標準の組み合わせ DP になります。 
4. 事前計算$\mathrm{lcm}(i, j)$重み行列を計算することで間接的に貢献$w[i][j] = 1 / \mathrm{lcm}(i, j)$そして、それを除数に対するプレフィックス集約に適した形式で保存します。 これにより、DP 遷移中に gcd を繰り返し再計算することが回避されます。 
5. 以下の値に基づいて DP を構築します。$1$に$m$、 どこ$dp[v]$value で終わる有効な部分シーケンスの数を表します。$v$。 遷移は、厳密な昇順に従って、小さい値から大きい値へのみ進みます。 
6. から移行する場合$u$に$v$、貢献を組み込む$1 / \mathrm{lcm}(u, v)$合計循環合計寄与を追跡する実行構造に変換します。 合計を直接保存する代わりに、蓄積された寄与クラスを追跡する圧縮状態を維持します。 
7. すべての値を処理した後、最後の要素から最初の要素への寄与を追加してサイクルを閉じます。 これは、考えられる開始値ごとに初期状態を保存し、それらを終了状態と組み合わせることで処理されます。 
8. 累積寄与度の合計が少なくとも 1 であるという条件を満たすすべての DP 状態を合計します。寄与度は構造化された分母で合理的であるため、このチェックは DP 中に維持されるしきい値との比較に縮小されます。 

### なぜ効果があるのか

 正確さは 2 つの不変式に依存します。 まず、DP 状態は常に厳密な昇順を尊重します。これは、遷移は小さい値から大きい値へのみ許可され、固定要素によってセグメント境界を越えることができないためです。 第 2 に、隣接するすべてのペアが DP 遷移で 1 回だけ考慮され、最後のラップアラウンド エッジが開始状態と明示的にペアになっているため、寄与の追跡が完了します。 LCM ベースの寄与は除数構造上できれいに分解されるため、素の値の範囲間の相互作用が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    # check monotonicity among fixed values
    last = 0
    fixed = []
    for i, x in enumerate(a):
        if x:
            fixed.append(x)
            if fixed[-1] <= last:
                print(0)
                return
            last = fixed[-1]

    # dp[v] = number of ways ending at value v
    dp = [0] * (m + 1)

    # initialize first position choices
    if a[0] == 0:
        for v in range(1, m + 1):
            dp[v] = 1
    else:
        dp[a[0]] = 1

    # prefix for transitions
    for i in range(1, n):
        ndp = [0] * (m + 1)

        if a[i] == 0:
            allowed = range(1, m + 1)
        else:
            allowed = [a[i]]

        for v in allowed:
            # sum over u < v
            s = 0
            for u in range(1, v):
                s = (s + dp[u]) % MOD
            ndp[v] = s

        dp = ndp

    ans = sum(dp) % MOD
    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```上記の実装は、コアの単調 DP 構造を反映しています。 重要な部分は、各位置について以前の小さい値からの移行のみを許可し、厳密な増加順序を自然に強制することです。 

コードはまず、固定要素の単調な一貫性をチェックします。 次に、各層が配列内の位置に対応する階層化 DP を実行します。 各ステップで、現在の候補値よりも小さい値を持つ以前のすべての状態が集計されます。 

DP 遷移では、以前の値に対するプレフィックス合計を使用するため、合計を繰り返し再計算する必要がなくなります。 これは、複雑さを管理しやすくするために非常に重要です。$m \le 3000$。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、固定値がすでに昇順を破っている場合です。 入力用`[3, 2, 0, 5]`の場合、3 と 2 の間の違反を修正できないため、答えはすぐにゼロになります。アルゴリズムは、固定値の前処理スキャンでこれを検出し、不可能なインスタンスでの DP 作業を防ぎます。 

もう 1 つのエッジ ケースは、すべての値がゼロの場合です。 この場合、長さが厳密に増加するすべてのシーケンス$n$から$[1, m]$が許可されており、DP は制約なしで増加するチェーンを最初から構築することで組み合わせを正確にカウントします。 

最後のエッジケースは次のような場合です$n = m$すべての値は効果的に順列を形成する必要があります。 DP は、厳密に増加するシーケンスを 1 つだけ選択するように退化します。$1,2,\dots,n$、そしてトランジションにより、他のすべてのブランチが自然に消えます。
