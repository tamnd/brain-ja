 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、根を張った木です。`n`頂点、ルートが頂点になります`1`、最初はすべての頂点が白です。 距離`d_i`頂点の`i`ルートからルートまでのパス上のエッジの数です。`i`。 複数の白い頂点を同時に黒く着色する操作を実行できますが、選択する頂点は 2 つの制約を満たす必要があります。エッジによって直接接続されている 2 つの頂点はないこと、およびルートから同じ距離を共有している 2 つの頂点はないということです。 目標は、すべての頂点を黒にするためのこのような操作の最小数を見つけることです。 

入力は複数のテスト ケースで構成され、それぞれがツリー構造を提供します。 出力はテスト ケースごとに 1 つの整数、つまり必要な操作の最小数です。 

制約が非常に強力であるため、単純なアプローチを行うことはできません。`n`最大 200,000 まで可能で、すべてのテスト ケースの合計も 200,000 に制限されます。 これは、アルゴリズムがテスト ケースごとの頂点の数に対してほぼ直線的な時間で実行される必要があることを意味します。そうしないと、2 秒の制限を超えてしまいます。 二次関数やノードのすべてのサブセットの明示的な列挙を必要とするものは、直ちに除外されます。 

明らかではないエッジ ケースには、多くの頂点が同じ深さを共有している状況や、一部の頂点が同時カラーリングを制限するチェーンを形成している状況が含まれます。 たとえば、ルートに 4 つの子があり、孫が存在しない場合、すべての子は同じ深さにあるため、直接接続されている子はなくても、それぞれを個別の操作で色付けする必要があります。 すべての子供たちに一度に色を付けようとする不注意なアルゴリズムでは、不正確な答えが生成されてしまいます。 もう 1 つの微妙なシナリオはチェーンです。`1-2-3-4`。 頂点`2`そして`3`それらは隣接しており、距離が連続しているため、一緒に色を付けることはできません。そのため、操作を最小限に抑えるためにセットを慎重に選択する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、制約を満たす白い頂点の有効なサブセットをすべて生成し、カラーリングを適用し、すべての頂点が黒になるまで繰り返します。 これはルールに正確に従っているため、原理的には機能します。 ただし、`n`最大 200,000 までは、サブセットの数は指数関数的に増加し、どの頂点が色付きか、または色付けされていないかを追跡するだけでも遅すぎます。 

重要な洞察は、制約の構造から得られます。 同じ距離の 2 つの頂点を選択することはできないため、各操作で選択できる頂点は深さごとに最大 1 つです。 また、選択した 2 つの頂点を隣接させることはできません。 ツリーでは、同じ操作で親とその子を選択しなければ、隣接性制約が自動的に満たされます。 これは、最小操作数が頂点が深度間でどのように分散されるか、および子を持つ頂点の数に関連していることを示唆しています。 

操作スケジュールの観点から各頂点の「有効度」を考慮することで、これを形式化できます。ルートは 1 回の操作で色付けできますが、その子が同じ深さを共有する場合は、別の操作が必要になる可能性があります。 各頂点は、その深さの「負荷」に寄与します。 次に、問題は次のようになります。頂点ごとに、その子に必要な操作の数を追跡し、すべての深さにわたって最大値を取得します。 この最大値により、必要な操作の最小数が決まります。 

つまり、最小操作数は、隣接制約によって生じる重複を調整した後の同じ深さの子の最大数と等しくなります。 頂点ごとおよび深さごとに子の数を計算することで、単純な DFS を使用して最小限の操作を効率的に決定できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての有効なサブセット) | O(2^n) | O(n) | 遅すぎる |
 | 深さカウント + DFS | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 隣接リストを使用してツリーを構築します。 各頂点には、接続された頂点のリストが保存されます。 
2. ルートから開始して DFS を実行して距離を計算します`d_i`各頂点をルートから順に移動します。 
3. 配列を初期化する`cnt`どこ`cnt[v]`頂点の直接の子の数を数えます`v`。 リーフノードには、`cnt[v] = 0`。 
4. 各頂点について、各深さに存在する子の数を数えます。 必要に応じて、優先キューまたはこれらのカウントのマルチセットを維持します。 
5. ルートの場合、最小限の操作数は次のとおりです。`1 + sum over children`すべての子が同じ深さにあり、隣接していない場合。 より一般的には、最小操作数は次のとおりです。`max(cnt[v] + 1 for all vertices)`。 の`+1`頂点自体に色を付ける操作を説明します。 
6. この最大値を各テスト ケースの答えとして出力します。 

機能する理由: DFS は、各頂点の子を親の操作カウントに結合する前に処理することを保証します。 深さごとに子の数をカウントすることで、同じ深さの 2 つの頂点が同時に色付けされることがなくなります。 すべての頂点の最大値は、最悪の場合の負荷、つまり、隣接性と深さの制約の両方を尊重するために必要なボトルネック操作の数を表します。 この不変条件により正確さが保証されます。つまり、問題のルールに違反することなく、より少ない操作で頂点のセットを色付けすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque, defaultdict

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        tree = [[] for _ in range(n)]
        for _ in range(n-1):
            u, v = map(int, input().split())
            tree[u-1].append(v-1)
            tree[v-1].append(u-1)
        
        depth_count = defaultdict(int)
        visited = [False]*n
        q = deque()
        q.append((0, 0))
        visited[0] = True
        while q:
            node, depth = q.popleft()
            depth_count[depth] += 1
            for neighbor in tree[node]:
                if not visited[neighbor]:
                    visited[neighbor] = True
                    q.append((neighbor, depth + 1))
        
        print(max(depth_count.values()))

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に隣接リストを構築し、BFS を実行して各頂点の深さを計算し、深さごとにカウンターをインクリメントします。 深度間の最大数は、一緒に色を付けることができない同じ深度にある頂点の最大数を表すため、必要な操作の最小数を示します。 ここでは簡単にするために DFS の代わりに BFS を使用していますが、DFS も同様に機能します。
