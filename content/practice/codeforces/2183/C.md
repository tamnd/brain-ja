 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられた塩基が線形に配置されています。 私たちの本拠地は位置 k にあり、そこにちょうど 1 人の兵士がいる状態で開始します。 毎日、基地を選択し、そこから任意の数の兵士を左右に 1 位置ずつ移動させることができます。 この移動の後、本拠地に新兵が現れる。 タスクは、m 日後に少なくとも 1 人の兵士を配置できる基地の最大数を決定することです。 

入力は複数のテスト ケースを与え、それぞれが n、m、k を指定します。 出力は、テスト ケースごとに、強化された塩基の最大数を表す単一の整数です。 

制約により、テスト ケースごとに n は最大 10^5、m は最大 10^9 にできることが示唆されています。 すべてのテスト ケースの n の合計は 2·10^5 で制限されるため、基本配列全体を反復処理することは可能ですが、m が非常に大きくなる可能性があるため、毎日明示的にシミュレートすることは不可能です。 これにより、毎日のシミュレーションを試みるソリューションは即座に排除されます。 

mが一方の端までの距離より小さい場合に微妙な点が生じます。 たとえば、n = 5、k = 3、m = 1 の場合、本拠地と隣接する 1 つの基地の 2 つの基地のみを強化できます。 兵士がいつでも両端に到達できると想定する単純なアプローチは、これらのシナリオでは失敗します。 同様に、m が非常に大きい場合、最終的にはすべての拠点を強化できますが、n を超えないよう注意する必要があります。 

## アプローチ

 ブルートフォースのアプローチは簡単です。毎日、より多くの基地をカバーするために兵士の最適な移動をシミュレートします。 各基地の兵士を追跡し、移動先を決定することを m 回繰り返すことができます。 これは原理的には機能しますが、演算の数は O(n・m) 程度になり、m が 10^9 の場合はまったく現実的ではありません。 

重要な洞察は、基地を強化できる最速は、本塁からの距離によって決まるということです。 ホームベースの左側にあるベースには、`home - i`最初の兵士が到着するまでに数日、右側の基地には`i - home`日々。 最初の兵士が到着した後、毎日追加の兵士が本拠地に連れて行かれ、すぐに外に派遣されます。 

これにより、問題は単純な計算に帰着します。k から距離 d にある基地の場合、最も早く強化できるのはその後です。`d`日々。 その後毎日新しい兵士が追加されるため、強化できる追加拠点の最大数は k から外側に向かって 1 日あたり 1 つずつ増加します。 したがって、強化された基地の最大数の式は次のようになります。`min(n, m + 1)`。 この公式が機能するのは、常に最も近い非強化基地を選択して、毎日そこに兵士を派遣でき、最初の日にはすでに本拠地が数えられるからです。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n・m) | O(n) | 遅すぎる |
 | 距離ベースの貪欲 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケース t の数を読み取ります。 
2. 各テスト ケースについて、n、m、および k を読み取ります。 
3. 強化できる拠点の最大数を次のように計算します。`min(n, m + 1)`。 これが機能するのは、本拠地が 0 日目にすでに強化されており、毎日さらに 1 つの拠点を強化できるためです。 m が線の終端までの追加塩基の数を超える場合は、単純に n でキャップします。 
4. 各テスト ケースの計算値を出力します。 

**これが機能する理由:** 不変条件は、兵士が毎日本拠地から 1 つの新しい要塞化されていない基地に到達できるということです。 k から距離 d にある基地を強化できるのは、最も早くても d 日後です。新しい兵士が毎日家に現れるため、次に近い非強化基地を守るためにいつでも彼らを使用できます。 これにより、ソリューションが最適であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m, k = map(int, input().split())
    # maximum fortified bases is the smaller of n or m+1
    print(min(n, m + 1))
```コードは複数のテスト ケースを読み取り、計算します。`min(n, m + 1)`それぞれについて、結果を出力します。 追加のデータ構造は必要ありません。 式ではホームベースが自動的に考慮され、`min`総塩基数を超えることを防ぎます。

## テストケース```python
def run(inp: str) -> str:
    import sys, io
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        output.append(str(min(n, m + 1)))
    return "\n".join(output)

 ## 特殊なケース

 m=0の場合、nに関わらず本拠地のみを強化できます。 n に対して m が大きい場合、式は強化された塩基を n で自動的にキャップします。 本拠地がエンドポイントにある場合でも、最も近い拠点が最初に強化されるため、貪欲なアプローチでも最大の効果が得られます。 計算`min(n, m + 1)`は、明示的な分岐やシミュレーションを行わずに、これらすべてのシナリオを処理します。 

たとえば、入力`n=10, m=0, k=5`結果として出力が得られます`1`と入力してください`n=10, m=20, k=1`結果として`10`、両方の極端なケースの正しい処理を示しています。
