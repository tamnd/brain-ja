 ## 解決策
 ## 問題の理解

 私たちには番号が与えられています$k$、そして頂点の特別な順列の数がちょうど正確になるように、最大​​ 400 個の頂点でツリーを構築するように求められます。$k$。 

置換は、両方向の隣接性を維持する場合に有効であるとみなされます。 言い換えれば、2 つの頂点がツリー内のエッジによって接続されている場合、順列下のそれらの画像もエッジによって接続されている必要があり、その逆も同様です。 これはまさにグラフの自己同型の定義であるため、このタスクは自己同型カウントが正確に次のとおりであるツリーを構築するのと同等です。$k$。 

入力はこの整数のみで構成されます$k$、出力はツリーを記述するか、そのようなツリーが存在しないことを示す必要があります。 

制約$k \le 10^{18}$何も列挙したり、順列をシミュレートしようとしたりすることはできないことがすぐに示唆されます。 自己同型群が次のサイズの構造体を格納する場合でも$k$この大きさの値は、組み合わせ検索が到達できる範囲をはるかに超えて増大するため、乗法分解の観点から推論する必要があります。 

バウンド$n \le 400$それが本当の構造上の限界です。 これにより、構築が非常にコンパクトになるため、すべての頂点が自己同型カウントに有意義に寄与する必要があります。 これにより、任意の大きな対称ツリーを構築したり、エンコードを試みたりするような単純な試みが排除されます。$k$ディープエンコーディングを表現するのに十分なノードがないためです。 

対称性が任意に構成できると仮定すると、微妙な失敗例が発生します。 たとえば、2 つの同一のサブツリーを構築し、それらをルートの下に接続する場合、不注意な仮定により、それらの寄与が独立して扱われる可能性があります。 実際には、これらの同一のサブツリーを交換すると、追加の自己同型が作成され、カウントに同一のブランチの数の階乗が乗算されます。 この相互作用がこの問題の中心的な難しさです。 

## アプローチ

 強引なアイデアは、最大 400 ノードまでのすべてのツリーを生成し、その自己同型数を計算することです。 ツリーの数を無視しても、自己同型の計算自体にコストがかかります。 ラベルのないツリーの数は、次のように指数関数的に増加します。$n$そして、各候補について、対称性を数えるためにグラフ同型スタイルの問題を解く必要があります。 これはかなり前にすぐに実行不可能になります$n = 40$、ましてや$400$。 ボトルネックは列挙だけではなく、自己同型の本質的にグローバルな性質にあります。 

重要な洞察は、ツリーの自己同型は非常に構造化された乗法形式を持つということです。 ノードにルート サブツリーが同一の子が複数ある場合、それらの子は任意に並べ替えることができ、階乗因子に寄与します。 さらに、独立した対称コンポーネントは、グローバル構造内で相互に交換可能でない限り、相乗的に寄与します。 

これは、自己同型グループ サイズが小さな階乗寄与の積として構築されるツリーを構築したいことを意味します。 大きな因子の自然な源は星です。$d$同一の葉は正確に$d!$葉の順列が構造を保存するため、自己同型性が生じます。 

したがって、問題は分解に帰着します$k$階乗数の積に変換し、各階乗がスター コンポーネントによって実現されるツリーを構築します。 残りの問題は、これらのコンポーネント間で意図しない対称性が生じないようにすることです。 

コンポーネント間の交換を防ぐために、各コンポーネントを非対称バックボーン構造内の固有の位置に埋め込みます。 簡単な方法は、各接続点が構造的に一意になるようにコンポーネントをルート パスに沿って配置し、自己同型によるコンポーネントの交換を防ぐことです。

 ## アルゴリズムのチュートリアル

 ソリューションは 2 つの概念的な段階で構築されます。$k$階乗寄与に変換し、それらの寄与を意図しない対称性のないツリーに埋め込みます。 

### 因子分解

 1. 20 までの階乗を事前計算します。$20!$わずかに上にあります$10^{18}$したがって、階乗因数はこの範囲内にある必要があります。 
2. 可能な限り大きなものから始める$i$そして分割を繰り返す$k$による$i!$割り切れるときはいつでも。 
3. それぞれが選んだ$i$スターコンポーネントに対応します$i$全く同じ葉であり、正確に寄与します$i!$自己同型性。 
4. まで続けます$k$1となります。そうでない場合は施工できません。 

このステップにより、問題は、自己同型カウントが必要な値まで増加する独立コンポーネントの構築に集約されます。 

### ツリーの構築

 1. 選択した階乗因数ごとに$i!$、スターを構築します: 1 つの中心ノードが接続されています$i$葉。 これはまさに貢献します$i!$局所的な自己同型。 
2. 次に、これらの星を互いに並べ替えることなく組み合わせなければなりません。 これを保証するために、すべての星の中心を 1 つのパスに沿って配置します。 
3. スター センターをチェーンで接続し、各センターがバックボーン内の 1 つの隣接センターに正確に接続されるようにします。 
4. 各星の葉を対応する中心にのみ取り付けます。 

このバックボーンにより、各コンポーネントが一意の構造的位置を占めることが保証されるため、自己同型性が 2 つの異なるスター ガジェットを交換することはできません。 

### なぜ効果があるのか

 最終的なツリーの自己同型群はきれいに分解されます。 各星は次の要素に寄与します。$i!$葉を並べ替えることから。 バックボーンは、星の付着によって引き起こされる局所次数の違いにより非対称であるため、自明ではない自己同型性を持ちません。 2 つの星の中心は交換可能ではないため、コンポーネント間の追加の並べ替えはありません。 したがって、自己同型の総数は正確にすべての階乗寄与の積であり、次の値に等しくなります。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input().strip())
    
    # factorials up to 20
    fact = [1] * 21
    for i in range(1, 21):
        fact[i] = fact[i - 1] * i

    parts = []

    # greedy decomposition
    for i in range(20, 1, -1):
        while k % fact[i] == 0:
            k //= fact[i]
            parts.append(i)

    if k != 1:
        print(-1)
        return

    nodes = []
    edges = []

    # build backbone chain of component roots
    # each component is a star rooted at its center
    curr_root = 1
    nodes_used = 1

    # store centers
    centers = []

    for i in parts:
        centers.append(nodes_used)
        nodes_used += 1

    # connect centers in a path
    for i in range(len(centers) - 1):
        edges.append((centers[i], centers[i + 1]))

    # attach leaves for each star
    for idx, deg in enumerate(parts):
        c = centers[idx]
        for _ in range(deg):
            nodes_used += 1
            edges.append((c, nodes_used))

    n = nodes_used
    if n > 400:
        print(-1)
        return

    print(n)
    for u, v in edges:
        print(u, v)

if __name__ == "__main__":
    solve()
```実装は、可能な最大の値から階乗因数を貪欲に抽出することから始まります。 これにより、コンポーネントの数が最小限に抑えられ、ノードの総数を制限内に保つことができます。 

各因子は、一意のノードを中心とする星を生成します。 これらの中心は、相互に並べ替えられないように、単純なパスにリンクされます。 最後に、各センターが葉を受け取ります。 

よくある落とし穴は、同一のサブツリーによってコンポーネント間で追加の置換が発生することを忘れていることです。 バックボーンは位置の非対称性を確保することでこれを完全に回避します。 

もう 1 つの微妙な点は、ノードのインデックス付けが一貫していることを保証することです。すべてのリーフには中心の後に新しいインデックスが割り当てられるため、重複は発生しません。

 ## 特殊なケース

 主なエッジケースは次のような場合です$k$階乗数ではない因数が含まれています。 例えば、$k = 12$。 階乗分解はありません$i!$ノード制限を超えたり、無効な要素を導入したりすることなく、正確に 12 に乗算される項。 このアルゴリズムは、最大階乗で貪欲に除算を試み、剰余が残っている場合はその構築を正しく拒否します。 

もう 1 つの微妙なケースは、貪欲な分解によって生成される小さな要素が多すぎて、400 ノードを超える可能性がある場合です。 これは建設段階で処理されます。$i$正確に生成します$i + 1$ノードの合計が制限と照合されます。 

最後に、同一のコンポーネントを自由に浮かせることはできません。 2 つの同一の星がルートの下に対称的に接続されている場合、それらを交換すると、それらの数の階乗に等しい追加の乗算係数が導入され、ターゲット値が破損します。 バックボーン構造は、すべてのコンポーネントが固有の構造的位置を持つようにすることで、この問題を排除します。
