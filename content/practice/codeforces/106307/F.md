 ## 解決策
 ## 問題の理解

 非常に大きい可能性がある文字列として書かれた数値が与えられ、その値が、開始値 f0 = 1 および f1 = 1 によって定義されるフィボナッチ数列に現れるかどうかを決定するように求められます。次の項はすべて、前の 2 つの値の合計によって形成されます。 

重要な問題は、入力数値 k が最大 100,000 桁まで持つことができるため、それを組み込みの整数型に変換するアプローチが即座に排除されてしまうことです。 64 ビット整数であっても、この範囲よりずっと前でオーバーフローする可能性があるため、この問題は文字列演算を使用するか、k を数値型に解析することをまったく避けることによって完全に解決する必要があります。 

素朴な解釈では、k に達するかそれを超えるまでフィボナッチ数を生成し、その後比較することを示唆しています。 この考え方は構造的には正しいですが、巨大な整数を効率的に比較できる場合にのみ機能します。 

k に先行ゼロがある場合、微妙なエッジ ケースが 1 つ現れます。 たとえば、「0001」は「1」として扱われ、フィボナッチ値 1 と一致する必要があります。k が非常に大きく、メモリに収まるフィボナッチ数をはるかに超えている場合、別の問題が発生します。この場合、大きな整数を処理しないと単純な数値の増加が不可能になります。 

制約に基づく主な洞察は、フィボナッチ数が指数関数的に増加し、その桁数がほぼ直線的に増加するということです。 これにより、たとえ k が 100,000 桁であっても、実際に生成する必要があるフィボナッチ数の数は最大でも数十万程度にすぎず、実際には指数関数的な増加によりはるかに少なくなることが保証されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。1, 1 から始まるフィボナッチ数を生成し、k に一致するかそれを超えるまで次の値を繰り返し計算します。 フィボナッチ数列が順番に生成され、値をスキップすることがないため、正確性は即座にわかります。 

問題は、フィボナッチ数がすぐに巨大になってしまうことです。 100,000 桁のフィボナッチ数は天文学的に大きいため、ネイティブの整数で保存したり計算したりすることは不可能です。 大きな整数の場合でも、それぞれ 100,000 桁の長さになる可能性がある 2 つの大きな数値を繰り返し加算すると、ステップごとの桁長が 2 次の動作になります。 生成されるフィボナッチ数が M 個あり、それぞれが最大 D 桁である場合、総コストはおよそ O(M · D) となり、上限に達すると遅すぎます。 

重要な観察は、大きな数の比較と加算以外には何も必要ないということです。 これにより、フィボナッチ数を文字列として表現し、桁ごとの加算を実装できるようになります。 シーケンスは指数関数的に増加するため、反復回数 M は管理可能なままであり、文字列ベースの加算で十分です。 

最適化は反復を変更することではなく、文字列演算を使用し、生成されたフィボナッチ数が辞書編集長比較で k を超えたら早期に停止することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (単純な数値) | O(F・D²) | O(D) | 遅すぎる |
 | 最適 (文字列シミュレーション) | O(F・D) | O(D) | 承認済み |

 ここで、F は k を超えるまでに生成されるフィボナッチ項の数、D は桁数です。 

## アルゴリズムのチュートリアル

 フィボナッチ数を文字列としてシミュレートします。

1. 数値比較は値のみに依存するため、先頭のゼロを削除して入力文字列 k を正規化します。 結果の文字列が空の場合は、「0」として扱います。 これにより、比較がフィボナッチ表現と一貫していることが保証されます。 
2. 連続するフィボナッチ数を表す 2 つの文字列 a = "1" および b = "1" を初期化します。 
3. a と k を比較します。 等しい場合は、最初のフィボナッチ項が一致するため、すぐに YES を返すことができます。 
4. 文字列加算を使用して次のフィボナッチ数 c = a + b を繰り返し生成します。加算はキャリーを使用して右から左へ 1 桁ずつ実行されます。 
5. c を計算した後、フィボナッチ数列の不変条件を維持しながら、a = b および b = c を更新します。 
6. 更新するたびに、b と k を比較します。 等しい場合は、YES を返します。 
7. b の桁長が k より大きくなった場合、または辞書編集的な比較で b > k が示された場合は、それ以降のフィボナッチ数はすべて大きくなるだけであるため、停止して NO を返すことができます。 

重要な操作は文字列の比較です。 長さの比較が優先されます。len(b) > len(k) の場合、b > k がすでにわかっています。 長さが等しい場合、両方の文字列が先行ゼロのない非負の整数を表すため、辞書編集的比較は数値比較に対応します。 

### なぜ効果があるのか

 すべてのステップで、a と b が正しい順序で連続するフィボナッチ数であるという不変条件を維持します。 フィボナッチ数列は初期項の後に厳密に増加するため、b が k を超えると、将来の項は k に一致することはありません。 オーバーシュートする前にすべてのステップで同等性をチェックするため、有効な一致を見逃すことなく正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def strip(s: str) -> str:
    i = 0
    while i < len(s) and s[i] == '0':
        i += 1
    return s[i:] if i < len(s) else "0"

def add_strings(x: str, y: str) -> str:
    i, j = len(x) - 1, len(y) - 1
    carry = 0
    res = []

    while i >= 0 or j >= 0 or carry:
        s = carry
        if i >= 0:
            s += ord(x[i]) - 48
            i -= 1
        if j >= 0:
            s += ord(y[j]) - 48
            j -= 1
        res.append(chr((s % 10) + 48))
        carry = s // 10

    return ''.join(reversed(res))

def greater(x: str, y: str) -> bool:
    x = strip(x)
    y = strip(y)
    if len(x) != len(y):
        return len(x) > len(y)
    return x > y

def main():
    n = int(input())
    k = strip(input().strip())

    a, b = "1", "1"

    if k == "1":
        print("YES")
        return

    while True:
        c = add_strings(a, b)
        a, b = b, c

        if b == k:
            print("YES")
            return

        if greater(b, k):
            print("NO")
            return

if __name__ == "__main__":
    main()
```この実装では、フィボナッチ数が文字列として保持されます。 の`add_strings`関数は、標準的な多倍整数構造である桁上げを使用した桁ごとの加算を実行します。 の`strip`関数により、先行ゼロによる不一致を確実に回避できます。 

比較関数はまず長さをチェックします。これは、大きな数値の主要な比較要素です。 長さが一致する場合にのみ、辞書編集的な比較に戻ります。 

k に一致するか、k を超えると終了が保証されるため、ループは意図的に無限になります。

 ## 特殊なケース

 ### 先頭のゼロ

 入力:

 k = "0001"

 ストリップ後、ｋは「１」となる。 このアルゴリズムは、最初のフィボナッチ数と即座に一致します。 正規化を行わないと、「1」!=「0001」のため、文字列比較が誤って失敗します。 

### 非常に小さい k

 入力:

 k = "2"

 シーケンスは 1、1、2 と進みます。アルゴリズムは各ステップをチェックし、3 番目の項で一致を正確に識別します。 到達する前にオーバーシュートは発生しません。 

### 大きな非フィボナッチ数

 入力:

 k = "100000000000000000000"

 生成されたフィボナッチ数列は、すぐにこの大きさを超えて増加します。 b の桁長または値が k を超えると、アルゴリズムは直ちに停止し、不必要な計算が続行されないようにします。
