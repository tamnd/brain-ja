 ## 解決策

 ## 問題の理解

 配列は一連の整数として始まり、非常に具体的な貪欲な削除ルールを通じて進化します。 連続する等しい値のすべての最大ブロックを常に調べて、最大長のブロックを選択し、複数のブロックがその最大長を共有する場合は、配列内で最初に出現するブロックを選択します。 1 回の操作でブロック全体を削除すると、残りの部分が互いに近づき、新しい連続ブロックが形成されることがあります。 

タスクは、素朴な方法で直接空になるまでシミュレートするのではなく、何も残らない前にそのような削除が何回発生するかを判断することです。 

この制約により、配列には最大 200,000 個の要素を含めることができるため、配列全体を繰り返しスキャンして最適なセグメントを見つけるアプローチは即座に除外されます。 削除のたびにセグメントを再計算するシミュレーションは、削除ごとに構造の完全な再スキャンがトリガーされ、最大 O(n) 回の削除が発生する可能性があるため、二次時間まで低下する可能性があります。 

同じ長さのセグメントが競合する場合、微妙なエッジケースが発生します。 たとえば、次のような配列では、`[1,1,2,2,3,3]`、すべてのセグメントの長さは 2 です。 このルールでは、任意のセグメントではなく、左端のセグメントを最初に強制的に削除します。 セグメントの順序を正確に保持しないソリューションは、ここで失敗します。 もう 1 つのエッジ ケースは、マージによって新しい長いセグメントが作成される場合です。中央のブロックを削除すると、2 つの同一の値がより大きなセグメントに結合され、次の削除ターゲットになる可能性があるため、セグメントの構造は動的であり、静的な間隔として扱うことができません。 

## アプローチ

 直接シミュレーションでは、配列をリストとして扱い、それを繰り返しスキャンしてすべての最大の等しいセグメントを特定し、最適なものを選択して削除し、それを繰り返します。 これは定義に正確に従っているため、概念的には正しいです。 ただし、セグメントを見つけるためのスキャンには O(n) かかり、すべての値が異なる場合や削除が小さい場合には O(n) 回の削除が発生する可能性があるため、各削除後にスキャンすると最悪の場合 O(n^2) 回の作業が必要になります。 

重要な観察は、プロセスが個々の要素ではなくセグメントのみに依存しているということです。 配列が連続した実行に圧縮されると、操作はこれらの実行とのみ対話します。 各ステップで 1 つの実行が削除され、隣接する実行が同一になった場合にはマージされることがあります。 これは、最適な候補に高速にアクセスできる動的に順序付けされたセグメントのセットを維持することを示唆しています。 

左の位置によるタイブレークで最長のセグメントを繰り返し選択することをサポートするには、優先キューを使用するのが自然です。 各セグメントは、その長さと左境界とともに保存できます。 セグメントが削除されると、その隣接セグメントが新しいセグメントにマージされ、その後構造に押し戻されることがあります。 各セグメントの作成と削除は最大でも数回行われ、各ヒープ操作には対数的な時間がかかるため、プロセスは効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | O(n^2) | O(n) | 遅すぎる |
 | マージによるセグメント ヒープ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、配列を等しい値の最大セグメントに圧縮します。 各セグメントは、その値、その長さ、および隣接するセグメントへのポインタを現在の順序で保存します。 

最初に長さを減らし、次に左のインデックスを増やすことによってセグメントが順序付けされる優先キューを維持します。 これにより、キューから抽出すると、問題により次に削除する必要があるセグメントが常に返されることが保証されます。 

また、セグメントはマージまたは削除されると陳腐化する可能性があるため、各セグメントの有効性フラグも維持します。 

### ステップ

 1. 配列を連続した等しい値の初期セグメントに圧縮し、各セグメントに一意の ID を割り当て、二重リンク構造で隣接セグメントをリンクします。 

これにより、問題は個々の要素から意味のある削除単位に軽減されます。 
2. すべての初期セグメントを、長さ (降順) と位置 (昇順) でキー設定された優先キューに挿入します。 

これにより、次に削除するセグメントを迅速に取得できます。 
3. アクティブなセグメントがまだある間に、ヒープから最上位のセグメントを抽出します。 すでに無効な場合はスキップしてください。 それ以外の場合は、次の削除として扱います。 

これにより、進化する構造の下で常に現在の最良の候補を処理することが保証されます。 
4. 選択したセグメントを無効としてマークし、隣接ポインタでバイパスすることにより、リンク構造から削除します。 

これは削除操作をモデル化します。 
5. 削除されたセグメントの左右の隣接部分を確認します。 両方が存在し、同じ値を持つ場合は、それらを両方の合計の長さを持つ新しいセグメントにマージし、それを構造にリンクします。 

このステップは、削除後に新しいセグメントが作成される唯一の方法をキャプチャします。 
6. 新しく作成されたマージされたセグメントを優先キューにプッシュします。 
7. 有効な削除が処理されるたびに、操作カウンタをインクリメントします。 

### なぜ効果があるのか

重要な不変条件は、プライオリティ キューには配列内の現在有効なすべてのセグメントが常に含まれており、以前のすべてのマージ後の各セグメントは正しい長さと位置を持っているということです。 ヒープ内の一部のエントリはマージ後に古くなっても、ポップされると遅延して無視されます。 現在の配列状態にあるすべての実セグメントは、引き続き有効なヒープ エントリによって表されるか、マージ直後に再作成されます。 各削除は正確に 1 つの処理されたセグメントに対応するため、処理された有効なポップをカウントすると操作の数がわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 0:
        print(0)
        return

    # build initial segments
    seg_id = 0
    value = []
    length = []
    left = []
    right = []

    # linked list via indices
    prev_seg = []
    next_seg = []

    i = 0
    while i < n:
        j = i
        while j < n and a[j] == a[i]:
            j += 1
        value.append(a[i])
        length.append(j - i)
        left.append(i)
        right.append(j - 1)
        prev_seg.append(seg_id - 1)
        next_seg.append(seg_id + 1)
        seg_id += 1
        i = j

    m = seg_id
    next_seg[m - 1] = -1

    # heap: (-len, left_index, seg_id)
    heap = []
    alive = [True] * m

    for i in range(m):
        heapq.heappush(heap, (-length[i], left[i], i))

    def merge(x, y):
        """merge two adjacent segments x and y (x before y)"""
        value.append(value[x])
        length.append(length[x] + length[y])
        left.append(left[x])
        right.append(right[y])
        prev_seg.append(prev_seg[x])
        next_seg.append(next_seg[y])
        nid = len(value) - 1

        alive.append(True)

        if prev_seg[x] != -1:
            next_seg[prev_seg[x]] = nid
        if next_seg[y] != -1:
            prev_seg[next_seg[y]] = nid

        return nid

    ops = 0

    while heap:
        neg_len, lpos, idx = heapq.heappop(heap)
        if idx >= len(alive) or not alive[idx]:
            continue

        # perform deletion
        ops += 1
        alive[idx] = False

        l = prev_seg[idx]
        r = next_seg[idx]

        if l != -1:
            next_seg[l] = r
        if r != -1:
            prev_seg[r] = l

        # try merge neighbors
        if l != -1 and r != -1 and alive[l] and alive[r] and value[l] == value[r]:
            alive[l] = False
            alive[r] = False
            nid = merge(l, r)
            heapq.heappush(heap, (-length[nid], left[nid], nid))

    print(ops)

if __name__ == "__main__":
    solve()
```コードは、各ノードが最大の実行を表すように、配列をセグメントに圧縮することから始まります。 このプロセスは実行を内部的に分割することはなく、実行全体を削除するか、隣接する実行をマージするだけであるため、これは不可欠です。 

ヒープには、問題内のルールに従って正確に順序付けされた候補が格納されます。つまり、最も長いセグメントが最初に、次に左端の位置に配置されます。 遅延削除チェックにより、マージ前に作成された古いヒープ エントリが正確さを妨げないことが保証されます。 

マージ機能は、構造の一貫性を維持する役割を果たします。 削除後に 2 つの隣接要素が同一になると、それらは新しいセグメントに置き換えられ、すべてのポインター リンクが更新されるため、リンクされた構造は有効なままになります。 

操作カウンタは、真にアクティブなセグメントが削除された場合にのみ増加し、削除ごとに 1 つの操作の定義と一致します。 

## 実用的な例

 ### 例 1

 入力:`[2, 5, 5, 2]`初期セグメントは`[2] [5,5] [2]`。 

| ステップ | ヒープトップ | 削除されたセグメント | マージ | 残りのセグメント |
 | --- | --- | --- | --- | --- |
 | 1 | [5,5] | [5,5] | なし | [2] [2] |
 | 2 | [2] (左端) | [2] | [2,2] にマージ | [] |

 最初の操作では最長のセグメントが削除されます`[5,5]`。 その後、２つ`2`セグメントは隣接して結合され、最終的に 1 つのセグメントになります。これは 2 番目のステップで削除されます。 

このトレースは、2 番目の操作は最初の削除後に作成された構造に完全に依存しているため、マージが不可欠であることを示しています。 

### 例 2

 入力:`[1,1,2,2,2,1,1]`初期セグメント:`[1,1] [2,2,2] [1,1]`。 

| ステップ | ヒープトップ | 削除されたセグメント | マージ | 残りのセグメント |
 | --- | --- | --- | --- | --- |
 | 1 | [2,2,2] | [2,2,2] | なし | [1,1] [1,1] |
 | 2 | 左 [1,1] | [1,1] | [1,1,1,1] にマージ | [] |

 2 番目のステップでは、削除によってより長いマージ セグメントが作成され、それが次のターゲットになる可能性があることを示します。

 ## 特殊なケース

 配列全体が 1 つのセグメントである場合、ヒープには 1 つのエントリが含まれており、最初の抽出では 1 回の操作ですべてが削除されます。 このアルゴリズムは、マージがまったく発生しないという事実と一致して、有効なポップを 1 つだけ処理し、すぐに終了します。 

すべての要素が交互になると、すべてのセグメントの長さは 1 になります。 ヒープは左端に残っているセグメントを繰り返し選択しますが、マージは行われません。 リンクされた構造は操作ごとに 1 ノードだけ縮小し、アルゴリズムは要素ごとに 1 つの操作を正確にカウントします。 

削除によって新しい隣接する等しいセグメントが作成される場合、マージ ロジックが重要なメカニズムになります。 のような場合には`[1,1,2,2,1,1]`、中央のセグメントを削除すると、`[1,1,1,1]`、マージ ステップにより、これが 4 つの独立したセグメントではなく、単一の新しいセグメントとして扱われることが保証されます。 このアルゴリズムは、次の削除の対象となる前にセグメントを正しく再構築します。
