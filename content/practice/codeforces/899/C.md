 ## 解決策

 ## 問題の理解

 最初の n 個の正の整数が与えられ、それらを 2 つの空でないグループに分割する必要があります。 すべての整数は 1 つのグループに属する必要があり、2 つのグループの合計ができるだけ近くなるようにします。 

構造の観点から考えると、これは固定セット {1, 2, ..., n} を 2 つのサブセットに分割したものです。 目的にとって重要な唯一の数量は、サブセット合計間の差です。 合計は固定されているため、差を最小限に抑えることは、1 つのサブセットの合計を合計の半分にできるだけ近づけることと同じです。 

最初の n 個の整数の合計は n(n+1)/2 であるため、目標は、合計が S/2 に近いサブセットを構築することです。 

n ≤ 60000 という制約は十分に大きいため、指数関数的なサブセットの構築は不可能です。 ブルートフォースのサブセット列挙には 2^n 通りの可能性が含まれますが、これは実行可能な制限をはるかに超えています。 n = 60000 の場合、S は 1.8 × 10^9 程度であるため、S までの合計状態に対してバックトラッキングまたは DP を使用して独立して包含を決定しようとするアプローチでも大きすぎます。 

この制約の主な意味は、すべてのサブセットについて直接推論することはできず、シーケンス 1、2、...、n の構造を利用する必要があるということです。 

n が非常に小さい場合、微妙なエッジケースが発生します。 n = 2 の場合、唯一の有効な分割は {1} と {2} であり、差は 1 になります。n = 3 の場合、ほぼ均衡のとれた分割は {1, 2} と {3} として存在し、合計が 3 と 3 になるため、差は 0 になります。完全な均衡が達成できる場合とそうでない場合があるため、どのソリューションでも合計の両方のパリティ ケースを正しく処理する必要があります。 

もう 1 つの失敗モードは、構造を持たずに 1 から上へ、または n から下へ貪欲な選択を試みることです。 たとえば、常に大きな数値を最初に置くと、残りの数値が小さすぎて補えないため、早期にオーバーシュートし、バランスを回復する方法がなくなる可能性があります。 

## アプローチ

 ブルートフォースの試みでは、1 から n までの各数値を 2 つのグループのいずれかに割り当て、最も良い差異を追跡しようとします。 これは 2^n 個のパーティションをチェックします。各チェックが O(n) だったとしても、総作業量は n・2^n として増加しますが、n = 40 ではすでに不可能になります。 

より構造化された動的プログラミング手法では、S/2 までの達成可能なすべてのサブセットの合計を計算しようとする可能性があります。 ただし、S 自体は n とともに二次関数的に増加するため、ビットセットベースの DP であっても、最悪の場合、約 1.8 × 10^9 ビットが必要となり、メモリと時間の面で実行不可能です。 

重要な点は、番号が連続していることです。 これは、最大数から順に貪欲に最適なパーティションを構築できることを意味します。 それぞれの大きな数字は、結合された残りの小さな数字すべてを支配するか、少なくともバランスの決定に強く影響します。 組み合わせサブセット合計問題を解決する代わりに、目標を大きく超えない限り、常に利用可能な最大の要素を取得することで、合計が S/2 に近づくサブセットを直接構築できます。 

この戦略は、総額の半分に向けて制御された貪欲な蓄積になります。 私たちは常に残りの合計を考慮し、実現可能な最大の要素を選択するため、最終的な合計を微調整するために常により小さな数が利用できるため、正確に目標を達成する能力を失うことはありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 合計に対する DP | O(nS) または O(S) スペース | O(S) | 大きすぎる |
 | 貪欲な建設 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 合計を S、ターゲットを T = S // 2 と表します。合計が T にできるだけ近いサブセット A を構築したいと考えています。

1. S = n(n+1)/2 を計算し、T = S // 2 を設定します。これにより、2 つのグループ間の理想的なバランス ポイントが定義されます。 
2. 空のセット A を初期化し、current_sum = 0 に設定します。このセットは、構築している最初のグループを表します。 
3. i を n から 1 まで繰り返します。各ステップで、i を A に追加することで T 内に収まるか、T に近い状態に保たれるかを検討します。 
4. current_sum + i ≤ T の場合、i を A に含めて current_sum を更新します。 その理由は、値が大きいほど柔軟性が小さい値よりも低下するため、ターゲットを超えずに適合する任意の数値を採用する必要があるためです。 
5. それ以外の場合は、i をスキップして、暗黙的に 2 番目のグループに割り当てます。 スキップすると i は補グループ内で利用可能な状態に保たれるため、完全なパーティションを引き続き形成できることが保証されます。 
6. すべての数値を処理した後、絶対差分 |S - 2・current_sum| を出力します。 そしてAセット。 

この構造では、利用可能なアイテム {1, ..., n} を降順に使用して、ナップザックを容量 T まで効果的に満たします。 

これが機能する理由は、連続する整数の単純な優勢特性に由来します。 どのステップでも、残りの未使用の数値は正確に連続する整数の接頭辞であり、貪欲な選択により、実現可能な最適な合計を決して逃すことがなくなります。数値が適合する場合、その数値を取得しても、残りの整数を使用してすべての小さな調整が可能であるため、T にさらに近似することが妨げられることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
S = n * (n + 1) // 2
T = S // 2

chosen = []
current = 0

for i in range(n, 0, -1):
    if current + i <= T:
        chosen.append(i)
        current += i

group2 = set(chosen)

print(abs(S - 2 * current))
print(len(chosen), *chosen)
```このソリューションでは、まず合計と目標の半分が計算されます。 貪欲ループは、n から 1 までの数値を処理し、次の不変式を維持します。`current`は選択された要素の合計であり、T を超えることはありません。各要素は残りの容量に対してテストされ、適合する場合にのみ含まれます。 

出力の差は、2 番目のグループの合計が S - 電流であるという恒等式を使用して計算されるため、絶対差は |電流 - (S - 電流)| になります。 = |S - 2・電流|。 

微妙な点は、2 番目のグループを明示的に構築しないことです。 これは選択したセットを暗黙的に補完するものであり、有効性が保証され、余分な作業が回避されます。 

## 実用的な例

 n = 4 とします。合計は 10 なので、T = 5 となります。 

| 私 | | 前の現在 | 決定 | 後の現在 |
 | --- | --- | --- | --- |
 | 4 | 0 | テイク (0+4 ≤ 5) | 4 |
 | 3 | 4 | スキップ (4+3 > 5) | 4 |
 | 2 | 4 | スキップ (4+2 > 5) | 4 |
 | 1 | 4 | スキップ (4+1 > 5) | 4 |

 選択されたセットは {4} ですが、これはこの場合には最適ではありません。 ただし、構造を正しく解釈しない限り、n から下への貪欲だけでは十分ではないことに注意する必要があります。私たちは 5 に近いサブセットの合計を目指しており、4 が達成可能なプレフィックスベースの貪欲の結果に最も近い値です。 より洗練された解釈は、タイの処理に応じて複数の有効な貪欲パスが存在するということです。 この場合、1 と 4 を含めることで正確なバランスが得られますが、これは含める順序を逆にすることによっても達成できます。 

より具体的なケースは、n = 5 です。合計は 15、T = 7 です。

これらのトレースは、アルゴリズムが貪欲に詰め込まれた境界のあるナップザックのように動作し、容量を尊重しながら常により大きな貢献を優先することを示しています。

 ## 特殊なケース

 n = 2 の場合、アルゴリズムは T = 3 // 2 = 1 から始まります。まず 2 を処理し、スキップして、次に 1 を受け取ります。結果のグループは {1} と {2} で、差は 1 になります。完全なバランスは不可能であるため、これが最適です。 

n = 3、S = 6、T = 3 の場合、アルゴリズムは最初に 3 を考慮してそれを取得し、次に 2 と 1 は両方とも容量を超えるためスキップします。 これにより、{3} と {1, 2} が得られ、両方の合計は 3 になるため、差は 0 になります。ターゲットが大きな要素と正確に一致するため、貪欲な選択は成功します。 

n = 4、S = 10、T = 5 の場合。アルゴリズムは 4 を受け取り、次に 1 を受け取り、正確に 5 に達します。残りの要素は 2 番目のグループを形成します。 これは、より小さな要素が以前の大きな選択をどのように補い、正確なターゲットへの到達可能性を維持するかを示しています。
