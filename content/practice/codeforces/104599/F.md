 ## 解決策
 ## 問題の理解

 私たちには円形の軌道が与えられています$n$ラベル付きの位置。 3 つのトークンが位置から始まります$a$、$b$、 そして$c$。 1 回の移動で、トークンを 1 つだけ選択し、円に沿って時計回りまたは反時計回りに 1 ステップ移動します。 

目標は、最小限の移動数で 3 つのトークンすべてを同じ位置に配置することです。 移動はトークンごとに独立しており、円形の距離のみに依存するため、実際の問題は、集合場所を選択し、各トークンがそこに到達するのにどれくらいのコストがかかるかを測定することです。 

出力は単一の整数、つまり 3 つのトークンすべてを揃えるのに必要なユニット移動の最小合計数です。 

制約$n \le 10^9$つまり、動きをシミュレートできないということです。 位置を反復したり、円上で BFS を実行したりするアプローチは不可能です。 直接距離の公式を使用して、すべてを一定時間内に計算する必要があります。 

点が円の周りを囲むと、微妙なエッジケースが現れます。 たとえば、$n = 5$からの移動$1$に$5$の距離です$1$、 ない$4$。 時計回りと反時計回りの距離の最小値を明示的に取得しない限り、直線距離の式は不正確になります。 

もう 1 つの明白ではないケースは、2 つ以上のトークンがすでに一致している場合です。 例えば、$(1, 1, 5)$退化しているように見えますが、最適な集合場所が共有場所でない場合は、移動が必要になる可能性があります。 

## アプローチ

 ブルートフォースソリューションは、考えられるすべてのミーティングポイントを試みます$x \in [1, n]$。 それぞれについて$x$からの円周距離の合計を計算します。$a$、$b$、 そして$c$に$x$次に、全体の最小値を取得します。$x$。 各評価には一定の時間がかかるため、総作業量は次のようになります。$O(n)$。 と$n$まで$10^9$、これはまったく不可能です。 

重要な観察は、コスト関数が純粋に円周距離に基づいており、円上の 3 つの点の場合、最適な合流点はそれらの点によって決定される円弧の 1 つ上にある必要があるということです。 すべての位置をスキャンする代わりに、円に沿った候補中央値のみを考慮する必要があります。 

直線上で、距離の合計を最小にする最適な合流点は中央値です。 円上で、考えられる各ギャップで円を「カット」し、直線状の配置に縮小することができます。 3 つの点の場合、唯一の意味のある構造はそれらの循環順序の配置であり、これにより問題は一定数の構成をチェックすることになります。 

3 つの位置をソートし、円弧の長さを推論することで、解は定数時間になります。

 ## アルゴリズムのチュートリアル

 1. 3 つの位置を並べ替えて、それらの循環順序を一貫して推論できるようにします。 これにより、順列によって生じる曖昧さが解消されます。 
2. 円に沿った点間の 3 つの連続する円形ギャップを計算します。 並べ替えられた位置に次のようにラベルを付けると、$x_1 \le x_2 \le x_3$、ギャップは次のようになります。$x_2 - x_1$、$x_3 - x_2$、ラップアラウンドギャップ$(n - x_3 + x_1)$。 
3. 最大のギャップを特定します。 これは、最適な合流点を選択した場合に通過する必要のない「空の弧」を表します。 
4. 最小合計移動量は、すべてのギャップの合計から最大ギャップを引いたものです。 直感的に、短い方の 2 つの円弧を横断し、最大の空の円弧を避けます。 

### なぜ効果があるのか

 最大のギャップの内側にミーティング ポイントを配置すると、トークンがその円弧を横切る必要がなくなります。 すべての移動は、すべてのポイントをまとめるために必要な周囲の合計を縮小するものと見なすことができます。 3 つの点をすべてマージするには 2 つの分離を削除する必要があり、最大の分離を避けると総移動量が最小限に抑えられるため、どのような解法でも 1 つを除くすべての円弧をカバーする必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a, b, c = map(int, input().split())

    x = sorted([a, b, c])

    d1 = x[1] - x[0]
    d2 = x[2] - x[1]
    d3 = n - x[2] + x[0]

    print(d1 + d2 + d3 - max(d1, d2, d3))

if __name__ == "__main__":
    solve()
```この解決策は、3 つの位置を並べ替えることから始まり、これにより円上のジオメトリが標準化されます。 計算された 3 つのギャップは、点によって形成される 3 つの円弧に正確に対応します。 ラップアラウンド用語により、循環性が正しく処理されることが保証されます。 最大のギャップを減算すると、交差しないことを選択した円弧が削除され、最適な位置合わせコストが得られます。 

よくある間違いは、周回距離を忘れたり、円を線として扱ったりすることです。これは、最適なパスが境界線を横切るときに失敗します。$n$そして$1$。

 ## 特殊なケース

 3 つのトークンがすべて同じ位置にある場合、すべてのギャップはゼロになるため、式は自然にゼロを返します。 移動は必要なく、アルゴリズムは特別な分岐を行わずにこれを処理します。 

2 つのトークンが一致すると、1 つのギャップがゼロになり、解決策は 3 番目のトークンを最短の円弧に沿って移動することになります。 ソートされたギャップの定式化では、最大の円弧がクラスターの反対側の円弧として正確に識別されます。 

最適構成が境界を越えるとき$n$そして$1$、ラップアラウンドギャップが重要な候補の1つになります。 アルゴリズムには、このケースが次のように明示的に含まれています。$n - x_3 + x_1$、余分なロジックなしで正しい処理を保証します。
