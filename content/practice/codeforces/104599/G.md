 ## 解決策
 ## 問題の理解

 小文字と多数のクエリで構成される文字列が与えられています。 各クエリは文字列の連続する部分文字列を選択します。その部分文字列について、1 つの繰り返し文字のみで構成される部分文字列がいくつあるかをカウントする必要があります。 

タスクを言い換える有効な方法は、実行の観点から考えることです。 文字列のセグメント内では、連続する等しい文字がブロックを形成します。 境界を越えると別の文字が導入されるため、応答内でカウントされる有効な部分文字列はすべて、そのようなブロック内に完全に存在する必要があります。 

単一の長さのブロックの場合$k$、有効な部分文字列の数は、そのブロック内の開始位置と終了位置を選択する方法の数です。$k(k+1)/2$。 したがって、クエリの答えは、クエリ範囲内に完全または部分的に含まれるすべての最大定数文字セグメントにわたるこの値の合計になります。 

制約により、前処理ステップごとに線形またはほぼ線形、クエリごとに定数または対数の解が強制されます。 と$10^5$キャラクターと$10^5$クエリの場合、クエリごとに部分文字列をスキャンするアプローチは遅すぎます。$10^{10}$最悪の場合の運用。 

セグメントの境界で微妙な問題が発生します。 抽出後にクエリ部分文字列内の実行を単純にカウントする単純なアプローチでは、クエリの境界を超えて実行が二重にカウントされたり、誤って分割されたりする可能性があります。 たとえば、`aaab`、部分文字列`[1,3]`は`aaa`、貢献度 6 ですが、実行境界を尊重しないメソッドは各文字を独立して扱い、グループ化を完全に見逃してしまう可能性があります。 

もう 1 つのエッジ ケースは、実行内で開始または終了するクエリです。 たとえば、`aaabbb`、クエリ`[2,5]`は`aabbb`。 正しい答えは、$aab$は 3 + 3 を返しますが、これは最初と最後の実行の部分的な寄与が慎重に処理された場合にのみ機能します。 

## アプローチ

 直接的なブルート フォース ソリューションでは、文字の一貫性を維持しながら部分文字列をスキャンし、考えられるすべての開始位置を拡張することによって、各クエリを独立して計算します。 各開始インデックスについて、文字が変更されるまで拡張し、そこから始まるすべての有効な部分文字列をカウントします。 すべての有効な部分文字列が 1 回だけ列挙されるため、これは正しいですが、クエリごとに必要な場合があるため、遅すぎます。$O(n^2)$最悪の場合には機能し、$O(n^3)$総合的な行動。 

重要な観察は、文字列が等しい文字の最大セグメントに圧縮できるということです。 各クエリの回答は、これらのセグメントからの寄与の合計になります。 すべてのクエリの構造を再計算する代わりに、実行境界を事前計算し、実行寄与率に対してプレフィックス合計を使用します。 

複雑なのは、クエリ境界と実行の間の部分的な重複を処理することです。 クエリ境界により実行が 2 つの部分に分割される可能性があるため、実行ベースのプレフィックス合計だけでは不十分です。 修正方法は、各位置で終了するプレフィックスの寄与を格納する配列を事前計算しますが、実行内の部分文字列のみを完全にカウントし、実行エンドポイントを使用して境界のオーバーカウントを修正します。 

これにより、前処理が線形になり、実行セグメントに対する算術演算と境界補正を使用して各クエリが一定時間内に応答されるソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2 Q)$|$O(1)$| 遅すぎる |
 | 分解 + プレフィックスの合計を実行する |$O(n + Q)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、文字列を同一文字の最大セグメントに分解します。 各セグメントは、開始インデックス、終了インデックス、および長さによって表されます。 

次に、次の式を使用して各セグメントの寄与度を事前計算します。$len \cdot (len+1)/2$。 これらのセグメントの寄与に基づいてプレフィックス合計配列を構築します。 

クエリごとに$[L, R]$, 以下のように進めていきます。 

1. 位置を含むセグメントを特定する$L$。 ランが右にどれだけ伸びるかを判断し、クエリ範囲との重複を計算します。 これにより、左側の部分セグメントの寄与が得られます。 これを分離する理由は、実行が左側の境界でカットされる可能性があり、クエリ内の部分のみをカウントする必要があるためです。 
2. 位置を含むセグメントを特定する$R$そして、同様に重複寄与を計算します。 これにより、右側の境界が対称的に処理されます。 
3. もし$L$そして$R$同じセグメント内にある場合、答えは単に長さの三角形の数です。$R-L+1$部分文字列が完全に均一であるためです。 
4. それ以外の場合は、すべての完全なセグメントの完全な寄与を、次のセグメント間で厳密に合計します。$L$そして$R$プレフィックス合計配列を使用します。 
5. 左右の境界セグメントからの部分的な寄与を加算します。 

重要な推論ステップは、すべての有効な部分文字列が完全に等しい文字の 1 つのセグメント内にあるため、セグメントごとに分割することで二重カウントが保証されないということです。 

### なぜ効果があるのか

 同一の文字で構成されるすべての部分文字列は、その文字の単一の最大ラン内に完全に含まれます。 最大ランへの分解では、有効な部分文字列が境界を越えないように文字列のパーティションが作成されます。 各実行は独立して寄与し、クエリ範囲は内部構造を変更せずにエンドポイントで実行を切り捨てるだけです。 これにより、クエリ範囲内の実行ごとの寄与を合計すると、有効な部分文字列がすべて 1 回だけカウントされ、無効なクロスラン部分文字列が決して含まれないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_runs(s):
    n = len(s)
    starts = []
    ends = []
    lens = []
    
    i = 0
    while i < n:
        j = i
        while j < n and s[j] == s[i]:
            j += 1
        starts.append(i)
        ends.append(j - 1)
        lens.append(j - i)
        i = j
    
    return starts, ends, lens

def solve():
    s = input().strip()
    n = len(s)
    q = int(input())
    
    starts, ends, lens = build_runs(s)
    m = len(lens)
    
    pref = [0] * (m + 1)
    for i in range(m):
        l = lens[i]
        pref[i + 1] = pref[i] + l * (l + 1) // 2
    
    def get_run(pos):
        lo, hi = 0, m - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if starts[mid] <= pos <= ends[mid]:
                return mid
            if pos < starts[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        return -1
    
    out = []
    
    for _ in range(q):
        L, R = map(int, input().split())
        L -= 1
        R -= 1
        
        rl = get_run(L)
        rr = get_run(R)
        
        if rl == rr:
            length = R - L + 1
            out.append(str(length * (length + 1) // 2))
            continue
        
        left_end = ends[rl]
        left_len = left_end - L + 1
        left_contrib = left_len * (left_len + 1) // 2
        
        right_start = starts[rr]
        right_len = R - right_start + 1
        right_contrib = right_len * (right_len + 1) // 2
        
        mid_contrib = pref[rr] - pref[rl + 1]
        
        out.append(str(left_contrib + right_contrib + mid_contrib))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、同一文字の最大ブロックがすべて明示的に表現されるように、最初に文字列をランに圧縮します。 プレフィックス配列には、完全な実行の累積寄与が格納されるため、クエリ内の内部セグメントの定数時間の合計が可能になります。 

二分探索`get_run`指定されたインデックスを含む実行を見つけます。 実行はばらばらであり、開始位置によって並べ替えられるため、これは安全です。 

各クエリは、左側の部分実行、中央の完全な実行のブロック、右側の部分実行の最大 3 つの部分に分割されます。 両方のエンドポイントが同じ実行内にある特殊なケースでは、二重カウント ロジックが回避され、三角数式が直接使用されます。

 ## 特殊なケース

 次のような単一文字列`a`長さ 1 のランが 1 つ含まれているため、部分文字列はそれ自体だけです。 このアルゴリズムは 1 つの実行を作成し、プレフィックス配列には 1 の寄与が 1 つ含まれ、クエリは単純に切り捨てられたランの長さにわたる三角数を返します。 

次のような、すべて同一の文字を含む文字列。`aaaaaa`実行は 1 回のみ行われます。 あらゆるクエリはコンピューティングに帰着します$k(k+1)/2$コードは単一実行分岐で同じロジックを使用し、プレフィックスの合計や境界処理に依存しないようにします。 

次のような文字が交互に並ぶ文字列`ababab`長さ 1 のランが多数生成されます。各ランは正確に 1 を寄与し、プレフィックスの合計は完全なラン全体にわたって寄与を正しく累積します。 各インデックスは個別のセグメントに属しているため、境界ロジックはマージが誤って実行されることはありません。
