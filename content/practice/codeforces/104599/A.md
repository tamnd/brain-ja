 ## 解決策
 ## 問題の理解

 私たちにはロボットの友達のコレクションが与えられており、それぞれがその高さを表す単一の整数値によってのみ記述されます。 ボブは、すべてのロボットを垂直に積み重ねて 1 つの「メガ ロボット」を作りたいと考えています。 タスクは単に、このスタックの合計の高さを決定することです。これは、個々のロボットの高さすべての合計です。 

入力は、整数 N とそれに続く N 個の整数で構成されます。 各整数は最終結果に直接寄与し、それ以外は問題の構造に影響を与えません。 順序の制約、値間の相互作用、個々の高さに適用される変換はありません。 出力は、合計の累積高さに等しい単一の整数です。 

制約から、N は最大 1000、各高さは最大 1,000,000 です。 これは、合計が最大 10^9 に達する可能性があることを意味します。これは標準の 32 ビット符号付き整数の範囲内に十分収まりますが、汎用ソリューションでは 64 ビット型を使用することが依然として安全な習慣です。 

問題は意図的に最小限に抑えられているため、主なリスクはアルゴリズムではなく実装に関連しています。 いくつかの微妙な特殊なケースがまだ存在します。 

エッジケースの 1 つは、ロボットが 1 台だけの場合です。 入力は次のようになります。```
1
42
```正しい出力は 42 です。ここでのバグのあるパターンは、少なくとも 2 つの値を想定し、空または部分的に埋められた構造から合計を誤って初期化するコードです。 

もう 1 つのエッジ ケースは、すべてのロボットの高さが最大である場合です。```
3
1000000 1000000 1000000
```正しい出力は 3000000 です。厳密なオーバーフロー動作を持つ言語で固定幅の 32 ビット整数を使用する不用意な実装は、ここで失敗する可能性がありますが、Python は自然にこの問題を回避します。 

3 番目の状況は、すべての値が 0 の場合です。これは制約に明示的に含まれていませんが、大まかに解釈すれば論理的には許可されます。 合計は依然として正しくゼロであるはずです。 これにより、アキュムレータを誤ってゼロ以外のデフォルトで初期化したり、次のような条件で値をスキップしたりするロジックが暴露される可能性があります。`if h_i`。 

## アプローチ

 問題の構造は要素間に依存関係がないことを示唆しているため、正しい解決策はすべての値を 1 つの集計結果に結合する必要があります。 最も直接的なアプローチは、リストを反復処理して現在の合計を累積することです。 

ブルートフォース的な考え方では、プレフィックスを繰り返し合計したり、検証のために合計を最初から再計算したりするなど、さまざまな方法で部分合計を再計算することを想像するかもしれません。 たとえば、各プレフィックスの合計を計算して結果を繰り返し結合したり、部分的なスタックを繰り返し結合してスタッキングをシミュレートしたりすることもできます。 これでも最終的にはすべての要素を合計することになりますが、不必要な繰り返し作業が必要になります。 最悪の場合、各要素の合計を最初から再計算すると O(N^2) 回の演算が発生します。これは N ≤ 1000 の場合にはまだ小さいですが、構造的に無駄であり、意図した方向ではありません。 

重要な観察は、スタッキングによって相互作用効果が導入されないことです。 最終的な構造の高さは、順序とグループ化の下では不変です。これは、問題が純粋に加算的なものであることを意味します。 これが認識されると、タスク全体が単一パスの蓄積にまとめられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース繰り返し合計 | O(N^2) | お(1) | 許容できるが不要 |
 | シングルパス累積 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数 N を読み取り、その後に続く高さの数を決定します。 これにより、集計する必要がある値の数が定義されます。 
2. 変数を初期化する`total`ゼロに。 この変数は、これまでに確認されたすべてのロボットの高さの累計を表します。 
3. N 個の入力値を 1 つずつ繰り返します。 それぞれの値について`h`に追加します`total`。 このステップは、問題で説明されている積み重ね操作を直接反映しています。つまり、各ロボットがその全高を最終構造に貢献します。 
4. すべての値を処理した後、出力します。`total`。 この時点で、すべてのロボットが 1 回だけ含まれているため、累積された値がメガ ロボットの最終的な高さになります。 

### なぜ効果があるのか

 このアルゴリズムは、最終的な構造がすべてのロボットを修正や重複なしで積み重ねることによって形成されるという事実に基づいています。 各ロボットは独立して全高に寄与し、相互作用によってその値が変化することはありません。 加算は結合的かつ可換であるため、累算の順序は重要ではなく、すべての有効なスタッキングは同じ合計に対応します。 現在の合計は不変状態を維持します。つまり、k 個の要素を処理した後、`total`最初の k 個の高さの合計に等しい。 k が N に達すると、不変式により次のことが保証されます。`total`すべての高さの合計に等しい。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    total = 0

    for _ in range(n):
        total += int(input().strip())

    print(total)

if __name__ == "__main__":
    main()
```このソリューションは、制約が小さい場合でもオーバーヘッドを回避するために、高速 I/O を使用して入力を読み取ります。 アキュムレータ`total`は単一パスで更新され、概念的なスタッキング プロセスに正確に対応します。 各行が解析されてすぐに組み込まれるため、一定のメモリ使用量が確保されます。 

微妙な実装の詳細は、`strip()`入力行から整数を読み取るとき。 ほとんどの場合、厳密に必要というわけではありませんが、末尾の空白に関する問題を防ぐことができます。 もう 1 つの詳細は、アキュムレータを入力解析から分離することです。これにより、ループ変数の誤った再利用や部分的な上書きが回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    total = 0
    for _ in range(n):
        total += int(sys.stdin.readline().strip())

 ## 特殊なケース

 単一のロボット入力の場合、次のようになります。`1`に続く`42`、ループは 1 回だけ実行されます。 アキュムレータは 0 から始まり、最初の反復後に 42 になり、直接出力されます。 これにより、初期化が複数の要素の存在に依存しないことが確認されます。 

最大値の場合、次のようになります。`1000000 1000000 1000000`、各反復で大きな数値が追加されますが、Python の整数には制限がないため、オーバーフローは発生しません。 現在の合計は 0 から 3,000,000 まできれいに推移しており、追加を繰り返しても制約内で安全にスケールできることが確認されています。 

すべてゼロの入力の場合、各反復ではアキュムレータは変更されません。 不変条件`total`処理された要素の合計に等しいはすべてのステップで自明に成立し、最終出力は特別なケースなしでゼロのままになります。
