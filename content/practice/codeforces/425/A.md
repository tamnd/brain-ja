 ## 解決策
 ## 問題の理解

 整数の配列とスワップ操作の限られた予算が与えられています。 各スワップでは、配列内の任意の 2 つの位置を交換でき、最大で次のことを実行できます。`k`そういった交換。 

目標は、以下のものを使用して配列を再配置することです。`k`特定のスコアが機能するように交換し、`m(a)`, できるだけ大きくなります。 この関数は、配列の位置に異なる重みを割り当てます。配列内で前に配置された要素は、後から配置された要素よりも最終的な値に大きく寄与します。 具体的には、要素の寄与はその要素がどれだけ右に位置するかによって決まるため、大きな値を配列の前半に持ってくると有益です。 

入力サイズが小さい場合:`n ≤ 200`そして`k ≤ 10`。 これにより、すべての順列に対する指数関数的な戦略が即座に除外されます。`n!`は大きすぎます。 平`O(n^3)`解決策は境界線にありますが、許容できます。 すべての並べ替えを列挙することを伴うものは実行不可能です。 

非常に小さな存在`k`が重要な構造上の制約です。 これは、配列を自由に並べ替えることが期待されているのではなく、元の構成から始めて限られた数の影響力のある編​​集を行うことが期待されていることを示唆しています。 

微妙なエッジケースは、重複した値や負​​の数値から発生します。 たとえば、すべての要素が負の場合、負の数が小さい数値を重みの高い位置に押し込み、非常に負の数値を後で残すと、スワップによって実際にスコアが減少する可能性があります。 同様に、アレイがすでに最適化されている場合、スワップの使用はオプションであり、強制すべきではありません。 

## アプローチ

 スコア関数は、配列の最終順序にのみ依存し、どのようにして配列に到達するかには依存しません。 スワップは任意の 2 つのインデックス間の任意の交換であるため、各スワップは 2 つのポジションを選択し、1 回の動きでそれらの値を交換するものとみなすことができます。 

強引なアイデアは、最大でも次のすべての可能なシーケンスをシミュレートすることです。`k`交換します。 あらゆるステップで、すべてのペアを試します`(i, j)`、スワップを適用し、再帰的に続行します。 これは、許可された操作数内で到達可能なすべての構成を調査するため、正しいです。 ただし、分岐要因は、`O(n^2)`ステップごと、深さは`k`、おおよそにつながります`O(n^(2k))`であっても非常に急速に成長する州`k = 3`。 

重要な観察は、私たちが決定している現在のポジションに関係しないスワップを考慮する必要はまったくないということです。 任意のスワップ シーケンスをグローバルに探索する代わりに、左から右に答えを構築できます。 位置で`i`、最大 1 回のスワップを使用して、後の位置からどの値を配置するかを決定します。 位置固定後`i`、前進します。 

これにより、問題は、選択を後戻りする制御された貪欲な構造に変わります。 各インデックスで、要素をそのままにするか、後の位置と交換して、スワップ バジェットの 1 単位を消費します。 なぜなら`k ≤ 10`、そのような選択肢をすべて検討することは可能です。 

したがって、再帰は、現在のインデックス、残りのスワップ数、配列の現在の構成という 3 つの状態にわたって定義されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全な順列検索 | O(n!) | O(n) | 遅すぎる |
 | 再帰的スワップ シミュレーション | O(n^(2k)) | O(n) | 遅すぎる |
 | スワップの選択肢を備えた制御された DFS | O(k · n^2 · n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 意味のあるすべてのスワップ決定を調査する深さ優先検索を使用してソリューションを構築します。 

1. インデックスから開始`i = 0`元の配列と`k`交換が可能です。 前の接頭辞`i`固定されているとみなされます。 
2. すぐに停止した場合の現在の配列のスコアを計算します。 これはベースライン候補として機能します。 
3. スワップが残っていない場合、または`i`最後に到達したら、計算されたスコアを返します。 
4. それ以外の場合は、現在の立場を改善することを検討してください。 インデックス用`i`、交換してみてください`a[i]`あらゆるポジションで`j ≥ i + 1`。 このようなスワップごとに 1 つの操作が消費され、新しいアレイ構成が生成されます。 
5. スワップ実行後`(i, j)`、インデックスから開始して部分問題を再帰的に解決します。`i + 1`利用可能なスワップが 1 つ少なくなります。 これはその立場を反映しています`i`修正されたので先に進みます。 
6. ポジションをまったく交換しないことも考慮してください`i`に進み、直接次へ進みます。`i + 1`同じ配列と同じ残りのスワップを使用します。 
7. これらすべての選択肢の中から最大の結果を選択します。 

常に左から右に進む理由は、一度ポジションを固定すると、後で変更しても、制御された方法で構造を改善することなくスワップを無駄にするだけだからです。 

### なぜ効果があるのか

 あらゆるポジションで`i`、アルゴリズムは、残りのスワップ バジェットの下でその位置を占める可能性のあるすべての値を列挙します。 最大でも任意の有効なシーケンス`k`スワップにより、インデックスに何らかの値が表示されます。`i`それらの交換の後。 私たちの移行では、候補となる値を適切な位置に導入するためのあらゆる方法が考慮されます。`i`1 回のスワップで、残りのサフィックスを 1 つ少ないスワップで再帰的に処理します。 すべてのスワップは現在の位置に影響を与えるか、実現可能性を変えることなく遅延させることができるため、これは有効なスワップ シーケンスの構造と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def compute_score(arr):
    n = len(arr)
    total = 0
    weight = n
    for x in arr:
        total += x * weight
        weight -= 1
    return total

def dfs(i, k, arr):
    n = len(arr)

    best = compute_score(arr)

    if i == n or k == 0:
        return best

    # option 1: do nothing at position i
    best = max(best, dfs(i + 1, k, arr))

    # option 2: try swapping i with any j > i
    for j in range(i + 1, n):
        arr[i], arr[j] = arr[j], arr[i]
        best = max(best, dfs(i + 1, k - 1, arr))
        arr[i], arr[j] = arr[j], arr[i]

    return best

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(dfs(0, k, a))

if __name__ == "__main__":
    main()
```この実装は、即時バックトラッキングによるインプレース スワップに依存しています。 これにより、各ステップで配列をコピーする必要がなくなり、余分な要素が追加されます。`n`複雑さに。 

スコア関数は必要な場合にのみ再計算されます。 以来`n ≤ 200`、再計算は許容され、再帰ロジックをクリーンに保ちます。 

微妙な点は、スワップ ブランチを探索した後は必ず配列を復元することです。 この復元を忘れると、後のブランチが破損し、誤った結果が暗黙的に生成されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、配列に要素が 1 つしかない場合です。 アルゴリズムはすぐにスコアを計算し、交換や並べ替えができないため、再帰を入力せずに戻ります。 入力用`1 5`配列あり`[7]`、関数は評価します`7 * 1 = 7`そして正しく止まります。 

もう 1 つのケースは、すべての要素が等しい場合です。 どのスワップでも同一の構成が生成されます。 DFS は引き続きスワップ ブランチを探索しますが、スコアはすべての状態で変化しません。 のために`5 2`と`[3, 3, 3, 3, 3]`、すべての再帰パスは同じ加重合計を生成するため、最大値は次の値で安定します。`45`。
