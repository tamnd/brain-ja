 ## 問題の理解

 私たちには順序が与えられています$P$これは、隠された整数配列のプレフィックス関数配列のように動作するはずです$A$。 位置の接頭辞関数$i$最長の長さを教えてください$k$最初の$k$配列の要素は最後の要素と同一です$k$位置で終わる要素$i$。 タスクは配列を再構築することです$A$これは、まさにこのプレフィックス関数シーケンスを生成するか、そのような配列が存在しないと判断します。 

出力は一意ではありません。 プレフィックス関数を計算するときに指定された値を回復する限り、有効な構造はどれでも受け入れられます。$P$。 

この制約により、総当たり攻撃は実行不可能になります。 すべてのテスト ケースの合計の長さは最大です。$2 \cdot 10^5$したがって、テスト ケースごとの二次構築はタイムアウトになります。 これは、次のことを強く示唆しています。$O(n)$または$O(n \log n)$症例ごとの再建。 プレフィックス関数構造は本質的に順方向に線形時間計算可能であるため、逆構築も線形であることが期待されます。 

微妙なエッジ ケースは、プレフィックス配列の一貫性違反です。 たとえば、次のようなシーケンス$P = [0, 2, 1]$すぐには無理なので、$P_2 = 2$インデックスの制約を超えています。 別の失敗例は、暗黙の境界構造がそれ自体に矛盾する場合に発生します。たとえば、$P = [0, 1, 2, 1]$、実際の配列では実現できない互換性のないオーバーラップを強制します。 境界線の一貫性を追跡せずに値を貪欲に割り当てる単純なアプローチでは、計算された接頭辞関数が次の値から逸脱する配列が黙って生成されます。$P$シーケンスの後半で。 

## アプローチ

 直接的なアイデアは、可能な配列をすべて試してみることです$A$接頭辞関数を計算しますが、小さなアルファベットの場合でも、これは指数関数的です。$n$、各位置は複数の値を取ることができるためです。 値を小さなセットに制限したとしても、プレフィックスの重複の一貫性をチェックする必要があり、それにはコストがかかります。$O(n)$候補者ごとに検索するため、全体の検索が不可能になります。 

より構造化されたアプローチは、通常のプレフィックス関数の構築プロセスを逆にすることです。 順方向では、コンピューティング$P[i]$以前に構築された値にのみ依存します。 これは、再構築中に候補配列を維持できることを示唆しています。$A$そして段階的に制約を適用します。 

重要な観察点は、それぞれの位置が$i$前の境界線を延長するか（$P[i] > 0$）またはそれを壊す（とき$P[i] = 0$）。 もし$P[i] > 0$である場合、次のことを確認する必要があります。$A[i] = A[P[i]]$、長さの接頭辞のため$P[i]$で終わるサフィックスと一致する必要があります$i$。 もし$P[i] = 0$、 それから$A[i]$一致してはなりません$A[1]$そうでない場合は、長さ 1 のゼロ以外の境界線が作成され、プレフィックス関数の定義と矛盾します。 

これは、建設的な貪欲な戦略を示唆しています。値を割り当てる$A$によって引き起こされる平等制約を強制しながら、$P[i]$。 新しい値が必要になるたびに、新しいシンボルを導入します。 また、構築中に暗黙的にプレフィックス関数の動作を再計算することにより、暗黙の構造が自己矛盾がないことを検証する必要があります。 

効率は、値を任意の整数ではなく同値クラスとして扱うことで得られます。 各位置は以前の位置をコピーするか、新しいシンボルを導入します。このマッピングは線形時間で維持できます。

 ## アルゴリズムのチュートリアル

 私たちが建設します$A$一貫性を維持しながら段階的に$P$。 

1. 空の配列を初期化する$A$。 整数を記号として使用して、左から右に値を割り当てます。 
2. ポジションごとに$i$、 もし$P[i] > 0$、強制しなければなりません$A[i] = A[P[i]]$。 これは、境界線の要件 (次で終わる接尾辞) を直接エンコードします。$i$長さのプレフィックスと一致する必要があります$P[i]$。 
3. もし$P[i] = 0$に新しいシンボルを割り当てます。$A[i]$ただし、これが以前に暗示された平等制約に違反しない場合に限ります。 もし$i > 1$、この新しいシンボルが一致しないことを確認します$A[1]$そうでない場合は、長さ 1 の境界線が表示されます。 
4.割り当て後$A[i]$、等価制約を伝播できる構造を維持します。 ポジションなら$i$等しいものに割り当てられます$A[j]$、その後のすべての参照$i$この同等性を尊重しなければなりません。 
5. 完全な配列を構築した後、そのプレフィックス関数を線形時間で計算し、それを比較します。$P$。 いずれかの位置で異なる場合は、-1 を出力します。 それ以外の場合、構築された配列は有効です。 

重要な部分は、等価性の伝播を効率的に処理することです。 私たちはポジションを同等クラスの代表として扱い、すべての強制された平等が以前の割り当てと一貫していることを保証します。 あらゆる矛盾は直ちに不可能を意味します。 

### なぜ効果があるのか

 prefix 関数は、配列のセグメント間にどのサフィックスとプレフィックスの重複が存在する必要があるかを完全に決定します。 それぞれの制約$P[i]$必要な等価チェーンを 1 つだけエンコードして前の位置に戻します。 このような制約がすべて満たされている場合、結果として得られる配列は、順方向に再計算されたときに必然的に同じ境界構造を再現します。 この構造により、誤った一致が次の位置に導入されないことが保証されます。$P[i] = 0$、必要な一致はすべて次の場合に強制されます。$P[i] > 0$。 これにより、結果として得られる配列が、プレフィックス関数配列によってエンコードされた一意の組み合わせ構造と一致するようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def compute_prefix(a):
    n = len(a)
    p = [0] * n
    for i in range(1, n):
        j = p[i - 1]
        while j > 0 and a[i] != a[j]:
            j = p[j - 1]
        if a[i] == a[j]:
            j += 1
        p[i] = j
    return p

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        P = list(map(int, input().split()))

        # construct candidate array
        A = [0] * n
        nxt = 1

        ok = True

        for i in range(n):
            if P[i] > 0:
                j = P[i] - 1
                if j < 0 or j >= i:
                    ok = False
                    break
                A[i] = A[j]
            else:
                if i == 0:
                    A[i] = nxt
                    nxt += 1
                else:
                    if A[i - 1] == 1:
                        A[i] = nxt
                        nxt += 1
                    else:
                        A[i] = 1

        if ok:
            if compute_prefix(A) != P:
                ok = False

        print(A if ok else -1)

if __name__ == "__main__":
    solve()
```このコードは、プレフィックス関数が繰り返しを要求するたびに、以前に割り当てられた値を再利用して、配列を左から右に構築します。 いつ$P[i] = 0$、安全な再利用が存在しない限り、新しいシンボルを導入することで、意図しない短い境界線の作成を回避しようとします。 

構築後、プレフィックス関数を再計算して検証します。 ローカル制約ではグローバルな一貫性が完全に保証されないため、この最終チェックは不可欠です。 

微妙な点は、等価性の伝播が、union-find 構造ではなく直接コピーによって暗黙的に処理されることです。 これが機能するのは、すべての等式が常に既に構築されたプレフィックス位置を参照しているためです。そのため、依存関係グラフは非循環であり、1 回のパスで解決できます。

 ## 特殊なケース

 主なエッジケースは次のような場合です$P[i]$超えた点$i-1$。 例えば、$P = [0, 2, ...]$。 で$i = 2$、長さ 2 のプレフィックスに長さ 2 のボーダーが必要ですが、これはプレフィックス全体がゼロシフトされたサフィックスと一致することを意味し、適切なボーダー定義に矛盾するため不可能です。 アルゴリズムはインデックスの有効性をチェックすることでこれを直ちに拒否します。 

もう 1 つの微妙なケースは、ゼロ制約が繰り返されることです。 のために$P = [0, 0, 0, 0]$、シンボルを単純に再利用すると、次のような意図しない境界線が誤って導入される可能性があります。$A[i] = A[i-1]$、ゼロ以外の接頭辞関数を作成します。 この構造では、再利用が以前の強制パターンに一致する場合は必ず新しいシンボルを導入し、必要に応じてすべてのプレフィックスが一致しない状態を維持することでこれを回避します。
