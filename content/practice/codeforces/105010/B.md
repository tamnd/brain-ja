 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 各シナリオには、$N$チャンピオンにはそれぞれ初期の強さの値があります。 単一の操作を使用して各チャンピオンを最大 1 回変更することができます。$K$、それを減らします$K$、または変更しないままにしておきます。 これらの選択をすべてのチャンピオンに個別に適用した後、結果として生じる強さを確認し、最大値と最小値の差を計算します。 課題は、この最終的な違いをできるだけ小さくする方法で操作を選択することです。 

重要な制約は、$N$テスト ケースあたり最大 1000、合計$N$これは、すでに 5000 回までのテストで、$O(N^2)$または$O(N \log N)$テスト溶液ごとに 1 つずつ行うことは許容されますが、テストごとに 3 次元のものを 500 回繰り返すと遅すぎます。 の値$P_i$大きい、最大$10^9$したがって、周波数配列や小さな範囲に関連付けられた値の圧縮に依存することはできません。 

素朴なアプローチではすべてを試してしまうだろう$3^N$プラス、マイナス、または変化なしの割り当て。 たとえ$N=20$、これは爆発するため、問題の構造では、より制限された決定スペースを許可する必要があります。 

微妙なエッジケースが現れるのは、$K = 0$。 この状況では、3 つの操作はすべて同一であり、答えは単純に元の最大値から最小値を引いたものになるはずです。 もう 1 つの特殊なケースは、すべてが$P_i$等しい。 その場合、考えられる最良の答えは 0 のいずれかです ($K=0$) または、スプレッドを変更せずにすべての値を一貫してシフトできるため、0 のままです。 

## アプローチ

 強引な考え方は、各要素への演算の割り当てをすべて考慮することです。 各要素について、次から選択します。$\{P_i - K, P_i, P_i + K\}$を計算し、結果の範囲を計算します。 これは探索します$3^N$テストケースごとの構成、さらには$N=30$それは完全に不可能になります。 各要素が状態空間を独立して分岐するため、コストは指数関数的に増加します。 

この問題をより単純にする構造は、実際には個々の割り当てを気にせず、最終的な最小値と最大値だけを気にすることです。 配列がソートされると、極端な値が答えを支配します。 重要な観察は、最適な構成は、配列を 2 つのグループに「分割」する場所にのみ依存するということです。一部の要素は、次のグループによってプッシュダウンされます。$K$そしていくつかは押し上げられました$K$、おそらくオプションの中間グループが付いています。 

配列をソートした後、境界インデックスを修正することを検討してください。$i$。 左側のすべての要素は、次のように削減される候補として解釈できます。$K$、右側のすべての要素は、次のように増加される候補です。$K$。 グループ内での混合割り当ては、極端な問題を改善せずに局所的な広がりを増やすだけであるため、役に立ちません。 

これにより、問題はチェックのみに減ります$N-1$分割ポイント。 分割ごとに、減算後の左側の部分の中で可能な最小値を計算します。$K$と、加算後の右側の部分のうち取り得る最大値$K$。 最良の答えは、そのようなすべての分割における最小値です。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(3^N \cdot N)$|$O(N)$| 遅すぎる |
 | 分割 + 並べ替え |$O(N \log N)$|$O(1)$追加 (入力以外) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. べき乗の配列を降順でない順に並べ替えます。 これにより、左右への分割が値空間内の意味のあるしきい値に対応することが保証されます。 
2. 可能な最大値の差として最初の答えを計算します。$P_{N-1} + K$および可能な最小値$P_0 + K$または$P_0 - K$, しかし、これを分割を通じて改良していきます。 これによりベースラインが提供されます。 
3. すべてのインデックスについて$i$から$0$に$N-2$、2 つのグループ間の分割点として扱います。 インデックスの要素$[0, i]$によって減少すると考えられます$K$、インデックスの要素$[i+1, N-1]$によって増加することが検討されています$K$。 
4. 左のグループについて、演算後の可能な最小値は次のとおりです。$P_0 - K$、そして最大のものは$P_i - K$。 適切なグループの場合、最小のものは次のとおりです。$P_{i+1} + K$、そして最大のものは$P_{N-1} + K$。 最終的な範囲で重要となる唯一の候補は次のとおりです。 

最小限の$P_0 - K$そして$P_{i+1} + K$、および最大値$P_i - K$そして$P_{N-1} + K$。 
5. この分割の範囲を次のように計算します。$$\max(P_i - K, P_{N-1} + K) - \min(P_0 - K, P_{i+1} + K)$$6. すべての分割の最小値を取得します。 
7. また、分割を使用しない場合と比較してください。これは、スプレッドが小さい方に応じて、すべての要素を均一に増減できるためです。 

なぜ効果があるのか

 ソート後、範囲を増やすことなく、すべての「減少」の選択肢がプレフィックスを形成し、すべての「増加」の選択肢がサフィックスを形成するように、最適な割り当てを変換できます。 大きい要素が減少し、小さい要素が減少しないパターンがある場合、それらの操作を交換しても最大値を増やしたり最小値を減らしたりすることはできませんが、通常は範囲を改善または維持します。 この交換引数により、最適解が単一のしきい値構造に強制的に組み込まれ、分割点の列挙が十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        # baseline: all +K or all -K gives same range as original
        ans = a[-1] - a[0]

        for i in range(n - 1):
            high = max(a[i] - k, a[-1] + k)
            low = min(a[0] + k, a[i + 1] - k)
            ans = min(ans, high - low)

        print(ans)

if __name__ == "__main__":
    solve()
```解決策は並べ替えから始まります。後の推論はグローバルな順序で隣接する値を比較することに依存するため、これは不可欠です。 ベースラインの答えは、分割が有益ではない場合に対処します。 

ループ内では、各インデックスが「減少グループ」と「増加グループ」の間の仮想的な境界として機能します。 の計算`high`そして`low`2 つの変換を適用した後の最悪の極端な状況をキャプチャします。 減算により結果の範囲が得られます。 

よくある実装上の間違いは、ベースライン ケースを含めるのを忘れることです。これは次の場合に重要です。$K = 0$または、分割しても範囲が改善されない場合。 もう 1 つの微妙な点は、正しく使用することです。$a[i]$そして$a[i+1]$境界の代表者として。 これらのインデックスを混合すると、計算された間隔でオフバイワンのエラーが発生します。

 ## 特殊なケース

 いつ$K = 0$、割り当てに関係なく、すべての要素は変更されません。 アルゴリズムは引き続きベースラインを次のように計算します。$a[-1] - a[0]$、そしてすべての分割は同じ値を生成します。$+K$そして$-K$は同一です。 すべての構成の最小値は正しいままです。 

いつ$N = 1$、並べ替えると単一の要素が生成されます。 分割点を巡るループは実行されず、答えは直接次のようになります。$a[0] - a[0] = 0$、単一の値には広がりがないという事実と一致します。 

すべての値が等しい場合、唯一の変化は適用によって生じます。$+K$または$-K$。 アルゴリズムは分割式の両極端を正しく考慮しており、最良の戦略はすべての要素に同じ方向を割り当て、次の要素に応じてゼロまたは対称の広がりを生成することです。$K$ただし、ベースラインまたは極端を折りたたむ分割によって常に正しく最小化されます。
