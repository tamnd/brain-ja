 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、時間の経過に伴う一連の価格が含まれています。 タスクは、価格が厳密に段階的に上昇するすべての連続した時間セグメントを調べ、そのセグメントの開始から終了までの価格の上昇量を測定することです。 このような増加するストレッチの中で、私たちは可能な限り最大の上昇を望んでいます。 

より正確には、次の値が前の値よりも厳密に大きいすべての連続する部分配列を考慮します。 このような各サブ配列について、最後の値と最初の値の差をとります。 テスト ケースの答えは、すべての有効なサブ配列にわたる最大の差異です。 

制約は直接的な意味で重要です。 テスト ケース全体のすべてのシーケンスの合計長は 100 万に達することがあります。 これにより、すべてのサブ配列、さらにはサブ配列内のすべてのペアを検査しようとするソリューションは即座に除外されます。これらのアプローチは二次関数の動作に向かってドリフトし、制限時間を超えてしまうためです。 テストケースごとにリニアスキャンが必要です。 

いくつかのエッジな状況は、誤って対処しやすいものです。 

1 つのケースは、シーケンスがまったく増加しない場合です。 たとえば、次のように入力します`5 4 3 2 1`には 1 要素よりも長く、厳密に増加する連続した部分配列が含まれていないため、答えは 0 です。 

もう 1 つのケースは、等しい値が出現する場合です。 例えば、`1 2 2 3`等しいペアで増加条件を破ります。 セグメント`1 2`違いを与える`1`、 そして`2 3`違いを与える`1`、したがって、答えは次のとおりです`1`、 ない`2`。 厳密さを無視した不注意なアプローチでは、セグメントが誤ってマージされる可能性があります。 

3 番目のケースは、単一要素の配列です。 値が 1 つだけの場合、有効な増加は存在しないため、答えはゼロになります。 

## アプローチ

 強引なアイデアは、考えられるすべての開始インデックスを列挙し、シーケンスが厳密に増加し続ける間に前方に拡張し、開始とすべての有効な終了の間の差を計算することです。 これにより、増加するすべてのサブ配列が正しくチェックされます。 ただし、完全に増加する配列の最悪のケースでは、各開始点が末尾まで拡張され、およそ N + (N-1) + ... + 1 回の演算が行われ、テスト ケースごとに O(N²) になります。 合計 N が 10⁶ に達すると、これは非常に遅くなります。 

重要な観察は、厳密に増加する最大の連続セグメントは予測どおりに動作するということです。 このようなセグメント内では、すべての要素が前の要素よりも大きいため、最小値は最初の要素、最大値は最後の要素になります。 その中のすべての有効なサブ配列は、セグメント全体を最初から最後まで取得するよりも小さいか等しい差を生成します。 これは、内部サブセグメントをまったく考慮する必要がないことを意味します。 

したがって、タスクは配列を厳密に増加する最大の実行に分割することになります。 実行ごとに、エンドポイントの差だけが必要です。 現在の増加する実行の開始を追跡し、条件が維持される間延長し、実行が中断されるたびに答えを更新します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | お(1) | 遅すぎる |
 | 最適 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、現在の増加セグメントを維持しながら配列を左から右にスキャンします。 

1. 新しいセグメントをインデックス 0 から開始します。その開始値を現在の実行の最小候補として保存します。 これは、現在の厳密に増加するブロックの最初の要素を表します。 
2. 配列内を左から右に移動します。 現在の値が前の値より厳密に大きい場合は、同じ増加セグメント内に留まります。 それ以外の場合、セグメントは前の位置で終了します。 
3. セグメントが終了すると、その寄与度を最後の値から最初の値を引いたものとして計算します。 これが大きい場合は、グローバル回答を更新します。 
4. ブレークは増加するプロパティがこの境界を越えて継続できないことを意味するため、現在の位置で新しいセグメントを開始します。 
5. ループが終了したら、ブレークで終了しないため、最後のセグメントの処理を忘れないでください。 

### なぜ効果があるのか

 厳密に増加する最大の連続セグメント内では、すべてのプレフィックスの最小値が最初の要素であり、すべてのサフィックスの最大値が最後の要素です。 セグメント内の有効な増加するサブ配列は、最初の要素がセグメントの開始点以上で、最後の要素がセグメントの終了点より大きくないため、その差はセグメント全体の差を超えることはできません。 したがって、グローバル最大値を取得するには、セグメント境界のみを考慮するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        if n == 1:
            print(0)
            continue
        
        ans = 0
        start = a[0]
        
        for i in range(1, n):
            if a[i] > a[i - 1]:
                continue
            else:
                ans = max(ans, a[i - 1] - start)
                start = a[i]
        
        ans = max(ans, a[-1] - start)
        print(ans)

if __name__ == "__main__":
    solve()
```ソリューションは単一のポインターを維持します`start`これは、現在厳密に増加している実行の最初の要素を表します。 実行が中断されると、最後の要素を次の要素と比較して前のセグメントを終了します。`start`。 これにより、セグメント境界を明示的に保存することが回避されます。 

ループ後の最後の更新は不可欠です。最後のセグメントはブレーク条件に遭遇しないため、そうしないとその寄与が失われるからです。

        n = int(input())

        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 次のような単一要素配列の場合`10`、アルゴリズムが初期化されます`start`増加するセグメントを形成できる遷移がないため、ただちにゼロが出力されます。 最後の貢献度`a[-1] - start`はゼロになり、正しい結果と一致します。 

次のような厳密に減少する配列の場合`5 4 3 2`、すべてのステップがセグメントのブレークをトリガーします。 各セグメントの開始値と終了値は同一であるため、それぞれの値はゼロになります。 アルゴリズムが繰り返しリセットされる`start`正しく、非増加部分をマージすることはありません。 

次のような等しい隣接する値を持つ配列の場合`1 2 2 3`の場合、等号は 2 つの 2 の間のセグメントを分割します。 アルゴリズムがセグメントを完成させます`1 2`1 を与えると、2 で新しいセグメントが開始され、その後、`2 3`したがって、最大値は 1 として正しく計算されます。
