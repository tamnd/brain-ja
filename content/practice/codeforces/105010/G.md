 ## 解決策
 ## 問題の理解

 黒と白の 2 つの可能な色で埋められた、最大 5 × 5 の非常に小さなグリッドが与えられます。 ゲームは同じ色の接続された領域を繰り返し削除し、削除するたびにグリッドの物理的な再構成が発生します。上のセルが落ちて隙間を埋め、空の列が右に押し出されて、すべての空のスペースがグリッドの右上の 1 つのブロックに収まります。 

1 つの移動は 1 つのセルを選択することによって定義され、そのセルの同じ色の連結成分全体 (上下左右の伝播のみが記述されているため、4 方向の隣接によって) が一度に消えます。 重力と柱の圧縮が適用されると、グリッドは新しい状態になります。 目標は、色の付いたセルがなくなるまでこのプロセスを繰り返し、移動の数を最小限に抑えることです。 

重要な観察は、移動するたびにグリッドが局所的に部分的に変更されるだけでなく、重力と列の圧縮によって完全に正規化されるということです。 つまり、局所的には異なって見える多くの異なる中間形状が、これらのルールの下では同等であるということです。 

制約は非常に小さく、n と m は最大 5 であるため、セルの総数は最大 25 です。これにより、枝刈りを行わない大規模な状態表現や指数関数的分岐に依存するアプローチは即座に除外されます。 ただし、各セルに 2 つの色があるにもかかわらず、正規化ステップにより効果的な分岐が大幅に減少するため、グリッド構成空間全体が状態をグラフ検索して探索できるほど十分に小さいことが強く示唆されます。 

単純なアプローチでは、メモ化せずに、すべての一連の動きを貪欲に、または再帰的にシミュレートしようとする可能性があります。 同じ中間グリッドにはさまざまな方法で到達でき、同じ状態を繰り返し探索することになるため、これは失敗します。 たとえば、2 つの異なる削除命令により同じ圧縮された構成が生成される可能性がありますが、単純な DFS ではそれらが別々に扱われ、指数関数的な爆発につながります。 

もう 1 つの微妙な失敗例は、重力とコラム シフトの不適切な処理に起因します。 たとえば、垂直重力のみを適用し、列の圧縮を忘れた場合、正規化後に同一であるはずのグリッドが別個の状態として扱われ、不正確な最小カウントが発生します。 

## アプローチ

 ブルートフォースのアイデアは単純です。現在のグリッドからあらゆる可能な手を試します。 空ではない各セルについて、その連結コンポーネントの削除をシミュレートし、重力と列の圧縮を適用して、再帰します。 これは、考えられるすべての動きのシーケンスを調査するため、正しいです。 

ただし、問題は、セル数が 25 個しかないにもかかわらず、分岐係数が大きいことです。 最悪の場合、すべてのセルが個別のコンポーネントとなり、最初の動きで最大 25 の選択肢が与えられ、その後はわずかに少なくなる可能性があります。 メモ化を行わないと、特に異なる移動順序によって同じ結果のグリッドが複数回生成されるため、検索ツリーが簡単に数十億の状態に爆発する可能性があります。 

重要な洞察は、グリッドが小さく、各移動後に完全に決定的であるため、正規化されたそれぞれの異なるグリッド状態をグラフ内のノードとして扱うことができるということです。 初期状態から空のグリッドまでの最短パスを探します。 これは当然、重み付けされていないグラフでは最短経路問題となり、メモ化された最小化を備えた BFS または DFS を使用して解決できます。 

重要な改善点は、状態の正規化です。 移動するたびに、グリッドを標準形式に圧縮します。つまり、空のセルを下にドロップし、空の列を右にシフトします。 これにより、同一の構成が常に同じ方法で表現されるようになり、再計算を避けることができます。 

次に、これらの正規の状態に対して BFS を実行します。 各状態遷移は、色の接続されたコンポーネントを 1 つ選択し、それを削除することに対応します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DFS | 指数関数 (≈ O(25!)) | O(深さ) | 遅すぎる |
 | 正規状態に対する BFS | O(S × 25²) | O(S) | 承認済み |

 ここで S は到達可能なグリッド構成の数ですが、積極的な圧縮と小さなグリッド サイズにより小さくなります。 

## アルゴリズムのチュートリアル

 グリッドを文字列のタプルとして表し、重力と列圧縮が適用されるように常に正規化されます。 

1. グリッドを読み取り、重力と列の圧縮をシミュレートすることにより、グリッドを直ちに標準状態に変換します。 これにより、BFS は初期構成の一意の表現から開始されることが保証されます。 
2. 状態とセルを指定して、グリッド上の BFS または DFS を使用して、同じ色の近傍に制限されたセルの連結成分を計算する関数を定義します。 これにより、1 回の移動で削除されるものが正確に特定されます。 
3. 遷移関数を定義します。有効な開始セルごとに、それらのセルを空としてマークして連結成分を削除し、列方向に重力を適用して、空の列を右にシフトして、新しい標準グリッドを生成します。 
4. BFS を初期状態から実行します。 各状態は、その距離に到達するまでに使用された移動数を表す距離を保存します。 
5. 状態を展開するときは、すべてのセルを反復処理します。 空ではないすべてのセルについて、1 回移動した後の結果の状態を生成します。 これまでに見たことがない場合は、その距離を記録し、キューに押し込みます。 
6. 空のグリッドに到達したら停止します。BFS は、最初にそのグリッドに到達した時点が最適であることを保証します。 

重要な点は、すべての移動後に正規化を確実にすることです。 これがないと、同一のグリッドが異なる状態として表示され、BFS が過剰にカウントしたり、最適なパスを見逃したりする可能性があります。 

### なぜ効果があるのか

 このアルゴリズムは、ノードが完全に正規化されたグリッドであり、エッジが有効な動きである暗黙的なグラフを構築します。 各移動には等しいコストがかかります。 BFS は重み付けされていないグラフ内の最短パスを保証するため、最初に空の構成に到達した時点が最小移動数に相当します。 正規化により、各物理構成が 1 つのノードに正確に対応することが保証され、状態の重複が防止され、距離の正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

n, m = map(int, input().split())
grid = [list(input().strip()) for _ in range(n)]

def normalize(g):
    # gravity
    cols = []
    for j in range(m):
        col = []
        for i in range(n-1, -1, -1):
            if g[i][j] != '.':
                col.append(g[i][j])
        col += ['.'] * (n - len(col))
        cols.append(col)

    # shift columns
    new_cols = [col for col in cols if any(x != '.' for x in col)]
    empty_cols = [ ['.'] * n for _ in range(m - len(new_cols)) ]
    cols = new_cols + empty_cols

    res = [['.'] * m for _ in range(n)]
    for j in range(m):
        for i in range(n):
            res[i][j] = cols[j][i]
    return tuple(''.join(row) for row in res)

def get_component(g, si, sj):
    color = g[si][sj]
    q = deque([(si, sj)])
    vis = set([(si, sj)])
    comp = []
    while q:
        x, y = q.popleft()
        comp.append((x, y))
        for dx, dy in ((1,0),(-1,0),(0,1),(0,-1)):
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                if (nx, ny) not in vis and g[nx][ny] == color:
                    vis.add((nx, ny))
                    q.append((nx, ny))
    return comp

def apply_move(g, comp):
    g = [list(row) for row in g]
    for x, y in comp:
        g[x][y] = '.'
    return normalize(g)

start = normalize(tuple(''.join(row) for row in grid))

if all(c == '.' for row in start for c in row):
    print(0)
    sys.exit()

dist = {start: 0}
q = deque([start])

while q:
    cur = q.popleft()
    d = dist[cur]

    g = [list(row) for row in cur]

    for i in range(n):
        for j in range(m):
            if g[i][j] == '.':
                continue
            comp = get_component(g, i, j)
            nxt = apply_move(g, comp)
            if nxt not in dist:
                dist[nxt] = d + 1
                q.append(nxt)

    if all(c == '.' for row in cur for c in row):
        print(d)
        break
```このソリューションは、すべてのグリッドを正規形式に即座に変換するため、検索で同等の構成が分岐することはありません。 BFS ループは、フラッド フィルを介して接続されているすべてのコンポーネントを列挙することにより、各状態からの考えられるすべての最初の動きを調査します。 削除ステップではこれらのセルを空に設定し、正規化によって不変構造を復元します。 

唯一の注意が必要な部分は、正規化中にグリッドを列リストに再構築することです。 これにより、重力とカラム圧縮の両方が説明どおりに正確に適用されるようになります。 順序にずれがあると、同じ状態の複数のエンコードが発生し、BFS の最適性が損なわれます。 

## 実用的な例

 ### サンプル 1

 最初に初期グリッドが正規化され、次に BFS が開始されます。 

| ステップ | 状態 (概念的) | アクション | 距離 |
 | --- | --- | --- | --- |
 | 0 | 初期グリッド | 開始 | 0 |
 | 1 | 最初のコンポーネントを削除した後 | 1 つの領域を削除する | 1 |
 | 2 | 縮小されたグリッド | 2 番目の領域を削除 | 2 |
 | 3 | 空のグリッド | 最後の動き | 3 |

 BFS は 3 回の拡張後に空の構成に達します。これは、最小移動数が 3 であることを意味します。これにより、さまざまな削除順序が探索されますが、最も短いシーケンスのみが保持されることが確認されます。 

### サンプル 2

 | ステップ | 状態 | アクション | 距離 |
 | --- | --- | --- | --- |
 | 0 | フルグリッド | 開始 | 0 |
 | 1 | 大規模なマージされた削除 | 最大のコンポーネントを削除します | 1 |
 | 2 | 残りのコンポーネントを削除 | 2番目の動き | 2 |
 | 3 | 空 | 完了 | 2 |

 ここで、BFS は、大きなコンポーネントを 1 回削除し、その後にクリーンアップを 1 回実行するだけで十分であると判断します。 この構造は、マージの決定はグローバルに重要であるため、小さなコンポーネントの貪欲な削除が失敗する理由を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(S × 25²) | 各状態は最大 25 個の開始セルを探索し、各コンポーネントの BFS はグリッド サイズ | によって制限されます。 
| スペース | O(S) | 個別の正規化されたグリッドはそれぞれ、BFS キューとディクショナリに一度保存されます。 

グリッド サイズは最大 25 セルであるため、各状態の操作は定数で制限されます。 各移動後の強力な正規化により、到達可能な状態の数は管理可能なままです。 これにより、最悪の分岐シナリオでも BFS が制限内に収まるようになります。

 ## 特殊なケース

 重要なエッジケースは、1 つのコンポーネントを除去すると、重力の影響で離れたセルが接続される場合です。 たとえば、単一の削除されたブロックによって分割された垂直スタックは、圧縮後にのみ、より大きなコンポーネントにマージできます。 次の動きが考慮される前にすべての状態が再正規化されるため、BFS はこれを正しく処理します。 

もう 1 つのエッジ ケースは、複数の異なる動きによって同じ結果のグリッドが得られる場合です。 訪問した正規状態を保存しないと、BFS はそれらを繰り返し再訪問し、過剰にカウントしてしまいます。 訪問した状態の辞書により、構成が一度処理されると再検討されることがなくなり、正確性と効率性の両方が維持されます。
