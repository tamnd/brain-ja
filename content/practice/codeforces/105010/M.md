 ## 解決策
 ## 問題の理解

 各クエリは、サイズのモジュラー グリッド ユニバースを記述します。$n \times m$、ポジションが構造化された方法でラップされます。 決まった時間に、$nm$それぞれに番号が付けられた個人$k$、そして各個人は時間の経過とともにグリッドセル全体で決定的な軌道をたどります。 動きは時間的に線形ですが、混合モジュラスを通じて投影されます。x 座標は時間スケールのインデックスの整数除算に依存し、y 座標はモジュロ成分に依存します。 

具体的には、日中$d$、 人$k$にあります$$x = \left(\left(\frac{dk}{m}\right) \bmod n\right), \quad y = (dk) \bmod m.$$クエリはこう尋ねます: すべての中で$k \in [0, nm-1]$、ターゲットセルに正確に着地する数$(x,y)$当日$d$。 

制約が非常に大きいため、個人ごとのシミュレーションは不可能です。 まで$10^5$クエリと$nm$潜在的に到達する$10^{18}$、 平$O(nm)$クエリごとには実行できません。 平$O(\sqrt{nm})$クエリは独立しており、構造を共有していないため、このアプローチは明らかに実行可能ではありません。 

単純な試みでは、すべてを反復しようとするでしょう$k$そしてその軌道が着地するかどうかを確認します$(x,y)$。 それには費用がかかります$O(nm)$クエリごとに、すぐに制限を超えます。 

より微妙な故障モードは、座標間の独立性を仮定することで得られます。 両方の座標は同じ製品に依存しているため、$dk$、ただし、除算と法によって分割されるため、x と y を別々に扱うと、誤ったカウントが発生します。 たとえば、行または列全体に一様な分布があると仮定すると、整数の除算によって生じる結合が無視されます。 

## アプローチ

 重要な問題はマッピングの構造です$$k \mapsto (dk \bmod m, \lfloor dk/m \rfloor \bmod n).$$これは任意の関数ではありません。 それはまさに乗算です$d$、続いて結果をbase-で解釈します。$m$、次に高位部分モジュロを小さくします$n$。 言い換えれば、すべての$dk$ペアを誘発します:$$t = dk, \quad y = t \bmod m, \quad x = \lfloor t/m \rfloor \bmod n.$$したがって、問題は次の倍数を数えるということになります。$d$範囲内で$$t \in \{0, d, 2d, \dots, d(nm-1)\}$$商と剰余の固定分割条件を満たす$m$そして$n$。 

という観点から考えるのではなく、$k$、等差数列モジュロに視点を移します。$nm$。 すべての計算は次のように調整されるため、$m$そして$n$、構造はピリオドで繰り返されます$nm / \gcd(d, nm)$。 これにより、問題は 2D モジュラー格子の線形マップの剰余を数えることに変換されます。 

重要な観察は、$t = dk$でサブグループを形成します$\mathbb{Z}_{nm}$、各状態はグリッドへの決定論的な投影に対応します。 指定されたプリイメージの数$(x,y)$は、ゼロか、ターゲット ファイバーに限定されたこの線形マッピングのスタビライザーのサイズと同じです。 

それが有効であることを示すことができます$k$合同系の解に対応します。$$dk \equiv y \pmod m$$そして$$\left\lfloor \frac{dk}{m} \right\rfloor \equiv x \pmod n.$$最初の条件制約$k$モジュロ$m / \gcd(d,m)$。 2 番目の条件に解を代入すると、問題は 1 つの算術一貫性条件をチェックし、有効な条件がいくつあるかを数えるようになります。$k$寝そべる$[0, nm-1]$。 

これにより、モジュラー逆関数と gcd 演算を使用したクエリごとの定数時間のソリューションが得られます。

 ## アルゴリズムのチュートリアル

 1. 方程式から始める$dk = t$、 どこ$t$の倍数にわたる範囲$d$。 目標は、これがいつ起こるかを特徴付けることです$t$与えられた場所に着地する$(x,y)$商と余りに分割した後$m$。 この再定式化は、個々のエージェントへの依存を取り除き、算術構造に焦点を当てます。 
2. 座標条件を単一の制約に変換します。$t$。 必要です$$y = t \bmod m, \quad x = \left(\frac{t - y}{m}\right) \bmod n.$$これは両方の座標を次のように直接表現します。$t$からマッピングを単射的にします。$t$グリッド状態に。 
3. 交換する$t$と$dk$で 2 つの合同式が得られます。$k$。 最初のものは、$dk \equiv y \pmod m$、次の場合にのみ解決可能です。$\gcd(d,m)$分割する$y$。 これが失敗した場合、有効なものはありません$k$存在します。 
4. 解ける場合は、gcd で除算して最初の合同式を小さくします。 これにより、一意の剰余クラスが生成されます。$k$モジュロ$m / \gcd(d,m)$。 このステップでは、無限構造を周期的な等差数列に圧縮します。 
5. 結果のパラメータ化を次のように置き換えます。$k$商を含む 2 番目の制約に代入します。 これは、次の線形式が誘導されたかどうかをチェックすることに帰着します。$k$マッチ$x \bmod n$。 この構造により、これが検索ではなく単一の整合性チェックになることが保証されます。 
6. の値がいくつあるか数えます。$k$で$[0, nm-1]$導出された剰余クラスを満たします。 有効な解は等差数列を形成するため、答えはゼロか、範囲長を係数ステップで単純に除算したものになります。 

### なぜ効果があるのか

 変換により、元の動きは整数から有限アーベル群への線形マップに変換されます。$\mathbb{Z}_n \times \mathbb{Z}_m$。 すべてのクエリは、によって生成されたサブグループに限定されたこの準同型性のファイバーのサイズを求めます。$d$。 このような設定での繊維サイズは、システムが一貫しているときは常に均一であるため、カウントが合同式の可解性のチェックとサブグループ指数の測定に軽減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def egcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = egcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def modinv(a, mod):
    g, x, _ = egcd(a, mod)
    if g != 1:
        return None
    return x % mod

def solve():
    Q = int(input())
    out = []

    for _ in range(Q):
        n, m, x, y, d = map(int, input().split())

        g = __import__("math").gcd(d, m)

        if y % g != 0:
            out.append("0")
            continue

        m1 = m // g
        d1 = d // g
        y1 = y // g

        inv = modinv(d1, m1)
        if inv is None:
            out.append("0")
            continue

        k0 = (y1 * inv) % m1

        # Now k = k0 (mod m1), check consistency with x
        # derive t = d*k, compute quotient
        t = d * k0
        x_calc = (t // m) % n

        if x_calc != x:
            out.append("0")
            continue

        # count k in [0, nm-1] satisfying k ≡ k0 (mod m1)
        limit = n * m
        if k0 >= limit:
            out.append("0")
        else:
            # arithmetic progression count
            out.append(str((limit - 1 - k0) // m1 + 1))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策により、弾性率の相互作用が 2 つのフェーズに分離されます。 最初のフェーズでは、gcd バリアを削除した後、モジュラー反転を使用して剰余制約を解決します。 第 2 フェーズでは、マップされた値を直接再構成して商の条件を検証します。 

実装の微妙な詳細は、モジュラー逆行列の処理です。最初に gcd による Reduce に失敗すると、不正確な逆計算が行われます。 もう一つのポイントは再構築のステップです`t = d * k0`これは、すべての有効な解が同じ剰余クラスを共有するため機能し、単一の代表をチェックするだけで十分です。

 ## 特殊なケース

 主なエッジケースは次の場合に発生します。$y$で割り切れない$\gcd(d,m)$。 たとえば、$m=6$、$d=4$、$y=3$、 我々は持っています$\gcd=2$そして$y \bmod 2 \neq 0$したがって、解決策は存在しません。 アルゴリズムは、反転を試みる直前にこれを捕捉し、不正確なモジュラー演算を防ぎます。 

別のケースは、換算係数が 1 になるときに発生します。$k$は剰余条件を満たしており、正しさは商のチェックに完全に依存します。 逆モジュラーが自明になり、累進カウントが全範囲の算術カウントに単純化されるため、アルゴリズムはこれを自然に処理します。 

3 番目のケースには大規模な問題が含まれます。$d$中間生成物が$10^{18}$。 意味のあるチェックではすべての除算が乗算の前に行われるため、Python の任意精度によって正確さが保証され、オーバーフロー処理は必要ありません。
