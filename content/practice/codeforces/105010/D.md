 ## 問題の理解

 正の整数の配列と固定の奇数整数が与えられます。$k$。 2 人のプレイヤーが交代でアレイを変換します。 移動は、2 つの要素を選択し、それらを削除し、それらの合計を追加することで構成されます。 自分のターンを開始し、配列内のすべての要素が次の値で割り切れることに気付いたプレイヤー$k$すぐに負けます。 

追加のグローバル制約があります。配列内のすべての要素の合計は、次で割り切れることが保証されます。$k$。 これは、すべての操作で合計が保持されるため、状態空間がその合同クラスから離れることがないため重要です。 

この動きに関する重要な観察点は、合計額は変更されず、値が再分配されるだけであるということです。 負け条件にとって実際に重要なのは、モジュロが非ゼロの要素がいくつあるかです。$k$要素が「安全」であるのは、要素が次の要素で割り切れる場合のみだからです。$k$。 

入力サイズは最大です$10^5$したがって、動きを明示的にシミュレートする解決策は不可能です。 移動するたびに配列サイズが 1 ずつ減少するため、$O(n)$移動は合計ですが、各移動には構造の検索と更新が含まれます。 単純なシミュレーションでは、モジュラー バケットを繰り返しスキャンしたり保守したりする必要があるため、簡単に劣化してしまいます。$O(n^2)$。 

エッジケースは主に構造的なものです。 

すべての要素がすでに割り切れる場合$k$、最初のプレイヤーはすぐに負けます。 

ちょうど 2 つの要素が次の要素で割り切れない場合$k$、最初の動きはいつでもそれらを組み合わせて次の倍数にすることができます。$k$総和制約により、それらの剰余が相互に補完されるようになるためです。 

非倍数が多い場合$k$、ゲームは、「悪い」要素を取り除くことと、対戦相手がクリーンな状態に直面するかどうかを制御することとの間の同等の競争になります。 

微妙な失敗例は、ソリューションが非倍数の貪欲なペアリングが常に機能すると想定している場合に発生します。 たとえば、パリティ制約によりきれいにペアリングできない残基の場合、単純なペアリングが可能であるように見えても、不一致を強制すると、強制的な損失位置が発生します。 

## アプローチ

 直接のシミュレーション ビューは簡単です。2 つの要素を繰り返し選択して結合し、残りのすべての要素が次の要素で割り切れるかどうかを確認します。$k$。 これは正しいですが、各ステップでアレイをスキャンしたり、頻繁に更新を必要とする構造を維持したりする必要があるため、コストがかかります。 と$n$まで$10^5$、これは二次関数の動作につながります。 

重要な洞察は、要素の正確な値は重要ではなく、その剰余のモジュロのみが重要であるということです。$k$。 移動には 2 つの剰余が必要です$a$そして$b$それらを次のように置き換えます$a+b \pmod{k}$。 ゲームは完全に、非ゼロモジュロである要素がいくつあるかにかかっています。$k$、およびこれらの残基がペアリングによってどのように除去されるかについて説明します。 

合計は以下で割り切れるので、$k$、すべての剰余の合計も次で割り切れます。$k$。 これにより、バランス条件が強制されます。ゼロ以外の剰余は集合的にモジュロを打ち消す必要があります。$k$これにより、有効な終了状態の構造が大幅に制限されます。 

ここで、ゲームは次の要素で割り切れない要素がいくつあるかを数える作業に移ります。$k$。 移動するたびに配列サイズが 1 つずつ減少しますが、さらに重要なのは、残っている「不良」要素の数が変化することです。 2 つの良い要素、または 1 つの良い要素と 1 つの悪い要素が関係する手は、構成をさまざまに変更しますが、ゲーム理論の観点から、唯一意味のある状態は、非倍数の数です。$k$。 

最適な戦略はパリティ ゲームに崩壊します。 非倍数の数がゼロの場合、現在のプレイヤーは負けます。 1 つの場合、ゲーム構造により直接解決が強制されます。 それ以上の場合、強制ペアリングの性質と剰余合計の合計が不変であるため、対戦相手を常に負けているパリティに保つ能力は、カウントから 1 を引いた値が偶数であるか奇数であるかによって決まります。 

これにより、単純な分類が得られます。結果は、要素の数が次数で割り切れるかどうかによってのみ決まります。$k$強制削減下では 1、または 1 より大きく、奇数/偶数です。

 ## アルゴリズムのチュートリアル

 ### 重要なアイデア

 すべての数値を剰余的に削減します$k$そしてゼロ以外のものがいくつあるか数えます。 

### ステップ

 1.読む$n$、$k$、および配列。 

の値$k$奇数であることは、偶数/奇数剰余の動作を崩壊させる可能性のあるモジュロペアリングの隠れた対称性を保証しないため、間接的にのみ問題になります。 
2. コンピューティング$c$、要素の数$A_i$そのような$A_i \bmod k \neq 0$。 

割り切れる要素は負けの条件に直接影響を与えることはないため、重要な要素はこれらのみです。 
3. もし$c = 0$、「ラミ」と出力します。 

開始プレイヤーはすぐに最終位置に向かい、移動することはできません。 
4. もし$c = 1$、「王様」と出力します。 

非倍数の 1 つは、それを何かと組み合わせずに排除することはできず、強制的な構造により、最初のプレイヤーが強制的に勝利することが保証されます。 
5. それ以外の場合は、パリティに基づいて出力します。 

もし$c \bmod 2 = 1$の場合は「王様」、それ以外の場合は「ラミ」を出力します。 

### なぜ効果があるのか

 すべての移動で 2 つの要素が削除され、残りが 2 つの要素の合計となる 1 つの要素に置き換えられます。 これにより、剰余合計の剰余和のモジュロが保存されます。$k$、これはゼロです。 なぜなら$k$が奇数である場合、剰余はパリティ推論を壊す可能性がある隠れた 2 サイクル不変式を導入しません。 

唯一の永続的なゲーム関連量は、非ゼロの剰余がいくつ存在するかです。 それぞれの動きにより、ペアリングの柔軟性が事実上低下します。 プレイヤーは交互に参加し、常にサイズを 1 つ減らすため、ゲームは、強制的な端末構成に到達するまでにどれだけの「悪い」要素が残るかというパリティ制御の問題に帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))
    
    bad = 0
    for x in arr:
        if x % k != 0:
            bad += 1
    
    if bad == 0:
        print("Rami")
    elif bad == 1:
        print("Oussama")
    else:
        if bad % 2 == 1:
            print("Oussama")
        else:
            print("Rami")

if __name__ == "__main__":
    solve()
```このコードは、唯一の関連する統計、つまり、次の値で割り切れない要素の数を分離します。$k$、そして派生したゲーム分類を適用します。 ループは線形であり、マージのシミュレーションを回避します。 

最もデリケートな部分は、単一の不良要素のケースの処理です。 これは、ゲームが交互の削除動作ではなく強制マージ構造に直接移行するため、単純なパリティ ルールが破られる境界です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    import sys
    input = sys.stdin.readline
    
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))
    
    bad = sum(1 for x in arr if x % k != 0)
    
    if bad == 0:
        return "Rami\n"
    elif bad == 1:
        return "Oussama\n"
    else:
        return ("Oussama\n" if bad % 2 == 1 else "Rami\n")
