 ## 解決策

 ## 問題の理解

 順列が与えられています。これは、1 から n までのすべての数値が何らかの順序で 1 回だけ現れることを意味します。 このタスクは、i < j < k である 3 つのインデックス i、j、k の特定のパターンを検出し、j の値が制約された意味での「ローカル ピーク」となるようにすることです。この値は、左に選択された要素と右に選択された要素の両方よりも大きく、左の要素は厳密にそれよりも小さくなります。 

言い換えれば、左側のどこかでより小さい値を見つけ、その右側のどこかでより小さい値を見つけることができる中間位置 j が必要です。 正確な要件は、p[i] < p[j] および p[k] < p[j] であり、i は j の厳密に左、k は j の厳密に右であることです。 隣接性は必要なく、インデックスの順序付けのみが必要です。 

制約は小さく、n は最大 1000、テスト ケースは最大 200 です。 単一のテスト ケースに対する 3 次アプローチは、Python ではすでに許容できる境界線にありますが、200 ケースを超えると安全ではなくなります。 これにより、テスト ケースごとに 2 次式に近いもの、あるいはそれ以上のものに近づくことができます。 

最良のトリプルには j の近傍が含まれるはずだと仮定すると、単純な解釈は失敗することがよくあります。 有効な i と k が遠く離れている可能性があるため、これは不正確です。 たとえば、[1, 3, 2, 4] のような順列では、有効なトリプルは選択に応じて i=1、j=2、k=3 または i=1、j=4、k=3 になります。 証人要素は必ずしも隣接している必要はありません。 

j を全体的な最大値として選択しようとすると、別の微妙な故障モードが現れます。 これは有効なトリプルを保証するものではありません。最大値がエンドポイントにあるか、すべての小さな要素が片側にのみ存在する可能性があるためです。 たとえば、どこでも増加構造があるにもかかわらず、[1, 2, 3, 4] には有効なトリプルがありません。 

主な困難は、単なるピークではなく、両側にサポートがあるピークを見つけなければならないことです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 インデックス i < j < k のすべてのトリプルについて、p[i] < p[j] および p[k] < p[j] かどうかを直接チェックします。 これはすべての可能性を列挙しており、有効な構成は最終的にテストされるため、これは正しいです。 

ただし、これはテスト ケースごとに O(n^3) のトリプルをチェックします。 n = 1000 の場合、テスト ケースごとにおよそ 10^9 のチェックが行われることになります。これは、特に最大 200 のテスト ケースでは、実現可能な範囲をはるかに超えています。 Python でも、これは合格には程遠いです。 

視点を変えることでこれを大幅に減らすことができます。 i と k を明示的に選択する代わりに、中央のインデックス j を固定し、その左側に少なくとも 1 つの小さな要素があり、右側に少なくとも 1 つの小さな要素があるかどうかを尋ねます。 両方が存在する場合は、すぐに作業が完了します。 

この観察により、問題は各 j の周囲をスキャンして 2 つの存在条件をチェックすることに帰着します。 各 j の直接スキャンは O(n^2) で、n が 1000 まで許容されます。有効な j が見つかったら、適切な i と k を選択できます。 

また、左側と同様に右側に小さい要素が存在するかどうかを位置ごとに事前計算することで、存在チェックを最適化することもできます。 ただし、制約があれば単純なスキャンでも十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのトリプル) | O(n^3) | お(1) | 遅すぎる |
 | スキャンで中央の j を修正 | O(n^2) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 各インデックス j を 1 から n まで繰り返します。 

j を潜在的なピーク位置として扱います。 目的は、それが有効なトリプルの中間要素になれるかどうかを判断することです。 
2. j の左をスキャンして、p[i] < p[j] となるインデックス i を見つけます。 

これにより、左の条件が確実に満たされます。 存在するだけで十分なので、そのような i を見つけたらすぐに立ち止まります。 
3. j の右をスキャンして、p[k] < p[j] となるインデックス k を見つけます。

これにより、適切な条件が満たされることが保証されます。 繰り返しますが、必要なのは存在だけです。 
4. 有効な i と k の両方が見つかった場合は、YES とトリプル (i, j, k) を出力し、このテスト ケースの処理を終了します。 
5. 両方の条件を満たす j がない場合は、NO を出力します。 

### なぜ効果があるのか

 有効な解法には、左側に小さい要素が存在し、右側に別の小さい要素が存在する、中間のインデックス j が存在する必要があります。 アルゴリズムは j のすべての可能な選択肢をチェックし、この条件を正確に検証します。 中間ポジションの候補をすべて網羅し、それぞれについて実現可能性を正確にテストするため、有効なトリプルを見逃すことはできません。 逆に、どの j もテストに合格しない場合、定義上、有効な構成は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    p = list(map(int, input().split()))

    found = False

    for j in range(n):
        left_i = -1
        right_k = -1

        for i in range(j):
            if p[i] < p[j]:
                left_i = i
                break

        if left_i == -1:
            continue

        for k in range(j + 1, n):
            if p[k] < p[j]:
                right_k = k
                break

        if right_k != -1:
            print("YES")
            print(left_i + 1, j + 1, right_k + 1)
            found = True
            break

    if not found:
        print("NO")
```ソリューションの中核となる構造は、固定中間戦略の直接実装です。 外側のループは j を選択し、2 つの内側のスキャンは両側の証人を探します。 両方の証人が存在する瞬間にすぐに出力されるため、無駄な作業が防止されます。 

よくある実装上の落とし穴は、Python ではインデックスが 0 から始まるのに、1 から始まるように出力する必要があることを忘れていることです。 もう 1 つの微妙な問題は、早期ブレークです。有効な i が見つかったら、左にスキャンを続ける必要はありませんが、より重要なのは、完全なトリプルが見つかったら、複数の出力を避けるために j ループから完全に抜け出す必要があることです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        found = False

        for j in range(n):
            i = -1
            k = -1

            for x in range(j):
                if p[x] < p[j]:
                    i = x
                    break

            if i == -1:
                continue

            for x in range(j + 1, n):
                if p[x] < p[j]:
                    k = x
                    break

            if k != -1:
                out.append("YES")
                out.append(f"{i+1} {j+1} {k+1}")
                found = True
                break

        if not found:
            out.append("NO")

    return "\n".join(out)

 ## 特殊なケース

 [1, 2, 3] のような小さな順列では、有効な j は決して生成されません。これは、より小さい左隣とより小さい右隣の両方を持つ要素は存在できないためです。 アルゴリズムは j=0、1、2 をチェックし、それぞれ少なくとも 1 つの側が失敗するため、正しく NO を返します。 

[5, 4, 3, 2, 1] のような逆順列では、すべての要素の片側にのみ小さな要素があり、両方にはありません。 スキャンではすべての j についてこれを確認し、多くのローカル比較が存在する場合でも誤検知を防ぎます。 

[2, 1, 4, 3] のようなケースは意図した動作を示しています。j=2 (値 4) には両側に小さな要素があり、アルゴリズムはすぐに i=0 と k=3 を見つけて、有効なトリプルを生成します。
