 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられたディスクのセットが与えられ、数字が大きいほどディスクが大きくなります。 これらのディスクは最初に m 個のタワーに分割されており、各タワーにはすでにディスクが下から上にサイズの降順で積み重ねられています。 

1 つのタワーからすべてのディスクを取り出して別のタワーに配置することで、2 つのタワーを繰り返しマージすることができますが、それは有効なスタッキング ルールを維持する方法でのみ可能です。ディスクをタワーに配置できるのは、そのタワーの現在の一番上のディスクがそれより大きい場合のみです。 マージ操作は事実上、ディスクのグループ化方法を再編成し、最終的にはすべてを含む単一のタワーで終了することを目指していることを意味します。 

私たちが気にするコストは、タワー内の移動の数ではなく、最終的に単一の有効なタワーを得るために最適な戦略で必要となる、そのようなタワーのマージ操作の数です。 

各クエリの後、2 つの既存のタワーが 1 つにマージされ、現在の構成全体の難易度、つまりすべてを 1 つのタワーにマージし終えるのに必要な最小操作数を報告する必要があります。 

制約は最大 200,000 個のディスクとタワーと大きく、マージ プロセスを直接シミュレートしたり、グローバル構造を最初から繰り返し再計算したりするアプローチは即座に除外されます。 クエリごとの 2 次計算は遅すぎます。最悪の場合、クエリごとの線形再計算ですらコストがかかりすぎます。 

単純な考えは、各クエリをシミュレートし、すべてのタワーを再構築し、難易度を最初から再計算することです。 そのためには、マージのたびにすべてのディスクをスキャンしてディスク間の関係を確認する必要があり、制限をはるかに超えるおよそ O(nm) の動作が発生します。 

素朴な貪欲な思考によるさらに微妙な失敗例は、2 つのタワーをマージすると常に難易度が 1 つだけ増加するか、グローバル構造なしでローカルに計算できると仮定することです。 たとえば、2 つのタワーが結合された場合でも、その効果は、インデックス空間内で遠く離れたディスク間の多くの隣接関係を通じて伝播する可能性があります。 

重要な問題は、その答えは時間の経過とともにディスク ラベルが接続されたコンポーネントにどのように分割されるかによって決まり、マージは多くの隣接関係に同時に影響を与えることです。 

## アプローチ

 効率を無視すると、各ディスクはタワー レーベル内にあると考えることができます。 最終的な目標は、すべてのディスクを 1 つの有効な減少スタックに入れることです。 難易度について考えるのに役立つ方法は、1 から n までのディスクのシーケンスを昇順に検討し、このシーケンスがタワーのメンバーシップに関してどの程度断片化されているかを尋ねることです。 

2 つの連続するディスク i と i+1 が、最終的に結合された異なるタワーに属している場合、構築プロセスのある時点でそれらを分離する必要があり、必要な操作の数が増加します。 それらが同じ最終タワーに属している場合、それらの間に操作境界は必要ありません。 

これは、その答えが、現在のタワー代表が異なる連続するインデックス i と i+1 の間の「切れ目」をカウントすることに密接に関連していることを示唆しています。 

次に、2 つの塔を結合すると何が起こるかを考えてみましょう。 両方のタワー内のすべてのディスクが突然同じアイデンティティを共有します。 これは、以前は「不良」だった隣接するペアの一部が、それらのエンドポイントが同じマージされたコンポーネントに属するため「良好」になることを意味します。 

これにより、位置 1 ～ n の固定回線を介した動的な接続の問題が発生します。各位置は DSU コンポーネント (そのタワー) に属し、コンポーネントの境界を越える隣接ペアの数を維持します。 

ブルート フォース手法では、マージのたびに n 個の位置をすべてスキャンすることで、この隣接数を再計算します。 これではクエリごとに O(n) のコストがかかり、合計は O(nm) となり、大きすぎます。

重要な洞察は、2 つの DSU コンポーネントをマージすると、マージされたコンポーネント内の要素に接触する隣接エッジにのみ影響するということです。 各コンポーネントについて、それに含まれる位置のリストを維持する場合、2 つのコンポーネントをマージするときに必要なのは、小さい方のコンポーネントの要素を検査し、それらの隣接要素 i−1 と i+1 をチェックすることだけです。 

これにより、サイズによる和集合を使用して、ほぼ直線的な合計時間で答えを段階的に更新することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各マージ後に再計算する | O(nm) | O(n) | 遅すぎる |
 | 隣接関係追跡を備えた DSU | O(n α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各タワーをディスク位置上の DSU セットとしてモデル化します。 各ディスク位置は、現在どのタワーに属しているかを保存します。 また、異なる DSU セットに属する隣接ペア (i、i+1) の数のグローバル カウンタも維持します。 

### ステップ

 1. 各タワーが独自のコンポーネントである DSU を初期化し、コンポーネントごとにそれに属するディスク位置のリストを保存します。 

これにより、後でコンポーネントがマージされるときに、影響を受ける位置のみを更新することができます。 
2. i を 1 から n − 1 までスキャンし、位置 i と i+1 が異なるタワーに属している回数を数えることによって、初期難易度を計算します。 

これは、初期構成におけるコンポーネント間の境界の数を表します。 
3. 各マージ クエリ (a、b) について、両方のタワーの DSU 代表を見つけます。 
4. それらがすでに同じコンポーネント内にある場合、構造は変更されず、現在の回答が単に出力されます。 
5. それ以外の場合は、必ず小さいコンポーネントを大きいコンポーネントにマージします。 

これにより、マージ間で各ディスク位置が最大でも対数的に移動されることが保証されます。 
6. 小さいコンポーネント内のすべての位置 x について、その隣接する x-1 および x+1 が存在するかどうかを確認します。 
7. 各隣接チェックで、マージ前に隣接が異なるコンポーネントに属している場合、このエッジは現在、答えに 1 を与えます。 マージ後、両方のエンドポイントが同じコンポーネントの一部になるため、この寄与はなくなり、答えが減分されます。 
8. 小さいコンポーネントのすべての要素を大きいコンポーネントに移動し、DSU 結合を実行します。 
9. 処理後、現在の回答を出力します。 

### なぜ効果があるのか

 重要な不変条件は、答えが常に隣接するインデックス ペア i および i+1 の数と等しく、その DSU 代表が異なることです。 すべてのマージ操作では、マージされたコンポーネント内の DSU 接続のみが変更されるため、それらのコンポーネントに接触する隣接エッジのみがステータスを変更できます。 このような影響を受けるすべての位置をより小さなコンポーネントから明示的に検査し、影響を受けるエッジごとに境界寄与を正確に 1 回更新するため、カウンターは常に正確なままになります。 

マージはコンポーネントを統合するだけで、分割することはないため、他の隣接関係は等しいから不等に変更することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    t = list(map(int, input().split()))

    parent = list(range(m + 1))
    size = [1] * (m + 1)

    comp = [set() for _ in range(m + 1)]
    for i, c in enumerate(t):
        comp[c].add(i)

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    ans = 0
    for i in range(n - 1):
        if t[i] != t[i + 1]:
            ans += 1

    def union(a, b):
        nonlocal ans
        a = find(a)
        b = find(b)
        if a == b:
            return

        if len(comp[a]) < len(comp[b]):
            a, b = b, a

        # merge b into a
        for x in comp[b]:
            for y in (x - 1, x + 1):
                if 0 <= y < n:
                    if find(t[y]) == a:
                        ans -= 1
            comp[a].add(x)
            t[x] = a

        comp[b].clear()
        parent[b] = a

    for _ in range(m - 1):
        a, b = map(int, input().split())
        union(a, b)
        print(ans)

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、タワー上の DSU とディスク位置のコンポーネントごとのコンテナーを維持します。 配列 t は、各位置の現在の代表メンバーシップを保存するために再利用されます。 マージ中は、小さいコンポーネント内の要素のみが検査され、各隣接関係の更新はローカルで処理されます。 

微妙な点は、隣接エッジが 2 つの異なるコンポーネントと交差していたが、マージ後に内部になったことを検出した場合にのみ、答えをデクリメントすることです。 マージでは新しい分離を作成できないため、マージ中に答えをインクリメントすることはありません。 

## 実用的な例

 次のようにディスクが配布される小さな例を考えてみましょう。 

入力:```
5 3
1 1 2 3 3
1 2
2 3
```初期状態には隣接配列があります。 

| 私 | 1 | 2 | 3 | 4 |
 | --- | --- | --- | --- | --- |
 | t[i] | 1 | 1 | 2 | 3 |
 | 違いは？ | 0 | 1 | 1 | 1 |

 最初の答えは 3 です。 

1 と 2 をマージした後、コンポーネント 2 に属する位置が検査され、(2,3) 間の境界が影響を受けます。 

| ステップ | 統合されました | 影響を受けるポジション | 答え |
 | --- | --- | --- | --- |
 | 0 | なし | なし | 3 |
 | 1 | (1,2) | 境界をチェック 2-3 | 2 |
 | 2 | (2,3) | 境界をチェック 3-4 | 1 |

 これは、各マージがすべてをグローバルに再構築するのではなく、既存の境界を削除するだけであることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各位置は、そのコンポーネントがより大きな位置にマージされる場合にのみ移動されます。 
| スペース | O(n + m) | DSU 配列とコンポーネントごとの位置のストレージ |

 サイズ別結合戦略は、すべてのマージにわたって各ディスク位置が限られた回数だけ処理されることを保証し、解を最大 2×10^5 の n の制限内に保ちます。

 ## 特殊なケース

 重要なエッジケースは、すべてのディスクが最初から個別のタワーに属している場合です。 この場合、すべての隣接するペアが最初の答えに寄与し、コンポーネントが統合されるにつれてマージのたびにこれらの境界が徐々に減少します。 すべてのマージでは隣接関係の寄与のみが削除され、最初から再計算が試行されることはないため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、ディスク インデックス スペース内に隣接関係のないタワーをマージで接続する場合です。 このような場合、答えはまったく変わりません。 隣接チェックではマージ前に一致するコンポーネントが見つからないため、アルゴリズムはデクリメントを正しく実行しません。 

最後に、繰り返しマージがすでに統合されたコンポーネントをターゲットにしている場合、DSU チェックは直ちに終了し、二重カウントや応答の破損が発生しないようにします。
