 ## 解決策

 ## 問題の理解

 一列に配置された戦士を表す一連の個別の整数が与えられます。 また、これも個別の整数で構成されるターゲット シーケンスも与えられます。 目標は、シーケンスをさまざまな方法で変更する 2 つの操作を使用して、最初の行をターゲット行に変換することであり、それぞれにコストがかかります。 

1 回の操作で、正確に k 個の要素の連続ブロックが固定コストで削除されます。 もう 1 つの操作は、隣接する要素に対してローカルに作用します。これは、2 つの隣接要素を比較し、小さい方の要素を削除します。これにより、ローカルでの戦闘を繰り返して、より弱い要素を効果的に「バブルアウト」することができます。 これらの操作は任意の順序で適用できますが、最終的にはターゲット シーケンスを正確な順序で実行し、総コストを最小限に抑えたり、レポートの不可能性を最小限に抑えたりしたいと考えています。 

主要な構造上の制約は、すべての値が異なるため、シーケンスを数値の並べ替えとして扱うことができるということです。 これにより、関係に関するあいまいさがなくなり、すべての要素が一意のアイデンティティを持つことが保証されます。 

境界は十分に大きいため、操作を直接シミュレートするソリューションは不可能です。 n が 200,000 までの場合、O(n²) の推論でも遅すぎるため、O(n log n) の解であっても線形スキャンまたは 2 つのポインターを中心に注意深く構成する必要があります。 これは、各操作の後にシーケンスを動的にモデル化するのではなく、どの要素が存続する必要があり、それらを一括で削除できるかを推論する必要があることを直ちに示唆しています。 

単純な失敗例は、将来のグループ化を考慮せずに要素を左から右に貪欲に削除しようとしたときに発生します。 たとえば、k = 3 で、不一致が見つかるたびにファイアボールを貪欲に適用すると、後でバーサーク削除の安価な構成をサポートするために実際に必要となる要素が破棄される可能性があります。 必要な要素間のすべてを「クリーンアップ」するために berserk のみに依存している場合、別の障害モードが発生します。berserk は操作ごとに 1 つの要素しか削除できないため、無関係な要素が長く続くと、ファイアボールを使用してバッチ処理しない限り、法外なコストがかかります。 

## アプローチ

 視点を反転すると、問題はより明確になります。ソースからターゲットを構築するのではなく、残りのシーケンスが順番にターゲット シーケンスと等しくなるように、初期配列のどの要素を残さなければならないかを検討します。 どちらのシーケンスも順列であるため、ターゲット内の各値はソース内の固有の位置に対応します。 

ターゲットの各値を元の配列のインデックスにマップしましょう。 これにより、元の配列内で厳密に増加するインデックスのシーケンスが得られます。 ターゲットにない要素は削除する必要があります。 最も重要な問題は、ターゲット要素の順序を維持しながらターゲット以外の要素をすべて削除し、コストを最小限に抑える方法です。 

元の配列内のターゲットの位置を修正すると、問題は連続するターゲット要素間のギャップに分解されます。 各ギャップ内で、「不良」要素の連続セグメントを削除する必要があります。 ただし、これらの不良セグメントは構造上の制約によって中断されます。バーサークを使用して個々の要素を安価に削除できますが、隣接する要素のみを削除できます。また、ファイアボールを使用してサイズ k のブロックを削除することもできます。 

これにより、古典的なインターバルをカバーする DP 構造が得られます。 連続して保持された要素間の各セグメントについて、すべての内部要素を削除するためのコストを計算します。 セグメント内では、berserk (削除数に比例するコスト) を繰り返し使用するか、ファイアボールを使用してサイズ k のチャンクを削除する (k ブロックごとに償却されるコスト)、または両方を混合することができます。

重要な観察は、berserk ではコスト y で単一の要素を効果的に削除できるのに対し、fireball ではコスト x で k 個の連続した要素を削除できるということです。 したがって、長さ L の連続セグメント内では、そのセグメントを削除するための最小コストは、セグメントをファイアボール チャンクと単一の削除に分割するよりも最小になります。 

したがって、ギャップごとに次のように計算します。 

L個の不良要素を取得し、fireballを使用してfloor(L/k)グループを削除し、berserkを使用して残りを削除できます。 これによりコストは (L//k)*x + (L%k)_y になりますが、火の玉は k バーサークよりも安い場合にのみ役立つため、すべてのバーサークのコスト L_y とも比較する必要があります。 

したがって、完全なブロックあたりの実効コストは min(x, k*y) で、残りは個別に処理されます。 

したがって、各ギャップのコストは次のようになります。 

フロア(L/k) * 最小(x, k*y) + (L%k)*y。 

また、実現可能性も確保する必要があります。ターゲット要素は元の配列内で正しい順序で出現する必要があります。 そうでない場合、答えは -1 です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 操作のブルート フォース シミュレーション | O(n²) | O(n) | 遅すぎる |
 | マッピング + ギャップ コストの最適化 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 位置マッピングとギャップ分解を使用して配列を処理します。 

1. 位置配列 pos を構築します。ここで、pos[v] は、初期シーケンス内の値 v のインデックスです。 これにより、各ターゲット要素が元の配列のどこに出現するかを追跡できるようになります。 
2. ターゲットに対応する位置のシーケンスが厳密に増加していることを確認します。 そうでない場合、ターゲット要素を相互に並べ替える操作はないため、ターゲットの順序を取得できません。 
3. 配列をセグメントに分割します。最初のターゲット要素の前、連続するターゲット要素の間、最後のターゲット要素の後です。 各セグメントは完全に削除する必要がある要素で構成されています。 
4. 各セグメントについて、その長さ L を計算します。これらの要素は最終シーケンスに属さないため、完全に削除する必要があります。 
5. 削除を最適にグループ化することにより、セグメントを削除するコストを計算します。 k 個の要素の各グループは、ファイアボールを使用して削除できます。または、berserk を繰り返し使用できます。 最適な選択は、k バーサークが k_y コストに等しく、ファイアボールの方が安価である可能性があるため、完全なブロックをコスト min(x, k_y) を持つものとして扱うことです。 
6. (L // k) * min(x, k*y) + (L % k) * y を各セグメントの答えに加算します。 
7. すべてのセグメントを合計し、結果を出力します。 

### なぜ効果があるのか

 ターゲット要素は固定セパレータとして機能するため、変換プロセスでは必要な要素の異なるセグメント間で相互作用する必要はありません。 セグメント内では、ターゲット以外の要素はすべて最終的な順序制約に関して無関係で区別できないため、操作は要素の識別情報ではなく、削除される要素の数のみが重要になります。 Berserk はコスト y でユニット削除機能を提供しますが、Fireball はコスト x でサイズ k のバッチ削除を提供します。そのため、各セグメント内の問題は、L をサイズ k のグループと単一削除のグループに分割することによる単純なコストの最小化に帰着します。 どの操作も新しい有用な要素を作成したり、必要な要素間の隣接関係を変更したりするため、この構造を改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    x, k, y = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(a):
        pos[v] = i

    # check order feasibility
    for i in range(1, m):
        if pos[b[i]] < pos[b[i - 1]]:
            print(-1)
            return

    ans = 0

    def cost(L):
        if L <= 0:
            return 0
        full = L // k
        rem = L % k
        return full * min(x, k * y) + rem * y

    # left segment
    ans += cost(pos[b[0]])
    # middle segments
    for i in range(1, m):
        ans += cost(pos[b[i]] - pos[b[i - 1]] - 1)
    # right segment
    ans += cost(n - 1 - pos[b[-1]])

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず、各ターゲット要素が O(1) に配置されるように位置マッピングを構築します。 単調性チェックにより、ターゲット シーケンスが元の順序を尊重していることが保証されます。 そうしないと、一連の削除を行っても復元できません。 

コスト関数は、核となる洞察がエンコードされる場所です。 削除をサイズ k の完全なブロックと残りに分割します。 ブロックごとに、1 つの火の玉と k 個の個々のバーサークのどちらか安い方を選択します。これは、他の削除に影響を与えることなく、互いに素な k 個の長さのグループに火の玉が適用されるように、最適なソリューションを再配置できるためです。 火の玉を部分的に適用することはできないため、残りは常にバーサーク操作で処理する必要があります。 

最後に、非ターゲット要素のすべてのセグメントにわたるコストを累積します。これらのセグメントは独立しているためです。

 ## 特殊なケース

 重要なエッジ ケースは、ターゲット シーケンスがインデックス順序の点で元の配列のサブシーケンスではない場合です。 たとえば、オリジナルが [1,2,3] でターゲットが [3,1] の場合、位置は減少しているため、一連の削除によって順序を修正することはできず、答えは -1 でなければなりません。 

k が 1 の場合、別のケースが発生します。ここで、ファイアボールは 1 つの要素を削除することと同等になるため、すべての削除は x または y のいずれかになり、解決策は要素ごとに安価な操作を選択することになります。 k ≥ 2 の構造を仮定する解法では、ここで過大カウントまたは過少カウントが行われます。 

3 番目のケースは、x が k_y よりもはるかに大きい場合です。 そのような状況では、ファイアボールは決して最適ではなく、解決策は純粋な凶暴な削除に減らす必要があります。 実装が常にブロック全体に貪欲にファイアボールを適用すると、過剰な負担が発生しますが、コスト式は min(x, k_y) を取得することでこれを正しく処理します。
