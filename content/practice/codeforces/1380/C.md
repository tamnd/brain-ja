 ## 解決策
 ## 問題の理解

 当社にはプログラマーのグループがあり、それぞれがスキル値を持っています。 できるだけ多くのチームを結成したいと考えています。 チームは次の場合に有効です。$$(\text{team size}) \times (\text{minimum skill in the team}) \ge x$$すべてのプログラマーは最大 1 つのチームに所属でき、一部のプログラマーは未使用のままになる場合があります。 

タスクは、作成できる有効なチームの最大数を決定することです。 

最大のテスト ケースには、以下が含まれます。$10^5$プログラマーと全員の合計$n$テスト ケース全体の値も最大で$10^5$。 この入力サイズでは、プログラマの異なるパーティションを繰り返し試行するアルゴリズムは不可能です。 たとえ$O(n^2)$解決策には約が必要です$10^{10}$限界をはるかに超えた最悪の場合の操作。 周りに何かが必要です$O(n \log n)$またはそれ以上です。 

難しいのは、チームの品質は最も弱いメンバーによってのみ左右されるということです。 より強力なプログラマーを追加しても最低限のスキルは向上しませんが、プログラマーを追加するとチームの規模は増加します。 単純なグループ化戦略は、優秀なプログラマーを簡単に無駄にし、最終的な答えを減らす可能性があります。 

次の例を考えてみましょう。```
n = 4, x = 10
skills = [10, 10, 10, 10]
```正解は 4 です。各プログラマは単独で有効なチームを形成します。$1 \times 10 = 10$。 プログラマをより大きなグループにまとめる不注意なアプローチでは、チームの数が少なくなります。 

もう 1 つの重要なケースは次のとおりです。```
n = 5, x = 10
skills = [5, 5, 5, 5, 5]
```正解は 2 です。有効な各チームには少なくとも 2 人のプログラマーが必要です。$2 \times 5 = 10$。 サイズ 2 の 2 つのチームを作成し、1 人のプログラマーを未使用のままにすることができます。 全員を使用することを要求する実装では、誤って 1 が返されます。 

3 番目のエッジケースは、チームを結成できない場合です。```
n = 4, x = 11
skills = [1, 3, 3, 7]
```4 人のプログラマすべてを使用しても、$4 \times 1 = 4$、これはまだ 11 を下回っています。答えは 0 です。 

これらの例は、チームの数を最大化することが、使用するプログラマーの数を最大化することと同じではないことを示しています。 

## アプローチ

 ブルート フォース ソリューションでは、さまざまな方法でプログラマをチームに分割し、どのパーティションが条件を満たすかを確認します。 このような方法はすべての可能性を調べるため正しいですが、パーティションの数は指数関数的に増加します。 数十人のプログラマーでもそれは不可能になります。 

より良い成果を出すためには、有効なチームがどのように特徴付けられているかを理解する必要があります。 

チーム内の最低限のスキルは$m$。 その場合、チームは次の場合にのみ有効になります。$$(\text{team size}) \times m \ge x$$スキルを降順に並べ替えて、最も強いプログラマから最も弱いプログラマまで処理すると、スキルを備えたプログラマに到達したとき、$a_i$、これまでに集められたすべてのプログラマーは少なくともスキルを持っています$a_i$。 私たちがそう決めたら$a_i$その場合、チームの中で最も弱いメンバーになります。$a_i$チームの最低限のスキルになります。 

この時点で必要なのは、現在のチームに何人のプログラマーが集まったかを知ることだけです。 もし：$$(\text{current size}) \times a_i \ge x$$そうすれば、有効なチームをすぐに完成させることができます。 

この観察は貪欲な戦略につながります。 スキルを最大のものから最小のものまで並べ替えます。 プログラマーを集めてチームを作る。 現在のグループが有効になったら、すぐにそれを完成させ、次のチームの構築を開始します。 

チームが有効になったらすぐに閉じても安全なのはなぜですか?

 なぜなら、このチームにプログラマーが追加されるたびに、後で別のチームを形成するのに役立つ可能性があるからです。 グループがすでに有効になったら、グループを大きくしてもチームの数が増えることはありません。 最小の有効なチームが常に最良の選択です。 

これにより、問題は単純な並べ替えとスキャンのプロセスに変換されます。

 ## アルゴリズムのチュートリアル

 1. すべてのスキルを降順に並べ替えます。 
2. カウンタの初期化`current_size = 0`。 
3.初期化`teams = 0`。 
4. ソートされたスキルを左から右に処理します。 
5.各スキル値について`s`を増やして、そのプログラマーを現在の未完成のチームに追加します。`current_size`。 
6. 治療する`s`現在のグループの最低限のスキルとして。 降順で処理を行っているため、以前に集められたプログラマーは全員少なくともスキルを持っています。`s`。 
7. 次のことを確認します。$$current\_size \times s \ge x$$この条件が当てはまる場合、現在のグループはすでに有効なチームを形成しています。 
8.増加`teams`1つずつ。 
9. リセット`current_size`ゼロにして次のチームの構築を開始します。 
10. すべてのプログラマが処理された後、出力`teams`。 

### なぜ効果があるのか

 重要な不変条件は、ソートされた配列をスキャンしている間、現在のスキル値が常に、未完成のチームに現在集められているすべてのプログラマーの中での最小スキルであるということです。 

条件が合うたびに`current_size * skill >= x`が真になると、最小限のスキルを備えた有効なチームを形成するのに十分なプログラマーがいます。`skill`。 チームを直ちに閉鎖すると、そのチームで使用するプログラマーの数が可能な限り最小限になります。 

チームがすでに有効になった後にプログラマーを追加し続けるソリューションは、後で追加のチームを作成するのに役立つ可能性があるリソースを消費するだけです。 チームが大きくなってもチーム数が増えることはないため、すべての有効なチームを貪欲に最終決定しても、最適な答えを減らすことはできません。 

したがって、アルゴリズムによって形成されたすべてのチームは有効であり、すべての有効なチームは利用可能なプログラマの最小数を使用するため、チームの総数が最大になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n, x = map(int, input().split())
        skills = list(map(int, input().split()))

        skills.sort(reverse=True)

        teams = 0
        current_size = 0

        for s in skills:
            current_size += 1

            if current_size * s >= x:
                teams += 1
                current_size = 0

        answers.append(str(teams))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```最初のステップでは、スキルを降順に並べ替えます。 これにより、スキル値を調べるときはいつでも、`s`、現在の未完成グループに既に配置されているすべてのプログラマーは少なくともスキルを持っています。`s`。 つまり、`s`それはまさに潜在的なチームの最低限のスキルです。`current_size`現在のチーム候補のために集められたプログラマの数を格納します。 プログラマを追加した後、チーム条件が満たされるかどうかをテストします。 

いつ`current_size * s >= x`、有効なチームが形成されました。 欲張りな選択は、すぐに終了してリセットすることです`current_size`ゼロに。 これは実装の重要な詳細です。 リセットを忘れると、複数のチームが誤って結合されてしまいます。 

すべての算術演算は Python 整数内に快適に収まります。 可能な最大の製品は次のとおりです。$$10^5 \times 10^9 = 10^{14}$$これは Python の範囲内に十分収まります。

 ## 特殊なケース

 次のことを考慮してください。```
1
5 10
5 5 5 5 5
```並べ替えても何も変わりません。 スキャンは次のように進行します。```
size=1 -> 1*5=5
size=2 -> 2*5=10 -> team
size=1 -> 1*5=5
size=2 -> 2*5=10 -> team
size=1 -> end
```答えは 2 です。プログラマ 1 人は未使用のままです。 このアルゴリズムは、すべてのプログラマーを強制的にチームに編成しようとすることはありません。 

ここで次のことを考えてみましょう。```
1
4 10
10 10 10 10
```各ステップは次の条件を直ちに満たします。```
1*10 = 10
```プログラマーごとにチームが形成され、4 つのチームが生成されます。 貪欲な戦略では、シングルトン チームが最適であることが自然にわかります。 

最後に、次のことを考慮してください。```
1
4 11
1 3 3 7
```並べ替えられた順序:```
7 3 3 1
```スキャンにより次のものが生成されます。```
1*7 = 7
2*3 = 6
3*3 = 9
4*1 = 4
```どのチェックも 11 に達しないため、チームは形成されません。 利用可能なすべてのプログラマを使用した後でも、アルゴリズムは正しく 0 を返します。
