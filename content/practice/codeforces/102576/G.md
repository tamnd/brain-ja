 ## 解決策
 ## 問題の理解

 平面上に 2 つの点のグループが与えられます。 最初のグループは講演者が開始する場所を表し、2 番目のグループは講演者が終了する必要がある部屋を表します。 どのスピーカーをどの部屋に流すかは私たちが自由に決めることができます。 このタスクは、すべてのパスがテーブルから始まり部屋で終わり、2 つのパスが接触したり交差したりしないように、スピーカーごとに 1 つのパスを描画することです。 

出力では、距離を最小化したり、特定の割り当てを使用したりする必要はありません。 有効なパスのコレクションはどれでも受け入れられます。 パスには複数の頂点が含まれている可能性がありますが、直線セグメントはすでに有効な多角形チェーンであるため、考えられる最も単純な答えは、交差しないセグメントのセットです。 

発言者の数は最大 6 人です。これにより、問題の性質が完全に変わります。 幾何学的制約を伴う一般的なマッチング問題は難しいかもしれませんが、ここでは考えられるすべての割り当てを試す余裕があります。 多くても6つですよ！ = 可能なペアリングの数は 720 ですが、これは非常に少ないです。 すべてのセグメントのペアをチェックした後でも、合計の作業量は非常に少ないままです。 

幾何学的入力も適切に動作します。 すべての X 座標は異なり、すべての Y 座標も異なり、同一線上にある 3 つの点はありません。 これにより、セグメントが重なったり、複数の点が同じ線上にあるようなあいまいなケースが排除されます。 実装上の主な危険は依然として交差点テストです。 すべての入力ポイントは 1 回だけ使用する必要があるため、端点で別のセグメントにのみ接触するセグメントは無効になります。そのため、端点を無視したり、適切な交差のみをチェックする不注意なチェッカーは、無効な構成を受け入れる可能性があります。 

たとえば、次の 2 つのテーブルについて考えてみましょう。`(0,0)`そして`(2,2)`そして2つの部屋`(0,2)`そして`(2,0)`。 最初のテーブルと最初の部屋、2 番目のテーブルと 2 番目の部屋を組み合わせると、交差する 2 つの正方形の対角線が作成されます。 正しい出力は逆のペアリングです。 この場合、交差点をテストせずに入力順序でポイントを接続する単純な実装は失敗します。 

もう一つのケースは、`n = 1`。 可能なパスは 1 つだけですが、それでも必要な形式で印刷する必要があります。 少なくとも 2 つのセグメントが存在することを前提としたコードは、ここで失敗する可能性があります。 

## アプローチ

 直接的なアプローチは、テーブルとルームの間で可能なすべての割り当てを生成することです。 割り当てごとに、対応する直線セグメントを描画し、2 つのセグメントが交差するかどうかをテストします。 割り当てに交差がない場合、すべてのパスは 1 つのセグメントで構成される多角形のチェーンであるため、これは有効な答えです。 課題の数は、`n!`、各割り当てについて、最大でも検査します`n(n-1)/2`セグメントペア。 

ブルートフォース手法が機能するのは、入力が意図的に小さいためです。 もし`n`が 10 か 11 程度であれば、階乗増加はすでに不快なものになります。 で`n = 11`、割り当ての数はほぼ 4,000 万であり、それぞれに幾何学的チェックが必要になります。 実際の制約は、`n <= 6`複雑な幾何学的な議論を構築する代わりに、最も単純で信頼性の高い構築を使用しましょう。 

重要な点は、特別な組み合わせを見つける必要がないということです。 必要な有効なペアは 1 つだけであり、検索スペースは列挙するには十分小さいです。 2 つの等しいサイズの点セット間に非交差マッチングが存在すると、検索で最終的に 1 つが見つかることが保証されます。 この事実の標準的な証明は、全長が最小のマッチングを選択することに基づいています。 その一致する 2 つのセグメントが交差する場合、それらの端点を交換すると全長が短くなり、最小性と矛盾します。 

したがって、最終的なアルゴリズムは、一致する可能性のあるものを完全に検索することになります。 有効な一致が見つかると、出力は各セグメントの 2 つのエンドポイントのみで構成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n²) | O(n) | n <= 6 | であるため受け入れられます。 
| 最適 | O(n! * n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 部屋インデックスの可能なすべての順列を生成します。 位置`i`順列では、どの部屋がテーブルに割り当てられているかがわかります`i`。 以来`n`が最大 6 であれば、すべての割り当てをチェックすることが可能です。 
2. 現在の割り当てに対して、`n`すべてのテーブルを割り当てられた部屋に接続するセグメント。 出力は話者ごとに単一のセグメントになる可能性があるため、エンドポイントのみを保存します。 
3. セグメントのすべてのペアを確認します。 方向テストを使用して、2 つのセグメントが交差するかどうかを判断します。 入力では 3 つの点が同一線上にないことが保証されているため、一方のセグメントの端点が他方のセグメントの反対側にある場合、またはその逆の場合に交差が発生します。 
4. すべてのセグメントのペアが互いに素である場合、これらのセグメントを出力し、検索を停止します。 すべてのセグメントは、2 つの頂点を持つ有効な多角形チェーンです。 
5. 割り当てが無効な場合は、次の順列に進みます。 

機能する理由: このアルゴリズムは、テーブルと部屋を組み合わせるあらゆる可能な方法を検査します。 有効な非交差マッチングが存在するため、生成された順列の 1 つが交差テストに合格する必要があります。 このアルゴリズムは、パスのすべてのペアが互いに素であることが検証された後にのみ出力するため、生成された構造はすべての幾何学的要件を満たします。 

## Python ソリューション```python
import sys
from itertools import permutations

input = sys.stdin.readline

def cross(a, b, c):
    return (b[0] - a[0]) * (c[1] - a[1]) - (b[1] - a[1]) * (c[0] - a[0])

def intersect(a, b, c, d):
    return cross(a, b, c) * cross(a, b, d) < 0 and cross(c, d, a) * cross(c, d, b) < 0

def solve_case(n, tables, rooms):
    for perm in permutations(range(n)):
        segments = []
        for i in range(n):
            segments.append((tables[i], rooms[perm[i]]))

        ok = True
        for i in range(n):
            for j in range(i + 1, n):
                if intersect(segments[i][0], segments[i][1],
                             segments[j][0], segments[j][1]):
                    ok = False
                    break
            if not ok:
                break

        if ok:
            return segments

    return []

def main():
    data = sys.stdin.read().strip().split()
    if not data:
        return

    it = iter(data)
    z = int(next(it))
    ans = []

    for _ in range(z):
        n = int(next(it))
        points = []
        for _ in range(2 * n):
            x = int(next(it))
            y = int(next(it))
            points.append((x, y))

        tables = points[:n]
        rooms = points[n:]

        result = solve_case(n, tables, rooms)

        for a, b in result:
            ans.append("2")
            ans.append(f"{a[0]} {a[1]}")
            ans.append(f"{b[0]} {b[1]}")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    main()
```の`cross`関数は三角形の符号付き面積を計算します。 その符号は、点が有向線のどちら側にあるかを示します。 このステートメントでは共線的なケースが削除されるため、各セグメントの 2 つの端点がもう一方のセグメントの線で区切られている場合にのみ、セグメントのペアが交差します。 

置換ループは、アルゴリズムで説明されている完全な検索です。 パイソンの`itertools.permutations`最大の順列数は 720 のみであるため、ここでは安全です。 

交差チェックでは厳密な不等式を意図的に使用します。 共線的なケースが可能であれば、端点の接触やセグメントの重なりについて追加のチェックが必要になりますが、入力制限によりそれらのケースは削除されます。 

出力では、すべてのパスが正確に 2 つの頂点として保存されます。 直線セグメントはすでに多角形の連鎖であるため、不必要な中間点を追加すると、間違いが増えるだけです。

```交差する構成の場合、アルゴリズムは入力順序に意味があるとは想定しません。 のために```

最大のケースとしては、`n = 6`、割り当ては 720 個しかありません。 アルゴリズムは依然として同じ徹底的な検索を実行しますが、検索スペースは依然として十分小さいため、特別な最適化は必要ありません。 可能な一致がすべて考慮されるため、正確性の引数は変更されません。
