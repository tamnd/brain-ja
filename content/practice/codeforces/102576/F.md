 ## 解決策
 # 問題の理解

 並んでいます`n`ユニークな番号が付けられた兵士。 目標は、現在の順列をソートされた順序に変換することです。 許可される操作は、隣接する兵士を交換する、列全体を逆転させる、または固定コストを支払って列全体をランダム化することです。 ランダム化の後、行はすべての行に均一に分散されます。`n!`可能な順列があるため、将来の予想コストはどの州でも同じになります。 

開始順列ごとに、最適な期待時間が必要です。 テスト ケースでは同じコストが一日中使用されますが、最初の順列は変化するため、ソリューションは多くのクエリに迅速に答える必要があります。 

バウンド`n <= 16`が主な手がかりです。 すべての順列を列挙することは不可能です。`16!`についてです`2 * 10^13`。 しかし、`n(n-1)/2 <= 120`、したがって、反転回数のみに依存する量は小さな動的プログラムで処理できます。 到達できる日数は`100000`これは、各クエリが前処理後に一定時間に近づく必要があることを意味します。 

微妙な点は、ランダム操作はランダムな状態をシミュレートする必要があるという意味ではないということです。 ランダム操作は 1 つの未知の値、つまりすべての順列にわたる平均予想コストのみを提供します。 もう 1 つのよくある間違いは、証明がなければ反転操作は 1 回しか使用できないと考えることです。 実際、2 つの反転を一緒に移動して削除できる一方で、それらの間の隣接するスワップをミラーリングできるため、最大でも 1 つの反転に減らすことができます。 

すでにソートされた順列には答えがあります`0/1`。 たとえば、`n=3`とコスト`a=b=c=1`、入力順列`1 2 3`生産しなければならない`0/1`; ランダム操作を必須として扱うと、間違った肯定的な答えが得られます。 

逆の操作でも境界ケースが作成されます。 のために`n=3`、順列`3 2 1`には 3 つの反転がありますが、その逆には反転はありません。 隣接スワップのみを考慮するソリューションでは、コストが発生します。`3a`、一方、正しい決定論的コストは単に`b`。 

# アプローチ

 直接的な解決策では、すべての順列をグラフ ノードとしてモデル化します。 各ノードには、隣接するスワップと反転によって取得された状態へのエッジと、ランダム化を表すエッジが含まれます。 このグラフで最短パス スタイルの緩和を実行するのは正しいはずですが、グラフには次のものが含まれます。`n!`ノード。 で`n=16`、ノードを保存することさえ不可能です。 

重要な観察は、決定論的なソートコストは反転回数のみに依存するということです。 隣接するスワップは 1 つの反転を削除または作成するため、反転コストなしでソートできます。`a * inv`。 1 回の反転を使用すると、反転カウントは次のように変化します。`k`に`m-k`、 どこ`m=n(n-1)/2`なぜなら、すべてのペアが反転から非反転、あるいはその逆に変化するからです。 したがって、最適な決定論的コストは次のようになります。`min(a*k, b + a*(m-k))`。 

次に、ランダム操作を考えてみましょう。 させて`M`すべての順列にわたって予想される平均の答えになります。 ランダム化のコストは`c+M`、これは定数です。 状態の決定論的コストが`D`、最適値は単純に次のとおりです。`min(D, c+M)`。 これが機能するのは、パスがランダム化コストよりも小さい値を持つ状態に到達した場合、そのパス自体が元の状態の決定論的解がより小さいことが証明されるためです。 

したがって、必要なのは反転数の分布だけです。 各反転カウントでの順列の数は、古典的なマホニアン数動的計画法によって見つけることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n!)`状態 |`O(n!)`| 遅すぎる |
 | 最適 |`O(n^2 + n^3 + d)`テストケースごと |`O(n^2)`| 承認済み |

 # アルゴリズムのチュートリアル

 1. 長さの順列の数を事前計算します。`n`可能なすべての反転回数を持ちます。 DP は、新しい最大の要素を追加し、考えられるすべての位置を試します。これにより、次の間が作成されます。`0`そして`i-1`新しい逆転。 
2. 可能なすべての反転回数について`k`、決定論的な並べ替えコストを計算します。`min(a*k, b+a*(m-k))`。 

特定の順列の答えには、その反転数のみが必要です。 
3. 平均ランダム化値を求めます。 させて`C=c+M`。 必要なものは次のとおりです。`C-c = average(min(C, deterministic_cost))`。 

すべての決定論的コストは定数値であるため、右側は区分的に線形です。 考えられる決定論的コストを並べ替えて、固定小数点を含む区間を見つけます。 1 つの区間内では、方程式は単純な線形方程式になります。 
4. すべてのクエリ順列について、二重ループを使用して反転をカウントします。 確定的なコストとリターンを計算する`min(C, cost)`換算分数として。 

これが機能する理由: 順列に必要な情報はその反転数だけです。 隣接するスワップとグローバル反転は、同じ反転カウントを持つすべての置換が同じ決定論的な最適値を持つように、十分な対称性を維持します。 すべての状態が決定論的なルートと同じランダムな再開値のどちらかを選択するため、固定小数点の計算では、最終的にランダム操作が使用される可能性が正しく考慮されます。 

# Python ソリューション```python
import sys
from fractions import Fraction

input = sys.stdin.readline

cache_dp = {}

def inversion_counts(n):
    if n in cache_dp:
        return cache_dp[n]
    dp = [1]
    for length in range(1, n + 1):
        ndp = [0] * (len(dp) + length)
        for i, x in enumerate(dp):
            for add in range(length):
                ndp[i + add] += x
        dp = ndp
    cache_dp[n] = dp
    return dp

def solve_average(n, a, b, c):
    counts = inversion_counts(n)
    total = 1
    for i in range(2, n + 1):
        total *= i

    mx = n * (n - 1) // 2
    values = []
    for k, cnt in enumerate(counts):
        values.append((min(a * k, b + a * (mx - k)), cnt))

    grouped = {}
    for v, cnt in values:
        grouped[v] = grouped.get(v, 0) + cnt

    arr = sorted(grouped.items())

    pref_sum = 0
    pref_cnt = 0
    prev = Fraction(0)

    for value, cnt in arr:
        if pref_cnt:
            cand = Fraction(total * c + pref_sum, pref_cnt)
            if cand <= value and cand >= prev:
                return cand
        pref_sum += value * cnt
        pref_cnt += cnt
        prev = Fraction(value)

    return Fraction(total * c + pref_sum, total)

def inv_of_perm(p):
    n = len(p)
    ans = 0
    for i in range(n):
        pi = p[i]
        for j in range(i + 1, n):
            if pi > p[j]:
                ans += 1
    return ans

def solve_case(n, a, b, c, perms):
    C = solve_average(n, a, b, c)
    mx = n * (n - 1) // 2
    out = []

    for p in perms:
        k = inv_of_perm(p)
        det = min(a * k, b + a * (mx - k))
        ans = min(C, Fraction(det))
        out.append(f"{ans.numerator}/{ans.denominator}")
    return out

def main():
    data = sys.stdin.read().strip().splitlines()
    if not data:
        return

    first = list(map(int, data[0].split()))
    idx = 0
    cases = []

    if len(first) == 1:
        z = first[0]
        idx = 1
        for _ in range(z):
            n, a, b, c, d = map(int, data[idx].split())
            idx += 1
            perms = []
            for _ in range(d):
                perms.append(list(map(int, data[idx].split())))
                idx += 1
            cases.append((n, a, b, c, perms))
    else:
        while idx < len(data):
            n, a, b, c, d = map(int, data[idx].split())
            idx += 1
            perms = []
            for _ in range(d):
                perms.append(list(map(int, data[idx].split())))
                idx += 1
            cases.append((n, a, b, c, perms))

    ans = []
    for case in cases:
        ans.extend(solve_case(*case))

    print("\n".join(ans))

if __name__ == "__main__":
    main()
```反転カウント動的計画法では、マホニアン数が格納されます。 この移行が機能するのは、新しい最大の兵士を位置に挿入すると、正確に既知の数の新しい反転が作成され、あらゆる可能な位置が考慮されるためです。 

固定小数点ソルバー グループは、すべての順列を反復するのではなく、決定論的なコストに等しくなります。 多くても`121`反転が重要なので、この部分は小さいままです。`Fraction`は、グローバル期待値を解決する場合にのみ使用され、必要な出力が正確な有理数である場合の精度エラーを回避します。 

クエリ部分では意図的にDPテーブルを使用しません。 この表には、すべての順列にわたる頻度のみが示されています。 実際の順列の場合、その正確な反転数が必要です。`n=16`二次計数法を簡単に十分高速にできるようになります。`100000`クエリ。 

# 実用的な例

 ソートされた順列の場合:

 | 順列 | 反転 | 決定論的コスト | 最終値 |
 | --- | --- | --- | --- |
 |`1 2 3 4 5 6`| 0 | 0 |`0/1`|

 反転回数はすでに最小限であるため、操作は必要ありません。 

順列については`5 4 3 2 1 6`:

 | 順列 | 反転 | 逆反転 | 決定的な選択 |
 | --- | --- | --- | --- |
 |`5 4 3 2 1 6`| 10 | 5 |`min(10a, b+5a)`|

 サンプル費用込みで`a=b=c=1`、決定論的なコストは`6`。 ランダムなオプションの方が高価なので、結果は次のようになります。`6/1`。

 # エッジケース

 解決された順列の反転カウントはゼロです。 決定論的コストはゼロになるため、ランダム化値が問題になる前にアルゴリズムはゼロを返します。 

完全に逆転した順列には反転カウントがあります`m`。 逆の演算によりゼロ反転に変更されるため、式は次を選択します。`b`隣接するすべてのスワップを支払う代わりに。 

ランダム化が魅力的な場合は、固定小数点によって処理されます。 すべての決定論的なオプションが高価な場合、計算された`C`はそれらのコストより小さくなり、そのようなすべての置換では最初にランダム操作が正しく使用されます。 方程式はグローバルに解かれるため、すべての順列は同じ再起動の期待値を共有します。
