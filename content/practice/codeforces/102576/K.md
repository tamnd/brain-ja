 ## 解決策
 ## 問題の理解

 長方形の劇場フロアがあります。 一部の座席は利用できず、残りの座席はグリッドのセルを形成します。 がある`k`さまざまな有名人のペア、意味`2k`個性的な人々。 私たちは全員を自由席に座らせなければなりません。 唯一禁止されている状況は、同じペアの 2 つのメンバーが、1 面を共有する隣接するセルに配置されている場合です。 

直接的な条件は 2 人のペアに関するものですが、それを表示する便利な方法はグリッド グラフを使用することです。 すべての自由席は頂点であり、2 つの自由席間のすべての側面接続はエッジです。 悪い有名人のペアがこのグラフの端を占めています。 count の代入が必要です。`k`固定ペアはエッジを使用します。 

グリッドには最大でも`144`細胞。 これにより、座席数に指数関数的に依存する方法は除外されます。 重要な構造上の結果は異なります。グリッドの片側は最大でも`12`なぜなら、両方の次元がより大きい場合だからです。`12`、彼らの製品は次を超えるでしょう`144`。 これにより、ビットマスクを使用したプロファイル動的プログラミング ソリューションが可能になります。 

不注意な解決策は、いくつかの点で失敗する可能性があります。 1つ目は、有名人は別個であるということを忘れていることです。 例えば：```
1 2 1
..
```席は自由席2席とペア1席。 唯一考えられる配置は、2 人の有名人に 2 つの議席を与えることです。したがって、答えは次のとおりです。`2`, 2 人を交換すると、別の割り当てが作成されるためです。 占有座席セットのみをカウントするソリューションが返されます。`1`。 

もう 1 つの間違いは、斜めのセルを隣接しているものとして扱うことです。 のために：```
2 2 1
..
..
```2 つの対角セルは許可されます。 答えは`8`：2席の4つの選択肢とペアの2つのオーダーがあります。 8 方向の隣接性を使用したソリューションでは、斜めの配置が誤って削除されてしまいます。 

最後のよくあるエラーは、有効なペアを個別にカウントしようとすることです。 で：```
1 4 2
....
```最初のペアは隣接するポジションを使用できませんが、2 番目のペアもシートを消費します。 座席は再利用できないため、選択肢は相互作用します。 

## アプローチ

 強引なアプローチでは、最初の有名人のペアに 2 つの席を選択し、次に 2 番目の有名人のペアに 2 つの席を選択し、再帰的に続行します。 これは、考えられるすべての割り当てを直接列挙しているため、正しいです。 最悪の場合、`144`自由席、ざっくり探索$$(144 \cdot 143 \cdot 142 \cdots)$$可能性をはるかに超えた選択肢。 

有益な観察は、有効な取り決めを直接カウントしないようにすることです。 包含排除により、反対の事象をカウントすることができます。 正確に仮定してください`s`有名人のペアは一緒に座ることを強制されます。 選択する方法の数が必要です`s`グリッド内で互いに切り離された隣接する座席ペア。 これらはサイズのマッチングです`s`グリッドグラフで。 

させて`R[s]`サイズの数値になります`s`マッチング。 固定セットの場合、`s`有名人のペア、悪い割り当ての数は次のとおりです。$$R[s] \cdot s! \cdot 2^s \cdot \frac{(F-2s)!}{(F-2k)!}$$どこ`F`自由席の数です。 係数は、グリッドのエッジの選択、選択した有名人のペアへの割り当て、各ペア内の順序の選択、および他の全員の配置に対応します。 

残りのタスクはコンピューティングです`R[s]`。 グリッドの幅は最大でも小さくできるため、`12`、壊れたプロファイル動的プログラミングが機能します。 グリッドをスキャンしている間、状態は、現在の行のどのセルが前の行からの垂直一致エッジによって既に占有されているかを保存します。 処理された各セルは、未使用にすることも、水平方向に一致させることも、垂直方向に下向きに一致させることもできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 座席数の指数関数的増加 | 指数再帰スタック | 遅すぎる |
 | 包含除外 + プロファイル DP |$O(n \cdot 2^w \cdot w \cdot k)$|$O(2^w \cdot k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 必要に応じてグリッドを転置し、列の数が`w`最小限です。 ビットマスクのサイズは次のものに依存します`w`, そのため、狭い側を幅にすることで、状態空間が小さく保たれます。 
2. グリッドの一致する多項式を計算します。 行全体にわたって DP を維持します。 マスクは、現在の行のどのセルが前の行からの垂直一致エッジによってすでに占有されているかを示します。 
3. 行が遷移するたびに、セルを左から右に処理します。 セルがブロックされているか、すでに占有されている場合は、何も行われません。 それ以外の場合は、一致しないままにする、次のセルと水平に接続する、または下のセルと垂直に接続するという 3 つの可能性を試します。 
4. グリッド全体が処理された後、可能なすべてのサイズの一致の数を収集します。`s`。 
5. 包含/除外を適用します。`k`有名人のペア。 あらゆる人にとって`s`、割り当ての数を加算または減算します。`s`特定のペアが隣接しています。 

機能する理由: プロファイル DP は、最初のエンドポイントが処理されるときにすべての一致するエッジが決定されるため、可能なすべての素の隣接座席ペアのセットを 1 回だけカウントします。 次に、包含/除外ステップにより、少なくとも 1 つの禁止された有名人のペアを含むすべての割り当てが削除されます。 すべての課題`t`議論するペアは、それらのサブセットに対応する用語に正確に現れます。`t`ペアであり、交互の合計は次の場合にのみそれを保持します。`t = 0`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve_case(n, m, k, grid):
    if n < m:
        grid = [''.join(grid[i][j] for i in range(n)) for j in range(m)]
        n, m = m, n

    free = sum(row.count('.') for row in grid)

    if free < 2 * k:
        return 0

    from functools import lru_cache

    @lru_cache(None)
    def transitions(r, incoming):
        res = {}
        def dfs(c, out, add):
            if c == m:
                key = (out, add)
                res[key] = res.get(key, 0) + 1
                return
            if grid[r][c] == 'X' or (incoming >> c) & 1:
                dfs(c + 1, out, add)
                return

            dfs(c + 1, out, add)

            if c + 1 < m and grid[r][c + 1] == '.' and not ((incoming >> (c + 1)) & 1):
                dfs(c + 2, out, add + 1)

            if r + 1 < n and grid[r + 1][c] == '.':
                dfs(c + 1, out | (1 << c), add + 1)

        dfs(0, 0, 0)
        return tuple(res.items())

    dp = {0: [1] + [0] * k}

    for r in range(n):
        ndp = {}
        for mask, poly in dp.items():
            for (nmask, add), ways in transitions(r, mask):
                if nmask not in ndp:
                    ndp[nmask] = [0] * (k + 1)
                cur = ndp[nmask]
                for i, v in enumerate(poly):
                    if v and i + add <= k:
                        cur[i + add] = (cur[i + add] + v * ways) % MOD
        dp = ndp

    match = [0] * (k + 1)
    for poly in dp.values():
        for i, v in enumerate(poly):
            match[i] = (match[i] + v) % MOD

    fact = [1] * (free + 1)
    for i in range(1, free + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (free + 1)
    invfact[-1] = pow(fact[-1], MOD - 2, MOD)
    for i in range(free, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    ans = 0
    comb = 1

    for s in range(k + 1):
        if s:
            comb = comb * (k - s + 1) % MOD * pow(s, MOD - 2, MOD) % MOD

        ways = match[s]
        ways = ways * fact[s] % MOD
        ways = ways * pow(2, s, MOD) % MOD
        ways = ways * fact[free - 2 * s] % MOD
        ways = ways * invfact[free - 2 * k] % MOD
        ways = ways * comb % MOD

        if s % 2:
            ans -= ways
        else:
            ans += ways

    return ans % MOD

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        n, m, k = map(int, input().split())
        grid = [input().strip() for _ in range(n)]
        ans.append(str(solve_case(n, m, k, grid)))
    print('\n'.join(ans))

if __name__ == "__main__":
    main()
```実装の最初の部分では、グリッドの幅を減らします。 内部の再帰`transitions`はプロファイル DP の行遷移です。 そのマスクには現在の行の境界を越える情報のみが含まれるため、状態カウントは小さいままになります。 

すべての DP 状態に保存されている多項式は、すでに作成されている一致するエッジの数を記録します。 水平エッジまたは垂直エッジを選択すると、次数が 1 つ増加します。 最終的な多項式は次のようになります。`R[s]`、各サイズのグリッド一致の数。 

包含-排他ループでは、順列を繰り返し計算する代わりに階乗を使用します。 モジュラスには、組み合わせと階乗除算の逆モジュラーが必要です。 Python の整数はオーバーフローしませんが、すべての乗算は剰余化されます。`10^9+7`値を小さく保つためです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \cdot 2^w \cdot w \cdot k)$| すべての行は、すべてのプロファイルの状態と一致する数を処理します。 
| スペース |$O(2^w \cdot k)$| アクティブなプロファイル状態とその多項式を保存します。 

ここ`w <= 12`、 それで`2^w`せいぜい`4096`。 グリッド領域の制約はまさにこのプロファイル DP を実用的なものにします。 

## 実用的な例

 のために`2 x 2`空のグリッドと`k = 2`、一致する多項式には次のものが含まれます。 

| 適合サイズ | 一致する数 |
 | --- | --- |
 | 0 | 1 |
 | 1 | 4 |
 | 2 | 2 |

 包含/除外の計算は次のとおりです。 

| s | 寄稿元 |
 | --- | --- |
 | 0 | すべての無制限の割り当て |
 | 1 | 選択した 1 つのペアが隣接するエッジにある割り当てを削除します。 
| 2 | 両方のペアを隣接するエッジに強制的に割り当てるバック割り当てを追加します。 

交互の合計により、`8`、サンプルと一致します。 

2 番目のサンプルでは、​​同じ DP が最初に不規則なグリッドの一致するカウントを構築します。 ブロックされたセルは、単にそれらの位置を通過する遷移を阻止するだけなので、一致するエッジのエンドポイント候補として表示されることはありません。 その後、包含-排他は特別なケースなしで有名人のペアを処理します。

 ## 特殊なケース

 包含/除外合計には依然として無制限の用語と禁止された用語の両方が含まれているため、空きシートが 2 つだけある 1 つのペアが処理されます。 禁止された用語は、隣接する配置のみを削除し、正しい順序で割り当てられたものを残します。 

ブロックされたセルは当然、遷移ジェネレーターによって処理されます。 例えば：```
2 2 1
X.
..
```自由席は3席あります。 DP はブロックされたセルを含むエッジを作成しないため、一致する多項式は有効なグリッド グラフのみを記述します。 

可能な限り狭いグリッドもカバーされます。 あ`1 x 144`劇場は横幅のある横顔になる`1`なので状態空間は小さいです。 このアルゴリズムは、大きい次元が小さいということに依存しません。
