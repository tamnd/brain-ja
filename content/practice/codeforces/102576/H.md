 ## 解決策
 ## 問題の理解

 頂点が灯台である凸多角形があります。 いくつかの頂点のペアは路面電車の線路で接続されており、Vladik はそれらの線路に沿ってのみ移動できます。 有効な旅行はこのグラフのパスですが、幾何学的制限があります。旅行セグメントの描かれたチェーンはそれ自体と交差したり、同じ地点を 2 回訪れたりすることはできません。 

タスクは、そのようなパスの可能な最大合計ユークリッド長を見つけることです。 

灯台の数は最大 300 であり、パスまたは頂点のサブセットの列挙に依存するソリューションは除外されます。 300 個の頂点を持つグラフでもほぼ 45,000 個のエッジを持つことができるため、3 次時間に近い解が自然な目標となります。 すべてのテストの頂点の合計数はわずか 3000 であるため、テストごとの処理が多少重くなる可能性があります。 

主な困難はグラフの走査ではありません。 一般的なグラフの最長パスは困難ですが、ここではすべての頂点が凸多角形上にあります。 頂点の順序により、強力な幾何学的構造が得られます。つまり、コードを選択するたびに、残りの可能なルートはそのコードの片側に制限されます。 これにより、より小さな独立した部分問題が作成されます。 

いくつかのケースでは、単純なアプローチが簡単に崩れてしまいます。 交差する路面電車の路線がある場合、グラフ理論上のより大きな経路が得られたとしても、両方が答えに現れることはできません。 たとえば、両方の対角線が利用可能な正方形では、ルートは許可されません。`1-3-2-4`, 対角線が真ん中で交差しているからです。 正しいルートでは交差点を避けなければなりません。 

もう 1 つの罠は、最長の経路が固定された灯台から始まらなければならないと想定していることです。 連続する辺が 3 つしかない正方形を考えてみましょう。 最適なルートはこれらの辺の一端から始まり、もう一方の端で終わるため、最初の頂点を修正すると最適なルートが失われる可能性があります。 

3 番目の問題は、多角形が円形であることです。 パスは、最後にインデックス付けされた頂点と最初にインデックス付けされた頂点の間の人工的な境界を越えることができます。 のみ機能する任意の間隔 DP`0...n-1`円を操作しないと、有効な答えを見逃す可能性があります。 

## アプローチ

 ブルートフォース ソリューションでは、考えられるすべての頂点シーケンスを試し、有効な路面電車の経路を形成するシーケンスのみを保持し、自己交差のあるものは拒否します。 これは正しいです。考えられるすべての移動が明示的に考慮されているからです。 ただし、可能なパスの数は指数関数的です。 サブセット全体を完全に検索する場合でも、すでにおおよその情報が必要になります。`2^300`状態、それは不可能です。 

有益な観察は、多角形が凸面であるということです。 有効なパスを選択し、頂点の一定間隔内の最初のエッジを確認します。 そのエッジが選択されると、パスの残りの部分は強制的に弦の片側に留まります。これは、両側で頂点を使用すると、将来のセグメントが選択した弦と交差することになるためです。 

これは、問題が区間動的計画法で解決できることを意味します。 まだ使用可能なポリゴンのセグメントと、現在のルートが配置されているエンドポイントを追跡します。 次の路面電車の端を選択すると、残る問題は、既知の終点を使用したさらに小さな間隔になります。 

多角形は円形であるため、頂点を複製し、この 2 倍の配列に対して間隔 DP を実行します。 可能なすべての長さの円区間`n`その後は通常の間隔として表示されます。

 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | インターバルDP | O(n3) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ポリゴンの頂点を複製します。 頂点`i`位置にコピーされます`i+n`、それに応じてすべての路面電車のエッジがコピーされます。 これにより、円形の範囲が通常の間隔に変換されます。 
2. 定義する`dp[l][r]`の頂点のみを使用する有効なルートの最大長として`l`に`r`現在のエンドポイントは`l`。 
3. 長さを増やして間隔を処理します。 しばらくの間`[l,r]`、最初に頂点をスキップしてから答えを継承します`l`、それは与える`dp[l+1][r]`。 
4. 可能な限りすべての最初の路面電車の端を試してください。`l`頂点へ`k`間隔の中。 そのエッジが存在する場合、次の場所に移動した後、`k`、残りの旅行は屋内にとどまる必要があります`[k,r]`そしてから始めます`k`。 移行は次のとおりです。$$dp[l][r] = \max(dp[l][r], dist(l,k)+dp[k][r])$$1. 答えは最大値です`dp[i][i+n-1]`すべてのスタートポジションにわたって。 これらの間隔は、円形の多角形を切り取る場所のあらゆる選択肢を表します。 

DP の背後にある不変条件は、間隔内のすべての有効なルートが現在のエンドポイントからの最初のエッジを 1 つだけ持つか、そのエンドポイントをまったく使用しないことです。 最初のケースでは、選択されたエッジにより、残りの検索スペースが弦の正しい側のより小さな間隔に分割されます。 2 番目のケースでは、エンドポイントを削除すると、別の有効間隔の問題が残ります。 すべての有効なルートはこれら 2 つの形式のいずれかに従っているため、反復では考えられるすべての答えが考慮され、無効な交差点が作成されることはありません。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve_case():
    n = int(input())
    pts = []
    for _ in range(n):
        x, y = map(int, input().split())
        pts.append((x, y))

    m = int(input())

    size = 2 * n
    edges = [[-1.0] * size for _ in range(size)]

    def length(a, b):
        x1, y1 = pts[a % n]
        x2, y2 = pts[b % n]
        return math.hypot(x1 - x2, y1 - y2)

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        w = length(a, b)
        for x in (a, a + n):
            for y in (b, b + n):
                if x < size and y < size:
                    edges[x][y] = w
                    edges[y][x] = w

    dp = [[0.0] * size for _ in range(size)]

    for ln in range(2, n + 1):
        for l in range(size - ln + 1):
            r = l + ln - 1
            best = dp[l + 1][r]
            row = edges[l]
            for k in range(l + 1, r + 1):
                if row[k] >= 0:
                    cand = row[k] + dp[k][r]
                    if cand > best:
                        best = cand
            dp[l][r] = best

    ans = 0.0
    for i in range(n):
        if dp[i][i + n - 1] > ans:
            ans = dp[i][i + n - 1]
    return ans

def main():
    data = sys.stdin.read().split()
    if not data:
        return

    it = iter(data)

    def next_input():
        return next(it)

    global input
    old_input = input

    def fake_input():
        return next_input() + "\n"

    input = fake_input

    t = int(input())
    out = []
    for _ in range(t):
        out.append(f"{solve_case():.12f}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```エッジ マトリックスには、利用可能なすべての路面電車の長さが格納されます。 重複したインデックス付けは、座標を法的に取得することによって処理されます。`n`, したがって、コピーされた頂点は同じ幾何学的位置を共有します。 

DP テーブルには、最大でも長さの間隔のみが保存されます。`n`。 2 倍のポリゴンの間隔が長くなると、灯台が繰り返され、無効なルートが作成される可能性があります。 間隔の長さのループにより、すべての依存関係が使用前にすでに計算されていることを保証します。 

移行では、現在の終点から出発する可能な最初の路面電車のすべての路線が試行されます。 トラム路線が存在しない場合、州は単にその終点を無視するオプションを保持します。 Python の整数は座標範囲を安全に処理し、すべての幾何学的計算では最終的な長さを計算する場合にのみ浮動小数点を使用します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n3) | O(n²) 個の間隔があり、それぞれが O(n) 個の次の頂点を試行します。 |
 | スペース | O(n²) | DP テーブルとエッジ マトリックスには両方とも O(n²) 値が含まれています。 |

 のために`n = 300`、3 次項は約 2,700 万回の遷移であり、指定された制限に適しています。 すべてのテストの頂点の合計数により、蓄積された作業が管理可能になります。 

## 特殊なケース

 路面電車の路線が存在しない場合、すべての DP 遷移は失敗し、すべての状態は 0 のままになります。 答えは正解です`0`、なぜなら、ウラジクはどこにも移動できないからです。 

最適なルートが入力オーダーの最後をラップする場合、複製されたポリゴンがそれをキャプチャします。 利用可能なエッジが次のような正方形の場合`1-4`、`4-3`、`3-2`、`2-1`、最適なルートは 3 つの側面を使用します。 元のインデックス付けでは、これは人工的な境界を越えますが、二重化された配列では通常の間隔として表示されます。 

利用可能な 2 つのコードが交差する場合、DP はそれらを 1 つのルートに結合しません。 1 つのコードを選択すると、残りのステートがそのコードの片側に制限されるため、交差するコードが同じパスの後半に現れることはできません。 これは、明示的な交差チェックに代わる幾何学的プロパティです。
