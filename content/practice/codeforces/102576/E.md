 ## 解決策
 ## 問題の理解

 世界は、多くの円形の禁止領域を含む平面として表されます。 爆発ごとにそのような領域が 1 つ作成されます。 クエリ内の 2 匹の動物は、水平バンド内で移動する必要があります。`ymin`に`ymax`、禁止されたサークルに入ることはありません。 タスクは、両方のポイントがそのバンドの同じ接続部分に属しているかどうかを判断することです。 

重要な幾何学的観察は、円が水平バンドの両方の水平境界に触れた場合にのみ、水平バンド内の動きをブロックできるということです。 円に垂直スパンがある場合`[cy-r, cy+r]`、まさに次の場合、それはクエリにとって完全な壁になります。`cy-r <= ymin`そして`cy+r >= ymax`。 

すべての汚染領域はばらばらであるため、これらの壁は複雑な形状に融合することができません。 壁によってストリップが左側と右側に分けられます。 中心の x 座標が厳密にそれらの x 座標の間にあるような壁が存在する場合、2 匹の動物は正確に会うことができません。 

制約により、オフラインでの解決が強制されます。 最大 100 万の爆発と 100 万のクエリを使用すると、すべてのクエリのすべての円をチェックするには約`10^12`操作、それは不可能です。 に近い前処理戦略が必要です。`O((n+q) log n)`。 

よくある間違いは、ストリップ内にブロッキング サークルが存在するかどうかだけを確認することです。 ブロックサークルが両方の動物の完全に左側または右側にある可能性があるため、これでは不十分です。 もう 1 つの間違いは、中心の x 座標が動物の座標の 1 つと等しい円を含めることです。 円がストリップ全体にまたがる場合、中心を通る垂直線全体が汚染されているため、このようなケースはストリップ内の有効な動物点では起こりません。 

たとえば、次のことを考えてみましょう。```
1 2
0 0 1
-5 0 5 0 -1 1
```円はストリップをブロックし、2 つの点を分離します。したがって、答えは次のようになります。`NO`。 

しかし：```
1 2
0 0 1
-5 0 -3 0 -1 1
```同じ円が存在しますが、両方の点がその左側にあるため、答えは次のようになります。`YES`。 ブロックサークルが存在するかどうかだけをチェックするソリューションは失敗します。 

## アプローチ

 直接的なアプローチは、すべてのクエリのすべての爆発をテストすることです。 クエリごとに、爆発が垂直方向の範囲をカバーしているかどうか、およびその中心が 2 つの X 座標の間にあるかどうかを確認します。 すべての区切り記号はこれらの全高の円の 1 つである必要があるため、これは正しいです。 ただし、`10^6`クエリと`10^6`最悪の場合は`10^12`小切手。 

重要な削減は、個々のクエリを幾何学的に考えるのをやめ、代わりに同じ移動境界を持つすべてのクエリを処理することです。 クエリを緯度の低い順に並べ替えます。 増えると`ymin`、下端がスイープ ラインの下にあるため、より多くの円を壁の下に配置できるようになります。 挿入された円ごとに、その上端をその x 座標に保存します。 

スイープのどの時点でも、構造には次を満たす円が正確に含まれています。`cy-r <= current_ymin`。 

クエリの場合`[ymin, ymax]`挿入された円のうち、少なくとも 2 匹の動物の間の x 座標に最大の上端があるかどうかを知る必要があるだけです。`ymax`。 そのような値が存在する場合、その円は上部の境界線に到達し、道を妨げます。 

これは、圧縮された x 座標に関する範囲最大クエリの問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | セグメントツリーによるオフラインスイープ | O((n+q) log n) | O(n+q) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての円を下部の座標で並べ替えます`cy-r`。 すべてのクエリを並べ替える基準`ymin`。 スイープ中に、底部がすでに現在のクエリの下限より下にある円を挿入します。 
2. すべての円の中心の X 座標を圧縮します。 セグメント ツリーには、圧縮された x 位置ごとに、最大の`cy+r`その中心を持つ挿入された円の間。 
3. 各クエリについて、厳密に 2 つの動物の位置の間の中心 x 座標の圧縮範囲を見つけます。 この範囲が空の場合、円で区切ることはできません。 
4. その X 範囲のセグメント ツリーをクエリします。 保存されている最大の上部座標が少なくとも`ymax`、動物の間には高さいっぱいの汚染壁が存在するため、答えは次のようになります。`NO`。 それ以外の場合、答えは次のとおりです。`YES`。 

なぜ効果があるのか:

 スイープの不変条件は、すべての円を次のように処理した後、`cy-r <= ymin`、セグメント ツリーには、現在のストリップの底部に接触する可能性のある円が正確に含まれています。 クエリは、それらのサークルのいずれかが到達した場合にのみ失敗します。`ymax`そしてその中心の x 座標は 2 匹の動物の間にあります。 範囲最大クエリはこの条件を正確にチェックするため、返されたすべての回答はストリップの実際の接続と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegmentTree:
    def __init__(self, n):
        self.n = 1
        while self.n < n:
            self.n *= 2
        self.t = [-(10**30)] * (2 * self.n)

    def update(self, i, v):
        i += self.n
        if self.t[i] >= v:
            return
        self.t[i] = v
        i //= 2
        while i:
            nv = self.t[2 * i]
            if self.t[2 * i + 1] > nv:
                nv = self.t[2 * i + 1]
            if self.t[i] == nv:
                break
            self.t[i] = nv
            i //= 2

    def query(self, l, r):
        if l >= r:
            return -(10**30)
        l += self.n
        r += self.n
        ans = -(10**30)
        while l < r:
            if l & 1:
                if self.t[l] > ans:
                    ans = self.t[l]
                l += 1
            if r & 1:
                r -= 1
                if self.t[r] > ans:
                    ans = self.t[r]
            l //= 2
            r //= 2
        return ans

n, q = map(int, input().split())

circles = []
xs = []

for _ in range(n):
    cx, cy, r = map(int, input().split())
    circles.append((cy - r, cy + r, cx))
    xs.append(cx)

xs.sort()
unique_x = []
for x in xs:
    if not unique_x or unique_x[-1] != x:
        unique_x.append(x)

circles.sort()

queries = []
for i in range(q):
    px, py, qx, qy, ymin, ymax = map(int, input().split())
    queries.append((ymin, ymax, px, qx, i))

queries.sort()

seg = SegmentTree(len(unique_x))
ans = ["YES"] * q
ptr = 0

import bisect

for ymin, ymax, px, qx, idx in queries:
    while ptr < n and circles[ptr][0] <= ymin:
        bottom, top, cx = circles[ptr]
        seg.update(bisect.bisect_left(unique_x, cx), top)
        ptr += 1

    if px > qx:
        px, qx = qx, px

    left = bisect.bisect_right(unique_x, px)
    right = bisect.bisect_left(unique_x, qx)

    if seg.query(left, right) >= ymax:
        ans[idx] = "NO"

print("\n".join(ans))
```スイープ ポインタは前方にのみ移動するため、すべての円は 1 回だけ挿入されます。 セグメント ツリーの更新では、各 X 座標の最大上端が維持されます。これは、同じ中心を持つ複数の円のうち、最も高い円のみがクエリをブロックできるためです。 

の使用`bisect_right`そして`bisect_left`意図的です。 クエリでは、厳密に 2 匹の動物間の中心が求められます。 エンドポイントを含めると、誤った障壁が発生します。 

すべての座標は Python 整数内に快適に収まります。 このアルゴリズムは二乗距離を計算したり、浮動小数点演算を実行したりしないため、精度の問題が回避されます。 

## 実用的な例

 サンプル入力の場合、円は次のとおりです。 

| 中心 x | 下 | トップ |
 | --- | --- | --- |
 | 3 | 1 | 5 |
 | 7 | 4 | 10 |
 | 12 | 3 | 7 |

 最初のクエリの場合、ストリップは次のようになります。`[2,6]`。 

| ステップ | 現在のymin | 挿入された円 | x=1 と x=14 の間の最大上部 | 結果 |
 | --- | --- | --- | --- | --- |
 | スイープが 2 に到達 | 2 | x=3 | 5 | 続ける |
 | クエリymax | 6 | x=3、x=12 チェック済み | 5 | はい |

 x=3 の円は下側には到達しますが、上側には到達しないため、ストリップを分割できません。 

2 番目のクエリの場合、ストリップは次のようになります。`[4,7]`。 

| ステップ | 現在のymin | 挿入された円 | x=1 と x=14 の間の最大上部 | 結果 |
 | --- | --- | --- | --- | --- |
 | スイープが 4 に到達 | 4 | x=3、x=7、x=12 | 10 | いいえ |

 x=7 を中心とする円はストリップ全体を覆い、動物の間にあり、通行できない壁を形成します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n+q) log n) | 各円の更新とクエリは対数 |
 | スペース | O(n+q) | 円、クエリ、圧縮された座標、および回答を保存します。 

このソリューションは、指定された制限に適した対数演算を使用して 200 万のオブジェクトを処理します。 メモリ使用量は線形です。

 ## 特殊なケース

 両方の境界線に正確に接する円は壁としてカウントされます。 条件は以下を使用します`<=`そして`>=`、厳密な不平等ではありません。 垂直スパンのある円の場合`[0,10]`そしてクエリストリップ`[0,10]`、円が動きをブロックします。 

1 つの境界線にのみ接触する円はカウントされません。 垂直方向のスパンを持つ円`[0,5]`ストリップ内の動きを防ぐことはできません`[0,10]`動物は頂上を回ることができるからです。 

同じ x 座標を持つ複数の円は、最大の上部値を維持することによって処理されます。 このような最も高い円は、今後のすべてのクエリにおいて、より低いすべての円を支配します。 

クエリは、出現する順序とは関係なく回答されます。 オフライン スイープでは、保存されたクエリ インデックスを使用して印刷前に元の順序が復元されます。
