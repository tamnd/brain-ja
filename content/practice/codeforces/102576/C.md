 ## 解決策
 ## 問題の理解

 数日間にわたって各コミットで変更された行数が表示されます。 単一のコミットに対して繰り返し 1 行を追加または削除することがあります。目標は、最終的な値の各ペアが少なくとも異なるようにコミット サイズを分散させることです。`d`。 タスクは、必要な単一行編集の最小数を見つけることです。 

1 つのテスト ケースでは、入力にはコミット数、2 つの最終コミット サイズ間の必要な最小距離、および元のサイズが含まれます。 出力は、有効なコミット サイズのセットに到達するために必要な最小の総移動量です。 コミット サイズはプロセス中に決して負になってはなりませんが、構築する最終値は負ではないため、そこに直接移動するときにゼロ未満を渡す必要はありません。 

すべてのテスト ケースにわたるコミットの合計数は 100 万に達する可能性があります。 これにより、多くのコミットのペアを比較したり、多くの可能な最終構成を試したりするソリューションは除外されます。 解決策`O(n log n)`または`O(n)`テストケースごとに必要です。 コミット サイズの値が大きいため、実装では小さな座標に基づく仮定も避ける必要があります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 すべての値が同一の場合、単純に元の値の周りに値を分散することは最適ではない可能性があります。これは、最も安価な配置では一部の値が下に移動し、一部の値が上に移動する可能性があるためです。 例えば：```
1
4 1
0 0 0 0
```答えは`4`。 後の要素だけを増やす不注意なアプローチでは、次のような問題が発生します。`0,1,2,3`そしてコスト`6`、最適な最終値は次のとおりです。`-1,0,1,2`ただし、値が負になることはできません。 非負の制限により、最初の値が次のように変更されます。`0`、最終的な値を与える`0,1,2,3`そしてコスト`6`。 この例では、重要な詳細が明らかになります。元のステートメントの制約は、解全体を自由にゼロ未満にシフトできないことを意味します。 

もう 1 つの注意が必要なケースは、元の順序が並べ替えられていない場合です。 編集後は日付自体に関係がないため、入力順序を守ると間違った答えが得られる可能性があります。 例えば：```
1
3 10
100 0 50
```値はまず次のように並べ替える必要があります。`0,50,100`。 入力順序に従って最終位置を割り当てると、最小の元の値が最小の最終値を受け取る必要があるため、編集が無駄になります。 

3 番目のケースは、変換された値が正確に境界上にある場合です。 例えば：```
1
3 5
0 5 10
```答えは`0`、値がすでに少なくとも少なくとも異なっているため、`5`。 厳密なアルゴリズムを使用するアルゴリズム`>`代わりに比較`>=`誤って変更を追加してしまう可能性があります。 

## アプローチ

 直接的な強引なアイデアは、値を並べ替えて、最終的な値を 1 つずつ選択しようとすることです。 最初の最終値が固定されると、それ以降のすべての値には下限が設定されます。これは、少なくとも次の値でなければならないためです。`d`前のものより大きい。 多くの可能な開始点または多くの可能な最終位置を試すことはすぐに不可能になります。 各値の可能な配置をすべてチェックするだけでも、利用可能な操作をはるかに超える操作が必要になります。`n`数十万に達します。 

並べ替えると構造が単純になります。 最適なソリューションでは、最小の元の値が最小の最終値に割り当てられ、2 番目に小さい値が 2 番目に小さい値に割り当てられます。 これは、絶対的な差分に対する通常の交換引数から導き出されます。つまり、2 つの割り当てが交差する場合、それらを交換しても合計距離を増やすことはできません。 

ソートされた値を次のようにします`a`。 最終的な値は次を満たす必要があります。```
y[0] <= y[1] - d <= y[2] - 2d <= ...
```便利な変換により、必須のギャップが削除されます。 定義する：```
b[i] = a[i] - i*d
```そして次のようにしましょう:```
x[i] = y[i] - i*d
```これで、条件は次のように単純になります。```
x[0] <= x[1] <= ... <= x[n-1]
```問題は、次の値に最も近い非減少シーケンスを見つけることに変わりました。`b`絶対距離下で。 これは古典的な 1 次元 L1 アイソトニック回帰問題です。 

L1 等張回帰の場合、昇順に違反する連続グループがマージされます。 マージされたすべてのグループは、グループの要素の中央値に等しい共通の値を受け取ります。 選択した値までの絶対距離の合計がどの中央値でも最小になるため、中央値が最適になります。 

プール隣接違反​​者アルゴリズムを使用して、これらのグループを維持できます。 新しい値によって最後の 2 つのグループが無効になると、それらはマージされます。 すべてのマージの後、各グループの寄与は、その要素からグループの中央値までの距離の合計になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コミット サイズを徐々に並べ替えます。 これにより、交差代入では差の絶対コストを改善できないため、最終値も昇順であると仮定できます。 
2. 各位置から必要な間隔を引きます。 インデックスの値について`i`、 作成する：```
b[i] = sorted[i] - i*d
```問題は今作ることです`b`合計の絶対変化を最小限に抑えながら減少しない。 

1. グループを使用して値を左から右に処理します。 各グループには、同じ最終アイソトニック値を共有する必要があるすべての変換値が保存されます。 最初は、すべての値が独自のグループを形成します。 
2. 前のグループの中央値が現在のグループの中央値より大きい場合は常に、2 つのグループをマージします。 増加条件が違反されるため、2 つのグループが分離されたままになることはできません。 
3. すべてのマージが完了したら、すべてのグループのコストを計算します。 グループの値の中央値を選択し、その中央値との差の絶対値の合計を加算します。 
4. 変換された問題の結果を必要な編集数として追加します。 

機能する理由: この変換では固定間隔の要件が削除されるだけなので、有効な最終配置はすべて、非減少変換配置に正確に対応します。 プール隣接違反​​者アルゴリズムは、単調制約が破られた場所を正確にマージし続けます。 マージされたブロックは 1 つの共通の値を持つ必要があり、中央値はそのブロック内の L1 エラーを最小化する値です。 考えられるすべての違反が解決され、すべてのブロックが個別に最適化されるため、最終的なシーケンスは全体的に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Block:
    __slots__ = ("vals", "left", "right")
    def __init__(self, vals):
        self.vals = vals
        self.left = 0
        self.right = len(vals) - 1

    def size(self):
        return self.right - self.left + 1

    def median(self):
        return self.vals[(self.left + self.right) // 2]

def solve():
    z = int(input())
    ans = []

    for _ in range(z):
        n, d = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        blocks = []
        for i, x in enumerate(a):
            blocks.append(Block([x - i * d]))
            while len(blocks) >= 2:
                x = blocks[-2]
                y = blocks[-1]
                if x.median() <= y.median():
                    break
                merged = sorted(x.vals[x.left:x.right + 1] + y.vals[y.left:y.right + 1])
                blocks.pop()
                blocks.pop()
                blocks.append(Block(merged))

        res = 0
        for block in blocks:
            m = block.median()
            for x in block.vals:
                res += abs(x - m)

        ans.append(str(res))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```ソートのステップでは、最適な割り当てが従う必要がある順序に値を配置します。 による引き算`i*d`連続するコミット間の強制的な距離を削除し、元の状態を通常の単調性に変えます。 

の`blocks`stack は、変換された配列の現在のパーティションを表します。 各ブロックはすでに内部で並べ替えられており、可能な限り最良の定数値を表す中央値を持っています。 2 つの隣接する中央値が正常でない場合、唯一の有効な修復は、それらを 1 つのより大きなブロックに結合することです。 

すべてのマージ後に最終的な L1 コストを計算する必要があるため、実装では各ブロック内に実際の値が格納されます。 すべてのブロックにわたる保存された値の合計数は線形のままです。 Python の整数は大きな中間合計を安全に処理します。これは、答えが 32 ビットの範囲を超える可能性があるため重要です。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline
    z = int(data())
    out = []
    for _ in range(z):
        n, d = map(int, data().split())
        a = list(map(int, data().split()))
        a.sort()
        blocks = []

        class B:
            def __init__(self, v):
                self.v = v
            def med(self):
                return self.v[(len(self.v) - 1) // 2]

        for i, x in enumerate(a):
            blocks.append(B([x - i * d]))
            while len(blocks) > 1 and blocks[-2].med() > blocks[-1].med():
                merged = sorted(blocks[-2].v + blocks[-1].v)
                blocks.pop()
                blocks.pop()
                blocks.append(B(merged))

        ans = 0
        for b in blocks:
            m = b.med()
            ans += sum(abs(x - m) for x in b.v)
        out.append(str(ans))

    sys.stdin = old
    return "\n".join(out)

 ## 特殊なケース

 すべて等しい場合:```
1
4 1
0 0 0 0
```変換された値は次のとおりです。`0,-1,-2,-3`。 新しい値はすべて前の中央値に違反するため、すべての要素が 1 つのブロックにマージされます。 中央値は変換された動きを最小化し、非負の最終値を尊重した後、コミットは次のようになります。`0,1,2,3`。 このアルゴリズムは、各コミットを個別に処理するのではなく、マージを通じて繰り返される値を処理します。 

未分類の場合:```
1
3 10
100 0 50
```並べ替えると得られるもの`0,50,100`。 変換された値は次のとおりです。`0,40,80`、すでに減少していないため、アルゴリズムは 3 つの別々のブロックを保持します。 最終的な値は、オフセットを追加し直した後、すでに正しく配置されており、最小コストが生成されます。 これにより、入力順序を保持するという間違いを回避できます。 

正確な境界の場合:```
1
3 5
0 5 10
```変換された値は次のとおりです。`0,0,0`。 等しい変換値が許可されるため、ブロックはマージされます。 最後のシーケンスはそのままでもよい`0,5,10`、合計の動きはゼロになります。 これにより、条件が以下に基づいていることが確認されます。`>= d`、厳密な不等式ではありません。
