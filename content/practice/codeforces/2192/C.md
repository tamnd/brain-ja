 ## 解決策
 ## 問題の理解

 私たちは銃の弾倉が入った銃を持っているシューティング ゲームのシナリオを与えられました。`n`弾丸。 各弾丸には固定ダメージがあります`a_i`、弾丸は 1 秒ごとに順番に発射されます。 マガジンをリロードする前にマガジンを完全に空にする必要があります。`k`秒が発生する可能性があり、リロード後に同じ弾丸シーケンスが復元されます。 敵はから始まる`h`私たちの目標は、できるだけ早く健康状態をゼロ以下にすることです。 さらに、オプションで、戦闘前にマガジン内の任意の 2 つの弾丸を 1 回交換して、ダメージ出力を最適化することができます。 

入力では複数のテスト ケースが提供され、それぞれのテスト ケースで弾丸の数、敵の体力、リロード時間、弾丸によるダメージのリストが記述されます。 出力は、各テスト ケースで敵を倒すのに必要な最小秒数です。 

制約は大きいです:`n`最大 2×10^5 まで可能で、`h`そして`k`最大 10^9。 合計から`n`すべてのテスト ケースの値も 2×10^5 で制限されるため、テスト ケースごとに線形または線形演算時間で実行されるアルゴリズムを設計する必要があります。 発砲を毎秒シミュレートする単純なアプローチは、特に高弾性の場合には失敗します。`h`なぜなら、それには何十億もの操作が含まれる可能性があるからです。 

明らかではないエッジケースには、最初の弾丸が弱すぎる状況が含まれ、最適な交換には強力な弾丸を前方に移動することが含まれます。 たとえば、次の場合`n = 5`、`h = 10`、`k = 2`、 そして`a = [1, 1, 1, 10, 1]`、スワップを行わない単純なアプローチでは、次の 3 つの弾丸をシミュレートする可能性があります。`1`そしてリロードすると不必要に時間がかかります。 正しい動きは最後の弾丸を交換することです`10`キルタイムを最小限に抑えるために、より早い位置に移動します。 

別のエッジケースは、1 つのマガジン内の全弾丸の合計が以下の場合に発生します。`h`、複数回のフルリロードが必要です。 リロードを過大評価するとキルタイムが膨らむ可能性があるため、フロア分割だけでなく、必要なフルサイクルと残りの弾丸の正確な数を計算するように注意する必要があります。 

## アプローチ

 強引な方法は、発砲の各秒をシミュレートし、可能な位置のすべてのペアでオプションのスワップを適用し、必要な合計時間をチェックすることです。 単一のテスト ケースの場合、これには O(n^2) 個のスワップが含まれる可能性があり、各スワップについて最大で次のシミュレーションが必要になる場合があります。`h`秒。 これは明らかに不可能です`n`最大 2×10^5 および`h`操作数は 10^14 に達する可能性があるため、最大 10^9 になります。 

重要な観察は、最初の弾丸が常に最初に発射されるため、キルタイムに最も大きな影響を与えるため、唯一の意味のある交換は最大の弾丸ダメージを最初の位置に持ってくることであるということです。 これが分かれば、元のシーケンスと、最初の弾丸が最大ダメージの弾丸と交換されたシーケンスの 2 つのシナリオを考えることができます。 どちらの場合も、到達するために必要な最小弾丸数を計算できます。`h`ヘルス状態を確認し、完全なリロードと部分的なサイクルを考慮して、それを時間に換算します。 

箇条書きのプレフィックスの合計を順番に事前計算することで、毎秒個別にシミュレーションすることなく、必要な箇条書きの数を迅速に決定できます。 これにより、テスト ケースごとに問題が O(n^2) から O(n) に減少します。

 | --- | --- | --- | --- |
 | すべてのスワップを使用したブルート フォース シミュレーション | O(n^2 + h) | O(n) | 遅すぎる |
 | 最適化されたスワップ + プレフィックスの合計 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`、`h`、`k`、そして弾丸ダメージの配列`a`。 
2. 最大弾丸ダメージの指標を特定します。`a`。 これを最初の箇条書きと交換して、オプションの最適化されたシーケンスを作成することを検討してください。 作成する`a_swapped`このオプションの交換後のシーケンスとして。 
3. 元のシーケンスと交換されたシーケンスの両方のプレフィックスの合計を計算します。 プレフィックスの合計`prefix[i]`最初の射撃によって与えられた合計ダメージを表します`i`弾丸を順番に。 
4. シーケンスごとに、削減するために必要な最小弾丸数を決定します。`h`ゼロ以下にします。 マガジン内の全弾丸の合計が`s`、その後、雑誌全体を適用できます`full_cycles = h // s`、残りは次のマガジンからの追加弾によって処理されます。 
5. 必要な弾丸の数を合計時間に変換します。 フルマガジンごとに消費する`n`秒、さらにリロード`k`秒。 部分的なマガジンは、マガジンを使い終えない場合、リロードを必要とせずに、それぞれの弾丸数を秒単位で追加します。 
6. 元のシーケンスと交換されたシーケンスの合計時間を比較します。 小さい方の時間を出力します。 

機能する理由: マガジンの最初の弾丸はリロード前に発射されるため、キルタイムの短縮に最も貢献します。 他の箇条書きペアを交換しても、最小時間をさらに短縮できるほど最初のショットのプレフィックス合計は改善されません。 プレフィックスの合計とサイクルを使用してダメージを計算することで、すべてのリロードを正確に考慮できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_time_to_kill(n, h, k, a):
    max_idx = max(range(n), key=lambda i: a[i])
    if max_idx != 0:
        a_swapped = a[:]
        a_swapped[0], a_swapped[max_idx] = a_swapped[max_idx], a_swapped[0]
    else:
        a_swapped = a[:]
    
    def compute_time(arr):
        prefix = [0] * n
        prefix[0] = arr[0]
        for i in range(1, n):
            prefix[i] = prefix[i-1] + arr[i]
        total = prefix[-1]
        if total >= h:
            for i, val in enumerate(prefix):
                if val >= h:
                    return i + 1
        else:
            full_cycles = h // total
            rem = h % total
            time = full_cycles * (n + k)
            if rem == 0:
                return time - k
            for i, val in enumerate(prefix):
                if val >= rem:
                    return time + i + 1
        return None

    return min(compute_time(a), compute_time(a_swapped))

t = int(input())
for _ in range(t):
    n, h, k = map(int, input().split())
    a = list(map(int, input().split()))
    print(min_time_to_kill(n, h, k, a))
```機能`min_time_to_kill`1 つのテスト ケースの最小秒数を計算します。 まず、オプションで最初の弾丸を最大ダメージ弾丸と交換します。 の`compute_time`この関数はプレフィックスの合計を使用して必要な弾丸の数を決定し、マガジン全体のリロードは合計時間に含まれます。 の`min`of the original and swapped sequence ensures we account for the optional swap.
