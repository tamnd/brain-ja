 ## 問題の理解

 次のシーケンスであるバイナリ文字列が与えられます。`0`と`1`s で、非常に具体的な操作を実行できます。インデックスを 1 つ選択します。`i`、インデックスのビットを除く文字列内のすべてのビットを反転します`i`。 反転とは変化することを意味します`0`に`1`そして`1`に`0`。 この操作は複数回実行できますが、各インデックスは 1 回しか使用できません。 目標は、文字列内のすべてのビットを次と等しくすることです。`0`。 それが不可能な場合は報告しなければなりません`-1`。 

文字列の長さ`n`最大 200,000 まで可能で、1 回の実行でのすべてのテスト ケースの合計長も 200,000 を超えることはありません。 これにより、組み合わせの数が指数関数的に増加するため、すべての一連の操作を試行するブルートフォース ソリューションが即座に排除されます。`n`。 代わりに、文字列構造を検査し、単一パスまたは文字列に対する数回のパスで選択するインデックスを決定するアプローチが必要です。 

一部の明らかではないエッジ ケースは、すでにすべて 0 である文字列、または次の数の文字列から発生します。`1`s は、ある意味では文字列の長さのちょうど半分になります。 たとえば、次のような文字列`1010`すべての操作で文字列のほぼ全体が反転され、パリティの競合が発生するため、すべてをゼロにすることはできません。 もう 1 つの微妙な点は、文字列に 1 つだけがある場合です。`1`操作により他のすべての 0 が 1 に反転されるため、そのインデックスを選択すると、これは望ましくないことです。 単純なソリューションでは、インデックスのパリティを考慮せずにインデックスに対する操作を誤って試行する可能性があります。`1`文字列内の s。 

## アプローチ

 ブルート フォース アプローチでは、文字列がすべて 0 になるか、それ以上の移動が不可能になるまで、可能なすべてのインデックスに対する操作を再帰的または反復的にシミュレートします。 これは非常に小さな文字列に対しては機能しますが、シーケンスの数は`O(n!)`最悪の場合、大きすぎて、`n`200,000まで。 

最適なソリューションを見つけるための重要な洞察は、単一の操作の影響を観察することから得られます。 インデックスの選択`i`を除くすべてのビットを反転します`s[i]`。 総数を考えてみると、`1`文字列内の s で示されます`count1`、インデックスに対する 1 回の操作の後`i`、の数`1`s になります`n - count1 - (s[i] == '1') + (s[i] == '0')`、これを単純化すると、`n - count1 - 1 + 1`もし`s[i] == '1'`または`n - count1`もし`s[i] == '0'`。 これは、次の数の場合にのみ操作が機能することがわかります。`1`s は特定のパリティ条件に一致します。 実際には、計算によって解決策を決定できます。`1`s. すべてがすでにゼロの場合、操作は必要ありません。 それ以外の場合は、`count1`等しい`n`または奇数の場合、常に次のインデックスを選択できます。`0`または`1`s はそれぞれすべて 0 に達します。 それ以外の場合は、`count1`等しい`n/2`さらに、各操作では偶数のビットが反転され、パリティの不一致が維持されるため、それは不可能です。 

この洞察があれば、過半数ビット (どちらかの位置) に基づいてどのインデックスを選択するかを決定するだけで済みます。`1`または`0`s)、文字列に対する 1 回のパスでソリューションを構築できます。

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取り、その数を数えます。`1`s、私たちはこう呼んでいます`count1`。 させて`n`文字列の長さになります。 
2. もし`count1`は`0`、文字列はすでにすべてゼロです。 出力`0`オペレーションと空のインデックスのリスト。 
3. もし`count1`は`n`、すべての操作で 1 を除くすべてのビットが反転されるため、すべてを 0 に反転することは不可能です。 出力`-1`。 
4. もし`count1`が奇数の場合、ビットが存在するすべてのインデックスを選択できます。`1`。 これらのインデックスに対して演算を実行すると、他のビットが反転され、最終的にはすべて 0 が生成されます。 
5. もし`count1`は偶数ですが等しくありません`0`または`n`、ビットが存在するすべてのインデックスを選択します`0`。 これらのインデックスを反転すると、文字列がすべてゼロに変換されます。 
6. 選択したインデックスの数とインデックスのリストを出力します。 各インデックスが最大 1 回使用される限り、どのような順序のインデックスでも機能します。 

これが機能する理由: 各操作は、選択されたビットを除くすべてのビットを反転します。 のパリティに基づいてインデックスを選択することにより、`1`s、次のように始まる場合、各ビットが奇数回反転されることを保証します。`1`に変換すると、`0`、次のように始まる場合は偶数回`0`、変更しないままにします。 この不変条件により、すべての操作の後、文字列がすべてゼロになることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        count1 = s.count('1')
        
        if count1 == 0:
            print(0)
            continue
        if count1 == n:
            print(-1)
            continue
        
        if count1 % 2 == 1:
            indices = [i+1 for i, ch in enumerate(s) if ch == '1']
        else:
            indices = [i+1 for i, ch in enumerate(s) if ch == '0']
        
        print(len(indices))
        print(' '.join(map(str, indices)))

if __name__ == "__main__":
    solve()
```このコードは、テスト ケースの数を読み取ることから始まり、各文字列を個別に処理します。 数える`1`は組み込みで行われます`count`関数。 Edge cases for strings that are already all zeros or all ones are handled first. The main decision is based on the parity of`count1`、インデックスは 1 から始まるインデックス付きのリスト内包表記を使用して生成されます。 インデックスのリストを作成したら、印刷は簡単です。

 ## 特殊なケース

 シングルビット文字列の場合`1`、count1 は 1 であり、奇数です。 インデックス 1 を選択すると、他のすべて (なし) が反転され、インデックス 1 は変更されないままになります。`0`。 のために`0`、操作は必要ありません。 交互ビットの場合`1010`、count1 = 2 (偶数) なので、次のインデックスを選択します。`0`s → 位置 2 と 4。これらを反転すると、すべてが次のように変換されます。`0`s. このアルゴリズムは正確なパリティ要件を処理し、インデックスが複数回使用されないようにします。
