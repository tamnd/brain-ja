 ## 解決策
 ## 問題の理解

 それぞれに高さがあり、昇順でない順にソートされた一連のフェンス板が与えられます。 Anya は、単位ブロックのグリッドとして見たときにフェンスが対称かどうかを知りたいと考えています。 ここでの対称性とは、板を取得し、高さの各単位を水平の行として扱い、板を列として配置した場合、結果として得られる 2D 形状が板の元の垂直レイアウトと同一になることを意味します。 

具体的には、それぞれの高さの板`h`貢献する`h`その列の水平単位。 水平方向の配置として見ると、最上部の行には最も高い板が含まれ、次の行にはその次に高い板が含まれます。 この変換後、列の長さのシーケンスが元の板の高さのシーケンスと同一である場合、フェンスは対称であると見なされます。 

入力は、すべてのテスト ケースにわたる板の総数が 200,000 を超えないように制限されます。 これにより、テスト ケースごとに線形よりも悪いアルゴリズムが排除されます。 高さは大きくなる可能性がありますが、反復には影響せず、カウントにのみ影響するため、値に比例した演算を実行する必要はありません。 

エッジケースには、単一の板、同じ高さの複数の板、および高さの差が不規則なシーケンスが含まれます。 例えば、`[5,5,5,1,1]`上の行は元の垂直レイアウトと一致するため対称ですが、`[5,4,2]`水平行の圧縮方法が異なり、水平方向の「行の長さ」が元の行と一致しないため、そうではありません。 

## アプローチ

 強引なアプローチは、水平表現全体を 2D グリッドとして構築し、結果の行の長さが元のシーケンスと一致するかどうかを行ごとにチェックすることです。 これは論理的には機能しますが、O(n * max_height) 時間がかかり、高さが大きい (最大 10^9) 場合は不可能です。 実際のグリッドの構築は不必要であり、時間がかかりすぎます。 

最適なアプローチでは、完全なグリッドは必要ないことがわかります。 代わりに、行を作成しているかのように、板の高さのトップダウンの縮小をシミュレートするだけで済みます。 

1. 列を「剥がす」ときに、各高さの板の数を追跡します。 
2. 各ステップで、残りの高さが、少なくともその高さの板の数が次の高さ以上であるという条件を満たしているかどうかを確認します。 

重要な洞察は、水平方向の表現は、高さを取得し、それらを並べ替え (既に非昇順で並べ替えられています)、各ステップでそれを検証することと同等であるということです。`i`、高さの板の数 >=`i`少なくとも`i`。 これはまさに、フェンスが対称ヤング図になるための条件です。 いずれかのステップでこれが失敗した場合、フェンスは対称ではありません。

 | ブルートフォースグリッドシミュレーション | O(n * max(a_i)) | O(n * max(a_i)) | 遅すぎる |
 | カウンティングと貪欲なチェック | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして高さのリスト`a`。 
3. カウンタの初期化`extra`背の高い板から運ばれる累積的な「過剰ユニット」を追跡するため。 
4. 最初の板から最後の板まで繰り返します。 

1. プランク用`i`、計算する`expected`この板が水平ビューで寄与する列の数として、`extra`。 
2. もし`a[i] > expected`、増分`extra`余分なユニットを下の板に持ち越します。 
3. もし`a[i] < expected`、フェンスを対称にすることはできません。 「NO」とマークして中断します。 
5. ループが失敗せずに完了した場合は、「YES」とマークします。 
6. 各テスト ケースの結果を出力します。 

**機能する理由**: 各ステップで、`extra`余分な高さが蓄積され、それを下の板に広げる必要があります。 これにより、水平方向の圧縮が垂直方向のシーケンスと確実に一致します。 ルールに違反する場合は、フェンスの水平方向の列の長さが元の垂直方向の高さと一致できないことを示し、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_symmetric(a):
    n = len(a)
    extra = 0
    for i in range(n):
        # the maximal allowed height in horizontal layout
        if a[i] > i + extra + 1:
            extra += a[i] - (i + extra + 1)
        elif a[i] < i + extra + 1:
            return "NO"
    return "YES"

def main():
    t = int(input())
    results = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        results.append(is_symmetric(a))
    print("\n".join(results))

if __name__ == "__main__":
    main()
```**コードの説明**:

 -`extra`より高い板からの累積余剰ユニットを追跡します。 これにより、グリッドを明示的に構築する必要がなくなります。 
-`i + extra + 1`は、対称性のためにこの位置で許容される板の最大高さを表します。 
- プランクごとに 1 回反復することで、テスト ケースごとに O(n) 時間を確保します。 
- 使用する`sys.stdin.readline`多数のテスト ケースの高速入力を保証します。 

## 実用的な例

 サンプル入力`[5,4,3,2,1]`:

 | 私 | a[i] | 番外編 | i + エクストラ + 1 | アクション |
 | --- | --- | --- | --- | --- |
 | 0 | 5 | 0 | 1 | 余分な += 4 → 4 |
 | 1 | 4 | 4 | 6 | わかりました |
 | 2 | 3 | 4 | 7 | わかりました |
 | 3 | 2 | 4 | 8 | わかりました |
 | 4 | 1 | 4 | 9 | わかりました |

 結果：`YES`。 背の高い板によって余剰が得られるため、水平レイアウトを垂直レイアウトに合わせることができます。 

サンプル入力`[4,2,1]`:

 | 私 | a[i] | 番外編 | i + エクストラ + 1 | アクション |
 | --- | --- | --- | --- | --- |
 | 0 | 4 | 0 | 1 | 余分な += 3 → 3 |
 | 1 | 2 | 3 | 5 | わかりました |
 | 2 | 1 | 3 | 6 | わかりました |

 シミュレーションでは、行 2 で 6 > 1 が期待され、対称性を満たすことができないことがわかります →`NO`。

 ## 特殊なケース

 一枚の板の場合`[1]`、`extra`は 0 で、高さは予想される 1 と一致します →`YES`。 

フェンス用`[5,1,1]`、最初のプランクの後`extra = 4`、しかし次の板の高さ 1 は期待される 6 に到達できません →`NO`。 

このアルゴリズムは余剰高さを正しく伝播し、不一致を検出し、すべての難しいシナリオをカバーします。
