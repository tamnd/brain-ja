 ## 問題の理解

 長さのある数字の文字列として表される数値が与えられます。$n$。 数字はすべてゼロではないため、数字は 43153 や 654321 のようなきれいなシーケンスになります。唯一許可されるアクションは、数字の連続するセグメントを 1 つ選択し、そのセグメントを降順でない順序で並べ替え、他のすべてを変更しないことです。 この操作は最大 1 回のみ実行できます。目的は、結果の数値を偶数にすることです。つまり、最後の桁が偶数でなければなりません。 

出力は、単一のセグメント並べ替え操作では数値を偶数にすることができないという宣言、またはセグメント境界の有効な選択のいずれかです。$L, R$、その後にそのセグメントを並べ替えた結果の変換された数値が続きます。 

重要な制約は、$n \le 1000$これにより、慎重にシミュレーションを繰り返す必要がある場合、二次または線形に近い戦略を超えるものは除外されます。 ただし、操作は 1 つだけなので、実際には 1 つの間隔を選択し、その効果を評価しています。 

微妙な点は、この演算が任意の桁の並べ替えではないことです。 連続したブロックのみを並べ替えるため、選択したセグメントの外側の相対的な順序が維持されます。 これにより、構造が非常に制限されます。最後の桁のみがパリティを決定するため、数値の接尾辞が特に重要になります。 

特殊なケースの 1 つは、数値がすでに偶数である場合です。 この場合、セグメントの選択はオプションですが、それでもそれを均一に保つ有効な操作を生成する必要があります。 もう 1 つのエッジ ケースは、以前の制約を破ることなく、有効な並べ替え動作を維持する方法で偶数桁を最後の位置に移動できるセグメントがない場合です。 

単純な間違いは、最小の偶数桁で終わるセグメントを選択することで、常に最小の偶数桁を最後に持ってくるべきだと考えることです。 セグメントのソートにより内部構造が乱され、奇数の桁が最後に押し込まれる可能性があるため、これは失敗する可能性があります。 

別の失敗例は、最後の桁を独立して選択できると仮定した場合です。 並べ替えはセグメント全体に影響するため、最後の位置は元のエンドポイントだけでなく、選択した間隔内のすべての桁に依存します。 

## アプローチ

 ブルートフォースアプローチにより、考えられるすべてのセグメントが試行されます$[L, R]$、並べ替えを適用し、結果の数値が偶数桁で終わるかどうかを確認します。 各セグメントの評価コスト$O(n)$変更された文字列を構築するには、$O(n^2)$セグメントなので、全体の複雑さは次のようになります。$O(n^3)$。 と$n = 1000$、これでは非常に遅くなります。 

実際に何が成功を決定するのかを観察することで改善できます。 セグメントをソートした後、パリティに関して重要なのは 2 つのことだけです。それは、どの桁が整数の最後の位置になるか、そしてそれが偶数かどうかです。 最後の位置は次の場合にのみ影響を受けます。$R = n$最後の桁を変更できるのは末尾に接しているセグメントだけであるためです。 これにより、検索スペースが直ちに大幅に減少します。 

ここで問題は、次で終わるセグメントを選択することです。$n$、つまり選択します$L$、並べ替えた後、$s[L:n]$、最後の桁は偶数です。 並べ替えとは、セグメントの最後の桁がそのセグメント内の最大の桁になることを意味します。 したがって、最後の桁が最大桁になります。$s[L:n]$。 したがって、条件は次のようになります。$L$サフィックスの最大桁数が$[L, n]$は均等です。 

サフィックスの最大桁数が偶数である場合、それは不可能です。 それ以外の場合は、右に拡張することで最大値が均一に保たれる最も早い位置を選択し、それを選択します。$L$。 このような有効なセグメントはすべて機能します。

 ## アルゴリズムのチュートリアル

 1. 右側から考慮した場合に、すべての接尾語の開始点でこれまでに確認された最大桁を維持しながら、左から右にスキャンします。 私たちはあらゆる可能性を評価するための準備を効果的に進めています。$L$効率的に。 
2. インデックスごとに$L$、の最大桁を計算します。$s[L:n]$。 これは、右から 1 回スキャンしてサフィックスの最大値を保存することで実行できます。 この手順により、セグメント プロパティを繰り返し再計算することがなくなります。 
3. このサフィックスの最大値が偶数であるかどうかを確認します。 そうであれば、選択します$[L, n]$ソートでは最大の要素が最後の位置にプッシュされるため、ソート後にその最大値が最後に配置されます。 
4. 最初のそのようなものを見つけたら$L$、やめます。 最も古い有効なものを選択する$L$有効な接尾辞は正しい最終桁をすでに保証しており、さらに左に拡張しても最大値がすでに固定されている場合は変更されない小さな桁のみが導入されるため、安全です。 
5. 出力$L = L$、$R = n$、部分文字列をソートして結果の文字列を構築します。$s[L:n]$プレフィックスとサフィックスを連結します。 
6. そうでない場合$L$存在する場合は、最後の位置で終了する演算は最後の桁を偶数にすることができないため、NO を出力します。 

### なぜ効果があるのか

 セグメントを並べ替えた後は、そのセグメントの最後の桁が常にそのセグメント内の最大桁になります。 位置で終わるセグメントのみなので$n$数値全体の最後の桁に影響を与える可能性がある場合、問題は最大桁が偶数である接尾辞を選択することに帰着します。 すべての有効なソリューションは、そのようなサフィックスの選択に正確に対応するため、アルゴリズムは有効な構成を見逃さず、無効な構成を生成しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = list(input().strip())

    suf_max = [0] * (n + 1)

    for i in range(n - 1, -1, -1):
        suf_max[i] = max(suf_max[i + 1], int(s[i]))

    best_l = -1
    for i in range(n):
        if suf_max[i] % 2 == 0:
            best_l = i
            break

    if best_l == -1:
        print("NO")
        return

    seg = sorted(s[best_l:])
    res = s[:best_l] + seg

    print("YES")
    print(best_l + 1, n)
    print("".join(res))

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にサフィックスの最大値を構築して、すべてのサフィックスを定数時間でその最大桁を評価できるようにします。 次のループでは、最大桁が偶数である最も古いサフィックスを検索します。これにより、ソートによって数値全体の末尾に偶数桁が配置されることが保証されます。 最後の構築ステップでは、そのサフィックスに対してソート操作を 1 回だけ実行し、それを未変更のプレフィックスと連結して戻します。 

実装でよくある落とし穴は、次で終わるセグメントのみであることを忘れることです。$n$案件。 もう 1 つは、ループ内のすべてのサフィックスの最大値を再計算することです。これにより、パフォーマンスが不必要に低下します。

 ## 特殊なケース

 エッジ ケースの 1 つは、数値に偶数桁が含まれているが、どの桁も接尾辞の最大値にならない場合です。 たとえば、13579 のようなシーケンスでは、偶数の数字がまったく存在しないため、すべてのサフィックスの最大値は奇数になります。 アルゴリズムはサフィックス最大値をスキャンし、有効な開始インデックスを正しく検出せず、NO を生成します。 

もう 1 つのケースは、唯一の偶数桁が接尾辞の最大値の一部ではない場合です。 たとえば、2193 には偶数の数字 2 がありますが、これを含む接尾辞には後でさらに大きな奇数の数字も含まれるため、接尾辞の最大値は常に奇数になります。 4 で終わるサフィックスを並べ替えても奇数の数字で終わるため、有効な操作が存在しないため、アルゴリズムはこれを正しく拒否します。
