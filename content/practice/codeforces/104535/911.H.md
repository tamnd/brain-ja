 ## 問題の理解

 各参加者が複数の選択肢にチェックを入れることができるアンケートから集計された調査統計が提供されます。 がある$n$リストされたプログラミング言語オプションに加えて、「other」と呼ばれる追加の暗黙のオプションも含まれています。 リストされた各オプションについて$i$、何人の回答者がそれを選択したかは示されますが、合計何人の回答者がいたかは示されません。 

各回答者は、選択したすべての選択肢の数に貢献します。 つまり、1 人で複数の値を増分できるということです。$a_i$、「その他」のみを選択した人は、指定された項目のいずれにも貢献しません。$a_i$。 すべての回答者は少なくとも 1 つの選択肢を選択する必要があるため、「その他」だけを選択したとしてもデータに完全に含まれていない人はいません。 

タスクは、指定された選択肢ごとの数を生成する可能性がある最小および最大の回答者数を再構築することです。 

重要な問題は、合計数が同じであっても、回答者間のさまざまな重複によって説明できることです。 極端な解釈の 1 つは、重度の重複を想定しており、多くの選択が同じ人から行われ、回答者の合計数が少なくなります。 反対の極端な場合は、重複が最小限であると仮定し、選択が個別の人々に分散され、合計数が大きくなります。 

制約$n \le 5000$そして$a_i \le 10^9$個人に対するあらゆるシミュレーションを即座に除外します。 どのアプローチも、カウントに関する集約された算術推論でのみ機能する必要があります。 

よくある間違いは、次の合計を扱うときに発生します。$a_i$回答者の数としては。 1 人の回答者が複数回貢献する可能性があるため、これは非常に重要です。 もう 1 つの間違いは、各回答者が少なくとも 1 単位をいくつかの項目に貢献していることを認識せずに、最大数に制限がないと想定していることです。$a_i$, したがって、合計はカウントの合計を超えることはできません。 

微妙なエッジケースとして、$a_i$はゼロです。 これらのオプションは何も貢献しませんが、それでも選択範囲の配布の実現可能性に影響を与えます。 たとえば、すべてが$a_i = 0$、回答できるのは「その他」のみを選択した人だけなので、答えは次のようになります。$1, 1$、 ない$0, 0$。

重要な観察は、重要な唯一の構造は、1 人の回答者が貢献できる選択の数であるということです。 各回答者は少なくとも 1 つの選択を提供し (何かを選択する必要があるため)、最大でも 1 つの選択を提供します。$n$選択内容 (リストされたすべてのオプションを選択した場合)。 したがって、各人は 1 から 1 までのサイズの「束」に相当します。$n$、バンドルの総数はすべてを説明する必要があります。$a_i$。 

これにより、問題は、複数のバンドルをカバーできるバンドルの数の限界に変わります。$S$選択トークン。各バンドルは各タイプの最大 1 つの出現をグループ化できます。 この構造は、単純なカウント引数に折りたたまれます。

 ## アルゴリズムのチュートリアル

 1. カウントの配列を読み取る$a_1, a_2, \dots, a_n$。 合計は選択イベントの合計を表し、最大値はオプションごとの最も厳しいボトルネックを表します。 
2. コンピューティング$S = \sum a_i$。 これは、全回答者全体で記録された選択の合計数です。 これは、すべての選択が異なる人から行われた場合に、何人の回答者を得ることができるかについての上限です。 
3. コンピューティング$M = \max a_i$。 これは、最も頻繁に選択されるオプションを表します。 回答をどのように分散するかに関係なく、各回答者は特定の選択肢に対して最大 1 つのカウントしか貢献できません。$M$回答者はそのオプションだけを説明する必要があります。 
4. 出力$M$最低回答者数として。 
5. 出力$S$回答者の最大数として。 

### なぜ効果があるのか

 各回答者は、特定のオプション数に最大 1 単位を寄与できるため、最も頻度の高いオプションには、少なくともその数の異なる人々が含まれることになります。 これにより下限が確立されます。 一方で、各選択イベントを、正確に 1 つの選択肢 (または必要に応じて「その他」のみ) を選択する別の回答者に割り当てることで、常に上限を実現できます。これにより、貢献が統合されずに回答者の総数が減ります。 この構造は、両方の境界が独立して達成可能であるため、厳密であることを示しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    mx = max(a)
    
    print(mx, total)

if __name__ == "__main__":
    solve()

最小値は次を使用して計算されます。`max(a)`それは、単一のオプションによって課される最も強い制約を捉えているからです。 最大値は次を使用して計算されます。`sum(a)`なぜなら、選択肢ごとのカウントに違反することなく、すべての選択肢を異なる回答者に割り当てることができるからです。

 ## 特殊なケース

 すべての値がゼロの場合、配列はリストされたオプションを誰も選択していないことを示します。 素朴な解釈では次のように出力される可能性があります。$0$ただし、すべての回答者は少なくとも 1 つの選択肢を選択する必要があります。つまり、「その他」のみを選択する必要があります。 一貫した最小限の解釈は、少なくとも 1 人の回答者が存在するため、正しい動作はモデルの仮定に依存するということです。 ここで使用される標準的な解釈では、両方の境界は空の調査が許可されている場合にのみ 0 に折りたたまれ、それ以外の場合は 1 に折りたたまれます。 

たとえば、1 つの値が優勢な場合、$a = [10^9, 0, 0]$、アルゴリズムは最小値を生成します$10^9$。 これは、どの回答者もその選択肢の出現ごとに複数のカウントを提供できないため、各回答者が主要な選択肢のみに割り当てられることに対応します。 

値が均等に分布している場合、次のようになります。$[1,1,1,1]$の場合、1 人の回答者がすべての選択肢を同時に選択できるため、最小値は 1 になりますが、最大値は 4 となり、選択肢が完全に分離されていることに対応します。
