 ## 解決策
 ## 問題の理解

 ちょうど 3 つの短い文字列が与えられており、それらは 1 つの隠し単語の一部です。 これらの部分は正しい順序ではありませんが、適切に並べ替えて連結すると、既知のターゲット単語「イジェフスク」が形成されます。 私たちの仕事は、文字列自体を再構築したり変更したりすることではなく、指定された 3 つのフラグメントの正しい順序を決定して、その連結がターゲットになるようにすることだけです。 

文字列が 3 つしかなく、それぞれの長さが最大 ​​5 であるため、入力サイズは非常に小さくなります。 これにより、効率の制約に関する懸念が即座に排除されます。 考えられるすべての置換を試行したり、連結を複数回再計算したりするソリューションでも、配置の合計数が 6 に固定されているため、十分に高速になります。 

微妙な問題は、入力文字列が任意の断片であることです。 ローカルでは無関係に見える可能性があり、ターゲットの単語の開始または終了を保証する単一の文字列はありません。 唯一信頼できる構造は、3 つの文字列の 1 つの順列だけで完全な単語が生成されるということです。 

単純な間違いは、辞書順に並べ替えたり、接頭辞を貪欲に照合したりすればうまくいくと考えることです。 たとえば、入力が「he Iz vsk」の場合、貪欲なアプローチでは、最初に「I」で始まる文字列を選択し、次に部分一致に基づいて他の文字列を追加しようとする可能性がありますが、複数の有効な継続が局所的に正しいように見える場合、これは失敗する可能性があります。 データが非常に小さいため、すべての順序を強引に実行するのが安全で決定的なアプローチです。 

## アプローチ

 この問題を考える最も簡単な方法は、3 つの要素の連結が既知のターゲット文字列と等しくなるような 3 つの要素の順列を検索することです。 文字列が 3 つある場合、可能な順序は 6 つだけです。 注文ごとに文字列を連結し、その結果をターゲットの単語と比較します。 

これが機能するのは、正確性がローカルな配置ではなく、グローバルな構造にのみ依存するためです。 間違った順序付けはすべて等価性チェックに失敗し、正しい順序付けは完全に一致します。 

ブルート フォース ソリューションでは、すべての順列を列挙し、それぞれに対して連結された文字列を構築し、等価性をチェックします。 順列の数は 6 に固定されており、各連結には合計で最大 15 文字が含まれるため、コストは一定です。 

入力サイズは固定されており小さいため、プルーニングやハッシュによるバックトラックなどの高度なテクニックは必要ありません。 この問題は本質的に、定数領域での順列マッチング タスクです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(6・L) | お(1) | 承認済み |
 | 最適 | O(6・L) | お(1) | 承認済み |

 ここで、L はすべての文字列を結合した合計の長さであり、15 で区切られます。 

## アルゴリズムのチュートリアル

 1. 3 つの入力文字列を読み取り、リストに保存します。 これにより、元の順序を失うことなく、簡単に並べ替えることができます。 
2. ターゲット文字列を「Izhevsk」として定義します。 すべての候補の順序付けが、この正確な文字列と比較されます。 
3. 3 つの文字列の考えられるすべての順列を生成します。 3 階乗は 6 に等しいため、このような順列は正確に 6 つあります。 
4. 順列ごとに、3 つの文字列をその順序で連結します。 これにより、意図したポスターの再構成候補が生成されます。 
5. 連結結果とターゲット文字列を比較します。 それらが正確に一致する場合、この順序は正しいです。 
6. 見つかった順序で 3 つの文字列を出力し、すぐに終了します。 

### なぜ効果があるのか

 正確さは、正確に 1 つの順列がターゲット文字列を形成するという事実に基づいています。 すべての順列を徹底的にテストし、各チェックで文字列が正確に等しいかどうかを確認するため、正しい順序を見逃すことはありません。 この問題は有効な取り決めが存在することを保証するため、あいまいさはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from itertools import permutations

def solve():
    a, b, c = input().split()
    arr = [a, b, c]
    target = "Izhevsk"
    
    for p in permutations(arr):
        if "".join(p) == target:
            print(*p)
            return

solve()
```このソリューションは 3 つのフラグメントを読み取り、それらをリストに保存するため、順列の生成が簡単になります。 順列関数は、6 つの可能な順序をすべて生成します。 順序ごとに文字列を連結し、「Izhevsk」と直接比較します。 一致するものが見つかるとすぐに、その順序を出力して停止します。 

実装の微妙な詳細は、印刷後の即時リターンの使用です。 これがないと、プログラムが続行され、今後ロジックが誤って追加された場合に複数行が出力される可能性があります。 ここでは、コストが無視できる場合でも、有効な順列を見つけた後にサイクルを無駄にしないことも保証されます。

## テストケース```python
import sys, io
from itertools import permutations

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    a, b, c = input().split()
    arr = [a, b, c]
    target = "Izhevsk"
    for p in permutations(arr):
        if "".join(p) == target:
            print(*p)
            return

## 特殊なケース

 エッジ ケースの 1 つは、入力がすでに正しい順序になっている場合です。 たとえば、次のように入力します。```
I zh evsk
```アルゴリズムは最初の順列をチェックし、すぐに「Izhevsk」と一致するため、入力を変更せずに出力します。 これにより、不必要な再配置ロジックが正解を妨げていないことが確認されます。 

もう 1 つのケースは、最後にチェックされた順列が正しい順序である場合です。 例えば：```
he Iz vsk
```最初の 2 つの置換は、それらの連結がターゲットと一致しないため失敗します。 順列の場合のみ`(Iz, he, vsk)`に達すると、条件は成功します。 アルゴリズムはすべての可能性を徹底的に探索するため、依然として正しく終了します。 

最後に、単語の他の部分に似たプレフィックスやサフィックスがあるなど、フラグメントが内部的に誤解を招く場合でも、等価性チェックにより部分一致エラーが防止されます。 このアルゴリズムはヒューリスティックに依存しないため、すべての有効な入力に対して正しいままになります。
