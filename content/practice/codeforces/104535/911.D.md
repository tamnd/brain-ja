 ## 解決策
 ## 問題の理解

 学生のグループに対して複数の座席計画を作成するように求められます。各計画では、学生が机に完全に割り当てられます。 各計画は基本的に 1 から n までの数字の並べ替えです。すべての机は 1 回だけ使用する必要があり、すべての生徒は 1 つの机を正確に使用する必要があるためです。 

m 個の異なる検査にわたって、m 個の異なる順列を生成する必要があります。 連続する 2 回の試験で学生が同じ机に座ることはできないという追加の制限があります。これは、すべての i について、位置 i の値が連続する順列間で異なっていなければならないという条件になります。 

したがって、タスクは、それぞれが {1, ..., n} の全単射であり、連続する順列がすべての位置で異なり、すべての順列がペアごとに異なるように、長さ n の m 個の順列を構築することです。 

制約 n、m ≤ 1000 は、O(nm) の構築は実行可能ですが、順列の階乗または指数列挙を伴うものはすべて不可能であることを意味します。 主な困難は、順列を生成することではなく、「連続する日の間に固定位置がない」制約の下で十分な数の順列が確実に存在するようにすることです。 

m が n に比べて大きい場合、微妙な失敗のケースが発生します。 n が小さい場合、少なくとも 1 つの位置で以前の配置との一致を回避できる十分な置換がありません。 たとえば、n = 4 および m = 30 の場合、ブルート フォースによる置換や単純なシフトの循環は、必然的に反復または隣接制約に違反します。 

単純なアプローチでは、以前のすべての順列をチェックしながら、貪欲に順列を生成しようとする可能性があります。 これは、遅すぎることと、有効な構造が存在する場合でも、グローバル構造の欠如により早期にスタックする可能性があるため、失敗します。 

## アプローチ

 強引なアイデアは、順列を 1 つずつ生成し、新しい順列ごとに、すべての位置で前の順列とは異なり、以前の順列と同一ではないものが見つかるまで、すべての可能性を試行することです。 各候補は、O(n) 内のすべての以前の順列と照合する必要があり、n! 個の順列が存在する可能性があります。 候補者たち。 体系的な生成に限定したとしても、探索空間は大きすぎ、最悪の場合の動作は要因的に増加します。 

重要な観察は、実際には恣意的な並べ替えが必要ないということです。 必要なのは、連続する順列がどこでも異なる、構造化された順列のセットだけです。 この性質を持つ自然な構造は基本順列の巡回シフトですが、巡回シフトでも n 個の順列しか与えられず、連続する順列間の任意の遷移は許可されません。 

より強力な構造は、順列とその逆を交互に切り替えてから、制御されたスワップを適用して追加の順列を生成することです。 中心的なアイデアは、すべての位置の変更を保証する固定変換によって、新しい順列が前の順列から確実に導出されるようにすることです。 

順列の観点から考えると、固定の順列変換を繰り返し適用してシーケンスを生成するセットが必要になります。 このような変換の最も単純なものは順列空間での回転ですが、あるステップから次のステップに移動するときに、要素がその位置に固定されたままになっていないことを確認する必要があります。 これは、混乱のような遷移を使用することになり、すべての i の次の順列で位置 i が異なる値にマッピングされることが保証されます。 

n ≥ 2 の場合、基本順列を構築し、値の巡回シフトを繰り返し適用できます。 これにより、各要素が次のステップで異なる位置に移動することが保証されます。 ただし、n ステップを超えて続行すると、元の順列に戻ります。つまり、サイクル内で得られる異なる有効な状態は最大でも n 個だけです。

したがって、実現可能性は m ≤ n かどうかに依存します。 m > n の場合、単一の一貫した変換の下では、n 要素上のフルサイクル構造のサイズは最大でも n であるため、繰り返しや制約違反を避けることはできません。 

m ≤ n の場合、単一の配列の循環シフトを使用して、必要なすべての置換を構築できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m・n・n!) | O(n) | 遅すぎる |
 | サイクリックシフト構築 | O(m・n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.恒等順列 [1、2、3、...、n] から始めます。 これは最初の試験の取り決めを表しており、各学生が固有の机に座るという要件を満たしています。 
2. 次の検査ごとに、前の順列を 1 位置回転して次の順列を構築します。 これは、最後の要素が前面に移動し、他のすべての要素が右に移動することを意味します。 これにより、どのポジションも以前の値を保持しないため、すべての生徒が前回の試験に応じて机を変更することが保証されます。 
3. m 個の順列が生成されるか、m が n を超えることが検出されるまで、このプロセスを繰り返します。 周期的な性質により、n 回シフトした後は元の配置に戻ります。 
4. m が n より大きい場合、サイクルは制約に違反せずに n を超える個別の有効な置換を生成できないため、IMPOSSIBLE を出力します。 
5. それ以外の場合は、生成されたすべての順列を出力します。 

回転で十分な理由は、次の順列ですべての要素の位置が変わるため、「連続した試験で同じ机は存在しない」という制約が自動的に満たされるためです。 

### なぜ効果があるのか

 各置換は、固定巡回シフトによって前の置換から取得されます。 巡回シフトは、連続するアプリケーション間に固定点のない全単射であり、すべてのインデックス i について、順列 t の位置 i の値が順列 t+1 の異なるインデックスに移動することを意味します。 これにより、隣接性の制約が保証されます。 変換の次数は n であるため、サイクルが終了するまで、つまり n ステップの後に正確に発生するまで、生成されたすべての順列は区別されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

if m > n:
    print("IMPOSSIBLE")
    sys.exit()

perm = list(range(1, n + 1))

print("POSSIBLE")
for _ in range(m):
    print(*perm)
    perm = [perm[-1]] + perm[:-1]
```コードはまず、限界 m ≤ n を使用して実現可能性をチェックします。 違反した場合は、直ちに IMPOSSIBLE が出力されます。 それ以外の場合は、恒等順列から開始して右回転を繰り返し適用します。 

回転ステップは重要な操作です。最後の要素を前面に移動すると、すべての位置がその占有者を変更する決定的な変換が保証されます。 これにより、バックトラッキングや衝突チェックの必要がなくなります。 

ループは正確に m 回実行され、必要な各試験構成が生成されます。 

## 実用的な例

 ### 例 1

 入力:

 n = 6、m = 3

 恒等置換から始めます。 

| ステップ | 順列 |
 | --- | --- |
 | 1 | 1 2 3 4 5 6 |
 | 2 | 6 1 2 3 4 5 |
 | 3 | 5 6 1 2 3 4 |

 これは、各ステップが完全な循環シフトであり、連続した試験で同じ机を使い続ける生徒がいないことを示しています。 

このステートメントで提供されるサンプル出力では、別の有効な構造が使用されていますが、固定位置を回避する変換によって導出される順列という同じ考え方に従っています。 

### 例 2

 入力:

 n = 4、m = 30

 ここでは m > n であるため、すぐに IMPOSSIBLE を出力します。 

これは、n 個の要素上の循環システムが、固定位置なしの遷移ルール​​を維持しながら、最大 n 個の異なる状態を生成できるという制約と一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m・n) | m 個の順列のそれぞれが出力され、O(n) 時間で回転されます。 
| スペース | O(n) | 現在の順列のみが保存されます。 

n、m ≤ 1000 という制約により、これが効率的になります。 合計操作は最大 10^6 であり、十分に制限内です。

 ## 特殊なケース

 n = 1 および m = 1 の場合、アルゴリズムは単一の順列 [1] を出力します。これは、ルールに違反する連続したペアがないため、すべての制約を自明に満たします。 

n = 2 および m = 2 の場合、回転は [1, 2] と [2, 1] の間で交互に行われ、各遷移で両方の位置が変更され、制約が正確に満たされます。 

n = 4、m = 30 など、m が n を超える場合、アルゴリズムは直ちに拒否します。 継続しようとすると、サイズ n の有限な循環構造により以前の順列の繰り返しが強制され、すべての毎日の配置が異なっていなければならないという要件に違反します。 

n = 3 および m = 1 の場合、アルゴリズムは単純に恒等順列を出力します。これは、連続した比較が存在しないため有効です。
