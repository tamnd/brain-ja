 ## 解決策
 ## 問題の理解

 私たちは持っています`n`円形に配置されたセイウチ。 プレゼンターは次から始めます`m`チップを取り出して順番に分配します。 セイウチ`1`受け取ります`1`チップ、セイウチ`2`受け取ります`2`セイウチまでのチップなど`n`、その後、セイウチからサイクルが再び繰り返されます`1`。 

このプロセスは、プレゼンターが現在のセイウチを完全に満足させるのに十分なチップを持っている限り継続されます。 プレゼンターが必要な金額を渡すことができなくなった瞬間、プロセスは停止し、残りのチップはプレゼンターの手元に残ります。 タスクは、最後に残っているチップの数を計算することです。 

制約は非常に小さいです。 セイウチの数は最大で`50`、チップの数は最大で`10^4`。 数値を 1 つずつ減算を繰り返す直接シミュレーションでも、制限時間内に簡単に収まります。 最悪の場合、各操作で少なくとも 1 つのチップが削除されるため、ループは最大でも実行されます。`10^4`これは 2 秒の制限としては些細なことです。 

間違いの主な原因は、停止条件を正しく処理することです。 部分的にチップを与えた後ではなく、プレゼンターが現在のセイウチを完全に満足させることができない場合、プロセスは終了します。 

次の入力を考えてみましょう。```
3 1
```最初のセイウチがまさに必要とするのは、`1`チップなので、プレゼンターはそれを渡して終了します。`0`。 

不注意な実装は、間違った不等式をチェックするため、チップを与える前に停止する可能性があります。 

もう 1 つの微妙なケースは、サイクルが循環する場合です。```
4 11
```プレゼンターがあげる`1 + 2 + 3 + 4 = 10`最初の完全なサイクル中にチップを残し、`1`。 そしてまたサイクルが始まるよ、セイウチ`1`最後のチップを受け取り、プレゼンターは次のように終了します。`0`。 実装が正しくないと、最初の完全なサイクルの直後に停止し、誤った出力が行われる可能性があります。`1`。 

残りのチップが次に必要な量よりも少ない場合、もう 1 つのエッジ ケースが発生します。```
3 7
```分布は次のようになります。`1 -> 2 -> 3 -> 1`プレゼンターは現在、`0`決勝戦を行った後に残ったチップ`1`。 代わりに次のようにした場合:```
3 6
```プレゼンターがあげる`1 -> 2 -> 3`そしてで止まります`0`。 

もし私たちが持っていたとしたら:```
3 5
```プレゼンターがあげる`1 -> 2`、出発`2`。 次のセイウチに必要なのは`3`、したがって、答えは次のとおりです`2`。 最初に減算して後でチェックするバグのある実装では、負の値が生成されます。 

## アプローチ

 最も直接的な解決策は、説明どおりにプロセスを正確にシミュレートすることです。 現在のセイウチの数を追跡し、次から循環します。`1`に`n`、チップが十分に残っているかどうかを繰り返し確認します。 「はい」の場合、必要な量を差し引いて次のセイウチに移動します。 それ以外の場合は、停止して残りのチップを印刷します。 

このブルートフォースアプローチは、オペレーションが成功するたびに少なくともチップ数が減少するため、すでに十分に高速です。`1`。 以来`m ≤ 10^4`、ループは最大で実行されます`10^4`回。 

このプロセスの背後には数学的な観察もあります。 1 つの完全なラウンドで次のものが配布されます。$1+2+\cdots+n=\frac{n(n+1)}{2}$チップス。 

残りの部分ラウンドをシミュレートする前に、ラウンド全体を繰り返し削除することができます。 これにより、反復回数がさらに削減されます。 それでも、与えられた制約を考慮すると、単純なシミュレーションの方がよりクリーンで十分に十分です。 

状態遷移が小さく、制限されているため、ブルートフォース ソリューションが機能します。 制約が非常に小さいため、最適化は不要です。 重要な部分は、循環順序と停止条件を正しく実装することです。

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`m`。 
2. 現在のセイウチインデックスを以下に等しい値から開始します。`1`。 
3. プレゼンターが現在のセイウチに十分なチップをまだ持っている間に、必要なチップ数を次の値から差し引きます。`m`。 
4. 時計回りに次のセイウチに移動します。 

もし今のセイウチが`n`、折り返して元に戻ります`1`。 
5. その瞬間`m`becomes smaller than the required amount for the current walrus, stop the process.
 6. 残りの値を出力します。`m`。 

なぜ効果があるのか:

 すべてのステップで、アルゴリズムは配布プロセスのルールに正確に従います。 現在のセイウチを表す変数は、チップを受け取る必要がある次のセイウチと常に一致します。`m`まだ利用可能なチップの数を常に保存します。 ループは、現在のセイウチが完全に満足できる場合にのみ継続します。 それが不可能になったら、問題の記述に従ってプロセスを直ちに終了する必要があります。 成功したすべての反復はプレゼンターの 1 つの正当な動きを反映するため、最終的に残った値は正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

current = 1

while m >= current:
    m -= current
    current += 1

    if current > n:
        current = 1

print(m)
```変数`current`次にどのセイウチがチップを受け取るべきかを保存します。 から始まります`1`なぜならプロセスは常にセイウチから始まるからです`1`。 

ループ条件は重要な詳細です。```
while m >= current:
```プレゼンターは、現在のセイウチを完全に満足させるのに十分なチップが存在する場合にのみ続行できます。 使用する`>`の代わりに`>=`残りのチップが必要な量と正確に一致すると失敗します。 

チップを差し引いた後、次のセイウチに進みます。 指数を超えると`n`に戻ります`1`循環秩序を維持するために。 

十分なチップが利用可能であることを確認した後にのみ減算が行われるため、この実装では負の値が生成されることはありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())

    current = 1

    while m >= current:
        m -= current
        current += 1

        if current > n:
            current = 1

    print(m)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("4 11\n") == "0\n", "sample 1"

# minimum values
assert run("1 1\n") == "0\n", "minimum case"

# cannot satisfy second walrus
assert run("2 1\n") == "0\n", "exactly enough for first walrus"

# partial stop in middle of cycle
assert run("3 5\n") == "2\n", "stop before giving 3 chips"

# wrap around multiple times
assert run("2 7\n") == "1\n", "multiple complete cycles"

# maximum style stress case
assert run("50 10000\n") == "145\n", "large input"
```| テスト入力 | 期待される出力 | 検証内容 |
