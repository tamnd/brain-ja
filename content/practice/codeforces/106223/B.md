 ## 解決策
 ## 問題の理解

 舞台は長方形に分割された農場です。$N \times M$グリッド。 すべてのセルには整数で表される果物の種類が含まれており、ミツバチは標準的な 4 方向のグリッド ステップを使用してグリッド上を移動し、常に最短経路に沿って移動します。 

各クエリの重要な考え方は次のとおりです。2 種類の果物が与えられます。$u$そして$v$1 つのセルに果物が含まれるすべてのセルのペアを考慮したいとします。$u$もう一つにはフルーツが入っています$v$。 このようなペアごとに、ミツバチはそれらの間の最短のグリッド パスに沿って移動し、そのパスはいくつかのセルをカバーします。 すべての有効なペア間のすべての最短パスの中で、$u$-細胞と$v$-cells の場合、そのようなパスの可能な最大長を決定するように求められます。 

同様に、クエリごとに 2 セットのグリッド ポイントを操作し、最初のセットの任意の点と 2 番目のセットの任意の点の間の最大のマンハッタン距離が必要になります。 

入力サイズが十分に大きいため、クエリごとに位置のすべてのペアを単純にスキャンすると遅すぎます。 まである場合$10^5$セルと多くのクエリを使用すると、クエリごとの二次ペアリングはすでに困難になり、クエリ全体のすべての出現を合計したとしても、距離を繰り返し再計算することは避けなければならないことがわかります。 これは、各果物の種類の位置を前処理することをすぐに示します。 

一方または両方の果物の種類が 1 回だけ発生する場合、微妙なエッジ ケースが発生します。 たとえば、グリッドに次のタイプのセルが 1 つだけ含まれている場合、$u$そしてタイプの1つ$v$、答えは単にそれらの間のマンハッタンの距離です。 複数の発生を想定し、存在を確認せずに極端な実装を試みる不用意な実装は、クラッシュしたり、ガベージを生成したりします。 

もう 1 つの失敗例は、2 つの格子点間の最短経路が一意ではないことを忘れたために発生します。 たとえば、$(1,1)$そして$(2,2)$、最短パスが 2 つありますが、それらはすべて同じ長さです。$2$。 この問題では、パスの数を数えたり、パスを構築したりする必要はなく、パスの長さだけを要求するため、ここでの混乱は、多くの場合、時間の複雑さが爆発する不必要なシミュレーション試行につながります。 

最後に、よくある間違いは、答えがパスに沿った中間セルに依存すると考えることです。 そうではありません。 グリッド内のすべての最短パスは、ルートとは関係なく、マンハッタンの距離に等しい長さがあるため、エンドポイントのみが問題になります。 

## アプローチ

 直接的な総当たりアプローチでは、クエリごとに次のようになります。$(u,v)$、フルーツのすべての位置を集めます$u$そして果物のすべての位置$v$, then compute the Manhattan distance for every pair. もし$c_u$そして$c_v$は周波数、これにはコストがかかります$O(c_u \cdot c_v)$クエリごとに。 果物の種類が何度も出現する密なグリッドでは、クエリごとにすぐに二次関数になり、最悪の場合は次のように劣化します。$O((NM)^2)$、実現可能な限界をはるかに超えています。 

重要な観察は、マンハッタン距離が独立した x 成分と y 成分に分離されていることです。$$|x_1 - x_2| + |y_1 - y_2|$$固定セットの場合、すべてのペアにわたってこの式を最大化すると、ペアを列挙することなく削減できます。 すべての組み合わせをチェックする代わりに、極値の座標の組み合わせ、つまり最小値と最大値を追跡するだけで十分です。$x+y$、$x-y$、およびマンハッタン距離をエンコードする同様の線形変換。 

果物の種類ごとに、次の 4 つの値を前処理して保存できます。$x+y$、および最小値と最大値の$x-y$そのすべての出来事にわたって。 これらの要約は、そのセットがマンハッタン ジオメトリでどこまで拡張できるかを完全に把握しています。 

これらが事前に計算されると、各クエリは 2 つのフルーツ タイプの間で可能な限り最良の極端な値を組み合わせることによる定数時間の計算になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリごとにすべてのセルをペアにする) |$O(c_u \cdot c_v)$クエリごと |$O(1)$番外編 | 遅すぎる |
 | フルーツごとの極値を事前計算する |$O(NM + Q)$|$O(K)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを 1 回横断し、果物の種類ごとに座標をグループ化します。 これにより、各果物の位置のリストが作成されます。 目標は、クエリ中にグリッドを繰り返しスキャンすることを避けることです。 
2. 果物の種類ごとに、その位置に関する 4 つの集計値 (最小値と最大値) を計算します。$x+y$、および最小値と最大値の$x-y$。 これらの値は、マンハッタン距離クエリに十分な方法で果物の種類の空間的広がりを要約します。 
3. クエリごとに$(u,v)$、両方の果物の種類の事前計算された値を取得します。 
4. 任意の 2 点について次の事実を使用して、2 つのセット間の最適なマンハッタン距離を計算します。$$|x_1-x_2|+|y_1-y_2| = \max((x_1+y_1)-(x_2+y_2), (x_2+y_2)-(x_1+y_1), (x_1-y_1)-(x_2-y_2), (x_2-y_2)-(x_1-y_1))$$これは、極値間の違いをチェックすることになります。$$\max(
\max(x+y)_u - \min(x+y)_v,
\max(x+y)_v - \min(x+y)_u,
\max(x-y)_u - \min(x-y)_v,
\max(x-y)_v - \min(x-y)_u
)$$5. これら 4 つの値の最大値をクエリの答えとして出力します。 

### なぜ効果があるのか

 マンハッタン距離は、次の 2 つの線形形式の最大値として見ることができます。$x+y$そして$x-y$サイン反転の下。 2 つのセットにわたるペアごとの最大値は常に、これらの線形投影の境界点で達成されます。 各投影の極値のみを保持するため、考えられるすべての最適なペアは、保存されている極値の組み合わせの 1 つによって表されます。 極端でない値は少なくとも 1 つの線形投影の境界値によって支配されるため、内部点によって結果を改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def add_point(stats, c, r):
    # stats: [min_xp, max_xp, min_xm, max_xm]
    xp = c + r
    xm = c - r
    if stats[0] is None:
        stats[0] = stats[1] = xp
        stats[2] = stats[3] = xm
    else:
        stats[0] = min(stats[0], xp)
        stats[1] = max(stats[1], xp)
        stats[2] = min(stats[2], xm)
        stats[3] = max(stats[3], xm)

def solve():
    n, m, q = map(int, input().split())
    grid = []
    for _ in range(n):
        grid.append(list(map(int, input().split())))

    # assuming fruit values up to K (compress if needed)
    # use dict for sparsity
    stats = {}

    for i in range(n):
        for j in range(m):
            v = grid[i][j]
            if v not in stats:
                stats[v] = [None, None, None, None]
            add_point(stats[v], i, j)

    out = []
    for _ in range(q):
        u, v = map(int, input().split())

        su = stats[u]
        sv = stats[v]

        ans = 0

        # x+y dimension
        ans = max(ans,
                  su[1] - sv[0],
                  sv[1] - su[0])

        # x-y dimension
        ans = max(ans,
                  su[3] - sv[2],
                  sv[3] - su[2])

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```グリッドは 1 回スキャンされ、果物の種類ごとに 4 つの数字のみが維持されます。 クエリ フェーズは純粋に算術演算であるため、セル リストに対する反復はありません。 

よくある実装上の間違いは、計算時に行と列のインデックスを交換することです。$x+y$そして$x-y$。 一貫性が保たれている限り、どちらか$(i,j)$または$(row,col)$マンハッタン距離は座標の再ラベル付けの下では不変であるため、機能します。 

もう 1 つの問題は、目に見えない果物の種類の統計を初期化するのを忘れることです。 クエリにはグリッド内に存在する任意のフルーツ ID を含めることができるため、クエリされたすべてのタイプが前処理マップに存在する必要があります。 

## 実用的な例

 小さなグリッドを考えてみましょう。 

入力:```
3 3 2
1 2 3
3 2 1
1 1 2
1 2
2 3
```果物の種類ごとに統計を計算します。 

タイプ 1 の場合:$$(x+y): \{2,4,4,3\}, (x-y): \{0,2,0,-1\}$$タイプ 2 の場合:$$(x+y): \{3,3,5\}, (x-y): \{1,-1,1\}$$タイプ 3 の場合:$$(x+y): \{4,4\}, (x-y): \{2,0\}$$クエリ 1: (1,2)

 | ステップ | 値 |
 | --- | --- |
 | 最大(x+y)₁ - 最小(x+y)₂ | 4 - 3 = 1 |
 | 最大(x+y)₂ - 最小(x+y)₁ | 5 - 2 = 3 |
 | 最大(x-y)₁ - 最小(x-y)₂ | 2 - (-1) = 3 |
 | 最大(x-y)₂ - 最小(x-y)₁ | 1 - (-1) = 2 |

 答え = 3

 クエリ 2: (2,3)

 | ステップ | 値 |
 | --- | --- |
 | 最大(x+y)₂ - 最小(x+y)₃ | 5 - 4 = 1 |
 | 最大(x+y)₃ - 最小(x+y)₂ | 4 - 3 = 1 |
 | 最大(x-y)₂ - 最小(x-y)₃ | 1 - 0 = 1 |
 | 最大(x-y)₃ - 最小(x-y)₂ | 2 - (-1) = 3 |

 答え = 3

 これらのトレースは、正しいペアが特定の中間点ではなく、常に極値の投影によって決定されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(NM + Q)$| グリッドを 1 回通過するだけで統計が構築され、各クエリは定数時間演算を使用します。 
| スペース |$O(K)$| 果物の種類ごとに 4 つの値のみが保存されます。 

前処理コストはグリッド サイズに比例して増加し、クエリ フェーズはグリッド密度に依存しません。 これは、グリッドの一般的な制約内に快適に適合します。$10^5$以上であり、クエリ数は同じ範囲内にあります。

 ## 特殊なケース

 果物の種類ごとに 1 つの出現が自然に処理されるのは、極値が同じ値に折りたたまれるため、4 つの計算式すべてが 2 つの一意の点間の同じマンハッタン距離に減少するためです。 

2 つの種類の果物が重複する領域を占めている場合でも、アルゴリズムは互いに素であることを想定していないため、機能します。 たとえ座標が一致したとしても、極値の差は正しくゼロを生成します。 

1 つの果物が長い対角線に現れ、別の果物が隅に集まっているなど、非常に偏った分布を持つグリッドは、まさに極値射影法が必要なケースです。これは、強引なペアリングでは遅すぎるものの、最大値は依然としてそれらの構造の端点から得られるためです。
