 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$N$、そしてその後の長いシーケンス$Q$操作。 各操作でセグメントが選択されます$[l, r]$そして、そのセグメント、つまり位置の要素に対して左回転を実行します。$l$位置に移動します$r$、シフト間のすべてのことを 1 つ左に行います。 

全部当てはめると$Q$操作を順番に実行すると、インデックスの最終的な並べ替えが得られます。 面白いのは、操作シーケンスが周期的に処理されることです。開始点を選択できるのです。$x$、からの操作を適用します$x$に$Q-1$、から続けます$0$に$x-1$。 操作リストのこのような回転ごとに、異なる最終的な置換が生成される可能性があります。 

回転されたシーケンスごとに、結果の順列をソート順に戻すために必要なスワップの数を計算します。 配列には次の順列が含まれているため、$1$に$N$、ソートするための最小スワップ数は次のとおりです。$N$順列分解のサイクル数を引いたもの。 タスクは、この値をすべて合計することです$Q$操作リストの循環シフト。 

制約は次のことを示しています$N \le 1000$、これにより、$O(N^2)$または$O(NQ)$単一構成ごとのスタイル処理。 しかし、$Q \le 10^5$したがって、シフトごとに完全な順列を再計算するものはすぐに遅すぎます。 各回転の単純なシミュレーションでは、次のことが必要になります。$O(Q \cdot N \cdot Q)$あるいはせいぜい$O(Q^2 N)$、それは限界をはるかに超えています。 

単純な推論を簡単に打ち破る微妙な問題は、各巡回シフトが根本的に異なる置換構造を生成すると仮定することです。 たとえば、操作シーケンスがどこから開始されるかに応じて、異なるサイクル数が予想される場合があります。 ここでの直感は間違っています。順列の積の循環シフトはすべて共役によって関連付けられ、循環構造が維持されるからです。 

小さなエッジケースの直観チェックが役に立ちます。すべての演算が互いに素なセグメント上の自明な回転である場合、最終的な順列は依然として順列であり、演算順序をシフトしても基礎となるサイクル タイプは変更されず、中間ステップのラベル付けのみが変更されます。 

## アプローチ

 直接的なアプローチは、それぞれをシミュレートすることです。$Q$操作リストのローテーション。 開始インデックスごとに$x$、すべてを適用して順列を再構築します。$Q$ローテーションされた順序で演算を実行し、サイクルをカウントします。 順列の構築には必要な作業が必要です$O(NQ)$、そしてすべての人のためにそれを行う$Q$シフトは与える$O(NQ^2)$が遅すぎるときは、$Q = 10^5$。 

重要な観察は、一連の操作が対称群の積を形成するということです。 させて$A$すべての演算を指定された順序で適用することによって得られる順列とし、$P_x$最初のものだけを適用することによって形成される順列である$x$操作。 演算シーケンスの巡回シフトは、正確に適用することに対応します。$P_x^{-1}$、 それから$A$、 それから$P_x$。 言い換えれば、シフトされたすべての結果は次の共役です。$A$。 

順列グループの共役はサイクル構造を維持します。 つまり、回転されたすべてのシーケンスは、まったく同じサイクル分解を持つ順列を生成し、したがって同じサイクル数と同じ最小スワップ カウントを生成します。 

したがって、再計算する代わりに$Q$順列の場合、すべての演算を 1 回適用した結果を計算し、そのサイクルをカウントし、その答えを乗算するだけで済みます。$Q$。

 ## アルゴリズムのチュートリアル

 ### 1. すべての操作を 1 回適用して、最終的な順列を取得します。 

恒等順列から始めて、各回転操作を順番に適用します。 各操作でセグメントが回転します$[l, r]$これは、最初の要素を一時的に保存し、残りをシフトすることによって実装されます。 

これにより、単一の最終的な置換が生成されます。$A$、すべての操作の完全な構成を表します。 

### 2. 置換マッピングを明示的に構築する

 シミュレーション後、結果の配列を位置からのマッピングとして解釈します。$i$大切にする$A[i]$。 これは、これから分析するサイクル構造の順列です。 

### 3. 順列内のサイクルを数える

 すべてのインデックスを横断します。$1$に$N$そして、未訪問のインデックスごとに、先頭に戻るまで順列マッピングに従います。 それぞれの走査で 1 つのサイクルが形成されます。 

順列を並べ替えるのに必要なスワップの数は次のとおりです。$N - \text{cycles}(A)$。 

### 4. 回転数を掛ける

 演算シーケンスの循環シフトごとに、次の共役である順列が生成されるため、$A$、それらはすべて同じサイクル構造を持っています。 したがって、すべての$f(x)$は等しく、最終的な答えは次のようになります。$$Q \cdot (N - \text{cycles}(A))$$### なぜ効果があるのか

 各操作はインデックスの順列であり、プロセス全体は順列の結果です。 群積内の因子の循環シフトにより、結果が共役形式に変換されます。$P^{-1} A P$。 共役はサイクルの長さやサイクル数を変更せず、サイクル内の要素のラベルを変更するだけです。 最小スワップはサイクル構造のみに依存するため、操作シーケンスのすべての回転で同じスワップ数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def apply_ops(n, ops):
    arr = list(range(n))
    for l, r in ops:
        l -= 1
        r -= 1
        if l >= r:
            continue
        tmp = arr[l]
        for i in range(l, r):
            arr[i] = arr[i + 1]
        arr[r] = tmp
    return arr

def count_cycles(p):
    n = len(p)
    vis = [False] * n
    cycles = 0

    for i in range(n):
        if not vis[i]:
            cycles += 1
            cur = i
            while not vis[cur]:
                vis[cur] = True
                cur = p[cur] - 1
    return cycles

def solve():
    n, q = map(int, input().split())
    ops = [tuple(map(int, input().split())) for _ in range(q)]

    final_perm = apply_ops(n, ops)
    cycles = count_cycles(final_perm)

    ans = q * (n - cycles)
    print(ans)

if __name__ == "__main__":
    solve()
```シミュレーション ステップでは、各回転を適用することにより、合成された順列を直接構築します。 次に、サイクル カウンターは標準的な方法で順列を解釈し、開始インデックスに戻るまでリンクをたどります。 

の乗算$Q$共役引数により、すべての巡回シフトがサイクル構造を正確に保持することが保証されるため、シフトごとの再計算は必要ないため、安全です。

 ## 特殊なケース

 一般的なエッジケースは、操作が順序に大きく依存しているように見える場合であり、開始回転が異なると順列の複雑さが変化するはずであることを示唆しています。 たとえば、演算が重複する小さな順列では、シフト間でサイクル数が異なることが予想される場合があります。 共役プロパティは、この依存関係を完全に削除します。 

もう 1 つのエッジ ケースは、セグメントの回転によって配列が有意に変更されない場合です。$[l, r]$ここで、セグメントはすでに周期対称になっています。 これらの操作は依然として置換積に寄与しますが、シフト間のサイクル カウントの一貫性には影響しません。 

すべての場合において、最終的な置換構造のみが答えを決定し、すべての巡回シフトはその構造を正確に保持します。
