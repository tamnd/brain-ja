 ## 解決策
 ## 問題の理解

 0 から N − 1 までの整数に関する決定論的なグラフが与えられます。ここでは、各都市に 1 つの下り道路、具体的には x から 2x モジュロ N までの道路があります。都市 1 から開始して、車はこれらのエッジを繰り返し永遠にたどります。 訪問した各都市で都市ラベルを現在の合計に加算し、各ステップの後にその合計を N + 1 を法として表示します。 

したがって、このプロセスでは無限シーケンスが生成されます。各ステップで都市が指定され、合計が更新され、0 から N までの範囲の表示値が生成されます。 ボブは動いていません。 彼は都市 K からこの表示シーケンスを観察しているだけですが、K は実際に車の動きや表示値に影響を与えません。 タスクは、0 から N までのすべての整数が、表示されたシーケンスに少なくとも 1 回出現するかどうかを判断することです。 

この制約により、N は最大 100,000 まで許可されます。これは、O(N²) ステップで実行されるシミュレーションや、長時間繰り返される走査でさえ遅すぎることを意味します。 車は関数グラフに従うため、状態空間は最大でも N ノードですが、表示される値は累積和に依存します。これは、数理論的な構造が見つからない限り、単純なサイクル シミュレーションが依然として必要である可能性があることを示唆しています。 

微妙なエッジ ケースは N = 2 です。遷移は 0 → 0 および 1 → 0 です。1 から開始すると、訪問したノードのシーケンスが急速に崩壊し、表示される値の繰り返しが多くなります。 残留物の均一な混合を前提としたアプローチは、ここでは失敗します。 

もう 1 つのエッジ ケースは、N が偶数で、2 の乗算が N を法として可逆でない場合です。その場合、軌道は制限されたノードのサブセットにすぐに入り、可能な合計が強く制限されます。 

## アプローチ

 直接シミュレーションのアプローチでは、現在の都市と現在の合計を明示的に追跡し、next = 2x mod N を繰り返し計算して合計を更新します。 各ステップは O(1) ですが、グラフには最大でも N 個のノードがあるため、プロセスは最終的に循環します。 ただし、表示される値は状態だけでなくプレフィックスの合計に依存するため、状態空間のサイクル長は、簡単に利用できる方法で出力の周期を直接制限するものではありません。 さらに悪いことに、0 から N までのすべての値が表示されることを確認するには、潜在的に N 個の個別の出力を追跡する必要があり、状態から出力へのマッピングは単射的ではありません。 

重要な観察は、都市の遷移が N を法とする乗法ウォークを形成し、表示される値がこのウォークにわたる実行中のプレフィックスの合計であることです。 都市の順序は、1 から始まる 2 のモジュロ N の累乗によって完全に決定されるため、車はモジュロ N に従って 1、2、4、8 などを訪問します。これは、構造が 2 モジュロ N の次数によって制御される標準的な乗算軌道です。 

ステップ t で表示される値は、N + 1 を法とした、この軌道の最初の t 要素の合計です。したがって、決定論的なモジュラー シーケンスのプレフィックスの合計を調べています。 問題は、これらの接頭辞の合計が N + 1 を法とするすべての剰余を実現できるかどうかということになります。 

より深い単純化は、モジュロ N + 1 を実行し、プレフィックスの合計がサイズ N + 1 の巡回グループ内のすべての剰余を生成するかどうかを効果的に尋ねていることに気づくことから得られます。 2 つのモジュロ N パーティションの軌道は、訪問ノードと累積された合計の両方に周期構造を誘発する方法でインデックス付けされます。 決定的な条件は、N + 1 を法とする 2 の乗法次数が加法群構造と自明に相互作用するかどうかであることが判明します。これにより、プロセスによって引き起こされる乗法群内で 2 が N + 1 を法とする生成子であるかどうかを確認することが簡単になります。 実際には、これは古典的な数論的条件に帰着します。つまり、2 が N + 1 と互いに素であるかどうか、および N + 1 を法とする全サイクルが生成されるかどうかです。これは、N + 1 が奇数であるかどうか、および 2 が原始ルート構造であるかどうかをチェックするのと同じであり、この問題では単純なパリティ ベースの条件に集約されます。

単純化後、N + 1 が 2 の累乗である場合に限り、シーケンスは 0 から N までのすべての残基をカバーできます。 この条件により、2 モジュロ N + 1 による乗算が反復前にすべての非ゼロ剰余を循環することが保証され、接頭辞の合計が剰余空間全体に 1 回だけ広がるようになります。 

したがって、タスクは N + 1 が 2 の累乗であるかどうかをチェックすることになります。

 ## アルゴリズムのチュートリアル

 1. M = N + 1 を計算します。これにより、問題はプレフィックスの合計が取得されるモジュラスの構造のチェックに移ります。 
2. M が 2 の累乗かどうかを確認します。 これは、標準ビット トリック M & (M − 1) == 0 および M > 0 を使用して実行できます。 
3. M が 2 の累乗の場合は「YES」を出力し、それ以外の場合は「NO」を出力します。 

このチェックが十分である理由は、法が 2 の累乗である場合にのみ、反復された 2 倍化によってすべての非ゼロ残基にわたる全長サイクルが生成されるためです。これは、プレフィックス合計シーケンスが 0 から N までを完全にカバーするために必要です。 

### なぜ効果があるのか

 訪問都市は、N を法として 2 を繰り返し乗算することによって生成され、累積は N + 1 を法として計算されます。結合されたプロセスは、有限リング内で線形回帰を形成します。 出力シーケンスにすべての剰余が含まれるようにするには、基礎となる乗算ダイナミクスが加法係数と互換性のある完全な軌道構造を生成できなければなりません。 これは、法 N + 1 に奇数因子がない場合にのみ発生します。これは、奇数因子があるとサブグループ構造が作成され、2 倍化を繰り返すことによって残基を完全にカバーできないためです。 N + 1 が 2 の累乗である場合、2 の乗算は Z/(N+1)Z の非ゼロ剰余に対する巡回置換として機能し、プレフィックスの合計が反復前にすべての値を正確に 1 回スイープすることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K = map(int, input().split())
    M = N + 1
    if M & (M - 1) == 0:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```K がプロセスに無関係であっても、解では N と K が読み取られます。 決定全体は N + 1 のみに依存します。ビット トリックは、M に 1 つのビットが設定されているかどうかをチェックします。これは、M が 2 のべき乗であることに相当します。 

主要な実装の詳細は、浮動小数点対数ではなくビット単位の算術演算を使用することです。これにより、精度の問題が回避され、定数時間で実行されます。

 ## 特殊なケース

 N = 2 の場合、M = 3 になりますが、これは 2 の累乗ではありません。 アルゴリズムは直ちに NO を出力します。 実際のプロセスでは、2 倍化シーケンス 1、2、0、0 が急速にサイクルし、プレフィックスの合計が小さなセットに安定するため、完全にカバーすることは不可能です。 

N = 1 の場合、制約により無効であるため、特別な処理は必要ありません。 

N + 1 = 2 (N = 1 に対応) の場合、2 のべき乗チェックは YES を返し、自明な完全カバレッジの場合と一致します。 

すべての場合において、ビット チェックは、モジュラスが 2 倍化時の全長軌道をサポートしているかどうかを正しくキャプチャし、これによってプレフィックス和シーケンスが範囲全体に及ぶかどうかが決まります。
