 ## 解決策
 ## 問題の理解

 複数の独立したテスト ケースが与えられます。 各テスト ケースには、都市人口を表す個別の正の整数のリストがあります。 タスクは、インデックスの順序付けされたトリプルを数えることです$(i, j, k)$この場合、母集団の値は、最初の 2 つの値の最大公約数が最後の 2 つの値の最小公倍数に等しいという非常に特殊な算術条件を満たすようになります。 

つまり、次のように表すと、$x = a_i$、$y = a_j$、 そして$z = a_k$、私たちは必要とします$$\gcd(x, y) = \operatorname{lcm}(y, z).$$各テスト ケースの出力は、そのような順序付けされたトリプルの数です。 

この制約により、テスト ケースごとに線形または線形に近い解決策が求められます。 すべてのテストにわたる値の合計数は最大で次のとおりです。$2 \cdot 10^5$したがって、大まかに言うよりも悪いアプローチはすべて$O(N \sqrt{A})$または$O(N \log A)$前処理に応じてテスト ケースごとに許容される可能性が高くなりますが、3 次または 2 次の関数はすべて許容されます。$N$失敗します。 

単純な試みでは、すべてのトリプルを試し、gcd と lcm を直接計算します。 それはすでに示唆しています$O(N^3)$、それは直ちに不可能です。 中間インデックスの固定まで削減$j$すべてのペアをスキャンします$(i, k)$与える$O(N^2)$テストごとに、それでも中断します$N = 2 \cdot 10^5$。 

さらに微妙な失敗のケースは、条件の誤解から生じます。 たとえば、gcd と lcm は対称的に見える演算であるため、トリプルは対称であるか、順序を無視してペアに還元できると誤って仮定する可能性があります。 ただし、順序が重要です: スワップ$i$そして$k$両面を異なる方法で変更します。 

もう 1 つの罠は、gcd が lcm と等しいと仮定すると、3 つの数値がすべて等しいことを意味します。 それは真実ではありません。 たとえば、次の場合$x = 6, y = 2, z = 6$、 それから$\gcd(6,2)=2$そして$\operatorname{lcm}(2,6)=6$、したがって失敗しますが、関係が平等よりも微妙である構造化されたケースがあります。 

## アプローチ

 ブルート フォース方式では、すべてのトリプルを反復処理し、状態を直接チェックします。 これは定義に正確に従っているため概念的には機能しますが、コストがかかります$N^3$テストケースごとの操作。 と$N$まで$2 \cdot 10^5$、単一のテストケースさえ不可能です。 

構造を明らかにする方法で条件を書き直す必要があります。 

等式から始めます:$$\gcd(x, y) = \operatorname{lcm}(y, z).$$この共通の値を$d$。 それから：$$d \mid x,\quad d \mid y,\quad d \mid z.$$しかし、より重要なのは、アイデンティティを使用することです。$$\operatorname{lcm}(y, z) = \frac{yz}{\gcd(y, z)}.$$したがって、条件は次のようになります。$$\gcd(x, y) = \frac{yz}{\gcd(y, z)}.$$させて$g_1 = \gcd(x, y)$そして$g_2 = \gcd(y, z)$。 それから：$$g_1 g_2 = yz.$$以来$g_1 \mid y$そして$g_2 \mid y$、書き換えることができます$y = g_1 \cdot a = g_2 \cdot b$。 これにより、強力な可分性の調整が強制されます。 重要な構造的帰結は、$y$は同時に両方の gcd 値の倍数でなければならず、これにより自由度が大幅に崩壊します。 

より便利な変換は、中央の要素を固定することです。$y$。 一度$y$固定されているので、いくつ数えますか$x$そして$z$満足する：$$\gcd(x, y) = \operatorname{lcm}(y, z).$$これが成立するには、両側が何らかの値に等しくなければなりません$d$。 以来$d = \operatorname{lcm}(y, z)$、すぐに得られます$y \mid d$、つまり$d \ge y$。 だけでなく$d = \gcd(x, y) \le y$。 したがって、唯一の可能性は次のとおりです。$$d = y.$$これにより、条件が完全に崩壊します。$$\gcd(x, y) = y \quad \text{and} \quad \operatorname{lcm}(y, z) = y.$$これら 2 つのステートメントは次のことを意味します。$$y \mid x \quad \text{and} \quad z \mid y.$$したがって、問題は値ごとに数えるということになります。$y$、値はいくつありますか$x$の倍数です$y$、値の数$z$の約数です$y$、次にそれらのカウントを乗算します。 

すべての値は個別であるため、周波数配列を事前計算してから、値の範囲にわたって除数と複数の列挙を使用できます。 

これが重要な単純化です。gcd-lcm の等式により、両側が中央の要素に等しくなり、数論の恒等式が単純な割り算の制約に変わります。

## アルゴリズムのチュートリアル

 1. テスト ケースに存在する値に対して周波数配列を構築します。 これにより、入力に数値が存在するかどうかの定数チェックが可能になります。 
2. あらゆる値について$y$配列内で、セット内で割り切れる数値がいくつあるかを計算します。$y$。 これは、次の有効な選択肢に対応します。$x$、必要なため$y \mid x$。 
3. 同じように$y$、数値が何番目に割られるかを計算します。$y$。 これは、次の有効な選択肢に対応します。$z$、必要なため$z \mid y$。 
4. それぞれの 2 つのカウントを乗算します。$y$それぞれ有効なので、答えに追加します$x$そして$z$選択は一度独立します$y$固定されています。 
5.全体を合計する$y$そして結果を出力します。 

重要な推論ステップは、等号が確立されると、gcd と lcm の両方が強制的に崩壊するということです。$y$、問題は、の左側と右側の独立した乗法制約にきれいに分離されます。$y$。 

### なぜ効果があるのか

 中間要素の固定$y$、条件力$\gcd(x,y)$そして$\operatorname{lcm}(y,z)$平等であること。 なぜなら$\gcd(x,y)$超えることはできません$y$そして$\operatorname{lcm}(y,z)$以下より小さくすることはできません$y$、平等は両方が等しい場合にのみ可能です$y$。 それは同時に施行します$y \mid x$そして$z \mid y$、その他の制約は残りません。 すべての有効なトリプルは、選択することによって一意に決定されます。$y$、次に独立して複数を選択します$x$そして約数$z$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXA = 200000

divisors = [[] for _ in range(MAXA + 1)]
for i in range(1, MAXA + 1):
    for j in range(i, MAXA + 1, i):
        divisors[j].append(i)

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    freq = [0] * (MAXA + 1)
    present = []
    for x in arr:
        freq[x] = 1
        present.append(x)

    # precompute multiples count using sieve-like method
    mult_count = [0] * (MAXA + 1)
    for i in range(1, MAXA + 1):
        if freq[i]:
            for j in range(i, MAXA + 1, i):
                mult_count[i] += freq[j]

    ans = 0
    for y in present:
        # count x such that y | x
        cx = mult_count[y]
        
        # count z such that z | y
        cz = 0
        for d in divisors[y]:
            cz += freq[d]
        
        ans += cx * cz

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、事前に計算された約数リストに依存しているため、各クエリでは次の約数が求められます。$y$速いです。 複数のカウントのステップでは、各値の倍数に対してふるいスタイルの反復を使用します。 なぜなら、価値観には限界があるからです。$2 \cdot 10^5$、事前計算とテストごとの処理の両方が引き続き効率的になります。 

微妙な点は、答えを蓄積するときに入力に存在する値のみを反復処理することです。 これにより、グローバル事前計算を利用しながら、未使用の数値に対する不必要な作業が回避されます。

 ## 特殊なケース

 重要なエッジ ケースは、配列に値 1 が含まれる場合です。$y = 1$、すべての数値は倍数であり、すべての数値は約数でもあります。 アルゴリズムはすべてのペアを正確にカウントします$(x, z)$この中間要素の周囲で、これは条件が次のように折りたたまれることと一致します。$y = 1$。 

もう 1 つのケースは、値が次のような厳密な連鎖を形成する場合です。$[1, 2, 4, 8]$。 中間値ごとに、約数と倍数は構造化されていますが、不均一です。 両方のカウントが同じ周波数配列から独立して計算されるため、アルゴリズムはこれを処理します。 

最後のエッジケースは、配列が完全に素数で構成されている場合です。 その場合、各要素の除数の数は 1 に集約され、複数の数も小さくなり、寄与は最小限になります。 セット内には自己倍数のみが存在するため、アルゴリズムはこれを自然に反映します。
