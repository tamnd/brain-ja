 ## 解決策
 ## 問題の理解

 ボブが高速道路沿いで見ているものの 1 次元表現が与えられ、長さの文字列としてエンコードされます。$N$。 各位置は、次のようにマークされたトラック セグメントのいずれかです。`T`または次のようにマークされた空の道路セグメント`.`。 これは、一部の位置が可視性に寄与し、その他の位置は可視性に寄与しないバイナリ配列と考えることができます。 

ボブは、一定の長さの連続したトラック セグメントを追加することを検討しています。$l_i$この同じ線上にあります。 重要な自由度は、この新しいセグメントは、長さ内に収まる限り、任意の有効な位置から開始して配置できることです。$N$。 一度配置すると、既存のトラックと重なっているポジションは当然トラックのままになるので、表示されているトラックの総数は、配置されているポジションの数になります。`T`元々のものか、新しいセグメントでカバーされるもの。 

クエリの長​​さごとに$l_i$の合計数を最大化するには、この追加されたセグメントの最適な配置を選択する必要があります。`T`挿入後の位置。 

制約は小さいです。$N, Q \le 100$。 これにより、おおよその解決策は次のとおりであることがすぐにわかります。$O(N^3)$全体の操作は次のように制限されているため、それでも快適に通過できます。$10^6$。 

単純な間違いは、最適な配置が常に中央にある、または常に既存のトラックに合わせて配置されていると想定することです。 たとえば、与えられた`T..T`長いセグメントの場合、既存のクラスターの近くに貪欲に配置すると、複数の小さなギャップをカバーすることでより良い合計が得られることを見逃す可能性があります。 

もう 1 つの微妙な失敗例は、重複の誤解です。既存の上にセグメントを追加した場合です。`T`、二重カウントは行わないため、重複をマスキングせずに単純にカウントを加算するアプローチは過大評価になります。 

エッジケースの小さな例:

 入力:```
5 1
T.T.T
3
```セグメントを位置 2 ～ 4 に配置すると、2 つのドットがカバーされますが、位置 3 のトラックとも重なります。正解は、「既存の 3 台のトラック + 3 台の追加」ではなく、結合のサイズです。 

## アプローチ

 ブルートフォースアプローチは簡単です。 クエリの長​​さごとに$l$、追加されたトラックセグメントの可能な開始位置をすべて試します。 配置ごとに、合計数を再計算します。`T`元の文字列と配置されたセグメントの結合内の位置。 これには、各配置の文字列全体をスキャンする必要があり、$O(N)$配置ごとに作業し、$O(N)$配置、与える$O(N^2)$クエリごとに、$O(N^3)$すべてのクエリ全体で。 

以来$N \le 100$、これはすでに機能していますが、不必要に繰り返します。 重要な観察は、ある長さのセグメントを配置すると、$l$位置から開始$i$、影響を受ける唯一の領域はそのウィンドウです。 外側のものはすべて固定されたままで、内側では事実上一部を置き換えています。`.`と`T`。 

したがって、最初から再計算する代わりに、既存のトラックのプレフィックスの合計を事前に計算してから、各配置を評価できます。$O(1)$。 利点は、各ウィンドウ スコアが一定時間で計算可能になり、各クエリが$O(N)$。 

選択したセグメントについて計算します$[i, i+l-1]$、貢献度は次のようになります。 

窓の外側の既存のトラック + 窓全体の長さ (内側のすべての位置が`T`挿入後ですが、重複するトラックはすでにカウントされているため、プレフィックスの合計によって修正します)。 

これにより、各クエリがすべての有効な位置をスキャンし、単純な式を評価するだけになります。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(QN^3)$|$O(1)$| 一般的な形式では遅すぎる |
 | プレフィックス合計ウィンドウ |$O(QN)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列をバイナリ配列に変換します。`T = 1`そして`.`= 0。これにより、トラックの算術カウントが可能になります。 
2. プレフィックス合計配列を構築して、一定時間内の任意の間隔で既存のトラックの台数をクエリできるようにします。 
3. クエリの長​​さごとに$l$、すべての可能な開始位置を反復します。$i$から$0$に$N-l$。 
4. ポジションごとに$i$、ウィンドウ内に元のトラックが何台あるかを計算します。$[i, i+l-1]$。 
5. 新しいセグメントを次のように配置した場合、結果として得られるトラックの合計数を計算します。 

既存のトラックの合計 + (ウィンドウの長さ - ウィンドウ内のトラック)。 

この式は、ウィンドウ内のすべての空のセルがトラックになり、既存のトラックはすでにカウントされていることを反映しています。 
6. すべてのプレースメントの最大値を追跡し、それをクエリに出力します。 

微妙な点はステップ 5 です。文字列全体を再計算しているわけではありません。 そのウィンドウ内で 0 が 1 に変換される数を測定しているだけです。 

### なぜ効果があるのか

 このアルゴリズムは、選択したウィンドウの外側のすべての位置が元の値に正確に寄与する一方、ウィンドウの内側では初期状態に関係なくすべての位置がトラックになるという不変条件を暗黙的に維持します。 したがって、最終的なカウントは、元の合計に、選択したウィンドウ内の空のセルの数を正確に加えたものになります。 すべての配置は 1 回だけ評価され、すべての変換は二重にカウントされることなく正しく考慮されるため、すべてのウィンドウにわたる最大値が正しい答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, Q = map(int, input().split())
    s = input().strip()

    a = [1 if c == 'T' else 0 for c in s]

    pref = [0] * (N + 1)
    for i in range(N):
        pref[i + 1] = pref[i] + a[i]

    total = pref[N]

    def range_sum(l, r):
        return pref[r] - pref[l]

    for _ in range(Q):
        L = int(input())
        best = 0

        for i in range(N - L + 1):
            j = i + L
            inside = range_sum(i, j)
            candidate = total + (L - inside)
            if candidate > best:
                best = candidate

        print(best)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず入力をバイナリ表現に圧縮します。これにより、重複に関する推論が簡素化されます。 プレフィックス合計配列を使用すると、定数時間内に候補配置ウィンドウ内にすでに存在するトラックの数を計算できます。 

クエリごとに、新しいトラック セグメントのあらゆる配置を評価します。 表現`total + (L - inside)`純利益を取得します。空のセルはすべてトラックになりますが、ウィンドウ内の既存のトラックはすでに 1 回カウントされているため、合計は増加しません。 

ネストされたループ構造は安全です。$N$そして$Q$小さいです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    N, Q = map(int, input().split())
    s = input().strip()

    a = [1 if c == 'T' else 0 for c in s]
    pref = [0] * (N + 1)
    for i in range(N):
        pref[i + 1] = pref[i] + a[i]
    total = pref[N]

    out = []
    for _ in range(Q):
        L = int(input())
        best = 0
        for i in range(N - L + 1):
            inside = pref[i + L] - pref[i]
            best = max(best, total + (L - inside))
        out.append(str(best))

    return "\n".join(out) + "\n"

# provided sample
assert run("8 3\nTT..T.T.\n1\n3\n8\n") == "5\n6\n8\n"

# minimum case
assert run("1 1\n.\n1\n") == "1\n"

# all trucks
assert run("5 1\nTTTTT\n2\n") == "5\n"

# all empty
assert run("5 1\n.....\n3\n") == "3\n"

# alternating
assert run("6 1\nT.T.T.\n2\n") == "4\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて空 | Ｌ | 配置による完全な利益 |
 | すべてのトラック | N | 改善は不可能 |
 | 交互 | 4 | オーバーラップ処理の正確性 |
 | 最小サイズ | 1 | 境界の正確性 |

 ## 特殊なケース

 完全に空の文字列は、オフバイワンの間違いに対して最も敏感なケースです。 例えば、`.....`と$L=3$どの配置でも選択したセグメントが完全に変換されるため、3 を返す必要があります。 アルゴリズムはこれを処理します。`inside = 0`すべてのウィンドウに対して、ゲインは常に正確に$L$。 

完全に埋められた文字列はその対極です。 のために`TTTTT`、どのような配置でも改善は見られません。`L - inside = 0`どこでも。 アルゴリズムは答えを正確に維持します$N$プレフィックスの合計は常にウィンドウの長さと一致するためです。 

のような混合交互パターン`T.T.T.`部分的なオーバーラップが正しく処理されるようにします。 プレフィックス合計の減算により、各ウィンドウ内にすでに存在するトラックの数が正確に分離され、二重カウントが防止され、計算されたゲインが正確になります。
