 ## 解決策
 ## 問題の理解

 時間の経過とともに 2 種類の操作をサポートするバイナリ配列が与えられます。 最初の操作はセグメント内のすべてのビットを反転し、0 を 1 に、1 を 0 に変換します。 2 番目の操作では、サブ配列を考慮し、その上で決定論的な 2 プレイヤー ゲームをプレイするように求められます。 

このゲームでは、移動は、完全に等しい値 (すべて 0 またはすべて 1) で構成される最大の連続ブロックを選択し、そのブロック全体をシーケンスから削除することで構成されます。 削除するたびに残りの部分が連結されるため、以前は別々だったブロックがマージされる可能性があります。 プレーヤーは交互に動き、動けなかったプレーヤーが負けます。 ゲーム クエリが評価された後、配列セグメントはすべて 0 にリセットされるため、後のクエリは中間の削除の影響を受けません。 

各ゲーム クエリの出力は、最初のプレーヤーが強制勝利、強制敗北、または引き分けのいずれであるかです。 

制約は最大 20 万の要素と 20 万のクエリに及ぶため、クエリごとに構造を最初から再計算するソリューションはすぐに遅すぎます。 クエリごとの線形スキャンであっても、最悪の場合、許容範囲をはるかに超える二次的な動作が発生する可能性があります。 これにより、ソリューションは、範囲反転と任意のサブ配列からの構造情報の高速抽出の両方をサポートする配列の動的表現を維持する必要があります。 

単純な落とし穴は、ゲーム自体をシミュレートすることです。 固定サブ配列上でも、最大均一セグメントの検索と削除を繰り返すと、移動ごとに線形なプロセスが得られ、移動数もセグメントの長さに対して線形になり、すべてのクエリにわたって三次的な動作が生成されます。 

もう 1 つの微妙な問題は、0 と 1 の数のみが重要であると仮定していることです。 これは失敗します。なぜなら、頻度だけではなく、ブロックの順序が正当な手を定義するからです。 例えば、`0101`そして`0011`カウントは同じですが、動きの構造がまったく異なります。 

## アプローチ

 直接的なシミュレーション手法では、部分配列を明示的に構築し、最大均一セグメントを繰り返し見つけて削除し、交互に回転します。 それぞれの削除には動的構造のスキャンまたは維持が必要であり、最悪の場合、単一のクエリのコストは O(セグメントの長さ) となり、全体で O(NQ) になります。 

重要な観察は、ゲームは個々の要素には依存せず、部分配列を最大の均一な実行に分解することだけに依存するということです。 それぞれの移動で 1 つのランが削除されます。 内部ランを削除した後、その 2 つの隣接ランがマージされるため、構造はランの数とその隣接関係によってのみ進化します。 

これにより、ゲームは交互のセグメントのライン上での純粋な組み合わせプロセスに縮小されます。 ゲームの状態全体は、単一の整数、つまり選択されたサブ配列内の実行数によってキャプチャされます。 

この縮小された形式から、ゲームの結果を分析的に計算できます。 ゲームはラン数の減算プロセスとなり、各移動によってランが削除され、場合によってはマージが発生します。 負けているポジションは、ラン数が 3 で割り切れるポジションであることが判明します。 

動的クエリをサポートするには、ビットのポイントごとの反転の下で任意の範囲の実行数を維持する必要があります。 セグメント内のランの数は、隣接する要素間の遷移をカウントすることによって決定されます。 これは、範囲反転の遅延伝播を備えたセグメント ツリーを使用して維持できます。各ノードには、その左の値、右の値、および遷移の数が格納されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(NQ) 以上 | O(N) | 遅すぎる |
 | セグメント ツリー + 実行カウント | O((N + Q) log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 このソリューションは 2 つの層で構成されています。1 つはフリップ時の隣接情報を維持する構造層、もう 1 つはゲームを単純な実行回数の関数に還元するゲーム評価層です。 

### 1. 配列上にセグメント ツリーを構築します。 

各ノードには、左端の要素の値、右端の要素の値、セグメント内の遷移数の 3 つの値が格納されます。 遷移はインデックス i (a[i] != a[i+1]) です。 

セグメント内の実行の数は常に 1 に遷移の数を加えたものに等しいため、この構造で十分です。 

### 2. セグメントツリーノードのマージルール

 2 つの隣接するセグメント A と B を結合する場合、合計トランジションは、A と B のトランジションの合計に、A の右端の値が B の左端の値と異なる場合に 1 つの余分なトランジションを加えたものになります。これにより、すべての境界を越えた変化がキャプチャされます。 

### 3. フリップの遅延伝播

 反転操作は、範囲内のすべてのビットを切り替えます。 重要なのは、隣接する 2 つの値が等しいかどうかに関係なく、反転しても変化しないため、内部遷移カウントは変化しないことです。 格納されたエンドポイント値のみを反転する必要があります。 

したがって、各ノードは、遷移カウントを変更せずにエンドポイントを切り替えるフリップ フラグをサポートできます。 

### 4. 実行回数のクエリ

 範囲クエリの場合、セグメント ツリー結果ノードを取得します。 セグメント内の実行の数は、トランジションに 1 を加えたものとして計算されます。 

### 5. ゲームの実行数を減らす

 k をクエリされたセグメント内の実行の数とします。 ゲームの結果はkだけに依存します。 最適なプレーの分析から:

 k が 3 で割り切れる場合は負け、そうでない場合は勝ちです。 

したがって、k % 3 == 0 の場合、最初のプレーヤーが負けます。 それ以外の場合は、最初のプレイヤーが勝ちます。 

### 6. クエリ後のリセット

 ゲームのクエリに答えると、セグメントはすべて 0 にリセットされます。 これは、[l, r] に対するゼロへの範囲割り当てに相当し、ツリー内のセグメントを上書きするか、更新を再適用することによって処理されます。 ゼロは単一の実行を形成するため、明示的なリセットを除いて、将来の構造は影響を受けません。 

### なぜ効果があるのか

重要な不変条件は、すべての有効なゲーム状態が、現在のセグメント内の最大均一ランの数によって完全に決定されるということです。 各移動は、k mod 3 で定義された同値クラスを保存する方法でこの構造を縮小します。遷移ベースのセグメント ツリーにより、すべてのフリップで隣接情報の正確さが保存されるため、実行カウントは常に正確になります。 ゲームの結果は k のみに依存するため、削減はすべての更新で有効なままです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("l", "r", "tc", "len")
    def __init__(self, l=0, r=0, tc=0, length=0):
        self.l = l
        self.r = r
        self.tc = tc
        self.len = length

def merge(a, b):
    if a.len == 0:
        return b
    if b.len == 0:
        return a
    res = Node()
    res.l = a.l
    res.r = b.r
    res.len = a.len + b.len
    res.tc = a.tc + b.tc + (1 if a.r != b.l else 0)
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 4 * self.n
        self.lval = [0] * self.size
        self.rval = [0] * self.size
        self.tc = [0] * self.size
        self.lz = [0] * self.size
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def apply_flip(self, v):
        self.lval[v] ^= 1
        self.rval[v] ^= 1

    def build(self, v, tl, tr):
        if tl == tr:
            self.lval[v] = self.rval[v] = self.arr[tl]
            self.tc[v] = 0
            return
        tm = (tl + tr) // 2
        self.build(v*2, tl, tm)
        self.build(v*2+1, tm+1, tr)
        self.pull(v)

    def pull(self, v):
        lc, rc = v*2, v*2+1
        self.lval[v] = self.lval[lc]
        self.rval[v] = self.rval[rc]
        self.tc[v] = self.tc[lc] + self.tc[rc] + (1 if self.rval[lc] != self.lval[rc] else 0)

    def push(self, v):
        if self.lz[v]:
            for c in (v*2, v*2+1):
                self.lz[c] ^= 1
                self.apply_flip(c)
            self.lz[v] = 0

    def update(self, v, tl, tr, l, r):
        if l > r:
            return
        if l == tl and r == tr:
            self.lz[v] ^= 1
            self.apply_flip(v)
            return
        self.push(v)
        tm = (tl + tr) // 2
        self.update(v*2, tl, tm, l, min(r, tm))
        self.update(v*2+1, tm+1, tr, max(l, tm+1), r)
        self.pull(v)

    def query(self, v, tl, tr, l, r):
        if l > r:
            return Node(0, 0, 0, 0)
        if l == tl and r == tr:
            return Node(self.lval[v], self.rval[v], self.tc[v], tr - tl + 1)
        self.push(v)
        tm = (tl + tr) // 2
        a = self.query(v*2, tl, tm, l, min(r, tm))
        b = self.query(v*2+1, tm+1, tr, max(l, tm+1), r)
        return merge(a, b)

def solve():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    st = SegTree(arr)

    for _ in range(q):
        t, l, r = map(int, input().split())
        l -= 1
        r -= 1

        if t == 1:
            st.update(1, 0, n-1, l, r)
        else:
            res = st.query(1, 0, n-1, l, r)
            runs = res.tc + 1
            if runs % 3 == 0:
                print("NO")
            else:
                print("YES")
            st.update(1, 0, n-1, l, r)

if __name__ == "__main__":
    solve()
```セグメント ツリーは遷移カウントを維持するため、すべてのクエリで対数時間で正確な実行数が抽出されます。 各フリップはエンドポイント値を切り替えるだけであり、遷移カウントを妨げることなく遅延フラグを伝播します。 

ゲーム ロジックは最終的なモジュラス チェックで分離され、すべての構造的な複雑さが実行回数に反映されます。

 ## 特殊なケース

 単一要素のクエリでは、遷移がないため、常に 1 つの実行が生成されます。 アルゴリズムは遷移をゼロとして正しく計算し、k = 1 を生成します。これは勝ちの位置です。 

完全に均一なセグメントは、内部遷移がないため、同様に動作します。 ランカウントは 1 なので、常に最初のプレイヤーが勝ちます。 

すべての隣接が遷移に寄与するため、完全に交互するセグメントは最も敏感なケースです。 セグメント ツリーは、境界を意識したマージを通じてこれを正確にキャプチャし、複数のフリップの後でも過小カウントされないようにします。 

隣接する要素間の等価関係は同時ビット反転の下では不変であるため、範囲全体の反転によって遷移カウントが破損することはありません。 これにより、すべての更新を通じて実行カウントが安定した状態に保たれます。
