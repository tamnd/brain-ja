 ## 問題の理解

 長さの文字列として表される 1 次元の道路が与えられます。$N$。 各文字は単位セル (ドットで示される通常の道路セグメント、またはアスタリスクで示される信号機) を表します。 ドットは物理的な距離に寄与しますが、アスタリスクは長さを追加しませんが、制約にとって重要なチェックポイントです。 

信号機を 1 つだけ削除することが許可されています。 それを削除した後、概念的にはこの無限の道路に「キロメートルマーカー」を配置します。各キロメートルは一定の長さを持ちます。$K$道路単位で測定されます。 ちょうど 1 キロメートルの境界線上にある信号機は、そのキロメートルの合計にはカウントされません。 

要件は、1 つの信号機を最適に削除した後、1 キロメートルのセグメントごとに最大で 1 つの信号機が存在することです。$L$残りの信号機はそのセグメント内にのみ存在します。 タスクは、削除を選択し、次に可能な最大値を決定することです。$K$この条件がすべてのキロメートルにわたって維持されるようにします。 

最大の難点は、制約が個々の信号機に局所的なものではなく、考えられる長さのすべてのスライディング ウィンドウの下で信号機がどのように集約されるかに依存することです。$K$。 

制約により許可されるのは、$N$まで$10^6$、考えられるすべてのセグメント長をチェックするソリューションは除外されます。$K$そして違反を再計算します$O(N)$小切手ごとに。 ナイーブ$O(N^2)$スキャンは不可能であり、$O(N \log N)$各チェックが線形以上である場合を除き、大量の再計算を行うことは危険です。 

境界動作に微妙な問題が発生します: 信号機が正確な位置にある$x$そして$x+K$両方とも 1 キロメートル内にカウントされることはありません。 これにより、ウィンドウのカウントに 1 つずつずれた感度が生じ、境界を包括的に扱う場合、素朴な「間隔内の星のスライディング ウィンドウのカウント」アプローチは失敗することがよくあります。 

もう 1 つの注意が必要なケースは、信号機の間隔が不均等な場合です。 星を 1 つ削除すると、単一の「最悪」セグメントだけが修正される可能性がありますが、そのセグメントは選択したセグメントによって異なります。$K$したがって、ボトルネックの正体は次のように変化します。$K$変化します。 

素朴な推論による具体的な失敗シナリオは次のとおりです。 

入力:```

.*.*.*.*.*
```欲張りな考えでは、任意の 1 つの星を削除するとすべての局所密度が十分に減少すると仮定するかもしれませんが、小さい場合には$K$重なっているウィンドウの多くはまだ超えています$L$。 正しい答えは、ローカルな修正ではなく、グローバルな間隔に依存します。

 ## アルゴリズムのチュートリアル

 固定の意思決定チェックを再定式化します。$K$、それをバイナリ検索に埋め込みます。$K$。 

### 1. 答えより二分探索

 検索範囲を維持します$K$。 各中間点について$K$、それが実現可能かどうかをテストします。 可能であれば、より大きな値を試します。 それ以外の場合は範囲​​を縮小します。 これが機能するのは、実現可能性が単調であるためです。$K$。 

単調性が成立するのは、増加するからです。$K$ウィンドウごとの星の数を増やすか維持するだけです。 

### 2. 星の位置上のスライディング ウィンドウ

 すべての信号機の位置を前処理します。 与えられた$K$、これらの位置上でウィンドウをスライドさせて、各間隔内に星の数が含まれるかを計算します。$[i, i+K)$。 

文字列全体をスキャンする代わりに、星の数が線形である星の位置の上に 2 つのポインターを維持します。 

このステップでは、すべての「不正なウィンドウ」を特定します。これは、少なくとも以下の内容を含むウィンドウを意味します。$L+2$星。 

### 3. 取り外し可能なスターのトラック制約

 悪い窓ごとに、その中にどの星があるかを記録します。 重要な要件は、すべての悪いウィンドウに 1 つの星が存在することです。 

許容される削除位置の交差をインデックスの範囲として維持します。 それぞれの不良ウィンドウは制約をもたらします。つまり、削除可能なスターはそのウィンドウのスター セット内になければなりません。 スターは順序付けされているため、各ウィンドウはスター インデックス配列内の連続したセグメントに対応するため、共通部分はグローバルな左境界と右境界を維持することになります。 

最後に交差点が空の場合、単一の削除ではすべての違反が修正されません。 

### 4. 実現可能性の決定

 不正なウィンドウがない場合、構成はすでに有効です。 不正なウィンドウがあっても、その交差部分が空でない場合は、それらすべてを解決する星を削除できます。 それ以外の場合は、現在の$K$は無効です。 

### なぜ効果があるのか

 正確さは、すべての違反が少なくとも次のウィンドウにローカライズされるという事実に基づいています。$L+2$違反しているウィンドウの外側にあるスターを削除しても、違反ウィンドウには影響しません。 したがって、すべての違反ウィンドウに参加するスターが存在する場合に限り、単一の削除で十分です。 スライディング ウィンドウによりすべての違反が確実に列挙され、交差条件により違反全体のグローバルな一貫性が保証されます。 二分探索により最大のものを見つけます$K$この実現可能条件を満たしていること。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, L = map(int, input().split())
    s = input().strip()

    stars = [i for i, c in enumerate(s) if c == '*']
    m = len(stars)

    if m == 0:
        print(n)
        return

    def check(k):
        if m <= L + 1:
            return True

        bad_intervals = 0
        left_ptr = 0

        # intersection over star indices [lo, hi]
        lo, hi = 0, m - 1

        for r in range(m):
            while stars[r] - stars[left_ptr] + 1 > k:
                left_ptr += 1

            cnt = r - left_ptr + 1
            if cnt >= L + 2:
                bad_intervals += 1
                lo = max(lo, left_ptr)
                hi = min(hi, r)

        if bad_intervals == 0:
            return True

        return lo <= hi

    # binary search answer
    ans = 1
    lo, hi = 1, n

    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、道路が星の位置に圧縮されるため、ウィンドウのカウントではドットが完全に無視されます。 スライディング ウィンドウは星のリストでのみ動作します。これは、$O(N)$チェックごとの動作。 

実現可能性関数は、違反しているウィンドウがあるかどうかを追跡し、同時にそのようなウィンドウすべてに表示されるスター インデックスの交差を維持します。 交差点が崩壊した場合、単一の削除ではそのすべての違反を修正できないことがわかっています。$K$。 

二分検索はこの述語をラップし、有効な最大キロメートル長を抽出します。
