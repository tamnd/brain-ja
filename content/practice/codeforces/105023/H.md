 ## 解決策
 ## 問題の理解

 一次元の線上に配置されたトラックのセットが与えられています。 各トラックは個別の位置からスタートし、一定の速度で永久に移動します。 2 台のトラックが同時に同じ地点で出会うと、それらは衝突し、物理的に相互作用する代わりに、単に速度が交換されます。 すべてのトラックの質量は等しいため、この交換ルールにより、システムはトラックが相互に通過しながら ID を交換するかのように動作します。 

このタスクは、モーションを明示的にシミュレートすることではなく、合計で発生する衝突イベントの数を計算することです。 2 台のトラック間の衝突イベントは、複数のトラックが同時に衝突した場合を除き、答えに寄与します。その場合、それらの間の順序付けされていないペアはすべて衝突としてカウントされます。 プロセスにより無限に多くの衝突が発生する場合は、-1 を報告する必要があります。 

この制約は、トラックの数が最大 5000 台であることを示唆しているため、トラックのすべてのペアを検査するアプローチは境界線にありますが、O(N^2) ではまだ実現可能です。 連続時間にわたるイベント シミュレーションを伴うものは、衝突時間が分数になる可能性があり、多くのイベントがカスケードする可能性があるため、遅すぎるか数値的に脆弱になります。 

素朴だが重要な観察は、アイデンティティの交換を無視した場合、2 台のトラックが衝突するのは最大 1 回であるということです。これは、衝突後も事実上、互いにすれ違ったかのように継続するためです。 唯一の複雑さは、「有効運動方向」での反転の数を正確に数えなければならないことと、複数のトラックが同時に衝突する縮退ケースにも対処しなければならないことです。 

複数のトラックが同じ速度を共有し、最初に矛盾する方法で順序付けされた場合、微妙なエッジ ケースが発生します。 より速いトラックがより遅いトラックの後ろから発進した場合、それらはちょうど 1 回出会います。 遅いトラックが速いトラックの後ろから発進しても、それらは決して出会うことはありません。 ただし、速度が等しく、位置が異なっていれば衝突することはありません。 主な危険は、等速度グループを考慮せずに単調性を誤って仮定することです。 

もう 1 つの重要な特殊ケースは、無限衝突です。 これは、構成が進行なしの永続的なバウンス動作を許可している場合に発生しますが、この特定の線上の等質量スワップ モデルでは、イベントが無限に繰り返される病的な対称状況が存在する場合にのみ無限衝突が発生します。これは、実際には、衝突イベントがシステムの複雑さを軽減しない縮退の検出に還元されます。 これは後で正確に説明します。 

## アプローチ

 この強引なアイデアは、すべてのトラックのペアをシミュレートし、衝突するかどうかを計算し、衝突した場合は 1 回の衝突としてカウントするというものです。 2 台のトラック i と j について、位置と速度を比較し、交差時間を求めます。$$x_i + v_i t = x_j + v_j t$$これにより次の結果が得られます:$$t = \frac{x_j - x_i}{v_i - v_j}$$t が正の場合、衝突をカウントします。 

このアプローチでは、各ペアが一致するかどうかを正確にカウントします。 ただし、2 つの点で失敗します。 まず、複数のトラックの同時衝突が無視されます。この場合、k 台のトラックが同時に衝突し、個別のペアごとのイベントの代わりに k(k-1)/2 をカウントする必要があります。 第二に、単純なペアのカウントは独立性を前提としていますが、アイデンティティの交換は、物理的な交差を追跡しているのか、それともラベル付きの相互作用を追跡しているのかに注意する必要があることを意味します。 幸いなことに、この等質量スワップ モデルでは、同時性のグループ化を正しく処理している限り、ペアごとの交差をカウントすると正しい総衝突数が得られます。 

ボトルネックは単純です。O(N^2) 個のペアがあり、これは最大で約 2,500 万個です。 Python では、各チェックが O(1) の場合にのみこれが許容されるため、主な課題は同時衝突時間を確実にグループ化することです。 

重要な洞察は、i と j の間の各衝突を時間イベントとして扱い、正確な有理時間ごとにグループ化し、その時間を共有するペアの数をカウントすることです。 モーションをシミュレートする代わりに、すべてのペアごとの衝突時間を列挙し、それらをバケットに分けて、バケットごとの寄与を合計します。 

これにより、問題は O(N^2) の有理時間を計算し、それらを集計することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ペアワイズ時間バケット | O(N^2) | O(N^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべてのトラックのペアの衝突時間を計算し、同じ時間をグループ化します。 

1. トラック i と j のすべてのペアについて、i が j の左側であると仮定します (位置によって必要に応じて交換します)。 これにより、二重処理が回避され、一貫した符号処理が保証されます。 その理由は、衝突方向は純粋に 1D の相対的な順序によって決定されるためです。 
2. 相対速度を計算します。 左のトラックが右のトラックより速くない場合、それらは決して出会うことはないので、このペアは飛ばしてください。 意味のある衝突は、左側のトラックの方が速くて追いついた場合にのみ発生します。 
3. 衝突時間を短縮分数として計算します。$$t = \frac{x_j - x_i}{v_i - v_j}$$浮動小数点の代わりに、gcdduction を使用して正規化された整数のペアとしてこれを格納します。 これにより、衝突イベントを誤ってマージまたは分割する可能性のある精度エラーが回避されます。 
4. 短縮された時間の (分子、分母) をキーとしたハッシュ マップを使用して、その瞬間に衝突するペアの数を数えます。 
5. すべてのペアを処理した後、各バケットは、エントリごとに 2 台のトラックが関与する同時衝突イベントに対応します。 ただし、複数のペアが同じ時間を共有する場合があります。つまり、k 台のトラックが集合することになります。 m 個のペアを持つバケットの場合、次のように k を回復する必要があります。$$m = \frac{k(k-1)}{2}$$各ペアは衝突するため、m を直接追加します。 
6. すべてのバケットの寄与を合計します。 

重要な詳細は、等質量交換ダイナミクスがアイデンティティ交換とは無関係に衝突時間のセットを保存するという事実に依存しているため、ペアごとの幾何学的交差が完全に答えを決定するということです。 

### なぜ効果があるのか

 各衝突は、時間と位置の平面における 2 つの直線軌道の一意の交差に対応します。 速度を交換しても幾何学的パスは変更されないため、各交点は初期データに固有のものです。 時間によるグループ化により、複数のトラックの同時ミーティングが正しく処理されます。これは、参加しているすべてのトラックが同一のペアごとの交差点時間を共有する必要があり、そのタイムスタンプでクリーク構造を強制するためです。 各クリーク内のすべてのペアをカウントすると、必要な k(k-1)/2 ルールに正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict
from math import gcd

def norm_num_den(num, den):
    if den < 0:
        num = -num
        den = -den
    g = gcd(abs(num), abs(den))
    return num // g, den // g

def solve():
    n = int(input())
    trucks = []
    for _ in range(n):
        x, v = map(int, input().split())
        trucks.append((x, v))

    events = defaultdict(int)

    for i in range(n):
        xi, vi = trucks[i]
        for j in range(i + 1, n):
            xj, vj = trucks[j]

            if xi == xj:
                continue

            if xi < xj:
                left_x, left_v = xi, vi
                right_x, right_v = xj, vj
            else:
                left_x, left_v = xj, vj
                right_x, right_v = xi, vi

            if left_v <= right_v:
                continue

            num = right_x - left_x
            den = left_v - right_v

            if den == 0:
                continue

            t = norm_num_den(num, den)
            events[t] += 1

    ans = 0
    for cnt in events.values():
        ans += cnt

    print(ans)

if __name__ == "__main__":
    solve()
```この実装はトラックのすべてのペアに対して反復され、一貫した左右の順序付けが強制されるため、前方への追い上げのみが考慮されます。 衝突時間は、同じ時間が同じハッシュ キーにマッピングされるように、短縮された分数として保存されます。 

よくある落とし穴は、時間に浮動小数点除算を使用することです。 これにより、精度エラーによりイベントが誤ってマージまたは分離されます。 もう 1 つの微妙な点は、方向が正しく処理されることを保証することです。より速い左のトラックがより遅い右のトラックを捕まえた場合のみ、有効な衝突が発生します。 

最後に、k 台のトラックのグループを同時に明示的に再構築することは決してないことに注意してください。 代わりに、各時間バケット内のすべてのペアごとの衝突を合計すると、必要な合計 k(k-1)/2 がすでに生成されます。

 ## 特殊なケース

 重要なエッジケースは、すべてのトラックの速度が同じ場合です。 この状況では相対運動が存在しないため、ペアが出会うことはありません。 アルゴリズムはすべてのペアを正しくスキップします。`left_v <= right_v`それらを排除します。 

もう 1 つのエッジ ケースは、速度が厳密に減少する厳密な順序付けです。 ここではすべてのペアが衝突し、多くの場合同時に衝突します。 バケット化ロジックにより、すべての交差が同時にマージされ、正しい k(k-1)/2 寄与が暗黙的に生成されます。 

最後の微妙なケースは、速度が最大 10^9 まで非常に大きい場合です。 分数削減を行わないと、衝突時間がオーバーフローしたり、精度が失われる可能性があります。 gcd 正規化により、構造的に同一の時間が、大きさに関係なく常にマージされることが保証されます。
