 ## 解決策
 ## 問題の理解

 単一の大文字の文字列が与えられます。 私たちの目標は、ある接尾辞と同一である文字列のすべての接頭辞を識別し、そのような接頭辞ごとに、文字列内のどこかに連続した部分文字列として出現する回数をカウントすることです。 たとえば、文字列が次の場合、`"ABACABA"`、接頭辞`"A"`これも長さ 1 の接尾辞であり、文字列内に合計 4 回出現します。 

入力文字列は 100,000 文字まで可能です。 考えられるすべてのプレフィックスをすべてのサブストリングに対してチェックする単純なアプローチは、次の順序で実行されます。$10^{10}$1 秒の制限時間をはるかに超える最悪の場合の操作。 これは、線形または線形に近い解決策が必要であることを示しています。 

単純な実装を失敗させる可能性のあるエッジ ケースには、すべての文字が同じである文字列が含まれます。`"AAAAA"`。 このシナリオでは、長さの異なる複数のプレフィックスがサフィックスと一致し、重複する出現によりその数が増加します。 不用意に解決すると、重複する部分文字列のカウントを間違えたり、文字列全体と同じ長さのプレフィックスを省略したりする可能性があります。 同様に、繰り返しパターンのない文字列も次のようになります。`"ABCDEFG"`、存在しない長い一致を誤って識別することなく、アルゴリズムが長さ 1 の一致がある場合のみを正しく返す必要があります。 

## アプローチ

 ブルート フォース手法では、考えられるすべてのプレフィックス長に対して反復処理が行われます。 プレフィックスごとに、同じ長さの対応するサフィックスと一致するかどうかがチェックされます。 次に、文字列全体をスキャンして、このプレフィックスが出現する回数を数えます。 このアプローチは正しいですが、およそ次のような複雑さがあります。$O(n^2)$、各プレフィックス チェックでは文字列のスキャンが必要であり、プレフィックスの総数は$O(n)$。 これは実用的ではありません$n = 10^5$。 

最適なアプローチは、Knuth-Morris-Pratt (KMP) アルゴリズムの接頭辞関数を使用して、部分文字列の繰り返し出現を効率的に計算できるという事実を利用します。 位置の接頭辞関数$i$部分文字列の最も長い適切なプレフィックスの長さを教えてくれます$s[0..i]$これはその部分文字列の接尾辞でもあります。 この関数を使用すると、接頭辞が接尾辞と線形時間で一致するすべての長さを識別できます。 さらに、各プレフィックス長がプレフィックス関数配列に出現する回数をカウントすることにより、各候補部分文字列が部分文字列として出現する頻度を判断できます。 これにより問題は次のように縮小されます$O(n)$時間。 

ブルート フォースは問題定義を直接実装するため機能しますが、長い文字列の場合は失敗します。 prefix 関数がすべての繰り返しの接頭辞と接尾辞の関係をエンコードしているという観察により、接頭辞と接尾辞の識別と部分文字列のカウントの両方を文字列の線形パスに減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | KMP / プレフィックス機能 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列の接頭辞関数を計算します。 ポジションごとに`i`、`pi[i]`の最長の適切なプレフィックスの長さを格納します`s[0..i]`で終わるサフィックスと一致するもの`i`。 この関数は、繰り返されるプレフィックスとサフィックスの関係をすべてキャプチャします。 
2. プレフィックス関数配列を使用して、文字列全体の各プレフィックス長の頻度をカウントします。 サイズの count 配列を初期化します`n+1`ゼロ付き。 それぞれについて`pi[i]`、増分`count[pi[i]]`。 これは、後で各プレフィックスが部分文字列として出現する回数を計算するのに役立ちます。 
3. カウントを長いプレフィックスから短いプレフィックスに伝播します。 長さの接頭辞があるため、`x`また、その適切なプレフィックスであるすべてのプレフィックスにも影響し、最大の長さから最小の長さまで反復されます。`count[pi[i]] += count[i+1]`。 これにより、すべてのプレフィックスに、重複する長いプレフィックスがすべて含まれることが保証されます。 
4. サフィックスでもあるすべてのプレフィックスの長さを特定します。 完全な文字列長から開始して、プレフィックス関数チェーンをたどります。`length = n`、 それから`length = pi[length-1]`まで繰り返す`length == 0`。 これらの長さを集めます。 
5. 収集されたプレフィックス長ごとに、出現数は次のようになります。`count[length] + 1`定義により、各プレフィックスが少なくとも 1 回出現するためです。 長さの昇順に出力します。 

機能する理由: prefix 関数は、反復するすべての接頭辞と接尾辞の構造を線形時間でエンコードします。 カウントを長いプレフィックスから短いプレフィックスに伝播することで、重複する発生を考慮します。 次のチェーン`pi[length-1]`これにより、接尾辞でもあるすべての接頭辞が、包含順に検索されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

# Step 1: Compute prefix function
pi = [0] * n
for i in range(1, n):
    j = pi[i-1]
    while j > 0 and s[i] != s[j]:
        j = pi[j-1]
    if s[i] == s[j]:
        j += 1
    pi[i] = j

# Step 2: Count occurrences of each prefix length
count = [0] * (n + 1)
for length in pi:
    count[length] += 1

# Step 3: Propagate counts
for i in range(n, 0, -1):
    count[pi[i-1]] += count[i]

# Step 4: Collect prefix-suffix matches
lengths = []
k = n
while k > 0:
    lengths.append(k)
    k = pi[k-1]
lengths.sort()

# Step 5: Output results
print(len(lengths))
for l in lengths:
    print(l, count[l] + 1)
```最初のループのプレフィックス関数の計算は標準の KMP です。 ステップ 2 では、周波数配列を初期化します。 ステップ 3 では、重複する一致を考慮して、出現したものを長いプレフィックスから適切なサブプレフィックスに伝播します。 ステップ 4 では、プレフィックス関数チェーンを反復して、サフィックスであるすべてのプレフィックスを検索します。 並べ替えると、出力が昇順になることが保証されます。 の`+1`ステップ 5 では、プレフィックス自体が少なくとも 1 回出現することを考慮しています。
