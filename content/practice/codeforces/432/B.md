 ## 解決策
 ## 問題の理解

 ～間のサッカートーナメントをシミュレートするよう求められました。`n`各チームには、異なる色のホーム キットとアウェイ キットがあります。 各チームはホームアンドアウェーで他のチームと対戦します。 デフォルトでは、ホーム チームはホーム キットを着用し、アウェイ チームはアウェイ キットを着用します。 ただし、色が一致した場合、アウェイチームはホームユニフォームに切り替えます。 

入力により提供されるのは、`n`に続く`n`各チームのホームキットとアウェイキットの色を表す整数のペア。 出力は、各チームのホーム キットとアウェイ キットでプレーした試合数を順番に表示する必要があります。 

制約により許可されるのは、`n`まで`10^5`および最大の色の値`10^5`。 すべての素朴なシミュレーション`n*(n-1)`ゲームの結果は約`10^10`最悪の場合、動作が非常に遅くなります。 大まかに機能するソリューションが必要です`O(n)`または`O(n log n)`時間。 

チームのホームカラーが重なっている場合、微妙な問題が発生します。 たとえば、チーム 1 がホーム カラー 1 とアウェイ カラー 2 を持ち、チーム 2 がホーム カラー 2 とアウェイ カラー 1 を持っている場合、各チームのアウェイ ユニフォームはいくつかのホーム ユニフォームと衝突します。 色の頻度を事前に計算せずに「ホームかアウェイか」だけをカウントする不注意なアプローチは、チームがアウェイ キットを切り替える必要がある頻度を誤ってカウントすることになります。 

## アプローチ

 ブルートフォース手法では、すべてのゲームで反復処理が行われます。 各ペアごとに`(i, j)`、チームかどうかを確認してください`i`のホームカラーはチームと同じです`j`のアウェイカラー。 その場合、アウェイチームはホームキットを着用します。 両チームの各発生をカウントします。 このアプローチは正しいですが、パフォーマンスは`n*(n-1)`比較、つまり`O(n^2)`。 のために`n = 10^5`、これには 100 億回の操作が必要であり、タイムアウトになります。 

より迅速な解決策のための重要な洞察は、各アウェイ キットの競合の総数のみを考慮するということです。 色ごとに、その色をホームキットとして使用しているチームが何チームあるかを事前に計算できます。 それから、チームに関しては、`i`、そのアウェイ キットは同じ色の各ホーム キットと衝突します。 各チームがプレーするので、`(n-1)`アウェイゲームの場合、すべての試合をシミュレートすることなく、ホームキット数に衝突の数を加算し、アウェイキット数から減算することができます。 これにより、複雑さが軽減されます。`O(n)`単純なカウント配列または辞書を使用します。 

ブルートフォースはすべての一致を個別にチェックするため機能しますが、次の場合には失敗します。`n`大きいです。 必要なのは色の頻度だけであるという観察により、問題をチーム間の 1 回のパスに減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(最大色) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 辞書または配列を初期化する`home_count`各色をホームキットとして使用しているチームが何チームあるかを追跡します。 すべてのチームを反復して増分します`home_count[color]`各チームのホームカラーに合わせて。 
2. チームごとに初期化を行う`home_games`として`n-1`各チームがプレーするので`n-1`ホームゲーム。 初期化する`away_games`として`n-1`各チームにもあるので`n-1`アウェイゲーム。 
3. チームのアウェイゲームについて`i`、同じ色のホームチームが何チームあるかを確認してください。`i`のアウェイキット。 このカウントを追加します`home_games`これらのゲームはチームに力を与えるからです`i`ホームキットを着る。 から同じカウントを減算します。`away_games`。 
4. を出力します。`home_games`そして`away_games`入力順にチームごとに。 

それが機能する理由: 各チームのプレー`(n-1)`ホームゲームと`(n-1)`アウェイゲーム。 アウェイ キットの衝突はすべて、別のチームのホーム キットがアウェイの色と一致するときに発生します。 ホームカラーの頻度をカウントすることで、個々の一致をシミュレートすることなく、すべての競合を確実に捕捉できます。 この不変条件により、すべてのチームの正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
teams = []
home_count = dict()

for _ in range(n):
    x, y = map(int, input().split())
    teams.append((x, y))
    home_count[x] = home_count.get(x, 0) + 1

for x, y in teams:
    home_games = n - 1 + home_count.get(y, 0)
    away_games = n - 1 - home_count.get(y, 0)
    print(home_games, away_games)
```まず、各ホームカラーの出現数をカウントするための辞書を構築します。 次に、各チームについて、アウェイ カラーを共有するチームの数を調べることにより、アウェイ キットの衝突によって生じる追加のホーム ゲームを計算します。 使用する`dict.get(y, 0)`ホームユニフォームとしてはどのチームにもないカラーを取り扱っております。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        n = int(input())
        teams = []
        home_count = dict()
        for _ in range(n):
            x, y = map(int, input().split())
            teams.append((x, y))
            home_count[x] = home_count.get(x, 0) + 1
        for x, y in teams:
            home_games = n - 1 + home_count.get(y, 0)
            away_games = n - 1 - home_count.get(y, 0)
            print(home_games, away_games)
    return out.getvalue().strip()

# Provided sample
assert run("2\n1 2\n2 1\n") == "2 0\n2 0", "sample 1"

# Custom cases
assert run("3\n1 2\n1 3\n2 1\n") == "2 1\n2 1\n3 0", "away kit collision"
assert run("2\n1 2\n3 4\n") == "1 1\n1 1", "no collisions"
assert run("4\n1 2\n2 3\n3 4\n4 1\n") == "2 1\n2 1\n2 1\n2 1", "chain collisions"
assert run("2\n100000 1\n1 100000\n") == "2 0\n2 0", "large color numbers"

## 特殊なケース

 すべてのチームのアウェイ キットがホーム キットと競合する場合、アルゴリズムは正しくカウントします。 たとえば、次の入力を使用します。```
2
1 2
2 1
```チーム 1 はホーム ゲームを 1 つプレイし、そのアウェイ キットがチーム 2 のホームと競合するため、再びホーム キットを着用し、合計でホーム ゲーム 2 試合、アウェイ ゲーム 0 試合となります。 チーム 2 は対称的な動作をします。 の`home_count`ディクショナリでは、すべての競合がアウェー キットごとに 1 回正確にカウントされるようになり、二重カウントや競合の欠落が回避されます。 これは、より大きな衝突チェーンや異常な色の割り当てに当てはまります。
