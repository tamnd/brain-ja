 ## 解決策
 ## 問題の理解

 小文字の英字を含む既存の文字列のセットと、許容される最大長 K が与えられます。タスクは、指定されたセットに含まれず、長さが最大 K で、すべての有効な選択肢の中で辞書順にできるだけ小さい新しい文字列を構築することです。 

ここでの辞書編集順序は、辞書の順序とまったく同じように動作します。つまり、ある文字列が別の文字列の接頭辞である場合は、短い接頭辞が最初に来ます。そうでない場合は、最初の異なる文字によって比較が決定されます。 

主な困難は、有効性をチェックすることではなく、欠落している最小の文字列を効率的に見つけることです。 N とすべての文字列の合計の長さは両方とも最大 2 × 10^5 と大きいため、すべての候補文字列を明示的に生成してテストしようとするアプローチは失敗します。 長さ K までのすべての文字列を生成する場合でも、K では指数関数的になります。 

辞書順に考えると、単純な落とし穴がすぐに現れます。「a」から始めて、次に「aa」、「aaa」などを試みたり、文字列を辞書順に反復しようとしたりする可能性があります。 文字列のスペースが指数関数的に増加し、ほとんどの候補がセットに含まれているために無効になるため、これはすぐに壊れます。 

より微妙なエッジケースは、プレフィックス構造です。 たとえば、セットに「a」と「aa」が含まれている場合、答えは「b」ではなく「ab」になります。 貪欲なプレフィックス拡張アプローチは、辞書編集空間で占有されているブランチを適切に考慮していない場合、簡単に失敗する可能性があります。 

もう 1 つの重要なケースは、すべての短い文字列がブロックされる場合です。 長さ 1 の文字列がすべて存在する場合は、長さ 2 に移動する必要がありますが、長さ 2 の文字列すべてを盲目的にチェックする必要はありません。 たとえば、「aa」、「ab」、...、「az」がすべて存在する場合は、「ba」に移動する必要があります。 

本質的な課題は、長さの制約の下で、禁止されたセットに含まれない辞書編集上の最小の文字列を見つけることです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。長さ K までのすべての文字列を辞書編集順に列挙し、セットにない最初の文字列を返します。 これは正しいです。辞書形式の生成では順序が維持され、各ステップでメンバーシップがチェックされるためです。 ただし、長さ K までの文字列の数は最悪の場合でも 26^K 程度になるため、これは実現不可能です。 K = 10 の場合でも、これは天文学的に大きく、K は最大 2 × 10^5 になる可能性があるため、列挙は完全に不可能になります。 

重要な点は、すべての文字列を考慮する必要はなく、有効な回答のプレフィックスとなる可能性のある文字列だけを考慮する必要があるということです。 これは当然、禁止された文字列のトライを構築することを示唆しています。 トライの観点から考えると、問題は、いくつかのノードが禁止されたエンドポイントとしてマークされている 26 分ツリーにわたる制御された走査になります。 

辞書編集上最小の欠損文字列は、このトライの事前順序走査の最初の点に対応します。この点では、欠落している子で拡張できるか、ノードが深さ K までの子パスで完全に飽和していない場所のいずれかになります。 

明示的に文字列を生成する代わりに、暗黙的なトライを介して DFS をシミュレートし、常に「a」から「z」までの文字を試行します。 存在しない文字列、または長さ K 以内で禁止されたセットを超えて拡張できる文字列を形成できる最初の点で停止します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O(26^K) | お(1) | 遅すぎる |
 | トライ + DFS 検索 | O(総文字数 × 26) | O(総文字数 × 26) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべての禁止された文字列を含むトライを構築します。 各ノードはプレフィックスを表し、ノードが完全な禁止語に対応するかどうかをマークします。 

次に、深さ優先検索を実行して、禁止されておらず、長さが K 以下の最小の辞書編集文字列を見つけます。

1. 指定されたすべての文字列をトライに挿入します。 各ノードには 26 個の子ポインタと、単語がそこで終わるかどうかを示すフラグが格納されます。 これにより共有プレフィックスが圧縮されるため、同一の構造を繰り返し処理することがなくなります。 
2. node で表される現在のプレフィックスから開始して答えを構築しようとする再帰関数 dfs(node, Depth) を定義します。 深さは、構築された文字列の現在の長さを追跡します。 
3. 深さが K に等しい場合、それ以上拡張することはできません。 このノードが禁止語ではない場合、現在のプレフィックス自体は有効であり、回答候補として返すことができます。 禁止されている場合、拡張は許可されないため、失敗を返します。 
4. 現在のノードが禁止語としてマークされていない場合、これまでに形成されたプレフィックスはすでに有効な文字列です。 辞書編集的に最小の値が必要なので、この接頭辞をすぐに返すことができます。 拡張しても文字列が大きくなるだけだからです。 
5. それ以外の場合は、文字列を拡張する必要があります。 文字を「a」から「z」まで繰り返します。 文字ごとに、対応する子ノードに移動し (必要に応じて暗黙的に欠落しているノードを作成します)、有効な拡張機能の構築を再帰的に試みます。 
6. 辞書編集順に探索しているため、最初に成功した再帰結果はすぐに返されます。 

### なぜ効果があるのか

 トライにより、禁止された文字列の既存のプレフィックスに従ってのみ分岐し、欠落している分岐は未使用の辞書編集スペースに対応することが保証されます。 DFS は、子を「a」から「z」までスキャンするため、厳密な辞書順で候補を探索します。 禁止された端子ではないノードに遭遇した瞬間、拡張子は辞書編集的に大きくなるため、安全に出力できます。 これにより、占有ワードとしてマークされていないノードのみを受け入れるため、より小さい有効な文字列をスキップしたり、禁止された文字列を返したりすることがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("next", "end")
    def __init__(self):
        self.next = {}
        self.end = False

root = Node()

def insert(s):
    cur = root
    for c in s:
        if c not in cur.next:
            cur.next[c] = Node()
        cur = cur.next[c]
    cur.end = True

N, K = map(int, input().split())
for _ in range(N):
    insert(input().strip())

def dfs(node, depth, path):
    if depth <= K and not node.end:
        return path

    if depth == K:
        return None

    for c in "abcdefghijklmnopqrstuvwxyz":
        if c in node.next:
            nxt = node.next[c]
        else:
            nxt = Node()
            node.next[c] = nxt

        res = dfs(nxt, depth + 1, path + c)
        if res is not None:
            return res

    return None

print(dfs(root, 0, ""))
```トライ構造では共有プレフィックスが圧縮されるため、類似した名前間での作業の繰り返しが回避されます。 DFS 関数は、文字を「a」から「z」まで反復することによって、辞書編集順を直接エンコードします。 重要なのはコンディションです`if depth <= K and not node.end`これにより、現在のプレフィックスがすでに有効で禁止されていない場合に早期終了が可能になります。 

子に動的辞書を使用すると、完全な 26 配列の割り当てが回避されます。これは、文字の総数が 2 × 10^5 に制限されるという制約の下では許容されます。 

## 実用的な例

 ### 例 1

 入力:```
2 10
torterra
pikachu
```両方の単語を含むトライを構築します。 次に、DFS をルートから開始します。 

| ステップ | 現在のプレフィックス | ノードは禁止されています | アクション |
 | --- | --- | --- | --- |
 | 1 | "" | いいえ | 空の接頭辞は単語ではないので、停止することはできません。 | を展開します。 
| 2 | "a" | いいえ | 「a」は禁止されていないため、すぐに戻ります |

 DFS は最初にルートで「a」を試行しますが、競合は見つかりませんでした。 ルート自体は終了ノードではないため、最初に検出される有効な文字列は「a」です。 

これにより、入力された単語が無関係であっても、辞書編集上の最小の文字列が正しく選択されることが確認されます。 

### 例 2

 入力:```
2 2
a
aa
```「a」が禁止語であり、「aa」がそれを拡張するトライを構築します。 

| ステップ | 現在のプレフィックス | ノードは禁止されています | アクション |
 | --- | --- | --- | --- |
 | 1 | "" | いいえ | 停止できません、展開します |
 | 2 | "a" | はい | さらに拡大する必要があります |
 | 3 | "ああ" | はい、ただし長さ=2 | 行き止まり |
 | 4 | "アブ" | いいえ | 「ab」を返す |

 「a」がブロックされ、「aa」もブロックされていることがわかります。そのため、DFS は次の辞書編集ブランチに進み、「ab」を返します。 

これは、プレフィックスが占有するチェーンの正しい処理を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(総文字数 × 26) | 各トライ ノードは文字分岐ごとに最大 1 回アクセスされ、分岐はアルファベットのサイズによって制限されます。 
| スペース | O(合計文字数) | Try は、個別のプレフィックス文字ごとに 1 つのノードを格納します。 

合計文字数制限は 2 × 10^5 であるため、メモリと時間の両方が制約内に収まります。 26 分岐による定数係数は、早期リターンからの枝刈りを考慮すると、Python では 1 秒で十分小さいです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    sys.setrecursionlimit(10**7)

    class Node:
        def __init__(self):
            self.next = {}
            self.end = False

    root = Node()

    def insert(s):
        cur = root
        for c in s:
            if c not in cur.next:
                cur.next[c] = Node()
            cur = cur.next[c]
        cur.end = True

    N, K = map(int, input().split())
    for _ in range(N):
        insert(input().strip())

    def dfs(node, depth, path):
        if depth <= K and not node.end:
            return path
        if depth == K:
            return None
        for c in "abcdefghijklmnopqrstuvwxyz":
            if c in node.next:
                nxt = node.next[c]
            else:
                nxt = Node()
                node.next[c] = nxt
            res = dfs(nxt, depth + 1, path + c)
            if res is not None:
                return res
        return None

    return dfs(root, 0, "")

assert run("2 10\ntorterra\npikachu\n") == "a"
assert run("2 2\na\naa\n") == "ab"
assert run("1 1\nz\n") == "a"
assert run("3 3\na\nb\nc\n") == "aa"
assert run("2 3\nabc\nabd\n") == "a"

 | --- | --- | --- |
 | 関係のない小さな言葉 | | 基本的な辞書編集の開始 |
 | プレフィックスチェーン | アブ | ブロックされたプレフィックス拡張子 |
 | 最大最後の文字 | | z から回り込む |
 | 最初の層全体 | ああ | より深い拡張 |
 | 親しい兄弟 | | 初期の辞書編集上の枝刈り |

 ## 特殊なケース

 禁止された空の文字列がないため、空のプレフィックスがすでに有効である場合、微妙なエッジ ケースが 1 つ発生します。 明示的に許可されていない限り、深さ 0 は有効な端末出力とみなされないため、このアルゴリズムは誤って空を返すことはありません。また、ルートが端末でない場合には、少なくとも 1 つの文字拡張子を常に確保します。 

もう 1 つの重要なケースは、単語が禁止されたエンドポイントであり、トライ内に子を持つ場合です。 たとえば、「a」は禁止されているが、「aa」は禁止されていない場合、アルゴリズムは「a」を正しくスキップし、「a」で始まるすべての短い辞書編集候補が失敗した後にのみ「aa」の探索を続けます。 

最後のケースは、K = 1 で、1 つを除くすべての文字が存在する場合です。 「a」から「z」までの最初のレベルのスキャンでは、より深い再帰を行わずに欠落している分岐が直接識別されるため、DFS は欠落している 1 つの文字を正確に選択します。
