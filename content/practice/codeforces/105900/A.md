 ## 解決策
 ## 問題の理解

 1 から N までのラベルが付けられた一連の山が与えられ、各ラベルはその難易度も表します。 B の前に A という形式の優先規則が M 個あります。つまり、イサはすでに山 A に登っていない限り、山 B に登ることはできません。A < B が常に保証されているため、すべての依存関係は、番号の小さい山から番号の大きい山のみを指します。 

課題は、すべての依存関係を尊重しながら、イサがすべての山を正確に 1 回登る順序を構築することです。 すべての有効な順序の中で、辞書編集的に最小のものを出力する必要があります。つまり、前提条件の制約に違反しない限り、常に小さい番号の山をできるだけ早く配置することを好みます。 有効な順序が存在しない場合は、不可能であることを報告する必要があります。 

構造は頂点 1 から N までの有向グラフであり、各制約は有向エッジ A → B です。目標はトポロジカルな順序付けですが、辞書編集上の最小順序であるトポロジカルな順序付けだけではありません。 

制約は最大 2 · 10^5 の頂点とエッジまでとなります。 これにより、O(NM) または O(N^2) のシミュレーション戦略が即座に除外されます。 O(NM) グラフの走査でも遅すぎます。 許容できる解は、O((N + M) log N) または O(N + M) に近いものだけです。 

重要な構造上の制約は、エッジが小さいラベルから大きいラベルにのみ移行することです。 これにより、グラフが構造上非循環的であることが保証されます。これは、より小さいインデックスに戻ることができないため、循環が存在できないためです。 ただし、順序付けの制約を尊重し、辞書編集出力を最適化する必要があります。 

素朴だが重要な落とし穴は、依存関係を注意深く追跡せずに、単に隣接関係リストを並べ替えたり、使用可能な最小のノードを貪欲に選択したりするだけで十分であると考えることです。 たとえば、常に最小の未訪問ノードをグローバルに選択すると、前提条件がまだ満たされていないノードが選択される可能性があります。 

もう 1 つの微妙なエッジ ケースは、複数のノードが異なる時間に利用可能になる場合です。 現在有効なノードのグローバル構造を維持しない場合、辞書編集上の正しい最小の継続を見逃す可能性があります。 

## アプローチ

 強引なアイデアは、すべてのノードを繰り返しスキャンし、使用されておらず、前提条件がすでに満たされている最小のノードを選択することです。 選択した後、使用済みとしてマークし、繰り返します。 毎回妥当性をチェックするために、度数を再計算するか、度数に影響を与えるすべてのエッジをスキャンします。 

すべてのステップで制約が遵守されるようにするため、これは論理的に機能しますが、コストは非常に高くなります。 N の各ステップで、すべてのノードをスキャンすると O(N) のコストがかかり、前提条件の検証には合計で O(M) かかる可能性があります。 これにより、O(N^2 + M) の動作が発生します。これは、N が 2 · 10^5 の場合、制限をはるかに超えます。 

重要な観察は、これが古典的なトポロジカル順序付け問題であり、唯一の違いは、入次数が 0 のノードの中から利用可能な最小のノードを常に選択しなければならないことです。 これは、現在有効な候補の動的なセットを維持することを示唆しています。 

常に最小の要素を与える構造内で、入力エッジがゼロのすべてのノードを維持すると、プロセスは簡単になります。 利用可能な最小のノードを繰り返し抽出し、それを答えに追加し、その出力エッジを削除して、場合によっては新しいノードをアクティブにします。 最小ヒープまたは優先キューは、このための自然なツールです。 

条件 A < B により、グラフがすでに非循環であることが保証されるため、最後にすべてのノードを処理したかどうかを検証する以外に循環検出ロジックは必要ありません。

 ## アルゴリズムのチュートリアル

問題を有向グラフとしてモデル化し、各ノードの入次数を計算します。 次数 0 のノードは、前提条件がすでに満たされているノードです。 

1. すべてのエッジ A → B の隣接リストを構築し、各エッジの indegree[B] を計算します。 これは、各山がまだ必要とする前提条件の数を正確にエンコードします。 
2. 最小ヒープ (優先キュー) を初期化し、indegree[i] = 0 となるようにすべてのノード i を挿入します。これらは、制約に違反することなくすぐに登ることができる山です。 
3. ヒープから最小の要素を繰り返し抽出します。 これにより、現在利用可能なすべての山の中で、常に辞書順に最小のオプションが選択されるようになります。 
4. この選択したノードを応答シーケンスに追加します。 
5. 選択したノード u の各近傍 v について、indegree[v] を 1 ずつ減分します。indegree[v] が 0 になった場合、v をヒープにプッシュします。 これは、v のすべての前提条件が満たされていることを表しており、選択できるようになります。 
6. ヒープが空になるまで続行します。 
7. 結果のシーケンスの長さが N の場合、それを出力します。 それ以外の場合は、-1 を出力します。 

新しくロック解除されたノードを常に直ちにヒープにプッシュするという正確さにより、辞書編集的に以前に選択できた有効な候補が遅れることがなくなります。 

### なぜ効果があるのか

 すべてのステップで、ヒープには、以前に選択されたノードによって前提条件がすべて満たされているノードのセットが正確に含まれます。 ヒープ内にないノードには依存関係が残っているため、それを選択することは無効です。 有効な候補の中で、最小のラベルを選択するのが最適です。これより大きな値を選択すると、後で利点が得られずに辞書編集的に順序が悪化するためです。 依存構造により、ノードが使用可能になると、遅延しても順序がさらに右に進むだけであり、実現可能性や辞書編集上の順序は決して改善されないことが保証されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)

    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        indeg[b] += 1

    heap = []
    for i in range(1, n + 1):
        if indeg[i] == 0:
            heapq.heappush(heap, i)

    res = []

    while heap:
        u = heapq.heappop(heap)
        res.append(u)

        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                heapq.heappush(heap, v)

    if len(res) != n:
        print(-1)
    else:
        print(*res)

if __name__ == "__main__":
    solve()
```隣接リストにはすべての依存関係エッジが格納され、indegree 配列は各ノードがまだ満たされていない前提条件の数を追跡します。 ヒープは、使用可能な最小のノードを常に選択することによって辞書編集上の最適性を強制する重要な構造です。 

実装の微妙な詳細は、ノードがその入次数がちょうど 0 になった場合にのみヒープにプッシュされることです。 ノードがまだ使用可能になっていないため、これより早くプッシュすると正確性に違反します。 

最終チェックでは、すべてのノードが処理されたことを確認します。 入力では A < B が保証されていますが、このチェックは依然としてトポロジカル ソート問題の標準的な安全条件です。

    indeg = [0] * (n + 1)

        a, b = map(int, input().split())

        indeg[b] += 1

        res.append(u)

    if len(res) != n:

    return " ".join(map(str, res))

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、依存関係が存在しない場合です。 この状況では、すべてのノードの初期度が 0 であるため、ヒープにはすべてのノードが含まれます。 ヒープでは各ステップで辞書編集的な選択が強制されるため、アルゴリズムは単純に 1 から N を順番に出力します。 

もう 1 つのケースは、依存関係が厳密なチェーンを形成する場合です。 たとえば、1 → 2 → 3 → 4 です。ヒープには常に 1 つの要素が含まれるため、アルゴリズムは単純な走査のように動作します。 順序付けに曖昧さはなく、ヒープ オーバーヘッドによって正確さが変わることはありません。 

より微妙なケースは、ノードが遅れて利用可能になるが、すでに利用可能なノードよりも小さい場合です。 たとえば、ノード 3 がノード 5 の後に使用可能になった場合、ヒープは、辞書編集上の最小性を維持しながら、挿入直後にノード 3 が選択されることを保証します。 これはまさに、単純な「毎回すべての候補者をスキャンする」アプローチが誤って処理したり、非効率的に実装したりするシナリオです。
