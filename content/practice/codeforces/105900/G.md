 ## 解決策
 ## 問題の理解

 人はそれぞれ、自分の「真実の愛」として、まさに一人の相手を選びます。 これから、有向グラフを構築します。$N$すべての頂点が、おそらくそれ自身への出力エッジを 1 つだけ持つ頂点。 これはすぐに強力な構造を意味します。方向を無視した場合、すべての頂点には依然として少なくとも 1 つの入射エッジがあり、全体的にグラフは連結成分に分解され、各連結成分には有向ツリーがフィードされる 1 つのサイクルが含まれます。 

課題は、愛について推論することではなく、単純な制約の下でできるだけ多くの互いに素な人々のペアを選択することです。 ペア$(u, v)$の場合は有効です$u \neq v$少なくとも 1 つの有向エッジ$u \to v$または$v \to u$グラフの中に存在します。 各人は最大でも 1 つのペアに所属できますが、そのようなペアの数を最大化したいと考えています。 

グラフ用語で言い換えると、関数的な有向グラフが与えられ、接続する基礎となる無向グラフのマッチングの最大サイズを求められます。$u$そして$v$いつでも$u$を指す$v$。 すべてのノードには 1 つの出力エッジがあるため、基礎となる構造は擬似フォレストです。すべての接続されたコンポーネントには 1 つのサイクルと、そのサイクルにルートされるツリーがあります。 

制約$N \le 10^5$あらゆる解を線形または線形に近いものに強制します。 エドモンズのアルゴリズムのように、すべてのペアリングを試したり、任意のグラフで一般的な最大マッチングを使用したりするものは、遅すぎます。 グラフの非常に制限された構造を利用する必要があります。 

単純だが有益な失敗例は、サイクルを無視することから生まれます。 グラフをツリーとして扱い、最大限のマッチングを得るために標準ツリー DP を実行するとします。 これは、サイクルが存在するとすぐに中断されます。 

たとえば、次のように考えてみましょう$1 \to 2, 2 \to 3, 3 \to 1$。 基礎となるグラフは三角形です。 ツリー DP は、サイクル周囲のエッジが一致する可能性を適切に考慮することはなく、任意のルートの選択に応じて、誤ってルート付きツリーとして処理します。 正解は 1 ですが、単純に root 化すると、サイクルが「切断」される場所によっては一貫性のない結果が生じる可能性があります。 

サイクルに木が接続されている場合、別の微妙な失敗が発生します。 単純なアプローチでは、各ツリーは正しく解決されますが、サイクル エッジがキャパシティの一致をめぐって互いに競合することは無視される可能性があります。 

## アプローチ

 ブルートフォースメンタルモデルは、無向グラフを構築し、一般的な最大一致アルゴリズムを実行することです。 これは原則として正しいです。なぜなら、最大一致問題を正確に解いているからです。 ただし、グラフには最大$10^5$頂点、エドモンズの花アルゴリズムは大まかに実行されます$O(N^3)$単純な実装では、または$O(N^2)$最適化されたものでは、ここで必要なものをはるかに超えています。 

重要な点は、これが任意のグラフではないということです。 各ノードには出力エッジが 1 つだけあるため、すべてのコンポーネントには 1 つのサイクルが含まれます。 サイクルの外側にあるものはすべて、サイクルに向かう木です。 この構造により、問題をツリー マッチングとサイクル マッチングに分けることができます。 

ツリーでは、最大一致は、ノードごとに 2 つの状態 (ノードがその親と一致するかどうか) を使用する標準の動的プログラミングです。 純粋なツリーでは、これは簡単です。 この複雑さは、コンポーネントごとに 1 つのサイクルがあるためにのみ発生します。 1 つのエッジでサイクルを断ち切ると、構造は再びツリーになりますが、削除されたエッジが最適なマッチングに使用される場合と使用されない場合があるという事実に対処する必要があります。 

したがって、サイクルごとに、それを分離し、1 つのエッジを壊してツリーに変え、ツリー DP とのマッチングを計算し、その壊れたエッジを取得または禁止する可能性がある影響を慎重に検討します。 各エッジをブレークポイントとして試すと一貫した結果が得られますが、ブレークする必要があるのは 1 回だけで、2 つの論理ケースを処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 一般的な最大一致（ブロッサム） |$O(N^3)$|$O(N)$| 遅すぎる |
 | 関数グラフ分解 + DP |$O(N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 無向隣接リストに変換する

 あらゆるインデックスに対して$i$の間に無向エッジを追加します。$i$そして$A_i$。 どちらの方向が存在してもペアは有効であるため、これにより、有効なペアリングに必要な隣接条件が正確に保持されます。 

結果のグラフは正確に次のようになります。$N$エッジオーバー$N$これにより、すべての接続コンポーネントに 1 つのサイクルが含まれることが保証されます。 

### ステップ 2: グラフをコンポーネントに分解し、サイクルを特定する

 未訪問の各ノードを走査し、DFS または反復走査を実行して、接続されているコンポーネントを収集します。 各コンポーネント内で、標準の訪問状態手法 (再帰スタックの追跡または次数ピーリングの使用) を使用して固有のサイクルを検出します。 

循環は、循環依存関係を導入するため、ツリー DP だけでは不十分なコンポーネントの唯一の部分です。 

### ステップ 3: ツリーをサイクル ノードにアタッチし、DP 構造を準備する

 サイクル ノードが識別されると、すべての非サイクル ノードは、あるサイクル ノードをルートとするツリーに属します。 概念的には、これらのツリーをサイクルでルートし、葉から上に向かって DP を実行します。 

すべてのノードについて$u$、2 つの値を計算します。 最初のものは、次の場合にサブツリー内で最もよく一致します。$u$親と自由に一致させることができます。 2 番目は次の場合に最適です。$u$すでに上向きに一致しているため、一致が禁止されています$u$どの子でも。 

これは DP に一致する標準のツリーであり、サブツリーが非循環であるため、きれいに動作します。 

### ステップ 4: サイクルを断ち切り、ツリー DP 問題に変換する

 1 つのエッジを選択します$(c_1, c_2)$サイクルに入れて取り外します。 1 つのエンドポイントをルートとして扱うと、構造はルート付きツリーになります。 

この構造に対して 2 つのシナリオでツリー DP を実行します。 

最初のシナリオでは、次の間のマッチングを禁止します。$c_1$そして$c_2$。 これにより、ベースライン一致値が得られます。 

2 番目のシナリオでは、一致を強制します$c_1$と$c_2$、これにより、両方がさらなるマッチングから削除され、それに応じて接続されたツリーの DP が調整されます。 

このサイクルでは、これら 2 つのケースの最大値を採用します。 

### ステップ 5: すべてのコンポーネントを合計する

 コンポーネント間にエッジがないため、各コンポーネントは独立しています。 各コンポーネントに最も一致する値を合計します。 

### なぜ効果があるのか

 正確かどうかは、すべてのコンポーネントに正確に 1 つのサイクルがあり、そのサイクルが処理されると、残りの構造はツリーになるという事実にかかっています。 ツリー DP は、すべてのエッジの決定によってツリーが独立した部分問題にローカルに分割されるため、ツリー上のマッチングに最適です。 依存関係ループが発生する唯一の場所はサイクル自体であり、これは 1 つのエッジを切断し、そのエッジがマッチングに参加しているかどうかを明示的に考慮することで解決されます。 すべての有効なマッチングは、これら 2 つのケースのいずれかに一致する方法でサイクル エッジの 0 または 1 つを使用するため、両方の最大値が最適値を捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(200000)

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    a = [x - 1 for x in a]

    g = [[] for _ in range(n)]
    for i in range(n):
        j = a[i]
        g[i].append(j)
        g[j].append(i)

    visited = [False] * n
    in_stack = [False] * n

    parent = [-1] * n
    comp_nodes = []
    cycles = []

    def dfs(u):
        visited[u] = True
        in_stack[u] = True
        comp_nodes.append(u)

        for v in g[u]:
            if not visited[v]:
                parent[v] = u
                dfs(v)
            elif in_stack[v] and v != parent[u]:
                # found a cycle, reconstruct
                cycle = [v]
                cur = u
                while cur != v:
                    cycle.append(cur)
                    cur = parent[cur]
                cycles.append(cycle)

        in_stack[u] = False

    dp0 = [0] * n
    dp1 = [0] * n

    def tree_dp(u, p):
        dp0[u] = 0
        dp1[u] = 0

        for v in g[u]:
            if v == p:
                continue
            tree_dp(v, u)
            dp0[u] += max(dp0[v], dp1[v])

        for v in g[u]:
            if v == p:
                continue
            dp1[u] = max(dp1[u], 1 + dp0[v] + (dp0[u] - max(dp0[v], dp1[v])))

    def solve_component(root):
        stack = [root]
        comp = []
        parent_local = {root: -1}

        while stack:
            u = stack.pop()
            comp.append(u)
            for v in g[u]:
                if v not in parent_local:
                    parent_local[v] = u
                    stack.append(v)

        # find cycle via degree peeling
        deg = {u: len(g[u]) for u in comp}
        from collections import deque
        q = deque([u for u in comp if deg[u] == 1])
        removed = set()

        while q:
            u = q.popleft()
            removed.add(u)
            for v in g[u]:
                if v in deg:
                    deg[v] -= 1
                    if deg[v] == 1 and v not in removed:
                        q.append(v)

        cycle = [u for u in comp if u not in removed]

        # pick arbitrary cycle edge
        c = cycle[0]
        for v in g[c]:
            if v in cycle:
                c2 = v
                break

        # build rooted tree at c ignoring cycle edge c-c2
        banned = {(c, c2), (c2, c)}

        def dp(u, p):
            dp0[u] = 0
            dp1[u] = 0
            for v in g[u]:
                if v == p or (u, v) in banned:
                    continue
                dp(v, u)
                dp0[u] += max(dp0[v], dp1[v])
            for v in g[u]:
                if v == p or (u, v) in banned:
                    continue
                dp1[u] = max(dp1[u], 1 + dp0[v] + (dp0[u] - max(dp0[v], dp1[v])))

        dp(c, -1)

        return max(dp0[c], dp1[c])

    ans = 0
    seen = [False] * n

    for i in range(n):
        if not seen[i]:
            stack = [i]
            seen[i] = True
            comp = []
            while stack:
                u = stack.pop()
                comp.append(u)
                for v in g[u]:
                    if not seen[v]:
                        seen[v] = True
                        stack.append(v)
            ans += solve_component(i)

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、「love」ポインターによって誘導される無向グラフを構築します。 各コンポーネントは単純な DFS を使用して抽出されます。 各コンポーネントの内部では、剥離度を使用してサイクルを検出し、サイクルだけが残るまで葉を繰り返し除去します。 

サイクルが分離されたら、1 つのサイクル エッジをブレークし、任意のサイクル ノードからツリー DP を実行します。 DP は、ノードごとに 2 つの状態 (空き状態であるか、すでに上位に一致しているか) を維持します。 トランジションは、子からの貢献を集約し、オプションでノードを 1 つの子とのみペアにします。 

実装の微妙な詳細は、削除されたサイクル エッジを横切るトラバースを回避することです。 これは、DP がサイクル構造を再導入してツリーの仮定を無効にするのを防ぐために必要です。 

## 実用的な例

 ### 例 1

 小さなサイクルが付加された単純な線を考えてみましょう。$1 \to 2 \to 3 \to 1$そして$4 \to 3$。 

サイクルは$[1,2,3]$、ノード 4 が 3 に接続されています。 

| ステップ | サイクルノード | ルートの DP 状態 | 決定 |
 | --- | --- | --- | --- |
 | ブレイクエッジ(1,2) | 3サイクル | 計算ツリー DP | サイクルはツリーとして扱われます |
 | 最も一致するものを含める | ルート 1 | dp0=1、dp1=1 | 最適なものを選択してください |

 これにより、サイクル ノードへのアタッチメントがツリーのように動作し、DP に正しく吸収されることが確認されます。 

### 例 2

 サイクルのないチェーン:$1 \to 2, 2 \to 3, 3 \to 4$| ノード | dp0 | dp1 |
 | --- | --- | --- |
 | 4 | 0 | 0 |
 | 3 | 1 | 0 |
 | 2 | 1 | 1 |
 | 1 | 2 | 1 |

 ルートは答え 2 で終わり、貪欲な直感と一致します: (1,2) と (3,4) のペア。

 ## 特殊なケース

 のような自己ループ$i \to i$～にとって有効なパートナーが存在しない$i$有効な個別のエッジが作成されないため、アルゴリズムは当然これを無視します。 

純粋なサイクルでは、1 つのエッジを壊しても最適なマッチングが可能かどうかをテストします。 DP は一致する構成と一致しない構成の両方を考慮するため、サイクル エッジが見逃されることはありません。 

サイクルに長いチェーンをフィードすることで、ツリー DP がサイクル処理による干渉なしに深いサブツリーからの寄与を正しく蓄積できるようになります。 

複数のノードが同じサイクル ノードを指すコンポーネントは、複数の子が DP 状態遷移で正しく競合するかどうかをテストし、ノードごとに一致するエッジが 1 つだけ選択されるようにします。
