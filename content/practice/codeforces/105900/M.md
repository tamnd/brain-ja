 ## 解決策
 ## 問題の理解

 ノードがガソリン スタンドを表し、エッジが移動距離のある一方通行の道路を表す、有向重み付きグラフが与えられます。 ノード 1 から開始し、ノード N に到達する必要があります。1 から N までのすべての有効なルートには 2 つの競合する基準があります。 

まず、ルートの総距離をできるだけ短くする必要があります。 この最小合計距離を達成するすべてのルートの中で、停車地間の燃料消費量の点でそのルートがどの程度「スムーズ」であるかを考慮します。 滑らかさは、パスに沿って使用される最大の単一エッジの重みとして測定されます。 最終的な目標は、最短のパスを選択し、その中で最大エッジの重みを最小限に抑えることです。 

したがって、出力は 2 つの値になります。 1 つ目は、1 から N までの可能な最短距離です。2 つ目は、すべての最短パスの中で、そのパスで使用される最大のエッジの最小値です。 

制約は最大 200,000 のノードとエッジに適用され、重みは最大 100,000 になります。 これにより、三次または二次さえも即座に除外されます。 単一のダイクストラ実行は問題ありませんが、エッジごとの最短パスの再計算やすべてのパスの列挙を伴うものは問題ありません。 

複数の最短パスが存在する場合、微妙な問題が発生します。 距離のみを追跡する単純な最短パス アルゴリズムは、任意の最短パスを喜んで返しますが、必ずしも最適なボトルネックを持つパスが返されるとは限りません。 もう 1 つの落とし穴は、ボトルネック最小パスの合計距離が最短ではない可能性があるため、最初にボトルネックを最適化しようとすることです。 

小さな対立の例:

 入力:```
3 3
1 2 1
2 3 10
1 3 5
```1 → 2 → 3 を経由した最短距離は 6 ですが、直接パス 1 → 3 の距離は 5 であり、最初の基準には無効です。 最短経路は 1 → 2 → 3 しか存在しないので、答えは (11, 10) となります。 素朴な「最初に最大エッジを最小化する」と、1 → 3 が誤って選択されてしまいます。 

もう 1 つのエッジ ケースは、異なるボトルネックを持つ等しい最短距離です。```
3 3
1 2 1
2 3 2
1 3 3
```1→2→3 と 1→3 の両方の距離は 3 です。最初のボトルネックは 2、2 番目のボトルネックは 3 です。正解は (3, 2) です。 

## アプローチ

 強引なアイデアは、1 から N までのすべてのパスを列挙し、それらの合計距離と最大エッジ重みを計算し、辞書編集的な順序に基づいて最適なペアを選択することです。 これは概念的には正しいですが、すぐには実行不可能です。 疎なグラフであっても、パスの数は指数関数的に増加する可能性があり、DAG のような構造では簡単に 2^N に達します。 各パス評価のコストは O(N) であるため、合計は指数関数的になり、使用できなくなります。 

より構造化された試みは、ダイクストラを最短距離で 1 回実行し、その後、少なくとも 1 つの最短パス上にあるエッジのみに注意を限定することです。 これにより、dist[u] + w =​​= dist[v] の場合にのみエッジ (u, v) が許可されるサブグラフが構築されます。 これが機能するのは、最短パスはすべてのステップでこの等式を満たさなければならないためです。 

この最短パス DAG を取得したら、問題は、最大エッジの重みを最小化するその内部の 1 から N までのパスを選択することになります。 これは古典的な「パス上の最大エッジを最小化する」問題であり、パス コストが合計ではなくルートに沿った最大エッジである場合の別の最短パス計算で解決できます。 エッジ緩和になりますので、`max(current, w)`、DAG 上で 2 番目のダイクストラのようなプロセスを実行できます。 

重要な洞察は、目的の分離です。 最短パス条件は制約曲面を定義し、その曲面内で 2 番目の目的を最適化します。 ダイクストラの構造では、二次コストを検討する前に、すべての最短距離が固定されることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(N) | 遅すぎる |
 | 2 相ダイクストラ (dist + 制約付きボトルネック DP) | O((N + M) log N) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最適な戦略

 1. ノード 1 からダイクストラを実行して、すべてのノードまでの最短距離を計算します。 これにより、各ステーションに到達するために可能な最小の総コストが確立されます。 これがなければ、各ノードでローカルに「最短パス」が何を意味するかを定義できません。 
2. dist[u] + w =​​= dist[v] を満たすエッジ (u、v、w) のみを保持するフィルター処理された隣接構造を構築します。 これにより、保持されたすべてのエッジが少なくとも 1 つの最短パスと互換性を持つことが保証されます。 この条件に違反するエッジは、厳密に総距離を増加させることになるため、有効な最短パスには決して現れません。 
3. このフィルタリングされたグラフで、次に 2 番目の DP 値を計算します。これは、最短パスのみに制限された、1 から各ノードまでのパスに沿った最小可能な最大エッジの重みです。 
4. ノード v での状態コストが、これまでに使用された最大エッジの可能な最小値である 2 番目のダイクストラ類似プロセスを初期化します。 ソース値を 0 に設定します。 
5. このボトルネック値によって順序付けされた優先キューを使用します。 ノード u からエッジ (u, v, w) を通過すると、新しいコストは max(current_cost, w) になります。 これは、パスに沿って発生する最大エッジを正確にモデル化します。 
6. この新しいボトルネック値が現在の最良値を改善する場合は、v をリラックスします。 
7. 処理後のノード N の答えは、最短距離として dist[N]、最短パス制約の下で最小化された最大エッジとして best_bottleneck[N] になります。 

### なぜ効果があるのか

 最初のダイクストラは正確な最短距離でロックします。 これにより、グラフが階層構造になり、すべての有効な動きが最適な距離の伸びを維持する必要があります。 この構造内では、1 から N までのパスはすべて、元のグラフの最短パスに対応します。 

保持されたすべてのエッジは局所的に最短経路の最適性を維持するため、そのようなエッジを連結すると距離のグローバルな最適性が維持されます。 これは、すべてのパスを検索するのではなく、最短パスのセットのみを検索することを意味します。 

その制限されたセット内で、2 番目のプロセスはすべての実行可能な最短パスを探索しますが、これまでに確認された最大エッジである単調コスト関数を使用してそれらを比較します。 パスを延長しても最大エッジを減らすことができないため、この関数はダイクストラ型緩和と互換性があります。 これにより、貪欲な拡張が引き続き有効であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq
from collections import defaultdict

def dijkstra_dist(n, adj):
    INF = 10**30
    dist = [INF] * (n + 1)
    dist[1] = 0
    pq = [(0, 1)]
    
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    
    return dist

def dijkstra_bottleneck(n, adj, dist):
    INF = 10**30
    best = [INF] * (n + 1)
    best[1] = 0
    pq = [(0, 1)]
    
    while pq:
        cur, u = heapq.heappop(pq)
        if cur != best[u]:
            continue
        for v, w in adj[u]:
            if dist[u] + w != dist[v]:
                continue
            nc = max(cur, w)
            if nc < best[v]:
                best[v] = nc
                heapq.heappush(pq, (nc, v))
    
    return best

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        a, b, w = map(int, input().split())
        adj[a].append((b, w))
    
    dist = dijkstra_dist(n, adj)
    best = dijkstra_bottleneck(n, adj, dist)
    
    print(dist[n], best[n])

if __name__ == "__main__":
    solve()
```このソリューションは、完全な有向隣接リストを構築することから始まります。 最初のダイクストラは、ノード 1 からの正確な最短距離を計算し、後でフィルタリング条件として使用します。 

2 番目のフェーズでは、同じ隣接リストが再利用されますが、最短パスの等価性を維持する遷移のみが許可されます。 このフィルタリングは、2 番目のグラフを事前に構築するのではなく、緩和中にインラインで実行されるため、メモリと時間が節約されます。 

実装の重要な詳細は等価性チェックです`dist[u] + w != dist[v]`。 これは正確でなければなりません。 を使用して`>`または`<`比較では、誤って非最短エッジが許可されたり、有効なエッジが破棄されたりすることがありました。 

ボトルネック DP は 2 番目の優先順位のキューを使用します。これは、状態空間が引き続き貪欲な拡張の恩恵を受けるためです。 コストは加算的ではありませんが、最大関数は拡張に沿って単調なままであるため、ダイクストラ スタイルの順序付けが有効になります。

 入力:```

 ## 特殊なケース

 よくある失敗は、ボトルネックの最適化を最短パスの計算とは独立して扱うことです。 ダイレクト エッジのホップは短く、重みは長い例では、単純なミニマックス アプローチでは誤ってエッジが選択されてしまいます。 

このようなエッジは最初の距離パス中に削除されるため、アルゴリズムはこれを処理します。 例えば：```
3 3
1 2 1
2 3 10
1 3 5
```ダイクストラは dist[3]=5 を与えます。 エッジ 2→3 は、1→2→3 の合計が 11 で 5 を超えるため、最短経路上にないため無視されます。 残りのパス構造では有効な最短ルートのみが許可され、ボトルネックはそれらの間でのみ計算され、正確性が維持されます。
