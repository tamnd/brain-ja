 ## 問題の理解

 無限のカードのコレクションが与えられ、各カードには固定の整数の累乗がラベル付けされています。$n$。 最初のカードには価値がある$n^0$、2番目$n^1$、3番目$n^2$、 等々。 このデッキから、カードの有限のサブセットを選択することによって「動き」が形成され、動きの値は選択されたカードの値の単純な合計になります。 

したがって、すべての動きはいくつかのインデックスの選択に対応します$i$、そして合計$n^i$。 各カードは選択することも選択しないこともできるため、すべての動きは本質的に次のべき乗の部分集合の和になります。$n$。 

次に、考えられるすべての手がその結果の合計によって並べ替えられ、$k$この順序で - 番目に小さい合計。 

制約は大きく、両方とも$n$そして$k$まで可能です$10^9$。 これにより、サブセットを明示的に生成したり、値を列挙しようとする試みが即座に排除されます。$k$シミュレーションによって。 サブセットの数は考慮されるカードの数に応じて指数関数的に増加するため、単純なアプローチでは、カットオフが適度な場合でも爆発的に増加します。 

微妙な点は、空のサブセットが含まれているかどうかを理解することです。 シーケンスは 0 ではなく 1 から始まるため、例ではそうではないことが明確になっています。つまり、空ではないサブセットのみを考慮します。 

典型的な失敗例は、合計を貪欲に生成しようとしたり、サブセットよりも優先キューを使用したりすることによって発生します。 例えば、権力だけでも$1, n, n^2$、サブセットの数はすでに 8 であり、この構造を拡張すると、$k = 10^9$不可能です。 

本当に難しいのは、ソートされた順序でこれらの合計の構造を認識することです。 

## アプローチ

 ブルートフォース手法では、インデックスのすべてのサブセットを生成し、それらの合計を計算してから並べ替えようとします。 段階的に生成しようとしても、サブセットの数は増加します。$2^m$どこ$m$考慮されるべき乗の数です。 周囲の価値観に到達するには$k$、必要になります$m$十分に大きい$2^m \ge k$、 意味$m \approx 30$すでに十分です$k \le 10^9$。 ただし、サブセットを明示的に列挙して並べ替えるには、最悪の場合でも約 10 億個の値を保存する必要があり、これは不可能です。 

重要な洞察は、サブセットを組み合わせオブジェクトとして考えるのをやめ、代わりに合計構造を再解釈することです。 各サブセットは、各パワーを含めるかどうかの選択に対応します$n^i$。 これはまさにインデックスごとのバイナリ選択であるため、すべての移動はバイナリ文字列に対応し、値はベースでのそのバイナリ文字列の評価になります。$n$数字は 0 と 1 のみを使用します。 

ここで重要な観察は、これらの値を数値でソートすることは、位置の重みを持つ数値として解釈されるバイナリ表現をソートすることと同じであるということです。$n^i$。 上位の力が下位の力を支配するため（なぜなら、$n \ge 2$)、この順序は、標準の基数 2 の位置の意味で解釈される 2 進整数の自然な順序と完全に一致します。

 ## アルゴリズムのチュートリアル

 次のバイナリ形式で表される値を計算したいとします。$k$ここで、各ビットは次の累乗の選択に対応します。$n$。 

1.読む$n$そして$k$。 治療します$k$サブセット合計のソートされたリスト内のランクとして。 
2.変換$k$バイナリ表現に変換します。 各ビット位置$i$かどうかを教えてくれます$n^i$サブセットに含まれています。 
3. 現在の答えを 0 として初期化し、現在の電力値を 1 として初期化します。$n^0$。 
4. ビットを反復処理します。$k$最も重要でないものから最も重要なものまで。 各ビットについて:

 ビットが 1 の場合、現在のべき乗を加算します。$n$答えに。 
5. 各ビットを処理した後、現在の電力を次のように乗算します。$n$(モジュロ$10^9+7$) 次の指数に移動します。 
6. 最終累積和モジュロを出力します。$10^9+7$。 

理由の乗算$n$うまくいくということは、各ステップが私たちを$n^i$に$n^{i+1}$、デッキの構造に一致します。 

### なぜ効果があるのか

 すべてのサブセットはバイナリ文字列に一意に対応し、その値は基数を伴う位置数値体系です。$n$数字は 0 または 1 に制限されます。$n \ge 2$、高いインデックスが常に低いインデックスよりも優先され、値による並べ替えがバイナリ マスクの整数値による並べ替えと同じであることが保証されます。 したがって、サブセット合計の順位順序は、整数の自然順序と一致します。$k = 1, 2, 3, \dots$、および のバイナリ表現$k$必要なサブセットを直接エンコードします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, k = map(int, input().split())

    ans = 0
    power = 1

    while k > 0:
        if k & 1:
            ans = (ans + power) % MOD
        power = (power * n) % MOD
        k >>= 1

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、バイナリ分解のアイデアを直接実装しています。 変数`power`トラック$n^i$ビットをスキャンすると$k$。 設定されたビットに遭遇するたびに、対応する累乗を結果に追加します。 オーバーフローを避けるために、モジュロはすべてのステップで適用されます。 

実装の微妙な点は、30 または 31 までのすべてのべき乗を明示的に事前計算することは決してないことです。 代わりに、それらを反復的に構築します。これで十分です。$k \le 10^9$最大 30 ビットを意味します。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, sys.stdin.readline().split())

    ans = 0
    power = 1
    while k > 0:
        if k & 1:
            ans = (ans + power) % MOD
        power = (power * n) % MOD
        k >>= 1

    return str(ans)

# provided samples
assert run("3 3\n") == "4"
assert run("3 5\n") == "10"

# custom cases
assert run("2 1\n") == "1", "minimum k"
assert run("2 2\n") == "2", "single higher bit"
assert run("10 7\n") == str(1 + 10 + 100), "mixed binary structure"
assert run("3 1\n") == "1", "smallest non-empty subset"

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$k$は 2 の累乗です。 例えば、$k = 8$バイナリに対応`1000`、のみの意味$n^3$が選択されます。 単一ビットのみが寄与し、より低い電力はすべて無視されるため、アルゴリズムはこれを自然に処理します。 

別のケースは、次のような下位ビットがすべて設定されている場合です。$k = 7$与える`111`。 ここで合計は次のようになります$1 + n + n^2$。 反復累積により、特別な処理を必要とせずにこれが正しく構築されます。 

最後の微妙なケースが大きい$n$。 すべての算術演算はモジュロであるため、$10^9+7$、中間べき乗は安全に削減され、乗算が Python の一般的な整数制限をオーバーフローすることはありませんが、モジュラー削減により値の制限と一貫性が維持されます。
