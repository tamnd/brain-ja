 ## 解決策
 ## 問題の理解

 アイスクリームが入った 2 つの容器、円筒形のボトルと、上部に追加のドームが付いたコーンを比較しています。 

ボトルは半径のある単純な円柱です`rL`と高さ`hL`、完全に埋まっています。 その容量はちょうど通常のシリンダー容積です。 

円錐面は半径のある直円錐で構成されます`rC`と高さ`hC`、これも完全に満たされ、その後、同じ半径の固体の半球が形成されます。`rC`その上にアイスクリームが詰められています。 したがって、コーン コンテナには実質的に容積に寄与する 2 つの部分があります。 

課題は、ボトルに半球のある円錐構造よりも厳密に多くのアイスクリームが入るかどうかを判断することです。 「はい」の場合、出力します`Injusto`、それ以外の場合は出力します`Justo`。 

入力サイズは非常に小さく、すべての次元が最大 100 です。これにより、高度な最適化の必要性が即座に排除されます。 直接的な定数時間の計算で十分であり、浮動小数点演算でも技術的には機能しますが、不必要な精度のリスクが生じます。 

唯一の微妙な問題は、体積には π が含まれることですが、両側に因子として π が含まれるため、代数的に比較すると完全に相殺されます。 π を維持し、浮動小数点比較を使用する不注意な実装でも合格する可能性はありますが、回避可能であり、堅牢性は低くなります。 

エッジケースは主に平等性と境界線の比較に関するものです。 たとえば、両方のコンテナの容量が同じ場合、答えは次のようになります。`Justo`なぜなら、この条件ではボトルを厳密に大きくする必要があるからです。 

## アプローチ

 ブルートフォース解釈では、幾何学式を使用して両方の体積を直接計算します。 ボトルは単純です: シリンダーの容積`π rL^2 hL`。 円錐は円錐の体積の合計です`(1/3)π rC^2 hC`と半球ボリューム`(2/3)π rC^3`。 

このアプローチはすでに O(1) であるため、アルゴリズムのボトルネックはありません。 唯一の潜在的な非効率性は、浮動小数点演算と π を不必要に使用することです。これにより、スケーリング後に正確な整数であるはずの値を比較するときに丸めの問題が発生します。 

重要な観察は、π がすべての項に共通であるということです。 すべてに 3/π を掛けると、すべての体積が整数に変換されます。 

ボトルはこうなります`3 rL^2 hL`、そして円錐は次のようになります`rC^2 hC + 2 rC^3`。 この変換後、比較は純粋に整数ベースで正確になります。 

これにより、問題は 1 つの整数比較に集約されます。

 ## アルゴリズムのチュートリアル

 ### 最適なアプローチ

 1. 4 つの整数を読み取ります`rL, hL, rC, hC`。 これらは、体積を比較する 2 つの幾何学的ソリッドを定義します。 
2. スケールされたボトルの体積を次のように計算します。`Vb = 3 * rL * rL * hL`。 これは、シリンダーの体積を 3 倍し、π を削除することで得られます。 
3. スケーリングされた円錐と半球の体積を次のように計算します。`Vc = rC * rC * hC + 2 * rC * rC * rC`。 最初の項は円錐に対応し、2 番目の項はスケーリング後の半球に対応します。 
4. 比較する`Vb`そして`Vc`。 もし`Vb`厳密には大きい、出力`Injusto`。 それ以外の場合は出力`Justo`。 

スケーリングの背後にある理由は、無理な定数を排除しながら順序を正確に維持することです。 

### なぜ効果があるのか

 両方の元の体積は π に比例します。 π は正であり、両方の式で同一であるため、π で乗算または除算しても順序は変わりません。 同様に、すべてに 3 を掛けると、円錐の公式の分数がクリアされます。 この変換後、両方の式は比例した体積を正確に表す整数になるため、それらを比較することは、元の体積を比較することと数学的に同等になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    rL, hL, rC, hC = map(int, input().split())

    bottle = 3 * rL * rL * hL
    cone = rC * rC * hC + 2 * rC * rC * rC

    if bottle > cone:
        print("Injusto")
    else:
        print("Justo")

if __name__ == "__main__":
    solve()
```実装は代数的単純化に直接従います。 必要な唯一の注意は、整数演算を一貫して使用することです。 最大の大きさはおよそであるため、すべての中間値は 32 ビット整数内に快適に収まります。`3 * 100^3 = 3e6`。 

決定ステップでは、ステートメントの要求に応じて厳密な不等式を使用します。 ネクタイのデフォルトは次のとおりです`Justo`。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、スケーリング後の平等です。 例えば、`1 4 1 10`同一のスケーリングされたボリュームを生成します。 このアルゴリズムは両方の式を正確に計算し、以下の条件に該当します。`Justo`条件が厳しいため分岐します。 

もう 1 つのケースは、コーンの半径が大きいが高さが小さい場合です。 半球項が立方体的に成長しても、その半径または高さが十分に大きい場合は、ボトルが依然として優勢になる可能性があります。 整数比較は、不安定になることなくこれを処理します。 

最終的なエッジ シナリオの最大値は 100 付近です。それでも、最大の中間値は約 100 です。`3 * 100^3 = 3,000,000`、整数の制限内に十分収まっているため、オーバーフローや精度の問題は発生しません。
