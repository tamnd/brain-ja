 ## 解決策
 ## 問題の理解

 ある長さの文字列を調べています`n`26 個の小文字の英語文字から形成されますが、実際に使用される文字は気にしません。 代わりに、一貫して文字の名前を変更することで一方をもう一方に変えることができ、各文字を別個の文字にマッピングする必要がある場合、2 つの文字列は同じであるとみなされます。 

これは、繰り返しの構造が重要であることを意味します。 たとえば、長さ 3 の文字列では、文字列は`aba`、`cbc`、 そして`xyx`最初と最後の位置は一致しますが、中間の位置は異なるため、構造はすべて同じです。 一方で、`aab`そして`aba`立場間の等価関係が異なるため、異なります。 

したがって、タスクは、長さの異なる「等値パターン」がいくつあるかを数えることです。`n`十分な大きさのアルファベット (26 文字) があると仮定しますが、利用可能な個別の文字を超えない限り再利用は許可されます。 

等価パターンはポジションの分割として見ることができます`1..n`グループに分割する場合、同じグループ内のポジションは同じ文字を共有する必要があり、異なるグループは異なる文字を使用する必要があります。 単射写像条件により、異なるグループを 1 つの文字にまとめることができなくなります。 

制約`n ≤ 10^6`パーティション、スターリング数、またはサブセットに対する DP に対する組み合わせ列挙を即座に除外します。 二次関数であっても`n`不可能です。 閉じた形式の組み合わせ恒等式または高速反復が必要です。 

微妙なエッジケースが現れるのは、`n > 26`。 この場合、26 個を超える異なる文字を割り当てることはできないため、すべてのパーティションが有効であるとは限りません。 したがって、26 ブロックを超えるパーティションは除外する必要があります。 小型用`n ≤ 26`、すべてのパーティションが有効です。 大型の場合`n`、最大 26 ブロックのパーティションのみ許可されます。 

## アプローチ

 効率を無視した場合、直接解釈すると、次の長さの文字列がすべて生成されます。`n`、最初に出現した順に文字のラベルを付け直すことでそれぞれを標準形式に減らし、個別の標準形式をカウントします。 これはすぐに爆発します。`26^n`文字列をグループ化することさえ不可能です。 

問題を再構成することが重要なステップです。 文字列について考える代わりに、左から右にスキャンするときに新しい文字が何個現れるかを考えます。 各位置は、既存のシンボルを再利用するか、新しいシンボルを導入します。 構造は、「新しい個別の文字」がいつ現れるか、および後の位置が前の位置をどのように参照するかによって完全に決定されます。 

これは古典的な解釈につながります。答えは、オブジェクトのセット パーティションの数です。`n`要素の順序付けされたシーケンスをラベル付きブロックに変換します。ブロックは文字に対応しますが、ラベルは名前を変更するまで無関係です。 これはまさにベル番号です`B(n)`アルファベットが無制限のとき。 

ただし、文字数の上限は 26 文字であるため、パーティションの数が必要です。`n`要素は最大 26 ブロックに設定されます。 つまり:$$\sum_{k=1}^{\min(n, 26)} S(n, k)$$どこ`S(n, k)`は第 2 種スターリング数です。 

までの完全な DP を計算することはできません。`n = 10^6`2Dテーブルで。 解決策を明らかにする観察は、必要なのは次のことだけです。`k ≤ 26`、一定の上限。 これにより、1D DP を使用してスターリング数を繰り返し計算できるようになります。`k`、それぞれ更新`n`。 

再発:$$S(n, k) = S(n-1, k-1) + k \cdot S(n-1, k)$$行ごとに構築してみましょうが、最大 26 列しか保持しません。

 ## アルゴリズムのチュートリアル

 最後に計算された行のみを保持しながら、スターリング数値を動的に構築します。 

1. DP アレイを初期化する`dp[k]`、 どこ`dp[k]`現在のプレフィックスを分割する方法の数を表します。`k`ブロック。 のために`n = 0`、設定しました`dp[0] = 1`空の構造には単純なパーティションが 1 つあるためです。 
2. 反復する`i`から`1`に`n`。 各ステップで新しい配列を更新します`ndp`サイズのパーティションを表す`i`。 
3. それぞれについて`k`から`1`に`min(i, 26)`、計算する`ndp[k] = dp[k-1] + k * dp[k]`。 最初の項は、新しい要素を独自のブロックにすることに対応し、2 番目の項は、新しい要素を既存のブロックに挿入することに対応します。 
4.充填後`ndp`、 交換する`dp`と`ndp`。 
5. すべてのポジションを処理した後、合計します。`dp[k]`のために`k = 1`に`min(n, 26)`最終的な答えを得るために。 

26 に制限することで、一定幅を超えて割り当てたり計算したりすることがなくなり、プロセスが線形に保たれます。`n`。 

### なぜ効果があるのか

 あらゆる段階で`i`、DP はプレフィックスのすべての有効なパーティションをエンコードします。`1..i`。 新しい要素はそれぞれ、新しい同値クラスを形成するか、既存の同値クラスに結合します。 これは、スターリング数の漸化式の定義と正確に一致します。 26 を超えるクラスは決して許可されないため、無効な状態は DP 次元を切り捨てることによって自然に除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input().strip())
    
    K = 26
    dp = [0] * (K + 1)
    dp[0] = 1
    
    for i in range(1, n + 1):
        ndp = [0] * (K + 1)
        lim = min(i, K)
        for k in range(1, lim + 1):
            ndp[k] = (dp[k - 1] + k * dp[k]) % MOD
        dp = ndp
    
    ans = sum(dp) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```DP 配列は、サイズを 26 に固定することで小さく保たれます。遷移はスターリング再帰を直接エンコードします。 ループを慎重にキャップします。`min(i, 26)`したがって、無効な状態にアクセスすることはありません。 最終的な合計は、最大 26 ブロックを持つすべての有効なパーティションを集計します。

 ## 特殊なケース

 のために`n = 1`、DP は 1 つの状態から始まり、すぐに任意の 1 文字に対応する 1 つの有効なパターンを生成します。 繰り返しでは無効な遷移が試行されることはありません。`dp[0]`唯一の貢献ベースです。 

のために`n ≤ 26`、すべてのスターリング数が寄与し、切り捨ては発生しません。 DP は、以下に制限された標準のベル数計算とまったく同じように動作します。`n`要素なので、アルファベットの制限は結果に影響しません。 

のために`n > 26`、26 を超えるブロックを持つステートは決して作成されません。`lim = min(i, 26)`キャップトランジション。 これにより、より明確な文字を必要とするパーティションが後でフィルタリングされるのではなく自動的に除外されるため、後処理の必要がなくなります。
