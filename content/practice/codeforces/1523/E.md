 ## 解決策
 ## 問題の理解

 一列に並んで点灯するライトの予想数を計算するように求められます。$n$連続する長さのセグメントに基づいて停止条件が与えられると点灯します。$k$。 各ライトが点灯し始め、各ステップで、まだ消灯しているランダムなライトが 1 つ点灯します。 デバイスは、いずれかのセグメントが開始されるとすぐに停止します。$k$連続したライトには複数のライトが点灯しています。 入力は、次の値を持つ複数のテスト ケースを与えます。$n$そして$k$、デバイスが停止した瞬間に点灯するライトの予想数を剰余で返す必要があります。$10^9+7$。 

制約が示唆する$n$と同じ大きさにすることができます$10^5$最大 10 個のテスト ケースを作成できます。 すべてのシーケンスをシミュレートしたり、可能性を列挙したりする単純なアプローチでは、すぐに限界を超えてしまうでしょう。$10^5$テストケースごとの操作は、最大で非常に遅すぎます。$3 \cdot 10^6$合計の反復回数。 明示的なシミュレーションではなく、分析的なアプローチが必要です。 

微妙なエッジケースが発生する場合$k$に非常に近いです$n$、 例えば$n = k = 2$。 長さ 2 の唯一のセグメントにすでに両方のライトが含まれているため、2 つのライトが点灯した直後にデバイスが停止します。 期待値が次のように直線的に増加するという単純な仮定$n/k$ここで失敗するだろう。 同様に、$k = 2$そして$n$が大きい場合、予想されるライトの数は$n$、セグメントの重複を考慮せずに一様確率を誤って適用すると、間違った答えが得られます。 

## アプローチ

 ブルート フォース アプローチは概念的には単純です。ライトのアクティベーションのすべてのシーケンスを列挙し、点灯したライトの数を追跡し、セグメントが点灯したときにシーケンスのカウントを停止します。$k$連続するライトには複数のライトが含まれます。 次に、結果の合計をシーケンスの総数で割ったものとして期待値を計算します。 このアプローチは正しいですが、次の要素に基づいています。$n$なぜなら、アクティベーションの各シーケンスはライトの順列だからです。 たとえ$n = 20$、これはもう$20! \approx 2.4 \cdot 10^{18}$実行不可能な操作。 

重要な洞察は、停止条件をトリガーせずにアクティブ化できるポジションに焦点を当てることです。 点灯するライトの予想数を位置の合計として考えると、ライトは少なくとも次の場合にのみ点灯できることがわかります。$k$以前に点灯したライトから離れた位置に配置します。 これにより、問題は、少なくとも重複しない「マーカー」を配置するという組み合わせまたは確率の問題に変換されます。$k$一列に離れて$n$ポジション。 期待値の線形性を利用すれば、シーケンスを列挙する必要はありません。 可能な距離を反復し、高調波の合計から導出される確率式を適用することで、期待されるライトの数を計算できます。 

最適なアプローチでは、派生式を使用して期待値を計算します。期待値は次のとおりです。$E = k - 1 + \sum_{i=0}^{n-k} 1 / (i + k)$モジュロ$10^9+7$これは、モジュロでの除算を処理する逆モジュラーを使用して効率的に計算できます。 これにより、問題が階乗から階乗に縮小されます。$O(n)$テストケースごとに、これは許容されます$n$まで$10^5$。

 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして$k$。 
2. 変数を初期化する`ans`に$k - 1$, なぜなら最初の$k - 1$ライトは規則に違反することなくいつでも点灯できます。 
3. 反復する`i`0から`n - k`包括的な。 それぞれについて`i`、の逆モジュラーを計算します。`i + k`モジュロ$10^9+7$そしてそれを追加します`ans`。 これは、安全に点灯できる残りのライトの予想される寄与に相当します。 
4. すべての寄与を合計した後、出力します。`ans`モジュロ $10^9+7`。 

機能する理由: 期待値の線形性により、各ライトの期待される寄与の合計として期待値を個別に計算できます。 停止条件は、安全にオンにできる残りの位置の数の調和和として再定式化できます。 逆モジュラを使用すると、モジュロ算術による除算が正しく処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def expected_lights(n, k):
    ans = k - 1
    for i in range(n - k + 1):
        ans = (ans + modinv(i + k)) % MOD
    return ans

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    print(expected_lights(n, k))
```機能`modinv(x)`フェルマーの小定理を使用して逆モジュラーを計算します。 ループは慎重に始まります`i = 0`に`n - k`、最初の金庫を超えた残りの位置を表します`k - 1`。 各項をモジュロで加算します$10^9+7$オーバーフローを避けるため。 の使用`pow(x, MOD - 2, MOD)`たとえ次のような場合でも正確性を保証します`i + k`大きいです。

### サンプル 2: n = 15、k = 2

 から始めます`ans = 1`。 次に、2 から 15 までの逆剰余を追加します。逆剰余の合計は、$10^9+7$与える`141946947`。 

これらの表は、モジュール逆関数を使用して各ライトの予想される寄与がどのように蓄積されるかを示しており、アルゴリズムが間隔制約を正しく考慮していることを確認しています。

 ## 特殊なケース

 いつ`n = k`、アルゴリズムは正しく設定します`ans = k - 1 = n - 1`最初にループが実行されます。`i = 0`に`n - k = 0`のモジュラー逆関数を追加します。`k = n`、その結果は正確に`n`。 例えば、`n = 10, k = 10`与える`ans = 9 + modinv(10) = 10`。 これは、デバイスがほぼ即座に停止条件をトリガーする状況をアルゴリズムが適切に処理し、予想される数値を正しく計算していることを示しています。
