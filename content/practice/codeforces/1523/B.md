 ## 解決策
 ## 問題の理解

 システムの内部変数を表す偶数長の配列が与えられます。 各変数には初期の正の整数値があります。 目標は、2 種類の操作を使用して、すべての要素をその否定に変更することです。1 つは、後の要素の値を前の要素に加算するか、または前の要素を後の要素から減算することができます。 操作では順序制約を尊重する必要があります。つまり、最初のインデックスは 2 番目のインデックスよりも厳密に小さくなります。 各操作では、以下の要素の絶対値を保持する必要があります。$10^{18}$、操作の合計数は 5000 を超えてはなりません。テスト ケースごとに、配列をその否定に変換する有効な一連の操作を提供する必要があります。 

制約は、配列の長さが最大 ​​1000 要素であることと、複数のテスト ケースがあることを示しています。 操作の最大数は 5000 であるため、この制限を超えると二次関数の爆発が発生する場合、すべてのペアを単純に任意に操作するようなソリューションを用意することはできません。 整数のオーバーフローも避ける必要があります。 ただし、演​​算は線形であり、最大値から開始されます。$10^9$に到達する前に安全なバッファーがあるため、$10^{18}$。 

要素がすでに等しい場合、または演算の順序に注意しないと大きな中間値が生成される可能性のある方法で数値のペアが相互作用する場合、微妙なエッジ ケースが発生します。 たとえば、単純なシーケンシャル アプリケーションは、次の値を超える一時的な値を作成する可能性があります。$10^{18}$大きな数値を繰り返し足した場合。 また、要素の数は偶数であるため、体系的なアプローチには要素を慎重に組み合わせることが重要です。 

## アプローチ

 ブルートフォースアプローチでは、他のすべての要素に操作を繰り返し適用することで、各要素を個別に反転しようとします。 符号が反転するまで加算または減算することを想像することもできます。 これは原理的には機能しますが、単一の要素に何百もの操作が必要になる可能性があり、他のすべての要素と相互作用することにより、すぐに実用的ではなくなります。$O(n^2)$ステップ数が多く、大規模な配列の場合は 5000 回の操作を超える可能性があります。 

重要な洞察は、この操作が各ペアを独立して変換できる線形システム操作に似ているということです。 要素を順番にペアにすることで、ペアごとに 6 つの操作の固定シーケンスを使用して両方を系統的に無効にすることができます。 ペアを検討してください$(x, y)$。 操作のシーケンスは次のとおりです。 

1.セット$y = y - x$2.セット$x = x + y$3.セット$y = y - x$4. 上記の 3 つの手順を同じ順序で再度繰り返します

 このシーケンスは変形します$(x, y)$の中へ$(-x, -y)$他の要素に影響を与えることなく。 線形結合のプロパティにより、各ステップで中間値の境界が維持され (おおよそ 2 または 3 倍)、順序制約が維持されます。$i < j$。 ペアごとに正確に 6 つの操作を実行し、$n/2$ペアの場合、操作の合計数は$3n$、これは安全に 5000 未満です。$n \le 1000$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる/危険 |
 | ペアごとの否定 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を 2 つのステップで繰り返し、連続するペアを作成します$(a_1, a_2), (a_3, a_4), \dots$。 均等な長さなので、要素が残りません。 
2. ペアごとに$(x, y)$、次の操作を順番に実行します。$y = y - x$、 それから$x = x + y$、 それから$y = y - x$。 このシーケンスは部分的に否定方向に進みます。 
3. 同じペアに対して上記 3 つの操作をもう一度繰り返します。 6回の手術の後、どちらも$x$そして$y$否定されてしまう。 
4. 各演算を必要な形式で出力に追加します。type (加算の場合は 1、減算の場合は 2) の後に要素のインデックスが続きます。 
5. 配列の終わりまで次のペアに進みます。 
6. 各テスト ケースの操作の合計数とシーケンスを出力します。 

これが機能する理由: 各ペアは独立して変換され、6 つの操作のシーケンスによって次のことが代数的に保証されます。$(x, y)$になる$(-x, -y)$。 ペアは相互作用しないため、プロセスはアレイ全体で一貫しています。 操作は、絶対値制限を超えないよう慎重に順序付けされ、インデックス制約が尊重されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ops = []
        for i in range(0, n, 2):
            x, y = i+1, i+2  # 1-based indices
            # Sequence of six operations to negate both
            ops.append((2, x, y))
            ops.append((1, x, y))
            ops.append((2, x, y))
            ops.append((2, x, y))
            ops.append((1, x, y))
            ops.append((2, x, y))
        print(len(ops))
        for op in ops:
            print(op[0], op[1], op[2])

if __name__ == "__main__":
    solve()
```このソリューションは、操作の 1 から始まるインデックス付けを慎重に処理し、ペアごとに正確に 6 つの操作を実行し、2 段階で反復して、各ペアが独立して処理されるようにします。 各演算タイプは問題の定義に対応し、このシーケンスが 2 回繰り返されて否定が実現されます。 このパターンでは、全体の操作が線形に保たれます。$n$そして安全に限界値を下回ります。 

## 実用的な例

 ### サンプル 1

 入力配列: [1, 1, 1, 1]

 | ステップ | 操作 | 演算後の配列 |
 | --- | --- | --- |
 | 1 | 2 1 2 | [1, 0, 1, 1] |
 | 2 | 1 1 2 | [1、1、1、1] |
 | 3 | 2 1 2 | [1, 0, 1, 1] |
 | 4 | 2 3 4 | [1, 0, 1, 0] |
 | 5 | 1 3 4 | [1, 0, 1, 1] |
 | 6 | 2 3 4 | [1, 0, 1, 0] |

 この表は、ペアごとの否定プロセスを示しています。 ペアごとに 6 つの操作がすべて完了すると、各要素が否定されます。 

### サンプル 2

 入力配列: [4、3、1、2]

 ペア (4,3) と (1,2) を個別に処理すると、最終的な否定配列 [-4, -3, -1, -2] が生成されます。 各中間操作は、制限された絶対値を維持します。

 ## 特殊なケース

 最小入力 [1,1] の場合、アルゴリズムは 1 つのペアに対して 6 つの演算を実行し、結果は [-1,-1] になります。 最大 n の場合、たとえば n=1000 の場合、アルゴリズムはちょうど 3000 回の操作を生成しますが、5000 未満であれば安全です。中間値は最大の初期要素の 3 倍を超えることはなく、十分に下回ります。$10^{18}$。 すべての値が等しい配列や変動が大きい配列は、各ペアが独立して順番に変換され、相互作用によって誤った否定が発生しないことが保証されるため、正しく処理されます。
