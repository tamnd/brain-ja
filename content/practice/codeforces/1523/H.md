 ## 解決策
 ## 問題の理解

 配列で表される一連のタイルの上をバッタが飛び回るのを手伝うように求められます。`a`。 各タイル`i`数字が含まれています`a[i]`バッタがそのタイルから前方にジャンプできる最大距離を定義します。 つまり、バッタがタイル上にいる場合`i`から任意のタイルに移動できます。`i+1`まで`i+a[i]`。 

各クエリについて、サブ配列を考慮します。`[l, r]`配列の最大の削除が許可されます`k`タイルを開始する前に (そのサブ配列の最初と最後を除く)。 目標は、タイルを削除できるこの自由を考慮して、サブ配列の最後のタイルに到達するために必要なジャンプの最小数を決定することです。 出力は、各クエリの最小ジャンプ数です。 

制約が与える`n`そして`q`20,000までですが、`k`非常に小さく、最大 30 です。`k`に指数関数的に依存する解決策がすぐに提案されます。`k`実現可能かもしれない。 取り外し可能なタイルのすべてのサブセットを素朴に総当たり攻撃しようとすると、サブセットの数は次のようになります。`2^k`、これは管理可能です。`k <= 30`。 

注意が必要なエッジケースには、長さが 1 または 2 のサブ配列、ジャンプが必要ないサブ配列が含まれます。`a[l]`すでに終わりと、すべてのホップの長さが 1 であるケースをカバーしています。これらを慎重に扱わないと、単純な実装では範囲外のインデックスを作成したり、ジャンプを過剰にカウントしたりする可能性があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。特定のサブ配列に対して、最大で次のすべての組み合わせを試すことができます。`k`取り外し可能なタイルを作成し、バッタのジャンプをシミュレートして、どの組み合わせがホップ数を最も少なくするかを確認します。 これが機能する理由は、`k`は小さいですが、シミュレーション ステップにはサブ配列の長さで線形時間がかかり、最大 20,000 になる可能性があります。 と`q`クエリの場合、これは非常に遅くなります。最悪のケースは次のとおりです。`q * subarray_length * 2^k`、大まかに言うと`20,000 * 20,000 * 2^30`単純に見積もっても、明らかに実現不可能です。 

重要な洞察は、これを動的プログラミングの問題として扱うことです。 定義すると`dp[i][j]`位置に到達するための最小ジャンプ数として`i`削除した`j`ここまでのタイルを使用して、サブ配列上に DP テーブルを構築できます。 各タイルについて、そのジャンプ長を使用して DP 値を前方に伝播します。 削除されるタイルの最大数`k`は小さいため、DP テーブルの 2 番目の次元は 31 によって制限されます。各 DP 更新は、以前の到達可能な位置に対するスライディング ウィンドウの最大値を使用して最適化できます。 これにより、クエリごとの複雑さが管理可能な程度に軽減されます。`O((r-l+1) * k)`。 

問題の構造により、このアプローチは機能します。`k`これにより、指数関数的に爆発することなく、削除されたタイルを明示的に追跡でき、ジャンプの伝播を効率的に管理できます。`a[i]`はサブ配列の長さに制限されます。実際には、`<= 20,000`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(2^k * n) | O(n) | 遅すぎる |
 | タイルを削除した DP | クエリごとに O(n * k) | O(n * k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. クエリごとに部分配列を抽出します。`[l, r]`そしてそれを次のように保存します`b`。 させて`m = r - l + 1`。 
2. DP テーブルの初期化`dp`サイズの`m x (k+1)`、 どこ`dp[i][j]`インデックスに到達するための最小ジャンプを表します`i`正確に削除した`j`タイル。 を除くすべてのエントリを無限大に設定します。`dp[0][0] = 0`ジャンプゼロの最初のタイルから開始するためです。 
3. タイルごとに`i`で`b`、すべてを繰り返します`j`0から`k`:

 ａ． もし`dp[i][j]`は有限であるため、ジャンプをタイルに伝播できます`i+1`を通して`min(i+b[i], m-1)`。 到達可能なタイルごとに`next_i`、 アップデート`dp[next_i][j]`なる`min(dp[next_i][j], dp[i][j]+1)`。 

b. さらに、`j < k`そして`i`最初または最後のタイルではありません。タイルを削除することを検討してください`i`。 その場合は伝播します`dp[i+1][j+1] = min(dp[i+1][j+1], dp[i][j])`。 これにより、ジャンプ数を増やすことなくタイルを効果的にスキップできます。 
4. 表を埋めると、答えは次のようになります。`min(dp[m-1][0], dp[m-1][1], ..., dp[m-1][k])`。 

機能する理由: DP テーブルは、次の不変条件を維持します。`dp[i][j]`タイルに到達するまでの最小ジャンプ数です`i`正確に削除した後`j`タイル。 どのタイルを削除するかについて考えられるすべての選択は、2 番目の次元を通じて暗黙的に考慮されます。`j`、ジャンプ伝播により、各タイルから到達可能なすべての位置が確実に考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    for _ in range(q):
        l, r, k = map(int, input().split())
        l -= 1
        r -= 1
        b = a[l:r+1]
        m = r - l + 1
        dp = [[float('inf')] * (k+1) for _ in range(m)]
        dp[0][0] = 0
        
        for i in range(m):
            for j in range(k+1):
                if dp[i][j] == float('inf'):
                    continue
                reach = min(i + b[i], m-1)
                for next_i in range(i+1, reach+1):
                    dp[next_i][j] = min(dp[next_i][j], dp[i][j]+1)
                if j < k and i != 0 and i != m-1:
                    dp[i+1][j+1] = min(dp[i+1][j+1], dp[i][j])
        
        print(min(dp[m-1]))

if __name__ == "__main__":
    solve()
```この解決策では、インデックス付けを簡素化するためにサブ配列がコピーされます。 明示的にチェックします`i != 0 and i != m-1`最初と最後のタイルは削除できないため、タイルを削除するときに使用します。 2 つのネストされたループ`i`そして`j`効率的であるため、`k <= 30`。 使用する`float('inf')`初期値として使用すると、取得時の微妙な off-by-one エラーが回避されます。`min`。
