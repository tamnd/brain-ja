 ## 解決策
 ## 問題の理解

 私たちは、移動と高速移動タワーという 2 つの相互作用するメカニズムを備えた 2D グリッド ゲームで、ウィリアムが完了できるクエストの数を最大化するように求められます。 ゲーム世界のサイズは無限ですが、ウィリアムの動きは、1 ターンにつき 1 ユニットずつ、上下左右の直交移動に制限されます。 彼はその場で待つこともできます。 クエストは特定の座標で正確なターンでのみ完了可能であり、ファストトラベルタワーは瞬間移動を許可する前にその座標を訪問してアクティブ化する必要があります。 

入力により座標が与えられます。`n`塔と`m`必要なターンのクエスト。 出力は、移動およびファストトラベルルールの下で完了できるクエストの最大数です。 

制約はアプローチを決定する上で非常に重要です。 塔の数`n`この小さな上限は、あらゆる解が指数関数的であることを示唆しています。`n`許容されます。 クエストの数`m`は最大 100 であるため、一連のクエストをすべて直接列挙するとコストがかかりすぎる可能性があります。 クエスト時間は 10^9 に達する可能性があるため、毎ターンをシミュレートしようとするアプローチが妨げられます。 座標は最大 10^6 に達し、密な 2D グリッド表現は除外されます。 

明らかではないエッジケースには、最初のクエストがどのタワーからも非常に遠い状況が含まれます。 利用可能な最も近いクエストに常に移動するなど、単純で貪欲なアプローチは失敗する可能性があります。 For example, if a quest at`(1000,1000)`ターン 1 で発生すると到達できないため、アルゴリズムは近接性だけでなく、クエストの正確なタイミングを尊重する必要があります。 

タワーのアクティブ化では、別の微妙なケースが発生します。 クエストがタワーの近くにあるが、タワーがまだアクティブ化されていない場合、ファストトラベルを使用してタワーに到達しようとすると、何も表示されずに失敗します。 同様に、クエストの正確な時間を守るために、ある場所で待機することが必要になる場合があります。 

## アプローチ

 ブルートフォースアプローチでは、クエスト完了のすべてのシーケンスとタワーのアクティブ化のすべての順序が考慮されます。 各クエストについて、アクティブ化されたタワーが与えられた場合に到達可能かどうかをシミュレートします。 これは、各クエストとタワーを独立して考慮できるため、原理的には機能しますが、実際には複雑すぎます。 と`m = 100`、すべての順列はおよそ 100! ですが、これはまったく実行不可能です。 クエストのサブセットに限定しても、依然として指数関数的な爆発につながります。`m`。 

重要な観察は次のとおりです`n`小さいです。 各タワーはアクティブ化することも、アクティブ化しないこともできます。`2^14 = 16384`タワーのアクティブ化の可能な状態。 これは、タワーのサブセットに対する動的プログラミング ソリューションを示唆しています。 

次に、タワーのサブセットがアクティブ化されると、ウィリアムは、おそらくテレポートを使用して、マンハッタンの距離を経由して任意のセルに到達できることに注目してください。 タワー間、およびタワーとクエスト間の最小移動時間を事前に計算できます。 この問題は、タワー上のサブセットベースの DP での移動時間を伴うクエストのスケジュール設定の変形に帰着します。 

最適なアプローチは、アクティブ化されたタワーのサブセットが追跡される DP 状態を維持することであり、そのような状態ごとに、特定の時間までに完了できるクエストの最大数を保存します。 移行には、タワー間を直接移動するか、最初のスポーンからタワーに移動するか、最後に訪れたタワーからクエストの場所に移動することが含まれます。 なぜなら`n`が小さい場合、サブセット DP は実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m!) | O(m) | 遅すぎる |
 | タワーサブセット + クエスト上の DP | O(2^n * n * m) | O(2^n * m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各タワーとクエストを座標で表します。 クエスト時間を個別に保存します。 
2. すべてのタワー間のマンハッタン距離と、スポーン位置から各タワーまでのマンハッタン距離を事前計算します。 
3. DP テーブルを定義する`dp[mask][q]`どこ`mask`アクティブ化されたタワーのビットマスクです。`q`クエストのインデックスを作成します。 この値には、ウィリアムが最後のクエストに到達できる最も早いターンが格納されます。`q`塔が入っている状態で`mask`活性化された。 
4. スポーン地点から開始して最初のタワーに移動する場合のDPを初期化します。 ウィリアムはどこにでもスポーンできるため、各タワーの最も早い到着は、任意のスポーンからそのタワーまでのマンハッタン距離にすぎません。 
5. DP 状態を繰り返し処理します。 アクティブ化されたタワーのサブセットごとに`mask`、新しいタワーの追加を検討してください`t`。 The earliest time to reach`t`以前にアクティブ化されたすべてのタワーの最小値です`p`そこからの距離を加えたもの`p`に`t`。 アップデート`dp[new_mask][q]`それに応じて。 
6. 各 DP 状態について、その場所への最も早い到着時刻とクエストの所要時間を比較することにより、どのクエストを完了できるかを確認します。 クエストに正確に到達できる場合`t_i`、そのパスのカウントをインクリメントします。 
7. すべての DP 状態にわたってクエストの最大数を維持します。 この番号を返します。 

これが機能する理由は、DP がタワーの到達可能なすべての構成を追跡し、各構成について、実行可能なすべてのクエストの完了が考慮されるためです。 タワーのサブセットの数が少ないため、潜在的な最適なシーケンスを見逃すことなく、タワーのアクティブ化に関係するすべての可能なパスを評価できます。 これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from itertools import combinations

def manhattan(a, b):
    return abs(a[0]-b[0]) + abs(a[1]-b[1])

def solve():
    n, m = map(int, input().split())
    towers = [tuple(map(int, input().split())) for _ in range(n)]
    quests = [tuple(map(int, input().split())) for _ in range(m)]

    # dp[mask][last] = earliest time to have activated towers in mask ending at last tower
    INF = 10**18
    dp = [ [INF]*n for _ in range(1<<n) ]

    for i in range(n):
        dp[1<<i][i] = 0  # Spawn anywhere

    # fill DP
    for mask in range(1<<n):
        for u in range(n):
            if not (mask & (1<<u)):
                continue
            for v in range(n):
                if mask & (1<<v):
                    continue
                new_mask = mask | (1<<v)
                dp[new_mask][v] = min(dp[new_mask][v], dp[mask][u] + manhattan(towers[u], towers[v]))

    # check max quests
    max_q = 0
    # check starting from arbitrary spawn without any tower
    for spawn in [(0,0)]:  # Arbitrary, we can always spawn at nearest quest
        for qmask in range(1<<n):
            times = []
            for i in range(n):
                if not (qmask & (1<<i)):
                    continue
                times.append(dp[qmask][i])
            for xb, yb, t in quests:
                best = min([time + manhattan(towers[i], (xb,yb)) for i, time in enumerate(times)] + [manhattan(spawn, (xb,yb))])
                if best <= t:
                    max_q += 1

    print(max_q)

solve()
```このコードは、マンハッタンの距離を使用して移動をモデル化し、タワーのサブセット上の DP を構築します。 私たちは、タワーのサブセットが与えられたときにクエストに到達できるかどうかを評価することによってクエストを処理します。 微妙なのは、最初のスポーンの処理です。これは、最初の移動時間を最小限に抑えるために任意に選択できます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^n * n^2 + 2^n * n * m) | 2^n 個のサブセット、各サブセット n^2 個のタワー遷移について、サブセットごとに m 個のクエストを評価します。 
| スペース | O(2^n * n) | DP テーブルには、各タワー サブセットの最も早い到着時刻が格納されます。 

と`n ≤ 14`, 2^n ≈ 16,384、これは管理可能です。 n^2 と m = 100 を乗算すると、10^7 未満の演算が行われ、2 秒の制限に適合します。
