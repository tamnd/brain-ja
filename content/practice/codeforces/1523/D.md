 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、`n`友達、それぞれが自分の好みを持っています`m`通貨。 各友達はせいぜい好きです`p`通貨が多いため、いいねリストはまばらです。 目標は、友人の少なくとも半数がそのセット内のすべての通貨を好むような最大の通貨セットを見つけることです。 言い換えれば、大多数の友人が各通貨に同意する最大サイズの通貨セットが必要です。 

入力はサイズの行列です`n x m`ただし、各行には最大でも`p`もの。`n`まで可能です`2*10^5`つまり、すべての友達を複数回繰り返すことは、友達ごとの操作が非常に高速な場合にのみ実現可能です。`m`最大でも 60 ですが、これは通貨に対するビットマスク操作を許可するのに十分な大きさです。`p`は最大でも 15 です。つまり、`m`は最大 60 で、各行は非常にまばらであり、そのまばらさが効率の鍵となります。 

すべてを列挙する素朴なアプローチ`2^m`考えられる通貨のサブセットは直ちに不可能です。`2^60`天文学的に大きいです。 同様に、友人ごとにすべてのサブセットをテストしようとするアプローチは、遅すぎるでしょう。 明らかではないエッジケースには、友人の少なくとも半数が好む通貨がない場合や、同等の最大セットが複数存在するが選択される通貨が異なる場合などがあります。 

たとえば、3 人の友人と 4 つの通貨について考えてみましょう。```
3 4 3
1000
0110
1001
```友達の半分は切り上げられ、2 になります。最初の通貨だけが 2 人の友達に好かれているため、答えにはそれが含まれている必要があります。 通貨ごとにカウントするだけの単純なアプローチでは、複数の通貨が一緒に過半数条件を満たす場合、組み合わせを見逃す可能性があります。 

## アプローチ

 ブルートフォース手法では、通貨のすべてのサブセットを反復処理し、友人の少なくとも半数がサブセット内のすべての通貨を気に入っているかどうかをそれぞれチェックします。 のために`m = 60`、 がある`2^60`サブセット、つまりおおよそ`10^18`操作、完全に実行不可能。 

重要な洞察は、各友達は最大でも好きなものを持っているということです`p`通貨。 この疎性は、大きな交差点の「候補」通貨の世界が、少数の選ばれた友人が好む通貨から抽出される可能性が高いことを意味します。 特に、大多数が好む通貨の最大セットは、少なくとも 1 人の友人が好む通貨のサブセットでなければなりません。 それ以外の場合は、友人が気に入った通貨を追加して交差サイズを増やすこともできます。 

最適なアプローチでは、友人のランダム サンプリングとビットマスク交差を組み合わせて使用​​します。 私たちはランダムに友人を選び、その友人が好む通貨のみを候補として検討することを繰り返します。 候補のサブセットごとに、ビットマスキングを使用して、そのサブセット内のすべての通貨を好む友人の数を数えます。 なぜなら`p`すべて列挙すると小さいです`2^p`彼らが好む通貨のサブセットは実現可能です (`2^15`は 32768、管理可能です)。 ランダムサンプリングを数回繰り返すことにより、全体的に最大のサブセットを見逃す確率は非常に低くなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 2^m) | O(n*m) | 遅すぎる |
 | 最適 (ランダム サンプリング + ビットマスク DP) | O(T * n * 2^p) | O(2^p) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各友達のいいねリストをビットマスクに変換します。 友人が通貨 j を好む場合、j 番目のビットが設定されます。 これにより、ビットごとの AND による高速なセット操作と、ビットマスク反復によるサブセット列挙が可能になります。 
2. 次のプロセスを複数回繰り返します (たとえば、速度と成功確率のバランスをとるために 30 回繰り返します)。 

1. 友達をランダムに選ぶ`f`。 させて`mask_f`好きな通貨のビットマスクになります。 
2. すべてのサブセットを列挙します。`mask_f`。 多くてもあります`2^p`サブセット。 各サブセットは、最大交差の潜在的な候補を表します。 
3. サブセットごとに、このサブセットが含まれる友人のビットマスクの数を数えます (つまり、`(friend_mask & subset) == subset`）。 
4. カウントが少なくとも`ceil(n / 2)`、このサブセットが現在の最良のものより大きいかどうかを確認します。 「はい」の場合は保管してください。 
3. すべての反復の後、最適なサブセットを長さのバイナリ文字列として出力します。`m`。 

機能する理由: 最大のサブセットは、友人が好む通貨のセットに含まれている必要があります。 ランダムな友人のサブセットを列挙することにより、すべての最大の候補を確率的にカバーします。 ビットマスキングを使用すると、サブセットごとおよびフレンドごとの操作が高速に保たれます。 

## Python ソリューション```python
import sys, random
input = sys.stdin.readline

def solve():
    n, m, p = map(int, input().split())
    friends = []
    for _ in range(n):
        line = input().strip()
        mask = 0
        for j in range(m):
            if line[j] == '1':
                mask |= 1 << j
        friends.append(mask)

    half = (n + 1) // 2
    best_mask = 0
    best_count = 0

    for _ in range(30):  # random trials
        f = friends[random.randint(0, n - 1)]
        positions = [j for j in range(m) if (f >> j) & 1]
        k = len(positions)
        count_dp = {}

        for subset in range(1 << k):
            mask = 0
            for i in range(k):
                if (subset >> i) & 1:
                    mask |= 1 << positions[i]
            count_dp[mask] = 0

        for friend_mask in friends:
            for mask in count_dp:
                if (friend_mask & mask) == mask:
                    count_dp[mask] += 1

        for mask, cnt in count_dp.items():
            if cnt >= half:
                bit_count = bin(mask).count('1')
                if bit_count > best_count:
                    best_count = bit_count
                    best_mask = mask

    result = ['0'] * m
    for j in range(m):
        if (best_mask >> j) & 1:
            result[j] = '1'
    print(''.join(result))

solve()
```このコードは友人の設定をビットマスクに変換し、複数のランダムなトライアルを実行します。 各トライアルでは、サンプリングされた友人が気に入った通貨のすべてのサブセットを列挙し、各サブセットを気に入った友人の数を数えます。 最後に、少なくとも半数の友人が好む通貨の最大数を含むサブセットを出力します。 

微妙な点には、ビット演算によるサブセットの正確なカウント、処理が含まれます。`ceil(n/2)`正しく反復して`2^p`効率的にサブセットを作成します。

## テストケース```python
import sys, io
def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    solve()
    return sys.stdout.getvalue().strip()

# Provided samples
assert run("3 4 3\n1000\n0110\n1001\n") == "1000", "sample 1"

# Custom cases
assert run("1 1 1\n1\n") == "1", "single friend/currency"
assert run("2 3 2\n110\n101\n") in ["100","101"], "two friends, overlapping"
