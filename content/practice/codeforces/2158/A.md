 ## 解決策
 ## 問題の理解

 私たちには、決まった人数の選手によるサッカーの試合が与えられ、イエローカードとレッドカードの形で一連の懲戒処分が与えられます。 各イエローカードは潜在的な出場停止に影響し、各レッドカードはプレーヤーを即座に出場停止にします。 プレーヤーは 2 つの異なる方法で出場停止になる可能性があります。1 つは直接レッドカードを受け取るか、2 枚のイエロー カードを累積するかのいずれかです。 

重要な制限は、プレーヤーが一時停止されると、そのプレーヤーはゲームに参加しなくなるため、そのプレーヤーに送られるはずだったカードは無効になるということです。 私たちは、時間の経過に伴う実際のカードの配分をシミュレートすることを求められているのではなく、代わりに、イエローカードとレッドカードの合計数を考慮して、最終的に出場停止になる可能性のある個別のプレーヤーの最大数を決定するように求められています。 

したがって、最も有利な方法でカードを配布すると仮定した場合、各テスト ケースの出力は、ゲームから退場させることができるプレイヤーの最大数になります。 

制約は小さく、テストあたりのプレイヤー数は最大 100 人、テスト ケースは最大 500 です。 これは、直接推論またはテスト ケースごとの定数時間式でも十分であることを直ちに示唆しています。 n の二次関数であっても問題なく通過しますが、問題の構造は、シミュレーションではなく閉形式の貪欲な割り当てを求めていることを強く示唆しています。 

イエローカードは豊富だがレッドカードが少ない場合、微妙なエッジケースが発生する。 たとえば、黄色が多く赤が少ない場合、黄色をペアにグループ化して「無駄」にするか、プレーヤー全体に分配するかを決定する必要があります。 もう 1 つの特殊なケースは、各レッドが最大 1 つの出場停止に対応するため、レッドだけですでにプレイヤーの数を超えている場合です。 

単純な間違いは、イエローカードを個別に扱い、それぞれのイエローを出場停止の可能性があるものとしてカウントすることです。 1 回の出場停止には 2 枚のイエローが必要であり、ペアで受け取るのに十分なプレーヤーが残っていない場合、残った 1 枚のイエローは使用できない可能性があるため、これは失敗します。 

## アプローチ

 ブルートフォース解釈では、イエローカードとレッドカードのそれぞれを個々のプレーヤーに割り当てるシミュレーションを試み、考えられるすべての割り当てを分岐させます。 各カードはまだアクティブなプレーヤーに与えることができ、プレーヤーが出場停止になるかどうかはそれぞれの割り当てによって変わる可能性があります。 これはすぐに爆発につながります。最大 2n 枚のカードのそれぞれに最大 n 個の選択肢があり、検索スペースは n^(2n) のオーダーになりますが、これは n = 100 の場合でもまったく実行不可能です。 

重要な観察は、実際にはプレイヤーの身元は気にしておらず、どれだけの出場停止を作成できるかだけを気にしているということです。 各レッドカードは独立して最大 1 人の出場停止選手を作成でき、イエロー カードの各ペアも 1 人の出場停止選手を作成できます。 プレイヤーはキャパシティの点で区別できないため（各プレイヤーを一時停止できるのは 1 回だけ）、問題は、利用可能なリソースからいくつのばらばらの「サスペンション ユニット」を形成できるかを数えることに帰着します。 

それぞれのレッドカードはすでに完全なユニットです。 イエローカードの場合、イエロー 2 枚ごとに 1 つのユニットが形成されます。 したがって、黄色ベースのサスペンションの数は、floor(y / 2) によって制限されます。 赤と黄の間の唯一の関係は、出場停止選手の合計が n 人を超えてはいけないということです。 

したがって、答えは、プレーヤーの数 n、レッド カードの数 r、および可能なサスペンション ユニットの総数 r + フロア(y / 2) の 3 つの数量の最小値です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース割り当て | O(n^(2n)) | O(n) | 遅すぎる |
 | 貪欲に数える | テストごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 直接カウント戦略を使用して、各テスト ケースの答えを計算します。

1. レッドカードだけで何人の選手が出場停止になる可能性があるかを計算します。 それぞれのレッドカードは個別のプレーヤーを出場停止にするため、これが出場停止の可能性をもたらします。 
2. イエローカードから何回の出場停止が可能かを計算します。 サスペンションごとに 2 つのイエローが必要なので、floor(y / 2) を取得します。 これにより、完全なイエローベースのサスペンションの数が得られます。 
3. これら 2 つのソースを合計して、プレイヤーの制限を考慮せずに「利用可能な一時停止スロット」の合計数を取得します。 
4. 出場停止にできるプレーヤーは合計で n 人だけであるため、結果を n で制限します。 
5. 最終値を出力します。 

重要な推論ステップは、レッドカードによる出場停止とイエローペアによる出場停止は、選手の独立した「消費」源であるということです。 それぞれが 1 人のプレーヤーを使用し、どのプレーヤーも 2 回カウントすることはできません。 

### なぜ効果があるのか

 最適な配置であれば、すべての出場停止は、正確に 1 人のプレーヤーにレッドカードまたは少なくとも 2 枚のイエローカードのいずれかが割り当てられることに対応します。 レッドカードは分割できず、イエローカードはペアでのみ重要であるため、私たちができる最善のことは、n人のプレーヤーが利用可能であることのみを条件として、形成できるサイズ1（レッド）または2（イエローのペア）の素グループの数を最大化することです。 r + Floor(y/2) を超えて合計サスペンションを増加させる相互作用はなく、n を超える再配置はできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    y, r = map(int, input().split())

    yellow_susp = y // 2
    ans = r + yellow_susp
    print(min(n, ans))
```実装は派生した式に直接に従います。 整数除算を使用して完全な黄色のペアが何組存在するかを計算し、次に赤色のカードの数を追加します。 最後に、利用可能なプレーヤーの数を尊重するために n でクランプします。 

唯一の微妙な点は、ペアがなければ、残った単一のイエローは出場停止に寄与できないため、イエローカードには整数の除算が使用されるようにすることです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        y, r = map(int, input().split())
        out.append(str(min(n, r + y // 2)))
    return "\n".join(out) + "\n"

 ## 特殊なケース

 主なエッジケースは、イエローが豊富にあるにもかかわらず、プレーヤーの制限によりすべてをサスペンションに組み込むことができない場合です。 たとえば、n = 4、y = 10、r = 0。アルゴリズムは y // 2 = 5 を計算しますが、r + y // 2 = 5 は n を超えます。 プレーヤーは 4 人しかいないため、最終的な正解は 4 になります。 グローバルキャップを認識せずにプレイヤーごとにイエローを貪欲に割り当てようとすると、誤ってオーバーカウントされてしまいます。 

もう 1 つのエッジ ケースは、赤がすでに n を超えている場合です。 n = 3、r = 5、y = 0 の場合、レッドから 5 つの出場停止を計算しますが、プレーヤーは 3 人しか存在しないため、答えは 3 になります。式は min(n, ...) を介してこれを正しく処理し、無効な過剰割り当てを防ぎます。 

最後の微妙なケースは、黄色の数が奇数である場合です。 n = 6、y = 5、r = 0 の場合、y // 2 = 2 が得られます。残った 1 つの黄色は使用できず、答えは 2 です。これは、1 つの黄色はペアになっていないままにしておく必要があり、単独でサスペンションを形成できないという事実と一致します。
