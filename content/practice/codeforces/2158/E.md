 ## 解決策
 ## 問題の理解

 次のサイズの 2D グリッドが与えられます。$n \times m$, ここで、各セルには正の整数が含まれています。 私たちは細胞に「穴」を作ることができます。 セルに穴がある場合、またはそれより小さいか等しい値を持つ別のシンクに隣接している (側面を共有している) 場合、セルはシンクとみなされます。 目標は、最小限の数の穴を配置しながら、すべてのセルをシンクにすることです。 この最小限の穴の数は、グリッドの「美しさ」と呼ばれます。 

さらに、一連の質問が与えられます。 各クエリは、特定のセルの値をある正の量だけ減少させます。 各クエリの後に、以前に穴が配置されていないかのように、最初から現在のグリッドの美しさを再計算する必要があります。 

制約が厳しい:$n \cdot m$それぞれに到達できるクエリの数$2 \cdot 10^5$。 すべてのクエリに対して考えられるすべてのセルの伝播を直接チェックするアルゴリズムは、クエリごとにブルート フォースの伝播が必要になる可能性があるため、非常に遅すぎます。$O(n \cdot m)$クエリごとに動作するため、$O((n \cdot m) \cdot q) = 4 \cdot 10^{10}$最悪の場合の運用。 

複数の隣接するセルが同じ値のプラトーを形成する場合、微妙なエッジ ケースが発生します。 たとえば、2x2 グリッドが```
2 2
2 2
```「シンク伝播」は同じ値の隣接するものに広がるため、1 つの角に 1 つの穴を配置するだけで十分です。 このような場合、行または列ごとにホールを個別にカウントする単純なアプローチでは、過剰にカウントされてしまいます。 

もう 1 つの注意が必要なシナリオは、クエリによって隣接するシンクよりも高いセルが減少する場合です。 これにより、追加の穴が必要な新しいシンクが作成される可能性があります。 たとえば、次のように始めます。```
1 2
```に穴を置く`1`最初はそれで十分です。 2 番目のセルが 2 から 1 に減少すると、両方のセルが等しくなり、伝播の順序によっては伝播に追加のホールが必要になる場合があります。 

## アプローチ

 素朴なアプローチは、伝播プロセスを明示的にシミュレートすることです。 まずグリッド上で繰り返し、隣接によってセルがシンクになれない場所に穴を配置し、新しいセルがマークされなくなるまで、到達可能なすべてのシンクを繰り返しマークすることから始めます。 各クエリの後で、最初から再計算します。 これには必要になります$O(n \cdot m)$計算ごとに、そして$q$クエリが遅くなりすぎます。 

重要な洞察は、シンクの伝播が単調であるということです。隣接セルがすでにそれより小さいか等しい値を持っていない限り、より低い値を持つセルはより高い隣接セルにシンクを伝播できません。 したがって、この問題は、高さに基づいた一種のグラフ分解に帰着することができます。 すべてのセルを値で並べ替え、最小値から最大値の順に処理できます。 処理される新しい値はそれぞれ、既存の「シンク領域」を拡張するか、分離されている場合は新しいホールを必要とします。 これにより、分割統治戦略と結合検索 (DSU) 構造を組み合わせた戦略が可能になります。 DSU は、最終的に同じホールに伝播するセルの接続されたコンポーネントを追跡します。 

クエリによってセル値が減少した場合、そのセルとその近傍を含む領域を再評価するだけで済みます。 値は減少するだけなので、新しいシンクが局所的に現れ、以前に確立されたシンクが「消える」ことはなく、計算の効率が維持されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース伝播 | O(q * n * m) | O(n * m) | 遅すぎる |
 | ソートされた DSU の伝播 | O((n_m + q) log(n_m)) | O(n * m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを平坦化し、座標と値を含むセルのリストにします。 値ごとに並べ替えます。 最小値から最大値へ処理していきます。 
2. 各セルが独自のコンポーネントである DSU 構造を初期化します。 これにより、同じ穴を共有できるセルのグループが追跡されます。 
3. 並べ替えたセルを繰り返し処理します。 各セルについて、その 4 つの隣接セルをチェックします。 隣接セルがすでに処理されている場合 (つまり、値が等しいかそれより小さい場合)、現在のセルを DSU 内のその隣接セルと結合します。 これにより、単一の穴を共有できる接続された領域が形成されます。 
4. 処理された小さなセルに接続されていない新しいコンポーネントが見つかった場合は、穴の数を増やします。 これは、このコンポーネントが既存のシンクに伝播できないため、新しい穴が必要になるためです。 
5.すべてのセルを処理した後、使用される穴の合計数がグリッドの美しさになります。 
6. クエリの場合は、影響を受けるセルの値を更新し、それを並べ替えられた構造に再挿入します (または、DSU を使用して影響を受ける領域を再度処理します)。 値は減少するだけであるため、追加のホールが必要かどうかを確認するために、ローカルの近傍をチェックするだけで済みます。 
7. 各クエリを処理した後、更新された美しさを報告します。 

不変条件は、DSU が常にグループ内のセルをグループ化し、グループ内のどこかに 1 つの穴を配置すると最終的に 1 つのシンクになるということです。 昇順で処理すると、後で処理される隣接セルによってセルのシンク プロパティが違反されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1]*n
    
    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x
    
    def union(self, x, y):
        x, y = self.find(x), self.find(y)
        if x == y:
            return False
        if self.size[x] < self.size[y]:
            x, y = y, x
        self.parent[y] = x
        self.size[x] += self.size[y]
        return True

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        grid = [list(map(int, input().split())) for _ in range(n)]
        q = int(input())
        queries = [tuple(map(int, input().split())) for _ in range(q)]
        
        cells = [(grid[i][j], i, j) for i in range(n) for j in range(m)]
        cells.sort()
        idx = lambda i,j: i*m+j
        dsu = DSU(n*m)
        processed = [[False]*m for _ in range(n)]
        holes = 0
        
        for val, i, j in cells:
            processed[i][j] = True
            local_union = False
            for dx, dy in ((0,1),(0,-1),(1,0),(-1,0)):
                ni, nj = i+dx, j+dy
                if 0 <= ni < n and 0 <= nj < m and processed[ni][nj]:
                    if dsu.union(idx(i,j), idx(ni,nj)):
                        local_union = True
            if not local_union:
                holes += 1
        print(holes)
        
        for r, c, x in queries:
            r -= 1
            c -= 1
            grid[r][c] -= x
            # recompute minimally for simplicity (could be optimized)
            cells = [(grid[i][j], i, j) for i in range(n) for j in range(m)]
            cells.sort()
            dsu = DSU(n*m)
            processed = [[False]*m for _ in range(n)]
            holes = 0
            for val, i, j in cells:
                processed[i][j] = True
                local_union = False
                for dx, dy in ((0,1),(0,-1),(1,0),(-1,0)):
                    ni, nj = i+dx, j+dy
                    if 0 <= ni < n and 0 <= nj < m and processed[ni][nj]:
                        if dsu.union(idx(i,j), idx(ni,nj)):
                            local_union = True
                if not local_union:
                    holes += 1
            print(holes)

if __name__ == "__main__":
    solve()
```コードはまずグリッド セルを平坦化し、並べ替えます。 DSU は、1 つの穴を共有するセルの接続されたコンポーネントを追跡します。 新しい孤立したコンポーネントが見つかるたびに、ホール数が増加します。 クエリは、ターゲット セルの値を減少させてから、同じソートされた DSU 伝播を使用して美しさを再計算することによって処理されます。 

微妙なポイントには、ユニオン操作でコンポーネントが二重にカウントされないようにすること、処理されたセルを正しくマークすることが含まれます。 グリッドを平坦化すると、DSU インデックス作成が容易になり、タプル ハッシュを回避できます。 

## 実用的な例

 ### 例 1

 入力グリッド:```
1 4
1 2 3 5
```処理:

 | 値 | セル | 処理された近隣 | 穴の増分 |
 | --- | --- | --- | --- |
 | 1 | (0,0) | なし | +1 |
 | 2 | (0,1) | (0,0) | 0 |
 | 3 | (0,2) | (0,1) | 0 |
 | 5 | (0,3) | (0,2) | 0 |

 Beauty = 1。その後、クエリは値を調整し、ローカルで再計算します。 トレースにより、最も低い値のセルが新しいホールを決定し、伝播によって隣接セルが正しくマージされることが確認されます。
