 ## 解決策
 ## 問題の理解

 長さのシーケンスを構築するように求められます$n$ここで、各要素は大きな正の整数であり、目標は、連続する要素間の最大公約数の構造を制御することです。 

隣接するペアごとに$(a_i, a_{i+1})$、計算します$\gcd(a_i, a_{i+1})$。 アレイ全体にわたって、これらは$n-1$値はすべて異なるものである必要があります。 同時に、すべての有効な構造の中で、シーケンス自体に現れる異なる値の数を最小限に抑えたいと考えています。 

したがって、問題は隣接する GCD を一意にすることだけでなく、配列値を積極的に再利用して個別の数値のセットを小さく保つことにもあります。 

制約は小さい$n$(最大 700) ですが、値自体は最大 700 まで非常に大きくなる可能性があります。$10^{18}$。 これは、構築が値に対する検索や動的プログラミングではなく、数理論的構造に依存する必要があることを直ちに示唆しています。 

単純な試みでは、隣接する 2 つの GCD が衝突した場合に、任意の番号を割り当てて競合を修正しようとします。 このアプローチは失敗します。GCD 制約がグローバルであるためです。1 つの要素を変更すると、隣接する 2 つのエッジに同時に影響があり、衝突が予測不能に伝播します。 

より微妙な失敗例は、次のような小さなセットからランダムな割り当てを試みたときに発生します。$\{1, 2, 3\}$。 たとえば、$n = 5$、次のような交互の値を選択します。$[1,2,1,2,1]$どこでも隣接する GCD が 1 に等しくなりますが、これは直ちに要件に違反します。 これは、可分性構造を制御せずに個別の値の数を単に減らすだけでは不十分であることを示しています。 

重要な問題は、各エッジが、慎重に選択された可分性チェーンを通じてエッジをエンコードすることを示唆する、一意の gcd 署名を「保持」する必要があることです。 

## アプローチ

 ブルートフォースアプローチでは、値を段階的に割り当てて、エッジに表示される gcd のセットを維持しようとします。 各ポジションについて、次の番号を選択しようとします。$10^{18}$これにより、前の要素を使用して新しい gcd が生成されます。 これには、以前のすべてのエッジに対して割り算と gcd 条件をチェックする必要があります。 

最悪の場合、その位置で$i$、多くの候補値をスキャンし、前の要素で gcd を計算すると、簡単に次のような複雑さになります。$O(n \cdot 10^{18})$あるいはせいぜい$O(n^2 \sqrt{10^{18}})$候補者を限定すると。 これは実現可能な限界をはるかに超えています。 

重要な洞察は、視点を逆転させることです。任意の数値を通じて間接的に gcd を制御する代わりに、エッジに表示したい gcd 値を直接割り当てます。 エッジの gcd を決定したら$i$、前の構造を維持しながらそれを実現する 2 つの隣接する配列値を構築できます。 

個別の gcd を強制するきれいな方法は、各エッジに一意の整数を割り当てることです。$g_i$、そして、次のように配列値を構築します。$\gcd(a_i, a_{i+1}) = g_i$。 エッジ間の干渉を避けるために、各エッジに新鮮な素数ベースの構造、または各 gcd が固有の因子によって強制的に分離される慎重に階層化された乗算構造を使用します。 

簡単なバージョンで機能する構築は、各エッジに個別の番号を割り当て、隣接する各ペアの gcd がその番号を正確に抽出するように連続した配列要素に埋め込むことに依存しますが、共有素因数がないため以前の gcd は繰り返すことができません。 

以来$n \le 700$、最初のものは安全に使用できます$n$primes or consecutive integers with controlled co-primality, scaling them to avoid collisions and ensuring uniqueness of gcd extraction.

 標準的な構造は、各エッジを$i$新しいプライムを使用する$p_i$を定義し、次のように定義します。$$a_i = p_i \cdot p_{i+1}$$隣接する各 gcd が正確に共有素数になるように境界を調整します。 これにより、各エッジが一意のプライム交差を持つクリーンなチェーンが作成され、明確な gcd が保証されます。 

各数値は最大でも 2 つの小さな素数の積であるため、値は十分に範囲内に収まります。$10^{18}$。

 ## アルゴリズムのチュートリアル

 隣接する各 gcd が強制的に一意のプライム識別子に対応するシーケンスを構築します。 

1.最初の生成$n$素数。 各素数はエッジの一意の「署名」として機能します。 
2. アレイを構築する$a$長さの$n$ここで、各エッジが正確に 1 つの素因数を共有するように、各位置は隣接する素数を使用して定義されます。 
3. 各エッジについて$i$、それを確認してください$a_i$そして$a_{i+1}$どちらにもプライムが含まれています$p_i$、ただし、以前に使用された他の素数はそれらの間で共有されません。 
4. 具体的な構造は次のとおりです。$$a_i = p_i \cdot p_{i+1}$$のために$1 \le i < n$、エンドポイントは次のように調整されます。$$a_1 = p_1 \cdot p_2,\quad a_n = p_{n-1} \cdot p_n$$5. 構築されたシーケンスを出力します。 

各ステップでは、隣接するペアが正確に 1 つの制御された素因数で重複することが保証されるため、各 gcd は正確にその素数になります。 

### なぜ効果があるのか

 各エッジ$(a_i, a_{i+1})$ちょうど 1 つの素因数を共有します$p_{i+1}$、および他のすべての因子は、各素数が構造化されたローカル パターンで使用されるため、互いに素です。 したがって：$$\gcd(a_i, a_{i+1}) = p_{i+1}$$以来、$p_i$が異なる場合、隣接するすべての gcd は異なるものになります。 また、この構造により、各数値が最大 2 つの位置で使用され、個別の値の数が最小限に抑えられ、制御されるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXP = 5000

def sieve(n):
    is_prime = [True] * (n + 1)
    is_prime[0] = is_prime[1] = False
    primes = []
    for i in range(2, n + 1):
        if is_prime[i]:
            primes.append(i)
            for j in range(i * i, n + 1, i):
                is_prime[j] = False
    return primes

primes = sieve(6000)

t = int(input())
for _ in range(t):
    n = int(input())
    
    # take first n primes
    p = primes[:n]
    
    a = [0] * n
    
    # construct chain
    for i in range(n - 1):
        a[i] = p[i] * p[i + 1]
    
    # last element
    a[n - 1] = p[n - 2] * p[n - 1]
    
    print(*a)
```コードは、ふるいを使用して素数を生成することから始まります。これは、各エッジが一意の素数識別子に依存しているため必要です。 各テスト ケースについて、最初のテスト ケースを取得します。$n$素数を求め、隣接する各ペアに連続する素数の積を割り当てます。 これにより、重複構造がシーケンス全体にわたって一貫していることが保証されます。 

最後の要素は、前のペアとの一貫性を維持するために選択されます。 隣接する素数と正確に 1 つの素数を共有し、連鎖構造を維持します。 

実装の微妙な詳細は、隣接しないエッジ間で素数を決して再利用しないことです。これにより、意図しない gcd 衝突が防止されます。
