 # 問題の理解

 入力は、物理的次元を表す数式です。 すべてのラテン文字は基本的な次元を表し、乗算、除算、括弧は通常の方法で次元を結合します。 文字を繰り返すということは、その次元を数回掛けることを意味します。`AAA`の 3 乗を表します`A`。 

タスクは、等しい次元を組み合わせて式全体を単純化することです。 分子に現れる次元は、分母に現れる同じ次元と相殺されます。 すべてのキャンセル後、残りの分子因数と分母因数を、それぞれの側を必要な順序に従ってソートして、個別に出力する必要があります。`A, a, B, b, ... , Z, z`。 

式の長さは最大 1000 文字です。 これは線形パーサーが適切であるほど十分に小さいですが、大きな中間文字列を繰り返し展開または単純化するアプローチは除外されます。 考えられるすべての因子のペアを試すソリューションは二次関数に近づく可能性があり、文字列置換を繰り返すと、置換ごとに式の大部分が再度スキャンされる可能性があるため、さらに悪化する可能性があります。 

扱いにくい部分は、ネストと、ディメンションの位置と最終符号の違いによって発生します。 たとえば、`kg/(kg/(m/s))`、最終結果が判明する前に、内側の部門は符号を 2 回変更します。 括弧を無視して左から右への乗算と除算のみを処理するパーサーは、誤って保持します。`kg`答えの中で。 

もう 1 つのエッジケースは、完全なキャンセルです。 入力用`A/A`、正しい出力は次のとおりです。```
1
1
```不用意に実装すると、恒等次元を次のように表す代わりに、片側に空の行が出力される可能性があります。`1`。 

大文字と小文字の区別も重要です。 入力用`aA`、2 つのシンボルは異なる次元です。 正しい出力は次のとおりです。```
Aa
1
```文字を小文字のみで扱うと、文字が誤って取り消されてしまいます。 

繰り返されるディメンションは、単一の出現として扱うのではなく、カウントする必要があります。 入力用`AAA/A`、正しい出力は次のとおりです。```
AA
1
```カウントの代わりにセットを使用するソリューションでは、残りの指数が失われます。 

## アプローチ

 直接的なアプローチは、演算を評価するときに式を個々の要素のリストに変換することです。 各乗算は現在のコンテキストの符号を維持し、各除算はそれを反転します。 その後、ブルート フォース シンプリファイアを使用して、すべての分子因子をすべての分母因子と比較し、一致するペアを削除できます。 これは正しいです。キャンセルは、各次元が各側に何回出現するかによってのみ決まるからです。 ただし、最悪の場合、約 1,000 個の因数を含む式では約 100 万回の比較が必要となり、リストからの削除を繰り返すとオーバーヘッドが増加します。 

重要な観察は、すべての次元には最後の指数のみが必要であるということです。 解析後は、因子が出現した正確な場所は重要ではなくなります。 各文字を整数カウントにマッピングする辞書は、これを直接保存できます。 正のカウントは次元が分子に残ることを意味し、負のカウントは分母に残ることを意味します。 

式の構造により、再帰的な解析が自然になります。 括弧は独立した部分式を作成し、除算は単純に次の項内のすべての因子の符号を変更します。 解析中に、現在の部分がプラスに寄与するかマイナスに寄与するかを表す乗数を維持します。 文字はその乗数をカウントに加えます。 これにより、単純化全体が式の 1 回の走査に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 繰り返し比較するには遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 式を再帰的に解析し、現在のコンテキストの符号乗数を維持します。 式全体が分子で始まるため、初期乗数は正になります。 括弧で囲まれた式は、周囲の演算子から乗数を受け取ります。 
2. 文字が見つかったら、その文字のカウンターに現在の乗数を加算します。 カウンタには正味指数が格納されるため、分子と分母の個別のリストを必要とせずに、後のキャンセルが自動的に行われます。 
3. 乗算が見つかったら、同じ乗数を使用して次の項の解析を続けます。 乗算では、因数が分子に属するか分母に属するかは変わりません。 
4. 除算が見つかった場合は、次の項を反対の乗数で解析します。 除算は、次の式のすべての次元 (かっこ内のすべてを含む) の表と裏を反転します。 
5. 解析が終了したら、正のカウンターを持つ文字と負のカウンターを持つ文字を分離します。 分子に正のカウントを出力し、分母に負のカウントの絶対値を出力します。 
6. 同じ文字の大文字と小文字が隣接するカスタムのアルファベット順を使用して各辺を並べ替えます。 側面に因子がない場合は印刷します`1`。 

符号乗算器が機能する理由は、除算演算が行われるたびに、それに続く式全体の指数符号が変更されるためです。 各再帰呼び出しは周囲のすべての除算から得られる符号を受け取るため、ネストされた除算は自然に処理されます。 

機能する理由: 解析中、すべての次元のカウンタは、その次元のすべての出現によってもたらされる指数とまったく同じです。 乗算では指数符号は変更されませんが、除算では除算された式の寄与が無効になります。 括弧は、どの部分式がその符号変更を受け取るかを制御するだけです。 走査後、正の指数は残りの分子因子を表し、負の指数は残りの分母因子を表すため、生成される出力は完全に縮小された次元になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    cnt = {}

    def parse(pos, sign):
        while pos < n:
            c = s[pos]

            if c.isalpha():
                cnt[c] = cnt.get(c, 0) + sign
                pos += 1
            elif c == '(':
                pos = parse(pos + 1, sign)
            elif c == ')':
                return pos + 1
            elif c == '*':
                pos += 1
            elif c == '/':
                pos = parse(pos + 1, -sign)
            else:
                pos += 1

        return pos

    parse(0, 1)

    def sort_key(c):
        return (c.lower(), 0 if c.isupper() else 1)

    numerator = []
    denominator = []

    for c in sorted(cnt.keys(), key=sort_key):
        if cnt[c] > 0:
            numerator.extend([c] * cnt[c])
        elif cnt[c] < 0:
            denominator.extend([c] * (-cnt[c]))

    print('*'.join(numerator) if numerator else "1")
    print('*'.join(denominator) if denominator else "1")

if __name__ == "__main__":
    solve()
```辞書`cnt`中心的なデータ構造です。 すべての出現を個別に保存する代わりに、コードは等しい次元を最終指数に即座にマージします。 これにより、メモリの使用量が少なくなり、キャンセルが自動的に行われます。 

再帰関数`parse`式を見ていきます。 2 番目のパラメータは現在の符号です。 文字は、その記号を使用してカウンターを変更します。 除算演算子が呼び出す`parse`反対の符号を付けます。これは、次の部分式に を乗算するのと同じです。`-1`。 

呼び出し元は括弧内の部分全体が乗算されたか除算されたかをすでに知っているため、右括弧は呼び出し元に制御を返します。 これにより、別の式ツリーを構築する必要がなくなります。 

ASCII ではすべての大文字が小文字の前に配置されるため、並べ替えキーでは通常の ASCII 順序を使用できません。 必要な順序では 2 つのケースをグループ化するため、キーは最初に小文字の形式を比較し、次に大文字を小文字の前に配置します。 

出力構造は、各文字をその指数に従って繰り返します。 これは次のような次元を処理します。`AAA/A`記憶されているカウントはキャンセル後の残量ですので正しく動作します。 

## 実用的な例

 最初のサンプルの式は次のとおりです。`kg/(kg/(m/s))`。 

| ステップ | 現在の式部分 | サイン | カウンター |
 | --- | --- | --- | --- |
 | 1 |`kg`最初の分割の前 | +1 | k:1、g:1 |
 | 2 | 内側`kg`| -1 | k:0、g:0 |
 | 3 | 内側`m`| +1 | m:1 |
 | 4 | 内側`s`| -1 | s:-1 |

 二人`kg`ネストされた除算によって符号が 2 回変更されるため、発生はキャンセルされます。 最後のプラス要因は、`m`そして最後のマイナス要因は`s`。 

2 番目のサンプルの式は次のとおりです。`kg*a/(Fs*B)*A*Kt`。 

| ステップ | 現在の式部分 | サイン | カウンター |
 | --- | --- | --- | --- |
 | 1 |`k`、`g`、`a`| +1 | k:1、g:1、a:1 |
 | 2 |`F`、`s`、`B`| -1 | F:-1、s:-1、B:-1 |
 | 3 |`A`、`K`、`t`| +1 | A:1、K:1、t:1 |

 カスタムオーダーでソートすると分子は となります。`A*a*Kt*kg`そして分母は次のようになります`B*Fs`。 この例は、大文字と小文字を区別するシンボルが分離されたままであること、およびすべての算術演算が完了した後にのみ並べ替えが行われることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | すべての文字は解析中に 1 回処理され、並べ替えでは最大 52 個の異なる文字のみが処理されます。 
| スペース | お(1) | カウンタ辞書には、式のサイズではなく、可能なラテン文字のみが保存されます。 

1000 文字という入力制限は、1 回の再帰走査で簡単に処理できます。 このソリューションは拡張された中間式を作成しないため、ネストされた括弧が多数存在する場合でも効率的です。

 ## 特殊なケース

 のために`kg/(kg/(m/s))`、パーサーが最初に記録します`kg`正の符号を付けて、括弧で囲まれた分割された式を負の符号を付けて入力します。 その式内で、2 番目の除算が再び符号を反転します。`m/s`。 二人`kg`要因がキャンセルされる、離れる`m`分子と`s`分母で。 

のために`A/A`、 最初`A`カウンタを 1 と 2 にインクリメントします`A`それをゼロに戻します。 どちらの側にも残りの要素がないため、両方の出力ラインは次のようになります。`1`。 

のために`aA`の場合、大文字と小文字はディメンション名の一部であるため、アルゴリズムは 2 つの別々の辞書キーを保持します。 並べ替えでは、両方のキーを小文字の形式で比較し、次に大文字と小文字を比較して、次の結果が得られます。`Aa`それらをマージする代わりに。 

のために`AAA/A`、のカウンター`A`が 3 になり、その後 1 ずつ減ります。 最後の指数は 2 であるため、出力には次のものが含まれます。`A`2回。 これは、アルゴリズムが存在だけではなく多重度を保存していることを確認します。
