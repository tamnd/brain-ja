 ## 解決策
 ## 問題の理解

 私たちは、`N x N`住宅の委員会。 一部のセルには最初にグレムリンが含まれています。 すべてのセルはライトがオンになった状態で開始されるため、グレムリンはセルを通過できません。 時間の経過とともに、照明がオフになったセルの履歴が説明されます。 セルが暗くなった後も、そのセルは永久に使用可能なままになります。 グレムリンは隣り合う暗いセルの間を移動する可能性があり、外側の境界にあるセルに到達すると町から出ることができることを意味します。 

課題は、境界に接する暗いセルの接続領域に少なくとも 1 つの初期グレムリンが属する、歴史の中で最初の操作を見つけることです。 操作の前にそのようなパスがすでに存在する場合、答えは次のようになります。`0`。 

ボードサイズに達することができます`500 x 500`、つまり、最大`250000`細胞。 履歴には次の内容も含めることができます`250000`操作。 すべての操作の後にボード全体を繰り返し検索するソリューションでは、約`250000 * 250000`携帯電話の訪問、これは約`6.25 * 10^10`限界をはるかに超えています。 すべてのセルとすべての操作が少数回のみ処理されるメソッドが必要です。 

主なエッジケースは、ボードの動的な性質から生じます。 不注意な解決法を行うと、セルは複数回オフにできることを忘れてしまう可能性があります。 例えば：```
2 1 2
0 0
0 1
0 1
```グレムリンは次から始まります`(0,0)`、すでに境界上にあるので、正解は次のとおりです。`0`。 履歴イベントの処理後にのみチェックするソリューションでは、誤って返される可能性があります。`1`。 

もう 1 つの注意が必要なケースは、新しく開いたセルが、以前は別々だった 2 つの暗い領域を接続する場合です。 例えば：```
3 1 2
1 1
0 1
1 0
```最初の手術後、`(0,1)`は境界セルであり、グレムリンはそこを通って逃げることができるため、答えは次のようになります。`1`。 新しく開かれたセル自体にグレムリンが含まれているかどうかだけをチェックするソリューションでは、接続を通じて作成されたパスを見逃してしまいます。 

3 番目のよくある間違いは、斜めのセルを接続されているものとして扱うことです。 例えば：```
3 1 2
1 1
0 0
2 2
```2 つの暗いセルは互いに対角にあり、パスを形成しません。 正しい答えはそうではありません`1`斜め移動は不可能なので。 

## アプローチ

 簡単なアプローチは、プロセスを正確にシミュレートすることです。 それぞれのライトが消された後、すべてのグレムリンの位置からグラフのトラバースを実行し、暗いセルを通って境界セルに到達できるかどうかを確認できます。 これはエスケープの定義を直接テストしているため、これは正しいです。 

問題はコストです。 最悪の場合はこうなる可能性もある`250000`履歴イベント、および各幅優先検索でアクセスできる`250000`細胞。 総作業量は約`6.25 * 10^10`が遅すぎます。 

有益な観察は、グリッドにおける唯一の変更は、セルが使用可能なセルのセットに追加されることであるということです。 一度セルが暗くなると、再びブロックされることはありません。 これは、暗いセルの接続されたコンポーネントが時間の経過とともにのみマージされることを意味します。 毎回正確なパスを知る必要はなく、コンポーネントにグレムリンが含まれているかどうか、およびコンポーネントが境界に触れているかどうかだけを知る必要があります。 

素のセット共用体構造はこの動作に適合します。 各暗いセルはノードとして表されます。 セルがオフになると、セルがアクティブ化され、すでにアクティブになっているすべての隣接セルとマージされます。 各コンポーネントの親とともに、コンポーネントに少なくとも 1 つの開始グレムリンが含まれるかどうか、およびコンポーネントに境界セルが含まれるかどうかという 2 つのプロパティが保存されます。 各マージ後、結果のコンポーネントに対して両方のプロパティが true であれば、その時点でエスケープが可能です。 

ブルートフォース手法では、同じ接続された領域が繰り返し検出されます。 DSU アプローチでは、これらの領域を記憶し、新しく開いたセルの影響を受けるグラフの小さな部分のみを更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(K * N²) | O(N²) | 遅すぎる |
 | 最適 | O(N² + K * α(N²)) | O(N²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのボード位置を含む素セット共用体構造を作成します。 最初はすべてのライトが点灯しているため、すべてのセルは非アクティブです。 すべてのコンポーネントに対して 2 つのフラグを保存します。最初のグレムリンが含まれるかどうかと、境界に接触するかどうかです。 
2. DSU データ内のすべての開始グレムリン位置にマークを付けます。 開始位置が既に境界上にある場合、答えはすぐに得られます。`0`グレムリンは電気が消えるのを待たずに逃げることができるからです。 
3. 履歴を順番に処理します。 操作ごとに、指定されたセルをアクティブにします。 同じ家が歴史の早い段階で出現したためにすでにアクティブになっていた場合、新たに接続を作成する必要はありません。 
4. 新しいセルをアクティブにするときは、その 4 つの隣接セルを検査します。 すでにアクティブな隣接セルは同じ暗い領域に属しており、新しいセルのコンポーネントとマージする必要があります。 
5. 必要なすべてのマージが完了したら、新しくアクティブ化されたセルを含むコンポーネントを検査します。 グレムリンと境界セルの両方がある場合、現在の操作番号が最初に脱出できる瞬間となります。 
6. 細胞は暗くなり、成分は成長するだけなので、この状態が最初に現れたときが答えです。 後の作戦では早期に脱出の機会を作り出すことはできません。 

機能する理由: DSU は常に、現在暗いセルすべての接続されたコンポーネントを正確に表します。 格納されたグレムリン フラグは、元のグレムリンがそのコンポーネント内のすべてのセルに到達できる場合に正確に true になり、ボーダー フラグはコンポーネントが出口を提供する場合に正確に true になります。 グレムリンは、そのコンポーネントが両方の特性を持っている場合にのみ脱出できます。 各操作は暗いセルを追加するだけなので、コンポーネントが両方のプロパティを持つ最初の操作は、まさに必要な最も早い瞬間です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    size = n * n
    parent = list(range(size))
    active = [False] * size
    has_gremlin = [False] * size
    has_border = [False] * size

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        ra = find(a)
        rb = find(b)
        if ra == rb:
            return ra
        if size_rank[ra] < size_rank[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        has_gremlin[ra] |= has_gremlin[rb]
        has_border[ra] |= has_border[rb]
        if size_rank[ra] == size_rank[rb]:
            size_rank[ra] += 1
        return ra

    size_rank = [0] * size

    gremlins = []
    answer = -1

    for _ in range(m):
        x, y = map(int, input().split())
        idx = x * n + y
        gremlins.append(idx)
        has_gremlin[idx] = True
        if x == 0 or y == 0 or x == n - 1 or y == n - 1:
            answer = 0

    history = []
    for _ in range(k):
        x, y = map(int, input().split())
        history.append((x, y))

    if answer == 0:
        print(0)
        return

    directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    for step, (x, y) in enumerate(history, 1):
        idx = x * n + y

        if not active[idx]:
            active[idx] = True
            root = idx

            if x == 0 or y == 0 or x == n - 1 or y == n - 1:
                has_border[root] = True

            for dx, dy in directions:
                nx = x + dx
                ny = y + dy
                if 0 <= nx < n and 0 <= ny < n:
                    nxt = nx * n + ny
                    if active[nxt]:
                        root = union(root, nxt)

        root = find(idx)
        if has_gremlin[root] and has_border[root]:
            print(step)
            return

    print(k)

if __name__ == "__main__":
    solve()
```DSU アレイはフラット化によってインデックス付けされます。`(x, y)`の中へ`x * n + y`。 これにより、大規模な入れ子構造の保存が回避され、すべてのセルに定常的にアクセスできるようになります。 

の`active`非アクティブなセルは共用体に参加してはいけないため、配列は DSU 状態から分離されます。 親配列はすべてのセルに存在しますが、セルはアクティブ化後にのみ現在のグラフの一部になります。 

の`union`この操作では、論理 OR を使用して 2 つのコンポーネントのプロパティを結合します。 いずれかの古いコンポーネントにグレムリンがあった場合、マージされたコンポーネントにもグレムリンが存在します。 同じ理由が国境接触にも当てはまります。 操作の順序は重要です。隣接するセルをチェックする前に新しいセルをアクティブにする必要があります。アクティブにしないと、そのセルを介した接続が失われます。 

この操作中に他のすべてのコンポーネントは変更されないため、最終チェックは変更されたセルを含むコンポーネントに対してのみ実行されます。 ランクによるユニオンとパス圧縮の使用により、各 DSU 操作の時間をほぼ一定に保ちます。

 ## 特殊なケース

 最初のエッジケースは初期エスケープです。 入力では:```
2 1 2
0 0
0 1
0 1
```グレムリンは次から始まります`(0,0)`、これはすでに境界セルです。 アルゴリズムは履歴セルをアクティブにする前にこれをチェックし、次の値を返します。`0`。 

2 番目のエッジ ケースは、履歴エントリが繰り返されることです。 同じセルが複数回オフになった場合、2 回目の発生では新しい接続は作成されません。 の`active`アレイにより重複したアクティベーションが防止されるため、DSU の状態は正しいままになります。 

3 番目のエッジ ケースは、間接的に作成される接続です。 で：```
3 1 2
1 1
0 1
1 0
```最初の操作の後、セルは`(0,1)`でアクティブ化され、グレムリンに直接接続されます。`(1,1)`。 コンポーネントにはグレムリンがあり、境界に触れているため、アルゴリズムは戻ります。`1`。 

4 番目のエッジ ケースは、斜めの隣接です。 暗いセルが配置されている場合、`(0,0)`そして`(1,1)`の場合、アルゴリズムは 4 つの隣接するもののみをチェックするため、それらは別個のコンポーネントに残ります。 これは移動ルールと一致し、誤った逃走を防ぎます。
