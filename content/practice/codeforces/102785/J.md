 ## 解決策
 ## 問題の理解

 このタスクは、パターン文字列によってテキスト文字列を生成できるかどうかを判断することです。 パターンは通常の小文字とオプションの繰り返し記号で構成されます。 あ`+`after は、その文字が最初に出現した後に少なくとも 1 回出現する必要があることを意味します。`*`は、文字がゼロを含む任意の回数出現できることを意味します。 これらの記号の影響を受けるのは直前の文字のみです。 

たとえば、次のパターンです。`ab*c`説明できる`ac`、`abc`、`abbc`、 等々。 パターン`ab+c`説明できません`ac`なぜなら、`b`must appear at least once. プログラムは印刷する必要があります`Yes`テキスト全体がパターン全体で記述できる場合、および`No`さもないと。 

文字列の長さは最大でも 1000 です。二次解は、1 秒の制限に対して 100 万回の操作は小さいため快適ですが、可能なすべての繰り返しを繰り返し試行するアプローチははるかに遅くなる可能性があります。 すべてを拡張するあらゆる可能な方法を探求する直接シミュレーション。`*`または`+`大きく分岐して指数関数的な動作に近づく可能性があるため、ソリューションではすでに計算された一致する状態を記憶する必要があります。 

この問題はいくつかの点で誤解されやすくなっています。 パターンには、何も一致しない繰り返し記号を含めることができます。 入力の場合:```
a*
""
```答えは`Yes`、 なぜなら`*`ゼロコピーを許可します。 常に少なくとも 1 文字を消費する不注意な実装では、次のような出力が出力されます。`No`。 

あ`+`のように振る舞うことはできません`*`。 入力の場合:```
a+
"a"
```答えは`No`、 なぜなら`+`元のシンボルに加えて 1 つ以上の繰り返しが必要です。 両方のシンボルを同一のものとして扱うと、誤って受け入れられてしまいます。 

繰り返し記号は前の文字にのみ属します。 入力の場合:```
ab*
"abb"
```答えは`Yes`、なぜなら、`b`を繰り返します。 パターンを誤ってグループ化する実装では、繰り返しが試行される可能性があります。`ab`そして誤った結果が生成されます。 

## アプローチ

 自然な最初の試みは、パターンとテキストを一緒に再帰的に処理することです。 現在のパターン文字に修飾子がない場合、現在のテキスト文字と一致するか、失敗します。 そうなったとき`*`または`+`、再帰的検索は可能な限り繰り返しを試行し、可能な各停止位置から継続します。 

パターンのあらゆる展開が考慮されるため、このアプローチは正しいです。 問題は繰り返される状態の数です。 のようなパターン`a*a*a*a*a*`の長い文字列と照合`a`文字は、パターンとテキスト内の同じ位置に到達するさまざまな再帰パスを作成します。 最悪の場合、探索される可能性の数は指数関数的に増加し、長さ 1000 が許容する長さをはるかに超えます。 

有益な観察は、結果が 2 つの位置 (どのパターン トークンがすでに処理されているか、およびテキストの何文字が消費されているか) のみに依存するということです。 ある状態に到達した正確な履歴を記憶する必要はありません。 

パターンをトークンに変換できます。各トークンには文字とその繰り返しルールが含まれます。 次に、動的プログラミングは、最初のいくつかのトークンがテキストの最初の数文字と一致するかどうかを保存します。 トークンを処理するとき、トークンが消費できるすべてのテキスト接頭辞を計算します。 

文字が繰り返されるケースは、スキャンを実行することで最適化できます。 のために`*`、状態は、同じ位置にある以前の到達可能な状態から、または現在のテキスト文字がトークンと一致する場合は前の位置から到達可能です。 のために`+`、同じスキャンが使用されますが、状態が有効になる前にトークンは少なくとも 1 文字を消費する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合は指数関数的 | O(パターンの長さ + テキストの長さ) | 遅すぎる |
 | 動的プログラミング | O(パターンの長さ × 文字の長さ) | O(パターンの長さ × 文字の長さ) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. パターンをトークンに解析します。 各トークンには小文字と、それが通常の文字であるかどうかが格納されます。`+`繰り返し、または`*`繰り返し。 これにより、パターンの構文が一致ロジックから分離されます。 
2. 動的プログラミング配列を作成します。`dp[j]`これは、これまでに処理されたトークンが最初のトークンと正確に一致する可能性があることを意味します。`j`テキストの文字。 初期状態では、空のプレフィックスに一致するトークンは存在しないため、`dp[0]`それは本当です。 
3. 各トークンを一度に 1 つずつ処理します。 通常キャラクターの場合、位置から移動`j`に`j + 1`次のテキスト文字が同じ文字である場合のみ。 通常のトークンはちょうど 1 文字を消費します。 
4.`*`トークンを使用して、現在のプレフィックスに到達できるかどうかを維持しながら、テキストを左から右にスキャンします。 の空の使用法`*`以前に到達可能なすべての位置を有効に保ち、一致する文字により、トークンにより一致をさらに 1 位置拡張できます。 
5. のために`+`トークン、と同じ考え方を使用します`*`ただし、空の繰り返しの場合は避けてください。 トークンが有効な状態を提供できるようになる前に、最初に一致する文字が消費される必要があります。 
6. すべてのトークンが処理された後、完全なテキストの状態に到達できるかどうかを確認します。 もし`dp[len(text)]`true の場合、テキスト全体がパターンに一致します。 

機能する理由: すべてのトークンが処理された後、動的プログラミング配列は、それらのトークンによって生成されるすべてのテキスト プレフィックスを正確に表します。 移行ルールは、次のトークンが文字を消費できるあらゆる合法的な方法を列挙しており、不正な繰り返し回数は決して許可しません。 各トークンは、有効な以前の一致を既に記述している状態のみを使用して処理されるため、テキスト全体と等しいパターン全体の有効な展開が存在する場合、最終状態は正確に true になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    p = input().rstrip("\n")
    t = input().rstrip("\n")

    tokens = []
    i = 0
    while i < len(p):
        ch = p[i]
        kind = 0
        if i + 1 < len(p) and (p[i + 1] == '+' or p[i + 1] == '*'):
            kind = 1 if p[i + 1] == '+' else 2
            i += 1
        tokens.append((ch, kind))
        i += 1

    n = len(t)
    dp = [False] * (n + 1)
    dp[0] = True

    for ch, kind in tokens:
        ndp = [False] * (n + 1)

        if kind == 0:
            for j in range(n):
                if dp[j] and t[j] == ch:
                    ndp[j + 1] = True

        elif kind == 2:
            active = False
            for j in range(n + 1):
                if dp[j]:
                    active = True
                if active:
                    ndp[j] = True
                if j < n and t[j] != ch:
                    active = False

        else:
            active = False
            for j in range(n + 1):
                if dp[j]:
                    if j > 0:
                        active = True
                if active:
                    ndp[j] = True
                if j < n and t[j] != ch:
                    active = False

            for j in range(1, n + 1):
                if t[j - 1] == ch and dp[j - 1]:
                    ndp[j] = True

        dp = ndp

    print("Yes" if dp[n] else "No")

if __name__ == "__main__":
    solve()
```パーサーは、生のパターンを一連の独立したトークンに変換します。 変数`kind`通常のキャラクターと区別します。`+`、 そして`*`これにより、マッチング中に元のパターンを繰り返し確認する必要がなくなります。 

の`dp`配列はトークンごとに更新されます。 プレーン キャラクタの場合、正確に 1 つのキャラクタを消費する必要があるため、前方遷移は 1 回のみ可能です。 

のために`*`、スキャンでは`active`フラグ。 以前の状態に到達できる場合、連続するテキスト文字がトークン文字と等しい限り、トークンは 0 個以上のコピーと一致します。 フラグは別のキャラクターが出現するとすぐにリセットされます。 

のために`+`、実装により空の一致が防止されます。 追加のループは最初に必要なオカレンスを処理し、スキャンによりその後の追加のコピーが可能になります。 この区別は、この問題における最も一般的な間違いの原因です。 

配列インデックスは文字間の位置を表すため、`dp[j]`文字の前で終わるプレフィックスを指します`j`。 この規則により、空の一致を処理する際の off-by-one エラーが回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(P×T) | 各パターン トークンはテキストを 1 回スキャンします。 
| スペース | O(T) | 現在と次のテキストプレフィックス状態配列のみが保存されます。 

ここ`P`は解析されたパターン トークンの数であり、`T`テキストの長さです。 どちらも最大 1000 であるため、動的プログラミング アプローチは約 100 万の状態操作を実行し、制限内に簡単に収まります。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    p = input().rstrip("\n")
    t = input().rstrip("\n")

    tokens = []
    i = 0
    while i < len(p):
        ch = p[i]
        kind = 0
        if i + 1 < len(p) and p[i + 1] in "+*":
            kind = 1 if p[i + 1] == "+" else 2
            i += 1
        tokens.append((ch, kind))
        i += 1

    dp = [False] * (len(t) + 1)
    dp[0] = True

    for ch, kind in tokens:
        ndp = [False] * (len(t) + 1)

        if kind == 0:
            for j in range(len(t)):
                if dp[j] and t[j] == ch:
                    ndp[j + 1] = True
        elif kind == 2:
            active = False
            for j in range(len(t) + 1):
                if dp[j]:
                    active = True
                if active:
                    ndp[j] = True
                if j < len(t) and t[j] != ch:
                    active = False
        else:
            active = False
            for j in range(len(t) + 1):
                if dp[j] and j > 0:
                    active = True
                if active:
                    ndp[j] = True
                if j < len(t) and t[j] != ch:
                    active = False
            for j in range(1, len(t) + 1):
                if dp[j - 1] and t[j - 1] == ch:
                    ndp[j] = True

        dp = ndp

    return "Yes\n" if dp[len(t)] else "No\n"

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

assert run("pa*t+ern\npattern\n") == "Yes\n", "sample 1"
assert run("c*cp+p\ncpp\n") == "Yes\n", "sample 2"
assert run("b+b\nb\n") == "No\n", "plus requires repetition"
assert run("a*\n\n") == "Yes\n", "star can match empty"
assert run("a+\na\n") == "No\n", "plus cannot match zero repetitions"
assert run("a*a*a*\naaaaa\n") == "Yes\n", "many repeated tokens"
assert run("ab*\na\n") == "Yes\n", "star can consume zero copies"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`a*\n\n`|`Yes`| 一致する空のテキスト`*`|
 |`a+\na\n`|`No`| の違い`+`そして`*`|
 |`a*a*a*\naaaaa\n`|`Yes`| 複数の繰り返しトークン |

## 特殊なケース

 空の一致の場合:```
a*
```パーサーは 1 つのトークンを作成します`a*`。 初期状態`dp[0]`それは真実であり、`*`ゼロコピーの使用は合法であるため、トランジションは位置ゼロに到達可能な状態を保ちます。 最終状態は true なので、答えは次のようになります。`Yes`。 

のために`+`最小長の場合:```
a+
a
```トークン`a+`元のシンボル解釈を超えて少なくとも 1 文字を消費する必要があります。 動的プログラミングの移行では空の位置は存続できないため、テキスト文字だけでは不十分であり、答えは次のようになります。`No`。 

修飾子スコープの場合:```
ab*
a
```トークンは、`a`そして`b*`。 マッチング後`a`、2番目のトークンはゼロを消費できます`b`文字。 最終的なテキスト位置は到達可能なままであり、`Yes`。 

連続した繰り返しの処理の場合:```
a*a*a*
aaaaa
```各トークンは独立して処理されます。 最初`a*`一部のプレフィックスを消費する可能性があり、次のトークンは到達可能なすべての位置から続行され、最後のトークンが残りの有効なサフィックスを埋めます。 DP 州は 5 つの可能な分割をすべて維持します。`a`文字なので、アルゴリズムはパターンを受け入れます。
