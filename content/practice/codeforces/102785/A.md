 ## 解決策
 ## 問題の理解

 各計量では 2 つの整数が記録されます。 1 つ目は秤に置かれた同一の部品の数、2 つ目はそれらの部品の測定された総重量です。 

バッチ内のすべてのパーツが同じ整数の重みを持つ場合`x`の場合、すべてのレコードは次の条件を満たす必要があります。`wi = ai × x`。 

コントローラーは事前に正確な重量を知りません。 彼は、記録されたすべての測定値を説明する整数の重みが存在するかどうかだけをチェックします。 このような整数が少なくとも 1 つ存在する場合、欠陥の証拠はなく、バッチは受け入れられます。 すべての測定値と一致する整数の重量がない場合、そのバッチは明らかに欠陥品です。 

測定の数は最大 1000 です。関係するすべての値も十分に小さいため、単純な整数演算で十分です。 すべてのレコードを 1 回処理するアルゴリズムでも簡単に制限内に収まるため、高度な最適化は必要ありません。 

唯一の本当の困難は、「欠陥」が何を意味するのかを正しく解釈することです。 部品の実際の重量を測定しようとしているわけではありません。 必要なのは、ある整数の重みがすべての測定値を同時に説明できるかどうかを判断することだけです。 

よくある間違いは、個々の測定値の重みが整数であることだけを確認することです。 考慮する```
2
2 6
3 12
```最初の計量では、次の重量が示唆されます。`3`、2番目は重みを示唆しています`4`。 どちらも整数ですが、一致しないため、正しい出力は次のようになります。```
DEFECT
```もう 1 つの簡単な間違いは、最初の測定値から重みを選択し、それが整数であるかどうかを無視することです。```
2
2 5
4 10
```最初のレコードは、次の重みを意味します。`2.5`、重みは整数でなければならないため、これは不可能です。 両方の測定値は同じ分数値と一致していますが、正しい答えは次のとおりです。```
DEFECT
```最後のエッジケースは、測定値が 1 つだけであることです。```
1
7 35
```唯一の暗黙の重みは、`5`これは整数であるため、正しい出力は次のようになります。```
QUALITY
```コントローラーはレコードが考えられるすべての整数の重みと矛盾する場合にのみバッチを拒否するため、一貫した測定を 1 回行うだけで十分です。 

## アプローチ

 最も直接的なアプローチは、考えられるすべての整数の重みを試して、すべての測定値が次の条件を満たすかどうかを確認することです。`wi = ai × weight`。 これは正しいです。なぜなら、少なくとも 1 つの候補重みがすべてのレコードに一致する場合にバッチが受け入れられるからです。 

弱点は、いくつの候補重みをテストする必要があるかを決定することです。 この声明では、実際の重量の明示的な上限は提供されていません。 観測された最大の重みまでのすべての可能な値を考慮して入力から値を導出したとしても、アルゴリズムは 1,000 回の測定値ごとに最大 100 万回近くのチェックを実行し、最悪の場合はおよそ 10 億回の比較が行われることになります。 

重要な観察は、すべての測定値が、それが表すことができる唯一の可能な重量を直接決定するということです。 方程式を整理すると、`weight = wi / ai`。 

重みは整数であるため、測定値が有効であるためには、除算が正確である必要があります。 有効な測定はすべて、まったく同じ値を生成する必要があります。 考えられる重みを検索する代わりに、最初のレコードから暗黙の重みを計算し、残りのすべてのレコードが同じ整数を暗示しているかどうかを検証します。 

これにより、問題は測定を通じて単一の線形スキャンに軽減されます。

 | 最適 | O(k) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 測定回数を読み取ります。 
2. 最初の測定値を読み取ります。 総重量が部品数で割り切れない場合は、すぐに印刷してください。`DEFECT`なぜなら、整数の重みはこの単一のレコードさえも説明できないからです。 
3. それ以外の場合は、候補の重みを次のように計算します。`w1 // a1`。 有効な測定はすべて、正確にこの値を生成する必要があります。 
4. 残りの測定を 1 つずつ処理します。 
5. 各測定ごとに、まず次のことを確認します。`wi`で割り切れます`ai`。 そうでない場合は印刷してください`DEFECT`暗黙の重みが整数ではないため終了します。 
6. 暗黙の重みを計算する`wi // ai`。 候補重量と異なる場合は印刷`DEFECT`異なる測定には異なる部品重量が必要となるため、終了します。 
7. すべての測定値が両方のチェックに合格した場合、印刷します。`QUALITY`。 

### なぜ効果があるのか

 このアルゴリズムは、スキャン全体を通じて 1 つの不変式を維持します。 候補重みは、処理されたすべての測定値と一致する唯一の整数の重みです。 

最初の有効な測定値によって候補が一意に決定されます。 その後のすべての測定は、それと一致するか、共通の整数の重みが存在しないことを証明します。 考えられるすべての有効な解はすべての測定値を満たさなければならないため、すべての暗黙の重みが同一である場合にのみ受け入れることが必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

k = int(input())

a, w = map(int, input().split())

if w % a != 0:
    print("DEFECT")
    sys.exit()

weight = w // a

for _ in range(k - 1):
    a, w = map(int, input().split())
    if w % a != 0 or w // a != weight:
        print("DEFECT")
        sys.exit()

print("QUALITY")
```最初の測定では、唯一可能な整数の重みが確立されます。 保存する前に、コードは除算が正確であることを検証します。 これにより、分数の重みが受け入れられなくなります。 

その後の各測定では、暗黙の重みを保存された候補と比較する前に、同じ割り算チェックが実行されます。 割り切れることを確認した後でのみ整数の割り算を使用すると、誤った切り捨てが回避されます。 

プログラムは矛盾を検出するとすぐに終了します。 一貫性のない測定値が 1 つあるだけでバッチが拒否されるため、残りの入力を処理する理由はありません。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    k = int(input())
    a, w = map(int, input().split())

    if w % a != 0:
        print("DEFECT")
        return

    weight = w // a

    for _ in range(k - 1):
        a, w = map(int, input().split())
        if w % a != 0 or w // a != weight:
            print("DEFECT")
            return

    print("QUALITY")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out

# provided samples
assert run("3\n10 30\n5 15\n2 6\n") == "QUALITY", "sample 1"
assert run("2\n2 5\n4 10\n") == "DEFECT", "sample 2"

# custom cases
assert run("1\n7 35\n") == "QUALITY", "single valid measurement"
assert run("2\n2 6\n3 12\n") == "DEFECT", "different integer weights"
assert run("4\n1 9\n2 18\n3 27\n4 36\n") == "QUALITY", "all equal weight"
assert run("2\n1000 999000\n1 999\n") == "QUALITY", "boundary values"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 1 つの有効な測定値 | 品質 | 最小入力サイズ |
 | 2 つの異なる暗黙的な整数の重み | 欠陥 | 一貫性のない測定値を検出 |
 | 4 つの一貫した測定 | 品質 | 複数の一致するレコード |

 ## 特殊なケース

 すべての測定値が個別に整数の重みを与えるが、その重みが異なる場合を考えてみましょう。```
2
2 6
3 12
```アルゴリズムは候補の重みを保存します`3`最初の測定から。 2 番目の測定値は次のことを意味します。`4`、候補と一致しないため、印刷されます`DEFECT`。 これにより、単純な可分性チェックでは見逃される矛盾が検出されます。 

ここで、分数の暗黙の重みを考えてみましょう。```
2
2 5
4 10
```最初の測定では、可算性チェックに失敗します。`5 % 2 != 0`。 アルゴリズムはすぐに出力します`DEFECT`その後の記録を調べずに。 これにより、非整数の重みによってのみ説明できるバッチが正しく拒否されます。 

最後に、最小の有効な入力を検討します。```
1
7 35
```測定値は整数の重みを意味します`5`。 これに矛盾する他の記録は存在しないため、アルゴリズムはスキャンを終了して印刷します。`QUALITY`。 これは、収集された証拠がすべての可能な整数の重みと一致しない場合にのみコントローラーがバッチを拒否するという要件と一致します。
