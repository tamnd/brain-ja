 ## 解決策
 ## 問題の理解

 ゲームの隠しパラメーターは、各手ごとに追加される値です。`a`、および負けの閾値、`n`。 記憶されたすべての開始パイルサイズに対して`s`, 最初のプレイヤーが勝つか負けるかがわかります。 タスクは可能な限り最小のものを回復することです`n`、そしてそれらの可能性の中で可能な限り小さなもの`a`。 

そのターンのプレイヤーが相手に到達する最終的な動きをさせることができた場合、そのポジションは勝利したとみなされます。`n`またはそれ以上。 届いてからは`n`すぐに負けてしまいますし、限界を超えた手は決して役に立ちません。 ポジションのために`x`、合法的に有用な手は以下のポジションにのみ適用されます。`n`、そしてポジションは次のいずれかのときに正確に勝ちます。`x + a`または`2x`負けの立場です。 

すべての値は 1000 で制限されます。これは、考えられる答えを検索するには十分小さいですが、すべてのペアを試すには大きすぎます。`(n, a)`ゲーム全体の状態を何度も再構築します。 すべてのペアに対して完全な動的プログラミング テーブルを使用して直接列挙するには、およそ 3 乗の作業量が必要になりますが、Python では多すぎます。 

慎重に扱う必要がある実際的な詳細が 2 つあります。 しきい値は、記憶されているすべての開始位置よりも大きくなければなりません。そうしないと、プレイヤーが移動する前にゲームがすでに終了しているからです。 また、正確に到達する動き`n`より大きな値に到達する動きと同じように、負けています。 治療中`n`通常のプレイ可能な状態では、境界近くで答えが変わります。 

たとえば、入力の場合```
1
2 1
```可能な最小のしきい値はそうではありません`2`、開始状態はすでに終了しているためです。 答えは必ずあるはずです`n > 2`。 

もう 1 つの境界ケースは、制限を超える移動です。 のために`n = 5`、`a = 3`、位置から`2`への移動`5`すぐに負けます。 相手がその位置を受け取ることは決してないので、それは勝ち手とはみなされません。 

## アプローチ

 簡単なアプローチは、可能な限りすべてのことを試してみることです`n`そして`a`からすべての位置を計算します。`n - 1`まで`1`。 繰り返しは簡単です:

 考えられるすべての手がターミナル ゾーンに到達するか、勝ちの位置に着地した場合、その位置は負けとなります。 すべての手がより大きな山に移動するため、計算は正しいため、大きな値から下に向かって処理すると、常に既知の答えが得られます。 

問題は繰り返し作業の量です。 候補ペアは約 100 万個存在する可能性があり、完全な動的プログラミング パスにはさらに 1,000 個の位置が含まれる可能性があります。 結果として得られるスケールは、快適なスケールをはるかに超えています。 

有益な観察は、記憶された位置に必要な状態だけを知る必要があるということです。 再帰的なメモ化された評価は、位置の依存関係グラフに従います。 計算します`x + a`そして`2x`それらの状態が実際に必要な場合のみ。 状態空間全体が探索される前に、記憶された位置が間違った結果を取得するため、多くの候補はすぐに失敗します。 

検索順序も役立ちます。 しきい値を昇順に試行し、加算を昇順に試行するため、最初の有効な答えが自動的に必須の答えになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²a) | O(n) | 遅すぎる |
 | 候補のメモ化された検索 | 探索された状態に依存し、O(1000³) 最悪のケースで制限されます。 候補者あたり O(n) | プルーニング付きで受け入れられる |

 ## アルゴリズムのチュートリアル

 1. 記憶されている最大の開始パイルより大きい 1 から最大 1000 までのしきい値のテストを開始します。しきい値が小さいと、指定された位置のいずれも記述することができません。 
2. 各しきい値について、次からの追加をテストします。`1`に`n`。 より大きい値`n`と同じように動作するため不要です。`a = n`、最小の加算が優先されます。 
3. 固定ペアの場合`(n, a)`、記憶された各位置を再帰的に評価します。 再帰状態は、現在のプレーヤーが勝つかどうかを返します。 
4. ポジションを評価する場合`x`、次の場合はすぐに拒否します`x >= n`なぜなら、そのような状態は有効な入力の説明には決して現れるべきではないからです。 
5. 動いてみる`x + a`。 以下にとどまる場合にのみ役立ちます`n`そして負け状態に陥る。 
6. 動いてみる`2x`同じように。 どちらかの手が負けポジションになった場合、`x`勝っている。 どちらの動作も機能しない場合は、`x`負けています。 
7. 計算結果を記憶されているすべての答えと比較します。 最初のマッチング`(n, a)`と印刷されています。 

なぜ効果があるのか:

 パラメータの固定ペアの場合、再帰はゲームの定義に正確に従います。 最終的な移動ではないすべての移動によって石の数が増加するため、サイクルは存在せず、すべてのポジションは最終的に評価済みの状態または最終的な移動に到達します。 したがって、戻り値はそのポジションの実際のゲーム結果になります。 候補者が増えてきているので、`n`そして増加します`a`、最初に一致するペアは必要な順序を満たします。 

## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

k = int(input())
need = {}
mx = 0

for _ in range(k):
    s, w = map(int, input().split())
    need[s] = (w == 1)
    mx = max(mx, s)

if mx >= 1000:
    print("0 0")
    sys.exit()

def check(n, a):
    @lru_cache(None)
    def win(x):
        if x >= n:
            return False

        if x + a < n and not win(x + a):
            return True
        if 2 * x < n and not win(2 * x):
            return True
        return False

    for s, expected in need.items():
        if win(s) != expected:
            return False
    return True

for n in range(mx + 1, 1001):
    for a in range(1, n + 1):
        if check(n, a):
            print(n, a)
            sys.exit()

print("0 0")
```入力は、開始パイル サイズから予想される結果までのマップとして保存されます。 これにより、候補ペアを直接チェックすることができます。 

の`win`関数は候補ペアごとに個別にメモ化されます。 再帰では、記憶された状態を決定するために必要な位置のみを訪問するため、ゲーム グラフの不要な部分の再構築が回避されます。 

2 つの境界チェックは不可欠です。 トランジションは、次の値に達すると無視されます。`n`またはそれ以上の場合、その動きはすぐに負けます。 検索では、そのような位置が正常な状態として評価されることはありません。 

外側のループでは、タイブレーク ルールが適用されます。 増加中`n`が主な順序であり、増加しています`a`二次発注です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | 通常の場合は O(C * S)、最悪の場合は O(1000³) |`C`はテストされた数です`(n, a)`ペアと`S`候補者ごとの訪問州の数 |
 | スペース | O(1000) | メモ化テーブルには、候補のパイル サイズごとに最大 1 つの値が保存されます。 

特にメモ化により無関係な状態の計算が回避されるため、制限は候補検索が実行できるほど十分に小さいです。 再帰の深さとキャッシュ サイズは最大しきい値によって制限されるため、メモリ使用量はわずかにとどまります。 

## テストケース```python
import sys, io

def solve(data):
    old = sys.stdin
    sys.stdin = io.StringIO(data)
    import functools

    input = sys.stdin.readline
    k = int(input())
    need = {}
    mx = 0

    for _ in range(k):
        s, w = map(int, input().split())
        need[s] = w == 1
        mx = max(mx, s)

    if mx >= 1000:
        return "0 0"

    def check(n, a):
        @functools.lru_cache(None)
        def win(x):
            if x >= n:
                return False
            return ((x + a < n and not win(x + a)) or
                    (2 * x < n and not win(2 * x)))

        return all(win(s) == v for s, v in need.items())

    ans = "0 0"
    for n in range(mx + 1, 1001):
        for a in range(1, n + 1):
            if check(n, a):
                ans = f"{n} {a}"
                break
        if ans != "0 0":
            break

    sys.stdin = old
    return ans

assert solve("""3
1 2
2 1
3 1
4 2
""") == "5 1"

assert solve("""1
2 2
""") == "0 0"

assert solve("""1
1 1
""") == "2 1"

assert solve("""2
1 2
2 2
""") == "0 0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | サンプル 1 |`5 1`| 通常の再建ケース |
 | サンプル 2 |`0 0`| 不可能な制約 |
 |`1 / 1 1`|`2 1`| 最小閾値境界 |
 |`2 / 1 2 / 2 2`|`0 0`| 矛盾のある複数の記憶された状態 |

入力用```

```可能性はありません`n`したがって、出力は次のようになります。```

```2 番目に重要なケースは、利用可能な唯一の手がターミナルエリアに到達する場合です。 たとえば、`n = 5`そして`a = 3`、 位置`2`に達するため追加技は使用できません`5`。 アルゴリズムはその遷移を無視し、倍増の動きのみを考慮します。 これは、最後の手を打ったプレイヤーが負けるというルールと一致します。
