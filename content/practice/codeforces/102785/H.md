 # 問題の理解

 長さのシーケンスを構築する必要があります`k`各位置は、そのインデックスがシーケンス全体の中でどのくらいの頻度で現れるかを表します。 位置の値が`i`は`x`、次に番号`i`正確に発生する必要があります`x`すべての要素の中で 1 回です。 

入力によりシーケンスの長さが与えられ、次に値が必要なインデックスのリストが与えられます。 シーケンス全体を印刷する必要はなく、要求された要素のみを同じ順序で印刷する必要があります。 必要な長さの有効なシーケンスが存在しない場合は、次のように出力します。`0`。 

長さは最大でも`230`、要求されたポジションの数が達する可能性がありますが、`100000`。 これにより、多数の候補シーケンスを構築したり、クエリごとにシーケンス全体を繰り返しスキャンしたりするものはすぐに除外されます。 ほぼ直線的な時間内で 1 つの有効なシーケンスを見つけ、直接インデックスを作成してクエリに答える必要があります。 

難しいのは出力サイズではなく、自己参照条件です。 1 つの値を変更すると、いくつかの頻度カウントが変更されるため、シーケンスはローカルでは有効であるように見えても、グローバルでは失敗することがあります。 

考慮する`k = 3`。 不用意に実装すると、次のような問題が発生する可能性があります。`[1, 2, 0]`これは、有効な長さ 4 の例に似ているためです。 ただし、カウントは、ゼロが 1 回、1 が 1 回、2 が 1 回です。 必要な値は次のとおりです。`[1, 1, 1]`, したがって、候補は無効です。 

もう 1 つのよくある間違いは、すべての長さに解決策があると仮定することです。 のために`k = 1`、可能なシーケンスは次のとおりです。`[0]`そして`[1]`。 で`[0]`、ゼロは 1 回出現しますが、インデックス 0 の値はゼロです。 で`[1]`、ゼロは 0 回現れますが、インデックス 0 の値は 1 です。 正しい出力は次のとおりです`0`。 

長さが短い場合は特別な取り扱いが必要です。 一般的な構造は、必要な非ゼロ周波数を個別のインデックスに配置するのに十分な余地がある場合にのみ機能し始めます。 

# アプローチ

 直接的なブルート フォース ソリューションでは、すべての値に対して可能な値が試行されます。`k`を配置し、結果のシーケンスがそれ自体を記述しているかどうかを確認します。 各要素は潜在的に間にある可能性があるため、`0`そして`k - 1`、この検索スペースは膨大です。 枝刈りを行っても、最悪の場合は指数関数的に成長し、枝刈りが不可能になります。`k = 230`。 

すべての値の合計を見ると、有益な観察が得られます。 シーケンスには以下が含まれます`k`これらの数値は出現回数であるため、合計は正確に次のとおりである必要があります。`k`。 

させて`z`シーケンス内のゼロの数になります。 なぜならインデックスの値は`0`ゼロがいくつ存在するかを示します。`a[0] = z`。 残りのゼロ以外のエントリの合計は次のようになります。`k - z`、その数も`k - z`。 これは、残りのゼロ以外のエントリがすべて正確に平均化されることを意味します。`1`。 すべての値を 1 にせずに平均値を正の整数にする唯一の方法は、1 つの値を 2 に等しく、他のすべての値を 1 に等しくすることです。 

十分な大きさの場合`k`、ちょうど 4 つの位置をゼロ以外にすることができます。 これらのゼロ以外の値を次のようにします。`k - 4`、`2`、`1`、`1`。 

値`k - 4`値が 1 回表示されると、`2`が 1 回表示され、値が`1`が2回出現します。 残り`k - 4`ポジションはゼロです。 したがって、シーケンスは次のようになります。`a[0] = k - 4`

`a[1] = 2`

`a[2] = 1`

`a[k - 4] = 1`他のすべての位置はゼロです。 

これはあらゆる場合に機能します`k >= 7`、 なぜなら`k - 4`少なくとも`3`したがって、4 つの特殊なインデックスはすべて別個のものになります。 

残りの有効なケースは、既知の回答の固定リストで処理できるほど小さいものです。

 # アルゴリズムのチュートリアル

 1. もし`k`は`4`、有効なシーケンスを使用してください`[1, 2, 1, 0]`。 これは、特殊なインデックスが重複するために一般的な構造を適用できない小さなケースの 1 つです。 
2. もし`k`少なくとも`7`、長さの配列を作成します`k`ゼロで埋められています。 セット`a[0]`に`k - 4`、 セット`a[1]`に`2`、 セット`a[2]`に`1`、と設定します`a[k - 4]`に`1`。 これら 4 つの値は、定義で必要な周波数を正確に作成します。 
3. 他のすべての長さについては、自己記述シーケンスが存在しないことを報告します。 
4. シーケンスが作成されている場合は、保存された値を直接読み取ることによって、要求されたすべてのインデックスに応答します。 

なぜ効果があるのか:

 この構造には 4 つの非ゼロ値があります。 インデックス 0 の値は次のとおりです。`k - 4`、したがって、正確に存在する必要があります`k - 4`ゼロ。 他の 3 つのゼロ以外の位置には次の値が含まれているため、`2`、`1`、 そして`1`、まさにあります`k - 4`エントリがゼロで、次のものがちょうど 2 回出現する`1`、次の 1 回の発生`2`、および次の 1 回の出現`k - 4`。 インデックスに格納される値`1`、`2`、 そして`k - 4`はまさにこれらの頻度であるため、すべてのインデックスは独自の出現数を表します。 

# Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    k = int(input())
    n = int(input())
    queries = list(map(int, input().split()))

    ans = None

    if k == 4:
        ans = [1, 2, 1, 0]
    elif k >= 7:
        ans = [0] * k
        ans[0] = k - 4
        ans[1] = 2
        ans[2] = 1
        ans[k - 4] = 1

    if ans is None:
        print(0)
        return

    print(" ".join(str(ans[x]) for x in queries))

if __name__ == "__main__":
    solve()
```プログラムはまず、有効なシーケンスが存在するかどうかを判断します。 配列は、長さカテゴリがわかった後にのみ作成されるため、不可能な場合の不要な作業が回避されます。 

のために`k >= 7`、割り当て順序は重要です。`k - 4`インデックスとして使用する必要があります。 この条件は、このインデックスが次のものと異なることを保証します。`0`、`1`、 そして`2`したがって、どの割り当ても互いに上書きされません。 

最後の出力ステップでは、配列の検索のみが実行されます。 クエリの数がはるかに大きいため、これが必要になります。`k`リクエストごとに頻度を再計算するのは無駄です。

# テストケース```python
import sys
import io

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    k = int(input())
    n = int(input())
    queries = list(map(int, input().split()))

    ans = None
    if k == 4:
        ans = [1, 2, 1, 0]
    elif k >= 7:
        ans = [0] * k
        ans[0] = k - 4
        ans[1] = 2
        ans[2] = 1
        ans[k - 4] = 1

    if ans is None:
        out = "0"
    else:
        out = " ".join(str(ans[i]) for i in queries)

    sys.stdin = old_stdin
    return out

assert solution("4\n4\n0 1 2 3\n") == "1 2 1 0", "sample 1"
assert solution("7\n4\n0 1 2 3\n") == "3 2 1 1", "sample 2"

assert solution("1\n1\n0\n") == "0", "minimum impossible length"
assert solution("3\n3\n0 1 2\n") == "0", "small impossible length"
assert solution("4\n2\n3 0\n") == "0 1", "small valid construction"
assert solution("230\n3\n0 1 226\n") == "226 2 1", "maximum length construction"

 # エッジケース

 のために`k = 1`、アルゴリズムは不可能な分岐に到達します。 単一の要素がそれ自体の値のカウントと等しく、ゼロ カウントの要件を満たすことはできないため、有効なシーケンスはありません。 

のために`k = 4`、一般的な数式はインデックスに特別な値を配置しようとします。`0`、 なぜなら`k - 4 = 0`。 これにより、構築ロジックが上書きされます。 明示的なシーケンス`[1,2,1,0]`はこの重複を回避し、定義を正確に満たします。 

のために`k = 7`、式は次のようになります`k - 4 = 3`、生産`[3,2,1,1,0,0,0]`。 ゼロが 3 つ、1 が 2 つ、2 が 1 つ、3 が 1 つあり、インデックスの値と一致します。`0`、`1`、`2`、 そして`3`。 これにより、一般的な建設が安全になる最初の境界が確認されます。
