 # 問題の理解

 入力はバイナリ シーケンスに関するローカル ルールを記述します。 ルールはブール式として記述されます。`r`というビットを意味します`r`positions before the current bit. 例えば、`0`現在のビットを表し、`1`は前のビットを表し、以下同様です。 式では、これらのビットを AND、OR、XOR、NOT と組み合わせることができます。 

長さのシーケンス`n`ルールが定義されているすべての位置が式を満たす場合、は有効です。 最大の参照オフセットが`k`、その後、位置から始まるすべてのビット`k + 1`現在のビットと前のビットが一致する場合、式は true と評価されるようにする必要があります。`k`ビットが式に代入されます。 

タスクは、有効な長さのバイナリ シーケンスをすべてカウントすることです。`n`。 答えは必須です`2^60`。 

の値`n`到達できる`1000`なので、すべてを列挙すると`2^n`可能なシーケンスは不可能です。 多くの前のビットを含む状態を持つ動的プログラミング ソリューションであっても、次の要素に線形に依存する場合は失敗します。`n`大規模な州の指数関数的な数の倍です。 式の長さは最大で`1000`、参照されるオフセットは からの桁に制限されます。`0`に`9`、これがキーの制限です。 次のビットが許可されるかどうかを決定するには、前の最大 9 ビットが必要であるため、状態の数は次のように制限されます。`2^9 = 512`。 

最初の微妙なケースは、式が現在のビットのみを使用する場合です。 例えば：```
2
0
```ルールによれば、あらゆるビットが`x_i = 1`。 唯一の有効なシーケンスは、`11`、したがって、答えは次のようになります。```
1
```サイズの状態を常に初期化するソリューション`2^k`と`k`少なくとも 1 に等しいと、維持する以前の履歴がないため、このケースは誤って処理されます。 

もう 1 つの注意が必要なケースは、二項演算子が通常のプログラミング言語の優先順位に従っていないことです。 例えば：```
2
0|1&2
```式は次のように評価されます。`(0|1)&2`としてではなく`0|(1&2)`。 通常のブール優先順位を使用するパーサーは、間違った遷移テーブルを構築し、間違ったシーケンスをカウントします。 

3 番目のエッジ ケースは、ビット数が最大オフセットよりわずかに大きいだけである場合です。```
3
0+1
```状態を確認する必要があるのは、最後の 2 つの位置だけです。 有効なシーケンスは次のとおりです。`000`、`001`、`010`、`011`、`100`、`101`、`110`、 そして`111`ただし、チェックされた位置で隣接する 2 つのビットが等しいものは除きます。 答えは`2`。 以前のビットが十分に存在する前にチェックを開始するソリューションでは、有効なプレフィックスが拒否されます。 

# アプローチ

 直接的なアプローチは、長さのすべてのバイナリ シーケンスを生成することです。`n`次に、ブール式を評価してすべての位置をテストします。 これは、妥当性の定義を正確にチェックするため、正しいです。 ただし、配列の数は、`2^n`、そして`n = 1000`これは考えられる限界をはるかに超えています。 たとえ 1 つのシーケンスをチェックするだけだったとしても`1000`最悪の場合、約`1000 * 2^1000`操作。 

有益な観察は、ルールがビットの固定ウィンドウのみを参照するということです。 この式では、前の 9 ビットと現在のビット以上を検査することはできません。 最後がわかったら`k`ビットがすでに生成されているため、以前のプレフィックス全体は、次のどのビットが可能であるかに影響を与えなくなります。 

これにより、問題は有限状態動的計画問題に変わります。 各状態は最後の状態を表します`k`ビット。 新しいビットを追加すると、ブール式が満たされた場合に別の状態への遷移が作成されます。 せいぜいあるので`512`状態、すべてを処理できます`n`効率的に配置します。 

この総当たり法は、すべての完全なシーケンスを個別にチェックできるため機能しますが、使用可能なプレフィックスの数が指数関数的に増加するため失敗します。 有限状態ビューは、同一の先物を持つプレフィックスをグループ化し、すべての同等のプレフィックスが 1 つの DP 値を共有できるようにします。

# Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1 << 60

class Parser:
    def __init__(self, s):
        self.s = s
        self.i = 0

    def parse(self):
        node = self.parse_atom()
        while self.i < len(self.s) and self.s[self.i] in "&|+":
            op = self.s[self.i]
            self.i += 1
            right = self.parse_atom()
            node = (op, node, right)
        return node

    def parse_atom(self):
        c = self.s[self.i]
        if c == '-':
            self.i += 1
            return ('-', self.parse_atom())
        if c == '(':
            self.i += 1
            node = self.parse()
            self.i += 1
            return node
        self.i += 1
        return ('var', int(c))

def eval_tree(node, bits):
    t = node[0]
    if t == 'var':
        return (bits >> node[1]) & 1
    if t == '-':
        return 1 - eval_tree(node[1], bits)
    a = eval_tree(node[1], bits)
    b = eval_tree(node[2], bits)
    if t == '&':
        return a & b
    if t == '|':
        return a | b
    return a ^ b

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)
    expr = input().strip()

    k = 0
    for c in expr:
        if c.isdigit():
            k = max(k, int(c))

    tree = Parser(expr).parse()

    if k == 0:
        value = eval_tree(tree, 0)
        if value == 1:
            print(pow(2, n, MOD))
        else:
            print(0)
        return

    limit = 1 << k
    good = [[False, False] for _ in range(limit)]

    for state in range(limit):
        for bit in range(2):
            mask = state | (bit << k)
            good[state][bit] = eval_tree(tree, mask) == 1

    dp = [1] * limit
    mask_limit = limit - 1

    for _ in range(k, n):
        ndp = [0] * limit
        for state, count in enumerate(dp):
            if count:
                if good[state][0]:
                    ndp[(state >> 1)] = (ndp[state >> 1] + count) & (MOD - 1)
                if good[state][1]:
                    ndp[((state >> 1) | (1 << (k - 1)))] = (
                        ndp[(state >> 1) | (1 << (k - 1))] + count
                    ) & (MOD - 1)
        dp = ndp

    print(sum(dp) & (MOD - 1))

if __name__ == "__main__":
    solve()
```パーサーは、すべてのリーフが 1 つの参照ビット位置であるバイナリ ツリーを構築します。 再帰降下順序は、問題の珍しい演算子ルールと一致します。つまり、括弧が最初に処理され、次の式にバインドされず、二項演算子が左から右に結合されます。 

前処理フェーズでは、追加するかどうかを計算します。`0`または`1`考えられるすべての履歴状態から許可されます。 状態マスクには以前の状態のみが保存されます。`k`ビット。 新しく追加されたビットは の位置に配置されます`k`式では現在位置を基準としたオフセットが使用されるため、一時的に実行されます。 

最初の履歴の前にルールがチェックされていないため、DP は考えられるすべての初期履歴から開始されます。`k`ビットは既知です。 各遷移は状態を 1 位置シフトし、新しいビットを挿入します。 式チェックは、古い履歴と候補ビットを使用して、遷移前に行われます。 

モジュロ演算では次を使用します。`2^60`。 法は 2 の累乗であるため、ビット マスクを使用して最下位 60 ビットのみを保持することができ、これは一般的な剰余演算よりも高速です。

 # エッジケース

 現在のビットのみの式の場合:```
2
0
```アルゴリズムがそれを検出します`k = 0`。 式はビット値 0 に対して 1 回評価されます。 1 だけが受け入れられるため、すべての位置に 1 が含まれている必要があります。 答えは次のようになります`2^n`式が両方のビット値を受け入れる場合のみ、それ以外の場合は、強制されたシーケンスに応じて 1 または 0 のいずれかになります。 

特殊な演算子の優先順位の場合:```
2
0|1&2
```パーサーは最初に読み取ります`0`、それを組み合わせます`1`OR を使用して、最後にその結果を`2`ANDを使用します。 構文ツリーが表すのは、`((0|1)&2)`、ステートメントと一致します。 通常の言語パーサーは別のツリーを構築し、不正確な遷移を生成します。 

オフセットが大きいルールの場合:```
3
0+1
```最大オフセットは 1 であるため、状態には 1 つ前のビットがあります。 最初のビットはチェックせずに保存されます。 後続の各ビットは前のビットに対してテストされ、遷移が受け入れられるたびに状態がシフトされます。 このアルゴリズムは、存在しない以前のビットを検査しないため、条件が定義されている位置のみをカウントします。
