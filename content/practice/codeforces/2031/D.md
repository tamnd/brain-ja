 ## 解決策
 ## 問題の理解

 私たちは、それぞれ高さのある木々の列を与えられています。 ウサギはある位置から開始し、位置と高さの両方に依存する非常に特殊なルールを使用して木の間を移動できます。 

インデックスの木から`i`、ウサギは 2 方向にジャンプできます。 左にジャンプした場合は、厳密に高い木に着地する必要があります。 右にジャンプする場合は、厳密に短い木に着地する必要があります。 移動するたびに「高さの変化の方向」が反転します。左に移動すると高さが増加し、右に移動すると高さが減少しますが、インデックス空間内の方向は独立しています。 

すべての開始位置について、ウサギがそのようなジャンプを何度でも繰り返して到達できるすべての木の中での最大の高さを知りたいと考えています。 

重要な課題は、ウサギが単に局所的に移動しているだけではないことです。 さまざまな方向で高さの増加と減少を交互に繰り返すことができるため、到達可能なインデックスのセットは単純な間隔ではありません。 これは、厳密な不等式の下ですべてのノードが他の多くのノードに接続するグラフのように動作します。 

制約は厳しく、すべてのテスト ケースにわたるツリーの総数は 500,000 に達します。 インデックスのペア間の遷移を明示的に考慮するソリューションは、すぐに遅すぎます。 たとえ$O(n \log n)$テスト ケースごとのアプローチは、要素ごとに非常にクリーンで直線的でない限り、TLE の危険性があります。 

貪欲に考えると、微妙な落とし穴が現れます。ローカルで次のジャンプを最大化しても、グローバルな到達可能性は保証されません。 小さな例でこれを説明します。 

考慮する`a = [3, 1, 2]`。 インデックス 1 から 2 にジャンプし (1 < 3 であるため)、次に 2 から 3 にジャンプする可能性があります (2 > 1 が false であるため、このパスは実際には中断されます)。 到達可能な構造はインデックスの順序付けと高さの順序付けの両方に同時に依存するため、単純な貪欲なステッピングは失敗します。 

本当の難しさは、到達可能性がローカルな隣接関係ではなく、高さによって誘発されるグローバルな順序構造に依存することです。 

## アプローチ

 直接的な総当たりアプローチは、各インデックスから開始され、BFS または DFS を使用してすべての可能なジャンプをシミュレートします。 ノードから`i`、すべてスキャンします`j < i`と`a[j] > a[i]`そしてすべて`j > i`と`a[j] < a[i]`、有効なトランジションをプッシュします。 

これは正しいですが、非常に高価です。 最悪の場合、すべてのノードが他のほぼすべてのノードに接続するため、開始ごとに探索が行われます。$O(n)$トランジション、与える$O(n^2)$全体。 

重要な観察は、ルールが常に単調な制約に沿って移動するということです。つまり、左に移動すると厳密に高さが増加し、右に移動すると厳密に高さが減少します。 これは、有効なパスに沿って、訪問した高さのシーケンスが増加と減少を交互に繰り返すことを意味します。 さらに重要なことは、すべての動きは、構造化された値の順序において「最も連絡可能な代表者」に移動すると解釈できることです。 

この問題をインデックス上のグラフとして再定式化できます。このグラフでは、エッジがソート順に最も近い強いまたは弱い近傍によって定義されます。 中間ノードは許可されたジャンプの推移性によって支配されるため、すべての有効なノードに接続する代わりに、到達可能性を維持する各方向で最も近い候補に接続するだけで済みます。 

これにより、問題は「左の次に大きい」と「右の次に小さい」関係を捉える構造の構築に集約され、単調スタックまたは DSU ベースのスキップを使用して維持できます。 この縮小されたグラフが構築されると、到達可能性はコンポーネントの和集合となり、各ノードの答えは接続コンポーネントの最大値になります。 

最後のステップでは、この暗黙的なグラフに対して連結成分を計算し、成分ごとの最大値を取得します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各ノードからのブルート フォース DFS |$O(n^2)$|$O(n)$| 遅すぎる |
 | 単調構造 + DSU コンポーネント |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 単調遷移を使用して暗黙的にグラフを構築し、到達可能なノードをコンポーネントにマージします。 

1. 到達可能性の概念を圧縮します。有効なノードへのジャンプを許可する代わりに、各インデックスを各方向で最も近い有効な候補にのみ接続します。 その理由は、到達可能性エンドポイントを変更せずに、さらに有効なジャンプを中間の有効なステップを通じて分解できるためです。 
2. 単調スタックを使用して、「左の次に大きい」と「右の次に小さい」構造を構築します。 各インデックスについて、左側の高さが大きい最も近いインデックスと、右側の高さの小さい最も近いインデックスが見つかります。 これらは、明示的に必要な唯一のエッジになります。 
3. 各インデックスをグラフ内のノードとして扱います。 これらの計算された遷移に従ってエッジを追加します。 各ノードの出力エッジは最大でも一定であるため、グラフのサイズは線形のままです。 
4. すべてのエッジにわたって DSU (素集合結合) を実行します。 2 つのインデックスが接続されている場合は、それらを同じコンポーネントに結合します。 これにより、相互に到達可能なすべての位置が集約されます。 
5. すべての結合の後、各 DSU コンポーネント内の最大高さを計算します。 
6. 開始インデックスごとに、そのコンポーネントの最大高さを出力します。 

これが機能する理由は、交互の単調な動きが常に崩壊して、長いパスが一連の「最も近い実行可能な拡張」に相当する構造になるためです。 これらがリンクされると、DSU は到達可能な状態で完全に閉じることを保証します。 

### なぜ効果があるのか

 すべての有効な移動は、インデックスの移動と一致する方向に厳密に高さを変更します。 厳密な不等式により、中間の障害物を飛び越えることなく、最も近いジャンプ以外のジャンプを、最も近い有効なジャンプのチェーンに置き換えることができます。 これにより、局所的な極値遷移がすでに完全な到達可能性をエンコードしている推移的閉包が作成されます。 次に、DSU はこのクロージャの接続されたコンポーネントをキャプチャし、コンポーネント内のすべてのノードに交互の単調ステップを介して他のすべてのノードに到達できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        dsu = DSU(n)

        # monotonic stack for next greater to left
        stack = []
        for i in range(n):
            while stack and a[stack[-1]] < a[i]:
                stack.pop()
            if stack:
                dsu.union(i, stack[-1])
            stack.append(i)

        # monotonic stack for next smaller to right
        stack = []
        for i in range(n - 1, -1, -1):
            while stack and a[stack[-1]] > a[i]:
                stack.pop()
            if stack:
                dsu.union(i, stack[-1])
            stack.append(i)

        comp_max = {}
        for i in range(n):
            root = dsu.find(i)
            comp_max[root] = max(comp_max.get(root, 0), a[i])

        out.append(" ".join(str(comp_max[dsu.find(i)]) for i in range(n)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DSU 構造は純粋に接続性コンプレッサーとして使用されます。 各結合は、単調制約によって暗示される即時構造の到達可能性に対応します。 スタック構造により、二次比較を回避しながら、必要な接続を決して見逃すことがなくなります。 

最後のパスは単なるグループ化です。コンポーネントが形成されると、各クエリは定数時間のルックアップになります。 

実装の微妙な点は、隣接リストを明示的に構築しないことです。 これにより、最悪の場合、O(n^2) メモリが危険にさらされることになります。 代わりに、ユニオンはスタック処理中に直接実行されます。

 ## 特殊なケース

 単一要素の配列は自明です。DSU は結合を実行しないので、コンポーネント max は要素そのものです。 アルゴリズムは正しくそれを即座に返します。 

次のような厳密に増加するシーケンスの場合`1 2 3 4 5`、左より大きいエッジはめったに存在しませんが、右より小さい遷移は依然として逆処理のスタック崩壊を通じてノードを接続します。 DSU は部分的なグループ化を保証し、到達可能な領域ごとに正しい最大値を生成します。 

次のような厳密に減少するシーケンスの場合、`5 4 3 2 1`、すべてのノードには左より大きい隣接ノードがあるため、共用体は構造全体に伝播します。 DSU はすべてを 1 つのコンポーネントに集約し、すべての出力が 5 になり、交互の移動による完全な到達可能性と一致します。
