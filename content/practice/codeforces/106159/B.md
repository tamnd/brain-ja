 ## 解決策
 ## 問題の理解

 連結された 2 つの整数 A と B を表す 1 つの数値文字列が与えられます。これら 2 つの数値は、もともと A と B が別個のコンポーネントであるアドレス形式から来ていますが、メッセージ内では区切り文字なしで結合されています。 私たちの仕事は、元のペアを回復することです。 

A と B は両方とも、1 ～ 99 の範囲の厳密に正の整数です。これらは標準 10 進数形式で記述されているため、先頭のゼロは許可されません。 入力文字列は、一部の A と B の有効な連結であることが保証されていますが、重要な問題は、この連結が一意にデコードできない可能性があることです。 

出力は、文字列を制約を満たす 2 つの数値に分割する有効な方法が 1 つだけ存在するかどうかによって異なります。 有効な分割が 1 つだけ存在する場合は、それを出力します。 有効な分割が複数ある場合は、-1 が出力されます。 

入力長は最大 4 桁です。 これは重要です。これは、組み合わせ検索空間を扱っているのではなく、非常に少数の一定数の可能性を扱っていることを意味します。 考えられるすべての分割を試すアプローチであれば、パフォーマンスの点ではすでに十分です。 

主なエッジケースは、可変桁長によって引き起こされる曖昧さです。 たとえば、文字列 111 は、1 と 11、または 11 と 1 として解釈でき、どちらも有効です。 対照的に、1020 のような文字列は、10 と 20 が有効かどうか、また先行ゼロ規則により 1 と 020 が無効かどうかに応じて、有効な解釈が 1 つだけになる可能性があります。 

もう 1 つの微妙なケースは、分割によって 99 より大きいか 0 に等しい数値が生成される場合です。この数値は、桁の境界に適合する場合でも拒否する必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。文字列を 2 つの部分に分割するためにあらゆる場所を試してみます。 文字列の長さは最大 4 であるため、分割ポイントは最大 3 つになります。 分割ごとに、左側の部分文字列を A として解釈し、右側の部分文字列を B として解釈し、両方を検証します。 

検証とは、正確に「0」でない限り、どちらの部分にも先行ゼロがないこと (A と B は 1 から始まるため、ここでは実際には無効です)、および両方の値が 1 から 99 までの範囲にあることを確認することを意味します。 各チェックは O(1) であるため、プロセス全体は定数時間です。 

入力サイズが一定であるため、ブルート フォース アプローチはすでに効率的に機能します。 高度な最適化は必要ありませんが、概念的な簡素化は、問題が単に制約の下での列挙に関するものであり、広い空間の検索に関するものではないことを認識することで得られます。 

重要な観察は、制約が解空間を完全に制限していることです。 A と B はそれぞれ最大 2 桁であるため、有効な分割では 1 と 2 の間の桁の長さを考慮する必要があります。これにより、最初の部分の長さが 1、2、または 3 である分割のチェックに制限されますが、実際には文字列の合計の長さは最大 4 であるため、列挙は簡単なままです。 

最後のステップでは、有効な分割がいくつ存在するかを数えます。 正確に 1 つ存在する場合は、それを出力します。 それ以外の場合、あいまいさにより出力は -1 になります。

 ## アルゴリズムのチュートリアル

1. 入力文字列 S を読み取ります。この文字列は、区切り文字のない 2 つの連結された数値を表すため、考えられるすべての分割点が解釈の候補になります。 
2. 有効な解釈のためのカウンタと、一意の回答が存在する場合はそれを格納する変数を初期化します。 
3. 1 から len(S) - 1 までのすべての可能な位置 i で S を 2 つの空でない部分に分割してみます。各分割は A = S[:i] および B = S[i:] に対応します。 
4. 分割ごとに、両方の部分文字列を整数に変換し、両方が 1 ～ 99 の範囲内にあることを確認します。この手順により、有効な住所コンポーネントのみを受け入れることが保証されます。 
5. スプリットが有効な場合は、カウンターをインクリメントし、ペアを保存します。 有効な分割が複数見つかった場合は、すでにあいまいさがあると結論付けることができますが、ループが小さいため、論理的に続行します。 
6. すべての分割をチェックした後、有効なペアが 1 つだけ存在する場合は、それを印刷します。 それ以外の場合は、-1 を出力します。 

### なぜ効果があるのか

 分割が固定されると連結は決定的になるため、すべての有効な解決策は文字列内の固有の切断位置に対応します。 すべての制約は 2 つの部分の数値のみに依存し、グローバル構造には依存しないため、すべてのカット位置をチェックすると、完全な解空間が使い果たされます。 正確さは、A と B の間に、それぞれの有効性の範囲を超えた隠れた変換や依存関係がないという事実から得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

valid = []
n = len(s)

for i in range(1, n):
    a = s[:i]
    b = s[i:]

    # no leading zeros allowed
    if (a != "0" and a[0] == "0") or (b != "0" and b[0] == "0"):
        continue

    A = int(a)
    B = int(b)

    if 1 <= A <= 99 and 1 <= B <= 99:
        valid.append((A, B))

if len(valid) == 1:
    print(valid[0][0], valid[0][1])
else:
    print(-1)
```コードはアルゴリズムを直接反映しています。 すべての分割位置を反復処理し、部分文字列を整数として解釈します。 通常、有効な入力ではそのようなケースは回避されますが、先頭のゼロ チェックは防御的に組み込まれています。 最終的な決定は、純粋に有効な分割の数に基づいて行われます。 

微妙な点は、最初の有効な分割を見つけるときに早期復帰を行わないことです。 すべての有効な分割を明示的にカウントすることもできますが、曖昧さの状態がより明確になり、複数の有効な解釈の欠落を避けることができます。

 ## 特殊なケース

 特殊なケースの 1 つは、文字列に次のような数字が繰り返される場合です。`"111"`複数の有効な分割が存在する場合。 アルゴリズムは両方の分割位置を評価し、2 つの有効な解釈を正確に識別し、出力 -1 をもたらします。 

もう 1 つのエッジ ケースは、分割により許容範囲外の数値が生成される場合です。 入力用`"99100"`、のように分割します`99 | 100`100 が 99 を超えるため失敗し、他のすべての分割も失敗するか制約に違反するため、有効な解釈が残されず、構造に応じた一意性が保証されません。 

先頭のゼロも重要なケースです。 のために`"1020"`、分割`1 | 020`は、数値的には 1 と 20 のように見えても拒否されます。このチェックでは、数値が等しいだけでなく、部分文字列の構造が保持されていることも確認されます。 

各ケースは、すべての分割を評価し、同じ妥当性ルールを適用することによって均一に処理されるため、最終的な実装では特別なケースは必要ありません。
