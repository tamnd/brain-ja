 ## 解決策
 ## 問題の理解

 未来からメッセージがいつ到着したかを表すタイムスタンプのコレクションが与えられます。 各タイムスタンプは、非常に大きな数直線上の単なる 1 つの整数です。 すべてのメッセージを読んだ後、複数のクエリに答えるように求められます。各クエリでは閉じた間隔が与えられます。$[L, R]$そして、その間隔内に保存されているタイムスタンプがいくつあるかを数えなければなりません。 

したがって、入力は静的です。最初は値の固定リスト、次にその同じリストに対する範囲カウント クエリのバッチです。 更新は行われず、すべてのクエリは独立しています。 各クエリは、整数直線の部分範囲にわたる頻度の質問をしています。 

制約が十分に大きいため、クエリごとにリスト全体をスキャンするアプローチはすぐに遅すぎます。 と$N, Q \le 2 \cdot 10^5$、ナイーブな$O(NQ)$ソリューションは最大でパフォーマンスを発揮します$4 \cdot 10^{10}$これは、一般的な制限の下で Python や C++ でさえ 4 秒で実行できる速度をはるかに超えています。 これにより、前処理と対数クエリ処理が推進されます。 

微妙な点は、タイムスタンプが内部で任意であることです。$[1, 10^9]$したがって、直接のインデックス付けや頻度配列に依存することはできません。 ドメインが大きすぎるため、直接ヒストグラムを作成できません。 

エッジケースは主に境界処理を中心に展開します。 たとえば、すべてのタイムスタンプが同一で、クエリがその値と正確に一致するか一致しない場合、正確さは完全に包含間隔ロジックに依存します。 

次のことを考慮してください。 

入力:```
3 1
5 5 5
5 5
```出力は次のようになります。```
3
```単純な間違いは、間隔を半開として扱ったり、等価性を誤って処理したりすることです。これにより、誤って 0 または 1 が返されます。 

別の特殊なケース:```
4 1
1 3 5 7
2 4
```正しい出力は 1 です。境界比較で 1 ずつずれている場合や、カウント方法が正しくない場合は、ここで中断されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに$[L, R]$、すべてを繰り返します$N$タイムスタンプを取得し、範囲内にある数をカウントします。 これはクエリの定義と直接一致するため、正解です。 ただし、クエリごとに同じ完全スキャンが繰り返されます。 と$Q$クエリ、これは次のことにつながります$N \cdot Q$比較。 

両方のとき$N$そして$Q$が大きい場合、これがボトルネックになります。 それぞれの比較が定数時間だったとしても、全体の作業量が多すぎます。 

重要な点は、タイムスタンプの元の順序を保持する必要がないということです。 クエリは、位置ではなく、値の範囲内のメンバーシップのみに依存します。 タイムスタンプを並べ替えると、すべてのクエリは、並べ替えられた配列内の 2 つの位置の間にある要素の数を見つけることになります。 

並べ替え後、すべての要素$\le R$プレフィックスとすべての要素を形成します$< L$別のプレフィックスを形成します。 答えは、2 つのプレフィックス数の差になります。 これはまさに二分探索が提供するものです。つまり、境界を見つけることができます。$R$そしてその境界線$L$対数時間で。 

したがって、配列をスキャンする代わりに、1 回事前に並べ替えてから、2 回の二分検索で各クエリに答えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(NQ)$|$O(1)$| 遅すぎる |
 | ソート + 二分検索 |$O(N \log N + Q \log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、範囲カウントがプレフィックス境界カウントになるソート順序問題に変換します。 

1. すべてのタイムスタンプを配列に読み取ります。 データを構造的に整理するために並べ替える必要があるため、これらを保存します。 ソートが必要なのは、任意の値を二分探索が適用される単調シーケンスに変換するためです。 
2. 配列を降順でない順に並べ替えます。 このステップが重要な変換です。並べ替えると、しきい値以下のすべての値が連続したプレフィックスを形成し、カウントを境界検出に置き換えることができます。 
3. クエリごとに$[L, R]$、ソートされた配列内の 2 つの位置、つまり値が以上である最初のインデックスを計算します。$L$、および値がより大きい最初のインデックス$R$。 これら 2 つの境界により、有効なセグメントが正確に分離されます。 
4. 質問に対する答えは、これら 2 つの位置の違いです。 これが機能するのは、左側の境界より前のすべてが小さすぎ、右側の境界より後のすべてが大きすぎ、その間にあるものはすべて有効であるためです。 
5. 計算された各差分を直ちに出力するか、最終出力のために結果を保存します。 

### なぜ効果があるのか

 ソートは、問題を任意のメンバーシップカウントから単調シーケンスでの区間長抽出に変換します。 各クエリは事実上、並べ替えられた配列と間隔の間の交差のサイズを要求します。 二分探索境界は、配列を 3 つの互いに素な領域に分割する正確なカット ポイントです。以下の値です。$L$、内部の値$[L, R]$、および上記の値$R$。 これらの領域はソート順に連続しているため、要素をスキャンせずにサイズを計算でき、要素が二重にカウントされたり欠落したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left, bisect_right

def main():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    arr.sort()

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        left = bisect_left(arr, l)
        right = bisect_right(arr, r)
        out.append(str(right - left))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```この解決策は、タイムスタンプを読み取って並べ替えることから始まります。 並べ替えは 1 回だけ行われるため、その後のすべての操作はバイナリ検索構造に依存できます。 

各クエリは 2 つの標準バイナリ検索を使用します。`bisect_left`最初の位置を見つけます。`l`順序を壊すことなく挿入でき、厳密に以下の要素の数を効率的に数えることができます。`l`。`bisect_right`より大きい最初の位置を見つけます`r`、以下の要素の数を数えます`r`。 それらの差により、区間内の要素の数が正確にわかります。 

よくある落とし穴は、これら 2 つの関数を交換したり、一方のみを使用したりすることです。 もう 1 つの微妙な問題は、間隔が両端を含むことを忘れていることです。`bisect_right`他のものではなく必要です`bisect_left`。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import bisect

    n, q = map(int, input().split())

    arr.sort()

    out = []

        l, r = map(int, input().split())
        from bisect import bisect_left, bisect_right
        out.append(str(bisect_right(arr, r) - bisect_left(arr, l)))

    return "\n".join(out) + "\n"

 ## 特殊なケース

 単一の繰り返し値の場合、並べ替えられた配列はすべての構造を同一の要素に折りたたみます。 アルゴリズムはまだ機能します。`bisect_left`そして`bisect_right`重複ブロック全体を正しく括弧で囲みます。 たとえば、入力の場合`[5,5,5]`そしてクエリ`[5,5]`、両方の境界がインデックスを分離します`[0,3)`、3を生成します。 

完全に範囲外のクエリの場合:`[4,4]`の上`[1,2,3,4,5]`、両方のバイナリ検索は同じインデックスを返し、ゼロを生成します。 これにより、空の間隔が特別なケースなしで自然に処理されることが確認されます。 

次のような全範囲のクエリの場合`[1,10^9]`、`bisect_left`0 を返し、`bisect_right`返品$N$、フルカウントを与えます。 これは、アルゴリズムがオーバーフローや要素の欠落なしに極端な境界を正しく処理していることを示しています。
