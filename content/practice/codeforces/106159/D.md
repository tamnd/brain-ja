 ## 解決策
 ## 問題の理解

 長い数字のシーケンスと、短いパターンのシーケンスが与えられます。 0 から 9999 までの単一のシフト値を選択できます。このシフトを適用するということは、長いシーケンスのすべての要素にシフトを追加し、すべてを 10000 を法として取得することを意味します。この変換後、シフトされた配列に連続した部分配列としてパターンが含まれている回数を数えたいと考えます。 私たちの仕事は、この発生回数を最大化するシフトを選択することであり、複数のシフトが同じ最大値に達する場合は、そのような最小のシフトを出力する必要があります。 

重要な構造は、変化が世界的なものであるということです。 パターン内の任意の値を照合しているのではなく、固定シフトの場合、A のすべての要素に同じ加算オフセットを適用した後、A[i..i+M-1] == B を満たす位置の数を求めています。 

制約は非常に大きく、配列の長さは最大 100 万に達する可能性があります。 これにより、各シフトを個別にシミュレートしようとしたり、候補シフトごとにパターン マッチを最初から再計算したりするソリューションは即座に排除されます。 N または O(N * 10000) の二次関数は、非常に小さな定数と強力なフィルタリングがない限り、避けなければなりません。 

微妙なエッジケースはモジュラーラップアラウンドから生まれます。 値は 10000 を法として取得されるため、減算と等価は循環的に動作します。 たとえば、モジュロ演算が正しく処理されない限り、生の差が負に見える場合でも、パターン マッチでは 9998 のようなシフトが必要になる場合があります。 もう 1 つのエッジ ケースは、複数のポジションが異なるシフトに均等に投票する場合です。 答えは最小のシフトでなければならないため、同点の処理は重要です。 

単純な実装では、すべてのシフトを試行し、シフトごとに配列全体をスキャンして一致をチェックします。 これは、実行不可能な約 10^4 × 10^6 の比較を実行するため、大きな入力では静かに失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 シフトを修正し、概念的にシフトされた配列を構築し、パターンをその上にスライドさせます。 すべての j について、A[i+j] + s ≡ B[j] (mod 10000) である場合、すべての位置 i は一致に寄与します。 すべてのシフトをチェックするとコストが 10000 倍になり、すべてのポジションをチェックすると N 倍になり、最悪の場合はおよそ 10^10 の操作が行われますが、これは制限をはるかに超えています。 

重要な観察は、シフトが A と B の各配置によって独立して決定されるということです。開始位置 i を固定する場合、パターン内のすべての j について、A[i+j] + s ≡ B[j] がなければなりません。 これは、すべての値 B[j] - A[i+j] (mod 10000) が等しくなければならないことを意味します。 したがって、各アライメントは 1 つの一貫したシフト値に寄与するか、何も寄与しないかのどちらかです。 

これにより、問題は、A のサイズ M の各ウィンドウから 1 つの候補シフトを抽出し、一貫性を検証し、各シフトに投票するウィンドウの数をカウントすることに軽減されます。 シフトをシミュレートする代わりに、違いによって引き起こされる制約を集約しています。 

効率の向上は、各ウィンドウが最大 1 つの有効なシフトを生成するという事実から得られるため、O(NM) ですべてのウィンドウを単純に処理できますが、それでも遅すぎます。 次に、ウィンドウ内のすべての差異が同一であるかどうかを検出するだけでよいことがわかります。これは、スライディング ウィンドウ ハッシュまたはローリング整合性チェックを使用して段階的に維持できます。 実際的な方法は、ウィンドウ内の最初の暗黙のシフトを追跡し、後続のすべての位置がそれに一致することを確認することです。 不一致が発生した場合、そのウィンドウは無効になります。 

したがって、O(N) で位置ごとに 1 つのシフト候補を計算し、10000 の可能なシフトにわたる頻度を集計できます。

 ## アルゴリズムのチュートリアル

 それぞれの調整をシフトの制約として再構成します。

1. 長さ M の完全なウィンドウが適合する A の各インデックス i について、A[i..i+M-1] をシフトすると B と等しくなるようなシフト s が存在するかどうかを判断します。最初のペアから候補シフトを計算します。s = (B[0] - A[i]) mod 10000。これは、このウィンドウが有効な場合にシフトが何でなければならないかを定義します。 
2. (A[i+j] + s) mod 10000 が B[j] に等しいことをすべての j でチェックすることにより、この候補シフトに対してウィンドウ全体を検証します。 いずれかのポジションが失敗した場合、このウィンドウは有効なシフトに寄与しません。 これが必要なのは、単一の不一致は差異が矛盾していることを意味し、全体的なシフトではパターンを満たすことができないためです。 
3. ウィンドウが有効な場合、shift s の周波数カウンターをインクリメントします。 これは、そのシフトの下で出現するパターンの回数を集計します。 
4. すべてのウィンドウを処理した後、0 から 9999 までのすべてのシフトをスキャンし、最大頻度のシフトを選択します。 複数のシフトが同点の場合は、上向きに反復して最小のシフトを選択します。 

重要な考え方は、各有効なマッチ ウィンドウが 1 つのシフトに 1 つの投票だけを提供するということです。 

### なぜ効果があるのか

 シフト s 下の位置 i でのパターンの有効な一致については、すべての等式 A[i+j] + s ≡ B[j] が同時に成立する必要があります。 これは、s が任意の 1 つの位置 j によって一意に決定され、すべての j にわたる一貫性が一致の有効性と同等であることを意味します。 逆に、チェックに合格したウィンドウは、正確に 1 回のシフトでパターンが正しく発生します。 したがって、シフトごとに有効なウィンドウをカウントすることは、変換された配列内の出現をカウントすることと正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10000

def main():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    freq = [0] * MOD

    for i in range(n - m + 1):
        s = (b[0] - a[i]) % MOD
        ok = True

        for j in range(m):
            if (a[i + j] + s) % MOD != b[j]:
                ok = False
                break

        if ok:
            freq[s] += 1

    best_s = 0
    best_cnt = freq[0]

    for s in range(1, MOD):
        if freq[s] > best_cnt:
            best_cnt = freq[s]
            best_s = s

    print(best_s, best_cnt)

if __name__ == "__main__":
    main()
```このコードは、スライディング ウィンドウ検証のアイデアを直接実装しています。 モジュロ演算により、ラップアラウンド時の正確性が保証されます。 サイズ 10000 の周波数配列は、制約があれば安全です。 

実装の微妙な詳細は、内部ループの初期のブレークです。 これがないと、早期に無効であっても各ウィンドウは常に M チェックを実行します。これは依然として正しいですが、速度が遅くなります。 もう 1 つの重要な詳細は、最適なシフトを 0 として初期化し、上方向にスキャンするときにタイが自動的に小さなシフトを優先するようにすることです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのウィンドウが無効な場合です。 その場合、すべてのシフト カウントは 0 のままであり、最小の最大化シフトを選択するため、正解はシフト 0 です。 freq[0] はゼロに初期化され、シフトがそれを超えることはないため、アルゴリズムはこれを自然に処理します。そのため、best_s は 0 のままです。 

もう 1 つのケースは、減算によって負の値が生成されるラップアラウンド演算です。 たとえば、A = [9999, 0] および B = [0, 1] です。 計算されたシフトは (0 - 9999) mod 10000 = 1 で、モジュロ加算後に両方の要素が正しく位置合わせされます。 このアルゴリズムはすべての比較でモジュラー演算に依存するため、モジュロ演算以外の特別な処理は必要ありません。 

3 番目のエッジ ケースは、同じウィンドウが複数回繰り返され、同じシフトが生成されます。 各開始インデックスは頻度に個別に寄与するため、各出現は独立してカウントされ、シフトされた配列内の出現の定義と一致します。
