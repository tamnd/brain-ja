 ## 問題の理解

 私たちに与えられた長いレースは、`n`ラップでは、各ラップに 26 人のドライバー候補の中から 1 人の勝者が選ばれ、英語の小文字でラベルが付けられます。 したがって、完全なレースは単に長さの文字列です`n`サイズ26のアルファベット以上。 

この種族の短い断片、つまり文字列も与えられます。`s`長さの`m`、これはレース全体のどこかに連続したブロックとして出現することが保証されています。 しかし、それがどこに現れるのかはわかりません。また、この断片の外側にある残りの種族もわかりません。 

タスクは、長さの完全なレース シーケンスの数をカウントすることです。`n`次のような部分文字列が可能です`s`それらのどこかに現れます。 勝者において少なくとも 1 つの順位が異なる場合、2 つのレースは異なるものとみなされます。 

重要な難点は、`n`最大 10^18 と非常に大きくなる可能性があるため、完全な文字列を明示的に構築したり反復したりすることはできません。 フラグメントの長さ`m`は小さく、最大でも 100 です。これは、すべての意味のある構造は、この部分文字列がどのように配置され、重複または複数の出現がどのように相互作用するかによってもたらされる必要があることを示唆しています。 

素朴な解釈では、開始位置を選択しようとする可能性があります。`s`文字列全体を検索し、他の場所で任意の詰め物をカウントします。 これはすでに複雑な問題を示唆しています。`s`が複数回出現したり、それ自体と重なったりする場合、異なる配置は独立していません。 

微妙なエッジケースが現れるのは、`s`内部に周期構造を持っています。 

たとえば、次の場合`s = "aaa"`、 そして`n = 3`の場合、部分文字列は位置 1 からのみ開始できますが、残りの文字は完全に強制されます。 不注意な解決策では、配置を個別に扱うため、過剰にカウントされる可能性があります。 

もう 1 つのエッジケースは次のような場合です`s`それ自体と重なります。`s = "ababa"`、パターンのシフトが有効な一致と一致する可能性があります。 重複構造を無視すると、構成が二重にカウントされることになります。 

したがって、主な課題は配置だけではなく、複数のパターンが完全な文字列内でどのように一貫して共存できるかということです。 

## アプローチ

 ブルートフォースアプローチは、考えられる長さのすべての文字列を考慮することです。`n`26 文字を超えているかどうかを確認してください。`s`部分文字列として表示されます。 文字列の数は 26^n であり、小さい文字列であっても天文学的に大きいため、これは明らかに実行不可能です。`n`。 

より構造化されたブルートフォースの改善は、開始位置を固定することです`i`の発生のために`s`、 から`1`に`n - m + 1`。 それぞれの選択に対して、`i`、それらを修正します`m`文字を選択し、残りを自由に選択します`n - m`ポジション。 これにより、`(n - m + 1) * 26^(n - m)`文字列。 ただし、これは非常に過大評価されます。`s`構築された単一の文字列には以下が含まれる可能性があるため、同じ文字列内の複数の位置に出現する可能性があります。`s`複数回。 

重要な観察は、問題は単一の配置に関するものではなく、`s`長さの中に`n`弦。 それぞれの配置`s`固定文字を課し、重複する配置では位置間の平等制約を課します。 これは、文字列を制約システムとして扱う古典的な構造です。 

以来`m`が小さい場合、オーバーラップ構造は`s`ボーダー機能 (接尾辞でもある接頭辞) を介して完全に理解できます。 これにより、`s`より大きな文字列内で整列できます。 

の配置をモデル化します`s`位置に関する制約のグラフ内のノードとして、重複するコピーがインデックスをマージします。 その結果、有効なグローバル構成は一貫した配置のセットを選択することによって決定されますが、一貫性があると自由度が低下します。 

重要な単純化は、すべてを推論するのではなく、`n`、長さがどのように重複するかを追跡するだけです`m`行動し、空いている独立したポジションがいくつあるか。 最終的な答えは、次の構造によって引き起こされる強制等式の数によって調整された 26 のべき乗になります。`s`、長さ内のパターンの有効なシフト アラインメントの数を乗算します。`n`。 

Thus, the solution reduces to computing how many effective independent character slots remain after accounting for all forced constraints from embedding`s`長さのどこでも`n`弦。

 ## アルゴリズムのチュートリアル

 We interpret the problem as counting strings of length`n`を含む文字が 26 文字以上`s`少なくとも 1 回は、直接包含/除外するのではなく、`n`、視点を変えます。まずすべての文字列を数えて、避けた文字列を差し引きます。`s`。 

これにより、問題は、長さのパターンにわたる古典的なオートマトンのカウント問題に変換されます。`m`。 

1. 次のプレフィックス関数を構築します。`s`これは、すべてのプレフィックス終了位置について、プレフィックスでもある最長の境界線を示します。`s`。 これは、文字列を拡張するときに部分一致がどのように遷移するかをエンコードします。 これが必要な理由は、文字列を左から右にスキャンすると、部分一致が検出されるためです。`s`重複する可能性があるため、その状態を追跡する決定的な方法が必要です。 
2. オートマトンを構築する`m`州、ここで州`i`現在、長さのプレフィックスが一致していることを意味します`i`の`s`。 状態やキャラクターごとに`c`、接頭辞関数の遷移を使用して次の状態を計算します。 状態に到達したら`m`、つまり完全に一致しました`s`。 
3. 文字列の長さに対して動的プログラミングを実行します。`n`、しかしそれ以来`n`は 10^18 までであるため、線形に反復することはできません。 代わりに、遷移をサイズの行列として表します。`m × m`、エントリは`(i, j)`状態からの遷移をカウントします`i`に`j`パターンを完成させずに。 
4. この遷移行列で高速累乗を使用して、長さの文字列の数を計算します。`n`末期状態に到達しないようにします。 行列のべき乗が適用される理由は、オートマトンの遷移が状態分布にわたって線形再帰を形成するためです。 
5. しましょう`total = 26^n mod MOD`。 させて`bad`長さの文字列の数になります`n`決して状態に達しないもの`m`。 そうすると答えは`total - bad`。 
6. 計算します`26^n mod MOD`2 進累乗を使用して、行列の累乗の結果を計算します。`bad`。 

### なぜ効果があるのか

 各位置のオートマトンの状態は、次の最も長いプレフィックスを正確にエンコードします。`s`その位置で終わるサフィックスと一致するもの。 これにより、起こり得るすべての事態が確実に防止されます。`s`重複を見逃したり二重にカウントしたりすることなく、発生時に正確に追跡されます。 少なくとも 1 つの出現を含む文字列は最終的に最終状態に達し、それを回避する文字列はすべて最終状態に達します。`s`決して到達しないパスに正確に対応します。 したがって、有効な文字列をカウントすることは、行列のべき乗によって完全に捕捉される有限オートマトン内のパスをカウントすることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def build_prefix(s):
    m = len(s)
    pi = [0] * m
    for i in range(1, m):
        j = pi[i - 1]
        while j > 0 and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
        pi[i] = j
    return pi

def build_automaton(s, pi):
    m = len(s)
    nxt = [[0] * 26 for _ in range(m + 1)]
    for i in range(m + 1):
        for c in range(26):
            if i == m:
                nxt[i][c] = m
                continue
            j = i
            while j > 0 and chr(ord('a') + c) != s[j]:
                j = pi[j - 1]
            if chr(ord('a') + c) == s[j]:
                j += 1
            nxt[i][c] = j
    return nxt

def mat_mul(a, b):
    m = len(a)
    res = [[0] * m for _ in range(m)]
    for i in range(m):
        for k in range(m):
            if a[i][k]:
                for j in range(m):
                    res[i][j] = (res[i][j] + a[i][k] * b[k][j]) % MOD
    return res

def mat_pow(mat, exp):
    m = len(mat)
    res = [[0] * m for _ in range(m)]
    for i in range(m):
        res[i][i] = 1
    while exp:
        if exp & 1:
            res = mat_mul(res, mat)
        mat = mat_mul(mat, mat)
        exp >>= 1
    return res

def solve():
    n, m = map(int, input().split())
    s = input().strip()

    pi = build_prefix(s)
    nxt = build_automaton(s, pi)

    size = m
    trans = [[0] * size for _ in range(size)]

    for i in range(size):
        for c in range(26):
            j = nxt[i][c]
            if j < m:
                trans[i][j] += 1

    mat = mat_pow(trans, n)

    dp0 = [0] * m
    dp0[0] = 1

    bad = 0
    for i in range(m):
        bad = (bad + mat[0][i]) % MOD

    total = pow(26, n, MOD)
    print((total - bad) % MOD)

if __name__ == "__main__":
    solve()
```この実装では、まずプレフィックス関数を構築します。これにより、文字が現在の一致を破った場合に効率的なフォールバックが可能になります。 オートマトンの構築では部分一致状態間の遷移を明示的に定義し、文字列のあらゆる拡張が表現されることを保証します。 

パターンが一致すると、それらの文字列を「回避 s」DP にカウントしたくないため、遷移行列には非終端遷移のみが含まれます。 行列のべき乗は、この遷移システムの長さを引き上げます。`n`、線形反復を行わずに、その長さの可能なすべての文字列を効果的にシミュレートします。 

からの最後の減算`26^n`補数の数を、次の文字列が少なくとも 1 回含まれる文字列の数に変換します。`s`。 

共通の微妙な点は、終了状態を正しく処理することです。DP への再入を避けるために、すべての遷移を吸収する必要があります。そうしないと、オーバーカウントが発生します。

 ## 特殊なケース

 主なエッジケースは、パターンが次のような繰り返しである場合です。`"aaaa..."`。 この場合、接頭辞関数は、すべての文字が一致を延長し続ける長いチェーンを作成します。 オートマトンは多くの遷移を 1 つのパスにまとめます。終了状態の処理が正しくないと、カウントが大幅に過少または過大になります。 正しい構造により、一度の状態が保証されます。`m`に達しても吸収されたままとなるため、そのパターンを含む文字列は「不良」カウントから 1 回だけ除外されます。 

もう 1 つのエッジケースは次のような場合です`m = 1`。 その場合、パターンは 1 つの文字になり、オートマトンは単純な 2 状態システムに縮小されます。 行列のべき乗は引き続き機能しますが、状態 0 からの遷移の初期化に誤りがあると、すべての文字が受け入れを直接トリガーするため、すぐにカウント エラーが発生します。 

最後の微妙なケースは次のような場合です。`n = m`。 ここでは、すべての文字列がパターンと等しいか等しくありません。 オートマトンは、文字列が 1 回だけ一致するかどうかを確認し、からの減算を正しく実行します。`26^n`二重にカウントすることなく、正しい単一オカレンス構造を生成します。
