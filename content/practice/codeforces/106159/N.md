 ## 解決策
 ## 問題の理解

 未知の整数位置から開始するモーションプロセスが与えられています。$X$。 この開始点から、一連の動きが実行されます。 最初の移動は 1 単位前に進み、2 番目の移動は 3 単位後ろに進み、3 番目の移動は 4 単位前に進み、4 番目の移動は 8 単位後ろに進み、というようにステップごとに方向が変わり、ステップの長さは毎回 2 倍になります。 このプロセスが終了すると、次の 2 つの値が表示されます: 総変位$D$、すべての署名された動きの正味合計と最終的な位置を意味します。$Y$、これはプロセスが停止したポイントです。 

タスクは、整数の開始位置が存在するかどうかを判断することです。$X$この決定論的な動きパターンに従うと、指定された最終位置と総変位が正確に生成されます。 そのような場合$X$存在する場合は、それを出力する必要があります。 それ以外の場合は、データに一貫性がないことが報告されます。 

制約は非常に大きく、$D$まで$3 \cdot 10^{18}$までのコーディネート$10^{18}$。 これは、プロセスをステップごとにシミュレーションすることを即座に除外します。そのような大きさに到達するために必要なステップ数は、距離に応じて対数的にのみ増加しますが、構造なしで素朴にアプローチした場合、安全な反復限界をはるかに超えるからです。 どのような解決策も、ムーブメントの構造に関する閉じた形式の観察に依存する必要があります。 

ステップ数が与えられていないという事実から、微妙な特殊なケースが発生します。 この交互の 2 倍化シーケンスの異なるプレフィックスは異なる部分和を生成するため、複数のプレフィックス長を考慮する必要があります。 完全な無限パターンが使用されるという単純な仮定は不正確です。これは、未知のプレフィックス長に対応するランドに到達した時点でプロセスが正確に停止するためです。 

もう 1 つの特殊なケースは、再構築における曖昧さです。$X$。 最終順位だったとしても$Y$が固定されている場合、複数の仮想歩数が同じ変位を生成する可能性があります。$D$、プレフィックス長と開始位置の一貫した組み合わせは 1 つだけ有効です。 

## アプローチ

 プロセスを直接シミュレートしようとすると、次の推測から開始します。$X$、サイズの動きを適用します$1, 3, 4, 8, 16, \dots$交互の符号を使用して、走行変位と最終位置の両方を計算します。 候補者ごとに$X$、観察されたものと一致しようとします$(D, Y)$。 ただし、以来、$X$それ自体は未知であり、与えられた制約内で制限がないため、この総当りアプローチは有限の検索空間としてさえ明確に定義されていません。 適切な範囲を固定したとしても、ステップ サイズが指数関数的に増加するということは、意味のある距離に到達するには次のオーダーが必要になることを意味します。$O(\log D)$シミュレーションごとにステップ数を増やし、可能な開始点をスキャンすると、これは完全に不可能になります。 

重要な洞察は、動きのパターンが開始点から独立しているということです。 後の総変位$k$ステップは等比数列の交互の合計にのみ依存します。$$+1 - 3 + 4 - 8 + 16 - \dots$$動きの接頭辞の合計を次のように定義すると、$S_k$、最終的な位置は$X + S_k$。 一方、変位は、$D$まさに$S_k$。 これは、シーケンスの長さが$k$既知であれば、問題は些細なものになります。$$X = Y - D$$全体的な困難は、有効かどうかを判断することにあります。$k$交互の幾何学的なプレフィックスの合計が次と等しくなるように存在します。$D$、そしてプロセスはそのステップで合法的に停止した可能性があります。 

シーケンスの構造により、プレフィックスの合計を明示的に計算できます。 最初のステップ以降の各ステップは明確なパターンに従います。大きさは次から始まる 2 のべき乗です。$1, 3, 4, 8, 16, \dots$、と標識が交互に表示されます。 これにより、$S_k$閉じた形式で表現可能であり、プレフィックスが一致するかどうかを確認するだけで済みます。$D$。 ステップサイズが指数関数的に増加するため、$k$以下のすべての有効な値について、最大でも約 60 です。$10^{18}$。 

したがって、問題は、すべての実行可能なプレフィックス長を反復処理し、対応する変位を計算し、次の値との一貫性をチェックすることに帰着します。$D$。 有効なプレフィックスが見つかったら、再構築します。$X$直接。

 ## アルゴリズムのチュートリアル

 1. 全プロセス後の正味変位が、開始位置に関係なく、すべての移動ステップの合計に等しいことを観察します。 これにより、役割を分離できるようになります。$X$モーションシーケンス自体から。 
2. 動作シーケンス値を事前計算または反復的に構築します。 最初のステップは$1$、次のすべての大きさが 2 倍になり、符号は正から始まり交互に変化します。 これにより、決定的なプレフィックス合計シーケンスが生成されます。 
3. 考えられるプレフィックス長ごとに$k$、プレフィックスの合計を計算します$S_k$。 これは、プロセスが正確に停止した場合の総変位を表します。$k$動く。 
4. 計算されたそれぞれを比較します$S_k$与えられたものと一緒に$D$。 プレフィックスの合計が一致しない場合$D$の場合、必要な変位を生成する有効な停止点がないため、データに一貫性がありません。 
5. 一致するプレフィックス長が見つかったら、次の関係を使用して開始位置を計算します。$X = Y - D$、最終位置は初期位置に変位を加えたものと等しいためです。 
6. データが計算された結果と一致していることを出力します。$X$。 

### なぜ効果があるのか

 モーション シーケンスは固定されており、開始位置とは独立しているため、考えられるすべてのシナリオがプレフィックス長の選択に独自に対応します。$k$。 それぞれの選択により固有の変位が定義されます$S_k$、最終的な位置は常に$X + S_k$。 したがって、一貫性は次のことを確認することと同じです。$D$シーケンスのプレフィックス合計の 1 つです。 それが成立すると、開始位置は最終位置から変位を減算することによって一意に決定され、曖昧さがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_prefix_sums(limit):
    # sequence: +1, -3, +4, -8, +16, ...
    vals = []
    cur = 1
    sign = 1
    for _ in range(limit):
        vals.append(sign * cur)
        sign *= -1
        if len(vals) >= 2:
            cur *= 2
        else:
            cur = 3  # second term is special: 3 instead of 2
    pref = []
    s = 0
    for v in vals:
        s += v
        pref.append(s)
    return pref

def solve():
    D = int(input())
    Y = int(input())

    # precompute enough terms (log scale bound)
    pref = build_prefix_sums(70)

    ok = False
    for s in pref:
        if s == D:
            ok = True
            break

    if not ok:
        print("Nao")
        return

    X = Y - D
    print("Sim")
    print(X)

if __name__ == "__main__":
    solve()
```実装では、移動シーケンスを明示的に構築し、プレフィックスの合計を構築します。 値が指数関数的に増加するため、シーケンスの長さの上限は 70 です。$10^{18}$はこの範囲内になければなりません。 

一貫性のチェックは、プレフィックス合計に対する単純な線形スキャンです。 見つかったら計算します$X$ID を直接使用する$Y = X + D$。 唯一の微妙な点は、2 番目の項のオフバイ 1 は構造全体を壊すため、シーケンス生成が説明された倍加および交互パターンと正確に一致することを保証することです。

 ## 特殊なケース

 1 つのエッジ ケースは、ディスプレイスメントが非常に初期のプレフィックスと一致する場合に発生します。 たとえば、次の場合$D = 1$、最初の移動の直後にプロセスが停止する可能性があります。 プレフィックス リストに最初の用語が含まれているため、このアルゴリズムはこれを処理し、それ以上の反復を必要とせずに一貫性を正確に識別します。 

もう 1 つの特殊なケースは負の変位です。 シーケンスは符号を交互に変えて大きさが大きくなるため、初期のプレフィックスは次のような負の和を簡単に生成する可能性があります。$-2$。 このチェックでは陽性を想定していないため、これらのケースは正しく受け入れられます。 

最後のエッジ ケースは、許容範囲内で一致するプレフィックスの合計が存在しない場合です。 値は指数関数的に増加するため、すべての一致が欠落すると不整合が生じ、固定された少数のステップを使い果たすとアルゴリズムが終了します。
