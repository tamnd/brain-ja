 ## 解決策
 ## 問題の理解

 平面上に描かれたいくつかの単純な凸多角形が与えられますが、これらは 2 つの多角形がまったく接触していないか、一方がもう一方の内側に完全に収まっているという特別な特性を持っています。 異なるポリゴン間に部分的な重なりやエッジの交差はありません。 

各クエリ ポイントについて、そのポイントが含まれるポリゴンの数を決定する必要があります。 ネスト構造のため、ポイントは複数のポリゴン内に存在できますが、それらのポリゴンは、それぞれが次のポリゴンを厳密に含むチェーンを形成する必要があります。 

入力は、各ポリゴンを反時計回りの頂点のリストとして提供し、次にクエリ ポイントのリストを提供します。 すべてのクエリ ポイントについて、内部にそのクエリ ポイントが含まれるポリゴンの数を出力する必要があります。 

すべてのポリゴンにわたる頂点の合計数が 6×10^5 に達する可能性があり、ポリゴンとクエリの数も大きくなる可能性があるため、制約は合計で大きくなります。 これにより、すべてのポリゴンをすべてのクエリ ポイントに対してチェックするソリューションは即座に除外されます。 K がポリゴン サイズである単純な O(N·Q·K) アプローチでは、最悪の場合、最大 10^11 の演算が必要になりますが、これは実用的な制限をはるかに超えています。 

微妙なエッジ条件は、ネストによりポイントが複数のポリゴンの内側に存在する可能性があることです。 たとえば、ポリゴン A にポリゴン B が含まれており、クエリ ポイントが B の内側にある場合、クエリ ポイントは A の内側にもあります。正解は、単一のポリゴンの内側にあるかどうかだけではなく、そのポイントでの完全なネストの深さです。 

もう 1 つの微妙な点は、凸多角形を使用すると効率的な点包含テストが可能になりますが、これはどの多角形をテストするかがすでにわかっている場合に限ります。 本当に難しいのは、単一のポリゴンをチェックすることではなく、各クエリ ポイントに関連するすべてのポリゴンを効率的に識別することです。 

## アプローチ

 直接的なアプローチは、凸状のポリゴン内ポイント チェックを使用して、各クエリ ポイントをすべてのポリゴンに対してテストすることです。 凸性により、角度にわたる二分探索または O(k) の線形スキャンが可能になるため、おおよそ O(Q · N · log K) が得られますが、N と Q が大きい場合にはそれでも遅すぎます。 

重要な観察は、幾何学的構造から得られます。多角形は、多角形が別の多角形を含まない限り交差しません。 これは、構成全体がネストされた凸多角形の森を形成することを意味します。 ポイントが複数のポリゴン内にある場合、それらのポリゴンはまさにそのポイントを含む最も内側のポリゴンの祖先になります。 

これにより、問題は 2 つの部分に分かれます。 まず、点が特定の凸多角形の内側にあるかどうかをすばやく判断する必要があります。 次に、どのポリゴンにクエリ ポイントが含まれる可能性があるかを効率的に特定する必要があります。 

ポリゴン上に空間検索構造を構築することで、すべてのポリゴンのチェックを回避します。 各ポリゴンはその境界ボックスで表され、これらのボックス上に KD ツリーを構築します。 KD ツリーを使用すると、境界ボックスにクエリ ポイントが含まれないためにクエリ ポイントを含むことができないポリゴンの大部分を取り除くことができます。 

クエリ ポイントの場合、境界ボックスにそのポイントが含まれるノードのみをたどって、KD ツリーを走査します。 訪問した候補ポリゴンごとに、正確な凸ポリゴン内ポイント テストを実行します。 ポイントを含むすべてのポリゴンの中で、最も深く含まれるポリゴンに対応する最大ネスト深度を取得します。 最終的な答えは、深さにレベルごとに 1 を加えたもの、つまり、コンテインメント チェーンに沿って見つかったポリゴンの数と同等になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(Q・N・K) | お(1) | 遅すぎる |
 | KD ツリー + 凸チェック | O((N + Q) log N + Q · log N · log K) 平均 | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: ポリゴンのメタデータを事前計算する

 各ポリゴンについて、頂点リストを介してその境界ボックスと内部点表現を暗黙的に計算します。 境界ボックスは空間枝刈りのみに使用され、頂点リストは正確な点包含テストに使用されます。

この分離が必要なのは、バウンディング ボックスは高速ですが不正確であるのに対し、凸状ポリゴン内ポイント チェックは正確ですがコストが高いためです。 

### ステップ 2: ポリゴン上に KD ツリーを構築する

 各ノードがポリゴンのセットを保存し、バウンディング ボックスの中心の中央座標によって分割し、x 次元と y 次元を交互に行う KD ツリーを構築します。 

各リーフには少数のポリゴンが格納されます。 この構造により、空間的に近いポリゴンが確実にグループ化されます。これは、クエリ中の枝刈りにとって重要です。 

### ステップ 3: ポリゴン内凸点テスト

 点が凸多角形の内側にあるかどうかをテストするには、向きに基づいて三角形の扇形スタイル チェックを使用します。 頂点は反時計回りの順序であるため、点がすべての有向エッジの同じ側に一貫して留まっていることを確認できます。 

エッジがポイントを外側に配置する場合、ポリゴンにはそのポイントは含まれません。 

### ステップ 4: KD ツリー トラバーサルによるクエリ処理

 各クエリ ポイントについて、ルートから開始して KD ツリーをたどります。 

クエリ ポイントがノードの境界ボックスの外側にある場合、そのノードは完全に破棄されます。 それ以外の場合は、その子に進みます。 

葉に到達したら、凸状のポリゴン内ポイント テストを使用して、その中の各ポリゴンをテストします。 ポイントを含むすべてのポリゴンが候補になります。 

### ステップ 5: ネストの深さを抽出する

 クエリ ポイントを含むすべてのポリゴンの中で、ネストの深さが最大のポリゴンを選択します。 これが機能するのは、包含が厳密なツリーを形成するためです。より深いポリゴンは、すべての先祖に完全に含まれる厳密に小さい領域に対応します。 

クエリの答えは単純に、そのチェーンに沿ったポリゴンの数です。 

### なぜ効果があるのか

 正確さは、ポリゴンが層状ファミリーを形成しているという事実に依存します。つまり、2 つのポリゴンが互いに素であるか、一方が他方を含んでいます。 これにより、特定のポイントを含むすべてのポリゴンが包含によって完全に順序付けされることが保証されます。 

KD ツリーは、境界ボックスにクエリ ポイントが含まれるポリゴンのみを考慮することを保証するため、有効な候補が見逃されることはありません。 凸状ポリゴン内ポイント テストにより、誤検知がカウントされないことが保証されます。 封じ込めはチェーンを形成するため、最も深い有効なポリゴンを選択すると、外側のすべてのポリゴンが自動的に考慮され、正しい数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def point_in_convex(poly, x, y):
    n = len(poly)
    prev = None
    for i in range(n):
        x1, y1 = poly[i]
        x2, y2 = poly[(i + 1) % n]
        cx = x2 - x1
        cy = y2 - y1
        px = x - x1
        py = y - y1
        c = cross(cx, cy, px, py)
        if c == 0:
            return False
        if prev is None:
            prev = c > 0
        else:
            if (c > 0) != prev:
                return False
    return True

class Node:
    __slots__ = ("xmin", "xmax", "ymin", "ymax", "left", "right", "items")
    def __init__(self, items):
        self.items = items
        self.left = None
        self.right = None
        self.xmin = self.ymin = float("inf")
        self.xmax = self.ymax = float("-inf")

        for poly in items:
            for x, y in poly["bbox"]:
                self.xmin = min(self.xmin, x)
                self.ymin = min(self.ymin, y)
                self.xmax = max(self.xmax, x)
                self.ymax = max(self.ymax, y)

def build(items, depth=0):
    if len(items) <= 8:
        return Node(items)

    axis = depth % 2
    if axis == 0:
        items.sort(key=lambda p: p["cx"])
    else:
        items.sort(key=lambda p: p["cy"])

    mid = len(items) // 2
    node = Node(items)
    node.items = None
    node.left = build(items[:mid], depth + 1)
    node.right = build(items[mid:], depth + 1)
    return node

def query(node, x, y):
    if node is None:
        return []

    if x < node.xmin or x > node.xmax or y < node.ymin or y > node.ymax:
        return []

    res = []
    if node.items is not None:
        for p in node.items:
            res.append(p)
        return res

    res += query(node.left, x, y)
    res += query(node.right, x, y)
    return res

n, q = map(int, input().split())

polys = []
for _ in range(n):
    k = int(input())
    poly = []
    xs = []
    ys = []
    for _ in range(k):
        x, y = map(int, input().split())
        poly.append((x, y))
        xs.append(x)
        ys.append(y)
    xmin, xmax = min(xs), max(xs)
    ymin, ymax = min(ys), max(ys)

    polys.append({
        "poly": poly,
        "bbox": [(xmin, ymin), (xmax, ymax)],
        "cx": sum(xs) / k,
        "cy": sum(ys) / k
    })

root = build(polys)

for _ in range(q):
    x, y = map(int, input().split())
    candidates = query(root, x, y)

    best = 0
    for p in candidates:
        if point_in_convex(p["poly"], x, y):
            best += 1

    print(best)
```KD ツリー構築では、空間的局所性が保たれるようにポリゴンをグループ化します。 クエリはまず境界ボックスでフィルタリングし、次に可能性の高い候補に対してのみ正確な凸チェックを実行します。 最後のループでは、ポイントを含むポリゴンの数がカウントされます。これは、層状構造によるネストの深さに相当します。 

微妙な実装の詳細は、凸テストにおける境界ケースの厳密な処理です。 この問題では、クエリ点がエッジや頂点上にないことが保証されるため、厳密な不等式チェックは安全であり、曖昧さが回避されます。

 ## 特殊なケース

 主なエッジケースは、ポリゴンが深くネストされている場合です。 このシナリオでは、最小のポリゴン内のクエリ ポイントは、外側のすべてのポリゴンの内側にもあります。 各包含チェックが独立しており、すべての有効なポリゴンがカウントされるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、多くのポリゴンが同様の境界ボックスを共有する場合です。 その場合でも、KD ツリーは複数の候補を返す可能性がありますが、各候補は正確な凸テストを使用して検証されるため、正確性は保たれます。 

最後に、ポリゴンの境界近くの点は問題ステートメントによって除外され、方向テストにおける数値の不安定性が回避されます。
