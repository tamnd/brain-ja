 ## 解決策
 ## 問題の理解

 私たちは一連の曲を与えられており、それぞれがプラスまたはマイナスの値に関連付けられています。 これらの曲のサブセットを選択して、選択した値の合計を最大化したいと考えていますが、間隔の制限があります。`i`、その後、次の曲を選択することは禁止されます`K - 1`位置、厳密に間のインデックスを意味します`i`そして`i + K`選択することはできません。 

タスクは、曲をまったく選択しない可能性も含めて、このルールに基づいて可能な限り最良の合計を計算することであり、合計がゼロになります。 

制約により、最大で`N = 10^5`要素。 すべてのサブセット、さらにはすべての有効な組み合わせを試す単純なソリューションでは、指数関数的に爆発的に増加し、位置ごとに以前のすべての候補をチェックする動的プログラミングでさえ、二次的な動作の危険性があります。 1 秒の制限があるため、ほぼ直線または直線に近い時間を目指す必要があります。これより悪くないことは確かです。`O(N log N)`。 

すべての値が負の場合、微妙なエッジ ケースが発生します。 貪欲な解釈や強制的な選択の解釈では、誤って一部の曲が選択される可能性がありますが、最適な戦略は、何も選択せずにゼロを出力することです。 もう 1 つのエッジケースは次のような場合です`K = 1`これにより、すべての制限が削除され、問題が単純にすべてのポジティブな貢献を受け入れることになります。 

## アプローチ

 ブルートフォース手法では、曲のすべてのサブセットを試して、間隔ルールを遵守しているかどうかを確認します。 これは正しいですが、実行不可能です。`2^N`サブセットを作成し、各サブセットを検証するだけでも直線的な時間がかかり、実行時間が天文学的に長くなります。 

より構造化されたブルート フォースは、各インデックスで決定を行うことでわずかに改善されます。`i`そしてジャンプして`i + K`、またはスキップして次へ移動します。`i + 1`。 この再帰では、すべての有効な解が正しく探索されますが、依然として分岐が大きく、同じサフィックス状態が繰り返し再計算されるため、最悪の場合は指数関数的な動作につながります。 

重要な観察は、問題には位置に対して最適な下部構造があるということです。 インデックスから最良の回答を定義すると`i`、それは将来の選択とその時点での決定にのみ依存します。`i`ローカルです: それを含めて前方にスキップします`K`、またはそれを除外して続行します。`i + 1`。 これは当然、インデックスに対する動的プログラミングにつながります。 

私たちは定義します`dp[i]`位置から開始して取得できる最大合計として`i`。 次に、将来の状態がすでにわかっているように、逆の順序で遷移を計算します。 これにより、問題は線形 DP に縮小されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N) | O(N) | 遅すぎる |
 | インデックスに対する DP | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を右から左に処理して、位置にあるときに次のようにします。`i`、それを超えたポジションについての最良の答えはすでにわかっています。 

1. DP 配列を定義する`dp`サイズの`N + K + 5`、ゼロで初期化されます。 余分なスペースにより、前方にジャンプする際の境界チェックが回避されます。 
2. 反復する`i`から`N`まで`1`。 各位置で 2 つの可能性を計算します。 
3. 最初のオプションは、現在の曲をスキップすることです。これにより、価値が得られます。`dp[i + 1]`。 これは曲を使用しないことを表します`i`全然。 
4. 2 番目のオプションは曲を撮ることです`i`、価値を与える`A[i] + dp[i + K]`。 これは、選択した後なので機能します`i`、次の有効な位置は`i + K`。 
5.セット`dp[i]`これら 2 つの値の最大値まで。 
6. 表に記入すると、答えは次のようになります。`dp[1]`、ただし、空の選択を許可するためにゼロと比較することもできます。 

### なぜ効果があるのか

 すべてのインデックスで`i`、州`dp[i]`インデックスのみを使用して達成可能な最良の合計を取得します`i`そしてその先へ。 有効なソリューションには次のいずれかを含める必要があります。`i`またはそれを除外します。 除外する場合`i`、まさにその通りです`dp[i + 1]`。 含まれている場合`i`、制限により、次の選択は強制的に開始されます。`i + K`そこからの最良の継続は`dp[i + K]`。 どちらの選択も重複することなくすべての有効な可能性を列挙するため、再帰が完了し、配列の最後から帰納的に最大値を取得することで最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K = map(int, input().split())
    A = list(map(int, input().split()))
    
    # 1-index the array for clarity
    A = [0] + A
    
    dp = [0] * (N + K + 5)
    
    for i in range(N, 0, -1):
        take = A[i] + dp[i + K]
        skip = dp[i + 1]
        dp[i] = max(take, skip)
    
    print(max(0, dp[1]))

if __name__ == "__main__":
    solve()
```DP 配列のサイズは追加のパディングを使用して設定されるため、`i + K`そして`i + 1`は常に有効なアクセスであり、ループ内の条件チェックを回避します。 遷移は、各インデックスでの 2 つの可能な決定を直接エンコードします。 

決勝戦`max(0, dp[1])`再帰では位置から開始する必要があると想定されているため、これは不可欠です`1`ただし、すべての寄与がマイナスの場合、最適な戦略には何も選択しないことが含まれる可能性があります。 

## 実用的な例

 ### 例 1

 入力:`N = 3, K = 1, A = [1, 2, 3]`ここ`K = 1`ピック間に事実上制限がないことを意味します。 

| 私 | A[i] | dp[i+1] | A[i] + dp[i+K] | dp[i] |
 | --- | --- | --- | --- | --- |
 | 3 | 3 | 0 | 3 | 3 |
 | 2 | 2 | 3 | 5 | 5 |
 | 1 | 1 | 5 | 6 | 6 |

 最終結果は`6`, すべての要素を取得できることを確認します。 

### 例 2

 入力:`N = 4, K = 4, A = [2, 3, 0, 2]`ここで、任意のインデックスを選択すると、他のすべてのインデックスがブロックされます。 

| 私 | A[i] | dp[i+1] | A[i] + dp[i+K] | dp[i] |
 | --- | --- | --- | --- | --- |
 | 4 | 2 | 0 | 2 | 2 |
 | 3 | 0 | 2 | 0 | 2 |
 | 2 | 3 | 2 | 3 | 3 |
 | 1 | 2 | 3 | 2 | 3 |

 最適な答えは`3`、2番目の曲の選択に対応します。 

これらのトレースは、DP が将来の可用性に対してローカル ゲインのバランスを自然にどのように取るかを示しています。

 ## 特殊なケース

 すべての値が負の場合でも、DP は達成可能な最良のサフィックス合計を計算しますが、結果を明示的にクランプしない限り、すべての遷移で負の値が伝播されます。 決勝戦`max(0, dp[1])`たとえすべての選択肢が合計を減らすとしても、空の選択が優先されることが保証されます。 

入力用`N = 3, K = 2, A = [-1, -2, -3]`, DPは以下のように進化します。 で`i = 3`、`dp[3] = max(-3, 0) = 0`。 で`i = 2`、与えるものを取る`-2 + dp[4] = -2`、スキップすると、`0`、 それで`dp[2] = 0`。 で`i = 1`、与えるものを取る`-1 + dp[3] = -1`、スキップすると、`0`、 それで`dp[1] = 0`。 最終的な答えは、`0`、空のプレイリストと一致します。 

いつ`K = 1`、すべてのインデックスは独立しています。 のために`A = [1, 2, 3]`、各州の取得を比較します。`A[i] + dp[i+1]`スキップに対して`dp[i+1]`これは、単純にすべてのプラスを累積することになり、すべての貢献が有益であるため、DP はすべてを正しく合計します。
