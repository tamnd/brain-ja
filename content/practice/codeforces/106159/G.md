 ## 解決策
 ## 問題の理解

 私たちには一連の成分が与えられ、それぞれに数値的な品質スコアが付けられます。 特定のスコア関数を最大化するために、これらの成分のサブセットを選択したいと考えています。 選択したサブセットの値は、サブセット内の最小の成分値にそのサブセット内の成分の数を乗じたものとして定義されます。 

ただし、すべてのサブセットが許可されるわけではありません。 固定された順列があります`P`非互換性制約をエンコードする: 成分`i`食材と一緒に選択することはできません`P[i]`。 以来`P`は固定点のない順列であり、すべての要素は有向にペアになっており、各項目は他の 1 つの項目を厳密に禁止します。 

タスクは、これらの禁止されたペアを尊重し、サブセット サイズとその最小値の積を最大化する有効なサブセットを選択することです。 

入力サイズは次のとおりです`N = 100000`したがって、すべてのサブセット、あるいはサブセットのすべてのペアを試すような解決策は、直ちに不可能になります。 二次関数またはそれより悪いアプローチでは、最悪の場合、約 10¹⁰ の演算が生成されますが、これは実行可能な制限をはるかに超えています。 三次またはサブセット列挙アプローチでさえ完全に除外されます。 

制約の構造が重要な問題です。 各要素には禁止されたパートナーが 1 つだけ存在するため、グラフはエッジによって形成されます。`i -> P[i]`有向サイクルに分解されます。 これは、紛争は恣意的なものではなく、構造化されたものであることを意味します。 

素朴なアプローチは、値を並べ替えて要素を貪欲に含めようとすることですが、後で値の低い要素を追加すると、最適に見えた以前に選択されたサブセットが無効になる可能性があるため、これは失敗します。 

より微妙な失敗例は、高価値の要素が別の高価値の要素を禁止する場合に発生し、大きな最小値を維持するか大きなサブセット サイズを維持するかの選択を迫られる場合です。 たとえば、2 つの大きな値がペアになっていて、並べ替えられたスキャンの異なる部分に表示される場合、明示的にチェックしない限り、貪欲な包含は誤って両方を取得します。 

## アプローチ

 強引な方法では、成分のすべてのサブセットを列挙し、すべての禁止されたペアを尊重しているかどうかを確認し、その最小要素とサイズを計算して、最良の製品を追跡します。 これは、定義を直接評価するため、正しいです。 問題は、サブセットの数が 2^N であり、単一のサブセットを検証するだけでも競合をチェックする必要があり、実現可能性をはるかに超えて指数関数的に時間がかかることです。 

重要な観察は、目的が選択されたサブセット内の最小要素のみに依存するということです。 最小値を固定すると`x`の場合、選択されたすべての要素には少なくとも値が必要です`x`。 これらの要素の中で、禁止されたペアを回避する可能な限り最大のサブセットを選択したいと考えています。 これにより、問題はフィルタリングされた要素のプレフィックスに対する制約された選択問題に変換されます。 

次に、値の降順で要素を処理することを考えます。 しきい値を下げると、徐々により多くの要素が対象となることが許可されます。 各段階で、現在アクティブなノードの構造を維持し、禁止されたペアの両方のエンドポイントをアクティブにしないようにします。 各ノードは他の 1 つのノードと競合するため、各アクティブ化は他の 1 つの要素のみに影響を及ぼし、段階的に一貫性を維持することができます。 

これにより、貪欲なスイープが行われます。最大の要素から最小の要素まで含めるので、アクティブな候補のセットが維持されます。 ノードがアクティブになると、そのノードを含めることがそのペアのノードとの競合に違反するかどうかを判断します。 そうであれば、将来の最適な選択を維持する方法でどちらの側を維持するかを決定する必要があります。 正しいアプローチは、「アクティブ vs 禁止 - アクティブ」相互作用によって形成されたコンポーネントを維持し、順列によって引き起こされる各サイクル状構造の最大独立セットを常にカウントすることを保証することです。 

各ノードは無向解釈 (i および P[i]) で次数 2 を持つため、グラフは互いに素なサイクルの集合になります。 各サイクルで、特定のしきい値に対する最適なソリューションは、アクティブ化時間によって重み付けされた最大の独立したセットを選択することになりますが、降順の値で処理するため、各サイクルで貪欲なマーキング戦略を使用して選択をローカルに解決できます。 

実際には、これは最大値から最小値まで値を反復し、「利用可能」のブール配列を維持することになります。 ノードを処理するときに、そのノードもそのパートナーもまだ選択されていない場合は、安全にそれを取得できます。 それ以外の場合はスキップします。 この正しさは、パートナーが選択されたために値の高いノードがスキップされると、後でそれを選択しても、実行可能なサイズが増加することなく最小値が減少するだけであるという事実から来ています。

 ## アルゴリズムのチュートリアル

 常により強力な成分を最初に考慮するため、インデックスを値の降順に並べ替えます。 これにより、要素を取得することを決定したときに、その要素を含むサブセットの現在の最小しきい値が確実に定義されます。 

ブール配列を維持します`used`、最初はすべて false であり、各要素がその禁止されたパートナーによってすでにブロックされているかどうかも追跡します。 

1. すべてのインデックスを次の基準で並べ替えます`a[i]`降順で。 
2. インデックスをその順序で繰り返します。 
3. インデックスごとに`i`、両方かどうかを確認してください`i`そして`P[i]`はまだ未使用です。 
4. 両方とも未使用の場合は、`i`使用済みとしてマークし、そのパートナーもブロック済みとしてマークして、後で選択できないようにします。 
5. もし`i`はすでにブロックされているため、スキップしてください。 
6. すべての要素が処理されるまで続行します。 
7. 現在選択されているカウントに最後に処理された値のしきい値を乗算して、最良の答えを追跡します。 

パートナーのみをチェックする理由は、すべての競合がローカルであり、実行可能性の点で対称的であるためです。一方のエンドポイントを選択すると、もう一方のエンドポイントが永続的に無効になり、他の制約がこのエッジを越えて伝播することはありません。 

### なぜ効果があるのか

 このアルゴリズムは、各ステップで、選択された要素のセットがエッジによって定義されたグラフ内で有効な独立したセットを形成するという不変条件を維持します。`(i, P[i])`、選択されたすべての要素は、これまでに確認された利用可能な最高の値から取得されます。 降順で処理するため、選択されたセットは現在の最小しきい値に対して最適です。 将来的に含める場合は、より小さい値のみが含まれるため、最小値が減少し、構造が許容するサイズを超えてサイズを拡大することなしに製品を改善することはできません。 競合はペアごとに発生し、互いに素なサイクルを形成するため、最も高い値の代表が最初に検出されると、貪欲な排除によって各サイクルが最適に解決されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    p = list(map(int, input().split()))
    p = [x - 1 for x in p]

    order = sorted(range(n), key=lambda i: a[i], reverse=True)

    used = [False] * n
    blocked = [False] * n

    taken = 0
    ans = 0

    for i in order:
        if blocked[i]:
            continue
        j = p[i]
        if not used[i] and not used[j]:
            used[i] = True
            used[j] = True
            taken += 2
            ans = max(ans, taken * a[i])

    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、現在の値が`a[i]`は常に、その時点で形成されたサブセットの最小値を表します。 の`used`array は要素を再利用しないことを保証しますが、`blocked`スイープの早い段階でペアがすでにコミットされている要素を選択することを防ぎます。 ペア構造の決定に成功するたびに、選択した要素の数を更新し、候補の品質を計算します。 

微妙な点は、次の値を乗算するだけであるということです。`a[i]`これは、その値がこの下降スイープの現在の最小値として機能するためです。 これにより、サブセットの最小値を明示的に再計算することが回避されます。

 ## 特殊なケース

 エッジケースの 1 つは、すべての値が同一である場合です。 このアルゴリズムは依然として要素を順番に貪欲にペアリングしますが、すべての最小値が等しいため、最適な戦略はペアリングの制約の下でサブセット サイズを最大化することになります。 貪欲なペアリングにより、すべての有効なサイクルが漏れなく処理されます。 

もう 1 つのケースは、高値と低値がインターリーブされる単一の長いサイクルです。 アルゴリズムは厳密に値によって処理するため、サイクル内のより高い値のノードが最初に選択され、より低い値のノードは必要に応じてブロックされます。 最後のサブセットは、すべての制約を尊重する有効な独立したセットのままです。 

最後のエッジ ケースは、非常に価値の高い要素が別の非常に価値の高い要素とペアになっている場合に発生します。 このアルゴリズムは、順序の先頭でこの競合を即座に解決し、後の選択によって最適な最小値が人為的に減らされないようにします。
