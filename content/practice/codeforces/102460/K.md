 ## 解決策
 ## 問題の理解

 パッケージのコレクションがあり、各パッケージにはプラスのサイズがあります。 バンドル操作では、現在のバンドルを 2 つだけ選択し、それらを 1 つの新しいバンドルに結合し、2 つのバンドル サイズの合計に等しい長さのロープを消費します。 新しいバンドルは同じ結合サイズを持ち、後の操作で使用できます。 

(n) 個の個別パッケージから始めて、最終的なバンドルを 1 つ取得するには、正確に (n-1) 回の操作が必要です。 これらの操作の順序によって消費されるロープの総量が変化するため、タスクは総量を最小化する順序を選択することです。 

たとえば、パッケージ サイズ (1、2、3) の場合、(1+2=3) を組み合わせるとコスト (3)、次に (3+3=6) を組み合わせるとコスト (6) となり、合計は (9) になります。 代わりに (2+3=5) を最初に組み合わせると (5+(1+5)=11) が得られるため、最初の順序の方が優れています。 

各テスト ケースには、パッケージの数とそのサイズが含まれます。 出力は、すべてのパッケージを 1 つのバンドルに結合するために必要な、可能な最小の合計ロープ長です。 

制約は (n\leq1000) を与え、最大 (10) のテスト ケースを持ちます。 これは (O(n\log n)) アルゴリズムや一部の (O(n^2)) アプローチにとっては十分小さいですが、網羅的な検索は完全に不可能です。 可能なマージ シーケンスの数は階乗的に増加するため、可能な順序を列挙するのではなく、コストの構造を利用する必要があります。 

パッケージ サイズは最大 (1000) ですが、同じ結合されたパッケージがその後のいくつかのマージに寄与する可能性があるため、合計の答えは個々のパッケージ サイズよりも大きくなります。 安全な実装では、合計を保持できる整数型で答えを蓄積する必要があります。 Python の整数には任意の精度があるため、提出されたソリューションにはオーバーフローの問題はありません。 

不注意な実装が露呈する可能性のあるエッジケースがいくつかあります。 

パッケージが 1 つだけの場合、同梱作業は必要ありません。 入力用`1`に続く`7`、正しい出力は次のとおりです。`0`。 1 つが残るまで 2 つの要素を盲目的に削除する実装は、削除するペアがないために失敗する可能性があります。 

2 つのパッケージの場合、可能な操作は 1 つだけです。 入力用```
1
2
1 1000
```答えは`1001`。 少なくとも 3 つのパッケージがあることを前提としたアルゴリズムや、不必要な追加のマージを実行するアルゴリズムでは、結果が間違ってしまいます。 

繰り返される値も通常どおりに処理する必要があります。 4つのサイズのパッケージ用`4`、最適なシーケンスのコスト (8+8+16=32)。 等しい要素を特別に並べ替えて扱うことは不必要であり、誤った仮定が生じる可能性があります。 

最後に、マージのたびに、現在の最小の 2 つのバンドルを再度選択する必要があります。 元の配列を 1 回ソートし、隣接する要素を繰り返し結合するだけでは十分ではありません。 たとえば、`1 2 3 100`、組み合わせて`1+2=3`、 それから`3+3=6`、 それから`6+100=106`(115) が得られます。 元のソート順のペアにコミットする戦略は、新しく作成されたバンドルがすぐに将来のマージの候補になるという事実を正しくモデル化しません。 

## アプローチ

 直接的な総当たりソリューションでは、すべての段階ですべての可能なペアを試すことができます。 (k) 個の現在のバンドルがある時点で、次のマージには (\binom{k}{2}) 個の選択肢があります。 考えられるすべてのシーケンスを調査すると、完全なマージ シーケンスの数は次のようになります。 

\frac{n!(n-1)!}{2^{n-1}}。 
】

 これは、比較的小さい (n) 場合にはすでに膨大であり、(n=1000) の場合は完全に計算を超えています。 すべての法的なバンドル注文が明示的に考慮されるため、強引な方法は正しいのですが、注文数が急速に増加します。 

有益な観察は、すべてのマージには、マージされる 2 つのバンドルの合計に等しいコストがかかり、その結果の合計自体が後の操作に参加するバンドルになるということです。 これは、大きなバンドルを早期に作成すると、後のマージでそのサイズが再度課金されるため、コストがかかることを意味します。 

現在のバンドル サイズに (x\leq y\leq z) が含まれているとします。 最初に (y) と (z) をマージすると、結果として得られるバンドルのサイズは (y+z) になります。これは、2 つの最小バンドルをマージした結果である (x+y) と少なくとも同じ大きさになります。 大きな中間バンドルは再びカウントされる機会が増えるため、大きな値を延期することは有益です。 

したがって、欲張りな選択は、2 つの最小の現在のバンドルを常にマージすることです。 

これは、最適なマージ パターンとハフマン コーディングの背後にある同じ構造的な考え方です。 すべての元のパッケージは、通過するマージ レベルごとに 1 回合計に寄与します。 小さなパッケージはマージ構造のより深くに安全に配置できますが、大きなパッケージを初期のマージで繰り返し運ぶとコストが増加します。 すべての段階で 2 つの最小のバンドルを選択すると、最適なバイナリ マージ ツリーが生成されます。 

ブルート フォースは、考えられるすべてのマージ ツリーを検査するため機能しますが、ツリーが多すぎるために失敗します。 利用可能な 2 つの最小のバンドルをマージすることで最適なツリーを常に構築できるという観察により、他のすべての選択肢を破棄できます。 必要なのは、最小の 2 つの値を繰り返し取得して削除し、それらの合計を挿入できるデータ構造だけです。 

最小ヒープは、これらの操作を (O(\log n)) 時間で正確に提供します。 (n-1) 個のマージを実行し、(O(n\log n)) 個の解を与えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O\left(\frac{n!(n-1)!}{2^{n-1}}\right)) シーケンスをマージする | (O(n)) 検索パスごと | 遅すぎる |
 | 最適 | (O(n\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在のテスト ケースのすべてのパッケージ サイズを読み取り、それらを最小ヒープに配置します。 ヒープは現在利用可能な最小のバンドルをルートに保持するため、次の 2 つの候補を見つけるためにコレクション全体をスキャンする必要はありません。 
2. 答えをゼロに初期化します。 これは、これまでに実行されたすべてのマージによって消費されたロープの合計を表します。 
3. 複数のバンドルが残っている間に、最も小さい 2 つのバンドル サイズをヒープから削除します。 これらは、貪欲ルールによってマージされる必要がある 2 つのバンドルです。 
4. それらの合計を答えに加えます。 この合計は、現在のバンドル操作によって消費されるロープとまったく同じです。 
5. 同じ合計をヒープに戻します。 新しく作成されたバンドルは依然として物理バンドルであり、後で再度結合する必要がある場合があるため、完全に削除すると問題の状態の一部が失われます。 
6. バンドルが 1 つだけ残っている場合、すべての元のパッケージがそのバンドルに組み込まれています。 累積された答えがロープの最小合計長になるので、それを印刷します。 

### なぜ効果があるのか

 重要な不変点は、マージのたびに、ヒープには現在存在するすべてのバンドルのサイズが正確に含まれるということです。 貪欲な選択では、常にそれらのうち最も小さい 2 つが削除されます。

この選択が最適である理由を確認するには、一連の操作を表す最適なマージ ツリーを検討してください。 このようなツリーの最も深い 2 つのリーフは、合計コストを増加させることなく、2 つの最小のパッケージまたはバンドル サイズに対応するように選択できます。 これら 2 つのオブジェクトは最も深いレベルでマージされます。つまり、それらの合計はできるだけ遅く作成されます。 オブジェクトがマージに参加するたびに、そのサイズが合計に寄与するため、最小のオブジェクトを最も奥に配置すると、それらの繰り返しの寄与が最小限に抑えられます。 最も深いペアを利用可能な 2 つの最小値に置き換えても、コストが増加することはありません。 そのマージを実行した後、同じ引数が残りのバンドルに適用されます。 この議論を繰り返すと、常に 2 つの最小の現在のバンドルをマージすると最適な合計が得られることが証明されます。 

ヒープの実装は、この証明に正確に従っています。 すべての段階で、将来の決定のために残りのすべてのバンドルを保存しながら、ローカルで必要な貪欲な選択を行います。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        heap = list(map(int, input().split()))
        heapq.heapify(heap)

        total = 0

        while len(heap) > 1:
            a = heapq.heappop(heap)
            b = heapq.heappop(heap)

            merged = a + b
            total += merged

            heapq.heappush(heap, merged)

        out.append(str(total))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力ループは、一度に 1 つの完全なテスト ケースを読み取ります。 パッケージのサイズはリストに直接変換され、次の最小ヒープに変換されます。`heapq.heapify`これには、すべての要素を個別に挿入するよりも直線的な時間がかかります。 

マージループは使用します`len(heap) > 1`その境界として。 残り 1 束でプロセスは完了です。 この条件は、ループがスキップされ、答えが 0 のままであるため、(n=1) の場合も自然に処理します。 

各反復では、正確に 2 つの値が削除されます。`heappop`。 それらの合計は、この操作のロープ コストと新しく形成されたバンドルのサイズの両方になります。 その値を追加すると、`total`同じバンドルが後のマージに参加する可能性があるため、プッシュバックする前に行うことが重要です。 

パイソンの`int`type は整数のオーバーフローを回避します。 中間バンドルの最大値は最大でも元のサイズの合計ですが、バンドルは繰り返し請求されるため、累積コストはさらに大きくなる可能性があります。 制約によっても、結果は快適に管理できる状態に保たれます。 

ヒープはテスト ケースごとに独立して再構築されます。 ケース間で状態が共有されることはないため、あるテスト ケースのパッケージが別のテスト ケースに誤って影響を与えることがなくなります。

import sys
import io
import heapq

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        heap = list(map(int, input().split()))
        heapq.heapify(heap)

        total = 0

        while len(heap) > 1:
            a = heapq.heappop(heap)
            b = heapq.heappop(heap)
            merged = a + b
            total += merged
            heapq.heappush(heap, merged)

        out.append(str(total))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

 ## 特殊なケース

 ヒープには最初に 1 つの要素が含まれているため、1 パッケージのケースが処理されます。 条件`len(heap) > 1`は false であるため、値は削除されず、累積された答えはゼロのままです。 のために```
1
1
7
```出力は`0`。 

2 つのパッケージの場合、アルゴリズムはマージを 1 回だけ実行します。 と```
1
2
1 1000
```ヒープは次のように始まります`[1, 1000]`。 2 つの値が削除され、その合計が`1001`が回答に追加され、結果が挿入されます。 1 つのバンドルが残っているため、出力は次のようになります。`1001`。 

パッケージ サイズが等しい場合、特別な処理は必要ありません。 4つのサイズのパッケージ入り`4`、最初の 2 つのマージは次のとおりです。`4+4=8`そして`4+4=8`。 残りのバンドルは、`8`そして`8`にマージします`16`。 合計は(8+8+16=32)となります。 ヒープはすべての出現を独立して保存するため、自然に等しい値を処理します。 

最も一般的な状態管理エラーは、新しく形成されたバンドルがコレクションに戻される必要があることを忘れることです。 のために```
1
3
1 1 1
```最初の操作で 2 つが削除されます`1`と作成します`2`のコストがかかります`2`。 ヒープには現在次のものが含まれています`1`そして`2`。 これら 2 つは別のコストで統合されます`3`、合計を与えます`5`。 これにより、期待される答えが実際には`5`、 ない`3`。 正しいトレースは`1+1=2`、 に続く`1+2=3`したがって、出力は次のようになります`5`。 期待しているテスト`3`最初にマージされたバンドルが最終操作に参加していないかのように誤って扱われます。 

最大サイズ1000梱包サイズの場合`1`、ヒープは 999 回のマージを実行します。 最適なマージ ツリーには深さ 9 に 24 枚の葉があり、深さ 10 に 976 枚の葉があり、合計の重み付き深さは (24\cdot9+976\cdot10=9976) になります。 ヒープは正確にこの値を生成し、操作数が最大値に近づいても実装が正しいままであることを確認します。
