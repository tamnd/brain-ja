 ## 解決策
 ## 問題の理解

 二項係数の特別な剰余を計算する必要があります。 (M)、(N)、および (D) が与えられ、(0 \le N \le M) で次のように考えます。 

[
 C(M,N)=\frac{M!}{N!(M-N)!}。 
】

 DivModulo 演算は、この数値の剰余 (D) を単純に取得するわけではありません。 代わりに、可能な限り (D) の完全な要素を繰り返し削除します。 もし

 [
 C(M,N)=X D^h
 】

 ここで (D\nmid X)、必要な答えは (X\bmod D) です。 

この区別は、二項係数が (D) で割り切れる場合に重要になります。 たとえば、(C(5,2)=10=2\cdot5) なので、通常のモジュロでは (0) が得られますが、DivModulo では (2) が得られます。 

入力サイズにより、直接階乗計算が不可能になります。 (M) は (4\cdot10^{18}) に達する可能性があるため、(O(M)) アルゴリズムでも約 (4\cdot10^{18}) 回の反復が必要になります。 正確な階乗も構築するには大きすぎます。 代わりに有用なサイズは (D) で、最大でも (1.6\cdot10^7) です。 これは、高価な前処理が (D) に依存し、巨大な値 (M) と (N) が対数回帰によって処理されるアルゴリズムを強く示唆しています。 

間違ったアプローチを明らかにするいくつかのエッジケースがあります。 

入力用`5 2 5`、二項係数は (10) です。 通常の剰余算術では (10\bmod5=0) となりますが、(5) の因数を 1 つ取り除く必要があるため、正解は (2) になります。 

入力用`6 2 6`、二項係数は (15) です。 (6) も (6^2) も (15) を割り切れないので、答えは (15\bmod6=3) になります。 (D) の素因数を独立して削除する不注意な実装では、DivModulo 演算では (6) の完全な因数しか削除されないにもかかわらず、因数 (2) または (3) が削除されてしまいます。 

入力用`1 0 2`の場合、(0!=1) であるため、二項係数は (1) になります。 (2) は取り除く要素がないので、答えは (1) になります。 (N>0) を想定する実装、または空の階乗を誤って扱う実装は、ここで失敗する可能性があります。 

入力用`6 3 6`、二項係数は (20) です。 (6\nmid20) なので何も削除されず、答えは (20\bmod6=2) になります。 (20) の素数評価が異なるため、これは有用な境界ケースです。(2) には 2 つの因子がありますが、(3) には因子がありません。 

## アプローチ

 ブルートフォースアプローチは簡単です。 階乗を計算し、二項係数を形成し、繰り返し (D) で除算し、最後に剰余を取ることができます。 それほど極端ではないバージョンでは、二項係数を乗算的に生成できますが、最悪の場合でも (\Theta(M)) の算術ステップが必要です。 (M=4\cdot10^{18}) では、操作される膨大な整数のコストを考慮する前に、およそ 4 京回の反復が必要になることを意味します。 パスカルの三角形はさらに実用的ではありません。 ブルート フォース手法は定義に直接従うため正しいですが、入力の制限により使用できなくなります。 

重要な観察は、(D) の要素を完全に取り除くことが評価上の問題であるということです。 係数 (D) として

 [
 D=\prod_{i=1}^s p_i^{a_i},
 】

 ここで、(p_i) は個別の素数です。 

しましょう

 [
 e_i=v_{p_i}(C(M,N))。 
】

 (D) の完全なコピーは、(i) ごとに (p_i) の (a_i) 個のコピーを消費します。 したがって、二項係数に含まれる (D) の完全なコピーの数は次のようになります。 

[
 K=\min_i\left\lfloor\frac{e_i}{a_i}\right\rfloor。 
】

 したがって、必要な整数は次のようになります。 

[
 R=\frac{C(M,N)}{D^K}。 
】

 (C(M,N)) 自体を計算することはできませんが、(D) を法とする (R) だけが必要です。 素数べき乗 (p_i^{a_i}) はペアごとに互いに素であるため、各素数べき乗を法として個別に (R) を計算し、その結果を中国剰余定理と組み合わせることができます。 

プライムパワーを1つ固定する

 [
 q=p^a。 
】

 二項係数が (p) 進評価 (e=v_p(C(M,N))) を持つと仮定します。 (D^K) を削除した後、残りの (p) 進指数は次のようになります。 

[
 k=e-aK。 
】

 二項係数を次のように書きます。 

[
 C(M,N)=p^eU、
 】

 ここで、(U) は (p) で割り切れません。 それから

 p^k U\left(\frac{D}{q}\right)^{-K}。 
】

 モジュロ (q)、(D/q) には因数 (p) が含まれていないため、分母は反転可能です。 したがって、残りのタスクは、(q) を法とする二項係数の (p) を含まない部分 (U) を計算することです。 

階乗の場合、次のように定義します。 

[
 F_p(n)=\frac{n!}{p^{v_p(n!)}}。 
】

 この値は常に (p) と互いに素であるため、逆モジュロ (q) を持ちます。 二項式の (p) を含まない部分は次のようになります。 

[
 同等品
 F_p(M)F_p(N)^{-1}F_p(M-N)^{-1}\pmod q.
 】

 重要な反復は、(n!) 内の (p) の倍数を分離することによって発生します。 (p) のすべての倍数から 1 つの因数 (p) を削除することができ、(p) で除算した後の対応する数値の (p) のない部分がそのまま残ります。 したがって、

 F_p\left(\left\lfloor\frac np\right\rfloor\right)
 \prod_{\substack{1\le i\le n\p\nmid i}}i
 \pmod q.
 】

 残りの積は、長さ (q=p^a) のブロック単位で周期的です。 もし

 [
 G(x)=\prod_{\substack{1\le i\le x\p\nmid i}}i\pmod q,
 】

 それから

 G(q-1)^{\lfloor n/q\rfloor}G(n\bmod q)
 \pmod q.
 】

 (O(q)) 時間内の (0\le x<q) ごとに (G(x)) を事前計算できます。 後続の階乗計算では、(n) が (\lfloor n/p\rfloor) に繰り返し置き換えられるため、必要なレベルは (O(\log_p M)) だけです。 

この総当たり法は、階乗定義を文字通りに評価するため機能しますが、(M) が巨大であるため失敗します。 (p) 進の評価と (p) のない部分のみが重要であるという観察により、天文学的な階乗計算を (O(D)) の前処理と (M) と (N) の対数的に多くのリダクションで置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(M)) またはそれ以上 | (O(M)) またはそれ以上 | 遅すぎる |
 | 最適 | (O(D+\オメガ(D)\log^2 M)) | (O(\max p_i^{a_i})) | 承認済み |

 ここで、(\omega(D)) は (D) の異なる素因数の数です。 (D) 項は素数電力プレフィックス テーブルから来ています。 対数項は、(p) による繰り返し除算とべき乗剰余を考慮しています。 

## アルゴリズムのチュートリアル

1. (D) を素数累乗に因数分解します (q_i=p_i^{a_i})。 (D\le1.6\cdot10^7) であるため、(\sqrt D) までの除数をチェックするだけで最大約 (4000) 個の試行値が必要となるため、試行除算で十分です。 
2. すべての素数 (p_i) について、計算します。 

[
 e_i=v_{p_i}(M!)-v_{p_i}(N!)-v_{p_i}((M-N)!)。 
】

 階乗の評価はルジャンドルの公式で与えられます。 

[
 v_p(n!)=\left\lfloor\frac np\right\rfloor+
 \左\l床\frac n{p^2}\右\r床+
 \left\lfloor\frac n{p^3}\right\rfloor+\cdots。 
】

 (O(\log_p M)) 項のみが非ゼロです。 

1. コンピューティング

 [
 K=\min_i\left\lfloor\frac{e_i}{a_i}\right\rfloor。 
】

 これはまさに、二項係数から除去できる (D) の完全なコピーの数です。 (D) の 1 つのコピーがすべての素数 (p_i) の (a_i) コピーを同時に消費するため、最小値が必要です。 

1. 各素数べき乗 (q=p^a) を個別に処理します。 プレフィックス配列を構築する

 [
 G(x)=\prod_{\substack{1\le i\le x\p\nmid i}}i\bmod q.
 】

 (p) で割り切れない数値のみがプレフィックスに乗算されます。 この表のすべての値は (p) と互いに素であり、後で逆剰余が有効になります。 

1. 階乗単位関数 (F_p(n)) を実装します。 各反復で、現在のブロックからの寄与を乗算します。 

[
 G(q-1)^{\lfloor n/q\rfloor}G(n\bmod q),
 】

 次に、(n) を (\lfloor n/p\rfloor) に置き換えます。 ループは (O(\log_p M)) 回反復した後に終了します。 

1. 3 つの階乗単位の値を使用して、二項係数の (p) を含まない部分を取得します。 

[
 U=
 F_p(M)F_p(N)^{-1}F_p(M-N)^{-1}\pmod q.
 】

 3 つの階乗単位はすべて (q) と互いに素であるため、逆数が存在します。 

1. しましょう

 [
 k=e-aK。 
】

 すべての完全な (D) 因数が削除された後でも、目的の DivModulo 値には (p^k) が含まれています。 したがって、その剰余モジュロ (q) は次のようになります。 

[
 r=
 う、p^k
 \left(\frac Dq\right)^{-K}
 q.
 】

 (q) には (D) の (p) 乗全体が含まれるため、(D/q) の逆行列は (q) を法として存在します。 

1. 中国剰余定理を使用して、すべての合同式 (R\equiv r_i\pmod{q_i}) を結合します。 素数べき乗はペアごとに互いに素であり、その積は (D) であるため、(D) を法とする答えは 1 つだけ存在します。 

機能する理由: アルゴリズムは、素数 (p_i) ごとに、二項係数をその正確な (p_i) 乗と (p_i) と互いに素な部分に分離します。 評価計算により、(D) の完全なコピーを全体的に何個削除できるかが正確に決まります。 これらのコピーを削除した後、各素数の残りの指数がわかり、残りの (p) を含まない部分が階乗再帰によって計算されます。 したがって、(D) のすべての素数べき成分を法とする剰余は正確です。 次に、中国剰余定理は、固有の整数法 (D) を再構築します。これは、まさに DivModulo の結果です。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def factorize(n):
    factors = []
    e = 0
    while n % 2 == 0:
        n //= 2
        e += 1
    if e:
        factors.append((2, e))

    p = 3
    while p * p <= n:
        if n % p == 0:
            e = 0
            while n % p == 0:
                n //= p
                e += 1
            factors.append((p, e))
        p += 2

    if n > 1:
        factors.append((n, 1))
    return factors

def vp_factorial(n, p):
    ans = 0
    while n:
        n //= p
        ans += n
    return ans

def build_prefix(p, q):
    # pref[x] = product of all 1 <= i <= x with p not dividing i, modulo q.
    pref = array('I', [0]) * q
    pref[0] = 1

    cur = 1
    for i in range(1, q):
        if i % p:
            cur = (cur * i) % q
        pref[i] = cur

    return pref

def factorial_unit(n, p, q, pref):
    # n! with every factor p removed, modulo q.
    block = pref[q - 1]
    res = 1

    while n:
        res = res * pow(block, n // q, q) % q
        res = res * pref[n % q] % q
        n //= p

    return res

def solve_case(M, N, D):
    factors = factorize(D)

    valuations = []
    K = 10**100

    for p, a in factors:
        e = (
            vp_factorial(M, p)
            - vp_factorial(N, p)
            - vp_factorial(M - N, p)
        )
        valuations.append(e)
        K = min(K, e // a)

    # CRT state: answer == x (mod mod)
    x = 0
    mod = 1

    for (p, a), e in zip(factors, valuations):
        q = p ** a

        pref = build_prefix(p, q)

        fm = factorial_unit(M, p, q, pref)
        fn = factorial_unit(N, p, q, pref)
        fr = factorial_unit(M - N, p, q, pref)

        unit = fm
        unit = unit * pow(fn, -1, q) % q
        unit = unit * pow(fr, -1, q) % q

        remaining_p = e - a * K

        residue = unit * pow(p, remaining_p, q) % q

        other = D // q
        residue = residue * pow(pow(other, K, q), -1, q) % q

        # Combine:
        # x + mod * t == residue (mod q)
        t = (residue - x) % q
        t = t * pow(mod, -1, q) % q

        x += mod * t
        mod *= q
        x %= mod

    return x

def solve():
    M, N, D = map(int, input().split())
    print(solve_case(M, N, D))

if __name__ == "__main__":
    solve()
```因数分解ルーチンでは試行除算が使用されます。 (D) は最大 (1.6\cdot10^7) であり、平方根は (4000) 以下であるため、単純な実装で十分です。`vp_factorial`ルジャンドルの公式を実装します。 階乗を構築することはなく、関連する素数による繰り返し除算のみを実行します。`build_prefix`(p) で割り切れない各位置までのすべての整数の積を格納します。 の`array('I')`表現は意図的です。 数百万の Python 整数を含む Python リストは数百メガバイトを消費しますが、符号なし整数配列は各エントリを 4 バイトに格納します。 一度に保持される主電力テーブルは 1 つだけです。`factorial_unit`アルゴリズムのウォークスルーからの繰り返しを実装します。 Python の再帰オーバーヘッドを避けるために、再帰は繰り返し記述されます。 各レベルで、長さ (q) の完全なブロックが寄与します。`pref[q - 1]`、不完全なブロックが寄与する一方、`pref[n % q]`。 それから`n`を (p) で割ります。 

3 つの階乗単位は、逆モジュラーを使用して結合されます。 元の階乗とは異なり、これらは (q) と互いに素であることが保証されており、まさにこれが (p) 進分解が必要な理由です。 

指数`remaining_p = e - a * K`決してマイナスではありません。 (K) の定義により、すべての素数べき成分に対して (K\le e/a) が得られます。 

要因`(D // q)^K`逆モジュロです`q`。 (D/q) には因数 (p) が含まれていないため、この逆は常に存在します。 逆数を計算する前にべき乗を計算すると、非単位法 (D) で除算することを避けることができます。 

最後に、CRT アップデートでは次の方程式が使用されます。 

[
 x+\text{mod}\cdot\equiv r\pmod q.
 ]

以来`mod`そして`q`互いに素であり、`pow(mod, -1, q)`存在します。 Python の整数は任意精度であるため、(M) が (4\cdot10^{18}) に達してもオーバーフローは発生しません。 

## 実用的な例

 ### サンプル 1

 のために`9 2 3`、私たちは持っています

 [
 C(9,2)=36=4\cdot3^2。 
】

 素数べき成分は 1 つだけ (q=3) あります。 

| ステップ | (p) | (a) | (e=v_p(C)) | (K) | 残りの (p) 電力 | 残留物 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 因数分解 | 3 | 1 | 2 | 2 | 0 | |
 | (3^2) を削除した後 | 3 | 1 | 2 | 2 | (2-2=0) | 1 |

 (36) の (3) を除いた部分は (4) であり、(4\bmod3=1) です。 (36=4\cdot3^2) なので、答えは次のようになります。`1`。 トレースは、通常のモジュロでは不十分な理由 (36\bmod3=0) も示していますが、DivModulo では最初に (3) の両方の因数が削除されます。 

### サンプル 2

 のために`5 2 5`、私たちは持っています

 [
 C(5,2)=10=2\cdot5。 
】

 ここでは (p=5)、(a=1)、および (e=1) であるため、(5) の完全な因数が 1 つだけ削除されます。 

| ステップ | (p) | (a) | (e=v_p(C)) | (K) | 残りの (p) 電力 | 最終残渣 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 因数分解 | 5 | 1 | 1 | 1 | 0 | |
 | (5^1) を削除 | 5 | 1 | 1 | 1 | (1-1=0) | 2 |

 (5) のない部分は (2) であるため、DivModulo の結果は次のようになります。`2`。 直接`10 % 5`誤ってゼロが生成されてしまいます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(D+\オメガ(D)\log^2 M+\sqrt D)) | プレフィックス テーブルには合計で最大 (D) 個のエントリが含まれますが、階乗単位の評価とモジュラべき乗は対数 (M) で表されます。 |
 | スペース | (O(\max_i p_i^{a_i})) | 一度に保存されるプライム電力プレフィックス テーブルは 1 つだけです。 |

 (D) の個別の素数べき成分の合計は最大でも (D) なので、プレフィックス前処理の合計は (O(D)) になります。 (D\le1.6\cdot10^7) の場合、これは問題の意図された規模です。 (M) の巨大な値は対数計算の内部でのみ現れるため、(4\cdot10^{18}) の範囲は階乗自体の反復を強制しません。 

の`array('I')`ストレージは、数百メガバイトの Python オブジェクト オーバーヘッドではなく、数十メガバイト程度の可能な最大のプレフィックス テーブルを保持します。これは、(D=1.6\cdot10^7) 境界に特に関係します。
