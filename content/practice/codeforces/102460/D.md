 ## 解決策
 ## 問題の理解

 料理名にはちょうど 3 つの小文字が含まれています。 これらの単語の一部はタピオカの装飾の一部であるため、削除する必要があります。 削除可能な単語はまさに`bubble`そして`tapioka`。 他のすべての単語は実際の料理に属しており、他の生き残った単語に対して元の位置に留まっている必要があります。 

例えば、`bubble tea pizza`になる`tea pizza`、 その間`tapioka cake tapiokas`になる`cake tapiokas`。 2 番目の例は意図的に役に立ちます。`tapiokas`と同じ言葉ではありません`tapioka`, したがって、削除してはなりません。 

3 つの単語すべてをフィルタリングすると、何も残らない場合があります。 その場合、必要な出力は単語です。`nothing`。 

入力は非常に小さいです。ちょうど 3 つの単語があり、各単語の長さは最大 32 です。入力全体を繰り返しスキャンするアルゴリズムであっても、一定数の操作しか実行されません。 したがって、2 秒の時間制限と大容量メモリの制限は、この問題を制限するものではありません。 より一般的には、同じタスクが最大 (10^5) ワードの配列に拡張された場合、(O(n)) 個の解が自然なターゲットになりますが、すべての削除が (O(n^2)) になった後で配列全体を繰り返しスキャンすることになります。 

不注意に実装すると、誤った結果が生じる可能性があるケースがいくつかあります。 まず、単語が正確に一致する必要があります。 のために`tapioka cake tapiokas`、正しい出力は次のとおりです。`cake tapiokas`。 部分文字列ベースの置換では、誤った処理が行われる可能性があります`tapiokas`削除可能な単語を含むものとして`tapioka`、残すべき単語が削除されてしまいます。 

第二に、削除可能な単語はすべて消える可能性があります。 のために`tapioka bubble tapioka`、すべての単語は削除可能であるため、正しい出力は次のようになります。`nothing`。 残りのリストを単純に結合するソリューションでは、代わりに空の行が生成されます。 

第三に、生き残った単語の順序が変わってはなりません。 のために`bubble ramen cake`、正しい出力は次のとおりです。`ramen cake`。 適切なフィルタリングまたは新しいリストの作成はどちらも機能しますが、単語を並べ替えたり並べ替えたりすると、必要な順序に違反します。 

## アプローチ

 直接的なブルートフォース解釈は、現在のリストを繰り返し調べて、以下に等しいすべての単語を削除することです。`bubble`または`tapioka`、削除可能な単語がなくなるまで続けます。 これは正しいです。出現した単語はすべて最終的に削除され、他の単語はすべて保持されます。 ちょうど 3 つのワードがある場合、最悪の場合は最大 3 回のフル スキャンが実行され、各スキャンで最大 3 つの位置が検査されるため、最大 9 個のワード比較が行われます。 実際の制約の下では、このバージョンが遅くなりすぎることはあり得ません。 

ただし、(n) 個のワードに対して同じ操作を想像すると、削除後に繰り返しスキャンすると、最悪の場合、(O(n^2)) 個の比較が必要になる可能性があります。 この問題の構造から、より単純な観察が得られます。単語を削除しても、他の単語を削除するかどうかには影響しません。 各単語は、正確かどうかをチェックすることで個別に分類できます。`bubble`または正確に`tapioka`。 つまり、削除をシミュレートする必要はまったくありません。 

最適解では、3 つの単語を 1 回通過します。 単語が削除可能な場合はスキップします。 それ以外の場合は、回答に追加します。 最後に、空の回答は次のように置き換えられます。`nothing`。 これにより、問題の一般化バージョンが線形時間に短縮され、入力を繰り返し変更するよりも簡単になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 一般化されたバージョンでは (O(n^2))、ここでは最大 9 つの比較があります。 (O(n)) | ここで受け付けます |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ここ (n=3) は実際の問題であるため、どちらのアプローチも簡単に十分に高速です。 ワンパスバージョンは、その正確さが各単語の独立した処理から直接得られるため、推奨されます。 

## アルゴリズムのチュートリアル

 1. 単一の入力行を読み取り、それを 3 つのワードに分割します。 空白で分割すると、文字の位置を手動で処理する必要がなく、個々の皿のコンポーネントが得られます。 
2. 実際の料理に属する単語の空のリストを作成します。 
3. 各入力単語を 1 回調べます。 まさにそうだったら`bubble`または正確に`tapioka`、捨ててください。 それ以外の場合は、結果リストに追加します。 次のような言葉があるため、完全な等価性が必要です。`tapiokas`生き残らなければなりません。 
4. 3 つの単語すべてが処理されたら、結果リストが空かどうかを確認します。 空の場合は印刷する`nothing`、料理全体が削除可能な単語で構成されているためです。 
5. それ以外の場合は、残った単語を単一のスペースで結合して出力します。 単語は元の順序で追加されるため、出力順序は自動的に正しいものになります。 

### なぜ効果があるのか

 入力の接頭辞を処理した後、結果リストには、その接頭辞のどちらでもない単語が正確に含まれます。`bubble`または`tapioka`、元の順序で。 次の単語が削除可能な場合、それをスキップしてもこのプロパティは保持されます。 次の単語が削除できない場合、それを追加するとプロパティも保持されます。 3 つの単語すべてが処理されるまでに、結果には必要な単語がすべて正確に含まれ、削除可能な単語は含まれません。 結果が空の場合、すべての入力単語は削除可能であるため、`nothing`まさに必要な出力です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    words = input().split()

    result = []

    for word in words:
        if word != "bubble" and word != "tapioka":
            result.append(word)

    if result:
        print(" ".join(result))
    else:
        print("nothing")

if __name__ == "__main__":
    solve()
```入力は 1 行として読み取られ、料理名にちょうど 3 つの単語が含まれているという事実と一致して、個々の単語に分割されます。 の`result`list には、アルゴリズムによるフィルタリング ステップを通過した単語のみが保存されます。 

この条件では、部分文字列チェックではなく、文字列の正確な等価性が使用されます。 これは実装の微妙な部分です。`tapiokas`、`bubbletea`、および削除可能な単語を含むその他の単語は依然として有効な料理単語であり、そのままにしておく必要があります。 

ループはすべての単語を 1 回だけ処理するため、off-by-one エラーを引き起こす可能性のあるインデックス操作や削除操作はありません。 Python の文字列は直接比較され、数値計算は行われないため、整数のオーバーフローは無関係です。 

最後にチェック`if result`は、可能な 2 つの出力形式を区別します。 空ではない結果はスペースで結合されますが、空の結果は`nothing`。

 入力用`tapioka cake tapiokas`、最初の単語が削除されます。 2 番目と 3 番目の単語は存続します。`cake`タピオカとは関係ありませんが、`tapiokas`正確にはそうではない`tapioka`。 

| 単語 | 取り外し可能ですか？ | ステップ | 後の結果

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n)) | すべての入力単語が 1 回だけチェックされます (ここでは (n=3))。 |
 | スペース | (O(n)) | 残った単語は結果リストに保存されます。 |

 実際の問題では、(n) は常に 3 で、各単語の文字数は最大 32 文字であるため、アルゴリズムは少数の文字列比較のみを実行し、使用するメモリは無視できます。 指定された制限内で問題なく収まります。 

## テストケース```python
import sys
import io

def solve(inp: str) -> str:
    words = inp.split()

    result = []
    for word in words:
        if word != "bubble" and word != "tapioka":
            result.append(word)

    if result:
        return " ".join(result)
    return "nothing"

# Provided samples
assert solve("bubble tea pizza") == "tea pizza", "sample 1"
assert solve("tapioka cake tapiokas") == "cake tapiokas", "sample 2"
assert solve("tapioka jasmine tea") == "jasmine tea", "sample 3"
assert solve("tapioka bubble tapioka") == "nothing", "sample 4"

# Minimum-size style case: three words with two removable words.
assert solve("bubble tapioka cake") == "cake", "two removable words"

# All three words are removable.
assert solve("tapioka tapioka tapioka") == "nothing", "all removable"

# Exact-word boundary: tapiokas must not be removed.
assert solve("bubble tapiokas bubble") == "tapiokas", "exact word matching"

# Maximum word length and non-removable words.
w = "a" * 32
x = "b" * 32
assert solve(f"bubble {w} {x}") == f"{w} {x}", "maximum word length"

 ## 特殊なケース

 最初の重要なエッジケースは、すべての単語が削除可能である場合です。 のために`tapioka bubble tapioka`、ループは 3 つの単語すべてをスキップし、残りの単語を残します。`result`空の。 最終チェックでこれが検出され、出力されます。`nothing`空行を出力する代わりに。 

2 番目のエッジ ケースは、単語の完全一致です。 のために`tapioka cake tapiokas`、最初の単語は満たします`word == "tapioka"`そして削除されます。 言葉`tapiokas`は比較に失敗し、結果に追加されます。 最終的な出力は次のとおりです`cake tapiokas`。 出現するすべての文字列を置き換えるなどの部分文字列の置換`"tapioka"`行内にあると、この単語が誤って破損します。 

3 番目のエッジ ケースは、削除可能な単語が、許可された任意の位置で通常の単語の隣に表示される可能性があることです。 のために`bubble tapiokas bubble`、最初と 3 番目の単語は破棄され、中央の単語は残ります。 アルゴリズムが生成するのは、`tapiokas`、削除可能な単語が 1 つの特定の位置に限定されることに依存していないことを示しています。 

4 番目のエッジ ケースは最大語長です。 32 文字の通常の単語では、比較ロジックはまったく変わりません。 Python は完全な文字列を直接処理するため、語長は文字列比較のわずかなコストにのみ影響し、境界の問題は発生しません。
