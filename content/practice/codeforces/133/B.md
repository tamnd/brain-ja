 ## 解決策
 ## 問題の理解

 次のようなキャラクターで構成される短いブレインファック プログラムが与えられます。`+`、`-`、`>`、`<`、 等々。 各コマンドは、固定の 4 ビットのバイナリ文字列に対応します。 すべての文字をそのバイナリ コードに置き換えた後、これらすべての 4 ビット チャンクを 1 つの長い 2 進数に連結します。 

タスクは、そのバイナリ文字列を基数 2 の整数として解釈し、その値を剰余として出力することです。`1000003`。 

単項表現に関する表現は、最初は気が散るように見えるかもしれません。 単項は数値を書き込むため、数値の単項表現のサイズは数値そのものになります。`n`を使用して`n`のコピー`1`。 したがって、実際には単項文字列を構築する必要はありません。 必要なのは 2 進数の 10 進数値だけです。 

入力長は最大 100 文字です。 各文字は正確に 4 つの 2 進数を構成するため、最終的な 2 進数は最大 400 ビットになります。 Python のような言語は技術的にはそのような整数を直接保存できますが、問題は結果の剰余を明示的に求めます。`1000003`したがって、モジュラー演算が最もクリーンなアプローチです。 

単純な実装ミスは、巨大なバイナリ文字列を構築し、後でそれを変換しようとすることです。 これはこれらの制約に対しても機能しますが、基数変換とまったく同じように数値を増分的に構築できるという核心的な観察が欠けています。 

もう 1 つのよくある間違いは、「単項プログラムのサイズ」の意味を誤解していることです。 次の入力を考えてみましょう。```
,.
```マッピングは次のようになります。```
, -> 1101
. -> 1100
```連結された 2 進数は次のようになります。```
11011100
```それは等しい`220`10進数で表すと、答えは次のようになります。`220`、バイナリ文字列の長さではなく、明示的に書き出された単項桁数でもありません。 

バイナリ表現が次で始まる場合、より微妙なエッジケースが現れます。`1`その後に多くのゼロが含まれます。 例えば：```
>
```以下にマッピングされます:```
1000
```等しい`8`。 先頭のゼロを誤って削除したり、チャンクを個別に扱ったりする不注意な実装では、間違った値が生成される可能性があります。 

もう 1 つの簡単なバグは、構築中にモジュール削減を忘れることによって発生します。 400 ビット整数は Python にまだ適合しますが、固定幅の整数を使用する言語では、これはすぐにオーバーフローします。 すべてのステップの後にモジュロを使用すると、この問題がきれいに回避されます。 

## アプローチ

 ブルートフォースアプローチは文字通りこのステートメントに従います。 Brainfuck コマンドから 4 ビット文字列までの辞書を作成し、すべてのバイナリ チャンクを 1 つの大きなバイナリ文字列に連結してから、そのバイナリ文字列を 10 進整数に変換します。 

最大入力長が 100 の場合、バイナリ文字列の長さはわずか 400 なので、直接変換でも十分高速です。 複雑さは、生成されるビット数に比例します。 

より興味深いアプローチは、2 進数全体を保存することを回避します。 すでにいくつかのプレフィックスを処理しており、その数値が次のようになっていると仮定します。`x`。 別の 4 ビット ブロックを追加すると`b`の場合、新しい値は次のようになります。```
x * 16 + value(b)
```4 つの 2 進数を追加することは、4 ビット左にシフトし、次の値を乗算することと同じであるためです。`2^4 = 16`。 

これにより、問題は標準的な位置番号の構成に変換されます。 プログラムを左から右にスキャンし、現在の答えに 16 を乗算し、次のコマンドの数値を加算することを繰り返します。 

最終的な答えはモジュロが必要なので、`1000003`、すべての操作の後に剰余を取得できます。```
ans = (ans * 16 + value) % MOD
```これにより、計算全体を通じて数値が小さく保たれます。 

合計入力が小さいため総当たり法は機能しますが、増分法はよりクリーンで、一定の追加メモリを使用し、2 進数の形成方法を直接反映します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(n) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各 Brainfuck コマンドからバイナリ変換後の 10 進数値へのマッピングを作成します。 

例えば、`">"`バイナリにマップします`1000`、10進数に等しい`8`。 同様に、`"["`にマップします`1110`に等しい`14`。 
2.初期化`ans = 0`。 

この変数には、これまでに形成された 2 進数の値が格納されます。 
3. 入力文字列を左から右に処理します。 

各コマンドは正確に 4 つの 2 進数を提供します。 
4. キャラクターごとに`c`、 アップデート：```
ans = (ans * 16 + value[c]) % 1000003
```16 を掛けると、現在の 2 進数が 4 ビット左にシフトされます。 追加`value[c]`新しい 4 ビット ブロックを追加します。 
5. すべての文字を処理した後、印刷します。`ans`。 

### なぜ効果があるのか

 最初の処理後`k`コマンド、`ans`対応する 4 ビット バイナリ コードを連結したモジュロの 10 進数値に等しい`1000003`。 

最初、何かを処理する前のバイナリ文字列は空であり、その値は`0`, したがって、不変式が成り立ちます。 

新しい 4 ビット ブロックが追加されると、既存の 2 進数が 4 桁左にシフトし、16 倍になります。新しいブロックの値を加算すると、拡張されたバイナリ文字列の正確な数値が生成されます。 モジュラー演算では加算と乗算が保持されるため、更新のたびにモジュロを取得すると、不変式が true に保たれます。 

最後に、すべてのコマンドが処理されるので、`ans`まさに必要なモジュロ結果です`1000003`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000003

values = {
    '>': 8,   # 1000
    '<': 9,   # 1001
    '+': 10,  # 1010
    '-': 11,  # 1011
    '.': 12,  # 1100
    ',': 13,  # 1101
    '[': 14,  # 1110
    ']': 15   # 1111
}

def solve():
    s = input().strip()

    ans = 0

    for ch in s:
        ans = (ans * 16 + values[ch]) % MOD

    print(ans)

solve()
```辞書には、バイナリ文字列自体ではなく、各 4 ビット コードの 10 進値が格納されます。 これにより、バイナリ解析の繰り返しが回避されます。 

コアアップデート:```
ans = (ans * 16 + values[ch]) % MOD
```数学的構造と正確に一致します。 16 を掛けると、既存の 2 進数が 4 ビットシフトされ、新しい値を追加すると、次のコマンド ブロックが追加されます。 

すべての反復中にモジュロを適用すると、中間値が小さく保たれます。 いずれにしても Python は完全な整数を処理できますが、このパターンの方が安全であり、問​​題の要件に直接一致します。 

使用する`strip()`重要なので`input()`末尾の改行文字も含まれます。 これを削除しないと、辞書検索が失敗します。`'\n'`。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

MOD = 1000003

values = {
    '>': 8,
    '<': 9,
    '+': 10,
    '-': 11,
    '.': 12,
    ',': 13,
    '[': 14,
    ']': 15
}

def solve():
    s = input().strip()

    ans = 0

    for ch in s:
        ans = (ans * 16 + values[ch]) % MOD

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    return sys.stdout.getvalue().strip()

# provided sample
assert run(",.\n") == "220", "sample 1"

# minimum size input
assert run(">\n") == "8", "single character"

# another single character
assert run("]\n") == "15", "maximum 4-bit value"

# two-character construction
assert run("[]\n") == "239", "binary concatenation"

# long repeated input
expected = 0
for _ in range(100):
    expected = (expected * 16 + 10) % MOD
assert run("+" * 100 + "\n") == str(expected), "maximum length"

print("All tests passed.")

ans = (ans * 16 + 10) % 1000003
