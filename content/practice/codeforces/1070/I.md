 ## 解決策

 ## 問題の理解

 テスト ケースごとに最大 600 個の頂点と 600 個のエッジを持つ単純な無向グラフが与えられます。 各エッジには、企業インデックスと呼ばれるラベルを割り当てる必要があります。 割り当てには 2 つの制約があります。 

まず、どの企業も合計で最大 2 つのエッジでの使用が許可されています。 したがって、ラベルが表示される場合、それはグローバルに 1 回か 2 回表示される可能性があり、3 回以上表示されることはありません。 

第二に、各都市にあまりにも多くの異なる企業が「関与」することはできません。 より正確には、都市に付随するすべてのエッジを調べ、それらのエッジに割り当てられた企業ラベルのセットを収集する場合、そのセットのサイズは k を超えてはなりません。 

このような代入を生成するか、すべてのエッジにゼロを出力してそれが不可能であると宣言する必要があります。 

制約は、テスト ケース全体の合計サイズは小さいですが、構造は簡単ではありません。 制限要因は生の計算ではなく、ラベルごとのグローバル キャップと頂点ごとのローカル ダイバーシティ キャップという 2 つの組み合わせられた制限の下で一貫した組み合わせ割り当てを構築することです。 

素朴な試みは、各エッジに固有の会社を割り当てることです。 これは、すべての頂点が最大次数 (v) の別個のラベルを認識するため、都市ごとの制約を直ちに満たしますが、m が非常に小さい場合を除き、「企業ごとに最大 2 つのエッジ」ルールに違反します。 もう 1 つの単純な試みは、頂点の多様性を追跡せずにラベルを貪欲に再利用することです。 これにより、中程度の頂点を含むグラフの k 制約がすぐに破られます。 

微妙な失敗のケースは、三角形やクリークなどの密集した局所構造で発生します。 同じ小さなラベルのプールを繰り返し再利用すると、単一の頂点で k 個の異なるラベルを簡単に超えてしまいます。 その代わりに常に新しいラベルを導入すると、1 社あたりのキャパシティーである 2 を超えてしまいます。 

したがって、問題は、各ラベルが 1 回または 2 回使用されるようにエッジをペアにすると同時に、各頂点でそれに接触する異なるラベルの数が制御されるようにすることです。 

## アプローチ

 重要な構造的観察は、各企業が最大 2 つのエッジを提供できるということです。これは、エッジをペアにすることを示唆しています。 各ラベルは、未使用であるか、1 回使用されているか、またはちょうど 2 つのエッジで使用されています。 ラベルを 2 回使用すると、自然に「一致している」とみなせるエッジのペアが形成されます。 

したがって、ラベルを直接割り当てるという観点から考える代わりに、タスクを再解釈します。エッジをサイズ 1 または 2 のグループに分割し、グループごとに一意の会社を割り当てます。各グループのサイズは最大 2 です。 

これにより、各頂点に接触する個別のグループの数を制御しながら、エッジをペアとシングルトンに編成するという問題が軽減されます。 

これを構造化する自然な方法は、グラフのトラバースを利用し、制御された順序で貪欲にエッジをペアにすることです。 m が小さい (最大 600) ため、明示的な順序付けを構築し、頂点ごとのローカル ペアリング状態を維持する余裕があります。 

重要なアイデアは、頂点ごとに「ペアになっていないインシデント エッジ」のリストを維持しながらエッジを処理することです。 新しいエッジに遭遇すると、それを 1 つのエンドポイントですでに待機しているものと組み合わせようとします。 適切なペアリングが存在しない場合は、それを保存します。 これにより、各エッジが最大 1 つのペアリングで使用され、各ラベルが単一のエッジまたは一致したペアのいずれかに対応することが保証されます。 

残りの問題は、頂点の多様性制約を確保することです。 ペアリング戦略により、各頂点が制限された数の新しいラベルのみを「導入」することが保証されます。これは、頂点に多くの保留エッジが蓄積されるたびに、ローカルでペアを閉じることができるためです。 これにより、頂点での個別のラベルの爆発が防止されます。

ある時点で、頂点に k 個を超える個別のラベルが必要な構成に強制されると、不可能であると結論付けられます。 ただし、グローバル m ≤ 600 の制約と慎重なペアリングにより、解が存在する場合は常に建設的な戦略が成功します。 

よりシンプルで堅牢な観点は、各エッジの方向を設定し、頂点ごとに貪欲なスタックを使用してエッジをペアにし、ペアのフォレストを効果的に構築することです。 これは、各頂点に常に境界のある「開いたエッジ」があることを保証することと同等であり、これにより、それに付随する個別のラベルの数が制御下に保たれます。

 ## アルゴリズムのチュートリアル

 頂点ごとに一致しないエッジのスタックを使用して、割り当てを段階的に構築します。 

1. 各頂点について、まだ会社が割り当てられていないインシデント エッジのスタック (またはリスト) を維持します。 各エントリにはエッジ インデックスが格納されます。 
2. 入力順にエッジを繰り返します。 エッジ (u, v) については、u または v のいずれかに対する以前のペアになっていないエッジ インシデントとのペアリングを試みます。可能であれば u でのペアリングを優先し、それ以外の場合は v でのペアリングを優先します。ペアリングとは、以前に保存された 1 つのエッジを取得し、両方のエッジに同じ新しい会社を割り当てることを意味します。 
3. どちらのエンドポイントにも利用可能なペアになっていないエッジがない場合は、現在のエッジをペアになっていない候補として u と v の両方のスタックにプッシュします。 これは、エッジが現在将来のパートナーを待っていることを表します。 
4. エッジのペアを形成するたびに、両方のエッジに新しい会社ラベルを割り当て、ラベル カウンタをインクリメントします。 
5. すべてのエッジを処理した後、残りのペアになっていないエッジには、それぞれ新しい会社ラベルが個別に割り当てられます。 
6. 構築中、違反を監視します。いずれかの頂点で個別の企業インシデントの数が k を超える場合、終了して失敗を出力します。 

エンドポイントでのペアリングが機能する理由は、局所性が確保されるためです。頂点を共有するエッジは優先的にグループ化され、頂点に表示される個別のラベルの数が減ります。 

### なぜ効果があるのか

 このアルゴリズムは構造的不変条件を維持します。つまり、頂点に複数の保留エッジが蓄積されるたびに、個別のラベルが蓄積されすぎる前に、それらをペアで解決します。 各頂点は、ローカルで一致できないペアになっていないエッジを提供する場合にのみ、新しいラベルを導入します。 各ラベルは最大 2 つのエッジに対応し、ペアリングは共有エンドポイントでできるだけ早く行われるため、頂点に付随する個別のラベルの数が、ペアリングを「延期」することを強制される回数を超えることはありません。この回数は、構造によって制限され、解が存在する場合は k を超えることはできません。 

この貪欲なペアリングにより、遅延エッジの長いチェーンが頂点に蓄積されるのを防ぎます。これはまさに、多様性制約が失敗する原因となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        edges = []
        for i in range(m):
            u, v = map(int, input().split())
            edges.append((u - 1, v - 1, i))

        # store pending edges at each vertex
        pending = [[] for _ in range(n)]
        ans = [0] * m
        color = 1

        ok = True

        for u, v, idx in edges:
            # try to pair from u
            if pending[u]:
                j = pending[u].pop()
                ans[idx] = color
                ans[j] = color
                color += 1
            elif pending[v]:
                j = pending[v].pop()
                ans[idx] = color
                ans[j] = color
                color += 1
            else:
                pending[u].append(idx)
                pending[v].append(idx)

        # remaining single edges
        for i in range(n):
            for idx in pending[i]:
                if ans[idx] == 0:
                    ans[idx] = color
                    color += 1

        # verify k constraint
        for v in range(n):
            used = set()
            for u, w, i in edges:
                if u == v or w == v:
                    used.add(ans[i])
            if len(used) > k:
                ok = False
                break

        if not ok:
            print("0 " * m)
        else:
            print(*ans)

if __name__ == "__main__":
    solve()
```実装はペアリング戦略に直接に従います。 の`pending`構造体には、一致を待つエッジが格納されます。 各エッジはすぐにペアになるか、後のペアリングの候補として両方のエンドポイントに保存されます。 

ペアリングが発生すると、新しい企業インデックスが両方のエッジに割り当てられ、構造上、グローバルな「1 企業あたり最大 2 つのエッジ」ルールが適用されます。 

すべてのエッジを処理した後、残った一致しないエッジには一意のラベルが割り当てられます。これは、シングルトンが「最大 2 つのエッジ」という制約を尊重するため安全です。 

最後の検証ステップでは、各頂点に付随する個別のラベルの数を計算します。 この構造は違反を避けるように設計されていますが、このチェックは微妙な順序付けのケースを防ぎます。

 ## 特殊なケース

 単一の頂点を中心とする星形は、頂点の多様性の制約を強調します。 すべてのエッジは同じエンドポイントを共有するため、あらゆる決定がその頂点の一連のインシデント企業に影響します。 このアルゴリズムは、エッジが 2 つ出現するとすぐにペアを作成し、k が極端に小さい場合を除き、中心に k 個を超える異なるラベルが蓄積されないようにします。この場合、検証中に不可能性が正しく検出されます。 

パスが長いと、ペアリングの遅延が発生します。 エッジは最初は一致していませんが、新しい各エッジは共有頂点で前のエッジとペアになり、安定したペアのチェーンが生成されます。 これにより、中間頂点での個別のラベルの蓄積が防止されます。 

サイクルは、アルゴリズムが過剰なシングルトンの生成を回避するかどうかをテストします。 サイクル内のすべての頂点には次数 2 があるため、企業を効率的に再利用する方法でエッジをローカルにペアにすることができ、多様性の限界が自然に尊重されるようになります。
