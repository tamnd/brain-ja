 ## 解決策
 ## 問題の理解

 2 つの制約を同時に満たす正の整数を探しています。 まず、指定された整数で割り切れる必要があります$d$。 第二に、10 進数形式で書かれた場合、その桁の合計は指定された値に等しくなければなりません。$s$。 このようなすべての整数の中で、数値が最も小さいものが必要です。 

出力は、単なる「はい」か「いいえ」の決定ではなく、通常の整数の順序付けという意味での辞書編集上の最小の数値です。 これにより、この問題は基本的に、数値の値が桁ごとに増分的に構築される状態空間にわたる最短経路問題になります。 

制約$d \le 500$そして$s \le 5000$最大規模の数値を直接構築することは直ちに除外されます$10^{5000}$。 整数を明示的に列挙したり、大きな候補の割り算をシミュレートしようとすると失敗します。$10^7$それぞれの候補が桁和計算とモジュロ追跡を必要とする場合、候補はすでに遅すぎます。 

素朴な考えは、整数を増やして、それらの桁の和を計算し、次のように割り切れるかどうかを確認することです。$d$。 これは 2 つの点で失敗します。 まず、検索スペースは、回答の桁の長さに応じて指数関数的に増加します。 第 2 に、次のサンプルで示されているように、入力が小さい場合でも、正解には多くの桁が含まれる可能性があります。$13, 50$6 桁の数字を生成します。 

グローバルな状態の追跡を行わずに貪欲な数字の構築を試みると、2 番目の微妙な失敗モードが現れます。 たとえば、数値を最小限に保つために局所的に小さい桁を選択すると、必要な剰余モジュロの達成が簡単に妨げられる可能性があります。$d$後で。 

重要な問題は、割り算が完全なプレフィックスのモジュロに依存することです。$d$、一方、桁の合計は累積された重みの制約に依存します。 これら 2 つの制約は立場を超えて相互作用するため、ローカルな決定ではグローバルな実現可能性を保証できません。 

## アプローチ

 ブルートフォースアプローチは、整数を昇順に生成し、それらの桁の合計を計算し、次のように割り切れるかどうかをテストすることです。$d$。 これは、最終的にすべての候補を順番に列挙するため正しいですが、桁付きの整数の合計が次のようになるため、実行不可能になります。$s$巨大です。 桁の和に限定しても$s = 5000$、の作曲数$s$数字に換算すると指数関数的になります$s$したがって、検索スペースは実際の限界をはるかに超えています。 

この構造は、2 つの状態 (現在の剰余モジュロ) を追跡しながら、数字を 1 桁ずつ構築するという問題を再定式化することを示唆しています。$d$、および残りの桁の合計。 各数字の選択は、決定的に新しい状態に移行します。 これにより、ノードが状態を表すグラフが自然に形成されます。$(remainder, remaining\_sum)$、エッジは数字の追加に対応します$0$に$9$。 

目標は初期状態からの最短経路を見つけることになります$(0, s)$どの状態にも$(0, 0)$、最初の桁がゼロ以外であることを確認します。 すべてのエッジのコストが等しい（各桁に 1 つの位置が追加される）ため、桁が昇順に処理される場合、BFS は辞書編集上で最小の有効な数値を生成します。 

これにより、問題は最大で最短経路の探索に変換されます。$d \cdot (s+1)$管理可能な状態です。

 | ブルートフォース | 指数 | お(1) | 遅すぎる |
 | 状態の BFS (mod、sum) |$O(10 \cdot d \cdot s)$|$O(d \cdot s)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 状態をペアとして定義する$(r, t)$、 どこ$r$現在の剰余モジュロです$d$、 そして$t$必要な残りの桁の合計です。 これら 2 つの値のみが実現可能性に影響を与えるため、これは将来的に満たす必要がある制約を正確に捉えています。 
2. 状態から開始$(0, s)$数字を配置する前に。 これは、全桁の合計がまだ利用可能な空のプレフィックスを表します。 
3. BFS と開始状態で初期化されたキューを使用します。 各 BFS レベルは、最終数値のもう 1 桁の固定に対応します。 
4. 状態から$(r, t)$、すべての数字を追加してみてください$x \in [0, 9]$。 これにより新しい状態が生成されます$(r', t')$どこ$t' = t - x$そして$r' = (r \cdot 10 + x) \bmod d$。 以下の場合にのみ移行を許可します。$t' \ge 0$。 
5. 同じ州を二度訪れることは避けてください。 これにより、状態空間が有限であるため、パスが再計算されなくなり、終了が保証されます。 
6. BFS 中に、以前の状態と使用された数字の両方を格納する、訪問された各状態の親ポインタを維持します。 これにより、到達した時点で最終的な数値を再構築できるようになります。$(0, 0)$。 
7. 次の場合はすぐに BFS を停止します。$(0, 0)$に達します。 これが有効なのは、BFS が桁数を増やしながら状態を探索するため、最初に有効な最終状態に到達したときに、最小長の解 (桁順での最小の数値でもある) に対応するためです。 

### なぜ効果があるのか

 不変条件は、BFS 内の訪問されたすべての状態が、桁の合計とモジュロ制約が状態の説明と正確に一致する有効なプレフィックスに対応するということです。 BFS は、パス長が増加するにつれて到達可能なすべての状態を調査し、0 から 9 までの桁の順序により、同じ長さのパスの中で小さい桁が最初に拡張されるようにします。 したがって、初めて到達したとき$(0, 0)$より小さい有効な数値は存在しません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    d, s = map(int, input().split())
    
    # dist[r][t] = visited state
    dist = [[False] * (s + 1) for _ in range(d)]
    parent = [[None] * (s + 1) for _ in range(d)]
    
    q = deque()
    q.append((0, s))
    dist[0][s] = True
    
    while q:
        r, t = q.popleft()
        
        if r == 0 and t == 0:
            # reconstruct answer
            res = []
            cr, ct = r, t
            while parent[cr][ct] is not None:
                pr, pt, digit = parent[cr][ct]
                res.append(str(digit))
                cr, ct = pr, pt
            print("".join(reversed(res)))
            return
        
        for digit in range(10):
            if r == 0 and t == s and digit == 0:
                continue
            
            if t < digit:
                continue
            
            nr = (r * 10 + digit) % d
            nt = t - digit
            
            if not dist[nr][nt]:
                dist[nr][nt] = True
                parent[nr][nt] = (r, t, digit)
                q.append((nr, nt))
    
    print(-1)

if __name__ == "__main__":
    solve()
```BFS キューには、剰余と残りの桁の合計によって定義された状態が格納されます。 訪問されたテーブルは、同じ状態に再度アクセスすることを防ぎます。これは、複数の数字シーケンスが同じ剰余と残りの和をもたらす可能性があるため、非常に重要です。 

再構築では、親ポインタを使用して逆の順序で数字を再構築します。 これにより、メモリを大量に消費する完全な文字列をキューに保存することがなくなります。$s$5000まで。 

唯一の微妙な制限は、先頭のゼロを禁止することであり、初期状態からの最初の遷移で数字 0 を禁止することで処理されます。 

## 実用的な例

 サンプル入力をトレースします$d = 13, s = 50$。 BFS は状態から始まります$(0, 50)$。

 | 1 | (0, 50) | 1 | (1, 49) | エンキュー |
 | 2 | (0, 50) | 2 | (2, 48) | エンキュー |
 | ... | ... | ... | ... | ... |
 | k | ... | ... | ... | 最終的には (0, 0) に到達します。 

中間ステップでは正確なパスは重要ではありません。 重要なのは、BFS が最初に検出された有効な端末状態が最適であることを保証することです。 

より小さな例として、次のことを考えてみましょう。$d = 3, s = 2$。 BFS は以下をすぐに見つけます。 

| ステップ | 状態 | 数字 | 新しい状態 |
 | --- | --- | --- | --- |

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    d, s = map(int, sys.stdin.readline().split())

    dist = [[False] * (s + 1) for _ in range(d)]
    parent = [[None] * (s + 1) for _ in range(d)]

    q = deque()
    q.append((0, s))
    dist[0][s] = True

    while q:
        r, t = q.popleft()

        if r == 0 and t == 0:
            res = []
            cr, ct = r, t
            while parent[cr][ct] is not None:
                pr, pt, digit = parent[cr][ct]
                res.append(str(digit))
                cr, ct = pr, pt
            return "".join(reversed(res))

        for digit in range(10):
            if r == 0 and t == s and digit == 0:
                continue
            if t < digit:
                continue
            nr = (r * 10 + digit) % d
            nt = t - digit
            if not dist[nr][nt]:
                dist[nr][nt] = True
                parent[nr][nt] = (r, t, digit)
                q.append((nr, nt))

    return "-1"

 ## 特殊なケース

 よくある失敗例は、先頭のゼロの処理を誤ることです。 最初の遷移として数字 0 が許可されている場合、アルゴリズムは 0009 のような数値を返す可能性がありますが、これは最小の正の整数表現としては数値的に無効です。 初期状態の制限により、最初の桁がゼロ以外になることが保証されます。 

もう 1 つの特殊なケースは、解決策が存在しない場合です。 このような場合、BFS は状態空間に到達することなく使い果たしてしまいます。$(0, 0)$。 到達可能な状態はすべて調査されており、両方の制約を同時に満たすものはないため、アルゴリズムは -1 を正しく出力します。
