 ## 問題の理解

 時系列順に並べられた一連のビデオ時間が与えられます。 タスクは、このシーケンスを正確に分割することです。`k`連続したグループ。各グループは 1 つの投稿を表し、すべてのビデオは 1 つのグループにのみ属する必要があります。 

重要な制約は、パーティショニング自体だけではなく、すべてのグループの継続時間の合計が同じでなければならないという事実です。 言い換えれば、各セグメント内の継続時間の合計を計算すると、すべての`k`セグメントの合計は同一である必要があります。 

出力はセグメント自体ではなく、これらのセグメントの順番の長さです。 で表すと`s_j`内のビデオの数`j`- 番目の投稿では、配列を連続したブロックに分割する正の整数のシーケンスを出力する必要があります。 

制約`n ≤ 100000`すべてのパーティションを試行するアプローチは除外されます。 スプリットポジションをめぐる素朴な後戻りですら、指数関数的に増加します。`n-1`潜在的なカット位置と選択`k-1`それらは組み合わせ爆発につながります。 同様に、セグメントの合計を繰り返し再計算すると、二次解さえも範囲外になってしまいます。 

すべてのビデオの再生時間の合計が次の値で割り切れない場合、微妙な問題が発生します。`k`。 その場合、均等な分割はまったく存在しません。 2 番目のエッジ ケースは、有効なセグメント境界が存在するものの、値が繰り返されているためにすぐには明らかではない場合に発生します。 たとえば、次のような配列`1 1 1 1 1`と`k = 2`複数の有効な分割を許可しますが、この問題では、答えが存在する場合にはその一意性が保証されます。つまり、有効な貪欲境界が見つかると、それが強制されます。 

## アプローチ

 ブルートフォース戦略では、次のいずれかを選択しようとします。`k-1`の間でポジションをカットする`n-1`ギャップを確認し、候補パーティションごとにセグメントの合計を計算し、等しいことを確認します。 合計の計算がプレフィックス合計で最適化されていても、各チェックには依然としてコストがかかります`O(k)`、パーティションの数は`C(n-1, k-1)`、これは中程度の入力でも天文学的に大きくなります。 これにより、総当たり攻撃は完全に不可能になります。 

重要な観察は、セグメントを自由に選択しているわけではないということです。合計が分かると、セグメントの合計は固定されます。 合計額なら`S`で割り切れます`k`の場合、各セグメントの合計は次のようになります。`S / k`。 これにより、問題は「すべてのパーティションを試す」から「正確な目標合計に達する境界を見つける」に変わります。 

目標合計がわかったら、配列を左から右にスキャンして値を累積します。 累計が正確に目標に達すると、セグメントがカットされます。 目標を超えた場合は無効となります。 この欲張りスキャンが機能するのは、すべての数値が正であるため、部分和は厳密に増加し、後で「自動的に修正」できないためです。 

したがって、問題の構造は、実行中のアキュムレータと強制カット ポイントを備えた線形スキャンに帰着します。

 ## アルゴリズムのチュートリアル

 1. すべてのビデオの再生時間の合計を計算します。 この合計が割り切れない場合は、`k`、有効なパーティションが存在しないと即座に結論付けます。 これが必要なのは、等しいセグメントの合計が合計と正確に一致する必要があるためです。 
2. 必要なセグメントの合計を計算します。`target = total / k`。 すべての投稿の合計がこの値になる必要があります。 
3. 現在のセグメントの累計を維持しながら、配列を左から右に走査します。 この累計は、現在の投稿に割り当てられた合計期間を表します。 
4. 現在の合計が次と等しくなるたびに`target`、現在のセグメントを閉じて、その長さを記録します。 累計をリセットし、次のセグメントの構築を続けます。 これが機能するのは、セグメントの合計を正確に一致させる必要があり、ポジティブであるため、検出されずにオーバーシュートすることがないことが保証されます。 
5. いずれかの時点で累計が超過した場合`target`、構築は失敗します。 これは、指定された制約の下では有効なパーティションを形成できないことを意味します。 
6. すべての要素を処理した後、それが正確であることを確認します。`k`セグメントが形成され、配列全体が消費されました。 存在する場合は、セグメントの長さを出力します。 それ以外の場合は「いいえ」を出力します。 

### なぜ効果があるのか

 正確さは、完成した各セグメントの合計が次と正確に等しいという不変条件に基づいています。`target`、累計が超えることはありません`target`。 すべての要素は厳密に正であるため、累計が次の値に達すると、`target`、さらに追加すると制約に違反するため、その時点でカットが発生する必要があります。 これにより、解決策が存在する場合は常に、問題の一意性の保証と一致して、すべてのセグメント境界が一意に強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

total = sum(a)

if total % k != 0:
    print("No")
    sys.exit()

target = total // k

res = []
curr = 0
length = 0

for x in a:
    curr += x
    length += 1

    if curr == target:
        res.append(length)
        curr = 0
        length = 0
    elif curr > target:
        print("No")
        sys.exit()

if len(res) == k:
    print("Yes")
    print(*res)
else:
    print("No")
```実装は、実現可能性のための厳しい前提条件である割り算条件を強制することから始まります。 次に、スキャンによって現在のセグメントの合計と長さの両方が同時に累積され、余分な記録を行わずにセグメント サイズを直接出力できるようになります。 

実装の重要な詳細は、次の場合に即時終了することです。`curr > target`。 このチェックを行わないと、無効なパーティションが黙って続行され、不正確なセグメント数が生成される可能性があります。 もう 1 つの微妙な点は、両方をリセットすることです`curr`そして`length`長さのリセットに失敗すると出力構造が歪む可能性があるため、セグメントが閉じるときとまったく同じです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    total = sum(a)
    if total % k != 0:
        return "No"

    target = total // k
    res = []
    curr = 0
    length = 0

    for x in a:
        curr += x
        length += 1
        if curr == target:
            res.append(length)
            curr = 0
            length = 0
        elif curr > target:
            return "No"

    if len(res) == k:
        return "Yes\n" + " ".join(map(str, res))
    return "No"

# provided sample
assert run("6 3\n3 3 1 4 1 6\n") == "Yes\n2 3 1"

# custom: impossible due to divisibility
assert run("3 2\n1 2 3\n") == "No"

# custom: all equal
assert run("5 5\n1 1 1 1 1\n") == "Yes\n1 1 1 1 1"

# custom: early failure

 ## 特殊なケース

 最初のエッジ ケースは、合計が次の値で割り切れない場合に発生します。`k`。 入力用`n = 3, k = 2, a = [1, 2, 3]`、合計は 6 なので、ターゲットは 3 です。スキャンによりセグメントが生成されます。`[1,2]`そして`[3]`、両方の合計が正しく、割り算だけでは十分ではないが、割り算が必要であることを示しています。 

2 番目のケースには、早期のオーバーシュートが含まれます。 入力用`n = 4, k = 2, a = [5,1,1,1]`、ターゲットは 4 です。最初の要素はすでにターゲットを超えているため、アルゴリズムはすぐに終了します。 削減を遅らせようとしても、前向きな姿勢によって総額がさらに増加するだけであり、不可能であることが確認される。 

3 番目のケースは、次のような最大の断片化です。`n = 5, k = 5, a = [1,1,1,1,1]`。 各要素は個別にターゲットと一致し、長さ 1 の 5 つのセグメントが生成されます。 このアルゴリズムは要素ごとに自然にリセットされるため、極端なパーティション密度でも正確性が実証されます。
