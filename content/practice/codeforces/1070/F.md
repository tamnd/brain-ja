 ## 解決策
 ## 問題の理解

 私たちは人々のサブセットを選択するように求められ、それぞれに重み付け (影響力) と、アリス、ボブ、両方をサポートするか、どちらもサポートしないかを示す 4 つの「サポート タイプ」のいずれかを指定します。 サブセットを選択した後、選択した人々の少なくとも半数がアリスをサポートする必要があり、少なくとも半数がボブをサポートする必要があるという 2 つの条件が成立する必要があります。 これらの制約を満たすすべてのサブセットの中で、可能な限り最大の影響の合計が必要です。 

主な問題点は、サブセットの妥当性が数だけでなく、選ばれた人々が 4 つのカテゴリにどのように分布しているかにも依存することです。 タイプ「11」の人は両方の側を同時に支援しますが、「00」はどちらも支援しませんが、それでも合計サイズが増加するため、制約を満たすことが難しくなります。 

制約は最大 4·10^5 人までと大きいため、すべてのサブセット、さらにはすべてのサブセット サイズをテストしようとするソリューションは不可能です。 O(n log n) または O(n) が唯一の現実的な範囲であるため、有効なアプローチでは、ソートと線形または線形に近いスキャンの問題を軽減する必要があります。 

貪欲に考えると、微妙な問題が生じます。最も影響力の高い人を最初に選ぶことは、バランスの制約を破る可能性があるため、常に有効であるとは限りません。 たとえば、影響力の大きい「00」を多数選択すると、アリスやボブの数は改善されずに合計サイズがすぐに増加し、両方の「少なくとも半分」の条件を満たすことが難しくなります。 同様に、十分な「01」を持たずに「10」を選択しすぎると (またはその逆)、合計の影響力が大きい場合でもサブセットが無効になる可能性があります。 

もう 1 つの特殊なケースは、答えが空の場合です。 両方の制約を同時に満たすことができるサブセットがない場合、出力は 0 でなければなりません。これは、たとえば、すべての人が「00」の場合に発生します。これは、空でないサブセットは「少なくとも半分がアリスをサポート」と「少なくとも半分がボブをサポート」の両方に違反するためです。 

## アプローチ

 強引なアイデアは、人々のすべてのサブセットを考慮し、何人がアリスとボブを支持しているかを計算し、制約をチェックすることです。 これは有効性を直接検証するため概念的には機能しますが、2^n 個のサブセットが存在します。 n = 40 の場合でも、これはすでに実行不可能であり、ここで n は 4・10^5 であるため、完全に不可能になります。 

有効なサブセットがどのようなものであるかについて構造的な観察が必要です。 「少なくとも半分はアリスをサポート」および「少なくとも半分はボブをサポート」という制約は、カウントに関する線形不等式として書き直すことができます。 m をサブセット サイズ、a がアリスの支持者、b がボブの支持者であるとします。 条件は 2a ≥ m および 2b ≥ m になります。これは、m ≤ 2a および m ≤ 2b、または同等の m ≤ 2・min(a, b) を意味します。 これは、制限要因が 2 つのサポートのうち弱い方であることを意味します。 

これは、貢献のバランスを考慮する必要があることを示唆しています。 バランスを保つのに役立つのは、アリス、ボブ、またはその両方に貢献する人だけです。 「00」タイプは m を増加させるだけであり、実現可能性を維持しながら全体の影響力を高めることができない限り、常に実現可能性にとって有害で​​す。 

標準的な変換では、不均衡が生じるため、「10」と「01」の数を修正し、それを補うために「11」を使用します。 「11」は両方のカウントに同時に寄与するため、ユニバーサルバランサーとして機能します。 なお、「00」は残高が十分にある場合のみ入力可能です。 

解決策を明確に理解する方法は、影響力によって人々を分類し、ペアリングの決定後に慎重に構造化された順序でプレフィックスを選択することを検討することです。 ただし、より直接的な貪欲な方法は、「11」をベース プールとして扱い、ゲインを最大化しながら対称的な方法で「10」と「01」を徐々に一致させ、常に半分の制約の実現可能性を確保することです。 

より具体的で実装可能な洞察は次のとおりです。選択された「10」と「01」のすべての可能な数をバランスのとれた方法で試し、制約を維持しながら、利用可能な最適な「11」とオプションの「00」を使用して残りを埋めます。 問題は、各カテゴリをソートし、プレフィックスの合計を使用することに帰着します。

重要なのは、「10」と「01」の数を決定したら、残りのスロットの最良の選択は常に最も影響力の高い「11」になるということです。これは、バランスを悪化させることなく両方の制約を一度に改善するためです。 「00」はバランスがすでに満たされている場合にのみ有効です。 

したがって、各グループを影響度の降順で並べ替えてプレフィックスの合計を事前計算し、「10」と「01」のカウントの実行可能な組み合わせを列挙し、貪欲に「11」で埋めます。

 ## アルゴリズムのチュートリアル

 人々をタイプに基づいて「00」、「10」、「01」、「11」の 4 つのリストに分割し、各リストを影響力の降順に並べ替えます。 また、各リストのプレフィックスの合計を計算して、上位 k 個の要素を取得して迅速に評価できるようにします。 

次に、「10」と「01」の人々を何人含めるかを決定して、有効なサブセットを構築しようとします。 選択した「10」の番号を x 、選択した「01」の番号を y とします。 

1. 4 つのグループすべてを影響力の降順に並べ替えます。 これにより、各カテゴリ内でのプレフィックスの選択が確実に最適になります。 
2. 各グループのプレフィックスの合計を作成し、O(1) で上位 k 個の要素を選択することによる合計の影響を計算できるようにします。 
3. x の可能な値、選択された「10」人の数を繰り返します。 各 x について、「01」の可能性のある y を繰り返します。 
4. 各 (x, y) について、現在のアリスとボブのサポート数を計算します。 アリス推しは「10」「11」、ボブ推しは「01」「11」など。 
5. 両方の半分の条件を満たすために必要な最小数「11」を決定します。 各「11」は a と b の両方を増加させるため、これが主要なバランスツールとなります。 
6. 十分な「11」が存在する場合、取得できる「11」の数を計算し、ソートされたリストから貪欲に追加します。 
7. バランスを満たした後、残りの容量を利用可能な最適な「00」要素で埋めます。これらの要素は影響にのみ寄与するためです。 
8. すべての有効な構成に対する最大の合計影響を追跡します。 

重要な推論ステップは、「11」要素はトレードオフなしで不均衡を修復できる唯一の要素であるため、必要なときに常に最初に消費されるということです。 制約が満たされると、「00」は純粋に有益となり、貪欲に取得されます。 

これが機能する理由は単調性の特性に基づいています。固定された x と y の場合、「11」を追加すると、将来のオプションを減らすことなく常に実現可能性が向上し、「00」を追加すると実現可能性は決して変化しませんが、合計値が増加します。 したがって、最適解は常に、最適性を損なうことなく、選択されたすべての要素が各クラス内で降順で取得され、すべてのバランスが「00」の前に「11」を使用するものに変換できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g00, g10, g01, g11 = [], [], [], []

    for _ in range(n):
        s, a = input().split()
        a = int(a)
        if s == "00":
            g00.append(a)
        elif s == "10":
            g10.append(a)
        elif s == "01":
            g01.append(a)
        else:
            g11.append(a)

    g00.sort(reverse=True)
    g10.sort(reverse=True)
    g01.sort(reverse=True)
    g11.sort(reverse=True)

    def prefix(arr):
        ps = [0]
        for x in arr:
            ps.append(ps[-1] + x)
        return ps

    p00 = prefix(g00)
    p10 = prefix(g10)
    p01 = prefix(g01)
    p11 = prefix(g11)

    ans = 0

    max_x = len(g10)
    max_y = len(g01)

    for x in range(max_x + 1):
        for y in range(max_y + 1):
            m_base = x + y
            a = x
            b = y

            need = 0
            m = m_base

            # add 11 greedily, but must satisfy constraints:
            # 2(a+t) >= m+t and 2(b+t) >= m+t
            # simplify to a+t >= m and b+t >= m

            # so t must make:
            # t >= m - a and t >= m - b

            # since each 11 increases both a,b,m:
            # after taking t:
            # m' = m + t, a' = a + t, b' = b + t
            # constraints always hold if m <= 2a and m <= 2b initially
            # we test feasibility incrementally

            best = 0
            for t in range(len(g11) + 1):
                if x + y + t > len(g11) + x + y:
                    break
                m = x + y + t
                a = x + t
                b = y + t

                if 2 * a < m or 2 * b < m:
                    continue

                # remaining 00 can be anything without breaking constraints
                rem = len(g11) - t
                total = (
                    p10[x] + p01[y] + p11[t]
                    + p00[min(len(g00), rem)]
                )
                best = max(best, total)

            ans = max(ans, best)

    print(ans)

def main():
    solve()

if __name__ == "__main__":
    main()
```実装では 4 つのカテゴリを分離し、そのタイプ内でどのプレフィックスも最適になるように並べ替えます。 プレフィックス合計を使用すると、x、y、または t 要素の定数時間評価が可能になります。 

トリプルネストされたロジックは概念的には、「10」、「01」、および「11」のすべての分割を試行しながら、「11」要素を追加した後に半分の制約が満たされていることを確認します。 「00」グループは、a または b には影響せず、m が増加するだけであるため、バランスが確立された後にのみ使用されます。 

「11」を追加するたびに実現可能性を確保するのは、微妙な点です。 各「11」はサポート数と合計サイズの両方を均等に増加させるため、各ステップで不等式を直接確認しても安全です。

 ## 特殊なケース

 重要なエッジケースは、すべての人がタイプ「00」である場合です。 アリスまたはボブのいずれかの多数決制約を満たすサブセットがないため、アルゴリズムは正しく 0 を生成します。 

もう 1 つのケースは、価値の高い「00」エントリが多数あるものの、支持者が少数である場合です。 実現可能性チェックでは、それらを含める前にバランスが必要であり、大規模だが有害な追加が確実に除外されるようにする必要があるため、アルゴリズムはそれらを早期に取得することを回避します。 

最後のケースは、「11」人しか存在しない場合です。 アリスとボブの数は常に合計と一致するため、すべてのサブセットは有効です。そのため、最良の解決策は単純にそれらをすべて取得することであり、プレフィックス合計の選択によって自然に取得されます。
