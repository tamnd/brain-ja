 ## 問題の理解

 それぞれに処理時間が指定された一連のタスクが与えられます。 Polycarp はタスクを左から右にスキャンし、しきい値に基づいて各タスクを実行するかスキップするかを決定します。$d$。 期間が次を超えるタスク$d$期間が長くてもタスクは完全に無視されます$d$即時に実行され、その全期間が総作業時間に寄与します。 

実行には追加の制約があります。$m$タスクが完了したら、Polycarp はそのタスクに費やした合計時間と同じ長さの必須の休憩を取る必要があります。$m$タスク。 休憩はスキップされたタスクには依存せず、完了したタスクのみに依存します。 最後のグループに含まれるのは次のグループよりも少ない場合があります$m$作業を行うため、完全な休憩は必要ありません。 

合計時間 (作業時間と休憩時間) がそれを超えると、プロセスは正確に停止します。$t$、開始されたものの、その時点までに終了していないタスクは、完了したものとしてカウントされません。 

目標は選択することです$d$完了したタスクの数が最大化されるようにします。 

制約があるため、効率について慎重に考える必要があります。 すべてのテスト ケースにわたるタスクの合計数は最大です。$2 \cdot 10^5$、および固定の各シミュレーション$d$線形にすることができます。 あらゆる可能性を試す素朴な解決策$d$それぞれを独立して最初からシミュレートするには、$O(n \cdot \max p_i)$あるいはさらに悪いことに、それは実行不可能です。 

隠された構造は、$d$対象となるタスクのセットが増えるだけです。 この単調性は、二分探索を示唆しています。$d$ただし、ブレークメカニズムと停止条件により、実現可能性のチェックは簡単ではありません。 

不注意なソリューションを壊すエッジケースには、休憩が時間の消費を支配するシナリオや、初期の大規模なタスクが非直感的な方法で完了数を減らすシナリオが含まれます。 たとえば、次のようなシーケンス$[1, 100, 1, 1, 1]$小さいもので$d$休憩を完全に回避しますが、$d$それらがトリガーされ、合計使用可能時間が大幅に減少します。 もう一つのエッジケースは、$m = 1$、すべてのタスクがその期間に等しい即時中断を引き起こし、タスクあたりのコストが 2 倍になります。 

## アプローチ

 ブルートフォース手法で候補のしきい値を修正する$d$Polycarp のプロセスを正確にシミュレートします。 タスクを左から右にスキャンし、現在のセグメントで実行されたタスクのリストを維持し、作業時間を蓄積し、到達するたびに実行します。$m$完了したタスクには、合計作業時間に等しい休憩が追加されます。 時間を超えたらやめる$t$完了したタスクの数を返します。 すべての異なる値を試してみます$d$のセットから$p_i$値は最大でも$n$シミュレーション、それぞれのコスト$O(n)$、につながる$O(n^2)$最悪の場合のテストごとに。 と$n$まで$2 \cdot 10^5$、これは実行不可能です。 

重要な観察は、実現可能性が単調であるということです。$d$。 しきい値の場合$d$の完了を許可します$k$タスクの場合、しきい値を大きくしても、適格なタスクを追加することはできますが、それを減らすことはできません。 これにより、二分検索が可能になります。$d$。 

ただし、固定値を評価する迅速な方法がまだ必要です。$d$。 シミュレーション自体は線形ですが、中断を正しくモデル化し、スキップされたタスクではなく実行されたタスクのみを追跡するように注意する必要があります。 

さらなる改良点は、すべての整数に対して二分探索を行う必要がないことです。 考慮する必要があるのは、次の値の間だけです。$p_i$、変わってから$d$並べ替えられた順序で 2 つの隣接する値の間を変更しても、有効なタスクのセットは変更されません。 これにより、検索スペースが減少します。$O(n)$、インデックスに対する二分検索で十分になります。

 ## アルゴリズムのチュートリアル

 個別のタスク値をソートし、このソートされた配列のインデックスをバイナリ検索して、それを候補しきい値として扱います。 

候補者ごとに$d$、実行をシミュレートします。 

1. タスクを左から右にスキャンし、次のタスクのみを処理します。$p_i \le d$。 より大きなタスクは完全に無視され、時間に影響を与えないため、これは Polycarp のルールを正確にモデル化します。 
2. 受け入れられたすべてのタスクについて、その処理時間を実行中のカウンタに加算し、現在のバッチで完了したタスクのカウンタをインクリメントします。 
3. バッチサイズに達するたびに$m$、最後の休憩の合計に等しい休憩を追加します。$m$そのバッチ内のタスクを実行してから、バッチ カウンターをリセットします。 これにより、休憩コストはスキップされたタスクではなく、実行されたタスクにのみ依存することが保証されます。 
4. 当社は合計経過時間を継続的に維持します。 いずれかの時点でそれを超えた場合$t$、これ以上のタスクを完了できないため、シミュレーションを直ちに停止します。 
5. このタスクの完了したタスクの総数を記録します。$d$、それを使用して、より大きなしきい値またはより小さなしきい値に向けて二分探索をガイドします。 

二分探索が終了したら、最良のものを得るために 1 回再計算します。$d$タスクの正確な数としきい値を出力します。 

正しさは、$d$適格なタスクを追加するだけであり、以前に実行可能なタスクは削除されません。 これは、実行可能なタスク数のシーケンスが単調であることを意味します。$d$。 各シミュレーションはプロセスを忠実に再構築したものであるため、全体の最大値は$d$増加する境界を検索することで見つかります。$d$結果は改善されなくなりました。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def simulate(p, d, m, t):
    time = 0
    cnt = 0
    batch = 0
    batch_sum = 0

    for x in p:
        if x > d:
            continue

        time += x
        batch += 1
        batch_sum += x
        cnt += 1

        if time > t:
            return cnt - 1

        if batch == m:
            time += batch_sum
            if time > t:
                return cnt
            batch = 0
            batch_sum = 0

    return cnt

def solve():
    c = int(input())
    for _ in range(c):
        n, m, t = map(int, input().split())
        p = list(map(int, input().split()))

        vals = sorted(set(p))

        def f(d):
            return simulate(p, d, m, t)

        lo, hi = 0, len(vals) - 1
        best_cnt = 0
        best_d = vals[0]

        while lo <= hi:
            mid = (lo + hi) // 2
            d = vals[mid]
            cur = f(d)

            if cur >= best_cnt:
                best_cnt = cur
                best_d = d

            if mid + 1 < len(vals) and f(vals[mid + 1]) >= cur:
                lo = mid + 1
            else:
                hi = mid - 1

        print(best_cnt, best_d)

if __name__ == "__main__":
    solve()

二分探索では、値を増やすと答えが良くなるという事実を利用します。$d$ただし、最適なしきい値を見逃さないように、候補点で明示的に評価します。 

微妙な点は、時間を超えたら早めに停止することです。$t$、タスク数を増やすことができないため、これ以上のシミュレーションは必要ありません。
