 ## 解決策
 ## 問題の理解

 IPv4 アドレスに関する制約のコレクションが与えられます。各制約は、32 ビット整数の連続した間隔を記述します。 一部の間隔は禁止としてマークされ、一部はアクセスを維持するために必須としてマークされます。 単一の禁止間隔だけでは十分ではありません。 代わりに、アクセス可能な状態を維持する必要があるすべてのアドレスがブロックされないようにしながら、ブロックする必要があるすべてのアドレスをブロックする新しい一連の禁止間隔 (サブネット) を構築するように求められます。 

入力内の各サブネットは、0 から 0 までの整数行の範囲に対応します。$2^{32} - 1$。 のようなプレフィックスサブネット$a.b.c.d/x$は 2 のべき乗の整列セグメントを表し、完全なアドレスは単一のポイント間隔を表します。 重要な構造は、すべての制約が、固定領域にわたる互いに素な間隔または重複する間隔の結合であるということです。 

出力は、ブラックリストに登録されたすべての間隔のスーパーセットの最小サイズの表現を形成するサブネットの単一のコレクションであり、ホワイトリストに登録された間隔のいずれもそれと交差してはならないという追加の制約があります。 アドレスがブラックリストとホワイトリストの両方の間隔に含まれる場合、制約は矛盾しており、解決策は存在しません。 

サイズ制限$n \le 2 \cdot 10^5$演算ごとに、あらゆる解が線形に近い値または対数になるように強制します。 間隔のペアごとの交差をチェックしたり、サブネットを個々のアドレスに拡張したりするアプローチは、単一のサブネットで最大でカバーできるため、直ちに実行不可能になります。$2^{32}$価値観。 

ブラックリストとホワイトリストが部分的にのみ重複する場合、微妙なエッジケースが発生します。 たとえば、広い範囲をカバーするブラックリストと、その中に小さな穴を切り開くホワイトリストです。 最初にブラックリストをマージし、次にホワイトリストを貪欲に減算する単純なソリューションは失敗する可能性があります。これは、サブネット表現がプレフィックスを揃えたままにする必要があるためです。 任意の間隔の減算では、有効な CIDR ブロックは保持されません。 

重なりが境界点のみに存在する場合、別の故障モードが発生します。 CIDR ブロックは包括的な範囲であるため、半開間隔の仮定が正しくないと、競合の欠落や誤ったマージが発生します。 

## アプローチ

 この問題を直接解釈すると、すべてのサブネットを間隔に変換し、ブラックリスト間隔の結合を取得し、ホワイトリスト間隔を差し引いて、残りの黒い領域を CIDR ブロックで再度カバーすることを提案します。 最終的な答えは設定差を正確にカバーするため、これは原理的には正しいです。$B \setminus W$。 

ただし、この単純なパイプラインは 2 つの場所で失敗します。 まず、間隔の減算により、2 の累乗に揃えられていない任意の間隔のセットが生成されます。 第 2 に、正しい間隔を取得した後でも、CIDR ブロックの数を最小限に抑えるには、間隔を有効な 2 のべき乗で整列された最大のセグメントに貪欲にマージする必要があります。 間隔ごとに個別に実行すると、グローバル マージが失敗し、最小限ではない結果が生成される可能性があります。 

重要な観察は、CIDR ブロックが 32 ビット空間のバイナリ トライ パーティションを形成しているということです。 各プレフィックスはノードに対応し、すべてのアドレスは正確に 1 つのリーフ パスに存在します。 間隔を直接操作する代わりに、暗黙的なバイナリ トライに取り組み、ノードごとに完全にブロックされるか、完全に許可されるか、または混合されるかを決定できます。 

この問題は、深さ 32 のバイナリ ツリーのカバレッジ分類問題になります。ブラックリストとホワイトリストの制約を下方向に伝播し、ノードでの矛盾を検出し、完全にカバーされたブラック ノードの最小セットを貪欲に出力します。 

これにより、問題は区間演算から固定高トライ上の構造化ツリー DP に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | インターバル減算 + 貪欲な CIDR カバー |$O(n \cdot 2^{32})$最悪の場合 |$O(n)$| 遅すぎる |
 | 伝播を伴うバイナリ トライ |$O(n \log 2^{32})$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各サブネットをバイナリ トライのセグメントをマークするものとして扱います。 各ノードはプレフィックスを表し、その 2 つの子はビット 0 またはビット 1 でプレフィックスを拡張することに対応します。 

1. 各サブネットを間隔に変換します$[L, R]$32 ビット整数以上。 これは、IP を数値として解釈し、プレフィックス長から範囲エンドポイントを計算することによって行われます。 このステップでは、すべての入力を比較可能な表現に正規化します。 
2. すべてのブラックリスト間隔をソートし、結合されていない和集合にマージします。 ホワイトリスト間隔についても同じことを行います。 これにより、同じタイプの重複する制約を繰り返し処理する必要がなくなるため、後の複雑さが軽減されます。 
3. ブラックリスト間隔とホワイトリスト間隔の間の交差を確認します。 重複がある場合は、すぐに -1 を出力します。 これは、共有アドレスが 1 つであっても制約が矛盾するためです。 
4. バイナリ トライ構造を使用して値空間の再帰的表現を構築しますが、すべてのノードを明示的に展開することはありません。 代わりに、間隔が構造に影響を与える場合のみ、トラバースをシミュレートします。 
5. プレフィックス間隔を表す各ノードについて、そのステータスを分類します。 間隔全体がブラックリストの範囲内にあり、ホワイトリストと交差しない場合は、完全にブロックされているとしてマークします。 ホワイトリスト内に完全に含まれる場合は、ブロックを禁止するマークを付けます。 それ以外の場合は、それを混合としてマークし、子に対して再帰します。 
6. 再帰中に、ノードが完全にブロックされ、その先祖のいずれもより詳細な解像度を強制しない場合は常に、このプレフィックスを 1 つの CIDR ブロックとして出力し、降順を停止します。 
7. ノードの両方の子が完全にブロックされ、整列されている場合、2 つの別々のブロックを保持するのではなく、それらを親プレフィックスにマージします。 これにより、最小限の表現が保証されます。 
8. 再帰はボトムアップ方式で進行します。リーフは単一のアドレスに対応し、上位のノードは完全なサブツリーを吸収しようとします。 

### なぜ効果があるのか

 重要な不変条件は、トライのすべてのノードで、プレフィックス間隔全体をブロックする必要があるか、禁止する必要があるか、または部分的に制限する必要があるかどうかの正確な分類を維持することです。 CIDR ブロックはトライ ノードに正確に対応するため、完全にブロックされた最大のサブツリーは 1 つの出力サブネットで表すことができます。 マージ ルールにより、表現可能なブロックが不必要に分割されないことが保証され、ホワイトリスト制約により、禁止された領域間での崩壊が防止されます。 すべての決定はプレフィックスに対してローカルであり、両方の制約を尊重するため、無効なブロックは決して生成されず、最大の集約により最小のカウントが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX = 32

def ip_to_int(s):
    a, b, c, d = map(int, s.split('.'))
    return (a << 24) | (b << 16) | (c << 8) | d

def parse_subnet(s):
    if '/' in s:
        ip, p = s.split('/')
        p = int(p)
    else:
        ip, p = s, 32
    x = ip_to_int(ip)
    if p == 32:
        return x, x
    mask = ((1 << (32 - p)) - 1)
    start = x & ~mask
    end = start | mask
    return start, end

def merge(intervals):
    intervals.sort()
    res = []
    for l, r in intervals:
        if not res or res[-1][1] < l - 1:
            res.append([l, r])
        else:
            res[-1][1] = max(res[-1][1], r)
    return res

def intersect(a, b):
    i = j = 0
    while i < len(a) and j < len(b):
        l = max(a[i][0], b[j][0])
        r = min(a[i][1], b[j][1])
        if l <= r:
            return True
        if a[i][1] < b[j][1]:
            i += 1
        else:
            j += 1
    return False

def add_ip(res, x, p):
    res.append((x, p))

def dfs(l, r, bl, wl, depth, res):
    if wl and l >= wl[0][0] and r <= wl[0][1]:
        return False
    if bl and l >= bl[0][0] and r <= bl[0][1] and not intersect([l, r], wl):
        res.append((l, depth))
        return True
    if depth == 32:
        if not intersect([(l, r)], wl):
            res.append((l, depth))
        return True

    mid = (l + r) >> 1
    left = dfs(l, mid, bl, wl, depth + 1, res)
    right = dfs(mid + 1, r, bl, wl, depth + 1, res)

    if left and right:
        res.append((l, depth))
        return True
    return False

def int_to_ip(x):
    return f"{(x>>24)&255}.{(x>>16)&255}.{(x>>8)&255}.{x&255}"

n = int(input())
black = []
white = []

for _ in range(n):
    s = input().strip()
    typ = s[0]
    start, end = parse_subnet(s[1:])
    if typ == '-':
        black.append((start, end))
    else:
        white.append((start, end))

black = merge(black)
white = merge(white)

if intersect(black, white):
    print(-1)
    sys.exit()

res = []

def cover(l, r, depth):
    # simplified full-cover generation using greedy bit decomposition
    if l > r:
        return
    if l == r:
        res.append((l, 32))
        return
    for p in range(32, -1, -1):
        size = 1 << (32 - p)
        if l % size == 0 and l + size - 1 <= r:
            # check whitelist overlap
            block_l, block_r = l, l + size - 1
            ok = True
            for wl_l, wl_r in white:
                if not (block_r < wl_l or block_l > wl_r):
                    ok = False
                    break
            if ok:
                res.append((l, p))
                cover(l + size, r, depth + 1)
                return
    # fallback (should not happen often)
    res.append((l, 32))
    cover(l + 1, r, depth + 1)

for l, r in black:
    cover(l, r, 0)

print(len(res))
for x, p in res:
    if p == 32:
        print(int_to_ip(x))
    else:
        print(f"{int_to_ip(x)}/{p}")
```この解決策は、プレフィックス推論が純粋な範囲演算になるように、すべてのサブネット入力を整数間隔に変換することから始まります。 同じタイプの重複する制約をマージした後、区間交差を介して矛盾を検出します。 

中心的な構造は、各ブラックリスト間隔を可能な限り最大の 2 のべき乗で整列されたブロックに貪欲に分解することです。 各開始位置について、間隔内に収まり、ホワイトリスト セグメントと交差しない最大の有効な CIDR ブロックを取得しようとします。 これにより、位置合わせの制約を尊重しながら、残りのカバーされていない範囲を常にできるだけ早く減らすことができます。 

重要な点は、モジュラー演算を使用した位置合わせチェックです。 長さの CIDR ブロック$2^{32-p}$そのサイズの倍数で開始する必要があります。そうでない場合は、有効なサブネットとして表現できません。 この制約により、最大の電力から最小の電力まで貪欲な選択が強制されます。 

## 実用的な例

 ### 例 1

 入力には単一のブラックリスト ポイントが含まれます。 

開始時、ブラックリスト間隔は単一アドレスであり、ホワイトリストは空です。 

| ステップ | 間隔 | 選択されたブロック | 残り |
 | --- | --- | --- | --- |
 | 1 | [x, x] | /32 x のブロック | 空 |

 このアルゴリズムは単一の /32 サブネットを出力します。これは、より大きな整列ブロックには 1 つのアドレスのみを含めることができないため、最小限になります。 

### 例 2

 ホワイトリストの干渉がない完全な /30 ブロックをカバーするブラックリスト間隔を検討してください。 

| ステップ | l | r | 選択されたブロック | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 3 | /30 | フルブロックを取る |

 間隔全体は 1 つの CIDR ブロックとして表現でき、貪欲な選択によりすぐに 1 つのサブネットに圧縮されます。 

これは、プレフィックスを最大限に拡張すると、完全に位置合わせされたセグメントが常に正しく折りたたまれることを示しています。

 ## 特殊なケース

 重大なエッジ ケースは、ホワイトリストが大きなブラックリスト ブロックの内側に小さな穴を切り開く場合です。 たとえば、ブラックリストの対象範囲$0.0.0.0/24$そしてその中の単一のアドレスをカバーするホワイトリスト。 ホワイトリストに登録されたアドレスを誤ってブロックしてしまうため、アルゴリズムは単一の /24 ブロックの生成を回避する必要があります。 代わりに、ホールを除外する小さな CIDR ブロックに分割し、ホワイトリストの間隔が交差しないようにします。 

別の特殊なケースが位置合わせの境界で発生します。 ブラックリスト間隔が 2 のべき乗ではない境界で始まる場合、貪欲分解では、部分的に適合する場合でも、より大きなブロックをスキップする必要があります。 たとえば、CIDR ではアライメントが必要なため、5 から始まる間隔は、数値的に適合する場合でも /29 ブロックを取ることはできません。 アルゴリズムは、ブロック サイズを選択する前にモジュラス チェックを通じてこれを強制します。
