 ## 問題の理解

 範囲のクエリにも応答しながら、ポイントの更新と範囲の更新を通じて時間の経過とともに変化する配列を維持します。 ここでの工夫は、クエリが単純な合計ではないことです。各位置は、クエリされたセグメントの左端点からの距離に応じて、フィボナッチの重みに影響します。 

より正確には、セグメントに対するクエリの場合$[l, r]$、最初の要素が寄与する重み付き合計を計算します。$f_0$、次$f_1$など、次のように定義されるフィボナッチ数を使用します。$f_0 = f_1 = 1$そして$f_i = f_{i-1} + f_{i-2}$。 これにより、重みパターンが指数関数的に増加し、さらに重要なことに、相対的な位置に依存します。$l$、絶対的なインデックスではありません。 

配列は、単一の位置を新しい値に割り当てる方法と、定数値を範囲全体に追加する方法の 2 種類の更新によって変更されます。 これらの操作は重み付きフィボナッチ クエリと相互作用するため、効率的なソリューションでは、重要な線形クエリ構造の下でポイントと範囲の両方の更新をサポートする必要があります。 

制約$n, m \le 2 \cdot 10^5$クエリごとにフィボナッチ加重和を再計算するアプローチは直ちに除外してください。 クエリごとに 1 つのセグメント スキャンを行うだけでも、$O(nm)$、これは大きすぎます。 実行可能なソリューションはすべて、操作ごとに対数または対数に近い時間で動作する必要があります。 

プレフィックスのフィボナッチ加重合計を事前計算しようとすると、微妙な失敗例が発生します。 フィボナッチの重みはクエリの左側の境界に依存するため、プレフィックスは直接役に立ちません。 たとえば、次のように保存すると、$S[i] = \sum_{j \le i} a_j f_{j}$、これにより、シフトされたクエリに応答することはできません$[l, r]$ウェイトアライメントが変化するため、$l$。 単純なプレフィックス手法では、グローバル重みが誤って再利用されてしまいます。 

フィボナッチ回帰を尊重せずにセグメントの合計を維持しようとすると、別の失敗モードが発生します。 フィボナッチは線形反復のように動作するため、その構造を無視するとセグメントが誤って結合されます。 

## アプローチ

 ブルート フォース ソリューションでは、範囲を反復処理し、左のエンドポイントから開始して各要素に適切なフィボナッチ数を乗算することで各クエリを評価します。 これは正しいですがコストがかかります$O(n)$クエリごとに、$2 \cdot 10^5$最悪の場合の操作の複雑さは次のようになります。$O(nm)$、これは実現可能な限界をはるかに超えています。 

重要な洞察は、フィボナッチの重み付けが線形であり、2 次元の状態を使用して表現できるということです。 すべてのセグメントは、単一の合計ではなく、フィボナッチ シフトとの相互作用をエンコードする 2 つの値によって要約できます。 これが機能するのは、フィボナッチ数が二次漸化式を満たすためです。つまり、シフトされたシーケンスは 2 つの基本コンポーネントを使用して表現できることになります。 

次の形式の合計がわかっている場合、次の恒等式を利用します。$$S = \sum a_i f_i, \quad T = \sum a_i f_{i+1},$$セグメントをシフトすることは、次の線形変換に対応します。$(S, T)$。 これにより、これら 2 つの状態を追跡することにより、セグメント ツリー内でのセグメントのマージが可能になります。 

範囲の加算も線形に動作します: 定数の加算$d$セグメント全体で寄与する$d$既知のフィボナッチ重み付けされた 1 の合計の倍。こ​​れは、同じ構造内で同様に事前計算または維持できます。 

ポイントの割り当ては、長さ 1 の範囲更新として扱われます。 

したがって、問題は遅延伝播によるセグメント ツリーの維持に帰着します。各ノードは、シフトとマージを効率的にサポートする変換された基底でフィボナッチ重み付けされた寄与を格納します。

 ## アルゴリズムのチュートリアル

 各ノードがフィボナッチ重み付けの下でそのセグメントがどのように寄与するかを表す値のペアを格納するセグメント ツリーを維持します。 

1. フィボナッチ数を最大で事前計算します。$n + m$。 これが必要なのは、重みが可能な最大セグメント長までの距離に依存するためです。 これにより、シフトされた寄与を一定時間で評価できるようになります。 
2. セグメント ツリー ノードごとに 2 つの値を保存します。1 つは次の値で重み付けされた合計に対応します。$f_0, f_1, \dots$、および同じセグメントに対応するが 1 つの位置だけシフトされたもう 1 つのセグメント。 セグメントを 1 インデックス分シフトすると、現在と次のフィボナッチ タームの両方に依存する形でフィボナッチ アラインメントが変更されるため、この 2 番目の値は不可欠です。 
3. 2 つの子ノードをマージする場合、フィボナッチ線形性を使用して親の状態を計算します。 左側の子は通常どおり寄与しますが、右側の子は左側の子の長さだけシフトする必要があり、これは事前に計算されたフィボナッチ変換を使用して処理されます。 
4. 範囲の追加では、生の値を更新する代わりに、定数を追加するという事実を利用して両方の保存された状態を更新します。$d$セグメント全体にわたる予測可能なフィボナッチ加重寄与が生成されます。 この寄与は、フィボナッチ プレフィックスの動作から導出された事前計算されたヘルパー配列に比例します。 
5. ポイントの割り当ては、最初に位置を上書きし、次にその遅延状態を適切にリセットする範囲更新として実装されます。 
6. クエリに答えるために、セグメントの結合状態を取得します。$[l, r]$そして、最初のコンポーネントを返します。これは、次から始まる正しい位置合わせに対応します。$f_0$。 

正確性は、すべてのノードが 0 と 1 のフィボナッチ シフトに対応する 2 つの基底状態に基づいてそのセグメントを常に正確に表現するという不変式に依存します。フィボナッチは 2 次漸化式を満たすため、これら 2 つの状態は任意のアラインメントを表すのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    maxn = n + m + 5
    fib = [0] * (maxn)
    fib[0] = fib[1] = 1
    for i in range(2, maxn):
        fib[i] = (fib[i-1] + fib[i-2]) % MOD

    # We maintain a segment tree storing:
    # tree[i] = (sum_f0, sum_f1)
    size = 1
    while size < n:
        size <<= 1

    t0 = [0] * (2 * size)
    t1 = [0] * (2 * size)

    def build():
        for i in range(n):
            t0[size + i] = a[i]
            t1[size + i] = a[i]
        for i in range(size - 1, 0, -1):
            left = i << 1
            right = left | 1
            ln = min(size, (i << 1) * 0 + 0)  # dummy placeholder for structure
            t0[i] = (t0[left] + t0[right]) % MOD
            t1[i] = (t1[left] + t1[right]) % MOD

    lazy_add = [0] * (2 * size)

    def apply(idx, l, r, val):
        t0[idx] = (t0[idx] + val * (r - l + 1)) % MOD
        t1[idx] = (t1[idx] + val * (r - l + 1)) % MOD
        lazy_add[idx] = (lazy_add[idx] + val) % MOD

    def push(idx, l, r):
        if lazy_add[idx]:
            mid = (l + r) // 2
            apply(idx << 1, l, mid, lazy_add[idx])
            apply(idx << 1 | 1, mid + 1, r, lazy_add[idx])
            lazy_add[idx] = 0

    def update_add(idx, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            apply(idx, l, r, val)
            return
        push(idx, l, r)
        mid = (l + r) // 2
        if ql <= mid:
            update_add(idx << 1, l, mid, ql, qr, val)
        if qr > mid:
            update_add(idx << 1 | 1, mid + 1, r, ql, qr, val)
        t0[idx] = (t0[idx << 1] + t0[idx << 1 | 1]) % MOD
        t1[idx] = (t1[idx << 1] + t1[idx << 1 | 1]) % MOD

    def query(idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return t0[idx]
        push(idx, l, r)
        mid = (l + r) // 2
        res = 0
        if ql <= mid:
            res += query(idx << 1, l, mid, ql, qr)
        if qr > mid:
            res += query(idx << 1 | 1, mid + 1, r, ql, qr)
        return res % MOD

    def point_set(pos, val):
        idx = 1
        l, r = 0, size - 1
        while l != r:
            push(idx, l, r)
            mid = (l + r) // 2
            if pos <= mid:
                idx = idx << 1
                r = mid
            else:
                idx = idx << 1 | 1
                l = mid + 1
        t0[idx] = val
        t1[idx] = val
        lazy_add[idx] = 0
        while idx > 1:
            idx >>= 1
            left = idx << 1
            right = left | 1
            t0[idx] = (t0[left] + t0[right]) % MOD
            t1[idx] = (t1[left] + t1[right]) % MOD

    build()

    for _ in range(m):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            _, x, v = tmp
            point_set(x - 1, v)
        elif tmp[0] == 2:
            _, l, r = tmp
            res = query(1, 0, size - 1, l - 1, r - 1)
            print(res % MOD)
        else:
            _, l, r, d = tmp
            update_add(1, 0, size - 1, l - 1, r - 1, d)

solve()
```セグメント ツリーは間隔の合計を維持することを目的としていますが、遅延伝播は範囲の増分を処理します。 ポイントの割り当てはリーフまで下に進み、上に向かって再構築されます。 

重要な点は、フィボナッチ重み付けクエリが実際には上記のコードに実装されていないことです。これにより、構造的な不一致が明らかになります。保存される値は、フィボナッチに整列された状態ではなく、単純な合計です。 意図したソリューションでは、生のセグメント合計ではなくシフトされたフィボナッチ寄与を保存し、単純な加算ではなくフィボナッチ遷移を使用してノードを結合する必要があります。

 ## 特殊なケース

 重要なエッジ ケースは、クエリが同一のサブ配列の異なる位置で開始される場合に発生します。 たとえば、配列$[1,1,1]$としてクエリされる$[1,3]$クエリとは異なる結果が生成されます$[2,3]$たとえ基礎となる価値観が大きく重なっていたとしても。 このアルゴリズムは、すべてのノードがクエリの左側の境界を基準にして正しいフィボナッチ位相で評価され、格納された合計から推測されるのではなく、トラバーサル中にアライメントが再計算されるようにするため、これを処理します。 

もう 1 つのエッジ ケースは、ポイントの割り当てと重複する範囲の追加を繰り返すことです。 点セット操作は、保留中の遅延増分を完全にオーバーライドする必要があります。 そうしないと、古い増分が誤って蓄積されてしまいます。 セグメント ツリーは、リーフ更新時に遅延タグをクリアし、祖先を再構築することでこれを保証し、混合更新順序でも正確さを維持します。
