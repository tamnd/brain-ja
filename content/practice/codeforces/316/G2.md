 ## 問題の理解

 ソース文字列が与えられます`s`。 内部に現れる部分文字列のみに興味があります`s`、出現回数に関係なく、それぞれの個別の部分文字列を 1 回カウントします。 

部分文字列がすべてのルールを満たしている場合、その部分文字列は良好であるとみなされます。 各ルールはパターン文字列で構成されます`p`そして範囲`[l, r]`。 候補部分文字列の場合`t`、何回数えますか`t`内部で発生する`p`部分文字列として。 出現回数が次の範囲にある場合、ルールは満たされます。`l`そして`r`。 

タスクは、次の異なる部分文字列がいくつあるかを数えることです。`s`すべてのルールを同時に満たします。 

この問題を難しくしている最初の点は、入力サイズです。 長さ`s`すべてのルール文字列は 50000 に達する可能性があります。長さ 50000 の文字列には、位置ごとに数えると約 12 億 5000 万の部分文字列があり、ほぼ同じ桁数の候補ペアが含まれます。`(start,end)`。 部分文字列を明示的に列挙するアプローチは絶望的です。 

ルールの数は少なく、多くても 10 です。この非対称性が鍵となります。 非常に長い文字列がありますが、制約はほとんどありません。 

微妙な点は、出現回数が多重度でカウントされることです。 部分文字列がルール文字列内の多くの場所に出現する場合、それらすべてが影響を及ぼします。 

例えば：```

rule: ("aaa", 2, 2)
```部分文字列`"a"`に3回発生します`"aaa"`、一度ではありません。 存在を確認するだけのソリューションでは、それが誤って受け入れられてしまいます。 

もう 1 つの簡単な間違いは、次の異なる部分文字列を数えることを忘れていることです。`s`。```
s = "aaaa"
n = 0
```答えは`4`、に対応`"a"`、`"aa"`、`"aaa"`、`"aaaa"`。 

位置ごとに出現回数をカウントすると、誤って返される`10`。 

3 番目の落とし穴は、下限がゼロのルールに由来します。```
s = "ab"

```のすべての部分文字列`s`それらはいずれも発生しないため、良好です`"c"`。 ルール文字列に出現する部分文字列のみを処理する実装では、有効な回答が失われます。 

この制約は接尾語構造を強く示唆しています。 個別の部分文字列は、接尾辞オートマトンの状態または接尾辞配列内の間隔に自然に対応します。 個別に列挙することなく、すべての個別の部分文字列を評価する方法が必要です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 のすべての個別の部分文字列を生成します`s`。 各候補部分文字列について`t`、およびルール文字列ごとに`p_i`、何回数えますか`t`内部で発生する`p_i`。 すべてのカウントが必要な範囲内にある場合は、答えを増やします。 

これは定義を直接実装しているため、これは正しいです。 残念ながら、壊滅的に遅いです。 がある`Θ(|s|²)`異なる部分文字列の位置と潜在的に`Θ(|s|²)`個別の部分文字列値。 効率的な文字列マッチングを行ったとしても、総作業量は長さ 50000 で可能な作業量をはるかに超えています。 

重要な点は、すべての候補部分文字列が同じソース文字列に由来しているということです。`s`。 部分文字列を 1 つずつ調べる代わりに、次から構築された接尾辞オートマトン内ですべての異なる部分文字列を同時に表すことができます。`s`。 

接尾辞のオートマトン状態は、部分文字列の長さの間隔全体を表します。 すべての部分文字列は、正確に 1 つのペアに対応します。```
(state v, length L)
where
len(link(v)) < L ≤ len(v)
```この表現では、すべての個別の部分文字列が 1 つのみに折りたたまれます。`O(|s|)`州。 

残りの課題はルールを評価することです。 固定ルール文字列の場合`p`、横断するとします。`p`のオートマトンを通して`s`。 あらゆるポジション`p`に表示されるそこで終わる最長の接尾辞を決定します。`s`。 標準的なサフィックス オートマトンのカウント手法を使用すると、状態ごとに、表現された各部分文字列が内部に何回出現するかを蓄積できます。`p`。 

ルールは最大 10 個なので、各ルールを個別に処理できます。 すべての状態について、ルール文字列内のその状態によって表される部分文字列の出現数を決定します。 これらのカウントにより、ルールを満たす長さの間隔が導き出されます。 すべてのルールの間隔を交差させると、その状態で表される適切な部分文字列の長さのセットが得られます。 

最後に、各状態で残っている長さの数を合計します。 

ソリューション全体は、次の 2 つの事実を活用します。

第 2 に、ルール文字列の数が少ないため、オートマトンに対するすべてのルールを個別に処理することが可能です。

 ## アルゴリズムのチュートリアル

 ### 接尾辞オートマトンの解釈

 すべての州について`v`接尾辞オートマトン内:```
mx = len(v)
mn = len(link(v)) + 1
```状態は、長さが属するすべての個別の部分文字列を表します。`[mn, mx]`。 

それぞれの個別の部分文字列は、正確に 1 つの状態内の正確に 1 つの長さに対応します。 

### 1 つのルールの処理

 ルール文字列の場合`p`:

 #### 1. トラバース`p`オートマトンを通して

 あらゆるポジションに対して、`p`、現在のオートマトンの状態と一致する最長のサフィックスの長さを維持します。 

これは標準的な SAM 照合手順です。 

#### 2. エンドポイントの貢献を数える

 走査が状態で終了するたびに`v`、その状態のカウンターをインクリメントします。 

これは、次の 1 つの接尾辞を記録します。`p`で終わる`v`。 

#### 3. カウントを上方に伝播する

 プロセス状態の降順`len`。 

各状態のカウンターをそのサフィックス リンクに追加します。 

この伝播の後、`cnt[v]`の出現数に等しい`p`状態によって表されるすべての部分文字列の`v`。 

This is the classical suffix automaton occurrence-count computation.

 #### 4. Convert counts into valid length intervals

 ルールで次のことが要求されるとします。```
l ≤ occurrences ≤ r
```すべての州について:

 もし`cnt[v]`ルールを満たしている場合、その状態によって表されるすべての長さが引き続き可能になります。 

そうしないと、どれもこの規則を満たすことができません。 

ブール値を保存する代わりに、以前のすべてのルールを処理した後も有効な長さの間隔を状態ごとに維持します。 

カウントがルールを満たす場合は常に、現在の有効な間隔と状態の完全な長さの間隔を交差させます。それ以外の場合は、空の間隔と交差します。 

#### 5. すべてのルールに対して繰り返します。 

各ルールは、各州で許可される長さをさらに制限します。 

すべての交差の後、残りの長さは、すべてのルールを満たす部分文字列に正確に対応します。 

### 最終的なカウント

 各州について:```
allowed = max(0, right[v] - left[v] + 1)
```この量を答えに加えます。 

生き残った各長さは、正確に 1 つの異なる部分文字列に対応します。 

### なぜ効果があるのか

 接尾辞オートマトンは、次のすべての異なる部分文字列を分割します。`s`互いに素な状態長のペアに変換します。 すべての部分文字列は、正確に 1 つの状態と、その状態の長さ間隔内の 1 つの長さの値に属します。 

固定ルール文字列の場合、伝播された状態の出現数は、そのルール文字列内でその状態によって表される部分文字列が出現する数と等しくなります。 これはサフィックス オートマトンの基本的な特性です。つまり、状態によって表されるすべての部分文字列には同じ終了位置が設定され、したがって同じ出現数が設定されます。 

すべてのルールはその出現回数のみに依存するため、状態間隔全体がルールに存続するか、間隔全体が拒否されます。 すべてのルールにわたって存続する長さの範囲を交差させると、すべての制約を満たす部分文字列が正確に残ります。 残りの長さを合計すると、適切な個別の部分文字列がそれぞれ 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SAM:
    def __init__(self):
        self.next = [{}]
        self.link = [-1]
        self.length = [0]

    def extend(self, ch):
        cur = len(self.next)
        self.next.append({})
        self.link.append(0)
        self.length.append(self.length[-1] + 1)

        p = self.last
        while p != -1 and ch not in self.next[p]:
            self.next[p][ch] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][ch]
            if self.length[p] + 1 == self.length[q]:
                self.link[cur] = q
            else:
                clone = len(self.next)
                self.next.append(self.next[q].copy())
                self.link.append(self.link[q])
                self.length.append(self.length[p] + 1)

                while p != -1 and self.next[p].get(ch) == q:
                    self.next[p][ch] = clone
                    p = self.link[p]

                self.link[q] = clone
                self.link[cur] = clone

        self.last = cur

    def build(self, s):
        self.last = 0
        for c in s:
            self.extend(c)

def solve():
    s = input().strip()
    n = int(input())

    sam = SAM()
    sam.build(s)

    sz = len(sam.next)

    maxlen = max(sam.length)
    cnt_len = [0] * (maxlen + 1)

    for x in sam.length:
        cnt_len[x] += 1

    for i in range(1, maxlen + 1):
        cnt_len[i] += cnt_len[i - 1]

    order = [0] * sz
    for v in range(sz - 1, -1, -1):
        l = sam.length[v]
        cnt_len[l] -= 1
        order[cnt_len[l]] = v

    left = [sam.length[sam.link[v]] + 1 if v else 1
            for v in range(sz)]
    right = sam.length[:]

    for _ in range(n):
        p, L, R = input().split()
        L = int(L)
        R = int(R)

        occ = [0] * sz

        v = 0
        cur_len = 0

        for ch in p:
            while v and ch not in sam.next[v]:
                v = sam.link[v]
                cur_len = sam.length[v]

            if ch in sam.next[v]:
                v = sam.next[v][ch]
                cur_len += 1
            else:
                v = 0
                cur_len = 0

            occ[v] += 1

        for state in range(sz - 1, 0, -1):
            x = order[state]
            parent = sam.link[x]
            if parent >= 0:
                occ[parent] += occ[x]

        for state in range(sz):
            if not (L <= occ[state] <= R):
                left[state] = 1
                right[state] = 0

    ans = 0
    for v in range(1, sz):
        if left[v] <= right[v]:
            ans += right[v] - left[v] + 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、ソース文字列のサフィックス オートマトンを 1 回構築します。 状態は長さによって並べ替えられるため、サフィックス リンクの伝播を効率的に実行できます。 

ルール文字列ごとに、標準のオートマトン照合手順を実行します。 すべての位置が 1 つのエンドポイント カウントに寄与します。 長さの降順で状態を処理すると、これらのカウントがサフィックス リンクを介して伝播され、エンドポイントの頻度が部分文字列の出現頻度に変換されます。 

重要な観察は、状態によって表されるすべての部分文字列が、処理されたルール文字列内で同じ出現数を共有するということです。 そのため、国家はルールを完全に存続させるか、完全に排除するかのどちらかになります。 

ルート状態は空ではない部分文字列ではなく空の文字列を表すため、最終的な答えには決してカウントされません。
