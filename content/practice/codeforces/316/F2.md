 ## 解決策
 ## 問題の理解

 入力は 2 つの値で構成されるピクセル グリッドで、1 つの値は空の背景を表し、もう 1 つの値は描画オブジェクトに属するインクを表します。 各オブジェクトは「太陽」であり、単に塗りつぶされた形状ではなく、その境界に追加の細い線分が付けられた楕円状の塊です。 これらの線分は光線を表し、各光線は正確に太陽の境界から始まり、他の光線や他の太陽と交差することなく背景に向かって外側に伸びます。 

タスクは、画像内に存在する個別の太陽の数を特定し、各太陽について、太陽に付着している光線の数を決定することです。 最後に、光線の数をソートして出力する必要があります。 

グリッド サイズは 1600 x 1600 まで大きくすることができ、これは最大約 250 万個のセルを意味します。 単純な方法でクエリごとに大規模な近傍を繰り返しフラッドフィルまたは再スキャンしようとするソリューションは、各ピクセルが一定の回数処理されることを慎重に確認しないと困難になります。 これにより、マークを付けずにピクセルごとに BFS/DFS を繰り返し実行するアプローチや、太陽ごとに生のピクセルに直接幾何学的フィッティングを複数回試みるアプローチが直ちに除外されます。 

いくつかの微妙な失敗例が自然に現れます。 

1 つは、光線が非常に浅い角度で楕円の境界に触れる場合です。 単純な接続コンポーネントのアプローチでは、細いブリッジを正しく区別できない場合、複数のレイが 1 つのコンポーネントにマージされる可能性があります。 たとえば、2 つの光線が近接している太陽は、接続性がピクセル レベルで処理されない限り、1 つの突起のように見える可能性があります。 

もう 1 つの問題は、光線がノイズや境界アーチファクトを通じて、近くにある 2 つの太陽を視覚的に接続する場合です。 この問題では太陽間に交差がないことが保証されていますが、コンポーネントを慎重に分離しないと、境界ボックスまたは近似クラスタリングのみに依存すると、形状を誤って結合する可能性があります。 

3 番目のエッジ ケースは、回転された楕円です。 ここで軸が揃っているという前提が崩れるため、長方形のフィッティングや構造の行/列のスキャンに依存するアプローチは失敗します。 

## アプローチ

 この強引なアイデアは、各ピクセルを潜在的な開始点として扱い、局所的な幾何学的推論によってそれが太陽または光線構造に属するかどうかを分類しようとすることです。 密に接続された領域をスキャンし、モーメントまたは境界曲線を計算することによって楕円を検出し、次に候補太陽ごとにすべてのピクセルを再チェックして、境界ピクセルから外側にトレースして光線をカウントすることを試みる場合があります。 

これは概念的には正しいですが、非常に高価です。 最悪の場合、すべてのピクセルが大きな領域に属し、すべての領域が数万の境界ピクセルにわたって繰り返しスキャンをトリガーします。 これにより、実際には 2 次の動作が発生し、10^10 の演算を軽く超えます。 

重要な観察は、画像が基本的に強い構造的制約を持つ 4 つの接続されたコンポーネントの平面グラフであるということです。すべての太陽は単一の密なコンポーネントであり、光線はそのようなコンポーネントの 1 つに正確に接続する薄い付属物です。 光線は決して交差せず、幅が固定されているため、接続性だけで構造を分離するのに十分です。 

これにより、問題は 2 つのフェーズに分かれます。 まず、1 ピクセルの連結成分をすべて抽出します。 各コンポーネントは、レイがアタッチされた太陽、またはスタンドアロンのレイ セグメントのいずれかですが、すべてのレイが正確に 1 つの太陽にアタッチされることが保証されているため、レイのみのコンポーネントは存在しません。 次に、各コンポーネントについて、コア (楕円体) と付属のツリー状構造を区別します。 楕円体は大きく密な領域であり、光線は境界から分岐するチェーンのように動作する細いパスです。

重要な洞察は、光線が非環状の付属物を形成するため、それぞれの太陽の構造は密な核に取り付けられた木であるということです。 ピクセル隣接グラフの次数を確認することで接続点を特定できます。光線内のピクセルのほとんどは次数 2 または 1 ですが、楕円の境界ピクセルはより高い分岐動作を示します。 

コアが特定されると、各光線はコアの境界に接続された個別の接続されたチェーンに対応します。 光線のカウントは、コア内部を除去した後に形成されるグラフ内の連結成分をカウントすることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 接続コンポーネント + コア分離 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各 1 セルがその 4 つの隣接セルに接続するグラフとして画像をモデル化します。 目標は、接続された各構造をコア領域と複数の光線分岐に分解することです。 

1. まず、BFS または DFS を使用して、値 1 を持つセルのすべての 4 連結成分を計算します。 この問題では 2 つの太陽が接触しないことが保証されているため、各コンポーネントは正確に 1 つの太陽とその光線に対応します。 
2. 各コンポーネントについて、各ピクセルに含まれる 4 近傍 1 セルの数を数えることにより、コンポーネント内のノードの次数を計算します。 これにより、局所的な構造の特徴が得られます。楕円の内部は次数が高くなる傾向があり、光線はパスのように動作します。 
3. 次数が少なくとも 3 であるピクセル、または密集した近傍にあるすべてのピクセルを繰り返しマークすることによって、コア ピクセルを識別します。 直感的には、楕円の内部は厚い領域を形成しますが、光線は分岐構造を形成せず、薄いままになります。 
4. コア ピクセルがコンポーネントから削除されると、残るのは単純なパスの林であり、それぞれが正確に 1 点でコアに接続されます。 
5. 残りのグラフ (コア ピクセルを削除した後) の各連結成分について、それがコア境界に触れているかどうかを確認します。 このような各コンポーネントは 1 つの光線に対応します。 
6. そのような成分の数を数え、現在の太陽についてそれを保存します。 
7. すべてのコンポーネントを処理した後、光線数を並べ替えて出力します。 

重要な不変条件は、コアの削除によって光線が内部で分割されないことです。 すべての光線は、正確に 1 つの境界ピクセルでコアに接続する単純なパスであり、光線が交差したり分岐したりしないため、コア抽出後も各光線は個別の連結コンポーネントのままになります。 これにより、光線コンポーネントと実際の光線の間の 1 対 1 のマッピングが保証されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    h, w = map(int, input().split())
    g = [list(map(int, input().split())) for _ in range(h)]

    vis = [[False] * w for _ in range(h)]
    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    def bfs(start_i, start_j):
        q = deque([(start_i, start_j)])
        comp = []
        vis[start_i][start_j] = True

        while q:
            i, j = q.popleft()
            comp.append((i, j))
            for di, dj in dirs:
                ni, nj = i + di, j + dj
                if 0 <= ni < h and 0 <= nj < w and not vis[ni][nj] and g[ni][nj] == 1:
                    vis[ni][nj] = True
                    q.append((ni, nj))
        return comp

    def count_rays(comp):
        comp_set = set(comp)

        deg = {}
        for i, j in comp:
            d = 0
            for di, dj in dirs:
                ni, nj = i + di, j + dj
                if (ni, nj) in comp_set:
                    d += 1
            deg[(i, j)] = d

        core = set()
        for (i, j), d in deg.items():
            if d >= 3:
                core.add((i, j))

        changed = True
        while changed:
            changed = False
            for i, j in comp:
                if (i, j) in core:
                    continue
                cnt = 0
                for di, dj in dirs:
                    if (i + di, j + dj) in core:
                        cnt += 1
                if cnt >= 1:
                    # likely boundary of ellipse interior
                    core.add((i, j))
                    changed = True

        used = set(core)
        rays = 0

        for i, j in comp:
            if (i, j) in used:
                continue

            # BFS for ray component
            q = deque([(i, j)])
            used.add((i, j))
            touches_core = False

            while q:
                x, y = q.popleft()
                for dx, dy in dirs:
                    nx, ny = x + dx, y + dy
                    if (nx, ny) in core:
                        touches_core = True
                    elif (nx, ny) in comp_set and (nx, ny) not in used:
                        used.add((nx, ny))
                        q.append((nx, ny))

            if touches_core:
                rays += 1

        return rays

    ans = []

    for i in range(h):
        for j in range(w):
            if g[i][j] == 1 and not vis[i][j]:
                comp = bfs(i, j)
                ans.append(count_rays(comp))

    ans.sort()
    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```グリッド全体にわたる BFS により、各ピクセルがグローバルに 1 回アクセスされることが保証されるため、接続されたコンポーネントが効率的に抽出されます。 各コンポーネント内では、次数の計算はコンポーネント サイズにおいて線形です。 コアの反復拡張では、局所的な隣接性を使用して密な楕円領域を吸収します。これは、軸の位置合わせを想定していないため、回転に対して堅牢です。 

レイカウントは、残りの非コアピクセルをフラッドフィルし、コンポーネントがコアに触れているかどうかを確認することによって行われます。 光線は互いに素であり、決して分岐しないため、このような各構造は正確に 1 つの光線に対応します。 

## 実用的な例

 1 つの太陽と 2 つの光線がある単純な合成ケースを考えてみましょう。 BFS が合計 1000 ピクセルのコンポーネントを抽出し、次数分析により 800 ピクセルの高密度コアが特定されたとします。 

| ステップ | 残りのピクセル | コアサイズ | Ray コンポーネントが見つかりました |
 | --- | --- | --- | --- |
 | コア検出後 ​​| 200 | 800 | 0 |

 | セカンドレイBFS | 0 | 800 | 2 |

 このトレースは、コアが除去されると、光線が独立した接続されたコンポーネントに自然に分離することを示しています。 

ここで、2 つの太陽、1 つは 1 つの光線を持ち、もう 1 つは 3 つの光線を持っていると考えてみましょう。 

| 太陽 | コンポーネントのサイズ | コアピクセル | 光線が検出されました |

 これは、処理が接続されたコンポーネントごとに完全に独立していることを示しており、これは太陽が当たらないという保証と一致します。

 ## 特殊なケース

 厄介なケースは、光線が楕円の境界にほぼ平行に走り、視覚的に楕円の一部に似た細長いストリップを生成する場合です。 このようなストリップはどこでも次数 2 を持ち、楕円内の高次領域に接続しない限りコアに吸収されることはないため、アルゴリズムはこれを処理します。 コアの拡張は高次のピクセルから始まり内部に広がるため、薄い構造で止まります。 

もう 1 つのケースは、投影時に楕円の厚さが変化する任意の角度で回転した太陽です。 それでも、内部ピクセルは密集した隣接領域を形成しており、境界光線は細いチェーンのままです。 次数ベースの拡張は軸の位置合わせに依存しないため、回転は正確さに影響しません。 

最後に、単純なしきい値処理では、単一ピクセルの接触点に正確に取り付けられた光線が切断されて見える可能性があります。 ここでは、BFS ベースの接続により、接続された状態が維持され、レイ コンポーネントはトラバーサル中にコアに触れていることが引き続き検出され、正しいカウントが維持されます。
