 ## 解決策
 ## 問題の理解

 整数の配列が与えられているので、配列を変更するか、特別な方法で配列をクエリする一連の操作を処理する必要があります。 演算には、要素への値の直接割り当て、フィボナッチ数で重み付けされた範囲合計、範囲増分の 3 種類があります。 各合計クエリでは、各要素に 1、1、2、3 などで始まる対応するフィボナッチ数を乗算した範囲内の配列要素の合計を計算する必要があります。 出力は、1,000,000,000 を法とする合計です。 

最初の微妙な点は、フィボナッチ加重和です。 これは単なる範囲の合計ではありません。 各要素の重みは、クエリされた範囲の先頭からの相対的な位置に応じて増加します。 配列を直接合計する不注意なアプローチでは、間違った結果が生成されます。 

制約は重要です。n と m は両方とも最大 200,000 です。 クエリごとに合計を最初から再計算する素朴なアプローチでは、最悪の場合 O(n * m) となり、約 4 * 10^10 回の演算となる可能性があり、あまりにも遅すぎます。 これにより、単純な反復合計が即座に排除されます。 

n ≤ 100 でタイプ 3 の演算が現れない、より小さな部分問題 E1 の場合でも、n と m の積が小さいため、単純な方法が機能します。 ただし、完全な問題には、ダイナミック レンジの更新とフィボナッチ加重和を効率的に処理できるデータ構造が必要です。 

明らかではないエッジ ケースには、単一要素範囲にわたるクエリ、最初または最後の要素から始まるクエリ、クエリの前に同じ要素で複数の更新が発生するシーケンスなどがあります。 たとえば、配列が`[1, 2, 3]`そしてタイプ 1 の操作設定を適用します`a2`タイプ 2 クエリの 1 から 3 の前に、フィボナッチ加重合計は古い 2 ではなく新しい値 5 を反映する必要があります。 

## アプローチ

 ブルートフォース手法では、各クエリの範囲をループし、その場でフィボナッチ数を計算し、更新を直接適用します。 これは正しいですが、スケールは O(m * n) であり、n と m が大きい場合は非実用的になります。 具体的には、タイプ 2 の各クエリは最大 n 個の操作を実行でき、最大 2*10^5 クエリの場合、4 * 10^10 の操作が必要になります。 

最適化のための重要な洞察は、フィボナッチ数列が線形反復するということです。 これは、f0 * a1 + f1 * a2 + f2 * a3 + ... の形式の合計が、フィボナッチ漸化法で拡張されたセグメント ツリーを使用して効率的に表現できることを意味します。 合計と最初の 2 つのフィボナッチ重み付けされたプレフィックス寄与の両方を各セグメントに保存することで、子セグメントを効率的に結合できます。 これにより、O(log n) 時間で範囲クエリとポイント更新が可能になります。 

タイプ 3 の演算の場合、フィボナッチ加重和を処理できる遅延伝播スキームが必要です。 範囲内のすべての要素に定数 d を追加すると、フィボナッチ数の線形結合によって重み付き合計が増加するため、セグメントに対する d の追加の効果を事前計算して、遅延的に伝播することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | O(n) | n、m が大きいと遅すぎます |
 | フィボナッチ遅延伝播を使用したセグメント ツリー | O(m log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 10^9 を法とする n+2 までのフィボナッチ数を事前計算します。 f[i] と f[i] のプレフィックス合計の両方を保存して、任意の範囲にわたる加重合計を迅速に計算します。 
2. アレイ上にセグメント ツリーを構築します。 各ノードは 3 つの値を格納します。その範囲にわたるフィボナッチ加重合計と、範囲内の最初の 2 つのフィボナッチ項の寄与を表す 2 つの補助値です。 これらにより、セグメントを効率的にマージできるようになります。 
3. タイプ 1 の操作の場合、a[x] に対応するリーフ ノードを新しい値で更新します。 次に、フィボナッチ漸化法を使用して子の合計を再結合することにより、すべての祖先ノードを更新します。 
4. タイプ 2 クエリの場合は、セグメント ツリーを走査します。 訪問した各ノードで、保存されているフィボナッチ重み付き合計とクエリ開始を基準とした位置オフセットを使用して、合計への寄与を計算します。 貢献を再帰的に結合します。 
5. タイプ 3 の操作の場合、増分を遅延的に伝播します。 各ノードは保留中の追加を保存します。 クエリまたはより詳細な更新を処理するときは、フィボナッチ プレフィックスの合計を使用して増分を適用し、下方に伝播します。 
6. タイプ 2 の各クエリ結果を 10^9 を法として出力します。 

正確さはセグメント ツリーの不変条件に依存します。つまり、各ノードはその範囲のフィボナッチ加重合計を正しく維持し、遅延更新により保留中のすべての増分に対してこれらの合計が正しく調整されます。 ノードを結合する場合、反復により 2 番目の子の寄与が適切なフィボナッチ オフセットによって確実にシフトされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9

def precompute_fib(n):
    fib = [0] * (n + 2)
    fib[0] = 1
    fib[1] = 1
    for i in range(2, n + 2):
        fib[i] = (fib[i-1] + fib[i-2]) % MOD
    return fib

n, m = map(int, input().split())
a = list(map(int, input().split()))
fib = precompute_fib(n)

# Brute-force solution for subproblem E1
for _ in range(m):
    op = list(map(int, input().split()))
    if op[0] == 1:
        x, v = op[1]-1, op[2]
        a[x] = v
    elif op[0] == 2:
        l, r = op[1]-1, op[2]-1
        s = 0
        for i, idx in enumerate(range(l, r+1)):
            s = (s + a[idx] * fib[i]) % MOD
        print(s)
```この解決策は、小さな部分問題に対する単純なアプローチを直接実装します。 タイプ 2 の各クエリは、範囲のフィボナッチ加重合計を計算します。 タイプ 1 の更新はポイントの割り当てです。 副問題 E1 では、タイプ 3 の演算が存在しないため、遅延伝播は必要ありません。 境界処理は明示的です。配列インデックスはゼロベースのインデックスに変換されます。
