 ## 解決策
 ## 問題の理解

 私たちには生徒の列が与えられ、各生徒は最初は別々のラベルが貼られたボールを持っています。 許可される唯一の操作は、2 人の生徒を選択し、現在保持しているボールを交換することです。 スワップの順序には制限があります。各生徒は最大でも指定された数のスワップに参加でき、この制限は 1 または 2 です。 

すべての交換は 2 つの位置を入れ替えるだけであるため、最終的な構成は、交換する生徒のペアがどのペアに選ばれるかによって完全に決まります。 この質問は、各ポジションが参加できるスワップの数に関する次数の制約の下で取得できるボール ラベルの個別の最終順列の数を求めます。 

グラフの観点から見ると、n 個のラベル付き頂点 (スチューデント) 上に単純なグラフを形成しています。 各エッジはスワップに対応し、各頂点 i の次数は最大で a[i] です。 このグラフのすべての連結コンポーネントは、そのコンポーネント内でボールが任意に並べ替えられた位置のセットです。これは、エッジに沿った一連の交換により、そのコンポーネントの任意の並べ替えが生成される可能性があるためです。 したがって、問題は、次数制約の下でコンポーネントへの異なる頂点分割構造がいくつ可能かを数えることと、各コンポーネント内の順列の寄与を合計することに帰着します。 

重要な制約は、n が最大 10^6 であり、これにより、サブセットに対する状態ベースの DP、さらには状態ごとの分岐を持つプレフィックスに対する DP が即座に除外されます。 どのソリューションも本質的に線形または線形に近いものでなければならず、構成を明示的に検討することは避けなければなりません。 唯一の実行可能な方向性は、次数 1 と 2 によって課される構造上の制限を理解することです。 

主なエッジ ケースは、サイクルまたはパスを形成する小さなコンポーネントから発生します。 素朴な間違いは、次数が局所的に尊重される限り、ノードの任意のグループ化が可能であると想定することです。 たとえば、度を使用すると、`[2,2,2]`、3 つのノードのすべての順列が可能であると考える人もいるかもしれませんが、トライアングル サイクルは、スワップの構成方法に応じて、6 つすべてではなく、可能な 2 つの異なる順列 (隣接するスワップ構造を介した順列も含む) のみに寄与します。 もう 1 つの微妙な失敗は、独立した選択ではなくパスのエンドポイントを強制することを追跡せずに、次数 1 のノードを独立したエンドポイントとして扱うことです。 

## アプローチ

 制約を無視すると、考えられるスワップのシーケンスをすべて列挙することができます。 各スワップの選択により順列が変化し、k 回のスワップの後、すべての可能性をシミュレートできます。 これはすぐに爆発します。n が中程度の場合でも、スワップのシーケンスの数はおよそ O((n^2)^k) であり、k 自体は列挙を実行できるほど厳密に制限されていません。 

より構造化されたブルート フォースは、各ノードの次数が最大で a[i] であるすべての可能なグラフを考慮し、各グラフに対してそれが誘発する順列の数を計算することです。 n 個のノード上のグラフの数は指数関数的であり、それぞれを評価すること自体が自明ではないため、これでも失敗します。 

重要な簡素化は、スワップの正確な順序ではなく、接続されたコンポーネントの構造のみが重要であることを認識することから生まれます。 サイズ k の各連結成分は k! に寄与します。 接続されたスワップ グラフではコンポーネント内で任意の順列を生成できるため、内部的に順列が生成されます。 したがって、問題は、次数制約に従って頂点を連結成分に分割できる方法が何通りあるかを数えることに帰着します。 

次数は 1 または 2 のみであるため、有効なコンポーネントはすべて単純なパスまたは単純なサイクルのいずれかです。 次数 1 の頂点はパスの終点でなければなりませんが、次数 2 の頂点は内部ノードまたはサイクルの一部にすることができます。 これにより、問題は、拘束された頂点のシーケンスをパスとサイクルに分割する方法が何通りあるかを数えることになります。 

頂点を順番に処理し、現在パス内にいるか、サイクルを開始しているか、構造物を閉じているかを追跡する DP を維持します。 重要な観察は、サイクルは次数 2 の頂点のみを消費し、端点を作成しないのに対し、パスは次数 1 の端点を 2 つ消費し、場合によっては中間の次数 2 頂点を消費することです。 

これにより、問題はシーケンス全体にわたる線形 DP に縮小されます。この場合、遷移は現在の頂点次数と、構造を開いているか閉じているかにのみ依存します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | グラフと順列のブルートフォース列挙 | 指数 | 指数 | 遅すぎる |
 | パスとサイクルにわたる構造 DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 頂点を左から右に処理し、現在開いている「未完成の構造」の数を表す DP を維持します。 次数制約により非常に限られた構成セットが強制されるため、状態は単純化されます。

1. 各位置を次数制約によって分類します。 次数 1 のノードは最終的にパスの終点になる必要がありますが、次数 2 のノードは内部パス/サイクル ノードとして機能することも、サイクル クロージャに参加することもできます。 
2. 動的プログラミング配列 dp[i][j] を維持します。ここで、i はプレフィックスの長さ、j は現在オープン パス エンドポイントの保留中の接続があるかどうかを示します。 エンドポイントはペアで提供されるため、j は 0 または 1 つの保留中のエンドポイントとして解釈できます。 
3. 次数 1 ノードを処理するときは、新しいオープン エンドポイントを開始するか、既存のエンドポイントを閉じる必要があります。 これは、エンドポイントをパスにペアリングすることに対応します。 構造全体でエンドポイントをペアにする方法の数は、乗算的に寄与します。 
4. 次数 2 ノードを処理する場合、既存の構造を拡張するか、サイクルの形成に参加するかの選択肢があります。 サイクル形成は、アクティブ構造内の 2 つの開放端をペアにすることに対応し、可能な構成の数が増加します。 
5. コンポーネントを閉じるたびに (パスの閉鎖またはサイクルの完了のいずれか)、結果にそのサイズの階乗を乗算します。これは、接続されたコンポーネントではすべての内部順列が許可されるためです。 
6. すべての有効な分解が正確に 1 回カウントされるように、すべてのコンポーネントにわたる寄与を蓄積します。 

### なぜ効果があるのか

 不変条件は、すべてのプレフィックスで、一致しないエンドポイントがいくつ存在するか、およびそれらが合法的に有効なコンポーネントに完成する方法を DP 状態が完全に捕捉することです。 次数は最大 2 であるため、どの頂点も複数の未解決の分岐決定に参加することはできません。これにより、状態空間が一定数の意味のある構成に崩壊することが保証されます。 すべての遷移は、パスの延長またはサイクルの終了に正確に対応し、これらの操作により、最終的な置換の素のセットが生成され、二重カウントが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # factorials up to n
    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    # dp[open_paths] = number of ways
    # open_paths = number of unfinished path endpoints (0 or 1 effectively)
    dp0, dp1 = 1, 0

    for x in a:
        ndp0, ndp1 = 0, 0

        if x == 1:
            ndp1 = (ndp1 + dp0) % MOD
            ndp0 = (ndp0 + dp1) % MOD
        else:
            ndp0 = (ndp0 + dp0) % MOD
            ndp1 = (ndp1 + dp1) % MOD
            ndp0 = (ndp0 + dp1) % MOD

        dp0, dp1 = ndp0, ndp1

    # final answer aggregates all completed structures
    # each configuration corresponds to full pairing, so multiply by n!
    print(fact[n] * dp0 % MOD)

if __name__ == "__main__":
    solve()
```有効な最終接続構造はそれぞれコンポーネント内の順列に対応し、順列の総数はコンポーネントの階乗にきれいに分解されるため、実装では階乗が事前計算されます。 DP は、閉じた構成で終了するか、最終ペアリングを必要とする構成で終了するかを追跡します。これは、最後に dp0 のみを受け入れることで解決されます。 

次数 1 ノードはエンドポイント動作を強制するのに対し、次数 2 ノードは継続または内部ペアリングの柔軟性を許可するため、遷移ロジックでは次数 1 ノードと次数 2 ノードが区別されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 重要なエッジ ケースは、すべての頂点の次数が 1 である場合です。その場合、すべてのノードを素のスワップにペアにして、完全に一致する構造を形成する必要があります。 このアルゴリズムは、エンドポイントのペアリングと最終的な n による乗算のみを許可する dp 遷移を強制します。 自明なパスへの完全な分解と一致する順列の数に正しく減少します。 

もう 1 つのエッジ ケースは、すべての頂点の次数が 2 である場合です。ここでは、エンドポイント制約が存在しないため、DP は決して制約状態に入りません。 最終的な答えは n! となり、完全に接続されたスワップのセットが任意の順列を実現できるという事実と一致します。 

次のような混合境界ケース`[1,2,2,1]`エンドポイント制約が次数 2 ノードを過度に制限しないようにします。 DP により、次数 2 のノードが柔軟性を吸収できるようになりますが、次数 1 のノードが適切に一致する必要があります。
