 ## 解決策
 ## 問題の理解

 私たちは、`n × m`グリッド。 すべてのセルには 1 つの靴が含まれており、すべての靴のペアの番号はグリッド全体で正確に 2 回表示されます。 

すべてのペアに属する 2 つの靴が隣接するセルを占有する場合、その構成は整然としていると見なされます。 隣接するのは角ではなく共有面です。 

セル間で靴を移動する場合があります。 靴は、元のセルに残っていない場合、移動したものとしてカウントされます。 タスクは、最終的な配置をきれいにするために、位置を変更する必要がある靴の最小数を見つけることです。 

グリッドには最大でも次のものが含まれます`80 × 80 = 6400`細胞。 すべてのペアは正確に 2 回出現するため、最大でも`3200`異なるペア。 

考えられるすべての最終取り決めを総当りで調査することは絶望的です。 グリッドのドミノ タイリングをすべて列挙するだけでも、天文学的な規模になります。 この制約は、解決策がグリッド構造を利用し、問題を多項式時間グラフ問題に還元する必要があることを直ちに示唆しています。 

難しいのは、最終的な取り決めを構築するように求められていないことです。 移動する靴は最小限の数だけ必要です。 これにより、どの靴がその場所に留まることができるかという観点から考えることができます。 

次の小さな例を考えてみましょう。```
1 1
```このペアはすでに隣接しています。 正しい答えは、`0`。 

すべてのペアの片方の靴を常に動かす不注意な解決策では、誤った出力が発生します。`1`。 

もう 1 つの興味深い例は次のとおりです。```
1 2
2 1
```各数字の 2 つの出現は対角線​​上にあるため、どちらのペアもすでに隣接していません。 

正しい答えは、`2`。 

ペアの片方の靴`1`滞在できる、一足の靴`2`can stay, and the other two shoes must move.

 よくある間違いは、靴を置き忘れると両方の靴を移動する必要があると考えることです。 

3 番目のエッジケースは次のとおりです。```
1 2 3
1 2 3
```すべてのペアはすでに垂直方向に隣接しています。 答えは`0`。 

最初に水平方向に隣接するものを貪欲に一致させるソリューションでは、最適な配置を逃すことになります。 

## アプローチ

 ブルートフォースの観点は、最終的な整然とした配置でどの隣接するセルがペアを形成するかを決定することです。 

整然とした配置により、グリッド全体が隣接セルのペアに分割されます。 グラフ言語では、グリッド グラフの完全な一致を探します。 

何らかの方法でそのようなセルの組み合わせを選択したとします。 

2 つの隣接するセルを接続する 1 つの一致エッジを取得します。 

2 つのセルにすでに同じ番号が含まれている場合は、両方の靴が所定の位置に留まる可能性があります。 そのペアの中の靴は動く必要がありません。 

2 つのセルに異なる数字が含まれている場合、最大でも 1 つの靴を残すことができます。 一方のセルは現在のシューズを保持し、後でパートナーを受け入れることができますが、もう一方のシューズは離れる必要があります。 一致するペアでは、靴の動きを 1 つだけ行うことは避けられません。 

この観察により、問題は完全に変わります。 

靴のアイデンティティをグローバルに推論する代わりに、一致するエッジの 2 つの端点に現在同じ数値が含まれているかどうかを知るだけで済みます。 

一致したエッジの場合:```
same numbers     -> cost 0
different numbers -> cost 1
```移動された靴の総数は、一致するすべてのエッジにわたるこれらのコストの合計に等しくなります。 

ここで問題は次のようになります。 

最小の総コストで完全に一致するグリッド グラフを見つけます。 

グリッド グラフは 2 部構成です。 チェス盤のようにセルに色を付けます。 

すべてのエッジが黒のセルと白のセルを接続します。 

二部グラフを構築します。 

- ソース → すべての黒マス、容量 1、コスト 0。 
- すべての白マス → シンク、容量 1、コスト 0。 
- 隣接する黒と白のセルの間:

 - 容量1
 - 数値が等しい場合はコスト0
 - それ以外の場合はコスト1

 フローのユニットは 1 つの一致するエッジを選択します。 

すべてのセルの容量は 1 であるため、最大流量は`nm/2`グリッドの完全な一致に正確に対応します。 

最小コストの完全マッチングにより、移動する靴の数が最小限になります。 この削減が重要な洞察です。 これは、扱いにくい再配置問題を、標準的な最小コスト最大フロー問題に変換します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ペアリングに対するブルートフォース | 指数 | 指数 | 遅すぎる |
 | グリッドグラフ上の最小コスト完全マッチング | 多項式 | O(V + E) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを市松模様に色付けします。 
2. 各セルに 1 つのグラフ頂点を作成します。 
3. ソースとシンクを追加します。 
4. 容量のあるすべての黒セルにソースを接続します。`1`そしてコスト`0`。 
5. すべての白いセルを容量のあるシンクに接続します。`1`そしてコスト`0`。 
6. 隣接するセルの黒と白のペアごとに、容量のエッジを追加します。`1`。 

2 つのセルに同じ数値が含まれている場合、エッジ コストは次のようになります。`0`。 

それ以外の場合、エッジコストは次のようになります。`1`。 
7. 最小コスト最大フローを実行し、正確に送信します`nm/2`流量の単位。 
8. フロー アルゴリズムによって返される最小コストが答えです。 

### なぜ効果があるのか

 フローの各単位は、隣接する黒と白のペアを 1 つ選択します。 それぞれのセルには容量があるので、`1`、サイズの最大フロー`nm/2`すべてのセルに 1 回だけ一致します。 それはまさにグリッド グラフの完全な一致です。 

一致するセルのペアの場合、答えへの寄与は次のようになります。 

-`0`両方のセルに同じペア番号がすでに含まれている場合。 
-`1`さもないと。 

これらのコストは、これら 2 つのセルから出さなければならない靴の最小数に正確に等しくなります。 

一致するすべてのペアを合計すると、完全に一致するために移動された靴の最小数が得られます。 

min-cost max-flow アルゴリズムはすべての完全一致を検査し、合計コストが最小のものを選択するため、結果として得られるコストはまさに最適な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class MinCostMaxFlow:
    class Edge:
        __slots__ = ("to", "rev", "cap", "cost")

        def __init__(self, to, rev, cap, cost):
            self.to = to
            self.rev = rev
            self.cap = cap
            self.cost = cost

    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, u, v, cap, cost):
        fwd = self.Edge(v, len(self.g[v]), cap, cost)
        rev = self.Edge(u, len(self.g[u]), 0, -cost)
        self.g[u].append(fwd)
        self.g[v].append(rev)

    def min_cost_flow(self, s, t, need):
        n = self.n
        INF = 10 ** 18

        flow = 0
        cost = 0
        pot = [0] * n

        while flow < need:
            dist = [INF] * n
            parent_v = [-1] * n
            parent_e = [-1] * n

            import heapq
            pq = [(0, s)]
            dist[s] = 0

            while pq:
                d, v = heapq.heappop(pq)
                if d != dist[v]:
                    continue

                for ei, e in enumerate(self.g[v]):
                    if e.cap <= 0:
                        continue

                    nd = d + e.cost + pot[v] - pot[e.to]
                    if nd < dist[e.to]:
                        dist[e.to] = nd
                        parent_v[e.to] = v
                        parent_e[e.to] = ei
                        heapq.heappush(pq, (nd, e.to))

            if dist[t] == INF:
                break

            for i in range(n):
                if dist[i] < INF:
                    pot[i] += dist[i]

            add = need - flow
            v = t

            while v != s:
                pv = parent_v[v]
                pe = parent_e[v]
                add = min(add, self.g[pv][pe].cap)
                v = pv

            v = t
            while v != s:
                pv = parent_v[v]
                pe = parent_e[v]
                e = self.g[pv][pe]

                e.cap -= add
                self.g[v][e.rev].cap += add

                v = pv

            flow += add
            cost += add * pot[t]

        return flow, cost

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    cells = n * m
    s = cells
    t = cells + 1

    mcmf = MinCostMaxFlow(cells + 2)

    def id_of(r, c):
        return r * m + c

    dirs = ((1, 0), (-1, 0), (0, 1), (0, -1))

    black_count = 0

    for r in range(n):
        for c in range(m):
            v = id_of(r, c)

            if (r + c) & 1:
                black_count += 1
                mcmf.add_edge(s, v, 1, 0)

                for dr, dc in dirs:
                    nr = r + dr
                    nc = c + dc

                    if 0 <= nr < n and 0 <= nc < m:
                        u = id_of(nr, nc)
                        cost = 0 if a[r][c] == a[nr][nc] else 1
                        mcmf.add_edge(v, u, 1, cost)
            else:
                mcmf.add_edge(v, t, 1, 0)

    _, answer = mcmf.min_cost_flow(s, t, black_count)
    print(answer)

if __name__ == "__main__":
    solve()
```グラフの構成は市松模様の色付けに従います。 すべての黒セルは 1 つの隣接する白セルと正確に一致する必要があり、すべての白セルは 1 回だけ一致する必要があります。 

隣接エッジのコストは、一致したペアに同じ数値が既に含まれているかどうかをエンコードします。 それが最適化の目標全体です。 

この実装では、ジョンソン ポテンシャルを使用した標準の連続最短拡張パス アルゴリズムが使用されます。 元のグラフではすべてのコストは負ではありませんが、残差エッジによって負のコストが導入されるため、ポテンシャルによってダイクストラが有効に保たれます。 

よくある実装上の間違いは、黒と白の隣接エッジのみを追加する必要があることを忘れていることです。 両方の方向が通常のグラフ エッジとして追加されると、一致制約が壊れます。 

もう 1 つの簡単な間違いは、間違った量の流量を要求することです。 必要な流量は正確に黒セルの数と同じです。`nm/2`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(F・E log V) | 連続する最短の拡張パス |
 | スペース | O(V + E) | 残留ネットワーク |

 ここ`V = nm + 2`、`E = O(nm)`、 そして`F = nm/2`。 

最大でも 6400 個のセルがあり、セルごとに隣接エッジが 4 つしかないため、グラフはまばらなままになります。 これはコンテストの制限内に問題なく収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    from heapq import heappush, heappop

    input_data = io.StringIO(inp)

    def input():
        return input_data.readline()

    class MCMF:
        class Edge:
            __slots__ = ("to", "rev", "cap", "cost")

            def __init__(self, to, rev, cap, cost):
                self.to = to
                self.rev = rev
                self.cap = cap
                self.cost = cost

        def __init__(self, n):
            self.g = [[] for _ in range(n)]
            self.n = n

        def add(self, u, v, cap, cost):
            a = self.Edge(v, len(self.g[v]), cap, cost)
            b = self.Edge(u, len(self.g[u]), 0, -cost)
            self.g[u].append(a)
            self.g[v].append(b)

        def flow(self, s, t, need):
            n = self.n
            pot = [0] * n
            cost = 0
            flow = 0
            INF = 10**18

            while flow < need:
                dist = [INF] * n
                pv = [-1] * n
                pe = [-1] * n
                dist[s] = 0

                pq = [(0, s)]

                while pq:
                    d, v = heappop(pq)
                    if d != dist[v]:
                        continue

                    for i, e in enumerate(self.g[v]):
                        if e.cap <= 0:
                            continue

                        nd = d + e.cost + pot[v] - pot[e.to]
                        if nd < dist[e.to]:
                            dist[e.to] = nd
                            pv[e.to] = v
                            pe[e.to] = i
                            heappush(pq, (nd, e.to))

                for i in range(n):
                    if dist[i] < INF:
                        pot[i] += dist[i]

                add = need - flow
                v = t

                while v != s:
                    add = min(add, self.g[pv[v]][pe[v]].cap)
                    v = pv[v]

                v = t
                while v != s:
                    e = self.g[pv[v]][pe[v]]
                    e.cap -= add
                    self.g[v][e.rev].cap += add
                    v = pv[v]

                flow += add
                cost += add * pot[t]

            return cost

    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    N = n * m
    s = N
    t = N + 1

    g = MCMF(N + 2)

    def idx(r, c):
        return r * m + c

    blacks = 0

    for r in range(n):
        for c in range(m):
            v = idx(r, c)

            if (r + c) & 1:
                blacks += 1
                g.add(s, v, 1, 0)

                for dr, dc in ((1,0),(-1,0),(0,1),(0,-1)):
                    nr = r + dr
                    nc = c + dc
                    if 0 <= nr < n and 0 <= nc < m:
                        g.add(v, idx(nr, nc), 1,
                              0 if a[r][c] == a[nr][nc] else 1)
            else:
                g.add(v, t, 1, 0)

    return str(g.flow(s, t, blacks))

 ## 特殊なケース

 次のことを考慮してください。```
2 1
1
1
```可能な唯一の一致は、2 つのセルを一緒に使用することです。 それらの値は等しいため、一致するエッジにはコストがかかります`0`。 アルゴリズムは戻ります`0`、それは正しいです。 

次に、次のことを考えてみましょう。```
2 2
1 2
2 1
```隣接するすべてのペアには異なる数字が含まれます。 完全なマッチングは 2 つの不一致エッジで構成され、それぞれがコストに寄与します。`1`。 最低コストは`2`、したがって、答えは次のとおりです`2`。 

ついに：```
2 3
1 2 3
1 2 3
```最小コストの完全一致では、3 つの垂直エッジが使用されます。 3つともコストがかかります`0`。 フローコストは`0`つまり、靴を動かす必要がありません。 最小コストの完全マッチングを構築するときは常にゼロコストのエッジが優先されるため、アルゴリズムはこれを自然に見つけます。
