 ## 解決策
 ## 問題の理解

 文字列の個別の部分文字列の数を数えるように求められます`s`一連の出現ベースのルールを満たすもの。 各ルールは文字列で構成されます`p`そして範囲`[l, r]`、および部分文字列`t`の`s`に出現する回数があれば良好とみなされます。`p`の中に入る`[l, r]`あらゆるルールに。 

入力はメイン文字列で構成されます`s`、いくつかのルール`n`、そしてルールそのもの。 出力は単一の整数です。つまり、次の適切な部分文字列の数です。`s`。 

制約は厳しいです:`n`は最大でも 10 と小さいですが、`s`そして補助弦`p`最も難しいサブタスクでは最大 50,000 まで上がる可能性があります。 これにより、すべての部分文字列をすべてのルールに対して単純にチェックする総当り的なアプローチが即座に除外されます。`s`は O(|s|²) で、50,000 の場合は約 25 億です。 ルール文字列内の出現をチェックする場合でも`p`O(|p|) を要する場合、その複雑さは実行不可能になります。 

明らかではないエッジ ケースには、範囲がゼロのルール、部分文字列の重複、パターンの繰り返しなどが含まれます。 たとえば、次の場合`s = "aaa"`そしてルールは`("aa", 1, 1)`、部分文字列のみ`"aa"`(最初と 2 番目の位置から開始) それらが 2 回出現しても、別のものとして 1 回カウントされます。`s`。 重複排除を行わずに部分文字列をカウントしたり、範囲制約を無視したりする不用意な実装は、誤った結果をもたらします。 

## アプローチ

 ブルートフォースメソッドは、次のすべての部分文字列を列挙します。`s`そして、それぞれについて、それがすべての期間で何回発生するかを数えます。`p`弦。 これは問題定義に直接従うため、正確性が保証されます。 ただし、時間計算量は O(|s|² * n * |p|max) です。 |s| の場合 = 50,000 の場合、長さ 50,000 のルールが 1 つだけでも、約 10¹³ の操作が発生し、非現実的です。 

重要な洞察は、部分文字列の出現を効率的にチェックし、重複カウントを回避する方法が必要であるということです。 部分文字列ハッシュを使用すると、部分文字列の定数時間比較が可能になるため、次の部分文字列を列挙できます。`s`そしてそのハッシュを保存して一意性をチェックします。 ルール内の出現カウントについては、各ルール文字列を前処理できます。`p`ローリング ハッシュまたは Rabin-Karp アプローチを使用して、考えられる各部分文字列長を度数表にマッピングします。 なぜなら`n`が小さい場合、制約を効率的に交差させることができます。 

したがって、問題は、次のすべての部分文字列を列挙することに帰着します。`s`、ハッシュを使用して区別性を維持し、ルールごとに事前に計算された度数表を使用して部分文字列が「良好」であるかどうかを迅速に検証します。 ボトルネックは管理可能になります。O(|s|²) は、前処理されたテーブルを使用して O(1) ハッシュ チェックと O(n) ルール チェックで部分文字列を列挙します。

 ## アルゴリズムのチュートリアル

 1. 各ルール文字列を前処理する`p`。 に出現する可能性のあるすべての部分文字列の長さに対して、`s`、各部分文字列ハッシュをその頻度にマッピングするハッシュ テーブルを計算します。`p`。 これにより、指定された部分文字列ハッシュの出現数を O(1) で検索できるようになります。 
2. セットを初期化して、適切な個別の部分文字列のハッシュを保存します。 
3. すべての部分文字列を列挙します。`s`。 部分文字列ごとに、そのハッシュを計算します。 ハッシュ セットを確認します。ハッシュ セットが見つかった場合は、カウントの重複を避けるためにスキップします。 
4. 新しい部分文字列ごとに、すべてのルールに照らしてチェックします。 前処理された頻度表で部分文字列ハッシュを検索し、頻度が範囲内にあるかどうかを確認します。`[l, r]`各ルールの範囲。 
5. 部分文字列がすべてのルールに合格した場合、そのハッシュをセットに追加します。 
6. すべての部分文字列を処理した後のセットのサイズは、適切な個別の部分文字列の数になります。 

機能する理由: ハッシュは、それぞれの異なる部分文字列が`s`は 1 回だけカウントされます。 ルールを前処理すると、出現カウントが正確かつ効率的に行われます。 すべての部分文字列とすべてのルールをチェックするため、アルゴリズムは適切な部分文字列をすべて正確に識別します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def rabin_karp_hash(s, base=257, mod=10**9+7):
    h = [0] * (len(s) + 1)
    p = [1] * (len(s) + 1)
    for i in range(len(s)):
        h[i+1] = (h[i]*base + ord(s[i])) % mod
        p[i+1] = (p[i]*base) % mod
    return h, p

def substring_hash(h, p, l, r, mod=10**9+7):
    return (h[r] - h[l]*p[r-l]) % mod

def solve():
    s = input().strip()
    n = int(input())
    rules = []
    for _ in range(n):
        parts = input().split()
        rules.append((parts[0], int(parts[1]), int(parts[2])))
    
    s_hash, s_pow = rabin_karp_hash(s)
    seen = set()
    
    # Preprocess rules
    rule_hashes = []
    for pstr, l, r in rules:
        ph, pp = rabin_karp_hash(pstr)
        freq = {}
        plen = len(pstr)
        for length in range(1, len(s)+1):
            for i in range(plen - length + 1):
                hval = substring_hash(ph, pp, i, i+length)
                freq[hval] = freq.get(hval, 0) + 1
        rule_hashes.append((freq, l, r))
    
    # Enumerate substrings of s
    slen = len(s)
    for i in range(slen):
        for j in range(i+1, slen+1):
            hval = substring_hash(s_hash, s_pow, i, j)
            if hval in seen:
                continue
            good = True
            for freq, l, r in rule_hashes:
                count = freq.get(hval, 0)
                if not (l <= count <= r):
                    good = False
                    break
            if good:
                seen.add(hval)
    
    print(len(seen))

if __name__ == "__main__":
    solve()
```最初のセクションでは、ローリング ハッシュを計算します。`s`そして各ルール文字列。 ネストされたループはすべての部分文字列を列挙し、事前に計算されたべき乗を使用して O(1) のハッシュを生成します。 の`seen`set を使用すると、個別の部分文字列のみがカウントされるようになります。 各ルール文字列を前処理すると、サブ文字列ごとに O(1) 頻度の検索が可能になります。
