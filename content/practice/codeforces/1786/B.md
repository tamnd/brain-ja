 ## 解決策
 ## 問題の理解

 数直線上に 2 つの順序システムが与えられます。 1 つのシステムはケーキを表し、それぞれが特定の位置を中心に一定の間隔を占めます。もう 1 つはチョコレート ディスペンサーを表し、同様に一定の間隔でカバー範囲を生成します。 ケーキの間隔はすべてばらばらであり、チョコレートの間隔もすべてばらばらです。 

ケーキコンベア全体を実際の値だけ左右に厳密にシフトすることができます。 このシフトの後、すべてのケーキはその間隔内のどこかにチョコレートを受け取る必要があり、すべてのケーキの間隔が結合した外側にチョコレートがこぼれることは許可されません。 ディスペンサー自体は固定されています。 ケーキシステムのみが動きます。 

このタスクは、すべてのケーキの間隔が少なくとも 1 つのチョコレートの間隔と交差するシフトが少なくとも 1 つ存在するかどうかを判断すると同時に、すべてのチョコレートの間隔が完全にケーキの間隔内に収まるようにすることです。 

制約は大きく、テスト ケース全体で最大 100,000 個の要素があります。 すべての区間ペアにわたる二次比較は制限を大幅に超えるため、すべての解はテスト ケースごとに線形または線形でなければなりません。 

ケーキの間隔がチョコレートの間隔よりも大きく、局所的には位置合わせが可能だが全体的には不可能である場合、微妙なエッジ ケースが発生します。 たとえば、各ケーキが個別にディスペンサーに重なる可能性がある場合でも、順序の制約により一貫した全体的なシフトが妨げられる可能性があります。 

## アプローチ

 強引なアイデアは、可能なすべてのシフトを試すことです。 シフトごとに、すべてのケーキの間隔を変換し、すべてのケーキがディスペンサーの間隔と交差していないか、ディスペンサーがケーキの外側に伸びていないかどうかを確認します。 ポジションは実数値であり、制約が大きいため、これは実行不可能です。 

重要な観察は、ケーキとディスペンサーの両方がすでに分類されており、内部で重なり合っていないことです。 この構造は、順序を維持するために有効な位置合わせを強制します。つまり、最初のケーキは最初の実行可能なディスペンサーと位置合わせする必要があり、2 番目のケーキは 2 番目のケーキと位置合わせする必要があります。 順序が固定されると、問題は、間隔の半値幅によって定義される許容誤差制約内ですべてのペアを同時に整列させる一貫したオフセットが存在するかどうかをチェックすることになります。 

これは古典的な間隔マッチングの問題になります。各ケーキの位置により、ディスペンサーの位置合わせごとにシフトの許容範囲が決まります。 これらすべての範囲の交差部分は空であってはなりません。 

各ペアごとのアライメント制約を有効なシフトの間隔に変換し、それらを交差させることで、実現可能性を効率的に判断できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのシフトを試す) | O(∞) 連続 | お(1) | 遅すぎる |
 | 最適 (区間交差) | テストあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ケーキとディスペンサーは両方ともソートされていてバラバラであるため、それらの間の順序を修正します。つまり、交差すると直ちに実現可能性が侵害されることになります。 

1. ケーキ i はシフト後のディスペンサー i に対応する必要があると仮定します。 他のマッピングでは、間隔がバラバラであるため、単調な順序付けが崩れてしまいます。 
2. 各ペアについて、ディスペンサーの間隔がケーキの間隔内に収まるようにシフトの範囲を計算します。 
3. 各ペアはグローバル シフト変数に制約を与え、有効なシフトの間隔を形成します。 
4. これらすべての区間を交差させます。 
5. 交差点が空でない場合、有効なシフトが存在します。 それ以外の場合は、そうではありません。 

各制約は、x だけシフトした後、ディスペンサー間隔 [b_i - h, b_i + h] が [a_i - w, a_i + w] の内側になければならないことを表現することによって導出されます。 これにより、両側から x を制限する不等式が生成されます。 

### なぜ効果があるのか

シフト変数はグローバルであるため、すべてのペアが同じ変数に線形制約を課します。 制約は独立しており、実線上で区間を形成するため、実現可能性はすべての区間が交差するかどうかを確認することになります。 交差割り当ては両方のシーケンスで保証されている単調間隔と矛盾するため、順序付けの仮定は有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, w, h = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        left = -10**18
        right = 10**18

        for i in range(n):
            # dispenser i after shift x lies inside cake i
            # [b_i + x - h, b_i + x + h] ⊆ [a_i - w, a_i + w]

            # left bound: b_i + x - h >= a_i - w
            # x >= a_i - w - (b_i - h)
            l = (a[i] - w) - (b[i] - h)

            # right bound: b_i + x + h <= a_i + w
            # x <= a_i + w - (b_i + h)
            r = (a[i] + w) - (b[i] + h)

            left = max(left, l)
            right = min(right, r)

        print("YES" if left <= right else "NO")

if __name__ == "__main__":
    solve()
```ソリューションの核心は、ケーキとディスペンサーの各ペアの有効なシフト間隔を導出することです。 各ペアは、許可される変換範囲を制限しており、最終的な答えは、そのような範囲がすべて重複するかどうかによってのみ決まります。 

よくある間違いは、制約をグローバル変数に変換せずに、エンドポイントを直接一致させたり、ケーキとディスペンサーを貪欲に組み合わせようとしたりすることです。 正しい見方は、システム全体が単一のシフト パラメーターに依存するため、すべての制約はその変数に関して表現される必要があるということです。 

## 実用的な例

 位置合わせが可能な、3 つのケーキと 3 つのディスペンサーを備えた小さなケースを考えてみましょう。 各ペアは有効なシフト間隔に寄与し、それらの交差部分は空ではないままになります。 次の表は、制約がどのように蓄積されるかを示しています。 

| 私 | l 制約 | r 制約 | 交差点左 | 交差点右 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 5 | 0 | 5 |
 | 2 | 1 | 6 | 1 | 5 |
 | 3 | 2 | 7 | 2 | 5 |

 最後に、交差 [2, 5] が有効になります。これは、この範囲内のどのようなシフトも機能することを意味します。 

ここで、制約が空になるまで徐々に縮小するという失敗例を考えてみましょう。 

| 私 | l 制約 | r 制約 | 交差点左 | 交差点右 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 3 | 0 | 3 |
 | 2 | 2 | 4 | 2 | 3 |
 | 3 | 4 | 5 | 4 | 3 |

 最終ステップでは、交差点は空であるため、すべてのケーキを同時に満たすシフトは存在しません。 

これらの例は、ローカル互換性が不十分であることを示しています。 グローバル交差のみが実現可能性を決定します。 

## 複雑さの分析

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, w, h = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        left = -10**18
        right = 10**18

        for i in range(n):
            l = (a[i] - w) - (b[i] - h)
            r = (a[i] + w) - (b[i] + h)
            left = max(left, l)
            right = min(right, r)

        out.append("YES" if left <= right else "NO")

    return "\n".join(out)

2 10 5
65 95
40 65
""") == "YES"

assert run("""1
3 3 2
10 20 30
1 100 200
""") in {"YES", "NO"}  # structural sanity

assert run("""1
3 1 1
1 10 20
1 10 20
""") == "YES"

assert run("""1
2 1 1
1 10
100 200
""") == "NO"

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのケーキとディスペンサーがすでに一定のシフトまで位置合わせされている場合に発生します。 この場合、すべての制約区間は共通の交点に集約されるため、アルゴリズムはすぐに受け入れる必要があります。 もう 1 つのケースは、制約が厳しいものの、厳密には等しくない場合です。この場合、浮動直感が実現可能性を示唆する可能性がありますが、整数演算によって有効な交差が得られる場合です。 区間定式化では、すべてを 1 つの変数の不等式限界に帰着させるため、両方を自然に処理でき、ケース分析やヒューリスティック マッチングの必要性が回避されます。
