 ## 解決策
 ## 問題の理解

 私たちは、同一のカードのデッキから非常に特殊なディーリング プロセスをシミュレートしています。 カードはデッキの一番上から取り出され、バッチサイズが増加します。 最初の動きでは 1 枚のカードが配られ、2 番目の動きでは 2 枚のカードが、3 番目の動きでは 3 枚のカードが配られます。 各手ごとに、受け手は 4 手ごとに繰り返すパターンで交代します。つまり、アリスが最初の手を受け取り、ボブが次の 2 つの手を受け、アリスが次の 2 つの手を受け、次にボブが次の 2 つの手を受け、この繰り返しサイクルが続きます。 

入力により、いくつかの独立したテスト ケースが得られます。 各テスト ケースはデッキ内のカードの数を提供します。プロセスの終了後、最終的にアリスに何枚のカードが残り、ボブに何枚になるかを計算する必要があります。これには、ステップの途中でデッキのカードがなくなった場合に、手が部分的にしか実行されない可能性も含まれます。 

テスト ケースあたり最大 10^6、テスト ケース最大 200 の制約 n は、カードごとにシミュレーションできないことを意味します。 すべてのカードを個別に反復する単純なシミュレーションは、すでに境界線に達していますが、それでも許容できます。 ただし、各ステップを非効率的に再計算したり、オーバーヘッドのあるカードごとの操作を使用したりする単純なシミュレーションでは、速度が非常に遅くなります。 プロセスの構造は、1 + 2 + ... + k が二次関数的に増加するため、ステップ数が約 sqrt(n) であることを示唆しています。 

ステップの途中でデッキがなくなると、微妙なエッジケースが現れます。 たとえば、n が 1 や 2 のように小さい場合、サイクルを誤って続行しようとせずに、残りのカードを現在のプレイヤーに正しく割り当てる必要があります。 もう 1 つのエッジ ケースは、n が三角数に正確に等しい場合です。これは、プロセスがステップの境界で正確に終了することを意味します。 バグのある実装では、最後の完全なバッチが誤って処理されたり、間違ってターンが進められたりすることがよくあります。 

## アプローチ

 直接シミュレーションでは、山札から i 枚のカードを取り出し、サイクルに応じてアリスまたはボブに割り当てることによってステップ i を処理します。 n から引き続けてカウントを蓄積します。 これはルールに正確に従っているので正しいですが、最悪の場合、k が k(k+1)/2 ≥ n を満たす k ステップを実行するため、k は約 sqrt(2n) になります。 n が 10^6 までの場合、これは約 1400 ステップであり、すでに問題ありませんが、不必要なオーバーヘッドやカードごとのループを実装すると脆弱になります。 

重要な観察は、個々のカードについて推論する必要がないということです。 各ステップは決定的です。私たちが気にするのは、完了した完全なステップの数と、どのプレーヤーが各ステップを受け取るかだけです。 ステップ サイズは直線的に増加するため、残りのカードを追跡しながら、O(sqrt(n)) 時間でステップごとにシミュレーションできます。 ステップ インデックス モジュロ 4 に基づく単純なパターンを使用して所有権を交互に切り替えるため、高価なものを再計算することはありません。 

ブルート フォースはプロセスを正確に模倣するため機能しますが、各カードを個別に扱うと非効率になります。 ステップが構造化されており、所有権が周期的であるという観察により、シミュレーションをステップ全体の 1 つのループに圧縮できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (カードごと) | O(n) | お(1) | 最悪の場合、実装が遅すぎる。 
| ステップシミュレーション | O(√n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. アリスとボブのカウンタをゼロとして初期化し、ステップ サイズ i = 1 から開始します。 
2. 残りのカード n の変数を維持します。 各ステップで、実際に取られるカードの枚数 (i と残りのカードの最小値) を決定します。 これにより、最後の部分ステップを正しく処理できるようになります。 
3. 繰り返しサイクルを使用して、このステップを誰が受け取るかを決定します。 このパターンは 4 ステップごとに繰り返されます。ステップ 1 はアリスに、ステップ 2 と 3 はボブに、ステップ 4 と 5 はアリスにというように続きます。 これは、i modulo 4 をチェックし、それを正しいプレーヤーにマッピングすることで実装できます。 
4. 取り出したカードを適切なプレイヤーの合計に加え、残りの山札から差し引きます。 
5. i をインクリメントし、カードがなくなるまで繰り返します。 

このマッピングが正しい理由は、問題がステップにわたる決定論的な周期的な割り当てを定義しており、各ステップが最後の切り捨てを除いてカードの数に依存しないためです。 切り捨ては最終ステップにのみ影響し、その後の割り当ては変更しないため (プロセスが即時に停止するため)、ステップ境界をシミュレートすると正確さが維持されます。 

維持される不変条件は、ステップ i の処理後、完了したステップ 1 から i に対応するすべてのカードが、サイクルに従ってアリスまたはボブの合計に完全に考慮され、残りのカード (存在する場合) は次のステップにのみ属するということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        alice = 0
        bob = 0
        
        i = 1
        while n > 0:
            take = i if i <= n else n
            n -= take
            
            # cycle: 1 A, 2 B, 3 B, 4 A, repeats every 4 steps
            r = i % 4
            if r == 1:
                alice += take
            elif r == 2 or r == 3:
                bob += take
            else:
                alice += take
            
            i += 1
        
        print(alice, bob)

if __name__ == "__main__":
    solve()
```このソリューションは、各テスト ケースを個別に読み取り、処理プロセスを段階的にシミュレートします。 このループはすべてのカードがなくなるまで続き、各反復では残りのカードに応じて完全または部分的なバッチが割り当てられます。 

モジュロベースの分岐では、配列の保存や割り当ての事前計算を行わずにサイクルをエンコードします。 唯一の微妙な点は、ステップ 2 と 3 をボブのグループとして、ステップ 1 と 4 をアリスのグループとして正しくグループ化し、プロセスで説明されている繰り返しパターンと一致させることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(√n) | 各ステップで i が増加し、約 sqrt(n) ステップ後に 1..k の合計が n を超えます。 
| スペース | お(1) | カウンタとループ変数のみが使用されます。 

この制約により、n が 10^6 までのテスト ケースを最大 200 個まで許可できるため、sqrt(10^6) はテスト ケースごとに約 1000 ステップであるため、総作業量は十分に少ないままです。

def run(inp: str) -> str:

    import sys

    out = []
    for _ in range(t):
        n = int(input())

        bob = 0

            else:

        out.append(f"{alice} {bob}")
    return "\n".join(out)

 ## 特殊なケース

 n = 1 の場合、シミュレーションはステップ 1 のみを実行し、それをアリスに割り当て、すぐに停止します。 ループが 1 回実行され、take が 1、Alice が 1 になり、残りのカードが 0 になるため、それ以上のステップは実行されません。 

n = 2 の場合、ステップ 1 でアリスに 1 枚のカードが与えられ、次にステップ 2 でボブに 2 枚のカードが与えられますが、残りのカードは 1 枚だけなので、ボブはまさにその最後のカードを受け取ります。 アルゴリズムは min(i, n) を正しく使用し、過剰な割り当てが発生しないようにします。 

n が 6 や 10 などの三角数に正確に等しい場合、プロセスはステップ境界で正確に終了します。 シミュレーションが部分ステップに入ることはありません。そのため、所有権は特別な処理を必要とせずに完全なステップ サイクルによって純粋に決定されます。
