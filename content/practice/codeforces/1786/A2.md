 ## 解決策
 ## 問題の理解

 私たちはデッキを持っています`n`カードは、白から始めて色が厳密に交互になるように配置されます。 アリスはこれらのカードをバッチ サイズを増やして配ります。最初に 1 枚のカードを自分自身に、次に 2 枚のカードをボブに、3 枚のカードをボブに、4 枚のカードをアリスに、5 枚のカードをアリスに、6 枚のカードをボブに、7 枚のカードをボブにというように配ります。 パターンはペアで交互に行われます。連続する 2 つのステップが 1 人のプレーヤーに進み、次の 2 つのステップが他のプレーヤーに進みます。 残りのカードがステップ サイズより少ない場合、残りのカードはすべて現在のプレーヤーに送られます。 

タスクは、テスト ケースごとに、アリスとボブの白カードと黒カードの最終的な枚数を計算することです。 入力はカードの枚数です`n`出力は 4 つの整数です: 白カード アリス、黒カード アリス、白カード ボブ、黒カード ボブ。 

重要な制約は、`n ≤ 10^6`最大 200 のテスト ケース。 カードごとの割り当てをシミュレートする単純なアプローチには、最大で次のことが含まれます。`200 * 10^6`最悪の場合、反復が非常に遅くなります。 テスト ケースごとに定数時間または対数時間でカウントを計算するメソッドが必要です。 

注意すべきエッジケースとしては、非常に小さなデッキが挙げられます。`n = 1`、アリスのみがカードを取得する場合、または残りのデッキが次のバッチサイズよりも小さい状況。 もう 1 つの微妙な点は、「プレーヤーごとに 2 ステップ」ルールに従いながら、プレーヤー間のバッチ割り当てを正しく交互に行うことです。 

## アプローチ

 ブルートフォースアプローチは簡単です。取引プロセスを正確にシミュレートします。 デックの先頭にポインタを置き、各ステップに次の値を割り当てます。`step`一度に 2 ステップずつ交互にカードを正しいプレーヤーに配り、各色が何枚もらえるかを数えます。 これが機能するのは、デッキが交互に配置されているためです。 白いカードは 1、3、5、... の位置にあり、黒いカードは 2、4、6、... の位置にあります。 ただし、操作の合計数は最初の操作の合計に比例します。`k`に達するまでの整数`n`、大まかに言うと`O(n)`テストケースごとに。 最大の場合`n`そして`t`、これは実行可能な時間制限を超えています。 

最適なアプローチでは 2 つの観測値を使用します。 まず、交互に並ぶカードの連続シーケンスでは、セグメントの長さと開始色から白と黒のカードの数を直接計算できます。 具体的には、ある長さのセグメントに対して`l`白から始まり、白いカードは`(l + 1) // 2`そしてブラックカードは`l // 2`。 次に、ステップ シーケンスには繰り返し構造があることがわかります。ステップは増加する整数のバッチで発生し、連続する 2 つのステップが同じプレーヤーに進みます。 これら 2 つの事実を使用すると、個々のカードをシミュレートすることなく、数式によってカウントを計算しながらステップを繰り返すことができます。 これにより、複雑さが軽減されます。`O(√n)`なぜなら最初の合計は`k`整数は二次関数的に増加するため、ステップ数はおおよそ次のようになります。`√n`。 これでも十分速いです`n ≤ 10^6`そして200のテストケース。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 大きいものには遅すぎる`n`|
 | 最適 | O(√n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. アリスとボブのカウントを初期化します。`alice_white = alice_black = bob_white = bob_black = 0`。 から始める`next_card_white = True`そして`step = 1`。 
2. どのプレイヤーが現在カードを受け取っているかを追跡します。 アリスがスタートし、各プレイヤーはスイッチする前に 2 つの連続したステップを受けます。 
3.カードが残っているうちに（`n > 0`):

 ａ． このステップで配るカードの枚数を計算します。`deal = min(step, remaining_cards)`。 

b. このバッチ内の白と黒のカードの数を決定します。 次のカードが白の場合、白のカウントは`(deal + 1) // 2`そして黒カウントは`deal // 2`。 次のカードが黒の場合、これらの式を交換します。 

c. カウントを正しいプレイヤーの合計に加算します。 

d. 減算`deal`から`remaining_cards`そして裏返します`next_card_white`場合にフラグを立てる`deal`奇数のカードを交互に使用すると、次のカードのパリティが変わるためです。 

e. インクリメント`step`by 1. 2 ステップごとにプレーヤーを更新します。 
4. 最終的なカウントを、白アリス、黒アリス、白ボブ、黒ボブの順に出力します。 

重要な不変点は、各バッチ後に次のカードの色が正確にわかっており、ステップの割り当てがプレイヤーごとに 2 ステップのパターンに従っていることです。 これにより、各カードを個別にシミュレートすることなく、正しい蓄積が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        alice_white = alice_black = bob_white = bob_black = 0
        remaining = n
        step = 1
        next_white = True
        # player 0 = Alice, 1 = Bob
        player = 0
        step_count = 0
        while remaining > 0:
            deal = min(step, remaining)
            if next_white:
                whites = (deal + 1) // 2
                blacks = deal // 2
            else:
                whites = deal // 2
                blacks = (deal + 1) // 2
            if player == 0:
                alice_white += whites
                alice_black += blacks
            else:
                bob_white += whites
                bob_black += blacks
            remaining -= deal
            if deal % 2 == 1:
                next_white = not next_white
            step += 1
            step_count += 1
            if step_count == 2:
                step_count = 0
                player ^= 1
        print(alice_white, alice_black, bob_white, bob_black)

if __name__ == "__main__":
    solve()
```このソリューションは両方のプレイヤーのカウントを初期化し、すべてのカードが配られるまでステップを繰り返します。 の`next_white`flag は一番上のカードの色を追跡します。 次のカードの色を裏返すことで奇数の長さのバッチを慎重に処理し、単純なカウンターを使用して 2 ステップ後にプレーヤーを切り替えます。 使用する`min(step, remaining)`デックの最後でのインデックス エラーを回避します。
