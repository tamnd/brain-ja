 ## 解決策
 ## 問題の理解

 私たちは、各チームが 1 試合だけを行うサッカー トーナメントの完全な結果を受け取ります。 各試合について、各チームが得点したゴール数がわかります。 トーナメント ルールを使用して、どのチームがノックアウト ステージに進むかを決定する必要があります。 

各チームは試合からポイントを獲得します。 勝つと3ポイント、引き分けは1ポイント、負けると0ポイントとなります。 チームは 3 つの基準によってランク付けされ、順番にチェックされます。 

1. 合計ポイント。 
2. 得失点差、得点数から失点数を引いたもの。 
3. 合計ゴール数。 

この声明は、これらのルールが常に厳密な順序付けを生成することを保証するため、3 つの比較をすべて適用した後に 2 つのチームが完全に同点になることはありません。 

順位を計算した結果、トップは`n / 2`チームが出場資格を得ます。 出力には、ランキング順ではなく辞書順にソートされた対象となるチーム名が含まれている必要があります。 

制約は非常に小さいです。 最大 50 チームが参加します。つまり、試合数は最大 50 チームです。`50 * 49 / 2 = 1225`。 たとえ`O(n²)`または`O(n² log n)`このソリューションは 2 秒の制限内で十分に高速です。 主な課題は最適化ではなく、ランキング ルールを正しく実装し、試合形式を安全に解析することです。 

よくある間違いは、修飾子をアルファベット順ではなくランキング順に出力することです。 次の例を考えてみましょう。```
4
Brazil
Argentina
Spain
Italy
Brazil-Argentina 1:0
Brazil-Spain 0:0
Brazil-Italy 2:0
Argentina-Spain 1:0
Argentina-Italy 1:0
Spain-Italy 3:0
```ランキング順が次のようになったとします。```
Brazil
Spain
Argentina
Italy
```資格のあるチームはブラジルとスペインですが、必要な成果は次のとおりです。```
Brazil
Spain
```修飾子がスペインとアルゼンチンだった場合、正しい出力にはアルファベット順の並べ替えが必要になります。```
Argentina
Spain
```もう 1 つの簡単なバグは、得点と失点を個別に追跡するのではなく、得失点差を直接更新するときに発生します。 想像する：```
2
A
B
A-B 2:1
```チームAの特徴は次のとおりです。 

- ポイント = 3
 - 得点 = 2
 - 失点 = 1
 - 差 = 1

 差を保存するだけで合計得点を忘れた場合、後で 3 回目のタイブレークを適用することはできません。 

名前には大文字と小文字が含まれるため、解析にも注意が必要です。 マッチライン:```
RealMadrid-PSG 3:2
```以下に正しく分割する必要があります。 

- チーム1 =`RealMadrid`- チーム2 =`PSG`- スコア1 =`3`- スコア2 =`2`不用意にスペースのみで分割すると、名前とスコアの構造が失われます。 

## アプローチ

 最も直接的なアプローチは、トーナメント全体を説明どおりに正確にシミュレートすることです。 すべてのチームについて、蓄積された統計を維持します。 

- ポイント
 - 得点
 - 失点

 次に、すべての一致を 1 つずつ処理します。 結果に従って両方のチームを更新し、ランキング ルールを使用してすべてのチームを並べ替えます。 

このブルートフォース手法は、最大 1225 件の一致があるため、すでに十分に高速です。 各試合の処理には一定の時間がかかり、50 チームの並べ替えにはほとんどコストがかかりません。 総作業量は 100 万回をゆうに下回ります。 

一部の初心者は、試合ごとにランキングを繰り返し再計算しようとしたり、ペアごとにチームを複数回比較したりして、この問題を複雑にしすぎます。 これはこれらの制約下でも機能しますが、問題の実際の構造がわかりにくくなります。 

重要な観察は、ランキング基準が集計された統計のみに依存しているということです。 すべての試合が処理されると、各チームは次のように完全に記述されます。 

- 合計ポイント
 - 得失点差
 - 得点

 他には何も関係ありません。 個人の試合履歴はもう必要ありません。 

これにより、問題全体を次のように簡略化できます。 

1. すべてのゲームから統計を作成します。 
2. 公式比較ツールを使用してチームを並べ替えます。 
3. 最初のものを取る`n / 2`。 
4. アルファベット順に出力します。 

解決策はアルゴリズムの難しさではなく、実装を慎重に行うことです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 比較を繰り返すブルートフォース | O(n3) | O(n) | 承認済み |
 | 最適な集計 + 単一ソート | O(n² + n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. チーム数を読み取り、すべてのチーム名を保存します。 

統計のインデックス付けと最終出力の両方に名前が必要です。 
2. すべてのチームの統計テーブルを作成します。 

各チームストアについて:

 - ポイント
 - 得点
 - 失点

 得失点差は常に次のように計算できます。```
scored - conceded
```3. すべてのマッチラインを処理します。 

各行の形式は次のとおりです。```
team1-team2 x:y
```行をチーム部分とスコア部分に分割し、次を抽出します。 

-`team1`-`team2`-`x`-`y`4. 両チームの目標を更新します。 

チーム1が得点した場合`x`そして譲歩する`y`：

- 追加`x`得点する
 - 追加`y`譲歩する

 チーム 2 に対して対称更新を実行します。 
5. 結果に応じてポイントを更新します。 

もし`x > y`、team1 が 3 ポイントを獲得します。 

もし`x < y`、team2 が 3 点を獲得します。 

Otherwise both teams get 1 point.
 6. すべての試合が処理されたら、ランキング ルールに従ってチームを並べ替えます。 

コンパレータは次のとおりです。 

- 高いポイントから順に
 - higher goal difference first
 - higher goals scored first

 Python はデフォルトで昇順にソートするため、負の値を使用してソートします。 
7. 最初のものを取る`n / 2`teams from the sorted standings.

 These are the qualified teams.
 8. 資格のあるチーム名を辞書順に並べ替えます。 

出力形式には、ランキング順ではなく、アルファベット順が必要です。 
9. Print the names one per line.

 ### なぜ効果があるのか

 すべてのランキング基準は、蓄積されたトーナメント統計のみに依存します。 各試合を処理すると、サッカーの得点ルールに従って正確に統計が更新されます。 すべての試合が処理された後、各チームの保存された値は実際のトーナメント記録と一致します。 

並べ替え基準:

 1.ポイント、
 2.得失点差、
 3. 得点、

 公式順位の定義を正確に再現します。 このステートメントでは完全な結合が保証されていないため、並べ替え順序は一意になります。 最初の選択`n / 2`チームは正確に予選を通過します。 これらの名前をアルファベット順に並べ替えると、必要な出力形式と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    stats = {}

    for _ in range(n):
        name = input().strip()
        stats[name] = {
            "points": 0,
            "scored": 0,
            "conceded": 0
        }

    matches = n * (n - 1) // 2

    for _ in range(matches):
        line = input().strip()

        teams_part, score_part = line.split()
        team1, team2 = teams_part.split('-')

        g1, g2 = map(int, score_part.split(':'))

        stats[team1]["scored"] += g1
        stats[team1]["conceded"] += g2

        stats[team2]["scored"] += g2
        stats[team2]["conceded"] += g1

        if g1 > g2:
            stats[team1]["points"] += 3
        elif g1 < g2:
            stats[team2]["points"] += 3
        else:
            stats[team1]["points"] += 1
            stats[team2]["points"] += 1

    teams = list(stats.keys())

    teams.sort(
        key=lambda name: (
            -stats[name]["points"],
            -(stats[name]["scored"] - stats[name]["conceded"]),
            -stats[name]["scored"]
        )
    )

    qualified = teams[: n // 2]
    qualified.sort()

    print('\n'.join(qualified))

solve()
```最初のセクションでは、すべてのチーム名を読み取り、統計の辞書を初期化します。 チーム名をキーとする辞書を使用すると、インデックス作成の問題が回避され、更新が簡単になります。 

各マッチ ラインは 2 つの部分に分割されます。 

-`"A-B"`-`"1:0"`次に、各部分が個別に解析されます。 チーム名には大文字と小文字の両方が含まれる場合があるため、一度にすべてを分割しようとするよりも安全です。 

得点と失点はポイントの前に更新されます。 得点と失点を別々に記録しておくと、タイブレークの計算ミスを避けることができます。 得失点差は並べ替え時にのみ算出されます。 

ソートキーはトーナメントルールを直接エンコードします。 負の値を指定すると順序が逆になるため、より大きな統計が最初に表示されます。 

微妙な詳細の 1 つは、資格のあるチームの最終的なアルファベット順の並べ替えです。 多くの誤った提出では、代わりにチームをランキング順に印刷します。
