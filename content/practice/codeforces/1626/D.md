 ## 解決策
 ## 問題の理解

 複数の重みセットが与えられているので、数直線上の 2 つのカットポイントを使用して、これらの値を 3 つのグループに分割する必要があります。 厳密に最初のカットより下のすべては 1 つのグループに属し、少なくとも 2 番目のカットよりもすべては別のグループに属し、その間にあるものはすべて 3 番目のグループを形成します。 

この分割の後、各グループのサイズは 2 の累乗である必要があり、空のグループは許可されません。 グループが小さすぎる場合、またはそのサイズが 2 の累乗でない場合は、サイズが 2 の累乗になるまでそのグループに要素を追加することができます。 目標は、3 つのグループすべてにわたって追加される要素の総数が最小限になるように 2 つのカット ポイントを選択することです。 

主な難点は、2 つのカット ポイントによって 3 つのグループ サイズが同時に決定され、境界を移動すると 2 つのグループが同時に変更されることです。 これにより、各グループを独立して扱うことができなくなり、決定が結合されます。 

制約が十分に厳しいため、$O(n^2)$すべての境界ペアにわたるスキャンは限界に達していますが、プレフィックス数と定数時間の評価を慎重に最適化すれば、依然として可能です。 要素を割り当てるすべての方法またはすべての可能なターゲット 2 のべき乗トリプルに対する完全な組み合わせ検索は、各テストに最大$2 \cdot 10^5$合計の要素。 

素朴だが誘惑しやすい間違いは、より適切な分割によりグループ間で要素が移動し、必要な追加が大幅に削減される可能性があることを考慮せずに、固定分割の現在のサイズに基づいて各グループを独立して 2 の累乗に切り上げることができると想定することです。 もう 1 つのよくある落とし穴は、最初はサイズ 0 のグループが許可されているものの、それでも非ゼロにする必要があることを忘れていることです。これにより、すでに少なくとも 1 回の挿入が強制されます。 

たとえば、すべての要素が等しい場合、合理的な分割によりすべてが 1 つのグループに配置され、他の 2 つは空のままになります。 単純なソリューションでは、空ではないグループの丸めのみが考慮され、空のグループをアクティブ化するための必須コストが欠落している可能性があります。 

## アプローチ

 2つの境界線を修正すれば$x$そして$y$、3 つのグループのサイズが決定的になります。以下に該当する要素の数を数えることができます。$x$、 間$x$そして$y$、以上$y$。 グループサイズごとに$k$、それを「修正」するためのコストは、厳密には 1 以上ですが、1 自体以上の 2 の最小累乗です。 具体的に変革する必要があるのは、$k$を 1 以上の最も近い 2 のべき乗に変換し、その差がコストとなります。 

ブルートフォース手法では、考えられるすべてのペアを列挙します。$(x, y)$。 以来$x$そして$y$配列内に現れる値のみが重要です。$O(n^2)$候補者が分裂する。 各分割について、グループ サイズを計算します。$O(n)$、につながる$O(n^3)$全体的に複雑なので、遅すぎます。 

配列をソートし、プレフィックス数を操作することで、これを減らすことができます。 固定の場合$x$、最初のグループはプレフィックスであり、固定の場合は$y$、3 番目のグループは接尾語です。 中間グループは差がつきます。 これにより、3 つのサイズすべてをペアごとに一定時間で計算できます。 

重要な観察は、コスト関数はグループ サイズのみに依存し、各グループのコストはそのサイズが 2 の次の累乗からどれだけ離れているかにのみ依存するということです。 可能なすべてのサイズについて事前計算できます。$n$、次の 2 の累乗に達するまでのコスト。 

これにより、すべての有効な分割ポイントをスキャンするという問題が軽減されます。$O(n^2)$の合計なので、これで十分です。$n$テスト全体にわたって$2 \cdot 10^5$, そのため、作業全体は管理可能なままです。

 ## アルゴリズムのチュートリアル

 まず、有効な分割が 2 つのインデックスの選択に対応するように配列を並べ替えます。$i < j$、ここで、前のすべての要素は$i$軽量、$i$そして$j$ミドル級以降$j$重量級です。 

配列を事前計算します`cost[k]`、これは、グループの規模を大きくするために必要な追加参加者の数を示します。$k$次の 2 のべき乗。 これは、以下の 2 の最小累乗を見つけることによって計算されます。$k$そして引き算$k$。 

次に、すべてのペアを試します$(i, j)$そして計算します:

 1.軽量級グループの規模は$i$。 
2. 中間グループのサイズは次のとおりです。$j - i$。 
3. ヘビー級グループの規模$n - j$。 

分割ごとに、合計コストを次のように計算します。`cost[i] + cost[j - i] + cost[n - j]`、すべての分割の最小値を追跡します。 

各ペアは、3 つの連続するグループへの重みの完全な割り当てを表し、並べ替えによって順序が維持されるため、すべての有効なしきい値ペアは、そのような分割の 1 つに正確に対応します。 

これが機能する理由は、一度並べ替えると、重要なのはどの特定の要素ではなく、各領域に分類される要素の数だけになるためです。 コスト関数はカウントのみに依存し、分割列挙は、しきい値の選択から生じる可能性のあるすべてのカウント トリプルをカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    # Precompute powers of two up to max n
    max_n = 2 * 10**5 + 5
    nxt = [0] * (max_n + 1)
    
    p = 1
    for i in range(1, max_n + 1):
        while p < i:
            p <<= 1
        nxt[i] = p
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()
        
        cost = [0] * (n + 1)
        for i in range(n + 1):
            cost[i] = nxt[i] - i
        
        ans = 10**18
        
        for i in range(n + 1):
            for j in range(i, n + 1):
                left = i
                mid = j - i
                right = n - j
                ans = min(ans, cost[left] + cost[mid] + cost[right])
        
        print(ans)

if __name__ == "__main__":
    solve()
```実装は、すべてのサイズの次の 2 のべき乗のルックアップ テーブルを構築することから始まります。 これにより、入れ子になったループ内で対数を繰り返し再計算する必要がなくなります。 の`cost`配列は、グループ サイズを一定時間で挿入コストに変換します。 

ダブルループオーバー`i`そして`j`ソートされた配列を 3 つの連続するセグメントに分割する可能なすべての方法を列挙します。 境界は 2 つのしきい値に直接対応します。$x$そして$y$ソートにより、しきい値の選択によってそのようなパーティションが確実に生成されるためです。 

微妙な点は、空のセグメントの処理です。 ループにより、`i == 0`または`j == i`、サイズがゼロのグループが生成されます。 コスト関数は、0 を次の 2 のべき乗である 1 にマッピングすることで、これらをサイズ 1 に正しく強制します。

 ## 特殊なケース

 重大なエッジ ケースは、1 つまたは 2 つのグループが空の場合です。 のような入力の場合`[5]`の場合、しきい値を選択すると、サイズ 1 のグループが 1 つと空のグループが 2 つ生成されます。 アルゴリズムはこれをコストとして評価します`0 + 1 + 1 = 2`、不足している両方の部門のアクティブ化を正しく強制します。 

もう 1 つのエッジ ケースは、グループ サイズがすでに 2 の累乗になっている場合です。`[1,1,2,2]`。 正しく分割するとサイズが得られます`[2,2,0]`または同様の置換を行うと、空ではないグループのコストはゼロになりますが、空のグループは依然として寄与します。 

空のグループはサイズ 0 として扱われ、2 の次のべき乗計算によって自動的に 1 に切り上げられるため、アルゴリズムはこれらのケースを均一に処理します。
