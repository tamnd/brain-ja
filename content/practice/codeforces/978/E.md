 ## 解決策
 ## 問題の理解

 バスの乗客数の一連の記録された変化が与えられます。 それぞれの値は、停車後に乗客数がどのように変化するかを示します。したがって、開始乗客数を次のように表すと、$x$、その後、各停止後に指定されたデルタを繰り返し加算し、実行中のプレフィックス合計プロセスを取得します。 

バスには厳しい制約があります。乗客の数は常に次の間隔に留まらなければなりません。$0$そして$w$、包括的。 これは、記録された各停止の後だけでなく、最初の停止の直前にも適用されます (カウントは$x$）。 

タスクは、1 つの有効なシナリオを再構築することではなく、最初の乗客数の整数値がいくつあるかを数えるということです。$x$は有効であるため、すべての中間プレフィックスの合計が許容範囲内に留まります。 

制約はすでに次のことを示唆しています。$O(n)$または$O(n \log n)$解決策が必要です。 と$n \le 1000$、たとえ$O(n^2)$アプローチは合格するかもしれませんが、可能なすべての開始値を広範囲にわたって直接シミュレートしようとするものはすべて、$10^9$不可能です。 

重要な微妙な点は、初期値が$x$入力によって制限されることはなく、暗黙的に実行可能性によってのみ制限されます。 単純な読者は、次のすべての可能な開始値を反復しようとするかもしれません。$0$に$w$ただし、実際の実行可能な範囲は、負のプレフィックス合計により中間状態の範囲外にシフトする可能性があります。 

よくある失敗例の 1 つは、中間の制約を無視したことに起因します。 たとえば、プレフィックスの合計がゼロを下回った場合、グローバルに有効に見える開始値が、あるステップで制約に違反する可能性があります。 同様に、プレフィックスの合計が特定の範囲を超えた場合も、開始は無効になります。 正確さは、最終的な値だけでなく、プレフィックス合計の軌跡全体を追跡することに依存します。 

## アプローチ

 中心的な観察は、ステップでの乗客数です。$i$次のように書くことができます:$$x + p_i$$どこ$p_i$までの記録された変更のプレフィックスの合計です。$i$。 

したがって、すべての制約は次のようになります。$$0 \le x + p_i \le w$$並べ替えると、間隔の制約が与えられます。$x$:$$-p_i \le x \le w - p_i$$したがって、各プレフィックスの合計は、有効な開始値の間隔に寄与します。 最終的な答えは、これらすべての間隔の交差点です。$i$、暗黙的なプレフィックス合計を含む$p_0 = 0$。 

強引なアイデアは、可能な限りすべてのことをテストすることです$x$から$0$に$w$コストがかかるすべてのステップをシミュレートします$O(wn)$、あまりにも大きすぎるので、$w$できる$10^9$。 上記の観察により、問題は間隔の交差を維持することに変わり、すべてが 2 つの値のみを追跡することになります。 

すべての制約の交差部分自体が 1 つの区間になります$[L, R]$、段階的に更新されます。 各プレフィックスの合計により、この間隔が狭まります。 いずれかの時点で間隔が空になった場合、有効な開始値は存在しません。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(nw)$|$O(1)$| 遅すぎる |
 | 区間交差点 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは定義します$p$変更の実行中のプレフィックスの合計として。 

1.初期化$p = 0$、有効範囲を設定します$x$として$L = 0$、$R = w$。 これは、バスが最初に容量制約をすでに満たしている必要があるという事実を反映しています。 
2. 記録された変更ごとに$a_i$、プレフィックスの合計を更新します$p = p + a_i$。 これは、初期状態からステップへの正味のシフトを表します。$i$。 
3. 条件を変換する$0 \le x + p \le w$の制約に$x$、間隔を生成します$[-p, w - p]$。 
4. この間隔を現在の有効範囲と交差させます。$L = \max(L, -p)$、$R = \min(R, w - p)$。 

これにより、これまでのすべての制約を満たす開始値のみを維持することが保証されます。 
5. いつでも$L > R$、有効な初期値が存在しないため、早期に停止します。 
6. すべてのステップを処理すると、答えは次のようになります。$R - L + 1$、最後の間隔のすべての整数が有効な開始乗客数であるためです。 

### なぜ効果があるのか

 各ステップでは、初期値に線形制約が課されます。$x$。 すべての制約は次の形式であるため、$x \in [\ell_i, r_i]$、有効なセットは区間の交差部分です。 間隔の交差は結合的であり、情報を失うことなく段階的に維持できます。 このアルゴリズムは、各ステップ後に実行可能なすべての開始値のセットを正確に保存するため、有効な解が破棄されることはなく、無効な解が導入されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, w = map(int, input().split())
    a = list(map(int, input().split()))

    prefix = 0
    L, R = 0, w

    for x in a:
        prefix += x

        L = max(L, -prefix)
        R = min(R, w - prefix)

        if L > R:
            print(0)
            return

    print(max(0, R - L + 1))

if __name__ == "__main__":
    solve()
```この実装では、単一の実行中のプレフィックス合計が保持され、各ステップで実行可能な範囲が更新されます。 境界$L$そして$R$は常に、これまでに確認されたすべての制約の交差部分を表します。 早期退場時$L > R$実現可能性が崩れた場合に不要な計算を回避します。 

微妙な点は、最終的な答えが正しく固定されていることを確認することです。制約が一貫している場合、$R - L + 1$すべての整数の初期値をカウントします。 不一致が発生した場合、関数はすでにゼロを返します。

 ## 特殊なケース

 1 つのエッジ ケースは、すべての変更がゼロの場合に発生します。 その状況では、プレフィックスの合計は全体を通してゼロのままであるため、次のすべての開始値は$0$に$w$有効です。 アルゴリズムは維持します$L=0$そして$R=w$変更せず、生産$w+1$、正しいカウントと一致します。 

もう 1 つのエッジ ケースは、制約がすぐに不可能になる場合です。 たとえば、次の場合$w = 3$そして最初の変化は$+5$の場合、プレフィックスの合計はすでに開始値の実行可能な範囲外になります。 間隔は$[L, R] = [0, 3] \cap [-5, -2]$これは空であり、アルゴリズムはそれ以上の処理を行わずに正しくゼロを出力します。 

最後の微妙なケースは、中間プレフィックスの合計によって、最終的な合計からは見えない制約が強制される場合です。 2 番目の実際の例は、合計の変化が小さい場合でも、中間の累積により有効な開始が制限されることを示しています。 間隔交差アプローチでは、最後だけでなくすべてのプレフィックスで制約が評価されるため、これが自動的に取得されます。
