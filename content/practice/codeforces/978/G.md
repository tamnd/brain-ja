 ## 解決策
 ## 問題の理解

 私たちに与えられたタイムラインは、$n$日とセット$m$試験はそれぞれ、特定の日に行われるように固定されています。 また、すべての試験には、発表日後に始まり、試験自体の前日に終了する準備期間と、必要な準備日数が含まれています。 

毎日を 1 つの方法で使用できます。 Petya は休むか、1 回だけの試験の準備をするか、試験を受けます。 試験の準備は連続して行う必要はなく、異なる試験を数日間に自由に挟むことができます。 唯一の厳しい制約は、各試験が許可された枠内で必要な準備日数を正確に受け取る必要があり、試験当日に準備を行うことはできないことです。 

出力は長さの完全なスケジュールです$n$、毎日を休息、特定の試験の準備、または試験のいずれかに割り当てます。 複数のスケジュールが存在する場合は、有効なスケジュールをどれでも使用できます。 

主要な構造的問題は、重複する時間帯で準備枠が競合し、試験日によって空き時間が永久に失われることです。 

制約$n \le 100$、$m \le n$スケジュールを超えた指数関数的な検索を直ちに除外します。 割り当てに対する素朴な後戻りさえも、$n$1 日に 3 つの選択肢がある日は、$3^n$、それは不可能です。 そうではなく、実現可能性を維持しながら一日ずつ日を割り当てる貪欲な構築が必要です。 

複数の試験の準備期間が重複し、締め切りが厳しい場合、微妙な特殊なケースが発生します。 たとえば、2 つの試験はどちらも共通の試験日の前に準備が必要な場合がありますが、どちらの試験が早く準備できるかを慎重に優先順位付けしないと、十分な「空き」日がなくなる可能性があります。 

将来の実現可能性を考慮せずに貪欲に準備を割り当てると、別の失敗モードが発生します。 たとえば、締め切りが遅い試験に早い日を割り当てた場合、後で厳しい試験を完了できないことが判明する可能性があります。 

## アプローチ

 強引なアイデアとしては、毎日をスケジュール内のポジションとして扱い、試験日を固定しつつ、準備と休憩のすべての課題に取り組むことです。 その後、各受験者のスケジュールは、試験ごとの準備をカウントし、時間枠をチェックすることによって検証されます。 このアプローチは原理的には正しいですが、おおよそのサイズの巨大な検索空間を探索します。$3^n$、これは限界をはるかに超えています$n = 100$。 

問題の構造は別の見方を示唆しています。 各試験には、間隔内に配置する必要がある多数の「スロット」が必要です。$[s_i, d_i)$、試験日そのものを除きます。 試験日は強制的な割り当てであり、タイムラインから 1 つのポジションを削除する厳しい制約として機能します。 これにより、問題は、使用可能なスロットを徐々に埋めるという制約付きのスケジューリング タスクに変換されます。 

重要な観察は、私たちは日々を順番に処理し、貪欲に課題を決定することができますが、実行不可能になるリスクのある試験を常に優先しなければならないということです。 いずれの日においても、準備のために複数の試験が用意されている場合は、試験日が最も近く、まだ準備が必要な試験を優先する必要があります。 これにより、より柔軟な試験に時間を浪費している間に、締め切り間近の試験で利用可能なスロットが不足してしまうという状況を防ぐことができます。 

これは当然、優先順位構造を備えた貪欲なプロセスにつながります。現在どの試験が準備に利用可能であるかを維持し、残りの必要な準備を追跡します。 当社では常に、空き日を現在有効な最も緊急の未完了の試験に割り当てます。

 ## アルゴリズムのチュートリアル

 1日から1日までスケジュールを組み立てていきます。$n$。 

1. まず、すべての試験日を記録して、どの日が強制試験日であるかを把握します。 当日は準備は禁止です。 
2. 試験ごとに、残りの必要な準備を保存します。$c_i$、その開始日$s_i$、そしてその試験日$d_i$。 
3. 1 日から 2 日まで繰り返します。$n$。 毎日、まずすべての試験を有効にします。$s_i$準備の対象となるため、現在の日と等しくなります。 
4. 当日が何らかの試験の試験日の場合$i$、その日を試験マーカーに割り当て、準備を許可しません。 試験日は決まっているのでこれは必須です。 
5. それ以外の場合は、現在アクティブなすべての試験が考慮されます。つまり、試験の開始日は過ぎており、まだ準備が残っていることを意味します。 これらの中で、期限が最も短い試験を選択します$d_i$そしてまだ準備が必要です。 
6. そのような試験が存在する場合、当日をその試験の準備に割り当て、残りの要件を減算します。 この選択により、最も緊急性の高い制約が優先されることが保証されます。 
7. 準備が必要な実際の試験がない場合は、その日を休息日として割り当てます。 

丸一日処理した後、すべての試験が必要な準備を完了したかどうかを確認します。 もしあれば$c_i$がまだ正である場合、出力します$-1$そうでない場合は、構築されたスケジュールを出力します。 

### なぜ効果があるのか

 このアルゴリズムは、重要な不変条件を維持しています。つまり、毎日、実行可能なすべての選択肢の中で、どちらもまだ作業が必要な場合、期限が早い試験を延期して、期限が遅い試験を優先することは決してありません。 これにより、厳しい試験が柔軟な試験によって不足するという締め切りの逆転を防ぐことができます。 

ある時点で有効なスケジュールが存在する場合、実行可能性を損なうことなく、後の期限に割り当てられた準備日を以前の期限と交換できるように、スケジュールを再調整する方法が常にあります。 この交換の議論は、利用可能な試験のうち最も近い締め切りを常に優先するという貪欲な選択を正当化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    exams = []
    exam_day = [-1] * (n + 1)
    
    for i in range(m):
        s, d, c = map(int, input().split())
        exams.append([s, d, c, i + 1])
        exam_day[d] = i + 1
    
    exams.sort()
    
    active = []
    remaining = [0] * (m + 1)
    start_map = [[] for _ in range(n + 2)]
    
    for s, d, c, idx in exams:
        start_map[s].append((d, idx))
        remaining[idx] = c
    
    res = [0] * (n + 1)
    
    import heapq
    
    for day in range(1, n + 1):
        for d, idx in start_map[day]:
            heapq.heappush(active, (d, idx))
        
        if exam_day[day] != -1:
            res[day] = m + 1
            continue
        
        while active and remaining[active[0][1]] == 0:
            heapq.heappop(active)
        
        if active:
            d, idx = heapq.heappop(active)
            if day < d:
                res[day] = idx
                remaining[idx] -= 1
            else:
                res[day] = 0
        else:
            res[day] = 0
    
    if any(remaining[i] > 0 for i in range(1, m + 1)):
        print(-1)
    else:
        print(*res[1:])

if __name__ == "__main__":
    solve()
```この実装は貪欲なプロセスを直接反映しています。 配列`exam_day`強制試験日をエンコードして、すぐに処理できるようにします。 の`start_map`この構造では、準備期間が開いたときに正確に試験が開始されます。 

ヒープには、期限順に並べられたアクティブな検査が保存され、最も緊急性の高い検査が常に最初に考慮されるようになります。 の`remaining`配列は準備に必要な日数を追跡し、古いヒープ エントリは遅延的にスキップされます。 

微妙な点ですが、試験日以降に準備を割り当てることは避けなければならないため、次のことを確認します。`day < d`準備課題に取り組む前に。 この条件が満たされない場合、その時点ではその試験に対する有効な割り当てが存在しないため、その日はアイドル状態として扱われます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、試験に利用可能な期間よりも多くの準備日数が必要な場合です。 たとえば、試験が 1 日目に発表され、3 日目に予定されているものの、準備に 3 日間必要な場合、間隔には使用可能な 2 日のみが含まれます。 ヒープベースの選択では最終的に有効な日数がなくなり、残されたままになるため、アルゴリズムはこれを正しく処理します。`remaining[i] > 0`、トリガー`-1`。 

もう 1 つのケースは、複数の試験が同じ試験日を共有する場合です。 試験日は制約によって排他的であるため、このようなことは起こり得ず、アルゴリズムはその一意性に基づいてマークを付けます。`exam_day[d]`安全に。 

最後の微妙なケースは、試験がアクティブになったが、期限がすでに過ぎている場合です。 その場合の条件としては、`day < d`割り当てが妨げられ、試験は事実上無視され、要件がまだ満たされていない場合は後で強制的に不合格になります。
