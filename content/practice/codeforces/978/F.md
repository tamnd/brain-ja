 ## 解決策
 ## 問題の理解

 私たちには一組のプログラマーが与えられており、それぞれが固定のスキル値を持っています。 あらゆるプログラマーにとって$i$、他に何人のプログラマーがいるかを数えたいと思います$j$彼らは「指導」することができます。 メンターシップには方向性があります。$i$指導できる$j$そのときだけ$i$よりも厳密に高いスキルを持っています$j$、そして同時に$i$そして$j$は競合しているものとしてリストされていません。 

したがって、各インデックスについて$i$、インデックスの数を効率的に数えています。$j$2つの条件を同時に満たす：スキル比較$r_i > r_j$、および禁止されたペアの不在$(i, j)$。 

難しさはスケールから来ています。 まで$2 \cdot 10^5$プログラマと競合ペアの数が同じ場合、すべてのペアを個別にチェックするアプローチは遅くなりすぎます。 すべてのペアにわたる単純な二重ループには、約$4 \cdot 10^{10}$最悪の場合の比較は、3 秒以内に実行可能な限界をはるかに超えます。 

入力の微妙な点は、競合がすべての可能なペアと比較してまばらであることです。 これは、構造が完全なグラフの問題ではなく、「ほとんどがソートされたカウントであり、小さな修正が加えられている」ことを示唆しています。 

単純なカウントを破るエッジケースの 1 つは、多くのプログラマーが同じスキルを共有している場合です。 たとえば、すべてのスキルが等しい場合、誰も誰かを指導することはできないため、答えはすべてゼロでなければなりません。 「厳密に低い」のではなく「低いか等しい」とカウントする単純なアプローチでは、この状況では誤って過剰にカウントされてしまいます。 

もう 1 つの厄介なシナリオは、プログラマに多くの競合がある場合に発生します。 スキルの順序を考慮せずにプログラマごとに固定数だけを減算すると、無効なペアが減算される可能性があります (相手のスキルが同等以上であり、そもそもカウントされなかった場合)。 

## アプローチ

 ブルートフォースのアイデアは簡単です: 各プログラマーにとって$i$、他のすべてのプログラマをスキャンします$j$、どうかを確認してください$r_i > r_j$、またそれを確認します$(i, j)$衝突ではありません。 This is correct because it directly enforces the definition of mentorship. ただし、各クエリはスキャンします$O(n)$候補者全員のためにこれを行う$n$ノードは次のことにつながります$O(n^2)$指定された制約では動作が遅すぎます。 

重要な改善は、問題を 2 つの部分に分割することによってもたらされます。 まず、競合を完全に無視し、各プログラマーよりも厳密に低いスキルを持っているプログラマーが何人いるかを数えます。$i$。 これは、並べ替えることによって、または圧縮された値に対する頻度カウントを使用して、グローバルなベースライン カウントを生成することによって実行できます。 

次に、競合ペアごとに、無効なケースを差し引いてこのベースラインを修正します。$(a, b)$、ちょうど 1 方向が誤ってカウントされた可能性があります。 もし$r_a > r_b$、 それから$b$に含まれていました$a$のベースライン数ですが、削除する必要があります。 もし$r_b > r_a$、 それから$a$から削除する必要があります$b$のカウント。 スキルが等しい場合、どちらの方向も有効ではなく、何も変わりません。 

これにより、問題がソートとすべてのエッジの 1 回の反復に減らされ、効率的になります。

 ## アルゴリズムのチュートリアル

 1. すべてのスキル値を読み取り、インデックスとともに保存します。 

これは、後で結果を元の位置にマッピングしながら、プログラマーをスキルごとに並べ替えることができるようにするために必要です。 
2. プログラマをスキル値で並べ替えます。 

並べ替えにより、単一の線形スイープで各スキル レベルに厳密に小さい値がいくつ存在するかを計算できます。 
3. ベースライン配列を計算する`cnt[i]`プログラマよりも厳密に低いスキルを持っているプログラマが何人いるかを表す$i$。 

これは、並べ替えられた順序に対する頻度の集計を使用して行われます。 等しい値を処理する場合、同じスキルが互いにカウントされないようにグループ化されます。 
4. 結果配列を初期化する`ans[i] = cnt[i]`。 

この段階では競合を無視しているため、有効な「スキルのみ」の候補がすべて含まれます。 
5. 各競合ペアを処理する$(x, y)$。 

もし$r_x > r_y$、 それから$y$誤ってカウントされました$x$の合計なので減分します`ans[x]`。 

もし$r_y > r_x$、デクリメント`ans[y]`。 

両者が同等の場合は、定義上、どちらも相手を指導できないため、何もしません。 
6. 最終出力`ans`配列。 

### なぜ効果があるのか

 ベースライン`cnt[i]`よりも厳密に小さいスキルを持つすべてのプログラマーを正確にカウントします。$i$。 このセットは競合から独立しています。 各競合ペアは、このベースラインで最大 1 つの指示された指導関係を無効にすることができます。より高いスキルからより低いスキルへの方向のみが重要です。 すべての無効なペアは 1 回だけ減算され、有効なペアは減算されないため、最終的なカウントは定義と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    r = list(map(int, input().split()))

    # pair (skill, index)
    arr = [(r[i], i) for i in range(n)]
    arr.sort()

    cnt = [0] * n

    # compute how many strictly smaller elements each index has
    i = 0
    smaller = 0
    while i < n:
        j = i
        while j < n and arr[j][0] == arr[i][0]:
            j += 1
        # all elements before i are strictly smaller
        for t in range(i, j):
            idx = arr[t][1]
            cnt[idx] = smaller
        smaller += (j - i)
        i = j

    ans = cnt[:]

    for _ in range(k):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        if r[x] > r[y]:
            ans[x] -= 1
        elif r[y] > r[x]:
            ans[y] -= 1

    print(*ans)

if __name__ == "__main__":
    solve()
```ソートのステップでは、グローバル カウンターを増やす前に、等しいスキルをグループ化し、それらに同じ「小さいカウント」を割り当てることで、厳密な不平等を正しく処理できるようにします。 減算ステップは意図的に非対称になっています。つまり、その方向のみが初期カウントに寄与する可能性があるため、よりスキルの高いエンドポイントのみを調整します。 

ここでは慎重なインデックス作成が不可欠です。 減算は完全なベースラインを計算した後に行われるため、競合処理と順序付けロジックの間の干渉が回避されます。

 ## 特殊なケース

 同等のスキルの場合、アルゴリズムは並べ替えステップでそれらをグループ化し、グループ内のプログラマが同じグループ内の他のプログラマよりもスキルが低いとみなさないようにします。 たとえば、入力`3 0 / 5 5 5`単一のブロックが生成されます。`smaller`カウントを割り当てるときは 0 のままであるため、すべてのエントリは 0 になります。 

同等のスキルを持ったプログラマー間の競合の場合、次のような場合があります。`(1,2)`両方のスキルが 10 の場合、どちらの条件トリガーの分岐もないため、減算は発生しません。 これにより、誤った負の調整が防止され、等価処理の正確さが維持されます。 

スキルの低いプログラマーが多くの競合を抱えている場合、相手側がより高いスキルを持っていない限り、それらの競合はカウントに影響を与えることはありません。 彼らは、より高いスキルまたは同等のスキルを持つプログラマーの指導者としてカウントされることはないため、無効な減算は発生せず、密集した競合グラフでもアルゴリズムは安定したままになります。
