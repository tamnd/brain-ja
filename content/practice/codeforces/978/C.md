 ## 解決策
 ## 問題の理解

 私たちはいくつかの寮を一列に並べて与えられます。 各寮には既知の数の部屋が含まれており、すべての寮のすべての部屋が概念的に 1 つの長いシーケンスに連結されています。 最初の寮が最初に部屋を割り当て、次に 2 番目の寮というように、1 から部屋の総数までの単一の連続した番号を形成します。 

タスクは、各クエリがこの組み合わせシーケンスでグローバル ルーム インデックスを与えるクエリに答えることです。 このようなインデックスごとに、2 つのことを決定する必要があります。それは、どの寮にその部屋があるのか​​、もう 1 つはその部屋のローカル インデックスがその寮内にあるのかということです。 

入力サイズにより構造が重要になります。 寮の数とクエリの数は両方とも最大 200,000 で、各寮には最大 10¹⁰ の部屋があります。 これにより、完全に平坦化された配列をシミュレートしたり、クエリごとに線形にスキャンしようとするアプローチは即座に排除されます。 クエリごとに寮をスキャンしても、最悪の場合は 2×10⁵ × 2×10⁵ の操作が発生し、制限時間を大幅に超えます。 

微妙なエッジ ケースは、累積合計の境界値から発生します。 たとえば、寮に広さがある場合`[3, 5]`次に、グローバル インデックス 1 ～ 3 がドミトリー 1 にマップされ、4 ～ 8 がドミトリー 2 にマップされます。単純な間違いは、プレフィックスの合計を一貫性のない開区間として扱うことであり、境界条件が慎重に処理されない場合、インデックス 3 を 2 番目のドミトリーに誤ってマッピングするなど、1 つずつずれたエラーが発生します。 

もう 1 つのエッジ ケースは、寮の最後の部屋に正確に到達するクエリを処理することです。 たとえば、累積合計が次の場合、`[10, 25, 37]`、次にクエリ`10`2 番目の寮ではなく、1 番目の寮にマッピングする必要があります。 ここで、厳密な不平等と非厳密な不平等が重要になります。 

## アプローチ

 ブルートフォース戦略では、寮内を歩き回り、残りのインデックスが寮内に収まるまで部屋数を差し引くことで、各クエリを個別に処理します。 単一のクエリの場合、これは O(n) です。 m 回のクエリを超えると、これは O(nm) になり、最悪の場合、4×10¹⁰ の操作に達し、実行不可能になります。 

問題の構造は、累積的な視点を示唆しています。 寮のサイズの接頭辞の合計を計算すると、各寮は数直線上の連続した区間に対応します。 各クエリは点の位置の問題になります。つまり、クエリ値以上の最初のプレフィックスの合計を見つけます。 

これはまさに単調配列に対する二分探索です。 プレフィックスの合計は厳密に増加しているため、クエリごとに O(log n) で正しい寮を見つけることができます。 寮のインデックスを見つけた後、前のプレフィックスの合計を減算することでローカルの部屋番号が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | プレフィックス合計 + 二分検索 | O(m log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各位置がその寮の最後のグローバルインデックスを表すように、寮のサイズのプレフィックスの合計を計算します。 これにより、問題は構造を反復するのではなく、範囲の検索に変換されます。 
2. 各クエリ値について`x`、プレフィックス合計配列に対して二分検索を実行して、最小のインデックスを見つけます。`i`そのような`prefix[i] >= x`。 これにより、その部屋が含まれる寮が特定されます。`x`累積間隔内にあります。 
3. 寮に入ると`i`が見つかったら、ローカル ルーム インデックスを計算します。 もし`i`が最初の寮です、答えは簡単です。`x`。 それ以外の場合は減算します`prefix[i-1]`から`x`。 
4. 出力`(i + 1, local_index)`寮のインデックスは 1 であるためです。 

重要な推論ステップは、各寮が数直線上の連続したセグメントを占めているため、部屋を見つけることは、どのセグメントに点が含まれているかを見つけることと同じであるということです。 

### なぜ効果があるのか

 プレフィックス合計配列は、グローバル番号付けを素の連続した間隔に分割し、各間隔は 1 つの寮に正確に対応します。 プレフィックスの合計は厳密に増加しているため、各クエリ値は正確に 1 つの間隔に分類されます。 二分探索では単調性を利用してその区間を見つけ、前の境界を減算すると区間内の正しいオフセットが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    prefix = []
    s = 0
    for x in a:
        s += x
        prefix.append(s)

    import bisect

    out = []
    for x in b:
        i = bisect.bisect_left(prefix, x)
        prev = prefix[i - 1] if i > 0 else 0
        out.append(f"{i + 1} {x - prev}")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、単一パスでプレフィックス合計を構築します。 重要な実装の詳細は、`bisect_left`、クエリ以上の最初のプレフィックスの合計を見つけます。 これにより、境界値が正しく処理されます。クエリがプレフィックスの合計と正確に等しい場合でも、次の寮ではなく、対応する寮にマッピングされます。 

減算ステップでは、負のインデックス付けを避けるために最初のドミトリーに条件を付けて、前のプレフィックスの合計を慎重に使用します。 ここで、多くの誤った解決策は、境界ケースを常に減算するか完全に忘れることによって失敗します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、クエリがプレフィックスの合計と正確に等しい場合です。 たとえば、寮のサイズが次の場合、`[4, 6]`、プレフィックスは`[4, 10]`、クエリは`4`。 二分検索はインデックスを返します`0`、ローカルインデックスは次のようになります`4 - 0 = 4`、最初の寮の最後の部屋に正しくマッピングされています。 

もう 1 つのエッジ ケースは、クエリが最後のドミトリーに該当する場合です。 プレフィックス付き`[4, 10]`そしてクエリ`9`、バイナリ検索はインデックスを返します`1`、その前にプレフィックス`4`、ローカルインデックスは次のようになります`5`、第 2 寮を正しく識別します。 

これらの事例は、各寮をプレフィックス境界上の閉じた間隔として扱うことと、`bisect_left`正確で安定した分類が得られます。
