 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、1 ずつ減らすか、1 増やすか、変更しないかを選択することで、各要素を個別にわずかに「微調整」することができます。 これらの微調整を適用した後、結果のシーケンスが等差数列を形成するようにします。これは、連続する要素間の差が配列全体で一定になることを意味します。 

目標は、これが可能かどうかを判断するだけではなく、実際に変更する位置の数を最小限に抑えることです。 位置に +1 または -1 を適用すると、その位置は変更されたものとしてカウントされます。 変更せずに放置しておいても費用はかかりません。 

重要な問題は、各要素に 3 つの可能な最終値があるため、すべての変更されたシーケンスの空間が指数関数的であるという事実にあります。 最大 100,000 個の要素があるため、すべての調整の組み合わせを総当たりで実行することは不可能です。 

制約について考えるのに役立つ方法は、有効な解決策は 2 つのパラメーター (変更後の最初の要素と共通の差分) によって完全に決定されるということです。 これらが修正されると、すべての要素のターゲット値が強制されます。 残された唯一の自由は、各位置が元の値と一致するか、ターゲットと一致するために 1 つだけシフトする必要があるかを選択することです。 

変更を加えても有効な等差数列を形成できない場合、微妙なエッジ ケースが発生します。 たとえば、必要な差異により、ある要素が元の値から 1 単位以上離れなければならない場合、その候補数列は無効になります。 もう 1 つのエッジ ケースは、長さが 1 または 2 のシーケンスです。この場合、値は常に等差数列を形成するため、答えは常に 0 になります。 

## アプローチ

 ブルートフォースアプローチでは、可能な調整のあらゆる組み合わせが試行されます。つまり、すべての要素が 3 つの状態のいずれかになります。 これは 3^n 通りの可能性をもたらしますが、n が 100,000 までの場合はまったく実現不可能です。 

より構造化された総当たり攻撃は、等差数列が最初の 2 つの要素によって定義されることを観察することです。 最初の 2 つの位置の調整された値を推測すると、シーケンスの残りの部分が強制されます。 最初の 2 つのポジションにはそれぞれ 3 つのオプションがあるため、先発ペアの候補は 9 つだけです。 各ペアについて、必要な共通差分を伝播し、すべての要素が元の値の ±1 以内で一致するかどうかを確認します。 

これにより、問題は一定数のリニア スキャンに軽減されます。 重要な洞察は、最初の項と差が固定されると、他のすべての項が一意に決定されるため、組み合わせを探索するのではなく、一貫性を検証するだけであるということです。 

検証中、各ポジションは 0 コスト (すでに正しい場合) または 1 コスト (±1 で調整する必要がある場合) のいずれかに寄与します。 いずれかの位置がターゲットから 1 を超えて離れている場合、その候補の進行は無効になります。

 ## アルゴリズムのチュートリアル

 私たちは、等差数列は最初の 2 つの値によって一意に決定されるという事実に依存しています。 

### ステップ

 1. 最初の要素の候補値を抽出します。$b_0 - 1, b_0, b_0 + 1$。 2 番目の要素に対しても同じことを行います。 これらは最大 9 つの開始構成を定義します。 

各構成は、位置 0 と 1 の調整値の可能な選択を表します。 
2. 各候補ペアについて$(x_0, x_1)$、共通の差を計算します$d = x_1 - x_0$。 

このステップが必要なのは、最初の 2 つの項が固定されると、後のすべての項がこの正確な違いに従う必要があるためです。 
3. 必要な変更に備えてカウンターを初期化します。 もし$x_0 \neq b_0$、1つ追加します。 もし$x_1 \neq b_1$、1つ追加します。 

これは、最初の 2 つの位置で ±1 の調整を使用したかどうかを説明します。 
4. 配列の残りの部分を繰り返し処理します。 インデックスごとに$i \ge 2$、必要な値を計算します。$$target_i = x_0 + i \cdot d$$5. 各ポジションの実現可能性を確認します。 

もし$|b_i - target_i| > 1$、この候補は不可能であり、すぐに破棄する必要があります。 

それ以外の場合は、$b_i \neq target_i$、変更カウンタをインクリメントします。 
6. すべての有効な候補ペアにわたる最小コストを追跡します。 
7. 有効な候補ペアがない場合は、-1 を返します。 それ以外の場合は、最小コストを返します。 

### なぜ効果があるのか

 すべての有効な最終シーケンスは等差数列である必要があるため、何らかの最初の項と共通の差がなければなりません。 各要素は最大 1 つずつ変更できるため、実際の最初の 2 つの要素はセット内に存在する必要があります。$\{b_0-1, b_0, b_0+1\}$そして$\{b_1-1, b_1, b_1+1\}$。 Therefore every valid solution is covered by one of the 9 candidate starting pairs.

 Once a pair is fixed, the rest of the sequence has no freedom. Any deviation from the original array contributes exactly one cost, and any deviation greater than one makes the candidate impossible. This guarantees we neither miss valid solutions nor accept invalid ones.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = list(map(int, input().split()))

    if n <= 2:
        print(0)
        return

    INF = 10**18
    ans = INF

    for a0_delta in (-1, 0, 1):
        for a1_delta in (-1, 0, 1):
            x0 = b[0] + a0_delta
            x1 = b[1] + a1_delta

            d = x1 - x0
            cost = 0

            if x0 != b[0]:
                cost += 1
            if x1 != b[1]:
                cost += 1

            ok = True

            for i in range(2, n):
                expected = x0 + i * d
                diff = b[i] - expected

                if abs(diff) > 1:
                    ok = False
                    break

                if diff != 0:
                    cost += 1

            if ok:
                ans = min(ans, cost)

    print(-1 if ans == INF else ans)

if __name__ == "__main__":
    solve()
```この実装では、最初の 2 つの要素の有効な初期摂動をすべて明示的に列挙します。 シーケンスの残りの部分は、候補ごとに 1 回のパスで検証されます。 コストの計算は、各要素がすでにターゲットと等しいか、±1 の調整が必要かどうかに直接関係します。 

よくある落とし穴は、絶対差を使用して実現可能性をチェックする必要があることを忘れていることです。 もう 1 つは、最初の 2 つの値を修正せずに差分を増分的に再計算するという誤った方法であり、これにより伝播に一貫性がなくなる可能性があります。

def run(inp: str) -> str:

    from math import inf

    n = int(input())
    b = list(map(int, input().split()))

    if n <= 2:
        return "0"

    INF = 10**18
    ans = INF

    for a0 in (-1,0,1):
        for a1 in (-1,0,1):
            x0 = b[0] + a0
            x1 = b[1] + a1
            d = x1 - x0

            cost = (a0 != 0) + (a1 != 0)
            ok = True

            for i in range(2, n):
                expected = x0 + i*d
                diff = b[i] - expected
                if abs(diff) > 1:
                    ok = False
                    break
                if diff != 0:
                    cost += 1

            if ok:
                ans = min(ans, cost)

    return "-1" if ans == INF else str(ans)

## 特殊なケース

 重要なエッジ ケースは、最適解が元の 1 番目または 2 番目の値を使用しない場合です。 たとえば、両方を ±1 だけシフトすると有効な進行が作成されるが、それらを固定したままでは有効な進行が作成されない場合でも、アルゴリズムはそれらの候補を探索する必要があります。 (b0±1, b1±1) が常に含まれるため、9 つの開始状態すべてを列挙すると、これがカバーされることが保証されます。 

もう 1 つのエッジ ケースは、初期のポジションが有効に見えても、後のポジションが ±1 許容誤差を超えている場合に発生します。 このような場合、アルゴリズムは、後で不一致を貪欲に「修正」しようとするのではなく、候補全体を即座に拒否する必要があります。 絶対差分チェックではこれが厳密に適用され、誤った部分受け入れが防止されます。 

最後に、長さ 1 または 2 のシーケンスは、任意の 2 つの数値が常に等差数列を形成するため、すべてのロジックをバイパスします。
