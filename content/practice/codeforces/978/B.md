 ## 解決策
 ## 問題の理解

 ファイル名を表す短い文字列が与えられます。 重要な唯一の制約は、部分文字列が`"xxx"`最後の文字列内のどこでも禁止されています。 任意の位置から文字を削除することができますが、3 つ連続しないようにできるだけ少ない文字を削除したいと考えています。`'x'`結果の文字列には文字が残ります。 

したがって、このタスクは 1 つの文字列に対する最小化問題です。連続した文字列の実行をすべて中断する必要があります。`'x'`できるだけ少ない文字を削除しながら、ランの長さが 3 以上になるように文字を削除します。 

入力サイズは小さく、文字列の長さは最大でも 100 です。これは、線形スキャンまたはもう少し複雑な貪欲ロジックでも十分であることをすぐに示唆しています。 たとえ$O(n^2)$このアプローチは問題なく通過しますが、問題の構造は、単一パスの貪欲な解決策で十分であることを強く示しています。 

素朴だが重要な観察は、実行範囲外の削除は、`'x'`この制約には決して役に立ちません。 連続したシーケンスのみ`'x'`禁止されたパターンは完全に文字から来ている必要があるため、文字が重要です。 

いくつかの特殊なケースは概念的に重要です。 

1 つのケースは次のような文字列です`"xx"`または`"axxa"`。 長さ 3 のランがないため、削除する必要はありません。正解は 0 です。 

もう一つのケースは、`"xxx"`。 ランを中断するには少なくとも 1 文字を削除する必要があるため、答えは 1 です。 

少し長めのケースのような`"xxxx"`結果として生じるランを減らすには、少なくとも 1 文字を削除する必要があります。`'x'`たとえば、1 文字を削除すると次のようになります。`"xxx"`, しかし、それでも無効であるため、少なくともあと 1 つ削除する必要があり、答えは 2 になります。 

かどうかを確認するだけで不注意なアプローチは失敗することがよくあります。`"xxx"`長い実行を考慮せずに、どこかに 1 文字を削除します。 これは長さが 3 の場合は機能しますが、長さが 4 以上の場合はすぐに中断されます。 

## アプローチ

 ブルート フォース ソリューションでは、削除する位置のすべてのサブセットを試し、結果の文字列を再構築し、その文字列に次のものが含まれているかどうかを確認します。`"xxx"`。 これは正しいですが、一般的には完全に実行不可能です。$2^n$サブセット。$n = 100$天文学的に大きいです。 

制約の構造により、問題はローカルになります。つまり、連続したブロックのみです。`'x'`案件。 削除をグローバルに考える代わりに、文字列を左から右に処理し、連続する各最大セグメントを処理できます。`'x'`独立して。 

のブロックの中に$k$連続した`'x'`文字が残っている場合は、最大 2 文字が残るようにしたいと考えています。 もし$k \le 2$、何も削除する必要はありません。 もし$k \ge 3$、正確に削除する必要があります$k - 2$2 文字以上保持すると条件に違反し、2 文字未満を保持すると削除が不必要に増加するだけであるためです。 

重要な洞察は、1 つのブロック内の削除が他のブロックに影響を与えないということです。 したがって、最適な戦略は、単純に、実行ごとに 2 を超える超過を合計することです。`'x'`。

 ## アルゴリズムのチュートリアル

 連続した追跡中に文字列を 1 回スキャンします`'x'`文字。 

1. 答えのカウンターと、現在のランレングスを追跡する変数を初期化します。`'x'`。 このランレングスは、連続する回数を表します。`'x'`これまで見てきたキャラクター。 
2. 文字列を 1 文字ずつ繰り返します。 
3. 現在のキャラクターが`'x'`、ランレングスを増加させます。 これにより、現在のブロックが拡張されます。 
4. 現在のキャラクターがそうでない場合`'x'`、前のブロックを終了します。 ランレングスが少なくとも 3 の場合、次を追加します。`run_length - 2`答えは2つだけなので`'x'`キャラクターはルールに違反せずに残ることができます。 次に、ランレングスをゼロにリセットします。 
5. ループの終了後、文字列が次で終わる場合は、最後のブロックを処理する必要があります。`'x'`。 同じルールが適用されます。2 回を超える実行が寄与します。`run_length - 2`削除。 

これが機能する理由は、構造的不変条件に基づいています。すべての時点で、連続したすべての完了した実行で必要な削除が完全に考慮されています。`'x'`文字、および他の文字と相互作用する実行はありません。 禁止パターンは隣接関係のみに依存し、1 つのブロック内の削除によって別のブロックに違反が発生したり修正されたりすることはないため、各ブロックは独立しています。 したがって、ローカル最適修正を合計すると、グローバル最適が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
s = input().strip()

ans = 0
run = 0

for ch in s:
    if ch == 'x':
        run += 1
    else:
        if run >= 3:
            ans += run - 2
        run = 0

# finalize last run
if run >= 3:
    ans += run - 2

print(ans)
```実装では単一の実行カウンタが維持されます。`run`連続して`'x'`文字。 重要な詳細は、ループ後の最後のフラッシュです。これは、文字列がで終わるためです。`'x'`そうしないと、最後のセグメントが未処理のままになります。 

よくある間違いは、この最後のステップを忘れることです。これにより、文字列が長いシーケンスで終了するときに過小数カウントが発生します。`'x'`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input().strip())
    s = input().strip()

    ans = 0
    run_len = 0

    for ch in s:
        if ch == 'x':
            run_len += 1
        else:
            if run_len >= 3:
                ans += run_len - 2
            run_len = 0

    if run_len >= 3:
        ans += run_len - 2

    return str(ans)

# provided samples
assert run("6\nxxxiii\n") == "1"

# custom cases
assert run("3\nxxx\n") == "1"
assert run("4\nxxxx\n") == "2"
assert run("5\naxxxa\n") == "1"
assert run("2\nxx\n") == "0"
assert run("7\nxxxxxxx\n") == "5"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`"xxx"`|`1`| 最低限の禁止事項 |
 |`"xxxx"`|`2`| 長時間の実行の処理 |
 |`"axxxa"`|`1`| 内部ブロックの処理 |
 |`"xx"`|`0`| 削除は必要ありません |
 |`"xxxxxxx"`|`5`| 大きな実行の正確性 |

 ## 特殊なケース

 のような文字列の場合`"axxxxa"`、アルゴリズムは 4 つの内部実行を分離します。`'x'`文字。 スキャンするとランレングス 4 が構築され、ランレングスが 4 に達するとリセットされます。`'a'`、追加`4 - 2 = 2`答えに。 周囲`'a'`文字は計算に影響しません。 

のために`"xxxxxxx"`、実行は 7 まで増加し、最後にのみ処理されます。 最後のフラッシュは追加します`7 - 2 = 5`、最悪の場合の連続ブロックを正しく処理します。 

どちらの場合も、それぞれの最大値が以下であるという不変条件が確認されます。`'x'`セグメントは、最小限の削除で、独立して最大 2 の長さに短縮されます。
