 ## 解決策
 ## 問題の理解

 整数のシーケンスが与えられ、重複を削除してそれを圧縮するように求められますが、特定のルールがあります。つまり、すべての個別の値について、配列内で最後に出現した値のみが残される必要があります。 最終出力は、単なる一意の値のセットではなく、元のシーケンスのフィルタリングされたバージョンであり、繰り返しの数値の以前の出現が消え、最後の出現は所定の位置に残ります。 

重要な制約は、配列サイズが最大 50 であることです。これにより、パフォーマンスの問題が即座に排除されます。 各要素を他のすべての要素と比較してチェックするアプローチであっても、合計操作数は最悪でも数千回程度になるため、制限時間内で十分に実行できるでしょう。 これは、最適化のプレッシャーではなく、明確さと正確さに完全に集中できることを意味します。 

このタイプの問題における微妙な問題は、「最後の出現を保持する」ことが方向に依存することです。 最初に値を確認した時点を保持する単純な前方スキャンでは、間違った答えが生成されます。 たとえば、配列では`[1, 2, 1]`、最初の出現の収量を維持する`[1, 2]`ですが、正しい出力は次のとおりです。`[2, 1]`なぜなら二番目だから`1`残らなければならないものです。 インデックスのシフトによって後の要素がスキップされたり、誤って処理されたりする可能性があるため、前方スキャン中にオンザフライで要素を削除すると、別の失敗ケースが発生します。 たとえば、次の重複を削除します。`5`で`[5, 5, 6]`左から右への反復中に、実装によっては誤ってチェックをスキップする可能性があります。 

正しい推論は「右端の出現」の概念に基づいている必要があります。これは本質的に、最初ではなく最後からスキャンする場合に推論するのが簡単です。 

## アプローチ

 ブルートフォース戦略では、各要素を考慮し、右側に検索して、再度出現するかどうかを判断します。 後で表示されない場合は、そのまま保持します。 それ以外の場合は破棄します。 これは、「最後の出現」の定義を直接エンコードしているため、論理的には正しいです。 ただし、それぞれについて、`n`要素をスキャンする場合があります。`n`順位が先行し、最悪の場合の複雑さは約`n^2`小切手。 

その間`n ≤ 50`実際にはこれは簡単ですが、問題の構造はより洗練されたアプローチを示唆しています。 前方への検索を繰り返す代わりに、視点を逆にすることができます。配列を右から左に処理しながら、すでに含まれている値を記録します。 この逆方向の走査で最初に値が検出されるのは、元の配列でその値が最後に出現したときです。 この観察により、スキャンを繰り返す必要がまったくなくなりました。 

私たちは一連の目に見える価値を維持します。 配列の末尾から先頭に移動するとき、以前に存在したことのない要素のみを取得します。 これにより、各値がその最後の出現に対応する時点で 1 回だけ追加されることが保証されます。 逆の順序で結果を収集した後、それを逆に戻して正しい出力順序を復元します。

 ## アルゴリズムのチュートリアル

 配列の末尾からスキャンして、最後に出現した各値を最初に検出することで答えを作成します。 

1. 配列の最後の要素から開始して、最初の要素に向かって左に移動します。 この方向により、最初に値が表示されるのは、元のシーケンスの右端にある値になります。 
2. すでに結果に含まれている値を保存するセットを維持します。 このセットは、最後に出現した値がすでに考慮されているすべての値を表します。 
3. 逆方向スキャン中に各要素について、それがすでにセット内にあるかどうかを確認します。 

存在しない場合は、現在その最後の出現箇所にいることを意味するため、それを結果に追加してセットに挿入します。 
4. 要素がすでにセット内にある場合は、その最後の出現がスキャンの早い段階で検出されたため、その要素をスキップします。 
5. 逆方向の走査が完了すると、収集された結果は目的の出力に対して逆の順序になっているため、印刷する前に一度逆にしてください。 

### なぜ効果があるのか

 不変条件は、逆方向スキャン中のどの時点でも、元の配列の右端に出現する値がすでに処理および格納されている値をセットに正確に含むということです。 右から左にトラバースするため、最初に値が見つかったときは、元の配列の最後の位置に正確に対応します。 これにより、各値が 1 回だけ追加され、最終的に出現する前には追加されないことが保証されます。 収集されたシーケンスを逆にすると、最後に出現したシーケンスの間で元の相対的な順序が復元されます。これは、逆方向トラバーサルでの順序が元の配列での順序の逆であるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    seen = set()
    res = []
    
    for i in range(n - 1, -1, -1):
        if a[i] not in seen:
            seen.add(a[i])
            res.append(a[i])
    
    res.reverse()
    
    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```ソリューションは配列を読み取り、右から左に繰り返します。 の`seen`set は、この逆方向の走査で各値が最初に出現したときのみを保持することを保証します。これは、元の配列で最後に出現した値に対応します。 結果リストは逆の順序で構築されるため、最終的に反転すると正しい出力順序が復元されます。 

唯一の微妙な実装の詳細は、反転ステップが必須であることです。 これがないと、出力では要素が最後に出現した順序で右から左にリストされますが、これは必須の形式ではありません。

 ## 特殊なケース

 次のような単一要素配列の場合`[7]`、逆スキャンによりすぐに追加されます`7`目に見えないものだからこそ結果につながる。 これ以上の要素は存在しないため、出力は残ります。`[7]`これは、単一の値がそれ自身の最後の出現であるという要件に一致します。 

すべての要素が同一である配列の場合、次のようになります。`[1, 1, 1, 1]`、逆方向スキャンにより追加されます`1`最後の位置にあり、それより前に出現したものはすべてスキップされます。`seen`セット。 結果には要素が 1 つだけ含まれます。これは、右端の要素のみが残される必要があるため、正しいものです。 

次のような厳密に増加する配列の場合`[1, 2, 3, 4]`、すべての要素は、後方スキャン中にその唯一の出現時に最初に検出されるため、すべてが含まれます。 逆にすると、元の順序が変更されずに復元され、アルゴリズムによって要素が不必要に削除されないことが確認されます。
