 ## 解決策
 ## 問題の理解

 以下からなるストライプが与えられています。`n`それぞれが整数を含む正方形。 タスクは、各セグメントの数値の合計が同一になるように、このストライプを 3 つの連続する空ではないセグメントに分割することです。 出力は、これらのカットを実行する有効な方法の数です。 各カットは正方形の間に発生し、すべてのセグメントには少なくとも 1 つの正方形が含まれている必要があります。 

入力制約から分かることは、`n`は 100,000 まで大きくなり、各正方形の数は絶対値で 10,000 まで大きくなります。 このサイズでは、カット位置のすべてのトリプレットを明示的にチェックするアプローチは実行不可能です。 O(n²) 解では最悪の場合、約 100 億回の演算が必要となり、1 秒の時間制限を超えるため、線形または線形解が必要です。 

明らかではないエッジケースには、ストライプの合計が 3 で割り切れない状況が含まれます。 たとえば、次の入力を考えてみましょう。```
3
1 2 3
```合計は 6 で、3 で割り切れますが、正の長さのセグメントが必要です。 唯一可能なカットはセグメントを生成することです`[1]`、`[2]`、`[3]`合計は 1、2、3 です。合計が等しくないため、正しい出力は 0 です。セグメントの長さを指定せずに割り算だけをチェックする単純な解決策では、誤った解決策が報告される可能性があります。 もう 1 つのエッジ ケースは、すべての数値が 0 である場合です。```
5
0 0 0 0 0
```ここで、任意の 2 つのカットは合計 0 のセグメントを生成するため、複数の有効なカット ペアが存在します。 

## アプローチ

 ブルートフォースアプローチでは、カット位置のすべてのペアが考慮されます。`(i, j)`どこ`i < j`、結果として得られる 3 つのセグメントの合計を計算し、それらが等しいかどうかを確認します。 これは問題定義を直接実装しているため機能しますが、時間的には O(n²) です。 のために`n = 10^5`、これはおよそ 5 * 10^9 のチェックを必要とし、これでは遅すぎます。 

最適化する上で重要な点は、各セグメントの特定の内容ではなく、セグメントの合計のみを考慮するということです。 させて`total`すべての数値の合計になります。 もし`total`たとえば、3で割り切れます`total = 3*S`の場合、各セグメントの合計は次のようになります。`S`。 その後、プレフィックスの合計を維持しながら、最初から繰り返すことができます。 プレフィックスの合計が等しくなるたびに、`S`、これは最初のセグメントの潜在的な終了を表します。 次に、2 番目のカットを配置する有効な方法の数は、プレフィックスの合計が次の値に達した回数によって決まります。`2*S`この位置以降、最後のセグメントは自動的に次のように合計されるため、`S`。 これらの発生を 1 回のパスでカウントすることで、複雑さを O(n) に軽減します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ストライプ内のすべての数値の合計を計算します。 この合計が 3 で割り切れない場合は、0 を出力します。それ以外の場合、3 つの等和セグメントは存在できません。 
2. しましょう`S = total / 3`。 2 つの変数を初期化します。`count_s`以下に等しいプレフィックスの合計の出現をカウントします。`S`そして`ways`有効な分割数を累積します。 
3. 現在のプレフィックス合計を維持しながら、ストライプを反復処理します。 先に進むにつれて、各要素がプレフィックスの合計に追加されます。 
4. プレフィックスの合計が等しい場合`2*S`、これは 2 番目のセグメントの潜在的な終了を示します。 追加`count_s`に`ways`なぜなら、以前に出現したプレフィックスの合計は次の値に等しいからです。`S`は有効な最初のセグメントを表します。 
5. プレフィックスの合計が等しい場合`S`、増分`count_s`この潜在的な最初のセグメントのエンドポイントを記録します。 
6. すべての要素を処理した後 (最後の正方形を除く。2 番目または 3 番目のセグメントの開始にはなりません)、`ways`有効な分割の合計数が含まれます。 

なぜ機能するのか: 不変条件は次のとおりです`count_s`現在のインデックスの前の最初のセグメントのカット ポイントの数を追跡します。 累計が達したとき`2*S`、その前にできる最初のカットの数によって、2 番目のカットを行うための有効な方法の数が直接決まります。 これにより、二重カウントや組み合わせの欠落が回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

total = sum(a)
if total % 3 != 0:
    print(0)
    sys.exit()

S = total // 3
prefix_sum = 0
count_s = 0
ways = 0

# iterate until the second-to-last element
for i in range(n - 1):
    prefix_sum += a[i]
    if prefix_sum == 2 * S:
        ways += count_s
    if prefix_sum == S:
        count_s += 1

print(ways)
```コードは最初に 3 で割り切れるかどうかをチェックし、割り切れない場合は早期に終了します。 このループでは最後の四角形が除外されます。これは、その後にセグメントを開始できないためです。 実行中のプレフィックス合計と 2 つのカウンターを維持し、off-by-one エラーを避けるために正確な順序で更新します。 インクリメント`ways`更新する前に`count_s`現在の正方形を最初のカットと 2 番目のカットの両方として考慮しないようにします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    total = sum(a)
    if total % 3 != 0:
        return "0"
    S = total // 3
    prefix_sum = 0
    count_s = 0
    ways = 0
    for i in range(n - 1):
        prefix_sum += a[i]
        if prefix_sum == 2 * S:
            ways += count_s
        if prefix_sum == S:
            count_s += 1
    return str(ways)

assert run("4\n1 2 3 3\n") == "1", "sample 1"
assert run("5\n0 0 0 0 0\n") == "6", "all zeros"
assert run("3\n1 2 3\n") == "0", "sum not divisible by 3"
assert run("3\n1 1 1\n") == "1", "minimal equal segments"
assert run("6\n1 2 3 0 3 0\n") == "2", "multiple valid splits"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 4\n1 2 3 3 | 1 | 標準サンプル |
 | 5\n0 0 0 0 0 | 6 | すべてゼロ、複数の分割 |
 | 3\n1 2 3 | 0 | 合計は 3 で割り切れますが、セグメントは等しくない |
 | 3\n1 1 1 | 1 | 等しいセグメントを形成する正方形の最小数 |
 | 6\n1 2 3 0 3 0 | 2 | 複数の有効なカット、カウントロジックをチェック |

 ## 特殊なケース

 もし`total`は 3 で割り切れません。`[1, 2, 3]`の場合、アルゴリズムは直ちに 0 を出力し、不必要な計算を回避します。 

すべてゼロのストライプの場合`[0, 0, 0, 0, 0]`、アルゴリズムは、次の複数の出現をカウントします。`S = 0`
