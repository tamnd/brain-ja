 ## 解決策
 ## 問題の理解

 各入力行は、平面内の幾何学的オブジェクトを記述します。 方程式$$Ax + By + C = 0$$線を表します。 タスクは、両方のラインに同時に属するポイントの数を決定することです。 

2 本の異なる非平行線がちょうど 1 点で交差します。 2 本の平行だが別個の線は決して交わることはありません。 2 本の同一の線は完全に重なっているため、無限に多くの点を共有します。 出力形式はこれに直接続きます。 

- 印刷する`1`線が一度交差すると、
 - 印刷する`0`それらが決して交わらない場合、
 - 印刷する`-1`それらが実際に同じ行である場合。 

制約は小さく、係数は次の間のみです。`-100`そして`100`。 ここでの課題はパフォーマンスではありません。 問題全体は、すべての幾何学的ケースを正しく処理し、比例係数の間違いを回避することに関するものです。 

危険なのは、「平行」と「同一」を区別することです。 単純な実装では、傾きを比較するだけかもしれません。 これは平行性の検出には機能しますが、方程式がまったく同じ直線を記述しているかどうかはわかりません。 

次の入力を考えてみましょう。```
1 1 0
2 2 0
```2 番目の方程式は、最初の式に次の値を掛けただけです。`2`, したがって、どちらも同じ行を記述します。 正しい答えは次のとおりです。```
-1
```行列式がゼロかどうかだけをチェックする不注意な実装では、誤って出力されてしまいます。`0`。 

もう 1 つの注意が必要なケースは、1 組の係数が比例的に一致するが、定数項が一致しない場合です。```
1 1 1
2 2 3
```方向ベクトルは比例するため、線は平行になります。 ただし、定数は同じ係数でスケールされないため、これらは別個の平行線になります。 正しい出力は次のとおりです。```
0
```バグのある等価性チェックにより、それらが誤って同一であると分類される可能性があります。 

ゼロ係数を含む微妙なエッジ ケースもあります。```
0 1 0
0 2 0
```これらの方程式は次のようになります。$$y = 0$$そして$$2y = 0$$繰り返しますが、それらは同じ行ですが、`A = 0`。 ここで、除算に基づくソリューションはクラッシュしたり、精度が失われたりする可能性があります。 整数の相互乗算はそれを完全に回避します。 

## アプローチ

 強引なアイデアは、線形システムを明示的に解き、結果を検査することです。 2 つの方程式の場合:$$A_1x + B_1y + C_1 = 0$$

$$A_2x + B_2y + C_2 = 0$$行列式を計算できます。$$D = A_1B_2 - A_2B_1$$もし`D ≠ 0`、システムには独自のソリューションがあるため、答えは次のようになります。`1`。 

もし`D = 0`、線は平行です。 この時点でも、「同じ行」と「異なる行」を区別する必要があります。 1 つの方法は、浮動小数点演算を使用して比率を求めることです。 これは理論的には機能しますが、ゼロ除算や精度の問題がすぐに現れるため、不必要に脆弱です。 

重要な点は、同一の線にはすべての係数が比例する必要があるということです。$$\frac{A_1}{A_2} = \frac{B_1}{B_2} = \frac{C_1}{C_2}$$分割する代わりに、製品を比較します。$$A_1B_2 = A_2B_1$$

$$A_1C_2 = A_2C_1$$

$$B_1C_2 = B_2C_1$$これにより、浮動小数点エラーが完全に回避され、ゼロが自然に処理されます。 

問題は、行列式と比例性に基づいた小規模なケース分析になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 浮動小数点比率を使用したブルート フォース | お(1) | お(1) | リスクのある実装 |
 | 最適な整数決定式のチェック | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのラインを表す 6 つの係数を読み取ります。 
2. 行列式を計算します。$$D = A_1B_2 - A_2B_1$$もし`D ≠ 0`、線は平行ではないため、正確に 1 点で交差します。 印刷する`1`。 

1. もし`D = 0`、線は平行または同一です。 ここで、すべての係数が比例しているかどうかを確認します。 
2. 比較します:$$A_1C_2 = A_2C_1$$そして$$B_1C_2 = B_2C_1$$決定要因チェックにより、以下がすでに保証されています。$$A_1B_2 = A_2B_1$$したがって、これらの追加の比較は、完全な比例性を検証するのに十分です。 

1. 両方の比例性チェックが成立する場合、方程式は同じ直線を表します。 印刷する`-1`。 
2. それ以外の場合、線は平行ですが明確です。 印刷する`0`。 

### なぜ効果があるのか

 行列式は、2 つの直線の方向ベクトルが線形独立であるかどうかを示します。 非ゼロの行列式は、線が 1 回交差する必要があることを意味します。 

行列式が 0 の場合、両方の線は同じ方向を持ち、まったく交わらないか、完全に一致します。 一方の方程式が他方の方程式に定数を乗じることによって得られる場合、2 つの線形方程式は同じ幾何学的な直線を正確に記述します。 相互乗算は除算を行わずにこの比例性をチェックするため、ゼロ係数とゼロ以外の係数の考えられるすべての組み合わせが安全に処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a1, b1, c1 = map(int, input().split())
a2, b2, c2 = map(int, input().split())

det = a1 * b2 - a2 * b1

if det != 0:
    print(1)
else:
    same = (
        a1 * c2 == a2 * c1 and
        b1 * c2 == b2 * c1
    )

    if same:
        print(-1)
    else:
        print(0)
```最初の部分では、係数行列の行列式を計算します。 これは、`2 × 2`リニアシステムには独自のソリューションがあります。 

行列式がゼロ以外の場合、答えはすぐに次のようになります。`1`, 線が一度交差しているためです。 

2 番目のブランチは並列ケースを処理します。 係数を除算して比率を比較する代わりに、実装では整数の乗算が使用されます。 係数はゼロになる可能性があるため、これは重要です。 たとえば、比較すると、`a1 / a2`次の場合に無効になります`a2 = 0`。 

比例チェックは正確な整数等価として記述されるため、浮動小数点の精度の問題はありません。 すべての値が小さいため、Python ではオーバーフローはほとんど発生しませんが、同じ方法はこれらの制限に対して C++ でも安全です。

-1
```この例は、行列式だけをチェックするだけでは不十分である理由を示しています。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    a1, b1, c1 = map(int, input().split())
    a2, b2, c2 = map(int, input().split())

    det = a1 * b2 - a2 * b1

    if det != 0:
        print(1)
    else:
        same = (
            a1 * c2 == a2 * c1 and
            b1 * c2 == b2 * c1
        )

        if same:
            print(-1)
        else:
            print(0)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("1 1 0\n2 2 0\n") == "-1\n", "sample 1"

# intersecting lines
assert run("1 -1 0\n1 1 -4\n") == "1\n", "unique intersection"

# parallel but distinct
assert run("1 1 1\n2 2 3\n") == "0\n", "parallel lines"

# zero coefficients, same line
assert run("0 1 0\n0 2 0\n") == "-1\n", "horizontal line scaling"

# maximum magnitude coefficients
assert run("100 -100 50\n-100 -100 0\n") == "1\n", "boundary coefficients"

# vertical parallel lines
assert run("1 0 -1\n2 0 -3\n") == "0\n", "distinct vertical lines"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1 0 / 2 2 0`|`-1`| 同じ行 |
 |`1 -1 0 / 1 1 -4`|`1`| ユニークな交差点 |
 |`1 1 1 / 2 2 3`|`0`| 平行だけど違う |
 |`0 1 0 / 0 2 0`|`-1`| ゼロ係数は安全に処理されます。 
|`100 -100 50 / -100 -100 0`|`1`| 境界係数値 |
 |`1 0 -1 / 2 0 -3`|`0`| 垂直平行線 | 写真

 ## 特殊なケース

 両方の方程式が同じ水平線を表す場合を考えてみましょう。```
0 1 0
0 2 0
```行列式は次のようになります。$$0 \cdot 2 - 0 \cdot 1 = 0$$したがって、線は平行または同一になります。 比例性チェックにより次のことがわかります。$$0 \cdot 0 = 0 \cdot 0$$そして$$1 \cdot 0 = 2 \cdot 0$$どちらも true なので、アルゴリズムは次のように出力します。`-1`。 ここでは部門ベースのアプローチは簡単に失敗する可能性があります。`A_1 = A_2 = 0`。 

次に、明確な平行線を調べます。```
1 1 1
2 2 3
```行列式は再びゼロになります。$$1 \cdot 2 - 2 \cdot 1 = 0$$しかし、比例性チェックは失敗します。$$1 \cdot 3 \neq 2 \cdot 1$$アルゴリズムは正しく印刷します`0`。 これにより、「同じ方向」と「同じライン」が区別されます。 

最後に、交差する垂直線と水平線を考慮します。```
1 0 -2
0 1 -3
```決定要因は次のとおりです。$$1 \cdot 1 - 0 \cdot 0 = 1$$ゼロ以外なので、アルゴリズムはすぐに出力します。`1`。 決定方法はすべての方向に対して均一に機能するため、垂直線に対する特別な処理は必要ありません。
