 ## 解決策
 ## 問題の理解

 私たちは単語のコレクションを与えられており、これらの単語のペアが有効な「分割決定」の手がかりとしてどのように動作するかを理解したいと考えています。 

有効な手がかりは、同じ長さの 2 つの単語を選択し、それらを位置ごとに比較することで得られます。 単語は、正確に 2 つの位置を除いてどこでも同一である必要があり、それら 2 つの異なる位置は隣接している必要があります。 これら 2 つの位置では、各単語が異なる文字のペアを構成し、そのペアを他のすべてのペアから区別する 2 文字の「窓」のようなものを形成します。 

タスクは、そのようなペアを見つけることだけではありません。 また、手がかりのレベルでの一意性も確保する必要があります。 2 つの異なる単語のペアが同じ 2 位置の違いパターンを生成する場合、そのパターンはあいまいであるため、カウントしてはなりません。 単語のペアが、隣接する不一致位置の特定の選択に一致する一意のペアである場合にのみ、それをカウントします。 

入力サイズは十分に小さいため、単語ペアに対する二次推論が可能です。 最大 1500 単語の場合、約 110 万のペアが存在します。これは、各ペアが単語の長さにわたって線形時間でチェックされる場合には許容可能です。 語長は最大 20 なので、単純な比較戦略はすでに限界に近づいていますが、注意して集計すればまだ実行可能です。 

位置のすべてのパターンとすべてのペアを個別に列挙しようとする単純なアプローチでは、過剰にカウントされ、一意性の要件が満たされなくなります。 重要な点は、複数のペアが同じ「隣接する 2 つの不一致位置」を共有する可能性があり、それらの衝突によりすべてが無効になることです。 

いくつかの特殊なケースが重要です。 

すべての単語が同一の場合、正確に 2 つの位置が異なるペアはないため、答えはゼロになります。 

2 つの単語が 3 つ以上の位置で異なっている場合、それらの位置の一部が隣接していても、有効な手がかりを形成することはできません。 

ペアのちょうど 2 つの位置が異なっていても、それらの位置が隣接していない場合、たとえ不一致数が一致していても、そのペアは無効になります。 

最後に、3 つ以上の単語が同様の 2 位置変換のサイクルを形成している場合、パターン レベルで一意性が強制されない限り、ペアごとの単純なカウントではそれらの単語が誤って受け入れられてしまいます。 

## アプローチ

 ブルートフォースのアイデアは定義から始まります。 すべての単語のペアについて、文字ごとに比較し、不一致を数え、異なる位置を記録します。 正確に 2 つの位置が異なり、それらの位置が連続している場合、このペアを手がかり候補とみなします。 

ただし、正しさだけでは十分ではありません。 この問題には一意性が必要です。他の単語のペアが同じ不一致位置のペアを生成することはできません。 ペアのみをチェックするブルートフォース手法では、これをグローバルに検出できません。 ローカルでのみ検証されます。 

これを修正するために、有効な候補はすべて、単語の長さ、最初の異なる文字のインデックス i、位置 i と i+1 にある両方の単語の文字のペアという 3 つの情報によって記述できることがわかりました。 複数の単語のペアが同じタプル (i、単語 A の文字、単語 B の文字) を生成する場合、その手がかりはあいまいであるため、破棄する必要があります。 

これは 2 段階の戦略を示唆しています。 まず、すべての単語ペアを列挙し、手掛かりパターンを表す署名によってグループ化されたすべての有効な候補を収集します。 次に、ちょうど 1 つのペアを含むグループのみをカウントします。 

重要な簡素化は、最後にペアについて直接推論するのではなく、ペアをスキャンしながらすぐにパターンによって集計することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ペア チェックのみ | O(n² · L) | お(1) | 間違っています (一意性を強制できません) |
 | パターン署名ごとにグループ化 | O(n² · L) | O(n²) 個の最悪の場合のシグネチャ | 承認済み |

 ## アルゴリズムのチュートリアル

手がかりに関連する情報を正確に捉える、単語のペアの署名を定義します。 

1. i < j であるすべての単語のペア (i, j) を繰り返します。 これにより、各ペアが 1 回考慮されることが保証されます。 
2. 各ペアについて、2 つの単語を同時にスキャンし、不一致の位置を記録します。 3 つ以上の不一致が発生した場合は、ルールを満たすことができないため、そのペアを直ちに破棄できます。 
3. 正確に 2 つの不一致が存在する場合は、それらの位置が隣接しているかどうかを確認します。 隣接していない場合は、そのペアを破棄します。 
4. 有効なペアの場合、不一致位置を p および p+1 とします。 位置 p、関連する 4 つの文字 (word1[p]、word1[p+1]、word2[p]、word2[p+1])、およびオプションで単語の ID 順序から構成される署名を構築します。 
5. この署名を生成するペアの数をマッピングする辞書に保存するか、一意性の検出のみが必要な場合はペア自体を直接保存します。 
6. すべてのペアを処理した後、記録されたすべての署名を反復処理し、1 回だけ出現する署名をカウントします。 
7. このカウントを答えとして返します。 

重要な点は、署名には位置と文字構成の両方が含まれている必要があるということです。 そうしないと、単語の 2 つの異なる領域または異なる文字の配置が、誤って同じキーに集約されてしまいます。 

### なぜ効果があるのか

 それぞれの有効な手がかりは、単語が異なる 2 つの隣接する位置によって完全に決定されます。 同じ手がかりを生み出す単語のペアは、それらの立場に一致し、まったく同じ方法で不一致でなければなりません。 したがって、この署名によってペアをグループ化すると、すべての有効な候補が同一の手がかりの同値クラスに分割されます。 サイズ 1 のクラスのみをカウントすることで、問題ステートメントで必要とされるとおりに一意性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    words = [input().strip() for _ in range(n)]
    
    from collections import defaultdict
    
    freq = defaultdict(int)
    
    # store whether a pair is the only one for a given signature
    # we also track if we have seen multiple pairs per signature
    used = set()
    bad = set()
    
    for i in range(n):
        w1 = words[i]
        for j in range(i + 1, n):
            w2 = words[j]
            if len(w1) != len(w2):
                continue
            
            diff = []
            for k in range(len(w1)):
                if w1[k] != w2[k]:
                    diff.append(k)
                    if len(diff) > 2:
                        break
            
            if len(diff) != 2:
                continue
            
            a, b = diff
            if b != a + 1:
                continue
            
            # signature of the clue
            sig = (a, w1[a], w1[a+1], w2[a], w2[a+1])
            
            if sig in used:
                bad.add(sig)
            else:
                used.add(sig)
    
    # count only unique signatures
    # (those that appear exactly once)
    return sum(1 for s in used if s not in bad)

if __name__ == "__main__":
    print(solve())
```このソリューションは、すべての単語ペアを反復処理し、不一致カウントを使用して積極的にフィルター処理を行い、隣接する 2 つの相違点を持つ候補のみがさらに処理されるようにします。 署名は、さまざまな手掛かりパターンを区別するために必要な、位置と文字のマッピングの両方をキャプチャします。 

の`used`set は、これまでに 1 回だけ確認された署名を追跡します。`bad`複数のサポートペアを持つものを追跡します。 これにより、一意性を維持しながら、ペア自体の完全な頻度マップが必要なくなります。 

よくある間違いは、2 つの異なる単語のペアが同じパターンを生成する可能性があることを忘れていることです。そのため、重複を無効にするために 2 番目のセットが必要になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n² · L) | 最大 ~110 万の各ペアが、長さ 20 | までの文字ごとに比較されます。 
| スペース | O(k) | k は保存されている有効な署名の数で、最大でも有効なペアの数です。 

最悪の場合、1500² × 20 で約 4,500 万文字の比較になるため、この制約により O(n² · L) アプローチが安全になります。これは、差分が 2 を超える場合に早期終了する Python では許容されます。

 ## 特殊なケース

 微妙なケースの 1 つは、複数の単語のペアが同じ 2 つの位置を共有しているが、文字マッピングが異なる場合です。 たとえば、いくつかの単語が位置 i と i+1 でのみベース単語と異なる場合、結果として得られるすべてのペアは同じ署名にまとめられます。 アルゴリズムはそれらを単一の署名に正しくグループ化し、複数回出現すると無効にします。 

もう 1 つのケースは、語長が異なる場合です。 不一致の比較では長さが等しいことが前提となるため、不一致の長さをスキップすることが重要です。 このチェックを行わないと、インデックス作成が無効になったり、誤った差異が表示されたりする可能性があります。 

最後のエッジケースは、差異が早い段階で 2 文字を超える場合です。 早期の中断により、不必要なスキャンが防止され、最悪の場合の同一プレフィックスであってもパフォーマンスが安定したままになります。
