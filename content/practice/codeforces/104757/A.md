 ## 解決策
 ## 問題の理解

 個別の正の整数のシーケンスが与えられており、配列内にすでに出現している未知のピボット値を使用して、このシーケンスがクイックソートの単一の分割ステップの結果であるかどうかを判断したいと考えています。 

値を中心に配列を分割するときに、その左側のすべての要素が有効なパーティションと一致して「小さい側」または「大きい側」のいずれかにある場合、値は有効なピボットとして機能します。ピボット以下のすべての要素は一方の側に存在し、ピボットより厳密に大きいすべての要素は反対側に存在する必要があります。 どの辺が「ピボット未満」に対応するかは示されていませんが、その構造は、ピボットが配列を 2 つのグループに分割し、辺間で混合することがないという考えと一致している必要があります。 

タスクは、配列の現在の順序を考慮して、そのようなピボットとして機能する可能性のあるすべての値を識別することです。 どの値も機能しない場合、配列は有効なパーティション結果を表していないとみなされます。 多くの値が機能する場合は、入力順にリストしますが、最初の 100 個までです。 

重要な制約は、配列の長さが最大 100 万であることです。 考えられるすべてのピボット候補をチェックし、配列全体をスキャンしてそれを検証するソリューションでは、約$O(n^2)$実行可能な限界をはるかに超えた最悪の場合の動作。 私たちは、おそらくシングルパスと事前計算された構造を使用した、線形または線形に近いアプローチを余儀なくされています。 

配列がほぼ分割されているように見えても、中央付近に小さな違反がある場合、微妙なエッジ ケースが発生します。 たとえば、次のことを考えてみましょう。 

入力:```
5
1 4 2 3 5
```ピボット 2 を試行すると、2 以下の要素は正しくグループ化される必要がありますが、3 と 4 を配置すると一貫した分割が崩れます。 正確性は近隣要素だけでなくすべての要素のグローバルな一貫性に依存するため、ピボット値に関する単純なローカル チェックは失敗します。 

もう 1 つのエッジケースは、配列がすでにソートされている場合です。 

入力:```
5
1 2 3 4 5
```ローカルでのみチェックするとすべての要素がピボットであるように見えますが、実際には特定の位置のみがパーティション境界条件を満たします。 

## アプローチ

 直接的なアプローチは、各値を潜在的なピボットとしてテストすることです。 候補ピボットについては、配列全体をスキャンし、要素をそれ以下の要素とそれより大きい要素に分離し、観察された順序が有効なパーティション境界に対応できるかどうかを検証します。 正しいピボットにより値が明確に分離されるため、これは概念的に機能します。 ただし、これをそれぞれに対して行うと、$n$候補者が導くのは$n$フルスキャン、生成$O(n^2)$時間の複雑さは不可能です$n = 10^6$。 

重要な観察は、有効なピボットは相対位置のみに関するものではなく、値の接頭辞と接尾辞の構造に関するものであるということです。 配列を左から右にスキャンすることを想像すると、これまでに確認された最大値を維持できます。 位置に配置される潜在的なピボット$i$小さい値と大きい値を分離する境界要素のように動作することを意図している場合は、少なくともその左側にあるすべてのものと同じ大きさでなければなりません。 同様に、右から左にスキャンすると、サフィックスに最小限の制約が与えられます。 

値が、そのプレフィックスの最大値であり、同時にそのサフィックスの最小値である位置にあるとき、その値は有効なピボットです。 これにより、問題が 2 つの線形スキャンと最後のフィルタリング ステップに変換され、次のように削減されます。$O(n)$。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | プレフィックスとサフィックスのチェック | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、入力順に保存します。 出力では順序を尊重する必要があるため、順序を保持します。 
2. アレイを構築する`pref_max`、 どこ`pref_max[i]`インデックスで終わるプレフィックスの最大値です`i`。 これにより、左側でピボットが「小さすぎる」ことを妨げる可能性のあるすべてがキャプチャされます。 
3. アレイを構築する`suf_min`、 どこ`suf_min[i]`インデックスで始まるサフィックスの最小値です`i`。 これにより、右側でピボットが「大きすぎる」ことを妨げる可能性のあるすべてがキャプチャされます。 
4. 各インデックスについて`i`、どうかを確認してください`pref_max[i] == suf_min[i] == a[i]`。 これが当てはまる場合、位置の要素は`i`は、まさに左パーティションと右パーティションの間の区切り値です。 
5. このような値をすべて順番に収集します。 100 を超える場合は、最初の 100 のみを出力します。 
6. 値が見つからない場合は、0 を出力します。これは、有効なパーティション解釈が存在しないことを意味します。 

### なぜ効果があるのか

 有効なピボットは、指定された配置内のすべての小さな要素をすべての大きな要素から明確に分離する値である必要があります。 値がその左側の値より小さい場合、プレフィックスの一貫性に違反します。 それが右側のものよりも大きい場合、接尾辞の一貫性に違反します。 プレフィックスの最大値により、それより大きな値がその前に出現しないことが保証され、サフィックスの最小値により、それより小さい値がその後に出現しないことが保証されます。 両方が要素自体に一致する場合、分割がクイックソートのパーティション定義と一致する一意の境界となり、有効なピボットになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    pref_max = [0] * n
    suf_min = [0] * n

    cur = float('-inf')
    for i in range(n):
        cur = max(cur, a[i])
        pref_max[i] = cur

    cur = float('inf')
    for i in range(n - 1, -1, -1):
        cur = min(cur, a[i])
        suf_min[i] = cur

    res = []
    for i in range(n):
        if pref_max[i] == a[i] == suf_min[i]:
            res.append(a[i])
            if len(res) == 100:
                break

    print(len(res), *res)

if __name__ == "__main__":
    solve()
```この実装は、プレフィックス最大値とサフィックス最小値を構築するために 2 つの線形パスに依存します。 プレフィックス スキャンでは、各位置までの最大の制約が確実にわかりますが、サフィックス スキャンでは右側からの最小の制約が得られます。 最後のループでは、両方の条件を同時に満たす要素がフィルターされます。 100 候補で早期停止することは、出力仕様により要求されます。 

よくある間違いは、隣接セグメントまたはローカル セグメントのみを比較しようとすることです。 パーティションの有効性は隣接関係ではなくグローバルな順序付けの制約に依存するため、これは失敗します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、次のような単一要素の配列です。`1\n7\n`。 プレフィックスの最大値とサフィックスの最小値はどちらもインデックス 0 の要素自体に等しいため、アルゴリズムはその値を有効なピボットとして正しく返します。 

もう 1 つのエッジ ケースは、次のような厳密に降順の配列です。`4\n4 3 2 1\n`。 各位置の接頭辞の最大値は常に最初の要素と等しくなりますが、接尾辞の最小値は現在の要素に向かって徐々に減少します。 すべてのインデックスで等価性が維持されるため、各位置が有効な分割境界として機能するという解釈と一致して、すべての要素が受け入れられます。 

より微妙なケースは、次のように 1 つの要素だけが中央で有効な境界を形成する場合です。`3\n2 1 3\n`。 インデックス 1 の値 1 は、そこから始まるサフィックスの最小値であり、有効なプレフィックス最大構造の一部でもあり、これが唯一の一貫したピボットになります。 そのインデックスのみが両方の制約を同時に満たすため、アルゴリズムはこれを自然に捉えます。
