 ## 解決策
 ## 問題の理解

 位置の 2 つの平行な行が与えられ、どちらも 0 から n − 1 までのインデックスが付けられます。最初の行にはすでに鳥が入力されており、複数の鳥が同じ位置から開始する可能性があります。 2 番目の行は最初は空ですが、各鳥は 2 番目の行に固定のターゲット位置を持っています。 

各バードは、最初の行の開始インデックスから 2 行目の目的のインデックスまでの直線セグメントを定義します。 すべての鳥が同時に飛び立ちます。 「危険なペア」とは、飛行セグメントが幾何学的意味で交差する別個の鳥のペアを指しますが、同じ位置から開始するか同じ位置で終了するような些細なケースは除きます。 

タスクは、そのような交差するペアがいくつ存在するかを数えることです。 

この制約は、合計で最大 2 · 10^5 の鳥を意味します。 すべてのペアを明示的に考慮するソリューションでは、n^2 程度の比較が必要になりますが、これは実現可能な限界をはるかに超えています。 一般的な制限時間内では 10 億回の操作でもすでに大きすぎるため、交差の構造を利用する必要があります。 

微妙な問題は、複数の鳥が同じ出発地または同じ目的地を共有できることです。 これらのペアは、単純な交差テストでエンドポイントの重複が検出されたとしても、決してカウントしてはなりません。 たとえば、2 羽の鳥が位置 3 から開始し、異なる目的地に向かう場合、それらのセグメントが幾何学的に交差する可能性があるとしても、定義上、危険とはみなされません。 同様に、2 羽の鳥が同じ目的地を共有する場合も除外されます。 

目的地が頻繁に繰り返される場合には、別の特殊なケースが発生します。 多くの鳥が同じターゲットに向かう場合、反転ベースの推論によって、フィルターで除外する必要があるペアを誤ってカウントしていないことを確認する必要があります。 

## アプローチ

 ブルートフォース ソリューションでは、すべての鳥のつがいを比較し、それらのセグメントが交差するかどうかを確認します。 m 羽の場合、これは m(m − 1) / 2 ペアをチェックすることを意味します。 各ペアについて、エンドポイントを比較し、開始インデックスと終了インデックスの順序付け条件を使用して交差を検出します。 これは正しいですが、約 2 · 10^10 のチェックが必要になるため、m が 2 · 10^5 までの場合はすぐに失敗します。 

重要な観察は、すべての鳥がペア (開始位置、目的地位置) によって完全に記述されるということです。 2 つのセグメントは、開始位置が一方向に順序付けされているが、目的地の位置が逆方向に順序付けされている場合、正確に交差します。 これは古典的な反転構造です。鳥を開始位置で並べ替えてから目的地のシーケンスを見ると、そのシーケンス内のすべての反転が交差ペアに対応します。 

ただし、重複したものは慎重に扱う必要があります。 同じ出発地または同じ目的地を共有する鳥は数えてはなりません。 これは、反転をカウントする際に、等しい開始グループをブロックとして扱い、内部相互作用のカウントを避ける必要があることを意味します。 宛先が同じ場合も同様です。 

これは、同じ開始位置で鳥をグループ化することで解決します。 各グループ内で目的地別に分類し、グループ間のやり取りのみを考慮するようにします。 次に、グループを開始順序の昇順に処理し、宛先値に関するフェンウィック ツリーを維持し、以前に確認された宛先が現在の宛先よりも大きいものがいくつあるかを数えます。 これにより、等しい開始が相互作用しないことを考慮しながら、自然に反転がカウントされます。 

フェンウィック ツリー構造を使用すると、目的地を挿入し、対数時間で指定された値を超える前の目的地の数をクエリすることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(㎡) | お(1) | 遅すぎる |
 | 並べ替え + フェンウィック ツリー | O(m log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各鳥をペア (s, d) として扱います。s は開始位置、d は目的地です。 複数の鳥が同じ を共有できるため、最初に鳥をグループ化します。

1. すべての鳥をペアとして収集します (s、d)。 入力構造をサイズ m の単一のリストに平坦化します。 これにより、元の位置ごとのストレージを気にする必要がなくなるため、推論が簡素化されます。 
2. 開始位置 s を増やしてすべての鳥を並べ替え、同じ場合は目的地 d で並べ替えます。 これにより、開始グループ内ですべての鳥が一貫した順序で一緒に処理されることが保証されます。 グループ内の順序付けにより、後で同じスタートの鳥間の相互作用をカウントすることができなくなります。 
3. 宛先インデックスを使用してフェンウィック ツリーを初期化します。 この構造は、以前に処理された鳥の数が各宛先値を持つかを維持します。 
4. ソートされたリストを左から右にスクロールします。 各鳥 (s, d) について、d を超える目的地を持つ前に処理された鳥の数をクエリします。 この数字が答えに追加されるのは、前の鳥がより高い目的地に向かう逆転を表し、現在の鳥との交差点を暗示するためです。 
5. クエリを処理した後、将来の鳥がそれに対してカウントできるように、d をフェンウィック ツリーに挿入します。 
6. 同じ start を持つ鳥が連続して現れるため、それらが内部反転に寄与しないことを保証します。 これは、(s, d) によるソートによって実現されます。これは、ブロック内のペアを反転としてカウントせずに、そのブロックに対するすべてのクエリが一貫して処理された後に、等しい開始のバードが挿入されることを意味します。 

### なぜ効果があるのか

 各鳥は (s, 0) から (d, 1) までのセグメントに対応します。 2 つのセグメントは、端点が反対方向 (s1 < s2 であるが d1 > d2) に順序付けされている場合にのみ交差します。 これは、s で順序付けされた d 値のシーケンスを考慮したときの反転の定義とまったく同じです。 フェンウィック ツリーは、すでに確認されている宛先のプレフィックス カウントを維持するため、各クエリは、現在のセグメントとの反転を形成する以前のセグメントの数を正確にカウントします。 均等開始によるグループ化により、定義により除外されるべきセグメントが比較されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        i += 1
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        i += 1
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if r < l:
            return 0
        return self.sum(r) - (self.sum(l - 1) if l > 0 else 0)

n = int(input())
pairs = []

for i in range(n):
    tmp = list(map(int, input().split()))
    p = tmp[0]
    for x in tmp[1:]:
        pairs.append((i, x))

pairs.sort()

max_d = n
fw = Fenwick(max_d + 1)

ans = 0

for s, d in pairs:
    # count previously seen destinations greater than d
    ans += fw.range_sum(d + 1, max_d)
    fw.add(d, 1)

print(ans)
```この解決策は、すべての入力バードを (開始点、目的地) ペアの単一のリストに平坦化することから始まります。 ソートにより、昇順で処理が開始されることが保証されます。これは、反転解釈が成立するために不可欠です。 

フェンウィック ツリーは、宛先値に対する動的な頻度テーブルを維持するために使用されます。 鳥ごとに、以前に処理された目的地がその鳥自身の目的地より厳密に大きいものがいくつあるかをクエリします。 このカウントは交差ペアを表すため、答えに追加されます。 

クエリを実行した後、現在の宛先を挿入して、将来の比較セットの一部とします。 

微妙な点の 1 つは、すべての宛先が制限された範囲 [0, n − 1] 内にあるという事実に依存していることです。これにより、Fenwick のインデックス作成が簡単になります。 range_sum(d + 1, max_d) を使用すると、厳密な不平等が適用されるため、同じ目的地を持つ鳥はカウントされず、同じ目的地を持つ鳥は危険なつがいではないという問題のルールと一致します。 

## 実用的な例

 3 羽の鳥が存在する小さな例を考えてみましょう。 

入力:```
0: 1
1: 0
1: 1
```これは、鳥が (0→1)、(1→0)、(1→1) であることを意味します。 

ソートされたペアは次のようになります。 

(0,1)、(1,0)、(1,1)

 フェンウィックの状態を段階的に追跡します。 

| ステップ | 鳥 | クエリ (>d) | 挿入後のフェンウィックの状態 | 実行中の答え |
 | --- | --- | --- | --- | --- |
 | 1 | (0,1) | 0 | {1:1} | 0 |
 | 2 | (1,0) | 1 | {0:1,1:1} | 1 |
 | 3 | (1,1) | 0 | {0:1,1:2} | 1 |

 2 番目の鳥は、開始順序では 1 > 0 ですが、目的地の順序では 1 < 0 であるため、最初の鳥と 1 つの反転に寄与し、交差を形成します。 

次に、重複がある場合を考えてみましょう。 

入力:```
0: 0 1
1: 1
```ペア:

 (0,0)、(0,1)、(1,1)

 処理により、開始 0 内ではペアはカウントされず、有効なクロススタート反転のみが含まれることがわかります。 フェンウィック構造は、誤った交差を作成する方法で 2 つの (0, *) ペアを相互に比較することはありません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log n) | m 個の鳥のそれぞれが 1 つのフェンウィック クエリと 1 つの更新を実行します。 
| スペース | O(n + m) | Fenwick ツリーと入力ペアのストレージ |

 鳥の総数は最大でも 2 · 10^5 であるため、対数更新は十分に制限内にあります。 メモリ フットプリントは入力サイズに対して線形であり、制約に簡単に適合します。

 ## 特殊なケース

 特殊なケースの 1 つは、多くの鳥が同じ開始位置を共有する場合です。 たとえば、すべての鳥は 0 から始まり、さまざまな目的地に行きます。 入力により、同一の s 値を持つ大きなグループが生成されます。 並べ替えによってそれらが一緒に配置されるため、フェンウィック ツリーではこれらの鳥がより早く開始されることはなく、そのためグループ内で反転はカウントされず、正確にはゼロが得られます。 

もう 1 つの特殊なケースは、すべての鳥が同じ目的地を共有する場合です。 開始位置が異なる場合でも、すべてのペアは等しい d 値を形成し、Fenwick クエリの厳密な不等式によりカウントできなくなります。 たとえば、(0→5)、(1→5)、(2→5) は、すべての比較が d1 > d2 条件を満たさないため、危険なペアは生成されません。 

最後のエッジ ケースは、出発地が増加し、目的地が厳密に減少している完全に逆のマッピングです。 これにより反転の最大数が作成され、フェンウィック ツリーは以前の各要素を現在の要素よりも大きいものとして累積し、完全な三角カウントを生成し、反転ロジックの正しさを確認します。
