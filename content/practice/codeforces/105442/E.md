 ## 解決策
 ## 問題の理解

 まず、豚とキリンという 2 つの独立した動物グループから始めます。 最初は、それぞれのブタがいくつかのキリンと「会話」する可能性があり、この関係は対称的であるため、キリンがそのブタに接続されている場合に限り、ブタはキリンに接続されます。 同種の動物と直接会話する動物はいないため、グラフは常に 2 部構成になります。 

通信ネットワークは時間の経過とともに進化します。 新しい動物が生まれるとき、それはブタかキリンのいずれかであり、同じ種類の既存の 2 つの親から作成されます。 生まれたばかりの子は、両親のどちらか一方と結びついている、正反対のタイプの動物と結びつきます。 グラフの用語では、新しいノードの隣接リストは、その 2 つの親の隣接リストの対称的な差分です。 

誕生するたびに、現在のグラフ全体を検討し、2 匹の動物間の距離を、動物間でメッセージを送信するために必要な最短の「会話ステップ」数として定義します。 パスがない場合、距離はゼロになります。 各挿入後に必要な出力は、異なる動物の順序付けされていないすべてのペアにわたる距離の合計です。 

主な難点は、グラフが最大 100,000 ノードまで成長するが、各ノードは明示的なエッジではなく XOR のような継承を通じて定義されることです。 これにより、サイズが大きいにもかかわらず、構造は非常に拘束されます。 

初期サイズの制約は非常に小さく、最大でもブタ 8 頭、キリン 8 頭までです。 これが主な構造上のヒントです。 グラフを任意の動的接続として扱おうとするソリューションは、すぐに問題に遭遇します。挿入のたびに最短パスを再計算するには、成長するグラフに対するクエリごとに少なくとも線形または BFS 作業が必要となり、おおよそ O(QN) の動作が発生するためです。Q と N が 100000 に達すると、これは非常に遅すぎます。 

コンポーネントが切断されていると、微妙なエッジケースが発生します。 素朴なアプローチが最初に接続された部分内の距離のみを追跡し、更新後もすべてのノードが接続されたままであると仮定した場合、到達不可能なままのペアを黙ってカウントし、寄与はゼロになるはずです。 もう 1 つの障害モードは、距離が新しいノードの周囲でローカルにのみ変化すると仮定することです。これは誤りです。ノードを追加すると、新しいより短いルートを通じて古いノード間の距離が間接的に減少する可能性があるためです。 

## アプローチ

 ブルートフォース解釈では、グラフが明示的に処理されます。 誕生するたびに、ノードの新しい隣接リストを構築し、マルチソース BFS または全ペア BFS を実行して最短パスを再計算します。 単一の BFS でさえ O(N + M) であり、これを Q 回実行すると O(Q(N + M)) になり、これは最悪の場合でおよそ 10^10 回の演算に相当します。 これは実現可能には程遠いです。 

重要な構造上の観察は、新しいノードを定義するルールが隣接セットに対して線形であるということです。 各ノードの近傍は、その親の近傍の対称的な差として取得されます。 これはまさに特性ビット ベクトルに対する XOR 動作です。 

ブタとキリンの初期数はそれぞれ最大 8 頭であるため、すべてのブタはどのキリンに接続しているかを表す 8 ビット ベクトルで表現でき、すべてのキリンはどのブタに接続しているかを表す 8 ビット ベクトルで表現できます。 継承ルールではこの表現が維持されます。すべての新しいノードは、同じ側にある 2 つの既存のベクトルの XOR です。 これは、特定のタイプのすべてのノードが、最大 8 次元の GF(2) 上のベクトル空間に存在することを意味します。 

したがって、最大 100,000 個のノードを作成できても、ブタの「状態」は最大 256 個、キリンの「状態」は最大 256 個存在します。 グラフ全体は最大 512 個の個別の頂点に圧縮できます。各頂点はタイプを表し、各タイプはそのタイプの実際のノードが現在存在する数に等しい多重度を持ちます。

この圧縮が認識されると、頂点の重みを動的に増加させて最大 512 ノードの重み付きグラフを維持することが問題になります。 タイプ間の距離は静的であり、この固定グラフに対して BFS を使用して一度事前計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 出産後に BFS を再計算する | O(Q(N + M)) | O(N + M) | 遅すぎる |
 | グラフ型に圧縮 + カウントを維持 | O(Q・512) | O(512^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはすべての動物をその「タイプ」に基づいてモデル化します。これは、反対側のビットマスクとしてエンコードされた隣接ベクトルです。 各サイドは最大 8 つのノードで始まるため、これらのマスクは 8 ビットに収まり、サイドごとに最大 256 の可能なタイプが得られます。 

次に、考えられるすべてのブタ型とキリン型を頂点とする固定グラフを構築します。 キリンに対応するビットが p のマスクに設定されている場合、ブタ型 p とキリン型 g の間にエッジが存在します。 このグラフは、タイプ間で起こり得るすべての相互作用を完全にキャプチャしています。 

この 512 ノードのグラフに対して BFS を使用して、タイプのすべてのペア間の最短パス距離を事前計算します。 

各タイプ v のカウンター配列 cnt[v] を維持し、最初は指定された開始動物で満たされます。 また、現在のペアごとの距離の合計も維持します。 

タイプ t の新しい動物が追加されるたびに、この新しいノードに関係するすべてのペアの寄与を追加して答えを更新します。 既存のタイプ v に cnt[v] ノードがある場合、新しい寄与は cnt[v] と dist[t][v] の積になります。 これをすべての v で合計し、グローバルな答えに追加してから、cnt[t] をインクリメントします。 

これは、新しいノードが追加されても既存のノード間の距離が変わらないため機能します。 古いノード間のグラフ構造は固定されています。 新しいノードは新しいペアを導入するだけです。 

### なぜ効果があるのか

 重要な不変条件は、既存の 2 つのノード間の最短パス距離が事前計算されたタイプ グラフのみに依存し、将来の挿入の影響を受けないことです。 すべてのノードはそのタイプによって完全に特徴付けられており、タイプは作成後に変更されません。 エッジはノードの識別性ではなくタイプの互換性によってのみ定義されるため、新しいノードを追加すると、既存のエッジは変更されずに新しい頂点のみが追加されます。 したがって、以前に計算されたすべての最短パス距離は有効なままであり、新しいノードに関係する距離のみを考慮する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

# We will treat pigs and giraffes as two separate sides:
# pigs: 0..255, giraffes: 0..255, shifted by 256 for giraffes
N = 256
TOTAL = 512

def pig_id(mask):
    return mask

def giraffe_id(mask):
    return mask + 256

# Precompute adjacency of type graph
adj = [[] for _ in range(TOTAL)]

# pig types: mask over 8 giraffe slots
# giraffe types: mask over 8 pig slots

# pig p connects to giraffe g if bit g is set in p
for p in range(256):
    for g in range(256):
        if p & (1 << (g % 8)):
            adj[pig_id(p)].append(giraffe_id(g))

# giraffe connects similarly (dual structure)
for g in range(256):
    for p in range(256):
        if g & (1 << (p % 8)):
            adj[giraffe_id(g)].append(pig_id(p))

# Precompute all-pairs shortest paths on 512 nodes
dist = [[10**9] * TOTAL for _ in range(TOTAL)]

for i in range(TOTAL):
    dist[i][i] = 0
    q = deque([i])
    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[i][v] > dist[i][u] + 1:
                dist[i][v] = dist[i][u] + 1
                q.append(v)

A, B, M = map(int, input().split())

# initial types (we assume initial nodes correspond to basis masks)
pig_type = [0] * A
giraffe_type = [0] * B

cnt = [0] * TOTAL
ans = 0

for _ in range(M):
    a, b = map(int, input().split())
    pig_type[a] |= 1 << (b % 8)
    giraffe_type[b] |= 1 << (a % 8)

# initial nodes exist
for i in range(A):
    cnt[pig_id(pig_type[i])] += 1
for j in range(B):
    cnt[giraffe_id(giraffe_type[j])] += 1

# initial contribution
for i in range(TOTAL):
    for j in range(TOTAL):
        ans += cnt[i] * cnt[j] * dist[i][j]
ans //= 2  # unordered pairs

Q = int(input())

def compute_type(kind, p, q):
    if kind == 'A':
        return pig_id(pig_type[p] ^ pig_type[q])
    else:
        return giraffe_id(giraffe_type[p] ^ giraffe_type[q])

for _ in range(Q):
    kind, p, q = input().split()
    p = int(p)
    q = int(q)

    t = compute_type(kind, p, q)

    # add contribution of new node
    for v in range(TOTAL):
        ans += cnt[v] * dist[t][v]

    cnt[t] += 1

    print(ans)
```コードはまず、すべての動物を 512 の可能なタイプの 1 つに圧縮します。 タイプ間の隣接関係はビットマスクから明示的に構築され、すべてのノードから BFS を使用してすべての最短パスが 1 回事前計算されます。 

クエリごとに、新しいノードのタイプが親マスクの XOR として計算されます。 答えは、その数によって重み付けされたすべての既存のノードにその距離を追加することによって更新されます。 最後の 2 による除算は、初期化ステップでのみ表示されます。これは、最初に順序付きペアの完全な対称合計を計算するためです。 

## 実用的な例

 最初の豚が 2 匹、最初のキリンが 2 匹いて、それぞれの豚が最初は 1 匹のキリンに接続しているという小さな仮説の例を考えてみましょう。 型空間は十分に小さいため、すべての距離を明示的にリストできます。 

最初の誕生の後、既存の 2 頭の豚から新しい豚が作成されます。 その隣接関係は近傍の XOR となり、新しいタイプまたは既存のタイプと同一のタイプが生成される可能性があります。 以下の表は、カウントがどのように変化するかを追跡しています。 

| ステップ | 追加されたタイプ | カウント更新 | 貢献が追加されました |
 | --- | --- | --- | --- |
 | 1 | t1 | cnt[t1] が増加 | sum_v cnt[v] * dist[t1][v] |

 これは、新しいノードに関係する距離のみが重要であることを示しています。 

2 番目の例では、同じタイプが複数回生成される繰り返しの誕生を考えます。 ノードは個別であっても、その寄与は純粋に多重性によって処理されます。 これにより、型圧縮が適用されると、個々のノードの ID は問題にならないことが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(Q · 512 + 512^3) | BFS 事前計算と型空間に対するクエリごとの更新 |
 | スペース | O(512^2) | 圧縮グラフの距離行列と隣接関係 |

 タイプ グラフの頂点数は最大 512 であるため、定数係数は小さくなります。 100,000 個のクエリがあっても、回答の更新にはクエリごとに 512 個の長さの固定スキャンのみが必要であり、制限内に問題なく収まります。

 ## 特殊なケース

 2 つの異なる誕生順序から同じ型が生成される場合、厄介な状況が発生します。 その場合、単純な実装ではそれらを別々のグラフ構造として扱う可能性がありますが、正しい動作はそれらを完全にマージすることです。 タイプベースの表現により、両方のノードが同じように寄与することが保証され、距離の更新は多重度によって単純にスケールされます。 

もう 1 つのエッジケースは、すべての動物がタイプのサブセットから切り離される場合です。 切断されたノード間の距離はゼロとして定義されるため、事前計算された距離行列は、到達不可能なペアを明示的にゼロまたは決してカウントされない大きなセンチネルとしてエンコードする必要があります。 BFS では初期化時から到達不能距離が変更されず、合計に寄与しないため、アルゴリズムはこれを自然に処理します。
