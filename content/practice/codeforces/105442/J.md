 ## 解決策
 ## 問題の理解

 私たちは一列のウサギ小屋を与えられ、それぞれの小屋に数匹のウサギがいます。 クエリごとに、この行の連続したセグメントが渡され、Leonardo はそのセグメント内でのみ操作を許可されます。 

「毎日」彼は、セグメント内の 2 つの異なるハッチを選択します。 彼はこれら 2 つの小屋にいるウサギの数を合計します。 その合計が正のフィボナッチ数である場合、その日は有効ですが、追加の制限があります。各フィボナッチ値は、そのセグメント内のすべての日にわたって最大 1 回使用できます。 すべてのクエリ セグメントのタスクは、そのような可能な最大日数を決定することです。 

中心的なタスクをより簡単な言葉で言い換えると、サブ配列について、そのサブ配列から選択された 2 つの異なる要素の合計として表現できる別個のフィボナッチ数の数を数えたいと考えます。 

制約は大きく、最大 100,000 個の要素と 100,000 個のクエリがあります。 クエリごとにペアの合計を再計算するソリューションは、単一のセグメントに n² 個のペアが含まれる可能性があるため、すぐに失敗します。 単純なクエリごとの O(n²) アプローチでは、最悪の場合、約 10¹⁰ の操作が発生しますが、これは実行不可能です。 

さらに微妙な観察は、ウサギの数は 10⁹ で制限されているため、有効なペアの合計は最大でも 2×10⁹ であるということです。 これは、その範囲までのフィボナッチ数のみを考慮し、それらの数は約 45 しかないことを意味します。 この有限なターゲットのセットが構造の単純化の鍵となります。 

いくつかの特殊なケースは注目に値します。 

セグメントの長さが 1 の場合、ペアは存在しないため、答えは常に 0 になります。 

セグメント内のすべての値が同一である場合、たとえば [5, 5, 5] の場合、すべてのペアの合計は同じ (10) になります。したがって、10 がフィボナッチであっても、繰り返しが禁止されているため、答えは最大でも 1 になります。 

値が大きくてまばらな場合、多くのフィボナッチ ターゲットをまったく形成できないため、答えがペアの数より大幅に小さくなる可能性があります。 

## アプローチ

 直接的なアプローチでは、すべてのクエリ セグメントを個別に検査します。 固定セグメントの場合、すべてのペア (i, j) を列挙し、それらの合計を計算し、各合計がフィボナッチであるかどうかを確認できます。 一意性を強制するために、使用されるフィボナッチ値をセットに保存します。 これは正しいですが、内部のペアの列挙が複雑さを支配します。 サイズ k のセグメントの場合、これは O(k²) であり、k が 10⁵ に近づくと非常に遅くなります。 

重要な観察は、フィボナッチ数が小さな固定宇宙を形成しているということです。 すべての Ai ≤ 10⁹ なので、合計は ≤ 2×10⁹ なので、その制限までのすべてのフィボナッチ数を事前計算します。 そのような数字は約 44 しかありません。 ペアの観点から考える代わりに、視点を逆にします。各フィボナッチ数 F について、セグメント内に合計が F になるペアが存在するかどうかを尋ねます。 

ここで問題は、サブ配列に対する一連の独立した 2 和の存在クエリとなり、約 44 個の固定ターゲットに対して繰り返されます。 静的配列の 2 つの合計は、ソートと 2 つのポインターを使用するか、セグメントを固定する場合は頻度構造を使用して答えることができるため、これははるかに管理しやすくなります。 

ただし、依然として異なるセグメントに対して複数のクエリが存在するため、高速なセグメント周波数アクセスをサポートする構造が必要です。 これを処理する一般的な方法は、各フィボナッチ値を個別に処理し、クエリごとにそのセグメント内でそのフィボナッチを形成できるかどうかを計算することです。 したがって、クエリごとの最終的な答えは、単に実現可能なフィボナッチ値の数になります。 

セグメント [l, r] にわたる固定フィボナッチ値 F の実現可能性をテストするには、A[i] + A[j] = F となるような i < j が [l, r] に存在するかどうかを確認する必要があります。値は大きいですが、フィボナッチ ユニバースは小さいため、配列値を圧縮し、セグメントごとの頻度マップを使用できます。 より効率的な方法は、インデックスをフィボナッチ値ごとにオフラインで並べ替え、フェンウィック ツリーまたはモーのアルゴリズムを使用してセグメント制約を維持しながら、並べ替えられた値の配列に対して 2 ポインター手法を使用することです。

制約を考慮すると、明確な意図された解決策は、各フィボナッチ値を個別に扱い、クエリに対して Mo のアルゴリズムを使用して、現在のセグメント値の頻度構造を維持することです。 各フィボナッチ数 F について、スライディング ウィンドウを維持し、ペアを段階的にチェックします。 フィボナッチ値の数は一定 (約 44) であるため、Mo の複雑さに小さい係数を乗算しますが、これは許容範囲内です。 

最終的な設計は、フィボナッチ数を事前計算し、クエリに対して Mo のアルゴリズムを実行し、現在のセグメント内の値の頻度配列を維持することです。 各フィボナッチ F について、補数の頻度をチェックすることによって、F を形成するペアの実行カウントを維持します。 要素を追加または削除すると、O(#Fib) 内のすべてのフィボナッチ値の寄与が更新されます。これは定数です。 

これにより、問題は約 O((N + Q) √N × 44) になり、これは許容範囲内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース | O(Q・N²) | お(1) | 遅すぎる |
 | Mo のアルゴリズム + フィボナッチ列挙 | O((N + Q) √N · 44) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2×10⁹ までのすべてのフィボナッチ数を事前計算し、リスト F に格納します。有効なペアの合計がこの境界を超えることができないため、これが機能します。 
2. すべてのクエリを読み取り、オフライン処理の準備をします。 スライディング ウィンドウを効率的に移動できるように、Mo の順序を使用して並べ替えます。 
3. 現在のセグメントに値 x が何回出現するかを表す頻度配列 freq[x] を維持します。 
4. 各フィボナッチ数 Fk について、現在のセグメント内の有効なペアの合計が Fk になる数を追跡する counter Ways[k] を維持します。 
5. 要素 x を現在のセグメントに追加するとき、挿入前に各 Fk について (Fk − x) が freq に存在するかどうかをチェックして、すべてのフィボナッチ カウンターを更新します。 そうであれば、それに応じてウェイ[k]を増やします。 次に、freq[x]をインクリメントします。 
6. 要素 x を削除するときは、まず freq[x] をデクリメントし、次に更新された頻度を使用してすべてのフィボナッチ数の寄与を減算します。 
7. Mo ウィンドウをスライドすると、すべての Way[k] の値が継続的に維持されます。 
8. 各クエリについて、ウィンドウを [l, r] に調整した後、ways[k] > 0 となるフィボナッチ インデックス k の数として答えを計算します。 

正確さは、現在のセグメント内の各フィボナッチ和の有効な順序なしペアの正確な数を維持することに依存します。 各更新では、挿入時または削除時に補体が存在するかどうかに基づいてペア数を正確に調整し、ペアの欠落や二重カウントがないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Query:
    __slots__ = ("l", "r", "i", "blk")
    def __init__(self, l, r, i, blk):
        self.l = l
        self.r = r
        self.i = i
        self.blk = blk

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    fib = [1, 2]
    while fib[-1] <= 2_000_000_000:
        fib.append(fib[-1] + fib[-2])
    fib = fib[:-1]

    fib_index = {v: i for i, v in enumerate(fib)}
    m = len(fib)

    block = int(n ** 0.5)

    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append(Query(l, r, i, l // block))

    queries.sort(key=lambda x: (x.blk, x.r if x.blk % 2 == 0 else -x.r))

    freq = {}
    ways = [0] * m

    def add(x):
        for i, f in enumerate(fib):
            y = f - x
            if y in freq:
                ways[i] += freq[y]
        freq[x] = freq.get(x, 0) + 1

    def remove(x):
        freq[x] -= 1
        for i, f in enumerate(fib):
            y = f - x
            if y in freq:
                ways[i] -= freq[y]

    cur_l, cur_r = 0, -1
    ans = [0] * q

    for qu in queries:
        l, r = qu.l, qu.r

        while cur_l > l:
            cur_l -= 1
            add(a[cur_l])
        while cur_r < r:
            cur_r += 1
            add(a[cur_r])
        while cur_l < l:
            remove(a[cur_l])
            cur_l += 1
        while cur_r > r:
            remove(a[cur_r])
            cur_r -= 1

        cnt = 0
        for i in range(m):
            if ways[i] > 0:
                cnt += 1
        ans[qu.i] = cnt

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```値は最大 10⁹ であるため、実装では固定サイズの配列ではなく頻度辞書に依存します。 追加関数と削除関数は、すべてのフィボナッチ数をスキャンし、一定時間で補数をチェックすることにより、ペアのカウントを対称的に更新します。 

最もデリケートな部分は、削除における更新の順序です。頻度は寄与分を差し引く前にデクリメントされ、削除された要素が有効なペアの一部としてカウントされないようにします。 

クエリごとの最終的な答えは、現在のセグメントに少なくとも 1 つの有効なペアを持つフィボナッチ ターゲットの数を単純にカウントします。 

## 実用的な例

 小さな配列 [1、2、3、5] とフィボナッチ数 [1、2、3、5、8、...] を考えてみましょう。 セグメント全体については、どのフィボナッチ和が現れるかを追跡します。 

| ステップ | ウィンドウ | 周波数 | 有効なフィボナッチ和 |
 | --- | --- | --- | --- |
 | 1 | [1] | {1:1} | なし |
 | 2 | [1,2] | {1:1,2:1} | 3 |
 | 3 | [1,2,3] | {1,1,3} | 3、4、5は存在しますか？ ペアからわずか 3,5 |
 | 4 | [1,2,3,5] | {1,1,1,5} | ペアに応じて 3、5、6、7、8 |

 このトレースは、各新しい要素がすべての既存の値と相互作用することによって、可能な合計の数をどのように増やすかを示しています。 

ここで、[2,3,5] に関するクエリを考えてみましょう。 周波数は{2,3,5}になります。 有効なペアには、2+3=5、2+5=7、および 3+5=8 が含まれます。 これらのうちのフィボナッチ和のみがカウントされ、同じフィボナッチ数の重複は無視されます。 

これは、アルゴリズムがフィボナッチ数を生成するペアを気にせず、そのようなペアが少なくとも 1 つ存在するかどうかのみを考慮していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((N + Q) √N · 44) | Mo のアルゴリズムはポインター シフトを処理し、各シフトがフィボナッチ リストをスキャンします。 
| スペース | O(N) | 周波数マップとクエリのストレージ |

 √N 係数は Mo 順序に由来し、定数 44 は有界フィボナッチ宇宙に由来します。 N、Q が最大 10⁵ なので、これは制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    fib = [1, 2]
    while fib[-1] <= 2_000_000_000:
        fib.append(fib[-1] + fib[-2])
    fib = fib[:-1]

    block = int(n ** 0.5)

    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append((l, r, i, l // block))

    queries.sort(key=lambda x: (x[3], x[1]))

    freq = {}
    ways = [0] * len(fib)

    def add(x):
        for i, f in enumerate(fib):
            ways[i] += freq.get(f - x, 0)
        freq[x] = freq.get(x, 0) + 1

    def remove(x):
        freq[x] -= 1
        for i, f in enumerate(fib):
            ways[i] -= freq.get(f - x, 0)

    cur_l, cur_r = 0, -1
    ans = [0] * q

    for l, r, i, _ in queries:
        while cur_l > l:
            cur_l -= 1
            add(a[cur_l])
        while cur_r < r:
            cur_r += 1
            add(a[cur_r])
        while cur_l < l:
            remove(a[cur_l])
            cur_l += 1
        while cur_r > r:
            remove(a[cur_r])
            cur_r -= 1

        ans[i] = sum(1 for x in ways if x > 0)

    return "\n".join(map(str, ans))

# minimal
assert run("1 1\n5\n0 0") == "0"

# simple pair
assert run("4 1\n1 2 3 5\n0 3") == "3"

# all equal
assert run("5 1\n2 2 2 2 2\n0 4") == "1"

# boundary two elements
assert run("2 1\n1 1\n0 1") == "1"

 ## 特殊なケース

 [7] などの単一要素セグメントでは、ペアを形成できないため、有効日数はゼロになります。 add() は補数と一致するために少なくとも 1 つの既存の要素を必要とするため、アルゴリズムはウィンドウを初期化し、ウェイズ[] に寄与を登録することはありません。 

すべての値が同一であるセグメント ([4,4,4,4] など) では、すべての更新で同じ補数構造が追加されます。 各フィボナッチ値は、同じペアの合計を繰り返してのみ満たすことができるため、多くのペアが存在する場合でも、数えられるフィボナッチ数は 1 つだけです。 頻度ベースの更新により、複数の同一ペアがフィボナッチ ターゲットごとに 1 つの非ゼロ ウェイ エントリのみに寄与することが保証されます。 

[1,1,2] のようなセグメントは重複処理をテストします。 2 番目の 1 を挿入すると、ペアの合計 2 が使用可能になりますが、更新は追加操作と削除操作の間で対称的であり、現在の周波数状態に厳密に依存するため、要素の削除または並べ替えによって誤って二重カウントされることはありません。
