 ## 解決策
 ## 問題の理解

 クッキートレイに書かれた 1 つの整数が与えられますが、それを並べて配置された一連の数字として考える必要があります。 アーロンは同じアクションを繰り返し実行します。現在のシーケンスから 1 桁を削除し、残りの桁を一緒にシフトしてギャップを埋め、結果の数値を再度読み取ります。 数字を削除すると先行ゼロが作成される場合、それらのゼロもすぐに破棄されるため、数値は常に正規化された形式で解釈されます。 

削除するたびに、アーロンは結果の数値が素数かどうかをチェックします。 素数の場合、プロセスは続行されます。 そうでない場合、プロセスは停止します。 最初の数値はすでに開始点としてカウントされているため、一度に 1 桁ずつ繰り返し削除することで、元の数値から開始して連続した「有効な状態」を何回取得できるかを事実上数えています。 

タスクは、プロセスが必然的に失敗する前に取得できる素数状態の最大数を計算することです。 

入力は 10^9 までの単一の数値ですが、キーの構造は算術演算ではなく組み合わせです。数値を 1 つずつ削除するすべての可能な方法を検討していますが、数値を素数に保つパスに沿ってのみ続行します。 

N ≤ 10^9 という制約は、最大 10 桁を意味します。 これは、削除によって到達可能なさまざまな状態の合計数を制限するため、非常に重要です。 どの状態も単なる数字のサブシーケンスであるため、検索スペースは最大 2^10 = 1024 個の候補であり、遷移では一度に 1 桁ずつ削除されるため、合計のエッジ数は少なくなります。 

素朴な誤解は、これを数値プロセスとして扱い、貪欲または決定論的に数字の削除をシミュレートしようとすることです。 これは、削除順序が異なると異なる中間数値が生成される可能性があるため、失敗します。また、単一の決定的な実行ではなく、可能な最大の実行が求められるためです。 

微妙なエッジケースは、数字を削除すると先行ゼロが作成される場合です。 たとえば、103 から 1 を削除すると 03 が生成され、これは 3 になります。正規化せずに文字列を文字通りに扱うソリューションは、「03」を別の状態として誤って扱うか、拒否します。 

もう 1 つの特殊なケースは、1 桁の素数です。 数値が 2、3、5、または 7 のような 1 桁になった場合、削除する桁がまだ残っている場合にのみプロセスは続行されますが、さらに削除すると空または無効な状態が生成される可能性があります。 

## アプローチ

 ブルートフォース解釈では、最初の番号から始まるあらゆる可能な削除シーケンスが考慮されます。 各ステップで、残りの各桁を削除し、結果の数値が素数かどうかを確認します。 再帰的に処理を進めると、各ノードが最大 d 個の子を持つツリーになります (d は現在存在する桁数です)。 

初期の長さは最大でも 10 なので、最悪の場合でも約 10 を探索することになります。 / 順序付けられた削除の観点からは 2 つのパスですが、より正確には、状態空間はすべてサブシーケンスであるため、最大 1024 の状態とそれらの間の遷移になります。 メモ化のない単純な DFS では、特に削除順序が異なると同一の残りの文字列が生成される可能性があるため、同じ桁の構成を繰り返し再利用することになります。 これは実際には指数関数的な爆発につながります。 

重要な観察は、プロセスの状態は、どのようにしてそこに到達したかではなく、残っている桁とその順序によって完全に決定されるということです。 これは、各状態を桁位置のビットマスクとしてモデル化できることを意味します。 どのマスクからでも、正確に 1 ビット少ないビットが設定されたマスクに移行できます。 問題は、デコードされた数が素数であるノードのみを通過するという制約のもとで、ノードが数字のサブセットであり、エッジが 1 つの数字の削除を表す有向非巡回グラフの最長パスになります。 

桁数は最大 10 であるため、各状態の素数性を直接評価し、サイズの小さい順にサブセットに対して動的計画法を実行できます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての削除シーケンスに対するブルート フォース DFS | お(ん!) | O(n) | 遅すぎる |
 | 状態ごとの素数チェックを行うサブセット DP | O(2^n * n) | O(2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 数字の各サブセットを状態として扱います。 

1. 入力数値を数字の文字列に変換し、各位置にインデックスを割り当てます。 これにより、残りの構成をビットマスクとして表すことができます。 
2. 0 から (1 << n) - 1 までのすべてのマスクを事前計算します。マスクごとに、数字を順番に読み取り、先頭のゼロをスキップして、対応する数値を構築します。 結果の文字列が空になった場合、そのマスクは無効であるとして無視されます。 
3. 有効なマスクごとに、その数値が素数であるかどうかを確認します。 形成される数値は最大 10 桁であるため、sqrt(x) までの決定的な素数性テストで十分です。 
4. DP 配列を定義します。ここで、dp[mask] は、この構成から始まる連続する有効な素数状態の最大数を表します。 
5. 現在の設定自体は 1 回の出現としてカウントされるため、素数を形成するすべてのマスクに対して dp[mask] = 1 を初期化します。 
6. ビット数の降順でマスクを処理し、より大きな構成がより小さな構成よりも前に解決されるようにします。 
7. 素数のマスクごとに、設定されている各ビットを削除して新しいマスクを形成してみます。 結果のマスクが有効な数値 (空ではない) を形成し、素数である場合は、dp[mask] = max(dp[mask], 1 + dp[next_mask]) として dp[mask] を更新します。 
8. 答えは dp[full_mask] です。ここで、full_mask は最初に存在するすべての桁に対応します。 

この順序付けが機能する理由は、すべての遷移で設定ビット数が厳密に削減されるため、ビット数を減らして処理することですべての依存関係が確実に計算されるためです。 

### なぜ効果があるのか

 各状態は、厳密に小さい桁のサブセットのみに依存します。 これにより、サイズ順に並べられたマスク上の DAG が誘発されます。 DP は、この DAG 内の最長の有効なチェーンを計算します。ただし、有効性は素数によって制限されます。 すべてのパスは一連の削除に正確に対応し、すべての有効な削除シーケンスは 1 つのパスに対応するため、DP は重複や省略なしにすべての可能性をカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(x: int) -> bool:
    if x < 2:
        return False
    if x % 2 == 0:
        return x == 2
    i = 3
    while i * i <= x:
        if x % i == 0:
            return False
        i += 2
    return True

def build_value(digits, mask):
    val = 0
    for i in range(len(digits)):
        if mask & (1 << i):
            val = val * 10 + digits[i]
    return val

def solve():
    s = input().strip()
    digits = list(map(int, s))
    n = len(digits)

    size = 1 << n
    valid = [False] * size
    val = [0] * size

    for mask in range(size):
        v = build_value(digits, mask)
        val[mask] = v
        if v > 0:
            valid[mask] = True

    prime = [False] * size
    for mask in range(size):
        if valid[mask]:
            prime[mask] = is_prime(val[mask])

    dp = [0] * size

    masks = list(range(size))
    masks.sort(key=lambda m: bin(m).count("1"), reverse=True)

    for mask in masks:
        if not prime[mask]:
            continue
        dp[mask] = 1
        i = 0
        while i < n:
            if mask & (1 << i):
                nxt = mask ^ (1 << i)
                if valid[nxt] and prime[nxt]:
                    dp[mask] = max(dp[mask], 1 + dp[nxt])
            i += 1

    full = (1 << n) - 1
    if not prime[full]:
        print(0)
    else:
        print(dp[full])

if __name__ == "__main__":
    solve()
```実装の詳細の核となるのはマスク表現です。 数字の各サブセットはビットマスクとしてエンコードされ、変換関数によって数値が O(n) に再構築されます。 n ≤ 10 であるため、このオーバーヘッドは 1024 のすべての状態であっても無視できます。 

よくある落とし穴は、先行ゼロを正しく正規化できないことです。 数字を整数に累積するだけなので、構築関数はそれらを暗黙的に削除します。 先行ゼロは値に寄与しません。 

もう 1 つの微妙な点は、空のマスクの処理です。 値 0 が生成されますが、これは無効であり、素数の考慮から除外されます。 

## 実用的な例

 元のステートメントには判読可能なサンプルが含まれていないため、説明用のサンプルを作成します。 

入力 103 を考えてみましょう。 

マスクを列挙します。 

| マスク | 数字 | 値 | プライム | DP |
 | --- | --- | --- | --- | --- |
 | 111 | 103 | 103 | はい | 2 |
 | 101 | 13 | 13 | はい | 1 |
 | 011 | 03→3 | 3 | はい | 1 |

 103 から、数字 1 を削除すると 03 になり、3 になります。数字 0 を削除すると、13 になります。どちらも素数ですが、この小さな例では 13 だけがそれ以上継続しません。一方、3 は終端です。 最高の連鎖は 103 → 13 で 2 になります。 

ここで入力 2357 を考えてみましょう。 

すべての数字は素数ですが、途中で削除すると 237 や 257 などの素数以外の数字が生成される場合があります。DP はすべてのサブセットを探索し、最も長い有効なチェーンを選択します。 

| マスク | 値 | プライム | DP |
 | --- | --- | --- | --- |
 | 1111 | 2357 | はい | 2+ |
 | 1110 | 235 | いいえ | 0 |
 | 1101 | 237 | いいえ | 0 |
 | 1011 | 257 | はい | 1 |

 2357 以降、特定の欠失のみが素数を保持し、dp は最も長く生き残ったパスを捕捉します。 

これらの例は、答えが数字の値だけではなく、数字の配置の構造に依存することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(2^n * n + 2^n * sqrt(10^9)) | 各サブセットは、n ≤ 10 | で素数性について評価およびテストされます。 
| スペース | O(2^n) | すべてのマスクにわたる DP、有効性、および値の配列 |

 桁制限が小さいため、指数サブセット係数が小さいままになります。 素数チェックを行っても、2^10 は 1024 にすぎないため、合計作業量は十分に制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from math import sqrt

    # inline solution
    def is_prime(x: int) -> bool:
        if x < 2:
            return False
        if x % 2 == 0:
            return x == 2
        i = 3
        while i * i <= x:
            if x % i == 0:
                return False
            i += 2
        return True

    s = input().strip()
    digits = list(map(int, s))
    n = len(digits)
    size = 1 << n

    def build(mask):
        v = 0
        for i in range(n):
            if mask & (1 << i):
                v = v * 10 + digits[i]
        return v

    val = [build(m) for m in range(size)]
    prime = [v > 0 and is_prime(v) for v in val]

    dp = [0] * size
    masks = sorted(range(size), key=lambda m: bin(m).count("1"), reverse=True)

    for m in masks:
        if not prime[m]:
            continue
        dp[m] = 1
        for i in range(n):
            if m & (1 << i):
                nxt = m ^ (1 << i)
                if prime[nxt]:
                    dp[m] = max(dp[m], 1 + dp[nxt])

    full = size - 1
    return str(dp[full] if prime[full] else 0)

# custom cases
assert run("2") == "1"
assert run("4") == "0"
assert run("13") == "2"
assert run("103") == "2"
assert run("2357") == run("2357"), "consistency check"

 ## 特殊なケース

 入力 101 の場合、中央の数字を削除すると素数である 11 が生成されますが、端の数字を削除すると 01 が生成され、これは 1 になり素数ではありません。 正しく実装するには、01 が 1 として解釈されて拒否されるようにする必要があります。そうしないと、チェーンが誤って拡張されてしまいます。 

入力 2 の場合、空ではない数値を保持する有効な削除はありません。 プロセスはすでに素数で開始されているため、アルゴリズムは初期状態に dp[mask] = 1 を正しく割り当て、1 を返します。 

入力 10 の場合、0 を削除すると素数ではない 1 が生成され、1 を削除すると無効な 0 が生成されます。 DP は両方の遷移が失敗することを保証します。開始番号が素数ではないため、答えは 0 になります。 

入力 37 の場合、両方の桁が素数ですが、1 桁を削除すると 3 または 7 になり、どちらも素数のままです。 DP では、最長のチェーンは 2 であり、1 桁に達するとそれ以上の移動は不可能であると捉えています。
