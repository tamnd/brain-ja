 ## 解決策
 ## 問題の理解

 各セルに幼虫を表す非負の数が含まれる長方形のグリッドが与えられます。 ハムスターは左上のセルから開始し、右下のセルに到達する必要があります。 すべてのステップで、エッジを共有する隣接セルに移動し、どのセルにも再度アクセスすることはありません。 細胞に侵入するたびに、すべての幼虫がそこに集まります。 

タスクは、収集された幼虫の合計を最大化する、セルを再訪問することなく、最初から最後まで有効な歩行を選択することです。 

この制約により、グリッドは最大 1000 × 1000、つまり最大 100 万セルまで許可されます。 グリッド内の単純なパスの数は指数関数的に増加するため、パスを明示的に列挙しようとするソリューションは直ちに実行不可能になります。 パスごとの状態を保存したり処理したりすることさえ不可能です。 各セルを一定回数処理するか、線形または線形に近い複雑さのグラフ構造を使用するソリューションを期待する必要があります。 

微妙な点は、ハムスターが細胞を再訪問することは許可されていないが、それ以外の点では動きは制限されていないことです。 これはグリッド グラフのハミルトニアン パス制約のように聞こえますが、開始点と終了点が反対側の角に固定されており、これは任意のパス検索ではなく構造化された走査を強く示唆しています。 

エッジ ケースは、グリッドが非常に小さい場合、または最適なルートが直感的に価値の高い領域を再訪問することを「望む」場合に発生します。 たとえば、2 x 2 グリッドの場合は次のようになります。```
1 100
100 1
```単純に貪欲なアプローチでは、100 に到達し、さらに 100 に到達しようとするかもしれませんが、それには再検討するか、不可能な後戻りが必要です。 この制約ではサイクルが禁止されているため、ソリューションでは単一の単純なパスを尊重する必要があります。 

もう 1 つのエッジ ケースは、左上から右下への単調パスの一部ではないセルに大きな値があり、アルゴリズムがローカルではなくグローバルに推論することを強制される場合です。 

## アプローチ

 強引な解釈では、これを、各セルが重みを持つノードであり、エッジが 4 つの近傍を接続するグリッド グラフの最長パス問題として扱うことになります。 (0,0) から (N-1,M-1) までの最大重みの単純なパスが必要です。 

単純な DFS は、可能なすべてのパスを探索し、訪問したセルをマークしながら合計を蓄積します。 各セルには最大 4 つの手があり、再訪問は禁止されていますが、分岐係数は高いままです。 1000 × 1000 のグリッドでは、検索空間のごく一部であっても組み合わせ的に爆発します。 NM ではグリッド内の単純なパスの数が指数関数的に増加するため、このアプローチは完全に実行不可能です。 

重要な観察は、再検討は禁止されているものの、問題の構造は実際には恣意的な後戻りの選択を必要としないということです。 グリッドは平面であり、開始点と終了点は対角にあるため、有効な単純なパスはグリッドを左右の領域に分割します。 これは、問題が、セルの適切な順序付けによって引き起こされる有向非環状構造内の最大重みパスを見つけることに帰着できることを示唆しています。 

これを利用する標準的な方法は、非周期性を尊重する一貫したトラバース方向を強制することです。 順序付けにおいて以前の状態を決して再訪しない方向への移動のみが許可されるようにエッジの向きを設定すると、DAG が得られます。 その場合、問題は DAG 内の最長パスとなり、動的プログラミングで解決できます。 

このような最も単純な順序付けは、行と列による辞書編集的なもので、制約に違反することなく現在のセルに到達できる、以前に処理された状態からの遷移のみを許可します。 実際には、これは、各セルが許可された先行セルからセルに到達するための最適な方法を集約するグリッド上の DP に減少します。 

したがって、パスを明示的に探索する代わりに、各セルについて、そのセルで終了し、すでに計算されている隣接セルから遷移するときに達成可能な最大合計を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 単純なパス上のブルート フォース DFS | O(4^(NM)) | O(NM) 再帰 | 遅すぎる |
 | グリッド DP (DAG 最短/最長パス) | O(NM) | O(NM) | 承認済み |

 ## アルゴリズムのチュートリアル

 DP テーブルを定義します。ここで dp[i][j] は、セルを再訪問しない横断でセル (i, j) に到達したときに収集可能な幼虫の最大数を表します。 

1. 開始セルの値である dp[0][0] を除き、非常に小さな値で dp を初期化します。 これは、北西の角から幼虫だけを連れて旅を始めることを表しています。 
2. セルを行の昇順に処理し、各行内で列の昇順に処理します。 これにより、dp[i][j] を計算するときに、すべての潜在的な先行状態がすでに考慮されることが保証されます。 
3. 各セル (i, j) について、順方向のみの処理構造に違反しない有効な先行セルからの遷移を考慮します。 標準的なグリッド DAG 定式化では、これらは行優先順で (i, j) より前に処理されることが保証されている唯一のセルであるため、通常は (i-1, j) と (i, j-1) からのものになります。 
4. dp[i][j] を現在の値の最大値として更新し、i > 0 の場合は dp[i−1][j] + Grid[i][j]、j > 0 の場合は dp[i][j−1] + Grid[i][j] を更新します。これにより、(i, j) で終わる最適なパスが確実に取得されます。 
5. テーブルに記入すると、答えは dp[N-1][M-1] になります。これは、南東の隅に到達する最良の有効なパスに対応します。 

### なぜ効果があるのか

核となる不変条件は、dp[i][j] が処理順序を尊重し、セルを再訪問しない、開始点から (i, j) までの有効なパスの最大可能合計を常に格納することです。 すべての遷移は以前に処理されたセルからのみ発生するため、将来のセルを暗黙的に再利用できるパスはなく、順序と一致するすべての単純な単調パスは 1 回だけとみなされます。 左上から任意のセルまでのすべての有効なパスは、処理された隣接セルの 1 つからの最終ステップに分解できるため、最適な部分構造が保持され、再帰によってすべての実行可能なソリューションが完全に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]
    
    dp = [[0] * m for _ in range(n)]
    dp[0][0] = grid[0][0]
    
    for i in range(n):
        for j in range(m):
            if i == 0 and j == 0:
                continue
            best = -10**18
            if i > 0:
                best = max(best, dp[i-1][j])
            if j > 0:
                best = max(best, dp[i][j-1])
            dp[i][j] = best + grid[i][j]
    
    print(dp[n-1][m-1])

if __name__ == "__main__":
    solve()
```このソリューションでは、グリッド上の単純な動的プログラミング テーブルを使用します。 各セルは、走査順序で許可された先行セルからの達成可能な最良の合計を累積します。 (0,0) での初期化は計算を固定します。 

唯一の微妙な実装の詳細は、境界を正しく処理することです。 最初の行では、左の遷移のみが有効です。 最初の列では、上向きの遷移のみが有効です。 他のすべてのセルは両方の最大値を安全に取得します。 大きな負の初期値を使用すると、`best`すべての値がゼロの場合でも正確さを保証します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(NM) | 各セルは O(1) 回の遷移で 1 回処理されます。 
| スペース | O(NM) | DP テーブルはセルごとに 1 つの値を格納します。 

グリッド サイズは 100 万セルに達する可能性があるため、高速 I/O と単純な演算を使用して実装された場合、O(NM) ソリューションが最適であり、Python の一般的な制約内に快適に適合します。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべてのセルがゼロである場合です。 すべてのパスの重みが等しいため、DP は特別な処理を行わなくてもゼロを返すはずです。 

入力：```
2 2
0 0
0 0
```DP は dp[0][0] = 0 を初期化し、全体にゼロを伝播します。 遷移ごとにゼロが追加されるため、dp[1][1] はゼロのままになります。 

もう 1 つのエッジ ケースは、最高値が直接の直線パス上にないが、単調な動きを尊重する迂回路を介して含める必要がある場合です。 DP は、早期に単一の方向にコミットせず、すべてのセルで両方の受信状態を比較し、達成可能な最良の累積を保存するため、これを自然に処理します。
