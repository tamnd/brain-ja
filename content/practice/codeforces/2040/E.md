 ## 問題の理解

 無向接続された非循環グラフであるツリーが与えられます。`n`頂点をルートとする頂点`1`。 ロボットはある頂点からスタートします`v ≠ 1`そして根元に向かって進みます。 奇数のステップは決定的です。ロボットは常に頂点に向かって最短経路に沿って 1 ステップ移動します。`1`。 偶数番号のステップでは選択が可能です。コインを支払ってルートに向かって決定的な移動を強制するか、ロボットを隣接する頂点にランダムに移動させることができます。 から始めます`p`コインをいつ使用するかを最適に決定する必要があります。 目標は、ロボットが頂点に到達するために予想される最小ステップ数を計算することです。`1`。 

入力は複数のテスト ケースで構成され、それぞれがツリーと複数のクエリを提供します。 各クエリは開始頂点とコインの数を指定します。 出力は単一の整数モジュロです`998244353`、予想されるステップ数をモジュラー分数の形式で表します。 

制約は頂点の数を示します。`n`テストケースでは以下を超えない`2000`、すべてのテスト ケースにわたる頂点の合計も`2000`。 クエリ数`q`テストケースごとに最大でも`2000`。 これは、`O(n^2)`テストケースごとのソリューションは実行可能ですが、何でも`O(n^3)`それ以上では遅すぎる可能性があります。 また、制約が小さいため、メモリ制限を気にすることなく、分数を使った正確な演算や動的プログラミングが可能になります。 

明らかではないエッジケースは次のような場合です。`p`がゼロに等しいか、ロボットはルートから 1 歩離れています。 たとえば、ロボットが隣接するリーフ ノードから開始すると、`1`そして`p = 0`、ロボットは奇数ステップで決定論的に動きますが、最初の偶数ステップでランダム性が生じる可能性があります。 これを正しく処理するには、強制されたコインのみが期待値に影響を与えることを理解する必要があります。 コインの支出を考慮せずに単純に平均すると、間違った答えが得られる可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、指定された数のコインを使用して、開始頂点からのロボットのあらゆる可能な一連の動作をシミュレートします。 ルートに向かって移動するか、隣接する頂点にランダムに移動する確率を考慮して、各ステップを再帰的に列挙します。 各分岐は確率を乗算し、予想される歩数を合計します。 これは非常に小さなツリーには機能しますが、コインを使用しない偶数ステップごとにパスの数と現在のノードの次数が乗算されるため、分岐係数は指数関数的に増加します。 ある木については、`2000`ノードの場合、ブルート フォースは最大で`2^n`パス、これは不可能です。 

重要な観察は、ツリー構造がルートに向かって自然な順序を課しているということです。 各頂点には、ルート ツリー内に一意の親が存在します。 奇数のステップは決定的であるため、偶数の動きに対して予想されるステップのみを計算する必要があります。 偶数ステップでは、最適な戦略は、決定論的に移動するためにコインを支払うか、ランダムに移動する場合は期待値を受け入れるかのいずれかです。 定義すると`f[v][c]`頂点から開始してルートに到達するまでの予想されるステップ数として`v`と`c`コインが利用可能であれば、動的プログラミングを使用できます。 リーフからルートまでの計算により、各頂点の期待値がその子と親のみに依存することが保証されます。 確率には分数演算が必要ですが、逆モジュラーを使用すると、すべてをモジュロで計算できます。`998244353`。 

確率が指数関数的に分岐するため、総当たり攻撃は失敗するという話です。 奇数のステップは決定的であり、偶数のステップのみが期待値を作成することを認識すると、問題を DP over に減らすことができます。`(vertex, coins)`ペア。 ツリー構造と制限されたコイン数により、これが可能になります。`O(n^2)`実現可能。

 ## アルゴリズムのチュートリアル

 1. ツリーの頂点にルートを作成します`1`すべての頂点の親関係と子リストを計算します。 これにより、各頂点がどの頂点に向かって移動するかを決定的に認識できるようになります。 
2. 各頂点について`v`そしてコインの数`c`、 定義する`dp[v][c]`ルートに到達するまでに予想される最小ステップ数として。 初期化する`dp[1][c] = 0`みんなのために`c`ロボットはすでにルートにあるためです。 
3. BFS または DFS の順序で、リーフからルートに向かって頂点を処理します。 頂点の場合`v ≠ 1`、初手は奇妙です。 ロボットは親に向かって決定的に移動します`u`。 したがって、`dp[v][c]`から始まる`1 +`親からの期待値。次の偶数ステップを考慮します。 
4. 偶数ステップで、2 つのオプションを計算します。コインを使ってルートに向かって決定的に移動します (`dp[parent][c-1] + 1`) またはランダムな移動を許可します。 ランダムに移動する場合の期待値は、隣接するすべての頂点の平均です。`w`の`dp[w][c] + 1`、確率で重み付け`1/degree(v)`。 DP値`dp[v][c]`これら 2 つのオプションの最小値です。 
5. 分数の剰余を避けるには`998244353`、逆モジュラーを使用して計算します。 たとえば、頂点に`k`隣接するものでは、ランダムな移動に対する期待値が次のように乗算されます。`k^{-1} mod 998244353`。 
6. 各クエリについて`(v_i, p_i)`、出力`dp[v_i][p_i]`。 

これが機能するのは、DP がすべての最適なコイン支出戦略を確実に考慮するためです。 不変条件というのは、`dp[v][c]`から始まる最小予想ステップ数を常に保存します。`v`と`c`子から親まで計算されるコイン。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        edges = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            edges[u].append(v)
            edges[v].append(u)

        parent = [0] * (n + 1)
        children = [[] for _ in range(n + 1)]
        degree = [0] * (n + 1)

        def dfs(u, p):
            parent[u] = p
            for v in edges[u]:
                if v == p:
                    continue
                children[u].append(v)
                dfs(v, u)
        dfs(1, 0)

        max_coins = n
        dp = [[0] * (max_coins + 1) for _ in range(n + 1)]

        for u in range(2, n + 1):
            for c in range(max_coins + 1):
                degree[u] = len(edges[u])

        for u in range(2, n + 1):
            for c in range(max_coins + 1):
                # Odd step: move to parent
                # Even step: choose min of paying or random
                if c > 0:
                    pay = (1 + dp[parent[u]][c - 1]) % MOD
                else:
                    pay = MOD
                deg = len(edges[u])
                rand_sum = sum((1 + dp[v][c]) % MOD for v in edges[u]) % MOD
                rand = rand_sum * modinv(deg) % MOD
                dp[u][c] = min(pay, rand)

        for _ in range(q):
            v_i, p_i = map(int, input().split())
            print(dp[v_i][p_i] % MOD)

if __name__ == "__main__":
    solve()
```解決策は、ツリー配列と親配列を構築することから始まります。 DP アレイ`dp[v][c]`予想される歩数を追跡します。 モジュラー逆関数は、ノード次数による除算を処理して、ランダムな移動の期待値を計算します。 コインを使うかロボットをランダムに動かすかの最小値によって、最適な選択が決まります。 各クエリへの回答は次のとおりです。`O(1)`事前に計算された DP テーブルを使用します。
