 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列を扱うように求められます。各順列には、連続するすべての部分配列を取得し、その最小値を加算することによって定義される合計が含まれます。 長さ n のすべての順列の中で、いくつかの順列がこの合計を最大化します。 整数 k が与えられた場合、辞書順で合計が最大になる k 番目の順列を生成するか、そのような順列が k 個よりも少ないことを示す必要があります。 

最初の重要な観察は、すべてのサブ配列の最小値の合計を最大化する順列の場合、多くのサブ配列に影響を与える位置で、大きな数値が後で出現し、小さな数値が先に出現する必要があるということです。 具体的には、先頭に小さい数値を配置すると、末尾に配置する場合よりも多くのサブ配列で最小値になることができます。 たとえば、サイズ 3 の順列では、1 が早く現れて複数の部分配列の最小値として寄与するため、合計 S([1,2,3]) は S([2,1,3]) より大きくなります。 

この制約は、n が 2 × 10^5 まで大きくなり得、テスト ケースの数 t が最大 10^4 まで可能であることを示しています。 すべての順列を列挙する単純なアプローチは不可能です。 10^5 よりもはるかに速く成長します。 同様に、各順列の合計 S(p) を直接計算しても、順列ごとに O(n^2) の演算が必要となるため、遅すぎます。 したがって、最大和順列を直接構築し、それらを辞書順に効率的に列挙する方法が必要です。 

明らかでないエッジ ケースには、n = 1 や n = 2 など、最大和順列の数が少ない非常に小さな順列や、k が最大和順列の数を超える順列が含まれます。 たとえば、最大合計を達成する順列は 4 つしかないため、n = 3 および k = 5 では -1 が生成されます。 

## アプローチ

 ブルートフォースアプローチは、すべての n! を生成することです。 順列を作成し、それぞれの S(p) を計算し、最大 S(p) を達成するものを並べ替えます。 これは正しいですが、n ≥ 10 の場合は絶望的に遅くなります。n = 10 の場合、3,628,800 の順列があり、それぞれの S(p) を計算するには O(n^2) が必要となり、3 × 10^8 を超える演算が行われます。 

重要な洞察は、S(p) を最大化する順列の構造を理解することで得られます。 利用可能な最小の数値を残りの位置のできるだけ左に配置すると、合計が最大になります。 最小の数字が配置されると、残りの数字は、目的とする辞書編集上の順序に応じて、増加または減少のシーケンスを形成できます。 これは貪欲で建設的なアプローチにつながります。つまり、連続して増加する数値の左端のブロックを繰り返し選択し、残りの数値を減少する尾部として配置することで順列を構築できます。 各選択肢はカタロニア語のようなカウントに対応しますが、最大合計のパターンは、利用可能な最大の数値から 1 までのブロックを選択することで表すことができるため、問題は単純化されます。 

この構造を使用すると、各ステップで現在のブロックに取り込む数値の数を決定するだけで、すべての順列を生成することなく、辞書順に順列を列挙できます。 これにより、選択ごとに存在する順列の数を事前に計算すると、問題が階乗時間から順列ごとの線形時間に短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! × n^2) | お(ん!) | 遅すぎる |
 | 建設的な貪欲さ | テストあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 1 から n までの全範囲の数値から開始し、次に小さい未使用の数値へのポインタを保持します。 未使用の最小の数値は、S(p) への寄与を最大化するために、常にできるだけ早く出現する必要があります。 
2. 各ステップで、現在の最小の数値から始まる連続的に増加する数値の次のブロックのサイズを決定します。 ブロックの長さの範囲は、1 から未使用の残りの番号の数までです。 
3. 考えられるブロック長ごとに、このブロックを配置した後の残りの数値の順列の数を事前計算します。 このブロック長の順列の合計数が k 未満の場合は、その数を k から減算して、次のブロック長を試します。 それ以外の場合は、このブロック長を修正し、順列に数値を追加し、残りの数値を再帰的に実行します。 
4. すべての数値が使用されるか、k が 1 になるまで続行します。いずれかのステップで、k のカウント要件を満たす有効なブロック長がない場合は、-1 を報告します。 
5. すべての数値が配置されたら、順列を出力します。 

機能する理由: このアルゴリズムが機能するのは、より小さい数値が前の位置を占めるときに合計 S(p) が最大化され、貪欲な選択が強制されるためです。 各ブロックの選択後に可能な順列の数をカウントすることで、すべての順列を生成しなくても、辞書順で k 番目の順列に効率的に移動できます。 不変条件は、各ステップで、これまでに構築された順列の接頭語が何らかの最大和順列の一部であり、残りの数値は最大性を維持する任意の順序で配置できるということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    import sys
    from math import comb
    input = sys.stdin.readline

    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        result = []
        left, right = 1, n
        while left <= right:
            # Compute number of permutations if we place 'left' at current position
            cnt = 1 << (right - left)  # 2^(right-left) possible block choices
            if k > cnt:
                k -= cnt
                result.append(right)
                right -= 1
            else:
                result.append(left)
                left += 1
        if k > 1:
            print(-1)
        else:
            print(' '.join(map(str, result)))

if __name__ == "__main__":
    solve()
```このソリューションでは、未使用の最小値と最大値を表す 2 つのポインター (左右) を維持するという貪欲なアプローチが使用されます。 2^(右-左) カウントは、それ以降に達成可能なすべての最大合計の順列を反映します。 各ステップで、k が現在のブロック選択の範囲内に収まるかどうか、またはいくつかの順列をスキップするために最初に大きい数を移動する必要があるかどうかを確認します。 これにより、すべての順列を明示的に生成することなく、辞書編集上の順序を効率的にナビゲートできます。 

## 実用的な例
