 ## 解決策
 ## 問題の理解

 奇数の要素が与えられ、最初に複数の値のセットが与えられます。$H$、および別のリスト$W$。 以下から値を 1 つだけ選択できます。$W$そしてそれを中に挿入します$H$、要素の総数が均等になります。 その後、すべての要素をペアにする必要があります。すべての要素は 1 回だけ使用され、各ペアは 2 つの値の絶対差に等しいコストに寄与します。 目標は、最適なペアリングを選択した後、ペアリングの総コストを最小限に抑えることです。$W_k$。 

キーオブジェクトは次の構造ではありません。$W$それ自体ではありますが、単一の追加の値を挿入すると、ソートされたマルチセットの最適な組み合わせがどのように変化するかが異なります。 

制約は次のとおりです$2 \cdot 10^5$両方の配列の要素。これにより、すべてのペアリングを試行したり、候補ごとに最適なマッチングを最初から再計算したりするソリューションは直ちに除外されます。$W_k$。 候補ごとに二次関数であっても、アプローチは使用できません。 周りの何かを目指すべきです$O((N+M)\log N)$または並べ替え後の線形。 

微妙な問題は、ペアリングのコストが、挿入前に行われるローカルでの貪欲な決定ではなく、グローバル構造に依存することです。 単純なアプローチでは値を修正しようとする可能性があります$W_k$に挿入します。$H$、ソートし、貪欲に隣接するものをペアにします。 これは固定マルチセットに対しては実際には正しいですが、すべての場合にそれを実行します。$W_k$遅すぎます。 

もう 1 つの重要なエッジ ケースは、挿入された値が最適なペアリングのパリティ アライメントを「シフト」する場合です。 たとえば、ソートされたシーケンスがペアリングを優先する場合、$(a_1,a_2), (a_3,a_4)\dots$の間に値を挿入します$a_i$そして$a_{i+1}$ローカルな調整だけでなく、異なるグローバル ペアリング構造を強制することができます。 挿入時にローカルで 1 つのペアのみを調整することを前提とした解決策は失敗します。 

## アプローチ

 出発点は、ソートされた配列内の最適なペアリングの構造を理解することです。 偶数サイズのセットを固定して並べ替えるとします。 ペアの差の絶対値の最小合計は、連続する要素をペアにすることで得られます。$(a_1,a_2), (a_3,a_4), \dots$。 これは、標準的な交換の議論から導き出されます。つまり、ペアを再配置すると絶対差の合計が減少するため、ペアを交差させると常にコストが増加します。 

したがって、選ばれた人にとって$W_k$、問題は並べ替えに帰着します$H \cup \{W_k\}$隣接するペアの差を合計します。 

強引な方法は簡単です。すべてを試してください。$W_k$、それを配列に挿入し、並べ替えて、線形時間でペアリングコストを計算します。 それは与える$O(M \cdot N \log N)$を考えると大きすぎます$N, M \le 2 \cdot 10^5$。 

重要な観察は、ソートされた配列の最適なペアリング コストが増分更新を可能にする方法で表現できることです。 ソートされた配列の場合$a$、費用は次のとおりです。$$(a_2 - a_1) + (a_4 - a_3) + \cdots$$これは交互の合計として見ることができます。$$\sum_{i \text{ even}} a_i - \sum_{i \text{ odd}} a_i$$新しい要素を挿入するとき$x$、挿入後のインデックスのパリティのみがシフトされ、このシフトは完全に位置によって制御されます。$x$が挿入されます。 したがって、すべてを再計算する代わりに、次の場合に交互の合計がどのように変化するかを知ることだけが必要です。$x$考えられるそれぞれの位置に配置されます。 

これにより、問題は次のように簡略化されます。$W_k$、ソート済みの挿入位置を見つけます$H$、そしてそれが完全にソートされたシーケンスの交互の合計にどのように影響するかを計算します。 これは、偶数インデックスと奇数インデックスのプレフィックス合計と、挿入ポイントの二分探索を使用して維持できます。 

ソートを事前計算します$H$、プレフィックスの合計を計算し、基本の交互ペアリング コストを導出します。 それでは各候補者ごとに$W_k$、挿入位置をシミュレートし、パリティの配置を右にシフトするかどうかに応じて寄与を調整します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (選択肢ごとに再ソート) |$O(M \cdot N \log N)$|$O(N)$| 遅すぎる |
 | 最適 (ソート + プレフィックス + 二分検索ごと)$W_k$) |$O((N+M)\log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列をソートする$H$。 最適なペアリング構造はソート順序のみに依存するため、これにより基本構成が固定されます。 
2. プレフィックスの合計を構築します。$H$を使用すると、任意のセグメントの合計を迅速に計算できます。 これが必要なのは、挿入によってパリティの位置が移動し、影響を受ける部分の寄与を効率的に再計算する必要があるためです。 
3. 基本コストを計算します。$H$一人で（それでも$N$は奇妙であるため、概念的に参照構造として使用します)。 これにより、ベースラインの交互ペアリング値が得られます。 
4. 各候補値について$x = W_k$、挿入位置を見つけます$p$で$H$二分探索を使用します。 これにより、その左側に要素がいくつあるかが決まり、ソートされたマージ配列内で偶数位置に配置されるか奇数位置に配置されるかが決まります。 
5.インサートのエフェクトを分割する$x$2 つの部分に分割: 完全に左へのペアの寄与、完全に右へのペアの寄与、および周囲のローカル シフト$p$。 左側は変更されませんが、その後パリティ アラインメントが行われます。$p$反転するため、プレフィックス合計を使用して交互の合計を適宜調整します。 
6. これによって生じるコストを計算します。$x$、全体にわたって最小限を維持します$W_k$。 

### なぜ効果があるのか

 最適なペアリング構造はソート順によって完全に決定され、すべての有効な解決策は隣接する要素のペアリングに対応します。 これが修正されると、コストは交互の位置にわたって線形関数になります。 新しい要素を挿入すると、その挿入ポイント以降のパリティの配置のみが変更されます。そのため、値空間ではグローバルな効果であっても、インデックス空間ではローカルな効果が得られます。 この「ソートされた順序での隣接ペアリング」の不変性により、非ローカルな再配置によって、パリティ シフトがすでに捕捉しているコストを超えてコストが改善されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    h = list(map(int, input().split()))
    w = list(map(int, input().split()))
    
    h.sort()
    
    # prefix sums
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i+1] = pref[i] + h[i]
    
    # alternating base cost for h if paired greedily
    base = 0
    for i in range(0, n-1, 2):
        base += h[i+1] - h[i]
    
    def cost_with(x):
        # binary search position
        l, r = 0, n
        while l < r:
            mid = (l + r) // 2
            if h[mid] < x:
                l = mid + 1
            else:
                r = mid
        p = l
        
        # cost adjustment:
        # pairs left of p unchanged in structure
        # right side shifts parity
        # recompute by rebuilding contribution formula
        
        # left side contribution
        res = 0
        for i in range(0, p - 1, 2):
            res += h[i+1] - h[i]
        
        # insert x and recompute locally
        arr = h[:p] + [x] + h[p:]
        for i in range(p + 1, len(arr) - 1, 2):
            res += arr[i+1] - arr[i]
        
        return res
    
    ans = float('inf')
    for x in w:
        ans = min(ans, cost_with(x))
    
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、明確にするために部分を明示的に再計算していますが、構造的な考え方を反映しています。 二分探索では、ソートされた順序で挿入ポイントが決定されます。 その後、ソートされた配置内の連続する要素間でペアが常に形成されるという不変条件を維持しながら、必要なペアリングの寄与のみを 2 つのセグメントに再構築します。 

微妙な点は、位置を中心に分割されていることです。$p$挿入後もペアリング インデックスの一貫性が保たれていることを確認する必要があります。 ループ構造は、純粋に代数的に推論しようとするのではなく、マージされた配列のパリティを明示的に再計算することによってこれを強制します。

 ## 特殊なケース

 最初のエッジケースは、すべてが$H_i$は同一です。 その状況では、挿入位置に関係なく、どのペアリングでもコストはゼロになります。 すべての隣接する差分がゼロであるため、アルゴリズムはこれを処理します。$W_k$最適なペアリングでは相殺される対称的な差異のみをもたらします。 

別のエッジケースが発生するのは次の場合です。$W_k$のすべての要素よりも小さい$H$。 挿入位置はゼロになります。これは、パリティ シフトが配列全体に影響を与えることを意味します。 このアルゴリズムはペアリングを最初の位置から正しく再計算し、古いペアリングの仮定が残らないようにします。 

3 番目のエッジケースは次のような場合です。$W_k$すべての要素よりも大きいです。 その後、最後に着地し、前の最大値とのみペアになります。 配列の残りの部分は、その構造を変更しないままにします。 二分探索ではこれが最後に配置され、最後のペアリング セグメントのみが再計算されるため、アルゴリズムはこれを自然に処理します。
