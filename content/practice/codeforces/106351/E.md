 ## 解決策
 ## 問題の理解

 私たちは持っています`n`番号が付けられたレゴピースのタイプ`1`に`n`、そして各位置がそこに配置されたピースのタイプを示す配列。 あらゆるクエリに対して`[l, r]`、これら 2 つの位置の間の部分のみを調べ、そのセグメントに現れないタイプを印刷する必要があります。 

課題は、1 つのセグメントで欠落しているタイプを見つけることではありません。 簡単なスキャンでセグメント内のすべてのタイプをマークし、欠落しているタイプを見つけることができます。 困難は、以下のものがあることから生じます。`200000`クエリの場合、その作業を繰り返すとコストがかかりすぎます。 この問題では、同じ配列に対する多くの独立した範囲クエリに答えることが求められます。 

と`n`そして`q`どちらも到達`2 * 10^5`、`O(nq)`ソリューションは次のように実行されます`4 * 10^10`通常の制限時間をはるかに超えた作戦です。 すべてのクエリに対して頻度配列を再構築するだけでも時間がかかりすぎます。 すべてのクエリをまとめて処理し、各クエリにおおよそ対数的な時間がかかるようにする必要があります。 

不注意な実装が失敗する可能性がある特殊なケースがいくつかあります。 

クエリが配列のほぼ全体をカバーする場合、欠落しているタイプは 1 つだけである可能性があります。 例えば：```
Input
5 1
1 2 3 4 1
1 4
```セグメントには以下が含まれます`1, 2, 3, 4`、したがって、答えは次のようになります。`5`。 グローバルに出現する値のみをチェックし、答えが範囲に依存することを忘れた実装では、間違った値が返される可能性があります。 

最小の欠損値が最初のタイプではない場合でも、検索ロジックはそれを正しく見つける必要があります。 例えば：```
Input
5 1
1 2 4 5 1
1 5
```配列全体には以下が含まれます`1, 2, 4, 5`、したがって、答えは次のとおりです`3`。 最初のいくつかの値のみをチェックする方法や、欠損値が終わり近くにあると想定する方法は失敗します。 

長さ 1 の範囲は、別の境界ケースです。```
Input
5 1
1 2 3 4 5
3 3
```セグメントにはタイプのみが含まれます`3`、つまり、いずれかの`1, 2, 4, 5`有効です。 アルゴリズムは、特別な場合を除き、単一の位置を処理する必要があります。 

## アプローチ

 直接的なアプローチは、各クエリを個別に処理することです。 お問い合わせの場合`[l, r]`、サブ配列をスキャンし、表示されるすべての LEGO タイプをマークしてから、次のタイプをスキャンします。`1`に`n`マークされていないものを見つけるまで。 

マークされた値はクエリされたセグメントに存在する部分そのものであるため、これは正しいです。 ただし、コストが高すぎます。 最悪の場合、クエリですべてをカバーできる可能性があります。`n`要素があり、`q`そのようなクエリ。 走行時間は、`O(nq)`、それは約です`4 * 10^10`両方の値が次の場合の演算`200000`。 

有益な観察は、各クエリではなく、各 LEGO タイプの観点から問題を観察することで得られます。 配列を左から右に処理し、その位置で停止するとします。`r`。 すべてのタイプについて、処理された要素内でそのタイプが最後に出現した位置を保存します。 

で終わるクエリの場合`r`、内部に型が存在します`[l, r]`正確に、その最新の発生が少なくとも`l`。 最新の発生が より小さい場合`l`、その型の最新のコピーはまだクエリの前にあります。これは、その型が範囲に存在しないことを意味します。 

したがって、すべてのクエリは次のようになります。 

"最新の出現回数が次の値より小さい最小の型を見つけます`l`。」

 ここで問題となるのは、型の動的検索です。 左から右へのスキャン中、新しい配列要素を読み取るたびに、1 つの型が最新の出現を変更します。 ポイントの更新をサポートし、保存された値がしきい値を下回る最初のインデックスを見つけることができる構造が必要です。 

セグメント ツリーはこれに完全に適合します。 各リーフは 1 つの LEGO タイプを表し、最新のレゴ タイプを保存します。 各内部ノードは、その子の中での最小の最新の出現を保存します。 検索時に、最小値がすでに少なくとも`l`これは、そのセグメント内のすべての型がクエリ内に出現するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(nq)`|`O(n)`| 遅すぎる |
 | 最適 |`O((n+q) log n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. LEGO タイプに基づいてセグメント ツリーを構築します。`1`に`n`。 最初はすべてのタイプに最新のオカレンスが含まれています`0`配列位置がまだ処理されていないためです。 ツリーには、タイプの間隔ごとに最小の最新の出現が格納されます。 
2. クエリを読み取り、適切なエンドポイントごとにグループ化します。 スキャンがクエリに到達すると、クエリを処理します。`r`なぜなら、その時点でセグメント ツリーには、で終わるプレフィックスに関する情報が正確に含まれているからです。`r`。 
3. 配列内を左から右に移動します。 位置決め時`i`タイプが含まれています`x`、タイプのリーフを更新します`x`価値のあるもの`i`。 これにより、現在のプレフィックスに対してすべての型の最新の出現が正しい状態に保たれます。 
4. で終わるすべてのクエリについて`i`、セグメント ツリーで、格納されている最新のオカレンスがクエリの左側のエンドポイントよりも小さい最初のタイプを検索します。`l`。 
5. ツリー検索中は、最初に左側の子を確認します。 左の子の最小値が以下の場合`l`、その子には有効な答えが含まれています。 それ以外の場合、答えは正しい子の中にあるはずです。 これにより、有効な型であれば何でも受け入れられますが、欠落している型は可能な限り最小になります。 

なぜ効果があるのか:

 加工後の位置`r`、すべての型の保存された値は、接頭辞内の最後の出現値となります。`[1, r]`。 型が存在します`[l, r]`その保存された位置が少なくとも`l`。 セグメント ツリー検索では、格納位置が より小さいタイプが返されます。`l`, そのため、その型はクエリ範囲内に出現できません。 この問題では、欠落している型が常に存在することが保証されているため、検索では常に型が見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegmentTree:
    def __init__(self, n):
        self.n = n
        self.tree = [0] * (4 * n)

    def update(self, node, left, right, idx, value):
        if left == right:
            self.tree[node] = value
            return
        mid = (left + right) // 2
        if idx <= mid:
            self.update(node * 2, left, mid, idx, value)
        else:
            self.update(node * 2 + 1, mid + 1, right, idx, value)
        self.tree[node] = min(self.tree[node * 2], self.tree[node * 2 + 1])

    def find_first(self, node, left, right, limit):
        if self.tree[node] >= limit:
            return -1
        if left == right:
            return left
        mid = (left + right) // 2
        result = self.find_first(node * 2, left, mid, limit)
        if result != -1:
            return result
        return self.find_first(node * 2 + 1, mid + 1, right, limit)

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    queries = [[] for _ in range(n + 1)]
    for idx in range(q):
        l, r = map(int, input().split())
        queries[r].append((l, idx))

    ans = [0] * q
    seg = SegmentTree(n)

    for i in range(1, n + 1):
        seg.update(1, 1, n, a[i - 1], i)

        for l, idx in queries[i]:
            ans[idx] = seg.find_first(1, 1, n, l)

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```セグメントツリークラスは最新の出現位置を保持します。 の`update`新しい配列要素の読み取りはその型に正確に影響するため、この操作では 1 つの LEGO 型のみが変更されます。 

の`find_first`機能が重要な部分です。 ノードの最小値がすでにクエリの左端点以上である場合、そのノード内のすべての型が範囲内に表示されるため、セグメント全体を無視できます。 それ以外の場合は、欠落している 1 つのタイプに到達するまで下降を続けます。 

クエリは適切なエンドポイントによって保存されます。 これにより、高度なオフライン クエリの順序付けが不要になります。 スイープが到達すると`r`、データ構造は、そこで終わるすべてのクエリに答えるために必要な正確なプレフィックスをすでに表しています。 

ツリーでは、LEGO タイプと配列位置に 1 から始まるインデックスが使用されます。 初期出現値は`0`これは、考えられるすべてのクエリ左エンドポイントよりも小さいため、一度も出現したことのない型は自動的に欠落しているとみなされます。

2 番目のクエリの場合:

 | 処理された位置 | 更新されたタイプ | クエリ | セグメントツリーの結果 |

これらのトレースは不変条件を示しています。つまり、ツリーは処理されたプレフィックス内のすべてのタイプの最新の位置を常に格納します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O((n+q) log n)`| 各配列要素によって 1 つのセグメント ツリー更新が行われ、各クエリによって 1 つのツリー検索が実行されます。 |
 | スペース |`O(n)`| クエリ リスト、回答、セグメント ツリーはすべてリニア メモリを使用します。 |

 この制約により、操作ごとにほぼ対数の作業が可能になります。 と`200000`アップデートと`200000`検索の場合、ツリー操作の総数は管理可能です。 

## テストケース```python
import sys
import io

def solve_data(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    class SegmentTree:
        def __init__(self, n):
            self.n = n
            self.tree = [0] * (4 * n)

        def update(self, node, l, r, idx, val):
            if l == r:
                self.tree[node] = val
                return
            m = (l + r) // 2
            if idx <= m:
                self.update(node * 2, l, m, idx, val)
            else:
                self.update(node * 2 + 1, m + 1, r, idx, val)
            self.tree[node] = min(self.tree[node * 2], self.tree[node * 2 + 1])

        def find_first(self, node, l, r, x):
            if self.tree[node] >= x:
                return -1
            if l == r:
                return l
            m = (l + r) // 2
            res = self.find_first(node * 2, l, m, x)
            if res != -1:
                return res
            return self.find_first(node * 2 + 1, m + 1, r, x)

    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    queries = [[] for _ in range(n + 1)]
    for i in range(q):
        l, r = map(int, input().split())
        queries[r].append((l, i))

    ans = [0] * q
    seg = SegmentTree(n)

    for i, x in enumerate(a, 1):
        seg.update(1, 1, n, x, i)
        for l, idx in queries[i]:
            ans[idx] = seg.find_first(1, 1, n, l)

    return "\n".join(map(str, ans))

## 特殊なケース

 配列のほぼ全体をカバーするクエリの場合:```
5 1
1 2 3 4 1
1 4
```スイープが位置に到達`4`。 最近の出来事は次のとおりです。```

type 2 -> 2
type 3 -> 3
type 4 -> 4
type 5 -> 0
```クエリは、出現頻度が以下のタイプを要求します。`1`。 タイプのみ`5`これを満たすので、木は戻ります`5`。 

末尾近くにない欠落しているタイプの場合:```
5 1
1 2 4 5 1
1 5
```配列全体を処理した後:```
type 1 -> 5

type 5 -> 4
```検索は最小のタイプから開始されます。 種類`1`そして`2`範囲内に表示されますが、次のように入力します。`3`最新の出来事があります`0`, なのですぐに返されます。

```加工後の位置`3`、ツリーには最新の出現が含まれます。```
