 ## 解決策
 # 問題の理解

 正の整数のコレクションが与えられます`A`。 別の正の整数を代入する必要があります`B_i`あらゆる要素に影響を与え、あらゆる製品を`A_i * B_i`全く同じ値です。 すべての可能な割り当ての中で、選択されたすべての最小の合計が必要です。`B_i`。 制約は次のとおりです。`N`まで`2 * 10^5`、その間、`A_i`せいぜい`20`。 

重要な制限は、それぞれの値が小さいことです。`A_i`。 関与する可能性のある素因数は少数であるため、すべての積の共通の値は、大規模な汎用アルゴリズムではなく、素因数分解を通じて処理できます。 共通の積の可能な値を試行するソリューションは、答えが入力値よりもはるかに大きくなる可能性があるため、すぐに失敗します。 と`N = 200000`、線形時間に近いアルゴリズムが必要です。 

主なエッジ ケースは、異なる素数累乗を含む値と数値の繰り返しから生じます。 たとえば、入力が次の場合:```
3
2 2 2
```正しい出力は次のとおりです。```
3
```一般的な製品としては、`2`、すべてを与える`B_i = 1`、つまり合計は`3`。 不用意に実装すると、すべての数値を乗算してそれをターゲットとして使用し、はるかに大きな答えが生成される可能性があります。 

もう 1 つの重要なケースは、1 つの数値にすでにより大きな素数のべき乗が含まれている場合です。```
3
2 4 8
```正しい出力は次のとおりです。```
7
```最小の一般的な製品は、`8`、与える`B = [4, 2, 1]`。 共通の積はすべての値で割り切れる必要があるため、一般に、配列内の最大値のみを使用するだけでは十分ではありません。 

# アプローチ

 直接的なアプローチは、可能な限り最小の共通値を検索することです。`X`すべての`A_i`分割する`X`。 一度`X`が既知であるため、各値が強制されます。`B_i = X / A_i`。 共通製品を選択した後には自由が残らないので、これは正しいです。 

ただし、可能な値を試してみると、`X`不可能です。 入力が小さい場合でも、最小公倍数はすぐに大きくなる可能性があり、列挙を可能にする有用な上限はありません。 

問題を変える観察は、共通積がすべての積の正確な最小公倍数でなければならないということです。`A_i`。 有効な共通積はすべて LCM の倍数であり、より大きな倍数を選択しても、すべての値が増加するだけです。`B_i`。 したがって、最適なターゲットは LCM 自体です。 

なぜなら、すべての`A_i`せいぜい`20`、各素因数の最大指数を維持するだけで済みます。`2`に`20`。 たとえば、数値に次のものが含まれている場合、`2`、`4`、 そして`8`、LCM が必要とする`2^3`。 これらの素指数を見つけた後、LCM を再構築し、必要な合計を計算します。

 # アルゴリズムのチュートリアル

 1. 入力に現れるすべての素数の最大電力を数えます。 

すべての値は最大であるため、`20`、関連する素数は次のとおりです。`2`、`3`、`5`、`7`、`11`、`13`、`17`、 そして`19`。 各数値を因数分解するのは継続的な作業です。 
2. これらの最大べき乗から最小公倍数を構築します。 

LCM には、入力数値に必要な最大の指数を持つすべての素因数が含まれます。 これはすべてで割り切れる最小の数です`A_i`。 
3.追加`LCM / A_i`すべての入力値に対して。 

一般的な商品であれば、`LCM`、 それから`A_i * B_i = LCM`、 それで`B_i`は一意に決まります。 

なぜ機能するのか: すべての有効なソリューションは何らかの数値を選択します`X`すべてで割り切れる`A_i`。 そのような最小の数値は LCM です。 その他の有効な`X`LCM の倍数であり、少なくとも同じ大きさであるため、すべての値が作成されます。`X / A_i`少なくとも同じ大きさ`LCM / A_i`。 したがって、LCM の割り当てにより合計が最小化されます。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    primes = [2, 3, 5, 7, 11, 13, 17, 19]
    best = [0] * len(primes)

    for x in a:
        for i, p in enumerate(primes):
            cnt = 0
            while x % p == 0:
                x //= p
                cnt += 1
            if cnt > best[i]:
                best[i] = cnt

    lcm = 1
    for p, e in zip(primes, best):
        lcm *= p ** e

    ans = 0
    for x in a:
        ans += lcm // x

    print(ans)

if __name__ == "__main__":
    solve()
```最初のループでは素数指数を抽出します。 数値が小さいため、一般的な因数分解構造を保存するよりも、繰り返し除算を行う方が高速かつ簡単です。 

変数`best`LCM情報を保存します。 各素数について、これまでに見つかった最大の指数を記憶します。 LCM 再構成では、各素数にその格納されている指数を 1 回だけ乗算します。 

LCM はすべての入力値で割り切れることが保証されているため、最後のループでは整数の割り算が使用されます。 Python の整数はオーバーフローの問題も回避しますが、数値の最大 LCM は次のとおりであるため、最終的な答えは一般的な競技プログラミングの制限に対して十分小さいままです。`20`は限られています。

# テストケース```python
import sys, io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    def solve():
        import sys
        input = sys.stdin.readline

        n = int(input())
        a = list(map(int, input().split()))

        primes = [2, 3, 5, 7, 11, 13, 17, 19]
        best = [0] * len(primes)

        for x in a:
            for i, p in enumerate(primes):
                cnt = 0
                while x % p == 0:
                    x //= p
                    cnt += 1
                best[i] = max(best[i], cnt)

        lcm = 1
        for p, e in zip(primes, best):
            lcm *= p ** e

        print(sum(lcm // x for x in a))

    solve()
    sys.stdin = old_stdin
    return sys.stdout.getvalue()

 # エッジケース

 値が繰り返される場合:```
3
2 2 2
```アルゴリズムは、素数の最大の指数を見つけます。`2`は 1 であるため、最小公倍数は次のようになります。`2`。 それぞれの値が貢献します`2 / 2 = 1`、答えを与える`3`。 この方法では重複する値を掛け合わせることがないため、ターゲットの過大評価を回避できます。 

素数電力の場合:```
3
2 4 8
```因数のカウントは次のとおりです。`2^1`、`2^2`、 そして`2^3`。 保存された最大指数は 3 で、LCM は次のようになります。`8`。 貢献内容は、`4`、`2`、 そして`1`、可能な最小の合計を与える`7`。 

単一要素の場合:```
1
15
```1 つの数値の最小公倍数は、その数値そのものです。 唯一可能な選択肢は、`B_1 = 1`、したがって、答えは次のとおりです`1`。 他の値との比較が必要ないため、アルゴリズムはこれを自然に処理します。
