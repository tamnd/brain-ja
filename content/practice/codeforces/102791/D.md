 ## 解決策
 ## 問題の理解

 樽が並んでいて、各樽にはある程度の水が入っています。 移動は、空ではない樽を 1 つ選択し、その水を任意の量で別の樽に注ぐことで構成されます。 私たちがパフォーマンスできるのはせいぜい`k`動く。 目標は、すべての移動後に最大のバレルと最も空のバレルの差をできるだけ大きくすることです。 

バレルの中身全体を 1 ステップで移動できるため、操作は非常に柔軟です。 重要なのは、1つの樽にどれだけの水を集めることができるか、そして同時に空の樽を作成できるかどうかだけです。 

制約により、最大で`2 * 10^5`樽。 一般的なコンテストの制限時間では、状態の数が急速に増加するため、考えられる多くの一連の動きを試すアプローチは不可能です。 多くのバレルの組み合わせをチェックするだけでも時間がオーバーしてしまいます。 に近い解決策が必要です`O(n log n)`またはそれ以上です。 

トリッキーなケースは、空のバレルと許可される移動数の間の相互作用から発生します。 

次の入力を考えてみましょう。```
3 1
0 5 0
```答えは`5`。 不注意な解決策では、2 つの樽がすでに空になっているため、1 つの移動は役に立たないと考えるかもしれませんが、樽を注ぐことができます。`5`空の樽にリットルを入れても、まだ空の樽を後ろに置いておくと、`5`。 

別のエッジケースは次のとおりです。```
4 2
7 0 0 0
```答えは`7`。 樽間で水を 2 回移動し、すべてが入った 1 つの樽で終了します。`7`リットルと少なくとも1つの空のバレル。 最初にいっぱいになったバレルから最後のバレルに直接移動することのみを考慮したソリューションでは、この種のケースを見逃す可能性があります。 

最後の重要なケースは、すべてのバレルが空の場合です。```
3 2
0 0 0
```答えは`0`。 最大収集水量の式は次のようになります。`0`、そしてどんな操作もそこになかった水を作り出すことはできません。 

## アプローチ

 直接的な力ずくのアプローチでは、どの樽が供与者となり、どの樽が水を受け取るかを決定しようとします。 選択したすべての受け取りバレルについて、選択したバレルからそこに水を移動することをシミュレートできます。 これは正しいです。最良の最終状態には最大量の水を含むバレルが必要であり、この値を増加させる動きはまさに水をそのバレルに移す動きであるためです。 

しかし、最適なドナーのセットを選択することが問題です。 がある`n`バレルを選択する必要があります`k`ドナーと受け取りバレル 1 つ。 すべての選択肢を試すには組み合わせ作業が必要ですが、これは人間の能力をはるかに超えています。`n = 2 * 10^5`。 

重要な観察は、演算後の最小値を常にゼロにすることができるということです。 以来`k < n`、最終レシーバーである必要のないバレルが少なくとも 1 つあります。 移動によってバレルを空にすることで、空のバレルを残すことができます。 

最小値がゼロに固定されると、答えを最大化することは、最大のバレルを最大化することと同じになります。 1 回の移動ですべての水をある樽から別の樽に移すことができるため、`k`内容を正確に組み合わせることができる動き`k`ドナーバレルを 1 つのデスティネーションバレルに入れます。 目的地のバレルも元の水に貢献します。 したがって、最終的な最大のバレルには、最大のバレルの合計が含まれる可能性があります。`k + 1`初期金額。 

ブルートフォース手法は、考えられるすべての転送を正確にモデル化するため機能しますが、検索する選択肢が多すぎるために失敗します。 可能な限り最大の蓄積バレルのみが重要であるという観察により、問題は分類と合計に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数的`n`| O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(1) 余分なスペース | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての樽の中の水の量を読み取り、降順に並べます。 

選別することで、最終的な最大量に最も多くの水が寄与している樽を特定することができます。 大きなバレルの代わりに小さなバレルを選択しても、結果は低下するだけです。 
2. 最初のものを追加します`k + 1`ソートされた配列からの値。 

1 つのバレルには最終的な最大量が入ります。 もう一つは`k`バレルとは、まさに水が移される樽のことです。 宛先バレルにはすでに独自の初期水が含まれているため、`k + 1`合計でバレル。 
3. この合計を出力します。 

最小額はゼロにすることができるため、この最大額は直接必要な差分になります。 

なぜ効果があるのか:

 最後の違いは、`maximum - minimum`。 少なくとも 1 つのバレルは最大でも空のままになる可能性があるため、`k`移動すると、最小値は常にゼロになる可能性があります。 残っている唯一のタスクは、バレルを 1 つ最大化することです。 各注出操作で 1 つのバレルの内容物を完全に移すことができるため、`k`操作により正確に許可されます`k`他の樽は、選択した目的地に水を提供します。 可能な限り最適な目的地と寄付者は次のとおりです。`k + 1`初期量が最も多いバレル。 選択したバレルをより小さいバレルに置き換えても合計が増加することはないため、他の選択では合計が大きくなりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort(reverse=True)
    
    print(sum(a[:k + 1]))

if __name__ == "__main__":
    solve()
```プログラムはまず、バレル金額を最大値から最小値の順に並べ替えます。 最初`k + 1`位置は最終的な最大バレルに寄与できる唯一の値であるため、残りのバレルを処理する必要はありません。 

スライス`a[:k + 1]`安全なので`k < n`、つまり少なくとも`k + 1`樽は常に存在します。 Python の整数は可能な合計サイズを自動的に処理するため、特別なオーバーフロー処理は必要ありません。 

この実装では、配列ストレージと内部で使用されるソート メモリのみが使用されます。 並べ替えステップが実行時間の大半を占めます。

 | イニシャル | 5、5、5、5 | 5、5 | 10 |

 最初に水を受け取る樽は元の状態を保ちます`5`、そしてある動きが別の動きを転送します`5`そこに。 空のバレルが残るので、違いは`10`。

def solve(inp: str) -> str:

 ## 特殊なケース

 対象:```
3 1
0 5 0
```ソートされた配列は`[5, 0, 0]`。 最大のものを採用します`k + 1 = 2`価値観、与える`5 + 0 = 5`。 1 回の移動で空の樽を残したまま別の樽に水を入れることができるので、違いは次のとおりです。`5`。 

のために：```
4 2
7 0 0 0
```ソートされた配列は`[7, 0, 0, 0]`。 最大の 3 つの値を取得すると、次のようになります。`7`。 寄与するバレルのうち 2 つは水がゼロですが、最終的な最大値はシステム内の水の総量を超えることはできません。 

のために：```
3 2
0 0 0
```選択された値はすべて 0 なので、答えは 0 です。 移動する水はなく、考えられるすべての最終状態の最大量と最小量は同じになります。 

のために：```
5 2
1 8 3 10 5
```アルゴリズムが選択するのは、`10`、`8`、 そして`5`。 許可される 2 つの移動により、`8`そして`5`バレルをバレルに入れる`10`。 関わるあらゆる選択`3`または`1`最終的な最大値が減少します。
