 ## 解決策
 ## 問題の理解

 ボードは、1 から n までのすべての整数が 1 回だけ書き込まれることから始まります。 操作により、既存の 2 つの数値 a と b が削除され、それらの平均の上限に置き換えられます。 これを正確に n - 1 回繰り返した後、数字は 1 つだけ残ります。 タスクは、その最終的な数値をできるだけ小さくし、それを達成する選択されたペアのシーケンスを出力することです。 

n の値は 200000 に達する可能性があるため、現在のボード値をすべて繰り返し検索したり、多くの可能な選択肢をシミュレートしたりするアプローチは不可能です。 出力する必要のある操作が n - 1 個あるため、ソリューションでは操作ごとに一定量の作業のみを実行する必要があります。 これにより、考えられるすべてのペアを試すなど、二次的な動作を伴うアプローチが除外されます。 

よくある間違いは、常に 2 つの最小値を組み合わせることが最適であると想定することです。 結果は切り上げられるため、この演算は通常の平均化ではありません。また、構築では、現在の最小値を減らすだけでなく、どの値が存続するかを制御する必要があります。 たとえば、n = 3 の場合、入力は次のようになります。```
3
```不注意で貪欲な戦略は、最初に 1 と 2 を結合して 2 を生成し、次に 2 と 3 を結合して 3 を生成する可能性があります。最終的な値は 3 になりますが、最適な出力は 2 のままになります。正しい順序は、最初に 2 と 3 を結合して 3 を生成し、次に 1 と 3 を結合して 2 を生成することです。 

もう 1 つのエッジ ケースは n = 2 です。重複した値を作成したり、複数ステップの構築を実行したりする余地はありません。 唯一可能な演算は 1 と 2 を組み合わせて 2 を与えることなので、常に繰り返し値を使用できると想定しているアルゴリズムは失敗します。 

## アプローチ

 ブルートフォース ソリューションでは、さまざまなペアを試して、可能な限り最小の最終的な数値を見つけます。 これは正しいです。すべての有効な操作シーケンスはペア選択のツリーとして表すことができ、すべてのツリーを探索すると最終的に最適なものが見つかるからです。 問題は、可能な選択肢の数が急速に増加することです。 最初の操作でも約 n² 個の可能なペアがあり、n - 1 個の操作があるため、利用可能な制限をはるかに超えて徹底的な探索が行われます。 

重要な観察は、考えられる最小の答えは常に 2 であるということです。最後の演算は 2 つの正の整数を結合し、リダクション後に利用可能な最小のペアは 1 を作成できないため、この演算は最後に 2 より小さい値を生成することはできません。残りの課題は、2 に達する演算を構築することです。 

この構築は、制御された大きな値を繰り返し作成し、それを下方に移動することによって機能します。 まず、n と n - 2 を結合します。これら 2 つの数値の平均は正確に n - 1 であるため、結果は n - 1 になります。次に、n - 1 をそれ自体と結合して、再び n - 1 を生成します。 この後、同じ考え方を残りの下位の数値に適用できます。つまり、i と i + 2 を組み合わせて i を減らします。 各操作では、重要な値を利用可能な状態に保ちながら、未使用の数値を 1 つ削除します。 結局、残る数は2のみとなりました。 

ブルートフォースはあらゆる可能な削減を探索するため機能しますが、n が大きくなると探索空間が膨大になるため失敗します。 この操作により慎重に選択された値が保存されることが観察されたため、検索を直接的な構築に置き換えることができます。

 ## アルゴリズムのチュートリアル

 1. 最終最小値として 2 を出力します。 以下の構築では、常にこの数値が正確に残ります。 
2. n が 2 の場合、1 と 2 を直接結合します。 四捨五入された平均は 2 であり、これが唯一可能な答えです。 
3. n が 2 より大きい場合は、n と n - 2 を組み合わせます。ceil((n + n - 2) / 2) が n - 1 に等しいため、生成される値は n - 1 になります。 
4. n - 1 と n - 1 を結合します。これにより、n - 1 は変更されずに維持され、元の n - 1 の値が削除されます。 
5. n - 3 から 1 までのすべての i について、i と i + 2 を結合します。現在のボードにはこの段階で i + 2 が含まれており、この操作により i + 1 が作成され、これが次のステップに必要な値になります。 

この構文が 1 ずつ下に移動する理由は、すべての演算で、間の距離が 2 である 2 つの数値が中央の数値に変換されるためです。 これにより、最終的に 2 に達する単一のチェーンを維持しながら、大きな値をすべて削除することができます。 

なぜ効果があるのか:

 不変条件とは、数値 i を処理した後、i + 1 より大きいすべての値が削除され、ボードにはまだ値 i + 1 が含まれていることです。最初の 2 つの操作は、最大値に対してこの不変条件を確立します。 i と i + 2 を組み合わせると i + 1 が作成されるため、後続のすべての操作ではその値が保持されます。i が 1 に達すると、最後の操作で 1 と 3 が結合され、2 が生成されます。2 未満の最終値はあり得ないため、構築は最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    ans = ["2"]

    if n == 2:
        ans.append("1 2")
    else:
        ans.append(f"{n - 2} {n}")
        ans.append(f"{n - 1} {n - 1}")
        for i in range(n - 3, 0, -1):
            ans.append(f"{i} {i + 2}")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```プログラムは、操作のたびに印刷するのではなく、出力行を保存します。 これにより、生成された応答に線形メモリのみを使用しながら、不要な出力オーバーヘッドが回避されます。 

一般的な構造では数値 n - 2 と n - 1 が存在する必要があるため、特殊なケース n = 2 は個別に処理されます。 n が大きい場合、最初の操作では n と n - 2 が使用され、これらは常に有効な値です。 ループは n - 3 で開始し、1 で停止します。最初の 2 つの後にちょうど n - 3 回の追加操作が生成され、合計で n - 1 回の操作が行われます。 

関係する最大値は n であり、最大でも 200000 であるため、すべての算術演算は通常の整数の制限内に収まります。 

## 実用的な例

 n = 4 の場合、アルゴリズムは次を生成します。 

| ステップ | 操作 | 結果として得られる重要な値 |
 | --- | --- | --- |
 | イニシャル | 値 1、2、3、4 | 4 |
 | 1 | 2 と 4 を組み合わせる | 3 |
 | 2 | 3 と 3 を組み合わせる | 3 |
 | 3 | 1 と 3 を組み合わせる | 2 |

 最後の数値は 2 です。これは、最大値が下向きのチェーンに変換される構造の最初の部分を示しています。 

n = 5 の場合、アルゴリズムは次を生成します。 

| ステップ | 操作 | 結果として得られる重要な値 |
 | --- | --- | --- |
 | イニシャル | 値 1、2、3、4、5 | 5 |
 | 1 | 3 と 5 を組み合わせる | 4 |
 | 2 | 4 と 4 を組み合わせる | 4 |
 | 3 | 2 と 4 を組み合わせる | 3 |
 | 4 | 1 と 3 を組み合わせる | 2 |

 このトレースは、不変条件がどのように維持されるかを示しています。 最初の 2 つの操作の後、残りの大きな値は 2 だけになるまで 1 つずつ減少します。

 | スペース | O(n) | 出力自体には n 行が含まれていますが、アルゴリズム ロジックは一定の追加メモリを使用します。 |

 n は 200000 に達する可能性があるため、制限には線形解が必要です。アルゴリズムは各操作に対して少量の固定量の作業を実行するため、制限時間内に簡単に収まります。

    return "\n".join(ans)

 ## 特殊なケース

 n = 2 の場合、ボードには 1 と 2 のみが含まれます。アルゴリズムは、可能な唯一の演算を即座に出力します。`1 2`。 結果の値は ceil(3 / 2) で、2 に等しくなります。 

n = 3 の場合、アルゴリズムは特殊なケースを使用しません。 まず 1 と 3 を結合して 2 を作成し、次に 2 と 2 を結合して 2 を維持します。最終値は依然として 2 であり、この構造により、最小の数値を最初に減らすという誤った戦略が回避されます。 

n が大きい場合、アルゴリズムはボードを明示的に保存しません。 使用された時点で値が存在することが保証されているシーケンスのみを出力します。 減少ループにより、n が 200000 に達した場合でも、無効なペアが要求されないことが保証されます。
