 ## 解決策
 # 問題の理解

 タスクはバイナリ文字列を与えます。 操作では、既存の文字を 1 つ選択し、それを削除します。 この削除後、同一の文字で構成される最長のプレフィックスも自動的に削除されます。 目標は、文字列が空になるまでの操作の数ができるだけ多くなるように、可能な限り最善の方法で削除を選択することです。 元の問題ステートメントと制約は、Codeforces Gym 102791H からのものです。 

文字列の長さは 200000 に達する可能性があります。このサイズでは、途中から削除するには多くの文字をシフトする必要があるため、各操作の後に実際に文字列を変更するシミュレーションはコストがかかりすぎます。 近似の二次解$n^2$作業はすでに 2 秒の制限をはるかに超えています。 文字列を線形時間で処理する必要があります。 

難しいケースは、多くの異なる文字を含む文字列ではなく、削除するたびにプレフィックス構造が変化するケースです。 単一の長いブロックは、間違って処理するとすぐに消えてしまう可能性がありますが、複数の単一文字ブロックを使用して追加の操作を作成することができます。 

たとえば、次の入力を使用します。```
2
11
```答えは次のとおりです。```
1
```不注意な方法では両方の文字を別々にカウントする可能性がありますが、一方を削除すると`1`葉`1`、自動プレフィックス削除により、同じ操作で残りの文字が削除されます。 

もう 1 つの重要なケースは次のとおりです。```
6
101010
```答えは次のとおりです。```
3
```すべての実行の長さは 1 です。 常に次の実行をすぐに消費する貪欲なソリューションでは、答えは実行回数であると考えるかもしれませんが、操作では選択した 1 つの文字と 1 つのプレフィックスしか削除できないため、6 つの単一文字が 3 つの便利な操作にペアになります。 

最終的な境界ケースは次のとおりです。```
8
10101000
```答えは次のとおりです。```
4
```最後のゼロのブロックを単純に無視することはできません。 以前の単一キャラクターの実行中に部分的に消費され、追加の操作が作成される可能性があります。 

## アプローチ

 直接的なアプローチは、操作をシミュレートすることです。 文字列のすべての状態について、削除できるすべての文字を試し、将来の操作数が最も多くなる手を選択し、これを繰り返します。 これはすべての法的選択肢を検討しているので正しいですが、完全に非現実的です。 1 つの文字列状態を保存するだけでもコストがかかります$O(n)$、そして多くの州にわたる可能な選択肢の数により、全体の作業は指数関数的に増加します。 常に選択した動きを実行する単純化されたシミュレーションでも、頻繁に中間削除を行う必要があり、$O(n^2)$。 

重要な点は、連続した等しい文字のみが重要であるということです。 文字列をランに圧縮できます。 例えば、`111010`長さになります`[3, 1, 1, 1]`。 

1 を超える長さのランは複数の操作を提供できるため、価値があります。 このようなランがプレフィックスになる場合、そこから 1 文字を削除すると、自動削除によってそのランの残りが削除されます。 単一キャラクターのランは異なります。先頭に到達すると完全に消えるため、できるだけ長く保存する必要があります。 

欲張りなアイデアは、追加の削除のソースとして常に長い実行を使用することです。 現在のフロントランの長さが 1 より大きい場合、それを消費します。 前のランが 1 文字の場合は、後の長いランを検索し、代わりにそのランから 1 文字を取得します。 これにより、単一文字のプレフィックスが別の操作のために維持されます。 長い実行が残っていない場合は、残りの単一実行をペアにすることしかできず、残りの操作数が直接得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列をランレングスに圧縮します。 連続した等しい文字は、その長さのみが将来の操作に影響するため、1 つのランになります。 
2. 2 つのポインタを保持します。 左のポインタは、完全に削除されていない最初の実行を表します。 右ポインタは、長さが 1 より大きい次のランを検索します。 
3. 現在の左ランの長さが 1 より大きい場合、それに 1 回の操作を費やして左ポインタを移動します。 この実行は自動プレフィックス削除によって削除できるため、他の実行に手を加える必要はありません。 
4. 現在の左側のランの長さが 1 である場合、1 より大きい長さを持つ後のランを検索してみます。 その後の実行から 1 文字を削除し、操作を 1 つカウントします。 左側の 1 文字の実行は、今後の操作で引き続き使用できます。 
5. 長いランがもう存在しない場合、残りのランはすべて長さ 1 になります。 このような実行は 1 回の操作につき 2 つ削除できるため、残りの実行数の上限を 2 で割った値を加算して終了します。 

なぜ効果があるのか:

 不変条件は、すべての操作で将来の削除をできるだけ多く保存する必要があるということです。 単一文字の接頭辞は、接頭辞になると完全に消えるため、最も脆弱なリソースです。 長い実行から 1 文字を削除しても、削除できるプレフィックスが残るため、追加操作の唯一の原因は長い実行です。 貪欲なアルゴリズムは、実行が失われる前に常に長い実行を費やし、単一文字の実行を遅らせるため、操作の機会が無駄になりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    runs = []
    cnt = 1
    for i in range(1, n):
        if s[i] == s[i - 1]:
            cnt += 1
        else:
            runs.append(cnt)
            cnt = 1
    runs.append(cnt)

    m = len(runs)
    ans = 0
    l = 0
    r = 0

    while l < m:
        if l > r:
            r = l

        if runs[l] > 1:
            ans += 1
            l += 1
        else:
            while r < m and runs[r] == 1:
                r += 1

            if r < m:
                runs[r] -= 1
                ans += 1
                l += 1
            else:
                ans += (m - l + 1) // 2
                break

    print(ans)

if __name__ == "__main__":
    solve()
```最初の部分では、ランレングス表現を構築します。 これにより、文字の正確な位置は重要ではなくなるため、実際の文字列を維持する必要がなくなります。 

メイン ループは、ウォークスルーからの貪欲な決定に従います。 削除されたランは戻らないため、左ポインタは前方にのみ移動します。 また、右ポインタは、有用な長期実行を検索している間は前方にのみ移動し、線形の合計作業量を与えます。 

減少分`runs[r] -= 1`微妙です。 実行全体を削除するわけではありません。 この中の 1 文字だけを使用して操作を作成し、残りは後で使用します。 これを忘れると、アルゴリズムは実行をすぐに削除するという誤った戦略になってしまいます。 

最後の表現`(m - l + 1) // 2`残りの単一文字の実行を処理します。 各操作で削除できるそのような実行は最大 2 つであるため、これが貢献できる操作の最大数になります。

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    s = input().strip()

    runs = []
    cnt = 1
    for i in range(1, n):
        if s[i] == s[i - 1]:
            cnt += 1
        else:
            runs.append(cnt)
            cnt = 1
    runs.append(cnt)

    m = len(runs)
    ans = 0
    l = 0
    r = 0

    while l < m:
        if l > r:
            r = l
        if runs[l] > 1:
            ans += 1
            l += 1
        else:
            while r < m and runs[r] == 1:
                r += 1
            if r < m:
                runs[r] -= 1
                ans += 1
                l += 1
            else:
                ans += (m - l + 1) // 2
                break

    return str(ans)

 ## 特殊なケース

 のために`2\n11\n`、圧縮形式は次のとおりです。`[2]`。 アルゴリズムは、長い実行を即座に認識し、1 つの操作をカウントして終了します。 自動プレフィックス削除により残りの文字が一度に削除されるため、実行が複数の操作に分割されることはありません。 

のために`6\n101010\n`、圧縮形式には 6 つの単一実行が含まれています。 使用する長い実行がないため、アルゴリズムは最終的なペアリング ルールに直接ジャンプします。 6 つの単一実行により 3 つの操作が生成されます。 

のために`8\n10101000\n`、ランは`[1,1,1,1,1,1,2]`。 最初の 6 つの単一実行はすぐに削除しないでください。 このアルゴリズムは、最後のロングランから 1 つの文字を繰り返し借用し、先頭のシングルを維持しながら徐々に文字を減らします。 ロングランが使い果たされた後、残りのシングルがペアになり、4 つのオペレーションが生成されます。
