 ## 解決策
 ## 問題の理解

 タスクは、特定の文字列をその逆に変換するために必要な隣接するスワップの最小数を見つけることです。 スワップでは隣接する 2 つの文字のみを交換できるため、コストは文字が文字列内を移動する距離を測定します。 

入力には、文字列の長さと文字列自体が含まれます。 出力は、すべての位置の文字が反転前のミラー位置にあった文字と一致するように元の文字列を再配置するために必要な隣接スワップの最小数です。 

長さは 200000 に達する可能性があります。文字列は 2 次数の移動を必要とする可能性があるため、スワップを直接シミュレートしようとするソリューションは不可能です。 最終的な答えは約 n² になる可能性がありますが、アルゴリズムによって実行される演算の数は依然として線形に近い値を維持する必要があります。 これにより、キャラクターを繰り返し検索したり、キャラクターを 1 つずつ物理的に移動したりすることが排除されます。 

主な問題は、文字が繰り返されることにあります。 文字列を反転する場合、文字には一意の宛先がありません。 たとえば、`aaaza`、3つ`a`中央の文字は区別できないため、間違った文字を選択すると、カウントされるスワップが増加する可能性があります。 

次の入力を考えてみましょう。```
5
aaaza
```正しい出力は次のとおりです。```
2
```不用意な解決策は最初の解決策と一致する可能性があります`a`最初の左側から`a`反転されたターゲットから、等しい文字の順序は無視されます。 同じキャラクターは交差を最小限に抑える順序でペアにする必要があるため、不要な動きがカウントされる可能性があります。 

もう 1 つの重要なケースは回文です。```
6
cbaabc
```出力は次のとおりです。```
0
```文字がミラーリングされた位置と異なるかどうかだけをチェックし、すべての不一致を移動するソリューションでは、カウントが過剰になる可能性があります。 文字列はすでにその逆と等しくなります。 

## アプローチ

 簡単な方法は、紐の両端を繰り返し固定することです。 最初と最後に残った文字を比較します。 それらが等しい場合、両方はすでに正しい最終位置にあります。 それらが異なる場合は、片側で一致する文字を検索し、両端が正しくなるまで隣接するスワップを使用して移動します。 この方法は正しいです。隣接するすべての交換が 1 単位の移動を表し、選択したキャラクターは何らかの方法で目的地まで移動する必要があるからです。 

問題は移動量です。 最悪の場合、長さ n の文字列の一端から反対側に文字を移動するには O(n) のコストがかかり、これを O(n) 個の位置で実行しなければならない場合があります。 総作業量は O(n²) となり、n = 200000 では遅すぎます。 

重要な点は、逆の操作では位置のみが変更され、文字数は変更されないということです。 元の文字列内のすべての文字は、反転されたターゲット内で一致します。 スワップを物理的にシミュレートする代わりに、キャラクターが移動しなければならない合計距離を計算できます。 

ターゲット配列内で文字が占める位置のシーケンスを作成すると、答えはそのシーケンス内の反転の数になります。 反転は、間違った順序で表示され、隣接する入れ替えを通過する必要がある 2 つの文字を表します。 これは、マージ ソートが反転ペアをカウントするのと同じ理由です。 

残りの課題は、同等の文字を処理することです。 どの文字がどのターゲット位置に移動するかを知る必要があります。 最適な選択は、オカレンスを左から右にペアにすることです。 各文字について、元の文字列内の最初の出現は反転文字列内の最初の出現と一致し、2 番目の出現は 2 番目の出現と一致する必要があります。 これにより、同一の文字間の不必要な交差が回避されます。 

ターゲット ポジションを構築した後、フェンウィック ツリーは、現在のポジションの後にすでに処理されたポジションがいくつあるかをカウントできます。 これにより、反転カウントが O(n log n) で得られます。

 | ブルートフォース | O(n²) | お(1) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 元の文字列内のすべての文字の位置を保存します。 等しい文字は左から右に一致する必要があるため、位置は昇順に保たれます。 
2. 反転した文字列を見てください。 この逆の順序のすべての文字について、元の文字列からその文字の最も古い未使用の出現を取得します。 その元の位置を新しい配列に記録します。 

結果の配列は、反転された文字列の文字が元の文字列のどこから来たのかを示します。 これらの位置がすでに増加している場合、文字列はすでに正しい順序になっています。 位置間の減少はすべて、交差する必要がある文字を表します。 
3. フェンウィック ツリーを使用して、位置配列内の反転をカウントします。 

位置 x を処理する場合、x より大きい前の位置の数が、この文字と交差する必要がある文字の数になります。 フェンウィック ツリーには、これまでに出現した位置の数が保存され、このクエリを対数時間で実行できます。 
4. すべての反転寄与を加算し、結果を出力します。 

なぜ効果があるのか:

 最終的な反転文字列の文字の順序は固定されています。 等しい文字を元の左から右の順序で一致させることにより、同一文字間の不必要な交換を回避する唯一の配置が選択されます。 残りの問題は、これらの一致したオカレンスの順序だけです。 ターゲットとは逆の順序で現れる出現のペアはすべて 1 回交差する必要があり、隣接するスワップごとにそのような交差が 1 つだけ修正されます。 したがって、スワップの最小数は、マップされた位置の反転数と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        res = 0
        while i > 0:
            res += self.bit[i]
            i -= i & -i
        return res

def solve():
    n = int(input())
    s = input().strip()

    pos = [[] for _ in range(26)]
    for i, c in enumerate(s):
        pos[ord(c) - 97].append(i)

    used = [0] * 26
    order = []

    for c in reversed(s):
        x = ord(c) - 97
        order.append(pos[x][used[x]])
        used[x] += 1

    fw = Fenwick(n)
    ans = 0

    for i, x in enumerate(order):
        x += 1
        already = fw.sum(n) - fw.sum(x)
        ans += already
        fw.add(x, 1)

    print(ans)

if __name__ == "__main__":
    solve()
```位置リストには、各文字の出現箇所がすべて保存されます。 リストは元の文字列のスキャン中に自然にソートされるため、位置を順番に取得すると、等しい文字間の正しいペアが得られます。 

の建設`order`目的の最終文字列、つまり元の文字列を逆方向にスキャンします。 各キャラクターは、その同じキャラクターの次に利用可能な元の位置を受け取ります。 の`used`配列により、同じオカレンスが 2 回割り当てられるのを防ぎます。 

フェンウィック ツリーは 1 から始まるインデックスを使用するため、格納されたすべての位置は挿入前に 1 ずつ増加します。 現在の位置の場合、式は`fw.sum(n) - fw.sum(x)`厳密にそれより大きい以前の位置をカウントします。 これらはまさに、間違った側にあり、それを横切らなければならない初期の文字です。 

答えは Python の整数型で保存されます。これが必要なのは、スワップの最大数が約 n² であり、32 ビット整数の制限よりはるかに大きいためです。

## テストケース```python
import sys
import io

def solve_case(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i

        def sum(self, i):
            r = 0
            while i:
                r += self.bit[i]
                i -= i & -i
            return r

    n = int(input())
    s = input().strip()

    pos = [[] for _ in range(26)]
    for i, c in enumerate(s):
        pos[ord(c) - 97].append(i)

    used = [0] * 26
    arr = []
    for c in reversed(s):
        x = ord(c) - 97
        arr.append(pos[x][used[x]])
        used[x] += 1

    fw = Fenwick(n)
    ans = 0
    for x in arr:
        x += 1
        ans += fw.sum(n) - fw.sum(x)
        fw.add(x, 1)

    return str(ans)

 ## 特殊なケース

 のために`aaaza`、アルゴリズムは次のように逆のターゲット順序を構築します。`azaaa`。 の発生`a`左から右に照合され、位置シーケンスが生成されます。`[0, 3, 2, 1, 4]`。 フェンウィックの木は、`z`間違った場所にあるため、必要な倒置法だけを数えた結果、正解は 2 になります。 

のために`cbaabc`、反転された文字列は元の文字列と同一です。 マッピングされた位置はすでにソートされているため、反転カウントはゼロのままです。 文字のペアが交差する必要がないため、アルゴリズムは回文を自然に処理します。 

繰り返される文字が 1 つだけ含まれる文字列の場合、次のようになります。`aaaaa`、順序を変更せずに、すべての出現を対応する出現と照合できます。 マッピングされた位置は増加しているため、答えはゼロです。 これにより、実際には交換可能な同一文字間の交換を数えるというよくある間違いを回避できます。
