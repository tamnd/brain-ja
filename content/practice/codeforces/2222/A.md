 ## 解決策
 ## 問題の理解

 私たちは、プログラミング コンテストが「素晴らしい」かどうかを、すべての可能な整数の合計スコアという意味で判断するように求められています。`0`そして`100 * n`達成できる。 コンテストには、`n`問題があり、それぞれの問題は次のように分類されます。`a_i`サブタスク。 の各サブタスク`i`- 番目の問題は、問題のスコアに等しく寄与します。つまり、`100 / a_i`ポイント。 

出場者の合計スコアは、各問題で解決したサブタスクのスコアの合計です。 入力にはいくつかのテスト ケースがあり、それぞれに問題の数と問題ごとのサブタスクのリストが示されます。 出力では、各テスト ケースについて、すべての整数の合計スコアが`0`に`100 * n`を得ることができます。 

制約は小さいです。`n`せいぜい`10`、`a_i`分割する`100`、 そして`t`までです`100`。 こんなに小さいのに`n`、総当り的なアプローチも実現可能ですが、より洗練された数学的洞察を見つけることができます。 

明らかではないエッジケースには、すべてが`a_i`は大約数です`100`。 たとえば、すべてが`a_i`は`100`、各問題は次の倍数のみを寄与します。`1`合計にすると、これは簡単に機能します。 しかし、もし`a_i`は`4`そしてもう一つは`25`、すべての問題のスコアの組み合わせで、すべての整数の合計が許可されることを確認する必要があります。 最大スコアを単純に合計する単純なアプローチでは、各問題の個別のステップによって生じるギャップを見逃す可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、次のすべての組み合わせを列挙します。`x_i`それぞれの問題ごとに。 以来`0 <= x_i <= a_i`そして`a_i <= 100`、これは最悪の結果をもたらします`101^10`単一のテスト ケースの組み合わせは大きすぎます。 それは正しいですが、実行不可能です。 

重要な洞察は、浮動小数点スコアではなく「1 ポイント」単位で作業することです。 それぞれなので`a_i`分割する`100`、問題のスコア`i`からの整数として表すことができます`0`に`100`の段階で`100 / a_i`。 させて`step_i = 100 / a_i`。 次に、質問は次のようになります: からのすべての整数を表すことができますか?`0`に`100 * n`以下の非負の整数の組み合わせとして`step_1, step_2, ..., step_n`多重度が以下の場合`a_i`?

 これを古典的なサブセット合計またはコインの小銭の問題としてモデル化できます。各コインの価値は次のようになります。`step_i`と`a_i`コピー。 と`n <= 10`そして`a_i <= 100`、到達可能な合計の合計数は最大で`1000`、動的プログラミング ソリューションを実現可能にします。 ブール配列を初期化します`reachable[0..100*n]`それぞれの倍数を加算することで、達成可能なすべてのスコアを繰り返しマークします。`step_i`。 

これにより、すべてのブルートフォース攻撃が回避されます`x_i`この問題では整数演算が十分であることが保証されているため、この問題は組み合わせて機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(prod(a_i)) | O(100*n) | 遅すぎる |
 | 動的プログラミング (コインのようなもの) | O(n * 100 * max(a_i)) | O(100*n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各問題のサブタスク数を変換する`a_i`スコアステップに:`step_i = 100 // a_i`。 これにより、小数点以下のスコアが整数に変換されます。 
2. ブール配列を初期化する`reachable`サイズの`100*n + 1`、 どこ`reachable[s]`合計スコアかどうかを示します`s`達成可能です。 セット`reachable[0] = True`。 
3. 問題ごとに`i`ステップ付き`step_i`そして`a_i`サブタスク、更新`reachable`加算して得られるすべての合計を含めるには`k * step_i`のために`k = 1..a_i`以前に到達可能な金額まで。 これにより、問題のサブタスク制限を超えないようにすることができます。 
4. すべての問題を処理した後、すべての整数が正しいかどうかを確認します。`s`から`0`に`100*n`到達可能です。 ある場合は出力します`Yes`、 さもないと`No`。 

なぜ効果があるのか​​:`reachable`サブタスクの制限内で形成できるすべての合計を正しくモデル化します。 各ステップ サイズの倍数を繰り返し含めることにより、組み合わせが失われないことが保証されます。 整数演算により、丸め誤差のない正確な計算が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_wonderful(a):
    n = len(a)
    steps = [100 // ai for ai in a]
    max_score = 100 * n
    reachable = [False] * (max_score + 1)
    reachable[0] = True

    for step, count in zip(steps, a):
        # We iterate backwards to avoid using the same problem multiple times
        new_reachable = reachable[:]
        for s in range(max_score + 1):
            if reachable[s]:
                for k in range(1, count + 1):
                    ns = s + k * step
                    if ns <= max_score:
                        new_reachable[ns] = True
                    else:
                        break
        reachable = new_reachable

    return all(reachable)

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print("Yes" if is_wonderful(a) else "No")
```このソリューションでは、まずスコアを整数の倍数に変換し、次に達成可能なすべての合計を繰り返しマークします。 逆方向に繰り返します`reachable`同じ問題による寄付の二重カウントを防ぐため。 ブレークにより最大スコアを超えることがなくなります。
