 ## 解決策
 ## 問題の理解

 整数の配列と一連の演算が与えられます。 各操作は 2 つの概念的な部分で構成されます。まず、配列内で選択した中心を中心に要素を対称的に交換でき、制御された方法で要素を効果的に並べ替えることができます。 2 番目に、操作入力に基づいて特定の要素をマークします。 重要なのは、マークは位置ではなく要素自体に付けられたままであるため、将来の交換によってマークが解除されることはありません。 すべての操作の後、タスクはマークされていないままの要素の合計を最小化することです。 

最初の重要な観察は、各操作の間隔の長さを自由に選択できるという意味で、対称スワップに制限がないことです。 これは、原則として、配列の境界を侵害しない限り、配列を任意に再配置できることを意味します。 したがって、スワップの正確な順序はアルゴリズムを制約しません。唯一関連する制約は、どの要素がマークされるかということです。 

入力制約では、テスト セットごとに最大 10^5 の要素と 10^5 の演算が許可され、最大 10^4 のテスト ケースが許可されます。 最悪の場合、各スワップが O(n) になる可能性があるため、すべてのスワップの単純なシミュレーションは実行不可能です。 スワップのシミュレーションを完全に回避し、マークされない要素に焦点を当てるアプローチが必要です。 

すべての要素が負の場合、重要なエッジ ケースが発生します。 不注意なアプローチでは、最大の要素を選択してマークを付けずに残そうとする可能性がありますが、最適な戦略は常に最大の要素をマークして、マークされていない要素の合計が最小になるようにすることです。 

## アプローチ

 ブルート フォースの方法は簡単です。操作ごとに、選択した中心の周りで対称の交換を実行し、指定された要素をマークします。 すべての操作の後、配列を反復処理してマークされていない要素を合計します。 このアプローチは問題のルールを忠実に実装しているため正しいですが、その時間計算量は最悪の場合でも O(m * n) になります。 n と m が最大 10^5 である場合、これには最大 10^10 の演算が必要となり、制限時間を数桁超えます。 

重要な洞察は、対称スワップによって、最終的にどの要素がマークされるかが制限されないということです。 要素を任意に交換できるため、いつでも最大の要素をマークされる位置に移動できます。 したがって、問題はより単純なタスクになります。マークされる要素を特定し、可能であればそれらの最大のものを選択し、残りの要素の合計を計算します。 

具体的には、次のことを行う必要があります。 

1. マークされるすべてのインデックスを収集します。 
2. 配列をソートします。 
3. 最大の要素 (マークされたインデックスの数まで) をマークして、マークされていない要素の合計を最小限に抑えます。 

これにより、ソートによる問題が O(m * n) から O(n log n) に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m * n) | O(n) | 遅すぎる |
 | 最適 | O(n log n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列の長さを読み取ります。`n`と操作の数`m`。 
2. 配列を読み取る`a`および操作インデックスのリスト`x`。 
3. 長さのブール配列を使用して、マークされたすべての要素を追跡します`n`またはセット。 入力インデックスに対応する各要素をマークします。 マーキングは要素ベースであるため、重複は問題になりません。 
4. 配列を昇順に並べ替えます。 
5. マークされた要素の総数を数えます。 
6. マークされていない要素の最小可能合計は、最初の要素を合計することによって取得されます。`n - marked_count`ソートされた配列の要素。 これが機能するのは、要素を任意に交換できるため、最大の要素を常にマークできるからです。 
7. 合計を出力します。 

機能する理由: 不変条件は、マークされている要素に関して、スワップによって配列の任意の並べ替えが許可されることです。 したがって、重要な唯一の決定は、どの要素にマークを付けるかということです。 最大の要素をマークすることにより、マークされていない残りの要素の合計が最小になります。 並べ替えにより、合計の最小要素を O(n log n) 時間で選択できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        x = list(map(int, input().split()))
        
        marked = [False] * n
        for idx in x:
            marked[idx - 1] = True  # convert to 0-based index
        
        marked_count = sum(marked)
        a.sort()
        unmarked_sum = sum(a[:n - marked_count])
        print(unmarked_sum)

if __name__ == "__main__":
    solve()
```コードはまず、どの要素がマークされているかを追跡するためにブール配列を初期化します。 入力からの 1 ベースのインデックスは、Python では 0 ベースのインデックスに変換されます。 マークされた要素を数えた後、配列を並べ替えることで最小の要素を選択できるようになります。`n - marked_count`マークされていない合計の要素。 これにより、スワップのシミュレーションが完全に回避され、境界の問題は単純な合計計算によって処理されます。

 ## 特殊なケース

 すべての要素が負の場合でも、アルゴリズムは最大の要素にマークを付け、最小の負の要素はマークされません。 単一要素の配列の場合、それをマークするとゼロ和になります。 マーキングは要素自体を追跡するため、重複が処理されます。 同じ要素を指す複数のインデックスはオーバーカウントされません。 

入力：```
1
5 5
-5 -1 -3 -2 -4
1 2 3 4 5
```ソートされた配列:`[-5,-4,-3,-2,-1]`。 すべての要素にマークが付けられています。 マークされていないものの合計 = 0。アルゴリズムは 0 を正しく計算します。 

これにより、否定的シナリオ、重複シナリオ、および境界シナリオ全体での正確性が確認されます。
