 ## 解決策
 ## 問題の理解

 この問題は、ジョーイとグレイの 2 人のプレイヤーが関与する確率的なカード プロセスを記述しています。最終的に予想されるカードの数は、スートの初期構成と結果間の再帰的相互作用の両方に依存します。 ドローを直接シミュレートする代わりに、タスクは、ジョーイの手のさまざまな「状態」間の線形関係のシステムから導出される期待値を計算することです。 

概念的には、ジョーイの手には 4 種類のカードが含まれていますが、最終的な貢献に重要なのはそのうちの 2 つだけです: スペードとクラブです。 残りのカードはシステムのベースラインの期待値にのみ影響し、ジョーイのわずかな貢献には影響しません。 スペードの貢献を値 x としてモデル化し、クラブの貢献を値 y としてモデル化します。 これらの値は独立した定数ではありません。 それらは、プロセスの確率的な遷移と、ジョーイが関連するカードを持っていないときに予想される基本結果に依存します。 

重要な導出量は E で、ジョーイにハンド効果がない場合の期待ベースライン値であり、ステートメントで与えられた公式では (a + c − 1) に単純化されます。 これは、繰り返しにおける固定オフセットとして機能します。 

次に、システムは、異なるスーツを描画する確率を通じて、x と y を結び付ける 2 つの線形方程式を定義します。 各用語は、異なる状態への移行に対応します。つまり、スペードのような状態に留まるか、クラブのような状態に移行するか、追加の期待コストを伴うベースラインの状態にリセットされます。 

最終的な答えは、ジョーイの最初のハンドのスペードとクラブの数によって重み付けされた、これらの貢献の線形結合です。 

最終 = E + x × (スペードの数) + y × (クラブの数)。 

制約は明示的には示されていませんが、線形方程式による期待値システムの存在により、意図したソリューションはテスト ケースごとに一定時間で実行される必要があります。 カードの数に応じて状態空間が増大するため、カード状態に対するシミュレーションや DP は実行不可能になります。 これは、線形システムを直接解く必要があることを強く意味します。 

線形システムが縮退すると、エッジケースが発生します。 特に、係数がゼロ除算につながる場合、または負の期待寄与を生成する場合、問題ステートメントでは、解を無限として扱う必要があると明示的に述べられています。 この場合、ジョーイが黒のカードを持っていない場合、答えは E に崩壊しますが、そうでない場合は無限になります。 これは、不安定な確率構造の下で期待利得が際限なく増加することを反映しています。 

単純なアプローチでは、反復的な期待値の伝播や遷移のシミュレーションを試みる可能性がありますが、システムには循環依存性があり、浮動小数点反復では確実に収束しないため、失敗します。 さらに微妙な間違いは、クラブの値をスペードの値に与える結合項を無視して、x と y が独立していると仮定することです。 

## アプローチ

 ブルートフォース解釈では、カードの移行プロセスをシミュレートしようとします。 各状態はジョーイの手札の構成を表し、遷移は関連する確率でカードの描画または解決をモデル化します。 これは概念的には簡単ですが、可能な状態の数はカードの数との組み合わせで増加するため、中程度の入力サイズでもこのアプローチは実行不可能になります。 n 枚のカードがある場合、構成の数は指数関数的に増加し、各遷移では期待値の再計算が必要となり、実行不能なランタイムが発生します。

重要な洞察は、システムが真の意味での組み合わせではなく、線形であるということです。 各カード タイプは予想に追加的に寄与し、スペードとクラブの間の相互作用は 2 つの未知数 x と y を通じて完全に把握できます。 この減少が認識されると、問題は確率から導出された係数を使用して 2×2 線形システムを解くことになります。 ステートメント内の再帰はすでに固定小数点方程式になっており、項を並べ替えて代数を使用して直接解くことができます。 

唯一の複雑な問題は、縮退の処理です。 システムの行列式がゼロである場合、または解くと負の値が得られる場合、プロセスは不安定であり、ステートメントに従って、期待される寄与は無限大として扱われます。 これにより、解はフォールバック ケースを伴う条件付き線形代数問題に変換されます。

 ## アルゴリズムのチュートリアル

 まずベースライン期待値 E を計算します。これは問題で与えられた非ジョーイ寄与構造によってのみ決定されます。 この値は、ジョーイが特別なスーツの影響を受けない場合に期待される結果を表します。 

次に、2 つの未知数 x と y を導出します。 これらは、それぞれスペードとクラブの限界予想貢献度に対応します。 ステートメントで指定された漸化関係を標準の線形形式に書き換えます。 

ステップ 1: 両方の方程式に分母を掛けて、端数を除きます。 これにより、確率的な期待が代数的な制約に変換されます。 

ステップ 2: x と y がすべて左側に表示されるように用語を並べ替えます。 これにより、次の形式の線形システムが得られます。 

A₁x + B₁y = C₁

 A₂x + B₂y = C₂

 ステップ 3: 標準消去法を使用して系を解きます。 行列式 D = A₁B₂ − A₂B₁ を計算します。 D がゼロの場合、システムは縮退しており、すぐに無限ケース ルールに切り替えます。 

ステップ 4: D がゼロ以外の場合、クラマーの法則を使用して x と y を計算します。 これにより、期待される寄与を表す正確な合理的な値が得られます。 

ステップ 5: ソリューションの有効性を確認します。 x または y のいずれかが負の場合、システムは不安定であるとして扱い、無限ケース ルールに切り替えます。 

ステップ 6: 有効な場合、最終的な答えを E + x・スペード + y・クラブとして計算します。 

これが機能する理由は、期待がカード タイプの素の寄与に対して線形であり、システムが状態間のすべての依存関係をエンコードしているためです。 x と y は、基礎となるマルコフ期待方程式の固定点であるため、一度解かれると、順序に関係なく一貫したままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, input().split()))
    
    # unpack based on problem structure
    # a, b, c, d represent counts of different suits
    a, b, c, d = data
    
    # baseline expectation
    E = a + c - 1
    
    # coefficients derived from rearranging equations
    # equation system:
    # x = b/(a+b+c)x + (a+c)/(a+b+c)(1+E) + b/(a+b+c+d)x + d/(a+b+c+d)y
    # y = b/(a+b+c)x + (a+c)/(a+b+c)(1+E)
    
    s1 = a + b + c
    s2 = a + b + c + d
    
    # Avoid division by zero edge cases
    if s1 == 0 or s2 == 0:
        print(E)
        return
    
    # convert to linear system Ax = C
    # x - b/s1 x - b/s2 x - d/s2 y = (a+c)/s1 * (1+E)
    # y - b/s1 x = (a+c)/s1 * (1+E)
    
    A1 = 1 - b / s1 - b / s2
    B1 = -d / s2
    C1 = (a + c) / s1 * (1 + E)
    
    A2 = -b / s1
    B2 = 1
    C2 = (a + c) / s1 * (1 + E)
    
    det = A1 * B2 - A2 * B1
    
    # degeneracy check
    if abs(det) < 1e-12:
        print(E)
        return
    
    x = (C1 * B2 - C2 * B1) / det
    y = (A1 * C2 - A2 * C1) / det
    
    # invalid system handling
    if x < 0 or y < 0:
        print("INF")
        return
    
    # assume we are given counts of spades/clubs separately
    spades = b
    clubs = d
    
    ans = E + x * spades + y * clubs
    print(ans)

if __name__ == "__main__":
    solve()
```実装は代数的還元に直接続きます。 最初のステップは、カウントを抽出し、ベースラインの期待値を計算することです。 次に、すべての変数を片側に移動することにより、漸化式が線形システムに変換されます。 システムが小さく、精度の問題が縮退チェックによって制御されるため、浮動小数点演算が使用されます。 

微妙な点は、決定的な閾値です。 確率が近い場合には浮動小数点のキャンセルが発生する可能性があるため、正確なゼロ比較の代わりに小さなイプシロンが使用されます。 もう 1 つの重要な詳細は、無効な解の処理です。負の x または y は、期待値モデルが確率構造の下で破綻し、無限出力条件をトリガーすることを示します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、x と y を結合するすべての係数が消滅する場合です。 その状況では、システムは独立した期待に帰着し、行列式はゼロになります。 アルゴリズムは行列式チェックを通じてこれを検出し、ベースライン E にフォールバックして、ゼロによる除算を防ぎます。 

別のエッジケースは、確率が大きく歪んでいる場合、たとえば b がゼロの場合に発生します。 その場合、方程式は大幅に単純化され、x は完全に y に依存するようになります。 一部の係数がゼロの場合でも線形システムのリダクションは有効なままであるため、ソルバーはこれを正しく処理します。 

最後のエッジケースは、数値の不安定性により計算された期待値が負になる場合です。 アルゴリズムはこれを明示的にチェックし、期待値の無制限の増加という問題の定義に一致する無限のケースに切り替えます。
