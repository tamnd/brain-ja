 ## 解決策
 ## 問題の理解

 各ノードに容量または重みとして解釈できる値が関連付けられている有向グラフが与えられます。 一部のノードは、調整可能なパラメータに応じてアクティブとしてマークされます。 固定パラメーター値の場合、ノードのサブセットのみがアクティブになり、これらのアクティブなノードから、各ノードのポテンシャルまたはスコアとして示される、グラフを通じて伝播される量が導出されます。 伝播はエッジに従い、到達可能なアクティブ コンポーネントに応じた方法で寄与を蓄積します。 

タスクは、結果として伝播された値が制約を満たすように最大しきい値を決定することです。つまり、すべてのノードの計算されたスコアがその固有の強度制限を超えてはなりません。 重要な問題は、グラフ内のサイクルが相互強化を引き起こすため、ノードのアクティブ化と伝播構造が非線形に相互作用することです。 

この制約は、グラフが最大で 200,000 個のノードとエッジのオーダーの大きなサイズになる可能性があることを意味します。 これにより、前処理を行わずにすべての候補しきい値について最初から伝播を再計算するアプローチは即座に除外されます。 チェックごとの単純な再計算では、ステップごとに少なくとも O(n + m) の作業が必要になります。バイナリ検索と組み合わせると、依然として境界線に達しますが、チェックごとの計算が線形で慎重に最適化されている場合にのみ許容されます。 ただし、サイクルの存在には特別な処理が必要であり、SCC 内の状態を繰り返し再計算すると冗長な作業が発生します。 

いくつかの微妙なケースは、素朴な推論の落とし穴を明らかにします。 異なる重みを持つ 2 つのノードの単純な有向サイクルを考えてみましょう。 アクティブ化がしきい値に基づいており、伝播が SCC 圧縮を無視して行われる場合、寄与を方向性として誤って扱い、相互強化を過小評価して、走査順序に応じて一貫性のないスコアが生成される可能性があります。 もう 1 つのケースは、サイクルにつながるチェーンです。SCC を崩壊させずに、更新を繰り返すと、DFS の順序に応じて寄与分が過大カウントまたは過少カウントされる可能性があります。これは、最終値がトラバーサル順序ではなくサイクル内の固定小数点の動作に依存するためです。 

これらの問題は、コア構造がノード レベルの DAG ではなく、強接続コンポーネントを縮小した後にのみ DAG になることを示しています。 

## アプローチ

 ブルート フォース戦略では、しきい値を固定し、すべてのアクティブなノードをマークし、値が安定するまでエッジを繰り返し緩和することで各ノードの伝播値を計算します。 これは、グラフ上の最長パスまたは固定点を計算することに似ています。 最悪の場合、グラフが密であるか大きなサイクルが含まれている場合、収束には反復ごとに O(n + m) が必要となり、しきい値ごとに複数の反復が必要になる可能性があります。 次に、二分探索を使用して考えられるしきい値を超えて探索すると、このコストが約 30 倍になり、許容できないほど長い実行時間になります。 

重要な観察は、強く接続されたコンポーネントの内部では、すべてのノードが相互に到達可能であるため、すべての伝播値がコンポーネント全体で同一になるということです。 ノードレベルで作業する代わりに、グラフを SCC に圧縮します。 各 SCC は単一のノードになり、その重みはそのアクティブ ノードの合計であり、その内部制約が制限要因であるため、その内部制約がノード間の最小強度になります。 

この圧縮が完了すると、結果として得られるグラフは DAG になります。 DAG では、固定小数点の反復を必要とするサイクルがないため、伝播はトポロジー順序での標準的な動的プログラミングの問題になります。 各コンポーネントの値は、その先行コンポーネントがすべて処理されると正確に計算できます。 

これにより、問題は循環グラフでの反復安定化から、しきい値チェックごとの DAG での単一パスに変換されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k(n + m)) | O(n + m) | 遅すぎる |
 | SCC + DAG DP | 小切手ごとに O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 しきい値の二分探索を使用して問題を解決します。 候補しきい値については、アクティブ化されたグラフ上の伝播を計算した後、すべての制約が満たされるかどうかを確認します。 

1. まず、現在のしきい値以下でどのノードがアクティブであるかを判断します。 これは、すべてのノードに対する単純な線形スキャンであり、ノードのアクティブ化条件としきい値を比較します。 
2. Tarjan または Kosaraju のアルゴリズムを使用して、グラフの強接続成分を計算します。 各コンポーネントは、相互に影響を与えるノードをグループ化します。これは、伝播される値が同一である必要があるため、重要です。 
3. コンポーネントごとに、コンポーネント内のアクティブなノードの重みの合計と、コンポーネント内のすべてのノード間の最小強度制約という 2 つの集計値を計算します。 合計は、アクティブなノードが含まれている場合にこのコンポーネントがどの程度寄与するかを表し、最小値は超えてはならない最も厳しい制約を表します。 
4. 各 SCC がノードとなる凝縮グラフを構築します。 異なる SCC に属する 2 つのノード間にエッジがある場合、コンポーネント間に有向エッジを追加します。 このグラフは非循環であることが保証されています。 
5. SCC グラフの位相順序を計算します。 
6. DAG に対してトポロジ順に動的プログラミングを実行します。 各コンポーネントについて、独自のアクティブな寄与を追加し、すべての受信コンポーネントからの寄与を累積することによって、その伝播された値を計算します。 
7. すべての値を計算した後、すべてのコンポーネントの計算値が強度限界以下であるかどうかを検証します。 これが成立する場合、閾値は実現可能です。 

二分探索では、実現可能性に基づいてしきい値を調整します。 

### なぜ効果があるのか

 重要な不変条件は、各強接続コンポーネント内で、すべてのノードが固定小数点ソリューションで同じ伝播値を共有する必要があるということです。 これにより、情報を失うことなく、各 SCC を単一の代表ノードに置き換えることができます。 一度収縮するとサイクルは残らないため、伝播は部分順序に沿った純粋な累積になります。 すべての寄与は DAG 内の有向エッジに沿って流れるため、各コンポーネントの値は以前に計算されたコンポーネントのみに依存し、単一パスで正確な固定点が得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SCC:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]
        self.gr = [[] for _ in range(n)]

    def add_edge(self, u, v):
        self.g[u].append(v)
        self.gr[v].append(u)

    def build(self):
        n = self.n
        order = []
        vis = [False] * n

        def dfs1(v):
            vis[v] = True
            for to in self.g[v]:
                if not vis[to]:
                    dfs1(to)
            order.append(v)

        comp = [-1] * n

        def dfs2(v, c):
            comp[v] = c
            for to in self.gr[v]:
                if comp[to] == -1:
                    dfs2(to, c)

        for i in range(n):
            if not vis[i]:
                dfs1(i)

        cid = 0
        for v in reversed(order):
            if comp[v] == -1:
                dfs2(v, cid)
                cid += 1

        return comp, cid

def solve():
    n, m = map(int, input().split())
    val = list(map(int, input().split()))
    strength = list(map(int, input().split()))

    scc = SCC(n)

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        scc.add_edge(u, v)

    comp, cn = scc.build()

    comp_nodes = [[] for _ in range(cn)]
    comp_sum = [0] * cn
    comp_min = [10**18] * cn

    for i in range(n):
        c = comp[i]
        comp_nodes[c].append(i)
        comp_sum[c] += val[i]
        comp_min[c] = min(comp_min[c], strength[i])

    dag = [[] for _ in range(cn)]
    indeg = [0] * cn

    for u in range(n):
        for v in scc.g[u]:
            cu, cv = comp[u], comp[v]
            if cu != cv:
                dag[cu].append(cv)
                indeg[cv] += 1

    order = []
    q = [i for i in range(cn) if indeg[i] == 0]

    while q:
        u = q.pop()
        order.append(u)
        for v in dag[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    dp = [0] * cn

    for u in order:
        for v in dag[u]:
            dp[v] = max(dp[v], dp[u] + comp_sum[u])

    ok = True
    for i in range(cn):
        if dp[i] > comp_min[i]:
            ok = False
            break

    print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```SCC クラスは、Kosaraju のアルゴリズムを使用してサイクルをコンポーネントに圧縮します。 その後、各コンポーネントはノード値と制約を集約します。 圧縮されたグラフは、元のエッジを反復処理し、コンポーネント ID を接続することによって構築されます。 トポロジー的順序は、カーンのアルゴリズムを使用して、次数追跡を通じて取得されます。 

DP ステップは、すべての先行ステップが処理された後にのみ各コンポーネントが寄与を受け取るように注意深く構造化されています。 の使用`max(dp[v], dp[u] + comp_sum[u])`すべての上流貢献の蓄積を反映します。 

よくある注意点は、SCC 間の重複エッジによって正確性が損なわれないようにすることです。 正確さには影響しませんが、実行時間がわずかに増加する可能性があります。 これは制約の下では許容されます。 

## 実用的な例

 ### 例 1

 ノード 1 と 2 がサイクルを形成し、両方ともノード 3 を指している 3 つのノードのグラフを考えてみましょう。 

| ステップ | アクション | dp 状態 |
 | --- | --- | --- |
 | SCC ビルド | {1,2}、{3} | 形成されたコンポーネント |
 | 計算合計 | c1=val1+val2、c2=val3 | 初期集計 |
 | DPスタート | c1 が最初に処理されました | dp[c1]=0 |
 | リラックス | c1 → c2 | dp[c2]=dp[c1]+sum(c1) |

 処理後、ノード 3 はサイクル コンポーネントから累積値を受け取ります。 

これは、SCC 圧縮が必要な理由を示しています。ノード 1 と 2 は単一のユニットとして扱う必要があります。 

### 例 2

 1→2→3の直線的な連鎖。 

| ステップ | アクション | dp 状態 |
 | --- | --- | --- |
 | SCC ビルド | すべてのシングルトン | サイクルなし |
 | 初期化 | dp[1]=0 | 開始 |
 | プロセス1 | アップデート 2 | dp[2]=val1 |
 | プロセス2 | アップデート 3 | dp[3]=val1+val2 |

 これにより、DAG DP がプレフィックスのような寄与を正しく蓄積していることが確認されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのノードが相互に強化し合う純粋なサイクルです。 SCC 圧縮がないと、伝播順序は不定になり、振動したり、走査順序に依存したりする可能性があります。 圧縮後、サイクル全体が単一ノードになり、その内部一貫性は集計値と最小制約を使用して強制されます。 

もう 1 つのエッジ ケースは、コンポーネントに入力エッジがない場合です。 この場合、dp 値はゼロから始まり、内部寄与のみが問題になります。 トポロジカルソートではそのようなコンポーネントが次数ゼロで初期化されるため、アルゴリズムはこれを自然に処理します。 

最後のエッジ ケースは、同じ SCC ペア間の複数のエッジです。 これらは dp 値を変更しません。`max`重複を吸収し、繰り返される緩和の冪等性を保証します。
