 ## 解決策
 ## 問題の理解

 Monocarp という生徒がいます。彼は次のシーケンスを持っています。`n`学期内の日数。 毎日、彼は勉強するか休むことができます。 勉強することでポイントを獲得するには 2 つの方法があります: レッスンに参加する (価値のある)`l`ポイント）と実践的なタスクを完了する（価値のある）`t`それぞれポイント）。 タスクは毎週ロック解除されます。1 日目に最初のタスク、8 日目に 2 番目のタスク、15 日目に 3 番目のタスクというようになります。 Monocarp は、レッスンに参加することに加えて、いつでも最大 2 つのロック解除されたタスクを完了できます。 

目標は、Monocarp が最低でも収入を得ながら何日休めるかを把握することです。`P`合計ポイント。 入力すると日数が得られます`n`、必要なポイント`P`、レッスンポイント`l`、およびタスクポイント`t`。 出力はテスト ケースごとに 1 つの整数、つまり可能な最大休息日数です。 

制約は大きいです。`n`そして`l`、`t`まで可能です`10^9`、 そして`P`まで可能です`10^18`。 これにより、毎日を直接シミュレートするアプローチは除外されます。 毎日力ずくでカウントするのは遅すぎます。 毎日繰り返すことなく、一定期間にわたって蓄積されたポイントを推論する方法が必要です。 

明らかではないエッジケースは 2 つの観察から生じます。 まず、レッスンがタスクに比べて非常に価値がある場合、Monocarp はほぼ毎日出席しなければならない可能性があります。 たとえば、次の場合`n = 1`、`P = 5`、 そして`l = 5`、彼はまったく休むことができません。 次に、彼が完了できるタスクの最大数は、日数だけでなく、1 日あたり 2 件の制限と毎週のロック解除によっても制限されます。 たとえば、次の場合`n = 8`、8 日目までにロックが解除されるタスクは 2 つだけなので、後で残りのタスクをすべて完了するのに十分な日数がある場合でも、1 日に 2 つを超えるタスクを実行することはできません。 

## アプローチ

 ブルートフォース手法では、毎日をシミュレートし、ロック解除されたタスク、完了したタスク、および蓄積されたポイントを追跡します。 毎日、どれだけ近づいているかに基づいて、勉強するか休むかを選択します。`P`。 これは原理的には正しいですが、テスト ケースごとに O(n) であり、これでは遅すぎます。`n`最大 10^9 および`tc`最大 10^4。 操作数が次を超える可能性があります`10^13`、それは不可能です。 

重要な観察は、勉強は「量が多く」、追加的であるということです。 各学習日には固定のレッスンポイントが与えられます`l`加えて最大 2 つのタスクポイント`t`。 タスクは 1 週間ごとに 1 つのグループでロック解除されるため、特定の日の後に使用できるタスクの最大数を計算できます。 Monocarp は、達成するために必要なだけ少ない学習日数を必要とします。`P`。 問題を再定式化できます: 最小学習日数はどれくらいですか`k`到達するために必要な`P`学習日ごとに常に最大数のタスクを完了するとどうなるでしょうか?

 させて`tasks_total`最終日までにロック解除されたタスクの総数になります。 特定の日に勉強した場合に獲得できる合計ポイント`k`日々は`l * k + t * min(2*k, tasks_total)`。 この合計は少なくとも次のようにする必要があります`P`。 最小値を解くと`k`の場合、最大休息日は単純に次のようになります。`n - k`。 機能が単調なので`k`、二分探索ではこの最小値を見つけることができます`k`効率的に。 これにより、複雑さがテスト ケースごとに O(log n) に軽減されますが、これは許容範囲内です。

 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースあたり O(n) | お(1) | 遅すぎる |
 | 最適 (勉強日の二分探索) | テスト ケースあたり O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 日ごとにロック解除されたタスクの合計数を計算します。`n`。 各タスクは 7 日ごとにロックが解除されるため、タスクの数は`(n + 6) // 7`。 これは、1 日目に最初のタスクのロックが解除され、8 日目に 2 番目のタスクがロック解除されるという事実を説明しています。 
2. ヘルパー関数を定義する`points(study_days)`Monocarp が勉強した場合に獲得できる最大ポイントを計算します。`study_days`日々。 勉強する日ごとに、彼は次のことを得ることができます。`l`レッスンのポイントを獲得し、最大 2 つのタスクを完了できます。 したがって、合計ポイントは、`l * study_days + t * min(2 * study_days, total_tasks)`。 
3. 学習日数にわたって二分探索を実行します。 セット`lo = 0`そして`hi = n`。 各反復で次のことを確認します。`points(mid)`以上です`P`。 「はい」の場合は、設定することで学習日数を減らしてみることができます。`hi = mid`。 それ以外の場合は、設定します`lo = mid + 1`。 まで続ける`lo == hi`。 
4. 戻る`n - lo`最大の休息日数として。 

なぜ機能するのか: 機能`points(k)`単調増加です。 学習日数が増えても合計ポイントが減ることはありません。`points(k)`到達する`P`、増加しています`k`それ以上は不要です。 二分探索では最小値が見つかります。`k`条件を満たすものです。 から引く`n`最大限の休息日を与えます。 1 日あたりのタスク制限と毎週のロック解除は尊重されます。`min(2*k, total_tasks)`両方の制約を考慮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_rest_days(n, P, l, t):
    total_tasks = (n + 6) // 7
    
    def points(k):
        return l * k + t * min(2 * k, total_tasks)
    
    lo, hi = 0, n
    while lo < hi:
        mid = (lo + hi) // 2
        if points(mid) >= P:
            hi = mid
        else:
            lo = mid + 1
    return n - lo

tc = int(input())
for _ in range(tc):
    n, P, l, t = map(int, input().split())
    print(max_rest_days(n, P, l, t))
```コードはまず、ロック解除されたタスクの数を計算します。 ヘルパー関数は、1 日あたり 2 点の制限に従って、与えられた学習日数に基づいて合計ポイントを計算します。 二分探索により、最小限必要な学習日数が効率的に見つかります。 次のような境界条件`0`勉強の日と`n`勉強日は自動的に処理されます。`lo = 0, hi = n`初期化。 

## 実用的な例

 **例 1:**`1 5 5 2`| k (勉強日) | ポイント(k) | 状態 |
 | --- | --- | --- |
 | 0 | 0 | < 5 |
 | 1 | 5 + 2*1 = 7 | >= 5 |

 二分探索の結果`k = 1`、つまり最大休息日 =`1 - 1 = 0`。 

**例 2:**`14 3000000000 1000000000 500000000`タスクの合計 =`(14 + 6)//7 = 2`。 

| k | ポイント(k) | 状態 |
 | --- | --- | --- |
 | 0 | 0 | < 3e9 |
 | 2 | 2e9 + min(4,2)*5e8 = 2e9 + 1e9 = 3e9 | >= 3e9 |

 最小学習日 = 2、最大休息日 = 14 - 2 = 12。 

これらのトレースは、二分探索が効率的に最小限の学習日数を見つけ、タスクの制限を尊重していることを示しています。
