 ## 解決策
 ## 問題の理解

 「0」文字と「1」文字のみで構成されるバイナリ文字列が与えられます。 任意の 2 つの連続する文字の間に特定の挿入操作を実行できます。 2 つの文字が同じ場合は、「1」を挿入します。 異なる場合は「0」を挿入します。 タスクは、これらの演算を任意の数だけ使用して、0 の数を 1 の数より厳密に大きくすることが可能かどうかを判断することです。 

入力には複数のテスト ケースがあり、それぞれの長さは最大 100 の文字列です。長さが短いため、大規模な入力のパフォーマンスの問題を心配することなく、各文字列を慎重に推論できます。 重要な観察は、文字列は挿入によってのみ増加しますが、挿入される文字のタイプは隣接パターンによって完全に決定されるということです。 文字列に隣接する異なる文字が含まれていない場合、ゼロを挿入することはできません。 逆に、文字列に少なくとも 1 つの「01」または「10」が含まれている場合は、さらに多くのゼロを生成できます。 

重要なエッジケースは、文字列が完全に「1」である場合です。 どれだけ挿入を実行しても、等しい文字間に挿入するたびに別の「1」が生成されるため、0 の数が 1 を超えることはできません。 たとえば、「11」と入力すると、答えは「いいえ」になります。 もう 1 つのエッジ ケースは、「0」のような 1 つの「0」を含む文字列です。 ここで、文字列はすでに要件を満たしているため、操作は必要ありません。 

## アプローチ

 ブルートフォースアプローチは、ゼロカウントが 1 カウントを超えるか、すべての可能性を使い果たすまで、考えられるすべての挿入をシミュレートすることです。 挿入するたびに文字列の長さが 1 ずつ増加し、各ステップで考慮すべき O(n) 個の位置があります。 n=100 の場合、このアプローチは組み合わせ的に爆発的に増加し、何百万もの潜在的な文字列が生成され、実行不可能になる可能性があります。 問題を直接モデル化しているため、原理的には機能しますが、明らかに遅すぎます。 

重要な洞察は、操作が隣接する文字に基づいて決定的であるということです。 文字列に既に 1 よりも 0 の方が多い場合、答えは自明に「YES」になります。 それ以上のペアがある場合は、異なる隣接するペアが少なくとも 1 つあるかどうかを確認するだけで済みます。 異なるペアの間に挿入すると 0 が生成され、挿入すると 1 カウントは増加せずに、0 カウントが増加します。 複数の異なるペアで操作を繰り返すことができるため、文字列がすべて 1 でない場合でも、常に 0 が 1 を上回る構成に到達できます。 

この観察により、問題は単純なチェックに集約されます。文字列に少なくとも 1 つの「0」が含まれており、完全に「1」ではない場合、答えは「YES」になります。 文字列がすべて「1」の場合、答えは「いいえ」です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n^2) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、文字列内の 0 と 1 の数を数えます。 0 がすでに 1 より大きい場合は、すぐに「YES」を出力します。 
2. 文字列に 1 のみが含まれている場合は、どの操作もゼロを生成できないため、「NO」を出力します。 
3. 少なくとも 1 つの「0」があり、ゼロの数が 1 より大きくない場合は、隣接する文字が異なる位置があるかどうかを確認します。 このようなペアが存在する場合は、ゼロを挿入して、最終的にゼロが 1 を超えるようにすることができます。 「YES」を出力します。 
4. それ以外の場合は、「NO」を出力します。 

機能する理由: 決定論的な挿入ルールにより、隣接する異なる文字が追加のゼロの唯一のソースであることが保証されます。 一連の演算ではゼロを減らすことも、等しい 1 の間にゼロを挿入することもできません。 したがって、文字列はこれらの挿入によって十分なゼロを生成できるか、不可能かのどちらかです。 異なる隣接ペアのチェックにより、必要な条件が正確に取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    
    zeros = s.count('0')
    ones = s.count('1')
    
    if zeros > ones:
        print("YES")
        continue
    
    if zeros == 0:
        print("NO")
        continue
    
    found_diff_pair = False
    for i in range(n - 1):
        if s[i] != s[i + 1]:
            found_diff_pair = True
            break
    
    if found_diff_pair:
        print("YES")
    else:
        print("NO")
```この解決策は、まず 0 と 1 を数えます。 すでにゼロが優勢である場合、操作は必要ありません。 文字列がすべて 1 の場合、ゼロは挿入できません。 それ以外の場合、ループは少なくとも 1 つの異なる隣接ペアをチェックし、ゼロが挿入される可能性を保証します。 不必要な計算を避けるために、最初の出現で停止します。

 ## 特殊なケース

 単一の「0」を含む最小限の入力エッジ ケースは、アルゴリズムが YES を返すための操作を必要としないことを確認します。 単一の「1」は正しく NO を返します。 「1111」や「0000」など、すべて同一の文字を含む文字列は、唯一の決定要因が初期カウントと異なる隣接ペアの存在であることを示しています。 「1010」のような交互パターンは、ゼロの挿入が常にバランスをシフトする可能性があることを示しており、アルゴリズムは異なるペアのスキャンを通じてこれを正しく検出します。
