 ## 問題の理解

 個別の整数の配列が与えられており、タスクは 2 つあります。まず、配列にまだ存在しない整数を 1 つだけ挿入できます。 次に、正の整数を選択します$x$各操作で追加する操作を実行します$x$単一の要素に。 目標は、挿入後に可能な限り少ない数の操作を使用して、すべての要素を等しくすることです。 出力は、この最小操作数です。 

入力は最大です$2 \cdot 10^5$すべてのテスト ケースにわたる要素、および値は次のような大きさにすることができます。$10^9$規模的には。 これは、すべての可能な値を反復するソリューションを意味します。$x$または、考えられるすべての最終ターゲットが遅すぎます。 テスト ケースごとに線形または線形に近いソリューションが必要です。 不注意なアプローチはいくつかの点で失敗する可能性があります。$x$差の最大公約数を考慮しない、最小限の操作を保証しないで目標値を選択する、または選択できることを忘れる$a_{n+1}$戦略的に操作数を削減します。 たとえば、配列の場合、`[1, 2, 3]`、素朴に選択すると、`a_{n+1} = 0`、操作の数が必要以上に大きくなる可能性があります。 正しい選択は`a_{n+1} = 4`と`x = 1`、操作が 6 に減ります。 

## アプローチ

 ブルートフォースアプローチでは、新しい要素のすべての可能な値と、考えられるすべての値が考慮されます。$x$（またはターゲット）。 各ペアについて、配列を等しくする操作をシミュレートできます。 これは理論上は機能しますが、法外に遅いです。 のために$n \sim 2 \cdot 10^5$、 そして$x$までの範囲$10^9$、すべてのオプションを反復処理することは不可能になります。 

重要な洞察は、新しい要素を選択すると、最適な要素が$x$は、配列内のすべてのペアごとの差の最大公約数 (GCD) です。 これは追加するためです$x$要素に対して繰り返し実行すると、その差を目標値まで埋める必要があり、すべての違いを調整できる最小のポジ​​ティブ ステップは GCD です。 さらに、挿入された要素に対する最良の選択は、最大値または最小値を延長して合計距離を最小化することです。 つまり、どちらかに等しい要素を追加すると、`max + 1`または`min - 1`差の合計が何らかの数で割り切れることを保証します$x$これにより、操作が最小限になります。 

最適なアプローチは、両端を拡張する新しい要素を含めた後で配列の範囲を計算することです。 次に計算します$x$1 つのエンドポイント (最小値など) に対する差の GCD として計算し、差の合計を で割った値として演算数を計算します。$x$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * max( | a_i | )) |
 | 最適 | O(n * log M) | お(1) | 承認済み |

 ここ$M$は配列内の最大値から最小値を引いたもので、GCD 計算を制御します。 

## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 テスト ケースごとに、次の内容を読んでください。$n$そして配列$a$。 
2. 配列の最小値と最大値を計算します。`mn`そして`mx`。 これにより、現在のスプレッドが特定されます。 
3. 新しい要素を次のいずれかとして考慮します。`mn - 1`または`mx + 1`。 これにより、操作の数が確実に削減される形で範囲が拡張されます。 
4. 新しい最小値からのすべての配列要素の差を計算します。 次に、これらの差の GCD を計算します。 これによりステップサイズが得られます$x$オペレーションのために。 
5. 操作の合計数を次の合計として計算します。`(max_value - element) // x`挿入された要素を含むすべての要素に対して。 すべての差は次の式で割り切れるため、これにより最小限の操作数が得られます。$x$。 
6. 操作の合計数を出力します。 

機能する理由: どちらかの端で新しい要素を選択すると、単一の正の要素を使用して相違点を確実に揃えることができます。$x$。 差分の GCD を使用すると、すべての要素が次の整数倍で最大値に到達できることが保証されます。$x$、合計操作数を最小限に抑えます。 新しい要素に対して他の選択肢を選択しても、差分の合計は減らず、必要な操作の数が増加する可能性があります。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        mn, mx = min(a), max(a)
        # Insert an element that extends the range
        new_elements = [mn - 1, mx + 1]
        res = float('inf')
        for new_elem in new_elements:
            arr = a + [new_elem]
            arr.sort()
            # Compute differences
            diffs = [arr[i+1] - arr[i] for i in range(len(arr)-1)]
            x = diffs[0]
            for d in diffs[1:]:
                x = math.gcd(x, d)
            # Compute operations needed
            operations = sum((arr[-1] - num)//x for num in arr)
            res = min(res, operations)
        print(res)

if __name__ == "__main__":
    solve()
```このコードは、まず候補要素を追加して配列を拡張します。 並べ替えると、違いが明確に定義されます。 差の GCD を計算して最適なステップを見つける$x$。 最大値までの距離を次のように割ります。$x$各要素の操作の数を示します。 最後に、挿入候補全体の最小値を選択します。

 ## 特殊なケース

 次のような単一要素配列の場合`[10]`、挿入`9`または`11`結果として`[10,9]`または`[10,11]`。 違いは`1`、そして選択`x=1`必要な操作は 1 回だけです。 単純な解決策は、ゼロ要素に対して GCD を計算しようとしたり、挿入を最適に考慮していなかったりするため、失敗する可能性があります。 アルゴリズムは境界に挿入された要素を正しく選択し、GCD を計算し、1 を出力します。
