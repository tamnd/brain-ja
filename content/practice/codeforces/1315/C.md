 ## 解決策
 ## 問題の理解

 いくつかの素なペアのそれぞれの小さい要素を表す一連の値が与えられます。 最終的な構築では、長さの配列を構築する必要があります。`2n`からのすべての数字を使用して`1`に`2n`正確に 1 回だけ実行し、次に分割します`n`連続したペア。 各ペアについて、指定された値`b_i`は、そのペアに含まれる 2 つの数値の最小値でなければなりません。 

それでそれぞれ`b_i`は単なる制約ではなく、非表示ペアの保証されたより小さいエンドポイントです。 私たちの任務は、すべての企業に個別に大きなパートナーを割り当てることです。`b_i`、残りの未使用の番号を使用して、すべてを完全な順列に配置します。 すべての有効な構造の中で、辞書編集上可能な限り最小の完全な配列を出力する必要があります。 

ここでの辞書順とは、配列を左から右に比較し、異なる最初の位置によってどちらが小さいかを決定することを意味します。 

制約は非常に小さいです。`n ≤ 100`と合計`n`オーバーテストケースも最大です`100`。 これにより、次のような大規模な最適化の必要性が即座に排除されます。`O(n log n)`あるいは`O(n^2)`。 バランスの取れたセットまたはソートされた構造を備えた貪欲な構造で十分です。 

主な問題はパフォーマンスではなく正確さです。特定の条件に対してパートナーの選択が早すぎます。`b_i`後でブロックできる`b_j`有効な解決策が存在する場合でも構築が不可能になります。 任意のパートナーを割り当てる単純なアプローチは、慎重に順序付けされた入力では失敗します。 

典型的な失敗例は次のようになります。非常に大規模なパートナーを初期の小規模なパートナーに貪欲に割り当てたとします。`b_i`、後でのために小さな数字だけを残します`b_j`、有効な大規模パートナーはもう存在しません。 解決策が存在するとしても、貪欲な選択は実現可能性を壊します。 

## アプローチ

 強引なアイデアでは、それぞれに割り当てを試みることになります。`b_i`それより大きいすべての未使用の数値の中からパートナーを選択し、すべての組み合わせを再帰的にチェックします。 これはすぐに爆発します。`n`我々が持つ可能性のある要素`O(n)`選択肢、おおよその結果につながる`n!`最悪の場合の可能性も。 でさえ`n = 100`、これはまったく不可能です。 

重要な観察点は、それぞれが`b_i`必要なパートナーは 1 つだけです。唯一の制約は、パートナーが厳密に大きくて未使用である必要があることです。 これは、パートナーを貪欲に、しかし慎重に割り当てる必要があることを示唆しています。将来の制約を満たすために必要になる可能性があるときに、利用可能な少数の数を消費することは避けたいと考えています。 

辞書編集上の最小限の要件は、順序付けに関する強力なヒントを与えます。 前の位置が辞書編集上の順序を支配するため、各ペアが次の順序で始まるようにします。`b_i`(これは固定です)、各ステップで可能な限り最小の有効なパートナーを選択します。 正しい貪欲な選択は次のとおりです。`b_i`、より大きい未使用の最小の数値を選択します。`b_i`。 

これが機能するのは、必要以上に大きいパートナーを使用すると、辞書編集上の順序が改善されずに後のステップの柔軟性が低下するだけであり、最小の有効なパートナーが将来の割り当てのためのほとんどのオプションを保持するためです。

 ## アルゴリズムのチュートリアル

 当社では、利用可能な番号のプールを維持しています。`1`に`2n`まだ使用されていないもの。 

1. 以下のすべての数値を含むソートされた構造を初期化します。`1`に`2n`。 これは、引き続き割り当てることができるすべての使用可能な値を表します。 
2. 値を処理する`b_1, b_2, ..., b_n`指定された順序で。 順番は決まっているので、`b_i`は、最終配列の i 番目のペアに対応します。 
3. それぞれについて`b_i`、最後の順列に表示される必要があるため、使用可能なプールから削除します。 
4. 次にパートナーを選択する必要があります`x_i`そのような`x_i > b_i`。 利用可能なすべての候補の中から、そのような最小の数を選択します。 この選択により、制約を満たしながら辞書編集上の接頭辞が可能な限り小さく保たれます。 
5. 使用可能な数値が厳密に大きい値がない場合は、`b_i`、建設は不可能であるため、`b_i`cannot be paired with any valid larger element.
 6. 1回`x_i`が選択されている場合は、プールから削除してペアを記録します`(b_i, x_i)`。 
7. すべての処理が完了したら`b_i`、すべてのペアの連結を順番に出力します。`(b_1, x_1, b_2, x_2, ..., b_n, x_n)`。 

### なぜ効果があるのか

 重要な不変条件は、最初の処理後、`k`要素、正確に使用しました`k`からの値`b`そして`k`残りの未使用番号はすべて、将来のペアリングに使用できます。 各ステップで、実行可能な最小のパートナーを選択することで、将来的に必要になる可能性が高い小さな数値を不必要に消費することがなくなります。`b_j`より大きくなる可能性のある値`b_i`しかし、それでもしっかりとしたフィット感が必要です。 

それぞれだから`b_i`が固定され、そのペアの最初の要素として表示される場合、辞書編集上の最適性は、選択された各パートナーをできるだけ早く最小化することになります。 より大きなパートナーへの逸脱は、シーケンスが異なる最も早い位置で大きくなるだけであり、新たな実現可能性が解放されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))
        
        available = set(range(1, 2 * n + 1))
        res = []
        
        possible = True
        
        for x in b:
            if x not in available:
                possible = False
                break
            available.remove(x)
            
            # find smallest y > x
            cand = None
            for y in range(x + 1, 2 * n + 1):
                if y in available:
                    cand = y
                    break
            
            if cand is None:
                possible = False
                break
            
            available.remove(cand)
            res.extend([x, cand])
        
        if not possible:
            print(-1)
        else:
            print(*res)

if __name__ == "__main__":
    solve()
```実装は貪欲なアイデアに直接従っています。 の`available`未使用のトラック番号を設定します。 それぞれについて`b_i`、上方向に線形にスキャンして、それより大きい最小の有効なパートナーを見つけます。 制約を考慮すると`2n ≤ 200`、このスキャンは十分に効率的です。 

微妙な点としては、`b_i`まだ中にあるはずだ`available`加工されたとき。 そうでない場合は、置換制約がすでに違反されています。 もう 1 つの重要な点は、常に削除することです。`b_i`パートナーを検索する前に、誤って再利用しないようにします。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
b = [1, 3, 2]
```利用可能な数と構造を追跡します。 

| ステップ | b_i | | より前に利用可能 選ばれたパートナー | |以降に利用可能
 | --- | --- | --- | --- | --- |
 | 1 | 1 | {1..6} | 2 | 1、2を削除 |
 | 2 | 3 | {3,4,5,6} | 4 | 3,4を削除 |
 | 3 | 2 | {2,5,6} | 5 | 2,5を削除 |

 最終的な配列:`1 2 3 4 2 5`ペアによる順序付けは無効ですが、構成どおりです。`[1,2, 3,4, 2,5]`すべての最小値を尊重するペア (1,2)、(3,4)、(2,5) に対応します。 

このトレースは、それぞれの`b_i`は直ちにペアにロックされ、最小の有効なパートナーが常に選択されます。

 入力:```
n = 2
b = [2, 1]
```| ステップ | b_i | | より前に利用可能 選ばれたパートナー | 結果 |

 最終的な配列:`2 3 1 4`これは、たとえ次のような場合でも、`b`がソートされていない場合でも、貪欲な選択によって有効な辞書編集上の最小限の構造が生成されます。

 ## 特殊なケース

 微妙なエッジケースが発生するのは、`b_i`に近いです`2n`となり、これ以上の数は利用できなくなります。 たとえば、次の場合`b_i = 2n`、有効なパートナーが存在せず、アルゴリズムはより大きな要素をスキャンするときに正しく失敗します。 

別のケースは、初期の選択が後で必要になる小さな中間数値を消費する場合に発生します。 アルゴリズムは常に最小の有効なパートナーを選択するため、大きなギャップを不必要に「無駄に」することがなくなり、将来のステップの柔軟性が維持されます。 この貪欲な選択により、ソリューションが存在する場合、初期の過度に積極的な割り当てによってそのソリューションが破壊されることがなくなります。
