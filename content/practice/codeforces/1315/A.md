 ## 解決策

 ## 問題の理解

 幅のある長方形の画面が与えられます`a`と高さ`b`、整数座標を持つピクセルのグリッドとして扱われます。 1 つのピクセルがその位置で壊れています`(x, y)`。 目標は、内部にこの壊れたピクセルを含まず、可能な限り大きな面積を持つ、軸に揃えられた長方形のサブウィンドウを選択することです。 

重要な制約は幾何学的なものです。ピクセルを削除したりグリッドを変更したりするのではなく、辺が画面の端に平行な長方形を選択します。また、その長方形には禁止点が含まれないようにする必要があります。 

各テスト ケースは独立しているため、その構成で達成可能な最大面積を計算する必要があります。 

入力サイズはテスト数の観点から大きく、最大で`10^4`、各ケースは小さく、定数時間で計算可能です。 これにより、四角形の候補を列挙したり、配置をシミュレートしようとするソリューションは即座に排除されます。 どのアプローチでも、各テスト ケースを O(1) の演算に減らす必要があります。 

単純なメンタル モデルでは、考えられるすべての長方形を試して、デッド ピクセルが回避されるかどうかを確認することになります。 これは失敗します。`a × b`グリッドは次のとおりです`a^2 b^2`、これは実現可能な限界をはるかに超えています。`a, b`までです`10^4`。 

より微妙な失敗例は、最良の長方形が単に画面全体から単位セルを引いたものであると仮定することから生じます。 これは不正確です。デッド ピクセルの削除は 1 つのセルを切り出すことを意味するわけではありません。四角形がその内部にまたがる境界隣接の場合も含め、その内部のどこかにその座標を含む四角形を除外する必要があります。 

たとえば、次のことを考えてみましょう。`5 × 1`中央の行にデッドピクセルがある画面。 素朴な考えでは、最適な長方形は次のとおりであると思われます。`5 × 1 = 5`ただし、ピクセルが水平方向の分割をブロックしている場合、包括性ルールの解釈に応じて、側セグメントのみを取得することで最適な解決策が得られる可能性があります。 正しい推論は、単一のセルを削除するのではなく、ポイントの周囲で分割することに依存します。 

最大の難点は、有効な長方形は、グリッドを分割して形成される 4 つの領域の 1 つに完全に収まらなければならないことを認識することです。`(x, y)`。 

## アプローチ

 ブルートフォース手法では、考えられるすべての四角形を試します。`(x1, y1)`に`(x2, y2)`かどうかを確認します`(x, y)`その中にあります。 これは制約を直接強制するので正しいですが、遅すぎます。 長方形の数はおおよそ`(a(a+1)/2) × (b(b+1)/2)`、約に達します`10^16`最悪の場合、手術は完全に不可能になります。 

重要な観察は、デッドピクセルを回避する長方形は、垂直線と水平線を引いて形成される、軸が揃った 4 つの象限の 1 つに完全に収まる必要があるということです。`(x, y)`:

 - 左側: 列`[0, x]`- 右側: 列`[x, a-1]`- 上側: 行`[0, y]`- 下側: 行`[y, b-1]`ただし、長方形には点自体が含まれないようにする必要があるため、分割を慎重に扱い、片側での完全な包含を考慮します。 

最適な長方形は、次の 4 つの領域のいずれかに完全に収まる必要があります。 

- 左上のブロック:`(x+1) × (y+1)`- 右上のブロック:`(a-x) × (y+1)`- 左下のブロック:`(x+1) × (b-y)`- 右下のブロック:`(a-x) × (b-y)`それぞれは、垂直および水平のカットの片側に完全に収まる長方形を選択することに対応し、デッドピクセルが内部に存在しないことを保証します。 

4 つの定数式の最大値だけが必要なので、各テスト ケースは O(1) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(a²b²) | お(1) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 値を読み取る`a, b, x, y`テストケースごとに。 これらは完全なグリッドと禁止された座標を定義します。 
2. 周囲を分割して形成される 4 つの長方形領域の候補を計算します。`(x, y)`。 各候補は、4 つの方向領域の 1 つに完全に収まる長方形を選択することに対応します。 

4 つの領域は次のとおりです。 

-`(x + 1) * (y + 1)`-`(a - x) * (y + 1)`-`(x + 1) * (b - y)`-`(a - x) * (b - y)`各式は、カットの各側で使用可能な列と行の数を数えることから得られます。 
3. これら 4 つの値の最大値を取得します。 これは、軸を揃えたままデッドピクセルを回避する最大の長方形を表します。 
4. テストケースの結果を出力します。 

### なぜ効果があるのか

 を避ける有効な長方形`(x, y)`その内部にその正確な座標を含めることは避けなければなりません。 長方形は軸に揃えられているため、左と右の両方にまたがる長方形は、`x`、そして上下両方`y`、ポイントが含まれている必要があります。 これにより、すべての有効な長方形が、垂直方向と水平方向のカットによって定義される 4 つの領域の 1 つに完全に収まるようになります。`x`そして`y`。 各領域は 4 つの面積公式のいずれかに正確に対応するため、最適解はそれらの最大値でなければなりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, x, y = map(int, input().split())

    ans = max(
        (x + 1) * (y + 1),
        (a - x) * (y + 1),
        (x + 1) * (b - y),
        (a - x) * (b - y)
    )

    print(ans)
```この実装は、4 つの領域の分解を直接変換したものです。 各項は、デッドピクセルを基準にして長方形の一辺を固定し、残りの寸法を最大化することに対応します。 

唯一の微妙な点は、off-by-one 推論を正しく処理することです。`x + 1`から利用可能な列の数を表します。`0`を通して`x`、 そして`a - x`から利用可能な列の数を表します。`x`を通して`a - 1`。 同じ対称性が次の場合にも当てはまります`y`。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        a, b, x, y = map(int, input().split())
        out.append(str(max(
            (x + 1) * (y + 1),
            (a - x) * (y + 1),
            (x + 1) * (b - y),
            (a - x) * (b - y)
        )))
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

 ## 特殊なケース

 次のようなコーナー配置`(0, 0)`4 つの候補領域のうち 3 つを強制的に崩壊させ、原点から伸びる長方形だけを残します。 計算`(x + 1)`そして`(y + 1)`になる`1`したがって、最大値は反対の軸に沿った完全な伸長から得られ、公式は依然としてそれを正しく捉えています。 

のような境界ケース`a = 1`これにより、問題が 1 つの列に縮小され、垂直方向の分割のみが問題となります。 表現`(a - x)`そして`(x + 1)`どちらもなる`1`最大値を確保することは、デッドピクセルの行を回避する最長の連続セグメントを選択することになります。 

完全に中央のデッドピクセルにより、4 つの象限すべての間の対称性が最大化されます。 その場合、答えは常に約半分の次元の 4 つの積の 1 つとなり、max 式は特別なケースを使用せずに最適なパーティションを正しく選択します。
