 ## 解決策
 ## 問題の理解

 それぞれ偶数の要素を持つ、いくつかの独立した配列が与えられます。 各配列について、すべての数値が正確に 1 つのペアに属し、各ペアが互換性ルールを満たすように、すべての要素を素のペアに分割できるかどうかを決定する必要があります。 

2 つの数値は、同じパリティを共有するか、正確に 1 だけ異なる場合、互換性があります。 同じパリティは、両方が偶数であるか、両方が奇数であることを意味します。 タスクは純粋に実現可能性であり、構築ではありません。 

制約構造は小さく、各配列の要素数は最大 50、値は最大 100、テスト ケースは最大 1000 個です。 これにより、50 要素を超える単純なマッチングは何度も繰り返されると実用的な限界を超えてしまうため、ペアリングに対する指数関数的な検索のようなものは排除されます。 ただし、値の範囲が小さく、構造も均一であることから、明示的なグラフ マッチングではなく、貪欲またはカウントベースの不変式を探す必要があることがわかります。 

パリティはバランスが取れているように見えても、ローカル構造がペアリングをブロックする場合、微妙なエッジ ケースが発生します。 たとえば、次のように考えてみましょう`[1, 2, 3, 4]`。 奇数が 2 つ、偶数が 2 つあるため、パリティ数は問題ないように見えますが、ペアリングでは隣接関係の制約を考慮する必要があります。 パリティのみで貪欲に一致させると、残りの不一致を解決するために奇数偶数の隣接関係が必要であることを見落とす可能性があります。 もう 1 つのエッジ ケースは、値が緊密にクラスター化されている場合です。`[1, 1, 2, 3]`、有効な取り決めが存在するにもかかわらず、単純なパリティ ペアリングは失敗します。 

これらの失敗は、パリティだけでは不十分であるだけでなく、その構造が十分に制約されていて、依然としてグローバル パリティ バランスが答えを支配していることを示唆しています。 

## アプローチ

 ブルートフォース手法では、要素を再帰的にペアリングしようとします。つまり、未使用の要素を選択し、互換性のある他のすべての要素とペアにして、再帰的に試みます。 これは、互換性グラフでの古典的な完全一致検索です。 ノード数が 50 の場合、ペアリング状態の数は (50-1)!! のオーダーとなり、天文学的に多くなります。 枝刈りを行ったとしても、これを 1000 のテスト ケースにわたって繰り返すことは不可能です。 

重要な点は、互換性が非常に制限されているということです。 任意の番号を次のものと組み合わせることができます。 

1. 同じパリティの任意の数。 
2. 逆パリティは最大 2 つの数値、つまり x-1 と x+1 です。 

これは、ローカルな ±1 調整を通じてパリティ グループのバランスが取れていることを確認するだけでよいことを意味します。 配列をソートする場合、隣接する値間で要素をシフトすることでパリティの不一致を「平滑化」できるかどうかが問題になります。 

標準的な洞察は、並べ替えによって問題がパリティの不均衡を順番に制御することに帰着するということです。 連続した要素に注目すると、奇数の孤立した要素は、±1 構造を介して別の奇数または隣接する偶数とペアになる必要があります。 重要な特性は、隣接する互換性のある要素を左から右に並べ替えて貪欲にペアリングすると、パリティの不一致をローカルで修復できない場合にのみ失敗するということです。これは、修正できない奇数のプレフィックスの不均衡に相当します。 

これは、貪欲なペアリング戦略につながります。つまり、配列をソートし、マルチセットのようなプロセスを使用して要素を貪欲に一致させようとし、常に可能な限り早い段階で有効なペアを消費します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に解決します。 

1. 配列をソートします。 ソートは、潜在的な ±1 の一致が隣接または隣接するように値を調整します。非パリティの柔軟性は連続する整数間のみであるため、これは不可欠です。 
2. 各値のカウントのマルチセットのような構造を維持します。 値が 100 以下であるため、頻度配列で十分です。 これにより、ペアリングがポインターのマッチングではなく、制御された消費に変換されます。 
3. 値を最小値から最大値まで繰り返します。 各値 x について、最初に、可能な場合は同じ値カウント内でペアを作成することにより、同じパリティのペアをできるだけ多く暗黙的に削除しようとします。 
4. x に残りの出現がある場合、それらを x+1 とペアにしようとします。 これは、以前の決定を破ることなく、残った不均衡を局所的に解決できる唯一の方向です。 それに応じて両方のカウントを減らします。 
5. すべての値を処理した後、すべてのカウントがゼロかどうかを確認します。 残っている場合はペアリングできません。 

重要な考え方は、すぐに行える決定を決して延期せず、常に値空間でローカル構造を左から右に解決することによって、すべての有効なペアリングをシミュレートできるということです。 

### なぜ効果があるのか

 このアルゴリズムは、周波数配列全体にわたって単調不変式を維持します。値 x の処理が終了すると、有効な解では x を再検討する必要はありません。これは、x に関係するペアは (x, x) または (x, x+1) のいずれかでなければならないためです。 より小さい値のペアはすでに処理されており、問題の制約の下ではより大きなギャップのペアは不可能です。 これにより、±1 の隣接関係を超える長距離の依存関係がないため、すべての決定が局所的に最適でグローバルに一貫したものになることが強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = [0] * 105
        for x in a:
            freq[x] += 1
        
        ok = True
        
        for x in range(1, 101):
            if freq[x] < 0:
                ok = False
                break
            
            if freq[x] % 2 == 1:
                if x == 101:
                    ok = False
                    break
                freq[x] -= 1
                freq[x + 1] -= 1
            
            if freq[x] < 0:
                ok = False
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```値が小さいため、このソリューションでは配列を周波数に圧縮します。 ループは値を昇順に処理するため、値 x での不均衡を修正するたびに、コストが x+1 にのみ押し上げられます。 これにより、後戻りが必要なくなります。 

パリティチェック`freq[x] % 2 == 1`残りの単一要素は、唯一許可される非パリティ エッジ (差分 1) を使用して前方一致する必要があるという考えをエンコードします。デクリメント ステップは、ペア (x, x+1) の形成をシミュレートします。 

無効な順方向ペアリングは x+1 を過剰に消費する可能性があるため、調整直後に負の周波数をチェックするように注意する必要があります。

 ## 特殊なケース

 みたいな小さなケース`[1, 3]`パリティも隣接も成立しないため、即時に失敗することを示します。 アルゴリズムは x=1 を処理し、奇数のカウントを確認し、x+1=2 から消費しようとしますが、サポートが見つからないため、負の頻度が生成され、正しく拒否されます。 

で`[1, 2, 3, 4, 5, 6]`、奇数の残りがそれぞれ前方に解決され、ローカル修正のチェーンが形成されます。 各ステップで次の値は減少しますが、負の周波数は決して生成されず、シーケンスが密な場合には順方向伝播で十分であることが確認されます。 

で`[1, 1, 2, 4]`、重複する 1 により 1 つの内部ペアが許可され、2 と 4 が残ります。 このアルゴリズムは、3 が存在する場合にのみ 2 を前方にペアリングできることを示していますが、構造は以前のペアリングによって解決されるため、最終状態は一貫したままであり、重複が局所的にパリティ圧力を安定させることが確認されます。
