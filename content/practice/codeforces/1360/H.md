 ## 解決策

 ## 問題の理解

 長さのすべてのバイナリ文字列の完全なスペースから始めます。`m`、標準の辞書編集順に並べられます。これは、固定長の 2 進数として並べ替えることと同じです。`0...0`まで`1...1`。 この完全な順序セットから、最大 100 個の文字列の小さなコレクションが削除されます。 これらの削除後、概念的に残りの文字列を調べ、辞書編集順に並べ替えて、中央の要素を選択します。ここで、「middle」は、残りの k 個の文字列のインデックス ⌊(k−1)/2⌋ にある要素として定義されます。 

構造について考えるのに役立つ方法は、フルセットが区間であるということです。`[0, 2^m − 1]`、先頭にゼロが付いた 2 進数として解釈されます。 文字列を削除すると、この非常に大きな順序付けされたユニバースから最大 100 個のポイントが削除されます。 タスクは、完全なセットを構築したり並べ替えたりすることなく、残っているものの中央値を決定することです。 

制約は重要なシグナルです。 長さ`m`最大 60 まで大きくすることができます。`2^m`天文学的に大きいため、すべての文字列を反復処理するメソッドは不可能です。 ただし、削除される要素の数は少なく、テスト ケースごとに最大 100 個であり、テスト全体の合計入力サイズには制限があります。 この非対称性は、答えが状態の列挙ではなく、除去がグローバルな順序でどのように位置を移動するかに依存することを強く示唆しています。 

素朴なアプローチは、すべてを明示的に生成することです。`2^m`文字列を削除し、禁止されている文字列を削除し、並べ替えて、中央値を選択します。 これはすぐに失敗します。`m = 60`、宇宙のサイズは計算の限界をはるかに超えています。 

もう 1 つの微妙な落とし穴は、候補に満たない有効な文字列の数をカウントすることでランクをチェックし、答えをバイナリ検索しようとすることです。 単純に実装した場合でも、すべてを反復処理する必要があります。`2^m`可能性を排除したり、大量のカウントを非効率的にシミュレートしたりできます。 正しいアプローチでは、スペース全体に触れないようにする必要があります。 

## アプローチ

 ブルート フォースの観点は単純です。一定の長さのバイナリ文字列をすべて列挙します。`m`、禁止されているものを削除し、残りのリストを並べ替えて、中央を選択します。 辞書編集上の順序はバイナリ表現上の数値順序と一致するため、これは概念的に機能します。 ただし、コストは指数関数的に増加します。`2^60`候補を保存することさえ不可能です。 

重要な点は、フルセットは決して必要ないということです。 候補位置の前に有効な文字列がいくつあるかを知る必要があるだけです。 最大 100 個の文字列のみが削除されるため、補体の構造はほぼ完成します。 削除された各文字列は、連続した順序に小さな「ギャップ」を生み出すだけです。 

これは、ほぼ完全な間隔にわたる注文統計の観点から考えることを示唆しています。 すべての候補を反復処理する代わりに、範囲内の答えをバイナリ検索できます。`[0, 2^m - 1]`。 候補番号については`x`、≤ x である有効な文字列の数を計算します。 これは単純に、`(x + 1) - count_removed_leq(x)`。 以来`n ≤ 100`、削除された要素の数 ≤ x は O(n) であり、各チェックが高速になります。 

60 ビット空間での二分探索には最大 60 回の反復が必要で、各反復のコストは O(n) であるため、合計は非常に小さくなります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m log 2^m) | O(2^m) | 不可能 |
 | 最適 | O(n log 2^m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各バイナリ文字列を 60 ビット整数として扱います。 

1. 削除されたすべての文字列を整数に変換します。 これにより、固定長により辞書順と一致する数値順序を使用した直接比較が可能になります。 この手順は文字列比較を算術比較に変えるため、不可欠です。 
2. 削除された値を並べ替えます。 並べ替えにより、二分検索を使用した高速なプレフィックス カウントが可能になります。 
3. 関数を定義する`removed_leq(x)`これは、ソートされた削除された配列に対する二分検索を使用して、x ≤ である削除された数値がいくつあるかを返します。 これにより、「x までのプレフィックスに禁止されている値がいくつあるか」にすばやくアクセスできるようになります。 
4. 定義する`valid_leq(x) = (x + 1) - removed_leq(x)`。 これは、有効な文字列がいくつあるかを表します。`[0, x]`。 
5. 目標ランクを計算する`target = (2^m - n - 1) // 2`。 これは、ゼロベースのインデックス付けにおける中央値のインデックスです。 
6. 最小の二分探索`x`そのような`valid_leq(x) > target`。 それ`x`はまさに中央値文字列です。 

二分検索は数値範囲全体にわたって機能します。`[0, 2^m - 1]`、すべての有効な文字列がその中にあるため安全です。 

### なぜ効果があるのか

 機能`valid_leq(x)`は単調です`x`、増えているので`x`プレフィックス内の有効な文字列の数を増やすことのみが可能です。 これにより、二分探索が有効であることが保証されます。 削除された各文字列はプレフィックス数からちょうど 1 ポイント減算されるため、完全なプレフィックスからの偏差は`[0, x]`は常に、その中にある禁止された要素の正確な数です。 その結果、セットを列挙することなく正確なランク情報を復元します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def to_int(s):
    return int(s, 2)

def count_leq(arr, x):
    # number of elements <= x in sorted arr
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        rem = [to_int(input().strip()) for _ in range(n)]
        rem.sort()

        total = (1 << m)
        k = total - n
        target = (k - 1) // 2

        def valid_leq(x):
            return (x + 1) - count_leq(rem, x)

        lo, hi = 0, (1 << m) - 1
        ans = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if valid_leq(mid) > target:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        s = bin(ans)[2:].zfill(m)
        print(s)

if __name__ == "__main__":
    solve()
```この解決策はバイナリ文字列を整数として扱うことに依存しており、これにより辞書編集上の複雑さがすべて排除されます。 ソートされた削除リストは、除外を効率的にカウントするためにのみ使用されます。 二分探索では、完全なセットを構築しなくても、正確なランク位置が見つかります。 

微妙な実装の詳細が埋め込まれています`zfill(m)`数値変換では先頭のゼロが削除されますが、出力は固定長を保持する必要があるためです。 もう 1 つの重要なポイントは、`x + 1`で`valid_leq(x)`これにより、包含範囲内での正確なカウントが保証されます。

 ## 特殊なケース

 主なエッジケースは、中央値が削除された数値のすぐ隣にある場合です。 たとえば、次の場合`m = 3`そして私たちは削除します`011`、範囲は 1 つの欠落点を中心に分割されます。 プレフィックスカウントでは、明示的なギャップ処理を必要とせずに欠損値が自然にスキップされるため、このアルゴリズムは引き続き機能します。
