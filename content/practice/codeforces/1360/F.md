 ## 解決策
 ## 問題の理解

 同じ長さの文字列がいくつか与えられているので、同じ長さの新しい文字列を構築したいとします。 要件は、この構築された文字列が指定されたすべての文字列に非常に近い必要があることです。入力文字列ごとに、最大 1 つの位置で構築された文字列と異なることが許可されます。 

これを理解するもう 1 つの方法は、すべての入力文字列が答えに「同意しない」のは 1 回だけであるということです。 すべての位置にわたって、各文字列は最大 1 つの不一致を許容します。 

タスクは、辞書編集順などを最適化したり、変更を最小限に抑えたりすることではありません。 有効な構造が存在するかどうかを判断し、有効な文字列を 1 つ出力するだけで済みます。 

制約は非常に特殊な点で小さく、文字列の数と長さは両方とも最大 10 です。これにより、漸近的な最適化トリックの必要性が即座に排除されます。 検索スペースは最大でも$26^{10}$、しかし、より重要なのは、位置ごとにローカルに考える場合、制約の構造によりブルートフォースが不要になるということです。 

素朴だが自然な考えは、答えを 1 文字ずつ構築してみることです。 ただし、各位置での局所的な合意だけを個別に考慮すると、微妙な故障モードが現れます。 制約は位置ごとではなく文字列ごとにグローバルです。 

たとえば、各位置で多数派の文字を選択しようとするとします。 それぞれの位置が個別に安全であるように見えても、1 つの文字列が 2 つの異なる位置で異なる可能性があるため、これは失敗する可能性があります。 

考慮する：```
n = 2, m = 3
a1 = "aba"
a2 = "bab"
```私たちが選ぶなら`"aaa"`多数決の論理により、両方の文字列が 2 回異なり、これは無効です。 したがって、位置に関する貪欲さは安全ではありません。 

主な問題点は、各文字列に正確に 1 つの不一致のバジェットがあり、これらの不一致をすべての位置に一貫して分散する必要があることです。 

## アプローチ

 ブルートフォースの観点は、応答文字列も長さであるという観察から始まります。$m \le 10$, したがって、26 文字を超えるすべての可能な文字列を試すことができます。 候補文字列ごとに、すべての入力文字列をチェックし、不一致をカウントします。 すべての文字列に最大 1 つの不一致がある場合は、受け入れられます。 

これは正しいですが、高価です。$26^m$候補者と各小切手のコスト$O(nm)$。 最悪の場合$m = 10$、これは次のようになります$26^{10} \approx 1.4 \cdot 10^{14}$、これは実現不可能です。 

コンディションの構造により、より鮮明な視界が得られます。 すべての文字列は最大でも 1 つの位置で答えと異なる可能性があるため、逆に考えることができます。つまり、すべての入力文字列に近い「ベース文字列」を推測した場合、すべての入力文字列はそれに等しいか、正確に 1 つの位置で異なります。 これは、各文字列は答えからの 1 つの逸脱のみを許容できるため、答えが少なくとも 1 つの入力文字列に非常に近い必要があることを示唆しています。 

重要な洞察は、指定された文字列の 1 つに構造を固定することです。 各入力文字列を試してみるとします$a_i$テンプレート候補として。 から始めると$a_i$、最終的な答えは、最大でも 1 つの位置でそれと異なる必要があります。$a_i$それ自体は、最大でも 1 つの位置で答えと異なっていなければなりません。 したがって、答えは次のいずれかを維持することで得られます。$a_i$変更されないか、その位置の 1 つだけが変更されます。 

これにより、検索スペースが大幅に削減されます。$a_i$、ゼロまたは 1 文字を変更してみて、すべての文字列に対して実現可能性を検証するだけです。 

以来$n, m \le 10$、これは非常に小さくなります: 最大でも$10 \times (1 + 10 \times 25)$候補者たち。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての文字列に対するブルート フォース |$O(26^m \cdot nm)$|$O(1)$| 遅すぎる |
 | 各基本文字列を試し、≤1 個の位置を変更します。$O(n^2 m \cdot 26)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各文字列を反復処理します。$a_i$そしてそれを潜在的なベース文字列として扱います。 

その理由は、最終的な答えは最大でも 1 つの位置ですべての入力文字列と異なっていなければならないため、どの入力文字列からも離れすぎてはいけないためです。 
2. まず、設定した候補をテストします$s = a_i$変更なしで。 

すべての文字列について計算します$a_j$、どのくらいの位置が異なりますか$s$そして$a_j$、すべてが最大 1 であることを確認します。 
3. 変更されていないベースが機能する場合は、すぐに出力できます。 

これは、1 つの入力文字列がすでにグローバル制約を満たしている場合に対応します。 
4. そうでない場合は、ちょうど 1 つの位置を変更してみてください。$a_i$。 ポジションごとに$p$0から$m-1$、各キャラクターごとに$c$「a」から「z」までを置換して候補文字列を形成します$a_i[p]$と$c$。 
5. このような各候補について、同じ方法ですべての入力文字列に対して検証し、文字列ごとに不一致を数えます。 

文字列が複数の位置で異なる場合、候補は破棄されます。 
6. 合格した候補者があれば、すぐに出力します。 
7. 文字列も単一位置の変更も機能しない場合は、-1 を出力します。 

正しさは、有効な答えがすべての入力文字列から最大 1 のハミング距離内に存在する必要があり、したがって、その中から選択された有効な塩基候補から最大 1 の距離内になければならないという事実にかかっています。 

### なぜ効果があるのか

 有効な答えを仮定する$s$存在します。 任意の入力文字列を選択します$a_i$。 以来$a_i$とは異なります$s$多くても 1 つの位置で、$a_i$そして$s$最大でも 1 つのインデックスが異なります。 つまり、$s$から入手できます$a_i$最大 1 文字を変更することによって。 

したがって、解決策が存在する場合、それはいくつかの関数から生成された列挙の中に現れる必要があります。$a_i$： どちらか$a_i$それ自体、または 1 文字の変更。 全部試してみるので$a_i$、私たちは遭遇しなければなりません$s$。 検証ステップにより、真に有効な構造のみを受け入れることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(s, arr, n, m):
    for a in arr:
        diff = 0
        for i in range(m):
            if s[i] != a[i]:
                diff += 1
                if diff > 1:
                    return False
        if diff > 1:
            return False
    return True

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    arr = [input().strip() for _ in range(n)]

    ans = None

    for base in arr:
        if ok(base, arr, n, m):
            ans = base
            break

        base = list(base)
        found = False

        for i in range(m):
            original = base[i]
            for c in "abcdefghijklmnopqrstuvwxyz":
                base[i] = c
                candidate = "".join(base)
                if ok(candidate, arr, n, m):
                    ans = candidate
                    found = True
                    break
            base[i] = original
            if found:
                break

        if ans is not None:
            break

    if ans is None:
        print(-1)
    else:
        print(ans)
```このコードは、各入力文字列をアンカーするという建設的なアイデアに直接従っています。 ヘルパー関数`ok`明示的に不一致をカウントし、ペアが 1 つの差を超えた場合に早期に停止することで、候補文字列がすべての入力に対する制約を満たすかどうかを計算します。 

内部構築ループは、一時的な変更後に文字を慎重に復元し、各ベース文字列の有効な単一位置のバリエーションのみをテストするようにします。 

有効な答えが見つかると、それ以上の検索は必要ないため、初期のブレーク構造は重要です。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        arr = [input().strip() for _ in range(n)]

        def ok(s):
            for a in arr:
                diff = 0
                for i in range(m):
                    if s[i] != a[i]:
                        diff += 1
                        if diff > 1:
                            return False
            return True

        ans = None
        for base in arr:
            if ok(base):
                ans = base
                break
            base = list(base)
            for i in range(m):
                orig = base[i]
                for c in "abcdefghijklmnopqrstuvwxyz":
                    base[i] = c
                    if ok("".join(base)):
                        ans = "".join(base)
                        break
                base[i] = orig
                if ans:
                    break
            if ans:
                break

        out.append(ans if ans else "-1")

    return "\n".join(out)

 ## 特殊なケース

 微妙な特殊なケースとしては、複数の弦が全体として 3 つ以上の位置で異なっていても、中心を共有できる場合があります。 たとえば、すべての文字列が 1 つの列でのみ異なる場合は、一貫した選択が機能します。 基本文字列を選択するとすぐに検証に合格するため、アルゴリズムがこれを処理します。 

もう 1 つのエッジ ケースは、単一のベース文字列が変更なしでは機能しないが、単一文字の変更によってすべての競合が修正される場合です。 構築ループはすべての位置とすべての文字を明示的に探索し、そのような隠れた中心が見逃されないようにします。 

最後のケースは、ペアごとの距離が小さいように見えても、答えが存在しない場合です。 例`"aaaa"`そして`"bbbb"`は、各ペアが遠く離れているにもかかわらず、両方のペアで 1 つの不一致制約を同時に満たすことができる文字列はないことを示しています。 すべての文字列に対する検証ステップでは、その状況にあるすべての候補が正しく拒否されます。
