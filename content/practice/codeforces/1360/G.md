 ## 解決策
 ## 問題の理解

 次のサイズのバイナリ グリッドを構築するように求められます。$n \times m$、行と列を密に結合する 2 つの同時制約の下で、各セルは 0 または 1 のいずれかになります。 すべての行に正確に含まれている必要があります$a$1 であり、すべての列に正確に含まれている必要があります$b$もの。 両方の制約を一度に満たすことが不可能な場合は、失敗を報告する必要があります。 

これを二部構成の入射設計問題として考えると便利です。 各行には列全体に分配する必要がある固定の「容量」があり、各列には行から受け取る必要がある固定の「需要」があります。 基本的に割り当てを行っています$n \cdot a$同一のトークン (行の寄与) を$n \times m$各列が正確に受け取るようなグリッド$b$トークン。 

最初の構造的制約は、数を数えることから生じます。 1 の合計数は 2 つの方法で決定されます。 行からは、$n \cdot a$、列からは次のようになります$m \cdot b$。 これら 2 つの値が異なる場合、同じグリッドに 2 つの異なる 1 の合計を同時に含めることはできないため、構築は存在できません。 

したがって、必要な条件は次のとおりです。$$n \cdot a = m \cdot b$$とすれば$n, m \le 50$、グリッドは非常に小さいです。 これにより、高度な最適化の必要性がなくなりましたが、存在条件が満たされていれば直接的な構築的なパターンで十分であることも示唆されています。 

単純な試みでは、調整を行わずにランダムな配置や行ごとの貪欲な配置を試行する可能性があります。 これは微妙なところで失敗します。 たとえば、各行を個別に次のように入力します。$a$カラム容量がグローバルに追跡されていないため、初期のカラムが過負荷になり、後のカラムが不足する傾向があります。 ラップアラウンドなしのバランスの取れた貪欲スキャンでも、次のような場合には失敗します。$n=3, m=6, a=2, b=1$ただし、局所的に均一な分布でも列の衝突や不足が発生する可能性があります。 

主な問題は、行の合計と列の合計の両方を正確に適用する必要があるため、部分的な決定はグローバルに一貫性を保つ必要があることです。 

## アプローチ

 ブルートフォース手法では、各セルに 0 または 1 を割り当て、グリッドを埋めた後に行と列の制約を検証しようとします。 概念的には、これはサイズのすべてのサブセットを調査します$n \cdot a$横切って$n \cdot m$これは本質的に組み合わせ的なものです。 1 の位置を選択する方法は次のとおりです。$\binom{nm}{na}$であっても天文学的に大きくなります。$50 \times 50$。 枝刈りを行ったとしても、初期の選択が後の実現可能性を大きく制限するため、行と列の間の制約結合によってバックトラッキングが爆発的に発生します。 

構造上の観察によると、任意の配置はまったく必要ありません。 すべての行には同一の要件があり、すべての列には同一の要件があるため、完全に周期的なパターンで要件を配布できます。 行列を長さの巡回シーケンスに平坦化すると、$m$、各行は単にそのサイクル内のシフトされた位置から開始されます。 これにより、各行が正確に表示されるようになります。$a$一方、巡回シフトは列の負荷を均等に分散します。 

これにより、問題は循環的なラテン スタイルのシフトの構築に変換されます。$i$位置に 1 を配置します$$(i \cdot a + j) \bmod m$$のために$j = 0 \dots a-1$と仮定すると$n \cdot a = m \cdot b$均一なカラム カバレッジを保証します。 

重要な洞察は、モジュラー演算によりバランスが自動的に適用されるということです。つまり、すべての列インデックスが正確に表示されます。$b$すべての行シフトにわたる時間。

 ## アルゴリズムのチュートリアル

 モジュラー シフトを使用して行列を決定論的に構築します。 

1. かどうかを確認します。$n \cdot a = m \cdot b$。 等しくない場合は、直ちに NO を出力します。 この条件は、行と列の両方の観点から合計値が等しいことが強制されるため、必須です。 
2. を初期化します。$n \times m$ゼロで埋められた行列。 これにより、固定パターンに従って配置するだけのクリーンなベースが得られます。 
3. 各行について$i$、正確に配置します$a$列インデックスを循環的に選択することによって生成されます。 これらの位置を次を使用して計算します。$(i \cdot a + j) \bmod m$のために$j = 0 \dots a-1$。 によるシフト$i \cdot a$異なる行が同じ列内で整列しないようにします。 
4. これらの計算された位置を行列内で 1 に設定します。 各割り当ては独立していますが、モジュール構造により全体的なバランスが確保されています。 
5. すべての行を処理した後、行列を出力します。 

これが機能する理由は、各行が正確に寄与しているためです。$a$建設によるもの。 行をステップごとに固定増分モジュロで開始位置を進めるため、巡回シフトはこれらの寄与をすべての列に均一に分散します。$m$。 1の合計数が一致するので$m \cdot b$、モジュラー シフトの下では分布は対称であり、各列は正確に累積されます。$b$もの。 

重要な不変条件は、行のプレフィックスを処理した後、列数の差が常に巡回的な意味で最大 1 に制限され、すべての行が処理された後は対称性により厳密な等価性が強制されることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, a, b = map(int, input().split())

        if n * a != m * b:
            print("NO")
            continue

        grid = [[0] * m for _ in range(n)]

        # pointer moves through columns cyclically
        for i in range(n):
            start = (i * a) % m
            for j in range(a):
                col = (start + j) % m
                grid[i][col] = 1

        print("YES")
        for row in grid:
            print("".join(map(str, row)))

if __name__ == "__main__":
    solve()
```実装は循環構築の直後に行われます。 唯一の微妙な部分は、`(i * a) % m`これにより、同じパターンを繰り返すのではなく、行が列全体に均等に分散されます。 

よくある間違いは、行インデックスによるラップやシフトを行わずに、列を線形に反復することです。 これでは有効な行の合計が生成されますが、列の均一性は失われます。 モジュラー シフトは、行を結合するメカニズムです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, m, a, b = map(int, input().split())
        if n * a != m * b:
            out.append("NO")

        out.append("YES")
        out.extend("".join(map(str, r)) for r in g)
    return "\n".join(out) + "\n"

 ## 特殊なケース

 いつ$n \cdot a \neq m \cdot b$、アルゴリズムは即座に拒否します。 例えば、$n=2, m=3, a=2, b=1$合計は 4 と 3 になるため、構築は存在しません。 コードは配置前に正しく終了します。 

いつ$n=1$、唯一有効なケースは次のとおりです。$a=m$そして$b=1$。 この構築では、単一行を完全に埋めるだけで、列の要件が自動的に満たされます。 

いつ$m=1$、対称性が適用されます。すべての行には次の条件が必要です。$a=1$すべての行が単一の列数と一致する必要があります$b=n$。 モジュラー構造は、唯一の列に正確に配置するように退化します。$n$回、制約を満たします。 

これらのそれぞれの場合において、巡回シフトは自明な一定のパターンに減少するか、実現可能性チェックにより完全にスキップされ、一貫性のない部分構造が生成されないことが保証されます。
