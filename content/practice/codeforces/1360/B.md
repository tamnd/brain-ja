 ## 解決策

 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 それぞれの場合において、アスリートの強みのリストを受け取ります。アスリートを空ではない 2 つのグループに分割し、一方のグループがその最大値に寄与し、もう一方のグループがその最小値に寄与し、これら 2 つの値の絶対差が可能な限り小さくなるようにする必要があります。 

目標を言い換えると、値のマルチセットを 2 つの部分に分割して、値空間の観点から 2 つの部分の間の境界ができるだけ狭くなるようにしようとしているということです。 1 つのグループには強みのサブセットが含まれており、その最大値のみを考慮し、もう 1 つのグループはその最小値のみを提供します。 各グループ内の残りの要素の実際のメンバーシップは、これら 2 つの極端な値を維持すること以外にはスコアに影響しません。 

制約は小さいです。 各テスト ケースには最大 50 個の要素があり、最大 1000 個のテスト ケースがあります。 これにより、テスト ケースごとの指数分割戦略が即座に除外されます。 50 の 2 乗はわずか 2500 回の演算に相当するため、テスト ケースごとに 2 次の解であっても安全です。 

主な微妙な点は、グループ化が位置や順序によって制限されず、値の選択によってのみ制限されることです。 これは、入力配列内の隣接性に基づく推論は無関係であり、値の並べ替え順序のみが重要であることを意味します。 

よくある間違いは、並べ替えずに要素を貪欲に割り当てようとすることです。 たとえば、交互に割り当てを行ったり、インデックスの中央値を中心に分割したりして、2 つのセットを構築しようとする場合があります。 最適性は元の順序ではなく数値の近さに依存するため、これは失敗します。 

最適な分割が中央値付近であると仮定すると、別の故障モードが現れます。 重複や不均一なギャップによって別のカットが最適になる可能性があるため、これは常に正しいとは限りません。 たとえば、値が`[1, 2, 100, 101]`2 から 100 の間で分割するのが明らかに最適ですが、値が`[1, 2, 3, 100]`、最適な分割は、インデックスの中央値付近ではなく、3 ～ 100 の間です。 

## アプローチ

 ブルートフォースアプローチは、配列の可能なすべての分割を 2 つの空でないセットに試みることです。 各パーティションについて、一方のセットの最大値ともう一方のセットの最小値を計算し、絶対差を評価します。 がある`2^n`可能なパーティションがあり、それぞれに最大で次のものが必要です。`O(n)`最大値と最小値を計算する作業が行われ、`O(n·2^n)`テストケースごとの複雑さ。 と`n = 50`、これは実現可能な限界をはるかに超えています。 

重要な観察は、値がソート順の 2 つのセット間の境界にのみ依存するということです。 配列を並べ替えたら、どの値を左側のグループに送り、どの値を右側のグループに入れるかを決定する分割点を選択することを考えることができます。 最適なパーティションは、グループ A のすべての要素がグループ B のすべての要素以下であるパー​​ティションに変換できます。この特性に違反した場合、要素を交換しても目的が改善または維持されるだけです。 

ソート後、候補となる答えは、ソートされた配列内のすべての隣接するペアをチェックすることになります。 ポジション間で分かれると`i`そして`i+1`の場合、可能な限り最高の貢献は次のようになります。`|s[i] - s[i+1]|`、グループ A は で終了できるため、`s[i]`グループ B は から開始できます`s[i+1]`。 より大きなギャップをもたらす他の割り当ては、その差を拡大するだけです。 

したがって、この問題は、ソートされた配列内の連続する要素間の最小の差を見つけることに集約されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 現在のテスト ケースの長所のリストを読みます。 目標は、比較で入力順序ではなく値の近さを反映するようにデータを準備することです。 
2. 配列を降順でない順に並べ替えます。 このステップは、最適な可能性のあるすべての分割を値空間内で隣り合わせに配置するため、不可欠です。 ソートがなければ、隣接する差異は意味を持ちません。 
3. 変数を初期化する`best`大きな値で。 これにより、有効な分割境界間で見つかった最小の差が保存されます。 
4. ソートされた配列をインデックス 1 から n-1 まで繰り返します。 各位置で、現在の要素と前の要素の差を計算します。 これは、これら 2 つの値の間で配列を分割するコストを表します。 
5.アップデート`best`より小さな差が見つかったときはいつでも。 これにより、2 つのグループ間の可能な限り厳密な分離を常に追跡することが保証されます。 
6. すべての隣接するペアを処理した後、出力します。`best`テストケースの答えとして。 

### なぜ効果があるのか

 ソート後、有効なパーティションは、配列を 2 つの空でない部分に分けるしきい値を選択していると見なされます。 パーティションの値は、左側の最大要素と右側の最小要素のみに依存します。 このようなペア間のギャップは、ソート順に並んだ 2 つの連続する要素の間に発生する必要があり、それよりも大きなジャンプはより近い候補ペアをスキップしてしまうためです。 したがって、最適な分割を保証するには、隣接する差分をスキャンするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = list(map(int, input().split()))
    
    s.sort()
    
    best = float('inf')
    for i in range(1, n):
        best = min(best, s[i] - s[i - 1])
    
    print(best)
```このソリューションでは、まず各テスト ケースを並べ替えます。これは、問題を値空間で 1 次元にする構造変換です。 隣接するペアにわたるループは、意味のある分割点のみを直接エンコードします。 

引き算`s[i] - s[i - 1]`配列はソートされているため安全です。そのため、差は常に負ではなく、これら 2 つの要素間で分割する正確なコストを表します。 

の初期化`best`with infinity は、最初の比較における特殊なケースの処理を回避します。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = list(map(int, input().split()))
        s.sort()
        best = float('inf')
        for i in range(1, n):
            best = min(best, s[i] - s[i - 1])
        out.append(str(best))
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

## 特殊なケース

 エッジケースの 1 つは、すべての値が同一である場合です。 入力用`[5, 5, 5, 5]`、並べ替えでは変更されず、隣接する差分はすべてゼロになります。 どの分割でもグループ全体で同じ最大値と最小値が生成されるため、アルゴリズムは正しくゼロを返します。 

もう 1 つのケースは、最適な分割が両端付近ではなく、クラスター構造の中央にある場合です。`[1, 100, 101, 102, 200]`。 並べ替えると同じ順序が得られ、隣接するギャップの最小値は次の順序になります。`100`そして`101`、これは最適なパーティション境界を正確に表します。 

最後のケースは、可能な最小の入力サイズです。`n = 2`。 このアルゴリズムは単一の比較を実行し、唯一の有効な分割である 2 つの要素間の差分を返します。
