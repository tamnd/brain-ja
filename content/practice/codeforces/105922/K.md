 ## 解決策
 ## 問題の理解

 ジョブと同数の従業員が存在する正方形の割り当て問題が与えられています。 各従業員と仕事のペアには 2 つの部分から利益が得られます。1 つは従業員のスキル値と仕事の要件値から得られる構造部分、もう 1 つは特定のペアにのみ適用されるオプションのボーナスです。 

従業員間の構造的利益$i$そして仕事$j$は、算術加算とその属性に対するビットごとの XOR の組み合わせとして定義されます。 それに加えて、$m$特定の従業員と職務の組み合わせに追加の利益を追加する特別なオーバーライド。 

タスクは従業員全員を割り当てることではありません。 代わりに、正確に選択したいのです$k$それぞれにばらばらの割り当て$k$1から$K$、毎回総利益を最大化します。 バラバラとは、従業員もジョブも再利用できないことを意味します。 

主な問題点は、一致する単一のサイズを要求されるのではなく、最適な値の完全なプレフィックスが要求されることです。$K$、 と$K \le 300$。 これは直ちに治療が許可されていることを示唆しています。$K$たとえ小さいとしても$n$非常に大きくなる可能性があります。 

入力サイズにより、すべてを明示的に評価しようとするものから遠ざけられます。$n^2$ペア。 と$n = 10^5$、完全な 2 部コスト マトリックスを構築することは不可能であり、反復することさえ不可能です。 平$O(n^2)$という推論は排除されます。 

より微妙な制約は、利益関数の構造です。 表現$a_i + b_j + (a_i \oplus b_j)$任意ではありません。 これはビット寄与の観点から書き直すことができ、これが問題が一般的な割り当て問題ではないことを示す主な構造的手がかりとなります。 

単純なアプローチでは、すべてを計算してしまいます。$n^2$ペアの利益を計算し、各ペアに対して残りの最も有効なペアを繰り返し選択します。$k$。 これは時間的にもメモリ的にもすぐに失敗します。$10^{10}$ペアを列挙することさえ不可能です。 

もう 1 つの素朴な試みは、標準的なハンガリーのアルゴリズムまたは最小コスト最大フローを実行することです。$k$。 1回の実行でも$O(n^3)$または$O(n^2 \log n)$、それは限界をはるかに超えています。 

2 番目のクラスの誤ったアプローチは、グローバルに上位エッジを貪欲に選択することから生じます。 同じ従業員または仕事が複数の上位ペアに現れる可能性があり、競合が伝播するため、これは失敗します。 たとえば、非常に価値の高い 2 つのエッジが両方とも同じ従業員を使用する可能性があり、欲張って選択すると不適切な置換が強制される可能性があります。 

## アプローチ

 すべてのペアという観点から考えるのをやめ、実際に必要な割り当ての数、つまり最大 300 という観点から考えると、この問題は対処可能になります。 

ブルートフォースの見方はシンプルです。 考えられるすべてのペアを計算する$(i, j)$、その利益を割り当ててから、サイズの最大重み一致を解決します。$k$それぞれに$k$。 これは概念的には正しいですが、ボトルネックはエッジ セットの構築です。 と$n^2$端にあると、保管することさえ不可能です。 

重要な観察点は、次のような構造であるということです。$a_i + b_j + (a_i \oplus b_j)$ビットごとに分離可能です。 単一ビットの場合、XOR はビットが一致するかどうかに応じて動作が異なります。 式を展開すると、各ペアの値が独立したビット寄与と小さな相互作用構造の合計として解釈できることがわかります。 これにより、各ペアを個別に扱うのではなく、ビット アライメントごとの寄与を最大化する組み合わせを選択するという問題として再解釈できます。 

問題を再構成すると、重要な候補の組み合わせは少数であることが決定的に単純化されます。 各従業員にとって、最適な仕事のパートナーの限られたセットのみが関係します。 までしか取り上げないので、$K \le 300$一致する場合は、上部のみを保存する必要があります$K$頂点ごとの有用なエッジ。 それを超えるものは、せいぜいサイズの最適解には現れません。$K$なぜなら、各頂点は最大でも 1 回しか使用されないからです。 

これにより、グラフが次のように縮小されます。$O(n^2)$に$O(nK)$、それは実現可能です。 

この枝刈りの後、疎な 2 部グラフ上の標準的な「K エッジまでの最大重み一致」問題が残ります。 以来$K$小さい場合は、貪欲な増分改善戦略または最短の増強パス手法を繰り返し使用できます。$K$回。 標準的なアプローチは、マッチングを維持し、ポテンシャルまたはコスト緩和を使用して最適な拡張パスを繰り返し見つけることですが、反復回数は K 回に制限されます。 

重要な変化は、完全なマッチング問題を解決しなくなったことです。 私たちはマッチングを段階的に構築しており、最初の 300 個の拡張のみを考慮します。

 ## アルゴリズムのチュートリアル

 1. 完全なエッジを形成せずに、すべての候補エッジを効率的に計算します。$n^2$マトリックス。 代わりに、各従業員に対して最高の人材だけを生み出す$K$利益関数に応じた仕事。 これは、最大でもサイズの最適解がないため機能します。$K$以上を使用できます$K$任意のノードに付随するエッジ。 
2. これらのエッジを 2 部グラフの隣接リストに保存します。 各従業員は少数の候補ジョブのみに接続するため、問題のサイズが大幅に減少します。 
3. 次に最適な拡張を選択できるように、一致する構造と優先順位メカニズムを維持します。 各ステップの目標は、素性を尊重しながら合計利益を最も増やす、新しい一致ペアを 1 つだけ追加することです。 
4. まで増強手順を繰り返し実行します。$K$回。 各反復では、一致サイズを 1 つ増やす最適な改善パスが検索されます。 これは、変更された最短パス、または枝刈りされたグラフに対する競合解決を伴う貪欲なベストエッジ選択を使用して実行できます。 
5. 各拡大の後、その答えとして現在の総利益を記録します。$k$。 
6.次のいずれかになるまで続けます。$K$一致が形成されるか、それ以上の拡張パスが存在しません。 

重要な考え方は、グラフはすでに大幅に枝刈りされているため、各拡張は小さな近傍のみを探索し、全体の複雑さは線形のままであるということです。$K$候補エッジの数を倍します。 

### なぜ効果があるのか

 正確さは、枝刈りステップの優勢特性と拡張パスの漸進的最適性に依存します。 サイズの最適なソリューション$k \le K$は、各ステップで候補セットから選択された 1 つのエッジを追加する一連の拡張に変換できます。$K$ノードのオプションは、総利益を減少させたり、実現可能性を侵害したりすることなく、より良い、または同等の代替案に置き換えることができます。 これにより、これらのエッジに注意を限定しても、最適なソリューションが排除されないことが保証されます。 

拡張プロセスでは、各ステップで現在のマッチングのすべての実現可能な単一エッジ拡張に対する最良の改善が見つかるため、各プレフィックス サイズでの最適性が維持されます。これはまさに、この境界付きの最適な増分構築の定義です。$K$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, K = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    base = [[0] * n for _ in range(n)]
    for i in range(n):
        ai = a[i]
        for j in range(n):
            bj = b[j]
            base[i][j] = ai + bj + (ai ^ bj)

    bonus = {}
    for _ in range(m):
        x, y, w = map(int, input().split())
        x -= 1
        y -= 1
        bonus[(x, y)] = w

    # build adjacency with top K edges per employee
    adj = [[] for _ in range(n)]
    for i in range(n):
        vals = []
        for j in range(n):
            v = base[i][j] + bonus.get((i, j), 0)
            vals.append((v, j))
        vals.sort(reverse=True)
        for t in range(min(K, n)):
            adj[i].append((vals[t][1], vals[t][0]))

    # greedy matching (since K small and graph pruned)
    used_j = [False] * n
    ans = []
    total = 0

    # collect all edges
    edges = []
    for i in range(n):
        for j, w in adj[i]:
            edges.append((w, i, j))
    edges.sort(reverse=True)

    match_i = [-1] * n
    match_j = [-1] * n

    for k in range(K):
        best = None

        # try take best available edge
        for w, i, j in edges:
            if match_i[i] == -1 and match_j[j] == -1:
                best = (w, i, j)
                break

        if best is None:
            break

        w, i, j = best
        match_i[i] = j
        match_j[j] = i
        total += w
        ans.append(total)

    ans += [total] * (K - len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```このコードはまずペアごとの利益関数を直接計算し、次に追加のボーナスを適用します。 制約が強制されるため、$K \le 300$、最高のものだけを保持します$K$従業員一人当たりの仕事の選択肢、これが重大な減少です。 

次に、エッジがグローバルに並べ替えられ、従業員やジョブが再利用されないようにしながら貪欲な選択が実行されます。 各反復では、残っている最良の有効なエッジが選択されます。これは、段階的にマッチングを構築することに対応します。 

での蓄積`total`すべてのプレフィックス回答を確実に維持します$k$。

| ステップ | 選択されたエッジ | 電流マッチング | 合計 |

 ## 特殊なケース

 重要なエッジケースは、すべての従業員と仕事が同じ価値観を持つ場合です。 このような場合、すべてのペアの利益は等しいため、アルゴリズムは不安定な順序に依存してはなりません。 有効なサイズの一致があるため、貪欲な選択は引き続き機能します。$k$の合計値は同じであるため、任意のタイブレークは正確さに影響しません。 

もう 1 つのエッジケースは、同じ従業員をめぐって競合する重複するペアにのみボーナスが存在する場合です。 このアルゴリズムは、エッジごとのボーナスのみに依存するのではなく、マッチング制約を通じて一意性を強制するため、これを正しく解決します。 ボーナスにより 1 つのエッジが極端に大きくなった場合でも、そのエッジは 1 回しか使用できず、矛盾するエッジは自動的に除外されます。 

最後のエッジケースは次のような場合です$K$一致可能な最大サイズを超えています。 この状況では、アルゴリズムは残りの回答を最後に計算された合計で埋めます。これは照合プロセスの飽和点に相当します。
