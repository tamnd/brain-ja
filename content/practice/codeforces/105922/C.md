 ## 問題の理解

 配列が与えられています$a$長さの$n$、および一連の$k$演算子。それぞれは合計演算または積演算のいずれかです。 私たちが評価しなければならない式は単純な線形式ではなく、深く入れ子になった構造、つまり各変数です。$x_i$からの範囲$0$に$n-1$、そして、$i$-th 演算子は和または積であり、次のすべての値を集計します。$x_i$加算または乗算によって。 

この入れ子になったシステム内では、すべての完全な割り当てが$(x_1, x_2, \dots, x_k)$用語に貢献する$a[(x_1 + x_2 + \cdots + x_k) \bmod n]$。 最終的な答えは、演算子を指定どおりに最も外側から最も内側に適用することによって得られます。 

この構造が自明ではないのは、同じ配列が、選択されたすべてのインデックスのモジュラー和によって繰り返しインデックス付けされる一方で、ネストが合計層と乗算層の間で交互に行われることです。 これは、線形結合と畳み込みのような集計を複数回効果的に構成していることを意味します。 

制約は非常に小さいです。$n, k \le 10$。 これは、大規模な複雑さの点で漸近的な最適化の必要性を即座に排除しますが、本当の困難はすべてを強引に列挙することではなく、構造の単純化であることも示唆しています。$n^k$州はまだ小さいですが、概念的には乱雑です。 直接拡張することは可能ですが、洞察が得られません。 意図したソリューションでは、各レイヤーの効果が圧縮されます。 

素朴なアプローチでは、すべてが拡張されてしまいます$n^k$しかし、これはすぐに概念的に扱いにくくなり、式を圧縮可能にする代数構造を隠してしまいます。 

すべての演算子が乗算である場合、微妙なエッジ ケースが発生します。 その場合、各層は同一の内部結果を乗算するため、同じ集計の累乗が繰り返される可能性があります。 同様に、合計レイヤーと積レイヤーを交互に使用すると、中間合計が繰り返し再利用される可能性があり、メモ化が慎重に構造化されていない場合、単純な再帰シミュレーションでは誤って再計算される可能性があります。 

もう 1 つの重要な例外ケースは次のような場合です。$n = 1$。 次に、すべてのインデックスモジュロ$n$はゼロであり、式全体は単一の値の繰り返し集計に崩壊しますが、乗算レイヤーは依然として項の数を組み合わせ的に増幅します。

重要な観察は、この式が同じ基盤空間に対する 2 つの線形演算の繰り返し適用として構造化されていることです。加算は加算に分配され、乗算は同一構造の繰り返しの畳み込みのような累積に対応します。 すべての層はインデックスのモジュロの合計にのみ依存するため、$n$を使用すると、タプルを列挙する代わりに、部分和の分布がどのように変化するかを追跡できます。

 ## アルゴリズムのチュートリアル

 可能なモジュラー和全体の分布を維持しながら、演算子を左から右に処理することによってソリューションを構築します。 

まず、変数が選択される前の空の代入を表す、合計 0 のみが値 1 を持つ分布配列を初期化します。 これは、変数がない場合、合計がゼロになる方法が 1 つだけあるという事実をエンコードしています。 

次に、シーケンス内の各演算子を反復処理します。 各ステップで、演算子が和であるか積であるかに基づいて分布を更新します。 

第三に、合計演算子に遭遇すると、概念的には新しい変数を追加します。$x_i$からのすべての値の範囲$0$に$n-1$。 現在の部分和ごとに$s$、その重みをすべての合計に分配します。$s + x_i \bmod n$。 各選択が均等に寄与するため、これは均一ベクトルによる畳み込みです。 

第 4 に、積演算子に遭遇すると、ネストを独立した分岐として解釈します。現在の状態ごとに、新しい変数のすべての選択により、同じ内部式の乗算コピーが生成されます。 これは、寄与分を追加する代わりに、現在の寄与構造を選択肢の数に対応する累乗にすることを意味します。これは、実際には、独立した拡張全体にわたる寄与分を乗算することになります。 操作上、これは、すべての分岐の合計によって引き起こされる分布に対する点ごとのべき乗のような変換になります。 

5 番目に、すべての演算子を処理した後、配列値で重み付けされたすべての最終状態を合計することで答えが得られます。$a[s]$、それぞれの最終モジュラー和がまさにその係数に寄与するためです。 

### なぜ効果があるのか

 プロセス全体は、式がインデックスの順序ではなく、累積されたインデックスのモジュール和のみに依存するという事実に依存しています。 すべての変換は、インデックス間に新たな依存関係を導入することなく、各合計に到達する方法の数 (合計演算子) を拡張するか、独立した部分構造 (積演算子) を複製します。 これにより、各ステップの後、状態ベクトルが、和の法によってのみグループ化されたすべての部分割り当ての寄与を完全にエンコードするという不変条件が維持されます。$n$。 どちらの演算子も、この同じグループに対する再配布またはレプリケーションを通じてのみ機能するため、情報が失われることはなく、最終的な集約は$a[s]$正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    ops = input().strip()

    dp = [0] * n
    dp[0] = 1

    for op in ops:
        if op == 's':
            ndp = [0] * n
            for s in range(n):
                if dp[s] == 0:
                    continue
                for x in range(n):
                    ndp[(s + x) % n] = (ndp[(s + x) % n] + dp[s]) % MOD
            dp = ndp
        else:
            total = sum(dp) % MOD
            ndp = [0] * n
            for s in range(n):
                ndp[s] = pow(dp[s], n, MOD)
            dp = ndp

    ans = 0
    for s in range(n):
        ans = (ans + dp[s] * a[s]) % MOD

    print(ans)

    solve()

 ## 特殊なケース

 いつ$n = 1$、操作に関係なく、すべてのインデックスはゼロになります。 dp 状態が広がることはなく、すべての合計演算または積演算は、単一値の繰り返しスケーリングに崩壊します。 すべての遷移は状態 0 をそれ自体にマップし直すため、アルゴリズムはこれを保持します。
