 ## 解決策
 ## 問題の理解

 2 つの整数が与えられます$x$そして$y$厳密にそれらの間に少なくとも 1 つの整数が存在するようにします。 タスクは整数を選択することです$z$それは厳密に区間内にあります$(x, y)$、同時に、どちらのエンドポイントとも 1 より大きい公約数を共有しないという意味で、両方のエンドポイントと「互換性」があります。$x$または$y$。 複数の選択肢が存在する場合はどれも受け入れられますが、そのような整数が存在しない場合は失敗が報告されます。 

入力は多くの独立したクエリで構成されます。 各クエリは、最大で 2 つの大きな整数のペアにすぎません。$10^{10}$したがって、固定範囲にわたる事前計算や、次の値に対するふるいのような方法に依存することはできません。$x$そして$y$。 ギャップの状態$x + 2 \le y$は、それらの間に少なくとも 1 つの整数の候補があることを保証しますが、それらの候補のいずれかが gcd 制約を満たすことは保証しません。 

中心的な問題は、「両方の端点に対して互いに素であること」がグローバルな算術条件であり、区間のローカルな構造によってチェックできるものではないことです。 すべての候補者に対する単純なスキャンは原則として可能ですが、ギャップが大きく、最大数の候補者が存在する場合は実行不可能になります。$10^4$テストケース。 

素朴な推論の典型的な失敗例は、間隔が小さいにもかかわらず、割り切れるパターンによって制限されている場合です。 たとえば、次の場合$x = 10$そして$y = 12$、唯一の候補は$z = 11$、これは機能します。 しかし、もし$x$そして$y$どちらも偶数です、例えば$x = 14, y = 16$、唯一の候補は$15$、これは再び機能します。 間隔が広い場合でも、間隔内のすべての数値が少なくとも 1 つの端点と小さな素因数を共有する場合、微妙さが現れます。 

本当の課題は、各候補者を個別にチェックすることを避けることです。 

## アプローチ

 ブルートフォース戦略は簡単です。すべての整数を反復処理します。$z$そのような$x < z < y$、どうかを確認してください。$\gcd(z, x) = 1$そして$\gcd(z, y) = 1$。 各 gcd 計算には数値の大きさで対数的な時間がかかるため、このアプローチでは次のようになります。$O((y-x)\log V)$テストケースごとに。 以来$x$そして$y$最大で異なる場合があります$10^{10}$、これは最悪の場合には完全に不可能です。 

重要な点は、実際には区間全体を検索する必要はないということです。 必要なのは、両方のエンドポイントのすべての素因数を回避する単一の整数だけです。 すべての数値を独立して扱う代わりに、次の主要な構造に焦点を当てることができます。$x$そして$y$。 

決定的に単純化するのは、両方が互いに素である数を選択すると、$x$そして$y$の場合、両方の素約数をすべて避ける必要があります。 特に、数値が素数除算で割り切れる場合は、$x$または$y$、すぐに無効になります。 したがって、禁止されている素数は、$x$または$y$、有限の素数セットを回避する短い間隔で数値を検索します。 

ここで、意図したソリューションで使用される重要な構造的洞察が必要になります。すべての値を検索する代わりに、間隔の中央付近にある小さな固定された候補セットを試します。 すべての整数は次の素数によってのみ制約されるため、$x$そして$y$、実際には、このスケールの数値に関連する素数はほとんどないため、一定数の候補をチェックするだけで、有効な素数が存在する場合に確実にそれを見つけることができます。 

自然な選択は、次の値に近い数値をテストすることです。$x + 1$、これは区間内で最も単純な候補であるためです。 失敗した場合は、次のような近くの整数を試すこともできます。$x + 2$、しかし問題の制約はすでに保証しています$y \ge x + 2$, したがって、常に少なくとも 2 つの候補が存在します。 両方とも失敗した場合は、有効な整数が存在しないと結論付けられます。 

これにより、問題はテスト ケースごとの gcd チェックの数が一定に減ります。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、2 つの整数の候補を計算します。$x+1$そして$x+2$。 これらは、制約によって保証される間隔内に存在できる唯一の値です。$x+2 \le y$。 
2. 各候補者について$z$、計算する$\gcd(z, x)$そして$\gcd(z, y)$。 両方のエンドポイントを明示的にチェックする理由は、その積または組み合わせた因子だけでなく、両方について共主性が独立して成立する必要があるためです。 
3. 両方の gcd 値が 1 に等しい候補が見つかった場合は、すぐにそれを出力し、次のテスト ケースに進みます。 有効な候補が見つかったら、さらに候補をチェックする必要はありません。 
4. どちらの候補も機能しない場合は、出力します。$-1$。 これは、区間内のすべての整数が次のいずれかの素因数を共有する場合に対応します。$x$または$y$、あらゆる可能性を排除します。 

### なぜ効果があるのか

 有効な解はいずれも区間内に存在する必要があります$(x, y)$、この間隔のサイズは少なくとも 2 であるため、正確に 2 つの整数が含まれます。$x+1$そして$x+2$少なくとも。 問題は、これら 2 つの整数のいずれかが両方のエンドポイントのすべての素因数を回避しているかどうかをチェックすることに帰着します。 どちらも機能しない場合は、最小の場合には区間内に他の整数が存在せず、より大きなギャップでは同じ障害パターンが端点との共有素因数を介して伝播するため、代替の選択肢はありません。 したがって、検索をこれらの候補に制限すると、不必要な探索を排除しながら正確性が保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(z, x, y):
    import math
    return math.gcd(z, x) == 1 and math.gcd(z, y) == 1

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        x, y = map(int, input().split())

        ans = -1
        for z in (x + 1, x + 2):
            if x < z < y and ok(z, x, y):
                ans = z
                break

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードはアルゴリズムに直接に従います。 機能`ok`両方のエンドポイントに対する共素性条件をカプセル化し、ロジックを読み取り可能な状態に保ちます。 正確に 2 つの候補に対するループは、区間に少なくともこれら 2 つの整数が常に含まれるという制約を反映しています。 小切手`x < z < y`構造を考えると技術的には冗長ですが、推論における端的な間違いに対する安全策として機能します。 

早めの休憩により、テスト ケースごとの継続的な作業が確保されます。これは、非常に重要です。$10^4$クエリ。 

## 実用的な例

 ### 例 1

 入力:```

```候補者をテストします$z = 4, 5$。 

| z | gcd(z, x) | gcd(z, y) | 有効 |
 | --- | --- | --- | --- |
 | 4 | 1 | 2 | いいえ |
 | 5 | 1 | 1 | はい |

 出力は 5 です。トレースは、1 つのエンドポイント インタラクションのみが 4 をブロックしているのに対し、5 は両方を回避していることを示しています。 

### 例 2

 入力:```

```候補者は、$15, 16$。 

| z | gcd(z, x) | gcd(z, y) | 有効 |

 | 15 | 1 | 3 | いいえ |
 | 16 | 2 | 2 | いいえ |

 両方の候補が失敗したため、出力は次のようになります。$-1$。 これは、区間内の両方の数値がエンドポイントから小さな素因数を継承し、すべてのオプションを排除するケースを示しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import gcd

    t = int(sys.stdin.readline())
    res = []
    for _ in range(t):
        x, y = map(int, sys.stdin.readline().split())
        ans = -1
        for z in (x+1, x+2):
            if x < z < y and gcd(z, x) == 1 and gcd(z, y) == 1:
                ans = z
                break
        res.append(str(ans))
    return "\n".join(res)

 ## 特殊なケース

 両方の候補が存在するが、一方または両方がいずれかのエンドポイントと素因数を共有する場合、微妙なエッジ ケースが発生します。 たとえば、$x = 14, y = 18$、間隔には正確に次のものが含まれます$15$そして$16$。 アルゴリズムは両方を評価します。 のために$15$, 18 の gcd は 3 なので拒否されます。 のために$16$、両方のエンドポイントの gcd は 1 より大きいため、これも拒否されます。 アルゴリズムは正しく返します$-1$。 

もう 1 つのケースは、素因数の非対称性により 1 つの候補のみが有効な場合です。 のために$x = 3, y = 6$、候補者$4$因子 2 を共有するため失敗します$6$、 その間$5$は両方のエンドポイントに対して互いに素です。 アルゴリズムは次のことを見つけます$5$これは、有効な解決策であればどれでも受け入れられるため、早期に停止しても正確さに影響を与えないことを示しています。
