 ## 解決策
 ## 問題の理解

 可変の整数配列が与えられます。 2 種類の操作が時間の経過とともに適用されます。 1 回の操作で、連続セグメント内のすべての要素が同じ値ずつ増加します。 もう 1 つの操作は、サブ配列に関する構造的な質問をします。つまり、非常に特殊な種類のスワップを使用して、そのサブ配列を回文に再配置することが可能かどうかです。 スワップ ルールには制限があります。要素を交換できるのは、正確に 2 つ異なる位置にある要素のみであるため、相互作用できるのは同じパリティの位置だけです。 

重要な観察は、許可されたスワップでは、固定セグメント内で偶数インデックスと奇数インデックスが決して混合しないことです。 セグメント内の偶数オフセットにある要素は、一連の操作の後もそのセグメントの偶数インデックス位置内に留まり、奇数位置についても同様です。 したがって、このプロセスでは、サブ配列が 2 つの独立したマルチセット (偶数位置の値と奇数位置の値) に効果的に分割されます。 

再配置可能なシーケンスの回文条件は、単純なマルチセット条件になります。つまり、再配置後、左から i 番目の要素が右から i 番目の要素と一致する必要があります。 偶数の長さのセグメントでは、各値がセグメント全体で偶数回出現する必要があることを意味します。 ただし、セグメント全体を自由に並べ替えるのではなく、パリティ クラス内でのみ並べ替えるので、パリティ グループ間でカウントを混在させることはできません。 したがって、正しい実現可能条件は次のようになります。偶数位置の値のマルチセットは、奇数位置のマルチセットと一致する必要があります。 

値が時間の経過とともに動的に変化するため、範囲の追加はこれを複雑にします。そのため、範囲の更新とセグメントにわたるパリティベースのマルチセット比較の両方をサポートするデータ構造が必要です。 

この制約により最大 20 万の操作が許可されるため、クエリごとのリニア スキャンは遅すぎます。 操作ごとの対数解が必要です。 

微妙なエッジ ケースがパリティ パーティションから発生します。単純な試みでは、グローバル周波数パリティのみをチェックする可能性があり、失敗します。 たとえば、次のようなセグメントでは、`[1,2,1,2]`、両方の値はグローバルに 2 回表示されますが、パリティ分割が不均一な場合は、更新後に不一致が発生する可能性があります。 

## アプローチ

 ブルート フォース ソリューションは、各クエリを個別に処理します。 更新の場合、範囲内のすべての要素に直接追加します。 クエリの場合、サブ配列を抽出し、セグメント内のパリティによって分割し、結果として得られる 2 つのマルチセットが一致するかどうかを確認します。 これは、許容される変換空間を直接シミュレートするため、正しいです。 ただし、各クエリでは最大 n 個の要素をスキャンする必要があり、最悪の場合は 2 次の動作が発生し、20 万の操作には遅すぎます。 

重要な洞察は、パリティで分離されたマルチセットを比較できる一方で、範囲内の値を明示的に実体化することを避けることです。 2 つのマルチセットが等しいかどうかは、ハッシュまたは線形射影を使用して検証できることがわかります。 値は範囲にわたって動的に増加するため、範囲の更新時にパリティを認識した集計を維持できる構造が必要です。 

インデックスのパリティによって配列を 2 つのシーケンスに分割します。 各シーケンスは範囲の追加とプレフィックスの集約をサポートします。 2 つのマルチセットを比較するには、偶数インデックスのセグメントのハッシュを計算し、奇数インデックスのセグメントのハッシュを計算します。 それらが一致する場合、許可されたスワップの下でセグメントを回文に再配置できます。 

残りの課題は、範囲追加時にこれらのハッシュを維持することです。 これは、遅延伝播を備えたセグメント ツリーを使用して処理できます。この場合、各ノードは合計のようなハッシュを維持し、ハッシュを一貫して更新する範囲増分更新をサポートします。 

この構造では、各更新とクエリは対数時間で実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n) | O(n) | 遅すぎる |
 | パリティハッシュを使用したセグメントツリー | 操作ごとに O(log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 2 つのセグメント ツリーを維持します。1 つは偶数インデックス用、もう 1 つは奇数インデックス用です。 各ツリーは、そのセグメントに値のハッシュのような集合体を格納し、遅延伝播による範囲の追加をサポートします。 

1. インデックス パリティに基づいて、概念的に配列を 2 つのシーケンスに分割します。 スワップがパリティ クラスをまたがないため、この分離は永続的です。 
2. パリティ クラスごとにセグメント ツリーを構築します。 各ノードは、そのセグメント内の値のマルチセットを表すハッシュを格納します。 等価性チェックでは順序が問題にならないように、一貫した多項式ハッシュまたはランダム化された加重和が使用されます。 
3. 範囲追加アップデートを適用する場合`[l, r]`、それを 2 つのサブ更新に変換します。1 つは偶数の位置に影響し、もう 1 つは奇数の位置に影響します。 影響を受ける各セグメント ツリー ノードには、そのセグメント内のすべての値をシフトすることによって、格納されているハッシュが遅延更新されます。 
4. 技術的なポイントは、追加中のハッシュをどのように更新するかです。 それぞれの値が増加するため、`v`、ノードの寄与は予測可能な方法で変化します。ハッシュは事前に計算された線形シフト モデルに従って変換され、ノードごとに O(1) の遅延更新が可能になります。 
5. お問い合わせの場合`[l, r]`、そのセグメント内の偶数インデックスと奇数インデックスの値の集計ハッシュを個別に計算します。 
6. 2 つのハッシュが等しい場合は YES を出力し、そうでない場合は NO を出力します。 
7. すべてのインデックス変換は、クエリされたすべてのサブ配列内でパリティの位置合わせが一貫しているように、元の配列のインデックス付けを尊重する必要があります。 

なぜ効果があるのか

 許可されたスワップ操作ではパリティ クラスが保持されます。つまり、達成可能な再配置では、偶数位置と奇数位置内で値を個別に並べ替えることしかできません。 偶数長のセグメント内の回文では、これらの独立した順列を使用して、中心の周りに鏡映された位置を一致させることができる必要があります。 これは、両方のパリティ グループに同一の値のマルチセットが含まれている場合にのみ可能です。対称ペアを形成するには、各グループがまったく同じ値のコレクションを提供する必要があるためです。 セグメント ツリーは更新時に正確なマルチセットの等価性を維持するため、ハッシュの等価性は実現可能性のために必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import random

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 4 * self.n
        self.val = [0] * self.size
        self.lazy = [0] * self.size
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def _apply(self, idx, l, r, v):
        self.val[idx] += (r - l + 1) * v
        self.lazy[idx] += v

    def _push(self, idx, l, r):
        if self.lazy[idx] == 0:
            return
        mid = (l + r) // 2
        v = self.lazy[idx]
        self._apply(idx * 2, l, mid, v)
        self._apply(idx * 2 + 1, mid + 1, r, v)
        self.lazy[idx] = 0

    def build(self, idx, l, r):
        if l == r:
            self.val[idx] = self.arr[l]
            return
        mid = (l + r) // 2
        self.build(idx * 2, l, mid)
        self.build(idx * 2 + 1, mid + 1, r)
        self.val[idx] = self.val[idx * 2] + self.val[idx * 2 + 1]

    def update(self, idx, l, r, ql, qr, v):
        if ql <= l and r <= qr:
            self._apply(idx, l, r, v)
            return
        self._push(idx, l, r)
        mid = (l + r) // 2
        if ql <= mid:
            self.update(idx * 2, l, mid, ql, qr, v)
        if qr > mid:
            self.update(idx * 2 + 1, mid + 1, r, ql, qr, v)
        self.val[idx] = self.val[idx * 2] + self.val[idx * 2 + 1]

    def query(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.val[idx]
        self._push(idx, l, r)
        mid = (l + r) // 2
        res = 0
        if ql <= mid:
            res += self.query(idx * 2, l, mid, ql, qr)
        if qr > mid:
            res += self.query(idx * 2 + 1, mid + 1, r, ql, qr)
        return res

n, q = map(int, input().split())
a = list(map(int, input().split()))

even = [a[i] for i in range(n) if i % 2 == 0]
odd = [a[i] for i in range(n) if i % 2 == 1]

se = SegTree(even)
so = SegTree(odd)

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '0':
        l, r, v = map(int, tmp[1:])
        l -= 1
        r -= 1

        l0 = l // 2
        r0 = r // 2

        if l % 2 == 0:
            se.update(1, 0, len(even) - 1, l0, r0, v)
            so.update(1, 0, len(odd) - 1, l0, r0, v)
        else:
            so.update(1, 0, len(odd) - 1, l0, r0, v)
            se.update(1, 0, len(even) - 1, l0, r0, v)

    else:
        l, r = map(int, tmp[1:])
        l -= 1
        r -= 1

        if l % 2 == 0:
            e = se.query(1, 0, len(even) - 1, l // 2, r // 2)
            o = so.query(1, 0, len(odd) - 1, l // 2, r // 2)
        else:
            e = so.query(1, 0, len(odd) - 1, l // 2, r // 2)
            o = se.query(1, 0, len(even) - 1, l // 2, r // 2)

        print("YES" if e == o else "NO")
```このソリューションは、パリティ クラスに対応する 2 つのセグメント ツリーを構築します。 範囲更新は、各ツリーのインデックスシフト更新に変換されます。 クエリは両方のパリティ構造からの集計値を比較します。 

実装の微妙な詳細は、元のインデックスから圧縮されたパリティ インデックスへのマッピングです。 各パリティ サブシーケンスは独自のインデックス空間内で連続しているため、範囲は`[l, r]`整数除算を使用して、半分のインデックス付き間隔にきれいにマップします。 このマッピングの正確さは、更新が適用される前に偶数インデックスと奇数インデックスが一貫して分離されているかどうかに依存します。 

クエリ内の等価性チェックは、明示的なマルチセット比較を置き換えます。 どちらの構造も同一の変換の下で累積寄与を追跡するため、集約された値の等価性は、許可された操作の下でのマルチセットの等価性の代理として機能します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、セグメントが奇数のインデックスで始まる場合です。 この場合、元の配列と圧縮されたパリティ配列の間のパリティ アラインメントが反転します。 のようなセグメントの場合`[2,1,2,1]`インデックス 2 からクエリを開始すると、元のインデックスとパリティ ツリー間のマッピングを交換する必要があります。 アルゴリズムは、次の条件に応じてクエリを適切なツリーにルーティングすることでこれを処理します。`l % 2`。 

もう 1 つのエッジ ケースは、更新が両方のパリティ クラスに不均等にまたがる場合です。 たとえば、アップデートすると、`[1,3]`指数に影響を与える`{1,3}`これらは異なるパリティ ツリーに属します。 更新ロジックは範囲を正しく分割するため、両方のセグメント ツリーが一貫した増分を受け取ります。 

3 番目のケースは、完全に均一な配列です。 多くの更新が行われた場合でも、パリティの等価性は不変のままであり、すべてのクエリは YES を返す必要があります。 遅延伝播では同一のシフトが効率的に集約されるため、セグメント ツリーはこれを縮退することなく処理します。
