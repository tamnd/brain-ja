 ## 解決策
 ## 問題の理解

 小文字の単一の文字列が与えられます。 タスクは、最初の位置に文字が含まれる、順序付けられた位置のペアをすべて調べることです。`e`、2 番目の位置には文字が含まれます`f`、そして`e`文字列内で`f`。 このようなペアごとに、インデックスの差として定義される位置間の距離を測定し、すべての有効なペアにわたってこの距離を合計します。 

言い換えれば、私たちが何かを見るたびに、`e`位置にある`i`、私たちはすべてを見ます`f`位置にある`j > i`そして貢献する`j - i`答えに。 目標は、この合計を効率的に計算することです。 

入力サイズの制約は次のとおりです。`n ≤ 5000`。 This is small enough that quadratic solutions are acceptable, but large enough that cubic or anything with unnecessary overhead will be too slow in practice. A solution that checks all pairs explicitly is borderline but still feasible in O(n²), while anything that recomputes inner sums repeatedly would risk timeouts.

 文字列に何も含まれていない場合、微妙なエッジケースが発生します。`e`またはいいえ`f`。 この場合、有効なペアは存在せず、答えはゼロになります。 もう 1 つの特殊なケースは、すべてが`e`やっぱりキャラクターが出てくる`f`文字。有効な順序付けがないため、ゼロも生成されます。`i < j`存在します。 たとえば、`feef`、有効なものはありません`(e, f)`以来ペア`f`どれよりも前にある`e`。 

3 番目の微妙な点は、貢献度がカウントだけではなくポジションの違いに依存することです。 の数を乗算する単純な計数ソリューション`e`そして`f`距離を無視するため、これは不正確です。 

## アプローチ

 直接的なアプローチは、すべての位置を反復処理することです。`i`含む`e`、そのような位置ごとに、すべての位置をスキャンします`j > i`そして蓄積する`(j - i)`いつでも`s[j] = 'f'`。 これは定義に正確に従っているため、簡単で正しいです。 ただし、文字列がすべてなくなってしまう最悪の場合、`e`続いて全員`f`、または交互の文字を使用すると、約`n² / 2`文字チェック、これはまだ許容されます`n = 5000`、しかし非効率の余地はほとんどありません。 

主な改善点は、距離表現を分離することです。`j - i`2 つの独立した部分に分割します。`j`そして`i`。 ポジションを固定したら`i`と`s[i] = 'e'`、後で全員の貢献`f`ポジションは`sum(j) - count(f) * i`、合計とカウントがすべて引き継がれます。`f`の右側の位置`i`。 これは、右から左への前処理戦略を示唆しており、次の数を維持します。`f`残りの文字とそのインデックスの合計。 

文字列を右から左に処理すると、2 つの現在の値を維持できます。`f`これまでに見た文字とそのインデックスの合計。 遭遇したとき`e`位置にある`i`、将来のすべてに対するその合計貢献度がすぐにわかります`f`保存された集計値を使用して位置を決定します。 これにより、各位置の処理が O(1) に削減されます。 

ブルート フォースは、すべての有効なペアを明示的に列挙するため機能しますが、同じサフィックス情報を繰り返し再計算するため、拡張できません。 すべての未来は`f`寄与分は、入れ子構造を線形スキャンに変える 2 つの集計によって要約できます。

 ## アルゴリズムのチュートリアル

 文字列を右から左に処理して、いつでもすべてを把握できるようにします。`f`現在の位置の右側にある文字。 

1. 2 つの変数を初期化します。`cnt_f = 0`そして`sum_f = 0`、 どこ`cnt_f`何個保存するか`f`これまで見てきた右側のキャラクター、そして`sum_f`それらのインデックスの合計を格納します。 これらは、有効なすべての内容の圧縮された要約を表します。`f`将来のポジション`e`貢献。 
2. 最終的な答えを初期化する`ans = 0`。 これにより、合計距離が累積されます。 
3. インデックスを反復処理する`i`から`n - 1`まで`0`。 各ポジションでは、キャラクターに基づいて更新または貢献する方法を決定します。 
4. もし`s[i] == 'f'`、インクリメントしてサフィックスの状態を更新します。`cnt_f`そして追加`i`に`sum_f`。 これにより将来が保証されます`e`ポジションがこれを説明できる`f`。 
5. もし`s[i] == 'e'`、現在知られているすべてを使用してその寄与を計算します`f`ポジション。 そういったそれぞれに対して`f`位置にある`j`、追加したいのは`(j - i)`。 これを拡張すると、`sum_f - cnt_f * i`なので、この値を直接追加します。`ans`。 
6. 文字列の先頭まで続けます。 決勝戦`ans`有効なすべての貢献度の合計が含まれます`(e, f)`ペア。 

### なぜ効果があるのか

 各インデックスで`i`、変数`cnt_f`そして`sum_f`正確にすべてを表します`f`厳密に右側に位置します`i`。 各位置を過ぎて左方向に移動するときにのみこれらの変数を更新するため、この不変条件は維持されます。 処理するとき`e`位置にある`i`、すべての有効なペア`(i, j)`と`j > i`式によって 1 回だけ説明されます`sum_f - cnt_f * i`。 すべての未来のため、見逃されるペアはありません`f`位置はサフィックス状態に含まれており、各ペアが二重にカウントされることはありません。`e`サフィックス情報の固定スナップショットを使用して独立して貢献します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    cnt_f = 0
    sum_f = 0
    ans = 0

    for i in range(n - 1, -1, -1):
        if s[i] == 'f':
            cnt_f += 1
            sum_f += i
        elif s[i] == 'e':
            ans += sum_f - cnt_f * i

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、すべてのサフィックスの概要を維持します。`f`ポジション。 毎回、`e`に遭遇すると、将来のすべてに対するその合計寄与度を計算します。`f`アルゴリズムのセクションで導出された ID を使用して、一定時間で文字を変換します。 主要な実装の詳細は右から左に反復されるため、サフィックスは常に有効な値に対応します。`j > i`ポジション。 

算術式`sum_f - cnt_f * i`の合計を直接展開します`(j - i)`保存されているすべての`j`。 これにより、内部ループが完全に回避されます。

## 特殊なケース
