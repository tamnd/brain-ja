 ## 解決策
 ## 問題の理解

 2 つの整数が与えられ、それらについての厳密な構造特性が伝えられます。つまり、一方は奇数であることが保証され、もう一方は偶数であることが保証されます。 それぞれの数字は、非常に単純な比較ゲームにおける「プレイヤーの選択」を表します。 一方のプレイヤーは奇数を好み、もう一方のプレイヤーは偶数を好みますが、最終的に重要なのは 2 つの値の数値比較だけです。 

タスクは 2 つの数値のうちどちらが大きいかを出力することですが、出力は数値そのものではありません。 代わりに、出力します`1`大きいほうの数字がたまたま奇数だった場合、そして`2`大きいほうの数がたまたま偶数だった場合。 

アルゴリズムの観点から見ると、制約は非常に小さく、値は最大 10^9 であり、標準の整数型に簡単に適合します。 さらに重要なのは、値が 2 つだけであり、配列、グラフ、複数のクエリなどの隠れた構造がないことです。 これにより、前処理、データ構造、漸近的に効率的なアルゴリズムの必要性が即座に排除されます。 2 つの数値を直接比較するソリューションはすべて、一定時間で実行されます。 

サイズに関しては、難しい隠れたエッジのケースはありませんが、概念的な落とし穴があります。それは、出力が位置ではなくパリティに関連付けられているということです。 単純な読者は、「a > b の場合は 1 を出力する」と誤って仮定する可能性がありますが、それは、答えのマッピングに不可欠な、大きい数が奇数であるか偶数であるかを無視することになります。 

小さな例で構造を明確に示します。 入力が`3 2`、奇数の方が大きいため、出力は次のようになります。`1`。 入力が`1 2`、偶数の方が大きいため、出力は次のようになります。`2`。 この混乱は、どの番号が印刷されるかではなく、パリティがどのラベルを印刷するかを決定することを忘れた場合にのみ発生します。 

## アプローチ

 反復するものが何もないため、総当りの解釈でも最適な解釈と同じように見えます。 両方の可能性を「テスト」することを想像する人もいるかもしれませんが、数値が 2 つしかないため、シミュレーションや列挙は単一の比較とそれに続く分類ステップに退化します。 たとえ両方の数のチェック条件として人為的に組み立てたとしても、作業は O(1) のままです。 

重要な観察は、この問題では何も構築する必要がなく、2 つの候補のうちどちらが大きく、既知のパリティを持つかを決定するだけであるということです。 正確に 1 つの数値が奇数で、もう 1 つが偶数であるため、モジュラス演算を使用してパリティを安全に識別し、値を直接比較できます。 

「両方試して決める」という強引な考えは、どちらの数字が大きいか、そしてその数字が奇数か偶数かという 2 つの事実によって答えが決まるという洞察に崩壊します。 両方のファクトが一定時間で計算できることが認識されると、問題は直接の条件チェックになります。

 ## アルゴリズムのチュートリアル

 1. 2 つの整数を読み取ります`a`そして`b`。 これらは、結果を決定するために必要な唯一の入力です。 
2. 2 つの数値のうちどちらが大きいかを確認します。 これにより、比較の意味でどの候補が「勝者」であるかが決まります。 
3. 大きい方の数値が 2 で割り切れるかどうかを確認して、その数値のパリティを決定します。 
4. 大きい方の数が奇数の場合、出力`1`, 奇数番号のプレイヤーが比較に勝つためです。 それ以外の場合は出力`2`、大きい数は偶数でなければならないためです。 

ここで重要な推論ステップは、パリティは順序を決定するために使用されるのではなく、勝者を必要な出力ラベルにマッピングするためにのみ使用されるということです。 この問題では奇数と偶数が 1 つずつ正確に保証されているため、このマッピングにはあいまいさはありません。 

### なぜ効果があるのか

 常に、一方の数字は奇数で、もう一方の数字は偶数であるため、奇数の正体は明確に定義されます。 このアルゴリズムはパリティとは独立して大きさを比較し、正しい勝者が選択されることを保証します。 より大きな値が特定されると、パリティ チェックによって、その勝者が奇数プレーヤーに対応するか偶数プレーヤーに対応するかが一意に判断されます。 どちらのステップも決定的であり、考えられるすべての有効な入力をカバーするため、出力は必要なルールに一致する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, b = map(int, input().split())

mx = a if a > b else b

if mx % 2 == 1:
    print(1)
else:
    print(2)
```問題の構造にはループや補助データ構造が必要ないため、実装は意図的に最小限に抑えられています。 最初のステップでは、2 つの整数を直接読み取ります。 2 番目のステップでは、単純な条件式を使用して大きい値を選択します。候補は 2 つだけであるため、これで十分です。 

パリティチェック`mx % 2 == 1`最大値が奇数かどうかを識別します。 この問題では奇数と偶数が 1 つだけ保証されているため、どのプレイヤーの番号が出力されているかが自動的に識別されます。 最後の print ステートメントは、この条件を必要な出力形式にマップします。 

よくある間違いは、`a % 2`または`b % 2`どちらが大きいかを最初に特定することなく、独立して。 大きい数が偶数であるがそうでない場合、不正確な答えにつながります。`a`、またはその逆。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    a, b = map(int, input().split())
    mx = a if a > b else b
    return str(1 if mx % 2 == 1 else 2)

# provided samples
assert run("1 2") == "2"
assert run("3 2") == "1"

# custom cases
assert run("2 1") == "2", "even larger"
assert run("5 4") == "1", "odd larger"
assert run("8 7") == "2", "even larger"
assert run("9 2") == "1", "odd larger"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2 1 | 2 | 偶数が大きい方が勝ち |
 | 5 4 | 1 | 奇数が大きいほど勝ち |
 | 8 7 | 2 | 逆の順序で勝つこともできます。 
| 9 2 | 1 | 大きな差がある奇数の勝利 |

 ## 特殊なケース

 唯一の構造エッジ条件は、間違った変数のパリティを誤って返してしまう可能性があるため、大きい数が偶数である場合です。 

入力用`2 1`、アルゴリズムは次のように計算します。`mx = 2`、次にチェックします`2 % 2 == 0`、つまり出力されます`2`。 素朴な間違いは、チェックすることです`a % 2`まずそれを見てください`2`は偶数であり、出力が次のようになると誤って想定されています。`2`それを確認せずに`a`実際にはすべての場合で最大値になります。 正しいロジックでは常に最大値にパリティ チェックを固定するため、この誤分類が防止されます。
