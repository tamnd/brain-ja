 ## 解決策
 ## 問題の理解

 行数が少ない非常に広いグリッドが与えられています。 各行は完全なバイナリ文字列として明示的に保存されるわけではありません。 代わりに、それはいくつかの切り離されたセグメントまたは重複するセグメントによって記述され、各セグメントは値が 1 である列の連続した間隔をマークします。その行内の他のすべての位置は暗黙的に 0 です。 

両方の行に 1 が含まれる列が少なくとも 1 つ存在する場合、2 つの行は互換性があるとみなされます。この意味で、最後に残ったシーケンス内の連続する行のすべてのペアが互換性がある場合、グリッドは美しいと呼ばれます。 

タスクは行を再配置することではなく、行の一部を削除することだけです。 削除後、残りの行を元の順序で確認します。それらの隣接するすべてのペアは、両方とも 1 を持つ少なくとも 1 つの列を共有する必要があります。削除される行数を最小限に抑え、削除されたインデックスの最適なセットも出力したいと考えています。 

制約は大きく、最大 300,000 行と 300,000 セグメント、列インデックスは最大 10^9 です。 これにより、完全な行表現を構築したり、行のすべてのペアを素朴にチェックしたりする試みが即座に排除されます。 すべての行のペアを比較するソリューションは二次関数的であり、非常に遅すぎます。 

重要な構造上の困難は、オーバーラップが行間の間隔の交差によって定義されることです。 単純なアプローチでは、行間のすべての交差を計算して、最長の有効なシーケンスを構築しようとする可能性がありますが、直接実行すると、O(n^2) の互換性グラフが作成されます。 

素朴な考えによる微妙な失敗例は、行 i が行 i+1 と交差し、行 i+1 が行 i+2 と交差する場合、行 i が行 i+2 と交差することは無関係であると仮定することです。 これは論理的には正しいですが、グローバル構造を考慮せずにローカルで隣接関係を維持しようとする、誤った貪欲な戦略を誘惑します。 もう 1 つのよくある間違いは、間隔を統一された構造に集約せずに各行を独立して処理することです。これにより、誤った交差チェックが行われます。 

## アプローチ

 制約を無視する場合、最も直接的なアイデアは、各行がノードであるグラフを構築し、間隔セットが交差する場合は i と j を接続することです。 次に、誘導された順序 (元の行順序) で、連続するすべてのペアがエッジを持つように、できるだけ多くのノードを保持したいと考えます。 これは、連続して選択されたインデックスに互換性があるように、インデックスの最大サブセットを選択することと同じです。 

ブルートフォースの方法は、各行を結合されていない間隔のセットに前処理してから、行のペアごとに間隔が重複しているかどうかを確認することです。 これは、最悪の場合の O(n^2) 間隔の交差チェックであり、各チェックはセグメント数が対数または線形であり、300,000 では完全に実行不可能です。 

重要な観察は、すべてのペアの交差が必要なわけではないということです。 私たちが気にするのは、有効なシーケンスを上から下に拡張できるかどうかだけです。 これは動的プログラミングを示唆しています。行ごとに、その行で終わる最適な有効なチェーンを知りたいと考えます。 

ただし、以前の行をすべてチェックすると、依然として移行にコストがかかります。 画期的な点は、各行を間隔の和集合として解釈し、行を順番にスイープしながらアクティブな「カバレッジ制約」を維持することです。 各行について、その行と重複する以前に保持された行が存在するかどうかだけを知る必要があります。 以前のすべての行をチェックする代わりに、チェーンの実行可能なすべての最後の行の間隔の和集合を表すデータ構造を維持します。 

これにより、問題は動的な一連の間隔を維持し、現在の行との交差を確認することになります。 行が保持される場合、その間隔は将来の到達可能性に寄与します。 私たちが維持する構造は、有効なチェーンの現在「到達可能な端」である列にわたる、結合されていない間隔のマージされたセットとして表すことができます。

したがって、各行は 1 回処理され、区間和集合クエリと交差クエリは順序付けられた構造で処理され、O((n + m) log m) の解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアチェック | O(n² · k) | O(m) | 遅すぎる |
 | スイープ + インターバル マージ | O((n + m) log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 行を昇順に処理し、保持された行で終了する有効なチェーンが 1 を持つすべての列位置を表す一連の素な間隔を維持します。 

各行について、最初にそのセグメントを結合しない間隔のソートされたリストにマージします。 これが必要なのは、行内の重複は個別には問題ではなく、交差ロジックでは結合のみが問題となるためです。 

次に、この行が現在の状態に接続できるかどうかを確認します。 つまり、その間隔のいずれかがグローバルなアクティブ間隔セットと交差するかどうかをテストします。 交差がない場合、この行を保持すると、以前に保持されていた行との連続性が失われるため、この行を削除する必要があります。 

少なくとも 1 つの交差がある場合は、行を保持し、そのすべての区間をアクティブ セットに追加し、重複部分をマージすることでグローバル構造を更新します。 

1. すべてのセグメントを行インデックスで並べ替え、行ごとにグループ化します。 
2. 各行について、その間隔を結合しないセグメントにマージします。 
3. 互いに素なアクティブ間隔のバランスの取れた構造 (順序付きマップまたは並べ替えられたリスト) を維持します。 
4. 順番に各行について、その間隔のいずれかがアクティブ セットと交差するかどうかを確認します。 
5. 交差が存在しない場合は、削除する行にマークを付けて続行します。 
6. それ以外の場合は、すべての間隔をアクティブ セットに追加し、重複部分をマージします。 

それが機能する理由は、単調な到達可能性の不変条件から来ています。 行 i を処理した後、アクティブな間隔セットは、i までの保持された行で終了する有効なチェーンの一部となり得るすべての列位置の和集合を正確に表します。 行にこのセットとの交差がない場合、有効なチェーンを拡張できないため、強制的にスキップされます。 交差する場合は、それを維持すると少なくとも 1 つの有効な継続が保持され、その間隔をマージすると、将来の接続の可能性がすべて更新されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def merge_intervals(intervals):
    if not intervals:
        return []
    intervals.sort()
    merged = [intervals[0]]
    for l, r in intervals[1:]:
        pl, pr = merged[-1]
        if l <= pr + 1:
            merged[-1] = (pl, max(pr, r))
        else:
            merged.append((l, r))
    return merged

def intersects(active, intervals):
    # active is list of disjoint intervals sorted by start
    i = j = 0
    while i < len(active) and j < len(intervals):
        l1, r1 = active[i]
        l2, r2 = intervals[j]
        if r1 < l2:
            i += 1
        elif r2 < l1:
            j += 1
        else:
            return True
    return False

def add_and_merge(active, intervals):
    for l, r in intervals:
        active.append((l, r))
    active.sort()
    merged = []
    for l, r in active:
        if not merged or merged[-1][1] < l - 1:
            merged.append((l, r))
        else:
            merged[-1] = (merged[-1][0], max(merged[-1][1], r))
    return merged

def solve():
    n, m = map(int, input().split())
    rows = defaultdict(list)

    for _ in range(m):
        i, l, r = map(int, input().split())
        rows[i].append((l, r))

    active = []
    removed = []

    for i in range(1, n + 1):
        intervals = merge_intervals(rows[i])

        if not active:
            if intervals:
                active = intervals[:]
            continue

        if not intersects(active, intervals):
            removed.append(i)
        else:
            active = add_and_merge(active, intervals)

    print(len(removed))
    if removed:
        print(*removed)

if __name__ == "__main__":
    solve()
```この実装では、まず行ごとにセグメントをグループ化し、次に各行を互いに素な間隔に圧縮します。 アクティブな構造は空で始まり、最初の行が 1 になった後でのみ空ではなくなります。 

交差チェックは、2 つのソートされた間隔リストにわたる線形スイープであり、列ごとのシミュレーションを回避します。 行が受け入れられると、その間隔はアクティブなセットにマージされ、素性が維持されます。 

微妙な詳細は、空の行の処理です。 間隔のない行は何も貢献できず、接続を拡張できないため、初期化の一部でない限り、常に削除されます。 

## 実用的な例

 すべての行がすでに有効なチェーンを形成しているサンプルを考えてみましょう。 

アクティブな間隔と決定を追跡します。 

| 行 | 間隔 | | 前にアクティブ 交差しますか？ | アクション | | 以降にアクティブになります
 | --- | --- | --- | --- | --- | --- |
 | 1 | [1,1]、[7,8] | [] | 該当なし | キープ | [1,1]、[7,8] |
 | 2 | [7,7]、[15,15] | [1,1]、[7,8] | はい | キープ | [1,1]、[7,8]、[15,15] |

 これは、アクティブ セットが徐々に拡張し、重複する列を介してチェーンできることを示しています。

| 行 | 間隔 | | 前にアクティブ 交差しますか？ | アクション | | 以降にアクティブになります

 | 1 | [1,1] | [] | 該当なし | キープ | [1,1] |
 | 2 | [] | [1,1] | いいえ | 削除 | [1,1] |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log m) | 各セグメントはマージされ、ソート/マージによってアクティブな間隔が維持されます。 
| スペース | O(m) | すべてのセグメントとマージされた間隔リストを保存する |

 各セグメントは一定の回数処理され、ソートは集約形式で行ごとに線形にのみ影響を与えるため、境界 n, m ≤ 3 · 10^5 によりこの複雑さが許容可能になります。

 ## 特殊なケース

 セグメントのない行は、何も交差できないため、最も極端なケースです。 アルゴリズムはそれを空の間隔リストを持つものとして扱い、それがアクティブな構造を初期化する最初の行でない限り、交差チェックは直ちに失敗します。 

2 番目のエッジ ケースは、行に多数の重複セグメントがあり、それらが 1 つの長い間隔にマージされる場合です。 マージ ステップでは、断片化された入力が人為的に複雑さを増大させたり、オーバーラップの欠落を引き起こしたりしないように、交差する前にそれらを折りたたむことで正確性を保証します。 

3 番目のケースは、接続がアクティブ セット内の複数の互いに素な間隔を飛び越える場合です。 スイープ ベースの交差は、すべての間隔ペアを並べ替えられた順序でチェックし、列の列挙に依存せずに重複が検出されるようにするため、これを正しく処理します。
