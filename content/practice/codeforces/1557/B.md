 ## 解決策
 ## 問題の理解

 個別の整数の配列が与えられ、非常に特殊な変換を 1 回だけ実行できます。 まず、配列をちょうど k 個の連続する部分に切り分けます。各部分は空ではありません。 次に、これらの部分を任意に並べ替えることができ、最後にそれらを新しい順序で貼り合わせます。 

目的は、k 個のセグメントを並べ替えた後、最終的にマージされた配列が非降順で完全にソートされるように、k 個のセグメントを選択する何らかの方法が存在するかどうかを判断することです。 

重要な問題は、個々の要素を再配置することはできず、連続したブロック全体のみを再配置することしかできないことです。 したがって、元の配列の構造により、ソートされたシーケンスに並べ替える機能を損なうことなく、どの要素をグループ化できるかが制限されます。 

制約は十分に大きいため、テスト ケースごとにどのような解も線形である必要があります。 合計 n が 3e5 までの場合、テスト ケースごとに O(n log n) のアプローチは問題ありませんが、セグメント探索で二次関数を使用することは不可能です。 分割方法は O(n 選択 k) 通りあるため、考えられるすべての k パーティションに対する総当り攻撃は組み合わせ的に爆発します。 

k が 1 に等しい場合、微妙なエッジケースが発生します。その場合、何も並べ替えることはできないため、配列はすでにソートされている必要があります。 もう 1 つのエッジ ケースは、k が n に等しい場合です。この場合、すべての要素は独自のセグメントであり、シングルトンを並べ替えることによって常に並べ替えることができるため、答えは常に YES になります。 

自明ではないケースは 1 < k < n の場合で、セグメンテーションが配列の内部順序と意味のある方法で相互作用します。 

## アプローチ

 ブルートフォース手法では、配列を k 個の連続セグメントに分割するあらゆる方法を試し、それらのセグメントのすべての順列を試し、並べ替えられた配列が生成される順序かどうかを確認します。 仕切り直してもkあるよ！ 順列、およびパーティションの数は組み合わせになります。 これは、n = 30 の場合でも大きすぎます。 

重要な洞察は、任意のセグメントについて考えるのをやめ、代わりに配列がソート順と「すでに一致している」場所を考えることです。 配列のコピーをソートして位置を比較してみましょう。 すべての要素は個別であるため、各値はソートされた配列内で一意の正しい位置を持ちます。 

ここで、有効なソリューションに実際に必要なものを観察してください。セグメントを並べ替えるとき、要素を効果的に k 個のブロックにグループ化しており、各ブロックはグローバルな並べ替え順序を崩すことなく移動可能でなければなりません。 これは、配列を k 個の連続するセグメントに分割し、各セグメントが内部的に考慮されたときに、ソートされた配列に必要な相対順序に違反しない場合にのみ可能になります。 

決定的な観察は、ソートされた順序で連続する要素間の隣接関係が元の配列で「壊れる」たびに、強制的にカットを配置する必要があるということです。 並べ替えられた順序で連続する 2 つの要素が元の配列内で隣接していない場合、グローバルな並べ替え可能性を維持したい場合、これらの要素は同じセグメントに属することはできません。 

そこで、ソートされた位置にマッピングされたときに、元の配列に「ソートされた隣接ブレーク」がいくつ存在するかを計算します。 その数を必要なカットとします。 k−1 個を超えるカットが必要な場合、ソートされた構造を尊重する k 個のセグメントを実現することはできません。 より少ないか等しい必要がある場合は、正確に k に達するまでセグメントをさらに分割することができます。 

これにより、問題はソートによって引き起こされる順列における遷移の単純なカウントに帰着します。

 ## アルゴリズムのチュートリアル

 配列をソート順に変換し、各値の位置を記録します。

1. ソートされた配列内の値からそのインデックスへのマッピングを構築します。 これにより、要素の意図された順序がわかります。 
2. 元の配列をこれらの位置に置き換えて、問題を 0 から n−1 への順列の分析に変えます。 
3. 変換された配列を左から右にスキャンし、ソート順で次の要素が現在の要素の正確な後続要素ではない回数を数えます。 このような不連続性は、ソート順に自由に再配置できるセグメントが必要な場合、新しいセグメント境界が必要であることを意味します。 
4. この数値を c とします。 これらは、並べ替えられた隣接関係を維持するために必要な最小限のセグメントです。 
5. c + 1 ≤ k の場合、余分なカットが有効性を損なうことはないため、既存のセグメントを任意に分割することで、正確に k 個のセグメントに達するまでさらに分割できます。 
6. そうしないと、c + 1 > k の場合、ソートされたシーケンスに並べ替えるのに十分な柔軟性を生み出すことができません。 

この決定は、k が少なくとも並べ替えられた隣接関係によって引き起こされる単調ランの数であるかどうかをチェックすることに帰着します。 

### なぜ効果があるのか

 スキャンでは、要素が連続してソートされた順序で表示される最大の連続ブロックが特定されます。 このようなブロック内では、すべての要素が既にチェーンを形成しており、有効な並べ替えではこのチェーンが一緒に留まらなければなりません。これを破ると、ソートされた隣接関係の逆転が強制され、ブロックの並べ替えだけでは修復できません。 この連鎖が切れるたびに、強制的な切断が導入されます。 有効なセグメンテーションはこれらのカットを尊重する必要があり、追加のカットはオプションの改良です。 したがって、達成可能なセグメントの最小数はまさにこれらの実行の数であり、実現可能性は、k がこの最小値以上であることと同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        b = sorted(a)
        pos = {v: i for i, v in enumerate(b)}
        
        cnt = 1
        for i in range(1, n):
            if pos[a[i]] != pos[a[i-1]] + 1:
                cnt += 1
        
        if cnt <= k:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```この解決策は、配列をソートして各要素のターゲット順序を決定することから始まります。 辞書`pos`は、各値のランクをこのソート順に格納し、問題を 0 から n−1 までの整数のシーケンスに変換します。 

変数`cnt`ソートされた隣接する単調セグメントが元の順序で何個存在するかをカウントします。 連続する要素がソート順で連続していない場合は常に、新しいセグメントを開始する必要があります。 

最後に、この最小必要なセグメント数を k と比較します。 k が十分に大きい場合は、いつでもさらに分割して正確に k 個のセグメントに到達できます。 

よくある間違いは、正確に k 個の「良い」セグメントを直接形成する必要があると考えることです。 正しい見方は、最大でも k 個のセグメントが構造的に必要であることを確認するだけでよいということです。 追加の分割はいつでも可能です。 

## 実用的な例

 ### 例 1

 入力:```
5 4
6 3 4 2 1
```ソートされた配列は`[1, 2, 3, 4, 6]`、位置は元の値をランクにマップします。 

| 私 | a[i] | pos[a[i]] | 連続した？ | CNT |
 | --- | --- | --- | --- | --- |
 | 0 | 6 | 4 | - | 1 |
 | 1 | 3 | 2 | いいえ | 2 |
 | 2 | 4 | 3 | はい | 2 |
 | 3 | 2 | 1 | いいえ | 3 |
 | 4 | 1 | 0 | いいえ | 4 |

 cnt = 4 が得られます。k = 4 であるため、条件が成立し、答えは YES になります。 

これは、ソートされた隣接関係が切れるたびに新しいセグメントが強制され、k が正確に一致するだけで十分であることを示しています。 

### 例 2

 入力:```
4 2
1 -4 0 -2
```ソートされた配列は`[-4, -2, 0, 1]`。 

| 私 | a[i] | pos[a[i]] | 連続した？ | CNT |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 3 | - | 1 |
 | 1 | -4 | 0 | いいえ | 2 |
 | 2 | 0 | 2 | いいえ | 3 |
 | 3 | -2 | 1 | いいえ | 4 |

 ここでは cnt = 4 ですが k = 2 であるため、構造を 2 つの並べ替え可能なセグメントのみに圧縮することは不可能です。 

これは、並べ替えが許可されていても、壊れた隣接関係が多すぎると、強制的に独立したブロックが多すぎることを示しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        for i in range(1, n):

                cnt += 1
        
        output.append("YES" if cnt <= k else "NO")
    
    return "\n".join(output)

 ## 特殊なケース

 k = 1 で完全にソートされた配列の場合、隣接関係の切れがなく cnt が 1 のままであるため、アルゴリズムは正しく YES を出力し、並べ替えが必要ないという事実と一致します。 

k = n の場合、たとえ配列が非常に無秩序であっても、cnt は常に最大でも n であるため、cnt ≤ k という条件が常に成り立ちます。 これは、すべての要素を分離し、シングルトン セグメントを自由に並べ替えることができることを反映しています。 

ソートされた順序が長く連続した実行で現れる配列の場合、cnt は小さくなり、アルゴリズムは少数のセグメントで十分であることを正確に識別します。 余分な k は、分割によって新しい順序制約が導入されることはないため、正確さに影響を与えることなくこれらの実行をさらに分割できることを意味します。
