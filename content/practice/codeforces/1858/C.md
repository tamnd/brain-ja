 ## 問題の理解

 1 から 1 までの整数の順列を構築するように求められます。$n$これにより、連続する要素間の最大公約数 (GCD) を (ラップアラウンドを使用して) 計算するときに、個別の GCD 値の数が最大化されます。 各テスト ケースは単一の整数で構成されます$n$、そして長さの順列を出力する必要があります$n$そのテストケースに対して。 

入力制約$2 \le n \le 10^5$まで組み合わせて$10^4$テストケースとその合計$n$すべてのテスト ケースにわたって、$10^5$、各数値を線形時間で処理する必要があることを意味します。$n$。 二次アルゴリズムの終焉$n$10^5^2 = 10^{10} 演算は 2 秒の制限では実行不可能であるため、遅すぎます。 

エッジケースには非常に小さなケースが含まれます$n$2 のように、順列が 2 つしかなく、GCD が自明に 1 であり、高度に複合されています。$n$複数の選択肢を複数選択すると、GCD が繰り返される可能性があります。 単純に数字を1から順に出力すると$n$、連続する数はほとんど互いに素であるか、小さな因数を共有するため、個別の GCD は通常小さくなります。そのため、GCD 配列の多様性を最大化するために同じ数の倍数を分散する戦略が必要です。 

## アプローチ

 ブルートフォースアプローチでは、すべてのものが生成されます。$n!$長さの順列$n$そして、最大数の個別の GCD を生成する順列を追跡しながら、それぞれの GCD 配列を計算します。 これは正しいですが、完全に非現実的です。$n!$指数関数的よりも速く成長します - たとえ$n = 10$、$10! = 3.6 \cdot 10^6$、そしてのために$n = 1000$それは天文学的な大きさです。 したがって、これは合理的なものには機能しません$n$。 

重要な洞察は、数値 1 が他のすべての数値と互いに素であるという観察から得られ、その倍数である数値の後により大きな数値が現れるように数値をシーケンス内に配置すると、新しい GCD が生成される傾向があります。 具体的には、最大の数から始めて、割り切れる値の降順に数値を出力するとします。$n$and repeatedly placing multiples of numbers that are not yet in the permutation - we maximize the number of distinct GCDs. 実際には、これはふるいのような貪欲な構造を使用して実装できます。最大の数値から 1 まで反復し、まだ使用されていない数値ごとにそれを出力し、その倍数すべてを使用済みとしてマークします。 This ensures we cover each number exactly once and exploit divisibility to produce a diverse set of GCDs.

 The story is that brute-force works conceptually because it enumerates every possibility, but fails for large$n$組み合わせ爆発によるもの。 可分性に関する観察により、線形時間で貪欲に順列を構築することが可能になり、順列を列挙することなく最大の個別の GCD を確保できます。

 ## アルゴリズムのチュートリアル

 1. 順列と配列を格納する空のリストを初期化します。`used`サイズの$n+1$どの数字が順列に配置されているかをマークします。 
2. 以下の数値を反復処理します。$n$この順序により、約数の少ない最大の数値から開始することが保証されるため、まずそれらを含めることで、その影響が倍数全体に効率的に分散されます。 
3. 数字ごとに`i`、使用されているかどうかを確認します。 存在する場合はスキップしてください。 それ以外の場合は、それを順列に追加します。 
4.配置したら`i`、すべての倍数を反復処理します。`i`より大きい`i`まで$n$。 倍数が使用されていない場合は、それを順列に追加し、使用済みとしてマークします。 このステップにより、次の倍数が確実に得られます。`i`後に現れる`i`、連続する要素に個別の GCD がある可能性が高くなります。 
5. 順列が長さに達するまで続けます$n$。 結果のリストを出力します。 

維持される不変条件は、1 から 2 までのすべての数値です。$n$は順列内で 1 回だけ出現し、配置するすべての数値について、それを割るより大きな数をすでにカバーしているため、GCD のシーケンスは可能な限り多様になります。 貪欲な配置により、数値が繰り返されず、より大きな数値がその倍数の前に表示されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        used = [False] * (n + 1)
        perm = []
        for i in range(n, 0, -1):
            if not used[i]:
                perm.append(i)
                used[i] = True
                for j in range(i*2, n+1, i):
                    if not used[j]:
                        perm.append(j)
                        used[j] = True
        print(' '.join(map(str, perm)))

solve()
```このソリューションは、テスト ケースの数を読み取り、それぞれを反復処理します。 テスト ケースごとに、`used`配列と空`perm`リスト。 外側のループは最大の番号から始まり、下に向かって進みます。 内側のループは現在の数値の倍数を加算します。`perm`、すでに使用されているものはスキップします。 最後に、順列がスペースで区切られて出力されます。 

微妙な点には初期化が含まれます`used`サイズ付き`n+1`1 から始まるインデックスを照合し、慎重に複数のループを開始します。`i*2`番号を繰り返さないようにするため`i`自体。 反復順序により、最大の数値が最初に配置されることが保証されます。
