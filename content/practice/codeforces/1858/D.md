 ## 問題の理解

 木の列を表すバイナリ文字列が与えられます。各位置はオークまたはモミのいずれかになります。 最終的な配置の品質は、2 つの数値のみに依存します。それは、0 の最長連続ブロックと、最長連続 1 のブロックです。 これらの値を$l_0$そして$l_1$、スコアは次のように計算されます。$a \cdot l_0 + l_1$、 どこ$a$1から$n$。 

評価の前に、最大でも反転することができます$k$の各固定値のスコアを最大化することを目的として、0 を 1 に、または 1 を 0 に変換して位置を調整します。$a$。 問題は、この最適化には、すべての場合に個別に答えなければならないことです。$a$。 

難しいのは、セグメントを変更すると両方に影響するという事実から来ています。$l_0$そして$l_1$結合した方法で。 通常、一方を増やすには他方を犠牲にする必要があり、フリップはランを延長するかセグメントをマージするために費やすことができます。 

制約は十分小さいので、$n \le 3000$テストケースごとの合計と$n$も 3000 で制限されており、おおよそより悪いものは除外されます。$O(n^2)$テストケースごとに。 これは、二次または二次に近い動的計画法、または開始位置ごとの貪欲な構築を強く示唆しています。 

単純な考えは、範囲内で到達可能なすべての最終文字列を試してみることです。$k$反転して計算します$l_0, l_1$。 状態の数は指数関数的であるため、これは不可能です。$n$。 

より微妙な失敗例は、貪欲なアプローチが 0 または 1 のいずれかを独立して最大化しようとした場合に発生します。 たとえば、次のような文字列では`01010`、長いゼロブロックを構築するためにフリップを費やすと、潜在的なブロックが破壊され、その逆も同様です。 正しいソリューションを実現するには、この 2 つの間のトレードオフを同時に検討する必要があります。 

## アプローチ

 ブルートフォースの観点では、各最終構成はフリップをポジションに割り当てる方法によって決定されると考えることです。 最大でもすべてのサブセットを試してみると、$k$反転すると、生成されます$\sum_{i=0}^k \binom{n}{i}$可能性はすでに指数関数的です。 これを位置とフリップ数にわたって DP に圧縮したとしても、結果として得られる文字列の最大ラン長を評価する必要があり、これにより余分な時間が追加されます。$O(n)$、につながる$O(n^3 k)$あるいはさらに悪いことに。 

重要な構造的観察は、スコアが最良のゼロ セグメントと最良の 1 セグメントのみに依存し、それらの位置や多重度には依存しないということです。 これは、文字列全体を追跡する必要はなく、反転後の 0 と 1 の「可能な限り最良の間隔」の存在のみを追跡する必要があることを意味します。 

ここで、連続するゼロを最大化したい候補セグメントを修正します。 間隔を選択する場合$[l, r]$すべてゼロになるように強制すると、コストはその中の 1 の数になります。 残りのフリップを使用して、この構造を拡張したり、競合するセグメントを別の場所に同時に構築したりすることもできます。 1 については対称的な議論が成り立ちます。 

重要な削減は、最適なソリューションでは、$l_0$そして$l_1$フリップ後の元の文字列内の連続したセグメントから得られ、そのような各セグメントは、部分文字列を均一にするために必要なフリップの回数をカウントするウィンドウをスライドさせることによって個別に評価できます。 

したがって、すべての間隔について、すべて 0 またはすべて 1 にするために必要な最小の反転を事前計算します。 これから、可能な長さごとに、達成可能な最良の値を導き出します。$l_0$そして$l_1$。 最後に、それらを組み合わせます。$a$、最高のゼロランと最高のワンランを構築する間でフリップを分割することを選択します。 

より効率的な再定式化により、フリップの明示的な分割が回避されます。 あらゆる長さに対して$L$を使用して、セグメントをすべて 0 またはすべて 1 にする最善の改善を計算します。$k$反転し、プレフィックス最大値を維持します。 これにより、達成可能なすべてのペアが得られます$(l_0, l_1)$、その後、トレードオフを考慮して凸包を計算し、評価します。$a \cdot l_0 + l_1$みんなのために$a$。 

どちらの次元もセグメントの長さが単調で反転しているため、構造は凸状になり、セグメント サイズに対する 2 ポインター スタイルの最適化が可能になります。

 ## アルゴリズムのチュートリアル

 2 つのヘルパー配列を構築します。1 つは部分文字列をすべて 0 に変えるのにかかるコストを測定するもので、もう 1 つはすべて 1 を表すものです。 プレフィックスの合計を使用して、次の各間隔をクエリできます。$O(1)$ですべての間隔を評価できるようになります。$O(n^2)$。 

1. ゼロと 1 のプレフィックスの合計を事前計算して、任意の間隔を均一化するために必要なフリップの回数をすぐに数えられるようにします。 
2. インターバルごとに$[l, r]$、すべてを 0 にするコストを内部の 1 の数として計算し、同様にすべて 1 にするコストを内部の 0 の数として計算します。 
3. 間隔ごとにコストがかかる場合$\le k$、少なくともセグメントの長さを保証できます$r-l+1$その値は完全に均一です。 
4. 配列 best0[len] と best1[len] を維持します。ここで best0[len] は、k 回のフリップ内で達成可能なゼロランの最大長であり、1 の場合も同様です。 
5. これらの配列を圧縮して単調になります: 長さを達成できれば$x$、さらに短い長さも実現できます。 
6. それぞれの可能性について$a$、の最適値を計算します。$a \cdot l_0 + l_1$可能なすべてを反復することによって$l_0$、そして最も互換性のあるものと組み合わせます$l_1$フリップ予算の競合を超えないこと。 
7. 両方の配列が単調であるため、前方にのみ移動するポインターを使用して、テストごとに線形時間で最良のペアリングを評価できます。 

重要なアイデアは、$l_0$より多くのフリップを費やす必要があるため、利用可能な構造が減少します$l_1$。 単調な構造により、先に進むと以前の状態を再考する必要がなくなることが保証されます。 

### なぜ効果があるのか

 実行可能なすべての解決策は、フリップ後の最良のゼロランと最良のワンランを表す 2 つの素な間隔または部分的に重複する間隔を選択することに対応します。 そのような構築には、それらの間隔で修正された不一致の数に正確に相当するコストがかかります。 すべての間隔が明示的に評価され、達成可能な最適な長さのコストは単調であるため、結果として得られるトレードオフ曲線は次のとおりです。$l_0$そして$l_1$凸です。 2 つのポインタの評価により、すべての勾配に対してこの曲線上の最適な点が正しく検出されます。$a$、目的があるので、$a \cdot l_0 + l_1$トレードオフ空間では線形です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        pref0 = [0] * (n + 1)
        pref1 = [0] * (n + 1)

        for i, ch in enumerate(s, 1):
            pref0[i] = pref0[i - 1] + (ch == '0')
            pref1[i] = pref1[i - 1] + (ch == '1')

        best0 = [0] * (n + 1)
        best1 = [0] * (n + 1)

        for l in range(n):
            for r in range(l, n):
                ones = pref1[r + 1] - pref1[l]
                zeros = pref0[r + 1] - pref0[l]
                length = r - l + 1

                if ones <= k:
                    best0[length] = max(best0[length], length)
                if zeros <= k:
                    best1[length] = max(best1[length], length)

        for i in range(n - 1, 0, -1):
            best0[i] = max(best0[i], best0[i + 1])
            best1[i] = max(best1[i], best1[i + 1])

        res = []
        j = 0
        for a in range(1, n + 1):
            while j + 1 <= n and best0[j + 1] * a + best1[j + 1] >= best0[j] * a + best1[j]:
                j += 1
            res.append(str(best0[j] * a + best1[j]))

        print(" ".join(res))

if __name__ == "__main__":
    solve()
```プレフィックス配列を使用すると、一定時間間隔のカウントが可能になり、セグメントの二次列挙が可能になります。 ネストされたループは、反転バジェット内で部分文字列を均一にし、0 と 1 をきれいに分離する実現可能性を計算します。 

単調な伝播ステップにより、より長い均一セグメントが達成可能であれば、より短い長さもすべて達成可能として扱われることが保証されます。これは、後で正しく貪欲な評価を行うために必要です。 最後のポインター スイープは、次の事実を利用します。$a$が増加すると、最適な選択が$l_0$単調に変化します。

 ## 特殊なケース

 次のような完全に均一な文字列`00000`または`11111`次のいずれかの場合にアルゴリズムが正しく処理されることを保証します。$l_0$または$l_1$は常にゼロです。 間隔の列挙によりすべてのセグメントが実行可能であることがマークされ、単調な伝播により最適な長さが単純に保証されます。$n$。
