 ## 解決策
 ## 問題の理解

 ペティアは番号が付けられたベンチの前を通り過ぎます`1`に`n`。 いくつかのベンチにはクッキー売りがいます。 Petya はベンチに着くと、次の 3 つの条件のうち 1 つが当てはまるとクッキーを食べます。 

1. ベンチには売り手がいます。その場合、彼はすぐにクッキーを買って食べます。 
2. 彼はこれまで一度も食事をしたことがありません。 
3. 少なくとも`d`前回のクッキーから数分が経過しました。 

3 番目のルールは、連続する 2 つの Cookie の間に最大でも次の Cookie が存在できることを意味します。`d - 1`食べずにベンチ。 

ウォークを開始する前に、販売者を 1 人だけ削除する必要があります。 次の 2 つの値を決定する必要があります。 

まず、販売者を 1 人削除した後に Petya が食べるクッキーの最小数です。 

第二に、削除されたときにその最小値を達成するさまざまな販売者の数。 

重要な観察は、`n`と同じ大きさにすることができます`10^9`, そのため、すべてのベンチをシミュレートすることは不可能です。 幸いなことに、売り手の数ははるかに少ないです。 すべてのテスト ケース全体で、販売者の合計数は最大で`10^5`これは、解がほぼ線形になることを強く示唆しています。`m`。 

よくある間違いは、販売者を削除しても Cookie が 1 つだけ削除されると考えることです。 販売者を削除すると、中断されない間隔が長くなり、いくつかの自動 Cookie が減少する場合があります。 

例えば：```
n = 6
d = 2
s = [2, 5]
```ペティアは移動せずにベンチで食事をします。```
1, 2, 4, 5
```合計4枚のクッキー。 

販売者の削除`2`与える:```
1, 3, 5
```たったの3枚のクッキーです。 

削除された売り手がベンチにいるときに、別の微妙なケースが発生します`1`。```
n = 10
d = 3
s = [1, 8]
```ベンチ`1`すでに最初の Cookie が発生しています。 この販売者を削除しても、必ずしもカウントが 1 つ減るわけではありません。 「最初のクッキー」ルールは依然としてベンチでトリガーされます`1`したがって、効果は慎重に計算する必要があります。 

3 番目のバグの原因は、最後の販売者の後のテール セグメントです。```
n = 20
d = 5
s = [6, 12]
```最後に食べたクッキーの位置からベンチまでの間隔`20`Cookie も提供します。 この最後のセグメントを無視すると、不正確な答えが生成されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての売り手について、それを削除し、Petya の歩行全体をシミュレートし、Cookie を数えて、最良の答えを保持します。 

ルールが決定的であるため、シミュレーション自体は簡単です。 問題はスケールです。 以来`n`多分`10^9`、すべてのベンチを歩き回るのは不可能です。 販売者のみに依存するようにシミュレーションを何らかの方法で圧縮したとしても、すべてを試してみると、`m`個別に削除するには、依然として大まかな必要があります`O(m²)`仕事。 と`m = 10^5`、それくらいでしょう`10^10`操作。 

重要な観察は、Cookie の総数が独立した間隔の寄与の合計として表現できるということです。 

Cookie が特定の位置に強制的に配置されると仮定します。```
1, s1, s2, ..., sm
```どこのベンチ`1`特別な必須の開始点のように機能します。 

2 つの連続した強制的な Cookie の位置を考慮します。`a < b`。 で食事をした後、`a`、自動ルールは次の間隔で Cookie を作成します。`d`到着するまでベンチ`b`。 

このギャップによって寄与される Cookie の数は次のとおりです。```
(b - a - 1) // d
```位置にクッキーを加えます`b`。 

これは、すべてのギャップが独立して寄与することを意味します。 

売り手が削除されても、ほとんどすべてのギャップは変更されません。 その売り手に隣接するギャップのみが影響を受けます。 2 つの隣接するギャップが 1 つの大きなギャップに結合されます。 

これにより、問題はローカル更新の問題に変わります。 元の Cookie 数を一度計算し、次に販売者ごとに、2 つの隣接する間隔を結合したときに合計がどれだけ変化するかを計算します。 

これにより、複雑さが 2 次から線形に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m²)以上 | O(m) | 遅すぎる |
 | 最適 | テスト ケースあたり O(m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 しましょう```
p = [1] + sellers + [n + 1]
```追加のポジション`n + 1`歩道の終点を表す番兵です。 

定義する```
gap(i) = (p[i] - p[i-1] - 1) // d
```隣接するペアごとに。 

削除されなかった Cookie の総数は次のとおりです。```
base = 1 + Σ gap(i)
```主要な`1`最初のクッキーを表します。 

### この式が機能する理由

 2 つの強制的な Cookie 位置の間`a`そして`b`、Petya は自動的にすべてを食べます。`d`後のベンチ`a`到達するまで`b`。 このような自動 Cookie の数は正確に次のとおりです。```
(b - a - 1) // d
```すべてのギャップを合計し、最初の Cookie を追加すると、完全な合計が得られます。 

### ステップ

 1. アレイを構築する```
p = [1] + s + [n + 1]
```2. コンピューティング```
base = 1 + Σ (p[i] - p[i-1] - 1) // d
```これは販売者を削除する前の Cookie 数です。 
3. 販売者ごとに`s[i]`、内部の位置を特定します`p`。 
4. 販売者に対応させます`p[k]`。 

削除前、影響を受ける投稿は次のとおりです。```
left = (p[k] - p[k-1] - 1) // d
right = (p[k+1] - p[k] - 1) // d
```5. この販売者を削除すると、2 つの間隔がマージされます。```
merged = (p[k+1] - p[k-1] - 1) // d
```6. 販売者自身が 1 つの強制 Cookie を提供するため、それを削除すると 1 つの Cookie が削除されます。 

新しい合計は次のようになります```
cur = base - left - right + merged - 1
```7. すべての値の中で最小値を追跡します。`cur`。 
8. 何人の販売者がその最小値を達成したかを数えます。 

### なぜ効果があるのか

 すべての Cookie カウントは、隣接する強制 Cookie 位置からの寄与に分解できます。 売り手を削除すると、その売り手に接触する 2 つの間隔にのみ影響します。 1 つおきの間隔は変更されません。 

この式では、2 つの古い間隔寄与分が減算され、マージされた間隔寄与分が挿入され、販売者自身の強制 Cookie が削除されます。 ウォークの変更されていない部分はすべてまったく同じ動作を保持するため、結果の値は削除後の真の Cookie 数と等しくなります。 

すべての販売者が独立して正確に評価されるため、最小値とその頻度が正しく計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m, d = map(int, input().split())
        s = list(map(int, input().split()))

        p = [1] + s + [n + 1]

        base = 1
        for i in range(1, len(p)):
            base += (p[i] - p[i - 1] - 1) // d

        best = 10**18
        cnt = 0

        for k in range(1, m + 1):
            left = (p[k] - p[k - 1] - 1) // d
            right = (p[k + 1] - p[k] - 1) // d
            merged = (p[k + 1] - p[k - 1] - 1) // d

            cur = base - left - right + merged - 1

            if cur < best:
                best = cur
                cnt = 1
            elif cur == best:
                cnt += 1

        print(best, cnt)

solve()
```配列`p`Cookie イベントを強制するすべての位置が含まれます。 ベンチ`1`Petya は最初にいつもそこで食事をするため、 が挿入されます。 番兵`n + 1`最後のセグメントで他のすべてのセグメントと同じ式を使用します。 

変数`base`販売者を削除する前に Cookie 数を保存します。 それぞれのギャップが寄与する`(length // d)`自動クッキー。 

インデックスの販売者の場合`k`、隣接する 2 つのギャップのみを変更できます。 計算:```
base - left - right + merged
```これら 2 つのギャップをマージされたバージョンで置き換えます。 

次に、販売者自身の強制 Cookie が消えるため、さらに 1 つ減算します。 

最も一般的な実装エラーは、センチネルを忘れることです。`n + 1`。 これがないと、最後の販売者の後に生成された Cookie はカウントされません。 

もう 1 つのよくあるバグは、ベンチで売り手を誤って扱うことです。`1`。 治療台`1`通常の販売者は二重カウントを引き起こすためです。 この場合は、挿入された開始位置によって自然に処理されます。

 ## 特殊なケース

 次のことを考慮してください。```
n = 2
m = 2
d = 2
s = [1, 2]
```ベンチ`1`には販売者が含まれていますが、Petya は最初のクッキーなのでとにかくそこで食べるでしょう。 販売者の削除`1`最初の Cookie は削除されません。 間隔公式はこれを自然に処理します。`1`常に含まれています`p`。 

考慮する：```
n = 20
m = 2
d = 5
s = [6, 12]
```からの最後のセグメント`12`に`20`自動 Cookie を生成します。 番兵`n + 1 = 21`この末尾を通常の間隔に変換します。 特殊な場合のロジックは必要ありません。 

考慮する：```

m = 4
d = 9
s = [2, 8, 9, 10]
```どの販売者を削除しても同じ答えが得られます。 このアルゴリズムはすべての販売者を個別にチェックし、最小値を達成したすべての削除をカウントします。`4 4`。 

これらのケースはまさに、アドホック シミュレーションが失敗する傾向がある一方で、間隔ベースの定式化は均一で正確なままです。
