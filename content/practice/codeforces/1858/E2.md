 ## 解決策
 ## 問題の理解

 4 種類のクエリを処理する際に、動的配列を維持するように求められます。数値を追加する、最後のクエリを削除する、というものです。$k$数値を取得し、最後の変更をロールバック (追加または削除) し、配列内の個別の数値の数を報告します。 配列は最初は空です。 ロールバックするたびに最新の変更が取り消されるため、複数の連続したロールバックで変更履歴を遡ることができます。 

入力はオンラインです。一度に 1 つのクエリを受け取り、それに答える必要があります。`?`次のクエリを読み取る直前にクエリを実行します。 クエリ数$q$まで可能です$10^6$と合計数`?`クエリは次までです$10^5$。 追加される数字は次のような大きさにすることができます$10^6$。 

制約を考慮すると、配列をスキャンして各要素の個別の要素をカウントするアプローチはすべて可能です。`?`クエリが遅すぎます。 ブルートフォース手法では、$O(n^2)$最悪の場合、これは受け入れられません$q = 10^6$。 さらに、元に戻す操作を効率的にサポートする必要があります。これにより、巧妙な履歴追跡メカニズムなしで Python リストまたはセットを単純に使用することができなくなります。 

明らかではないエッジ ケースには、連続したロールバック、ロールバック削除、要素の繰り返しなどが含まれます。 たとえば、次のシーケンスを考えてみましょう。```
+ 1
+ 2
- 2
!
?
```後`- 2`、配列は空です。 削除をロールバックする`!`復元します`[1,2]`。 完全な変更履歴を追跡しない不注意な実装では、配列を正しく復元できなかったり、個別の要素のカウントを誤ったりする可能性があります。 

## アプローチ

 単純な解決策では、配列をリストに保持し、`+`そして`-`演算を実行し、セットに変換して個別の要素をカウントします。`?`クエリ。 ロールバックは、変更のたびに配列の完全なコピーを保存することで処理できます。 これは正しいですが、配列を繰り返しコピーするとコストがかかります$O(n)$変更ごとに。 と$q = 10^6$、これは$O(n^2)$時間と記憶、それは不可能です。 

重要な洞察は、ロールバックを実装するために完全なアレイのコピーは必要ないということです。 操作の履歴をスタックに保存できます。スタックには、各操作が元に戻すのに十分な情報だけが記録されます。 追加用`+ x`、 店`('add', x)`。 削除用`- k`、削除された要素のリストを保存します。 ロールバックは単にこの履歴から最後の操作をポップし、逆の操作を適用します。 個別の要素を効率的にカウントするために、`Counter`現在の要素の。 これにより、`?`実行するクエリ$O(1)$個別の要素の数を段階的に追跡できるため、時間がかかります。 変更のスタックと頻度カウンターを組み合わせることで、追加、削除、ロールバック、および個別のカウントを効率的にサポートします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * n) | O(n * q) | 遅すぎる |
 | スタック + カウンター | O(q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のリストを初期化する`a`現在の配列を保存するには、`Counter`物体`freq`各数値の頻度を追跡するには、変数を使用します。`distinct_count`個別の要素の現在の数とスタックを保存します。`history`過去の操作を保存します。 
2. 各クエリについて、そのタイプを解析します。 

1. のために`+ x`、追加`x`に`a`、増分`freq[x]`。 もし`freq[x]`以前はゼロでしたが、増加します`distinct_count`。 押す`('add', x)`に`history`。 
2. のために`- k`、最後をポップします`k`からの要素`a`そしてそれらのカウントをデクリメントします`freq`。 いずれかのカウントがゼロになった場合はデクリメントします`distinct_count`。 押す`('remove', [removed_elements])`に`history`。 
3. のために`!`、最後の操作をポップします`history`:

 - もしそうだったら`('add', x)`から最後の要素を削除します。`a`そして減少します`freq[x]`。 もし`freq[x]`ゼロになる、減少する`distinct_count`。 
- もしそうだったら`('remove', removed_elements)`、追加`removed_elements`に戻る`a`そして増加します`freq`それぞれに。 以前にカウントが 0 だった場合は、インクリメントします`distinct_count`。 
4. のために`?`、印刷`distinct_count`そして出力をすぐにフラッシュします。 
3. 次のクエリに進みます。 

なぜ効果があるのか​​:`history`スタックは、ロールバックによって常に最後の変更が正しく取り消されることを保証します。 の`freq`カウンタは各数字が何回出現したかを追跡し、`distinct_count`常に正確です。 すべての操作は`a`そして`freq`に反映されています`history`したがって、ロールバックするたびに両方が復元されます。`a`個別の数値を正確にカウントします。 

## Python ソリューション```python
import sys
from collections import Counter

input = sys.stdin.readline
output = sys.stdout.write

a = []
freq = Counter()
distinct_count = 0
history = []

q = int(input())
for _ in range(q):
    line = input()
    if line[0] == '+':
        x = int(line[2:])
        a.append(x)
        if freq[x] == 0:
            distinct_count += 1
        freq[x] += 1
        history.append(('add', x))
    elif line[0] == '-':
        k = int(line[2:])
        removed = []
        for _ in range(k):
            val = a.pop()
            freq[val] -= 1
            if freq[val] == 0:
                distinct_count -= 1
            removed.append(val)
        removed.reverse()  # preserve original order
        history.append(('remove', removed))
    elif line[0] == '!':
        op = history.pop()
        if op[0] == 'add':
            val = a.pop()
            freq[val] -= 1
            if freq[val] == 0:
                distinct_count -= 1
        else:
            removed = op[1]
            for val in removed:
                if freq[val] == 0:
                    distinct_count += 1
                freq[val] += 1
            a.extend(removed)
    else:  # '?'
        output(f"{distinct_count}\n")
        sys.stdout.flush()
```ソリューションでは、`Counter`周波数を効率的に維持します。 それぞれ`+`または`-`運用の最新情報`distinct_count`で$O(1)$要素ごとに。 ロールバックはこれらの更新を反映します。 それぞれの後に出力をフラッシュします`?`オンラインクエリ要件への準拠を保証します。
