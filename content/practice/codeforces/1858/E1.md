 ## 解決策
 ## 問題の理解

 要素の追加、最後の要素の削除という 4 種類の操作で配列を維持するように求められます。$k$要素を調べ、最後の変更 (追加または削除のいずれか) をロールバックし、現在配列内の個別の要素の数をクエリします。 各クエリは順番に処理され、ロールバックはクエリ自体ではなく、最新の変更にのみ影響します。 

入力は最大 100 万のクエリで構成され、追加される各要素は最大 100 万になる可能性があります。 クエリの種類`?`個別の要素の数を求めるメッセージは最大 100,000 回表示されます。 これは、クエリを実行するたびに個別の要素のセットを最初から再構築する余裕がないことを意味します。$10^6$遅すぎるでしょう。 また、メモリ制限を超えるため、変更ごとにアレイの完全なスナップショットを保存することもできません。 

素朴なアプローチは、配列を直接シミュレートし、それぞれの`?`クエリを実行すると、それをセットに変換して個別の要素をカウントします。 これは論理的には正しいですが、最悪のシナリオでは、長さ 1,000,000 までの配列に対して 100,000 件のクエリが発生し、$O(10^{11})$操作。 これは 3 秒の制限では明らかに非現実的です。 

明らかではないエッジ ケースには、ロールバックの繰り返し、追加と削除の交互の実行、複数の同一の番号などが含まれます。 たとえば、配列が次の場合、`[1,2,2,3]`2 つの要素を削除すると、配列は次のようになります。`[1,2]`。 その後ロールバックする場合は、正確に元の状態に戻る必要があります。`[1,2,2,3]`、カウントを正しく保存します。 履歴を慎重に保存しない単純な実装では、`[1,2,3]`または何らかの間違った状態。 

## アプローチ

 ブルートフォース手法では、配列の単純なリストを維持し、各クエリを文字通りに処理します。 追加用`+ x`、 追加`x`リストに。 除去用`- k`、最後の部分を切り取ります`k`要素。 ロールバック用`!`、スナップショットのスタックを維持し、前のスナップショットに戻します。 個別のクエリの場合`?`、配列をセットに変換し、そのサイズを返します。 論理的には正しいものの、このアプローチは速度とメモリの両方で失敗します。ロールバック用に大規模な配列のスナップショットを保存すると過剰なスペースが消費され、個別の要素を繰り返しカウントするのは遅すぎます。 

重要な洞察は、ロールバックや個別のカウントに配列全体が必要ないということです。 代わりに、スタックを使用して配列を段階的に表現し、操作を元に戻すために必要な情報を保存できます。 個別のカウントについては、要素の頻度マップを維持します。 追加するたびに追加された要素の周波数が増加し、削除されるたびに周波数が減少し、ロールバックするたびに最後の周波数の変更が単に元に戻されます。 削除の場合は、ロールバックで正確に復元できるように、削除された要素が履歴に保存されます。 これにより、$O(1)$変更ごとに更新し、$O(1)$正のカウントを持つ周波数マップのキーを使用した個別のカウントの取得。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * n) | O(q * n) | 遅すぎる |
 | 最適 | O(q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のリストを初期化する`a`配列の場合は頻度辞書`freq`要素を現在の数と履歴ス​​タックにマッピングする`history`ロールバックのために変更を保存します。 
2. 各クエリについて、操作タイプを読み取ります。 もしそうなら`+ x`、追加`x`に`a`、増分`freq[x]`1ずつ押してください`('+', x)`に`history`。 履歴エントリにより、後でこの追加を元に戻すことができます。 
3. クエリが次の場合`- k`、最後のものを削除します`k`からの要素`a`。 削除された要素ごとに、その頻度を減少させます。`freq`。 削除された要素のリストをタプルとして保存します`('-', removed_elements)`で`history`ロールバックを許可します。 
4. クエリが次の場合`!`、最後の操作をポップします`history`。 追記だったら`('+', x)`から最後の要素を削除します。`a`そして減少します`freq[x]`。 撤去だったら`('-', removed_elements)`、削除されたすべての要素を元に追加します`a`そしてその周波数を増加させます`freq`。 
5. クエリが次の場合`?`、内のキーの数を返します。`freq`正のカウントを使用すると、個別の要素の現在の数が得られます。 

機能する理由: 周波数マップは常に現在の配列構成を反映し、各要素を正確にカウントします。 履歴スタックは、追加または削除にかかわらず、各ロールバックが最後の変更を正確に元に戻すことを保証します。 これにより、配列の内容と個別の要素数の両方が保存され、すべての要素の正確性が保証されます。`?`クエリ。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def main():
    q = int(input())
    a = []
    freq = defaultdict(int)
    history = []
    results = []

    for _ in range(q):
        line = input().strip()
        if line[0] == '+':
            x = int(line[2:])
            a.append(x)
            freq[x] += 1
            history.append(('+', x))
        elif line[0] == '-':
            k = int(line[2:])
            removed = []
            for _ in range(k):
                val = a.pop()
                freq[val] -= 1
                removed.append(val)
            history.append(('-', removed))
        elif line[0] == '!':
            if not history:
                continue
            op, data = history.pop()
            if op == '+':
                val = a.pop()
                freq[val] -= 1
            else:
                for val in reversed(data):
                    a.append(val)
                    freq[val] += 1
        else:  # '?'
            distinct_count = sum(1 for v in freq.values() if v > 0)
            results.append(str(distinct_count))
    
    print('\n'.join(results))

if __name__ == "__main__":
    main()
```ソリューションでは、`defaultdict(int)`頻度管理を簡素化します。 ロールバックの場合、追加と削除は慎重に元に戻され、配列と頻度の両方のカウントが復元されます。 削除された要素を元に戻すと、配列の元の順序が確実に保持されます。
