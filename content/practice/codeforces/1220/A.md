 ## 問題の理解

 元々はいくつかのバイナリワードを書くことで得られた複数の文字セットが与えられます。各ワードは次のいずれかの文字列です。`"zero"`数字の0を表す、または`"one"`これらの単語は連結されてからすべての文字がシャッフルされるため、生の文字数を除くすべての構造が失われます。 

私たちの仕事は、これらの文字を生成した可能性のある 2 進数を再構築することですが、すべての有効な再構築の中で、可能な最大の 2 進数を出力する必要があります。 つまり、できるだけたくさん欲しいということです`1`バイナリ表現では任意の数字が使用できるため、できるだけ数字を使用してください。`1`よりも多くの価値に貢献する`0`同じ位置にあります。 

重要な制約は、すべての文字を正確に使用する必要があり、形成するすべての数字が次のいずれかに対応している必要があることです。`"zero"`または`"one"`。 

入力サイズは最大 100000 文字です。 これにより、取り決めを並べ替えたり検索したりしようとするアプローチは即座に排除されます。 最悪の場合、二次手法でも遅すぎる可能性があります。 純粋にカウントと貪欲な抽出に基づいた線形または線形に近い再構成が必要です。 

単語間で文字が重なり合う場合、微妙なエッジケースが発生します。 例えば、`"o"`、`"n"`、`"e"`と重なる`"z"`、`"e"`、`"r"`、`"o"`手紙の中だけで`'o'`そして`'e'`。 注意して順序付けせずに貪欲に単語を選択しようとする単純な試みは、抽出を優先しないと失敗する可能性があります。`"one"`初め。 

もう 1 つのエッジケースは、完全な単語が存在しない場合です。`"one"`または`"zero"`文字は存在するのに。 例えば、`"noe"`どちらの単語も形成できず、制約により出現すべきではありませんが、中間の貪欲ロジックでは、部分一致が有効であると想定することを回避する必要があります。 

## アプローチ

 ブルートフォース解釈では、文字をサイズ 3 または 4 のチャンクにグループ化するすべての順列を試し、各チャンクが形成されているかどうかを確認することによってシーケンスを再構築しようとします。`"one"`または`"zero"`。 グループ化サイズを修正したとしても、文字列のパーティションの組み合わせを試す必要があり、文字列のパーティションは n とともに指数関数的に増加します。 n = 100000 では、これは完全に不可能です。 

重要な観察は、各数字が固定された複数の文字セットに対応しているということです。 文字を恣意的に配置しているのではなく、マルチセットを既知の固定マルチセットに分解しています。`zero → {z, e, r, o}`

`one → {o, n, e}`これは古典的な複数集合の分解問題です。 貪欲な戦略は、文字数とは独立して各単語を何回形成できるかを決定することです。 

2 つの単語の間の唯一の結合は共通の文字です`'o'`そして`'e'`ですが、抽出を優先することでこれをきれいに解決できます。`"one"`初め。 その理由は、`"one"`用途`'n'`には登場しません。`"zero"`、したがって一意に識別可能です。 一度すべて`"one"`単語が抽出され、残りの文字が自然に形成されます`"zero"`できれば言葉も。 

何個数えた後`"one"`形成することができ、頻度表から文字の使用状況を差し引いてから数えます。`"zero"`。

 ## アルゴリズムのチュートリアル

 文字を数え、決定的な順序で単語を抽出することで進めます。 

1. 入力文字列内のすべての文字の頻度をカウントします。 これにより、形成できる単語の数にグローバルな制約が与えられます。 
2. 何回結成できるかを決める`"one"`。 以来`"one"`必要`'n'`、そしてのみ`"one"`用途`'n'`、の数`"one"`単語は正確に次の数です`'n'`。 
3. それぞれについて`"one"`を削除し、カウントをデクリメントします`'o'`、`'n'`、 そして`'e'`。 このステップにより、すでにコミットされたレターを再利用しないことが保証されます。 
4.すべて取り外したら`"one"`単語、何個かを計算します`"zero"`言葉を形成することができる。 これは、残りのカウントによって制限されます。`'z'`、`'e'`、`'r'`、 そして`'o'`。 削除後はすべての文字が独立しているため、`"one"`、の数`"zero"`単語は、これらの必須文字の最小頻度によって制限されます。 
5. すべてを出力して最終的な答えを作成します。`"one"`最初に数字 (バイナリ値を最大化するため)、次にすべての数字が続きます`"zero"`数字。 

2 進数は上位の位置に 1 を配置することで最大化され、出力はスペースで区切られた数字であるため、最初にすべて 1 を配置することで辞書編集上および数値的に最大の出力が保証されるため、順序付けは重要です。 

### なぜ効果があるのか

 正しさは次の事実に依存します`"one"`固有の識別文字がある`'n'`に現れないもの`"zero"`。 これにより、`"one"`単語は固定されており、順序の選択とは独立しています。 すべての発生が完了すると、`"one"`が削除されると、残りのマルチセットには有効な組み合わせのみが含まれます。`"zero"`入力が有効であることが保証されている場合は、単語。 貪欲な分離によって最適性が失われることはありません。なぜなら、`"one"`のために`"zero"`固定文字制約に違反することなく。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    cnt = [0] * 26

    for ch in s:
        cnt[ord(ch) - 97] += 1

    o = ord('o') - 97
    n = ord('n') - 97
    e = ord('e') - 97
    z = ord('z') - 97
    r = ord('r') - 97

    ones = cnt[n]

    # build ones
    cnt[o] -= ones
    cnt[n] -= ones
    cnt[e] -= ones

    zeros = min(cnt[z], cnt[e], cnt[r], cnt[o])

    res = []
    res.extend(["1"] * ones)
    res.extend(["0"] * zeros)

    sys.stdout.write(" ".join(res))

if __name__ == "__main__":
    solve()
```実装は完全に頻度アカウンティングによって推進されます。 私たちは明示的に依存しています`'n'`カウントの軸として`"one"`そこにユニークに現れるからです。 その寄与を差し引いた後、安全に計算します。`"zero"`残りの文字から数えます。 

最後の連結ステップでは、順序付けの正確性が保証されます。`"1"`数字は前に置かれます`"0"`数字。 

微妙な実装の詳細は、`"one"`数える前に`"zero"`。 このステップをスキップすると、次のような文字が共有されます。`'o'`そして`'e'`二重にカウントされ、水増しされた数が生成されます。`"zero"`言葉。
