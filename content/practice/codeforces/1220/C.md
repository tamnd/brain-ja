 ## 問題の理解

 文字列が与えられています`s`そして、開始位置ごとに 2 人のプレーヤーのゲームの結果を予測する必要があります。`k`文字列の中で。 ゲームは、位置にある単一の文字で構成される部分文字列から始まります。`k`。 アンが最初に動き、各プレイヤーは現在の部分文字列を外側 (左または右) に拡張して、現在の部分文字列よりも **辞書編集的に小さい** 新しい部分文字列を形成します。 有効な手を打てなかったプレイヤーは負けます。 

出力は次のようになります。`|s|`開始インデックスごとに 1 行ずつ`k`、両方が最適にプレイした場合にアンとマイクのどちらが勝つかを指定します。 

文字列の長さは最大 500,000 です。 これにより、開始位置ごとに最大 O(n²) 個の部分文字列が存在する可能性があるため、すべての可能な部分文字列拡張を明示的にシミュレートする総当り的なアプローチが即座に除外されます。 1 回の O(n²) 反復でも 2.5 × 10¹¹ 操作に達しますが、これは 2 秒の制限時間では実現不可能です。 これは、構造化された形式または前処理された形式での文字列比較を活用する、O(n log n) または O(n) ソリューションの必要性を示しています。 

文字列に繰り返し文字が含まれる場合、微妙なエッジケースが発生します。 たとえば、`s = "aaaa"`、拡張子は厳密に小さい部分文字列を作成できないため、開始インデックスに関係なく、最初のプレーヤーはすぐに負けます。 単純な解決策では、拡張が常に可能であると誤って想定され、誤った結果が生じる可能性があります。 

## アプローチ

 ブルートフォースアプローチは、開始位置ごとにゲームをシミュレートすることです。`k`。 ターンごとに、左右に広がるすべての部分文字列を生成し、それらを辞書編集的に比較し、どの手が有効であるかを判断します。 ゲームは完全に決定的で有限であるため、これは原理的には正しく機能します。 ただし、各位置の部分文字列の数は二次関数的に増加し、辞書編集的な比較を単純に再計算すると、最悪の場合の複雑さは O(n³) になります。 これは、n が 500,000 までの場合は不可能です。 

重要な洞察は、ゲームの結果は、**各位置から始まる接尾辞の辞書編集上の順序**に完全に依存するということです。 部分文字列は、より小さい部分文字列が存在する場合にのみ拡張できるため、文字列を **接尾辞配列**に前処理するか、組み合わせゲーム理論の **グランディ数値**を使用すると、勝者を効率的に計算できます。 具体的には、各開始インデックスを表すことができます。`k`接尾辞によって`s[k:]`、およびその位置での勝者`k`重複する辞書編集的に小さい接尾辞が存在するかどうかによって決定されます。`k`。 このアプローチを使用すると、サフィックス配列を前処理した後、問題は O(n) に削減されます。

 ## アルゴリズムのチュートリアル

 1. 文字列の **サフィックス配列** を構築します`s`。 サフィックス配列はすべてのサフィックスを並べ替えます`s[i:]`辞書編集上の順序に従って。 これにより、どの接尾辞が指定された位置よりも小さいかを迅速に判断できます。 
2. 各ポジションの **グランディ数**を計算します。 グランディ数値はゲーム状態の「番号」を表します。0 は負けの位置を示し、正の数値は勝ちの位置を示します。 インデックスごとに`k`、左または右に展開することで到達可能な、辞書編集上最小の接尾辞を確認します。 そのような動きが存在する場合は、到達可能な状態の xor を計算します。 
3. グランディ番号を使用して勝者を決定します。 位置にグランディ番号がある場合`k`が 0 の場合、アンは負けます (したがってマイクは勝ちます)。 それ以外の場合は、マイクを負けの立場に追い込むような動きをしたアンが勝ちます。 
4. すべてのポジションの勝者を出力します`k`0からn-1の順に。 

**機能する理由:** サフィックス配列により、最長共通プレフィックス (LCP) 情報を使用して O(1) 内の任意の 2 つの部分文字列を迅速に比較できることが保証されます。 グランディ数値は最適なプレイをエンコードし、XOR プロパティにより、どのような動きでもゲームが既知の状態にまで低下することが保証されます。 これにより、すべての有効な手を抽象化された圧縮形式で徹底的に考慮するため、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    s = input().strip()
    n = len(s)
    
    # Compute the minimal character to the left and right for each position
    left_min = [s[0]] * n
    for i in range(1, n):
        left_min[i] = min(left_min[i-1], s[i])
    
    right_min = [s[-1]] * n
    for i in range(n-2, -1, -1):
        right_min[i] = min(right_min[i+1], s[i])
    
    # Determine the winner at each position
    res = []
    for k in range(n):
        if s[k] > left_min[k] or s[k] > right_min[k]:
            res.append("Ann")
        else:
            res.append("Mike")
    
    print("\n".join(res))

if __name__ == "__main__":
    main()
```このソリューションは完全なサフィックス配列を回避し、プレーヤーがより小さな部分文字列を作成するためにのみ拡張できるより単純なプロパティに依存します。 各インデックスの左右の最小文字を追跡することで、より小さい部分文字列が到達可能かどうかがすぐにわかります。 これにより、複雑さが O(n) 時間と O(n) 空間に軽減されます。
