パス全体が終了すると、2 ステップ離れた位置のペアごとに異なる色が表示されます。 ポジションなら`j`が変更された場合、明示的に異なるものになります`j - 2`、その後の操作`j + 2`明示的に作る`j + 2`とは違う`j`。 したがって、財産は峠の終わりまで存続します。 
4. ポジションを見つける`k`ターゲット文字列内で、隣接する 2 つの文字列が異なります。 から始まる`k + 1`、すべての位置を循環的に歩きます。 ポジションごとに`j`、別の色を選択してください`t[j - 2]`そして現在`s[j + 2]`。 

最初のパスの後はわかっているため、最初の操作は正当です。`s[k] != s[k + 2]`。 後続の操作ごとに、前の位置`j - 1`とは異なる値に色が変更されただけです`s[j + 1]`, そのため、現在の位置には異なる色の隣接点があります。 

このパスの終わりには有用な条件が得られます`s[j] != t[j - 2]`あらゆる人にとって`j`。 特に、最後に処理された位置は`k`、私たちも持っています`s[k] != s[k + 2]`。 
5. 再度次から開始して最終パスを実行します。`k + 1`、そして単純にすべてを設定します`s[j]`に`t[j]`。 

最初の手術は、`k + 1`合法であるため、`s[k]`そして`s[k + 2]`異なる。 通常の後の位置の場合`j`、その左隣はすでに`t[j - 1]`、その右隣はまだ古いものですが、`s[j + 1]`。 2パス目からは、`s[j + 1] != t[j - 1]`位置での 2 番目のパス条件のため`j + 1`まさにそうでした`s[j + 1] != t[j - 1]`。 したがって、隣接する 2 つは異なります。 

ようやくスキャンが完了したら`k`、両方の隣接色がすでにターゲット カラーになっています。 彼らです`t[k - 1]`そして`t[k + 1]`の選択によって異なります。`k`。 したがって、最後の操作も合法です。 
6. 3 つのパスには正確に次の内容が含まれます`n`それぞれの操作。 合計は`3n`、常に最大です`10n`。 

### なぜ効果があるのか

 中心的な不変条件は、最初のパスで`s[j] != s[j + 2]`どこでも。 これにより、2 番目のパスを任意に選択したターゲット位置で開始できるようになり、後続のすべての位置の先行者がその位置を合法にすることができます。 

2 番目の不変式は`s[j] != t[j - 2]`。 最終パス中に、すでに固定されている位置の左隣`j`まさに`t[j - 1]`、一方、手つかずの右隣は`s[j + 1]`。 の 2 番目の不変式`j + 1`この2つの色は違うと言います。 この引数が変更される唯一の位置は、`k`、そしてそこではターゲット自体が異なる近隣を保証します。 したがって、それぞれの`3n`生成された操作は正当であり、最終状態は正確に`t`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

COLORS = "RYB"

def find_movable(a):
    n = len(a)
    for i in range(n):
        if a[(i - 1) % n] != a[(i + 1) % n]:
            return i
    return -1

def choose_color(a, b):
    for c in COLORS:
        if c != a and c != b:
            return c
    raise RuntimeError("No color exists")

def solve_case(n, s, t):
    if s == t:
        return []

    start = find_movable(s)
    target_start = find_movable(t)

    if start == -1 or target_start == -1:
        return None

    a = list(s)
    ans = []

    # First pass:
    # make every pair of positions at distance 2 different.
    for step in range(n):
        j = (start + step) % n
        c = choose_color(a[(j - 2) % n], a[(j + 2) % n])
        a[j] = c
        ans.append((j + 1, c))

    # Second pass:
    # make a[j] different from t[j - 2] for every j.
    k = target_start
    for step in range(1, n + 1):
        j = (k + step) % n
        c = choose_color(t[(j - 2) % n], a[(j + 2) % n])
        a[j] = c
        ans.append((j + 1, c))

    # Third pass:
    # directly construct t.
    for step in range(1, n + 1):
        j = (k + step) % n
        c = t[j]
        a[j] = c
        ans.append((j + 1, c))

    assert ''.join(a) == t
    assert len(ans) == 3 * n
    assert len(ans) <= 10 * n

    return ans

def main():
    n = int(input())
    s = input().strip()
    t = input().strip()

    ans = solve_case(n, s, t)

    if ans is None:
        print(-1)
        return

    print(len(ans))
    for pos, color in ans:
        print(pos, color)

if __name__ == "__main__":
    main()
```の`find_movable`関数は、正当な操作に必要な条件を正確にチェックします。 最初と最後のローソク足が隣接するローソク足として扱われるように、モジュール式インデックスを使用します。 

最初のパスは変更します`a`所定の位置にあります。 重要な実装の詳細は、色がすぐ隣の位置ではなく、2 つ離れた位置を使用して選択されることです。 直近の近傍は操作が正当であるかどうかを決定し、距離 2 の位置は作成する不変式を決定します。 

2 番目のパスでは、固定ターゲット文字列を使用します。`t`2 つの除外項目のうちの 1 つで。 もう 1 つの除外は、現在の変更可能な文字列からのものです`a`。 この区別は重要です。`t`決して変更してはなりませんが、`a`は、以前のすべての操作後の状態を表します。 

ループは使用します`(k + step) % n`と`step`からの範囲`1`を通して`n`。 これは正確に訪問します`k + 1, k + 2, ..., k`周期的に、特別な位置`k`意図的に最後に処理されます。 

ここでは、Python 整数には特別なオーバーフロー処理は必要ありません。 答えには正確に含まれています`3n`せいぜいオペレーション`300000`したがって、操作リストとすべてのインデックスの両方がメモリに快適に収まります。

def run(inp: str) -> str:
    data = inp.strip().split()
    n = int(data[0])
    s = data[1]
    t = data[2]

    ans = solve_case(n, s, t)

    if ans is None:
        return "-1\n"

    out = [str(len(ans))]
    out.extend(f"{p} {c}" for p, c in ans)
    return "\n".join(out) + "\n"

def validate(inp: str, out: str):
    data = inp.strip().split()
    n = int(data[0])
    s = data[1]
    t = data[2]

    lines = out.strip().splitlines()

    if lines == ["-1"]:
        # Verify independently that at least one endpoint is frozen
        def movable(x):
            for i in range(n):
                if x[(i - 1) % n] != x[(i + 1) % n]:
                    return True
            return False

        assert s != t
        assert not movable(s) or not movable(t)
        return

    k = int(lines[0])
    assert 0 <= k <= 10 * n
    assert len(lines) == k + 1

    a = list(s)

    for line in lines[1:]:
        p, c = line.split()
        p = int(p)
        assert 1 <= p <= n
        assert c in "RYB"

        i = p - 1
        assert a[(i - 1) % n] != a[(i + 1) % n]

        a[i] = c

    assert ''.join(a) == t

 ## 特殊なケース

 単色ソースは完全にフリーズしています。 のために```
3
RRR
RRY
```どのポジションにも 2 つあります`R`近所の人、だから`find_movable`返品`-1`。 文字列が異なるため、アルゴリズムはすぐに戻ります。`-1`。 違法な最初の操作を捏造しようとすることは決してありません。 

偶数交流電源もフリーズします。 のために```
4
RYRY
RYRB
```位置`1`隣人がいる`Y`そして`Y`、 位置`2`隣人がいる`R`そして`R`、同じパターンがサイクル全体で続きます。 ソースには移動可能な位置がないため、アルゴリズムは戻ります。`-1`。 

凍結されたターゲットも同様に制限されます。 のために```
3
RYB
RRR
```ソースは移動可能ですが、ターゲットは移動できません。 最終的な動き`RRR`ターゲット内のすべてのキャンドルには同じ色の隣があるため、これは不可能です。 ターゲット チェックは、シーケンスを構築する前にこれを検出します。 

同等の凍結された文字列は異なります。 のために```
4
RYRY
RYRY
```ソースとターゲットが同一であるため、アルゴリズムは構成が移動可能かどうかを確認する前に空の操作リストを返します。 これが必要なのは、凍結状態自体がすでに有効な最終状態であるためです。 

構成`RRYY`は、この構造が、両方の隣接色と異なる独自の色を持つ位置を検索するのではなく、異なる隣接位置を検索する理由を示しています。 で```
4
RRYY
YYRR
```位置`1`隣人がいる`Y`そして`R`なので、それ自身の色であっても移動可能です。`R`。 最初のパスはそこから開始して、距離 2 の不変条件を確立できます。 

周期的な境界もエラーの一般的な原因です。 実装では、次のような式が使用されます。`a[(j - 2) % n]`そして`a[(j + 2) % n]`どこでも使われています。 これによりポジションが近くなります`0`近くの位置と正しく相互作用します`n - 1`。 2 番目と 3 番目のパスは意図的にその位置で終了します`k`、それが彼らのループが使用する理由です`range(1, n + 1)`それよりも`range(n)`。 

最後に、操作カウントはサンプルと一致する必要はありません。 サンプル出力は、有効なシーケンスの例にすぎません。 私たちの建設は常に`0`いつ動くか`s == t`、`-1`変身が不可能なとき、そしてまさに`3n`それ以外の場合は動きます。 以来`3n <= 10n`、成功したすべての建設は必要なリソース制限を満たします。
