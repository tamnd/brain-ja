 ## 問題の理解

 (n) 個の非負の整数の配列 (a_1,a_2,\ldots,a_n) があります。 3 つの異なる要素ごとの積の合計が必要です。ここで、インデックスは (i<j<k) を満たす必要があります。 

[
 \sum_{1\le i<j<k\le n} a_i a_ja_k。 
】

 選択したトリプル内の順序は重要ではありませんが、3 つの異なる位置のセットごとに 1 回だけ寄与する必要があります。 答えはモジュロ (10^9+7) である必要があります。 

難しさは (n) の大きさに由来します。 (n\le 10^6) の場合、すべてのトリプルをチェックすることは現実的ではありません。 トリプルの数は、

 [
 \binom{n}{3}、
 】

 届くのは

 [
 \binom{10^6}{3}=166666166667000000
 】

 最大サイズで。 たとえ 1 つの積を計算するのにいくつかの基本的な操作しか必要なかったとしても、およそ (1.67\cdot10^{17}) 個のトリプルを反復処理するのは妥当な制限時間をはるかに超えています。 

値 (a_i) は (10^6) まで大きくなる可能性があるため、数学的な答えは膨大になります。 算術モジュロ (10^9+7) を実行する必要があり、実装では不必要に大きな整数が蓄積されるのではなく、定期的に中間値を減らす必要があります。 

不適切な実装が明らかになる可能性のあるいくつかのエッジケースがあります。 最小限の要素数を使用すると、入力は```
3
1 2 3
```にはトリプルが 1 つだけあるため、答えは (1\cdot2\cdot3=6) になります。 実装が誤って 4 つの要素を必要としたり、応答に寄与を追加する前にペアの合計の更新を開始したりすると、この境界ケースが間違ってしまう可能性があります。 

ゼロ値も便利なケースです。 のために```
4
0 5 6 7
```ゼロを含むすべてのトリプルは何も寄与せず、(5\cdot6\cdot7=210) だけが残ります。 ここでは、除算に基づいた数式、またはすべての値が正であるという仮定に基づいた数式が誤って動作する可能性があります。 

値が繰り返される場合は、数値ではなく位置を個別の選択肢として扱う必要があります。 例えば、```
4
2 2 2 2
```には 4 つのトリプルがあり、それぞれが (8) に寄与するため、答えは (32) になります。 インデックスの組み合わせではなく、個別の値の組み合わせを列挙しようとする実装では、これが誤ってカウントされます。 

最後に、非常に大きな値も、(10^9+7) を法として正しく処理する必要があります。 例えば、```
3
1000000 1000000 1000000
```has answer (10^{18}), which is (49) modulo (10^9+7). The individual input values fit comfortably in standard integer types, but products and sums grow much faster.

 ## アプローチ

 The direct solution follows the definition literally. We choose (i), then (j>i), then (k>j), calculate (a_i a_j a_k), and add it to the answer. This is correct because every valid triple of indices is visited exactly once.

 問題は反復回数です。 For (n=10^6), the three nested loops execute once for each of the

 [
 \binom{10^6}{3}=166666166667000000
 】

 possible triples. つまり (O(n^3)) ですが、これでは遅すぎます。 

The useful observation is that the triple containing the current element does not need to be constructed explicitly. Suppose we process the array from left to right and currently examine (a_k). Every new triple ending at position (k) has the form

 [
 a_i a_ja a_k、\qquad i<j<k。 
】

 We can factor out (a_k):

 [
 a_k\sum_{i<j<k}a_i a_j.
 】

 So, before processing (a_k), we only need to know the sum of products of every pair among the elements already processed.

 Call this quantity`pair_sum`。 (a_k) がペアの一部になると、前のすべての要素がそれと 1 つのペアを形成するため、前のすべての要素の合計も必要になります。 

a_k\sum_{i<k}a_i.
 】

 したがって、2 つの実行値で十分です。`sum1`前の要素の合計を保存し、`sum2`前の要素間のすべてのペアの積の合計を格納します。 

(x=a_k) を処理するとき、既存の`sum2`(i<j<k) のペア ((i,j)) を正確に表します。 これに (x) を乗算すると、(k) で終わるすべての新しいトリプルが追加されます。 

[
 \text{答え}\mathrel{+}=x\cdot\text{sum2}。 
】

 その後、(x) は将来のすべてのペアの一部になる必要があります。 それらの新しいペアは積和の合計を持ちます

 [
 x\cdot\text{sum1},
 】

 それで更新します

 [
 \text{sum2}\mathrel{+}=x\cdot\text{sum1}。 
】

 最後に、(x) が前の要素として利用可能になります。 

[
 \text{sum1}\mathrel{+}=x。 
】

 これらの更新の順序は重要です。 答えは古いものを使用する必要があります`sum2`現在の位置で終わるトリプルは 2 つ前の位置を使用する必要があるためです。 更新していたら`sum2`まず、現在の要素が誤って 2 回使用される可能性があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^3)) | (O(1)) | 遅すぎる |
 | 最適 | (O(n)) | (O(1)) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`sum1 = 0`、`sum2 = 0`、 そして`answer = 0`。 何かを処理する前には、以前の要素、以前のペア、および以前のトリプルは存在しません。 
2. 各配列値 (x) を左から右に読み取ります。 位置を自然な順序で処理するため、新しく作成されたすべてのトリプルのインデックスが自動的に昇順になります。 
3. (x\cdot\text{sum2}) を追加します`answer`。 まさにこの瞬間、`sum2`現在の位置より厳密に前の両方のインデックスを持つすべての積 (a_i a_j) が含まれます。 それぞれに (x) を乗算すると、最後のインデックスが現在の位置となるすべてのトリプルが作成されます。 
4.アップデート`sum2`(x\cdot\text{sum1}) を追加します。 ここ`sum1`には以前に処理されたすべての値が含まれるため、現在の要素と 1 つ前の要素で構成されるすべてのペアが正確に作成されます。 
5.アップデート`sum1`(x) を追加します。 現在の要素は、後で処理されるすべての位置の前の要素になります。 
6. 算術モジュロ (10^9+7) を実行します。 加算と乗算はモジュラー演算を考慮するため、各実行量を法で減算すると、最初に完全な整数を計算した場合とまったく同じ最終剰余が得られます。 

### なぜ効果があるのか

 最初の (k) 要素を処理した後の不変条件は次のとおりです。`sum1`等しい

 [
 \sum_{i=1}^{k}a_i,
 】

 その間`sum2`等しい

 [
 \sum_{1\le i<j\le k}a_i a_j,
 】

 そして`answer`等しい

 [
 \sum_{1\le i<j<l\le k}a_i a_ja_l。 
】

 次の値 (a_{k+1}) が到着すると、古い値を乗算します。`sum2`by (a_{k+1}) は、最大のインデックスが (k+1) であるすべてのトリプルを正確に加算します。 更新中`sum2`次に、(a_{k+1}) を含むすべての新しいペアを正確に追加し、更新します`sum1`新しい要素自体を追加します。 各トリプルは最大のインデックスが処理されるときに追加されるため、トリプルを 2 回追加することはできません。また、無効なトリプルが出現することはありません。`sum2`以前の位置からのペアのみが含まれます。

input = sys.stdin.readline

MOD = 1_000_000_007

def solve():

    sum1 = 0
    sum2 = 0
    answer = 0

    for _ in range(n):

```入力には 2 行目にすべて (n) 個の数値が含まれているため、直接ストリーミング ループが実行されます。`input().split()`Pythonでは推奨されます。 完全な実装は次のとおりです。```python
import sys
input = sys.stdin.readline

MOD = 1_000_000_007

def solve():
    n = int(input())
    a = map(int, input().split())

    sum1 = 0
    sum2 = 0
    answer = 0

    for x in a:
        answer = (answer + x * sum2) % MOD
        sum2 = (sum2 + x * sum1) % MOD
        sum1 = (sum1 + x) % MOD

    print(answer)

if __name__ == "__main__":
    solve()
```最初の状態変数、`sum1`は、処理されたプレフィックスにわたる次数 1 の基本対称和を表します。 2番目、`sum2`、 は 2 次対称和を表します。 答え自体は 3 次の対称和です。 

回答は以前に更新されました`sum2`。 これは実装の最も微妙な部分です。 現在の値 (x) を考えてみましょう。 加工する前に、`sum2`には、以前の要素のみから形成されたペアが含まれています。これは、(x) で有効なトリプルを作成するためにまさに必要なものです。 回答の更新後、(x\cdot\text{sum1}) を追加します`sum2`後の要素のために状態を準備します。 

コードは次の値を受け取ります。`map`したがって、入力から Python 整数の 2 番目のリストは構築されません。 入力行自体は依然としてトークン化されています。`split`これは、この問題のサイズに適しており、実装を単純に保ちます。 

Python の整数はオーバーフローしませんが、モジュラー リダクションは状態が更新されるたびに実行されます。 これにより、数値を小さく保つだけでなく、数学的なモジュラー計算との対応関係が明確になります。 

最初の 2 つの要素には特別な処理はありません。 最初は`sum2`はゼロであるため、最初の 2 つの値はトリプルに寄与できません。 2 つの値が処理された後、`sum2`にはその積が含まれており、3 番目の値は最初に考えられるトリプルを自然に作成します。

 ## 特殊なケース

 ### まさに 3 つの要素

 のために```
3
1 2 3
```初期状態は`sum1 = 0`、`sum2 = 0`、`answer = 0`。 処理(1)のみ変更`sum1`、(1)を与えます。 処理 (2) ではペアの合計 (2) が作成されますが、要素がまだ 2 つしかないため、答えはゼロのままです。 (3)の処理では古いペアの合計を使用するので、`answer = 3 * 2 = 6`。 出力は`6`。 

これにより、実装が現在の要素の寄与を計算する前にペアの状態を更新する可能性がある、off-by-one の間違いが捕捉されます。 

### ゼロ要素

 のために```
4
0 5 6 7
```ゼロを処理すると、3 つの状態がすべてゼロのままになります。 処理 (5) は次のようになります。`sum1 = 5`。 処理 (6) により生成される`sum2 = 30`。 (7) が到着すると、寄与します (7\cdot30=210)。 出力は`210`。 

再発には特別なゼロケースは必要ありません。 ゼロは当然、新しいペアと新しいトリプルの両方にゼロを与えるため、同じ不変式は変更されずに機能します。 

### 繰り返される値

 のために```
4
2 2 2 2
```最初の 2 つの値によって生成されるのは`sum2 = 4`。 3 番目の値が寄与し (2\cdot4=8)、ペアの状態は (12) になります。 4 番目の値が寄与します (2\cdot12=24)。 最終的な答えは (8+24=32) です。 

4 つのインデックス トリプルは、((1,2,3))、((1,2,4))、((1,3,4))、および ((2,3,4)) です。 それぞれに積 (8) があるため、合計は (32) になります。 繰り返しでは、最大のインデックスに従ってそれらがカウントされます。これにより、4 番目の要素を処理するときに 3 つのトリプルが得られ、3 番目の要素を処理するときに 1 つのトリプルが得られます。 

### 最大値と剰余演算

 のために```
3
1000000 1000000 1000000
```トリプルが1つあり、製品付き

 [
 10^6\cdot10^6\cdot10^6=10^{18}。 
】

 以来

 [

 】

 正しい出力は`49`。 

実装では、更新のたびに状態を減らすことによって同じ結果が計算されます。 Python 自体は任意精度の整数を持ちますが、モジュラー リダクションにより実行状態が制限された状態に保たれ、必要な算術と一致します。 

### 最大配列サイズ

 (n=10^6) ですべての値が 0 に等しい場合、入力には 100 万個の要素が含まれますが、答えは依然として 0 です。 このアルゴリズムは、要素ごとに定数時間反復を 1 回だけ実行します。 トリプルのネストされた列挙は決して作成されないため、実行時間は 3 次ではなく線形に増加します。 

同じループ構造は、100 万個の非ゼロ値も処理します。 の値`sum1`、`sum2`、 そして`answer`は (10^9+7) を法として縮小されたままであるため、維持される状態のサイズは (n) に依存しません。
