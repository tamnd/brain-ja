 ## 解決策
 ## 問題の理解

 変化する妖精のセットがあります。 最初に存在するのは、`n`番号が付けられた妖精`1`を通して`n`、そして妖精`i`社交性の整数値を持ちます`a[i]`。 観察中には、`q`イベント。 

A型`1`イベントでは新しい妖精が追加されます。 その値はイベントによって直接与えられ、次に使用されない番号を受け取るため、削除された番号が再利用されることはありません。 A型`2`イベントは、既存の妖精をその番号によって削除します。 A型`3`価値のあるダンスを発表するイベント`e`。 現在存在するすべての妖精がその値を置き換えます`b`と`b XOR e`。 

すべてのイベントの後、まだ存在するすべての妖精の現在の値の合計が必要になります。 

難しいのは、グローバル XOR 演算です。 1 つのダンスが最大の影響を与える可能性がある`100000`妖精もいるかもしれない`100000`踊ります。 すべての妖精を個別に更新するには、約`10^10`最悪の場合の XOR 演算。 と`n, q <= 100000`、周りのアルゴリズム`O(nq)`実用的なものをはるかに超えていますが、`O((n+q) log(n+q))`または`O(30(n+q))`このアプローチは容易に合理的です。 

単純な実装が静かに間違ってしまう可能性があるエッジケースがいくつかあります。 まず、数回踊った後に妖精が参加できます。 考慮する```
1 3
5
3 7
1 2
3 1
```出力は次のとおりです。```
2
4
5
```最初のダンスの後、元の妖精は`5 XOR 7 = 2`。 新しい妖精がバリューで仲間入り`2`、 ない`2 XOR 7`、最初のダンスのときには存在しなかったからです。 単一のグローバル XOR のみを保存し、それを新しく挿入されたすべての値に盲目的に適用するソリューションでは、このケースは誤って処理されます。 

第二に、いくつかのダンスの後に妖精を削除するには、その現在の値を知る必要がありますが、以前のすべてのダンスを物理的に適用してはなりません。 例えば、```
1 3
4
3 3
2 1
1 1
```生成する```
7
0
1
```本来の妖精には価値がある`4 XOR 3 = 7`それが去るとき。 新しく入った妖精には価値がある`1`、ダンスの後に到着するため。 挿入時の各妖精の値に基づく表現では、削除時にグローバル XOR を考慮する必要があります。 

第三に、識別子は決して再利用されません。 例えば、```
1 4
10
2 1
1 5
2 2
```生成する```
0
5
0
```新しく来た妖精は番号を取得します`2`、数字ではありません`1`。 削除された ID を再利用すると、後の削除が間違った保存状態に関連付けられる可能性があります。 

最終的に、値はほぼ次の値に達する可能性があります。`2^30`、合計はおおよそに達する可能性があります`10^14`。 Python の整数はこれを直接処理しますが、固定幅の整数型を使用する言語では、答えとして 64 ビットの整数が必要です。 

## アプローチ

 直接的な解決策は、すべての妖精の現在の値を保存することです。 タイプの場合`1`イベントでは、type の新しい値を追加します。`2`要求された妖精を削除し、タイプとして`3`現在存在するすべての妖精を反復処理し、その値を次のように置き換えます。`value XOR e`。 値とともに合計を維持すると、挿入と削除が一定の時間で行われますが、ダンスでは依然としてすべてのアクティブな妖精に触れる必要があります。 

この総当り的な方法は、問題で説明されている操作を正確に実行するため、正しいです。 弱点はアップデートの繰り返しが多いことです。 最悪の場合、`100000`妖精たちと`100000`ダンスイベント、約パフォーマンス可能`10^10`個々の妖精のアップデート。 Python のオーバーヘッドを考慮する前でも、これは大きすぎます。 

重要な観察は、XOR が各ビットに対して独立して動作するということです。 1 つのビット位置に注目するとします。 ダンスビットがあれば`0`、そのビットは変わりません。 ダンスビットがあれば`1`、現在のすべての妖精はそのビットを反転します。 合計に対するそのビットの寄与を知るために、各妖精の完全な値を知る必要はありません。 必要なのは、対応する格納ビットが次のようなアクティブな妖精の数だけです。`1`。 

厄介な問題が 1 つあります。それは、新しい妖精が任意のタイミングで現れることです。 これに対処するきれいな方法は、グローバル ダンスの歴史を各妖精の保存された状態から分離することです。 させて`X`これまでに起こったすべてのダンスの XOR になります。 アクティブな妖精ごとに、非表示の値を保存します`base`実際の電流値は`base XOR X`。 

オリジナルの妖精の場合、`base`は最初に指定された値です。 実際の価値を持つ新しい妖精の場合`v`到着したら、そのベースを次のように選択します`v XOR X`。 その後、その実際の値はすぐに`(v XOR X) XOR X = v`、必要に応じて正確に。 

妖精が去ったとき、現在の値を特定するには、その保存されたベースがあれば十分です。`base XOR X`。 古いダンスを再生することなく、ビットごとのカウントからその寄与を取り除くことができます。 

残りの問題は、合計金額を迅速に取得する方法です。 ビットごとに`k`、 維持する`cnt[k]`、アクティブな妖精の数`base`ビットがある`k`セット。 噛まれたら`k`の`X`まさにゼロです`cnt[k]`現在の値にはそのビットが設定されています。 噛まれたら`k`の`X`が 1 の場合、XOR はビットを反転するため、正確には`active - cnt[k]`現在の値にはそのビットが設定されています。 したがって、ビットの寄与は`k`設定ビット数を乗算した値です。`2^k`。 

すべての入力値は最大でも 30 ビットしかないため、関連するビットは 30 ビットのみです。`10^9`、以下にあります`2^30`。 すべてのイベントでビット数を更新できます。`O(30)`すべての答えは時間で計算することもできます。`O(30)`時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(nq)`最悪の場合 |`O(n + q)`| 遅すぎる |
 | 最適 |`O(30(n + q))`|`O(n + q)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グローバル整数を保持する`X`、最初はゼロです。 これは、これまでに発生したすべてのダンスの XOR を表します。 すべての妖精の実際の値は次のように表されます。`base XOR X`。 
2. メンテナンス`cnt[k]`各ビットごとに`k`から`0`を通して`29`。 アクティブな妖精が何人噛んだかを保存します`k`彼らの中に設定`base`価値。 配列も保持します`base[id]`考えられるすべての妖精識別子に対して、後で削除することで識別子が得られ、その保存された表現が必要になるためです。 
3. 初期の妖精ごとに、その指定された値をベースとして保存します。 に 1 つ追加します`cnt[k]`その値の設定されたビットごとに。 以来`X = 0`最初は、基本表現は実際の値と等しくなります。 
4. タイプの場合`1`価値のあるイベント`v`、次の未使用の識別子を割り当てます。 新しい拠点は、`v XOR X`。 これは重要な挿入ルールです。新しい妖精には実際の値が必要です。`v`これまでのダンスはすべてすでにエンコードされていますが、`X`。 
5. この新しいベースのビットを`cnt`。 妖精は、既存のすべての妖精と一貫して表現されるようになりました。 
6. タイプの場合`2`識別子付きのイベント`p`、取得します`base[p]`。 設定されたビットをから削除します`cnt`。 グローバルな`X`変更されないため、他に何も変更する必要はありません。 
7. タイプの場合`3`価値のあるイベント`e`、 交換する`X`による`X XOR e`。 個々の妖精には触れません。 すべての現在値は次のように表されるため、`base XOR X`、変化する`X`新しい XOR 演算をそれらすべてに同時に適用します。 
8. イベントごとに、少しずつ答えを計算します。 ちょっと`k`、 もし`X`そこにゼロがある場合、現在の値の数は`cnt[k]`。 もし`X`そこに 1 があり、その番号は`active - cnt[k]`。 そのカウントを乗算します`2^k`そしてそれを答えに追加します。 

### なぜ効果があるのか

 不変条件は、すべてのアクティブな妖精について、その実際の値が正確に`base[id] XOR X`、 その間`cnt[k]`は、ビットを含むアクティブな塩基の正確な数です。`k`セット。 最初は両方のステートメントが成り立ちます。`X = 0`。 挿入が選択します`base = v XOR X`したがって、新しい実際の値は次のようになります。`v`。 削除では、すべてのビット カウントからその妖精のベースが正確に削除されます。 ダンスが変わるだけ`X`、すべての現在の値を次から変換します。`base XOR X`の中へ`base XOR X XOR e`、まさに必要な新しい値です。 最後に、各ビットについて、XOR はすべてのビットを保持するか、すべてのビットを反転します。`cnt[k]`または`active - cnt[k]`そのビットを含む現在の値の正確な数を示します。 これらのビット寄与を合計すると、正確な合計が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

BITS = 30

def add_base(x, cnt, delta):
    for b in range(BITS):
        if (x >> b) & 1:
            cnt[b] += delta

def solve():
    n, q = map(int, input().split())
    initial = list(map(int, input().split()))

    # base[id] is the value that must be XORed with global_x
    # to obtain the fairy's current value.
    base = [0] * (n + q + 1)

    # Number of active fairies whose base has each bit set.
    cnt = [0] * BITS

    global_x = 0
    active = n
    next_id = n + 1

    for i, x in enumerate(initial, 1):
        base[i] = x
        add_base(x, cnt, 1)

    out = []

    for _ in range(q):
        event = list(map(int, input().split()))
        t = event[0]

        if t == 1:
            v = event[1]

            # We need (base ^ global_x) == v.
            b = v ^ global_x

            base[next_id] = b
            add_base(b, cnt, 1)

            active += 1
            next_id += 1

        elif t == 2:
            p = event[1]
            b = base[p]

            add_base(b, cnt, -1)
            active -= 1

        else:
            e = event[1]
            global_x ^= e

        # Reconstruct the sum from the bit counts.
        ans = 0
        for b in range(BITS):
            ones = cnt[b]
            if (global_x >> b) & 1:
                ones = active - ones
            ans += ones << b

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`base`配列にはスペースがあります`n + q`識別子はせいぜい`q`新しい妖精が到着する可能性があり、到着するすべての妖精が新しい識別子を受け取ります。 配列にはフェアリー番号によって直接インデックスが付けられるため、削除は 30 ビットの更新とは別に一定時間行われます。 

の`add_base`ヘルパーは、1 つの基本値のすべてのビット カウンターを更新します。 と呼ばれます`delta = 1`妖精が入ってくると、`delta = -1`妖精が去ったとき。 ダンスが何回行われたかに関係なく、同じ表現が使用されます。 

挿入行`b = v ^ global_x`実装の最も微妙な部分です。 保管されたベースは意図的にそうではありません`v`。 現在の値は次のとおりである必要があるため、`b ^ global_x`、選択する`b = v ^ global_x`現在の値を正確に計算します`v`。 

A型`3`イベントは実行のみ`global_x ^= e`。 これは、ブルート フォース ソリューションの潜在的な二次関数の動作を排除する操作です。 すべての妖精は、変更された世界的価値観を通じて暗黙のうちにダンスを受け取ります。 

答えは 30 ビット カウンタから再構築されます。 ちょっとしたとき`global_x`がゼロの場合、そのビットが設定された塩基は設定されたままになります。 1 の場合、ビットが反転されるため、0 の基数が現在の基数になります。 表現`ones << b`と同等です`ones * 2^b`。 

Python ではオーバーフロー処理は必要ありません。 合計の最大値は、Python の任意精度の整数表現の範囲内に安全に収まります。

 |`4 4 / 7 7 7 7 / 3 7 / 3 1 / 2 2 / 1 7`|`0, 4, 3, 10`| すべて等しい値と繰り返されるグローバル XOR |
 |`2 5 / 1 1073741823 / ...`|`1073741822, 1073741823, 1073741822, 1073741823, 0`| 関連ビットの最大値と大きな合計 |
 | 生成された`n=q=100000`ケース |`100000`出力行 | イベント数と識別子の最大増加 |

 ## 特殊なケース

 以前のダンスの後に参加する妖精は、現在のグローバル XOR に対してベースを調整することで処理されます。 で```
1 3
5
3 7
1 2
3 1
```最初のダンスが変わる`global_x`に`7`。 値が`2`到着すると、そのベースは`2 XOR 7 = 5`。 現在の値はすぐに`5 XOR 7 = 2`、必要に応じて。 次のダンスは変わります`global_x`に`6`、新しい妖精は自動的に`5 XOR 6 = 3`。 出力シーケンス`2, 4, 5`新しい妖精が以前のダンスによって遡及的に影響を受けないことを確認します。 

削除は現在の値ではなくベースに基づいて行われるため、ダンス後の妖精の削除は機能します。 のために```
1 3
4
3 3
2 1
1 1
```オリジナルの妖精にはベースがあります`4`そして`global_x = 3`したがって、その現在の値は次のようになります。`7`。 削除するとbaseのビットが減算されます`4`から`cnt`、アクティブな妖精は残りません。 次の挿入は次のように行われます。`global_x = 3`、それで価値のある新しい妖精`1`ベースを取得します`1 XOR 3 = 2`。 現在の値は`2 XOR 3 = 1`、出力を生成します`7, 0, 1`。 

識別子の再利用は、次のメンテナンスによって回避されます。`next_id`アクティブな妖精の数とは関係ありません。 で```
1 4
10
2 1
1 5
2 2
```妖精`1`は削除されますが、新しい妖精が識別子を受け取ります`2`。 そのベースとなるのが、`5`、識別子の削除`2`その妖精を正しく削除します。 出力は次のとおりです。`0, 5, 0`。 無料の識別子を検索または再利用するソリューション`1`最終的な削除で間違った妖精が参照される可能性があります。 

空セット状態は削除後も有効です。 一度`active`がゼロになると、すべてのビットの現在の 1 カウントは、`global_x`、 なぜなら`active - cnt[k]`もゼロです。 後続の挿入は現在の挿入から開始されます。`global_x`そして正しい現在値を即座に再構築します。 

提供されるすべての値は最大でも次の値であるため、30 ビット境界は安全です。`10^9`、および以下の数値の XOR`2^30`以下にも残ります`2^30`。 ビット`0`を通して`29`したがって、十分です。 合計額はこれよりもはるかに大きくなる可能性があります`2^30`, ただし、Python の整数には任意の精度があるため、答えを直接計算しても安全です。
