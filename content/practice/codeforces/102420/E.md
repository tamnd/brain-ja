 ## 問題の理解

 (n) 人の木こりの順序付けられたシーケンスがあります。 木こり (i) は 1 つのインターバル ([l_i,r_i]) で作業し、そのインターバルでちょうど 0.5 メートルだけ壁を下げます。 選択した連続する木こりのグループ (a,a+1,\ldots,b) では、壁上のすべての座標での合計減少量が整数になる必要があります。 

すべての寄与は (0.5) であるため、重要なのはパリティだけです。 すべての座標で、その座標をカバーする選択された間隔の数は偶数である必要があります。 答えは、このパリティ条件を満たす木こりの連続する部分配列の数です。 

公式の制約では (n=200,000) が許可されていますが、コンテスト ページでは 2 秒の制限時間と 512 MB のメモリが与えられています。 (O(n^2)) 列挙は、最悪の場合、約 (n(n+1)/2)、おおよそ (2\cdot10^{10}) 個の部分配列チェックを実行します。 たとえ各小切手が非常に安価だったとしても、それは期限内に収まる金額をはるかに超えています。 線形または線形に近いアルゴリズムが必要です。 

座標は (-10^9) ほど小さくても (10^9) ほど大きくてもよいため、すべての整数座標を配列インデックスとして扱うことは不可能です。 重要なのは間隔の終点だけであり、最大 (2n) 個の関連座標が得られます。 

誤って対処しやすい特殊なケースがいくつかあります。 たとえば、木こり 1 人の場合、答えはゼロになります。```
1
1 2
```1 つの間隔は ([1,2]) の 0.5 メートルに寄与するため、それ自体で整数の変化を形成することはできません。 エンドポイントが異なるためにすべての間隔をカウントする実装は間違っています。 

2 番目のよくある間違いは、一連の間隔が完全にキャンセルされた場合に空の変更が許可されていることを忘れていることです。 例えば：```
2
1 3
1 3
```両方の木こりを選択すると ([1,3]) で正確に 1 メートル減少するため、答えは (1) です。 より一般的には、パリティだけを見ると、同一間隔はペアでキャンセルされます。 

負の座標も特別な処理なしで機能する必要があります。```
2
-5 -2
-5 -2
```やはり答えは(1)です。 座標による直接配列インデックス付けに基づく解決策は、座標圧縮を実行しない限り、ここでは失敗します。 

最後に、間隔が同一でなくても、間隔は別の間隔のエンドポイントと同じエンドポイントを持つことができます。 例えば：```
3
1 2
2 3
1 3
```答えは(1)です。 3 つの間隔は一緒になってパリティ レベルでキャンセルされますが、空ではない適切なプレフィックスはキャンセルされません。 間隔の長さだけ、または共有されるエンドポイントの数だけを考慮したソリューションでは、実際のパリティ構造が欠落します。 

## アプローチ

 直接的なアプローチは、すべてのペア ((a,b)) を調べることです。 選択したサブ配列ごとに、関連するすべての座標をカバーする選択した間隔の数を維持し、それらの数がすべて偶数であるかどうかを確認できます。 これは正しいです。物理的な状態では、0.5 メートルごとの寄与が偶数回発生するためです。 座標圧縮と効率的な更新を行ったとしても、(\Theta(n^2)) 個の可能な部分配列が存在します。 (n=200,000) の場合、それらは (20,000,100,000) 個あるため、2 次アプローチは実行できません。 

有益な観察は、区間内のすべての点ではなく、端点を通して区間を観察することによって得られます。 数直線に沿って歩くことを想像してください。 アクティブな間隔の数のパリティは、エンドポイントを通過すると正確に変化します。 間隔 ([l,r]) は、(l) でパリティを切り替え、(r) でパリティを戻します。 したがって、端点座標のセットを奇数の多重度で表す場合、区間は 2 つの座標 (l) と (r) を正確に切り替えることによって表されます。 

間隔のコレクションの場合、すべてのエンドポイント座標が偶数回出現する場合、最終的なカバレッジ パリティはどこでもゼロになります。 代数用語では、すべての区間は (\mathrm{GF}(2)) 上のベクトルであり、その 2 つの端点に (1) があり、これらすべてのベクトルの XOR が 0 である場合に、選択されたグループが正確に有効になります。 

次に、プレフィックス グループについて考えてみましょう。 (P_i) を木こり (1) から (i) までのエンドポイント ベクトルの XOR とし、(P_0=0) とします。 (a) から (b) までの区間は XOR されます。 

[
 P_b \oplus P_{a-1}。 
】

 この XOR は、まさに次の場合にゼロになります。 

[
 P_b=P_{a-1}。 
】

 したがって、元の問題はよく知られたプレフィックス状態カウント問題になります。木こりごとに状態を計算し、等しい状態を数えるというものです。 1 つの状態が (k) 回出現すると、次の出現により (k) 個の新しい有効な部分配列が作成されます。 

状態は実際には最大 (2n) 個の座標にわたるパリティ セットであるため、状態を文字通りに保存するとコストがかかりすぎます。 すべての座標にランダムな 128 ビットのフィンガープリントを与え、エンドポイントのフィンガープリントの XOR を与えることができます。 2 つの独立した 64 ビット コンポーネントでは、等しいパリティ セットは常に等しいフィンガープリントを生成しますが、2 つの異なるパリティ セットが衝突する確率は無視できます。 新鮮なランダム シードを使用すると、衝突を引き起こすために入力データを特別に構築することが非現実的になります。 

ブルートフォース手法は、すべての間隔グループを明示的にチェックするため機能しますが、二次関数的に多くのグループがあるため失敗します。 パリティの目的で、間隔がその 2 つのエンドポイントによって完全に特徴づけられるという観察により、すべてのグループをプレフィックス XOR 比較に変換し、タスク全体をハッシュ マップを使用した 1 つのパスに減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) またはそれ以上 | (O(n)) | 遅すぎる |
 | 128 ビットのフィンガープリントを使用したプレフィックス XOR | (O(n)) が期待されます | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての座標に、2 つの独立した 64 ビット整数として表されるランダムな 128 ビット フィンガープリントを割り当てます。 同じ座標は常に同じペアを受け取る必要がありますが、異なる座標はほぼ確実に異なるフィンガープリントを受け取る必要があります。 
2. プレフィックス状態 ((0,0)) から開始します。 これは木こりの空のコレクションを表します。 この状態をカウント (1) の周波数マップに入れます。これは、それと等しい以降のすべてのプレフィックスが木こり (1) から始まる有効な部分配列を形成するためです。 
3. 木こりを左から右に処理します。 間隔 ([l_i,r_i]) の場合、(l_i) のフィンガープリントと (r_i) のフィンガープリントを現在のプレフィックス状態に XOR します。 間隔によって開始時と終了時にアクティブ カバレッジ パリティが変更されるため、両方のエンドポイントが切り替わります。 
4. 周波数マップで新しいプレフィックス状態を検索します。 以前に (k) 回出現した場合は、答えに (k) を追加します。 以前の各出現は、(P_j=P_i) を持つプレフィックス (P_j) に対応し、その結果、木こり (j+1,\ldots,i) の XOR はゼロになります。 
5. 現在の状態の頻度を増やします。 この状態を使用して、後の位置で終わる有効な部分配列を形成できるようになりました。 
6. すべて (n) 個の木こりの処理が完了したら、蓄積された答えを出力します。 

### なぜ効果があるのか

 すべての座標 (x) について、選択したカバレッジのパリティは、間隔が (x) で開始または終了する場合にのみ変更されます。 したがって、間隔は、各エンドポイントに 1 つずつ、正確に 2 つのパリティ トグルに寄与します。 間隔のグループは、すべての座標が偶数回トグルされると、正確にどこでも整数の高さが変化します。これは、まさにそれらの終点ベクトルの XOR が 0 になるときです。 

プレフィックス状態 (P_i) には、最初の (i) 間隔の XOR が格納されます。 部分配列 (a,\ldots,b) は、(P_{a-1}\oplus P_b=0) の場合、または同等の場合 (P_{a-1}=P_b) にエンドポイント パリティがゼロになります。 頻度マップは、(a-1) の選択肢の数がこの等価性を与えるものを正確に数えます。 したがって、有効なサブ配列はすべて 1 回カウントされ、無効なサブ配列はカウントされません。 

唯一の近似は、完全なパリティ ベクトルをランダムな 128 ビット フィンガープリントで置き換えることです。 2 つの異なるパリティ ベクトル間の衝突により、理論的には誤った答えが生成される可能性がありますが、2 つの独立した 64 ビット値を使用すると、この入力サイズでは確率は無視できます。 

## Python ソリューション```python
import sys
import random

input = sys.stdin.readline

MASK = (1 << 64) - 1
SM_CONST = 0x9E3779B97F4A7C15

def splitmix64(x):
    x = (x + SM_CONST) & MASK
    x = (x ^ (x >> 30)) * 0xBF58476D1CE4E5B9 & MASK
    x = (x ^ (x >> 27)) * 0x94D049BB133111EB & MASK
    return (x ^ (x >> 31)) & MASK

def solve():
    n = int(input())

    seed1 = random.SystemRandom().getrandbits(64)
    seed2 = random.SystemRandom().getrandbits(64)

    state1 = 0
    state2 = 0

    freq = {(0, 0): 1}
    answer = 0

    def fingerprint(x):
        # x is allowed to be negative, so normalize it to 64 bits.
        ux = x & MASK
        h1 = splitmix64(ux ^ seed1)
        h2 = splitmix64(ux ^ seed2)
        return h1, h2

    for _ in range(n):
        l, r = map(int, input().split())

        l1, l2 = fingerprint(l)
        r1, r2 = fingerprint(r)

        state1 ^= l1 ^ r1
        state2 ^= l2 ^ r2

        state = (state1, state2)
        answer += freq.get(state, 0)
        freq[state] = freq.get(state, 0) + 1

    print(answer)

if __name__ == "__main__":
    solve()
```の`splitmix64`関数は、座標をよく混合された 64 ビット値に変換します。 2 つの独立したシードは 2 つの独立したフィンガープリントを生成し、プレフィックス状態に合計 128 ビットを与えます。 の使用`& MASK`Python の整数は自然には 64 ビットでラップされないのに対し、混合関数は符号なし 64 ビット演算で定義されているため、これが必要です。 

プレフィックス状態は 0 から始まり、次のように挿入されます。`freq`間隔を処理する前に。 その最初の出現は (P_0) を表し、これは木こり (1) で始まる部分配列に必要です。 それを忘れると、有効なプレフィックスがすべて失われます。 

コードは間隔ごとに、両方のエンドポイントのフィンガープリントを状態に XOR します。 XOR はまさにパリティに必要な演算です。同じ座標を 2 回適用すると、(x\oplus x=0) であるためキャンセルされます。 2 つのエンドポイント更新の順序は重要ではありません。 

現在の状態の頻度を増やす前に、答えが更新されます。 これにより、マップは以前のプレフィックスのみを表すようになります。 最初に現在の状態を追加すると、選択肢 (a\le b) にない長さ 0 の部分配列が誤って許可されてしまいます。 

Python の整数は任意の精度を持ちますが、すべてのフィンガープリント演算は内部で明示的に 64 ビットに削減されます。`splitmix64`。 最終的な答え自体は、(n(n+1)/2) (2\cdot10^{10}) 程度の大きさになる可能性があり、Python が直接処理します。 

## 実用的な例

 サンプル 1 の場合、間隔は ([1,3])、([2,3])、([2,3])、および ([1,3]) です。 座標 (x) のフィンガープリントを (A_x) と書くことができます。 プレフィックスの状態は、これらのフィンガープリントの XOR として記号的に表されます。 

| 私 | 間隔 | プレフィックスの状態 | 以前の等しい状態 | 答え |
 | --- | --- | --- | --- | --- |
 | 0 | なし | (0) | 1 | 0 |
 | 1 | ([1,3]) | (A_1\oplus A_3) | 0 | 0 |
 | 2 | ([2,3]) | (A_1\oplus A_2) | 0 | 0 |
 | 3 | ([2,3]) | (A_1\oplus A_3) | 1 | 1 |
 | 4 | ([1,3]) | (0) | 1 | 2 |

 (i=3) では、状態は最初の木こりの後の状態と等しいため、木こり (2) から (3) までが有効なグループを形成します。 (i=4) では、状態はゼロに戻り、空のプレフィックスと一致するため、4 人の木こり全員が別の有効なグループを形成します。 答えは(2)です。 

サンプル 2 の場合、間隔は ([1,2])、([2,3])、および ([1,3]) です。 

| 私 | 間隔 | プレフィックスの状態 | 以前の等しい状態 | 答え |
 | --- | --- | --- | --- | --- |
 | 0 | なし | (0) | 1 | 0 |
 | 1 | ([1,2]) | (A_1\oplus A_2) | 0 | 0 |
 | 2 | ([2,3]) | (A_1\oplus A_3) | 0 | 0 |
 | 3 | ([1,3]) | (0) | 1 | 1 |

 完全なシーケンスのみが初期状態に戻ります。 その 3 つの間隔にはエンドポイント マルチセット (1,2,2,3,1,3) があるため、すべての座標が正確に 2 回出現します。 答えは(1)です。
