 ## 問題の理解

 2 つの正の整数があります。`a`そして`b`、10 進数の文字列として与えられ、以下のすべての整数を考慮します。`a`を通して`b`。 これらすべてを掛け合わせて、結果の数値を 1 桁だけが残るまで 10 進数の合計で繰り返し置き換えます。 必要な出力は最後の 1 桁です。 

重要な難点は、`a`そして`b`最大 100,000 桁を含めることができます。 プロダクトを構築することはできず、エンドポイントを通常のマシン整数に安全に変換することさえできません。 ソリューションは、指定された算術を文字通りに実行するのではなく、10 進表現を直接操作し、最後の桁のプロパティを利用する必要があります。 

繰り返された数字の合計がデジタルルートです。 すべての正の整数に対して`x`、そのデジタル ルートは完全に次のように決定されます。`x mod 9`: 剰余がゼロ以外の場合、答えはその剰余であり、剰余ゼロはその数字に対応します。`9`。 したがって、巨大な積はモジュロのみを意味します`9`。 

一般に誤った解決策を引き起こすエッジケースが 2 つあります。 まず、積は次のように割り切れます。`9`、余りを与える`0`、ただし最後の桁は`9`、 ない`0`。 たとえば、入力の場合`9`そして`9`、製品は`9`、したがって、答えは次のとおりです`9`。 印刷するだけのソリューション`product % 9`印刷するだろう`0`。 

第 2 に、エンドポイントが巨大な 10 進数文字列であっても、間隔が巨大になる可能性があります。 例えば、`1`そして`100000000000000000000000000000`要素が多すぎて列挙できない区間を表します。 すべての整数を乗算しようとするソリューションは単に遅いだけでなく、入力サイズと根本的に互換性がありません。 

連続する差異が 5 つ以下である間隔の周囲に便利な境界もあります。 例えば、`1`を通して`5`与える`120`、そのデジタル ルートは`3`、 その間`1`を通して`6`与える`720`、そのデジタル ルートは`9`。 この遷移は、6 つの連続する整数には必ず次の 2 つの倍数が含まれるために発生します。`3`で製品を割り切れるようにします。`9`。

 ## アルゴリズムのチュートリアル

 1.読む`a`そして`b`文字列として。 どちらのエンドポイントにも 100,000 桁がある可能性があるため、意図的に文字列として保持します。 
2. コンピューティング`a mod 9`その桁をスキャンして残りを累積することによって。 これが可能なのは、10 進数が次の条件を満たすためです。`10 ≡ 1 (mod 9)`, したがって、数値全体はその桁の合計と一致します。 
3. かどうかを確認します。`b >= a + 5`。 計算できます`a + 5`通常の 10 進数文字列加算を使用して、次と比較します。`b`。 この条件が当てはまる場合、間隔には少なくとも 6 つの整数が含まれるため、少なくとも 2 つの倍数が含まれます。`3`。 彼らの積は次のように割り切れます。`9`、最後のデジタルルートは次のとおりです。`9`。 
4. もし`b < a + 5`、間隔には最大 5 つの整数が含まれます。 正確な違いを見つけてください`d`構築することによって`a`、`a + 1`、...、`a + 4`10 進数の文字列としてそれらを比較する`b`。 以来`a <= b`、これらの値の正確に 1 つが等しくなければなりません`b`。 
5. 次の剰余を乗算します。`a, a + 1, ..., a + d`モジュロ`9`。 なぜなら`d <= 4`、これは最大 5 つの剰余乗算です。 
6. 得られた剰余をデジタルルートに変換します。 からの残り`1`を通して`8`はすでに答えです。 残りの`0`積が次の正の倍数であることを意味します`9`、したがって、答えは次のとおりです`9`。 

機能する理由: アルゴリズム全体を通じて、製品から破棄される情報は、そのデジタル ルートに影響を与えない情報だけです。 合同モジュロ`9`は乗算によって保存されるため、剰余の積は真の積とまったく同じ剰余になります。 少なくとも 6 つの数値の間隔の場合、積には必ず次で割り切れる 2 つの因数が含まれます。`3`, したがって、その剰余はゼロであることが保証されます。 短い間隔の場合、すべての因子の剰余を明示的に乗算します。 したがって、すべての可能な間隔は正確なモジュロによって処理されます。`9`計算、および剰余ゼロから次への最終変換`9`反復された桁の合計の結果を正確に返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def add_small(s, x):
    """Return the decimal string representing int(s) + x, where x <= 5."""
    digits = list(s)
    i = len(digits) - 1
    carry = x

    while i >= 0 and carry:
        value = (ord(digits[i]) - 48) + carry
        digits[i] = chr(value % 10 + 48)
        carry = value // 10
        i -= 1

    if carry:
        digits.insert(0, chr(carry + 48))

    return ''.join(digits)

def mod9(s):
    r = 0
    for ch in s:
        r = (r + ord(ch) - 48) % 9
    return r

def solve():
    a = input().strip()
    b = input().strip()

    # Six consecutive integers contain two multiples of 3,
    # so their product is divisible by 9.
    if b >= add_small(a, 5):
        print(9)
        return

    # Here b - a <= 4, so we can find the exact difference
    # by checking only five possibilities.
    diff = 0
    for d in range(5):
        if add_small(a, d) == b:
            diff = d
            break

    result = 1
    current_mod = mod9(a)

    for d in range(diff + 1):
        result = (result * ((current_mod + d) % 9)) % 9

    print(9 if result == 0 else result)

solve()
```の`mod9`関数は中央監視を実装します。 文字列で表される巨大な整数を構築することはありません。 各桁は独立して処理でき、剰余は常に次の値の間に留まります。`0`そして`8`。 

の`add_small`関数は次の値でのみ使用されます。`0`を通して`5`。 通常の 10 進加算を右から左に実行するため、100,000 桁のエンドポイントでも整数変換なしで処理されます。 キャリーは文字列全体に伝播する可能性があるため、その間ループを続行する必要があります。`carry`ゼロ以外です。 たとえば、追加`5`に`999`正しく生成する`1004`。 

比較`b >= add_small(a, 5)`計算を行わずに大きな間隔のケースを処理します`b - a`。 入力文字列には先行ゼロがないため、長さが異なる場合、または長さが等しい場合には、通常の辞書編集的な比較で十分です。 

間隔に含まれる数値が最大 5 つであることが判明すると、ループは一般的な大きな減算を計算しようとするのではなく、正確なエンドポイントをチェックします。 これは数学的限界を意図的に使用したものです。候補は 5 つしかないため、一定数の文字列操作で十分です。 

乗算ループは次を使用します。`(current_mod + d) % 9`連続した値の場合。 追加してから`d`の残りに`a`の残差を与える`a + d`モジュロ`9`、実際の大きな整数が存在する必要はありません。 

Python の任意精度の整数は、ここで使用されている小さなモジュロ値ではオーバーフローしませんが、100,000 桁の 10 進数文字列を解析するには Python に依存します。`int()`は不要であり、Python の 10 進数変換の制限に達する可能性もあります。 エンドポイントを文字列として保持すると、この問題は完全に回避されます。
