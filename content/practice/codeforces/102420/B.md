 ## 問題の理解

 У нас есть дерево из`n`きょう。 В каждой комнате находится один эльф с силой`w[i]`。 Нужно выбрать хотя бы две комнаты так、чтобы выбранные комнаты образовывали связное поддерево. Среди всех таких групп требуется найти максимальное среднее значение сил.

 Связность здесь существенно ограничивает выбор. Если выбраны две комнаты, то все версоины на пути между ними тоже обязаны быть выбраны. При этом выбранная группа может состоять из двух соседних версин, из длинного пути, из верлины с несколькими あなたのことを忘れないでください。`n`ビデオ`200000`、поэтому перебор всех групп невозможен。 Уже на простой цепочке число связных групп размера хотя бы два равно

 [
 \frac{n(n-1)}2.
 】

 При`n = 200000`୨୧`19 999 900 000`だ。 何かが起こったら、それを忘れないでください。 Значит, алгоритм должен работать почти линейно на каждой проверке, а само число проверок должно быть ね。 

Силы лежат от`0`до`10^9`、поэтому ответ также лежит в этом диапазоне。 Требуемая точность`10^-6`естественно подсказывает двоичный поиск по вещественному ответу. При примерно 60 итерациях интервал длиной`10^9`よろしくお願いします`10^-9`、чего с бользим запасом хватает для требуемой точности.

 Есть несколько случаев, в которых наивная логика легко ломается. Во-первых, нельзя разрезить группу из одной версины. Например、```
2
100 0
1 2
```Единственная допустимая группа состоит из двух эльфов, поэтому ответ равен`50`。 Если при проверке некоторого значения просто искать связное множество с положительной преобразованной суммой, одна версина веса`100`может осибочно объявить значение`75`достижимым。 

Во-вторых、нельзя просто взять две самые сильные версины。 Например、```
4
10 0 0 10
1 2
2 3
3 4
```いいえ、`10`必要に応じて、必要な情報を入力してください。 Максимальное допустимое среднее равно`5`、 например для группы`{1,2}`とか`{3,4}`。 Ответ`10`был бы осибкой。 

Наконец、оптимальная группа не обязана состоять из двух версин. Например、```
4
0 10 10 10
1 2
1 3
1 4
```Любая пара соседних верзин имеет среднее`5`、 но группа из всех четырех верзин имеет среднее`7.5`。 Значит、проверка только рёбер тоже недостаточна。 

## アプローチ

 Самый прямой способ заключается в переборе всех связных групп, вычислении суммы их сил и делении на размер ゴージャス。 На цепочке число кандидатов уже равно`n(n-1)/2`、 то есть при`n = 200000`ジャンク`2 * 10^10`。 Если для каждой группы ещё отдельно искать сумму, работа становится ещё бользе. Для общего дерева число связных групп может быть экспоненциальным, поэтому такой подход не просто медленный, он принципиально не масboltабируется.

 Нужно убрать среднее из задачи. Предположим, что мы хотим проверить, существует ли группа со средним не меньзе некоторого числа`x`。 歌詞の意味: ロシア語`S`そうですね

 [
 \frac{\sum_{v\in S} w_v}{|S|} > x
 】

 тогда и только тогда, когда

 [
 \sum_{v\in S}(w_v-x)>0。 
】

 Значит, для фиксированного`x`можно заменить силу каждой версины на

 [
 a_v=w_v-x
 】

 искать связное множество размера хотя бы два с положительной суммой.

 Теперь задача стала обычной задачей о максимальной сумме связного поддерева, но с дополнительным условием ぱっつん。 На дереве такую задачу резает динамика снизу вверх.

 Зафиксируем корень дерева。 Пусть`dp[u]`означает максимальную сумму связного множества, которое содержит`u`и целиком лежит в поддереве`u`。 Если мы уже посчитали значение для сына`v`、то его можно присоединить к`u`、только если`dp[v]`そうです。 Если оно отрицательно、добавление этой ветки только ухудлит сумму.

 Получаем

 [
 dp[u]=a_u+\sum_{v\text{ }u}\max(0,dp[v]) の子。 
】

 Но здесь появляется тонкость。`dp[u]`メッセージを送信してください。 問題は、それが原因です。 Поэтому отдельно рассматриваем лучзий вариант, который обязательно присоединяет хотя бы одного сына.

 ああ`u`есть сын с неотрицательным`dp`、カク`u`можно присоединить все положительные сыновья и хотя бы одного сына с нулевым значением. Если все значения отрицательны, никакого допустимого множества с положительной суммой через`u`ありがとうございます。 

Таким образом, одна проверка выполняется за`O(n)`。 Само условие достижимости монотонно: если существует группа со средним бользе`x`、то она существует и для любого меньзего значения。 Это позволяет использовать двоичный поиск。

 ## アルゴリズムのチュートリアル

 1. ロシア語`1`и один раз строим массив`parent`と порядок обхода`order`。 Используем итеративный обход, потому что при`n = 200000`DFS と Python を組み合わせて使用​​できます。 
2. Аля текущего кандидата`x`заменяем мысленно вес каждой верлены на`w[u] - x`。 Нала задача теперь состоит в том, чтобы найти связную группу из хотя бы двух вер程ин с суммой бользе нуля.
 3. Обрабатываем верзины в обратном порядке`order`、то есть сначала листья、затем их родителей。 ждля каждой верзины вычисляем

 [
 dp[u]=(w[u]-x)+\sum_{\text{子}v}\max(0,dp[v])。 
】

 Положительная ветка полезна, отрицательная нет, поэтому отрицательные значения никогда не присоединяются.
 4. Одновременно запоминаем максимальное`dp[v]`最高です。 Если хотя бы один сын имеет`dp[v] >= 0`、можно построить допустимое множество, содержащее`u`и этого сына。 При этом все остальные положительные ветки тоже выгодно добавить. Если сумма положительных веток равна нулю, но лучлий сын имеет значение ноль, всё равно его нужно добавить, поскольку это увеличивает размер группы с одного до двух, не меняя сумму.
 5. Если для некоторой верслины полученная сумма допустимого множества бользе нуля, проверка для`x`और देखें`True`。 Это означает, что существует группа со средним бользе`x`。 
6. Выполняем двоичный поиск между минимальной и максимальной силой. Если проверка успегаем левую границу вверх, иначе двигаем правую границу вниз. После 60 итераций левая граница достаточно близка к настоящему ответу.

 ### なぜ効果があるのか

 Рассмотрим любую допустимую группу. После фиксации корня у неё существует единственная верзина`u`、ближайзая к корню дерева。 Все остальные верзины группы лежат в отдельных дочерних поддеревьях`u`、причём внутри каждого выбранного дочернего поддерева группа обязана быть связной и содержать соответствующего сына。 Именно такие варианты описывает`dp[v]`。 あなたの人生は、あなたの人生を変えることを意味します。 

Чтобы группа содержала хотя бы две верзины, для некоторой версины`u`должен быть выбран хотя бы один сын. Проверка явно требует такого сына, поэтому одиночная вер程ина никогда не считается допустимой. Следовательно、проверка возвращает`True`тогда и только тогда, когда существует допустимая группа с положительной суммой`w[v]-x`、 а это эквивалентно существованию группы со средним бользе`x`。 Монотонность этого условия делает двоичный поиск корректным.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    w = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append(b)
        g[b].append(a)

    parent = [-1] * n
    parent[0] = n
    order = [0]

    for u in order:
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            order.append(v)

    dp = [0.0] * n

    def possible(x):
        for u in reversed(order):
            base = w[u] - x
            positive_sum = 0.0
            max_child = -float("inf")

            for v in g[u]:
                if parent[v] != u:
                    continue

                value = dp[v]

                if value > 0.0:
                    positive_sum += value

                if value > max_child:
                    max_child = value

            dp[u] = base + positive_sum

            if max_child >= 0.0:
                candidate = base + positive_sum
                if candidate > 0.0:
                    return True

        return False

    lo = float(min(w))
    hi = float(max(w))

    for _ in range(60):
        mid = (lo + hi) / 2.0
        if possible(mid):
            lo = mid
        else:
            hi = mid

    print(f"{lo:.15f}")

if __name__ == "__main__":
    solve()
```Сначала строится обычное неориентированное представление дерева. Затем`parent`や`order`Созволяют получить направление от корня к листьям без рекурсии. Массив`order`имеет свойство、что при проходе справа налево дети уже обработаны до своего родителя.

 Внутри`possible`テスト`dp[u]`хранит лучзую сумму для связного множества, содержащего`u`、без требования размера хотя бы два. Именно это значение нужно родителю, потому что родитель может захотеть присоединить только одного сына или Пообще не присоединять его`positive_sum`содержит сумму всех положительных`dp`детей。`max_child`нужен именно для ограничения размера. Если все дети отрицательны, версина`u`может дать только одноэлементную группу, и она не должна влиять на ответ. Если существует ребёнок с нулевым`dp`、 его тоже можно присоединить, поэтому проверяется`max_child >= 0.0`、 не только`max_child > 0.0`。 

Нижняя граница двоичного поиска равна минимальному весу. Любая пара соседних вер程ин имеет среднее не минимального веса, поэтому настоящий ответ не ниже этой ゴー。 Верхняя граница равна максимальному весу, поскольку среднее не может быть бользе максимального элемента.

 Используются 60 итераций。 Этого достаточно даже для диапазона`10^9`、 поскольку после 60 делений пополам его длина становится примерно`8.7 * 10^-10`。 Python は、 числа двойной точности、чего достаточно для требуемой абсолютной или относительной погрезности です。

 ## DP の詳細を修正

 Чтобы избежать указанной ловузки, введём ещё одно значение`best2[u]`。 Оно означает максимальную сумму связного множества, которое содержит`u`и содержит хотя бы одного ребёнка`u`。 

ああ`dp[u]`結果:

 [
 dp[u]=a_u+\sum_v\max(0,dp[v])。 
】

 ああ`best2[u]`Можно взять все положительные ветви. Если среди них есть хотя бы одна, этого уже достаточно для размера хотя бы два. Если положительных ветвей нет, всё равно нужно выбрать лучзего ребёнка, даже если его`dp`отрицателен:

 a_u+
 \begin{ケース}
 \sum_v\max(0,dp[v]), & \text{если существует }dp[v]>0,\
 \max_v dp[v]、& \text{иначе}。 
\end{件}
 】

 Именно`best2[u] > 0`Сляется правильным условием успеха.

 Следовательно, приведённый выbolе код должен использовать`max_child`あなたのことを考えてください`max_child >= 0`。 Нужно проверять и отрицательного ребёнка, если положительных детей нет. Ниже находится окончательная версия резения。

                    positive_sum += value

                    best_with_child = base + max_child

```Ключевое исправление находится вычислении`best_with_child`。 Если существует положительная дочерняя ветка, мы берём все положительная дочерняя ветки. Если положительных веток нет, мы обязаны выбрать хотя бы одну, и тогда оптимальным выбором является ребёнок с メッセージ`dp`、даже если это значение отрицательное。 

Это особенно важно на цепочке`7, 1, 7`。 При проверке значения чуть меньзе`5`группа из всех трёх верзин положительна после преобразования, хотя промежуточная динамика для версины`2`остаётся отрицательной。 Если разрезать только положительные дочерние`dp`、такая группа была бы потеряна。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(n log(10^9 / eps))`| Каждая из 60 итераций двоичного поиска делает один проход по всем верзинам и рёбрам |
 | スペース |`O(n)`| Дерево、родители、порядок обхода и массив DP занимают линейную память |

 При`n = 200000`60 メートルの距離にあります。 Это около нескольких десятков миллионов простых операций по рёбрам, что существенно меньзе квадратичного ぱっとん`10^10`だ。 Итеративный обход также позволяет безопасно работать с деревом, являющимся длинной цепочкой.

 ## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    w = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append(b)
        g[b].append(a)

    parent = [-1] * n
    parent[0] = n
    order = [0]

    for u in order:
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            order.append(v)

    dp = [0.0] * n

    def possible(x):
        for u in reversed(order):
            base = w[u] - x
            positive_sum = 0.0
            max_child = -float("inf")

            for v in g[u]:
                if parent[v] != u:
                    continue

                value = dp[v]

                if value > 0.0:
                    positive_sum += value

                if value > max_child:
                    max_child = value

            dp[u] = base + positive_sum

            if max_child != -float("inf"):
                if positive_sum > 0.0:
                    best_with_child = base + positive_sum
                else:
                    best_with_child = base + max_child

                if best_with_child > 0.0:
                    return True

        return False

    lo = float(min(w))
    hi = float(max(w))

    for _ in range(60):
        mid = (lo + hi) / 2.0
        if possible(mid):
            lo = mid
        else:
            hi = mid

    print(f"{lo:.15f}")

def run(inp: str) -> str:
    global_input = sys.stdin
    global_output = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = global_input
        sys.stdout = global_output

 ## 特殊なケース

 Случай с двумя верзинами проверяет сразу условие минимального размера группы. ああ、```
2
100 0
1 2
```やっぱ`x = 75`ジャンヌ・ダルク`25`や`-75`。 Для первой верзины её собственное`dp`положительно, но это одиночная версина, поэтому она не может дать`True`。 Чтобы получить допустимую группу, нужно добавить вторую верго сумма становится`-50`。 Проверка возвращает`False`、 а двоичный поиск сходится к`50`。 

Случай с несвязанными сильными показывает, почему DP должно учитывать структуру дерева. ああ```
4
10 0 0 10
1 2
2 3
3 4
```और देखें`1`や`4`ありがとうございます`10`、но между ними находятся две вер程ины нулевого веса。 Группа`{1,4}`ね。 Максимум достигается на группе`{1,2}`とか`{3,4}`ああ`5`。 DP автоматически учитывает промежуточные версвины, потому что любое выбранное множество строится из связных дочерних поддеревьев。 

Случай、где оптимальная группа больbolе двух вербин、особенно хорость проверяет корректность динамики。 ああ```
4
0 10 10 10
1 2
1 3
1 4
```каждое отдельное ребро имеет среднее`5`、 но вся группа имеет сумму`30`と、`4`、 то есть среднее`7.5`。 При проверке`x < 7.5`ビデオを見て、DP を確認してください。`1`присоединяет их одновременно。 Это показывает, почему нельзя ограничиваться выбором одной лучзей дочерней ветки.

 Наконец、значение`dp`ребёнка может быть отрицательным, хотя этот ребёнок всё равно обязан быть выбран для получения группы さあ、これで終わりです。 Именно это происходит в цепочке```
3
7 1 7
1 2
2 3
```やっぱ`x = 4.9`。 ロシア語`2`значение равно`-1.8`、 、 потому что`1 - 4.9 + (7 - 4.9) = -1.8`。 Но версина`1`имеет преобразованный вес`2.1`、 поэтому группа`{1,2,3}`имеет суммарный преобразованный вес`0.3`и действительно улучзает ответ относительно`4.9`。 Отдельное хранение`dp`и лучзего варианта с обязательным ребёнком позволяет не потерять такие группы.
