 ## 解決策
 ## 問題の理解

 (n) 人のハンターがおり、各ハンターは平面上の異なる点 ((x_i,y_i)) を占めます。 位置が 1 つの直線上にない 3 人の異なるハンターを選択する必要があります。 そのようなトリプルが存在する場合、次のように出力します。`Yes`およびそれらのインデックス。 すべてのハンターが同じ線上にある場合、次のように出力します。`No`。 

これら 2 つのケースの区別は幾何学的なものですが、整数演算で確認できます。 3 つの点 (A)、(B)、および (C) については、ベクトル (B-A) と (C-A) の外積がゼロの場合、それらは正確に同一直線上にあります。 

[
 (x_B-x_A)(y_C-y_A) - (y_B-y_A)(x_C-x_A)=0。 
】

 境界 (n\le 100000) では、すべてのトリプルのチェックが除外されます。 あります

 [
 \binom{100000}{3}\約 1.67\cdot 10^{14}
 】

 これは、競技プログラミングの制限時間で処理できる範囲をはるかに超えています。 線形または線形に近い解決策が必要です。 座標境界は (10^9) に達するため、外積の積は約 (4\cdot 10^{18}) に達し、差は (8\cdot 10^{18}) に近づく可能性があります。 Python の整数はこれらの値を正確に処理しますが、固定幅の 32 ビット整数ではひどいオーバーフローが発生します。 

最初の自明ではないケースは、有効な答えが存在するにもかかわらず、最初の 3 人のハンターが同一線上にある場合です。 例えば、```
4
0 0
1 1
2 2
0 1
```正しい出力は次のとおりです`Yes`、たとえばインデックスの場合`1 2 4`。 最初の 3 点のみをテストするメソッドでは、誤って出力されます。`No`。 

逆のケースは、すべての点が実際に 1 つの線上にある場合です。```
4
1 1
2 2
3 3
4 4
```正しい出力は次のとおりです`No`。 どのメソッドでも、不可能と宣言する前に、最初の 3 つを超えるポイントを検査できなければなりません。 

3 番目のケースは垂直線に関するものです。```
3
5 0
5 2
5 7
```正しい出力は次のとおりです`No`。 ((y_2-y_1)/(x_2-x_1)) などの傾きを計算すると、誤ってゼロ除算が発生する可能性があります。 外積にはそのような特殊なケースはなく、垂直線と水平線は同じように扱われます。 

## アプローチ

 直接総当たりソリューションでは、ハンターのすべてのトリプルが考慮され、その 3 つのポイントが同一線上にあるかどうかがチェックされます。 これは正しいです。考えられるすべての答えが明示的に検査されるからです。 問題はトリプルの数です。 (n=100000) の場合、それらは約 (1.67\cdot10^{14}) 個あるため、トリプルあたりの非常に少量の一定量の作業でも多すぎます。 

有益な観察は、最初の 2 人のハンターが異なるため、1 つの固有のラインを決定するということです。 有効な答えがあるとすれば、このラインの外側に 3 人目のハンターがいるはずです。 逆に、すべてのハンターがこの線上にある場合、考えられるすべてのトリプルは同一線上にあり、答えは不可能になります。 

つまり、トリプルを検索する必要はありません。 ハンター (1) と (2) を修正し、残りのハンターをすべてスキャンして、ライン上にあるかどうかをテストします。 直線上にない最初の点は、すぐに有効な答えを与えます。 スキャンが最後まで到達しても何も見つからなかった場合、すべてのハンターが同じ線上にあり、答えは次のようになります。`No`。 

トリプルをテストするとそのトリプルの質問に直接答えることができるため、総当たり法は機能しますが、トリプルが多すぎるため失敗します。 固定線観測により、問題は残りの点ごとに 1 つの共線性テストに減ります。

 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^3)) | (O(1)) | 遅すぎる |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべて (n) 個のポイントを元の 1 から始まるインデックスと一緒に読み取ります。 出力には座標だけでなくインデックスも必要です。 
2. 最初の 2 点を (A=(x_1,y_1)) および (B=(x_2,y_2)) として取得します。 このステートメントでは、2 人のハンターが同じポイントを占有しないことが保証されているため、これら 2 つのポイントが一意のラインを定義します。 
3. 3 番目の点から始まるすべての点 (C=(x_i,y_i)) について、計算します。 

[
 クロス=(x_2-x_1)(y_i-y_1)-(y_2-y_1)(x_i-x_1)。 
]

もし`cross != 0`、3 つの点 (A、B、C) は同一線上にないため、すぐに出力します。`Yes`およびそれらのインデックス。 

1. 残りのポイントがすべて残っている場合`cross == 0`、すべてのハンターは最初の 2 人のハンターを通過する線上にあります。 その場合、3 人のハンターは非縮退三角形を形成できないため、次のように出力します。`No`。 

最初の 2 点を通る線がアルゴリズム全体で固定されているため、スキャンは機能します。 非ゼロのクロス積は、現在の点がそのラインの外側にあることを証明し、ゼロのクロス積は、現在の点がライン上にあることを証明します。 

### なぜ効果があるのか

 不変条件は、最初の 2 点が常に基準線を定義することです。 スキャン中に、ある点がこれら 2 つの点とゼロ以外の外積をもつ場合、その点はその線の外側にあるため、選択された 3 つの点は同一直線上にあることができず、アルゴリズムは有効な答えを見つけたことになります。 

アルゴリズムがそのような点を見つけられなかった場合、すべての入力点は最初の 2 つの点との外積がゼロになります。 したがって、すべての点はその固有の線上にあります。 すべてのハンターが 1 つの線上にあるため、3 人のハンターの可能な選択肢はすべて同一線上にあります。`No`が唯一の正解です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    points = []

    for i in range(1, n + 1):
        x, y = map(int, input().split())
        points.append((x, y, i))

    x1, y1, i1 = points[0]
    x2, y2, i2 = points[1]

    dx = x2 - x1
    dy = y2 - y1

    for x, y, i in points[2:]:
        cross = dx * (y - y1) - dy * (x - x1)

        if cross != 0:
            print("Yes")
            print(i1, i2, i)
            return

    print("No")

if __name__ == "__main__":
    solve()
```入力ループは、各座標を元のインデックスとともに保存します。 これにより、後でインデックスを再構築する必要がなくなり、幾何学的計算が出力の番号付けから分離されます。 

2つの違い`dx`そして`dy`基準線は決して変更されないため、計算は 1 回だけ行われます。 それ以降の各点では、最初の点から現在の点までのベクトルのみが変化します。 

表現```
dx * (y - y1) - dy * (x - x1)
```は 2 次元の外積です。 その符号は、その点が基準線のどちら側にあるかを示しますが、この問題では、ゼロか非ゼロかだけが問題になります。 

分割がないため、縦線は特別な問題を引き起こしません。 Python の整数は、許容される最大の座標であってもオーバーフローを回避します。 に保存されているインデックス`points`はすでに 1 から始まり、必要な出力形式と一致しています。 

ループは次から始まります`points[2:]`最初の 2 人のハンターがすでに固定ペアとして使用されているためです。 格納されたインデックスは入力位置とまったく同じであるため、出力でのオフバイ 1 の問題は発生しません。

## テストケース

 このステートメントは、2 人のハンターが同じ点を占有しないことを保証するため、すべての座標ペアが同一であるリテラル入力は有効な入力領域の外になります。 以下のテスト スイートには、堅牢性チェックなどの入力が含まれています。 それをサポートするために有効なソリューションは必要ありませんが、実装は自然に次の結果を返します。`No`。 

アサート ヘルパーは標準出力をキャプチャしますが、チェッカーは 1 つの特定の有効なトリプルを必要とするのではなく、実際の幾何学的プロパティを検証します。 この問題では 3 つのインデックスの正しいセットが許容されるため、これが必要になります。```python
import sys
import io
import contextlib

def solve():
    input = sys.stdin.readline

    n = int(input())
    points = []

    for i in range(1, n + 1):
        x, y = map(int, input().split())
        points.append((x, y, i))

    x1, y1, i1 = points[0]
    x2, y2, i2 = points[1]

    dx = x2 - x1
    dy = y2 - y1

    for x, y, i in points[2:]:
        cross = dx * (y - y1) - dy * (x - x1)

        if cross != 0:
            print("Yes")
            print(i1, i2, i)
            return

    print("No")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    output = io.StringIO()
    try:
        with contextlib.redirect_stdout(output):
            solve()
    finally:
        sys.stdin = old_stdin

    return output.getvalue().strip()

def valid_answer(inp: str, out: str) -> bool:
    data = inp.strip().splitlines()
    n = int(data[0])
    points = [tuple(map(int, line.split())) for line in data[1:]]

    tokens = out.split()

    if tokens[0] == "No":
        x1, y1 = points[0]
        x2, y2 = points[1]

        for x, y in points[2:]:
            cross = (x2 - x1) * (y - y1) - (y2 - y1) * (x - x1)
            if cross != 0:
                return False

        return True

    assert tokens[0] == "Yes"
    a, b, c = map(int, tokens[1:4])
    assert 1 <= a <= n
    assert 1 <= b <= n
    assert 1 <= c <= n
    assert len({a, b, c}) == 3

    x1, y1 = points[a - 1]
    x2, y2 = points[b - 1]
    x3, y3 = points[c - 1]

    cross = (x2 - x1) * (y3 - y1) - (y2 - y1) * (x3 - x1)
    return cross != 0

# Sample 1

3
1 1
2 2
2 3
"""
assert run(sample1).startswith("Yes")
assert valid_answer(sample1, run(sample1)), "sample 1"

# Sample 2
sample2 = """\
5

0 0
3 6
4 8
4 4
"""
assert run(sample2).startswith("Yes")
assert valid_answer(sample2, run(sample2)), "sample 2"

# Sample 3
sample3 = """\
4

2 2
3 3
4 4
"""
assert run(sample3) == "No"
assert valid_answer(sample3, run(sample3)), "sample 3"

"""

1000000000 1000000000
1000000000 -1000000000

"""

"""

## 特殊なケース

```基準線は (y=x) です。 3 番目の点では外積 (0) が得られるため、スキャンは続行されます。 4 番目のポイントは、

 [
 1\cdot1-1\cdot0=1、
 】

 したがってアルゴリズムは次のように出力します`Yes`インデックス付き`1 2 4`。 これはまさに、単純な最初の 3 点の解決策を打ち破るケースです。 

すべての点が同一線上にある場合、たとえば```
4

4 4
```最初の 2 つの点は (y=x) を定義します。 後続の外積はすべてゼロになります。 ループは外側の点を見つけられずに終了するため、アルゴリズムは次のように出力します。`No`。 すべての点が同じラインに属しているため、代替トリプルが機能する可能性はありません。 

縦線の場合は、```
3
5 0
5 2
5 7
```最初の 2 つの (x) 座標の差はゼロです。 外積は引き続き直接機能します。 

[
 0\cdot(y-0)-2\cdot(5-5)=0。 
】
