 ## 問題の理解

 入力は、小文字と 3 つの構造文字のみを含む 1 つの文字列です。`<`、`>`そして`/`。 すべての文字を任意に並べ替えることはできますが、その多重度を変更することはできません。

任意の並べ替えを許可すると、元の位置がまったく問題にならないという重要な結果が得られます。 重要なのは文字数だけです。 次のようないくつかの独立したペアから構成される特に単純で有効な構造を選択できます。`<a></a><bc></bc>`。 元のネストを再作成する必要はありません。

## アプローチ

 直接的な総当たりアプローチでは、入力文字の順列を生成し、各順列が有効な XML 構造であるかどうかをテストします。 すべての文字が個別である場合、次のようになります。`n!`順列、および 1 つの順列のチェックには時間がかかります`O(n)`時間。 したがって、単純な検索には次のことが必要です`O(n · n!)`最悪の場合は動作します。 実際のアルファベットには 29 文字しか含まれていませんが、個別のマルチセット順列の数は依然として天文学的に多くなります。`n = 100000`。 ブルート フォースは、あらゆる可能な配置を明示的に探索するため機能しますが、その探索空間のほとんどすべてが無関係であるため、失敗します。 

有益な観察は、配置自体を私たちが選択できるということです。 あると仮定します`k`終了タグ。 それから、それもあるはずです`k`開始タグなので、最後の文字列には正確に次の文字列が含まれます。`k`の発生`/`、`k`の発生`<`、 そして`k`の発生`>`。 したがって、入力文字数は次の条件を満たす必要があります。`count('<') = count('>') = count('/')`。 

次に文字について考えてみましょう。 すべてのタグ名は、開始タグで 1 回、対応する終了タグで 1 回の合計 2 回使用されます。 したがって、完全な結果では、すべての文字が偶数回出現します。 この条件は文字の多重度についても十分です。なぜなら、すべての文字数を 2 で割った後、結果として得られるマルチセットを単純に複数の文字に分散できるからです。`k`タグ名。 

追加の要件が 1 つあります。すべてのタグ名が空であってはなりません。 あれば`k`タグペアには少なくとも必要です`k`文字のペア。つまり、文字の合計数は少なくとも`2k`。 

これらの条件が整えば、構築は簡単です。 すべての文字数の半分を取得し、それらの文字を連結してシーケンスにし、そのシーケンスを分割します。`k`空ではない名前と出力`<name></name>`それぞれの名前ごとに。 すべての文字が半分になるため、それぞれの名前を 2 回書くと、ちょうど元の文字数が消費されます。 

したがって、問題全体は、順列の検索から少数の文字数のチェックと 1 つの標準的な配置の構築へと縮小されます。

 ## アルゴリズムのチュートリアル

 1. 次の発生を数えます。`<`、`>`、`/`、およびすべての小文字。 任意の置換により入力からすべての位置制約が削除されるため、これらの多重度のみが必要になります。 
2. しましょう`k`の数になります`/`文字。 必要とする`count('<') = k`そして`count('>') = k`。 すべてのタグ ペアは 1 つだけ貢献します`<`、 1つ`>`、そして1つ`/`, したがって、これらの等式が必要です。 
3. 必須`k > 0`。 入力は空ではなく、有効な結果には空ではない名前のタグが含まれている必要があるため、タグのペアを含まない入力は有効な結果を生成できません。 
4. すべての小文字について、その数が偶数である必要があります。 タグ名内に出現する文字は、対応する開始タグと終了タグ内で同一に出現する必要があるため、すべての出現を同一のペアに分割できます。 
5. しましょう`pairs`文字ペアの合計数は、文字の合計数の半分になります。 必要とする`pairs >= k`。 それぞれの`k`タグ名には少なくとも 1 文字が必要なので、少なくとも`k`文字のペアが必要です。 
6. すべての文字の出現のちょうど半分を含むリストを作成します。 たとえば、元の文字列が 4 つある場合、`a`キャラクターと二人`c`文字、ハーフリストに含まれる文字`a, a, c`。 このリスト内のすべての文字は、開始タグと終了タグの両方にコピーされる 1 つの出現を表します。 
7. 最初の者にそれぞれ 1 文字を与えます。`k - 1`タグ名を入力し、残りの文字をすべて最後のタグ名に入力します。 これは正確に作成します`k`利用可能なすべての文字ペアを使用しながら、空ではない名前を使用します。 
8. 構築されたすべての名前について`x`、追加`<x></x>`答えに。 各ペアは、その名前に割り当てられた文字を正確に 2 回消費するため、完全な出力は入力の順列になります。 

### なぜ効果があるのか

 不変条件は、構築によって消費されるすべての文字が、入力内に存在する多重度で正確に消費されるということです。 構造文字は 1 つの文字のグループで使用されます。`<`、 1つ`>`、そして1つ`/`タグペアごとに。 まず文字が 2 で除算され、結果として得られるすべての名前が 2 回書かれるため、元のすべての文字数が正確に復元されます。 

生成されたすべてのコンポーネントには形式があります`<S></S>`空でないもの`S`。 このようなコンポーネントは有効な一致するタグのペアであり、有効な独立したペアを連結すると有効なブラケット シーケンスが得られます。 必要な条件には、構造上のカウントが間違っている、文字数が奇数である、または空ではない名前の必要な数に対して文字が少なすぎるなど、考えられるすべての障害も含まれています。 したがって、有効な順列が存在する場合、構築は正確に成功します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    angle_open = s.count('<')
    angle_close = s.count('>')
    slash = s.count('/')

    if angle_open != slash or angle_close != slash or slash == 0:
        print("Impossible")
        return

    freq = [0] * 26
    for ch in s:
        if 'a' <= ch <= 'z':
            freq[ord(ch) - ord('a')] += 1

    for c in freq:
        if c % 2:
            print("Impossible")
            return

    k = slash
    total_letters = sum(freq)

    if total_letters < 2 * k:
        print("Impossible")
        return

    half = []
    for i, c in enumerate(freq):
        half.extend([chr(ord('a') + i)] * (c // 2))

    names = []
    for i in range(k - 1):
        names.append(half[i])

    names.append(''.join(half[k - 1:]))

    answer = []
    for name in names:
        answer.append('<')
        answer.append(name)
        answer.append('></')
        answer.append(name)
        answer.append('>')

    print(''.join(answer))

if __name__ == "__main__":
    solve()

文字数はサイズ 26 の固定配列に保存されます。名前の実際のスペルは管理下にあるため、パリティをチェックするだけで十分です。 元の入力でどの文字が一緒に属しているかを調べる必要はありません。 

の`half`リストには、各タグ ペアの片側に表示される文字が正確に含まれています。 入力に次のものが含まれている場合`c`手紙のコピーを置きます`c / 2`にコピーします`half`。 構築されたすべての名前を 2 回書き込み、その後すべてを復元します`c`コピー。 

名前への分割では、最初のそれぞれに意図的に 1 文字が使用されます。`k - 1`名前。 姓の残りの文字。 先ほどの状態`total_letters >= 2 * k`姓も空でないことを保証します。 

構築が追加されます`<name></name>`ネストされたタグを配置するのではなく、直接。 これにより、スタック管理が完全に回避されます。 有効なタグ ペアのシーケンスは、すでに有効なバランス ブラケット シーケンスになっています。

    s = input().strip()

    angle_open = s.count('<')
    angle_close = s.count('>')

        return "Impossible"

        answer.append('></')
        answer.append(name)

    old_input = input
    stream = io.StringIO(inp)
    input = lambda: stream.readline()
    try:
        return solve()
    finally:
        input = old_input

のために`<ab></ac>`、すべての構造カウントは正しく、文字の合計数は 6 で偶数です。 しかし、`b`そして`c`それぞれ 1 回ずつ発生します。 文字ごとのパリティ ループは構築前にこれを検出し、次のような不正な結果を防ぎます。`<ab></ab>`間違った文字数を消費してしまいます。 

のために`<a>/a`、元の順序は無効に見えますが、並べ替えは許可されています。 カウントにより、1 つのタグ ペアと 1 つのタグ ペアが得られます。`a`ペアなので、その構造は`<a></a>`。 これは、ソリューションが元の文字列を XML として解析しない理由を示しています。 複数の文字セットのみが重要です。 

100,000 文字境界の場合でも、アルゴリズムは入力と出力に対して一定数のパスを実行します。 再帰的解析や二次検索は含まれないため、最大入力サイズによって、読み取って出力する必要があるデータ量を超えてアルゴリズムの動作が変更されることはありません。
