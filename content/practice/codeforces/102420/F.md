 ## 解決策
 ## 問題の理解

 (n) 個の物理キューブがあります。 各立方体は、その 6 つの面の 1 つに表示される任意の数字を表示できますが、立方体は一度に 1 つの数字しか表示できません。 数値を構築するために、Aurora は数値の桁数と同じ数の立方体を選択し、各桁の位置に 1 つの異なる立方体を割り当てます。 立方体は自由に並べ替えることができ、別の数値を作成するときに同じ立方体のコレクションを再利用できます。 

タスクは、そのような割り当てが不可能な最小の正の整数を見つけることです。 

立方体の有用な表現は、正確な 6 つの面ではなく、立方体上に現れる一連の個別の数字です。 立方体が言うなら`111234`、これは立方体が言うのと同じくらいこの問題に役立ちます。`112234`なぜなら、どちらも正確に数字 (1、2、3、4) を提供できるからです。 同じ立方体上の数字のコピーを繰り返しても、その数字のコピーが 2 つ得られることはありません。立方体は 1 つの位置のみを占めることができるためです。 

入力には最大 (100,000) 個の立方体が含まれており、各立方体を 6 桁で表します。 可能性のある数値を直接検索することは、この範囲によって完全に除外されます。 たとえ 1 つの数値のチェックが低コストだったとしても、最初の不可能な数値の前の候補の数は (n) で指数関数的に増加する可能性があります。 このソリューションでは、立方体を基本的に 1 回処理し、可能な桁数が 10 個しかないという事実を利用する必要があります。 

素朴なソリューションを静かに破壊する可能性のあるエッジケースがいくつかあります。 

まず、1 つの立方体上で繰り返される面を複数回カウントしてはなりません。 例えば、```
1
111111
```には、数字 (1) を表示できる立方体が 1 つだけあり、6 つの独立したコピーはありません。 数字 (2) は出現しないため、正解は次のようになります。`2`。 立方体ではなく面を数えると、(1) のコピーが多数存在すると誤って示唆されてしまいます。 

次に、最初の数字としてゼロを使用することはできません。 のために```
1
012345
```数字 (1、2、3、4、5) は作成できますが、数字 (6) は作成できないため、答えは次のようになります。`6`。 すべての桁を単純に対称的に扱う方法では、ゼロの不足が数値に与える影響は、ゼロ以外の桁の不足とは異なるため、注意が必要です。 

第三に、各桁に十分な立方体を個別に用意しても、2 つの桁の組み合わせが常に可能であるとは限りません。 考慮する```
2
012349
456788
```数字 (9) は 1 つのキューブ上に出現し、数字 (0) も 1 つのキューブ上、つまり同じキューブ上に出現します。 番号`9`可能です、そして`99`不可能ですが、数字が小さいほうが`90`(9) を表示できる単一の立方体は (0) を表示できる唯一の立方体でもあるため、すでに不可能です。 正しい答えは、`90`。 この共有キューブの状況は、最適なアルゴリズムによって検査する必要がある、異なる桁タイプ間の唯一の相互作用です。 

## アプローチ

 最も直接的なアプローチは、正の整数を昇順に列挙することです。 すべての候補について、左側がその桁の位置で構成され、右側が立方体で構成される 2 部グラフを作成します。 数字 (d) を含む位置を、少なくとも 1 つの面に (d) を持つすべての立方体に接続します。 このグラフにすべての桁位置をカバーする一致がある場合、候補は正確に構築可能です。 

マッチングとは、正確に数字の位置に個別の立方体を割り当てることなので、この強引な判断は正しいのです。 問題は候補者の数だ。 立方体あたり 6 つの面により、使用できる異なる桁の数が制限されますが、最初の不可能な数が (\Theta(n)) 桁を持つことは妨げられません。 たとえば、バランスの取れた構造では、ゼロ以外のすべての桁がおおよそ (2n/3) 個の立方体上に出現する可能性があるため、長さ約 (2n/3) の数値はすべて個別の桁数テストに耐えることができます。 それまでのすべての数値を列挙すると、(10^{2n/3}) 個の候補が存在することになります。 候補者ごとに (O(n)) 個のチェックを行うだけでも絶望的です。 

重要な観察は、実際には個々の番号をテストする必要がないということです。 (cnt[d]) を数字 (d) を含む立方体の数とします。各立方体はこの数に最大 1 回だけ寄与します。 

数値の長さが (k) であると仮定します。 すべての非ゼロの数字が少なくとも (k) 個の立方体で発生し、ゼロが少なくとも (k-1) 個の立方体で発生する場合、すべての (k) 桁の数値が構成可能です。 これは、桁の位置を 1 つずつ考慮することで直接確認できます。 要求された非ゼロの数字については、少なくとも (k) 個の可能なキューブが存在しますが、(k) 未満の位置ですでにキューブが消費されている可能性があります。 ゼロの場合、有効な (k) 桁の数値内のゼロ位置の最大数と正確に一致する、少なくとも (k-1) 個の可能な立方体が存在します。 

公式コンテストのチュートリアルでは、これと同じ削減を桁ごとの立方体の数に適用し、ゼロと最初の不十分な非ゼロ桁の間の 1 つの特別な相互作用を分離します。 

したがって、

 [
 L=\min\left(cnt[0]+2,\ \min_{d=1}^{9}(cnt[d]+1)\right)。 
】

 (L) 桁未満の数値はすべて構成可能ですが、(L) 桁の一部の数値は構成できません。 したがって、答えはちょうど (L) 桁になります。 

ゼロ項が (L) を決定する場合、多くのゼロを必要とする最小 (L) 桁の数値は次のようになります。 

[
 100\ldots0。 
】

 ゼロ以外の数字が (L) の原因である場合は、そのような最小の数字 (d) を選択します。 明らかに無理な候補は

 [
 ddd\ldots d.
 】

 これに勝てる初期の候補が 1 つあります。 

[
 d000\ldots0。 
】

 この候補には、(d) を含む 1 つの立方体と、ゼロを含む (L-1) 個の立方体が必要です。 興味深いケースでは、(cnt[d]) と (cnt[0]) は両方とも (L-1) に等しくなります。 (d) とゼロを含む立方体のセットが同一である場合、正確に失敗します。 両方の数字を含む立方体がいくつあるかを知る必要があるだけなので、(both[d]) を維持します。 もし

 [
 cnt[0]=cnt[d]=両方[d]=L-1、
 】

 それから`d000...0`不可能であり、それが答えです。 それ以外の場合は構築可能であり、`ddd...d`は最初の不可能な数です。

 ## アルゴリズムのチュートリアル

 1. すべての立方体を読み取り、その 6 つの面を 10 ビットのマスクに変換します。 ビットは、その数字が立方体上に表示されたときに正確に設定されます。 これにより、重複した面が自動的に削除されます。 
2. すべての数字 (d) について、ビット (d) が設定されている立方体の数を数えます。 この値を (cnt[d]) と呼びます。 同時に、ゼロ以外の数字 (d) ごとに、ゼロと (d) の両方を含む立方体の数を数え、結果を (both[d]) に保存します。 
3. コンピューティング

 [
 L=\min\left(cnt[0]+2,\ \min_{d=1}^{9}(cnt[d]+1)\right)。 
】

 (cnt[d]+1) という用語は、数字 (d) の (cnt[d]) 個のコピーが利用可能であることを示しているため、もう 1 つのコピーにはすでに多すぎる立方体が必要です。 最初の桁をゼロにすることはできないため、ゼロ項は 1 だけシフトされます。 

1. (L=cnt[0]+2)の場合、出力`1`(L-1) 個のゼロが続きます。 ゼロ対応キューブは (L-2) 個しかありませんが、この数には (L-1) 個のキューブが必要なので、不可能です。 これは長さの最小の数なので、すぐに答えになります。 
2. それ以外の場合は、(cnt[d]+1=L) を満たす最小の非ゼロ桁 (d) を見つけます。 すべての小さいゼロ以外の数字は少なくとも (L) 個の立方体で発生しますが、(d) は正確に (L-1) 個の立方体で発生します。 したがって、完全に (d) からなる数は不可能です。 
3. かどうかを確認します。`d000...0`不可能です。 これは、(cnt[0]=L-1) の場合にのみ考慮する必要があります。 (cnt[d]=L-1) であるため、すべてのゼロ対応立方体が (d) 対応である場合、またその逆の場合、その数は正確には不可能です。 セットのサイズが等しい場合、これは (both[d]=L-1) と同等です。 
4. その特別な条件が当てはまる場合、(d) に続いて (L-1) 個のゼロが出力されます。 それ以外の場合は、出力 (d) を (L) 回繰り返します。 

アルゴリズムの背後にある不変条件は、すべての桁に個別に利用可能な十分な立方体があるため、(L) より短いすべての数値は安全であるということです。 長さ (L) では、最初の不十分なゼロ以外の桁のみが不足を生み出すことができ、2 番目の不足を利用できる唯一の辞書編集的に前の組み合わせは次のとおりです。`d000...0`。 その実現可能性は、(d) とゼロを含む立方体間の重なりのみに依存します。 その候補が除外されると、より小さい (L) 桁の数値には、要求されたすべての桁に対して十分な利用可能な立方体が存在するため、繰り返し (d) 桁の数値が最初に不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    cnt = [0] * 10
    both = [0] * 10

    for _ in range(n):
        s = input().strip()

        mask = 0
        for ch in s:
            mask |= 1 << (ord(ch) - ord('0'))

        for d in range(10):
            if mask & (1 << d):
                cnt[d] += 1

        if mask & 1:
            for d in range(1, 10):
                if mask & (1 << d):
                    both[d] += 1

    L = cnt[0] + 2
    for d in range(1, 10):
        L = min(L, cnt[d] + 1)

    if L == cnt[0] + 2:
        print('1' + '0' * (L - 1))
        return

    d = 1
    while cnt[d] + 1 != L:
        d += 1

    if cnt[0] == L - 1 and both[d] == L - 1:
        print(str(d) + '0' * (L - 1))
    else:
        print(str(d) * L)

if __name__ == "__main__":
    solve()
```最初のループは、1 つのキューブのビットマスクを構築します。 入力にはちょうど 6 文字があるため、キューブごとに一定の時間がかかります。 のような繰り返しの顔`111111`同じビットを 6 回設定しますが、カウントに寄与するのは 1 つだけです。 

2 つのカウント ループが更新されます。`cnt`。 The second one runs only for cubes containing zero and records the overlap with each nonzero digit. There is no need to store the cubes themselves after these counts have been accumulated.

 の計算`L`は中心境界の計算です。 の`+1`ゼロ以外の数字の場合は、(cnt[d]) 個の使用可能なキューブが最大で (cnt[d]) 個の出現をサポートできることを意味します。 の`+2`ゼロの場合は、有効な数の長さ (k) に最大で (k-1) 個のゼロを含めることができることを意味します。 

比較`L == cnt[0] + 2`意図的に同数の候補をゼロ候補に有利に処理します。 たとえば、両方の場合、`100...0`そして`ddd...d`同じ長さでは不可能なため、前者の方が常に数値的に小さくなります。 

の検索`d`は桁 (1) から始まるため、最初の不十分なゼロ以外の桁が選択されます。 Python の整数はオーバーフローせず、潜在的に大きなオブジェクトは最終的な答えだけであり、その長さは最大 (n+1) です。

import sys
import io

def solve_data(inp: str) -> str:
    stream = io.StringIO(inp)
    n = int(stream.readline())

    cnt = [0] * 10
    both = [0] * 10

    for _ in range(n):
        s = stream.readline().strip()

        mask = 0
        for ch in s:
            mask |= 1 << (ord(ch) - ord('0'))

        for d in range(10):
            if mask & (1 << d):
                cnt[d] += 1

        if mask & 1:
            for d in range(1, 10):
                if mask & (1 << d):
                    both[d] += 1

    L = cnt[0] + 2
    for d in range(1, 10):
        L = min(L, cnt[d] + 1)

    if L == cnt[0] + 2:
        return '1' + '0' * (L - 1)

    d = 1
    while cnt[d] + 1 != L:
        d += 1

    if cnt[0] == L - 1 and both[d] == L - 1:
        return str(d) + '0' * (L - 1)

    return str(d) * L

def run(inp: str) -> str:
    return solve_data(inp).strip()

 ## 特殊なケース

 同じ数字の繰り返しコピーを持つ立方体は、その桁数に 1 単位だけを寄与する必要があります。 のために```
1
111111
```立方体のマスクには数字 (1) のみが含まれています。 したがって`cnt[1] = 1`そして`cnt[2] = 0`。 この式は (L=1) を示し、桁 (2) が最初の不十分な非ゼロ桁になります。 アルゴリズムの出力`2`、それは正しいです。 

先行ゼロの制限により、ゼロのしきい値が変更されます。 考慮する```
2
012345
