 ## 解決策
 ## 問題の理解

 配列には (n) 個の位置がありますが、それらの位置に割り当てられる値は固定されていません。 試行ごとに (n) 個の値を受け取り、それらを自由に並べ替えることができます。 

配列上には (q) 個の固定間隔があります。 順列が選択されると、すべての間隔がその中に配置された最大値に寄与します。 順列のスコアは、それらの (q) 最大値の合計です。 すべての試行に対して独立して可能な最大スコアが必要です。 

たとえば、間隔が ([1,2]) と ([2,3]) の場合、同じ値が両方の間隔の最大値になるため、最大値を位置 2 に配置すると特に便利です。 問題は、この間隔間の重複をどのように活用するかを決定することです。 

制約の位置の数は (n\le 30) と少なく、クエリされる間隔は最大 30 です。 これにより、試行あたりの 2 次または 3 次の作業量を伴うアルゴリズムが合理的になります。 一方、試行回数は 1000 回である可能性があるため、すべての (n!) 個の順列を列挙するなど、(n) で指数関数的なことは完全に不可能です。 値は (10^9) に達する可能性があり、最終的な答えは (q\cdot10^9) 程度になる可能性があるため、固定幅整数を使用する言語では 32 ビット整数では十分ではありません。 

不適切な実装が露呈する可能性のあるエッジケースがいくつかあります。 

(n=1) の場合、選択する意味のある順列はありません。 たとえば、(n=1,m=1,q=1)、間隔 ([1,1])、値 (42) の場合、答えは (42) になります。 少なくとも 2 つの位置があることを前提とした実装では、選択ループが誤って処理される可能性があります。 

間隔が完全に重なる場合もあります。 (n=3) の場合、2 つの区間が ([1,3]) と ([1,3]) で、値が (1,5,2) である場合、値 (5) が両方の区間の最大値であるため、答えは (10) になります。 カバーされた間隔を削除せずに各位置の最初の間隔範囲を一度だけカウントすると、後の寄与が不正確になる可能性があります。 

ポジションは、現在カバーされていない間隔に属することもできます。 たとえば、(n=3)、間隔 ([1,1]) および ([3,3]) の場合、最大値として位置 1 を選択した後、位置 2 は残りの間隔に寄与しません。 値を割り当てることは無害ですが、実装ではそれをクエリをカバーするものとして扱ってはなりません。 

値が等しい場合も微妙なケースです。 複数の値が等しい場合、それらの順序はスコアに影響しません。 たとえば、(n=3)、1 つの間隔 ([1,3])、および値 (7,7,7) の場合、すべての順列は (7) になります。 貪欲な選択により、関係が勝手に切れてしまう可能性があります。 

最後に、ゼロ値は有効です。 (n=2)、間隔 ([1,2])、値 (0,0) を使用すると、答えは (0) になります。 位置または間隔が処理されていないことを示すためにゼロを使用するコードは、正当な値と初期化されていない状態を暗黙的に混同する可能性があります。 

## アプローチ

 直接的なブルート フォース ソリューションは概念的に単純です。 (n) 値の順列ごとに、その順列に従って値を配置し、すべての (q) 間隔をスキャンし、各間隔内の最大値を計算し、最大スコアを保持します。 これは正しいです。考えられるすべての順序が明示的に検査されるからです。 

問題は順列の数です。 それらは (n!) 個あり、各間隔を直接スキャンする場合、1 つの順列を評価するには (O(qn)) の作業が必要になる可能性があります。 最悪の場合、これは (O(n!,qn)) になります。 (n=30) の場合、順列の数だけでも約 (2.65\cdot10^{32}) となるため、このアプローチは実現可能とは言えません。 

値を降順に見ると有益な観察が得られます。 

最大値が (x) であるとします。 (x) を配置する場所を決定すると、その間隔がまださらに大きな値で処理されていない限り、その位置を含むすべての間隔が最終的な最大値として (x) を取得します。 このような間隔は考慮から除外できます。 次に、2 番目に大きい値を配置し、繰り返します。

現在配置されている値より大きい値がインターバル内に入力されていない場合は、いつでもインターバルをアクティブと呼び出します。 現在の値は、選択した位置を含むアクティブな間隔ごとに 1 回だけ寄与します。 

これにより、問題はポジションの貪欲な順序付けに変わります。 現在の最大残り値として、アクティブな間隔の最大数に含まれる未使用の位置を選択します。 選択したら、それらすべての間隔をカバー済みとしてマークします。 

明らかではない部分ですが、この貪欲な選択が全体的に最適であることが証明されています。 現在の最大の残りの値が (x) であり、最適解によりそれが位置 (r) に配置されるとします。 私たちの貪欲なアルゴリズムは、少なくとも (r) と同じ数のアクティブな間隔に属する位置 (p) を選択します。 

(y) を最適解が (p) に置く値とする。 (x) が残りの最大値であるため、(x\ge y) になります。 (x) と (y) を交換し、(x) を (p) に、(y) を (r) に置きます。 

両方の位置を含むアクティブな間隔は影響を受けません。 (p) を含むが (r) を含まないアクティブな間隔は、(y) から (x) に改善されます。 (r) を含むが (p) を含まないアクティブな間隔は、(x) から (y) に減少します。 したがって、合計スコアの変化は次のようになります。 

[
 (x-y)\左(c_p-c_r\右),
 】

 ここで、(c_p) と (c_r) は、(p) と (r) を含むアクティブな間隔の数です。 どちらの係数も負ではないため、スワップによって答えが減少することはありません。 

したがって、最大の残りの値が最大のアクティブ カバレッジを持つ位置に配置される最適なソリューションが常に存在します。 その位置を固定した後、まったく同じ引数が残りの値と間隔に適用されます。 これにより貪欲なアルゴリズムが得られます。 

(q\le30) であるため、間隔は 30 ビット マスクで表すことができます。 位置ごとに、どのクエリ間隔にその位置が含まれるかを保存します。 別のビットマスクは、どの間隔がまだアクティブであるかを保存します。 ポジションを含むアクティブなインターバルの数は、ビット単位の AND とそれに続く母数カウントになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n!,qn)) | (O(n+q)) | 遅すぎる |
 | 貪欲 | 試行ごとに (O(n^2+n\log n)) | (O(n+q)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列の位置ごとにビットマスクを作成します。 ビット (k) は、クエリ間隔 (k) にその位置が含まれる場合にのみ設定されます。 間隔は最大 30 個あるため、1 つの Python 整数ですべての間隔を表すことができます。 
2. 1 回の試行に対して、その (n) 値を降順に並べ替えます。 可能な限り多くの間隔の最大値を決定する必要があるため、最初に最大値を処理します。 
3. 最初に、すべてのクエリ間隔をアクティブとしてマークします。 アクティブな間隔は、現在処理されている値より大きな値をまだ受け取っていません。 
4. 現在の値については、未使用のすべての位置を検査します。 そのカバレッジ マスクをアクティブ インターバル マスクと交差させることにより、その位置を含むアクティブ インターバルの数を計算します。 
5. カウントが最大の未使用の位置を選択します。 現在の値が (x) で、位置がアクティブな間隔 (c) をカバーする場合、答えに (x\cdot c) を追加します。 これらの (c) 間隔は、最終的な最大値が (x) に固定されるようになりました。 
6. 選択した位置を使用済みとしてマークし、その位置を含むすべての間隔をアクティブなマスクから削除します。 以降の値はすべて現在の値より大きくないため、これらの間隔を再度考慮する必要はありません。 
7. すべての位置が割り当てられるまで、次の値を続けます。 すでにカバーされているインターバルはそれ以上何も寄与しませんが、以前にカバーされていないすべてのインターバルは最終的に、その中の最初に選択された位置によってカバーされます。 

### なぜ効果があるのか

 不変条件は、最初の (k) 個の最大値を処理した後、アクティブ セットから削除されたすべての間隔が、それらの (k) 個の値の 1 つによって最終的な最大値がすでに固定されていることです。 すべてのアクティブな間隔には未使用のポジションのみが含まれるため、最終的な最大値は残りの値の 1 つから取得する必要があります。

次に大きい値 (x) については、残りの値の最適な配置を検討します。 (x) が位置 (r) に配置され、貪欲アルゴリズムが位置 (p) を選択する場合、(x) を (p) の値と交換すると、スコアが次のように変化します。 

[
 (x-y)(c_p-c_r)\ge0。 
】

 (x) が最大の残りの値であるため、最初の係数は負ではありません。また、グリーディ ポジションのアクティブ カバレッジが最大であるため、2 番目の係数は負ではありません。 したがって、最適な配置は常に貪欲な選択に一致する配置に変換できます。 

この交換議論を繰り返し適用すると、あらゆる貪欲な選択を最適な完全な置換に拡張できることが証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    q = int(input())

    intervals = []
    for _ in range(q):
        l, r = map(int, input().split())
        intervals.append((l - 1, r - 1))

    # cover[p] is a bitmask of all intervals containing position p.
    cover = [0] * n

    for k, (l, r) in enumerate(intervals):
        bit = 1 << k
        for p in range(l, r + 1):
            cover[p] |= bit

    full_mask = (1 << q) - 1

    answers = []

    for _ in range(m):
        values = list(map(int, input().split()))
        values.sort(reverse=True)

        active = full_mask
        used = [False] * n
        ans = 0

        for value in values:
            best_pos = -1
            best_count = -1

            for p in range(n):
                if used[p]:
                    continue

                count = (active & cover[p]).bit_count()

                if count > best_count:
                    best_count = count
                    best_pos = p

            ans += value * best_count
            used[best_pos] = True

            # Every active interval containing best_pos is now fixed.
            active &= ~cover[best_pos]

        answers.append(str(ans))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```最初の前処理ループは、すべての間隔を位置カバレッジ マスクに変換します。 たとえば、間隔が 3 つあり、位置 2 が間隔 0 と 2 に属する場合、そのマスクにはビット 0 と 2 が設定されます。 

試行ごとに値を逆順に並べ替えると、貪欲交換引数で必要なシーケンスが正確に得られます。 の`active`マスクには最初はすべての (q) 間隔が含まれています。 

表現`(active & cover[p]).bit_count()`位置を含むアクティブな間隔を正確にカウントします`p`。 なぜなら、(q\le30) 区間のセット全体が 1 つの整数内に収まるからです。 

選択後`best_pos`、式`active &= ~cover[best_pos]`その位置を含むすべての間隔を削除します。 Python の整数は無制限の表現を持っているため、補数は`~cover[best_pos]`無限に多くの概念的な 1 ビットを含めることができますが、それを非負のビットと AND 演算します。`active`マスクは、表現された間隔に対応するビットのみをクリアします。 

次の値に移動する前に、位置が使用済みとしてマークされます。 これにより、2 つの値を配列の同じ位置に割り当てることができなくなります。 

Python の整数は、潜在的に大きな答えも直接処理します。 32 ビット整数を使用する言語では、(30\cdot10^9) 付近の答えがオーバーフローするため、64 ビット整数が必要になります。 

の使用`bit_count()`ここでは、クエリ間隔の数が最大 30 で、カバレッジ状態が 1 つのマシンサイズの整数に自然に収まるため、特に便利です。 

## 実用的な例

 ### サンプル 1

 すべてのクエリ間隔は正確に 1 つの位置で構成されているため、各位置は最初は 1 つのアクティブな間隔を正確にカバーします。 値は最大から最小の順に処理されます。 

最初のテスト ケースの値は (2,1,1,1,1) です。 

| 値 | 選択された位置 | | より前のアクティブな間隔 現在カバー中 | 答え |
 | --- | --- | --- | --- | --- |
 | 2 | 5 | 5 | 1 | 2 |
 | 1 | 1 | 4 | 1 | 3 |
 | 1 | 2 | 3 | 1 | 4 |
 | 1 | 3 | 2 | 1 | 5 |
 | 1 | 4 | 1 | 1 | 6 |

 すべての位置の適用範囲が等しいため、最初の値はどこにでも配置できます。 位置が選択されると、そのシングルトン間隔は削除されます。 最終的なスコアは (2+1+1+1+1=6) です。 

残りの試行では、同じプロセスですべての値が個別のシングルトン間隔に割り当てられるため、スコアは単にすべての値の合計になります。 これにより (7,8,9,10) が生成されます。 

### サンプル 2

 クエリは ([1,2]) と ([2,3]) です。 位置 2 でのオーバーラップが重要な部分です。 

最初の配列の値は (1,5,1) です。 

| 値 | 選択された位置 | | より前のアクティブな間隔 現在カバー中 | 答え |
 | --- | --- | --- | --- | --- |
 | 5 | 2 | 2 | 2 | 10 |

 | 1 | 3 | 0 | 0 | 10 |

 位置 2 は両方の間隔に属するため、最大値は両方を同時にカバーします。 そこに 5 を配置すると、両方の間隔の最終的な最大値は 5 になり、(5+5=10) になります。 

3 番目の配列の値は (10,1,7) です。 同じ位置 2 が最大値にとって最適な位置であるため、10 は両方の間隔をカバーします。 

| 値 | 選択された位置 | | より前のアクティブな間隔 現在カバー中 | 答え |

 | 1 | 3 | 0 | 0 | 20 |

 これは (10+10=20) となり、サンプル出力と一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(m(n^2+n\log n)+nq)) | 各試行は (n) 個の値をソートし、(n) 個の貪欲ラウンドを実行し、それぞれ最大 (n) 個の位置をチェックします。 |
 | スペース | (O(n+q)) | カバレッジ マスク、現在の値、および使用位置の状態には線形空間が必要です。 |

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout
        input = sys.stdin.readline

 ## 特殊なケース

 最小サイズの場合、入力は (n=1)、1 つのクエリ ([1,1])、および値 42 で構成されます。唯一の位置にはアクティブな間隔が 1 つあるため、貪欲アルゴリズムはそれを選択し、(42\cdot1) を追加し、間隔を削除して、42 を出力します。 

完全に重複する間隔の場合 (n=3)、間隔は ([1,3])、([2,3])、および ([1,2]) で、すべての値は 7 です。最初はすべての位置が 2 つまたは 3 つの間隔のいずれかをカバーしますが、どちらの位置を選択しても、その位置を含むすべての間隔が削除されます。 すべての値が等しいため、交換引数ではタイブレークが許可され、最終的な答えは 7 の 3 つの寄与、つまり 21 のままになります。 

右境界に達する間隔については、間隔 ([1,1])、([4,4])、および ([2,4]) と値 (10,1,2,20) を持つ入力を考慮します。 位置 4 は 2 つのアクティブな間隔をカバーするため、20 がそこに配置され、(40) に寄与します。 残っているアクティブな間隔は ([1,1]) だけであるため、10 が位置 1 に配置され、別の 10 が追加されます。答えは 50 です。これにより、間隔のエンドポイントが包括的に処理されることが確認されます。 

値が等しい場合、交換証明では (x-y\ge0) が使用されます。 (x=y) の場合、それらを交換しても何も変わらないため、任意のタイブレークが有効です。 したがって、実装では重複値に対する特別な処理は必要ありません。 

値がゼロの場合は (n=2)、1 つの間隔 ([1,2])、および値 (0,0) を考慮します。 貪欲アルゴリズムは、アクティブ カバレッジが 1 であるため、引き続き位置を選択し、(0\cdot1=0) を追加し、間隔を削除し、正しい答え 0 を取得します。値 0 はセンチネルとして使用されることはないため、未処理の状態と混同することはできません。 

最大サイズの場合は (n=q=30) で、30 個の間隔はすべて ([1,30]) に等しくなります。 すべての位置は 30 の間隔すべてをカバーするため、最初で最大の値によってすべての間隔が即座に決定されます。 値が (1,2,\ldots,30) の場合、最大値 30 が寄与します (30\cdot30=900)。アクティブな間隔が残っていないため、それ以降の値はすべてゼロになります。 結果は 900 です。これは、貪欲な選択を行うたびにカバーされた間隔を削除する必要がある理由を示しています。
