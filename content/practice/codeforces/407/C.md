 ## 解決策
 ## 問題の理解

 配列と一連の範囲操作が与えられます。 各操作でセグメントが選択されます$[l, r]$そしてパラメータ$k$、そしてすべてのポジションについて$j$そのセグメント内に、距離に応じて値を追加します。$j$左端からです$l$。 加算された値は二項係数であり、その引数は次のようにシフトします。$j - l$これは、1 回の更新内で、寄与が次から始まる固定の組み合わせシーケンスを形成することを意味します。$l$右に行くにつれて決定的に進化します。 

すべての演算を順番に処理した後、すべての配列位置のモジュロの最終値が必要になります。$10^9+7$。 

制約により、私たちは厳しい体制に追い込まれます。 と$n, m \le 10^5$、すべてのクエリのすべての要素に触れるソリューションは、すぐに遅すぎます。$10^{10}$最悪の場合はアップデートも。 平$O(n \log n)$クエリごとの値は許容範囲をはるかに超えています。 したがって、更新の構造は、各クエリが一定時間またはほぼ一定時間で寄与するように変換する必要があり、重労働はグローバルな再構築ステップに延期されます。 

微妙な問題は、更新がセグメント全体で一定ではないという事実から生じます。 単純な間違いは、二項値を区間全体にわたって固定されているかのように扱うことです。 たとえば、更新によってどこにでも同じ値が追加されると誤って仮定した場合、$[l, r]$、次に次のようなクエリ$(l=1, r=3, k=2)$は一律に適用されますが、位置によって寄与が異なるため、これは誤りです。$1, 2, 3$。 正しい順序は、からの距離によって異なります。$l$したがって、非常に小さな例でもすでにエラーが明らかになります。 

別の失敗モードは、セルごとに独立して二項係数を計算しようとすることです。 それでも$k \le 100$、すべての組み合わせ論を再計算します。$(i, j)$各クエリ内のペアは、実際には依然として二次的な動作につながります。 

本当の課題は、すべての更新が同じファミリーの離散関数の変換であること、およびこれらの関数は、より単純な基本表現のプレフィックス合計を繰り返すことで生成できることを認識することです。 

## アプローチ

 直接シミュレーションでは、セグメントを反復処理し、適切な二項値を各位置に追加することで各クエリを適用します。 これは定義に正確に従っているため概念的に機能しますが、各クエリは次の点に達する可能性があります。$10^5$要素、大まかにつながる$m \cdot n$最悪の場合の運用。 両方の制限が$10^5$、これは数桁実現不可能になります。 

重要な観察は、固定の機能に追加された機能であることです。$k$任意ではありません。 位置の関数として$i$、次数の離散多項式のように動作します。$k$。 このような関数は接頭辞の合計の下で安定しています。接頭辞を繰り返すと、有効な「二項レベル」が 1 つ増加します。 これはアイデンティティに直結します$$\binom{x}{k} = \sum_{t=0}^{x} \binom{t}{k-1},$$これは、累積和を使用して、高次の二項層を低次の二項層から構築できることを意味します。 

これは分解戦略を示唆しています。 クエリを配列に直接適用する代わりに、次のインデックスが付いた階層構造を維持します。$k$。 各クエリは、単純な範囲の追加として、対応するレイヤーにのみ寄与します。 次に、プレフィックス合計を使用して、下位層から上位層へ寄与度を繰り返し伝播し、その過程で実際の二項形状の寄与度を再構築します。 

これにより、問題は「範囲を超えて複雑な関数を適用する」という問題から、「一定の範囲の更新を適用し、その後最大 101 層にわたる構造化された伝播を適用する」という問題に変わります。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(nm)$|$O(1)$| 遅すぎる |
 | 階層化されたプレフィックスの伝播 |$O(n \cdot 100)$|$O(n \cdot 100)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各レベルが固定されたオブジェクトに対応する 2D 構造を構築します。$k$、各レベルは位置にわたる差分配列を保存します。 

1. 配列を作成します$dp[k][i]$みんなのために$k \in [0, 100]$、ゼロに初期化されます。 各層は最終的に二項次数の寄与を表すことになります。$k$上方変換される前。 
2. すべてのクエリに対して$(l, r, k)$、レイヤーに標準の範囲更新を適用します$k$: インクリメントします$dp[k][l]$そして減少します$dp[k][r+1]$。 これは、順序の二項シーケンスをエンコードします。$k$位置から始まります$l$そして続く$r$。 形状自体はまだ展開されていません。 
3. それぞれについて$k$から$0$に$100$, まず、位置にわたるプレフィックスの合計を使用して、差分配列を配列に沿った実際の値に変換します。 このステップの後、$dp[k][i]$レベルでのすべてのクエリの累積寄与を表します$k$位置にある$i$、上向き伝播の前。 
4. まだ同じパスオーバー内にあります$k$を追加することで、これらの貢献を次のレベルに伝播します。$dp[k][i]$の中へ$dp[k+1][i]$。 このステップは組み合わせ変換です。これは、二項層のプレフィックス和を繰り返すことで次の二項層を生成するという恒等をエンコードします。 
5. すべてのレイヤーを処理した後、結果を結合します。 各ポジション$i$すべての合計を受け取ります$dp[k][i]$横切って$k$、元の配列値に追加されます。 

### なぜ効果があるのか

 各層$k$は、インデックスに対する多項式のような関数の離散微分レベルを表します。 範囲の更新により、開始位置に「単位インパルス」が挿入され、プレフィックス合計によってそのレベルの正しい二項構造に分散されます。 上向きの伝播により、ID リンクが確実に行われます。$\binom{x}{k}$とプレフィックスの合計$\binom{x}{k-1}$は世界的に施行されています。 

すべての変換は線形であり、配列全体に一貫して適用されるため、さまざまなクエリからの寄与が干渉することなく重なり合い、伝播中に情報が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    K = 100
    dp = [[0] * (n + 2) for _ in range(K + 2)]

    for _ in range(m):
        l, r, k = map(int, input().split())
        dp[k][l] += 1
        dp[k][r + 1] -= 1

    for k in range(K + 1):
        for i in range(1, n + 1):
            dp[k][i] += dp[k][i - 1]
            dp[k][i] %= MOD
        if k < K:
            for i in range(1, n + 1):
                dp[k + 1][i] += dp[k][i]
                dp[k + 1][i] %= MOD

    for i in range(1, n + 1):
        a[i - 1] = (a[i - 1] + sum(dp[k][i] for k in range(K + 1))) % MOD

    print(*a)

if __name__ == "__main__":
    solve()
```実装では懸念事項が明確に分離されます。 最初のループでは、すべてのクエリを適切な二項レベルでの単純な範囲更新として記録します。 ここでは組み合わせ論は計算されません。 

第 2 段階は構造化された再構築です。 それぞれの内部のプレフィックスの合計$k$差分形式を配列に沿った実際の寄与に変換します。 その直後に、上向きの伝播ステップにより、蓄積された影響が次の二項レベルに転送されます。 順序が重要です: それぞれの中で$k$、プレフィックスは伝播前に発生する必要があります。そうしないと、コントリビューションの構造が破損します。 

最後に、すべてのレベルを元の配列に追加して、答えを組み立てます。 合計が終わりました$k$安全なので$k \le 100$、この最後のステップを直線的にします。$n \cdot 100$。

 ## 特殊なケース

 単一の位置を持つ最小限の配列は、範囲更新が正しく低下するかどうかをテストします。$l = r$。 その場合、差分配列の更新は 1 点のみに触れるので、プレフィックス ロジックが誤って境界を超えて拡張することはありません。 

2 番目のエッジケースは次のような場合です。$k = 0$。 ここでは、すべての更新がその範囲にわたって一定となり、アルゴリズムがそれを誤って歪んだ方法で上位層に伝播してはなりません。 関数がフラットであっても、伝播ルールは正確さを維持する必要があります。 

最後のデリケートな状況は、重複するクエリの長​​いチェーンです。 すべてが加算的なため、アルゴリズムは可換性と線形性に依存します。 伝播が間違った順序で行われた場合、以前の貢献が部分的に上書きされたり、二重にカウントされたりする可能性があります。 層ごとの伝播前のプレフィックスの順序が固定されているため、このような事態は発生しません。
