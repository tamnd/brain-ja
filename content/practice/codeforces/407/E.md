 ## 問題の理解

 長さの整数シーケンスが与えられます$n$そして 2 つの追加パラメータ:$k$、挿入できる要素の最大数、および$d$、等差数列の意図された差。 タスクは、最大で 1 倍まで拡張できる、元のシーケンスの最長の連続する部分配列を見つけることです。$k$ソート後に差分のある等差数列を形成するように数値を並べ替える$d$。 出力は、そのような部分配列の左端と右端の 1 から始まるインデックスです。 複数のサブ配列の長さが同じ場合は、最も早く始まるサブ配列が選択されます。 

制約は高いです:$n$まで行くことができます$2 \cdot 10^5$、 そして$k$同様の大きさになる可能性があります。 ナイーブ$O(n^2)$考えられるすべての部分配列を考慮し、欠落している数を数えて等差数列を完成させるアプローチは、おおよそのパフォーマンスを発揮します。$2 \cdot 10^5 \cdot 10^5 \sim 2 \cdot 10^{10}$最悪の場合、2 秒の制限をはるかに超えて操作が行われる可能性があります。 理想的には、線形に近いアルゴリズムが必要です$O(n \log n)$またはそれ以上です。 

単純な実装を失敗させる可能性のあるエッジ ケースには、次のようなシーケンスが含まれます。$d = 0$。 たとえば、シーケンス`[5, 5, 5]`自明のことですが、あらゆるものにとって優れた 2 次元シーケンスです。$k \ge 0$ただし、不注意にゼロ以外の差を仮定すると、エラーが発生する可能性があります。 もう 1 つの微妙な点は、サブ配列にすでに重複が含まれているか、逆にソートされている可能性があることです。 厳密に増加するシーケンスを想定している場合、不注意なアプローチでは欠落している要素を誤ってカウントする可能性があります。 

## アプローチ

 ブルートフォースアプローチを説明するのは簡単です。 可能な開始インデックスごとに$l$、すべての終了インデックスを試します$r \ge l$、部分配列を抽出します$a[l..r]$、差のある等差数列にするために挿入する必要がある要素の数を計算します。$d$。 部分配列をソートし、最小値と最大値を決定し、完全な等差数列で予想される要素数を計算し、部分配列の長さを減算します。 必要な挿入が最大でも$k$、回答を更新します。 このアプローチは正しいですが、$O(n^2 \log n)$各サブ配列をソートするため、大規模な配列には遅すぎる$n$。 

最適化するための重要な洞察は、「位置モジュロ」にマッピングした後のサブ配列の最小値と最大値、および個別の要素の数のみが必要であるということです。$d$" のために$d \neq 0$。 具体的には、差のある等差数列内のすべての数値$d$次の形式でなければなりません$start + j \cdot d$。 定義すると$b_i = (a_i - a_1) / d$部分配列内の各要素に対して (要素が次の値で割り切れると仮定して)$d$)、サブアレイは良いです$k$-$d$最大値の場合のシーケンス$b_i$最小値を引いた値に 1 を加えた値から部分配列内の要素の数を引いた値を超えないこと$k$。 

このマッピングにより、配列全体にわたってウィンドウを維持し、最小値と最大値を効率的に追跡するという問題が軽減されます。$b_i$窓の中。 スライディング ウィンドウとバランスのとれた BST またはマルチセットを組み合わせると、これらの境界を維持できます。$O(\log n)$挿入/削除ごとに、$O(n \log n)$全体。

 ## アルゴリズムのチュートリアル

 1. ポインタの初期化`left = 0`そして`right = 0`スライディング ウィンドウを定義し、これまでに見つかった最適な長さとインデックスを保存する変数を定義します。 
2. マルチセット (または同等の構造) を使用して、すべてのマップされた位置を維持します。`(a_i - a[left]) / d`現在のウィンドウ内で。 これにより、いつでもウィンドウの最小値と最大値を効率的に取得できます。 
3. ウィンドウを移動して拡大します。`right`一度に 1 つの要素を転送します。 新しい要素ごとに`a[right]`、相対的な位置を計算して含めることができるかどうかを確認します。`a[left]`。 もし`(a[right] - a[left]) % d != 0`、要素は で始まる等差数列に適合できません。`a[left]`そして違いがあります`d`。 その場合は移動してください`left`残りの条件が成立するまで前進します。 
4. 等差数列を完成させるために欠落している要素の数が最大でも次であるという不変条件を維持します。`k`。 これを次のように計算します`max_pos - min_pos + 1 - current_window_size`。 不変式に違反した場合は、再び保持されるまでウィンドウを左から縮小します。 
5. ウィンドウを拡張するたびに、現在のウィンドウの長さが記録された最適な長さより大きい場合は、最適な長さとインデックスを更新します。 
6. まで続けます`right`配列の最後に到達します。 保存されている最適な左右のインデックスを返します。 

**機能する理由**: すべてのステップで、ウィンドウは、最大でも等差数列に拡張できる連続した部分配列を表します。`k`挿入。 スライディング ウィンドウにより、左の各インデックスから始まる最大の有効な部分配列のみが考慮されるようになります。 マップされた位置の最小値と最大値を追跡することで、欠落している要素の数を正確に計算できます。 有効なサブ配列がスキップされることはなく、無効なサブ配列が誤って含まれることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict
from sortedcontainers import SortedList

n, k, d = map(int, input().split())
a = list(map(int, input().split()))

if d == 0:
    # special case: all elements must be equal
    best_len = 1
    best_l = 0
    count = defaultdict(int)
    l = 0
    for r in range(n):
        count[a[r]] += 1
        while (r - l + 1) - max(count.values()) > k:
            count[a[l]] -= 1
            if count[a[l]] == 0:
                del count[a[l]]
            l += 1
        if r - l + 1 > best_len:
            best_len = r - l + 1
            best_l, best_r = l, r
    print(best_l + 1, best_r + 1)
else:
    b = [ai // d for ai in a]
    best_len = 0
    best_l = 0
    s = SortedList()
    l = 0
    for r in range(n):
        s.add(b[r])
        while (s[-1] - s[0] + 1) - len(s) > k:
            s.remove(b[l])
            l += 1
        if r - l + 1 > best_len:
            best_len = r - l + 1
            best_l, best_r = l, r
    print(best_l + 1, best_r + 1)
```ソリューションはエッジケースに対処します`d = 0`除算とモジュロ演算は意味がないため、別々に実行します。 のために`d > 0`、各要素を仮想の等差数列でその「位置インデックス」にマッピングします。`SortedList`最小値と最大値を効率的に追跡できます。 スライディング ウィンドウ ロジックにより、連続するサブ配列が次の条件を満たすことが保証されます。`k`挿入要件。
