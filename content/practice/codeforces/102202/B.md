 ## 解決策
 ## 問題の理解

 試合結果は、有向トーナメント グラフを形成します。 各生徒は頂点であり、異なる生徒のペアごとに 1 つの有向エッジが存在します。つまり、生徒 (i) が生徒 (j) に勝った場合、エッジ (i \to j) が存在します。 

勝ちパスは、このグラフの単なる有向パスです。 (x) から (y) までの距離は最短の有向パス長で、(y) が到達できない場合は特別な値 (9000) になります。 生徒の弱点は、その生徒と他の生徒との最大の距離です。 できるだけ弱点が小さい生徒を、その最小限の弱点とともにアウトプットする必要があります。 

入力は (N \times N) 文字行列です。 行 (i) は生徒 (i) が関係するすべての試合を表します。`W`エッジが (i) からその列の学生に向かうことを意味し、`L`エッジが反対方向に進むことを意味します。 すべてのペアが 1 回だけプレイするため、これは任意の有向グラフではなくトーナメントです。 

制約 (N \le 3000) が中心的な手がかりです。 行列全体の読み取りにはすでに (O(N^2)) のコストがかかります。これは最大サイズで約 900 万文字であり、完全に妥当です。 ただし、(O(N^3)) アルゴリズムは、(N=3000) の場合に最大 270 億の基本グラフ操作を実行します。これは、1 秒の時間制限が許容できる範囲をはるかに超えています。 すべてのペアの最短パスを計算するのではなく、トーナメント構造から直接より多くの情報を抽出する必要があります。 

不注意な解決策によって誤って対処される可能性がある簡単なケースが 2 つあります。 まず、生徒と自分自身との距離は１ではなくゼロです。 例えば、```
2
-W
L-
```生徒 1 が生徒 2 に直接勝つため、生徒 1 との距離は (0,1) となり、弱点は (1) になります。 正しい出力は次のとおりです`1 1`。 開始頂点を 1 ステップ必要であるとカウントするソリューションでは、(2) が誤って報告される可能性があります。 

2 番目のケースは、誰も直接勝てない場合です。 循環トーナメントを検討してください```
3
-LW
W-L
LW-
```生徒 1 は生徒 2 に負けますが、生徒 1 は生徒 3 に勝ち、生徒 3 は生徒 2 に勝ちます。したがって、生徒 1 は 2 勝以内にすべての生徒に到達し、弱点 (2) が与えられます。 正しい出力は次のとおりです`2 1`。 単純に直接勝利数が最も多い生徒を選択し、答えが常に (1) であると仮定すると、ここでは失敗します。 

3 番目の微妙な点は、特別な値 (9000) が答えに現れる必要がないことです。 トーナメントには、最大 2 つの有向エッジで他のすべての生徒に到達できる生徒が常に含まれます。 以下の解決策はそのような生徒を直接構築するため、最適な弱点は常に (1) または (2) のいずれかになります。 

## アプローチ

 直接的なアプローチは、結果を有向グラフとして扱い、すべての生徒から幅優先検索を実行することです。 1 つの BFS は 1 人の開始生徒からすべての最短距離を計算するため、(N) 回の BFS 実行後、すべての生徒の弱点がわかり、最小の距離を選択できます。 隣接行列を使用すると、各 BFS は (N) 個の頂点ごとに (N) 個の可能な出力エッジを検査し、ソースごとに (O(N^2)) 個の作業を、全体で (O(N^3)) 個の作業を与えることができます。 (N=3000) では、これは (3000^3 = 27{,}000{,}000{,}000) 回の隣接性チェックに相当し、非常に遅すぎます。 

BFS がウィニング パスの距離の定義と正確に一致するため、ブルート フォース手法が機能します。 問題は、トーナメントには一般的な有向グラフよりもはるかに強力な構造が含まれていることです。 

重要な観察は、最大の出次数を持つ頂点が常に最大 2 ステップで他のすべての頂点に到達できるということです。 ここで、出次数は単に次数の数です。`W`その生徒の行の文字。 

最大アウトディグリーの学生 (v) を取り上げ、(v) が負けた別の学生 (u) を考えます。 (v) が 2 段階で (u) に到達できない場合、(v) が (w) に勝ち、(w) が (u) に勝つような生徒 (w) は存在しません。 各ペアには勝者が 1 人だけいるため、(v) に負けた生徒はすべて (u) に負ける必要があります。 

それは矛盾を生みます。 生徒 (u) は (v) に勝ち、(u) も (v) が勝つすべての生徒に勝ちます。 その結果、(u) の直接勝利の数は (v) よりも厳密に大きくなり、最大外次学生としての (v) の選択と矛盾します。 

したがって、すべての生徒は (v) に直接負けるか (この場合、中級の生徒を経由する両刃ルートが存在します)、または既に (v) に直接負けています。 したがって、最大外次数の学生の弱点は最大でも (2) です。 

これにより、問題全体が直接の勝利を数えるということになります。 一部の生徒が (N-1) 回勝利した場合、他のすべての生徒が直接到達するため、その生徒の弱点は正確に (1) になります。 そうでない場合、どの生徒の弱点も (1) になることはあり得ませんが、最大外次数の生徒の弱点はせいぜい (2) です。 したがって、その弱点はまさに (2) です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての生徒からの BFS による総当たり攻撃 | (O(N^3)) | (O(N^2)) | 遅すぎる |
 | 最大出次数 | (O(N^2)) | (O(N^2)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 完全な結果マトリックスを読み取ります。 すべての生徒の直接勝利数によって候補が決まるため、すべての文字を検査する必要があります。 
2. 各行について、文字数を数えます。`W`。 この数は生徒の外次数、つまり生徒が直接倒した対戦相手の数を意味します。 
3. 最大の出次数を持つ生徒を保持します。 最大外次数プロパティにより、この学生が 2 ステップ以内に全員に到達することがすでに保証されているため、まだパスを構築する必要はありません。 
4. 最大出次数が (N-1) の場合、弱点 (1) とその生徒を出力します。 他のすべての生徒は直接発信する隣人であるため、1 を超えるプラスの距離は必要ありません。 
5. それ以外の場合は、弱点 (2) と同じ生徒を出力します。 最大外次数の議論は、直接負けていないすべての対戦相手に 1 人の中間学生を介して到達できることを証明します。 選ばれた生徒は全員を直接倒すわけではないので、弱点は(1)ではあり得ず、まさに(2)になります。 

### なぜ効果があるのか

 (v) を最大出次数を持つ学生とします。 (v) がある生徒 (u) に負けたとします。 矛盾のために、(v) は 2 段階では (u) に到達できないと仮定します。 (v) が勝つすべての生徒 (w) については、(u) も (w) に勝つ必要があります。そうしないと (v \to w \to u) が有効な 2 段階パスになるからです。 (u) がさらに (v) に勝つため、(v) の直接の勝利はすべて (u) の直接の勝利に加え、(u) の (v) に対する勝利でもあります。 したがって、(u) は (v) よりも厳密に出次数が大きく、極大性に矛盾します。 

したがって、すべての頂点は (v) から最大 2 の距離にあります。 (v) に (N-1) 個の直接勝利がある場合、その弱点は (1) です。 それが少ない場合、その弱点は少なくとも (2) であり、上記の議論により上限は (2) になります。 したがって、選ばれた生徒の弱点はまさに可能な最小値です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    best_player = 0
    best_wins = -1

    for i in range(n):
        row = input().strip()
        wins = row.count('W')

        if wins > best_wins:
            best_wins = wins
            best_player = i

    weakness = 1 if best_wins == n - 1 else 2

    print(weakness, best_player + 1)

if __name__ == "__main__":
    solve()
```入力ループは一度に 1 つの完全な行を読み取り、`count('W')`学生の学位を取得するため。 対角線`-`そしてすべて`L`どちらの文字も現在の行の生徒による直接の勝利を表すものではないため、特別な処理は必要ありません。 

比較には、`>`それよりも`>=`。 複数の最大外次数の学生が許可されるため、どちらの選択も正しいことになりますが、次のように使用します。`>`最初のそのような生徒をただ維持するだけです。 

最終テストは、`best_wins == n - 1`、 ない`best_wins == n`。 学生は自分自身に勝つことはできないため、直接勝利できる可能性は (N-1) つだけです。 この条件が当てはまる場合、1 つのエッジで 1 つおきの頂点に到達します。 それ以外の場合、最大出次定理はちょうど 2 の弱点を与えます。 

答えは、ゼロから始まる Python インデックスを、問題で必要とされる 1 から始まる生徒の番号付けに変換します。 

Python には整数オーバーフローの問題はなく、最大数は`best_wins`は (N-1) のみです。 各行の処理後に行列自体を保存する必要がないため、余分なメモリ使用量が非常に少なく抑えられます。

この例では、長さ 0 の自己距離と 1 エッジの距離の間の境界を調べます。 生徒自身のエントリーは勝利数には影響しません。

| 学生 | 行 | 直接の勝利 | 列の後に最高 | 弱点決定 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N^2)) | (N^2) 個の行列文字がすべて 1 回読み取られるか検査されます。 
| スペース | (O(N)) | 一度に 1 つの入力行が保存され、少数のカウンターとインデックスのみが保存されます。 

(N=3000) では、(N^2=9{,}000{,}000) となり、指定された制限内では実用的です。 このアルゴリズムは、全ソース BFS アプローチで必要となる可能性のある 270 億回の操作を回避します。 Python の文字列実装では、`W`この入力サイズに対して十分効率的な各行の文字。 

## テストケース

 次のテスト ハーネスは、返された結果を確認できるように、同じアルゴリズムを関数として実装しています。 この問題では、複数の Gosu が存在する場合は任意の Gosu が許可されるため、バリデーターは、1 つの正確な生徒インデックスを要求するのではなく、報告された生​​徒が主張されている弱点を持っているかどうかをチェックします。```python
import sys
import io

def solve_data(inp: str) -> str:
    data = inp.strip().splitlines()
    n = int(data[0])

    best_player = 0
    best_wins = -1

    for i in range(n):
        wins = data[i + 1].count('W')
        if wins > best_wins:
            best_wins = wins
            best_player = i

    weakness = 1 if best_wins == n - 1 else 2
    return f"{weakness} {best_player + 1}"

def brute_weakness(rows, start):
    n = len(rows)
    dist = [-1] * n
    dist[start] = 0
    queue = [start]

    for v in queue:
        for u in range(n):
            if rows[v][u] == 'W' and dist[u] == -1:
                dist[u] = dist[v] + 1
                queue.append(u)

    if -1 in dist:
        return 9000
    return max(dist)

def check(inp: str, out: str):
    lines = inp.strip().splitlines()
    n = int(lines[0])
    rows = lines[1:]

    weakness, player = map(int, out.split())
    assert 1 <= player <= n
    assert weakness == brute_weakness(rows, player - 1)

    all_weaknesses = [brute_weakness(rows, i) for i in range(n)]
    assert weakness == min(all_weaknesses)

def run(inp: str) -> str:
    out = solve_data(inp)
    check(inp, out)
    return out

# Provided samples

L-
""")

run("""3

LW-
""")

run("""5

L-LLW
WW-LL
WWW-W
LLWL-
""")

# Minimum size

""")

""")

# Student 1 beats everybody, so the answer must have weakness 1.
n = 3000
rows = []
for i in range(n):
    row = ['-'] * n
    for j in range(i + 1, n):
        row[j] = 'W'
        row[i] = 'L'
    rows.append(''.join(row))

## 特殊なケース

 ミニマムサイズのトーナメントの場合```
2
-W
L-
```最初の学生の出次数は (1=N-1) ですが、2 番目の学生の出次数は 0 です。 アルゴリズムは生徒 1 を選択し、弱点 (1) を返します。 自己距離は 0 で、他の距離は 1 だけであるため、結果は定義と正確に一致します。 

ユニバーサル優勝者のいないトーナメントの場合、```
3
-LW
W-L
LW-
```3 人の生徒全員が次数 1 を持っています。 アルゴリズムはスチューデント 1 を保持します。これは最初の最大値であるためです。 生徒 1 は生徒 3 に直接到達し、生徒 3 を介して生徒 2 に到達するため、弱点は (2) です。 (N-1=2) 直接勝利した生徒はいないため、弱点 (1) はあり得ません。 

1 人の生徒がすべての試合に勝つ境界ケースの場合、```
4
-WWW
L-WW
LL-W
LLL-
```Student 1 には外次数 3 があり、これは (N-1) に等しくなります。 アルゴリズムは直ちに弱点 (1) を割り当てます。 他のすべての生徒の出次数は小さいため、生徒 1 を選択することも明らかに最適です。 

最大サイズのケースには 3000 人の生徒が収容されます。 推移的トーナメントは、生徒 (i) がより大きなインデックスを持つすべての生徒に勝つようにすることで形成できます。 生徒 1 は 2999 回の直接勝利を獲得したため、アルゴリズムは次の結果を返します。`1 1`。 実装ではちょうど 3000 行が処理され、その行数がカウントされます。`W`文字数、合計約 900 万のマトリックス エントリ。 BFS を実行したり、距離行列を構築したりすることはありません。これが、二次アプローチが上限において実用的なままである理由です。
