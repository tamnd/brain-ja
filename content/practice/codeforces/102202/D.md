 ## 解決策
 ## 問題の理解

 2 つの正の整数があります`A`そして`B`、最初は最大 (10^{18}) です。 許可される唯一の移動は、現在の値の 1 つをいずれかの変数に追加します。 目標は、2 つの変数が等しくなるまでのこのような動きのシーケンスを最大 5000 回生成することです。 審査員はあらゆる有効なシーケンスを受け入れるため、一意の答えではなく単純化を目的として自由に最適化できます。 公式問題では、まさにこれら 4 つの操作と同じ 5000 手の制限が使用されます。 

(10^{18}) のサイズ境界により、どちらかの入力の数値に比例するものは除外されます。 小さい数を繰り返し加算する戦略では、ほぼ (10^{18}) 回の操作が必要になる可能性があり、これは 5000 回の移動バジェットをはるかに超えます。 同時に、入力には整数が 2 つしか含まれていないため、対数演算、さらには数千の算術演算を行うことができます。 Python の整数は (10^{18}) を超える値も処理します。これは、中間加算が一時的に入力境界を超える可能性があるため便利です。 

最初のエッジケースは、最初から平等です。 入力用`5 5`、正しい出力は単に次のとおりです。`0`, 操作が必要ないためです。 常に少なくとも 1 つの操作を実行する不用意な実装では、許可されたすべての操作が 2 つの値のうちの 1 つを厳密に増加させるため、この問題から回復することはできません。 

2 番目のエッジ ケースは、一方の値が偶数で、もう一方の値が奇数である場合です。 入力用`2 3`文字通り分割することはできません`2`除算は許可されていないため、2 で割ります。 便利なトリックは、代わりに他の変数を 2 倍にすることです。 後`B+=B`、実際の状態は`(2, 6)`、これは概念的な状態のちょうど 2 倍です`(1, 3)`。 除算演算を直接記述するソリューションでは、無効な出力が生成されます。 

3 番目のエッジ ケースは、両方の値が偶数である場合です。`8 12`。 両方の概念的な値を 2 で割ると、次のようになります。`(4, 6)`、そしてこれは、ペアを最終的に等しくできるかどうかに変わりはありません。 一度に 1 つの偶数値のみを処理する不注意な実装も機能しますが、共通のスケーリング不変条件が曖昧になり、終了引数の確立が難しくなる可能性があります。 

4 番目のエッジ ケースは、次のような大きな奇数ペアです。`1 999999999999999999`。 繰り返し追加する`1`値を大きくするには、ほぼ (10^{18}) 回の演算が必要になります。 意図された構造では、代わりに 2 つの奇数の合計が偶数であるという事実を利用し、たった 1 回の加算で 2 の累乗による大幅な削減が可能になります。 

## アプローチ

 直接的なアプローチは、小さい値を大きい値に繰り返し加算することです。 もし`A < B`、私たちは実行します`B += A`; もし`B < A`、私たちは実行します`A += B`。 これは正しいです。小さい値を大きい値に加算するたびに 2 つの値の差が減少し、最終的には正の整数の値が等しくなるからです。 

問題は操作回数です。 のために`(1, 10^18)`、この貪欲なメソッドには (10^{18}-1) 個の追加が必要です。 すべてのステップで 4 つの操作が利用可能であり、深さ (k) でおよそ (4^k) 個のシーケンスの検索スペースが与えられるため、考えられる操作シーケンスを徹底的に検索する場合でも、さらに悪いことになります。 どちらのアプローチも、5000 回の移動制限の目的を完全に逸脱しています。 

重要な観察は、両方の数値を同じ正の整数で乗算または除算した場合に、等号が達成可能かどうかを判断する目的で、状態が変化しないことです。 概念的な状態が次のようになっているとします。`(A/2, B)`、 どこ`A`は均等です。 両方の概念的な値を 2 で乗算すると、次のようになります。`(A, 2B)`、 そして`(A, 2B)`実際の状態から取得されます`(A, B)`正確に使用して`B += B`。 したがって`B += B`分割をシミュレーションできる`A`2つまでに。 対称的に、`A += A`分割をシミュレーションできる`B`2つまでに。 

両方の概念的な値が奇数になると、両方とも 1 でない限り、それらを等しくすることはできません。 もし`A < B`、追加`A`に`B`与える`A + B`、これは偶数です。 その後、その新しい値が再び奇数になるまで、その新しい値で 2 による除算を繰り返しシミュレーションできます。 これは圧縮ユークリッド アルゴリズムのように動作しますが、減算の代わりに 1 回加算してから 2 の累乗で除算する点が異なります。 差は対数スケールで繰り返し縮小されます。 

結果として得られるアルゴリズムは完全にパリティに基づいています。 値が偶数の場合は常に、概念的に 2 の因数を削除し、反対側の変数の 2 倍演算を実行します。 両方の値が奇数で等しくない場合は、小さい方を大きい方に加算し、得られた偶数の値から 2 の因数をすべて削除します。 この構造は、この問題に対する標準的な解決策です。

 ## アルゴリズムのチュートリアル

 1.読む`A`そして`B`。 それらがすでに等しい場合は、ゼロの操作を出力します。 これは、変換を実行する前にアルゴリズムを終了する必要がある唯一の状況です。 
2. その間`A`偶数であり、概念的に置き換えます`A`による`A / 2`。 実際のシーケンスでは、`B+=B`その代わり。 概念的な状態が`(A/2, B)`、両方の値を 2 倍にすると、`(A, 2B)`、まさに実際の操作によって生成された状態です。 
3. その間`B`偶数であり、概念的に置き換えます`B`による`B / 2`。 実際のシーケンスでは、`A+=A`。 同じ共通スケーリング引数が適用されます。`(A, B/2)`2を掛けると`(2A, B)`。 
4. パリティのクリーンアップ後、次の場合は`A == B`、 停止。 両方の値が奇数になるため、共通スケーリング解釈によって同等性が保たれます。 
5. 両方の値が奇数であり、`A < B`、追加`B+=A`。 概念的には、このペアは次のようになります。`(A, A+B)`。 2 つの奇数の合計は偶数であるため、2 番目の値は 2 で割り切れます。 
6. パリティのクリーンアップを続行します。 それぞれの 2 による除算は次のように表されます。`A+=A`いつ`B`は均等です。 これにより、新しく拡大された値が奇数になるまで繰り返し縮小されます。 
7. 両方の値が奇数であり、`B < A`、対称操作を実行します`A+=B`、続いてパリティのクリーンアップが行われます。 大きい値は偶数になるので、すぐに 2 の累乗で減ります。 
8. 概念的な値が等しくなるまで繰り返します。 奇数から奇数への遷移によって関連する差が 2 分の 1 に減少する一方、間に介在する半減演算は値から 2 の累乗のみを削除するため、この構築は等価に達します。 

### なぜ効果があるのか

 中心的な不変条件は、現実の状態が常に概念的な状態の共通の 2 の累乗倍数であるということです。 概念的なアルゴリズムが分裂するとき`A`2 倍すると、実際のアルゴリズムは 2 倍になります`B`、結果として得られる実際のペアは、概念的なペアのちょうど 2 倍になります。 分割するときにも同じ議論が機能します`B`。 

両方の概念的な値が奇数で等しくない場合、次のように仮定します。`A < B`。 後`B += A`、概念的なペアは`(A, A+B)`。 2 番目の値を 2 で割ると、次のようになります。`(A, (A+B)/2)`さらに分割する前に。 違いは次のようになります

 [
 \frac{A+B}{2}-A=\frac{B-A}{2}。 
】

 追加の除算が必要な場合、新しく処理される値は小さくなるだけです。 したがって、アルゴリズムはより小さいスケールのペアに繰り返し移動します。 値は正の整数であるため、プロセスは無限に継続することはできず、最終的には等価に達します。 構造とその対数的動作は、同じ問題に対する独立した解決策によって文書化されています。 

移動限界も 5000 未満に十分収まります。入力が (10^{18}<2^{60}) で区切られている場合、関連する 2 の累乗の数は最大 60 です。この構造の標準的な課金引数では、(60^2+O(60)) 程度の限界が与えられ、約 3600 回の演算が行われ、必要な 5000 より下にかなりの余地が残されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    ans = []

    while a != b:
        # Conceptually divide A by 2.
        # In the real state, double B instead.
        while a % 2 == 0:
            ans.append("B+=B")
            a //= 2

        # Conceptually divide B by 2.
        # In the real state, double A instead.
        while b % 2 == 0:
            ans.append("A+=A")
            b //= 2

        if a == b:
            break

        if a < b:
            # Conceptually: b <- a + b
            # Since a and b are odd, the new b is even.
            ans.append("B+=A")
            b += a
        else:
            # Conceptually: a <- a + b
            # Since a and b are odd, the new a is even.
            ans.append("A+=B")
            a += b

    print(len(ans))
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```2 つの内側のループは、シミュレートされた分割を実装します。 概念コードが実行されるとき`a //= 2`、実際の操作は`B+=B`。 概念的なものだけを更新します`a`将来の決定は正規化された表現に基づいて行われるため、プログラムに含まれます。 すべての概念的な状態は、対応する実際の状態と共通の因子によってのみ異なるため、出力された操作シーケンスは元の変数に対して有効なままになります。 

パリティチェックでは、`a % 2 == 0`浮動小数点演算ではなく、(10^{18}) に近い値の精度の問題はありません。 Python の任意精度の整数を使用すると、固定幅言語で次のような操作を実行するときに発生するオーバーフローの懸念も解消されます。`a += b`一時的に (2\cdot10^{18}) に近づきます。 

2 つのパリティ ループの順序は概念的に重要です。 まず、次から 2 の因数をすべて削除します。`A`、次に 2 のすべての因数`B`、その後でのみ加算を実行します。 その結果、すべての加算は 2 つの奇数の概念的な値の間で行われるため、拡大される値は必ず偶数になります。 

出力数は生成された操作リストから取得されるため、操作行数と一致することはありません。 この問題にはテスト ケースが 1 つしかないため、外側のテスト ケース ループはありません。

## テストケース

 これは建設的な問題であるため、裁判官は 1 つの正確な出力を要求しません。 サンプル出力は 1 つの有効なシーケンスのみであり、別の正しい実装ではさまざまな操作を正当に出力できます。 したがって、以下のテストでは、出力テキストをサンプル出力と文字通り比較するのではなく、生成されたシーケンスを解析してシミュレートします。```python
import sys
import io

def solve_text(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    a, b = map(int, sys.stdin.readline().split())
    ans = []

    while a != b:
        while a % 2 == 0:
            ans.append("B+=B")
            a //= 2

        while b % 2 == 0:
            ans.append("A+=A")
            b //= 2

        if a == b:
            break

        if a < b:
            ans.append("B+=A")
            b += a
        else:
            ans.append("A+=B")
            a += b

    print(len(ans))
    print("\n".join(ans))

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return result

def run(inp: str) -> str:
    return solve_text(inp)

def validate(inp: str):
    a0, b0 = map(int, inp.split())
    out = run(inp)
    lines = out.strip().splitlines()

    n = int(lines[0]) if lines else 0
    assert 0 <= n <= 5000
    assert len(lines) == n + 1

    a, b = a0, b0

    for op in lines[1:]:
        if op == "A+=A":
            a += a
        elif op == "A+=B":
            a += b
        elif op == "B+=A":
            b += a
        elif op == "B+=B":
            b += b
        else:
            raise AssertionError(f"invalid operation: {op}")

    assert a == b, f"final state is ({a}, {b})"

# Provided sample.
validate("2 3")

# Minimum-size input.
validate("1 1")

# Maximum-size values.
validate("1000000000000000000 1000000000000000000")
validate("1000000000000000000 999999999999999999")

# Boundary case with a large power of two.
validate("1 576460752303423488")

# Odd values that force the addition-and-halving transition.
validate("5 13")

 ## 特殊なケース

 のために`1 1`の場合、変数はすでに等しいため、外側のループはすぐにスキップされます。 出力は、次の内容を含む 1 行になります。`0`。 操作は必要ありません。さらに重要なことに、任意の操作を実行するとペアが不等になります。 

のために`2 3`、最初のパリティ クリーンアップで次のことがわかります。`A`は均等です。 概念的な値は次のようになります。`1`、実際の出力は`B+=B`。 実際の状態は次から変化します。`(2,3)`に`(2,6)`、これは概念の 2 倍です`(1,3)`。 次の操作`B+=A`生成する`(2,8)`、概念に対応`(1,4)`。 二`A+=A`操作により生成される`(8,8)`。 アルゴリズムが内部的により小さい値について推論した場合でも、出力は元の変数で有効です。 

のために`8 12`、最初の 2 つの概念的な還元は次のようになります。`(4,12)`そして`(4,6)`で表される`B+=B`に続く`A+=A`。 さらにパリティのクリーンアップが完了します`(2,3)`。 そこからペアは奇数で等しくないため、アルゴリズムは小さい値を大きい値に加算し、別の半減フェーズを開始します。 このケースは、実装が 1 回の除算の後で停止するのではなく、加算のたびに 2 の累乗の削除を継続しなければならない理由を示しています。 

のために`1 576460752303423488`、2 番目の値は (2^{59}) です。 パリティ ループは概念的な値を繰り返し半分にします。`B`放射しながら`A+=A`実際のシーケンスでの操作。 このような概念的な分割を 59 回行った後、ペアは次のようになります。`(1,1)`。 これはまさに、固定数のパリティ反復または浮動小数点対数を使用して実装を公開する種類の入力です。 

のために`5 13`、両方の値が奇数で等しくありません。 以来`5 < 13`、アルゴリズムは次のように出力します。`B+=A`、概念的なペアを与える`(5,18)`。 新しい 2 番目の値は偶数であるため、次に発行される操作は次のようになります。`A+=A`、概念的には次のように還元されます。`9`。 ペアは次のようになります`(5,9)`と違いは変わりました。`8`に`4`。 平等に達するまで同じメカニズムが続きます。 これは、潜在的に膨大な繰り返し加算を対数的に多くの演算で置き換えるコア削減です。
