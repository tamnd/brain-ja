 ## 解決策
 ## 問題の理解

 2 つの正の整数から始めます。`A`そして`B`。 これらを変更する唯一の方法は、現在の値の 1 つをいずれかの変数に追加することです。 したがって、演算により 1 つの変数を 2 倍にしたり、1 つの変数を 2 つの合計で置き換えたりすることができます。 目標は、2 つの値を等しくするような操作を最大 5000 回含むシーケンスを出力することです。 入力には次の初期値が含まれます。`A`そして`B`、最大でもそれぞれ\(10^{18}\)。 公式コンテストの声明には、まさにこの構造と制限があります。 citeturn3search1

 の境界\(10^{18}\)演算数が値に線形に依存するメソッドは直ちに除外されます。 必要な工事\(A+B\)、\(|A-B|\)、または \(\max(A,B)\) のステップが必要になる場合があります\(10^{18}\)操作。 5000 回の演算制限は実際のアルゴリズム上の制約であるため、対数的または同様に小さな構造が必要です。 入力には整数が 2 つしか含まれていないため、高度なデータ構造は必要なく、メモリ制限も十分に大きいため、数千の操作文字列を保存するのは簡単です。 

最初のエッジケースは、最初から平等です。 入力用`5 5`、正しい出力は単に次のとおりです。`0`, 操作が必要ないためです。 常にリダクション ループに入る不用意な実装は、不必要な操作を実行する可能性があり、さらに深刻な場合、すでに有効な答えから遠ざかってしまう可能性があります。 

2 番目のエッジ ケースは偶数値です。 入力用`4 6`、概念的にペアを次のように縮小できます。`(1, 3)`両方の値を半分にすることによって実行できますが、許可される演算には除算は含まれません。 建築はそれらの分割を間接的に実現しなければなりません。 出力中`B+=B`治療に相当する`A`公約数 2 を除いた後半分になりますが、`A+=A`～に対して対称的な役割を果たす`B`。 直接書き込み`A//=2`対応する演算を行わないと、数学的には有用な計算が生成されますが、無効な答えが得られます。 

3 番目のエッジ ケースは、奇数の値のペアです。 入力用`3 5`、小さい値を大きい値に加算すると、`(3, 8)`。 新しい大きな値は偶数であるため、正規化された表現では半分にすることができます。 代わりに、パリティを使用せずに小さい値を繰り返し加算すると、値は等しくなるどころか増加する可能性があります。 

## アプローチ

 簡単なアプローチは、考えられる操作シーケンスを検索することです。 どの州からも 4 つの選択肢があるため、\(k\)ステップはいくつでも可能です\(4^k\)考慮すべきシーケンス。 シーケンス数が 5000 のオーダーであるため、許容される深さ 5000 までの検索は完全に不可能です。\(4^{5000}\)。 値が急速に増大し、到達可能な状態が多すぎるため、状態をメモ化しても有用な限界は得られません。 

より自然な建設的な試みは、ユークリッド アルゴリズムと同じ精神で加算を使用することです。 問題は、ユークリッド アルゴリズムでは減算が必要であるのに、利用可能な演算はすべて加算のみであることです。 たとえば、から始めて、`(1, 1000000000000000000)`減算を直接エミュレートしようとすると、小さい値を大きい値に繰り返し加算する必要があるため、膨大な数の加算が必要になります。 

重要な観察は、両方の数値に同じ正の係数を掛けても、それらが等しいかどうかには影響しないということです。 2 つの共通因数を除算して得られる正規化されたペアについては、自由に推論できます。 これにより、2 倍演算を仮想の 2 倍演算として再解釈できます。 

正規化されたペアが次のようになると仮定します。`(A, B)`そして`A`は均等です。 実際に操作してみると`B+=B`、物理ペアは次のようになります。`(A, 2B)`。 概念的に両方の値を 2 で割ると、これは次と同等になります。`(A/2, B)`。 したがって、1 つの正当な操作により、半分にするのと同じ正規化された状態が得られます。`A`。 同様に、`A+=A`半減とみなせる`B`正規化された表現では。 

正規化された値が両方とも奇数になったら、次のようにします。`A < B`。 出演します`B+=A`、与える`(A, A+B)`。 両方のオペランドが奇数だったので、`A+B`は偶数であるため、次の正規化ではその大きい値を 2 で割ることができます。 概念的な変遷は、\[
(A,B)\rightarrow \left(A,\frac{A+B}{2}\right).
\]これが決定的な削減です。 もし`B-A=C`この移行後の新しい違いは次のようになります。\[
\frac{A+B}{2}-A=\frac{B-A}{2}=\frac C2.
\]したがって、両方の値が奇数の場合、1 回の加算とその後の正規化により、差はおよそ半分になります。 これは、バイナリ ユークリッド アルゴリズムの背後にある同じパリティの考え方です。 

結果として得られる構築では、2 の因数を繰り返し削除し、小さい方の奇数値を大きい方の奇数に加算します。 正規化された値は、両方が 1 になるまで着実に減少します。この時点では、すべての変換で等価関係が維持されているため、実際の値は等しくなります。 詳細な操作数引数では、5000 未満の限界が与えられ、より厳密な分析では、最大値に対して 3969 回の操作が与えられます。\(10^{18}\)。 citeturn4view0

 ## アルゴリズムのチュートリアル

 1.キープ`a`そして`b`推論に使用される正規化された値として。 これらは、すべての操作の後に裁判官によって保存されたリテラル値を表すものではありません。 代わりに、これらは 2 の共通因数を削除した後の等価なペアを表します。 

2. その間`a`偶数である場合は追加します`B+=B`答えに置き換えてください`a`による`a // 2`。 実際の操作は2倍になります`B`、概念的に両方の値を 2 で割った後の正規化された状態は、半分にしたのとまったく同じになります。`a`。 

3. その間`b`偶数である場合は追加します`A+=A`そして交換してください`b`による`b // 2`。 これが対称変換です。 実際の操作は2倍になります`A`、これは半分に相当します`B`2 の共通因数を削除した後。 

4. もし`a == b`、 停止。 正規化された値は等しいため、それらによって表される実際の値も同様に等しくなります。 

5. 正規化された値が両方とも奇数であり、`a < b`、追加`B+=A`そして交換してください`b`による`a + b`。 2 つの奇数の合計は偶数なので、次の反復で半分にすることができます。`b`。 

6. 両方の正規化値が奇数であり、`b < a`、追加`A+=B`そして交換してください`a`による`a + b`。 ここでも、更新された大きい値は偶数であり、次の反復の開始時に半分になります。 

プロセスが進歩する理由は、違いから見るのが最も簡単です。 仮定する`a < b`そして両方とも奇妙です。 足し算とその後の半分の後、差は次のようになります。`(b-a)/2`。 したがって、加算ステップが必要になるたびに、2 つの正規化された値間の距離は 2 分の 1 に減少します。 パリティ削除手順により、数値自体が減少します。 

### なぜ効果があるのか

 不変条件は、正規化されたペアであることです。`(a, b)`は、両方の値に同じ 2 の正の累乗を乗算するまでの現在の実際のペアを表します。 このような共通のスケーリングでは、2 つの値が等しいかどうかを変更することはできません。 

いつ`a`均等です、`B+=B`実際のペアをから変更します`(A,B)`に`(A,2B)`。 両方を 2 で割ると、`(A/2,B)`なので、正規化されたものを置き換えます`a`による`a/2`合法です。 同じ議論が次の場合にも当てはまります`b`は均等です。 

両方の正規化された値が奇数で等しくない場合、小さい方を大きい方に加算することは正当な演算です。 結果として得られる大きい値は偶数であり、次の正規化により半分になります。 小さい方の値の場合`a`、ペアは概念的に から変わります。`(a,b)`に`(a,(a+b)/2)`。 新たな違いは、`(b-a)/2`したがって、プロセスでは同じプラスの差を永久に維持することはできません。 最終的に、正規化された値は等しくなり、不変式により実際の値も等しいことがわかります。 

操作数も 5000 の制限に対して十分小さいです。 有用な限界の 1 つは、正規化された値の積が少なくとも 2 分の 1 に減少するフェーズにプロセスをグループ化することです。 このような各フェーズに必要なのは、最大でも\(2\lfloor\log_2 B\rfloor+1\)動作、初期製品は以下のため\(10^{36}\)、これらの境界を合計すると、演算数は 7200 未満になります。 よりシャープな位相解析により、必要な限界は 3969 となり、5000 を余裕で下回ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    ans = []

    while a != b:
        while a % 2 == 0:
            ans.append("B+=B")
            a //= 2

        while b % 2 == 0:
            ans.append("A+=A")
            b //= 2

        if a == b:
            break

        if a < b:
            ans.append("B+=A")
            b += a
        else:
            ans.append("A+=B")
            a += b

    print(len(ans))
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```問題には値のペアが 1 つしかないため、入力は 1 回読み取られます。 の`ans`配列には、出力する必要がある正確な正当な操作が格納されます。 

最初`while`ループは 2 のすべての因数を処理します。`a`。 答えに追加される操作は次のとおりです`B+=B`、 ない`A+=A`他の実際の値を 2 倍にすることで半分になるためです。`A`共通の正規化後に有効です。 この逆転は、最も間違いやすい実装の詳細です。 

2 番目のループは対称操作を実行します。`b`。 元の値は最大でも\(10^{18}\), Python の整数は十分すぎるほどであり、オーバーフローの問題はありません。 

両方のループの後、正規化された値が等しい場合、構築は終了します。 そうでなければ両方とも奇数です。 ちょうど 1 つの方が大きいため、小さい方を大きい方に追加します。 新しい大きな値は偶数であるため、次の反復で有用な作業が保証されます。 

コードは、各操作後の実際の値を明示的にシミュレートしません。 そうすることは不必要であり、推論が混乱する可能性があります。 各半分のステップは実際のペアから共通因数 2 を削除することを表すため、正規化された値で十分です。

 ## 特殊なケース

 のために`5 5`、アルゴリズムは外側のループ条件に入ります。`a != b`、それがすでに false であることを確認し、すぐにゼロの操作を出力します。 ターゲット条件がすでに成立しているため、これが唯一の賢明な構成です。 

のために`4 6`、正規化されたアルゴリズムは、最初に 2 の因数を除去します。`a`。 最初`B+=B`を表します`4 -> 2`、2番目は次を表します`2 -> 1`。 それから`A+=A`を表します`6 -> 3`。 正規化された状態は次のとおりです`(1,3)`。 操作`B+=A`概念的に次のように変更します`(1,4)`、その後2つ`A+=A`演算は表す`4 -> 2 -> 1`。 正規化された状態に達すると、`(1,1)`、実際の値は次の値に達しました`(32,32)`。 

のために`1 1000000000000000000`、大きな値には 2 の因数が多く含まれます。 アルゴリズムはこれらの要素を次のように削除します。`A+=A`操作を実行するのではなく、正規化された表現で操作します。\(10^{18}\)個別の追加。 残りの奇数部分が露光されると、加算ステップによって関連する差が繰り返し半分になります。 これはまさに、直接加算的なアプローチは失敗するが、パリティ ベースの構築は動作制限内に留まる状況です。 

のために`999999999999999999 1000000000000000000`、値は隣接していますが、逆のパリティを持っています。 最初のパリティ除去ステージでは、偶数の正規化値が仮想的な半分によって直ちに変更されます。 このアルゴリズムでは、元の値が両方とも奇数であるとは決して想定されず、パリティ削除ループ後に両方とも奇数であるとのみ想定されます。 この境界条件により、奇数プラス奇数遷移の誤った適用が防止されます。 

のために`1 1`、可能な最小限の入力である場合、答えは再びゼロになります。 のために`1000000000000000000 1000000000000000000`、可能な最大の等しい入力は同じように動作します。 すでに等しい場合、整数の大きさは影響を及ぼしません。
