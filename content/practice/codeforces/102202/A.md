 ## 解決策
 ## 問題の理解

 長さ (N) の文字列があり、すべての宝石は次のいずれかになります。`R`、`B`、 または`V`。 1 つの連続した部分文字列を選択し、その最大長が必要な場合があります。 

選択された部分文字列は、3 人の異なる観察者にとって多様に見える必要があります。 通常の観察者は 3 つの色すべてを区別しますが、赤色盲の観察者は 3 つの色をすべて区別します。`V`として`R`、そして青色盲の観察者が扱います`V`として`B`。 すべての観察者にとって、隣接する宝石は異なる色を知覚するはずです。 

これら 3 つの要件を組み合わせる便利な方法は、隣接する元の色の考えられるすべてのペアを調べることです。 通常の観察者にとって、2 つの同じ色は禁止されています。 ペア`R,V`赤色盲の観察者には禁止されています。`R,R`。 ペア`B,V`青色盲の観察者には禁止されています。`B,B`。 したがって、考えられるすべての異なるペアのうち、生き残る唯一のペアは、`R,B`。 

これは、問題をより簡単に言い換えたものです。少なくとも 2 つの長さの有効な部分文字列には、`R`そして`B`、すべての隣接するペアが交互になる必要があります。 あ`V`長さ 1 の有効な部分文字列にのみ出現できます。 

限界 (N \le 250,000) は、意図したソリューションで二次アルゴリズムまたはそれより劣ったアルゴリズムを除外します。 1 回のリニア スキャンでは、ジュエルごとに一定量の作業のみが実行されます。これは、Python の 1 秒の制限内に余裕で収まります。 位置のすべてのペアを検査するアルゴリズムでは、最大入力サイズですでに約 310 億のペア チェックが実行されるため、有効な部分文字列の構造を直接利用する必要があります。 

元の定義のみに基づいた実装が失敗する可能性がある小さなケースがいくつかあります。 入力用`1`に続く`V`、答えは`1`なぜなら、1 宝石の部分文字列には、条件に違反する隣接するペアがないからです。 交互だけを求めるいいかげんな実装`R`そして`B`誤ってゼロを返す可能性があります。 

入力用`3`と`RVB`、答えは`1`。 オリジナルカラーは3色とも異なりますが、`RV`になる`RR`赤色盲の観察者にとって、そして`VB`になる`BB`青色盲の観察者のために。 隣接する元の文字が異なるかどうかだけをチェックすると、文字列全体が誤って受け入れられてしまいます。 

入力用`4`と`RBRB`、答えは`4`。 すべての隣接するペアは次のいずれかです`RB`または`BR`したがって、3 人の観測者全員が境界ごとに異なる色を認識します。 複数の色の存在をあまりにも大雑把に扱う実装では、完全に交互になっている色を見逃す可能性があります。`R/B`文字列は有効です。 

## アプローチ

 直接的なブルート フォース ソリューションでは、すべての連続する部分文字列を列挙し、それが 3 つのオブザーバーすべてを満たすかどうかをテストできます。 部分文字列の場合、隣接するすべてのペアをチェックするにはその長さに比例して時間がかかるため、最良の回答を更新する前に定義を明示的に検証するため、このアプローチは正しいです。 

問題は部分文字列の数です。 それらは (N(N+1)/2) 個あり、それぞれを最初からチェックすると、文字検査の総数は次のようになります。 

\frac{N(N+1)(N+2)}{6}。 
】

 (N=250,000) の場合、これは約 (2.6\times10^{15}) 回の操作となり、制限時間を大幅に超えます。 無効な境界に遭遇するまで各開始位置を拡張する改良された総当り実装でも、最悪の場合でも (O(N^2)) かかります。これは、文字列が交互になるとすべての拡張が継続できるためです。 

重要な観察は、3 つの色盲条件により、隣接するペアがすべて排除されるということです。`R,B`そして`B,R`。 これが認識されると、任意の部分文字列を検査する必要はなくなります。 必要なのは、すべての隣接するペアが異なるペアで構成される最長の連続実行のみです。`R`そして`B`文字。 

この特性は、左から右へのスキャン中に維持できます。 現在のキャラクターが`R`または`B`前のキャラクターとは異なり、現在の交互のランは 1 つ延長されます。 それ以外の場合は、現在の実行を現在の文字から再開する必要があります。 あ`V`少なくとも 2 の長さの有効な部分文字列にはそれを含めることができないため、常に長さ 1 の新しいランが開始されます。 

ブルート フォースは、可能なすべての間隔を明示的にテストするため機能しますが、間隔が多すぎるため失敗します。 有効なローカル遷移が正確に次のとおりであるという観察`R -> B`そして`B -> R`問題は、1 回のパスで実行できる最長の交互実行を 1 つ見つけることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^3)) すべての部分文字列を最初からチェックする場合 | (O(1)) | 遅すぎる |
 | 早期停止によるブルートフォース | (O(N^2)) | (O(1)) | 遅すぎる |
 | 最適なスキャン | (O(N)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取り、現在の有効なランレングスをゼロに初期化し、最大応答をゼロに初期化します。 ランは、すべての隣接するペアが有効である現在位置で終わるサフィックスを表します。 
2. 文字列を左から右に処理します。 最初の文字では、長さ 1 のランを開始します。 前の文字がないため、チェックする境界がありません。 
3. 以降のすべての文字について、現在の文字と前の文字の両方が次の文字に属しているかどうかを確認します。`{R, B}`そしてそれらは違うのかどうか。 これはまさに、新しい隣接ペアが次のいずれかであるという条件です。`RB`または`BR`。 
4. その条件が当てはまる場合は、現在のランレングスを 1 つ増やします。 新しく追加された境界は有効であり、実行内の以前の境界はすべてすでに有効です。 
5. それ以外の場合は、現在の文字から長さ 1 の新しいランを開始します。 これは両方をカバーします。`V`そして次のような繰り返しの色`RR`または`BB`。 どちらも以前の有効な部分文字列を拡張することはできません。 
6. 現在のラン長を決定した後、最大応答を更新します。 スキャン中に検出された最長の実行が、最長の有効な部分文字列になります。 

### なぜ効果があるのか

 不変条件は、位置 (i) を処理した後、`current`位置 (i) で終わる最長の有効な部分文字列の長さです。 新しい境界が`RB`または`BR`、現在の文字を追加すると有効性が保持されるため、前の実行が 1 つ延長されます。 他のすべての境界では、長さが 2 以上の有効な部分文字列はその境界を越えることができないため、現在位置で終わる唯一の有効な部分文字列の長さが 1 になります。 これらの終了長の最大値を取得すると、考えられるすべての有効な部分文字列が正確に終了する位置が考慮されるため、最終的な最大値が全体的な最適値となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    best = 1
    current = 1

    for i in range(1, n):
        if s[i] in "RB" and s[i - 1] in "RB" and s[i] != s[i - 1]:
            current += 1
        else:
            current = 1

        if current > best:
            best = current

    print(best)

if __name__ == "__main__":
    solve()
```入力は次を使用して読み取られます`sys.stdin.readline`これは長さ (250,000) の文字列には十分であり、不要な入力オーバーヘッドを回避できます。`current`現在の位置で終わる有効な代替サフィックスの長さを格納します。 条件```
s[i] in "RB" and s[i - 1] in "RB" and s[i] != s[i - 1]
```位置間の境界かどうかを正確にチェックします`i - 1`そして`i`許可されています。 両方の文字は非`V`、それらは異なるはずです。 アルファベットには以下しか入っていないので、`R`、`B`、 そして`V`、これは、ペアが次のとおりであると言うのと同じです。`RB`または`BR`。 

条件が満たされない場合、`current`になる`1`、 それよりも`0`。 現在の宝石自体は、たとえそうであったとしても、常に有効な 1 宝石ビーズです。`V`。 

答えは次のように初期化されます`1`なぜなら (N \ge 1)。 これはすべてのことも処理します。`V`特別な分岐がない場合。 Python では整数オーバーフローは発生せず、保存される入力サイズのオブジェクトは文字列自体だけです。

 入力は`RBRBB`。 最初の 4 文字は交互に続きます。`R/B`順序。 決勝戦`B`他に隣接している`B`, したがって、新しい実行が開始されます。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())
    s = input().strip()

    best = 1
    current = 1

    for i in range(1, n):
        if s[i] in "RB" and s[i - 1] in "RB" and s[i] != s[i - 1]:
            current += 1
        else:
            current = 1

        best = max(best, current)

    print(best)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("4\nRBBB\n") == "2", "sample 1"
assert run("5\nRBRBB\n") == "4", "sample 2"

# Minimum-size input
assert run("1\nV\n") == "1", "single V"

# All equal values
assert run("5\nRRRRR\n") == "1", "all equal"

# V cannot participate in a valid substring of length > 1
assert run("3\nRVB\n") == "1", "V blocks both neighboring transitions"

# Maximum-size input
n = 250000
s = "".join("R" if i % 2 == 0 else "B" for i in range(n))
assert run(f"{n}\n{s}\n") == str(n), "maximum alternating string"

# Boundary and off-by-one case
assert run("6\nBRBBRB\n") == "3", "longest run is BRB"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / V`| 1 | 最小サイズと単一の`V`有効です |
 |`5 / RRRRR`| 1 | 繰り返しの色は有効な隣接ペアを形成できません。 
|`3 / RVB`| 1 |`V`どちらにも隣接することはできません`R`または`B`|
 |`250000 / RBRB...`| 250000 | 最大入力サイズと完全な文字列に達する実行 |
 |`6 / BRBBRB`| 3 | 無効な境界の後で再起動し、off-by-one エラーを回避する |
