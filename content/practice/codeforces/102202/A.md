 ## 解決策
 ## 問題の理解

 長さ (N) の文字列があり、すべての宝石に色が付けられています。`R`、`B`、 または`V`。 連続した部分文字列を 1 つ選択して、それを渡すことができます。 選択された部分文字列は、3 人の異なる観察者にとってカラフルに見える必要があります。 

通常の観察者は3色すべてを区別できるため、隣接する宝石は異なる本来の性質を持っているはずです。 赤色盲の観察者は見る`R`そして`V`青色盲の観察者には同じ色が見えますが、`B`そして`V`同じ色として。 選択した部分文字列には、これらの観測点のいずれに対しても隣接する同じ色があってはなりません。 

重要な結果は、元の状態が最初に示唆するよりも強力です。 以下を含む隣接するペアを考慮します。`V`。 他の宝石があれば`R`、赤色盲の観察者には、2 つの連続した赤い宝石が見えます。 他の宝石があれば`B`、青色盲の観察者には、2 つの連続した青い宝石が見えます。 ペアの場合`VV`、誰もが同じ色に見えます。 したがって`V`有効な部分文字列内の何かに隣接させることはできません。 

3 人の観測者全員が生き残る唯一の隣接ペアは、`RB`または`BR`。 したがって、少なくとも 2 つの長さの有効な部分文字列には、`R`そして`B`、これらの文字は交互に配置する必要があります。 

例えば、`RBRB`は有効ですが、`RVB`そうではありません。 単一の宝石のような`V`隣接するペアがまったくないため、常に有効です。 

入力には最大 (250,000) 個の宝石を含めることができます。 (O(N^2)) アルゴリズムは、おおよそ (N(N+1)/2) 個の部分文字列を検査します。これは、(N=250,000) の場合、約 (312 億 5,000 万) 個になります。 それは1秒の制限時間をはるかに超えています。 文字列を一定の回数だけ検査して、(O(N)) 個の解を得る必要があります。 

誤った実装を容易に引き起こす可能性のあるいくつかの特殊なケースがあります。 

考慮する```
1
V
```答えは`1`。 交互に検索するだけのソリューション`R`そして`B`セグメントは、単一のジュエルが常に有効であることを忘れて、誤ってゼロを返す可能性があります。 

考慮する```
4
RVBR
```答えは`1`。 それでも`V`は隣接する文字のいずれとも等しくないため、隣接することはできません`R`赤みのない色覚異常の観察者のため、または`B`青色盲の観察者のために。 元の文字列内の隣接する文字のみをチェックするソリューションでは、次の文字列を含む部分が誤って受け入れられてしまいます。`V`。 

考慮する```
5
RBRBB
```答えは`4`、 から`RBRB`。 決勝戦`BB`交互パターンが壊れるため、無効なペアを検出した後に現在の長さを維持する不注意な実装はオーバーカウントする可能性があります。 

ついに、```
5
RRRRR
```答えがあります`1`。 等隣接`R`Jewel はすぐに無効になりますが、個々の Jewel は有効な部分文字列のままです。 

## アプローチ

 直接的なアプローチは、すべての連続する部分文字列を列挙し、それが 3 人の観察者全員にとってカラフルであるかどうかを確認することです。 (N(N+1)/2) 個の部分文字列があります。 各部分文字列がその隣接するペアをすべてスキャンすることによってチェックされる場合、最悪の場合の作業は (O(N^3)) になりますが、これは明らかに不可能です。 

開始位置を固定し、部分文字列を一度に 1 ジュエルずつ拡張することで、この素朴な考えを少し改善することができます。 無効な隣接ペアが出現すると、同じ位置で始まる長い部分文字列もすべて無効になるため、部分文字列全体を再スキャンする必要はありません。 これにより、作業が (O(N^2)) に削減されます。これは、最悪の場合でも、すべての開始位置に対してすべての可能な終了位置を検査するためです。 (N=250,000) の場合、これは約 (312 億 5) 億拡張ですが、それでも多すぎます。 

妥当性は隣接するペアによって完全に決定されるため、ブルートフォースアプローチが機能します。 有益な観察は、3 つのオブザーバーすべての要件を組み合わせると、ほぼすべてのペアが禁止されるということです。`R`の隣に`B`が唯一の有効なペアです。 あ`V`1 を超える長さの有効な部分文字列に参加することはできません。 

つまり、任意の部分文字列を考慮する必要がまったくありません。 すべての文字が含まれる最長の連続セクションを見つけるだけで済みます。`R`または`B`そして隣接するペアはすべて異なります。 このようなセクションは、単に次のような交互のシーケンスです。`RBRBR`または`BRBRB`。 

文字列を 1 回スキャンできます。 現在のキャラクターが交互に続けている間、`R`/`B`シーケンスの長さを増やします。 それ以外の場合、現在の文字が次の場合、長さ 1 の新しいシーケンスを開始します。`R`または`B`。 のために`V`、シーケンスが通過できなくなるため、現在の長さは 1 になります。 

単一の宝石は常に有効であるため、答えは少なくとも 1 つです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^3)) | (O(1)) | 遅すぎる |
 | インクリメンタルブルートフォース | (O(N^2)) | (O(1)) | 遅すぎる |
 | 最適なスキャン | (O(N)) | (O(1)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取り、最適な有効長を初期化します。`1`。 1 つの宝石の部分文字列には隣接するペアがないため、常にカラフルです。 
2. メンテナンス`cur`、現在の位置で終わる最長の有効な部分文字列の長さ。 最初は`cur = 1`。 
3. 最初の文字以降のすべての位置について、前の文字と現在の文字を検査します。 両方ある場合`R`または`B`それらは異なり、ペアは 3 つのオブザーバーすべてに対して有効であるため、次のように設定して現在の部分文字列を拡張します。`cur += 1`。 
4. そうしないと、前の部分文字列をこの位置まで拡張できません。 セット`cur = 1`なぜなら、現在のジュエル自体は常に有効な部分文字列だからです。 
5.グローバル回答を次のように更新します。`max(ans, cur)`各文字を処理した後。 

無効なペアの直後に前の部分文字列を破棄できる理由は、現在位置で終了し、無効なペアの前から始まるすべての長い部分文字列には、同じ禁止された隣接ペアが含まれるためです。 どれも保存しておいてもメリットはありません。 

### なぜ効果があるのか

 少なくとも 2 つの長さの部分文字列が 3 人の観測者全員にとってカラフルであるためには、すべての隣接するペアが 3 つの色の解釈すべてに対して有効でなければなりません。`R-B`そして`B-R`そのようなペアは だけです。 を含むすべてのペア`V`少なくとも 1 人のオブザーバーに対しては無効であり、等しい`R`または同等`B`ペアは通常のオブザーバーには無効です。 

したがって、長さが少なくとも 2 の有効な部分文字列は、正確に次の交互シーケンスになります。`R`そして`B`。 スキャン中に、`cur`正確には、現在の位置で終わるそのような最長のシーケンスです。 有効な`R/B`ペアはそれを拡張しますが、他のペアは拡張を不可能にし、最も有効なサフィックスが現在の単一ジュエルになるように強制します。 の最大値を取ると、`cur`すべての位置にわたって、結果的に最長の有効な連続部分文字列が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    ans = 1
    cur = 1

    for i in range(1, n):
        if s[i] in "RB" and s[i - 1] in "RB" and s[i] != s[i - 1]:
            cur += 1
        else:
            cur = 1

        if cur > ans:
            ans = cur

    print(ans)

if __name__ == "__main__":
    solve()
```入力は次のように読み取られます`readline`これは、長さ (250,000) の文字列には十分です。 文字列自体は一度保存されます。`cur`現在の位置で終わる有効な接尾辞を表します。 条件```
s[i] in "RB" and s[i - 1] in "RB" and s[i] != s[i - 1]
```新しい隣接ペアが次のいずれかであるかどうかを正確にチェックします。`RB`または`BR`。 メンバーシップを確認中`RB`必要なので`V`1 を超える長さの有効な部分文字列には含めることはできません。 

条件が満たされない場合、`cur`になる`1`それよりも`0`。 これは、次のような通常の休憩の両方を処理します。`BB`そして特別な場合`V`。 現在の Jewel は、常にそれ自体で新しい有効な部分文字列を開始できます。 

Python には整数オーバーフローの問題はありません。`cur`(N) を超えることはありません。 スキャンはインデックスから開始されます`1`したがって、前の文字へのアクセスは常に文字列内にあります。

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n = int(input())
    s = input().strip()

    ans = 1
    cur = 1

    for i in range(1, n):
        if s[i] in "RB" and s[i - 1] in "RB" and s[i] != s[i - 1]:
            cur += 1
        else:
            cur = 1

        ans = max(ans, cur)

    sys.stdin = old_stdin
    return str(ans)

# Provided samples
assert solution("4\nRBBB\n") == "2", "sample 1"
assert solution("5\nRBRBB\n") == "4", "sample 2"

# Minimum-size input
assert solution("1\nV\n") == "1", "single V is always valid"

# All equal values
assert solution("5\nRRRRR\n") == "1", "equal adjacent colors are invalid"

# V cannot be part of a multi-character valid substring
assert solution("5\nRVBRB\n") == "4", "longest valid part is BRBR"

# Maximum-size input
assert solution("250000\n" + "RB" * 125000 + "\n") == "250000", \
    "entire maximum-length alternating string is valid"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1\nV\n`|`1`| 最小サイズと単一の`V`有効です |
 |`5\nRRRRR\n`|`1`| 同じ色を繰り返すとシーケンスが壊れる必要があります。 
|`5\nRVBRB\n`|`4`|`V`| 1 を超える長さの有効な部分文字列に属することはできません。 
|`250000\n`に続く`RB`125000 回繰り返しました |`250000`| 最大入力サイズと全長境界の場合 |

 ## 特殊なケース

 単一宝石ケースの場合```
1
V
```隣接するペアがないため、ループは実行されません。`ans`から始まります`1`、アルゴリズムは次のように出力します`1`。 これが、選択された初期化が自然に問題の保証 (N \ge 1) と一致する一方で、実装が空のスキャンを個別に処理した場合にのみ、答えをゼロに初期化することも機能する理由です。 

以下を含む部分文字列の場合`V`、 考慮する```
4
RVBR
```位置で`1`、ペア`RV`は無効なので、`cur`になる`1`。 位置で`2`、ペア`VB`も無効なので、`cur`残っている`1`。 位置で`3`、`BR`有効なので、`cur`になる`2`。 答えは`2`、最後の部分文字列に対応します`BR`。 これは次のことを示しています`V`は、単に 2 つのシーケンス間の区切り文字であるだけでなく、マルチジュエルの有効な部分文字列にまったく参加できないことを意味します。 

繰り返しカラーの場合は、```
5
RRRRR
```すべての隣接するペアは`RR`。 各ペアは交互に失敗します`R/B`状態なので、`cur`繰り返しリセットされる`1`。 最大値が残る`1`これは正しいです。なぜなら、少なくとも 2 の長さの部分文字列には、等しい隣接する赤い宝石が含まれているからです。 

最長シーケンスが最後に到達する境界の場合、```
5
BRBRB
```すべてのペアが有効です。`cur`進行する`1, 2, 3, 4, 5`、 そして`ans`到達する`5`。 最後の文字の処理中に応答が更新されるため、特別な文字列の終わりの処理はありません。 

最大サイズの交流入力の場合、次で構成されます。`250000`パターン内の文字`RBRB...`、すべての隣接するペアは次のいずれかです`RB`または`BR`。 したがって、現在の長さは次のようになります。`250000`、アルゴリズムはビーズ全体​​を返します。 これにより、リニア スキャンが特別な場合のロジックを使用せずに、許容される最大の入力を処理できることが確認されます。
