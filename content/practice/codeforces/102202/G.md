### なぜ効果があるのか

 頂点で終わるすべての増加するサブシーケンスは、階層化された LIS DAG を通るパスになります。 頂点は、対応する DAG 頂点を支配する場合に、そのようなすべてのサブシーケンスに存在します。 ドミネーター ツリーの不変条件では、頂点のすべてのドミネーターが正確にそのツリーの祖先であるため、ツリーの深さはそれらをカウントします。 

DAG の場合、頂点の直接のドミネーターは、すでに構築されているドミネーター ツリー内のすべての先行する頂点の LCA です。 位置が増加するにつれて、等しい LIS レイヤーの値が厳密に減少するため、スライディング ウィンドウにはこれらの先行レイヤーが正確に含まれます。 したがって、アルゴリズムによって選択されたすべての親が、正しい直接のドミネーターになります。 同じ引数を反転および補完順列に適用すると、不可避の接尾辞要素が得られます。 増加するサブシーケンスの接頭辞と接尾辞には次のものが含まれるため、`i`一度独立する`i`が固定されている場合、2 つのカウントを加算すると、削除によって最適値が減少するインデックスが正確に得られます。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve_dom_depth(a):
    n = len(a)

    # layers[k] contains indices whose LIS-ending length is k + 1.
    layers = []
    tails = []

    for i, x in enumerate(a):
        k = bisect_left(tails, x)
        if k == len(tails):
            tails.append(x)
            layers.append([])
        else:
            tails[k] = x
        layers[k].append(i)

    log = (n + 1).bit_length()

    # Binary lifting table for the dominator tree.
    up = [[0] * n for _ in range(log)]
    depth = [0] * n

    def lca(a1, a2):
        if a1 == a2:
            return a1

        if depth[a1] < depth[a2]:
            a1, a2 = a2, a1

        diff = depth[a1] - depth[a2]
        bit = 0
        while diff:
            if diff & 1:
                a1 = up[bit][a1]
            diff >>= 1
            bit += 1

        if a1 == a2:
            return a1

        for k in range(log - 1, -1, -1):
            if up[k][a1] != up[k][a2]:
                a1 = up[k][a1]
                a2 = up[k][a2]

        return up[0][a1]

    class AggQueue:
        def __init__(self):
            self.in_nodes = []
            self.in_agg = []
            self.out_nodes = []
            self.out_agg = []

        def push(self, v):
            self.in_nodes.append(v)
            if self.in_agg:
                self.in_agg.append(lca(self.in_agg[-1], v))
            else:
                self.in_agg.append(v)

        def _transfer(self):
            while self.in_nodes:
                v = self.in_nodes.pop()
                self.in_agg.pop()

                self.out_nodes.append(v)
                if self.out_agg:
                    self.out_agg.append(lca(v, self.out_agg[-1]))
                else:
                    self.out_agg.append(v)

        def pop(self):
            if not self.out_nodes:
                self._transfer()
            self.out_nodes.pop()
            self.out_agg.pop()

        def empty(self):
            return not self.in_nodes and not self.out_nodes

        def query(self):
            if not self.out_nodes:
                return self.in_agg[-1]
            if not self.in_nodes:
                return self.out_agg[-1]
            return lca(self.out_agg[-1], self.in_agg[-1])

    # Layer 0 has no real predecessor.
    for v in layers[0]:
        depth[v] = 1

    for k in range(1, len(layers)):
        prev = layers[k - 1]
        cur = layers[k]

        q = AggQueue()

        left = 0
        right = 0
        m = len(prev)

        for v in cur:
            # Add all previous-layer vertices with position < v.
            while right < m and prev[right] < v:
                if right >= left:
                    q.push(prev[right])
                right += 1

            # Remove vertices whose value is not smaller than a[v].
            # Values in prev are strictly decreasing.
            while left < right and a[prev[left]] >= a[v]:
                q.pop()
                left += 1

            if q.empty():
                parent = 0
                depth[v] = 1
            else:
                parent = q.query()
                depth[v] = depth[parent] + 1

            up[0][v] = parent
            for j in range(1, log):
                up[j][v] = up[j - 1][up[j - 1][v]]

    return depth

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    left = solve_dom_depth(a)

    transformed = [n + 1 - x for x in reversed(a)]
    right_rev = solve_dom_depth(transformed)

    ans = [0] * n
    for i in range(n):
        right = right_rev[n - 1 - i]
        ans[i] = left[i] + right - 2

    print(*ans)

if __name__ == "__main__":
    solve()

の`up`テーブルはドミネーター ツリーを表します。`up[0][v]`～の直接の支配者である`v`、一方、上位の行には 2 のべき乗の祖先が含まれます。 仮想ソースはインデックスで表されます`0`テーブルでは、実際の配列の頂点がゼロから始まるインデックスを使用しているにもかかわらずです。 ソースは特別な親値で表されるため、実際の頂点をソースと混同することはありません。`0`、 その間`depth[0]`暗黙的にゼロです。 

LCA ルーチンは、最初に深さを均等化し、次に両方の頂点を一緒に持ち上げます。 最大の揚力は、`(N+1).bit_length()`これは、考えられるすべてのツリーの深さを表すのに十分です。

2つの指針`left`そして`right`前の LIS 層の先行間隔を記述します。 条件`prev[right] < v`位置制限を処理します。 条件`a[prev[left]] >= a[v]`先行できない値を削除します`v`厳密に増加するサブシーケンス。 の使用`>=`それよりも`>`サブシーケンスは厳密に増加する必要があるため、これが必要です。

assert run("9\n1 2 3 6 5 4 7 8 9\n") == "5 5 5 6 6 6 5 5 5", "sample 5"

# Single element.
assert run("1\n7\n") == "0", "minimum size"

# Strictly decreasing permutation.
assert run("5\n5 4 3 2 1\n") == "0 0 0 0 0", "all LIS have length 1"

# A case with two different choices on one side.

# A longer case where both prefix and suffix dominators matter.
assert run("4\n3 1 2 4\n") == "1 2 2 2", "prefix and suffix dominance"

# Equal values are outside the permutation constraints, but are useful

assert run("3\n5 5 5\n") == "0 0 0", "equal values"

n = 250000

 ## 特殊なケース

 単一要素入力の場合`1 / 1`、唯一の頂点が最初の LIS レイヤーに配置されます。 そのドミネーターの深さは`1`元のシーケンスと変換されたシーケンスの両方で。 式は次のようになります`1 + 1 - 2 = 0`したがって、アルゴリズムが選択されたインデックス自体を誤ってカウントすることはありません。 

次のような厳密に増加する配列の場合、`1 2 3`、各レイヤーには頂点が 1 つだけ含まれます。 したがって、先行ウィンドウには最初以外の頂点ごとに 1 つの要素が含まれており、ドミネーター ツリーは単なるチェーンです。 深さは`1, 2, 3`左からと`3, 2, 1`右から、与える`2, 2, 2`。 これは、他のすべての要素が本当に必要な場合を例にしています。 

次のような厳密に減少する配列の場合、`3 2 1`、すべての頂点は最初の LIS 層にあります。 実際の頂点間にはエッジがないため、すべてのドミネーターの深さは次のようになります。`1`。 変換された配列には同じプロパティがあります。 最後の式はどこでもゼロを生成し、選択された要素が長さ 1 で増加するサブシーケンスにのみ参加できる場合を正しく処理します。 

のために`1 3 2`、左側のレイヤーは`[0]`そして`[1, 2]`。 インデックス用`1`、先行ウィンドウにはインデックスが含まれています`0`、インデックス`0`それを支配します。 インデックス用`2`、先行ウィンドウにもインデックスが含まれています`0`、インデックス作成`0`避けられないプレフィックス要素。 右側にインデックス`1`その後に大きな要素はありませんが、インデックス`2`接尾辞拡張子はありません。 2 つの方向を組み合わせると、`0 1 1`。 この例では、値の境界を無視して、同じ LIS レイヤー内のすべての要素を先行要素の可能性があるものとして扱うという間違いを特に捉えています。 

のために`3 1 2 4`、左のドミネーターの深さは次のとおりです。`1, 1, 2, 3`。 値`1`で終わるサブシーケンスを支配します`2`、そして両方`1`そして`2`で終わる後続を支配する`4`。 変形したパスが右側に奥行きをもたらす`2, 3, 2, 1`。 それらを組み合わせると、`1 2 2 2`。 このケースは、ドミネーター ツリーの複数の層を介して頂点が避けられない可能性があるため、直接の先行ノードを単に数えるだけでは不十分である理由を示しています。 

次のような等しい値の場合`5 5 5`、公式の入力保証に違反していますが、このテストは厳密な比較境界をチェックするのに役立ちます。 2 つの等しい値は厳密に増加するサブシーケンスを拡張できないため、選択されたすべてのインデックスの最大長は 1 であり、期待される結果は次のようになります。`0 0 0`。 実装では使用します`bisect_left`そして`>=`一貫して厳密な不平等を伴う前任者の拒否。
