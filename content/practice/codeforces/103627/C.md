 ## 解決策
 ## 問題の理解

 0 から N − 1 までのインデックスが付けられた要素のユニバースが与えられます。このユニバースのすべてのサブセットは、関数 a(S) を通じて値に関連付けられます。 この問題では、これらのセットの組み合わせ間に特定の不等式が成立する、通常 x、y、z と呼ばれる 3 つのペアごとに素なサブセットを見つけることが求められます。

 式は、これらのサブセットの和集合に対して関数 a を評価して構築されます。 直感的には、グループ間で要素を移動したときに値がどのように変化するかを比較しています。 一方では y を x に追加するゲインを測定し、もう一方では z をシステムに追加した後にゲインがどのように変化するかを測定します。 課題は、この不均衡が必要な方向に厳密に正になる構成を検出することです。 

このステートメントは抽象的な集合演算の観点から表現されていますが、実際の難しさは組み合わせにあります。つまり、グラウンド セットの分割を最大 3 つの部分に分けて検索しており、関数 a(S) は各サブセットに割り当てられたブラック ボックスの重みのように機能します。 

複雑さの観点から見ると、入力サイズ N はサイズ 2^N のサブセットのユニバースを意味します。 すべてのサブセットまたはサブセットのすべてのトリプルを明示的に評価するアプローチは、すぐに指数関数的になります。 N が約 20 の場合、2^N は約 100 万であり、これは強力な枝刈りで実現可能な境界線です。 N が大きい場合、O(2^N · N) でさえ遅すぎるため、どのソリューションでも有効な構成を制限できる方法で構造を利用する必要があります。 

微妙なエッジ ケースは、多くの単純なソリューションが 3 つのサブセットすべてが空ではないことを前提としているということです。 不等式は、それらの 1 つがシングルトンである場合、または証明によって暗示される変換後に 1 つの部分が崩壊した場合でも依然として保持されます。 もう 1 つの問題は、すべての要素が分散されなければならないと仮定していることです。 実際には、この帰結は、ほとんどの要素が 1 つの「背景」セット x にグループ化でき、重要なのは 1 つまたは 2 つの例外的な要素だけであることを示しています。 

たとえば、N = 3 で関数 a(S) が任意であると仮定します。 単純なソルバーは、要素を 3 つのグループすべてに徹底的に割り当てようとする可能性があります。 ただし、不等式の構造は、解が存在する場合、1 つまたは 2 つの要素だけが特別で、残りはすべて x 内にある解に常に変換できることを意味します。 これを怠ると、Θ(3^N) 分割を不必要に探索することになります。 

## アプローチ

 この問題の総当たり的な見方は簡単です。素のサブセット (x、y、z) の可能なすべてのトリプルを反復処理し、a(S) を使用して必要な式を計算し、不等式をチェックします。 候補パーティションごとに、式を評価するには a(S) を複数回呼び出す必要があり、各呼び出し自体もサブセットに対する反復が必要になる場合があります。 a(S) のすべての値を事前計算したとしても、分割数は依然として 3^N であり、N ≈ 15 を超えると大きすぎます。

 重要な構造的洞察は、要素をセット間で徐々に移動させたときに不等式がどのように変化するかを分析することで得られます。 x と y を固定し、要素を 1 つずつ z に追加すると、差分関数は段階的に変化します。 不等式を真にする z が存在する場合、z を要素ごとに構築するときに、加算によって不等式が反転する最初の要素が存在する必要があります。 つまり、単一の要素が挿入された時点で違反がすでに表示されているため、大きな z は必要ありません。 

対称引数は、y と z の役割を交換するときに適用されます。 この 2 番目の変換は、y を単一の要素に制限することもできることを示しています。 両方のリダクションを適用した後、任意の有効な構成を、z が単一要素、y が単一要素であり、x には証人に関係しない残りの要素がすべて含まれる構成に変換できます。

これにより、検索スペースが大幅に減少します。 任意のパーティションを反復する代わりに、サブセット x と、y = {e} および z = {f} を表す、x に含まれない 2 つの異なる要素 e および f を選択するだけで済みます。 このような選択ごとに、不等式を満たす有効な x の割り当てが存在するかどうかを検証します。 x は暗黙的に「含めることを決定した e と f を除くすべての要素」として表すことができるため、事実上、x をペア (e, f) と一緒に列挙します。 

この縮小構造に対する総当たり攻撃は O(2^N · N^2) になります。これは 3^N に比べて大幅な改善であり、定数係数に応じて最大約 20 ～ 22 までの N に対して実行可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 完全なパーティションの列挙 | O(3^N · コスト(a)) | O(1) または O(2^N) | 遅すぎる |
 | 削減された証人 (x、e、f) の列挙 | O(2^N · N^2 · コスト(a)) | O(2^N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 任意のサブセット S について関数 a(S) の高速評価を事前に計算するか、想定します。これが必要なのは、すべての候補チェックでサブセット値が繰り返しクエリされるためです。 
2. 基底集合のすべてのサブセット x を列挙します。 各 x はパーティションの「背景」部分を表し、不等式において特別な役割を果たしていないすべての要素が含まれます。 
3. 各サブセット x について、e ∉ x および f ∉ x および e ≠ f となるように、別個の要素 (e, f) のすべての順序付きペアを反復します。 これらはシングルトン集合 y = {e} および z = {f} を表します。 
4. 各トリプル (x, e, f) について、集合式 a(x ∪ {e})、a(x ∪ {f})、a(x ∪ {e, f})、および a(x) の直接計算を使用して不等式を評価します。 比較は、変換された条件で述べたとおりに正確に行われます。 
5. 不等式が成立する場合、対応するサブセット x、y、z を出力し、直ちに終了します。 

この列挙が十分である理由は、すべての有効な解を、x の外側に 2 つの要素だけが存在する解に変換できるためです。 列挙により、そのような構成がすべてアクセスされることが保証されます。 

### なぜ効果があるのか

 正しさは、z 構造の「最初の変更」引数に依存します。 潜在的に大きな z を持つ有効な解を取得し、その要素を 1 つずつ追加すると、その追加によって不等式が真になる最初の要素が存在するはずです。 この時点で、以前に追加されたすべての要素は、証人構造に影響を与えることなく x に吸収されます。 これにより、z がシングルトンに折りたたまれます。 対称引数は y も折りたたみます。 したがって、あらゆる解をアルゴリズムが列挙する制限された形式で表すことができ、検索空間の完全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Placeholder for subset value function.
# In an actual implementation, this would be provided or precomputed.
def solve():
    n = int(input().strip())

    # Assume we can read or compute a(S) somehow; details depend on full problem statement.
    # For editorial purposes, we focus on search structure.

    # This is a conceptual representation:
    # val[mask] = a(mask)
    val = [0] * (1 << n)

    # Enumerate x
    for x in range(1 << n):
        # try all ordered pairs (e, f)
        for e in range(n):
            if (x >> e) & 1:
                continue
            for f in range(n):
                if e == f:
                    continue
                if (x >> f) & 1:
                    continue

                xe = x | (1 << e)
                xf = x | (1 << f)
                xef = x | (1 << e) | (1 << f)

                # inequality check (from transformed condition)
                # a(x ∪ y) - a(x) < a(x ∪ y ∪ z) - a(x ∪ z)
                if val[xe] - val[x] < val[xef] - val[xf]:
                    # output representation
                    # exact format depends on original problem specification
                    print("YES")
                    print(x, e, f)
                    return

    print("NO")

if __name__ == "__main__":
    solve()
```コードには、検索スペースの縮小が反映されています。 x、e、f にわたるトリプル ループは、構造定理を直接実装します。 実装の重要な詳細は、和集合演算がビットごとの OR になるようにサブセットをビットマスクとして表現することです。 これにより、各遷移は O(1) に保たれます。 

よくある間違いは、非結合条件を明示的に強制することを忘れることです。 小切手`(x >> e) & 1`そして`(x >> f) & 1`e と f がまだ x に含まれていないことを確認してください。 もう 1 つの微妙な問題は、順序付きペアを正しく処理しないことです。 (e, f) と (f, e) は不等式における異なる役割を表す可能性があるため、両方を考慮する必要があります。 

## 実用的な例

 N = 3 の小さな例を考えてみましょう。アルゴリズムが x = {0}、e = 1、f = 2 を検出したとします。 

| x (マスク) | e | f | x∪e | x∪f | x∪{e,f} | 状態 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 001 | 1 | 2 | 011 | 101 | 111 | 評価済み |

 このトレースは、2 つの要素だけが異なる役割に交換されながら、単一の背景セット x がどのように再利用されるかを示しています。 計算は、最小の摂動のもとで関数 a がどのように変化するかに完全に焦点を当てます。 

x = ∅ の 2 番目の例は、すべての構造が 2 つの要素のみによって決定されるという極端なケースを強調しています。 その状況では、アルゴリズムはすべての順序付けされたペア (e、f) を直接テストし、空の背景も列挙によってカバーされることを確認します。 

## 複雑さの分析

 ## 特殊なケース

 エッジ ケースの 1 つは、N が小さすぎて有効なペア (e, f) が存在しない場合です。 その状況では、e と f のループはトリガーされず、アルゴリズムは無効なサブセット評価を試行することなく正しく失敗を出力します。 

もう 1 つのエッジ ケースは、x に 1 つを除くすべての要素がすでに含まれている場合に発生します。 この場合、x の外側にはペアを形成するのに十分な要素がないため、内側のループには有効な f がありません。 アルゴリズムはこれらの構成を自然にスキップし、誤った自己ペアリングを回避します。 

3 番目のエッジ ケースは、複数の有効な構成が存在する場合です。 アルゴリズムは最初に成功した証人で停止するため、一意性には依存しません。 正しさの議論では、1 つの縮小形式の解の存在のみが必要であるため、早期終了は妥当性に影響しません。
