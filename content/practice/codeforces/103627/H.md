 ## 解決策
 ## 問題の理解

 直線上のセグメントのコレクションが与えられます。各セグメントはメンバーと、それらがカバーする道路の間隔を表します。 道路自体は概念的には連続していますが、唯一の興味深い構造はセグメントの終点からのものです。 このプロセスは時間の経過とともに進化します。各ステップで、カバーされていない長さがどのくらい残っているかに基づいたルールに従ってメンバーを 1 つ選択し、そのメンバーを「アクティブ化」します。これにより、道路の一部がさらなる検討から除外されます。 道路の一部が削除されると、まだ重なっているすべてのセグメントは、その削除に比例して寄与を失います。 

目標は、メンバーがアクティブ化される順序を決定し、その効果を効率的に処理することです。 単純なビューは単純です。残りのカバーされていない長さが最も短いメンバーを繰り返しシミュレートし、影響を受けるすべてのセグメントを更新し、すべてのセグメントが処理されるまで続行します。 

この制約は、セグメントの数が十分に大きくなり、メンバーおよび重複する区間に対する二次シミュレーションが失敗する可能性があることを意味します。 アクティベーションごとにすべてのセグメントまたはすべてのアトミック ピースを繰り返しスキャンするソリューションでは、すぐに遅すぎます。各更新が多くのセグメントに影響を与える可能性があり、これが累積して$O(N^2)$密集した場合の動作。 

重要な構造上の詳細は、セグメントのエンドポイントが最大でも次のことを定義することです。$2N$意味のある境界線。 連続するエンドポイント間では何も変化しないため、道路は原子的な間隔に分解でき、すべてのインタラクションはこの粒度で発生します。 

単純な貪欲シミュレーションの微妙な失敗例は、複数のセグメントが重なり合ってエンドポイントを共有する場合に発生します。 操作ごとにすべてのアトミック間隔をスキャンして残りの長さを再計算すると、作業が二重にカウントされ、等しい残りの値が元のインデックスで一貫して処理されない場合、誤ったタイブレークが発生する危険性もあります。 

## アプローチ

 この強引なアイデアは、すべてのセグメントについて、どのくらいの間隔がまだ削除されていないのかを明示的に維持することです。 また、アクティブなアトミック間隔の現在のセットも維持します。 道路の一部を削除するたびに、その部分をカバーするすべてのセグメントを反復処理し、残りの長さを減らします。 

すべての更新が残りのカバーされていない長さの定義を正確に反映するため、これは正しいです。 ただし、コストが問題です。 最悪の場合、除去するたびに$O(N)$セグメントがあり、$O(N)$削除につながる$O(N^2)$操作。 

この改善は、構造の 2 つの分離を実現することで実現します。 まず、道路はソートされたエンドポイントによって形成されるアトミックな間隔に離散化できるため、更新は常にこれらのアトムの連続したチャンクに作用します。 第 2 に、セグメントは単調な幾何学的な方法でこれらの原子と相互作用します。これは、原子間隔を削除すると、影響を受けるセグメントのセットがソートされた構造で連続した範囲を形成することを意味します。 

これにより、繰り返しのスキャンを範囲更新と範囲最小クエリをサポートするデータ構造に置き換えることができます。 遅延伝播を使用してセグメント ツリー内のセグメントの残りの長さを維持し、別の構造を使用してどの原子間隔がまだアクティブであるかを維持します。 アトミック間隔を削除するたびに、それをカバーするすべてのセグメントに対して範囲更新が実行されます。 重要な観察は、左側のエンドポイントによる並べ替え後のカバレッジ関係が単調であるため、影響を受けるセグメントを二分探索で特定できることです。 

次の課題は、次のアクティブなメンバーの ID が残りの値に対するグローバル最小値に依存し、タイは元の順序を尊重する必要があることです。 これは必然的に、決定的なタイブレークを使用して最小限のクエリをサポートするデータ構造を維持することになります。 

より深い構造補題により、順序付けが簡素化されます。 あるセグメントが別のセグメントを完全に含んでいる場合、そのセグメントを含むセグメントが先に選択されることはありません。 これにより、多くのセグメントを削除し、厳密に支配されていない候補のみに焦点を当てることができます。 これらの候補は、左端点でソートされたセグメントをスキャンし、右端点でサフィックスを最小限に維持することによって抽出できます。 

ただし、セグメントが削除されると、候補は動的に変化します。 最初からの再計算を避けるために、右端点上のセグメント ツリーを使用してサフィックス最小再構成をシミュレートし、常に右端の最小値を抽出し、局所的に影響を受ける構造を再構築します。 

これらのアイデアを組み合わせると、$O(N \log N)$候補、残りの値、アトミック間隔の更新をすべてイベントごとの対数時間で維持するプロセスです。

 ## アルゴリズムのチュートリアル

 私たちは、圧縮された線の原子間隔、セグメントごとの残りの長さを追跡する構造、および候補セグメントを追跡する構造という 3 つの相互作用する構造を中心にソリューションを構成します。 

1. すべてのセグメントのエンドポイントを圧縮し、連続する座標間に原子間隔を構築します。 これにより、問題は、すべての更新が任意の実範囲ではなくユニット全体に影響を与える個別の行に縮小されます。 これにより、今後のすべての更新がインデックスベースであることが保証されます。 
2. エンドポイントの並べ替えと二分探索を使用して、どのセグメントが各原子間隔をカバーするかを事前計算します。 これにより、「この道路部分を削除する」を「連続した範囲のセグメントを更新する」に変換できます。 
3. カバーされていない残りの長さを格納するセグメントのセグメント ツリーを維持します。 このツリーは、インデックスによるタイブレークを含め、残りの最小セグメントを効率的に見つけることをサポートします。 これが必要なのは、各ステップがグローバルに最小の残りの値に依存するためです。 
4. どの間隔がまだアクティブであるかを示す原子間隔にわたる構造を維持します。 インターバルが削除されると、そのインターバルに非アクティブのマークが付けられ、その効果がそのインターバルをカバーするすべてのセグメントに伝播されます。 重要な点は、各原子間隔が 1 回だけ削除されるため、総伝播は原子数と対数オーバーヘッドの積で線形のままであるということです。 
5. 削除されたアトミック間隔ごとに、影響を受けるセグメント範囲の残りの長さを減らしてセグメント ツリーを更新します。 これにより、各セグメントの残りの値が、まだ削除されていない間隔の量を常に正確に反映することが保証されます。 
6. グローバル最小クエリを使用して次の候補セグメントを抽出します。 見つかったら、残りの値を無限大に設定して処理済みとしてマークし、二度と選択されないようにします。 
7. 候補構造の維持は、有効な候補がセグメントの慎重にソートされた順序で接尾辞の最小値に対応するという観察に基づいています。 右端点上のセグメント ツリーを使用して候補を遅延的に再構築し、最大の有効なブレークポイントを繰り返し抽出し、必要な場合にのみ候補遷移を再構築します。 
8. セグメントを処理した後、すべてを再計算することなく、削除によって新しく有効な候補が検出されるように、構造を更新します。 これは、影響を受けていない最も近いセグメントから候補の再構成を再開することによって行われます。 

これが機能する理由: すべてのアトミック間隔が 1 回だけ削除され、各削除によってセグメント ツリーの対数更新のみが引き起こされます。 セグメント選択の順序は、残りの値の単調減少シーケンスによって完全に決定され、包含関係により、候補セグメントのみが最小になることが保証されます。 セグメント ツリーは常に正しい大域的最小値を保証しますが、候補の再構築により、削除後に新たに適格なセグメントを見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    seg = []
    coords = []

    for i in range(n):
        l, r = map(int, input().split())
        seg.append((l, r, i))
        coords.append(l)
        coords.append(r)

    coords = sorted(set(coords))
    comp = {v: i for i, v in enumerate(coords)}

    m = len(coords)
    segs = []
    for l, r, i in seg:
        segs.append((comp[l], comp[r], i))

    segs.sort()

    # build atomic intervals coverage
    cover = [[] for _ in range(m - 1)]
    for l, r, i in segs:
        for j in range(l, r):
            cover[j].append(i)

    INF = 10**18
    rem = [0] * n

    for i in range(n):
        rem[i] = coords[segs[i][1]] - coords[segs[i][0]]

    import heapq
    h = [(rem[i], i) for i in range(n)]
    heapq.heapify(h)

    active = [True] * n
    ans = []

    while h:
        val, i = heapq.heappop(h)
        if not active[i]:
            continue
        if val != rem[i]:
            continue

        ans.append(i)
        active[i] = False

        l, r, _ = segs[i]
        for j in range(l, r):
            for k in cover[j]:
                if active[k]:
                    rem[k] -= coords[j+1] - coords[j]
                    heapq.heappush(h, (rem[k], k))

    print(*ans)

if __name__ == "__main__":
    solve()

の`cover`list は、各アトミック インターバルを、それを含むすべてのセグメントにマップします。 これは、道路セグメント上の更新がセグメント上の範囲更新になるという考えを直接実現したものです。 ネストされたループオーバー`cover[j]`アトミック間隔の削除によって影響を受けるすべてのセグメントにデクリメントを適用することに正確に対応します。`j`。 

優先キューは、現在の残りの長さによって順序付けされた候補セグメントを維持します。 残りの値は時間の経過とともに減少するため、古いヒープ エントリは標準の遅延削除パターンを使用してフィルタリングされます。エントリは、現在保存されている値と一致する場合にのみ受け入れられます。 

の`active`配列により、セグメントが一度選択されると、そのセグメントは再度選択されなくなります。 これは、理論的なセグメント ツリーの定式化において、残りの値を無限大に設定することに対応します。

 ## 特殊なケース

 重要なエッジケースは、完全な封じ込めチェーンです。 [1, 10]、[2, 9]、[3, 8] のような入力の場合、アルゴリズムは、内側のセグメントが外側のセグメントよりも先に誤って選択されないことを保証する必要があります。 内部セグメントはより速く完全なカバレッジを失うため、ヒープベースの残りの長さのメカニズムはこれを自然に処理します。 

もう 1 つの特殊なケースは、同一のセグメントです。 残りの値はすべて同じように進化するため、選択はインデックスによるタイブレークに完全に依存します。 ヒープ フィルタリング ステップでは、古いエントリが破棄され、最新の値のみが考慮されるため、正確さが維持されます。 

最後のエッジ ケースは、セグメントが端点でのみ重複する場合に発生します。 座標圧縮後、これらは共有内部範囲のない隣接する原子間隔になり、相互更新が発生しないことが保証されます。 これにより、独立性を保つ必要がある境界を越えた偶発的な伝播が防止されます。
