 ## 解決策
 ## 問題の理解

 曲線タイルで作られた競馬場の部分的な構成を表す長方形のグリッドが与えられています。 一部のセルはカーリー タイルを含むものとしてすでに修正されていますが、他のセルは空であり、管理者が後で埋めることができます。 最終的な目標は、隣接するすべてのタイルが正しく一致するように空のセルを埋めることができるかどうかを判断することです。つまり、トラック ピースを水平方向と垂直方向に整列させる方法のルールに従って、隣接するセルのすべてのペアが一貫して接続されているか、両方とも空であることを意味します。 

主な問題は、隣接するセル間のローカル制約が独立していないことです。 1 つのセルで行われた選択によって制約が行や列に伝播され、一見有効なローカル構成が後でグリッド内の他の場所で矛盾を強制する可能性があります。 タスクは、明示的な充填を構築することではなく、隣接制約の下でそのような充填が存在するかどうかを推論することです。 

グリッド サイズが十分に大きい場合、どのソリューションでも制約の 2 次または 3 次の伝播を回避する必要があります。 考えられるすべてのタイル配置をシミュレートしたり、接続されたコンポーネント全体に制約を単純に伝播しようとするソリューションは失敗します。これは、各更新が行または列全体にカスケードされる可能性があり、テストごとに最悪の場合の二次動作が発生する可能性があるためです。 

隣接関係を通じて制約の小さなサイクルが形成される場合、微妙なエッジ ケースが発生します。 たとえば、交互の要件が競合する 2x2 ブロックでは、すべてのローカル ペアが単独で一貫しているように見えても、グリッドが不可能になる可能性があります。 もう 1 つの失敗例は、水平方向の一貫性が強制されているが、グローバルな伝播後にのみ垂直方向の一貫性が違反される場合です。 

たとえば、4 つのセルすべてが強制的にカーリー タイルになる 2x2 グリッドを考えてみましょう。 左上と右上が反対の水平方向を強制し、左上と左下が反対の垂直方向を強制する場合、右下は過度に制約され、伝播された両方の要件と矛盾する可能性があります。 一見したところ、すべてのペアが独立して一貫しているように見えるため、素朴なローカル チェッカーはこれを受け入れるでしょう。 

中心的な課題は、これらのローカル隣接ルールを、効率的にチェックできるグローバル構造に変換することです。 

## アプローチ

 直接的なアプローチは、各空のセルを複数のタイル タイプを取ることができる変数として扱い、すべての隣接するペア間に互換性の制約を適用することです。 制約を繰り返し伝播します。セルが 1 つの隣接セルによって特定の向きに強制された場合、その状態を更新して伝播を続けます。 最悪の場合、更新のたびに行または列全体にわたる変更がトリガーされ、同じセルが何度も再訪される可能性があります。 n × m グリッドの場合、制約が密な領域に繰り返し波及すると、この伝播は O(n²m²) の動作に変質する可能性があります。 

重要な観察は、制約が任意の依存構造ではなくパリティ構造を持っているということです。 各セルの水平方向と垂直方向の互換性は、行と列を交互に繰り返すバイナリの選択肢としてエンコードできます。 各セルがその配向状態を表す「色」を持つと解釈すると、隣接制約により、水平方向と垂直方向の両方のエッジに沿って色が交互に配置されます。 これにより、グリッドは、すべての有効な構成が 2 部構成の整合性条件のように動作するシステムに変換されます。 

このパリティ解釈を割り当てると、各隣接制約は 2 つのエンドポイント間の等価制約または不等制約になります。 異なる必要があるセルは、端点が反対の値を持つ必要があるグラフのエッジを定義します。 次に、問題は、隣接するアクティブ セルがこれらのパリティ制約に従わなければならないことを考慮しながら、どのセルが「アクティブ」である (カーリー タイルを含む) かを選択することに帰着します。

ただし、すべてのセルがアクティブな状態を維持できるわけではありません。 特定の強制的な不一致は、エンドポイントが反対のパリティ要件を課す最大の水平または垂直セグメントに沿って発生します。 このような各セグメントは、両方のエンドポイントが同時にアクティブになることを禁止する制約のように動作します。 これらの制約は、アクティブ セルの数を最大化し、禁止された配置の数を最小限に抑えたい場合、二部グラフのエッジとしてモデル化できます。 

これにより、問題は 2 部グラフ上の最大一致または最小頂点カバー構造に変わります。 各エッジは 2 つの潜在的な配置間の競合を表し、一致するものを選択することは、競合を最適に解決することに対応します。 グリッドをこのグラフに縮小することで、伝播の必要性がなくなり、代わりによく研究された組み合わせ最適化問題が解決されます。

 ## アルゴリズムのチュートリアル

 ### 1. セルパリティ構造をエンコードする

 通常、行インデックスと列インデックスから派生したチェッカーボード パターンを使用して、各グリッド セルにその位置に基づいてパリティ クラスを割り当てます。 これは、水平および垂直の隣接関係に必要な交互をエンコードし、有効な構成が二部構造を尊重する必要があることを保証します。 

### 2. 強制的な非互換性を特定する

 両方ともカーリー タイルを含む可能性がある隣接するセルのすべてのペアについて、それらのパリティ制約が競合するかどうかを判断します。 存在する場合、このペアを禁止された同時アクティブ化を表すエッジとして扱います。 

このステップでは、局所的な幾何拘束を離散バイナリ拘束に変換します。 

### 3. 制約の 2 部グラフを構築する

 関連する各セルがノードに対応するグラフを構築します。 2 つのノード間のエッジは、パリティ不一致の伝播により両方を同時に選択できないことを示します。 二部構成の性質はチェッカーボードのカラーリングに由来しており、エッジが反対側のパリティ クラスのみを接続することが保証されます。 

### 4. 最大の独立集合補数まで削減します。 

カールしたタイルを残すことができるセルの数を最大化したいと考えています。 同様に、残りの 2 つの頂点を接続するエッジが存在しないように、最小数の頂点を削除する必要があります。 これは、2 部グラフ上の最大独立集合問題であり、最小の頂点カバーに減じられます。 

### 5. 最大一致を計算する

 ケーニッヒの定理により、最小頂点カバーのサイズは最大マッチングのサイズと等しくなります。 したがって、DFS ベースの拡張パスまたは Hopcroft-Karp アルゴリズムを使用して、構築されたグラフ上で最大の 2 部マッチングを計算します。 

### 6. 最終的な答えを導き出す

 有効なカーリー タイルの数は、対象となるセルの合計数から最小頂点カバーのサイズを引いたものです。 これにより、すべての隣接制約との一貫性を安全に維持できるセルの最大数が得られます。 

### なぜ効果があるのか

 重要な不変条件は、グリッド内のすべての競合が 2 部制約グラフ内の 1 つのエッジによってのみ捕捉され、有効な構成は内部エッジのない頂点のサブセットの選択に対応するということです。 パリティ エンコーディングは、すべての隣接制約がバイナリの非互換性にまで減少し、ペアごとの競合を超える高次の制約が存在しないことを保証します。 グラフは 2 部構成であるため、ケーニッヒの定理により、最大一致を解決することがすべての競合の最適な解決策を正確に特徴付けることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

class HopcroftKarp:
    def __init__(self, n_left, n_right):
        self.n_left = n_left
        self.n_right = n_right
        self.adj = [[] for _ in range(n_left)]
        self.pair_left = [-1] * n_left
        self.pair_right = [-1] * n_right
        self.dist = [0] * n_left

    def add_edge(self, u, v):
        self.adj[u].append(v)

    def bfs(self):
        q = deque()
        for i in range(self.n_left):
            if self.pair_left[i] == -1:
                self.dist[i] = 0
                q.append(i)
            else:
                self.dist[i] = float('inf')

        found = False
        for u in q:
            if self.dist[u] == float('inf'):
                continue
            for v in self.adj[u]:
                if self.pair_right[v] == -1:
                    found = True
                elif self.dist[self.pair_right[v]] == float('inf'):
                    self.dist[self.pair_right[v]] = self.dist[u] + 1
                    q.append(self.pair_right[v])
        return found

    def dfs(self, u):
        for v in self.adj[u]:
            if self.pair_right[v] == -1 or (
                self.dist[self.pair_right[v]] == self.dist[u] + 1 and self.dfs(self.pair_right[v])
            ):
                self.pair_left[u] = v
                self.pair_right[v] = u
                return True
        self.dist[u] = float('inf')
        return False

    def max_matching(self):
        match = 0
        while self.bfs():
            for i in range(self.n_left):
                if self.pair_left[i] == -1 and self.dfs(i):
                    match += 1
        return match

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    id_left = {}
    id_right = {}
    left_count = 0
    right_count = 0

    def cell_id(i, j):
        return i * m + j

    # build bipartite partition by checkerboard coloring
    for i in range(n):
        for j in range(m):
            if grid[i][j] != '#':  # '#' treated as blocked/empty/non-curly base
                continue
            if (i + j) % 2 == 0:
                id_left[(i, j)] = left_count
                left_count += 1
            else:
                id_right[(i, j)] = right_count
                right_count += 1

    hk = HopcroftKarp(left_count, right_count)

    directions = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    for i in range(n):
        for j in range(m):
            if grid[i][j] != '#':
                continue
            if (i + j) % 2 != 0:
                continue
            u = id_left[(i, j)]
            for di, dj in directions:
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < m and grid[ni][nj] == '#':
                    v = id_right[(ni, nj)]
                    hk.add_edge(u, v)

    matching = hk.max_matching()
    total = left_count + right_count
    print(total - matching)

if __name__ == "__main__":
    solve()

微妙な点は、エッジを構築するときに隣接の一方向のみが処理されることです。これにより、2 部構造でのエッジの重複が回避されます。 もう 1 つの重要な詳細は、モジュラー パリティを使用して左右のパーティションを分離することです。これにより、マッチング リダクションの正確さが保証されます。

 ## 特殊なケース

 最小の 1x1 グリッドには隣接性の制約が含まれていないため、常に 1 つの有効なセルが提供されます。 アルゴリズムはそれを 2 部パーティションの片側に割り当て、一致するサイズ 0 を生成し、答えは変更されません。 

2x2 の完全に埋められたブロックは、4 つのノード間に完全な 2 部相互作用を作成します。 一致するペアはパリティ ノードの反対側にあり、必要な数の競合が正確に削除されます。 このアルゴリズムは、2 つのパーティションに分割された 4 つのノードを構築し、すべてのエッジに対してマッチングを実行することでこれを処理します。 

チェッカーボードの多い 3x3 グリッドでは、すべてのセルに複数の隣接セルがあるため、2 部構成が強調されます。 このアルゴリズムは、各隣接関係を 1 回正しくエンコードし、重複する制約を二重にカウントすることなく照合によって解決することを保証します。
