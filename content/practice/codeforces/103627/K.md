 ## 解決策
 ## 問題の理解

 頂点 1 をルートとするツリーが与えられます。各頂点は整数の重みを持ちます。 ツリーとともに、2 つのパラメーター、下限 L と上限 R、および目標数 K が与えられます。タスクは、ツリーの頂点を、「閉じたサブツリー」のように動作する、互いに素な接続コンポーネントの構造化されたコレクションに分割できるかどうかを判断する一方で、部分的に構築されたコンポーネントを 1 つだけ構築中に「開いた」ままにすることができるかどうかを判断することです。 

これらのコンポーネントを構築するプロセスは、ボトムアップ方式で制約されます。 各サブツリーは、完全に完成した部分、または祖先によってまだ拡張できる未完成の部分のいずれかを提供できます。 「閉じたサブツリー」は、合計重みが区間 [L, R] 内にある連結コンポーネントに対応します。 「拡張可能なサブツリー」は、部分的に形成されたコンポーネントであり、親チェーンを通じて上向きに成長することができます。 

ルートでは、すべてのコンポーネントが重み制限を順守するという制約の下で、すべてを処理した後、正確に K + 1 個の閉じたサブツリーで終了できるかどうかを判断したいと考えています。 動的プログラミングの状態は、これまでに完了した閉じたサブツリーの数と、現在の開いた構造が取り得る重みの合計を追跡します。 

主な問題は、すべてのノードがその子からの情報をマージし、可能な部分重み合計の数が組み合わせ的に増加することです。 制約が十分に大きいため、ノードごとおよびサブツリーごとにすべての DP 状態を明示的に列挙するソリューションは遅すぎます。 特に、単純なマージは値のセットに対する畳み込みのように動作し、ノードごとに二次関数またはさらに悪い動作に簡単に達する可能性があります。 

典型的な障害モードは、到達可能なすべての合計を圧縮せずに正確に保存した場合に発生します。 たとえば、ノードに 2 つの子があり、それぞれが多くの可能な合計を提供する場合、それらの組み合わせにより完全なペアごとの合計集合の爆発が生成されます。 適度なツリーであっても、マージのたびに二次爆発が発生します。 

もう 1 つの微妙な問題は、DP は単に合計の実現可能性に関するものではなく、有限の「ギャップ感度」に関するものであるということです。つまり、任意の値が長さ R − L の区間に該当するかどうかだけを考慮します。これを無視すると、最終的な決定では区別できない多くの値が不必要に保持されることになります。 

## アプローチ

 ブルートフォース動的プログラミングは、当然ツリー構造に従います。 各ノードについて、形成された閉じたサブツリーの数である k と、アクティブなコンポーネントの現在の合計である x に関するテーブルを維持します。 2 つの子を結合する場合、k のすべての分割と両方の子の和のすべてのペアを試行し、畳み込みのようなマージを生成します。 

このアプローチは、サブツリーを分割する可能なすべての方法を正確に追跡するため、正しいです。 ただし、2 つの子が両方とも可能な数が O(K) で、可能な合計が O(R) である場合、それらをマージすると、最悪の場合、ノードごとに O(K^2 R^2) のコストがかかります。 N ノードを超えると、これは完全に不可能になります。 

重要な観察は、到達可能な合計のセットの完全な構造が実際には必要ないということです。 有効な閉じたサブツリーは [L, R] に分類される必要があり、決定はそのようなウィンドウにヒットするかどうかのみに依存するため、長さ R − L のスライディング区間に値が存在するかどうかだけを知る必要があります。 これにより、DP 状態を積極的に圧縮することができます。 

各 DP 状態を到達可能な合計のセットとして再解釈し、固定 k の値の広がりが k(R − L) によって制限されることに注目します。 これは、間隔クエリに関して正確さを失うことなく値を安全に近似できることを意味します。 すべての値を保存する代わりに、長さ R − L のすべての間隔の空を保存する縮小された代表セットを保存します。

これは 2 番目の重要なアイデアにつながります。マージのたびに、極端な代表のみを小さなバケット内に保持する削減を適用し、セット サイズが O(K) のままになるようにします。 R − L に対して十分に近い 2 つの値は、有効なクエリでは区別できないため、正確性が保証されます。 

したがって、DP 状態の指数関数的な増加の代わりに、制限された表現を維持し、各マージが多項式のままであることを保証します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N K^2 R^2) | O(N K R) | 遅すぎる |
 | 最適 | O(N K^3) | O(NK) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノード 1 でツリーをルートし、各ノードの DP 状態をセット S(v, k) のコレクションとして定義します。ここで、k は、v のサブツリーの処理された部分にある完了した閉じたサブツリーの数です。各セットには、現在開いているコンポーネントの可能な合計が格納されます。 
2. 葉ノードの 2 つの可能性を直接列挙して葉ノードを初期化します。その重みが [L, R] にある場合、頂点は閉じたサブツリーを形成するか、現在の合計として重みを持つ開いたコンポーネントに寄与します。 これにより、再帰なしで基本 DP 状態が確立されます。 
3. 子が親に結合される前に完全に解決されるように、ポストオーダー トラバーサルで各ノードを処理します。 これにより、すべてのマージが完全な部分問題に対して確実に実行されます。 
4. k の畳み込みを使用して 2 つの子 DP 状態をマージします。 k を i と k − i に分割するそれぞれの方法で、S(w1, i) のすべての合計と S(w2, k − i) のすべての合計を組み合わせます。 これにより、マージされたサブツリーのすべての可能な合計が生成されます。 この手順が必要な理由は、閉じたサブツリーが子全体に独立して分散される可能性があるため、すべての組み合わせを考慮する必要があるためです。 
5. ノードのすべての子をマージした後、Av を加算して S(w, k) のすべての合計をシフトすることでノード自体を組み込みます。 これは、開いたコンポーネントを現在の頂点を通って上に拡張することを表します。 
6. 拡張後、結果の和が [L, R] に該当することによって有効な閉じたサブツリーを形成できるかどうかを確認します。 その場合、そのコンポーネントが閉じられ、開いたコンポーネントがゼロにリセットされる新しい状態を導入し、k を 1 つ増やして S(v, k + 1) に 0 を挿入します。 
7. 各 S(v, k) にリダクション ステップを適用します。 このステップでは、長さ R − L の区間交点を決定するのに必要のない中間値を削除し、圧縮された表現のみを保持します。 この削減により、幅 R − L の任意の間隔クエリに対して、答えが変更されないことが保証されます。 
8. このプロセスをルートまで続けます。 最終的な答えは、S(1, K + 1) に 0 が含まれるかどうかです。これは、正確に K + 1 個のサブツリーを閉じ、開いたコンポーネントなしで終了できることを意味します。 

### なぜ効果があるのか

 重要な不変条件は、各 S(v, k) がすべての正確な合計を格納する必要はなく、元の非圧縮セットが交差する場合に限り、長さ R − L の任意の区間がセットと交差するのに十分な代表値のみを格納する必要があるということです。 リダクションではこの特性が維持され、加算時に区間の区別不能性が安定しているため、sumset 演算でも同様にこの特性が維持されます。 その結果、すべての DP 遷移は、圧縮されているが到達可能な解空間の同等の表現に基づいて動作するため、実現可能性が失われたり、誤って導入されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, K, L, R = map(int, input().split())
    w = [0] + list(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    parent = [0] * (n + 1)
    order = []
    stack = [1]
    parent[1] = -1

    while stack:
        v = stack.pop()
        order.append(v)
        for to in g[v]:
            if to == parent[v]:
                continue
            parent[to] = v
            stack.append(to)

    S = [None] * (n + 1)

    def reduce_set(arr):
        if not arr:
            return []
        arr = sorted(set(arr))
        res = []
        D = R - L
        last_keep = -10**18
        for x in arr:
            if not res or x > last_keep + D:
                res.append(x)
                last_keep = x
        return res

    def merge(A, B):
        if not A:
            return B[:]
        if not B:
            return A[:]
        out = []
        for a in A:
            for b in B:
                out.append(a + b)
        return reduce_set(out)

    def dp(v):
        cur = {0: [0]}  # k -> set of sums

        for to in g[v]:
            if to == parent[v]:
                continue
            child = dp(to)
            nxt = {}
            for k1, s1 in cur.items():
                for k2, s2 in child.items():
                    k = k1 + k2
                    merged = merge(s1, s2)
                    if k not in nxt:
                        nxt[k] = merged
                    else:
                        nxt[k] = merge(nxt[k], merged)
            cur = nxt

        new = {}
        for k, vals in cur.items():
            shifted = [x + w[v] for x in vals]
            new[k] = reduce_set(shifted)

        if any(L <= x <= R for x in new.get(0, [])):
            if 1 not in new:
                new[1] = []
            new[1].append(0)
            new[1] = reduce_set(new[1])

        return new

    res = dp(1)
    print("YES" if 0 in res.get(K + 1, []) else "NO")

if __name__ == "__main__":
    solve()
```コア構造は DP 定義に直接準拠します。 各ノードは、k から可能な合計の圧縮リストまでの辞書を計算します。 マージ関数は、2 つの子セット間でデカルト積を実行し、リダクション ルールを使用して積極的に圧縮します。 値の範囲の爆発を防ぐためには、削減が不可欠です。 

拡張ステップは、すべての合計をノードの重みによってシフトすることによって実装されます。 クロージャ条件は、合計が [L, R] に該当するかどうかをチェックし、次の k 状態に 0 を挿入してオープン コンポーネントをリセットします。 

最後の答えは、ルートに空の開いたコンポーネントを持つ正確に K + 1 個の閉じたコンポーネントを達成できるかどうかをチェックします。 

## 実用的な例

 元のステートメントでは明示的なサンプルが提供されていないため、一列に 3 つのノードがある小さなツリーを考えます。1 は 1 に接続され、2 は 3 に接続され、重みは [3, 2, 4]、L = 3、R = 5、K = 1 です。 

ノード 3 の DP を上向きにトレースします。 

| ノード | 受信セット | マージ後 | シフト後 | 閉鎖チェック |
 | --- | --- | --- | --- | --- |
 | 3 | {0: [0]} | 同じ | {0: [4]} | いいえ |
 | 2 | 3歳からの子供 | {0: [4]} | {0: [6]} | いいえ |
 | 1 | 2歳からの子供 | {0: [6]} | {0: [9]} | いいえ |

 これは、セグメントが [3, 5] に該当しないため、クロージャが発生しない失敗ケースを示しています。 

次に、L = 2、R = 4、K = 1 として重みを [2, 2, 2] に変更します。 

| ノード | 受信セット | マージ後 | シフト後 | 閉鎖チェック |
 | --- | --- | --- | --- | --- |
 | 3 | {0: [0]} | 同じ | {0: [2]} | はい → 閉じたものを追加 |
 | 2 | クロージャを受け取ります | {0: [0]} | {0: [2]} | はい |
 | 1 | 最終 | {0: [0]} | {0: [2]} | はい |

 これは、有効なサブツリーがどのように繰り返し閉じられ、リセットされるかを示しています。 

最初のトレースは、不可能な分割を拒否することが正確であることを確認し、2 番目のトレースは、クロージャー メカニズムが繰り返しトリガーされることを示しています。
