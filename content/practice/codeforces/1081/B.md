 ## 解決策
 ## 問題の理解

 n 人のグループが与えられました。 各人は厳密に 1 つの帽子をかぶっており、すべての帽子は 1 から n までのラベルが付けられた n 個の可能なタイプの 1 つに属します。 複数の人が同じ種類の帽子を共有することもできますし、一部の種類の帽子はまったく使用されないこともあります。 

各人 i は単一の数字 a_i を提供します。これは、自分の帽子とは異なる種類の帽子をかぶっている人が何人いるかを表すことになっています。 ハット タイプの最終的な割り当てを b_1、b_2、...、b_n と表すと、人 i の場合、値 a_i は、b_j が b_i と異なるようにインデックス j の数と等しくなければなりません。 

タスクは、これらすべてのステートメントと一致するハット タイプの割り当てが存在するかどうかを判断し、存在する場合は 1 つの有効な割り当てを構築することです。 

n ≤ 10^5 という制約により、二次関数や人々の間のペアごとの比較を避けることが強制されます。 すべての割り当てを検証したり、候補を明示的にシミュレートしようとするソリューションは失敗します。これは、O(n^2) であってもすでに約 10^10 の演算が暗示されているためです。 

微妙な点は、状態が対称的でありながら個別に表現されていることです。 各人の発言は、自分の帽子の種類を共有する人が何人いるかによってのみ決まります。 これは、基本的に、問題はインデックスをクラスにグループ化し、各クラス サイズがそのクラス内のすべてのユーザーに対して同じ値を決定することであることを意味します。 

誤った直感を明らかにするエッジ ケースの 1 つは、すべての a_i が等しいが、グローバルには不可能である場合です。 たとえば、すべての a_i が 1 で、n = 2 の場合、各人は他の人を 1 人だけ認識しているため、両方の人を同時に満足させることはできませんが、グループ化の制約が破られます。 

別の失敗例は、ある人が a_i = n - 1 など、[1, n] 以外のグループ サイズを暗示する値を要求した場合に発生します。これにより、その人はシングルトン グループに強制的に入れられます。 

## アプローチ

 強引なアプローチでは、各人に帽子のタイプを割り当て、すべての制約が満たされているかどうかを確認しようとします。 各 b_i は n 個の値を取ることができるため、n^n 個の可能性が生じますが、これは n = 10 の場合でもまったく実現不可能です。 

より構造化された総当り攻撃のアイデアは、グループ サイズを推測することです。n をグループ サイズに分割する可能性があるそれぞれに対して、それに応じて値を割り当てます。 ただし、パーティションの数は指数関数的に増加し、依然として拡張できません。 

重要な観察は、人の発言は完全にそのグループの規模によって決まるということです。 ある人がサイズ s のグループに属している場合、正確に s - 1 人が帽子を共有するため、n - s 人は別の帽子をかぶっています。 したがって、値 a_i を持つすべての人は、次のサイズのグループに属している必要があります。 

s = n - a_i

 これにより、問題は任意の割り当てから、必要なグループ サイズによるグループ化インデックスに変換されます。 

ここで問題は、各インデックス i がサイズ s_i = n - a_i のグループに属し、グループのすべてのメンバーが同じ s_i に同意する必要があるグループにインデックスを分割できるかということです。 

これは一貫性とグループ化の問題であり、同じ必要なサイズをグループ化することで貪欲に解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^n) | O(n) | 遅すぎる |
 | サイズ頻度による最適なグループ化 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ステートメントを必要なグループ サイズに変換します。

1. 各個人 i について、s_i = n - a_i を計算します。 これは、i のステートメントが当てはまる唯一の可能なグループ サイズです。 
2. いずれかの s_i が 1 未満または n より大きい場合、直ちに不可能と結論付けます。 グループに無効なサイズを含めることはできません。 
3. サイズから人のリストへのマッピングを使用して、必要なサイズ s_i ごとにインデックスをグループ化します。 
4. サイズ s の各グループについて、サイズ s を必要とする人の数が s で割り切れることを確認します。 そうでない場合は、サイズ s の均一なグループに分割できないため、構成は不可能です。 
5. 有効なサイズ s ごとに、リストをちょうど s 人のチャンクに分割します。 各チャンクは 1 つのハット タイプに対応します。 
6. 各チャンクに一意のハット ラベルを割り当て、それに応じて b_i を設定します。 

### なぜ効果があるのか

 変換 s_i = n - a_i が強制されます。サイズ s のグループに属する人は必ず、グループ外の n - s 人を正確に認識し、そのステートメントと一致します。 必要なサイズが同じであるすべての人々が収集されたら、有効な解決策はそれらをちょうど s のサイズのグループに分割する必要があります。サイズが混在すると、少なくとも 1 人の必要なグループ サイズに違反するためです。 可分性条件により、そのようなすべてのグループを残り物なく形成できることが保証され、チャンクごとに個別のラベルを割り当てることで、有効な監視ソリューションが構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    groups = {}
    required = []

    for i, x in enumerate(a):
        s = n - x
        if s < 1 or s > n:
            print("Impossible")
            return
        required.append(s)
        if s not in groups:
            groups[s] = []
        groups[s].append(i)

    ans = [0] * n
    color = 1

    for s, idxs in groups.items():
        if len(idxs) % s != 0:
            print("Impossible")
            return

        for i in range(0, len(idxs), s):
            chunk = idxs[i:i+s]
            for j in chunk:
                ans[j] = color
            color += 1

    print("Possible")
    print(*ans)

if __name__ == "__main__":
    solve()
```コードはまず、各 a_i を必要なグループ サイズ s_i に変換します。 次に、同じ要件を共有するインデックスのバケットを構築します。 各バケットは、そのサイズのグループに均等に分割できる必要があります。 色の割り当ては、これらのグループの構築に直接対応します。 

実装の微妙な点は、グループの順序付けを強制する必要がないことです。 グループ内のすべてのメンバーは制約に関して互換性があるため、どのパーティションでも機能します。

```ここで、各 s_i = 3 - 0 = 3 であるため、3 人全員が 1 つのグループに属している必要があります。 

| ステップ | 結成されたグループ | アクション | 状態 |

 | ビルドグループ | サイズ 3 のチャンク | 色 1 を割り当てる | b = [1,1,1] |

 これにより、サイズ 3 の単一グループがすべてのステートメントと一致していることが確認されます。

```s_i = 4 - a_i = [2,2,3,3] を計算します。 

| ステップ | 結成されたグループ | アクション | 状態 |

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各インデックスはグループ化のために 1 回処理され、割り当てのために 1 回処理されます。 
| スペース | O(n) | グループと出力配列のストレージ |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from io import StringIO

    input_data = sys.stdin.read().strip().split()
    it = iter(input_data)

    n = int(next(it))
    a = [int(next(it)) for _ in range(n)]

    groups = {}
    for i, x in enumerate(a):
        s = n - x
        groups.setdefault(s, []).append(i)

    ans = [0] * n
    color = 1

    for s, idxs in groups.items():
        if len(idxs) % s != 0:
            return "Impossible"
        for i in range(0, len(idxs), s):
            for j in idxs[i:i+s]:
                ans[j] = color
            color += 1

    return "Possible\n" + " ".join(map(str, ans))

# provided sample
assert run("3\n0 0 0\n") == "Possible\n1 1 1"

# all impossible due to mismatch
assert run("3\n0 1 2\n") == "Impossible"

# simple split case
assert run("4\n2 2 1 1\n") == "Impossible"

# single group edge
assert run("1\n0\n") == "Possible\n1"

# alternating valid grouping
assert run("4\n3 3 3 3\n") == "Possible\n1 1 1 1"

 ## 特殊なケース

 1 つのエッジ ケースは、すべての a_i = n - 1 の場合に発生します。その場合、すべての s_i = 1 となるため、すべての人がシングルトン グループに属している必要があります。 サイズ 1 の各バケットは自明に 1 で割り切れるため、アルゴリズムは各インデックスを独自のグループに正しく割り当て、すべての人が固有の帽子を持つ有効な割り当てを生成します。 

もう 1 つのエッジ ケースは、n = 1、a_1 = 0 です。これにより、s_1 = 1 が得られ、単一の有効なグループが形成されます。 グループ化により自然に 1 つのチャンクが生成されるため、アルゴリズムは特別なロジックを使用せずにこれを処理します。 

より微妙なケースは、必要なサイズが複数存在するが、1 つのサイズに要素が残っている場合です。 たとえば、n = 6、S 値は [2,2,2,2,2,3] です。 サイズ 2 のグループには 5 つの要素があり、完全なペアを形成できないため、アルゴリズムは部分的な割り当てが試行される前にインスタンスを正しく拒否します。
