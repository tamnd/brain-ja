 ## 解決策
 ## 問題の理解

 並んでいます`n`ライト。 一部のポジションはすでにオンになっており、他のポジションはすべてオフになっています。 

移動とは、隣接するライトが少なくとも 1 つすでにオンになっているオフのライトを選択し、それをオンにすることで構成されます。 すべてのライトが点灯するまで続けます。 

タスクは、異なる有効な動きのシーケンスがいくつ存在するかを数えることです。 2 つのシーケンスは、あるステップで異なる位置に切り替わる場合、異なるものとみなされます。 答えはモジュロで計算する必要があります`1000000007`。 

入力により、最初にオンになっている位置が得られます。 以来`n ≤ 1000`、比較的小さめのサイズを取り扱っております。 消灯の数が 1000 に近くなる可能性があるため、指数関数的な動作を持つアルゴリズムは不可能です。`O(n³)`解決策は不要です。 この制約は、事前に計算された階乗とモジュラー演算を使用した組み合わせ計数ソリューションを強く示唆しています。 

問題の微妙な部分は、移動の合法性が、すでにアクティブになっているライトへの隣接性のみに依存することです。 これにより、最初にオフになっているライトの各ブロック内の位置間に依存関係が作成されます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
5 2
2 4
```オフの位置では 3 つのギャップが形成されます。```
1 | 3 | 5
```各ギャップのサイズは 1 です。すべてのギャップは独立して位置に寄与できますが、答えは単純ではありません。`3! = 6`。 それぞれのギャップの内部制約を考慮する必要があります。 

もう 1 つの重要なケースは内部ギャップです。```
7 2
2 6
```2 位と 6 位の間のギャップには次のものが含まれます。```
3 4 5
```このブロックはどちらの端からでも入力できます。 位置 4 を最初にアクティブにすることはできません。 これら 3 つの位置のすべての順序を有効なものとして扱う単純な解決策では、過剰にカウントされてしまいます。 

最後の特殊なケースは、すべてのライトがすでにオンになっている場合に発生します。```
4 4
1 2 3 4
```実行する動きはありません。 正しい答えは次のとおりです。```
1
```空のシーケンスが 1 つだけあります。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべての有効な移動シーケンスをシミュレートします。 各状態で、現在切り替え可能なすべてのライトを見つけて、各選択を再帰的に試し、すべてのライトがオンになるまで続行します。 

これは、すべての正当なシーケンスを明示的に列挙しているため、正しいです。 問題は州の数です。 1 つのライトだけが点灯し、残りの 999 個のライトが消灯している場合、有効なシーケンスの数は膨大になります。 徹底的な検索は完全に不可能になります。 

重要な観察は、行が最初に点灯したライト間の独立したギャップに自然に分割されることです。 

初期オンの位置がソートされているとします。 連続するすべてのオン ライトのペアの間にはオフ ライトのギャップがあります。 最初の点灯の前と最後の点灯の後にギャップがある場合もあります。 

境界ギャップは内部ギャップとは異なる動作をします。 

境界ギャップの場合、アクティブ化は片側からのみ拡張できます。 ギャップが含まれている場合`k`位置が異なると、そのギャップ内の順序は完全に強制されます。 

例えば：```
111000
```右端の 3 つの位置は、左から右にアクティブ化する必要があります。 

内部ギャップのほうが面白いです。 ギャップの長さが`k`。```
1 0 0 0 1
```両端はアクティブ ライトに隣接しています。 各ステップで、左端の残りの位置または右端の残りの位置を取ることができます。 このプロセスはギャップがなくなるまで続きます。 

長さのギャップに対して`k`、有効な内部注文の数は次のとおりです。```
2^(k-1)
```なぜ？ 最初`k-1`それぞれのアクティベーションには、左端または右端の 2 つの選択肢があります。 最終的な位置は強制されます。 

各ギャップ内の有効な注文を数えた後、異なるギャップからの手をマージする必要があります。 ギャップ サイズが次の場合:```
g1, g2, ..., gt
```次に、さまざまなギャップからの動きの相対的な順序を選択できます。$$\frac{(g_1+g_2+\cdots+g_t)!}{g_1!g_2!\cdots g_t!}$$これは多項係数です。 

答え全体は次のようになります。$$\text{multinomial} \times \prod_{\text{internal gaps}} 2^{k-1}$$これにより、問題が純粋な組み合わせ論に変換されます。

 ## アルゴリズムのチュートリアル

 1. 初期オン位置を読み取り、ソートします。 
2. すべてのギャップ長を計算します。 

最初の点灯までのギャップは長さがある`a[0]-1`。 

最後の点灯後のギャップは長さがある`n-a[m-1]`。 

連続点灯の間`a[i]`そして`a[i+1]`、内部ギャップの長さは次のとおりです。$$a[i+1]-a[i]-1$$3. しましょう`off = n - m`、まだアクティブにする必要があるライトの合計数。 
4. 以下から始めます:$$ans = off!$$これには、ギャップ制約を考慮する前に、将来のアクティベーションを調整するためのすべての方法がカウントされます。 
5. あらゆる長さのギャップに対して`k`、で割る`k!`。 

これは変換します`off!`異なるギャップからのアクティベーションをどのようにインターリーブできるかをカウントする多項係数に変換します。 
6. 正の長さの内部ギャップごとに`k`、次の乗算:$$2^{k-1}$$なぜなら、片方のポジションだけが残るまで、どちらの側からもギャップが縮まる可能性があるからです。 
7. すべての除算をモジュロで実行します。`10^9+7`モジュラーインバースを使用します。 
8. 最終結果を出力します。 

### なぜ効果があるのか

 すべてのオフ位置は、正確に 1 つのギャップに属します。 

境界ギャップ内では、既に点灯しているライトに隣接する側からのみ成長が進むため、活性化順序は一意に決定されます。 

内部ギャップ内では、常に残りの間隔の 2 つの境界位置のみが選択可能です。 左または右を繰り返し選択することで、アクティブ化シーケンスが完全に決定されます。 長さのギャップ`k`したがって、正確に貢献します`2^(k-1)`有効な内部注文。 

異なるギャップは、グローバル タイムラインを介する場合を除いて相互作用しません。 各ギャップの有効な内部順序が固定されると、残る唯一の自由は、異なるギャップからの手をどのようにインターリーブするかです。 多項係数はこれらのインターリーブを正確にカウントします。 

答えは有効な内部順序の数と有効なインターリーブの数を乗算するため、すべての正当なグローバル シーケンスは 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def main():
    n, m = map(int, input().split())
    a = sorted(map(int, input().split()))

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    inv_fact = [1] * (n + 1)
    inv_fact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        inv_fact[i - 1] = inv_fact[i] * i % MOD

    gaps = []

    left_gap = a[0] - 1
    gaps.append(left_gap)

    ans = 1

    for i in range(m - 1):
        k = a[i + 1] - a[i] - 1
        gaps.append(k)
        if k > 0:
            ans = ans * pow(2, k - 1, MOD) % MOD

    right_gap = n - a[-1]
    gaps.append(right_gap)

    off = n - m
    ans = ans * fact[off] % MOD

    for k in gaps:
        ans = ans * inv_fact[k] % MOD

    print(ans)

if __name__ == "__main__":
    main()
```階乗配列および逆階乗配列を使用すると、ギャップごとに一定時間で多項係数を計算できます。 

変数`ans`まず内部ギャップからの寄与を蓄積します。 その後、次を掛けます`off!`、グローバル タイムラインにおける将来のアクティベーションのすべての可能な配置を表します。 

で割る`k!`すべてのギャップは次の乗算として実装されます。`inv_fact[k]`。 法は素数であるため、フェルマーの小定理は逆剰余を与えます。$$x^{-1} \equiv x^{MOD-2} \pmod{MOD}$$よくある間違いは、次の値を乗算することです。`2^k`の代わりに`2^(k-1)`内部の隙間に。 最後に残ったポジションには選択肢がないので、最初のポジションのみ`k-1`アクティベーションは二者択一の決定に貢献します。 

もう 1 つの頻繁なバグは、境界ギャップに 2 のべき乗係数を適用することです。 境界ギャップは片側からのみ拡大し、正確に 1 つの内部順序に寄与します。

MOD = 1000000007

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, m = map(int, input().split())

    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    inv_fact = [1] * (n + 1)
    inv_fact[n] = pow(fact[n], MOD - 2, MOD)

        inv_fact[i - 1] = inv_fact[i] * i % MOD

 ## 特殊なケース

 次のことを考慮してください。```
4 4
1 2 3 4
```隙間がなく、`off = 0`。 

アルゴリズムは以下を計算します。```
0! = 1
```2 のべき乗因数は表示されません。 答えは残っている`1`、これは一意の空のシーケンスに対応します。 

考慮する：```
4 2
1 4
```真ん中の隙間は長さがある`2`。 

アルゴリズムは以下を計算します。```
2! / 2! × 2^(2-1)
= 2
```有効なアクティベーション順序は次の 2 つです。```
2,3
3,2
```これは、内部ギャップが二者択一の選択に寄与していることを裏付けています。 

考慮する：```
5 1
3
```ギャップは次のとおりです。```
2 and 2
```どちらも境界ギャップです。 

答えは次のようになります。```
4! / (2!2!) = 6
```どちらのギャップも内部的なものではないため、2 のべき乗係数は追加されません。 すべてのギャップを同様に扱うソリューションでは、誤って 2 のべき乗が余分に乗算され、オーバーカウントされてしまいます。
