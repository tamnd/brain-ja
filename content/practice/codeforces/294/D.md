 ## 解決策
 ## 問題の理解

 サイズ _n_×_m_ タイルのキッチンの床があり、最初はすべて白でした。 ロボットは座標 (_x_s_, _y_s_) の境界タイルの上に立ち、4 つの対角方向のいずれかを向いています。 ロボットがタイルに移動するたびに、タイルを黒く塗ります。 壁に当たるとビリヤードの球のように反射します。 ロボットの目標は、床がチェッカー盤になるまでタイルをペイントすることです。このとき、隣り合う 2 つのタイルが同じ色を共有することはありません。 この条件が満たされるまで、または満たされない場合は -1 されるまで、黒く塗られたタイルの総数を計算します。 

ロボットは開始タイルをすぐにペイントします。 反射ルールは、ロボットが水平または垂直の壁に衝突すると、その水平または垂直の動き成分が反転することを意味します。 コーナーにぶつかると、両方のコンポーネントが逆転します。 

制約は大きく、_n_、_m_ は最大 10^5 まで可能です。 ロボットをタイルごとに動かす単純なシミュレーションでは、2 秒の制限時間をはるかに超える、最大 10^10 の操作が必要になる可能性があります。 したがって、より分析的または数学的なアプローチが必要です。 

ロボットがチェッカーボードの正しいタイルをカバーせずにサイクルに入る場合、微妙なエッジ ケースが発生します。 たとえば、角から始まる 2×3 の長方形では、ロボットは 3 つのタイルの間を繰り返し振動するだけかもしれません。 無制限にシミュレーションを行う不注意な実装は決して終了せず、チェッカーボード条件が満たされることはありません。 

## アプローチ

 ブルートフォース手法では、一度に 1 つのタイルを移動するロボットをシミュレートし、タイルの色を更新し、各移動後にチェッカーボードの状態をチェックします。 これは、問題ステートメントを直接実装しているため正しいですが、各移動には一定の時間がかかり、複数の反射で繰り返される単一の対角パスで最大 O(n*m) 個の固有のタイルが訪問される可能性があるため、大規模なグリッドでは実行できません。 

重要な観察は、ロボットが斜めに移動し、その移動パターンが周期的に繰り返されるということです。 次の壁に両方向に同時に到達するまでの移動数を追跡すると、各タイルをシミュレートするのではなく、次の反射点に直接ジャンプできます。 具体的には、位置 (_x_, _y_) から増分 (_dx_, _dy_) ずつ移動し、ロボットは次の壁にぶつかります。`t = min((dx>0?n-x:x-1)//abs(dx), (dy>0?m-y:y-1)//abs(dy))`ステップ。 そのようなジャンプの 1 つで、それは絵を描きます`t`新しいタイル。 壁にぶつかった後は方向成分が反転し、これを繰り返します。 これにより、反射のたびに壁までの距離が減り、ロボットが境界を訪れることができる回数は限られているため、操作の数は最大で O(n + m) に減ります。 

また、2 を法とするタイル座標のパリティも追跡します。偶数の和座標を持つすべてのタイルがペイントされ、奇数の和座標を持つすべてのタイルがペイントされる場合、床はチェッカーボードになります。 ロボットがチェッカーボードのパリティに一致するタイルから開始すると、最終的にはそのパスに沿って 1 つのパリティのすべてのタイルをカバーします。 ロボットが反対パリティのタイルに触れずにループに入った場合、アルゴリズムは、以下から構成される訪問済み状態セットを使用してそれを検出できます。`(x, y, dx, dy)`タプル。 ロボットがある状態を繰り返す場合、ロボットはサイクルにはまり、決して終了しないことがわかっているため、出力は -1 になります。

 ## アルゴリズムのチュートリアル

 1. グリッドの寸法 _n_、_m_、開始座標 (_x_s_、_y_s_)、および初期方向を読み取ります。 「UL」などの方向を増分に変換します`dx`、`dy`どこ`dx = ±1`列の移動と`dy = ±1`コラム移動用。 
2.初期化`painted = 1`開始タイルがすぐにペイントされるためです。 
3. ロボットの現在位置を追跡する`(x, y)`そして方向`(dx, dy)`。 
4. セットを使用する`visited_states`追跡する`(x, y, dx, dy)`ループを検出します。 ロボットが同じ状態に戻った場合は、-1 で終了します。 
5. チェッカーボードが完了していない間は、次の操作を行います。 

ａ． 次の壁までの両方向の最大歩数を計算します。`tx = (n-x) if dx>0 else (x-1)`

`ty = (m-y) if dy>0 else (y-1)`

`t = min(tx, ty)`b. ロボットを動かす`t`斜めにステップします:`x += dx*t`、`y += dy*t`。 

c. 増加`painted`による`t`。 

d. ロボットが垂直の壁にぶつかった場合は反転します`dy`。 水平の壁にぶつかったら逆転`dx`。 コーナーにぶつかった場合は両方を反転します。 
6. パリティがあるかどうかを確認します。`(x_s + y_s) % 2`ペイントされたすべてのタイルのパリティと一致します。 最終的に両方のパリティがカバーされる場合は、終了して出力します`painted`。 
7. 各パリティのすべてのタイルがペイントされるか、ループが検出されるまで繰り返します。 

**機能する理由:** ロボットは斜めに動き、境界で反射します。 その経路は周期的であり、現在の位置と方向にのみ依存します。 反射点にジャンプして歩数をカウントすることで、訪問したタイルの数を正確にカウントします。 パリティ チェックはチェッカーボードが完了できることを保証し、ループ検出は完了できない場合の終了を保証します。
