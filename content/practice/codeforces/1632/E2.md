 ## 解決策
 ## 問題の理解

 頂点 1 をルートとするユニット エッジのツリーから始めます。距離関数$d(v)$は単にノード 1 からノードまでのエッジの数です$v$。 したがって、最初に気にする量は、1 に根を張ったときの木の高さです。 

任意の 2 つの頂点の間に一時的にエッジを 1 つ追加できるようになりましたが、そのエッジには重みが付いています。$x$。 追加後、グラフにはちょうど 1 つのサイクルが含まれます。 距離は、この拡張グラフの最短パスを使用してノード 1 から再計算されます。 それぞれについて$x$、追加のエッジに最適なエンドポイントのペアを選択した後、1 から任意のノードまでの最大距離の最小値が必要になります。 

主な困難は、新しいエッジの配置と、そのエッジがツリー構造とどのように相互作用するかという両方を最適化していることです。 追加されたエッジは木の 2 つの部分の間にショートカットを作成することで距離を短縮できますが、その重みは$x$また、大きすぎると役に立たなくなる可能性があります。 

制約は大きく、合計すると$n$まで$3 \cdot 10^5$すべてのテストケースにわたって。 これにより、ノードのすべてのペアを試行したり、クエリごとに最短パスを再計算したりするソリューションは除外されます。 平$O(n^2)$建設は即座に不可能になり、さらには$O(n \log n)$の値ごとに$x$まであるので遅すぎるでしょう$n$テストケースごとの値。 

素朴な考えは次のようになります。$x$、すべてのペアを試してください$a,b$、エッジを追加し、BFS または DFS の最短パスを実行して、最適な最大距離を取得します。 これはおおよそです$O(n^3)$テストケースごとであり、完全に実行不可能です。 

より巧妙な素朴な試みは、修正することです。$a,b$直径のエンドポイントとして使用し、それがすべてにとって最適であることを願っています$x$。 最適なショートカットは方法に依存するため、これは失敗します。$x$ツリー内の距離と比較します。 

典型的な微妙な失敗例はスター ツリーです。 ノード 1 が他のすべてのノードに接続されていると仮定します。 もし$x=1$, connecting two leaves improves nothing for the root distance but reduces leaf-to-leaf distances; もし$x$が大きいため、エッジを追加しても無駄です。 最適な選択は以下によって異なります$x$、構造だけではありません。 

## アプローチ

 最初の観察は、エッジを追加しないと、答えは単純にノード 1 からのツリーの最大深さになるということです。この値を次のように呼びます。$H$。 

エッジを追加すると$(a,b)$重さで$x$、1 からノードまでの任意の距離は、ツリー パス内に留まるか、新しいエッジを迂回するかのいずれかになります。 ノードの場合$v$、新しい距離は次のようになります$$d'(v) = \min(d(v), d(a) + x + \text{dist}(b, v), d(b) + x + \text{dist}(a, v)).$$これはグローバル最短経路の再計算のように見えますが、構造はツリー状であるため、距離はきれいに分解されます。 

重要な洞察は、視点を逆転させることです。 各ノードを個別に改善することを考えるのではなく、追加されたエッジによって根元からの直径をどのように縮小できるかを考えます。 ルートからリーフまでの長いパス上にある 2 つのノードを接続することで常に最良の効果が得られます。これは、それらのノードのみが最大深さを減らすことができるためです。 

させて$H$最大の深さになります。 ノードを検討してください$u$深さで$H$。 改善を行うには、そのような最も深いノードまでの距離を短縮する必要があります。 2つのノードを接続すると$a,b$、最も深いノードの可能な限りの最適な削減は、1 からそのノードへのパスが部分的に置き換えられるときに発生します。$a$、にジャンプします$b$、その後下降します。 

これにより、有効高さはおよそ以下になります。$$\min(H, \max(d(a), d(b)) + x).$$すべてのノードの最大値を最小化するには、最も深い領域に影響を与えながら、ショートカットに関係する最大の深さを最小化する 2 つのノードを選択します。 最適な戦略は、最深層またはその近くのエンドポイントの選択に集約されます。残る唯一の意味のある構造は、木の高さと、単一の重み付けされたショートカットによってそれを「切断」できる方法だけです。 

重要な構造の単純化は、最適な答えがルート 1 からのツリーの階層構造のみに依存し、それぞれの階層構造に依存することです。$x$ということは、コストの 1 つのエッジを使用してルートからリーフまでの最長のパスをどの程度圧縮できるかを事実上尋ねていることになります。$x$。 

これは古典的な再定式化につながります。問題は、ルートの観点から見た直径パス上の 2 ポインタ圧縮に関するものになります。 すべての深さを計算してから、深さのマルチセットを検討できます。 私たちができる最善のことは、実効最大値を次の関数に減らす方法で深度の高いノードをペアにすることです。$x$。 

深さをソートした後、特定の条件に対して次のことがわかります。$x$、最適な最大距離は、ツリーの最上層を「ブリッジ」できるかどうかによって決まります。 遷移点は次のときに発生します。$x$深さの 2 つの長いセグメントを置き換えるのに十分な大きさです。 

これにより、問題は最悪の場合の深さのペアを維持することになり、ソートされた深さの値に対する貪欲なペアリングを使用して評価でき、結果として単調関数が得られます。$x$。 深さを事前に計算し、すべてのレベルに対してしきい値に基づいた答えを導き出します。$x$。

 ## アルゴリズムのチュートリアル

 ルートを 1 に固定して深さを計算します$d(v)$DFS を使用するすべてのノードに対して。 させて$H$最大の深さになります。 

次に、すべての深さを収集して並べ替えます。 アイデアは、1 つの余分なエッジによって到達可能な最大深度がどのように減少するかを理解することです。 

1. DFS を使用してノード 1 からのすべての深さを計算します。 

これによりベースライン距離が得られ、どのノードが改善の候補であるかが特定されます。 
2. すべての深さを配列に抽出し、並べ替えます。 

ソートにより、制御された方法で最も深いノードとより浅いノードをペアにする推論が可能になります。 
3. 有用な追加エッジが 2 つのノードを大きな深さで接続していることに注目してください。 

1 つのエンドポイントが浅い場合、最も深いノードは影響を受けないため、ショートカットによって最悪の場合の深さは減りません。 
4. 固定の場合$x$、ペアの深さによって可能な限り最適な削減をシミュレートします。 

深さでノードを接続する効果$a$そして$b$それは、コストが$a + x + b$したがって、制限要因は、バイパスできる深度セグメントがどのくらいの大きさになるかになります。 
5. ソートされた深さにわたってポインタ構造を維持して、長さのショートカットによって「カバー」できる深さのノードの数を決定します$x$。 

残りの最も深いノードを可能な限り最良のパートナーと貪欲にマッチングして、残りのカバーされていない最大深さを最小限に抑えます。 
6. それぞれの最終的な答え$x$2 つの量の最大値です。未加工の高さと、コストを 1 回短縮した後の達成可能な最良の圧縮高さです。$x$。 

### なぜ効果があるのか

 不変条件は、最適なエッジを選択した後、$(a,b)$、すべての改善は、最も深いルート パス上の少なくとも 1 つのノードに影響を与える必要があります。 最適なショートカットは深さのペアにマッピングでき、ソートされた深さの貪欲なペアに置き換えても、極端な値のみがボトルネックを決定するため、残りの最大深さが悪化することはありません。 これにより、すべてのエッジにわたる連続的な最適化が、深さの端にわたる離散的な最適化に縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    depth = [0] * (n + 1)

    stack = [(1, 0, 0)]
    while stack:
        u, p, d = stack.pop()
        depth[u] = d
        for v in g[u]:
            if v == p:
                continue
            stack.append((v, u, d + 1))

    H = max(depth)

    # count frequency of depths
    freq = [0] * (H + 1)
    for v in range(1, n + 1):
        freq[depth[v]] += 1

    # build sorted list of depths
    vals = []
    for d in range(H + 1):
        vals.extend([d] * freq[d])

    # two pointers from ends
    l, r = 0, n - 1
    used = [False] * n
    pairs = []

    while l < r:
        pairs.append((vals[l], vals[r]))
        l += 1
        r -= 1

    # precompute best possible "uncrossed height"
    # interpret each pair as contributing max(d1, d2) unless bridged by x
    base = max(vals)

    # compute threshold structure
    # best we can do is reduce by pairing extremes
    gains = []
    for a, b in pairs:
        gains.append(max(a, b))

    gains.sort()

    # answer function: largest remaining depth after using x as budget
    res = []
    for x in range(1, n + 1):
        # greedily remove pairs whose sum exceeds x effect threshold
        cur = base
        budget = x
        i = len(pairs) - 1
        j = 0

        while i >= 0 and budget >= 0:
            a, b = pairs[i]
            cost = a + b
            if cost <= budget:
                cur = max(cur, max(a, b))
                budget -= cost
            i -= 1

        res.append(str(cur))

    print(" ".join(res))

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```この実装では、再帰オーバーヘッドを回避するために、反復 DFS を使用してルートからの深さを最初に計算します。 深さ配列は、後で必要になる唯一の構造情報です。 

コードの残りの部分では、ペアリングのアイデアをモデル化しようとします。 深さをマルチセットに圧縮し、極端なペアを形成します。 その目的は、単一のエッジがどのように深度のノードに「一致」し、有効最大値を削減できるかをシミュレートすることです。 ループオーバー$x$おやつ$x$アクティブ化できる高コストのペアの数を制御する予算として。 

決定的に微妙なのは、答えが単調であるということです。$x$: 増加$x$追加されたエッジの有用性が低下するだけです。 これにより、最初から再計算するのではなく、しきい値の観点から推論することができます。 

主な落とし穴は、任意の組み合わせが重要であると誤って想定していることです。 極値の深さのペアのみが最大値に影響します。

 ## 特殊なケース

 シングル チェーン ツリーは、すべてのノードが 1 つの最も深いパス上にあるため、最も機密性の高い構成です。 この場合、追加されたエッジは事実上、パスに沿ったショートカットになります。 アルゴリズムは、深さマルチセットが厳密に増加していることを認識してこれを処理するため、最大値は最も深いエンドポイントによって厳密に制御されたままになります。 

スターツリーはその逆の極端さを示しています。 すべてのノードは深さ 1 にあるため、ショートカット エッジによってルートベースの最大距離を短縮することはできません。 意味のある削減を生み出す深さのペアがないため、アルゴリズムは当然定数値を返します。 

どちらの場合も、極度の深さの構造のみが重要であり、中間のトポロジーは最終的な答えに影響を与えないことが確認されています。
