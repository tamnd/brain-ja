 ## 解決策
 ## 問題の理解

 開鎖分子を表すツリーが与えられます。これは、n 個の原子が n−1 個の結合で接続されており、環が存在しないことを意味します。 タスクは、すべての原子の順列を出力することです。 

このような順列については、固定原子 u を考えてみましょう。 ツリー内のその近傍の一部は順列で u の前に表示され、残りは u の後に表示されます。 これら 2 つのカウントが正確に等しい場合、その原子はバランスが取れていると呼ばれます。 これは、ノードの次数が偶数の場合にのみ可能です。そうでない場合は、奇数の近傍を 2 つの等しい半分に分割することができないからです。 

目標は、すべてのノードのバランスを整えることではなく、このバランス条件を満たすノードの数を最大化する順列を生成することです。 

重要な点は、順列がグローバルな順序を定義し、すべてのエッジが両方のエンドポイントの「分割前/分割後」に同時に寄与することです。 単一の順序決定がすべてのノードに伝播されるため、ローカルでの貪欲な選択は簡単に競合する可能性があります。 

この制約により、最大 5×10^5 ノードが許可され、すべての順列を試行したり、サブセットに対して状態ごとに大量の DP を実行したりするソリューションは除外されます。 ノードごとの O(n log n) または O(n) 推論でも許容されますが、二次関数やツリー構造に対する繰り返しの再計算を伴うものは失敗します。 

単純なアプローチでは、順列を構築してバランス状態を継続的にチェックしようとしたり、次数に応じてノードを貪欲に配置しようとしたりします。 ノードを早くまたは遅く配置すると、すべての隣接ノードとの関係が即座に修正され、後で調整することが不可能になるため、どちらも失敗します。 

小さな木でも微妙な失敗例が現れます。 3 つのノード 0-1-2 のパスを考えてみましょう。 ノード 1 には次数 2 があり、バランスを取ることができますが、ノード 1 を両方の隣接ノードに対して早すぎたり遅すぎたりすると、必要な分割を達成できなくなります。 これは、順序付けの決定では、ローカル次数プロパティだけでなく、エッジ方向のグローバル構造を尊重する必要があることを示しています。 

## アプローチ

 強引なアイデアは、ノードのすべての順列を生成し、順序ごとにバランスのとれたノードの数を計算することです。 これは正しいですが、n 個あるため完全に実行不可能です。 順列。 各スワップが O(deg(u)+deg(v)) のバランス条件に影響を与え、依存関係がツリー全体に伝播するため、サンプリングやヒューリスティック スワッピングでもすぐに信頼性が低くなります。 

問題をより構造的に見る方法は、順列を直接並べるのではなく、エッジに焦点を当てることです。 順列が修正されると、すべてのエッジが前の端点から後の端点に向けられます。 これにより、ツリーは、各ノードの入力エッジの数が、順列でそのノードの前に出現する近傍エッジの数と等しくなる方向に変換されます。 ノードは、その入次数がその次数の半分に等しい場合に正確にバランスが取れています。 

したがって、タスクは、できるだけ多くのノードの次数が正確に deg(u)/2 になるように、ツリー エッジの方向を選択することになります。 すべてのツリー エッジが 1 つの入力カウントを 1 つのエンドポイントに正確に寄与するため、合計の入次数合計は n−1 に固定されます。 これにより、ノードレベルの次数要件を満たそうとする際に、各エッジを 1 つのエンドポイントに割り当てるという問題が発生します。 

重要な構造上の観察は、ツリーの任意の方向が有効であり、そのようなすべての方向が少なくとも 1 つの順列 (有向ツリーの位相順序) に対応するということです。 したがって、問題を 2 つの段階に分けることができます。まず満足するノードを最大化する方向を選択し、次に一貫した順序を出力します。

残りの問題は、多くのノードが入射エッジのちょうど半分を受け取るようにエッジを割り当てる方法です。 これはノードごとの要求を伴うツリーの実現可能性の問題となり、ボトムアップの貪欲な構築によって解決できます。 リーフは、決定論的な割り当てを強制するため、特に重要です。リーフは、その単一のエッジを一方向にのみ送信できるため、その要件によってそのエッジが即座に決定されます。 

すべてのノード要件が修正されたら、リーフから上方向に割り当てを伝播し、サブツリーが「準備完了」になったときに常にエッジを解決できます。 これにより、グローバルな後戻りが回避され、複雑さが線形に保たれます。

 ## アルゴリズムのチュートリアル

 まず、できるだけ多くのノードが入射エッジのちょうど半分を向くようにエッジに方向を割り当てるという問題を再解釈します。 その後、この方向の割り当てと一致する有効な順列を再構築します。 

1. 任意にツリーをルート化します。 これにより、ツリーにはサイクルがないため、実現可能性を変えることなくエッジをボトムアップで処理するための構造が得られます。 
2. すべてのノード u について、そのターゲットの入力次数を計算します。 deg(u) が偶数の場合、target[u] = deg(u) / 2 を設定します。 deg(u) が奇数の場合、u のバランスを考慮しないため、グローバルな実現可能性を確保するために、ターゲットを後で柔軟に設定できます。 

すべての偶数次のノードを修正できる理由は、これらのノードがまさにバランスをとることができる唯一のノードであるためです。そのため、数を最大化するということは、可能であればすべてのノードを満たすように努めることを意味します。 
3. ここで、各ノード u が正確に target[u] の入力エッジを受信するように、各エッジに方向を割り当てます。 葉を剥がす戦略を使用してツリーを処理します。 親 p を持つリーフ u では、エッジ (u, p) が唯一の入射エッジであるため、u が入力エッジをまだ必要としているか、それとも入力エッジを外側に送信する必要があるかに基づいて方向を決定します。 

u を満たすために利用できる他のエッジがないため、これは強制されます。 
4. リーフを処理した後、それを削除し、親の残りの要件を更新します。 縮小されたツリーにおいて親がリーフになった場合は、次に親が処理されます。 これにより、すべてのエッジが 1 回だけ決定されることが保証され、各決定は 1 つのエンドポイントの下に未解決の構造が残っていないときに行われるため、矛盾は発生しません。 
5. すべてのエッジの方向が決まったら、有向ツリーのトポロジカル順序付けを実行して有効な順列を構築します。 ツリーは非巡回であるため、どの向きでも DAG が生成され、標準の DFS ベースの順序付けまたはカーンのアルゴリズムを簡単に実行できます。 

### なぜ効果があるのか

 不変条件は、葉 u からその親 p までのエッジを最終決定するときは、u の要件が残りの未解決の構造によってすでに決定されている場合にのみ最終決定するということです。 これにより、u は今後の決定によって影響を受けることがなくなり、すべてのエッジがノードのターゲットを満たすために 1 回だけ貢献します。 すべてのノードにわたる入力エッジの総数は n−1 に固定されており、すべての割り当てによって明確に定義されたローカル不足が削減されるため、プロセスは、要件が固定されると、満たされたノードをオーバーシュートまたはアンダーシュートすることはできません。 これにより、残りの構造でターゲットが実現可能なすべてのノードが満たされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    adj = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    deg = [len(adj[i]) for i in range(n)]
    target = [0] * n
    for i in range(n):
        if deg[i] % 2 == 0:
            target[i] = deg[i] // 2
        else:
            target[i] = 0

    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = -2

    while stack:
        u = stack.pop()
        order.append(u)
        for v in adj[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    children = [[] for _ in range(n)]
    for v in range(1, n):
        children[parent[v]].append(v)

    indeg_need = target[:]

    # process nodes in reverse order (postorder)
    for u in reversed(order):
        for v in children[u]:
            if indeg_need[v] > 0:
                indeg_need[v] -= 1
            else:
                indeg_need[u] -= 1

    # build directed edges consistent with needs
    directed = [[] for _ in range(n)]

    for u in range(n):
        for v in adj[u]:
            if parent[v] == u:
                # edge u - v, decide direction
                if indeg_need[v] > 0:
                    directed[u].append(v)
                    indeg_need[v] -= 1
                else:
                    directed[v].append(u)
                    indeg_need[u] -= 1

    # topological order (tree so simple DFS works)
    visited = [False] * n
    res = []

    def dfs(u):
        visited[u] = True
        for v in directed[u]:
            if not visited[v]:
                dfs(v)
        res.append(u)

    dfs(0)
    print(*res)

if __name__ == "__main__":
    solve()
```実装は、ツリーを読み取り、次数を計算することから始まります。 奇数次数のノードは決してバランスをとることができず、目標に寄与しないため、バランス ターゲットは偶数次数のノードにのみ割り当てられます。 

ルート検索により親子関係が確立され、制御されたボトムアップ方式でツリーを処理できるようになります。 逆走査は、子から上への「受信エッジ要件」の分散をシミュレートし、先祖に影響を与える前に不足がローカルで解決されることを保証します。 

2 番目のフェーズでは、残りの要件に基づいて実際のエッジ方向を割り当てます。 各エッジは 1 回だけ決定され、その決定は子が入力エッジをまだ必要としているかどうかによってのみ決まります。 

最後に、有向構造上の DFS により、すべてのエッジ方向と一致する有効な順序付けが生成されます。 ツリーの向きが常に DAG を形成するため、この順序が存在することが保証されます。

 ## 特殊なケース

 単一ノードの場合、エッジは存在しないため、順列は自明に有効であり、ノードは空にバランスが保たれています。 このアルゴリズムはゼロのターゲットを割り当て、単一の頂点を出力します。 

長さ 2 のパスの場合、中間ノードは次数 2 を持ち、バランスをとることができます。 リーフ処理は 2 つのエッジに反対方向を強制し、中間ノードがターゲットと一致する 1 つの入力エッジを確実に受け取ります。 

スター グラフの場合、パリティに応じて中心ノードのみが偶数次数を持つ場合があります。 リーフ ストリッピング プロセスでは、すべてのリーフが最初に解決され、すべての決定が強制的にセンターに蓄積され、パリティ制約に応じてバランスがとれるかどうかが正しく判断されます。
