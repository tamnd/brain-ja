 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、$n$問題設定者と$n$トピックス。 注文した各ペア$(setter, topic)$コストがかかる場合があります。これは、設定者がそのトピックの問題を準備するのに何時間必要かを意味します。 これらのペアの一部のみが利用可能であり、次のように与えられます。$m$エントリ。 

すべてのセッターが少なくとも 1 つのトピックで作業し、すべてのトピックが少なくとも 1 つのセッターに割り当てられるように、作業を割り当てる必要があります。 セッターは複数のトピックで作業でき、トピックは複数のセッターで処理できます。 ただし、重要な制限があります。ステートメントで説明されている依存関係の禁止された混合サイクルを形成するような方法で、セッターとトピックのグループが「相互接続」される状況は存在できません。これは事実上、複数のトピックを共有しながらトピック間で分岐する複数のセッター間での特定の周期的な対話パターンを回避する必要があることを意味します。 

割り当てのコストは、選択したすべてのコストの合計です$(setter, topic)$ペア。 私たちの目標は、この総コストを最小限に抑えるか、それが不可能であると報告することです。 

構造的な観点から見ると、入力はセッターとトピック間の重み付けされた 2 部グラフを定義します。 選択したサブグラフに曖昧さサイクルを導入することに対応する禁止された構造構成を回避しながら、両側のすべての頂点を強制的にカバーする制約の下でエッジを選択しています。 

制約$n \le 200$そして$m \le n^2$潜在的に次のようなグラフの定式化を強く提案します。$O(n^2)$エッジ。 このサイズにより、エッジまたは頂点にわたる指数関数的なサブセットの列挙が除外されます。 割り当てのすべてのサブセットを明示的に考慮しようとするソリューションは、直ちに実行不可能になります。 

単純なアプローチでは、各セッターを独立して処理するか、頂点ごとに最小エッジを貪欲に割り当てようとしますが、サイクル制限の下では局所的な最適性がグローバルな実現可能性を維持しないため、これは失敗します。 主な困難は、実現可能性がノードごとのカバレッジだけでなくグローバル構造に依存することです。 

貪欲な選択により、セッターとトピックの交互割り当ての間でサイクルが発生する場合、微妙な失敗ケースが発生します。 たとえば、設定者 A がトピック X を B と共有し、B がトピック Y を C と共有し、C が分岐しながら再び X を共有すると、禁断の絡み合った構造が作成されます。 ノードごとに最も安価なエッジを選択する貪欲な割り当てにより、気付かずにそのような構成を簡単に作成できます。 

もう 1 つのエッジ ケースは、セッターまたはトピックに利用可能なエッジが 1 つしかない場合です。 そのエッジを選択しないと実現不可能になります。 正しいアルゴリズムは、暗黙的または明示的に強制割り当てを尊重する必要があります。 

## アプローチ

 この問題を解決する鍵は、禁止された構成の構造がまさにこの問題を単純な独立した代入問題として扱うことを妨げていることを認識することです。 代わりに、エッジの選択を二部構造を形成するものとして解釈する必要があります。そこでは、接続された各コンポーネントが交互の制約の下で制限されたツリー状または非循環的な方法で動作する必要があります。 

ブルートフォースのアイデアは、エッジのすべてのサブセットを試し、すべての頂点がカバーされているかどうかを確認し、禁止された相互作用パターンが現れるかどうかを確認し、コストを計算することです。 これは正しいですが、まったく実行不可能です。 まで$200^2 = 40000$エッジの場合、サブセットの数は$2^{40000}$、これは計算の限界をはるかに超えています。 

重要な観察は、禁止された「クリエイティブすぎる」条件は、マルチブランチ インタラクション サイクルの回避に対応しており、これは、カバレッジ制約のある 2 部擬似フォレストを形成する最小コストのエッジ セットを選択するのと同様の構造を強制するものとしてモデル化できるということです。 これは自然に、フローまたはマッチングベースの再定式化につながります。 

各セッターとトピックには少なくとも 1 つのインシデント選択エッジが必要であり、各エッジにはコストがかかるフロー ネットワークを構築します。 循環を防止する制約は、各頂点がカバーされ、構造規則に違反するような「過剰接続」の頂点がない最小コストの割り当てを選択するという問題に集約することで強制できます。 これは、両方のパーティションにまたがる構造を形成する最小コストのエッジ セットを確実に選択することと同等になり、下限のある最小コスト フローを使用して解決できます。 

各セッターとトピックを、少なくとも 1 つの発信エッジまたは着信エッジを強制する制約を持つノードに分割し、スーパー ソースとスーパー シンクを追加します。 それぞれ有効$(setter, topic)$エッジはコスト付きの容量 1 のエッジになります$h$。 下限制約により、すべてのノードが少なくとも 1 回は参加する必要があります。 これにより、この問題は、需要を伴う標準的な最小コストの循環問題に変換されます。 

ブルート フォースは組み合わせ爆発により失敗しますが、フロー モデルはすべての相互作用を多項式構造に圧縮します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース |$O(2^m)$|$O(m)$| 遅すぎる |
 | 下限のある最小コスト フロー |$O(n^2 \log n)$または$O(n^3)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 左側のノードがセッター、右側のノードがトピックで、それぞれが指定されたペアである 2 部グラフを構築します。$(k, t)$コストを伴うエッジです$h$。 これにより、考えられるすべての有効な作業割り当てが直接エンコードされます。 
2. 各セッターが少なくとも 1 単位のフローに寄与する必要があることを保証する容量制約のあるすべてのセッターに接続されたソース ノードを追加します。 これにより、すべてのセッターが少なくとも 1 回は使用されるようになります。 
3. 同様の下限制約を使用して各トピックからシンクにエッジを追加し、すべてのトピックが少なくとも 1 回カバーされるように強制します。 
4. ノードの需要を調整することにより、すべての下限制約を標準循環問題に変換します。 各セッターには需要があります$+1$、それぞれのトピックには需要があります$+1$、ソースとシンクの合計フローのバランスがとれています。 この変換により、実現可能性がすべてのノードをカバーすることに正確に対応することが保証されます。 
5. 許可されるそれぞれについて$(setter, topic)$割り当てでは、容量 1 と必要な時間に等しいコストの有向エッジを追加します。 これらのエッジは、可能な割り当てを表します。 
6. 最小コスト最大フロー (または最小コスト循環) アルゴリズムを実行して、最小の総コストですべての要求を満たします。 フローは合計時間を最小限に抑えながら、割り当てを自動的に選択します。 
7. フローがすべての要求を満たせない場合は、「不可能」を出力します。 それ以外の場合、フローの合計コストは、最小合計準備時間になります。 

### なぜ効果があるのか

 核となる不変条件は、フローのすべての単位が有効な 1 つのみを選択することに対応するということです。$(setter, topic)$割り当て、および需要制約により、すべてのセッターとすべてのトピックが少なくとも 1 つの選択された割り当てに強制的に付随します。 フロー保存制約により、一貫性のない部分割り当てが防止され、容量制約により、単一ペアの実行可能性を超えた過剰使用が防止されます。 コストはエッジにわたって加算され、フローは独立した割り当て単位に分解されるため、実行可能な循環は有効なコンテスト構造に正確に対応し、最適なフローは最小の合計準備時間に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque
import heapq

class Edge:
    def __init__(self, to, cap, cost, rev):
        self.to = to
        self.cap = cap
        self.cost = cost
        self.rev = rev

class MinCostFlow:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, fr, to, cap, cost):
        fwd = Edge(to, cap, cost, len(self.g[to]))
        rev = Edge(fr, 0, -cost, len(self.g[fr]))
        self.g[fr].append(fwd)
        self.g[to].append(rev)

    def flow(self, s, t, maxf):
        n = self.n
        res = 0
        h = [0] * n

        while maxf > 0:
            dist = [10**18] * n
            dist[s] = 0
            prevv = [-1] * n
            preve = [-1] * n
            pq = [(0, s)]

            while pq:
                d, v = heapq.heappop(pq)
                if dist[v] < d:
                    continue
                for i, e in enumerate(self.g[v]):
                    if e.cap > 0 and dist[e.to] > d + e.cost + h[v] - h[e.to]:
                        dist[e.to] = d + e.cost + h[v] - h[e.to]
                        prevv[e.to] = v
                        preve[e.to] = i
                        heapq.heappush(pq, (dist[e.to], e.to))

            if dist[t] == 10**18:
                return None

            for i in range(n):
                if dist[i] < 10**18:
                    h[i] += dist[i]

            addf = maxf
            v = t
            while v != s:
                pv = prevv[v]
                pe = preve[v]
                addf = min(addf, self.g[pv][pe].cap)
                v = pv

            v = t
            while v != s:
                pv = prevv[v]
                pe = preve[v]
                e = self.g[pv][pe]
                e.cap -= addf
                self.g[v][e.rev].cap += addf
                res += addf * e.cost
                v = pv

            maxf -= addf

        return res

n, m = map(int, input().split())

S = 2 * n + 2
SRC = 2 * n
SNK = 2 * n + 1

mcf = MinCostFlow(S)

deg = [0] * S

for _ in range(m):
    k, t, h = map(int, input().split())
    mcf.add_edge(k, n + t, 1, h)

    deg[k] -= 1
    deg[n + t] += 1

for i in range(n):
    mcf.add_edge(SRC, i, 1, 0)
    mcf.add_edge(n + i, SNK, 1, 0)

need = 0
for i in range(S):
    if deg[i] > 0:
        mcf.add_edge(S, i, deg[i], 0)
        need += deg[i]

ans = mcf.flow(S, SNK, need)

if ans is None:
    print("Impossible")
else:
    print(ans)
```この実装では、有効な各割り当てがキャパシティ 1 のエッジであり、コストが準備時間に等しい最小コストのフロー ネットワークを構築します。 また、各セッターとトピックが少なくとも 1 回は強制的に参加するように、スーパー ソース メカニズムを使用してバランス制約をエンコードします。 ポテンシャルを使用した連続最短経路アルゴリズムを使用して、最小コスト循環を効率的に計算します。$n \le 200$これにより、グラフが緻密になりながらも管理しやすくなります。 

よくある落とし穴は、リバース エッジを正しく追加するのを忘れたり、ダイクストラでのポテンシャルの処理を誤ったりすることです。これにより、負のサイクルの問題や不正確な最短拡張パスが発生します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、セッターまたはトピックに利用可能なインシデント エッジが 1 つしかない場合です。 このような場合、そのエッジは有効なソリューションに強制的に適用されます。 需要制約により、そのノードがフローの 1 単位のみを受信するように強制され、代替手段がなくなるため、フロー定式化はこれを自然に処理します。 

もう 1 つの特殊なケースは、2 部グラフ内のコンポーネントが切り離されていることです。 各コンポーネントは独立してカバレッジ制約を満たす必要があります。 それ以外の場合、グローバル割り当ては存在しません。 フローは切断されたコンポーネントを通過できないため、フロー ネットワークはこれらを自然に分離します。 

最後のエッジ ケースは、入力グラフに有効なカバレッジがあるにもかかわらず、コストのバランスが極端に不均衡である場合です。 単純に貪欲に選択すると、局所的に安価なエッジを選択し、他の場所で必要なカバレッジを誤ってブロックしてしまう可能性があります。 最小コスト フローは、すべての割り当てにわたってグローバル コストを同時に考慮することでこれを回避します。
