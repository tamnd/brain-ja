 ## 解決策
 ## 問題の理解

 1 つ以上の無向マルチグラフが与えられます。 各エッジは 2 つの頂点を接続し、正の整数の重みを持ちます。 このタスクは、エッジのサブセットを選択できるように見えるグラフ上の関数を定義しますが、選択されたサブセットの寄与は乗法的です。選択されたすべてのエッジに対して、その重みを乗算します。ただし、一部のエッジは「禁止」されており、寄与はゼロです。 

より正確に言うと、重みのあるエッジ$w$貢献する$w \times p(w)$、 どこ$p(w)$が 1 になるのは次の場合のみです$w$は奇数、それ以外の場合は 0 です。 したがって、均等な重さのエッジが含まれていると、製品全体がすぐに壊れてしまいます。 これは、積を強制的にゼロにするため、最適なサブセットには均等な重みのエッジが決して含まれないことを意味します。 

したがって、問題は、奇数の重みを持つエッジのサブセットを選択し、それらの重みの積を最大化することに帰着します。 エッジなしを選択した場合、製品は慣例により 1 (空の製品) になります。 

入力サイズは最大で$10^5$ノードと$10^5$テスト ケースごとにエッジがあるため、どのソリューションもエッジの数が線形に近くなければなりません。 二次または偶数$O(m \log m)$重い定数を使用するのは問題ありませんが、サブセットを列挙したり、ペアごとの組み合わせを実行したりすることは不可能です。 

微妙なエッジケースとは、すべてのエッジが均一な場合です。 したがって、空でないすべてのサブセットには積 0 が含まれるため、空のセットを選択すると、正解は 1 になります。 答えを 0 として初期化するか、常に少なくとも 1 つのエッジを乗算する単純な実装は、ここで失敗します。 

もう 1 つのエッジ ケースは、同じノード間の複数のエッジです。 エッジはプロダクト内で独立しているため、重複は構造的には重要ではありませんが、数値的には重要であり、奇数の場合はすべて考慮する必要があります。 

## アプローチ

 ブルートフォースの解釈は簡単です。エッジのすべてのサブセットを試し、次の積を計算します。$w(e)$重みが奇数のエッジを対象とし、偶数の重みのエッジを含むサブセットはゼロと評価されるため無視します。 定義は選択されたすべてのエッジに明示的に乗算されるため、これは正しいです。 ただし、サブセットの数は$2^m$、これは$m = 10^5$全く実現不可能です。 

重要な単純化は、グラフ構造が無関係であることを観察することから生まれます。 乗算以外のエッジ間には相互作用はありません。 唯一の決定は、奇数の重みの各エッジを含めるかどうかであり、各含めると独立して積がその重みの係数だけ増加します。 すべての重みは 1 以上の正の整数であるため、すべての奇数重みエッジを含めても積が減少することはありません。 それらをすべて摂取することを妨げる制約はありません。 

したがって、最適な戦略は、すべての奇数の重みを単純に乗算することです。 奇数のエッジがない場合、結果は 1 になります。

 ## アルゴリズムのチュートリアル

 各グラフを個別に処理します。 

1. アキュムレータを初期化する`ans`これは、これまでに選択されたすべての有効なエッジの積を表します。 1 から開始すると、すべてのエッジをスキップして正しい ID 値が得られます。 
2. 各エッジを 1 つずつ読み取ります。 重量のあるエッジに`w`、どうかを確認してください`w`奇数です。 
3. もし`w`が偶数の場合、エッジを完全に無視します。 その寄与はゼロになるため、これは何の役にも立ちません。また、これを含むサブセットは積を強制的にゼロにすることになりますが、これは常にスキップするよりも悪いことです。 
4. もし`w`奇数です、それを掛けます`ans`。 これは、最適なサブセット内のエッジを選択することに対応します。 
5. すべてのエッジを処理した後、出力します`ans`。 

重要な推論ステップは、乗算は結合的かつ可換的であり、選択された値はすべて正であるため、奇数のエッジを除外するメリットはまったくないということです。 

### なぜ効果があるのか

 実行可能なすべての解決策は、エッジのサブセットを選択することに対応します。 偶数の重みのエッジを含むサブセットには積ゼロがあり、すべての奇数エッジの積もゼロでない限り、空のサブセットによって厳密に支配されますが、奇数の重みは少なくとも 1 であるため、ゼロではありません。したがって、最適なサブセットは奇数のエッジのみで構成されます。 奇数エッジでは、それぞれが 1 以上の乗算係数に寄与するため、それらをすべて含めることで積が最大化されます。 エッジ間には依存関係が存在しないため、貪欲な選択が全体的に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return
    it = iter(data)
    out = []

    while True:
        try:
            n = int(next(it))
        except StopIteration:
            break
        m = int(next(it))

        ans = 1

        for _ in range(m):
            w = int(next(it))
            u = int(next(it))
            v = int(next(it))

            if w % 2 == 1:
                ans *= w

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、繰り返しの I/O オーバーヘッドを回避するために、すべての入力を一括で読み取ります。 各エッジは、簡単なパリティ チェックを使用して一定時間で処理されます。 ノード`u`そして`v`計算には無関係で、入力ストリームを正しく進めるためにのみ読み取られます。 

よくある実装上の間違いは、隣接リストを構築しようとしたり、接続性について推論しようとしたりすることですが、グラフ構造が目的関数において何の役割も果たしていないことです。 もう 1 つの微妙な問題は、答えを 0 ではなく 1 に初期化するのを忘れていることです。これにより、すべての出力が誤ってゼロに強制されてしまいます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのエッジの重みが均等である場合です。 次のような入力の場合:```
3 2
2 1 2
4 2 3
```アルゴリズムが初期化されます`ans = 1`、次に両方のエッジをスキップし、結果は変更されません。 これは、必要な空のサブセット値と一致します。 

もう 1 つのケースは、次のような単一の大きな奇数の重みです。```
2 1
999999937 1 2
```このアルゴリズムはそれをアキュムレータに直接乗算し、任意精度の整数による Python でのオーバーフローを心配することなく正しい結果を生成します。 

最後のケースは、すべての奇数エッジを持つ大きな入力サイズです。 このアルゴリズムは引き続きエッジごとに 1 つの乗算を実行し、線形動作を維持します。
