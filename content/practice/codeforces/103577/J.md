 ## 解決策
 ## 問題の理解

 単位正方形の長方形グリッドの上に描かれた単純な多角形が与えられます。 多角形の各頂点は整数座標上にあり、多角形のエッジは連続する頂点間の直線セグメントです。 

タスクは、ポリゴンが削除された領域に完全に含まれるように、いくつの単位グリッド正方形を切り出す必要があるかを決定することです。ただし、各単位正方形が完全に取得されるか、まったく取得されないという制限があります。 言い換えれば、イワンは正方​​形を部分的にカットすることを許可されていません。 正方形の一部が多角形と重なっている場合は、その正方形を削除する必要があります。そうしないと、多角形が削除されたセットに完全に含まれないからです。 

したがって、出力は、少なくとも空ではない方法でポリゴンと交差するグリッド セルの数です。 

グリッドは大きく、各次元で最大 100,000 個ですが、ポリゴン自体は小さく、頂点が最大 50 個です。 この非対称性が重要な構造上のヒントです。すべてのグリッド セルを反復処理するのではなく、グリッド構造に対してポリゴンを処理します。 

素朴な解釈では、多角形の境界ボックス内のすべての単位正方形をテストし、多角形との交差をチェックしようとします。 境界ボックスの辺の長さが最大 ​​100,000 である場合、それはすでに最大 10¹⁰ セルを意味します。これは、セルごとの定数時間の幾何学的テストであっても完全に実行不可能です。 

ポリゴン エッジがグリッド境界に正確に沿って走っている場合、またはグリッドの頂点を通過している場合には、より微妙なエッジ ケースが発生します。 たとえば、エッジが直線 x = k または y = k 上に正確に存在する場合、不注意な交差ルールによって二重にカウントされたり、セルのストリップ全体が見逃されたりする可能性があります。 もう 1 つの問題は、頂点でのみグリッド ラインに接するポリゴンです。頂点の交点の処理が一貫性を持たないと、スキャンラインのカウントでオフバイ 1 エラーが発生します。 

## アプローチ

 この問題は、単純な多角形が「接触」している単位セルの数を数えるのと同じです。 セルは、ポリゴンがその内部または境界と交差する場合にカウントされます。 頂点は整数座標であるため、ポリゴンとグリッドの間のすべての関連する相互作用は、整数に揃えられた水平線と垂直線で発生します。 

ブルートフォースのアイデアは簡単です。多角形の境界ボックス内のすべてのグリッド セルを反復処理し、多角形がその正方形と交差するかどうかを確認します。 セルごとのポリゴン内のポイントまたはセグメント正方形の交差テストは正しいでしょう。 ただし、境界ボックスは 10⁵ × 105 にもなり、候補セルの数が 10¹⁰ になる可能性があり、これは実行可能な実行時間をはるかに超えています。 

重要な観察は、個々のセルについて独立して推論する必要がないということです。 代わりに、グリッドを行ごとに処理できます。 y と y + 1 の間の固定水平ストリップの場合、その行のすべてのセルが x 軸の単位間隔に対応します。 多角形が水平線と交差する x 間隔がわかれば、整数単位セグメントが何個重なっているかを直接数えることができます。 

これにより、問題はスキャンラインの計算に変わります。水平線 y + 0.5 (セルの行の中央を表す) ごとに、多角形とその線の交点を計算し、1 つ以上の x 間隔を生成します。 各間隔は、カバーされる整数セグメントの数に基づいて、完全な単位セルの数に寄与します。 

n は最大 50、h は最大 10⁵ であるため、これらの交差を行ごとに個別に再計算することができます。 各行では多角形のすべてのエッジをチェックする必要があり、合計で約 5 × 10⁶ のエッジ チェックが行われますが、これは許容範囲内です。

 ## アルゴリズムのチュートリアル

グリッドを行ごとに処理します。 各行は、その行内のすべてのセルの中心を通過する水平線 y + 0.5 に対応します。 

1. 行インデックス y を 0 から h − 1 までに固定します。この行内の単位正方形の数が多角形と交差する数を計算します。 
2. この行について、多角形のエッジと高さ y + 0.5 の水平線の間のすべての交点を計算します。 各エッジについて、端点間でこの水平線を厳密に横切るかどうかを確認します。 一致する場合は、線形補間を使用して交点の x 座標を計算します。 
3. すべての交点の X 座標を収集します。 多角形は単純であるため、これらの交差は並べ替え可能なシーケンスを形成し、多角形は走査線に入るときと走査線から出るときを交互に繰り返します。 並べ替え後、連続するペアによってポリゴン内の x 間隔が定義されます。 
4. 各区間 [l, r] について、整数単位セグメント [x, x + 1] が交差する数を計算します。 この行の単位セルは、その間隔が多角形投影と重なる場合に含まれます。 これは、x < r および x + 1 > l となるような整数 x をカウントすることになり、max(0, Floor(r − ε) − ceil(l) + 1) として計算できます。 
5. すべての間隔にわたる寄与を合計し、最終的な答えに累積します。 
6. すべての行に対してこれを繰り返し、合計を出力します。 

重要な実装の詳細は、走査線に接触するエッジの一貫した処理です。 二重カウントを避けるために、各エッジは 2 つのエンドポイントの行のうちの 1 つで正確にカウントされる必要があります。 これは、y の半開間隔でエッジをアクティブとして扱うことによって処理されます。 

### なぜ効果があるのか

 このアルゴリズムは、固定スキャンラインの不変式に依存しています。つまり、任意の水平線 y + 0.5 について、多角形は互いに素な間隔の集合で交差し、それらの間隔は、標準の偶奇ルールに基づいて、その線上のどの点が多角形の内側に位置するかを正確に表します。 行 y のすべての単位正方形には点 (x + 0.5, y + 0.5) が含まれるため、多角形内にそのような点がいくつあるかを数えるのは、交差するセルを数えるのと同じです。 各単位セルがその走査線上の一意の整数 x 間隔に対応するため、連続間隔から整数カウントへの変換は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, w, h = map(int, input().split())
    poly = [tuple(map(int, input().split())) for _ in range(n)]

    # close polygon
    poly.append(poly[0])

    ans = 0

    for y in range(h):
        y_line = y + 0.5
        xs = []

        for i in range(n):
            x1, y1 = poly[i]
            x2, y2 = poly[i + 1]

            # check if edge crosses the horizontal line
            if y1 == y2:
                continue

            # ensure y1 < y2
            if y1 > y2:
                x1, x2 = x2, x1
                y1, y2 = y2, y1

            if y1 <= y_line < y2:
                t = (y_line - y1) / (y2 - y1)
                xs.append(x1 + t * (x2 - x1))

        xs.sort()

        # pair up intersections
        for i in range(0, len(xs), 2):
            l = xs[i]
            r = xs[i + 1]
            if r <= l:
                continue

            L = int(l + 1e-12)
            R = int(r - 1e-12)

            if R >= L:
                ans += R - L + 1

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、行ごとのスキャンラインのアプローチに従っています。 水平ストリップごとに、すべてのポリゴン エッジから x 交差を収集し、それらを並べ替えて、それらをペアとして処理して内部セグメントを形成します。 セグメントごとの最終的な整数カウントは、浮動区間を整数でカバーされる単位セルに変換することによって計算されます。 

実装の微妙な詳細は、半開間隔条件です。`y1 <= y_line < y2`これにより、共有頂点での二重カウントが防止されます。 このルールがないと、2 つのエッジが共有する頂点によって重複した交点が生成され、間隔のペアが破損します。 

浮動小数点区間エンドポイントから整数境界への変換では、小さなイプシロン シフトを使用して浮動小数点境界ケースを安定させます。 これが必要なのは、正確な算術構造により交差座標が整数に非常に近くなる可能性があるためです。

 ## 特殊なケース

 重要なエッジ ケースは、ポリゴンの頂点が正確にスキャンライン y + 0.5 上にある場合です。 その状況では、両方の入射エッジを単純に含めると重複した x 交差が生成され、不正確なペアリングが発生します。 半開間隔ルール y1 <= y_line < y2 により、各頂点が正確に 1 つの走査線に寄与することが保証されます。 

もう 1 つのケースは、水平ポリゴン エッジです。 水平エッジは完全に走査線の境界内にあり、開始イベントまたは終了イベントを定義しないため、交差には影響しません。 それらを含めると、交差点の数が人為的に増大します。 

最後に、グリッド ラインに正確に沿って走るポリゴンは、浮動小数点を慎重に処理する必要があります。 一貫したイプシロン戦略や堅牢な整数演算がないと、連続間隔を整数セル範囲に変換するときに交差エンドポイントでオフバイ 1 エラーが発生する可能性があります。
