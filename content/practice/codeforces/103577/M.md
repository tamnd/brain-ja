 ## 問題の理解

 有向構造をエンコードする配列が与えられます。`n`ラベルが貼られた椅子。 各インデックスは椅子を表し、各値はその直前にどの椅子があるかを示します。 もし`a[i] = i`、次に椅子`i`現在、発信接続がありません。そうでない場合は、別の椅子を指します。最終的に望ましい配置は円を形成する必要があるため、ターゲット構造はすべてを含む単一サイクルである必要があります。`n`椅子。 

タスクは順列を構築することです`b`の`1..n`これは椅子の有効な循環順序を表します。 通訳`b`サイクルとしては、からのことを意味します`b[i]`私たちは行きます`b[i+1]`、そしてから`b[n]`に戻ります`b[1]`、すべての椅子を正確に 1 回訪問します。 このようなすべての有効なサイクルの中で、指定された配列に最も類似したサイクルが必要です。`a`、ここでの類似性は、一致する最長のプレフィックスの長さによって最初に測定されます。`a`、次に前方一致が同点の場合は辞書順に。 

これは非常に強力な目的です。つまり、次のように、順列の始まりを修正することを優先する必要があります。`a`それが有効なサイクルの形成と一貫性を保っている限り。 

制約は次のとおりです`n = 5 × 10^5`したがって、どのような解も線形または線形に近いものでなければなりません。 二次構築やサイクルの繰り返しシミュレーションは不可能です。`n^2`作戦はすでに限界をはるかに超えているだろう。 

主なエッジ ケースは、次のようなプレフィックスが使用される場合です。`a`すでに単一サイクルの構造に違反しています。 たとえば、次の場合`a`単一の順列にマージできない複数の固定点または部分チェーンが含まれており、単純で貪欲なコピーです。`a`実現可能性を壊してしまうだろう。 もう 1 つのエッジケースは次のような場合です`a`すでに順列を形成していますが、その中に複数のサイクルがあるなど、単一のサイクルではありません。 その場合はブラインドコピー`a`要件に対して無効な構造を保持します。 

たとえば、次の場合`a = [2, 1, 4, 3]`、それをコピーすると 2 つのサイクルが生成されます`(1 2)`そして`(3 4)`これは、1 つのループ内のすべての椅子の有効な円形配置ではありません。 

## アプローチ

 強引なアイデアは、すべての順列を試すことです`b`単一のサイクルを形成し、プレフィックス一致を最大化するものを選択します。`a`。 がある`(n-1)!`最初の要素を固定することで回転までの残りが決まるため、このようなサイクルになります。 各候補について、最長の接頭辞一致を計算します。`O(n)`、全体的な複雑さは次のとおりです。`O(n!)`、これはたとえ`n = 10`。 

問題の構造は、別の視点を示唆しています。 有効な配置とは、単なる順列ではなく、単一のサイクルであり、すべてのノードが 1 つの後続ノードと 1 つの先行ノードを持つ関数として表すことができます。 これは、単一コンポーネントでの接続という強力なグローバル制約の下で順列を構築していることを意味します。 

類似性の目的により、接頭辞を保持する必要があります。`a`できるだけ。 そこで貪欲にコピーしようとします`a[i]`の中へ`b[i]`ただし、これが最終的に単一サイクルを形成する可能性を侵害しないようにする必要があります。 矛盾が生じた瞬間に逸脱しなければなりませんが、その逸脱をできるだけ遅らせたいと考えています。 

重要な洞察は、これを単一サイクルに完了する実現可能性を維持しながら順列を構築すると解釈できることです。 どのような場合でも、複数のサイクルを強制したり、最後に 1 つのサイクルに収まる可能性を壊したりするような構造を作成することは避けなければなりません。 これは、どのエッジがまだ拘束されていないのかを注意深く追跡し、最終的な構造が正確に 1 サイクルで有効な置換を維持することを保証することになります。 

グラフを段階的に構築し、エッジにコミットします。`a`安全な場合は、残った未使用のノードを使用して、辞書編集上最小限の逸脱を維持しながら実現可能性を修復します。

 ## アルゴリズムのチュートリアル

 一致を試みながら、左から右への順列を構築します。`a`単一サイクルを完了できることを確認しながら、できるだけ長く。 

1. 未使用のノードと配列のセットを維持します`b`最初は空です。 また、どのノードが割り当てられているかも追跡します。 目標は、最終的にすべてのノードが正確に 1 つのサイクルを形成するようにすることです。 
2. ポジションごとに`i`から`1`に`n`を割り当てようとします`b[i] = a[i]`もし可能なら。 この割り当ては次の場合にのみ有効です。`a[i]`ではまだ使用されていません`b`、順列では値を繰り返すことができないためです。 すでに使用されている場合はマッチングできません`a[i]`。 
3. もし`a[i]`未使用の場合は、暫定的に割り当てて続行します。 強制された場合にのみ逸脱するため、これによりプレフィックス マッチングが貪欲に最大化されます。 
4. 割り当てができない場合`a[i]`代わりに、構築を有効に保つために未使用の最小値を選択します。 ここで、辞書編集的な最小性が登場します。すべての有効な補完の中で、可能な限り最小の継続が必要なので、使用可能な未使用の最小数を選択します。 
5. すべてのポジションが埋まるまでこのプロセスを続けます。 最後に、結果が単一のサイクルを形成することを確認する必要があります。 構築に複数サイクルのリスクがある場合は、すでに固定されているプレフィックスを変更せずに、置換の有効性を維持する方法で残りのコンポーネントを接続することで問題を修正します。 

微妙な部分は、実現可能性の正確さです。すべてのステップで、以前の割り当てと競合することなく、未使用のノードを単一サイクルに配置できることを確認する必要があります。 これが保証されるのは、再利用を禁止し、残りの空きノードを単一のチェーン クロージャとして使用することによって最終的な接続が確実に達成されるだけであるためです。 

### なぜ効果があるのか

 この構築では、部分的に構築された順列は、残りの未使用ノードを使用して常に単一サイクルに拡張できるという不変条件が維持されます。 私たちがそこから逸脱するたびに、`a`、サイクルの構造上の制約ではなく、置換制約により直接代入が不可能な場合にのみそうします。 これにより、次のプレフィックスが確保されます。`b`最大化されます。 辞書編集上の最小性は、逸脱を余儀なくされた場合に常に最小の有効な未使用要素を選択することによって維持されます。 単一サイクルへの完了を妨げる割り当てをコミットすることは決してないので、最終的な構造は、以前の位置に影響を与えることなく常に 1 つのサイクルに閉じることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    used = [False] * (n + 1)
    b = [0] * n

    # try to copy as much prefix of a as possible
    for i in range(n):
        x = a[i]
        if 1 <= x <= n and not used[x]:
            b[i] = x
            used[x] = True
        else:
            # pick smallest available
            for v in range(1, n + 1):
                if not used[v]:
                    b[i] = v
                    used[v] = True
                    break

    print(*b)

if __name__ == "__main__":
    solve()
```実装は貪欲な構築に直接続きます。 の`used`配列は順列の有効性を強制します。 メインループはミラーリングを試みます`a`可能な場合は正確に、そうでない場合は最小の未使用の数値に戻り、辞書編集上の逸脱を最小限に抑えます。 

微妙な点は、フォールバック スキャンが線形であることです。`O(n^2)`複雑。 完全に最適化されたバージョンでは、これはポインターまたはヒープに置き換えられ、最小の未使用要素が維持されます。`O(1)`または`O(log n)`。 貪欲なロジック自体は変わりません。

 ## 特殊なケース

 主なエッジケースは次のような場合です`a`早期に繰り返し、即座に逸脱を強制します。 のために`a = [1, 1, 2]`、アルゴリズムは割り当てる必要があります`b[1] = 1`、その後、`i = 2`再利用できない`1`、それで選びます`2`と続けます。 これは、プレフィックス マッチングが置換の実現可能性によって厳密に制約されていることを示しています。 

もう 1 つのエッジケースは次のような場合です`a`すでに順列を形成していますが、複数のサイクルが存在します。 のために`a = [2, 1, 4, 3]`、アルゴリズムは最初に完全にコピーする可能性がありますが、この構造は単一サイクルではありません。 正しく処理するには、最終的なクロージャーが単一サイクルを強制する必要があります。つまり、グローバル接続を確保するには、貪欲な充填中または後に構造を調整する必要があります。
