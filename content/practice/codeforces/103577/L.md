 ## 解決策
 ## 問題の理解

 各頂点がすでに整数値を持っているルート付きツリーが与えられます。 ルートはノード 1 です。ツリーとともに、更新値のリストが与えられます。 更新ごとに、頂点のサブセットを選択し、その更新値を選択したすべての頂点に追加できます。 どの頂点が更新を受け取るかは、更新ごとに個別に決定できます。 

すべての更新を適用した後、すべての頂点は、初期値に更新値の選択されたサブセットの合計を加えた値で終了します。 異なる頂点は異なるサブセットを選択することができます。 

最後の要件はツリー上のヒープ条件です。すべての子はその親以下の値を持つ必要があります。 更新を適用するあらゆる方法の中で、すべての最終頂点値の合計が可能な限り最小になる有効なヒープを実現したいと考えています。 ヒープ条件を満たす割り当てがない場合は、-1 を出力します。 

制約が非常に厳しいため、強引なサブセット構築で各頂点を個別に処理することはできません。 最大 1000 の更新と最大 100000 の頂点があるため、ノードごとにすべての割り当てを計算または探索しようとするソリューションはすぐに失敗します。 サブツリーごとに考えられるすべてのサブセットの合計を追跡する動的プログラミング ソリューションでさえ、最悪の場合、サブセットの合計が約 10^6 に達する可能性があるため、爆発する可能性があります。 

微妙なエッジ ケースは、頂点が親の制約を満たすのに十分な高い値に到達できない場合に発生します。 たとえば、親が少なくとも 50 である必要があるが、子が 40 から開始し、可能な増分が {5, 7} のみである場合、子は 40、45、47、52 などにのみ到達できます。 50 を超える到達可能な最小値が存在しない場合、ツリー構造自体は問題なくても、構成は不可能です。 

## アプローチ

 一見すると、各ノードが到達可能な値のセットから値を選択し、親子の順序制約を強制するツリー動的プログラミングの問題のように感じられます。 これにより、当然のことながら、「このノードが値 v を持つ場合のサブツリーの最小コスト」のような DP 状態が得られます。 遷移には、各子に対して、v を超えないすべての値の最小値を取る必要があります。ノードの数と可能な値の数が両方とも大きいため、これはすぐにコストが高くなります。 

本当の単純化は、通常は絡み合っている 2 つの概念、つまり、許容値の構造とツリー制約を分離することで実現します。 

各ノードは、更新値のサブセットを独立して選択できます。 これは、すべてのノードが、初期値によってのみシフトされる、可能な増分の同じ基本セットを持っていることを意味します。 重要なのは、これらのサブセットの選択方法にノード間の結合がないことです。 1 つの頂点に対する選択は、別の頂点の実行内容には影響しません。 

ノードの値を固定したら、その子はその値に対する 1 つの制約を満たすだけで済みます。 兄弟間の交流はなく、世界的な予算もありません。 これにより、サブツリー DP の必要性が完全になくなります。 代わりに、最適な戦略は貪欲になります。つまり、各ノードに、その親に関して依然として有効な、取り得る最小の値を割り当てます。 

したがって、更新配列のすべてのサブセット合計を 1 回事前計算します。 次に、各ノードの許容値は、その初期値にサブセットの合計を加えたものになります。 ルートからの走査中に、各ノードが到達する必要がある最小値 (親に割り当てられた値) を維持します。 各ノードは、少なくともこのしきい値である到達可能な最小値を個別に選択します。 それができないなら、答えは不可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブツリー状態に対するブルート フォース DP | O(n · 2^q) 以上 | O(n · 2^q) | 遅すぎる |
 | 値ドメイン上のサブツリー DP | O(n · V^2) | O(n · V) | 遅すぎる |
 | サブセット合計の前処理による貪欲な | O((n + q・V) + n log V) | O(V) | 承認済み |

 ここで、V はすべての更新値の合計であり、約 10^6 で区切られます。 

## アルゴリズムのチュートリアル

## アルゴリズムのチュートリアル

 1. 可能な合計に対してブール型ナップザック スタイルの DP を使用して、更新配列のすべてのサブセット合計を計算します。 0 から開始し、値 xi を更新するたびに、既存の合計に xi を加算して、新しい到達可能な合計をマークします。 これにより、どのノードでも達成できる増分の完全なセットが得られます。 
2. 到達可能なサブセット合計のリストを並べ替えます。 これにより、二分探索を使用して「しきい値を超える最小の到達可能な値」クエリに答えることができます。 
3. ツリーを構築し、ノード 1 でルートします。DFS または BFS を使用してツリーを走査し、各ノードに許容される最小値を伝えます。 
4. ルートに可能な限り小さい値を割り当てます。 サブセットの合計には常に 0 が含まれるため、ルートは単純にその初期値を取得します。 この選択は最適です。なぜなら、この値を増やすと、制約を解決することなく最終的な合計が増加するだけであるからです。 
5. 根元から下に向かってトラバースします。 各ノード u について、その親に割り当てられた値に等しい必要な下限 L を維持します。 
6. ノード u について、a[u] + s ≥ L となる最小のサブセット合計 s を計算します。これは、ソートされたサブセット合計リストを二分探索して最小の s ≥ L − a[u] を求めることによって行います。 
7. そのようなサブセット合計が存在しない場合、構成は不可能であると直ちに結論付けます。 
8. それ以外の場合は、値 a[u] + s をノード u に割り当て、この値を下限として使用してその子へのトラバースを続行します。 

これが機能する主な理由は、親の値が固定されると、各ノードの決定が独立しているためです。 唯一の制約はエッジに沿った単調性であるため、各ノードの値を局所的に最小化しても子孫の実現可能性が制限されることはありません。 

### なぜ効果があるのか

 この構造では単純な不変条件が維持されます。つまり、ノードに入ると、その親から渡される値が、その上のすべての制約を尊重しながら、このノードが取り得る最小値になります。 すべてのノードの実行可能なセットは、そのノード自身のサブセット合計の選択にのみ依存するため、各ノードで実行可能な最小値を選択しても、サブツリー内の将来の選択をブロックすることはできません。 ノードの値を大きくすると子孫の新しいオプションがアンロックされるメカニズムがないため、局所的な最小化が全体的に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    adj = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)
        adj[v].append(u)
    
    xs = list(map(int, input().split()))
    
    # subset sum DP
    S = {0}
    for x in xs:
        new = set()
        for s in S:
            new.add(s + x)
        S |= new
    
    S = sorted(S)
    
    from bisect import bisect_left
    
    parent = [-1] * n
    order = [0]
    stack = [0]
    
    # build parent array
    while stack:
        u = stack.pop()
        for v in adj[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)
            order.append(v)
    
    # DFS assign values
    val = [0] * n
    
    # root
    val[0] = a[0]
    
    for u in order[1:]:
        p = parent[u]
        L = val[p]
        need = L - a[u]
        idx = bisect_left(S, need)
        if idx == len(S):
            print(-1)
            return
        val[u] = a[u] + S[idx]
    
    print(sum(val))

if __name__ == "__main__":
    solve()
```解決策は、更新値から到達可能なすべてのサブセットの合計を計算することから始まります。 これは、「ノードごとに複数のサブセットの選択」という複雑さが処理される唯一の場所であり、グローバルに一度だけ実行されます。 

次に、ツリーをルート化し、反復走査を使用して親関係を計算します。 これにより、n が 100000 までの再帰の深さの問題が回避されます。 

割り当て中、各ノードは親、子の順序で 1 回だけ処理されます。 各ノードについて、その親制約を満たすために必要な最小サブセット合計を計算し、二分探索を使用して効率的に選択します。 

よくある実装の落とし穴は、サブセットの合計には 0 (更新を適用しないことに相当する) を含める必要があることを忘れていることです。 これがないと、ルートが誤って拘束されているように見えます。 もう 1 つの微妙な点は、親の値が常に子の前に認識されるように、有効な走査順序でノードを処理することです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ルートを増やす必要はないが、他のすべてのノードがルートに依存している場合です。 この状況でも、ルートは空のサブセット合計にアクセスできるものとして扱われ、その初期値が確実に取得されるようにする必要があります。 サブセット合計セットには 0 が含まれるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、ノードの初期値が非常に小さいものの、親からの必要なしきい値が大きい場合です。 サブセット合計に対する二分探索により、更新の組み合わせがギャップを埋めることができるかどうかが正しく判断されます。 そうでない場合は、より深いサブツリーを探索することなく、そのノードで障害が即座に検出されるため、無駄な計算が防止されます。 

3 番目のケースは、ツリー内の複数のパスが異なる制約を示唆しているが、貪欲なトラバーサルによって各ノードがその親からの制約のみを参照することを保証する場合です。 制約は横方向に伝播しないため、兄弟間の不一致な割り当てが回避され、ソリューションのグローバルな一貫性が維持されます。
