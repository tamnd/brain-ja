 ## 解決策
 ## 問題の理解

 各テスト ケースではゲノム文字列が与えられ、そのすべての連続する部分文字列から得られる数値スコアを割り当てる必要があります。 任意の部分文字列について、その接頭辞パターンがその末尾でどの程度強く繰り返されるかを調べます。 より正確には、部分文字列の場合、同じ部分文字列の接尾辞としても表示される最も長い適切な接頭辞を取得し、その長さを測定します。 その長さは部分文字列のレベルと呼ばれます。 タスクは、指定された文字列のすべての可能な部分文字列にわたってこのレベルを合計することです。 

入力は最大 50 個の文字列で構成され、それぞれの長さは最大 5000 です。これにより、線形スキャンで各部分文字列を独立して処理するアプローチは即座に排除されます。 文字列ごとに O(n^2) 個の部分文字列があるため、部分文字列ごとに O(n) 回の作業を行ったとしても、最悪の場合、約 1.25 × 10^11 回の演算が必要となり、これは実現可能性をはるかに超えています。 

微妙な問題は、レベルが適切なプレフィックスとサフィックスを使用して定義されているため、部分文字列全体がたとえ些細に一致したとしても許可されないことです。 たとえば、「aaaa」の場合、部分文字列「aa」のレベルは 1 ですが、「a」のレベルは 0 です。ミスを引き起こすもう 1 つの点は、構造の重複です。異なる部分文字列が計算の大部分を共有するため、部分文字列ごとに接頭辞と接尾辞の構造を最初から再計算するのは無駄です。 

エッジ ケースは、すべての部分文字列がレベル 0 である「abcde」など、文字列に繰り返しがない場合や、「aaaaa」など、すべての部分文字列に大きな境界構造がある文字列の繰り返しが多い場合に発生します。 完全な部分文字列を有効な境界線として除外することを忘れた単純な解決策では、「aaa」のような場合に過剰にカウントされてしまいます。「aaa」は 3 ではなく 2 に寄与するはずです。 

## アプローチ

 ブルート フォース アプローチでは、すべての部分文字列を検査し、そのレベルを個別に計算します。 部分文字列 s[l..r] の場合、その部分文字列に対して KMP 接頭辞関数などの接頭辞と接尾辞の計算を実行して、その最長の境界を見つけることができます。 これを計算するには O(r-l+1) のコストがかかり、O(n^2) 個の部分文字列があるため、合計の複雑さは O(n^3) になります。 n が最大 5000 の場合、これはすでに遅すぎ、最大 50 のテスト ケースにわたって繰り返すと完全に実行不可能になります。 

重要な観察は、部分文字列のレベルはその部分文字列内の接頭関数の動作にのみ依存し、接頭関数は任意の固定開始位置に対して線形時間で増分的に計算できるということです。 左端点 i を固定すると、接尾辞 s[i:] について、その接頭関数を O(n) で 1 回計算できます。 この接尾辞のすべての接頭辞は、i で始まる部分文字列に正確に対応します。 位置 j の接頭関数の値は、部分文字列 s[i..i+j] のレベルを示します。 これにより、繰り返しの再計算が不要になり、合計作業量が文字列あたり O(n^2) に減ります。 

ブルート フォースから最適な状態への移行は、本質的に、部分文字列ごとの構造の再計算から、同じ開始点を共有するすべての部分文字列にわたる KMP のオートマトンのような移行の再利用に移行することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 開始ごとのプレフィックス関数 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各文字列を個別に処理します。 

1. 開始インデックス i を 0 から n − 1 に固定します。s[i:] を新しい文字列として扱います。 
2. 標準の KMP ロジックを使用して、このサフィックスのプレフィックス関数配列 pi を構築します。 

このサフィックスの位置 j では、pi[j] は、そのサフィックスでもある s[i..i+j] の最長の適切なプレフィックスの長さを表します。 
3. すべての j について、答えに pi[j] を追加します。 これは、部分文字列 s[i..i+j] のレベルを直接累積します。 
4. すべての開始位置 i について繰り返し、寄与を合計します。 

重要な詳細は、pi が文字列全体に対して 1 回ではなく、接尾辞ごとに再計算されることです。 接頭辞の関係は部分文字列の先頭と相対的なものであるため、これが必要です。 

### なぜ効果があるのか

固定 i の場合、接頭辞関数の計算は、s[i:] の接頭辞とその接尾辞の一致をシミュレートします。 各位置 j で計算された pi[j] は、まさに部分文字列 s[i..i+j] の最長境界です。これは、接頭辞関数が、j で終わる接頭辞の接尾辞でもある最長の適切な接頭辞を追跡するように定義されているためです。 すべての部分文字列は何らかの接尾辞の接頭辞として一意に表現されるため、すべての i,j に対するすべての pi[j] を合計すると、すべての部分文字列が 1 回だけカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(s: str) -> int:
    n = len(s)
    total = 0

    for i in range(n):
        pi = [0] * (n - i)
        for j in range(1, n - i):
            k = pi[j - 1]
            while k > 0 and s[i + j] != s[i + k]:
                k = pi[k - 1]
            if s[i + j] == s[i + k]:
                k += 1
            pi[j] = k
            total += k

    return total

def main():
    data = sys.stdin.read().strip().split()
    out = []
    for s in data:
        out.append(str(solve_one(s)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```外側のループは部分文字列の開始を修正し、内側のループはプレフィックス関数を増分的に構築します。 変数 k は、KMP とまったく同様に、現在の境界長候補の役割を果たします。 各不一致フォールバックは、pi でエンコードされた障害リンクに従います。 

よくある実装の落とし穴は、文字を比較するときにインデックスを i でオフセットするのを忘れることです。 もう 1 つは、単一のグローバル プレフィックス関数を誤って使用することです。これにより、関連のない部分文字列が混在し、不正確な境界線が生成されてしまいます。

 文字列「aaa」について考えてみましょう。 

i = 0 の場合:

 | j | 部分文字列 | pi[j] |

 | 0 | | 0 |
 | 1 | ああ | 1 |
 | 2 | ああ | 2 |

 貢献度は3です。 

i = 1 の場合:

 | j | 部分文字列 | pi[j] |
 | --- | --- | --- |
 | 0 | | 0 |
 | 1 | ああ | 1 |

 貢献度は1です。 

i = 2 の場合:

 | j | 部分文字列 | pi[j] |
 | --- | --- | --- |
 | 0 | | 0 |

 貢献度は0です。 

合計は4です。 

次に「アババ」について考えてみましょう。 

i = 0 の場合:

 | j | 部分文字列 | pi[j] |
 | --- | --- | --- |
 | 0 | | 0 |
 | 1 | アブ | 0 |
 | 2 | アバ | 1 |
 | 3 | アバブ | 2 |

これらのトレースは、各部分文字列がその左端から始まる接尾辞の接頭辞として 1 回だけ扱われることを示しています。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | 文字列ごとに O(n^2) | 各接尾辞は線形接頭辞関数を構築し、n 個の接尾辞があります。

 ## 特殊なケース

 「abcde」のような文字列の場合、すべての不一致は接頭関数内ですぐに発生するため、すべての pi[j] はゼロのままになります。 重要なプレフィックス構造を共有するサフィックスがないため、アルゴリズムはすべての部分文字列に対して正しくゼロを累積します。 

「aaaaa」のような均一な文字列の場合、接頭辞関数は接尾辞ごとに線形に増加します。 各開始位置 i について、寄与は三角形であり、アルゴリズムはこれらの寄与を再計算せずに累積します。 プレフィックス関数の構造により、位置 j では、完全な部分文字列自体ではなく、部分文字列よりも厳密に短い有効な最長の境界が常にカウントされることが保証されます。 

「ababa」のような高度に重複するパターンの場合、pi[k-1] によるフォールバックを繰り返すと、「a」、「aba」、「ababa」などのネストされた境界線が正しくキャプチャされます。 各フォールバック ステップでは、k が常に現在のプレフィックスの有効な境界長であるという不変条件が保持されるため、無効な境界長が追加されることはありません。
