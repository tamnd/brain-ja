 ## 解決策
 ## 問題の理解

 私たちは維持しています$n \times n$時間の経過とともに変化するバイナリ マトリックスであり、更新のたびにフローと呼ばれる単一の概要値を報告する必要があります。 フローは、完全に 1 で構成される行の数と、完全に 1 で構成される列の数の合計として定義されます。 

難しいのは、この量を一度計算するのではなく、2 種類の動的操作の下でそれを維持することです。 最初の操作では、単一のセルが変更されます。 2 番目の演算では、左上隅に値を挿入し、行列全体をカスケード方式でシフトします。最初の行が右にシフトし、その最後の要素が 2 行目にドロップされ、このリップルは最後の行まで続き、そこで最後のオーバーフローが破棄されます。 

制約$n, q \le 5000$これは、各操作の後に行と列の純度を最初から再計算するアプローチは遅すぎることを意味します。 フルスキャンには費用がかかります$O(n^2)$を繰り返した$q$回になる$2.5 \times 10^8$操作は境界線に達しており、Python では遅すぎる可能性があります。 さらに悪いことに、シフト操作は移動するため、単純な更新のコストがさらに高くなる可能性があります。$O(n^2)$価値観。 

微妙だが重要な観察は、フローは正確な値ではなく、各行と列が「すべて 1」であるかどうかのみに依存するということです。 これは、生の行列状態ではなく、行と列のカウンターを維持することを示唆しています。 

自明ではないエッジケースはシフト演算です。 行が 1 つのゼロを除いてほとんどすべて 1 である行列を考えてみましょう。 単純なアプローチでは、カウントを追跡するだけで、ゼロが行に出入りするときに正しく更新できない可能性があります。 たとえば、シフト後に行がいっぱいになった場合、その遷移を正確に検出する必要があります。 そうしないと、フローが 1 つずれてしまいます。 

## アプローチ

 ブルート フォース ソリューションでは、操作のたびに行と列のチェックが再計算されます。 クエリごとに、すべての行と列をスキャンし、それぞれが完全に 1 であるかどうかを確認します。 これはフローの定義に直接一致するため、単純明快で正しいです。 ただし、再計算ごとにコストがかかります$O(n^2)$、そして$q = 5000$が鈍くなるにもほどがあります。 

ボトルネックは、どちらの操作もマトリックスの大きな部分に触れる必要があることです。 重要な洞察は、各更新後に実際には完全な行列は必要なく、各行と列が完全に 1 で埋められているかどうかを維持する機能のみが必要であるということです。 これにより、追跡による問題が軽減されます$n^2$セルを追跡する$2n$集約に加えて、構造化されたシフトをサポートします。 

シフト操作が本当の障害です。 完全なカスケードを明示的にシミュレートする代わりに、概念的な長さの 1D 配列に沿った周期的な動きとして再解釈します。$n^2$、しかしそれを具体化することを避けます。 代わりに、行と列のメタデータを維持し、影響を受ける要素に対して循環バッファー スタイル表現を使用します。 

これにより、以下を維持する最適なアプローチが得られます。 

行ごとに 1 つのカウンター: 行にゼロがいくつ残るか

 列ごとに 1 つのカウンター: 列に残るゼロの数

 マトリックス全体を物理的に移動させずにカスケード シフトをシミュレートする構造。 

重要なトリックは、シフトが一定の長さのパスにのみ影響することです。$n$また、最初の列の受信ストリームを表す deque のような構造を使用して、シフトされた要素の「フロンティア」を追跡することで一貫性を維持できます。

 ## アルゴリズムのチュートリアル

 私たちは 3 つの主要なコンポーネントを維持しています。 まず、配列`row_zero[i]`現在行にゼロがいくつあるかを保存する$i$。 この値がゼロの場合、行は 1 でいっぱいになります。 2 番目に、配列`col_zero[j]`列についても同様に定義されます。 3 番目に、効率的な巡回シフトをサポートする方法で行列を維持します。これは、行ごとのデキュー、または行を回転してオーバーフローを伝播する同等のグローバル構造として実装されます。 

また、現在のフロー値を増分的に維持し、行または列が「すべて 1」と「すべて 1 ではない」の間で遷移する場合にのみ更新します。 

### ステップ

 1. 行列を初期化して計算します`row_zero`そして`col_zero`すべてのセルを 1 回スキャンすることによって。 

これにより、ゼロカウントがゼロである行と列をカウントすることにより、初期フローが得られます。 
2. 各行が両端キューとして保存される行列の表現を構築し、$O(1)$両端からのポップおよびプッシュ操作。 

これが必要なのは、シフト操作が行間伝播を伴う行での右回転のように動作するためです。 
3. タイプ 1 の各操作について`(i, j, b)`、セルの古い値を確認して更新します`row_zero[i]`そして`col_zero[j]`それに応じて。 

重要な考え方は、2 つの構造のみが影響を受けるため、行または列がゼロしきい値を超えた場合にのみフローを調整するということです。 
4. 将来のシフト操作の一貫性が保たれるように、実際の更新を両端キュー構造に適用します。 
5. タイプ2動作の場合`(b)`、カスケード挿入をシミュレートします。 

挿入する`b`1列目の前で

 置き換えられた値を行 1 から行 2 へ、というように行まで伝播します。$n$行からの最後のオーバーフローを破棄します$n$各伝播ステップはローカルで 2 行にのみ影響するため、更新します`row_zero`そして`col_zero`再計算ではなく段階的に。 
6. 各操作の後に出力`flow = number of rows with row_zero[i] == 0 + number of columns with col_zero[j] == 0`。 

### なぜ効果があるのか

 このアルゴリズムは、次の不変式に依存します。`row_zero[i]`そして`col_zero[j]`現在の行列状態の各行と列にあるゼロ値のセルの数を常に正確に表します。 すべての操作は一定数のセルのみを変更するか、単一のチェーンに沿って変更を伝播し、そのような各変更はすぐにカウンターに反映されます。 フローはこれらのカウンターがゼロであるかゼロ以外であるかのみに依存するため、カウンターを段階的に維持することで正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    g = [list(map(int, list(input().strip()))) for _ in range(n)]

    row_zero = [0] * n
    col_zero = [0] * n

    for i in range(n):
        for j in range(n):
            if g[i][j] == 0:
                row_zero[i] += 1
                col_zero[j] += 1

    row_full = sum(1 for x in row_zero if x == 0)
    col_full = sum(1 for x in col_zero if x == 0)

    for _ in range(q):
        op = input().split()

        if op[0] == '1':
            i = int(op[1]) - 1
            j = int(op[2]) - 1
            b = int(op[3])

            if g[i][j] != b:
                if g[i][j] == 0:
                    row_zero[i] -= 1
                    col_zero[j] -= 1
                else:
                    row_zero[i] += 1
                    col_zero[j] += 1

                g[i][j] = b

                if row_zero[i] == 0:
                    row_full += 1
                elif row_zero[i] == 1 and b == 0:
                    row_full -= 1

                if col_zero[j] == 0:
                    col_full += 1
                elif col_zero[j] == 1 and b == 0:
                    col_full -= 1

        else:
            b = int(op[1])

            carry = b
            for i in range(n):
                old = g[i][0]
                g[i][0] = carry

                if old != carry:
                    if old == 0:
                        row_zero[i] -= 1
                        col_zero[0] -= 1
                    else:
                        row_zero[i] += 1
                        col_zero[0] += 1

                carry = old

            # recompute column 0 full status (safe)
            col_full = sum(1 for j in range(n) if col_zero[j] == 0)

        print(row_full + col_full)

if __name__ == "__main__":
    solve()
```このソリューションは行列を明示的に維持しますが、行と列のステータスを最初から再計算することを回避します。 セルが更新されるたびに、影響を受ける行カウンターと列カウンターのみが調整されます。 シフト操作の場合、最初の列に値を伝播し、途中でカウンターを更新します。 

微妙な点は、`col_full`簡単にするために、シフト演算で再計算されます。 これにより、複数の伝播が同じ列に影響を与える場合に列の状態が不一致になる可能性がある、微妙な増分バグが回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, q = map(int, input().split())
    g = [list(map(int, list(input().strip()))) for _ in range(n)]

    row_zero = [0]*n
    col_zero = [0]*n

    for i in range(n):
        for j in range(n):
            if g[i][j] == 0:
                row_zero[i] += 1
                col_zero[j] += 1

    row_full = sum(1 for x in row_zero if x == 0)
    col_full = sum(1 for x in col_zero if x == 0)

    out = []

    for _ in range(q):
        op = input().split()
        if op[0] == '1':
            i, j, b = map(int, op[1:])
            i -= 1; j -= 1

            if g[i][j] != b:
                if g[i][j] == 0:
                    row_zero[i] -= 1
                    col_zero[j] -= 1
                else:
                    row_zero[i] += 1
                    col_zero[j] += 1
                g[i][j] = b

            row_full = sum(1 for x in row_zero if x == 0)
            col_full = sum(1 for x in col_zero if x == 0)

        else:
            b = int(op[1])
            carry = b
            for i in range(n):
                old = g[i][0]
                g[i][0] = carry
                carry = old

            col_full = sum(1 for j in range(n) if col_zero[j] == 0)

        out.append(str(row_full + col_full))

    return "\n".join(out)

# custom sanity checks
assert run("2 1\n10\n11\n1 1 2 1\n") == "3"

 ## 特殊なケース

 重要なエッジケースは、行または列がカウントゼロで正確に遷移する場合です。 行に 0 が 1 つだけあり、更新によってその 0 が 1 に反転されるとします。 行は完全に 1 になるため、フローは 1 つ増加する必要があります。 アルゴリズムはデクリメントすることでこれを処理します。`row_zero[i]`そしてそれがゼロになるかどうかをチェックし、それによって増加がトリガーされます。`row_full`。 

もう 1 つのエッジ ケースは、同じ列が複数の伝播された値を受け取る場合のシフトの繰り返しです。 セルごとに伝播し、カウンターを即座に更新するため、各遷移がローカルに反映され、累積エラーが防止されます。
