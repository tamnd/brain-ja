 ## 問題の理解

 ノードがプール内の指定された点を表し、エッジがそれらの間の直接の水泳ルートを表す、有向重み付きグラフが与えられます。 各エッジには移動時間があります。 参加者はこれらのエッジに従ってパスに沿って移動しますが、追加のグローバル ルールがあります。参加者はノードに到着するたびに正確に待機する必要があります。`x`離脱が許可される数秒前に、最終ノードでこの待機コストも支払います。 

各クエリは開始ノード、終了ノード、および値を提供します。`x`。 その特定の`x`、始点から終点までの移動にかかる最短時間を計算する必要があります。ここで、パスのコストはエッジの重みの合計に重みを加えたものになります。`x`両方のエンドポイントを含む、訪問したすべてのノードに対して。 

主要な構造上の困難は、グラフが固定されているものの、ノードのコストがクエリに依存するため、最短パスをさまざまな値に対して評価する必要があることです。`x`効率的に。 

制約が示すのは、`n`は最大 500、エッジの数は最大`2n`, したがって、グラフは非常にまばらです。 ただし、クエリの数は最大 100,000 になる可能性があるため、クエリごとに最短パス アルゴリズムを実行することは直ちに不可能になります。 クエリごとのフロイド-ウォーシャルですら不可能です。`O(n^3 q)`。 

微妙なエッジ ケースは、自己クエリと切断されたペアから発生します。 もし`u == v`、答えはゼロではありませんが、それでもノードでの待ち時間が含まれるため、少なくとも次のようになります。`x`。 パスがない場合は出力する必要があります`-1`中間ノードは存在するが、有向意味で到達不可能な場合でも。 

もう 1 つの落とし穴は、中間ノードだけでなく、訪問したすべてのノードで待機が発生することを忘れていることです。 たとえば、パスが`u -> v`直接的に言えば、コストは`w(u,v) + 2x`、だけではありません`w + x`。 

## アプローチ

 ブルートフォースのアイデアは単純です。クエリごとに、開始ノードからダイクストラのアルゴリズムを実行します。エッジを横断するたびにその重みが追加され、ノードの待機コストも組み込まれます。 ただし、ノードの待機は訪問するノードの数に依存します。これは、標準の最短パス状態には、これまでに訪問したステップまたはノードの数を組み込む必要があることを示唆しています。 これにより、状態定義が拡張されます。`(node, k)`どこ`k`は訪問したノードの数であり、遷移は以下に依存します。`x`。 この定式化では、エッジ遷移ごとに距離とノード数の両方が増加し、コストは次のようになります。`distance + k * x`。 

このクエリごとの総当たりアプローチは、拡張された状態で完全なダイクストラを実行するか、クエリごとに変換されたグラフ内のすべてのペアの最短パスを再計算するため、コストがかかりすぎます。 最悪の場合、拡張状態のダイクストラはおよそ`O(n^2 log n)`密な状態空間内のクエリごとに、これは完全に実行不可能です。`q = 1e5`。 

重要な洞察は、構造を 2 つのコンポーネントに分離することです。1 つはグラフのみに依存するコンポーネント、もう 1 つはグラフに線形に依存するコンポーネントです。`x`。 パスを修正する場合、そのコストは次のように記述できます。`sum of edge weights + x * (number of nodes in path)`パス内のエッジの数を次のようにします。`k`の場合、ノード数は`k+1`したがって、コストは次のようになります。`edge_sum + x * (k+1) = (edge_sum + x) * k + x`これは、各エッジに応じて重みが変更されたものとして扱う必要があることを示唆しています。`x`、しかしより重要なのは、線形依存性を分離する形式ですべてのペアの最短経路を事前計算できることです。`x`。 

コストを次のように書き換えます。`edge_sum + x * nodes = edge_sum + x + x * edges = (edge_sum + x*edges) + x`したがって、各ペアについて`(u,v)`、エッジの数とエッジの重みの合計による最短経路を同時に知りたいと考えています。 これは、パス長に対する最小プラス畳み込みの古典的な設定であり、2 つの DP 層を維持することで処理できます。1 つは最小コストを追跡し、`k`エッジと別の集約エッジ数。 

以来`n ≤ 500`、2 つの行列を維持する修正された Floyd-Warshall を使用できます。`dist[i][j]`最小エッジ和と`cnt[i][j]`その合計構造を達成する最小数のエッジの場合。 次に、各クエリが関数を評価します。`ans(u,v,x) = dist[u][v] + x * (cnt[u][v] + 1)`重要な単純化は、最短パスの場合、次のことを最小限に抑えることです。`edge_sum`すべてのエッジが負ではない重みを持っているため、等しいエッジの合計の中で最小エッジ数は一貫しているため、それだけで十分です。 したがって、最短のパス和を求めて標準的なフロイド-ウォーシャルを実行することができ、また、等コスト パス間のエッジの最小数を維持することもできます。 

これにより、O(1) の各クエリに答える事前計算が生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリ最短パスごと) | O(q · n² log n) | O(n²) | 遅すぎる |
 | 最適 (エッジ トラッキングを備えたフロイド ウォーシャル) | O(n3 + q) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 距離行列を初期化する`dist`無限大とエッジ数行列を使用した場合`cnt`無限大を除く`dist[i][i] = 0`そして`cnt[i][i] = 0`。 これは、同じノードに留まるとエッジにコストがかからず、エッジが使用されないことを表します。 
2. すべての有向エッジについて`u -> v`重さで`w`、 セット`dist[u][v] = min(dist[u][v], w)`そして`cnt[u][v] = 1`。 これは、最良の直接接続が 1 つのエッジのみを使用することをエンコードします。 
3. 中間ノード上で Floyd-Warshall を実行する`k`、すべてのペアを更新します`(i, j)`ノードを使用しています`k`橋として。 トリプルごとに`(i, k, j)`を組み合わせて候補パスを計算します。`i -> k`そして`k -> j`。 
4. パスを結合する場合、合計エッジ重みとエッジ数を計算します。 新しいエッジの重みが現在の最良のものよりも小さい場合は、両方を交換します。`dist[i][j]`そして`cnt[i][j]`。 等しい場合は、小さい方のエッジ数を維持します。 
5. 前処理後、各クエリ`(u, v, x)`という公式を使って答えられます`dist[u][v] + x * (cnt[u][v] + 1)`、ノード数はエッジに 1 を加えた値に等しいためです。 
6. もし`dist[u][v]`まだ無限です、出力`-1`パスが存在しないからです。 

### なぜ効果があるのか

 からのすべての有効なパス`u`に`v`エッジのシーケンスに対応します。 このアルゴリズムにより、ノードのすべてのペアについて、可能な最小の総エッジ重みが保存され、それらの間でエッジの数を維持する一貫した代表的な構造が維持されます。 すべてのエッジの重みが負ではないため、Floyd-Warshall は最短パスの合計を正しく計算します。 待機コストは訪問ノードの数のみに依存します。これは、選択したパス内のエッジの数によって正確に決まります。 したがって、最適なエッジ重みパスが固定されると、クエリ コストは次の単純な一次関数になります。`x`事前に計算された定数に適用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    n, m, q = map(int, input().split())
    
    dist = [[INF] * (n + 1) for _ in range(n + 1)]
    cnt = [[INF] * (n + 1) for _ in range(n + 1)]
    
    for i in range(1, n + 1):
        dist[i][i] = 0
        cnt[i][i] = 0
    
    for _ in range(m):
        u, v, w = map(int, input().split())
        if w < dist[u][v]:
            dist[u][v] = w
            cnt[u][v] = 1
    
    for k in range(1, n + 1):
        for i in range(1, n + 1):
            if dist[i][k] == INF:
                continue
            for j in range(1, n + 1):
                if dist[k][j] == INF:
                    continue
                
                nd = dist[i][k] + dist[k][j]
                nc = cnt[i][k] + cnt[k][j]
                
                if nd < dist[i][j]:
                    dist[i][j] = nd
                    cnt[i][j] = nc
                elif nd == dist[i][j] and nc < cnt[i][j]:
                    cnt[i][j] = nc
    
    out = []
    for _ in range(q):
        u, v, x = map(int, input().split())
        if dist[u][v] == INF:
            out.append("-1")
        else:
            out.append(str(dist[u][v] + x * (cnt[u][v] + 1)))
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず 2 つの行列を構築します。1 つは最短経路の重み用で、もう 1 つはその最適な重みを達成するエッジの数を追跡するためのものです。 Floyd-Warshall は両方を一貫して更新し、すべてのペアに正規の最短パス表現が保存されるようにします。 次に、各クエリは、事前に計算されたエッジ数を使用して単純な線形式を評価します。 

よくある間違いは、クエリごとに最短パスを再計算しようとしたり、ノード訪問数とエッジ数の間の依存関係を無視したりすることです。 もう 1 つの微妙な点は、パスの重みが厳密に優れている場合、または同等に優れているがエッジ数が優れている場合にのみ、エッジ数が更新されるようにすることです。 

## 実用的な例

 3 つのノードとエッジを持つ小さなグラフを考えてみましょう。`1 -> 2 (2)`、`2 -> 3 (2)`、`1 -> 3 (10)`。 

クエリ`(1, 3, x)`。 

| ステップ | 距離[1][3] | cnt[1][3] | 選択したパス |
 | --- | --- | --- | --- |
 | 直接初期化 | 10 | 1 | 1→3 |
 | 経由 2 | 4 | 2 | 1→2→3 |
 | 最終 | 4 | 2 | 1→2→3 |

 のために`x = 0`、答えは`4`。 のために`x = 5`、答えは`4 + 5*3 = 19`。 

これは、アルゴリズムがより多くのエッジを使用する場合でも、エッジの重みがより小さいパスを正しく優先することを示しています。 

ここで、2 つのパスの重みが等しい場合を考えてみましょう。`1 -> 2 (1)`、`2 -> 3 (1)`、`1 -> 3 (2)`。 

| ステップ | 距離[1][3] | cnt[1][3] | 選択したパス |
 | --- | --- | --- | --- |
 | 直接初期化 | 2 | 1 | 1→3 |
 | 経由 2 | 2 | 2 | 1→2→3（タイブレーク） |
 | 最終 | 2 | 2 | 1→2→3 |

 ここで、両方のパスの合計重み 2 は等しいですが、アルゴリズムは重みが同点の場合にのみエッジの少ない方を選択します。 両方が有効であるため、エッジ数が小さい方を保持し、正しいノードコスト評価を保証します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(n3 + q) | n ≤ 500 にクエリごとに O(1) を加えたフロイド・ウォーシャル |
 | スペース | O(n²) | 距離とエッジ数の 2 つの n×n 行列 |

 三次前処理は受け入れられます。`n = 500`、約 1 億 2,500 万のトランジションが得られ、これはプルーニングを使用して最適化された Python の時間制限内に収まります。 クエリ処理は線形です`q`、これは必要なので、`q`大きくなる可能性があります。

 エッジケースの 1 つは次のような場合です`u == v`。 アルゴリズムが初期化されます`dist[i][i] = 0`そして`cnt[i][i] = 0`、したがって、答えは次のようになります`0 + x * (0 + 1) = x`、同じノードである開始点と終了点での待機を正しく考慮しています。 

もう 1 つのケースは、エッジの重みは等しいがエッジの数が異なる複数の最短パスが存在する場合です。 Floyd-Warshall のタイブレークにより、常に最小数のエッジを持つパスが選択されるようになります。これは、ノードのコストがエッジ数に依存するため、非常に重要です。 

最後に、切断されたペアは無限の距離に残り、正しく出力されます。`-1`式を適用しようとせずに、オーバーフローや無効な演算を防ぎます。
