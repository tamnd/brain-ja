 ## 解決策
 ## 問題の理解

 入力は、コンパクトな文法で記述された多項式を表す単一の文字列です。 標準の代数表記とは異なり、スペースはなく、構造は符号、数字、変数を使用してエンコードされます。`x`、およびオプションの指数マーカー`b`。 項は、単純な整定数、または整数係数の積、単一変数にすることができます。`x`、および正または負のオプションの指数。 目標は、この多項式の形式導関数を計算し、単純化して並べ替えた後、同じコンパクトな形式で再度出力することです。 

主な困難は微積分そのものではなく、文字列を正しく解釈することです。 多項式には、連鎖した加算と減算、オプションの係数、指数が欠落している場合の暗黙の指数 1、および負の指数を含めることができます。 微分後、結果のすべての項を等しい指数で結合し、指数の昇順で出力する必要があります。 

入力サイズは最大 100,000 文字であるため、部分文字列を繰り返し再スキャンしたり、素朴な方法で文字列連結を繰り返し使用したりするソリューションでは、速度が非常に遅くなります。 慎重な解析を伴うリニア スキャンが必要です。 すべての指数は絶対値で 100 によって制限されているため、無制限の増加を心配することなく、指数をキーとする配列または辞書に結果を安全に蓄積できます。 

記号と用語の境界を解析するときに、微妙な失敗モードが発生します。 ナイーブな分割`+`そして`-`次のような指数部分を分割します`b-10`、これは演算子ではなく構文の一部です。 もう 1 つのよくある間違いは、実際には指数 0 の定数項であるのに、独立した数値を指数または係数として誤解することです。 

2 番目のクラスのエラーは、指数の解釈から生じます。 例えば、`x`指数 1 を意味し、`4xb3`指数 3 を意味し、`5x`は指数 1 を意味しますが、`7`これらを誤って分類すると、誤った導関数シフトが発生します。 

3 番目の問題は、単項マイナスの処理です。 文字列は次で始まる場合があります`-term`または次のようなシーケンスが含まれています`...+ -term`スペースなしで。 符号の処理が正しくないと、項の係数が誤って反転またはマージされる可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、まず、繰り返しの部分文字列スキャンまたは正規表現のような分割を使用して文字列を完全にトークン化し、用語の明示的なリストを構築し、次に用語ごとに導関数を計算し、最後に結果を並べ替えてマージします。 概念的には単純ですが、用語境界ごとに単純な部分文字列を抽出すると、同じ文字を繰り返しスキャンすることになります。 最悪の場合、各文字が何度も再表示される可能性があり、100,000 文字の入力で二次的な動作が発生する可能性があり、1 秒の制限の下では遅すぎます。 

重要な観察は、多項式文法が線形であり、単一パスで解析できることです。 各項の境界が正しく検出されると、各項は局所的に自己完結し、各項の導関数は解析された係数と指数にのみ依存します。 これにより、文字列を 1 回スキャンし、項を増分的に抽出し、寄与を即座に計算し、指数によってインデックス付けされた固定サイズの構造に結果を蓄積することができます。 

解析後の微分は純粋に算術的です。 各学期`a * x^k`貢献する`a*k * x^(k-1)`、定数は消えます。 指数は狭い範囲に制限されているため、更新ごとの集計は O(1) です。

 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 文字列を左から右にスキャンし、用語の境界を特定します

 ポインタを保持して解釈します`+`そして`-`用語の最上位に出現する場合にのみ区切り文字として使用され、次のような指数部分内では使用されません。`b-10`。 これには治療が必要です`b`特別なマーカーとして: 指数内にある場合、数字と先頭にあるマイナス記号はその指数に属し、項を分割すべきではありません。 

### 2. 各生の用語部分文字列を抽出します

 境界を検出するたびに、1 つの項を表す部分文字列をスライスします。 この部分文字列は常に定数または構造化された文字列のいずれかをエンコードします。`coefficient x exponent`形状。 

これが機能する理由は、文法によってすべての用語が構文的に完全であることが保証され、境界が正しく識別されると周囲のコンテキストに依存しないためです。 

### 3. 係数、変数の存在、および指数を解析します。 

この用語を 3 つの部分に分けて解釈します。 ない場合`x`、項は指数 0 の定数です。`x`が存在し、明示的な係数がない場合、係数は 1 です。後ろに指数がない場合は、`x`、指数は 1 です。指数が存在する場合、それは正または負の可能性があり、次の後に解析する必要があります。`b`マーカー。 

このステップでは、文字列表現を数値ペアに変換します。`(coef, exp)`。 

### 4. 派生ルールをローカルに適用する

 解析された用語ごとに`(a, k)`、 もし`k == 0`導関数はゼロであり、何も寄与しません。 それ以外の場合、導関数が寄与します`(a * k, k - 1)`。 

これが必要な唯一の微積分演算であり、用語ごとに独立して適用されます。 

### 5. 指数による結果の累積

 結果は、指数をキーとした辞書または固定配列に保存されます。 複数の項が同じ指数を生成する場合、それらの係数は直ちに合計されます。 

出力では印刷前に同様の用語を組み合わせる必要があるため、これは非常に重要です。 

### 6. 指数の昇順で出力します。 

最後に、最小値から最大値まで指数を繰り返し、ゼロ以外の係数を必要な形式で出力します。 各項は、定数、線形、一般のいずれかに応じて出力されます。`x`同じエンコード規則に逆に従います。 

### なぜ効果があるのか

 このアルゴリズムは、構文項と代数項の間の 1 対 1 のマッピングを保持します。 すべての有効な部分文字列は 1 つの多項式項に正確に対応し、微分は項ごとに 1 回だけ適用されます。 集計は整数係数に対して可換かつ結合的であるため、局所微分の後に項を結合すると、完全な式の記号微分と同じ結果が生成されます。 解析により、用語が間違って分割されないことが保証されるため、寄与が失われたり重複したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def parse_terms(s):
    terms = []
    n = len(s)
    i = 0

    def read_number(i):
        sign = 1
        if i < n and s[i] == '-':
            sign = -1
            i += 1
        val = 0
        while i < n and s[i].isdigit():
            val = val * 10 + (ord(s[i]) - 48)
            i += 1
        return sign * val, i

    while i < n:
        if s[i] in '+-':
            if i == 0:
                sign = -1 if s[i] == '-' else 1
                i += 1
            else:
                sign = 1
                if s[i] == '-':
                    sign = -1
                i += 1
        else:
            sign = 1

        coef = None
        has_x = False
        exp = None

        if i < n and s[i].isdigit():
            j = i
            while j < n and s[j].isdigit():
                j += 1
            coef = int(s[i:j])
            i = j
        else:
            coef = 1

        coef *= sign

        if i < n and s[i] == 'x':
            has_x = True
            i += 1

            if i < n and s[i] == 'b':
                i += 1
                start = i
                if i < n and s[i] == '-':
                    i += 1
                while i < n and s[i].isdigit():
                    i += 1
                exp = int(s[start:i])
            else:
                exp = 1
        else:
            exp = 0

        terms.append((coef, exp))

    return terms

def solve():
    s = input().strip()
    terms = parse_terms(s)

    OFFSET = 200
    poly = [0] * 405

    for c, e in terms:
        if e == 0:
            continue
        poly[e - 1 + OFFSET] += c * e

    out = []
    for idx in range(len(poly)):
        coef = poly[idx]
        if coef == 0:
            continue
        exp = idx - OFFSET
        if exp == 0:
            out.append(str(coef))
        elif exp == 1:
            if coef == 1:
                out.append("x")
            elif coef == -1:
                out.append("-x")
            else:
                out.append(f"{coef}x")
        else:
            if coef == 1:
                out.append(f"xb{exp}")
            elif coef == -1:
                out.append(f"-xb{exp}")
            else:
                out.append(f"{coef}xb{exp}")

    print("".join(out))

if __name__ == "__main__":
    solve()
```解析関数は文字列を 1 回調べて、次のリストを作成します。`(coefficient, exponent)`ペア。 次に、メイン ソルバーは導関数ルールを直接適用し、指数をマイナス 1 だけシフトし、係数に元の指数を乗算します。 

固定サイズの配列`poly`は、シフト後の指数範囲が元の制約である ±100 の周囲に制限されたままであるため、辞書の代わりに使用されます。 オフセットにより、負の指数を安全に処理できるようになります。 

出力の構造は、指数 0 と 1 の特殊なケースを含む、必要なエンコード規則に従います。

 ## 特殊なケース

 重要なエッジケースは、次のような単一の定数項です。`7`。 パーサーはそれを指数 0 として分類し、微分によって直ちにそれを破棄し、出力形式でゼロとして解釈される空の結果を生成します。 

もう 1 つのエッジ ケースは、次のような純粋な線形項です。`x`。 これは係数 1 と指数 1 として解析されます。微分後は定数 1 になり、何も指定せずに出力する必要があります。`x`または指数マーカー。 

次のような負の指数の場合`3xb-2`用語を生成する`(3,-2)`。 導関数は次のようになります`-6xb-3`指数シフトは純粋に算術演算であり、符号や書式設定に依存しないため、アルゴリズムはこれを正しく処理します。 

最後に、次のような混合チェーン`x-x+x-x`正しい符号解析をテストします。 各用語は以下を交互に行います。`1x`そして`-1x`、そして集計はすべてをゼロに正しくキャンセルし、出力項を残しません。
