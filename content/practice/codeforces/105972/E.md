 ## 解決策
 ## 問題の理解

 整数の配列が与えられているので、非常に具体的な成長ベースの制約の下で「良好」なサブセグメントがいくつあるかを数える必要があります。 

サブセグメント$[l, r]$長さ 1 から全長まで、このセグメント内のすべての位置を、特別な形式で表現できるセグメントの値と一致させることができれば、これは良好であると考えられます。 具体的には、指数ごとに$i = 1, 2, \ldots, (r - l + 1)$に等しい要素がセグメント内に少なくとも 1 つ存在する必要があります。$x^i$ある整数に対して$x$。 重要な点は、各指数について$i$、ベース$x$は独立して変化することが許可されているため、単一の等比数列を探しているのではなく、少なくとも 1 つの完全な数列の存在を探しています。$i$すべてのセグメントの - 乗$i$。 

したがって、条件はインデックス全体の構造を要求しません。 セグメントの長さに等しい指数まで、セグメントに完全な正方形である数値が少なくとも 1 つ、完全な立方体である数値が少なくとも 1 つ含まれているかどうかが尋ねられます。 

再構成された、長さのセグメント$k$すべての指数について良い$i$から$1$に$k$、セグメントには完全な値が少なくとも 1 つ含まれています。$i$整数の - 乗。 

入力は最大で 1 つの配列です。$10^5$要素、それぞれ最大$10^9$。 出力は、このプロパティを満たすサブ配列の数です。 

制約$n \le 10^5$すべてを検査するアプローチを除外します$O(n^2)$それぞれの内部で指数チェックを再計算するサブ配列。 ナイーブでも$O(n^2 \sqrt{\max a_i})$または$O(n^2 \log a_i)$解決策は遅すぎるでしょう。 

微妙な難しさは、セグメントが適切であるかどうかのチェックが、順序や合計ではなく、セグメント内の数論的プロパティの分布に依存することです。 これにより、プレフィックス集約が重要になります。 

いくつかの特殊なケースが直接的に重要になります。 

指数が大きいため、単一要素セグメントは常に適切です。$i = 1$次の数値が存在することだけが必要です$x^1$、これは常に真実です。 たとえば、入力$[7]$答えが得られます$1$。 

長さ 2 のセグメントには、少なくとも 1 つの完全な正方形と少なくとも 1 つの完全な線形値が必要です (これはどの整数にも常に当てはまります)。 したがって、実際の制約は指数から重要になり始めます$2$上向きに。 

指数を超える非完全べき乗のみを含むセグメント$1$、 例えば$[2, 3, 5]$、長さの点で失敗します$3$セグメントには立方体がないため、指数$3$すでに不可能です。 

## アプローチ

 ブルートフォース手法では、すべてのサブ配列を列挙し、それぞれの長さを計算します。$k$、各指数を確認します$i \le k$部分配列内の要素が完全であるかどうか$i$-乗。 これには、重複するセグメントにわたって電力チェックを繰り返し再計算する必要があります。 

各サブ配列について、その要素をスキャンするのは次のとおりです。$O(n)$、次の値までのすべての指数をチェックします。$k$別の要素が加わります。 これは次のことにつながります$O(n^3)$最悪の場合、明らかに遅すぎます。$n = 10^5$。 

事前計算したとしても、すべての要素について$a_j$、すべての指数$i$それが完璧であるように$i$の乗であっても、指数範囲をカバーするために部分配列を効率的にクエリする方法がまだ必要です。 中心的な観察は、それぞれの数値が少数の指数セットにのみ寄与しているということです。$a_i \le 10^9$、完全な累乗となり得る最大指数は急速に縮小します。 たとえば、完全な 10 乗となる数はほとんどなく、20 乗となる数はさらに少ないなどです。 

これは視点を反転することを示唆しています。部分配列を指数に対してチェックする代わりに、有効な値が存在する位置を指数ごとに追跡します。 次に、問題はセグメント内のすべての指数層をカバーすることになります。これは、ある指数レベルを欠落する前にセグメントをどこまで拡張できるかという制約に帰着できます。 

重要な洞察は、答えは各指数レベルが配列全体でどの程度「サポート」されるかによって決まるということです。 指数ごとに事前計算できます$i$、$i$-乗が発生します。 次に、任意の開始インデックスについて、特定の範囲までのすべての指数に対して少なくとも 1 つの有効な値を含む最も右のエンドポイントを決定できます。 これは当然、2 ポインタまたは右展開のアプローチにつながります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | 事前計算 + 2 つのポインター |$O(n \log A)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての要素、すべての指数について事前計算します。$i$それが完璧であるように$i$-乗。 これは、指数の限界まで整数の根を繰り返し求めることによって行われます。$2^i \le 10^9$。 結果は指数からのマッピングです$i$有効な値が存在する位置に移動します。 
2. 指数ごとに$i$、配列に含まれるインデックスのソートされたリストを作成します。$i$-乗。 これにより、定期的にカバレッジをすばやく確認できます。 
3. 開始位置が固定の場合$l$、私たちは最小のものを望んでいます$r$からのすべての指数が$1$に$k = r-l+1$内部でサポートされています$[l, r]$。 これは、指数ごとにチェックすることになります。$i$、次に発生するかどうか$i$-乗以降$l$セグメント内にあります。 
4. ポインタを維持する$r$それは前に進むだけです。 それぞれについて$l$、段階的に拡張します$r$現在のセグメント長までの必要な指数層がすべて満たされるまで。 必要な指数が範囲内にない場合、セグメントをさらに拡張することはできません。 
5. から始まるすべての有効なセグメントをカウントします。$l$有効なエンドポイントの数を追加します。 

明らかではない部分は、$l$要件を減らすだけなので、ポインタは$r$決して後退する必要はありません。 これによりリニアスキャンが可能になります。 

### なぜ効果があるのか

 どのセグメントについても、有効性は各指数レベルの中に少なくとも 1 つの代表があるかどうかによってのみ決まります。 これはセグメントの拡張に関して単調な特性です。要素の追加は、不足している指数レベルを満たす機会を増やすだけであり、要素を削除することはできません。 したがって、セグメントが一定期間有効になると、$r$、延長$r$有効性を維持し、同様に縮小します$l$条件を厳しくすることしかできません。 この単調性により、状態を再訪することなく 2 ポインターのトラバースが可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_kth_power(x, k):
    if k == 1:
        return True
    lo, hi = 1, int(x ** (1 / k)) + 2
    while lo <= hi:
        mid = (lo + hi) // 2
        val = mid ** k
        if val == x:
            return True
        if val < x:
            lo = mid + 1
        else:
            hi = mid - 1
    return False

def factor_exponents(x):
    res = []
    for k in range(1, 32):
        if (1 << k) > x and k > 1:
            break
        if is_kth_power(x, k):
            res.append(k)
    return res

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = {}
    max_k = 30

    for i, v in enumerate(a):
        for k in range(1, max_k + 1):
            if k == 1:
                pos.setdefault(k, []).append(i)
            else:
                if is_kth_power(v, k):
                    pos.setdefault(k, []).append(i)

    for k in pos:
        pos[k].sort()

    def has_k(k, l, r):
        if k not in pos:
            return False
        arr = pos[k]
        # binary search for any index in [l, r]
        lo, hi = 0, len(arr) - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if arr[mid] < l:
                lo = mid + 1
            else:
                hi = mid - 1
        return lo < len(arr) and arr[lo] <= r

    ans = 0
    r = 0

    for l in range(n):
        r = max(r, l)
        k = 1
        while True:
            ok = True
            for i in range(1, k + 1):
                if not has_k(i, l, r):
                    ok = False
                    break
            if ok:
                k += 1
            else:
                break

        ans += (k - 1)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、要素が完全累乗として動作するすべての指数レベルを列挙することに依存しています。 指数ごとに、ソートされた位置を保存し、二分探索を使用して、セグメントに少なくとも 1 つの有効な要素が含まれているかどうかを確認します。 

外側のループは左側のエンドポイントを固定します。 内部拡張では、達成可能な最大長を増やそうとします。$k$これは、指数カバレッジを段階的にチェックすることに対応します。 内部の二分探索`has_k`これにより、カバレッジを効率的にテストできるようになります。 

微妙な点は、$r$。 より最適化されたソリューションでは、$r$の反復間で共有されます$l$ですが、ここでは単調展開を介して概念的に効果的に再計算されます。
