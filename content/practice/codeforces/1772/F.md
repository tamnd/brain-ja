 ## 解決策
 ## 問題の理解

 私たちは一連の白黒写真を与えられ、それぞれが$n \times m$0 と 1 の行列。 これらの画像の 1 つはオリジナルであり、他の画像は一連の 2 つの可能な操作 (反対色のセルで完全に囲まれたセルを反転する、または現在の画像のコピーを作成する) の後に得られたコピーです。 写真は任意の順序で表示されます。 私たちの仕事は、妥当な操作シーケンスを再構築し、最初の画像を特定し、操作に従ってコピーにラベルを付けることです。 

制約は小さいです。$n$そして$m$多くても30歳であり、$k$コピー数は最大でも 100 です。つまり、すべてのセルを繰り返し反復するブルートフォース アプローチは実行可能ですが、回避する必要があります。$O((nm)^2)$不要な場合は写真ごとにさらに悪いことになります。 小さなボードを使用すると、画像を文字列または整数のタプルとして効率的に表現して、高速に比較することもできます。 エッジ ケースには、色変更が不可能なボード、すべてのコピーが同一であるボード、または複数の操作で同じ画像が得られるボードが含まれます。 各反転後にコピーが 1 つだけ存在すると仮定する単純なアプローチでは、最初の画像に簡単に誤ったラベルが付けられる可能性があります。 

## アプローチ

 ブルートフォース手法では、すべての画像を初期状態として試し、考えられるすべての再着色シーケンスをシミュレートし、残りの画像がコピー操作で一致するかどうかを確認します。 正しいのですが、これは組み合わせ的に爆発します。内部の各セルは反転することも反転しないこともでき、次のような結果が得られます。$2^{(n-2)(m-2)}$可能性。 最大 28×28 の内部セルがあるため、これは大きすぎます。 

重要な洞察は、再着色操作を逆に識別できるということです。 反転は、隣接する 4 つのセルが反対の色である内部セルでのみ発生します。 したがって、2 つの画像間の違いを調べる場合、後の画像で、異なるが 4 つの反対側の隣接セルに囲まれているセルは、最後に反転されている必要があります。 この推論を使用すると、シーケンスを逆方向に再構築できます。つまり、最後のステップで反転された可能性のあるすべてのセルを見つけて、それらを反転し、続行します。 コピーは現在の状態と正確に一致する画像として認識されるため、コピー操作は現在のボードのスナップショットにすぎません。 

プロセスを逆にすることで、考えられるすべての順方向シーケンスのシミュレーションを回避し、代わりに操作を決定論的に識別します。 この問題は、指定された一連の画像が有効な一連の操作から得られることを保証するため、機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^{(n-2)(m-2)} * k) | O(nm) | 遅すぎる |
 | 逆再構築 | O(k * nm) | O(k * nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての画像をメモリに読み取り、元の入力インデックスを追跡します。 比較を容易にするために、各画像を文字列のタプルとして表します。 
2. 消去法によって最初の画像を特定します。 別の画像から 1 回の反転によって取得できなかった画像が候補となります。 実際には、任意の画像から開始して逆方向に再構築します。 すべての逆の操作を適用した後に残ったものが最初のものです。 
3. 操作の空のリストを初期化します。 
4. まだコピーとして割り当てられていない画像がある間に、現在の画像のすべての内部セルを反復処理します。 セルが残りのピクチャ内の対応するセルと異なり、後のピクチャ内の 4 つの隣接セルすべてが反対の色である場合、そのセルを反転としてマークします。 反転を適用して反転します。 
5. 残りの画像が現在の画像と正確に一致するたびに、コピー操作を記録し、その画像を未割り当てセットから削除します。 
6. すべての画像が一致するまで手順 4 ～ 5 を繰り返します。 操作リストを逆にして、最初から最後までのシーケンスを生成します。 
7. 最初のピクチャのインデックス、その後に操作の数、その後に操作を順番に出力します。 

これが機能する理由: 隣接するものを検査すると、各反転は元に戻すことができ、コピーは完全に一致します。 逆方向に処理し、近傍プロパティを使用することにより、1 つの有効な操作シーケンスを決定論的に復元します。 不変条件は、各ステップで、有効な操作シーケンスによって残りのすべてのピクチャが現在のボードから生成できることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def read_picture(n):
    pic = []
    for _ in range(n):
        line = input().strip()
        pic.append(line)
    return tuple(pic)

def inside(i, j, n, m):
    return 0 < i < n-1 and 0 < j < m-1

def neighbors_opposite(pic, i, j):
    c = pic[i][j]
    return (pic[i-1][j] != c and pic[i+1][j] != c and
            pic[i][j-1] != c and pic[i][j+1] != c)

def solve():
    n, m, k = map(int, input().split())
    pictures = []
    for _ in range(k+1):
        input()  # empty line
        pictures.append(read_picture(n))
    
    unassigned = set(range(k+1))
    curr = list(pictures[0])
    ops = []
    copies = {}
    
    while unassigned:
        changed = False
        for idx in list(unassigned):
            pic = pictures[idx]
            flips = []
            for i in range(1, n-1):
                for j in range(1, m-1):
                    if curr[i][j] != pic[i][j]:
                        if neighbors_opposite(pic, i, j):
                            flips.append((i, j))
            if flips:
                for i,j in flips:
                    row = list(curr[i])
                    row[j] = '0' if curr[i][j]=='1' else '1'
                    curr[i] = ''.join(row)
                    ops.append(f"1 {i+1} {j+1}")
                changed = True
            if tuple(curr) == pic:
                copies[idx] = len(ops)+1
                ops.append(f"2 {idx+1}")
                unassigned.remove(idx)
                changed = True
        if not changed:
            # no flips detected; assign first unassigned as initial
            initial = unassigned.pop()
            break
    else:
        initial = 0

    print(initial+1)
    print(len(ops))
    for op in ops:
        print(op)

if __name__ == "__main__":
    solve()
```このソリューションは、画像を読み取り、インデックスを追跡し、割り当てられていない各画像と一致するように反転を繰り返し適用します。 各反転は、4 つの近傍が反対である場合にのみ適用され、正確さが保証されます。 現在のピクチャが残りの未割り当てのピクチャと一致するたびに、コピー操作が記録されます。 反転が必要ない場合、アルゴリズムは自然に消去によって初期画像を復元します。
