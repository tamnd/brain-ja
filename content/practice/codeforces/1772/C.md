 ## 問題の理解

 厳密に増加する長さのシーケンスを構築するように求められます$k$、すべての要素が間にあります$1$そして$n$。 このようなすべてのシーケンスの中で、値自体を最大化しているのではなく、連続した差に基づいて派生した量を最大化しています。 

有効なシーケンスの場合$a$、によって形成される差分配列を計算します。$a_2-a_1, a_3-a_2, \dots, a_k-a_{k-1}$。 シーケンスのスコアは、この差分配列に現れる個別の値の数です。 タスクは、このスコアを最大化する有効な増加シーケンスを構築することです。 

重要な制約は、$k$そして$n$両方とも最大 40 であり、このことから、ソリューションに重いアルゴリズム機構が必要ないことがすぐにわかります。 どれでも$O(k^2)$または、テスト ケースは最大 819 個あるため、テスト ケースごとに穏やかな建設的な推論さえあれば十分です。 

素朴なアプローチでは、増加するシーケンスをすべて列挙してスコアを計算しようとするかもしれませんが、$n = 40$、組み合わせの数$\binom{40}{k}$巨大化する。 中程度の場合でも$k$、これは実現可能性をはるかに超えて爆発します。 

より微妙な障害モードは、早期にギャップを最大化しようとする貪欲な構造から発生します。 たとえば、差異の多様性を高めるために、可能な限り最大の次の要素を常に選択しようとする場合があります。 これは、後で柔軟性を低下させ、多くの場合、残りのすべての違いを繰り返し大小のギャップに折りたたんで、区別性を高めるのではなく低下させるため、逆効果になる可能性があります。 

もう 1 つのよくある間違いは、明確な差異の数を最大化するには差異の大きさを最大化する必要があると仮定することです。 それは真実ではありません。 区別性はサイズではなく、平等構造のみに依存します。

 ## アルゴリズムのチュートリアル

 ギャップの増加を制御するという考えに基づいて、配列を逆方向に構築します。 

1. 空のリストから開始し、現在の値を 1 に設定します。これにより、範囲内にとどまることが保証され、推論が簡素化されます。 
2. 1 から順に差分を決定します。 ステップで$i$、違いを使用しようとします$i$。 これにより、それぞれが厳密に増加するため、選択されたすべての差異が本質的に区別されることが保証されます。 
3. 選択したそれぞれの違いの後、新しい値を最後の値に追加して配列に追加します。 すべての差が正であるため、これにより厳密な増加が自動的に維持されます。 
4. 次の値を追加すると次の値を超えたら、差の増加を停止します。$n$。 その時点で、上限に違反せずにギャップを拡大し続けることはできません。 
5.まだ制作していない場合$k$要素の場合、最後の値から 1 の定数ステップを追加して残りのスロットを埋めます。 制約の下で可能な限り個別の大きな差をすでに最大化しているため、最適性に影響を与える重複した差は導入されません。 

本質的な考え方は、差異をできるだけ長く増やすことで、すべての差異が明確になることを保証するということです。 唯一の制限は、次によって課される合計制約です。$n$、場合によっては早期の終了を余儀なくされます。 

### なぜ効果があるのか

 この構造では、差分配列が厳密に増加する正の整数のシーケンスで始まることが保証されるため、すべてのプレフィックスの差分は一意になります。 境界に違反せずに次の差を増やすことができなくなると、$n$、いかなる継続も、実現可能性を損なうことなく、新たな明確な違いを導入することはできません。 したがって、明確な差分のプレフィックスを最大化することが最適であり、残りのステップでは、総和によって制限される達成可能な最大値を超えてスコアを改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        k, n = map(int, input().split())

        a = [1]
        cur = 1
        d = 1

        while len(a) < k:
            if cur + d <= n:
                cur += d
                a.append(cur)
                d += 1
            else:
                break

        while len(a) < k:
            cur += 1
            a.append(cur)

        print(*a)

if __name__ == "__main__":
    solve()

微妙な点は、確認する必要があるということです`cur + d <= n`ジャンプを適用する前に。 これにより、許容範囲のオーバーシュートが防止され、すべての値が有効なままになります。 2 番目のループは、最悪の場合でも到達するまで 1 を繰り返し加算するため、終了することが保証されています。$k$要素。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        k, n = map(int, input().split())
        a = [1]
        cur = 1
        d = 1
        while len(a) < k:
            if cur + d <= n:
                cur += d
                a.append(cur)
                d += 1
            else:
                break
        while len(a) < k:
            cur += 1
            a.append(cur)
        out.append(" ".join(map(str, a)))
    return "\n".join(out)

 ## 特殊なケース

 いつ$k = n$、唯一の有効なシーケンスは$1,2,\dots,n$。 アルゴリズムは、より大きなジャンプが不可能になるたびに 1 を加算し続けるため、自然にこれを生成します。 

いつ$n$急激に増加する差に比べて小さい場合、貪欲な増加はほぼ即座に停止します。 その場合、シーケンスは単純な連続チェーンとなり、依然として制約を満たし、厳しい境界の下で達成可能な明確な差異を最大化します。
