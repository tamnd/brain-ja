 ## 解決策
 ## 問題の理解

 フェリックスは、選択した辺の長さのべき乗に対応するサイズのチョコレートの超立方体を受け取ります`w`。 利用可能なピースには重みがあります。`1, w, w², w³, ..., w¹⁰⁰`。 

パッケージごとの重量`x`、フェリックスがこれらのハイパーキューブの一部を天秤秤のどちらかの側に配置して、パッケージが片側にある状態で 2 つの辺が等しくなるようにできるかどうかを判断する必要があります。 

チョコレート片をパッケージと同じ側に置くと、パッケージの有効重量からその価値が減算され、反対側に置くとその価値が追加されます。 利用可能なハイパーキューブはすべて最大 1 回使用できるため、問題は次のとおりです。`x`の累乗の和として書くことができます`w`ここで、すべての係数は次のいずれかになります。`-1, 0, 1`。 

入力には最大 20 個のパッケージ重量が含まれます。それぞれ最大で`10^9`。 可能な累乗数は 101 あるため、サブセットを直接検索することは不可能です。`w`、探索できるよりもはるかに多くの組み合わせが得られます。 有用な権力に限定したとしても、依然として指数関数的な検索スペースが残るため、解決策は権力の構造を利用する必要があります。 

重要な特性は、`w`位置番号体系を形成します。 ピースをグローバルに選択する代わりに、最小パワーから順に各パワーの係数を決定できます。 係数が`w^i`が固定されている場合、残りの値は次の値で割り切れる必要があります。`w^(i+1)`これにより、問題を一度に 1 桁ずつ減らすことができます。 

扱いにくいケースは、表現可能に近い値に見えても無効な数字が必要な場合に発生します。 たとえば、`w = 5`、値`2`作成できません:```
1
5
25
```この範囲に近い符号付きの組み合わせは次のとおりです。`-5, -4, -1, 0, 1, 4, 5`、したがって、答えは次のとおりです`NO`。 通常の 5 進数の数字だけをチェックする単純なアプローチでは、すべての数字が調整可能であると誤って想定する可能性があります。 

もう 1 つの特殊なケースは、剰余が次の場合です。`w - 1`。 たとえば、`w = 5`そして`x = 4`、正しい表現は次のとおりです。`5 - 1 = 4`。 

最初の桁は実際には`-1`、 ない`4`。 数字のみを許可するアプローチ`0`を通して`w-1`ここで失敗します。 

小さな例:```
Input
1 5
4

Output
YES
```パッケージは、`5`片面には立方体、もう片面には単一の立方体。 

## アプローチ

 ブルートフォースアプローチは、利用可能なハイパーキューブの可能な割り当てをすべて試みることです。 各電源には、未使用、パッケージと一緒に置かれている、またはパッケージに接して置かれているという 3 つの状態があります。 101 乗すべてを考慮すると、次のようになります。`3^101`その可能性は天文学的に大きい。 までしかパワーアップしていないにもかかわらず、`10^9`数値的には重要ですが、検索スペースは依然として指数関数的であり、機能しません。 

有益な観察は、これがまさにバランスの取れた位置表現の問題であるということです。 通常の基地では、`w`表現では、すべての数字が次の範囲内にある必要があります`0`そして`w-1`。 ここで、すべての数字は次のようになります。`-1`、`0`、 または`1`。 現在の剰余モジュロを検査するだけで済みます。`w`。 

現在の値が`x`。 の係数`1`-power は、で割ったときの余りを決定します。`w`。 もし`x % w`がゼロの場合、現在の桁はゼロである必要があります。 余りが 1 の場合は、正の値を使用します。 残りが`w-1`、1 を減算すると値が次で割り切れるため、負の値を使用します。`w`。 

その数字を削除した後、次の値で割ります。`w`次のパワーでも同じ問題を解決します。 で表せない余りが出た場合`-1`、`0`、 または`1`、答えは不可能です。 

ブルート フォースは有効な配置をすべて試行するため機能しますが、位置構造を無視するため失敗します。 すべての決定は割り算によって強制されるため、貪欲な桁ごとのプロセスは成功します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^101) | お(101) | 遅すぎる |
 | 最適 | クエリごとに O(100) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各パッケージの重量を読み取り、その重量を で割ったときの余りを繰り返し調べます。`w`。 最低のパワー`w^0`剰余モジュロに影響を与える唯一のべき乗です`w`, したがって、最初に決定する必要があります。 
2. 余りがゼロの場合、係数を割り当てます`0`現在のパワーに。 現在の値は既に次の値で割り切れます。`w`なので、このサイズの立方体は必要ありません。 
3. 余りが 1 の場合、係数を割り当てる`1`。 現在のサイズの立方体を 1 つ取得すると、余分な残りが削除されます。 
4. 余りがあれば`w - 1`、係数を割り当てる`-1`。 これは、次の数字に 1 を加算するのと同じです。`-1 ≡ w-1 (mod w)`、残りの値は次で割り切れます。`w`。 
5. 余りがそれ以外の場合、現在の電力に対する有効な係数は存在しないため、答えは次のようになります。`NO`。 
6. 残りの値を次の値で割ります。`w`そして次の力を続けます。 値がゼロになるとプロセスは停止します。 

なぜ効果があるのか:

 すべてのステップで、現在の値は次のように表す必要があります。`current = digit + w * remaining`どこ`digit`の 1 つです`-1`、`0`、 または`1`。 選択された数字は、`current - digit`で割り切れる`w`。 それを削除した後、残りの問題は同じですが、1 乗高くなります。 すべての桁の決定は元のバランス問題との等価性を維持するため、ゼロに達することは有効な配置が見つかったことを意味しますが、不可能な剰余に遭遇すると配置が存在しないことが証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(x, w):
    while x > 0:
        r = x % w

        if r == 0:
            digit = 0
        elif r == 1:
            digit = 1
        elif r == w - 1:
            digit = -1
        else:
            return False

        x = (x - digit) // w

    return True

def solve():
    n, w = map(int, input().split())

    ans = []
    for _ in range(n):
        x = int(input())
        ans.append("YES" if possible(x, w) else "NO")

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`possible`関数はバランスベース変換を実行します。 変数`x`は常に、パッケージの重量のうち、より小さな電力でまだ処理されていない部分を表します。 

剰余チェックは実装の中核です。 3 つの有効なケースは、現在の電力の 3 つの可能な係数に正確に対応します。 ライン`x = (x - digit) // w`まず選択した係数を削除し、次に次のべき乗に進みます。 

次のパワーを明示的に生成する必要はありません。`w`。 分割を繰り返すと自然と同じ位置を歩きます。 すべての入力は最大なので、`10^9`、必要な反復は 100 回未満です。

## テストケース```python
import sys
import io

def possible(x, w):
    while x > 0:
        r = x % w
        if r == 0:
            digit = 0
        elif r == 1:
            digit = 1
        elif r == w - 1:
            digit = -1
        else:
            return False
        x = (x - digit) // w
    return True

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, w = map(int, sys.stdin.readline().split())
    res = []
    for _ in range(n):
        x = int(sys.stdin.readline())
        res.append("YES" if possible(x, w) else "NO")
    return "\n".join(res)

assert run("""4 5

26
29
32
""") == """YES

YES
NO""", "sample 1"

assert run("""3 3
1
2

""") == """YES

YES""", "balanced ternary"

assert run("""1 5
2
""") == "NO", "invalid remainder"

assert run("""1 2
1000000000
""") == "YES", "large binary case"

1

""") == """YES

YES""", "decimal balanced representation"

 ## 特殊なケース

 どちらでもないとき`0`、`1`、 または`w-1`の場合、アルゴリズムはその値を即座に拒否します。 例えば：```
Input
1 5
2
```最初の残りは`2`。 現在の数字は次のようにする必要があります`2`、ただし、単一のキューブのみが貢献できます`-1`、`0`、 または`1`この位置で。 アルゴリズムは戻ります`NO`。 

残りが`w-1`、解には負の数字を使用する必要があります。 例えば：```
Input
1 5
4
```最初の残りは`4`なので、数字を選択します`-1`:`4 - (-1) = 5`で割った後`5`、残りの値は`1`、数字を選択することで処理されます`1`。 その表現は、`5 - 1`、したがって、答えは次のとおりです`YES`。 

最大値も安全です。 例えば：```
Input
1 2
1000000000
```このアルゴリズムはバイナリ リダクションのみを実行します。 利用可能な 100 乗をはるかに下回る約 30 回の反復後に終了し、符号付き表現が存在するかどうかを正確に判断します。
