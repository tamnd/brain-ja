 ## 解決策
 ## 問題の理解

 フランシーヌは 10 進数のコレクションを持っており、それらのいくつかを可能な限り最大の不気味な数字にアレンジしたいと考えています。 不気味な数字は、2、3、5 で割り切れる非負の整数です。つまり、30 で割り切れる必要があります。数字を破棄することはできますが、残りの数字は選択した数字に 1 回だけ使用する必要があり、結果の数字には不要な先頭のゼロを含めることはできません。 タスクは、形成可能な最大の有効な数値を出力することです。または、`-1`有効な番号が存在しない場合。 

割り算ルールは、アルゴリズムに対する主な制約です。 30 で割り切れる数は、3 で割り切れて、最後の桁が 0 であることと同じです。`100000`数字は通常の整数演算では処理できないため、多くの可能な数値を構築してテストしようとするアプローチは不可能です。 ほんの一部の順列を生成するだけでも、利用可能な時間をはるかに超えてしまいます。 意図したソリューションは、数値全体に対して演算を実行するのではなく、桁を数え、割り切れる性質を使用することによって機能する必要があります。 

有効な最大の数値は、割り算条件を満たしながら、できるだけ多くの大きな桁を保持する必要があります。 不用意に実装すると、ほんの小さなケースでも失敗する可能性があります。 例えば：```
Input
1
0
```正しい出力は次のとおりです。```
0
```先頭にゼロ以外の数字が期待されるため、すべての 1 桁の数値を拒否するソリューションでは、誤って出力されます。`-1`。 

もう 1 つの重要なケースは、数字が 3 で割り切れない場合です。 例えば：```
Input
6
2 3 1 3 1 0
```正しい出力は次のとおりです。```
33210
```すべての数字を使用すると、`332110`、その桁の合計は 3 で割り切れません。常にすべての桁を保持する貪欲なソリューションは失敗するため、一部の桁を削除する必要があります。 

3 番目のエッジ ケースは、唯一可能な最後の数字が欠落している場合です。 例えば：```
Input
4
1 2 3 4
```正しい出力は次のとおりです。```
-1
```いかなる取り決めも次で終わることはできません`0`したがって、30 で割り切れる数値はありません。この条件をチェックせずに数字だけを並べ替えると、無効な答えが生成されます。 

## アプローチ

 直接的なアプローチは、考えられる数字のサブセットを試し、各サブセットを降順に並べ、結果の数値が 30 で割り切れるかどうかを確認することです。これは正しいです。最終的には、すべての選択肢の中から最大の有効な配置が表示されるからです。 問題は可能性の数です。 と`n`数字、あります`2^n`サブセット、さらには数百桁の場合でも、これはすでに不可能です。 のために`n = 100000`、ブルートフォースは実行可能とは程遠いです。 

問題の構造により、はるかに単純なパスが得られます。 10 で割り切れる必要があるため、30 で割り切れる数値はゼロで終わる必要があります。 また、桁の合計が 3 で割り切れる必要があります。末尾のゼロは固定要件であり、残りのタスクは、桁の合計を正しくするために必要な最小量の桁値を削除するだけです。 

利用可能なすべての数字を保持するとします。 桁の合計がすでに 3 で割り切れる場合は、すべての桁を降順に並べ替えるだけで済みます。 余りが 1 の場合、値が 1 余りの 1 桁を削除するか、値が 2 余りの 2 桁を削除できます。余りが 2 の場合、対称的な選択が適用されます。 最終的な数値を最大化するには、削除する桁数が少ない方が常に適切です。同じ桁数を削除する必要がある場合は、可能な限り小さい桁を削除することで最大の結果が得られます。 

割り算ルールにより、問題全体は 10 桁の可能な数字の数を維持することに帰着します。 最後の桁を降順に並べ替えると、保持されているすべての桁が使用され、大きい桁が先に表示されるため、最大の数値が得られます。

 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各桁が出現する回数を数え、桁の合計を計算します。 同じ値の数字は交換できるため、カウントは十分です。 
2. ゼロが存在するかどうかを確認します。 ゼロが存在しない場合、30 で割り切れる数は存在しないため、答えは不可能になります。 最後の数字としてゼロが必要です。 
3. 3 を法とした桁和の余りを計算します。ゼロでない場合は、余りを固定する桁を削除します。 1 桁を削除すると、より多くの桁が保持されるため、推奨されます。 それが不可能な場合は、結合した余りが正しい 2 つの数字を削除します。 
4. 必要な桁を削除した後、残りの桁を降順にすべて収集します。 数値が同じ長さの場合は辞書編集的に比較されるため、最大の桁が最初に表示される必要があります。 
5. 残りの桁がすべて 0 である特殊なケースを処理します。 答えは 1 つである必要があります`0`、余分なゼロは値を増加させないため、多くのゼロを含む文字列ではありません。 

機能する理由: 30 で割り切れる唯一の条件は、ゼロで終わること、および桁の合計が 3 で割り切れることです。アルゴリズムは常にゼロの要件を満たし続け、桁の合計を修復するために可能な最小限の桁数を削除します。 削除される桁数が同じすべての方法の中で、最小の桁が削除され、辞書編集上可能な最大の配置が残ります。 残りの桁を降順に並べ替えると、両方の条件を満たす最大の数値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(data):
    arr = data.split()
    if not arr:
        return ""

    n = int(arr[0])
    digits = list(map(int, arr[1:]))

    cnt = [0] * 10
    total = 0

    for d in digits:
        cnt[d] += 1
        total += d

    if cnt[0] == 0:
        return "-1"

    def remove_digit_with_remainder(rem):
        for d in range(1, 10):
            if d % 3 == rem and cnt[d] > 0:
                cnt[d] -= 1
                return True
        return False

    def remove_two_with_remainder(rem):
        for d in range(1, 10):
            if d % 3 == rem and cnt[d] > 0:
                for e in range(d, 10):
                    if e % 3 == rem and cnt[e] > 0:
                        if d == e and cnt[d] < 2:
                            continue
                        cnt[d] -= 1
                        cnt[e] -= 1
                        return True
        return False

    remainder = total % 3

    if remainder == 1:
        if not remove_digit_with_remainder(1):
            if not remove_two_with_remainder(2):
                return "-1"
    elif remainder == 2:
        if not remove_digit_with_remainder(2):
            if not remove_two_with_remainder(1):
                return "-1"

    ans = []
    for d in range(9, -1, -1):
        ans.append(str(d) * cnt[d])

    result = "".join(ans)

    if result == "":
        return "-1"

    if result[0] == "0":
        return "0"

    return result

if __name__ == "__main__":
    print(solve(sys.stdin.read()))
```このソリューションでは、潜在的に大きな整数を保存するのではなく、まず桁の頻度を保存します。 これにより、数値には次のものが含まれる可能性があるため、整数変換が完全に回避されます。`100000`数字。 

削除ヘルパーは、3 を法とする剰余によって数字を検索します。最初のヘルパーは 1 桁を削除し、2 番目のヘルパーは 2 桁を削除します。 小さい桁を削除すると、より大きな最終的な数値が保持されるため、桁は小さいものから大きいものへとチェックされます。 

桁の合計を修正した後、構築フェーズは次から繰り返されます。`9`まで`0`。 残りの数に従って各桁を繰り返すと、可能な限り最大の順序が作成されます。 施工後のゼロチェックでは、こんなケースにも対応します。`0000`、ここでの正しい表現は次のとおりです。`0`。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    import collections

    def solve(data):
        arr = data.split()
        if not arr:
            return ""
        n = int(arr[0])
        digits = list(map(int, arr[1:]))

        cnt = [0] * 10
        total = 0
        for d in digits:
            cnt[d] += 1
            total += d

        if cnt[0] == 0:
            return "-1"

        def remove_one(rem):
            for d in range(1, 10):
                if d % 3 == rem and cnt[d]:
                    cnt[d] -= 1
                    return True
            return False

        def remove_two(rem):
            for d in range(1, 10):
                if d % 3 == rem and cnt[d]:
                    for e in range(d, 10):
                        if e % 3 == rem and cnt[e] - (d == e) > 0:
                            cnt[d] -= 1
                            cnt[e] -= 1
                            return True
            return False

        r = total % 3
        if r == 1:
            if not remove_one(1) and not remove_two(2):
                return "-1"
        elif r == 2:
            if not remove_one(2) and not remove_two(1):
                return "-1"

        ans = "".join(str(d) * cnt[d] for d in range(9, -1, -1))
        return "0" if ans and ans[0] == "0" else ans

    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    res = solve(sys.stdin.read())
    sys.stdin = old
    return res
