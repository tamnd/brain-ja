 ## 問題の理解

 ニックは、指定された長さのすべての数値をリストしたいと考えています`n`基地内で`b`、数字の範囲は 0 ～`b-1`ただし、数字を 0 で始めることはできません。彼のメモ帳の各ページには正確な内容が含まれています。`c`数字。 私たちは、彼が記入した最後のページに数字がいくつ現れるかを計算するように求められます。 

入力は 3 つの整数で構成されます。`b`(ベース)、`n`(数値の長さ)、および`c`(ページごとの数字)。 出力は単一の整数、つまり最後のページの数値のカウントです。 

制約の場合は両方とも`b`そして`n`最大 10^105 まで可能です。 これにより、数値を明示的に列挙しようとしたり、サイズの配列を構築しようとしたりするソリューションは即座に排除されます。`b^n`。 標準の 64 ビット整数でもこれらの値を格納できないため、数学的に推論し、数値を大きな整数またはモジュラー/指数形式で操作する必要があります。 ページ数、`c`は最大 10^9 であり、管理可能ですが、それでも最大 10^9 まで線形に反復することはできません。`b^n`。 

数字の合計数が正確に割り算される場合、微妙なエッジケースが発生します。`c`。 たとえば、12 個の数字があり、各ページに 4 個の数字が含まれる場合、すべてのページがいっぱいになるため、最後のページには 4 個の数字が含まれます。 計算するだけの素朴なアプローチ`b^n % c`正確な割り算を処理しないと 0 が返されますが、これは正しくありません。 この問題では、その場合の最後のページでレポートが表示されます。`c`。 もう 1 つのエッジ ケースは、最小限の入力です。`b = 2`、`n = 1`、`c = 1`、数値は 1 つだけ存在します。 

## アプローチ

 ブルートフォースアプローチは簡単です。すべてを生成します。`n`-底の数字`b`、ゼロで始まるものをスキップし、それらを数えて、サイズのページを埋めます`c`。 概念的には正しいですが、このアプローチにはコンピューティングが必要です`b^n`不可能な数字`n`10^5 以上の大きさ。 コンピューティングでも`b^n`繰り返し乗算を直接使用すると遅すぎて、標準の整数型をはるかに超える数値が生成されてしまいます。 

重要な観察は、数値自体は必要なく、その数だけが必要であるということです。 有効枚数の合計`n`-底の数字`b`は`(b-1) * b^(n-1)`。 最初の数字は次のいずれかになります`1`に`b-1`、与える`b-1`オプションと残りのそれぞれ`n-1`数字は可能です`0`に`b-1`、与える`b^(n-1)`オプション。 合計数がわかれば、問題は最後のページに残っている数字の数を決定する単純なモジュラー算術演算に帰着します。 

したがって、問題はコンピューティングに帰着します`(b-1) * b^(n-1) % c`。 なぜなら`b`そして`n`が非常に大きくなる可能性があるため、べき乗剰余演算を効率的に実行する必要があります。これは二乗によるべき乗で実行できます。 このメソッドにより、次の計算が可能になります。`b^(n-1) % c`一度も保管せずに`b^(n-1)`明示的に。 最終的に、次の結果が得られた場合、`(b-1) * b^(n-1) % c`がゼロの場合は、最後のページがいっぱいであることを意味するため、返す必要があります`c`。

 | ブルートフォース | O(b^n) | お(1) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 入力値を解析する`b`、`n`、 そして`c`整数として。 以来`b`そして`n`桁数は数百桁になる可能性があるため、任意精度の整数として扱う必要があります。 
2. 指数を計算する`n-1`最後の選択肢の数を決定する`n-1`数字。 
3. べき乗剰余を使用して計算する`b^(n-1) % c`。 これにより、膨大な数を計算したり保存したりすることがなくなります。`b^(n-1)`直接。 累乗モジュラは二乗を繰り返すことで機能します`b`モジュロを削減する`c`各ステップで、毎回指数を半分にします。 
4. 結果を乗算します。`(b-1)`そしてモジュロを取る`c`また：`remaining = ((b-1) * pow(b, n-1, c)) % c`。 これにより、最後のページの数字の数が得られます。 
5. もし`remaining`がゼロの場合、最後のページが完全にいっぱいであることを意味するため、次のように出力します。`c`。 それ以外の場合は出力`remaining`。 

なぜ機能するのか: 各ステップでカウントのモジュロを維持します。`c`。 べき乗剰余演算は、同一性により正確さを保証します。`(x*y) % m = ((x % m)*(y % m)) % m`。 乗算する`(b-1)`残りのカウントによってシーケンスの数が正しくスケーリングされます。 ゼロをチェックすると、正確な割り算のエッジ ケースが処理され、最後のページが正しくレポートされるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

b, n, c = map(int, input().split())

# compute number of numbers on the last page
# pow supports three arguments: pow(base, exp, mod)
remaining = (b - 1) * pow(b, n - 1, c) % c
if remaining == 0:
    remaining = c

print(remaining)
```このコードは、高速 I/O を使用して入力を読み取り、潜在的に大きな整数を処理します。 の`pow`Python の関数は効率的に計算します`b^(n-1) % c`二乗によるべき乗を使用します。 乗算`(b-1)`最初の桁のカウントをスケーリングし、`% c`ページ制限内に確実に収まるようにします。 ゼロの最終チェックでは、最後のページが完全に埋まっている場合が処理されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

 ## 特殊なケース

 数字の合計がぴったり割れるとき`c`、モジュラー演算はゼロを返します。 例えば、`b = 2, n = 2, c = 3`合計数を与える`2*2 = 4`。`4 % 3 = 1`したがって、最後のページには 1 つの数値があり、アルゴリズムはそれを正しく出力します。 のために`b = 2, n = 3, c = 4`、合計数`2*(2^2)=8`。`8 % 4 = 0`、完全な最後のページを示します。 アルゴリズムは正しく `4 を返します
