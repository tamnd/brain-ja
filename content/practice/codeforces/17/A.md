 ## 解決策
 ## 問題の理解

 2 つの整数が与えられます。`n`そして`k`。 すべての素数を調べます。`2`まで`n`。 これらの素数のうち、次の形式で記述できる素数の数を数えたいとします。$$p_i + p_{i+1} + 1$$どこ`p_i`そして`p_{i+1}`は隣接する素数であり、昇順で連続する素数を意味します。 

たとえば、連続する素数`5`そして`7`生産する：$$5 + 7 + 1 = 13$$以来`13`も素数であり、カウントされます。 

タスクは、少なくとも次のことを判断することです。`k`までの素数`n`この性質を満たします。 「はい」の場合、印刷します`YES`、それ以外の場合は印刷します`NO`。 

制約は非常に小さいです。`n`せいぜい`1000`なので、かなり非効率な素数生成方法でも許容されます。 までのすべての数値に対する二次アルゴリズム`1000`まだ瞬時に実行されます。 これにより、問題の焦点が最適化から正確さとクリーンな実装に変わります。 

難しいのは、条件を正しく解釈することです。 数値が 2 つの素数に 1 を加えた合計として記述できるかどうかをチェックしているのではありません。 2 つの素数は、素数の順序付きリスト内で連続していなければなりません。 

次の入力を考えてみましょう。```
27 2
```有効な構造は次のとおりです。$$5 + 7 + 1 = 13$$そして$$7 + 11 + 1 = 19$$両方`13`そして`19`素数で最大でも`27`、したがって、答えは次のとおりです`YES`。 

よくある間違いは、隣接しない素数を許可してしまうことです。 例えば：```
20 1
```不注意な実装では、次のものが使用される可能性があります。$$3 + 13 + 1 = 17$$そして次のように結論付けます`17`カウントします。 それは間違いです、なぜなら`3`そして`13`隣接する素数ではありません。 正しい隣接ペアは次のとおりです。`(2,3)`、`(3,5)`、`(5,7)`、`(7,11)`、 等々。 

もう 1 つの簡単な間違いは、生成される数値自体も素数でなければならず、次を超えてはいけないことを忘れることです。`n`。 

例えば：```
10 1
```隣接する素数を使用する:$$2 + 3 + 1 = 6$$

`6`は素数ではないのでカウントされません。$$3 + 5 + 1 = 9$$

`9`もプライムではありません。 

有効な数値が存在しないため、正しい答えは次のとおりです。`NO`。 

もう 1 つのエッジケースは、`k = 0`。 その状況での答えはいつも`YES`有効な素数が少なくともゼロであることは自動的に真となるためです。 

例：```
2 0
```正しい出力は次のとおりです。```
YES
```有効な数値が見つかったかどうかだけをチェックするソリューションでは、誤って印刷される可能性があります。`NO`。 

## アプローチ

 最も直接的な総当たりアプローチは、次のすべての数値をテストすることです。`2`に`n`そしてすべての素数のペアを試して、その数値が次のように表現できるかどうかを確認します。$$p_i + p_j + 1$$素数が隣接しているかどうかもチェックします。 

おおよそありますので、`168`までの素数`1000`、このアプローチはまだ通過できるほど十分に小さいです。 最悪の場合の作業は次のとおりです。$$1000 \times 168^2$$これはわずか数百万回の操作にすぎません。 

ブルートフォース手法は制約が小さいため機能しますが、不必要な作業が行われます。 私たちが注目する式は、連続する素数によって完全に決定されます。 素数のリストがわかったら、有効な候補はすべて次のようになります。$$p_i + p_{i+1} + 1$$任意の組み合わせをテストする理由はありません。 

この観察により、問題は大幅に単純化されます。 まず、以下までのすべての素数を生成します。`n`。 次に、連続する素数のペアを反復処理し、候補値を計算し、その候補自体が素数であるかどうかを確認します。`n`。 

素数チェックを高速に行うために、すべての素数をセットに保存します。 そうすれば、メンバーシップテストは一定時間になります。 

条件ではすでに連続する素数が指定されているため、問題の構造は自然にこの解決策につながります。 数値の表現を検索する代わりに、考えられるすべての表現を直接生成します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(P²) | O(P) | 承認済み |
 | 最適 | O(n log log n) | O(n) | 承認済み |

 ここ`P`は最大の素数の数です`n`。 

## アルゴリズムのチュートリアル

 1. すべての素数を次から生成します。`2`に`n`エラトステネスの篩を使って。 

ふるいはシンプルで、小さな制約に対して信頼性があります。 また、後で素数検索を高速に行うこともできます。 
2. 生成されたすべての素数をリストとセットの両方に保存します。 

このリストには、隣接する素数にアクセスするために必要な素数の順序が保存されます。 このセットを使用すると、数値が素数かどうかを定数時間でチェックできます。 
3. 連続する素数ペアを反復処理します。 

あらゆるインデックスに対して`i`、 取る：$$primes[i] \text{ and } primes[i+1]$$4. 以下を計算します。$$candidate = primes[i] + primes[i+1] + 1$$これはまさに問題で必要とされる形式です。 
5. 候補が素数集合内にあり、以下を超えていないかどうかを確認します。`n`。 

両方の条件が当てはまる場合は、カウントを増やします。 
6. すべての隣接するペアを処理した後、カウントを次と比較します。`k`。 

カウントが少なくとも`k`、印刷`YES`。 それ以外の場合は印刷します`NO`。 

### なぜ効果があるのか

 すべての有効な数値は、隣接する素数の 1 つのペアから正確に取得されなければならないため、アルゴリズムは、問題定義で許可されているすべての可能な式を検査します。 有効な候補はスキップされません。 

連続するペアごとに、そのペアが生成できる唯一の数値を計算します。 素数セットのメンバーシップをチェックすると、素数のみがカウントされることが保証されます。 すべてのカウント値が必要な構造を満たしており、考えられるすべての構造がテストされるため、最終的なカウントは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    is_prime = [True] * (n + 1)

    if n >= 0:
        is_prime[0] = False
    if n >= 1:
        is_prime[1] = False

    for i in range(2, int(n ** 0.5) + 1):
        if is_prime[i]:
            for j in range(i * i, n + 1, i):
                is_prime[j] = False

    primes = []
    for i in range(2, n + 1):
        if is_prime[i]:
            primes.append(i)

    prime_set = set(primes)

    count = 0

    for i in range(len(primes) - 1):
        candidate = primes[i] + primes[i + 1] + 1

        if candidate <= n and candidate in prime_set:
            count += 1

    print("YES" if count >= k else "NO")

solve()
```最初のセクションではふるいを作成します。`is_prime[x]`かどうかを教えてくれます`x`プライムです。 から始まる`i * i`より小さな倍数はより小さな素数によってすでに処理されているため、冗長な作業が回避されます。 

ふるいにかけた後、すべての素数をリストに集めます。 この問題では隣接する素数が特に必要となるため、順序が重要になります。 

セットされたバージョンの素数は高速検索に使用されます。 これがなければ、候補が素数であるかどうかを確認するには、線形探索を繰り返すか、素数性テストを繰り返す必要があります。 

連続するペアにわたるループがソリューションの核心です。 使用する`range(len(primes) - 1)`読み取り時にリストの末尾を超えてアクセスするのを防ぎます`primes[i + 1]`。 

条件:```
candidate <= n and candidate in prime_set
```重要です。 生成された数値が素数であっても、許容範囲内にある場合にのみカウントされます。 

最後に、カウントを次と比較します。`k`そして必要な答えを印刷します。

 ## 特殊なケース

 次の入力を考えてみましょう。```
20 1
```このアルゴリズムは、隣接する素数ペアを生成します。$$(2,3), (3,5), (5,7), (7,11), \dots$$彼らの候補者は次のとおりです。$$6, 9, 13, 19, \dots$$

`13`そして`19`は素数であるため有効であり、最大でも`20`。 

アルゴリズムでは、次のような式は考慮されません。$$3 + 13 + 1 = 17$$なぜなら`3`そして`13`隣接する素数ではありません。 これにより、数えすぎを防ぐことができます。 

次に、次のことを考えてみましょう。```
10 1
```候補者は次のとおりです。$$2 + 3 + 1 = 6$$そして$$3 + 5 + 1 = 9$$どちらもプライムではありません。 素数集合の検索では両方の値が正しく拒否されるため、カウントは残ります。`0`そして出力は次のようになります`NO`。 

最後に、次のことを考慮してください。```
2 0
```プライムリストには以下が含まれます：`[2]`, したがって、隣接するペアはまったくありません。 カウントはそのまま`0`。 

最終的な比較では以下がチェックされます。$$0 \ge 0$$これは true なので、アルゴリズムは次のように出力します。`YES`。 これにより、特別な分岐を行わずに、空の場合のロジックが正しく処理されます。
