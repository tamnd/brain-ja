 ## 解決策
 ## 問題の理解

 それぞれの DNA 文字列は、形式の規則を繰り返し適用することによって進化します。`a -> bc`。 1 つの文字がちょうど 2 つの文字に置き換えられ、この操作は何度でも繰り返すことができます。 ある祖先の文字列から始まり、進化は長さを増すだけです。 

私たちは 2 つの最終的な DNA 文字列を与えられており、それらが両方とも同じ祖先に由来する可能性があるかどうかを知りたいと考えています。 可能であれば、そのような祖先の可能な最小限の長さを見つけなければなりません。 

重要な観察は、進化が祖先のそれぞれの性格に独立して作用するということです。 祖先文字列が次の場合:```
x1 x2 x3 ...
```次に、各文字が何らかの部分文字列に展開され、すべての展開が連結されて最終的な DNA が生成されます。 

入力文字列の長さは最大 50 で、生成ルールの数は最大 50 です。 これは 3 次または 4 次動的計画法には十分小さいですが、到達可能なすべての文字列を総当たり的に生成するには大きすぎます。 ルールは再帰的に分岐する可能性があるため、単一の文字であっても、指数関数的に多くの異なる文字列が生成される可能性があります。```
c -> cc
```すでに無限に多くの到達可能な文字列を作成しています。 

アルファベットのサイズはわずか 26 文字ですが、これは非常に重要です。 文字によってインデックス化された DP はどれも安価です。 

置換がまったく存在しない場合、微妙なエッジケースが発生します。 

例：```
ab
ab
0
```答えは`2`、なぜなら祖先は単に`"ab"`自体。 すべての文字が少なくとも 1 回展開される必要があると仮定する不注意な解決策は、このケースを誤って拒否することになります。 

もう 1 つの注意が必要なケースは、再帰的な生成です。 

例：```
a
aaaa
1
a->aa
```正しい答えは、`1`。 1 つの祖先文字は、ターゲット文字列全体に繰り返し展開できます。 生成された文字列に対する単純な BFS は、文法が循環的であるため、終了しない可能性があります。 

もう 1 つの重要な例外ケースは、両方の文字列が単一のシンボルから個別に導出可能であるにもかかわらず、最適な祖先が 1 文字より長い場合です。 

例：```
ab
ba
2
x->ab
x->ba
```答えは`2`、 ない`1`。 単一のシンボルで両方の文字列を同時に生成することはできません。 最も短い共通祖先は`"ab"`自体。 

最後の微妙な点は位置合わせです。 異なる祖先文字は、異なる長さの部分文字列に展開される場合があります。 

例：```
abba
baab
2
x->ab
x->ba
```最適な分割は文字ごとではありません。 同じパーティションが両方の文字列に対して同時に機能する必要があるため、貪欲一致アプローチは失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 考えられるすべての祖先文字列について、そこから到達可能なすべての文字列を生成し、両方のターゲット文字列が表示されるかどうかを確認します。 

進化のプロセスは置換ルールによって完全に定義されるため、これは理論的には正しいです。 問題は、サイクルが存在する場合は常に、到達可能な状態空間が無限であることです。 サイクルがない場合でも、生成される文字列の数は展開ステップの数に応じて指数関数的に増加します。 ターゲットの長さが最大 ​​50 に達すると、ブルート フォースはほぼ即座に絶望的になります。 

ルールを逆から読むと、より良い視点が得られます。 

ルール:```
a -> bc
```これは、から生成された隣接する部分文字列が表示されるたびに意味します。`b`そして`c`、それらは一緒に起源した可能性があります`a`。 

これはまさに文脈自由文法解析です。 すべての文字は非終端であり、各ルールは 2 つのシンボルを 1 つの親シンボルに結合します。 

次のように定義するとします。```
can[c][l][r]
```そのキャラクターを意味する`c`部分文字列を生成できる`s[l:r]`。 

次に、CYK 解析と同様に、間隔 DP を使用してこれを計算できます。 1 つの文字が自動的に生成され、文字を 2 つの小さな間隔に分割し、文法規則を適用することで、より大きな間隔が構築されます。 

わかったら、次のすべての部分文字列について、`s1`そして`s2`, which characters can generate it, the original problem becomes another DP.

 何かの祖先キャラクターであれば`x`部分文字列を生成できる`s1[l1:r1]`部分文字列も`s2[l2:r2]`、その場合、1 つの祖先の位置で両方の部分を同時に説明できます。 

次に、次のように定義します。```
dp[i][j]
```プレフィックスを生成するために必要な祖先の最小長としては、次のようになります。```
s1[:i], s2[:j]
```終了部分文字列のすべてのペアを試し、共通の生成文字が存在するかどうかを確認します。 「はい」の場合、分解を 1 つの祖先文字まで拡張します。 

これにより、問題は無限探索から多項式動的計画法に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 最適 | O(26 × n3 + | s1 | ² × |

 ここ`n`多くても50です。 

## アルゴリズムのチュートリアル

 1. すべての置換ルールを解析します。 

あらゆるルールについて`a -> bc`、それを保管してください`a`の結果を組み合わせることができます`b`そして`c`。 
2. 最初の文字列の間隔 DP を構築します。 

定義する：```
can1[ch][l][r]
```文字の場合はどちらが当てはまりますか`ch`部分文字列を生成できる`s1[l:r]`。 

長さについて`1`, only the matching character is possible.
 3. 長さの昇順に間隔を拡張します。 

間隔ごとに`[l, r)`、すべての分割ポイントを試してください`m`。 

何らかのルールがある場合:```
a -> bc
```を満たす:```
can1[b][l][m] and can1[c][m][r]
```それから：```
can1[a][l][r] = True
```これが機能するのは、自明でない部分文字列のすべての導出ツリーがルート ルールで 2 つの子導出に分割される必要があるためです。 
4. 2 番目の文字列に対して同じ DP を繰り返します。 

これで、両方の文字列のすべての部分文字列を生成できるすべての文字がわかりました。 
5. メイン DP を定義します。 

させて：```
dp[i][j]
```生成するために必要な祖先の最小の長さは次のとおりです。```
s1[:i] and s2[:j]
```初期化:```
dp[0][0] = 0
```6. 祖先文字を 1 つ一致させて遷移します。 

以前のすべての状態に対して`(i, j)`、すべての部分文字列の終わりを試してください。```
s1[i:ni], s2[j:nj]
```キャラクターが存在する場合`c`次のような:```
can1[c][i][ni] and can2[c][j][nj]
```この場合、1 つの祖先シンボルが両方の部分文字列を生成できるため、次のようになります。```
dp[ni][nj] = min(dp[ni][nj], dp[i][j] + 1)
```7. 答えは次のとおりです。`dp[len(s1)][len(s2)]`。 

到達できない場合は印刷する`-1`。 

### なぜ効果があるのか

 間隔 DP は、各文字から導出可能な部分文字列のセットを正確に計算します。 これは文法構造から帰納的に導き出されます。 長さ 1 の部分文字列は定義上正しく、すべての大きな派生はルートに 1 つの生成を適用し、2 つの小さな派生に分割する必要があります。 

2 番目の DP は、両方の文字列を対応する部分に分割します。 各ピースのペアは同じ祖先キャラクターから生成されます。 これらの祖先文字を連結すると、有効な共通祖先文字列が形成されます。 

すべての有効な祖先はそのようなパーティションを誘発し、DP によって構築されたすべてのパーティションは有効な祖先に対応します。 トランジションでは祖先文字が 1 つだけ追加されるため、DP は祖先の長さを正しく最小化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**9

def build_can(s, rules):
    n = len(s)

    can = [[[-1] * (n + 1) for _ in range(n)] for _ in range(26)]

    for i, ch in enumerate(s):
        can[ord(ch) - ord('a')][i][i + 1] = 1

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length

            for m in range(l + 1, r):
                for a, b, c in rules:
                    if can[b][l][m] == 1 and can[c][m][r] == 1:
                        can[a][l][r] = 1

    return can

def solve():
    s1 = input().strip()
    s2 = input().strip()

    n = int(input())

    rules = []

    for _ in range(n):
        line = input().strip()

        a = ord(line[0]) - ord('a')
        b = ord(line[3]) - ord('a')
        c = ord(line[4]) - ord('a')

        rules.append((a, b, c))

    can1 = build_can(s1, rules)
    can2 = build_can(s2, rules)

    n1 = len(s1)
    n2 = len(s2)

    dp = [[INF] * (n2 + 1) for _ in range(n1 + 1)]
    dp[0][0] = 0

    for i in range(n1 + 1):
        for j in range(n2 + 1):
            if dp[i][j] == INF:
                continue

            for ni in range(i + 1, n1 + 1):
                for nj in range(j + 1, n2 + 1):

                    ok = False

                    for ch in range(26):
                        if can1[ch][i][ni] == 1 and can2[ch][j][nj] == 1:
                            ok = True
                            break

                    if ok:
                        dp[ni][nj] = min(dp[ni][nj], dp[i][j] + 1)

    ans = dp[n1][n2]

    print(-1 if ans == INF else ans)

solve()
```の`build_can`関数は文法解析 DP を実行します。 各状態は、文字が部分文字列を導出できるかどうかを格納します。 より大きな派生はより小さな間隔に依存するため、間隔は長さの増加順に処理されます。 

表現:```
can[ch][l][r]
```右側のエンドポイントが排他的であるため、少し特殊です。 これにより、多くのオフバイワンミスを回避できます。 部分文字列は常に次のとおりです。```
s[l:r]
```Python のスライスとまったく同じです。 

メイン DP は、文字列を同期されたチャンクに分割されているものとして扱います。 すべての遷移では、1 つの文字が選択された両方の部分文字列を導出できるかどうかがチェックされます。 

ネストされたループは高価に見えるかもしれませんが、制限はわずかです。 最大でも:```
51 × 51 × 51 × 51 × 26
```チェックが発生するため、時間に簡単に合わせることができます。 

実装の微妙な詳細の 1 つは、派生ツリーが同じ形状であることを決して要求しないことです。 必要なのは、共通の文字が両方の部分文字列を独立して生成できることだけです。 間隔 DP は、考えられるすべての派生をすでにカプセル化しています。

 ## 特殊なケース

 置換がない場合を考えてみましょう。 

入力：```
ab
ab
0
```間隔 DP は単一文字の部分文字列のみをマークします。 1 つのシンボルでそれより大きな部分文字列を生成することはできません。 

メイン DP は両方の文字列を次のように分割します。```
a + b
```したがって、答えは次のようになります`2`。 

これは、変更されていない文字が許可されることを正しくモデル化しています。 Evolution では操作が実行されない場合があります。 

次に、再帰的な成長について考えてみましょう。 

入力：```
aaaa
aa
1
a->aa
```間隔 DP は最初にすべてが単一であることをマークします`a`部分文字列。 次に、長さ 2 の部分文字列が次から導出可能になります。`a`。 これらを再度結合すると、長さ 4 の部分文字列が次のように導出されます。`a`。 

このアルゴリズムは、拡張の深さを明示的にシミュレートすることはありません。 部分文字列の導出可能性のみを追跡するため、サイクルは無害です。 

最後に、互換性のない導出について考えてみましょう。 

入力：```
ab
ba
2
x->ab
x->ba
```間隔 DP は以下を検出します。```
x generates ab
x generates ba
```しかし、同じ文字で両方の文字列全体を同時にカバーする単一の部分文字列ペアはありません。 

代わりに、メインの DP は次のように分解されます。```
a + b
```答える`2`。 

これは、同期パーティション化が必要な理由を示しています。 2 つの文字列の導出可能性を個別に照合するだけでは十分ではありません。
