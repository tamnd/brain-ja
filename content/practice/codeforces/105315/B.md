 ## 解決策
 ## 問題の理解

 いくつかの独立したクエリが与えられます。 各クエリは整数 n を提供し、単一の整数 a を出力する必要があります。ここで、a は n に最も近い素数です。 2 つの素数が同等に近い場合は、小さい方を選択する必要があります。 

このタスクは基本的に、「数直線上の指定された値に最も近い素数はどれですか?」という質問に繰り返し答えることです。 

入力サイズから、n は最大 1,000,000 に達し、最大 100,000 のクエリが存在する可能性があることがわかります。 各 n の素数性を個別にテストしようとする単純なアプローチでは、クエリごとに重い作業を繰り返すと、すでに困難が生じます。 この制約の主な意味は、素数情報を一度前処理して効率的に再利用する必要があるということです。 

n 自体が素数の場合、微妙なエッジ ケースが発生します。 この場合、それ自体までの距離はゼロであるため、答えは自明に n になります。 別のエッジ ケースは、2 つの素数が等距離にある場合、たとえば n = 10 付近で、7 と 11 が両方とも距離 3 である場合に発生します。問題では明示的に小さい方の素数を選択する必要があるため、7 が正解です。 

単純なロジックを破る可能性があるもう 1 つの状況は、適切な境界を持たずに n から外側に検索する場合です。 下方向のみまたは上方向のみを検索すると、反対側にある最も近い素数を見逃してしまう可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各クエリ n について、n から外側のすべての整数をチェックします。最初に n が素数かどうかをチェックし、次に n−1 と n+1、次に n−2 と n+2 というように、両側で素数が見つかるまでチェックします。 各素数チェックには少なくとも O(√n) のコストがかかり、最悪の場合、両側で素数をヒットする前に広い範囲を探索する可能性があります。 クエリが 100,000 件を超えると、すぐに非常に遅くなります。 

この非効率性は、異なるクエリ間で重複する数値の素数チェックを繰り返すことから発生します。 多くのクエリは近くの値を尋ねますが、数値の素数はクエリ間で変わりません。 これは、可能な最大値 n までのすべての素数を 1 回前処理し、その後一定時間で各クエリに応答することを示唆しています。 

1,000,000 までの各数値が素数かどうかを示すブール配列を事前計算すると、問題は静的セット内の最近傍検索に縮小されます。 各 n について、各辺で少なくとも 1 つの素数が見つかるか、一方の方向が勝つことを確認するまで、n から外側に両方向に同時に拡張します。 検索範囲は事前に計算されたふるいによって制限されるため、実際には十分に高速になります。 

これをより構造化して考えると、繰り返される素数クエリを単一のグローバル sieve 構造に変換し、その後にローカル最近接素数検索を行うということになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(t · √n · k) 最悪の場合の展開 | お(1) | 遅すぎる |
 | ふるい + 検索 | O(N log log N + t · d) | O(N) | 承認済み |

 ここで d は最も近い素数までの平均距離であり、10^6 までの数値では小さくなります。 

## アルゴリズムのチュートリアル

 まず、ふるいを使用して、1,000,000 までのすべての数値の素数性を事前計算します。 これにより、後の素数チェックが O(1) になることが保証されます。これは、この情報を何度もクエリするため必要です。 

次に、各クエリ値 n を反復処理して、最も近い素数を決定します。

1. true に初期化されたサイズ 1,000,001 の配列 is_prime を事前計算し、0 と 1 を非素数としてマークします。 これにより、そうでないことが証明されるまで、すべての数値が素数であると想定されるベースラインが確立されます。 
2. 2 から上のふるいを実行し、素数 p が見つかった場合は常に、p のすべての倍数を非素数としてマークします。 このステップでは、それぞれを個別にテストするのではなく、構造化されたバッチ内の合成数を排除することで、範囲全体の完全な素数構造を効率的に構築します。 
3. 各クエリ値 n について、まず is_prime[n] が true かどうかを確認します。 そうであれば、それ自体までの距離がゼロであるため、すぐに n を出力し、可能な限り最も近い素数とします。 
4. n が素数でない場合、1 から開始して距離 d を増加させながら外側に拡張します。各ステップで、範囲内に留まっている限り、n − d と n + d をチェックします。 これらの候補の中から少なくとも 1 つの素数を見つけたらすぐに終了します。 
5. n − d と n + d の両方が同じ距離にある素数である場合、問題では同点の場合に小さい方の素数を選択する必要があるため、n − d を出力します。 

これが機能する理由は、検索プロセスの対称性に関係しています。 私たちは n からの距離を増やしながら数値を探索するため、初めて素数に遭遇したとき、それは可能な限り最も近い素数でなければなりません。 d を増加する前に各距離レベルで両側をチェックするため、より近い素数がスキップされないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 10**6

is_prime = [True] * (MAXN + 1)
is_prime[0] = is_prime[1] = False

p = 2
while p * p <= MAXN:
    if is_prime[p]:
        step = p
        start = p * p
        for x in range(start, MAXN + 1, step):
            is_prime[x] = False
    p += 1

def solve(n):
    if is_prime[n]:
        return n
    d = 1
    while True:
        left = n - d if n - d >= 0 else None
        right = n + d if n + d <= MAXN else None

        if left is not None and is_prime[left]:
            return left
        if right is not None and is_prime[right]:
            return right
        d += 1

t = int(input())
out = []
for _ in range(t):
    n = int(input())
    out.append(str(solve(n)))

print("\n".join(out))
```ふるいセクションはグローバル素数知識を一度構築します。 ループ構造により、複合材料が正方形から効率的に削除されるため、冗長な作業が回避されます。 

クエリ関数は、事前計算された配列に完全に依存します。 素数 n を早期に返すことは、不必要な拡張を避けるために重要です。 距離が単調増加するため、双方向展開では正確さが保証されます。 

細かい点の 1 つは境界チェックです。 n − d と n + d が配列境界内に収まるようにしないと、無効なインデックスにアクセスしたり、エッジで有効な素数を見逃したりする可能性があります。 実装では明示的に両方向を保護します。 

## 実用的な例

 ### 例 1

 入力:

 n = 10

 私たちは外側に拡張します:

 | d | n-d | プライム？ | n+d | プライム？ | 決定 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 9 | いいえ | 11 | はい | リターン11 |

 11 は素数ですが、9 は素数ではないため、d = 1 で停止します。 これは、最も近い素数が片側にのみ存在する可能性があるため、上向き検索と下向き検索の両方が必要であることを示しています。 

### 例 2

 入力:

 n = 10 (タイケースのデモンストレーション)

 もう一度距離を確認します。 

| d | n-d | プライム？ | n+d | プライム？ | 決定 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 9 | いいえ | 11 | はい | リターン11 |
 | 2 | 8 | いいえ | 12 | いいえ | 続ける |

 これは、アルゴリズムが常に最小距離で最初に遭遇した素数を選択し、ある d で両方の辺が一致する場合、左側が選択されることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log log N + t · d) | sieve は素数を構築し、各クエリは最も近い素数になるまで外側に拡張されます。 
| スペース | O(N) | 1e6 までの素数のブール配列 |

 ふるいは前処理の大半を占めますが、N = 1e6 の制約内に簡単に適合します。 この範囲では素数が密集しているため、各クエリは通常、非常に小さな外向きの動きを必要とし、100,000 クエリに対してソリューションが快適に高速になります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MAXN = 10**6
    is_prime = [True] * (MAXN + 1)
    is_prime[0] = is_prime[1] = False

    p = 2
    while p * p <= MAXN:
        if is_prime[p]:
            for x in range(p * p, MAXN + 1, p):
                is_prime[x] = False
        p += 1

    def solve(n):
        if is_prime[n]:
            return n
        d = 1
        while True:
            if n - d >= 0 and is_prime[n - d]:
                return n - d
            if n + d <= MAXN and is_prime[n + d]:
                return n + d
            d += 1

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(solve(n)))
    return "\n".join(out)

# provided samples (conceptual)
assert run("3\n10\n11\n1\n") == "11\n11\n2"

# custom cases
assert run("1\n2\n") == "2", "minimum prime"
assert run("1\n14\n") == "13", "closest below"
assert run("1\n15\n") == "13", "tie handling"
assert run("1\n1000000\n") != "", "upper bound stability"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | n = 2 | 2 | 最小のプライムエッジ |
 | n = 14 | 13 | 下向きの最も近い素数 |
 | n = 15 | 13 | タイブレークの正しさ |
 | n = 1000000 | 有効な素数 | 上限の堅牢性 |

 ## 特殊なケース

 n = 1 の場合、アルゴリズムは d = 1 から開始し、n − d = 0 および n + d = 2 をチェックします。0 は無効で、2 は素数であるため、正しく 2 をすぐに返します。 

n = 2 の場合、初期のプライム チェックは検索ループに入らずに 2 を返します。 これにより、不必要な境界チェックが回避され、最小の有効な素数での正確さが保証されます。 

n = 999983 (すでに上限近くで素数) のような大きな値の場合、ふるいはその値を正しくマークし、アルゴリズムは展開せずに直ちにその値を返します。 これは、早期終了条件が密なプライム領域付近のパフォーマンスの安定性にとって重要であることを示しています。
