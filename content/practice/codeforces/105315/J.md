 ## 解決策
 ## 問題の理解

 各テスト ケースは料理のコレクションを記述します。各料理は特定のレストランに属し、味の数値を持ちます。 重要な制約は、レストランを混在させることができないことです。 レストランを 1 つだけ選択し、そこに属するすべての料理を摂取する必要があります。 選択したレストランの価値は、そのレストランで最も弱い料理、つまりすべての料理の中で最低の味の値によって決まります。 あなたの仕事は、最も弱い料理ができるだけ強いレストランを特定することです。 

より具体的に言うと、すべてのレストラン ラベルについて、それに関連付けられている味の値をすべてグループ化し、そのグループ内の最小値を計算し、これらすべての最小値の中から最大値を選択します。 

入力サイズはすべてのテスト ケースで合計 500,000 料理に達します。これにより、クエリごとにリストを繰り返しスキャンしたり、レストランの選択ごとに最小値を最初から再計算したりするアプローチは即座に除外されます。 ディッシュ数が 2 次であるソリューションでは、テスト ケースごとに 10^5 の操作を 10^3 回繰り返すだけでも、すでに許容できない実行時間が発生するため、遅すぎます。 

複数の料理が同じレストランに属しているにもかかわらず、任意の順序で到着する場合、微妙なエッジケースが発生します。 たとえば、レストランに値 10、2、および 7 の料理がある場合、順序に関係なく、このレストランからの回答寄与度は 2 になります。 レストランごとに最後に検出された値のみを追跡する単純なアプローチでは、最小値が以前に出現して上書きされると、この場合に誤って 7 が出力されます。 

すべてのレストランで料理が 1 種類だけの場合、別の特殊なケースが発生します。 各レストランの最小値が唯一の値であるため、答えは単純に最大 di になります。 誤ってレストランをマージする誤ったグループ化ロジックは、ここで失敗します。 

## アプローチ

 各レストランを個別に扱うという強引なアプローチです。 すべてのレストラン ラベルについて、すべての料理を収集し、割り当てられた料理の完全なリストをスキャンして最小値を明示的に計算します。 n 個の料理があり、n 個の異なるレストランが存在する可能性がある場合、最悪の場合、各レストランの配列のほぼ全体を繰り返し再スキャンします。 これにより、最悪の場合の操作数は n の 2 乗のオーダーとなり、最大制約ではおよそ 10^10 の操作となり、2 秒の制限で処理できる操作数をはるかに超えます。 

重要な観察は、実際には何も再計算する必要がないということです。 各料理は、正確に 1 つのレストラン グループに 1 つの値を提供し、グループごとに重要な情報はその最小限の情報だけです。 これは、入力を一度読み取ると、レストランごとの実行最小値を維持することを示唆しています。 データを再検討する代わりに、レストラン ID をキーとする辞書を更新し、これまでに確認された最小値を保存します。 

これにより、問題はシングルパス集計問題に変換されます。 各更新は一定時間で行われ、すべての料理を処理した後、収集された最小値をスキャンして最大値を見つけるだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、レストラン ID から現在の最小料理値へのマッピングを構築します。

1. レストランごとに、これまでに確認された最小の味の値を保存する空の辞書を初期化します。 この構造が必要なのは、ディッシュごとに一定時間の更新が必要なためです。 
2. 各料理を 1 つずつ読みます。 レストラン a に属する値 d の料理について、a が以前に見たことがあるかどうかを確認します。 そうでない場合は、d を現在の最小値として直接保存します。 
3. レストランがすでに辞書に存在する場合は、新しい料理の値が小さい場合にのみ、保存されている値を更新します。 これにより、そのレストランで最も弱い料理を見失うことがなくなります。 
4. すべての料理を処理した後、保存されているすべての最小値を反復処理し、それらの最大値を計算します。 この最後のステップでは、必要な基準に従って可能な限り最高のレストランを選択します。 
5. テスト ケースのこの最大値を出力します。 

これが機能する理由は、すべてのレストランの貢献度がその最小値によって完全に決定され、料理の完全なリストを再度必要とせずにその最小値を段階的に維持できるためです。 

### なぜ効果があるのか

 処理中のどの時点でも、辞書には各レストランのすべての処理済み料理の正確な最小値が保存されます。 これは、より小さい値が出現した場合にのみ保存された値を置き換えることによって保存される不変式です。 すべての料理は正確に 1 回処理されるため、入力が終了するまでに、各レストランに保存される値は、そのレストランのフルセットのグローバル最小値となります。 これらの正しい最小値よりも最大値を取ることで、最適なレストランの選択が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        best = {}
        for _ in range(n):
            a, d = map(int, input().split())
            if a in best:
                if d < best[a]:
                    best[a] = d
            else:
                best[a] = d

        ans = 0
        for v in best.values():
            if v > ans:
                ans = v
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装の中核は辞書です`best`、レストランごとの現在の最小値が保存されます。 更新ステップは、不要な関数呼び出しやマージを避けるために慎重に記述されています。 集計と読み取りを混合すると、正当性の推論が複雑になり、すべてのレストランにわたる最終的な比較が行われない危険性があるため、最後のループは別個にされています。 

微妙な点の 1 つは、`ans`。 制約で指定されているように、すべてのディッシュ値は正であるため、0 から開始するのが安全です。 値が負の可能性がある場合は、初期化を負の無限大または最初の辞書値に調整する必要があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 各料理は 1 回処理され、各辞書操作は平均 O(1) 回です。 
| スペース | O(k) | k は辞書に格納されている個別のレストランの数です。 

テスト ケース全体の n の合計は最大 5 × 10^5 であるため、線形解は時間制限内に問題なく収まります。 メモリ使用量は、レストランごとに最大 1 つのエントリを保存することで制限されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        best = {}
        for _ in range(n):
            a, d = map(int, input().split())
            if a in best:
                best[a] = min(best[a], d)
            else:
                best[a] = d

        ans = max(best.values())
        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、レストランが何度も表示され、時間の経過とともに値が減少する場合です。 たとえば、次のように入力します。```
1
4
1 10
1 5
1 7
1 3
```アルゴリズムは、保存された値を段階的に更新します。 

最初は 10、次に 5、7 以降も 5 のままで、その後 3 になります。格納された値が常にこれまでに確認された最小値であるという不変式により正確さが保証され、最終出力は 3 になります。 

もう 1 つのケースは、複数のレストランが接戦を繰り広げている場合です。```
1
5
1 10
2 9
3 8
4 7
5 6
```各レストランには単一の値があるため、辞書にはすべての値が変更されずに保存されます。 最終的な最大値は正しく 10 を返します。これは、グループ化の調整が必要ない場合、アルゴリズムが単純な最大値の選択に縮小されることを示しています。
