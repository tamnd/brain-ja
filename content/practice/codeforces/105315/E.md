 ## 問題の理解

 別の隠し配列の累積 gcd 情報を記述するシーケンスが与えられます。 ポジションごとに$i$、値$b_i$最初の gcd に等しい$i$未知の配列の要素$a$。 私たちのタスクは、有効な配列を再構築することです。$a$指定されたシーケンスを生成できる$b$、またはそのような配列が存在しないと判断します。 

重要な問題は、gcd は累積的であり、一般に可逆的ではないことです。 それぞれ$b_i$前の要素をすべて同時に拘束します。$a_i$。 したがって、再構築ではプレフィックス全体にわたるグローバルな一貫性条件を尊重する必要があります。 

制約により、最大で$10^6$テスト ケース全体の要素の合計。これは、$O(n)$または$O(n \log n)$試験溶液ごとに。 ペアごとの整合性チェックや候補のバックトラックを伴うアプローチは、遅すぎるでしょう。 

gcd シーケンスが単調非増加ではない場合、微妙な失敗のケースが発生します。 プレフィックス gcd は同じままか減少することしかできないため、増加するとすぐにシーケンスが不可能になります。 たとえば、次の場合$b = [6, 10]$、より大きなプレフィックスの gcd は前のプレフィックス gcd よりも大きくできないため、これは無効です。 

もう 1 つのよくある間違いは、次の設定を想定していることです。$a_i = b_i$常に機能します。 たとえば、次の場合$b = [6, 3]$、設定$a = [6, 3]$プレフィックス gcds を生成します$6, 3$これは問題ありませんが、後の制約によって可分性構造を通じて矛盾が強制される場合、単純な代入はより複雑なシーケンスで失敗する可能性があります。

より構造化されたブルートフォースは、$a$すべてのプレフィックス gcd 制約を維持しながら段階的に。 ステップで$i$の値を試してみます。$a_i$そのような$\gcd(b_{i-1}, a_i) = b_i$ただし、有効なすべての倍数をテストします。$b_i$まで$10^9$実行不可能な検索につながります。 

重要な洞察は、視点を逆転させることです。 治療する代わりに$b_i$未知のプレフィックス動作に対する制約として、候補配列を構築します。$a$これは、プレフィックス gcd Evolution が正確に一致するように強制するものです。 プレフィックス gcd が から変化することが観察されます。$b_{i-1}$に$b_i$、新しい要素は正確に正しい gcd 削減を導入する必要があり、次のことを保証するだけで十分です。$$\gcd(b_{i-1}, a_i) = b_i$$これにより、単純な gcd 制約の下で各要素を個別に構築するという問題が軽減されます。 

以下を選択することでこれを強制できます。$$a_i = b_i$$いつでも$b_i$分割する$b_{i-1}$、 以来：$$\gcd(b_{i-1}, b_i) = b_i$$ただし、これだけでは完全なプレフィックス展開の正確性を保証するには十分ではありません。以前の要素が将来のすべての gcd 値と一貫性を保っていることも確認する必要があるからです。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列を読み取ります。$b$。 これを、何らかの配列によって正確に実現される必要がある必須のプレフィックス gcd シーケンスとして扱います。$a$。 
2. 各プレフィックス gcd が増加してはいけないという必要条件を確認します。 具体的には、すべての項目について確認します。$i > 1$、$b_{i-1} \ge b_i$。 これが失敗した場合は、要素を追加しても gcd 値を増やすことができないため、すぐに -1 を出力します。 
3. 以下をチェックして、シーケンス全体の割り算の一貫性を検証します。$b_{i-1} \bmod b_i = 0$みんなのために$i > 1$。 これにより、各ステップを前のプレフィックスからの有効な gcd 遷移として取得できることが保証されます。 
4. すべてのチェックに合格したら、次の設定を行って答えを作成します。$a_i = b_i$すべてのポジションに。 この選択により、各プレフィックス gcd が指定されたシーケンスと正確に一致することが保証されます。 
5. 構築された配列を出力します。 

The reason this construction is chosen is that it directly embeds the desired prefix structure into the array itself, removing the need for any hidden adjustments or auxiliary values.

 ### なぜ効果があるのか

 あらゆる段階で$i$、構築された配列の接頭辞 gcd が次と等しいことを維持します。$b_i$。 導入は簡単に始まります$i = 1$、 どこ$a_1 = b_1$。 プレフィックス gcd が以下であると仮定すると、$i-1$等しい$b_{i-1}$、追加$a_i = b_i$結果:$$\gcd(b_{i-1}, b_i) = b_i$$割り切れる条件があるからです。 これにより、プレフィックス gcd 遷移がすべてのステップで指定されたシーケンスと正確に一致することが保証されるため、構築された配列は有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))

        ok = True
        for i in range(1, n):
            if b[i-1] < b[i] or b[i-1] % b[i] != 0:
                ok = False
                break

        if not ok:
            out.append("-1")
        else:
            out.append(" ".join(map(str, b)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、アルゴリズムで導出された構造条件が直接強制されます。 最初のループは、単調非増加動作と割り算の両方をチェックします。これが、妥当性のために必要な唯一の制約です。 確認したら再利用$b$出力配列で十分なので。 

よくある実装の落とし穴は、割り算のチェックを忘れて、単調性のみを強制することです。 それは次のようなシーケンスを誤って受け入れます$[6, 4]$これは、gcd を 6 から 4 に減らすことができる数値がないため、どの配列からも生じません。

 ## 特殊なケース

 重要なエッジケースは、数列が減少するが、割り切れるわけではない場合です。 入力用$b = [12, 8]$、アルゴリズムがチェックします$12 \bmod 8 \neq 0$、すぐに拒否します。 これは、不可能性を正しく反映しています。プレフィックス gcd 12 の後に 8 が続く配列は存在しないためです。
