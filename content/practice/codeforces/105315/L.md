 ## 問題の理解

 複数の独立したテスト ケースが与えられます。 各テスト ケースは、複数の整数のペアで構成されます。 各ペアごとに$(a, b)$として定義された値を計算します。$a^b$。 この問題では、値自体を通常の数値形式で求めることはありません。 代わりに、次の無限小数展開を考慮します。$a^b$そして、小数点以下の桁に焦点を当て、この分数展開を無限シーケンスとして扱います。 

2 つのペアは、対応する値の小数部が無限大である場合に同等とみなされます。$a^b$全く同じです。 タスクは、順序付けされていないインデックスのペアの数を数えることです。$(i, j)$、 と$i < j$、同一の無限小数桁シーケンスを生成します。 

「無限に多くの桁に等しい場合にのみ等しい」という表現により、有限精度によって生じる曖昧さが解消されます。 2 つの実数を完全な 10 進展開で比較しています。つまり、どの桁でも、どんなに離れていても、ほんのわずかな違いでもそれらは異なります。 

制約は大きく、最大で$2 \cdot 10^6$合計ペア。 これにより、比較ごとに数値を再計算またはシミュレートするアプローチは即座に除外されます。 平$O(n^2)$テストケースごとに不可能であり、さらには$O(n \log n)$大きなべき乗や任意精度の 10 進シミュレーションなどの要素ごとの重い計算を避ける必要があります。 

素朴な解釈では、計算しようとします。$a^b$浮動小数点数または高精度数値として変換し、小数部分を比較します。 それは 2 つの点で失敗します。 まず、正確な分数展開で大きな累乗を計算することは不可能です。 第 2 に、浮動小数点演算は無限展開の等価性を完全に破ります。 

2 番目の微妙なエッジ ケースは、対数表現の構造的な周期性により、異なる整数のペアが同一の小数部分を生成する可能性があることです。 たとえば、2 つの式が、分数表現では打ち消される整数乗の差だけが異なる場合、単純な数値比較では誤ってそれらを別のものとして扱います。 

## アプローチ

 ブルートフォースソリューションでは次のように計算されます。$a^b$高精度（または非常に細かく近似）で、小数部の長い接頭辞を抽出し、文字列を比較します。 プレフィックスの長さだけを比較したとしても$k$、選択する$k$すべてのケースで正確性を保証するのに十分な大きさを計算することは、数理論的な深い洞察がなければ不可能であり、ペアごとのそのような計算は、与えられた条件を考慮すると遅すぎます。$n$まで$2 \cdot 10^6$。 

重要な観察は、実際には次の数値が必要ないということです。$a^b$。 すべてのペアの中でそれを一意に識別する、その部分的な動作の表現のみが必要です。 これにより、表現を標準的な形式に変換する方向に進むことができます。 

対数を使用します。 書く$$a^b = e^{b \ln a}.$$今すぐ分解してください$b \ln a$整数部と小数部に分ける:$$b \ln a = \lfloor b \ln a \rfloor + \{b \ln a\}.$$それから$$a^b = e^{\lfloor b \ln a \rfloor} \cdot e^{\{b \ln a\}}.$$整数部分は整数のスケーリング係数にのみ寄与しますが、小数部分の動作は小数部分によって完全に決定されます。$\{b \ln a\}$。 の整数乗を掛けるので、$e$大きさはシフトしますが、無限 10 進数列としての等価性の下での分数展開パターンの繰り返し構造には影響しません。2 つの値は、分数の対数成分が一致する場合に正確に一致します。 

Thus, each pair can be represented by the key:$$key(a,b) = b \ln a - \lfloor b \ln a \rfloor.$$ここで問題は、すべてのペアにわたってこのキーの等しい値を数えるということになります。 この浮動値を計算し、慎重に正規化し、ハッシュ マップを使用して頻度をカウントします。 

微妙な点はフローティング精度です。 double を直接比較するのは安全ではないため、十分な精度にスケーリングすることで小数部分を離散化します (たとえば、$10^{-12}$またはそれ以上）、それを整数キーに変換します。 This ensures stable grouping.

 ## アルゴリズムのチュートリアル

 1. ペアごとに$(a, b)$、計算する$x = b \cdot \ln(a)$。 これにより、べき乗が対数空間の一次式に変換され、オーバーフローや巨大な数が回避されます。 
2. 小数部分を抽出します。$x$として$f = x - \lfloor x \rfloor$。 これにより、無限小数表現の繰り返し構造を決定する部分が分離されます。 
3.変換$f$たとえば、固定の大きな定数を使用してスケーリングすることで、安定した整数キーに変換します。$10^{12}$、丸めます。 この手順により、数値精度を超えてのみ異なる値が同じバケットに集約されます。 
4. ハッシュ マップを使用して、すべてのペアにわたって各キーが出現する回数を数えます。 
5. 周波数ごとに$c$、 追加$c(c-1)/2$答えに。 これは、同じ分数署名を共有するすべてのインデックス ペアをカウントします。 

スケーリングが機能する理由は、小数部分が$[0,1)$、十分に大きな固定精度により、数学的に同一のすべての値の決定論的なグループ化が保証されます。 

### なぜ効果があるのか

 各ペア$(a,b)$実数にマッピングされる$b \ln a$、そして、同一の無限小数動作を生成するすべてのペアは、この対数値の同じ小数部分を共有する必要があります。 整数部分は乗法スケーリングにのみ寄与し、等価条件には影響を与えません。 したがって、元の問題の等価性は、単一の正規化された分数不変量の等価性になります。 その不変式の決定論的な離散化によってバケット化するため、有効な同値クラスはすべて 1 回だけカウントされ、表現可能な精度を超えて異なる場合を除き、2 つの異なるクラスがマージされることはありません。これは十分に高いスケーリングによって制御されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math
from collections import defaultdict

SCALE = 10**12

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        freq = defaultdict(int)

        for _ in range(n):
            a, b = map(int, input().split())
            x = b * math.log(a)
            f = x - math.floor(x)
            key = int(f * SCALE + 0.5)
            freq[key] += 1

        ans = 0
        for c in freq.values():
            ans += c * (c - 1) // 2

        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、各ペアを対数空間表現に変換し、小数部分を分離することに依存しています。 固定スケールを乗算すると、連続的な小数値が離散バケット インデックスに変わります。 丸めのステップは不可欠です。 これがないと、浮動小数点表現のノイズにより、同一の数学的値が別々のキーに分割されてしまいます。 

最後のカウント手順では、ペアの標準的な組み合わせ式を使用し、明示的なペアの列挙を回避します。

## テストケース```python
import sys, io
import math
from collections import defaultdict

SCALE = 10**12

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        freq = defaultdict(int)
        for _ in range(n):
            a, b = map(int, input().split())
            x = b * math.log(a)
            f = x - math.floor(x)
            key = int(f * SCALE + 0.5)
            freq[key] += 1
        ans = 0
        for c in freq.values():
            ans += c * (c - 1) // 2
        out.append(str(ans))
    return "\n".join(out)

# small no-collision case
assert solve("1\n3\n2 3\n5 2\n4 5\n") == "0"

# duplicate groups
assert solve("1\n4\n2 2\n4 1\n8 2\n16 1\n") == "2"

# all equal
assert solve("1\n3\n2 2\n2 2\n2 2\n") == "3"

# minimum case
assert solve("1\n1\n10 10\n") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 無関係な 3 つのペア | 0 | 偶発的な衝突はありません |
 | 2 つの重複したロググループ | 2 | グループ化の正確性 |
 | 同一のペア | 3 | 組み合わせを数える |
 | 単一要素 | 0 | 境界処理 |

 ## 特殊なケース

 エッジケースの 1 つは、すべてのペアが同一である場合です。たとえば、$(2,2)$何度も繰り返しました。 このアルゴリズムは、すべてのペアを同じ対数キーにマッピングし、次のサイズの単一の周波数バケットを生成します。$n$。 ペア数は次のようになります。$n(n-1)/2$、これは組み合わせ式によって正しく処理されます。 

もう 1 つのエッジ ケースは、浮動小数点の丸めにより小数部が非常に近い場合です。たとえば、深い精度レベルでのみ異なるペアなどです。 スケーリング ステップでは、これらを同じ整数キーに圧縮し、丸めによりグループを分割するのではなく、一貫したバケット割り当てを保証します。 

最後のエッジケースは次のような場合です$a = 1$。 その場合$1^b = 1$、 それで$b \ln 1 = 0$みんなのために$b$。 このようなすべてのペアはゼロにマッピングされ、すべてが単一の同値クラスに正しくグループ化され、そのサブセット内のペアの完全な二次カウントが生成されます。
