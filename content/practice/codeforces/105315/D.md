 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには文字列のリストがあり、最初の文字列と 2 番目の文字列を連結すると、結果の文字列が前後方向に同じように読み取られるように、個別のインデックスの順序付きペアをカウントしたいと考えています。 

出力は回文の作成や文字列の変更に関するものではありません。 これは純粋に、連結後に回文を形成する異なる単語の順序ペアがいくつあるかを数えるということです。 

この制約により、文字列の全長が 2 次になるものから直ちに遠ざけられます。 すべてのテスト ケースにおいて、文字列の長さの合計は 4 · 10^5 で制限されるため、文字列のペアごとに文字を繰り返し検査するソリューションは失敗します。 単純な O(n² · L) アプローチ (L は平均文字列長) では、最悪の場合、制限をはるかに超えて、およそ 10^10 文字の比較にまで悪化します。 

文字列が異なる役割で再利用できる場合、ペアは順序付けされており、インデックスは異なる必要があるため、微妙なエッジケースが発生します。 たとえば、すべての文字列が空の場合、「" + "" は回文であるため、順序付けられた個別のインデックスのペアはすべて有効です。 インデックスではなく文字列値に基づいて不用意に重複排除を行うと、過小評価されてしまいます。 

別の特殊なケースには、個別にすでに回文になっている文字列が含まれます。 単純な考えとしては、回文文字列を数えてそれらを任意に組み合わせるということがあるかもしれませんが、それは 2 つの文字列間の境界が重要であるという構造上の制約を見逃してしまいます。 たとえば、「ab」と「ba」は有効なペアを形成しますが、どちらも単独の回文ではありません。 

## アプローチ

 ブルートフォースソリューションでは、すべての順序付きペア (i, j) を試し、si と sj を連結し、結果が回文であるかどうかを確認します。 定義を直接検証するため、正確性は簡単です。 ただし、各回文チェックには O(|si| + |sj|) のコストがかかり、O(n²) 個のペアが存在します。 最悪の場合、これは O(n² · L) になります。n が 10^5 に達すると、文字列が平均的に短い場合でも、これは非常に遅すぎます。 

重要な点は、連結を構築する必要がないということです。 連結文字列 si + sj は、sj が si の逆に等しい場合、回文になりますが、より微妙な制約があり、完全な連結を逆にすると 2 つの部分が入れ替わるように境界を揃える必要があります。 これは、sj が si の逆でなければならず、反転した文字列の正確な一致以外に追加の構造は必要ないことを意味します。 

これにより、問題は、各文字列が出現する回数を数え、それをその逆の文字列と照合するだけになります。 唯一の問題は、異なるインデックスで複数回出現しない限り、文字列とそれ自体のペアを避けることです。 したがって、個別の文字列 x ごとに、その頻度を reverse(x) の頻度と一致させ、順序付きペアを二重にカウントしないように注意深く確認します。 

したがって、周波数マップを構築し、各文字列 x について、その反転形式 rx を検索できます。 寄与は、x が rx に等しいかどうかによって異なります。 

x != rx の場合、x のすべての出現は rx のすべての出現とペアになり、freq[x] · freq[rx] 順序ペアに寄与します。 これは慎重に反復すると両方向をカウントするため、順序付けされていない各ペアを 1 回のみカウントするか、順序付けを明示的に制御する必要があります。 

x == rx の場合、文字列自体が回文であり、別個の出現の順序付きペアが有効な連結に寄与し、freq[x] · (freq[x] - 1) になります。

 ## アルゴリズムのチュートリアル

1. テスト ケース内のすべての文字列を読み取り、文字列自体をキーとする頻度辞書を構築します。 ペアリング ロジックには個別の文字列値のみが重要となるため、これにより繰り返しの作業が圧縮されます。 
2. 個別の文字列 x ごとに、その反転バージョン rx を計算します。 連結全体にわたる回文構造により境界を越えて対称性が強制されるため、これが重要な唯一の変換です。 
3. x が反復順序で辞書編集上または構造的に rx より「小さい」場合、ペア (x, rx) の寄与を 1 回だけ計算します。 x の各出現は rx の各出現とペアになるため、寄与は freq[x] · freq[rx] になります。 
4. x が rx に等しい場合、つまり文字列自体が回文であることを意味し、freq[x] · (freq[x] - 1) を答えに追加します。 これは、同じ回文値バケット内の個別のインデックスの順序付きペアをすべてカウントします。 
5. 辞書順で x <= rx の場合のみ処理するなど、一貫した順序付けルールを適用して、逆ペアが二重にカウントされないようにします。 

### なぜ効果があるのか

 すべての有効な連結 si + sj は、その中心を中心に完全にミラーリングする必要があります。 この制約により、回文の後半が前半に反転するため、sj は si の逆になります。 したがって、問題は各文字列をその逆の文字列と一致させることに帰着します。 同一の文字列をグループ化すると、すべてのインデックス レベルのペアが正しくカウントされ、順序付けルールにより対称ペア間での二重カウントが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = input().split()

        freq = {}
        for s in arr:
            freq[s] = freq.get(s, 0) + 1

        ans = 0
        used = set()

        for s in freq:
            rs = s[::-1]

            if s in used:
                continue

            if s == rs:
                c = freq[s]
                ans += c * (c - 1)

            else:
                c1 = freq[s]
                c2 = freq.get(rs, 0)
                ans += c1 * c2

            used.add(s)
            used.add(rs)

        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、文字列の繰り返しによって繰り返し作業が発生しないように、入力を周波数マップに圧縮することから始まります。 反転操作は一意の文字列のレベルでのみ適用されるため、合計入力サイズの複雑さが線形に保たれます。 

の`used`set は、文字列とその逆の間で二重にカウントされることを防ぎます。 ペア (s、reverse(s)) が処理されると、両方がマークされ、後で対称性が再検討されないようにします。 

特別な場合`s == rs`は、同じグループ内の個別の出現の順序付きペアをすべてカウントすることにより、回文文字列を正しく処理します。 

よくある実装の落とし穴は、順序が重要であることを忘れていることです。(i, j) と (j, i) は、両方向が別々に考慮されない限り、別個のペアです。 式`c * (c - 1)`にはすでに両方向が含まれています。

 ## 特殊なケース

 次のような単一文字の繰り返し文字列の場合`["a", "a", "a"]`の場合、「a」はその逆に等しいため、アルゴリズムは自己回文分岐に入ります。 頻度は 3 なので、寄与率は 3 · 2 = 6 になります。これは、すべての順序付きインデックス ペア (i, j) (i ≠ j) に正確に対応します。 

次のような混合リバース チェーンの場合`["ab", "bc", "ba", "cb"]`、各文字列はその逆とのみペアになります。 このアルゴリズムでは、次の理由により各ペア グループが 1 回処理されることが保証されます。`used`すべてのクロスペアの組み合わせを正しく累積しながら、二重カウントを防止します。
