 ## 解決策
 ## 問題の理解

 0 から n までの番号が付けられたタイルの行が与えられ、猫はタイル 0 から始まります。 j が厳密に前にあり、k ステップを超えない限り、猫は任意のタイル i から任意のタイル j にジャンプできます。つまり、1 ≤ j − i ≤ k です。 質問は、猫がそのようなジャンプを繰り返した場合に、タイル n に到達するための明確な方法が何通り存在するかを尋ねます。 

各ウェイは 0 から始まり n で終わる一連の位置であり、各ステップは最大で k タイルずつ前方に進みます。 異なるシーケンスは、たとえ中間位置を共有していても、ジャンプの選択が異なる場合でも、異なる方法で考慮されます。 

入力には、それぞれが独立した複数のテスト ケースが含まれています。 各ペア (n, k) について、1e9 + 7 を法とする有効なジャンプ シーケンスの数を計算する必要があります。 

制約は大きく、テスト ケースごとの n は最大 1e6 であり、テスト ケース全体のすべての n の合計は最大 2e6 です。 これにより、O(k) 時間で各位置の遷移を最初から再計算するソリューションは即座に除外されます。これは、最悪の場合、k が大きくなり、総作業量が 1e12 操作を超える可能性があるためです。 

単純な動的プログラミング アプローチでは、タイル i に到達する方法の数として dp[i] を定義し、dp[i − 1] から dp[i − k] までを合計することによって dp[i] を計算します。 これは正しいですが、各状態で最大 k 個の加算が必要となり、テスト ケースごとに O(nk) が得られるため、遅すぎます。 

2 番目の微妙な問題は、k が大きい場合 (たとえば、k ≥ n) に発生します。 その場合、以前の位置はすべて i に直接遷移できるため、dp[i] は以前のすべての dp 値のプレフィックス合計になります。 k を反復処理する単純な実装では、構造が完全に単純化されたとしても、不必要な作業と TLE が実行されます。 

## アプローチ

 ブルートフォース動的プログラミングの解釈は簡単です。 各タイル i から、i + 1、i + 2、最大 i + k への可能なすべての次のジャンプを試み、寄与を蓄積します。 これが機能するのは、すべての有効なパスが短い有効なパスを拡張することによって一意に構築されているためです。そのため、すべての先行パスを合計すると、すべてのシーケンスが正確にカウントされます。 

非効率性は、重複する合計を再計算することに起因します。 dp[i] を計算するときは、dp[i + 1]、dp[i + 2] などにすでに使用されている同じ dp 値を繰り返し合計します。 連続するウィンドウ間の重複は、実行ウィンドウの合計を毎回再計算するのではなく維持することを示唆しています。 

重要な観察は、dp[i] が前の k 値のスライド範囲にのみ依存するということです。 この範囲合計を最初から再計算する代わりに、最後の k dp 値のローリング合計を維持します。 i − 1 から i に移動するとき、dp[i − 1] をウィンドウに追加し、dp[i − k − 1] が存在する場合は削除します。 これにより、各遷移が O(1) に減少し、DP 全体が線形時間に変わります。

 ## アルゴリズムのチュートリアル

 dp[i] をタイル i に到達する方法の数として定義します。 トランジションは、距離 k 内にあるすべての前のタイルから発生します。

1. ジャンプを行わずに原点から開始する方法が 1 つだけあるため、dp[0] = 1 を初期化します。 
2. dp[i − 1] + dp[i − 2] + ... + dp[i − k] を表す実行ウィンドウの合計を維持しますが、有効なインデックスに対してのみ維持します。 この合計は、1 回の追加ジャンプで現在位置に到達するすべての方法を表します。 
3. 1 から n までの各位置 i に対して、dp[i] を現在のウィンドウの合計に等しく設定します。 これが機能するのは、すべての有効な最後のジャンプが前の k 位置の 1 つから来ていなければならず、そのような各 dp 値が i への 1 つの拡張に寄与するためです。 
4. dp[i] を割り当てた後、dp[i] を追加してウィンドウ合計を更新します。これは、将来の状態に寄与する可能性があるためです。 
5. i ≥ k の場合、ウィンドウ合計から dp[i − k] を削除します。これは、dp[i − k] が将来の位置から距離 k 以内にないためです。 これにより、ウィンドウ合計が常に最後の k dp 値を正確に反映するという不変条件が維持されます。 

中心となる考え方は、各 dp[i] が 1 回だけ計算され、次の k 個の状態に寄与し、その後有効期限が切れるということです。 

### なぜ効果があるのか

 すべてのインデックス i で、ウィンドウの合計は、i − k ≤ j ≤ i − 1 となるタイル j に到達する方法の総数に等しくなります。 i で終わるすべての有効なパスは、そのような j の 1 つから来ていて、その後に j から i への 1 つのジャンプが続く必要があります。 dp[j] はすでに j に到達するすべての方法をカウントしているため、すべての有効な j を合計すると、最後のジャンプ起点に基づいてすべてのパスが互いに素なグループに分割されます。 これにより、パスが見逃されたり、二重にカウントされたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve_case(n, k):
    dp = [0] * (n + 1)
    dp[0] = 1

    window_sum = 1

    for i in range(1, n + 1):
        dp[i] = window_sum % MOD
        window_sum = (window_sum + dp[i]) % MOD

        if i >= k:
            window_sum = (window_sum - dp[i - k]) % MOD

    return dp[n]

def main():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        print(solve_case(n, k))

if __name__ == "__main__":
    main()
```実装はスライディング ウィンドウ DP に正確に従います。 dp 配列はわかりやすくするために保持されていますが、正確さを維持するために実際に必要なのは最後の k 値だけです。 window_sum 変数は、合計の繰り返しの再計算を回避する重要な最適化です。 

i ≥ k の場合の減算ステップは、ウィンドウが無制限に拡大するのを防ぎます。 これがないと、アルゴリズムはジャンプ起点として許可されなくなった位置からの寄与を誤って蓄積してしまいます。

 ## 特殊なケース

 k = 1 の場合、アルゴリズムは単一パス チェーンに縮退します。 n = 5 の場合、各 dp[i] は dp[i − 1] にのみ依存するため、ウィンドウの合計は常に dp[i − 1] と等しくなります。 dp[i] を追加し、すぐに dp[i − 1] を削除して、値の安定した伝播を残すため、更新ルールは引き続き機能します。 

k ≥ n の場合、すべての dp[i] は、dp[0] を含む以前のすべての dp 値の合計になります。 n = 3、k = 10 の場合、すべてのステップで i < k であるため、ウィンドウは何も削除しません。 ウィンドウの合計はすべての dp 値を累積し、前のタイルがすべて後のタイルに直接ジャンプできるという事実と一致する指数関数的な増加を生成します。
