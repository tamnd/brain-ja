 ## 解決策
 ## 問題の理解

 指定された開始ノードとターゲット ノードとともに、テスト ケースごとに有向または無向の重み付きグラフが与えられます。 ルートは、開始点とターゲットを接続する任意のエッジのシーケンスであり、頂点とエッジは、グラフ内で有効なウォークを形成している限り繰り返すことができます。 このようなルートの値は、そのルートに沿ったすべてのエッジの重みのビット単位の AND として定義されます。 タスクは、開始点からターゲットまでのすべての可能な有効なルートの中でこの値を最大化することです。 

重要な構造の詳細は、パス上でビット単位の AND がどのように動作するかです。 ルートに沿って使用されるエッジの重みのビットが 0 になると、そのビットはルート値全体で永久に失われます。 したがって、長いルートは最終値を制限するだけですが、より多くの上位ビットを保持するエッジに到達できるため、依然として有用である可能性があります。 

この制約は、パスを列挙できないことを意味します。 テスト ケースごとに最大 10^5 のノードと 3×10^5 のエッジがあるため、すべてのウォークやすべての単純なパスの探索に依存するソリューションは不可能です。 サブセットに対する最短パス形式の動的プログラミングさえも実現できません。 唯一の実行可能な方向は、ビットを独立して扱い、問題をエッジ フィルタリング下での到達可能性チェックの繰り返しに減らすことです。 

答えが単にある最短パスまたは任意の最短パスに沿った最小エッジ重みであると仮定すると、微妙な失敗例が現れます。 たとえば、s から e への直接パスが低重みのエッジで存在するが、サイクルが長くなることで高重みのエッジのみを使用した別のパスが可能になるグラフを考えてみましょう。 貪欲な最短パス手法では、より適切な AND を保持するルートが存在する場合でも、直接エッジが誤って選択され、より小さい AND 値が生成されます。 

もう 1 つの落とし穴は、パス長またはエッジの重みが単調であると仮定することです。 許可されるビットに制約を課さない限り、エッジを追加しても、必ずしも予測可能な方法で AND が減少するとは限りません。 これが、問題が古典的な最短パスではなく、自然にフィルタリングと接続の問題に変わる理由です。 

## アプローチ

 ブルートフォースのアイデアは、s から e までのすべての可能なウォークを考慮し、それぞれに沿って重みのビットごとの AND を計算することです。 これは、すべての有効なルートを明示的に評価するため、正しいです。 ただし、サイクルは任意に何度も横断できるため、歩行の数は指数関数的に増加します。 単純なパスに制限しても役に立ちません。密なグラフでパスを列挙すると、最悪の場合でも依然として指数関数的になるからです。 

重要な観察は、視点を反転することです。 パスを構築する代わりに、最終的な答えにどのビットを残しておきたいかを決定します。 特定のビット マスク X が達成可能であると推測します。 これは、s から e までのパスが存在し、そのパス上のすべてのエッジに X のすべてのビットが設定されていることを意味します。 言い換えれば、パス上のすべてのエッジは、ビットのサブセットとして X を含む重みを持つエッジをフィルタリングすることによって形成されたサブグラフに属します。 したがって、実現可能性はフィルタリングされたグラフでの接続チェックに帰着します。 

これにより、最上位ビットから下に向かって貪欲なビット構築が行われます。 答え = 0 から始めます。最上位から最下位までの各ビットについて、それを設定し、重みに現在必要なビットがすべて含まれているエッジのみを使用して s と e がまだ接続されているかどうかをテストします。 接続が維持される場合はビットを保持します。 それ以外の場合は破棄します。 

接続テストは、フィルタリングされたエッジ上で DFS、BFS、または DSU を使用して実行できます。 このチェックを最大 60 ビットまで繰り返すため、全体的な複雑さは管理可能なままです。

 ## アルゴリズムのチュートリアル

 私たちは、高いものから低いものまで少しずつ構築する候補の回答マスクを維持します。

1. 応答マスクを 0 に初期化します。これは、ビット制約がまだ適用されていないため、最初はすべてのパスを許可していることを表します。 
2. 59 から 0 までのビットを繰り返します。各ビットが最終的な答えに含められるかどうかを検討します。 
3. 与えられたビット b に対して、現在の答えにこのビットを加えたものに等しいテスト マスクを一時的に構築します。 
4. 重みにテスト マスク内のすべてのビットが含まれるエッジのみで構成されるサブグラフを構築またはトラバースします。 このフィルタリングにより、このグラフで見つかったすべてのパスがビットごとの AND でマスク内のすべてのビットを保持することが保証されます。 
5. から接続検索 (通常は BFS または DFS) を実行します。 e に到達できれば、テスト マスク内のすべてのビットを保持する有効なルートが存在するため、このビットを応答に永続的に設定します。 
6. e に到達できない場合は、このビットを破棄し、前の応答を変更しないでください。 

この貪欲な選択が有効である理由は、バイナリ表現では上位ビットが下位ビットよりも優先されるためです。 上位ビットが実行不可能であることが判明すると、その後の操作ではそれを復元できないため、安全に破棄します。 逆に、ビットが実行可能な場合、下位ビットは制約をさらに強化するだけであるため、ビットを保持しても後で下位ビットを追加する可能性が妨げられることはありません。 

### なぜ効果があるのか

 どのステップでも、現在のマスクは、すでに選択されているすべてのビットとすべて互換性のあるエッジのセットを表します。 接続性チェックにより、この制約されたサブグラフに完全に含まれるパスが少なくとも 1 つ存在することが確認されます。 したがって、不変条件は、ビット b を処理した後、重みに選択されたすべてのビットが含まれるエッジのみを使用する s から e へのパスが存在するということです。 ビットの決定はグラフを制限するだけであるため、実現可能性が確認されると、以前に受け入れられたすべてのビットと一貫性が保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, s, e = map(int, input().split())
        
        edges = []
        adj_all = [[] for _ in range(n + 1)]
        
        for _ in range(m):
            a, b, w = map(int, input().split())
            edges.append((a, b, w))
            adj_all[a].append((b, w))
            adj_all[b].append((a, w))
        
        def can(mask):
            from collections import deque
            vis = [False] * (n + 1)
            dq = deque([s])
            vis[s] = True
            
            while dq:
                u = dq.popleft()
                if u == e:
                    return True
                for v, w in adj_all[u]:
                    if not vis[v] and (w & mask) == mask:
                        vis[v] = True
                        dq.append(v)
            return False
        
        ans = 0
        for bit in range(59, -1, -1):
            if can(ans | (1 << bit)):
                ans |= (1 << bit)
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、完全な隣接リストが保持され、ビット トライアルごとに BFS が実行されます。 キーチェック`(w & mask) == mask`使用されるすべてのエッジが、現在応答に必要なすべてのビットを保持することを強制します。 

BFS はビットごとに再起動されますが、ビットに対する制約が小さく、グラフ サイズが適度であるため、これは許容可能です。 制約が追加されるたびに到達可能性が変化するため、正確性は異なるマスク間で訪問済みの状態を再利用しないことに依存します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(60 × (n + m)) | 各ビットはグラフ上で 1 つの BFS をトリガーし、すべてのエッジを 1 回スキャンします。 
| スペース | O(n + m) | 隣接リストと BFS 訪問済み配列 |

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    def solve():
        input = sys.stdin.readline
        t = int(input())
        out = []
        for _ in range(t):
            n, m, s, e = map(int, input().split())
            adj = [[] for _ in range(n + 1)]
            for _ in range(m):
                a, b, w = map(int, input().split())
                adj[a].append((b, w))
                adj[b].append((a, w))
            
            from collections import deque
            
            def can(mask):
                vis = [False] * (n + 1)
                dq = deque([s])
                vis[s] = True
                while dq:
                    u = dq.popleft()
                    if u == e:
                        return True
                    for v, w in adj[u]:
                        if not vis[v] and (w & mask) == mask:
                            vis[v] = True
                            dq.append(v)
                return False
            
            ans = 0
            for bit in range(59, -1, -1):
                if can(ans | (1 << bit)):
                    ans |= (1 << bit)
            out.append(str(ans))
        return "\n".join(out)
    
    return solve()

 ## 特殊なケース

 1 つのエッジ ケースは、接続を維持するために使用可能なパスのみが上位ビットを緩和する必要がある場合に発生します。 s が低重みのブリッジを介して e に接続されているが、高重みのエッジが e から切り離されたサイクルを形成しているグラフを想定します。 視覚的に長いパスが完全なグラフに存在する場合でも、制約付きマスクの下の BFS はターゲットに到達できないため、アルゴリズムは上位ビットを正しく拒否します。 

もう 1 つのケースは、複数のコンポーネントが存在し、接続が正確なマスクに依存する場合です。 たとえば、エッジは s をマスク X の下の中央コンポーネントに接続する可能性がありますが、 e はエッジの異なるサブセットの下にのみ接続されます。 BFS はマスクごとに到達可能性を新たに再計算し、ビット トライアル間で古い到達可能性の仮定が漏れないようにします。
