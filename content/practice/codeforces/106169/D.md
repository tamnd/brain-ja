 ## 問題の理解

 マップは長方形の島のグリッドです。 セルは、動きを妨げる水、空の土地セル、または大文字で表される固有のランドマークを含むセルのいずれかになります。 船長は、未知の出発点から宝物に至る一連の動きを正確に覚えています。 地図の欠落部分は開始位置を隠しているだけであり、船長は開始位置がランドマーク セルの 1 つであることを知っています。 

すべてのランドマークについて、それを開始セルとして使用することで一連の移動全体を完了できるかどうかを判断する必要があります。 歩行全体を通じて、訪問したすべてのセルが陸地になければならず、すべての有効なランドマークがアルファベット順に印刷されなければなりません。 どのランドマークも出発点にならない場合、答えは次のとおりです。`no solution`。 

グリッドの寸法は最大 1000 x 1000 であるため、最大 100 万個のセルが存在できます。 命令の数は 100000 に達する可能性があります。すべてのグリッド セルを試してパス全体をシミュレートするソリューションには、最大 100000000000 回の操作が必要になりますが、これは通常の制限時間をはるかに超えています。 可能な開始位置の数がはるかに少ない、つまり可能な文字が 26 個しかないという事実を利用する必要があります。 

指示は一方向に大きく進む可能性があり、よくある間違いは最終目的地のみを確認することです。 たとえば、パスは陸地で始まり、終わりますが、途中で水を横切ることができます。 

例：```

```正しい出力は次のとおりです。```

```始まりは`A`南に 2 回移動した後、パスは水である行 3、列 2 に入ろうとします。 最終位置のみをチェックするソリューションでは、完全な移動後に最終セルに到達できるため、開始が誤って受け入れられます。 

もう 1 つのエッジ ケースは、パスの正味変位がゼロであるにもかかわらずブロックされたセルを横切る場合です。

## アプローチ

 直接的なブルート フォース ソリューションでは、マップ内の考えられるすべての開始セルを検査します。 各セルについて、すべての命令が再生され、パスが水に入ると停止します。 これは、問題で説明されている状態を正確にチェックするため、正しいです。 ただし、グリッドには最大 100 万個のセルを含めることができ、命令リストには 100,000 の手を含めることができます。 最悪の場合、これでは約 100000000000 回の移動チェックが発生し、遅すぎます。 

重要な観察は、キャプテンはランドマークセルからのみ開始できるということです。 すべてのランドマークには異なる大文字があるため、マップにはそのようなセルが最大 26 個含まれます。 すべてのセルをテストするのではなく、これらの少数の候補をテストするだけで済みます。 

ランドマークごとに、パスを 1 回シミュレートします。 中間位置が島の外にある場合、または水が含まれている場合、そのランドマークは無効になります。 それ以外の場合、それは有効な答えです。 シミュレーションの数は最大 26 であるため、合計演算数は命令数の約 26 倍にすぎません。 

ブルートフォースは、パスをシミュレートすることで開始位置が機能するかどうかを正確に識別するため機能しますが、何百万もの不可能な開始位置で労力を無駄にします。 ランドマークのみが開始点になり得るという観察により、検索スペースがグリッド全体から一定サイズのセットに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm・k) | O(nm) | 遅すぎる |
 | 最適 | O(26 · k + nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを読み取り、すべてのランドマークの位置を保存します。 シミュレートされたすべての動きは、目的地のセルが水であるかどうかを知る必要があるため、グリッド自体は維持されます。 
2. すべての命令を行と列の変更に変換します。 たとえば、北に移動すると行が 1 つ減り、東に移動すると列が 1 つ増加します。 この形で動きを維持するとシミュレーションが簡単になります。 
3. 保存されたランドマーク位置ごとに、そのセルからシミュレーションを開始します。 失われた開始点は照準器でなければならないため、現在位置はランドマーク座標に初期化されます。 
4. 指示を 1 つずつ適用します。 各命令の後で、現在の行と列を更新し、新しいセルを確認します。 位置がグリッドの外側にある場合、またはグリッドが含まれている場合`#`、このランドマークを無効としてマークし、チェックを停止します。 
5. すべての指示が水に当たらずに終了した場合は、この目印となる文字を答えに追加します。 ランドマークは後でアルファベット順にチェックされるため、出力形式は満たされます。 
6. シミュレーションでランドマークが生き残らない場合は、印刷します。`no solution`。 

機能する理由: 固定ランドマークの場合、アルゴリズムは、船長がそこから出発するときに訪問するであろう一連の位置とまったく同じに従います。 ランドマークは、訪問したすべての位置が有効な島セルである場合にのみ受け入れられます。 したがって、受け入れられたすべてのランドマークが開始点となり得ますが、拒否されたすべてのランドマークは失敗します。これは、実際のパスがあるステップで水にぶつかる可能性があるためです。 考えられるすべてのランドマークをチェックすると、有効なスタートの完全なセットがカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    grid = []
    sights = []

    for i in range(n):
        row = input().strip()
        grid.append(row)
        for j, ch in enumerate(row):
            if 'A' <= ch <= 'Z':
                sights.append((ch, i, j))

    k = int(input())
    moves = []

    for _ in range(k):
        d, length = input().split()
        length = int(length)
        if d == 'N':
            moves.append((-length, 0))
        elif d == 'S':
            moves.append((length, 0))
        elif d == 'W':
            moves.append((0, -length))
        else:
            moves.append((0, length))

    ans = []

    for ch, sr, sc in sights:
        r, c = sr, sc
        ok = True

        for dr, dc in moves:
            r += dr
            c += dc

            if r < 0 or r >= n or c < 0 or c >= m or grid[r][c] == '#':
                ok = False
                break

        if ok:
            ans.append(ch)

    ans.sort()

    if ans:
        print(''.join(ans))
    else:
        print("no solution")

if __name__ == "__main__":
    solve()
```グリッドは文字列として保存されるため、セルへのアクセスは一定時間になります。 リスト`sights`可能な開始位置のみが含まれるため、シミュレーション数は少なく抑えられます。 

各命令はすぐに行と列のオフセットに変換されます。 このコードは、単一セルの移動を何度も繰り返すのではなく、移動の長さをオフセット内に維持するため、不必要な作業が回避されます。 のような動き`N 1000`行を次のように変更します`-1000`この問題では移動がセル間の直線に沿って行われることが保証されるため、目的地のみが重要となります。 単一の命令が水を飛び越える場合、セグメント全体がクリアされている必要があるため、チェック対象の宛先セルだけでは十分ではありません。 入力移動長は最大 1000 であるため、シミュレーションでは中間セルもチェックする必要があります。 

上記で提供されている実装は、プレフィックス ディスプレイスメントを保存し、範囲チェックを使用することでさらに最適化できますが、制約によりすでに直接ランドマーク シミュレーションで十分です。 ランドマークは最大でも 26 個あるため、合計の歩行距離が制限されている場合にのみ、各命令をその長さだけ拡張しても十分に小さくなります。 代わりに、コードは方向セグメントがそのセルに沿って検証される必要があるというより強力な観察を使用します。 以下の実装には、欠落している検証が含まれています。```python

        elif d == 'S':

```2 番目のバージョンが最終実装です。 内側のループは、移動命令が通過するすべての四角形をチェックします。移動はブロックされたセルを通過できるため、これが必要です。 合計歩行距離は、命令の数と 1 つの命令の最大長の積によって制限され、ランドマークの数のみが乗算されます。 指定された制限により、これは許容範囲内にとどまります。 

重要な境界条件は、新しいセルに移動した直後のチェックです。 開始ランドマーク自体は土地であることが保証されているため、別途検証する必要はありません。 また、アクセスする前に行と列のインデックスがチェックされます。`grid[r][c]`無効なメモリアクセスを避けるため。

1

境界近くのランドマークの場合、グリッドにインデックスを付ける前に、すべての動きがグリッドの境界に対してチェックされます。 例えば：```

結果が異なるいくつかのランドマークについて、アルゴリズムはそれらを個別にテストします。 すべてのシミュレーションはランドマーク自体の座標から開始されるため、1 つの無効なランドマークが他のランドマークに影響を与えることはありません。
