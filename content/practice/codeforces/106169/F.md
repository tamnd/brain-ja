 ## 解決策
 ## 問題の理解

 この問題では、2 つのイベントが十分に近い時間で発生し、反対の符号を持つイベントのペアを数えるよう求められます。 各レコードにはタイムスタンプと符号が付けられます。`+`そして`-`二つの異なる側面を表現します。 タイムスタンプが最大で異なる場合、ペアは有効です。`d`そして2つの記号は異なります。 イベントはすでに時間順に並べ替えられているため、タスクはそのようなすべての十字記号のペアを効率的にカウントすることです。 

入力サイズは以下に達します`3 * 10^5`これにより、イベントのすべてのペアのチェックが即座に除外されます。 直接比較すると次のように実行されます。`n * (n - 1) / 2`小切手、つまり約`4.5 * 10^10`最大サイズでの操作。 非常に最適化された実装であっても、一般的なコンテストの制限時間内にそれを完了することはできません。 タイムスタンプがソートされているという事実を利用する必要があります。 

いくつかの詳細により、それ以外は合理的な解決策であっても不正確な答えが生じます。 タイムスタンプが等しいということは、差がゼロになる可能性があり、条件が同じ時刻のペアを許可するため、よくある罠です。 例えば：```
3 0
5 5 5
+-+
```答えは`2`なぜなら二人は`+`イベントは`-`同じタイムスタンプのイベント。 厳密に小さい時間または大きい時間のみを検索するソリューションでは、それらの時間を見逃してしまいます。 

もう 1 つの間違いは、同じタイムスタンプの複数のイベントが別個のイベントであることを忘れていることです。 例えば：```
4 1
1 1 2 2
++--
```答えは`4`。 毎`+`時に`1`すべてに一致します`-`時に`2`。 異なるタイムスタンプのみをカウントすると、`1`、それは間違いです。 

最後の厄介なケースは距離の境界です`d`。 例えば：```
2 3
10 13
+-
```答えは`1`距離がちょうどいいから`3`。 代わりに厳密な比較を使用する`<= d`有効なペアが失われます。 

## アプローチ

 簡単なアプローチは、すべてのポジティブなイベントとすべてのネガティブなイベントを比較することです。 各ペアについて、時間間の絶対的な差を計算し、最大でも 1 を加算します。`d`。 これは有効なペアの定義に直接従うため、推論するのは簡単です。 

問題は、比較の数が二次関数的に増加することです。 と`n = 300000`、可能なペアの数はおおよそ次のとおりです。`45000000000`, これは私たちが処理できる範囲をはるかに超えています。 

有用な観察は、ソートされたタイムスタンプから得られます。 以前のすべてのイベントが後のイベントと一致するかどうかを確認する代わりに、現在のイベントにまだ十分近い以前のイベントのセットを維持できます。 左から右に移動すると、以前のイベントはすべて、許可された時間枠内にとどまるか、古すぎて二度と一致できなくなります。 

現在のすべてのイベントについて、少なくとも反対の符号とタイムスタンプを持つ過去のイベントが何件あるかを知る必要があります。`current_time - d`。 入力はソートされているため、移動ポインターを使用して期限切れのイベントを削除できます。 必要なのはアクティブな数だけです`+`そして`-`個々の立場ではなく、出来事。 

現在のイベントのとき`+`、すべてアクティブな有効なペアを形成します。`-`イベント。 そうなったとき`-`、すべてアクティブな有効なペアを形成します。`+`イベント。 カウント後、現在のイベントをアクティブ ウィンドウに挿入し、将来のイベントで使用できるようにします。

 ## アルゴリズムのチュートリアル

 1. すべてのイベントを次のように保存します`(time, sign)`ペア。 イベントはすでに並べ替えられているため、再度並べ替えることなく、指定された順序で処理できます。 まだ有効な時間枠内にある最初のイベントを表す左ポインタを保持します。 
2. アクティブなイベントの数を符号で区切って維持します。 アクティブなウィンドウには、タイムスタンプが少なくとも次の以前のイベントが正確に含まれています。`current_time - d`。 
3. 現在のイベントを処理する前に、左側のイベントが古すぎる間に左ポインタを前方に移動します。 将来のイベントと有効なペアを形成できなくなるため、アクティブなカウントからその符号を削除します。 
4. 現在のイベントの兆候を見てください。 そうであれば`+`、アクティブな数を追加します`-`答えへの出来事。 そうであれば`-`、アクティブな数を追加します`+`代わりにイベント。 これらは、正反対の符号と有効な距離を持つ前のイベントです。 
5. 対応する符号の数を増やして、現在のイベントをアクティブなウィンドウに挿入します。 後のイベントに一致する可能性があるため、利用可能な状態にしておく必要があります。 

機能する理由: スキャンのすべての時点で、アクティブ ウィンドウには、現在および将来のイベントと有効なペアを作成できる以前のイベントのみがすべて含まれます。 すべてのペアは、ペア内の後のイベントが処理されるときに 1 回だけカウントされます。 アクティブなウィンドウから逆符号のイベントのみを追加するため、カウントされたすべてのペアは符号条件と時間条件を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    t = list(map(int, input().split()))
    s = input().strip()

    ans = 0
    left = 0
    plus = 0
    minus = 0

    for i in range(n):
        while left < i and t[left] < t[i] - d:
            if s[left] == '+':
                plus -= 1
            else:
                minus -= 1
            left += 1

        if s[i] == '+':
            ans += minus
            plus += 1
        else:
            ans += plus
            minus += 1

    print(ans)

if __name__ == "__main__":
    solve()
```メインループは、ウォークスルーからのスライディング ウィンドウを実装します。 ポインタ`left`決して後戻りすることはないため、すべてのイベントは最大 1 回削除されます。 これにより、作業全体が直線的に保たれます。 

削除条件は、`t[left] < t[i] - d`それよりも`<=`タイムスタンプに正確な違いがあるため`d`はまだ有効です。 現在のイベントは、保存されているカウントに追加される前にカウントされるため、イベントがそれ自体とペアになるのを防ぎます。 

答えはすべてのペアの数と同じくらい大きくなる可能性があるため、ここでは Python の整数で十分です。`4.5 * 10^10`。

 ## 特殊なケース

 タイムスタンプが等しい場合:```
3 0
5 5 5
+-+
```最初のイベントがアクティブなイベントに追加されます。`+`カウント。 2 番目のイベントではアクティブなイベントが 1 つ表示されます`+`したがって、有効な 1 つが追加されます`-`ペアになり、`-`カウント。 3 番目のイベントでは 1 つがアクティブになります`-`、別のペアを追加します。 結果は`2`これは、まったく同じ時刻のイベントのみがペアになるという事実と一致します。 

多数のイベントを含む重複したタイムスタンプの場合:```
4 1
1 1 2 2
++--
```両方のイベントの時間`1`2 つのイベントを同時に処理するときにアクティブなままにする`2`、それらの違いはまさに`1`。 それぞれのネガティブなイベントは 2 つのポジティブなイベントをカウントします。`4`合計ペア数。 このアルゴリズムは、一意のタイムスタンプではなくイベントの数を保存するため、多重度を処理します。 

境界条件の場合:```
2 3
10 13
+-
```最初のイベントはウィンドウ内に残ります。`10 < 13 - 3`は誤りです。 2 番目のイベントは、1 つの反対符号のイベントを検出し、それを答えに追加します。 結果は`1`、包括的な比較が正しく処理されることを証明します。
