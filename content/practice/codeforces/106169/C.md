 ## 解決策
 ## 問題の理解

 1 から 2 までの範囲の整数をカウントする必要があります。`n`という2つの条件を満たすもの。 数自体は奇数でなければならず、その数が持つ正の約数の量は奇数の素数でなければなりません。 入力には上限のみが含まれます`n`、出力はそれを超えない有効な整数の数です。 

主要な制約はサイズの中に隠されています。`n`。 値は次のように大きくできます。`11^13`、これは、以下のすべての整数をチェックするには大きすぎます。`n`。 リニアスキャンでも数兆回の演算が必要になります。 必要な約数の数を含む数値の数学的構造を活用する必要があります。 

いくつかの特殊なケースは見落とされがちです。 番号`1`約数は 1 つありますが、1 つは素数ではないため、決して数えるべきではありません。 入力の場合:```
1
```答えは次のとおりです。```
0
```除数の数が奇数かどうかだけをチェックする直接的なアプローチでは、除数の数が誤って含まれてしまいます。 

もう 1 つの罠は、素数自体には約数の素数がありますが、約数の数は奇数でなければならないということです。 例えば：```
5
```約数が 2 つあり、`1`そして`5`, したがって、それは無効です。 答えは次のとおりです。```
0
```素数値のみを探すソリューションはここでは失敗します。 

最後の境界ケースは、必要な形式ではない完全な正方形です。 例えば：```
81
```は正方形ですが、`5`約数。 以来`5`は素数であり、有効であり、カウントされる必要があります。 対照的に：```
45
```は正方形ではないため、奇数の約数を持つことはできません。 有用な特性は、単に奇数か素数であるということではなく、正確な因数分解パターンです。 

## アプローチ

 強引なアイデアは、次のすべての奇数を反復処理することです。`1`に`n`、その約数の数を計算し、その数が素数かどうかを確認します。 数値の約数は、その平方根までの約数をテストすることでわかります。 これは正しいです。なぜなら、すべての数値には有限の約数があり、約数の数によって条件を満たすかどうかが決まるからです。 ただし、範囲は約`1.6 * 10^13`, そのため、候補者を訪問することさえ不可能です。 最悪の場合は、合理的な運用限界をはるかに超えています。 

主な観察は、除数の公式から得られます。 数値に素因数分解がある場合:```
x = p1^a1 * p2^a2 * ... * pk^ak
```その場合、約数の数は次のようになります。```
(a1 + 1) * (a2 + 1) * ... * (ak + 1)
```この積は、すべての指数が偶数の場合にのみ奇数になります。 つまり、数値自体は完全な平方でなければなりません。 数値も奇数でなければならないため、平方根も奇数でなければなりません。 

平方根を次のようにします。```
m = p1^b1 * p2^b2 * ... * pk^bk
```それから：```
x = m^2
```そして、除数の数は次のようになります。```
(2b1 + 1) * (2b2 + 1) * ... * (2bk + 1)
```この製品が最高であるためには、要因は 1 つだけです。 それ以外の場合は、1 より大きい 2 つの数値の積になります。 したがって`m`単一の奇数素数の累乗でなければなりません。```
m = p^a
```と：```
2a + 1
```プライムであること。 

これで、問題は巨大な値のチェックからすべての有効なルートの生成に減りました。`m`を超えない`sqrt(n)`。 考えられる最大の根は約`3.3 * 10^6`, したがって、ふるいは簡単に十分に速いです。 パワーは急速に増大するため、可能な指数も非常に小さくなります。

 ## アルゴリズムのチュートリアル

 1. コンピューティング`limit = floor(sqrt(n))`。 有効な数値はすべて平方であるため、その平方根はこの値を超えることはできません。 
2. 以下のすべての素数を生成します。`limit`エラトステネスのふるいを使って。 元の数は奇数でなければならないため、奇数の素数のみが必要です。 
3. 指数のリストを生成する`a`どこ`2a + 1`プライムです。 これらは、有効なルートに現れることができる唯一の指数です。 
4. 奇数の素数ごとに`p`そしてすべての有効な指数`a`、計算する`p^a`。 値が最大の場合`limit`の場合、その二乗は有効な数値なので、それを答えに追加します。 
5. 現在の電力が より大きくなったら、乗算を停止します。`limit`なぜなら、より大きな権力は決して貢献できないからです。 

これが機能する理由は、すべての有効な数値が一意の平方根を持つためです。 因数分解の引数は、根が素数条件を満たす指数まで累乗された正確に 1 つの素数でなければならないことを証明します。 生成プロセスではそのようなルートがすべて列挙されるため、有効な値が失われることはありません。 異なるルートは異なる正方形を生成するため、重複したカウントは発生しません。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)

    limit = math.isqrt(n)

    is_prime = bytearray(b'\x01') * (limit + 1)
    if limit >= 0:
        is_prime[0] = 0
    if limit >= 1:
        is_prime[1] = 0

    i = 2
    while i * i <= limit:
        if is_prime[i]:
            start = i * i
            is_prime[start:limit + 1:i] = b'\x00' * (((limit - start) // i) + 1)
        i += 1

    exponents = []
    for a in range(1, 64):
        if 2 * a + 1 <= limit + 10 and is_prime[2 * a + 1]:
            exponents.append(a)

    ans = 0
    for p in range(3, limit + 1, 2):
        if not is_prime[p]:
            continue
        power = p
        for a in range(1, max(exponents, default=0) + 1):
            if a > 1:
                if power > limit // p:
                    break
                power *= p
            if a in exponents:
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず次の平方根までの素数テーブルを構築します。`n`。 すべての候補は元の値ではなく平方根から生成されるため、これで十分です。 

指数リストには値のみが含まれます。`2a + 1`プライムです。 ループは指数 1 から始まります。`a = 0`数字を表すでしょう`1`、これは無効です。 

コードは、素数の基数ごとに、根の制限内に留まりながら、その基数を繰り返し乗算します。 乗算前の除算チェックにより、オーバーフローが発生する可能性のある言語で値が Python の整数の範囲を超えることがなくなり、不必要な作業も回避されます。 

最終的な数は有効なルートの数です。 二乗の代わりに根を数えると、二乗演算が必要ないため、大規模な算術演算が回避されます。

 ## 特殊なケース

 のために`1`の場合、平方根は 1 であり、生成された素数パワーがそれを生成できないため、アルゴリズムはゼロを返します。 これにより、1 の単一の約数を誤って素数として数えることを回避できます。 

のために`5`、平方根の制限は 2 であるため、奇数の素数根を生成することはありません。 このアルゴリズムでは素数自体は決して考慮されませんが、数値の素数性は無関係であるため、これは正しいことです。 

のために`81`、アルゴリズムはルートを生成します`9`。 根は`3^2`、指数チェックでは次のようになります。`2 * 2 + 1 = 5`、これは素数なので、平方`81`カウントされます。 これは、正方形条件だけをチェックするだけでは十分ではない理由を示しています。
