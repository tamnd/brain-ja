 ## 解決策
 ## 問題の理解

 秘密の単語とテキスト文字列の辞書が与えられます。 テキストに小文字と特殊文字が含まれています`?`。 

あ`?`任意の小文字を表すことができます。 このタスクは、テキスト全体を辞書の単語に分割できる方法が何通りあるかを数えることです。 

辞書の単語は、長さが同じで、すべての位置が次の条件のいずれかを満たしている場合に、テキストのセグメントと一致します。 

- テキスト文字は単語文字と同じです。 
- テキスト文字は`?`、その単語の文字を表すことができることを意味します。 

各辞書の単語は何度でも使用できます。 テキストのすべての文字は、選択した 1 つの単語に正確に属している必要があります。 有効な分解の剰余数が必要です`10^9 + 7`。 

制約は小さいですが、非常に示唆的です。 単語は最大 100 個、各単語の長さは最大 10、テキストの長さは最大 100 です。`O(|T| * n * maxLen)`完全に安全です。 平`100 * 100 * 10 = 100000`キャラクターの比較はほんのわずかです。 

主な微妙な点は、`?`一致する単語が 1 つだけ作成されるわけではありません。 複数の異なる辞書の単語と一致する可能性があり、一致するすべての選択肢が個別に答えに寄与します。 

最初のサンプルを考えてみましょう。```
Words: a, b, c, d, ab, bc, cd
Text: ab?d
```3 番目の文字は次のように動作できます。`a`、`b`、`c`、 または`d`、いくつかの異なる分解が生成されます。 答えは4ではなく11です。 

もう 1 つの簡単な間違いは、同じ長さの異なる単語が同じ部分文字列に一致する可能性があることを忘れていることです。 

例：```
Words:
ab
ac

Text:
a?
```どちらの言葉も一致します。 答えは次のとおりです。```
2
```位置が到達可能かどうかだけを記録するブール型 DP は、誤って 1 を返します。 

3 番目の特殊なケースは、テキスト全体が疑問符で構成されている場合です。 

例：```
Words:
a
b

Text:
??
```最初の位置には 2 つの選択肢があり、2 番目の位置には 2 つの選択肢があるため、答えは次のようになります。```
4
```これは公式サンプルの 1 つです。 

## アプローチ

 最も直接的なアイデアは、再帰的バックトラッキングです。 テキストの先頭から始めて、現在の位置に一致する辞書の単語をすべて試し、文字列の残りの部分を再帰的に処理します。 正常に完了するたびに、答えが 1 つ得られます。 

すべての有効な分解が再帰ツリー内の 1 つのパスに正確に対応するため、このアプローチは正しいです。 問題は、同じサフィックスが何度も再計算されることです。 最悪の場合、テキストがいっぱいになるなど、`?`文字と一致する単語が多数あると、再帰状態の数は指数関数的に増加します。 

繰り返しの作業は動的プログラミングを示唆します。 

させて`dp[i]`位置の前で終わるプレフィックスを分解する方法の数を示します`i`。 次に、一致するすべての単語が、前の位置から後の位置への遷移を与えます。 

ある長さの単語を想定します`L`位置で終わる部分文字列と一致します`i`。 その後、その単語の前にある接頭辞の有効な分解はすべて、この単語によって拡張できます。 これにより、次のようになります。```
dp[i] += dp[i - L]
```残っている唯一のタスクは、単語がテキストセグメントと一致するかどうかを効率的にチェックすることです。 単語の長さは最大 10 なので、単純な文字ごとの比較はすでに十分に高速です。 

ブルートフォースは分解を直接探索します。 動的プログラミング ソリューションは、すべてのプレフィックスのすべての分解を 1 回カウントし、それらの結果を再利用します。

 ## アルゴリズムのチュートリアル

 1. 辞書の単語をすべて読みます。 
2. しましょう`m`テキストの長さを指定して配列を作成します`dp`長さの`m + 1`。 
3.セット`dp[0] = 1`。 

これは空のプレフィックスを表します。 何も分解しない方法は 1 つだけです。 
4. ポジションごとに`i`から`0`に`m - 1`、すべての辞書の単語を調べます。 
5. 現在の単語に長さを持たせる`L`。 

もし`i + L > m`、単語をその位置で開始することはできません`i`なので飛ばしてください。 
6. 単語とテキストセグメントを比較します`T[i : i + L]`。 

あらゆるポジションについて`j`、どちらかの場合に一致は成功します。`T[i + j] == '?'`または`T[i + j] == word[j]`。 
7. 単語全体が一致する場合は、次を追加します。```
dp[i + L] += dp[i]
```そして結果のモジュロを取得します`10^9 + 7`。 

各分解到達位置`i`この一致する単語で拡張できます。 
8. すべての位置と単語を処理した後、出力します`dp[m]`。 

### なぜ効果があるのか

 不変条件とは、`dp[i]`常に最初の有効な分解の数と等しくなります。`i`テキストの文字。 

空のプレフィックスには 1 つの分解しかないため、最初はこれが当てはまります。 

単語がその位置から始まると一致するとき`i`、すべての分解は次のようにカウントされます。`dp[i]`単語によって拡張でき、長さの分解が生成されます。`i + L`。 トランジションはまさにこれらの新しい分解を追加するものであり、それ以外は何も追加しません。 

すべての有効な分解には固有の最後の単語があります。 最後の単語が処理されると、その前の接頭辞までの分解が 1 回だけカウントされます。 すべての分解は 1 回生成され、生成されたすべての分解は有効であるため、`dp[m]`望ましい答えと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

n = int(input())
words = [input().strip() for _ in range(n)]
text = input().strip()

m = len(text)

dp = [0] * (m + 1)
dp[0] = 1

for i in range(m):
    if dp[i] == 0:
        continue

    for word in words:
        L = len(word)

        if i + L > m:
            continue

        ok = True
        for j in range(L):
            if text[i + j] != '?' and text[i + j] != word[j]:
                ok = False
                break

        if ok:
            dp[i + L] = (dp[i + L] + dp[i]) % MOD

print(dp[m])
```DP 配列には、プレフィックスのカウントが保存されます。 位置`i`最初のものを表します`i`これにより、トランジションがきれいになり、off-by-one エラーが回避されます。 

マッチングテストは直接実行されます。 すべての語長は最大 10 であるため、ハッシュ化、試行、または文字列の前処理は必要ありません。 

の`if dp[i] == 0`チェックは正確性を保証するために必要ではありませんが、到達不可能な状態からの不必要な照合試行を回避します。 

モジュロ演算は加算のたびに適用されます。これは、分解の数が非常に早く増加する可能性があるためです。`?`文字が存在します。

# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    MOD = 10 ** 9 + 7

    n = int(input())
    words = [input().strip() for _ in range(n)]
    text = input().strip()

    m = len(text)
    dp = [0] * (m + 1)
    dp[0] = 1

    for i in range(m):
        if dp[i] == 0:
            continue

        for word in words:
            L = len(word)

            if i + L > m:
                continue

            ok = True
            for j in range(L):
                if text[i + j] != '?' and text[i + j] != word[j]:
                    ok = False
                    break

            if ok:
                dp[i + L] = (dp[i + L] + dp[i]) % MOD

    return str(dp[m]) + "\n"

# provided samples
assert run(
"""7

c
d

bc
cd

"""
) == "11\n", "sample 1"

"""
) == "1\n", "single exact match"

"""

# overlapping decomposition choices

 ## 特殊なケース

 次のことを考慮してください。```
2
ab
ac
a?
```位置 0 では、両方の単語が一致します。`?`どちらかを表すことができます`b`または`c`。 

アルゴリズムは両方の遷移を実行します。```
dp[2] += dp[0]
dp[2] += dp[0]
```与える`dp[2] = 2`。 一部の単語が一致するかどうかだけをチェックするソリューションでは、誤って 1 が生成されます。 

次のことを考慮してください。```
2
a
b
??
```最初の文字では、両方の単語が一致します。 2番目の文字でも同じことが起こります。 

DP は次のように進化します。```
dp = [1, 2, 4]
```これにより、選択した単語に含まれるすべての文字の割り当てが正しくカウントされます。 

考慮する：```
1
ab
a
```単語が残りのテキストよりも長くなっています。 トランジションがスキップされる理由は、`i + L > m`。 最後まで到達する状態はないので、`dp[m]`は 0 のままで、テキストを辞書の単語に分解できないことを正しく示しています。
