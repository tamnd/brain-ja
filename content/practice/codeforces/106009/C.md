 ## 解決策
 ## 問題の理解

 グリッドで表された鉱山があります。 一部のセルには金が含まれており、一部は石でブロックされており、一部はすでに空になっています。 スミロは空のセルを選択し、そこに爆弾を設置できます。 爆弾は選択したセルの周囲の半径の正方形を消去します`k`チェビシェフの距離で。 この正方形の境界線上にある金は収集されますが、厳密に正方形の内側にある金は失われます。 

目標は、収集したゴールドの量を最大化する爆発を選択することです。 難しいのは、爆発の後、多くのセルが空になるため、後の爆発が新しい場所に配置される可能性があることです。 

グリッドの寸法と`k`最大 500 個まで増やすことができますが、すべてのテスト ケースにわたるセルの合計数は制限されています。 これにより、考えられるあらゆる爆発シーケンスをシミュレートするソリューションは除外されます。 空のセルのすべてのサブセットを直接検索することは不可能です。 すべての有用な最初の手を効率的に評価し、残りの手を暗黙的に処理できることを証明する方法が必要です。 

いくつかの特殊なケースは見落とされがちです。 いつ`k = 1`、爆弾は周囲の8つのセルと中心にのみ影響します。 よくある間違いは、3 × 3 の正方形全体を失われた金として扱うことですが、中心は境界線の一部ではありません。 例えば：```
1
2 2 1
g.
.g
```唯一の空のセルは右上隅です。 爆弾は斜めに隣接するゴールドを収集し、それが正方形の中にある場合にのみ他のゴールドを破壊します。 正しい答えは、`1`、 ない`0`。 

もう 1 つのエッジケースは、最適な戦略に複数の爆弾が必要な場合です。 最高の単一爆発だけを探しても失敗します。 例えば：```
1
3 4 2
.g..
g..#
g##.
```1 つの爆弾ですべてのゴールドを収集することはできませんが、2 つの爆弾ではすべてのゴールドを収集できます。 答えは`3`。 最良の初期爆発だけをカウントするソリューションでは、結果が過小評価されてしまいます。 

3 番目の微妙なケースは、爆発がグリッドの外側に達した場合です。 爆発四角形の境界線は鉱山の外側にまだ存在するため、実際にグリッド内にあるセルを数える場合にのみ四角形をクリップする必要があります。 例えば：```
1
1 3 5
g.g
```唯一の空のセルは中央にあります。 爆発はグリッドよりもはるかに大きくなりますが、両方の金のセルが正方形の境界上にあるため、答えは次のようになります。`2`。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべての最初の爆弾の位置を試し、その後のすべての選択をシミュレートすることです。 これは、Smilo が実行できるアクションを正確に検討しているため、正しいです。 問題は、可能なシーケンスの数です。 最大合計 250,000 個のセルがあるため、位置のペアだけを考慮するだけでもコストがかかりすぎ、シーケンス全体の完全な検索は限界をはるかに超えています。 

重要な観察は、最初の爆発の後、その後の爆発はまだ破壊されていない金を集めるためにのみ役立つということです。 後の爆弾が金を収集できる場合、その中心は前の爆発後に利用可能になったエリア内にある必要があります。 重要な部分は、最初の爆発が、クリアが発生する前にまだ存在するゴールドを破壊できる唯一の爆発であるということです。 

選択された最初の爆弾センターの場合、収集されずに永久に失われる可能性がある唯一のゴールドは、厳密に爆発マス内にあるゴールドです。 他のものはすべて、最初の爆弾によって、または後の爆発を手配することによって収集できます。 欲張りな考えは、最小限のゴールドを破壊する最初の爆弾を選択することです。 最終的な答えは、合計ゴールドからその最小損失を差し引いたものです。 

考えられるすべての最初の中心をチェックするには、サイズの内側の正方形の中にどれだけの金が入っているかを知る必要があります。`(2k - 1) x (2k - 1)`。 2 次元のプレフィックス合計を使用すると、これを一定時間でクエリできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 実際に定義するには大きすぎます | O(nm) | 遅すぎる |
 | プレフィックス合計貪欲 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ゴールド セルの総数を数え、各エントリが左上隅からその位置までの長方形内のゴールド セルの数を格納する 2 次元プレフィックス合計配列を構築します。 これにより、任意の長方形内の金を即座に数えることができます。 
2. すべての空のセルを最初の爆発中心の可能性があると考えます。 これが機能するのは、最初の爆発が、その後の爆弾が到達する前にどのゴールドが消えるかを決定する唯一の決定であるためです。 
3. センターの場合`(i, j)`、厳密に爆発の内側にある内側の正方形を計算します。 その行範囲は次のとおりです`i - k + 1`に`i + k - 1`、その列範囲は次のとおりです。`j - k + 1`に`j + k - 1`。 鉱山にはその外側のセルが含まれていないため、座標はグリッドにクリップされます。 
4. 接頭辞の合計を使用して、この内側の正方形内で破壊されたゴールドの量を確認します。 考えられるすべての最初の爆発の中で、そのような最小値を維持してください。 
5. ゴールドの総量から最小損失ゴールドを差し引きます。 残りのゴールドが収集できる最大量です。 

なぜ効果があるのか:

 最初の爆発により、金が 2 つのグループに分けられます。 爆発の境界にある金はすぐに回収でき、爆発の外側にある金は後の操作に利用できるようになります。 爆発内部のゴールドは消滅するため、回収することはできません。 最初の爆発の後、将来の爆弾に必要なセルはクリアされているため、最初の爆発で生き残ったゴールドは、その後の適切な爆発を選択することで入手できます。 したがって、収集したゴールドを最大化することは、最初の爆発によって失われるゴールドを最小化することと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    pref = [[0] * (m + 1) for _ in range(n + 1)]
    total = 0

    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'g':
                total += 1
            pref[i + 1][j + 1] = (
                pref[i][j + 1]
                + pref[i + 1][j]
                - pref[i][j]
                + (grid[i][j] == 'g')
            )

    def get(x1, y1, x2, y2):
        if x1 > x2 or y1 > y2:
            return 0
        return (
            pref[x2 + 1][y2 + 1]
            - pref[x1][y2 + 1]
            - pref[x2 + 1][y1]
            + pref[x1][y1]
        )

    lost = total

    for i in range(n):
        for j in range(m):
            if grid[i][j] == '.':
                x1 = max(0, i - k + 1)
                y1 = max(0, j - k + 1)
                x2 = min(n - 1, i + k - 1)
                y2 = min(m - 1, j + k - 1)

                lost = min(lost, get(x1, y1, x2, y2))

    print(total - lost)

def main():
    t = int(input())
    for _ in range(t):
        solve()

main()
```プレフィックス合計構造では、セルの種類ではなく、ゴールドの数が保存されます。 これにより、すべての四角形クエリでは 4 つのプレフィックス値の演算のみが必要となるため、後のクエリが単純になります。 

ヘルパー関数`get`長方形内の金色のセルの数を返します。 境界は呼び出す前にすでにクリップされているため、負のインデックスや 1 つの間違いによる外れが回避されます。 

内側の正方形は使用します`k - 1`セルが正確であるため、その半径として`k`中心から離れた部分は境界上にあり、収集されます。 厳密に近いセルのみが失われます。 

最後のループでは、考えられるすべての最初の爆弾の位置を試します。 答えはこれらの場所の中で最小の破壊されたゴールドのみに依存するため、後の爆発をシミュレートする必要はありません。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    
    data = sys.stdin.read().split()
    sys.stdin = old

    it = iter(data)
    t = int(next(it))
    out = []

    for _ in range(t):
        n = int(next(it))
        m = int(next(it))
        k = int(next(it))
        grid = [next(it) for _ in range(n)]

        pref = [[0] * (m + 1) for _ in range(n + 1)]
        total = 0

        for i in range(n):
            for j in range(m):
                if grid[i][j] == 'g':
                    total += 1
                pref[i + 1][j + 1] = (
                    pref[i][j + 1]
                    + pref[i + 1][j]
                    - pref[i][j]
                    + (grid[i][j] == 'g')
                )

        def get(x1, y1, x2, y2):
            if x1 > x2 or y1 > y2:
                return 0
            return pref[x2 + 1][y2 + 1] - pref[x1][y2 + 1] - pref[x2 + 1][y1] + pref[x1][y1]

        lost = total
        for i in range(n):
            for j in range(m):
                if grid[i][j] == '.':
                    lost = min(
                        lost,
                        get(
                            max(0, i - k + 1),
                            max(0, j - k + 1),
                            min(n - 1, i + k - 1),
                            min(m - 1, j + k - 1)
                        )
                    )

        out.append(str(total - lost))

    return "\n".join(out)

 ## 特殊なケース

 のために`k = 1`この場合、アルゴリズムは内側半径 0 を使用します。 長方形のクエリは中心の周囲で単一セルのクエリになるため、中心のセルのみが失われたとみなされます。 爆弾センターは空であるため、ゴールドは破壊されたものとしてカウントされません。 これにより、最小の爆発サイズが正しく処理されます。 

複数の爆弾を必要とする戦略の場合、アルゴリズムはそれらの爆弾を明示的にシミュレートしません。 代わりに、損失が最も少ない最初の爆発を見つけます。 内側の領域の外側にあるゴールドは最初のステップを通過し、後で収集できます。 これが、1 回の爆発では答えが得られないにもかかわらず、3 番目のサンプルが正しく処理される理由です。 

爆発がボードよりも大きい場合、計算された内側の正方形は実際の地雷の境界にクリップされます。 正方形の外側の部分には金が含まれていないため、これを無視しても破壊されたセルの数は変わりません。
