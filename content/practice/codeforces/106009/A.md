 ## 問題の理解

 私たちには、一連のポジションに対して決定論的なプロセスのように動作するシステムが与えられています。 各位置には順列によって与えられる「次の位置」があり、さらに各位置にはバイナリ フラグがあり、その位置を通過するときに状態を反転させることができます。 

どの開始位置からでも、プロセスは段階的に進化します。 位置で`i`に移動します`p[i]`。 出発中`i`に応じて、オプションで少し切り替えることもできます。`b[i]`。 すべての位置には常に 1 つの出力遷移があるため、システム全体は、各ノードの出次数が 1 である有向グラフとして見ることができますが、各位置は 2 つの内部状態 (「通常」と「反転」を考えてください) になる可能性があるため、実質的に 2 倍の数の状態が存在します。 

要件は、ある状態から開始してプロセスを十分に長く繰り返すことにより、これらの 2 倍になった状態のすべてに到達可能になることです。 グラフ用語では、プロセスによって引き起こされる関数グラフを指します。`2n`状態は単一の有向サイクルを形成する必要があります。 

入力は順列を与えます`p`そしてバイナリ配列`b`。 のエントリを変更することが許可されています`p`(順列を維持しながら) とエントリ`b`。 各変更のコストは 1 です。必要な変更の総数を最小限に抑えて、誘導されたグラフが`2n`状態は単一サイクルになります。 

制約により、最大約`2 · 10^5`要素。 これにより、シミュレーションを試みるアプローチは即座に排除されます。`2n`-状態グラフを明示的に、またはすべての状態遷移について理由付けします。 順列構造全体にわたって線形または線形に近い時間で機能するソリューションが必要です。 

いくつかのエッジな状況は間違いやすいものです。 

順列にすでに複数のサイクルがある場合、単純なアプローチでは、各サイクルをマージせずに個別に「修正」しようとする可能性がありますが、それではすべての状態にわたって単一のグローバル サイクルを生成することはできません。 たとえば、次の場合`p = [2 1 4 3]`、2つのサイクルがあります`(1 2)`そして`(3 4)`。 全部調整しても`b[i]`、変更しない限り、これらのコンポーネントを接続することはできません。`p`。 

もう 1 つの微妙なケースは、順列がすでに単一サイクルであるが、バイナリ値が「互換性がない」場合です。 たとえば、サイクルに従って内部状態を交換するのではなく保持する場合、各位置は 2 つの状態のうちの 1 つにのみ表示され、必要な状態の半分は到達できないままになります。 

## アプローチ

 ブルートフォースの観点は、次の完全なグラフを構築することです。`2n`と明示的に述べています。 各州`(i, 0)`または`(i, 1)`に基づいて別の状態に決定的に遷移します。`p[i]`そして`b[i]`。 構築したら、グラフが単一サイクルになるように必要なエッジ変更の最小数を計算してみることができます。 

これはすぐに実行不可能になります。`p[i]`または`b[i]`一度に 2 つの状態に影響を与え、非ローカルな方法でグローバル サイクル構造を変更します。 単一の変更がサイクル分解にどのような影響を与えるかを特定するだけでも、長期間にわたって繰り返し再計算する必要があります。`2n`ノード、少なくとも 2 次の動作につながります。 

重要な単純化は、システムが順列のサイクルに沿って自然に分解することを観察することで得られます。`p`。 各サイクルの`p`バイナリ配列はサイクル内で独立して動作します。`b`そのサイクルが 1 つの大きなサイクルに寄与するかどうかを決定します。`2L`状態を 2 つの別々の長さのサイクルに分割する`L`。 

一定の長さのサイクルの場合`L`、サイクルを 1 回横断すると、内部状態はすべての XOR に従って反転します。`b[i]`そのサイクルの中で。 この XOR が 0 の場合、1 回の走査で元の状態に戻ります。これは、2 つの内部状態が分離されたままであることを意味します。 XOR が 1 の場合、1 回の完全な走査で内部状態が交換され、すべての状態がマージされます。`2L`状態を 1 つのサイクルにまとめます。 

したがって、問題は 2 つの独立した目標に帰着します。 まず、順列を単一のサイクルに変換する必要があります。 次に、次の XOR が成立することを確認する必要があります。`b`その最後のサイクルでは 1 に等しくなります。 どちらも最小限の変更で実現できます。 

順列を回転するには`k`複数のサイクルを 1 つのサイクルにするには、すべてのサイクルを 1 つにマージする必要があります。これには正確なコストがかかります`n - k`の変化`p`。 その後、結果のサイクルで XOR 条件を計算し、最大 1 回の変更で修正します。`b`。

 ## アルゴリズムのチュートリアル

 1. 順列を分解する`p`そのサイクル構造に組み込まれます。 We walk through all indices and count how many distinct cycles exist. Each unvisited node starts a new cycle and we follow`p`帰るまで。 このステップでは、システムの独立したコンポーネントをキャプチャします。 
2. サイクル数を数える`k`。 These cycles represent disconnected components in terms of reachability before any modifications.
 3. すべての XOR を計算します。`b[i]`各サイクル内の値。 これにより、そのサイクルが変更されないままの場合、1 回の完全な走査後に内部状態が保持されるか反転されるかがわかります。 
4. すべてのサイクルを 1 つにマージするために必要な変更の数を決定します。 それぞれの変更以来、`p[i]`ノードをリダイレクトしてサイクルを効果的にマージできるため、必要な変更の最小数は`k - 1`。 これは、すべてのコンポーネントを単一のチェーン状の構造に接続することに対応します。 
5. 単一サイクルを形成した後、次の XOR を計算します。`b`その構築されたサイクルに沿って。 すでにある場合`1`、それ以上の変更は必要ありません。 そうであれば`0`、いずれかを反転します`b[i]`サイクル内では、1 回の操作が必要となり、パリティが切り替わります。 

### なぜ効果があるのか

 変更しない限り遷移がサイクルから離れることはないため、順列の各サイクルは独立して進化します。`p`。 サイクル内で、両方の内部状態に到達可能かどうかを決定する唯一のグローバル プロパティは、`b`そのサイクルに沿った価値観。 この XOR は、サイクルの横断によって状態パリティが維持されるか反転されるかを制御します。 

すべてのサイクルが単一の順列サイクルにマージされると、システムは単一の機能ループになります。`2n`州。 有限集合上の関数グラフは、それが接続されており、すべてのノードが出次数 1 を持っている場合に限り、単一のサイクルを形成します。これはすでに保証されています。 残りの唯一の要件は、内部状態がループに沿って正しく切り替わることです。これはまさに、サイクル全体の XOR が 1 に等しい条件です。 

各操作はサイクルをマージするかパリティをローカルに反転するかのいずれかであり、両方の効果は独立しているため、サイクル マージと最終パリティ修正の貪欲なカウントにより、最小限の変更数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = [0] + list(map(int, input().split()))
    b = [0] + list(map(int, input().split()))

    vis = [False] * (n + 1)
    cycles = 0
    xor_global = 0

    for i in range(1, n + 1):
        if not vis[i]:
            cycles += 1
            cur = i
            xor_local = 0
            while not vis[cur]:
                vis[cur] = True
                xor_local ^= b[cur]
                cur = p[cur]
            xor_global ^= xor_local

    # need to make permutation a single cycle
    ans = cycles - 1

    # ensure XOR over final cycle is 1
    if xor_global == 0:
        ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、標準の訪問ウォークを使用して順列サイクルを抽出します。 各サイクルを走査しながら、XOR を蓄積します。`b`その中にある価値観。 サイクル数によって、必要なマージの数が決まります。 

すべてのサイクルを処理した後、`cycles - 1`順列を 1 つのサイクルに変えるコストです。 最後の XOR チェックでは、パリティを修正するために追加の変更が 1 つ必要かどうかが判断されます。 

実装におけるよくある間違いは、概念的にサイクルをマージする前に、XOR を配列全体でグローバルに計算するのではなく、サイクルごとに計算する必要があることを忘れていることです。 もう 1 つの微妙な点は、訪問したノードのマーク付けは、厳密に順列走査に沿って行われなければならないことです。 これを隣接リストに関するグラフの問題として扱う試みは不要であり、エラーが発生しやすくなります。

 ## 特殊なケース

 単一要素の順列は、マージが必要ない境界を強調表示します。 アルゴリズムは 1 つのサイクルを認識するため、`cycles - 1`はゼロです。 もし`b[1]`はすでに一貫しており、XOR は 1 であり、補正は適用されません。

不正確なパリティを持つ完全に正しい単一サイクルは、ロジックの 2 番目の部分を分離します。 構造はすでに最適化されていますが、XOR 条件により 1 つだけ変更が強制されます。`b`、構造とパリティが独立した自由度であることを示しています。
