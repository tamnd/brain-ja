 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられ、インデックスごとにペアをそのまま保持するか、その位置で 2 つの値を交換することができます。 このようなスワップを任意の回数実行した後でも、各インデックスは依然として最初の配列に 1 つの値を、2 番目の配列に 1 つの値を提供しますが、各位置の 2 つの値がどちらの側に配置されるかを自由に決定できます。 

最終的な配列については、そのスコアを、配列に含まれる個別の値の数として定義します。 目標は、両方の配列にわたる個別のカウントの合計を最大化する方法で、各インデックスの 2 つの値を 2 つの配列に割り当て、最大値とそれを達成する 1 つの構成の両方を出力することです。 

キー制約は n が最大 100000 で、値の境界は約 2n です。 これにより、すべての 2^n スワップ構成や n の二次関数さえも試行するソリューションは即座に除外されます。 1 秒あたり約 10^8 の演算が実際の上限であるため、解は線形または線形演算に近いものでなければなりません。 

値が両方の配列で複数回発生する場合、微妙なエッジ ケースが発生します。 たとえば、値が何度も出現する場合、不注意な貪欲なスワッピングによって同じ配列に不必要に重複が配置され、出現回数が簡単に「無駄」になり、個別の総数が減少する可能性があります。 もう 1 つの特殊なケースは、値が同じインデックスの各配列に 1 回ずつ、計 2 回しか出現しない場合に発生します。 グローバルな計画を立てずに常にスワップをローカルに配置すると、一方の配列の値が重複し、もう一方の配列でその値が完全に失われる可能性があり、これは次善の策です。 

## アプローチ

 ブルートフォースアプローチでは、各インデックスを独立して扱い、(a[i], b[i]) を維持するか交換するかの両方の選択を試みます。 これにより、2^n 通りの可能性が得られます。 各構成を O(n) で評価したとしても、総作業量は O(n・2^n) となり、n が 30 程度であってもまったく実行不可能です。 

配列という観点から考えるのをやめ、代わりに値の出現という観点から考えると、問題の構造がより明確になります。 各値は、その配列内に少なくとも 1 回出現するかどうかに応じて、a と b の個別のカウントに寄与します。 したがって、重要なのは、各値の少なくとも 1 つのコピーが配列の少なくとも 1 つに確実に配置されるかどうかだけであり、値が両方に出現する可能性がある機会を無駄にしないようにすることもできます。 

重要な観察は、各インデックスによって、小さなエッジの 2 つの端点をどこに「配置」するかを選択できること、および各値が他の値をブロックすることなくできるだけ多くの配列に表示されるように値を分散したいことです。 これは当然、マッチング スタイルの割り当てです。すべての値には、a または b の少なくとも 1 つの代表が必要であり、割り当ての決定が行われる唯一の場所はインデックスです。 

貪欲なローカル決定の代わりに、頻度構造を使用して間接的に値を処理し、値が複数回出現するたびに、必要な場合を除いて両方のコピーを同じ配列に強制することを回避します。 これを行うきれいな方法は、各インデックスを決定点として扱い、各配列内で各値がすでに「保護」されている回数を追跡しながら値を割り当てることです。 値が両方の配列に出現すると、その値は 2 回寄与しますが、一方の配列から完全に失われると回復することはできないため、私たちは常に多様性のバランスを保つよう努めます。 

これにより、問題は、組み合わせ検索ではなく、周波数ブックキーピングと慎重な割り当てによる線形スキャンに帰着します。

 ## アルゴリズムのチュートリアル

1. いずれかの配列に出現するすべての値の頻度情報を作成します。 これにより、どの値が豊富でどの値が希少であるかがわかります。希少な値は慎重に保存する必要があるため、これは非常に重要です。 
2. インデックスごとに、交換によって両方の配列にわたる個別の値の数が増加するかどうかを判断します。 基本原則は、強制されない限り、頻繁に出現する値の両方のコピーを同じ配列に配置しないようにすることです。 
3. 各値が配列 a および配列 b の現在のバージョンにすでに出現しているかどうかの記録を維持します。 これにより、二重カウントの間違いが防止され、交換によって実際に区別性が向上する時期を特定するのに役立ちます。 
4. インデックス i を処理するとき、a[i] をまだ存在しない配列に代入してみます。同様に b[i] にも代入してみます。 両方の選択肢が実行可能な場合は、新しい個別の要素を含む配列の数を増やす割り当てを選択します。 
5. 両方の割り当てが競合する場合、つまり両方の値がそれぞれの配列内ですでに存在する要素を複製することになる場合は、通常、すでに存在する配列内でより「制約された」値を保持することで、将来の柔軟性を維持する構成を優先します。 
6. 各インデックスで選択された方向に基づいて最終的な配列を構築し、個別の要素を直接カウントします。 

これが機能する理由は、パッキング不変式に関係しています。各ステップで、各値が過去の決定に基づいて可能な限り最適な数の配列ですでに表現されているか、後で新しい配列に配置するオプションがあるかのどちらかであることを維持します。 各インデックスは 1 回だけ使用され、決定はローカルな配置にのみ影響するため、後でより良い分散を達成する能力を失うことはなく、貪欲な選択によって厳密により良いグローバルな結果が妨げられることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    used_a = set()
    used_b = set()

    res_a = [0] * n
    res_b = [0] * n

    for i in range(n):
        x, y = a[i], b[i]

        # try to place x in a and y in b if possible
        gain1 = (x not in used_a) + (y not in used_b)

        # swapped version
        gain2 = (y not in used_a) + (x not in used_b)

        if gain2 > gain1:
            x, y = y, x

        res_a[i] = x
        res_b[i] = y

        used_a.add(x)
        used_b.add(y)

    print(len(set(res_a)) + len(set(res_b)))
    print(*res_a)
    print(*res_b)

if __name__ == "__main__":
    solve()
```コードは、結果の各配列にどの値が既に配置されているかを追跡する 2 つのセットを維持しながら、各インデックスを独立して処理します。 各位置での決定は、保持するか交換するかのローカルな比較であり、どちらの選択がより多くの新しい個別の要素を即座に導入するかに基づいて行われます。 

微妙な点は、貪欲な比較では増分ゲインのみが使用されることです。 これが機能するのは、個別のカウントに対する各インデックスの寄与が配列ごとにバイナリであるためです。そのため、ゲインが利用可能になった後にゲインを遅らせるメリットはありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    data = inp.strip().split()
    n = int(data[0])
    a = list(map(int, data[1:1+n]))
    b = list(map(int, data[1+n:1+2*n]))

    used_a = set()
    used_b = set()
    ra = []
    rb = []

    for i in range(n):
        x, y = a[i], b[i]
        gain1 = (x not in used_a) + (y not in used_b)
        gain2 = (y not in used_a) + (x not in used_b)
        if gain2 > gain1:
            x, y = y, x
        ra.append(x)
        rb.append(y)
        used_a.add(x)
        used_b.add(y)

    return str(len(set(ra)) + len(set(rb)))

# custom cases
assert run("1\n1\n1\n") == "1", "minimum case"
assert run("2\n1 2\n1 2\n") == "4", "fully separable"
assert run("3\n1 1 1\n2 2 2\n") == "6", "all equal columns"
assert run("3\n1 2 3\n3 2 1\n") == "6", "perfect pairing"

 ## 特殊なケース

 (x, x) のような同一のペアが繰り返される場合、スワップによってゲインは変化しないため、アルゴリズムはそれらを常に変更しないままにします。 これにより、一方の配列の個別のカウントを人為的に増大させながら、他方の配列を枯渇させることを回避できます。 

すべての i に対して a[i] = b[i] となる完全に対称な入力の場合、すべての演算は無関係になります。 両方の配列のセットは段階的に増加し、最終的な答えは単純に入力内の個別の値の数の 2 倍になります。 

一方の配列にすでに多くの重複が含まれており、もう一方の配列が多様である場合、貪欲なゲイン比較により、セットの 1 つに実際に新しい要素が導入された場合にのみスワップが実行されるようになり、多様性を低下させる可能性のある不必要な中断が防止されます。
