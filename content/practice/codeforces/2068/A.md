 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 候補者間には有向関係が与えられており、入力ペア「a が b に勝つ」は投票ではなく、シミュレーションする必要がある最終結果に対する制約となります。 実際の出力はランキングそのものではなく、完全なランキング (すべての候補の順列) のマルチセットです。つまり、これらの順列にわたるすべてのペアを比較すると、入力が a が b に勝つ必要があると言うときは常に、厳密に順列の半分以上で候補 a が候補 b より前に表示されます。 

言い換えれば、各順列は投票のように機能し、候補者がこれらの投票の半分以上で先に配置されていれば、ペアごとの決闘に勝ちます。 誘導多数決関係が指定されたすべての有向辺と一致する、最大 50,000 個の置換を構築する必要があります。 それが不可能な場合は、失敗を報告する必要があります。 

隠された構造は、各投票がすべてのペアごとの比較に等しく寄与するというものであり、そのため、このタスクは、合計注文のマルチセットによって引き起こされる多数決トーナメントとして有向グラフを実現することと同等です。 

n に関しては制約が小さく、n は最大 50 です。これは、ソリューションではペアに対して O(n^2) または O(n^3) の推論を使用できることを強く示唆していますが、順列に対して指数関数的なものは不可能です。 本当の課題は複雑さではなく、完全な順列を使用してペアごとの多数決の一貫したシステムを構築する実現可能性です。 

素朴だが魅力的なアイデアは、すべてのエッジに一貫したグローバル ランキングを割り当てようとすることです。 グラフにはサイクルが含まれている可能性があるため、これはすぐに失敗します。たとえば、1 敗北 2、2 敗北 3、3 敗北 1 です。単一の順列で 3 つの制約すべてを同時に満たすことはできません。 もう 1 つの素朴なアプローチは、各エッジを個別に扱い、個別の投票で「修正」しようとすることです。 これも失敗します。1 つの順列がすべてのペアに同時に影響するため、独立したエッジ処理は不可能です。 

制約がサイクルを形成しているものの、程度が局所的に一貫している場合、微妙なエッジ ケースが発生します。 たとえば、3 サイクルは局所的には常に実現可能に見えますが、1 つまたは 2 つの置換でそれを強制しようとすると、慎重にバランスをとらない限り、多数派の一貫性が崩れてしまいます。 

## アプローチ

 強引な解釈では、最大 50,000 個の順列のシーケンスを検索し、誘導された多数決関係がすべての必要なエッジと一致するかどうかを確認します。 たとえ小さい数 k に制限したとしても、状態空間は天文学的に大きくなり、各順列は n になります。 したがって、k = 2 であっても (n!)^2 個の可能性が生じますが、これは完全に実行不可能です。 

重要な観察は、任意の順列を独立して構築する必要がないということです。 代わりに、ペアごとのマージンを制御するという観点から考えることができます。 各順列は、その順序と一致してすべてのペアに +1 を与えます。 すべてのペア (a, b) に対して希望する多数の方向を割り当てることができれば、順列にわたる一貫した線形不等式の系が必要になります。 これはまさにトーナメント実現の問題です。 

重要な構造的洞察は、有向グラフを多数決トーナメントとして実現する必要があるだけであり、これはグラフが非巡回である場合にのみ常に可能であるということです。 グラフに有向サイクル (a → b → c → a など) がある場合、そのサイクルの周囲で多数決制約を合計すると矛盾が生じます。各エッジは一方向の厳密な多数決を要求しますが、すべての順列を集計すると、循環合計に少なくとも 1 つの矛盾が生じます。 逆に、グラフが非巡回の場合は、トポロジカルな順序付けを構築し、それを使用してすべてのエッジを強制する順列を定義できます。

トポロジカルな順序を取得すると、構築は簡単になります。この順序を尊重する順列を繰り返し出力します。 慎重に選択した摂動を交互に行うことで (たとえば、隣接するセグメントを反転したり、ブロックをシフトしたり)、必要な各エッジを他のエッジを侵害することなく厳密な多数決に増幅できます。また、n が小さいため、制限された数の構造化投票でこれを行うことができます。 

これにより、問題は、有向グラフが非巡回であるかどうかをチェックし、位相順序と一致する置換の有界セットを構築することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順列に対するブルートフォース | O(k・n!) | O(k · n) | 不可能 |
 | グラフ + 建設的な投票 | O(n² + k・n) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 この解決策は、非循環性を検証し、トポロジカルな順序と一致する制御された順列セットを構築することに基づいています。 

1. 与えられた制約から有向グラフを構築します。ここで、各エッジ a → b は、a が投票の過半数において b よりも前に出現する必要があることを意味します。 
2. トポロジカルソートを使用して、このグラフに有向サイクルが含まれているかどうかを確認します。 サイクルが存在する場合は直ちに NO を出力します。 その理由は、どのサイクルでも、同時に満たすことができない矛盾した多数の要件を強制することになるからです。 
3. グラフが非巡回の場合、すべてのノードのトポロジー的順序付けを計算します。 この順序付けは、一方向の必要なエッジをすべて考慮したベースラインのランキングを表します。 
4. 順列のシーケンスを構築します。 最も単純で有用な構造は、トポロジー順序のコピーを繰り返し使用し、各エッジの厳密な多数決を保証する慎重に選択されたスワップと組み合わせることです。 各エッジ a → b は、順列の半分以上で正しく出現する必要があるため、ほとんどの順列を位相順序に偏らせることで、すべてのエッジが「保護」されるようにします。 
5. k = 2 · n (または 50,000 以内の別の安全な線形境界) を設定します。 順列の前半では位相順序を出力します。 後半では、すべてのエッジ a → b がすべての順列の半分以上で厳密に尊重されるように、制御された方法でローカル セグメントを反転するわずかな摂動を出力します。 
6. 必要なエッジのみが重要であるため、入力によって制約されないすべてのペアが任意に動作できることを確認します。 

### なぜ効果があるのか

 維持される不変条件は、すべての必要なエッジ a → b がすべてのベースライン順列で尊重され、最大でも慎重に制限された摂動順列のサブセットで違反されるということです。 違反する順列の数は厳密に半分未満であるため、多数決関係は維持されます。 非巡回性は、少なくとも 1 つの順列ですべてのエッジを同時に尊重するグローバルな順序の存在を保証し、重複によってその順序が多数決システムに増幅されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    indeg = [0] * n

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append(b)
        indeg[b] += 1

    # Kahn topological sort
    from collections import deque
    q = deque(i for i in range(n) if indeg[i] == 0)
    topo = []

    while q:
        u = q.popleft()
        topo.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    if len(topo) != n:
        print("NO")
        return

    # Construct permutations
    # Use 2*n permutations: n copies forward, n copies slightly perturbed
    k = 2 * n
    print("YES")
    print(k)

    base = [x + 1 for x in topo]

    for _ in range(n):
        print(*base)

    # perturbations: swap adjacent pairs in a cyclic way
    for i in range(n):
        perm = base[:]
        if n > 1:
            j = i % (n - 1)
            perm[j], perm[j + 1] = perm[j + 1], perm[j]
        print(*perm)

if __name__ == "__main__":
    solve()
```コードはまず有向グラフを構築し、カーンのアルゴリズムを実行して一貫した順序付けが存在するかどうかを検出します。 トポロジー的ソートにすべてのノードが含まれない場合、制約は循環的であり、有効な選択を構築できません。 

有効な順序が取得されると、それがバックボーンの並べ替えとして使用されます。 出力は、この順序の繰り返しコピーで構成され、一貫した方向で必要なエッジをすべてすでに満たしています。 追加の順列により、制御されたローカル反転が導入され、システム全体で両方向にエッジが人為的に強化されることがなくなります。 

重要な実装の詳細は、すべての順列が有効な完全な順列のままである必要があるため、任意のサブセットを並べ替えるのではなく、隣接する要素を交換することによって摂動が行われることです。

 ## 特殊なケース

 重要なエッジ ケースは、制約が 1 つの欠落エッジを除いてほぼ完全なサイクルを形成する場合です。 たとえば、1 → 2、2 → 3、3 → 4、4 → 1 の 1 つのエッジが削除されます。 この状況では、サイクルがまだ存在するため、トポロジカル ソートは失敗します。 アルゴリズムは、次数枯渇を通じてこれを正しく検出します。少なくとも 1 つのノードは常に未処理のままになります。 

もう 1 つのケースは、m = 0 の場合です。任意の順列セットが機能し、アルゴリズムは位相順序から同一の順列を繰り返し出力しますが、これは任意の順序に退化します。 制約が存在しないため、どの出力も有効です。 

3 番目の微妙なケースは、制約がすでに全体の順序と一致している場合です。 その場合、トポロジー順序は一意であり、アルゴリズムは同一の順列を出力します。 すべての必要なエッジがすべての投票で満たされるため、すべての多数決条件が自明に満たされます。
