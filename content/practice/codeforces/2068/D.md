 ## 解決策
 ## 問題の理解

 シンボルのセットが与えられ、それぞれが既知の確率で使用されます。 どのコードも別のシンボルのプレフィックスになることができないという制限の下で、各シンボルにドットとダッシュの 2 文字で構成されるバイナリ コードを割り当てる必要があります。 この制限により、コードは各シンボルが葉に位置するバイナリ ツリーを形成するようになります。 

ドットのラベルが付いたエッジを通過するたびに 1 単位の時間を支払い、ダッシュ エッジごとに 2 単位のコストがかかります。 シンボルを送信するコストは、ルートからリーフまでのパスに沿ったエッジ コストの合計です。 目的は、すべてのリーフ コストの確率加重合計として計算される予想送信コストが最小限になるように、シンボルをリーフに割り当てることです。 

入力サイズは十分に小さいため、二次または三次動的計画法が実行可能です。 最大 200 個のシンボルを使用すると、O(n^3) ソリューションは制限内で快適に実行できますが、プレフィックスのないコードの数は n とともに超指数関数的に増加するため、ツリーの指数関数的な構築は直ちに実行できなくなります。 

古典的なハフマンコーディングの観点から考えると、微妙な問題が現れます。 ハフマンはすべてのエッジのコストが等しいと想定していますが、ここではドットとダッシュの重みが異なります。 これにより、通常の貪欲なマージ解釈が破られ、ツリー形状と非対称エッジ コストについて明示的に推論する必要が生じます。 

単純な間違いは、深さのみが重要であると仮定することです。 たとえば、ダッシュを「2 つのドット」として扱い、すべてを単位深さのバイナリ ツリーに折りたたむと、コストが不正確になります。これは、ダッシュがコスト 2 に寄与する単一のエッジであり、2 つの独立したステップではないためです。 もう 1 つのよくある失敗は、ハフマンが依然として適用されると仮定することです。これにより、非対称のエッジ配置が問題となる小規模な構築ケースで最適性の失敗が発生します。 

## アプローチ

 ブルートフォース手法では、n 個の葉を持つすべての完全なバイナリ ツリー形状を試し、あらゆる方法でシンボルを割り当てます。 代入を無視しても、ツリー形状の数はカタルーニャ数のように増加し、代入を使用すると n の階乗になります。 候補ツリーの各評価では、根から葉までのすべてのコストを計算し、重み付けされた値を合計する必要があります。 これは、n が 20 を超えると、実行可能な限界を超えて急速に爆発します。 

重要な構造的観察は、最適なコードが常に、大きさによってソートされた周波数にわたる順序付けられた 2 分木に対応するということです。 重いシンボルが軽いシンボルよりも深くなってはなりません。そうでない場合は、シンボルを交換することで目的が改善されます。 これにより、頻度によって葉の順序を修正し、その順序を二分木に括弧で囲む方法のみを理解できるようになります。 

ソートされた周波数の間隔に制限すると、問題は古典的な間隔動的計画法の問題になります。 セグメントを左右のサブツリーに分割する方法を決定します。 セグメントを親に接続するコストは、サブツリー内のすべてのリーフが同じ追加コストを継承するため、どちらの側が点エッジを使用し、どちらが破線エッジを使用するかによって異なります。 

これにより、各分割で子へのエッジの重みの両方の割り当てが考慮される DP が得られます。 遷移は n で 3 次であり、n が 200 まで許容されます。

 ## アルゴリズムのチュートリアル

 ### 1. シンボルを頻度で並べ替えます

 周波数が増加しない順序になるようにシンボルを並べ替えます。 これにより、最適なツリーを構築するときに、高頻度のシンボルが構造内の浅い位置に自然に割り当てられることが保証されます。 

### 2. 間隔で DP を定義する

 私たちは定義します`dp[i][j]`インデックスからのシンボルを使用して最適なプレフィックスフリーのコード ツリーを構築するための最小限のコストとして`i`に`j`このソート順で。 

これが機能するのは、最適な部分構造が成立するためです。区間のルート分割を修正すると、両側が独立して動作します。 

### 3. すべての分割ポイントを試してみる

 インターバルごとに`[i, j]`、分割を選択します`k`どこ`[i, k]`左側のサブツリーを形成し、`[k+1, j]`右のサブツリーを形成します。 

### 4. 非対称エッジコストを考慮する

 2 つのサブツリーを親にアタッチする場合、どのサブツリーが点エッジ (コスト 1) を取得し、どちらが破線エッジ (コスト 2) を取得するかを選択する必要があります。 と表すと`W(i, k)`の周波数の合計として`[i, k]`、次にこのサブツリーをエッジコストでアタッチします`c`総コストが増加する`c * W(i, k)`。 

したがって、分割ごとに 2 つの可能性を評価します。 

左をドットに、右をダッシュに割り当てるか、それらを交換します。 2 つのうち安い方を採用します。 

### 5. 部分問題を結合する

 遷移は次のようになります。```
dp[i][j] = min over k:
    dp[i][k] + dp[k+1][j] + min(
        1 * W(i,k) + 2 * W(k+1,j),
        2 * W(i,k) + 1 * W(k+1,j)
    )
```### 6. ツリーを再構築する

 どの分割とどの方向 (ドット/ダッシュの割り当て) が最適な値を生成したかを保存します。 完全な間隔から開始して、エッジに沿って文字列を割り当ててツリーを再帰的に構築します (ドットは「.」を追加し、ダッシュは「-」を追加します)。 

### なぜ効果があるのか

 DP は、周波数がソートされると、最適な解は、葉がこの順序付けの連続セグメントに対応するバイナリ ツリーとして表現できるという事実に基づいています。 2 つのシンボルの深さの順序が狂っている場合、周波数は位置に依存しないが、コストは深さに対して単調であるため、それらを交換するとコストが削減されます。 これにより、間隔パーティションに注意を限定しても最適なソリューションが失われないことが保証されます。 

どの区間内でも、残された唯一の自由は、バイナリ ツリーの形状と非対称エッジの重みの割り当てだけです。 反復では、考えられるすべてのルート分割を考慮してそのような形状をすべて列挙しますが、方向の最小値により、両方の点線の割り当てが確実に調査されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    f = list(map(float, input().split()))
    
    # sort by frequency descending, keep original indices
    order = sorted(range(n), key=lambda i: -f[i])
    freq = [f[i] for i in order]

    # prefix sums
    pref = [0.0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + freq[i]

    def W(l, r):
        return pref[r + 1] - pref[l]

    INF = 1e100
    dp = [[0.0] * n for _ in range(n)]
    choice = [[None] * n for _ in range(n)]  # store (k, swap)

    # intervals of length 1
    for i in range(n):
        dp[i][i] = 0.0

    for length in range(2, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            dp[i][j] = INF

            for k in range(i, j):
                leftW = W(i, k)
                rightW = W(k + 1, j)

                cost1 = 1 * leftW + 2 * rightW
                cost2 = 2 * leftW + 1 * rightW

                c = dp[i][k] + dp[k + 1][j] + min(cost1, cost2)

                if c < dp[i][j]:
                    dp[i][j] = c
                    choice[i][j] = (k, cost1 <= cost2)

    # build tree
    res = [""] * n

    def build(l, r, prefix):
        if l == r:
            res[l] = prefix
            return

        k, swap = choice[l][r]
        left, right = (l, k), (k + 1, r)

        # swap decides which side is dot vs dash
        if swap:
            # left->dot, right->dash
            build(left[0], left[1], prefix + ".")
            build(right[0], right[1], prefix + "-")
        else:
            # left->dash, right->dot
            build(left[0], left[1], prefix + "-")
            build(right[0], right[1], prefix + ".")

    build(0, n - 1, "")

    # restore original order
    ans = [""] * n
    for i, idx in enumerate(order):
        ans[idx] = res[i]

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```コードはまず、頻度を減らすことによってシンボルを並べ替えます。これにより、DP はこの順序を考慮した最適なソリューションを安全に想定できます。 プレフィックス合計により、間隔頻度合計の定数時間計算が可能になります。これは、遷移が両方のサブツリーの合計重みに依存するため、非常に重要です。 

DP は、より小さな部分問題が常に利用できるように、サイズを大きくしながら間隔を埋めていきます。 間隔ごとに、すべての分割ポイントと、点と破線のエッジの両方の割り当てがテストされます。 保存されている`choice`配列には、分割位置と、ドット エッジが左のサブツリーに移動したか右のサブツリーに移動したかの両方が記録されます。 

再構成ステップでは、DP ツリーを走査して実際の文字列を構築します。 再帰呼び出しごとに「.」のいずれかが追加されます。 選択した方向に応じて「-」または「-」になります。 

最後に、結果は元のシンボルの順序にマップされて戻されます。 

## 実用的な例

 ### 例 1

 入力周波数:`[0.3, 0.6, 0.1]`ソート順は`[0.6, 0.3, 0.1]`。 

間隔コストをボトムアップで計算します。 

| 間隔 | ベストスプリット | 方向 | コスト |
 | --- | --- | --- | --- |
 | [0,1] | 分割0 | 一点鎖線 | 最小限の現地コスト |
 | [0,2] | 分割 1 | 重みに応じてダッシュ/ドット | グローバル最適 |

 DP は最終的に最も頻繁に使用されるシンボルを割り当てます。`0.6`最も短いコードは単一のドットですが、最も頻度の低いシンボルは、ダッシュの多いルートを含む長いパスを受け取ります。 

このトレースは、高周波シンボルが常に構築されたツリーの浅い葉に到達するという不変条件を確認します。 

### 例 2

 入力周波数:`[0.5, 0.25, 0.15, 0.10]`もう並べ替え済み。 

| 間隔 | スプリット k | 左の重み | 適切な体重 | 選択された方向 |
 | --- | --- | --- | --- | --- |
 | [0,3] | 1 | 0.75 | 0.25 | 重い側のドット |
 | [0,1] | 0 | 0.5 | 0.25 | 重い側のドット |
 | [2,3] | 2 | 0.15 | 0.10 | 重い側のドット |

 この例では、DP が一貫して安価なエッジを重いサブツリーに割り当てる動作が繰り返され、非対称エッジ処理が正しくキャプチャされていることを確認しています。

 ## 特殊なケース

 1 つのエッジ ケースは、2 つのサブツリーの合計重みが等しい場合に発生します。 その状況では、ドットとダッシュのどちらの方向でも同じコストが生成されます。 DP はどちらかの選択を保存し、同一コストのサブツリーの交換は目的に影響を与えないため、再構築によって有効な最適なエンコードが得られます。 

もう 1 つのケースは、1 つのシンボルの頻度が 1 に非常に近い場合です。DP は自然に縮退ツリーに崩壊し、そのシンボルが単一の点またはダッシュとしてルートに配置され、他のすべてがより深くに押し込まれます。 すべての比較は浮動小数点値に基づいているため、アルゴリズムは安定した比較に依存しますが、両方の向きが有効なままであるため、等しい場合でも正確性が損なわれることはありません。
