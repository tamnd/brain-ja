 ## 解決策
 ## 問題の理解

 の行が与えられています$2n$ちょうど半分が白で半分が赤のワインボトル。 ガブリエラはこれらのボトルを 2 つのグループに分けたいと考えています。$n$それぞれを交換し、グループ間でペアごとにボトルを交換します。 この 1 回の交換の後、すべての白いボトルが最初のボトルを占めるはずです。$n$行内の位置。 

入力は複数のテスト ケースを提供し、それぞれに整数が含まれます。$n$と長さの文字列$2n$ワインの色を表します。 出力は、希望の配置を実現するために説明どおりにパーティション化およびスワップが可能である場合は「YES」、それ以外の場合は「NO」と答える必要があります。 

重要な制約は次のとおりです。$n$最大 100 まで指定でき、最大 500 のテスト ケースがあります。 以来$2n \le 200$ケースごとに、テスト ケースごとに 2 次複雑度のアルゴリズムが実現可能です。 ただし、問題の構造は、組み合わせまたは貪欲な洞察によって作業を大幅に削減できることを示唆しています。 

白ワインが最後にあるとき、または赤ワインが最初にあるとき、微妙なエッジケースが発生します。 単純なアプローチが、目的の最初のグループに対する相対的な位置を考慮せずに、ボトルを最初または 2 番目のグループに貪欲に割り当てようとすると、$n$スロットでは、不可能なシナリオを誤って宣言する可能性があります。 例えば、`n=1`、`s="WR"`成功できません: 唯一のパーティションが結果として発生します`RW`ですので、正解は「NO」です。 

## アプローチ

 ブルートフォースアプローチは、すべてを列挙することです。$\binom{2n}{n}$最初のサブセットを選択する方法。 選択肢ごとに、相補的な 2 番目のサブセットを形成し、ペアごとのスワップを実行して、最初のサブセットが一致するかどうかを確認します。$n$ポジションが真っ白になります。 これは原理的には機能しますが、次の理由により実行不可能になります。$\binom{200}{100} \approx 9 \cdot 10^{58}$したがって、明示的に列挙することは不可能です。 

重要な洞察は、各交換が最初の 1 つのボトルにのみ影響を与えることを観察することで得られます。$n$ポジション。 まずすべてを確実にするために$n$交換後は位置が白になります。最初にこれらの中に赤いボトルがあるかどうかを確認するだけで済みます。$n$2 番目に対応する白いボトルがある位置$n$それと交換できるポジション。 最初のすべての赤いボトルがあれば$n$にそのようなパートナーがある場合、スワップ ペアを左から右に貪欲に並べ替えることができます。 

同様に、行を左からスキャンできます。 「過剰な赤」の数を追跡します。赤いボトルを見つけるたびに、その数を増やします。 白いボトルが表示されるたびに、カウントを減らします (または、交換する必要がある赤の数を減らします)。 いずれかの時点で、交換される赤の数が右側に残っている白の数を超える場合、交換は不可能です。 これに違反せずに行全体を処理できれば、解決策は存在します。 これにより、問題はテスト ケースごとに 1 つの線形パスに縮小されます。

 | 貪欲なリニアスキャン | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$そして文字列$s$長さの$2n$。 
2. カウンタの初期化`red_needed = 0`。 これは最初の赤いボトルの数を表します。$n$後で白と交換する必要がある位置。 
3. 文字列を左から右に繰り返します。 ポジションごとに$i$0から$2n-1$:

 1. もし`s[i]`は「R」、増分`red_needed`。 この赤は最初の位置から移動する必要があるかもしれません$n$ポジション。 
2. もし`s[i]`'W'、デクリメント`red_needed`正の場合は 1 ずつ増えます。 この白は、前の赤との交換パートナーとして機能します。 
3. いつでも`red_needed`右に残っているポジションの数を超えると、それは不可能です。 正式に言うと、`red_needed > 2n - i - 1 - (n - current_white_count)`、停止して「NO」を返します。 
4. 条件に違反せずに反復が完了した場合は、「YES」を返します。 

機能する理由: 前半の各赤を後半の白と交換する必要があります。 左から右にスキャンし、余分な赤を利用可能な白と一致させることで、必要なすべての交換が確実に実行可能になります。 リニア スキャンにより、障害物を見逃さないことが保証されます。また、不変条件により、`red_needed`利用可能な白を超えることはなく、正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    red_needed = 0
    possible = True
    for i in range(2 * n):
        if s[i] == 'R':
            red_needed += 1
        else:
            if red_needed > 0:
                red_needed -= 1
        # if there are too many reds to be swapped with remaining whites, impossible
        if red_needed > n:
            possible = False
            break
    print("YES" if possible else "NO")
```このソリューションは、単一の線形パスで各テスト ケースを処理します。`red_needed`最初の赤の数を追跡します$n$白人のパートナーを必要とするポジション。 後で白が出現すると、保留中の赤とペアになる可能性があります。 小切手`red_needed > n`これにより、スワップ可能な白の数を決して超えないようにすることができます。 これにより、オフバイワンの間違いが回避され、エッジケースが正しく処理されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        red_needed = 0
        possible = True
        for i in range(2 * n):
            if s[i] == 'R':
                red_needed += 1
            else:
                if red_needed > 0:
                    red_needed -= 1
            if red_needed > n:
                possible = False
                break
        print("YES" if possible else "NO")
    return out.getvalue().strip()
