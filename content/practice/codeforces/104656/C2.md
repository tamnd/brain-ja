 ## 問題の理解

 整数の配列が与えられ、それを正確に分割するように求められます。$k$連続したセグメント。 すべての要素は 1 つのセグメントにのみ属している必要があり、空のセグメントは存在できません。 配列が分割されると、各セグメントはその要素の合計を減算したモジュロとして定義されるスコアを生成します。$p$。 必要な最終値はこれらのセグメント スコアの合計であり、この合計を最大化するパーティションを選択する必要があります。 

目的を言い換えるのに役立つ方法は、$k-1$カット位置、および結果として得られる各ブロックは、小さな数を法とする和に寄与します。$p \le 100$。 各セグメント内にモジュロが存在すると、セグメントを分割すると要素のグループ化方法だけでなく、剰余の動作も変化するため、問題は非線形になります。 

制約は、特定のアルゴリズムの形状を暗示します。 配列の長さは最大 20,000 ですが、$k$すべてのパーティションを試す単純なアプローチでは、指数関数的な効果が得られます。$k$または少なくとも二次関数$n$DP のレイヤーごとに、遅すぎます。 ただし、 の小さな値は、$k$すべてを最初から再計算するのではなく、レイヤーごとにトランジションが最適化される動的プログラミング ソリューションを強く提案します。 

いくつかの特殊なケースは、早期に切り分ける価値があります。 もし$k = 1$、分割はないため、答えは単純に配列全体のモジュロの合計になります。$p$。 単純な DP は依然として分割を試み、誤って無効な遷移を導入する可能性があります。 別の微妙なケースが現れるのは、$k = n$つまり、すべての要素は独自のセグメントである必要があります。 すると、答えは次の合計になります。$a_i \bmod p$また、より長いセグメントに依存するソリューションでも、単一要素セグメントを正しく処理する必要があります。 最後に、DP 遷移内の再計算がボトルネックになるため、大きな値を持つ配列は合計を繰り返し再計算する実装に誤解を与える可能性があります。

重要な観察は、取得するセグメントの数と最後のセグメントの終了場所を固定すれば、最適な部分構造が存在するということです。 プレフィックスを位置まで分割する最適な方法がすでにわかっている場合$i$の中へ$t-1$セグメントに拡張し、$i+1$のために$t$セグメントは、最後のカットが配置された場所にのみ依存します。 これにより、問題は階層化された DP に変換され、各状態が「最初に使用した最適な値」を表します。$i$要素と$t$セグメント」。

 ## アルゴリズムのチュートリアル

 DP テーブルを定義します。$dp[t][i]$プレフィックスを分割することで取得できる最大合計スコアです。$A[1..i]$正確に$t$セグメント。 

1. プレフィックス和の剰余を事前計算する$p$。 させて$pref[i]$なれ$(A_1 + \dots + A_i) \bmod p$。 これにより、定数時間のセグメント クエリが可能になります。 
2. 1 つのセグメントの基本ケースを初期化します。 あらゆる人にとって$i$、$dp[1][i]$単純に$pref[i]$、プレフィックス全体が 1 つのセグメントとして扱われ、そのスコアがその和を法とする 1 つのセグメントとして扱われるためです。$p$。 
3. セグメント数ごと$t$2から$k$、計算する$dp[t][i]$最後のセグメントがどこから始まるかを考慮して。 最後のセグメントが 位置で始まる場合$j+1$の場合、最後のセグメントのスコアは次のようになります。$(sum(j+1..i) \bmod p)$に等しい$(pref[i] - pref[j]) \bmod p$。 
4. トランジションを次のように書き換えます。$$dp[t][i] = \max_{j < i} (dp[t-1][j] + (pref[i] - pref[j]) \bmod p).$$両方への依存$dp[t-1][j]$そして$pref[j]$の残基クラスごとに状態をグループ化することを提案します。$pref[j]$。 
5.固定用$t$、反復します$i$の最良の値を追跡する補助構造を維持しながら、左から右へ$dp[t-1][j] - pref[j]$剰余クラスごとに。 以来$p$小さい場合、可能なそれぞれの最適な値を保存します$pref[j]$モジュロ$p$、進捗に応じて更新します。 
6. これらの維持された最良の値を使用して、それぞれの値を計算します。$dp[t][i]$一定時間内に、なぜなら$i$、式は、最も互換性のある前の残基を選択することになります。 
7. すべてのレイヤーを次の位置まで埋めた後、$k$、答えは$dp[k][n]$。 

正確さは、各セグメントの寄与がプレフィックスの差のモジュロのみに依存するという事実に依存します。$p$、そしてそれらの違いは接頭辞残基によって完全に決定されます。 これにより、以前のすべてのカット位置に対する検索が、残基によってインデックス付けされた状態の制限されたセットに折りたたまれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, p = map(int, input().split())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = (pref[i - 1] + a[i - 1]) % p

    dp_prev = [-10**18] * (n + 1)
    dp_prev[0] = 0

    for t in range(1, k + 1):
        dp = [-10**18] * (n + 1)

        best = [-10**18] * p

        for i in range(1, n + 1):
            j = i - 1

            val = dp_prev[j] - pref[j]
            r = pref[j]
            if val > best[r]:
                best[r] = val

            cur = pref[i]
            dp[i] = best[cur] + pref[i]

        dp_prev = dp

    print(dp_prev[n])

if __name__ == "__main__":
    solve()
```各状態は前の状態にのみ依存するため、実装では 2 つの DP 層のみが保持されます。 配列`best[r]`達成可能な最高の値を保存します$dp[t-1][j] - pref[j]$すべてのポジションの中で$j$そのプレフィックス和モジュロ$p$等しい$r$。 これはまさに、トランジションが以前のカット ポイントをすべてスキャンすることを回避できるようにするものです。 

よくある間違いはアップデートです`best`計算後`dp[i]`。 順序は重要です: 位置を処理するとき`i`、まずインデックスを組み込む必要があります`i-1`遷移に使用する前に構造に追加しないと、正確に終了する有効なパーティションが失われます。`i-1`。

## Edge Cases

A critical edge case is when \(k = 1\). The algorithm collapses to a single DP layer where no transition is performed, and the answer is directly the prefix sum modulo \(p\). The DP initialization already handles this because \(dp[1][n]\) equals the full prefix modulo value.

Another case is when all elements are identical. Here many partitions produce similar segment sums, and a greedy-looking update of `best` can accidentally overwrite optimal states if updates are not ordered carefully. The algorithm avoids this by processing indices in increasing order and only extending from previously finalized prefix positions.

A final subtle case arises when prefix sums wrap around modulo \(p\). Two different prefix indices may share the same residue, and a naive DP that ignores grouping by residue would incorrectly treat them as distinct. The `best[r]` array resolves this by collapsing all such states into a single optimal representative per residue class, ensuring no valid transition is lost.
