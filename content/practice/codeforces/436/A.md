 ## 解決策
 ## 問題の理解

 キャンディーは最大2000個あります。 各キャンディーには、0 または 1 のタイプ、必要なジャンプの高さ、および質量があります。 

オムノムはジャンプ力から始まる`x`。 彼は、最大でも現在のジャンプ力の高さまでの食べ残したキャンディーを食べることができます。 固まったキャンディーを食べた後`m`、彼のジャンプ力は次のように増加します`m`。 

さらに制限が 1 つあります。連続するキャンディーは異なる種類でなければなりません。 最後に食べたキャンディーがタイプ 0 の場合、次に食べるキャンディーはタイプ 1 でなければなりません。逆も同様です。 

目標は、食べたキャンディーの総数を最大化することです。 

制約は驚くほど小さいです。 と`n ≤ 2000`、`O(n²)`このソリューションは約 400 万の操作を実行するため、完全に安全です。 一方、注文数は階乗的に増加するため、すべての有効な食事注文を指数関数的に検索することは不可能です。 

難しいのは、キャンディーを食べると将来の到達可能性が変わることです。 ローカルで良さそうな選択をすると、後でさらに多くのキャンディーのロックが解除される可能性があります。 

簡単な間違いの 1 つは、常に手の届く高さの最小のキャンディーを選択してしまうことです。 

例：```
3 3
0 2 10
1 3 1
1 20 1
```正しい出力:```
2
```先に零式アメを食べるとジャンプ力が13になり、壱種アメも食べられます。 増加した質量ではなく高さに焦点を当てた場合、将来の到達可能性を最大化できない可能性があります。 

もう 1 つの微妙なケースは、最適なシーケンスがどちらのタイプでも開始される可能性があることです。```
2 1
0 1 1
1 100 100
```正しい出力:```
1
```タイプ0から始めるとキャンディーが1つ与えられます。 タイプ 1 から始めるとゼロになります。 固定開始タイプを前提としたソリューションは失敗します。 

3 番目の落とし穴は、必要なタイプの到達可能なキャンディーの中では、どの選択肢を選んでも同じように良いと仮定していることです。```
3 5
0 5 1
0 5 10
1 15 1
```正しい出力:```
2
```最初にタイプ 0 のキャンディーを選択する場合、タイプ 1 のキャンディーのロックがすぐに解除されるため、マス 1 を取るよりもマス 10 を取る方が厳密に優れています。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのステップで、必要なタイプの到達可能なキャンディーをすべて試し、再帰的に実行し、最良の結果を取得します。 これにより、有効な食事の順序がすべて調査されます。 

ブルートフォースはすべての法的シーケンスを明示的にチェックするため、正しいです。 残念ながら、シーケンスの数は膨大です。 数十個のキャンディーでもそれは不可能になります。`n = 2000`それはまったく不可能です。 

何かをより早く手に入れるためには、実際に何が重要なのかを理解する必要があります。 

次のキャンディーはタイプ 0 でなければならないと仮定します。到達可能なすべての未使用のタイプ 0 キャンディーの中から、質量のあるものを選択することを想像してください。`a`一方、別の到達可能な選択肢はより大きな質量を持っています`b`。 

質量の大きいキャンディーを食べると、小さいものを食べる時よりもジャンプ力が大きくなります。 獲得後に到達できるすべてのキャンディー`a`獲得後にも到達可能`b`。 ゲインを大きくしても可能性がなくなることはありません。 

この観察は、重要な貪欲な特性です。 特定の種類のキャンディーを選択する必要がある場合、最良の選択は単純に、最大の質量を持つその種類の到達可能なキャンディーです。 

唯一残る不確実性は先発タイプだ。 タイプが 2 つしかないため、貪欲なプロセスを 2 回シミュレートできます。 

あるシミュレーションでは、最初のキャンディーはタイプ 0 であると主張します。 

他のシミュレーションでは、最初のキャンディーがタイプ 1 であると主張します。 

各シミュレーションについて:

 1. 最大質量を持つ、必要なタイプの未使用の到達可能なキャンディーを繰り返し見つけます。 
2. 食べる。 
3.ジャンプ力を高めます。 
4. 必要なタイプを切り替えます。 

必要なタイプの到達可能なキャンディーが存在しない場合、シミュレーションは終了します。 

答えは、2 つのシミュレーションのより大きな結果です。 この貪欲な戦略は、この問題に対する標準的に受け入れられた解決策です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適な貪欲なシミュレーション | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのキャンディーを読み取り、その種類、高さ、質量を保存します。 
2. 最初に食べたキャンディーがタイプ 0 であると仮定してシミュレーションを実行します。 
3.`used`どのキャンディーがすでに食べられたかを示す配列。 
4. 現在のジャンプ力を次のように設定します。`x`。 
5. しましょう`need_type`次に食べなければいけないタイプです。 
6. すべてのキャンディーをスキャンし、タイプが次の未使用のキャンディーを見つけます。`need_type`、その身長は最大でも現在のジャンプ力であり、その質量はそのようなすべての候補の中で最大です。 
7. 候補が存在しない場合は、このシミュレーションを停止します。 

次のキャンディーには必要なタイプがなければならないため、この時点では合法的な手段はありません。 
8. 選んだキャンディーを食べます。 

ジャンプ力を質量分増加させ、使用済みとしてマークし、このシミュレーションの答えを増加させ、反転します`need_type`。 
9. 手順 6 から繰り返します。 
10. 同じ手順をもう一度実行します。今回はタイプ 1 から始めます。 
11. 2 つの結果のうち大きい方を出力します。 

### なぜ効果があるのか

 次のキャンディーが何らかの固定タイプを持つ必要があるステップを考えてみましょう。 

そのタイプの到達可能なすべてのキャンディーの中で、`A`最大の質量を持つキャンディーになります。 別の到達可能なキャンディーがあるとします。`B`代わりに選ばれます。 

食後`A`、ジャンプ力は少なくとも食後と同じくらい大きくなる`B`。 選択後に到達できるすべてのキャンディー`B`選択後も到達可能`A`。 タイプ変更の要件はキャンディーのタイプのみに依存し、質量には依存しないため、`A`将来の有効な手のセットを減らすことはできません。 

より小さい質量の選択を、到達可能な最大の質量に置き換えても問題はありません。 この引数をすべてのステップに適用すると、固定開始タイプに対して貪欲な選択が常に最適であることが証明されます。 

すべての有効なシーケンスはタイプ 0 またはタイプ 1 のいずれかで開始する必要があるため、両方の開始タイプをチェックすることで、グローバルな最適値が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def simulate(start_type, candies, x):
    n = len(candies)
    used = [False] * n

    cur_jump = x
    need_type = start_type
    eaten = 0

    while True:
        best_idx = -1
        best_mass = -1

        for i, (t, h, m) in enumerate(candies):
            if not used[i] and t == need_type and h <= cur_jump:
                if m > best_mass:
                    best_mass = m
                    best_idx = i

        if best_idx == -1:
            break

        used[best_idx] = True
        cur_jump += candies[best_idx][2]
        eaten += 1
        need_type ^= 1

    return eaten

def solve():
    n, x = map(int, input().split())

    candies = []
    for _ in range(n):
        t, h, m = map(int, input().split())
        candies.append((t, h, m))

    ans = max(
        simulate(0, candies, x),
        simulate(1, candies, x)
    )

    print(ans)

solve()
```シミュレーション機能は貪欲なプロセスを直接実装します。 の`used`配列はキャンディーの再利用を防ぎます。 各ステップで、すべてのキャンディーを検索し、最大質量を持つ必要なタイプの到達可能なキャンディーを選択します。 

証明は将来のジャンプ力の最大化に依存しているため、比較では高さではなく質量が使用されます。 到達可能な最高のキャンディーを選択すると、貪欲なプロパティは保持されません。 

更新の順序は重要です。 まずキャンディーを使用済みとしてマークし、次にその質量をジャンプ力に追加してから、必要なタイプを切り替えます。 これは、問題の一連のイベントと正確に一致します。 

すべての値は Python 整数に簡単に適合します。 極端な場合でも、合計の増加質量は最大でも`2000 × 2000 = 4,000,000`。

# helper: run solution on input string, return output string
import sys
import io

def solve():
    n, x = map(int, input().split())

    candies = [tuple(map(int, input().split())) for _ in range(n)]

    def simulate(start_type):
        used = [False] * n
        cur = x
        need = start_type
        ans = 0

        while True:
            best = -1
            best_mass = -1

            for i, (t, h, m) in enumerate(candies):
                if not used[i] and t == need and h <= cur and m > best_mass:
                    best_mass = m
                    best = i

            if best == -1:
                break

            used[best] = True
            cur += candies[best][2]
            ans += 1
            need ^= 1

        return ans

    print(max(simulate(0), simulate(1)))

def run(inp: str) -> str:
    global input
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    out = io.StringIO()
    old = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = old
    return out.getvalue().strip()
