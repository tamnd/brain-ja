 ## 解決策
 ## 問題の理解

 広告付きの無料バージョンと広告なしの有料バージョンの両方があるモバイル アプリからの収益を最適化するように求められています。 各ユーザーには 2 つの個人制限があります。それは、有料版に支払える金額と、無料版で許容できる広告バナーの数です。 ユーザーが無料版を許容できる場合は、無料版を使用します。 それ以外の場合、有料版を購入する余裕がある場合は、それを購入します。 どちらも受け入れられない場合、ユーザーはアプリを使用しません。 

可能なすべてのバナーの数を計算する必要があります$c$0 からユーザー間の最大許容範囲 + 1、可能な最大の総利益とそれに対応する最適な価格まで$p$有料版の場合。 無料ユーザーが貢献する$c \times w$有料ユーザーが貢献しながら利益を得る$p$。 

制約が教えてくれる$n$まで可能です$10^5$、各ユーザーの支払い意思と許容範囲は次のとおりです。$10^5$。 これだけ多くのユーザーがいる場合、すべての価格を明示的にチェックするアルゴリズムは$p$バナー数ごとに$c$遅すぎるでしょう。 もっと近いものが必要です$O(n \log n)$よりも$O(n^2)$。 また、出力には 1 行につき 1 行が必要です。$c$までの可能性があります$10^5 + 2$線。 これにより、すべてを列挙するアプローチが即座に除外されます。$p$素朴に価値観を持ちます。 

明らかではないエッジ ケースには、ゼロ バナーを許容するユーザー、何も支払うことができないユーザー、およびすべてのユーザーが無料のみまたは有料のみであるシナリオが含まれます。 たとえば、あるユーザーが$a_i = 0$そして$b_i = 0$、別のユーザーが$a_i = 1$そして$b_i = 1$、選択する$c = 0$無料ユーザーから完全に利益を得る可能性があります。 不用意に処理すると、しきい値の平等性が適切に考慮されていない可能性があるため、単純なアルゴリズムにより、どのユーザーが無料になるのか有料になるのかが誤って計算される可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 バナー数ごとに$c$、すべてのユーザーは、状況に応じて無料、有料、または非アクティブのいずれかであると見なされます。$c$そして候補価格$p$。 すべての候補者を試すこともできます$p$ユーザーをソートすることによる値$a_i$そしてテストの閾値。 これは正しいですが、それぞれについて$c$、考えられるすべての価格をテストすると、$O(n^2)$操作、つまり大まかに言うと$10^{10}$最悪の場合、実行不可能になります。 

重要な洞察は、それを一定期間観察することによって得られます。$c$、の利益関数$p$区分的には一定であり、ユーザーの$a_i$価値観。 増えているからです$p$ユーザーの支払い意思をわずかに上回ると、即座に支払い済みから非アクティブになり、減少します。$p$少し下回っても支払う人は変わりません。 ユーザーを並べ替える基準$a_i$そして掃除$p$これらのしきい値を使用すると、合計利益を効率的に計算できます。 無料ユーザーの貢献は以下にのみ依存します。$c$なので、直接追加できます。 これにより、最大でも次のことだけを考慮するため、複雑さが大幅に軽減されます。$n$候補者$p$あたりの値$c$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n log n + n * max_b) | O(n + max_b) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を読み取り、各ユーザーの支払い意思を保存します$a_i$と寛容性$b_i$。 最大値を追跡する$b_i$考慮する必要があるバナー数の範囲を知るために。 
2. ユーザーを前処理します。ユーザーを昇順に並べ替えます。$a_i$。 これにより、候補の価格を効率的に調べ、どのユーザーが有料から非アクティブに切り替わったのかを正確に知ることができます。$p$が増加します。 
3. バナー数ごとに$c$0 から max_b + 1 まで、ユーザーを保証された無料ユーザー ($b_i \ge c$）および潜在的な有料ユーザー（$b_i < c$）。 無料ユーザーの合計利益を c \times w \times \text{num_free} として計算します。 
4. 有料ユーザーの場合は、並べ替えられたリストを繰り返し実行します。$a_i$値を候補価格として使用します。 それぞれについて$p$有料ユーザーと同等$a_i$、総収益を p \times \text{a_i ≥ p のユーザー数} + \text{無料利益} として計算します。 最大の利益をもたらす価格を追跡します。 複数の価格で同じ利益が得られる場合は、どれも有効です。 
5. 最高の利益とそれに対応する価格を保存します。$c$。 全員に繰り返します$c$。 

機能する理由: 並べ替えにより、支払いユーザーのセットが変化する価格のしきい値を見逃すことがなくなります。 を持つユーザーのみを考慮すると、$b_i < c$有料の候補者として、無料版の制約を尊重します。 掃き掃除$p$並べ替えたものの上に$a_i$有料ユーザー数のすべての変化を効率的に捕捉することを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, w = map(int, input().split())
users = [tuple(map(int, input().split())) for _ in range(n)]

max_b = max(b for _, b in users)
count_b = [0] * (max_b + 2)
for _, b in users:
    count_b[b] += 1

# Precompute prefix sums of free users for each c
free_count = [0] * (max_b + 2)
running = 0
for c in range(max_b + 2):
    running += count_b[c]
    free_count[c] = n - running

# Sort users by a_i descending for paid revenue calculation
paid_users = sorted(users, key=lambda x: x[0], reverse=True)
a_list = [a for a, b in paid_users]

for c in range(max_b + 2):
    num_free = free_count[c]
    free_profit = num_free * c * w
    
    max_profit = free_profit
    best_p = 0
    # Number of paid users decreases as p increases
    for i, (a, b) in enumerate(paid_users):
        if b >= c:
            continue
        p = a
        paid_count = i + 1  # because list is descending
        profit = paid_count * p + free_profit
        if profit > max_profit:
            max_profit = profit
            best_p = p
    print(max_profit, best_p)
```説明: それぞれの無料ユーザー数を計算します。$c$プレフィックス合計を使用する$b_i$カウントします。 有料ユーザーは次の基準で並べ替えられます$a_i$これにより、各しきい値価格を検討するときに、何人のユーザーが支払うことになるかを正確に知ることができます。 収益の計算では無料の寄付金と有料の寄付金が加算され、最大値が得られる価格が選択されます。
