 ## 解決策
 ## 問題の理解

 各レベルは、最終的に 3 つの状態のいずれかになります。 

州`0`無視して星を獲得しないことを意味します。 

州`1`星 1 つで完了して消費することを意味します`a[i]`時間。 

州`2`2つ星を獲得してそれを完了し、費やすことを意味します`b[i]`時間。 

レベルは 1 回だけプレイできるため、2 つ星を選択しても支払いを意味するわけではありません**`a[i] + (b[i]-a[i])`。 総費用は単純に`b[i]`。 

星の総数が少なくとも である状態の最終的な割り当てが必要です。`w`合計時間を最小限に抑えながら。 また、最適な割り当てを 1 つ出力する必要があります。 

制約があるからこそ、問題は面白くなります。 まであります`3·10^5`したがって、スターとレベルの数を超える動的プログラミングは完全に不可能です。 たとえ`O(n√n)`解決策は不快になるでしょう。 に近いものが必要です`O(n log n)`。 

微妙な罠は、各星を独立して扱うことです。 考慮する：```
2 2
3 4
2 5
```最も安い星を最初に取ると、最初のレベルのコストに 1 つの星が与えられます。`2`、次にコストの点でもう一つの星`3`、 合計`5`。 ただし、最初のレベルを 2 つ星で直接クリアするのにかかる費用はわずかです`4`。 次の個々のスターだけを見る貪欲な人は失敗する可能性があります。 

もう 1 つの罠は、レベルが 1 つの星を獲得したら、すべての最適なソリューションで少なくとも 1 つの星を維持する必要があると想定していることです。 場合によっては、最適なソリューションが 1 つ星レベルをまったく異なる 2 つ星レベルに置き換えることもあります。 最適なアルゴリズムには、以前の決定を「元に戻す」方法が必要です。 

例えば：```
3 2
1 100
2 3
2 3
```単純なプロセスでは、最初はコストがかかるレベルに達する可能性があります`1`一つ星のために。 後で、その選択を破棄して、次のいずれかを選択する方が良いになります。`b=3`2つ星のレベル。 

## アプローチ

 ブルートフォースの見方はシンプルです。 各レベルには 3 つの可能な状態があるため、`3^n`課題。 各割り当ての合計スターと合計時間を計算し、最も有効な割り当てを維持できます。 すべてをチェックするので、これは明らかに正しいです。 

残念ながら、`3^300000`天文学的を超えています。 

重要な観察は、実際には完全な割り当てを選択しているわけではないということです。 獲得できるスターの合計数は徐々に増加しています。`0`まで`w`。 

すでに最適な構成があり、正確に`k`星。 入手するには`k+1`星のように、いくつかの異なる変更が可能です。 

現在使用されていないレベルには 1 つ星を付けることができます。 

1 つ星レベルを 2 つ星レベルにアップグレードできます。 

「後悔」操作を実行することもできます。つまり、あるレベルから星を削除し、別のレベルを 2 つ星レベルにすることで補うことができます。 このような動きは割り当てを変更しますが、星の総数は 1 つだけ増えます。 

この視点により、問題は、星の数を 1 つ増やすために最も安価な方法を繰り返し購入するという問題に変わります。 問題は、最も安価なアクションには、以前の選択を取り消すことが含まれる可能性があることです。 それが、普通の貪欲が失敗し、後悔の貪欲が成功する理由です。 

結果として得られるソリューションは、追加の星を 1 つ獲得するためのすべての可能な方法を表す 5 つの優先キューを維持します。 反復ごとに、利用可能な最も安価なオプションが選択され、レベルの状態が更新されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^n) | O(n) | 遅すぎる |
 | 後悔貪欲 + 山 | O(w log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 しましょう`star[i]`現在のレベルの状態になります`i`、最初はすべてゼロです。 

5 つのミニヒープを維持します。`q1`未使用のレベルを保存する`a[i]`。`q2`1 つ星のレベルを保存する`b[i]-a[i]`、2つ星にアップグレードするために必要な追加コスト。`q3`未使用のレベルを保存する`b[i]`。`q4`1 つ星のレベルを保存する`-a[i]`。`q5`2 つ星のレベルを保存する`-(b[i]-a[i])`。 

最後の 2 つのヒープは奇妙に見えますが、リグロング操作が可能です。 

それぞれについて、`w`私たちが必要とする星:

 1. 保存された状態がそのレベルの現在の状態と一致しなくなった古いヒープ エントリを削除します。 
2. 星をさらに 1 つ獲得するために考えられる 4 つの方法のコストを計算します。`x1 = min a[i]`未使用レベルの間。 

これは、`0-star`にレベルアップする`1-star`レベル。 
3. コンピューティング`x2 = min (b[i]-a[i])`一つ星レベルの中でも。 

これは、をアップグレードすることを意味します`1-star`にレベルアップする`2-star`レベル。 
4. コンピューティング`x3 = min b[j] - max a[i]`。 

ヒープを使用すると、次のようになります。`q3.top + q4.top`。 

ここでは、以前に選択した 1 つ星のレベルを削除し、代わりに未使用のレベルを 2 つ星の価値のあるものにします。 星の純利益は依然としてちょうど 1 です。 
5. コンピューティング`x4 = min b[j] - max (b[i]-a[i])`。 

ヒープを使用すると、次のようになります。`q3.top + q5.top`。 

ここでは、2 つ星のレベルを 1 つ星にダウングレードし、別の未使用のレベルを 2 つ星に変更します。 
6. 以下から最小のものを選択します`x1`、`x2`、`x3`、 そして`x4`。 
7. 対応する状態遷移を適用し、関連するヒープを更新します。 
8. 選択したコストを答えに追加します。 

後`w`反復では、現在の割り当てには正確に次の内容が含まれます`w`星が付いており、合計時間が最小です。 

### なぜ効果があるのか

 稼いだ後は`k`星がある場合、現在の割り当ては、正確に次の値を持つすべての割り当ての中で最小コストの割り当てです。`k`星。 

上記の 4 つのトランジションは、ある状態から移行するためのあらゆる可能な方法を列挙しています。`k`-star への割り当て`(k+1)`-スターの割り当てにより、以前に選択したレベルを再検討できます。 後悔の転換が重要な部分です。 これらにより、以前のローカルな決定が最適ではなくなった場合でも、アルゴリズムがそれをより適切なグローバル構成に置き換えることができます。 

各ステップで、星を 1 つ増やすできるだけ安価なものを選択します。 以来、`(k+1)`-スターの割り当ては、いくつかの場所から取得できます。`k`これらの遷移タイプのいずれかによる -star 割り当てでは、最小遷移を選択すると最適性が維持されます。 帰納法により、後の割り当ては`w`繰り返しが最適です。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, w = map(int, input().split())

    a = [0] * n
    b = [0] * n

    for i in range(n):
        a[i], b[i] = map(int, input().split())

    star = [0] * n

    INF = 10**30

    q1 = [(INF, n)]
    q2 = [(INF, n)]
    q3 = [(INF, n)]
    q4 = [(INF, n)]
    q5 = [(INF, n)]

    for i in range(n):
        heapq.heappush(q1, (a[i], i))
        heapq.heappush(q3, (b[i], i))

    star.append(-1)  # sentinel

    def clean(heap, need_state):
        while len(heap) > 1 and star[heap[0][1]] != need_state:
            heapq.heappop(heap)

    ans = 0

    for _ in range(w):
        clean(q1, 0)
        clean(q2, 1)
        clean(q3, 0)
        clean(q4, 1)
        clean(q5, 2)

        x1 = q1[0][0]
        x2 = q2[0][0]
        x3 = q3[0][0] + q4[0][0]
        x4 = q3[0][0] + q5[0][0]

        best = min(x1, x2, x3, x4)
        ans += best

        if best == x1:
            _, i = heapq.heappop(q1)

            star[i] = 1

            heapq.heappush(q2, (b[i] - a[i], i))
            heapq.heappush(q4, (-a[i], i))

        elif best == x2:
            _, i = heapq.heappop(q2)

            star[i] = 2

            heapq.heappush(q5, (-(b[i] - a[i]), i))

        elif best == x3:
            _, j = heapq.heappop(q3)
            _, i = heapq.heappop(q4)

            star[j] = 2
            star[i] = 0

            heapq.heappush(q5, (-(b[j] - a[j]), j))

            heapq.heappush(q1, (a[i], i))
            heapq.heappush(q3, (b[i], i))

        else:
            _, j = heapq.heappop(q3)
            _, i = heapq.heappop(q5)

            star[j] = 2
            star[i] = 1

            heapq.heappush(q5, (-(b[j] - a[j]), j))

            heapq.heappush(q2, (b[i] - a[i], i))
            heapq.heappush(q4, (-a[i], i))

    print(ans)
    print("".join(str(star[i]) for i in range(n)))

if __name__ == "__main__":
    solve()
```実装は 4 つの遷移タイプに直接従います。 

遅延削除は不可欠です。 リチャード操作中にレベルの状態が変化するため、レベルはヒープ内に何度も出現することがあります。 古いエントリをすぐに削除するのではなく、ヒープ内に残し、最上位に達したら破棄します。 

山盛り`q4`そして`q5`負の値を保存します。 最小ヒープ`-a[i]`最大のものへのアクセスを提供します`a[i]`、これはまさに後悔の公式が必要とするものです。 同じ考え方が当てはまります`-(b[i]-a[i])`。 

すべての算術演算では Python 整数が使用され、可能な最大の答えが安全に処理されます。 まで`3·10^5`レベルとコストは最大`10^9`、合計の答えは 32 ビットの範囲を超える可能性があります。

 ## 特殊なケース

 次のことを考慮してください。```
1 2
5 10
```唯一可能な割り当ては状態です`2`。 アルゴリズムはまずコストとして 1 つ星を購入します`5`、コストをかけてアップグレードします`5`、総コストに達する`10`。 最初からレベルが 2 つ星レベルとして明示的に選択されていない場合でも、出力は正しいです。 

古典的な貪欲な反例を考えてみましょう。```
2 2
3 4
2 5
```単純な方法はコストを選択します`2`まず、次にコスト`3`、合計を与える`5`。 後悔に貪欲なフレームワークでは、最初のレベルを 2 つの星に直接割り当てるとコストがかかるだけだと考えられます。`4`、安いです。 最終的な答えは、`4`。

1 100
2 3
2 3
```1つ星のコストを取った後`1`、アルゴリズムはリグアロングトランジションを通じてその選択を自由に置き換えることができます。 山盛り`q4`そして`q5`まさにそのような置き換えを可能にするものです。 これらがないと、アルゴリズムは、局所的には最適でも、全体的には次善の構成に陥る可能性があります。
