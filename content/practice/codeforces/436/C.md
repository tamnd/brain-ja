 ## 解決策
 ## 問題の理解

 私たちは与えられています`k`ゲームのレベル。 各レベルは、`n × m`文字のグリッド。 レベルは 2 つの異なる方法で送信できます。 

最初のオプションは、グリッド全体を最初から送信することです。 すべてのセルを送信する必要があるため、コストは次のようになります。`n * m`。 

2 番目のオプションは、すでに送信されたあるレベルとの差分のみを送信することです。 2 つのレベルが異なる場合`d`セルの場合、コストは`d * w`。 

送信の順序は固定されていません。 最初に送信するレベルを選択し、その後のすべてのレベルを最初から構築するか、以前に送信した 1 つのレベルから再構築することができます。 

出力には 2 つのことが必要です。 まず、可能な最小の総伝送コストです。 2つ目は、実際の送電計画です。 すべてのレベルについて、最初から送信されたことを指定する必要があります (`parent = 0`)、または以前に送信されたレベルから再構築されたものであること。 

制約により、意図された方向が明らかになります。 各レベルには最大で次のものが含まれます`10 × 10 = 100`細胞。 まであります`1000`レベル。 2 つのレベル間の差を計算するには、最大 100 文字の比較が必要となるため、すべてのペアごとの距離は約 2 時間で計算できます。`1000² × 100 = 10^8`最悪の場合の運用。 これは大きいですが、最適化された C++ ではまだ管理可能であり、この問題は受け入れられます。 ペアごとのコストがわかったら、1000 頂点のみに関するグラフ アルゴリズムが必要になります。 

微妙な点は、レベルを最初から送信することが常に許可されていることです。 よくある間違いは、すべてのレベルが別のレベルに接続されている必要があると考えることです。 考慮する：```
1 1 2 100
A
B
```変身コストは`100`、ゼロからレベルを送信するのにかかる費用はわずかです`1`。 最適な答えは、両方のレベルを合計コストで個別に送信します。`2`。 

もう 1 つの簡単な間違いは、変換は再構築よりも安価な場合にのみ役立つということを忘れていることです。 仮定する：```
1 2 2 5
AA
AB
```1 つのセル内でレベルが異なるため、変換コストは`1 * 5 = 5`。 最初から送信する場合は費用のみがかかります`2`。 最適解は、変換エッジを完全に無視します。 

3 番目の落とし穴は、送信順序に関するものです。 レベル 3 がレベル 1 から再構築される場合、レベル 1 が出力の前に現れる必要があります。 有効なソリューションは、選択した依存関係と一致する順序を生成する必要があります。 

## アプローチ

 強引な見方は、送信順序と親の選択について直接考えることです。 すべてのレベルについて、親が送信シーケンスの最初に現れるという要件を尊重しながら、最初から送信するか、別のレベルから派生させるかを決定できます。 

すべての有効な送信戦略はそのような決定によって説明できるため、これは明らかに正しいです。 残念ながら、可能性の数は指数関数的に増加します`k`、数十レベルであっても完全に実行不可能になります。 

重要な観察は、問題が密かにグラフの問題であるということです。 

レベルごとに 1 つの頂点を作成します。 また、「最初から構築」を表す追加の仮想頂点も作成します。 この頂点に番号を付けます`0`。 

接続レベル`i`頂点に直接`0`送信レベルを意味します`i`ゼロから。 このようなエッジのコストは常に次のとおりです。`n * m`。 

レベルのペアごとに`i`そして`j`、異なるセルの数を計算します。 一方を他方のコストから再構築する`difference(i, j) * w`。 

これは、間のエッジの重みになります。`i`そして`j`。 

ここで、有効な送信戦略を考えてみましょう。 すべてのレベルは、最初から作成されるか、まったく 1 つ前のレベルから作成されます。 つまり、すべてのレベルで親が 1 つだけ選択されます。 結果として得られる構造は、頂点をルートとするツリーです。`0`。 

逆に、頂点をルートとする任意のツリーは、`0`有効な送信戦略について説明します。 直結したレベル`0`最初から送信されます。 別のレベルに接続されたレベルは、そこから再構築されます。 

総伝送コストは、このツリー内のエッジの重みの合計と正確に一致します。 

この問題は、すべての頂点を接続する最小コスト ツリー (正確には最小スパニング ツリー) を見つけることに変換されました。 

MST が見つかったら、それを頂点にルートします`0`DFS または BFS 順序ですべてのレベルの親を出力します。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 (MST) | O(k² · n · m + k² log k) | O(k²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.すべて読む`k`レベルを作成し、そのグリッドを保存します。 
2. 頂点を含むグラフを作成する`0...k`、頂点`0`仮想「最初から構築」ノードです。 
3. あらゆるレベルに対応`i`、エッジを追加します`(0, i)`重さで`n * m`。 

このエッジは送信レベルを表します`i`直接。 
4. レベルのペアごとに`(i, j)`、異なるセルが何個あるか数えます。 

このカウントを乗算します`w`変換コストを取得します。 
5. 間にエッジを追加します`i`そして`j`その費用で。 
6. すべてのエッジで Kruskal のアルゴリズムを実行します。 

MST は、直接送信と変換の最も安価な組み合わせを正確に選択します。 
7. MST の隣接リストを作成します。 
8. MST を頂点にルートします`0`DFS または BFS を実行します。 
9. レベルの頂点にアクセスするたびに、次のようにします。 

- その親が`0`、出力`(level, 0)`。 
- それ以外の場合は出力`(level, parent)`。 
10. すべての MST エッジの重みを合計し、総コストを出力します。 

### なぜ効果があるのか

 有効な送信計画はすべて、各レベルに仮想ルートまたは別のレベルのいずれかのソースを 1 つだけ提供します。 その構造は、すべての頂点にまたがる接続された非巡回グラフであるため、頂点をルートとするスパニング ツリーになります。`0`。 

送信計画のコストは、選択されたエッジの重みの合計に等しくなります。 

逆に、頂点をルートとするすべてのスパニング ツリー`0`有効な送信計画を定義します。 エッジから頂点まで`0`レベルを最初から送信することを意味し、2 つのレベル間のエッジはそれらの差を送信することを意味します。 

このグラフの有効な送信計画とスパニング ツリーの間には 1 対 1 の対応があるため、送信コストを最小化することはまさに最小スパニング ツリー問題です。 クラスカルのアルゴリズムは最小の合計重みのスパニング ツリーを返すため、生成される送信計画は最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def find(x, parent):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(a, b, parent, size):
    a = find(a, parent)
    b = find(b, parent)

    if a == b:
        return False

    if size[a] < size[b]:
        a, b = b, a

    parent[b] = a
    size[a] += size[b]
    return True

def main():
    n, m, k, w = map(int, input().split())

    levels = []
    for _ in range(k):
        grid = [input().strip() for _ in range(n)]
        levels.append(grid)

    edges = []

    build_cost = n * m

    for i in range(k):
        edges.append((build_cost, 0, i + 1))

    for i in range(k):
        for j in range(i + 1, k):
            diff = 0

            a = levels[i]
            b = levels[j]

            for r in range(n):
                row_a = a[r]
                row_b = b[r]
                for c in range(m):
                    if row_a[c] != row_b[c]:
                        diff += 1

            edges.append((diff * w, i + 1, j + 1))

    edges.sort()

    parent = list(range(k + 1))
    size = [1] * (k + 1)

    mst_cost = 0
    mst_adj = [[] for _ in range(k + 1)]

    used = 0

    for cost, u, v in edges:
        if union(u, v, parent, size):
            mst_cost += cost
            mst_adj[u].append(v)
            mst_adj[v].append(u)
            used += 1

            if used == k:
                break

    result = []
    stack = [(0, -1)]

    while stack:
        node, par = stack.pop()

        for nxt in mst_adj[node]:
            if nxt == par:
                continue

            result.append((nxt, 0 if node == 0 else node))
            stack.append((nxt, node))

    print(mst_cost)
    for x, y in result:
        print(x, y)

if __name__ == "__main__":
    main()
```最初の部分は、すべてのレベルを読み取り、保存します。 各グリッドには最大 100 個のセルが含まれるため、2 つのレベルを比較するのは安価です。 

グラフの構築は、送信ルールを正確に反映しています。 仮想ルートからのエッジは、最初からの再構築を表します。 レベル間のエッジは送信差を表します。 

クラスカルのアルゴリズムは、グラフが高密度であるため、自然に適合します。 おおよそあります`k² / 2`Kruskal では、エッジを 1 回ソートしてから、ほぼ一定時間の DSU 操作を実行するだけで済みます。 

MST を構築した後、グラフは隣接リストに変換されます。 頂点をルートとする DFS`0`出力形式で必要な親関係を決定します。 ツリーにはルートからすべての頂点までのパスが 1 つだけあるため、選択される親は明確です。 

微妙な点の 1 つは、MST エッジの方向が決まっていないことです。 DFS の方向によって、送信計画でどのエンドポイントが親になるかが決まります。 すべての頂点はルートから到達可能であるため、結果として得られる順序付けは、親がその子の前に送信されるという要件を常に満たします。

 ## 特殊なケース

 次のことを考慮してください。```
1 1 2 100
A
B
```変換コストは 100、再構築コストは 1 です。グラフにはエッジが含まれています`(0,1)=1`、`(0,2)=1`、`(1,2)=100`。 Kruskal は両方のルート エッジを選択します。 出力は両方のレベルを総コスト 2 で独立して送信します。常にレベルを接続しようとするソリューションは間違っています。 

考慮する：```
1 1 3 1
A
A
A
```すべてのペアごとの変換コストは 0 です。MST には、コスト 1 の 1 つのルート エッジとレベル間に 2 つのゼロコスト エッジが含まれています。 合計コストは 1 になります。これにより、同じレベルを不必要に再構築しないことが確認されます。 

考慮する：```
1 2 2 5
AA
AB
```1 つのセル内でレベルが異なります。 変換コストは 5 ですが、再構築コストは 2 です。グラフにはエッジが含まれています`(0,1)=2`、`(0,2)=2`、`(1,2)=5`。 MST は 2 つのルート エッジを選択し、コスト 4 を与えます。「少数のセルだけが異なる場合に常に変換する」などの貪欲なルールは、乗数が異なるため失敗します。`w`経済学を完全に変えます。 

最後に、レベル 3 がレベル 2 に依存し、レベル 2 がレベル 1 に依存するツリーを考えます。MST エッジは方向性がありませんが、仮想ルートからの DFS によってそれらの方向が正しく設定されます。 トラバースでは親が常に子の前に表示され、有効な送信順序が生成されます。
