 ## 解決策
 ## 問題の理解

 無限整数ライン上にモンスターを配置しました。 連続したモンスターはすぐにくっついてブロックを形成します。 移動では、ブロック全体を 1 つ選択し、別のブロックと衝突するまで左または右にスライドさせます。 衝突後、2 つのブロックは結合します。 

重要なセルは特別なセルだけです。 一連の動きを実行した後、モンスターが含まれる特別な位置の数を最大化したいと考えています。 

ゲームについて考えるのに役立つ方法は、モンスターを位置で分類し、左から右にラベルを付けることです。 モンスターの順番は変わりません。 ブロックは結合できますが、モンスターが交差することはありません。 すべての最終構成は、「アンカー」として固定されたままのモンスターをいくつか選択することによって記述できますが、2 つのアンカー間のモンスターはいずれかのアンカーに対してしっかりと詰め込まれています。 

入力には最大で次のものが含まれます$10^5$モンスター、ただし最大まで$2000$特別な細胞。 この非対称性こそが問題の鍵なのです。 に比例した作業を実行するソリューション$n^2$は絶望的ですが、$O(nm)$動的プログラムが実行可能な理由は、$10^5 \cdot 2000 = 2 \cdot 10^8$遷移が大幅に最適化されない限り、依然として大きすぎます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

モンスターがすでに連続したブロックを形成していると仮定します。```
monsters: 1 2 3
stars:    1 2 3
```答えは 3 です。モンスターを個別に扱うと、連続するモンスターがすでに接着されているため、不可能な再配置が誤って許可されてしまいます。 

別の微妙なケースは次のとおりです。```
monsters: 10 20
stars:    1 2 3 4
```モンスターは 2 体しか存在しないため、たとえ星が長い間隔を形成していても、最終構成で 2 つ以上の星をカバーすることはできません。 

3 番目のトラップは、スターが元のモンスターの位置に正確にある場合です。 このような星は何も動かさずに数えることができます。 この移行を忘れると、有効な解決策が失われます。 

## アプローチ

 ブルート フォース ビューでは、ブロックのマージと移動をシミュレートしようとします。 ブロックは何度も移動でき、さまざまな順序でマージできるため、状態空間は膨大です。 到達可能なすべての構成を説明するだけでも膨大な量になります。 

最初の構造的観察は、モンスターの順序が決して変わらないということです。 モンスターを左から右に番号を付けると、$i$常にモンスターの左側にいる$i+1$。 

2 番目の観察は、すべての移動の後、マージされた連続モンスターの各グループがセルの連続セグメントを占有することです。 モンスターなら$i$元の位置に留まります$a_i$、左からそれに接続されているモンスターは、で終わるセルを占有します。$a_i$、右から取り付けられたモンスターは、次のセルを占有します。$a_i$。 

これは、分類されたモンスターに対する DP を示唆しています。 

させて$f_i$最初の方法を使用して得られる最良の回答であること$i$モンスター。 

させて$g_i$最初の方法を使用して得られる最良の回答であること$i$そのモンスターを条件とするモンスター$i$それ自体は元の位置に残ります。 

直接実装すると、$O(n^2)$トランジション。 重要な最適化は、次のことだけが存在するという事実から生まれます。$m \le 2000$特別な細胞。 以前のすべてのモンスターを列挙する代わりに、特別なセルを列挙します。 意味のあるすべての移行は、何らかの特別な位置まで適用範囲を拡大することに対応します。 これにより、次からの遷移候補の数が減少します。$O(n)$に$O(m)$モンスターごとに。 承認されたソリューションが実行されます$O(nm)$。

 ## アルゴリズムのチュートリアル

 1. モンスターのポジションと特別なポジションを分類します。 
2. 最大 200000 の座標にわたるプレフィックス配列を構築します。`cnt(l,r)`間隔内の特殊セルの数を返します。$O(1)$。 
3. コンピューティング`L[i]`そして`R[i]`。`L[i]`モンスターと同じ初期接着ブロックに属する一番左のモンスターです`i`。`R[i]`モンスターと同じ初期接着ブロックに属する一番右のモンスターです`i`。 

これらの配列は、すでに接着されているブロックをトランジションが不法に分割するのを防ぎます。 
4. 2 つの DP アレイを維持します。`f[i]`= 最初のものを使用した最良の回答`i`モンスター。`g[i]`= 最初のものを使用した最良の回答`i`モンスターと飼うモンスター`i`位置に固定`a[i]`。 
5. モンスターが配置される簡単な遷移を初期化します。`i`にある星を提供するだけです`a[i]`、そんな星があったら。 
6. コンピューティング`g[i]`。 

すべての特別な位置を列挙する`b[j] ≤ a[i]`。 

で終わるパックされたセグメントが必要な場合は、`a[i]`そしてから始まる`b[j]`、その長さは`a[i] - b[j] + 1`。 

そのセグメントは正確に消費します`a[i] - b[j]`モンスターの左側のモンスター`i`。 

前の状態は、最初に消費されたモンスターを含む接着ブロックの前に終了する必要があるため、`f[L[i-len]-1]`。 
7. すべての左展開遷移が処理された後、伝播します。`g[i]`の中へ`f[i]`。 
8. 使用する`g[i]`右側に範囲を拡大します。 

すべての特別な位置を列挙する`b[j] ≥ a[i]`。 

間隔があれば`[a[i], b[j]]`満たされてから消費されます`b[j]-a[i]`追加モンスター。 

右側で到達した接着ブロック全体に対応する DP 状態を更新します。`R[i+len]`。 
9. 答えは次のとおりです。`f[n]`。 

### なぜ効果があるのか

 有効な最終構成はすべて、元の位置に留まるモンスターを中心に分解できます。 このような 2 つの固定モンスターの間には、すべての中間モンスターが片側にぴったりと詰め込まれていなければなりません。 DP の状態はまさにこれらの状況を説明しています。`g[i]`一番右の固定モンスターがいる構成を表します。`i`。 左を展開すると、次で終わるすべての可能なパックされたセグメントが再構築されます。`a[i]`。 右に展開すると、次から始まるすべての可能なパックされたセグメントが再構築されます。`a[i]`。 の`L`そして`R`修正により、最初に接着されたブロックは決して分解できないというルールが適用されます。 

到達可能なすべての配置にはこれらのパックされたセグメントへの固有の分解があり、すべての遷移では 1 つのセグメントでカバーされるスターが正確にカウントされるため、DP はすべての正当な構成を調査し、違法な構成は決してカウントしません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXX = 200000

def solve():
    n, m = map(int, input().split())

    a = sorted(map(int, input().split()))
    b = sorted(map(int, input().split()))

    pref = [0] * (MAXX + 1)
    for x in b:
        pref[x] += 1
    for i in range(1, MAXX + 1):
        pref[i] += pref[i - 1]

    def count_range(l, r):
        if l > r:
            return 0
        return pref[r] - (pref[l - 1] if l > 1 else 0)

    a = [0] + a

    L = [0] * (n + 1)
    R = [0] * (n + 1)

    for i in range(1, n + 1):
        if i == 1 or a[i] != a[i - 1] + 1:
            L[i] = i
        else:
            L[i] = L[i - 1]

    for i in range(n, 0, -1):
        if i == n or a[i] != a[i + 1] - 1:
            R[i] = i
        else:
            R[i] = R[i + 1]

    f = [0] * (n + 1)
    g = [0] * (n + 1)

    for i in range(1, n + 1):
        star_here = count_range(a[i], a[i])

        f[i] = max(f[i], f[i - 1] + star_here)
        g[i] = max(g[i], f[i - 1] + star_here)

        for x in b:
            if x > a[i]:
                break

            length = a[i] - x
            if length < i:
                left_index = L[i - length] - 1
                g[i] = max(
                    g[i],
                    f[left_index] + count_range(x, a[i])
                )

        f[i] = max(f[i], g[i])

        for x in reversed(b):
            if x < a[i]:
                break

            length = x - a[i]
            if length <= n - i:
                pos = R[i + length]
                f[pos] = max(
                    f[pos],
                    g[i] + count_range(a[i] + 1, x)
                )

    print(f[n])

solve()
```prefix-sum 配列は、インターバルスターのカウントを$O(1)$手術。 これがなければ、すべての遷移で特別なセルを再度スキャンする必要があります。`L`そして`R`実装の中で最もデリケートな部分です。 モンスターが最初に連続した位置を占めている場合、それらはすでに 1 つの接着されたブロックを形成しています。 このようなブロックに入る遷移は、ブロック全体を消費する必要があります。 使用する`L[i-len]-1`そして`R[i+len]`まさにそれを強制します。 

特別なセル上のループは、ソリューションを通過させるための最適化です。 代わりにモンスターを列挙すると、二次関数の動作が発生します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    from collections import deque

    sys.stdin = io.StringIO(inp)

    MAXX = 200000
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = sorted(map(int, input().split()))
    b = sorted(map(int, input().split()))

    pref = [0] * (MAXX + 1)
    for x in b:
        pref[x] += 1
    for i in range(1, MAXX + 1):
        pref[i] += pref[i - 1]

    def cnt(l, r):
        if l > r:
            return 0
        return pref[r] - (pref[l - 1] if l > 1 else 0)

    a = [0] + a

    L = [0] * (n + 1)
    R = [0] * (n + 1)

    for i in range(1, n + 1):
        if i == 1 or a[i] != a[i - 1] + 1:
            L[i] = i
        else:
            L[i] = L[i - 1]

    for i in range(n, 0, -1):
        if i == n or a[i] != a[i + 1] - 1:
            R[i] = i
        else:
            R[i] = R[i + 1]

    f = [0] * (n + 1)
    g = [0] * (n + 1)

    for i in range(1, n + 1):
        here = cnt(a[i], a[i])

        f[i] = max(f[i], f[i - 1] + here)
        g[i] = max(g[i], f[i - 1] + here)

        for x in b:
            if x > a[i]:
                break
            d = a[i] - x
            if d < i:
                g[i] = max(g[i], f[L[i - d] - 1] + cnt(x, a[i]))

        f[i] = max(f[i], g[i])

        for x in reversed(b):
            if x < a[i]:
                break
            d = x - a[i]
            if d <= n - i:
                f[R[i + d]] = max(
                    f[R[i + d]],
                    g[i] + cnt(a[i] + 1, x)
                )

    return str(f[n])

 ## 特殊なケース

 次のことを考慮してください。```
3 3
1 2 3
1 2 3
```すべてのモンスターはすでに 1 つの接着されたブロックに属しています。`L=[1,1,1]`そして`R=[3,3,3]`。 ブロックに入るトランジションは、ブロック全体を自動的に消費します。 DP は正しく返されます`3`ブロックを不正に分割する代わりに。 

考慮する：```
1 1
5
10
```モンスターは1体だけです。 すべての覆われたセルにはモンスターが含まれている必要があるため、位置 10 を含む間隔は形成できません。 すべての遷移はカバレッジを取得できず、答えは残ります`0`。 

考慮する：```
2 4
10 20
9 10 11 12
```不注意な解決法を行うと、星が短い間隔を形成するため、4 つすべての星が数えられる可能性があります。 DP はモンスターの使用状況を明示的に追跡します。 連続する 4 つのマスをカバーするには 4 匹のモンスターが必要ですが、存在するのは 2 匹だけなので、答えは正しく次のように限定されます。`2`。
