 ## 問題の理解

 整数の複数セットが与えられます。値は`i`正確に表示されます`m_i`回。 このマルチセットから、完全に展開された配列のあらゆる可能な並べ替えを検討します。 それぞれの順列について`a`、プレフィックスを左から右にスキャンし、これまでに確認された最小値を追跡することによって定義されたスコアを計算します。 このプレフィックスの最小値が新しい値に減少するたびに、その値がスコアに乗算されます。 同様に、スコアは、スキャン中にプレフィックスの最小値となるすべての個別の値の積です。 

したがって、プレフィックス最小値のシーケンスが`4, 4, 2, 2, 1, 1`、個別の値は次のとおりです。`4, 2, 1`、そしてスコアは彼らの積です。 

タスクは、マルチセットのすべての異なる順列にわたるこのスコアの合計を計算することです。`998244353`。 

入力サイズは 2 つの異なる次元で大きくなります。 個別の値の数`n`テスト全体で 100 万に達する可能性があり、すべての値の多重度の合計は 1,000 万に達する可能性があります。 これにより、順列を反復したり、シーケンスを明示的に構築したりするソリューションは即座に除外されます。 平`O(total permutations)`階乗増加に依存するものは不可能です。 テストごとにほぼ直線的またはほぼ直線的な時間で動作するものが必要です。 

微妙な問題は、スコアが順序付けのグローバル プロパティであるプレフィックス最小値に依存することです。 寄与を値ごとに独立して素朴に扱うことは失敗します。なぜなら、小さな数値を早期に配置すると、大きな数値がすべてプレフィックス最小値になることが抑制されるからです。 

典型的な失敗例は、各値が独立して寄与していると仮定することから生じます。 たとえば、すべての数値が個別である場合、単純な考えでは、プレフィックス最小値になる確率に基づいて各値が寄与するものとして扱われる可能性があります。 しかし、依存関係を順序付けると独立性が損なわれます。`1`他のすべての投稿を早期に完全に削除します。 

## アプローチ

 ブルートフォース手法では、マルチセットのすべての順列を列挙し、それぞれの接頭辞の最小値を計算し、個別の最小値を乗算し、結果を合計します。 中程度のサイズであっても、順列の数が膨大になるため、これは爆発的に増加します。`(sum m_i)! / ∏ m_i!`、これは小さな入力でも天文学的に大きくなります。 順列ごとのプレフィックス最小値の計算は線形であるため、このアプローチは絶望的です。 

重要な観察は、プレフィックス最小プロセスは「レコード最小値」の相対的な順序にのみ依存するということです。 値が現在の最小値になると、その後のすべての寄与は、より小さい値が後で現れるかどうかのみに依存します。 これは、最初に最小値を修正し、最小値の連鎖に影響を与えることなく、より大きな値がどのように表示されるかを推論するという視点を示唆しています。 

考え方を逆転させます。順列を構築する代わりに、最小値から最大値までのプレフィックス最小値のシーケンスを構築します。 値`x`は、ある位置でこれまでに確認された最小値になった場合にのみ積に表示されます。これは、新しいグローバル最小値が正確に最初に発生したことと同等です。`x`。 これは、新しい最小値が現れるまで、それより大きな値がすべてブロックされる構造に対応します。 

値を小さい値から大きい値まで処理します。 現在の価値があると仮定します`i`。 私たちがそう決めたら`i`ある段階では最小値であり、その後はすべての値がそれより大きくなります`i`少なくとも 1 つ配置するまでは無関係です`i`。 これは、現在の最小値が であるシーケンスを構築できる方法の数を維持する DP を示唆しています。`i`等しい値の配置を考慮しながら、それ以上の値になります。 

重要な組み合わせの単純化は、プロセスを新しい最小値で区切られたブロックを構築するものとみなすことです。 新しい最小値を導入するたびに`i`、私たちは事実上、最初の位置を選択しています。`i`以前に配置されたすべての要素に対して相対的に表示されます。 より大きな値の残り​​の出現は、このバリアを超えて自由にインターリーブできます。 これにより、問題は、各最小レベルを導入できる方法の数によって重み付けされた独立した「接尾辞の配置」の寄与を乗算することに帰着します。 

組み合わせを再配置した後、結果は階乗のような寄与を持つ値に対するプレフィックス DP に減ります。ここで、より低い値の最小値によって決定されるスロットにすべてのより高い値を挿入する方法の数を維持し、寄与を乗算して累積します。`i`いつ`i`アクティブミニマムになります。 

これにより、次の線形スイープが得られます。`1`に`n`階乗事前計算と、現在の最小構造と一致する順列の数を追跡する実行中の組み合わせ係数を使用します。

 ## アルゴリズムのチュートリアル

 以下の値を処理します。`n`まで`1`、すでに処理された大きな値を、小さな値がまだ強制的に表示されていないシーケンスに配置できる方法が何通りあるかを維持します。 

多項係数が繰り返し必要になるため、全長まで階乗と逆階乗を事前計算します。 

実行中の変数を維持します`ways`、最初は次と等しい`1`、空のセットを配置する方法の数を表します。 メンテナンスも行っております`remaining`、現在のインデックスより大きい値によって現在埋められているポジションの数。 

それぞれの値について`i`から`n`まで`1`、次のことを行います。 

1. すべてのコピーを挿入することを検討します。`i`より大きな要素の現在の配置に組み込まれます。 がある`remaining + m_i`挿入後の合計スロットの位置を選択します。`m_i`のコピー`i`。 これは二項因子に寄与します`C(remaining + m_i, m_i)`。 
2. これらすべての取り決めの中で、価値があるのは、`i`が最初に出現した時点で、新しい可能なプレフィックスの最小値になります。`i`は、より小さい値 (この逆スイープにはまだ挿入されていません) の前に配置されます。 これは次の乗算係数に寄与します。`i`構成のスコアに`i`最小境界としてアクティブになります。 
3. 価値から貢献を乗算して実行中の答えを更新します`i`そのレベルで最初のアクティブな最小値となる構成の数によって重み付けされます。 
4. 次に増加します`remaining`による`m_i`、これらの要素は、将来の (より小さい) 値に使用できる構築されたサフィックスの一部になっているためです。 

すべての値を処理した後、累積された合計が最終的な答えになります。 

### なぜ効果があるのか

 核となる不変条件は、処理後の値が次の値を超えることです。`i`、これらの値のすべての有効な部分順列は、次のように均一に表されます。`ways`であり、すべての構成は同じ組み合わせの重みを持ちます。 値を挿入するとき`i`、すべてのインターリーブを正確に列挙しています。`i`二項係数は、二重にカウントすることなく、可能なすべての配置を考慮します。 プレフィックス最小値は降順の値の相対的な順序にのみ依存するため、より小さい値を導入するたびに、それが最小チェーンの一部になるかどうかを正確に識別し、有効な順列はすべて、累積加重和に 1 回だけ寄与します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    
    # constraints across tests
    maxN = 10**6
    maxM = 10**7
    
    # precompute factorials once
    # since sum over tests is large, we allocate up to max total size
    N = 10**6 + 5
    
    fact = [1] * (N)
    inv = [1] * (N)
    invfact = [1] * (N)
    
    for i in range(2, N):
        fact[i] = fact[i - 1] * i % MOD
    
    inv[1] = 1
    for i in range(2, N):
        inv[i] = MOD - MOD // i * inv[MOD % i] % MOD
    
    for i in range(2, N):
        invfact[i] = invfact[i - 1] * inv[i] % MOD
    
    for _ in range(t):
        n = int(input())
        m = list(map(int, input().split()))
        
        total = sum(m)
        
        ways = 1
        rem = 0
        ans = 0
        
        for i in range(n, 0, -1):
            c = m[i - 1]
            if c == 0:
                continue
            
            ways = ways * fact[rem + c] % MOD
            ways = ways * invfact[rem] % MOD
            ways = ways * invfact[c] % MOD
            
            ans = (ans + ways * i) % MOD
            
            rem += c
        
        print(ans % MOD)

if __name__ == "__main__":
    solve()

アップデート`ways = ways * C(rem + c, c)`階乗比によって実装され、以前に配置された要素と新しい値グループのすべてのインターリーブが確実にカウントされます。 答えは溜まっていく`i * ways`それぞれの価値観があるので、`i`すべての有効な取り決めにわたって、潜在的な新しいプレフィックスの最小境界として機能します。 

よくある落とし穴はアップデートです`rem`寄与を計算する前に実行してください。これにより、組み合わせ境界が誤ってシフトされてしまいます。 順序は重要です。`ways`現在のブロックを挿入する前に構成を表す必要があります。

 ## 特殊なケース

 重要なエッジケースは、すべての質量が大きなインデックスに集中している場合です。`m[n] = 10^7`そして他のすべてはゼロです。 この場合、寄与する値は 1 つだけなので、答えは次のようになります。`n * 1`、すべての順列が同一のプレフィックス最小構造を持つためです。

最後のエッジケースは、非常に大きな合計額を処理することです。`m_i`。 階乗配列のサイズは、合計ではなく合計に基づいて設定する必要があります。`n`そうでない場合、二項係数は静かにオーバーフローするか、不正確になります。
