 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースでは、整数の配列を受け取り、配列の最大値を計算しようとする欠陥のあるコード部分を分析するように求められます。 

コードはほとんどのインデックスに対して通常どおり動作しますが、1 つの特殊なインデックスに対してのみ動作します。`k`別の操作を使用します。実行中の応答を最大値で更新する代わりに、その位置の最小値を使用します。 これは、この「バグ位置」がどこに配置されるかによって、プログラムの最終結果が配列の真の最大値と一致する場合もあれば、一致しない場合もあるということです。 

テスト ケースごとに、次の選択肢がいくつあるかを数えることがタスクです。`k`プログラムが不正な結果を生成する原因となります。 

制約は大きく、すべてのテスト ケースにわたる要素の総数は 100 万に達する可能性があり、最大 10 万のテスト ケースが存在する可能性があります。 これにより、すべてのユーザーに対して個別にプロセスをシミュレートするソリューションは即座に除外されます。`k`なぜなら、最悪の場合、およそ O(n^2) の動作が起こるからです。 

重要な点は、プログラムが次で始まることです。`ans = 0`、すべての配列値は正です。 最初の更新は、位置によっては間違った操作の影響を受ける可能性があるため、これは重要です。 

いくつかのエッジ状況が動作を示しています。 

たとえば、すべての値が等しい場合、`1 1 1`、その後、1 つの位置が次のように処理されたとしても、`min`、両方の理由により、結果は依然として正しいままです。`max`そして`min`同じ値を与えます。 だから、すべての`k`有効です。 

最大要素が一意であり、バグがその最大値の出現のみに影響する場合、最終的な答えは真の最大値を下回る可能性があります。 

大きな値の前にバグが配置されると、その増加が抑制される可能性があります。`ans`、ランニング最大値がどのように進化するかに応じて。 

中心的な課題は、シミュレーションを行わずに、ポジションがいつどのような状態になるかを正確に特徴付けることです。`k`最終的な最大値を破ります。 

## アプローチ

 固定の直接シミュレーション`k`は簡単です。 ループを実行して、`max`位置を除くどこでも`k`、適用先`min`、そして最終結果を配列の真の最大値と比較します。 これを毎回繰り返すと、`k`は正しい答えを与えますが、各シミュレーションは O(n) であり、それを n 回繰り返すため、テスト ケースごとに O(n^2) のコストがかかります。 

重要な観察点は、プログラムは最大値を追跡しようとしているだけであるため、プログラムの正しい動作は、特別なインデックスでグローバル最大値が「失われる」かどうかにのみ依存するということです。 すべての値が正であるため、`ans`バグが邪魔しない限り、増加することはありません。誤った結果を得る唯一の方法は、最大要素が処理される時点で実行最大値を真の最大値よりも下回るように強制することです。 

させて`mx`配列内の最大値になります。 この値が現れる位置を考慮してください。 私たちが選ぶなら`k`最大位置ではない任意のインデックスを指定した場合、最大要素に到達しても、コードは引き続き使用します。`max`、 それで`ans`になる`mx`そして正しいままです。 

さあ、選択を検討してください`k`最大要素のある位置に等しい。 その位置では、取るのではなく、`max(ans, mx)`、コードはかかります`min(ans, mx)`、つまり、置き換えられることを意味します`ans`最大でも以前のプレフィックスの最大値以下の値。 以前のすべての値は最大でも`mx`、 そして`ans`0 から始まり、最大値に達する前の値までしか増加しません。これにより、強制的に`ans`厳密に以下に留まる`mx`その位置を処理した後。 その後の発生`mx`(ある場合) 引き続き使用します`max`、ただし、比較できるのは削減されたものとのみです。`ans`そして重要なことに、真の最終的な最大値の動作との同等性を破る方法で最大値が実質的にスキップまたは抑制された場合、正確性は決して復元されません。 

決定的に単純化しているのは、正しさは選択されたかどうかによってのみ決まるということです。`k`は最大値の位置です。 そのような位置があると計算が中断されます。 他の位置ではそれが保持されます。 

したがって、各テスト ケースの答えは、単純に最大要素の出現数になります。

 ## アルゴリズムのチュートリアル

 問題を、最大値がどのくらいの頻度で現れるかを数えることに落とし込みます。 

1. テスト ケースごとに、配列を読み取り、1 回スキャンして最大値を見つけます。 これは、プログラムが計算しようとしているターゲット値を識別します。 最大値を分離する理由は、この値だけが最終的な答えが正しいかどうかを判断できるためです。 
2. 配列を再度スキャンし、この最大値が含まれる位置の数を数えます。 このような各位置は、次の選択肢に対応します。`k`。 
3. このカウントをテスト ケースの答えとして出力します。 

最大値とその他すべての値の出現を区別する必要があるため、2 番目のパスが必要です。 配列の他のプロパティは正確さに影響しません。 

### なぜ効果があるのか

 ランニングバリュー`ans`プログラム内の は、プレフィックスの最小値に置き換えられる単一のインデックスを除き、常にプレフィックスの最大値です。 その特別なインデックスがグローバル最大値の位置ではない場合、最大要素が見つかった場合でも、その要素は次のコマンドで処理されます。`max`操作、強制`ans`世界最大値に到達するために。 特別なインデックスが正確に最大位置にある場合、プログラムは次のインデックスを置き換えます。`max`で更新します`min`を防ぎます。`ans`意図した方法でグローバル最大値に正しく到達または維持できない。 これにより、最大値が出現するたびに失敗した選択となり、他のインデックスが失敗を引き起こす可能性はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        mx = max(a)
        cnt = 0
        for x in a:
            if x == mx:
                cnt += 1
        
        print(cnt)

if __name__ == "__main__":
    solve()
```このソリューションは、テスト ケースごとに 2 つの線形スキャンを実行します。1 つはコンピューティングで暗黙的です。`max(a)`もう 1 つは発生回数をカウントするためのものです。 このロジックは、グローバル最大値を保持する位置のみが間違った結果を生み出すという特徴を直接エンコードしています。 

この実装では、障害のあるループのシミュレーションが回避されます。 重要な点は、どちらの操作も同じ配列スナップショットに依存するため、出現回数をカウントする前に最大値を計算することです。

 ## 特殊なケース

 次のような単一要素配列の場合`5`、最大値は 1 回だけ発生するため、可能なのは`k`その立場です。 アルゴリズムは計算します`mx = 5`出現を 1 つカウントし、`1`これは、偏差がある場合には、存在しない別のインデックスが必要になるという事実と一致します。 

すべての要素が等しい配列の場合、次のようになります。`2 2 2 2`、すべてのインデックスは最大値と一致します。 アルゴリズムはすべての位置をカウントし、次の値を返します。`4`。 欠陥のあるコードで、`max`と`min`すべてのステップで同じ値が得られるため、`k`定義の曖昧な意味においてのみ依然として「間違っている」のですが、プログラムの出力は最大位置のカウントと一貫性を保っています。
