 ## 解決策
 ## 問題の理解

 長さの配列が与えられます`n`ここで、位置の値は`i`は`i-1`、したがって配列は次のように固定されます`[0, 1, 2, ..., n-1]`。 タスクは、すべての連続する部分配列を考慮し、その要素のビットごとの XOR を計算し、それらの XOR 結果をすべて合計することです。 

したがって、すべてのペアについて`(l, r)`と`1 ≤ l ≤ r ≤ n`、評価します`a[l] XOR a[l+1] XOR ... XOR a[r]`そしてそれをグローバル合計に加算します。 出力はこの合計モジュロです`998244353`。 

重要な難点は、`n`と同じ大きさにすることができます`10^9`、最大まであります`10^5`テストケース。 これにより、サブ配列を反復したり、個々の要素に触れたりするソリューションは即座に除外されます。 たとえ`O(n)`テストケースごとのアプローチは不可能です。`10^14`合計の操作。 

微妙なエッジ ケースは、連続する整数の範囲にわたる XOR がバイナリで、特に 2 の累乗付近で不規則に動作することです。 「ほとんどのビットがキャンセルされる」などの単純なパターンベースの仮定はすぐに失敗します。 たとえば、次のような小さなセグメント`[1,2,3]`すでに自明ではない XOR 相互作用が発生しており、より長い範囲は単純な等差数列に安定しません。 

もう 1 つの落とし穴は、寄与をカウントせずにプレフィックス XOR が直接役立つと想定していることです。 プレフィックス XOR は範囲 XOR クエリを削減します。`O(1)`、まだすべてを集計する必要があります`(l, r)`ペア。これは、単一のクエリではなく、組み合わせの合計です。 

## アプローチ

 ブルート フォース アプローチでは、すべての開始インデックスのプレフィックス XOR を計算し、それをすべての終了インデックスに拡張します。 それぞれについて`l`、実行中の XOR を次のように維持します。`r`増加して答えに追加します。 これはすべてのサブ配列を正しく列挙しますが、パフォーマンスは大まかです`n(n+1)/2`テスト ケースごとの XOR 演算。 と`n`まで`10^9`、これはまったく実行不可能です。`n = 10^5`すでに約が必要になります`5 × 10^9`操作。 

重要な観察は、XOR がビットごとに独立しているため、問題全体を各ビット位置からの寄与に個別に分解できることです。 完全な数値を追跡する代わりに、各ビットが寄与する頻度を追跡します。`1`部分配列の XOR に変換します。 

どんなビットでも`k`、バイナリ配列を定義します`b[i]`どこ`b[i] = 1`もし`k`-番目のビット`i-1`が設定されています。 サブ配列の XOR にはビットがあります`k`次の合計の場合にのみ設定します`b`その部分配列の値は奇数です。 したがって、問題は、各ビット位置に奇数の 1 を持つサブ配列がいくつあるかを数えてから、次の値を掛けることになります。`2^k`。 

これにより、プレフィックス パリティ カウントの問題が軽減されます。 ビットごとに、プレフィックスのパリティ状態を追跡し、異なるパリティを持つプレフィックスのペアをカウントします。 以来`a[i] = i-1`、各ビットは周期のある周期パターンを形成します。`2^(k+1)`、これにより、長さのプレフィックスにわたる貢献をカウントできます`n`で`O(1)`ビットあたり。 

以来`n ≤ 10^9`、約 30 までのビットだけが必要です。

 ## アルゴリズムのチュートリアル

 各ビットを個別に処理し、その寄与を合計します。 

1.固定ビットの場合`k`、値の順序を考慮します。`a[i] = i-1`ビットを抽出します`k`が設定されています。 これにより、周期のある繰り返しパターンが形成されます`2^(k+1)`、からなる`2^k`ゼロが続く`2^k`もの。 この構造はバイナリ カウンティングから直接得られます。 
2. しましょう`cnt1`プレフィックス内の位置の数になります`[0, n-1]`どこビット`k`は`1`。 これは、全サイクルと剰余を使用して計算されます。 それぞれの完全なサイクルが正確に寄与します`2^k`残りの部分は同じパターンのプレフィックスに寄与します。 
3. サブ配列の XOR にはビットがあります`k`に等しい`1`その部分配列内の 1 の数が奇数の場合。 サブ配列を直接追跡する代わりに、プレフィックス パリティを使用します。 プレフィックスパリティをインデックスまでのパリティとして定義します`i`。 
4. 奇数パリティを持つサブ配列の数は、プレフィックス インデックスのペアの数に等しい`(i, j)`パリティが異なる場合。 パリティを持つプレフィックスの数を数えると`0`そして何人がパリティを持っていますか`1`、 言う`c0`そして`c1`の場合、有効な部分配列の数は次のようになります。`c0 * c1`。 
5. このビットについて、答えへの寄与は次のとおりです。`c0 * c1 * (1 << k)`。 
6. これをすべてのビットで合計します`k`から`0`に`30`、すべてを剰余として計算します`998244353`。 

### なぜ効果があるのか

 セグメント上の XOR は 2 つのプレフィックス状態の XOR と同等であるため、サブ配列 XOR からプレフィックス パリティへの変換は正確です。 これにより、各サブ配列がプレフィックスのペアに一意に対応するようになります。 ビット分解ではビット間の独立性が維持されるため、ビットごとの寄与を合計すると、相互作用項のない完全な XOR 合計が再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def count_ones(n, k):
    """count ones in bit k over [0, n-1]"""
    if n <= 0:
        return 0
    period = 1 << (k + 1)
    full = n // period
    rem = n % period
    ones_in_full = full * (1 << k)
    ones_in_rem = max(0, rem - (1 << k))
    return ones_in_full + ones_in_rem

def solve(n):
    ans = 0
    for k in range(31):
        ones = count_ones(n, k)
        zeros = n - ones
        ans = (ans + ones * zeros % MOD * ((1 << k) % MOD)) % MOD
    return ans

t = int(input())
for _ in range(t):
    n = int(input())
    print(solve(n))
```コードはビットごとの分解を直接実装します。 機能`count_ones`に数値がいくつあるかを計算します`[0, n-1]`周期構造を使用して特定のビットを設定します。 各ビットは独立して寄与し、乗算します`ones * zeros`なぜなら、そのようなプレフィックス パリティの各ペアは、そのビットが XOR 結果に現れる部分配列を誘導するからです。 

の乗算`2^k`寄与をその数値に戻します。 すべてはモジュロで実行されます`998244353`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MOD = 998244353

    def count_ones(n, k):
        if n <= 0:
            return 0
        period = 1 << (k + 1)
        full = n // period
        rem = n % period
        ones_in_full = full * (1 << k)
        ones_in_rem = max(0, rem - (1 << k))
        return ones_in_full + ones_in_rem

    def solve(n):
        ans = 0
        for k in range(31):
            ones = count_ones(n, k)
            zeros = n - ones
            ans = (ans + ones * zeros % MOD * ((1 << k) % MOD)) % MOD
        return ans

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str(solve(n)))
    return "\n".join(out)

 ## 特殊なケース

 のために`n = 1`、配列は`[0]`そして、XOR が次であるサブ配列は 1 つだけあります。`0`。 このアルゴリズムはビットごとに 0 と 0 を計算するため、すべての寄与はゼロとなり、期待される結果と一致します。 

小型用`n`のように`2`または`3`、ビットパターンはまだ完全に周期的ではありません。 この方法は完全なサイクルと剰余に分割され、剰余の計算で部分ブロックが正しく処理されるため、引き続き機能します。 たとえば、`n = 3`、 少し`0`模様がある`0,1,0`、有効な不均衡が 1 つ生成されますが、プレフィックスベースのカウントでは依然として正しい数が得られます。`(ones, zeros)`最終的な合計に寄与するペア。
