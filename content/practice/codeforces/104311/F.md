 ## 解決策
 ## 問題の理解

 同じサイズの 2 つのバイナリ グリッドが与えられ、それらを開始グリッドとターゲット グリッドと呼びます。 唯一許可される移動は、同じ長さの連続したセグメントを選択することです。`l`行内で水平方向に、または列内で垂直方向に、そのセグメント内のすべてのビットを反転します。 反転とは、0を1に、1を0に変えることです。 

問題は、このようなセグメントの反転を何度でも行った後、開始グリッドをターゲット グリッドに正確に変換できるかどうかです。 

主な難点は、操作が重複し、相互作用することです。 セグメントの反転は一度に複数の位置に影響を及ぼし、複数のセグメントが同じセル上に重なって反転がキャンセルまたは強化される可能性があるため、セルを独立して制御することはできません。 

この制約では、最大 100 のテスト ケースが許可され、すべてのテストにわたるセルの合計数は最大 1000 です。これは、テストごとに線形または線形に近いことが必要になるには十分小さいですが、フリップの構成にわたる指数関数的な状態の探索には大きすぎます。 

素朴な解釈では、考えられるすべての操作シーケンスをシミュレートするか、各セルを独立して処理しようとします。 操作の数に制限がなく、相互作用がグローバルであるため、どちらも失敗します。 

次の場合、微妙なエッジケースが発生します。`l = 1`。 この場合、すべての操作で 1 つのセルが反転されるため、任意のグリッドを他のグリッドに変換できます。 近隣者間の相互作用を想定した不注意な解決策は、このケースを誤って拒否する可能性があります。 

もう 1 つのエッジケースは次のような場合です`l = n`または`l = m`。 その後、各操作は列全体または行全体のフリップ セグメントになり、問題は行または列ごとのグローバル パリティ制約に軽減されます。 これをローカル伝播の問題として扱うと失敗します。 

## アプローチ

 ブルート フォース パースペクティブは、許可された各セグメントをセルのサブセットを切り替える操作として扱います。 各状態が完全なグリッド構成であり、エッジが有効な反転を表すグラフを構築することを想像できます。 状態の数は`2^(n*m)`、各状態に多くの遷移があるにもかかわらず、このグラフを探索することは完全に不可能です。 

セルごとの推論に限定したとしても、依然として依存関係に直面します。1 つのセグメントを反転すると複数のセルに影響し、それらのセルが将来の有効な操作に影響します。 フリップのシーケンスをシミュレートしようとすると、指数関数的に爆発してしまいます。 

重要な観察は、フリップがバイナリ フィールドに対する XOR 演算のように動作することです。 各操作は固定パターンを切り替えます。操作を任意の順序で適用することは、XOR が差分グリッドと一致する操作のサブセットを選択することと同じです。`a XOR b`。 

これにより、問題は、差分グリッドが許可されたセグメントの (GF(2) 上の) 線形結合として表現できるかどうかを判断することに変わります。 セグメントの構造は非常に規則的なシステムを形成しており、グローバルな組み合わせについて推論する代わりに、グリッドを貪欲に処理して、必要な反転を左上から右下に伝播させることができます。 

重要な考え方は、ある位置から開始するセグメントを適用するかどうかを決定すると、その効果はそのスパン内のセルにのみ影響し、行ごと、列ごとに一貫性を強制できるということです。 

私たちは問題を、決定論的な順序で貪欲に修正することですべての不一致を排除できるかどうかをチェックし、すべての強制された反転が範囲内で有効であることを確認することに集約します。

 ## アルゴリズムのチュートリアル

 まず差分グリッドを計算します`d`、 どこ`d[i][j] = a[i][j] XOR b[i][j]`。 目標は、すべてのものを排除することです`d`許可されたセグメント反転を使用します。 

グリッドを左上から右下に処理し、セルに到達した時点で、以前のセルに影響を与える可能性のあるすべての操作がすでに決定されているという考えを維持します。 

1. 各セルについて`(i, j)`、 もし`d[i][j] == 0`、何もせずに続行します。 
2. もし`d[i][j] == 1`場合は、このセルをカバーする有効な操作を使用して修正する必要があります。 候補は 2 つあります。 から始まる水平セグメントです。`(i, j)`もし`j + l <= m`、またはで始まる垂直セグメント`(i, j)`もし`i + l <= n`。 
3. どちらのセグメントも適合しない場合、このセルを修正することはできず、すぐに「いいえ」を返します。 これは、今後の操作が影響を与える可能性がないためです。`(i, j)`すでに処理された制約にも違反することなく。 
4. 水平セグメントが有効な場合は、すべてを反転して適用します。`d[i][j .. j+l-1]`。 
5. それ以外の場合は、すべてを反転して垂直セグメントを適用します。`d[i .. i+l-1][j]`。 
6. すべてのセルが処理されるまで続行します。 

常に最も早い未解決のセルを解決するため、順序は重要です。 これにより、後の操作で以前に固定されたグリッドのプレフィックスが無効になることがなくなります。 

### なぜ効果があるのか

 各操作は接続されたブロックを反転しますが、すべてのセルはスキャン順序の固有の最も早い位置で最初に検出されます。 その時点で、不一致を修正する唯一の方法は、そのセルに固定されているセグメントを選択することです。これは、後で開始するセグメントではそれをカバーできず、より早く開始するセグメントはすでに決定されているためです。 

これにより、貪欲な一意性の特性が強制されます。セルに初めて修正が必要な場合、決定的な選択肢は最大 2 つあり、どちらかが一貫した拡張につながるか、解決策が存在しません。 XOR 構造により、この貪欲な順序で操作を適用する場合にバックトラッキングが不要になります。これは、2 回反転するとキャンセルされ、すべての効果が線形になるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, l = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]
        b = [list(map(int, input().split())) for _ in range(n)]

        d = [[a[i][j] ^ b[i][j] for j in range(m)] for i in range(n)]

        ok = True

        for i in range(n):
            for j in range(m):
                if d[i][j] == 0:
                    continue

                # try horizontal
                if j + l <= m:
                    for k in range(j, j + l):
                        d[i][k] ^= 1
                elif i + l <= n:
                    for k in range(i, i + l):
                        d[k][j] ^= 1
                else:
                    ok = False
                    break

            if not ok:
                break

        print("YES" if ok and all(all(row == 0 for row in d[i]) for i in range(n)) else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは、差分グリッドを構築し、遭遇したものを貪欲にクリアします。 可能であれば水平方向の反転が推奨されますが、現在のセルをカバーする限り、どちらの選択も有効です。 最終的な検証により、不一致が残らないことが確認されます。 

微妙な点は、セグメント反転をすぐに完全に適用する必要があることです。 更新を遅らせたり、グリッドを更新する代わりにパリティをカウントしようとすると、将来の決定は更新された状態に依存するため、正確性が損なわれます。 

強制的な障害が検出されると早期終了が発生する可能性があるため、最終的なフルグリッド チェックが必要ですが、部分的な処理では依然としてゼロ以外のエントリが残る可能性があります。

 ## 特殊なケース

 いつ`l = 1`、すべての操作で 1 つのセルが反転されます。 水平セグメントまたは垂直セグメントは常に長さ 1 で存在するため、アルゴリズムはすべての不一致をローカルに修正可能なものとして正しく処理します。したがって、どのグリッドも他のグリッドに変換でき、貪欲ループは各セルを個別にクリアすることになります。 

いつ`l`全幅または全高に等しい場合、フリップは行または列セグメント全体に及びます。 セルごとに利用できる方向は 1 つだけであるため、アルゴリズムはこれを自然に処理し、一貫した伝播を強制します。 長さのセグメントが存在しない位置に不一致が発生した場合`l`適合する場合、アルゴリズムは正しく即座に拒否します。 

最後など、不一致が境界付近に集中している場合`l-1`列または行を使用すると、アルゴリズムは有効なセグメントでカバーできないセルに遭遇する可能性があります。 これらのケースは、処理された瞬間に正確に検出されます。`i + l > n`そして`j + l > m`失敗し、正しい初期の「NO」が生成されます。
