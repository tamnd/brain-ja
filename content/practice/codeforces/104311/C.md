 ## 問題の理解

 同じ長さの 2 つのバイナリ配列が与えられます。 各配列から 1 つの連続セグメントを選択できます。各セグメントの唯一の制限は、その長さが指定された範囲内に収まらなければならないことです。 2 つのセグメントを選択した後、それらの両方に含まれる 0 と 1 の数を合計して数えます。 目的は、0 の合計数が 1 の合計数と等しくなるような 2 つのセグメントの選択肢が存在するかどうかを判断することです。 

条件を書き直す便利な方法は、バランスの観点から考えることです。 どのセグメントでも、その値を 1 の数から 0 の数を引いたものとして定義します。 選択した両方のセグメントにわたって合計 0 が合計 1 に等しいという要件は、これら 2 つのセグメント値の合計が 0 であるという要件とまったく同じです。 したがって、配列内の 1 つのセグメントを探しています`a`配列内の 1 つのセグメント`b`、それぞれの長さの制約内で、その「不均衡」が完全に相殺されるようにします。 

この制約により、すべてのセグメントに対する総当たり攻撃は不可能になります。 各配列にはテスト ケース全体で最大 200,000 個の要素があり、テスト ケースは最大 100,000 個あります。 テスト ケースごとのセグメントの二次列挙でさえ、実行可能な制限をはるかに超えます。 テスト ケースごとのリニア スキャンは、すでに意図したスケールになっています。 

一般的な障害モードは、セグメントが 2 つの異なるアレイからのものであることを無視することです。 単純な解決策では、1 つの配列内のすべてのセグメントの合計を事前に計算し、それらをもう 1 つの配列と照合しようとする可能性がありますが、長さの制約を忘れると正確さが失われます。 もう 1 つの微妙な間違いは、プレフィックスの合計のみを考慮するか、最小および最大のセグメントの合計のみを考慮することです。 どちらも、ここでは重要な、許可されたセグメント長への依存性を失います。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての有効なセグメントを列挙します。`a`長さは次の間です`x1`そして`y1`、その残高を計算し、すべての有効なセグメントを列挙します。`b`長さは次の間です`x2`そして`y2`、その残高を計算し、ペアの合計がゼロになるかどうかを確認します。 これは定義に直接従っているため機能しますが、遅すぎます。 最悪の場合、各配列には O(n²) 個のセグメントがあるため、慎重に実装したとしても、単純なクロス積ビューでは比較の総数は O(n⁴) になります。 

重要な観察は、この条件が変換された配列のセグメントの合計にのみ依存するということです。 各バイナリ配列を配列に変換すると、`0 → -1`そして`1 → +1`の場合、すべてのセグメントの合計が正確にその残高となります。 問題は、各配列から 1 つずつ、合計が 0 になる許可されたセグメントが 2 つ存在するかどうかです。 

これは、長さの制約の下で達成可能なセグメントの合計に関する集合交差問題として再構成できます。 すべてのセグメントを列挙する代わりに、各配列でどの合計が達成可能であるかのみを考慮します。 固定配列と固定長間隔の場合、プレフィックス合計に対するスライディング ウィンドウを使用して、すべてのセグメント合計を効率的に決定できます。 課題は、以下の合計があるかどうかを確認することです。`a`その否定が入っています`b`。 

考えられるすべての合計を明示的に保存することは避けます。 代わりに、1 つの配列をスキャンし、ハッシュ セットで達成可能なセグメントの合計をマークし、それからもう 1 つの配列をスキャンして補数をテストします。 セグメントの合計はプレフィックスの差に依存するため、各セグメントの合計は O(1) で計算でき、各配列は全体で O(n) 個の候補に寄与します。

 ## アルゴリズムのチュートリアル

 ゼロが -1 に寄与し、1 が +1 に寄与するように、各バイナリ値を変換します。 これにより、すべてのセグメントの合計が 1 と 0 の間の不均衡を表します。 

次に、両方の配列のプレフィックスの合計を計算して、セグメントの合計を一定時間内に抽出できるようにします。 

配列ごとに、すべての有効なセグメント長を反復処理します。 固定長の場合`len`では、配列全体でウィンドウをスライドさせ、プレフィックスの差を使用してセグメントの合計を計算します。 配列の場合`a`、達成可能なすべてのセグメント合計をハッシュ セットに保存します。 配列に対して同じプロセスを繰り返します`b`。 

最後に、値が存在するかどうかを確認します`s`のセットで`a`そのような`-s`のセットの中に存在します`b`。 「はい」の場合は「YES」を出力し、そうでない場合は「NO」を出力します。 

微妙な点は、両方の配列に対して長さの制約を独立して尊重する必要があるということです。 セットは有効なウィンドウ サイズのみから構築されます。そうでない場合、実際のソリューションには現れない無効な候補が含まれてしまいます。 

### なぜ効果があるのか

 すべての有効なセグメントはプレフィックスの違いに一意に対応するため、長さと開始インデックスで列挙するときに有効な候補が見逃されることはありません。 ±1 への変換は、2 つのセグメントにわたる 0 と 1 の等しいことがサムキャンセルと同等であることを保証します。 同じ制約の下で両方の配列から得られるすべての合計をチェックするため、ゼロ和ペアの存在は 2 つのセット内の一致する否定を検出することと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_sums(arr, x, y):
    n = len(arr)
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (1 if arr[i] == 1 else -1)

    res = set()

    for length in range(x, y + 1):
        for i in range(n - length + 1):
            s = pref[i + length] - pref[i]
            res.add(s)

    return res

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, x1, y1, x2, y2 = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        sa = build_sums(a, x1, y1)
        sb = build_sums(b, x2, y2)

        # check intersection via negation
        ok = False
        if len(sa) > len(sb):
            sa, sb = sb, sa

        for v in sa:
            if -v in sb:
                ok = True
                break

        out.append("YES" if ok else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()

否定チェックは、2 つのセグメントの残高がキャンセルされなければならない条件を直接翻訳したものです。

 ## 特殊なケース

 両方の配列が完全に同一のビットで構成されている場合、1 つのエッジ ケースが発生します。 すべての値がゼロの場合、すべてのセグメントの不均衡がゼロになるため、有効なペアはどれも機能します。 このアルゴリズムは両方のセットにゼロのみを正しく挿入し、ゼロでの一致を見つけます。 

セグメントの長さの範囲が 1 つを除くすべての長さを除外する場合、別の特殊なケースが発生します。 アルゴリズムは引き続きその長さのみを列挙するため、無効なセグメントが漏れ込むことはありません。たとえば、両方の範囲が`[1,1]`、単一の要素のみが考慮され、バランス チェックは配列全体で個々のビットを比較することになり、これはプレフィックス ロジックによって自然に処理されます。 

3 番目のエッジ ケースは、一方の配列が正と負の両方のセグメント合計を生成できる一方で、もう一方の配列が厳密に片側である場合です。 この状況では、値の分布が対称的に重なり合わないため、否定チェックは決して成功しません。 セットベースのアプローチは、特別な処理を必要とせずに、この非対称性を正確に捕捉します。
