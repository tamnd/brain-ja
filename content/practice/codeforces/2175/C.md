 ## 問題の理解

 2 つの文字列が与えられています。`s`そして`t`。 目的は、文字を並べ替えることです。`t`そのような`s`は、最終的な文字列を辞書編集的に可能な限り小さくしながら、結果の文字列のサブシーケンスとして表示されます。 サブシーケンスとは、文字を削除できることを意味します。`t`ただし、相対的な順序を変更することはできません。 含める方法がない場合`s`サブシーケンスとして、「Impossible」を出力する必要があります。 

制約は、すべての長さの合計が`t`テスト ケース全体の文字列数は最大 100,000 であるため、合計入力サイズに対して線形時間で実行されるソリューションは十分に効率的です。 二次関数以上の複雑さは、2 秒の制限に快適に収まりません。`10^5 × 10^5`操作が多すぎる。 

次の場合には、明らかではないエッジケースが発生します。`t`ある文字の出現がより少ない`s`ニーズ。 たとえば、次の場合`s = "aa"`そして`t = "ab"`、形成できません`s`1 つしかないため、サブシーケンスとして`'a'`で`t`。 もう 1 つの微妙なケースは、辞書編集順です。単に挿入するだけです。`s`ソートの先頭または末尾`t`文字では最小の文字列が得られない場合があります。 例えば、`s = "dc"`そして`t = "abcd"`。 仕分け`t`与える`"abcd"`、しかし挿入します`s`最初に生成します`"dcab"`よりも大きい`"abcdc"`。 

## アプローチ

 ブルートフォースアプローチでは、次のすべての順列が考慮されます。`t`かどうかを確認してください`s`はサブシーケンスです。 これは原理的には正しいですが、まったく実行不可能です。`|t| = 10^5`、順列の数は天文学的に多くなります。 部分的に列挙することさえできません。 

重要な観察は、問題は文字を数えることと、残りの文字の順序を決定することに帰着するということです。`s`辞書編集上の最小性を維持するため。 具体的には、各文字が何回出現するかがわかっている場合、`t`に必要なカウントを減算できます。`s`残りの文字を自由に並べ替えます。 主な課題はどこに配置するかを決めることです`s`これらの残った文字の中から辞書編集的に最小の結果を生成します。 

貪欲な洞察が有効です。次の最初の文字を考えてください。`s`。 置いたら`s`すべての文字が最初の文字より小さい位置に、`s`がその前にあり、より大きな文字がすべてその後にある場合、最小の結果が得られます。 文字が次の最初の文字と等しい場合、微妙なケースがあります。`s`残り物に表示されます: それらを前に置くか後ろに置くかを決定する必要があります`s`。 例をテストした後、それらを前に配置します`s`それらが最初の位置より前にある場合のみ`s`最小限性を確保します。 より簡単な戦略は比較することです`s`残りに同じ文字のブロックがある: if`s`辞書編集上、同じ文字の文字列よりも小さいです。`s`初め; それ以外の場合は、後に配置します。 

このアプローチは、文字を数えて最終的な文字列を構築するだけであるため、文字列ごとに線形時間で機能します。

 ## アルゴリズムのチュートリアル

 1. の各文字の頻度を数えます。`t`小文字ごとに 1 つずつ、26 要素の固定サイズの配列を使用します。 これにより、使用されている文字をすばやく差し引くことができます。`s`。 
2. の各文字について`s`、周波数配列からそのカウントをデクリメントします。 いずれかのカウントが負になった場合は、「不可能」と出力されます。`t`形成するのに十分な文字が含まれていません`s`続編として。 
3. 最終的な文字列を順番に構築します。 キャラクターごとに`c`から`'a'`に`'z'`、残りのすべてのコピーを追加します`c`前か後か`s`辞書編集的な比較によれば、

 - もし`c`の最初の文字より小さいです`s`、残りをすべて追加します`c`前に`s`。 
- もし`c`の最初の文字に等しい`s`、文字列を比較します`s`と`c`残った回数を繰り返した`c`s. もし`s`辞書編集的に小さい場合、挿入します`s`初め; それ以外の場合は、残りの部分を追加します`c`最初に、それから`s`。 
- もし`c`の最初の文字より大きいです`s`、残りをすべて追加します`c`後`s`。 
4. すべての文字が配置されると、以下を含む辞書順で最小の文字列が取得されます。`s`続編として。 

機能する理由: アルゴリズムにより、すべての文字が先頭よりも小さくなります。`s`前に現れる`s`大きな文字はすべてその後に表示されます。 等しい文字を慎重に処理することで、必要以上に大きな文字列が作成されないことが保証されます。 カウントすると、利用可能な文字数を超える文字が削除されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        s = input().strip()
        t = input().strip()
        freq = [0]*26
        for c in t:
            freq[ord(c)-ord('a')] += 1
        for c in s:
            freq[ord(c)-ord('a')] -= 1
            if freq[ord(c)-ord('a')] < 0:
                print("Impossible")
                break
        else:
            result = []
            first_s = s[0]
            for i in range(26):
                c = chr(i+ord('a'))
                if c < first_s:
                    result.append(c*freq[i])
                elif c == first_s:
                    # Decide whether s should go before or after leftover c's
                    leftover_c = c*freq[i]
                    if s < leftover_c:
                        result.append(s)
                        result.append(leftover_c)
                    else:
                        result.append(leftover_c)
                        result.append(s)
                    freq[i] = 0
                else:
                    result.append(c*freq[i])
            print(''.join(result))

if __name__ == "__main__":
    solve()
```コードはまず、次のすべての文字をカウントします。`t`必要なものを削除します`s`。 どこかの時点で手紙が届いた場合、`s`が見つからない場合は、すぐに「不可能」と出力されます。 それ以外の場合は、すべての文字を反復処理して、最初の文字よりも小さい文字を配置します。`s`その前に。 最初の文字と等しい文字は、比較することによって慎重に処理されます。`s`残った文字のブロックを使用して最小の挿入ポイントを決定します。 残りの文字は後で追加されます。
