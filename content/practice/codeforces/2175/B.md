 ## 解決策
 ## 問題の理解

 長さの正の整数の配列を構築するように求められます。`n`インデックスからの単一の連続する部分配列の XOR が計算されるようにする`l`に`r`はゼロですが、他のすべての空でない部分配列の XOR はゼロではありません。 入力は複数のテスト ケースで構成され、それぞれが配列の長さを指定します。`n`そしてインデックス`l`そして`r`これは、ゼロと XOR する必要があるサブ配列をマークします。 出力は、条件を満たす任意の配列です。 

境界は重要です。 と`n`400,000までとその合計`n`最大 500,000 のすべてのテスト ケースにわたって、線形のソリューションが必要です。`n`。 すべてのサブ配列 XOR を構築すると 2 次的になりますが、これは実行不可能です。 各要素は最大 1e9 まで指定できるため、オーバーフローに陥ることなく、十分な柔軟性を持って数値を選択できます。 

単純なアプローチでは、ターゲットのサブ配列のみが XOR 0 になるまで、すべてのサブ配列を反復し、XOR を計算し、数値を調整しようとします。 たとえば、`n=3`、`l=1`、`r=3`、総当たりアプローチでは XOR がチェックされます。`[a1], [a1,a2], [a1,a2,a3], [a2], [a2,a3], [a3]`繰り返し。 これは大規模な場合にはすぐに不可能になります`n`サブアレイの数は次のように増加するため、`n*(n+1)/2`。 

明らかではないエッジケースには、最小の配列が含まれます。`r-l=1`(XOR ゼロの部分配列は単なる 2 つの数値です) または次の配列`n`小さくて`l`そして`r`終わり近くに。 不注意なアプローチでは、他のゼロ XOR につながる繰り返し番号を誤って選択する可能性があります。 たとえば、すべての要素を 1 に設定すると、偶数長の部分配列ごとに XOR がゼロになりますが、これは要件に違反します。 

## アプローチ

 ブルート フォース アプローチでは、すべてのサブ配列を反復処理して、指定されたセグメントについてのみ XOR がゼロになるようにします。 このアプローチは小規模な場合に適しています`n`しかし、操作の数は次の値に比例するため、現実的ではありません。`n^2`、最悪の場合は 1e11 に達し、制限時間を桁違いに超えます。 

重要な観察は、XOR が線形で自己反転的であるということです。 単一の連続する部分配列を強制的にゼロにするには、XOR がゼロになるような数値を選択できます。 その後、追加のゼロ XOR が作成されるのを避けるために、これらの数値とは異なる、また互いに異なる数値をすべて選択できます。 非常に単純な構造は、配列のプレフィックスとサフィックス (外側) を埋めることです。`[l,r]`) 2 の累乗で、すべての非ゼロ XOR を保証し、内部の数値を慎重に選択します`[l,r]`そのため、XOR はゼロになります。 これが機能するのは、すべての項が正確にキャンセルされない限り、2 のべき乗の XOR がゼロにならないためであり、これは制御可能です。 

外側のすべての数値の XOR という観察`[l,r]`そして、XOR ゼロの部分配列が選択されたセグメントの合計であるため、問題を線形時間の構築に縮小できます。 すべての部分配列を明示的にチェックできないため、ブルート フォースは失敗しますが、線形構造では XOR の代数的性質を利用して正確さを保証します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 線形建設的 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 長さの配列を初期化します。`n`ゼロで埋められています。 
2. インデックスの前の位置を埋めます`l`(プレフィックス) 連続した 2 の累乗:`1,2,4,...`。 これにより、これらの数値だけを含む各サブ配列の XOR がゼロ以外になることが保証されます。 
3. インデックスの後にポジションを埋めます`r`(サフィックス) 同様に、衝突を避けるために 2 の明確な累乗を続けます。 
4. セグメントについて`[l,r]`、最初を埋めてください`r-l`プレフィックスおよびサフィックスとは異なる、連続する 2 のべき乗の位置。 このセグメントの最後の要素は、セグメント内の以前のすべての数値の XOR となるように選択されます。これにより、次の XOR が確実に得られます。`l`に`r`はゼロです。 
5. 配列を返します。 

なぜ機能するのか: ゼロと XOR する唯一のセグメントは`[l,r]`最後の要素をセグメント内の前の要素の XOR として明示的に構築するためです。 他のすべての部分配列には、外側に少なくとも 1 つの異なる 2 のべき乗要素が含まれます。`[l,r]`またはその部分的なサブセット`[l,r]`、すべてが含まれない限り、2 の個別のべき乗の XOR は決してゼロにはならないため、合計がゼロになることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, l, r = map(int, input().split())
        a = [0] * n
        used = set()
        val = 1
        # fill prefix
        for i in range(l-1):
            a[i] = val
            used.add(val)
            val <<= 1
        # fill suffix
        for i in range(r, n):
            while val in used:
                val += 1
            a[i] = val
            used.add(val)
            val += 1
        # fill middle except last
        xor_sum = 0
        for i in range(l-1, r-1):
            while val in used:
                val += 1
            a[i] = val
            used.add(val)
            xor_sum ^= val
            val += 1
        # last element to make XOR zero
        a[r-1] = xor_sum
        print(' '.join(map(str, a)))

if __name__ == "__main__":
    solve()
```コードは、プレフィックスとサフィックスに個別の数字を入力し、慎重にインクリメントします。`val`衝突を避けるため。 中央のセグメントでは、XOR を段階的に計算し、最後の要素を設定してバランスをゼロにします。 使用する`used`すべての数値が区別されるようにします。 インデックス付けでは 0 から始まる配列が使用されますが、入力は 1 から始まるため、調整は次のように行われます。`l-1`そして`r-1`。 

## 実用的な例

 入力用`3 1 3`、 我々は持っています`n=3, l=1, r=3`。 

| ステップ | 配列状態 | xor_sum |
 | --- | --- | --- |
 | プレフィックス | [0,0,0] | 0 |
 | サフィックス | [0,0,0] | 0 |
 | 中から順 | [1,0,0] | 1 |
 | 真ん中の最後 | [1,2,?] | 1^2=3 |

入力用`4 1 3`:

 | --- | --- | --- |
 | プレフィックス | [0,0,0,0] | 0 |
 | サフィックス | [0,0,0,4] | 0 |
 | 中から順 | [1,2,0,4] | 1^2=3 |
 | 最後に設定 | [1,2,3,4] | [1,2,3]=0 の XOR |

 不変式は次のとおりです。`[l,r]`XOR is zero, all other subarrays non-zero.
