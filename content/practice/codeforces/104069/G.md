 ## 解決策
 ## 問題の理解

 私たちには、西から東に固定された順序で駅が配置された直線状の地下鉄路線が与えられています。 各駅は隣の駅とつながっており、隣接する駅間の移動には常に 1 分かかります。 2 人が 2 つの異なる駅から同時に出発し、両方ともこの線に沿って移動します。 課題は、彼らが同じ瞬間に同じ駅に到着できるまでの最小時間を決定することです。 

入力により駅の数が得られ、その後に路線沿いの駅名の順序付きリストが続きます。 その後、2人の出発位置を示す2つの駅名が与えられます。 出力は単一の整数です。つまり、両方がすぐに移動を開始し、線路に沿って最適に移動した場合に、同じ駅を占有することができる最も早い時刻です。 

重要な構造は、グラフが一般的なグラフではなく、単純なパスであることです。 どのステーションにも隣接するステーションは最大 2 つあり、移動の距離は決定的です。任意の 2 つのステーション間の時間は、リスト内のインデックスの差にすぎません。 

制約は小さく、ステーションは最大 100 個で、ステーション名の長さは最大 100 です。これにより、ステーションのすべてのペアに対する 2 次または単純なアプローチであっても、制限内で実行するのは簡単であることがすぐにわかります。 本当の課題はパフォーマンスではなく、満たされた条件を最短時間の表現に正しく変換することです。 

微妙な点は、2 人が明示的にお互いに向かって歩いて会う必要がないことです。 ラインに沿って任意に移動でき、可能なすべての集合ステーションでの集合時間は最小限になります。 素朴な解釈では、途中で会わなければならない、または一方向のみを考慮する必要があると誤って仮定する可能性があり、最適な会合ポイントを逃してしまいます。 

注目に値するエッジ ケースとしては、両方が同じ駅から出発する場合 (答えが 0 である場合)、および最適な集合場所が開始位置の 1 つである場合 (つまり、1 人が到着するまでにもう 1 人がその場で待機する場合) が挙げられます。 

## アプローチ

 この問題を考える強引な方法は、すべての駅を潜在的な待ち合わせ場所と考えることです。 各駅について、両方の人がその駅に到着するまでにかかる時間を計算します。これは、駅リスト内のインデックス間の絶対差にすぎません。 両方が同時に到着する必要があるため、その駅での集合時間は 2 つの到着時間の最大値となります。 答えは、すべてのステーションにおけるこの値の最小値です。 

これが機能するのは、有効な会議はすべてどこかの駅で発生する必要があり、時刻は路線上の距離によって完全に決定されるためです。 問題は、これを構造なしで実装すると、不必要にスキャンや距離の再計算を繰り返してしまうということですが、n が 100 しかないので、それでも問題ありません。 

重要な簡素化は、ステーション名をインデックスに直接マッピングできることを認識していることです。 2 つの開始ステーションのインデックスがわかれば、問題はすべての k にわたって max(|i - k|, |j - k|) を最小化することになります。 直線上では、k が i と j の間にあるときにこの式が最小になり、最適値はそれらの間の距離のちょうど半分になり、切り上げられます。 

これにより直接的な式が得られます。答えは (|i - j| + 1) // 2 です。

 | --- | --- | --- | --- |
 | すべての会議ステーションに対するブルートフォース | O(n) | お(1) | 承認済み |
 | インデックスマッピング + 直接式 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. ステーション数を読み取り、リストを順番に保存します。 順序はグラフのメトリック構造を定義するため、順序が非常に重要です。 
2. ステーション名からリスト内のインデックスへのマッピングを構築します。 これにより、位置の定時検索が可能になります。 
3. 2 つの開始ステーションのインデックスを取得します。 それらを i と j とします。 
4. 直線上のそれらの間の絶対距離を計算します。 この距離は、一方が直接移動した場合に他方に到達するまでの最短時間を表します。 
5. この距離の半分を切り上げて返します。これは、両方が同時に互いに向かって移動する可能性があり、1 分ごとに最大で合計 2 ステップずつ距離が縮まるためです。 

これが機能する理由: 経路上では、どの集合点 k も到着時間 |i - k| を誘導します。 および |j - k|。 会議時間は、これら 2 つの値の最大値です。 この関数は、k が i と j の間にある場合に最小化されます。これは、k を間隔に向かって移動すると、2 つの距離のうち大きい方が小さくなるためです。 k がセグメント内に入ると、両側が対称的に縮小するときに最適なバランスが達成され、i と j の間の合計距離が分割されます。 動きは分単位で離散的であるため、結果は距離の半分の上限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
stations = []
pos = {}

for i in range(n):
    name = input().strip()
    stations.append(name)
    pos[name] = i

c, m = input().split()
i = pos[c]
j = pos[m]

dist = abs(i - j)
print((dist + 1) // 2)
```この実装は、ステーション名をインデックスに変換することに完全に依存しているため、スキャンの繰り返しが回避されます。 辞書により、位置への O(1) アクセスが保証されます。 最後の表現`(dist + 1) // 2`は、回線上の最適な会議時間に一致する、距離の半分の上限を計算するコンパクトな方法です。 

よくある間違いは、動きを段階的にシミュレートしようとすることですが、構造によって閉じた形式の解決策が保証されているため、その必要はありません。 もう 1 つの潜在的な問題は、両方が同時に移動することを忘れていることです。そのため、距離は 1 分間に 1 つではなく、最大 2 つ縮まります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    stations = []
    pos = {}

    for i in range(n):
        name = input().strip()
        stations.append(name)
        pos[name] = i

    c, m = input().split()
    i = pos[c]
    j = pos[m]

    dist = abs(i - j)
    return str((dist + 1) // 2)

 ## 特殊なケース

 両方の人が同じ駅から出発する場合、インデックスの差はゼロであるため、計算される距離はゼロとなり、式はゼロを返します。 アルゴリズムは、特別なケースを使用せずにこれを正しく処理します。 

インデックス 2 と 3 などの隣接するステーションの場合、距離は 1 であるため、`(1 + 1) // 2 = 1`。 これは、彼らが互いに近づくと 1 分後に出会うという事実と一致します。 

インデックス 0 や n-1 などの極端なエンドポイントの場合、会議は中央領域で発生します。 この式は、パス上の 2 つの直線距離の最大値を最小化することから導出されるため、中点を明示的に検索する必要がなく、これを自動的に取得します。
