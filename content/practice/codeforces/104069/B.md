 ## 解決策
 ## 問題の理解

 学生のリストが与えられます。各学生には名前とそれに関連付けられた整数があります。 各整数を素因数分解できます。 その整数のすべての素因数の中で、それを割る最大の素数に注目します。 すべての生徒について、生徒数の「最大素因数」を計算します。 タスクは、そのような値が最大の番号を持つ生徒を見つけることです。 複数の生徒が同じ最大の素因数を共有する場合は、入力順序で最も早く出現した生徒を返します。 

入力サイズは最大 100,000 人の学生で、それぞれの数は最大 1 億です。 これにより、クエリごとに最大 n までの単純な試行除算を使用して数値を個別に因数分解するアプローチが即座に除外されます。 数値あたり O(n √x) であっても、最悪の場合、およそ 10^5 × 10^4 の演算が必要になります。これは Python ではすでに限界であり、定数を多く使用する実装ではさらに悪化します。 

微妙な特殊なケースは、数値自体が素数である場合に発生します。 そのような学生にとって、答えは数字そのものです。それは、それが唯一の最大の素因数であるためです。 もう 1 つのケースは、最大の因数が必ずしも最頻値または最小値であるとは限らない、複数の素数の積である数値です。 たとえば、2 × 3 × 97 は 97 に基づいて評価される必要があります。最後に、同点は入力順序に厳密に依存するため、最初に出現する動作を保持する必要があります。 

## アプローチ

 直接的なアプローチは、各数値を個別に因数分解することです。 各整数 x について、2 から √x までのすべての整数で除算して、素因数を追跡します。 合成数は平方根以下の係数を持つ必要があるため、これは論理的に機能します。 ただし、これを 100,000 個の数値に対して実行すると、最悪の場合でも約 100,000 × 10,000 回の演算が必要になります。これは Python では遅すぎ、定数が大きい場合は最適化された言語でも依然として無駄です。 

重要な観察は、完全な因数分解は必要ないということです。 必要なのは最大の素約数だけです。 これにより、より増分的なアプローチが可能になります。数値 x ごとに、小さな素数または因数で繰り返し除算しますが、すべての因数を保存するのではなく、リダクション中に発生した最大の約数のみを追跡します。 すべての小さな因数を取り除くと、残りの値が 1 より大きい場合、その残りの値自体が素因数となり、自動的に最大の候補になります。 

これにより、早期終了とこれまでに見つかった最大因子の定時間追跡による数値ごとの効率的な因子抽出に問題が軽減されます。

 | 試算は数値ごとに最大 √x まで | O(n √x) | お(1) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 これまでに見られた最良の回答を維持しながら、各生徒を 1 人ずつ処理します。

1. 生徒の名前と番号 x を読み取り、この生徒の変数 best_factor = 1 を初期化します。 この変数は、x について発見された最大の素因数を追跡します。 
2. x を 2 で繰り返し割ってみます。 除算が成功するたびに、best_factor = 2 を更新します。これを行うのは、2 で x を 1 回でも除算すると、それが素因数であり、それをすぐに記録したいためです。 
3. 2 の因数をすべて削除した後、3 から始まり √x まで奇数の候補 p を繰り返します。 各 p について、割り切れる限り x を p で繰り返し割り、そうするたびに best_factor = p を更新します。 これにより、x のすべての素因数が確実に取得され、有効な約数が出現した場合にのみ上書きされるため、最終的に格納される値は検出された最大値になります。 
4. すべての候補を処理した後、x > 1 の場合、x 自体は以前に抽出されたすべての因子よりも大きい素数であるため、best_factor = max(best_factor, x) と設定します。 
5. best_factor をグローバル最大 best_so_far と比較します。 それが大きい場合は、現在の学生への回答を更新します。 等しい場合は、何もせずに早い方を保持します。 
6. すべての生徒を処理した後、保存されている名前を出力します。 

これが機能する理由は、すべての合成数に平方根を超えない素因数が少なくとも 1 つあるため、反復中にすべての小さな素数が見つかることが保証されるためです。 すべての小さな因数が削除されると、残りの値は素数になる必要があり、これ以上約分できないため、元の数値の最大の因数になる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_prime_factor(x: int) -> int:
    best = 1

    while x % 2 == 0:
        best = 2
        x //= 2

    p = 3
    while p * p <= x:
        while x % p == 0:
            best = p
            x //= p
        p += 2

    if x > 1:
        best = max(best, x)

    return best

def main():
    n = int(input())
    best_name = ""
    best_value = -1

    for _ in range(n):
        parts = input().split()
        name = parts[0]
        x = int(parts[1])

        val = max_prime_factor(x)

        if val > best_value:
            best_value = val
            best_name = name

    print(best_name)

if __name__ == "__main__":
    main()
```因数分解ルーチンは、後のループを簡素化するために、最初に 2 の因数をすべて削除します。 これは標準的な最適化であり、その後は奇数のみをステップ実行できるようになり、反復回数が半分になります。 

ループ条件`p * p <= x`x は分割すると縮小するため、境界は動的に正しいままとなるため、これは重要です。 元の値を使用すると、反復処理が過剰になります。 

最終チェック`if x > 1`残りの因数が分割されなかった大きな素数である場合をキャプチャします。 

メイン ループはグローバル最大値のみを保存し、最も早い値を優先してタイが自動的に解決されるようにします。

 ## 特殊なケース

 重要なケースの 1 つは、数値自体が素数である場合です。 たとえば、入力`alice 97`。 因数分解ループでは約数が見つからないため、ループ後も x は 97 のままです。 最終チェック`if x > 1`97 が最大素因数として記録されることを保証し、後の生徒が 97 を超えない場合、アルゴリズムはアリスを正しく返します。 

別のケースとしては、次のような完全権力があります。`49`。 49 から始めて、7 で 2 回割ります。 各除算は 7 に最適に更新されます。削除後、x は 1 になるため、最終値は 7 のままです。これにより、繰り返される要因によって最大追跡ロジックが歪められないことが確認されます。 

3 番目のケースは、2 × 50000017 など、非常に大きな素因数と小さな素因数の組み合わせを持つ数値です。アルゴリズムは素因数 2 をすぐに削除し、残りの値を素数として認識し、試行分割の制限が小さいために大きな素因数が見逃されないようにします。
