 ## 解決策
 ## 問題の理解

 人が数日間にわたってどのように感じたかを表す一連の整数が与えられます。 各値は -10 から 10 までの範囲であるため、シーケンスは短い毎日の気分スコアをエンコードします。 タスクは、これらすべての値の算術平均を計算し、その結果を 3 つの感情ラベル (正の平均、ゼロの平均、または負の平均) のいずれかに分類することです。 

出力は数値平均そのものではなく、その符号のみです。 すべての値の合計を n で割った値が 0 より大きい場合、幸せな顔を出力します。 正確にゼロの場合は、ニュートラルな面を印刷します。 そうしないと、悲しい顔を印刷してしまいます。 

重要な点は、平均を浮動小数点数として明示的に計算する必要がないということです。 正の整数による除算は数値の符号を変更しないため、代わりに配列の合計を直接操作できます。 

n ≤ 100000 という制約は、リニア スキャンで十分であることを意味します。 部分範囲にわたる再計算や集計の繰り返しを試みるソリューションはすべて合格しますが、O(n) より悪いものは不要です。 二次アプローチでは、最悪の場合、最大 10^10 の演算が実行されますが、これは明らかに 1 秒の制限には遅すぎます。 

エッジケースは主にサインの処理に関するものです。 

エッジケースの 1 つは、すべての数値がゼロである場合です。 合計はゼロであり、出力は「:|」でなければなりません。 浮動小数点平均を不用意に実装すると、float で実装した場合に丸めの問題が発生する可能性がありますが、整数合計ではそれが完全に回避されます。 

もう 1 つのエッジ ケースは、[-1, 1] など、合計が非常に小さいがゼロではない場合です。 平均は正確にゼロであり、整数演算ではそれが正確に維持されます。 実装の詳細によっては、浮動小数点除算では正確なゼロではなく小さなイプシロンが生成される可能性があるため、これは重要です。 

## アプローチ

 この問題の強引な解釈は、すべての値の合計を計算して n で割って、結果を確認することです。 合計を計算するのに 1 回のパスが必要で、その後は定数時間の除算が必要なので、これはすでに線形時間です。 意味のあるサブ問題構造はなく、プレフィックスの計算、並べ替え、データ構造も必要ありません。 

もう少し単純なバージョンでは、加算と除算を繰り返したり、部分和を複数回再計算したりして、ループ内で平均を計算できます。 たとえば、各要素の合計を最初から再計算すると O(n^2) 時間がかかりますが、n が 100000 に達すると実行不可能になります。 

重要な単純化は、n が厳密に正であるため、平均の符号は合計の符号にのみ依存することを認識することです。 これにより、ほとんどの実装で除算の必要性が完全になくなり、浮動小数点の問題が回避されます。 

この問題を配列上の 1 回の累積パスに縮小します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 合計を繰り返し再計算する | O(n^2) | お(1) | 遅すぎる |
 | 単一パスの合計 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 記録された日数を表す整数 n を読み取ります。 これにより、集計する値の数が決まります。 
2. 変数を初期化する`total_sum = 0`。 この変数は、入力を処理するときに毎日のすべてのスコアを蓄積します。 
3. シーケンス内の n 個の整数をそれぞれ反復処理し、各値を`total_sum`。 これにより、1 回のパスで毎日のすべての気分の正確な合計が構築されます。 
4. すべての値を処理した後、比較します。`total_sum`ゼロで。 n は正であるため、n で割っても符号は変わらないため、この比較によって答えが完全に決まります。 
5. もし`total_sum > 0`、「:)」を出力します。 もし`total_sum == 0`、「:|」を出力します。 それ以外の場合は「:(」を出力します。

 なぜ機能するのか: 平均は次のように定義されます。`total_sum / n`。 n > 0 であるため、分数の符号は完全に次のように決定されます。`total_sum`。 除算では符号を反転できないため、合計を直接チェックすることは平均をチェックすることと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    total = 0
    for x in arr:
        total += x
    
    if total > 0:
        print(":)")
    elif total == 0:
        print(":|")
    else:
        print(":(")

if __name__ == "__main__":
    solve()
```解決策は、入力サイズと整数のリストを読み取ることから始まります。 次に、コア計算である単一の累積ループを実行します。 整数アキュムレータ以外の中間構造は必要ありません。 

最後の決定ステップでは、累積合計をゼロと比較します。 これにより、実際の平均の計算が回避され、浮動小数点演算が完全に回避されるため、解の正確さと安全性が保たれます。

 ## 特殊なケース

 重要なエッジケースは、すべての値がゼロの場合です。 たとえば:

 入力:```
3
0 0 0
```アルゴリズムが初期化されます`total = 0`そしてそれを決して変更しません。 最終的な比較`total == 0`トリガーして「:|」を出力しますが、これは正しいです。 

もう 1 つのエッジ ケースは、完全なキャンセルです。 

入力:```
2
-1 1
```両方の要素を処理すると、累計は 0 になります。 中間値が負であっても、重要なのは最終状態です。 アルゴリズムは「:|」を正しく出力します。 

最後の微妙なケースは、すべて 10 またはすべて -10 など、大きな正または負のスキューです。 アキュムレータは整数演算を使用し、合計の最大値は 100000 × 10 = 10^6 によって制限されるため、標準の 32 ビットまたは 64 ビット整数型ではオーバーフローのリスクはありません。 符号比較は安定しており、決定的です。
