 ## 問題の理解

 一連の建物に関する集計統計が提供されていますが、個々の建物の高さは失われています。 しきい値ごとに$k$、厳密にそれ以上のものがある建物がどれだけあるかを私たちは知っています。$k$床。 正式には配列$a$どこに与えられるか$a_k$より高い高さの建物をカウントします$k$。 配列は増加していません。これは、しきい値が増加するにつれて、それを超えることができる建物の数が少なくなるという事実と一致します。 

この蓄積された情報から、建物の高さの複数のセットを再構築する必要があります。 出力は順序付けられた構造としては一意ではありませんが、建物の総数とともに、非昇順にソートされた復元された高さを出力するように求められます。 

制約$m \le 10^6$私たちは二次関数やさらには何かを避けるように強制されます$O(m \log m)$慎重に設計しない限り、重い定数が必要になります。 おそらく、連続する値間の差異を解釈することによって、線形再構成が期待されます。$a$。 

微妙な点は、この数列は累積分布を表していますが、各高さの頻度を直接表しているわけではないことです。 素朴な誤解は治療することです$a_k$高さのある建物の数として正確に$k$、これは間違いです。 もう 1 つの間違いは、高さがそれぞれ減少することに気づかずに、貪欲に高さを再構築しようとすることです。$a$特定の高さの境界で「終わる」建物のバッチに対応します。 

失敗例を確認するには、次の点を考慮してください。$a = [4, 3, 1, 1]$。 素朴な解釈では、レベルごとの数として高さを直接割り当て、背の低い建物が多すぎるような結果が生じる可能性があります。 正しい再構築では、すべてのしきい値にわたる一貫性を同時に確保する必要があります。 

シーケンスがいくつかの位置でフラットである場合、別の特殊なケースが発生します。 例えば$a = [5, 5, 5]$増加しても建物が消失しないことを意味します$k$したがって、すべての建物の高さは少なくとも 3 でなければなりません。レベルごとの割り当てを貪欲に行うと、プラトーが正しく解釈されない場合、簡単にカウントを誤ってしまう可能性があります。 

## アプローチ

 重要な観察は、解釈することです$a_k$身長のヒストグラムの接頭語として。 

させて$b_k$高さが正確に一致する建物の数になります。$k$。 それから：

-$a_k = b_k + b_{k+1} + \dots$これは古典的な接尾語の合計関係です。 したがって：

-$b_k = a_k - a_{k+1}$のために$k < m-1$-$b_{m-1} = a_{m-1}$したがって、連続する値間の各差により、その高さで「終了」する建物の数がわかります。 

取得したら$b_k$、高さを出力することで答えを再構築できます$k$その通り$b_k$回。 最終出力は非増加順序である必要があるため、単純に高い値から低い値へ反復します。 

強引なアプローチでは、個々の建物に高さを割り当て、すべての建物との一貫性を検証しようとします。$a_k$、それは次のことにつながります$O(nm)$チェックかそれ以上。 これは不可能です$10^6$。 

差分配列の解釈により、問題は 1 つのパスに短縮されます。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取る$a$。 これを未知の周波数にわたる累積的なサフィックス構造として扱います。 
2. 新しい配列を計算する$b$、ここでそれぞれ$b_k$建物の正確な数を表します$k$床。 最後のインデックスには、$b_{m-1} = a_{m-1}$。 
3. 1 つおきのインデックスについて$k$から$m-2$まで$0$、計算する$b_k = a_k - a_{k+1}$。 この減算により、高さを超えて寄与を停止した建物の数が特定されます。$k$、正確な高さがあることを意味します$k$。 
4. すべてを合計する$b_k$建物の総数を取得するには$n$。 
5. 各高さを印刷して出力を構築します$k$その通り$b_k$回、高い値から低い値まで繰り返すため、結果は自動的に増加しません。 

重要な推論ステップは、隣接する累積カウントを減算することで正確な頻度を分離することです。 このステップを行わないと、データの累積的な性質により実際の分布が隠蔽されてしまいます。 

### なぜ効果があるのか

 それぞれ$a_k$厳密に次の高さを超えるすべての建物をカウントします。$k$。 引き算すると$a_{k+1}$を超える高さの建物をすべて削除します。$k+1$に等しい高さを持つものをそのまま残します。$k+1$。 これにより、すべての建物が独立した高さクラスに完全に分割されます。 すべての建物は正確に 1 つの要素に貢献するため、$b_k$、再構築はロスレスです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    m = int(input())
    a = list(map(int, input().split()))

    b = [0] * m

    for i in range(m - 1):
        b[i] = a[i] - a[i + 1]
    b[m - 1] = a[m - 1]

    n = sum(b)

    out = []
    for h in range(m - 1, -1, -1):
        if b[h]:
            out.extend([str(h)] * b[h])

    sys.stdout.write(str(n) + "\n")
    sys.stdout.write(" ".join(out))

if __name__ == "__main__":
    main()
```再構成は、隣接する差分を介して高さごとの正確なカウントを計算することにかかっています。 上位から下位へのループにより、ソートなしで必要な順序付けが保証されます。 出力の構築では直接の繰り返しを使用します。 重く見えるかもしれませんが、印刷される要素の総数は正確に$n$、これは避けられません。 

すべての算術演算は整数で実行され、アクセス時にインデックス付けが範囲外にならないように注意する必要があります。$a[i+1]$。 最後の要素は個別に処理する必要があります。
