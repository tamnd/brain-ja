 ## 解決策
 ## 問題の理解

 すべての正の整数を見つけるように求められます$x$たとえば、ゆずが次のように始まると、$x$キャンディーを使用する場合、すべての敵を順番に倒す (敵の順列) 方法が多数あり、彼女が常に現在の敵と少なくとも同じ数のキャンディーを持っているようにします。 各決闘で彼女が勝った場合、追加のキャンディーが 1 つ与えられます。 敵のキャンディーの数は配列で与えられます$a$、そして素数を考慮することになります$p$正の整数になるように$x$有効な順列の数が「良好」である場合$f(x)$は ** で割り切れません$p$**。 出力は、すべての適切な整数とその数を昇順に並べたものです。 

入力できるサイズは、$n \le 2000$そして$a_i \le 2000$。 これにより、すべての置換を明示的にブルートフォースすることができなくなります。$n!$順列が大きくなりすぎて、$10^{5000}$で$n=2000$。 代わりに、ソリューションは、$n$、 理想的には$O(n^2)$。 出力は最大で次のように保証されます。$10^5$整数なので、適切な整数をすべて保存することも可能です。 

明らかではないエッジケースは、すべての敵が小さなキャンディーよりも多くのキャンディーを持っている場合です。$x$。 たとえば、次の場合$n=3$、$a=[5,5,5]$、 そして$p=2$、その後、$x=1$または$x=2$または$x=3$有効な順列は存在しないため、$f(x)=0$で割り切れます$p$。 不用意に実装すると、次の事実を見落とす可能性があります。$x$最小値より小さい値$a_i - n + 1$有効な置換を生成できません。 

もう 1 つの微妙なケースは、複数の連続した場合です。$x$値は同じ数の有効な順列を生成します。 適切な整数は、常に最小値から開始して連続しています。$x$、スイープアプローチが可能になります。 

## アプローチ

 素朴なアプローチは、すべての候補者について敵のすべての順列を列挙することです。$x$、そしてユズがすべての決闘に勝つことができる順列の数を数えます。 これにより正しい結果が生成されますが、$f(x)$、その複雑さは$O(n! \cdot n)$、それは絶望的です$n=2000$。 組み合わせを段階的に生成しても拡張できません。 

重要な洞察は、有効な順列の数はソートされた敵の順序にのみ依存するということです。 並べ替えてみましょう$a$昇順で。 それでは、候補者としては$x$、ゆずがステップで倒せる敵の数$i$は単に次の数です$a_j$以下$x + i - 1$。 これを使用すると、各ステップで倒せる敵の数を事前計算し、数のリストを生成できます。$c_i$。 有効な順列のモジュロの合計数$p$組み合わせ公式を使用して計算できます$f(x) = \prod_{i=1}^n c_i$。 なぜなら$p$は素数なので、積の剰余が得られたら停止できます$p$はゼロです。 これにより、複雑さが軽減されます。$O(n^2)$、実現可能$n \le 2000$。 

ブルートフォースは概念的には単純ですが、実行不可能です。 最適なアプローチでは、ソートされた敵の配列を利用し、各ステップで実行可能な敵をカウントし、割り算モジュロをチェックします。$p$効率的に。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n) | 遅すぎる |
 | 最適 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 敵のキャンディーを並べ替える$a$昇順で。 これにより、実行可能な順列は、利用可能な最も弱い敵に直面することから開始する必要があることが保証されます。 
2. 可能な最小の開始キャンディーを決定します。$x_\text{min}$として$\max(0, \min(a_i) - n)$。 これを下回る値では、すべての決闘に勝つことはできません。 
3. 各候補者について$x$から$x_\text{min}$まで$x_\text{max} = \max(a_i)$:

 1. 配列を初期化する$c$長さの$n$、 どこ$c[i]$ユズが最後に倒せる残りの敵の数を数えます。$i$-回目の決闘。 
2. のために$i = 0$に$n-1$、敵の数を数えます$a_j$満足のいく$a_j \le x + i$。 
3. 減算$i$この数から、以前の決闘ですでに直面した敵を考慮してください。 
4. すべての積を計算します。$c[i]$モジュロ$p$。 積モジュロの場合$p$がゼロ以外の場合、$x$良いです。 
5. 良いものをすべて集める$x$値を入力し、昇順に出力します。 

機能する理由: 並べ替えにより、各ステップで残っている最も弱い敵を最初に考慮することが保証されます。 カウント$c[i]$以前の選択を尊重しながら、各決闘で利用可能な選択肢の正確な数を取得します。 それらを乗算すると、有効な順列の数が得られます。 剰余算術は、次の値で割り切れる場合に計算を停止します。$p$が発生し、効率が維持されます。 これにより、すべての候補者の正確性と完全性が保証されます$x$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, p = map(int, input().split())
a = list(map(int, input().split()))
a.sort()

min_x = max(0, min(a) - n)
max_x = max(a)

good_x = []

for x in range(min_x, max_x + 1):
    c = []
    for i in range(n):
        count = 0
        for j in range(n):
            if a[j] <= x + i:
                count += 1
        c.append(count - i)
    prod = 1
    for v in c:
        prod = (prod * v) % p
        if prod == 0:
            break
    if prod != 0:
        good_x.append(x)

print(len(good_x))
print(' '.join(map(str, good_x)))
```解決策は敵を分類することから始まります。 ループオーバー候補$x$値は次によって制限されます$x_\text{min}$そして$x_\text{max}$。 内側のループでは、決闘の各ステップで実行可能な敵をカウントします。 モジュラー製品は、以下のことを効率的に判断します。$f(x)$で割り切れます$p$膨大な階乗を計算することなく。 二重カウントを避けるためにすでに使用した敵を減算するように注意が払われ、モジュラー積はゼロを短絡するように段階的に計算されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, p = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()
    min_x = max(0, min(a) - n)
    max_x = max(a)
    good_x = []
    for x in range(min_x, max_x + 1):
        c = []
        for i in range(n):
            count = sum(1 for val in a if val <= x + i)
            c.append(count - i)
        prod = 1
        for v in c:
            prod = (prod * v) % p
            if prod == 0:
                break
        if prod != 0:
            good_x.append(x)
    return f"{len(good_x)}\n{' '.join(map(str, good_x))}"

# All equal values
