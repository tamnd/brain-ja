 ## 問題の理解

 を構築するように求められています。$n \times n$グリッドは 0 と 1 だけで埋められ、正確に次のような制約が与えられます。$k$セルには 1 が含まれています。 グリッドは、グリッドがどのように配置されているかによって直接判断されるのではなく、行と列にどれだけ不均等に配置されているかによって判断されます。 

各行について、そこに含まれる行の数を数え、一連の行の合計を生成します。 列についても同じことを行います。 グリッドのコストは、これらの合計がどの程度分散するかによって決まります。最大行合計と最小行合計の差を 2 乗し、列に同じ数量を追加します。 

したがって、タスクは正確に配置するだけではありません$k$ただし、行の合計が可能な限りバランスが取れ、列の合計も可能な限りバランスが取れるように配置します。 

制約が十分に大きいため、組み合わせて配置を試行することは不可能です。 可能なグリッドの数は次のとおりであるため、すべてのグリッドを反復処理することさえ問題外です。$2^{n^2}$。 単一のグリッドを評価するだけでもコストはかかりませんが、最適なグリッドを構築するには、検索ではなく構造を理解する必要があります。 

微妙なコーナーケースが現れるのは、$k = 0$または$k = n^2$。 どちらの場合も、グリッドは完全に均一であるため、すべての行と列の合計は同一であり、コストはゼロです。 「行ごとに拡張する」という単純で貪欲なアプローチでも、これらの極端な点を慎重に扱わないと、誤って不均衡が生じる可能性があります。 

もう 1 つの注意が必要なケースは次のような場合です。$k$で割り切れない$n$。 たとえば、$n = 4, k = 7$行を均等に埋めようとするかもしれませんが、列の不均衡が実際の制限要因となり、不注意に行ごとに埋め込むと、行のバランスが取れているように見えても列に大きな差異が生じる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる可能な配置を試みます。$k$中のもの$n^2$位置を計算し、すべての行と列の合計を計算し、コスト関数を評価します。 これは正しいですが、実行不可能です。選択肢の数は$\binom{n^2}{k}$、指数関数的に増加し、中程度の場合でも天文学的に大きくなります$n$。 

重要な観察は、行の合計と列の合計の両方が、行と列に沿ってどれだけ均等に分散するかによってのみ依存するということです。 順番に配置することを考えると、行の合計の差異を最大 1 に保つことが最善であり、列の合計についても同様です。 不均衡が大きくなると、即座に二乗ペナルティが増加するため、最適な構成は可能な限り「フラット」でなければなりません。 

これは建設的な戦略につながります。つまり、行と列にわたってほぼ均一にグリッドを配置する方法でグリッドを埋めます。 これを達成する自然な方法は、行優先の順序でグリッドを走査し、1 つずつ配置することです。 ただし、行と列の両方のバランスを同時に確保するために、直線塗りつぶしではなく、循環対角パターンを使用します。 

具体的には、次の位置に配置します。$(i, (i + j) \bmod n)$、行を移動しながら列を循環します。 これにより、各行が次のいずれかを受け取ることが保証されます。$\lfloor k/n \rfloor$または$\lceil k/n \rceil$列についても同様です。 不均衡は両方の次元で同時に最小化されます。 

行と列の合計の差が最大 1 でなければならないことを受け入れると、最小コストの計算は簡単になります。追加の 1 を取得する行 (または列) の数にのみ依存します。

 ## アルゴリズムのチュートリアル

 グリッドをできるだけ均等に分散して構築します。 

1. 各行が理想的に受け取るべき値の数を計算します。 させて$q = k // n$そして$r = k \bmod n$。 これは、すべての行が次のいずれかを取得することを意味します$q$または$q+1$もの。 これは、行の合計のバランスを可能な限り維持する唯一の方法です。 
2. 最初のものに追加のものを割り当てます$r$行。 これにより、行の合計の差が最大 1 になることが保証され、最小化されます。$\max(R) - \min(R)$。 
3. 各行内で、最初の列に任意に配置するのではなく、配置を周期的にシフトします。 行$i$列に列を配置します$(i \cdot q + j) \bmod n$。 これにより、列が初期のインデックスに大きく偏るのを防ぎます。 
4. このパターンをすべての行に対して繰り返し、列の合計の差が最大 1 であることを確認します。 循環シフトは、行方向の超過を列全体に均等に分散するものです。 
5. 最後に、構築によってすでに決定されている、達成された行と列の合計の最大値と最小値を使用してコストを計算します。 

### なぜ効果があるのか

 重要な不変条件は、構築後のすべての行の合計が次のいずれかであるということです。$q$または$q+1$、すべての列の合計も次のいずれかになります$\lfloor k/n \rfloor$または$\lceil k/n \rceil$。 平均から 1 を超えて逸脱する行や列はないため、一方の分散をさらに減らそうとすると、もう一方の不均衡がさらに大きくなります。 巡回シフトにより行と列の対称性が確保されるため、どちらの次元も優先されなくなり、まさに範囲の二乗和が最小化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        
        grid = [[0] * n for _ in range(n)]
        
        q, r = divmod(k, n)
        
        # distribute ones row-wise with cyclic shifts
        for i in range(n):
            ones = q + (1 if i < r else 0)
            for j in range(ones):
                col = (i + j) % n
                grid[i][col] = 1
        
        # compute row and column stats
        row = [sum(row) for row in grid]
        col = [sum(grid[i][j] for i in range(n)) for j in range(n)]
        
        cost = (max(row) - min(row)) ** 2 + (max(col) - min(col)) ** 2
        
        print(cost)
        for row in grid:
            print(''.join(map(str, row)))

if __name__ == "__main__":
    solve()
```この構築では、まず商剰余分布を使用して行の不均衡を修正します。 各行内の巡回シフトにより、連続する行にわたって同じ列にあるものを積み重ねるのが防止されます。そうしないと、列の分散が大きくなります。 

構造がすでに最適であることが保証されているため、コストの計算は建設後にのみ行われます。

 ## 特殊なケース

 いつ$k = 0$、この構築によりオールゼロのグリッドが生成されます。 すべての行と列の合計はゼロであるため、両方の範囲はゼロであり、コストはゼロとして正しく計算されます。 循環配置を試みる貪欲な実装では、明示的に保護されていない限り、誤って列にアクセスしようとし、無効な書き込みが発生する可能性があります。 

いつ$k = n^2$、すべてのセルに 1 が入力されます。 行と列の合計はすべて$n$したがって、やはり分散はゼロになります。 構造はこれを自然に処理します。$q = n$そして$r = 0$, したがって、各行は完全に埋められます。 

いつ$k < n$、最初の行のみが 1 を受け取ります。 循環シフトにより、これらの列が個別の列に確実に分散され、列の集中が防止されます。 シフトしないと、すべての 1 が同じ列にスタックされ、1 に等しい列範囲が生成されます。これは、分散構成と比較すると最適ではありません。
