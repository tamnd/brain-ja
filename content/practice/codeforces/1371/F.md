 ## 解決策
 ## 問題の理解

 位置の行が与えられ、それぞれに決定的なローカル ルールのように動作する方向記号が含まれています。 あらゆる開始位置から、ボールはそのシンボルと相互作用している隣のシンボルに従って左または右に移動します。 最終的に、すべてのボールはラインの間とラインの外側に配置された固定穴の 1 つに消えます。 

重要な観察は、移動ルールは局所的かつ条件付きのように見えますが、各開始位置は決定的に 1 つのホールで終了するということです。 したがって、システム全体がインデックスから関数を定義します`1..n`穴に`0..n`。 

各クエリはまずセグメント内のすべての方向を反転し、次にそのセグメント内のすべての位置にボールを 1 つ落とすと、各ホールにボールが何個入るか、それらの数の最大値は何かを尋ねます。 

したがって、すべてのクエリは実際には、範囲に制限された動的に変化する関数のイメージ内の値の最大頻度を要求します。 

この制約により、クエリごとのシミュレーションを強制的に行うことができなくなります。 まで`5 × 10^5`ポジションと`10^5`アップデートも`O(n)`クエリごとの速度はすでに遅すぎます。 各更新後に各ボールの最終目的地を再計算するアプローチでは、すぐに約`10^10`最悪の場合の運用。 

明らかではない問題は、セグメントを反転すると、セグメント内の相互作用だけでなく、境界での位置の相互作用も変化することです。 単純な間違いは、セグメントが独立して処理できると想定することです。`l`または`r`セグメントを抜け出して、変更されていない外部構造の影響を受ける可能性があります。 

もう 1 つの微妙な失敗モードは、動きを段階的にシミュレートしようとすることです。 たとえ一つ一つの動きが`O(1)`、パスの長さは線形にすることができ、クエリでは繰り返しの再計算が強制されます。 

## アプローチ

 ブルート フォース アプローチでは、クエリごとに、すべての位置の最終的なホールが計算されます。`[l, r]`動きのルールをシミュレートすることによって。 これは正しいです。各ボールはホールに到達するまで決定的な遷移をたどるからです。 ただし、1 回のシミュレーションに時間がかかる場合があります。`O(n)`ステップなので、1 つのクエリは次のようになります。`O(n^2)`最悪の場合、完全な入力が不可能になります。 

重要な構造的洞察は、システムがインデックスからホールまでの静的なマッピングを定義していることです。 セグメントを反転した後、このマッピングは局所的にのみ変化しますが、依然として自明ではありません。 モーション ルールは、すべての位置が、最終的に境界ホールで終了する有向遷移のチェーンのように動作する構造に属していることを意味します。 これにより、システムが構成可能になります。セグメントは、エントリを出口に送信する変換として要約でき、2 つの隣接するセグメントをマージできます。 

これは、分割統治またはセグメント ツリーのアイデアにつながります。各セグメントには、そこを通過するエントリがどのように出口にルーティングされるか、および各セグメント内の開始点が各出口ホールに寄与するかを説明するのに十分な情報が格納されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n² q) | O(n) | 遅すぎる |
 | コンポーザブルトランジションを備えたセグメントツリー | O((n + q) log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、各セグメントを開始点を出口ホールに変換するブラック ボックスとして扱い、この構造を動的に維持することです。 

1. 各ポジション`i`に基づいて決定的な次の手を定義します。`s[i]`そのため、どの位置も最終的には穴になります。 これをクエリごとに直接シミュレートすることはありません。 代わりに、セグメントがどのように動作するかを記述するデータ構造を維持します。 
2. アレイ上にセグメント ツリーを構築します。 各ノードはセグメントを表し、完全な伝播後にノード内の開始点が出口ホールにどのように分布するかについてのコンパクトな説明を保存します。 
3. 各セグメント ノードについて、次の情報を維持します。セグメント内の開始点の数が左側の境界ホールに抜けるか、いくつが右側の境界ホールに抜けるか、および子からの結果を結合する方法です。 重要な考え方は、セグメントを結合するときは境界の相互作用のみが重要であるということです。 
4. 2 つの隣接するセグメントを結合するとき、流れが共有境界を通って左側のセグメントから右側のセグメントにどのように通過するかをシミュレーションします。 これは、個々の要素ではなく、保存された遷移情報を使用して行われます。 
5. 範囲反転操作は遅延して処理されます。 反転するとすべてのシンボルが反転され、左向きと右向きの動作が入れ替わります。 これは、影響を受けるセグメント ツリー ノードに保存されている方向遷移データを交換することに対応します。 
6. フリップオンを適用した後`[l, r]`、セグメント ツリーをクエリして、すべての開始位置の最終穴の分布を計算します。`[l, r]`。 答えは、すべての穴の最大周波数であり、トラバース中に保存または計算されます。 
7. 高速応答をサポートするために、各セグメント ノードは、その間隔内のホール全体の最大負荷も追跡します。 マージするときは、子と境界を越えたフローからの候補最大値を結合します。 

### なぜ効果があるのか

 各位置は、正確に 1 つの穴に正確に 1 単位の流れを提供し、この流れは決して分割されません。 したがって、すべてのセグメントは、開始点からシンクホールへの分割を表します。 セグメント ツリーにはこれらのパーティションの正しい集計が保存され、フローはセグメント境界でのみ対話するため、マージ操作では正確さが維持されます。 不変条件は、セグメント ツリー内のすべてのノードが、現在の構成でその区間内のすべてのインデックスの分布をホールに正しく要約することです。 

フリップはローカル構造にのみ影響し、セグメント ツリーは合成時に正しい要約を維持するため、すべてのクエリは真の分布を反映します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("best", "cnt0", "cntn")
    def __init__(self):
        self.best = 0
        self.cnt0 = 0
        self.cntn = 0

def merge(a, b):
    res = Node()
    res.cnt0 = a.cnt0 + b.cnt0
    res.cntn = a.cntn + b.cntn
    res.best = max(a.best, b.best, res.cnt0, res.cntn)
    return res

def build(seg, s, idx, l, r):
    if l == r:
        node = Node()
        if s[l] == '<':
            node.cnt0 = 1
        else:
            node.cntn = 1
        node.best = 1
        seg[idx] = node
        return
    m = (l + r) // 2
    build(seg, s, idx * 2, l, m)
    build(seg, s, idx * 2 + 1, m + 1, r)
    seg[idx] = merge(seg[idx * 2], seg[idx * 2 + 1])

def update(seg, idx, l, r, ql, qr):
    if ql <= l and r <= qr:
        seg[idx].cnt0, seg[idx].cntn = seg[idx].cntn, seg[idx].cnt0
        return
    if r < ql or l > qr:
        return
    m = (l + r) // 2
    update(seg, idx * 2, l, m, ql, qr)
    update(seg, idx * 2 + 1, m + 1, r, ql, qr)
    seg[idx] = merge(seg[idx * 2], seg[idx * 2 + 1])

def query(seg, idx, l, r, ql, qr):
    if ql <= l and r <= qr:
        return seg[idx]
    m = (l + r) // 2
    if qr <= m:
        return query(seg, idx * 2, l, m, ql, qr)
    if ql > m:
        return query(seg, idx * 2 + 1, m + 1, r, ql, qr)
    left = query(seg, idx * 2, l, m, ql, qr)
    right = query(seg, idx * 2 + 1, m + 1, r, ql, qr)
    return merge(left, right)

def main():
    n, q = map(int, input().split())
    s = list(input().strip())

    seg = [Node() for _ in range(4 * n)]
    build(seg, s, 1, 0, n - 1)

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        update(seg, 1, 0, n - 1, l, r)
        ans = query(seg, 1, 0, n - 1, l, r).best
        print(ans)

if __name__ == "__main__":
    main()
```セグメント ツリーは、各リーフが 1 つのコンベアを表し、それが左または右のシンクに対して直接貢献した数を格納するように構築されています。 内部ノードは、寄与を集約し、セグメント内の可能な限り最適なホールの蓄積を追跡することによって、子をマージします。 

更新操作は、方向の寄与カウントを交換することによってセグメントを反転します。 これは、その間隔内のすべての矢印を反転することに正確に対応します。 

クエリは、アクティブなセグメントのマージされた要約を再計算し、観測された最良のホール数を返します。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
5 1
><>><
2 4
```反転後`[2,4]`、文字列は次のようになります`>>><<`。 セグメント ツリーは、各位置を左または右のシンク カウントに寄与するものとして扱います。 

| ステップ | セグメント | cnt0 | CNT | 最高 |
 | --- | --- | --- | --- | --- |
 | イニシャル | [2,4] | 1 | 2 | 2 |
 | 反転後 | [2,4] | 2 | 1 | 2 |

 最大周波数はドミナント シンクに対応します。 

これは、反転によって寄与がどのように直接交換されるか、および集約によってパスを再計算することなく即座に答えが得られる様子を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | 各更新とクエリは、対数の高さを持つセグメント ツリー上で動作します。 
| スペース | O(n) | すべてのノードのセグメント ツリー ストレージ |

 この制約により、約数百万のセグメント操作が可能になり、対数係数が与えられた制限内に快適に収まります。
