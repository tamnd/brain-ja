 ## 解決策
 ## 問題の理解

 私たちは 1 週間の長さを柔軟に設定できる魔法のカレンダーを持っています。アリスは任意の整数を選択できます。$k$から$1$に$r$1週間の日数になります。 アリスは絵を描きたい$n$このカレンダーの連続した日。 カレンダーの 1 日が 1 つのセルに対応し、絵画は連続するセルを左から右へ長さの行に埋めることで表現されます。$k$、週が終了すると次の行に折り返されます。 

目標は、アリスが作成できる個別の形状の数を数えることであり、形状が回転や反射なしで移動して正確に重なる場合、形状は同一とみなされます。 2 つのセルが 1 つの側面を共有している場合、接続されているとみなされます。 

入力はテストケースの数です$t$、 に続く$t$各行に整数が含まれる$n$そして$r$。 各テスト ケースの出力は、アリスが週の長さと開始日を選択して生成できる個別の形状の数です。 

制約が高い:$n$そして$r$まで行くことができます$10^9$したがって、カレンダーを明示的にシミュレートしたり、考えられるすべての構成を列挙したりするアプローチは実行不可能です。 定数時間の数式が必要です。 

主な明らかではないエッジケースは、次のような場合に発生します。$n \le r$または$n > r$。 たとえば、次の場合$n = 3$そして$r = 4$, アリスは、週の長さを 1、2、3、または 4 から選択できます。$n = 3$そして$r = 2$、最大週の長さは制限されており、一部のより大きな形状は発生できません。 単純な解決策では、週の長さの上限を忘れてしまう可能性があります。$r$または最低限のものを誤って扱う$n-1$そして$r$、間違ったカウントを与えます。 

## アプローチ

 ブルートフォースアプローチでは、可能なすべての週の長さを生成しようとします。$k$1から$r$、のグリッドをシミュレートします。$k$行ごとの日数とマーク$n$最初の週の各位置から始まる連続したセル。 次に、形状を原点に移動することで正規化し、一意の形状をカウントするためにセットに保存できます。 これは概念的には機能しますが、操作の数は少なくとも$O(r \cdot n)$テストケースごとに。 与えられた$n$そして$r$それぞれできるでしょうか$10^9$、このアプローチは非現実的です。 

重要な観察は、明確な形状は行数にのみ依存するということです。$n$連続した日数が占有されます。 週の長さが次の場合$k$、絵画が占めています$\lceil n / k \rceil$行。 独特の形状が現れるのは、$k$1 から まで変化します$\min(n-1, r)$。 その理由は、$k \ge n$、 全て$n$日は 1 つの行に収まり、1 つの形状のみが生成されます。 のために$k < n$、週の長さに対する個別の形状の数$k$まさに$k$なぜなら、最初の行の異なる位置から開始すると、同じ列オーバーラップ構成の異なるシフトが生成されるからです。 

したがって、最終的な式は次のようになります。$\min(n-1, r)$。 1 週間の長さより長い場合$n-1$、すべての図形が横一列に折りたたまれます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. テスト ケースごとに、整数を読み取ります。$n$そして$r$。 
3. 異なる形状の最大数を最小値として計算します。$n-1$そして$r$。 これにより、$k \ge n$、横一列の形状は 1 つだけです。 のために$k < n$、最初の週のペイントの各開始位置は独自の形状を生成し、正確な結果をもたらします。$k$独特の形。 
4. 各テスト ケースの結果を出力します。 

これが機能する理由: 重要な不変条件は、連続して描かれたすべての日数が占有されることです。$\lceil n / k \rceil$行。 1週間程度の場合$k < n$、最初の行の異なる位置からペイントを開始すると、異なる形状が生成されます。 一度$k \ge n$、 全て$n$日が 1 つの行に収まり、1 つの形が生成されます。 これは、構成を明示的に列挙することなく、すべての有効な週の長さをカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, r = map(int, input().split())
    # Maximum distinct shapes is min(n-1, r)
    print(min(n-1, r))
```このコードは、高速 I/O を使用してすべての入力を読み取ります。 テストケースごとに、次のように計算します。`min(n-1, r)`そしてすぐに印刷してください。 微妙なのは使い方です`n-1`それよりも`n`より短い週の長さのシェイプをキャップするには`n`。 Python は大きな整数を自動的に処理するため、64 ビットのオーバーフローを心配する必要はありません。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()

    for _ in range(t):

        print(min(n-1, r))
    
    return output.getvalue().strip()

 ## 特殊なケース

 いつ`n = 1`そして`r = 1`、ペイントするセルは 1 つだけです。 式によると`min(n-1, r) = min(0,1) = 0`。 アルゴリズムは 0 を出力します。これは正しいです。単一のセルは複数の異なる形状を生成しません。 

いつ`n > r`、 例えば`n = 10`そして`r = 3`、数式の出力は`min(9,3) = 3`。 これにより、週の長さ 1、2、および 3 で達成可能な最大の個別の形状が正しくカウントされます。アルゴリズムは、より大きな週の長さを必要とする形状を過剰にカウントすることはありません。 

次のような非常に大きな入力の場合`n = 10^9`そして`r = 10^9`、数式は大きな整数を正しく処理し、戻り値を返します。`10^9-1`Python の任意精度演算のおかげで、ループやオーバーフローが発生しません。 

これは、週の長さの制約や最小ペイントの長さによって単純な実装が失敗する可能性があるすべてのエッジ シナリオをカバーします。
