 ## 解決策
 ## 問題の理解

 1 から 2 までの長さのスティックのセットがあります。$n$、各長さのスティックを 1 つずつ。 Rocher は、任意の 2 本のスティックを接続して、2 本の合計の長さの新しいスティックを形成し、その過程で元のスティックを削除します。 目標は、最終的に同じ長さになるスティックの最大数を決定することです。 入力は、次の複数の値を提供します。$n$、そしてそれぞれについて、単一の整数の答えを計算する必要があります。 

制約により許可されるのは、$n$と同じくらい大きくなる$10^9$最大 1000 のテスト ケースを使用できます。 これにより、スティック接続を明示的にシミュレートするアルゴリズムは即座に除外されます。そのようなシミュレーションには$O(n)$または$O(n \log n)$テスト ケースごとの操作数は簡単に超える可能性があります$10^9$オペレーション全般。 

明らかではないエッジケースは次のような場合に発生します。$n$は 1 や 2 など非常に小さいです。$n = 1$、棒は 1 本しかないので、答えは明らかに 1 です。$n = 2$、スティックは 1 と 2 です。それらを接続すると長さ 3 のスティックが生成されるため、特定の長さのスティックは 1 つだけです。 答えはまだ 1 です。$n = 3$、棒は 1、2、3 です。1 と 2 を接続して 3 を作ることができ、長さ 3 の棒が 2 本になるので、答えは 2 になります。このパターンを認識することは、シミュレーションなしで答えを直接計算できる数学的構造を明らかにするため、非常に重要です。 

## アプローチ

 ブルートフォース手法では、考えられるスティックの組み合わせのシーケンスをすべて列挙し、結果として得られる各スティックの長さのカウントを追跡し、任意の長さの最大頻度を決定します。 正しいですが、これは実行不可能です。$n = 10^9$がある$2^{10^9}$可能な組み合わせは、計算の限界をはるかに超えています。 

重要な洞察は、できるだけ多くの同じ長さのスティックが必要であり、2 本のスティックを組み合わせると常に大きなスティックが生成されるという事実から得られます。 すべてのスティックの合計を考慮します。$S = 1 + 2 + \dots + n = n(n+1)/2$。 同じ長さのスティックの数を最大化するには、ターゲットのスティックの長さが必要です$L$この合計のおよそ半分以下になるはずです。$L$大きすぎるので、スティックは1本しか作れません。 もう 1 つの観察は、最小のスティックと最大のスティックを繰り返し組み合わせるように、スティックを反対側の端から対称的にペアにすると、自然にほぼ同じ長さのスティックが複数生成されることです。 このパターンから簡単な公式が導かれます。同じ長さのスティックの最大数は次のとおりです。$\lfloor (n+1)/2 \rfloor$。 小さな例でこれを確認します。$n = 3$、$(3+1)//2 = 2$、これは観察された答えと一致します。 のために$n = 4$、$(4+1)//2 = 2$、これも予想される出力と一致します。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 各テストケースを繰り返していきます。 
2. 各テスト ケースについて、整数を読み取ります。$n$, ロシェが持っているスティックの数。 
3. 次の式を使用して、同じ長さのスティックの最大数を計算します。$(n+1)//2$。 これは最初の理由で機能します$(n+1)//2$スティックを残りのスティックとペアにして、同じ長さの複製を作成できます。スティックの数が奇数の場合、1 つのスティックがペアになっていないままになる可能性があり、複製の数は減りません。 
4. テストケースの結果を出力します。 

なぜ機能するのか: 公式$(n+1)//2$最小と最大のスティックを組み合わせて内側に移動することで発生します。 各ペアは同じ長さのスティックの形成に貢献し、これによりカウントが最大化されます。 この演算では各組み合わせをシミュレートする必要はなく、最大等しいスティックの数が常に約半分であるという不変条件から算術公式が導出されます。$n$丸められた。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    print((n + 1) // 2)
```コードは最初にテスト ケースの数を読み取ります。 それぞれについて$n$、直接計算します$(n+1)//2$そして結果を出力します。 整数の除算を使用すると、自動的に切り捨てられ、奇数と偶数の両方が正しく処理されます。$n$。 配列やループはありません$n$これにより、ソリューションの高速性とメモリ効率が維持されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())

        n = int(input())
        output.append(str((n + 1) // 2))
    return "\n".join(output)

 ## 特殊なケース

 のために$n = 1$、アルゴリズムの出力$(1+1)//2 = 1$スティックが 1 つしか存在しないため、これは正しいです。 のために$n = 2$、出力は$(2+1)//2 = 1$これは、2 本のスティックを接続すると、指定された長さのスティックが 1 本だけ残ることを反映しています。 大きな奇数の場合$n$のように$999999999$、$(999999999+1)//2 = 500000000$、ペアリングパターンから導出された等しい長さのスティックの理論上の最大数と一致します。 式は小規模と大規模の両方に一般化されるため、各エッジ ケースは正しく処理されます。$n$分岐せずに。
