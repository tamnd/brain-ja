 ## 問題の理解

 リアクターには、隠れたボタン押下シーケンスが表示されます。 シーケンスには長さがあります`N`、9つのボタンのみを使用します`A`を通して`I`、同じボタンを二度押すことはありません。 数回の繰り返し中に、一部のフラッシュが失われるため、各観測は実際のシーケンスのサブシーケンスにすぎません。 タスクは、すべての観測値を合わせて、考えられる元のシーケンスが 1 つだけ決定されるかどうかを判断することです。 そうであれば、印刷します。 それ以外の場合は、情報が不十分です。 

入力により、いくつかのテスト ケースが得られます。 各テスト ケースについて、ターゲット シーケンスの長さと、観察されたサブシーケンスのコレクションがわかります。 観察されたすべてのサブシーケンスでは、表示されたボタンの相対的な順序が保存されます。これは、押し忘れても要素が削除されるだけで、順序が変更されることはないためです。 

の小さな値`N`が重要な制約です。 ボタンが 9 つしかないため、検索スペースはサブセット動的プログラミングには十分に限られています。 考えられるすべてのシーケンスを直接試すソリューションでは、最大で次のことが考慮されます。`9! = 362880`のシーケンス`N = 9`。 最大 1000 のテスト ケースでは、特にすべての候補シーケンスを最大 100 の観測値に対してチェックする必要があるため、コストが高くなりすぎる可能性があります。 このアプローチの最大の効果は次のとおりです。`362880 * 100 * 1000`、快適にフィットするものをはるかに超えています。 

難しいケースは、ボタンの欠落や注文情報の不完全なために発生します。 不注意な解決策では、観察中に出現した文字のみが考慮される可能性がありますが、目に見えないボタンもターゲット パターンに属する可能性があります。

もう 1 つの注意が必要なケースは、観察されたすべてのペアに一貫性があるものの、順序が完全に修正されていない場合です。```

## アプローチ

 直接的な総当りのソリューションでは、可能なすべての長さが生成されます。`N`9 つのボタンの配置を確認し、各観測値がそのサブシーケンスであるかどうかをテストします。 有効なターゲット シーケンスが生成されたセットに出現する必要があり、生成されたすべてのシーケンスを観察に対して検証できるため、このアプローチは正しいです。 問題は候補者の数だ。 いつ`N = 9`、 がある`9! = 362880`可能性があり、それぞれをすべてチェックする必要があるかもしれません`R`観察。 検証を繰り返すと、最悪のケースでも遅くなりすぎます。 

有益な観察は、観察が相対的な順序制約を与えるだけであるということです。 観察に次のものが含まれる場合、`A C E`、その後、ターゲットは配置する必要があります`A`前に`C`そして`C`前に`E`。 フラッシュの欠落をシミュレートする必要はありません。 以前のすべての順序制約を尊重しながら、次にどのボタンを配置できるかを知る必要があるだけです。 

これにより、問題は、小さな有向グラフの有効なトポロジー次数をカウントすることに変わります。 グラフには、各ボタンに 1 つずつ、合計 9 つの可能な頂点があります。 エッジ`u -> v`すべての有効なターゲット シーケンスを次のように配置する必要があることを意味します。`u`前に`v`。 

サブセット動的プログラミングのアプローチが機能するのは、`2^9 = 512`すでに配置されているボタンの可能なセット。 すべての状態について、前提条件がすでに選択されたセット内にあるボタンの追加を試みます。 長さを何個か数えます`N`シーケンスを形成することができます。 考えられる答えが 0 つ、1 つ、または複数あることを区別するだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(9! * R * N) | O(N) | 遅すぎる |
 | 最適 | O(2^9 * 9) | O(2^9) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 観察結果から有向グラフを構築します。 隠れたシーケンスはその順序を保持する必要があるため、観察されたすべてのシーケンスについて、前の各ボタンから後のすべてのボタンにエッジを追加します。 
2. ボタンのサブセットに対してメモ化された検索を実行します。 州`mask`は、ターゲット シーケンスの先頭に既に配置されているボタンを表します。 
3. 現在の状態から、まだ使用されていないボタンをすべて試します。 ボタンの前に配置する必要があるすべてのボタンが既に存在する場合、ボタンを追加できます。`mask`。 
4. ステートに含まれたら展開を停止する`N`ボタン。 これは、考えられる完全なターゲット配列を表します。 
5. 可能な完了の数を数えます。 完了が 1 つだけある場合は、それを返します。 ゼロまたは複数の補完がある場合は、出力`NOT ENOUGH INFO`。 

これが機能する理由: すべての有効なターゲット パターンは、まさに次のトポロジカルな順序付けです。`N`制約グラフのボタン。 動的プログラミングは、そのような順序付けの可能なすべての有効な接頭辞を調査し、既知の順序付け要件をすべて尊重する場合にのみ遷移が許可されます。 考えられるすべてのターゲット パターンは状態グラフを通る 1 つのパスに対応し、すべてのパスは有効なパターンに対応するため、パスをカウントすると、考えられる答えの正確な数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case():
    N, R = map(int, input().split())

    graph = [0] * 9

    for _ in range(R):
        parts = input().split()
        r = int(parts[0])
        seq = [ord(c) - 65 for c in parts[1:]]

        for i in range(r):
            for j in range(i + 1, r):
                graph[seq[j]] |= 1 << seq[i]

    full_size = N
    memo = {}

    def dfs(mask):
        if mask.bit_count() == full_size:
            return 1, ""

        if mask in memo:
            return memo[mask]

        count = 0
        answer = ""

        for nxt in range(9):
            if mask & (1 << nxt):
                continue

            if graph[nxt] & ~mask:
                continue

            sub_count, sub_answer = dfs(mask | (1 << nxt))

            if sub_count:
                if count == 0 and sub_count == 1:
                    answer = chr(65 + nxt) + sub_answer

                count = min(2, count + sub_count)

                if count == 2:
                    answer = ""

        memo[mask] = (count, answer)
        return memo[mask]

    count, ans = dfs(0)

    if count == 1:
        return " ".join(ans)
    return "NOT ENOUGH INFO"

def main():
    t = int(input())
    out = []

    for _ in range(t):
        out.append(solve_case())

    print("\n".join(out))

if __name__ == "__main__":
    main()
```グラフはビットマスクとして保存されます。`graph[x]`ボタンの前に表示する必要があるすべてのボタンが含まれます`x`。 これにより、遷移チェックが単一ビット操作になります。現在のマスクに必要なボタンが欠落している場合、そのボタンはまだ配置できません。 

再帰関数はサブセット DP を表します。 基本ケースに達するのは、正確に`N`ターゲット パターンには重複するボタンが含まれず、長さが固定されているため、ボタンが選択されています。`N`。 

回答数の上限は 2 です。 解決策がないのか、解決策が 1 つだけあるのか、それとも複数の解決策があるのか​​だけを考慮します。 より大きなカウントを維持すると、決定を変更せずに作業が追加されます。 

再構築文字列は、状態に継続が 1 つだけある場合にのみ保持されます。 2 つの異なるパスが見つかった場合、最終結果があいまいになるため、保存されている回答は破棄されます。
