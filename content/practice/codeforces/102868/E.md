 ## 解決策
 # 問題の理解

 タスクは、無限グリッド上の点をある格子点から別の格子点に移動することです。 1 回の移動で 1 つの座標が 1 単位ずつ変更されるため、すべての移動は 4 つの基本方向のいずれかになります。 同じ方向を 2 回連続して使用できないという制限があります。 たとえば、北に 2 回続けて移動することは禁止されていますが、北、東、北に移動することは許可されています。 

シナリオごとに、ポイントの開始座標と終了座標が与えられます。 必要な出力は、方向制限を尊重しながら必要な最小移動数です。 

座標は次のように大きくできます。$10^{18}$、最大 1000 のシナリオが可能です。 これにより、パスまたはグラフ検索のシミュレーションが直ちに除外されます。 ソリューションでは、テスト ケースごとに算術演算のみを使用する必要があります。これは、点間の距離を反復する場合でも、最大で$10^{18}$ステップ。 

重要な問題は、マンハッタンへの最短経路が常に有効であるとは限らないことです。 通常の最短パスでは、必要な数の水平方向および垂直方向の移動が正確に使用されますが、同じ種類の移動が連続して多すぎる場合があります。 パスは水平方向と垂直方向の移動を頻繁に繰り返す必要があります。 

不注意な実装が失敗する次のようなケースを考えてみましょう。 

からの移動のために$(0,0)$に$(5,0)$、マンハッタンの距離は 5 です。単純な解法では 5 が出力されますが、すべての移動が水平であるため、これは不可能です。 正解は 10 です。有効なルートの 1 つは、右、上、右、下、右、上、右、下、右、下です。 

からの移動のために$(0,0)$に$(2,1)$、マンハッタンの距離は 3 です。2 つの水平方向の移動は垂直方向の移動によって分離できるため、これはすでに有効です。 正しい出力は 3 です。両方の座標がゼロ以外の場合に常に余分な迂回路を追加するアプローチでは、間違った答えが生成されます。 

からの移動のために$(1,1)$に$(1,1)$の場合、答えは 0 です。移動が必要ないため、迂回路を追加する必要はありません。 

# アプローチ

 強引なアイデアは、現在位置と以前の方向を追跡しながら、段階的にパスを構築しようとすることです。 すべての状態には、どの手が合法であるかを決定するために必要な情報が正確に含まれているため、これは制限を正確にモデル化します。 しかし、グリッドは巨大です。 可能な位置の数は座標の距離とともに増加するため、位置に対する幅優先検索や動的プログラミングは不可能です。 座標が近くにある場合、マンハッタンの距離の単純なシミュレーションでも失敗します。$10^{18}$。 

有益な観察は、実際の方向は最初は重要ではないということです。 重要なのは、横方向の動きと縦方向の動きをどれだけ使用するかです。 有効な動きのシーケンスでは、シーケンスの両端で一方のタイプがもう一方のタイプよりも 1 回ずつ出現する場合を除き、水平方向と垂直方向の動きを交互に行う必要があります。 

必要な水平距離と垂直距離が次のとおりであると仮定します。$x$そして$y$。 少なくとも必要です$x$少なくとも水平移動$y$垂直方向の動き。 追加の移動はバックトラック ペアとしてのみ有用であるため、軸の総移動数は必要な距離と同じパリティを持つ必要があります。 可能な最小のカウントは最初は$x$そして$y$。 それらの差が最大 1 であれば、すでに交互のシーケンスに配置できます。 

1 つの軸が 2 倍以上大きい場合、小さい方の軸がセパレータとして機能するために追加の移動が必要になります。 追加の動きはペアで行われるため、差が最大 1 になる最小の偶数だけ小さいカウントを増やします。

 # アルゴリズムのチュートリアル

 1. 開始点と終了点の間の絶対的な水平距離と垂直距離を計算します。 電話してください$x$そして$y$。 左右、上下どちらに移動しても同じ構造が機能するため、距離だけが重要です。 
2. しましょう`big`大きい方であること$x$そして$y$、そしてさせてください`small`もう一人になってください。 もし`big - small`が最大 1 の場合、マンハッタンのパスはすでに交互方向ルールと互換性があるため、答えは単純です。`big + small`。 
3. 差が 1 より大きい場合は、値を大きくします。`small`偶数で。 追加された動きは、小さい軸上での往復を表します。 2 つの手数の差を最大 1 に減らす最小の偶数加算を選択します。 
4. 新しい総移動数を返します。 

これが機能する理由は、すべての有効なパスが水平方向と垂直方向の移動の交互のシーケンスとして見なせるためです。 このようなシーケンスでは、1 つのカテゴリを他のカテゴリの上に複数回出現させることはできません。 アルゴリズムは、その条件を正確に満たすために必要な追加の移動の最小数を見つけます。 追加の動きはペアとしてのみ追加され、最終的な座標が保存されるため、結果として得られるカウントは達成可能かつ最小限になります。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        a, b, c, d = map(int, input().split())

        x = abs(c - a)
        y = abs(d - b)

        big = max(x, y)
        small = min(x, y)

        diff = big - small
        if diff > 1:
            add = diff - 1
            if add % 2:
                add += 1
            small += add

        ans.append(str(big + small))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```プログラムはまず、座標の変化を 2 つの非負の距離に変換します。 余分な動きは常に往復であるため、動きの兆候は無関係です。 

変数`big`そして`small`交互の問題を解決する前に、各軸で必要な移動数を表します。 大きい軸の移動が多すぎる場合、コードは小さい軸を均等量だけ増加させます。 追加のセパレータは遠方への移動と後方への移動で構成され、常に 2 つの移動が追加されるため、パリティ調整が必要です。 

Python の整数は、$10^{18}$座標範囲を直接扱うため、オーバーフロー処理は必要ありません。 この実装ではパスが構築されないため、実行時間とメモリの両方が一定に保たれます。

# エッジケース

 入力など、両方の点が同一の場合:```
1
3 4 3 4
```距離は$x=0$そして$y=0$。 差はゼロであるため、アルゴリズムはすぐにゼロを返します。 方向の衝突がないため、無駄な動きを追加しません。 

次のように、動きが 1 つの軸のみに存在する場合:```
1
0 0 5 0
```初期カウントは水平方向です$5$そして垂直$0$。 差が 5 なので、最初に 4 つの縦方向の手が追加されますが、その量は均等でなければなりません。 差を 1 に減らすには 4 つで十分ですが、小さい方の側は正しいパリティを持つ必要があるため、さらに 1 つのペアが必要となり、5 つの垂直方向の移動と最終的な答えは 10 になります。 

次のように、両方の軸の距離が同様の場合:```
1
0 0 3 2
```カウントは 1 つずつ異なるため、余分な動きは必要ありません。 アルゴリズムは 5 を返し、移動は水平、垂直、水平、垂直、水平の順序で実行できます。 

次のような座標が非常に大きい場合:```
1
0 0 1000000000000000000 0
```アルゴリズムは減算、比較、加算のみを実行します。 経路を構築しようとすることは決してないので、膨大な距離が走行時間に影響することはありません。
