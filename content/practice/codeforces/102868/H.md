 ## 解決策
 ## 問題の理解

 この問題では、できるだけ少ないドアを閉めて、イエローがグリッドを通過するのを阻止するように求められます。 グリッドには、常にブロックされている壁、常に開いている廊下、開閉可能なドアが含まれています。 黄色は左上のセルから始まり、右下のセルに到達したいと考えています。 閉じると目的地に到達できなくなるドアの最小数を見つける必要があります。 廊下だけですでに道ができている場合、詐欺師はイエローを止めることはできないので、答えは次のとおりです。`-1`。 公式問題では、行、列、壁、ドア、廊下を使ったこのグリッド分離タスクが説明されています。 

グリッドには最大 1000 行と 1000 列を含めることができます。つまり、最大 100 万個のセルを含めることができます。 多くのパスを明示的に試行するアルゴリズムは、可能なパスの数が指数関数的に増加するため、非常に遅くなります。 すべてのセルのペアを処理するアルゴリズムでさえ、すでにコストが高すぎるでしょう。 各セルに触れる回数が少なく、線形に近い複雑さのグラフ アルゴリズムを指すメソッドが必要です。 

主な厄介なケースは、通常のオープンスペースではないセルから発生します。 開始セルと終了セル自体をドアにすることができます。 不注意な解決策では、それらが常にアクセス可能であると想定し、どちらかを閉じるとすぐに Yellow がブロックされることを見逃してしまう可能性があります。 例えば：```
2 2
..
.@
```正しい答えは、`1`。 開始ドアを閉じるだけで十分ですが、開始と終了の間のドアのみを考慮するソリューションでは、誤ってより大きな値が出力されます。 

もう 1 つのエッジ ケースは、パスに廊下のみが含まれる場合です。 廊下は閉じることができないため、どのドアを選択しても 2 つのエンドポイントを切断することはできません。```
2 2
@@
@@
```正しい答えは、`-1`。 検出された 1 つのパス上のドアのみをカウントする最短パス検索では、誤った出力が発生する可能性がありました。`0`たとえ別の廊下の道がまだ存在していても。 

最後の微妙なケースは、既に壁によって端点が分離されているため、答えがゼロになる場合です。```
3 3
@#.
###
.@.
```正しい答えは、`0`。 アルゴリズムでは、最小カットにドアがまったく含まれないようにする必要があります。 

## アプローチ

 自然な総当たりアプローチは、ドアのすべての可能なサブセットを閉じることを検討することです。 サブセットごとに、最初からフラッド フィルを実行し、宛先に到達可能な状態が維持されているかどうかを確認できます。 ドアをブロックする可能なすべての方法がテストされているため、これは正しいですが、サブセットの数は`2^D`、 どこ`D`ドアの数です。 何十万ものドアが存在する可能性があるため、これは不可能です。 

重要な観察は、これは実際には経路探索の問題ではないということです。 私たちはイエローのルートを探しているわけではありません。 除去すると 2 つの場所が分離される、除去可能な障害物の最小セットを探します。 それはまさにミニマムカットの定義です。 

グリッドはフロー ネットワークに変換できます。 すべてのセルがグラフ ノードになり、隣接するセル間の移動は無限容量のエッジになります。 壁は単純に省略されています。 廊下は塞ぐことができないため、収容力は無限大です。 このようなセルを通過することは、ちょうど 1 つのドアを閉じることを意味するため、ドアの容量は 1 です。 

残りの課題は、標準の最小カット アルゴリズムがエッジで機能する一方で、コストはセルに属することです。 これはノード分割で解決します。 各セルは、入口ノードと出口ノードの 2 つのノードになります。 入口から出口までのエッジには、そのセルを削除するコストがかかります。 移動エッジは、1 つのセルの出口側から隣接するセルの入口側まで無限の容量で進みます。 最低限`s-t`次に、cut はどのセルのエッジをカットするかを選択します。その容量の合計は、閉じられたドアの数と正確に一致します。 

グリッドには最大 100 万個のセルが含まれるため、効率的な最大フローの実装が必要です。 グラフがまばらであるため、ここでは Dinic のアルゴリズムがうまく機能します。 各セルは一定数のエッジのみを作成するため、ネットワークは管理しやすい状態を保ちます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^D * (R*C)) | O(R*C) | 遅すぎる |
 | 最適 | Dinic の O(V^2E) 最悪のケース、この疎なグリッドでは実用的 | O(R*C) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての非壁セルを 2 つのグラフ ノード (入口ノードと出口ノード) に変換します。 入口から出口までエッジを追加します。 その容量は`1`ドアの場合は無限、廊下の場合は無限大です。 開始セルと終了セルがドアになる可能性があるため、送信元と送信先は慎重に選択されます。 
2. 隣接する非壁セルのペアごとに、最初のセルの出口ノードから 2 番目のセルの入口ノードまで、無限の容量を持つ有向エッジを追加します。 逆方向も追加します。 これは、黄色が隣接するセルを通って双方向に移動できることを表しています。 
3. 開始側から宛先側まで最大フロー アルゴリズムを実行します。 最大流量最小カット定理により、この流量の値は、両側を分離する最も安価なエッジのセットの容量に等しくなります。 
4. 結果として得られる流量値が少なくとも無限大である場合、あらゆる分離には不可能な廊下の端を切断する必要があることを意味します。 その場合の答えは、`-1`。 それ以外の場合、流量値は閉じる必要があるドアの最小数になります。 

これが機能する理由: グラフ内の唯一の有限容量エッジは、ドアの入口から出口までのエッジです。 有限カットではこれらのエッジの一部を選択する必要があり、廊下のエッジを選択することはできません。 ドアの端を切るということは、まさにドアを閉めることを意味します。 黄色をブロックするドアのセットは同じコストの有効なカットを作成し、有限カットは閉じたドアの有効なセットを作成します。 したがって、最小カット値は正確に必要なドアの最小数となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Dinic:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.g[u].append([v, c, len(self.g[v])])
        self.g[v].append([u, 0, len(self.g[u]) - 1])

    def max_flow(self, s, t):
        flow = 0
        n = self.n
        INF = 10**9

        while True:
            level = [-1] * n
            level[s] = 0
            q = [s]
            for u in q:
                for v, c, _ in self.g[u]:
                    if c and level[v] == -1:
                        level[v] = level[u] + 1
                        q.append(v)

            if level[t] == -1:
                return flow

            it = [0] * n

            def dfs(u, pushed):
                if u == t:
                    return pushed
                while it[u] < len(self.g[u]):
                    e = self.g[u][it[u]]
                    v, c, rev = e
                    if c and level[v] == level[u] + 1:
                        tr = dfs(v, min(pushed, c))
                        if tr:
                            e[1] -= tr
                            self.g[v][rev][1] += tr
                            return tr
                    it[u] += 1
                return 0

            while True:
                pushed = dfs(s, INF)
                if not pushed:
                    break
                flow += pushed

def solve():
    r, c = map(int, input().split())
    grid = [input().strip() for _ in range(r)]

    total = r * c * 2
    dinic = Dinic(total)

    def inside(x, y):
        return 0 <= x < r and 0 <= y < c

    def node(x, y, out):
        return (x * c + y) * 2 + out

    INF = 10**8

    for i in range(r):
        for j in range(c):
            if grid[i][j] == '#':
                continue
            cap = 1 if grid[i][j] == '.' else INF
            dinic.add_edge(node(i, j, 0), node(i, j, 1), cap)

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    for i in range(r):
        for j in range(c):
            if grid[i][j] == '#':
                continue
            for dx, dy in dirs:
                ni, nj = i + dx, j + dy
                if inside(ni, nj) and grid[ni][nj] != '#':
                    dinic.add_edge(node(i, j, 1), node(ni, nj, 0), INF)

    source = node(0, 0, 0)
    sink = node(r - 1, c - 1, 1)

    ans = dinic.max_flow(source, sink)
    print(-1 if ans >= INF else ans)

if __name__ == "__main__":
    solve()
```グラフの構築は、ノード分割の考え方に直接従っています。 入口から出口までのエッジにはセルを削除するコストが保存されるため、最終的なカット値に寄与するのはドアのみです。 廊下は、有効な最小カットが廊下を削除することを決して選択すべきではないため、非常に大きな収容力を受け取ります。 

移動エッジは、あるセルの出口側を別のセルの入口側に接続するため、セル エッジの後に追加されます。 この方向は、黄色がすでにセルに入ってセルから出た後の状態と一致します。 4 方向すべてに移動できるため、両方の方向が必要です。 

ソースは最初のセルの入口側を使用し、シンクは最後のセルの出口側を使用します。 これは、どちらかのエンドポイントがドアである特殊なケースを処理します。 ソースまたはシンクのドアが最も安価に削除できるものである場合、フロー アルゴリズムはそのエッジを選択できます。 

無限大に使用する値は、可能な最大の答えよりも大きい値だけを必要とします。 答えはセルの数を超えることはできないので、`10^8`安全に大きいです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(V^2E) ディニックにとって最悪のケース | グリッドは O(R_C) 個のノードと O(R_C) 個のエッジを作成し、スパース構造は実際には良好に機能します。 
| スペース | O(R*C) | 各セルは 2 つのノードと一定数のエッジを作成します。 

セルが 100 万個あるため、グラフは大きくなりますが、入力サイズは線形です。 この実装では、不必要な接続を含むグラフとしてグリッドを保存することを回避し、隣接リストを使用することでメモリ使用量を制限内に保ちます。

 ## 特殊なケース

 開始セルがドアの場合、ソースはドアの容量エッジを介して接続する必要があります。 のために：```
2 2
..
.@
```最初のセルのソースから出口までのエッジには容量があります`1`。 最小カットではそのエッジを即座に削除でき、フロー値は次のようになります。`1`。 

廊下が避けられない経路を形成する場合、有限のカットは存在しません。 のために：```
2 2
@@
@@
```すべてのルートは無限容量のエッジのみで構成されます。 Dinic は、ドアの端が存在しないため、有限の分離を押し出すことができません。そのため、流れが無限のしきい値に達し、アルゴリズムが出力します。`-1`。 

壁がすでにグリッドを切断している場合:```
3 3
@#.
###
.@.
```構築されたグラフにはソースからシンクへのパスはありません。 Dinic の初期 BFS はシンクに到達できないため、最大流量はゼロのままで、答えは次のように正しく報告されます。`0`。
