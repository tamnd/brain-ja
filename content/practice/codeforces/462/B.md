 ## 解決策
 ## 問題の理解

 Appleman は _n_ 枚のカードのコレクションを持っており、それぞれに大文字のラベルが付けられています。 トーストマンは正確に _k_ 枚のカードを選ぶことができ、彼が選ぶカードごとに、アップルマンはそのカードと同じ文字を持つトーストマンのカードの枚数に等しいコインをトーストマンに支払います。 言い換えれば、トーストマンが同じ文字を持つ複数のカードを選んだ場合、それらの各カードは、手札にあるその文字の数を合計に加えます。 

入力は、カードの数 _n_、選択するカードの数 _k_、および各文字がカードの文字を表す長さ _n_ の文字列を与えます。 出力は単一の整数である必要があります。トーストマンがカードを最適に選択した場合に獲得できるコインの最大数です。 

境界は重要です。 _n_ が最大 100,000 で、時間制限が 1 秒であるため、O(n log n) よりも悪いアルゴリズムはタイムアウトになる危険性があります。 サイズ _k_ の考えられるすべてのサブセットをチェックする単純なアプローチは、完全に実行不可能です。サブセットの数は、n が k を選択するオーダーで組み合わせ的に増加するためです。 

複数の文字が何度も出現するが、個々の文字が _k_ 未満である場合、明らかではないエッジ ケースが発生します。 たとえば、カードが次のような場合`AABBC`_k_ は 4 です。単純に最初の _k_ 枚のカードを順番に取る単純なアプローチでは、`AABB`または`ABBC`。 最適なのは`AABB`2 つの A と 2 つの B を選択すると、繰り返される文字が最大化され、コインが最大化されるためです。 もう 1 つのエッジ ケースは、_k_ が最も頻繁に使用される文字の数を超える場合です。 アルゴリズムは次に頻繁に使用される文字を補足する必要があります。 

## アプローチ

 ブルートフォースアプローチは、_k_ 枚のカードのすべての組み合わせを調べ、各組み合わせのコインの合計を計算し、最大値を維持することです。 これはあらゆる可能性をテストするので原理的には正しいですが、_n_ = 100,000 や中程度の _k_ の場合でも組み合わせの数が天文学的に増えるため、使用できません。 

重要な観察は、コインの獲得が、選択されたカードに文字が出現する回数に関して二次関数であるということです。 トーストマンが同じ文字の _x_ 枚のカードを選択すると、それらは合計コインに _x²_ を寄付します。 したがって、コインを最大化するには、最初に最も頻繁に出現する文字からできるだけ多くのカードを選択し、次に最も頻繁に出現する文字を選択し、合計 _k_ 枚のカードを選択するまで繰り返す必要があります。 残りの _k_ が次の文字のカウントより小さい場合、単純にその枚数のカードを取り、選択したカウントの 2 乗を寄付します。 

これは古典的な貪欲な戦略です。つまり、二次ゲインが最大化されるため、常に最も高い頻度の文字を最初に取得します。 カウントを降順に並べ替えることで、常に最適な文字を選択できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n は k を選択) | O(n) | 遅すぎる |
 | 最適 | O(n + 26 log 26) ≈ O(n) | O(26) ≈ O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カード文字列内の各文字の出現を数えます。 大文字には辞書または 26 要素の配列を使用します。 これにより、各文字の頻度がわかります。 
2. 周波数を降順に並べ替えます。 これにより、最も多くのコインを提供する文字を常に最初に選択することが保証されます。 
3. 変数を初期化する`coins = 0`そして`remaining = k`。 ソートされた周波数をループします。 
4. 周波数ごと`f`、 もし`f <= remaining`、 追加`f * f`に`coins`そして引きます`f`から`remaining`。 
5. もし`f > remaining`、のみを取る`remaining`その文字のカードを追加してください`remaining * remaining`に`coins`、設定します`remaining = 0`。 正確に _k_ 枚のカードを選択したため、ループを終了します。 
6. 印刷`coins`。 

これが機能する理由: 不変条件は、すべてのステップで、残りの _k_ 個のピックの平方和を最大化する文字のセットを選択していることです。 大きな数を二乗すると、小さなグループに分割するよりも常に大きな増分が得られます。 したがって、同じ _k_ 枚のカードを他の配布しても、これ以上のコインを生み出すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
cards = input().strip()

# Step 1: Count letter frequencies
freq = [0] * 26
for c in cards:
    freq[ord(c) - ord('A')] += 1

# Step 2: Sort frequencies descending
freq.sort(reverse=True)

coins = 0
remaining = k

# Step 3: Greedy selection
for f in freq:
    if remaining == 0:
        break
    take = min(f, remaining)
    coins += take * take
    remaining -= take

print(coins)
```最初のセクションでは、定数アクセスのために ASCII インデックスを使用して文字をカウントします。 並べ替えにより、貪欲な選択により、利用可能な最大のグループが最初に選択されるようになります。 ループ内では、`take = min(f, remaining)`残りのスロットが周波数よりも少ない場合を処理します。これは見落とされやすく、off-by-one エラーの一般的な原因です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + 26 log 26) ≈ O(n) | 文字のカウントは O(n)、26 個の頻度のソートは一定です |
 | スペース | O(26) ≈ O(1) | 26 文字の頻度配列のみが使用されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    cards = input().strip()
    freq = [0] * 26
    for c in cards:
        freq[ord(c) - ord('A')] += 1
    freq.sort(reverse=True)
    coins = 0
    remaining = k
    for f in freq:
        if remaining == 0:
            break
        take = min(f, remaining)
        coins += take * take
        remaining -= take
    return str(coins)

# provided sample
assert run("15 10\nDZFDFZDFDDDDDDF\n") == "82"

# custom cases
assert run("5 3\nAABBC\n") == "5", "mixed letters, k less than max count"
assert run("3 3\nAAA\n") == "9", "all letters same"
assert run("4 2\nABCD\n") == "1", "all different, pick 2"
assert run("1 1\nZ\n") == "1", "single card"
assert run("100000 100000\n" + "A"*100000 + "\n") == "10000000000", "max size all same"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 5 3、AABBC | 5 | 部分周波数による貪欲な選択 |
 | 3 3、AAA | 9 | すべてのカードが同じ |
 | 4 2、ABCD | 1 | すべて異なる文字、k < n |
 | 1 1、Z | 1 | 最小入力 |
 | 100000 100000、すべて A | 10000000000 | 最大入力サイズ |

 ## 特殊なケース

 _k_ が最も一般的な文字の頻度を超えると、アルゴリズムは次に高い頻度まで正しく続行されます。 たとえば、入力の場合`AABBC`および *k=4` の場合、最も頻繁に使用される文字 'A' の頻度は 2 です。アルゴリズムは両方の As を取得し、2 が残ります。 次に、「B」の頻度は 2 であり、残り = 2 なので、両方の B がかかります。 コインの合計 = 2² + 2² = 8。常に最初の k 文字を順番に取る単純なアプローチでは、合計が誤って異なってしまう可能性があります。 貪欲不変式は、すべてのステップで可能な限り最大の寄与が選択されることを保証し、正確性を保証します。
