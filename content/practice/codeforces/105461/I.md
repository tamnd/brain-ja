 ## 解決策
 ## 問題の理解

 固定整数を法とする線形漸化によって生成されたシーケンスが与えられます。$M$。 シーケンスは 2 つの初期値から始まります$a_0$そして$a_1$、次のすべての要素は、固定係数を使用して前の 2 つの要素を結合することによって形成されます。$A$そして$B$、次に結果のモジュロを削減します$M$。 これは決定論的なプロセスであるため、最初のペアが固定されると、無限シーケンス全体が固定されます。 

課題は、このシーケンスが最終的にいつ周期的になるかを判断することであり、さらに重要なことは、最小のプラスのシフトを見つけることです。$T$ある位置以降、シーケンスが毎回繰り返されるようにします。$T$永遠の歩み。 

重要な観察は、シーケンスがペアによって完全に決定されるということです。$(a_i, a_{i+1})$。 同じペアが再び現れると、次の値はこれら 2 つにのみ依存するため、反復により将来のすべての値が同じように繰り返されます。 

制約$M \le 10^9$すべての状態を明示的に追跡するアプローチは除外されます。 状態空間は概念的には一定のサイズであるにもかかわらず、$M^2$、反復したり保存したりすることはできません。 1 秒という制限時間は、周期が非常に長くなる可能性があるため (最大$10^{18}$）。 

すべてのペアを保存して繰り返しを検出しようとすると、単純な落とし穴が発生します。$(a_i, a_{i+1})$。 期間が長いと、すぐにメモリの問題が発生します。 もう 1 つの微妙な問題は、最初の繰り返しで正しい周期が与えられると仮定することです。 シーケンスは一時的なプレフィックスの後にサイクルに入る可能性があるため、状態グラフの意味で最初に繰り返される状態でない限り、ペアの最も早い繰り返しが必ずしも最終的な周期構造であるとは限りません。 

## アプローチ

 反復により、ペアの決定的な遷移が定義されます。$$(a_{i-1}, a_i) \rightarrow (a_i, a_{i+1})$$どこ$$a_{i+1} = (A a_i + B a_{i-1}) \bmod M.$$これは、各ノードが次の値のペアである有向グラフをたどることを意味します。$[0, M)$、各ノードには出力エッジが 1 つだけあります。 このような構造は関数グラフであるため、すべての接続されたコンポーネントは、それにフィードされる有向ツリーを含む単一のサイクルで構成されます。 

ブルートフォース手法では、訪問されたすべてのペアを保存しながらシーケンスをシミュレートします。 ペアが繰り返される瞬間に、サイクルが検出されます。 関数グラフは最終的な繰り返しを保証するため、これにより周期性が正しく識別されます。 ただし、訪問したすべての状態を保存するには、$O(M^2)$最悪の場合はメモリが失われ、さらには最大$10^9$価値観は実現不可能です。 サイクルが非常に長くなる可能性があるため、時間も問題になります。 

重要な構造的洞察は、一般的なグラフの繰り返しまでシミュレーションすることを求められるのではなく、むしろ線形漸化モジュロを分析することを求められるということです。$M$。 これは、有限リング内のベクトルの線形変換を研究することに相当します。 ペアの進化は線形マップです。$$\begin{pmatrix}
a_i \\
a_{i+1}
\end{pmatrix}
=
\begin{pmatrix}
0 & 1 \\
B & A
\end{pmatrix}
\begin{pmatrix}
a_{i-1} \\
a_i
\end{pmatrix}
\bmod M.$$したがって、問題は、反復乗算モジュロの下で行列シーケンスの周期を見つけることに帰着します。$M$。 サイクル長は、初期ベクトルに作用するこの行列の次数に対応しますが、空間は有限であるため、システムは最終的に有界サイクル構造内で前の状態に戻らなければならないという事実を利用できます。 

より直接的な観察は、システムはペアの関数グラフであるため、周期がサイクルに入ると到達するサイクルの長さと正確に一致するということです。 フロイドのサイクル検出アルゴリズムを使用してサイクルを見つけることができます。このアルゴリズムでは、すべての状態の保存を回避し、定数メモリのみを使用します。 

繰り返される状態を見つけたら、サイクルの周囲を 1 回歩くことでサイクルの長さを計算できます。

 ## アルゴリズムのチュートリアル

 各状態をペアとして扱います$(x, y) = (a_i, a_{i+1})$。 遷移関数は次のペアを計算します。 

1. ペアをマッピングする関数を定義する$(x, y)$に$(y, (A \cdot y + B \cdot x) \bmod M)$。 これにより、繰り返しが状態遷移として直接キャプチャされます。 
2. 2 つのポインターを使用してフロイド周期検出を実行します。 一方のポインタは一度に 1 ステップずつ進み、もう一方のポインタは一度に 2 ステップずつ進みます。 それらが一致すると、サイクルが存在します。 これが機能するのは、状態空間が有限であるため、繰り返しが保証されるためです。 
3. 1 つのポインタを初期状態にリセットし、両方のポインタが再び一致するまで一度に 1 ステップずつ移動します。 これにより、サイクルのエントリ ポイントが得られます。 これが機能する理由は、同期動作が使用される場合、開始からサイクル開始までの距離が両側で等しいためです。 
4. サイクルの開始点から始めて、同じ状態に戻るまで歩数を数えながら前に歩きます。 このカウントはサイクル長であり、まさに必要な期間です。 
5. 各テスト ケースのサイクル長を出力します。 

### なぜ効果があるのか

 各状態は決定的に 1 つの次の状態に遷移するため、一連の状態は有限有向グラフ内のパスを形成します。 このようなグラフは、最終的にはある状態を再訪し、サイクルを形成する必要があります。 サイクルに入ると、サイクル長に等しい固定シフトでシーケンスが繰り返されます。 フロイドのアルゴリズムは、同じサイクル内の 2 つのトラバースの相対速度の違いを利用することで、履歴を保存せずにこのサイクルの検出を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def nxt(x, y, A, B, M):
    return y, (A * y + B * x) % M

def cycle_length(a0, a1, A, B, M):
    tortoise = (a0, a1)
    hare = nxt(a0, a1, A, B, M)

    while tortoise != hare:
        tortoise = nxt(*tortoise, A, B, M)
        hare = nxt(*nxt(*hare, A, B, M), A, B, M)

    start = (a0, a1)
    mu = 0
    tortoise = start
    while tortoise != hare:
        tortoise = nxt(*tortoise, A, B, M)
        hare = nxt(*hare, A, B, M)
        mu += 1

    lam = 1
    hare = nxt(*tortoise, A, B, M)
    while tortoise != hare:
        hare = nxt(*hare, A, B, M)
        lam += 1

    return lam

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        M, a0, a1, A, B = map(int, input().split())
        out.append(str(cycle_length(a0, a1, A, B, M)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、繰り返しを完全にエンコードします。`nxt`関数を使用して、状態遷移がアルゴリズム内のどこでも一貫した状態に保たれるようにします。 フロイドの周期検出は 3 つのフェーズで実装されます。最初に集合点を検出し、次に周期の入り口を見つけ、最後に周期の長さを測定します。 

微妙な点は、状態がタプルとして保存され、辞書検索ではなくハッシュなしの比較であることです。 これによりオーバーヘッドが回避され、各ステップの時間が一定に保たれます。

 ## 特殊なケース

 重要なエッジ ケースは、シーケンスがすぐに自己ループに入る場合です。 例えば、$M = 10, a_0 = 5, a_1 = 5, A = 0, B = 0$。 次の値は常に 0 であり、シーケンスは一定になります。 このアルゴリズムは最初の比較で状態が繰り返されることを検出し、状態は 1 ステップ後にそれ自体に遷移するため、サイクル長は 1 として計算されます。 

もう 1 つのエッジ ケースは、一時的なプレフィックスなしで再発が短いサイクルに崩壊する場合です。 のために$M = 3, a_0 = 0, a_1 = 1, A = 2, B = 2$、シーケンスはすぐに循環します。 フロイドのアルゴリズムは、カメとウサギがサイクル自体の中で出会うため、以前の状態を保存する必要なしにこれを検出します。 

3 番目のエッジ ケースは、サイクル長が長く、理論的限界に近い場合です。$10^{18}$。 このアルゴリズムは状態を列挙しようとしません。 ポインタが一致するまでのみ追跡し、その後サイクルを直接測定して、大きさに関係なく正確さを保証します。
