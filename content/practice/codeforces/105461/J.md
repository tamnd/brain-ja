 ## 解決策
 ## 問題の理解

 1 から n までの位置の隠された並べ替えを扱っています。 長さ n の単語を送信するたびに、システムはこの固定順列に従って文字を再配置し、結果を返します。 

順列はすべてのクエリで一貫しているため、すべての応答はインデックスの決定論的な再ラベル付けにすぎません。 タスクは、それぞれの元の位置がどこに終わるかを正確に再構築することです。 

主な難点は、対話が最大 4 回までしかなく、n が 100000 に達する可能性があることです。これにより、一度に 1 つの位置の順列を回復しようとする戦略は除外されます。 各インデックスを個別にクエリするアプローチは、インタラクションの制限をすぐに超えてしまい、位置のプローブペアに基づく非インタラクティブな再構築であっても、依然として線形または超線形のインタラクションカウントを必要とします。 

この構造は、各クエリが多くの位置に関する情報を同時に伝える必要があり、各応答によって位置の同一性を間接的に抽出できる必要があることを示唆しています。 

同一の文字や低解像度のラベルを割り当てようとすると、微妙に失敗するケースが発生します。 たとえば、すべての文字列を送信すると、`'a'`、応答もすべてです`'a'`、これは順列について何も明らかにしません。 同様に、少数の区別可能なシンボルのみを使用すると、複数の位置が同じ署名を共有する衝突が発生し、再構築が曖昧になります。 

中心となる要件は、4 つのクエリのみを使用しながら、すべての位置が順列後に回復できる一意の ID を持っていることを保証することです。 

## アプローチ

 強引なアイデアは、位置を分離するクエリを作成して、各インデックスがどこに行くのかを特定しようとすることです。 たとえば、1 つの位置だけが異なるマークが付けられた文字列を送信し、そのマークが出力のどこに表示されるかを観察することができます。 これは、クエリごとに 1 つの位置の動きを追跡できるため、機能します。 ただし、これは規模的にはすぐに失敗します。n 個の位置を特定するには Θ(n) クエリが必要ですが、許可されるクエリは 4 つだけです。 

重要な観察は、位置を順番に識別する必要がないということです。 代わりに、すべての位置を小さな固定長の署名でエンコードし、置換後にその署名を復元できます。 

順列は情報を破壊しません。 それを再配置するだけです。 各位置が一意の「ラベル ベクトル」を持つ場合、並べ替え後、それらのベクトルは位置間で単純にシャッフルされます。 各出力インデックスで見られるベクトルを再構築できれば、それを元の位置にマップし直すことができます。 

わずか 4 つのクエリで、各ポジションは 4 つの情報シンボルを提供できます。 26 文字のアルファベットを使用すると、各シンボルは基数 26 の数字をエンコードできます。 これにより、26^4 の可能な個別コードが得られます。これは、n が 100000 までの場合は十分以上です。 

各位置に 4 桁の基数 26 表現を割り当てます。 クエリ k では、位置 i に文字として k 番目の桁が割り当てられます。 並べ替え後、各出力位置からソース インデックスの完全な 4 文字コードが明らかになります。 これにより、再構築が直接的に行われます。各 4 文字タプルを元のインデックスにマップして戻します。

 | 最適なエンコーディング | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 4 桁の Base-26 エンコードを使用して、各インデックスに一意の識別子を割り当てます。 これにより、すべての位置に、後で再構築できる個別の署名が確保されます。 
2. 4 つのクエリ文字列を作成します。 各位置 i および 0 ～ 3 の各クエリ k について、アルファベットの i の k 番目の数字を k 番目の文字列の位置 i に配置します。 
3. 最初のクエリ文字列を送信し、並べ替えられた結果を受け取ります。 応答内の各位置 j について、置換の下で j にマップされる元の位置からの文字を記録します。 
4. 4 つのクエリすべてに対して同じプロセスを繰り返します。 すべての応答を処理した後、各位置 j は 4 つの文字を集め、4 文字の署名を形成します。 
5. Base-26 デコードを使用して、各 4 文字の署名を元のインデックスに変換します。 これにより、逆順列が得られます。つまり、各出力位置 j について、どの元のインデックス i がそれを生成したかがわかります。 
6. 必要な形式で順列を出力します。 

これが機能する理由は、各クエリがインデックスの 4 次元エンコードの投影のように機能するためです。 順列はこれらのエンコーディングを並べ替えるだけであり、混合はしないため、各位置は完全な回復可能な署名を保持します。 

### なぜ効果があるのか

 不変条件は、いつでも、並べ替えられた文字列内のすべての位置が、一意の元のインデックスに割り当てられたのとまったく同じ 4 文字のコードを保持することです。 インデックスから 4 文字ベクトルへのエンコード関数は単射的であり、順列は値を変更せずにマルチセット構造を保持するため、任意の位置から元のインデックスを再構築することは常に明確です。 同じ 4 文字タプルを共有する 2 つのインデックスは存在しないため、再構築中に衝突は発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def encode(i):
    # 4-digit base-26 encoding
    res = []
    for _ in range(4):
        res.append(chr(ord('a') + (i % 26)))
        i //= 26
    return res  # least significant digit first

def main():
    n = int(input().strip())

    # build 4 query strings
    queries = [ [''] * n for _ in range(4) ]

    codes = []
    for i in range(n):
        c = encode(i)
        codes.append(c)
        for k in range(4):
            queries[k][i] = c[k]

    queries = [''.join(q) for q in queries]

    # store received characters per position
    got = [ [] for _ in range(n) ]

    for k in range(4):
        print("?", queries[k])
        sys.stdout.flush()
        resp = input().strip()

        for j, ch in enumerate(resp):
            got[j].append(ch)

    # reconstruct mapping
    pos = {}
    for i, c in enumerate(codes):
        pos[''.join(c)] = i + 1

    ans = [0] * n
    for j in range(n):
        key = ''.join(got[j])
        ans[j] = pos[key]

    print("!", *ans)
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```構築フェーズでは、それぞれが Base-26 識別子の 1 桁として機能する 4 つの独立した文字レイヤーを構築します。 インタラクション ループは、これらのレイヤーの 4 つの並べ替えられたバージョンを読み取り、各出力位置に属する文字を蓄積します。 4 つのレイヤーがすべて収集されると、各位置は 4 文字のキーによって完全に識別され、その後、元のインデックスにデコードされます。 

よくある実装の落とし穴は、順列の方向を混同することです。 重要な洞察は、出力位置には元のインデックスに関する情報が格納されており、その逆ではないため、再構築では収集されたタプルを逆マッピングのターゲットとして扱う必要があるということです。 

## 実用的な例

 順列 p = [3, 5, 1, 4, 2] を持つ小さな順列 n = 5 を考えてみましょう。 これは、位置 1 が 3 に移動し、位置 2 が 5 に移動するということを意味します。 

Base-26 コードを割り当てますが、簡単にするために文字を想像してください。 

| インデックス i | コード |
 | --- | --- |
 | 1 | ああ |
 | 2 | あーあ |
 | 3 | アバ |
 | 4 | アバア |
 | 5 | ばあ |

 順列後、位置はソースからコードを受け取ります。 

| 出力位置 j | 受信したコード |
 | --- | --- |
 | 1 | アバ |
 | 2 | ばあ |
 | 3 | ああ |
 | 4 | アバア |
 | 5 | あーあ |

 このテーブルから、コードを割り当てられた位置に突き合わせることで、元のインデックスを直接復元します。 

このトレースは、デコードを超えたクロス位置推論を必要とせずに、各出力位置が独立して原点を再構築することを示しています。 

n = 3 および恒等順列を使用した 2 番目の例では、安定性が確認されています。 すべての出力位置は正確に独自のコードを受け取るため、デコードすると当然 [1, 2, 3] が返され、固定小数点の場合の正しさが検証されます。

 ## 特殊なケース

 n = 1 の場合、エンコーディングは引き続き 1 つの位置に対して 4 文字の署名を生成します。 4 つのクエリはすべて同一の単一文字列を返し、再構築によりその署名が曖昧さなくインデックス 1 にマップされます。 

100000 に近い大きな n の場合、26^4 が範囲を超えるため、base-26 の 4 桁エンコードでも十分な一意性が得られます。 各インデックスは一意に識別可能であり、デコード マップに衝突が発生しないため、大規模な正確性が保証されます。
