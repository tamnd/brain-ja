 ## 解決策
 ## 問題の理解

 私たちには、決まった順序で到着する車のシーケンスが与えられています。 各車には可能な最大速度があり、各車を 2 車線のいずれかに割り当てることができます。 各レーン内の車両の順序は元の順序と同じであるため、各レーンは部分列を形成します。 

車が同じ車線内で別の車を追跡する場合、実際の速度は直前の車によって制限されます。 具体的には、制限のある車の場合、$s_i$事実上のスピードで走行している車の後ろにいる$c$、その場合、高速で移動することも強制されます$\min(s_i, c)$。 車線の先頭の車であれば、全力で走行します$s_i$。 

車両を割り当てるコストは、すべての車両の速度損失の合計であり、これは次の合計です。$s_i - c_i$、 どこ$c_i$は、これらの制約の後に達成される実際の速度です。 この合計損失を最小限に抑えるには、車を 2 車線に分割する必要があります。 

重要な構造は、各車線がその車線内のすべての前の車の最小値によって制限されるため、各車線が実効速度の増加しないシーケンスのように動作することです。 これにより、2 つの実行中の「プレフィックス最小」プロセスを維持しながら、各要素がどこに配置されるかを決定することが問題になります。 

制約の合計サイズはテスト ケース全体で小さく、全体で最大 1000 台の車両です。 これは、3 次または 2 次の動的計画法ソリューションが受け入れられる一方で、サブセットにわたる指数関数的なものは不要であることを直ちに示唆しています。 

単純な考えは、すべての車を 2 車線に割り当ててみるというものです。 それは次のことにつながります$2^n$すでに不可能になっている可能性$n = 1000$。 単一の割り当てを評価するだけでもコストがかかります$O(n)$、二重に実行不可能になります。 

即時ペナルティがより小さい車線に常に車を入れるなど、貪欲な割り当てを試みると、より微妙な失敗のケースが現れます。 たとえば、速度の場合$[5, 4, 3]$、貪欲な選択により、早期の配置が強制され、後のキャップが不必要に増加し、グローバル最小値が悪化する可能性があります。 

もう 1 つの問題は、速度の伝播についての誤解です。 この制約は、隣接する車両のみに局所的に適用されるわけではありません。 それはプレフィックスの最小値として伝播されます。 フルレーンの状態を追跡せずに、直前のものとのみ比較するアプローチでは、不正確な結果が生成されます。 

## アプローチ

 各車線がその現在の実効速度によって完全に記述されることを観察すると、この問題は対処可能になります。実効速度は常に、その車線でこれまでに割り当てられた車両の最低速度です。 新しい車が追加されると、その寄与は、それが接続する車線の現在の最小値にのみ依存します。 

これは、各レーンが現在どの程度「タイト」であるかを追跡する動的プログラミング状態を示唆しています。 ただし、完全な履歴は必要ありません。両方の車線の現在の最低速度のみが必要です。 

強引な定式化では、最初のすべての割り当てが考慮されます。$i$各車線の最低速度を監視しながら、車を 2 車線に進入させます。 各状態ごとに車を配置することで遷移します$i+1$どちらかのレーンに追加し、レーンの最小値を更新し、コストを累積します。 これは正しいですが、潜在的に$O(n \cdot s^2)$各車線の最低速度は可能なすべての速度に及ぶ可能性があるため、$5000^2$位置ごとの状態が大きすぎます。 

重要な洞察は、レーンの最小値は減少するだけであるということです。 さらに重要なことは、車を配置するコストの寄与は、車が新しい最小値になるか、車線の現在の最小値によってクリップされるかによってのみ依存することです。 この構造により、状態空間を圧縮できます。任意の最小値のペアを追跡する代わりに、一方のレーンの現在の可能な最小値に対して DP を考慮するだけで済み、もう一方のレーンは順序付けされた選択肢によって暗黙的に決定されます。 

より直接的でクリーンな再定式化は、プレフィックス順に各車線に何台の車両が割り当てられるかという観点から考えることです。 両方のレーンで順序が維持されるため、シーケンスを 2 つのサブシーケンスに分割し、それぞれが実行最小値を維持するものとしてプロセスを再解釈できます。 各レーンのコストは、プレフィックス最小値がどのように進化するかにのみ依存し、それは段階的に取得できます。 

車を左から右に処理し、一方の車線の現在の最小値の可能な値ごとに可能な限り最良のコストを維持し、遷移を通じてもう一方の車線の影響を暗黙的に推測する DP を定義します。 各車には、レーン A に参加するかレーン B に参加するかの 2 つの選択肢があります。レーンに参加する場合、追加されるコストは次のとおりです。$\max(0, s_i - m)$、 どこ$m$はそのレーンの現在の最小値であり、新しいレーンの最小値は次のようになります。$\min(m, s_i)$。 

これにより、管理可能な DP が得られます。$s_i \le 5000$したがって、可能な最小値に関するテーブルを維持し、プレフィックス最小値の更新を使用して遷移を圧縮できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てに対するブルートフォース |$O(2^n)$|$O(n)$| 遅すぎる |
 | レーン最小状態上の DP |$O(n \cdot S)$または$O(n \cdot S \log S)$|$O(S)$| 承認済み |

 ここ$S = 5000$。 

## アルゴリズムのチュートリアル

 1. 車両のプレフィックスを処理した後、車線最小値の構成に対して達成可能な最良のコストを追跡する DP 構造を初期化します。 両方のレーンが空の状態で開始します。これは、レーンの最小値が事実上無限であり、コストが発生していないことを意味します。 
2. 入力順に車を反復処理します。 スピードを出すクルマごとに$s_i$、どちらかのレーンに配置することを検討します。 
3. 現在の最小値が次の車線に車を置くとします。$m$、実際の速度は次のようになります。$\min(s_i, m)$したがって、この車が寄与する損失は次のようになります。$s_i - \min(s_i, m)$。 もし$s_i \le m$、損はありません。 そうでなければ損失は$s_i - m$。 これは、まさにその車線の前の車によって車がどれだけ減速されるかです。 
4. 各 DP 状態について、2 つの遷移を計算します。車をレーン A またはレーン B に割り当てます。各遷移は、そのレーンの最小値を次のように更新します。$\min(m, s_i)$、他の車線は変更されません。 
5. レーン最小値の同じペアで終了する状態間の最小コストを常に維持しながら、DP を慎重に更新します。 多くの異なる割り当て履歴が同じ有効な状態につながるため、このマージ手順は不可欠です。 
6. すべての車を処理した後、すべての DP 状態をスキャンし、その中で最小コストを取得します。 

### なぜ効果があるのか

 車線の将来の動作全体は、現在の最低速度のみに依存します。これは、後続のすべての車が、その前の順序に関係なく、その最低速度によってクリップされるためです。 したがって、同じ最小値のペアで終わる 2 つの履歴は、将来のすべての決定に対して同等になります。 遷移ではこの特性が正確に保持されるため、DP は最適解を失うことはなく、将来のコストに無関係な状態を区別することもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    n = int(input())
    s = list(map(int, input().split()))

    # dp[m1][m2] = minimum cost
    # we compress using dictionary for sparsity
    dp = {(float('inf'), float('inf')): 0}

    for x in s:
        new_dp = {}

        for (m1, m2), cost in dp.items():
            # put in lane 1
            nm1 = min(m1, x)
            add1 = 0 if x <= m1 else x - m1
            state1 = (nm1, m2)
            if state1 not in new_dp or new_dp[state1] > cost + add1:
                new_dp[state1] = cost + add1

            # put in lane 2
            nm2 = min(m2, x)
            add2 = 0 if x <= m2 else x - m2
            state2 = (m1, nm2)
            if state2 not in new_dp or new_dp[state2] > cost + add2:
                new_dp[state2] = cost + add2

        dp = new_dp

    print(min(dp.values()))

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```実装は DP 状態定義に直接に従います。 各状態は 2 つの現在の車線の最小値を保存し、遷移は現在の車をどちらかの車線に配置することを反映します。 

の使用`float('inf')`は、車が割り当てられる前の空の車線を表します。 各更新では、車が車線に挟まれているかどうかに応じて、新しい最小コストと増分コストの両方が正しく計算されます。 

微妙な点は、状態を積極的に重複排除していることです。`new_dp`。 これがないと、多数の等価構築パスが同一の最小ペアを生成するため、状態の数が爆発的に増加します。

 ## 特殊なケース

 重要なエッジケースは、すべての車両が厳密に減少している場合です。 この状況では、各新しい車が前方の最小速度よりも遅くなることはないため、どの車線割り当てでも損失はゼロです。 すべての遷移で次のことが確認されるため、DP はコストを正しくゼロに保ちます。$s_i \le m$選択したレーンに対して。 

もう 1 つの微妙なケースは、次のように高い値と低い値が交互に現れることです。$[10, 1, 9, 2, 8]$。 単純で貪欲な戦略は、すべての高値をまとめて配置する傾向があり、急速に減少するレーン最小値を作成し、大きな損失を引き起こします。 代わりに、DP は車線全体で高音を分離し、より高い実効速度を維持します。 

3 番目のケースは、多くの車が同じ速度を共有する場合です。 等しい値を配置してもレーンの最小値が減少することはないため、DP は状態を積極的にマージし、分布に関係なくコストをゼロに保ちます。
