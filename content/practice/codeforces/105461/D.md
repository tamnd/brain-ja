 ## 解決策
 ## 問題の理解

 初期ビットセットから新しいビットセットを構築できるシステムが与えられています。$B_0$。 各ビットセットには長さがあります$n$、そして、以前に構築されたビットセット間の左または右のシフト、XOR、および OR という小さな操作セットのみを使用して、新しいビットセットを生成できます。 ビットのインデックスは右から左に定義されるため、右端の位置が最下位ビットになります。 

タスクは、特定のプログラムの結果を計算することではなく、この制限された言語でプログラムを設計することです。 このプログラムが任意の入力ビットセットで実行されるとき$B_0$、正確に最下位セットビットを含む最終ビットセットを生成する必要があります。$B_0$、その他の場所にはゼロが表示されます。 言い換えれば、出力は、入力に含まれる 2 の最小累乗を表すビットセットである必要があります。 

制約$n \le 100000$これはプログラムを評価する実行時間に関するものではなく、概念的にシミュレートするビットセットのサイズに関するものです。 本当の制限は、このカスタム言語では最大 100 個の操作しか出力できないことです。そのため、構築は非常にコンパクトでなければなりません。 

単純な誤解は、ビットを個別に検査できる、または右から左へのスキャンをシミュレートできると考えることです。 分岐も比較もインデックスへの直接アクセスもないため、これは不可能です。 すべての変換は、グローバルに適用される均一なビット単位の演算である必要があります。 

微妙なエッジケースは、入力に 1 ビットしか設定されていない場合です。 たとえば、次の場合$B_0 = 00001000$、正しい出力は同じビットセットが変更されていないものです。 少なくとも 2 ビットを想定する構造や、下位位置から情報を「伝播」しようとする構造は、この縮退の場合でも正確さを維持する必要があります。 

もう 1 つのエッジ ケースは、最下位ビットがすでに位置 0 にある場合です。 シフトベースの構築では、誤ってシフトしたり、XOR を介してキャンセルしたりしないようにする必要があります。 

## アプローチ

 ブルート フォースの考え方では、最下位セット ビットを分離するための古典的なビット トリックをシミュレートしようとします。$x \& (-x)$。 ただし、この演算は算術否定とビット単位の AND に依存しており、どちらもこの言語では使用できません。 シフト、XOR、OR しかないため、直接算術を構築することは不可能です。 

もう 1 つのアイデアは、シフトと組み合わせを使用して右から徐々にビットを「フィルタリング」し、最下位ビットを保持しながら上位ビットをすべて削除しようとすることです。 問題は、ビットが特定の位置に存在するかどうかをテストできないことです。そのため、2 のべき乗の構造表現を構築し、それを使用して最も低いアクティブな位置を分離する必要があります。 

重要な点は、最下位ビットの位置を識別する必要がないということです。 代わりに、倍加結合戦略を使用して入力の完全なバイナリ分解を構築できます。 ビットの範囲を表すマスクを構築できれば、最下位のアクティブなセグメントのみを保持する構造を繰り返し改良し、最終的には単一のビットに折りたたむことができます。 

この構築では古典的なアイデアを使用します。次のように、増加する間隔をカバーする一連のマスクを構築します。$1$、$2$、$4$、$8$、など、右からのプレフィックス カバレッジをシミュレートする方法でそれらを組み合わせます。 OR マージはカバレッジを蓄積しますが、XOR はシフトの対称性を通じて慎重に構造化されている場合、重複する寄与をキャンセルするために使用できます。 

最終的なプログラムは基本的に、「右端のアクティブ ビット抽出器」のように動作する全幅マスクの対数構造です。 総当りの直感ではすべてのビットをスキャンする必要がありますが、シフトマージ階層によりこれが次のように圧縮されます。$O(\log n)$各レイヤーは一定数の操作でシミュレートされます。

 ## アルゴリズムのチュートリアル

 徐々に大きなシフト パターンを構築する一連の中間ビットセットを構築します。 目標は、シフトされたコピーからの情報が重なり合わなくなる最初の点を分離することによって、最も低い設定ビットを「選択」できるシステムを作成することです。 

1. から始める$B_0$、入力ビットセット。 これが唯一の情報源であるため、すべての構築は最終的にそれに依存する必要があります。 
2.構築する$B_1 = B_0 \;|\; (B_0 \ll 1)$。 これにより、設定されたすべてのビットが含まれるマスクが作成されます。$B_0$すぐ左隣の要素にも影響を与えます。 目的は、プレゼンス情報を上方に伝播し始めることです。 
3. シフトされたバージョンをマージするというアイデアを繰り返し、毎回シフト距離を 2 倍にします。 ステップで$k$、ビットセットを、そのバージョンをシフトして結合します。$2^k$。 各段階で影響範囲が指数関数的に拡大し、ビットセット上でプレフィックスのような構造をエンコードできるようになります。 
4. 各段階の後、構築されたビットセットが、次のサイズのウィンドウ内にセットされたビットが存在するかどうかを表すことを維持します。$2^k$各位置で終了します。 これにより、生のビットが間隔の要約に変換されます。 
5.その後$O(\log n)$各段階で、各位置で終わるプレフィックスにビットが存在するかどうかをエンコードする構造が得られます。 これにより、右から左への累積 OR が効果的にエンコードされます。 
6. この累積構造の連続するシフトされたバージョン間で XOR を使用して、最初のアクティブ ビットが現れる境界を分離します。 XOR は重複する領域をキャンセルし、遷移点のみを残します。 
7. もう一度シフトして結合し、この遷移を最下位設定ビットに合わせて単一ビット表現に正規化します。 

### なぜ効果があるのか

 この構築では不変条件が維持されます。$k$- 番目の倍増ステージ、各位置は、サイズのブロック内に元の設定ビットが存在するかどうかを格納します。$2^k$その位置で終了します。 この不変条件は、OR によってマージされた間隔全体の存在が保持され、シフトによってそれらの間隔が正しく位置合わせされるため、成立します。 

ブロックサイズを超えると$n$、すべての位置は、その右側に設定されたビットが存在するかどうかを正確に反映します。 最下位ビットは、まさにこの累積情報が false から true に遷移する位置です。 隣接する累積状態間の XOR は、同一のプレフィックス領域をキャンセルして境界を保持するため、その遷移を一意に分離します。 

すべての操作は以前に構築された有効なサマリーのみに依存するため、不正な伝播は発生せず、最終的に分離されたビットは元の入力の最下位セット ビットに対応する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

ops = []

def add(op):
    ops.append(op)

# We build a prefix-OR style doubling structure.
# We maintain a working register cur starting from B0.
cur = 0

# We simulate power-of-two shift merging.
# We cannot actually refer to bitsets symbolically in code,
# so we output a fixed construction pattern.

# Step 1: build OR with shift 1
add("B1 = B0 << 1")
add("B2 = B0 | B1")

# Step 2: expand to 2, 4, 8, ... up to cover n
shift = 1
prev = "B2"
idx = 2

while shift < n:
    add(f"B{idx+1} = {prev} << {shift}")
    add(f"B{idx+2} = {prev} | B{idx+1}")
    prev = f"B{idx+2}"
    idx += 2
    shift *= 2

# Final isolation step using XOR of last two states
add(f"B{idx+1} = {prev} ^ ({prev} << 1)")

print(len(ops))
for op in ops:
    print(op)
```この実装は、各ステージが現在の構造をそれ自体のシフトされたバージョンとマージする、倍加シフトのチェーンを構築します。 その目的は、指数関数的に増加するセットビットの影響範囲をシミュレートすることであり、これが 100 操作制限内のすべての位置に到達する唯一の方法です。 

最後の XOR ステップは、連続する累積領域間の境界を抽出するために使用されます。 この境界は、累積到達可能性が空から非空に変化する最初の位置であるため、最下位設定ビットに対応します。 

微妙な点は、ビットを直接検査しようとしないことです。 すべての変換は均一であり、以前に構築されたビットセットのみに依存するため、言語の制約の下で有効性が維持されます。 

## 実用的な例

 検討してください$n = 8$位置 2 (右から) に最低セットビットを持つ入力ビットセットを使用します。 

概念的な入力が累積的 OR とシフトの下でどのように進化するかを追跡します。 

| ステップ | 操作 | 概念的な効果 |
 | --- | --- | --- |
 | 1 |$B_1 = B_0 << 1$| すべてのビットを左にシフトします。 
| 2 | (B_2 = B_0 | B_1) |
 | 3 | 倍増シフト | 影響範囲を 4 に拡大 |
 | 4 | 次へ または | より広い範囲を統合 |
 | 最終 | XOR ステップ | 境界を分離します |

 重要な観察は、2 倍化を繰り返した後、すべての位置がその右側に元のビットが存在するかどうかをエンコードしていることです。 XOR ステップは、このプロパティが false から true に切り替わる場所 (まさに最下位設定ビット) を検出します。 

この例は、その構築がビットの特定の位置には依存せず、遷移境界の存在のみに依存することを示しています。 

たとえば、最上位ビットのみが設定されている入力を考えてみましょう。$10000000$。 

| ステップ | 状態 |
 | --- | --- |
 | イニシャル | 単一のアクティブビット |
 | マージ後 | 境界を除いてすべてのプレフィックスは false のままです。 
| 最終 XOR | 同じビットを分離します |

 ここでは、OR 伝播中にキャンセルが発生しないため、アルゴリズムはきれいに縮退します。 アクティブ領域が 1 つだけあるため、XOR ステップではスプリアス ビットが導入されません。 

これにより、まばらな入力と極端な入力の正しさが確認されます。

 ## 特殊なケース

 次のようなシングルビット入力$B_0 = 00000001$すべての OR ベースの構造を通じて安定性を保ちます。 シフトごとに有効範囲外のゼロが生成されるため、OR によって新しいアクティブ ビットが導入されることはありません。 干渉する 2 番目のアクティブ領域がないため、XOR 境界ステップもきれいにキャンセルされます。 

最下位ビットが可能な限り最高の位置にある場合、シフトを繰り返しても、そのビットが他のビットと重複することはありません。 OR 伝播は、到達可能なすべてのプレフィックスをマークしますが、遷移はビットセットの境界で明確に定義されたままであり、XOR はオーバーフロー アーティファクトを発生させることなく正しく分離します。 

設定ビットが 1 つだけの入力は、構築が冪等性を維持する必要があることを示しています。 すべてのステージで単調 OR 拡張が使用されるため、どのステップも既存のアクティブ ビットを破壊できず、最後の XOR は存在を変更するのではなく構造を抽出するだけです。
