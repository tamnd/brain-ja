 ## 解決策
 ## 問題の理解

 0 から L までの連続セグメントとして表される直線の道路が与えられています。このセグメントに沿った整数座標に配置された n 個の固定街灯があります。 位置を選択することはできません。各街灯に取り付けられる電球の種類のみが選択できます。 

利用可能な電球のタイプは m 種類あり、各タイプは単一のパラメータ、つまり両方向にどれだけ遠くまで照らすかによって定義されます。 x に位置するランプに範囲 l の電球を取り付けると、そのランプは x − l から x + l までの全区間を照らします。 すべてのランプは同じタイプの電球を使用する必要があり、どのタイプを購入するかを選択することができます。 

目標は、すべての照明間隔の和集合が [0, L] のすべての点を完全にカバーできるように、指定されたタイプの中で最小の電球範囲を決定することです。 どのタイプの電球も完全にカバーできない場合、答えは -1 になります。 

n、m ≤ 100000 という制約により、すべての電球タイプを試して二次関数でカバレッジを再計算するアプローチは直ちに除外されます。 単純な O(nm) シミュレーションでは、最悪の場合、約 10^10 の間隔チェックが必要になりますが、これは実用的な制限をはるかに超えています。 O(mn log n) でさえ定数によっては厳しくなるため、電球タイプに対する対数選択戦略と組み合わせた、候補ごとの線形または線形に近いチェックが必要です。 

この問題の微妙な側面は、報道が継続的であるということです。 これは、部分的な重複が重要であることを意味し、間隔の端点が整数点をカバーしているかどうかを確認するだけでは十分ではありません。 たとえば、[0, 5] と [6, 10] をランプが覆う場合、両端が「近い」にもかかわらず、隙間が生じます。 正しい解決策は、離散サンプルではなく、完全な区間和集合について推論する必要があります。 

もう 1 つの潜在的な落とし穴は、極端なランプに対応する十分な大きさの電球があればカバー範囲が保証されると想定していることです。 連続するランプ位置間に大きなギャップがある場合、これは誤りです。 たとえば、L = 10 の位置 0 と 10 のランプには l = 5 が必要ですが、0、4、10 のような構成は、エンドポイントが妥当に見えても l = 3 では失敗します。 

最後に、左側の境界 0 と右側の境界 L を明示的にカバーする必要があることを忘れがちです。 0 付近でカバレッジが失われることは特に一般的です。これは、左端のランプが十分に左に到達するかどうかに完全に依存するためです。 

## アプローチ

 簡単なアプローチは、各電球タイプを個別にテストすることです。 固定範囲 l について、すべての区間 [p_i − l, p_i + l] の和集合を計算し、この和集合が [0, L] をカバーするかどうかを確認します。 これを行う標準的な方法は、開始点で間隔を並べ替え、最も遠いカバーされた点を追跡しながらそれらを貪欲にマージすることです。 現在のカバレッジが終了した後に次の間隔が始まるギャップが発生した場合、カバレッジは失敗します。 

このチェックは正しく、ソート間隔により電球タイプごとに O(n log n) で実行されます。事前にソートされた位置の順序を再利用する場合は O(n) で実行されます。 ただし、m 個の電球タイプすべてに対してこれを行うと O(mn) となり、100000 x 100000 には大きすぎます。 

重要な観察は、実現可能性が l において単調であるということです。 電球の範囲 l が街路をカバーするのに十分な場合は、すべての間隔が拡大するだけであるため、より大きな範囲 l' > l でも十分です。 この単調性により、問題をバルブ範囲のソートされたリストに対する二分探索として扱うことができます。 

まず電球の範囲を並べ替えます。 次に、対応する範囲が可能な最小のインデックスを二分探索します。 各実現可能性チェックは、ソートされたランプ位置を 1 回スイープし、現在カバーされているセグメントを維持することにより、O(n) で実行されます。 これにより、問題は O((n + m) log m) に軽減され、十分に高速になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 電球ごとのブルート フォース | O(mn) | お(1) | 遅すぎる |
 | ソート + 二分探索 + 線形チェック | O(n + m log m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

各電球タイプがすべてのランプ位置の周囲に対称的な拡大を引き起こし、半径が大きくなるにつれてカバー範囲が容易になるという事実を利用します。 

### 1. ランプの位置を並べ替える

 カバレッジを左から右に推論できるように、p をソートします。 これにより、ランプを順番に処理するときに、ランプの間隔の左側の端点も減少しないことが保証されます。 

### 2. 固定範囲 l の実現可能性チェックを定義します。 

与えられた l に対して、各ランプは間隔 [p_i − l, p_i + l] を作成します。 これらの間隔を明示的に保存せずにマージをシミュレートします。 

すでに 0 から連続的に照らされている通りの最も遠い地点を表す、可変電流を維持します。 

### 3. ランプを左から右にスキャンします。 

p_i の昇順に各ランプ i について、その間隔の開始と終了を計算します。 start > current の場合、カバレッジにギャップがあるため、この l はすぐに失敗します。 それ以外の場合は、current を max(current, end) まで拡張します。 

### 4. 完全な範囲を検証する

 すべてのランプを処理した後、電流 ≥ L の場合、通り全体がカバーされます。 それ以外の場合は、右端近くに露出したセグメントがいくつかあります。 

### 5. バルブ範囲の二分探索

 m 個のバルブ範囲をソートし、その範囲が実現可能性チェックに合格する最小のインデックスを二分探索します。 答えはその範囲、または何も機能しない場合は -1 です。 

### なぜ効果があるのか

 実現可能性チェックは、すべての間隔の和集合に 0 から L までの連続パスが含まれているかどうかを検証することと同じです。貪欲スキャンが機能するのは、どの時点でも、ある位置までの可能な最良のカバレッジは、その位置の前またはその位置で開始された間隔の中で最も遠くに到達する間隔によってのみ決定されるためです。 後で開始する間隔は、ギャップが存在すると修復できないため、早めに失敗しても安全です。 l の単調性により、ある値が機能すると、より大きな値もすべて機能し、二分探索が有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_cover(p, L, l):
    current = 0
    for x in p:
        start = x - l
        end = x + l
        if start > current:
            return False
        if end > current:
            current = end
        if current >= L:
            return True
    return current >= L

def solve():
    n, m, L = map(int, input().split())
    p = list(map(int, input().split()))
    lvals = list(map(int, input().split()))

    p.sort()
    lvals.sort()

    lo, hi = 0, m - 1
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if can_cover(p, L, lvals[mid]):
            ans = lvals[mid]
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、間隔のマージが 1 つの左から右へのスイープになるようにランプの位置を並べ替えることから始まります。 機能`can_cover`貪欲なカバレッジ ロジックをエンコードします。 現在の継続的に点灯しているプレフィックスを追跡し、ギャップが現れるとすぐに電球範囲を拒否するため、不必要な作業が回避されます。 

二分探索はソートされたバルブ範囲に対して実行され、実行可能性関数を使用して各中間点がテストされます。 すべての電球のカバレッジを個別に再計算すると時間がかかりすぎるため、この構造は不可欠です。 

よくある実装上の間違いは、カバレッジが離散的ではなく連続的であることを忘れていることです。 小切手`start > current`これは、実際に覆われていないギャップを検出する正確な条件です。 もう 1 つの微妙な点は、次の場合に早期終了することです。`current >= L`完全なカバレッジが達成されると、不必要なスキャンが回避されます。

 ## 特殊なケース

 重要なエッジ ケースは、最初のランプが原点に到達しない場合です。 たとえば、L = 20 で p = [5, 10] および l = 2 の場合、最初の区間は [3, 7] となり、[0, 3] はカバーされないままになります。 電流は 0 から始まり、最初の開始は 3 であるため、アルゴリズムはこれを正しく検出し、即座に障害をトリガーします。 

もう 1 つのケースは、カバレッジが最後にのみ失敗する場合です。 p = [0, 4, 8]、l = 2、L = 15 の場合、和集合は 10 に達しますが、15 には達しません。電流が L に達しないため、スキャンは完了し、false を返します。 

最後の微妙なケースは、間隔がちょうど境界で交わる密な連鎖です。 p = [0, 3, 6] および l = 3 の場合、間隔は端点で正確に接触しており、連続していると見なされます。 start > current という条件は等価性を有効な接続として正しく処理し、誤ったギャップが導入されないようにします。
