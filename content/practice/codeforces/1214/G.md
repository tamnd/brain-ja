 ## 解決策
 ## 問題の理解

 カメレオンの体を表す 2 次元グリッドが与えられます。 最初はすべてのセルが緑色です。 各セルは緑または青のいずれかであり、色は複数回反転できます。 各反転は、単一行の連続する水平セグメントに影響を与えます。 フリップするたびに、カメレオンのご機嫌が良いかどうかを判断する必要があります。これは、「ご機嫌証明書」を形成する 4 つのセルからなる長方形が存在する場合に行われます。 良い気分の証明書は、向かい合う角が同じ色を共有する 2×2 のサブグリッドですが、4 つの角がすべて同じではありません。 

入力はグリッド サイズを提供します`n × m`そして一連の`q`反転します。 各反転では、色を反転する行と列の間隔を指定します。 各反転後の出力は次のいずれかです。`-1`カメレオンのご機嫌が悪い場合、または有効なご機嫌証明書の座標を表す 4 つの整数。 

制約は、反転するたびにすべての可能な四角形を検査する総当り的なアプローチが実行不可能であることを意味します。 と`n, m`2000 まで、可能な 2×2 部分長方形の数はおよそ`O(n*m) = 4×10^6`、最大 500,000 回のフリップでは、単純な O(n_m_q) アプローチでは何兆もの演算が必要になります。 これにより、毎回グリッド全体を再チェックするのではなく、増分更新を考慮する必要があります。 

エッジ ケースには、長方形が存在できない 1 行または 1 列のみのグリッド、相互に元に戻す反転、証明書が表示されたり消えたりする交互のパターンが含まれます。 たとえば、2×2 グリッドを反転すると、`(1,1,1)`そして`(2,2,2)`繰り返し行うと、気分が良いときと悪いときを交互に繰り返す可能性があります。 

## アプローチ

 単純なアプローチでは、グリッドを明示的にシミュレートします。 反転するたびに、すべての 2×2 サブ長方形を反復処理して色を確認し、証明書が存在する場合は証明書を出力します。 これは正しいですが、遅すぎます。各フリップのコストは O(n*m) です。`q`500,000も可能です。 

重要な洞察は、グリッド全体を検査することなく、良い気分の証明書を作成できるパターンを追跡することです。 カラー反転の異なるパリティを持つセグメントが 2 つの行に含まれる長方形のみが証明書を生成できます。 行セグメントが奇数回反転された場合、その色は最初の緑色とは異なります。 したがって、各行の左端と右端の反転されたセルを監視し、隣接する行に 2×2 の長方形の可能性があるかどうかをチェックするだけで済みます。 

各行をビットマスクとして、またはフリップのパリティを備えた間隔のリストとして表すことができます。 更新するたびに、その行とその隣接する行内の影響を受ける 2×2 四角形をチェックするだけで済みます。 これにより、フリップごとのチェックが O(m) に削減され、合計の複雑さは O(q*m) になります。これは、`m`2000年までと`q`500,000まで。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q_n_m) | O(n*m) | 遅すぎる |
 | 最適 | O(q*m) | O(n*m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各行を、各セルが奇数回反転されたかどうかを示すバイナリ配列として表します。 最初はすべてゼロです。 
2. フリップごとに`(a, l, r)`、指定された間隔でフリップ数を増加させます。 プレフィックス合計または差分配列を使用すると、行ごとの操作ごとに O(1) で効率的に実行できます。 
3. フリップをローに適用した後`a`、差分配列の累積和を使用して、行を実際のパリティ値 (緑の場合は 0、青の場合は 1) に変換し直します。 影響を受ける行のみを更新する必要があります。 
4. 良い気分の証明書を確認します。 行とそのすぐ下の行 (存在する場合) を反復処理して、向かい合う角は等しいが、4 つの角がすべて等しいわけではない 2×2 の部分長方形を見つけます。 各列インデックスについて`c`、4つのセルを確認してください`(a, c)`、`(a, c+1)`、`(a+1, c)`、`(a+1, c+1)`。 
5. そのような四角形が存在する場合は、その座標を出力します。 それ以外の場合は出力`-1`。 
6. フリップごとに繰り返します。 

機能する理由: 反転するたびに 1 つの行のみを変更するため、その行とそのすぐ下の行に関係する 2×2 の長方形のみがステータスを変更できます。 パリティを維持し、増分チェックを使用することで、潜在的な証明書を決して見逃さないようにします。 各四角形が変更される可能性があるときに正確にチェックされるため、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, q = map(int, input().split())
rows = [[0]*m for _ in range(n)]  # 0=green, 1=blue

def check_good(x):
    if x == n - 1:
        return None
    for y in range(m-1):
        a = rows[x][y]
        b = rows[x][y+1]
        c = rows[x+1][y]
        d = rows[x+1][y+1]
        if a == d and b == c and not (a == b == c == d):
            return (x+1, y+1, x+2, y+2)  # 1-based
    return None

for _ in range(q):
    a, l, r = map(int, input().split())
    a -= 1
    l -= 1
    r -= 1
    for y in range(l, r+1):
        rows[a][y] ^= 1
    found = None
    for x in [a-1, a]:
        if 0 <= x < n-1:
            res = check_good(x)
            if res:
                found = res
                break
    if found:
        print(*found)
    else:
        print(-1)
```各行を 0/1 値のリストとして維持します。 フリップ演算は、影響を受ける区間に対する単純な XOR です。 良い気分の証明書のチェックでは、更新された行とそのすぐ隣の行を含む四角形のみが検査されます。 これは効率にとって非常に重要です。アルゴリズムは影響を受けない行を決してスキャンせず、クエリごとの時間を直線的に保ちます。`m`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q*m) | 各フリップは 1 行を更新し、最大 2*(m-1) 個の四角形をチェックします。 
| スペース | O(n*m) | サイズ n×m のグリッドを格納する |

 n_m ≤ 4_10^6 および q ≤ 5*10^5 であるため、解は容易に制限内に収まります。 操作の合計数は最大 10^9 であり、実際には効率的な I/O で管理可能です。
