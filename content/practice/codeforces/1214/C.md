 ## 解決策
 ## 問題の理解

 "(()))(" や ")(" のような括弧の文字列が与えられており、最大 1 つの括弧を別の位置に移動するだけで正しい括弧シーケンスになるかどうかを判断する必要があります。正しいシーケンスは、空であるか、正しいシーケンスを囲む 1 つのペア、または正しいシーケンスの連結のいずれかです。1 回の移動で修正できる場合、出力は「Yes」、そうでない場合は「No」になります。

 入力の長さは最大 200,000 まで可能ですが、O(n²) 個の演算が必要となるため、各括弧をあらゆる可能な位置に移動しようとする解決策は除外されます。 線形時間 O(n) で実行されるアルゴリズムが必要です。 シーケンスはすでに正しい場合もあれば、開始括弧または終了括弧が 1 つ間違って配置されているためにずれている場合もあれば、1 回の移動では完全に修正できない場合もあります。 長さが 1 のシーケンス、すべての括弧が同じであるシーケンス、および単一の誤って配置された括弧が先頭または末尾にあるシーケンスには、特別な注意が必要です。 

たとえば、シーケンス「)(」は、最初の文字を最後に移動することで修正できます。シーケンス「(()」は、許可されていない閉じ括弧を挿入する必要があるため、一度の移動では修正できません。シーケンス「()」はすでに正しいです。単に「(」と「)」の数をカウントする単純な実装では、不均衡がグローバルではなく内部にあるシーケンスを誤って判断する可能性があります。

 ## アプローチ

 ブルート フォース ソリューションでは、すべての括弧を他の位置に移動し、結果のシーケンスが正しいかどうかを確認しようとします。 それぞれの動きについて、シーケンスを検証するには O(n) 時間が必要となり、O(n²) 動き × O(n) 検証 = O(n³) 時間となります。 n が 200,000 までの場合、これは完全に不可能です。 

重要な洞察は、1 つの括弧を移動することで修正できるシーケンスは、ほぼ正しいものだけであるということです。 正しい括弧シーケンスには 2 つの特性があります。「(」の合計数は「)」の数と同じであり、「(」マイナス「)」の接頭辞の合計は決して負になりません。 シーケンスが 1 つの手で修正できる場合、残高が -1 を下回るか +1 を超えるプレフィックスを最大 1 つ持つことができます。 合計の不均衡がいずれかの方向に複数ある場合、一度の操作では修正できません。 これにより、1 回のパスでシーケンスをスキャンし、プレフィックスの合計 (バランス) を追跡し、違反の数をチェックすることができます。 これにより、問題は O(n) 時間と O(1) 空間に縮小されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`balance`ゼロに。 これは、左から右に反復するときに発生する「(」と「)」の数の差を追跡します。 
2. カウンタの初期化`bad_prefix`ゼロに。 これで回数がカウントされます`balance`-1 を下回ります。これは、接頭辞が閉じ括弧内に深すぎることを示します。 
3. シーケンス内の各括弧を繰り返します。 インクリメント`balance`括弧が「(」の場合は 1 ずつ減分し、「)」の場合は 1 ずつ減分します。 
4. アップデート後`balance`各ステップで、それが -1 より小さいかどうかを確認します。 その場合は増分します`bad_prefix`。 これは、単純な 1 つの手による修正では十分ではない可能性があることを示しています。 
5. すべてのブラケットを処理した後、最終的なブラケットを確認します。`balance`。 もし`balance`が -1、0、または 1 ではない場合、複数の括弧が所定の位置にないため、1 回の移動でシーケンスを修正することはできません。 
6. 最後に、次のことを確認します。`bad_prefix`は 0 または 1 です。 その場合は、「はい」と出力します。 それ以外の場合は、「いいえ」を出力します。 不良プレフィックスがゼロの場合は、シーケンスがすでに正しいことを意味し、不良プレフィックスが 1 つある場合は、単一の括弧を移動する必要があることを示します。 

機能する理由: バランスを維持することで、ローカルとグローバルの両方の正確さを追跡します。 正しいシーケンスは常に、すべてのプレフィックスでバランス ≥ 0 を持ち、バランス 0 で終了します。最大 1 つの違反を許可すると、シーケンスを修正するために移動できる 1 つの括弧が考慮されます。 複数の違反がある場合は、複数の手が必要になることを意味し、これは禁止されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()

balance = 0
bad_prefix = 0

for c in s:
    if c == '(':
        balance += 1
    else:
        balance -= 1
    if balance < -1:
        bad_prefix += 1

if abs(balance) > 1:
    print("No")
elif bad_prefix > 1:
    print("No")
else:
    print("Yes")
```このコードはシーケンスを 1 回スキャンして更新します。`balance`一致しない開始括弧と終了括弧の数を追跡します。 の`bad_prefix`counter は、単一のブラケットを移動することで修正できる範囲を超える内部不均衡を確実に捕捉します。 最終チェックでは、合計の不均衡が 1 回の移動で十分なほど小さいことを確認します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    s = input().strip()

    balance = 0
    bad_prefix = 0

    for c in s:
        if c == '(':
            balance += 1
        else:
            balance -= 1
        if balance < -1:
            bad_prefix += 1

    if abs(balance) > 1 or bad_prefix > 1:
        return "No"
    return "Yes"

# Provided samples
assert run("2\n)(") == "Yes", "sample 1"
assert run("2\n()") == "Yes", "sample 2"

# Custom cases
assert run("1\n(") == "No", "single open bracket"
assert run("4\n(()(") == "No", "cannot be fixed by one move"
assert run("6\n()()()") == "Yes", "already correct"
assert run("3\n)(") == "No", "too short, cannot fix"
assert run("4\n())(") == "Yes", "one move fixes"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1\n( | いいえ | 単一の文字は固定できません |
 | 4\n(()( | いいえ | 複数の移動が必要です |
 | 6\n()()() | はい | すでに正しい順序 |
 | 3\n)( | いいえ | 修正不可能 |
 | 4\n())( | はい | 単一のブラケットの移動で修正できます |
