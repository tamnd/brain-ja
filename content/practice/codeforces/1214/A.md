 ## 解決策
 ## 問題の理解

 まずはルーブルで固定額のお金を用意し、固定額面のドル紙幣とユーロ紙幣のみを販売する両替所を使って外貨に両替したいと考えています。 各ドルの価格はルーブルで固定されており、各ユーロにも独自の固定ルーブル価格があります。 これらの外国紙幣を何枚でも購入すると、未使用のルーブルがいくらか残りますが、目標はその残額を最小限に抑えることです。 

重要な制約は、任意の金額の通貨を選択するのではなく、紙幣全体を購入する必要があり、各紙幣の種類には独自の通貨での固定価値があり、それが紙幣あたりの固定ルーブルコストに換算されるということです。 したがって、実際の決定は、使用総額ができるだけ大きくなるように、ただし最初の金額を超えないようにするために、ドル紙幣とユーロ紙幣を何枚購入するかということです。 

入力サイズは、妥当な紙幣の組み合わせを直接探索できるほど十分小さいですが、考えられるすべての紙幣のマルチセットを列挙しようとすると失敗するほど大きいです。 重要な観察は、両方の通貨の額面が少数しかないため、意味のある組み合わせの数が厳密に制限されていることです。 

単純な間違いは、常に最初にどちらかの通貨で可能な限り最大の紙幣を購入するなどの貪欲な戦略を想定することです。 混合組み合わせは単一通貨の貪欲な選択に勝てる可能性があるため、これは失敗します。 たとえば、すべてをユーロで支出すると、予算に合わせて数ドルとユーロを混ぜるよりも悪い残金が残る可能性があります。 

もう 1 つの微妙な問題は、ユーロ紙幣とドル紙幣が総額ルーブルという共通の制約を通じてのみ相互作用するということを無視していることです。 この共有予算を超えて宗派間に構造的な結合はないため、問題は 2 つの独立したアイテム セットに対する制限されたナップザックのような検索に帰着します。 

## アプローチ

 この問題を強引に見ると、ドル紙幣とユーロ紙幣の選択の可能性がそれぞれ 1 つの状態として扱われます。 ドル紙幣は最大 100 まで、ユーロ紙幣は最大 200 までの固定額面があるため、各額面の枚数のすべての組み合わせを試してみることが考えられます。 紙幣枚数の適度な上限（最大 n を最小価格で割った値、約 30）であっても、宗派ごとに独立して処理すると、巨大な国家空間が生じるため、これはすぐに爆発するでしょう。 

ただし、構造は見た目よりもはるかに単純です。 各通貨は独立して請求書あたりの固定コストの倍数のみを寄与します。つまり、実際の問題は、次のような 2 つの非負の整数 (ドルとユーロの数) を選択することです。$$d \cdot x + e \cdot y \le n$$そして支出額を最大化すること。 

重要な洞察は、x と y の両方が最大でも n / 30 で制限されるため、一方の変数を安全に修正して、定数時間内にもう一方の可能な限り最良の値を計算できるということです。 ドル紙幣の枚数が固定されている場合、ユーロ紙幣の最適枚数は単純に e で割った余りになります。 これにより、問題はすべての可能な金額にわたる線形スキャンに分解されます。 

逆も同様ですが、正確さのために対称性は必要ないため、必要な方向は 1 つだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての組み合わせに対するブルート フォース | O((n/d)・(n/e)) | お(1) | 遅すぎる |
 | 1 つの通貨を固定し、貪欲な剰余を計算する | O(n/d) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 0 から n // d までのドル紙幣のすべての可能な数を反復します。 各選択肢は、予算の固定部分をドルで支出することを表し、残りの金額はユーロで最適に埋められるようにします。 
2. 固定枚数のドル紙幣 x ごとに、ドルを購入した後の残りのルーブルを rem = n - x * d として計算します。 この残りはユーロで利用可能な予算の全額を表します。 
3. この余りから何ユーロ紙幣を購入できるかを y = rem // e として計算します。 ユーロ紙幣のコストは同一であり、貪欲な充填を妨げる制約がないため、これは最適です。 
4. 合計使用金額を使用額 = x * d + y * e として計算し、すべての x の最大値を追跡します。 
5. すべての可能性を繰り返した後の答えは n - best_spent で、これは最小の残りルーブルを表します。 

### なぜ効果があるのか

 最適な解決策を得るには、使用するドル紙幣の枚数を修正します。 すべてのユーロ紙幣は同一のコスト構造を持ち、予算以外の制限がないため、この問題が修正されれば、ユーロ紙幣が収まるのであれば、残りを未使用のままにしておく理由はありません。 したがって、最良のユーロの選択は常に貪欲です。 これにより、実行可能な予算のすべての分割が x の値を通じて考慮され、そのような分割ごとに最適な対応する y が選択されるため、最適なソリューションが見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    d = int(input())
    e = int(input())

    max_spent = 0

    # try all possible number of dollar bills
    for x in range(n // d + 1):
        rem = n - x * d
        y = rem // e
        spent = x * d + y * e
        if spent > max_spent:
            max_spent = spent

    print(n - max_spent)

if __name__ == "__main__":
    solve()
```このソリューションは、実行可能なすべての金額を明示的に反復します。 それぞれについて、残りの予算を貪欲にユーロで満たします。 最後の減算により、最大化された使用額が最小化された残額に変換されます。 

実装でよくある落とし穴は、反復中に残りを直接最小化するのではなく、使用済みのお金を最大化していることを忘れることです。 どちらも同等ですが、消費された状態を追跡することで、中間状態での混乱を回避できます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    d = int(input())
    e = int(input())

    max_spent = 0
    for x in range(n // d + 1):
        rem = n - x * d
        y = rem // e
        max_spent = max(max_spent, x * d + y * e)

    return str(n - max_spent)

# provided sample
assert run("100\n60\n70\n") == "40"

# minimum case
assert run("30\n30\n30\n") == "0"

# only one currency useful
assert run("100\n50\n100\n") == "0"

# mixed optimal
assert run("120\n30\n50\n") == "10"

# boundary large-ish
assert run("100000000\n99\n100\n") == str(100000000 % 99)
```| テスト入力 | 期待される出力 | 検証内容 |

 | 100,50,100 | 0 | 単一の最適通貨 |

 ## 特殊なケース

 エッジケースの 1 つは、1 つの通貨が優勢であるものの、予算とわずかに一致しない場合です。 たとえば、n = 100、d = 60、e = 70 の場合、どちらの通貨も単独では完全に適合しません。 このアルゴリズムは、ドルについて x = 0 と x = 1 の両方をチェックし、ユーロを多用する構成とドルを多用する構成の両方が確実に評価されるようにします。 x = 0 の場合、100 // 70 = 1 ユーロを取得し、70 を費やします。x = 1 の場合、60 を費やし、ユーロを支払う余裕がないため、全体で 70 を費やし、30 を残すのが最善です。 

もう 1 つのエッジケースは、ある通貨のコスト効率が厳密に劣っているにもかかわらず、モジュラー調整を改善する必要がある場合です。 d < e またはその逆の場合でも、混合スキャンでは、d によって誘発されるすべての剰余クラスが探索されることが保証されるため、列挙の外に隠れたより良い組み合わせは存在しません。
