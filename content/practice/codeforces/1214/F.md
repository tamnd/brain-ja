 ## 解決策
 # 問題の理解

 ある長さの円上に点のマルチセットが 2 つあります`m`。 

最初のセットにはオフィスの場所が含まれています。 オフィス`i`市内にあります`a[i]`。 

2 番目のセットには候補が含まれています。 候補者`j`都会に住んでいます`b[j]`。 

すべての事務所は 1 人の候補者を受け入れる必要があり、すべての候補者は 1 つの事務所に割り当てられる必要があります。 候補者を事務所に割り当てるコストは、候補者の都市間の最短の円周距離になります。 総コストを最小限に抑えながら、最適な割り当てを 1 つ出力する必要があります。 

サークルには以下が含まれます`10^9`都市、ただしそれだけ`n ≤ 200000`事務所も候補者も。 都市の数は膨大であるため、円のサイズに応じたアルゴリズムは不可能です。 私たちが処理できる唯一のオブジェクトは、`n`自分自身を位置づけます。 

の値`n`二次アルゴリズムを即座に除外します。 アン`O(n²)`解決策には大まかに必要になります`4 × 10^10`最悪の場合の操作は完全に不可能です。 ターゲットの複雑さは次のとおりである必要があります`O(n log n)`。 

難しいのは、都市が線ではなく円上にあることです。 

考慮する：```
m = 10
offices    : 1 9
candidates : 2 10
```線形解釈では距離を使用します。`1`そして`1`、しかしサークルシティでは`10`市に隣接している`1`, したがって、ジオメトリは回り込みます。 

もう 1 つの簡単な間違いは、両方の配列を並べ替えて位置ごとに一致させることです。```
m = 10
offices    : 1 4 8
candidates : 3 6 8
```ソート後、同じランクを一致させるとコストが得られます```
|1-3| + |4-6| + |8-8| = 4
```しかし、円上では 1 つの並べ替えられた順序を回転させることができます。 マッチング```
1 <- 3
4 <- 6
8 <- 8
```実際には、ここで最適なものを生み出すシフトです。 重要な観察は、最適なマッチングは常にソートされた順序の循環シフトであり、必ずしもゼロ シフトではないということです。 

重複により、別の微妙なケースが発生します。```
m = 20
offices    : 5 5 5
candidates : 5 5 5
```最適な割り当てはたくさんあります。 ソリューションは、候補インデックスの有効な順列を出力する必要があります。 

## アプローチ

 ブルートフォースソリューションでは、可能な限り完全なマッチングを試みます。 がある`n!`マッチングはすぐに不可能になります。 

より合理的な総当り攻撃は、構造観察から始まります。 オフィスの位置を円の周りで並べ替え、候補者の位置を円の周りで並べ替えると、最適なマッチングには交差ペアがありません。 2 つの一致したパスが交差する場合、それらのエンドポイントを交換しても合計距離が増加することはなく、多くの場合減少します。 交差を繰り返し除去すると、最適値は交差しない最適値に変換されます。 

交差が禁止されると、マッチングは循環シフトによって完全に決定されます。 両方のセットを並べ替えた後、シフトを選択します`k`、次に一致します```
A[i] <-> B[i+k]
```インデックスは周期的に取得されます。 

これにより、検索スペースが減少します。`n!`のみに一致`n`シフトします。 

残念ながら、すべてのシフトを個別に評価するには依然としてコストがかかります`O(n²)`。 

残りの観察は、固定の役職についての観察です。`a`、シフトが変化するときの寄与は、シフトの範囲にわたる区分的定数関数です。 円周距離```
dist(a, b) = min(|a-b|, m-|a-b|)
```ときだけ形を変える`b`～に対していくつかの重要な位置の 1 つを横切る`a`。 

座標をソートした後、これらの重要な遷移を二分探索で見つけることができます。 各オフィスと各候補者は、連続するシフト範囲にわたって一定の値を提供します。 シフト領域の差分配列を使用して、すべての寄与を累積できます。 

結果は、`O(n log n)`アルゴリズム。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのシフトにわたるブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 差分配列オーバーシフト | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元のインデックスを思い出しながら、オフィスを都市の位置で並べ替えます。 
2. 元のインデックスも記憶しながら、都市の位置によって候補者を並べ替えます。 
3. 非交差プロパティを使用します。 最適な割り当ては、ソートされたオフィス シーケンスと、ソートされた候補シーケンスの循環シフトと一致する必要があります。 
4. シフトしましょう`k`整理されたオフィスを意味します`i`ソートされた候補と一致します`(i+k) mod n`。 
5. アレイを構築する`cost[k]`、シフトの総コスト`k`。 
6. 各シフトを個別に評価するのではなく、すべてのオフィスのポジションを処理します`a[i]`。 

固定オフィスの場合、次の式は`dist(a[i], b[j])`ときだけ形を変える`b[j]`円の周りの 4 つの重要な領域の 1 つを横切ります。 ソートされた候補座標の二分探索により、次の範囲が特定されます。`j`それぞれの地域に属しています。 
7. このようなすべての領域をシフト変数の範囲更新に変換します。`k = j - i`。 

差分配列を使用すると、シフト間隔全体に同じ値を加算できます。`O(1)`時間。 
8. すべての候補位置に対して対称プロセスを繰り返します。`b[j]`。 

両方のパスの後、各シフトの累積値は、そのシフトの合計マッチング コストと等しくなります。 
9. 差分配列をプレフィックス合計して次の間隔で復元します`cost[k]`。 
10. コストが最小限のシフトを選択します。 
11. 割り当てを再構築します。 最適なシフトであれば`k`、その後、オフィスを整理しました`i`ソートされた候補を受け取ります`(i+k) mod n`。 
12. 割り当てを元のインデックスに変換し、結果を出力します。 

### なぜ効果があるのか

 円の周囲の点を並べ替えた後、目標値を増加させることなく、交差一致を解除できます。 このプロセスを繰り返すことで、最適な非交差マッチングが得られます。 

循環的に順序付けられた 2 つのセット間の非交差完全マッチングは、1 つの開始ペアによって完全に決定されます。 最初のペアが選択されたら、残りのペアは循環順序に従う必要があります。 つまり、すべての最適解は、ソートされた候補シーケンスの循環シフトに対応します。 

差分配列の構築により、すべてのシフトの正確な合計コストが同時に計算されます。 各オフィス候補者ペアは、そのペアが一致するシフトに正確に寄与し、区分的分解はすべての可能性をカバーします。 したがって、シフトの回復値は、`k`は、正確には、そのシフトによって定義されるマッチングの総コストです。 それらの中から最小値を選択すると、全体的な最適値が得られます。 

## Python ソリューション```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

def solve():
    m, n = map(int, input().split())

    A = [(x, i) for i, x in enumerate(map(int, input().split()), start=1)]
    B = [(x, i) for i, x in enumerate(map(int, input().split()), start=1)]

    A.sort()
    B.sort()

    a = [x for x, _ in A]
    b = [x for x, _ in B]

    aa = [2 * x for x in a]
    bb = [2 * x for x in b]

    diff = [0] * (n + 1)

    def add_range(l, r, v):
        if l > r:
            return

        l %= n
        r %= n

        if l <= r:
            diff[l] += v
            if r + 1 < n:
                diff[r + 1] -= v
        else:
            diff[0] += v
            if r + 1 < n:
                diff[r + 1] -= v
            diff[l] += v

    for i in range(n):
        x = a[i]

        r = bisect_right(bb, 2 * x - m - 1) - 1
        add_range(-i, r - i, -x)

        l = r + 1
        r = bisect_right(bb, 2 * x - 1) - 1
        add_range(l - i, r - i, x)

        l = r + 1
        r = bisect_right(bb, 2 * x + m) - 1
        add_range(l - i, r - i, -x)

        l = r + 1
        r = n - 1
        add_range(l - i, r - i, x + m)

    for i in range(n):
        x = b[i]

        r = bisect_right(aa, 2 * x - m - 1) - 1
        add_range(i - r, i, -x)

        l = r + 1
        r = bisect_right(aa, 2 * x) - 1
        add_range(i - r, i - l, x)

        l = r + 1
        r = bisect_right(aa, 2 * x + m) - 1
        add_range(i - r, i - l, -x)

        l = r + 1
        r = n - 1
        add_range(i - r, i - l, x + m)

    cur = 0
    best_shift = 0
    best_cost = None

    for k in range(n):
        cur += diff[k]
        if best_cost is None or cur < best_cost:
            best_cost = cur
            best_shift = k

    ans = [0] * n

    for i in range(n):
        j = (i + best_shift) % n
        office_idx = A[i][1]
        candidate_idx = B[j][1]
        ans[office_idx - 1] = candidate_idx

    print(best_cost)
    print(*ans)

solve()
```最初の部分では、最終的な割り当てを再構築できるように、元のインデックスを保存しながら事務所と候補者を並べ替えます。 

実装の中核は、シフトドメインの差分配列です。 各シフトのコストを個別に計算するのではなく、各二分探索により、同じ寄与を受けるシフトの間隔全体が特定されます。 ヘルパーさん`add_range`シフトはモジュロで取得されるため、循環範囲更新を実行します。`n`。 

4 つの二分探索範囲は、円周距離の 4 つの異なる代数形式に対応します。 それらの導出は、ダイレクト アークとラップ アークの比較から得られます。 

すべての更新が適用された後、プレフィックス合計によってシフトごとの合計コストが再構築されます。 最小シフトによって最適なマッチングが決まります。 

間違いやすい場所の 1 つは、モジュラー間隔の更新です。 間隔はシフト配列の終わりに折り返される可能性があるため、2 つの通常の範囲に分割する必要があります。 バグのもう 1 つの一般的な原因は、`bisect_right(...)-1`、リージョンに属する最後のインデックスを意図的に検索します。

 ## 特殊なケース

 次のことを考慮してください。```
10 2
1 9
10 2
```円周距離は`1`そして`1`、総コストを与える`2`。 直線距離のソリューションでは、正しく計算されません。`1 + 7 = 8`。 距離分解では循環メトリックが明示的に使用され、ラップされたパスが第一級の候補として扱われるため、アルゴリズムはこれを処理します。 

ここで、繰り返される位置を考えてみましょう。```
20 3
5 5 5
5 5 5
```すべてのシフトにはコストがかかります`0`。 差分配列の構築ではどこでも寄与ゼロが割り当てられ、すべてのシフトが結合され、アルゴリズムは 1 つの有効な置換を出力します。 特別な取り扱いは必要ありません。 

最後に、最適なマッチングが元の順序からは明らかではない場合を考えてみましょう。```
10 3
1 4 8
8 3 6
```ソートすると循環順序が明らかになります。 非交差特性により探索空間が巡回シフトに削減され、最小コスト シフトにより総コストで最適な割り当てが再現されます。`4`。 アルゴリズムは元の入力順序には決して依存せず、円の周りの幾何学的順序のみに依存します。
