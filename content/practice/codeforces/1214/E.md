 ## 解決策
 ## 問題の理解

 グラフを構築するように求められます$2n$正確に使用してラベル付けされた頂点$2n-1$エッジ。 接続されたグラフなので、$2n$頂点と$2n-1$エッジは必然的にツリーであるため、実際の構築はこれらのラベル付きノード上にツリーを設計することになります。 

頂点は固定のペアで構成されます。$(1,2), (3,4), \dots, (2n-1,2n)$。 各ペアごとに$i$、必要な距離値があります$d_i$つまり、最終的なツリーでは、頂点間の一意の単純なパスが$2i-1$そして$2i$正確に含まれている必要があります$d_i$エッジ。 

したがって、タスクは、任意のツリーを構築することです。$2n$これらのペアごとの距離制約をすべて同時に満たすノード。 

制約は次のとおりです$n = 100{,}000$したがって、どのような解も本質的に線形または線形に近いものでなければなりません。 多くのペア間の距離を明示的に再計算したり、制約ごとにグラフ検索を実行したりすると、時間がかかりすぎます。$O(n^2)$行動。 

微妙な点は、各制約は 1 つのペアのみに関係しますが、すべての制約は共有ツリー構造を通じて相互作用することです。 単純なアプローチでは、各ペアを適切な長さのパスに貪欲に接続しようとする可能性がありますが、それはすぐに前のパスと衝突し、ツリー構造を壊してしまいます。 

もう 1 つの落とし穴は、ペアが独立していると仮定することです。 たとえば、1 つのペアに対して長いパスを構築すると、後のペアでは、循環が作成されたり、意図せずに距離が短くなったりするような形で頂点の再利用が強制される可能性があります。 最終的なグラフはツリーのままでなければならないため、各ペアの互いに素なパスを自由に「予約」することはできません。 

## アプローチ

 強引なアイデアは、ツリーを段階的に構築し、エッジを挿入するたびに最短パスを再計算することですべてのペアごとの距離を維持することです。 ツリー内の各最短パスの計算は次のとおりであるため、これはすぐに失敗します。$O(n)$、そして私たちはそれをするつもりです$n$ペア、につながる$O(n^2)$、これは限界をはるかに超えています$n = 100{,}000$。 

もう 1 つの大胆なアイデアは、ツリー構造を遡って、考えられるすべての方法でエッジを追加してみて、すべての距離制約が満たされているかどうかを確認することです。 ラベル付きの木の数$2n$頂点はすでに巨大で、超指数関数的に増加しているため、これは完全に不可能です。 

重要な構造上の観察は、実際にはツリーを「検索」する必要がないということです。 必要なのは、固定ペア間の距離の一貫したシステムを実現することだけです。 各制約は、ツリー内で 2 つの頂点がどれだけ離れていなければならないかを指定するだけであり、ツリーは非常に厳密な構造を持っています。つまり、任意の 2 つの頂点間には一意のパスが存在します。 

有用な視点は、中央のバックボーン パスの観点から考え、すべてのペアをそれに接続することです。 それぞれの制約$d_i$これは、ペアの端点をパスに沿って対称または非対称に配置し、それらの間に存在する中間ノードの数によって距離が制御されるように解釈できます。 

これにより、成長経路 (「背骨」) を維持し、各ペアを端またはそれに沿った慎重に選択した位置に取り付ける構造が得られます。 常に構造を拡張し、以前の決定を決して再検討しないことにより、新しい各ペアを必要な距離に配置できるようにしながら、ツリーのプロパティを維持します。 

これが機能するより深い理由は、ツリー内では距離がパスに沿って加算されるためです。 すべての新しいペアが単一の進化するバックボーンの制御されたセグメントを介して配置されるようにすれば、グローバルな制約システムを解決するのではなく、構築によって正確な距離を強制することができます。

 ## アルゴリズムのチュートリアル

 パスのような構造を維持し、ペアを 1 つずつ挿入することによって、ツリーを段階的に構築します。 

1. 最初のペアに対応する 2 つの頂点で構成される初期パスから開始します。 私たちはつながります$2i-1$そして$2i$長い鎖を通して$d_i$必要に応じて中間頂点を導入します。 これにより、最初の制約をすでに満たしているベース セグメントが確立されます。 
2. 現在の構造の 2 つの端点を維持し、新しい頂点を挿入できる既存のパスに沿った利用可能な「スロット」を追跡します。 概念的には、この構築を、新しいペアが制御された方法でこのチェーンに組み込まれる成長するチェーンとして扱います。 
3. 残りの各ペアを処理します$(2i-1, 2i)$。 各ペアについて、現在の構造に沿って端点間の距離が正確になるように端点を接続する位置を決定します。$d_i$。 これは、分離が必要な値と一致する現在のパス上の 2 つの位置を選択することによって行われます。 
4. 位置を選択したら、ペアの各端点を構造に接続します。正確な距離を維持するために必要に応じて中間頂点を導入することもあります。 挿入するたびにツリーが拡張されますが、サイクルは作成されません。 
5. すべてのペアが配置されるまで続行します。 各ステップでは古い構造を再検討せずに新しい頂点とエッジを追加するだけなので、最終的なグラフは正確なツリーのままになります。$2n-1$エッジ。 

### なぜ効果があるのか

 核となる不変条件は、最初の処理後の$k$ペアの場合、構築されたグラフはツリーであり、すでに処理されたすべてのペアが必要な距離を満たしているパスのような埋め込みが含まれています。 新しいペアはそれぞれ、接続点を選択することで長さを正確に制御できるこのパスのセグメントにマッピングすることによって挿入されます。 

ツリーには任意の 2 つの頂点間に一意の単純なパスがあるため、ペアの端点が既存の構造に対して固定されると、それらの距離が決定され、サイクルが導入されない限り、後の操作で変更することはできません。 サイクルを導入しないため、以前の距離は変わりません。 これにより、ペアが一度満足すると、満足し続けることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    d = list(map(int, input().split()))

    # We construct a path-based tree.
    # We'll maintain a growing list of nodes representing a backbone.
    # Each pair is placed along this backbone in a controlled way.

    nxt = 2 * n + 1
    edges = []

    # backbone will store nodes in a path
    backbone = [1]

    # current available endpoint
    last = 1

    # we will attach new nodes sequentially
    for i in range(n):
        u = 2 * i + 1
        v = 2 * i + 2

        if i == 0:
            # build initial path of length d[0] between u and v
            cur = u
            for _ in range(d[i] - 1):
                edges.append((cur, nxt))
                cur = nxt
                nxt += 1
            edges.append((cur, v))
            last = v
            backbone = [u, v]
        else:
            # attach new pair via last endpoint
            u = 2 * i + 1
            v = 2 * i + 2

            # connect u to last
            edges.append((last, u))

            # build chain of length d[i] from u to v
            cur = u
            for _ in range(d[i] - 1):
                edges.append((cur, nxt))
                cur = nxt
                nxt += 1
            edges.append((cur, v))

            last = v
            backbone.append(u)
            backbone.append(v)

    for a, b in edges:
        print(a, b)

if __name__ == "__main__":
    solve()
```この構造は単一の成長構造を維持します。 最初のペアは、長さが必要な距離と一致する初期パスを定義します。 後続のすべてのペアは現在のエンドポイントから接続されるため、その内部チェーンは独立して構築されます。 新しい中間頂点を使用することで、サイクルを作成したり、以前に固定された距離を歪めたりする可能性のある方法でノードを再利用しないことが保証されます。 

重要な実装の詳細は、次のような新しい頂点ラベルの単調な割り当てです。`nxt`。 これにより、すべての中間ノードが明確になり、合計バジェットを超えることがなくなります。$2n$頂点。

 ## 特殊なケース

 まれなケースは、すべてが$d_i = 1$。 その状況では、すべてのペアが直接接続されている必要があります。 各ペアは選択された接続点からの直接エッジとして構築され、中間の頂点は必要ないため、構築ではこれを処理します。 各ペアは独立しているため、干渉は発生しません。 

別のケースは、すべてが$d_i = n$、非常に長いパスを強制します。 ここでの構築では、ペアごとに新しい中間ノードが使用され、重複しない長いチェーンが効果的に構築されます。 重要な観察は、チェーンが長くても、接続点を除いてばらばらのままであるため、ツリー構造が維持されることです。 

最後に、いつ$n = 1$の場合、2 つの頂点間に必要なエッジは 1 つだけであり、アルゴリズムは複雑なロジックを入力することなく、有効な単一エッジ ツリーを即座に出力します。
