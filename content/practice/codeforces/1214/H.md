 ## 問題の理解

 私たちに与えられた木は、$n$頂点。各頂点は歩行者ネットワーク内の正方形を表します。 各頂点には次のいずれかを割り当てる必要があります。$k$色。 要件はグローバルかつパスベースです。つまり、正確に含まれるツリー内の単純なパスを選択する場合、$k$頂点、そのパスにはすべての頂点が含まれている必要があります$k$少なくとも一度は色を付けます。 

ツリー構造が重要なのは、任意の 2 つの頂点間には単純なパスが 1 つだけ存在するためです。そのため、すべての制約は最終的にはツリー パスに沿った一連の頂点に関するものになります。 この条件は局所的なものではなく、あらゆる長さに適用されます。$k$このパスは、色を恣意的に配置するのではなく、高度に構造化した方法で配置する必要があることを即座に示唆しています。 

制約は大きく、$n$200,000まで。 ツリー内のパスの数は二次であるため、パスを列挙したりパスごとの条件をチェックしたりするソリューションは直ちに除外されます。 平$O(nk)$最悪の場合は危険になります。 ソリューションは線形または線形に近いものでなければなりません。通常、$O(n)$または$O(n \log n)$。 

いくつかの特殊なケースでは、状況の困難さが明らかになります。 ツリーが単純なチェーンの場合、$k = n$、その場合、長さの唯一のパス$k$はツリー全体であり、すべての色はそのチェーンのどこかに 1 回だけ出現する必要があるため、厳密な色付けパターンが強制されます。 もし$k = 2$、すべてのエッジには 2 頂点パスごとに両方の色が表示される必要があり、すべてのエッジに交互の色が強制的に適用されます。これは 2 部グラフでのみ可能ですが、ツリーは 2 部であるため、このケースは常に実現可能です。 ただし、本当の課題は次のような場合です。$k \ge 3$長いパスは重なり合い、ツリー全体に伝播する繰り返しパターンを強制するためです。 

単純なアプローチでは、色を割り当ててから、長さのすべてのパスを検証しようとします。$k$。 チェックをすべての根から葉のパスまたはすべての直径セグメントに制限したとしても、依然として内部パスを見逃してしまうため、正確性は信頼できなくなります。 

## アプローチ

 強引な解釈では、色を任意に割り当ててから、長さの単純なパスをすべてチェックすることになります。$k$。 このようなパスごとに、すべてのパスが$k$色が現れます。 長さのすべてのパスを生成する場合でも$k$すでに木の中にいる$O(nk)$チェーン状構造の最悪の場合のパスと各チェックのコスト$O(k)$、につながる$O(nk^2)$、これは限界をはるかに超えています。$n = 2 \cdot 10^5$。 

重要な構造的洞察は、この条件が固定長のパスのみを制約するということです。$k$、すべてのパスではありません。 木では、あらゆる長さを強制する唯一の方法 -$k$すべての色を含めるパスは、どのパスに沿っても色が制御された周期で定期的に動作することを保証することです。 すべてのパスにわたって均一性を強制する自然オブジェクトは、制御された深さの階層化を備えた DFS トラバーサル順序です。 

正しい構築は、ルートの選択と深度モジュロに基づいた色の定義に依存します。$k$, しかし、慎重に同期しない限り、異なるブランチでは一貫性のないパターンが作成されるため、これだけでは十分ではありません。 実際の観察はより強力です。すべての長さのパスが確実に存在することを確認するだけで済みます。$k$すべての剰余モジュロを含みます$k$これは、ルートからノードへのすべてのパスに沿って、色が厳密に一貫したサイクルに従い、ツリーがどのような長さのパスにも適用されるように構造化されている場合に保証されます。$k$すべての残基を正確に 1 回走査します。 

これにより、問題は、深さクラスが矛盾なく循環的に動作する方法でツリーの方向と色を指定できるようにするという問題に集約されます。 建設的な解決策は、BFS 深度モジュロによって色を割り当てます。$k$ただし、構造的な矛盾が現れないことを確認した後でのみ、それは木にとって常に実現可能であることがわかります。 

これが機能する理由は、ツリー内の単純なパスには、選択したルートに関連する固有の深さのシーケンスがあり、長さのパスに沿った深さの違いがあるためです。$k$常に正確にスパンする$k$連続した深さの値。 したがって、モジュロ-$k$カラーリングはすべてを保証します$k$色はそのようなパスごとに 1 回だけ表示されます。

 ## アルゴリズムのチュートリアル

 1. 木には自然な開始点がなく、一貫した深さの概念が必要なため、任意の頂点をルートとして選択します。 これにより、階層構造における各ノードの位置を定義できます。 
2. BFS または DFS をルートから実行して、すべてのノードの深さを計算します。 深さは、一意のツリー パスに沿ってノードがルートからどれだけ離れているかを表します。 
3. 各ノードに次の色を割り当てます。$(\text{depth}[v] \bmod k) + 1$。 これにより、次のサイクルが繰り返されます。$k$ツリーの下に移動すると色が変わります。 
4. 構築ではすべての有効なパスに必要なプロパティがすでに保証されているため、これらの色を直接出力します。 

この手順が正しい理由は、ツリー内でパスがどのように動作するかを理解することにかかっています。 2 つのノード間のパスは、プレフィックスを共有する 2 つのルートからノードへのパスに分解できるため、パスに沿ったカラー シーケンスは、連続する整数の間隔を形成する深度値の差によって決まります。 長さ-$k$したがって、パスは正確にまたがる必要があります$k$ツリー内のどこかにある連続した深さレベル。 

### なぜ効果があるのか

 重要な不変条件は、ルートからノードへのパスに沿って色がピリオドで繰り返されることです。$k$深さ順に。 ツリー内の単純なパスは、1 つのノードから最下位の共通祖先に上向きに移動し、次に別のノードに下向きに移動することに対応します。 この横断に沿って、深さはエッジごとに 1 つずつ変化するため、一連の深さは連続した整数の間隔を形成します。 その間隔にサイズがある場合$k$、必ず各剰余クラスのモジュロを表す 1 つが含まれます。$k$、すべてを意味します$k$色は 1 回だけ表示されます。 これにより、長さが妨げられます-$k$色の欠落からのパス。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

n, k = map(int, input().split())
g = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

depth = [-1] * n
q = deque([0])
depth[0] = 0

while q:
    u = q.popleft()
    for v in g[u]:
        if depth[v] == -1:
            depth[v] = depth[u] + 1
            q.append(v)

colors = [(d % k) + 1 for d in depth]

print("Yes")
print(*colors)
```実装は、効率的な走査に必要なツリーの隣接リストを構築することから始まります。 Python での再帰の深さの問題を回避するために、DFS の代わりに BFS が使用されます。$n$最大200,000まで可能です。 深さ配列にはルートからの距離が格納されます。 

深度が計算されると、色付けはノードごとに即時かつ一定時間行われます。 モジュロ演算は、構築に必要な周期構造を強制します。 最終出力では、有効性フラグと割り当てられた色が印刷されます。 

微妙な実装ポイントは、Python 再帰では縮退チェーンでスタック オーバーフローの危険があるため、DFS 再帰ではなく BFS 再帰を選択することです。 もう 1 つは、エッジを読み取るときのゼロ インデックス調整です。これは、隣接リストの構築全体を通じて一貫している必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, k = map(int, input().split())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    depth = [-1] * n
    q = deque([0])
    depth[0] = 0
    while q:
        u = q.popleft()
        for v in g[u]:
            if depth[v] == -1:
                depth[v] = depth[u] + 1
                q.append(v)

    colors = [(d % k) + 1 for d in depth]
    return "Yes\n" + " ".join(map(str, colors))

 ## 特殊なケース

 微妙なケースの 1 つは、1 つのノードが他のすべてのノードに接続する星型ツリーです。 BFS を中心から開始すると、すべての葉に同じ深さが割り当てられ、同じ色が生成されます。 任意の長さのパス$k$中心を通過する必要があるため、深さの間隔は必要な残基をすべてカバーします。 長さのパスがないため、構築は有効なままです$k$葉の中に完全に留まることができます。 

もう 1 つのケースは、長いチェーンです。$n = k$。 ここでは木全体が唯一の長さです -$k$モジュロ割り当てにより、各ステップで深さが 1 ずつ増加するため、各色がチェーンに沿って 1 回だけ表示されることが保証されます。 

より深いケースは非常に不均衡な分岐であり、異なるサブツリーの深さは同じですが、祖先を経由する以外にサブツリー間に接続パスがありません。 BFS 深さの割り当てでは、ブランチ間のすべてのパスが必然的に共有祖先を通過し、正確性を高める連続した深さ間隔のプロパティが維持されるため、一貫性が保証されます。
