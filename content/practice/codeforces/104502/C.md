 ## 解決策
 ## 問題の理解

 私たちは一連のコンテスト全体で Teadose の評価をシミュレーションしています。 各コンテストには、パフォーマンス値と部門フラグの 2 つの属性があります。 初期レーティングから始めてコンテストを順番に処理し、現在のレーティング範囲とコンテスト部門に応じてレーティングを更新します。 

重要な問題は、現在のレーティングが特定の期間内にない限り、ほとんどのコンテストが「非アクティブ」であることです。 コンテストがアクティブな場合、評価は、パフォーマンスと現在の評価の差を 4 で割ってゼロに向かって切り捨てたものから導出されるわずかな調整によって変更されます。 それ以外の場合、評価は変更されません。 

このシミュレーションに加えて、最大 1 つのコンテストを完全に無視することができます。 目標は、「伝説のドロップ」を最小限に抑えることが最終レーティングを最大化することと同じであるため、最終レーティングができるだけ大きくなるように、コンテストをまったくスキップしないのか、それとも 1 つだけスキップするのかを選択することです。 

入力サイズは最大 10 万コンテストに達するため、スキップされる可能性のある位置ごとにプロセス全体を再計算しようとするソリューションは遅すぎます。 二次アプローチでは次のことが必要になります$10^{10}$実行可能な限界をはるかに超えた最悪の場合の操作。 

このシミュレーションの微妙な問題は、コンテストをスキップすると評価の軌道が変わり、その後のコンテストがアクティブか非アクティブかに影響を与えることです。 この依存関係により、ローカル推論が難しくなります。 

よくある失敗例は、コンテストをスキップするとレーティングが変更され、将来のアクティベーション条件が逆転する場合に発生します。 たとえば、スキップされたコンテストによりレーティングが 2100 未満に維持され、そうでなければ非アクティブになる将来の div2 更新が多数許可されるシナリオを考えてみましょう。 インデックスごとに単純に「削除して再シミュレート」するアプローチでは、誤って独立性を前提としてしまい、これらのカスケード効果を見逃してしまう可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。考えられるすべてのコンテストをスキップして (または何もスキップせずに)、毎回プロセス全体をシミュレートして、最良の結果を取得します。 各シミュレーションの費用$O(n)$、そしてこれを行うのは$n$選択は～につながる$O(n^2)$が遅すぎる$10^5$。 

重要な観察は、スキップの決定が決定されると、プロセスは逐次的かつ決定的であるということです。 どの時点でも、将来は現在の評価とスキップがすでに使用されているかどうかにのみ依存します。 どのコンテストがスキップされたかを覚えておく必要はありません。将来、コンテストをスキップするオプションがまだあるかどうかだけを覚えておく必要があります。 

これにより、問題は、コンテスト インデックスごとに 2 つの状態 (スキップをまだ使用していない状態とすでに使用した状態) を持つ動的なプロセスに縮小されます。 各州には、完全な履歴ではなく、単一の整数の評価のみが保存されます。 トランジションは前のステップから直接適用されます。 

これら 2 つの状態を単一パスで前方に伝播することで、完全なシミュレーションの再計算を回避します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | Brute Force (skip each index + simulate) |$O(n^2)$|$O(1)$| 遅すぎる |
 | プレフィックス上の 2 状態の DP |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 コンテストを左から右にスキャンしながら、2 つの実行値を維持します。 

1. 2 つの評価を初期化します。1 つはコンテストをスキップしない場合、もう 1 つはコンテストを最大 1 つスキップできる場合です。 
2. 各コンテストについて、まず自然な遷移を計算します。 この更新は、現在のレーティングとコンテストの種類によって異なります。 評価がその部門のアクティブな期間外にある場合、評価は変更されません。 それ以外の場合は、以下に基づいて切り捨てられた更新を適用します。$(p_i - r) / 4$。 
3. この状態には柔軟性がないため、遷移を直接適用して「スキップ使用なし」状態を更新します。 
4. 「スキップ許可」状態については、2 つの可能性を考慮します。 コンテストを取得して前のスキップ状態から移行するか、このコンテストをスキップします。これは、スキップがまだ使用されていない場合にのみ有効です。 ここでスキップすると、スキップによって許可された削除が 1 つ消費され、以前の評価が保持されるため、評価は以前のスキップ未使用状態と同じままになります。 
5. スキップ状態のこれら 2 つの可能性のうち、より良い方を選択します。 
6. すべてのコンテストを処理した後、両方の州の最終評価を比較し、大きい方を採用します。 

### なぜ効果があるのか

 重要な特性は、すべての指標において、州が将来の決定に関連するすべてを完全に把握していることです。 今後重要となる唯一の情報は、現在の評価とスキップがすでに使用されているかどうかです。 同じスキップ ステータスで同じ評価で終了する 2 つの履歴は、将来のコンテストがこれら 2 つの値のみに依存するため、将来のすべての移行で交換可能です。 これにより、将来の進化はその状態にどのように到達したかに依存しないため、DP 最適下部構造が有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def apply(r, p, d):
    if d == 0:
        if r >= 2100:
            return r
    else:
        if r < 1900:
            return r

    diff = (p - r) // 4
    return r + diff

n, k = map(int, input().split())
p = list(map(int, input().split()))
d = list(map(int, input().split()))

dp0 = k
dp1 = k

for i in range(n):
    ni = apply(dp0, p[i], d[i])
    new_dp1_take = apply(dp1, p[i], d[i])

    new_dp1_skip = dp0

    dp0 = ni
    dp1 = max(new_dp1_take, new_dp1_skip)

ans = max(dp0, dp1)
print(k - ans)
```の`apply`関数は、コンテスト ルールを記載どおりにエンコードします。 まず、コンテストが現在のレーティングでアクティブであるかどうかを確認します。 そうでない場合は、評価を変更せずに返します。 それ以外の場合は、この範囲内でゼロに向かう切り捨てと一致する符号動作を持つ下限除算を使用して、整数切り捨て除算ルールが適用されます。 

保守します`dp0`スキップを使用しない場合の評価として、`dp1`これまでに最大 1 つのスキップが使用された場合に、可能な限り最高の評価として評価されます。 トランジションでは、現在のコンテストでスキップを消費するか、スキップを使用せずに続行するかを慎重に区別します。 

よくある間違いは、許可してしまうことです`dp1`すでにスキップを使用した後でもコンテストをスキップすること。 これにより、誤って複数の削除が許可されてしまいます。 もう 1 つの微妙な問題は、スキップ時の状態の混合です。スキップは常に、まだスキップを使用していない状態から行われなければなりません。`dp0`、 ない`dp1`。

 | 私 | p | d | dp0 前 | dp1 前 | dp0 後 | dp1 後 |

このトレースは、シーケンスをそのまま維持することで自然な軌道がすでに恩恵を受けているため、最適なパスではスキップが使用されていないことを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n)$| 各コンテストは一定時間の遷移で 1 回処理されます。 
| スペース |$O(1)$| 維持される実行状態は 2 つだけです。 

このソリューションは、最大で 1 回のリニア スキャンを実行するため、制約内に簡単に適合します。$10^5$ステップごとに一定の作業を伴うコンテスト。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from __main__ import solve
    out = solve()
    sys.stdin = old_stdin
    return str(out)

# We adapt solution into callable form
def solve():
    import sys
    input = sys.stdin.readline

    def apply(r, p, d):
        if d == 0:
            if r >= 2100:
                return r
        else:
            if r < 1900:
                return r
        return r + (p - r) // 4

    n, k = map(int, input().split())
    p = list(map(int, input().split()))
    d = list(map(int, input().split()))

    dp0 = k
    dp1 = k

    for i in range(n):
        new_dp0 = apply(dp0, p[i], d[i])
        new_dp1 = max(apply(dp1, p[i], d[i]), dp0)
        dp0, dp1 = new_dp0, new_dp1

    return k - max(dp0, dp1)

 ## 特殊なケース

 今後のコンテストがアクティブかどうかをスキップによって変更すると、厄介な状況が発生します。 たとえば、初期のコンテストをスキップすると、レーティングが 2100 未満に保たれる可能性があり、そうでなければブロックされるであろう後の div2 の獲得が可能になります。 DP はこれを正しく処理します。これは、両方の州が現在の格付けを明示的に引き継ぎ、将来のすべての決定が推測された履歴ではなく、その正確な格付けに基づいて計算されるためです。 

もう 1 つのエッジ ケースは、最適な戦略がスキップをまったく使用しない場合です。 これは自然に処理されるため、`dp1`スキップを完全に無視し、同じトランジションに従うオプションが常に含まれています。`dp0`、最後に両方の可能性が比較されるようにします。
