 ## 解決策
 ## 問題の理解

 文字列と固定長が与えられます$k$。 次の長さの連続する部分文字列を 1 つだけ削除する必要があります。$k$、残りのパーツを結合します。 これにより、次の長さの新しい文字列が生成されます。$|s| - k$。 削除されたセグメントのすべての可能な選択肢の中で、辞書編集的に最小の結果の文字列が必要です。 

重要な点は、削除位置によって文字列が構造化された方法で変更されるということです。削除されたブロックの前のすべてはその位置に留まり、ブロックが左にシフトした後のすべては$k$。 したがって、削除を選択するたびに、プレフィックスとサフィックスの異なる「スプライス」が定義されます。 

制約は全体として厳しいです。テスト ケース全体の文字列の合計長は最大です。$4 \cdot 10^5$したがって、すべての削除を試行し、完全な文字列を明示的に構築して比較するソリューションは、$O(n)$試行ごとに二次関数の動作に崩壊します。 平$O(n^2)$総作業量が大きすぎるため、本当の目標は、各候補の比較をほぼ一定時間または対数時間に短縮することです。 

削除位置を欲張って考えると、微妙な落とし穴が現れます。 結果のプレフィックス内の文字を局所的に最小化しても、全体的な最適性は保証されません。これは、削除が少し早くなったり遅くなったりすると、文字列のかなり奥まで配置が変更される可能性があるためです。 2 つの異なる削除が分岐する前に長いプレフィックスに一致する場合があり、その分岐によって答えが決まります。 したがって、正しい解決策では、削除の周囲だけでなく、結果の文字列全体を辞書編集的に比較する必要があります。 

もう 1 つのエッジ ケースは、最適な削除によって文字が最前面から削除される場合です。 一部の入力では、最初のブロックを削除し、文字列を効果的に左に積極的にシフトして、より小さい文字を早く露出させることが最適な戦略となります。 早期の削除を回避する単純なアプローチでは、これらのケースを完全に見逃してしまいます。 

## アプローチ

 直接的な総当たり戦略は、あらゆる可能な開始位置を試みます$a$、削除後に結果の文字列を構築します$s[a : a+k-1]$、すべての結果を比較します。 これはすべての有効な結果を明示的に評価するため正しいですが、遅すぎます。 1 つの候補文字列の構築にはコストがかかります$O(n)$、そして、あります$O(n)$の選択肢$a$、につながる$O(n^2)$最悪の場合のテスト ケースごとの作業量は、制限をはるかに超えています。$n$合計すると$4 \cdot 10^5$。 

重要な観察は、実際に各候補文字列を比較するために完全に実体化する必要がないということです。 各結果は、元の文字列の決定論的な再インデックス化にすぎません。プレフィックスまたはサフィックスから文字を取得し、単一のブロックされた間隔をスキップします。 このような 2 つの「仮想文字列」を効率的に比較できれば、すべての結果を構築しなくても最適な削除を検索できます。 

これにより、削除された間隔によって暗黙的に定義された多くの文字列を維持し、それらの 2 つの間の辞書編集的な比較をサポートするという問題が軽減されます。 このための自然なツールは、ハッシュと最初の異なる位置の二分探索を組み合わせたものです。 元の文字列のプレフィックス ハッシュを使用すると、任意の部分文字列ハッシュを定数時間で計算できます。結果の文字列の各部分文字列は、削除された 1 つのギャップにより、元の部分文字列の最大 2 つの部分文字列に対応します。 この構造は、任意の 2 つの候補を比較するのに十分です。$O(\log n)$、すべての削除位置の完全なスキャンが可能になります。$O(n \log n)$。

 ## アルゴリズムのチュートリアル

 考えられる削除開始をそれぞれ扱います$a$候補結果文字列を定義する場合$x_a$を連結したものです。$s[0:a)$そして$s[a+k:n)$。 私たちの仕事は、すべての中で辞書編集的に最小のものを見つけることです$x_a$。 

### ステップ

 1. 元の文字列のプレフィックス ハッシュと累乗を事前計算します。 

これにより、任意の部分文字列ハッシュを一定時間内にクエリできるようになり、高速比較の基礎となります。 
2. 候補文字列の任意の部分文字列のハッシュを計算するヘルパーを定義します。$x_a$。 

の部分文字列$x_a$プレフィックス部分内全体、サフィックス部分内全体、または両方にわたってマップされます。 交差の場合は、2 つの元の部分文字列に分割され、事前に計算されたべき乗を使用してそれらのハッシュが結合されます。 
3. 2 つの候補を比較する関数を定義する$x_a$そして$x_b$。 

最も長い共通プレフィックスの長さに対して二分検索を実行します。 各中間点で、次の対応する部分文字列のハッシュを比較します。$x_a$そして$x_b$。 これにより、その長さまで一致するかどうかが決まります。 
4. 最初の異なる位置が見つかったら、両方の候補のその位置にある文字を比較します。 

文字が小さい方が辞書順に小さくなります。 
5. すべての有効な削除位置を反復します。$a$、これまでに見つかった最高のものを維持します。 

新しい候補はそれぞれ、比較関数を使用して現在の最良の候補と比較され、より優れた候補が置き換えられます。 
6. すべての位置を処理した後、最良のプレフィックスとサフィックスを連結して最終的な答えを再構築します。$a$。 

### なぜ効果があるのか

 すべての候補文字列は 1 つの削除間隔によって完全に決定され、辞書編集上の順序は 2 つの候補間の最初の不一致のみに依存します。 ハッシュ構造により、あらゆるプレフィックスの同等性を効率的に検出できることが保証され、二分探索により、線形にスキャンすることなく最初の不一致を確実に特定できます。 正しい辞書編集上の比較の下で、これまでに見つかった最良の候補を常に保持するため、最終的に保存された削除位置は、結果としてグローバルに最小の文字列を生成する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Hash:
    def __init__(self, s, base=91138233, mod=10**9+7):
        self.mod = mod
        self.base = base
        n = len(s)
        self.pow = [1] * (n + 1)
        self.h = [0] * (n + 1)
        for i, c in enumerate(s):
            self.pow[i + 1] = (self.pow[i] * base) % mod
            self.h[i + 1] = (self.h[i] * base + (ord(c) - 96)) % mod

    def get(self, l, r):
        return (self.h[r] - self.h[l] * self.pow[r - l]) % self.mod

def solve():
    s, k = input().split()
    k = int(k)
    n = len(s)

    hs = Hash(s)

    def get_hash(l, r):
        return hs.get(l, r)

    def candidate_hash(a, l, r):
        # substring of x_a in [l, r)
        # maps to original string with gap [a, a+k)
        left_len = max(0, min(r, a) - l)
        h = 0

        if left_len > 0:
            h = (h * hs.base + get_hash(l, l + left_len)) % hs.mod

        if r > a:
            l2 = max(l, a)
            r2 = r
            if l2 < a + k:
                l2 = a + k
            if l2 < r2:
                h = (h * hs.base + get_hash(l2, r2)) % hs.mod

        return h

    def compare(a, b):
        lo, hi = 0, n - k
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if candidate_hash(a, 0, mid) == candidate_hash(b, 0, mid):
                lo = mid
            else:
                hi = mid - 1

        if lo == n - k:
            return 0

        ca = get_char(a, lo)
        cb = get_char(b, lo)
        return -1 if ca < cb else 1

    def get_char(a, i):
        if i < a:
            return s[i]
        return s[i + k]

    best = 0
    for a in range(n - k + 1):
        if compare(a, best) < 0:
            best = a

    res = s[:best] + s[best + k:]
    print(res)

t = int(input())
for _ in range(t):
    solve()
```このソリューションでは、元の文字列にハッシュ構造を構築して、部分文字列クエリが定数時間になるようにします。 各削除候補はインデックス マッピングを通じて暗黙的に表現されるため、比較中に中間文字列を構築することはありません。 

比較関数は、最初の不一致を見つけるために、応答の長さにわたる二分検索に依存します。 各ステップで、2 つの候補文字列のプレフィックス ハッシュを比較します。 分岐点が見つかったら、削除オフセットを使用して文字インデックスを元の文字列に直接マッピングして、分岐点を解決します。 

一般的な実装の落とし穴は、削除された間隔にわたる部分文字列マッピングの処理を誤ることです。 候補の部分文字列は最大でも 2 つの元のセグメントに分割される可能性があり、ギャップをまたぐときにインデックスの調整を忘れると、不正なハッシュ値や誤った比較が発生します。

 ## 特殊なケース

 微妙な特殊なケースは、すべての文字が同一である場合です。 すべての削除は同じ結果を生成するため、早期に停止して最適化を試みる実装では、誤って有効な候補をスキップしてはいけません。 すべてのプレフィックス ハッシュが一致し、最終的なタイブレーク ステップで自然に最初の候補が保持されるため、アルゴリズムは比較を正しく評価します。 

もう 1 つのケースは、最適な削除が文字列のプレフィックスと重なる場合です。 たとえば、最初の部分を削除すると、$k$文字。 インデックス マッピングにより、すべての比較でサフィックスがシフトされたものとして正しく扱われることが保証され、結果の文字列は位置 0 から始まる完全な候補として評価されます。 

3 番目のケースは次の場合です。$k = 1$ここで、すべての候補は削除された 1 文字だけ異なります。 ここでは、辞書編集構造の機密性が非常に高くなり、すべてのペアについて 1 文字ずつスキャンすることを避けるためにバイナリ検索の比較が不可欠になります。
