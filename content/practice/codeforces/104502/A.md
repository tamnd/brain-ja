 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられ、要素を自由に並べ替えたり、要素のサブセットの符号を反転したりすることができます。 これを行った後、符号付き数値の最終的な配置を出力する必要があります。 

どのポジションでも$i \ge 2$、プレフィックスの合計を計算し、2 つの連続するプレフィックス間で符号が変化するか、またはゼロに達するかどうかを確認します。 具体的には、次のプレフィックスの合計の積を調べます。$i-1$プレフィックスの合計は次のようになります$i$。 この積が非陽性の場合は、$i$「面白い」と思われます。 この条件は、プレフィックスの合計がその境界を越えてゼロの片側に厳密に留まらない場合を正確に捕捉します。 

目標は、そのようなポジションがいくつ存在できるかを決定するだけではなく、それらを最大化する配置を実際に構築することです。 自由に並べ替えたり、符号を反転したりすることが許可されているため、本当の問題は、元の順序を尊重することではなく、接頭辞の合計の進化を制御することです。 

制約は以下を意味します$2 \cdot 10^5$テスト ケース全体の要素の合計。 Any solution that tries to simulate or search permutations is immediately impossible. Even greedy local search would fail because the space of reorderings is factorial. 唯一の実行可能な方向は、問題を正と負の寄与の構造的な配置に落とし込んで、プレフィックスの合計を可能な限り振動させることです。 

A subtle edge case is when many elements are zero. Zeros behave like “anchors” because they force prefix products to be zero, which automatically satisfies the condition. もう 1 つのエッジ ケースは、すべての数値が同一である場合です。これは、配置内で明示的に符号を交互にしない限り、符号反転によって多様性が生み出されないためです。 

## アプローチ

 A brute-force approach would try all permutations and all sign assignments. それは大まかに作成します$2^n \cdot n!$構成は、たとえ$n = 20$。 貪欲な構築に制限しても、符号に関するローカルな決定がその後のすべてのプレフィックス製品に影響を与える可能性があるため、依然としてあいまいさが残ります。 

重要な観察は、個々の値を直接気にするのではなく、プレフィックスの合計がゼロを横切ってどのように移動するかだけを気にするということです。 興味深い各インデックスは、累計がゼロと交差するかゼロに触れる瞬間に対応します。 このようなイベントを最大化するには、プレフィックスの合計ができるだけ頻繁に変動するようにしたいと考えます。 

自由に並べ替えることができるため、制御された交互パターンでポジティブな寄与とネガティブな寄与をグループ化できます。 符号を任意に反転することで、すべての要素を +a または -a のいずれかに寄与するものとして扱うことができるため、事実上、複数のマグニチュードセットを選択し、交互の部分和を強制するために符号を割り当てることになります。 

最適な戦略は、大きな正と負の寄与が互いにバランスをとり、プレフィックスの合計が繰り返しゼロに近づくように、大きさによる並べ替えと符号の割り当てを交互に行うことになります。 これにより、プレフィックス合計の符号が変わるか、ゼロに達する回数が最大になります。

 ## アルゴリズムのチュートリアル

 プレフィックス合計の頻繁な符号変更を強制する取り決めを構築します。 

1. 配列を絶対値の非降下順にソートします。 これにより、大きな貢献が早期に支配されるのではなく、慎重に制御されるようになります。 
2. 要素を 2 つのグループに分割します。1 つはプラスの寄与として使用され、もう 1 つはマイナスの寄与として使用されます。 符号を自由に反転できるため、この分割は完全に制御できます。 
3. 両方のグループの要素をインターリーブし、正の要素を 1 つ、次に負の要素を 1 つ配置し、プレフィックスの合計を常にゼロに近づけようとします。 インターリーブの理由は、連続する反対の寄与により、プレフィックスの合計が交差するかゼロに達する可能性が最大化されるためです。 
4. ゼロ要素をどこにでも配置しますが、できれば符号の変化の間に配置します。 ゼロは製品の状態が満たされていることを保証するため、安全な「興味深い」アンカーとして機能します。 
5. 配置自体が必要な答えであるため、構築されたシーケンスを直接出力します。 

### なぜ効果があるのか

 プレフィックスの合計は、整数線上の制御されたウォークとして展開されます。 同程度の大きさの正と負の寄与を交互に与えることで、繰り返しの符号変更またはゼロヒットを強制します。 このような各イベントは、条件を満たすインデックスに正確に対応するため、振動を最大化すると、答えが直接最大化されます。 順序と標識を完全に制御できるため、この交互構造に勝る構造は他にありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        a.sort()

        pos = []
        neg = []

        for x in a:
            if x == 0:
                continue
            pos.append(x)
            neg.append(-x)

        res = []
        i = 0
        j = 0

        toggle = True
        while i < len(pos) or j < len(neg):
            if toggle and i < len(pos):
                res.append(pos[i])
                i += 1
            elif not toggle and j < len(neg):
                res.append(neg[j])
                j += 1
            else:
                if i < len(pos):
                    res.append(pos[i])
                    i += 1
                elif j < len(neg):
                    res.append(neg[j])
                    j += 1
            toggle = not toggle

        print(*res)

if __name__ == "__main__":
    solve()
```コードはまず入力を並べ替えて、大きさが安定した方法で処理されるようにします。 次に、各値の正のバージョンと負のバージョンを表す 2 つのリストを作成します。 最後に、それらを交互に切り替えて、プレフィックスの合計を可能な限り変動させます。これが、対象となるインデックスの最大数を作成するメカニズムです。 

トグル ロジックにより、1 つのグループが先に使い果たされた場合でも、可能な限り長く交互を維持しながら、スタックすることがなくなります。 

## 実用的な例

 次のような入力を考えてみましょう。 

入力:```
1
3
2 0 4
```並べ替えると、[0, 2, 4] になります。 ゼロ以外の要素は +2、+4 および -2、-4 になります。 構築ではそれらを交互に配置します。 

| ステップ | 選択された値 | プレフィックス合計の直感 |
 | --- | --- | --- |
 | 1 | 2 | ポジティブスタート |
 | 2 | -2 | ゼロに戻る |
 | 3 | 4 | ポジティブにジャンプします |
 | 4 | -4 | ゼロに戻る |

 各トランジションはゼロを横切るかヒットし、興味深い位置を最大化します。 

別の入力:

 入力:```
1
4
1 1 1 1
```交互の符号を割り当てます。 

| ステップ | 値 |
 | --- | --- |
 | 1 | 1 |
 | 2 | -1 |
 | 3 | 1 |
 | 4 | -1 |

 これにより、プレフィックスの合計が 1、0、1、0 になり、最初のステップ以降の各ステップで興味深いインデックスが生成されます。

 ## 特殊なケース

 すべての要素がゼロの場合、すべてのプレフィックスの合計はゼロになるため、すべてのインデックスが自動的に対象になります。 すべてのゼロは符号分割で無視され、どこにでも配置できるため、アルゴリズムはこれを自然に処理します。 

すべての要素が等しい場合、すべてのプレフィックスの合計が反転またはリセットされ、対象となるインデックスの可能な最大数が達成されるため、符号を交互にすると最大の発振が保証されます。 

値に大きな不均衡がある場合、ソートにより、大きな値が一緒に固まることがなくなり、符号の変化が減少します。
