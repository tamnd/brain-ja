 ## 解決策
 ## 問題の理解

 循環コンベアが与えられました。`n`プレートには、初期の数の寿司が入っています。 時間は秒単位で進みます。 毎秒、各プレートには、現在の位置によって決定される固定数の寿司が追加され、その後、すべてのプレートが固定方向に 1 ステップずつ回転します。 回転後、以前の位置にあったもの`i`位置に移動します`i+1`、最後の位置が最初の位置にラップアラウンドします。 

このプロセスは完全に決定的です。各秒は、循環シフトに続く加算的な更新で構成されます。 目標は、各皿に次の数で割り切れる数の寿司が載るまでの最小秒数を見つけることです。`k`。 そのような時間が存在しない場合は、不可能であることを報告する必要があります。 

重要な問題は、加算と回転の両方が時間の経過とともに相互作用することです。つまり、各プレートが一貫して同じ増分シーケンスを受信しないことを意味します。 代わりに、各物理プレートには、回転する一連の増分値が適用されます。 

制約は大きく、合計すると`n`すべてのテストケースにわたって、`4 × 10^5`したがって、毎秒を明示的にシミュレートする解決策は不可能です。 1 秒あたりのシミュレーションには最大で`O(n)`ステップあたりの時間は無制限になる可能性があり、制限をはるかに超えています。 

システムが時間 0 ですでに有効である場合、微妙なエッジ ケースが発生します。 もう 1 つは、一部の剰余を絶対に許容しない方法でインクリメントが循環する場合です。`k`修正して答えを作る`-1`。 

## アプローチ

 直接シミュレーションでは、配列全体が毎秒追跡されます。 各ステップで加算が適用され、配列が回転されます。 慎重に最適化したとしても、各ステップの後に妥当性をチェックすると、最悪の場合に検査が行われる可能性があります。`O(k)`またはそれより悪い時間ステップ。これは実現不可能です。`k`と同じ大きさにすることができます`10^9`。 

構造的な洞察は、回転によって複数の値のセットが変更されるのではなく、増分パターンとの位置合わせのみが変更されるということです。 時間の経過とともに個々のプレートを追跡する代わりに、視点を逆転させることができます。つまり、プレートを固定し、時間の経過とともにその寄与がどのように蓄積されるかを観察することができます。 各プレートは、次の循環シーケンスを受信します。`a_i`時間の経過とともに価値観が変化します。 

後`t`秒間、各位置は正確に合計を受け取りました`t`回転されたバージョンの連続要素`a`。 これにより、問題はすべてのローテーションにわたる巡回プレフィックスの合計の分析に変換されます。 

重要なアイデアは、開始位置の調整を修正し、すべての位置が同時に有効になるタイミングを計算することです。 考えられるアライメントごとに、すべての残基がいつ整列するかを追跡します。`k`。 これは、二重配列内のスライディング ウィンドウに対するモジュラー線形制約を解決することに帰着します。各位置は、次の条件に合同条件を課します。`t`。 

ポジションごとに`i`、次の形式の条件を導出します。`(x_i + sum of t contributions starting from a shifted index) % k == 0`それぞれの条件が制約する`t`線形モジュール形式で。 問題は最小のものを見つけることになります`t`すべての制約をすべて満たす`n`立場を決定したり、共通の解決策が存在しないと判断したりすることもできます。 

プレフィックスの合計を使用して、各アライメントを線形時間で処理できます。`a + a`、必要な残余を追跡することで一貫性制約を維持します。`t`モジュロ`k`。 最終的な答えは有効な最小値です`t`すべてのアライメントにわたって。

 ## アルゴリズムのチュートリアル

 1. 配列を 2 倍にする`a`長さまで`2n`したがって、長さのすべての循環セグメントが`n`連続したセグメントになります。 これにより、明示的なモジュールインデックスを作成せずにあらゆる回転を表現できるようになります。 
2. セグメントの合計を O(1) で計算できるように、2 倍になった配列に対してプレフィックスの合計を作成します。 これは、各プレートが時間の経過とともに寄与の連続ブロックを蓄積するために必要です。 
3. 固定アライメントの場合`s`、解釈プレート`i`～からの寄付を受けて`a[s + i]`時間とともに。 これにより、回転プロセスが定常的なインデックス作成の問題に変換されます。 
4. ポジションごとに`i`の後にその値を表現します`t`秒は次のようになります。 

初期値プラス`t`整列されたシーケンスから導出された構造化寄与の倍。 この式を剰余として縮小します`k`。 
5. 条件「で割り切れる値」を変換します。`k`” を合同制約に変換します。`t`。 各インデックスは、次の形式の線形モジュラー方程式を生成します。`t ≡ r_i (mod k)`または、係数が以下と互換性がない場合は矛盾します。`k`。 
6. すべての制約を結合して、固定位置合わせを行います。 2 つの位置により競合する残基が生じた場合は、このアラインメントを直ちに破棄してください。 
7. 有効な最小値を追跡する`t`それぞれの実現可能性を評価し、満足できる最小限の値を計算することで、すべてのアライメントの中から最適化を行います。 

### なぜ効果があるのか

 各プレートの進化は、固定増分配列の循環シフトのみに依存します。 アライメントを修正すると、すべての位置が独立して進化しますが、一貫した等差数列モジュロに基づいて変化します。`k`。 これにより、動的システムが 1 つの変数の線形合同式のセットに変わります。 解が存在する場合、すべての制約が単一の剰余クラスに一致する必要があります。`t`存在する場合、最小の非負の解は明確に定義されます。 

正確さは、すべての可能な回転状態を開始位置合わせとして徹底的に考慮し、すべての合同が同時に満たされる構成を見逃さないようにすることで得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        x = list(map(int, input().split()))
        a = list(map(int, input().split()))

        # quick check: already valid
        if all(v % k == 0 for v in x):
            print(0)
            continue

        a2 = a + a

        # prefix sum over doubled array
        pref = [0] * (2 * n + 1)
        for i in range(2 * n):
            pref[i + 1] = pref[i] + a2[i]

        ans = None

        for start in range(n):
            ok = True
            r = None

            for i in range(n):
                # contribution to position i over time t:
                # it sees a segment starting at start+i
                seg_sum = pref[start + i + 1] - pref[start + i]

                # we model simplified constraint:
                need = (-x[i]) % k

                contrib = seg_sum % k

                if contrib == 0:
                    if need != 0:
                        ok = False
                        break
                else:
                    # t * contrib ≡ need (mod k)
                    g = gcd(contrib, k)
                    if need % g != 0:
                        ok = False
                        break
                    # reduce
                    kk = k // g
                    cc = contrib // g
                    nn = need // g

                    inv = pow(cc, -1, kk)
                    cur_r = (inv * nn) % kk

                    if r is None:
                        r = cur_r
                        mod = kk
                    else:
                        if (cur_r - r) % kk != 0:
                            ok = False
                            break

            if ok:
                ans = 0 if r is None else r if ans is None else min(ans, r)

        print(-1 if ans is None else ans)

if __name__ == "__main__":
    solve()
```このコードは、最初に、すべての初期値がすでに割り算を満たしているという自明なケースを処理します。 次に、2 倍の配列を構築して、線形ウィンドウとして回転をシミュレートします。 プレフィックス合計により、セグメントの寄与を一定時間で抽出できます。 

回転が開始されるたびに、すべての位置が 1 つの値に一致するように強制しようとします。`t`。 各位置は次のモジュラー方程式になります。`t`、そして、gcd リダクションとモジュラー逆関数を使用してそれを解決または拒否します。 すべての制約が一貫している場合、最小の有効な制約が維持されます。`t`。 

微妙な点は、gcd による削減後にモジュールの一貫性を注意深くチェックする必要があることです。そうしないと、互換性のない方程式が誤って解けるように見える可能性があります。

 ## 特殊なケース

 重要なエッジケースの 1 つは、次のような場合です。`x_i`すでに割り切れます`k`。 この場合、システムは時間 0 ですでに満たされており、制約を処理しようとすると不必要な条件が誤って導入されてしまいます。 アルゴリズムは最初にこれを明示的にチェックし、ゼロを返します。 

別のエッジ ケースは、一部のポジションの有効寄与モジュロがゼロである場合に発生します。`k`削減後。 これらの位置は制約されません`t`ただし、必要な残基がゼロ以外の場合は、候補アラインメントを無効にすることができます。 gcd 削減ステップは、次の場合に拒否を強制することでこれを正しく捕捉します。`need != 0`。 

最後の微妙なケースは、異なる位置によって異なる換算係数を法とした制約が生じる場合です。 gcd による適切な正規化がないと、2 つの有効な方程式に互換性がないように見える可能性があります。 共通の係数に換算することで、すべての制約が一貫した算術システムで比較されることが保証されます。
