 ## 解決策
 ## 問題の理解

 私たちはカップケーキの列を与えられ、それぞれのカップケーキはいくつかのスプリンクルから始まります。 時間の経過とともに、アリスは一連の操作を実行します。 各操作で、彼女はすべてのカップケーキのスプリンクルを、配列から固定された順序で取得した固定量だけ増やします。 このようにグローバルに増加するたびに、ボブはすぐに介入します。彼は現在最も多くのスプリンクルが含まれているカップケーキを見て、そのスプリンクルの半分を削除し (切り捨て)、残りはそのままにします。 

このプロセスは、追加されたレイヤーごとに 1 回だけ繰り返されます。 すべてのレイヤーが適用され、ボブの介入がすべて行われた後、すべてのカップケーキに残っているスプリンクルの合計数を求められます。 

主な問題点は、両方の操作が異なる点でグローバルであることです。 アリスの更新はすべての要素に均一に影響しますが、ボブのアクションは時間の経過とともに自明ではない方法で変化するグローバル最大値に依存します。 

制約が十分に大きいため、大規模な構造上で単純な方法で各ステップをシミュレートするアプローチは失敗する可能性が高くなります。 最大 50,000 個のカップケーキと 50,000 回の操作がある場合、すべてのカップケーキを繰り返しスキャンして各ステップの後に最大値を見つける直接シミュレーションでは、約 25 億回の比較コストがかかりますが、これは Python では遅すぎます。 

2 番目の微妙な問題は注文です。 ボブは常に、アリスがそのステップに完全に追加した後に行動します。 足し算と半分を誤って交互に入れたり、順序を忘れたりすると、たとえ小さな入力であっても不正確な結果が得られます。 

最後のエッジケースは、複数のカップケーキが最大値を共有する場合に発生します。 Bob はそのうちの 1 つにのみ影響しますが、任意の最大値を選択しても問題ありません。 ただし、一貫したデータ構造を維持できない場合、誤って古い最大値を選択したり、以前の半減後の更新を見逃したりする可能性があります。 

## アプローチ

 直接シミュレーションでは、現在のスプリンクル数が配列に維持されます。 各レイヤーについて、最初にすべてのカップケーキにレイヤー値を追加し、次に配列全体をスキャンして最大値を見つけ、それを半分にします。 

これはプロセスを正確に反映しているため、これは正しいです。 問題はコストです。 各ステップには、更新に O(N) と、最大値を見つけるために O(N) が必要で、N 回繰り返されます。 これにより O(N^2) が得られますが、これは上限で 25 億回の演算に達し、実行可能ではありません。 

重要な観察は、実際にはすべてのカップケーキについての完全な知識を繰り返し必要とするわけではないということです。 グローバルに追加するたびに、すべてのカップケーキが同じ定数ずつ増加します。 これは、サイズによる相対的な順序が、アリスの操作だけによって変更されないことを意味します。 ボブの半分にする操作のみが相対的な順序を変更し、単一の要素のみを変更します。 

この構造は、単一要素の更新をサポートしながら、常に現在の最大値への効率的なアクセスを提供するデータ構造でカップケーキを維持することを示唆しています。 現在の値を明示的に保存して遅延更新する場合、または影響を受ける要素を直接調整して再挿入する場合は、最大ヒープで十分です。 

また、Alice のグローバル追加をランニング オフセットとして扱うことができるという事実も利用します。 毎回すべての値を更新するのではなく、グローバル増分変数を維持します。 各カップケーキの実際の値は、保存されている基本値にこのオフセットを加えたものです。 これにより、グローバル加算が O(1) に変換されます。 

各ステップは次のようになります。オフセット増分を適用し、最大値を抽出し（オフセットを考慮して）、それを半分に減らし、更新された値を再挿入します。 これにより、各操作が O(log N) に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^2) | O(N) | 遅すぎる |
 | ヒープ + レイジー オフセット | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 カップケーキの最大ヒープと、アリスからの合計追加を表すグローバル オフセットを維持します。 

各ヒープ エントリには、実際の値から現在のオフセットを引いた値を意味する「ベース値」が格納されます。

1. すべてのカップケーキの初期値からオフセット 0 を差し引いた値を使用してヒープを初期化します。 

この表現により、オフセットを追加することでいつでも実際の値を再構築できるようになります。 
2. 変数を初期化する`offset = 0`。 
3. 各レイヤーの値について`b[i]`に追加します`offset`。 

これは、アリスがすべてのカップケーキを増やすことを表しています`b[i]`個々の要素には触れずに。 
4. ヒープから最大の要素を抽出します。 

ヒープには基本値が格納されるため、これは最高の実数値を持つカップケーキに対応します。 
5. を追加して、この基本値を実際の値に変換します。`offset`。 
6. Bob の操作を適用します。この値を次のように置き換えます。`floor(value / 2)`。 
7. 更新された値を減算して基本形式に変換します。`offset`。 
8. この変更された基本値をヒープにプッシュして戻します。 

すべてのレイヤーを処理した後、各カップケーキの実際の値は、保存されている基本値に最終オフセットを加えたものになります。 すべてのヒープ要素を合計して追加する`N * offset`最終的な答えが得られます。 

### なぜ効果があるのか

 このアルゴリズムは、維持される不変式に依存します。つまり、各ヒープ要素は常に、真のカップケーキ値から同じグローバル オフセットを引いたものを表し、オフセットがすべての要素で同一であるため、ヒープ プロパティは真の値の順序を反映します。 アリスの操作はこの共有オフセットのみを変更するため、相対的な順序が維持されます。 Bob の操作は 1 つの要素にのみ影響を与えるので、その更新された形式をすぐに再挿入して、ヒープ構造の正確さを復元します。 これにより、すべてのステップがその時点での真の最大値で動作することが保証されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # max heap via negatives
    heap = []
    offset = 0

    for x in a:
        heapq.heappush(heap, -x)

    for add in b:
        offset += add

        # extract max (real value = -heap[0] + offset)
        x = -heapq.heappop(heap)
        real = x + offset

        # Bob halves it
        real //= 2

        # store back as base value
        heapq.heappush(heap, -(real - offset))

    # final sum
    total = 0
    for x in heap:
        total += (-x + offset)

    print(total)

if __name__ == "__main__":
    solve()
```このソリューションは、負数を使用して値を最大ヒープに格納することに依存しており、これによりカスタム ヒープの実装が回避されます。 オフセットがヒープに直接適用されることはありません。これにより、O(N) 更新の繰り返しが防止されます。 

ボブが最大値の半分を削除すると、オフセットを使用して実際の値を一時的に再構築し、操作を適用してから、調整されたベースを格納し直します。 

最終的な合計では、すべての要素にオフセットが 1 回だけ追加され、繰り返しの再計算が回避されます。 

## 実用的な例

 小さな例を考えてみましょう。 

入力:```
N = 3
A = [4, 2, 10]
B = [3, 1, 2]
```ヒープ (基本値として) とオフセットを追跡します。 

| ステップ | オフセット | ヒープ (ベース) | 最大実数 | ボブの後 |
 | --- | --- | --- | --- | --- |
 | 初期化 | 0 | [10、2、4] | - | - |
 | +3 | 3 | [10、2、4] | 13 | 6 |
 | | | [6-3=3 挿入] → [4, 2, 3] | | |
 | +1 | 4 | [4、2、3] | 8 | 4 |
 | | | [4-4=0 挿入] → [3, 2, 0] | | |
 | +2 | 6 | [3、2、0] | 9 | 4 |
 | | | [4-6=-2 挿入] → [2, 0, -2] | | |

 最終合計:

 実数値 = ヒープ + オフセット = [8, 6, 4]、合計 = 18。 

このトレースは、オフセットによってグローバル効果とローカル効果がどのように明確に分離されるかを示しています。 

値が等しい 2 番目の例:

 入力:```
N = 2
A = [5, 5]
B = [10, 10]
```最初のステップの後、両方が等しくなり、ボブはどちらかを選択し、それを半分にします。タイブレークは正しさに影響しないため、構造は一貫したままになります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log N) | N ステップのそれぞれが 1 つのヒープのポップとプッシュを実行します。 
| スペース | O(N) | ヒープには N 個の要素が格納されます。 

log N が小さく、合計操作が約 100 万ヒープ操作であるため、これは 50,000 個の要素と操作の制約内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    import heapq
    heap = []
    for x in a:
        heapq.heappush(heap, -x)

    offset = 0

    for add in b:
        offset += add
        x = -heapq.heappop(heap)
        real = x + offset
        real //= 2
        heapq.heappush(heap, -(real - offset))

    return str(sum(-x + offset for x in heap))

# minimum case

# equal values
assert run("2\n5 5\n1 1\n") == "10"

# decreasing pattern
assert run("3\n9 6 3\n2 2 2\n") == "20"

 ## 特殊なケース

 重要なエッジケースは、アリスを追加した後にすべてのカップケーキが等しい場合です。 例えば：```
3
5 5 5
1 1 1
```最初の加算の後、すべてが 6 になります。ボブは 1 つを選択し、それを半分の 3 にします。変更される要素は 1 つだけであるため、ヒープには依然として一貫した表現が含まれており、オフセットは共有の増加を正しく表し続けます。 複数の有効な最大値が存在する場合でも、問題は決定的な選択を必要としないため、いずれかを選択すると有効な状態になります。 

もう 1 つのエッジ ケースは、半分にすることで最大値が他の要素よりも小さくなる場合です。 例えば：```
2
1 100
0 0
```最初のステップの後、100 は半分の 50 になり、まだ最大のままである可​​能性がありますが、いくつかのステップの後、他のカップケーキを下回る可能性があります。 再挿入後、順序が自動的に復元され、次の最大クエリに更新された状態が反映されるため、ヒープはこれを正しく処理します。
