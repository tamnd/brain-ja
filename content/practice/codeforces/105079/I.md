 ## 解決策
 ## 問題の理解

 私たちは、各セルが工場内のさまざまな種類の地形を表すグリッドに取り組んでいます。 サリーは左上隅から開始して、右下隅に到達したいと考えています。 グリッドには、オープン セル、動きを妨げる壁、彼女を強制的に移動させる方向性のあるコンベア ベルト、および時間をかけずにすべてのコンベアをグローバルにオンまたはオフに切り替える特別なスイッチ セルが含まれています。 

動きは均一ではありません。 サリーが隣接するセルに自由に移動すると、2 秒かかります。 彼女がアクティブなコンベアの上に立っている場合、彼女はコンベアの方向に移動することを強制され、その強制的な移動には 1 ステップあたり 1 秒かかります。 重要な問題は、スイッチがすべてのコンベアのグローバルな状態を変更し、強制的な移動が適用されるかどうか、または方向を自由に選択できるかどうかが変化することです。 

したがって、タスクは、エッジの重みが位置だけでなく、コンベアのオンまたはオフといったグローバルなバイナリ状態にも依存するグラフの開始から終了までの最短時間パスを計算することです。 

この制約により、すべてのテスト ケースにわたって合計最大 10^6 セルにわたる最短パス アルゴリズムが実現されます。 各セルを均一コストのノードとして扱う単純な BFS は、エッジの重みが 1 と 2 であるため、すぐに失敗します。各位置がグローバル スイッチ状態と相互作用するため、状態サイズを注意深く制御しない限り、生のグリッド状態に対するダイクストラでも十分ではありません。 

微妙だが重要なエッジ ケースがコンベヤ チェーンから発生します。 コンベアが作動している場合、サリーは選択の余地なく複数のセルを強制的に通過する可能性があります。 これらの移動のいずれかが壁や境界に当たると、そのパス全体が無効になります。 個々のエッジのみをチェックする単純な最短パスでは、中間の無効な強制遷移が誤って許可される可能性があります。 

もう 1 つのエッジケースはスイッチの使用です。 「スイッチに入るときは常にコンベアをオフにする」などの貪欲な戦略は失敗します。なぜなら、コンベアに 1 秒移動の長くて安い経路を通ってサリーを運ぶことが最適な場合があるからです。 

## アプローチ

 重みを無視すると、グリッド セルに対して単純な BFS を試みることができます。 これにより、各移動が等しいコストとして扱われ、階層的に拡張されます。 ただし、グリッドには 2 つの異なるコスト 1 と 2 が含まれており、すでに BFS の正確性が損なわれています。 

より慎重な強引なアイデアは、各状態を位置とコンベアのステータスで構成されるペアとして扱い、ダイクストラを実行することです。 各状態からスイッチの切り替えを考慮し、自由またはコンベアを介した動きをシミュレートします。 問題は、コンベアの動きの単純なシミュレーションでは、緩和ごとに O(nm) になる可能性がある長いセルのチェーンを繰り返し通過する可能性があることです。 最悪の場合、これは O((nm)^2) にまで縮退し、遅すぎます。 

重要な観察は、グローバル状態はコンベアがオフかオンかの 2 値のみであるということです。 つまり、各セルには最大でも 2 つの意味のある状態があります。 実際の構造は階層化されたグラフです。すべてのセルは 2 回存在し、遷移はオンレイヤーにいるかオフレイヤーにいるかによって異なります。 

これを受け入れると、移動は最大 2 * nm ノードを持つグラフ上の標準的な最短経路になりますが、エッジは圧縮される可能性があります。 自由移動のコストは 2 です。コンベア強制移動のコストは 1 で、方向は決定的です。 スイッチ セルは 2 つの層をコスト 0 で接続します。 

残る唯一の困難は、コンベヤチェーンを効率的に扱うことです。 セルごとにステップ実行する代わりに、動きが停止するか無効になる安定したセルに到達するまでコンベアを繰り返したどった結果を事前計算します。 これにより、長いチェーンを繰り返し歩くのではなく、各状態の展開を方向ごとに O(1) にすることができます。 

これにより、問題は、状態ごとに小さな一定次数をもつスパース グラフ上の最短経路になり、0-1-2 ダイクストラまたは優先キューを使用した標準ダイクストラで解決できます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ステート シミュレーション | O((nm)^2) | O(nm) | 遅すぎる |
 | 階層化グラフ + 圧縮を使用したダイクストラ | O(nm log(nm)) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各グリッド セルを 2 つの状態としてモデル化します。1 つはコンベアがオフになっている状態、もう 1 つはコンベアがオンになっている状態です。 これにより、システム内の唯一のグローバル変数がキャプチャされます。 
2. 状態間の遷移を構築します。 サリーは、オフ状態のセルから、コスト 2 の隣接する非壁セルに移動できます。また、現在のセルがスイッチである場合、コスト 0 のオン状態の同じセルに遷移することもできます。同じロジックがオン状態でも対称的に適用されます。 
3. 決定的な次の位置関数を定義することにより、オン状態でのコンベアの動作を処理します。 任意のセルから、チェーンが停止するセルに到達するまで、コンベアの方向が存在しアクティブである間、その方向に繰り返し従います。 チェーンがグリッドの外側または壁につながっている場合、その遷移は破棄されます。 
4. コンベヤに続くチェーンをすべてダイレクトエッジに交換します。 オン状態のセルから、1 つずつステップするのではなく、チェーン内のステップ数に等しい単一のコスト エッジを最終の有効なエンドポイントに追加します。 
5. 最初はすべてのコンベアがオフであるため、ダイクストラを (0, 0, off) から開始して実行します。 2 層グラフ上の距離を維持します。 
6. 答えは、宛先セルにおける両方の状態間の最小距離です。 

正確さは、コンベア チェーンをアトミックな遷移として扱うことと、唯一のグローバル状態を明示的に表すことから得られます。 元のプロセスの有効な動作シーケンスはすべて、このグラフの 1 つのパスに正確に対応します。また、その逆も同様です。これは、強制されたすべての動作が決定的であり、すべてのトグルが明示的に表現されているためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

INF = 10**18

dirs = {
    '>': (0, 1),
    '<': (0, -1),
    '^': (-1, 0),
    'v': (1, 0)
}

def solve(n, m, grid):
    def id(x, y, s):
        return (x * m + y) * 2 + s

    N = n * m * 2
    dist = [INF] * N
    dist[id(0, 0, 0)] = 0
    pq = [(0, 0, 0, 0)]  # dist, x, y, state

    def inside(x, y):
        return 0 <= x < n and 0 <= y < m

    def conveyor_sink(x, y):
        cx, cy = x, y
        steps = 0
        while True:
            c = grid[cx][cy]
            if c not in dirs:
                return cx, cy, steps
            dx, dy = dirs[c]
            nx, ny = cx + dx, cy + dy
            if not inside(nx, ny) or grid[nx][ny] == '#':
                return -1, -1, -1
            cx, cy = nx, ny
            steps += 1

    while pq:
        d, x, y, s = heapq.heappop(pq)
        if d != dist[id(x, y, s)]:
            continue

        idx = id(x, y, s)

        if grid[x][y] == '!':
            ns = 1 - s
            nid = id(x, y, ns)
            if dist[nid] > d:
                dist[nid] = d
                heapq.heappush(pq, (d, x, y, ns))

        if s == 0:
            for dx, dy in [(1,0), (-1,0), (0,1), (0,-1)]:
                nx, ny = x + dx, y + dy
                if not inside(nx, ny) or grid[nx][ny] == '#':
                    continue
                nid = id(nx, ny, 0)
                if dist[nid] > d + 2:
                    dist[nid] = d + 2
                    heapq.heappush(pq, (d + 2, nx, ny, 0))
        else:
            tx, ty, cost = conveyor_sink(x, y)
            if tx != -1:
                nid = id(tx, ty, 1)
                nd = d + cost
                if dist[nid] > nd:
                    dist[nid] = nd
                    heapq.heappush(pq, (nd, tx, ty, 1))

    tx, ty = n - 1, m - 1
    return min(dist[id(tx, ty, 0)], dist[id(tx, ty, 1)])

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    print(solve(n, m, grid))
```コア構造は、2 倍の状態空間上の標準ダイクストラです。 インデックス機能は、位置とコンベアの状態の両方を単一の整数にエンコードします。 優先キューにより、常に既知の最小距離状態が最初に拡張されます。 

機能`conveyor_sink`重要な最適化です。 強制的な動きシーケンス全体を 1 つのトランジションにまとめます。 コンベヤーのないセルに到達するか、壁や境界によって失敗するまで歩き続けます。 ステップ数がその移行のコストになります。 

スイッチ処理は、状態ビットを反転するゼロコスト エッジとして実装されます。 自由な移動はコンベアがオフの場合にのみ許可され、強制移動はコンベアがオンの場合にのみ適用されるというルールと一致します。 

## 実用的な例

 コンベア チェーンがオン状態で存在し、出口に直接つながっている単純なグリッドを考えてみましょう。 

単一のテストケースをトレースします。 

| ステップ | ポジション | 状態 | アクション | コスト |
 | --- | --- | --- | --- | --- |
 | 1 | (0,0) | オフ | 開始 | 0 |
 | 2 | (0,0) | に | スイッチでトグル | 0 |
 | 3 | (0,0) | に | コンベアシンクから出口まで | +k |

 これは、単一のトグルで中間決定をバイパスする決定論的な強制パスを有効にする方法を示しています。 

2 番目の例では、自由移動を使用します。 

| ステップ | ポジション | 状態 | アクション | コスト |
 | --- | --- | --- | --- | --- |
 | 1 | (0,0) | オフ | 開始 | 0 |
 | 2 | (0,1) | オフ | 右に移動 | +2 |
 | 3 | (1,1) | オフ | 下に移動 | +2 |

 これは、自由な移動が一貫して重み付けされており、将来の状態の変化とは無関係であることを示しています。

 ## 特殊なケース

 重大なエッジ ケースは、コンベヤ チェーンが途中で壁にぶつかる場合です。 このような場合、シンク関数は無効を返し、その遷移全体がグラフから削除されます。 壁に向かって右に動くコンベアのような入力の場合、アルゴリズムはその状態からエッジを追加することはありません。これにより、ダイクストラが不可能な強制パスを探索することができなくなります。 

もう 1 つのケースは、複数のトグルを連続して必要とする交互スイッチです。 各スイッチ エッジのコストはゼロであるため、アルゴリズムはペナルティなしで異なる状態で同じセルを再訪できます。 正確さは、状態をノードの一部として扱い、再訪が単層グラフのサイクルと混同されないようにすることから生まれます。
