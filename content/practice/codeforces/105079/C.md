 ## 解決策
 ## 問題の理解

 原点を中心とする円形の「ベース」領域と、その上に配置されたいくつかの追加の円形領域を使用して作業しています。 このタスクは、基本円の内側にあり、少なくとも 1 つのつや消し円によって覆われている格子点 (両方の座標が整数の点を意味する) がいくつあるかを数えるということです。 

各フロスティング サークルは、その半径と中心によって表されます。 格子点は、カップケーキの境界内にあり、同時に少なくとも 1 つのつや消し円内にある場合にのみ、答えに寄与します。 出力は単一の整数、つまりそのような整数座標点の総数です。 

制約は小さく、円の数とすべての座標の大きさは両方とも最大 50 です。これにより、洗練された幾何学的データ構造の必要性が即座に排除されます。 関連するすべての整数点を直接列挙することが可能です。 パフォーマンスに関する唯一の意味のある考慮事項は、半径 50 の円内に整数点がいくつ存在するかです。これは数千のオーダーです。 

ここでの単純な間違いは、サイズ 101 × 101 の正方形の境界ボックスを反復処理し、最初に基本円でフィルター処理することを忘れたことです。 それはまだ正しいのですが、さらに微妙な間違いは、浮動小数点距離をチェックして精度の問題が発生することです。 すべての座標は整数であり、二乗距離は安全な整数の範囲内に収まるため、すべてを整数演算を使用して実行する必要があります。 

エッジケースはほとんどが幾何学的境界条件です。 

コーナーケースの 1 つは、基本円の完全に外側にあるつや消し円です。 たとえば、つや消しの中心が (100, 100) にある場合、それは何も寄与しないため、アルゴリズムは、不適切な境界ボックスの処理により誤って点を含めてはいけません。 

もう 1 つのケースはフルカバレッジです。つまり、ベース円を完全に含むつや消し円です。 この場合、答えは基本円自体の整数点の数である必要があり、正しい解決策では、複数の円が重なっている場合でも二重カウントを回避する必要があります。 

最後の微妙なケースは、境界上にある点です。 つや消し円について、x² + y² ≤ R² または x² + y² ≤ r_i² の場合、点 (x, y) が含まれる必要があります。 平等条件が重要です。 

## アプローチ

 ブルートフォースのアイデアは簡単です。基本円内にある可能性のあるすべての整数点を反復処理し、それが基本円内にあるかどうかを確認し、次にそれが少なくとも 1 つの曇り円内にあるかどうかを確認して、それを数えます。 

基本円の半径は最大 50 であるため、境界正方形は最大でも 101 × 101、つまり約 10,000 個の候補点になります。 各点について、N 個の円をすべてチェックするには O(N) のコストがかかります。 これにより、およそ 10,000 × 50 = 500,000 回の距離チェックが行われ、これは Python ではすでに許容されています。 

ただし、より明確に構造化することもできます。正方形をスキャンする代わりに、基本円内の点のみをスキャンします。 これにより、反復がさらに減り、ロジックが簡素化されます。 

制約は意図的に小さいため、より高度なジオメトリは必要ありません。 重要な観察は、答えが整数グリッド メンバーシップ テストによって完全に定義されるため、総当たり列挙が最適であるということです。

 ## アルゴリズムのチュートリアル

 基本円内のすべての整数点を直接列挙し、フロスティング範囲をテストします。

1. x を -R から R まで繰り返します。この範囲外の点は x² + y² ≤ R² を満たすことができないため、これらの値のみを考慮します。 
2. 各 x について、点を基本円内に維持する有効な y 値の最大垂直範囲を計算します。 ここでは厳密には最適化は必要ありませんが、それでも状態を直接チェックします。 
3. [-R, R] の各 y について、x² + y² ≤ R² を使用して、(x, y) が基礎円の内側にあるかどうかをテストします。 
4. そうでない場合は、貢献できないため、すぐにスキップしてください。 
5. 基本円の内側にある場合は、少なくとも 1 つのつや消し円で覆われているかどうかを確認します。 
6. 各つや消し円 i について、(x - x_i)² + (y - y_i)² ≤ r_i² かどうかを確認します。 
7. フロストサークルがポイントを覆っている場合、答えを増やします。 

### なぜ効果があるのか

 寄与できるすべての整数点は、基本円によって定義される有限集合内に存在する必要があります。 アルゴリズムはまさにこのセットを列挙します。 このような点ごとに、フロスティング サークル上の存在条件を満たすかどうかがチェックされます。 サークルの結合のメンバーシップが直接チェックされるため、ポイントが失われることはなく、無効なポイントがカウントされることもありません。 論理構造は、離散点上の集合交差と和集合の定義を正確に実装したものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = sys.stdin.read().strip().split()
    if not data:
        return
    n = int(data[0])
    R = int(data[1])
    arr = list(map(int, data[2:]))

    circles = []
    idx = 0
    for _ in range(n):
        r = arr[idx]
        x = arr[idx + 1]
        y = arr[idx + 2]
        idx += 3
        circles.append((r, x, y))

    ans = 0

    for x in range(-R, R + 1):
        for y in range(-R, R + 1):
            if x * x + y * y > R * R:
                continue

            covered = False
            for r, cx, cy in circles:
                dx = x - cx
                dy = y - cy
                if dx * dx + dy * dy <= r * r:
                    covered = True
                    break

            if covered:
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、すべての円データをタプルのリストに読み取ることから始まります。 各タプルには、チェック中に素早くアクセスできるように半径と中心の座標が保存されます。 

ネストされたループは、基本円の境界正方形上で反復されます。 条件`x * x + y * y > R * R`整数演算を使用して基本円制約を強制し、浮動小数点演算を完全に回避します。 

有効な格子点ごとに、すべてのつや消し円をスキャンします。 1 つの円がポイントをカバーすると、それ以上のチェックは不要になるため、早めの休憩が重要です。

 ## 特殊なケース

 主なエッジ ケースは、フロスティング サークルがベース サークル内のどの点もカバーしていない場合です。 アルゴリズムは引き続きすべてのポイントを列挙しますが、すべてのカバレッジ チェックが失敗し、必要に応じてゼロが生成されるため、カウンタは決して増加しません。 

もう 1 つのケースは、フロスティング サークルが重なり合う場合です。 アルゴリズムは最初のカバー円の早い段階で中断されるため、重複する領域によってカウントが膨らむことはありません。 

境界ケースは、点が円の境界上に正確に位置する場合に発生します。 状態は使用しておりますので、`<=`、そのような点は正しく含まれています。 たとえば、x² + y² が R² に等しい場合、その点は依然としてベースの一部であり、曇り円にもその点が含まれていればカウントされる可能性があります。 

最後に、基本円のはるか外側にある孤立したフロスティング円は、フロスティング チェックが行われる前に基本円チェックによって無関係な点がすべてフィルタリングされるため、安全に無視されます。
