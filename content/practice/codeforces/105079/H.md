 ## 解決策
 ## 問題の理解

 動的プロセスをシミュレートしています。$N \times M$最初は空で、徐々にセルごとに塗りつぶされるグリッド。 受信操作ごとに、3 つのフレーバーのいずれかのカップケーキが特定の空のセルに配置されます。 配置するたびに、現在配置されているすべてのカップケーキの中に接続されたコンポーネントがいくつ存在するかを報告する必要があります。接続性は直交的に定義されます。セルは側面を共有する場合に接続され、領域は同一のフレーバーの最大接続セットです。 

重要な点は、地域が味に敏感であるということです。 2 つの隣接するセルは、同じフレーバーが含まれており、同じフレーバーの隣接関係のチェーンを通じて接続されている場合にのみ、同じ領域に寄与します。 これは、各色が独自の進化グラフを引き起こすことを意味しますが、すべての色を組み合わせた連結成分の合計数が求められます。 

制約$N, M \le 300$最大 90,000 回の挿入を意味します。 各挿入後に接続コンポーネントを最初から再計算するソリューションでは、ステップごとに最大 90,000 セルにわたるフラッド フィルまたは DFS が必要となり、$O((NM)^2)$、これは実現可能な限界をはるかに超えています。 更新ごとに 1 つの DFS さえも、すでに境界線に達しています。 それをやってる$NM$時代がそれを不可能にします。 

操作はオンラインであるため、接続を動的に維持する必要があります。 

いくつかの微妙なケースが重要です。 

まず、隣接セルが占有されていないセルに挿入すると、新しい領域が作成されるため、カウントが 1 つ増加します。 

次に、同じ色の 1 つ以上のセルの隣に挿入すると、領域が結合される可能性があります。 たとえば、新しいセルが以前は別々だった 2 つのイチゴ領域を接続する場合、それらの領域は 1 つになるため、領域の合計数は 2 つではなく 1 つ減ります。 

第三に、異なる色の隣接性はまったく相互作用しません。 青い隣人はイチゴの接続に影響を与えません。 

マージを示す小さな例:

 入力グリッドの更新 (概念):

 ステップ 1: S を (1,1) → 1 領域に配置

 ステップ 2: S を (1,2) に配置 → 依然として 1 つの領域

 ステップ 3: S を (2,1) に配置 → 依然として 1 つの領域

 ステップ 4: S を (2,2) に配置 → 依然として 1 つの領域

 ここで、別の順序を考えてみましょう。 

ステップ 1: (1,1) の S → 1

 ステップ 2: (1,3) の S → 2

 ステップ 3: S at (1,2) → 2 つの領域をマージ → 1

 隣接するコンポーネントがすでに異なるコンポーネントに属しているかどうかを考慮せずに、「同じ色に触れているかどうか」だけをチェックする単純な方法では、過剰にカウントされてしまいます。 

したがって、この問題は、挿入のみを伴うグリッドにおける古典的な動的接続維持の問題です。 

## アプローチ

 ブルート フォース アプローチでは、グリッド全体が維持され、DFS または BFS を使用して挿入のたびに接続されたコンポーネントが再計算されます。 それぞれの後に、$NM$更新する場合は、すべてのセルをスキャンし、未訪問の占有セルをフラッドフィルします。 各フラッド フィルは各セルを最大 1 回訪問するため、1 回の再計算にコストがかかります$O(NM)$。 これを繰り返すと、$NM$操作が与える$O((NM)^2)$、それは約です$8 \times 10^9$最悪の場合に訪問するのは、$N=M=300$。 これでは遅すぎます。 

重要な観察は、接続が挿入されたセルでのみローカルに変化するということです。 それぞれの新しいセルは、最大 4 つの隣接セルとのみ対話できます。 これらの近傍が同じコンポーネントに属しているのか、異なるコンポーネントに属しているのかを迅速に判断できれば、操作ごとに一定またはほぼ一定の時間で領域の数を更新できます。 

これはまさに、時間の経過とともにエッジが追加されるだけのグラフにおける動的接続の問題です。 各セルはノードであり、同じフレーバーの隣接するセルの間にエッジが存在します。 エッジ挿入の下で接続されたコンポーネントを維持する必要があります。 

Disjoint Set Union (DSU) は Union-Find とも呼ばれ、これに適しています。 セルを配置するたびに、新しいノード (最初は独自のコンポーネント) が作成されます。 次に、それを、同じフレーバーのすでに占有されている近隣のものと結合しようとします。 2 つのノードがすでに同じセット内にある場合、変更は行われません。 異なるセットにある場合、マージすると領域の数が 1 つ減ります。 

微妙だが重要な点は、複数の隣接コンポーネントが同じコンポーネントに属する可能性があるということです。 同じ領域に対して複数回減算することは避けなければなりません。 同じセット内で繰り返される結合は無視されるため、DSU はこれを自然に処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (各ステップで DFS を再計算) |$O((NM)^2)$|$O(NM)$| 遅すぎる |
 | DSU インクリメンタル マージ |$O(NM \cdot \alpha(NM))$|$O(NM)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各グリッド セルを一意の整数でインデックス付けされたノードとして扱います。$id = i \cdot M + j$。 

1. すべての DSU 構造を初期化します。$N \times M$可能なノード。 占有配列を最初はすべて false に維持します。 実行中の変数も維持します`regions = 0`。 
2. 受信操作ごとにフレーバーを配置します$f$セルで$(i, j)$、セルを占有としてマークし、設定します`regions += 1`。 これは新たな孤立地域が誕生していることを反映している。 
3. 4 つの近傍のそれぞれについて、$(i, j)$、隣人がグリッド内にいて、すでに占有されているかどうかを確認します。 
4. 隣接セルが占有されており、同じフレーバーを持っている場合は、現在のセルを DSU 内の隣接セルと結合しようとします。 結合が成功した場合 (以前は別のコンポーネントにあったことを意味します)、デクリメントします。`regions`by 1。これは、以前は別々だった 2 つの領域の結合をキャプチャします。 
5. 出力`regions`現在の操作を処理した後。 

ステップ 4 の背後にある微妙な理由は、ルートを比較しない限り、DSU は 2 つのセルが異なる領域に属しているかどうかを直接教えてくれないということです。 ユニオンが成功すると、2 つのコンポーネントがマージされ、合計数がちょうど 1 つ減少することを意味します。 

### なぜ効果があるのか

 不変条件は、各操作の処理後、同じ色の占有セルのすべての接続コンポーネントが 1 つの DSU セットに正確に対応することです。`regions`はそのようなセットの数に等しい。 最初は両方ともゼロです。 挿入するたびにシングルトン セットが追加され、増加します。`regions`1つずつ。 有効な隣接関係を介して 2 つの異なるセットを結合するたびに、以前は別々だった 2 つのリージョンが 1 つにマージされ、カウントが 1 ずつ減ります。 他の操作で接続が変更されることはありません。 DSU はすでに接続されているノードを誤ってマージすることはないため、カウントは接続されているコンポーネントの実際の数と一致したままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return True

def solve():
    N, M = map(int, input().split())
    total = N * M

    dsu = DSU(total)
    occupied = [False] * total
    color = [''] * total

    regions = 0

    def id_of(i, j):
        return i * M + j

    for _ in range(N * M):
        i, j, f = input().split()
        i = int(i) - 1
        j = int(j) - 1
        idx = id_of(i, j)

        occupied[idx] = True
        color[idx] = f

        regions += 1

        for di, dj in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            ni, nj = i + di, j + dj
            if 0 <= ni < N and 0 <= nj < M:
                nidx = id_of(ni, nj)
                if occupied[nidx] and color[nidx] == f:
                    if dsu.union(idx, nidx):
                        regions -= 1

        print(regions)

if __name__ == "__main__":
    solve()
```DSU は、パス圧縮を使用してセル間の接続を親ポインターのフォレストとして維持します。 の`union`この関数は、マージが実際に行われたかどうかを示すブール値を返します。これは、リージョン数を正しく更新するために不可欠です。 

また、各セルのフレーバーを配列に保存して、同じ色の隣接セルのみを結合します。 このチェックを行わないと、異なるフレーバーが誤って 1 つの領域にマージされ、定義に違反します。 

グリッドからインデックスへのマッピングにより、2D グリッドをフラットな DSU 構造として扱うことができます。 

## 実用的な例

 ### 例 1

 すべての配置がイチゴ S である 2 x 2 グリッドを考えてみましょう。 

| ステップ | セル | アクション | ユニオンのマージ | 地域 |
 | --- | --- | --- | --- | --- |
 | 1 | (1,1) S | 新しいコンポーネント | 0 | 1 |
 | 2 | (1,2) S | 左とマージ | 1 マージ | 1 |
 | 3 | (2,1) S | 上とマージ | 1 マージ | 1 |
 | 4 | (2,2) S | 両方の近隣をマージしますが、問題となるのは 1 つの新しいマージだけです。 1 マージ | 1 |

 重要な観察は、最後の挿入が 2 つの隣接するものに触れますが、それらの隣接するものはすでに同じ DSU セットに属しているため、1 つの結合のみが成功するということです。 

これにより、DSU がマージの二重カウントを防止していることが確認できます。 

### 例 2

 色を混ぜるシーケンス:

 | ステップ | セル | フレーバー | 隣人同士の交流 | 地域 |
 | --- | --- | --- | --- | --- |
 | 1 | (1,1) | S | なし | 1 |
 | 2 | (1,3) | P | なし | 2 |
 | 3 | (1,2) | S | (1,1) のみとマージします | 2 |
 | 4 | (2,3) | P | (1,3) のみとマージします | 2 |
 | 5 | (2,2) | B | なし | 3 |
 | 6 | (2,1) | B | (2,2) と新しいマージ | 3 |

 これは、色の分離が厳密に適用され、結合は同一のフレーバー内でのみ発生することを示しています。

        def __init__(self, n):
            self.p = list(range(n))
            self.s = [1]*n
        def f(self,x):
            while self.p[x]!=x:
                self.p[x]=self.p[self.p[x]]
                x=self.p[x]

            a,b=self.f(a),self.f(b)

            if self.s[a]<self.s[b]:
                a,b=b,a

 ## 特殊なケース

 新しいセルが、他のパスを介してすでに接続されている複数の隣接セルに接触する場合、クリティカルなエッジ ケースが発生します。 たとえば、同じ色の 2 つの隣接するセルに隣接するセルを配置しますが、それらの隣接するセルはすでに同じ DSU セット内にあります。 成功する結合は 1 つだけであるため、DSU は二重デクリメントを防止します。 入力:```
2 2
1 1 S
1 2 S
2 1 S
2 2 S
```(2,2) を処理するとき、3 つの S ネイバーに触れますが、すべてのネイバーが同じルートを共有しているため、DSU マージは 1 つだけ発生します。 アルゴリズムは領域数を変更せずに正しく維持します。 

これにより、このメソッドがマージを過剰にカウントすることなく、冗長な隣接関係を安全に処理できることが確認されます。
