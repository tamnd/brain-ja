 ## 解決策
 ## 問題の理解

 最小しきい値が与えられています$n$、数字を選択したいと思います$x$カップケーキの水玉の数を表します。 この数は 2 つの制約を同時に満たす必要があります。 初め、$x \ge n$。 2番、$x$素数であってはなりません。 このようなすべての有効な値の中で、可能な限り最小の値を返さなければなりません。 

したがって、タスクは本質的に、次から始まる「次の有効な番号」クエリです。$n$ここで、有効性は「合成または 1」を意味します。1 は素数ではなく、「素数ではない」というルールの下で許容されるものとしてカウントされるためです。 

制約$2 \le n \le 1000$私たちが狭い探索空間にいることがすぐに示唆されます。 上向きの単純なスキャンでも、$n$最悪の場合でも 1000 チェックですが、これは無視できる程度です。 各チェック内の唯一の実際の計算は素数性テストです。 

唯一の微妙なエッジ ケースは、小さな整数に関する素数の定義方法に起因します。 数値 2 は素数なので、次の場合$n = 2$、それをスキップして先に進む必要があります。 数字の 3 も素数なので、連続スキップが発生する可能性があります。 もう 1 つの微妙なケースは、答えが以下に等しい可能性があることです。$n$もしそれ自体$n$すでにプライムではありません。たとえば、$n = 1000$。 常に増やさなければならないという軽率なアプローチ$n$それは不正確でしょう。 

## アプローチ

 直接的なアプローチは、以下から始めることです。$x = n$かどうかを繰り返し確認します。$x$プライムです。 素数の場合はインクリメントします$x$もう一度試してください。 素数性テストに失敗した最初の値が返されます。 

これが機能するのは、検索空間が単調であるためです。値が無効 (素数) になると、前に進むだけで済みます。昇順にスキャンするため、最初に見つかった有効な値が必然的に最適になります。 

ボトルネックは素数性テストです。 単純な素数チェックが実行されます$O(\sqrt{x})$, 最悪の場合は1000回程度まで行う場合もあります。 これにより、おおよその結果が得られます$1000 \cdot 31$簡単な操作です。 実装がわずかに遅くても、十分に制限内に収まります。 

もう少し構造化された最適化は、ふるいを使用して最大 1000 までの素数を事前計算し、単純に上方向にスキャンしてブール配列をチェックすることです。 これにより、各チェックが次のように削減されます。$O(1)$、最悪の場合でも解は純粋に線形になります。 

どちらのアプローチも受け入れられます。 複数のクエリが予想される場合は sieve がよりクリーンになりますが、単一の入力の場合は直接の素数チェックが最も簡単です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース (ステップごとに素数チェック) |$O((m-n)\sqrt{m})$|$O(1)$| 承認済み |
 | ふるい + スキャン |$O(M \log \log M + (m-n))$|$O(M)$| 承認済み |

 ここ$M = 1000$。 

## アルゴリズムのチュートリアル

 最終スキャンが簡単になるため、ふるいベースのアプローチについて説明します。 

### ステップ

 1. ブール配列を構築する`is_prime`サイズ 1001 は、2 ～ 1000 のすべてのインデックスに対して true に初期化されます。 

0 と 1 は素数の定義を満たさないため、直ちに非素数として扱います。 
2. エラトステネスを 2 から 1000 までふるいにかけます。 

それぞれの番号について$i$まだ素数としてマークされているものは、すべての倍数をマークします$2i, 3i, \dots$ノンプライムとして。 

この手順は正しいです。合成数には最小の素因数が必要であり、その素因数の反復によって削除されるからです。 
3. から始める$x = n$そして上に移動します。 
4. それぞれについて$x$、どうかを確認してください`is_prime[x]`は誤りです。 

falseの場合は即時に出力$x$。 

それ以外の場合はインクリメントします$x$そして続けます。 

候補をスキップせずに昇順にスキャンしているため、素数ではない最初の値が有効な最小の答えになります。 

### なぜ効果があるのか

 ふるいは、数値を最大 1000 までの素数と非素数に正しく分割します。前処理後、素数クエリは定数時間ルックアップになります。 からのスキャン$n$上向きは順序を維持するため、最初に遭遇する非素数は構造上最小限になります。 出力よりも小さいすべての候補がすでにチェックされ、素数として拒否されているため、より小さい有効な答えを見逃す方法はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N = 1000

is_prime = [True] * (N + 1)
is_prime[0] = is_prime[1] = False

p = 2
while p * p <= N:
    if is_prime[p]:
        for m in range(p * p, N + 1, p):
            is_prime[m] = False
    p += 1

n = int(input().strip())

x = n
while True:
    if not is_prime[x]:
        print(x)
        break
    x += 1
```ふるいは、最大 1000 までの固定範囲にわたって 1 回構築されます。内側のループは次から始まります。$p^2$なぜなら、より小さな倍数はすでにより小さな素数によってマークされており、冗長な作業が避けられるからです。 

スキャン ループは意図的に単純になっています。合成数または 1 が見つかるまで上方向にのみ進みます。`not is_prime[x]`は 1 を非素数として正しく扱い、すべての合成数も処理します。 

## 実用的な例

 ### 例 1: 入力 5

 少なくとも 5 までの素数を事前計算します。 

| × | プライム[x] | アクション |
 | --- | --- | --- |
 | 5 | 本当 | スキップ |
 | 6 | 偽 | 停止して出力 |

 アルゴリズムは最初に 5 をチェックし、それが素数であることを見つけてから、複合である 6 に移動して、それを返します。 これは、答えが厳密に次より大きい必要はないことを示しています。$n$、プライム以外のみで、少なくとも$n$。 

### 例 2: 入力 2

 | × | プライム[x] | アクション |
 | --- | --- | --- |
 | 2 | 本当 | スキップ |
 | 3 | 本当 | スキップ |
 | 4 | 偽 | 出力 |

 スキャンでは連続する素数が正しくスキップされます。 出力は 4 になります。これは、2 以上の最小の合成数です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    N = 1000
    is_prime = [True] * (N + 1)
    is_prime[0] = is_prime[1] = False

    p = 2
    while p * p <= N:
        if is_prime[p]:
            for m in range(p * p, N + 1, p):
                is_prime[m] = False
        p += 1

    n = int(sys.stdin.readline().strip())
    x = n
    while True:
        if not is_prime[x]:
            return str(x)
        x += 1

# provided samples
assert run("2\n") == "4"
assert run("5\n") == "6"
assert run("1000\n") == "1000"

# custom cases
assert run("3\n") == "4", "next composite after prime"
assert run("4\n") == "4", "already composite"
assert run("6\n") == "6", "composite stays same"
assert run("997\n") == "1000", "jump across primes near upper bound"

 ## 特殊なケース

 2 や 3 のような小さな素数の場合、スキャンでは複数の連続する値を正しくスキップする必要があります。 入力 2 の場合、アルゴリズムは 2 と 3 を素数としてチェックし、4 で停止します。これにより、インクリメントを繰り返しても有効な候補を見逃さないことが確認されます。 

4 や 1000 など、すでに複合入力である場合、最初のチェックはすぐに成功します。`is_prime[x]`は誤りです。 ループはそれ以上インクリメントせず、答えが入力自体と等しい場合に正しさを確認します。
