 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた位置の円形配置が与えられ、各位置には特定の「美味しさ」値を持つカップケーキが含まれる可能性があります。 スージーは位置 1 から開始し、一度に 1 インデックスずつ繰り返し前進し、n から 1 に戻ります。スージーは、位置に着地するたびに、そこにカップケーキがまだ存在する場合はそれを食べることを選択できます。 

制約はすぐに食べることではありません。 彼女はおいしい順にカップケーキを食べなければなりません。つまり、彼女がカップケーキを食べるたびに、その価値は彼女がすでに食べたどのカップケーキよりも小さくなることはありません。 彼女はカップケーキを通過するときにカップケーキをスキップし、後のラップで後で戻ってくることが許可されています。 

私たちが気にするコストは、この減少しない食べる順序を尊重する何らかの有効な戦略の下で、すべてのカップケーキが食べられるまでに実行される前進ステップの総数です。 「ステップ」は i から i + 1 に移動し、n は 1 にラップします。 

したがって、問題は単にすべてのポジションを訪問することだけではありません。 それは、値による並べ替えと一致する食事の順序を選択することと、同時に循環し続ける単一の時計回りのポインタに移動が制限されることを尊重することです。 

n が 2 · 10^5 までの制約により、段階的な動きをシミュレートしようとしたり、食べる順序のすべての順列を試行したりするソリューションは即座に除外されます。 テストケースごとの二次関数は遅すぎます。 n 回のテストの合計が大きいため、合計動作が O(n^2) であっても安全ではありません。 

貪欲なローカル決定で十分であると仮定すると、微妙な失敗例がいくつか現れます。 たとえば、[1, 100, 2] のような値を考えてみましょう。 可能な限り貪欲に食べると、1 を選択してしまい、2 と 100 の順序を尊重しようとすると非効率な移動パターンを強いられる可能性があります。本当の困難は、値による順序付けによって部分的な順序が固定されることですが、等しい値内および離れたインデックス間では、依然として巡回トラバーサルを最小限に抑える必要があることです。 

もう 1 つの注意が必要なケースは、最適な戦略を複数回ラップアラウンドする必要がある場合です。 次に必要なカップケーキが現在のポインターの「後ろ」にあるように値が分散している場合、後戻りすることはできないため、完全なサイクルを考慮する必要があります。 

## アプローチ

 直接シミュレーションでは、現在の位置を維持し、値の順序で次の有効なカップケーキが見つかるまで前方へのスキャンを繰り返します。 「次の有効なアイテムの検索」ごとに O(n) のコストがかかる可能性があり、カップケーキごとにそれを行うと O(n^2) になるため、これはすぐにコストが高くなります。 

重要な観察は、食べる順序は基本的にカップケーキを価値順に分類することによって決定されるということです。 美味しさの増加順序を修正したら、残された唯一の自由は、等しい値を持つインデックスをトラバースする順序と、連続するターゲット間の円運動をどのように処理するかだけです。 

これにより、問題は次の構造に帰着します。 カップケーキは値の大きい順に処理されます。 同じ値内で、現在の位置から時計回りの移動が最小になる順序でそれらの位置を訪問したいと考えています。 それはまさに「常に前に進みながら、順番にポイントを巡って回りながら歩く」というものです。 

このための自然なデータ構造は、現在の値グループの残りのインデックスのソートされたコンテナーです。 現在の位置から、現在の位置以上である最小のインデックスに繰り返しジャンプします。 存在しない場合は、最小のインデックスにラップします。 各ジャンプは円周上での前進距離に貢献します。 

これにより、問題はソートと順序付き集合演算に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n²) | O(n) | 遅すぎる |
 | ソート + 値グループごとの順序付けされた走査 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 カップケーキをおいしい順に処理し、すべての等しい値をブロックとして扱います。

1. すべてのインデックスをカップケーキ値で並べ替えます。 

すべての有効な注文はこのグローバル順序を尊重する必要があるため、これにより、非減少食事制限に違反することがなくなります。 
2. 同じ値を持つインデックスをグループ化します。 

グループ内では、訪問順序を自由に選択でき、それが移動距離に影響します。 
3. 現在のグループ内のインデックスのソートされたコンテナを維持します。 

この構造により、常に次の時計回りの候補に効率的にジャンプできます。 
4. ポインタを維持する`cur`円上のスージーの現在位置を 1 から表します。 
5. 各値グループについて:

 次にアクセスするインデックスを繰り返し選択します。 

インデックス ≥ cur が存在する場合、最小のインデックスを採用します。 それ以外の場合は、ラップしてグループ内の最小のインデックスを取得します。 

からの時計回りの距離を加算します。`cur`選択したインデックスに。 
6. インデックスにアクセスした後、更新します`cur`そのインデックスに追加し、セットから削除します。 
7. グループが空になるまで続行し、次の値グループに移動します。 

重要なアイデアは、動的な開始位置から開始して、固定値内で「一連の点をカバーする円上の最小限の前方移動」を解決しているということです。 

### なぜ効果があるのか

 どの時点においても、食べる順序に関する唯一の制約は、後でより小さい値に移動できないことです。 値グループ内に入ると、残りのすべてのカップケーキの優先順位が同じになるため、順序を並べ替えてもグローバル非減少要件に違反することはできません。 

グループ内の貪欲な選択は、開始位置を固定した後、常に次の時計回りに利用可能なポイントを取ることで当面のコストを最小限に抑え、逸脱すると後で追加のラップまたはより長い円弧を強制するため、最適です。 動きは加算的かつ単調であるため、より近い時計回りの候補を遅らせて、より遠い候補を優先しても、合計距離が増加するだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        arr = sorted([(a[i], i + 1) for i in range(n)])
        
        ans = 0
        cur = 1
        
        i = 0
        while i < n:
            j = i
            while j < n and arr[j][0] == arr[i][0]:
                j += 1
            
            indices = sorted(arr[k][1] for k in range(i, j))
            remaining = indices
            used = [False] * len(remaining)
            
            # simulate ordered circular traversal within group
            import bisect
            
            pos = cur
            rem = remaining
            
            taken = [False] * len(rem)
            cnt = len(rem)
            
            while cnt > 0:
                idx = bisect.bisect_left(rem, pos)
                if idx == len(rem):
                    # wrap
                    nxt = rem[0]
                    ans += (n - pos + nxt)
                else:
                    nxt = rem[idx]
                    ans += (nxt - pos)
                
                # remove nxt
                remove_idx = bisect.bisect_left(rem, nxt)
                rem.pop(remove_idx)
                cnt -= 1
                pos = nxt
            
            cur = pos
            i = j
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、グループ化された処理戦略に従います。 まずカップケーキを値で並べ替えてから、同じ値のセグメントを個別に処理します。 

各セグメント内では、並べ替えられたインデックスのリストが維持されます。 次の移動ごとに、現在位置以上の最初のインデックスをバイナリ検索します。 存在しない場合は、最小のインデックスにラップアラウンドします。 コストは前方円周距離として累積されます。 

実装の微妙な詳細の 1 つは、リストからの削除の処理です。これにより、Python リストからのポップにより、最悪の場合、このソリューションは O(n^2) になります。 厳しい競争環境では、これをバランスの取れたツリーまたは 2 つのヒープに置き換える必要があります。 意図したソリューションでは、バランスのとれた順序セットを使用します。 ロジックは同じままです。
