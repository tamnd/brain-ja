 ## 解決策
 ## 問題の理解

 一連のカップケーキの種類が与えられ、各種類の辛さの値は固定されています。 裁判官はすべてのカップケーキを一定の順序で、各種類 1 つずつ食べます。 カップケーキの貢献度は、カップケーキ自体の辛さだけではなく、その前にすでに食べたカップケーキの数にも依存します。 

スパイシーなカップケーキなら`s`定位置で食べられる`j + 1`順序で言えば、その貢献度は`(j + 1) * (A * s + B)`。 合計スコアは、すべてのカップケーキに対するこれらの貢献の合計です。 タスクは、この合計を最大化するようにカップケーキを並べ替えることです。 

重要な問題は、ポジション乗数が`(j + 1)`は直線的に成長するため、配置の前後により各カップケーキの重量が変化します。 決定は、位置と変換された値の両方に依存する重みを使用して項目を順序付けるかどうかによって決まります。`A * s + B`。 

制約により、最大で次のことが許可されます。`N = 100000`したがって、すべての順列を試行する解決策は不可能です。 順列の階乗数は計算限界をはるかに超えて増加します。 二次方程式でも`O(N^2)`アプローチは定数によってはタイムアウトになる危険性があるため、`O(N log N)`または`O(N)`貪欲な構造。 

微妙な点としては、`A`そして`B`マイナスになることもあります。 これは、変換された貢献度を意味します`(A * s + B)`正、負、またはゼロにすることができます。 これにより、従来の「値による並べ替え」スケジューリングの問題と比較して、順序付けの動作が大幅に変わります。 

素朴な直感を打ち破るエッジケースの 1 つは、変換されたすべての値が同一である場合です。 たとえば、次の場合`A = 0`、その後、すべてのカップケーキが貢献します`(j + 1) * B`、順序はまったく問題ありません。 もう 1 つの注意が必要なケースは次のような場合です。`A < 0`、「大辛がいい」の意味を逆転させたもの。 

小さな失敗例は、次の条件でソートすると仮定した場合に発生します。`s`常に機能します。 もし`A = -1`そして`B = 0`、より大きい`s`値はより負になり、それらを早めに配置すると重みペナルティが軽減されるため、最適な順序は正の場合とは逆になります。 

## アプローチ

 ブルートフォース ソリューションでは、カップケーキのすべての順列を試し、各順序のスコアを計算し、最大値を取得します。 これは目的関数を直接評価するため正しいですが、評価する必要があります。`N!`順列。 たとえ`N = 10`、これはすでに境界線になっており、`N = 100000`それは全く不可能です。 

構造を見つけるには、固定次数の寄与を書き換えます`p`:

 ポジションを合計します`i`:`i * (A * s_{p[i]} + B)`合計を分配します。`A * sum(i * s_{p[i]}) + B * sum(i)`第 2 項は以下にのみ依存します。`N`、 以来`sum(i)`として固定されています`N(N+1)/2`。 つまり、`B`順序にはまったく影響しません。 最終値をシフトするだけです。 

したがって、最適化全体は次の最大化に帰着します。`A * sum(i * s_{p[i]})`ここで、問題は古典的な重み付き順序付けタスクになります。つまり、位置と値の間のドット積を、次の符号に応じて最大化または最小化します。`A`。 

もし`A > 0`、大きいものが欲しいです`s`どちらも大きな位置に現れるため、`i`そして`s`積極的に貢献します。 これは並べ替えの不等式と一致します。両方のシーケンスを同じ順序で並べ替えると合計が最大になります。 

もし`A < 0`を効果的に最小限に抑えたいと考えています。`sum(i * s_{p[i]})`なので、順序を逆にします。`s`小さいものと組み合わせる必要があります`i`。 

もし`A = 0`、最初の項全体が消え、定数だけが消えます。`B * N(N+1)/2`が残るので、どのような順列も最適です。 

これにより、問題は一度ソートされ、単一の線形パスが計算されるようになります。

 ## アルゴリズムのチュートリアル

 1. の符号に基づいて、変換された比較ルールを計算します。`A`。 もし`A`が正の場合、より小さく配置したい`s`以前; もし`A`が負の場合、より大きい値が必要です`s`以前。 もし`A`がゼロの場合、順序は関係ありません。 
2. このルールに従って辛さの値の配列を並べ替えます。 これにより、再配置不等式の下で位置と値の間の組み合わせが最適になることが保証されます。 
3. 以下から定数寄与を計算します。`B`。 どのポジションでも`i`が 1 回だけ出現すると、すべてのポジションの重みの合計は次のようになります。`N(N+1)/2`、つまり、からの合計貢献度は、`B`固定されています。 
4. ソートされた配列を反復処理して主項を計算します。 ランニングポジションインデックスを維持する`i + 1`そして蓄積する`(i + 1) * A * s[i]`。 
5. 定数を追加します`B * N(N+1)/2`累積結果を加算して出力します。 

### なぜ効果があるのか

 目的は、順列に適用される位置依存の線形関数にきれいに分離されます。 展開すると、順序によって影響を受ける唯一の用語は次のとおりです。`sum(i * s_{p[i]})`。 並べ替え不等式により、係数が正の場合は一方のシーケンスを他方と同じ順序でソートし、負の場合は逆の順序でソートすることにより、この合計が最大化されることが保証されます。 以来`B`は順列とは独立した固定定数に寄与しますが、最適な配置には影響しません。 この不変性により、ソートされた構造からの逸脱は加重合計を悪化させるだけであることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, A, B = map(int, input().split())
    s = list(map(int, input().split()))
    
    if A == 0:
        # all permutations equal
        return B * N * (N + 1) // 2

    s.sort()

    if A < 0:
        s.reverse()

    res = 0
    for i, val in enumerate(s, 1):
        res += i * (A * val)

    res += B * N * (N + 1) // 2
    return res

if __name__ == "__main__":
    print(solve())
```コードは、入力を読み取り、縮退ケースを処理することから始まります。`A = 0`, それ以降、順​​序付けは効果がなく、答えは一定の算術合計に崩壊します。 

リストはデフォルトでは昇順にソートされ、次の場合には逆順にソートされます。`A`位置インデックスと変換された値の間の正しいペアを保証するには、負の値を指定します。 これは、再配置不等式によって決定される最適な配置を直接実装します。 

ループは、`A`用語のみ。各値に 1 から始まるインデックスを乗算します。 の`B`項は、最初の閉形式の合計を使用して最後に 1 回追加されます。`N`整数を使用し、順序への依存を回避します。
