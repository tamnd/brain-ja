 ## 解決策
 ## 問題の理解

 1 から 1 までの数字から始めます$n$。 位置に直接配置するのではなく$1$を通して$n$、それぞれの数字$i$最初は の位置に配置されます$2i-1$。 したがって、長さの配列$2n$奇数の位置にのみ数字があり、偶数の位置は空です。 

次に、プロセスが要素を繰り返し左に移動します。 各ステップで、右端の占有位置を調べます。 そこにある番号を取得し、厳密にその左側の最も近い空の位置に移動します。 これは、すべての数値が最初の数値に詰め込まれるまで続きます。$n$残りの位置は無関係です。 

タスクは、このプロセス全体が終了した後、各位置にどの数字が入るかを決定することです。$x$から$1$に$n$、多くのクエリに対して。 

制約$n \le 10^{18}$あらゆるシミュレーションを即座に除外します。 配列を保存することすら不可能であり、すべての位置を 1 回通過するだけでも大きすぎます。 唯一の実行可能なアプローチは、クエリごとに対数または定数時間で各値の最終位置または逆マッピングを計算する必要があります。 

素朴な精神的な落とし穴は、これが単純なパターンで「2 番目の要素を繰り返し削除する」だけであると想定することです。 小規模なケースでは、これはヨセフスのような消去法に似ていますが、「左に最も近い空のスロット」ルールにより、自明ではない並べ替えが作成されます。 たとえば、次のようなとき$n=4$、最終的な配列は$[1, 3, 2, 4]$、これはすでに単純な交互の直観と矛盾しています。 

もう 1 つの失敗例は、最大までしかシミュレートしようとしたことに起因します。$n$ステップ。 このプロセスは要素を独立して移動しません。 以前の動きによって空のスロットの利用可能性が変化し、それが後続のすべての動きに段階的に影響します。 部分的なシミュレーションはすぐに発散します。 

## アプローチ

 ブルート フォース シミュレーションでは、次のサイズの配列が明示的に構築されます。$2n$、位置に初期配置をマークします$2i-1$、右から左にスキャンを繰り返して次の占有位置を見つけ、それを最も近い空のスロットに左に移動します。 それぞれのステップにかかる可能性があるのは、$O(n)$時間もあるし、$n$要素、$O(n^2)$行動。 これはたとえ$n = 10^5$、そして不可能です$10^{18}$。 

重要な洞察は、このプロセスは実際の移動履歴には依存せず、要素が奇数の位置から連続するプレフィックスに「折りたたまれる」相対的な順序のみに依存するということです。 操作の構造により、要素がサイズが 2 のべき乗であるブロックに効果的にマージされることが保証されます。 これは、「2 つおきの要素を取得する」プロセスを繰り返す場合に現れるのと同じパターンです。各ラウンドでアクティブ セットが半分になり、生き残ったセットの識別はインデックスの 2 値分解に依存します。 

プロセスを逆に解釈することが転換点です。 動きをシミュレートする代わりに、元のインデックスがどれであるかを尋ねます。$i$結局その位置に着く$x$? 答えはやり方次第$x$ペアリングと消去の繰り返しによって引き起こされるバイナリ構造の内部に存在します。 それぞれのビット$x$区間の概念的な二値分解で左の分岐から移動するか右の分岐から移動するかをエンコードします$[1, n]$。 

これは対数分解につながります。$x$概念セグメントの前半または後半に位置し、元のラベルを回復するまでそれに応じてインデックスを調整します。

 ## アルゴリズムのチュートリアル

 最終的な配列は、アクティブな要素の概念的なシーケンスを繰り返し半分にすることによって構築されたものとして再解釈されます。 

### ステップ

 1. 最終的な構成は、2 つおきの要素を繰り返し削除することによって引き起こされる相対的な順序にのみ依存することに注目してください。 

これは再帰的な構造を示唆しています。1 回の完全なパスの後、同じように動作する小さなシーケンスが残ります。 
2. クエリ位置の場合$x$、現在のアクティブなセグメントの前半にあるか後半にあるかを判断します。 

後半にある場合は、前半のサイズを減算して前半にマッピングし直します。 
3. 基本レベルに達するまでにこの「圧縮」が何回発生したかを追跡します。 

各圧縮は、暗黙的なバイナリ プロセスの 1 つの層を削除することに対応します。 
4. 各段階で、構築の奇数層と偶数層のどちらを見ているのかを反映するように論理インデックスを調整します。 

これは、プロセスが要素の保持と破棄を何回繰り返したかを追跡することに相当します。 
5. インデックスが自明になるまで続行し、その時点で元の数値を回復します。 

### なぜ効果があるのか

 このプロセスでは、次の決定論的な順列を定義します。$1..n$2 つおきの要素を繰り返し破棄して構築されます。 このような操作は安定した反復を形成します。各ステージは、レイヤーのパリティに応じて、現在のシーケンスを奇数インデックスまたは偶数インデックスのサブセットにマッピングします。 各ステップは、生き残ったサブセット内の順序を維持しながら、有効な問題のサイズを半分にするため、すべての位置$x$最大でも次のシーケンスを通じて一意に追跡できます。$\log n$削減。 これにより、再構築が正しく終了し、位置に割り当てられた一意の要素が得られることが保証されます。$x$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    
    for _ in range(q):
        x = int(input())
        
        shift = 0
        length = n
        
        while length > 1:
            half = length // 2
            
            if x > half:
                x -= half
            
            length = half
        
        print(x)

if __name__ == "__main__":
    solve()
```実装における中心的なアイデアは、有効な間隔サイズを繰り返し縮小することです。 変数`length`現在取り組んでいる概念セグメントを表し、`half`それを2つの等しい部分に分割します。 

クエリインデックスが後半にある場合は、`half`1 つの圧縮ステップの後、後半には 1 から始まる番号が付け直されるためです。これは、2 番目の要素が削除されるたびに要素が折りたたまれる方法を反映しています。 

ループは概念セグメントに 1 つの要素だけが残るまで続き、その時点で現在の`x`が答えです。 

微妙な点は、実際の配列を決して構築しないことです。 すべての推論はインデックス空間で行われます。 これがソリューションを実行可能にする理由です$n$まで$10^{18}$。
