 ## 解決策
 ## 問題の理解

 それぞれのコインが 2 の正または負の累乗の値を持つ「コイン」のマルチセットを構築することができます。 すべてのラウンドで、目標の整数が発表され、固定コインの一部を選択して、その合計がその目標と等しくなるようにする必要があります。 ラウンド後、コインは返されるため、同じマルチセットがすべてのクエリ値に対して独立して機能する必要があります。 

タスクは、指定されたすべてのターゲット値がサブセットの合計として表現できるように、最小サイズのマルチセットを選択することです。 

制約により、ラウンド数が線形または線形に近い解に近づきます。 値が 100,000 まで、大きさが 100,000 までの場合、クエリごとに表現を個別に再計算しようとするソリューションでは、値ごとに対数以上の処理を繰り返し実行することになり、サブセットに対する組み合わせ検索も試行すると遅くなりすぎる危険性があります。 

素朴な解釈では、クエリごとに新しいバイナリ分解を割り当て、必要なコインをすべてマージしようとします。 これは、異なる数値が同じ 2 のべき乗の符号付き数字の矛盾する選択を要求する可能性があるため、失敗します。 本当の難しさは、単一の固定マルチセットがすべての表現を同時にサポートしなければならないことです。 

値がクエリ間で「キャンセル」される場合、微妙なエッジ ケースが発生します。 たとえば、あるクエリが 1 で、別のクエリが -1 の場合、単純なアプローチでは、+1 コインと -1 コインが 1 つ必要であると結論付ける可能性があります。 ただし、2 進数の位置を借用することで負の表現を形成できるため、コインまたは空のサブセットを選択することにより、1 と -1 の両方を得るには、単一の +1 コインだけで十分です。 このビット間の相互作用がまさに、局所的な数値ごとの決定を不正確にする原因となります。 

もう 1 つのエッジ ケースは、大きな正の値と負の値が交互になるなど、複数の値によってキャリーが繰り返される場合に発生します。 キャリー伝播を無視してビットごとのカウントを貪欲に行うと、高次のコインの必要性が過小評価されてしまいます。 

## アプローチ

 ブルートフォース戦略では、最小のマルチセットを見つけて、各ターゲットのすべてのサブセット合計の可能性をチェックすることでそれを検証します。 たとえ 2 の累乗に限定したとしても、これは巨大な状態空間に退化します。 各コインはラウンドごとに使用することも使用しないこともでき、100,000 のターゲットにわたる表現可能性を検証するには、サブセット合計の計算を繰り返し行う必要があり、それぞれに指数関数的または擬似多項式の時間がかかります。 合計が 100,000 を超える動的プログラミングであっても、すべての候補構成に対して繰り返されることになりますが、これは実行不可能です。 

重要な観察は、2 の累乗が 2 進位置システムの数字のように動作するということです。 サブセット合計条件は、すべてのビット位置にわたって固定の符号付き数字表現を使用してすべてのターゲットを表現できるかどうかという問題になります。 数値ごとに考えるのではなく、すべての数値をビット位置ごとの共有「需要」に集約し、キャリーを含む 2 進加算がグローバルにどのように動作するかをシミュレートします。 

すべてのターゲット値を同時に処理し、各ビットが必要な回数を累積し、過剰または不足をキャリーとして上方に伝播します。 各ビット位置の絶対的な不均衡から、そのパワーのコインを何枚含める必要があるかがわかります。 これにより、問題は、すべての制約のグローバルにバランスの取れたバイナリ表現を維持することに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数 / 擬似多項式 | 高い | 遅すぎる |
 | 最適 (ビットごとの桁上げ集計) | O(n log A) | O(log A) | 承認済み |

 ## アルゴリズムのチュートリアル

 各数値をバイナリで解釈し、ビット位置ごとの実行不均衡を維持し、すべての制約を満たすために符号付きバイナリ表現をどのように調整する必要があるかをシミュレートします。

1. すべての入力数値をビット位置全体のバイナリ寄与に変換し、設定された各ビットをその位置での +1 要求として扱い、各負の数値を -1 要求として扱います。 
2. 配列を維持する`cur[k]`ビット位置での累積された符号付き需要を表す`k`。 
3. 各入力数値について、その寄与を次のように加算します。`cur`。 
4. ビット位置を更新した後、バイナリ キャリーの動作をシミュレートして、直ちに解決します。 

もし`cur[k]`1 を超えるか -1 未満の場合、超過分を次のビット位置にプッシュします`k+1`2で割って余りだけを保持します`cur[k]`。 
5. すべての数値を処理した後、次の絶対値が求められます。`cur[k]`±2^k の価値を持つコインを何枚含める必要があるかを示します。 
6. これらのコインをすべて、次の符号に従って正または負の符号を使用して出力します。`cur[k]`。 

重要な点は、すべてのキャリー操作が値 2^k の 2 枚のコインを値 2^(k+1) の 1 枚のコインに置き換えることに正確に対応し、カウントを最小限に抑えながら表現性を維持することです。 

### なぜ効果があるのか

 すべてのビット位置で、次の不変条件が維持されます。`cur[k]`これまでに確認されたすべての入力を処理した後に、符号付きバイナリ展開で正味必要な係数を表します。 この係数が単一の符号付き数字の表現可能な範囲を超えるたびに、バイナリ キャリー ルールを使用して正規化します。これは、冗長なコインをより価値の高いコインにマージすることに対応します。 

2 の累乗にわたるサブセットの合計は位置番号体系を形成するため、この正規化によって表現可能な整数のセットは変更されません。 最終的に、各ビット位置には、避けられないユニット貢献の最小数が保存され、これは必要なコインの最小数に直接変換されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    MAXB = 20
    cur = [0] * (MAXB + 5)

    for x in a:
        sign = 1
        if x < 0:
            sign = -1
            x = -x

        b = 0
        while x > 0:
            if x & 1:
                cur[b] += sign
            x >>= 1
            b += 1

        k = 0
        while k < len(cur):
            if cur[k] > 1:
                carry = cur[k] // 2
                cur[k] -= carry * 2
                cur[k + 1] += carry
            elif cur[k] < -1:
                carry = (-cur[k]) // 2
                cur[k] += carry * 2
                cur[k + 1] -= carry
            k += 1

    res = []
    for i, v in enumerate(cur):
        for _ in range(abs(v)):
            res.append((1 if v > 0 else -1) * (1 << i))

    print(len(res))
    print(*res)

if __name__ == "__main__":
    solve()
```このコードは、符号付き桁の不均衡のグローバル配列を維持します。 各数値はビットに分解され、符号が追加されます。 挿入直後の正規化ステップでは、各位置がキャリーまで {-1, 0, 1} 以内に収まるように強制されます。 

キャリー伝播ループが重要な点です。 余分なビットを上位ビットに押し込むと再びオーバーフローが発生する可能性があるため、処理を続行する必要があります。 これが、ループが現在位置のみを処理するのではなく、上向きにスキャンする理由です。 

最終的な再構成では、ゼロ以外の各桁がその数の ±2 のべき乗のコインに単純に拡張されます。 

## 実用的な例

 単一の値が 9 である入力を考えてみましょう。 

9 をバイナリ 1001 として処理し、ビット 0 とビット 3 に寄与を生成します。他の制約は存在しないため、正規化を超えるキャリー調整は必要ありません。 

| ステップ | ビット0 | ビット 1 | ビット 2 | ビット 3 | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 9を追加 | 1 | 0 | 0 | 1 | 初期分解 |
 | 正規化 | 1 | 0 | 0 | 1 | キャリーは必要ありません |

 最終的なコインは 1 と 8 で、これらを直接組み合わせると 9 になります。 

ここで、混合入力 1、-1、2 を考えてみましょう。 

1 の処理ではビット 0 に +1 が加算されます。-1 の処理ではビット 0 で 1 が減算され、キャンセルされます。 処理2ではビット1に+1を加算します。 

| ステップ | ビット0 | ビット 1 | アクション |
 | --- | --- | --- | --- |
 | +1 | 1 | 0 | 貢献を追加する |
 | -1 | 0 | 0 | キャンセル |
 | +2 | 0 | 1 | 貢献を追加する |

 最後のマルチセットには値 2 のコインが 1 つだけ含まれており、これですべてのクエリに十分です。 

これらのトレースは、異なる入力にわたるキャンセルが、数値ごとの構築ではなく、符号付き累積によって自然に処理されることを示しています。

 ## 特殊なケース

 重要なエッジケースは、次のような入力全体にわたる完全なキャンセルです。`1 -1 1 -1`。 アルゴリズムは、寄付を繰り返しキャンセルします。`cur[0]`、すべての上位ビットをそのままにしておきます。 不変式により、不必要な上位ビットのコインが導入されず、最終出力が空になることが保証されます。 

もう 1 つのエッジ ケースは、オーバーフローが繰り返されることです。たとえば、次のような多くの値が挙げられます。`1`10万回繰り返した。 ビット 0 の位置には大きな正の値が蓄積され、キャリーの伝播が繰り返されると、質量の大部分が上位ビットに押し込まれます。 アルゴリズムはこれを段階的に処理し、単一のビット位置が上向きに正規化されずに無制限の大きさを格納しないようにします。
