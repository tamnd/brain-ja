 ## 解決策
 ## 問題の理解

 日付の時系列シーケンスを表すバイナリ文字列が与えられます。各文字は 0 または 1 です。すべての位置が 1 つのグループに属するように、これらの位置をいくつかのグループに分割する必要がありますが、各グループが連続したインデックスで構成されている必要はありません。 

各グループは「ゼブラシーケンス」を形成する必要があります。 有効なゼブラ シーケンスには 3 つのプロパティがあります。 これは空ではなく、0 で始まり 0 で終わり、サブシーケンス内の隣接する要素は 0 と 1 の間で切り替わる必要があります。 

これは、すべての有効なサブシーケンスが 0、01、010、0101 などのように見える必要があることを直ちに意味しますが、常に 0 で終わるため、その長さは奇数で、1 より 1 つ多い 0 が含まれます。 

このようなパーティションが可能かどうかを判断し、可能である場合は有効なパーティションを出力するように求められます。 

入力サイズは最大 200,000 文字で、二次関数や偶数関数は除外されます。$O(n \log n)$非常によく構造化されていない限り、重い定数が含まれます。 線形または線形に近い貪欲な構造が期待されます。 

重要な構造上の制約が定義内に隠されています。すべてのゼブラは 0 で始まり、0 で終わるため、すべてのグループは、開始と終了の両方として機能する方法でゼロを使用する必要があります。 これは、ゼロが実現可能性を制御することをすでに示唆しています。 

単純な間違いは、交互構造の利用可能性を追跡せずに貪欲にサブシーケンスを構築しようとしたり、1 と正しくペアにせずに独立して 0 を割り当てたりすることです。 もう 1 つのよくある失敗は、サブシーケンス内で常に 2 つのゼロの間になければならないという事実を無視することです。 交互にペアにできない 1 は強制的に失敗します。 

小さな失敗例としては、次のようなものがあります。`111000`。 全体的に十分な 0 と 1 がありますが、すべての 1 を正しく消費する方法で 0 から開始できる交互のパターンがないため、複数のシーケンスを開始しようとしても失敗します。 正しい出力は次のとおりです`-1`。 

もう一つの微妙なケースは、`0101`。 交互に見えますが、1 で終わるため、サブシーケンスにそれを完全に含めることはできません。 これを有効なゼブラ シーケンスに割り当てることは不可能です。 

## アプローチ

 ブルートフォース手法では、インデックスをグループに分割し、各グループの有効性をチェックしようとします。 これは、各インデックスを次のいずれかに割り当てることを意味します。$O(n)$サブシーケンスとグループごとの交互の検証。 貪欲な割り当てに限定したとしても、要素を分散する方法の数は指数関数的に増加し、検証自体は候補パーティションごとに線形です。 これは完全に不可能です$n = 2 \cdot 10^5$。 

重要な観察は、各シマウマの構造が剛であるということです。 シーケンスは交互に 0 で始まる必要があるため、1 を配置するたびに、現在 0 で終わる以前に開始されたシーケンスを継続する必要があります。同様に、0 ごとに新しいシーケンスが開始されるか、次に 0 を期待する既存のシーケンスが閉じられます。 

これは、「オープン サブシーケンス」の 2 つの動的なセットを維持することを示唆しています。現在 0 で終わるものと 1 で終わるものです。私たちは常に文字を貪欲に一致させたいと考えています。1 は 0 で終わるシーケンスを拡張する必要があり、0 は 1 で終わるシーケンスを拡張するか、新しいシーケンスを開始する必要があります。 

重要な洞察は、パーティションを自由に選択しているわけではないということです。 代わりに、文字列を介してシーケンスを効率的にスレッド化します。 各インデックスは 1 つのチェーンにのみ接続され、チェーンは最後に期待される文字に基づいてスタックのような方法で進化します。 これにより、問題は、アクティブなシーケンスのブックキーピングによる貪欲な構築に帰着します。 

最後に、すべてのシーケンスは 0 で終わる必要があります。つまり、1 を期待するシーケンスを残すことはできません。

 ## アルゴリズムのチュートリアル

 2 つのスタック (またはリスト) を維持します。1 つは現在 0 で終わるシーケンス用で、もう 1 つは現在 1 で終わるシーケンス用です。各シーケンスは、収集されたインデックスによって表されます。 

1. 文字列を左から右に繰り返します。 
2. を見たとき`0`、現在で終わるシーケンスにそれをアタッチする必要があります。`1`そのようなシーケンスが存在する場合、それは交互性を維持するためです。 そのようなシーケンスが存在しない場合は、このインデックスで新しいシーケンスを開始します。 新しいシーケンスを 0 から開始することは、正しく開始されるため有効です。 
3. を見たとき`1`、現在で終わるシーケンスにそれをアタッチする必要があります。`0`。 存在しない場合、構築は不可能であり、即座に失敗します。 
4. アタッチ後、末尾文字が反転するため、シーケンスをスタック間で移動します。 
5. すべての文字を処理した後、シーケンスが次の文字で終わっていないことを確認します。`1`。 このようなシーケンスは、すべてのシーケンスが 0 で終わるという要件に違反します。 

各ステップでの決定は、交互ルールによって強制されます。 1 はゼブラを開始したり、別の 1 に従うことはできないため、常に利用可能な「オープン ゼロエンド チェーン」を消費します。 

### なぜ効果があるのか

 文字列のすべてのプレフィックスで、各アクティブ シーケンスは最後の要素によって一意に特徴付けられます。 このアルゴリズムにより、1 で終わるシーケンスは常に次の 0 を待機し、0 で終わるシーケンスは次の 1 を待機することが保証されます。 有効なゼブラは厳密に交互する必要があるため、貪欲な割り当てから逸脱すると、キャラクターの消費が遅れ、将来の柔軟性が低下するだけです。 1 には有効な先行状態 (0 で終了するシーケンス) が 1 つだけあり、0 には 1 で終了するシーケンスが存在する場合に実現可能性を決して低下させない選択肢があるため、貪欲な選択では将来の可能性がすべて保存されます。 どこかの時点で 1 を割り当てることができない場合、それを受け入れることができるすべてのシーケンスがすでに構造的に互換性がないため、再配置しても問題を解決できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    zero_end = []  # sequences ending with 0
    one_end = []   # sequences ending with 1
    res = []       # list of sequences

    # each sequence is a list of indices
    for i, ch in enumerate(s, 1):
        if ch == '0':
            if one_end:
                seq = one_end.pop()
                seq.append(i)
                zero_end.append(seq)
            else:
                seq = [i]
                zero_end.append(seq)
        else:  # ch == '1'
            if not zero_end:
                print(-1)
                return
            seq = zero_end.pop()
            seq.append(i)
            one_end.append(seq)

    # all sequences must end with 0
    if one_end:
        print(-1)
        return

    print(len(zero_end))
    for seq in zero_end:
        print(len(seq), *seq)

if __name__ == "__main__":
    solve()
```このソリューションは明示的なシーケンスを維持し、追加された最後の文字に応じて状態間で動的にシーケンスを移動します。 実装の重要な詳細は、シーケンスが直接保存されるため、最後に再構築が必要ないことです。 

微妙な点の 1 つは、最終検証の処理です。ゼブラは 0 で終わる必要があるため、「1 で終わる」プールに残っているシーケンスは無効になります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    s = sys.stdin.readline().strip()
    zero_end = []
    one_end = []

    for i, ch in enumerate(s, 1):
        if ch == '0':
            if one_end:
                seq = one_end.pop()
                seq.append(i)

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、文字列が 1 の連続で始まる場合です。`11100`。 最初の文字では、付加する既存のゼロエンドのシーケンスが存在しないため、アルゴリズムは直ちに入力を拒否します。 シマウマは 1 から始めることはできないため、これは正しいです。 

もう 1 つのエッジ ケースは、1 で終わる完全に交互のプレフィックスです。`010`。 アルゴリズムは 1 で終わるシーケンスを正常に構築しますが、ゼブラは 0 で終わる必要があるため、最終検証は失敗します。これは、最終状態のチェックが不可欠であり、構築中にローカル チェックで置き換えることができない理由を示しています。 

3 番目のケースは、複数の競合シーケンスです。たとえば、`000111000`。 アルゴリズムは必要に応じて複数のチェーンを作成し、各 1 は異なるオープン ゼロエンド シーケンスを消費します。 ここでの正しさは、構造が許可しない限り、2 つの 1 を同じチェーンに強制しないという事実から来ています。
