 ## 解決策
 ## 問題の理解

 あります`n`一列に並んだ部屋。 各部屋は正確に終わる必要があります`b`生徒は検査官によって数えられていますが、最初は配列として分布が任意です`a[i]`、生徒の総数は次のとおりです。`n · b`したがって、自由に再分配できれば、世界中ですべての部屋を満たすのに十分な「質量」が存在します。 

問題は、再配布がローカルで時間に依存することです。 学生は近くの部屋の間を移動できますが、限られた距離内でのみ移動できます。`d`ステージごとに、建物は両端から徐々にロックされます。 インストラクターによって部屋が処理されると、その部屋は永久に封印され、通過ポイントとして使用できなくなります。 

2 人の検査官が同時に内側に向かって掃除します。1 人は左端から、もう 1 人は右端からです。 各部屋は、対応する側によって 1 回だけ処理されます。 検査時に部屋にいる非表示の生徒の数が次の数に等しくない場合`b`、その部屋はその検査官への苦情として記録されます。 学生は、部屋内に表示される数を減らすために隠れることが許可されているため、部屋内に表示される数を効果的に減らすことができますが、物理的に存在する学生を超えて追加の表示可能な学生を作成することはできません。 

学生たちは、許可された移動と隠れを利用して配置を変更し、2 人の検査官間の不良部屋の最大数が最小限に抑えられるようにしたいと考えています。 

キーの出力は単一の整数、つまり次の可能な最小値です。`max(x1, x2)`すべての有効な戦略にわたって、`x1`そして`x2`左右の検査官が確認した不一致の部屋の数です。 

制約は大きく、最大で`100000`部屋。 これにより、生徒ごとまたはタイム ステップごとの動きをシミュレートするソリューションは即座に除外されます。 各生徒を個別に扱ったり、アレイ全体で繰り返しリバランスを実行したりするアプローチでは、制限時間を超えてしまいます。 

さらに微妙な問題は、可視性が明らかに単調ではないことです。 部屋を独立して処理する単純な貪欲な試みは失敗します。学生がロックされる前に部屋間を移動できるため、離れた位置にある決定を結び付けることができます。 

単純なローカル バランシングが失敗する小さな例は次のとおりです。```
n = 3, d = 1, b = 1
a = [2, 0, 1]
```地元の貪欲な人は、最初に部屋 1 を修正し、余分な部屋をすぐに右に移動しようとするかもしれませんが、タイミングによっては、中央の部屋がバッファとして機能し、後で使用できなくなる可能性があります。 これを誤って管理すると、たとえ調整された動きが 0 または 1 を達成したとしても、不良部屋を数えすぎてしまうことになります。 

## アプローチ

 移動が制限されていない場合、問題は総供給量と総需要量が等しいかどうかを確認するという問題に陥りますが、これはすでに保証されています。 この難しさは、距離が限られ、時間に依存する移動と、境界線が部屋を越えると使用できなくなるという事実によってもたらされます。 

ブルート フォース ビューでは、プロセス全体を段階的にシミュレートしようとします。 各段階で、どの学生が移動できるかを追跡し、考えられるすべての再配分を適用し、構成ごとの不一致を最小限に抑えるように努めます。 各学生は多くのステップをまたいで移動する可能性があり、各ステップがグローバルな到達可能性に影響を与えるため、これはすぐに実行不可能になります。 すべての州を表すだけでも、部屋の数は指数関数的に増加します。 

重要な観察は、実際には正確な最終構成を気にしていないということです。 私たちが気にするのは、せいぜい以下のことを保証できるかどうかだけです。`k`固定の場合、部屋の両側が一致していません。`k`、次にそのような最小のものを検索します`k`。 これは、答えをバイナリ検索することを示唆しています。 

候補が決まったら`k`、構造は単純化されます。各側で、私たちは最大で「犠牲」を払うことができます。`k`厳密な要件を厳密に実施していない部屋`b`。 1 つおきの部屋を正しくする必要があります。 

これにより、問題は制約付きの輸送実現可能性チェックに変わります。つまり、余分な学生を移動させて、残りの全員を満足させることができるかということです。`k`距離の制約と、処理スイープによって部屋が徐々にロックされるという事実を考慮して、両側の位置を調整しますか?

 重要な構造の簡素化は、各側を供給が内側に流れる単調な掃引として扱うことができ、利用可能な可動余剰を維持し、それを必要な不足と一致させることで、最大で許容しながら実現可能性を貪欲にチェックできることです。`k`不一致はスキップされます。

 ## アルゴリズムのチュートリアル

 まず答えを二分探索します`k`。 固定の場合`k`、左のインスペクターと右のインスペクターの両方がそれぞれ最大で表示を強制できるかどうかを確認します。`k`悪い部屋。 

左側に焦点を当てます。 右側は配列を反転すると対称になります。 

### 片側の実現可能性チェック

 1. 処理室を左から右にシミュレートします。 
2. 私たちは、部屋がロックされる前に将来の部屋に移動できる「利用可能な余剰学生」を表す構造を維持します。 私たちが部屋にいるたびに`i`、最初の供給量を追加し、距離内にまだ輸送できる量を追跡します。`d`。 
3. また、ほとんどの部屋が正確に完成する必要があるという要件も維持します。`b`目に見える生徒たち。 したがって、各部屋には、相対的に赤字または黒字があります。`b`。 
4. 私たちは部屋をくまなく調べ、各部屋について、現在利用可能な余剰を使用してその要件を満たすよう努めます。 マッチングできれば`b`、それに応じて供給を消費し、部屋を有効としてマークします。 
5. 部屋を満足できない場合は、最大でも部屋の 1 つと宣言することができます。`k`悪い部屋を無視し、その正確な要件の適用をスキップします。 供給を消費せずに続行します。 
6. 私たちは、以下を超えて使用しないことを保証します。`k`スキップします。 それを超えてしまうと、これは`k`は無効です。 
7. 移動の制約`d`有効な到達範囲内でのみ電源の使用を許可することにより、暗黙的に強制されます。 スイープの進行により部屋が遠くなりすぎると、残りの転送可能な容量が期限切れになります。 

### この構造で十分な理由

 重要な不変条件は、スイープのどの時点においても、残っている使用可能な生徒はすべて、未処理の部屋に合法的に到達できる生徒であるということです。 貪欲なマッチングにより、最も早い未満た需要に対して常に最も早い利用可能な余剰が使用されるため、将来必要な転送がブロックされることがなくなります。 

許可する`k`スキップは、厳格なマッチング問題を、最大で破棄できる容量付き問題に変換します。`k`制約があり、実現可能性は、間隔が制限されたフローの下で残りのシステムが満たされるかどうかを確認することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d, b = map(int, input().split())
    a = list(map(int, input().split()))

    total = sum(a)

    def check(k):
        # left side feasibility on original array
        # we simulate greedy supply usage with a window
        from collections import deque

        supply = deque()
        used = 0
        bad = 0

        curr = 0
        for i in range(n):
            supply.append([a[i], i])

            # remove expired supply (too far to be useful for future)
            while supply and i - supply[0][1] > d:
                supply.popleft()

            need = b

            while need > 0 and supply:
                take = min(need, supply[0][0])
                supply[0][0] -= take
                need -= take
                used += take
                if supply[0][0] == 0:
                    supply.popleft()

            if need > 0:
                bad += 1
                if bad > k:
                    return False

        return True

    lo, hi = 0, n
    while lo < hi:
        mid = (lo + hi) // 2
        if check(mid) and check(mid):  # symmetric sides
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```このコードは、許可された数の不良ルームに対して二分検索を実行します。 候補値ごとに、貪欲な実現可能性シミュレーションを実行します。 

Deque は、距離制約を強制できるように、利用可能な学生のプールとその元の位置を維持します。`d`現在の位置に到達できなくなったエントリを期限切れにすることによって。 各部屋は、要件が満たされるまでこのプールから学生を消費します`b`満たされています。 それが満たされない場合、その部屋は違反としてカウントされます。 

二分探索により最小のものを確実に見つけます`k`これにより、両方のスイープが成功します。 対称性チェックは、両方のインスペクタが同じ境界を独立して尊重する必要があることを反映しています。 

ロックの進行は位置スイープに直接対応するため、供給の有効期限が時間ステップではなくインデックス距離に基づいていることに注意する必要があります。

 ## 特殊なケース

 重大なエッジケースは、すべての余剰が需要から遠く離れたところに集中している場合です。たとえば、`a = [0, 0, 0, n*b]`。 距離が制限された移動を慎重に処理しないと、単純な貪欲な人は、中間の部屋を通る有効なルーティングが存在する場合でも、質量を早めにプッシュしようとして失敗するでしょう。 デキューベースの有効期限により、供給がまだ到達可能な間のみ使用されることが保証されます。 

もう一つの微妙なケースは次のような場合です。`d`地球規模の移動を可能にするのに十分な大きさです。 その状況では、答えは次のように崩れるはずです`0`、学生はロックする前に完全に再配布できるためです。 消費される前に供給ウィンドウが期限切れになることがないため、アルゴリズムはこれを自然に処理します。 

最後のエッジケースが発生するのは、`b`小さく、多くの部屋は少し離れています。 ここでは不良ルームの数が大半を占めており、二分探索により、早期にオーバーコミットするのではなく、ローカルな不一致とグローバルな実現可能性を適切にトレードオフすることが保証されます。
