 ## 解決策
 ## 問題の理解

 2 つの順列が与えられています`p`そして`q`数字のうち`0...n-1`。 

あらゆるポジションについて`i`、インデックスのすべてのペアを評価する必要があります`(j, i-j)`そのような`0 ≤ j ≤ i`、そして計算します$$2^{p_j}+2^{q_{i-j}}$$これらすべての候補の中から最大値を取り、それを次の場所に保存します。`r[i]`。 

指数は次のように大きくなる可能性があるため、直接値は膨大になります。`n-1`、したがって、最終的な答えは剰余が必要です`998244353`。 

最初に注目すべきことは、関係する数値が 2 のべき乗であるということです。 2 のべき乗は非常に急速に増大するため、比較すると$$2^a+2^b$$大きい方の指数が完全に支配的になります。 もっと正式に言えば、`a > c`、 それから$$2^a+2^b > 2^c+2^d$$の価値観とは関係なく、`b`そして`d`。 

これは、合計を最大化することは、ペアのうち大きい方の指数を最初に最大化することと同等であり、それらの大きい方の指数が等しい場合にのみ、小さい方の指数を比較することを意味します。 

制約があるからこそ、この構造を活用せざるを得なくなります。 の合計額`n`すべてのテストケース全体で最大でも`10^5`。 アン`O(n^2)`アルゴリズムは大まかに実行します`10^{10}`限界をはるかに超えた最悪の場合の動作。 周りに何かが必要です`O(n log n)`または`O(n)`テストケースごとに。 

微妙な点は、候補ペアの最大指数がどちらの配列からもたらされる可能性があることです。 

考慮する：```
p = [2,0,1]
q = [0,2,1]
```のために`i = 1`、候補者は```
j=0: (2,2)
j=1: (0,0)
```答えは指数から出ます`2`、両方の配列が均等に寄与します。 1 つの配列から最大値のみを追跡するソリューションでは、そのようなケースは見逃されます。 

もう 1 つの簡単な間違いは、最大化することです`p[j] + q[i-j]`。 目標は指数の合計ではありません。 

例えば：```
(5,0) -> 32+1 = 33
(3,3) -> 8+8 = 16
```それでも`5+0 < 3+3`、最初のペアは指数が大きいため、はるかに大きくなります。`5`支配する。 

## アプローチ

 ブルート フォース ソリューションは、定義に直接準拠します。 

あらゆるポジションについて`i`、すべてを反復処理します`j`から`0`に`i`、計算する$$2^{p_j}+2^{q_{i-j}}$$そして最大値を維持します。 

これは、すべての有効なペアを明示的にチェックするため、正しいです。 問題は複雑さです。 1 つのテスト ケースの場合、検査されるペアの数は次のとおりです。$$1+2+\cdots+n = O(n^2)$$おおよそになります`5 × 10^9`操作時の操作`n = 10^5`。 

より良い成果を上げるには、次の事実を利用する必要があります。`p`そして`q`順列です。 

させて$$M_i=\max\Big(\max_{0\le j\le i} p_j,\ \max_{0\le j\le i} q_j\Big)$$位置までのいずれかのプレフィックスに現れる最大の指数である`i`。 

最適なペア`r[i]`指数を含める必要があります`M_i`。 

なぜ？ どちらの側も貢献しない場合`M_i`の場合、その候補の最大指数は厳密に次よりも小さくなります。`M_i`、および以下を含むペア`M_i`常に大きくなります。 

なぜなら`p`そして`q`は順列であり、各指数は 1 回だけ現れます。 指数を仮定します`M_i`に登場する`p`位置で`posP[M_i]`。 

もし`posP[M_i] ≤ i`の場合、この指数を含む唯一のペアは$$j = posP[M_i]$$これにより、もう一方の指数は次のようになります。$$q_{i-posP[M_i]}.$$同様に、`M_i`に登場する`q`、一致する可能性のある唯一のペアは次のとおりです。$$p_{i-posQ[M_i]}.$$したがって、それぞれについて`i`、最大の指数を含む候補は最大 2 つあります。`M_i`。 

最大の指数が決定されると、比較はより大きな 2 番目の指数を選択することになります。 したがって、考えられる 2 つの値を比較するだけで済みます。 

これにより、問題は線形スキャンに変わります。

 ## アルゴリズムのチュートリアル

 1. 2 のべき乗モジュロを事前計算する`998244353`まで`100000`。 
2. アレイの構築`posP`そして`posQ`順列内のすべての値の位置を保存する`p`そして`q`。 
3. プレフィックスの最大値を計算します。`prefP[i] = max(p[0..i])`

`prefQ[i] = max(q[0..i])`4. ポジションごとに`i`、計算する$$M=\max(prefP[i],prefQ[i]).$$最適なペアには指数が含まれている必要があります`M`。 
5. もし`M`のプレフィックス内に表示されます`p`、その位置を次のようにします`k=posP[M]`。 

次に、対応する候補者は次を使用します$$(M,\ q_{i-k})$$提供された`k ≤ i`。 
6. もし`M`のプレフィックス内に表示されます`q`、その位置を次のようにします`k=posQ[M]`。 

次に、対応する候補者は次を使用します$$(p_{i-k},\ M)$$提供された`k ≤ i`。 
7. 有効な候補のうち、2 番目の指数を比較します。 両方とも同じ最大の指数を含むため、`M`、2 番目の指数が大きいほど合計も大きくなります。 
8. 選択したペアを次のようにします。`(M,S)`。 出力$$2^M + 2^S \pmod{998244353}.$$### なぜ効果があるのか

 あらゆるインデックスに対して`i`、 させて`M`いずれかのプレフィックスに現れる最大の指数です。`i`。 

最大の指数が以下のすべての候補ペア`M`を含む候補よりも自動的に劣ります。`M`2 の累乗は最大の指数によって厳密に順序付けされるためです。 

各指数は各順列で 1 回だけ出現するため、以下を含むペアを形成するには 2 つの方法しかありません。`M`: での出現を使用`p`またはその出現を使用して`q`。 すべての最適なソリューションは、これらの候補の 1 つである必要があります。 

最大の指数を修正した後`M`、比較する$$2^M+2^a$$そして$$2^M+2^b$$比較することに帰着する`a`そして`b`。 アルゴリズムは大きい方の 2 番目の指数を選択するため、最大値のペアが正確に選択されます。 

したがって、すべての`r[i]`は正しく計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXN = 100000

pow2 = [1] * (MAXN + 1)
for i in range(1, MAXN + 1):
    pow2[i] = (pow2[i - 1] * 2) % MOD

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        q = list(map(int, input().split()))

        posP = [0] * n
        posQ = [0] * n

        for i, x in enumerate(p):
            posP[x] = i

        for i, x in enumerate(q):
            posQ[x] = i

        prefP = [0] * n
        prefQ = [0] * n

        prefP[0] = p[0]
        prefQ[0] = q[0]

        for i in range(1, n):
            prefP[i] = max(prefP[i - 1], p[i])
            prefQ[i] = max(prefQ[i - 1], q[i])

        ans = [0] * n

        for i in range(n):
            M = max(prefP[i], prefQ[i])

            best_second = -1

            k = posP[M]
            if k <= i:
                best_second = max(best_second, q[i - k])

            k = posQ[M]
            if k <= i:
                best_second = max(best_second, p[i - k])

            ans[i] = (pow2[M] + pow2[best_second]) % MOD

        print(*ans)

solve()
```位置配列は重要な実装の詳細です。 これらにより、特定の指数がいずれかの順列のどこに現れるかをすぐに特定できるようになります。 

プレフィックス maxima は、それぞれの関数で利用可能な最大の指数を識別します。`i`。 これらがなければ、プレフィックスを繰り返し検索する必要があります。 

固定の場合`i`、指数を含める 2 つの方法のみを調べます。`M`。 対応する 2 番目の指数は、反対側の配列から直接読み取られます。 

答えは、事前に計算された 2 のべき乗を使用して再構成されます。 高速累乗を使用して繰り返し計算能力を高めることはまだ許容されますが、事前計算により各クエリが定数時間になります。 

インデックスには注意が必要です`i-k`。 小切手`k <= i`このインデックスが負でないことを保証します。

 ## 特殊なケース

 ### 最大の指数は 1 つの配列のプレフィックスにのみ表示されます

 次のことを考慮してください。```
n = 2
p = [1,0]
q = [0,1]
```のために`i = 1`、利用可能な最大の指数は次のとおりです。`1`、から来ています`p[0]`。 

アルゴリズムは次のことを見つけます`posP[1]=0`、マッチングパートナーを評価します`q[1]=1`を取得し、`(1,1)`。 

答えは$$2^1+2^1=4.$$すべてのペアをスキャンする必要はありません。 

### 最大の指数が両方のプレフィックスに表示されます

 次のことを考慮してください。```
n = 3
p = [2,0,1]
q = [0,2,1]
```のために`i = 2`、指数`2`両方のアレイから使用できます。 

候補者は２名です```
(2,1)
(1,2)
```どちらも値に対応します`6`。 

アルゴリズムは両方の出現をチェックし、大きい方の 2 番目の指数を保持します。`1`、正しい結果が生成されます。 

### 最大指数がすべての小さい指数よりも優先されます

 次のことを考慮してください。```
n = 3
p = [2,1,0]
q = [0,1,2]
```のために`i = 2`、候補としては以下が挙げられます。```
(2,2)
(1,1)
(0,0)
```それでも`(1,1)`バランスのとれたペアを持っています、それに勝つことはできません`(2,2)`なぜなら指数`2`最大の指数が次のようなすべての候補を優勢にします`1`。 

アルゴリズムは、利用可能な最大の指数を含むペアに注目を制限する場合、このプロパティに正確に依存します。
