 ## 解決策
 ## 問題の理解

 q の操作で展開される長さ n の配列が与えられます。 各操作は 2 つのインデックス x と y を受け取り、それらの現在の値の小さい方を計算し、その値を 3 番目の位置 z に書き込みます。 すべての操作の後、最終的な配列 b が与えられるので、b を生成する可能性のある初期配列 a を再構築する必要があります。 

重要な視点の変化は、値が「最小」操作を通じてのみ下方向に移動することです。 どの操作も値を増やすことはできず、割り当てごとに 2 つのソースのいずれかから情報がコピーされます。 したがって、システムは、各位置が少なくとも 2 つの以前に存在した位置によって繰り返し上書きされる、指示された情報フロー プロセスのように動作します。 

制約は大きく、n と q はテスト全体で最大 3・10^5 になります。 可能な初期状態を明示的にシミュレートしようとしたり、値ごとの割り当てを調べたりするソリューションは遅すぎます。 合計入力サイズによりすでに O(n + q) の動作が強制されるため、テストごとに線形または線形に近いものが必要です。 

微妙なエッジ ケースは、b の制約が min 伝播の単調な性質と矛盾する場合です。 たとえば、インデックスが後で別のインデックスのソースとして使用される場合、最終値に暗黙的に不平等が適用されます。 サンプルでは、​​b2 > b1 であるが、演算 c2 = min(c1, c2) がある場合、その時点では c2 は常に最大でも c1 であるため、b2 は伝播後に b1 を超えることはできません。 

もう 1 つのよくある落とし穴は、各ポジションが独立して処理できると想定していることです。 これは、操作がインデックスを結合するため、失敗します。単一のポジションが、一連の最小割り当てを通じて他の多くのポジションに影響を与える可能性があります。 

## アプローチ

 直接的な試みは、 a を未知のものとして扱い、すべての操作を逆方向にシミュレートすることです。 各割り当てを「元に戻す」ことを試みるかもしれませんが、min は元に戻すことができません。c_z = min(c_x, c_y) がわかっても、c_x と c_y を回復する固有の方法はありません。 これにより、後方シミュレーションが曖昧になります。 

もう 1 つの単純なアイデアは、初期値を推測し、フォワード シミュレーションによって検証することです。 これは可能性としては指数関数的ですが、すぐには実現不可能です。 

重要な洞察は、視点を逆転させることです。どのような初期値が最終値を生成するかを問うのではなく、最終値が初期値にどのような制約を課すかを問うことです。 各演算 c_z = min(c_x, c_y) は、すべての演算の後、割り当ての時点で c_z は最大でも c_x と c_y の両方でなければならないことを意味します。 ただし、値は減少するだけであるため、最終的な b 値は、すべての伝播で生き残った値の下限を表します。 

このプロセスは、各操作が最終値間の不平等を強制する有向制約グラフを構築するものとして解釈できます。 重要な観察は、逆の順序で操作を通じて下限を後方に伝播することによって候補の初期配列を構築し、すべての最小制約との一貫性を確保できることです。 矛盾があれば解決策はありません。 

この構築は、ベースラインとして b から開始し、操作を逆の順序で逆方向に「再生」することで機能し、ソースの潜在的な上限を更新して、最小割り当てごとに観察された最終状態が生成されるようにします。

 ## アルゴリズムのチュートリアル

 私たちは操作を逆に処理し、各ステップでソースと宛先の間の一貫性を強制するという考えを維持します。

1. 配列 a を b のコピーとして初期化します。 これは、すべての制約が考慮された後に各位置が最終的に取り決められる最小値を表します。 
2. 操作を最後から最初に処理します。 操作 (x, y, z) の場合、実行時に z が min(x, y) に設定されたことがわかります。 すべての演算の後、その時点では z は x または y を超えることはできないため、z の最終値によって x と y に下限制約が逆方向に課されます。 具体的には、x と y の両方が少なくとも a[z] でなければなりません。そうしないと、z が最終値に到達できないからです。 
3. 逆の演算 (x、y、z) ごとに、以下を更新します。 

a[x] = max(a[x], a[z])

 a[y] = max(a[y], a[z])

 これにより、両方のソースが z で観測された最終値を生成できることが強制されます。 
4. すべての操作を処理した後、前方一貫性を検証する必要があります。 最初から最後まで操作を再生し、構築した a に操作を適用した場合に配列がどのようになるかを計算します。 いずれかの時点で z の計算値が min(x, y) と異なる場合、その構築は無効です。 
5. 検証に合格した場合は、a を出力します。 それ以外の場合は -1 を出力します。 

逆方向伝播は下限の実現可能性を強制するだけであり、構築された値が実際に正確な変換シーケンスを再現するわけではないため、前方検証ステップが必要です。 

### なぜ効果があるのか

 各操作により依存関係が作成されます。z に書き込まれる値は、その時点では x または y よりも大きくなることはありません。 逆方向に実行すると、x と y の両方が、そこを流れるすべての値をサポートするのに十分な大きさになることが保証されます。 最終的なフォワード シミュレーションにより、意図しない余分な削減が導入されていないことが保証されます。 下限伝播と正確な再生の組み合わせにより、システムに過剰な制約を与えることなく、最小操作によって引き起こされるすべての制約が満たされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        b = list(map(int, input().split()))
        
        ops = []
        for _ in range(q):
            x, y, z = map(int, input().split())
            ops.append((x - 1, y - 1, z - 1))
        
        a = b[:]
        
        for x, y, z in reversed(ops):
            a[x] = max(a[x], a[z])
            a[y] = max(a[y], a[z])
        
        c = a[:]
        ok = True
        
        for x, y, z in ops:
            c[z] = min(c[x], c[y])
        
        if c != b:
            print(-1)
        else:
            print(*a)

if __name__ == "__main__":
    solve()
```このソリューションは概念的に 2 つの配列を維持します。 最初の a は、制約を逆方向に伝播することによって得られる、再構築された候補初期状態です。 2 番目の c は、転送プロセスをシミュレートすることによる検証のみに使用されます。 

微妙な点は、最終的な構成のみが重要であるため、中間状態ではなく b と比較することです。 もう 1 つの重要な点は、逆方向伝播では min ではなく max を使用することです。値を直接再構築するのではなく、下限を上げて実現可能性を確保しています。 

## 実用的な例

 ### 例 1

 入力:```
n = 2, q = 1
b = [1, 2]
op: (2, 1, 2)
```逆方向処理:

 | ステップ | 操作 | 前 | 更新 | 後 |
 | --- | --- | --- | --- | --- |
 | 初期化 | - | [1,2] | - | [1,2] |
 | rev1 | (2,1,2) | [1,2] | a2 は a2 を強制します、a1 ≥ 2 | [2,2] |

 フォワードシミュレーション:

 c1=2、c2=2 ですが、b=[1,2] が予期されており、不一致のため無効です。 

これは、制約が固定の最終値と競合する場合、逆方向伝播だけでは十分ではないことを示しています。 

### 例 2

 入力:```
n = 3, q = 2
b = [1,2,3]
ops: (2,3,2), (1,2,1)
```逆方向伝播:

 | ステップ | 操作 | 前 | 更新 | 後 |
 | --- | --- | --- | --- | --- |
 | 初期化 | - | [1,2,3] | - | [1,2,3] |

 | rev1 | (2,3,2) | [1,2,3] | a2、a3 ≥ 2 | [1,2,3] |

これは、矛盾が存在しない場合、逆方向伝播により、すべての min 操作に耐える安定した割り当てが得られることを確認します。

 ## 特殊なケース

 エッジ ケースの 1 つは、インデックスが z として表示されず、x または y として表示される場合です。 この状況では、逆方向伝播によって値が増加することはないため、値は b に等しいままになります。これは、強制された等価性に影響を与えることがないため、これは正しいです。 

もう 1 つのケースは、c[z] = min(c[z], c[y]) のような自己代入です。 これにより、z は最大でも y でなければならないという制約が作成され、逆方向伝播では、最大更新を通じて逆形式で a[z] ≤ a[y] が正しく適用されます。 

最後の微妙なケースは、1 つの値が多くの位置を流れる長いチェーンです。 各伝播ステップは実現可能性を強制するだけであり、最大更新を繰り返すことで、中間の依存関係を見逃すことなく最も必要な下限が蓄積されるため、アルゴリズムはこれを処理します。
