 ## 問題の理解

 同じ友達の順列が 2 つあります。 現在の行は`a`、必要な行は次のとおりです`b`。 1 つの再編成では、空ではない友人のセットを選択し、現在の位置から削除し、相対的な順序を逆転させ、逆転した部分列を最前面に置きます。 

この仕事は建設的なものです。 最小限の組織再編は必要ありません。 変換する演算を最大 15 個出力するだけで済みます。`a`の中へ`b`。 ここで提供されているステートメントは、102672L として公開されている「Transformations」というタイトルの Codeforces Gym の問題に対応しています。 

限界`n <= 10000`が構築の鍵となります。 以来`2^14 = 16384`, すべての友人に個別の 14 ビット コードを与えるには、14 回の二項決定で十分です。 これはまさに私たちが必要とするスケールです。 を使用した構築`O(n log n)`作業は簡単に十分に高速ですが、二次関数も潜在的に受け入れられます。`n = 10000`しかし、本当の課題は実行時間ではありません。 課題は、操作数が 15 に制限される構造を見つけることです。 

実装を静かに破壊する可能性のあるエッジケースがいくつかあります。 もし`n = 1`、操作は必要ないため、答えはゼロでなければなりません。 もし`a`すでに等しい`b`、ゼロ演算も有効ですが、一般的な構造では依然として有効な空ではない演算シーケンスを生成できます。 ビットにフレンドが割り当てられていない場合、そのステートメントでは出力されるすべての操作で空でないセットを選択する必要があるため、その操作を出力してはなりません。 最後に、順列には個別の値が含まれるため、次のような入力が必要になります。`1 1 2`は有効なテスト ケースではありません。 繰り返しの値を含むテストを、ソリューションの動作を正当化するために使用しないでください。 

たとえば、```
1
1
1
```正しい出力は単純に```
0
```常に少なくとも 1 つのビット操作を作成する不注意な実装では、空の選択セットで無効な操作が出力される可能性があります。 

のために```
2
1 2
2 1
```友達を選択する 1 つの操作で十分です`2`。 選択されたサブシーケンスは`[2]`、結果は次のようになります`[2,1]`。 少なくとも 2 ビットが必要であると想定する実装は、冗長な有効な演算を出力する場合には依然として正しいですが、15 演算の制限を決して超えてはなりません。 

## アプローチ

 直接的な総当たりアプローチでは、すべての操作に対して友人のサブセットを選択し、結果をシミュレートしようとします。 1回の手術でも、`2^n - 1`可能なサブセット。 いくつかの操作のシーケンスを検索すると、おおよその結果が得られます。`2^(nk)`～の可能性`k`まったく実行不可能な操作です。 すべての法的組織再編はこれらのサブセットの 1 つによって表されるため、強引な方法は正しいのですが、その検索スペースはすぐに膨大になります。 

より自然な貪欲な試みは、ターゲット順列の次の部分となるグループを繰り返し選択することです。 これにより操作が正しくキャプチャされますが、操作の数について信頼できる制限が与えられるわけではありません。 別の再編成シーケンスがはるかに短い場合でも、順列にはそのような貪欲なグループが多数必要になる場合があります。 

有益な観察は、選択されたセットを任意のサブセットとして考えるのをやめ、代わりにすべての友人にバイナリ コードを与えることです。 手術`i`友人を正確に選択します。`i`-番目のコードビットは1です。 

2 人の友人が異なるコードを持っているとします。 それらのビットが異なる最後の操作を考えてみましょう。 その操作中に、そのうちの 1 つだけが選択されます。 選択した友達は選択していない友達の前に移動するので、その瞬間に相対的な順序が決まります。 以降のすべての操作では、両方を選択するか、どちらも選択しません。 両方を選択すると相対的な順序が逆転しますが、どちらも選択しないと変更されません。 したがって、すべての操作後の相対順序は、最初の相対順序ではなく、2 つのコードのみに依存します。 

これが中心的なトリックです。 すべての友人が個別のコードを受信した場合、すべてのコードビット操作後の最終的な順序はコード自体によって完全に決定されます。 入力の順列とは関係なく、その次数を一度計算できます。`a`。 

私たちが使用するのは`k = ceil(log2(n))`ビット。 少なくともあります`n`間の異なるコード`0, 1, ..., 2^k - 1`。 をシミュレートします。`k`これらのコード自体に対する操作は、番号順に開始されます。 これにより、すべての操作後のコードに普遍的な順序が与えられます。 次に最初の値を割り当てます`n`その普遍的な順序でコードを友人に要求する正確な順序で送信します。`b`。 

コードが割り当てられたら、対応する操作を実際の順列に適用します。`a`生成する`b`。 すべての友達が固有のコードを持っているため、最初の順序は重要ではなくなりました。

 ## アルゴリズムのチュートリアル

 1. 最小の数値を計算します`k`そのような`2^k >= n`。 以来`n <= 10000`、 我々は持っています`k <= 14`、これはすでに許容制限である 15 操作を下回っています。 のために`n = 1`、これは与えます`k = 0`。 
2. すべて作成する`2^k`バイナリコード、最初は次のように順序付けされています`0, 1, 2, ..., 2^k - 1`。 私たちはこれらのコードを、コード番号をアイデンティティとする抽象的な友人としてのみ使用します。 
3. 最下位ビットから最上位ビットまでの各ビットについて、後で実際の友人に対して実行するのと同じ再編成をコード シーケンスに対して実行します。 選択された要素は、そのビットが設定されているコードです。 現在の順序が逆になり、前に配置されます。 結局`k`演算の結果として得られるコード シーケンスは、その構築によって引き起こされる普遍的な順序です。 
4. 希望の順列にコードを割り当てます。`b`この普遍的な秩序に従って。 普遍的な秩序がコードから始まるなら`c1, c2, ..., cn`、割り当てます`c1`に`b1`、`c2`に`b2`、 等々。 すべての友達が固有のコードを持つようになりました。 
5. ビットごとに、割り当てられたコードにそのビットが含まれるすべての友人番号を収集します。 これらの友人が 1 つの法的組織を形成します。 操作自体が現在位置を使用して反転したサブシーケンスを決定するため、それらの順序を特定の順序で出力する必要はありません。 
6. 本当の友達がそのビットを設定していない場合は、少し飛ばしてください。 このような操作は空であるため、許可されません。 残りの操作数は最大です`k <= 14`。 
7. これらの演算を、ユニバーサル コード順序を構築する際に使用したのと同じビット順序で出力します。 この構造により、結果として得られるラインが正確であることが保証されます。`b`。 

### なぜ効果があるのか

 異なるコードを持つ 2 人の友人を考えてみましょう。 させて`t`コード間でビットが異なる最後の操作になります。 手術前`t`、それらの相対的な順序は任意である可能性があります。 動作中`t`、正確に 1 人の友人が選択され、選択された友人は選択されていない友人の前に移動されるため、相対的な順序は完全に 2 ビットによって決まります。`t`。 以降のすべての操作では、両方の友人が選択されるか、どちらの友人も選択されません。 どちらも選択されていない場合、順序は変更されません。 両方を選択すると、両方が一緒に反転されるため、それらの順序は決定的な方法で反転されます。 したがって、それらの最終的な相対順序は、それらのコードのみの関数です。 

割り当てられたコードはすべて個別であるため、友人の各ペアには最終的な相対順序が決定されます。 シミュレートされたコード シーケンスはまさにその順序です。 最初に割り当てます`n`の友達へのコード`b`したがって、すべてのペアは、次の場合とまったく同じ相対順序になります。`b`。 どちらも同じ友人の順列であるため、完全な最終シーケンスは次のようになります。`b`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    if n == 1:
        print(0)
        return

    k = (n - 1).bit_length()
    m = 1 << k

    # Find the final order of all k-bit codes.
    order = list(range(m))

    for bit in range(k):
        selected = []
        unselected = []

        mask = 1 << bit
        for x in order:
            if x & mask:
                selected.append(x)
            else:
                unselected.append(x)

        selected.reverse()
        order = selected + unselected

    # The first n codes in this order will be assigned to b[0], b[1], ...
    code_of = [0] * (n + 1)

    for i in range(n):
        code_of[b[i]] = order[i]

    operations = []

    for bit in range(k):
        mask = 1 << bit
        chosen = []

        for friend in range(1, n + 1):
            if code_of[friend] & mask:
                chosen.append(friend)

        if chosen:
            operations.append(chosen)

    print(len(operations))
    for op in operations:
        print(len(op), *op)

if __name__ == "__main__":
    solve()
```最初の部分では 2 つの順列を読み取ります。 この構造では、登場する友人にコードが直接割り当てられるため、逆順列を構築する必要はありません。`b`。 

表現`(n - 1).bit_length()`最小のものを与える`k`満足のいく`2^k >= n`。 例えば、`n = 8`与える`k = 3`、 その間`n = 9`与える`k = 4`。 と`n <= 10000`、最大値は 14 です。 

の`order`配列には友達番号ではなく抽象コードが含まれています。 1 ビットの場合、この操作はまさに問題の操作です。そのビットが設定されているコードを収集し、現在の順序を逆にして、そのビットのないコードの前に配置します。 これをビットごとに繰り返すことで、すべての実際の操作の後にこれらのコードが持つ順序が生成されます。 

重要な任務は、`code_of[b[i]] = order[i]`。 友人の地位`i`希望の順列で、最終的にその位置を占めるコードを受け取ります`i`抽象的な構造で。 これにより、抽象的なコードの実験が実際のターゲットの順列に接続されます。 

操作を生成するとき、コード ビットによって友人が選択されているかどうかが決まります。 フレンド番号は任意の順序で印刷できるので、次からスキャンしてください。`1`に`n`で十分です。 選択した友達の実際の順序は、番号が表示される順序ではなく、現在の位置によって決まります。 

コードでは再帰は決して使用されず、通常の Python 整数を超える大きな整数に依存することもありません。 多くてもあります`16384`抽象コードを使用し、それらを通過するのは最大 14 回であるため、構築は小規模です。

 ## 特殊なケース

 のために`n = 1`、`(n - 1).bit_length()`はゼロです。 コードはこれを明示的に処理し、操作を出力しません。 これにより、不必要な操作でビット ユニバースを構築しようとすることが回避され、バイナリ決定が必要ない唯一のケースが直接処理されます。 

すでに等しい順列ペアの場合、一意のコードをターゲット位置に割り当て、対応する演算を適用するため、一般的な構成は引き続き有効です。 特別なケースにする必要はありません`a == b`ただし、そうすることでゼロ操作の出力が小さくなります。 建設的な問題では、解答が最小手数を使用しているかどうかではなく、結果の状態が判断されるため、これは便利です。 

のために`n`2 の累乗をわずかに超えると、ビット数はちょうど 1 増加します。 例えば、`n = 8`3ビット必要なので、`2^3 = 8`、 その間`n = 9`3 ビットでは 8 つの異なるコードしか提供されないため、4 つが必要になります。 表現`(n - 1).bit_length()`は、off-by-one エラーを発生させずにこの境界を処理します。 

最大の場合`n = 10000`、14 ビットが提供します`16384`明確なコード。 誘導された順序の最初の 10,000 コードのみが実際の友人に割り当てられます。 未使用のコードはいかなる操作にも出現しないため、実際の行には影響を与えません。 これが、構築で 2 のべき乗のコード ユニバースを使用できる理由です。`n`特別なパディングロジックは必要ありません。 

値の繰り返しは、問題の入力コントラクトに基づく正当なエッジ ケースではありません。 どちらの配列も順列であるため、すべての友人番号が 1 回だけ表示されます。 構築する実装`code_of`したがって、友人番号による認証は安全であり、衝突処理は必要ありません。 

最後に、友達が選択されていない操作は出力してはなりません。 コードは、フレンド コードを構築した後、そのようなビットをフィルターで除外します。 合計で最大 14 ビットがあるため、空の演算を削除すると、答えは必要な最大値である 15 を安全に下回ります。
