 ## 問題の理解

 同じグループの友人の順列が 2 つあります。 最初の順列`a`は現在の順序であり、2 番目の順列です`b`は必須の順序です。 

1 回の操作で、空ではない友人のセットが選択されます。 選択した友達は現在の位置から削除され、相対的な順序が逆になり、結果のシーケンスが最前面に配置されます。 選ばれなかった友達は相対的な順序を保ちます。 

たとえば、現在のシーケンスが`1 2 3 4 5`そして私たちは選択します`{2, 4}`、選択された友達は次のように発生します`2, 4`したがって、それらを反転して前面に移動すると、次のようになります。`4 2 1 3 5`。 

最小限の操作は必要ありません。 必要なのは、変更を加える最大 15 個の操作のシーケンスだけです`a`の中へ`b`。 出力には、操作の数と、その後に各操作で選択された一連のフレンド番号が含まれます。 

値`n`は最大でも 10000 です。これは十分に大きいため、明示的に順列を試行することは不可能です。`n!`可能な注文。 1 つの操作に対してすべてのサブセットを考慮しても、すでに次のようになります。`2^n - 1`可能性は絶望的ですが、`n = 10000`。 この制約の便利な部分は、操作数が 15 に制限されていることです。 以来`2^14 = 16384 > 10000`、14 の二項決定に基づく構造で十分です。 

誤って処理しやすい微妙なケースが 2 つあります。 まず、いつ`n = 1`、可能な順列は 1 つだけです。 例えば、```text
1
1
1
```すでにターゲットを満たしているため、正しい出力は次のようになります。`0`。 やみくもに計算する構造`ceil(log2(n))`少なくとも 1 つの操作が存在すると仮定すると、誤って無効な空の操作が作成される可能性があります。 

第 2 に、入力順列には個別の値が含まれることが保証されます。 したがって、次のようなテスト```text
3
1 1 2
1 2 1
```はまったく有効なテストケースではありません。 繰り返される値を処理する必要はなく、一意のターゲット位置を持つすべての友人に依存する構築は入力によって正当化されます。 

もう 1 つの境界ケースは 2 の累乗です。 のために```text
4
4 3 2 1
1 2 3 4
```4 つのターゲット位置をすべて区別するには、ちょうど 2 ビットが必要です。 この構築では 4 つの異なる 2 ビット コードを使用するため、追加の操作は必要ありません。`n`コードスペースの容量に達しました。 

2 の累乗以外の場合、次のようになります。`n = 5`、8 つの 3 ビット コードすべてを適切な順序で並べた最初の 5 つのコードを使用します。 未使用のコードは決して友人に属さないため、結果の並べ替えには影響しません。 

## アプローチ

 直接的なアプローチでは、可能な操作を検索しようとします。 がある`2^n - 1`1 回の操作で選択できる空ではないサブセット。 1 つの候補をシーケンスに適用するとコストがかかります`O(n)`シーケンスが明示的に再構築される場合、考えられるすべての最初の操作コストを調べても`O(n 2^n)`。 複数のレベルを深く検索すると、分岐係数がおよそ 1 になるため、はるかに悪化します。`2^n`。 状態空間には`n!`州。 

すべての合法的な動きがこれらのサブセット間で明示的に表現されるため、ブルート フォースは概念的に機能します。 その失敗は完全に、膨大な数の可能なサブセットとその結果として生じる順列によって引き起こされます。 

重要な観察は、すべての友人に対して 1 つの二分決定を使用して操作を記述できるということです。 すべての友人に、その友人が作戦に参加するかどうかを少し伝えてください。 選択した友達は選択されていないすべての友達の前に移動され、選択した部分が反転されます。 

いくつかの操作を実行し、すべての友人にその参加ビットで構成されるバイナリ コードを割り当てるとします。 最終的な順序はこれらのコードによって決まります。 興味深いのは、コードの順序が通常のバイナリ順序ではないことです。 選択されたすべてのグループが反転されるため、ナチュラル コードの順序はグレイ コードの順序を反映したものになります。 

のために`k`操作、あります`2^k`考えられるバイナリコード。 すべての友達が異なるコードを受け取った場合、元の順序は無関係になります。 操作シーケンスが目的のターゲット順序を生成するようにコードを割り当てるだけで済みます。 

させて`G_k`通常のバイナリ反射グレイコード シーケンスになります。 3 ビットの場合は次のようになります。`000, 001, 011, 010, 110, 111, 101, 100`。 

私たちの操作によって生成される順序は、この順序の逆になります。`100, 101, 111, 110, 010, 011, 001, 000`。 

ターゲット位置のコードには直接式があります`r`:`code[r] = gray(2^k - 1 - r)`、

どこ`gray(x) = x XOR (x >> 1)`。 

これらのコードを、登場する順序で友達に割り当てます。`b`。 その後の操作`i`割り当てられたコードにビットがある友達を正確に選択します`i`セット。 

建設に必要なのは`ceil(log2 n)`操作。 以来`n <= 10000`、これは最大でも 14 であり、必要な制限である 15 を余裕で下回ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|

 実際の実装で使用できるのは`O(n)`すべてのコードが必要に応じて生成されるため、追加のメモリが必要になり、実際のスペース使用量はテーブルの一般的な限界よりもさらに小さくなります。 

## アルゴリズムのチュートリアル

 1. もし`a`すでに等しい`b`、出力ゼロ操作。 これは一般的な構造を正確にするために必要なわけではありませんが、可能な限り単純な答えを提供し、`n = 1`当然。 

2. 最小のものを選択します`k`そのような`2^k >= n`。 十分な違いがあります`k`-ビットコードは、すべてのターゲット位置に一意のコードを与えます。 なぜなら`n <= 10000`、私たちはいつも持っています`k <= 14`。 

3. から希望する順列の位置に番号を付けます。`0`を通して`n - 1`。 ポジションについて`r`、計算する`x = 2^k - 1 - r`そしてコードを割り当てます`x XOR (x >> 1)`。 

これらはまさに最初のものです`n`逆バイナリのコードは、グレイコード順序を反映しています。 

4. ビットごとに`i`から`0`を通して`k - 1`、1 つの操作を構築します。 ターゲットの順列をスキャンします`b`。 割り当てられたコードが`b[r]`ビットがある`i`設定、友達を入れる`b[r]`運用開始`i`。 

選択したフレンド番号が印刷される順序は関係ありません。 操作自体は、順序を逆転する前に、現在の相対順序を回復します。 

5. 全て出力する`k`ビットから昇順の演算`0`噛む`k - 1`。 

これらの操作の順序は重要です。 最後の操作は最終的なグループ化に最も大きな影響を及ぼし、操作によって引き起こされる再帰的な反転はまさに逆のグレイコード順序を与えるものです。 

### なぜ効果があるのか

 すべてを考慮してください`2^k`考えられるコード。 最初の操作の後、ビットでコード化します`0`に等しい`1`逆の順序で前に移動し、ビット付きのコードを作成します。`0`に等しい`0`後に残ります。 次の操作以降はビットに応じて同様の処理が行われます`1`、選択した部分が反転されます。 このように続けると、再帰シーケンスが得られます。`C_k = 1 + reverse(C_{k-1}), 0 + C_{k-1}`上位ビットが最初に書き込まれるとき。 塩基配列は、`C_1 = [1, 0]`。 

標準反射グレーコードは次の条件を満たします。`G_k = 0 + G_{k-1}, 1 + reverse(G_{k-1})`。 

このアイデンティティを逆転すると、`reverse(G_k) = 1 + G_{k-1}, 0 + reverse(G_{k-1})`、

 これはまさに私たちの操作によって生成されたシーケンスです。 したがって、個別のコードの最終的な順序は次のようになります。`reverse(G_k)`。 

最初のものを割り当てます`n`このシーケンスのコードを次の要素に変換します。`b`目標順に。 その結果、すべての操作の後、友人は正確な順序で表示されます。`b`。 割り当てられたコードはそれぞれ異なるため、友達のペアが関係を破るのに元の相対的な順序を必要とすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_operations(a, b):
    n = len(a)

    if a == b:
        return []

    k = 0
    while (1 << k) < n:
        k += 1

    operations = []

    # code[r] is the r-th code in reverse Gray-code order.
    # We only need the codes for the n target positions.
    codes = [0] * n
    full = (1 << k) - 1

    for r in range(n):
        x = full - r
        codes[r] = x ^ (x >> 1)

    for bit in range(k):
        mask = 1 << bit
        selected = []

        for r in range(n):
            if codes[r] & mask:
                selected.append(b[r])

        if selected:
            operations.append(selected)

    return operations

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    operations = build_operations(a, b)

    print(len(operations))
    for op in operations:
        print(len(op), *op)

if __name__ == "__main__":
    solve()

ループコンピューティング`k`少なくとも表現できる最小のビット数を見つけます。`n`異なる価値観。 のために`n = 10000`、で止まります。`k = 14`なぜなら`2^13 = 8192`小さすぎる一方で`2^14 = 16384`で十分です。

## テストケース

import sys
import io

def build_operations(a, b):
    n = len(a)

    if a == b:
        return []

    k = 0
    while (1 << k) < n:
        k += 1

    full = (1 << k) - 1
    codes = [0] * n

    for r in range(n):
        x = full - r
        codes[r] = x ^ (x >> 1)

    operations = []

    for bit in range(k):
        mask = 1 << bit
        selected = []

        for r in range(n):
            if codes[r] & mask:
                selected.append(b[r])

        if selected:
            operations.append(selected)

    return operations

def solve_string(inp):
    data = io.StringIO(inp)

    n = int(data.readline())
    a = list(map(int, data.readline().split()))
    b = list(map(int, data.readline().split()))

    operations = build_operations(a, b)

    out = [str(len(operations))]
    for op in operations:
        out.append("{} {}".format(len(op), " ".join(map(str, op))))

    return "\n".join(out) + "\n"

def run(inp: str) -> str:
    return solve_string(inp)

def validate(inp: str):
    lines = inp.strip().splitlines()
    n = int(lines[0])
    a = list(map(int, lines[1].split()))
    b = list(map(int, lines[2].split()))

    output = run(inp)
    tokens = output.split()
    ptr = 0

    k = int(tokens[ptr])
    ptr += 1

    assert 0 <= k <= 15

    current = a[:]

    for _ in range(k):
        c = int(tokens[ptr])
        ptr += 1

        assert 1 <= c <= n

        chosen = list(map(int, tokens[ptr:ptr + c]))
        ptr += c

        assert len(chosen) == c
        assert len(set(chosen)) == c
        assert all(1 <= x <= n for x in chosen)

        chosen_set = set(chosen)

        selected = []
        remaining = []

        for x in current:
            if x in chosen_set:
                selected.append(x)
            else:
                remaining.append(x)

        current = selected[::-1] + remaining

    assert ptr == len(tokens)
    assert current == b

## 特殊なケース

 のために`n = 1`、唯一可能な置換は次のとおりです。`[1]`。 以来`a`そして`b`両方に唯一の値が含まれている必要があり、それらは等しく、`build_operations`すぐに空のリストを返します。 出力は`0`操作は必要ないため、これは有効です。 

のために`n = 2`、1ビットで十分です。 逆のグレイコード シーケンスは次のとおりです。`[1, 0]`。 ターゲットが`[1, 2]`、友人`1`コードを受信します`1`そして友人`2`コードを受信します`0`。 操作はフレンドを選択するだけ`1`、初期の順列に関係なくターゲットの順序が生成されます。 

のために`n = 4`、2 ビット逆グレイコード シーケンスは次のようになります。`[2, 3, 1, 0]`、バイナリ文字列に対応`10, 11, 01, 00`。 4 つのコードはすべて異なるため、構築は容量境界で正確に機能します。 心配する必要のない未使用のコードはありません。 

のために`n = 5`、3 ビットが必要です。 割り当てられたコードは、`111, 110, 101, 100, 000`式を適用した後、適切な逆グレー順序で。 残りの 3 つのコードは使用されません。 これらは友人が所有していないため、操作には影響しません。 

のために`n = 10000`、`k = 14`なぜなら`2^13 = 8192`では不十分ですが、`2^14 = 16384`十分です。 すべての友人は一意の 14 ビット コードを受け取るため、構築に必要な操作は 14 回のみで、1 回の操作のマージンは 15 の制限内に残ります。 

最も一般的な off-by-one エラーは、`gray(r)`の代わりに`gray(2^k - 1 - r)`。 前者は通常のグレイコード順序を生成しますが、演算はその逆を生成します。 から 1 を引いたもの`2^k`も不可欠です。 使用する`2^k - r`意図した範囲外の値が生成されてしまう`k`-最初の位置のビット範囲。 

もう 1 つのよくある間違いは、演算を最上位ビットから最下位ビットに適用することです。 この構築は、ビットの昇順で実行される演算に依存します。 最後の操作は、それまでのすべての操作で作成された選択されたグループを反転し、その再帰的な反転がまさに反映されたグレイコード構造を生成するものです。 

最後に、元の順列`a`操作が選択された後は、コード構築には表示されません。 これは意図的なものです。 The assigned codes are all distinct, and the sequence of operations forces every pair of friends into the relative order determined by their codes. 最初の相対順序は中間の順列に影響を与える可能性がありますが、最終的な順序には影響を与えることはできません。`k`操作。
