 ## 解決策
 # 問題の理解

 セルのストリップがあり、それぞれが次のいずれかに着色されています。`R`または`B`。 2 つのエンドポイントの色が異なる現在のストリップに対して移動を行うことができます。 この移動により、2 つのセルの間のカットが選択され、そのストリップが 2 つの空ではないストリップに分割されます。 結果として得られる 2 つのストリップは、ゲームの独立した位置になります。 正当な手を持たなかったプレイヤーは負けるので、最適なプレイで最初のポジションが勝っているとき、ビルは正確に勝ちます。 

重要な構造上の詳細は、ストリップが最初と最後のセルにのみ基づいて再生可能であるということです。 内部の色はどのカットが役立つかを決定しますが、特定のストリップに動きがあるかどうかには直接影響しません。 

長さは 100000 に達する可能性があるため、すべての部分文字列、すべてのパーティション、またはゲーム ツリー全体を検査するアルゴリズムは実用的なものをはるかに超えています。 O(n 2 ) であっても、最大長ではすでに約 10 10 個の基本演算を意味します。 問題を入力文字ごとの一定の作業量に削減する必要がありますが、実際、最終的な観察では、作業量はさらに少なくなります。 

カットの存在のみに基づいた実装が失敗する可能性がある小さなケースがいくつかあります。 のために`R`、最初と最後のセルは同じであるため、移動はなく、答えは次のようになります。`Lose`。 1 を超える長さのすべてのストリップが切断できると想定する不用意な解決策は、誤った結果を返します。`Win`。 

のために`RRRR`、エンドポイントは再び等しいため、正しい答えは次のようになります。`Lose`。 両方の端点の色が一致する場合、内部の長さは関係ありません。 

のために`RB`、エンドポイントが異なります。 唯一可能なカットが生み出すもの`R`そして`B`、どちらも移動がないので、正解は次のとおりです。`Win`。 これは、勝ち手が存在する最小のポジ​​ションでもあります。 

のために`RBR`、ストリップ内の色が変化しても、端点は同じです。 正しい答えは、`Lose`。 現在のストリップがカットできるかどうかはエンドポイントだけで決まるため、文字列に両方の色が含まれているかどうかを確認するだけでは十分ではありません。 

# アプローチ

 直接的なブルート フォース ソリューションでは、ゲームを再帰的にモデル化できます。 現在再生可能なすべてのストリップについて、考えられるすべてのカットを試し、結果として得られる 2 つのストリップを再帰的に解決し、少なくとも 1 つのカットがポジションの負けにつながる場合はポジションが勝利であると宣言します。 これは、まさに有限公平ゲームの標準的なミニマックス定義であるため、これは正しいです。 

問題はゲームツリーのサイズです。 移動するたびに追加のストリップが 1 つ作成されるため、完全なシーケンスには n-1 カットが含まれます。 n−1 個の可能なカット境界があり、単純な再帰では、それらの境界が選択される多くの異なる順序が考慮される可能性があります。 可能な履歴の数は (n−1)! によって制限され、n=100000 ではすでに天文学的に大きくなります。 メモ化された定式化でも一般的なアプローチは保存されません。最大 2 n−1 まで、指数関数的に多くの異なるカット境界のセットが存在する可能性があります。 

ブルートフォースは、何らかの手が負け局面に到達したかどうかを明示的にチェックするため機能しますが、このゲームにはさらに強力な特性があります。 現在のストリップがカラーで始まると仮定します。`R`そしてカラーで終わります`B`。 左から右に移動すると、色は次のように変化する必要があります。`R`に`B`どこかで。 左側のセルが存在する最初の境界を選択します`R`そして右のセルは`B`。 そこをカットすると、で終わる左側のストリップが生成されます。`R`したがって、その 2 つのエンドポイントは両方とも`R`、およびで始まる右のストリップ`B`そしてで終わる`B`したがって、その 2 つのエンドポイントは両方とも`B`。 結果として得られるストリップには法的な動きはありません。 

同じ引数が色を反転しても機能します。 したがって、エンドポイントが異なるすべてのストリップは、結果として得られる両方のストリップが負けている位置に即座に移動します。 逆に、エンドポイントが等しいストリップには、法的な動きはまったくありません。 したがって、ゲーム全体は最初と最後の文字をチェックすることになります。

 | --- | --- | --- | --- |
 | ブルートフォース | 最大 O((n−1)!) のゲーム履歴 | O(n) 再帰の深さ | 遅すぎる |
 | 最適 | 入力を読み取った後の O(1) | 入力文字列の場合は O(n) | 承認済み |

 # アルゴリズムのチュートリアル

 1. ストリップを読む`s`。 最初と最後のセルだけが必要なので、考えられるゲーム状態を検査する必要はありません。 
2. 比較する`s[0]`と`s[-1]`。 それらが等しい場合、最初のストリップはプレイできないため、ビルは何も動けずに負けます。 
3. エンドポイントが異なる場合、ビルはすぐに勝つことができます。 色は 2 値であるため、最初の端点から最後の端点に移動するときに、左側が最初の色、右側が最後の色を持つ境界が存在する必要があります。 その境界でカットすると、結果として得られる両方のストリップの端点が同じ色のものになり、リッチーは動かなくなります。 
4. 印刷`Win`エンドポイントが異なる場合と、`Lose`さもないと。 

これが機能する理由: エンドポイントが等しいストリップは、正当な手を持たないため、負けの立場になります。 異なるエンドポイントを持つストリップの場合、ストリップに沿ったどこかで、最初のエンドポイントの色から 2 番目のエンドポイントの色への遷移が必然的に発生します。 このような遷移で正確に切断すると、端点が等しい 2 つのストリップが作成されます。 両者ともポジションを失っているため、ビルが 1 つの手を打つと、リッチーは法的な手を失う可能性があります。 したがって、エンドポイントが異なる場合には、初期ポジションが正確に勝ちます。

長さは少なくとも 1 であることが保証されているため、両方のインデックスが常に有効です。 特に、1 セルの文字列の場合、同じ文字を参照し、次のようになります。`Lose`必要に応じて。 

再帰、動的プログラミング、シミュレーションは必要ありません。 ゲーム理論の議論により、ゲーム全体が 1 つのエンドポイント比較にすでに縮小されています。 文字列の長さに関係する算術演算は必要ないため、Python の整数オーバーフローは無関係です。

# テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    s = sys.stdin.readline().strip()
    if s[0] != s[-1]:
        print("Win")
    else:
        print("Lose")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("RB\n") == "Win", "sample 1"
assert run("BRB\n") == "Lose", "sample 2"

# Minimum-size input
assert run("R\n") == "Lose", "single-cell strip has no move"

 # エッジケース

 次のような 1 セル ストリップの場合`R`、最初と最後の位置は同じ物理セルです。 比較`s[0] != s[-1]`false であるため、アルゴリズムは次のように出力します。`Lose`。 これにより、ゼロより長いすべてのストリップを再生可能として扱うというよくある間違いを回避できます。 

次のようなすべてが等しいストリップの場合、`RRRRRR`、エンドポイントは両方とも`R`。 現在のストリップ自体がエンドポイント条件を満たしていないため、ノーカットは正当です。 アルゴリズムはすぐに出力します`Lose`内部カットを試みることなく。 

のために`RBR`、文字列には両方の色が含まれており、色の遷移がありますが、その端点は両方とも`R`。 つまり、内部で何が起こっても、元のストリップを切断することはできません。 アルゴリズムはエンドポイントのみを比較し、正しく出力します。`Lose`。 

のために`RBRB`、エンドポイントは`R`そして`B`, つまりポジションは勝ちです。 適切なカットは最初のカットの後にあります`R`、生産`R`そして`BRB`。 2 番目のストリップにはエンドポイントがあります`B`そして`B`, 一方、最初のストリップにはセルが 1 つしかないため、結果として得られるストリップは両方とも失われています。 アルゴリズムは出力します`Win`。 

最大長の場合 (100000 の文字列など)`R`文字の場合、カット全体の検索は実行されないため、アルゴリズムは遅くなりません。 文字列を読み取り、2 つの文字を比較するため、入力とともに増加する作業は 100,000 文字の読み取りだけです。
