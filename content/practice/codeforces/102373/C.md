 ## 問題の理解

 最大 300,000 個の頂点と 300,000 個のエッジを持つ単純な無向グラフがあります。 ダイヤモンドは、同じエッジを使用する 2 つの異なる三角形で構成されます。 エッジにその両方の端点に接続された複数の頂点がある場合、それらの共通の近傍のすべてのペアが 1 つのひし形を形成します。 

エッジが (u-v) で、ちょうど (c) 個の頂点が (u) と (v) の両方に隣接しているとします。 それぞれの共通の近傍により、(u-v) を含む 1 つの三角形が得られるため、任意の 2 つの共通の近傍を選択すると、そのエッジを共有する三角形のペアが得られます。 したがって、このエッジの寄与は次のようになります。 

[
 \binom{c}{2}=\frac{c(c-1)}2.
 】

 タスクは、すべてのエッジにわたってこの値を合計することです。 

グラフには 300,000 のエッジを含めることができるため、頂点のすべてのペアを検査するアルゴリズムはすでに大きすぎます。 (O(n^2)) アルゴリズムには、最大の場合、およそ (9\cdot10^{10}) 個の頂点ペアが含まれますが、(O(n^3)) または (O(n^4)) のアプローチは完全に範囲外です。 公式の制限は 2 秒と 512 MB であるため、ソリューションには、網羅的な列挙ではなく、ほぼ線形またはおおよそ (m\sqrt m) のグラフ処理が必要です。 

誤って対処しやすい特殊なケースがいくつかあります。 グラフにはひし形を含めずに三角形を含めることができます。 例えば、```
4 4
1 2
2 3
3 4
4 1
```には三角形がまったくないので、答えは次のようになります。`0`。 すべての三角形をひし形として扱う三角形カウントの実装は、誤って返します。`1`。 

4 つの頂点上の完全なグラフも便利なケースです。```
4 6
1 2
1 3
1 4
2 3
2 4
3 4
```答えは`6`、 ない`1`。 すべてのエッジは 2 つの三角形に属し、6 つのエッジのそれぞれが 1 組の三角形を与えます。 4 つの頂点の各セットを 1 回だけカウントする不注意な実装では、5 つのひし形を見逃すことになります。 

1 つのエッジの周囲に複数の三角形がある場合もあります。 考慮する```
5 7
1 2
1 3
2 3
1 4
2 4
1 5
2 5
```エッジ (1-2) は、頂点 (3、4、5) を使用する 3 つの三角形に属します。 これらの三角形のうち任意の 2 つがひし形を形成し、(\binom32=3) が得られます。 各三角形は複数のひし形に関与しているため、三角形を数えて単純に 2 で割っても機能しません。 

## アプローチ

 最も直接的なブルート フォース ソリューションは、すべての 4 つの頂点セットを考慮します。 ダイヤモンドは常に 4 つの異なる頂点を使用します。 これら 4 つの頂点の中には 6 つの可能なエッジがあります。 ちょうど 5 つ存在する場合、4 つの頂点が 1 つのひし形を形成します。 6 つすべてが存在する場合、それらは (K_4) を形成します。これには、共有エッジの選択ごとに 1 つずつ、6 つの異なるダイヤモンドが含まれます。 

したがって、すべての 4 つ組について、その 6 つの可能なエッジを調べて、答えに 0、1、または 6 のいずれかを追加できます。 これは正しいですが、次のようなものもあります。 

[
 \binom n4=O(n^4)
 】

 四倍。 (n=300000) では、これは 4 倍数あたり 6 つのエッジ チェックを考慮する前に、(3.4\cdot10^{20}) 4 倍数のオーダーになります。 このアプローチは、概念的なベースラインとしてのみ役立ちます。 

重要な観察は、4 つの頂点を直接見るのをやめるということです。 すべてのエッジ (u-v) について必要な情報は、その共通の近傍の数だけです。 すべての三角形のペアを明示的に構築する代わりに、最初にすべての三角形を列挙し、どの 3 つのエッジがそれに属しているかを記録することができます。 

エッジが既に (k) 個の三角形に現れており、そのエッジを含む別の三角形が見つかった場合、その新しい三角形は、以前に見つかった三角形と正確に (k) 個の新しいダイヤモンドを形成します。 したがって、三角形が検出されると、その 3 つのエッジのそれぞれについて、そのエッジの現在の三角形数を答えに追加し、そのエッジの三角形数を増やします。 

残りの問題は、効率的な三角形の列挙です。 すべての頂点の近傍のすべてのペアをチェックすることは、高次の頂点を持つスターまたは別のグラフでは二次関数になる可能性があります。 これを回避する標準的な方法は、頂点の次数に従ってすべてのエッジの方向を設定することです。 エッジは、次数が小さい端点から次数が大きい端点まで進み、頂点番号によって等しい次数の関係を分割します。 次に、これらの前方エッジを通してのみ三角形を検索します。 

この次数の順序付けは、標準の次数指向の三角形カウント限界である (O(m\sqrt m)) によって前方ウェッジ探索の総量を制限します。 同じ考え方が、スパース グラフでの効率的な三角形および 4 サイクルの列挙にも一般的に使用されます。 

すべてのダイヤモンドは 4 頂点構造であるため、ブルート フォースは機能しますが、4 頂点セットが多すぎるため失敗します。 ダイヤモンドは単にエッジを共有する三角形のペアであるという観察により、問題を三角形の列挙と各エッジに対する小さなカウンターに縮小できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^4)) | (O(m)) | 遅すぎる |
 | 最適 | (O(m\平方メートル)) | (O(n+m)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフを読み取り、すべての頂点の次数を計算します。 エッジの方向を設定する前に角度が必要です。これは、方向によって後の三角形の検索が小さく保たれるためです。 
2. すべての頂点に次の順序を与えます。`(degree, vertex_id)`。 エッジは、この順序で小さい頂点から大きい頂点に向けられます。 等しい次数は頂点番号によって解決されるため、すべてのエッジは正確に 1 つの方向を受け取ります。 
3. 各頂点の出方向エッジのみを保存します。 後でそのエッジに属する三角形の数を更新する必要があるため、宛先とともに元のエッジ ID を保存します。 
4. 配列を維持する`mark`。 頂点 (v) の処理中に、すべての出力近傍 (w) に (v-w) のエッジ ID をマークします。 これにより、(v) とマークされた頂点の間のエッジへの一定時間のアクセスが可能になります。 
5. すべての出力エッジ (v\rightarrow u) について、すべての出力エッジ (u\rightarrow w) をスキャンします。 (w) が現在 (v) でマークされている場合、(v,u,w) は三角形を形成します。 エッジ (v-u)、エッジ (u-w)、およびマークされたエッジ (v-w) の 3 つのエッジ ID がすぐにわかります。 
6. 三角形が見つかったら、その 3 つの辺が現在、以前に見つかった三角形 (a)、(b)、および (c) に属していると仮定します。 新しい三角形は、(a+b+c) 個の新しいひし形を形成します。これは、これらのエッジのいずれかを共有する以前のすべての三角形と組み合わせることができるためです。 その値を答えに加算し、3 つのエッジ カウンターをすべてインクリメントします。 
7. 次の頂点に移動する前に、(v) の出力近傍に属するマークをクリアします。 クリア手順により、ある中心としてマークされた頂点が別の中心の隣接頂点と間違われるのを防ぎます。 

### なぜ効果があるのか

 すべての三角形には、選択された合計順序の下で一意の最小頂点があります。 他の 2 つの頂点は両方ともその頂点より大きく、これら 2 つの大きい頂点間のエッジは小さい方の頂点から大きい方の頂点に向いています。 したがって、三角形は、最小の頂点が処理されるときに 1 回だけ検出されます。 

すべてのエッジについて、そのカウンターは、そのエッジを含むこれまでに発見された三角形の数と正確に一致します。 エッジを含む新しい三角形が見つかると、そのエッジ上で以前にカウントされた各三角形とともに 1 つの新しいひし形が形成されます。 したがって、インクリメントする前に古いカウンタを追加すると、三角形のすべてのペアが 1 回だけカウントされます。 すべてのダイヤモンドは正確に 1 つのエッジを共有する 1 組の三角形であるため、累積された答えは正確に必要なダイヤモンドの数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    degree = [0] * n
    edges = [None] * m

    for eid in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges[eid] = (u, v)
        degree[u] += 1
        degree[v] += 1

    order = sorted(range(n), key=lambda v: (degree[v], v))
    pos = [0] * n
    for i, v in enumerate(order):
        pos[v] = i

    out = [[] for _ in range(n)]

    for eid, (u, v) in enumerate(edges):
        if pos[u] < pos[v]:
            out[u].append((v, eid))
        else:
            out[v].append((u, eid))

    triangle_count = [0] * m
    mark = [-1] * n
    answer = 0

    for v in range(n):
        ov = out[v]

        for w, eid in ov:
            mark[w] = eid

        for u, eid_vu in ov:
            for w, eid_uw in out[u]:
                eid_vw = mark[w]

                if eid_vw != -1:
                    answer += (
                        triangle_count[eid_vu]
                        + triangle_count[eid_uw]
                        + triangle_count[eid_vw]
                    )

                    triangle_count[eid_vu] += 1
                    triangle_count[eid_uw] += 1
                    triangle_count[eid_vw] += 1

        for w, _ in ov:
            mark[w] = -1

    print(answer)

if __name__ == "__main__":
    solve()
```最初のパスのビルド`degree`すべてのエッジを安定した ID で保存します。 ID が必要なのは、最終的な答えは、単に合計でいくつの三角形が存在するかだけではなく、それぞれの特定のエッジを使用する三角形の数によって決まるためです。 

の`order`配列は度の方向を実装します。`pos[v]`はその順序で頂点の位置を与えるため、すべての無向エッジを 1 回の比較で方向付けることができます。 送信隣接リストには次のものが含まれます。`(neighbor, edge_id)`これにより、別の辞書検索を行わずに、トライアングル検索で 3 つのエッジ カウンタすべてを識別できるようになります。 

の`mark`配列は頂点ごとに再利用されます。 加工時`v`、`mark[w]`すべての前方隣接 (w) のエッジ ID (v-w) が含まれます。 したがって、内側のループが頂点に到達すると、`w`から`u`、`mark[w] != -1`はまさに (v-w) も存在する条件です。 

答えは、3 つのカウンターがインクリメントされる前に更新されます。 エッジが (k) 個の以前の三角形に出現している場合、新しい三角形はそのエッジと (k) 個の新しいペアを作成します。 最初に更新すると、それ自体とペアになった新しい三角形がカウントされますが、これは無効です。 

Python の整数には任意の精度があるため、可能な最大の答えであってもオーバーフローすることはありません。 たとえば、775 個の頂点を持つ完全なグラフには、すでに 89,491,021,650 個のダイヤモンドがあります。

import sys
import io

def solve_data(inp: str) -> str:
    data = inp.split()
    it = iter(data)

    n = int(next(it))
    m = int(next(it))

    degree = [0] * n
    edges = [None] * m

    for eid in range(m):
        u = int(next(it)) - 1
        v = int(next(it)) - 1
        edges[eid] = (u, v)
        degree[u] += 1
        degree[v] += 1

    order = sorted(range(n), key=lambda v: (degree[v], v))
    pos = [0] * n

    for i, v in enumerate(order):
        pos[v] = i

    out = [[] for _ in range(n)]

    for eid, (u, v) in enumerate(edges):
        if pos[u] < pos[v]:
            out[u].append((v, eid))
        else:
            out[v].append((u, eid))

    cnt = [0] * m
    mark = [-1] * n
    ans = 0

    for v in range(n):
        for w, eid in out[v]:
            mark[w] = eid

        for u, e1 in out[v]:
            for w, e2 in out[u]:
                e3 = mark[w]
                if e3 != -1:
                    ans += cnt[e1] + cnt[e2] + cnt[e3]
                    cnt[e1] += 1
                    cnt[e2] += 1
                    cnt[e3] += 1

        for w, _ in out[v]:
            mark[w] = -1

    return str(ans)
