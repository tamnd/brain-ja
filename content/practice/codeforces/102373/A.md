## アプローチ

 直接的な解決策では、次のすべての部分文字列を列挙できます。`s`。 固定された左端点の場合、右端点を一度に 1 文字ずつ拡張し、現在の部分文字列内のすべての文字の頻度を維持し、それらの頻度が次の頻度内に収まるかどうかを確認します。`t`。 チェックが一定時間維持される場合、`n(n+1)/2`拡張機能があるため、最悪の場合の実行時間は次のようになります。`Theta(n^2)`。 のために`n = 10^6`、それは約です`5 * 10^11`2 秒の制限をはるかに超えた部分文字列の拡張。 拡張子ごとに 26 文字すべての文字数を再チェックすることは依然として問題です`Theta(26n^2)`、これは同じ漸近的失敗です。 

有益な観察は、有効な部分文字列が部分間隔を取ると閉じられるということです。 部分文字列を組み立てることができる場合`t`、文字を削除しても無効にはなりません。 これにより、すべての開始位置に単調な境界が与えられます。 ポジションごとに`i`、 定義する`r[i]`最大の正しいエンドポイントとして、`s[i..r[i]]`有効です。 次に、次で始まるすべての部分文字列`i`そしてそれ以前に終わる`r[i]`も有効です。 

もう 1 つの重要な単調性特性があります。 スタート位置が移動した場合`i`に`i + 1`、有効な右端点の最大値を左に移動することはできません。 削除中`s[i]`現在のウィンドウを満たすことが容易になるため、`r[i+1] >= r[i]`。 公式社説では、まさにこのプロパティを使用して、独立した境界検索を 1 つのスライディング ウィンドウ パスに変換しています。 

したがって、ウィンドウを 1 つ維持できます`[left, right)`そのウィンドウの文字数も表示されます。 延長します`right`ウィンドウが有効な間。 次の文字を追加すると、使用可能なカウントに違反する場合`t`、やめます。 で始まるすべての部分文字列`left`そしてその前に終わる`right`は有効なので、`right - left`彼らのうち。 次に、削除します`s[left]`そして移動します`left`フォワード。 なぜなら`right`決して後退することはなく、すべての文字がウィンドウに出入りするのは最大 1 回だけです。

 ## アルゴリズムのチュートリアル

 1.読む`s`そして`t`、各小文字が何回出現するかを数えます。`t`。 これらのカウントは、有効な部分文字列が使用できる最大頻度です。 
2. 周波数配列を維持する`have`現在のウィンドウの場合`s`。 も保管してください`right = 0`そして答えはゼロに初期化されます。 現在のウィンドウは`[left, right)`、 それで`right`は現在含まれていない最初の位置です。 
3. それぞれについて`left`から`0`に`len(s) - 1`、延長してみてください`right`追加しながら`s[right]`その周波数が対応する周波数を超えることはありません。`t`。 成功したすべての拡張は有効性を保持します。 
4. 次の文字を追加できなくなると、現在のウィンドウが`[left, right)`で始まる最長の有効な部分文字列です。`left`。 からのすべての終了位置`left`を通して`right - 1`は有効なので追加します`right - left`答えに。 
5. 次の開始位置に移動する前に、`s[left]`から`have`。 これはウィンドウを次から変更することに対応します。`[left, right)`に`[left + 1, right)`。 私たちは決して動かない`right`左端の文字を削除しても、残りのウィンドウの有効性が低下することはないためです。 
6. 蓄積された回答を印刷します。 部分文字列の最大数は次のとおりであるため、Python 整数で十分です。`n(n+1)/2`、それは約です`5 * 10^11`のために`n = 10^6`。 

### なぜ効果があるのか

 あらゆる人にとって`left`、アルゴリズムは次の不変条件を維持します。`[left, right)`から始まる最長の有効なウィンドウです。`left`。 より短いウィンドウごとにその前に終了します`right`文字のコピーをそれ以上使用しないため、これも有効です。 次の文字は含めることができません。含めると次の文字を含めることができません。`t`その文字で使用可能な頻度が制限されるため、で始まる部分文字列はなくなります。`left`有効です。 

取り外し後`s[left]`、前の`right`文字を削除しても頻度を増やすことはできないため、新しい開始位置の有効な境界は依然として残ります。 その後アルゴリズムは拡張されます`right`必要な範囲でのみ。 したがって、すべての有効な部分文字列は、それ自身の左端点で 1 回だけカウントされ、無効な部分文字列はカウントされません。 以来`right`前方にのみ移動する場合、ウィンドウの拡張と削除の合計数は線形です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    limit = [0] * 26
    for ch in t:
        limit[ord(ch) - 97] += 1

    have = [0] * 26
    n = len(s)
    right = 0
    answer = 0

    for left in range(n):
        while right < n:
            c = ord(s[right]) - 97
            if have[c] == limit[c]:
                break

            have[c] += 1
            right += 1

        answer += right - left

        c = ord(s[left]) - 97
        if left < right:
            have[c] -= 1

    print(answer)

if __name__ == "__main__":
    solve()
```最初の部分のビルド`limit`、 どこ`limit[c]`正確にキャラクターのコピー数です`c`で利用可能です`t`。 文字の実際の位置を保存する必要はありません。`t`なぜなら、彼らの順序には関連性がないからです。`have`現在の部分文字列内の周波数を保存します。 条件`have[c] == limit[c]`キャラクターの別のコピーを追加することを意味します`c`ウィンドウが無効になります。 後でウィンドウを追加したり修理したりするのではなく、すぐに停止できます。 

表現`right - left`で始まる有効な部分文字列の数です。`left`。 ウィンドウはハーフオープンインデックスを使用するため、`[left, right)`正確に含まれています`right - left`文字。 空ではないプレフィックスは次で終わります。`left`、`left + 1`、 を通して`right - 1`、まさにそれだけ多くの選択肢が与えられます。 

これらの部分文字列を数えた後、次の文字が`left`が削除されます。 の`if left < right`ガードはウィンドウが空の場合を処理します。 その状況で`right == left`したがって、維持されたウィンドウから削除する文字はありません。 これは、特定の文字が出現しない文字列も処理します。`t`。 

二分探索、接尾辞構造、または 2 次元頻度表は必要ありません。 アルファベットには 26 文字しかなく、右境界の単調性により、1 つの移動ウィンドウで全体の解が得られます。 線形時間アプローチは、ITMO の公式社説で説明されているのと同じ中心的なアイデアです。
