 ## 問題の理解

 頂点が 2 色で着色された木があり、次のように表されます。`0`そして`1`。 1 つの操作を払って、まだ存在する 1 つの頂点の色を反転するか、頂点を選択して、その頂点を含む現在の色の接続されたコンポーネント全体を破棄し、同様に 1 つの操作を支払うことができます。 目標は、できるだけ少ない操作ですべての頂点を削除することです。 

答えは単純に現在の単色コンポーネントの数ではありません。慎重に選択した頂点を再カラーすると、いくつかのコンポーネントがマージされ、1 つの連鎖反応ですべてのコンポーネントが削除される可能性があるからです。 サンプルはまさにこれを示しています: 中心色の星で`1`そして三つ葉の色`0`、中心を次のように変更します`0`は 1 つの単色コンポーネントを作成するため、2 つの操作で十分です。 

ツリーには以下が含まれます`200000`頂点。 木は正確に持っているので、`n - 1`エッジでは、入力の読み取りと処理にはすでに線形時間が必要です。 二次関数の動作を伴うアルゴリズムは、このサイズでは遅すぎるため、カラーリングに対する指数関数的な検索は完全に不可能です。 意図したソリューションでは、すべての頂点とエッジを一定の回数だけ処理する必要があります。`O(n)`時間。 

表面的な解決策では失敗する可能性がある小さなケースがいくつかあります。 たとえば、頂点が 1 つある場合、```
1
0
```答えは`1`なぜなら、単一の頂点は単純に破壊できるからです。 常に色変更操作を追加する数式は、誤って返されます。`2`。

## アプローチ

 直接的な総当たりアプローチは、すべての頂点が破棄される直前にその色を決定することです。 がある`2^n`可能なターゲットカラーリング。 ターゲットのカラーリングごとに、色が変化した頂点の数とそれに含まれる単色の連結コンポーネントの数を数えて、最小値を取得します。 1 つの色を評価するのにかかる時間`O(n)`すべての頂点とエッジを検査するため、合計の複雑さは次のようになります。`Theta(n * 2^n)`。 これは数十の頂点ではすでに絶望的です、ましてや`200000`。 

有益な観察は、連鎖反応を実際にシミュレートする必要がないということです。 

操作の完全なシーケンスを検討してください。 すべての頂点に、破壊された瞬間の色を与えます。 最終的な破壊の色が最初の色と異なるすべての頂点は、少なくとも 1 回は色を変更する必要があります。 次に、同じ破壊色を受け取る 2 つの隣接する頂点を見てください。 それらが異なる連鎖反応で破壊された場合、概念的にはそれらの反応を 1 つの単色コンポーネントに統合することができ、これにより破壊操作の数を減らすことしかできません。 したがって、最適な戦略は、ツリーの最終的なバイナリ色付けによって表すことができます。 

最終的なカラーリングが固定されている場合、必要な再カラーリング操作の回数は、元のカラーリングからのハミング距離と同じになります。 連鎖反応の数は、最終的な着色における単色の接続コンポーネントの数です。 

グラフはツリーであるため、このコンポーネント数は特に単純な形式になります。 1 つのコンポーネントから始めます。 最終的な色が異なる端点を持つ各エッジは 2 つのコンポーネントを分離しますが、端点が同じ色のエッジは 1 つのコンポーネント内に残ります。 その結果、`number of components = 1 + number of edges whose endpoints have different colors`。 

したがって、問題全体が最小化されます。`1 + sum over vertices [final_color != initial_color] + sum over edges [final_color differs across the edge]`。 

これは標準的な 2 状態ツリー DP です。 各頂点について、その頂点が最終的​​な色を受け取るときのサブツリーの最小コストを計算します。`0`または`1`。 子の寄与は、子の最終色が親の最終色と等しいかどうかのみに依存するため、各子は独立して処理できます。 

考えられるすべての最終的な色付けが破壊プロセスを組織する有効な方法を記述しているため、強引な方法は機能しますが、色付けの数が指数関数的に多いため失敗します。 目的が独立した頂点コストとエッジ コストのみで構成されているという観察により、これらを最適化できます。`2^n`ツリー上の 2 つの状態の DP による選択肢。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n * 2^n)`|`O(n)`| 遅すぎる |
 | 最適なツリー DP |`O(n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーの頂点にルートを作成します`0`。 目的は無向ツリーで定義されるため、ルートの選択は任意です。 
2. 頂点ごとに`v`、2 つの値を維持します`dp[v][0]`そして`dp[v][1]`。`dp[v][c]`のサブツリーによって寄与される最小コストです。`v`もし`v`最終的な色を受け取ります`c`、グローバルを除く`+1`最初の連結成分に対応します。 
3. の状態を初期化します。`v`再着色費用がかかります。 オリジナルカラーであれば、`v`すでに`c`、この費用は`0`; それ以外の場合はそうです`1`。 
4. すべての子を処理する`u`の`v`。 もし`u`同じ色を受け取ります`c`として`v`、エッジ`(v,u)`追加の単色コンポーネント境界は作成されないため、子が寄与します。`dp[u][c]`。 もし`u`反対の色を受け取ります。エッジは 2 つのコンポーネント間の境界であり、`dp[u][1-c] + 1`。 

したがって、固定親色の遷移は`c`は`dp[v][c] += min(dp[u][c], dp[u][1-c] + 1)`。 

の`+1`2 番目のオプションは、端点が異なる最終色を持つエッジを表します。 
5. 頂点を事後順序で処理し、親が計算される前にすべての子の DP 値がわかるようにします。 ツリーは長さのパスになる可能性があるため、Python では反復トラバーサルが推奨されます。`200000`、これは Python のデフォルトの再帰呼び出しの深さを超えます。 
6. ルートでは、最終的な色の安い方を選択します。 最後に追加します`1`グローバルコンポーネント数項の場合、次のようになります。`answer = 1 + min(dp[root][0], dp[root][1])`。 

余分な`1`空ではないツリーには少なくとも 1 つの単色コンポーネントがあるため、常に存在します。 

### なぜ効果があるのか

 選択した最終的なカラーリングでは、カラーが変更されたすべての頂点の再カラーリング操作が 1 回だけかかり、異なる最終カラーを結合するすべてのエッジで単色コンポーネントの数が 1 つだけ増加します。 ツリーは 1 つのコンポーネントから始まるため、そのカラーリングの総コストは正確に DP 目標に 1 を加えたものになります。 

逆に、実際の一連の操作は、頂点が破棄されるときに各頂点にその色を割り当てることによって、そのような最終的な色に変換できます。 シーケンス内の再カラーリングの数は、最終カラーが最初のカラーと異なる頂点の数以上であり、破壊操作の数は、少なくとも最終カラーリングの単色コンポーネントの数です。 したがって、DP 目標を最適な操作シーケンスのコストより大きくすることはできません。 すべての DP カラーリングについて、最初に必要な再カラーリングを実行し、次に各単色コンポーネントを破棄することで、DP 値を達成できます。 2 つの方向により最適性が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    graph = [[] for _ in range(n)]

    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    parent = [-1] * n
    order = [0]
    parent[0] = n

    for v in order:
        for u in graph[v]:
            if u == parent[v]:
                continue
            parent[u] = v
            order.append(u)

    dp0 = [0] * n
    dp1 = [0] * n

    for v in reversed(order):
        original = ord(s[v]) - ord('0')

        dp0[v] = 1 if original != 0 else 0
        dp1[v] = 1 if original != 1 else 0

        for u in graph[v]:
            if parent[u] != v:
                continue

            dp0[v] += min(dp0[u], dp1[u] + 1)
            dp1[v] += min(dp1[u], dp0[u] + 1)

    print(1 + min(dp0[0], dp1[0]))

if __name__ == "__main__":
    solve()
```隣接リストには、通常の無向形式でツリーが格納されます。 まさにあるので、`n - 1`エッジではリニアメモリを使用します。 

最初の走査構造`parent`そして`order`。 なぜなら`order`はルートから離れることによって生成され、それを反転すると有効なボトムアップ順序が得られます。 これにより再帰が完全に回避され、次のようなパス形状のツリーに役立ちます。`200000`頂点。 

2 つの DP 配列には、可能な 2 つの最終色が個別に格納されます。 元の色が次の頂点の場合`0`、`dp0[v]`から始まります`0`その間`dp1[v]`から始まります`1`。 オリジナルでは逆のことが起こります`1`。 

子供の頃`u`親に強制的に色を付ける`0`、可能性は2つだけです。 保管`u`で`0`費用`dp0[u]`、色を付けながら`1`費用`dp1[u] + 1`接続エッジが単色成分間の境界になるためです。 同じ理由で親色の遷移が得られます。`1`。 

テスト`if parent[u] != v`隣接リストにはすべてのエッジの両方向が含まれるため、これが必要になります。 これにより、親が別の子であるかのように処理されるのを防ぎます。 

すべてのコストは最大でも次の数倍です`n`, そのため、Python の整数にはオーバーフローの問題はありません。 の使用`sys.stdin.readline`入力処理を線形かつ十分に高速に保ちます。`200000`エッジ。

import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()

    graph = [[] for _ in range(n)]

    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        graph[a].append(b)
        graph[b].append(a)

    parent = [-1] * n
    order = [0]
    parent[0] = n

    for v in order:
        for u in graph[v]:
            if u == parent[v]:
                continue
            parent[u] = v
            order.append(u)

    dp1 = [0] * n

    sys.stdin = io.StringIO(inp)
    try:
        return solve().strip()
    finally:
        sys.stdin = old_stdin
