 ## 問題の理解

 配列があります`a[1..n]`、 どこ`a[i]`位置にある子の数です`i`。 古いペニーワイズは接頭辞、位置を取得します`1`を通して`l`、現代のペニーワイズは接尾語をとりますが、`r`を通して`n`。 2 つのセグメントは重なってはなりません。`l < r`。 

選択したペアについて`(l, r)`、2つのスコアは次のとおりです。`S1 = a[1] + ... + a[l]`そして`S2 = a[r] + ... + a[n]`。 

タスクは、最小化する有効なペアを見つけることです。`|S1 - S2|`、その最小の差を対応するものと一緒に出力します。`l`そして`r`。 

制約`n <= 10^6`は主要なアルゴリズム信号です。 およそ 100 万のポジションが存在する可能性があるため、`O(n^2)`検索は完全に不可能です。 たとえ`O(n log n)`正の配列値により線形スキャンが可能な単調構造が得られるため、ここではアプローチは不要です。 値自体は次のように大きくできます。`10^9`、合計が到達する可能性があります`10^15`。 C++ ではこれらの合計に 64 ビット整数型が必要ですが、Python 整数ではすでに安全に処理されています。 

実装が通知なく失敗する可能性がある境界ケースがいくつかあります。 と`n = 2`、唯一の有効なペアは`l = 1, r = 2`。 入力用```
2
8 3
```正しい結果は```
5 1 2
```なぜなら、2つのスコアは`8`そして`3`。 最初のペアを評価する前にポインターを 1 つ移動する実装では、唯一の有効な答えを見逃す可能性があります。 

2 番目のエッジ ケースは、2 つの最初のセグメントの合計がすでに等しい場合に発生します。 のために```
4
7 1 1 7
```ペア`l = 1, r = 4`スコアを与える`7`そして`7`、したがって、答えは次のとおりです```
0 1 4
```差分をチェックする前に常にポインタの移動を実行する不注意な実装では、最適なゼロを見逃す可能性があります。 

反対側のポインター境界も同様に重要です。 考慮する```
3
1 2 3
```最初と最後の要素から始めるとスコアが得られます`1`そして`3`。 左のスコアが小さいため、左ポインタが の位置に移動します。`2`、与える`3`そして`3`。 正しい結果は```
0 2 3
```条件が間違って書かれていて、等号または最終的な有効な位置によって余分な動きが発生する場合、ペアは`(2, 3)`スキップすることができます。 

## アプローチ

 直接的なアプローチではすべてのペアを考慮します`(l, r)`満足のいく`l < r`。 各ペアについて、事前に計算されたプレフィックスの合計を使用してプレフィックスとサフィックスの合計を計算できるため、各候補は次のようになります。`O(1)`時間。 がある`n(n-1)/2`有効なペア、つまり`O(n^2)`。 のために`n = 10^6`、それは約です`5 * 10^11`競技プログラミングの時間制限をはるかに超えています。 

2 つの合計の構造により、はるかに優れた検索方法が得られます。 現在の左のスコアが`S1`そして現在の正しいスコアは`S2`。 すべての配列要素は正の値です。 もし`S1 < S2`、移動してプレフィックスを拡張します`l`1 つ右の位置は厳密に増加します`S1`、右側の接尾辞は変更しないままにします。 この状況で正しい境界を移動すると、`S2`しかし、2 つの境界を小さい方の増加と大きい方の減少の間の競合とみなすことで、より直接的に推論することができます。 

便利な 2 ポインター プロセスは、可能な限り幅の広いペアから始まります。`l = 1`そして`r = n`。 プレフィックスの合計が小さい場合は、次へ進みます。`l`、そうすることでのみ、より小さい合計が追いつくことができるからです。 サフィックスの合計が小さい場合は減少します`r`, そうして初めてその合計が追いつくことができるからです。 すべての状態の後、絶対的な差をチェックし、最良のものを維持します。 

なぜこれで十分なのでしょうか? プレフィックスの合計は次のように単調増加します。`l`右に移動すると、接尾辞の合計は次のように単調に縮小します。`r`右に移動します。 最適なペアは、これら 2 つの単調量が交差する点またはその付近で発生する必要があります。 2 ポインター プロセスはその交差点に直接移動し、その周囲で必要なすべての状態を評価します。 

ブルートフォース手法は、考えられるすべての境界ペアを検査するため機能します。 このようなペアは二次関数的に多く存在するため、失敗します。 一方の和は上向きにしか移動できず、もう一方の和は下向きにしか移動できないという観察により、各比較後に候補ペアの領域全体を破棄して、検索を次のように短縮できます。`O(n)`州。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、初期化します。`l = 0`そして`r = n - 1`。 これらは内部的にゼロベースであるため、位置を表します`1`そして`n`必要な出力に。 セット`left_sum = a[l]`そして`right_sum = a[r]`。 

この開始状態は常に有効です。`n >= 2`、 それで`l < r`。 
2. これら 2 つの初期合計の差を使用して最良の答えを初期化します。 最初のペアがすでに最適である可能性があるため、対応するポインターをすぐに保存することが必要です。 
3. その間`l < r`、 比較する`left_sum`そして`right_sum`。 もし`left_sum <= right_sum`、 前進`l`そして追加します`a[l]`左の合計に。 それ以外の場合は減少します`r`そして追加します`a[r]`適切な金額に。 

左の合計が小さい場合、その側を大きくする唯一の動きはプレフィックスを増やすことです。 正しい合計が小さい場合、減少します`r`は接尾辞に別の要素を加えて、その側面を大きくする動きです。 
4. ポインタを移動するたびに、新しい絶対差と、これまでに見つかった最良の差を比較します。 それが小さい場合は、現在のポインターを保存します。 

移動後の状態は、2 つの合計が等しくなるか交差する最初の点になる可能性があるため、初期状態のみをチェックするだけでは十分ではありません。 
5. 停止するタイミング`l == r`。 その時点で、選択した 2 つのセグメントは位置を共有するため、ペアは無効になります。 保存されているゼロベースのインデックスを 1 ベースのインデックスに変換し、その差を出力します。`l + 1`、 そして`r + 1`。 

### なぜ効果があるのか

 あらゆる有効な状態で、`left_sum`で終わる接頭辞の合計です。`l`、 そして`right_sum`で始まる接尾辞の合計です。`r`。 だって全部`a[i]`ポジティブで、動いている`l`右は移動中に左の合計を厳密に増加させます`r`左は右の合計を厳密に増加させます。 

左側の合計が小さい場合、差を減らすための有効な試みは、右側に追いつくまで左側を増やす必要があります。 アルゴリズムはまさにそれを行います。 対称的に、右の合計が小さい場合、右のセグメントが拡張されます。 したがって、ポインタは常に 2 つの単調和が最も近い点に向かって移動します。 アルゴリズムは、交差前の状態と交差後の状態を含む、このパスに沿ったすべての状態の違いをチェックします。 したがって、これらの状態間の最小値は、すべての有効な境界ペアにわたるグローバル最小値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    l = 0
    r = n - 1

    left_sum = a[l]
    right_sum = a[r]

    best_diff = abs(left_sum - right_sum)
    best_l = l
    best_r = r

    while l < r:
        if left_sum <= right_sum:
            l += 1
            left_sum += a[l]
        else:
            r -= 1
            right_sum += a[r]

        if l >= r:
            break

        diff = abs(left_sum - right_sum)
        if diff < best_diff:
            best_diff = diff
            best_l = l
            best_r = r

    print(best_diff, best_l + 1, best_r + 1)

if __name__ == "__main__":
    solve()
```配列が保存されるのは、右ポインターが左に向かって移動できるためです。そのため、アルゴリズムでは、新しく組み込まれた要素へのランダム アクセスが必要です。 初期合計には次の値が使用されます。`a[0]`そして`a[n - 1]`、可能な最小のプレフィックスとサフィックスを表します。 

比較には、`<=`左側用。 合計が等しい場合、技術的にはどちらのポインタも移動できますが、現在の状態が可能な限り最良の差であるゼロとしてすでに記録されているため、左のポインタを選択するだけで十分です。 

ポインタを移動した後、コードは最初にチェックを行います。`l >= r`。 これにより、プレフィックスとサフィックスが重複する無効なペアが評価されるのを防ぎます。 最初のペアはループに入る前に個別に評価されるため、最初のペアはループに入る前に個別に評価されます。`n = 2`正しく処理されます。 

Python の任意精度の整数は、次の合計を安全に保存します。`10^15`。 アルゴリズムは、ポインタの移動ごとに一定量の作業のみを実行し、各ポインタは最大で`n`ポジション。
