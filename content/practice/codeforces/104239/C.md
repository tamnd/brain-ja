 ## 解決策
 ## 問題の理解

 2 つの整数シーケンスが与えられ、それぞれが 2 つの別々の棚にあるトロフィーの順序を表します。 各シェルフ内では、すべての値は個別ですが、両方のシェルフに同じ値が表示される場合があります。 目標は、元のシーケンスの両方をサブシーケンスとして含む単一のシーケンスを構築することです。つまり、要素は削除できますが、残っているものを並べ替えることはできません。 このような有効なマージされたシーケンスすべての中で、可能な限り長さが短いものが必要です。 複数のシーケンスがその最適な長さを持つ場合、最初の要素ができるだけ小さいものを選択します。 

これはまさに 2 つのシーケンスに対する最短の共通スーパーシーケンス問題ですが、結果として得られるシーケンスの最初の要素に追加のタイブレークが含まれています。 

この制約により、シーケンスごとに最大 200,000 個の要素が許可されるため、完全な状態空間にわたる二次動的計画法は直ちに不可能になります。 最短のスーパーシーケンスを直接計算しようとする単純なアプローチでは、O(nm) DP またはインターリーブの明示的な列挙が必要になりますが、どちらも実現可能な限界をはるかに超えています。 

主要な構造上の制約は、各値が各シーケンス内で最大 1 回しか出現しないことです。 これにより、オーバーラップの性質が大きく変わります。共通の要素は一意に一致する可能性があり、問題は共有の値のセットに対して 2 つの順列を揃えることに帰着します。 

2 つのシーケンスに共通の要素がない場合、微妙なエッジ ケースが発生します。 その場合、すべての有効なスーパーシーケンスにはすべての要素が含まれている必要があり、その答えは、最初の要素を最小限に抑えながら内部順序を尊重する単純なマージです。 単純な LCS ベースの再構成は、LCS が空の場合には壊れてはなりません。LCS が空の場合は、アンカー ポイントが存在しないからです。 

最初の要素が大きく異なる場合、別の特殊なケースが発生します。 辞書編集上最小の最初の要素の要件により、グローバルな優先順位が強制されますが、これは両方のシーケンスがサブシーケンスのままであるという要件に違反することはできません。 将来のアライメントを考慮せずに、常に利用可能な最小のヘッドを選択する不用意な貪欲なマージは、ここでは依然として正しいかもしれませんが、それは最短のスーパーシーケンスの構造を通じて正当化される必要があります。 

## アプローチ

 ブルートフォースアプローチでは、順序を維持しながら 2 つのシーケンスのすべてのインターリーブを試行してスーパーシーケンスを構築しようとします。 最短の候補だけを保持することで枝刈りを行ったとしても、可能なインターリーブの数は n と m で指数関数的に増加します。 これは、マージされたシーケンス内のすべての位置が最初のシーケンスから取得するか 2 番目のシーケンスから取得するかの二者択一であり、最悪の場合 O(2^(n+m)) の可能性が生じるため、失敗します。 

最も短い共通スーパーシーケンスの標準的な観察では、LCS が分かればその長さは固定されるということです。 LCS の長さが L の場合、最適解の長さは n + m − L になります。したがって、実際のタスクは、LCS を効率的に計算し、有効なスーパーシーケンスを再構成することです。 

要素は各シーケンス内で一意であるため、LCS は最長増加部分列問題に変換できます。 最初のシーケンスの各値をそのインデックスにマップし、次に 2 番目のシーケンスを最初のシーケンスに現れる値のインデックスのシーケンスに変換します。 LCS は、このマッピングされたシーケンスの LIS に正確に対応します。 

LCS の一致する位置がわかったら、これらの一致したアンカーを尊重しながら両方のシーケンスを調べてそれらをマージすることで、答えを再構築できます。 連続する一致した要素間では、両方のシーケンスが独立したブロックを構成しており、内部順序を維持しながらマージする必要があります。 これらのブロックをインターリーブすると有効性が維持されるため、最終シーケンスの最初の要素を最小化するよう貪欲に選択できます。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n + m) | 遅すぎる |
 | LIS ベースの LCS + マージ再構築 | O(n log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初のシーケンスの位置マップを構築し、各値が出現する場所を保存します。 これにより、2 番目のシーケンスの要素が共通であるかどうかを定数時間で検索できます。 
2. 2 番目のシーケンスを最初のシーケンスの位置の配列に変換しますが、両方のシーケンスに存在する要素のみを保持します。 これに加えて、実際の値を保存します。 
3. 位置配列の LIS を計算します。 私たちは古典的な忍耐ソート構造を維持し、LIS を再構築するために親ポインターを保存します。 これにより、インデックスだけでなく実際の値の観点から LCS が得られます。 
4. LIS の親ポインタをバックトラックして、LCS の一致した要素を正しい順序で回復します。 
5. 次に、最短の共通スーパーシーケンスを再構築します。 2 つのシーケンスにわたって 2 つのポインター i と j を維持し、LCS の一致についても反復します。 
6. 一致した値ごとに、まず a[i:pi] と b[j:pj] のすべてをマージします。ここで、pi と pj は、両方のシーケンス内の現在一致した要素の位置です。 このマージ中は、常に a[i] と b[j] のうち小さい方の現在のヘッドを選択します。これは、どの選択をしても有効性が維持され、より小さい値を早く選択することで最終シーケンスの最初の要素が最小化されるためです。 
7. 両方の接頭辞を使用した後、一致した要素を 1 回追加し、両方のポインターをその要素を超えて進めます。 
8. 一致した要素をすべて処理した後、両方のシーケンスの残りのサフィックスを同じ貪欲な方法でマージします。 

機能する理由: LCS は両方のシーケンスを強制一致によって区切られた独立したブロックに分割します。 各ブロック内では、両方のシーケンスに値が出現しないため、順序制約を維持しながら自由にインターリーブできます。 インターリーブによって有効なスーパーシーケンスが生成され、小さい方のヘッドを最初に取得するという貪欲な選択により、残りの構造を完成させる実現可能性に影響を与えることなく、可能な限り最小の開始要素が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def lis_with_parent(seq):
    import bisect
    n = len(seq)
    if n == 0:
        return []

    tails = []
    tails_idx = []
    parent = [-1] * n

    for i, x in enumerate(seq):
        pos = bisect.bisect_left(tails, x)
        if pos == len(tails):
            tails.append(x)
            tails_idx.append(i)
        else:
            tails[pos] = x
            tails_idx[pos] = i

        if pos > 0:
            parent[i] = tails_idx[pos - 1]

    # reconstruct LIS
    k = tails_idx[-1]
    lis = []
    while k != -1:
        lis.append(k)
        k = parent[k]
    lis.reverse()
    return lis

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos = {v: i for i, v in enumerate(a)}

    b_idx = []
    b_val = []
    for v in b:
        if v in pos:
            b_idx.append(pos[v])
            b_val.append(v)

    lis = lis_with_parent(b_idx)
    lcs_vals = [b_val[i] for i in lis]

    i = j = 0
    ans = []

    for x in lcs_vals:
        while i < n and a[i] != x and (j >= m or a[i] < b[j]):
            ans.append(a[i])
            i += 1
        while j < m and b[j] != x and (i >= n or b[j] < a[i]):
            ans.append(b[j])
            j += 1

        while i < n and a[i] != x and j < m and b[j] != x:
            if a[i] < b[j]:
                ans.append(a[i])
                i += 1
            else:
                ans.append(b[j])
                j += 1

        while i < n and a[i] != x:
            ans.append(a[i])
            i += 1
        while j < m and b[j] != x:
            ans.append(b[j])
            j += 1

        ans.append(x)
        i += 1
        j += 1

    while i < n or j < m:
        if j == m or (i < n and a[i] < b[j]):
            ans.append(a[i])
            i += 1
        else:
            ans.append(b[j])
            j += 1

    print(len(ans))
    print(*ans)

if __name__ == "__main__":
    solve()
```この解決策は、LIS リダクションを使用して LCS を計算することから始まります。 マッピング ステップでは、両方のシーケンスに共通の値のみが考慮されることが保証され、LIS では相対的な順序制約が保持されることが保証されます。 

再構築フェーズは構造化されたマージです。 一致する要素に到達するたびに、両方のシーケンスにその値が含まれる必要がある同期ポイントに到達します。 それ以前のすべては 2 つのシーケンス間で独立しているため、安全に貪欲にインターリーブします。 最終的なサフィックスのマージは同じロジックに従いますが、さらなる同期制約はありません。 

一般的な実装の落とし穴は、一方のポインターが他方のシーケンスよりも前に一致に到達するセグメントの処理に失敗することです。 マージ ループ内の明示的なチェックにより、必要な一致要素がスキップされないことが保証されます。 

## 実用的な例

 両方のシーケンスがいくつかの要素を共有しているものの、要素間で大きく異なる場合を考えてみましょう。 ポインターと LCS アンカーを追跡します。 

| ステップ | 私はポインタ | j ポインタ | アクション | 出力 |
 | --- | --- | --- | --- | --- |
 | 開始 | 0 | 0 | ヘッドを比較 | 貪欲に成長する |
 | 試合前 | 前進 | 前進 | ブロックをマージ | 部分シーケンス |
 | 試合中 | 整列します | 整列します | LCS 要素を追加 | 同期 |

 これは、一致によって構造が強制されながら、順序制約に違反することなく独立したブロックがどのようにマージされるかを示しています。 

共通の要素がない 2 番目のケースでは、LCS は空であり、アルゴリズムは 2 つのシーケンスの単一の貪欲なマージに縮小されます。 これは、アルゴリズムが純粋なスーパーシーケンス構築に正常に劣化することを確認します。

 ## 特殊なケース

 2 つのシーケンスに交差がない場合、LCS は空になり、アルゴリズムはすべての同期ステップをスキップします。 マージ ループは、順序を維持しながらすべての要素の有効なインターリーブを直接生成し、貪欲な比較により最初の要素が可能な限り最小になるようにします。 

両方のシーケンスですべての要素が一致する場合、すべての要素が同期ポイントになります。 アルゴリズムは各要素を順番に 1 回だけ追加し、両方の入力と同一のシーケンスを生成します。これが可能な最小限の答えです。 

最初の要素が大きく異なる場合、最初の貪欲マージにより、実行可能性を妨げない限り、最小の要素が最初に表示されます。 実現可能性は試合間の各ブロックで独立して保持されるため、この貪欲な選択によってスーパーシーケンスを完了する能力が無効になることはありません。
