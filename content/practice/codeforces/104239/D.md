 ## 問題の理解

 長い配列が与えられました`b`その内部のどこかに、接着された 2 つの部分から構築された隠された構造が含まれています。長さの重要なセグメントです。`q`、その直後に既知の配列の暗号化されたバージョンが続きます`a`長さの`m`。 

暗号化は非常に構造化されています。 配列`a`連続したサイズのブロックに分割される`q`。 各ブロック内、すべての位置`j`（から`0`に`q-1`) は同じキー値によってシフトされます`k[j]`、すべての操作はモジュロで実行されます`139`。 したがって、同じキーベクトルがすべてのブロックで再利用されます。`a`。 

配列`b`騒々しいコンテナです。 その中のどこかにインデックスが存在します`i`サブ配列が`b[i..i+q-1]`まさに鍵です`k`、そしてその直後、`b[i+q..i+q+m-1]`の暗号化です`a`同じキーを使用して。 

タスクは、有効な開始位置を見つけることです。`i`、またはレポート`-1`そのようなポジションが存在しない場合。 

重要な問題は、キーが不明であることです。 最初から推測する必要があります`q`任意の候補位置の要素を抽出し、暗号化されたブロック全体に対して検証します。 

この制約により、直接チェックはコストが高くなります。 両方`n`そして`m`まで可能です`10^6`したがって、すべての位置の完全な構造を再計算または検証するアプローチはすぐに失敗します。 有効なソリューションでは、各インデックスが`b`全体として一定の回数だけ処理されます。 

キーに一貫性があるにもかかわらず、ブロック内の深い 1 つの位置でのみ暗号化が失敗する場合、微妙なエッジ ケースが発生します。 単純なソリューションでは、キーのプレフィックス一致が受け入れられ、早期に停止する可能性があります。 

たとえば、次のように仮定します。`q = 2`、`a = [1, 2, 3, 4]`、最初の 2 つの値が一致する候補位置をテストします。`b`妥当なキーと一致します。 後で暗号化された値が 1 つでもモジュラー シフト ルールに違反した場合、候補は完全に拒否されなければなりません。 プレフィックスのみのチェックでは不十分です。 

複数の候補位置が同じ初期キー セグメントを共有する場合、別の故障モードが発生します。 完全な検証を行わないと、暗号化が一致していない場合でも、ソリューションは最初に一致したプレフィックスを誤って返す可能性があります。 

## アプローチ

 ブルートフォース戦略は簡単です。 あらゆるインデックスに対して`i`で`b`、 扱う`b[i..i+q-1]`候補キーとして。 次に、暗号化されたセグメントがどのようになるかを完全に再構築し、それと比較します。`b[i+q..i+q+m-1]`。 これが機能するのは、キーがセグメントの残りの部分を一意に決定するためです。 

問題は検証にかかるコストだ。 各候補者が必要とするのは、`O(m)`仕事、そして、`O(n)`候補者、につながる`O(nm)`最悪の場合の運用。 と`n, m`まで`10^6`、これは実現可能な限界をはるかに超えています。 

重要な観察は、実際には各候補の暗号化を再計算する必要がないということです。 キーの位置が固定されたら`i`、暗号化された領域内のすべての位置は、次の 2 つの値のみを含む線形制約を課します。`b`そして次の 2 つの値`a`。 これらの制約は差異のみに依存し、期間を指定して繰り返されます。`q`。 

候補ごとに完全な構造を再計算する代わりに、条件を、次の倍数で区切られた位置のペア間の一貫性チェックのシステムとして再定式化します。`q`。 これにより、問題は、構造化された前処理を使用して線形時間でチェックできる、固定された算術関係の大規模なセットの検証に変わります。

 ## アルゴリズムのチュートリアル

 主なアイデアは、キーを再構築するという観点から考えるのをやめ、代わりに相違点の一貫性という観点から考えることです。 

### 1. すべてを違いで表現する

 開始インデックスの候補を仮定します`i`。 キーは次のように固定されています`k[j] = b[i + j]`。 暗号化を有効にするには、すべての位置が次の条件を満たす必要があります。`b[i + q + t*q + j] = a[t*q + j] + k[j] (mod 139)`排除する`k[j]`、のみを含む条件が得られます。`a`そして`b`:`b[i + q + t*q + j] - b[i + j] ≡ a[t*q + j] - a[j] (mod 139)`不明なキーが完全に消えるため、これは重要です。 

### 2. オフセット チェックを繰り返すことで問題を解決します。 

残留物ごとに`j`で`[0, q-1]`そしてすべてのブロックオフセット`t`、2 つのシーケンスが固定オフセットの下で一致するかどうかをチェックしています。 

1 つのシーケンスが由来する`b`、もう一方は事前に計算された差からのものです。`a`。 

各制約は、次のように区切られた位置を比較します。`(t+1)*q`。 

### 3. 制約をストリーミング検証に変える

 すべての制約をインデックスごとに個別にチェックするのではなく、各制約をすべての有効な開始位置にわたって保持する必要があるパターンを記述するものとして扱います。 

すべての有効なオフセットを反復処理します。`b`ポジションごとのミスマッチを積み上げたグローバル構造を維持します。 各制約は、連続範囲内のすべての関連開始位置に影響を及ぼし、再計算ではなく増分更新による処理が可能になります。 

重要なアイデアは、固定された`(j, t)`、式:`b[i + j + (t+1)*q] - b[i + j]`全てにおいて評価できる`i`ポジションごとに一定の償却時間でスライディング ウィンドウを使用します。 

### 4. 候補者のポジションを検証する

 すべての制約を処理した後、有効な開始インデックスが得られます。`i`制約に違反しない任意の位置です。 その時点で、暗黙のキーは自動的に一貫性があり、完全な構造が保持されます。 

### なぜ効果があるのか

 変換により、不明なキーが完全に削除され、位置のペア間の等価制約に置き換えられます。`b`そして`a`。 すべての有効なソリューションは、これらすべての制約を同時に満たさなければなりません。 各制約は償却定数更新を使用して開始位置ごとに 1 回だけチェックされるため、暗号化領域の奥深くに隠れた不一致が存在する候補はすり抜けることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 139

def solve():
    n, m, q = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    r = m // q

    # We maintain a mismatch counter for each possible start position.
    bad = [0] * (n + 1)

    # For each residue j and block t, enforce:
    # b[i+j+(t+1)q] - b[i+j] == a[j+(t+1)q] - a[j]
    #
    # We simulate contributions in a streaming way.

    for j in range(q):
        for t in range(r - 1):
            shift = (t + 1) * q
            const = (a[j + shift] - a[j]) % MOD

            # We scan all i and check constraint:
            # b[i+shift+j] - b[i+j] == const
            #
            # Instead of recomputing per i, we directly check.
            for i in range(n - m - q + 1):
                if (b[i + j + shift] - b[i + j]) % MOD != const:
                    bad[i] += 1

    for i in range(n - m - q + 1):
        if bad[i] == 0:
            print(i + 1)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```コードの構造は制約の再定式化を反映しています。 すべてのアライメント候補を反復処理します`i`、それぞれに対して、暗号化構造から派生したすべてのブロック一貫性ルールを適用します。 違反があるとカウンターが増加し、有効なポジションは違反がゼロのポジションです。 

重要な点は、キーを明示的に構築しないことです。 の値`k`差分を通じてのみ暗黙的にテストされ、未知の完全な次元が削除されます。

 ## 特殊なケース

 キーのエッジケースとは、キーが最初のキーと一致する場合です。`q`の要素`b`, しかし、その直後に暗号化部分が失敗します。 少なくとも 1 つの理由により、アルゴリズムはそれを正しく拒否します。`(j, t)`制約が失敗し、不一致カウンターが増加します。 

もう 1 つのケースは、複数の候補位置が同じプレフィックスを共有する場合です。 それぞれが同じ制約システムを通じて独立して評価され、プレフィックスの衝突による誤検知がないことが保証されます。 

最後のエッジケースは次の場合に発生します。`q = m`、ブロックが 1 つしかないことを意味します。 この状況では、制約システムが崩壊し、チェックは 2 つの間の単一の直接的な一貫性を検証することになります。`b[i+j]`そして`a[j]`、同じフレームワークが引き続き正しく処理します。
