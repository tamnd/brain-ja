 ## 解決策
 ## 問題の理解

 学期は、単一の連続した日のタイムラインとしてモデル化されています。 各研究室は連続した日数のブロックを占め、これらのブロックは重複しません。 最初のラボが続いたら$a_1$数日、それから数日をまたぐ$1$を通して$a_1$。 2 番目のラボは直後に開始され、次の期間実行されます。$a_2$日まで、など$n$-番目の研究室は学期を終了します。 

Vlad という名前の学生は、特定の日にのみ参加します。$k$日から始まる - 日目$k$、つまりアクティブな日は$k, 2k, 3k, \dots$。 これらの日が研究室の時間間隔内に収まるたびに、Vlad はその研究室に少なくとも 1 つの解決された問題を提供します。 タスクは、少なくとも 1 つの倍数が含まれる検査間隔が何回あるかを数えることです。$k$。 

重要な構造は、毎日シミュレーションするように求められていないということです。 学期の合計日数は次のようになります。$10^{18}$したがって、何日も繰り返すアプローチは不可能です。 唯一実現可能なアプローチは区間演算を使用する必要があります。 

検査間隔が完全に 2 つの連続する倍数の間にある場合、微妙なエッジケースが発生します。$k$。 たとえば、次の場合$k = 10$、11 日目から 19 日目まで実行されるラボには、アクティブな日が含まれません。 逆に、長さが 1 の非常に短いラボでも、次の倍数が含まれている場合はカウントできます。$k$、20 日目をカバーするラボなど、$k = 10$。 

## アプローチ

 ブルートフォース解釈は簡単です。 各研究室の正確な日間隔を計算し、すべての倍数にわたって繰り返します。$k$学期の終わりまでに、各倍数が各期間に該当するかどうかを確認します。 これにより、入れ子構造が形成されます。ラボごとに、多数のスキャンを実行する可能性があります。$k$、または同様に、全日をスキャンしてメンバーシップを確認します。 合計日数はすべての合計なので、$a_i$、到達できる$10^{18}$、これは直ちに実行不可能です。 

重要な観察は、視点を反転することです。 ラボに次のものが複数含まれているかどうかを尋ねる代わりに、$k$の何倍かを尋ねます。$k$タイムラインのプレフィックス内に収まります。 各ラボは、グローバル日軸上のプレフィックス間隔に対応します。 の倍数$k$1日まで$x$単純に$\lfloor x / k \rfloor$。 したがって、複数のラボにわたる場合、$[L, R]$、その中のアクティブな日数は$\lfloor R/k \rfloor - \lfloor (L-1)/k \rfloor$。 この差がゼロより大きい場合、研究室は貢献します。 

これにより、ラボごとに単純な算術条件を評価しながら、ラボ期間の実行中のプレフィックス合計を維持するという問題が軽減されます。

 | 数日間または複数回にわたる総当たり攻撃 |$O(\sum a_i)$あるいはさらに悪いことに |$O(1)$| 遅すぎる |
 | プレフィックス間隔 + 分割チェック |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 実行中の変数を維持する`cur`前の研究室の最終日を表します。 最初は`cur = 0`。 これにより、各ラボの間隔を計算する直接的な方法が得られます。 
2. 研究室ごと$i$、その間隔を次のように計算します。$[cur + 1, cur + a_i]$。 その後、アップデートしてください`cur += a_i`。 これにより、セグメント化された構造が保存されずに明示的な数値間隔に変換されます。 
3. インターバルごとに$[L, R]$、の倍数を計算します。$k$整数除算を使用してその中にあります。`R // k - (L - 1) // k`。 
4. 結果が正の場合、答えを 1 つ増やします。 これは、間隔内に少なくとも 1 つの有効な日が存在するかどうかを直接チェックします。 
5. すべてのラボを処理した後、最終的なカウントを出力します。 

重要な考え方は、$k$は等間隔であり、任意のプレフィックス間隔内でそれらをカウントすると、定数時間の算術式に減らすことができます。 

### なぜ効果があるのか

 各研究室は、数直線上の連続したセグメントに対応します。 有効な参加日数の順序も固定された等差数列です。 セグメントと等差数列間の交差のカウントは、エンドポイントでのプレフィックス数の比較に帰着します。 表現$\lfloor R/k \rfloor - \lfloor (L-1)/k \rfloor$フォームの用語の数を正確に数えます$t \cdot k$寝そべる$[L, R]$したがって、「ヴラドがこのラボに参加している」という条件は、このカウントがゼロ以外であることと同等です。 すべてのラボは独立して 1 回だけ処理されるため、合計数は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    cur = 0
    ans = 0
    
    for x in a:
        L = cur + 1
        R = cur + x
        cur = R
        
        if R // k - (L - 1) // k > 0:
            ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは実行中のエンドポイントのみを保持します`cur`したがって、明示的に保存したり、数日間反復したりすることはありません。 各ラボは算術演算を使用して一定時間で処理されます。 

表現`(L - 1) // k`境界を正しく処理するには不可欠です。 1を引かずに、`L`それ自体はの倍数です`k`フロア分割の境界が誤って移動するため、カウントが間違ってしまう可能性があります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、研究室が正確に次の時刻に開始する場合です。$k$。 たとえば、$k = 5$、10 日目に開始したラボは直ちにカウントする必要があります。 

入力の場合:```
1 5
10
```間隔は$[1, 10]$。 次のように計算します。$10 // 5 = 2$、$(1 - 1) // 5 = 0$したがって、カウントは 2 です。つまり、倍数 5 と 10 の両方がラボ内にあり、ラボは正しくカウントされます。 

もう 1 つのエッジ ケースは、ラボがちょうど次の時間に終了する場合です。$k$ただし、前のものの直後から始まります。 のために$k = 4$、間隔$[5, 8]$有効な日として 8 が含まれています。 計算:$8 // 4 = 2$、$4 // 4 = 1$、カウント 1 が与えられ、参加を正しくマークします。 

これらのケースでは、境界処理が有効であることが確認されています。$(L-1)$正しさのためには不可欠です。
