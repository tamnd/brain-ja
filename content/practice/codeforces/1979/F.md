 ## 解決策
 ## 問題の理解

 元々は完全なグラフであった未知のグラフが与えられました。$n$頂点、ただし正確には$n-2$エッジが削除されました。 これは、最終的なグラフが非常に密であることを意味します。$\frac{n(n-1)}{2} - (n-2)$エッジが欠落しているため、それのみが欠落しています$n-2$合計接続数。 

グラフを直接見ることはできません。 代わりに、「? d」形式のクエリを使用してシステムと対話します。 各クエリは非常に特殊な操作を実行します。つまり、頂点を識別します。$v$それは次数のしきい値条件を満たし、そのようなすべての頂点の中から最小次数と最小インデックスを持つ頂点が選択されます。 また、接続されていない 1 つの頂点も返します。$v$、そのような頂点が存在する場合、最小のラベルが優先されます。 この情報を報告した後、頂点は$v$は、すべての入射エッジとともにグラフから削除されます。 

目標は、最大でも次の値を使用して、元のグラフ内のハミルトニアン パスを再構築することです。$n$そのようなクエリ。 ここでのハミルトニアン パスは、すべての頂点が 1 回だけ出現するようにすべての頂点を並べただけです。 元のグラフのエッジが連続する頂点の間に存在する必要はありません。 

制約$n \le 10^5$すべてのテスト ケースにわたって、隣接関係を明示的にシミュレートまたは再構築できないことを意味します。 どのようなソリューションでも、定数クエリまたは対数クエリで頂点ごとの構造情報を抽出することに依存する必要があり、相互作用自体が計算のボトルネックになります。 これは対話型の再構成問題であり、各クエリで 1 つの頂点が削除されるため、アルゴリズムは基本的に線形時間でグラフを「ピーリング」する必要があります。 

重要な点は、各クエリが頂点の選択と削除の両方を行うことです。 これにより、システムは純粋なクエリ オラクルではなく、制御された削除プロセスのように動作します。 構造に影響を与えることなく次数を繰り返し調べることができるという単純な仮定は、すべてのクエリがグラフを変更するため、すぐに壊れます。 

典型的な失敗例は、削除を追跡せずに固定しきい値を繰り返しクエリしようとした場合に発生します。 たとえば、頂点次数が安定していると仮定すると、たとえ小さなケースであっても失敗します。 

入力アイデア:```
4
```高い次数を持つ頂点がクエリ後も高い次数のままであると仮定すると、同じ頂点を繰り返し選択する可能性がありますが、インタラクターは最初の選択後にその頂点を削除します。 クエリを明示的に破壊的なものとして扱わないソリューションは、すぐに非同期になります。 

もう 1 つの微妙なエッジ ケースは、複数の頂点が同じ最小次数を共有し、最小インデックス タイブレークによって出力が決定される場合です。 たとえば、星のような残差構造では、選択ルールを慎重に利用しない限り、単純で貪欲な選択により「間違った」中心が選択される可能性があります。 

## アプローチ

 ブルート フォース パースペクティブでは、しきい値を超えて各頂点の次数の動作を繰り返し調査することで、グラフ全体を再構築するか、インタラクターをシミュレートしようとします。 各クエリはすでに頂点を削除しているため、単純な考えでは、ステップごとにすべての可能な候補を試すか、正しい頂点が分離されるまでしきい値を繰り返しスキャンすることになります。 これは、各頂点の削除を頭の中で「シミュレート」するにはコストがかかり、繰り返しのプローブでは頂点ごとに複数のクエリが必要になるため、すぐに実行不可能になります。$O(n^2)$最悪の場合は相互作用。 

重要な構造的洞察は、グラフがほぼ完成しており、欠落している部分だけが残っているということです。$n-2$エッジ。 これは、補グラフがサイズのフォレストであることを意味します。$n$、まさに$n-2$したがって、それはツリーである正確に 2 つの接続されたコンポーネントで構成されます。または、より直接的には、元のグラフは「完全なグラフからツリーを引いたもの」になります。 これが決定的な削減です。欠落したエッジがツリー構造を形成します。 

元のグラフのハミルトニアン パスは、失われたツリー エッジを回避するトラバースに対応します。 以来$n-2$エッジが欠落している場合でも、補体構造には十分な制約があり、非近傍を識別することで隣接関係を段階的に再構築できます。 

インタラクティブ クエリは、削除された頂点ごとに 1 つの非隣接頂点を明らかにするように設計されています。 プロセス全体を通じて、各頂点は 1 つの「禁止エッジ ヒント」(欠落エッジ ツリー構造の端点を除く) を提供するため、補数ツリーを再構築してハミルトニアン パスを導出することができます。 

戦略は次のようになります。返された単一の非隣接頂点を記録しながら頂点を繰り返し削除し、親のような関係を構築します。 これにより、補グラフ上にツリーが効果的に再構築され、そのツリーの DFS または BFS 順序付けが元のグラフの有効なハミルトニアン パスとして出力されます。 

これが機能する理由は、補体ツリーでは各エッジが元のグラフの欠落しているエッジに対応するため、これらのエッジを回避することで元のグラフでの隣接性が保証されるためです。

 ## アルゴリズムのチュートリアル

 インタラクティブなプロセスを使用して補体構造を暗黙的に再構築します。 

1. 残りの頂点のリストを維持します。最初はすべての頂点が$1 \ldots n$。 各ステップで、可能な限り小さいしきい値を使用してクエリを発行します。$d$、 通常$d = 0$構造がすでに枯渇していない限り、常に有効な頂点を取得できることを保証するためです。 これにより、私たちは常に進歩することが保証されます。 
2. 各クエリは頂点を返します。$v$削除された頂点と$u$それはつながっていない$v$(存在しない場合は 0)。 私たちは解釈します$u$固有の欠落エッジ近傍として$v$補体構造で。 
3. 関係を保存します$v \leftrightarrow u$補数グラフのエッジとして、次の場合を無視します。$u = 0$。 
4. すべての頂点が削除されるまで、このプロセスを繰り返します。 各クエリはちょうど 1 つの頂点を削除するため、最大でも$n$クエリ。 
5. すべてのクエリを実行すると、補数グラフを表すフォレスト構造が得られます。 次に、任意の頂点から開始して DFS を実行し、頂点の順序を生成します。 
6. この DFS 次数は、元のグラフのハミルトニアン パスとして返されます。 

重要な推論ステップは、インタラクターが返す「非隣接者」は任意ではないということです。 元のグラフはほぼ完成しているため、各頂点には 1 つまたはごく少数の欠落した接続があり、選択ルールにより削除全体で一貫性が確保され、密集した曖昧なグラフではなくツリー状の構造を再構築できます。 

### なぜ効果があるのか

 補数グラフは正確に$n-2$これにより、解釈に応じて、厳密に 2 つのコンポーネントまたは単一のツリー状構造を含むフォレストになることが強制されます。 各クエリでは、削除された頂点ごとに 1 つの欠落した隣接関係が公開されるため、すべてのクエリにわたってすべての補エッジを 1 回だけ復元します。 元のグラフはこれらのエッジを除いて完全であるため、補数エッジを回避するトラバーサルは元のグラフに有効なハミルトニアン パスを生成します。 

常に頂点を 1 つずつ削除し、その固有の禁止された接続を記録するため、構造情報が失われることはありません。 再構築はロスレスであり、DFS の順序付けではすべての制約が尊重されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    
    parent = [-1] * (n + 1)
    adj = [[] for _ in range(n + 1)]
    alive = [True] * (n + 1)

    for _ in range(n):
        print("? 0")
        sys.stdout.flush()
        v, u = map(int, input().split())
        if v == 0:
            break
        alive[v] = False
        if u != 0:
            parent[v] = u
            adj[v].append(u)
            adj[u].append(v)

    visited = [False] * (n + 1)
    order = []

    def dfs(x):
        visited[x] = True
        order.append(x)
        for y in adj[x]:
            if not visited[y]:
                dfs(y)

    start = 1
    dfs(start)

    print("! " + " ".join(map(str, order)))
    sys.stdout.flush()

t = int(input())
for _ in range(t):
    solve()
```この実装では、常に最小しきい値をクエリすることにより、頂点ごとに 1 つのクエリを実行します。 インタラクターは枯渇するまで常に有効なリムーバブル頂点を返すため、これにより進行が保証されます。 

隣接リストは、返された非隣接情報から構築され、それを補完構造のエッジとして解釈します。 その後、DFS が最終的な順序を構築します。 

実装の微妙な点は、再構成された構造が長いチェーンに縮退する可能性があるため、再帰の深さを増やす必要があることです。 もう 1 つの重要な点は、ソリューションが対話型であるため、クエリごとにフラッシュすることです。 

## 実用的な例

 次の小さなケースを考えてみましょう$n = 4$。 

すべての頂点が生きている状態から始めます。$\{1,2,3,4\}$。 

| ステップ | クエリ | 返された (v, u) | アライブセット | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | ? 0 | (1, 4) | {2,3,4} | レコード 1-4 |
 | 2 | ? 0 | (2, 3) | {3,4} | 記録 2-3 |
 | 3 | ? 0 | (3,0) | {4} | 録音を停止する |
 | 4 | ? 0 | (4,0) | {} | 仕上げ |

 補完エッジは小さな鎖状の構造を形成します。 1 からの DFS により、有効なハミルトニアン順序が得られます。 

このトレースは、すべての削除がせいぜい 1 つの構造制約に寄与し、制約の完全なセットが補完エッジ上のスパニング ツリーを再構築するのに十分であることを示しています。 

ここで、1 つの頂点に最後までエッジが欠けていない、わずかに歪んだ構造を考えてみましょう。 このアルゴリズムは依然として機能します。孤立した頂点であっても、最終的には返された非隣接頂点を通じて明らかにされ、アタッチされ、再構成の接続性が保証されるからです。

 ## 特殊なケース

 重要なエッジケースは、長い鎖など、補体構造が大きく歪んでいる場合です。 その状況では、DFS 再帰の深さは次のようになります。$O(n)$、再帰制限を増やさないと、たとえロジックが正しいとしても、解は失敗します。 実装では、これを処理するために高い再帰制限を明示的に設定します。 

もう 1 つのエッジケースは、インタラクターが戻ったときです。$u = 0$終わり近くの複数の頂点の場合。 これらの頂点は補体構造のリーフに対応し、ゼロ エッジを無視しないと隣接関係の構築が破損します。 アルゴリズムが扱うのは、$u = 0$その頂点のみの終了信号として。 

最後に、グラフが非常に密で、欠落しているエッジが集中している場合、複数の頂点が同様の構造的役割を共有する可能性があります。 決定論的な選択ルールにより一貫性が保証されますが、返された非近傍を使用せずに構造を「推測」しようとすると、対称性が崩れ、無効なハミルトニアン順序が生成されます。
