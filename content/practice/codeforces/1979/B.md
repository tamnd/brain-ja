 ## 問題の理解

 2 つの整数が与えられます。`x`そして`y`。 それらを使用して、2 つの無限シーケンスを定義します。$$a_n=n\oplus x$$そして$$b_n=n\oplus y.$$インデックスは次から始まります`1`。 すべての要素は、インデックスと固定値の XOR 演算によって取得されます。 

タスクは、両方のシーケンスに出現する連続ブロックの最大長を見つけることです。 ブロックは 2 つのシーケンスの異なる位置から開始することもできますが、開始位置を選択したら、要素は全長にわたって 1 つずつ一致する必要があります。 

テスト数の点では制約は小さいですが、`x`そして`y`と同じ大きさにすることができます$10^9$。 シーケンス自体は無限であるため、項を明示的に生成しようとする解決策は不可能です。 答えは次のように大きくなる可能性があるため、最初の数百万の要素を調べるだけでは十分ではありません。$2^{25}$サンプルに示されているように。 

問題は実際には、XOR が連続する整数をどのように変換するかを理解することです。 基礎となるビット パターンが見つかると、テスト ケースごとに一定時間で答えを計算できます。 

微妙なエッジケースが現れるのは、`x`そして`y`最下位ビットのみが異なります。 

例えば：```
x = 0
y = 1
```それから：```
d = x xor y = 1
```答えは`1`。 よくある間違いは、答えは次のように考えられることです。`2`XOR は 1 ビットのみを変更するためです。 連続する整数の桁上げ動作により、一致する長いセグメントは直ちに中断されます。 

もう一つの簡単な間違いは次のような場合に起こります。`x xor y`は 2 の累乗です。 

例えば：```
x = 12
y = 4
```それから：```
x xor y = 8
```答えは`8`、 ない`4`。 長さは、異なるビットの数ではなく、最も低い異なるビットの位置によって決まります。 

## アプローチ

 強引なアイデアは、両方のシーケンスの大きなプレフィックスを生成し、最も長い共通のサブ配列を検索することです。 この定義は文字通り、共通の連続セグメントを要求しているため、これは正しいです。 

問題は、シーケンスが無限であることです。 たとえ最初の 100 万個の要素を生成したとしても、そこに最適なセグメントが発生するという保証はありません。 答え自体は 3,000 万を超える可能性があるため、直接のシミュレーションは絶望的です。 

重要な観察は、等価条件を書き換えることから得られます。 

共通セグメントが次の位置で始まると仮定します。`i`そして`j`。 次に、オフセットごとに`t`セグメント内で、$$(i+t)\oplus x=(j+t)\oplus y.$$XOR を適用する`x`両側で与えます$$(i+t) \oplus (j+t)=x\oplus y.$$させて$$d=x\oplus y.$$問題は次のようになります。 

の連続する値の最長間隔を見つけます。`t`そのような$$(i+t)\oplus(j+t)=d.$$ここで必要なのは、2 つの数値が同時に増加したときに XOR がどのように動作するかを研究することだけです。 

重要な事実は、可能な最大長は、設定された最下位ビットのみに依存するということです。`d`。 

設定された最小ビットの場合、`d`位置にあります`k`、その場合、答えは次のとおりです。$$2^k.$$同様に、$$\text{answer}=d\ \&\ (-d).$$この量は、設定された最下位ビットの値です。

 ## アルゴリズムのチュートリアル

 1. コンピューティング$$d=x\oplus y.$$以来`x ≠ y`、私たちは知っています`d > 0`。 
2. の最下位セットビットを見つけます。`d`。 

二項演算ではこれは$$d\ \&\ (-d).$$3. その値を出力します。 

ソリューション全体は次の 3 つのステップで構成されます。 

### なぜ効果があるのか

 最低設定ビットを`d`位置にいる`k`。 

位置より下のすべてのビット`k`ゼロです`d`。 これは、一致する数値のペアに対して、`u`そして`v`満足のいく$$u\oplus v=d,$$彼らの下位`k`ビットは同一である必要があります。 

両方の数値を同時に増加させると、低い数値が増加します。`k`ビットはまったく同じように進化します`2^k`キャリーがビットに到達する前の連続した値`k`。 

そのキャリーが発生するとビット`k`一方の側ではもう一方の側とは異なる変化が起こるため、`d`が含まれています`1`その位置で。 平等$$(u+t)\oplus(v+t)=d$$もう続けることはできません。 

したがって、セグメントはこれより長くすることはできません`2^k`。 

この限界は、適切な開始値を選択することで達成できます。`k`ビットはゼロから始まります。 この場合、XOR は次と等しいままになります。`d`まさに`2^k`連続したステップ。 

したがって、可能な限り長い共通セグメントの長さは$$2^k=d\&(-d).$$## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        x, y = map(int, input().split())
        d = x ^ y
        ans.append(str(d & -d))

    sys.stdout.write("\n".join(ans))

solve()
```実装は数学的結果に直接従います。 

表現`x ^ y`異なるビットのマスクを計算します。 数値は個別であるため、この値は常に正になります。 

表現`d & -d`最下位の設定ビットを分離します。 2 の補数演算では、`-d`設定された最低ビットより上のすべてのビットを反転し、AND 演算されたときにそのビットを正確に保持します。`d`。 

Python の整数は任意の精度を持つため、オーバーフローの心配はありません。 値は最大でも約`2^30`したがって、固定幅の 64 ビット整数でも十分です。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        x, y = map(int, input().split())
        d = x ^ y
        out.append(str(d & -d))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    res = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return res.strip()

 ## 特殊なケース

 次のことを考慮してください。```
x = 7
y = 6
```それから$$x\oplus y = 1.$$最下位の設定ビットは`1`、したがって、答えは次のとおりです`1`。 

非常に類似した数値であれば長い共通セグメントが許容されるはずだというのは誤った直感です。 1 回のインクリメント後に生成されるキャリーは、すぐに異なるビットに到達するため、セグメントは 1 つの要素を超えて拡張できません。 

次に、次のことを考えてみましょう。```
x = 0
y = 32
```それから$$x\oplus y=32.$$最下位の設定ビットは`32`、そして答えは`32`。 XOR マスクの下位 5 ビットはすべて同一であるため、正確に許可されます。`32`キャリーが最初の異なるビットに到達する前の連続した位置。 

最後に次のことを考慮してください。```
x = 13
y = 9
```それから$$x\oplus y=4.$$上位のいくつかのビットが異なる場合でも、下位から最初に異なる位置はビットです。`2`、答えを与える`4`。 最初の避けられないキャリーが等式を破る場合、上位ビットは影響を与えないため、アルゴリズムはすべての上位ビットを無視します。
