 ## 解決策
 ## 問題の理解

 いくつかの独立した賭けゲームが与えられます。 各ゲームには、`n`各結果に配置するコインの正の整数を選択します。 発生する結果は 1 つだけです。`i`発生すると、それに賭けた賭け金は既知の係数で乗算されます`k_i`そして賞金として戻ってきました。 

この制約はグローバルです。すべての賭け金の合計は、考えられるすべての勝利シナリオにおける配当よりも厳密に小さくなければなりません。 言い換えると、賭け金の合計を次のように表すと、`S = x_1 + x_2 + ... + x_n`次に、インデックスごとに`i`、条件`k_i * x_i > S`を同時に保持する必要があります。 

タスクは、そのような賭けのベクトルを構築するか、それが不可能であると報告することです。 

この制約により、合計で最大 10^4 のテスト ケースが許可されます。`n`最大 2 × 10^5、およびそれぞれ`n`これにより、割り当てに対する指数関数的な検索が除外されます。 テストケースごとに線形または線形に近い構造が必要です。`n`。 

素朴な試みとしては、総額を推測することになります。`S`そして、それぞれが次のようにベットを分配します。`x_i > S / k_i`しかし、これはすぐに循環してしまいます。`S`すべてに依存します`x_i`。 

すべての乗数が同一で小さい場合、微妙な失敗のケースが発生します。 たとえば、すべてが`k_i = 2`、すべての不平等を厳密にしようとする試みは、同時に下限間の矛盾を強制します。`x_i`そしての定義`S`。 

## アプローチ

 ブルートフォースアプローチでは、コインの考えられるすべての分布を一定の合計まで推測し、すべての不等式が満たされているかどうかを確認しようとします。`k_i * x_i > S`所有。 キャップをしても`x_i`10^9 などでは、構成の数は天文学的に多くなり、最悪の場合でもおよそ 10^9^50 となるため、これは完全に不可能です。 

重要な観察は、制約が均一であり、賭けの絶対的な規模ではなく、賭けの相対的な比率にのみ依存するということです。 総額を決めると`S`、各制約は下限になります。`x_i > S / k_i`。 これは、より大きな乗数が比例してより小さなベットを受け取りますが、合計に対する厳密な不等式を満たすのに十分な大きさであるという構造が必要であることを示唆しています。 

これについて考えるのに便利な方法は、次のように設定しようとしていると仮定することです。`S`最初に実行可能な最小値を導き出します`x_i`。 これらの下限を合計すると、一貫性条件が得られます。`S`。 問題は、誘導された合計がまだ必要なしきい値を下回っている場合に、自己一貫性のあるスケーリングを見つけることに帰着します。 

これは当然、次の順序で候補構造を試すことになります。`k_i`の順序を決定します`x_i`、制約を並べ替えたり、繰り返し強制したりすることで、ソリューションを貪欲に構築できます。

 ## アルゴリズムのチュートリアル

 中心的なアイデアは、累積合計を支配するほど急速に増加する重みを並べ替えて割り当てることによって、循環不等式を線形構造に変換することです。 

結果を昇順に処理します。`k_i`。 

1. 次のようにインデックスを並べ替えます。`k_1 ≤ k_2 ≤ ... ≤ k_n`。 その理由は、乗数が小さいほど、より大きな値が必要になるため、満足するのが難しいためです。`x_i`同じ合計を上回る`S`。 
2. 最大の乗数から始めて、逆方向に賭けを構築します。 当社は、すでに割り当てられたベットの現在のサフィックス合計を維持します。 
3.初期化`x_n = 1`。 これにより、基本スケールが固定され、ゼロの処理が回避されます。 
4. のために`i`から`n-1`まで`1`、 選ぶ`x_i`次のような最小の整数として`k_i * x_i > S_current + x_i`、 どこ`S_current`右側にすでに割り当てられている値に将来の寄与分を加えた合計です。 この段階では将来の値は不明であるため、代入後の不変式を維持します。`x_i`、からの接尾辞`i`以降はその部分和に関して有効です。 

より直接的で実装可能なバージョンでは、循環推論を回避します。右から左に構築して、各プレフィックスが次の乗数と比較して十分に小さいことを確認します。 設定しました`x_i = x_{i+1} + 1`、その後、満足するように最小限にスケールします`k_i * x_i > total`。 

クリーンな実装では、次の安定した貪欲パターンを使用します。最大のものから開始します。`k`、 セット`x = 1`、および前のインデックスごとに強制します`x_i = x_{i+1} + 1`まで上向きに乗算します。`k_i * x_i`現在の合計を超えています。 
5. 構築後、すべての制約を確認します。 失敗した場合は出力`-1`。 それ以外の場合は、構築された配列を元の順序で出力します。 

この構築の背後にある直観は、コントリビューション間の厳密な分離を強制し、より小さい乗数を補うために、より早い (弱い乗数) ポジションが十分に大きな重みを確実に受け取るようにするということです。`k_i`。 

### なぜ効果があるのか

 維持される不変条件は、各ステップで、割り当てられたすべてのベットの合計が積によって厳密に支配されるように部分割り当てがスケーリングされるということです。`k_i * x_i`現在のインデックスは構築中であり、その後のすべてのインデックスは構築によってすでに制約を満たしています。 各ステップは制御された乗算方法で以前の値を増加させるだけであるため、以前に満たされていた不等式は破られず、最終的なスケーリングによってすべての制約が同時に保持されることが保証されます。 

重要な構造上の事実は、実現可能性は乗算器の順序のみに依存するということです。配列がソートされると、指数関数的に増加する重みを割り当てることができるため、各制約は全体的な合計ではなく、独自の項によって支配されるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        k = list(map(int, input().split()))
        
        idx = list(range(n))
        idx.sort(key=lambda i: k[i])
        
        x = [0] * n
        x[idx[-1]] = 1
        total = 1
        
        ok = True
        
        for j in range(n - 2, -1, -1):
            i = idx[j]
            nxt = idx[j + 1]
            
            x[i] = x[nxt] + 1
            
            # ensure condition holds, otherwise scale up
            while k[i] * x[i] <= total + x[i]:
                x[i] *= 2
            
            total += x[i]
        
        for i in range(n):
            if k[i] * x[i] <= sum(x):
                ok = False
                break
        
        if not ok:
            print(-1)
        else:
            print(*x)

if __name__ == "__main__":
    solve()
```コードは、最初に強い制約を適用できるように、乗数値に従ってインデックスを並べ替えることから始まります。 この構造では、より大きな値をより弱い乗算器に割り当て、総和を支配できるようにします。 

私たちは割り当てられたベットの現在までの合計を維持し、インデックスの制約に違反するたびに、そのベットを指数関数的に増加させます。 これにより、単一位置のスケーリングはその不等式を満たしやすくするだけであるため、正確さを維持しながら迅速な収束が保証されます。 

最後に、すべての制約を明示的に検証します。 構造がスケール間の分離を保証していることを考えると、このチェックは主に実装の微妙な点を防ぐためのものです。

 ## 特殊なケース

 重要なエッジケースは、すべての乗数が同一で小さい場合です。たとえば、`k = [2, 2, 2]`。 任意の割り当て`x`合計を与える`S`。 それぞれの条件は、`2x_i > S`、すべてを合計すると、`2S > 3S`、それは不可能です。 すべての制約を同時に満たすスケーリングはないため、アルゴリズムは最終検証中にこれを自然に検出します。 

もう 1 つのエッジ ケースは、1 つの乗数が他の乗数よりも大幅に大きい場合です。`[2, 2, 20]`。 最大の乗数が合計を支配しやすくなり、その位置にほとんどの重みが集中するソリューションが可能になります。 この構造では、最初に最小値を high-k 位置に割り当て、次に必要な場合にのみ low-k 位置をインフレートして、実現可能性を維持します。 

最後のエッジケースは、次のような厳密に混合された値です。`[3, 3, 2]`。 ここでは実現可能性はありますが、慎重な順序付けが必要です。最小の乗数が最大の賭け金を受け取る必要があります。 ソートされた構造によりこれが自動的に保証され、検証ステップではすべての不等式を最終的な合計と照合することで正確さを確認します。
