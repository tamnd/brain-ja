 ## 解決策
 ## 問題の理解

 3 つの整数配列が与えられます。 課題は三つ子の数を見つけることです`(i, j, k)`最初の配列の要素が`a[i]`2 番目の配列の要素以下である`b[j]`、および 2 番目の配列の要素`b[j]`3 番目の配列の要素以下である`c[k]`。 インデックス`i`、`j`、 そして`k`独立している。 数値的な関係だけを気にします。 

入力は 3 つの配列を順番に提供します。 出力は単一の整数、つまり有効なトリプレットの数です。 

制約は、各配列に最大で次のものを含めることができるというものです。`10^5`要素と値は最大です`10^9`。 これは、ブルートフォースの三重ネストループが必要になることを意味します。`10^15`操作は実行不可能です。 どのような解決策であっても、最悪の場合でも線形演算に近いものでなければなりません。 

微妙な点は、値が繰り返される可能性があることです。 たとえば、次の場合`a = [1, 1]`、`b = [1]`、`c = [1, 1]`、合計数は単に一意の値の数ではなく、多重度の積です。ここでは 2 つです。`1`にいる`a`それぞれのペアとそのペア`1`で`b`、そしてそれ`b`二人とペアになる`1`にいる`c`、与える`2 * 1 * 2 = 4`有効なトリプレット。 一意の数値のみをカウントする単純なソリューションでは、ここでは失敗します。 

もう 1 つのエッジ ケースは、一部の配列が空であるか、次の配列の最小値よりも大きい要素がすべて含まれている場合です。 たとえば、次の場合`a = [5]`、`b = [3]`、`c = [4]`、三つ組は不可能であり、不注意な解決策により誤って何かを数えてしまう可能性があります。 

## アプローチ

 強引な解決策は、最初の配列の各要素を反復処理し、それらのそれぞれについて 2 番目の配列のすべての要素を反復し、さらにそれらのそれぞれについて 3 番目の配列のすべての要素を反復することです。 組み合わせごとに、次のことを確認します。`a[i] <= b[j] <= c[k]`存在する場合はカウンターをインクリメントします。 これは正しく動作しますが、次のことが必要です`O(n * m * l)`到達できる操作`10^15`最大サイズの配列の場合、実現可能な制限をはるかに超えています。 

最適化のための重要な洞察は、配列は独立しているが、それらの相対的な順序のみが重要であるということです。 配列をソートすると、要素ごとに`b[j]`中央の配列では、`a[i]`満足のいく`a[i] <= b[j]`は単に要素の数です`a`以下`b[j]`。 同様に、`c[k]`満足のいく`b[j] <= c[k]`の要素の数です`c`以上`b[j]`。 これにより、二分探索を使用してこれらを効率的にカウントできるようになります。`b[j]`。 

複雑さを 3 次から 3 次へ削減します。`O(n log n + m log n + m log l + l log l)`最初の並べ替えによって`a`そして`c`、それから繰り返します`b`そして使用して`bisect_right`の上`a`そして`bisect_left`の上`c`。 これは実現可能です`10^5`並べ替えは要素なので、`O(n log n)`そしてそれぞれの二分探索は`O(log n)`。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m * l) | お(1) | 遅すぎる |
 | 最適 | O(n log n + m log n + m log l + l log l) | O(n + m + l) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列のソート`a`降順ではない順に。 これにより、二分探索でターゲット以下の要素をすばやくカウントできるようになります。 
2. 配列のソート`c`降順ではない順に。 これにより、二分探索も使用して、ターゲット以上の要素をすばやくカウントできるようになります。 
3. カウンタの初期化`total = 0`有効なトリプレットを蓄積します。 
4. 各要素を反復処理する`b_j`配列内`b`。 それぞれについて`b_j`の要素の数を求めます。`a`それは`<= b_j`。 使用する`bisect_right(a, b_j)`、まさにこのカウントが得られます。 
5. 同様に、それぞれについて`b_j`の要素の数を求めます。`c`それは`>= b_j`。 使用する`len(c) - bisect_left(c, b_j)`このカウントを与えます。 
6. ステップ 4 と 5 のカウントを乗算して、この特定のトリプレットの数を取得します。`b_j`そしてそれを追加します`total`。 
7. すべての処理が完了したら`b_j`、合計を出力します。 

### なぜ効果があるのか

 配列を並べ替えると、しきい値以下のすべての要素が連続していること、およびしきい値以上のすべての要素が連続していることが保証されます。 使用する`bisect_right`そして`bisect_left`この特性を利用します。 重要な不変条件は、それぞれの`b_j`、私たちが計算するカウントは正確であり、独立しています。 それらを乗算すると、制約を満たすすべての組み合わせが得られます。 二分探索により要素ごとの比較が確実に保持されるため、トリプレットが見逃されることはなく、無効なトリプレットもカウントされません。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

def solve():
    n, m, l = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    c = list(map(int, input().split()))

    a.sort()
    c.sort()

    total = 0
    for bj in b:
        count_a = bisect.bisect_right(a, bj)
        count_c = len(c) - bisect.bisect_left(c, bj)
        total += count_a * count_c

    print(total)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず配列の長さと値を読み取ります。 仕分け`a`そして`c`それを保証します`bisect`通話は正しく機能します。 それぞれについて`b_j`、`bisect_right(a, bj)`すべて有効なものを数える`a[i]`そして`len(c) - bisect_left(c, bj)`すべて有効なものを数える`c[k]`。 これらの数を乗算すると、すべての三つ組が計算されます。`b_j`真ん中の要素です。 の`total`カウンタは最終的な答えを蓄積します。 重要な実装の詳細は、`bisect_right`のために`a`そして`bisect_left`のために`c`を尊重する`<=`そして`>=`不平等。
