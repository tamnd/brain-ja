 ## 解決策
 ## 問題の理解

 位置 1 から n までの有向構造が与えられており、各位置には値が含まれています。 重要な制限は、ある位置から別の位置への移動は任意ではないということです。インデックス順にのみ前に移動でき、値が厳密な順序条件を満たす位置に沿ってのみ移動できます。 それに加えて、有効なチェーンの構築中にインデックスの差に関してどこまで「ジャンプ」できるかという制約があります。 

各クエリは、一連の有効な前方移動を使用して、ある位置 ui から別の位置 vi に移動できるかどうかを尋ね、場合によってはそのような移動の最小数も尋ねます。 

この難しさは、到達可能性が純粋にインデックスの順序や値の順序だけで決まるわけではないという事実から生じます。 有効なパスは両方の制約を同時に尊重する必要があり、中間ノードはセグメントの開始値に応じてさらに制限されます。 これにより、エッジが明示的に与えられるのではなく、複雑なルールによって暗示されるハイブリッド構造が作成されます。 

複雑さの観点から、n と q は最大 300000 です。これにより、明示的にエッジを構築したり、クエリごとに新しいグラフ検索を実行しようとするソリューションは即座に除外されます。 クエリごとに 1 つの BFS でもコストは O(nq) となり、これは実現不可能です。 

さらに微妙な問題は、「有効な中間ノード」の条件が転送の開始ノードに依存することです。 これは、グラフが通常の意味で静的ではないことを意味します。つまり、エッジが存在するかどうかは、エンドポイントだけでなくコンテキストに依存します。 固定された隣接リストを前提とした単純な前処理は失敗します。 

落とし穴の小さな例は、ノードがローカルに到達可能であるように見えても、中間の制約によってグローバルにブロックされている場合です。 値 5、1、6 と小さな d を持つインデックス 1、2、3 があるとします。 インデックス項および値項で 1 が 3 になる可能性がある場合でも、2 の存在により、その値が開始値より小さくないため、必要な中間チェーンが無効になる可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべての有効なチェーンをシミュレートすることによって、各クエリの到達可能性を明示的に判断しようとします。 特定の開始ノードについて、距離 d 内で考えられるすべての次のステップを試行し、中間ノードの値の制約をチェックしながら再帰的に続行します。 これはすぐに、クエリごとにグラフの大部分を探索することになります。 

最悪の場合、各ノードは O(d) 個の次の候補に分岐し、深さが O(n) になる可能性があり、実際には指数関数的な動作が発生します。 BFS または DFS として慎重に実装したとしても、すべてのクエリの合計作業量は O(nq) になります。これは、指定された制限では不可能です。 

重要な構造的洞察は、制約は一般的なグラフ問題のように見えますが、インデックスによる順序付けと値の厳密な不等式によって単調な動作が強制されるということです。 開始ノードを修正すると、ノードの特定の領域のみが中間として機能できるようになり、これらの領域はクエリごとのグラフの走査を削除する方法で前処理できます。 

「ジャンプ距離最大 d」に関する制約は、エッジがインデックス空間内でローカルであることも示唆しています。 これにより、問題は、サイズ d のローカル ウィンドウを互換性ルールに基づいてマージすることによって接続性が決定されるという問題に変わります。 これはまさに、順序付けされた処理と組み合わされた素セット共用体が役立つ場所です。制約の下で安全に相互に到達できるインデックスを段階的に接続できると同時に、クエリごとにコストのかかる走査を再度行うことがなくなります。 

最終的な解決策は、動的な到達可能性の問題を、慎重に構築された Union-Find 構造を介した静的な接続クエリに削減します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(nq) | O(n) | 遅すぎる |
 | オフライン接続構築対応DSU | O((n + q) α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 有効な遷移は ai 値間の比較に依存するため、値の順序を尊重する方法でノードを並べ替えまたは処理します。 これにより、グラフ探索中に値の制約を繰り返しチェックすることを回避できます。 
2. インデックスに対して素の集合共用体構造を維持します。 遷移が想定されていないため、最初は各位置が分離されています。 
3. 値の昇順にノードをスイープします。 ノード i を処理するときは、ai に対する値の制約を満たす、インデックス距離 d 以内の可能なすべての前方接続を考慮します。 これらは、i から始まる有効なチェーンの一部になることができる唯一の候補です。 
4. 制約により直接的または間接的な有効な接続が許可される場合、このウィンドウ内の有効な候補 j ごとに、DSU 内の i と j をマージします。 DSU は、2 つのノードが制約の下で接続されると、それらは関連するクエリに対して到達可能な同じコンポーネントに属するという考えを取り入れています。 
5. すべての共用体を前処理した後、ui と vi が同じ DSU コンポーネントに属しているかどうかを確認して、各クエリに答えます。 存在する場合、有効なチェーンが存在します。 それ以外の場合は、そうではありません。 
6. 最小限の転送回数を必要とするクエリの場合、DSU コンポーネントを介した追加の前処理により、深さまたは代表的な距離を保存できるため、同じ接続構造内の最短のチェーン長を取得できます。 

なぜ効果があるのか:

 DSU は、2 つのインデックスを接続する有効な制約付き遷移のシーケンスが存在する場合に限り、2 つのインデックスが同じセット内にあるという不変条件を維持します。 値をスイープすることで、ノードを検討するときに、将来発生する可能性のあるすべての接続が一貫した順序で解決され、後方無効化が防止されます。 すべての制約はローカル インデックスの距離と値の順序にのみ依存するため、接続が確立されると、後で他のノードを処理することによって接続を解除することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    n, d = map(int, input().split())
    a = list(map(int, input().split()))

    order = sorted(range(n), key=lambda i: a[i])
    dsu = DSU(n)

    for idx in order:
        left = max(0, idx - d)
        right = min(n - 1, idx + d)
        for j in range(left, right + 1):
            if j != idx and a[j] > a[idx]:
                dsu.union(idx, j)

    q = int(input())
    out = []
    for _ in range(q):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        out.append("YES" if dsu.find(u) == dsu.find(v) else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DSU の実装では、パス圧縮とランクごとの結合を使用して、ほぼ一定の償却操作を保証します。 前処理ループは、各インデックスをその許可された近傍内の候補とのみ接続し、「最大 d までジャンプ」制約を直接結合プロセスにエンコードします。 

クエリ フェーズは 1 つの代表的な比較に縮小されます。これはまさに DSU が設計されたものです。 

## 実用的な例

 n = 5、d = 2、値が [3、1、4、2、5] の小さなインスタンスを考えてみましょう。 値によるソート処理順序は、ai が増加するにつれて 1、2、3、0、4 のインデックスになります。 

最初は、すべてのノードが分離されています。 

| ステップ | いずみ | 値 | チェックされた隣人 | 組合が結成されました |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 0、2、3 | (1,2)、(1,3) |
 | 2 | 3 | 2 | 1,2,4 | (3,4) |
 | 3 | 0 | 3 | 1,2 | (0,2) |
 | 4 | 2 | 4 | 0、1、3 | 新しいものはありません |
 | 5 | 4 | 5 | 2,3 | 新しいものはありません |

 1 と 4 の間の接続を尋ねるクエリは成功します。これは、1 が中間コンポーネントに接続し、最終的には中間ノードを介して上向きにマージされるためです。 

このトレースは、DSU がどのようにローカルの近隣を徐々にマージし、より価値の高いノードを通じて接続を伝播するかを示しています。

 ## 特殊なケース

 値が厳密に減少しているにもかかわらず、インデックスが十分に近いためローカル結合が依然として発生する場合、重大なエッジ ケースが発生します。 このような場合、単純な貪欲到達可能性では、前方への移動は不可能であると想定されますが、値の順序付けで間接的な接続が許可されている場合でも、DSU は中間ピボットを介してノードをマージします。 

もう 1 つのエッジ ケースは、d が配列全体をカバーするのに十分な大きさである場合です。 そうすれば、すべてのノードが他の多くのノードに接続できる可能性があり、DSU は 1 つのコンポーネントに集約されます。 単純なクエリごとのトラバーサルでは、冗長パスの探索に依然と​​して時間が無駄になりますが、DSU はすべてのクエリを一定時間内に即座に解決します。 

3 番目のケースは、n = 1 またはすべての値が等しい場合です。 どちらの状況でも、有効な厳密な比較は存在しないため、すべてのノードは分離されたままとなり、異なるノード間のすべてのクエリは NO を返さなければなりません。
