 ## 問題の理解

 私たちには家の木が与えられています。`1`永続的なシェルターとして機能する特別なノードです。 どの家にも最初はある程度の人が住んでいます。 家と家の間の道路は双方向であり、最初はすべての道路が使用可能です。 

2 種類の更新を処理します。 最初のタイプは、特定の家の人数を変更します。 2 番目のタイプは、特定の道路の状態を切り替えます。つまり、ブロックされている状態とブロックされていない状態が切り替わります。 更新のたびに、家に到達できる人数を計算する必要があります`1`封鎖されていない道路のみを使用します。 

したがって、アクティブなグラフはいつでも、固定ツリーからブロックされたエッジを削除することによって誘導される森林のような構造になります。 基本構造はツリーであるため、エッジをブロックすると接続されたコンポーネントに分割され、問題はノードを含むコンポーネントの値を合計することになります。`1`。 

重要な観察は、ノードのペア間の任意の到達可能性については決して尋ねられず、ノードがまだノードに接続されているかどうかだけが尋ねられることです。`1`。 これは、エッジの切り替えの下でツリー内の動的な接続を維持していることをすぐに示唆します。 

制約は以下を意味します`10^5`ノードと`10^5`したがって、各クエリの後に接続を最初から再計算するアプローチは、線形時間であっても遅すぎます。 クエリごとの単純な DFS または BFS では、`O(NQ)`周りにあるのは`10^{10}`最悪の場合の操作は明らかに実行不可能です。 

エッジケースは、更新に値の変更と構造の変更の両方が含まれるという事実から発生します。 微妙な問題は、ルートへのサブツリー パスに沿ったすべてのエッジがブロックされ、ノードが依然として大きな値を保持している場合でも、そのサブツリー全体が何も寄与しない場合です。 もう 1 つは、同じエッジの繰り返しの切り替えであり、これにより構造が振動し、単調な削除を前提とするアプローチが壊れます。 

素朴な再計算を壊す最小限の例:

 入力:```
3 3
1 2
2 3
10 20 30
2 3
1 3 100
2 3
```最初の切り替え後、ノード`3`ルートから切断されるため、貢献度が低下します。 値を更新して再度切り替えると、再接続されます。 ソリューションは、元に戻せる接続の変更を効率的に処理する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、クエリごとにノードから DFS または BFS を実行して到達可能性を再計算します。`1`現在アクティブなエッジ上で、到達可能なノードの値を合計します。 これは接続の定義に直接従うため正しいですが、遅すぎます。 各走査のコスト`O(N)`、そして`Q`オペレーションの総コストは次のようになります`O(NQ)`。 

主な問題点は、基礎となるグラフがツリーであるため、すべてのエッジが 2 つの部分間の接続性を一意に決定することです。 各切り替えにより、ツリー内の 1 つのブリッジが削除または復元されます。 この構造により、グローバルな再計算を回避できます。 

重要な洞察は、これをエッジがアクティブまたは非アクティブな動的なツリーとして扱うことです。 到達可能性を再計算する代わりに、各サブツリーがノードに接続されているかどうかを追跡するデータ構造を維持します。`1`は現在アクティブであり、アクティブな各コンポーネントの値の合計です。 ツリー内の各エッジは親子関係を定義するため (ルート化後)`1`)、エッジを切り替えると、相対的にサブツリー全体が効果的にアクティブ化または非アクティブ化されます。`1`。 

これは、オイラー ツアーを使用してツリーを平坦化し、各サブツリーが連続したセグメントになるようにすることを示唆しています。 各エッジのトグルは、セグメントのアクティブ化または非アクティブ化に対応します。 範囲更新とグローバル合計クエリを備えたセグメント ツリーまたはフェンウィック ツリーを維持します。 

したがって、この問題は、値のポイント更新と範囲アクティブ化切り替えを伴う古典的な動的サブツリーアクティブ化問題に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに BFS/DFS を再計算する | O(NQ) | O(N) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 ノードでツリーをルートします`1`そして、すべてのノードが`v`入場時間があります`tin[v]`そして退場時間`tout[v]`、およびそのサブツリー`v`連続したセグメントに対応する`[tin[v], tout[v]]`。 

また、各ノードで現在の人の値の配列も維持します。 

さらに、ノードが現在ルートに接続されているかどうかを保存するセグメント ツリーを維持します。`1`。 最初はすべてのエッジがアクティブであるため、すべてのノードに到達可能です。 

ここで操作を処理します。 

1. 隣接リストを構築し、ノードでツリーをルート化します。`1`、サブツリー クエリが範囲クエリになるように、親関係とオイラー ツアー間隔を計算します。 
2. 現在到達可能な場合、各ノードがその母集団値に寄与するノード上のセグメント ツリーを初期化します。 
3. 各エッジが現在アクティブであるかブロックされているかを示すブール状態を維持します。 
4. タイプのアップデートの場合`1 x y`、ノードの保存された人口を更新します`x`。 If ノード`x`現在、からアクセス可能です`1`、新しい値を反映するようにセグメント ツリーを調整します。 
5. タイプのアップデートの場合`2 x`間のエッジを特定します。`x`とその親が根付いたツリーにあります。 アクティブ状態を切り替えます。 エッジがブロックされると、より深いエンドポイントをルートとするサブツリー全体が切断されます。 ブロックが解除されると、再び接続されるようになります。 セグメント ツリーをアクティブ化または非アクティブ化することで、サブツリー間隔にわたってセグメント ツリーを更新します。 
6. 各操作後の答えは、セグメント ツリーのルート集合体に格納される値であり、ノードから到達可能な総人口を表します。`1`。 

重要な不変条件は、セグメント ツリーが常に、現在ノードに接続されているノードのセットを正確に反映することです。`1`。 エッジが切り替えられるたびに、正確に 1 つのサブツリーが切断または再接続され、オイラー ツアーにより、このサブツリーが連続したセグメントに対応することが保証されます。 更新は常にツリー構造と一致しているため、ノードが部分的に到達可能なセットに属することはできません。

import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, arr):
        n = len(arr)
        self.n = n
        self.sum = [0] * (4 * n)
        self.lazy = [0] * (4 * n)
        self.build(1, 0, n - 1, arr)

    def build(self, v, l, r, arr):
        if l == r:
            self.sum[v] = arr[l]
            return
        m = (l + r) // 2
        self.build(v * 2, l, m, arr)
        self.build(v * 2 + 1, m + 1, r, arr)
        self.sum[v] = self.sum[v * 2] + self.sum[v * 2 + 1]

    def push(self, v, l, r):
        if self.lazy[v]:
            m = (l + r) // 2
            self.apply(v * 2, l, m, self.lazy[v])
            self.apply(v * 2 + 1, m + 1, r, self.lazy[v])
            self.lazy[v] = 0

    def apply(self, v, l, r, val):
        if val == 1:
            self.sum[v] = 0
        else:
            self.sum[v] = 0
        self.lazy[v] = val

    def update_point(self, v, l, r, idx, val):
        if l == r:
            self.sum[v] = val
            return
        self.push(v, l, r)
        m = (l + r) // 2
        if idx <= m:
            self.update_point(v * 2, l, m, idx, val)
        else:
            self.update_point(v * 2 + 1, m + 1, r, idx, val)
        self.sum[v] = self.sum[v * 2] + self.sum[v * 2 + 1]

    def update_range(self, v, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.apply(v, l, r, val)
            return
        self.push(v, l, r)
        m = (l + r) // 2
        if ql <= m:
            self.update_range(v * 2, l, m, ql, qr, val)
        if qr > m:
            self.update_range(v * 2 + 1, m + 1, r, ql, qr, val)
        self.sum[v] = self.sum[v * 2] + self.sum[v * 2 + 1]

 ## 特殊なケース

 重要なエッジ ケースは、同じエッジを繰り返しトグルします。 アルゴリズムは、明示的に保存することでこれを処理します。`active`エッジごとにフラグを立て、それに応じてサブツリーの寄与を反転し、再接続によって正確な元のサブツリーの合計が復元されるようにします。 

もう 1 つのケースは、更新が現在ルートから切断されているノードにのみ影響する場合です。 この状況では、ポイントの更新により保存された値が変更されますが、再接続が発生するまでグローバル合計には影響しません。 値の保存と到達可能性をこのように分離することは、正確性を保つために不可欠です。 

最後のエッジ ケースは、ルートに属するすべてのエッジがブロックされる場合です。 他のすべてのサブツリーがゼロに設定され、到達可能性の定義と一致するため、セグメント ツリーは自然に全体の合計をルート ノード自身の値に縮小します。
