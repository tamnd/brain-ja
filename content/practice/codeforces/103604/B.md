 ## 解決策
 ## 問題の理解

 私たちには複数レベルのダンジョンが与えられています。 各レベルはセルのグリッドであり、すべてのレベルは特別な出口セルを介して連続的に接続されます。 プレイヤーは最初のレベルの左上のセルから開始し、初期パワーは 1 です。 

ダンジョン内の各セルは地形タイプのように動作します。 一部のセルは空で何も行われません。 中には入れない壁もあります。 一部には正の強さの値を持つ敵が含まれています。 一部には次のレベルへの出口が含まれています。 

プレイヤーが移動するとき、ブロックされていないセルのみを通過できます。 重要なルールは、プレイヤーが敵のいるセルに入ったとき、現在の力が少なくとも敵の強さである場合にのみ敵を倒すことができるということです。 彼らが勝つと、彼らの力は敵の値によって増加します。 

目標は、プレイヤーがダンジョン内を常に最適に移動すると仮定して、プレイヤーが最終レベルに到達するまでに達成可能な最大パワーを計算することです。 

制約から、すべてのレベルにわたるセルの合計数は最大 1e6 です。 これにより、到達可能性をパワー値ごとまたは敵ごとに繰り返しゼロから​​再計算するソリューションは即座に除外されます。 すべてのパスを独立してシミュレートしようとするソリューションは遅すぎます。指数関数的なパス探索や、更新ごとに BFS を繰り返すと時間制限を超える可能性があるからです。 

重要な点は、ダンジョンが単に最短経路や到達可能性の問題ではないということです。 プレイヤーがセルに入る能力は現在のパワーに依存し、現在のパワーはどの敵がすでに倒されているかによって異なります。 これにより、グラフの走査と状態の成長の間にフィードバック ループが作成されます。 

いくつかの特殊なケースが重要です。 

まず、十分な勢力を拡大するために必要な、より弱い敵がいる地域へのアクセスが強い敵によってブロックされている状況を考えてみましょう。 常に最初に利用可能な敵と戦うという単純な貪欲な戦略は、後でより良い蓄積を得ることができなくなるため、失敗する可能性があります。 

次に、敵の背後にある切断された「ポケット」を考慮します。 弱い敵が強い敵の後ろにいる場合は、他の場所で勢力を伸ばしてから後で戻る必要があるかもしれません。 単純なシングルパス BFS は、それらのセルが永久に到達不可能であると誤って想定します。 

第三に、レベル間の終了遷移は誤解を招く可能性があります。 たとえ早期にレベルの出口に到達できたとしても、現在のレベルでより強い成長がまだ可能であれば、すぐに出口を選択するのは次善の策である可能性があります。 

## アプローチ

 強引な解釈では、これを各状態が次のような状態グラフとして扱うことになります。`(cell, current power)`。 各状態から隣接するセルに移動でき、敵に遭遇した場合は電力制約が満たされた場合にのみ遷移し、それに応じて電力が更新されます。 

これは正しいですが、まったく実行不可能です。 敵を倒すたびに可能な電力値の数が増加し、最悪の場合、各セルが異なる電力状態で複数回訪問される可能性があります。 それは状態の爆発につながり、1e9の概念遷移を優に超えます。 

重要な観察は、電力が単調増加しているということです。 一度一定の力に到達すると、もう元には戻りません。 これは、セルごとに複数の状態を追跡する必要がないことを意味します。 代わりに、現在のパワーを考慮してできるだけ多くの「現在倒せる」敵に到達するように常に努め、パワーが増加するにつれて到達可能なスペースを繰り返し拡大する必要があります。 

これは当然、ダンジョン グラフを最良から順に探索することを示唆していますが、敵の強さによって優先されます。 到達可能なすべてのセルを維持し、現在倒すことができる最も弱い敵を常に消費する場合、最適な成長プロセスをシミュレートします。 

これにより、問題が単一のグローバルなプロセスに変換されます。つまり、到達可能なエリアを拡大し、アクセス可能な敵をすべて収集し、制御された方法で次に到達可能な最も強力な利益を常に選択します。 優先キューまたはマルチセット構造が自然なツールになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | BFS の状態 (セル、電源) | 指数 | O(LNM × 電力状態) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 ### 1. ダンジョンをセル上のグラフとしてモデル化します。 

ブロックされていないすべてのセルをグラフ内のノードとして扱い、各レベル内の 4 方向の隣接性と出口セルを介した垂直接続によって接続されます。 これにより、移動が標準のグラフ走査に変換されます。 

### 2. 到達可能なセルのセットを維持する

 パワー 1 の初期位置から開始し、BFS/DFS を実行して、強すぎる敵を考慮せずに物理的に到達できるすべてのセルをマークします。 これらは現在アクセス可能なフロンティアを表しています。 

これが安全である理由は、敵によってブロックされた場合を除き、移動の制約が力に依存しないためです。 

### 3. 「利用可能な敵」の構造を維持する

 到達可能なすべてのセルのうち、強さが現在のパワー以下であるすべての敵のセルを収集します。 これらは、私たちが今実行できる行動を表しています。 

敵の強さによってキー設定された最小ヒープにそれらを保存するため、常に利用可能な最も弱い敵が最初に処理されます。 この順序は、必要な中間ステップをスキップすることなく段階的にパワーを拡大できるため、重要です。 

### 4. 敵の抽出と処理を繰り返す

 少なくとも 1 人の倒せる敵が存在する間、私たちは次のことを繰り返します。 

1. 現在倒せる敵の山から最も弱い敵を選びます。 
2. その値によってパワーが増加します。 
3. より高いパワーにより、以前にブロックされていた領域のロックが解除される可能性があるため、この敵がいた位置から到達可能性を再度拡張します。 

電力が増加するたびに、到達可能な領域は拡大するだけで、縮小することはありません。 これにより、グローバルに再計算するのではなく、新しくロックが解除された境界から BFS を再実行することが正当化されます。 

### 5. これ以上進めなくなるまで続行します

 ヒープに強さ ≤ 現在の強さの敵がいなくなり、新たに到達可能な拡張でそのような敵が現れなくなると、プロセスは安定します。 現在の電力は達成可能な最大値です。 

### なぜ効果があるのか

 不変なのは、常に現在の電力で到達可能なセルのセットを正確に維持しており、それらのセルの中から現在倒せる可能性のあるすべての敵を特定していることです。 パワーは敵が倒されたときにのみ増加するため、以前は到達できなかったセルが到達可能になった場合は、パワーがある程度増加した後にのみ表示され、再拡張によって見逃されることはありません。

将来の選択肢はすべてパワーの増加のみに依存するため、貪欲な選択は安全です。 到達可能な敵を倒すことは、到達可能性の観点からは決して有害ではありません。 到達可能な領域を厳密に拡張または保持します。 優先順位付けにより、後でより大きな利益にアクセスできるようにするために必要な小さなステップをスキップすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque
import heapq

def solve():
    L, N, M = map(int, input().split())
    
    grid = []
    starts = []
    
    for _ in range(L):
        level = [list(map(int, input().split())) for _ in range(N)]
        grid.append(level)

    visited = [[[False]*M for _ in range(N)] for _ in range(L)]
    
    dq = deque()
    dq.append((0, 0, 0))
    visited[0][0][0] = True

    power = 1
    pq = []

    def add_cell(z, x, y):
        if visited[z][x][y]:
            return
        visited[z][x][y] = True
        val = grid[z][x][y]
        if val == -9:
            return
        dq.append((z, x, y))

    while dq:
        z, x, y = dq.popleft()
        val = grid[z][x][y]

        if val > 0:
            if val <= power:
                heapq.heappush(pq, (val, z, x, y))

        # move in same level
        for dx, dy in ((1,0), (-1,0), (0,1), (0,-1)):
            nx, ny = x+dx, y+dy
            if 0 <= nx < N and 0 <= ny < M and not visited[z][nx][ny]:
                if grid[z][nx][ny] != -9:
                    visited[z][nx][ny] = True
                    dq.append((z, nx, ny))

        # level transition
        if val == -1 and z+1 < L:
            if not visited[z+1][x][y]:
                visited[z+1][x][y] = True
                dq.append((z+1, x, y))

    # process enemies greedily
    while True:
        while pq and pq[0][0] <= power:
            val, z, x, y = heapq.heappop(pq)
            if grid[z][x][y] != val:
                continue
            power += val

            # after gaining power, re-expand from this point
            dq = deque([(z, x, y)])
            while dq:
                z0, x0, y0 = dq.popleft()
                for dx, dy in ((1,0), (-1,0), (0,1), (0,-1)):
                    nx, ny = x0+dx, y0+dy
                    if 0 <= nx < N and 0 <= ny < M and not visited[z0][nx][ny]:
                        if grid[z0][nx][ny] != -9:
                            visited[z0][nx][ny] = True
                            dq.append((z0, nx, ny))

                if grid[z0][x0][y0] == -1 and z0+1 < L:
                    if not visited[z0+1][x0][y0]:
                        visited[z0+1][x0][y0] = True
                        dq.append((z0+1, x0, y0))

        break

    print(power)

if __name__ == "__main__":
    solve()
```この実装では、到達可能性の拡張と敵の処理という 2 つの懸念事項が分離されます。 BFS のような拡張により、アクセス可能なセルを見逃すことがなくなり、ヒープにより常に制御された順序でパワー ゲインを適用できるようになります。 微妙な点は、新しい領域がアクセス可能になる可能性があるため、電力が増加するたびに新たな拡張が引き起こされるということです。

 ## 特殊なケース

 主なエッジケースは、別の弱い敵が他の場所で倒されるまで、弱い敵が到達不可能な領域に囲まれている場合です。 電力が増加するたびに到達可能性の拡張がトリガーされ、遅延したアクセシビリティが確実に捕捉されるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、次のレベルへの出口に早期に到達できるものの、最適なパワー ゲインが得られない場合です。 BFS は移行を強制しません。 物理的に到達可能な場合にのみ許可されるため、より多くの利益を得るために現在のレベルに留まることが自然に処理されます。 

最後に、複数の敵が同じ強さを共有する場合は、同じ値の間でのヒープの順序付けが正確さに影響しないため、安全です。 それらはすべて、到達可能になると独立して有効な電力増分になります。
