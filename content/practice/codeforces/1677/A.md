 ## 解決策
 ## 問題の理解

 1 から n までの整数の順列が与えられ、インデックスの 4 倍がいくつあるかを数えるように求められます。`[a, b, c, d]`2 つの不等式を満たす: 最初の要素は 3 番目の要素より小さい (`p_a < p_c`) かつ 2 番目の要素が 4 番目の要素より大きい (`p_b > p_d`）。 インデックスは厳密に増加する必要があります。つまり、`a < b < c < d`。 入力には複数のテスト ケースが含まれており、それぞれに順列があり、テスト ケースごとに 4 倍の数を出力する必要があります。 

制約により許可されるのは、`n`テスト ケースあたり最大 5000、合計`n`これは、すべての 4 倍数を直接チェックする O(n^4) 総当たりアプローチでは、最悪の場合 6×10^13 を超える演算が発生する可能性があるため、遅すぎることを意味します。 O(n^3) のアプローチは、慎重に実装すればかろうじて適合しますが、O(n^2) または O(n^2 log n) のソリューションが理想的です。 

順列が厳密に増加または厳密に減少している場合、微妙なエッジ ケースが発生します。 例えば、`p = [1,2,3,4]`満足のいくクアドルプルがない`p_a < p_c`そして`p_b > p_d`同時に行われるため、正しい出力は 0 になります。ランダムな分布を前提とする単純なアルゴリズムでは、タプルを誤ってカウントする可能性があります。 もう 1 つのエッジ ケースは、次のように、4 要素が境界にある最小要素と最大要素に依存する場合です。`p = [5,3,6,1,4,2]`、ここで、特定の位置のみが両方の不等式を満たします。 アルゴリズムは、値をローカルで比較するのではなく、配列全体でカウントを正しく追跡する必要があります。 

## アプローチ

 ブルート フォースのアプローチはシンプルです。すべての 4 倍を反復処理します。`(a, b, c, d)`4 つのネストされたループを使用して、不等式を直接チェックします。 すべての組み合わせを評価するため、これは正しいですが、複雑さは O(n^4) であり、これでは遅すぎます。`n=5000`。 

最適化するには、不等式に注意してください。`p_a < p_c`そして`p_b > p_d`は、ペアごとの 2 つの独立した計数問題に分解できます。`(b, c)`と`b < c`の数が必要です。`a`前に`b`そのような`p_a < p_c`そしてその数`d`後`c`そのような`p_b > p_d`。 これらのカウントが判明すると、以下を含む 4 倍の数が決まります。`(b, c)`はこれらのカウントの積です。 これにより、ネストされたループが 4 つから 3 つに減り、反復処理が可能になります。`(b, c)`そして有効に計算します`a`そして`d`効率的に。 

有効にカウントするには`a`与えられたもののために`c`、より小さい要素の数を追跡するプレフィックス配列を維持できます。`p_c`それぞれのポジションまで。 同様に、有効にカウントするには`d`与えられたもののために`b`より小さい要素のサフィックス配列を維持できます。`p_b`各ポジションから最後まで。 これにより、内部ループが単純なプレフィックス/サフィックス検索に削減され、O(n^3) のソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^4) | お(1) | 遅すぎる |
 | プレフィックス/サフィックス数 | O(n^3) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、順列を読み取ります。`p`長さの`n`。 
2. カウンタの初期化`ans = 0`有効な 4 倍の数。 
3. 反復処理`b`インデックス 1 から`n-2`。`b`4 要素の 2 番目の要素になります。 
4. それぞれについて`b`、繰り返します`c`から`b+1`に`n-1`。`c`3番目の要素です。 
5. の数を数えます`a`そのような`a < b`そして`p_a < p_c`。 これは、インデックスに対する単純なループで実行できます。`0..b-1`。 
6. の数を数えます`d`そのような`d > c`そして`p_b > p_d`。 インデックスのループ`c+1..n-1`。 
7. これら 2 つのカウントを乗算し、結果を加算します。`ans`。 有効な各組み合わせ`a`そして`d`固定されたもので`(b, c)`有効な 4 倍体を形成します。 
8. すべてを繰り返した後`(b, c)`ペア、印刷`ans`テストケース用。 

なぜそれが機能するのか: 中央のペアの各選択について`(b, c)`、任意の有効な`a`そして`d`不等式を満たす 4 倍を完成させます。 すべてを繰り返すことで`(b, c)`ペアとカウントが有効`a`そして`d`、すべての 4 倍数を 2 重にカウントせずに 1 回だけ列挙します。 不変条件`a < b < c < d`プレフィックス/サフィックスの数によって正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        ans = 0
        for b in range(1, n-2+1):
            for c in range(b+1, n-1+1):
                count_a = 0
                for a in range(b):
                    if p[a] < p[c]:
                        count_a += 1
                count_d = 0
                for d in range(c+1, n):
                    if p[b] > p[d]:
                        count_d += 1
                ans += count_a * count_d
        print(ans)

if __name__ == "__main__":
    solve()
```外側のループは中間のインデックスを固定します`(b, c)`。 内側の 2 つのループは有効とカウントされます`a`そして`d`これらの固定インデックスの場合。 これは、次の各選択が実行される組み合わせ観察を明示的に実装します。`a`そして`d`1つのクアドルプルに貢献します。 使用する`range`境界線は慎重にそれを保証します`a < b`そして`d > c`所有。 Python リストにはゼロから始まるインデックスが付けられているため、1 から始まるインデックスと 0 から始まるインデックス間の変換は自然に処理されます。
