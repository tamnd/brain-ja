 ## 問題の理解

 一連の位置が与えられ、各位置は特定のタイプの同一の宝石のスタックに貢献します。 位置`i`保持します`a_i`タイプの宝石`i`。 任意のセグメント`[l, r]`したがって、マルチセットを形成します。`i`正確に表示されます`a_i`の回`i`はセグメント内にあり、それ以外の場所には表示されません。 

次に、セグメントごとに、セグメント内のタイプごとに独立して、次から任意の数のコピーを選択することによって形成される、考えられるすべての「サブマルチセット」を検討します。`0`まで`a_i`。 このような各選択はベクトルを定義します`t`各タイプの宝石が何個選択されるかを説明します。 

このような選択ごとに 2 つの量を計算します。 1 つ目は、型の重み付け合計です。ここで、型は`i`貢献する`p^{t_i} * t_i^k`。 2 番目は、選択したマルチセットに現れる個別のタイプの数です。 最終的な答えは、すべての選択肢に対するこれら 2 つの値の積を合計します。`t`、そしてすべてのセグメントにわたって。 

この構造はセグメントにわたって乗算的ですが、問題は、各セグメントに指数関数的に多くのサブマルチセットが含まれており、式が「非ゼロ成分の数」項を通じてすべての座標を結合していることです。 ここが本当の難しさです。指標項がなければ、問題は完全に因数分解されてしまいます。 

制約`n ≤ 10^5`そして`k ≤ 10^5`セグメントまたはセグメントのサブセットに対する列挙を直ちに除外します。 平`O(n^2)`セグメントの列挙は不可能です。 実行可能な解決策は、すべてのセグメントの寄与を全体として削減する必要があります。これには、おそらく合計の順序を逆にして、各位置が構造化された方法ですべてのセグメントに寄与するようにする必要があります。 

素朴なアプローチで解決します`(l, r)`、すべて列挙します`t`、式を計算して合計します。 単一の長さのセグメントであっても`m`、これは`Π (a_i + 1)`州はすでに天文学的な規模に達しており、`a_i`自明ではない。 

微妙なエッジケースが現れるのは、`a_i = 1`。 それでも、各セグメントの長さは`m`もっている`2^m`サブマルチセットの場合、問題はすべての部分配列のすべてのサブセットにわたる非線形関数の合計となり、やはり組み合わせ的に爆発します。 

重要な問題は、インジケーターが`sum [t_i > 0]`座標間の独立性が失われるため、直接因数分解ができなくなります。 

## アプローチ

 結合項を無視すると`sum [t_i > 0]`の場合、式はセグメント内の位置の積になります。これは、各座標が独立して寄与するためです。`p^{t_i} t_i^k`。 その単純化された世界で、それぞれの立場が`i`ローカル多項式を提供します。```
F_i = sum_{t=0}^{a_i} p^t * t^k
```そして各セグメントはこれらの寄与を単純に掛け合わせるだけです。 

本当の問題は、空ではない選択された型の数も乗算することです。 この用語はグローバルです。どれだけのポジションが選ばれるかをカウントします。`t_i > 0`。 このような項の標準的なトリックは、生成関数に対する導関数のような演算子として解釈することです。 

「ゼロ以外の座標の数」を直接数えようとする代わりに、標準の恒等式を使用してそれを書き直します。```
count of non-empty coordinates = sum over i of [t_i > 0]
```したがって、元の式は次のようになります。```
sum_i (p^{t_i} t_i^k [t_i > 0]) * 1 + cross-interaction induced by multiplicity of choices of i
```合計を並べ替えると、位置が固定されます`i`インジケーターを担当する「マークされた座標」として、他のすべての座標を独立して扱います。 これにより、問題は次のように変換されます。 

それぞれに`i`、インジケーターの合計において顕著な非ゼロ寄与因子である場合に、その寄与度を計算します。 

これによりカップリングが解消されます。どのインデックスがインジケーターに寄与するかを固定すると、他のすべてのインデックスは無制限の合計を通じてのみ寄与します。`t_j`。 

これでセグメント構造が管理しやすくなりました。 ポジションごとに`i`、セグメントの数を数えます`[l, r]`それを含めてください、つまり`i * (n - i + 1)`。 ただし、他のポジションの選択肢が各セグメント内でどのように増加するかも考慮する必要があります。 これにより、間隔にわたる 2 つのグローバル集計を定義することになります。 

1 つは無制限の選択肢です。```
A_i = sum_{t=0}^{a_i} p^t
```もう 1 つは重み付けされた選択肢用です。```
B_i = sum_{t=0}^{a_i} p^t t^k
```各セグメントの貢献は次の積に分解されます。`A`単一の位置を次のように置き換えた用語`B`。 

残りの最後の困難は、次の積をすべてのセグメントにわたって効率的に合計することです。`A_i`、およびによる交換も処理します。`B_i`。 これは古典的な「重みの積のすべての部分配列の合計」構造であり、プレフィックス積と線形 DP による寄与手法を使用して計算できます。 

したがって、最適な解決策は、問題全体を、アレイ全体をスイープするときに 2 つの実行中のセグメント積 DP 状態を維持することに帰着します。

 ## アルゴリズムのチュートリアル

 1. すべてのポジションの事前計算`i`2 つの値:`A_i = sum_{t=0}^{a_i} p^t`そして`B_i = sum_{t=0}^{a_i} p^t t^k`。 これらはそれぞれ、選択の合計の重みを表します。`i`、および加重バージョンでは、`i`指標用語における傑出した貢献者です。 この分離により、元の式を線形化できるようになります。 
2. 固定セグメントについてそれを観察します。`[l, r]`、指標を無視した場合、その寄与度は次のようになります。`∏ A_i`。 これは、セグメント全体にわたるすべての独立した選択に対応します。 
3. 指標用語は 1 つの指標を選択することで処理できます`i`内部`[l, r]`「アクティブな」貢献を提供します。 そのインデックスについては、`A_i`による`B_i`、他のすべてのポジションはそのままです`A_j`。 これにより、セグメントの寄与が、識別されたインデックスの選択の合計に変換されます。 
4. 固定インデックスの場合`i`、それを含むすべてのセグメントに対する合計寄与度を計算します。 すべてのセグメント`[l, r]`貢献します:```
B_i * (∏_{j in [l, r], j != i} A_j)
```それで因数分解します`B_i`すべての製品を個別にカウントします`A`以下を含むサブ配列に対して`i`。 
5. DP 状態を定義する`dp[i]`の積の合計として`A`で終わるすべてのサブ配列にわたって`i`。 これは、前の部分配列を拡張することで計算されます。`dp[i] = A_i * (1 + dp[i-1])`。 これにより、すべての適切なエンドポイントがキャプチャされます。 
6. 同様に、リバース DP を維持します。`rev[i]`で始まるサブ配列の場合`i`、同様に右から左に計算されます。 
7. 指数寄与度合計`i`すべてのセグメントにわたって、`B_i * (sum of left contributions) * (sum of right contributions)`、ここで、左側と右側の部分は、周囲のセグメント境界を選択するすべての方法を説明します。`i`。 
8. この貢献度をすべて合計します`i`最終的な答えのモジュロを取得するには`998244353`。 
9. 事前計算`t^k`そしてべき乗剰余を慎重に使用して幾何学和を計算します。`A_i`そして`B_i`位置ごとに O(log k) で計算できます。 

### なぜ効果があるのか

 正確さは、グローバル指標を「責任のある指標」の合計に分解するかどうかにかかっています。 インジケーターの有効な割り当てはそれぞれ、1 つのインデックスの選択に一意に対応します。`i`と`t_i > 0`それがカウントされた貢献者として指定されます。 そのインデックスが固定されると、残りのすべての座標は独立するため、セグメントの寄与は、独立したローカル重みのプレフィックスとサフィックスの積に考慮されます。 サブ配列上の DP は、二重にカウントすることなくすべてのセグメント境界を正確に列挙し、それぞれの境界を保証します。`(l, r, i)`構成は 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def mod_pow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve():
    n, k, p = map(int, input().split())
    a = list(map(int, input().split()))

    # precompute t^k is expensive per t up to a_i,
    # so we compute on the fly with memoized pow if needed
    # but we only need sum over t, so we precompute prefix powers of p
    ans = 0

    # A_i and B_i
    A = [0] * n
    B = [0] * n

    for i in range(n):
        pk = 1
        sA = 0
        sB = 0
        # compute sum t^k p^t
        for t in range(a[i] + 1):
            if t > 0:
                pk = pk * t % MOD
                pk = pk if t == 1 else pk  # placeholder clarity
            # actually recompute t^k properly
            # (replace by pow)
            val = mod_pow(p, t)
            if t > 0:
                sA = (sA + val) % MOD
                sB = (sB + val * mod_pow(t, k)) % MOD
            else:
                sA = (sA + 1) % MOD
        A[i] = sA
        B[i] = sB

    # prefix DP for subarray products
    dp = [0] * n
    dp[0] = A[0]
    for i in range(1, n):
        dp[i] = A[i] * (1 + dp[i-1]) % MOD

    # suffix DP
    suf = [0] * n
    suf[-1] = A[-1]
    for i in range(n-2, -1, -1):
        suf[i] = A[i] * (1 + suf[i+1]) % MOD

    # combine contributions
    for i in range(n):
        left = 1 + (dp[i-1] if i > 0 else 0)
        right = 1 + (suf[i+1] if i + 1 < n else 0)
        ans = (ans + B[i] * left % MOD * right) % MOD

    print(ans)

if __name__ == "__main__":
    solve()

最後のループは、各インデックスを指標項の一意のソースとして解釈し、左右のセグメント拡張を乗算的に結合します。 

微妙な点としては、`left`そして`right`空の拡張子が含まれます。これは、正確に開始または終了するセグメントに対応します。`i`。 これにより、単一要素セグメントの欠落が回避されます。
