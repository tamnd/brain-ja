 ## 解決策
 ## 問題の理解

 1 から 1 までの整数の順列が与えられます。$n$、そしてこの順列の連続したサブセグメントについて複数のクエリが尋ねられます。 サブセグメントの最大値がそのセグメント内の 2 つの要素の積として表現できる場合、そのサブセグメントは _Beautiful_ と呼ばれます。 クエリごとに、指定された範囲に完全に含まれるすべての美しいサブセグメントをカウントする必要があります。 

単純に理解すると、すべてのサブセグメントを反復処理し、それらの最大値を計算し、その最大値まで乗算されるペアがあるかどうかを確認したくなるかもしれません。 ただし、以来、$n$到達できる$2 \cdot 10^5$そしてクエリの数$q$到達できる$10^6$、クエリごとにすべてのサブセグメントを反復処理することは不可能です。 具体的には、$\Theta(n^2)$これは数秒で処理できる量をはるかに超えています。 

考慮すべきエッジ ケースには、ペアが存在しない長さ 1 のセグメント、および最大値が素数であるセグメントが含まれます。これらのセグメントは、反復しない限りセグメントの 2 つの整数の積として表現できません (順列では不可能です)。 たとえば、セグメント`[3]`最大値があります`3`でもいいえ`i < j`すべてのセグメントに有効なペアがあると仮定する不用意な解決策は、カウントをオーバーします。 

この問題は、配列全体について答えるだけでなく、任意の範囲について効率的に答えることを求めています。 これは、クエリにサブリニア時間で応答できる前処理ステップまたはデータ構造が必要であることを示唆しています。 

## アプローチ

 強引なアプローチでは、すべてのサブセグメントを考慮することになります。`[x, y]`各クエリ間隔内で`[l_i, r_i]`、その最大値を計算し、セグメント内のすべてのペアをチェックして、その積が最大値と等しいかどうかを確認します。 これは定義に直接従うため、原理的には正しいですが、複雑さは次のとおりです。$O(q \cdot n^2)$最悪の場合、これは上限では不可能です ($q \sim 10^6$、$n \sim 2 \cdot 10^5$）。 単一のクエリでも時間がかかる場合があります$O(n^2)$動作が遅すぎます。 

より高速な解決策を明らかにする重要な観察は、各順列要素が一意であり、サブセグメントの最大値が常にセグメント内の要素の 1 つであるということです。 したがって、各値の位置に注目するだけで済みます。 与えられた最大値に対して$m$位置にある$k$、以下を含むサブセグメント$k$より小さい値が存在する場合にのみ美しくなることができます$a$インデックスで$i < k$より小さい値$b$インデックスで$j > i$そのような$a \cdot b = m$。 これにより、各最大要素の周囲で有効な積を見つけるという問題が軽減されます。 

要素を降順で繰り返し、セグメント ツリーまたはバイナリ インデックス付きツリーを使用して小さい要素の位置を効率的に追跡することにより、クエリごとに、特定の最大値を含み、積の条件を満たすサブセグメントの数を数えることができます。 順列の構造により、各積チェックには既存の要素のペアのみが含まれ、各要素の潜在的な約数の数が含まれることが保証されます。$m$に限定されています$O(\sqrt{n})$。 

これにより、すべてのクエリに大まかに答える最適なソリューションが可能になります。$O(n \sqrt{n} + q \log n)$慎重なオフライン処理を使用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(q \cdot n^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n \sqrt{n} + q \log n)$|$O(n + q)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. Precompute the position of each value in the permutation in an array`pos`そのような`pos[value] = index`。 これにより、一定時間内に任意の数値を見つけることができます。 
2. 順列値を最大から最小まで繰り返します。 それぞれの値について$m$、すべての約数のペアを生成します$(a, b)$そのような$a \cdot b = m$そして両方とも$a$そして$b$順列で存在します。 順列なので位置のみを考慮します`pos[a]`そして`pos[b]`。 
3. 各約数ペアについて$(a, b)$、最小位置と最大位置を特定します。`pos[m]`、`pos[a]`、 そして`pos[b]`。 これにより、3 つの要素すべてを含む最小のセグメントが決定され、これが製品の条件が満たされる最小のセグメントになります。 
4. セグメントを効率的にカウントするためのデータ構造を維持します。 位置ごとに、この最大値が得られる間隔の配列を更新します。`m`美しいセグメントを定義する値になる可能性があります。 プレフィックス合計を使用してクエリに答える$O(1)$前処理後のクエリごと。 
5. すべてのクエリをオフラインで処理します。 プレフィックス合計配列を活用するには、左エンドポイントまたは右エンドポイントで並べ替えます。 クエリごとに`[l, r]`、事前に計算された累積カウントを使用して、間隔内に完全にある美しいセグメントのカウントの合計を計算します。 
6. 各クエリの結果を返します。 

機能する理由: このアルゴリズムは、考えられるすべての最大値とすべての有効な約数のペアを考慮するため、美しいセグメントを見逃すことはありません。 プレフィックスの合計により、重複するセグメントが正確に 1 回カウントされることが保証されます。 降順で反復することで、小さい最大値よりも大きい最大値を処理することが保証されます。最大の要素がサブセグメントの最大積を決定するため、これは重要です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
p = list(map(int, input().split()))
pos = [0] * (n + 1)
for i, val in enumerate(p):
    pos[val] = i

import math
from collections import defaultdict

# For each segment, we store how many beautiful subsegments start at each index
count = [0] * (n + 1)

for m in range(1, n + 1):
    limit = int(math.isqrt(m)) + 1
    for a in range(1, limit):
        if m % a == 0:
            b = m // a
            if a <= n and b <= n:
                idxs = sorted([pos[m], pos[a], pos[b]])
                l, _, r = idxs[0], idxs[1], idxs[2]
                count[l] += 1
                if r + 1 < n:
                    count[r + 1] -= 1

# prefix sum to accumulate
for i in range(1, n):
    count[i] += count[i - 1]

# compute prefix sum again for query range sums
for i in range(1, n):
    count[i] += count[i - 1]

for _ in range(q):
    l, r = map(int, input().split())
    l -= 1
    r -= 1
    ans = count[r]
    if l > 0:
        ans -= count[l - 1]
    print(ans)
```最初のセクションでは、各値をその位置にマップします。これにより、定数時間内に任意の数値を見つけることができます。 ダブルプレフィックス合計トリックにより、ポイント更新が範囲合計に効率的に変換されます。 除数のペアを反復することで、実現可能な美しいセグメントのみが考慮されるようになります。 インデックスを並べ替えることにより、次のことが保証されます。`l`そして`r`最小のカバーセグメントを正確に特定します。
