 ## 解決策
 ## 問題の理解

 特定の頂点にトークンが含まれ、特定の頂点にボーナスが含まれる、接続された無向グラフが与えられます。 トークンはエッジに沿って移動できますが、移動回数は制限されています。各トークンは最初に 1 回だけ移動できます。 ただし、トークンがボーナスを含む頂点に着地した場合、ゲームは他のトークンからの追加の移動を許可します。 複数のトークンが同じ頂点を占めることができ、いずれかのトークンがフィニッシュである頂点 1 に到達するとゲームに勝利したとみなされます。 トークンが頂点 1 から開始すると、すぐにゲームに勝ちます。 

入力には複数のテスト ケースが含まれます。 各テスト ケースは、グラフ構造、トークンの位置、ボーナスの位置を提供します。 グラフには、すべてのテスト ケースにわたって合計で最大 200,000 個の頂点と 200,000 個のエッジを含めることができます。つまり、ソリューションはテスト ケースごとにほぼ線形または線形である必要があります。 すべての頂点またはすべてのトークンにわたるネストされたループは、おそらく遅すぎるでしょう。 エッジ ケースには、ボーナスがゼロのグラフ、トークンがすでに終了点にある、または頂点 1 から遠く離れて開始するが連鎖を許可するボーナスに隣接するトークンが含まれます。 

単純な解決策では、各ターンでどのトークンが移動できるかを追跡しながら、一連の動きをすべてシミュレートしようとする可能性があります。 各ボーナスが任意のトークンからの動きをトリガーする可能性があり、複数のトークンが相互作用するため、これはすぐに指数関数的になります。 

## アプローチ

 ブルート フォース アプローチでは、ボーナス チェーン ルールを尊重しながら、グラフ内のすべてのパスを探索して、トークンの移動の可能なすべてのシーケンスをシミュレートしようとします。 これは原理的には正しいですが、最大 200,000 個の頂点とエッジ、およびグラフごとに複数のトークンがある場合、シーケンスの数は組み合わせ的に増加します。 最悪の場合、シーケンスの数は指数関数的に増加し、2 秒の制限時間を大幅に超えます。 

重要な点は、すべてのトークンの一連の動きを個別に追跡する必要がないということです。 各ボーナスにより効果的に移動を連鎖させることができますが、重要なのは、すべてのボーナスを「別の移動を可能にする中間頂点」として扱った場合に到達可能な、トークンから頂点 1 までのパスが存在するかどうかです。 これを、ボーナスを持つすべての頂点がゲートウェイになるグラフ到達可能性の問題として再構成できます。トークンがボーナスに到達できれば、どのトークンからでも移動を「再開」できます。 したがって、問題は 2 レベルの検索に帰着します。 まず、トークンから、またはボーナス チェーンを介して 1 回の移動で到達可能なすべての頂点を見つけます。 次に、頂点 1 がそのセット内にあるかどうかを確認します。 

幅優先検索 (BFS) または深さ優先検索 (DFS) を使用して、すべてのトークンから開始してエッジに沿って拡張することで、これを効率的に実装できます。 ボーナスに遭遇したときは常に、それを「無料拡張」とみなし、他のトークンからの移動を継続できるようにします。 これは事実上、ボーナスを複数回再訪できるキューを持つすべてのトークンからの BFS です。 グラフが接続されており、頂点とエッジの数が制限されているため、BFS はテスト ケースごとに O(n + m) で実行されます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースについて、頂点、エッジ、トークン、ボーナスの数を読み取ります。 トークンとボーナスポジションをセットで保存して、メンバーシップを簡単に確認できます。 グラフの隣接リストを作成します。 
2. いずれかのトークンがすでに頂点 1 にある場合は、すぐに YES を出力し、次のテスト ケースに進みます。 
3. すべてのトークンとその開始位置をマークする訪問済みセットを含む BFS のキューを初期化します。 
4. キューが空でない間に、頂点をポップします。`u`。 もし`u`頂点 1 の場合、YES を出力し、BFS を停止します。 
5. 隣人ごとに`v`の`u`、訪問したかどうかを確認します。 そうでない場合は、訪問済みとしてマークし、キューに入れます。 もし`v`ボーナスが含まれている場合、これを「自由な移動」とみなして、すべてのトークンがまだアクティブな状態で BFS が続行できるようにします。 実際には、エンキューするだけです`v`通常、BFS は拡張を自然に処理するためです。 
6. BFS が頂点 1 に到達せずに完了した場合は、NO を出力します。 

不変条件は、BFS が、ボーナスによってトリガーされたチェーンを含む、有効なトークンの移動によって到達可能なすべての頂点が最終的​​に訪問されることを保証することです。 BFS はグラフをレベルごとに探索するため、一連の移動が許可されていれば頂点 1 に到達します。 

## Python ソリューション```python
import sys
from collections import deque
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        p, b = map(int, input().split())
        tokens = list(map(int, input().split()))
        bonuses = set(map(int, input().split())) if b > 0 else set()
        
        adj = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v = map(int, input().split())
            adj[u].append(v)
            adj[v].append(u)
        
        if 1 in tokens:
            print("YES")
            continue
        
        visited = [False] * (n + 1)
        queue = deque(tokens)
        for tok in tokens:
            visited[tok] = True
        
        found = False
        while queue:
            u = queue.popleft()
            if u == 1:
                found = True
                break
            for v in adj[u]:
                if not visited[v]:
                    visited[v] = True
                    queue.append(v)
        
        print("YES" if found else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは、高速 I/O を使用して入力を読み取り、グラフを構築し、すべてのトークンから BFS を初期化します。 BFS 拡張は、ボーナスの効果を自然に処理します。BFS はキューに入れられたすべての頂点から継続するため、ボーナスを通じて到達可能な頂点はすべて訪問されます。 チェック中`if u == 1`BFS 全体を不必要に完了することなく、成功を即座に検出できるようにします。 

## 実用的な例

 ### 例 1 (サンプル 1 より)```
n=8, m=10
tokens=[7, 8]
bonuses=[2, 4, 5, 6]
finish=1
```| キュー | 訪問した頂点 | メモ |
 | --- | --- | --- |
 | [7,8] | 7,8 | BFS を開始する |
 | [8、隣人…] | 7、8、6、... | 8→6、7→近隣へ移動 |
 | ... | ... | ボーナス6→4などでBFSを継続 |
 | ... | ... | チェーン 8→6→4→2→1 を介して頂点 1 に到達 |

 出力は YES で、ボーナス連鎖により終了までのリーチが可能であることを示します。 

### 例 2 (ボーナスなし)```
n=5, m=4
tokens=[5]
bonuses=[]
finish=1
edges: 1-2-3-4-5
```| キュー | 訪問 |
 | --- | --- |
 | [5] | 5 |

 | [1] | 5,4,3,2,1 |

 ボーナスがなくてもトークンはパスを通過できるため、出力は YES になります。 1 つの移動のみが許可されるテストでは、ボーナスがないと頂点 1 に到達できません。これは、アルゴリズムが両方のシナリオを正しく処理していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n + m) | BFS は各頂点とエッジを最大 1 回訪問します。 |
