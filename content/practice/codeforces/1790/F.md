 ## 解決策
 ## 問題の理解

 1 つの頂点が黒で始まり、他のすべての頂点が最初は白であるツリーが与えられます。 その後、頂点が一定の順序に従って 1 つずつ徐々に黒くなっていきます。 新しい頂点がそれぞれ黒くなった後、単一の値、つまりツリー内の 2 つの黒い頂点間の最小距離を計算するように求められます。 

言い換えれば、ステップ i の後、黒いノードのセットが増加します。 このセット内のすべてのノード間のペアごとの最小距離が必要です。ここで、距離はツリー内の固有のパス上のエッジの数です。 

主な問題点は、黒いノードを挿入するたびにこの値を更新する必要があり、各ステップの後にすべてのペアごとの距離を単純に再計算すると時間がかかりすぎることです。 

制約によってこれが明確になります。 すべてのテスト ケースにわたる頂点の合計数は最大 2e5 で、最大 1e4 のテスト ケースが存在できます。 ステップごとに最初から距離を再計算したり、ステップごとに BFS を実行したりするソリューションでは、更新の密なシーケンスで二次的な動作が発生する危険があります。 

ローカルで考えると、微妙な落とし穴が現れます。 新しい黒いノードが追加されるとき、答えは最も近い既存の黒いノードまでの距離だけであると考える人もいるかもしれません。 この部分は正しいですが、見落としがちなのは、この最も近い距離は、毎回グローバルに再計算されるのではなく、すべての黒いノード間で動的に維持される必要があるということです。 

もう 1 つの潜在的な間違いは、新しく追加されたノードに関係する距離のみが重要であると想定していることです。 これは更新にほとんど当てはまりますが、グローバル最小値を正しく維持しない限り、それだけでは十分ではありません。 

## アプローチ

 直接的なアプローチは簡単です。黒ノードのセットを維持し、各挿入後にすべての黒ノードから BFS または DFS を実行してすべてのペアごとの距離を計算します。 これが機能するのは、ツリーの距離が明確に定義されており、ソースごとに線形時間で計算できるためです。 

あるステップで k 個のノードが黒である場合、各 BFS は O(n) であるため、このアプローチのコストはステップごとに O(k * n) になります。 すべてのステップにわたって、これは O(n^2) となり、2e5 ノードにとっては遅すぎます。 

もう少し慎重にブルート フォースを実行すると、新しく追加されたノードから BFS を実行し、既存のすべての黒いノードまでの距離を計算するだけで、この問題が改善されます。 これにより、ステップあたりのコストが O(n) に削減されますが、それでも合計は O(n^2) になります。 

重要な観察は、各挿入後の答えは、新しく追加されたノードに最も近い既存の黒いノードのみに依存するということです。 これは、ツリー上の「最も近いマークされたノードまでの距離」クエリをサポートする動的構造が必要であることを示唆しています。 

これは、ツリー上の古典的なマルチソース最短パス シナリオです。 すべての黒いノードを同時 BFS ソースとして扱う場合、すべての頂点の最も近い黒いノードまでの距離は、グローバル BFS 拡張によって維持できます。 ただし、時間の経過とともに発生するソース自体の間のペアごとの最小距離を維持する必要もあります。 

より強力な考え方は、ツリーを任意にルート化し、アクティブなノードを維持し、LCA を介してノード間の距離を効率的にクエリできるデータ構造を使用することです。 重要な洞察は、すべてのペアごとの距離は必要ではなく、最小の距離だけが必要であるということです。 これは、重心分解の DFS トラバーサルによって順序付けされたセットを使用して維持でき、同じ重心コンポーネント内のノード間の距離を増分的に追跡できます。 

重心分解は、ツリー距離クエリをサブツリー距離の対数組み合わせに変換するため、自然なツールになります。 各ノードはすべての重心の祖先との距離を維持し、新しい黒いノードが追加されると、これらの重心パスを介して以前に挿入されたノードとのみ比較されます。 これにより、各ノードは O(log n) セントロイド レベルに参加するため、各挿入が O(log n) に減ります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ステップごとのブルート フォース BFS | O(n^2) | O(n) | 遅すぎる |
 | 重心分解 | O(n log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーの重心分解を構築し、すべてのノードについて、その重心の祖先とそれらまでの距離を事前計算します。 

最初の黒ノードのみで初期化されたグローバルな答えを維持します。これはまだペアが存在しないため、事実上無限です。 

また、アクティブな黒いノードによって寄与される距離を保存する、重心ノードごとのマルチセットのような構造も維持します。 

ノードをアクティブ化するたびに、セントロイド パスを使用してグローバル最小値を更新します。 

1. ツリーの重心分解を構築します。 各ノードは、その重心の祖先とそれらの祖先までの距離を表すペアのリストを保存します。 この構造により、共有重心祖先を介してツリーの距離を表現できるようになります。 
2. 現在の答えとして大きな値を初期化します。 最初の黒いノードをアクティブとしてマークしますが、ペアごとの距離はまだ計算しません。 
3. 新しくアクティブ化されたノードごとに、その重心祖先リストを調べます。 ノードからの距離 d にある各重心祖先 c について、同じ重心を通じて貢献した以前にアクティブ化されたノードを使用して、候補の最小距離を計算しようとします。 
4. 各重心祖先 c で、c を通過したアクティブなノードからの最小距離を維持します。 新しいノード u を処理するとき、候補値を d(u, c) + best[c] として計算します。best[c] は、以前のアクティブ ノードから c までの保存された最小距離です。 
5. すべての重心祖先をクエリした後、最適な候補でグローバル回答を更新します。 次に、best[c] を d(u, c) で更新することで、新しいノードをすべての重心祖先構造に挿入します。 

機能する理由: 2 つのノード間のすべてのパスには、それらのパスが交わる場所で固有の最も高い重心分解レベルがあります。 その重心では、両方のノードから重心までの距離の合計がツリーの距離に等しくなります。 各重心での最良の寄与を追跡することにより、共有重心祖先を通じてすべてのペアが正確に 1 回考慮されることが保証され、ペアごとの最小距離が正しく取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class CentroidDecomposition:
    def __init__(self, n, g):
        self.n = n
        self.g = g
        self.dead = [False] * n
        self.sub = [0] * n
        self.parent = [-1] * n
        self.level = [0] * n
        self.dist = [[] for _ in range(n)]

        self.best = [10**18] * n

        self.build(0, -1, 0)

    def dfs_size(self, v, p):
        self.sub[v] = 1
        for to in self.g[v]:
            if to != p and not self.dead[to]:
                self.dfs_size(to, v)
                self.sub[v] += self.sub[to]

    def find_centroid(self, v, p, n):
        for to in self.g[v]:
            if to != p and not self.dead[to]:
                if self.sub[to] > n // 2:
                    return self.find_centroid(to, v, n)
        return v

    def dfs_dist(self, v, p, c, d):
        self.dist[v].append((c, d))
        for to in self.g[v]:
            if to != p and not self.dead[to]:
                self.dfs_dist(to, v, c, d + 1)

    def build(self, v, p, depth):
        self.dfs_size(v, -1)
        c = self.find_centroid(v, -1, self.sub[v])
        self.parent[c] = p
        self.level[c] = depth
        self.dead[c] = True

        self.dfs_dist(c, -1, c, 0)

        for to in self.g[c]:
            if not self.dead[to]:
                self.build(to, c, depth + 1)

    def add(self, v):
        res = 10**18
        for c, d in self.dist[v]:
            res = min(res, self.best[c] + d)
        for c, d in self.dist[v]:
            self.best[c] = min(self.best[c], d)
        return res

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, c0 = map(int, input().split())
        c0 -= 1
        order = list(map(int, input().split()))
        order = [x - 1 for x in order]

        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)

        cd = CentroidDecomposition(n, g)

        active = [False] * n
        active[c0] = True
        for v in order:
            active[v] = True

        best = 10**18
        res = []
        cd.best[c0] = 0
        for v in order:
            cand = cd.add(v)
            best = min(best, cand)
            res.append(best)

        out.append(" ".join(map(str, res)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```重心分解では、重心チェーンまでのすべてのノードの距離が前処理されます。 の`add`関数は唯一の動的部分です。 各ノードについて、参加しているすべての重心レベルをチェックし、以前に保存された最小値を使用して最適なペアの形成を試み、その後、それらの最小値を更新します。 

実装の微妙な点は、すべての距離を事前に計算して重心構造を初期化する必要があることです。 そうしないと、動的 BFS が遅すぎます。 また、`best[c]`セントロイド c を通過したすべてのアクティブなノードの圧縮された概要として機能します。 

## 実用的な例

 ノードが 1 - 2 - 3 - 4 のように一列に配置されている小さなツリーを考えてみましょう。2 が最初は黒で、1、3、4 の順序でノードをアクティブ化するとします。 

前処理後、重心パスは中点を通る距離をエンコードします。 

段階的なアクティベーションの場合:

 | ステップ | 追加されたノード | 最適な距離候補 | グローバルな答え |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 (から 2) | 1 |
 | 2 | 3 | 1 (から 2) | 1 |
 | 3 | 4 | 2 (2 または 3 チェーン効果に) | 1 |

 これは、複数のノードがアクティブであっても、最小ペアは最も近いペアに対してローカルのままであり、セントロイド集約が共有祖先を通じてそれを捕捉することを示しています。 

ここで、中心が 1 で葉が 2、3、4、5 にあり、最初の黒いノードが 1 である星について考えてみましょう。 

| ステップ | 追加されたノード | 候補距離 | グローバルな答え |
 | --- | --- | --- | --- |
 | 1 | 2 | 1 | 1 |
 | 2 | 3 | 1 | 1 |
 | 3 | 4 | 1 | 1 |
 | 4 | 5 | 1 | 1 |

 新しいノードはそれぞれ重心ルートを介して接続するため、すべてのペアは中心からの距離が 2 ですが、重心が直接更新されるため、最小値は 1 のままです。 

これらのトレースは、重心レベルの凝集がパス状構造とスター状構造の両方を正しく捕捉していることを確認します。

 ## 特殊なケース

 病理学的ケースは完全に線形のツリーです。 重心分解では深さが対数的に減少するため、各更新は依然として O(log n) 個の先祖のみに影響し、正確さと速度が保証されます。 

別のケースは、最初の黒いノードが極端な葉にある場合です。 最初の数回のアップデートでは、安定するまでに距離が伸びているように見える場合があります。 すべてのペアは最も高い共有重心で評価されるため、重心構造は正しい最小値を取得します。 

最後のケースは、すべてのノードが最終的に黒になるが、最小距離が早期に達成される場合です。 アルゴリズムはグローバル最小値を正しく保存します。`best[c]`最小値のみを蓄積し、以前のより緊密なペアを破棄することはありません。
