 ## 解決策
 ## 問題の理解

 それぞれ 1 から n までのラベルが付けられた一連のプロジェクトと、「プロジェクト b を開始する前にプロジェクト a を終了する必要がある」という形式の依存関係ルールのリストが与えられます。 これらのルールはプロジェクト間の有向関係を定義し、タスクはすべての依存関係を尊重した順序ですべてのプロジェクトを完了できるかどうかを決定することです。 このような順序が存在する場合は、すべてのプロジェクトの有効な順序を 1 つ出力する必要があります。 複数の有効な順序が存在する場合は、辞書順に最小のものを選択する必要があります。 

グラフの観点から見ると、各プロジェクトはノードであり、各依存関係は a から b への有向エッジです。 したがって、出力は有向グラフの位相順序付けであり、すべての有効な位相順序の中から辞書編集順で最小のものを選択する必要があるという追加の制約があります。 

制約は n = 100000 および m = 200000 までです。次の有効なプロジェクトを見つけるためにすべてのノードを繰り返しスキャンするなど、n で二次的な解決策は機能しません。 本質的に線形または線形に近い時間に制限されます。つまり、O(n log n) または O(n + m) がターゲット範囲です。 これはすでに、組み合わせ検索ではなくグラフ走査方法を強く示唆しています。 

ここではいくつかの特殊なケースが重要です。 まず、サイクルがある場合、たとえば 1 は 2 に依存し、2 は 3 に依存し、3 は 1 に依存します。その場合、順序付けは不可能であり、IMPOSSIBLE を出力する必要があります。 第 2 に、複数の有効な次のプロジェクトが存在する場合、辞書編集上の最小要件により、各ステップで利用可能な最小のインデックス付きプロジェクトを常に優先する必要があります。そうでない場合、貪欲ではあるが順序付けされていないトポロジカル ソートにより、有効ではあるが最小ではないシーケンスが生成されます。 第三に、依存関係がまったくない場合、答えは単純に 1 2 3 ... n でなければなりません。 

## アプローチ

 素朴なアプローチは、すべてのプロジェクトを繰り返しスキャンし、前提条件が満たされているプロジェクトを選択することです。 各ステップで、すべてのエッジをチェックするか、度数を最初から再計算して、現在どのノードが利用可能であるかを判断します。 依存関係を常に尊重しているため、これは概念的には機能しますが、単純な実装では各選択ステップに O(n + m) のコストがかかる可能性があります。 これを n 回行うため、最悪のケースは O(n(n + m)) となり、入力制限に対して大きすぎます。 

重要な観察は、依存関係の満足度を最初から再計算する必要がないということです。 実際に必要なのは、現在利用可能なすべてのプロジェクト、つまり次数が 0 のプロジェクトの動的なセットです。 プロジェクトが取得されると、そのプロジェクトから発信される隣接プロジェクトのみが影響を受けます。 これは当然、入次数を維持し、段階的に更新することを示唆しています。 

辞書編集的に最小の順序を適用するには、各ステップで利用可能な最小のプロジェクトを常に選択する必要があります。 これにより、問題は、優先メカニズムを備えた標準的なトポロジカル ソート タスクに変わります。 任意のキューの代わりに、最小ヒープを使用して、常に次数 0 の最小のインデックス付きノードを抽出します。 

ヒープからノードを削除するたびに、そのプロジェクトの完了をシミュレートし、その近傍の次数を減分します。 次数が 0 になる近傍はヒープに追加されます。 これにより、利用可能なノードの正しいフロンティアが常に維持されることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n(n + m)) | O(n + m) | 遅すぎる |
 | 最適 (最小ヒープ トポロジカル ソート) | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題を有向グラフに変換し、度数を追跡します。

1. グラフの隣接リストを作成し、すべてのノードの次数を計算します。 これにより、各プロジェクトにまだ必要な前提条件がいくつあるかがわかります。 
2. 最小ヒープを初期化し、次数が 0 であるすべてのノードをプッシュします。 何も依存しないのですぐに始められるプロジェクトです。 
3. ヒープから最小のノードを繰り返し抽出します。 この選択により、現在有効なすべての候補のすべてのステップで辞書編集上の最小性が保証されます。 
4. この位置でプロジェクトを完了することにコミットしているため、抽出したノードを応答シーケンスに追加します。 
5. このノードのすべての隣接ノードについて、その度数を減分します。 これは、それらの依存プロジェクトの 1 つの前提条件を満たすことを表します。 
6. いずれかの近傍の次数が 0 になった場合は、実行可能になったため、それをヒープにプッシュします。 
7. ヒープが空になるまで続行します。 その時点で、すべてのノードが処理されるか、サイクルが存在します。 
8. 最後に、結果の順序付けに n 個のノードがすべて含まれているかどうかを確認します。 そうでない場合は、一部のノードが依存関係から解放されず、サイクルが存在することを意味するため、IMPOSSIBLE と出力されます。 

重要な詳細は、ヒープが常に現在有効なノードのセットを正確に反映しており、常にそれらの中から最小のものを選択するということです。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは、すでに出力されているすべてのノードが残りのグラフに関して次数 0 を持ち、現在ヒープ内にあるすべてのノードがまさに前提条件がすべて満たされているノードであるという不変条件を維持します。 エッジは次数更新によって暗黙的にのみ削除されるため、すべての依存関係がシーケンスの前半に現れる前にノードが順序付けに挿入されることはありません。 ヒープの順序付けにより、すべての有効な次の選択肢の中から最小のインデックスが選択されることが保証されるため、構築されたシーケンスから以前に分岐する、辞書編集的により小さい有効なシーケンスが存在することはできません。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    adj = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)

    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        indeg[b] += 1

    heap = []
    for i in range(1, n + 1):
        if indeg[i] == 0:
            heapq.heappush(heap, i)

    order = []

    while heap:
        u = heapq.heappop(heap)
        order.append(u)

        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                heapq.heappush(heap, v)

    if len(order) != n:
        print("IMPOSSIBLE")
    else:
        print(*order)

if __name__ == "__main__":
    solve()
```実装は、隣接リストを構築し、すべての前提条件となる制約の構造表現である度数を計算することから始まります。 次に、ヒープにはすべてのゼロ度数ノードがシードされ、開始プロジェクトの最初の有効なセットが形成されます。 

メイン ループは、使用可能な最小のノードを繰り返しポップします。 キューの代わりにヒープを使用することで、辞書編集上の最小限性が強制されます。 これを通常のキューに置き換えても、有効なトポロジー順序が生成されますが、必ずしも最小の順序になるとは限りません。 

ノードを削除するたびに、次数を減分することによって、その効果が出力エッジを通じて伝播されます。 近傍は、その入次数がちょうど 0 になった場合にのみプッシュされ、すべての前提条件が満たされたときに正確に適格になることが保証されます。 

最終チェックでは、構築された注文サイズを n と比較します。 それらが異なる場合は、少なくとも 1 つのノードが、次数削減を通じて到達できなかったことになります。これは、サイクルが存在する場合にのみ発生します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) | 各ノードはヒープに出入りするのは最大 1 回であり、各エッジで 1 回の度数更新が発生します。 
| スペース | O(n + m) | 隣接リストと次数配列とヒープ |

 m が最大 200000 であり、各ヒープ操作が n の対数であるため、複雑さは制限内に問題なく収まり、合計操作は 2 秒の制約の下で管理可能になります。 

## テストケース```python
import sys, io
import heapq

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    def solve():
        n, m = map(int, input().split())
        adj = [[] for _ in range(n + 1)]
        indeg = [0] * (n + 1)

        for _ in range(m):
            a, b = map(int, input().split())
            adj[a].append(b)
            indeg[b] += 1

        heap = []
        for i in range(1, n + 1):
            if indeg[i] == 0:
                heapq.heappush(heap, i)

        order = []
        while heap:
            u = heapq.heappop(heap)
            order.append(u)
            for v in adj[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    heapq.heappush(heap, v)

        if len(order) != n:
            return "IMPOSSIBLE"
        return " ".join(map(str, order))

    return solve()

 ## 特殊なケース

 重要なエッジ ケースは、複数のノードの開始時に次数が 0 である場合です。 たとえば、5 ノード グラフのエッジ 2 → 3 および 4 → 5 では、最初は 1、2、および 4 の両方が使用可能である可能性があります。 アルゴリズムはそれらをすべてヒープに配置し、常に最小のものを選択して、決定的な辞書編集動作を保証します。 

もう 1 つのエッジ ケースは、1 → 2 → 3 → 1 などの完全に循環するグラフです。ここでは、どのノードも次数 0 に到達しないため、ヒープは空で開始されるか、初期化直後に空になります。 出力リストは不完全なままですが、アルゴリズムは正しく IMPOSSIBLE を出力します。 

最後のエッジ ケースは、コンポーネントが切り離されたグラフです。 各コンポーネントは、次数伝播を通じて個別に処理され、ヒープは、コンポーネント間で使用可能な最小のノードを常に選択することによって、コンポーネントを単一のグローバルな順序付けに自然にマージします。
