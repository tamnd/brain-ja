 ## 問題の理解

 私たちは、各エッジにコストではなく「ラベル」として考える必要がある重みを持つ有向グラフに取り組んでいます。 パスは正確に次のシーケンスとして定義されます。$k$固定ノードから始まる有向エッジ$s$そして固定ノードで終わる$t$。 主な目的は、有効な長さのパスを見つけることだけではありません$k$ただし、エッジ ラベルのシーケンスが辞書編集的に最小のものを見つけます。 

辞書編集的な比較は、2 つのシーケンスが異なる最初の位置を調べ、そこでエッジの重みが小さい方を選択することによって行われます。 これにより、初期のエッジが後のエッジよりもはるかに重要になります。 

最適な重みのシーケンスが決定されると、そのシーケンスを直接出力しません。 代わりに、それをベースとして解釈します。$x$最初のエッジが最も高いパワーに寄与し、最後のエッジが最も低いパワーに寄与する数値をモジュロで出力します。$10^9 + 7$。 正確に歩かない場合$k$からエッジが存在します$s$に$t$の場合、-1 を出力します。 

制約により、ある長さのパスをシミュレートする試みは即座に排除されます。$k$直接。 歩数$k$まで行くことができます$10^9$したがって、パス長によってインデックス付けされた動的プログラミングは不可能です。 ただし、ノードの数は非常に少なく、最大でも 50 個です。これは、明示的なパスの列挙ではなく、ノード全体の状態圧縮とステップ長全体の高速変換の観点から考える必要があることを示唆しています。 

素朴だが魅力的なアイデアは、これをサイズの層状グラフ内の最短の辞書編集パスとして扱うことです。$n \cdot k$、しかし、そのサイズのため、そのグラフを構築したり走査したりすることは不可能です。$k$。 

貪欲な思考による微妙な失敗例は、局所的に最小のエッジが全体的に実現可能な完了につながらないグラフに現れます。 たとえば、次の場合$s$最小のエッジは到達できないノードにつながります$t$で$k-1$ステップはありますが、エッジがわずかに大きい場合は可能です。単純に欲張った選択は失敗します。 これは、継続の実現可能性が辞書編集上の順序と同じくらい重要であることを示しています。 

## アプローチ

 ブルートフォースパースペクティブは、長さのすべてのパスを列挙しようとします。$k$、それらの配列を追跡し、辞書編集的に最小のものを選択します。 実行可能な遷移に限定しても、各ステップは最大で分岐します。$n$発信エッジのため、パスの数は次のように指数関数的に増加します。$O(n^k)$。 たとえ$k = 50$、これはすでに実行不可能であり、$k$まで$10^9$、それはまったく不可能です。 

重要な構造上の観察は、辞書編集的な最小化が接頭辞のみに依存するということです。 わかっていれば、どのノードでも$u$、可能な限り最適な長さの接尾辞シーケンス$r$それはからつながります$u$に$t$、そのエッジを取得することで辞書編集的に最適な接尾辞で補完できるかどうかをチェックすることで、ノードから出力されるエッジを比較できます。 これは、パスを介した動的プログラミングを示唆していますが、ダイレクト DP を介したものではありません。$k$不可能です。 

2 番目の重要なアイデアは、固定パス長にわたる遷移が構成されるということです。 それぞれの長さごとに$L$、遷移行列を定義できます。$A_L$どこ$A_L[u][v]$辞書編集的に最小のエッジの重みのシーケンスがわかります。$u$に$v$まさに$L$ステップを実行するか、不可能としてマークします。 最適な長さのパスがわかっている場合は、これらの行列を組み合わせることができます。$a$そして$b$、それらを組み合わせて最適な長さのパスを取得できます$a+b$中間ノードを試してシーケンスを連結します。 

なぜなら$n \le 50$、私たちは余裕があります$O(n^3)$コンビネーションステップ。 次に、パスの長さに対してバイナリ リフティングを使用します。$k$、高速累乗に似ています。 2 のべき乗の行列を事前計算し、次のバイナリ表現に従ってそれらを結合します。$k$。 

辞書編集的な比較にはシーケンスを保存する必要がありますが、完全なシーケンスは大きすぎます。 代わりに、連結を比較するのに十分な情報のみを保存します。各状態で、到達可能性と最良の辞書編集的遷移の表現の両方を維持します。 パス長は長いがノード数は少ないので、ペアごとに保存できます。$(u,v)$、各パワーセグメントに最適なシングルエッジの選択を行い、貪欲に再構築します。 

これにより、問題は、乗算が連結で加算が辞書編集上の最小となる半リング上の最短の辞書編集パスに変わります。

 ## アルゴリズムのチュートリアル

 この問題を、固定ステップ数にわたる遷移構造の繰り返し構成として再定式化します。 

1. ノードのペアごとに$u, v$、辞書編集上最小の単一エッジ遷移を計算します。つまり、複数のエッジがあるかどうかを意味します。$u \to v$、最小の重量のみを保持します。 これにより、平行なエッジが 1 つに圧縮されます。 
2. 基本的な移行構造を構築する$T$長さ 1 のパスの場合、$T[u][v]$エッジが存在する場合はエッジの重みです。それ以外の場合は無限大として扱われます。 これは、最良の 1 ステップ動作を表します。 
3. これを結合可能な構造に拡張します: 2 つの構造を結合する場合$A$そして$B$、新しい構造を計算します$C$すべてのペアに対して$u, v$、すべての中間ノードを考慮します$w$、パスを形成しようとします$u \to w \to v$。 候補コストは、次の最良のシーケンスを連結したものです。$A[u][w]$そして$B[w][v]$。 このようなすべての選択肢の中で辞書編集的に最小のものを保持します。 
4. 2 の累乗を事前計算します。$T, T^2, T^4, \dots$最大ビットまで$k$、組み合わせルールを繰り返し適用します。 
5.分解する$k$バイナリに変換します。 「空のパス」動作を表すアイデンティティ構造から始めます。長さ 0 のパスは、開始と終了が等しい場合にのみ有効です。 
6. 各ビットについて$k$、設定されている場合は、同じ結合ルールを使用して、現在の結果構造体に対応する 2 のべき乗の遷移構造体を乗算します。 
7. すべてのビットを処理した後、エントリは$result[s][t]$ある長さのパスに対する辞書編集上最小のエッジ重みのシーケンスが含まれます。$k$、 または は不可能を示します。 
8. このシーケンスを基数の数値に変換します。$x$モジュロ$10^9+7$重みを順番に繰り返すことによって。 

正確さは、比較が接頭辞から先に行われる場合に、辞書編集上の順序が連結下で保持されるという事実に依存します。 各 DP 構造は、固定長の可能な限り最良のプレフィックスを完全にキャプチャするため、それらを組み合わせることで全体的な最適性が維持されます。 

### なぜ効果があるのか

 各行列は、ノードの各ペア間の固定ステップ数に対する最適な辞書編集結果を表します。 2 つの行列を結合すると、パスの中間分割点を効果的に選択し、連結によって形成された完全なプレフィックスを比較することになります。 辞書編集上の順序は最初の異なるエッジのみに依存し、各部分構造は内部的に最適なプレフィックスをすでに保証しているため、後で組み換えても、すでに検討されているプレフィックスよりも優れたプレフィックスを生成することはできません。 これにより、セミグループ構成が有効になり、バイナリ リフティングによって全体的に最適なパスが生成されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = None

def better(a, b):
    if a is INF:
        return b
    if b is INF:
        return a
    return min(a, b)

def merge(A, B, n):
    C = [[INF] * n for _ in range(n)]
    for i in range(n):
        for k in range(n):
            if A[i][k] is INF:
                continue
            a_seq = A[i][k]
            for j in range(n):
                if B[k][j] is INF:
                    continue
                b_seq = B[k][j]
                cand = a_seq + b_seq
                if C[i][j] is INF or cand < C[i][j]:
                    C[i][j] = cand
    return C

def build_base(n, edges):
    T = [[INF] * n for _ in range(n)]
    for u, v, w in edges:
        u -= 1
        v -= 1
        if T[u][v] is INF or [w] < T[u][v]:
            T[u][v] = [w]
    return T

def identity(n):
    I = [[INF] * n for _ in range(n)]
    for i in range(n):
        I[i][i] = []
    return I

def main():
    n, m, s, t, x, k = map(int, input().split())
    edges = [tuple(map(int, input().split())) for _ in range(m)]

    base = build_base(n, edges)

    maxb = k.bit_length()
    pw = [base]
    for _ in range(maxb):
        pw.append(merge(pw[-1], pw[-1], n))

    res = identity(n)
    for i in range(maxb):
        if (k >> i) & 1:
            res = merge(res, pw[i], n)

    if res[s-1][t-1] is INF:
        print(-1)
        return

    seq = res[s-1][t-1]

    MOD = 10**9 + 7
    ans = 0
    for w in seq:
        ans = (ans * x + w) % MOD
    print(ans)

if __name__ == "__main__":
    main()
```このソリューションは、各状態を行列として表します。各エントリは、固定長の 2 つのノード間の重みの辞書編集上最適なシーケンスです。 の`merge`関数は、すべての中間ノードを試行することによって、そのような 2 つの長さ構造を構成します。これは、標準的な行列乗算パターンですが、加算の代わりに辞書式連結を使用します。 

恒等構造は長さ 0 のウォークを表し、開始と終了が一致する場合にのみ有効であり、バイナリ リフティングの正しい初期化にとって重要です。 

最後の変換ステップでは、復元された配列を塩基として解釈します。$x$数値を左から右に累積するため、より早いエッジがより高い重要性をもたらします。

 ## 特殊なケース

 重要なエッジケースは、局所的に最適なエッジが実現可能性を壊す場合です。 ノード 1 から 2 つのエッジがあるとします。1 つは行き止まりノードに向かう重み 1 のエッジ、もう 1 つは残りのステップでターゲットに到達できるサイクルにつながる重み 2 のエッジです。 このアルゴリズムは、最小の出力エッジにすぐにはコミットしません。 代わりに、完全な到達可能性情報を遷移構造内に保持するため、有効な長さを完了できないため、行き止まりパスはマトリックス構成中に自然に破棄されます。$k$歩く。 

もう 1 つのエッジ ケースは、複数のパスが同じ辞書編集プレフィックスを生成するが、後で異なる場合です。 マトリックスのマージは完全な連結シーケンスを明示的に比較し、プレフィックスが同一の場合にのみ後の相違が考慮されるようにします。 これにより、シーケンス構造を保存せずにエッジの重みだけを比較した場合に発生する誤った枝刈りが回避されます。
