 ## 解決策
 ## 問題の理解

 長さの非表示の整数配列が与えられます。$n$ここで、すべての要素は 1 から 100 の間です。配列を直接見ることはできません。 代わりに、その配列内の隣接する要素のすべてのペアによって形成される積のマルチセットが与えられます。 

具体的には、未知の配列が$A = [a_1, a_2, \dots, a_n]$、その後、順序付けされていないコレクションが与えられます$$\{a_1 a_2, a_2 a_3, \dots, a_{n-1} a_n\}.$$タスクは、有効な配列を再構築することです。$A$これにより、まさにこの隣接する積のマルチセットが生成されるか、そのような配列が存在しないと判断される可能性があります。 

難点は商品の順番が分からなくなることです。 どの積がどの位置に属するかは知らされないため、隣接構造は純粋に因数分解制約から推測する必要があります。 

制約$n \le 18$が中心的なヒントです。 全範囲のすべての配列に対する指数関数的な検索を除外します。$[1, 100]^n$これは天文学的に大きくなりますが、エッジの順列または割り当てに対する枝刈りによるバックトラックを快適に行うことができます。 各積は最大でも 10000 であるため、因子のペアが制限され、分岐がさらに制限されます。 

素朴な試みはすべてを並べ替えようとするかもしれません$n-1$積を取得し、順番にエッジとして割り当ててから、配列を再構築して整合性をチェックします。 それはすでに$(n-1)!$可能性は、たとえ$n = 18$。 もう 1 つの素朴なアイデアは、考えられるすべての開始値を試してみることです。$a_1$、その後、各積を貪欲に因数分解しますが、早い段階で間違った因子を選択しても後で有効な補完が残る可能性があり、一意の継続を強制するものがないため、貪欲に因数分解することは失敗します。 

製品に多数の因子ペアがある場合、微妙な失敗例が発生します。 たとえば、積が 36 の場合、その積は (1, 36)、(2, 18)、(3, 12)、(4, 9)、(6, 6) から得られる可能性があります。 1 つのエッジを間違って選択しても、残りのエッジを完了できる可能性はありますが、最終的なマルチセットの使用が一貫性を欠くことになります。 

## アプローチ

 主な難点は、隣接構造が隠蔽されていることですが、有効な配列はすべて、各位置が正確に 2 つのエッジ (端点を除く) に寄与するパスのような構造を誘発することです。 これは、未知の頂点間にエッジを配置するという観点から考えることを示唆しています。各エッジは積によってラベル付けされ、各頂点の値はすべての入射エッジと一致する必要があります。 

強引な解釈では、次のすべての順列を試してみることになります。$n-1$積と、チェーンに沿って一貫して因子ペアを割り当てるためのあらゆる方法。 順列ごとに開始値を選択します$a_1$、そして推測します$a_2 = b_{\pi(1)} / a_1$、その後は決定的に続行します。 問題は、順列空間と因子の選択が爆発的に増加することです。 因子分岐を無視しても、$(n-1)!$注文はすでに不可能です。 

重要な観察は、単一のエッジを修正し、その 2 つのエンドポイント値を決定すると、配列の残りの部分はほぼ強制されるということです。 私たちが知っていれば$a_i$、残りの未使用製品については$b$、次のように書けるなら$a_i \cdot x$、 それから$x$が次の値の候補になります。 これにより、問題は長さのパスを構築することに変わります$n$ここで、各ステップは 1 つの未使用の製品を消費します。 

なぜなら$n \le 18$、部分的な構造に対して深さ優先検索を行うことができます。 状態は小さく、配列内の現在位置、現在値、および残りの積のマルチセットです。 各ステップで、現在の値で割り切れるすべての未使用の積を試し、シーケンスを前方または後方に拡張します。 各製品には最大 100 までの数の約数しかないため、分岐係数は制限されています。 

この構造は本質的に、値に関する制約付きのパス構築問題であり、エッジは 1 回だけ再利用可能であり、各ステップは利用可能な製品と一致する必要があります。 方向の対称性（次のように解釈できます）$a_i a_{i+1}$どちらの方向でも) は、各製品を双方向として扱うことで自然に処理されます。

 ## アルゴリズムのチュートリアル

 私たちは問題を次のシーケンスを構築するものとして扱います。$n$正確に摂取しながら数値を把握する$n-1$製品。 

1. 重複が重要であり、各出現を正確に 1 回消費する必要があるため、すべての製品をマルチセット構造 (頻度マップ) に保存します。 これは、同一の製品が入力では区別できないが、それでもエッジが分離しているという事実をモデル化します。 
2. 私たちはあらゆる製品を潜在的な出発点として試します。 選んだ商品について$b = x \cdot y$、両方の方向を試します。$a_1 = x, a_2 = y$そして$a_1 = y, a_2 = x$。 これは、隣接方向が不明なため必要です。 
3. 試行ごとに、左から右に配列を構築する深さ優先検索を実行します。 いつでも現在の値が得られます$a_i$そして部分的なシーケンス。 
4. から$a_i$まで拡張しようとします$a_{i+1}$残りのすべての製品を反復処理します。 製品の場合$p$満足する$p \mod a_i = 0$、 それから$a_{i+1} = p / a_i$は次の値の候補です。 
5. その製品を消費し (頻度を減らし)、新しい値を追加し、再帰します。 再帰が失敗した場合は、製品を復元し、追加された値を削除することでバックトラックします。 
6. を配置すると、検索は正常に停止します。$n$数値とすべての積は 1 回だけ使用されます。 
7. 開始した製品と方向性が成功につながった場合は、構築された配列を出力します。 

### なぜ効果があるのか

 構築された配列の任意のプレフィックスにおいて、残りの未使用の積は、まさに隣接するペアにまだ割り当てられていない積です。 DFS は、選択されたすべてのステップが最終的な隣接マルチセット内の実際のエッジに対応するという不変条件を維持します。 すべての拡張は厳密に 1 つの積を消費し、シーケンスの長さを 1 つ増やすため、無効な補完が誤って完全な制約を満たすことはありません。 有効な元の配列は、その最初のエッジから始まる少なくとも 1 つの有効な DFS パスに対応するため、検索スペースが完成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    b = list(map(int, input().split()))
    
    from collections import Counter
    
    def backtrack(path, cnt):
        if len(path) == n:
            return True
        
        last = path[-1]
        
        for p in list(cnt.keys()):
            if cnt[p] == 0:
                continue
            if p % last != 0:
                continue
            nxt = p // last
            if nxt < 1 or nxt > 100:
                continue
            
            cnt[p] -= 1
            path.append(nxt)
            
            if backtrack(path, cnt):
                return True
            
            path.pop()
            cnt[p] += 1
        
        return False
    
    cnt0 = Counter(b)
    
    for i in range(n - 1):
        for a, c in [(b[i], True)]:
            # try factor pairs
            for x in range(1, 101):
                if a % x == 0:
                    y = a // x
                    if 1 <= y <= 100:
                        cnt = cnt0.copy()
                        cnt[a] -= 1
                        path = [x, y]
                        if backtrack(path, cnt):
                            print("Yes")
                            print(*path)
                            return
                        cnt[a] += 1
    
    print("No")

if __name__ == "__main__":
    solve()
```この解決策は、入力をエッジのマルチセットとして扱うことから始まります。 各候補開始エッジは、許容値範囲内のすべての有効な因子ペアに拡張されます。 その後、DFS は、現在の値が未使用の積をきれいに分割し、有効な次の値を生成する遷移のみを許可することで一貫性を確保します。 

微妙な点は、残りの製品の注文をまったく想定していないことです。 代わりに、各ステップで常に未使用の候補をすべて検索します。これは許容されます。$n$は小さく、制約が伝播すると分岐はすぐに崩壊します。 

## 実用的な例

 ### 例 1

 有効な再構成が存在する小さなケースを考えてみましょう。 

入力製品:$[8, 12, 6]$、$n = 4$製品 12 から始めてみます。 

| ステップ | パス | 残りの製品 | アクション |
 | --- | --- | --- | --- |
 | 1 | [3、4] | [8、6] | ピック 12 = 3×4 |
 | 2 | [3、4、2] | [8] | 8 = 4×2 | を使用します。 
| 3 | [3、4、2、4] | [] | 6 = 2×4 を使用します。 

各ステップで、現在のエンドポイントに一致する製品を選択します。 残りのすべての製品が進化するチェーンと一致しているため、構築は成功します。 

このトレースは、最初のエッジが固定されると、配列の残りの部分が強制されることを示しており、制約の強い伝播効果を示しています。 

### 例 2

 入力製品:$[36, 6, 6]$、$n = 4$36 = 6×6 から始めてみましょう。 

| ステップ | パス | 残りの製品 | アクション |
 | --- | --- | --- | --- |
 | 1 | [6、6] | [6、6] | 36を選ぶ |
 | 2 | [6、6、1] | [6] | 6 = 6×1 | を使用します。 
| 3 | 失敗 | 後戻り | 有効な継続がありません |

 これは、因子の選択があいまいであることを示しています。 最初の選択が有効であっても、次の値として 1 を選択すると、それ以上の拡張がブロックされます。 DFS は代替因数分解を確実に探索し、時期尚早なコミットメントを防ぎます。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての積が等しい場合です。たとえば、36 のコピーが多数ある場合です。DFS は、単一の分割に固定するのではなく、36 の複数の因数分解を正しく試行する必要があります。 マルチセット追跡により、各コピーが正確に 1 回消費されることが保証され、特定のチェーンが失敗した場合は、バックトラッキングにより代替の分解が探索されます。 

もう 1 つのエッジ ケースは、有効な配列は存在するが、早期に非自明な因子の選択が必要な場合に発生します。 たとえば、36 に対して 6×6 を選択すると進行が妨げられる可能性がありますが、4×9 は機能します。 アルゴリズムは、各候補製品のすべての因子ペアを再試行し、失敗した場合は状態を完全に元に戻すことでこれを処理し、探索の完全性を保証します。
