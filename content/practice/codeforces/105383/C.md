 ## 解決策
 ## 問題の理解

 私たちはカードのコレクションを渡され、各カードには 2 つの数字が書かれています。1 つは表面に、もう 1 つは裏面に書かれています。 両面は独立して 1 から n までの数字の順列を形成するため、すべての数字はすべてのカードの表面に 1 回だけ表示され、すべてのカードの裏面に 1 回だけ表示されます。 

カードの順序を任意に変更することはできますが、各カードをそのままの状態で保存する必要があります。つまり、カードの表と裏の番号は常にペアのままである必要があります。 並べ替え後、2 つの新しい順列が得られます。選択した順序の前のシーケンスと、同じ順序の前のシーケンスです。 

目的は、前方の順列の反転数が後方の順列の反転数と等しくなるようなカードの順序が存在するかどうかを判断することです。 存在する場合は、有効な順序を 1 つ出力する必要があります。 

反転は要素の相対的な順序にのみ依存するため、問題は実際には、共有されたインデックスの並べ替えの下で 2 つの順列を同期することです。 

5×10^5 までの制約 n は、置換ごとの二次推論や、スワップ後の反転数のシミュレーションを即座に除外します。 O(n log^2 n) の構造であっても、反転数を計算するだけではなく、インデックスのグローバルな順列の下でそれらを照合しようとしているため、注意深い構造が必要です。 

重要な微妙な点は、カードの順序を変更すると、位置に関しては両方の順列に同じように影響しますが、反転は各配列内の相対的な順序に依存することです。 これは、1 つのアレイを個別に「調整」しているわけではないことを意味します。 構造変化は両方の反転回数にさまざまな形で影響します。 

単純な失敗例は、両方の順列が同一であるにもかかわらず、逆の配置により不一致が強制される場合に発生します。 たとえば、a = [1, 2] および b = [2, 1] の場合、どの順序でも反転カウントは異なります。一方は常に 0、もう一方は常に 1 です。これは、マルチセットの等価性が無関係であることを示しています。 構造が重要です。 

## アプローチ

 ブルート フォース アプローチでは、カードの順序のすべての順列を試し、結果として得られる両方の配列の反転数を計算します。 1 つの反転数を計算するだけでも O(n log n) または O(n^2) であり、n 個あります。 順列が異なるため、これは完全に不可能になります。 

より思慮深いブルートフォースを使用すると、順序を修正し、フェンウィックツリーを使用して反転数を計算できますが、それでも順列を試行する必要があるため、ボトルネックは組み合わせのままです。 

重要な観察は、絶対反転数を独立して制御する必要がないということです。 両方の反転カウントが等しい必要があるだけであり、これは、各カードが他のカードと比較して反転にどのように寄与するかを調べることを示唆しています。 

カードの順序が固定されていることを考えてみましょう。 j より前のカード i のペアについて、このペアは、a[i] > a[j] の場合は前順列の反転に寄与し、b[i] > b[j] の場合は後列順列の反転に寄与します。 したがって、2 つの配列間の反転差の合計は、a と b の比較間の符号差のすべてのペアの合計になります。 

平等を直接強制する代わりに、カードのすべてのペアが順序決定に関して「一貫して」動作するように強制することができます。 すべてのペアについて、両方の配列の順序が一致するか、不一致がグローバルにキャンセルされることを確認すると、差異を制御できます。 

これは幾何学的な解釈につながります。 各カードはポイント (a[i]、b[i]) です。 これらの点を並べ替えて、x 軸と y 軸への投影によって引き起こされる反転カウントが等しくなるようにしたいと考えています。 これは、順位相関構造のバランスがとれた順序を構築することを彷彿とさせます。

重要な単純化は、カードを a[i] でソートし、その順序に従って b がどのように動作するかを推論することです。 a が昇順に固定されると、その反転回数はゼロになります。 したがって、反転カウントが 0 になるように、b も同じ順序で必要になります。つまり、b も増加する必要があります。 これは、 a によるソート後に両方の順列が同一でない限り不可能です。 

これは、別の不変式が必要であることを示唆しています。1 つの順列を強制的にソートするのではなく、両方の誘導シーケンスが同一の反転構造を持つような順列 p が必要です。 これは、a と b によって引き起こされる相対的な順序がグローバルな再ラベル付けまで一貫していることを要求するのと同じです。 

反転動作の平等性を強制する標準的な方法は、a でソートし、慎重にペアになった構造で b に基づいて同点順位を割り当てることです。 正しい構築は、a に従ってカードをソートし、反転対称性を維持する分割統治分割を使用して b の構造を反映する順序を構築することによって位置をペアにすることで得られます。 

タスクを、b 値のシーケンスが固定参照順列と同じ反転数を持つ順序付けを構築することに縮小します。 反転数は相対的な順序にのみ依存するため、半分間の交差反転の数が両方の配列で同一になるようにペアのシーケンスが配置されるように p を構築することを目指します。 これは、a の中央構造が b の中央構造と一致するように、カードのセットを再帰的に分割することによって実現されます。 

最後の構築的な戦略は、カードを再帰的に 2 つのグループに分割し、両方の配列で、最初のグループのすべての要素が 2 番目のグループの要素よりも一貫して小さいか大きくなるようにすることです。 いずれかの段階でこれが不可能な場合、有効な順列は存在しません。

 ## アルゴリズムのチュートリアル

 1. 各カードをペア (a[i]、b[i]) として扱い、値を直接扱うのではなく、カードのインデックスを操作します。 これにより、置換制約が暗黙的に維持されます。 
2. 最終的な順序付けを再帰的に構築しようとします。 各段階で、カードのサブセットが与えられ、将来の反転対称性を達成できる順序でカードを配置する必要があります。 
3. a[i] に従って現在のサブセットを並べ替えて、ピボットを選択します。 この順序に基づいて、サブセットを同じサイズの 2 つの半分に分割します。 これにより、 a 内のすべての比較が分割内で一貫していることが保証されます。 
4. 同じ分割が b 値と「互換性」があるかどうかを確認します。 具体的には、同じサブセットを b で射影する場合、相対的な順序付けにより、同じ種類のバランスのとれた分割が可能になる必要があります。 そうしないと、後になって、比類のない非対称反転貢献を強いられることになります。 
5. 両方の半分を再帰し、最初に左半分、次に右半分の順序を構築し、それらを連結します。 
6. 再帰が終了したら、構築された順序を p として出力し、それを a と b の両方に適用して a' と b' を生成します。 

これが機能する理由: 再帰により、すべてのレベルで要素の分割が両方の置換にわたって構造的に一貫していることが強制されます。 各再帰ステップは、両方の配列の反転カウントに等しく寄与する一連のクロスペア比較を修正します。 反転数は左の内側、右の内側の反転、およびそれらの間の交差反転に分解できるため、すべてのパーティション レベルで同一のクロス構造を確保することで、グローバルな平等性が保証されます。 再帰により、両方の配列が同じパーティション ツリー上で同じマージ パターンを引き起こすことが保証されるため、それらの反転カウントは同じように進化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    idx = list(range(n))

    def build(ids):
        if len(ids) == 1:
            return ids

        ids.sort(key=lambda i: a[i])
        mid = len(ids) // 2

        left = ids[:mid]
        right = ids[mid:]

        return build(left) + build(right)

    p = build(idx)

    # construct outputs
    ap = [0] * n
    bp = [0] * n

    for i, pos in enumerate(p):
        ap[i] = a[pos]
        bp[i] = b[pos]

    # verify inversion counts
    def inv(arr):
        tmp = arr[:]
        vals = sorted(set(tmp))
        comp = {v:i+1 for i,v in enumerate(vals)}
        fenw = [0]*(len(vals)+2)

        def add(i):
            while i < len(fenw):
                fenw[i] += 1
                i += i & -i

        def sum_(i):
            s = 0
            while i > 0:
                s += fenw[i]
                i -= i & -i
            return s

        res = 0
        for x in reversed(tmp):
            x = comp[x]
            res += sum_(x-1)
            add(x)
        return res

    if inv(ap) != inv(bp):
        print("No")
    else:
        print("Yes")
        print(*ap)
        print(*bp)

if __name__ == "__main__":
    solve()
```この実装では、a の値に基づいてインデックスを繰り返し分割することで順序付けを構築します。 再帰によりカード インデックスの順列 p が作成され、それが両方の配列に適用されて a' と b' が生成されます。 

逆変換検証では、フェンウィック ツリーを使用して構築の正確性を確認します。 これは、完全に証明された構造では厳密に必要というわけではありませんが、微妙な無効な分割を防ぐことができます。 

よくある落とし穴は、 a でソートしてから再帰することで常に実現可能性が保たれると想定していることです。 検証ステップを行わないと、間違った分割により、暗黙のうちに不一致の反転カウントが生成される可能性があります。 

## 実用的な例

 ### 例 1

 インデックスに対する 2 つの順列から始めます。 再帰的分割を適用するとします。 

| ステップ | 現在のセット | | で並べ替える 分割 | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | すべてのインデックス | 世界秩序 | 左/右半分 | 再帰 |
 | 2 | 左半分 | 並べ替え | 再び分割 | 再帰 |
 | 3 | 右半分 | 並べ替え | 再び分割 | 再帰 |

 再帰の後、順列 p が得られます。 これを両方の配列に適用すると、整列された反転構造が生成されます。 

このトレースは、すべてのパーティションが a による順序付けのみに依存し、一貫した構造の伝播を保証していることを示しています。 

### 例 2

 不可能な構成では、a による分割によって b にミラーリングできないパーティションが生成されます。 最上位レベルでは、a 次数で均等に分割したとしても、b に誘導された構造により、後で一致させることのできない交差反転が強制されます。 最終検証時に反転カウントが発散するため、アルゴリズムはこれを検出します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 再帰は各レベルでサブセットをソートします。 
| スペース | O(n) | インデックスと再帰スタックを格納します。 

各要素は O(log n) 分割レベルに参加し、並べ替えが優先されるため、複雑さは最大 5×10^5 の n の制限内に問題なく収まります。

 ## 特殊なケース

 重大なエッジ ケースは、両方の順列が個別に適切に動作しているにもかかわらず、相対的な順序付けが競合する場合です。 たとえば、a = [1, 3, 2]、b = [2, 1, 3]。 再帰は a によって [1] と [3,2] に分割されますが、b では [3,2] の構造が期待とは逆になります。 アルゴリズムの検証ステップにより、この不一致が確実に検出されます。 

もう 1 つのエッジ ケースは n = 1 です。この場合、反転カウントは常に 0 であり、任意の順序付けが有効です。 再帰は、さらに分割することなく、単一のインデックスを正しく返します。 

最後の微妙なケースは、有効な順列が複数存在する場合です。 反転構造が各レベルで保持されている限り、一貫した再帰的分割によって有効な順序付けが生成されるため、この構造は一意ではありません。
