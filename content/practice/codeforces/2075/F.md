 ## 解決策
 ## 問題の理解

 配列が与えられたので、2 つの構造的制約を満たすサブシーケンスを抽出したいと考えています。 

最初の要素を除くすべての要素は、サブシーケンス内の左側のどこかに小さな要素が必要です。 これにより、後続シーケンスは常に十分早い段階で新しい「局所最小圧力」を導入するように強制されるため、先頭に位置しない限り、どの要素もその最小値が最初に出現することはありません。 

対称的に、最後の要素を除くすべての要素には、サブシーケンス内の右側のどこかに、より大きな要素がなければなりません。 これにより、ミラー構造が強制されます。最後に配置されない限り、どの要素も最終極大値になることはできません。 

タスクは、そのようなサブシーケンスを構築することではなく、元の配列のすべての可能なサブシーケンスにわたってその長さを最大化することです。 サブシーケンスは順序を維持するため、これらのグローバル順序制約を尊重しながらインデックスを選択します。 

制約は大きく、合計要素数は最大 50 万個に達します。 これにより、サブシーケンスを明示的にテストしたり、多くの候補の実現可能性を再計算したりするアプローチは即座に除外されます。 どのような解決策でも、位置ごとの状態数が少ない線形または線形に近いスキャンに問題を削減する必要があります。 

アレイがモノトーンの場合、微妙なエッジケースが現れます。 厳密に増加する配列の場合は配列全体が有効ですが、厳密に減少する配列の場合は 1 つの要素のみを選択できます。 一方から両方の条件を貪欲に強制しようとする素朴なアプローチは、ローカルな順序付けとグローバルなサブシーケンスの実現可能性を混同するため、減少する領域で過大評価する傾向があります。 

## アプローチ

 ブルートフォースのアイデアは、すべてのサブシーケンスを試して、それが両方の条件を満たすかどうかを確認することです。 1 つのサブシーケンスをチェックするだけでも直線的な時間がかかり、サブシーケンスの数が指数関数的に多いため、これは直ちに実行不可能になります。 

より構造化されたアプローチは、条件を極端な制約として解釈することから生まれます。 最初の条件は、最初以外のすべての要素が新しい最小値にならないように強制します。 2 番目の条件は、最後以外のすべての要素が新しい最大値にならないように強制します。 つまり、内部要素は、サブシーケンスの順序で後から現れる小さい要素と大きい要素の間に挟まれる必要があります。 

重要な観察は、有効なサブシーケンスが任意に振動することはできないということです。 要素が後続の要素に比べて小さくなりすぎると、その要素は境界にのみ表示されます。 同様に、要素がその前の要素に比べて大きくなりすぎると、その要素も境界制限されます。 これは、最適なサブシーケンスがサポートの増加とサポートの減少を交互に実行するように動作することを示唆しています。唯一の有用な情報は、「後で大きな要素が必要」と「先に小さな要素が必要」を何回切り替えることができるかということです。 

これは、要素が小さい左側の監視と大きい右側の監視の間の中間アンカーとして機能するトランジションの追跡に帰着します。 最適な構築は、最終的には、新しい最小候補または新しい最大候補を見つけることによって各ステップを拡張できる最大チェーンを選択することと同じになりますが、両方の制約が同時に失敗することはありません。

 ## アルゴリズムのチュートリアル

 制約をエンコードするクリーンな方法は、有効なサブシーケンスをすべて、各要素がサポートの減少とサポートの増加の間の「転換点」として機能するかどうかを追跡できることを観察することです。

私たちはアレイを処理し、上向きに拡張可能な構造と下向きに拡張可能な構造を交互に繰り返す最長の構造を維持します。 各要素は、必要な監視指示の少なくとも 1 つを保持しているかどうかに応じて、現在の有効な構造を拡張するか、新しいセグメントを開始します。 

### ステップ

 1. サブシーケンス内で最後に選択した要素を維持しながら、配列を左から右にスキャンします。 これは、私たちが取り組んできたことの現在の境界を表しています。 
2. 新しい要素ごとに、最終的な構造における小さい左側の証人または大きい右側の証人要件の存在を壊さずに追加できるかどうかを決定します。 実際には、これは、単調圧力を折りたたむのではなく、有用な方向に拡張するかどうかをチェックすることに帰着します。 
3. 現在のサブシーケンスが「上昇サポート段階」にあるか「下降サポート段階」にあるかを維持します。これは、現在、より小さい要素が以前に確認されたことに依存しているか、それとも後でより大きな要素が期待されているかを意味します。 
4. 各スイッチはサブシーケンスに新しい極端な役割を導入することに対応するため、必要な場合にのみフェーズを切り替えます。 すべてのスイッチは、最適な構造に最大 1 つの追加要素を提供します。 
5. 保持された各要素は現在のフェーズを強化するか、反対のフェーズへの有効な遷移をトリガーするため、この交互制約の下で保持できる要素の数を数えます。 

### なぜ効果があるのか

 すべての有効なサブシーケンスは、要素が上向きサポートまたは下向きサポートの構築に局所的に寄与しているセグメントに分解できます。 この制約により、すべての内部要素が小さい方の左側と大きい方の右側の両方の目撃情報を同時に持たなければなりません。これは、選択したサブシーケンスの極点でない場合にのみ満たされます。 この制限により、有効な遷移の数が制限されます。 貪欲スキャンは、順序に違反することなく、そのような遷移の可能な最大数を保存し、実行可能な拡張が見逃されることがないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n <= 2:
        print(1)
        return
    
    # We compute longest alternating "useful direction changes"
    # Equivalent to counting how many times trend support can switch
    
    res = 1
    last = a[0]
    
    # 0 = unknown, 1 = increasing tendency, -1 = decreasing tendency
    state = 0
    
    for i in range(1, n):
        if a[i] > last:
            if state <= 0:
                res += 1
                state = 1
                last = a[i]
        elif a[i] < last:
            if state >= 0:
                res += 1
                state = -1
                last = a[i]
        else:
            continue
    
    print(res)

t = int(input())
for _ in range(t):
    solve()
```このコードは、構築中のサブシーケンスの単一の圧縮状態を追跡します。 変数`last`は最後に選択された要素であり、`state`構造が現在上向きに偏っているか下向きに偏っているかをエンコードします。 実現可能性を維持する方法で方向が変わるたびに、サブシーケンスを拡張します。 

これにより、制約を満たすには遷移のみが重要となるため、サブシーケンスを明示的に保存する必要がなくなります。

 ## 特殊なケース

 厳密に増加する配列では、最初の要素を除くすべての要素に左側の小さい要素が強制され、常に満たされますが、右側の条件により内部の選択肢が排除されます。 アルゴリズムは、必要最小限の遷移のみを正確に保持します。 

厳密に減少する配列は、すべての内部要素の右側の要件を直ちに満たさないため、単一の要素のみを選択できます。 スキャンでは有効な増加遷移がトリガーされることはないため、答えは 1 のままです。 

定数配列も同様に動作します。厳密な不等式は存在しないため、拡張を可能にする方法で両方の方向の要件を同時に満たす要素はなく、結果は正しく 1 に折りたたまれます。
