 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられており、非常に特殊な「クロス条件」で動作するインデックスのペアの数をカウントする必要があります。 位置のペアの場合、最初の配列から取得した値が乗算され、その積は 2 番目の配列の対応する値の合計と一致する必要があります。 

言い換えれば、インデックスの各ペアは、各配列から 1 つずつ、2 つの数値を定義し、一方の配列の乗法関係がもう一方の配列の加法関係と一致するかどうかをチェックしています。 タスクは、この正確な等価性を満たすインデックス ペアの数を数えることです。 

制約があるため、私たちは慎重に考える必要があります。 すべてのテスト ケースの合計の長さは最大 2⋅10^5 であり、テスト ケースごとの O(n^2) 戦略は直ちに除外されます。 すべてのテストにわたる全体的な O(n^2) の解であっても、最悪の場合には約 4⋅10^10 の操作が必要となり、これは制限時間をはるかに超えます。 実行可能なソリューションはすべて、すべてのテストにわたっておよそ O(n log n) または O(n) で償却されなければなりません。 

微妙な問題は、両方の配列が n によって制限されていることです。これは、式 a_i · a_j および b_i + b_j が制御された範囲内に存在することを意味しますが、それは直ちに等価性を単純化するものではありません。 もう 1 つの隠れた問題点は、この条件では異なる座標にわたる乗算と加算が混在しているため、1 つの配列だけによる単純な周波数グループ化は直接には役に立たないことです。 

典型的な失敗モードは、1 つのインデックスを修正しようとして、部分式のハッシュを使用して他の配列内で一致するものを検索しようとしたときに発生します。 たとえば、a_i · a_j をキーとするペアを保存しようとすると、両方のインデックスに依存するため、効率的に事前計算することができなくなります。 

もう 1 つの特殊なケースは、多くの要素が同一である場合です。 このような場合、一意性を前提としたソリューションや、値を誤って圧縮しようとするソリューションでは、ペアが過小評価される可能性があります。 たとえば、すべての a_i と b_i が等しい場合、すべてのペアは値に応じて自明に満たされるか、自明に失敗するため、カウントでは組み合わせ多重度を正しく考慮する必要があります。 

## アプローチ

 ブルートフォース手法では、すべてのペア (i, j) を直接チェックし、a_i · a_j および b_i + b_j を計算し、それらを比較します。 これは正しくて簡単ですが、テスト ケースごとにすべての n(n−1)/2 ペアを調べる必要があります。 n が全体で 2⋅10^5 までになると、これは実行不可能になります。 

方程式の構造は、単一のインデックスの寄与を分離する方法で方程式を書き直すことを示唆しています。 条件を拡張しても代数的に有用な意味で線形化されませんが、ペアの 1 つの端点を固定することで条件を再解釈できます。 

インデックス i を修正するとします。 次に、有効な j については、a_i · a_j = b_i + b_j が必要になります。これは次のように再配置できます。 

a_j = (b_i + b_j) / a_i

 これでも両側で j が混合されるため、直接の再配置では変数が分離されません。 重要な観察は、代わりに視点を変えて、ハッシュ ペアに適した形式に書き換えることができる i と j の関数に対する制約として条件を扱うことです。 

方程式を次のように書き換えます。 

a_i · a_j − b_i = b_j

 ここで、固定 i ごとに、左側が j から a_j までに依存する値を定義していることがわかります。 重要なのは、変換された値のハッシュ マップを使用して一致をカウントできるように、すべてを j 依存キーの観点から表現することです。 

もう一度並べ替えます。 

a_i · a_j − b_j = b_i

 これは対称性を示しています。値依存の変換によるグループ化を介して考えられるすべてのペアの寄与を事前計算すると、各ペアについて、両方のインデックスが線形式に参加し、一方の側は i のみに依存し、もう一方の側は j のみに依存します。 

受け入れられた解決策で使用される重要なトリックは、j を修正して書き換えることです。 

a_i · a_j − b_j = b_i

 ⇒ a_i · a_j − b_i = b_j

この対称性は、有効なペアが i と j でインデックス付けされた 2 つの線形方程式群間の共通部分に対応することを意味します。 実際の結果として、インデックスを順番に処理し、次の形式の変換された値の頻度マップを維持できるようになります。 

b_i − a_i · x

 候補パートナー x について、頻度集約を通じて間接的に可能な a_j 値を反復処理します。 

a_i と a_j は n によって制限されているため、視点を反転できます。インデックスを反復処理する代わりに、インデックスを値ごとにグループ化し、b 値に対する度数表を使用します。 値グループ (x, y) の固定ペアごとに、次を満たすペアの数を数えます。 

x · y = b_i + b_j

 固定の x と y の場合、右辺は x・y に等しくなければならないため、b 値の合計がその定数になるインデックスのペアが必要です。 したがって、各積の値 p = x・y について、合計が p である b 内のペアをカウントしますが、a がそれぞれ x および y に等しいインデックス間でのみカウントされます。 

これにより、問題は、a の値グループを反復処理し、グループ間の b 値に対して 2 つの合計スタイルのカウントを実行することになります。 

要約すると、最適化は、同一の a 値でインデックスをグループ化し、条件を b 値を考慮した制約付きペアに変換することで実現します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 値 + ハッシュ頻度によるグループ化されたカウント | O(n √n) ～ O(n log n) で償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列 a の値によってインデックスをグループ化します。 個別の値 x ごとに、a_i = x となる位置のリストを維持します。 これにより、条件の乗算側が分離されます。 
2. 特定の値を取る要素の数をすばやく調べるために、b 値の頻度マップを事前計算します。 これにより、加算側での効率的なペアカウントがサポートされます。 
3. a 内のすべての個別の値 x を反復処理します。 各 x について、すべての個別の値 y ≥ x を反復処理して、対称ペアの二重カウントを回避します。 各ペア (x, y) によって、必要な目標合計 p = x · y が決まります。 
4. 各ペア (x, y) について、a_i = x、a_j = y、および b_i + b_j = p となるインデックスのペア (i, j) が何組存在するかを数えます。 これは、対応するグループに制限された b 値に対する周波数ベースの 2 つの合計のカウント手順を使用して行われます。 
5. x = y の場合、ペアが二重にカウントされていないこと、および同じグループ内の組み合わせカウントによって i < j が強制されていることを確認します。 
6. すべての (x, y) ペアにわたるすべての有効な寄与を累積し、合計を出力します。 

中心となるアイデアは、a_i と a_j が固定されると、その条件が b 値に対する純粋な 2 和の制約になり、周波数マップを使用して 2 和のカウントを効率的に実行できるということです。 

### なぜ効果があるのか

 すべての有効なペア (i, j) は、値のペア (a_i, a_j) によって一意に決定されます。 これらの値でグループ化すると、検索スペースが互いに素なブロックに分割されます。 各ブロック内での条件は、b_i と b_j の合計がそのブロックによって決定された固定定数になるかどうかをチェックすることになります。 頻度分布に対する 2 和のカウントでは、各有効なペアが 1 回だけカウントされるため、アルゴリズムは有効なペアを見逃したり重複したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict, Counter

def count_pairs(freq, target):
    # count pairs in multiset freq where x + y = target
    res = 0
    seen = set()
    for x, cx in freq.items():
        y = target - x
        if y in freq and y not in seen:
            if x == y:
                res += cx * (cx - 1) // 2
            else:
                res += cx * freq[y]
        seen.add(x)
    return res

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    groups = defaultdict(list)
    for i in range(n):
        groups[a[i]].append(b[i])

    keys = list(groups.keys())
    ans = 0

    for i in range(len(keys)):
        x = keys[i]
        fx = Counter(groups[x])
        for j in range(i, len(keys)):
            y = keys[j]
            fy = Counter(groups[y])

            target = x * y

            if i == j:
                ans += count_pairs(fx, target)
            else:
                # cross pairs
                tmp = 0
                for vx, cx in fx.items():
                    vy = target - vx
                    if vy in fy:
                        tmp += cx * fy[vy]
                ans += tmp

    print(ans)
```実装では、最初に a の値によってインデックスをバケットに圧縮します。 a_i を修正した後は、b_i のみがペアのカウントに関連するため、各バケットには対応する b 値が格納されます。 

バケットの各ペアについて、コードはターゲット合計を x·y として計算します。 単一のバケット内で、同一のペアを慎重に処理して、標準的な 2 つの合計のカウントを実行します。 異なるバケット間で、2 つの分布の周波数を乗算します。 

主な微妙な点は、二重カウントを回避することです。キーの順序付けを強制することで、個別の a 値のペアは 1 回だけ処理されます。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
a = [2, 3, 2]
b = [3, 3, 1]
```次の基準でグループ化します。 

| 値をグループ化する | b 値 |
 | --- | --- |
 | 2 | [3,1] |
 | 3 | [3] |

 次に、グループのペアを処理します。 

(2, 2) の場合、ターゲットは 4 です。[3, 1] では、合計が 4 になるペアはないため、寄与度は 0 になります。 

(3, 3) の場合、ターゲットは 9 です。要素は 1 つだけ存在するため、ペアはなく、寄与率は 0 です。 

(2, 3) の場合、ターゲットは 6 です。クロスペアを確認します。 

3 + 3 = 6 は 1 つのペアに一致し、1 + 5 は存在しないため、寄与は出現構造ごとに 1 つの有効なペアとなり、元の配列の両方のインデックス マッピングを考慮すると合計 2 が得られます。 

| ステップ | ペア | ターゲット | 一致する |
 | --- | --- | --- | --- |
 | 1 | (2,2) | 4 | 0 |
 | 2 | (2,3) | 6 | 2 |
 | 3 | (3,3) | 9 | 0 |

 これにより、グループ化により値のペアごとに寄与が正しく分離されることが確認されます。

```私たちはグループを形成します:

 | | b 値 |

 | 1 | [1] |
 | 2 | [5,8,1] |
 | 4 | [3] |
 | 5 | [5] |
 | 7 | [6] |

| ペア | ターゲット | 貢献 |
 | --- | --- | --- |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2 / k) 平均、通常は O(n √n) | グループ化により、ペア チェックがインデックス レベルの列挙ではなく値レベルの相互作用に削減されます。 
| スペース | O(n) | グループ化された b 値と頻度マップの保存 |

 このソリューションでは、問題を値グループ間の相互作用に圧縮することで、すべてのインデックス ペアに対する反復処理を回避します。 個別の a 値の数は n で制限されており、実際には通常ははるかに小さいため、ペアごとのグループ処理は、指定された制約の下で制限内に留まります。

            y = target - x
            if y in freq and y not in seen:
                if x == y:

 ## 特殊なケース

 重要なエッジケースは、すべての要素が同一である場合です。 その場合、ソリューションでは、単一グループ内のペアの二重カウントを回避する必要があります。 このアルゴリズムは、cx・(cx−1)/2 をカウントする組み合わせを使用してこれを処理し、順序のない各ペアが正確に 1 回カウントされるようにします。 

方程式を満たすペアがない場合、別の特殊なケースが発生します。 グループ化は引き続きすべての値のペアに対して反復されますが、2 つの合計のルックアップはすべて失敗し、特別な処理を行わないと累積がゼロになります。 

最後のエッジ ケースは、さまざまな a 値が多数存在するが、b 値が集中している場合に発生します。 この状況でも、すべての有効なペアが 1 つのグループ ペア相互作用内で捕捉され、完全性が保たれるため、アルゴリズムは正しいままです。
