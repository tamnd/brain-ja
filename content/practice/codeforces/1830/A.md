 ## 解決策
 ## 問題の理解

 エッジの順序付きリストによって記述されたツリーが与えられます。 エッジは単なる接続情報ではなく、描画プロセスで何度も連続してエッジをスキャンするため、エッジの順序が重要になります。 

プロセスは、頂点 1 のみが「描画された」とみなされることから始まります。 エッジ リストを完全に通過するたびに、最初から最後まですべてのエッジを調べます。 すでに持っている頂点とまだ描画していない頂点を接続するエッジを見つけると、すぐにその新しい頂点を描画します。 すべてのエッジの完全なスキャンが終了した後、いくつかの頂点がまだ欠けている場合はスキャンを繰り返します。 答えは、すべての頂点が描画されるまでに必要なフル スキャンの回数です。 

したがって、問題は最短パスやツリー構造だけに関するものではなく、固定されたエッジ順序を通じて情報がどれだけ早く拡散するかということです。 

制約は、テスト ケース全体で合計 200,000 頂点までになります。 フルスキャンを繰り返しシミュレートし、反復ごとに単純にエッジを処理しようとするソリューションでは、O(n) 回の作業を何度も繰り返す危険があり、チェーンのような最悪のケースでは O(n²) まで低下します。 3 秒の制限の下では遅すぎます。 このソリューションでは、エッジ リストを繰り返し明示的に再スキャンすることなく、「新しくアクティブ化された頂点」が各パスでどこまで伝播するかを抽出する必要があります。 

通常は頂点を早くアクティブにするエッジが入力順序の後半に配置される場合、微妙な失敗のケースが発生します。 

たとえば、チェーン 1 - 2 - 3 - 4 がエッジの順序が (3,4)、(2,3)、(1,2) であるとします。 最初のスキャンでは、(1,2) のみが使用可能ですが、最後に表示されるため、引き続き機能しますが、より複雑な分岐ツリーでは、論理的にツリー構造の早い段階で到達可能であったとしても、完全なパスが完了するまで頂点のアクティブ化が遅れる可能性があります。 

この順序依存関係により、反復スキャン動作を考慮しない限り、単純な BFS または DFS が不十分になります。 

## アプローチ

 直接的なシミュレーションは容易に想像できます。 描画された頂点のセットを保持し、エッジ リストを繰り返し反復して、そのパスで到達可能になった頂点を追加します。 各パスは 1 つの「読み取り」に正確に対応します。 これはプロセスを文字通り反映しているため、これは正しいです。 

ただし、最悪の場合、費用が高くつくことになります。 フル スキャンごとに新しい頂点が 1 つだけ検出された場合、頂点ごとにエッジ リスト全体のスキャンを繰り返し、O(n²) 個の動作を与えます。 

重要な観察は、各頂点が特定の「ラウンド」または「読み取りインデックス」で描画され、この値は既に描画された頂点への接続がエッジ順序にいつ現れるかによってのみ依存するということです。 エッジがリスト内の位置 i で u を v に接続する場合、v は、u がすでにアクティブになった後の次の読み取りにのみ現れることができます。 これにより、既知の最良のアクティブ化時間を維持しながら、エッジ上の 1 回のパスで解決できる頂点にわたる依存構造が作成されます。 

各頂点に、それが現れる可能性のある最も古い読み取り値を割り当てます。 頂点 1 は読み取り値 1 から始まります。順番にエッジごとに、1 つのエンドポイントが特定の読み取り値で既知である場合、もう一方のエンドポイントは、スキャンの後半に現れるかどうかに応じて、最大でその読み取り値または 1 つ以上の読み取り値に更新できます。 正しい伝播は、エッジ リストに対する動的プログラミングの形式になり、改善が安定したときにエッジを超える各パスが追跡によって暗黙的にシミュレートされます。 

重要な単純化は、最終的な答えが、この伝播を通じて「レイヤーを進める」必要がある最大回数に等しいということです。これは、頂点ごとに実行中の最良の状態を維持し、エッジ スキャン相当ごとに 1 回更新することで、O(n) で計算できます。

より具体的には、フル スキャンをシミュレートする代わりに、プロセスを繰り返し緩和として扱います。各フル パスにより、情報はエッジの順序を尊重する任意のパスに沿って 1 つのエッジに移動できます。 これにより、問題はエッジ位置によって引き起こされる最長の「活性化チェーン」の計算に変わります。

 ## アルゴリズムのチュートリアル

 このプロセスを、エッジが順方向スキャンでのみ使用できるという制約の下で、頂点 1 から到達可能になる最初の読み取り値を頂点ごとに計算するものとして再解釈します。 

1. 配列を初期化する`dp`どこ`dp[v]`どの頂点の最も古い読み取り値を表します`v`引かれるようになる。 セット`dp[1] = 1`そして他のものはすべて無限に。 これはプロセスの開始条件をエンコードします。 
2. エッジ リストを順番に走査し、現在最もよく知られているアクティブ化時間を使用してエンドポイントを繰り返し緩和します。 エッジがある場合`(u, v)`そして`u`すでに読み取り可能です`r`、 それから`v`より早く到着することはできません`r + 1`このエッジが後のスキャンでアクティブ化する場合。 
3. 頂点はさまざまなエッジを通じて複数回改善される可能性があるため、緩和ごとに更新されます。`dp[v] = min(dp[v], dp[u] + 1)`そして対称的に`dp[u] = min(dp[u], dp[v] + 1)`役割が逆転したとき。 これは、特定のスキャンでは、すでにアクティブ化された頂点のみが次のスキャンで隣接する頂点をアクティブ化できることを反映しています。 
4. 値が変化しなくなるまで、エッジ リスト全体に対してこの緩和プロセスを繰り返します。 各完全な反復は、元のプロセスの 1 回の読み取りに正確に対応します。 
5. 答えは次の最大値です。`dp`、それは頂点が描画される最後の瞬間であるためです。 

これが機能する理由は、`dp[v]`頂点 v が現れる最も早いスキャン境界を追跡し、スキャンごとに、既に検出された頂点を未検出の頂点に接続するエッジを介した 1 つの追加層の伝播が可能になります。 ツリーにはサイクルがないため、改善は常に前進し、最大 n ステップ後に安定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        edges = [tuple(map(int, input().split())) for _ in range(n - 1)]

        INF = 10**9
        dp = [INF] * (n + 1)
        dp[1] = 1

        changed = True

        while changed:
            changed = False
            for u, v in edges:
                if dp[u] + 1 < dp[v]:
                    dp[v] = dp[u] + 1
                    changed = True
                if dp[v] + 1 < dp[u]:
                    dp[u] = dp[v] + 1
                    changed = True

        print(max(dp[1:]))

if __name__ == "__main__":
    solve()
```コードは緩和解釈を直接実装します。 の`dp`配列には最も古い読み取り値が格納されます。 エッジを繰り返しスイープし、一方のエンドポイントに到達すると次の読み取りでもう一方のエンドポイントに到達できることが判明するたびにエンドポイントを更新します。 

ループは、改善が起こらなくなるまで続きます。これは、追加のフル スキャンで新しい頂点が検出されなくなった瞬間に相当します。 の最大値`dp`は必要なスキャンの数です。 

微妙な点は、更新が対称的であることです。 プロセスは概念的には頂点 1 から開始しますが、特定の読み取りで頂点がアクティブ化されると、次の読み取りでその隣接頂点をアクティブ化できます。 木には方向がないため、リラックスする際には両方の方向を考慮する必要があります。

 ## 特殊なケース

 重大なエッジ ケースは、ツリーが長いチェーンであるにもかかわらず、エッジが逆の順序で表示される場合です。 各パスではエッジ位置ではなくスキャン サイクルに関して 1 層深い伝播のみが許可されるため、アルゴリズムは依然として収束します。 

入力の場合:```
4
4 3
3 2
2 1
```dp は値 1 を持つ頂点 1 から始まります。緩和を繰り返した後でのみ、値はチェーンを通して逆方向に伝播します。 緩和するたびに次の頂点に必要な読み取り数が増加します。これは、各スキャンでこの順序で追加の層が 1 つだけ明らかにされるという考えと一致します。
