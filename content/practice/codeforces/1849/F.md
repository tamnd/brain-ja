 ## 解決策
 ## 問題の理解

 個別の整数のセットが与えられており、各サブセット内のすべてのペア間の最小 XOR ができるだけ大きくなるように、それらを 2 つのサブセットに分割する必要があります。 パーティションの値は、2 つのサブセット コストの小さい方です。 各要素は、正確に 1 つのサブセットに属している必要があります。 要素が 2 つ未満のセットの場合、コストは次のように定義されます。$2^{30}$。 

入力サイズは最大です$2 \times 10^5$それぞれ以下の整数$2^{30}$。 これは、すべてのペアの XOR を計算するためのセット全体にわたるネストされたループを含むソリューションは遅すぎることを意味します。 考えられるすべてのパーティションの総当たり検索。$O(2^n)$、明らかに不可能です。 すべてのペアごとの XOR を計算する場合でも、$O(n^2)$届くだろう$4 \times 10^{10}$上限での動作となります。 

この問題の微妙な部分は、XOR がバイナリ空間の距離メトリックのように動作することです。 XOR の観点から見て隣接する数値は数値的に隣接していない可能性があるため、値の順序に基づいて単純に分割しようとすると失敗する可能性があります。 一部のサブセットに要素が 1 つしかない場合、別のエッジ ケースが発生します。この場合、コストはデフォルトで$2^{30}$。 不用意に実装すると、これが無視され、ゼロとして扱われる可能性があります。 

たとえば、与えられた`[0, 1, 2]`に分割します`[0,1]`そして`[2]`のサブセットコストを与える`1`そして`2^30`。 2 つの最小値は 1 です。サブセット サイズのバランスを常に保つ単純なアプローチでは、1 を選択する可能性があります。`[0,2]`そして`[1]`アルゴリズムでは、カウントだけでなく XOR 構造を考慮する必要があります。 

## アプローチ

 ブルートフォースソリューションは、すべてを生成することです。$2^n$パーティションを分割し、それぞれについて、各サブセット内のすべてのペアを反復処理してコストを計算します。 これは正しいですが、実行不可能です。$n = 2 \times 10^5$、パーティションの数は天文学的であり、各コストの計算には時間がかかります。$O(n^2)$。 

最適なソリューションを得るために重要な洞察は、整数をバイナリ形式で解釈することです。 セット内の XOR の最小値は、数値が異なる最上位ビットによって決まります。 これは、再帰的な分割統治アプローチを示唆しています。 最上位ビットを調べると、数値を 2 つのグループ (そのビットに 0 が含まれるグループと 1 が含まれるグループ) に分割できます。最小の XOR を最大化するには、必要な場合にのみ、異なるパーティション間で数値をペアにする必要があります。 いずれかのグループが空の場合、最適な分割は次の下位ビットで行われます。 

再帰はビットに向かって続行され、同じサブセット内の要素の XOR が大きくなるようにしながら、各数値を 2 つのサブセットのいずれかに割り当てます。 これは、バイナリ トライを構築し、各ノードで再帰的に分割することと同じです。 最適なパーティションは、ビット分割に従って番号を割り当てることによって決定されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^2) | O(n) | 遅すぎる |
 | 最適 | O(n log MAX_BIT) | O(n log MAX_BIT) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 数値は 30 ビット未満であるため、各数値を 30 ビットのバイナリ表現に変換します。$2^{30}$。 これにより、最上位ビットから最下位ビットまでを調べることができます。 
2. インデックスのリストとビット位置を受け取る再帰関数を定義します。 ビット位置が 0 未満であるか、リストに要素が 1 つある場合は、残りのすべての要素を 1 つのサブセットに割り当てて戻ります。 
3. 現在のビットに基づいてリストを 2 つのサブリストに分割します。1 つはこのビットが 0 の要素用で、もう 1 つはこのビットが 1 の要素用です。 
4. 両方のサブリストが空でない場合は、次の下位ビットで両方のサブリストを再帰的に分割します。 サブリストが空の場合は、空ではないサブリストの分割を続けます。 再帰により、上位ビットで異なる要素が分離される可能性が高くなり、各サブセットの最小 XOR が最大化されます。 
5. バックトラック中に、分割のどちら側に該当するかに基づいて、各要素にサブセット識別子 (0 または 1) を割り当てます。 サブセットの分割を維持するために識別子を一貫して反転します。 
6. すべての再帰が完了したら、サブセットに対応する 0 と 1 の文字列としてパーティションを出力します。 

機能する理由: 再帰は、最小の XOR が要素間の最大の異なるビットによって支配されるという特性を尊重します。 数値を異なるビットで早期に分離することで、同じサブセット内で小さな XOR 値が作成されることを回避します。 上位ビットは常に XOR 値により多く寄与し、下位ビットは上位ビットが同一の場合にのみ考慮されるため、ビットごとのこの貪欲な選択は全体的に最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

def xor_partition():
    n = int(input())
    a = list(map(int, input().split()))
    ans = [0] * n

    def solve(indices, bit):
        if bit < 0 or len(indices) <= 1:
            for i in indices:
                ans[i] = 0
            return
        zeros, ones = [], []
        for i in indices:
            if (a[i] >> bit) & 1:
                ones.append(i)
            else:
                zeros.append(i)
        if not zeros:
            solve(ones, bit - 1)
        elif not ones:
            solve(zeros, bit - 1)
        else:
            solve(zeros, bit - 1)
            for i in ones:
                ans[i] = 1
            solve(ones, bit - 1)

    solve(list(range(n)), 29)
    print(''.join(map(str, ans)))

xor_partition()
```大規模な場合には分割統治が深くなる可能性があるため、解決策は再帰制限を増やすことから始まります。$n$。 再帰関数は、現在のビットに基づいてインデックスを分割します。 0 または 1 の割り当ては再帰中に行われます。 パーティションの片側が空の場合、アルゴリズムは空ではない側で続行します。 それ以外の場合、`ones`グループはサブセット 1 に割り当てられ、両側で再帰を続けます。 これにより、サブセット間の XOR が上位ビットで最大化されます。
