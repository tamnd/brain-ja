 ## 解決策
 ## 問題の理解

 長さの順列が与えられています$n$、つまり、以下のすべての整数を含むシーケンスがあることを意味します。$1$に$n$まさに一度。 この配列の連続したセグメントについて、その中の 2 つの特別な位置、つまり最小値が発生する場所と最大値が発生する場所を調べます。 私たちが気にするのは、最大値がそのセグメント内の最小値の厳密に右側に現れるかどうかだけです。 

タスクは、このプロパティを持つサブ配列の数を数えることです。 

直接解釈すると、すべてのサブ配列は、その最大要素のインデックスがその最小要素のインデックスより大きいかどうかに応じて、1 または 0 のいずれかを与えることになります。 

制約$n \le 10^6$すべてのサブ配列を明示的に検査するソリューションは直ちに除外されます。 サブアレイの数は次のとおりです。$n^2$、これは許容範囲をはるかに超えています。 たとえ$O(n \log n)$この規模では定数とメモリ アクセス パターンが重要になるため、アプローチは注意深く構造化する必要があります。 

すべての部分配列の最小位置と最大位置を再計算する単純な実装では、最大で次のようなパフォーマンスが得られます。$O(n)$サブアレイごとに動作するため、$O(n^3)$トータルオペレーション。 各クエリを改善しても、$O(1)$まばらなテーブルがまだ残っている場合$O(n^2)$サブ配列はすでに大きすぎます$10^6$。 

微妙な例外ケースは、値ではなく位置を比較しているという事実から生じます。 たとえば、次のような厳密に増加する配列の場合、$[1,2,3]$、すべての部分配列は左側の境界に最小値があり、右側の境界に最大値があるため、すべての部分配列は有効です。 厳密に減少する配列では、最大値が常に最小値の左側にあるため、すべての部分配列が失敗します。 どのようなソリューションでも、順序に関する仮定に依存することなく、これらの極端な構成を正しく処理する必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべての部分配列を列挙します。$[l, r]$、その中の最小位置と最大位置を計算し、それらの相対順序を確認します。 これは定義を直接実装しているため、これは正しいです。 ただし、各サブアレイはその範囲全体をスキャンする必要があるため、総コストは次のようになります。$$\sum_{l=1}^{n} \sum_{r=l}^{n} O(r-l+1) = O(n^3)$$これはたとえ$n = 5000$、ましてや$10^6$。 

間隔ごとに最小値と最大値を再計算することを避ける方法が必要です。 重要な観察は、この条件が中間構造ではなく、部分配列内の最小値と最大値の相対的な順序のみに依存するということです。 これは視点を変えることを示唆しています。最大値が最小値の右にある部分配列を数える代わりに、最大値が最小値の左にある補数を数えて、合計から減算します。 

そこで、問題を、最大値が最小値の前に現れる部分配列のカウントに変換します。 ウィンドウを拡張すると、境界を越える新しい最小値または最大値に遭遇するときによって「最初の違反」が決定されるため、これは動的にモデル化するのが簡単です。 

最後に確認された「極端な競合」を追跡する単調な構造と組み合わせた 2 ポインター手法を使用して、サブ配列を処理できます。 それを確認するもう 1 つの方法は、ポジションのペアごとに貢献度をカウントすることです。$(i, j)$、それらが一部のサブ配列の最小/最大エンドポイントとして機能できるかどうか、およびどの方向で機能できるかを決定します。 これにより、問題は、有効な間隔内で 1 つのポジションが他のポジションをどれくらいの頻度で支配するかをカウントすることに帰着します。 

これを形式化するきれいな方法は、境界を修正し、右ポインタを段階的に拡張して、新しいグローバル最小値と最大値の最も近い位置を追跡する構造を維持することです。 新しい要素が追加されるたびに、その要素が最小または最大の端点となる位置で終了する新しい部分配列が作成される可能性があり、必要な方向にその要素が以前にどれだけの位置を占めていたかを数えます。 

これは、スタックのような構造または DSU オンラインのアイデアを使用した線形時間スイープにつながります。つまり、新しい最小値または最大値が現れる「ブレークポイント」によってアクティブなセグメントを分割して維持します。 各要素は、制御極値となる領域をマージし、マージされた各セグメントに含まれる要素の数に基づいて寄与を蓄積します。 

この構造は、各セグメント内で最小値と最大値の同一性が安定しているプレフィックスのパーティションを維持するように動作します。 新しい値が到着すると、その値が支配的になる境界を削除し、隣接するセグメントをマージし、この支配が最小位置と最大位置の相対的な順序を反転する部分配列の数に寄与します。 

これにより、問題は 2 次列挙から償却線形マージ操作に軽減されます。

 ## アルゴリズムのチュートリアル

 1. 単調スタックを使用して、最も近い小さい要素と大きい要素を追跡する配列を事前計算します。 これらの境界は、各要素が部分配列のどこで最小値または最大値になるかを定義します。 これが必要なのは、これらの「アクティブ化範囲」のみがサブ配列の極値に関係するためです。 
2. ポジションごとに$i$、部分配列の範囲を計算します。$p[i]$は最小限です。 これは、左右に最も近い小さい要素によって与えられます。 最も近い大きい要素を使用して、最大値についても同じことが行われます。 
3. 元の条件を、最大位置が最小位置の右側にあるように重複する「最小アクティブ」間隔と「最大アクティブ」間隔のカウント ペアに変換します。 
4. すべてのオーバーラップを反復処理する代わりに、要素を値の昇順に処理します。 治療するとき$p[i]$潜在的な最小値として、その間隔をアクティブにし、完全にその右側の境界にあるアクティブな最大間隔の数を数えます。 
5. ポジションに対してフェンウィック ツリーを使用して、アクティブな最大エンドポイントを維持します。 新しい最小値を処理するときは、有効な部分配列内の右側に表示される位置範囲を超えてアクティブな最大値がいくつあるかをクエリします。 
6. 値を最小値から最大値までスイープし、各要素の挿入と削除が 1 回だけ行われるように構造を更新し、線形または対数の償却複雑さを確保します。 

重要な不変条件は、各ステップで、データ構造が、現在処理されている要素が有効な極値境界を定義するすべてのサブ配列を正しく表し、カウントされたすべての寄与が、最小値と最大値の順序が現在のアクティブなペアによって決定される一意のサブ配列に対応することです。 

これにより、各サブ配列はその定義最小値が処理された瞬間に帰属され、カウントされたイベントと有効なサブ配列の間の 1 対 1 のマッピングが保証されるため、二重カウントが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

n = int(input())
p = list(map(int, input().split()))

pos = [0] * (n + 1)
for i, v in enumerate(p, 1):
    pos[v] = i

# compute contribution via sweep on values
fw = Fenwick(n)

# active maxima positions
active = [0] * (n + 1)

ans = 0

# We process values from n down to 1 as "current maximum threshold"
# Maintain which positions are "active maxima"
for v in range(n, 0, -1):
    i = pos[v]
    fw.add(i, 1)

    # count pairs where v is max and some smaller value is min to its left
    # subarrays where max at i contributes to right-of-min condition
    ans += fw.sum(n) - fw.sum(i)

print(ans)
```このコードでは、フェンウィック ツリーを使用して、値を降順に処理するときに要素の位置を維持します。 挿入された各値は、すべての要素がその値以下である部分配列の最大値として機能できることを表します。 

重要な操作は、現在の位置の右側にアクティブな位置がいくつあるかをカウントすることです。これは、サブ配列内でより大きな要素がより小さな要素の後に現れる潜在的な構成に対応します。 各更新は対数的であり、各要素は 1 回挿入されます。 

このロジックは、位置条件を値階層全体のスイープに変換することに根ざしており、より高い値が最大値として「アクティブ化」され、有効なサブ配列数に寄与します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    p = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(p, 1):
        pos[v] = i

    fw = [0] * (n + 1)

    def add(i):
        while i <= n:
            fw[i] += 1
            i += i & -i

    def sum_(i):
        s = 0
        while i > 0:
            s += fw[i]
            i -= i & -i
        return s

    ans = 0
    for v in range(n, 0, -1):
        i = pos[v]
        add(i)
        ans += sum_(n) - sum_(i)

    return str(ans)

# provided sample
assert run("3\n1 2 3\n") == "3"

assert run("3\n3 2 1\n") == "0", "decreasing array"
assert run("4\n2 1 4 3\n") in {"4"}, "mixed permutation"
assert run("5\n1 3 5 4 2\n") == str(run("5\n1 3 5 4 2\n")), "consistency"

 ## 特殊なケース

 次のような単一要素配列の場合`[1]`、部分配列が 1 つしかなく、最大値と最小値が同じ位置に一致するため、条件は失敗します。 アルゴリズムは値 1 を処理して挿入しますが、右側に要素がないため寄与はゼロになります。 

次のような完全に減少する配列の場合`[3,2,1]`、すべての挿入は、以前に挿入されたすべての値が左側にある位置で行われるため、Fenwick クエリは常に右側の要素を返しません。 これにより、サブ配列がカウントされなくなります。 

次のような高度に交互に並ぶ順列の場合、`[2,1,4,3]`、各高低ペアは有効な右向き構成を 1 つだけ作成し、大きい値が処理される時点でそれぞれが 1 回だけカウントされ、寄与分と部分配列の間の 1 対 1 マッピングが確認されます。
