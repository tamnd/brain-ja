 ## 解決策
 ## 問題の理解

 セルの行が与えられ、各セルには値 0、1、または 2 が含まれています。すべてのセルはペイントされていない状態から始まり、目標はすべてのセルをペイントすることです。 

コインは 2 つの異なる方法で使用できます。 1 つ目は直接ペイントです。ペイントされていないセルを選択してペイントし、1 コインを支払います。 2 番目は伝播操作です。値が 1 または 2 のペイントされたセルがすでにある場合、それを使用して隣接するペイントされていないセルに「感染」し、その隣接セルを無料でペイントし、同時に元のペイントされたセルの値を 1 つ減らすことができます。 値 0 のセルを使用してさらに伝播することはできません。 

重要な緊張関係は、より高い値が近隣に塗料を拡散する可能性がある限られた「エネルギー源」のように機能し、コインを節約できる可能性があるということです。 この問題では、最終的に配列全体を描画するために必要なコインの最小数を求めます。 

n が 200,000 までの制約により、あらゆる解が線形または線形に近いものになります。 開始点のサブセットを試したり、O(n^2) で間隔 DP を試行したり、すべての伝播の選択肢を単純にシミュレートしたりすることを伴うものはすべて失敗します。 この構造は、各セルの値が少数回しか使用できず、伝播がローカルであることを示唆しています。そのため、ソリューションは貪欲またはスキャンベースのアカウンティングに帰着するはずです。 

微妙な障害モードは、伝播電力を過大評価することによって発生します。 たとえば、`[2,0,0]`、単一の 2 で両方の隣接をカバーできると考えがちですが、方向が重要です。伝播は順次であり、値を消費するため、順序が実現可能性を決定します。 もう 1 つの失敗例は、1 は 1 回しか役に立たず、2 は 2 回役立つことを無視して、ゼロ以外のすべてのセルを交換可能なソースとして扱うことです。 

## アプローチ

 このプロセスを強引に考える方法は、どのセルに最初にコインを支払うかを決定することです。 一部のセルがペイントされると、値が残っている限り外側に拡張できます。 初期コインペイントのすべてのサブセットを試して、伝播をシミュレートすることができます。 これは原理的には正しいです。すべての有効なプロセスは有料の開始点のセットから始まりますが、サブセットの数は n で指数関数的になるため、n が 200,000 まではこれが不可能になります。 

重要な観察は、伝播が常に隣接関係に沿って移動し、一度に 1 ステップずつ線形に値を消費することです。 これにより、プロセスは「ソース」からカバレッジ セグメントを構築するように動作します。 任意の最初のソースを選択する代わりに、左から右にスキャンして、支払いを強制されるタイミングを貪欲に決定できます。 

重要な洞察は、左側からの残りの伝播能力によって到達できない位置に遭遇したときは常に、そこで新しい有料セグメントを開始する必要があるということです。 次に、各有料セルは、その値に等しい右側への制限された量のリーチを提供し、現在のリーチがどこまで伸びるかを維持します。 

これにより、問題は、移動するカバレッジの境界を追跡し、その境界を何回リセットする必要があるかをカウントすることに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 初期ペイントセット + シミュレーションに対するブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 貪欲な左から右へのカバレッジ追跡 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 すでにアクティブ化された値を使用して、どこまで右まで無料でペイントできるかを表す変数を維持します。 また、スキャンしている現在の位置も維持します。 

1. 変数を初期化する`reach = 0`つまり、現時点では開始点とカウンターを超えてペイントを拡張することはできません。`coins = 0`。 
2. 配列を左から右に走査します。 各インデックスで`i`、どうかを確認してください`i`現在の到達可能な範囲内にあります`reach`。 
3. もし`i <= reach`、この位置は、以前の有料セルまたは伝播されたセルを介してすでに無料でペイントできるため、何もしません。 
4. もし`i > reach`、これまでの伝播では到達できない位置にいます。 このセルを直接ペイントするにはコインを支払わなければなりません。 支払い後、この細胞は新たな増殖源となるため、増加します。`coins`1までに。 
5. ポジションで支払いを行ったら`i`、設定しました`reach = i + a[i]`。 これは、この新しくアクティブ化されたセルからペイントを最大まで拡張できることを反映しています。`a[i]`steps to the right.
 6. 配列の最後まで続けます。 

重要な考え方は、以前の決定を決して再考しないということです。 現在の範囲から外れるたびに、新しい情報源を作成する必要があり、その情報源は使用可能な能力をすべて将来のポジションに提供します。 

### なぜ効果があるのか

 アルゴリズムは次の不変条件を維持します。`reach`は、以前に選択されたすべての支払済みセルとその残りの伝播力を使用して、追加のコインを支払わずにペイントできる最も遠いインデックスです。 この境界を超えるインデックスに遭遇すると、伝播は一度に 1 ステップずつしか移動せず、既にペイントされた正の値のセルからのみ開始されるため、以前の伝播ステップのシーケンスはそのインデックスに到達できません。 したがって、その時点で支払いを怠ると、その位置をペイントすることが不可能になるため、新たな有料ソースが必要になります。 最初の到達不能なインデックスで正確に支払うことを選択するのが最適です。これより後の選択では、現在のポジションが未描画のままになり、利点は得られません。また、それより前の選択では、すでに到達範囲内にあるか、以前のギャップのカバレッジが改善されないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    reach = 0
    coins = 0

    for i in range(n):
        if i > reach:
            coins += 1
            reach = i + a[i]
        else:
            reach = max(reach, i + a[i])

    print(coins)

if __name__ == "__main__":
    solve()
```このソリューションは、左から右に 1 回スキャンし、到達可能な最も遠いインデックスを維持します。 ポジションがその範囲外にある場合、コインの購入が強制され、そのポジションの値に基づいてリーチがリセットされます。 それ以外の場合、現在のセルがさらなる延長を提供する場合は、単純にリーチを更新します。 

微妙な点はアップデートです`reach = max(reach, i + a[i])`コインを使わない場合でも。 これは、すでに到達可能な位置が依然として伝播力に寄与しており、カバレッジをさらに拡大できることを示しています。

## テストケース```python
import sys, io

    sys.stdin = io.StringIO(inp)
    import sys
    from collections import deque

    coins = 0

 ## 特殊なケース

 重要なエッジケースは、最初の要素がゼロの場合です。 のような入力で`[0, 2, 0]`、アルゴリズムはインデックス 0 から始まり、次の値では到達不可能であることがわかります。`reach = 0`、すぐに支払わされることになります。 その後、リーチは後のセルをカバーできるほど遠くまでジャンプする可能性があります。 事前の伝播ソースがないため、インデックス 0 で支払うという貪欲な選択は避けられません。 

もう 1 つのエッジ ケースは、値の高い要素がゼロの長いプレフィックスの後に現れる場合です。 のために`[0, 0, 0, 2, 0]`、アルゴリズムはインデックス 0、1、2 で支払いを行い、最後にインデックス 3 を使用してリーチを拡張します。 アクティブなソースがないと伝播がゼロを横切ることができないため、各ゼロは個別のコインを強制します。 

3 番目のケースは、複数の小さな値が重なっている場合です。 で`[1, 0, 1, 0, 1]`、各 1 はリーチをわずかに拡張するだけであり、アルゴリズムにより、可能な限り以前のアクティベーションが再利用されることが保証されます。 スキャンにより、すでにカバーされている領域に対して二重に支払うことがないことが保証され、新しいコインはそれぞれ、以前は到達できなかったインデックスに正確に対応します。
