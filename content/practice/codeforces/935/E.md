 ## 解決策
 ## 問題の理解

 二分木のような形の完全に括弧で囲まれた算術式が与えられます。 すべての内部ノードは演算子であり、すべてのリーフは 1 つの数字です。 ただし、すべての演算子は消去され、プレースホルダーに置き換えられています。 また、元々存在していたプラス記号とマイナス記号の数も正確に知っており、最終的な評価値ができるだけ大きくなるように、これらの演算子をプレースホルダーに割り当てて式を復元することがタスクです。 

式の構造は括弧によって固定されているため、用語をどのようにグループ化するかは決定していません。 私たちは、葉が数字である二分木の各内部ノードにどの演算子ラベルを配置するかを決定しているだけです。 各内部ノードは、加算または減算を使用して 2 つの子の値を結合します。 減算は加算と同様に可換または単調ではないため、代入が異なると最終値が大幅に変化する可能性があります。 

式は非常に大きくなり、最大長は 10^4 になります。これは、ツリーに数千個のノードが含まれる可能性があることを意味します。 すべての演算子の割り当てを明示的に試行するソリューションでは、これらの内部ノード上に P プラスと M マイナスを配置するあらゆる方法を検討する必要がありますが、これは組み合わせによって増大し、演算子が数十個になるずっと前に実行不可能になります。 

部分式が減算を通じて相互作用する場合、微妙な問題が発生します。 「最も役立つ場所に常にプラスを配置する」などの貪欲なローカル決定は失敗します。ローカルで有益に見えるノードが、他の場所でマイナス配置から恩恵を受ける上位ノードの能力を低下させる可能性があるためです。 もう 1 つの失敗モードは、式をフラットまたは無視した構造として扱うことです。たとえば、すべての葉の和を計算してから独立して符号を割り当てます。これは、減算がサブツリーの値に依存するため機能しません。 

正しいソリューションはツリー構造を尊重し、同時にプラス演算子とマイナス演算子の限られたグローバル バジェットを考慮する必要があります。 

## アプローチ

 演算子の数に関する制約を無視すると、各内部ノードは加算と減算のどちらかを個別に選択し、すべての割り当てを探索することで最良の結果を評価できます。 これにより、2 つの選択肢を使用してすべての内部ノードに対して総当たり再帰が行われます。 k 個の演算子を使用すると、すでに 2^k 個の可能性が得られます。 k は最大 10^4 であるため、このアプローチは完全に不可能です。 

主な問題は、各サブツリーが単一の固定値を持たないことです。 その代わり、その寄与は、ツリーの残りの部分でまだ使用可能なプラス演算子とマイナス演算子がいくつあるかによって決まります。 これは、各サブツリーが 1 つの値だけを返すのではなく、その内部の指定された数のプラス代入を使用して達成できるすべての可能な値の記述を返す必要があることを示唆しています。 

これは自然にツリー動的プログラミングにつながります。 各ノードについて、関数 dp[v][p] を計算します。これは、v をルートとするサブツリー内で正確に p 個のプラス記号を使用した場合に達成可能な最大値を意味します。 マイナス記号の数は、サブツリーのサイズから暗黙的に決定されます。 

この観点に移ると、各内部ノードは 2 つの子 DP テーブルの畳み込みになります。 左右のサブツリーを結合するノードの場合、利用可能なプラスの数をそれらの間で分割し、加算または減算を使用して結果を結合します。 最終的な答えは、正確に P​​ プラス記号を使用したルートの最良の値です。 

これが機能するのは、ツリー構造によって部分問題が明確に分離されるためです。 各サブツリーは、親での予算分割を除いて独立しており、制約は十分に小さいため (P ≤ 100)、DP テーブルは管理可能なままです。

 ## アルゴリズムのチュートリアル

まず、完全に括弧で囲まれた式から暗黙的な二分木を再構築します。 すべての数字がリーフ ノードになり、すべての括弧のペアが 2 つの子を持つ内部ノードに対応します。 プレースホルダーは構造的には重要ではありません。 演算子が挿入される場所をマークするだけです。 

ツリーが構築されたら、事後動的プログラミング トラバーサルを実行します。 

1. すべてのリーフ ノードについて、p = 0 を除くすべての p に対して dp[p] を無効として定義します。ここで、dp[0] は数字の値に等しいです。 リーフには演算子が含まれていないため、プラスの代入は行われません。 
2. すべての内部ノードについて、その左右の子に基づいて 2 つの一時的な DP 配列を計算します。 左側の子が dpL を持ち、右側の子が dpR を持っているとします。 
3. このサブツリー内に割り当てられたプラス演算子の総数を左と右に分割することを検討します。 pL + pR = p となるすべての可能な pL と pR について、2 つのサブツリーを結合します。 
4. このノードで結果を結合するには 2 つの方法があります。 演算子がプラスの場合、値は dpL[pL] + dpR[pR] になります。 演算子がマイナスの場合、値は dpL[pL] - dpR[pR] となります。 
5. このノードでは演算子を自由に選択できるため、各 p について両方の選択肢の最大値を取得します。 
6. P までのすべての有効な p に対して dp[p] を埋め、このテーブルを上方向に伝播します。 

合計でちょうど P 個のプラス記号を使用する必要があるため、根本的な答えは dp[P] です。 

### なぜ効果があるのか

 各 dp テーブルは、プラス演算子の固定割り当ての下でサブツリーに対して達成可能な最良の値を表します。 重要な不変条件は、すべてのサブツリーとすべての有効な p について、dp[p] は、正確に p 個のプラス記号を使用する、そのサブツリー内の演算子のすべての有効な割り当ての中で最適な値を格納することです。 2 つのサブツリーを結合する場合、すべての有効なグローバル割り当ては、子間のプラス カウントの 1 つの分割に正確に対応し、遷移はそのようなすべての分割をチェックします。 減算と加算は各内部ノードで明示的に処理されるため、相互作用が失われることはなく、考えられるすべての有効なグローバル構成が DP 状態空間で 1 回だけ表現されます。

        else:

def dfs(node, P):
    if node.val is not None:
        dp = [-10**18] * (P + 1)
        dp[0] = node.val
        return dp

    left_dp = dfs(node.left, P)
    right_dp = dfs(node.right, P)

    dp = [-10**18] * (P + 1)

    for p in range(P + 1):
        best = -10**18
        for pl in range(p + 1):
            pr = p - pl
            if left_dp[pl] < -10**17 or right_dp[pr] < -10**17:
                continue
            best = max(best, left_dp[pl] + right_dp[pr])
            best = max(best, left_dp[pl] - right_dp[pr])
        dp[p] = best

    return dp

DFS は各ノードの DP 配列を返します。 リーフ ノードはゼロプラス状態のみを初期化します。 内部ノードは、プラス バジェットのすべての可能な分割を反復して子 DP テーブルをマージし、分割ごとに両方の演算子の選択を評価します。 大きなネガティブセンチネルは、ありえない状態をきれいに処理します。 

最終的な答えは、正確に P​​ プラス記号を使用してルートから抽出されます。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    sys.setrecursionlimit(10**7)

    class Node:
        def __init__(self):
            self.left = None
            self.right = None
            self.val = None

    def build(s):
        stack = []
        for ch in s.strip():
            if ch == '(':
                continue
            if ch == ')':
                r = stack.pop()
                stack.pop()  # placeholder
                l = stack.pop()
                node = Node()
                node.left = l
                node.right = r
                stack.append(node)
            elif ch.isdigit():
                node = Node()
                node.val = int(ch)
                stack.append(node)
            else:
                stack.append(None)
        return stack[0]

    def dfs(node, P):
        if node.val is not None:
            dp = [-10**18] * (P + 1)
            dp[0] = node.val
            return dp

        L = dfs(node.left, P)
        R = dfs(node.right, P)
        dp = [-10**18] * (P + 1)

        for p in range(P + 1):
            best = -10**18
            for pl in range(p + 1):
                pr = p - pl
                best = max(best, L[pl] + R[pr], L[pl] - R[pr])
            dp[p] = best

        return dp

    s = input().strip()
    P, M = map(int, input().split())
    root = build(s)
    return str(dfs(root, P)[P])

 ## 特殊なケース

 すべての演算子がマイナスの場合、1 つの特殊なケースが発生します。 プラス記号が使用されていない場合でも、DP は有効な構成を許可する必要があります。 のような入力の場合`(1?(2?3))`と`P = 0`、アルゴリズムはすべてのノードに減算の組み合わせのみを評価するように強制し、DP は無効な状態を必要とせずに負の寄与を上方に正しく伝播します。 

もう 1 つのケースは、すべての演算子がプラスの場合です。 サブツリー内の中間的な減算は最適な構成には存在しないため、構造は依然として重要ですが、DP フレームワークは依然としてそれらを評価し、自然にオールプラスの組み合わせのみを選択します。 

より深い構造のエッジケースは、サブツリーに多くのノードが含まれているにもかかわらず、ゼロプラスバジェットを受け取る場合に発生します。 その状況では、そのサブツリー内のすべての内部ノードは減算を解決する必要があり、DP はサブツリー全体をその制約に対する 1 つの最悪の場合の評価に正しく圧縮し、ツリー内で上位の兄弟とマージしたときの一貫性を確保します。
