 ## 解決策
 ## 問題の理解

 問題は、ファファが一連の動きに従ってグリッドに沿って歩いているときに、2つの王国の間の壁を越えた回数を数えるというものです。 壁は _x = y_ の線に沿っており、その線に沿ったすべての整数座標にゲートがあります。 最初の王国は壁の下の点 (_y < x_) を占め、2 番目の王国は壁の上の点 (_y > x_) を占め、門自体は中立です。 ファファは門を通ってある王国から別の王国に渡るたびに、コインを支払います。 彼はゲートである (0,0) から開始し、そこでは支払いをしません。 入力では、移動数 _n_ と、「R」(右) 移動と「U」(上) 移動で構成される長さ _n_ の文字列を指定します。 

重要なタスクは、このシーケンスに従って Fafa が支払わなければならないコインの数を決定することです。 課題は、ファファの位置を追跡するだけではなく、彼がゲートである王国から別の王国に渡ったときを、必要以上の料金を支払うことなく検出することです。 

_n_ が最大 10^5 の場合、グリッド内のすべての点を反復する解法は遅すぎます。 1 移動あたり 10^5 の演算は許容されますが、2 次以上の複雑さは 2 秒の制限を超えるため、解はおよそ O(n) 時間で実行される必要があります。 エッジ ケースには、完全に片側に残るシーケンス、壁にぴったりとくっつくシーケンス、または対角線に沿って余分な動きをせずに繰り返し交差するシーケンスが含まれます。 

たとえば、_S = "UUU"_ の場合、ファファは決して右に移動せず、壁を越えることはありません。 正しい出力は 0 です。移動方向を考慮せずにすべてのゲートをチェックする単純なアプローチでは、交差していないコインを誤ってカウントする可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、グリッド上でファファの経路をシミュレートし、各ステップにマークを付け、動きが壁を越えるかどうかを確認します。 これは概念的には正しいです。ステップごとに、ファファの新しい位置を計算し、現在の王国を決定し、それを前の王国と比較します。 ゲートにいる間に王国が変化した場合、コインの数が増加します。 問題は、移動するたびに王国をチェックするのは簡単ですが、長いシーケンスでは、パスに沿ったすべてのゲートもチェックしたり、距離を再計算したりする単純なシミュレーションでは遅すぎることです。 

重要な洞察は、ファファが門で壁を越えて実際に王国を変えたときにのみ支払う必要があるということです。 ゲートは _x = y_ 上にあるため、支払いが可能な位置は _x = y_ の点だけです。 したがって、対角線に沿って Fafa の位置を追跡できます。_r_ を右への移動の数、_u_ を上への移動の数とします。 ファファが _r = u_ のいずれかのゲートに到達し、以前の移動とは異なる王国に移動しようとしているときにコインの数が増加します。 これにより、問題は単純なカウンターを使用した単一のリニア スキャンに軽減されます。 

右と上の移動のカウントを維持し、_r = u_ の位置のみをチェックすることで、すべてのグリッド セルを明示的にシミュレートすることなく、Fafa がいつ王国を切り替えるかを判断できます。 これにより、O(1) 個の追加スペースを持つ線形 O(n) 解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (グリッド シミュレーション) | O(n) | お(1) | 受け入れられますが、単純なチェックは過剰である可能性があります。 
| 最適 (トラック r、u、およびゲート) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`r = 0`そして`u = 0`ファファの現在の座標を表すため、そして`coins = 0`支払いを蓄積するため。 フラグも初期化する`last_side`ファファが現在の移動前にどの王国にいたかを追跡します。 
2. シーケンス内の各動きを反復します。`S`。 移動が「R」の場合、インクリメントします`r`。 移動が「U」の場合、インクリメントします`u`。 これにより、グリッド上のファファの位置が更新されます。 
3. 移動するたびに、ファファがゲートにいるかどうかを確認します。`r == u`。 ゲートは対角線に沿ってのみ存在し、コインの支払いはこの点でのみ可能です。 
4. ゲートにいる場合は、ファファが前のステップと次のステップでどちらの王国に入るかを決定します。 具体的には、`r > u`, ファファは壁の下にいます。 もし`r < u`, ファファは壁の上にいます。 の`last_side`変数は前の面を記録します。 
5. ファファが門にいる場合、`last_side`現在の側と異なる、増分`coins`1 までに更新してください`last_side`現在の側へ。 これは正当な壁の横断を捉えています。 
6. すべての動きが処理されるまで続行します。 出力`coins`。 

**それが機能する理由:** 不変条件は次のとおりです。`coins`ファファが門の壁を越えたときに正確に増加します。 ゲートは対角線に沿ってのみ存在するため、この対角線の外側に移動するとコインの支払いが発生する可能性があります。 トラッキング`last_side`対角線に沿った複数の連続移動によって余分なコインが誤ってカウントされないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
S = input().strip()

r = u = coins = 0
last_side = 0  # 0: start, 1: below wall, 2: above wall

for move in S:
    if move == 'R':
        r += 1
    else:
        u += 1
    
    if r == u:
        if r > 0:
            if last_side == 0:
                # Determine first side
                last_side = 1 if r > u else 2
            else:
                # Current side after move
                side = 1 if r > u else 2
                if side != last_side:
                    coins += 1
                    last_side = side

print(coins)
```このソリューションでは、まず移動に応じて座標を更新し、ゲートを確認してから、王国を比較します。`last_side`対角線に沿った複数のステップで王国が変わらない場合の二重カウントを防ぎます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    S = input().strip()
    r = u = coins = 0
    last_side = 0
    for move in S:
        if move == 'R':
            r += 1
        else:
            u += 1
        if r == u and r > 0:
            side = 1 if r > u else 2
            if last_side != 0 and side != last_side:
                coins += 1
            last_side = side if last_side == 0 else side
    return str(coins)

# Provided samples
assert run("1\nU\n") == "0", "sample 1"

# Custom cases
assert run("3\nUUU\n") == "0", "all up, never cross"
assert run("4\nRRUU\n") == "1", "cross once at (2,2)"
assert run("6\nRUURUU\n") == "2", "cross at (1,1) and (2,2)"
assert run("1\nR\n") == "0", "single right, no cross"
assert run("2\nRU\n") == "1", "cross at (1,1)"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3\nううう | 0 | 一つの王国だけを移動し、決して越えることはありません |
 | 4\nるう | 1 | 壁を一度だけ越える |
 | 6\nルウルウ | 2 | 複数の交差、last_side ロジックを確認 |
 | 1\nR | 0 | 最小入力、交差なし |
 | 2\nRU | 1 | 最初のゲートを通過 |
