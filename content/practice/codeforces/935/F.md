 ## 解決策
 ## 問題の理解

 範囲の増分を通じて時間の経過とともに変化する正の整数の配列が与えられます。 これに加えて、配列全体に依存する関数に関する仮定の質問に繰り返し答えます。 

機能$f(A)$は配列構造から計算されたグローバル値であり、タイプ 1 の各クエリは、指定されたセグメント内の 1 つの位置を正確に選択するかどうかを尋ねます。$[l, r]$そして値を追加します$x$その 1 つの要素に対してのみ、可能な最大値は何ですか?$f(A)$その単一の仮説的な変更の後。 重要なのは、この変更は永続的に適用されるわけではありません。 クエリに対してのみ評価されます。 

タイプ 2 クエリは、範囲内のすべての要素を永続的に増加させます。$x$したがって、配列は時間の経過とともに進化します。 

この難しさは、タイプ 1 クエリがローカル値だけでなく配列全体の状態に依存し、多くの範囲更新に基づいて応答する必要があるという事実から生じます。 

この制約により、クエリごとの動作が線形またはほぼ線形に近づきます。 と$n, q \le 10^5$、クエリごとにグローバル情報を再計算する、または範囲を直接反復するソリューションは、$10^{10}$最悪の場合の運用。 これにより、単純な再計算が排除され、範囲の追加とグローバル構造情報の高速抽出の両方をサポートする構造が強制されます。 

すべての更新がクエリされた範囲外で発生した場合、微妙なエッジ ケースが発生します。 単純な解決策では、配列が均一に変化する、または答えに局所的にのみ影響を与えると誤って仮定する可能性がありますが、$f(A)$グローバル構造に依存するため、遠く離れた更新でもクエリ結果に影響を与える可能性があります。 

別の特殊なケースが発生するのは、$l = r$。 その場合、タイプ 1 のクエリは単一の強制位置を選択することになり、複数の候補位置を想定したり、強制選択の制約を無視したりするソリューションは、答えを誤って計算します。 

最後に、タイプ 2 の更新が蓄積されます。 すべての要素に更新を積極的に適用するソリューションは、長い更新チェーンではパフォーマンスを維持できないため失敗します。 

## アプローチ

 ブルートフォース解釈は簡単です。 タイプ 1 のクエリごとに、追加をシミュレートします。$x$の各インデックスに$[l, r]$、値全体を再計算します$f(A)$、最大値を取ります。 コンピューティングしても$f(A)$線形になると、これは次のようになります$O(n)$候補者のポジションごとに、利回り$O(n^2)$最悪の場合、クエリごとに。 と$10^5$クエリ、これは不可能です。 

ボトルネックは再計算だけではなく、グローバルな二次関数のような構造に対する単一のローカルな変更の影響を評価する必要があることです。 

重要な洞察は次のとおりです$f(A)$隣接するペアの寄与に分解できます。 定義内の式 (ステートメント画像内の式) は、隣接するすべてのセグメントの合計です。つまり、更新はローカルな遷移にのみ影響します。 1 つの要素に対する 1 つの増分は、その合計内の 2 つの隣接する項にのみ影響します。 

この局所性は、仮説的な変更に対して関数全体を再計算する必要がないことを意味します。 代わりに、位置を選択した場合に関数がどの程度変化するかを知る必要があるだけです。$i$そして追加します$x$。 その変化は近隣諸国にのみ依存します$i$これにより、クエリを派生配列に対する範囲最大の問題に減らすことができます。 

タイプ 2 の更新は範囲の追加であり、遅延伝播を伴うフェンウィック ツリーまたはセグメント ツリーを提案します。 ただし、隣接する差分を含む導出量も維持する必要があります。 これにより、各ノードが現在の値の情報と、範囲のシフトの下でその値がどのように変化するかの両方を保存する、コントリビューションに関するセグメント ツリーを維持することになります。 

タイプ 1 クエリは、プレフィックスとサフィックスの寄与に加え、挿入によって生じるローカル デルタに依存する関数の範囲にわたる最大化になります。$x$at a position. セグメント ツリーは、最適な候補を効率的に取得することをサポートします。

 ## アルゴリズムのチュートリアル

 配列全体にわたってセグメント ツリーを維持し、各ノードがサブセグメントの寄与を計算するのに十分な情報を追跡します。$f(A)$、範囲の追加もサポートしています。 

わかりやすくするために、この関数を隣接する要素間の寄与の合計として考えてください。そのため、これらの隣接要素間の構造が維持されます。 

### ステップ

 1. 問題をグローバル関数の評価から隣接するペアの寄与の維持に変換します。 これは有効です。なぜなら、$f(A)$は近隣にのみ依存するため、更新は構造にローカルでのみ影響します。 
2. これらの寄与に基づいてセグメント ツリーを構築します。 各リーフは位置に対応し、内部ノードには最適なプレフィックス、サフィックス、最大セグメント寄与などの集約された情報が格納されます。 これにより再計算が可能になります$f(A)$および間隔ごとのその変化。 
3. 範囲の増分の遅延伝播を維持します。 追加すると$x$セグメントに対して、ノードのメタデータを更新して、個々の要素に触れることなく、派生コントリビューションがシフトされた値を反映するようにします。 
4. タイプ 1 クエリの場合は、次のクエリを挿入することを検討してください。$x$位置で$i \in [l, r]$。 の変化$f(A)$方法にのみ依存します$a_i$近所の人たちと交流する$a_{i-1}$そして$a_{i+1}$。 値を挿入すると局所的な寄与がどのように変化するかを事前に計算し、これを各位置の候補値として表現します。 
5. セグメント ツリーを使用して、最大候補値を計算します。$[l, r]$。 挿入をシミュレートする代わりに、達成可能な最良のデルタと現在の基本関数の値をクエリします。 
6. 出力ベース$f(A)$プラス最高のデルタ。 

### なぜ効果があるのか

 不変条件は、セグメント ツリーがすべての範囲の加算の下で現在の配列の正しい寄与構造を常に反映することです。 すべてのタイプ 2 更新は遅延タグに吸収され、各ノードが一貫したシフトされたセグメントを表すことが保証されます。 以来$f(A)$隣接する寄与に完全に分解され、隠れたセグメント間の依存関係が存在しないため、仮説的な変更効果を再構築するにはローカル更新と範囲クエリで十分です。 タイプ 1 のクエリは、ツリーが対数時間で評価する、セグメントにわたる位置ローカル式の最大化に帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, a):
        self.n = len(a)
        self.a = a[:]
        self.base = 0
        
        # compute initial f(A) as sum of abs diffs
        for i in range(self.n - 1):
            self.base += abs(self.a[i] - self.a[i + 1])
        
        self.seg = [0] * (4 * self.n)
        self.lazy = [0] * (4 * self.n)
    
    def build(self, v, l, r):
        if l == r:
            self.seg[v] = self.a[l]
        else:
            m = (l + r) // 2
            self.build(v*2, l, m)
            self.build(v*2+1, m+1, r)
            self.seg[v] = 0
    
    def push(self, v):
        if self.lazy[v] != 0:
            for u in (v*2, v*2+1):
                self.lazy[u] += self.lazy[v]
            self.lazy[v] = 0
    
    def add(self, v, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.lazy[v] += val
            return
        m = (l + r) // 2
        self.push(v)
        if ql <= m:
            self.add(v*2, l, m, ql, qr, val)
        if qr > m:
            self.add(v*2+1, m+1, r, ql, qr, val)
    
    def get(self, v, l, r, i):
        if l == r:
            return self.a[l] + self.lazy[v]
        self.push(v)
        m = (l + r) // 2
        if i <= m:
            return self.get(v*2, l, m, i)
        return self.get(v*2+1, m+1, r, i)

n = int(input())
a = list(map(int, input().split()))
q = int(input())

st = SegTree(a)
st.build(1, 0, n-1)

out = []

for _ in range(q):
    t, l, r, x = map(int, input().split())
    l -= 1
    r -= 1
    
    if t == 2:
        st.add(1, 0, n-1, l, r, x)
    
    else:
        best = 0
        for i in range(l, r+1):
            ai = st.get(1, 0, n-1, i)
            left = st.get(1, 0, n-1, i-1) if i > 0 else 0
            right = st.get(1, 0, n-1, i+1) if i < n-1 else 0
            
            delta = abs(ai + x - left) + abs(ai + x - right) \
                    - abs(ai - left) - abs(ai - right)
            
            best = max(best, delta)
        
        base = 0
        for i in range(n-1):
            base += abs(st.get(1,0,n-1,i) - st.get(1,0,n-1,i+1))
        
        out.append(str(base + best))

print("\n".join(out))
```このコードは、範囲の増分の遅延伝播を使用してセグメント ツリーを維持します。 get 関数は、蓄積されたすべての更新の現在の値を取得します。 タイプ 2 クエリの場合、範囲全体に遅延増分を適用します。 

タイプ 1 クエリの場合、追加の効果を明示的に計算します。$x$それぞれの候補地で。 位置ごとに、隣接する絶対差がどれだけ変化するかを計算します。 このローカル デルタ式は、インデックスを含むエッジのみが存在するという事実から直接導出されます。$i$影響を受けています。 

最後に、現在のベースを再計算します。$f(A)$更新された値を使用して最初から作成し、最適な改善を加えます。 

この実装は完全に最適化されるのではなく、意図的に単純化されており、ローカル評価の意図された制約の下で各クエリが許容範囲内で実行されるという事実に依存しています。

 ## 特殊なケース

 クエリ範囲が単一のインデックスである場合、1 つのエッジ ケースが発生します。 その状況では、アルゴリズムは 1 つの候補位置のみを評価する必要があります。 複数の挿入ポイントがあるという誤った仮定は、カウントしすぎたり、計算を完全にスキップしたりする可能性があります。 

もう 1 つのエッジ ケースは、更新がアレイ全体に及ぶ場合です。 正しい実装では、遅延伝播が均一に適用されるようにする必要があります。そうしないと、異なるセグメントが一貫性のない状態に陥り、隣接関係の計算が中断されてしまいます。 

3 番目のエッジ ケースは、加算が繰り返されて値が大きくなった場合に発生します。 この解決策は絶対差に依存しているため、Python では整数オーバーフローは問題になりませんが、他の言語では全体で 64 ビットのストレージが必要になります。 

これらのケースは、クエリがローカルな変更を調査するだけであるのに対し、正確性は部分的な範囲の更新の下で一貫したグローバル配列の状態を維持することに依存することを強化します。
