 ## 解決策
 ## 問題の理解

 グラスは100個までございます。 ガラス`i`保持できる`a_i`水の単位と現在含まれている水`b_i`単位。 

グラスの間で水を移動することは許可されています。 問題は、送金するたびに送金額の半分が失われることです。 注ぐなら`x`ガラスから取り出したユニットのみ`x/2`ユニットは目的地に到達できる可能性があります。 宛先の容量を超えた超過分も同様に失われます。 

あらゆる人にとって`k`から`1`に`n`、正確に選択する必要があります`k`一連の移送を実行した後に、選択したグラス内に最終的に入る可能性のある水の量を最大化します。 

それぞれの答えは`k`あるセット内に確保できる最大総水量です。`k`眼鏡。 

制約は、意図した解決策への最初の手掛かりです。 ガラスは 100 個しかなく、すべての容量と初期量は最大 100 です。合計容量は最大 10000、合計水も最大 10000 です。これは、容量の合計によってインデックス付けされた動的プログラミング状態には十分小さいですが、ガラスのサブセットを列挙するには大きすぎます。`2^100`可能性は完全に不可能です。 

問題の微妙な部分は、転送によって実際に何が達成できるのかを理解することです。 

メガネの選択を検討してください`S`。 

させて

-`A = Σ a_i`メガネの上から`S`-`B = Σ b_i`メガネの上から`S`-`T = Σ b_i`すべてのメガネの上に

 選択したメガネにはすでに含まれています`B`水の単位。 セットの外には、`T - B`単位。 

外部から入ってくる水は、選択されたセットに到達する前に 50% の損失を受けます。 したがって、すべて外部の水を使用したとしても、せいぜい`(T - B)/2`追加のユニットを選択したガラスに組み込むことができます。 

同時に、選択したグラスには総容量を超えるものを収納することはできません。`A`。 

したがって、この選択されたセット内で達成可能な水の量は次のようになります。$$\min\left(A,\; B + \frac{T-B}{2}\right)$$不用意なアプローチは、これら 2 つの制限のいずれかを見逃すことがよくあります。 

例えば：```
2
100 0
1 1
```のために`k=1`, 最初のグラスを選択すると容量が100になりますが、世界的には1ユニットのみ存在します。 流出後はせいぜい0.5が到達するので、答えは100ではなく0.5になります。 

逆に:```
2
5 5
100 100
```最初のグラスのみを選択すると、$$\min(5,\;5+100/2)=5$$容量制限が優先されます。 

問題全体は、あらゆるものを見つけることになります。`k`、その式を最大化するサブセット。 

## アプローチ

 ブルートフォースソリューションでは、ガラスのすべてのサブセットを列挙します。 サブセットごとに、その合計容量を計算します。`A`、その最初の水`B`、評価します$$\min\left(A,\; B+\frac{T-B}{2}\right).$$この式はそのサブセットの達成可能な量を完全に特徴づけているため、これは正しいです。 

問題はサブセットの数です。 と`n = 100`、 がある`2^{100}`その可能性は天文学的に大きい。 

重要な観察は、サブセットの値は次の 2 つの集合量にのみ依存するということです。$$A=\sum a_i,\qquad B=\sum b_i.$$これらの合計が判明すると、個人の身元はもはや重要ではなくなります。 

総容量は最大でも$$100 \cdot 100 = 10000.$$これは、すべてのサブセット サイズとすべての容量合計について、取得可能な最大値を追跡するナップザック スタイルの動的プログラミングを示唆しています。`B`。 

各ペアについて、わかっているとします。`(k, A)`、可能な最大値`B`サイズのサブセット間で`k`その容量の合計は`A`。 

その状態に対する答えは単純です。$$\min\left(A,\; \frac{T+B}{2}\right),$$なぜなら$$B+\frac{T-B}{2} = \frac{T+B}{2}.$$固定用`(k, A)`、より大きい`B`常に大きな目標が得られるため、最大値のみを保存します`B`で十分です。 

これにより、問題は、選択されたグラスの数と総容量という 2 つの次元を持つ古典的な 0/1 ナップザックに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース |$O(2^n)$|$O(1)$| 遅すぎる |
 | 最適なDP |$O(n^2 \cdot \sum a_i)$|$O(n \cdot \sum a_i)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのグラスを読み取り、水の総量を計算します。$$T=\sum b_i.$$2. しましょう`MAXA = Σ a_i`。 
3. DP テーブルを作成します。$$dp[j][s]$$最大総初期水を貯蔵します`B`正確に選択することで取得可能`j`容量の合計が`s`。 

到達不能な状態は次のように初期化されます。`-1`。 
4.セット$$dp[0][0]=0.$$5. ガラスを1枚ずつ加工します。 

グラス用`(a,b)`、反復します`j`そして`s`降順で、標準の 0/1 ナップサック遷移を実行します。$$dp[j+1][s+a] = \max(dp[j+1][s+a],\, dp[j][s]+b).$$降順反復により、同じガラスを複数回使用することができなくなります。 
6. すべてのガラスが処理された後、すべてのガラスの答えを計算します。`k`。 
7. 到達可能なすべての状態について`(k,s)`保存された値を使用して`B`、 評価する$$\min\left(s,\frac{T+B}{2}\right).$$これは、その特定の骨材ペアで達成可能な最大水量です。`(A=s,B)`。 
8. 同じに属するすべての状態の最大値を取得します。`k`。 
9. すべての回答を十分な精度で出力します。 

### なぜ効果があるのか

 選択したメガネのセットを修正します。 

させて`A`合計容量であり、`B`彼らの最初の水。 残ったグラスには以下が入っています`T-B`単位。 

外部から到着するすべてのユニットは少なくとも 1 回は転送する必要があるため、外部の水の最大半分が選択したセット内に到達する可能性があります。 したがって、選択したグラスに集められる水の総量は最大でも$$B+\frac{T-B}{2} = \frac{T+B}{2}.$$選択したグラスには、合計容量を超えるものを入れることはできません`A`。 したがって、これを超える戦略は存在しません$$\min\left(A,\frac{T+B}{2}\right).$$この限界は達成可能です。 選択したセット内にすべての水をすでに入れておきます。 必要に応じて、外部の水を選択したセットに移します。 最大半分の外部水を供給でき、容量に達したらプロセスを停止できます`A`に達します。 したがって、そのサブセットの正確な最適値は次のようになります。$$\min\left(A,\frac{T+B}{2}\right).$$DP は考えられるすべてのペアを列挙します`(A,B)`サイズのサブセットによって達成可能`k`。 各容量合計について`A`、可能な限り最大のものを保存します`B`目的は次のように単調増加するため、これで十分です。`B`。 したがって、それぞれについて計算される最大値は、`k`まさに全体最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    glasses = []
    total_water = 0
    total_capacity = 0

    for _ in range(n):
        a, b = map(int, input().split())
        glasses.append((a, b))
        total_water += b
        total_capacity += a

    dp = [[-1] * (total_capacity + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    current_capacity_sum = 0

    for a, b in glasses:
        for cnt in range(n - 1, -1, -1):
            for cap in range(current_capacity_sum, -1, -1):
                if dp[cnt][cap] == -1:
                    continue

                nxt_cap = cap + a
                nxt_water = dp[cnt][cap] + b

                if nxt_water > dp[cnt + 1][nxt_cap]:
                    dp[cnt + 1][nxt_cap] = nxt_water

        current_capacity_sum += a

    ans = [0.0] * (n + 1)

    for k in range(1, n + 1):
        best = 0.0

        for cap in range(total_capacity + 1):
            inside_water = dp[k][cap]
            if inside_water == -1:
                continue

            value = min(float(cap), (total_water + inside_water) / 2.0)
            if value > best:
                best = value

        ans[k] = best

    print(*("{:.10f}".format(x) for x in ans[1:]))

if __name__ == "__main__":
    solve()
```DP テーブルはソリューションの中心です。`dp[k][cap]`答えを直接保存しません。 代わりに、サイズのすべてのサブセットの中で、最初に存在する可能な最大量の水を貯蔵します。`k`その容量の合計は`cap`。 

この選択により、状態空間が管理可能になります。 容量の合計は最大 10,000 までしかないため、DP 全体には約 100 万の州が含まれます。 

下りループは必須です。 容量が昇順に処理されると、同じ反復内でガラスが複数回再利用され、遷移が無制限のナップザックになり、誤った結果が生成される可能性があります。 

ナップザックが終了した後、到達可能な各状態はいくつかのサブセット集合体に対応します`(A,B)`。 式$$\min\left(A,\frac{T+B}{2}\right)$$は直接評価され、各サブセット サイズの最適な値が保持されます。 

すべての合計は最大 10000 であるため、整数オーバーフローの懸念はありません。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())

    glasses = []
    total_water = 0
    total_capacity = 0

    for _ in range(n):
        a, b = map(int, input().split())
        glasses.append((a, b))
        total_water += b
        total_capacity += a

    dp = [[-1] * (total_capacity + 1) for _ in range(n + 1)]
    dp[0][0] = 0

    cur = 0

    for a, b in glasses:
        for k in range(n - 1, -1, -1):
            for s in range(cur, -1, -1):
                if dp[k][s] == -1:
                    continue
                dp[k + 1][s + a] = max(
                    dp[k + 1][s + a],
                    dp[k][s] + b
                )
        cur += a

            best = max(best, min(float(s), (total_water + B) / 2.0))
        ans.append(f"{best:.10f}")

    return " ".join(ans) + "\n"

 ## 特殊なケース

 次のことを考慮してください。```
2
100 0
1 1
```のために`k=1`、大きなグラスを選択すると、`A=100`、`B=0`。 アルゴリズムが評価するのは、$$\min(100,(1+0)/2)=0.5.$$小さなグラスを選ぶと、$$\min(1,(1+1)/2)=1.$$DP は両方の状態を保持し、正しい方の大きい値を返します。 

ここで次のことを考えてみましょう。```
2
5 5
100 100
```最初のガラスのみを選択すると、$$A=5,\quad B=5.$$式は次のようになります$$\min(5,(105)/2)=5.$$たとえ巨大な水が他の場所に存在しても、選択されたガラスはその容量を超えることはできません。 アルゴリズムはこれを自動的に実行します。`min`。 

ついに：```
3
10 0
10 0
10 0
```すべての州が持っています`B=0`そして総水分量`T=0`。 すべての評価はゼロになるので、すべての答えはちょうどゼロになります。 DP は、最初は水を含まないグラスを正しく処理します。`0`到達不可能な状態と混同されるのではなく、有効な到達可能な水の合計として保存されます。
