 ## 解決策
 ## 問題の理解

 まずは、\(n \times n\)ラテン広場。 すべての行は以下の順列です\(1 \ldots n\)、すべての列も次の順列です。\(1 \ldots n\)。 

一連の操作により行列が変更されます。 4 つの演算により、行または列の巡回シフトが実行されます。 他の 2 つの操作はさらに特殊です。\(I\)すべての行の置換をその逆順に置き換えます。\(C\)すべての列の置換をその逆順に置き換えます。 

すべての演算の後、結果の行列を出力する必要があります。 

最初の観察は制約から生じます。 すべての合計\(n\)せいぜい\(1000\)したがって、最終的な行列の出力には、テスト ケースごとにすでに \(O(n^2)\) のコストがかかります。 その部分は避けられません。 本当の課題は操作文字列であり、その合計の長さは次のようになります。\(10^5\)。 

単純なシミュレーションでは、すべての演算が行列に直接適用されます。 それぞれの操作でタッチする\(n^2\)したがって、最悪のケースは次のようになります。$$
O(mn^2).
$$と\(m=10^5\)そして\(n=1000\)、これはまったく不可能です。 

問題は、強力な代数構造が隠されていることです。 ラテン方陣セルには当然 3 つの座標が含まれます。$$
(\text{row}, \text{column}, \text{value}).
$$6 つの操作は、これら 3 つの座標をさまざまな方法で並べ替えるだけなので、ラテン平方の性質を破壊することはありません。 

### 明らかではないエッジケース

 検討してください\(n=3\)そして操作\(I\)。$$
\begin{matrix}
1&2&3\\
2&3&1\\
3&1&2
\end{matrix}
$$不用意に実装すると、各行を個別に反転しようとする可能性があります。 それは機能しますが、より深い構造が欠けています。 逆行列の後、行列は次のようになります。$$
\begin{matrix}
1&2&3\\
3&1&2\\
2&3&1
\end{matrix}
$$これはまさに、列のインデックスと値の役割が交換された場合に起こることです。 この座標の解釈が最適解の鍵となります。 

運用を検討する\(C\)同じマトリックス上にあります。 

結果は$$
\begin{matrix}
1&3&2\\
2&1&3\\
3&2&1
\end{matrix}
$$これは行反転ではありません。 行のインデックスと値を交換します。 これら 2 つの変換を混同すると、有効なラテン方乗のように見える間違った答えが生成されます。 

多くのシフトが累積すると、別の微妙なケースが発生します。 

たとえば、\(n=5\)、$$
RRRRR
$$元の行列を生成する必要があります。 シフトのモジュロを保存する\(n\)は必須です。 オフセットを削減せずに拡大することを許可すると、最終的には不正なインデックス作成が発生します。 

## アプローチ

 ブルートフォース手法では、各演算を行列に直接適用します。 

のために\(R,L,U,D\)、行または列を回転します。 のために\(I\)、すべての行の逆順列を計算します。 のために\(C\)、すべての列の逆順列を計算します。 

各操作には \(O(n^2)\) のコストがかかります。 あり得るので、\(10^5\)オペレーションの全体的な複雑さは次のようになります。$$
O(mn^2).
$$ボトルネックは、同じデータを繰り返し移動させることです。 

より良いものを見つけるには、行列エントリをトリプルとして調べます。$$
(r,c,x),
$$どこ\(r\)は行インデックス、\(c\)列インデックス、および\(x\)値。 

行列はラテン方格であるため、すべての演算は完全にこれら 3 つの座標の変換として記述できます。 

シフト操作は 1 つの座標のみを変更します。$$
R,L : c
$$

$$
U,D : r
$$反転操作はさらに興味深いものです。 

行の置換の場合、反転によりその行内の位置と値が交換されます。 したがって$$
I : c \leftrightarrow x.
$$列の置換の場合、反転により行と値が交換されます。$$
C : r \leftrightarrow x.
$$重要な洞察は、すべての演算が 3 つの座標タイプ \((r,c,x)\) を並べ替えるだけであり、現在行、列、または値の役割を果たしている座標に巡回シフトを追加するということです。 

マトリックス全体を変換する代わりに、以下を追跡します。 

1. 現在行を表している元の座標。 
2. 現在列を表している元の座標。 
3. 現在値を表している元の座標。 
4. 各座標に付加されたオフセット。 

すべての演算を処理した後、\(O(n^2)\) で答えを 1 回再構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | \(O(mn^2)\) | \(O(n^2)\) | 遅すぎる |
 | 最適 | \(O(m+n^2)\) | \(O(n^2)\) | 承認済み |

 ## アルゴリズムのチュートリアル

 座標タイプに番号を付けます。$$
0=r,\quad 1=c,\quad 2=x.
$$配列を維持する\(p\)どこ：$$
p[i]
$$元の座標が現在どの位置を占めているかを示します\(i\)。 

オフセットを維持する$$
add[0],add[1],add[2].
$$すべての座標はゼロベースの形式で保存されます。 

1.初期化$$
p=[0,1,2]
$$そして$$
add=[0,0,0].
$$2. 各操作を処理します。 

3. のために\(R\)、現在列として機能している座標のオフセットを増やします。$$
add[p[1]]=(add[p[1]]+1)\bmod n.
$$4. のために\(L\)、同じオフセットモジュロを減少させます\(n\)。 

5. のために\(D\)、現在行として機能している座標のオフセットを増やします。$$
add[p[0]]=(add[p[0]]+1)\bmod n.
$$6. のために\(U\)、そのオフセットモジュロを減少させます\(n\)。 

7. のために\(I\)、列と値の役割を交換します。$$
p[1],p[2]=p[2],p[1].
$$8. のために\(C\)、行と値の役割を交換します。$$
p[0],p[2]=p[2],p[0].
$$9. すべての操作が完了したら、元のすべてのセル \((i,j)\) にアクセスします。 

10. 値をゼロベースの形式に変換します。$$
x=a_{ij}-1.
$$11. フォーム$$
cur=[i,j,x].
$$12. 累積オフセットを適用します。$$
cur[k]=(cur[k]+add[k])\bmod n.
$$13. 次を使用して、変換された座標を最終的な役割に配置します。\(p\)。 

14. しましょう$$
res[p[k]]=cur[k].
$$15.それでは$$
res[0]
$$最後の行です、$$
res[1]
$$最後の列です、

 そして$$
res[2]
$$は最終的な値です。 

16. 書く$$
res[2]+1
$$位置の回答行列に入力します$$
(res[0],res[1]).
$$### なぜ効果があるのか

 すべての演算はトリプル \((r,c,x)\) に作用します。 シフト演算により追加されるのは、\(1\)または\(-1\)モジュロ\(n\)現在行または列として機能している座標に移動します。 操作\(I\)そして\(C\)座標値自体を変更することはなく、座標タイプの意味を交換するだけです。 

アルゴリズムは、次の 2 つの情報を正確に維持します。\(p\)座標タイプの現在の意味を記述し、累積されたすべての循環シフトを記述するオフセット。 すべての操作は、座標トリプルを変換するときに正確にこれらの構造を更新するため、操作文字列を処理した後の表現は、操作をすべてのセルに個別に適用することと同じになります。 変換されたトリプルから行列を再構築すると、一意の最終的な行列が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]
        ops = input().strip()

        p = [0, 1, 2]
        add = [0, 0, 0]

        for ch in ops:
            if ch == 'R':
                add[p[1]] = (add[p[1]] + 1) % n
            elif ch == 'L':
                add[p[1]] = (add[p[1]] - 1) % n
            elif ch == 'D':
                add[p[0]] = (add[p[0]] + 1) % n
            elif ch == 'U':
                add[p[0]] = (add[p[0]] - 1) % n
            elif ch == 'I':
                p[1], p[2] = p[2], p[1]
            else:  # 'C'
                p[0], p[2] = p[2], p[0]

        ans = [[0] * n for _ in range(n)]

        for i in range(n):
            for j in range(n):
                cur = [i, j, a[i][j] - 1]

                for k in range(3):
                    cur[k] = (cur[k] + add[k]) % n

                res = [0, 0, 0]

                for k in range(3):
                    res[p[k]] = cur[k]

                ans[res[0]][res[1]] = res[2] + 1

        out = []
        for row in ans:
            out.append(" ".join(map(str, row)))
        sys.stdout.write("\n".join(out) + "\n")

solve()
```配列`p`座標の役割の現在の順列を保存します。 いつでも`I`または`C`が表示されると、この順列のみが変化します。 

配列`add`現在のロールではなく、元の座標タイプに関連付けられたシフトを保存します。 この詳細は間違いやすいです。 座標が後で役割を変更した場合、`I`または`C`、その蓄積されたシフトはそれとともに移動する必要があります。 

再構成中、各セルは座標トリプルとして解釈されます。 オフセットは座標タイプに属しているため、最初に適用されます。 それから順列`p`どの変換された座標が行、列、または値になるかを決定します。 

モジュロ演算は、オーバーフローやインデックス ドリフトを発生させることなく、任意の長さのシフト シーケンスを処理します。

 操作:`I`| 操作 | p | 追加 |

 | 開始 | [0,1,2] | [0,0,0] |
 | 私 | [0,2,1] | [0,0,0] |

(r,c,x)=(1,2,3).
$$交換後:$$
(r,x,c)=(1,3,2).

 ## 特殊なケース

 検討してください\(n=1\)。 すべての座標モジュロ\(1\)残る\(0\)。 スワップのたびに、単一のセルは変更されません。 アルゴリズムは維持します`p`そして`add`、1つのトリプルを再構築し、出力します`1`。 

次のようなシーケンスを考えてみましょう`RRRRR`と\(n=5\)。 列オフセットは次のようになります。$$
(0+5)\bmod 5 = 0.
$$再構成フェーズでは、元の座標を受け取り、元の行列を再作成します。 モジュロを削減せずに生のシフトを保存する実装\(n\)後でインデックスが正しく作成されない危険性があります。 

考慮する`IC`。 後`I`、列と値を交換します。 後`C`、行と値が交換されます。 これらの操作は、行列のエントリに直接作用するのではなく、座標の役割に作用します。 行と列のシフトのみを追跡すると、この相互作用が見逃されます。 順列配列`p`正しく記録する$$
[0,1,2]
\to
[0,2,1]
\to
[1,2,0],
$$これはまさに、操作によって実行される座標変換です。
