 ## 解決策
 ## 問題の理解

 無限の 2D グリッドの原点に立っているロボットがあり、座標を使用してターゲット セルにロボットを誘導する必要があります。$(x, y)$。 ロボットは北、東、南、西に移動したり、その場に留まることはできますが、同じコマンドを連続して繰り返すことはできません。 入力により複数のテスト ケースが得られ、それぞれが宛先を指定します。$(x, y)$。 目的地ごとに、ロボットを目的地まで移動させる最小の移動数を決定する必要があります。$(0, 0)$に$(x, y)$ただし、連続コマンド禁止の制限は尊重されます。 

制約は控えめです。 最大 100 のテスト ケースと最大の座標$10^4$、テスト ケースごとに線形時間で結果を計算するアルゴリズムが必要です。 考えられるすべての動きシーケンスをシミュレートしようとすると、どれも遅すぎます。これは、可能性のあるシーケンスの数が指数関数的に増加するためです。$x + y$。 

エッジケースは、次のいずれかの場合に発生します。$x$または$y$代替コマンドには慎重な取り扱いが必要なため、ゼロです。 たとえば、から移動するには$(0, 0)$に$(2, 0)$、単純な戦略では 2 つの東の動きを示唆するかもしれませんが、ロボットにはそれができません`E E`したがって、最小限のシーケンスでは実際には間に「stay」コマンドが使用されます。`E 0 E`。 同様に、両方の座標がゼロの場合、ロボットはすでに目的地に到着しており、コマンドは必要ありません。 

## アプローチ

 ブルートフォースアプローチでは、「繰り返し禁止」ルールを遵守し、到達するすべての一連の動きを生成しようとします。$(x, y)$。 この方法は原理的には正しいですが、大きな座標ではシーケンスの数が次のように指数関数的に増加するため、実行不可能です。$2^{x+y}$最悪の場合。 

重要な洞察は、制限が同じ方向に連続して移動する場合にのみ重要であるということです。 同じコマンドを繰り返さないようにするために、移動が必要な 2 つの方向 (南北と東西) を交互に切り替えることができます。 事実上、最小シーケンス長は、次のいずれか大きい方にのみ依存します。$x$そして$y$。 両方の座標が等しい場合、追加の「stay」コマンドを使用せずに交互に移動し、正確な結果を得ることができます。$x + y$動きます。 座標が等しくない場合、ロボットは小さい次元に沿って交互に移動した後、小さい次元を超えて大きい次元の残りのステップごとに追加の動作を 1 つ挿入する必要があります。 これにより、次の式が得られます。`2 * max(x, y) - 1`もし`x != y`、 そして`x + y`もし`x == y`。 

以下の表にアプローチをまとめます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(x+y)) | O(x+y) | 遅すぎる |
 | 最適 | テスト ケースごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. テストケースごとに、目的地の座標を読み取ります。$x$そして$y$。 
3. 両方の場合$x$そして$y$はゼロであり、0 を出力し、移動する必要がないため続行します。 
4. 小さい方の座標を決定します$a = \min(x, y)$そして大きな座標$b = \max(x, y)$。 
5. もし$x$そして$y$等しい、出力$x + y$, 余分な手順なしで完璧に動きを交互にできるからです。 
6. もし$x$そして$y$等しくない、出力`2 * b - 1`。 これは、小さい座標までの交互の移動と、最後のコマンドを繰り返さずに大きい座標での残りの移動を完了するために必要な追加のステップを考慮しています。 
7. すべてのテスト ケースに対して繰り返します。 

不変条件は、1 つの座標が使い果たされるまでロボットが常に方向を変えるということです。 大きな座標内の残りの移動には、滞在または反対方向の移動をインターリーブする必要があり、残りのステップごとに 1 つの追加コマンドを追加する必要があります。 このロジックは、「連続した繰り返しなし」ルールを尊重しながら、最小限のコマンド数を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    x, y = map(int, input().split())
    if x == 0 and y == 0:
        print(0)
        continue
    a, b = min(x, y), max(x, y)
    if x == y:
        print(x + y)
    else:
        print(2 * b - 1)
```コードはまず、次のような簡単なケースを処理します。`(0, 0)`不必要な計算を避けるため。 次に、最小座標と最大座標を計算して、パスを完全に交互にできるかどうかを判断します。 座標が等しい場合、合計により最小の移動が得られます。 それ以外の場合は、導出された式を適用します`2 * max(x, y) - 1`。 

## 実用的な例

 両方の軸に沿って交互に完全に移動すると、`N E N E ...`10手。 

**サンプル入力 2:**`(3, 4)`| × | y | 分 | 最大 | x==y | 出力 |

 両方の軸に沿って 3 つの動作を交互に実行します。`N E N E N E`(6 移動)、次に、繰り返さずに大きい軸 (東) に沿って追加の 1 移動、合計 7 移動します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t) | 各テスト ケースは一定の時間で処理されます。 |
 | スペース | お(1) | テスト ケースごとに保存される変数はわずかです。 |

 最大値を考えると$t = 100$、アルゴリズムは最大でも数百の操作を実行しますが、2 秒の制限内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        x, y = map(int, input().split())
        if x == 0 and y == 0:
            print(0)
            continue
        a, b = min(x, y), max(x, y)
        if x == y:
            print(x + y)
        else:
            print(2 * b - 1)
    return output.getvalue().strip()

 ## 特殊なケース

 ロボットが 1 つの軸に沿ってのみ移動する必要がある場合、交互ルールにより、繰り返される移動の間に強制的に停止コマンドが挿入されます。 入力用`(2, 0)`、`a = 0`そして`b = 2`。 式は次のようになります`2 * 2 - 1 = 3`、シーケンスに対応します`E 0 E`。 のために`(0, 0)`、コマンドが必要ないため、出力は 0 です。 次のような大きな等しい座標の場合`(10000, 10000)`、両方の軸に沿って交互に移動すると、正確に結果が得られます。`x + y = 20000`、アルゴリズムが正しくスケーリングされていることを示しています。 各エッジ ケースでは、ロボットが最小限のステップ数を使用しながらコマンドを連続的に繰り返さないという不変条件が尊重されます。
