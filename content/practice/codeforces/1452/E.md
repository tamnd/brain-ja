 ## 解決策
 ## 問題の理解

 私たちに与えられた問題集は、`n`問題と`m`参加者。 各参加者は、次のように定義される特定の連続した範囲の問題に興味を持っています。`[l_i, r_i]`。 2 人の著者が、それぞれの内容を正確にカバーするチュートリアルを紹介します。`k`連続問題。 どのセグメントの長さを著者が独自に選択するか`k`カバーするために。 

すべての参加者は、そのセグメントが参加者の興味範囲と最も重複する著者のみに参加します。 各参加者について、彼らが聞くことができる問題の数を呼びます。`a_i`。 私たちの目標は、2 人の著者のセグメントを選択して、すべての合計が`a_i`最大化されます。 

制約`n, m ≤ 2000`意味する`O(n^2 * m)`不注意だと最大で約 80 億回の演算が行われるため、この解決策は実現可能です。 もっと速いものが必要です。 著者のセグメントのすべてのペアをチェックし、すべての参加者の重複を計算する単純なソリューションには、以下が含まれます。`O((n-k+1)^2 * m)`操作は許容されます。`(n-k+1)^2 * m ≤ 4*10^9`最悪の場合、きつすぎる可能性があります。 

明らかではないエッジ ケースには、完全に一致するセグメント、部分的に重なり合うセグメント、または完全に一致するセグメントが含まれます。`k`等しい`n`。 たとえば、次の場合`k = n`、両方の著者が問題セット全体をカバーするため、すべての参加者が必要な問題をすべて見ることができます。 もう 1 つのエッジ ケースは、関心範囲が以下の参加者です。`k`; オーバーラップは参加者の範囲を超えることはできないため、アルゴリズムは最小/最大を正しく処理する必要があります。 もし`k = 1`参加者は複数の問題に興味があるため、最適な単一問題セグメントを選択するには、どの参加者が各セグメントから最も利益を得るかを慎重に計算する必要があります。 

たとえば、次の入力を使用します。```
5 2 2
1 3
3 5
```不注意な実装はセグメントを選択する可能性があります`[1,2]`そして`[2,3]`かどうかを確認せずに著者に対して`[4,5]`より良い金額が得られる可能性があります。 正解は、両方の参加者の合計の重複を最大化することです。 

## アプローチ

 ブルートフォースアプローチは簡単です。 長さの各セグメントに対して`k`最初の著者が選択できること (`n-k+1`オプション)、および長さの各セグメントに対して`k`2 番目の著者が選択できること (`n-k+1`オプション)、各参加者と 2 つのセグメントの最大オーバーラップを計算し、これらの最大値を合計します。 これには必要です`O((n-k+1)^2 * m)`操作。 これは正しいですが、許容される最大値の場合は遅くなります。`n`そして`m`、特にそれ以来`n-k+1`最大 2000 まで可能です。 

重要な洞察は、問題はセグメントの各ペアのすべての参加者の最大重複の合計を効率的に計算することに帰着するということです。 各参加者のセグメントとの重複`[s, s+k-1]`単純に`max(0, min(r_i, s+k-1) - max(l_i, s) + 1)`。 したがって、セグメントのすべての可能な開始位置と各参加者のオーバーラップを事前計算できます。 次に、最初の著者セグメントごとに、オーバーラップ合計の現在の最大値を維持することで、「可能な限り最良の 2 番目のセグメント」を迅速に計算できます。 

最適なソリューションは、プレフィックス合計/動的プログラミング手法を活用します。 第一著者となる可能性のあるセグメントごとに、第一著者がそのセグメントをカバーしている場合の貢献度を参加者ごとに計算します。 次に、2 番目の作成者については、各参加者が 2 つの重複の最大値を選択することを考慮して、スライディング ウィンドウを使用して、すべての参加者の追加合計を最大化するセグメントを見つけます。 これにより、時間の複雑さが軽減されます。`O(n^2 + n*m)`、これは許容されます`n, m ≤ 2000`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n-k+1)^2 * m) | O(m*(n-k+1)) | 最大制約に対して遅すぎる |
 | 最適 | O(n^2 + n*m) | O(n*m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 事前計算`overlap[i][s]`参加者ごとに`i`および次から始まるすべての可能なセグメント`s`、 どこ`overlap[i][s] = max(0, min(r_i, s+k-1) - max(l_i, s) + 1)`。 これにより、参加者の問題の数がわかります`i`著者が次から始まるセグメントを選択したかどうかを聞きます`s`。 
2.初期化`max_sum = 0`。 これにより、すべての参加者の可能な限り最良のオーバーラップの最大合計が保存されます。 
3. あらゆる可能な開始位置に対して`s1`最初の著者のセグメントの重複合計を計算します`first_overlap[i] = overlap[i][s1]`参加者ごとに。 
4. 2 番目の作成者については、追加の寄与を効率的に計算する必要があります。 考えられる各セグメントの開始位置について`s2`、計算します`second_sum = sum(max(first_overlap[i], overlap[i][s2]) for i in 1..m)`。 最大値を追跡する`second_sum`全体`s2`。 
5.アップデート`max_sum`最大のものと`second_sum`現在のために見つかった`s1`。 
6. すべてを繰り返した後`s1`、出力`max_sum`。 

機能する理由: このアルゴリズムは、すべての最初の著者セグメントを明示的に考慮し、その選択が与えられた場合に最適な 2 番目のセグメントを見つけます。 不変条件は各ペアの`(s1, s2)`、合計`sum(max(overlap with s1, overlap with s2))`各参加者が獲得できる最大値を正しく表しています。 すべてを繰り返す`s1`より良い組み合わせを見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())
participants = [tuple(map(int, input().split())) for _ in range(m)]

# Precompute overlaps
overlap = [[0]*(n-k+2) for _ in range(m)]  # 1-based indexing for segments
for i, (l, r) in enumerate(participants):
    for s in range(1, n-k+2):
        overlap[i][s] = max(0, min(r, s+k-1) - max(l, s) + 1)

max_sum = 0
for s1 in range(1, n-k+2):
    first_overlap = [overlap[i][s1] for i in range(m)]
    best_second_sum = 0
    for s2 in range(1, n-k+2):
        total = 0
        for i in range(m):
            total += max(first_overlap[i], overlap[i][s2])
        if total > best_second_sum:
            best_second_sum = total
    if best_second_sum > max_sum:
        max_sum = best_second_sum

print(max_sum)
```可能なセグメントごとに参加者の重複を事前に計算することで、合計を迅速に計算できます。 すべての第一著者の位置を反復処理し、すべての第二著者の位置をスキャンして、次を使用して合計を更新します。`max(first_overlap, second_overlap)`参加者の選択ルールを尊重します。 1 から始まるインデックスを使用すると、正しいセグメント境界が保証されます。
