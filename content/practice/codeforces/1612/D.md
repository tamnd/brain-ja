 ## 解決策
 ## 問題の理解

 整数のペアが与えられます$a$そして$b$、および別の整数$x$。 どちらかを繰り返し交換することができます$a$または$b$絶対的な差で$|a - b|$。 タスクは、これらの操作を何回か繰り返した後で、次のいずれかのことが可能かどうかを判断することです。$a$または$b$等しい$x$。 複数の独立したテスト ケースがあり、それぞれに独自のテスト ケースがあります。$a, b, x$。 

制約により許可されるのは、$a, b, x$まで行く$10^{18}$、最大で$10^4$テストケース。 これにより、ステップ数が非常に大きくなる可能性があるため、すべての操作を明示的にシミュレートするアプローチは実行不可能になります。 の数値プロパティを直接操作するアプローチが必要です。$a$そして$b$可能なすべての操作シーケンスを生成するのではなく、

 重要な、明白ではないエッジケースは、次のような場合に発生します。$a = b$。 ここ、$|a-b| = 0$したがって、後続の操作では、現在のペアとゼロ以外の数値が生成されることはありません。 たとえば、次の場合$a = b = 30$そして$x = 30$答えはYESですが、もし$x = 15$の場合、ペアは 15 ではなく 0 にのみ到達できるため、NO になります。 

もう一つの微妙なケースは次のような場合です。$x$どちらよりも大きい$a$または$b$。 例えば、$a = 40, b = 50, x = 90$。 この操作では数値を減らすことしかできないため、$x > \max(a, b)$、答えは即座にNOです。 これらの制約を早期に認識すると、不必要な計算が防止されます。 

## アプローチ

 ブルートフォースの解決策は簡単です。両方の操作をあらゆる方法で繰り返し適用し、生成されたすべての新しいペアを追跡して、どちらかが発生するまで追跡します。$x$が見つかるか、シーケンスが安定します。 この問題では 2 つの操作を任意の順序で実行できるため、これは正しいです。 このアプローチの問題点は、大規模な場合には$a, b$生成できる個別のペアの数は膨大であり、最大で$10^{18}$、それは完全に不可能です。 

最適なソリューションに関する重要な洞察は、操作が最大公約数を計算するためのユークリッド アルゴリズムを模倣していることを観察することで得られます。 数字を 1 つ置き換えるたびに、$|a-b|$、差が元のペアの線形結合であるより小さなペアに向かって進んでいます。$a$そして$b$。 具体的には、これらの操作を通じて到達可能な数値は次の条件を満たす必要があります。$x \le \max(a, b)$そして$x \equiv a \pmod{\gcd(a, b)}$。 これは、ユークリッド アルゴリズムにより、繰り返し適用することによって生成される数値シーケンスが保証されるためです。$|a-b|$最終的にはすべての倍数が生成されます$\gcd(a, b)$以下のもの$\max(a, b)$。 

したがって、操作をシミュレートする代わりに、次の 2 つの条件を直接確認できます。$x \le \max(a, b)$そして$x \% \gcd(a, b) == a \% \gcd(a, b)$。 両方が成立する場合、ペアは次のようになります。$x$-魔法。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. テスト ケースごとに、整数を読み取ります。$a, b, x$。 
3. コンピューティング$g = \gcd(a, b)$。 これにより、操作を通じて到達可能なすべての数値のステップ サイズが取得されます。 到達可能な数値はすべて以下に一致する必要があります$a$モジュロ$g$。 
4. 次のことを確認します。$x \le \max(a, b)$。 そうしないと、操作はそれ以上の数値に到達できないため、「NO」を出力して続行します。 
5.次のことを確認します$x \equiv a \pmod{g}$。 本当なら、$x$到達可能である。 それ以外の場合はそうではありません。 それに応じて YES または NO を出力します。 

機能する理由: ユークリッドに似た演算では、ペアの最大公約数が維持され、最大値が増加することはありません。 したがって、任意の数$x$到達可能な値は現在の最大値以下でなければならず、GCD を法とした元の数値と一致する必要があります。 これら 2 つの単純なチェックにより、到達可能な数値のセットが完全に取得されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, x = map(int, input().split())
    g = math.gcd(a, b)
    if x <= max(a, b) and (x % g == a % g):
        print("YES")
    else:
        print("NO")
```コードは最初にすべてのテスト ケースを読み取ります。 重要な計算は、`math.gcd(a, b)`これにより、動作をシミュレートする代わりにモジュールの状態を直接確認できます。 チェック中`x <= max(a, b)`現在のペアより大きい数値に到達しようとしないことを保証します。`x % g == a % g`ユークリッド パターンによる到達可能性を保証します。

これらの例は、アルゴリズムが 2 つの条件によって到達可能な数値を正しく識別することを示しています。

            print("YES")
        else:
            print("NO")
    return output.getvalue().strip()

 ## 特殊なケース

 もし$a = b = x$の場合、アルゴリズムは正しく YES を返します。`x <= max(a,b)`そして`x % g == a % g`ささいなことではありません。 のために$x > \max(a, b)$、正しくはすぐに NO を返します。 数値が非常に大きい場合、GCD 計算はそれらを効率的に処理し、モジュラー演算によりオーバーフローのない正確性が保証されます。
