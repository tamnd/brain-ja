 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列を作成するように求められます。n は偶数です。 順列は 2 つの等しい半分に分割されます。最初の n/2 要素が左半分を形成し、残りの n/2 要素が右半分を形成します。 

2 つの条件を同時に満たす必要があります。 左半分では、最小値は正確に a でなければなりません。 右半分では、最大値は正確に b でなければなりません。 1 から n までの配列が両方の制約を満たすことができない場合は、-1 を出力する必要があります。 

これは何かを最適化することではなく、2 つの特定の極値条件が順列の 2 つの互いに素なセグメントに保持されるように数値を配置することです。 主な難しさは、1 から n までのすべての数字が 1 回だけ出現する必要があるため、a と b を配置すると、両方の半分で使用できるものが影響を受けることです。 

制約は小さく、n は最大 100、テスト ケースは最大 1000 です。 これにより、テスト ケースごとに O(n^2) または O(n) さえあれば簡単に十分であることがすぐに分かります。 本当の課題は純粋に構造的なものです。 

単純なアプローチでは、すべての順列を試したり、実現可能性を考慮せずに貪欲にポジションを埋めたりする可能性があります。 極値制約がグローバルに相互作用するため、これは失敗します。 たとえば、右半分に非常に小さな数値を配置すると、誤って最大値が大きすぎたり小さすぎたりする可能性があります。 

いくつかの微妙な失敗例がすぐに現れます。 

a が右半分に配置されている場合、左半分には a が存在しないため、最小値として a を持つことができない可能性があります。 同様に、b が左半分に配置された場合、右半分は b を最大値に達することができません。 

また、a と b が異なる半分に正しく配置されている場合でも、最小値と最大値の制約に違反することなく、残りの数値をすべて収容できる十分な「スペース」が各半分にあることを確認する必要があります。 

## アプローチ

 ブルートフォース手法では、1 から n までのすべての順列を生成し、条件が満たされるかどうかを確認します。 これは正しいですが、n = 10 であっても 10 個あるため、完全に実行不可能です。 順列はすでに限界をはるかに超えています。 

より構造化されたブルート フォースでは、半分に数値を割り当てて妥当性をチェックしようとします。 これにより、左半分に n/2 個の数値を選択してそれらを配置するという問題が軽減されますが、効果的にサブセットを選択しているため、n では依然として指数関数的になります。 

重要な観察は、各半分の内部の完全な順序を実際には気にしていないということです。 左半分の最小値と右半分の最大値の 2 つの境界プロパティのみを考慮します。 つまり、次のことを確認するだけで済みます。 

- a は左半分に含まれており、そこにある最小の要素です
 - b は右半分に含まれており、そこで最大の要素です

 a と b の位置を決めたら、これら 2 つの制約を破らない限り、残りの数値を分配できます。 

これは建設的な戦略につながります。 最初に a と b を配置し、次に、極端な役割を考慮して、それらより小さい値と大きい値を使用して残りの位置を慎重に埋めます。 

実現可能条件は以下を数えることから得られます。 

- 左半分には a が含まれている必要があり、他のすべての要素は厳密に a 以上である必要があります。 
- 右半分には b が含まれている必要があり、他のすべての要素は厳密に b 以下である必要があります。 

これは、a より小さい値はすべて右半分に配置され、b より大きい値はすべて左半分に配置される必要があることを意味します。 違反があると、最小値または最大値が強制的にシフトされます。 

この構造から、順列を直接構築するか、カウントが適合しない場合は拒否することができます。

 ## アルゴリズムのチュートリアル

a を左半分の最小値として、b を右半分の最大値として強制しながら、それぞれサイズ n/2 の 2 つの半分を構築したいと考えています。 

1. まず左半分にaを置きます。 これにより、左半分が最小の a を持つ可能性があることが保証されますが、その左半分に a より小さいものが現れた場合にのみ有効になります。 
2. bを右半分に配置します。 これにより、それより大きな値が入力されない限り、右半分が最大 b を持つ可能性があることが保証されます。 
3. 残りのすべての数値を 3 つのグループに分割します。a 未満の数値、a と b の間の数値、および b より大きい数値です。 
4. a 未満の数字はすべて右半分に入力する必要があります。 それらのいずれかが左半分に配置された場合、a がそこで最小であるという要件に違反します。 
5. b より大きい数値はすべて左半分に配置する必要があります。 それらのいずれかが右半分に配置された場合、b がそこで最大であるという要件に違反します。 
6. 次に、a と b の間に残りの番号を任意に割り当て、両方の半分の残りのスロットを埋めます。 この段階では、2 つのアンカーの間にあるため、最小/最大条件を破ることはできません。 
7. 充填後、半分がサイズ n/2 を超えるか、一貫して充填できない場合は、-1 を出力します。 

これが機能する理由: a と b が極端なアンカーとして固定されると、他のすべての数値が比較により強制的に片側に配置されます。 a より小さい値をそこに配置すると左の最小値を破ることになり、b より大きい値をそこに配置すると右の最大値を破ることになります。 残りの値は「中立」であり、自由に配布できます。 容量制約がこれらの強制配置と一致したときに、構築は正確に完了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, a, b = map(int, input().split())
        half = n // 2

        if a == b:
            print(-1)
            continue

        left = [a]
        right = [b]

        used = set([a, b])

        # numbers less than a must go right
        less = [x for x in range(1, a) if x not in used]
        # numbers greater than b must go left
        greater = [x for x in range(b + 1, n + 1) if x not in used]
        # middle numbers
        middle = [x for x in range(1, n + 1) if x not in used and a < x < b]

        # feasibility checks
        if len(greater) + 1 > half or len(less) + 1 > half:
            print(-1)
            continue

        left += greater
        right += less

        # fill remaining spots
        remaining_left = half - len(left)
        remaining_right = half - len(right)

        if remaining_left + remaining_right != len(middle):
            print(-1)
            continue

        left += middle[:remaining_left]
        right += middle[remaining_left:]

        if len(left) != half or len(right) != half:
            print(-1)
            continue

        print(*left, *right)

if __name__ == "__main__":
    solve()
```この実装では、強制配置ロジックを使用して 2 つの半分を明示的に構築します。 重要な詳細は、a より小さい数値が決して左半分に入らないこと、また b より大きい数値が右半分に入らないことを保証することです。 容量制約が確認されると、中央のセグメントが任意に分割されます。 

中間要素を割り当てる前にサイズチェックに注意する必要があります。 そうしないと、簡単に半分がオーバーフローしてしまい、無効な順列が生成されてしまう可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, a, b = map(int, input().split())
        half = n // 2

        if a == b:
            out.append("-1")
            continue

        left = [a]
        right = [b]
        used = {a, b}

        less = [x for x in range(1, a) if x not in used]
        greater = [x for x in range(b + 1, n + 1)]
        middle = [x for x in range(1, n + 1) if x not in used and a < x < b]

        if len(greater) + 1 > half or len(less) + 1 > half:
            out.append("-1")
            continue

        left += greater
        right += less

        if len(left) > half or len(right) > half:
            out.append("-1")
            continue

        rem_l = half - len(left)
        rem_r = half - len(right)

        if rem_l + rem_r != len(middle):
            out.append("-1")
            continue

        left += middle[:rem_l]
        right += middle[rem_l:]

        if len(left) != half or len(right) != half:
            out.append("-1")
            continue

        out.append(" ".join(map(str, left + right)))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、a と b が境界に非常に近い、または境界に近い場合です。 たとえば、a = 1 および b = n の場合、他のすべての数値は強制的に中央領域に配置され、配置順序が尊重される限り、この構築は簡単に機能します。 1 未満または n より大きい数値がないため、アルゴリズムはこれを処理します。そのため、強制グループは空であり、容量チェックは常にパスします。 

もう 1 つの特殊なケースは、a が大きく、b が小さい場合です。 たとえば、n = 6、a = 5、b = 2 です。ここでは、5 未満のすべての数値が右半分に強制的に入れられ、2 より大きいすべての数値が左半分に強制的に入れられるため、両方の半分がオーバーフローします。 アルゴリズムは、サイズチェックを通じてこれを正しく検出します。`less`そして`greater`、無効な配置を試みる前に -1 を出力します。 

最後の微妙なケースは、中央のセグメントが残りのスロットを正確に埋める場合です。 この平等性が厳密にチェックされないと、静かに半分を入れすぎてしまう可能性があります。 残りの容量と中間サイズの間の明示的な等価性チェックにより、これが防止され、順列が完全かつ正確に分割されることが保証されます。
