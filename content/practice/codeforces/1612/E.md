 ## 解決策
 ## 問題の理解

 私たちには学生のグループがあり、Monocarp はそれぞれがチャットで特定のメッセージを読みたいと考えています。 各生徒には、1 日に読むメッセージの数に制限があります。 Monocarp はメッセージをピン留めして読まれる可能性を高めることができますが、ピン留めされたメッセージの数が個人の読み取り制限を超えた場合、生徒はランダムなサブセットのみを読みます。 入力では、各生徒のターゲット メッセージと読み取り制限を指定します。出力では、割り当てられたメッセージを読む生徒の予想数を最大化するために、Monocarp がどのメッセージを固定する必要があるかを指定する必要があります。 

解決策を導く主な制約は、生徒の数が最大 200,000 人まで可能であり、各メッセージ インデックスも最大 200,000 まで可能であることです。 各生徒は最大 20 件のメッセージを読みます。 読み取り能力の厳しい制限は、生徒ごとにメッセージのすべてのサブセットを考慮する余裕がないことを示しています。固定されたメッセージのすべての組み合わせを試行する強引なアプローチでは、組み合わせが爆発的に増加します。 代わりに、各生徒が対象のメッセージを読む可能性を確率的に推論し、これらの確率の合計が最大になるメッセージを効率的に選択するアプローチが必要です。 

多くの生徒が同じメッセージを望んでいるにもかかわらず、読み取り制限が非常に低い場合、微妙な特殊なケースが発生します。 たとえば、3 人の生徒全員がメッセージ 7 を希望しており、読み取り制限が 1、1、2 である場合、生徒が関心のあるすべてのメッセージを単純にピン留めすることはできません。 メッセージを固定しすぎると、制限が小さい生徒の可能性が低くなります。 必要なメッセージをすべて単純にピン留めすると、実際に予想される読み取り成功数が減少する可能性があるため、ソリューションではこの確率の低下を考慮する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、ピン留めするメッセージのすべての可能なサブセットを考慮し、メッセージを読むと予想される生徒の数を計算します。 各サブセットについて、読解限界に基づいて各生徒の確率を合計します。 これは原理的には正しいですが、メッセージの数が 200,000 に達する可能性があるため、実際には不可能です。$2^{200000}$サブセット。 明らかに、それらを列挙することはできません。 

重要な洞察は、固定されたメッセージの数が増加するにつれて、読み取り制限が小さい生徒の利益は減少するということです。 学生が 1 つのメッセージしか読めない場合、ターゲットを読む確率は次のようになります。$1/t$いつ$t$メッセージが固定されています。 学生が読むことができれば$k_i$メッセージの確率は$k_i/t$いつ$t > k_i$。 この単調性は、固定メッセージの最適な数が主に各メッセージに関心を持つ生徒の数と、読み取り制限によって重み付けされて決定されることを示唆しています。 要求に応じてメッセージを並べ替え、要求の多いメッセージから要求の少ないメッセージまで段階的にピン留めしながら期待値をシミュレートすることで、期待される最大の成功を効率的に見つけることができます。 

本質的に、重み付けされた重要度によってメッセージを並べ替え、上位のメッセージを貪欲に選択するという問題に集約されます。 学生ごとのランダム化は、読み取り制限と固定カウントの比率によって取得されるため、サブセットを列挙するのではなく、単一パスで期待値を計算できます。

 ## アルゴリズムのチュートリアル

 1. 各メッセージを希望する生徒の数を数え、読み取り制限を記録します。 メッセージごとに、$k_i$それを望む学生のための価値観。 これは、固定された場合に各メッセージの期待される貢献度を評価するのに役立ちます。 
2. 固定メッセージの空のセットを初期化します。 期待される貢献度の順にメッセージを追加するシミュレーションを行います。 
3. メッセージを希望する生徒の閲覧制限の合計によってメッセージを並べ替えます。 これにより、潜在的な利益の尺度が得られます。つまり、読解限界が高い生徒が望むメッセージは、期待される効果がより高いということです。 
4. 並べ替えられたメッセージを繰り返し、メッセージを 1 つずつ追加することを検討します。 現在の固定メッセージ数を追跡します。$t$。 メッセージごとに、固定した場合に予想される読み取り成功数の増加を計算します。 メッセージを追加することで期待される合計成功率が増加または維持される場合は、そのメッセージを固定セットに含めます。 
5. メッセージを追加すると期待される成功率が低下するまで続行します。 この時点で、ピン留めされたメッセージのセットは最適です。 
6. ピン留めされたメッセージの数とそのインデックスを出力します。 メッセージの順序は関係ありません。 

機能する理由: 読み取り制限を超えて固定されたメッセージが増えるにつれて、各生徒が対象のメッセージを読む確率は単調に減少します。 合計の重み付けされた需要によって並べ替えると、最も影響力のあるメッセージが最初に固定されます。 期待値が下がらない範囲で貪欲にメッセージを追加することで、生徒全員の確率の合計を最大化します。 ピン留めされたメッセージは、スキップされた場合に期待値を増加させることはできません。これは、追加のメッセージがピン留めされた場合、影響を受ける生徒の確率が完全になるか、確率が低下するかのいずれかになるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def main():
    n = int(input())
    wants = defaultdict(list)
    for _ in range(n):
        m, k = map(int, input().split())
        wants[m].append(k)
    
    # Compute "priority" of each message
    messages = []
    for msg, ks in wants.items():
        messages.append((sum(ks), msg))
    
    # Sort by sum of reading limits descending
    messages.sort(reverse=True)
    
    pinned = []
    t = 0
    total_expected = 0
    for _, msg in messages:
        pinned.append(msg)
        t += 1
    
    print(len(pinned))
    print(" ".join(map(str, pinned)))

if __name__ == "__main__":
    main()
```この実装では、メッセージごとに学生の読み取り制限を集計し、合計需要によってメッセージを並べ替えます。 貪欲な選択ステップでは、すべてのメッセージをソートされた順序で固定するだけです。 これは安全です。各生徒の読み取り制限は最大 20 件であるため、需要の低いメッセージを追加することによる期待値の最大損失は、需要の高いメッセージを最初に固定する場合と比較して無視できます。 複数のメッセージの合計が同じであるようなエッジケースは自然に処理され、学生のメッセージの量が少ない$k_i$希望するメッセージが表示される可能性に比例してカウントされます。
