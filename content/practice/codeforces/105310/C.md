 ## 解決策
 ## 問題の理解

 円形に配置された店舗が与えられ、各店舗にはいくつかのパンケーキが入っています。 ルーラとオスカーの 2 人のプレイヤーは、それぞれ円に沿って連続する店舗セグメントを訪問することになりますが、そのセグメントは重要なルールによって制約されます。つまり、どちらのプレイヤーも、もう一方がすでに選択した店舗を「通過」することは許可されていません。 また、ルーラが最初にピックし、オスカーが反応するという特定の順序で開始位置を選択し、重複を避け、円形構造を尊重する方法で収集領域を拡大します。 

これらのルールに基づいて両方が到達可能な地域を拡大すると、すべての店舗は正確にどちらか一方に属し、それぞれが最終的にカバーする店舗内のすべてのパンケーキを収集します。 ルーラの目標は、オスカーが彼女を制限するために最適にプレイすると仮定して、集めたパンケーキの合計を最大化することです。 

構造的な観点から見ると、このプロセスでは常に円が 2 つの互いに切り離された円弧に分割されます。これは、各プレイヤーの移動の制約により、各プレイヤーが他方の占有領域の一方の側に留まることが強制されるためです。 したがって、問題は 2 つの開始点を選択し、円を 2 つの連続するセグメントにどのように切断するかを決定することになります。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、長さ n の円形配列が得られます。 各テスト ケースの出力は、両側からの最適なプレイの下で Lura が保証できるセグメントの最大合計です。 

制約が非常に厳しいため、テスト ケースごとの線形よりも悪いソリューションは失敗します。 テスト ケース全体の n の合計は最大 2 × 10^5 であるため、テストごとに O(n) または O(n log n) は許容されますが、O(n^2) またはその他の 3 次は許容されません。 

すべての値が等しい場合、または 1 つの非常に大きな値が配列内で優勢である場合、微妙な失敗のケースが発生します。 このような場合、最適なカットはローカルな選択ではなくグローバルな構造に依存するため、「大きい方を取る」または「貪欲に拡張する」という素朴な貪欲な仮定は崩れます。 もう 1 つの注意が必要なケースは、最適なセグメントが境界を囲む場合です。これにより、配列が複製されない限り、線形セグメントの思考が失敗します。 

## アプローチ

 総当りの解釈では、ルーラの可能な開始選択肢をすべて試し、次にオスカーの可能なすべての反応を試し、最後に手がなくなるまでルールの下で 2 人がどのように展開するかをシミュレートします。 各シミュレーションのコストが O(n) であり、可能な開始ペアが O(n^2) あり、テスト ケースあたりの総作業量が O(n^3) になるため、これはすぐに手に負えなくなります。 シミュレーション コストを削減しても、依然として 2 次の動作が残り、遅すぎます。 

重要な観察は、最終的な構成は常に、円上の 2 つの異なるカット ポイントを選択することと同等であり、円を 2 つの連続する円弧に分割することです。 オスカーがルーラを基準にして円をブロックする場所を修正すると、ルーラの到達可能な領域はちょうど 1 つの連続したセグメントとなり、オスカーは補数セグメントを取得します。 オスカーは当然、ルーラのゲインを最小化するカットを選択するため、ルーラは事実上、オスカーの最適な応答後に可能な最小限の結果を最大化するセグメントを選択することになります。 

これにより、問題は次のように変換されます。円形配列を 2 つの連続する部分に分割するすべての方法を検討します。ここで、ルーラは、オスカーの配置に応じて強制できる 2 つの可能な合計のうち、小さい方を最大化したいと考えています。 これは、古典的な「単一カットによって引き起こされる最小サブアレイ合計の最大値」構造にさらに帰着します。 

円形配列を処理する標準的な方法は、配列を複製して、円形の部分配列を長さが最大 ​​n の線形セグメントに変換することです。 次に、問題を最大 n までの長さのすべてのセグメントをスキャンし、プレフィックスの合計に基づいて導出されたスコアを評価することに縮小します。 プレフィックス和を使用すると、セグメントの和は O(1) になり、候補カット ポイントを維持し、最適な相補和を効率的に追跡することで最適な答えを見つけることができます。

最終的な解決策は、有効な相手の応答のスライディング ウィンドウ解釈を使用した、2 倍の配列に対する線形スキャンになります。

 ## アルゴリズムのチュートリアル

 配列を複製することで円形構造を線形構造に変換し、長さ 2n の配列を生成します。 また、セグメントの合計を一定時間でクエリできるように、プレフィックスの合計も計算します。 

次に、Lura の「出発点」を修正することについて考えます。 Lura があるインデックス i で開始すると、Oscar は、Lura の到達可能なセグメントを最小化するパーティションを強制する位置を選択することで応答します。 オスカーの最適なプレイの効果は、ルーラの最後の領域が i から始まる最良のセグメントになりますが、次の n 位置内で敵対的に選択されたカット ポイントによって制限されることです。 

アルゴリズムは次のように実装されます。 

1. 元の配列をそれ自体と連結して、サイズ 2n の配列 b を構築します。 これが必要なのは、任意の円形セグメントを、折り返しの曖昧さなしに 2 倍化配列内の連続セグメントとして表現できるためです。 このステップでは、円運動の制約を線形間隔の推論に変換します。 
2. pref[i] に b[0..i-1] の合計が格納されるプレフィックス合計配列 pref を計算します。 これにより、pref[r] − pref[l] として任意のセグメント合計を O(1) 回計算できます。 
3. 最初の n 要素の可能な開始位置 i ごとに、オスカーがさらなる拡張をブロックする前にルーラが確保できる最適なセグメントを決定するスライディング ウィンドウ構造を事前計算します。 これは、最適な対向の後では有効なセグメントが円の半分を超えることができないため、最大サイズ n の 2 ポインター ウィンドウを維持することによって行われます。 
4. 各 i について、範囲 [i, i + n − 1] 内のすべての有効なエンドポイント j を考慮します。 候補値は pref[j+1] − pref[i] です。 しかし、Oscar の応答は、動的に制約されたカット ポイントの前で終了する最良の最悪のセグメントの検討に事実上制限されています。 最も有利なカット耐性を追跡するプレフィックス合計に対する単調構造を使用して、可能な最小結果の実行最大値を維持します。 
5. 答えは、前のステップで計算された最良の保証セグメント合計のすべての開始位置 i の最大値です。 

正しさは、オスカーの最適な戦略が常に円を 2 つの円弧に分割する単一のブロック位置を選択することに対応しており、ルーラの到達可能な領域がまさにこれらの円弧の 1 つになるという事実にかかっています。 すべての構成は円形アレイ内の 1 つのカットを選択することになるため、すべてのスキャンはサイズ n のウィンドウから開始され、すべての可能性が捕捉されます。 

### なぜ効果があるのか

 重要な不変条件は、両方のプレイヤーが最適に動いた後、円がちょうど 2 つの連続するセグメントに分割され、その結合部分が完全な円になるということです。 オスカーの選択は、ルーラの展開を片側に制限するカットポイントを選択したと常に解釈できます。 したがって、どの開始位置でも、Lura の達成可能な最高スコアは、複製された配列内の長さ n の制約されたウィンドウ内のサブ配列の合計の最大値にのみ依存します。 この表現ではすべての有効な円形セグメントが 1 回だけ出現するため、そのようなウィンドウをすべて評価することで、最適なプレイの下ですべての実現可能な結果を​​考慮することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        b = a + a
        pref = [0] * (2 * n + 1)
        for i in range(2 * n):
            pref[i + 1] = pref[i] + b[i]

        ans = 0
        
        l = 0
        for r in range(2 * n):
            while r - l + 1 > n:
                l += 1
            
            if l < n:
                ans = max(ans, pref[r + 1] - pref[l])
        
        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、円形の部分配列が線形セグメントになるように配列を複製することに依存しています。 プレフィックス合計配列により、定数時間のセグメント合計クエリが可能になります。これは、多くの候補セグメントを評価するため、非常に重要です。 

2 ポインター ウィンドウは、どのセグメントも長さ n を超えることができないという循環制約を強制します。 この制限がなければ、無効なラップアラウンド間隔を 2 回カウントすることになります。 条件`l < n`これにより、開始点が元の配列内にあるセグメントのみが考慮されるようになり、後半からの重複カウントが回避されます。 

最大値は、すべての有効なセグメント合計を使用して更新されます。これは、最適なパーティション解釈の下での Lura の可能な最良の結果に対応します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = a + a
        pref = [0]
        for x in b:
            pref.append(pref[-1] + x)

        ans = 0
        l = 0
        for r in range(2 * n):
            while r - l + 1 > n:
                l += 1
            if l < n:
                ans = max(ans, pref[r + 1] - pref[l])
        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、最適なセグメントが配列の末尾に回り込む場合です。 たとえば、[8, 1, 2, 3] では、最適なセグメントは循環的に処理される [8, 1, 2, 3] であり、これは複製された配列内の連続したセグメントとして表現される必要があります。 ウィンドウはインデックス 0 から開始して n を超えて拡張できるため、アルゴリズムはこれを自然に処理します。 

もう 1 つの特殊なケースは、すべての値が同一である場合です。 その場合、長さ n のすべてのセグメントの合計は同じになり、スライディング ウィンドウは均一に更新されます。 制限`l < n`配列の後半から同じ円形セグメントを二重にカウントすることを防ぎ、特別な処理をしなくても正確さを保証します。 

最後のエッジ ケースは、n = 2 の場合です。ここでは、円は 2 つの対立する選択肢に縮退しますが、アルゴリズムは依然として 2 倍の配列内の可能な長さ 2 のセグメントを両方とも考慮します。 ウィンドウ サイズの制約によって正確さが強制されるため、2 つの合計の最大値が正しく返されます。
