 ## 解決策
 ## 問題の理解

 時計回りに番号が付けられた n 頭のレッサーパンダの円が与えられます。 パンダの一部のペアは、非交差コードによってすでに接続されています。 各パンダは、これらの初期コードの多くても 1 つに出現するため、初期構造は、交差のない円の内側に描かれた互いに素なエッジの集合となります。 

目標は、n 個の頂点すべてで完全な非交差マッチングを実現することです。つまり、すべてのパンダが他の 1 台のパンダと正確にペアになり、すべてのペアのコードを交差することなく円の中に描くことができます。 最初のコードはどれも破棄することができます。タスクは、完全な非交差の完全なマッチングにマッチングを完了できるように、削除するコードの数を最小限に抑えることです。 

言い換えれば、指定された素のコードをできるだけ多く保持したいのですが、円上で完全に非交差の完全一致と共存できるものだけを保持したいと考えます。 

制約は厳しく、すべてのテスト ケースの合計 n は最大 2 · 10^5、t は最大 10^4 です。 これにより、テスト ケースごとに二次関数が除外されます。 O(n log n) であっても、すべてのテストにわたって慎重に線形化する必要があります。 マッチングを列挙したり、組み合わせで除去をシミュレートしようとするアプローチは、n 点でのマッチングの可能性の数がカタラン語式に増加するため、直ちに実行不可能になります。 

微妙な問題は、最初のコードが交差していなくても、完了を妨げる可能性があることです。 単一のコードにより、セグメント内に奇数の頂点を残すインターバル構造が強制される可能性があり、そのコードを削除しない限り完成が不可能になります。 「非交差 + 互いに素なエンドポイントは常に拡張可能であることを意味する」という単純な仮定は誤りです。 

失敗の小さな例: n = 6 で 1 つのコード (1, 4) がある場合、頂点はセグメント [2,3] と [5,6] に分割され、[4 は 1 つの副作用に回り込みます]。 構造によっては、そのコードを削除しないと特定の完了が不可能になります。 

重要な問題は、どの初期コードが少なくとも 1 つの完全な非交差マッチングと互換性があるかを判断することです。 

## アプローチ

 ブルートフォースの観点は、最初に n 点上で完全に完全な非交差マッチングを選択することを考えることから始まります。 このような一致の数はカタロニア数 C(n/2) であり、指数関数的に増加します。 このような完全な一致ごとに、それに含まれる最初の k 個のコードの数を数えて、最適なものを選択できます。 

すべての有効な最終構成はこれらの一致の 1 つであるため、これは原理的には正しいです。 ただし、n = 100 の場合でも、この空間は膨大であり、すべての一致を列挙することは不可能です。 

視点を逆転させる必要がある。 完全な一致を選択して互換性をチェックする代わりに、固定された独立したコードが与えられた場合、それらは円にどのような構造を課すのかを尋ねます。 

最初のコードはすでに交差していないため、円を独立した音程に分割します。 各区間内では、頂点は交差しない方法で頂点間で一致する必要があり、唯一のグローバル制約はパリティです。各区間には、保持されたコードを考慮した上で偶数個の空き頂点が含まれている必要があります。 

これは重要な観察につながります。 円をスイープし、既存の各コードをコンストレイントとして扱うことを想像すると、各コードは 2 つの端点を一緒に「ロック」するコンストレイントのように動作します。 有効な補完は、保持されている各コードを分離不可能な単位として扱う必要があります。 コードを維持することで、奇数の一致しない頂点が残っている間隔が強制される場合、そのコードは互換性がなくなります。

より深い構造は、互換性がセグメント上の 2 部形式のペアリングに帰着するということです。維持されたすべてのコードが入れ子構造を定義し、すべての誘導領域が均一に保たれるようにする必要があります。 最適な戦略は、有効なネスト互換構造内に共存できる初期コードの最大サブセットを選択することになります。 コードはすでに交差していないため、これはツリー状の音程依存問題となり、内側から外側へ貪欲に解決できます。 

最後の簡略化は、実際には完全なマッチングを構築する必要がないということです。 ネストされた区間でパリティ条件に違反することなく、どの初期コードが同時に保存できるかを確認するだけで済みます。 これは、エンドポイント上のスタックのような構造を持つ線形スキャンに帰着します。

 | 間隔 + 貪欲なネスト検証 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 コードのエンドポイントを円周上で順番に処理し、現在アクティブなコードの構造を維持します。 

1. すべてのコードのエンドポイントを円上の位置で並べ替え、それぞれがコードの左または右のエンドポイントであることをマークします。 これにより、円の周囲を線形に移動する順序が与えられます。 
2. 左端が見えているが右端がまだ閉じていないアクティブなコードのスタックを維持しながら、位置 1 から n までスイープします。 左側のエンドポイントに遭遇すると、そのコードをスタックにプッシュします。 
3. 正しいエンドポイントに遭遇したら、それを最新のアクティブなコードと一致させる必要があります。 スタックの最上位がこのコードに対応する場合、それをポップし、互換性があるとマークします。 それ以外の場合は、入れ子構造の非互換性が検出されます。 

このステップが機能するのは、非交差構造は、バランスの取れた括弧と同様に、有効なコードが横断順序で適切にネストされたシーケンスを形成する必要があることを意味するためです。 

1. このネスト順序に違反するコードは、有効な完全拡張子の一部となることができないため、削除対象としてマークされます。 
2. 答えは、k から互換性があると正常に検証されたコードの数を引いたものです。 

### なぜ効果があるのか

 重要な不変条件は、有効な非交差コードが円トラバース上の適切にネストされた間隔に正確に対応することです。 拡張可能なコードの完全なセットでは、この入れ子構造を保持する必要があります。これは、違反があると交差が強制されたり、完了するために不可能なパリティを持つ音程が作成されたりするためです。 スタックはこのネスト制約を強制し、LIFO 順序で一致できないコードは必ず完全な非交差完全一致の存在と競合する必要があります。 したがって、スタック一貫性のあるコードを正確に維持すると、有効な最終構成で共存できる初期コードの可能な最大のサブセットが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        pos = [[] for _ in range(n + 1)]
        
        for i in range(k):
            a, b = map(int, input().split())
            if a > b:
                a, b = b, a
            pos[a].append((b, i))
            pos[b].append((a, i))
        
        used = [False] * k
        stack = []
        
        for i in range(1, n + 1):
            for b, idx in pos[i]:
                if b > i:
                    stack.append((b, idx))
                else:
                    if stack and stack[-1][1] == idx:
                        stack.pop()
                        used[idx] = True
        
        keep = sum(used)
        print(k - keep)

if __name__ == "__main__":
    solve()
```この実装では、最初にエンドポイントの隣接リストを構築して、各位置のすべてのコードのエンドポイントを順番に処理できるようにします。 各コードはちょうど 2 つのエンドポイント イベントに影響します。 方向を正規化して、左のエンドポイントが表示されたときに常にプッシュし、右のエンドポイントに到達したときに検証するようにします。 

スタックはネスト制約を強制します。コードは、現在最も新しく開かれたコードである場合にのみ閉じることができます。 そうでない場合は、非交差拡張可能な構成に必要な構造に違反するため、維持できません。 

の`used`配列は、どのコードがこの検証に生き残るかを追跡します。 最小限の削除が必要なため、最終的な答えは k からこれを減算します。 

よくある微妙な点は、エンドポイントの順序を一貫して確保することです。 「閉じる前に開く」を明確に定義するには、(a, b) を交換して a < b にする必要があります。

 ## 特殊なケース

 最小のケースは、和音のない n = 2 です。 スタックは空のままで、答えは 0 で、削除の必要がないことと一致します。 

単一コードのケースは常に成功します。これは、1 つの非交差エッジを常に完全一致に拡張できるため、スタックによって常に使用可能としてマークされるためです。 

(1, 3) と (2, 5) のような構造的に矛盾するペアは、(2, 5) の前に (1, 3) を閉じようとするとスタックの不一致を引き起こし、少なくとも 1 つのコードが無効としてマークされます。 アルゴリズムは 1 つのコードを削除します。これは、両方を維持すると完成に必要な一貫したネスト構造を妨げるために必要です。 

(1, 6)、(2, 5)、(3, 4) などの完全にネストされた構成は、すべてのコードが LIFO ネストを尊重するため、すべてのコードを保持してスタックを完全に通過します。
