 ## 解決策
 ## 問題の理解

 次のサイズの正方形グリッドが与えられます$n \times n$そして正確に$k$ものと$n^2 - k$ゼロ。 タスクは、すべての値をグリッドに配置することです。 

グリッドが構築されたら、すべての行をバイナリ文字列として読み取り、すべての列をバイナリ文字列として読み取ります。 最小化したい「スコア」は、行と列を単一のコレクションとして扱う、すべての行とすべての列の中の個別の文字列の数です。 

したがって、多くの行が同一に見える場合、または多くの列が同じパターンを繰り返す場合、スコアは小さくなります。 すべての行と列が異なる場合、スコアは大きくなります。 

制約$n \le 1000$グリッドには最大 100 万個のセルがあることを意味します。 配置を検索したり、多数の候補グリッドをシミュレートしようとしたソリューションは、すぐに遅すぎます。 線形または線形に近い構造でパターンを直接構築する必要があります。$n^2$。 

微妙なエッジケースは次のような場合です$k$極端に小さい、または極端に大きい。 たとえば、次のようなとき$k = 0$、グリッドは強制的にすべてゼロになり、すべての行とすべての列が同一になります。 答えは自明のことですが、1 つの異なる行と 1 つの異なる列であるため、構造は特殊な場合のバグなしにきれいに縮退する必要があります。 同様に、$k = n^2$、すべては一つです。 

もう 1 つの重要な状況は次のような場合です。$k$に近いです$n$または$n^2 - n$ここで、単純な貪欲な行充填は、誤って列の多様性を増加させながら、多くの異なる行パターンを作成する傾向があり、これがまさに目的がペナルティを与えるものです。 

## アプローチ

 強引なアイデアは、あらゆる配布方法を試すことです。$k$向こうのもの$n^2$セルを抽出し、結果として得られる個別の行と列の数を計算します。 グリッドの数が次のとおりであるため、これは組み合わせ的に不可能です。$\binom{n^2}{k}$、これは$n = 1000$天文学的に大きいです。 

貪欲に行ごとに構築するように制限したとしても、依然としてハードカップリングに直面します。単一のセルを変更すると、その行と列の両方に影響が及ぶため、ローカルな決定がグローバルに伝播することになります。 列を制御せずに「個別の行を最小化」しようとしたり、その逆を試みたりする戦略はすぐに失敗します。 

重要な観察は、個別の行と列が個々の配置によってではなく、グリッドの構造によって左右されるということです。 行が少数のパターンを繰り返し、列が少数のパターンを繰り返す場合、スコアは小さくなります。 両方の方向に同時に繰り返しを強制する最も安定した方法は、構造がインデックスの合計、つまり反対角のみに依存するグリッドを構築することです。 

左上から右下へ対角線の順序でグリッドを埋め、これらの対角線に沿って連続して配置すると、どの行または列も予測可能なパターンのプレフィックスになることが保証されます。 これにより、すべての行が同じ対角パターンをシフトし、すべての列が同じことを行うため、行と列の両方で高い繰り返しが強制されます。 

この構造により、配布の問題が軽減されます。$k$任意のセルを選択するのではなく、固定された順序で対角線に沿って表示されます。

 ## アルゴリズムのチュートリアル

 対角順序を使用して決定論的にグリッドを構築します。 

1. を初期化します。$n \times n$グリッドはゼロで埋められます。 これにより、最初はすべての行と列が同一である有効なベースラインが保証されます。 
2. インデックスが付いた対角線を反復処理します。$s = 0$に$2n - 2$。 各対角線にはすべてのセルが含まれます$(i, j)$そのような$i + j = s$。 塗りつぶされたセルがこの順序で連続領域を形成するように、対角線を昇順に処理します。 
3. 対角線ごとに、すべての有効なセルを反復処理します。$(i, j)$その対角線上に。 クォータがまだ残っている場合は、セルに 1 を割り当てます。$k > 0$、およびデクリメント$k$。 それ以外の場合は 0 のままにしておきます。 
4. 次の場合は早めに中止してください。$k = 0$、必要なものがすべて配置されているため。 
5. 結果のグリッドを出力します。 

行優先の順序ではなく対角順序を使用する理由は、行優先の順序では 1 の長い水平プレフィックスが作成され、初期の行が密になり、後の行は空のままになり、多くの異なる行パターンが生成されるためです。 対角順序では、両方の次元にわたってより均等に分散されます。 

### なぜ効果があるのか

 対角線の順序で埋めることによって作成されたグリッドにより、任意の 2 行は対角線のスライディング ウィンドウの位置のみが異なり、同じ対称性が列にも当てはまります。 すべての行は同じグローバルな対角スイープから形成されるため、個別の行パターンの数は厳密に制御され、同じことが列にも当てはまります。 この構造では、独立した行方向または列方向の構造ではなく、共有されたグローバル構造が強制され、結合された多様性が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    grid = [[0] * n for _ in range(n)]
    
    for s in range(2 * n - 1):
        for i in range(max(0, s - (n - 1)), min(n, s + 1)):
            j = s - i
            if k > 0:
                grid[i][j] = 1
                k -= 1
    
    for row in grid:
        print("".join(map(str, row)))

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に完全なゼロ グリッドを構築し、すべての位置が割り当てに対して有効であることを確認します。 次に、対角線を反復処理し、有効なインデックス範囲を慎重に計算して、内向きのセルのみが訪問されるようにします。 

停止条件はチェックに暗黙的に含まれます`if k > 0`、過剰充填を防ぎます。 疲れた後も補充を続けるため、これは重要です$k$入力制約に違反します。 

対角インデックスのロジックは最もデリケートな部分です。固定額の場合です。$s$、 有効$i$からの範囲$\max(0, s - (n - 1))$に$\min(n - 1, s)$。 ここでの off-by-one エラーは、インデックスのクラッシュやセルの欠落につながります。

 ## 特殊なケース

 いつ$k = 0$、対角ループは実行されますが、割り当ては行われず、グリッドは完全にゼロのままになります。 すべての行とすべての列が同一であり、可能な限り最小限の多様性を生み出します。 

いつ$k = n^2$、斜めの移動中にすべてのセルが塗りつぶされます。 早期終了条件は決してトリガーされず、グリッドはすべて 1 になり、再び単一の行タイプと単一の列タイプが生成されます。 

いつ$k$は非常に小さいので、最初のいくつかの対角線のみが部分的に塗りつぶされます。 これにより、対角線は本質的に初期の配置を複数の行および列に分散させるため、単一の行または列内に長い構造化パターンが作成されることが回避されます。
