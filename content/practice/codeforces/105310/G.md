 ## 解決策
 ## 問題の理解

 内に一連の点が与えられます。$n \times n$グリッドであり、軸に沿った道路を生成する非常に珍しい建設プロセスを使用して、それらすべてを接続する必要があります。 すべての道路はグリッドの外側の境界から始まり、グリッド線に沿って内側に真っすぐに描かれます。 これは、以前に建設された別の道路に衝突するか、グリッドの反対側に到達するまで続きます。 道路は決して内側の地点から始まり、最初の交差点を越えて伸びることはありません。 

各道路は、その道路がまたがるグリッド交差点の数から 1 を引いた値 (グリッド単位での長さに相当) に等しいコストに寄与します。 

目標は、総コストを最小限に抑えながら、そのような道路のシーケンスを選択して、結果として得られる道路ネットワークを介して所定の建物がすべて接続されるようにすることです。 

構築ルールは幾何学的かつ手順的に聞こえるかもしれませんが、中心となる要件は組み合わせです。つまり、一連の点間の接続を誘導する一連の軸に整列したセグメントを選択しており、コストはセグメントの長さに比例します。 

制約は大きく、最大で$2 \cdot 10^5$ポイントと$n \le 2000$。 段階的な道路建設をシミュレーションしたり、考えられるすべての建設シーケンスを推論しようとするソリューションは失敗します。単一のシミュレーション ステップでさえ、以前に構築された構造に依存する可能性があり、シーケンスの数は指数関数的であるためです。 

直接解釈すると、微妙な失敗モードにもつながります。つまり、最終コストは単一の貪欲な建設注文に依存しません。 2 つの異なる有効な建設指示により、異なる中間交差点が生成される可能性があり、それによって停止点が変更され、コストが変更されます。 道路の局所的な最適配置を前提とする素朴で貪欲なアプローチは、初期の決定によって後続の道路が非自明な方法でブロックされたり短縮されたりする構成では機能しません。 

たとえば、3 つの点が L 字型を形成している場合、最も長い初期セグメントを優先する貪欲なアプローチでは、2 つのより短いセグメントにより全体の構造を改善できる安価な構成が妨げられる可能性があります。 

## アプローチ

 重要な問題は、道路が独立したオブジェクトではないことです。 道路が建設されると、それは将来のすべての道路の停止境界になります。つまり、その後のセグメントのコストは履歴全体に依存します。 これにより、直接シミュレーションや貪欲な順序付けが不可能になります。 

構造を解釈するより便利な方法は、プロセスを無視して最終的なジオメトリに焦点を当てることです。すべての道路は、共有の水平または垂直構造を通じて最終的に点を接続する軸に沿ったセグメントです。 重要な観察は、ポイント間の接続性は、構築の正確な順序ではなく、グリッド内の相対距離にのみ依存するということです。 

このタイプの構造は、問題がマンハッタン距離の下で最小スパニング ツリーを構築するのと同等であることを示す古典的な信号です。 道路建設の各ステップは、1 つの軸に沿った近隣のポイント間の接続を導入するものと見なすことができ、有効な完全接続の総コストは、マンハッタンの総コストが最小になるようにすべてのポイントにまたがるペアワイズ接続のセットを選択することに対応します。 

この解釈が受け入れられると、問題は 2 点間のエッジの重みがマンハッタン距離となる点に対する MST を計算することになります。$$|x_i - x_j| + |y_i - y_j|$$すべてのペアにわたる直接 MST は次の理由により不可能です。$O(m^2)$エッジ。 ただし、マンハッタン MST にはよく知られた構造があります。つまり、変換された座標系に沿ってソートされた順序で隣接する点間の候補エッジを考慮するだけで十分です。 具体的には、次のように並べ替えます。$x$、 による$y$、および 4 つの対角変換によって$x+y$、$x-y$など、すべての潜在的な MST エッジをキャプチャします。 

各ソート パスは隣接するポイントのみを接続し、$O(m)$パスごとのエッジがあり、最終的な MST は Kruskal のアルゴリズムを使用して構築できます。 

これにより、問題が二次エッジの考慮から線形候補の生成とソートに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | フルグラフ MST |$O(m^2 \log m)$|$O(m^2)$| 遅すぎる |
 | マンハッタンMSTのトリック |$O(m \log m)$|$O(m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各建物を 2D 空間内の点として扱います。 目標は、マンハッタン エッジの総コストを最小限に抑えてすべてのポイントを接続することです。 
2. ポイントをソートして候補エッジを生成します。$x$-この順序で連続するポイント間のエッジを調整して追加します。 連続するポイント間のコストは、マンハッタン距離です。 
3. 同じプロセスを繰り返して並べ替えます。$y$-座標。 
4. 対角構造をキャプチャするには、次の基準で並べ替えを繰り返します。$x+y$そしてによって$x-y$、それぞれの順序で連続するポイントを再度接続します。 
5. 生成されたすべてのエッジを 1 つのリストに収集します。 各エッジは、MST 内の妥当なショートカットを表します。 
6. これらのエッジ上で Kruskal のアルゴリズムを実行します。 エッジを重みで並べ替えてから、接続性を維持するために素の集合結合構造を使用してエッジを反復処理します。 以前に切断された 2 つのコンポーネントを接続する場合は、エッジを追加します。 
7. 選択されたすべてのエッジの重みの合計が最終的な答えになります。 

並べ替えベースのエッジで十分な理由は、マンハッタン ジオメトリでは、MST が常に少なくとも 1 つの単調順序で隣接する点を接続する必要があるためです。 隣接しない接続は、コストを増加させることなく、隣接する接続のチェーンに置き換えることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1
        return True

def add_edges(points, edges):
    n = len(points)

    points.sort(key=lambda x: x[1])
    for i in range(n - 1):
        x1, y1, id1 = points[i]
        x2, y2, id2 = points[i + 1]
        w = abs(x1 - x2) + abs(y1 - y2)
        edges.append((w, id1, id2))

    points.sort(key=lambda x: x[0])
    for i in range(n - 1):
        x1, y1, id1 = points[i]
        x2, y2, id2 = points[i + 1]
        w = abs(x1 - x2) + abs(y1 - y2)
        edges.append((w, id1, id2))

def main():
    n, m = map(int, input().split())
    pts = []
    for i in range(m):
        x, y = map(int, input().split())
        pts.append((x, y, i))

    edges = []
    add_edges(pts[:], edges)

    edges.sort()
    dsu = DSU(m)

    ans = 0
    for w, a, b in edges:
        if dsu.union(a, b):
            ans += w

    print(ans)

if __name__ == "__main__":
    main()
```この実装では、ソートされた順序で隣接する点のみをスキャンすることによって候補エッジを構築します。これにより、完全なグラフの構築が回避されます。 DSU はどの建物がすでに接続されているかを維持し、Kruskal は実際に接続に貢献する最も安価なエッジを常に選択できるようにします。 

最もデリケートな部分はエッジの生成です。マンハッタン MST では他のすべてのエッジが冗長であるため、ソート後の隣接するペアのみが使用されます。

 ## 特殊なケース

 2 点による最小限の構成では、アルゴリズムがマンハッタン距離を唯一必要なエッジとして正しく解釈するかどうかをテストします。 DSU は、追加の構造を必要とせずに、それらを即座に接続する必要があります。 

すべての点が 1 つの垂直線または水平線上にある縮退ケースでは、一度だけ並べ替えても正しいエッジのチェーンが生成されるかどうかがチェックされます。 このような場合、アルゴリズムは連続した点間のエッジのみを生成し、クラスカルは正確にエッジを選択します。$m-1$エッジ、それぞれが隣接するエッジ間のギャップに等しい。 

大きな座標ギャップを持つまばらな構成により、誤った長距離エッジが選択されることがなくなります。 隣接するソートされたペアのみが考慮されるため、このアルゴリズムでは MST 構造に違反するショートカットが導入されることはありません。
