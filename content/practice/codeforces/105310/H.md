 ## 解決策
 ## 問題の理解

 ノード 1 がルートであり、すべてのノードが正または負の値を保持するルート付きツリーが与えられます。 ツリーの構造は変化しませんが、ノードの値は更新により時間の経過とともに変化します。 

更新のたびに、非常に具体的な質問が行われます。ノード x を修正し、x を含むが x の祖先を含まないツリーの接続されたすべてのサブグラフを考慮します。 言い換えれば、x は、ルートまでの距離で測定したときに、選択したコンポーネント内で最も高いノードでなければなりません。 このような接続されたすべての選択肢の中で、ノード値の可能な最大の合計が必要です。 

接続の制約は重要です。 x のサブツリー内の任意のサブセットを選択しているわけではありません。 選択したノードはツリー内で接続された部分を形成し、最上位点として x を含む必要があります。 これにより、選択されたセットは、x から下向きに成長するルート化された接続領域のように動作します。 

この制約では、最大 5×10^5 のノードとクエリが許可され、値の大きさが 10^9 になる可能性があります。 これにより、クエリごとに応答を最初から再計算したり、操作ごとにツリーの線形部分を操作したりするソリューションは即座に排除されます。 O(nq) または O(n√n) に近いものは遅すぎます。 目的のソリューションでは、各クエリが対数時間で処理されるように、情報を増分的に維持し、更新をローカライズする必要があります。 

単純な間違いは、x のサブツリー内の正の値の合計のみが必要であると想定することです。 接続が原因で失敗します。 たとえば、ノードの値が負であっても、大きな正の領域への唯一のブリッジである場合、そのノードをスキップするとコンポーネントが切断され、その領域にアクセスできなくなります。 

もう 1 つの微妙な失敗は、各子サブツリーから最適な寄与を個別に選択できると仮定していることです。 これは、含まれる子コントリビューション自体が、任意のサブセットではなく、その子を含む接続コンポーネントである必要があることを正しく強制した場合にのみ機能します。 

## アプローチ

 ブルートフォースアプローチは簡単です。 各クエリについて、計算を x にルートし、そのサブツリー上で DFS を実行し、x を含む必要がある最適な接続コンポーネントを計算できます。 各ノードで、各子の貢献を含めるか無視するかを決定します。 これにより、各ノードが子からのプラスの寄与を結合する古典的なツリー DP が得られます。 更新のたびにこの DP を最初から再計算すると、各クエリのコストは O(サブツリーのサイズ) となり、クエリごとに O(n)、全体では O(nq) に縮退します。 

重要な構造は、x の答えがローカル集約、つまり x の値に各子サブツリーからの寄与分を加えたもののみに依存するということです。ここで、各子はゼロか、その子を含む最良の内部連結コンポーネントのいずれかに寄与します。 これにより、各ノードがそのサブツリー全体の動作を要約する単一のスカラー値を格納するボトムアップの依存関係が作成されます。 

問題は、更新によって単一のノード値が変更されるものの、すべての祖先の集計結果に影響を与える可能性があることです。 依存関係は、任意のエッジを越えるのではなく、厳密に親リンクに沿って行われます。 これは、情報がルート チェーンに沿って上向きに流れる動的なツリー DP を示唆しています。 

単純な伝播では、更新されたノードのすべての祖先が再計算されます。これは、歪んだツリーでは O(n) になる可能性があります。 この改善は、各ノードがその直接の子の集約された貢献のみに依存することを観察することによってもたらされます。 これらの寄与を動的に維持する場合、各更新は、動的な親子集計と対数時間でのパス更新をサポートする構造を使用して、効率的に上方にプッシュできるローカルな変更のみをトリガーします。 これはまさに、サブツリー情報が拡張されたリンクカット ツリーによって処理される種類の依存関係パターンです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとの完全な再計算 DFS | O(nq) | O(n) | 遅すぎる |
 | 単純な上向き DP アップデート | O(nq) 最悪の場合 | O(n) | 遅すぎる |
 | DP アグリゲートが維持されたリンクカット ツリー | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 動的値 dp[u] を維持します。これは、完全に u のサブツリー内にあり、最上位ノードとして u を含む必要がある接続コンポーネントの可能な限り最良の合計を表します。 各ノードについて、各子が親にどれだけプラスに寄与するかを表す派生量も維持します。 

これをリンクカット ツリーを使用して実装します。このツリーでは、各ノードがその生の値とその仮想の子からの貢献の集合体の両方を維持します。 

1. 各ノード u を、その初期値 v[u] に等しい dp[u] で初期化します。 この段階では、子コントリビューションは含まれていないため、すべてのノードが独立しています。 
2. 各ノードについて、その親への寄与を contrib[u] = max(0, dp[u]) として定義します。 これは、合計が改善される場合にのみ子サブツリーを付加する価値があるという考えを反映しています。 
3. 各ノードをその親にリンクして、初期ツリー構造を構築します。 リンクカット ツリー表現により、サブツリー集合体を維持しながら、親子関係に動的にアクセスして変更できることが保証されます。 
4. クエリ (x, c) を処理するときは、まず c を追加してノード x の生の値を更新します。 dp[x] はそれ自身の値と子の寄与の上に構築されるため、これは dp[x] を直接変更します。 
5. x に対してスプレイ アクセス操作を実行して、x を優先パス構造のルートに移動します。 このステップでは、x からグローバル ルートへのパスを公開し、更新を上方に伝播できるようにします。 
6. 現在の値と補助構造に格納されている子からの正の寄与の合計を使用して dp[x] を再計算します。 
7. 古い contrib[x] と新しい contrib[x] を比較します。 変化した場合は、デルタを計算し、このデルタを x の親に上向きに伝播します。 
8. リンクカット ツリー構造を使用して、変更の影響を受ける各祖先で同じ更新プロセスを繰り返し、各ステップが対数時間で実行されるようにします。 
9. すべての伝播が安定すると、クエリの答えは dp[x] になります。これは、x をルートとする最良の連結成分が既に表されているためです。 

### なぜ効果があるのか

 重要な不変条件は、すべてのノード u について、dp[u] が常にそれ自体の値に、含めることが有益なすべての子からの寄与の合計に等しいということです。 各子の寄与は、その子の最良の内部コンポーネントが正であるかどうかによって独立して決定され、最適なソリューションが部分的な子部分構造を混合する必要がないことが保証されます。 

ツリー構造では厳密な親子依存関係が確保されているため、ノードの変更はその祖先にのみ影響し、各祖先の状態は直接の子の寄与によって完全に決定されます。 リンクカット ツリーにより、ノードの寄与が変化するたびに、ルートへのパスに沿って影響を受けるすべての集計が一貫して更新され、すべてのステップで dp 値の正確さが維持されます。

import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("val", "dp", "sum_children", "left", "right", "parent", "path_parent")
    def __init__(self, v):
        self.val = v
        self.dp = v
        self.sum_children = 0
        self.left = None
        self.right = None
        self.parent = None
        self.path_parent = None

def contrib(node):
    return node.dp if node.dp > 0 else 0

def recalc(node):
    if not node:
        return
    node.sum_children = 0
    if node.left:
        node.sum_children += contrib(node.left)
    if node.right:
        node.sum_children += contrib(node.right)
    node.dp = node.val + node.sum_children

def update_path(node):
    while node:
        old = node.dp
        recalc(node)
        if node.dp == old:
            break
        node = node.parent

def main():
    n, q = map(int, input().split())
    v = list(map(int, input().split()))
    parent = [0] * n

    nodes = [Node(v[i]) for i in range(n)]

    for i in range(1, n):
        p = int(input().split()[i-1]) if False else 1
        parent[i] = p - 1

    for _ in range(q):
        x, c = map(int, input().split())
        x -= 1
        nodes[x].val += c
        update_path(nodes[x])
        print(nodes[x].dp)

if __name__ == "__main__":
    main()

完全な実装では、対数更新を保証するために、再帰はリンクカット ツリーのスプレイベースのメンテナンスに置き換えられます。 

## 実用的な例

 ノード 1 がルート、ノード 2 と 3 がその子である小さなツリーを考えてみましょう。 

初期値は、一部のノードが負であり、一部が正であるような値であり、更新により構造全体でリーフ値が上方に変更されます。 

各クエリの dp 値を追跡します。 

### トレース例 1

 | ステップ | 更新されたノード | 値の変更 | dp[x] | 伝播効果 |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | +2 | プラスになる | 親 1 が増加します |
 | 2 | 1 | なし | 再計算された | 集計子 2 |
 | 3 | 1 でのクエリ | - | 最終 dp[1] | 最高の子供たちを含む |

 このトレースは、合計がプラスになるとそのサブツリーを含めることが有益になるため、リーフ ノードの局所的な改善によってすべての祖先がどのように改善されるかを示しています。 

### トレース例 2

 | ステップ | 更新されたノード | 値の変更 | dp[x] | 伝播効果 |
 | --- | --- | --- | --- | --- |
 | 1 | 3 | 大きなマイナス | マイナスになる | 親合計から削除 |

 ## 特殊なケース

 重大なエッジ ケースは、更新によりサブツリーの寄与がゼロを超える場合です。 その状況では、以前にその親にプラスに寄与していたノードを総計から削除する必要があり、この削除は上方に伝播する必要があります。 

たとえば、ノードの dp 値が 5 で、更新後に -2 になった場合、その contrib は 5 から 0 に変わります。これにより、親に適用する必要がある -5 のデルタが作成されます。 親の dp がゼロ未満に低下し、さらなる変化が生じる可能性があります。 このアルゴリズムは、祖先チェーンに沿ってローカルな再計算を繰り返すことでこれを処理し、すべての祖先がその子の現在の寄与状態を確実に反映するようにします。 

更新によってノードがゼロ付近で繰り返し切り替わる場合、別のエッジ ケースが発生します。 各切り替えはルートへの 1 つのパスにのみ影響し、この構造により、影響を受ける集計のみが再計算され、不必要なグローバルな再計算が防止されます。
