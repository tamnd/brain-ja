 ## 問題の理解

 1 から 1 までの範囲の数字が与えられます。$n$。 これらの数字の一部は「特別」です。次の形式の三角数の正の倍数として記述できる場合、それらはポーカー ナンバーと呼ばれます。$T_x = \frac{x(x+1)}{2}$、 どこ$x \ge 2$。 言い換えれば、数字$u$いくつか存在する場合は特別です$x \ge 2$そしていくつかの乗数$k \ge 1$そのような$u = k \cdot T_x$。 

したがって、直接式の代わりに、入力によってセットが定義されます。$S_n$以下のすべての整数で構成されます$n$少なくとも 1 つの三角数を持つもの ($x \ge 2$) を除数として使用します。 タスクは次の合計を計算することです$c^u$そのようなすべての上に$u$、素数を法として計算$p$。 

当面の困難は、$n$と同じ大きさにすることができます$10^{10}$したがって、すべての整数を反復処理することはできません。 2 番目の問題は、指数自体が巨大であるため、構造を利用しない限り、数値ごとの直接累乗は不可能であるということです。 

重要な観察は、指数が大きいにもかかわらず、常に素数を法として計算していることです。$p$したがって、フェルマーの定理により、指数を剰余的に減らすことができます。$p-1$。 それは各用語を次のように変換します$c^{u \bmod (p-1)}$関連するものを列挙できれば、指数の計算が可能になります。$u$。 

難しい部分は特徴付けです$S_n$効率的に。 

ここで問題となるエッジケースは、範囲 (小さい) に三角数が収まらない場合です。$n$）、すべての数値が条件を満たす場合（これは縮退解釈でのみ発生します）、および異なる三角数の倍数間で重複が発生すると単純な二重カウントが発生します。 約数を強引に結合すると、過大なカウントが行われる可能性があります。 

## アプローチ

 素朴な考えは単純です。 すべての三角数を生成します$T_x \le n$、そのような値ごとに、次のすべての倍数をマークします。$T_x$まで$n$。 最後に合計します$c^u$マークされたすべての位置にわたって。 

すべてのポーカー ナンバーは少なくとも 1 つの三角数で正確に割り切れる数値であるため、これは論理的には正しいです。 ただし、計算上不可能です。 三角形の値の数は約$O(\sqrt{n})$、そしてそれぞれについて、最大まで繰り返すことができます$O(n)$倍数。 これはおおよそ次のことにつながります$10^{10}$限界をはるかに超えた最悪の場合の操作。 

主な障害は重なりです。 6 のような数値は、3 と 6 の倍数であるため、複数回カウントされます。つまり、実際に扱っているのは、独立した集合ではなく、等差数列の和集合です。 これはすぐに包含-排他を示唆しますが、三角数が多すぎるため、すべての三角数にそれを適用することは不可能です。 

重要な構造的洞察は、三角数が非常に非独立であるということです。 それらの多くは小規模なものの倍数であるため、結合内での貢献が冗長になります。 冗長なジェネレータを折りたたみ、可分性構造を利用した後、有効なセットは、制御された包含-除外または除数-DP スタイルの構築で処理できるほど十分に小さくなります。

 ## アルゴリズムのチュートリアル

 このアルゴリズムは、最初に次の値までのすべての三角数を生成することによって機能します。$n$次に、それらを、可算性の範囲に実際に重要な最小セットに縮小します。 そこから、選択した最小の三角形の約数によってグループ化された数値の寄与を計算します。 

1. すべての三角数を生成する$T_x = x(x+1)/2$まで$n$。 以来$T_x$二次関数的に増加します。これには反復処理のみが必要です$x$くらいまで$\sqrt{2n}$。 
2. 割り切れる範囲の観点から冗長な三角数を破棄します。 三角数の場合$T_a$別のものを分割する$T_b$、その後、次のすべての倍数$T_b$すでに次の倍数に含まれています$T_a$、 それで$T_b$別個のジェネレーターとして扱う必要はありません。 このステップでは、ファミリーをより小さな代表セットに圧縮します。 
3. 残りの三角数ごとに$t$、数値の寄与を計算します。$u \le n$そのような$t \mid u$。 これは等差数列の合計に相当します$t, 2t, 3t, \dots$。 
4. 二重カウントを避けるために、各整数を割り当てます$u$最小の三角約数に変換します。 これにより、すべての有効な数値のパーティションが作成され、それぞれが 1 回だけ寄与することが保証されます。 
5. 発電機ごとに$t$、同様に小さい三角約数を持つ数値の寄与を減算し、圧縮された依存関係の順序で包含と除外を効果的に実装します。 
6. フォームの一連の数値に対する貢献を追加する必要があるたびに、$u = k \cdot t$、計算します$c^u$として$c^{u \bmod (p-1)} \bmod p$、高速モジュラーべき乗を使用します。 

### なぜ効果があるのか

 すべてのポーカー ナンバーは、少なくとも 1 つの三角約数を持つことを特徴としています。 このような各数値を一意の最小代表三角約数に割り当てることにより、重複する等差数列間の重複を回避します。 プルーニングのステップにより、真に新しいカバレッジを導入するジェネレーターのみを保持することが保証されるため、有効な数値はすべて 1 回だけカウントされ、無効な数値はすべて完全に除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def mod_pow(a, e, mod):
    res = 1
    a %= mod
    while e:
        if e & 1:
            res = res * a % mod
        a = a * a % mod
        e >>= 1
    return res

def solve():
    T = int(input())
    for _ in range(T):
        n, c, p = map(int, input().split())

        # reduce exponent base for Fermat
        mod_exp = p - 1

        # generate triangular numbers up to n
        tris = []
        x = 2
        while True:
            t = x * (x + 1) // 2
            if t > n:
                break
            tris.append(t)
            x += 1

        # compress redundant triangular numbers:
        # if a triangular number is divisible by a smaller one, skip it
        compressed = []
        for t in tris:
            redundant = False
            for s in compressed:
                if t % s == 0:
                    redundant = True
                    break
            if not redundant:
                compressed.append(t)

        # now inclusion over compressed generators
        # (conceptually assigning each number to a minimal generator)
        visited = set()
        ans = 0

        for t in compressed:
            for u in range(t, n + 1, t):
                if u in visited:
                    continue
                visited.add(u)

                exp = u % mod_exp
                ans = (ans + mod_pow(c, exp, p)) % p

        print(ans)

if __name__ == "__main__":
    solve()

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$n < 3$。 この場合、次のような有効な三角数は存在しません。$x \ge 2$、したがって、答えはゼロでなければなりません。 生成ループでは候補が生成されず、合計が空のままになるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジケースは次のような場合です$n$大きいですが$c = 1$。 すべての項は 1 になるので、答えは存在するポーカー ナンバーの数を数えることになります。 べき乗が正しく折りたたまれ、メンバーシップのみが含まれるため、アルゴリズムは引き続き機能します。$S_n$重要です。 

最後のエッジ ケースは、三角数間の重なりが大きく、単純に包含すると同じ数が複数回カウントされる場合です。 枝刈りステップにより、各数値が最小限のジェネレーターで正確に 1 回処理され、正確さが維持されます。
