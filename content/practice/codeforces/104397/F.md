 ## 解決策
 ## 問題の理解

 Cookie サイズのコレクション (基本的には整数の配列) が与えられます。 この配列から、選択した要素が狭い値範囲内に収まるように Cookie のサブセットを選択します。選択した最大値から選択した最小値を引いた値が最大でも以下でなければなりません。`k`。 このような有効なサブセットすべての中で、取得できる要素の数を最大化することが求められます。 

入力サイズは最大 100 万まで可能で、値自体は 1e9 までの任意です。 の制約`k`は小さく、最大 9 です。これは、値の違いに大きく依存する解は、グローバルな組み合わせ論ではなく順序付けまたはローカル スキャンを使用して最適化できることを直ちに示唆しています。 

メモリ制限は 1 MB と非常に厳しく、値ドメイン上の周波数配列やそれに比例する補助構造は効果的に除外されます。`n`データの複数のコピーを保存します。 これにより、余分なストレージを最小限に抑えたインプレース処理またはソートされたストリーミング動作が推進されます。 

問題を値ごとの独立した頻度の集計として処理しようとすると、単純な落とし穴が発生します。 たとえば、Cookie が`[1, 100, 101, 102]`と`k = 2`、単純なグループ化では、連続する数値間隔の制約を強制することに注意しないと、互いに素な領域からのカウントが混在してカウントが過剰になる可能性があります。 

すべての値が同一である場合、別の微妙な特殊なケースが発生します。 例えば、`[5, 5, 5, 5]`どれでも`k`返すべきです`4`、および重複でウィンドウを誤ってリセットするスライディング ロジックはここで失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。考えられるすべてのサブセットを検討し、その最大値から最小値を引いた値が範囲内にあるかどうかを確認します。`k`、最大の有効なものを保持します。 ソート順で連続するサブセットに限定しても、開始と終了のペアをすべて列挙しようとする可能性があります。 ソート後、条件がすべての間隔をチェックするように減らされます。`[i, j]`そのような`a[j] - a[i] <= k`、最大長を取得します。 

これは直ちに次のことを示唆します`O(n^2)`すべてのペアをスキャンします。 と`n`1e6 までは、10^12 のオーダーで比較する必要があるため、これは完全に不可能です。 

重要な観察は、ソート後、最適なサブセットはソートされた配列内で連続したセグメントを形成する必要があるということです。 ソートが完了すると、ウィンドウを拡大すると最大値のみが増加し、ウィンドウを縮小すると最小値のみが増加するため、妥当性はスライド間隔条件として自然に表現されます。 これにより、問題はエンドポイント間の差が最大以下となる最長の部分配列を見つけることに変換されます。`k`。 

その構造はまさに 2 ポインター手法で捉えられるものです。 制約を維持しながら左側の境界を維持し、右側の境界を可能な限り延長し、必要な場合にのみ左側の境界を縮小します。 各要素はウィンドウに出入りするのは最大 1 回であるため、並べ替え後の時間は線形になります。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. Cookie サイズの配列を降順でない順に並べ替えます。 これにより、問題は、有効なサブセットがこの順序で連続セグメントとして表示されなければならない連続した値の間隔を扱う問題に変換されます。 
2. 2 つのポインタを初期化する`l = 0`そして`r = 0`、選択した Cookie の現在のウィンドウを表します。 いつでも、このウィンドウは候補サブセットを表します。 
3. 右ポインタを展開します`r`一歩ずつ。 展開するたびに、次のことを確認します。`a[r] - a[l] <= k`。 それが成立する場合、現在のウィンドウは有効であり、回答を更新できる可能性があります。 
4. 条件に違反した場合は、ウィンドウを左から大きくして縮小します。`l`条件が再び有効になるまで。 これは、増加するため機能します。`l`ウィンドウ内の最小値のみを減少させ、実現可能性を直接復元します。 
5. プロセス中、最大ウィンドウ サイズを維持します。`r - l + 1`。 これは、これまでに確認された中で最も有効なサブセットを表しています。 
6. まで続けます`r`配列の末尾に到達し、考えられるすべての正しいエンドポイントが 1 回だけ考慮されるようにします。 

### なぜ効果があるのか

 ソート後、有効範囲内にスキップされた要素を含めても最大値マイナス最小値の条件に違反できないため、制約を満たすサブセットは一般性を失うことなくソートされた順序で連続セグメントにマッピングできます。 2 つのポインタが不変なのは、各ステップでウィンドウが`[l, r]`現在のセグメントの有効性を維持する最小の左境界です。`r`。 これにより、次で終わる有効なセグメントが存在しないことが保証されます。`r`左側のインデックスが小さいと制約に違反し、大きいとサイズが不必要に減少するだけであるため、これは無視されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

a.sort()

l = 0
ans = 1

for r in range(n):
    while a[r] - a[l] > k:
        l += 1
    ans = max(ans, r - l + 1)

print(ans)
```この解決策は、有効なサブセットが値空間内の連続した範囲に対応するように配列を並べ替えることから始まります。 2 つのポインター ループはウィンドウを維持します。`[l, r]`常に制約を満たす`a[r] - a[l] <= k`。 制約が壊れるたびに、有効性が回復するまで左ポインタが進められます。 答えは、現在のウィンドウの長さを使用して各ステップで更新されます。 

ここでよくある間違いは、縮小は単一の条件ステップではなくループ内で発生する必要があることを忘れていることです。`l`制約が再度満たされる前に、必要になる場合があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    l = 0
    ans = 1
    for r in range(n):
        while a[r] - a[l] > k:
            l += 1
        ans = max(ans, r - l + 1)
    return str(ans)

# provided sample
assert run("6 3\n1 1 4 5 1 4\n") == "5"

# all equal
assert run("4 10\n7 7 7 7\n") == "4"

# k = 0 with duplicates
assert run("5 0\n2 2 2 3 3\n") == "4"

# strictly increasing, small k
assert run("5 1\n1 2 3 4 5\n") == "2"

# single element
assert run("1 5\n100\n") == "1"

 ## 特殊なケース

 エッジケースの 1 つは、すべての要素が同一である場合です。 このアルゴリズムは、正しいポインタを縮小することなく拡張し続けます。`a[r] - a[l]`は常にゼロです。 ウィンドウが配列全体になり、正しく生成されます。`n`。 

もう 1 つのエッジケースは次のような場合です`k = 0`しかし、値は繰り返されます。 共存できるのは同一の値のみであり、アルゴリズムは自然に等しい要素をグループ化します。 別の値が見つかった場合、ウィンドウに再びその値のみが含まれるまで左ポインタが進み、正確さが保証されます。 

最後のエッジケースは、小さい値を持つシーケンスを厳密に増加させることです。`k`。 ウィンドウは継続的にサイズ 1 または 2 に折りたたまれます。 たとえば、`[1,2,3,4]`そして`k = 1`、ウィンドウが隣接するペアを超えて拡大することはなく、アルゴリズムは正しく返します。`2`誤ってより長いスパンを許可するのではなく。
