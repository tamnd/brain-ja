 ## 解決策
 ## 問題の理解

 いくつかのバイナリ文字列が与えられ、それらを任意の順序で連結して 1 つの長いバイナリ文字列にすることができます。 連結したら、通常の意味で反転を数えます。つまり、`1`の前に表示されます`0`。 

タスクは、固定文字列の反転を計算するだけではなく、最終的な連結で生成される反転の数が最小限になるように入力文字列の順序を選択することです。 

単一の文字列内では、文字の相対的な順序は固定されているため、内部反転の影響は避けられません。 本当の自由は、異なる文字列がどのように相互作用するかによってもたらされます。ある文字列を別の文字列の前に配置すると、文字列が変化するたびに追加の反転が作成される可能性があります。`1`前の文字列は、`0`後の文字列で。 

この制約は、すべての文字列の合計の長さが最大 ​​100 万であることを意味します。 これにより、文字列のすべての順列や、文字列の数の二次関数さえも試行するソリューションは除外されます。 並べ替えベースのアプローチまたは連結全体にわたる線形スキャンが必要です。 

単純なアプローチでは、文字列のすべての順列を試し、そのたびに反転数を計算します。 再計算コストを無視しても、最大 10^6 の文字列では階乗増加が完全に不可能になるため、これは不可能です。 文字列が少なくても、順列ごとに反転カウントを再計算するには、すべての文字を繰り返しスキャンする必要があり、O(n! · total_length) のような結果になります。 

2 番目の単純なアイデアは、任意の順序で連結し、反転を 1 回計算することです。 この順序は文字列間の反転を大幅に変更するため、これは失敗します。 

文字列に 1 のみまたは 0 のみが含まれる場合、微妙なエッジ ケースが発生します。 例えば、`"111"`そして`"000"`順序に応じて大きく異なる動作をします。 もし`"111"`前に来る`"000"`、すべてのペアは反転に寄与しますが、反転は何も生じません。 正しい戦略は、この非対称性を捉える必要があります。 

## アプローチ

 反転カウントを 2 つの部分、つまり各文字列内の反転と文字列間に作成された反転に分けます。 

ご注文に関わらず内部は固定となります。 各文字列について、ペアの数を計算できます。`(1 before 0)`その内部では、その長さ全体にわたって線形時間で直接発生します。 

難しいのは文字列間の反転です。 文字列 A を文字列 B の前に置くとします。`1`A では、あらゆるものと反転を形成します。`0`したがって、B の前に A を順序付けることの寄与は次のようになります。```
cost(A before B) = ones(A) * zeros(B)
```それらを交換すると、コストは次のようになります。```
cost(B before A) = ones(B) * zeros(A)
```したがって、順序付けの問題は、ペアごとのスワップに依存するコストの合計を最小化する順列を選択することになります。 

この構造は、比較ルールを使用したスケジューリングまたは並べ替えの問題とまったく同じです。 2 つの文字列 A と B の場合、次の場合には A を B の前に置きます。```
ones(A) * zeros(B) <= ones(B) * zeros(A)
```並べ替えると、安定した順序付け条件が得られます。```
ones(A) / zeros(A) <= ones(B) / zeros(B)
```(ゼロがゼロの場合は慎重に取り扱います)。 

したがって、文字列を比率でソートすることで最適な配置が得られます。`ones / zeros`昇順で、文字列にゼロが含まれる特殊なケースには特別な処理が行われます。 

並べ替えたら、左から右にスイープし、次の数を維持します。`1`はすでに登場しています。 新しい文字列 B を配置すると、`0`B の内部では、以前のすべてのものとの反転が作成され、以下が寄与します。```
ones_so_far * zeros(B)
```また、その内部反転も追加します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての順列) | O(n!・L) | O(L) | 遅すぎる |
 | 最適 (ソート + リニア スイープ) | O(L log n) | O(L) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各文字列に含まれる 1 の数と 0 の数という 2 つの値を抽出することで、各文字列を前処理します。 このスキャンを実行している間、各ゼロの右側にいくつのゼロが残っているかを追跡することによって、その内部反転カウントも計算します。 

次に、すべての文字列を並べ替えます。 ソートキーは、比率をゼロで割った値です。 文字列にゼロが含まれる場合、その比率は無限大のように動作し、最適な順序付けにおいて前に来るべきではないため、その文字列はまだゼロを含むすべての文字列の後に配置されます。 

並べ替えた後、その順序で文字列を繰り返し処理します。 私たちは、これまでに出現したものの数を継続的に記録しています。 各文字列について、2 つの寄与を追加します。1 つはその文字列に対してすでに計算されている内部反転、もう 1 つはその文字列のゼロと以前のすべてのゼロのペアによって作成される相互反転です。 

次に、現在の文字列に 1 の数を追加して、実行中の 1 のカウンターを更新します。 

これが機能する理由は、2 つの文字列間の相互寄与が 1 と 0 の合計数にのみ依存するという事実から来ています。 隣接する文字列を交換すると、正確に比較することによって答えが変わります。`ones(A)*zeros(B)`と`ones(B)*zeros(A)`。 これにより、この問題は一貫性のあるコンパレータによる並べ替えと同等になり、この順序付けルールの隣接する反転が存在しなくなると、グローバルな並べ替えによって総コストを改善できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def inv_inside(s: str) -> int:
    zeros = 0
    inv = 0
    # count inversions of type 1 before 0
    for c in reversed(s):
        if c == '0':
            zeros += 1
        else:
            inv += zeros
    return inv

def key(item):
    ones, zeros, _ = item
    if zeros == 0:
        return (1, 0)  # treat as largest possible ratio
    return (0, ones / zeros)

def solve():
    n = int(input())
    items = []

    for _ in range(n):
        s = input().strip()
        ones = s.count('1')
        zeros = len(s) - ones
        items.append((ones, zeros, inv_inside(s)))

    items.sort(key=key)

    ones_so_far = 0
    ans = 0

    for ones, zeros, internal in items:
        ans += internal
        ans += ones_so_far * zeros
        ones_so_far += ones

    print(ans)

if __name__ == "__main__":
    solve()
```実装ではまず、各文字列の右側にゼロがいくつあるかをカウントする逆スキャンを使用して、各文字列の内部反転構造を分離します。 これにより、文字列ごとの二次的な動作が回避されます。 

ソート関数は、派生した順序付けルールをエンコードします。 ゼロを含む文字列は、最大キーを割り当てることによって強制的に末尾に移動されます。 他のすべての文字列では、1 と 0 の比率によって位置が決まります。 

最後のスイープでは、プレフィックスの 1 の合計を使用して文字列間の反転を累積します。これは正確にその数を表します。`1`それぞれ`0`現在の文字列内で相互作用します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    def inv_inside(s: str) -> int:
        zeros = 0
        inv = 0
        for c in reversed(s):
            if c == '0':
                zeros += 1
            else:
                inv += zeros
        return inv

    def solve():
        n = int(input())
        items = []
        for _ in range(n):
            s = input().strip()
            ones = s.count('1')
            zeros = len(s) - ones
            items.append((ones, zeros, inv_inside(s)))

        items.sort(key=lambda x: (1, 0) if x[1] == 0 else (0, x[0] / x[1]))

        ones_so_far = 0
        ans = 0
        for ones, zeros, internal in items:
            ans += internal
            ans += ones_so_far * zeros
            ones_so_far += ones

        return str(ans)

    return solve()

 ## 特殊なケース

 1 だけで構成される文字列は内部反転を持たず、クロス式で 0 = 0 を与えるため、どこに配置されても将来の反転は作成されません。 アルゴリズムは、その無限比率の動作により、そのような文字列を正しく最後に押し込み、その配置は合計に影響を与えません。 

ゼロのみで構成される文字列にも内部反転はありませんが、早い段階で配置されると相互反転に大きく寄与します。 ゼロ > 0 および 1 = 0 であるため、その比率は 0 であるため、自然にソート順の先頭に表示され、前のゼロへの露出が最小限に抑えられます。 

1/0 の比率が同一の文字列は、スワップ時に同じ順序コストを生成します。 アルゴリズムではそれらの間で任意の順序が許可され、プレフィックスと合計の定式化により、等比率交換によって最終的な答えが変更されないことが保証されます。`ones(A)*zeros(B) == ones(B)*zeros(A)`その場合に成立します。
