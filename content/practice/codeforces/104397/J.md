 ## 解決策
 ## 問題の理解

 ランク付けされた曲のリストが与えられます。各曲は最初は 1 から n までの固有の位置にあります。 すべての曲について、現在の位置が許容できるか、または変更する必要があるかについて、正確に 1 つの統合された意見を受け取ります。 最後のタスクは、これらの曲の新しい順列を構築することです。つまり、すべての意見を尊重しながら、すべての曲を 1 つの新しいランクに割り当てる必要があります。 

それぞれの意見によって、その曲の新しい位置が元の位置とどのように比較されるかが決まります。 曲の評価が低すぎる場合は、より良い (小さい番号の) ランクに移動する必要があります。 高すぎる場合は、より悪い (より大きな番号の) ランクに移動する必要があります。 正しいとマークされている場合は、正確にその場所に留まる必要があります。 出力は最終的なランキングそのものではなく、逆マッピングです。新しいランキングの位置 i で、元の位置がどの位置を占めるかを出力します。 

したがって、実際の決定は、pos[x] < x、pos[x] > x、または pos[x] = x などの制約を尊重しながら、元の各インデックス x を新しい位置 pos[x] に割り当て、1 から n の順列を形成することです。 

n はテスト ケースごとに最大 100,000、合計サイズが 200,000 になる可能性があるため、制約は厳しくなります。 これにより、二次代入や順列に対する単純な後戻りが排除されます。 すべての解は、テスト ケースごとに線形または n log n に近い必要があります。 

グローバル構造を使用せずに貪欲な直感を適用すると、微妙な失敗例が発生します。 たとえば、多くの曲が左に移動する必要があり、初期に少数のスロットしか存在しない場合、制約のある小さな曲を早く割り当てすぎると、後でより制約のある曲がブロックされる可能性があります。 別の失敗は、固定位置の曲がすぐに適用されずに遅れて処理される場合に発生します。 

具体的な問題となるシナリオは、2 つの曲が両方ともポジション 1 を望んでいるが、それを取得できるのは 1 つだけであり、恣意的に選択すると、代替手段のない固定ポジションの曲がポジション 2 でブロックされることになる場合です。 

## アプローチ

 ブルートフォースビューでは、これを制約をチェックしながら各曲を自由な位置に割り当てるものとして扱います。 順列を生成して検証したり、制約チェックでバックトラックしたりすることもできます。 これは、各代入が常に不等式条件を尊重することを保証するため、概念的に機能しますが、指数関数的な検索空間を探索します。 すべての決定は多くの有効な位置の中から選択することになるため、枝刈りを行っても、最悪の場合は階乗増加が依然として残ります。 

重要な構造上の観察は、各曲に任意の制約があるのではなく、有効な位置の単一の間隔があるということです。 低すぎるとマークされた曲は、元の位置よりも前のプレフィックスのどこかにのみ移動できます。 高すぎるとマークされた曲は、元の位置の後のサフィックスにのみ挿入できます。 正しい曲には、許可されるスロットが 1 つだけあります。 したがって、すべての曲はインターバル割り当ての問題になります。つまり、各項目を許容範囲内の一意の整数位置に割り当てます。 

このように再構成すると、問題はポイント 1 から n までの間隔をスケジュールすることになり、各タイム スロットは、それをカバーする 1 つの間隔だけで満たされる必要があります。 これは古典的な貪欲な割り当ての問題です。左から右に位置をスイープするときに、現在使用可能な間隔を維持し、最も緊急に配置する間隔を常に選択します。

 ## アルゴリズムのチュートリアル

 各曲を許容される位置の間隔に変換します。 もともと位置 x にあった曲の場合、0 とマークされている場合、その間隔は正確に [x, x] になります。 -1 とマークされている場合、その有効な位置は [1, x−1] です。 1 とマークされている場合、その有効な位置は [x+1, n] です。 

その後、1 から n までの位置を昇順に処理し、どの曲が各位置を占めるかを決定します。

1. まず、すべての曲を意見に基づいて音程 [L, R] に変換します。 これにより、n 個のスロットに配置する必要がある n 個の間隔のセットが得られます。 
2. スイープが開始点に達したときに間隔をアクティブにできるように、左端点 L ごとに間隔を並べ替えまたはグループ化します。 ポインタは、このソートされたリストを反復処理します。 
3. L がすでに ≤ 現在の位置 i であるすべての「アクティブ」インターバルの優先順位構造を維持します。 可能な限り早いスロットに到達すると、インターバルはアクティブになります。 
4. 位置 i の間隔を選択する前に、有効な場所に割り当てることができなくなるため、R < i であるアクティブな間隔を削除します。 これらの間隔はすでに不可能であるため、それより早く配置できない場合、構成は失敗します。 
5. 残りのすべてのアクティブなインターバルの中で、最小の R を持つインターバルを選択し、それを位置 i に割り当てます。 

最小の R を選択する理由は、期限が早い間隔が最も制約されるためです。 延期すると、すべての有効なスロットが失われる可能性がありますが、より柔軟な間隔を後で配置することはできます。 

1. 選択した間隔を使用済みとしてマークし、位置 i + 1 に進みます。 

### なぜ効果があるのか

 すべてのステップ i で、アルゴリズムは、有効な割り当てが存在する場合、破棄されていない間隔のうち i をカバーする少なくとも 1 つの間隔が常に存在することを保証します。 最小の適切なエンドポイントの間隔を選択すると、柔軟な間隔で初期スロットを無駄にすることが回避されるため、将来の実現可能性が維持されます。 これにより、未割り当てのすべての間隔が将来のセグメントに少なくとも 1 つの可能な位置が残っているという不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        intervals = []
        
        for i in range(1, n + 1):
            p, x = map(int, input().split())
            if p == 0:
                L, R = x, x
            elif p == -1:
                L, R = 1, x - 1
            else:
                L, R = x + 1, n
            intervals.append((L, R, x))
        
        intervals.sort()
        
        import heapq
        res = [0] * (n + 1)
        heap = []
        idx = 0
        
        for i in range(1, n + 1):
            while idx < n and intervals[idx][0] <= i:
                L, R, x = intervals[idx]
                heapq.heappush(heap, (R, x))
                idx += 1
            
            while heap and heap[0][0] < i:
                heapq.heappop(heap)
            
            if not heap:
                print(-1)
                break
            
            R, x = heapq.heappop(heap)
            res[i] = x
        
        else:
            print(*res[1:])

solve()
```コードはまず、各意見を具体的な間隔に変換します。 次に、これらの間隔を左側のエンドポイントで並べ替えて、スイープ順序でアクティブ化できるようにします。 最小ヒープは、現在有効なエンドポイントの中で最小の右エンドポイントを持つ間隔を常に取得するために使用されます。 

各位置 i で、L ≤ i であるすべての間隔がヒープに挿入されます。 次に、R < i が削除される無効な間隔。 ヒープの先頭には、割り当てるべき最も緊急の間隔が与えられます。 これにより、厳しい制約を遅らせることがなくなります。 

結果の配列には、必要な出力形式と一致する、各位置に配置される元のインデックスが格納されます。 

よくある落とし穴は、R < i の区間は選択前に破棄する必要があることを忘れていることです。 もう 1 つは、直接置換ではなく逆マッピングを要求する出力要件を誤解していることです。 

## 実用的な例

 n = 3 の小さなケースを考えてみましょう。 

入力:

 1 1

 -1 2

 0 3

 間隔は次のようになります。 

1 → [2,3]

 2 → [1,1]

 3 → [3,3]

 ポジションを処理します:

 | 私 | アクティブな間隔 | 選ばれた | 理由 |
 | --- | --- | --- | --- |
 | 1 | [2,2] アクティブなし | - | [2,2] だけがまだアクティブではありません |
 | 2 | [2,3]、[2,2] | 2 | 固定間隔は位置 2 を取る必要があります |
 | 3 | [1,3]、[3,3] | 3 | 3 または残りの有効な間隔で固定 |

 これは、固定制約が自然に配置を強制する一方で、柔軟な制約がそれに合わせて適応することを裏付けています。 

次に、競争が激しい場合を考えてみましょう。 

n = 4

 1 -1 1

 -1 2

 -1 3

 0 4

 間隔:

 1 → [1,0] はすぐに無効になるため、慎重に扱わない限り不可能であり、間隔の有効性が重要である理由を示しています。 位置 1 にアクティブな間隔が存在しない場合、アルゴリズムは早期に拒否します。 

これは、実現可能性が各ステップでローカルに適用されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各間隔はヒープから 1 回プッシュおよびポップされます。 
| スペース | O(n) | 間隔、ヒープ、および結果の配列を保存する |

 すべてのテスト ケースの n の合計は最大 2 × 10^5 であるため、ヒープベースのスイープは時間制限内に簡単に収まります。 各演算は対数的であり、定数係数は小さいです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    import sys as _sys

    input = _sys.stdin.readline

    def solve():
        T = int(input())
        out = []
        for _ in range(T):
            n = int(input())
            intervals = []
            for i in range(1, n + 1):
                p, x = map(int, input().split())
                if p == 0:
                    L, R = x, x
                elif p == -1:
                    L, R = 1, x - 1
                else:
                    L, R = x + 1, n
                intervals.append((L, R, x))

            intervals.sort()
            import heapq
            heap = []
            idx = 0
            res = [0] * (n + 1)

            for i in range(1, n + 1):
                while idx < n and intervals[idx][0] <= i:
                    L, R, x = intervals[idx]

                res[i] = x

 ## 特殊なケース

 単一の固定位置ソングの場合、その間隔は [x, x] であるため、アルゴリズムはすぐに配置します。 ヒープにはその位置に有効な選択肢が 1 つだけ含まれているため、あいまいさは生じません。 

複数の曲が初期の位置に依存する厳しく制約されたチェーンの場合、最小の R を選択するという貪欲なルールにより、最も制限の厳しい曲が最初に配置され、後で行き詰まりになるのを防ぎます。 

あるステップで必要な間隔が使用可能な位置をカバーしないような不可能な構成の場合、ヒープは空になり、アルゴリズムは無効な割り当てを続行するのではなく、直ちに -1 を正しく出力します。
