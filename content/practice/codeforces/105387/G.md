 ## 解決策
 ## 問題の理解

 長さのシーケンスが何個あるかを数えるように求められます`n`赤、緑、青の 3 色を使用して形成できます。シーケンス内の各位置は立方体になります。 唯一の制限は、その制限を超えて連続ブロック内に色を表示できないことです。赤の最大ストリーク長は次のとおりです。`k_r`、緑は`k_g`、そして青は`k_b`。 

したがって、任意の長さのシーケンスを選択する代わりに、`n`、サイズ 3 のアルファベットにわたるすべての有効な文字列をカウントします。各文字には、連続して繰り返される場合に許可される独自の最大ランレングスがあります。 

出力は、そのような有効なシーケンスの数を法にしたものです。`10^9 + 7`。 

この制約により、シーケンスを列挙したり、可能なすべてのランレングスにわたって完全な状態を明示的に維持したりするソリューションからは遠ざけられます。 以来`n`最大 100 万までの可能性があり、状態ごとに線形または二次関数のアプローチでも可能です。`n`失敗します。 各色の位置と最後のランレングスを追跡する単純な動的プログラミングにより、おおよそのサイズの状態空間が得られます。`n * k`、両方が到達できる場合、これは大きすぎます。`10^6`。 

2 番目の素朴な試みは、最後の色とランレングスのみを追跡し、遷移を直接反復することですが、それでも、状態ごとの遷移は最大で依存します。`k_c`以前の状態で、再び$O(n \cdot k)$最悪の場合。 

いくつかの特殊なケースでは、素朴な推論の落とし穴が明らかになります。 もしすべてなら`k_r = k_g = k_b = 1`の場合、隣接する 2 つの立方体を同じ色にすることはできません。 答えは次のようになります`3 * 2^(n-1)`。 長さ 1 のランを誤って拡張することを許可する単純な DP は、次のような小さな入力に対してもすぐにオーバーカウントしてしまいます。`n = 2`。 もう 1 つのエッジ ケースは、1 つの制限が非常に大きい場合です。たとえば、`k_r = 10^6`他は小さいです。 すべての色の実行を対称的に盲目的にキャップするソリューションは、関連する水平線内で決して発生すべきではない赤色の遷移に不必要な制限を誤って課す可能性があります。 

最大の難点は、各色に独自の独立した「メモリ ウィンドウ」があり、すべての有効なシーケンスをカウントしながら、その制約を効率的に適用する必要があることです。 

## アプローチ

 ブルートフォース手法では、考えられるすべての長さのシーケンスが構築されます。`n`連続実行をスキャンして検証します。 各ステップは 3 つの選択肢に分岐するため、$3^n$シーケンス、さらには各シーケンスのチェックにも時間がかかります$O(n)$、不可能につながる$O(n \cdot 3^n)$ランタイム。 

より構造化された動的プログラミングのアプローチでは、次のことが考慮されます。`dp[i][c][l]`、長さのシーケンスの数`i`色で終わる`c`現在のランレングスで`l`。 これは実行制約を明示的に強制するので正しいですが、次のように拡張されます。$O(n \cdot (k_r + k_g + k_b))$州は、最悪の場合でもまだ大きすぎます。 

重要な観察は、実際には正確なランレングス分布を明示的に追跡する必要がないということです。 特定の色のランを延長する場合に重要なのは、その色の前のランがすでに最大許容長に達しているかどうかです。 すべての有効な遷移は、各色の最近の履歴にわたる累積カウントとして表現できます。 

これにより、状態が 3 つのシーケンスに圧縮されます。`dpR[i]`、`dpG[i]`、 そして`dpB[i]`、ここで、それぞれは有効な長さのシーケンスの数を表します。`i`あの色で終わる。 一連の色の延長`c`最後だけに依存する`k_c`これは、繰り返しに埋め込まれたスライディング ウィンドウのアイデアを使用して維持できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 |$O(3^n \cdot n)$|$O(n)$| 遅すぎる |
 | ランレングスを伴う状態 DP |$O(n \cdot k)$|$O(n \cdot k)$| 遅すぎる |
 | スライドトランジションを備えた最適化された DP |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 長さから段階的に答えを構築します`1`に`n`、3 つの配列を維持`dpR`、`dpG`、 そして`dpB`。 

1. 一定の長さのシーケンスの基本ケースを初期化します。`1`。 それぞれの単一立方体は任意の色にすることができ、長さは一定であるため、それぞれが有効です。`1`いかなる制約にも違反することはありません。 それで`dpR[1] = dpG[1] = dpB[1] = 1`。 
2. ポジションごとに`i`から`2`に`n`、各色で終了するシーケンスの数を計算します。 まず赤を考えます。 有効な長さのシーケンス`i`赤で終わるものは一連の長さから来ている必要があります`i-1`そして赤い立方体を追加します。 
3. 赤色の拡張子を 2 つのカテゴリに分割します。 前のキューブが赤でなかったか、赤だったが赤のランを延長することができます。 最初のカテゴリは貢献します`dpG[i-1] + dpB[i-1]`。 
4. 既存のレッドランの拡張として、以下を追加します。`dpR[i-1]`ただし、これは、赤色のランがすでに最大許容長に達しているシーケンスを上回ります。 これらの無効な拡張子は、赤色が次の位置で実行されるシーケンスに正確に対応します。`i-1`すでに長さがある`k_r`、シフト項を使用して除外できます`dpR[i-1-k_r]`。 
5. これにより再発が生じます`dpR[i] = dpR[i-1] + dpG[i-1] + dpB[i-1] - dpR[i-1-k_r]`、インデックスが範囲外の場合、減算は省略されます。 
6. それぞれの制限を使用して、同じロジックを緑と青に対称的に適用します。`k_g`そして`k_b`。 
7. すべての状態を満たした後、`n`、3 つの終了状態を合計して、有効なシーケンスの総数を取得します。 

重要な不変条件は次のとおりです`dpC[i]`常に、有効な長さのシーケンスをすべて正確にカウントします。`i`最後の立方体は色です`C`、その時点までにすべての実行制約が満たされています。 すべての拡張機能が異なる色から新しい実行を開始するか、有効な実行を継続するため、反復処理ではこの不変条件が維持されます。また、減算により、実行が許容制限を超えるシーケンスが正確に削除されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, kr, kg, kb = map(int, input().split())

    dpR = [0] * (n + 1)
    dpG = [0] * (n + 1)
    dpB = [0] * (n + 1)

    dpR[1] = dpG[1] = dpB[1] = 1

    for i in range(2, n + 1):
        # Red
        val = (dpR[i - 1] + dpG[i - 1] + dpB[i - 1]) % MOD
        if i - 1 - kr >= 0:
            val = (val - dpR[i - 1 - kr]) % MOD
        dpR[i] = val

        # Green
        val = (dpR[i - 1] + dpG[i - 1] + dpB[i - 1]) % MOD
        if i - 1 - kg >= 0:
            val = (val - dpG[i - 1 - kg]) % MOD
        dpG[i] = val

        # Blue
        val = (dpR[i - 1] + dpG[i - 1] + dpB[i - 1]) % MOD
        if i - 1 - kb >= 0:
            val = (val - dpB[i - 1 - kb]) % MOD
        dpB[i] = val

    print((dpR[n] + dpG[n] + dpB[n]) % MOD)

if __name__ == "__main__":
    solve()
```実装は繰り返しを直接反映します。 各色は同じ遷移ロジックを使用して独立して処理されますが、独自の制約長が使用されます。 減算ステップは、無効な実行が許容制限を超えて拡張されるのを防ぐため、唯一デリケートな部分です。 値を範囲内に保ち、減算後の負の結果を安全に処理するために、モジュロ演算がすべてのステップに適用されます。 

このパターンの実装でよくある間違いは、Python の負の数のモジュロには正規化が必要であることを忘れていることです。 を使用して`% MOD`減算後は正確さを保証します。 

## 実用的な例

 インプットを考慮する`5 2 2 2`。 すべての色は対称的に動作し、長さ 2 までのすべてのランが許可されます。 

| 私 | dpR[i] | dpG[i] | dpB[i] |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 |
 | 2 | 2 | 2 | 2 |
 | 3 | 6 - dpR[0] = 6 | 6 | 6 |
 | 4 | 18 - dpR[1] = 17 | 17 | 17 |
 | 5 | 同様に計算される | | |

 各ステップで、シーケンスの総数は、制約された 3 色のフィボナッチのような拡張のように増加します。 長さから引き算が重要になり始める`kr + 2`、2 を超える実行は除外されるようにします。 これにより、すべての色間の遷移をカウントしながら、繰り返しがローカル実行制限を正しく適用していることが確認されます。 

のために`6 1 1 3`、赤と緑は厳密な交互制約のように動作しますが、青ではより長い実行が可能になります。 

| 私 | dpR[i] | dpG[i] | dpB[i] |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 |
 | 2 | 2 | 2 | 3 |
 | 3 | 4 | 4 | 8 |
 | 4 | 8 | 8 | 20 |
 | 5 | 16 | 16 | 48 |
 | 6 | 32 | 32 | 112 |

 このトレースは、より厳しい制約が赤と緑の状態の成長をどのように崩壊させるかを示していますが、青は組み合わせの拡張を支配しています。 再帰により、共有された前のステップの合計を超えて相互干渉することなく、これらの効果がきれいに分離されます。

 ## 特殊なケース

 のために`n = 1`、拡張する前の状態がないため、繰り返しでは遷移を試みるべきではありません。 初期化`dpR[1] = dpG[1] = dpB[1] = 1`このケースを直接カバーしており、合計は`3`これは、単一の立方体が制約に関係なく有効であるという事実と一致します。 

のようなケースの場合`3 1 1 1`、すべての色の変更は厳密に交互に行われなければなりません。 アルゴリズムは、長さを超えてランを延長しようとする試みを正しく差し引きます。`1`、次のようなシーケンスが効果的に確保されます。`RR`または`GG`決してカウントされません。 計算結果`12`3 色にわたる長さ 3 の有効な交互シーケンスの正確な数と一致します。
