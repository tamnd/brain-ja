 ## 解決策
 ## 問題の理解

 非常に大きなグリッドが与えられていますが、その中の少数のセルのみがマークされています。 この状態から、1 つの空のセルを選択し、4 つの基本的な方向の 1 つを選択できます。 選択した方向では、ゲームは、水平移動または垂直移動のどちらを選択したかに応じて、同じ行または同じ列に沿ってその方向に厳密に存在するすべてのマークされたセルを破壊します。 

目標は、破壊されたマークされたセルの数ができるだけ多くなるように、空の開始セルと方向を選択することです。また、この最大値を達成する有効な開始位置を 1 つ出力する必要もあります。 

グリッド サイズは両方の次元で最大 10^9 まで可能ですが、マークされるセルは最大 200,000 個のみです。 これにより、ソリューションの構造は完全なグリッド表現ではなく、マークされたセルのみに依存する必要があることがすぐにわかります。 

強引な解釈では、すべての空のセルを試し、それぞれの行と列をスキャンして、各方向にマークされたセルの数をカウントします。 空のセルの数は実質的に n・m から k を引いたものとなり、膨大になる可能性があるため、これは不可能です。 

より微妙な制約は、方向の選択では位置合わせのみが考慮されるという事実から生じます。 セルを修正すると、行または列内のマークされたセルのみが問題になります。 これは、問題を行方向と列方向の頻度情報に圧縮することを示唆しています。 

単純な推論による一般的な失敗例は、最適な位置がマークされたセル上またはその隣にあると仮定した場合に発生します。 これは誤りです。行または列の極値のマークされた位置の外側に開始点を配置すると、その行内のすべてのマークされたセルがキャプチャされる可能性があるからです。 

たとえば、列 3 と列 10 にマークが付いている行を考えます。同じ行の列 1 に開始点を置くと、右方向全体が両方のマークを破壊します。 マークされたセルに隣接する位置のみを考慮するソリューションでは、これを見逃してしまいます。 

別の失敗例は、マークされたすべてのセルが単一の行または列にある場合に発生します。 そのような状況では、別の行または列のセルを選択することは依然として有効であり、行が完全に埋まっているかどうかに応じて必要になる可能性があります。 

## アプローチ

 直接的なブルート フォース アプローチでは、すべての空のセルを反復処理し、4 方向に到達可能なマークされたセルの数を計算します。 各候補セルについて、ハッシュ セットまたは二分探索を使用してその行と列をスキャンすると、最悪の場合、セルあたり O(k) のコストがかかります。 空のセルの数は本質的に n・m であるため、このアプローチは完全に実行不可能です。 

重要な点は、グリッド構造は、マークされたセルを行および列ごとにグループ化すること以外には無関係であるということです。 行を修正したら、重要なのはその行にマークされたセルがいくつ存在するかだけです。 同じことが列にも当てはまります。 

マークされたセルが t 個ある固定行の場合、その行の空のセルを選択するとします。 マークされた細胞がまたがる間隔の外側に配置すると、すべての t 細胞を一方向で捕捉できます。 間隔内に配置すると、行を左右の部分に分割できますが、それでも t − 1 が限界です。グリッドが大きく、行が完全に埋まらない限り少なくとも 1 つの空の位置があるため、いつでもマークされた範囲の外側の位置を選択して、値 t を与えることができます。 

したがって、各行は、完全に埋まっていない限り、マークされたセルの数に影響します。 同一の引数が列に適用されます。 

これにより、選択した行または列に少なくとも 1 つの有効な空のセルが存在することを確認しながら、行頻度と列頻度を計算してそれらの最大値を取得する作業が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・m・k) | O(k) | 遅すぎる |
 | 最適 | O(k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

問題を行統計と列統計に分けます。 

1. マークされたセルをすべて読み取り、行および列ごとにグループ化します。 各行にはそのマークされた列のリストが保存され、各列にはそのマークされた行のリストが保存されます。 グリッドに関して必要な情報はこれだけです。 
2. 各行について、その行に含まれるマークされたセルの数を計算します。 カウントが m に等しい場合、この行には空のセルがなく、開始位置として使用できないため、無視します。 
3. 使用可能な行ごとに、その行内のマークされたセルの数に等しい候補スコアを計算します。 また、最良の行とその数も追跡します。 
4. 列に対して同じプロセスを繰り返します。 列のカウントが n に等しい場合、その列は完全に占有されており、使用できません。 それ以外の場合、候補スコアはその列内のマークされたセルの数になります。 
5. 行の最高スコアと列の最高スコアを比較します。 大きい方が答えです。 両方がゼロであるか、有効な行/列が存在しない場合、有効な移動はなく、答えは座標 0 0 のゼロになります。 
6. 最適な行の開始セルを再構成するには、最大カウントの行を選択し、その行でマークされていない列インデックスを見つけます。 行にはマークされたセルが最大でも k 個あるため、セット内に存在しない列インデックスが見つかるまで、1 から始まる列インデックスを試すことができます。 同じロジックが最適な列にも当てはまります。 

これが機能する理由は、空のセルが少なくとも 1 つある行では常にマークされた列のセグメントの外側に開始点を配置し、マークされたすべてのセルを一方向にキャプチャできるという事実に基づいています。 したがって、その行で達成可能な最良の水平方向の破壊は、その行内のマークされたセルの数と同じになります。 同じ議論が列にも対称的に当てはまります。 すべての有効な動きは何らかの行または列に固定されている必要があるため、全体的な最適値はこれらの行ごとの最大値の中に現れる必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    row = {}
    col = {}
    marked = set()

    for _ in range(k):
        x, y = map(int, input().split())
        marked.add((x, y))
        if x not in row:
            row[x] = []
        if y not in col:
            col[y] = []
        row[x].append(y)
        col[y].append(x)

    best = 0
    best_type = None  # 0 for row, 1 for col
    best_idx = None

    for x, ys in row.items():
        t = len(ys)
        if t < m:
            if t > best:
                best = t
                best_type = 0
                best_idx = x

    for y, xs in col.items():
        c = len(xs)
        if c < n:
            if c > best:
                best = c
                best_type = 1
                best_idx = y

    if best == 0:
        print(0)
        print("0 0")
        return

    if best_type == 0:
        x = best_idx
        forbidden = set(row[x])
        y = 1
        while y in forbidden:
            y += 1
        print(best)
        print(x, y)
    else:
        y = best_idx
        forbidden = set(col[y])
        x = 1
        while x in forbidden:
            x += 1
        print(best)
        print(x, y)

if __name__ == "__main__":
    solve()
```このコードは、まず行と列の隣接リストを構築し、同時にメンバーシップ クエリを迅速に行うためにマークされたすべてのセルを追跡します。 メインの選択ループは、有効な開始セルを含めることができないため、完全に塗りつぶされた行を破棄しながら、最良の行および列の候補を計算します。 

再構成ステップは意図的に単純です。選択したラインでマークされていない座標が見つかるまで、1 から上向きにスキャンします。 マークされたセルの数が少ないため、これは安全であり、選択したラインごとに最悪の場合でもスキャンは k によって制限されます。 

## 実用的な例

 サンプル入力を考えてみましょう。 

マークされたカウントを持つ行があります。行 3 には 2 つのマークがあり、行 6 には 1 つ、行 12 には 1 があります。列 4 には 2 つのマークがあり、列 7 と 11 にはそれぞれ 1 つのマークがあります。 

| ステップ | 行 3 | 6行目 | 12行目 | 4列目 | 列 7 | 11列目 |
 | --- | --- | --- | --- | --- | --- | --- |
 | カウント | 2 | 1 | 1 | 2 | 1 | 1 |
 | 有効？ | はい | はい | はい | はい | はい | はい |

 最大値は 2 で、行 3 または列 4 から達成できます。アルゴリズムは行 3 を選択し、その行内のマークされていない列 (4 など) を選択します。 

これは、行と列の両方のパースペクティブで同じ最適値が得られ、有効な再構成が許容されることを示しています。 

ここで、行が完全に埋まっている場合を考えてみましょう。 

入力:```
1 5 5
1 1
1 2
1 3
1 4
1 5
```空のセルはまったくありません。 アルゴリズムはすべての行と列が無効であることを正しく識別するため、ゼロを出力します。 

これは、完全に占有されているラインを除外することが重要であることを示しています。そうしないと、そこに開始点を配置できると誤って仮定してしまうからです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k) | マークされた各セルは 1 回処理され、再構成では最大 k 個の位置がスキャンされます。 
| スペース | O(k) | 行と列のリストとマークされたセルのセットを保存します。 

この制約により、マークされたセルは最大 200,000 個まで許可されるため、k を超える線形解は容易に十分高速になります。 グリッドを反復処理することはないので、グリッド サイズは無関係です。

 ## 特殊なケース

 主なエッジ ケースは、マークされたすべてのセルが行全体を占める場合です。 この状況では、有効な空の開始セルがないため、その行は何も寄与しません。 このアルゴリズムは、行数が m に等しいかどうかを明示的にチェックし、スキップすることでこれを処理します。 

別のエッジ ケースは、最適なソリューションが行ではなく列にある場合に発生します。 再構築ロジックは行処理を反映しており、その列内の最初のマークされていない位置をスキャンすることで、有効な空の座標が確実に見つかるようにします。 

3 番目のエッジ ケースは、k が 0 に等しい場合です。 その場合、すべてのセルは空になりますが、どの移動によっても何も破壊されません。 アルゴリズムは正しくゼロを返し、任意の座標を受け入れます。ここでは 0 0 として表されます。
