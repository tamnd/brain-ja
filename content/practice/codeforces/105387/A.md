 ## 解決策
 ## 問題の理解

 膨張と呼ばれる形態学的操作が適用された後の画像を表すバイナリ グリッドが与えられます。 各セルは黒 (`#`) または白 (`.`）。 変換ルールはローカルです。出力内のピクセルは、元のイメージですでに黒であるか、隣接する 8 つのピクセル (対角線を含む) のうち少なくとも 1 つが黒の場合に黒になります。 

タスクが逆になります。 拡張された画像が与えられるので、この規則に従ってその画像を生成した可能性のある元の画像が存在するかどうかを判断する必要があります。 存在する場合は、有効な元のイメージを構築する必要があります。 

主な問題点は、膨張により黒いピクセルが外側に拡張されるため、複数の異なる元の構成が同じ最終イメージをもたらす可能性があることです。 したがって、逆のプロセスは一意に決定されず、場合によっては不可能です。 

グリッドの寸法は最大でも 100 x 100 なので、O(nm) または O(nm log nm) のソリューションが快適に使用できます。 セル近傍推論をシミュレートするアプローチはどれも問題ありませんが、サブセットにわたる指数関数的なものは不必要であり、実行不可能です。 

出力内の黒いピクセルが、考えられるソース ピクセルによって「説明」できない場合、微妙なエッジ ケースが発生します。 たとえば、あるセルが黒だが、その隣接するセルがすべて白である場合、そのセルは同じ位置にある黒のオリジナルからのみ得られる可能性があります。 それはいつでも大丈夫です。 本当の矛盾は、膨張後に与えられた画像と正確に一致しなければならないオリジナルを再構築しようとするときに発生しますが、局所的な一貫性制約が重複する近傍間で競合します。 

たとえば、拡張結果に余分な黒セルを強制することなく、元のソースを同時に割り当てることができない位置に孤立した黒ピクセルが表示されるパターンを考えてみましょう。 単純な貪欲な再構成では、原点の黒を誤って割り当て、黒のピクセルが過剰に生成される可能性がありますが、正しいアプローチでは推測を回避し、代わりに「必要なソース」を特定することによって逆方向に作業します。 

## アプローチ

 強引なアイデアは、考えられるすべてのオリジナル グリッドを試すことです。 オリジナルの各セルは黒または白であり、2^(nm) の可能性があります。 候補ごとに膨張をシミュレートし、指定されたグリッドと比較します。 これは正しいですが、10 x 10 のグリッドでもすでに 2^100 の構成が得られるため、完全に実行不可能です。 

重要な観察は、膨張が単調で局所的であるということです。出力内の黒ピクセルは、元の 3 × 3 の近傍にある少なくとも 1 つの黒ピクセルから来ている必要があります。 これは、セルごとに逆の推論ができることを意味します。出力内のセルが黒の場合、その隣接するセル (セル自身を含む) の少なくとも 1 つは元のセルでは黒でなければなりません。 出力内のセルが白である場合、元のセル内の隣接するセルは黒であってはなりません。 

これにより、建設的な制約システムがすぐに得られます。 出力内のすべての白いセルは、元の 3 行 3 列の近傍にあるすべての黒い割り当てを禁止します。 このような制約をすべて適用すると、一部のセルが強制的に白になり、他のセルが潜在的に黒のままになる、元のグリッドの候補が得られます。 次に、出力内のすべての黒セルの近傍に利用可能なソース セルが少なくとも 1 つあるかどうかを確認します。 そうでなければ再建は不可能です。 それ以外の場合は、黒のセルごとに 1 つの有効な近傍に黒を安全に割り当てることができます。 

これにより、問題は一定サイズの近傍を持つグリッド上の制約の伝播に変換され、線形時間に短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(nm) · nm) | O(nm) | 遅すぎる |
 | 制約に基づいた再構成 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 黒としてマークされたすべてのセルで初期化された候補オリジナル グリッドを作成します。 不可能な黒の位置のみを削除するため、これは最も寛容な開始点を表します。 
2. 出力画像内のすべての白いセルについて、元のグリッド内の 3 × 3 の近傍を検査し、それらのすべての位置を強制白としてマークします。 これは、白い出力セルがオリジナルの黒いピクセルの影響を受けてはならないという規則に基づいています。 
3. 白いセルからすべての制約を適用すると、部分的に固定された元のグリッドが得られます。 この時点では、出力内の一部の黒いセルはまだ説明できない可能性があります。 
4. 出力イメージ内の各黒いセルについて、元のグリッド候補内の 3 × 3 の隣接セルのうちの少なくとも 1 つがまだ黒いかどうかを確認します。 そのような近隣が存在しない場合、再構築は不可能です。 
5. すべての黒出力セルに少なくとも 1 つのサポート元の黒候補がある場合は、残りの許可されたセルで正確に黒を選択して有効なオリジナルを作成します。 このような割り当ては必要な拡張を生成するのに十分であるため、これ以上の最適化は必要ありません。 
6. 結果を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、拡張ルールを逆にエンコードします。 白い出力セルは、ハード除外制約を強制し、その近傍にある考えられる黒のソースをすべて排除します。 黒の出力セルには存在制約が適用されます。少なくとも 1 つのソースがその近傍に存在する必要があります。 これらの制約は純粋にローカルであり、異なるセル間で独立しているため、それらを個別に満たすことでグローバルな一貫性が保証されます。 共有グリッド位置を超えるセル間の依存関係はなく、その構造により、禁止された構成が導入されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def inb(x, y, n, m):
    return 0 <= x < n and 0 <= y < m

n, m = map(int, input().split())
b = [list(input().strip()) for _ in range(n)]

# start with all black possible
a = [['#' for _ in range(m)] for _ in range(n)]

# step 1: white cells eliminate sources in 3x3 neighborhood
for i in range(n):
    for j in range(m):
        if b[i][j] == '.':
            for dx in (-1, 0, 1):
                for dy in (-1, 0, 1):
                    ni, nj = i + dx, j + dy
                    if inb(ni, nj, n, m):
                        a[ni][nj] = '.'

# step 2: verify black cells can be explained
for i in range(n):
    for j in range(m):
        if b[i][j] == '#':
            ok = False
            for dx in (-1, 0, 1):
                for dy in (-1, 0, 1):
                    ni, nj = i + dx, j + dy
                    if inb(ni, nj, n, m) and a[ni][nj] == '#':
                        ok = True
                        break
                if ok:
                    break
            if not ok:
                print("Impossible")
                sys.exit()

print("Possible")
for row in a:
    print("".join(row))
```このソリューションでは、すべて黒に初期化された候補のオリジナル イメージを構築します。 これは重要です。なぜなら、私たちは可能性を排除するだけであり、実現可能性を検証する場合を除いて黒さが必要であるとは決して想定しないからです。 

最初のパスでは、出力内のすべての白いセルが処理されます。 各白いピクセルは周囲の 3 x 3 領域に黒いソースを禁止するため、候補グリッド内のすべての位置を安全に白に変換します。 これにより、拡張定義から必要なすべての制約が強制されます。 

2 番目のパスでは、出力内のすべての黒ピクセルの近傍に少なくとも 1 つのサポート黒候補があることが保証されます。 黒の出力セルがそのようなサポートを欠いた瞬間に、有効なオリジナルがそれを生成できないため、終了します。

 ## 特殊なケース

 クリティカル エッジ ケースは、元々黒ピクセルが含まれる可能性がある領域を白ピクセルが完全に囲む場合に発生します。 たとえば、出力に黒のセルが 1 つある 3 × 3 グリッドでは、周囲のすべてのセルが白の場合、アルゴリズムによって近傍全体が強制的に白に設定され、その黒ピクセルの考えられるソースが排除されます。 最終チェックでは、サポートが存在しないことが正しく検出され、「不可能」が出力されます。 

もう 1 つのエッジ ケースは、黒いピクセルが遠く離れて孤立している場合です。 このような場合、各黒セルは独立して少なくとも 1 つの候補ソースを必要とします。 近傍は局所的な重複を超えて干渉しないため、アルゴリズムは競合することなく有効なソースを自然に割り当て、制約の独立性が維持されることを示しています。 

3 番目のエッジ ケースは、完全に白いグリッドです。 すべてのセルは、少なくとも 1 つの制約によって白に強制されるか、不要なままになり、黒のセルをサポートする必要はありません。 このアルゴリズムは、有効な全白のオリジナルを正しく出力します。
