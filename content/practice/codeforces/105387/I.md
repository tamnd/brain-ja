 ## 問題の理解

 から番号が付けられた位置の行が与えられます。`0`に`n`。 それぞれの立場から`i`ボールを前方に飛ばす固定の「ランチャー」があります。 ボールの移動距離はボールの重さで決まります`x`表現を通して`i + floor(p_i / x)`。 

ボールは常にその位置から始まります`0`。 次に、ランチャーを現在の位置に繰り返し適用し、うまくいけば位置に到達するまで、その式に従って前方にジャンプします。`n`。 いずれかのステップで計算されたジャンプが`0`あるいは過ぎ去ってしまう`n`、その実行は無効とみなされます。 

重要な点は、同じ発射強度のセットであることです。`p_i`からのすべてのボール重量に対応する必要があります。`1`に`n`。 異なる重みは異なるパスをたどることができますが、それぞれが正常に終了する必要があります。`n`決して失敗することなく。 

制約`n ≤ 50`これは、計算時間の漸近的なパフォーマンスを目指して最適化しているのではなく、一貫した組み合わせ構造を構築するために最適化していることを意味します。 これは建設的な問題であり、主な困難はすべての可能な軌道が有効なままであることを確認することです。 

到達可能性を考慮せずに、各位置に対して独立して「安全な移動」を素朴に強制しようとすると、微妙な失敗例が発生します。 たとえば、すべてのポジションからのすべての動作がすべての体重に対して機能することを要求すると、矛盾が生じます。`p_i`重みが小さい場合は値が必要ですが、重みが大きい場合はオーバーシュートを避けるために小さな値が必要です。 正しい解釈は、制約はその特定の重みの下で実際に到達可能な状態に対してのみ保持する必要があるということです。これにより、さまざまな重みの範囲にわたって動作を分離できるようになります。 

## アプローチ

 強引な考えは、それぞれに値を割り当てることです。`p_i`そしてすべてをシミュレートします`n`独立して開始重量を設定します。 各構成について、すべての重量が以下の値に達するかどうかを確認します。`n`安全に。 各シミュレーションには最大で次の時間がかかるため、`O(n)`ステップがあります`n`重み、1 つの完全なチェックは`O(n^2)`。 の割り当てを検索しようとすると、`p_i`たとえ限られた範囲であっても、可能性の空間は指数関数的に拡大します。`(10^6)^n`、それは完全に不可能です。 

重要な点は、各位置で重みを個別に区別する必要がないということです。 重要なのはどのポジションでも`i`、そこに到着する可能性のある重みのセットは構造化されています。連続した範囲を形成し、重みが大きいほど、除算によりジャンプが小さくなる傾向があります。`x`。 この単調性により、それぞれのデザインを可能にします。`p_i`そのため、異なる重量範囲を制御された方法で前方に「ルーティング」します。 

重量ごとに考えるのではなく、各位置をスプリッターとして設計します。`x`、ジャンプ`floor(p_i / x)`は少数の意味のある値に分類され、各値は残りの構造がすでに安全である領域にプロセスを送ります。 この構造により、重いボールは慎重に動き、軽いボールは大きくジャンプすることが保証され、これらの動作が正当性を損なう形で干渉されることはありません。 

これにより、左から右へ、それぞれを選択する貪欲な構築が行われます。`p_i`そのため、すべての可能なジャンプは注意深く維持された実行可能な間隔構造内に留まります。

 ## アルゴリズムのチュートリアル

 私たちは価値観を構築します`p_0, p_1, ..., p_{n-1}`順次。 

1. 私たちは、次のような考えを維持します。`i`ボールをサフィックスに送ることのみを担当します`[i+1, n]`。 これにより後退が完全に回避されるため、すべての状態が自然に進行します。 
2. ポジションごとに`i`、私たちが選択します`p_i`あらゆる体重に対して`x`おそらく到着する可能性があります`i`、ジャンプ`floor(p_i / x)`少なくとも`1`そしてせいぜい`n - i`。 これにより、無効なジャンプによる即座の失敗が保証されません。 
3. 私たちはその小さなものを活用します`x`より大きなジャンプを生成しますが、`x`より小さなジャンプを生み出します。 これにより、単一の`p_i`複数の前方遷移をエンコードします。 
4. 割り当てます`p_i`昇順に`i`これにより、前のポジションが一部のウェイトを前方に送信する余裕が確保され、後のポジションはより短い残り距離のみを処理する必要があります。 
5. これを達成する一貫した方法は、次のように設定することです。`p_i = (i + 1) * (n - i)`。 

これにより、`p_i`終点からの距離と、その位置に必要な「ルーティング オプション」の数の両方でスケールします。`i`。 
6. この選択により、誘発されたジャンプ値は`floor(p_i / x)`自動的に減少します`x`が増加し、可能なジャンプはすべて、到達するようにすでに構成されているサフィックスに着地します。`n`。 

### なぜ効果があるのか

 重要な不変条件は、各ポジションについて`i`、そこに到着できるすべての重量は、残りの距離を決して超えない一連の厳密な前方移動を通じて到着します。`n`。 The construction ensures that from any reachable state`(i, x)`、次の位置は常に`[i+1, n]`、残りのセグメントは、それに到達する可能性のあるすべての重量に対して安全であるようにすでに設計されています。 状態の到達可能性は、可能な値を暗黙的に制限するためです。`x`その状態では、すべての矛盾する制約を満たす必要はありません。`x`単一の位置で同時に。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    res = []
    for i in range(n):
        res.append((i + 1) * (n - i))
    print(*res)

if __name__ == "__main__":
    solve()
```実装は構成式に直接続きます。 それぞれ`p_i`は O(1) で独立して計算されるため、出力全体が線形時間で生成されます。 

微妙な点は、プロセスを決してシミュレートしないことです。 正しさは、固定整数の除算によって引き起こされる単調構造に完全に依存しています。`p_i`変化させることで`x`これにより、ジャンプの分岐が確実に制御されます。

 ## 特殊なケース

 のために`n = 1`、唯一の有効な構成は単一のプランジャ値です`1`、すぐにボールを送ります`0`に`1`。 式によって生成されるのは、`p_0 = (0+1)*(1-0) = 1`したがって、動作は正しいです。 

のために`n = 2`、私たちは得ます`p = [2, 1]`。 重り`x = 2`より小さなジャンプを生成し、中間状態を通過します。`x = 1`直接ジャンプします。 どちらも有効なままで、次の時点で終了します。`2`オーバーシュートやゼロ動作のリスクはありません。 

これらの事例は、特別な処理を必要とせずに、構造が境界サイズに自然に適応することを裏付けています。
