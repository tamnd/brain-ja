 ## 解決策
 ## 問題の理解

 店舗を表すグリッド上での制約された歩行をシミュレートしています。 グリッドには、$n$行と$m$列。各セルは空かブロックされています。 人間はグリッドの左下隅から開始し、その後、一連の長い移動コマンドに従います。 各コマンドは 4 つの基本的な方向のいずれかに 1 歩ずつ移動しようとしますが、移動は自由ではありません。その方向の次のセルがブロックされているか、グリッドの外側にある場合、人はすぐに停止し、現在の位置に留まります。 

タスクは、このようなコマンドの非常に長いシーケンスを処理した後に最終位置を計算することです。 

重要な解釈は、各コマンドは連続的なスライドではなく、正確に 1 ステップの移動を試みるということです。 動作はコマンドごとに個別であるため、障害物で停止するという文言は、すぐ隣のセルを越えると事実上無関係です。 

制約は非常に直接的な意味で重要です。 グリッドは最大で$1000 \times 1000$、直接保存して一定時間内にインデックスを付けるのに十分な大きさです。 コマンド文字列は最大で$2 \cdot 10^6$これにより、ソリューションは各文字を一定時間で処理するように強制されます。 パスを再計算したり、ラインをスキャンしたり、方向スイープで可視性をシミュレートしたりするアプローチは、グリッド サイズにコマンドの数が乗算されるため、遅くなりすぎます。 

素朴ですがよくある間違いは、各コマンドを障害物に当たるまで続く「光線」として解釈することです。 たとえば、あるポジションにいて、`R`、壁にぶつかるまで誤って右方向にスキャンしてしまう可能性があります。 これにより、各コマンドが$O(m)$最悪の場合、$O(nm|s|)$まったく実行不可能な行動です。 

もう 1 つの微妙な問題は、座標の向きです。 開始位置は左下のセルで、移動方向によって行と列のインデックスが非標準的な方法で増加または減少します。 行 1 が上か下かを混同すると、動きの解釈が不正確になります。 

最後に、境界の処理が重要です。 グリッドから離れようとする動きは、部分的に適用されるのではなく、完全に無視されなければなりません。 

## アプローチ

 ブルート フォース解釈では、各コマンドは、障害物または境界に遭遇するまでその方向にグリッドをスキャンする必要がある可能性があるものとして扱われます。 各命令について、中間位置のグリッド セルを確認しながら、段階的に繰り返し進めます。 最悪の場合、1 回の移動で行または列全体がスキャンされる可能性があり、これはコマンド文字列内のすべての文字で発生する可能性があります。 と$2 \cdot 10^6$コマンド以降$10^6$グリッド セルを使用すると、許容制限をはるかに超える膨大な数のセル チェックが発生します。 

重要な観察は、動きが連続的ではないということです。 各コマンドは、正確に 1 セル分だけ移動しようとします。 障害物がすぐ隣接するセル内でのみ問題になることがわかると、シミュレーション全体が単純な状態更新になります。つまり、1 つの隣接セルをチェックし、移動するか留まるかのいずれかになります。 

これにより、パス シミュレーションの問題が直接グリッド ステッピングに軽減されます。 命令ごとに定数時間の配列ルックアップのみが必要です。

 ## アルゴリズムのチュートリアル

 グリッドを静的な障害物マップとして扱い、単一の現在位置を維持します。 

1. セルが一定時間内にブロックされているかどうかをテストできるように、グリッドを読み取り、2D 配列に保存します。 これは、すべての移動が直接の隣接性チェックに依存するため必要です。 
2. 行に対応する左下のセルの開始位置を初期化します。$n$、 カラム$1$標準のトップダウンインデックス、または同等の行を使用する場合$0$、 カラム$0$ゼロベースの座標で。 
3. 文字列内の各コマンド文字について、行/列デルタとして目的の方向を計算します。 これにより、問題は状態遷移の繰り返しに変換されます。 
4. 移動を適用する前に、次の位置の候補を計算します。 移動をコミットする前に検証する必要があるため、この分離は重要です。 
5. 候補位置がグリッド境界内にあるかどうかを確認します。 外側にある場合は、コマンドを完全に無視して、現在の位置を維持します。 
6. 位置が境界内にある場合は、セルがブロックされているかどうかを確認します。 ブロックされた場合も無視します。 
7. それ以外の場合は、現在位置を候補セルに更新します。 
8. すべてのコマンドを処理した後、1 から始まるインデックスで最終座標を出力します。 

中心となる考え方は、すべてのコマンドは有効な隣接遷移を生成するか、何も行わない結果となり、どのコマンドも複数のセルに影響を与えることはないということです。 

### なぜ効果があるのか

 アルゴリズムは、最初の処理後の不変条件を維持します。$i$コマンドを実行すると、現在の位置は、すべてのステップで強制される即時ブロックと境界制約を使用して、これらのコマンドを順番に適用した結果となります。 各コマンドは、現在の位置のみに依存し、その位置を超えた以前のパス履歴には依存しないという意味で独立しています。 移動をコミットする前に正当性を評価するため、無効なセルに入ったりグリッドから離れたりすることはありません。また、すべてのコマンドが順番に 1 回だけ処理されるため、有効な遷移がスキップされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    s = input().strip()

    # convert to 0-based indexing, start bottom-left
    x, y = n - 1, 0

    for c in s:
        nx, ny = x, y

        if c == 'U':
            nx -= 1
        elif c == 'D':
            nx += 1
        elif c == 'L':
            ny -= 1
        else:  # 'R'
            ny += 1

        if 0 <= nx < n and 0 <= ny < m and grid[nx][ny] == '.':
            x, y = nx, ny

    print(x + 1, y + 1)

if __name__ == "__main__":
    main()
```このソリューションではグリッドをメモリに読み込むため、各障害物チェックは直接配列にアクセスされます。 位置はゼロベースの座標で保存され、原点は実質的に配列の左上になります。 この問題では左下での開始が定義されているため、初期化します。$x = n - 1, y = 0$。 

各コマンドはデルタ更新に変換されます。 私たちは常に最初に候補の位置を計算し、次にコミットする前に境界と障害物の制約に対してそれを検証します。 これにより、偶発的な部分更新や一貫性のない状態の変更が回避されます。 

最終出力は、必要に応じて 1 から始まるインデックスに変換されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    s = input().strip()

    x, y = n - 1, 0

    for c in s:
        nx, ny = x, y
        if c == 'U':
            nx -= 1
        elif c == 'D':
            nx += 1
        elif c == 'L':
            ny -= 1
        else:
            ny += 1

        if 0 <= nx < n and 0 <= ny < m and grid[nx][ny] == '.':
            x, y = nx, ny

    return f"{x+1} {y+1}"

# sample 1
assert run("4 4\n....\n....\n....\n....\nDRLU\n") == "1 1"

# sample 2
assert run("4 4\n...#\n....\n....\n....\nDRUL\n") == "1 2"

# custom: single cell
assert run("1 1\n.\nURDL\n") == "1 1"

# custom: blocked neighbors
assert run("2 2\n.#\n..\nURR\n") == "2 1"

# custom: long harmless moves
assert run("3 3\n...\n...\n...\n" + "R"*1000000) == "3 3"

 ## 特殊なケース

 エッジケースの 1 つは、すべての動きがグリッドから離れようとする場合です。 たとえば、左下隅から開始して繰り返し発行します。`D`または`L`コマンド。 アルゴリズムは各動きを独立して評価し、候補位置が範囲外であることを検出し、現在の状態を変更しないで維持します。 無効な動作の蓄積は発生しません。 

もう 1 つのケースは、開始位置の周囲が完全にブロックされている場合です。 コマンドが移動を示唆している場合でも、隣接するセルのチェックはすべて失敗します。`#`, そのため、位置が変わることはありません。 このアルゴリズムは、コマンドごとにすべてのチェックを一定時間で実行します。 

3 番目のケースは、コマンド文字列が非常に長い場合です。 各反復では算術演算と単一の配列検索のみが実行されるため、ランタイムは線形にスケールされ、グリッドの次元に依存しません。
