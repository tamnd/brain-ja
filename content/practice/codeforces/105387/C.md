 ## 問題の理解

 火星の温度センサーから送信された、歪んだ 32 ビット整数の一連の測定値が与えられます。 ハードウェア障害は時間の経過とともに一貫しています。ビット位置の一部の固定サブセットが測定ごとに反転されています。つまり、それらの位置では、記録されたすべてのビットが真の信号に対して反転されています。 

単一の 32 ビット整数を選択できます$k$。 すべての測定値を xor すると、$k$、どのビットを反転するかを効果的に選択します。 目標は、非常に特殊な形状を持つシーケンスを再構築することです。まず、少なくとも 2 つの連続する要素が非減少であり、次に少なくとも 2 つの連続する要素が非増加である必要があります。 2 つのフェーズは中間で重なる可能性があるため、シーケンスはピークで平坦化できますが、増加傾向の後に減少傾向が続くように動作するセグメントが存在する必要があります。 

タスクは、有効な値を決定することです。$k$これにより、変換されたシーケンスは、両側の最小プラトー長が 2 となり、この「平らなプラトーを持つ山が許可される」動作を満たすようになります。 

制約$n \le 10^4$重要です。 すべてを試した解決策$2^{32}$の候補者$k$すぐには無理です。 候補のすべてのペアまたは位置のすべてのペアにわたる二次スキャンでさえ、すでに境界線に達していますが、$O(n \log n)$または$O(n \cdot 32)$スタイルのビットごとの推論が受け入れられます。 

微妙なエッジ ケースは、有効な形状が厳密に「厳密に増加し、その後厳密に減少する」わけではないということです。 プラトーは許可されており、2 つのモノトーン部分にはそれぞれ少なくとも 2 つの要素が含まれている必要があります。 これにより、シーケンスが一定であるか、または 1 ステップの変更しかないような簡単な解決策は除外されます。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての値を試行します。$k$、すべての要素に xor を適用し、結果のシーケンスが必要な形状を満たしているかどうかを確認します。 それぞれのチェックは、$O(n)$、そしてそれ以来$k$以上の範囲$2^{32}$、これはまったく実行不可能であり、最悪の場合の操作数は$O(2^{32} \cdot n)$。 

重要な観察は、xor が各ビット位置で独立して動作するということです。 これは、それぞれのビットを意味します$k$すべての要素にわたってそのビットを反転するかどうかを決定します。 したがって、完全な整数について考える代わりに、各ビットがシーケンスの順序構造にどのような影響を与えるかを考えることができます。 

重要な構造的洞察は、「最初は減少せず、その後は増加しない」という条件が隣接する値間の比較のみに依存し、それが変換後のビットごとの比較に依存するということです。 xor はビットごとの相対構造を保持するため、ビットの制約について推論できます。$k$ペアかどうかによって引き起こされる$t_i, t_{i+1}$シーケンスの異なる部分で特定の方向に比較する必要があります。 

これは建設的なアプローチにつながります。つまり、シーケンス形状の比較の有効な方向を推測し、そのビットに対する制約を導き出すことを試みます。$k$そのため、xor の後、変換されたシーケンスはその形状を尊重します。 この構造にはピーク遷移が 1 つだけあるため、問題を、シーケンスを非減少プレフィックスと非増加サフィックスに分割する比較の一貫した割り当てを決定することに問題を集約し、ビット制約を通じてこれらの比較を強制することができます。 

有効なモノトーン分割が修正されると、隣接する各比較が形式の制約になります。$t_i \oplus k \le t_{i+1} \oplus k$またはその逆。 このような各不等式は、次の最上位の異なるビットに対する制約に変換できます。$t_i$そして$t_{i+1}$これは標準的なトリックです。xor は最も重要な異なるビットの位置を保持するため、実現可能性は一貫したビット選択に減ります。$k$すべての制約にわたって。

 ## アルゴリズムのチュートリアル

 有効な$k$これは、変換されたシーケンスを増加フェーズとそれに続く減少フェーズに強制的に分割できるようにすることによって行われます。 正確な分割点が指定されていないため、そのような分割が存在するという考えをテストし、それに応じて制約を導き出します。 

1. 隣接するペアを調べます$t_i, t_{i+1}$そして、遷移が増加フェーズにあるか減少フェーズにあるかに応じて、変換されたシーケンス内でどのような順序を満たさなければならないかを決定します。 目標は、少なくとも 1 つの有効なピーク分割が存在することを確認することです。 
2. 任意の注文候補者について$a \le b$または$a \ge b$変換後、次のように書き換えます$t_i \oplus k \le t_{i+1} \oplus k$。 この不等式は最上位ビットによって支配されます。$t_i$そして$t_{i+1}$xor はどのビットが最初に異なるかを変更しないためです。 
3. それぞれの不等式を制約に変換します。$k$上位ビットを反転すると、そのビットが 2 つの値の比較において決定ビットである場合に限り、比較が逆転することがわかります。 下位ビットは比較結果に影響しません。 
4. すべての隣接するペアにわたって制約を蓄積し、どのビット位置も矛盾する要件を受けないことを保証します。 競合が発生した場合、分割の仮定は無効となり、分割点または方向が調整されます。 
5. 一貫した割り当てが見つかったら、再構築します。$k$ビットごとに、少なくとも 1 つの制約によって強制された場合にのみ各ビットを設定します。 
6. 最後に、これを適用することを確認します。$k$有効な非減少セグメントの後に少なくとも 2 の長さの非増加セグメントが続くシーケンスを生成します。 

### なぜ効果があるのか

 正確さは、2 つの XOR 変換された数値間のすべての比較が、それらが異なる最上位ビットによって完全に決定されるという事実に依存しています。 xor はすべての要素にわたってビットを均一に反転するだけなので、どの位置が決定ビットの候補であるかは変更されず、その極性のみが変更されます。 これにより、各不等式制約が、一貫したビットレベル制約のセットに縮小されます。$k$。 シーケンスは 1 つの転換点を持つ単峰性である必要があるため、有効な分割が存在する場合に限り、制約はグローバルに一貫したシステムを形成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(k, t):
    n = len(t)
    r = [x ^ k for x in t]

    inc = [False] * n
    dec = [False] * n

    inc[0] = True
    for i in range(1, n):
        inc[i] = inc[i-1] and r[i-1] <= r[i]

    dec[n-1] = True
    for i in range(n-2, -1, -1):
        dec[i] = dec[i+1] and r[i] >= r[i+1]

    for i in range(n):
        if inc[i] and dec[i]:
            if i >= 1 and i + 1 < n:
                if inc[i] and (i == 0 or r[i-1] <= r[i]) and (i == n-1 or r[i] >= r[i+1]):
                    if inc[i] and dec[i]:
                        return True
    return False

def solve():
    n = int(input())
    t = list(map(int, input().split()))

    # try to construct k bit by bit greedily
    k = 0

    for bit in range(31, -1, -1):
        candidate = k | (1 << bit)
        if check(candidate, t):
            k = candidate

    print(k)

if __name__ == "__main__":
    solve()
```このソリューションでは、次の貪欲な構造を使用します。$k$最上位ビットから下に向かって。 各ステップで、ビットの設定が有効な単峰構造を形成する可能性を維持しているかどうかをテストします。 ヘルパー関数は、変換されたシーケンスを再構築し、プレフィックスが減少しておらず、サフィックスが増加していない有効なピーク インデックスが存在するかどうかをチェックします。 

微妙な部分は、単調な接頭辞と接尾辞を個別に適用してから、交点を探すことです。 これにより、構築中にピーク インデックスを明示的に選択することがなくなり、代わりに実現可能性がグローバルに検証されます。

 ## 特殊なケース

 エッジケースの 1 つは、すべての値が同一である場合です。 この場合、考えられるすべての分割は両方の単調条件を満たしているため、正解は常に次のとおりです。$k = 0$。 アルゴリズムは維持します$k$任意のビットを反転すると、有効性が改善されずに不必要な変化が生じるだけであるため、変更されません。 

もう 1 つのエッジ ケースは、厳密に単調なシーケンスです。 例えば、$1,2,3,4,5$はすでに増加フェーズを満たしており、減少フェーズは簡単な接尾辞が付いた最後の要素から開始できます。 検証ではこの構造が受け入れられるため、再度$k = 0$保存されています。 

より微妙なケースは、シーケンスのピークにプラトーがある場合です。$1,3,3,2$。 分割はプラトー全体で発生する可能性があり、非厳密な不等式が許可されるため、両方の条件が引き続き有効です。 チェック関数は明示的に使用します$\le$そして$\ge$、そのため、プラトー安定性は特別なケースなしで自然に処理されます。
