 ## 解決策
 ## 問題の理解

 1 から n までの整数の順列が与えられ、それを左から右に処理することをシミュレートします。 各ステップでは、現在の位置より前にすでに表示されている値のみを調べます。 

現在の値 x について、以前に確認された値の中から 2 つの参照点を見つけます。 1 は、x よりまだ小さい、以前に確認された最大の値です。 もう 1 つは、以前に確認された最小値ですが、それでも x より大きい値です。 片側が存在しない場合は、値の範囲の自然な境界まで区間を拡張します。 

これら 2 つの境界が決定されると、x の寄与は厳密にそれらの間にある整数の数になります。 最終的な答えは、順列全体にわたるこれらの寄与の合計です。 

これを解釈する便利な方法は、1 から n までの数直線上に表示される値の動的なセットを維持することです。 新しい値はそれぞれ、このセット内の最も近い既存の値の間のギャップに「広がり」、そのギャップ内に未使用の整数がいくつあるかを数えます。 

n が 2 · 10^5 までの制約は、毎回表示されたセットをスキャンすることによって近傍の再計算を即座に除外します。 すべての要素について、増大する配列の左右を検索する単純なアプローチでは、二次時間まで劣化し、制限を超えてしまいます。 これにより、対数時間での動的な先行クエリと後続クエリをサポートするデータ構造が実現されます。 

現在の要素が表示された値の中で最小または最大である場合、微妙なエッジ ケースが発生します。 たとえば、順列で最初に 1 を処理すると、先行処理が存在しないため、間隔は事実上 1 から始まります。同様に、n を先に処理すると、後続処理は存在せず、間隔は n まで拡張されます。 これらの境界拡張を適切にモデル化できない不注意な実装は、これらの場合の寄与を過小評価することになります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 私たちは、すでに確認されている値のリストを増やし続けています。 新しい値 x ごとに、値ドメイン内で左方向にスキャンして最も近い小さい値を見つけ、右方向にスキャンして最も近い大きい値を見つけます。 これら 2 つの値を特定したら、範囲を反復処理するか、直接計算することによって、それらの間に厳密に存在する整数の数を数えます。 これは定義に正確に従っているため正しく機能しますが、最悪の場合、各スキャンに O(n) 時間がかかり、n が大きい場合は合計操作が O(n^2) になる可能性があります。 

ボトルネックは、増大する順序付けされていないセットの中で、先行者と後続者を繰り返し検索することです。 重要な観察は、セットの完全な構造は必要なく、順序統計だけが必要であるということです。各 x について、その上下に最も近い値が必要です。 これは、高速な先行クエリと後続クエリをサポートする構造でセットを維持することを示唆しています。 

値ドメイン [1, n] 上のフェンウィック ツリーを使用して、表示された値をモデル化できます。各位置は、値がすでに出現しているかどうかを示します。 この構造を使用すると、プレフィックス内に存在する要素の数を効率的に計算でき、プレフィックス数を二分探索して k 番目に小さい要素を見つけることができます。 これにより、x の先行と後続の両方を O(log n) 時間で回復できます。 それらを取得すると、寄与は境界間の単純な算術差になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォーススキャン | O(n^2) | O(n) | 遅すぎる |
 | 注文統計を含むフェンウィック ツリー | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 1 から n までのインデックスに対してフェンウィック ツリーを維持します。各インデックスは、値がすでに出現しているかどうかを示します。 この構造により、プレフィックスに含まれる値の数をすぐに数えることができます。 
2. 左から右へ順列を繰り返します。 各現在の値 x について、まずフェンウィック ツリーの接頭辞合計クエリを使用して、x より厳密に小さい値がいくつあるかを決定します。 このカウントにより、前任者が存在する場合のランク位置がわかります。 
3. x 未満の検出された値のカウントが 0 より大きい場合、k 番目に小さい検出された要素 (k はそのカウントに等しい) を見つけて、先行要素を見つけます。 そのような要素が存在しない場合、先行要素を境界を表す 0 として扱います。 
4. 同様に、x 以下の値がいくつあるかを計算します。 この値が検出された要素の総数よりも厳密に小さい場合、後続要素を (k+1) 番目に小さい検出された要素として配置します。 存在しない場合は、n+1 として扱います。 
5. 先行者 l と後続者 r が決定したら、x の寄与を r - l - 1 として計算します。これは、値空間内で最も近い隣接値の間に厳密に存在する整数の数を直接カウントします。 
6. フェンウィック ツリーに見られるように x をマークし、続行します。 

正確かどうかは、いつでも、表示されたセットが値の行をギャップに分割し、すべての新しい要素が、それが埋めるギャップのサイズに正確に寄与するという事実にかかっています。 

### なぜ効果があるのか

 各ステップで、表示された値は [1, n] の順序付きサブセットを形成します。 任意の新しい値 x について、この順序セット内のその先行値と後続値は、x の周囲のすべての目に見えない整数を制約する最も近い境界となります。 l と r の間の整数は現在認識されず、その間隔を埋める最初の要素が処理されるときに 1 回だけカウントされます。 したがって、アルゴリズムは値ライン全体を時間の経過とともに互いに素な間隔に分解し、各寄与はそのステップで「アクティブ化」されている間隔のサイズを測定します。 これにより、カウントの重複や漏れがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1
        return idx + 1

n = int(input())
a = list(map(int, input().split()))

fw = Fenwick(n)
seen = 0
ans = 0

for x in a:
    left_count = fw.sum(x - 1)
    right_count = fw.sum(x)

    if left_count == 0:
        l = 0
    else:
        l = fw.kth(left_count)

    if right_count == seen:
        r = n + 1
    else:
        r = fw.kth(right_count + 1)

    ans += (r - l - 1)

    fw.add(x, 1)
    seen += 1

print(ans)
```フェンウィック ツリーは、動的プレゼンス配列と順序統計構造の両方として使用されます。 の`sum`関数は、表示される要素間のランクを決定するプレフィックス数を提供します。 の`kth`関数はバイナリ リフティング検索を実行して、ランクに対応する実際の値を回復します。これは、先行者と後続者を効率的に見つけるために不可欠です。 

実装でよくある落とし穴は、プレフィックス数と実際の値を混同することです。 ツリーは値インデックスによって存在を格納するため、すべてのロジックは順列の位置空間ではなく値空間で動作する必要があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | n 回の挿入のそれぞれで、Fenwick クエリとバイナリリフティング k 番目の検索が実行されます。 
| スペース | O(n) | 値の範囲にわたるフェンウィック ツリーとブックキーピング配列 |

 実際には、n ≤ 2 · 10^5 により両方の対数因数が小さく保たれるため、この解は制限内に問題なく収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import log2

    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i

        def sum(self, i):
            s = 0
            while i > 0:
                s += self.bit[i]
                i -= i & -i
            return s

        def kth(self, k):
            idx = 0
            bitmask = 1 << (self.n.bit_length())
            while bitmask:
                nxt = idx + bitmask
                if nxt <= self.n and self.bit[nxt] < k:
                    k -= self.bit[nxt]
                    idx = nxt
                bitmask >>= 1
            return idx + 1

    n = int(input())
    a = list(map(int, input().split()))
    fw = Fenwick(n)
    seen = 0
    ans = 0

    for x in a:
        lc = fw.sum(x - 1)
        rc = fw.sum(x)

        l = 0 if lc == 0 else fw.kth(lc)
        r = n + 1 if rc == seen else fw.kth(rc + 1)

        ans += r - l - 1
        fw.add(x, 1)
        seen += 1

    return str(ans)

 ## 特殊なケース

 最初の要素が可能な最小値または最大値である場合、先行要素または後続要素が欠落しているため、アルゴリズムは境界 0 および n+1 を正しく使用します。 たとえば、入力では`1 3 2`、処理するとき`1`、先行者も後続者も存在しないため、寄与は 3 - 0 - 1 = 2 となり、その時点で 2 と 3 の両方がまだ右側に制限されていないという事実と一致します。 

要素がソートされた順序で到着すると、各ステップは片側の残りの間隔のみを縮小します。 先行または後続は常に最も近い境界を反映し、新しい挿入によって最初に「閉じられた」ときにすべてのギャップが正確に 1 回カウントされるようにするため、アルゴリズムは引き続き正しく動作します。
