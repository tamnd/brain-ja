 ## 解決策
 ## 問題の理解

 一定の合計長さに達するまで音符を端から端まで配置して曲を構築するという作曲の問題が与えられました。 各音符は正の整数の長さを持ち、音符は何度でも再利用できます。 課題は、異なる音符のシーケンスの合計が目標の全長に正確に一致する数を数えることです。 

入力は、「ビート」単位の目標の長さ (指定された小節数から導出され、実質的に単一の整数の合計長にスケール化される) と、許可される音符の長さのリストを提供します。 有効な各ソングは、これらの音符の順序付けされたシーケンスであり、その合計はターゲットと正確に等しくなります。 同じ複数のノートセットが使用されている場合でも、オーダーが異なると別の曲としてカウントされます。 

重要な点は、順序が重要であるということです。したがって、これはサブセットやパーティションの問題ではなく、順列形式のコイン釣銭計数の問題です。 

制約から、ターゲットの長さは次のとおりです。$10^5$音符タイプの数は最大 20 です。これにより、シーケンスの指数関数的な列挙が即座に除外されます。 すべてのコンポジションを明示的に構築しようとするソリューションは、有効なパーティションの数と同じように増加し、中程度の入力であっても天文学的に大きくなる可能性があります。 したがって、部分的な結果を再利用する動的プログラミングのアプローチが必要です。 

すべての音の長さの最大公約数がターゲットを分割しない場合、微妙なエッジケースが発生します。 たとえば、メモが次のような場合$[3, 6]$そしてターゲットは$5$、両方の数値が小さい場合でも、正確に 5 に達するシーケンスはありません。 状態を誤って初期化するか、すべての値からの到達可能性を想定する単純な DP は、遷移が慎重に制限されていない場合、依然として誤ったゼロ以外の値を生成する可能性があります。 

もう 1 つの重要なケースは、長さが 1 のノートがある場合です。このシナリオでは、有効なシーケンスの数が非常に急速に増加し、たとえ小さなターゲットであっても指数関数的なアプローチは不可能になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。合計が正確に目標となる音の可能な限りのシーケンスを構築しようとします。 各ステップで、次のいずれかを選択します。$N$ノートを削除し、残りの長さを再帰的に減らします。 これにより、各ノードが最大で分岐する再帰ツリーが形成されます。$N$子と深さは次のように大きくできます。$M$。 最悪の場合、次の順序で探索されます。$N^M$たとえ小さな入力であっても、それは完全に不可能です。 

重要な観察は、唯一関連する状態は、埋める必要がある残りの長さであるということです。 残りの長さが同じになる部分シーケンスは、どのようにしてそこに到達したかに関係なく、同等です。 これにより、問題は 1 次元の動的計画法に帰着され、0 からターゲットまでの各プレ​​フィックス長を構築する方法の数が計算されます。 

DP 配列を定義します。$dp[x]$全長が正確に一致するシーケンスを構築する方法の数を表します。$x$。 の各値に対して、$x$、許可されているすべての音符の長さを追加してみます$v$、からの移行$x$に$x+v$。 これにより、各拡張ステップが現在のプレフィックスを独立して処理するため、順序付けられたシーケンスが確実にカウントされます。 

ブルートフォース手法は、同じサフィックス数を繰り返し再計算するため失敗します。 DP が機能するのは、各状態が以前に計算された小さな状態のみに依存し、部分問題の結果を再利用できるためです。

 ## アルゴリズムのチュートリアル

 1. 問題を全長の順序付けられた構成の数の計算に変換します。$M$指定された音符の長さを使用します。 各音符を現在の長さを増やす「ステップ」として扱います。 
2.次のサイズの DP 配列を作成します$M+1$、位置の値$i$正確な長さに到達する方法の数を表します$i$。 初期化する$dp[0] = 1$なぜなら、空のシーケンスを構築する方法は 1 つだけだからです。 
3. 0 から 0 までのすべての長さを反復します。$M-1$。 現在の長さごとに$i$、次の場合にのみ有効なプレフィックス状態とみなされます。$dp[i]$はゼロ以外であり、それを構築する方法が少なくとも 1 つ存在することを意味します。 
4. 有効な各状態から$i$、許可されているすべての音符の長さを使用してシーケンスを拡張してみてください。$v$。 もし$i + v \le M$、 追加$dp[i]$に$dp[i + v]$、すべてのシーケンスが到達するため、$i$によって延長できます$v$有効な長さのシーケンスを形成するには$i + v$。 
5. すべての加算を剰余として計算する$10^9+7$オーバーフローを回避し、値を範囲内に保つため。 
6. 最終的な答えは次のとおりです。$dp[M]$、ターゲットの長さを正確に満たすすべての可能な順序付けされたシーケンスを集計します。 

### なぜ効果があるのか

 核となる不変条件は、どのインデックスでも$i$、$dp[i]$すでに、合計が正確に一致する有効な順序付けされたシーケンスの数と等しくなります$i$。 すべてのトランジションで正確に 1 つのノートが追加されるため、自然な順序が維持されます。 状態を長さの昇順に処理するため、$dp[i + v]$完全に計算された有効なシーケンスのみから得られます。$i$、部分工事の二重カウントを防止します。 これにより、各シーケンスが DP 遷移を通る 1 つの一意のパスに正確に対応し、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    M, N = map(int, input().split())
    notes = list(map(int, input().split()))
    
    dp = [0] * (M + 1)
    dp[0] = 1

    for i in range(M + 1):
        if dp[i] == 0:
            continue
        for v in notes:
            if i + v <= M:
                dp[i + v] = (dp[i + v] + dp[i]) % MOD

    print(dp[M])

if __name__ == "__main__":
    solve()
```実装は DP 定義に直接準拠します。 外側のループは到達可能なプレフィックス長を繰り返し、内側のループは各ノートをトランジションとして適用します。 基本的なケース$dp[0] = 1$構造を固定します。 

実装でよくある落とし穴は、順序が重要であることを忘れていることです。 代わりに、最初に音符を反復し、次に長さを反復すると、順序が無視された組み合わせが計算されます。 選択したループ順序により、順列形式のカウントが強制されます。 

もう 1 つの微妙な問題は、到達不能な状態をスキップすることです。 なしで`if dp[i] == 0`ガード、アルゴリズムはまだ機能しますが、時間を無駄にします。 これにより、まばらな状態での不必要な遷移を回避できます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(M \cdot N)$| M の状態のそれぞれについて、最大 N 個の音符遷移を試みます。 
| スペース |$O(M)$| DP 配列はすべてのプレフィックス長のカウントを格納します。

import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    notes = list(map(int, input().split()))

assert run("4 2\n1 2\n") == "5", "small compositions"

 ## 特殊なケース

 エッジ ケースの 1 つは、最小の音符がターゲットよりも大きい場合です。 この状況では、状態 0 からの遷移は正の状態に到達できないため、dp[0] を除くすべての dp エントリはゼロのままになります。 有効な拡張機能がトリガーされないため、アルゴリズムは正しく 0 を出力します。 

ノート セットに 1 が含まれる場合、別のエッジ ケースが発生します。ここでは、すべてのプレフィックスが到達可能であり、DP が密に入力されます。 各状態は遷移パスごとに 1 回だけ更新され、カウントが大きくなってもモジュロ演算によりオーバーフローが防止されるため、アルゴリズムは引き続き正しく動作します。 

最後のエッジケースは、ターゲットがノートの 1 つと正確に等しい場合です。 のような入力の場合$M=4$、メモ$[4]$、DP は 0 から 4 に 1 回だけ遷移し、有効なシーケンスが 1 つだけ生成されます。
