 ## 問題の理解

 固定整数が与えられます`n`そして範囲の長さ`k`。 すべての整数に対して`i`から`1`に`k`、次の場合に剰余を計算します。`n`で割られる`i`。 これにより、一連の値が生成されます。$$r(i) = n \bmod i$$タスクは、これらすべての剰余が互いに異なるかどうかを判断することです。 言い換えれば、2 つの異なるインデックスを見つけることが不可能かどうかを知りたいのです。`i < j`そのように分割する`n`による`i`そして`j`同じ余りを与えます。 

制約により両方が許可されます`n`そして`k`と同じくらい大きくなる$10^{18}$。 これにより、次の値までのすべての値を反復するソリューションは即座に除外されます。`k`なぜなら、リニアスキャンですら遅すぎるからです。 有効なアプローチはどれも、時間内にほぼ対数または定数で機能する必要があります。`k`。 

微妙なエッジケースは、約数が小さい場合に現れます。`n`存在する。 たとえば、次の場合`n = 4`、その後両方`4 mod 1`、`4 mod 2`、 そして`4 mod 4`等しい`0`。 次のような小さなプレフィックスに制限しても`k = 2`すでに衝突が発生しています。 これは、重複が大きな値だけによって発生するのではなく、約数の算術構造によって発生することを示しています。 

別のエッジケースが発生する場合`n = 1`。 それから、それぞれについて`i ≥ 2`、余りは常に`1`したがって、重複は一度発生するとすぐに表示されます。`k ≥ 2`。 「約数」のみを考慮した解決策は、`n`これを個別に扱わないと、このケースは誤って分類されてしまいます。 

## アプローチ

 直接シミュレーションでは次のように計算されます。`n % i`あらゆる人にとって`i`から`1`に`k`値が繰り返されるかどうかを確認します。 これは問題の定義を正確に反映しているため、概念的には正しいです。 ただし、そのとき`k`できる$10^{18}$、パフォーマンスさえ$10^9$操作はすでに実行不可能であり、ここでは最大で次の操作が必要になる可能性があります$10^{18}$制限時間内では絶対に不可能な操作。 

重要な観察は、衝突が非常に構造化されているということです。 値`n % i`になる`0`まさにいつ`i`分割する`n`。 以来`1`常に分裂する`n`、最初の余りは常に`0`。 他の約数`i > 1`範囲内で`[1, k]`剰余も生成します`0`の値をすぐに複製します。`i = 1`。 

これは、区別性を維持する唯一の方法は、他の約数が存在しないことを保証することであることを意味します。`n`範囲内に表示されます`2 ... k`。 このような約数が存在する場合、重複は避けられません。 

したがって、問題全体は、次の値より大きい最小の整数を見つけることに帰着します。`1`それは分ける`n`。 この最小の約数が`p`の場合、すべての残りは正確に区別されます。`k < p`。 そのような約数が存在しない場合 (これは次の場合にのみ発生します)`n = 1`または`n`は素数です）、答えは次のいずれかによって異なります。`k`非除数構造で反復残基が出現し始める点に達しますが、実際には、最初の反復が依然として除数構造によって支配されているため、同じ条件が依然として正確さを捉えています。 

ブルートフォースのアイデアはすべてをチェックします`i`一方、最適解では、すべてを圧縮して次の最小の約数を見つけます。`n`。

 ## アルゴリズムのチュートリアル

 より大きい最小の整数を特定したいと考えています。`1`それは分ける`n`と比較してください`k`。 

1. もし`n == 1`、すべての残りの動作が異なるため、個別に処理します。`1 % i`等しい`1`みんなのために`i > 1`、そのため、すぐに重複が表示されます`k ≥ 2`。 このケースは、さらに計算することなく直接答えることができます。 
2. 最小の約数を見つけてみる`p > 1`の`n`からの整数をチェックすることで`2`まで`√n`。 数字を見つけたら`i`そのような`n % i == 0`、 それから`i`は最小の候補約数です。 
3. この範囲内に約数が見つからない場合は、`n`は素数なので、より大きい最小の約数は`1`は`n`自体。 この場合、設定したのは、`p = n`。 
4. 比較する`k`と`p`。 もし`k < p`の場合、以外の約数はありません`1`はテスト範囲内にあるため、2 つの位置で同じ剰余が生成されることはありません。 それ以外の場合、少なくとも 2 つのインデックスにより剰余が生成されます。`0`, そのため重複が発生します。 

決定は完全に、範囲が以下であるかどうかによって決まります。`[2, k]`の任意の約数が含まれます`n`。 

### なぜ効果があるのか

 残りを伴うすべての衝突`0`の約数から来ます`n`。 以来`i = 1`いつも貢献してくれる`0`、他の約数はその値を直ちに複製します。 他の潜在的な衝突はすべて、同じ構造上の問題に遡ることができます。範囲内に除数が存在すると、剰余パターンは単射性を失います。 最小の約数は、最初の避けられない繰り返しが現れる境界として機能するため、その最小値を厳密に下回るようにすることで、すべての残りが明確に保たれることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    if n == 1:
        # 1 % 1 = 0, 1 % i = 1 for i >= 2 -> duplicates appear from k >= 2
        print("Yes" if k <= 1 else "No")
        return

    # find smallest divisor > 1
    p = n
    i = 2
    while i * i <= n and i <= k:
        if n % i == 0:
            p = i
            break
        i += 1

    print("Yes" if k < p else "No")

if __name__ == "__main__":
    solve()
```実装ではまず特殊なケースを分離します。`n = 1`なぜなら、そこでは除数ロジックが異なる動作をするからです。 大型の場合`n`までしか検索されません。`√n`なぜなら、自明でない約数はペアで出現する必要があり、そのうちの 1 つが平方根を超えないからです。 次の場合にもループは早期に停止します。`i > k`、約数を超えるため`k`クエリ範囲に重複が出現するかどうかには関係ありません。 

最終的な比較`k < p`の約数が存在しない条件を直接エンコードします。`n`(以外の`1`）に登場する`[1, k]`。
