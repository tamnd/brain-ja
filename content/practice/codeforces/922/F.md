 ## 解決策
 ## 問題の理解

 このサブセットで計算される非常に具体的な量が正確に k に等しくなるように、1 から n までの数値のサブセットを構築するように求められます。 この数量は、a が b よりも先に値が出現し、a が b を均等に分割する、個別の要素 (a, b) の順序付きペアをカウントします。 言い換えれば、選択したすべての数値を調べ、選択した小さい数値が選択した大きい数値の約数の何倍になるかを数えます。 

これについて考えるのに役立つ方法は、選択されたすべての数値 b が、厳密に小さい b の選択された約数 a ごとに 1 回ずつ答えに寄与するということです。 したがって、各要素は、セット内に存在するその約数から「寄与を収集」します。 

通常、入力サイズでは n が最大約 10^5 まで許容されるため、すべてのサブセットを試行する解決策は直ちに不可能になります。 サブセットのサイズが線形である可能性があり、二次的な動作につながる可能性があるため、サブセット内のすべてのペアを反復処理しても、密な場合は遅すぎます。 ただし、割り算の構造は非常に不均一です。ほとんどの数値には大きな 2 の累乗の連鎖がほとんどなく、約数が比較的まばらであるため、任意の組み合わせではなく乗算構造に基づいて構築されることが示唆されます。 

微妙な問題は、複数の構造で同じ k が生成される可能性がありますが、k のすべての値が達成できるわけではないことです。 たとえば、n が小さい場合、大きな k を形成するのに十分な分割構造が存在しない可能性があります。 一方、あまりにも多くの数値を貪欲に選択すると、k をオーバーシュートする傾向があります。これは、割り算の連鎖によってペアの数が二次関数的に増加するためです。 

導入される新しいペアの数に基づいて個別に数値を選択する単純なアプローチは、1 つの数値を追加すると、以前に追加された数値の寄与が大幅に変化する可能性があるため、失敗します。 たとえば、1、2、4、8 を選択すると、すべてのプレフィックスが後続のすべての要素と相互作用する密なチェーンが作成され、寄与が二次関数的に増加します。 要素を独立して扱うと、この結合は無視されます。 

別の失敗例は、最初に小さな数値の倍数をすべて貪欲に選択しようとした場合に発生します。 たとえば、3 を検討する前に 2 の倍数をすべて選択すると、k が小さい場合でも、すぐにオーバーシュートが発生します。これは、チェーン 2、4、8、16 がすでに多くの内部ペアに寄与しているためです。 

## アプローチ

 約数のペアの数を制御するための鍵は、任意のサブセットの観点から考えることを避け、代わりに選択したセットを独立した乗法チェーンに構築することです。 

固定の開始番号 x を考えてみましょう。 n 以内に収まるように 2 を繰り返すと、連鎖 x、2x、4x などが得られます。 このようなチェーン内では、前のすべての要素が後のすべての要素を分割するため、長さ L のチェーンは正確に L・(L−1)/2 の有効なペアに寄与し、これらの寄与は完全にチェーンの内部にあります。 

最終的なセットをいくつかの素なチェーンに分解できれば、合計の答えは、その長さにわたる三角形の数の合計にすぎません。 主な課題は、チェーン全体で数値を再利用しないようにしながら、三角形の合計が k に等しいチェーンの長さを選択することです。 

強引なアイデアは、すべてのサブセットを考慮し、それらの寄与を直接計算することです。 これは n で指数関数的であるため、すぐに失敗します。 

重要な観察は、チェーンが要素を共有していない場合、チェーンが独立して動作し、各チェーンが予測可能な二次量に寄与するということです。 これにより、問題は三角数の和を使用して k を構築することに変わります。ここで、各三角数は元のセット内の幾何学的チェーンに対応します。 大きなチェーンは不釣り合いに大きな寄与を与えるため、利用可能な大きな数から貪欲にチェーンを構築し、k を超えずに常に可能な限り多くを取得することができます。

 | 貪欲なチェーン構築 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 n から 1 までの番号を処理し、未使用の各番号から始まるチェーンの形成を試みます。 

1. 数値がすでに何らかのチェーンで使用されているかどうかをマークするために使用されるブール配列を維持します。 これにより、チェーンが切り離されたままになります。 
2. i を n から 1 まで繰り返します。i がすでに使用されている場合は、新しいチェーンを開始できないため、スキップします。 
3. 値が ≤ n で未使用である限り、i、2i、4i、8i と 2 を繰り返し乗算して、i から始まる乗算チェーンを構築します。 これらの値をリスト v に収集します。これにより、i から始まる完全な使用可能なチェーンが生成されます。 
4. L を v の長さとします。次に、このチェーンの実際にいくつの要素を取るかを決定します。 最初の t 要素を取得すると、正確に t・(t−1)/2 ペアが提供されるため、t・(t−1)/2 ≤ k および t ≤ L となるような最大の t を選択します。t が大きいほど厳密にチェーンごとにより多くの値が与えられ、k がより速く減少するため、このステップは貪欲です。 
5. v の最初の t 要素を使用済みとしてマークし、それらを回答セットに追加します。 kからt・(t−1)/2を引きます。 
6. i が 1 になるか、k が 0 になるまで続けます。k が 0 になった場合、残りの数値は安全に無視できます。 
7. k が 0 の場合、構築されたセットを出力します。 それ以外の場合は「いいえ」を出力します。 

重要な不変条件は、各チェーンを処理した後、k が未使用の数値で形成する必要がある残りの必要なペア数と常に等しいということです。 2 つのチェーンには数値が表示されず、チェーン内ではすべての寄与が内部にあるため、各チェーンは独立して寄与します。 所与の点から開始するすべての可能なチェーンの中で、実現可能な最大のプレフィックスを選択することは将来の構築を妨げないため、貪欲な選択は有効です。開始点の降順で処理を進め、後で使用するために未使用の番号を常に保存するため、残りの要件はより小さいチェーンを使用して形成できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    used = [False] * (n + 1)
    ans = []
    
    for i in range(n, 0, -1):
        if used[i]:
            continue
        
        v = []
        x = i
        while x <= n and not used[x]:
            v.append(x)
            x *= 2
        
        L = len(v)
        
        # find largest t such that t*(t-1)//2 <= k and t <= L
        t = 0
        for c in range(L + 1):
            if c * (c - 1) // 2 <= k:
                t = c
        
        if t > 0:
            for j in range(t):
                used[v[j]] = True
                ans.append(v[j])
            k -= t * (t - 1) // 2
        
        if k == 0:
            break
    
    if k != 0:
        print("No")
    else:
        print("Yes")
        print(len(ans))
        print(*ans)

if __name__ == "__main__":
    solve()
```コードはまず、未使用の各数値から始まる最大の 2 倍化チェーンを構築します。 次に、残りの k がどれだけ吸収できるかに基づいて、各チェーンから取り出す要素の数を決定します。 二次項 t(t−1)/2 は、前の要素がすべて後の要素を分割するため、完全に接続された二重化チェーン内の有効な割り算ペアの正確な数です。 

注意すべき点は、チェーンのプレフィックスのみを取得するようにすることです。 プレフィックスを取得すると、スキップされた要素との部分的な相互作用を回避しながら、すべての割り算ペアが存在することを保証する内部構造が保存されます。 

## 実用的な例

 ### 例 1

 n = 10、k = 3 を考えてみましょう。 

10から下へ処理していきます。 i = 8 の場合、チェーンは [8] になります。 選択に関係なく寄与するペアは 0 であるため、何も変わりません。 i = 4 では、チェーンは [4, 8] ですが、前のステップに応じて 8 がすでに使用されています。 まだ使用されていないとします。 t = 2 として、1 ペアを寄与し、k を 2 に減らすことができます。 

i = 2 では、チェーンは [2, 4, 8] ですが、一部はすでに使用されている可能性があります。 残りの使用可能な構造により t = 2 が許可され、別の 1 ペアが寄与し、k が 1 に減少すると仮定します。 

i = 1 では、チェーンは [1, 2, 4, 8] ですが、再び使用法でフィルタリングすると、さらに 1 つのペアに寄与する t = 2 を取得して、k を 0 に減らすことができます。 

| 私 | チェーンv | 選択された t | 貢献 | 残り k |
 | --- | --- | --- | --- | --- |
 | 4 | [4、8] | 2 | 1 | 2 |
 | 2 | [2、4、8] | 2 | 1 | 1 |
 | 1 | [1、2、4、8] | 2 | 1 | 0 |

 このトレースは、k が独立したチェーンからの三角形の寄与にどのように分解されるかを示しています。 

### 例 2

 n = 6、k = 2 とします。 

i = 6、v = [6] では、寄与は 0 です。 

i = 3、v = [3, 6] では、t = 2 として 1 つのペアが得られるため、k は 1 になります。 

i = 2、v = [2, 4] では、やはり t = 2 で 1 ペアが得られるため、k は 0 になります。 

| 私 | チェーンv | 選択された t | 貢献 | 残り k |
 | --- | --- | --- | --- | --- |
 | 3 | [3、6] | 2 | 1 | 1 |
 | 2 | [2、4] | 2 | 1 | 0 |

 これは、異なる開始点がどのようにして合計が正確に k になる互いに素な寄与を生成するかを示しています。

 ## 特殊なケース

 k = 0 の場合、アルゴリズムは意味のあるチェーンを選択しないか、シングルトン要素のみを選択することによって直ちに受け入れます。 シングルトンはペアを提供しないため、任意の単一の数値で十分であり、構築は自然に早期に終了します。 

n が小さい場合、多くのチェーンは長さ 1 に折りたたまれます。これは、すべての三角形の寄与がゼロになることを意味します。 このような場合、k もゼロにする必要があり、そうでない場合は構築できません。 どのチェーンも k を減らすことができないため、アルゴリズムは正しく失敗します。 

2 の累乗の数値の場合、チェーンは長くなり、価値が高くなります。 アルゴリズムは、これらのチェーンが素であるため、奇数で始まる無関係なチェーンに影響を与えることなく、早期にそれらを貪欲に消費し、k を迅速に減らすことでこれを処理します。
