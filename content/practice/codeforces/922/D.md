 ## 問題の理解

 それぞれが文字のみで構成されるいくつかの短い文字列が与えられます。`s`そして`h`。 これらの文字列を任意の順序で並べ替えて、1 つの長い文字列に連結することができます。 最終的な文字列が形成されたら、その「ノイズ」を位置のペアの数として測定します。`(i, j)`そのような`i < j`、位置の文字`i`は`s`、および位置の文字`j`は`h`。 言い換えれば、すべての`s`の前に表示されるのは`h`それぞれのノイズに対して 1 単位のノイズが寄与します`h`。 

タスクは、この合計数が最大になるような指定された文字列の順序を選択することです。 

制約は次のとおりです`n = 100000`全長の文字列`100000`。 これにより、文字列のすべての順列を試行するアプローチは即座に除外されます。これは、階乗になるためです。`n`。 すべての順列を並べ替えたり、サブセットに対して動的プログラミングを実行したりすることさえ不可能です。 ソリューションは基本的に線形計算時間で実行する必要があります。`O(n log n)`またはそれ以上です。 

微妙な問題は、文字列の寄与がその内部構造だけでなく、その前後に配置された他の文字列とどのように相互作用するかにも依存することです。 各文字列の寄与を個別に計算するという単純な考えがあるかもしれませんが、それは問題の全体的な難しさである境界を越えたペアを無視しています。 

重要なエッジ ケースの 1 つは、文字列が内部的には「良好」でも、順序付けでは有害である場合に発生します。 たとえば、文字列を考えてみましょう`"sh"`そして`"hs"`。 内部的には両方とも小さなノイズに寄与しますが、順序を入れ替えると相互寄与が大幅に変化します。 もう 1 つのエッジ ケースは、次のもののみで構成される文字列です。`s`またはのみ`h`、内部寄与はゼロですが、グローバルな順序付けに強い影響を与えます。 

## アプローチ

 ブルートフォースソリューションでは、すべての順列を試みます。`n`文字列を連結し、すべてをカウントします`s-h`結果の文字列内のサブシーケンス。 各順列について、ノイズをカウントするには次の時間がかかります。`O(total length)`したがって、完全な複雑さは次のようになります。`O(n! * 100000)`、これはたとえ`n = 10`。 

単純化するために、各文字列が 3 つの値で要約できることに注目してください。`s`文字、数`h`文字数、および内部ペアの数`s`の前に表示されます`h`文字列自体の内部。 内部寄与は順序に関係なく固定されるため、制御可能な部分は文字列が境界を越えてどのように相互作用するかだけです。 

2 つの文字列が連結されている場合、相互寄与はその文字列の数にのみ依存します。`s`最初の文字列にあるものとその数`h`2番目の文字列にあります。 文字列の場合`A`前に置かれます`B`、その後は毎回`s`で`A`あらゆるものに貢献します`h`で`B`、生産`sA * hB`新しいペア。 これは、順序付けの問題が 2 つのパラメータを使用して項目を配置することに帰着することを示しています。`s_i`そして`h_i`、ペアごとの積の合計を最大化します。 

ここで 2 つの文字列を交換することを考えてみましょう`A`そして`B`。 貢献度の違いはクロスタームによってのみ生じます。 もし`A`前です`B`、貢献度は`sA * hB`、逆にすると、`sB * hA`。 すべての隣接するスワップにわたって一貫して選択されたこれらをより良くする順序が必要です。 これにより、貪欲な並べ替え基準「場所」が生まれます。`A`前に`B`もし`sA * hB >= sB * hA`。 

これは、文字列を比率で並べ替えることと同じです。`s_i / h_i`降順で、ゼロ値に注意してください。 直感的には、多くの文字列が含まれる`s`そして少数の`h`これらは将来の貢献を多く生み出すため、より早く指定する必要があります。`h`ペアリングを最大化するには、後で行う必要があります。

 ## アルゴリズムのチュートリアル

 各文字列を 3 つの値に圧縮します。`s`、数`h`、弦内部の内部ノイズ。 内部ノイズは、左から右にスキャンし、その数を数えることによって計算されます。`s`私たちがそれぞれに遭遇したとき、これまで見られてきた`h`。 

次に、相互作用に基づいてカスタム コンパレータを使用して文字列を並べ替えます。 

1. 各文字列について、カウントします。`s_i`、`h_i`、 そして`internal_i`。 内部値は順序に依存しないため、最終応答に直接追加されます。 
2. 2 つの文字列間の比較ルールを定義する`A`そして`B`。 配置します`A`前に`B`もし`sA * hB >= sB * hA`。 この条件により、確実に配置されます。`A`まず、配置に比べて相互貢献を失うことはありません`B`初め。 その理由は、数を直接比較するためです。`s-h`両方の順序で作成されたペア。 
3. このコンパレータに従ってすべての文字列を並べ替えます。 これにより、貢献する文字列がより有用になるように配置されます。`s`早い人が最初に現れ、より多くの貢献をした人が`h`遅いのは後で現れる。 
4. ソート後、プレフィックスの合計を計算します。`s`。 各文字列を順番に処理すると、`h`現在の文字列のすべてに寄与します`s`以前の文字列から蓄積されます。 
5. 内部寄与率とソートされた順序から計算された相互寄与率の合計として、合計の回答を累積します。 

これが機能する理由は、ペアごとの交換引数に基づいています。 隣接する文字列のペアを考慮します。 コンパレータに従ってそれらの順序が間違っている場合、それらを交換することでクロス ペアの総数が厳密に増加または維持されます。 任意の順列は、隣接する交換によってソート順に変換でき、それぞれの目的が減少することはないため、最終的なソート順は最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    strings = []

    for _ in range(n):
        t = input().strip()
        s_count = 0
        h_count = 0
        internal = 0
        seen_s = 0

        for ch in t:
            if ch == 's':
                s_count += 1
                seen_s += 1
            else:
                h_count += 1
                internal += seen_s

        strings.append((s_count, h_count, internal))

    def cmp(a):
        s, h, _ = a
        return -s / h if h != 0 else float('inf')

    strings.sort(key=cmp)

    prefix_s = 0
    ans = 0

    for s_count, h_count, internal in strings:
        ans += internal
        ans += prefix_s * h_count
        prefix_s += s_count

    print(ans)

if __name__ == "__main__":
    main()
```コードはまず、各文字列を 3 つの必要な統計に圧縮します。 内部ノイズは、どれだけのノイズを追跡することによって 1 回のパスで計算されます。`s`これまでのキャラクターが登場しました。 これにより、後の再計算が回避されます。 

ソートステップでは貪欲ルールをエンコードします。 文字列付き`h = 0`貢献するだけなので最初に配置されます`s`将来の貢献をブロックすることはありません。 それ以外の場合は、降順で並べ替えます`s / h`比率により、初期の`s`そして遅い`h`。 

最後に、合計の実行カウントを使用してクロスコントリビューションを計算します。`s`これまで見られた。 それぞれ`h`現在の文字列ペアと以前のすべての文字列ペア`s`これは、連結境界を越えるノイズの定義と正確に一致します。
