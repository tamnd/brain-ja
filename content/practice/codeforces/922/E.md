 ## 解決策

 ## 問題の理解

 木が並んでいて、それぞれの木に鳥がたくさんいます。 インプは最初の木から最後の木まで歩き、各木でマナを消費してそこに住んでいる鳥を呼び出すことができます。 各鳥はその木で固定量のマナを消費し、鳥を永続的に連れて行くと、固定値だけ最大マナ容量が増加します。 

木々の間で、インプは前進してマナを部分的に回復しますが、現在の能力を超えることはありません。 これによりプロセスが動的になります。現在のマナと最大マナの両方が時間の経過とともに変化するため、パスの早い段階で同じアクションが後で不可能になったり、その逆の場合もあります。 

タスクは、収集される鳥の総数が最大になるように、各木で何羽の鳥を捕まえるかを選択することです。 

制約は、最大 1000 本の木と木あたり最大 10^4 羽の鳥を示しますが、マナ値は 10^9 まで大きくなる可能性があります。 これにより、数値範囲にわたる単純な DP 次元としてマナを追跡するソリューションは即座に除外されます。 あらゆる可能なマナ値を直接シミュレートしようとするアプローチは、時間制限をはるかに超えてしまいます。 

重要な問題は、鳥を捕まえる作業が木を越えて独立して行われないことです。 鳥を捕まえると将来のキャパシティが増加し、間接的に後でより高価な鳥を獲得できるようになります。一方、移動すると現在のマナが増加し、次のステップで入手可能なマナが変わります。 

微妙なエッジケースは、初期の貪欲な選択により当面のマナが減少するものの、容量が増加しすぎて後の高価なネストが完全に利用可能になる場合に発生します。 たとえば、安い初期の木に中程度のコストと大きなBを持つ鳥がたくさんいる場合、そこからさらに取ると、部分的にアクセスできなくなる後の木のロックを解除できます。 単純な「できるだけ多くをローカルで取得する」戦略は、将来の容量増加効果を無視しているため、ここでは失敗します。 

もう 1 つのエッジ ケースは、木の間を移動することでマナが回復し、容量を増やさずに、以前は手が届かなかった次の鳥が利用可能になる場合です。 これにより、前のツリーでの消費が遅れると、後の選択の実現可能性が変わるという状況が生じます。 

## アプローチ

 この強引なアイデアは、各木に何羽の鳥を捕まえるかについて、あらゆる選択肢をシミュレートすることです。 ツリー i で、0 から ci までの k を試し、更新されたマナと容量で次のツリーに再帰的に続行し、最良の合計を追跡します。 これは正しいですが、組み合わせ的に爆発します。状態の数は、おおよそすべての ci の選択の積であり、最悪の場合、天文学的に大きくなります。 

主な観察は、単一の木の中で、鳥はマナへのコスト効果を除いて交換可能であるということです。 鳥をコストで分類する場合、より安い鳥を最初に取るのが常に最適です。なぜなら、鳥は鳥ごとに同じ容量増加を与えながら、将来の決定のためにより多くのマナを保存するからです。 これにより、各ツリーはプレフィックス長 k を選択することになります。コストは k 個の最も安い鳥の合計になります。 

これで、構造は木ごとの DP になり、各遷移は現在の木で捕らえられた鳥の数のみに依存し、どの鳥が捕らえられたかには依存しません。 

まだ生のマナ値を超える DP はできませんが、各ツリーの後で到達可能な「状態」のみを維持できます。状態は現在のマナと収集された鳥の総数によって特徴付けられます。 多くの州が支配されるようになります。ある州が他の州よりも多くのマナとより多くの鳥を持っている場合、より悪い州を破棄することができます。 

このパレート刈り込みにより、マナ値は単調であり、容量は鳥によってのみ増加するため、実際には状態設定が小さく保たれます。

 ## アルゴリズムのチュートリアル

到達可能な状態のセットを維持しながら、ツリーを左から右に処理します。 各状態には、インプが現在どれだけのマナを持っているか、そして彼がこれまでに集めた鳥の数が保存されています。 

1. ツリー 1 の単一状態から開始します。現在のマナは W、収集された鳥は 0 です。開始時の容量は暗黙的に W です。 
2. 各木について、その鳥をコストの昇順に並べ替えます。 これにより、有効な選択を、このソートされたリストのプレフィックスを取るものとして扱うことができます。 
3. 既存の状態ごとに、k 羽の鳥を 0 から ci まで取ることをシミュレートします。 k を 1 つずつ拡張するときにランニングコストの合計を維持します。 各 k について、インプが現在のマナと容量の制約の下で k 番目の鳥を入手できるかどうかを確認します。 

鳥が捕獲されるたびに、マナはコストだけ減少し、容量は B だけ増加します。k 羽の鳥を計算した後、移動トランジションも適用します。マナは X だけ増加しますが、現在の容量によって制限されます。 
4. 結果として得られる各 (マナ、鳥の合計) ペアが次の状態セットに挿入されます。 
5. ツリーのすべての遷移を生成した後、支配的な状態を枝刈りします。 状態 A が mana_A ≥ mana_B であり、bird_A ≥ Bird_B である場合、将来の決定にとって B は決して良いものではないため、B を破棄できます。 
6. 最後の木まで続けます。 答えは、残りのすべての州の中での鳥の最大値です。 

重要な不変条件は、ツリー i を処理した後、状態セットには i ツリーにアクセスした後に達成可能な非支配的な (マナ、鳥) の構成がすべて含まれるということです。 破棄された状態はマナと収集された鳥の両方において厳密に悪くなるため、より良い継続にはつながりません。将来の移行はこれら 2 つの量と単調な容量の増加のみに依存するため、支配された状態は後で「回復」することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, W, B, X = map(int, input().split())
    c = list(map(int, input().split()))
    cost = list(map(int, input().split()))

    states = [(W, 0)]  # (mana, birds)

    for i in range(n):
        ci = c[i]
        costs = [cost[i]] * ci
        costs.sort()

        new_states = []

        for mana, birds in states:
            cur_mana = mana
            cur_cap = mana + birds * B  # current capacity

            taken_cost = 0

            # try taking k birds greedily (sorted costs)
            for k in range(ci + 1):
                if k > 0:
                    if k - 1 >= len(costs):
                        break
                    if cur_mana < costs[k - 1]:
                        break
                    cur_mana -= costs[k - 1]
                    cur_cap += B

                # move to next tree
                nm = cur_mana + X
                if nm > cur_cap:
                    nm = cur_cap

                new_states.append((nm, birds + k))

        # prune dominated states
        new_states.sort(reverse=True)
        pruned = []
        best_birds = -1

        for mana, birds in new_states:
            if birds <= best_birds:
                continue
            pruned.append((mana, birds))
            best_birds = birds

        states = pruned

    print(max(b for _, b in states))

if __name__ == "__main__":
    solve()
```このコードは、完全な DP テーブルではなく、状態のフロンティアを維持します。 各ツリーは、マナと容量の更新を順番に追跡しながら、より多くの鳥を段階的に取得することで、すべての状態を最大 ci+1 の可能性に拡張します。 拡張後は、状態空間が爆発しないように、支配された状態は削除されます。 

重要な実装の詳細は、容量が別の DP ディメンションとして明示的に保存されないことです。 代わりに、それは初期マナと鳥から得たゲインから再構築されます。 これにより、余分な次元が回避され、各状態がコンパクトに保たれます。 

剪定のステップは不可欠です。 これがなければ、ツリーごとに状態の数が増加します。 これにより、マナと鳥の総数の間の意味のあるトレードオフのみが生き残ることになります。

 ## 特殊なケース

 重要なエッジケースの 1 つは、コストがゼロの場合です。 その状況では、鳥を捕まえてもマナは減らずに容量が増えるだけなので、最適な戦略はすべての木ですべての鳥を捕まえることです。 貪欲なプレフィックス シミュレーションは決してブロックされず、すべての k 値が探索されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、コストと比較して B が大きい場合です。 早期に契約すると生産能力が大幅に向上し、後で高価な契約が可能になります。 鳥の数が多いほど、生産能力と将来性の両方において優勢になる傾向があるため、DP 状態セットはこれらの状態を保存します。 

最後のエッジケースは、X がゼロの場合です。 その場合、移動しても何のメリットも得られないため、決定はより局所的に制約されます。 このアルゴリズムは移動が有用であることを前提としておらず、再生ゲインなしで明示的にキャップを適用するため、依然として機能します。
