 ## 解決策
 ## 問題の理解

 コピー品ではなく、オリジナルのぬいぐるみ 1 つからスタートします。 マシンは繰り返し適用でき、適用されるおもちゃの種類に応じて各アプリケーションのインベントリが変更されます。 

これをオリジナルのおもちゃに適用すると、そのオリジナルは事実上 2 つのオリジナルと 1 つのコピーに置き換えられ、両方のカテゴリが増加します。 これをコピーに適用すると、そのコピーは 3 つのコピーに置き換えられ、コピーの数だけが増加します。 

タスクは、初期状態を正確に変換する一連のマシン アプリケーションが存在するかどうかを判断することです。`y`オリジナルと`x`おもちゃを捨てたり、必要なタイプが存在しない場合に機械を適用したりすることなく、コピーできます。 

制約では最大 10^9 の値が許可され、すべての状態またはシーケンスにわたるシミュレーションが除外されます。 ステートを介した単純な BFS または DFS でシーケンスを段階的に構築しようとするアプローチは、両方のカウントが操作の繰り返しによって指数関数的に増加する可能性があるため、爆発的に増加します。 これは、問題が検索問題ではなく単純な算術条件に帰着する必要があることを直ちに示唆しています。 

ターゲットの 1 つが小さい場合、微妙なエッジ ケースが発生します。 たとえば、次の場合`y = 0`、オリジナルに対する操作が行われるたびにオリジナルが増加するため、このプロセスではオリジナルの数が 1 よりも減ることはありません。 同様に、`y = 1`の場合、コピーを生成する操作は最初にオリジナルに適用することから開始する必要があるため、オリジナルを 1 より大きくしないとコピーを生成できません。 

これらの境界の動作は、構造が単調かつ制約されており、自由に調整できないことを示唆しています。 

## アプローチ

 ブルートフォースの観点では、初期状態から考えられるすべての操作シーケンスをシミュレートしようとします。`(1 original, 0 copies)`。 各状態はマシンをオリジナルに適用するかコピーに適用するかに応じて分岐し、ノードがペアである状態グラフを生成します。`(orig, copy)`。 

このグラフは非常に急速に成長します。 少なくとも 1 つのオリジナルと 1 つのコピーがある状態からは、2 つの遷移が可能であり、時間の経過とともに両方のカウントが増加します。 までの境界状態も`(10^9, 10^9)`天文学的に大きな検索スペースが生成されるため、制限内では BFS または DFS が不可能になります。 

重要な観察は、実際にはシーケンスは必要ではなく、最終状態に到達できるかどうかだけが必要であるということです。 順方向のシミュレーションではなく、逆方向に推論します。 

有効な状態を生成した可能性がある最後の操作を検討します。`(y, x)`。 最後の操作がコピーに適用された場合、そのコピーは以前に存在し、追加のコピーが 2 つ作成されている必要があります。 つまり、削減することで逆転できるということです。`x`2までに。 

最後の操作がオリジナルに適用された場合、その操作の前に、システムにはオリジナルが 1 つ減り、コピーが 1 つ減ります。`( +1 original, +1 copy )`。 これを逆にすると、減算することになります`(1,1)`。 

だから、から`(y, x)`2 つの逆演算を使用して、逆方向に戻ることを試みることができます。 

から`(y, x)`に`(y-1, x-1)`もし`y > 0`、そしてから`(y, x)`に`(y, x-2)`もし`x >= 2`。 

分岐の代わりに、構造的不変条件に注目します。オリジナルを増加させるすべての操作では、コピーもまったく同じ量だけ増加しますが、コピーのみの操作では、オリジナルに影響を与えることなくコピーが増加します。 これは、オリジナルが使用された「オリジナルタイプの操作」の数を厳密に追跡していることを意味します。 

一つのオリジナルからスタートするので、`y`オリジナルとは正確に意味します`y-1`操作はオリジナルに適用されました。 このような各操作は、正確に 1 つのコピーも提供するため、すでに`y-1`コピー。 残りのコピーは完全にコピーのみの操作から取得する必要があり、それぞれが 2 つのコピーを提供します。 したがって、残りは`x - (y - 1)`負ではなく、2 で割り切れる必要があります。 

これにより、問題は単純な算術チェックに減ります。

 ## アルゴリズムのチュートリアル

 私たちは、オリジナル生産業務の役割から直接、実現可能性の条件を導き出します。 

1. 元のおもちゃに適用される操作の数を計算します。 1 つのオリジナルから開始し、そのような操作のたびにオリジナルが 1 つだけ増加するため、次のようにしたはずです。`y - 1`そのような操作。 もし`y = 0`、オリジナルは 1 を下回らないため、これはすでに失敗しています。 
2. それらの操作によって提供されたコピーを考慮します。 各オリジナル操作は正確に 1 つのコピーを提供するため、すでに`y - 1`コピー。 
3. 残りのコピーを次のように計算します。`x - (y - 1)`。 これは、純粋にコピー複製操作から作成される必要があるコピーを表します。 
4. 残りの部分の実現可能性条件を確認します。 余りがマイナスだと部数を減らすことができないので目標は達成できません。 余りが偶数でない場合、2 を繰り返し足しても形成できません。 
5. 両方の条件が当てはまる場合は「Yes」を返し、そうでない場合は「No」を返します。 

### なぜ効果があるのか

 重要な不変条件は、オリジナルの数がオリジナルに適用される演算の数を一意に決定するということです。その演算がオリジナルを増やす唯一の方法であり、常に正確に 1 だけ増加するためです。 これらの操作が修正されると、コピーへの影響も修正されます。 残された唯一の柔軟性は、オリジナルに影響を与えることなくコピーを 2 つずつ変更するコピーのみの操作にあります。 この分離により、線形制約とパリティ制約が強制され、追加の自由度は残りません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x, y = map(int, input().split())

# must have at least one original at all times
if y == 0:
    print("No")
    sys.exit()

# number of "original operations"
orig_ops = y - 1

# copies contributed by those operations
remaining = x - orig_ops

if remaining < 0 or remaining % 2 != 0:
    print("No")
else:
    print("Yes")
```コードは不変条件を直接実装します。 まず、オリジナルがゼロになるという不可能性を扱います。 次に、オリジナルに適用された操作の数を計算し、コピーへの強制的な影響を差し引きます。 残りのコピーは、非負性と偶数パリティを強制するコピー複製操作のみを使用して実現可能である必要があります。 

よくある間違いは、オリジナルは決して減らないということを忘れていることです。`y = 0`直ちに拒否しなければなりません。 

## 実用的な例

 ### 例 1

 入力:`x = 6, y = 3`私たちは計算します`orig_ops = y - 1 = 2`。 これら 2 つの操作により、すでに 2 つのコピーが作成されています。 残りのコピーは、`6 - 2 = 4`。 

| ステップ | オリグオプス | 残りの部数 | 決定 |
 | --- | --- | --- | --- |
 | 初期化 | 2 | 6 | 計算する |
 | 元の寄与を差し引く | 2 | 4 | チェック |
 | パリティチェック | 2 | 4 | 有効 |

 4 は負ではなく偶数なので、答えは「はい」です。 

これにより、元の操作の数を固定した後、システムの残りの部分は純粋にパリティによって制約されることが確認されます。 

### 例 2

 入力:`x = 3, y = 2`私たちは計算します`orig_ops = 1`。 それはすでに 1 コピーを提供しています。 残りのコピーは、`3 - 1 = 2`。 

| ステップ | オリグオプス | 残りの部数 | 決定 |
 | --- | --- | --- | --- |
 | 初期化 | 1 | 3 | 計算する |
 | 元の寄与を差し引く | 1 | 2 | チェック |
 | パリティチェック | 1 | 2 | 有効 |

 2 は偶数で負ではないため、これも可能です。 

これは、コピー数の小さな調整であっても、大きさではなくパリティによって厳密に制約されることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    x, y = map(int, input().split())

    if y == 0:
        return "No"

    orig_ops = y - 1
    remaining = x - orig_ops

    if remaining < 0 or remaining % 2 != 0:
        return "No"
    return "Yes"

# provided sample
assert run("6 3") == "Yes"

# minimum originals impossible
assert run("0 0") == "No"

# cannot reduce originals
assert run("1 0") == "No"

# simple valid chain
assert run("1 1") == "Yes"

# parity failure
assert run("3 3") == "No"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 0 0 | いいえ | オリジナルゼロは不可能 |
 | 1 0 | いいえ | オリジナルは減らない |
 | 1 1 | はい | 基本状態はすでに有効です |
 | 3 3 | いいえ | パリティ制約違反 |

 ## 特殊なケース

 重大なエッジケースの 1 つは次のような場合です。`y = 0`。 たとえ式であっても、`orig_ops = y - 1`示唆する`-1`、システムは元の値が 1 を下回ることを決して許可しないため、これを代数的に解釈しようとする試みは物理的に失敗します。 アルゴリズムは、算術を適用する前にこのケースを明示的に拒否します。 

もう 1 つのエッジケースは次のような場合です`x`よりも小さいです`y - 1`。 例えば、`x = 1, y = 5`与える`orig_ops = 4`、出発`remaining = -3`。 これはすぐに無効になり、たとえパリティが機能したとしても、状態を拒否するには否定性だけで十分であることがわかります。 

3 番目のエッジ ケースは、剰余が奇数の場合です。 例えば、`x = 4, y = 3`与える`orig_ops = 2`、出発`remaining = 2`、有効ですが、`x = 5, y = 3`葉`remaining = 3`、2 の増分に分解できないため、合計で十分なコピーがあるにもかかわらず、構成に到達できなくなります。
