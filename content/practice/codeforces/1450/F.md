 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 それぞれに問題タグのシーケンスがあり、このシーケンスのすべてのインデックスを順列に配置したいと考えています。これは、各ステップで解決する問題を並べ替えることを意味します。 

この順序付けは 2 つの制約によって形成されます。 まず、同じタグを持つ 2 つの問題を、選択した順序で並べて配置することはできません。 2 番目に、連続して選択された位置が「元のインデックス付けでどれだけ離れているか」に基づいてコストを測定します。 元の配列で隣接していないインデックス間を移動するたびに、1 単位のコストを支払います。 目標は、タグの制約を尊重し、このコストを最小限に抑える有効な順序を見つけることです。 

制約$n \le 10^5$すべてのテスト ケースにわたって、すべてのソリューションがテスト ケースごとに線形に近いことがすぐにわかります。 二次関数または偶数$O(n \log n)$テスト ケースごとのアプローチはまだ問題ありませんが、すべての順列を試したり、グローバル スキャンを繰り返し実行したりするものは遅すぎます。 

よくある失敗例は、実現可能性に影響を与えることなく、各値のインデックスを独立して自由に並べ替えられると想定していることです。 たとえば、値が何度も出現する場合、その値を他の値とインターリーブすることが常に可能であるとは限りません。 次のようなシーケンスを考えてみましょう$[1,1,1,2,2]$。 有効な順序付けでは、等しい値を区切る必要がありますが、1 つの値があまりにも多くを占めている場合、隣接性を避けることができず、回答が無効になる可能性があります。 もう 1 つの微妙なケースは、最適な配置によって局所的にはジャンプが最小限に抑えられるものの、後で不可能な隣接関係が強制される同一タグのグローバル クラスタリングが作成される場合です。 

## アプローチ

 ブルートフォースのアイデアは、インデックスのすべての順列を生成し、隣接する要素がタグ制約を満たすかどうかを確認してから、コストを計算することです。 これは正しいですが、次のような理由から実行不可能です。$n!$順列、および 1 つの順列をチェックするだけでも時間がかかります$O(n)$、要因爆発につながります。 

重要な観察は、失敗する唯一の理由は、1 つの値が分離できないほど頻繁に出現する場合であるということです。 実現可能性が確保されれば、最適な順序付けの構造は、異なる値のインデックスをどのようにインターリーブするかによってのみ決まります。 

問題を再構成できます。完全な順列について考える代わりに、異なるタグに属する一連のインデックスをどのようにつなぎ合わせるかを検討します。 コストが増加するのは、隣接していない位置間をジャンプする場合のみです。そのため、元のインデックス付けで連続したピックをできるだけ近くに保つ方法でインデックスを配置したいと考えています。 最適な戦略は、各値の出現をグループ化し、「ギャップ」を最小限に抑えながら隣接関係の競合を回避する方法でこれらのグループをインターリーブすることです。 

重要な単純化は、各値内でその出現をブロックとして扱うことです。 強制的なラージ ジャンプの数は、非ローカルな方法で異なる値のブロック間の切り替えを強制される回数によって決まります。 これは、頻度分布と順序制約に基づく組み合わせ計数問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n!)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列内の各タグの頻度をカウントします。 これにより、有効な順序で各型が何回出現する必要があるかがわかります。 
2. 実現可能性を確認します。タグが他の要素で分離できないほど頻繁に出現する場合、有効な順列は存在しません。 これは、最大周波数が残りの要素に比べて大きすぎる場合に発生します。 
3. 要素をその位置でソートまたは整理するか、タグでグループ化して、生のインデックスではなくインターリーブ構造について推論できるようにします。 
4. 貪欲なインターリーブ戦略を構築します。常に、異なるタグの要素をできるだけ長く交互に配置し、残っているタグを優先します。 
5. 元のインデックス順序で隣接していないグループから 2 つの要素を強制的に配置する必要があるときを追跡します。 このような強制的な切り替えはそれぞれコストの増加につながります。 
6. タグ制約を満たし、インデックス距離を最小化する次の有効な要素を常に選択しながら、構築をシミュレートします。 これは、別のタグ ブロックから最も近い利用可能な次の位置を常に選択することと同じです。 
7. 構築中の強制的な非隣接遷移をすべて合計します。 この合計が答えです。 

### なぜ効果があるのか

 この構築により、ローカルの隣接関係を維持する選択肢が存在しない場合にのみコストを支払うことが保証されます。 すべてのステップで有効性と最小インデックス距離の両方が貪欲に維持されるため、逸脱するとタグ制約に違反するか、不必要なロング ジャンプが発生する可能性があります。 したがって、貪欲なインターリーブは、達成可能なコストの下限マッチングを形成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict, deque

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pos = defaultdict(deque)
        for i, x in enumerate(a):
            pos[x].append(i + 1)

        # collect groups
        groups = [deque(v) for v in pos.values()]
        groups.sort(key=len, reverse=True)

        # feasibility check: if one group is too large
        mx = len(groups[0])
        if mx > n - mx + 1:
            print(-1)
            continue

        # greedy interleaving simulation
        import heapq
        heap = [(-len(g), i, g) for i, g in enumerate(groups)]
        heapq.heapify(heap)

        prev_tag = None
        prev_idx = -2
        cost = 0

        # we simulate picking next element from different group
        while heap:
            tmp = []
            chosen = None

            while heap:
                cnt, i, g = heapq.heappop(heap)
                if i != prev_tag:
                    chosen = (cnt, i, g)
                    break
                tmp.append((cnt, i, g))

            for item in tmp:
                heapq.heappush(heap, item)

            if not chosen:
                # forced switch
                cnt, i, g = tmp.pop()
                chosen = (cnt, i, g)

            cnt, i, g = chosen
            idx = g.popleft()

            if prev_idx != -2 and abs(idx - prev_idx) > 1:
                cost += 1

            prev_tag = i
            if cnt + 1 < 0:
                heapq.heappush(heap, (cnt + 1, i, g))

        print(cost)

if __name__ == "__main__":
    solve()
```制約は数値自体ではなくタグの同等性にのみ依存するため、ソリューションではまずタグごとにインデックスをグループ化します。 実現可能性チェックにより、単一のグループが過度に支配的になることがないことが保証されます。これは、隣接するタグが任意の順序で強制されるためです。 

ヒープベースの構築では、使用可能なグループが維持され、常に前のグループとは異なるグループを選択しようとします。 それが不可能な場合には、リピート構造を強いられることになり、まさにそこに追加コストが発生します。 コストは、選択された次のインデックスが元の番号付けで隣接していない場合は常に増加し、順列の「ジャンプ」を反映します。 

微妙な点は、ヒープ内で更新されたグループ サイズを維持することです。 グループからインデックスをポップするたびに、要素がまだある場合にのみ、残りのカウントを減らしてインデックスをプッシュバックします。 

## 実用的な例

 ### 例 1

 入力:```
n = 6
a = [2, 1, 2, 3, 1, 1]
```ポジションをグループ化します:

 | タグ | ポジション |
 | --- | --- |
 | 1 | [2、5、6] |

 私たちは貪欲にインターリーブを開始し、常にタグを交互に試みます。 

| ステップ | 選択されたタグ | インデックス | 前のインデックス | コスト変更 |

 コストは、隣接しないインデックスをまたぐときに増加します。これは、グループをローカルに配置できない場合に発生します。

 ## 特殊なケース

 重大なエッジ ケースは、1 つのタグがちょうど半分の時間で表示される場合です。 アルゴリズムは、自己隣接を強制することなく、慎重に交互に実行する必要があります。 もう 1 つは、異なるタグのインデックスが高度にクラスター化されている場合で、有効なタグの変更であってもインデックスのギャップによりコストが発生します。 貪欲な構造では、タグの実現可能性とインデックス距離の影響を分離することで両方を処理し、グループ間の制御された切り替えを通じて正確性を確保します。
