 ## 解決策
 ## 問題の理解

 競技プログラミング プラットフォーム上のユーザーの評価グラフを表す整数の配列が与えられます。 各整数について$k$1から$n$、配列の「k-圧縮」を考慮するように求められます。 k 圧縮は、長さのすべての連続する部分配列の最小値を取ることによって形成されます。$k$。 目標は、それぞれについて決定することです。$k$、この圧縮された配列が 1 から 1 までの数値の順列であるかどうか$n-k+1$。 そうであれば、ユーザーは満足しているので、出力します。`1`; それ以外の場合は出力します`0`。 

制約により許可されるのは、$n$到達する$3 \cdot 10^5$テストケースごと、およびすべての合計$n$テストケース全体での制限も次のとおりです。$3 \cdot 10^5$。 これは、$O(n^2)$すべての部分配列の最小値を明示的に計算するアプローチでは、およその結果が得られます。$10^{10}$最悪の場合、動作が非常に遅くなります。 テスト ケースごとに線形または線形に近い時間で実行されるソリューションが必要です。 

明らかではないエッジ ケースには、繰り返しの番号を持つ配列、すでにソートされている配列、境界に最小または最大の要素を持つ配列、および次のような非常に小さな配列が含まれます。$n = 1$。 たとえば、配列`[3,3,2]`複数の繰り返し番号があります。 素朴なアプローチではそれを見落とす可能性があります$k = 2$、最小値`[3,2]`重複を含める`3`間違って処理された場合。 

## アプローチ

 ブルートフォースアプローチは、それぞれに対して反復されます。$k$1から$n$、k 圧縮配列を明示的に構築し、それが順列を形成するかどうかをチェックします。 これは正しいですが、すべての部分配列の最小値を単純に計算するには時間がかかるため、非効率的です。$O(nk)$あたり$k$、につながる$O(n^2)$全体。 これは次の場合に失敗します。$n$アプローチ$10^5$。 

重要な洞察は、順列を形成できる最小の k 圧縮が、配列内の最小要素と最大要素の位置に依存するということです。 具体的には、配列に 1 から 1 までの各数値が含まれている場合、$n$ちょうど 1 回、配列全体が次の順列になります。$k = 1$。 次に、より大きな場合には、$k$、数値の最初と最後の出現により、スライディング ウィンドウが一意の最小値を生成できるかどうかが決まります。 各値の位置を追跡し、2 ポインター アプローチを使用して、各長さの有効なウィンドウを維持できます。 

すべての k 圧縮を生成する代わりに、最小の要素が境界にあるかどうかをチェックし、次に最小の要素が境界にあるかどうかをチェックするだけで済みます。 利用可能な最小の要素を端から繰り返し「削除」することで、すべての要素に対してバイナリ文字列を構築できます。$k$で$O(n)$テストケースあたりの時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列を読み取ります。$a$そしてその長さ$n$。 バイナリ結果配列を初期化する`ans`長さの$n$ゼロで埋められています。 
2. 配列が正しいかどうかを確認します$a$1 から 1 までのすべての数字が正確に含まれます$n$。 そうであれば、1-圧縮は順列であるため、次のように設定します。`ans[0] = 1`。 
3. 各数値の最初と最後の出現インデックスを次のように記録します。$a$。 これにより、各値がどこに表示されるかを知ることができます。 
4. 2 つのポインタを初期化します。`l = 0`そして`r = n-1`、現在のウィンドウの左端と右端を表します。 
5. 反復する`val`1から$n$昇順で:

 - もし`val`にあります`a[l]`、増分`l`。 
- それ以外の場合`val`にあります`a[r]`、デクリメント`r`。 
- それ以外の場合、次に小さい値は境界にないため、より大きなウィンドウは順列、つまりブレークになりません。 
- 正常に処理された場合`val`、 セット`ans[n - val] = 1`、ウィンドウの長さのため`n - val + 1`順列に対して有効です。 
6. バイナリ文字列を出力する`ans`。 

機能する理由: スライディング ウィンドウの一意性を維持するために、各ステップで残りの最小の数値が境界の 1 つに表示される必要があります。 現在の最小値に対応する境界要素を削除することにより、残りの部分配列が次のウィンドウ サイズの順列を形成できるという不変条件が保存されます。 数値がウィンドウ内にある場合、一意性プロパティは失敗し、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        ans = ['0'] * n
        
        # Check if full array is a permutation
        if sorted(a) == list(range(1, n+1)):
            ans[0] = '1'
        
        l, r = 0, n-1
        count = [0] * (n+2)
        for x in a:
            count[x] += 1
        
        valid = True
        for val in range(1, n+1):
            if count[val] != 1:
                valid = False
                break
        if not valid:
            ans[0] = '0'
        
        left, right = 0, n-1
        for k in range(1, n):
            if a[left] == k:
                left += 1
                ans[n-k] = '1'
            elif a[right] == k:
                right -= 1
                ans[n-k] = '1'
            else:
                break
        
        print(''.join(ans))

if __name__ == "__main__":
    solve()
```コードはまず、配列が次の順列であるかどうかをチェックします。`k=1`の最初の文字を設定します`ans`。 次に、2 ポインタ アプローチを使用して、長さを増加させて有効な順列を形成できるかどうかを検証し、更新します。`ans`終わりから始まりへ。 これにより、サブ配列の最小値を明示的に再計算することが回避され、線形な時間計算量が維持されます。
