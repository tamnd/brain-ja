 ## 解決策
 ## 問題の理解

 空のセル、X トークン、O トークンの 3 つのシンボルで満たされた正方形のボードが与えられます。 構成が「不良」になる唯一の方法は、3 つの同一のトークンが水平方向または垂直方向に直線上に連続して出現する場合です。 タスクは、そのような長さ 3 の単色セグメントがどこにも存在しないようにボードを変更することです。 

移動は、単一のトークンを裏返し、X を O に、または O を X に変えることで構成されます。空のセルは決して変化しません。 最大 ⌊k/3⌋ の移動が許可されます。ここで、k は空ではないセルの数です。 保証されるのは、この予算内で常に有効な構成に到達することが可能であり、最適な一連の移動ではなく、有効な最終グリッドを 1 つ構築するだけで十分であるということです。 

n が最大 300、テスト全体の n の合計が最大 300 という制約は、すべてのボードにわたるセルの総数が最大約 9e4 であることを意味します。 これは、テスト ソリューションごとに O(n²) が適切であることを強く示唆していますが、定数係数が小さい場合は、三次関数や修正ごとにフルグリッド スキャンを繰り返すものでも合格する可能性があります。 

微妙な点は、競合は局所的だが重複していることです。 1 つのセルが複数の不良トリプルに属する可能性があるため、単純な「一度に 1 つの違反を修正する」アプローチでは、慎重に設計されていない場合、操作が過剰にカウントされたり、不安定になったりする可能性があります。 もう 1 つの落とし穴は、検出されたすべてのトリプルを独立して貪欲に破壊することです。同じセルが複数回カウントされる可能性があるため、⌊k/3⌋ フリップ以上の時間を費やす可能性があります。 

単純な修正が失敗する最小限の例は次のとおりです。```
XXX
XXX
XXX
```すべての行と列には、重複する長さ 3 のセグメントが多数含まれています。 中央のセルを反転して各不良セグメントを貪欲に修正すると、より構造化されたソリューションが存在するにもかかわらず、同じ位置を何度も繰り返しタッチして予算を超えてしまいます。 

主な難しさは、k/3 の範囲に合わせて、各操作が最大 3 トークン相当の制約を「支払う」ように反転を選択することです。 

## アプローチ

 強引なアイデアは、変更をシミュレートし、不良トリプルがなくなるまでグリッド全体を繰り返しスキャンすることです。 各スキャンには O(n²) のコストがかかり、最悪の場合、スキャンごとに 1 つの違反しか修正できない可能性があり、合計で O(n³) 個の動作が発生する可能性があります。 これは、n が 300 までの場合には遅すぎます。 

実際の観察は、「行または列に 3 つの連続した等しいトークンがない」という条件が周期的な制約であるということです。 有効な構成では、すべての行と列に沿って、AAA のようなパターンを避ける必要があります。 AAA パターンを体系的に排除する自然な方法は、そのようなパターンを形成する可能性のある 3 つのセルが最終グリッドですべて一致しないようにすることです。 

強力な建設的なトリックは、3 を法とする座標によってセルを分類することです。水平トリプル (i, j)、(i, j+1)、(i, j+2) には、3 を法とするすべての残基を 1 回だけカバーする列インデックスがあります。 同様に、垂直トリプルも構造化された方法ですべての行残基 mod 3 にまたがります。 これにより、「ターゲット パリティ クラス」を割り当ててトークンを反転し、各 mod 3 構造内で不一致を強制することによってすべての同種トリプルを破壊することができます。 

重要なアイデアは、(i + j) mod 3 に基づいて、空でないすべてのセルを 3 つの剰余クラスに分割することです。長さ 3 の連続セグメントには、各クラスのセルが 1 つだけ含まれている必要があります。 1 つのクラス内のすべてのセルを隣接するセルとは反対のタイプに強制的に反転すると、連続する 3 つのセルが同じままになることはなくなります。 3 つのクラスがあるため、反転するのは最大でも 1 つのクラスだけであり、そのクラス サイズは最大でも ⌊k/3⌋ または ⌈k/3⌉ であり、これは制限を尊重します。 

反転が最も安価な剰余クラスを 1 つ選択します。これは、反転を最小限に抑えるために、そのクラスを X または O のどちらに強制するかを決定することを意味します。 これにより、問題はクラスごとの単純なカウント比較に変わります。

 ## アルゴリズムのチュートリアル

 1. 空ではないセルの数 k を計算します。 これはフリップの最大許容数を定義するため、以降のすべての選択では変更が k/3 を超えないようにする必要があります。 
2. (i + j) mod 3 に基づいて、空でないすべてのセルを 3 つのグループに分割します。各グループは、構造化違反パターンを直接作成せずに一貫して反転できるセルの候補セットです。 
3. 各グループについて、そのグループに含まれる X セルと O セルの数を計算します。 これにより、そのグループに一律の「反転決定」を強制するコストを見積もることができます。 
4. 各グループについて、そのグループ内のすべての X を O に反転するか、すべての O を X に反転するという 2 つの戦略を検討します。コストは、各選択肢におけるそのグループ内の不一致セルの数です。 
5. 最小コストで最適な (グループ、ターゲット タイプ) ペアを選択します。 これにより、許容される予算内に収まりながら潜在的な競合を減らすセルのみを変更することが保証されます。 
6. 選択したグループ内の、選択したターゲット文字と一致しないセルにのみ反転を適用します。 
7. 結果のグリッドを出力します。 

これが機能する理由は、任意の行または列のすべての危険な長さ 3 のセグメントが各剰余クラスと正確に 1 回交差する必要があるためです。 反転によって 1 つのクラスが他のクラスに対して「不均一」になると、トリプルは完全に等しい状態を保つことができなくなります。これは、等価であるためには 3 つの位置すべてが変更されないか、一様に変換される必要があるためですが、この構造ではそれが妨げられます。 

### なぜ効果があるのか

不変条件は、処理後、すべての行およびすべての列で、連続する 3 つの位置が同じ文字を共有できないことです。 これは、連続したトリプルが 3 つの別個の mod 3 クラスにまたがり、選択した反転後にそれらのクラスの少なくとも 1 つが他のクラスと異なることが保証されるため、当てはまります。 すべてのフリップは 1 つのクラスに制限されているため、均一なトリプルを再作成する方法で競合が他の場所で再現されることはありません。 

予算保証は、3 つの剰余クラスに対する鳩の巣原理に従います。つまり、合計 k 個の空でないセルが 3 つのクラスに分割されるため、1 つのクラスのサイズは最大 ⌊k/3⌋ になります。 そのクラス内でのみ反転します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        g = [list(input().strip()) for _ in range(n)]

        groups = [[] for _ in range(3)]
        counts = [[0, 0] for _ in range(3)]  # X, O counts

        k = 0

        for i in range(n):
            for j in range(n):
                if g[i][j] != '.':
                    k += 1
                    c = 0 if g[i][j] == 'X' else 1
                    groups[(i + j) % 3].append((i, j, c))
                    counts[(i + j) % 3][c] += 1

        best = None
        best_cost = 10**18

        for r in range(3):
            x, o = counts[r]
            # flip X -> O
            cost1 = x
            # flip O -> X
            cost2 = o

            if cost1 < best_cost:
                best_cost = cost1
                best = (r, 0)
            if cost2 < best_cost:
                best_cost = cost2
                best = (r, 1)

        r, target = best

        for i, j, c in groups[r]:
            if c != target:
                g[i][j] = 'O' if target == 1 else 'X'

        for i in range(n):
            print("".join(g[i]))

if __name__ == "__main__":
    solve()
```この実装では、最初にすべてのトークンを (i + j) mod 3 でグループ化し、グループごとにシンボルの頻度をカウントします。 これは、均質化するのに最も安価なクラスを決定するために必要な唯一の情報です。 

選択ステップでは、クラスごとに 2 つの可能な変換を比較します。 ここで、k/3 保証が暗黙的に適用されます。3 つのパーティション間で可能な最小値よりも大きいクラスを選択することはありません。 

最後に、選択したクラスにのみ反転を適用します。 これにより、許可された操作予算内に収まり、無関係な構造への影響が回避されます。 

よくある実装上の間違いは、グループ化で空のセルを無視することを忘れることです。 空のセルはトリプルの形成に無関係であるため、k またはフリップに寄与してはなりません。

 ## 特殊なケース

 重要なエッジ ケースは、いくつかの空のセルを除いて、ほぼすべてのセルが埋まっている場合です。 この場合、k は n² に近く、アルゴリズムは選択された剰余クラスが ⌊k/3⌋ を超えないことを保証する必要があります。 グループ化は純粋に構造的なものであるため、空のセルはクラスのバランスに影響を与えず、境界は有効なままになります。 

もう 1 つのエッジ ケースは、すべてのトークンが同一であるグリッドです。 ここでは、すべてのポジションがすべての潜在的なトリプルに等しく貢献します。 アルゴリズムは引き続き 1 つのクラスを選択して反転し、構造の少なくとも 3 分の 1 が変更されることを保証します。これにより、行と列にわたるすべての一様トリプルが同時に破壊されます。 

最後のエッジ ケースは、k が非常に小さい場合 (1 行に 3 つのトークンがある場合など) です。 このアルゴリズムは、サイズ 1 の mod 3 クラスを 1 つ選択し、必要に応じてそれを反転することで、唯一可能なトリプルを直接破壊します。
