 ## 解決策
 ## 問題の理解

 平面上の異なる座標に配置されたいくつかの鋼球が与えられます。 帯電したボールは、マンハッタン距離で測定される半径を持つ磁石のように機能します。 ボールをチャージするとき、ボールからマンハッタンまでの距離が最大でもすべてのボール`k`チャージされたボールの位置に瞬時に移動します。 

目標は、すべてのボールが 1 つの位置を占めるようにすることです。 当社は、任意の数の充電操作を実行できます。 テスト ケースごとに、必要な操作の最小数を決定するか、それが実行できないことを報告する必要があります。 

制約は異常に小さいです。 各テスト ケースには最大 100 ポイントが含まれており、テスト ケースの数は最大 100 です。 たとえ`O(n²)`または`O(n³)`ソリューションは簡単に十分に高速です。 と`n = 100`、`O(n²)`アルゴリズムは、テスト ケースごとに 10,000 回の距離チェックのみを実行します。 

最初のエッジケースは、すべてのポイントがすでに距離内にある場合です。`k`ある時点の。 例えば：```
3 3
6 7
8 8
6 9
```すべての点は、他のすべての点から距離 3 以内にあります。 どのボールをチャージしてもすぐにすべてのボールが集まるため、答えは次のようになります。`1`、 ない`0`。 この問題では、すべてのボールを一致させるために必要な最小限の操作が求められますが、最初はそれらは区別されます。 

もう 1 つの微妙なケースは、ポイントが接続されたチェーンを形成しているが、単一のポイントが他のすべてのポイントに到達できない場合に発生します。```
4 1
0 0
0 1
0 2
0 3
```各点は隣接する点に近いですが、他の点との距離が最大 1 である点はありません。不注意な解決策では、操作を繰り返すことですべてが徐々にマージされると想定する可能性があります。 それはできません。 正しい答えは、`-1`。 

3 番目のエッジケースは、`k = 0`。 すべての座標は個別であるため、どのボールも他のボールを引き付けることはできません。 答えはいつも`-1`。 

## アプローチ

 ブルート フォース シミュレーションでは、一連の充電操作を試し、ポイントがどのように移動するかを追跡します。 このような検索は、操作のたびに状態が変化し、可能なシーケンスの数が指数関数的に増加するため、すぐに複雑になります。 

重要な観察は、答えが 1 を超えることはないということです。 

すべてのボールが最終的にある位置に到達すると仮定します。 その最終位置は、元のボール位置の 1 つでなければなりません。 ボールが新しい座標を作成することはありません。 すべての動きは、チャージされたボールの位置をコピーします。 

成功したシーケンスの最後の操作を考えてみましょう。 その瞬間、残っているすべてのボールはチャージされたボールの位置に移動しなければなりません。 したがって、すべてのボールはすでに距離内にある必要があります`k`そのチャージされたボールの。 

移動するボールは既存のボールの位置を変更するだけなので、ある元のボールが他のすべての元のボールを直接引き付けることができれば、1 回の操作で十分です。 そのようなボールが存在しない場合、一連の操作で後でボールを作成することはできません。 

これにより、問題全体が、他のすべての点までのマンハッタン距離が最大以下である点が存在するかどうかを確認することになります。`k`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 状態空間シミュレーション | 指数 | 指数 | 遅すぎる |
 | すべての候補センターをチェック | O(n²) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースのすべてのポイントを読みます。 
2. ポイントごとに`i`、集合場所の可能性があるものとして扱います。 
3. 点からのマンハッタンの距離を計算します。`i`他のすべての点に。 
4. すべての距離が最大の場合`k`、次に充電ポイント`i`1 回の操作ですべてのボールを集めます。 出力`1`。 
5. この条件を満たす点がない場合、出力`-1`。 

### なぜ効果があるのか

 成功したシーケンスが存在すると仮定します。 最終的な操作を見てください。 チャージされたボールにはある程度の位置があります`P`、これは元のボール座標の 1 つです。 最終的に結合された位置の一部となるすべてのボールは距離内になければなりません`k`の`P`その瞬間。 

Since all positions throughout the process are copied from original ball locations, the final gathering point must correspond to an original point. If that original point cannot directly attract some other original point, then there is no way to make that point participate in the final merge. したがって、元の点が距離内にある場合にのみ、解が存在します。`k`あらゆる原点の。 

そのようなポイントが存在する場合、一度の操作ですべてのボールがすぐに集まります。 そうしないと、シーケンスは成功しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, k = map(int, input().split())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    possible = False

    for x1, y1 in pts:
        ok = True

        for x2, y2 in pts:
            if abs(x1 - x2) + abs(y1 - y2) > k:
                ok = False
                break

        if ok:
            possible = True
            break

    print(1 if possible else -1)
```外側のループでは、すべてのポイントが潜在的な集合中心としてテストされます。 内側のループは、他のすべてのポイントがマンハッタンの距離内にあるかどうかを検証します。`k`。 

初期の`break`ステートメントは便利ですが、必須ではありません。 距離が一つ超えた瞬間`k`、その候補者はもう働くことができません。 有効な候補が 1 つ見つかるとすぐに、答えがわかります。 

マンハッタンの距離は次のように計算する必要があります。```
abs(x1 - x2) + abs(y1 - y2)
```ユークリッド距離または二乗距離を使用すると、別の問題が解決されます。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n, k = map(int, input().split())
        pts = [tuple(map(int, input().split())) for _ in range(n)]

        possible = False

        for x1, y1 in pts:
            ok = True
            for x2, y2 in pts:
                if abs(x1 - x2) + abs(y1 - y2) > k:
                    ok = False
                    break
            if ok:
                possible = True
                break

        ans.append("1" if possible else "-1")

    return "\n".join(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# sample

 ## 特殊なケース

 次のことを考慮してください。```
1
2 0
0 0
1 0
```点間の距離は 1 であり、`k = 0`。 アルゴリズムは両方のポイントをチェックし、両方の候補を拒否します。 出力します`-1`。 

考慮する：```
1
2 5
0 0
3 2
```マンハッタンの距離はちょうど5です。最大でも距離が条件なので`k`、両方のポイントが対象となります。 アルゴリズムは正しく出力します`1`。 

チェーンを考えてみましょう。```
1
4 1
0 0
0 1
0 2
0 3
```中間点は隣接する点に近いため、有望に見えます。 アルゴリズムはすべての点までの距離を計算し、1 つの端点までの 2 の距離を検出し、各候補を拒否して出力します。`-1`。 

1 つの点が優勢である場合を考えてみましょう。```
1
5 10
0 0
1 1
2 2
3 3
4 4
```ポイント`(0,0)`他のすべてのポイントからマンハッタンまでの距離は最大 8 です。 アルゴリズムはそれをすぐに受け入れて出力します。`1`。 これにより、早期終了ロジックが正しいことが確認されます。
