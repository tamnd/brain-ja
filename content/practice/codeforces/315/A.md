 ## 解決策
 ## 問題の理解

 各ボトルには 2 つの特性があります。 

値`a[i]`ボトル自体のブランドです。 値`b[i]`は、このボトルが開けることができるボトルのブランドです。 

ボトルは、そのブランドと一致する開封機能を備えた他のボトルが存在する場合に開けることができます。 ボトルは既に開いているか閉じたままであるかに関係なく使用される可能性があるため、ブランド間の静的な関係のみを考慮します。 シミュレーションする一連のアクションはありません。 

ブランド入りボトルの場合`a[i]`、別のボトルが存在するかどうかを確認する必要があります`j`そのような`b[j] = a[i]`。 そんなボトルがあったらボトル`i`開けることができる。 そうしないと、決して開くことができません。 

課題は、他のボトルでは開けられないボトルが何本あるかを数えるということです。 

制約は非常に小さいです。 最大でも100本あります。 すべてのボトルのペアを比較するアルゴリズムでさえも、`100 × 100 = 10,000`制限時間内であれば簡単なチェックです。 複雑なデータ構造や最適化は必要ありません。 

微妙な点は、ボトルが自動的に開けられないことです。 ボトルかどうかを確認するとき`i`開けることができる場合は、異なるインデックスを持つボトルのみを考慮する必要があります。 

次の例を考えてみましょう。```
2
1 1
2 2
```ボトル 1 はブランド 1 を開けることができますが、その機能は同じボトルに属します。 ボトル 2 も同様に動作します。 どちらのボトルも別のボトルで開けることはできないので、答えは次のようになります。```
2
```自己照合を許可する不用意な実装では、誤った出力が発生します。`0`。 

もう 1 つの重要なケースは、複数のボトルが同じブランドを共有している場合です。```
3
1 5
1 7
2 1
```ボトル 3 はブランド 1 を開けることができるため、ブランド 1 のボトルは両方とも開けることができます。 ボトル 3 自体にはブランド 2 があり、ブランド 2 を開けるボトルはありません。正解は次のとおりです。```
1
```個々のボトルではなく固有のブランドのみをチェックする実装では、カウントを誤る可能性があります。 

3 番目のケースは、複数のボトルが同じブランドを開ける可能性がある場合です。```
3
4 4
5 4
4 1
```1 つ目と 2 つ目のボトルはどちらもブランド 4 を開けることができます。3 つ目のボトルにはブランド 4 があり、1 つ目のボトルはそれを開くことができます。 ブランド 4 のすべてのボトルは、独立して開けられると考えるべきです。 

## アプローチ

 最も直接的なアプローチは、各ボトルを個別に検査することです。 ボトル用`i`、他のすべてのボトルをスキャンし、ボトルがあるかどうかを確認します。`j`もっている`b[j] = a[i]`。 そんなボトル見つけたらボトル`i`開閉可能です。 それ以外の場合は、答えに貢献します。 

このアプローチは正しいです。なぜなら、開封可能性の定義は、開封ブランドがボトル自身のブランドと一致する別のボトルの存在にのみ依存するからです。 あらゆるボトルをチェックすることで`j`、問題で必要な条件を正確にテストします。 

制約が大きい場合、すべてのペアを比較するとコストが高くなる可能性があります。 と`n = 100`ただし、最悪の場合の比較はわずか 10,000 件であり、ごくわずかです。 

すべての開始ブランドを含むセットを構築することもできます`b[i]`そしてメンバーシップを確認します。 唯一の問題は、自動開閉が禁止されていることです。 制約が非常に小さいため、ペアごとの解決策はより単純であり、特別な処理を回避できます。 

重要な観察は、ボトルのステータスは、そのブランドが他のボトルの開封機能の中に表示されるかどうかによってのみ決まるということです。 これは当然、ボトルのすべてのペアをチェックすることになります。

 | ブランド追跡構造 | O(n²) または O(n) | O(n) | 受け入れられるが不要 |

 ## アルゴリズムのチュートリアル

 1.読む`n`すべてのペアを保存します`(a[i], b[i])`。 
2.初期化`answer = 0`。 
3. ボトルごとに`i`、最初は開けないと仮定します。 
4. すべてのボトルをスキャンします`j`。 
5. ケースをスキップする`i == j`、ボトル自体を使用して開けることはできないためです。 
6. もし`b[j] == a[i]`、次にボトル`i`ボトルで開けることができる`j`。 開封可能としてマークし、それ以上のボトルの確認を停止します。 
7. 考えられるすべてのボトルを検査した後、ボトルが`i`まだ開けません。増分します`answer`。 
8. すべてのボトルを処理した後、印刷します。`answer`。 

### なぜ効果があるのか

 ボトル用`i`、問題は、以下の開封能力を持つ別のボトルが存在するかどうかを尋ねます。`a[i]`。 アルゴリズムはすべてのボトルをチェックします`j ≠ i`。 そのようなボトルが存在する場合は、スキャン中に発見され、ボトルがボトルに入れられます。`i`開閉可能とマークされています。 ボトルが見つからずにスキャンが終了した場合、そのようなボトルは入力のどこにも存在しないため、ボトル`i`開けることは不可能です。 

この推論はすべてのボトルに独立して適用されるため、最終的なカウントは、開けられなかったボトルの数とまったく同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
bottles = [tuple(map(int, input().split())) for _ in range(n)]

answer = 0

for i in range(n):
    brand = bottles[i][0]
    openable = False

    for j in range(n):
        if i == j:
            continue

        if bottles[j][1] == brand:
            openable = True
            break

    if not openable:
        answer += 1

print(answer)
```プログラムは最初にすべてのボトルの説明を保存します。 ボトルごとにブランドを抽出します`a[i]`そして、その値と等しい開封ブランドを持つ別のボトルを検索します。 

の`i == j`check は最も重要な実装の詳細です。 それがなければ、自分のボトルは`b[i]`等しい`a[i]`would incorrectly be considered openable by itself.

 The inner loop stops immediately after finding a valid opener. This does not change correctness, but avoids unnecessary comparisons.

 No special handling is needed for duplicate brands or duplicate opening capabilities because every bottle is checked individually.

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(input())
    bottles = [tuple(map(int, input().split())) for _ in range(n)]

    answer = 0

    for i in range(n):
        brand = bottles[i][0]
        openable = False

        for j in range(n):
            if i == j:
                continue

            if bottles[j][1] == brand:
                openable = True
                break

        if not openable:
            answer += 1

    return str(answer)

# provided sample
assert run("4\n1 1\n2 2\n3 3\n4 4\n") == "4", "sample 1"

# minimum size
assert run("1\n42 42\n") == "1", "single bottle cannot open itself"

# cyclic opening
assert run("3\n1 2\n2 3\n3 1\n") == "0", "all bottles openable"

# duplicate brands
assert run("3\n1 5\n1 7\n2 1\n") == "1", "two bottles opened by same opener"

# all bottles open same brand
assert run("4\n1 5\n2 5\n3 5\n4 5\n") == "4", "no bottle brand appears among opening capabilities"
