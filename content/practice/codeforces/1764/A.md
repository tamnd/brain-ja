 ## 解決策
 ## 問題の理解

 配列が与えられ、連続するセグメントを選択するように求められます。 選択したセグメントについて、その長さとその中に現れる個別の値の数という 2 つの量を計算します。 セグメントのスコアは、長さから個別の値の数を引いたものです。 タスクは、このスコアを最大化するセグメントを見つけることです。 

より直感的に言えば、すべての位置がセグメントの長さに寄与しますが、各個別の色は個別のカウントで「1 回だけ支払う」だけです。 したがって、ある色が繰り返し出現することは有益ですが、繰り返しなしで多くの異なる色を導入するとスコアが低下する傾向があります。 

制約により、最大で次のことが許可されます。$10^5$テスト ケースごとの要素とすべてのテスト ケースの合計も$10^5$。 これにより、すべての部分配列に対する二次関数のアプローチが即座に除外されます。 ナイーブでも$O(n^2)$すべてのセグメントのスキャンが遅すぎます。 どのようなソリューションも、テスト ケースごとに本質的に線形である必要があります。 

この問題の微妙な点は、一見すると自然なことのように見えますが、最適なセグメントが必ずしも配列全体ではないということです。 完全な配列には多数の単一出現値を含めることができますが、それぞれの値はスコアに何のプラスにも寄与せず、効果的に結果を低下させます。 繰り返される値の周りに集中する小さなセグメントは、それよりも優れたパフォーマンスを発揮する可能性があります。 

すべての要素が異なる場合、一般的なエッジ ケースが発生します。 その状況では、長さのすべてのセグメントが$k$スコアがある$k-k=0$したがって、すべての単一要素セグメントが最適になります。 もう 1 つのエッジ ケースは、重複が存在するが遠く離れている場合です。この場合、その間にあるものをすべて選択すると、異なる要素が多すぎてスコアが低下する可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべてのペアを列挙します。$(l, r)$、各セグメント内の個別の要素の数を計算し、スコアを評価します。 個別のカウントを段階的に維持することは可能ですが、それでも次のような問題が発生します。$O(n^2)$セグメントと全体$O(n^2)$またはさらに悪いことに複雑になり、これは受け入れられません$10^5$。 

重要な観察は、実際に何が重要かを明らかにする方法でスコアを書き直すことです。 セグメントの場合、そのセグメント内で最初に出現した値を超えて値が繰り返し出現するたびに、スコアが 1 ずつ増加します。 同様に、スコアはセグメントに含まれる重複の数によって決まります。 単一の出現は中立ですが、同じ値が複数出現すると有益です。 

これにより視点が変わります。私たちはすべての価値のバランスを注意深く取ろうとしているのではなく、可能な限り多くの繰り返しの貢献を含めようとしているのです。 値が配列内に少なくとも 2 回出現する場合、その値が 2 回出現するセグメントは、純粋に別個のセグメントに対して負でないゲインを保証します。 

From here, a crucial simplification emerges. すべてのセグメントを検索する代わりに、複数回出現する値を選択し、その出現のうち 2 つをカバーするセグメントを返すだけで十分です。 そのセグメントは、少なくとも 1 つの重複した寄与をすでにキャプチャしているため、最適であるか、最適に結合されていることが保証されますが、単一要素または完全に別個のセグメントはその構造を超えることはできません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | Brute Force over all subarrays |$O(n^2)$|$O(1)$または$O(n)$| 遅すぎる |
 | 繰り返される値の最初/最後の出現 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列をスキャンし、各値の最初と最後の位置を保存します。 これにより、値が複数回出現するかどうか、およびその極端な出現がどこにあるかを検出できます。 
2. 値が少なくとも 2 回出現するかどうかを確認します。 値が繰り返されない場合、各セグメントにはすべて個別の要素が含まれるため、単一のインデックスが最適な答えを形成します。 
3. 繰り返される値が存在する場合は、そのような値を選択します。 最初の出現を次のようにします$l$そしてその最後の発生は$r$。 このセグメントを出力します。 

繰り返される任意の値で安全に停止できる理由は、この目標が繰り返しの出現のみに報酬を与え、同じ値の出現を 2 つ含むセグメントは、純粋に別個の要素で構成されるセグメントよりも厳密に優れた構造をすでに達成しているためです。 

### なぜ効果があるのか

 セグメントのスコアは、「セグメント内に最初に出現したものを超える余分な出現の数」として解釈できます。 2 回出現する値は、両方の出現が含まれる場合、少なくとも 1 つのそのような追加の出現に寄与します。 重複のないセグメントはプラスには何も寄与しないため、ゼロに制限されます。 セグメントに繰り返し値が含まれると、そのセグメントはすべて異なるセグメントと競合するか、それよりも優れたものになります。また、追加の要素を含めてもすでに存在する重複した寄与の数を減らすことができないため、セグメントを拡張しても正確性が無効になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    first = {}
    last = {}
    
    for i, x in enumerate(a, 1):
        if x not in first:
            first[x] = i
        last[x] = i
    
    l, r = 1, 1
    found = False
    
    for x in first:
        if first[x] != last[x]:
            l, r = first[x], last[x]
            found = True
            break
    
    print(l, r)
```この解決策は、単一パス内の各値の最初と最後の出現を記録することに依存しています。 これにより、サブ配列をスキャンせずに繰り返し要素を識別できるようになります。 最後のループでは、繰り返される値を選択し、その極値位置を出力します。 繰り返しが存在しない場合は、デフォルトの出力がそのまま残ります。$1, 1$すべての単一要素セグメントのスコアが等しいため、これは有効です。 

一般的な実装の落とし穴は、セグメントごとに個別のカウントを計算しようとしたり、間隔を動的に最適化しようとしたりすることです。 目的の構造により、間隔全体での最適化ではなく、繰り返しの検出の問題が解決されるため、これは不要です。 

## 実用的な例

 配列を考慮してください$[1, 3, 2, 2, 4]$。 最初と最後の出現は次のように追跡されます。$1:(1,1)$、$3:(2,2)$、$2:(3,4)$、$4:(5,5)$。 値$2$唯一繰り返されるものなので、出力します$3, 4$。 これは重複をキャプチャすることですでにプラスのスコアを達成しています。 

ここで考えてみましょう$[1, 2, 3, 4, 5]$。 すべての値は 1 回だけ出現するため、繰り返される値は存在しません。 アルゴリズムの出力$1, 1$。 すべてのセグメントのスコアが 0 であるため、単一のインデックスは同様に有効です。 

より微妙なケースは、$[2, 1, 2, 1]$。 ここでは両方とも$1$そして$2$繰り返す。 選ぶなら$1$、出力します$2, 4$、そして私たちが選ぶなら$2$、出力します$1, 3$。 両方のセグメントに少なくとも 1 つの繰り返し値が含まれているため、両方とも有効です。 

これらの例は、アルゴリズムがセグメントの微調整を試みるのではなく、改善の唯一の源として反復の存在に依存していることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        first = {}
        last = {}

        for i, x in enumerate(a, 1):
            if x not in first:
                first[x] = i
            last[x] = i

        l, r = 1, 1
        for x in first:
            if first[x] != last[x]:
                l, r = first[x], last[x]
                break

        out.append(f"{l} {r}")

    return "\n".join(out)

 ## 特殊なケース

 すべての要素が異なる場合、最初と最後に異なる値がないため、アルゴリズムは単一の位置を返すようにフォールバックします。 たとえば、入力$[4, 7, 9]$生成する$1, 1$、および他の単一インデックスは、すべてのセグメントのスコアが 0 であるため、同様に有効です。 

複数の値が繰り返される場合、アルゴリズムは最初に検出された値で停止します。 入力用$[5, 1, 5, 1]$、どちらの値も有効なアンカーです。 スキャンが成功した場合$5$、出力します$(1, 3)$; それが選ばれたら$1$、出力します$(2, 4)$。 どちらも同じ最適スコアを達成するため、どちらでも正しいです。 

繰り返される値が 2 回しか出現しないが、多くの個別の値で囲まれている場合でも、少なくとも 1 つの重複の存在によって負の寄与がないことが保証され、個別の要素が追加されても最適性が無効になることはないため、セグメントは引き続き有効です。
