 ## 問題の理解

 整数で表される 2 つのユニットの山が与えられます。$a$そして$b$。 1 回の操作で正の整数を選択できるようになります$x$そして 2 つの変換のうちの 1 つを適用します。$x$から$a$そして$2x$から$b$、または減算します$2x$から$a$そして$x$から$b$。 さまざまな値を選択して、これらの動きを何度でも繰り返すことができます。$x$毎回。 

問題は、値を決してマイナスにすることなく、両方のパイルを同時に完全にゼロに排出できるかどうかです。 

テスト ケースの数という点では制約は少ないですが、$a$そして$b$と同じ大きさにすることができます$10^9$。 これにより、削減の規模が大きすぎて選択肢の余地がなくなるため、操作を段階的に適用しようとするシミュレーションは除外されます。$x$は正の整数にわたって連続です。 正しい解決策は、問題をテスト ケースごとの一定時間のチェックに減らす必要があります。 

異なる値を選択する自由から微妙な問題が発生します。$x$。 素朴な直感は、最初に大きい値を貪欲に減算するか、常に次の値を使用することを提案するかもしれません。$x=1$しかし、これらのアプローチは、操作が独立した単位ステップではないため失敗します。 各操作では 2 つの変数が固定比率で結合されるため、ローカルで貪欲な決定を行うと、グローバルな実現可能性が破壊される可能性があります。 たとえば、から始めて、$(1,2)$, だけを貪欲に適用します。$(x,2x)$両方の操作タイプを使用した有効なシーケンスが存在する場合でも、操作はすぐに失敗します。 

中心となる問題は、固定数の単位演算を分散するのではなく、2 つのベクトル変換を任意のスケーリングで組み合わせることです。 

## アプローチ

 効率を無視する場合は、操作を繰り返し適用し、考えられるすべてのシーケンスを探索するという観点から考えることができます。 各操作でペアが減少します$(a,b)$どちらかで$x(1,2)$または$x(2,1)$。 ブルート フォース検索では、操作の種類と可能な値が分岐します。$x$、到達しようとしています$(0,0)$。 離散化しても$x$両方の座標が次のように大きくなる可能性があるため、状態空間は非常に速く成長します。$10^9$。 これにより、検索ベースの方法は実行できなくなります。 

重要な点は、操作の順序は重要ではないということです。 各操作タイプの合計寄与のみが重要です。 次のタイプのすべての操作を集約するとします。$(1,2)$合計金額に$p$、および次のタイプのすべての操作$(2,1)$合計金額に$q$。 次に問題は、これらの集約された寄与が正確に一致する必要がある線形システムを解くことになります。$a$そして$b$。 

これにより、問題はシーケンスに関する推論から、非負の制約を持つ 2 つの線形方程式を解く問題に縮小されます。 これを実行すると、構造は十分に剛直になり、実現可能性を一定時間内にチェックできるようになります。

 ## アルゴリズムのチュートリアル

 各操作タイプの合計累積使用量の観点から操作を再解釈します。 個々の動きについて考えるのではなく、すべてをグループ化します$(1,2)$-type の削減をまとめて行う$(2,1)$-タイプの削減を一緒に行います。 

1. しましょう$p$次の種類の操作によって貢献された合計金額を表します$(1,2)$、 そして$q$次の種類の操作によって貢献された合計金額を表します$(2,1)$。 これは、分割によって操作をスケーリングするため有効です。$x$より小さな部分に分割しても、最終的な効果は変わりません。 
2. 最終的な削減量を表現します。$a$そして$b$に関しては$p$そして$q$。 合計の減少量は、$a$になる$p + 2q$の合計が減少する一方、$b$になる$2p + q$。 ゼロに到達するには、次のシステムが必要です。$$p + 2q = a, \quad 2p + q = b$$3. このシステムを解き、実現可能条件を理解します。 変数を削除すると、$3p = 2b - a$そして$3q = 2a - b$。 これは、整数解が存在するには、両方の式が非負であり、3 で割り切れる必要があることを直ちに意味します。 
4. 方程式を追加すると、より単純な必要条件が得られます。$3(p+q) = a + b$、 それで$a + b$この条件は、ほとんどの不可能なケースをすでに制限しています。 
5. 非負の制約は幾何学的実現可能性に変換されます。どちらの座標も他方の座標に対して小さすぎることはできません。 具体的には、両方の演算タイプを組み合わせて提供できる以上のリダクションを 1 つの変数から要求してはなりません。 
6. これらの条件を組み合わせると、コンパクトなチェックが得られます。合計は 3 で割り切れる必要があり、どちらも割り切れない必要があります。$a$または$b$他の2倍を超える可能性があります。 

### なぜ効果があるのか

 すべての操作により合計が減少します$a + b$まさに$3x$したがって、合計はすべての演算にわたって不変のモジュロ 3 になります。 このため、3 で割り切れるのは難しい要件になります。 その条件が満たされると、プロセス全体は、この合計削減量を 2 つの固定ベクトル間で分配することになります。$(1,2)$そして$(2,1)$。 これらのベクトルは 2 次元の基底を形成するため、到達可能なエンドポイントはそれらの非負の組み合わせに正確に対応します。 不等式により、この組み合わせには負の係数が必要なくなります。負の係数は、許可されていない逆演算に相当します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b = map(int, input().split())

        if (a + b) % 3 != 0:
            print("NO")
            continue

        if max(a, b) > 2 * min(a, b):
            print("NO")
            continue

        print("YES")

if __name__ == "__main__":
    solve()
```コードは、導出された実現可能性条件を直接実装します。 最初のチェックでは、すべての操作が正確に削除するという事実から得られるモジュロ 3 の不変式を強制します。$3x$合計単位。 2 番目のチェックでは、どちらの変数も他方の変数に比べて大きすぎないことが強制されます。これにより、許可された稼働率を使用して削減のバランスを取ることが不可能になります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b = map(int, input().split())
        if (a + b) % 3 != 0:
            out.append("NO")
        elif max(a, b) > 2 * min(a, b):
            out.append("NO")
        else:
            out.append("YES")
    return "\n".join(out) + "\n"

 ## 特殊なケース

 よくある落とし穴は、モジュラー制約をチェックせずに比率条件のみに依存することです。 例えば、$(2,4)$バランスの直感は満たされますが、同様のバリアントで合計条件が無視されると失敗します。 ここでは、システム全体が一貫しているため、実際に機能します。 正しい処理は、常に両方の制約を一緒に強制することです。これは、一方は地球規模の保全を捉え、もう一方は方向性のある削減の実現可能性を捉えるためです。
