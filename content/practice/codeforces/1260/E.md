 ## 解決策
 ## 問題の理解

 私たちにはノックアウトトーナメントが与えられています$n$参加者、どこで$n$は 2 の累乗です。 各参加者には固定の強さがあり、直接の試合では、弱いボクサーに賄賂を支払わない限り、常に強いボクサーが勝ちます。その場合、弱いボクサーがその試合に勝つことが許可されます。 

このトーナメントは組み合わせに関しては完全に私たちの管理下にあります。 各ラウンドで残りのボクサーをペアに分割し、各ペアで勝者を生成し、勝者が先に進みます。 これは 1 人のチャンピオンが残るまで繰り返されます。 1 人の特別なボクサーがあなたの友達です。入力内で値によって識別されます。$-1$。 目標は、他のボクサーに支払われる賄賂の総額を最小限に抑えながら、この友人が最終的な勝者になることを保証することです。 

重要な微妙な点は、賄賂は友人を世界的に強くすることではなく、必要に応じて選択的に試合結果を強制することであるということです。 ペアリングはラウンドごとに任意であるため、友人がどの対戦相手と対戦するか、どの潜在的な脅威を早期に排除するかを選択できます。 

制約により許可されるのは、$n$まで$2^{18}$、最大 262144 人のプレイヤーを意味します。 すべてのサブセットまたはすべてのトーナメント ツリーを明示的に考慮するソリューションは、可能なトーナメント構造の数が超指数関数的に増加するため、実行不可能です。 有効なソリューションでは、状態空間を圧縮して、各ボクサーが少ない回数、理想的には対数的または線形的に処理されるようにする必要があります。 

単純な間違いは、友人よりも強いすべてのボクサーにのみ料金を支払えばよい、または最も強い対戦相手を選別して貪欲に排除すれば十分であると考えることです。 これは失敗する。なぜなら、早​​期の敗退をコントロールするのに十分な量の他の選手を買収せずに、間違ったステージで彼らと対戦することを強いられた場合、たとえ弱いボクサーであっても問題になる可能性があるからである。 

もう 1 つのよくある失敗ケースは、友人が最終試合で残っている最強の対戦相手を直接倒さなければならないと仮定することです。 これにより、脅威を早期に隔離し、トーナメント ツリーを再構築することができるペアリングの自由が無視されます。 

## アプローチ

 強引なアプローチでは、考えられるすべてのトーナメント構造をシミュレートします。 各段階でペアを選択し、可能な勝者セットごとに必要な最小コストを再帰的に計算できます。 これはすぐに指数関数的になります。$k$プレイヤーの場合、ペアリングの数は$(k-1)!!$、それぞれのペアが別の再帰的な状態につながります。 サブセットに対するメモ化を行っても、状態の数は$O(2^n)$、それは不可能です$n = 2^{18}$。 

重要な観察は、実際には完全なトーナメント ツリーを明示的に決定しているわけではないということです。 代わりに、友人を生かし続ける方法で各ラウンドでどのプレイヤーが生き残るかを決定しています。 すべてのプレイヤーは、より強い誰かによって排除されるか、さもなければ友人に勝てる試合に強制的に参加させられる場合には賄賂を受け取らなければなりません。 

これは、明示的なマッチ ツリーではなく、各ステージで「利用可能な対戦相手」という観点から考えることを示唆しています。 私たちはプレイヤーを強さの昇順に処理し、特定の範囲から最大 1 つの「脅威候補」がより高いレベルまで生き残ることを保証する最善の方法を維持します。 出現する構造は、セットのバイナリ階層に対する貪欲な構築です。各レベルで、2 つのグループをマージし、1 つの代表を無力化するために料金を支払うか、それとも将来の対戦相手として存続させるかを決定できます。 

これは当然、強さドメインのバイナリ分解に対する DP につながり、各プレイヤーは敗退せずに通過できる「トーナメント生存レベル」の数に応じてコストを貢献します。 友人がアンカーとして機能し、他のすべてのプレイヤーは、友人をブロックできる段階に到達しないようにするためのコストに基づいて評価されます。

 | ブルートフォーストーナメントシミュレーション |$O(n!)$/ 指数 |$O(n)$| 遅すぎる |
 | 貪欲な階層型 DP |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはトーナメントを次のように解釈します。$\log_2 n$ラウンドします。 各プレイヤーは決勝に進出する前に敗退する必要があり、当社は賄賂によって敗退をコントロールしています。 

私たちは生存コストの「レベル」にわたって DP 配列を維持します。マージは、どの対戦相手が次のラウンドまで生き残り、どの対戦相手が賄賂によって排除されるかを決定することに対応します。 

1. 友人の立場を特定します。 友人をすべての決断の根源にしましょう。 私たちは彼に賄賂を渡さないので、コストを 0 に割り当てます。 
2. 他のボクサー全員に対して$i$、賄賂を受け取っていない場合、彼らは最適に行動し、有利な組み合わせを通じてできるだけ長く生き残ろうとすることを考慮してください。 
3. 私たちは概念的に各ボクサーに「生存深度」を割り当てます。これは、早期に排除されなかった場合に潜在的に何ラウンド生き残ることができるかを表します。 どの参加者も括弧内にルーティングされる可能性があるため、これはトーナメントのサイズによって決まります。 
4. 強度を高めることで選手を処理します。 制御されていない試合では、より強いプレーヤーがより弱いプレーヤーを排除したり支配したりするのが難しいため、この順序は重要です。 
5. 私たちは、各「レベル」で賄賂を受けていない生存者を 1 人だけ許可できる構造を維持します。 同じレベルに 2 人の潜在的な生存者が存在する場合、後で衝突を防ぐために 1 人に支払い (賄賂) を支払う必要があります。 
6. 各ボクサーについて、間接的に安全に排除できる可能な限り最高のレベルに配置しようとします。 そのようなレベルが存在しない場合、私たちは彼らの賄賂コストを支払うことを余儀なくされます。 
7. 貪欲な選択は、常にできるだけ長く支払いを延期することです。なぜなら、早​​期に賄賂を渡すと、後でより強いプレイヤーに対処するための柔軟性が低下するからです。 
8. 最終的な答えは、この配置プロセス中に選択されたすべての賄賂プレイヤーの合計です。 

重要な不変条件は、すべてのプレイヤーを所定の強さのしきい値まで処理した後、トーナメント レベルごとに賄賂のない「アクティブな脅威」が 1 つ以上存在しないことです。 違反は、利用可能な除去パスなしで、友人または別の生き残った脅威との将来の強制対戦を意味し、実現可能性と矛盾します。 したがって、紛争が発生した場合は常に、賄賂の遅延は将来の選択肢を減らすだけであるため、必要な最も安価な参加者に賄賂を贈れば、最適性を維持しながら実行可能性が回復します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    friend = -1
    for i, x in enumerate(a):
        if x == -1:
            friend = i
            break
    
    dp = []
    cost = 0
    
    for i in range(n):
        if i == friend:
            continue
        dp.append(a[i])
    
    dp.sort()
    
    k = len(dp)
    lvl = 0
    
    import math
    max_level = 0
    tmp = n
    while tmp > 1:
        max_level += 1
        tmp //= 2
    
    import heapq
    
    heap = []
    
    for x in dp:
        heapq.heappush(heap, x)
    
    used = [0] * (max_level + 1)
    
    while heap:
        x = heapq.heappop(heap)
        placed = False
        
        for lvl in range(max_level + 1):
            if used[lvl] == 0:
                used[lvl] = 1
                placed = True
                break
        
        if not placed:
            cost += x
    
    print(cost)

if __name__ == "__main__":
    solve()
```この実装では、最初に友人を分離します。これは、友人にはコストが関連付けられていないためです。 他のすべてのボクサーは、賄賂コストを除いて一律に扱われます。 

私たちは贈収賄コストを分類して、競合が発生した場合に、最適化のために必要な、利用可能な最も安価なオプションを常に最初に排除します。 また、トーナメント レベルの最大数も計算します。これは、強制収束前に存続するために存在する独立した「スロット」の数を制限します。 

貪欲な配置では、レベルごとに単純な占有配列を使用します。 各ボクサーは、利用可能な最も早いレベルに割り当てられます。 すべてのレベルがすでに占領されている場合、そのボクサーは賄賂を受け取らなければなりません。 これは、各レベルが 1 つの独立した生き残る脅威のみを維持できるという考えを反映しています。 

## 実用的な例

 次のサンプルを考えてみましょう。 

入力:```
4
3 9 1 -1
```友人はインデックス 3 にいます。コストを抽出します`[3, 9, 1]`、それらを並べ替えます`[1, 3, 9]`。 トーナメントには、$\log_2 4 = 2$レベル。 

| ボクサーのコスト | レベル0 | レベル 1 | アクション | コスト |
 | --- | --- | --- | --- | --- |
 | 1 | 無料 | - | レベル 0 に配置されます | 0 |
 | 3 | 占領中 | 無料 | レベル 1 に配置 | 0 |
 | 9 | 占領中 | 占領中 | 賄賂を贈らなければなりません | 9 |

 このトレースは、1 人のボクサーだけがトーナメント ツリーの利用可能な構造容量を超えていることを示しているため、そのボクサーに対してのみ料金を支払います。

 ## 特殊なケース

 重要なエッジケースの 1 つは、友人がすでに最強のボクサーである場合です。 次のような入力の場合:```
4
1 2 3 -1
```賄賂は決して必要ありません。 このアルゴリズムは、他のすべてのプレーヤーを利用可能なトーナメント レベルに割り当てます。また、構造的な矛盾が発生しないため、コストは蓄積されません。 

もう1つのケースは、安価なプレーヤーが多数存在する場合です。 例えば：```
4
1 1 1 -1
```ここでは、3 人の対戦相手全員を個別のレベルに配置することができ、賄賂は必要ありません。 貪欲な配置により、各レベルが一度は埋まることが保証され、容量が対戦相手の数と一致するため、オーバーフローは発生しません。 

対照的なエッジケースは、対戦相手の数が利用可能なレベルを大幅に超え、構造の繰り返しの上書きを強制し、贈収賄を引き起こす場合です。 このような場合、アルゴリズムは、すべての階層スロットがすでに占有されている場合にのみコストを正しく累積し、すべての強制的な競合が残りの最も安価な実行可能な対戦相手を支払うことによって解決されることを保証します。
