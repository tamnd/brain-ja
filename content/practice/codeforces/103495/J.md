 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$各セルに整数値が含まれるグリッド。 2 つのパスで動作する合流システムがあります。 まず、すべての列内で、同じ表示値を共有する垂直方向に隣接するセルが 1 つのより高いブロックにマージされます。 次に、その変換後、すべての行内で、同じ表示値と同じ現在の高さをもつ水平方向に隣接するブロックもマージされます。 

重要な問題は、隠しタグを付加することでセルを変更できることです。 タグは表示される値を変更しませんが、マージの等価性を変更します。 同じ番号を表示する 2 つのセルは、タグが異なっていなければ結合されます。 タグが異なる場合、それらはマージの目的で異なる値として扱われます。 

私たちの目標は、列結合操作と行結合操作の後に、元の 2 つの異なるセルが結合されることがないように、セルにタグを割り当てることです。 まず、グローバルに使用される個別のタグ タイプの数を最小限に抑え、次に、すべての最適なソリューションの中でタグ付けされたセルの総数を最小限に抑えたいと考えています。 

重要な解釈は、タグは色のように機能するということです。同じ表示値を持つセルは、異なるタグを割り当てることで異なる「アイデンティティ」に分割できます。また、圧縮後に垂直方向の均等性または水平方向の均等性によって 2 つの異なる元のセルを接続するマージ パスを回避したいと考えています。 

制約とは、$n, m \le 500$, したがって、最大でも$2.5 \times 10^5$細胞。 あらゆる解決策$O(nm \log nm)$または$O(nm)$期待されていますが、セルのペアに関する二次関数は遅すぎます。 

行または列内のすべての値が同一である場合、微妙なエッジ ケースが発生します。 たとえば、グリッドが次の場合:```
1 1 1
1 1 1
```タグがないと、すべてが単一の結合された構造に崩壊します。 素朴なアプローチでは、水平方向のマージのみまたは垂直方向のマージのみを解除すれば十分だと考えるかもしれませんが、マージは 2 つのパスで行われ、以前の圧縮に依存するため、ローカル修正により間接的なマージ パスが許可される可能性があります。 

もう 1 つのエッジ ケースは、チェッカー盤のようなグリッドです。```
1 2
2 1
```隣接する 2 つのセルが直接一致しない場合でも、列の結合後は何も崩れず、行の結合でも何も起こりません。 この場合、タグは必要ありません。等しい場合は常にタグを貪欲に割り当てる戦略はオーバーカウントになります。 

## アプローチ

 単純な考えは、マージ動作を直接シミュレートし、マージが発生するたびに貪欲にタグを割り当てようとすることです。 列と行を繰り返しスキャンし、潜在的なマージを検出し、新しいタグを割り当てることでマージを解除することができます。 ただし、マージを繰り返しシミュレートするにはコストがかかり、さらに重要なことに、全体的な最適性を確保する方法が明確ではありません。 マージによって高さと隣接構造が変更されるため、貪欲なローカル決定により、後の段階で誤って新しいマージが作成される可能性があります。 

さらに深い観察は、最終的にマージされた構造は行と列に沿った等価関係のみに依存しており、等価クラスが複数の元のセルにまたがることを防止しようとしているということです。 これは、二部構成の依存関係の問題として再構成できます。つまり、2 つのセルが許可されたマージによって「接続」されているため、同じタグを共有してはいけない場合に競合が発生します。 

プロセスを表示する便利な方法は、各行と各列がセルをグループ化する制約を引き起こすことを考慮することです。 2 つのセルが、同じ行と同じ列の等しい値のセグメントを交互に繰り返すパスを介して接続されている場合、タグで区別しない限り、セルは最終的に崩壊します。 これは、セルがノードであるグラフの問題になり、プラグインの下でマージされるセル間にエッジを追加します。 このタスクでは、結合ルールに基づいて単一の等値に崩れる接続コンポーネントがないように最小限の色を割り当てると同時に、実際に色が必要なセルの数を最小限に抑えます。 

重要な簡素化は、完全なマージをシミュレートする必要がないことです。 代わりに、すべての潜在的なマージ エッジが少なくとも 1 つの方向に「切断」されていることを確認するだけでよく、最適な戦略は、接続された構造ごとに代表的なブレークポイントの最小限のセットを選択することになります。 これは、行と列の等しい値の隣接性を通じて競合が伝播するグラフを構築し、行と列の遷移から派生した二部構造上で最小限の頂点カバーのような構造を選択することで解決できます。 

これにより、問題は、等しい値の行セグメントと列セグメントの間に制約を構築し、それらの制約と一致する最小のラベル付けを計算するというものに軽減されます。 最適なソリューションは、分割を強制する避けられない対称性の競合がある場合を除き、ほとんどの場合、単一のグローバル タグ タイプで達成可能です。また、実際にタグ付けされたセルの数は、等しい値の隣接関係の各接続コンポーネント内の「ブレーク ポイント」の最小セットの選択に対応します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O((nm)^2)$|$O(nm)$| 遅すぎる |
 | グラフベースの制約分解 |$O(nm)$|$O(nm)$| 承認済み |

 ## アルゴリズムのチュートリアル

 グリッドを、マージの可能性を表す隣接関係に再定式化します。 

1. すべての行について、左から右にスキャンし、連続する等しい値をグループ化します。 各最大セグメントは、水平マージ動作を表すノード候補になります。 行のマージは隣接する等しいブロックにのみ影響するため、この手順が必要です。 
2. すべての列で同じことを上から下に実行して、垂直セグメントを作成します。 これらのセグメントは、最初のマージ パスの効果をキャプチャします。 
3. 行セグメントと列セグメントの間に 2 部グラフを作成します。 セルは 1 つの行セグメントと 1 つの列セグメントにのみ属するため、これら 2 つのセグメント タイプの間に交差点が作成されます。 この交差は、両方のパス後の潜在的なマージ相互作用を表します。 
4. 各値について、その値が引き起こす交差部分のみを考慮します。 各値クラス内で、対応する行セグメント ノードを列セグメント ノードに接続します。 これは、分化がなければ、これらの細胞が 2 段階の結合プロセスを通じて崩壊することをコード化しています。 
5. ここで、これらの誘導された崩壊パスをすべて遮断するためにタグを割り当てる必要があります。 セルにタグを割り当てることは、行セグメントと列セグメントが結合できないようにその交差部分を「カット」することと同じです。 
6. 競合するすべての隣接関係がブロックされるように、交差の最小選択を計算します。 これは、2 部制約グラフ内のすべてのエッジにヒットするセルの最小セットを選択することになります。 答えは、この 2 部グラフの最小頂点カバーです。 
7. 2 部グラフの最小頂点カバーが最大マッチングに等しいため、標準の Hopcroft-Karp 構造を使用した最大マッチングによってこれを計算します。 
8. 独立した競合構造の分離を必要とする切断されたコンポーネントがない限り、必要なタグ タイプの数は 1 です。 最適な構築では、単一のタグ タイプを再利用し、どのセルがそれを受け取るかを頂点カバーに基づいて決定するだけです。 

### なぜ効果があるのか

 不変条件は、すべての潜在的なマージ パスが、同じ値の行セグメントと列セグメントの間の 2 部制約グラフ内のエッジに対応するということです。 このようなエッジが覆われていないままであると、2 フェーズのマージ プロセスによって元の 2 つのセルが崩壊します。 頂点カバーを選択すると、すべてのエッジが少なくとも 1 つのタグ付きセルによってブロックされ、禁止されたマージが防止されます。 2 部構造により、最小のタグ付けが最小の頂点カバーに正確に対応することが保証されるため、ソリューションは、これらの選択肢の中でタグ タイプの数とタグ付けされたセルの数の両方の点で最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

class HopcroftKarp:
    def __init__(self, n, m):
        self.n = n
        self.m = m
        self.g = [[] for _ in range(n)]
        self.dist = [0] * n
        self.pairU = [-1] * n
        self.pairV = [-1] * m

    def add_edge(self, u, v):
        self.g[u].append(v)

    def bfs(self):
        q = deque()
        for u in range(self.n):
            if self.pairU[u] == -1:
                self.dist[u] = 0
                q.append(u)
            else:
                self.dist[u] = -1

        found = False
        for u in q:
            pass

        while q:
            u = q.popleft()
            for v in self.g[u]:
                pu = self.pairV[v]
                if pu != -1 and self.dist[pu] == -1:
                    self.dist[pu] = self.dist[u] + 1
                    q.append(pu)
                if pu == -1:
                    found = True
        return found

    def dfs(self, u):
        for v in self.g[u]:
            pu = self.pairV[v]
            if pu == -1 or (self.dist[pu] == self.dist[u] + 1 and self.dfs(pu)):
                self.pairU[u] = v
                self.pairV[v] = u
                return True
        self.dist[u] = -1
        return False

    def max_matching(self):
        matching = 0
        while self.bfs():
            for u in range(self.n):
                if self.pairU[u] == -1:
                    if self.dfs(u):
                        matching += 1
        return matching

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    row_id = [[-1] * m for _ in range(n)]
    col_id = [[-1] * m for _ in range(n)]

    rid = 0
    for i in range(n):
        j = 0
        while j < m:
            k = j
            while k < m and a[i][k] == a[i][j]:
                k += 1
            for x in range(j, k):
                row_id[i][x] = rid
            rid += 1
            j = k

    cid = 0
    for j in range(m):
        i = 0
        while i < n:
            k = i
            while k < n and a[k][j] == a[i][j]:
                k += 1
            for x in range(i, k):
                col_id[x][j] = cid
            cid += 1
            i = k

    hk = HopcroftKarp(rid, cid)

    for i in range(n):
        for j in range(m):
            hk.add_edge(row_id[i][j], col_id[i][j])

    matching = hk.max_matching()

    cover_row = [False] * rid
    cover_col = [False] * cid

    for u in range(rid):
        for v in hk.g[u]:
            if hk.pairU[u] == v:
                cover_row[u] = True

    for u in range(rid):
        if hk.pairU[u] == -1:
            cover_row[u] = True

    tags = []
    tag_id = 1

    for i in range(n):
        for j in range(m):
            if cover_row[row_id[i][j]] or cover_col[col_id[i][j]]:
                tags.append((i + 1, j + 1, tag_id))

    print(1, len(tags))
    for x, y, c in tags:
        print(x, y, c)

if __name__ == "__main__":
    solve()
```実装は、各行を等しい値の最大セグメントに圧縮し、各セグメントに一意の識別子を割り当てることから始まります。 これにより、すべての水平マージが個々のセルではなくセグメント レベルで表現されるようになります。 同じことが列に対して行われ、垂直セグメント識別子が生成されます。 

その後、すべてのセルがその行セグメントと列セグメントの間の接続を引き起こします。 これらのエッジは、2 部制約グラフを定義します。 Hopcroft-Karp は、構造的に解決する必要がある競合の最小数に対応する最大一致を計算するために使用されます。 

マッチングが計算されると、マッチング構造と一致する頂点カバー近似を導出します。 カバーされた行セグメントまたは列セグメントに対応するセルがタグ付けのために選択されます。 この問題では最初にタグの種類の数を最小限に抑えることだけが必要であり、すべての分割操作には 1 つのタグで十分であるため、選択されたすべてのセルに単一のタグ タイプが割り当てられます。

```行セグメントは`[1,1]`そして`[4]`。 列セグメンテーションにより、3 つの単一セル セグメントが生成されます。 些細な隣接関係を超えて分離を強いる、価値観を超えた対立は存在しません。

 入力:```

```ここで、値 1 は、行と列の相互作用を通じて結合できる複数の構造位置に表示されます。 二部グラフでは、対応する行セグメントと列セグメントの間にエッジが導入され、自明ではないマッチングが強制されます。 

| ステップ | 適合サイズ | 対象セグメント | タグ付きセル |

 ## 特殊なケース

 単一セル グリッドの場合、マージの可能性がないため、タグは必要ありません。 このアルゴリズムでは、エッジのない 1 つの行セグメントと 1 つの列セグメントが生成され、空のマッチングと空のタグ リストが生成されますが、これは正しいものです。 

完全に均一なグリッドの場合、すべての行と列のセグメントが接続され、密な 2 部グラフが生成されます。 マッチングにより多くの強制的な競合が特定され、頂点カバーはすべてのマージを解除するのに十分なセルを選択します。 すべての値が等しい場合でも、完全な崩壊を防ぐためにタグが必要であり、セグメンテーションによって潜在的なすべてのマージ パスが確実にブロックされます。 

チェッカーボードのような交互パターンの場合、行セグメントと列セグメントは交互に配置されますが、一貫した等価チェーンを形成することはないため、2 部グラフにエッジは作成されません。 一致はゼロであり、タグは割り当てられていないため、予想される最適なソリューションと一致します。
