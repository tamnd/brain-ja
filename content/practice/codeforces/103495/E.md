 ## 解決策
 ## 問題の理解

 いくつかの文字列が与えられ、各文字列から独立して一様にランダムに 1 文字を選択します。 選んだキャラクターたちを呼んだら$T_1, T_2, \dots, T_n$、その後、それぞれ$T_i$から引き出されます$S_i$その位置とその結果の文字列に対して等しい確率で$T$長さがある$n$。 

次に、インデックスのすべての順列を考慮します。$1 \dots n$。 固定順列の場合$p$、連結を見てみましょう$$T_{p_1} T_{p_2} \dots T_{p_n}$$そして、この結果の文字列が回文であるかどうかを尋ねます。 特定の結果の「検出力値」$T$は、この方法で使用した場合に回文を生成する単純な順列の数です。 

タスクは、次のランダム性に対するこの検出力の期待値を計算することです。$T$、それをモジュロで出力します$998244353$。 

重要な問題は、ランダム性が順列全体ではなく、各位置内の文字全体であるのに対し、評価する量は順列全体にわたるグローバルな対称制約に依存することです。 

制約は、ある次元では小さく、別の次元では大きくなります。$n \le 30$ただし、各文字列の長さは最大 50,000 です。これは、集約された頻度形式を除いて、文字を明示的に反復すべきではないことを強く示唆しています。 どのような解決策でも、各文字列を文字の頻度に圧縮し、位置ではなくアルファベットを組み合わせて推論する必要があります。 

複数の文字列が同一の文字分布を共有しているが長さが異なる場合、微妙なエッジ ケースが発生します。これは、確率が頻度数だけではなく長さに依存するためです。 もう 1 つの落とし穴は、置換妥当性イベント間の独立性を仮定することですが、これは誤りです。異なる置換は、同じ確率変数に重複する等式制約を課します。$T_i$。 

## アプローチ

 直接的な総当たりアプローチでは、まず、考えられるすべての結果が生成されます。$T$、すでにあります$\prod |S_i|$可能性。 それぞれの結果について、すべてを列挙します。$n!$順列を計算し、結果の連結が回文であるかどうかをテストします。 たとえランダム性の爆発を無視して固定されたものだけに焦点を当てたとしても$T$、すべての順列をチェックすることは階乗であり、これに指数サンプリングを乗算することは完全に不可能です。 

本当の構造的洞察は、視点を逆転させることです。 順列を修正して回文が得られる確率をチェックする代わりに、回文構造を修正し、それと互換性のある順列の数をカウントし、すべての可能な実現を合計します。$T$。 

順列内のペアの位置が同じ文字に対応する場合に限り、順列は回文を生成します。$T$。 順列を端から対称にインデックスをペアリングするものとして解釈すると、有効な各順列は、位置間に完全に一致する構造を誘導し、おそらく中央の固定点を持ちます。$n$奇数です。 これにより、問題は一致するものを数えるという問題に変換されます。$n$各エッジが等価制約を課すラベル付きノード$T_i = T_j$。 

期待は順列にわたって線形になります。すべての順列にわたって合計し、各順列について、その誘導された制約が満たされる確率を計算できます。 それぞれの制約は次のいずれかです$T_i = T_j$、その確率は、次の文字分布の重複にのみ依存します。$S_i$そして$S_j$、または中間の場合は制約なし。 これにより、問題は、ペアごとの等価確率から導出された重みを使用した、インボリューションのような順列に対する重み付きカウントに縮小されます。 

したがって、タスクはインデックスのペアに対する組み合わせ DP になり、各ペアは次の乗算係数に寄与します。$$P(T_i = T_j) = \sum_{c \in \Sigma} \frac{\text{cnt}_i[c]}{|S_i|} \cdot \frac{\text{cnt}_j[c]}{|S_j|}$$これは次のように事前に計算できます。$O(26n^2)$、次に、最大 30 のサイズのサブセットに対して DP を実行します。 

DP 状態は、どのインデックスがすでに使用されているかを表し、遷移ではシングルトン (パリティが許可される場合のみ) を割り当てるか、2 つの未使用のインデックスをペアにします。

 ## アルゴリズムのチュートリアル

 ランダムな選択後に 2 つの位置が文字内で一致するすべてのペアごとの確率を事前計算します。 これにより、文字列のランダム性が 1 つに圧縮されます。$n \times n$マトリックス。 

## アルゴリズムのチュートリアル

 1. 各文字列を変換する$S_i$26 個の小文字にわたる度数テーブルに変換し、その長さを保存します。 これにより、文字列を再度スキャンすることなく確率を計算できるようになります。 
2. ペアごとに$i, j$、次の確率を計算します。$T_i = T_j$文字を合計することによって$c$彼らが選択する独立した確率の積$c$。 これにより、エッジが「一致可能」を表すインデックスに対して完全な重み付けされたグラフが構築されます。 
3. インデックスのサブセットに対する DP を定義します。 させて`dp[mask]`セットを正確にカバーするすべての有効な部分ペアの合計寄与度を表します`mask`ここで、有効性とは、すべてのペアのインデックスが一貫して一致している必要があることを意味します。 
4.初期化`dp[0] = 1`。 空のセットは制約に対応せず、乗法恒等式に寄与します。 
5. 与えられた条件に対して`mask`、最小のインデックスを見つけます`i`入っていない`mask`。 これにより、各状態が正規の順序で構築されることが保証され、同じ一致する構造の並べ替えを過剰にカウントすることが回避されます。 
6. オプション 1: 離れる`i`まだ中間点が必要な場合は、中心要素として使用します (これは、残りのサイズが奇数の場合にのみ寄与します)。 この場合、マークを付けて進みます`i`ペアリングせずに使用した場合、現在の確率が引き継がれます。 
7. オプション 2: ペア`i`他の未使用のインデックスとの併用`j > i`。 現在の DP 値に、事前に計算された確率を乗算します。$T_i = T_j$、に遷移します`mask ∪ {i, j}`。 
8. 答えは次のとおりです。`dp[(1<<n)-1]`各ペアリング構造に対応する順列の数を掛けます。 この要因は、DP 構築順序によって暗黙的に処理されます。 

正確さは、順列をオプションの中心との完全な一致として解釈することに依存しており、各一致はエッジ制約を通じて独立して寄与します。 すべての有効な置換は、正確に 1 つの DP 構築パスに一意に対応し、すべての DP 遷移は、回文形成に必要な等価性制約の強制に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

n = int(input())
cnt = []
length = []

for _ in range(n):
    s = input().strip()
    length.append(len(s))
    freq = [0] * 26
    for ch in s:
        freq[ord(ch) - 97] += 1
    cnt.append(freq)

prob = [[0] * n for _ in range(n)]

for i in range(n):
    inv_li = modinv(length[i])
    pi = [c * inv_li % MOD for c in cnt[i]]
    for j in range(n):
        inv_lj = modinv(length[j])
        pj = [c * inv_lj % MOD for c in cnt[j]]
        s = 0
        for k in range(26):
            s = (s + pi[k] * pj[k]) % MOD
        prob[i][j] = s

size = 1 << n
dp = [0] * size
dp[0] = 1

for mask in range(size):
    if dp[mask] == 0:
        continue

    i = 0
    while i < n and (mask >> i) & 1:
        i += 1
    if i == n:
        continue

    # try leaving i as singleton (center possibility handled implicitly)
    dp[mask | (1 << i)] = (dp[mask | (1 << i)] + dp[mask]) % MOD

    for j in range(i + 1, n):
        if not (mask >> j) & 1:
            dp[mask | (1 << i) | (1 << j)] = (
                dp[mask | (1 << i) | (1 << j)] + dp[mask] * prob[i][j]
            ) % MOD

print(dp[size - 1] % MOD)
```等価確率には文字の分布のみが重要であるため、コードは各入力文字列を 26 次元の周波数ベクトルに圧縮することから始まります。 繰り返しの除算を避けるために、長さのモジュラー逆数が事前に計算されます。 

の`prob[i][j]`行列は、文字列からランダムな文字が選択される確率を格納します。$i$そして$j$等しいです。 これは核となる削減ステップです。すべてのランダム性がペアごとの重みでエンコードされます。 

DP はインデックスのサブセットを反復します。 毎回、最初の未使用のインデックスが選択され、構築の正規の順序が維持されます。 それをシングルトンとして扱うか、その後の未使用のインデックスと組み合わせて、対応する確率を乗算します。 これにより、すべての構造が正確に 1 回カウントされるようになります。 

## 実用的な例

 次の小さなケースを考えてみましょう$n = 3$, ここで、各文字列は非常に短いため、確率は単純です。 

入力：```
S1 = "ab"
S2 = "ac"
S3 = "a"
```確率を計算します。 

| ペア | 等しい確率 |

| マスク | アクション | 貢献 |

同一の文字列を使用した 2 番目の例は、対称性を強調しています。 

もしすべてなら$S_i = "aa"$の場合、すべてのペアの確率は 1 であるため、DP は純粋な一致をカウントします。 結果は、有効な回文順列構造の数と等しくなります。$n$、これは既知のインボリューションカウント動作と一致します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての文字列の長さが 1 である場合です。この状況では、それぞれの$T_i$は決定論的であり、問​​題は、誘導された連結が固定文字上の回文である置換を数えることに帰着します。 DP は等式制約を超えて純粋な組み合わせ論に退化し、確率行列はすべて 1 または 0 になります。 

もう 1 つの特殊なケースは、すべての文字列のアルファベットがバラバラである場合です。 この場合、すべてのペアごとの確率はゼロになります。これは、ペアのない構成のみが寄与することを意味します。これは、次の場合にのみ可能です。$n \le 1$。 DP は、ペアリングの試行に対して正しく折りたたまれて寄与がゼロになり、無効な状態または重みがゼロの状態のみが残ります。 

3 番目のエッジケースは最大です$n=30$、DP がフルに近づく場合$2^n$サイズ。 ここでは、最初の未使用のインデックスを選択する順序が重要です。 これがないと、同じペア構造が異なる順序で複数回カウントされ、結果が不正確に水増しされてしまいます。
