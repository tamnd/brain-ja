 ## 解決策
 ## 問題の理解

 各ノードが数値を保持するツリーが与えられます。 どの開始ノードからでも、サルはノードを再度訪問することなくエッジに沿って歩くことができるため、すべての有効な歩行はツリー内の単純なパスに対応します。 このようなパスに沿って、最終メトリックの走査順序を無視し、代わりにパス上に出現する順序でノード値のシーケンスを調べます。 

開始ノードごとに$i$で始まるすべての可能な単純なパスを考慮します。$i$。 このようなパスごとに、パスに沿った値を取得し、その値シーケンスの最長増加サブシーケンス (LIS) の長さを計算します。 から始まるすべてのパスの中で$i$、可能な最大の LIS 長が必要です。 

したがって、タスクは単一のパスを選択することではなく、パスの選択とその中のサブシーケンスの選択の両方を最適化することです。 各ノードの出力は 1 つの数値、つまり、そのノードから始まるすべての単純なパスの中で取得できる最良の LIS です。 

この制約は、最大で処理する必要があることを意味します。$2 \cdot 10^5$すべてのテスト ケースの合計ノード数。 二次関数または偶数$O(n \log^2 n)$テストケースごとのアプローチは生き残れません。 ツリー構造は、最終的なソリューションでは各エッジが定数または対数回のみ処理されるべきであること、およびノー​​ド全体で計算をグローバルに再利用する必要があることを強く示唆しています。 

重要な点は、LIS がツリー構造自体ではなく、パス シーケンスに沿って計算されることです。 これは、祖先関係ではなく、パスによって引き起こされる順列に対して最適化していることを意味します。 ここでの素朴な混乱は、これを「ルート ツリー DP 上の LIS」として扱うことですが、パスは上下に移動できるため、これは直接的には有効ではありません。 

素朴な考えによる失敗例は、星型の木です。 中心の値が 100 で、葉の値が増加しているとします。 葉から始めて、答えは単なる「より大きな近傍の数」であると考えるかもしれませんが、最適なパスは葉→中心→他の葉となる可能性があり、中心は方向に応じて単調性制約を破り、異なるサブシーケンスはそれを完全にスキップします。 これは、パス構造とサブシーケンスの選択が自明ではない形で相互作用していることを示しています。 

## アプローチ

 ブルート フォース ソリューションでは、各ノードから始まるすべての単純なパスを列挙し、その値シーケンスを生成し、標準の忍耐ソート方法を使用して LIS を計算します。 あるので$O(n)$開始ノードと各ノードには$O(n)$ツリー内の可能なパスが多数あると、最悪の場合、指数関数的な数のパスに急速に縮退します。 単純なパスに限定したとしても、単一のノードが参加できます。$O(n)$実行不可能な道へ導く$O(n^2)$あるいは、評価するシーケンスの数がさらに悪くなります。 各 LIS の計算コスト$O(n \log n)$, 合計は明らかに不可能になります。 

重要な点は、実際にはすべてのパスを明示的に考慮する必要はないということです。 重要なのは、ツリー内の単純なパスは、開始ノードを選択して外側に向かって歩くことによって一意に決定されるということです。 固定されたスタートから、最適なソリューションはすべての分岐点で方向を選択し、パスを形成することに対応します。 このようなパスに沿って、値の増加するサブシーケンスのみに関心があります。これは、サブシーケンスを改善しないノードを自由にスキップできることを意味します。 

これにより、問題は「値の制約によって引き起こされる暗黙的な有向構造内のルートからノードへのウォークに沿って最長の増加シーケンスを見つける」ことに近いものに変換されます。 これに対処する古典的な方法は、値の昇順にノードを処理し、ツリー上の LIS に似た動的プログラミングのアイデアを使用することです。ノードを処理するとき、そのノードで終わる達成可能な最良の LIS を維持し、単調性を尊重しながら隣接関係を通じて改善を伝播します。 

ただし、どのノードからでも開始できるため、すべてのノードを潜在的な開始点として扱う必要があり、通常の LIS DP の方向が逆になります。 正しい再解釈は、各ノードについて、そのノードから始まるツリー内で到達可能な値の最も長く厳密に増加するチェーンが必要であるということです。移動は制限されていませんが、単純なパス上にとどまる必要があります。 これは、ノードを値でソートし、小さい値から大きい値に移行するエッジによって引き起こされる DAG に対して DP を実行することで解決できます。 

ツリー構造により、この有向バージョンではサイクルがないことが保証され、各エッジは一貫した方向に緩和されます。 ノードの最終的な答えは、そのノードから始まる最適なチェーン長です。これは、遷移を逆にするか、DP を昇順に計算し、到達可能な最適な拡張を保存することによって計算できます。

 ## アルゴリズムのチュートリアル

 この問題を、エッジに沿って遷移が許可されるが、より小さい値のノードからより大きい値のノードへのみが許可されるツリー内で、厳密に増加する最長のチェーンを見つけることとして再解釈します。 

1. すべてのノードを値の昇順に並べ替えます。 これにより、ノードを処理するときに、昇順で考えられるすべての先行ノードがすでに考慮されることが保証されます。 この順序付けは、シーケンスを値の前方向にのみ拡張することを強制するため、不可欠です。 
2. DP 配列を維持します。$dp[u]$ノードで終わる増加シーケンスの最大長を表します$u$。 初期状態では、すべてのノードには$dp[u] = 1$、各ノードだけで有効なシーケンスが形成されるためです。 
3. 値の昇順にノードを移動します。 各ノードについて$u$、すべての隣人を考慮します$v$そのような$a[v] > a[u]$。 このようなエッジごとに、次のシーケンスを拡張しようとします。$u$に$v$、更新中$dp[v] = \max(dp[v], dp[u] + 1)$。 値の順序によってパスに沿った厳密な増加が保証されるため、このステップは有効です。 
4. すべてのノードを処理した後、各開始ノードの答えが得られます。$u$単純ではありません$dp[u]$、 なぜなら$dp$ノードで終了するシーケンスについて説明します。 ノードから始まるシーケンスが必要です。 これを変換するには、視点を逆にします。つまり、前方に伝播する代わりに、降順で 2 番目の DP を計算するか、または同様に、逆の値の順序でノードを処理し、より小さい近傍に向かって緩和することによって、各ノードから開始して最適なチェーンを計算します。 
5. 逆の順序でノードごとに$u$、私たちは隣人を見ます$v$と$a[v] < a[u]$、更新します$ans[v] = \max(ans[v], ans[u] + 1)$。 これにより、各ノードがそれを起点として可能な限り最良のチェーンを蓄積することが保証されます。 
6. 最終的な配列$ans$すべてのノードに必要な回答が含まれています。 

中心的な考え方は、ツリー内の増加するパスを小さい値から大きい値への有向エッジとして扱うことができ、値でソートされた DP を 2 回使用してこの DAG 内の最長のパスを計算し、チェーンの両端を処理できるということです。 

### なぜ効果があるのか

 不変条件は、ソートされた順序でノードを処理するときに、チェーンを拡張するたびに、ノードから厳密に大きな値のノードにのみ移動し、誘導されたグラフの非循環性を確保することです。 すべての有効な増加シーケンスは、この DAG 内のパスに対応し、そのようなすべてのパスは、そのエッジが順番に緩和されるときに 1 回だけ考慮されます。 DP は有効な先行ノードから各ノードで達成可能な最大チェーン長を常に記録するため、最適なシーケンスが失われることはなく、無効なシーケンスが導入されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    adj = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)
        adj[v].append(u)
    
    nodes = list(range(n))
    nodes.sort(key=lambda x: a[x])
    
    dp = [1] * n
    
    for u in nodes:
        for v in adj[u]:
            if a[v] > a[u]:
                if dp[v] < dp[u] + 1:
                    dp[v] = dp[u] + 1
    
    ans = [1] * n
    
    for u in reversed(nodes):
        for v in adj[u]:
            if a[v] < a[u]:
                if ans[v] < ans[u] + 1:
                    ans[v] = ans[u] + 1
    
    sys.stdout.write("\n".join(map(str, ans)) + "\n")

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```このソリューションは、テスト ケースごとに隣接リストを構築し、値でソートされた順序でノードを処理します。 最初の DP パスはノードで終わる最適な増加チェーンを計算し、2 番目の逆パスはこれをノードで始まる最適なチェーンに変換します。 隣接性チェックにより、パスに応じて厳密に増加または減少する値のエッジに沿ってのみ移動することが保証されます。 

微妙な点は、並べ替えによってグローバルな順序が強制されるため、単調性に違反するような方法でノードを再検討することは決してないということです。 2 つのパスを使用すると、複雑な LCA または重心分解が必要なくなります。

 ## 特殊なケース

 単一ノードの場合は、遷移が存在しないため自明であり、そのため、答えは 1 でなければなりません。アルゴリズムは dp と ans を 1 に初期化するため、両方のパスで変更されないままになります。 

パスを厳密に増加させると、順伝播が分岐干渉なしにラインに沿ってチェーンの長さを正しく蓄積するかどうかがテストされます。 各ノードには値の順序で有効な前方隣接ノードが 1 つしかないため、DP はチェーンをきれいに構築します。 

厳密に減少するパスは、逆 DP パスをテストします。 値の順序で上向きの伝播を許可するエッジがないため、最初のパスは何も行わず、正確さは有効な開始チェーンをキャプチャする逆パスに完全に依存します。
