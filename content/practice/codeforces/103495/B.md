 ## 解決策
 ## 問題の理解

 重み付けされた無向パスによって接続された部屋のマップが与えられます。 2 人の詐欺師は固定の部屋から開始し、これらの重み付けされた秘密のパスに沿ってのみ移動できます。 時間は連続しており、エッジに沿った移動には秒単位の重みがかかるため、詐欺師は事実上、標準的な最短経路メトリクスに沿って移動します。 

乗組員は最大 8 名です。 各乗組員は予測された出現のリストを持っており、これは特定の時間に特定の部屋にいるということを意味します。 ある時点で詐欺師が乗組員の出現と同じ部屋にいた場合、その乗組員は即座に排除されます。 

詐欺師は、乗組員全員が殺害されるまでの時間を最小限に抑えたいと考えているか、許容範囲 tmax 以内に全員を殺害することを保証するのは不可能であると判断します。 

重要な問題は、キルは静的なノードのセットに到達することではないということです。 これらは、移動時間を 2 つのエージェントのみが存在し、同じグラフ制約を共有しながら、複数のエージェント間でスケジュールされたイベントと移動時間を同期することを目的としています。 

制約はソリューションを強力に形作ります。 グラフには最大 10^4 のノードと 2×10^4 のエッジがあるため、最短パスの計算はソースごとに線形に近い計算になる必要があります。 乗組員の数は少なく、最大でも 8 人であり、これはすぐにビットマスク状態空間であることを示唆しています。 イベントの数は最大 10^5 であるため、イベントごとの高価なシミュレーションは安全ではありません。 

素朴な解釈では、すべての乗組員とのあらゆる会議時間を追跡しながら、詐欺師の動きをシミュレートしようとするかもしれませんが、各詐欺師の選択がグラフのパスやイベントのタイミングで分岐するため、それは爆発的に起こります。 

複数の乗組員が調整された訪問を必要とする場合、より微妙な特殊なケースが発生します。 たとえば、乗組員 A が (部屋 1、時間 5) に現れ、乗組員 B が (部屋 2、時間 6) に現れても、両方に到達するには別の詐欺師か慎重にルートを分割する必要がある場合、単純な貪欲な割り当ては失敗する可能性があります。 別の失敗モードは、詐欺師がイベント時間に正確に到着する必要があることを無視して、乗組員が「到達したら殺される」と仮定することです。 

3 番目の落とし穴は、これを各詐欺師の開始から各イベントまでの独立した単一ソースの最短パスとして扱うことです。 これでは、異なる乗組員に属するイベント間の相互作用や、それらすべてを共有タイムラインでカバーする必要性が無視されます。 

## アプローチ

 強引な視点では、各詐欺師を、道を選択し、次にどのイベントに参加するかを決定できる継続的な旅行者として扱おうとします。 なりすまし者へのイベントの可能な割り当てと、なりすまし者ごとのイベントのそれぞれの順序について、最短パスのタイミング チェックによって実現可能性を計算します。 これは概念的には正しいですが、すぐに組み合わせになります。最大 10^5 のイベントと最大 8 人の乗組員の場合、乗組員ごとにイベントをグループ化しても、外観全体で階乗的な動作が発生し、2 人の詐欺師の間で指数関数的に分裂します。 

重要な観察は、乗組員は少数であるため、個々の出来事について直接推論すべきではないということです。 代わりに、すべての予測を「時刻 t に部屋 x にいた場合、詐欺師が乗組員 p をいつ殺すことができるか」という概念に圧縮します。 各乗組員 p については、特定の時間に詐欺師が必要な部屋にいることができるかどうかだけを考慮します。 これは、最短パスを使用して部屋間の最も早い到着時間を事前に計算する必要があることを示唆しています。 

これで、構造がより明確になります。各詐欺師の開始は、部屋全体にわたる距離関数を定義します。 詐欺師が時間までにイベントルームに到着できれば、殺害は可能です。 待機は許可されているため、不等式 dist(start, x) ≤ t のみが問題になります。 

したがって、詐欺師の開始ごとに、グラフ上の最短パスを計算します。 次に、すべてのイベント (p、x、t) について、どの偽者がそれを満たすことができるかをチェックします。 これにより、各乗組員は、偽者 1 または偽者 2 のいずれかによってすべてカバーされなければならないタイムスタンプ付きの殺害機会のセットに変わります。

ここで、残りの問題は割り当てです。各乗組員は最大で多くのイベントを持ちますが、k ≤ 8 なので、各乗組員をビットマスクに圧縮することができ、そのビットマスクの偽者がそのすべてのイベントの責任を負うことになります。 固定割り当てマスクの場合、実現可能性は、選択した偽者距離に対してすべてのイベントをチェックすることになります。 

最後に、応答時間 T を二分探索します。固定 T の場合、t > T のイベントを無視し、すべてのイベントがカバーされるような偽者への乗組員の割り当てが存在するかどうかを確認します。 k ≤ 8 であるため、すべての 2^k の割り当てをブルート フォースで実行し、事前に計算された距離を使用して O(e) でそれぞれを検証できます。

 ## アルゴリズムのチュートリアル

 まず、ダイクストラのアルゴリズムを使用して、両方の詐欺師の開始部屋からの最短経路距離を計算します。 これにより、すべての部屋 x の dist1[x] と dist2[x] が得られます。 

次に、すべての予測イベントを前処理し、乗組員ごとに論理的にグループ化しますが、実現可能性をテストするときにそれらをグローバルに評価します。 

次に、すべての乗組員を排除できる最小時間 T を二分探索します。 tmax を過ぎると誰かが生き残るとゲームに負けるため、下限は 0、上限は tmax です。 

固定の候補時間 T の場合、時間 T による除去を達成するためには後のイベントは重要ではないため、イベントを t ≤ T のイベントのみにフィルターします。 

ここで、乗組員の詐欺師への 2^k の割り当てをすべて試します。 割り当てでは、各乗組員 p に詐欺師 0 または詐欺師 1 が割り当てられます。 

与えられた割り当てについて、すべてのイベント (p、x、t) をチェックします。 p が偽者 0 に割り当てられている場合は dist1[x] ≤ t が必要で、そうでない場合は dist2[x] ≤ t が必要です。 いずれかのイベントが失敗した場合、割り当ては無効になります。 

少なくとも 1 つの割り当てが有効であれば、時間 T は実現可能です。 

実現可能な最小の T を出力するか、T ≤ tmax が機能しない場合は −1 を出力します。 

これが機能する理由は、グラフの距離によって作成される独立性に関係しています。 距離が固定されると、各イベントは、単一の詐欺師の到達可能性をタイムスタンプと比較するローカル制約になります。 唯一のグローバル結合は、どの詐欺師がどの乗組員を処理するかということであり、その結合は k ≤ 8 のビットマスクによって完全にキャプチャされます。待機すると順序付けの制約がなくなるため、イベントの順序付けは必要ありません。割り当てが固定されると各イベントは独立します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

INF = 10**30

def dijkstra(n, adj, src):
    dist = [INF] * (n + 1)
    dist[src] = 0
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in adj[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

def solve():
    T = int(input())
    for _ in range(T):
        n, m, k = map(int, input().split())
        adj = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v, w = map(int, input().split())
            adj[u].append((v, w))
            adj[v].append((u, w))

        e, tmax = map(int, input().split())
        events = []
        for _ in range(e):
            p, x, t = map(int, input().split())
            events.append((p - 1, x, t))

        s1, s2 = map(int, input().split())

        dist1 = dijkstra(n, adj, s1)
        dist2 = dijkstra(n, adj, s2)

        lo, hi = 0, tmax
        ans = -1

        def feasible(Tlim):
            # try all assignments of k crewmates
            for mask in range(1 << k):
                ok = True
                for p, x, t in events:
                    if t > Tlim:
                        continue
                    if (mask >> p) & 1:
                        if dist2[x] > t:
                            ok = False
                            break
                    else:
                        if dist1[x] > t:
                            ok = False
                            break
                if ok:
                    return True
            return False

        if feasible(tmax):
            lo, hi = 0, tmax
            while lo < hi:
                mid = (lo + hi) // 2
                if feasible(mid):
                    hi = mid
                else:
                    lo = mid + 1
            ans = lo

        print(ans)

if __name__ == "__main__":
    solve()
```ダイクストラは、インポスターの開始ごとに 1 回実行され、すべての移動制約がキャプチャされます。 実現可能性関数は中核的な削減です。動きをシミュレートする代わりに、問題を、各イベントがその時点で選択された詐欺師の手の届く範囲内にあるかどうかを確認することに削減します。 

ビットマスク ループは、乗組員の偽者へのすべての割り当てを列挙します。 これは、k ≤ 8 であるため有効であり、最大 10^5 のイベントを掛けても 256 個の構成は十分に小さいです。 

二分探索が使用されるのは、実現可能性が時間的に単調であるためです。時間 T までにすべてのキルを完了できる場合は、イベントが満たされやすくなるだけなので、それより大きな時間 T' も機能します。 

## 実用的な例

 2 つの部屋が直接接続され、1 人の乗組員が 2 つの外観を持つ最小限のシナリオを考えてみましょう。 各部屋で 1 人の詐欺師が開始します。 最初の出現は部屋 A の早い段階で、2 番目の出現は部屋 B の後半です。アルゴリズムは両方の距離を計算し、割り当てをテストします。 1 つの割り当てでは乗組員を詐欺師 1 に割り当てますが、2 番目のイベントでは距離が原因で失敗します。 もう一方の割り当ては、両方のイベントが詐欺師 2 から時間内に到達できる場合に成功します。これは、割り当ての柔軟性が重要である理由を示しています。 

ここで、乗組員がタイムスタンプより前に両方の詐欺師から遠すぎる部屋に現れた場合を考えてみましょう。 そのイベントでは、dist1[x] と dist2[x] の両方が t を超えているため、すべての割り当ては即座に失敗します。 実現可能性チェックはすべての T に対して false を返し、最終的な答えは -1 になります。 

これら 2 つのトレースは、正しさが完全に最短パスの到達可能性とイベントの期限との比較に依存する一方で、割り当てが唯一の組み合わせの自由を処理することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n + 2^k · e · log tmax) | ダイクストラを 2 回実行し、実行可能性チェックで二分探索を行い、各回ですべてのマスクのすべてのイベントをチェックします。 
| スペース | O(n + e) | グラフストレージ、距離配列、イベントリスト |

 制約は、k が小さいままで指数関数が無害になるように設計されていますが、グラフ サイズには効率的な最短経路の計算が必要です。 2^8 はわずか 256 であり、テスト ケースごとにダイクストラが優勢であるため、この解は制限内に問題なく収まります。

 ## 特殊なケース

 主なエッジケースは、複数のイベントが同じ部屋で異なる時間に発生する場合です。 各イベントは同じ距離制約に対して個別にチェックされるため、アルゴリズムはこれを自然に処理します。そのため、前のイベントが後のイベントを誤ってブロックすることはありません。 

もう 1 つのケースは、1 人の詐欺師が厳密に支配されている場合です。これは、その距離配列がすべての部屋に対して悪くなるということを意味します。 ビットマスク列挙は、特別なケースを使用せずに、すべての乗組員をより優れた偽者に割り当てるだけなので、引き続き機能します。 

最後のエッジケースは、すべてのイベントが tmax の後に発生する場合です。 この場合、失敗期限の前にアクティブな制約が存在せず、T = 0 で二分探索が即座に実行不可能になるため、最適解は自明のことながら 0 になります。
