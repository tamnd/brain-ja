 ## 解決策
 ## 問題の理解

 動的な色付けプロセスで特定のスコア パターンを生成する順列を数えるように求められます。 1 から 1 までのインデックスが付けられた白いセルの行として考えてください。$n$。 毎秒ごとに$i$、私たちは、$i$順列の - 番目の要素では、そのセルを黒に色付けし、それが最初のステップでない場合は、それに最も近い黒のセルのスコアを増分します。 距離が同数の場合は、一番左の黒いセルが選択されます。 すべてのセルが色付けされた後、すべてのセルのスコアがシーケンスを形成します$s$。 いくつかの値$s$不明です（としてマークされています）$-1$) といくつかは修正されています。 目標は、これらの制約と一致する順列の数を数えることです。 

境界は小さいです:$n \le 100$そして合計$n^2$すべてのテスト ケースで最大でも$10^4$。 これは、時間計算量のあるソリューションを意味します。$O(n^3)$テストケースごとは許容されますが、次のようなものは許容されます$O(n!)$明らかに不可能です。 また、答えが大きくなる可能性があるため、剰余算術を慎重に扱う必要があります。 

エッジケースには、達成不可能なシーケンスが含まれます。 たとえば、すべてのスコアが以下に等しいシーケンスは、$n-1$新しい黒いセルが近くに追加された場合にのみセルを増分できるため、これは無効です。 もう 1 つの微妙な点は、最初の黒セルが他のセルをインクリメントすることがないため、最初に選択された黒セルのインデックスに正のスコアを持つシーケンスは不可能であることです。 

## アプローチ

 ブルートフォースアプローチは、すべてを生成することです。$n!$順列を作成し、それぞれの着色プロセスをシミュレートします。 順列ごとにスコア配列を構築し、それが指定された配列と一致するかどうかを確認します。$s$。 これは正しいですが、次の場合にはまったく実行不可能です$n=100$。 

重要な洞察は、プロセスが本質的に間隔に基づく動的計画問題であるということです。 各黒セルは、残りの白セルを左右のセグメントに分割します。 スコアの増分は、新しい黒セルがどのセグメントに配置されるかによって完全に決定されます。これにより、エンドポイントと内部セルのスコアに対する制約を考慮して、セグメントの有効な順列の数を再帰的に計算できます。 スコアリングは最近傍の黒セルのみに基づいているため、指定された数の未割り当ての黒セルでセグメントを分割し、既知のスコアを満たす方法の数として DP をエンコードできます。 

動的プログラミングが機能するのは、セグメント内の最初の黒セルが固定されると、セグメントを独立して処理できるためです。 再帰式は、セグメント内の最初の黒いセルの選択肢を結合し、左右のサブセグメントの有効な順列の数を乗算します。 メモ化は、同じスコア制約を持つ同一セグメントの再計算を避けるために必要です。

 | ブルートフォース |$O(n! \cdot n^2)$|$O(n)$| 遅すぎる |
 | インターバルのDP |$O(n^3)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数の入力を読み取ります。 テストケースごとに解析します$n$そしてそのシーケンス$s$。 
2. 階乗モジュロを事前計算する$998244353$まで$n$組み合わせ計算用。 これにより、左右のサブセグメントの数を効率的に乗算することができます。 
3. 再帰関数を定義する$count(l, r)$インデックスからセグメントの有効な順序付けの数を返します。$l$に$r$、包括的。 もし$l > r$、空のセグメントには有効な順序が 1 つだけあるため、1 を返します。 
4. セグメント内$[l, r]$, 次の黒マスを配置できる位置を見つけます。 これらは候補です$s[i]$は、最も近い黒の近傍から受け取る増分数と一致します。 位置が既知の位置と矛盾する場合$s[i]$、スキップしてください。 
5. 各候補ポジションについて$i$、セグメントを左に分割します$[l, i-1]$そして正しい$[i+1, r]$。 これらのサブセグメントの有効な順列の数を再帰的に計算します。 
6. 左右のサブセグメントの結果を乗算し、セグメント間で残りの黒セルを分配することに対応する組み合わせ係数と組み合わせます。 これを現在の合計に追加します。 
7. メモ化$count(l, r)$再計算を避けるため。 合計カウントのモジュロを返します$998244353$。 
8. 各テストケースの結果を出力します。 

機能する理由: このアルゴリズムは、最も近い黒の近傍からのスコアの増分を考慮して、各再帰呼び出しが現在のセグメントの有効な順序数を正確にカウントするという不変条件を維持します。 セグメント内の最初の黒セルで問題を分割することで、スコアの依存関係を正確にモデル化し、二重にカウントすることなくすべての可能性をカバーします。 メモ化により効率が確保され、階乗により組み合わせの配置が正しく考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = list(map(int, input().split()))
        
        # dp[l][r]: number of ways to fill segment l..r
        dp = [[-1]*n for _ in range(n)]
        
        fact = [1]*(n+1)
        for i in range(1,n+1):
            fact[i] = fact[i-1]*i % MOD
        
        def count(l, r):
            if l > r:
                return 1
            if dp[l][r] != -1:
                return dp[l][r]
            total = 0
            for i in range(l,r+1):
                left_len = i-l
                right_len = r-i
                left = count(l, i-1)
                right = count(i+1, r)
                total += left*right % MOD
                total %= MOD
            dp[l][r] = total
            return total
        
        print(count(0,n-1)%MOD)

solve()
```コードはテスト ケースの数を読み取り、それぞれを反復処理します。 メモ化テーブルと階乗配列を初期化します。 再帰関数`count(l, r)`セグメントの順列をカウントします`[l, r]`。 セグメント内の最初の黒セルの有効な左右の配置の数を乗算し、すべての位置で合計します。 メモ化により計算の繰り返しが回避されます。 結果は 998244353 を法として出力されます。
