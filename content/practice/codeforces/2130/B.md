 ## 解決策
 ## 問題の理解

 各要素が 0、1、または 2 の整数の配列と目標合計が与えられます。`s`。 アリスは、最初の要素から開始して、最後の要素に到達するまで左または右に段階的に移動したいと考えています。 移動中に、訪問した値を合計し、この合計が等しくなるようにします。`s`。 ボブは配列を再配置できます。タスクは、アリスが正確な合計を与えるパスを見つけられないような方法でそれができるかどうかを判断することです。`s`。 彼ができるなら、私たちはそのような再配置を一つ起こさなければなりません。 それ以外の場合は印刷します`-1`。 

制約は小さいです。`n`最大50まで上げることができます、`s`最大 1000 個、テスト ケースも最大 1000 個まで可能です。 配列の長さが非常に短いため、指数関数的に複雑なアルゴリズムを使用する余裕はありません。`n`ただし、単純な線形スキャンと再配置は許容されます。 各配列には、各値 0、1、2 が少なくとも 1 つ含まれることが保証されているため、数値が欠落するというエッジ ケースはありませんが、合計は`s`配列に対して小さすぎるか大きすぎる場合は、依然として到達できない可能性があります。 

素朴なアプローチでは、アリスがたどる可能性のあるすべての経路をシミュレートしようとするかもしれませんが、アリスは任意に前後に移動できるため、すぐに複雑さが爆発します。 不用意に実装すると、アリスがいつ達成できるかを誤って判断する可能性があります。`s`繰り返しの訪問を小さな値に組み合わせることで、 たとえば、次の場合`a = [0,1,2]`そして`s = 3`, アリスはインデックス 1 から 3 に直接移動することも、ジグザグに移動して複数の方法で合計を蓄積することもできます。 単一のパスで十分であると想定するソリューションは失敗します。 

## アプローチ

 ブルート フォース アプローチでは、配列のすべての順列を列挙し、順列ごとに最初のインデックスから最後のインデックスまでの可能なすべてのパスを列挙し、パスの合計が以下になるかどうかを確認します。`s`。 パスの数は指数関数的です`n`なぜなら、アリスは要素を何度も再訪できるからです。 たとえ`n=50`、これは不可能です。 

重要な観察は、0、1、2 の正確な位置は、アリスが達成できる最小値と最大値を制御する場合にのみ重要であるということです。 可能な最小の合計は、最初から最後までまっすぐに移動し、各要素を 1 回訪問する場合です。これは次のようになります。`sum(a)`。 以来`n`が小さく、値が小さい場合、合計は`sum(a)`せいぜい`100`もし`n=50`すべての要素は 2 です。アリスは常に以下の合計を達成できます。`sum(a)`彼女が複数の前後の動きを使用できる場合。 

各ステップは隣接するインデックスに移動するため、配列で達成できる合計にギャップが存在することはできません。 賢明な洞察は、アリスが次の金額に達するのをボブが阻止できないということです。`min(a)`そして`max(a)`合計の場合`s`実現可能です。 したがって、ボブは次の場合にのみ成功できます。`s`が直接パス内の配列の合計に等しくない場合、または合計が十分に小さい場合は、次のような要素を再配置できます。`0,2,1`彼女が到達するのを妨げることができる`s`。 

具体的には、この問題に対する既知の解決策は次のとおりです。`s`が非降順でソートした場合の配列の合計に等しいため、ボブはアリスを阻止できません。 それ以外の場合はすべて、配列を特定の順序で並べ替えるだけ (最大の要素を先頭に配置するなど) だけで、アリスが直線パスで合計に到達するのを防ぐことができます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして`s`、配列を読み取ります`a`。 
3. 配列の合計を計算します。`sum_a`。 
4. もし`sum_a == s`、出力`-1`アリスは達成できるから`s`最初から最後まで順番に移動します。 これを防ぐ再配置はありません。 
5. それ以外の場合は、配列を非降順で並べ替えます。 
6. ソート後の最初の要素が残りの合計からマイナスされた値に等しい場合`s`、最後の 2 つの要素を交換して、達成するパスを中断します。`s`。 
7. 結果の配列を出力します。 

これが機能する理由: 不変条件は、ソートされた配列が生成する合計が より大きいことです。`s`開始または終了で、連続したパスを一致させることが不可能になります`s`その通り。 配列の合計が等しい場合のみ`s`アリスが通ることのできる、妨げられない直接の道はあるのでしょうか。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, s = map(int, input().split())
    a = list(map(int, input().split()))
    total = sum(a)
    if total == s:
        print(-1)
        continue
    a.sort()
    # Ensure that the prefix sum never equals s
    prefix = 0
    for i in range(n):
        prefix += a[i]
        if prefix == s:
            # Swap current with last
            a[i], a[-1] = a[-1], a[i]
            break
    print(*a)
```このソリューションは入力を効率的に読み取り、合計をチェックします。`s`すぐに対処するために`-1`場合に応じて配列をソートします。 以下に等しいプレフィックスをスキャンしているとき`s`、パスを壊すために交換します。 並べ替えにより合計が最初から最後まで確実に制御され、交換により完全一致が回避されます。 の`print(*a)`再配置された配列を必要な形式で出力します。

 ## 特殊なケース

 もし`s`がゼロで、配列に 0 が含まれている場合、アリスは 0 上でのみ移動しようとしますが、アルゴリズムはソートされた配列を出力します。`[0,...]`との即時の一致を防ぎます。`s`プレフィックス合計を通じて。 いつ`s`合計に等しい、`-1`ブランチは再配置を防止し、保証されたパスの場合を正しく処理します。 複数の 0 または 2 を含む小さな配列はソートとスワップによって処理され、アリスが正確に蓄積できないことが保証されます。`s`道沿いにあります。
