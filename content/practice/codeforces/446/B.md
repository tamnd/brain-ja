 ## 解決策
 ## 問題の理解

 私たちは、`n × m`整数の行列。 私たちは正確に実行しなければなりません`k`操作。 

操作では、行全体または列全体のいずれかを選択します。 その行または列の現在の合計が答えに追加され、その中のすべての要素が減算されます。`p`。 

同じ行または列を複数回選択することができます。 選択するたびにすべてのセルが減少するため、再度選択することで得られる値は小さくなります。 

課題は、正確に蓄積された合計の喜びを最大化することです`k`操作。 

マトリックスの次元は最大でも`1000`、中程度です。 本当の課題は、`k`と同じ大きさにすることができます`10^6`。 操作のたびに行と列を明示的に更新するシミュレーションは不可能です。 たとえ`O(k·n)`または`O(k·m)`最悪の場合、アルゴリズムが遅すぎる可能性があります。 

答えは非常に大きくなる可能性があります。 行の合計はおよそである可能性があります`10^6`まで行います。`10^6`演算のため、64 ビット整数が必要です。 

微妙な部分は、行操作と列操作が相互作用することです。 行を選択するとすべての列の合計が変更され、列を選択するとすべての行の合計が変更されます。 現在最大の行または列を常に取得する貪欲な戦略は、将来の選択に影響を与えるため失敗する可能性があります。 

考慮する：```
2 2 2 100
1000 1
1 1
```最初の操作は明らかに最初の行です。 その後、その行のすべての要素が減少します。`100`これにより、両方の列の合計が変更されます。 世界最大の選択肢を再計算し続ける戦略では、簡単な最適構造は明らかになりません。 

もう 1 つの簡単な間違いは、行操作の最適なシーケンスと列操作の最適なシーケンスを個別に計算し、それらを単純に加算することです。 

例：```
1 1 2 1
10
```1 行 1 列を取ると、単純合計は次のようになります。```
10 + 10 = 20
```これは不可能です。 行を取得した後、単一セルは次のようになります。`9`, したがって、列は次の結果のみを生成します。`9`。 

正しい答えは次のとおりです。```
19
```行と列の間の相互作用は明示的に考慮する必要があります。 

## アプローチ

 ブルートフォースの見方は簡単です。 すべてのステップで、現在のすべての行の合計と列の合計を計算し、最適な操作を選択し、行列を更新して続行します。 これはプロセスに正確に従っているため、これは正しいです。 

問題はスケールです。 マトリックスには以下が含まれます`10^6`セルと私たちは最大まで実行することができます`10^6`操作。 すべてのステップの後で合計を再計算するには、何兆もの演算が必要になります。 

重要な点は、行が非常に単純な方法で行と相互作用するということです。 

現在行に合計があるとします。`S`。 選択すると利益が得られます`S`、その後、そのすべての`m`細胞が減少します`p`。 その行の合計は次のようになります。```
S - m·p
```行操作のみを考慮する場合、この行合計には他に何も影響しません。 

つまり、行選択から得られる一連の利益は列から完全に独立しています。 行が選択されるたびに、その将来の価値は正確に減少します。`m·p`。 

同じ考え方が列にも当てはまります。 列を選択すると、その将来の価値は正確に減少します`n·p`。 

これにより、問題は 2 つの独立した優先キュー プロセスに変換されます。 

させて：`row[i]`= 正確に得られる最大利益`i`行の操作。`col[i]`= 正確に得られる最大利益`i`列の操作。 

最大ヒープを使用して両方の配列を貪欲に計算できます。 

行の場合:

 - 最初にすべての行の合計を最大ヒープに挿入します。 
- 現在の行合計の最大値を繰り返し抽出します。`x`。 
- 追加`x`累積利益に。 
- 再挿入`x - m·p`。 

後`k`反復により、任意の数の行操作から得られる最大の利益がわかります。 

列も同様に計算されます。 

さて、正確に実行するとします`i`行操作と`k-i`列の操作。 

相互作用を無視すると、利益は次のようになります。```
row[i] + col[k-i]
```ただし、すべての行操作では、その行のすべてのセルが減少します。`p`。 すべての列演算により、その列内のすべてのセルが減ります。`p`。 

選択された行演算と選択された列演算の交差点にあるセルは 2 回カウントされます。 

私たちが演奏したら`i`行操作と`k-i`列操作には次のものがあります。```
i · (k-i)
```行と列のペア。 

各ペアは 1 つの交差セルを次のように減らします。`p`、そしてこの損失は喜びの計算にカウントされます。 マトリックス全体での超過合計は次のとおりです。```
i · (k-i) · p
```したがって、真の値は次のようになります。```
row[i] + col[k-i] - i·(k-i)·p
```全部試してみます`i`から`0`に`k`そして最大値を取る。

 ## アルゴリズムのチュートリアル

 1. 行列を読み取り、すべての行の合計とすべての列の合計を計算します。 
2. すべての行の合計を含む最大ヒープを構築します。 
3. しましょう`row_profit[0] = 0`。 
4. 繰り返します`k`回:

 1. 最大の行合計を抽出する`x`。 
2.追加`x`現在の合計に。 
3. 累計を`row_profit`。 
4. 再挿入します`x - m·p`。 

これにより、行操作を可能な限り実行した後に得られる最大の利益が貪欲に生成されます。 
5. すべての列の合計を含む別の最大ヒープを構築します。 
6. しましょう`col_profit[0] = 0`。 
7. 繰り返します`k`回:

 1. 最大の列合計を抽出する`x`。 
2.追加`x`現在の合計に。 
3. 累計を`col_profit`。 
4. 再挿入します`x - n·p`。 
8. あらゆる人にとって`i`から`0`に`k`:

 1. 正確に仮定する`i`行の操作。 
2. 次に、`k-i`列の操作。 
3. コンピューティング```
row_profit[i]
+ col_profit[k-i]
- i·(k-i)·p
```4. 回答を更新します。 
9. 見つかった最大値を出力します。 

### なぜ効果があるのか

 すべての行は将来の行操作に関して独立して動作するため、行のヒープ プロセスは最適です。 行を選択すると、その行の将来価値が一定量だけ変更されます。`m·p`。 この状況は、コレクションから最大の要素を繰り返し取得し、定数を減算した後に再挿入することとまったく同じです。 貪欲な選択は常に最適です。 

同じ議論が列にも適用されます。 

一度`row_profit[i]`そして`col_profit[j]`既知の、あらゆる解決策`i`行操作と`j`列操作は、独立した利益に加えて交互作用項に寄与します。 すべての行と列のペアで、正確に 1 回の余分な減算が発生します。`p`彼らの交差点で。 がある`i·j`このようなペアなので、修正は正確に`i·j·p`。 したがって、あらゆる実現可能な戦略は、`i+j=k`価値がある```
row_profit[i] + col_profit[j] - i·j·p.
```可能なすべての分割の最大値を取ると、最適な答えが得られます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, k, p = map(int, input().split())

    row_sums = [0] * n
    col_sums = [0] * m

    for i in range(n):
        row = list(map(int, input().split()))
        row_sums[i] = sum(row)
        for j, x in enumerate(row):
            col_sums[j] += x

    row_heap = [-x for x in row_sums]
    heapq.heapify(row_heap)

    row_profit = [0] * (k + 1)
    cur = 0

    for i in range(1, k + 1):
        x = -heapq.heappop(row_heap)
        cur += x
        row_profit[i] = cur
        heapq.heappush(row_heap, -(x - m * p))

    col_heap = [-x for x in col_sums]
    heapq.heapify(col_heap)

    col_profit = [0] * (k + 1)
    cur = 0

    for i in range(1, k + 1):
        x = -heapq.heappop(col_heap)
        cur += x
        col_profit[i] = cur
        heapq.heappush(col_heap, -(x - n * p))

    ans = -10**30

    for i in range(k + 1):
        value = (
            row_profit[i]
            + col_profit[k - i]
            - i * (k - i) * p
        )
        ans = max(ans, value)

    print(ans)

solve()
```最初の部分では、行列の 1 回のスキャンで行の合計と列の合計を計算します。 

2 つのヒープ ループはほぼ同一です。 各ループは、そのタイプの操作を可能な限り実行した後に、最高の累積利益を生成します。 最大ヒープは、Python の最小ヒープを使用して、否定された値を格納することによって実装されます。 

再挿入手順は非常に重要です。 現在の合計を含む行を選択した後`x`、そのすべての`m`エントリが減少します`p`、したがって、その将来の行の合計は次のようになります`x - m·p`。 列の使用`x - n·p`。 

最後のループでは、考えられるすべての分割を試みます。`k`操作。 以来`row_profit[i]`はすでに正確に最適な合計を表しています`i`行操作と`col_profit[k-i]`は残りの列演算からの最適な合計を表します。交互作用補正のみを適用する必要があります。 

Python の整数は任意の精度であるため、オーバーフローのリスクはありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
import heapq

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, m, k, p = map(int, input().split())

    row_sums = [0] * n
    col_sums = [0] * m

    for i in range(n):
        row = list(map(int, input().split()))
        row_sums[i] = sum(row)
        for j, x in enumerate(row):
            col_sums[j] += x

    row_heap = [-x for x in row_sums]
    heapq.heapify(row_heap)

    rp = [0] * (k + 1)
    cur = 0
    for i in range(1, k + 1):
        x = -heapq.heappop(row_heap)
        cur += x
        rp[i] = cur
        heapq.heappush(row_heap, -(x - m * p))

    col_heap = [-x for x in col_sums]
    heapq.heapify(col_heap)

    cp = [0] * (k + 1)
    cur = 0
    for i in range(1, k + 1):
        x = -heapq.heappop(col_heap)
        cur += x
        cp[i] = cur
        heapq.heappush(col_heap, -(x - n * p))

    ans = max(
        rp[i] + cp[k - i] - i * (k - i) * p
        for i in range(k + 1)
    )

    return str(ans)

### 行と列の混合操作

 入力:```
1 1 2 1
10
```単純な計算では、次のものが追加される可能性があります。```
10 + 10 = 20
```1 つの行操作と 1 つの列操作の場合。 

アルゴリズムは次のように適用されます。```
10 + 10 - 1·1·1 = 19
```これはまさに共有セルの原因となります。 

### 大量の操作

 入力:```

```取得可能な行合計のシーケンスは次のとおりです。```

```最終的にはマイナスの利益が現れます。 残りの選択肢がすべて負の場合でも、ヒープは常に利用可能な最良の値を選択するため、アルゴリズムは引き続き機能します。 まさにそれ以来`k`操作が必要な場合、否定的な選択を避けることはできません。 

プレフィックス配列はこの状況を自然に処理し、最終的な最大化は正しいままになります。
