 ## 解決策
 ## 問題の理解

 最大の配列が与えられます$10^5$整数。 任意の連続したサブ配列を選択でき、そのサブ配列内の最大 1 つの要素を変更して、必要な整数に置き換えることができます。 目標は、最大 1 回の変更を行った後に厳密に増加できるサブ配列の長さを最大化することです。 

重要な点は、変更が完全に制限されていないことです。 元の値に制約されず、大小を問わず任意の整数を選択できます。 最大 1 回の変更で部分配列を厳密に増加するシーケンスに変換できるかどうかだけを考慮します。 

制約$n \le 10^5$二次アルゴリズムを即座に除外します。 すべてのサブ配列を検査するソリューションでは、約$5 \times 10^9$限界をはるかに超えた最悪の場合の操作。 線形または線形に近い解決策を目指す必要があります。 

いくつかの特殊なケースは見落とされがちです。 

考慮する：```
3
1 2 3
```答えは 3 です。1 つの要素を変更することは許可されていますが、その変更を使用する必要はありません。 変更が 1 つだけ必要であると想定したソリューションは失敗します。 

考慮する：```
3
5 5 5
```答えは 1 です。隣接する 2 つの要素は厳密な増加に違反します。 1 回の変更で修復できる位置は 1 つだけなので、長さが 2 以上のサブ配列は厳密に増加することはできません。 不注意な解決策は、すべての違反が独立して修正できると想定し、誤って 2 を返す可能性があります。 

次のことを考慮してください。```
5
1 2 10 3 4
```答えは 4 です。10 を 2 ～ 3 の間の任意の値に変更すると、長さ 5 の厳密に増加するセグメントが得られます。置換値が隣接する要素間に適合する必要があるという事実が重要です。 単に違反を数えるだけでは十分ではありません。 

考慮する：```
5
1 2 3 4 5
```答えは 5 です。よくある間違いは、シーケンスが途切れている場所だけを見てしまうことです。 ブレークがまったくない場合、配列全体はすでに有効です。 

## アプローチ

 最も直接的なアイデアは、すべてのサブ配列を調べることです。 各部分配列について、最大 1 つの要素を変更するだけで要素が厳密に増加するかどうかを確認できます。 

この総当り的なアプローチは、すべての回答候補を明示的にテストするため、正しいです。 残念ながら、あります$O(n^2)$サブアレイ。 たとえ各サブ配列を一定時間でチェックしたとしても、それはすでに大きすぎて、$n = 10^5$。 現実的な実装はさらに時間がかかります。 

より高速な解決策を得るには、実行を厳密に増加させる構造を検討する必要があります。 

すべての位置について、そこで終了する厳密に増加する最長のセグメントの長さと、そこから始まる厳密に増加する最長のセグメントの長さがわかっているとします。 

させて：

-`L[i]`= で終わる厳密に増加する接尾辞の長さ`i`-`R[i]`= から始まる厳密に増加するプレフィックスの長さ`i`これらの配列は線形時間で計算できます。 

それらを入手したら、より焦点を絞った質問をすることができます。`i`変更する要素は、厳密に増加するセグメントがその位置をどれだけ長く通過できるか?

 可能性は 2 つあります。 

まず、1 つのエンドポイントを変更して、増加するセグメントを拡張します。 たとえば、セグメントが次で終わる場合、`i - 1`長さがある`L[i - 1]`、変化する`a[i]`適切に、1 要素分拡張することができます。 右側についても同様に、`R[i + 1]`。 

次に、左側の増加するセグメントを右側の別の増加するセグメントに接続します。 これは、間に厳密に整数が存在する場合にのみ可能です。`a[i-1]`そして`a[i+1]`。 

値は整数であるため、そのような値は次の場合に正確に存在します。$$a[i+1] - a[i-1] > 1$$この状態が続く場合は交換可能です`a[i]`適切な整数を使用して、2 つの実行を 1 つのより大きな厳密に増加するセグメントにマージします。 

問題全体は、線形時間内のすべての位置についてこれらの可能性を評価することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取ります。 
2. もし`n = 1`、すぐに 1 を返します。 
3. アレイの構築`L`。`L[i]`位置で終了する厳密に増加する最も長い連続セグメントの長さを格納します`i`。 

もし`a[i] > a[i-1]`、セグメントを拡張すると、次のようになります。`L[i] = L[i-1] + 1`。 

さもないと：`L[i] = 1`。 
4. アレイの構築`R`。`R[i]`位置から始まる厳密に増加する最長の連続セグメントの長さを格納します`i`。 

もし`a[i] < a[i+1]`、 それから：`R[i] = R[i+1] + 1`。 

さもないと：`R[i] = 1`。 
5. 既存の最大の増加セグメントで答えを初期化します。 

これは単純に、`max(L)`。 
6. ポジションごとに`i`、変更を検討してください`a[i]`。 

もし`i > 0`、左側のランを 1 つの要素だけ拡張できます。`answer = max(answer, L[i-1] + 1)`。 
7. もし`i + 1 < n`、右側の run を 1 つの要素だけ拡張できます。`answer = max(answer, R[i+1] + 1)`。 
8. もし`0 < i < n-1`、左右のランをマージできるかどうかを確認します。 

もし：`a[i+1] - a[i-1] > 1`その場合、それらの間には何らかの整数が厳密に存在します。 

交換させていただく場合がございます`a[i]`このような値を使用して次を取得します。`L[i-1] + R[i+1] + 1`結合した長さとして。 
9. 答えは最大でも`n`。 
10. 答えを出力します。 

### なぜ効果があるのか`L[i]`そして`R[i]`配列内のすべての最大増加ランをキャプチャします。 最適なソリューションは、実行の終点または 2 つの実行間の位置を変更します。 

エンドポイントを変更する場合、考えられる最良の結果は、片側を 1 つの要素だけ拡張することです。これは、`L[i-1] + 1`そして`R[i+1] + 1`トランジション。 

内部位置を変更する場合、より長いセグメントを取得する唯一の方法は、増加するランの終了点を接続することです。`i-1`から始まるランが増加します`i+1`。 このような接続は、有効な置換値を隣接する値の間に厳密に配置できる場合にのみ実現可能です。 条件`a[i+1] - a[i-1] > 1`必要かつ十分です。 

考えられる最適な変更はすべてこれらのケースのいずれかに該当するため、アルゴリズムによって検査された最大値が正確に答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        print(1)
        return

    L = [1] * n
    for i in range(1, n):
        if a[i] > a[i - 1]:
            L[i] = L[i - 1] + 1

    R = [1] * n
    for i in range(n - 2, -1, -1):
        if a[i] < a[i + 1]:
            R[i] = R[i + 1] + 1

    ans = max(L)

    for i in range(n):
        if i > 0:
            ans = max(ans, L[i - 1] + 1)

        if i + 1 < n:
            ans = max(ans, R[i + 1] + 1)

        if 0 < i < n - 1 and a[i + 1] - a[i - 1] > 1:
            ans = max(ans, L[i - 1] + R[i + 1] + 1)

    print(min(ans, n))

if __name__ == "__main__":
    solve()
```最初のパスでは、各位置で終わる増加するセグメントを計算します。 2 番目のパスでは、各位置から開始して増加するセグメントを計算します。 これらは一緒に、配列内のすべての局所的な増加構造を要約します。 

メインループは、考えられるすべての変更位置を評価します。 実行を 1 つの要素だけ拡張することは、現在の値を非常に大きな値または非常に小さな値に変更することに相当します。 2 つの実行をマージするには、有効な整数が隣接する値の間に収まるかどうかを確認する必要があります。 

決勝戦`min(ans, n)`ほとんどの場合、技術的には不要ですが、遷移が発生した場合には結果を配列境界内に安全に保持します。`n + 1`。 

境界処理は、実装の中で最もデリケートな部分です。 配列の端にある位置は、一方の側が存在しないため、2 つの実行をマージできません。 条件`i > 0`、`i + 1 < n`、 そして`0 < i < n - 1`範囲外からのアクセスを防ぎます。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        return "1"

    L = [1] * n
    for i in range(1, n):
        if a[i] > a[i - 1]:
            L[i] = L[i - 1] + 1

    R = [1] * n
    for i in range(n - 2, -1, -1):
        if a[i] < a[i + 1]:
            R[i] = R[i + 1] + 1

    ans = max(L)

    for i in range(n):
        if i > 0:
            ans = max(ans, L[i - 1] + 1)

        if i + 1 < n:
            ans = max(ans, R[i + 1] + 1)

        if 0 < i < n - 1 and a[i + 1] - a[i - 1] > 1:
            ans = max(ans, L[i - 1] + R[i + 1] + 1)

    return str(min(ans, n))

# provided sample
assert run("6\n7 2 3 1 5 6\n") == "5", "sample"

# minimum size
assert run("1\n42\n") == "1", "single element"

# already increasing
assert run("5\n1 2 3 4 5\n") == "5", "already valid"

# all equal
assert run("5\n5 5 5 5 5\n") == "2", "one modification extends by one"

# merge impossible because gap is 1
assert run("5\n1 2 10 3 4\n") == "4", "cannot merge across middle"

# merge possible
assert run("5\n1 2 100 4 5\n") == "5", "full merge"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 42`| 1 | 最小配列サイズ |
 |`1 2 3 4 5`| 5 | すでに厳密に増加しています |
 |`5 5 5 5 5`| 2 | 1 つの変更により、長さ 2 のセグメントを作成できます。 
|`1 2 10 3 4`| 4 | ギャップが 1 に等しい場合、マージ条件は失敗します。 
|`1 2 100 4 5`| 5 | 2 つの実行のマージが成功しました |

 ## 特殊なケース

 ### 単一要素配列

 入力:```
1
10
```配列には要素が 1 つしか含まれていないため、すでに厳密に増加しています。 このアルゴリズムは、補助配列を構築する前にすぐに 1 を返します。 

### すべての要素が等しい

 入力:```
5
5 5 5 5 5
```以下を取得します。```
L = [1, 1, 1, 1, 1]
R = [1, 1, 1, 1, 1]
```隣接する値が等しいため、マージ条件は成功しません。 どちらかの辺を伸ばすと長さは2になるので、答えは2になります。 

答えが 1 ではないため、これはよくある間違いの原因です。1 つの変更により、常に厳密に増加するペアが作成される可能性があります。 

### ギャップが小さすぎて結合できません

 入力:```
3
1 100 2
```中間の位置:```
a[2] - a[0] = 1
```厳密に 1 と 2 の間には整数はありません。マージ遷移は拒否されます。 アルゴリズムは正しく 2 を返します。 

### アレイ全体がすでに増加中

 入力:```
5
1 2 3 4 5
```計算された配列は次のとおりです。```
L = [1, 2, 3, 4, 5]
```最初の答えはすでに 5 です。いかなる変更も配列全体より長いセグメントを生成することはできないため、最終結果は 5 のままです。これは、変更が必要ない場合をアルゴリズムが正しく処理していることを検証します。
