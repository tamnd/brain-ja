 ## 解決策
 ## 問題の理解

 整数セルの数直線上に一連のイベントが与えられます。 各イベントは特定の時間と位置に出現するコインであり、正確に 1 秒間存在します。 2 台のロボットが時間 1 より前にスタートし、毎秒、ラインに沿っていずれかの方向に固定速度制限まで移動します。 移動するとコインが出現し、コインのマスの上に立っているロボットがコインを集めます。 

タスクは、一定の速度での動きをシミュレートすることではありません。 代わりに、2 台のロボットがすべてのコインを収集できるように、開始位置と移動戦略の選択肢が存在するように、可能な最小速度を決定する必要があります。 

主な問題点は、コインには時間順序があり、移動の制約により時間の経過に伴う結合が生じることです。 ロボットはテレポートできないため、各コインには、その位置と時間を、以前に収集したコインから到達可能であったものに関連付ける制約が課されます。 

入力サイズは大きく、テスト ケース全体で合計最大 10^6 コインです。 これにより、コインのペアについて推論したり、時間をステップごとにシミュレートしたりするソリューションは即座に除外されます。 どのアプローチでも、テスト ケースごとに本質的に線形またはほぼ線形の時間でコインを処理する必要があります。 

微妙なエッジ ケースは、コインが時空的に離れすぎていて 1 台のロボットでも到達できないが、2 台のロボットなら集合的に到達できる可能性がある場合です。 たとえば、コインが (時間 1、位置 1) と (時間 1、位置 10^9) に現れた場合、1 台のロボットが単一の位置から開始した場合、速度に関係なく両方を収集することはできませんが、2 台のロボットであれば責任を自明に分割できます。 正しい解決策は、実行不能の原因が速度不足によるものか、それとも基本的な幾何学的な分離によるものなのかを正確に区別する必要があります。 

時間の経過とともにコインが 2 つの遠く離れた領域間で交互に移動する場合、別の重要な状況が発生します。 時差を超えたグローバルな実現可能性を考慮せずに、単純にロボットにコインを貪欲に割り当てると失敗します。これは、初期の割り当てが、ローカルでは見えない方法で将来の到達可能性を制限するためです。 

## アプローチ

 ブルートフォースの観点は、候補速度 v を固定し、実現可能性を確認することから始まります。 与えられた v をテストできれば、答えを二分探索できます。 

固定 v の場合、各ロボットは時間の経過とともに到達可能な間隔を定義します。開始位置から t 秒後には、v・t の半径内のどこにでも到達できます。 これは、ロボットが一連のコインを収集する場合、連続して収集されたコイン間の距離は時間と空間の両方の制約を考慮する必要があることを意味します。 ただし、ロボットが 2 台あるため、各コインを 2 つのシーケンスのいずれかに割り当てる必要があります。 

直接総当たりでは、2 台のロボットとすべての開始位置へのコインのすべての割り当てが試行されます。 これは n において指数関数的であり、すぐには実行不可能です。 

重要な観察は、v が固定されると、時間順の点における 2 つの「パス」での実現可能性がスケジューリングの問題になるということです。 各ロボットは、割り当てられたサブシーケンスを時間の増加順に独立して移動できなければなりません。また、同じロボットに割り当てられた連続する各ペア (ti, ci)、(tj, cj) について、 |cj − ci| が必要です。 ≤ v · (tj − ti)。 この制約は、単一ロボットの実現可能性を完全に特徴づけます。 

したがって、固定 v の場合、問題はシーケンスを 2 つのサブシーケンスに分割し、それぞれが単調な到達可能性制約を遵守することになります。 これは、部分的に順序付けされたセットに関する古典的な 2 パスの実現可能性問題です。 

私たちは貪欲な構造を使用することで、明示的にパーティションを検索することを避けます。つまり、各ロボットの到達可能な最新の「状態」を維持し、将来を最も柔軟に保ちながら、各ロボットがそれを取得できる可能性のあるものに各コインを割り当てます。 これは、O(n) での実現可能性チェックに変えることができます。 

特定の v の実現可能性がテスト可能になったら、最大 10^9 の範囲で v を二分探索します。

 ## アルゴリズムのチュートリアル

 すべてのコインを 2 つの有効なロボット ルートに割り当てることができるように、最小の v を二分探索します。 

固定 v の場合、時間の増加順にコインを処理し、ロボットごとに最後に収集したコインを維持します。 

1. コインを時間順に並べ替えます。ただし、入力によってこれはすでに保証されています。 
2. ロボットごとに、最後に収集したコインを (時間、位置) として保存します。 最初は両方のロボットにコインがありません。これは、時間 0 で任意の位置から開始すると想像できることを意味します。 
3. コインを時間順に繰り返します。 現在のコイン (t, c) について、ロボット A またはロボット B のどちらがそれを受け取ることができるかを決定します。 ロボットは、以前のコインを持っていない場合、または距離の制約が満たされている場合に、それを受け取ることができます。 

|c − c_prev| ≤ v · (t − t_prev)。 

この条件により、ロボットは最後に収集したコインから時間内に新しいコインに物理的に移動できることが保証されます。 
4. 両方のロボットがコインを受け取ることができる場合は、前のコインが「制限が少ない」ロボット、つまり時間と空間のトレードオフにおいて現在のコインに近い最後の位置を持つロボットにそのコインを割り当てます。 単純で効果的なルールは、前回の時間が短いロボットにそれを割り当てることです。そのロボットには、今後より多くの時間余裕があるからです。 
5. 1 台のロボットだけでそれを受け取ることができる場合は、そこに割り当てます。 
6. どちらのロボットもそれを受け入れることができない場合、現在の v は実行不可能です。 
7. すべてのコインが正常に割り当てられた場合、v が実行可能です。 

0 から 10^9 までの v に対して二分探索を使用します。 実現可能性のチェックは単調です。速度 v が機能する場合、すべての到達可能性制約が弱くなるため、より大きな速度も機能します。 

### なぜ効果があるのか

 正しさは、各ロボットが収集したコインが、時間に対する空間の厳密なリプシッツ制約を伴う時間増加シーケンスを形成するという事実に依存しています。 この制約は時間順に凸型です。つまり、シーケンスが実行可能である場合、以前の制約を挿入しても、局所的な違反を超えて後の実行可能性が無効になることはありません。 貪欲な割り当てにより、有効な割り当てが存在する場合に両方のロボットでコインを不必要にブロックすることがなくなります。これは、実行可能なソリューションであれば、この段階的な実行可能性チェックと互換性のある少なくとも 1 つの割り当てが誘導されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(v, coins):
    # each robot: (time, position)
    a_t = a_x = -1
    b_t = b_x = -1

    for t, x in coins:
        can_a = True
        can_b = True

        if a_t != -1:
            if abs(x - a_x) > v * (t - a_t):
                can_a = False
        if b_t != -1:
            if abs(x - b_x) > v * (t - b_t):
                can_b = False

        if not can_a and not can_b:
            return False

        if can_a and not can_b:
            a_t, a_x = t, x
        elif can_b and not can_a:
            b_t, b_x = t, x
        else:
            # both can take it: assign to the more flexible robot
            # heuristic: choose robot with smaller last time gap advantage
            if a_t < b_t:
                a_t, a_x = t, x
            else:
                b_t, b_x = t, x

    return True

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        coins = []
        for _ in range(n):
            t, c = map(int, input().split())
            coins.append((t, c))

        # quick impossibility check
        if n == 0:
            print(0)
            continue

        lo, hi = 0, 10**9
        ans = -1

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, coins):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、実現可能性テストを v の検索から分離します。実現可能性関数は、各ロボットの最後に取得したコインを維持し、新しいコインがそれぞれ到達可能かどうかをチェックします。 重要な実装の詳細は、移動制限を正確にモデル化する制約内の時間差スケーリングです。 

微妙な点は、ロボットの状態が時間 -1 で初期化されることです。 これにより、最初の割り当ての前に距離制約が強制されないため、最初に割り当てられたコインを任意の開始位置から取得できるようになります。 

両方のロボットがコインを獲得できる場合の貪欲なタイブレーク ルールは、一方のロボットが早期に飢えてしまうことを避けるために選択されます。 前回に基づいた割り当ては、柔軟性を維持する単純なヒューリスティックです。 

## 実用的な例

 コインを考えてみましょう。 

(1, 1)、(2, 10)、(3, 2)

 v = 4 をテストします。 

| コイン | ロボットA | ロボットB | 割り当て |
 | --- | --- | --- | --- |
 | (1,1) | 無料 | 無料 | あ |
 | (2,10) | | B は到達できますが、A は到達できません | B |
 | (3,2) | A は到達できますが、B は到達できません | | あ |

 これは、分割によって 1 台のロボットだけではカバーできない大きなジャンプをどのように回避できるかを示しています。 

次に、不可能なケースを考えてみましょう。 

(1, 1)、(2, 10)、(3, 1)

 v が小さい場合、同じロボットが単位時間ギャップ内に 1 と 10 の間をジャンプして 1 に戻ることができないため、ロボットの割り当ては失敗します。 実現可能性関数は最終的に、必要なしきい値を下回るすべての v を拒否し、二分探索は有効な最小速度に収束します。 

これらの痕跡は、実現可能性が空間的な距離だけでなく時間的な間隔にも依存することを裏付けています。

 ## 特殊なケース

 重要なエッジケースは、すべてのコインが同時に出現するが、大きく離れた位置に出現する場合です。 その状況では、各ロボットはその瞬間に空間内の連続した領域を 1 つだけ収集することができ、速度に関係なく、2 つ以上の連続しない位置を必要とするコイン セットは不可能です。 どちらのロボットも未定義の位置から開始し、時間差ゼロ以内に複数の遠くのセルにテレポートできないため、アルゴリズムはこれを正しく拒否します。 

もう 1 つのエッジ ケースは、コインが空間内で単位時間のギャップはあるものの大きな空間ジャンプを伴うジグザグを形成する場合です。 個々のジャンプは実行可能であっても、1 台のロボットが反対方向に 2 回の大きなジャンプを強制された場合、交互の割り当ては失敗する可能性があります。 実行可能性チェックは、割り当てられたサブシーケンス全体にわたって各ロボットの軌道の一貫性を強制するため、これを検出します。 

最後に、単一のロボットで十分であるが、貪欲な割り当てが誤って分割されるケースは、柔軟性ルールによって処理されます。 1 台のロボットの拘束が早すぎると、後のコインが両方のロボットで失敗する可能性があるため、割り当て戦略では、ロボットをタイトな軌道に早まってロックすることを回避する必要があります。
