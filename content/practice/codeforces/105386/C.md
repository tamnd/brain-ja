 ## 解決策
 ## 問題の理解

 私たちは非常に大きなグリッドで作業していますが、関連するのはまばらなセルのセットのみです。いくつかのセルには城が含まれており、いくつかのセルには障害物が含まれています。 2 つの城が同じ行または列にある場合、それらの城はお互いを「認識」でき、厳密にはそれらの間に重要なものはありません。 

ここでの「重要」とは、別の城または障害物を意味します。 したがって、そのような物体は視界を妨げます。 いくつかの障害物を取り除くと、城の間に新たな視線が広がり、攻撃的なペアが形成される可能性があります。 

タスクは、障害物を取り除いた後にこれらの攻撃ペアを数えるだけではありません。 正確に選択しなければなりません`k`取り除くべき障害物がたくさんあるため、最終的に攻撃する城のペアの数をできるだけ少なくしたいと考えています。 

障害物を取り除くと視認性が高まるだけなので、最初はこれは逆説的に聞こえます。 私たちができる唯一のコントロールは、新しい攻撃関係をできるだけ少なくするために、どの障害物を取り除くかを選択することです。 

制約は大きく、テスト ケースごとに最大 100,000 の城と障害物があり、合計入力サイズも 100,000 で制限されます。 これにより、ペアごとに可視性をシミュレートしようとするソリューションや、削除のたびに可視性を再計算しようとするソリューションは直ちに除外されます。 許容可能な解決策はすべて、線形または`n log n`テストケースごとに。 

よくある失敗例は、ローカルで考えることから生じます。 たとえば、1 行に次があるとします。```
C . O . C
```障害物が 2 つの城の間の視界を妨げます。 その障害物を取り除くと、すぐに攻撃ペアが 1 つ作成されます。 単純なアプローチでは、各障害物を個別に評価しようとする可能性がありますが、複数の障害物が同じ城の間にある場合、または障害物が複数の行と列に同時に関与している場合は失敗します。 

もう 1 つの微妙な問題は、責任の重複です。 単一の障害物によって、その行および列内の複数の城のペアの視界が妨げられる可能性があります。 貢献を方向ごとに独立して処理すると、二重カウントや誤った貪欲な決定につながります。 

本当の難しさは、攻撃する可能性のある各ペアが、1 つの城だけではなく、_2 つの城の間のすべての障害物_ に依存していることです。 

## アプローチ

 この問題を考える強引な方法は、考えられるすべてのセットを試した後で可視性を再計算することです。`k`障害物。 サブセットごとに、行と列の構造を再構築し、表示されているすべての城のペアを数えます。 これは明らかに正しいですが、完全に実行不可能です。 サブセットの数は組み合わせによるもので、次のとおりです。$\binom{m}{k}$、そして 1 つの評価でさえ、すでに少なくとも直線的なポイント数の時間がかかります。 

2 番目の強引なアイデアは、障害物を 1 つずつ取り除くことをシミュレートし、どの城のペアが新たに表示されるかを常に再計算することです。 行および列ごとにソートされた順序を維持したとしても、削除のたびに更新するには依然として多くの間隔を更新する必要があり、最悪の場合は 2 次の動作が発生します。 

重要な構造上の観察は、城の可視性は行と列に沿った順序によってのみ決定されるということです。 占有されているすべてのセルを連続して並べ替えると、城は障害物や他の城によって区切られた、接続されたセグメントになります。 この順序で連続する 2 つの城は潜在的な攻撃ペアを定義し、そのペアは、その間にあるすべての障害物が取り除かれた場合にのみアクティブになります。 

したがって、グローバルな可視性の観点から考えるのではなく、問題を各行と列の連続する城によって定義される独立した「セグメント」に還元します。 このような各セグメントには一連の障害物があり、そのセグメント内のすべての障害物を除去した場合にのみ 1 つの攻撃ペアに貢献します。 

さて、問題は次のとおりです。私たちは選択しなければなりません`k`各セグメントは、その中のすべての障害物が選択された場合にのみ「アクティブ化」されます。 完全にアクティブになるセグメントの数を最小限に抑えたいと考えています。 

これはセット システムの問題です。各セグメントは一連の障害物に対応しており、選択する必要があります。`k`可能な限り多くのセットを完全にカバーすることを避けながら、要素を配置します。 セグメントは共有障害物を介してのみ重複するため、自然な貪欲信号は、多くのセグメントに参加するという点で各障害物がどれほど「危険」であるかを示します。 

実行可能な削減は、すべての障害物について、それが属する城に隣接するセグメントの数を計算することです。 直感的には、多くの重要なセグメントにある障害物を選択すると、そのうちの 1 つを完全に完了できる可能性が高くなるため、可能な限り避けるべきです。 したがって、関与が最も小さい障害物を最初に選択します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(m) | 遅すぎる |
 | セグメント + 貪欲なスコアリング | O((n + m) log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、順序付けされた点の行方向および列方向の処理に圧縮します。 

1. すべての城と障害物を行ごとにグループ化します。 各行を列インデックスで並べ替えます。 同じグループ化を列ごとに実行し、行インデックスで並べ替えます。 

これにより、可視性が重要となる各ラインに沿ったすべての占有セルの線形順序が得られます。 
2. ソートされた各行を左から右にスキャンして、連続する城を見つけます。 連続する城のペアごとに、それらの間のすべての障害物を記録します。 これらの障害物は、その城のペアに対する「ブロック セット」を形成します。 

列についても同じことが繰り返されます。 列内の各城のペアには、一連の障害物も与えられます。 
3. すべての障害物について、それが出現するブロック セットの数を表すカウンターを維持します。 

このカウンターは、この障害物が城の視界を妨げる頻度を測定します。 このようなセグメントの多くに関係する障害は、より「重大」です。 
4. このカウンタによってすべての障害物を昇順に並べ替えます。 

その考え方は、潜在的なセグメントの完了に最小限の影響を与える障害物を最初に選択して、1 つのブロッキング セットを完全にクリアできる可能性を減らすことです。 
5. 最初の項目を選択します`k`この順序付けによる障害。 
6. 選択後、各セグメントをチェックして最終的な攻撃ペアの数を計算します。セグメントは、そのすべての障害物が選択された場合にのみ 1 回の攻撃に貢献します。 

### なぜ効果があるのか

 各攻撃ペアは特定の障害物のセットに関連付けられており、そのセット内のすべての障害物が除去された場合にのみアクティブになります。 したがって、ペアをアクティブにするリスクは、これらのセットの 1 つを完全に選択することに集中します。 

このような多くのセットに参加する障害物は、決定間の結合を増加させます。障害物を選択すると、複数のセットが完全に選択される状態に近づきます。 参加者の多い障害物を貪欲に回避すると、選択がさまざまなブロック構造に分散され、その中で完全にカバーできるセットの数が最小限に抑えられます。`k`ピックします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    castles = []
    obstacles = []
    
    for _ in range(n):
        r, c = map(int, input().split())
        castles.append((r, c))
    
    obs = []
    for i in range(m):
        r, c = map(int, input().split())
        obs.append((r, c, i))
    
    # map obstacle index to participation count
    contrib = [0] * m
    
    from collections import defaultdict
    
    row_castles = defaultdict(list)
    row_obs = defaultdict(list)
    col_castles = defaultdict(list)
    col_obs = defaultdict(list)
    
    for r, c in castles:
        row_castles[r].append(c)
        col_castles[c].append(r)
    
    for r, c, i in obs:
        row_obs[r].append((c, i))
        col_obs[c].append((r, i))
    
    # process rows
    for r in row_castles:
        cs = sorted(row_castles[r])
        os = sorted(row_obs[r])
        
        j = 0
        for idx in range(len(cs) - 1):
            left = cs[idx]
            right = cs[idx + 1]
            
            while j < len(os) and os[j][0] <= left:
                j += 1
            
            tmp = j
            while tmp < len(os) and os[tmp][0] < right:
                contrib[os[tmp][1]] += 1
                tmp += 1
    
    # process cols
    for c in col_castles:
        rs = sorted(col_castles[c])
        os = sorted(col_obs[c])
        
        j = 0
        for idx in range(len(rs) - 1):
            top = rs[idx]
            bottom = rs[idx + 1]
            
            while j < len(os) and os[j][0] <= top:
                j += 1
            
            tmp = j
            while tmp < len(os) and os[tmp][0] < bottom:
                contrib[os[tmp][1]] += 1
                tmp += 1
    
    order = sorted(range(m), key=lambda i: contrib[i])
    chosen = set(order[:k])
    
    # compute result
    row_obs_map = defaultdict(list)
    col_obs_map = defaultdict(list)
    
    for r, c, i in obs:
        row_obs_map[r].append((c, i))
        col_obs_map[c].append((r, i))
    
    active = set(chosen)
    
    def segment_count():
        ans = 0
        
        for r in row_castles:
            cs = sorted(row_castles[r])
            os = sorted(row_obs_map[r])
            
            j = 0
            for i in range(len(cs) - 1):
                L, R = cs[i], cs[i + 1]
                ok = True
                
                while j < len(os) and os[j][0] <= L:
                    j += 1
                
                tmp = j
                while tmp < len(os) and os[tmp][0] < R:
                    if os[tmp][1] not in active:
                        ok = False
                    tmp += 1
                
                if ok:
                    ans += 1
        
        for c in col_castles:
            rs = sorted(col_castles[c])
            os = sorted(col_obs_map[c])
            
            j = 0
            for i in range(len(rs) - 1):
                L, R = rs[i], rs[i + 1]
                ok = True
                
                while j < len(os) and os[j][0] <= L:
                    j += 1
                
                tmp = j
                while tmp < len(os) and os[tmp][0] < R:
                    if os[tmp][1] not in active:
                        ok = False
                    tmp += 1
                
                if ok:
                    ans += 1
        
        return ans
    
    print(segment_count())
    print(*[i + 1 for i in chosen])

solve()
```行と列の前処理により、城間の隣接情報が構築されます。これが、新しい攻撃ペアを生成できる唯一の構造です。 の`contrib`配列は重要なヒューリスティックです。各障害物がブロック セグメントに関与する頻度を測定します。 

最後の選択ステップでは、最も「影響力の低い」障害物を選択するだけです。 その後、各セグメント内のすべての障害物が選択したセットに属しているかどうかを確認して、完全にクリアされたセグメントの数を再計算します。 

## 実用的な例

 ### 例 1

 単一の行を考えてみましょう。```
C  O1  O2  C  O3  C
```2 つの城のペアがあります。1 番目と 2 番目の城の間、および 2 番目と 3 番目の城の間です。 

| ステップ | セグメント | 障害物 | 投稿アップデート |
 | --- | --- | --- | --- |
 | スキャン行 | C1-C2 | O1、O2 | O1 += 1、O2 += 1 |
 | スキャン行 | C2-C3 | O3 | O3 += 1 |

 もし`k = 1`、寄与が最小の障害物を選択します。 O3 が選択されたとします。 

2 番目のセグメントのみがアクティブになりますが、そのセグメントに対してのみ O3 だけで十分です。 代わりに O1 または O2 を選択した場合、他の構造内の複数のセグメントに影響を与える可能性が高くなります。 

これは、スコアリングによって、複数のクリティカル インターバル内にある障害物を選択することがどのように抑制されるかを示しています。

 ## 特殊なケース

 主なエッジケースは、同じペアの城の間に複数の障害物がある場合です。 例えば：```
C . O1 . O2 . C
```ここで、ペアは O1 と O2 の両方が削除された場合にのみアクティブになります。 アルゴリズムは両方の障害物を同じセグメントに属するものとして扱い、両方ともそのセグメントから寄与を受け取ります。 いずれか 1 つだけを選択してもペアはアクティブ化されず、要件に一致します。 

もう 1 つのエッジ ケースは、障害物が行セグメントと列セグメントの両方に属する場合です。 次のような交差構成の場合:```
C O C
. O .
C O C
```中央の障害物は複数のブロッキング セットに寄与します。 貢献度が増加するため、早期に選ばれる可能性が低くなります。 これは、その世界的な重要性の高さを正しく反映しています。 

最後のエッジケースは次のような場合です`k = m`。 この場合、すべての障害物が取り除かれ、すべてのセグメントが完全にクリアされ、同じ行または列にある考えられるすべての城のペアがアクティブになります。 アルゴリズムは自然にすべての障害物を選択し、制約に従って最大の攻撃回数を生成します。
