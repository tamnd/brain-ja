 ## 解決策
 ## 問題の理解

 私たちにはいくつかのコンテストが与えられています。 各コンテストには「星評価」とプロパティのベクトルがあります。 コンテストのスコアは、そのすべてのプロパティの単純な合計です。 一部のプロパティ値はすでに固定されていますが、その他の値は欠落していて不明としてマークされています。 すべてのプロパティには最終的に範囲内の整数を割り当てる必要があります。$[0, k]$。 

この要件は厳密な順序付け条件です。あるコンテストに他のコンテストよりも多くのスターがいる場合、その最終スコアも厳密に大きくなければなりません。 したがって、スターの順序は、構築されたプロパティ ベクトルの合計によって引き起こされる順序と一致する必要があります。 

タスクは、この単調性が維持されるようにすべての欠損値を埋めるか、それが不可能であると判断することです。 

制約はすぐに問題を形成します。 すべてのテスト ケースにわたるプロパティ エントリの合計数は最大で次のとおりです。$4 \cdot 10^5$したがって、各セルを一定の回数だけ処理するソリューションは実行可能です。 どちらかの二次関数$n$または$m$不可能です。 

主な困難は、コンテストごとに独立して任意の値を選択するだけではないということです。 合計は厳密なグローバル順序を尊重する必要があるため、1 つのコンテストの選択が他のすべてのコンテストを制約する可能性があります。 

空白を埋める前であっても、固定値がすでに実現可能性に違反している場合、微妙な失敗のケースが発生します。 

たとえば、2 つのコンテストに星評価があるとします。$s_1 < s_2$, しかし、未知数を埋める前であっても、最初のものはすでに 2 つ目よりも大きな固定合計を持っています。 未知のものは制限された最大値までしかスコアを増加させないため、いくら埋めてもこの問題を解決することはできません。 

もう 1 つの注意が必要な状況は、スターの高いコンテストにはすべて不明なエントリがあり、スターの低いコンテストではすでにすべてのエントリが高い値に固定されている場合です。 ソリューションでは、貪欲に割り当てる前に実現可能性をチェックする必要があります。 

素朴なアプローチでは、グローバルな順序を考慮せずに、セルごとにすべての代入を試行したり、欠損値を貪欲に埋めたりしますが、制約は基本的に個々のプロパティではなく全体の合計に関するものであるため、これは失敗します。 

## アプローチ

 強引なアイデアは、欠落している各セルを変数として扱い、すべての制約が満たされるように値を割り当てようとすることです。 これはすぐに高次元の制約充足問題に発展します。 コンテストごとの調整額だけを考えたとしても、各コンテストには最大で$m$変数、および各変数の範囲は次のとおりです$[0, k]$、したがって、単一のコンテストでも、$(k+1)^m$構成。 これはまったく実現不可能です。 

重要な簡素化は、各コンテストを 1 つの数値 (合計) にまとめることで実現します。 和についてのみ考えると、ベクトルの内部構造は、目標の和をエントリ全体に分散する方法として以外には無関係になります。 

ここで問題は、各コンテストに最終的な合計額を割り当てることです。$v_i$、既存の固定貢献を尊重し、星の評価に関して厳密な単調性を確保します。 

コンテストを星評価で並べ替える場合、この順序に沿って合計を厳密に増加させる必要があります。 したがって、実際のタスクは、実行可能な合計の厳密に増加するシーケンスを構築することになります。実現可能性は、欠落しているエントリを使用してコンテストをどれだけ増やすことができるかによって決まります。 

コンテストごとに 2 つの境界を計算できます。 可能な最小合計は、欠落しているすべてのエントリをゼロとして扱うことによって取得されます。 可能な最大合計は、不足しているすべてのエントリを次のように埋めることによって得られます。$k$。 これは問題を間隔スケジュールに変換します。各コンテストには実行可能な間隔があります。$[L_i, R_i]$値を選択する必要があります$v_i \in [L_i, R_i]$そのような$v$星の順序が増加するにつれて厳密に増加します。 

必要な金額が決まったら、それぞれを分配します。$v_i$に戻る$m$座標は単純です。最初に固定値を割り当ててから、不足しているスロットを貪欲に埋めます。 

核となる洞察は、実現可能性はこれらの間隔によって完全に決定され、ソートされた星に対する貪欲な左から右への割り当てで十分であるということです。

 ## アルゴリズムのチュートリアル

 1. 各コンテストについて、欠損していない値をすべて加算して、その固定貢献額を計算します。 また、欠落しているエントリがいくつあるかも数えます。 これにより、各コンテストにどれだけの自由が残っているかが区別されます。 
2. 各コンテストについて、欠落しているエントリがすべてゼロになると仮定して、可能な最小合計スコアを計算します。 これにより、$L_i$。 同様に、欠落しているすべてのエントリが次のようになると仮定して、可能な最大スコアを計算します。$k$、与える$R_i$。 これにより、各コンテストが達成可能な合計額の範囲内に圧縮されます。 
3. すべてのコンテストを星評価順に並べ替えます。 これが必要なのは、制約が方向性を持っているためです。つまり、より高い星ほど、厳密により高い合計を持たなければなりません。 
4. スターの昇順でコンテストを繰り返し、最終的な合計を貪欲に割り当てます。 変数を維持する`prev`最後に割り当てられた合計。 現在のコンテストでは、厳密に次より大きい値を選択する必要があります。`prev`、だけでなく、$[L_i, R_i]$。 もし`L_i > prev`、私たちは取る`L_i`。 それ以外の場合は、`prev + 1`。 これを超えると$R_i$、割り当ては不可能です。 
5. すべての目標金額を決定した後、コンテストごとに実際の資産価値を再構成します。 固定値から始めます。 次に、不足しているポジションごとに、目標合計に達するのに必要なだけ割り当てますが、決してそれを超えないようにします。$k$。 これは貪欲に行われ、不足しているスロットを 1 つずつ埋めていきます。 
6. 完成した行列を出力します。 

貪欲な割り当てが機能する主な理由は、初期のコンテストが最も制限的であるためです。 各コンテストで実行可能な最小値を決定すると、後のコンテストのために最大限の余地を確保します。 初期の値を増加させようとしても、後の間隔の実現可能性が低下するだけであり、利益はありません。 

### なぜ効果があるのか

 各コンテストでは、実行可能な合計の間隔が定義されます。 星評価による並べ替えでは、これらの間隔から選択された代表者に厳格な順序制約が課されます。 貪欲なステップは、間隔と互換性のある可能な限り最小の厳密に増加するシーケンスを構築します。 これがどこかの時点で失敗した場合、現在の間隔で最も小さい有効な選択であっても前の割り当てを超えることはできないため、有効なシーケンスがまったく存在しないことを意味します。 これは、実行可能な解決策は点的に貪欲な解決策を支配する必要があり、貪欲な解決策が失敗するとそれは不可能であることを証明するのと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    stars = []
    fixed_sum = [0] * n
    missing = [0] * n
    arr = []

    for i in range(n):
        data = list(map(int, input().split()))
        s = data[0]
        stars.append((s, i))
        row = data[1:]
        arr.append(row)

        ssum = 0
        miss = 0
        for x in row:
            if x == -1:
                miss += 1
            else:
                ssum += x

        fixed_sum[i] = ssum
        missing[i] = miss

    intervals = []
    for i in range(n):
        L = fixed_sum[i]
        R = fixed_sum[i] + missing[i] * k
        intervals.append((L, R, i))

    stars.sort()

    assigned = [0] * n
    prev = -10**30

    for s, i in stars:
        L, R, idx = intervals[i]
        if L > prev:
            val = L
        else:
            val = prev + 1

        if val > R:
            print("No")
            return

        assigned[i] = val
        prev = val

    result = [row[:] for row in arr]

    for i in range(n):
        need = assigned[i] - fixed_sum[i]
        for j in range(m):
            if result[i][j] == -1:
                give = min(k, need)
                result[i][j] = give
                need -= give

    print("Yes")
    for i in range(n):
        print(*result[i])

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```この解決策は、各コンテストを解析し、固定された投稿を欠落しているエントリから分離することから始まります。 この分離により、個々の値を推測することなく、達成可能な合計の下限と上限を正確に計算できるため、不可欠です。 

ソートされたスターに関する貪欲なセクションは、意思決定の核となる部分です。 変数`prev`厳格な増額を強制します。 選択`max(L, prev+1)`は、実現可能性と単調性の両方を尊重する唯一の有効な候補です。 

再構築のステップはコンテストごとに独立しています。 合計はすでに固定されているため、欠落しているセルに残りの値を分配することは、コンテスト間で調整することなく貪欲に行うことができます。 

## 実用的な例

 ### 例 1

 星の順序がすでにソートされている 3 つのコンテストを考えてみましょう。 

| コンテスト | 定額 | 欠落しています | Ｌ | R | 前へ | 選ばれた |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | 1 | 3 | 8 | -inf | 3 |
 | 2 | 5 | 1 | 5 | 10 | 3 | 5 |
 | 3 | 4 | 2 | 4 | 14 | 5 | 6 |

 3 番目のコンテストでは、実行可能な最小値 4 は 5 を超える必要があるため、取ることができません。そのため、6 を選択します。これはまだ上限内に収まります。 

このトレースは、間隔が確実に柔軟性を維持しながら、前の割り当てが後の割り当てをどのように制約するかを示しています。 

### 例 2

 失敗例:

 | コンテスト | Ｌ | R | 前へ | 選ばれた |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | -inf | 0 |
 | 2 | 0 | 1 | 0 | 1 |
 | 3 | 0 | 1 | 1 | 不可能 |

 ここで 3 回目のコンテストは、$R = 1$、ただし超える必要があります`prev = 1`。 1 より大きい値は存在しないため、アルゴリズムはインスタンスを正しく拒否します。 

これは、厳密な増加を世界的に維持できない限り、間隔の実現可能性だけでは不十分であることを示しています。

 ## 特殊なケース

 例外的なケースの 1 つは、すべてのコンテストのスター値が同じである場合に発生します。 この制約は 1 つの星の数が厳密に大きい場合にのみ適用されるため、内部実現可能性が維持される限り、どの割り当ても有効です。 並べ替えによって等しいグループが生成されるため、アルゴリズムはこれを自然に処理します。`prev`不必要な増加を強制することはありません。 

もう 1 つのエッジ ケースは、コンテストに欠損値がゼロである場合です。 その場合、その間隔は単一点に崩壊します。$[L, L]$。 貪欲がより高い値を必要とする場合、利用可能な調整がないため、アルゴリズムは不可能であることを正しく検出します。 

最後のコンテストの上限が非常に厳しい場合、よりデリケートなケースが発生します。 もし以前の貪欲な選択が後押しするなら`prev`高すぎると、以前のすべての選択がローカルで有効であったとしても、最終的な間隔は必要な厳密な増加に対応できない可能性があります。 アルゴリズムはまさにその時点で失敗します。これは、インスタンスの実際の実行不可能性と一致します。
