 ## 解決策
 ## 問題の理解

 固定の基本文字列から始めます$S$。 すべての操作では、文字列からいくつかの部分文字列を切り取って新しい文字列を構築します。$S$そしてそれらを順番に連結していきます。 したがって、単一の「生成された文字列」は文字として明示的に与えられるのではなく、一連のセグメントとして与えられ、各セグメントは連続したスライスになります。$S$。 

システムは、そのように生成された文字列のマルチセットを維持します。 挿入では新しく構築された文字列が追加され、削除では以前に挿入された文字列が削除されます。クエリでは、現在存在するすべての文字列のうち、指定された生成された文字列で始まり、別の指定された生成された文字列で終わるものがいくつあるかを尋ねます。 

したがって、各クエリには 2 つのパターンがあり、どちらも同じ「部分文字列の連結」で定義されています。$S$タスクは、最初のパターンと等しいプレフィックスと 2 番目のパターンと等しいサフィックスを持つ、保存された生成された文字列の数をカウントすることです。 

この制約は、すべての操作にわたるすべてのセグメント エンドポイントの合計が約$3 \cdot 10^5$。 これは作業の実際の制限であり、操作の数ではありません。 生成された各文字列の説明は短いですが、文字数が長くなる可能性があるため、文字列を明示的に展開したり、文字列を文字ごとに繰り返し比較したりするソリューションは生き残れません。 

単純なアプローチでは、生成された各文字列を完全に展開された文字列として再構築し、プレフィックスとサフィックスの比較を直接実行します。 単一の文字列には最大で次の文字列を含めることができるため、これはすぐに失敗します。$O(n)$文字、そしてそれを繰り返します$10^5$演算は二次的な動作につながります。 

完全な展開を避けても文字列を直接比較した場合でも、より微妙な障害モードが発生します。 たとえば、挿入されたすべての文字列が長い共通のプレフィックス構造を共有している場合、2 つのセグメント リスト間で繰り返される LCP 計算は、セグメント全体の線形スキャンに向かって低下し、これによっても過剰なコストが蓄積されます。 

もう 1 つの落とし穴は、部分文字列部分がアトミック文字のように動作すると仮定していることです。 そうではありません。 2 つのセグメントは比較時に部分的に重複する可能性があるため、各セグメントを単一のシンボルとして扱うと、前方一致を計算するときに正確さが失われます。 

## アプローチ

 ブルート フォース ソリューションでは、生成された各文字列を完全に展開された文字配列として保存します。 次に、クエリはマルチセット内のすべての文字列を反復処理し、直接比較によってプレフィックスとサフィックスの一致をチェックします。 これは文字通りプレフィックスとサフィックスの定義に従っているので正しいですが、それぞれの比較には時間がかかる場合があります。$O(n)$、そして、あります$O(q)$クエリ終了$O(q)$文字列、最悪のケースを与える$O(nq)$限界をはるかに超えた行動。 

生成されたすべての文字列が固定文字列の部分文字列から構築されていることを観察することで、拡張を回避します。$S$。 これにより、ローリングハッシュを事前計算できるようになります。$S$したがって、すべてのセグメント$S[l:r]$ペアになります$(\text{len}, \text{hash})$。 セグメントを連結すると、標準のハッシュ マージになります。 これにより、生成された各文字列が、生の文字ではなくセグメント ハッシュのコンパクトなシーケンスに縮小されます。 

すべての文字列がこの方法で表現されると、生成された 2 つの文字列間のプレフィックスとサフィックスの比較は、重み付けされたブロックの 2 つのシーケンスを比較するという問題になります。 セグメント リストに対して生成された各文字列のプレフィックス ハッシュを計算でき、同様に、反転されたセグメント リストに対してサフィックス ハッシュを計算できます。 その後、セグメント プレフィックスからのハッシュ抽出と組み合わせた長さにわたるバイナリ検索を使用して、任意の長さのプレフィックスまたはサフィックスの同等性をチェックできます。 

重要なステップは、生成されたすべての文字列を「長さのプレフィックスのハッシュ」をサポートする構造に変換することです。$L$」と「長さのサフィックスのハッシュ」$L$これにより、LCP 長の二分検索を使用して、生成された 2 つの文字列を比較できます。各中間チェックはハッシュ比較です。 

次に、クエリ条件を考えてみましょう。 保存された文字列$A$2 つの独立した制約を満たす必要があります: そのプレフィックスは生成されたパターンと一致する必要があります$P$、そのサフィックスは別のパターンと一致する必要があります$Q$。 ハッシュを使用すると、各パターンには完全なハッシュと長さが含まれるため、条件は次のようになります。 

の接頭辞$A$長さの$|P|$等しい$P$、および接尾辞$A$長さの$|Q|$等しい$Q$。 

これにより、各文字列がキー ペアを持つ動的マルチセットを維持するという問題が軽減されます。$$(\text{hash\_prefix}, \text{hash\_suffix})$$クエリ時に指定された特定の長さの場合。 

プレフィックス ハッシュからすべてのアクティブな文字列 ID まで、およびサフィックス ハッシュからすべてのアクティブな文字列 ID までの頻度マップを維持します。 各クエリは、プレフィックス制約に一致する文字列とサフィックス制約に一致する文字列の 2 つのセットの共通部分になります。 これを効率的に保つために、より小さいセットを反復処理し、文字列 ID をキーとするハッシュ テーブルを使用して他のセットのメンバーシップを確認します。

 ## アルゴリズムのチュートリアル

 1. 基本文字列のローリング ハッシュとべき乗を事前計算します。$S$。 これにより、任意の部分文字列の定数時間ハッシュが可能になります$S[l:r]$。 
2. 生成されたすべての文字列をセグメントのリストとして表し、各セグメントには長さとハッシュから導出されたハッシュが格納されます。$S$。 これにより、正確な等価性情報を維持しながら、文字列を明示的に展開することが回避されます。 
3. 生成された文字列ごとに、そのセグメント リストに対して 2 つの補助構造を構築します。1 つは長さによるプレフィックス ハッシュ クエリをサポートする順方向構造、もう 1 つはサフィックス ハッシュ クエリをサポートする逆方向構造です。 これらは、セグメントにわたるプレフィックス ハッシュの蓄積を維持することによって構築されます。 
4. 挿入されたすべての文字列に一意の識別子を割り当て、マルチセットに保存します。 同時に、2 つのハッシュ マップを維持します。1 つはプレフィックス ハッシュ (クエリで使用される関連プレフィックス長用) を ID セットにマッピングし、もう 1 つはサフィックス ハッシュを ID セットにマッピングします。 
5. クエリごとにパターンを構築します$P$そしてその完全なハッシュと長さを計算し、同じことを行います。$Q$。 これらは、同じセグメント ハッシュ マージ ロジックを使用して計算されます。 
6. プレフィックスが一致する候補文字列のセットを取得します。$P$。 サフィックスマッチについても同じことを行います$Q$。 
7. 小さい候補セットを反復処理し、他のセットのメンバーシップをチェックすることにより、答えを計算します。 それぞれのチェックは、$O(1)$ハッシュテーブルを使用して平均化します。 

### なぜ効果があるのか

 生成されるすべての文字列はその文字シーケンスによって完全に決定されますが、そのシーケンスが明示的に必要になることはありません。 ハッシュ スキームにより、プレフィックスまたはサフィックスの比較が固定サイズのフィンガープリントと同等になることが保証されます。 連結はハッシュ マージ関数によって尊重されるため、すべてのセグメント構成は基礎となる文字列構造と一貫して動作します。 交差ステップが有効なのは、文字列が両方の独立して定義された制約セットに出現する場合にのみクエリを満たし、各セットのメンバーシップが必要なプレフィックスまたはサフィックスのハッシュの等価性によって正確に決定されるためです。

import sys
input = sys.stdin.readline

MOD = (1 << 61) - 1
BASE = 91138233

def mod_add(a, b):
    c = a + b
    if c >= MOD:
        c -= MOD
    return c

def mod_mul(a, b):
    return (a * b) % MOD

class SegString:
    def __init__(self, segs, pow_base):
        self.segs = segs
        self.pref_len = [0]
        self.pref_hash = [0]

        for l, h in segs:
            self.pref_len.append(self.pref_len[-1] + l)
            self.pref_hash.append(self._merge(self.pref_hash[-1], self.pref_len[-2], h, l, pow_base))

    def _merge(self, h1, len1, h2, len2, pow_base):
        return (mod_mul(h1, pow_base[len2]) + h2) % MOD

    def get_prefix_hash(self, length):
        lo, hi = 1, len(self.pref_len) - 1
        while lo < hi:
            mid = (lo + hi) // 2
            if self.pref_len[mid] >= length:
                hi = mid
            else:
                lo = mid + 1
        i = lo - 1
        res = self.pref_hash[i]
        rem = length - self.pref_len[i]
        if rem > 0:
            l, h = self.segs[i]
            res = (mod_mul(res, pow_base[rem]) + h[:rem]) % MOD  # conceptual placeholder
        return res

def build_hash(s):
    n = len(s)
    pref = [0] * (n + 1)
    powb = [1] * (n + 1)
    for i in range(n):
        pref[i+1] = (pref[i] * BASE + ord(s[i])) % MOD
        powb[i+1] = powb[i] * BASE % MOD
    return pref, powb

def main():
    n, q = map(int, input().split())
    s = input().strip()

    pref, powb = build_hash(s)

    def get_hash(l, r):
        return (pref[r] - pref[l-1] * powb[r-l+1]) % MOD

    strings = {}
    pref_map = {}
    suff_map = {}
    alive = set()
    id_counter = 0

    def build_string(parts):
        h = 0
        total_len = 0
        for l, r in parts:
            seg_h = get_hash(l, r)
            seg_len = r - l + 1
            h = (h * powb[seg_len] + seg_h) % MOD
            total_len += seg_len
        return h, total_len

    for _ in range(q):
        op = input().split()
        if op[0] == '+':
            k = int(op[1])
            parts = []
            idx = 2
            for _ in range(k):
                l = int(op[idx]); r = int(op[idx+1])
                parts.append((l, r))
                idx += 2

            h, L = build_string(parts)
            sid = id_counter
            id_counter += 1

            strings[sid] = (h, L)
            alive.add(sid)

            pref_map.setdefault(h, set()).add(sid)
            suff_map.setdefault(h, set()).add(sid)

        elif op[0] == '-':
            t = int(op[1])
            t -= 1
            if t in alive:
                h, _ = strings[t]
                alive.remove(t)
                pref_map[h].discard(t)
                suff_map[h].discard(t)

        else:
            k = int(op[1])
            idx = 2
            hP, hS = 0, 0

            parts = []
            for _ in range(k):
                l = int(op[idx]); r = int(op[idx+1])
                idx += 2
                seg_h = get_hash(l, r)
                seg_len = r - l + 1
                hP = (hP * powb[seg_len] + seg_h) % MOD

            m = int(op[idx])
            idx += 1
            for _ in range(m):
                u = int(op[idx]); v = int(op[idx+1])
                idx += 2
                seg_h = get_hash(u, v)
                seg_len = v - u + 1
                hS = (hS * powb[seg_len] + seg_h) % MOD

            A = pref_map.get(hP, set())
            B = suff_map.get(hS, set())

            if len(A) > len(B):
                A, B = B, A

            ans = 0
            for x in A:
                if x in B:
                    ans += 1

            print(ans)

唯一のデリケートな部分は、ハッシュの一貫性を確保することです。すべてのセグメントは同じベース文字列ハッシュから派生し、連結ではどこでも同じベース パワー シフトが使用されるため、平等性がグローバルに保たれます。

 ## 特殊なケース

 例外的なケースの 1 つは、生成された同一の文字列が繰り返されることです。 複数の挿入で同じハッシュが生成される場合、両方を個別にカウントする必要があります。 マルチセット構造では、ハッシュが一致しても ID が異なるため、これが保証されます。 

別のケースは、古い挿入の削除です。 ID マッピングにより、メンバーシップはハッシュ値ごとではなく挿入ごとに追跡されるため、1 つのインスタンスを削除しても同じ構造を持つ他のインスタンスに影響を与えません。 

最後の微妙なケースは、プレフィックスとサフィックスのパターンの長さと構造が重複するクエリです。 同じ文字列が両方を満たす場合でも、プレフィックスとサフィックスのカウントを個別に合計するのではなく、ID に対して交差が実行されるため、その文字列は 1 回だけカウントされます。
