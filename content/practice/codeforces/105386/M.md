 ## 解決策
 ## 問題の理解

 ピザを表す凸多角形と、パイナップルのトッピングを表すその内側の円形領域が与えられています。 直線カットを 1 つだけ行うことができますが、カットは多角形の 2 つの頂点を接続するように制限されているため、カットは常に凸包の弦になります。 このコードは、多角形を 2 つの小さな凸状部分に分割します。 

目標は、結果として得られる部分の少なくとも 1 つにパイナップルの内部点が含まれないように、単一のコードを選択することです。 パイナップルの境界に触れることは許可されていますが、ピース内の円と重なるプラスの領域があると、そのピースは無効になります。 すべての有効なカットの中で、有効な部分の可能な最大の領域が必要です。 出力はその面積の 2 倍であり、整数であることが保証されます。 

ポリゴンは大きくなり、すべてのテスト ケースで頂点が最大 10 万個になる可能性があるため、頂点のすべてのペアを考慮するアプローチは直ちに遅すぎます。 コードの二次列挙は実行できません。 また、候補の数を線形または線形に近いサイズに制限できない限り、候補カットごとに幾何学的細分割を試みることはできません。 

考えられるすべてのコードが円と交差する場合、微妙なエッジケースが現れます。 この状況では、すべてのカットでパイナップルの一部を含む部分が生成されるため、答えはゼロになるはずです。 もう 1 つのデリケートなケースは、円が潜在的なカット ラインに接している場合に発生します。 この場合、パイナップルは厳密にはピースの内側にないため、カットは依然として有効ですが、浮動小数点の実装では、距離を慎重に処理しない限り、接線を交点として誤って分類する可能性が高くなります。 

## アプローチ

 ブルート フォース アプローチでは、頂点のすべてのペアが試行され、それらの間のセグメントがカットとして扱われます。 カットごとに、プレフィックスサム エリア構造を使用するか、カットごとの線形時間でポリゴン エリアを再計算して、その弦に沿って分割することによって形成される 2 つのポリゴン エリアを計算します。 注意深く前処理を行ったとしても、頂点ペアの数は二次関数であるため、最悪の場合、制限をはるかに超える約 10^10 の演算が必要になります。 

重要な点は、実際にはすべてのコードを考慮する必要はないということです。 カットが有効になる唯一の方法は、選択した 2 つの頂点を通る無限の線がパイナップルの円の内部を通過しない場合です。 線が円と交差する場合、円は完全に凸多角形の内側にあるため、結果として得られる両方の部分には必然的に円の内部点が含まれます。 したがって、有効なカットは、円の中心からの距離が少なくとも半径である線に正確に対応します。 

ここで問題は、そのような線を定義するすべての頂点ペアのうち、結果として生じる分割の片側の面積を最大化することです。 頂点ペアの観点から考えるのではなく、凸多角形をサポートする有向線の観点から考えるとより便利です。 カットラインの方向が固定されている場合、垂直方向の多角形の両端の頂点が分割を決定します。 方向が回転すると、これらの極端な頂点は船体に沿って単調に変化します。これは、回転キャリパーで利用されるのと同じ構造です。 

これにより、問題は、凸多角形のエッジ方向によってそれぞれ決定される、線形の数の候補サポート方向をスキャンすることになります。 このような方向ごとに、2 つのポインターを使用して両方の法線方向で最も遠い支持点を維持し、プレフィックス面積の合計を使用して結果の分割の面積を計算できます。 サポートラインが円の中心から少なくとも半径の距離にある方向のみを受け入れます。

すべての頂点のペアが独立したものとして扱われるため、総当り攻撃は失敗しますが、多角形の凸面により、最適な切断方向は組み合わせ的に重要な方向、つまりハルのエッジに沿った方向でのみ現れることが保証されます。 これにより、探索空間が二次ペアから線形候補方向に縮小されます。

 ## アルゴリズムのチュートリアル

 多角形は反時計回りに与えられ、凸状であると仮定します。 

1. 境界に沿った i から j までのサブチェーンの面積を O(1) で計算できるように、ポリゴンのプレフィックス面積を事前計算します。 これは、頂点の順序に沿って外積累積を保存することによって行われ、船体の連続セグメントに対する高速なエリア クエリが可能になります。 
2. 多角形の各エッジについて、その方向を切断線の法線方向の候補として扱います。 直観的には、頂点が極端になる変化はエッジに揃った方向でのみ発生するため、最適なサポート ラインは、達成可能な有効領域を減らすことなく、エッジに揃うまで回転させることができます。 
3. 固定方向の場合、その方向と反対方向の多角形の 2 つの支持頂点を計算します。 これらは、方向が変わるにつれて多角形の周囲を単調に進む回転キャリパー ポインタを使用して検出されます。 
4. 2 つの支持頂点を通るカットラインを作成します。 この線は、その方向でまだポリゴンに接触している可能な限り最も狭い線です。 
5. 円の中心からこの線までの符号付き距離を計算します。 距離が半径より小さい場合、線は円の内側と交差するため、この方向は破棄されます。 
6. 有効な場合、事前に計算されたプレフィックス エリア構造を使用して、このコードによって引き起こされる 2 つのポリゴン部分を計算します。 2 つの部分のうち大きい方を選択し、答えを更新します。 
7. すべてのエッジ方向に対して繰り返し、最大有効ピース面積を 2 倍して出力します。 

### なぜ効果があるのか

 凸多角形により、任意の方向の極点が船体に沿って単調な順序で表示されます。 これにより、エッジに対応する離散イベントの場合にのみ候補サポート ラインのセットが変化します。 制約は固定点までの距離のみに依存するため、最適なカットは、実現可能性や領域の最適性を失うことなく、サポート ラインになるまで継続的に回転できます。 したがって、最適なソリューションを取得するには、これらのイベントの方向のみをチェックするだけで十分であり、キャリパーを回転させることで、各方向が償却定数時間で処理されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def dot(ax, ay, bx, by):
    return ax * bx + ay * by

def area2(poly):
    n = len(poly)
    s = 0
    for i in range(n):
        x1, y1 = poly[i]
        x2, y2 = poly[(i + 1) % n]
        s += cross(x1, y1, x2, y2)
    return abs(s)

def line_dist2(x1, y1, x2, y2, cx, cy):
    # distance from point to line squared * |ab|^2 form avoided here
    # we only need comparison, so we compute raw cross magnitude
    dx = x2 - x1
    dy = y2 - y1
    return abs(cross(dx, dy, cx - x1, cy - y1))

def main():
    T = int(input())
    for _ in range(T):
        xc, yc, r = map(int, input().split())
        n = int(input())
        poly = [tuple(map(int, input().split())) for _ in range(n)]

        total = area2(poly)

        # rotating calipers pointers for antipodal points
        j = 1
        best = 0

        def subarea(i, j):
            # area of chain i -> j
            s = 0
            k = i
            while k != j:
                nx = (k + 1) % n
                x1, y1 = poly[k]
                x2, y2 = poly[nx]
                s += cross(x1, y1, x2, y2)
                k = nx
            return abs(s)

        for i in range(n):
            ni = (i + 1) % n
            while True:
                nj = (j + 1) % n
                # compare distance of line i-j to center vs i-nj
                if line_dist2(poly[i][0], poly[i][1], poly[nj][0], poly[nj][1], xc, yc) > \
                   line_dist2(poly[i][0], poly[i][1], poly[j][0], poly[j][1], xc, yc):
                    j = nj
                else:
                    break

            # check validity of line i-j
            dx = poly[j][0] - poly[i][0]
            dy = poly[j][1] - poly[i][1]
            if abs(cross(dx, dy, xc - poly[i][0], yc - poly[i][1])) >= r * (dx * dx + dy * dy) ** 0.5:
                # compute two pieces
                s1 = subarea(i, j)
                s2 = total - s1
                best = max(best, s1, s2)

        print(best)

if __name__ == "__main__":
    main()
```この解決策は、移動する対蹠頂点を維持するためにキャリパーを回転させることに依存しています。`j`それぞれに`i`、それらの間の線の方向が円の中心に対して可能な限り極端になるようにします。 面積の計算は、ポリゴンの境界に沿って外積を累積するヘルパーに分割され、チェーンの符号付き面積の 2 倍が直接得られます。 

幾何学的妥当性チェックでは、円の中心から直線までの垂直距離と半径が比較され、明示的な除算を避けるために外積によって実装されます。 

一般的な実装上の落とし穴は、ポリゴン チェーンを抽出するときに、符号付き領域と符号なし領域が混在することです。 からの方向`i`に`j`反時計回りの順序と一致している必要があります。 そうしないと、2 つの部分のうちの 1 つが誤って計算されるか、二重にカウントされます。 

## 実用的な例

 円の中心が中央付近にある単純な凸状の四角形を考えてみましょう。 キャリパーが 1 つのエッジ方向から次のエッジ方向に移動すると、対蹠点が`j`単調に前進します。 

| ステップ | 私 | j | 有効な行 | ピース領域 (チェーン i→j) | ベスト |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 2 | はい | 12 | 12 |
 | 1 | 1 | 3 | はい | 15 | 15 |
 | 2 | 2 | 0 | いいえ | スキップしました | 15 |

 この表は、各エッジ方向がどのように分割候補を生成し、有効なラインのみが答えに寄与するかを示しています。 対蹠点ポインタの移動により、各ペアが 1 回だけ考慮されることが保証され、冗長な再計算が防止されます。 

次に、頂点を通るすべての線が円と交差する場合を考えてみましょう。 この場合、すべての距離チェックが失敗するため、更新は行われず、答えはゼロのままになります。 これは、パイナップルを含まない部分が存在しないという要件と一致します。

 ## 特殊なケース

 最初のエッジ ケースは、すべてのコードが円と交差する場合です。 この状況では、すべての候補方向について距離チェックが失敗するため、答えの更新は実行されず、出力は正しくゼロのままになります。 

2 番目のエッジ ケースは、円が支持線に正確に接する場合に発生します。 アルゴリズムでは、これはしきい値と正確に等しい外積距離に対応します。 チェックは以上または等しい比較で記述されているため、接線は有効なものとして受け入れられ、結果の分割は引き続き通常どおり評価されます。 

3 番目のエッジ ケースは、複数の頂点が同一線上にある場合に発生します。 多角形が凸面のままであっても、連続するエッジが同じ線上にある場合があります。 支持方向が同一直線上で変化しないため、キャリパーは引き続き正しく前進します。そのため、ポインタの動きは単調なままで頂点を再訪しません。
