 ## 解決策
 ## 問題の理解

 左から右に読むと、すべてのプレフィックスの XOR が厳密に正になるように、0 から n マイナス 1 までの数値の順列を構築するように求められます。 つまり、各要素を配置した後、それまでに配置されたすべての累積 XOR を計算します。この実行値はどの時点でもゼロになることはできません。 

この制約を満たすすべての順列の中で、辞書編集的に最小のものを出力する必要があります。 つまり、XOR 条件を尊重しながら、最初の位置をできるだけ小さくすることを優先し、次に 2 番目の位置というようになります。 

入力は複数の独立したテスト ケースで構成されます。 各テスト ケースについて、1 つの順列のみを出力するか、それが不可能であると宣言します。 

テスト ケースにわたるすべての n の合計が最大 100 万であるという制約は、解が要素ごとに線形または対数線形に近くなければならないことを意味します。 すべての順列を試したり、注意深いデータ構造を持たずに大規模な配列に対して繰り返しスキャンを実行したりするなど、二次関数はすべてすぐに失敗します。 

建設の最初の段階で微妙な問題が発生します。 最初のプレフィックス XOR は単純に p0 であるため、p0 はゼロ以外でなければなりません。 これにより、最初の要素として 0 を選択することはすでに除外されています。 2 番目の微妙な点は、これまで有効なプレフィックス XOR を維持していたとしても、将来の要素を選択すると XOR が即座にゼロに戻される可能性があることです。 残りの番号が利用可能かどうかを考えずに現在のプレフィックスだけをチェックすると、この状況は見落とされやすくなります。 

たとえば、現在のプレフィックス XOR が値 x に等しく、x に等しい唯一残っている未使用の数値が選択されようとしている場合、それを選択すると、プレフィックス XOR はすぐにゼロになります。 未使用の最小値を常に取得する単純な貪欲なアプローチは、そのシナリオでは失敗します。 

## アプローチ

 ブルート フォース ソリューションでは、すべての順列を試し、それがプレフィックス XOR 条件を満たすかどうかを確認します。 各順列について、すべての接頭辞 XOR を計算するには O(n) が必要で、n 個の階乗順列が存在します。これは、n が 10 という小さい場合でも完全に実行不可能です。 

もう少し合理的な強引なアイデアはバックトラックです。順列を段階的に構築し、各段階で未使用の数値をすべて試し、現在の XOR を維持します。 これでも、最初のステップでは n 個の選択肢が分岐し、2 番目のステップでは n マイナス 1 が分岐し、階乗増加が得られます。 多くのブランチでは早い段階で制約に違反しますが、最悪の場合、深いレベルに達するまで枝刈りは行われないため、複雑さは指数関数的なままになります。 

重要な点は、ステップ i でプレフィックス条件を破る唯一の方法は、実行中の XOR がゼロになる場合であるということです。 これは、選択した数値が現在の XOR 値と等しい場合に正確に発生します。これは、v が x に等しい場合にのみ、x XOR v がゼロに等しいためです。 これにより、有効性チェックが非常にローカルなルールに変わります。必要なのは、現在の XOR に等しい数値の選択を回避することだけです。 

これが見えてくると構築も貪欲になってきます。 各ステップで、現在の XOR と等しくない、使用可能な最小の数値が必要です。 これにより、自然に辞書編集上最小の有効なシーケンスが生成されます。これは、より小さい数を遅延させようとすると、辞書編集上の最小性に違反するか、禁止されている XOR ゼロ遷移が強制されるためです。 

残る唯一の課題は、禁止値を 1 つだけスキップしながら、未使用の最小の数値を効率的に見つけられるようにすることです。 インデックスに対する素セット構造では、ほぼ一定時間内に次に利用可能な数値を維持できるため、最小の有効な候補を繰り返し選択できます。

 ## アルゴリズムのチュートリアル

実行中の XOR 値 x と、未使用の数値を追跡する構造を維持します。 また、「次に利用可能な」クエリも維持されているため、未使用の最小番号を常に効率的に取得できます。 

1. 答えを空として初期化し、0 から n から 1 を引いた値までのすべての数値を未使用としてマークし、x をゼロに設定します。 
2. 0 から n マイナス 1 までの位置 i ごとに、可能な限り小さい未使用の数値 v を選択しようとします。 
3. 0 から始まる最小の未使用数値をクエリします。その候補が x に等しい場合、それを一時的にスキップし、代わりに、厳密に x より大きい次の未使用数値をクエリします。 
4. このステップで有効な候補が存在しない場合、つまり、残りの未使用のすべての数値が v を x に等しくすることを意味し、構築は不可能であると結論付けます。 
5. v を選択したら、それを答えに追加し、未使用の構造から削除して、x を x XOR v に更新します。 

重要な技術的な作業はステップ 3 と 4 の中にあります。どのステップでも唯一禁止されている選択は、プレフィックス XOR をキャンセルする値です。 他の未使用の番号は、プレフィックスの状態という点では安全です。 

### なぜ効果があるのか

 いかなる瞬間においても、制約に違反する唯一の方法は、実行中の XOR をゼロにすることです。 次の要素を選択する前に実行される XOR は固定されているため、この失敗を引き起こす可能性があるのは 1 つの候補、つまり現在の XOR 値自体だけです。 したがって、各ステップには最大 1 つの禁止値が含まれます。 

常に最小の有効な数値が選択されるため、辞書編集上の最小性がローカルに適用されます。 制約の構造により、将来の決定が現在の XOR と残りの数値プール以外のものに依存しないことが保証されるため、各位置を貪欲に最小化しても、そのステップで有効な選択が存在する限り、有効な完了をブロックすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.n = n
        self.parent = list(range(n + 1))

    def find(self, x):
        while x <= self.n and self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def remove(self, x):
        self.parent[x] = self.find(x + 1)

def solve():
    n = int(input())
    if n == 1:
        print("impossible")
        return

    dsu = DSU(n)
    res = []
    x = 0

    for i in range(n):
        v = dsu.find(0)

        if v == x:
            v = dsu.find(x + 1)

        if v > n - 1:
            print("impossible")
            return

        res.append(v)
        dsu.remove(v)
        x ^= v

    print(*res)

t = int(input())
for _ in range(t):
    solve()
```DSU 構造は、「次に使用可能な要素」ポインターとして使用されます。 値を削除すると、その値が次の候補にリンクされるため、今後のクエリでは自動的にその値がスキップされます。 

重要な微妙な点は、各ステップでの二重クエリです。 最初に、未使用の最小の数値を試します。 その数値が現在の XOR と一致することによってプレフィックス条件を即座に破棄する場合は、その次に使用可能な候補に直接ジャンプします。 これにより、制約を尊重しながら辞書編集上の最小性が保証されます。 

不可能性チェックは、2 番目の候補さえ存在しない場合に行われます。つまり、残りのセットでは禁止された XOR 一致が強制されます。 

## 実用的な例

 n が 3 で、使用可能な数値が 0、1、2 である小さなケースを考えてみましょう。 

x が 0 であることから始めます。 

| ステップ | Available set | Chosen v | Running XOR x |
 | --- | --- | --- | --- |
 | 1 | {0,1,2} | 1 | 1 |
 | 2 | {0,2} | 0 | 1 |
 | 3 | {2} | 2 | 3 |

 最初のステップの後、0 を選択するとプレフィックス XOR がすぐにゼロになるため、それをスキップして 1 を選択します。その後、残りの選択肢はすべて安全です。 

このトレースは、禁止された値が常に正確に現在の XOR であること、およびそれをスキップすることで実現可能性がどのように維持されるかを示します。 

Now consider n equals 2.

 | ステップ | Available set | Chosen v | Running XOR x |
 | --- | --- | --- | --- |
 | 1 | {0,1} | 1 | 1 |
 | 2 | {0} | 0 | 1 |

 これは、0 から始まることが無効である最小の場合でも、辞書編集上最小の有効な順列を示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    class DSU:
        def __init__(self, n):
            self.n = n
            self.parent = list(range(n + 1))

        def find(self, x):
            while x <= self.n and self.parent[x] != x:
                self.parent[x] = self.parent[self.parent[x]]
                x = self.parent[x]
            return x

        def remove(self, x):
            self.parent[x] = self.find(x + 1)

    def solve():
        n = int(input())
        if n == 1:
            return "impossible"
        dsu = DSU(n)
        res = []
        x = 0
        for i in range(n):
            v = dsu.find(0)
            if v == x:
                v = dsu.find(x + 1)
            if v > n - 1:
                return "impossible"
            res.append(str(v))
            dsu.remove(v)
            x ^= v
        return " ".join(res)

    t = int(input())
    out = []
    for _ in range(t):
        out.append(solve())
    return "\n".join(out)

# provided samples (format assumed consistent)
assert run("1\n1\n") == "impossible"
assert run("1\n2\n") in ["1 0", "1 0"]

# custom cases
assert run("1\n3\n") == "1 0 2"
assert run("1\n4\n")  # should produce a valid permutation implicitly
assert run("2\n1\n2\n") == "impossible\n1 0"

 ## 特殊なケース

 n が 1 の場合、唯一の順列は [0] です。 The first prefix XOR is already zero, which violates the requirement immediately, so the algorithm correctly returns impossibility before any construction begins.

 n が 2 に等しい場合、現在の XOR は 0 から始まるため、最初のステップで 0 を選択することは禁止されます。 したがって、アルゴリズムは最初に 1 を選択し、残りの数値 0 が追加されます。 最終的な XOR はゼロ以外のままであるため、条件は両方のプレフィックスに当てはまります。 

現在の XOR がたまたま最小の未使用数値と一致するような大きなケースでは、DSU は次の候補に直接スキップします。 This ensures that the greedy choice does not accidentally pick the forbidden value, and it preserves lexicographic order by only skipping when absolutely necessary.
