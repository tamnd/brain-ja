 ## 解決策
 ## 問題の理解

 課題は、幽霊も同じ建物内を同じ速度で移動していることを考慮して、ハリーが建物内のどの出口の部屋に安全に到達できるかを判断することです。 

家を、部屋がノード、ドアがエッジである無向グラフとして見ることができます。 ハリーは決まった部屋からスタートしますが、出口としてマークされた部屋がいくつかあります。 同時に複数の幽霊がそれぞれの部屋から出発します。 毎秒、ハリーは端に沿って隣の部屋に移動することができ、すべてのゴーストも同じことができます。 動きは離散的なステップで同時に発生します。 

ハリーが幽霊と同時に部屋を占有しないようにしながら、出口に到達できれば、その出口は安全であるとみなされます。 どちらも同じ速度で移動し、最適な経路を選択できるため、ハリーと最も近いゴーストが各部屋にどれくらい早く到達できるかを効果的に比較することになります。 

この制約では、最大 200,000 の部屋と 200,000 のエッジが許可されており、出口ごとに最短経路を個別に再計算したり、時間の経過に伴う動きをシミュレートしたりするアプローチは即座に除外されます。 ソリューションは、少数の線形または線形に近いグラフ走査 (通常は O(n + m)) に依存する必要があります。 

ハリーと同時に幽霊が部屋に到着する可能性がある場合、微妙な失敗例が表示されます。 たとえば、ハリーが 3 秒で部屋に到着し、幽霊も 3 秒でその部屋に到着した場合、ハリーは同じタイム ステップで同じ部屋を占有しているため、そこでは安全ではないと考えられます。 

もう 1 つの重要なエッジ ケースは、ハリーがすでに幽霊がいる部屋からスタートする場合です。 その場合、時間 0 で両方が同じ部屋を占有しているため、開始位置は生存するには直ちに無効になります。 

最後に、出口にはハリーが最初から到達できない部屋が含まれる場合があります。 そのような出口は、ハリーがまったく到達できないため、自動的に安全ではなくなります。 

## アプローチ

 この問題を直接考える方法は、ハリーとすべての幽霊の両方を時間の経過とともにシミュレーションすることです。 マルチエージェント BFS を試みたり、毎秒シミュレートしてすべてのエンティティの位置を追跡したりすることができます。 各ステップで各ゴーストがグラフ内で分岐し、同じ状態を繰り返し探索することになるため、これはすぐに実行不可能になります。 最悪の場合、これは各エンティティおよび各タイム ステップでサイズ O(n + m) の繰り返し走査に変質し、限界をはるかに超える指数関数的または少なくとも O(k(n + m)) の動作につながります。 

より構造化されたアプローチは、各部屋にとって重要なのは、たどった正確な経路ではなく、ハリーと幽霊がそこに到着できる最も早い時刻であることを観察することです。 ハリーの開始ノードからすべての部屋までの最短距離を計算し、ゴーストの開始位置からすべての部屋までの最短距離を個別に計算すると、問題は出口部屋ごとの単純な比較に減ります。 

重要な洞察は、すべてのゴーストが同時に独立して移動するため、すべてのゴーストの開始位置を単一のマルチソース BFS 内のソースとして扱うことで、その影響を組み合わせることができるということです。 これにより、すべての部屋について、幽霊がその部屋に住み着くことができる最も早い時間がわかります。 ハリーの BFS は彼の最も早い到着時間を示します。 どちらも 1 秒ごとに 1 歩ずつ移動するため、ハリーが部屋の中で安全なのは、幽霊が到達する前に厳密に到着した場合のみです。 

これにより、問題全体が同じグラフに対する 2 つの BFS 走査に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(k · (n + m)) またはそれ以上 | O(n + m) | 遅すぎる |
 | デュアルマルチソースBFS | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 グラフ上で 2 つの距離マップを計算することで問題を解決します。 

## アルゴリズムのチュートリアル

 1. 指定されたエッジからグラフの隣接リストを作成します。 これにより、接続されているすべての部屋を効率的に移動できます。 
2. すべてのゴースト位置からマルチソース BFS を一度に実行します。 距離配列を初期化する`distG`ここで、0 に設定されているゴースト開始部屋を除き、すべての値は無限大です。すべてのゴースト ソースから同時に拡張すると、自然に最速の拡散がシミュレートされるため、この BFS は、ゴーストが各部屋に到達できる最も早い時間を計算します。 
3. ハリーの開始部屋から標準的な BFS を実行します`s`別の距離配列を計算するには`distH`、ハリーが各部屋に到着できる最も早い時間を表します。 
4.各出口室ごと`e_i`、どうかを確認してください`distH[e_i]`厳密に以下です`distG[e_i]`。 「はい」の場合、ハリーは幽霊がその部屋を占拠する前に到着できるので、安全です。 そうしないと安全ではありません。 
5. この条件を満たすすべての出口部屋を数え、合計を出力します。 

厳密な不平等が重要な理由は、同時に到着すると安全ではないからです。 両方の距離が等しい場合、ハリーが到着すると同時に幽霊が部屋を占拠する可能性があり、安全条件に違反します。 

### なぜ効果があるのか

 各 BFS は、重み付けされていないグラフ内の最短経路距離を計算します。これは、単位移動コストの下での最小時間に正確に対応します。 ゴーストとハリーは同じ速度で移動し、衝突以外の相互作用はしないため、最も早い到着時間がその位置を安全に占領できるかどうかを完全に特徴づけます。 不変条件は、BFS の最後で、`distG[v]`幽霊が部屋に到達できる最小時間です`v`、 そして`distH[v]`ハリーが到達できる最短時間です`v`。 両方のプロセスがすべての最適なパスを並行して探索するため、BFS の記録よりも早く到着することはできません。 したがって、これら 2 つの値を比較することは、ハリーが各出口まですべてのゴーストを厳密に追い越せるかどうかを確認することと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

INF = 10**18

def bfs(starts, adj, n):
    dist = [INF] * (n + 1)
    q = deque()
    for s in starts:
        dist[s] = 0
        q.append(s)

    while q:
        v = q.popleft()
        for to in adj[v]:
            if dist[to] == INF:
                dist[to] = dist[v] + 1
                q.append(to)
    return dist

def solve():
    n, m, s, k, g = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    exits = list(map(int, input().split()))
    ghosts = list(map(int, input().split()))

    distH = bfs([s], adj, n)
    distG = bfs(ghosts, adj, n)

    ans = 0
    for e in exits:
        if distH[e] < distG[e]:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、ハリーとゴーストの両方に共有 BFS ルーチンを使用します。 唯一の違いは初期化です。Harry の BFS は単一ノードから開始されますが、ゴースト BFS は複数のソースから同時に開始されます。 

微妙な点は、距離を大きなセンチネル値に初期化することです。これにより、未訪問のノードが実質的に到達不能のままになります。 到達不可能なゴーストノードがハリーの到達を妨げてはいけないため、これは距離を比較するときに重要です。 

厳密な比較`distH[e] < distG[e]`同時性制約を直接エンコードします。 

## 実用的な例

 ### サンプル 1

 ハリーと幽霊からの距離を計算し、出口で比較します。 

| ステップ | 出口での distH | 出口での distG | 決定 |
 | --- | --- | --- | --- |
 | ハリーからのBFS | 計算された最短時間 | - | - |
 | ゴーストからのBFS | - | 計算された最短時間 | - |
 | 比較 | 2 | 3 | 安全 |

 ハリーはどの幽霊よりも厳密に早く出口に到着するため、出口は有効なものとしてカウントされます。 これは、ハリーがすべての幽霊の道の先を行くことに成功したケースを示しています。 

### サンプル 2

 | ステップ | 出口での distH | 出口での distG | 決定 |
 | --- | --- | --- | --- |
 | ハリーからのBFS | 2 | - | - |
 | ゴーストからのBFS | - | 2 | 安全でない |
 | 比較 | 2 | 2 | 拒否されました |

 ここでは、幽霊がハリーと同時に出口に到達する可能性があります。 ハリーには道があっても、同時性の条件により出口は安全ではありません。 これは、厳密な不平等が必要な理由を強調しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 2 つの BFS トラバーサルは、それぞれすべてのノードとエッジを最大 1 回処理します。 
| スペース | O(n + m) | 隣接リストと距離の配列 |

 ## 特殊なケース

 幽霊の発生源でもある部屋でハリーが出発したときに、重要なエッジケースが発生します。 その状況では、ゴースト BFS は開始ノードに距離 0 を割り当て、Harry の BFS も 0 を割り当てます。比較はすぐに失敗するため、そのノードに留まるか通過する必要がある出口は安全ではありません。 平等は許されないため、アルゴリズムはこれを自然に処理します。 

別のケースは、出口がハリーとすべての幽霊の両方から切断されている場合です。 ハリーの距離は無限大になり、ゴーストの距離も無限大になります。 この条件では厳密な不等式が必要であるため、無限大は無限大未満ではなく、ハリーがまったく到達できないため、出口は安全ではないと正しくマークされます。 

最後に、複数のゴーストが存在する場合、マルチソース BFS は、優先するゴーストからの最小到着時間を保証します。 これにより、ゴーストが個別に処理された場合に、一見安全に見える出口が無効になってしまう、より高速なゴースト パスを見逃すことがなくなります。
