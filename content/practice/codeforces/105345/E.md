 ## 解決策
 ## 問題の理解

 私たちには数種類のキャンディーが与えられますが、それぞれの種類には供給量が限られており、1 個あたりの美味しさが固定されています。 チャーリーは限られた日数にわたってキャンディーを食べることができますが、毎日 2 つの制約があります。1 日あたりのキャンディーの数が決まっていることを超えてはいけないこと、および 1 日に同じ種類のキャンディーを 2 つ食べてはいけないことです。 すべてのキャンディーは締め切り日までに食べなければなりません。目標は、総合的な美味しさを最大限に高めることです。 

これは古典的な「間隔」の意味でのスケジューリングの問題ではなく、むしろ 1 日あたりの容量とタイプごとの 1 日あたりの排他性制約を伴うリソース割り当ての問題です。 毎日は、最大でも受け入れることができる境界のあるコンテナのように動作します。`x`異なるタイプがあり、選択したタイプごとに、その日に最大 1 つのユニットを取得できます。 

制約から、`n`そして`d`どちらも最大 200,000 であるため、毎日の割り当てをシミュレートしたり、1 日あたりすべてのタイプを繰り返しスキャンしようとしたりするソリューションは、すぐに遅すぎます。 単純な 1 日あたりの貪欲な構築では、次のような結果が得られます。`O(n d)`さらに悪いことに、10^10 の演算規模ではまったく実現不可能です。 

重要な構造上の観察は、グローバルな 1 日の上限を除いて、各タイプが独立して動作するということです。 難しいのは、高価なキャンディーが生産能力の制約によってブロックされないように、各タイプの出現を日をまたがって分散する方法を決定することです。 

日数は少ないが、タイプごとのスタックが非常に多い場合、微妙なエッジ ケースが発生します。 もし`d = 1`, その場合、キャンディーの数に関係なく、各種類から最大 1 つのキャンディーしか取ることができません。 「1 日あたりタイプごとに最大 1 つ」という制約を無視した単純な解決策では、誤ってすべてのデータが取得されてしまいます。`k_i`最も価値のあるタイプのコピーですが、これは不可能です。 

次の場合には、別のエッジケースが発生します。`x ≥ n`。 この場合、1 日あたりの制限は実質的になくなり、1 日あたり最大で 1 種類につき 1 つ摂取できるため、唯一の制約は次のようになります。`d`日、つまり各タイプが最大で寄与することを意味します`min(k_i, d)`コピー。 「毎日を貪欲に埋めよう」とする単純なアプローチは、このケースを複雑にしすぎて、間違ったスケジュールを設定する危険性があります。 

## アプローチ

 直接的な総当たり戦略では、毎日シミュレーションが行われます。 毎日、在庫がまだ残っており、その日は使用されていない、入手可能な最高のキャンディーの種類を繰り返し選択します。`x`キャンディーがなくなるか、有効な種類がなくなってしまいます。 その後、カウントを減らして次の日に進みます。 

このアプローチは常に局所的な制約を尊重するため、概念的には正しいです。 ただし、その複雑さは、利用可能な最適なタイプを繰り返し選択することによって決まります。 優先構造があっても、最大で挿入および削除することになります。`O(k_i)`アイテムの合計とパフォーマンス`d * x`選択。 最悪の場合、両方とも20万人となり、数百億規模の運用につながる。 

重要な洞察は、視点を逆転させることです。 キャンディーを日にちに割り当てる代わりに、制約を考慮した上で、実際に各タイプの最大何コピーを使用できるかを尋ねます。 

各キャンディーの種類`i`1 日に最大 1 つのスロットに出現できるため、タイプから取得できるコピーの最大数は`i`によって制限されています`d`。 別途、その可用性を超えることはできません`k_i`。 したがって、タイプごとの本当の上限は次のとおりです。`min(k_i, d)`。 

残りの制約は、1 日あたり最大で`x`異なるタイプ。つまり、一日を通して合計容量があることを意味します。`d * x`「スロット」。 選択したキャンディーはそれぞれ 1 つのスロットを正確に占有し、残りの問題はどのキャンディーでそれらのスロットを埋めるかだけです。 

したがって、問題は次のようになります。 タイプごとに`i`、私たちはせいぜい`min(k_i, d)`コピー、それぞれの価値`c_i`、そして私たちはせいぜい選択する必要があります`d * x`項目を合計して値の合計を最大化します。 これは、タイプごとにアイテム数が統一されている単なるナップザックのような選択であり、値による並べ替えに折りたたまれます。 

各タイプを次の重みに展開します。`min(k_i, d)`価値のある同一のアイテム`c_i`, しかし、明示的には拡張しません。 代わりに、タイプを次の基準で並べ替えます。`c_i`そして、私たちが到達するまで、できるだけ多くの人を彼らの能力まで貪欲に受け入れます`d * x`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(d · x · log n) 最悪の場合 | O(n) | 遅すぎる |
 | 並べ替え + 貪欲な割り当て | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各キャンディー タイプが貢献できる最大回数を計算します。 タイプについて`i`、これは`min(k_i, d)`。 これは、コピー数が多くても、1 日に複数枚しか使用できないという事実を反映しています。 
2. 各タイプを、同一の高価値アイテムのバンドルに寄与するものとして解釈します。バンドルのサイズは次のとおりです。`min(k_i, d)`そしてそれぞれのアイテムには価値がある`c_i`。 
3. 全日にわたる利用可能なスロットの合計数を次のように計算します。`d * x`。 これは、チャーリーが消費できるキャンディーの絶対最大数です。 
4. すべてのキャンディーの種類を美味しさ順に並べ替えます`c_i`降順で。 これにより、最も価値のあるキャンディ タイプを常に最初に考慮することが保証されます。これは、容量による以外にタイプ間に相互作用がないため、必要です。 
5. ソートされたタイプを反復処理し、タイプごとにできるだけ多くのコピーを取得しますが、そのバンドル・サイズと残りのグローバル容量の両方を超えないようにしてください。 貢献度を答えに蓄積し、それに応じて残りの容量を減らします。 
6. グローバル容量がゼロになると、それ以上キャンディーを消費できないため、早めに停止します。 

### なぜ効果があるのか

 このアルゴリズムは、グローバル交換引数に依存します。 おいしさのより低いキャンディを使用する一方で、よりおいしいキャンディのために利用可能な容量を残すソリューションは、制約に違反することなくそれらを交換することで改善できます。 各タイプの1日あたりの制限はすでに吸収されているため、`min(k_i, d)`上限に達すると、残りのすべての決定は独立した項目の選択になります。 おいしさを減らすことによる貪欲な順序により、すべてのスロットが利用可能な残りの最良のオプションで満たされることが保証され、未使用の候補はすべてそれよりも低いか等しい値を持つため、後で置き換えても結果を改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d, x = map(int, input().split())
    k = list(map(int, input().split()))
    c = list(map(int, input().split()))

    items = []
    for i in range(n):
        items.append((c[i], min(k[i], d)))

    items.sort(reverse=True)

    cap = d * x
    ans = 0

    for val, cnt in items:
        if cap == 0:
            break
        take = min(cnt, cap)
        ans += take * val
        cap -= take

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、各キャンディ タイプを有効な使用可能な数に圧縮することから始まります。 重要な変革は置き換えです`k_i`と`min(k_i, d)`、これは、1 日あたりの一意性制約をタイプごとの制限に直接エンコードします。 

並べ替え順`c_i`選択順序が最適性と一致していることを保証します。 貪欲ループは、問題を固定数のスロットを埋めるものとして扱います。`d * x`利用可能な最高価値のユニットを使用します。 

微妙な点は、日数を明示的にシミュレートする必要がないことです。 日々の構造は、`min(k_i, d)`キャップと総容量。 それが完了すると、問題はすべての時間構造を失います。

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(n log n) | 美味しさによる種類の分類が主流です。 その後単一の線形スイープ |
 | スペース | O(n) | 圧縮型リストを格納します |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, d, x = map(int, sys.stdin.readline().split())
    k = list(map(int, sys.stdin.readline().split()))
    c = list(map(int, sys.stdin.readline().split()))

    items = [(c[i], min(k[i], d)) for i in range(n)]
    items.sort(reverse=True)

    cap = d * x
    ans = 0
    for v, cnt in items:
        take = min(cnt, cap)
        ans += take * v
        cap -= take
        if cap == 0:
            break

    return str(ans)

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。`x = 1`。 そうすれば、毎日合計で最大 1 つのキャンディーを摂取することができ、「1 日に同じ種類のキャンディーを 2 つ禁止」という制約は意味がなくなります。 総容量が`d`、各タイプは最大で貢献します`min(k_i, d)`なので、単純に一番上を選択します`d`金額別のキャンディー全体。 

もう 1 つのエッジケースは次のような場合です`d = 1`。 ここでは、どのタイプも最大 1 つのキャンディーを提供するため、問題は最大 1 つのキャンディーを選択することになります。`x`最も価値の高いタイプ。 このアルゴリズムは自然に次のような並べ替えに帰着します。`c_i`そしてトップを取る`x`アイテム。 

3 番目のケースは次の場合です。`x ≥ n`。 そうすれば、毎日すべてのタイプに対応でき、唯一の制限は日数だけです。 各タイプは最大で取得できます`min(k_i, d)`アルゴリズムによってすでに強制されています。 グローバル容量のため、特別な処理は必要ありません。`d * x`タイプごとの上限が決定を支配するほど十分に大きくなります。
