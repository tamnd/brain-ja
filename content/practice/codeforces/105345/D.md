 ## 解決策
 ## 問題の理解

 私たちは建物の列を与えられ、それぞれの建物に何人かの学生が住んでいます。 フレディは常に最初の建物から開始し、厳密に右に移動します。 順番に建物を巡っていくうちに、これまでに見た生徒の数が溜まっていく。 

各クエリ値について、単純な論理的な質問が尋ねられます。つまり、フレディが遭遇した生徒の総数がそのクエリ値以上になるためには、最初からどこまで進む必要があるかということです。 すべての建物を訪問しても合計がクエリよりも小さい場合は、回答は不可能です。 

キー オブジェクトは、配列のプレフィックスの累積です。 すべてのクエリは、合計が目標に達するかそれを超える最小のプレフィックス長を要求します。 

この制約により、線形または線形に近い前処理が必要になります。 最大 100,000 の建物と 100,000 のクエリでは、クエリごとに合計を再計算するソリューションは失敗します。 二重ループでは、最悪の場合、10^10 回の操作が発生し、1 秒の制限をはるかに超えます。 

クエリで生徒数がゼロの場合、微妙なエッジ ケースが発生します。 この場合、フレディは建物に入る前にすでに要件を満たしているため、答えは建物がゼロになるはずです。 もう 1 つのケースは、建物にゼロが含まれている場合です。これにより、プレフィックスの合計が変化しない長い範囲が作成される可能性があります。 進歩は新しい建物を訪問することに結びついていないため、単純な「合計が増えたら停止する」というアプローチはここで破綻します。 

## アプローチ

 直接的なアプローチでは、各クエリを個別に処理します。 与えられたターゲット q に対して、最初の建物から歩くことをシミュレートし、合計が q に達するまで生徒数を追加し続けます。 これは正確な移動ルールに従っているため、これは正しいです。 ただし、各クエリでは、ほぼすべての建物をスキャンする必要がある場合があります。 m 個のクエリの場合、これは O(nm) になり、n と m の両方が大きい場合には遅すぎます。 

問題の構造は単調です。 右に移動しても、プレフィックスの合計は減少しません。 この単調性は、プレフィックスの合計を事前に計算すると、各クエリがソートされた (減少しない) 配列に対する検索問題になることを意味します。 すべてのクエリを再シミュレートする代わりに、必要なしきい値に達する最初のプレフィックス合計を特定することで、それぞれのクエリに答えることができます。 

これにより、タスクがプレフィックス合計配列のバイナリ検索に減ります。 各クエリは、単一の線形前処理パスの後、対数時間で応答されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | プレフィックス合計 + 二分検索 | O(n + m log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 建物配列のプレフィックスの合計を計算します。 位置 i の値は、建物 1 から建物 i までの学生の総数を表します。 これにより、問題は各ステップが減少しない単調配列に変換されます。 
2. 各クエリ値 q について、それが最後のプレフィックスの合計を超えているかどうかを確認します。 存在する場合、要件を満たすプレフィックスがないため、答えは -1 になります。 これにより、不必要な検索が回避されます。 
3. q が 0 の場合、学生をゼロにするために建物は必要ないため、すぐに 0 を返します。 
4. それ以外の場合は、プレフィックス合計配列に対して二分検索を実行して、prefix[i] が q 以上となる最小のインデックス i を見つけます。 これは、プレフィックス配列が非減少でソートされているため機能します。 
5. ゼロベースのインデックスを内部で使用する場合、答えは訪問した建物の数で定義されるため、i + 1 を出力します。 

### なぜ効果があるのか

正確さは、接頭辞の合計の単調性から得られます。 プレフィックスの合計が特定の値に達すると、それ以降のすべてのプレフィックスは少なくとも同じ大きさになります。 これにより、有効な回答のセットが連続したインデックスの接尾辞を形成することが保証されます。 二分探索は、有効な答えが合計が不十分なすべての位置の右側、およびすでに十分であることが確認されたすべての位置の左側に存在する必要があるという不変条件を維持しながら、検索空間を繰り返し半分にすることによって、まさにこの構造を利用します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import bisect

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    q = list(map(int, input().split()))
    
    pref = []
    s = 0
    for x in a:
        s += x
        pref.append(s)
    
    total = pref[-1] if pref else 0
    
    out = []
    for x in q:
        if x == 0:
            out.append("0")
            continue
        if x > total:
            out.append("-1")
            continue
        idx = bisect.bisect_left(pref, x)
        out.append(str(idx + 1))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は、建物上の単一パスでプレフィックス合計配列を構築することから始まります。 これにより、O(n) の前処理が保証されます。 

各クエリは独立して処理されます。 エッジ ケース x == 0 は、検索前に明示的に 0 として返され、建物が必要ないという定義と一致します。 

キー操作は、`bisect_left`、プレフィックスの合計がクエリ値以上である最初の位置を見つけます。 1 を追加すると、0 から始まるインデックスが建物の数に変換されます。 

合計合計チェックにより、クエリが到達可能な学生全員を超える場合に、不必要なバイナリ検索が防止されます。

 ## 特殊なケース

 入力のようなゼロクエリケース`[5, 2, 3]`クエリ付き`0`すぐに戻ります`0`プレフィックス合計条件は、建物を訪問する前にすでに満たされているためです。 アルゴリズムは検索を構築する前にこれを処理するため、インデックス付けは実行されません。 

次のようなすべてゼロの配列`[0, 0, 0]`プレフィックスの合計を生成します`[0, 0, 0]`。 のようなクエリの場合`1`、バイナリ検索は最初のインデックスを返しますが、合計はまだゼロであるため、事前チェックは`x > total`正しく出力される`-1`。 これにより、ゼロの繰り返しを進行中と誤って解釈することがなくなります。 

合計に等しいクエリ (配列など)`[3, 1, 2]`そしてクエリ`6`、最後の接頭辞に正確に着地します。 二分検索は最終的なインデックスを返します。これより前のプレフィックスが合計に達しないため、答えは完全な長さになります。
