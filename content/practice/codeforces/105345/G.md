 ## 解決策
 ## 問題の理解

 迷路は小さなグリッドであり、各セルはサムの移動方法に影響を与える地形タイプのように動作します。 一部のセルは自由に通過でき、一部はブロックされ、一部にはリソースの制限が課されます。サムは、特定の障害物を通過するためにキャンディ コーンを収集する必要がある場合があります。 タスクは、開始セルから移動するのに必要な最小時間を計算することです。`S`出口セルへ`E`、または出口に到達することが不可能であると判断します。 

移動はグリッド上での標準的な 4 方向のステップであり、各移動にはちょうど 1 単位の時間がかかります。 複雑さは 2 つの特殊なタイル タイプから生じます。 キャンディコーン細胞`C`サムが持っているキャンディーの数が永久に増加します。 ジャック・オ・ランタン`J`サムが現在少なくとも 1 つの未使用のキャンディ コーンを持っている場合にのみ入力でき、それに入力すると 1 つ消費されます。 カボチャ`P`壁です。 

これにより、最短経路問題が状態を伴う最短経路に変わります。 集められたキャンディコーンの数が異なると同じセルに到達する可能性があるため、位置だけでは十分ではありません。将来の可能性も異なります。 キャンディ コーンの総数が最大 8 個であるという制約は、これを管理可能にする重要な構造上の制限です。 

グリッドは最大でも 100 × 100 なので、最大でも 10,000 個の位置があります。 キャンディ コーンは最大でも 8 であるため、正しい状態表現は、10,000 に 256 の可能なキャンディ ステートを乗算したオーダーの比較的小さいままであり、これでも最短パス検索には許容されます。 

キャンディーの状態を無視した単純なアプローチは、微妙な点で失敗します。 たとえば、サムが道路を通過しなければならない状況を考えてみましょう。`J`迂回路にあるキャンディコーンを回収して初めてタイルを取得できます。 セルの再訪問を不要なものとして扱うと、最適なパスを誤って破棄してしまう可能性があります。 

別の失敗例は、複数のキャンディ コーンが存在するが、一連のキャンディ コーンのロックを解除するのに必要なのは一部のみである場合に発生します。`J`タイル。 状態追跡を行わない貪欲なグリッド内最短パスのアプローチは、段階的により速く出口に到達する可能性がありますが、キャンディーが不十分で、後で行き詰まります。 

具体的な最小限の図:

 入力:```
1 5
S C J E
```正しい出力:```
3
```キャンディーの状態を無視する単純な BFS は、`C`もう一歩として、進んでみてください`S -> J -> E`、失敗したため`J`収集前に入力することはできません`C`。 

## アプローチ

 簡単な試みは、BFS を実行することです。`S`、各セルをグラフ内のノードとして扱います。 BFS は重み付けされていないグラフでの最短パスを保証するため、これはコストが均一で追加の制約がない単純なグリッドで機能します。 

エッジを横断する能力は動的リソース、つまり収集されたキャンディ コーンの数に依存するため、この問題はこの仮定を破ります。 これは、グラフが静的ではないことを意味します。 各グリッド位置は、考えられるキャンディ数ごとに 1 つずつ、複数の状態に効果的に拡張されます。 

強引な考え方は、各州を次のように扱うことです。`(row, col, mask or count of candies)`、タイルの種類に基づいてトランジションを許可します。 状態から 4 つの動きをすべて試し、踏んだ場合はキャンディーの数を更新します`C`、そして踏むことだけを許可します`J`キャンディカウントが正の場合。 これにより、最大で階層化されたグラフが生成されます。`n * m * 2^d`州。 

以来`d ≤ 8`、州の数は 10000 × 256 = 256 万によって制限されます。 各状態には最大 4 つの遷移があるため、約 1,000 万のエッジがあります。 これはすでに境界線に達していますが、効率的な BFS を備えた Python では許容されます。 

さらに注意深く見ると、すべての移動のコストが等しいため、BFS が依然として有効であることがわかります。 唯一の変更点は、位置は同じに見えるがリソースが異なる状態を誤ってマージしないように、訪問した構造にキャンディーの数を含める必要があることです。 

重要な観察は、キャンディ コーンの数が少なく、状態空間を乗算的に増加させるだけであるということです。 したがって、拡張された状態グラフで標準の 0-1 の重み付けされていない BFS を実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (状態を無視したグリッド BFS) | O(nm) | O(nm) | 不正解 |
 | 状態 BFS (位置 + キャンディ数) | O(nm · 2^d) | O(nm · 2^d) | 承認済み |

 ## アルゴリズムのチュートリアル

 各構成を、サムの位置と現在保持しているキャンディ コーンの数で構成されるトリプルとしてモデル化します。 目標は、有効なキャンディーの数を持って出口セルに到達することです。 

1. 開始位置を特定します`S`初期のキャンディー数をゼロとして扱います。 これにより、BFS の初期状態が確立されます。 
2. 次のコマンドでキューを初期化します。`(S_row, S_col, 0)`すべての状態に対して無限に初期化された距離配列。 距離は、各構成に到達するまでの最小時間を追跡します。 
3. 状態全体にわたって BFS を実行します。 状態をポップする`(r, c, k)`位置とキャンディーの数を表します。 
4. 4 つの方向のそれぞれについて、隣接セルを計算します。`(nr, nc)`。 範囲外かカボチャの場合`P`、通行不可なのですぐにスキップします。 
5. に移動するかどうかを決定します。`(nr, nc)`タイル タイプに基づいて許可されます。 そうであれば`J`、 必要とする`k > 0`。 許可されている場合は、キャンディーの数を 1 つ減らします。 これはキャンディ コーンの消費をモデル化しています。 
6. セルが`C`、移動後にキャンディーの数を増やします。 ジャック・オ・ランタンに入ると、そのセルでの潜在的な利益が考慮される前にキャンディーが消費されるため、この順序は重要です。 
7. 結果の状態が`(nr, nc, new_k)`これより短いか同じ距離で訪問されていない場合は、その距離を更新してキューに押し込みます。 
8. BFS が終了するか終了セルまで続行します。`E`に達します。 答えは、すべてのキャンディーの状態にわたる最小距離です。`E`。 

### なぜ効果があるのか

 すべての移動には均一のコストがかかるため、BFS では、状態が距離の減少しない順序で処理されることが保証されます。 唯一の複雑な問題は、異なるキャンディー数で同じグリッド セルに到達すると、根本的に異なる状態になることです。 キャンディー数を含めるように状態空間を拡張することで、古典的な BFS の不変式を復元します。つまり、状態がデキューされると、その正確な構成へのすべての可能なパスの中でその距離が最小になります。 すべての有効な遷移が調査されるため、どの状態への短いパスも見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]
    
    sr = sc = er = ec = -1
    
    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'S':
                sr, sc = i, j
            if grid[i][j] == 'E':
                er, ec = i, j
    
    max_mask = 1 << 8  # up to 8 candies
    
    dist = [[[10**9] * max_mask for _ in range(m)] for _ in range(n)]
    
    q = deque()
    dist[sr][sc][0] = 0
    q.append((sr, sc, 0))
    
    dirs = [(1,0), (-1,0), (0,1), (0,-1)]
    
    while q:
        r, c, k = q.popleft()
        d = dist[r][c][k]
        
        for dr, dc in dirs:
            nr, nc = r + dr, c + dc
            if nr < 0 or nr >= n or nc < 0 or nc >= m:
                continue
            
            cell = grid[nr][nc]
            nk = k
            
            if cell == 'P':
                continue
            
            if cell == 'J':
                if nk == 0:
                    continue
                nk -= 1
            
            if cell == 'C':
                nk += 1
                if nk >= 8:
                    nk = 7
            
            if dist[nr][nc][nk] > d + 1:
                dist[nr][nc][nk] = d + 1
                q.append((nr, nc, nk))
    
    ans = min(dist[er][ec])
    if ans == 10**9:
        print("SPOOKED!")
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、前述した状態の展開を直接反映しています。 三次元`dist`配列により、異なるキャンディー数を持つ状態がマージされなくなります。 各トランジションでは、キャンディーの状態を変更する前に、ジャック・オ・ランタン制約が慎重に適用されます。 

微妙な実装の詳細は、更新の順序です。入力時にキャンディーを減算します。`J`検討する前に`C`この問題定義では、セルを同時に両方に含めることはできないため、同じセルに含めます。 キャンディー数のクランプは正確さを保つために厳密には必要ありませんが、状態を 0 ～ 7 の範囲内に安全に制限します。

 ## 特殊なケース

 重要なエッジケースの 1 つは、キャンディーの蓄積が必要だがすぐには役に立たない場合です。 すべての直接ルートが含まれるパスを検討してください。`E`通り抜ける`J`セルを早期に収集し、収集に迂回を強いる`C`初め。 BFS は、貪欲な方向の選択を想定していないため、これを処理します。 到達可能なすべての州を探索するため、迂回路も当然含まれます。 

もう 1 つのケースは、サムが異なるキャンディー数で同じセルを再訪問できる場合です。 単純な訪問済み配列では再訪問が誤ってブロックされますが、状態ベースの BFS は次のように処理します。`(r, c, k1)`そして`(r, c, k2)`明確なため、後でより多くのキャンディーを持って訪問すると進行状況がロック解除される回復パスが可能になります。 

最後に、キャンディーが豊富だが不要な状況でも、過剰なキャンディーがトラバースを妨げないため、正しく動作します。 キャンディー数が多いステートは共存できますが、BFS では、リソースの残りに関係なく、最短時間のステートが最初に出口に到達することが保証されます。
