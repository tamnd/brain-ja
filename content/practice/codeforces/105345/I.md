 ## 解決策
 ## 問題の理解

 私たちは一列に並んだ家を与えられます。 各家には開始から分単位で測定される期限があり、期限を過ぎてもアリスは到着することができますが、その時間以降に到着した場合はキャンディーを受け取りません。 アリスは位置 k から開始し、1 分ごとに線に沿って左または右に 1 歩移動できます。 

目標は、アリスが期限までにすべての家を少なくとも 1 回訪問できるかどうかを確認し、訪問できる場合はすべての訪問を完了するのに必要な最小合計時間を計算することです。 重要な点は、家に到着するとすぐに訪問できるが、到着は締め切り前に厳密に行われなければならないということです。 

制約の観点から見ると、n は最大 2000 であり、訪問オーダーの順列に対する指数関数的なサブセット探索が除外されます。 三次解は境界線にありますが、慎重に最適化すれば許容できる可能性があります。 考えられるすべての訪問順序またはパスを明示的にシミュレートしようとするソリューションは拡張できません。これは、考えられるルートの数が n とともに非常に急速に増加するためです。 

貪欲に考えると、微妙な問題が現れます。最初に近くの家を訪問すると、期限が迫っている遠くの家に時間内に到達できなくなる地域にアリスを閉じ込める可能性があります。 もう 1 つの失敗例は、最適なパスでは方向を複数回切り替える必要があるため、単一の掃引方向を想定した場合に発生します。 

具体的なエッジケースは、両端に厳しい期限が存在する場合です。 

入力：```
5 3
100 1 100 100 100
```アリスが位置 2 の狭いハウスに向かって欲張って左に移動すると、時間を無駄にし、期限内に右側に到達できない可能性があります。 正しい動作を行うには、どちらの側を最初に訪問するかを慎重にバランスをとる必要があります。 

もう 1 つのエッジ ケースは、開始位置が最も厳しい締切ハウスにとって最適ではなく、最初にそこに到達する必要がある場合です。 

## アプローチ

 強引な解釈としては、アリスがすべての家を訪問する順序を選択し、順序ごとに移動コストをシミュレートすると考えることです。 あるよ！ 可能な順列を計算するだけでなく、単一の順列コストを計算するだけでも O(n) かかるため、このアプローチは直ちに実行不可能です。 

問題の構造は 1 次元であり、最適なパスは任意ではなく、開始点からの連続的なセグメントの拡張のように動作することを示唆しています。 アリスがある領域から離れると、その領域に戻るにはコストがかかるため、最適なソリューションは、カバレッジを k から外側に「拡大」する傾向があります。 

重要な洞察は、順列の観点から考える代わりに、最後に訪問したセットを時間の経過とともに拡大する連続区間 [l, r] として考えるということです。 間隔内のすべての家が期限内に到達可能になると、連続セグメント内の走査は前後のスイープとして常に最適であるため、間隔内の順序は無関係になります。 

これにより問題は、どの間隔を完全にカバーできるかを確認し、期限を守りながら k からすべての家が含まれるまで拡張するのに必要な最小時間を決定することに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | お(ん!) | O(n) | 遅すぎる |
 | インターバル拡張DP/貪欲 | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 タスクを、常に開始位置 k を含むセグメント [l, r] を成長させるものとして再解釈します。 

任意の時点で、区間 [l, r] がある場合、k から開始してそれを完全にカバーするのに必要な時間は、k から一方の端まで歩き、横切って、構造によっては戻るのにかかるコストです。 ただし、1 つの次元では、固定間隔に対する最適な戦略がわかっています。つまり、最初に左に進むか、右に先に進むかのどちらか良い方を選択し、その後完全に横断します。 

課題は、すべての期限を守りながら、間隔をどこまで延長できるかということです。 

私たちは動的プログラミングを使用して、実行可能な間隔を追跡します。 

1. 期限を守りながら区間 [l, r] をカバーできるかどうかとして dp[l][r] を初期化します。 アリスは時間 0 ですでに存在しているため、dp[k][k] を true として開始します。 
2. 有効な間隔から左または右に拡張することによって間隔を拡張します。 dp[l][r] が有効な場合は、dp[l-1][r] と dp[l][r+1] を試します。 
3. 各候補間隔について、k から始まるその間隔内のすべてのノードを訪問するのに必要な最小時間を計算します。 これは、最初に左に進み、次に右に進む、または最初に右に進み、次に左に進むという 2 つの可能な走査順序を考慮することによって行われます。 
4. この時間が、[l, r] の i に対するすべての a[i] よりも厳密に小さいことを確認します。 「はい」の場合、その間隔は有効であるとマークされます。 
5. 有効な間隔がなくなるまで拡張を続けます。 
6. 答えは、[1, n] をカバーするすべての有効な間隔の最小時間、または不可能な場合は -1 です。 

重要な考え方は、間隔の有効性は単調であるということです。間隔が実現可能になると、期限が許せばより大きな間隔に拡張するのに役立ちます。 

### なぜ効果があるのか

 未訪問のポイントをスキップして戻ることは不必要な時間を追加するだけであるため、一連の有効なツアーは、隙間なく連続したセグメントを訪問するツアーに変換できます。 したがって、すべての最適解は、k からの何らかの区間拡張に対応します。 DP では、最も厳しい期限制約内で完全に横断できる間隔のみを考慮し、間隔内のすべての可能な順序が 2 つの単調な横断方向のいずれかによって支配されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = [0] + list(map(int, input().split()))
    k -= 1  # convert to 0-index

    INF = 10**18

    # dp[l][r] = minimum time to cover [l, r] starting from k
    dp = [[INF] * n for _ in range(n)]

    def cost(l, r):
        # compute minimal time to visit entire segment starting at k
        if l <= k <= r:
            # go to one side then sweep
            left = (k - l) * 2 + (r - k)
            right = (r - k) * 2 + (k - l)
            return min(left, right)
        elif r < k:
            return k - l
        else:
            return r - k

    # initialize single point
    dp[k][k] = 0

    for length in range(1, n + 1):
        for l in range(0, n - length + 1):
            r = l + length - 1
            if l == r:
                continue

            best = INF

            # extend from left
            if l + 1 <= r and dp[l + 1][r] != INF:
                best = min(best, dp[l + 1][r])
            # extend from right
            if l <= r - 1 and dp[l][r - 1] != INF:
                best = min(best, dp[l][r - 1])

            if best == INF:
                continue

            t = cost(l, r)
            ok = True
            for i in range(l, r + 1):
                if t >= a[i + 1]:
                    ok = False
                    break

            if ok:
                dp[l][r] = t

    ans = dp[0][n - 1]
    print(ans if ans != INF else -1)

if __name__ == "__main__":
    solve()
```コードは長さを増やすことによってボトムアップで間隔を構築します。 間隔ごとに、より小さい間隔から実現可能性を継承しようとします。 コスト関数は、開始位置が与えられた固定間隔内の最適なトラバースをエンコードします。 

正確さは、セグメントの最小走査時間を計算することにかかっており、これは、k がセグメントの内側、左側、または右側にあるかどうかに応じて 3 つのケースに分かれます。 締め切りチェックにより、締め切り時間以降に家が訪問されないことが保証されます。

 ## 特殊なケース

 1 軒の家で最小限のインプット:```
1 1
10
```インターバルはすでに完了しており、移動する必要がないためコストはゼロです。 DP は dp[0][0] = 0 で開始され、すぐに出力されます。 

対称的なタイトエンドの場合:```
5 3
2 100 1 100 2
```正しい戦略では、中心への到達と慎重な拡大を優先する必要があります。 DP は、外側の要素に到達する前にコストが 1 を超えて増大するため、位置 3 の厳しい期限に違反する間隔が決して受け入れられないことを保証します。 

期限が非対称なケース:```
5 3
100 1 100 1 100
```ここでは、両側に厳しい制約が含まれているため、アルゴリズムは展開順序を慎重に選択する必要があります。 間隔 DP は、左右の拡張の両方を評価し、計算されたコストがすべてのローカル期限を下回っているシーケンスのみを受け入れ、無効な早期拡張を防ぎます。
