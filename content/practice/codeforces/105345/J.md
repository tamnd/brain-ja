 ## 解決策
 ## 問題の理解

 の配列が与えられます$n$カードは一列に並べられており、各カードには 1 から 13 までの値が含まれています。時間の経過とともに値は更新によって変化し、範囲のクエリに答えることも求められます。 

最初のタイプのクエリは、配列内の 1 つの位置を新しい値に変更します。 2 番目のタイプのクエリでは、指定されたセグメントから空ではないカードがいくつ選択されているかを数えるように求められます。$[l, r]$各カードは位置によって異なるため、異なるインデックスで同じ値であっても異なる組み合わせが生成されます。 

最大の難点は、単純な和や度数ではなく、その積がモジュロ 13 の特定の剰余クラスに入るサブセットをカウントしていることです。 13 は素数であるため、13 を法とする乗算は非ゼロ剰余に対するきれいな代数構造を形成しますが、値 1 の存在と繰り返しの更新は、ダイナミック レンジ クエリをサポートするデータ構造が必要であることを示唆しています。 

制約$n, q \le 10^4$サイズの範囲が 1 つであっても、クエリごとにすべてのサブセットに対してゼロから回答を再計算することは直ちに除外されます。$m$もっている$2^m$サブセット、これは中等度の人でも実現不可能$m$。 クエリごとにサブセット情報を再計算するソリューションは、すぐに遅すぎます。 

微妙な問題は、積の条件はモジュロ 13 ですが、要素には 1 ～ 13 の値が含まれることです。値 13 自体は 0 モジュロ 13 として動作します。これは重要です。13 を乗算すると常に積が 0 mod 13 に折りたたまれ、そのような要素が吸収状態のように動作するためです。 

もう 1 つのエッジ ケースは更新に由来します。単一の要素を変更すると、範囲内のサブセット数に大きな影響を与える可能性があるため、静的な答えを事前計算するアプローチは変更後に存続できません。 

## アプローチ

 ブルートフォースのアイデアはクエリを検討することから始まります$[l, r]$。 セグメントのすべてのサブセットを列挙し、その積を法 13 で計算し、値が 5 に等しい場合に答えを増分します。これは、タスクの定義と直接一致するため、正しいです。 

ただし、このアプローチは拡張されます$m$要素を$2^m$クエリごとのサブセットなので、$m = 20$それは境界線になる、そして$m = 10^4$それは不可能です。 問題はサブセットの列挙だけでなく、クエリと更新の繰り返しにもあり、コストがさらに増大します。 

重要な構造上の観察は、13 を法とする乗算が剰余クラスのみに依存しており、乗算制約の下で部分集合を数えていることです。 これは、要素を有限状態空間に変換し、サブセットにわたる畳み込みのような構造を維持する古典的な設定です。 各要素はサブセット積に乗算的に寄与し、積をカウントするサブセットは、13 を法とするグループ状の構造上で母関数を結合することに対応します。 

各セグメントを残基 0 ～ 12 にわたる頻度分布を生成するものとして扱います。ここで、各位置は多項式に寄与します。$$P_i(x) = 1 + x^{a_i}$$セグメント積は、これらの多項式の乗算に対応します。 の係数$x^k$最終的な積では、積が次と等しいサブセットがカウントされます。$k \bmod 13$。 答えは単純に剰余 5 の係数です。 

更新はポイント変更であり、クエリは範囲ベースであるため、各ノードがこの 13 次元分布を格納するセグメント ツリーが必要です。 2 つのセグメントの結合は、13 を法とする乗算による畳み込みに相当します。$O(13^2)$、定数。 

これにより、点の更新と範囲のクエリを使用して多項式のようなベクトルのセグメント ツリーを維持するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 残差 DP 上のセグメント ツリー |$O((n+q)\cdot 13^2 \log n)$|$O(n \cdot 13)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各セグメントを周波数配列で表します`dp`サイズ 13 の場合、`dp[k]`に適合する製品を生成するセグメントのサブセットがいくつあるかを格納します$k \bmod 13$。 

1.値のリーフノードを初期化します。$x$。 単一の要素を含むセグメントから開始するため、2 つのサブセットが存在します。製品 1 を含む空のサブセットと、製品を含むシングルトン サブセットです。$x$。 これは初期化することを意味します`dp[1] = 1`そして`dp[x % 13] += 1`、次の場合を除く$x \equiv 0 \pmod{13}$ここで、乗算は 0 に折りたたまれるため、明示的に処理する必要があります。 
2. 内部ノードごとに、サブセット積の分布を組み合わせて 2 つの子をマージします。 残留物ごとに$i$左の子から、$j$右の子からサブセットを乗算すると積が得られます$i \cdot j \bmod 13$。 これらを親ディストリビューションに蓄積します。 
3. マージするには、残基のすべてのペアを反復処理し、次を計算します。$$new[k] += left[i] \cdot right[j], \quad k = (i \cdot j) \bmod 13$$4. このマージ操作を使用して、配列上にセグメント ツリーを構築します。 
5. タイプ 1 クエリの場合、単一のリーフを更新し、同じマージ ルールを使用して、影響を受けるすべてのセグメント ツリー ノードを上方向に再計算します。 
6. タイプ 2 クエリの場合、セグメント ツリーをクエリします。$[l, r]$そして結果の分布を取得します。 答えは`dp[5]`。 

これが機能する理由は、各セグメント ツリー ノードがそのセグメントのサブセット積のマルチセットを正確に表すためです。 マージ操作は、左右のセグメントから独立してサブセットを選択し、それらを結合することと同等であり、素の和集合に対するサブセットの組み合わせ定義と一致します。 和集合のすべてのサブセットはそれぞれの半分のサブセットに一意に分解されるため、畳み込みは重複することなくすべての可能性を完全に捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [None] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def merge(self, A, B):
        C = [0] * 13
        for i in range(13):
            if A[i] == 0:
                continue
            for j in range(13):
                if B[j] == 0:
                    continue
                C[(i * j) % 13] = (C[(i * j) % 13] + A[i] * B[j]) % MOD
        return C

    def build(self, v, l, r, arr):
        if l == r:
            x = arr[l] % 13
            dp = [0] * 13
            dp[1] = 1
            dp[x] = (dp[x] + 1) % MOD
            self.t[v] = dp
            return
        m = (l + r) // 2
        self.build(v*2, l, m, arr)
        self.build(v*2+1, m+1, r, arr)
        self.t[v] = self.merge(self.t[v*2], self.t[v*2+1])

    def update(self, v, l, r, idx, val):
        if l == r:
            x = val % 13
            dp = [0] * 13
            dp[1] = 1
            dp[x] = (dp[x] + 1) % MOD
            self.t[v] = dp
            return
        m = (l + r) // 2
        if idx <= m:
            self.update(v*2, l, m, idx, val)
        else:
            self.update(v*2+1, m+1, r, idx, val)
        self.t[v] = self.merge(self.t[v*2], self.t[v*2+1])

    def query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.t[v]
        m = (l + r) // 2
        if qr <= m:
            return self.query(v*2, l, m, ql, qr)
        if ql > m:
            return self.query(v*2+1, m+1, r, ql, qr)
        left = self.query(v*2, l, m, ql, qr)
        right = self.query(v*2+1, m+1, r, ql, qr)
        return self.merge(left, right)

n, q = map(int, input().split())
arr = list(map(int, input().split()))

st = SegTree(arr)

for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        _, i, x = tmp
        st.update(1, 0, n-1, i-1, x)
    else:
        _, l, r = tmp
        res = st.query(1, 0, n-1, l-1, r-1)
        print(res[5] % MOD)
```コア実装は、セグメント ツリー ノード表現を中心に展開します。 各ノードは、そのセグメント内のサブセットのすべての可能な積残基をキャプチャする 13 長の配列です。 マージ関数は剰余に対して完全な畳み込みを実行します。これは定数であり、制約の下では安全です。 

微妙な点は初期化です。すべてのセグメントには空のサブセットが含まれており、常に製品 1 に寄与します。`dp[1] = 1`すべてのリーフで必要です。 次に、単一要素のサブセットが上に追加されます。 空のサブセットを忘れると、正しい畳み込み動作に必要な単位要素が削除されるため、すべてのマージが中断されます。 

更新操作では、ビルド時とまったく同じようにリーフが再構築され、一貫性が確保されます。 クエリ ロジックは標準のセグメント ツリー分解に依存し、部分的な回答を順番にマージします。 

## 実用的な例

 小さな配列を考えてみましょう$[2, 5, 7]$そして全範囲にわたるクエリ。 各リーフは、空のサブセットが剰余 1 を与え、シングルトンがその値に寄与する分布として始まります。 

| ノード | dp[1] | dp[2] | dp[5] | dp[7] | その他 |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 1 | 1 | 0 | 0 | - |
 | 5 | 1 | 0 | 1 | 0 | - |
 | 7 | 1 | 0 | 0 | 1 | - |

 最初の 2 つのノードをマージすると、{2,5} のすべてのサブセット製品が結合されます。 結果の分布には、製品 1、2、5、および 10 が含まれます。 

7 とマージした後、以前のすべての積は保持されるか (7 を除く)、7 が乗算されます。 

| ステップ | アクティブなセグメント | dp[5] |
 | --- | --- | --- |
 | [2,5] 以降 | 最初の 2 つのサブセット | 1 |
 | [2,5,7]以降 | フルレンジ | 最終値 |

 最後の dp[5] は、積 mod 13 が 5 に等しいすべてのサブセットをカウントします。 

このトレースは、すべてのサブセットがセグメント境界を越えてきれいに分割され、畳み込みによってマージ全体で正確さが維持されることを示しています。

 ## 特殊なケース

 値が 13 の場合、重大なエッジ ケースが発生します。その場合、その剰余は 0 であり、それを含むサブセットは積を 0 に強制します。DP は、乗法構造を壊すことなく剰余 0 への遷移を正しく許可する必要があります。 13 のみを含むセグメントには、0 への空のマッピングを除くすべてのサブセットが含まれている必要がありますが、空のサブセットは 1 のままであるため、マージの一貫性が確保されます。 

もう 1 つの微妙なケースは、複数の 1 です。 1 は製品を変更しないため、各セグメントのサブセットの数が 2 倍になるだけです。 DP は、それぞれの 1 が独立した選択を導入し、それが残基 1 にある空のサブセットとシングルトンの寄与によって捕捉されることを正しく反映する必要があります。 

最後のケースは、値を 13 からゼロ以外の剰余に変更する更新です。 リーフを最初から再構築しないと、以前の DP 状態が新しい状態に漏れ込み、畳み込み構造が破損します。 各リーフを再初期化すると、変更のたびに正確さが完全に保証されます。
