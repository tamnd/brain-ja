 ## 解決策
 ## 問題の理解

 0 から n までの整数位置の線分が与えられます。 数人の学生が最初は 1 から n−1 の間の位置を占めます。 各生徒は独立して、0 に向かって左方向、または n に向かって右方向を選択します。それぞれの確率は 1/2 です。 

プロセスが開始されると、各生徒は選択した方向に 1 秒ごとに 1 歩ずつ進みます。 2 人の生徒が同時に同じ位置で出会うと、すぐに方向を反転して移動を続けます。 複数の生徒が同じ位置から開始した場合、経路によって相互作用が強制されない限り、生徒は単に独立して移動します。 同じ方向に同じ速度で移動する生徒は決して出会うことはありません。 

プロセスは継続し、学生は最終的に位置 0 または位置 n に到達してセグメントを終了する可能性があります。 クエリ時間 t ごとに、時間 t までに生徒が退室しなかった確率が求められます。 答えは常に 0 または 2 の負の累乗であることが保証されているため、確率が 2^{-m} に等しくなるように指数 m を出力し、確率が 0 の場合は -1 を出力します。 

n が 10^5 まで、q が 10^5 まで、t が 10^8 までという制約により、時間の経過に伴う動きやペアごとの相互作用のシミュレーションが除外されます。 各クエリを O(n) で処理するだけでも、すでに遅すぎます。 重要な問題は、衝突と方向の交換が相互作用のような錯覚を生み出すことですが、実際には、はるかに単純な基礎構造が保持されていることです。 

少なくとも 1 つの方向の選択が常に非常に早く終了を強制するように生徒が配置されている場合、微妙なエッジケースが発生します。 たとえば、生徒が位置 1 から開始した場合、左を選択すると時間 1 で即時に退出します。そのようなすべての強制退出を防ぐ代替構成がない場合、t が十分に大きい場合、確率はゼロになります。 もう 1 つのエッジ ケースは、複数の生徒が同じ位置を共有する場合です。これは、正しいモデルがパリティとペアリングのみに依存する一方で、生徒を別個の移動するエンティティとして単純に扱うと相互作用が過大評価される可能性があるためです。 

## アプローチ

 直接シミュレーションでは、すべての生徒を明示的に追跡し、段階的に移動させ、衝突を解決します。 これにより、ルールが正しくモデル化されます。なぜなら、衝突時の方向の交換は、アイデンティティを無視した場合、粒子が相互に通過することと同等であるからです。 ただし、クエリごとに時刻 t までをシミュレートすることは不可能です。 t が最大 10^8、q が最大 10^5 の場合、1 秒あたりのイベントあたり O(1) ですら実現不可能です。 

重要な観察は、「誰かがすでに終了したか」というイベントにとって衝突は問題ではないということです。 アイデンティティを無視し、生徒を区別できない粒子として扱う場合、衝突は 2 つの粒子が互いに通過するのと同じです。 この古典的なトリックは、システムを独立した歩行者に変換します。つまり、各生徒は相互作用することなく効果的に左右に真っすぐに移動します。 

この変換が受け入れられると、生徒が時間 t までに退出を避ける唯一の方法は、生徒が選択した方向で生徒をセグメントからあまりにも早く送り出さないことです。 位置 x にいる生徒は、t ステップ以内に 0 または n に到達する方向を選択しない場合にのみ、時間 t までに退出を回避します。 これは学生ごとのローカル制約になります。 

したがって、確率は、即時終了を回避するために「強制」される独立した二項選択の数を数えることによって決定されます。 各強制制約は 1/2 の係数に寄与します。これが、最終確率が常に 2^{-m} の形式になる理由を説明しています。 少なくとも 1 人の生徒が t 以内に退出を回避する有効な方向選択を持たない場合、確率はゼロになります。 

私たちは問題を、生徒ごとに、時間 t の間両方向が安全か、どちらかだけが安全か、またはどの方向も安全ではないかを計算することに落とし込みます。 指数 m は、安全な方向が 1 つだけある生徒の数です。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | O(n・t・q) | O(n) | 遅すぎる |
 | Independent direction reduction | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 衝突は生徒が時間 t までに退室するかどうかに影響を与えないことに注目してください。そのため、各生徒は固定された選択された方向に独立して移動しているものとして扱います。 This removes all interaction complexity.
 2. 位置 x にいる生徒の場合、左に退出する時間を x として、右に退出する時間を n − x として計算します。 これらは決定論的であり、他の学生に依存しません。 
3. 与えられたクエリ時間 t に対して、各生徒が各指示の下で時間 t まで生存できるかどうかに基づいて分類します。 x > t の場合は左の移動が安全で、n − x > t の場合は右の移動が安全です。 
4. どちらの方向も生徒にとって安全でない場合、ランダムな選択に関係なく、生徒は時刻 t より前または時刻 t に退場するため、退場がない確率はゼロとなり、すぐに -1 を返します。 
5. 正確に 1 つの方向が安全な場合、その生徒には自由がありません。生徒は安全な方向を選択しなければならず、確率に 1/2 の係数が寄与します。 
6. どちらの方向も安全な場合、どちらの選択をしても時間 t 以内に退出することが回避されるため、生徒は制約を課しません。 
7. すべてのポジション (または多重度のある固有のポジション) にわたる制約された生徒の数を合計し、この数を m として出力します。 

### なぜ効果があるのか

 崩壊した衝突の後、各生徒は方向を独立してランダムに選択して進化し、終了時間は最初の位置と選択した方向にのみ依存します。 「時間 t までに誰も退出しない」というイベントは、それぞれのイベントが特定の方向の選択を禁止することを要求する独立したイベントの交差点になります。 独立性により確率が倍増することが保証されるため、強制された各バイナリ選択は正確に 1/2 の係数に寄与します。 有効な選択肢がゼロの学生がいる場合、交差点は空となり、確率はゼロになります。 指数 m は、制約システムによって固定された独立した 2 値決定の数と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    # compress counts of positions
    from collections import Counter
    cnt = Counter(a)
    
    # precompute positions list
    positions = list(cnt.items())
    
    for _ in range(q):
        t = int(input())
        m = 0
        ok = True
        
        for x, c in positions:
            left_safe = x > t
            right_safe = (n - x) > t
            
            if not left_safe and not right_safe:
                ok = False
                break
            
            if left_safe != right_safe:
                m += c
        
        if not ok:
            print(-1)
        else:
            print(m)

if __name__ == "__main__":
    solve()
```同じ座標にいるすべての学生は生存条件下では同じように動作するため、コードは最初に位置によって学生を圧縮します。 クエリ時間 t ごとに、左右の移動によって生徒がセグメント内に留まるかどうかがチェックされます。 重要な部分は、左側の生存の場合は x > t、右側の生存の場合は n − x > t という条件であり、生徒が t 秒以内に境界に到達したかどうかを直接エンコードします。 

変数 m は、安全な方向が 1 つだけある生徒の数を累積します。 どの位置でも両方向が安全でない場合、ok は false になり、答えは -1 になります。 

よくある落とし穴は、同じポジションの生徒の数を掛けるのを忘れることです。 各生徒は独立したコイン投げであるため、多重度は指数に寄与する必要があります。 

## 実用的な例

 n = 7 で、生徒が位置 [2, 2, 2, 3, 3] にいるとします。 t = 1 を評価してみましょう。 

| 位置 x | カウント c | 安全に放置 (x>1) | 右セーフ (n-x>1) | 貢献 |
 | --- | --- | --- | --- | --- |
 | 2 | 3 | はい | はい | 0 |
 | 3 | 2 | はい | はい | 0 |

 ここでは学生は単一の方向に強制されることはないので、m = 0、確率は 1 です。 

ここで、t = 2 について考えてみましょう。 

| 位置 x | カウント c | 安全に放置 (x>2) | 右セーフ (n-x>2) | 貢献 |
 | --- | --- | --- | --- | --- |
 | 2 | 3 | いいえ | はい | 3 |
 | 3 | 2 | はい | はい | 0 |

 位置 2 の 3 人の生徒は右に移動し、指数 3 を寄与する必要があります。他の生徒は自由です。 したがって、m = 3 となります。 

これは、純粋に安全な方向のオプションを排除することによって制約がどのように蓄積されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O((n + q) · u) | u はクエリごとの個別の位置の数で、圧縮後は通常小さくなります。 
| スペース | O(n) | 位置の周波数マップ |

 各クエリは個別の位置のみをスキャンし、n は最大 10^5 であるため、このソリューションは制限内で機能します。 1 秒ごとのシミュレーションは実行されず、独立性によって衝突の複雑さはすべて排除されます。

 ## 特殊なケース

 生徒が境界線に非常に近いところからスタートした場合、重大なエッジケースが発生します。 x ≤ t かつ n − x ≤ t の場合、どちらの方向も時間 t 以内に終了するため、生存確率はゼロです。 アルゴリズムは、両方の条件を false としてチェックし、すぐに -1 を返すことで、これを正しく検出します。 

もう 1 つのケースは、すべての生徒が x > t と n − x > t の両方が成立する中間領域にいる場合です。 その場合、制約は課されず、m は 0 のままとなり、確率は 1 になります。 

最後に、複数の生徒が同じ位置を共有する場合、制約されていれば、それぞれが独立して指数に寄与します。 頻度ベースのカウントにより、同じポジションの生徒が重複エラーなく正確にカウントされることが保証されます。
