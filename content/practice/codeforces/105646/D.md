 ## 解決策
 ## 問題の理解

 一連の整数が与えられると、それを連続したセグメントに分割するためのあらゆる可能な方法を検討します。 各セグメントは、その要素のビット単位の XOR に等しい値を提供し、パーティションのスコアはこれらのセグメントの XOR の積になります。 タスクは、考えられるすべてのパーティションにわたってこれらのスコアの合計を計算することです。 

この構造が微妙なのは、パーティションが要素ごとに独立した選択肢ではないことです。 パーティションはカット位置を選択することによって定義され、そのような選択ごとにすべてのセグメント境界が変更されます。これにより、xor 値が非常に非線形に変更されます。これは、xor が連結下の合計や積のように動作しないためです。 

入力サイズは、パーティションの数が n、具体的には 2^(n−1) で指数関数的に増加することを意味するため、中程度の n であってもパーティションを列挙することは不可能です。 すべてのセグメンテーションを反復したり、セグメント XOR を繰り返し再計算したりするソリューションは、すぐに制限を超えます。 以前のすべてのカット ポイントを試行する 2 次動的計画法のアプローチでは、すでに約 n² 個の遷移が実行されており、プレフィックス前処理が使用されない限り、各遷移では xor を再計算する必要があります。 プレフィックス xors を使用した場合でも、n が 2 · 10^5 付近の典型的な Codeforce 制限に達すると、n² は遅すぎます。 

すべての数値がゼロの場合、小さいながらも重要なエッジ ケースが発生します。 すべてのセグメントの xor はゼロであるため、すべてのパーティションの積はゼロですが、空のプレフィックスの基本ケースを忘れた単純な実装では、有効なパーティション数を考慮せずに、すべての dp 状態に対して誤ってゼロが生成される可能性があります。 もう 1 つのまれなケースは、n = 1 の場合に発生します。パーティションは 1 つだけあり、1 つのセグメントにわたる積はそのセグメントの xor にすぎないため、答えは単に 1 つの要素の値になります。 

## アプローチ

 この問題に対処する自然な方法は、dp[i] を i で終わるプレフィックスのすべてのパーティションの値の合計として定義することです。 j で終わる短いプレフィックスのパーティションを拡張するには、j < i を選択し、セグメント (j+1 … i) を追加します。 これにより、dp[i] がセグメント (j+1 … i) の xor で乗算された dp[j] の以前のすべての j の合計となる反復が得られます。 これは正しいです。i で終わるすべてのパーティションは、j で終わる前のパーティションと最後のセグメントによって一意に形成されるからです。 

ボトルネックは、すべてのペア (j, i) のセグメント xor を計算すると、O(n²) 個の遷移が発生することです。 各セグメント xor が定数時間になるようにプレフィックス xor を事前計算したとしても、各 i についてすべての j を考慮する必要があります。 

重要な構造観察は、セグメントの xor をプレフィックス xor に書き換えることです。 pref[i] を最初の i 要素の xor とします。 この場合、xor(j+1 … i) は pref[i] xor pref[j] と等しくなります。 これにより、問題はセグメントに関する推論からプレフィックス状態のペアに関する推論に変換されます。 

ここで、寄与は、pref[i] と pref[j] の間でビットが異なるかどうかによって決まります。 ビット b は、pref[i] x または pref[j] に設定されている場合、2^b に寄与します。これは、pref[i] と pref[j] の b 番目のビットが異なる場合に正確に発生します。 これにより、遷移は、prefix-xor ビット状態によってグループ化された以前の dp 値に対するビット単位のカウント問題に変わります。 

すべての j を反復する代わりに、ビット位置ごとに、そのビットが 0 または 1 である前のプレフィックス間にどれだけの dp 質量が存在するかを維持します。その後、すべてのビットにわたるこれらの合計を個別に組み合わせることで、dp[i] を計算できます。 これにより、各遷移が O(log A) に減少します。ここで、A は配列内の最大値です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのカットにわたるブルート DP | O(n²) | O(n) | 遅すぎる |
 | ビットごとにグループ化された DP | O(n log A) | O(log A) | 承認済み |

 ## アルゴリズムのチュートリアル

1. プレフィックス xor 配列 pref を定義します。ここで、pref[i] は最初の i 要素の xor であり、pref[0] = 0 と設定します。これにより、任意のセグメント xor を pref[i] xor pref[j] として書き込むことができます。 
2. dp 配列を維持します。ここで、dp[i] は i で終わるプレフィックスのすべてのパーティションの合計寄与度であり、dp[0] = 1 を設定して、後のセグメントを構築するための乗算的に中立な構造に寄与する空のパーティションを表します。 
3. これまでに処理されたすべての dp 値の現在までの合計を保持します。これは、すべての有効な以前のカット位置 j にわたる dp[j] の合計を表します。 この集合体は、ビット差を処理す​​るときに効率的に補数を形成するために使用されます。 
4. 各ビット位置 b について、2 つのアキュムレータを維持します。1 つは pref[j] のビット b が 0 に等しい dp[j] の合計を格納し、もう 1 つはビット b が 1 に等しいものです。これら 2 つのグループにより、ビットが現在のプレフィックスと一致するか異なるかに応じてインデックスを迅速に分離できます。 
5. dp[i] を計算するには、すべてのビット位置を反復処理します。 固定ビット b については、pref[i] にビット b が設定されているかどうかを判断します。 0 の場合、pref[j]_b = 1 を持つすべての前の j が寄与し、1 の場合、pref[j]_b = 0 を持つすべての前の j が寄与します。 関連する累積 dp 合計に 2^b を乗算し、それを dp[i] に加算します。 
6. dp[i] を計算した後、新しく計算された dp[i] を使用してすべてのアキュムレータと dp 合計を更新し、また、将来の状態が参照できるように pref[i] のビット パターンをビットごとの構造に登録します。 

正確さは、i で終わるすべてのパーティションが最後のカット位置 j によって一意に定義され、その遷移の寄与は dp[j] と pref[i] と pref[j] の間のビット単位の関係のみに依存するという事実に依存します。 ビットごとにグループ化すると、j を列挙することなく、その依存関係に必要な情報が正確に分離されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] ^ a[i]

    maxb = max(pref).bit_length() if n > 0 else 0

    dp = [0] * (n + 1)
    dp[0] = 1

    total_dp = 1

    bit_count = [[0, 0] for _ in range(maxb)]
    for b in range(maxb):
        if (pref[0] >> b) & 1:
            bit_count[b][1] = 1
        else:
            bit_count[b][0] = 1

    for i in range(1, n + 1):
        x = pref[i]
        cur = 0

        for b in range(maxb):
            bit = (x >> b) & 1
            if bit == 0:
                cur += (total_dp - bit_count[b][0]) << b
            else:
                cur += (total_dp - bit_count[b][1]) << b

        dp[i] = cur

        total_dp += dp[i]

        for b in range(maxb):
            if (x >> b) & 1:
                bit_count[b][1] += dp[i]
            else:
                bit_count[b][0] += dp[i]

    print(dp[n])

if __name__ == "__main__":
    solve()
```コードは最初にセグメント XOR クエリをプレフィックス XOR 形式に変換し、すべての遷移が 2 つのプレフィックス状態のみに依存するようにします。 dp 状態は左から右に増分的に構築され、以前のすべての寄与はインデックスを反復するのではなくビットごとのグループ化を使用して要約されます。 

微妙な実装ポイントは、pref[0] と dp[0] の初期化です。 dp[0] = 1 がなければ、どのパーティションも有効な開始状態を持ちません。 もう 1 つのデリケートな側面は、bit_count を 0 と 1 に対して別々に維持することです。 これらを混同すると、一致するビットと異なるビットを区別する補数ロジックが壊れます。 total_dp を使用すると、dp 配列を繰り返し合計することなく補数が計算されます。 

## 実用的な例

 配列 [1, 2] について考えてみましょう。 プレフィックス xor は [0, 1, 3] です。 dp[0] = 1 から始めます。 

i = 1 の場合、pref[1] = 1。以前の状態は j = 0 のみです。セグメント xor は 1 xor 0 = 1 であるため、dp[1] = 1 となります。 

i = 2、pref[2] = 3 の場合、2 つの可能性を考えます。j = 0 はセグメント xor 3 を与え、j = 1 はセグメント xor 2 を与えます。つまり、dp[2] = 1·3 + 1·2 = 5 となります。 

| 私 | プレフィ[i] | dp[i] の計算 |
 | --- | --- | --- |
 | 0 | 0 | 1 |
 | 1 | 1 | 1 |
 | 2 | 3 | 5 |

 このトレースは、各 dp 状態が以前のすべてのパーティションをどのように集約するか、およびセグメントを明示的に列挙せずにプレフィックス xor がどのようにセグメント値を決定するかを示します。 

次に [1, 1, 1] を考えてみましょう。 プレフィックス xor は [0, 1, 0, 1] です。 交互のパターンにより、セグメント XOR 値のキャンセルが繰り返されます。 DP は以前のすべてのカットからの寄与を蓄積しますが、多くのセグメントがゼロと評価されるため、多くのパーティション積がゼロになります。 このアルゴリズムは、同じプレフィックス ビットを持つ状態が同じビット クラス間で質量を繰り返し移動する、プレフィックス xor グループ化を通じてこれを自然に捕捉します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・B) | 各位置はすべてのビット位置を 1 回反復し、各ビットの更新は事前計算された集計を使用して定数時間で行われます。 
| スペース | O(n + B) | プレフィックス配列とビット単位のアキュムレータは、線形および対数の補助データを格納します。 

ビット数 B は配列内の最大値の対数によって制限されるため、n が大きい場合でも計算は十分に制限内に収まります。

 ## 特殊なケース

 単一要素配列の場合、アルゴリズムは pref[0] と pref[1] のみを処理します。 dp[0] は 1 から始まり、ビットの違いのみが pref[1] と pref[0] によって直接決定されるため、dp[1] は正確にその要素の値になります。 ビットごとのテーブルは、pref[0] をすべて 0 として正しく分類し、期待される単一の寄与を生成します。 

すべてゼロの配列の場合、すべてのプレフィックス xor はゼロのままであるため、すべてのセグメント xor はゼロになります。 アルゴリズムでは、pref[i] はどのビットにおいても pref[j] と異なることはありません。これは、すべての寄与が各アキュムレータの「同じビット」ブランチを介してルーティングされることを意味します。 これらの寄与は total_dp から減算され、ビット全体で完全に相殺されるため、最初のステップの後、すべての dp[i] はゼロになり、すべてのパーティション積がゼロであるという事実と一致します。 

[1, 2, 1, 2] などの交互のビット パターンの場合、プレフィックス xor は前の状態を繰り返し再利用します。 ビットによるグループ化により、dp 質量が二重にカウントされることなく、同一のプレフィックス ビット構成間で一貫して再配分されることが保証されます。 各状態遷移はビットごとの等しいか差にのみ依存するため、プレフィックスを再検討してもセグメントの寄与に曖昧さが生じることはありません。
