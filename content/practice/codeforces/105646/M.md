 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列が与えられ、その「コスト」を要素の自然な位置からの総変位、具体的には |p[i] − i| のすべての位置 i にわたる合計として定義します。 直観的には、各要素は、その要素がその同一位置からどれだけ離れているかに影響します。 

タスクは、この値をカウントまたは最適化するだけではなく、固定コスト b の順列を列挙し、その中から辞書順で k 番目のものを選択することです。 

辞書編集的な順序は、並べ替えに関する標準的な方法で定義されます。つまり、最初の位置から比較し、最初に異なる値によって順序が決まります。 

したがって、入力は順列にわたる制約システムをエンコードし、出力はすべての有効な順列の中でグローバル コスト制約とランク制約の両方を満たす単一の順列になります。 

編集上の物語に暗黙的に含まれる制約は、複雑さという点で非常に大きいものです。 提案されている動的プログラミングはすでに O(n^4) に達しており、プレフィックスを列挙するとさらにその値が増加します。 順列の空間は n の階乗であるため、これにより、すべての有効な順列を明示的に生成または並べ替えようとするアプローチは即座に除外されます。 この解決策は、多くの順列を一度に集計するカウント構造に依存する必要があります。 

バランスが構造とどのように相互作用するかによって、微妙な特殊なケースが発生します。 たとえば、n = 3 のような小さな順列を考えてみましょう。p = [2, 3, 1] を試してみると、バランスは |2−1| になります。 + |3−2| + |1−3| = 1 + 1 + 2 = 4。[3, 1, 2] のような別の順列でも、異なるバランスが生成されます。 素朴な考えでは、バランスは辞書順で単調に動作すると考えるかもしれませんが、これは誤りです。 辞書編集上の順序と変位コストは独立しているため、カウントせずに貪欲に選択すると、k 番目の答えが不正確になります。 

別の失敗例は、複数の順列が同じバランスを共有しているが、要素が左右に移動する距離が構造的に異なる場合に発生します。 全体の変位のみを追跡する単純な DP では、プレフィックスを構築するとき、特に部分的な置換を継続しようとするときに、実現可能性に関する情報が失われます。 

## アプローチ

 ブルートフォースの観点は単純明快です。 1 から n までのすべての順列を生成し、それらのバランスを計算し、値が正確に b であるものをフィルターし、辞書順に並べ替えて、k 番目を返すことができます。 これは問題の定義に直接従うため、正しいです。 ただし、n! を列挙する必要があります。 各評価には O(n) のコストがかかり、O(n! · n) 時間がかかりますが、これは n が 12 程度の場合でも実行不可能になります。 

重要な観察は、置換構造を位置と値のペアとして再解釈すると、バランス関数が自然に分解されるということです。 p[i] を直接考える代わりに、線上でインデックスを一致させることを考えます。一方の側は位置を表し、もう一方の側は値を表し、両方ともソートされています。 各割り当ては、これら 2 つのセットのペアに対応します。 

このペアリングの観点により、新しい要素が以前の不一致の要素とペアになるか、ペアリングが延期される一連の決定として順列を再解釈することができます。 この構造は、非交差または部分的に順序付けされたマッチングに似ており、プレフィックスおよび開いた不一致要素の数に対する動的プログラミングを使用してキャプチャできます。 

最初の DP はコストを無視し、すべての有効なペアをカウントします。 DP[i][j] が、j 個の一致しないエンドポイントを開いたままにして、最初の i 要素を処理する方法の数を表すものとします。 遷移では、新しい要素が開いている要素の 1 つを閉じるか、新しい要素を開くかが考慮されます。 これはすでに順列の組み合わせ構造を捉えています。

バランスを組み込むために状態を磨き上げます。 重要なのは、各ペアが総変位に測定可能な値を寄与しており、この寄与はペアのどちら側を考慮しているかによってのみ決まるということです。 ペアの「右端点」のインデックスの合計を追跡すると、左端点の合計が自動的に決定され、それらの差によって全体のバランスが決まります。 これにより、DP 状態 DP[i][j][s] が得られます。ここで、i はプレフィックス長、j はオープン ペアの数、s は右エンドポイントの累積合計です。 

i の範囲は最大 n、j の範囲は最大 n、s の範囲は最大 O(n^2) であり、遷移は状態ごとに定数時間であるため、この DP は O(n^4) 状態で実行されます。 

与えられた残高要件を持つ部分的に固定されたプレフィックスに対して完了がいくつ存在するかをカウントできたら、k 番目の順列を辞書編集的に構築できます。 各位置で、未使用の可能性のある値を昇順に配置してみます。 候補の選択肢ごとに、その割り当てを一時的に修正し、残りのバランス制約を満たす有効な補完がいくつ残っているかをカウントするために DP にクエリを実行します。 カウントが k 未満の場合はスキップして減算します。 それ以外の場合は、それにコミットして続行します。 

これにより、問題はグローバル列挙から、部分的な割り当ての下で繰り返されるカウント クエリに軽減されます。これはまさに DP がサポートするものです。

 ## アルゴリズムのチュートリアル

 まず、順列を位置と値の間のマッチング プロセスとして再解釈します。 すべての割り当てを一度に修正するのではなく、現在の部分的な選択と一貫性を保っている完全な順列の数を評価するのに十分な情報を維持しながら、段階的に順列を構築します。 

各状態が、これまでに処理した要素の数、現在一致していない要素の数、および最終的なバランスに向けて蓄積された部分的な寄与を表す動的プログラミング テーブルを定義します。 右の端点がどのように寄与するかが分かれば、左の端点が暗黙的に決定され、バランスが計算可能になるため、この構造は十分です。 

この DP はプレフィックスに対してボトムアップで計算されます。 各ステップで、新しい要素を追加するときに、その要素が既存の開いている要素とペアになるか、将来のペアリングのために一致しないままになるかを検討します。 これは、順列構築のすべての構造的可能性を説明します。 

この DP を埋めた後、回答の順列の構築に進みます。 未使用の値のセットを維持します。 各位置 i で、候補値を昇順に繰り返します。 各候補値 x について、一時的に p[i] = x と仮定し、問題をこの制約の下でいくつの補完が存在するかをカウントすることに縮小します。 これは、この選択によって引き起こされた強制ペアリングを反映する更新されたパラメータを使用して DP に問い合わせることによって行われます。 

完了数が k 未満の場合は、k からそれを減算し、次の候補に進みます。 それ以外の場合は、位置 i で x を固定し、位置 i + 1 に進みます。常に小さい選択肢を最初に使い尽くすため、これにより辞書編集上の正確さが保証されます。 

### なぜ効果があるのか

 正確さは、部分順列を曖昧さなく拡張するために必要なすべての情報を DP 状態が完全にキャプチャしているという事実に依存します。 プレフィックスの有効な継続はすべて 1 つの DP パスに対応し、すべての DP パスは 1 つの完了に対応します。 したがって、DP 状態をカウントすると、特定のプレフィックスを拡張する有効な順列の数が正確に測定され、カウントを減算することで正しい辞書編集的な選択が可能になります。

 ## 特殊なケース

 重要なエッジ ケースは、バランス制約により、置換の非常に小さなサブセットのみが有効なままになる場合です。 たとえば、n = 2 および b = 2 の場合、置換 [2, 1] のみが制約を満たします。 DP は、この構造につながるプレフィックス選択の完了を 1 つだけ正確に報告する必要があります。 過剰にカウントすると、誤って以前の辞書編集上の選択が許可されてしまいます。 

有効な順列の数に比べて k が大きい場合、別のエッジ ケースが発生します。 このような場合、早い位置にあるすべての候補をスキップする必要があり、アルゴリズムは後の選択にコミットする前にすべての DP カウントを正しく使い果たさなければなりません。 DP カウントが正確でない場合、k が負になるか、正しく終了しない可能性があります。
