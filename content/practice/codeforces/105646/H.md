 ## 解決策
 ## 問題の理解

 一連の整数が与えられており、それを正確に分割したいと考えています。$k$連続したセグメント。 各セグメントには平均値があり、その要素の合計をその長さで割った値として計算されます。 パーティション内のすべてのセグメントの中で最小の平均に注目します。私たちの目標は、この最小の平均をできるだけ大きくするパーティションを選択することです。 

言い換えれば、配列を次のように分割しています。$k$間隔であり、平均の観点から最も弱い間隔に注目します。 その最も弱いインターバルを可能な限り強くしたいと考えています。 

入力サイズにより、チェックごとにすべての解が線形またはほぼ線形になるように十分な大きさの配列が許可されます。 パラメータの存在$k$また、パーティションにわたる最適化は、すべての分割にわたる動的プログラミングではなく、貪欲または二分探索構造を強く示唆しています。$O(n^2)$あるいはさらに悪い依存関係。 

微妙な点は、すべての数値が負の場合、または次の場合に現れます。$k$大きいです。 平均が良好になるまでセグメントを貪欲に拡張しようとする単純な戦略は、ローカルな決定が将来のセグメントの実現可能性に影響を与えるため、失敗する可能性があります。 

たとえば、配列が次のようになっているとします。$[1, 2, 3, 4]$そして$k = 2$。 素朴な考えは、後でカットしようとするかもしれません$3$ただし、平均の計算方法によっては、これが最適ではない可能性があります。 正しいソリューションでは、パーティションを貪欲に評価するのではなくグローバルに評価する必要があります。 

値が変動している場合、または平均が直接比較される場合には、別の問題が発生します。 浮動小数点の不安定性により、境界しきい値の実行可能性チェックが不正確になる可能性があります。 

## アプローチ

 強引なアプローチでは、選択できるあらゆる方法が列挙されます。$k-1$間のポジションをカットする$n-1$ギャップ。 各パーティションについて、セグメントの合計とセグメントの平均を計算し、最小値を取得して最大化します。 これは正しいですが、カットを選択する方法は無数にあるため、組み合わせが爆発的になります。$\binom{n-1}{k-1}$、控えめな人でも実行不可能になります$n$。 

重要な構造的洞察は、パーティションについて直接考えるのをやめ、代わりに、固定値についての決定に関する質問をすることです。$x$、配列を次のように分割できますか?$k$すべてのセグメントが少なくとも平均値を持つようなセグメント$x$? これに答えることができれば、可能な限り最大値を探すことができます。$x$二分探索を使用します。なぜなら、特定のしきい値がある場合だからです。$x$は達成可能ですが、それより小さいしきい値も達成可能です。 

修正の実現可能性を確認するには$x$、平均に関する条件を合計に関する条件に変換します。 からのセグメント$l$に$r$満足する$$\frac{a_l + \dots + a_r}{r-l+1} \ge x$$これは以下と同等です$$(a_l - x) + \dots + (a_r - x) \ge 0.$$したがって、引き算します$x$すべての要素から取得し、各セグメントの合計が負でないことを要求するようになりました。 

プレフィックス合計の場合、これはプレフィックス値に関する選択の問題になります。$k+1$各セグメントが、連続して選択されたプレフィックス位置間の非負の和の差に対応するようなインデックス (セグメント境界)。 これは、最後のカットと比較してプレフィックスの合計が減少しない有効なカット ポイントを選択すると解釈できる、貪欲な実現可能性チェックにつながります。 

結果として得られる構造は、選択できるかどうかを見つけることになります。$k$有効なセグメント。これは、変換されたプレフィックス合計に対する最長の非減少構造としてフレーム化することも、より直接的にはプレフィックス最小制約を使用した貪欲なセグメンテーションとしてフレーム化することもできます。 

二分探索は、この実現可能性チェックをラップします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 二分探索 + 貪欲チェック | O(n 対数精度) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 答えを実際の値として扱い、最適な平均が安全に含まれる範囲で二分探索を使用して検索します。 

1. 関数を定義する`check(x)`これにより、配列を少なくとも次のように分割できるかどうかが決まります。$k$すべてのセグメントが少なくとも平均値を持つセグメント$x$。 これは中核となる実現可能性テストです。 
2. 配列を減算して変換します。$x$あらゆる要素から。 これにより、「平均 ≥ x」という条件が「セグメント合計 ≥ 0」に変換されます。 
3. この変換された配列に対してプレフィックスの合計を計算します。 させて$p[i]$最初の合計になる$i$変換された要素。 
4. 貪欲に左から右にセグメントを構築します。 前回のカット位置を維持します。 位置で終わる新しいセグメントの場合$i$かどうかを確認します。$p[i] - p[last]\ge 0$。 「はい」の場合、ここでセグメントを閉じることができます。 
5. セグメントを閉じるたびに、最後のカットを次の位置に移動します。$i$セグメント数を増やします。 
6. 配列をスキャンした後、少なくとも次の情報が得られたかどうかを確認します。$k$セグメント。 
7. 二分探索$x$これを使って`check`機能を使用して、希望の精度に達するまで間隔を狭めます。 

微妙な理由は、非負セグメントが達成可能になったら常にできるだけ早くカットするということです。 削減を遅らせても、残りの柔軟性が低下するだけなので、将来の実現可能性には役立ちません。 

### なぜ効果があるのか

 変換された条件により、すべてのセグメント制約がプレフィックスの違いに関する非負の要件に軽減されます。 貪欲なセグメンテーションにより、選択された各セグメントが有効なまま制約の下で最大になることが保証されます。 特定のパーティションに対して有効なパーティションが存在する場合$x$の場合、有効なセグメンテーションは実行可能性を損なうことなく左端の貪欲セグメンテーションに変換できるため、この貪欲戦略ではそのようなパーティションが少なくとも 1 つ見つかります。 これにより、到達する能力が維持されます。$k$可能な場合は正確にセグメント化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(arr, k, x):
    cnt = 0
    cur = 0
    last = 0

    for v in arr:
        cur += v - x
        if cur - last >= 0:
            cnt += 1
            last = cur

    return cnt >= k

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    lo, hi = -1e5, 1e5

    for _ in range(60):
        mid = (lo + hi) / 2
        if can(arr, k, mid):
            lo = mid
        else:
            hi = mid

    print(lo)

if __name__ == "__main__":
    solve()
```の`can`関数は、変換された配列に貪欲なセグメンテーションを実装します。 変数`cur`候補の平均を減算した後、実行中のプレフィックスの合計を維持します。 変数`last`最後のカット位置にプレフィックスの合計を保存するため、`cur - last`は現在のセグメントの正確な合計です。 これが負でなくなったら、セグメントを閉じます。 

二分探索は固定回数の反復で実行されます。これは浮動小数点の収束には十分です。 範囲$[-10^5, 10^5]$典型的な制約が与えられた場合、合理的な平均が安全に含まれます。 

## 実用的な例

 配列を考慮してください$[1, 2, 3, 4]$と$k = 2$。 

候補者をテストします$x = 2.5$。 

| 私 | 値 | 変換された合計 | セグメント合計 (現在 - 最後) | カット？ | セグメント |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | -1.5 | -1.5 | いいえ | 0 |
 | 2 | 2 | -2.0 | -3.5 | いいえ | 0 |
 | 3 | 3 | -1.5 | -5.0 | いいえ | 0 |
 | 4 | 4 | -0.5 | -5.5 | いいえ | 0 |

 カットは不可能なので、2 つのセグメントに到達できません。 これは次のことを示しています$x$大きすぎます。 

今テストしてください$x = 1.5$。 

| 私 | 値 | 変換された合計 | セグメント合計 | カット？ | セグメント |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | -0.5 | -0.5 | いいえ | 0 |
 | 2 | 2 | 0.5 | 0.0 | はい | 1 |
 | 3 | 3 | 1.5 | 1.5 | はい | 2 |

 2 セグメントを達成しているため、この値は実現可能です。 次に、二分探索ではより高い値が試行され、達成可能な最小平均値の近くに収束します。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$k = n$。 各要素は独自のセグメントを形成するため、答えは最小の配列要素と等しくなければなりません。 すべてのセグメント チェックが単一の変換された値に還元されるため、アルゴリズムはこれを処理します。$a_i - x \ge 0$、二分探索は、すべてが非負に保たれる最小値に正確に収束します。 

すべての値が同一である場合、別の特殊なケースが発生します。 どのパーティションでも同じセグメント平均が得られるため、答えは一定です。 実現可能性チェックは常にその値で正確に成功しますが、それを超えると、変換されたすべての値が負になるため失敗します。 

最後のエッジケースは、値が負であり、正の値が混在している場合です。 この変換では、絶対スケールを候補周囲の相対オフセットに変換するため、正確さが保証されます。$x$したがって、セグメンテーションは符号の分布ではなく累積バランスのみに依存します。
