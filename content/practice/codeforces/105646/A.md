 ## 解決策
 ## 問題の理解

 固定開始頂点 1 と固定終了頂点 n を持つ有向非巡回グラフが与えられます。 タスクは、単一のパスを見つけることではなく、以前に選択したすべてのパスと比較して、新しいパスのそれぞれが「何か新しいものをもたらす」という制約を付けて、可能な限り長い有効な 1 対 n のパスのシーケンスを構築することです。 具体的には、シーケンス内の次のすべてのパスには、シーケンス内の以前のパスに一度も出現したことのない有向エッジが少なくとも 1 つ含まれている必要があります。 

したがって、基本的にグラフの使用可能な部分を 1 対 n のウォークのシーケンスに分解します。各ウォークは、以前に使用されていなかったエッジを少なくとも 1 つ提供する必要があります。 選択したパスにエッジが現れると、そのエッジは新規性を数える目的で「使用」されます。 

入力グラフは DAG であるため、サイクルに関する懸念は解消されますが、パスがどのようにオーバーラップするかという組み合わせの性質は単純化されません。 出力は単一の整数、つまりそのようなシーケンスの最大長です。 

Codeforces のグラフ問題に典型的な制約からの直接的な影響は、n と m が十分に大きいため、m が線形または線形に近いものより悪い解は実行されないということです。 これは、DAG 内の単純なパスの数が指数関数的に増加する可能性があるため、パスを列挙したり、貪欲な構築を明示的にシミュレートしたりできないことをすでに示唆しています。 

重要な構造上のエッジケースは、頂点 1 が頂点 n にまったく到達できない場合です。 この場合、有効なパスはないため、答えは 0 でなければなりません。2 番目の微妙なケースは、到達可能性はあるものの、非常に狭い通路を通った場合にのみ発生します。 たとえば、1 から n までのパスが 1 つだけある場合、そのパスを使用した後はすべてのエッジがすでに使用されており、2 番目のパスは新しいエッジを導入できないため、答えは 1 になります。 

単純なアプローチでは、少なくとも 1 つの未使用のエッジを含む 1 から n までのパスを繰り返し検索し、そのエッジを削除またはマークして、続行しようとする可能性があります。 これは、どのエッジを「消費」するか選択するかによって将来の構造が決まり、貪欲なパス選択では最適性が維持されないため、問題が発生します。 

## アプローチ

 この問題を考える強引な方法は、プロセスを明示的にシミュレートすることです。 使用されているエッジのセットを維持し、少なくとも 1 つの未使用のエッジを含むパスを 1 から n まで繰り返し検索します。 そのようなパスを見つけるたびに、そのすべてのエッジを使用済みとしてマークし、答えをインクリメントします。 

DFS または BFS を使用して各検索を最適化した場合でも、反復回数はエッジの数に線形になる可能性があり、各反復のコストは O(n + m) です。 さらに重要なのは、パスの選択は独立していないということです。1 つのパスを選択すると、将来の複数のパスでより効率的に再利用できたはずのエッジが「無駄になる」可能性があります。 これにより、総当たり攻撃が遅くなるだけでなく、正しく推論することが難しくなります。 

重要な洞察は、パス全体という観点から考えるのをやめ、代わりにエッジと頂点がそれぞれの新しいパスに必要な最小限の構造にどのように寄与するかを推論することです。 実際に関連するサブグラフ、つまり少なくとも 1 つの有効な 1 対 n パス上にある頂点に注意を限定します。 これらはまさに 1 から到達可能な頂点であり、逆グラフでは n に到達できる頂点です。 このような頂点の数を N とし、頂点間のエッジの数を M とします。 

この制限されたサブグラフ内では、すべての有効な 1 対 n パスは 1 で開始し、n で終了する必要があります。また、新しいパスに現れるすべての中間頂点により、パスはすでに説明されているものを超えて少なくとも 1 つの新しいエッジを「消費」する必要があります。 これにより、すべてのパスに導入できる新しい頂点の数と、それをサポートするために存在する必要があるエッジの数との間に密接な関係が作成されます。

最適なシーケンス内のパスの数を p で表し、v を「パス構造ごとの新しい頂点の寄与」の合計数とすると、各パスは、導入される新しい頂点の数よりも少なくとも 1 つ以上多くのエッジを強制しているとみなすことができます。 すべてのパスを合計すると、M、N、および p の間に線形関係が得られます。 この会計恒等式を解くと、閉じた形式 p = M − N + 2 が得られます。 

この変換は単純化の核心です。組み合わせパス シーケンスを探索する代わりに、すべてを「有用な」サブグラフ内の頂点とエッジを数えるまでに減らします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルート フォース パス シミュレーション | 最悪の場合は指数関数的 | O(n + m) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 まず、1 から n までの有効なパスに実際に参加できるグラフの部分を分離します。 有効なシーケンスにはこれらの頂点やエッジを含めることはできないため、この領域の外側にあるものはすべて無関係です。 

1. 頂点 1 からグラフの走査を実行して、到達可能なすべての頂点をマークします。 これにより、有効なパス セグメントの開始点に現れる可能性のある頂点のみを考慮することが保証されます。 
2. 頂点 n から開始して反転グラフ上で走査を実行し、シンクに到達できるすべての頂点をマークします。 これにより、実際に有効なパスを終了できる頂点のみを保持することが保証されます。 
3. これら 2 つの頂点セットを交差させます。 これらの頂点のみが、ソースから到達可能であり、シンクにも到達できるため、有効な 1 対 n パスに出現できます。 
4. この交差点の頂点の数として N を数えます。 この時点では、すべての有効なパスが存在するグラフの「コア」だけに焦点を当てています。 
5. 両端点がこの交点の内側にある有向エッジの数として M を数えます。 これらは、有効なパスに出現する可能性がある唯一のエッジです。 
6. 頂点 1 から頂点 n に到達できない場合は、すぐに 0 を返します。 有効なパスがまったくないため、シーケンスは存在できません。 
7. それ以外の場合は、答えを M − N + 2 として計算します。 

この式が現れる理由は、最初のパスを超える追加のパスはそれぞれ、以前に使用された頂点を補う少なくとも 1 つの新しいエッジを強制的に含めるものとして解釈できるためです。 存在するエッジの数と、通過する必要がある頂点の数との間のバランスにより、そのような「新鮮な」拡張の最大数が制限されます。 

### なぜ効果があるのか

 有用なサブグラフに限定した後、エンドポイント 1 と n を除くすべての頂点は、有効な 1 対 n トラバーサルに参加するために少なくとも 1 つの入力エッジと 1 つの出力エッジを必要とするものと考えることができます。 シーケンス内の各新しいパスは、以前に使用されていなかったエッジを少なくとも 1 つ導入する必要があります。DAG の構造により、新しい頂点参加制約も導入することなく、これらの導入を任意に再利用することはできません。 これにより、厳密なアカウンティング関係が作成されます。エッジは新しいパスに「供給」を提供しますが、頂点はパス間でエッジを再利用する効率を低下させる「構造的オーバーヘッド」を課します。 派生式 M − N + 2 は、ベース パスとエンドポイントの制約を考慮した後、この余剰を正確に取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    rg = [[] for _ in range(n + 1)]
    edges = []

    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        rg[v].append(u)
        edges.append((u, v))

    # reachability from source
    vis1 = [False] * (n + 1)
    q = deque([1])
    vis1[1] = True
    while q:
        u = q.popleft()
        for v in g[u]:
            if not vis1[v]:
                vis1[v] = True
                q.append(v)

    # reachability to sink (reverse graph)
    vis2 = [False] * (n + 1)
    q = deque([n])
    vis2[n] = True
    while q:
        u = q.popleft()
        for v in rg[u]:
            if not vis2[v]:
                vis2[v] = True
                q.append(v)

    # check connectivity
    if not (vis1[n] and vis1[1]):
        print(0)
        return

    cnt_v = 0
    for i in range(1, n + 1):
        if vis1[i] and vis2[i]:
            cnt_v += 1

    cnt_e = 0
    for u, v in edges:
        if vis1[u] and vis2[u] and vis1[v] and vis2[v]:
            cnt_e += 1

    print(cnt_e - cnt_v + 2)

if __name__ == "__main__":
    solve()
```解決策は、2 つの独立した到達可能性の計算が必要であるため、順方向と逆方向の両方の隣接リストを構築することから始まります。 1 からの 1 つの BFS はソース側から使用可能な頂点を識別し、反転グラフ上の n からの別の BFS は依然としてシンクにつながる可能性のある頂点を識別します。 これら 2 つのセットの交差部分が有効なサブグラフを定義します。 

次に、このサブグラフ内の頂点とエッジを数えます。 無関係な頂点に接触するエッジを M に含めてはいけないため、エッジ フィルタリングは重要です。 そうしないと、式は完全に一貫した制限された構造を前提としているため、式が壊れます。 

最後に、閉じた形式の式 M − N + 2 を適用し、最大シーケンス長を直接生成します。 

## 実用的な例

 ### 例 1

 余分なエッジのない、1 → 2 → 3 → n という単純なチェーンを考えてみましょう。 

| ステップ | 1から到達 | n に到達する | アクティブな頂点 | アクティブエッジ | 結果 |
 | --- | --- | --- | --- | --- | --- |
 | 開始 | {1,2,3,n} | {1,2,3,n} | {1,2,3,n} | 3 | |
 | カウント | 4 | 4 | 4 | 3 | |

 ここで M = 3、N = 4 なので、答えは 3 − 4 + 2 = 1 となります。 

これにより、すべてのエッジが即座に消費されるため、単一の単純なパスは 1 つのシーケンス要素のみを提供できることが確認されます。 

### 例 2

 ダイヤモンド構造を考えてみましょう。1 が 2 と 3 に分割され、両方とも 4 に進み、次に 4 → n になり、追加のクロス エッジ 2 → 3 が追加されます。 

アクティブな頂点はすべて 5 つのノードであるため、N = 5 です。アクティブなエッジは 1→2、1→3、2→3、2→4、3→4、4→n であるため、M = 6。 

| ステップ | N | M | 結果 |
 | --- | --- | --- | --- |
 | 計算 | 5 | 6 | 6 − 5 + 2 = 3 |

 これは、追加の内部エッジによって、単に分離されたルートの数を超えて、シーケンス内で可能な個別の 1 対 n パスの数がどのように増加するかを示しています。

## 特殊なケース

 主なエッジケースは、シンクがソースから到達できない場合です。 たとえば、コンポーネント間の接続がない 1 → 2 および 3 → n などです。 1 からの BFS は {1,2} のみをマークしますが、n からの逆 BFS は {n,3} のみをマークします。 それらの交差は空であるため、N = 0 および M = 0 ですが、有効なパスがまったくないため、直接 0 を返します。 これにより、縮退状態で式を適用することが回避されます。 

もう 1 つのケースは、グラフが単一の単純なパスである場合です。 1 → 2 → 3 → n の場合、すべての頂点が交点内にあるため、N = 4 および M = 3 になります。計算では 1 が得られ、シーケンス要素が 1 つだけ可能であるという直観と一致します。 

より微妙なケースは、到達可能性を変えずに M を増加させる追加のエッジがある場合です。これらのエッジは、個別のパスに追加の「新しいエッジの機会」を提供し、シミュレーションを必要とせずに数式がそれらを線形に考慮するため、最終的な答えが正しく増加します。
