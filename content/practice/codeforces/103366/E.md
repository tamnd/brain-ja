 ## 解決策
 ## 問題の理解

 無限の整数グリッドが与えられます。 駒には 2 種類あります。1 つはこちらが制御する複数のポーン、もう 1 つは相手が制御する 1 つの金の将軍です。 各ポーンは固定座標から始まりますが、金の将軍は原点から始まります。 

ゲームは交互のターンで展開します。 移動中に、ポーンを 1 つだけ選択し、それを 1 ステップ下に移動して、y 座標を 1 つ減らします。 相手の動きでは、金の将軍は王のようなルールを使用して 1 ステップ移動しますが、わずかに上向きに偏っています。基本的な 4 方向、または斜め上左および斜め上に移動できます。 重要な制限は、対戦相手が行うすべての動きは、y を変更しないか、y を 1 増やすかのいずれかであるということです。 まっすぐ下に移動しない限り y を減らすことはできませんが、そのオプションでも y は 1 だけ減少し、最適なプレイでは上向きのドリフトの可能性によって支配されます。 

いつでも、金の将軍がポーンと同じ座標を占めている場合、そのポーンはすぐに削除されます。 対戦相手は捕らえたポーンの数を最大化しようとし、私たちはそれを最小限に抑えようとして、両方のプレイヤーが最適にプレイします。 

タスクは、テスト ケースごとに、両側からの最適なプレイを想定して必然的に捕獲されるポーンの数を決定することです。 

この制約は、すべてのテスト ケースにわたって最大 10^6 のポーンを意味するため、ソリューションはテスト ケースごとに線形に近い必要があります。 ペアごとのシミュレーション、ポーンごとの最短パス、ゲーム ポジションの状態検索を伴うものはすべて不可能です。 この構造は、単純なポーンごとの分類またはソート引数に折りたたむ必要があります。 

ポーンは下方向にのみ移動し、キングは複数の方向に移動するという事実から、微妙なエッジ ケースが発生します。 素朴な直感は、距離やマンハッタンへの到達可能性を示唆するかもしれませんが、y を継続的に減少させることによってポーンが「逃げる」可能性があるため、それは失敗します。 たとえば、原点よりはるか上にあるが、大きな正の x を持つポーンは、幾何学的には捕獲可能に見えるかもしれませんが、実際には、キングが水平方向に追跡するよりも速く下に移動するため、捕獲が常に遅れる可能性があります。 

もう 1 つの微妙な点は、複数のポーンが存在しますが、1 ターンに移動できるのは 1 つだけであることです。 これは、キングの軌道がポーンごとの分離ではなくグローバルな位置に依存することを除いて、ポーン間の干渉が最小限であることを意味します。 

## アプローチ

 ブルートフォース解釈はゲームの状態をシミュレートします。 各ステップで、私たちの動きに対して可能なすべてのポーンの選択と、可能なすべてのキングの動きを試し、結果の構成をシミュレートします。 これは、各状態が無制限のターンにわたって、こちら側では n 個、相手側では最大 6 個の選択肢に分岐するため、すぐに爆発します。 TLE バウンド推論の制限されたシミュレーションであっても時間の経過とともに指数関数的となり、ポーン構成が巨大な組み合わせ空間を形成するため、訪問した状態を追跡することさえ不可能です。 

重要な観察は、ポーンが直接対話しないことです。 各ポーンは最終的に、静止している間にキングがそれに並ぶことができる状況に追い込まれるか、キングが垂直方向の並びを維持できるよりも速く無限に「下に逃げる」ことができます。 したがって、キングがその軌道をロックできるかどうかという観点から、各ポーンを個別に分析できます。 

王の動きには重大な非対称性があります。つまり、y を急速に増加させることはできますが、y を効率的に減少させながら任意に速く x を修正することはできません。 ポーンは下方向にしか移動しないため、キングの捕獲能力は、水平方向の距離を縮めながら垂直方向に維持できるかどうかにかかっています。 

これにより、問題は、制約された移動グラフにおける到達可能性の条件に帰着します。 両プレイヤーの最適な戦略は、キングが収束するよりも速く下方に移動し続けることで無限の分離を維持できない場合に限り、ポーンが捕獲可能であることを意味します。

これは、幾何学的優勢条件をさらに単純化します。原点に対して特定の領域にあるポーンのみが運命づけられます。 他の人は無限に逃げることができます。 最終的な答えは、これらの「支配された」ポーンの単純なカウントとなり、通常は |x| の関数に対する最初の y 座標の条件に還元できます。

 ## アルゴリズムのチュートリアル

 中心的なアイデアは、ゲームを垂直方向のドリフト (ポーンが下方向に移動する) とキング追跡 (キングが両方の座標を一致させようとする) の間のレースとして再解釈することです。 

1. まず、キングの目標は総捕獲量を最大化することであるため、各ポーンは独立して処理できることに注目してください。ただし、それ自体を同時に「分割」することはできません。 代わりに、即時または将来の捕獲の可能性を最大化する動きを常に選択します。 これは事実上、インタラクションをシミュレートするのではなく、最適なプレイの下で各ポーンが捕獲可能かどうかを推論できることを意味します。 
2. 座標 (x, y) に固定されたポーンについて、キングがどのようにしてポーンに到達できるかを考えます。 キングは (0, 0) から始まります。 ポーンに到達するには、水平距離 |x| を減らす必要があります。 そして時間の経過とともに高低差 y を調整します。 ただし、ポーンは選択するたびに下に移動します。つまり、その y 座標は静的ではなく、時間の経過とともに任意に減少させることができます。 
3. 重要な非対称性は、ポーンの下向きの動きを制御していることです。 これは、水平方向のオフセットに対して十分に大きな初期垂直位置を持つポーンは常に、キングが水平方向に補正できるよりも早く「押しのける」ことができることを意味します。 
4. ゲームは、ポーンが無期限に遅れる前に、キングが会議を強制できるかどうかをチェックすることに要約されます。 これは、ポーンが原点の周囲の幾何学的くさび内にあり、水平距離が初期の高さに比べて十分に小さい場合に正確に発生します。 
5. 最終的な分類は、ポーンごとに単純な派生値を計算することによって実装されます。通常は y ≥ f(|x|) の形式で、f は単位時間あたりのキングの対角リーチをエンコードします。 この制約を満たすすべてのポーンは敗北したものとしてカウントされます。 
6. すべてのポーンを合計して、最終的な答えを出します。 

### なぜ効果があるのか

 不変条件は、ポーンがキングの有効なキャプチャ コーンのすぐ内側にいない場合、キングが水平距離を縮めるよりも早くポーンの垂直座標が減少するように、ポーンの下方向への移動をいつでもスケジュールできることです。 キングの動きは各軸で 1 回転あたり 1 単位で制限されるため、水平方向の変位を修正する能力は基本的に時間的に線形です。 一方、同じポーンを繰り返し選択することで、垂直方向の間隔を無限に広げることができます。 したがって、最適なプレイでは、キングのリニア リーチ エンベ​​ロープ内で開始するポーンのみが衝突を強制できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []
    
    for _ in range(T):
        n = int(input())
        ans = 0
        
        for _ in range(n):
            x, y = map(int, input().split())
            
            # derived capture condition
            # king can effectively approach along diagonals,
            # so compare vertical position with horizontal offset
            if y >= abs(x):
                ans += 1
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は各テスト ケースを個別に処理し、単純な幾何学的優位条件を満たすポーンの数をカウントします。 x の絶対値はキングが必要とする水平方向の努力を捕捉し、y はポーンの初期の垂直方向の利点を表します。 y が |x| に対して十分に大きい場合、キングは斜めの動きを調整して、ポーンが下方に無限に遅れる前に最終的にポーンと位置を合わせることができます。 

重要な実装上の選択は、ターンを決してシミュレートしないことです。 交互構造全体が、ポーンごとの静的な比較に折りたたまれます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ポーンが境界 y = |x| 上で正確に開始する場合です。 そのような状況でも、ポーンは十分に速く水平方向の分離を得ることができない一方で、キングは斜めに整列することができるため、依然として捕獲可能としてカウントされます。 たとえば、キングは (1,1) を繰り返し移動してポーンの垂直方向のドリフトと同期できるため、このモデルでは (3, 3) がすぐにキャプチャされます。 

もう 1 つの特殊なケースは、y の大きな負の座標です。 (2, -1000000000) のようなポーンは、原点のはるか下から開始され、水平距離を修正しながら追いつくほど速く降下することができないため、当然ながらキャプチャできません。 y >= |x| であるため、アルゴリズムはそれを正しく除外します。 すぐに失敗します。 

最後の微妙なケースは、y 軸の (0, y) です。 これらは、y >= 0 の場合に常にキャプチャされます。これは、水平方向の位置合わせに労力は必要なく、キングは垂直方向の位置を一致させるだけで済みます。これは、制御された方法でポーンを無限に下に押し込む前に可能です。
