 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 各クエリでは、この配列の連続したセグメントに焦点を当て、そのセグメント内のできるだけ多くの数値を分割する 1 より大きい単一の整数を見つけようとします。 この整数のさまざまな選択がクエリごとに許可されており、1 より大きい固定整数で同時に割り切れるセグメント内の要素の最大数にのみ関心があります。 

つまり、部分配列の場合、p で割り切れる部分配列内の要素の数が最大になるように、1 より大きい約数 p を選択し、その最大数を報告します。 

重要な構造は、可分性が素因数によって駆動されるということです。 数値は、p がその約数の 1 つである場合にのみ候補 p に寄与し、有効な p はセグメント内の要素の素因数に由来する必要があります。 

この制約は、n と q の両方がテスト ケースごとに最大 50000 であり、テスト ケース全体の合計も 50000 で制限されることを意味します。各配列値は最大 1e6 であるため、ふるいベースの前処理で因数分解が可能です。 ただし、クエリごとに範囲全体をスキャンしてすべての約数をテストするのは遅すぎるため、出現回数を事前計算して範囲クエリに効率的に答える方法が必要です。 

微妙なエッジ ケースは、多くの要素が因子のわずかな重複のみを共有する場合です。 たとえば、[6, 10, 15] のようなセグメントでは、3 つすべてを分割する数値はありませんが、各ペアは素因数を共有しており、セグメントの構成に応じて p = 2 または 3 または 5 を選択できるため、それでも 2 を返す必要があります。 素朴な「グローバル最良除数」または数値ごとの貪欲なアプローチは、配列全体にわたって固定の支配的な除数を仮定する場合、ここでは失敗します。 

もう 1 つの特殊なケースは、多数の 1 を含む配列です。 1 には素因数がないため、有効な p に寄与することはなく、1 で満たされたセグメントは常に 0 を返す必要があります。 

## アプローチ

 各クエリを解決する直接的な方法は、セグメントを反復処理し、各数値を因数分解し、そのセグメントに出現するすべての約数または素数の頻度をカウントすることです。 次に、最大周波数を取得します。 これは正しいです。すべての有効な p は素数から構築される必要があり、素数が k 要素を分割する場合、その素数に等しい p は k に達します。 

ただし、これをクエリごとに実行するとコストがかかりすぎます。 素因数分解が高速であっても、各数値が複数の素数に寄与する可能性があり、すべてのクエリにわたってこれにより繰り返し作業が発生します。 最悪の場合、クエリごとに最大 50,000 個の要素を繰り返し因数分解し、約 25 億回の操作が発生します。 

重要な観察は、複合約数を明示的に必要としないということです。 複合 p が要素を分割する場合、その素因数の少なくとも 1 つも要素を分割し、その素因数は p よりも多くの要素に現れます。 したがって、セグメントに対して可能な最良の p は、常にそのセグメント内で最も頻繁に現れる素因数になります。 

これにより、問題は次のように簡略化されます。すべての素因数 x について、各クエリで [l, r] 内の x で割り切れる数値がいくつあるかを知り、すべての x の最大値を取得する必要があります。 各数値はその個別の素因数のみに寄与するため、プレフィックス構造を使用して位置と回答範囲のカウント全体にわたって各素数の出現を保存できます。 

1e6 までのふるいを使用してすべての数値の素因数を事前計算し、各素数について、それが出現するインデックスのソートされたリストを構築します。 各クエリは、関連する素数ごとに、[l, r] に該当する出現の数をカウントします。 セグメント内に実際に出現する素数を確認するだけで済みます。これは、前処理で数値の因数分解を繰り返し、オフライン処理または二分探索を使用したクエリ範囲ごとの直接検索によってクエリを関連付けることで処理できます。

よりシンプルで効率的な実装では、素数からソートされたインデックス リストへのマップを使用し、クエリごとに、セグメント エンドポイントの要素の因数分解の和集合に現れるすべての素数をテストします。 すべての数値にわたる個別の素数の出現の合計が少ない (各数値に素数がほとんどない) ため、償却コストは許容可能なままです。

 ## アルゴリズムのチュートリアル

 ### 1. 最小の素因数を事前計算する

 1e6 までの最小の素因数ふるいを構築して、すべての数値をすばやく素因数分解できるようにします。 これにより、因数分解が値の大きさではなく、値内の個別の素数の数において線形になることが保証されます。 

トライアル分割を繰り返すと実行時間が大きく左右されるため、この手順が必要です。 

### 2. すべての配列要素を個別の素数に因数分解する

 各インデックス i について、a[i] の個別の素因数のセットを抽出します。 素数は数値を割るか割らないかのどちらかであり、倍数のべき乗によって割り切れる数は変わらないため、多重度は無視します。 

各素数 p について、p が出現するインデックスのリストを保存します。 

### 3. 素数と位置のマッピングを構築する

 遭遇したすべての素数 p について、p が a[i] を除算するように、すべてのインデックス i を含むソートされた配列 pos[p] を維持します。 

この構造は、割り算の質問を範囲カウントの質問に変換します。 

### 4. 二分検索を使用して各クエリに回答します

 クエリ [l, r] の場合、配列内に出現するすべての素数 (またはより効率的には、追跡されている場合にセグメントの要素に出現する素数のみ) を反復処理し、pos[p] に対する 2 つの二分探索を使用して範囲内に各素数が何回出現するかを計算します。 

私たちはそのような最大の頻度を追跡します。 

### 5. 最大値を出力する

 クエリの答えは、考慮されたすべての素数の中で最大の数です。 

### なぜ効果があるのか

 有効な各候補 p には少なくとも 1 つの素因数が必要です。 p が k 要素を分割する場合、それらの k 要素はすべて、p の少なくとも 1 つの素因数で割り切れます。 素因数に関する鳩の巣原理によ​​り、p の少なくとも 1 つの素因数は、そのセグメント内の少なくとも k 個の要素も分割する必要があります。 したがって、単一の素数に注意を限定しても最適性が失われることはありません。 したがって、アルゴリズムはセグメント上の任意の素約数の最大頻度を計算し、これは答えと正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXA = 10**6

spf = list(range(MAXA + 1))
for i in range(2, int(MAXA ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXA + 1, i):
            if spf[j] == j:
                spf[j] = i

def factor_distinct(x):
    res = set()
    while x > 1:
        p = spf[x]
        res.add(p)
        while x % p == 0:
            x //= p
    return res

t = int(input())
for _ in range(t):
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pos = {}

    for i, val in enumerate(a):
        for p in factor_distinct(val):
            if p not in pos:
                pos[p] = []
            pos[p].append(i)

    primes = list(pos.keys())

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        ans = 0

        for p in primes:
            arr = pos[p]
            # count occurrences in [l, r]
            lo, hi = 0, len(arr)
            while lo < hi:
                mid = (lo + hi) // 2
                if arr[mid] < l:
                    lo = mid + 1
                else:
                    hi = mid
            left = lo

            lo, hi = 0, len(arr)
            while lo < hi:
                mid = (lo + hi) // 2
                if arr[mid] <= r:
                    lo = mid + 1
                else:
                    hi = mid
            right = lo

            ans = max(ans, right - left)

        print(ans)
```ふるいを使用すると、各数値をすばやく因数分解できます。 各値は、その個別の素数のみを隣接リストに組み込みます。 

各クエリについて、二分探索により範囲頻度を計算します。 2 つのバイナリ検索により、出現リスト内の最初の位置 ≥ l と最初の位置 > r が分離され、素数ごとに O(log n) のカウントが得られます。 

微妙な点は、配列は 0 から格納されますが、クエリは 1 から始まるため、0 から始まるインデックス付けです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) · π · log n) | 各クエリは素数をチェックし、バイナリ検索を実行します。 
| スペース | O(n · π) | 素数の出現リストを保存する |

 ここで、π は数値ごとの個別の素数の平均数であり、小さい値です (通常、1e6 までの値では ≤ 7)。 合計 n + q ≤ 5e4 とすると、これは制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MAXA = 10**6
    spf = list(range(MAXA + 1))
    for i in range(2, int(MAXA ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, MAXA + 1, i):
                if spf[j] == j:
                    spf[j] = i

    def factor_distinct(x):
        res = set()
        while x > 1:
            p = spf[x]
            res.add(p)
            while x % p == 0:
                x //= p
        return res

    t = int(input())
    out = []
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        pos = {}
        for i, v in enumerate(a):
            for p in factor_distinct(v):
                pos.setdefault(p, []).append(i)

        primes = list(pos.keys())

        for _ in range(q):
            l, r = map(int, input().split())
            l -= 1
            r -= 1

            best = 0
            for p in primes:
                arr = pos[p]
                lo, hi = 0, len(arr)
                while lo < hi:
                    mid = (lo + hi) // 2
                    if arr[mid] < l:
                        lo = mid + 1
                    else:
                        hi = mid
                L = lo

                lo, hi = 0, len(arr)
                while lo < hi:
                    mid = (lo + hi) // 2
                    if arr[mid] <= r:
                        lo = mid + 1
                    else:
                        hi = mid
                R = lo

                best = max(best, R - L)

            out.append(str(best))

    return "\n".join(out)

 ## 特殊なケース

 主要なエッジ ケースは、すべての数値が 1 であるセグメントです。この場合、因数分解により空の素数セットが生成されるため、どの位置リストにもエントリは追加されません。 クエリ処理中、素数はチェックされず、答えは 0 のままです。空のセットの最大値は 0 として初期化されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、30 = 2 × 3 × 5 など、数値に複数の異なる素数がある場合です。この数値は 3 つの異なるリストに影響します。 [30, 14, 21] を含むセグメントでは、素数 2、3、7 がそれぞれ 2 回出現し、すべての素数が同時に含まれる単一の数値がないにもかかわらず、アルゴリズムは正しく 2 を返します。
