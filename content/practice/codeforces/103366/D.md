 ## 問題の理解

 複数の整数セットが与えられており、それらを任意の順序に並べ替えることができます。 再配置後、少なくとも 1 つの値の存在を保証する必要があります。$x$, のすべての出現が$x$十分に離れている: を含む任意の 2 つの位置$x$少なくとも異なる必要があります$d$。 他の値には制限はありません。 

タスクは、1 つの有効な再配置を見つけるだけではなく、すべての有効な再配置の中から辞書編集的に最小の配列を出力する必要があります。 どの配置を選択しても間隔要件を満たすことができない場合は、$x$、答えは$-1$。 

制約$n \le 10^6$すべてのテスト ケースでは、テスト ケースごとにほぼ直線的またはほぼ直線的な時間がかかります。 すべての順列をテストしたり、候補値ごとに配置を繰り返しシミュレートしようとするアプローチは、すぐに失敗します。$O(n \log n)$多くのテストを合計すると、テスト ケースごとの計算が厳しくなる可能性があり、二次関数は不可能です。 

微妙な問題は、特別な値$x$は事前に固定されていません。 どの値を「間隔をあけた」値にするかは自由に選択できます。 これは重要な構造的自由であり、最も誤った貪欲なアイデアの源でもあります。$x$解決可能なインスタンスが不可能であるかのように見える可能性があり、逆に、間違った構築順序を選択すると、辞書編集上の最適性が破壊される可能性があります。 

よくある失敗例は、貪欲な配置中に実現可能性の制約を無視したことに起因します。 たとえば、選択されたかどうかを追跡せずに、小さな値を貪欲にあまりにも積極的に配置すると、$x$間隔の制約の下でも完了することはできますが、最終的には、$x$もう置くことはできません。 

別の失敗は選択から起こります$x$純粋に周波数によって。 頻度だけでは辞書編集の実現可能性を決定しません。 原理的には、間隔パターンが可能かどうかを判断するだけです。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべての異なる値を候補として試してみます。$x$、そしてそれぞれについて、その値に間隔制約を適用しながら配列の有効な順列の構築を試み、辞書編集的に最小の有効な結果を取得します。 

直したとしても$x$、有効な順列を構築するには、すべての位置でバックトラックまたは将来の実現可能性を確認する必要があります。 単純な構築では、枝刈りを行わずにすべての順列、さらにはすべての貪欲な配置を考慮します。これにより、各位置が多くの選択肢に分岐する可能性があるため、最悪の場合は階乗または指数関数的な動作が発生します。 

重要な観察は、候補を確定すると、$x$、唯一の制約は、同一のアイテムに対する間隔の制約です。 これは古典的なスケジュール構造です。$x$位置に配置する必要があります$p_1 < p_2 < \dots < p_k$そのような$p_{i+1} \ge p_i + d$。 これは問題を配置に変換します$k$同一の長さのマーカー$n$最小距離の配列。 

これから、実現可能性の条件を導き出すことができます。$x$表示されます$k$何度も必要です$p_1 = i$、 それから$p_k = i + (k-1)d \le n$。 したがって、実現可能性のための必要十分条件は、$x$配置とは、次の間隔で位置を割り当てることができることです。$d$。 

実現可能性が理解されると、辞書編集的な最小性は貪欲な左から右への構築を示唆します。各位置に、配置を完了する可能性を損なわない最小の値を配置しますが、特別な値を選択した場合には、$x$ある位置には、スペース制約の下で残りのコピーを配置するのに十分なスペースがまだ残っています。 

実際に決める必要はない$x$代わりに、それを「構築中に追跡された制約」として扱う場合、事前に、選択された制約を仮定できます。$x$そして実現可能性を動的に強化します。 ただし、これを決定論的にするために、有効な値を選択します。$x$まず、それを考慮して辞書編集的に最小の配列を貪欲に構築します。

 ## アルゴリズムのチュートリアル

 まず配列を周波数に圧縮し、どの値を特別な値として選択できるかを検討します。$x$。 値$x$すべての出現箇所を少なくとも次の間隔で配置できる場合にのみ実現可能です。$d$、これは以下と同等です$k_x$に収まるほど小さいこと$n$間隔をあけて配置する$d$。 

次に、実行可能な候補を 1 つ選択します$x$。 辞書編集を容易にするために最小の値を選択するのが自然な選択ですが、構築が正しい場合は、実行可能な値であればどれでも機能します。 

固定後$x$、各値の残りの出現回数を維持し、次の値の出現回数を追跡しながら、左から右に答えを構築します。$x$まだ配置する必要があります。 

各位置で値を昇順に試し、その値を配置することで残りのインスタンスが保持されるかどうかを暫定的に決定します。$x$実現可能。 以外の値の場合$x$、構造的な制約がないため、存在する限り常に安全です。 

設置を検討する際には$x$位置にある$i$、あれば$r$残りのコピー$x$この配置の後、可能な最新の最終配置は依然として次の条件を満たす必要があります。$i + (r-1)\cdot d \le n$。 この条件が満たされない場合は配置できません$x$たとえそれが利用可能な最小値であっても。 

私たちは常に、現在の位置で実現可能性を通過する最小値を選択し、そのカウントをデクリメントして続行します。 

### なぜ効果があるのか

 この構造では、単一の不変条件が維持されます: 接頭辞を埋めた後$1 \dots i$、サフィックスの補完が少なくとも 1 つ存在するため、残りのすべての出現が$x$距離を考慮して配置できる$d$。 すべての決定は、この不変条件を維持する手のみを受け入れるため、デッド状態になることはありません。 辞書編集的な最小性が続きます。これは、各位置で実現可能性を損なわない最小値を選択するためであり、これより小さい選択が拒否されると完了が不可能になるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, d = map(int, input().split())
        a = list(map(int, input().split()))

        freq = {}
        for v in a:
            freq[v] = freq.get(v, 0) + 1

        # feasibility limit for spacing
        # k elements need (k-1)*d + 1 positions
        def ok(k):
            return (k - 1) * d + 1 <= n

        candidates = [v for v, c in freq.items() if ok(c)]
        if not candidates:
            print(-1)
            continue

        x = min(candidates)

        remaining = freq.copy()

        # we greedily construct lexicographically smallest array
        res = []

        # remaining count of x
        rx = remaining[x]

        for i in range(1, n + 1):
            for v in sorted(remaining.keys()):
                if remaining[v] == 0:
                    continue

                # try place v
                remaining[v] -= 1

                if v == x:
                    rx_after = rx - 1
                    if rx_after <= 0:
                        res.append(v)
                        rx = rx_after
                        break
                    # check feasibility of future x placements
                    # we placed one x at position i, so remaining rx_after must fit
                    if i + (rx_after - 1) * d <= n:
                        res.append(v)
                        rx = rx_after
                        break
                else:
                    res.append(v)
                    break

                remaining[v] += 1
            else:
                print(-1)
                break
        else:
            print(*res)

if __name__ == "__main__":
    solve()
```コードは最初に周波数を計算し、特別な間隔の値として機能する可能性のある値をフィルターします。 次に、構築を辞書編集上の最適性に偏らせるために、最小の実現可能な候補を選択します。 

貪欲ループは、位置ごとに回答を構築します。 各位置について、値を昇順にスキャンし、その頻度を一時的に減分し、それらの選択によって構成が有効に保たれるかどうかをチェックします。 唯一重要なチェックは、$x$、残りのコピーを間隔をあけて配置できるようにします。$d$残りのサフィックスに。 

微妙な点は、残りの数を更新することです。$x$実現可能性を確認した上でのみ。 チェックが失敗した場合は、周波数を元に戻し、次の候補の検索を続けます。

 ## 特殊なケース

 1 つの重要なエッジ ケースは、実行可能な候補が 1 つだけである場合に発生します。$x$は存在しますが、配列内の最小値ではありません。 そのような状況では、常に最小の数字を最初に配置しようとする単純な辞書編集の貪欲さが、誤って実現可能性を破壊する可能性があります。$x$。 アルゴリズムは、選択されたものについてのみ実現可能性をチェックすることでこれを回避します。$x$、すべての値に当てはまるわけではありません。 

もう 1 つのエッジケースは次のような場合です$d = 1$。 同一の値のすべてのペアが自動的に少なくとも 1 の距離を満たし、任意の順列が有効になるため、制約は空になります。 貪欲な構造は、単純に配列をソートすることに退化します。 

最後のエッジケースは、周波数がぎりぎり実現可能な場合です。たとえば、$k_x = \frac{n+1}{d}$。 このような場合、早期に貪欲な配置を行うと、$x$早期に配置すると、後で唯一の有効な間隔パターンが削除される可能性があるため、慎重に制御する必要があります。 不平等チェック$i + (r-1)\cdot d \le n$すべてのステップでグローバルな実現可能性を強制することで、この正確な障害モードを防ぎます。
