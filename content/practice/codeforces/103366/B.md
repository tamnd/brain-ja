 ## 解決策
 ## 問題の理解

 換算分数 x/y として表される正の有理数が与えられ、それを有限連分数として表すように求められます。 ここでの連分数は、値が整数部分 a0 に、残りの係数 a1、a2 などから形成される別の連分数の逆数を加えて an まで書き込むネストされた式です。 

より操作的な用語で言えば、x/y を一連の整数に分解して、下から開始して反転と加算を繰り返すと、元の分数が正確に再構築されるようにしたいと考えています。 出力は単一の値ではなく、この分解を一意に記述する一連の係数です。 

制約は値のサイズの点で大きく、x と y は最大 10^9、テスト ケースは最大 1000 個です。 これは、O(x) または O(y) スタイルのアプローチですら不可能であるため、あらゆるソリューションをテスト ケースごとに対数時間で実行する必要があることを強く示唆しています。 標準のユークリッド アルゴリズムは O(log min(x, y)) で実行されます。これは快適に高速であり、重要なヒントである連分数にも構造的に関連しています。 

リダクションステップ後に数値の一方が他方の倍数になる場合、微妙なエッジケースが発生します。 たとえば、x = 5 および y = 1 の場合、分数はすでに整数です。 連分数は [5] であればよく、それより長いものは使用できません。 もう 1 つの特殊なケースは、114/1 や 1/114 など、除算ステップですぐにゼロの剰余が生成される場合です。 このような場合、シーケンスは非常に短くなり、相互ステップを常に追加しようとする不注意な実装により、余分なゼロや無効な項が誤って追加される可能性があります。 

## アプローチ

 この問題を考える素朴な方法は、定義を直接シミュレートすることです。 x/y の整数部分を繰り返し計算して減算し、残りの小数部分を反転して、小数が整数になるまで継続することができます。 これは概念的に明確です。各ステップで ai = Floor(x/y) が抽出され、(x, y) が (y, x - ai * y) に置き換えられます。 これが機能するのは、連分数の数学的定義を正確に反映しているためです。 

ただし、このプロセスは単なるトリックではなく、本質的にはユークリッド アルゴリズムを別の形式で記述したものです。 重要な観察は、減算ステップ x - ai * y が除算の剰余を正確に計算しており、(x, y) の交換が次の除数と剰余のペアに移動することに対応していることです。 これは、各連分数係数が Euclid のアルゴリズムの商に直接対応することを意味します。 

ブルートフォースの観点からは、潜在的に大きな中間分数に対して算術演算を繰り返すことが示唆されます。 ただし、各ステップは厳密に数値の 1 つを前の約数よりも小さい剰余に減らすため、ステップ数は対数であるユークリッド反復数によって制限されます。 

この等価性を認識すると、問題は、整数の除算と剰余の抽出を剰余がゼロになるまで繰り返し実行することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 連分数の直接シミュレーション | O(log min(x, y)) | お(1) | 承認済み |
 | ユークリッド アルゴリズムの解釈 | O(log min(x, y)) | お(1) | 承認済み |

 どちらのアプローチも本質的には同じですが、Euclid を介して表示すると、正確性が即座に確認され、実装が簡単になります。 

## アルゴリズムのチュートリアル

 現在のペア (x, y) が常に展開する必要がある残りの部分を表すという不変式を維持しながら、整数の除算を繰り返し適用します。

1. a = x // y を計算し、次の連分数係数として記録します。 これにより、現段階の小数部の整数部分が抽出されます。 
2. 剰余 r = x % y を計算します。 これは、x から y の完全な整数部分を削除した後に残ったものを表します。 
3. 剰余 r がゼロの場合、停止します。 この時点では、x/y は正確に整数であったため、連分数は最後の係数で終了します。 
4. それ以外の場合は、(x, y) を (y, r) に置き換えます。 これは、小数剰余を反転することに対応します。残りの分数は r/y であり、逆数をとると、次のステージで y/r が得られます。 
5. 終了するまでプロセスを繰り返します。 

各反復では、ユークリッドの意味で 2 番目の値 y が厳密に減少し、プロセスが確実に終了する必要があります。 

### なぜ効果があるのか

 すべてのステップで、分数 x/y を a + r/y として表します (a = Floor(x/y))。 これはまさに連分数の第 1 項です。 次に、残りの部分 r/y が反転されて分解が続行されます。 (x, y) → (y, r) の変換は、r/y を 1 / (y/r) に書き換えることに対応するため、連分数構造の下で分数の値を保存します。 Euclid のアルゴリズムでは、各ステップが正確に 1 つの除算ステップであるため、商のシーケンスは一意に決定され、剰余がゼロになったときに終了する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(x, y):
    res = []
    while True:
        a = x // y
        res.append(a)
        r = x % y
        if r == 0:
            break
        x, y = y, r
    return res

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        x, y = map(int, input().split())
        cf = solve_case(x, y)
        out.append(str(len(cf) - 1) + " " + " ".join(map(str, cf)))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コア機能`solve_case`ユークリッド除算ループを実装します。 各反復で商が追加されます`a = x // y`、これは連分数の係数に直接対応します。 残りは終了するか続行するかを決定します。 

主要な実装詳細はスワップです`(x, y) = (y, r)`これは、Euclid のアルゴリズムではなく分数の観点から考えると誤解しやすくなります。 このスワップがないと、プロセスは終了に向けて正しく進行しません。 

出力形式では係数間の遷移の数を出力する必要があるため、次のように出力します。`len(cf) - 1`それよりも`len(cf)`。 

## 実用的な例

 ### 例 1: x = 105、y = 38

 ユークリッドステップを追跡します。 

| × | y | a = x//y | r = x%y |
 | --- | --- | --- | --- |
 | 105 | 38 | 2 | 29 |
 | 38 | 29 | 1 | 9 |
 | 29 | 9 | 3 | 2 |
 | 9 | 2 | 4 | 1 |
 | 2 | 1 | 2 | 0 |

 収集された係数は [2, 1, 3, 4, 2] です。 

これは、各剰余が厳密に小さくなる完全ユークリッド降下を示しており、各係数が 1 つの除算ステップに対応していることが確認されます。 

### 例 2: x = 114、y = 1

 | × | y | a = x//y | r |
 | --- | --- | --- | --- |
 | 114 | 1 | 114 | 0 |

 1 ステップ後にすぐに終了し、[114] を生成します。 

これは、連分数に入れ子構造がない整数の場合を示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、x < y の場合であり、これにより直ちに a0 = 0 が生成されます。 たとえば、x = 1、y = 5 は 0 から始まるシーケンスを生成します。x // y は 0 になり、剰余ステップで小数部が (y, x) に反転され、正しく続行されるため、アルゴリズムはこれを自然に処理します。 

x = 1、y = 5 をトレースします。 

最初のステップでは、a = 0、余り 1 が得られます。次に (5, 1) に進み、5 を生成して終了します。 最後のシーケンスは [0, 5] で、これは正しい連分数形式です。 

もう 1 つの特殊なケースは、x = y の場合です。 この場合、a = 1 となり、剰余は直ちにゼロになります。 出力は [1] であり、これ以上の処理は必要ありません。 アルゴリズムは、余分なスワップや無効な係数を生成することなく、正しく停止します。
