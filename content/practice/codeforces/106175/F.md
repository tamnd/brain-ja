 ## 解決策
 ## 問題の理解

 私たちには最初の金額と固定の年数が与えられます。 毎年、私たちは複数の債券を保有することが許可されています。 各債券タイプには購入コストがあり、毎年一定の利益が得られます。 重要なルールは、債券は額面どおりに自由に売買でき、取引コストはかからないということです。 毎年、総資本は現在保有しているすべての債券の利息の合計によって増加し、その後、更新された資本を使用してポートフォリオのリバランスを行うことができます。 目標は、最終年の後に総資本が最大になるように、各種類の債券をいくつ保有するかを毎年決定することです。 

重要な構造は、蓄積された資本によるものを除いて、各年が決定に関して独立しているということです。 毎年の初めに、私たちは自分がどれだけのお金を持っているかを正確に知り、それを任意の組み合わせの債券に変換することができます。 1 年間保有すると確定的なリターンが得られ、その後は同じプロセスを繰り返します。 

債券の種類は最大10種類と制約が非常に少ないですが、年数は最大40年、初期資本は最大100万まで可能です。 これは、私たちが恣意的かつきめ細かいお金の分布を追跡できないことを直ちに示唆しています。 代わりに、州が現在の首都にすぎない動的プログラミングまたは州圧縮アプローチを期待する必要があります。 

素朴なアプローチでは、各年の債券の考えられるすべての組み合わせを検討しようとします。 お金を 1000 単位で離散化したとしても (債券の価値はすべて 1000 の倍数であるため)、資本の範囲は急速に拡大し、組み合わせは爆発的に増加します。 単年であれば、d ボンドがあり、それぞれを複数購入できる場合、可能なポートフォリオの数はすでに資本規模の組み合わせになります。 

先を見据えずに毎年貪欲な戦略を使用すると、微妙なエッジケースが発生します。 たとえば、当面の金利対価値の最適な比率を選択すると、将来の複利の可能性が低下する可能性があります。 レシオは若干悪いものの、将来の資本規模との整合性が良好な債券は、より高い長期成長につながる可能性があります。 

もう 1 つの失敗例は、分割投資が可能であると想定していることです。 この問題は暗黙的に整数の債券を強制するため、連続したナップザックのように扱うとリターンを過大評価し、無効なポートフォリオが生成されてしまいます。 

## アプローチ

 強引な解釈では、年ごとにシミュレーションし、各年で現在の資本を債券全体に分配する可能なすべての方法を列挙します。 固定資本 C および d の債券タイプの場合、sum(xi * value_i) ≤ C となるすべてのタプル (x1、x2、...、xd) を考慮し、結果として得られる利益を計算します。 これは、1 つを選択するのではなく、すべての構成をカウントする制限されたナップザックであるため、このような割り当ての数は、最悪の場合、C/1000 では指数関数的になります。 中程度の C であっても、これは実行不可能になります。 

重要な観察は、各年の決定は現在の資本のみに依存し、債券は線形制約を介さない限り相互作用しないということです。 これは、資本がどのように達成されたかを思い出す必要はなく、その価値だけを思い出す必要があることを意味します。 さらに重要なのは、固定資本の場合、1 年以内の最適配分の問題自体が、1 年後の総収益を最大化するという古典的な無制限のナップザックであるということです。 

したがって、問題は反復変換に帰着します。現在の資本 C が与えられた場合、各アイテム i が重み value_i と利益 value_i + Interest_i を持つ無制限のナップザックを解くことによって、1 年後の最大資本を計算します (1 年後には価値と利息を回収するため)。 この遷移を T 回繰り返します。 

これにより、問題全体が同じ DP 遷移を T 回適用することになり、各遷移は容量 C (毎年変わります) のナップザックになります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ポートフォリオのブルートフォース列挙 | 指数関数 | 指数関数 | 遅すぎる |
 | 年ごとの無制限のナップザック DP | O(T * C * d) | O(C) | 承認済み |

 ## アルゴリズムのチュートリアル

 dp[c] を、1 年間に与えられた利用可能な資本 c に対して債券を選択した後に達成可能な最大資本として定義します。 この移行により、c を債券に投資する最適な方法が計算され、1 年後に結果として得られた資本が返還されます。 

1. dp[0] = 0 で開始し、他のすべての値は 0 に初期化します。 

これは、お金がゼロでは何も投資できないことを表しています。 
2. 各債券タイプ i について、コスト value_i と戻り値 value_i + Interest_i を持つ項目として考慮します。 

これにより、財務操作が標準的な無制限のナップサック形式に変換されます。 
3. 固定年の場合、無制限のナップザック遷移を使用して新しい配列 best[c] を計算します。 

best[c] = max(best[c], best[c - value_i] + value_i + Interest_i - value_i)。これにより、資本使用量に対する純利益の追跡が簡素化されます。 

より直接的には、総コストが最大 c の項目を使用して達成可能な最大合計値として best[c] を計算します。ここで、各項目はその年末価値全体に寄与します。 
4. 今年の最良を計算した後、現在の資本 C を best[C] に設定します。 

このステップにより、分布全体が単一のスカラー状態に戻ります。将来の決定は総資本のみに依存するため、これで十分です。 
5. 指定された年数だけこのプロセスを繰り返します。 

中心的な考え方は、毎年、単一のスカラー状態遷移を伴う完全な再最適化問題であるということです。 

### なぜ効果があるのか

 重要な不変条件は、各年後、考えられる資本金額 c ごとに、dp[c] が c から始まる達成可能な年度末資本の最大値を正しく表すことです。 翌年は総資本のみに依存し、内部での構造には依存しないため、すべてのポートフォリオ構成を単一の値に安全に圧縮できます。 無制限のナップザックにより、毎年、債券の有効な組み合わせをすべて調査できるため、実行可能な投資戦略が見逃されることはありません。 各年の決定はスカラー資本価値を除いて独立しているため、この移行を繰り返すと最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N = int(input())
    for _ in range(N):
        C, T = map(int, input().split())
        d = int(input())
        bonds = [tuple(map(int, input().split())) for _ in range(d)]

        # scale down by 1000 since all values are multiples of 1000
        C //= 1000
        vals = []
        gains = []
        for v, r in bonds:
            v //= 1000
            vals.append(v)
            gains.append(v + r // 1000)

        cap = C

        for _ in range(T):
            dp = [0] * (cap + 1)

            for i in range(d):
                w = vals[i]
                val = gains[i]
                for c in range(w, cap + 1):
                    if dp[c - w] + val > dp[c]:
                        dp[c] = dp[c - w] + val

            cap = dp[cap]

        print(cap * 1000)

if __name__ == "__main__":
    solve()
```この実装では、すべての債券価値が 1000 の倍数であることが保証されているため、すべての貨幣価値を 1000 ずつ圧縮して状態の規模を縮小します。毎年、新しいナップザック DP が構築され、dp[c] には最大で c 単位の資本を使用して、達成可能な最高の年末資本が格納されます。 

内側のループは無制限のナップザック遷移であり、各ボンドを複数回使用できるように容量を上向きに反復します。 1 年が終了した後は、達成可能な全容量の投資結果の最大値のみを考慮するため、dp[cap] のみを保持します。 

利子を資本と同じ規模に換算する場合は、両方とも DP 単位で比較できる必要があるため、注意が必要です。 もう 1 つの微妙な点は、使用可能な資本が反復ごとに変化するため、dp を再利用しようとするのではなく、毎年再構築していることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(T * C * d) | 毎年、容量 C および d の項目に対して無制限のナップザックを実行します。 
| スペース | O(C) | DP アレイは 1 年に 1 つだけ |

 T ≤ 40 および d ≤ 10 という制約により、資本が 10^6 (10^3 にスケール) までであっても、アイテム数が少なく、構造化された移行により DP が引き続き実行可能であることが保証されます。

 ## 特殊なケース

 すべての債券の利息がゼロの場合、微妙なケースが発生します。 どの構成も価値を高めることができないため、DP は常に資本を正確に保存する必要があります。 すべての遷移値はコストに等しいため、アルゴリズムはこれを処理します。そのため、ナップザックは dp[c] を c を超えて改善することはありません。 

もう 1 つのケースは、結合タイプが 1 つだけ存在する場合です。 DP は毎年できるだけ多くのコピーを繰り返し購入するようになり、状態圧縮により反復ごとに最大倍数が正しく再計算されます。 

最後に、債券の規模に比べて資本が小さい場合、多くの DP エントリーはゼロのままです。 遷移は到達可能な状態のみをアクティブにし、dp[cap] は完全な状態の探索を必要とせずに常に最適な実行可能な構成を反映するため、アルゴリズムは引き続き機能します。
