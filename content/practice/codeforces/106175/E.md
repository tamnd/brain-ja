 ## 解決策
 ## 問題の理解

 2 人のプレイヤーが与えられ、それぞれが標準的なデッキから同じ枚数のカードを受け取ります。 両方のプレイヤーのカードはすでに固定されていますが、ゲーム開始前にカードを自由に並べ替えることができるのはイブだけです。 両方の列が固定された後、アダムの i 番目のカードとイブの i 番目のカードが対戦され、各ペアはその比較の勝者にちょうど 1 ポイントをもたらします。 

カードの比較は、単なる数値の比較ではありません。 まず、ランクが優先されます。ランクが同じでない限り、常に額面の高い方が勝ちます。 ランクが同じ場合、スートは厳密な階層を使用して勝者を決定します。ハートはすべてに勝ち、スペードはダイヤモンドとクラブに勝ち、ダイヤモンドはクラブに勝ち、クラブは他のすべてに負けます。 

課題は、イブのカードがアダムの対応するカードに対して勝つ位置の数を最大にするカードの順序を選択することによって、イブが保証できるポイント数を決定することです。 

重要な制約は、各プレーヤーがテスト ケースごとに最大 26 枚のカードを持ち、複数のテスト ケースが存在できることです。 デッキが小さい場合でも、順列の階乗数により、強引な順序付けは完全に不可能になります。 イブのカードのすべての順列を試してみようという単純な試みでは、爆発的に 26 枚になります。 実現可能な計算をはるかに超えた可能性があります。 

明らかではない問題は、スーツによって厳密な順序が作成されるため、ランクの平等が結果の対称性を意味しないことです。 ランクを比較するだけの不注意な解決策は、タイでのスーツの利点を利用して勝利を強制するイブの能力を過小評価することになります。 

小さな特殊なケースがこれを示しています。 アダムが「9H」、イブが「9C」を持っているとします。 ランクのみのアプローチでは平等とみなし、中立的なものとして扱いますが、ハートがクラブを支配しているため、実際にはイブが負けます。 逆に、「9S」対「9C」では、スペードを持っていればイブが勝ちます。 これは、比較が部分的なものではなく、完全に厳密な順序付けであることを意味します。 

## アプローチ

 この強引なアイデアは、イブのカードのすべての順列を試し、アダムの固定順序に対して彼女が何回勝つかを計算することです。 これは、考えられるすべての戦略を検討するため正しいですが、k での階乗時間がかかり、26 はおろか、k = 20 ではすでに不可能になります。 

問題の構造は、一致する解釈を示唆しています。 アダム側には k 個のポジションがあり、それぞれがイブからのカードを 1 枚だけ必要とし、各割り当てはイブがそのマッチアップに勝つかどうかに応じて 1 または 0 の利益をもたらします。 1 対 1 の割り当て制約の下で総利益を最大化したいと考えています。 

これは重みを使用した最大の 2 部マッチングですが、エッジごとのバイナリ ゲインに単純化されています。 各アダム カードは各イブ カードとペアにすることができ、勝利ペアの数を最大化して完全に一致するものを選択したいと考えています。 k が小さいため、ノードのユニット容量とエッジの重み 1 または 0 を使用した最大 2 部マッチングとしてこれをモデル化できます。 

標準的な変換は、これをフロー問題、または同等の重み付き割り当て問題として見ることです。 重みは 0 または 1 のみであるため、最小コスト最大フローの定式化は適切に機能します。一致が成功するたびにコスト削減に貢献し、損失を最小限に抑えることで合計勝利を最大化します。 

アダムの位置からイブのカードまでの二部グラフを構築し、すべてのアダム i をすべてのイブ j に接続し、そのペアでイブがアダムに勝つ場合はコスト 0、そうでない場合はコスト 1 を割り当てます。次に、ソースからアダム ノードを介してイブ ノードにシンクする k 単位のフローを送信します。 最小コストは損失を最小限に抑えることに相当するため、k からコストを引いた値がイブの最大の勝ちになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | O(k!) | O(k) | 遅すぎる |
 | 最小コスト最大流量の割り当て | O(k^3) 典型的な | O(k^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、完全なルール システムで 2 つのカードを比較し、Eve が勝つかどうかを判断する関数が必要です。

次に、各アダムの位置が左側のノード、各イブ カードが右側のノードとなるフロー ネットワークを構築します。 

1. すべてのカードを解析し、各カードをランク​​とスーツの優先順位から構成される同等の値表現に変換します。 これにより、エッジ構築中に高速な比較が可能になります。 
2. すべてのアダムの位置 i がすべてのイブ カード j に接続される 2 部グラフを構築します。 これにより、k² の候補割り当てが作成されます。 
3. 各ペア (i, j) について、イブのカード j がアダムのカード i に勝つかどうかを計算します。 存在する場合は、そのエッジにコスト 0 を割り当て、そうでない場合はコスト 1 を割り当てます。その理由は、「勝ちエッジ」を無料として扱い、「負けエッジ」をペナルティ付きとして扱うためです。 
4. ソース ノードからのエッジを、容量 1、コスト 0 の各 Adam ノードに追加します。これにより、各 Adam 位置が 1 回だけ使用されることが強制されます。 
5. 各 Eve ノードから、容量 1、コスト 0 のシンクにエッジを追加します。これにより、各 Eve カードが最大 1 回使用されることが強制されます。 
6. 正確に k 単位のフローを送信する min-cost max-flow を実行します。 各ユニットは、1 つのアダムの位置と 1 つのイブ カードのマッチングに対応します。 
7. このフローの合計コストは、負けた試合の数に等しくなります。 答えは、k からこのコストを引いたものです。 

重要なアイデアは、すべての強制割り当てがイブに勝利またはペナルティを与え、フローは貪欲なローカルの決定ではなく、最適なグローバルの組み合わせを選択するということです。 

### なぜ効果があるのか

 フローのどの段階でも、部分一致は、個別のアダムの位置に対する個別のイブ カードの有効な割り当てを表します。 完了したフローのコストは、まさにイブがアダムに勝つことができなかったペアの数です。 すべての Adam 位置は 1 回だけ一致する必要があるため、総コストを最小限に抑えることは勝利数を最大にすることと同じです。 ネットワーク構築により、すべての有効な割り当てが、損失の数に等しいコストの 1 つのユニット フローに正確に対応することが保証されるため、最適なフローは最適な順序を直接エンコードします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

rank_map = {str(i): i for i in range(2, 10)}
rank_map.update({'T': 10, 'J': 11, 'Q': 12, 'K': 13, 'A': 14})

suit_rank = {'C': 0, 'D': 1, 'S': 2, 'H': 3}

def parse(card):
    r, s = card[0], card[1]
    return rank_map[r], suit_rank[s]

def eve_beats(a, b):
    ra, sa = a
    rb, sb = b
    if ra != rb:
        return ra > rb
    return sa > sb

class MinCostMaxFlow:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, cap, cost):
        self.adj[u].append([v, cap, cost, len(self.adj[v])])
        self.adj[v].append([u, 0, -cost, len(self.adj[u]) - 1])

    def flow(self, s, t, maxf):
        n = self.n
        res = 0
        h = [0] * n

        while maxf > 0:
            dist = [INF] * n
            dist[s] = 0
            inq = [False] * n
            prevv = [-1] * n
            preve = [-1] * n

            dist[s] = 0
            q = [s]
            inq[s] = True

            while q:
                u = q.pop(0)
                inq[u] = False
                for i, e in enumerate(self.adj[u]):
                    v, cap, cost, rev = e
                    if cap > 0 and dist[v] > dist[u] + cost:
                        dist[v] = dist[u] + cost
                        prevv[v] = u
                        preve[v] = i
                        if not inq[v]:
                            inq[v] = True
                            q.append(v)

            if dist[t] == INF:
                break

            addf = maxf
            v = t
            while v != s:
                u = prevv[v]
                e = self.adj[u][preve[v]]
                addf = min(addf, e[1])
                v = u

            v = t
            while v != s:
                u = prevv[v]
                e = self.adj[u][preve[v]]
                e[1] -= addf
                self.adj[v][e[3]][1] += addf
                v = u

            res += addf * dist[t]
            maxf -= addf

        return res

def solve():
    k = int(input())
    adam = list(map(parse, input().split()))
    eve = list(map(parse, input().split()))

    N = 2 + k + k
    S = 0
    T = N - 1
    A0 = 1
    E0 = 1 + k

    mcmf = MinCostMaxFlow(N)

    for i in range(k):
        mcmf.add_edge(S, A0 + i, 1, 0)
    for j in range(k):
        mcmf.add_edge(E0 + j, T, 1, 0)

    for i in range(k):
        for j in range(k):
            cost = 0 if eve_beats(eve[j], adam[i]) else 1
            mcmf.add_edge(A0 + i, E0 + j, 1, cost)

    cost = mcmf.flow(S, T, k)
    print(k - cost)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```このソリューションは、各カードの比較をバイナリ コストにエンコードし、全体的な最適化を最小コスト フロー ソルバーに委任します。 主な実装の微妙な点は、ランクの平等によっても厳密な順序付けが行われるように、スーツのタイブレーカーを正しく定義することです。 

フロー構造により、各イブ カードは最大 1 回使用され、各アダム ポジションは 1 回だけ埋まることが保証されます。これは、イブのデッキを順列に再配置する要件と正確に一致します。 

## 実用的な例

 アダムが 2 枚のカードを持ち、イブが 2 枚のカードを持っているという小さなケースを考えてみましょう。 

入力:

 アダム: 9 時間 9 ℃

 イブ: 9S 9D

 ペアごとの結果を計算します。 

| アダム・アイ | イブ J | 比較結果 |
 | --- | --- | --- |
 | 9時間 | 9S | イブの勝ち |
 | 9時間 | 9D | イブの勝ち |
 | 9C | 9S | イブの勝ち |
 | 9C | 9D | イブは負けます |

 アルゴリズムは、可能であれば単一のペアリングの喪失を回避する割り当てを選択します。 

有効な最適なマッチングは次のとおりです。 

アダム 9H ↔ イブ 9S

 アダム 9C ↔ イブ 9D

 | ステップ | 割り当て | これまでの費用 |
 | --- | --- | --- |
 | 1 | 9時間→9秒 | 0 |
 | 2 | 9C→9D | 1 |

 合計コストは 1 なので、イブは 1 勝します。 

このトレースは、アルゴリズムが強いスーツの利点と同順位の組み合わせを優先し、構造が限られているためにやむを得ない場合にのみ犠牲を払うことを示しています。

 ## 特殊なケース

 1 つのエッジケースは、さまざまなスーツでフルランクの平等です。 たとえば、アダムとイブが両方ともすべてのスーツのうち 7 しか持っていない場合、順序は完全にスーツの階層によって決まります。 すべてのエッジには依然として厳密なコストがあるため、アルゴリズムはこれを処理します。そのため、フローは勝者のスーツの組み合わせのみを選択します。 

もう 1 つのエッジ ケースは、イブが厳密に優れたカードを持っているが、順序が逆である場合です。 貪欲な左から右への割り当てはひどく失敗する可能性がありますが、フローは一致をグローバルに再割り当てし、すべての支配的なカードが最適に使用されるようにします。 

3 番目のエッジ ケースは、イブが多くの勝ちカードを持っているものの、一致制約によって制限されている場合です。 たとえカードが多くのアダム カードに勝てるとしても、それを使用できるのは 1 回だけです。 フロー モデルの容量制約により、これが正しく適用されます。
