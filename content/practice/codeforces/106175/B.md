 ## 問題の理解

 から、整数座標を持つ正方形の屋根が与えられます。$(0,0)$に$(S,S)$、およびその内部のハッチング位置のセット。 リードを取り付ける屋根上の 1 点を選択する必要があります。 そのアンカー ポイントから、犬は中心が半径内にあるすべてのハッチに到達できます。$R$、 どこ$R$リードの長さです。 リードの長さは事前に固定されているわけではなく、アンカーポイントを選択した後に選択されますが、すべてのハッチをカバーするのに十分な長さと、リードが屋根の外に出ないように十分に小さい必要があります。 幾何学的用語では、リードは正方形の境界を越えて到達することはできないため、アンカー ポイントは、アンカー ポイントから境界までの最も遠い距離が少なくとも必要な半径になるようにする必要があります。 

タスクは、この点から正方形の境界までの最小距離が、少なくともこの点から任意のハッチングまでの最大距離となるような、ハッチング位置に等しくない整数の座標点が正方形内に存在するかどうかを判断することです。 有効なアンカー ポイントが複数存在する場合は、最も小さいアンカー ポイントが選択されます。$x$、まだ同点の場合は最小$y$。 

この問題を管理可能にする重要な制約は次のとおりです。$S \le 40$、したがって、可能なアンカーポイントの全体の検索空間は最大でも$41 \times 41 = 1681$テストケースごとの候補者。 最大 50 のハッチングでは、候補ごとの直接的な幾何学的評価は低コストであるため、ブルートフォース幾何学的スキャンはすでに限界内にあります。 

エッジの微妙な条件は、アンカー ポイントがハッチングと一致できないことです。 これにより、最適な中心が無効になる可能性があり、このチェックを忘れた単純な解決策では誤った答えが生成されます。 

もう 1 つの失敗モードは、「境界制約」とコーナーからの厳密な距離のみを混同していることです。 リードは正方形の内側に留まらなければならないため、中心や角ではなく、最も近い端までの距離を考慮する必要があります。 

## アプローチ

 簡単なアプローチは、すべての整数座標点を試すことです。$(x,y)$ハッチ位置を除く正方形の内側。 候補点ごとに 2 つの量を計算します。 

1 つ目は、必要なリードの長さです。これは、リードからの最大ユークリッド距離です。$(x,y)$あらゆるハッチに。 これにより、すべてのハッチに到達できるようになります。 

2 つ目は、犬を屋根の中に留めておくためのリードの最大の長さです。 犬は広場の外に出ることができないため、リードは広場からの距離を超えることはできません。$(x,y)$最も近い境界線まで。 この距離は$\min(x, y, S-x, S-y)$。 

ポイントが有効であるためには、必要な距離が境界距離以下である必要があります。 すべての有効な点の中で、辞書編集的に最小のものを選択します。 

ブルート フォース ソリューションは次のように評価します。$O(S^2)$候補者はそれぞれチェックアップ$H$ハッチ、につながる$O(S^2 \cdot H)$複雑。 と$S \le 40$そして$H \le 50$、これは最悪の場合でもテスト ケースごとに最大約 320 万回の距離計算であり、これは容易に許容できます。 

重要な観察は、探索空間が明らかに小さく離散的であるため、ボロノイ図や半径の二分探索などのジオメトリ最適化手法が必要ないということです。 この問題は基本的に、有界グリッド上での制約付きミニマックス実現可能性チェックです。

 ## アルゴリズムのチュートリアル

 正方形内のすべての可能な整数点を反復処理し、それが有効なリードの取り付け点として機能するかどうかをテストします。 

1. 候補点をすべて列挙する$(x, y)$と$0 \le x \le S$そして$0 \le y \le S$。 問題は整数座標に限定されているため、これはすべての法的な取り付け位置をカバーします。 
2. ハッチング位置と一致する場合、候補をスキップします。 ハッチにリードを直接取り付けることは明示的に禁止されているため、これが必要です。 
3. 残りの候補ごとに、からの最大距離を計算します。$(x,y)$ユークリッド距離を使用してすべてのハッチングに適用します。 この値は、すべてのハッチに到達するために必要な最小リードの長さを表します。 
4. この時点での最大許容リード長、つまり正方形の最も近い端までの距離を計算します。$\min(x, y, S-x, S-y)$。 これにより、リードが完全に屋根内に留まることが保証されます。 
5. 必要な距離が許容境界距離より大きい場合は、リードが屋根の境界を越えることになるため、この候補を破棄します。 
6. 候補が有効な場合は、辞書順に基づいて現在の最良の候補と比較します。$(x,y)$、小さい方が好ましい$x$、次に小さくなります$y$。 

すべての点を確認した後、有効な候補が存在しない場合は、「プードル」を出力します。 

### なぜ効果があるのか

 すべての有効な解は 2 つの独立した制約を満たす必要があります。つまり、すべてのハッチングをカバーする必要があり、境界までの距離を超えてはなりません。 このアルゴリズムは、考えられるすべての整数座標について両方の制約を正確にチェックするため、有効な候補が見逃されることはありません。 考えられる接続点の離散領域全体を徹底的に評価するため、すべての可能な接続点のうち辞書順で最初の有効な点が必要な答えであることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def dist2(x1, y1, x2, y2):
    dx = x1 - x2
    dy = y1 - y2
    return dx * dx + dy * dy

t = int(input())
for _ in range(t):
    S, H = map(int, input().split())
    hatches = []
    hatch_set = set()

    for _ in range(H):
        x, y = map(int, input().split())
        hatches.append((x, y))
        hatch_set.add((x, y))

    best = None

    for x in range(S + 1):
        for y in range(S + 1):
            if (x, y) in hatch_set:
                continue

            # max distance to any hatch (squared)
            need = 0
            for hx, hy in hatches:
                d = dist2(x, y, hx, hy)
                if d > need:
                    need = d

            # max allowed squared radius (distance to boundary)
            # compare squared carefully by squaring boundary distance
            bd = min(x, y, S - x, S - y)
            bd2 = bd * bd

            if need <= bd2:
                if best is None or (x, y) < best:
                    best = (x, y)

    if best is None:
        print("poodle")
    else:
        print(best[0], best[1])
```この実装では、浮動小数点の精度の問題を回避するために二乗距離を使用します。 機能`dist2`候補とハッチングの間の二乗ユークリッド距離を計算します。 これにより、平方根をとらずに直接比較できます。 

境界制約も二乗されます。 必須リーチと境界リーチは両方とも 2 乗されるため、精度エラーのリスクを回避し、比較は整数演算で行います。 

辞書編集上の選択は Python タプル比較によって処理され、自然に最小値が強制されます。$x$、次に最小$y$。

        S, H = map(int, input().split())
        hatches = []
        hatch_set = set()
        for _ in range(H):
            x, y = map(int, input().split())

 ## 特殊なケース

 すべての候補点が境界制約により無効であるか、ハッチングと一致する場合、微妙なケースが 1 つ発生します。 たとえば、ハッチがほぼすべての内部ポイントを占める小さなグリッドでは、ループはすべての可能性を正しく網羅し、「プードル」を返します。 

もう 1 つのケースは、最適なポイントが正方形の境界上にある場合です。 境界距離はエッジでゼロになるため、十分内側にある点のみが残ります。 アルゴリズムはこれを自然に処理します。`min(x, y, S-x, S-y)`は境界上でゼロになり、ゼロ以外の必要なリードの長さは即座に拒否されます。 

3 番目のケースは、複数の候補が同一の実現可能性を達成する場合です。 辞書編集上の比較`(x, y) < best`最小値の決定的な選択を保証します$x$最初に、次に最小の$y$追加の並べ替えや後処理は必要ありません。
