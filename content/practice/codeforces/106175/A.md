 ## 解決策
 ## 問題の理解

 私たちには、一部の短いパターンが部分文字列として禁止されている、小文字を使用する言語が与えられています。 少なくとも 1 つの禁止パターンを含む文字列は無効とみなされ、言語から削除されます。 すべての有効な文字列の中で、最初に長さを増やし、標準の辞書編集順で同じ長さ内に収めるという厳密な順序付けを課します。 

これにより、ランク 1 から始まる、明確に定義された有効な「単語」の無限シーケンスが作成されます。タスクは、このシーケンスに対する 2 種類のクエリをサポートすることです。つまり、有効な単語をそのランクに変換するか、ランクを対応する有効な単語に変換します。 

重要な問題は、有効性が文字ごとの独立性だけではなく、部分文字列制約にも依存することです。 単語は、その中のどこにも禁止パターンが出現しない場合にのみ受け入れられます。また、禁止パターンは重複したり、1 文字ほど短くなったりする可能性があるため、使用可能な文字列のスペースが大幅に削減される可能性があります。 

この制約は、すべての文字列の単純な列挙が不可能であることを示唆しています。 長さを最大 20 に制限したとしても、26 文字を超える文字列の総数は 26^20 と天文学的に大きくなります。 禁止された部分文字列を使用して枝刈りを行っても指数構造が残るため、いかなる解決策でも明示的な生成を回避する必要があります。 

禁止されたパターンに単一の文字が含まれる場合、微妙な特殊なケースが発生します。 その場合、辞書編集ツリーの枝全体が即座に消えます。 もう 1 つの注意が必要なケースは、「aaa」と「aa」など、パターンが重複する場合です。この場合、フィルタリングは無効な拡張子の二重カウントを正しく回避する必要があります。 3 番目の問題は、単語とランクの間のマッピングは単純な意味で接頭辞に依存しないことです。これは、文字を追加すると、禁止パターンを完了した場合に接頭辞が突然無効になる可能性があるためです。 

## アプローチ

 ブルートフォース手法では、すべての有効な文字列を辞書順に生成し、配列に格納し、インデックス付けまたは検索によってクエリに応答しようとします。 順序付けの定義が単純であるため、これは概念的に機能します。 ただし、長さを 20 に制限しても、分岐係数は 26 であるため、概念ツリー内のノードの総数は、最悪の場合でも 26^20 程度になります。 禁止された部分文字列を積極的に削除しても、十分な削減が保証されるわけではなく、すべての有効な単語を保存することは不可能であるため、メモリ使用量も爆発的に増加します。 

重要な観察は、有効性は最近の履歴、特に現在のサフィックスが禁止されたパターンに一致するかどうかのみに依存するということです。 禁止パターンの長さは最大 3 であるため、単語を拡張するときに覚えていればよいのは最後の 2 文字だけです。 これにより、問題は有限オートマトンにわたる状態遷移システムに変わります。各状態は現在の文字列の最後の最大 2 文字を表し、遷移は禁止パターンを完了していない新しい文字の追加に対応します。 

このオートマトンを作成すると、問題は、特定の状態から特定の残りの長さまでに、有効な完了がいくつ存在するかを数えることになります。 これにより、数字 DP スタイルのカウントを使用してランクを計算し、各ブランチに含まれる有効な単語の数に基づいて次の文字を取得するかを貪欲に決定することでランクから単語を構築することができます。 

ブルート フォースでは文字列を明示的に列挙しますが、最適解ではすべての有効な継続を状態グラフに圧縮し、生成ではなくカウントを実行します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | Exponential in length, ~O(26^20) | O(総単語数) | 遅すぎる |
 | オートマトン+DP | O(N_states * 26 * max_length + Q * 26 * max_length) | O(N_states * max_length) | 承認済み |

 ## アルゴリズムのチュートリアル

まず、禁止されたパターンを、文字の追加によって無効な部分文字列が作成されるかどうかを迅速にチェックできる構造に変換します。 すべての禁止文字列の長さは最大 3 であるため、現在の位置で終わる新しく形成された禁止パターンを検出するには、長さ 2 までのサフィックスを追跡するだけで済みます。 

状態を、部分単語の最後の文字を表す長さ 0、1、または 2 の現在の接尾辞として定義します。 どの状態からでも、「a」から「z」までの各文字を追加して、結果のサフィックスに禁止されたパターンが含まれているかどうかを確認します。 存在する場合、その移行は許可されません。 これにより、小さな状態セットにわたって決定的な遷移グラフが構築されます。 

次に、すべての状態と 20 までの残りの長さごとに、その状態から開始して有効な単語がいくつ形成できるかを計算します。 値 dp[state][len] が正確に len の長さの有効な完了の数を表す動的プログラミングを使用します。 繰り返しは、許可されているすべての次の文字を合計し、次の状態に移行することによって取得されます。 

このテーブルが計算されると、単語を左から右にスキャンすることで、単語からランクへのクエリに答えることができます。 各位置で、現在の状態からの遷移が許可されている辞書編集的に小さい文字をすべて考慮し、それらの分岐から始まる有効な補完の数を追加します。 次に、実際の単語の性質に沿って進み、続けます。 

ランクから単語へのクエリの場合、貪欲に答えを構築します。 空の状態と残りの長さ制限 20 から開始して、辞書順に文字を反復処理します。 候補文字ごとに、その接頭辞で始まる有効な単語の数を計算します。 カウントが残りのランクよりも小さい場合は、それを減算して続行します。 それ以外の場合は、その文字を選択して次の状態に進みます。 

これが機能する理由は、DP テーブルがあらゆるプレフィックス状態からの有効な補完の数を完全にキャプチャし、常にソートされた順序で文字を反復し、検索スペースを素のサブツリーに分割するため、辞書編集的な順序が保持されるためです。 有効な各単語はオートマトン内の 1 つのパスに正確に対応するため、過剰カウントや省略は発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

ALPHA = 26

def idx(c):
    return ord(c) - 97

def build_automaton(blocked):
    # states are all suffixes of length <= 2 that can appear
    states = {""}
    for ch in "abcdefghijklmnopqrstuvwxyz":
        states.add(ch)

    for s in list(states):
        for c in "abcdefghijklmnopqrstuvwxyz":
            states.add((s + c)[-2:])

    states = list(states)
    id_map = {s: i for i, s in enumerate(states)}

    n = len(states)
    trans = [[-1] * ALPHA for _ in range(n)]
    bad = [[False] * ALPHA for _ in range(n)]

    def contains_bad(s):
        for b in blocked:
            if b in s:
                return True
        return False

    for i, s in enumerate(states):
        for c in range(ALPHA):
            ns = (s + chr(97 + c))[-2:]
            full = s + chr(97 + c)
            if contains_bad(full[-3:]):
                bad[i][c] = True
            else:
                trans[i][c] = id_map[ns]

    return states, trans, bad

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        blocked = [input().strip() for _ in range(n)]

        states, trans, bad = build_automaton(blocked)
        S = len(states)

        MAXL = 20

        dp = [[0] * (MAXL + 1) for _ in range(S)]
        for i in range(S):
            dp[i][0] = 1

        for length in range(1, MAXL + 1):
            for i in range(S):
                total = 0
                for c in range(ALPHA):
                    if bad[i][c]:
                        continue
                    j = trans[i][c]
                    total += dp[j][length - 1]
                dp[i][length] = total

        def count_from(sid, length):
            return dp[sid][length]

        for _ in range(m):
            q = input().strip()

            if q[0].isdigit():
                k = int(q)
                res = []
                state = 0
                length = MAXL

                for _pos in range(MAXL):
                    for c in range(ALPHA):
                        if bad[state][c]:
                            continue
                        nxt = trans[state][c]
                        cnt = count_from(nxt, length - 1)
                        if cnt < k:
                            k -= cnt
                        else:
                            res.append(chr(97 + c))
                            state = nxt
                            length -= 1
                            break
                    else:
                        break

                out.append("".join(res))

            else:
                word = q
                state = 0
                length = len(word)
                rank = 1

                for i, ch in enumerate(word):
                    cidx = idx(ch)
                    for c in range(cidx):
                        if bad[state][c]:
                            continue
                        nxt = trans[state][c]
                        rank += count_from(nxt, MAXL - i - 1)
                    state = trans[state][cidx]

                out.append(str(rank))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、最初に長さ 2 までの接尾辞のコンパクトな状態空間が構築されます。 禁止パターンの最大長は 3 であるため、これで十分です。そのため、違反は最後の 3 文字から検出できます。これは、保存されている最後の 2 文字と次に追加された文字によって完全に決定されます。 

DP テーブルは、最大 20 の長さにわたってボトムアップで構築されます。各エントリは、すべての有効な次の遷移を集計します。 これは、両方のクエリ タイプを高速化するコアの事前計算です。 

Rank-to-Word クエリの場合、DP 値を使用して各ブランチに含まれる単語の数を決定し、辞書編集的な構築をシミュレートします。 word-to-rank クエリの場合、各文字位置で辞書編集的に小さいすべての分岐の数を累積します。 

## 実用的な例

 仕組みを説明するために、アルファベット {a、b、c} と禁止パターン「ab」を使用した簡略化された例を使用します。 

### 例 1: ランク付けする単語

 「ac」のランクを計算するとします。 

| 位置 | 現在の状態 | チェックされた文字 | アクション | 累計ランク |
 | --- | --- | --- | --- | --- |
 | 開始 | "" | - | 開始 | 1 |
 | 1 | "" | | さあ、次へ進みましょう | 1 |
 | 2 | "a" | b | 禁止された「ab」のためスキップ | 1 |
 | 2 | "a" | c | cを取る | 1 |

 この制約では、「ac」より前に辞書編集的に小さい有効な単語が存在しないため、結果は 1 になります。 

### 例 2: 単語へのランク付け

 3 番目の単語が必要だとします。 

| ステップ | 状態 | 候補者 | DP カウント | 選択 | 残り k |
 | --- | --- | --- | --- | --- | --- |
 | 1 | "" | a、b、c | a=2、b=1、c=... | | 3 |
 | 2 | "a" | a、b、c | a=1、b=無効、c=1 | c | 2 |

 正しい文字が見つかるまで、カウントが残り k よりも小さい分岐をスキップします。 

これらのトレースは、DP がどのように辞書編集空間をブロックに分割し、列挙せずに直接ナビゲーションできるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(S * 26 * 20 + Q * 26 * 20) | 状態と長さに対する DP の事前計算、およびアルファベットに対するクエリごとのスキャン |
 | スペース | O(S * 20) | 状態と残りの長さによってインデックス付けされた DP テーブル |

 状態空間は長さ 2 までのサフィックスのみに依存し、最大ワード長は 20 で制限されるため、小さくなります。これにより、テスト ケースの最大数であっても、前処理とクエリの両方が十分に制限内に保たれます。

 ## 特殊なケース

 重要な例外ケースの 1 つは、禁止パターンが 1 文字である場合です。 そのような状況では、オートマトンは開始状態からその文字を使用するすべての遷移を直ちにブロックする必要があります。 これらの遷移の dp エントリはゼロのままであり、カウントに寄与できないため、DP は引き続き機能します。 

もう 1 つのケースは、「aa」と「aaa」のような重複パターンです。 最後に追加された文字だけを検証する単純な部分文字列チェックは失敗しますが、状態ベースのサフィックス追跡により、最後の 3 文字に対するサフィックス チェックで「aaa」が検出されるため、「aa」を形成した後、それ以降の「a」は直ちに拒否されます。 

3 番目のケースは、クエリを最大境界に近いランクに設定する場合です。 ランクは最大 2e9 に達する可能性があるため、DP 値は、オーバーフローが比較に影響を与えることなく、大きなカウントを表現できなければなりません。 Python の整数を使用すると正確さが保証され、貪欲な減算ロジックにより、完全な列挙を必要とせずにカウントのみを比較することが保証されます。
