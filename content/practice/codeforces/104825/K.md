 ## 解決策
 ## 問題の理解

 10 進数や 2 進数のような固定基数ではないことを除いて、位置数値体系の記述のように機能する文字列が与えられます。 代わりに、各ポジションには独自の「キャリー ルール」があります。 位置に数字 x が含まれる場合、その位置は基数 x のように動作します。つまり、x に達すると 0 にリセットされ、1 が次の位置に繰り上がります。 

また、負でない整数 d も通常の 10 進数形式で与えられます。 タスクは、この混合基数システムで d を表現し、上位の位置が使用されていない場合は先行ゼロを含む正確に m 桁を生成することです。 

これをイメージするのに役立つ方法は、各ホイールに異なる数のスロットがあり、それらの容量が入力文字列 s の文字によって指定される走行距離計です。 

m ≤ 1000 という制約は、表現の長さが最大 ​​1,000 桁であることを意味するため、1 桁ごとに数値を 1 回処理するソリューションであれば、簡単に十分に高速になります。 2 番目のパラメータ n は計算自体には無関係なので、一度読み取ったら無視しても問題ありません。 

ここで最も一般的な失敗例は、システムを単一塩基による通常の塩基変換として扱うことです。 これは、s = "29" のような入力ですぐに中断されます。 最下位桁の基数は 9 ですが、次の桁の基数は 2 である可能性があるため、一律の基数解釈では構造が完全に失われます。 

もう一つの微妙な問題は方向性です。 左端の数字が最下位であると仮定すると、変換は逆になります。 たとえば、s = "23" および d = 5 の場合、桁上げの伝播方向によって位置の重みが変化するため、右から左ではなく左から右に解釈すると異なる剰余が生成されます。 

## アプローチ

 ブルートフォース解釈では、0 から d に達するまで数値をインクリメントし、毎回混合基数の数字を更新することをシミュレートします。 各増分には最大 m 個の位置にキャリーを伝播する必要があるため、最悪の場合のコストは d の m 倍に比例します。 d は 10^10 まで大きくなる可能性があるため、m が小さい場合でもこれは完全に不可能になります。 

システムの構造は、より直接的な解釈を示唆しています。 各位置は、数値を階乗数系または一般的な混合基数系に変換するのと同様に、最下位側から見たときに合計数がどのように拡大するかに独立して影響します。 増分をシミュレートする代わりに、繰り返し除算を使用して数字を直接抽出できます。 

重要な観察は、文字列 s が一連の塩基を定義し、d の表現がこれらの塩基に基づく d の混合基数分解であるということです。 これにより、剰余を取り、d を段階的に減らすことで各桁を計算できます。 

ブルート フォース アプローチは数値を時間の経過とともに変化するものとして扱うため失敗しますが、最適なアプローチは数値を静的な分解問題として扱います。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(d・m) | O(m) | 遅すぎる |
 | 混合基数分解 | O(m) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

1. 文字列 s の各文字を、対応する桁位置の整数の基数として解釈します。 標準の位置システムではキャリーが左方向に伝播するため、右端の文字が最下位の位置になります。 
2. 指定された 10 進数 d から開始します。これは、混合基数表現に分解する必要がある完全な値を表します。 
3. 位置を右から左に移動します。 各位置 i で、d を s[i] で割った余りとして数字を計算します。 これにより、数字がローカルの基本制約内で有効であることが保証されます。 
4. 位置 i の桁を抽出した後、s[i] による整数除算によって d を減算します。 これは、現在のポジションの寄与を除去し、残りの値をより高いポジションに伝播することをモデル化します。 
5. トラバーサル中に、抽出されたすべての数字を配列に格納します。 
6. すべての位置を処理した後、桁を元の順序で左から右に出力します。 

これが機能する理由は、各位置が位置システムの係数に寄与し、その重みがその右側のすべての基底の積によって動的に決定されるためです。 繰り返されるモジュロ演算と除算演算により、そのシステム内の係数が正確に計算され、グローバル値を維持しながら各桁がローカル制約を満たすことが保証されます。 

プロセス全体を通じて維持される不変条件は、処理位置 i の開始時に、変数 d が下位位置にまだ割り当てられていない残りの値を表し、この残りの値は、すでに処理された基底の接尾辞によって定義される構造に常に割り切れるということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    m, n = map(int, input().split())
    s = input().strip()
    d = int(input().strip())

    bases = [int(c) for c in s]
    res = [0] * m

    for i in range(m - 1, -1, -1):
        b = bases[i]
        res[i] = d % b
        d //= b

    print("".join(map(str, res)))

if __name__ == "__main__":
    solve()
```実装はアルゴリズムに正確に従います。 配列 res は最終位置に数字を格納するため、インデックス i に直接書き込むことで最後に反転することを避けます。 ループは m-1 の最下位位置から 0 まで実行され、正しいキャリー伝播方向が保証されます。 

よくある実装上の間違いは、モジュロを使用したまま左から右に処理することです。これにより、依存関係の構造が壊れます。 もう 1 つの微妙な問題は、各 s[i] が文字であり、算術演算の前に整数に変換する必要があることを忘れていることです。 

## 実用的な例

 s = "243" および d = 17 を考えてみましょう。右端の桁を基数 3、中央の桁を基数 4、左側の桁を基数 2 として解釈します。 

右から左に処理していきます。 

| ポジション | ベース | 現在の d | 数字 (d % ベース) | 新しい d (d // ベース) |
 | --- | --- | --- | --- | --- |
 | 2 | 3 | 17 | 2 | 5 |
 | 1 | 4 | 5 | 1 | 1 |
 | 0 | 2 | 1 | 1 | 0 |

 最終出力は 112 です。 

このトレースは、各ポジションが残りの値の一部をどのように消費するかを示し、合計値を維持しながら、どのポジションもローカルの基本制約を超えないようにします。 

ここで、s = "9999" および d = 123 について考えてみましょう。これは、固定長の標準の Base-9 表現のように動作します。 

| ポジション | ベース | 現在の d | 数字 | 新しいd |
 | --- | --- | --- | --- | --- |
 | 3 | 9 | 123 | 6 | 13 |
 | 2 | 9 | 13 | 4 | 1 |
 | 1 | 9 | 1 | 1 | 0 |
 | 0 | 9 | 0 | 0 | 0 |

 出力は0146です。 

これは、すべての塩基が等しい場合に、このメソッドがどのように自然に標準の塩基変換に還元されるかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    m, n = map(int, input().split())
    s = input().strip()
    d = int(input().strip())

    bases = [int(c) for c in s]
    res = [0] * m

    for i in range(m - 1, -1, -1):
        b = bases[i]
        res[i] = d % b
        d //= b

    return "".join(map(str, res))

# minimal case
assert run("1 1\n2\n0\n") == "0"

# simple mixed radix
assert run("3 1\n234\n10\n") == "102"

# all same base behavior
assert run("4 1\n9999\n123\n") == "0146"

# leading zeros needed
assert run("5 1\n22222\n3\n") == "00003"

 | --- | --- | --- |

 ## 特殊なケース

 d が 0 の場合、すべてのモジュロ演算で 0 が生成され、除算ではずっと 0 が維持されます。 たとえば、s = "2345" および d = 0 の場合、各ステップは桁 0 を計算し、d を 0 として保持し、完全にゼロで埋められた出力を生成します。 

d が初期の塩基と比較すると非常に小さいが、後の塩基よりは大きい場合、低い位置が最初にすべての値を吸収します。 たとえば、s = "234" および d = 2 は、右から左に処理されると数字 [0, 0, 2] を生成します。これは、最下位の基数のみが非ゼロの剰余に寄与するためです。 

s = "7777" のように、すべての基数が等しい場合、アルゴリズムは固定幅の基数 7 変換とまったく同じように動作し、混合基数が標準位置システムを置き換えるのではなく、標準位置システムを一般化することを確認します。
