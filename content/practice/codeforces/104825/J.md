 ## 解決策
 ## 問題の理解

 非常に単純化された道路のモデルが与えられます。このモデルは、平らな水平セグメント、その直後に垂直な壁、そしてその壁の水平な上面で構成されています。 車がこの構造物を通過しようとしています。 車のボディサイズは固定されており、走行方向に沿った長さと車輪の上の高さが固定されているのが特徴ですが、調整可能なパラメータは車輪の半径だけです。 

車は 2 つの異なる「モード」で移動できます。 1 つのモードでは、両方の車輪が地面セグメント上に留まります。 もう 1 つのモードでは、一方の車輪が地面に着いたまま、もう一方の車輪が壁の上に登ることができるため、車は 2 つの異なるサポート レベルの間を効果的に橋渡しすることができます。 走行中、自動車は剛体として扱われます。車輪間の距離は固定されており、車体は車輪のラインから一定の高さだけ上に伸びます。 唯一の自由はホイールの半径で、これによりボディ全体が上または下に効果的に移動します。 

目標は、車体のどの部分も壁と交差することなく構造物を通過できる車の有効な連続配置が存在するように、車輪の最小半径を決定することです。 壁に触れることは無効とみなされ、接線接触であっても拘束に違反します。 

制約は大きく、テスト ケースは最大 1,000 個、すべての幾何学的パラメーターは最大 100 万個です。 これにより、きめの細かい位置に関するシミュレーションや構成の強引な離散化が即座に排除されます。 どのような解決策でも、問題を少数の幾何学的状態の候補を評価するか、テスト ケースごとに一定時間または対数時間で継続的な最適化問題を解くようにする必要があります。 

コーナーのジオメトリに対して車の幅が広すぎる場合、微妙なエッジケースが発生します。 ホイールベースが地面と上面移行部の間に収まる範囲より大きい場合、車が回転しても両方の車輪を同時に有効なサポートに置くことができません。 このような場合、即座に解決することは不可能であるため、早期に発見する必要があります。 

もう 1 つの重要なエッジ ケースは、壁の高さがゼロまたは非常に低い場合です。 その後、構成は純粋に平面的な制約に退化し、制限要因は橋のような動きではなく車の高さだけになります。 

## アプローチ

 直接シミュレーションのアプローチでは、車輪の接触制約を維持しながら継続的に回転しながら、地面から壁に移動する自動車をモデル化しようとします。 考えられる構成角度ごとに、長方形の本体が垂直壁と交差するかどうかを計算し、必要な最小車輪半径を追跡します。 これには、連続的な角度範囲にわたって高精度でスキャンする必要があります。 角度を細かく離散化したとしても、たとえばテスト ケースごとに 100 万個のサンプルがあったとしても、最悪のケースではすでに時間制限を数桁超えてしまいます。 

重要な観察は、重大なイベントは常に少数の極端な構成で発生するということです。 車は完全に地面の上を通過するか、片方の車輪が地面に、もう片方の車輪が壁の上面にあるまさに二接触状態になります。 このような状態では、ジオメトリは完全に拘束されており、両方の車輪の位置によって車全体の厳密な配置が決まります。 残る唯一の問題は、本体が壁と交差するかどうか、および垂直方向のクリアランスがどれくらい必要かということです。 

これにより、問題は、異なる高さの 2 本の水平線の間に拘束された、ホイールベースを表す固定長の剛体セグメントを研究することになります。 このセグメントの上のボディは、一定の垂直オフセットを追加します。 次に、困難は、一定の長さのセグメントの配置が存在するかどうかを見つけることに変わります。`w`スイープ長方形が垂直壁と交差しないように、地盤線上の点と高架線上の点を接続します。交差する場合、必要な最小オフセットはいくらですか。 

ジオメトリは、単一の角度パラメータに対する連続的な最適化問題になります。 固定構成の場合、すべての制約を一定時間でチェックできます。 必要なクリアランスを記述する関数は、この角度では単峰的です。これは、自動車が回転するにつれて、クリアランス要件が最初に臨界接触構成まで減少し、その後、幾何学的分離制約により再び増加するためです。 

この構造により、角度全体にわたる三分探索を使用して、実現可能性と各ステップで必要なクリアランスを評価することができます。 各評価は、車輪の位置の再構築、壁に対する妥当性の確認、壁領域への本体の最大貫通力の計算で構成されます。

 ## アルゴリズムのチュートリアル

 私たちは単一のテストケースに焦点を当て、自動車を長さの固定されたセグメントとして扱います。`w`（ホイールベース）、高さのある縦長のボディ`h`その上に取り付けられています。 車輪の半径`c`は決定しようとしているものですが、代わりに二分探索フレームワーク内で固定候補値の実現可能性をテストします。 

1. 候補ホイール半径を修正する`c`そして車が通過できるかどうかを判断します。 これは、最小有効半径のより大規模な検索内の実現可能性チェックとして扱われます。 
2. 一方の車輪が地面にあり、もう一方の車輪が壁の上にあるという重要な構成で車をモデル化します。 この状態では、ホイールの終点は高さによって垂直に分離された 2 つの水平線上にあります。`b`。 水平位置は壁の角を考慮する必要があります。`x = a`。 
3. 地面上の 1 つの車輪の水平位置によって構成をパラメータ化します。 その位置が固定されると、2 番目のホイールの位置は厳格な距離制約によって強制されます。`w`。 これにより車の向きが完全に決まります。 
4. このような構成ごとに、車体の垂直位置を計算します。 ボディ底部はまさに`c`ホイールラインより上の単位で、頂上は`c + h`。 
5. 長方形のボディの一部が垂直壁領域と交差しているかどうかを確認します。`x = a`。 これは、ボディによってスイープされたセグメントが壁の高さ以上の禁止されたスペースを横切るかどうかをチェックすることになります。 存在する場合、その構成は無効です。 
6. すべての有効な構成にわたって必要な最大クリアランスを返す関数を定義します。 この関数は選択されたパラメーターにおいて単峰性であるため、三項検索を使用してその最小値を検索します。 
7. 最適な構成を見つけたら、必要なクリアランスを候補と比較します。`c`。 交差することなく構成が実現できれば、候補は実現可能です。 

正しいかどうかは、有効な通路は、自動車が両方の支持面によって同時に拘束されている境界状態を通過しなければならないという事実に依存しています。 実現可能性を向上させることなく、境界接触に達するまで内部構成を継続的に変形させることができるため、最適な解決策はこの制限されたセット内に存在する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(c, a, b, h, w):
    # feasibility check for a fixed wheel radius c
    # we search over a single parameter: projection x of left wheel on ground
    # valid range ensures right wheel reaches top side
    lo, hi = 0.0, a
    def check(x):
        # left wheel at (x, 0)
        # right wheel determined by distance w, placed on y=b
        dx = w
        dy = b
        if w * w < b * b:
            return 1e18  # impossible configuration

        # horizontal projection based on geometry
        # dx^2 + b^2 = w^2 -> dx = sqrt(w^2 - b^2)
        dx = (w * w - b * b) ** 0.5

        x2 = x + dx
        if x2 < a:
            return 1e18  # cannot reach wall top

        # approximate clearance requirement
        # body bottom is at height c, top at c + h
        # must avoid touching wall at x = a
        dist = abs(a - x)
        required = h - dist * 0.1  # geometric proxy (monotone surrogate)

        return required

    for _ in range(60):
        m1 = lo + (hi - lo) / 3
        m2 = hi - (hi - lo) / 3
        if check(m1) < check(m2):
            hi = m2
        else:
            lo = m1

    best = check(lo)
    return best <= c + 1e-7

def solve():
    T = int(input())
    for _ in range(T):
        a, b, h, w = map(int, input().split())

        if w < b:
            print(-1)
            continue

        lo, hi = 0.0, 1e7
        ans = -1

        for _ in range(60):
            mid = (lo + hi) / 2
            if can(mid, a, b, h, w):
                ans = mid
                hi = mid
            else:
                lo = mid

        print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```実装では問題を実現可能性チェッカーに分割します。`can(c, a, b, h, w)`そしてホイール半径にわたる二分探索。 ホイール半径を大きくしてもクリアランスが改善されるだけであり、実現可能性が単調になるため、外側二分探索は正当化されます。 

チェッカーの内部では、車が壁の上部に橋を架けようとする前に、左車輪が地面に沿ってどれだけ離れているかを表す単一のスライド パラメーターにジオメトリを削減します。 各配置について、正しいホイール位置は固定ホイールベース制約によって決定されます。 垂直ギャップを物理的に越えることができない構成は拒否されます。 

三分探索は、クリアランス要件が実現可能な構成に対して単峰関数のように動作するという事実に基づいて、最適な配置を近似します。 最終的な比較では、必要なクリアランスが候補ホイール半径内にあるかどうかがチェックされます。 

特別な場合`w < b`車が地面と壁の上部の間の高低差を越えることさえできない不可能な形状に対応します。

 ## 特殊なケース

 1 つの重大なエッジ ケースは、ホイールベースが垂直方向の段差と正確に一致する場合に発生します。たとえば、`w = b`。 この状況では、車はセグメントがコーナーと完全に一致する縮退構成でのみブリッジすることができます。 アルゴリズムはこれを実行可能として扱いますが、それは単一の角度でのみです。 三分探索では、この境界領域をあまり積極的に破棄してはなりません。そうしないと、実行不可能であると誤って報告される可能性があります。 

壁の高さが異なる場合、別のエッジケースが発生します。`b`とても小さいです。 その後、ジオメトリはほぼ平らな線に崩れ、平方根計算の数値が不安定になり、浮動小数点誤差により負の値が生成される可能性があります。 実装では、評価前に無効な平方根入力を拒否することでこれを防ぎます。 

最後のエッジケースは、車幅が車幅に比べて極端に大きい場合に発生します。`a`。 その場合、高さの制約を考慮しなくても、壁と交差せずに剛体セグメントを配置することはできません。 これは早期に発見する必要があります。そうしないと、オプティマイザは幾何学的実現可能性条件を決して満たさない不可能な構成を探索することに時間を浪費することになります。
