 ## 解決策
 ## 問題の理解

 各セルが空か単一の敵ユニットを含むグリッドが与えられます。 空のセルとグリッドの外側の領域は、すでに私たちが管理しています。 グリッドはすべての敵セルがまだ生きている状態で開始され、目標はすべての敵セルを排除することです。 

いつでも、少なくとも 1 つの味方セルに隣接する敵セルのみを攻撃できます。友好度はグリッド内のゼロ セルまたは外側の境界線から得られます。 このようなセルを攻撃する場合、その時点で残っている敵の構成の構造に応じたコストを支払います。コストは、セル自体の 1 ユニットに、除去時にまだ敵を含む 4 方向の隣接セルのそれぞれに追加のユニットを加えたものです。 コストを支払うと、その細胞は友好的になります。 

タスクは、総コストが最小になるようにすべての敵セルを除去する順序を選択することです。 

この制約により、グリッドのサイズは最大 1000 x 1000、つまり最大 100 万セルまで許可されます。 削除のたびに近隣カウントを動的に再計算しながらプロセスを段階的にシミュレートしようとするソリューションは、遅すぎます。 除去ごとに直線的な時間を実現するアプローチでも、おおよその結果は次のとおりです。$10^{12}$最悪の場合の操作は実行不可能です。 

微妙な点は、コストがグリッドの初期状態ではなく、現在の状態に依存することです。 このため、貪欲な注文やシミュレーションが必要であると考えたくなります。 もう 1 つの落とし穴は、実際にはコストに隠れた加法性があるにもかかわらず、BFS または境界順序でセルを削除するとエッジの寄与が複雑に変化すると仮定することです。 

エッジケースは主に構造に関するものです。 

すべての敵セルが孤立している場合 (たとえば、単一セルのチェッカー盤のようなパターン)、どのセルにも敵の隣接セルが存在しないため、すべての除去のコストはちょうど 1 です。 答えは 1 の数に等しい。 

完全に満たされた状態ですべてのセルが敵の場合$n \times m$グリッドでは、素朴な直観により、コストは削除順序に大きく依存すると思われるかもしれませんが、実際には、この構造により、順序に関係なく、すべての隣接するペアが 1 回だけ貢献することが強制されます。 

## アプローチ

 ブルートフォース手法では、すべての有効な削除命令を明示的にシミュレートします。 各ステップで、現在除去可能な敵セルをすべて特定し、それぞれを除去してみて、結果として生じるコストを再帰的またはバックトラッキングによって追跡します。 これは、正確なルール定義に従っているため、問題を正しくモデル化していますが、分岐係数が大きく、除去の順列の数が$(nm)!$、これは小さなグリッドでも天文学的に大きくなります。 有効なフロンティア セルのみを考慮してプルーニングした場合でも、状態空間は指数関数的なままになります。 

重要な観察は、コスト関数がローカルであり、セルおよび隣接関係にわたって分解されるということです。 各セルは、削除されるときに常に基本コスト 1 を提供します。 追加コストは、その時点でまだ敵となっている近隣諸国の数を数えることによって発生します。 時間の経過を追跡する代わりに、除去順序の 2 つのセルのうち後者のセルが処理されるときに、2 つの敵のセル間の各隣接が 1 回だけチャージされるものとして再解釈できます。 

これにより、問題は動的なプロセスから静的な計数問題に変換されます。つまり、各敵セルが 1 つ寄与し、隣接する敵セルの各ペアがもう 1 つ寄与します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 | O(nm) | 遅すぎる |
 | セルと隣接関係を数える | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 除去のシミュレーションを完全に回避し、代わりに初期グリッドから直接寄与を計算します。 

1. まず、グリッド全体をスキャンし、敵が含まれるセルの数を数えます。 すべての敵セルが正確に 1 回除去され、常に少なくとも 1 つのユニットを支払うため、これにより基本コストの貢献が得られます。 
2. 次に、各敵セルを検査し、その右隣と下隣のみをチェックします。 隣接する敵セルのペアごとに、追加コストが 1 つカウントされます。 各隣接関係は無向であるため、二重カウントを避けるために右と下のみをチェックします。 
3. ベース数と隣接数を合計して、最終的な答えを取得します。 

右方向と下方向のみを考慮する理由は、2 つの敵セル間のすべての隣接には正確に 2 つの端点があり、両側をチェックすると同じペアが 2 回カウントされるためです。 

### なぜ効果があるのか

 削除順序は任意ですが、固定されていると考えてください。 すべてのセルは、基本コストを 1 回だけ提供します。 次に、隣接する敵セル u と v のペアを考えます。そのうちの 1 つが最初に削除されます。 それが起こった場合、もう一方のセルは依然として敵であるため、最初のセルの除去にちょうど 1 つの追加コストが寄与します。 2 番目のセルが削除されると、最初のセルはすでに消滅しており、何も寄与しません。 したがって、隣接するすべてのペアは、順序とは関係なく、正確に 1 つのユニット合計に寄与します。 これにより、総コストは敵のセルの数と隣接する敵のペアの数を加算したものと等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
g = [list(map(int, input().split())) for _ in range(n)]

ones = 0
edges = 0

for i in range(n):
    for j in range(m):
        if g[i][j] == 1:
            ones += 1
            if i + 1 < n and g[i + 1][j] == 1:
                edges += 1
            if j + 1 < m and g[i][j + 1] == 1:
                edges += 1

print(ones + edges)
```コードは、応答のノード寄与分とエッジ寄与分への分解を直接実装します。 ネストされたループにより、すべてのセルが 1 回アクセスされることが保証されます。 小切手`(i + 1, j)`そして`(i, j + 1)`隣接ペアの一意のカウントを強制します。 境界条件はインデックス チェックによって自然に処理されるため、追加のパディングやセンチネル グリッドは必要ありません。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    g = [list(map(int, input().split())) for _ in range(n)]

    ones = 0
    edges = 0

    for i in range(n):
        for j in range(m):
            if g[i][j] == 1:
                ones += 1
                if i + 1 < n and g[i + 1][j] == 1:
                    edges += 1
                if j + 1 < m and g[i][j + 1] == 1:
                    edges += 1

    return str(ones + edges)

def run(inp: str) -> str:
    return solve(inp)

 ## 特殊なケース

 完全に空のグリッドは、スキャンによってどちらのカウンターもインクリメントされず、特別なロジックなしでゼロが生成されるため、自然に処理されます。 

単一の敵セルも、ベース カウントに 1 を寄与し、隣接寄与を生成する隣接セルがないため、正しく動作します。 すべての近隣チェックが保護されているため、アルゴリズムは無効なインデックスへのアクセスを試行しません。 

完全に塗りつぶされたグリッドは、正確さが最もわかりにくい場所です。 のために$n \times m$ブロックでは、すべての内部隣接が右方向と下方向のスキャンによって正確に 1 回カウントされ、削除順序に関係なく各エッジが単一のコスト単位に寄与するという考えと一致します。
