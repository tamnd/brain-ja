 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$各エッジには未知の整数の重みがあります。 ツリー構造は事前にわかっていますが、重みは隠されています。 情報を取得する唯一の方法は、対話型操作を介することです。2 つのノードを選択する場合があります。$u$そして$v$ただし、ツリー内のそれらの距離が正確に一致する場合に限ります。$k$。 このようなペアの場合、システムはそれらの間の一意のパスに沿ったすべてのエッジの重みの XOR を返します。 

目標は、最大でも次の値を使用してツリー内のすべてのエッジの重みを回復することです。$n$そのようなクエリ。 

この問題が標準的でない理由は、任意のパス クエリを取得できないことです。 親子関係や任意の距離を自由に調べることはできません。 単一の固定距離に制約されている$k$つまり、正確に横たわるノードのペアから抽出できる唯一の情報が得られます。$k$エッジが離れています。 この制限により、エッジを直接調査するのではなく、間接的にグローバル構造を再構築する必要があります。 

この制約は、クエリと前処理の両方において、あらゆるソリューションが線形または線形に近いものでなければならないことを示唆しています。 と$n \le 5 \times 10^4$、全対推論のようなもの、または$O(n^2)$探索は不可能です。 平$O(n \log^2 n)$クエリは高価であり、制限が厳密であるため、クエリを多用するアプローチは危険です。 

微妙なエッジケースが現れるのは、「距離-$k$「グラフ」は明らかにつながっていません。たとえば、中心のある星形の場合$1$そして葉を残します$2,3,4,5$、 もし$k=2$、葉のすべてのペアは距離 2 にあります。$k$が大きい場合、多くのノードには有効なパートナーがほとんどないか、まったく存在しない可能性があります。 すべてのノードが他の十分な数のノードとともに直接クエリできるという単純な仮定は、正確性を損なうか、クエリの制限を超える可能性があります。 

主な難点は、隠れエッジの重みがツリー上のポテンシャル関数のように動作するのですが、固定メトリック距離にあるノード間の XOR の差を観察することしかできないことです。 

## アプローチ

 直接的な試みは、エッジの重みを 1 つずつ再構成することです。 選択したルートからすべてのノードまでの XOR 距離がわかっている場合、すべてのエッジの重みは、そのエンドポイントのルート距離の XOR 差になります。 これは標準的なトリックです: 定義する$d[u]$ルートからルートへのパス上のエッジの重みの XOR として$u$。 それからエッジ$(u,v)$重さがある$d[u] \oplus d[v]$。 

問題はすべてを決定することになります$d[u]$、全体の XOR オフセットまで。 

任意のペアをクエリできれば、単純に次のように計算します。$d[u] \oplus d[v]$すべてのペアについて計算し、連立方程式を解きます。 ただし、値を取得できるのは次の場合のみです。$\text{dist}(u,v)=k$したがって、次の形式の制約のみがわかります。$$d[u] \oplus d[v] = \text{query}(u,v)$$制限されたペアのセット用。 

これにより、頂点がツリー ノードとなり、距離のあるペア間にのみエッジが存在するグラフが形成されます。$k$。 このような各エッジには、既知の XOR 制約が含まれています。 この補助グラフのスパニング ツリーを選択すると、すべてのグラフを割り当てることができます。$d[u]$1 つのルート値を固定し、スパニング ツリーに沿って制約を伝播することにより、値を調整します。 

したがって、実際のタスクは、「距離を超えて接続されたスパニング構造を構築する」ことになります。$k$すべてを列挙せずに「関係」$O(n^2)$ペア。 

ブルートフォースアプローチでは、離れた場所にあるすべてのペアを計算します$k$、最悪の場合は 2 次になります。 各ノードからツリー DP または BFS を使用したとしても、これはすぐに実行不可能になります。 

重要な観察は、この補助グラフのすべてのエッジが必要ないということです。 すべてのノードを接続するのに十分なエッジのみが必要です。 これにより、重心分解を使用して有効な距離の疎なセットを生成できるようになります。$k$ペアでも接続が確保されます。 

各重心はツリーを独立した部分問題に分割します。 すべての重心について、重心までの距離に基づいてノードをグループ化し、距離の合計が以下になる相補的なペアを探すことができます。$k$。 サブツリー間で慎重にペアリングすることで、$O(n)$合計で有用な候補ペア。それぞれが 1 つの有効なクエリに対応します。 

これらのペアを取得したら、クエリを実行し、制約グラフを構築し、BFS/DFS を実行してすべてを回復します。$d[u]$、最後にすべての元のエッジの重みを計算します。

 ## アルゴリズムのチュートリアル

 ### 1. ツリーの重心分解を構築します。 

再帰的に重心を選択し、ツリーをサブツリーに分割し、各サブツリーを個別に処理します。 この構造は、各ノードがのみに参加することを保証します。$O(\log n)$重心レベル。 

この分解の目的は、遠くにあるノードを検索するときに、$k$、ツリー全体ではなく、重心パーティション内でローカルに推論する必要があるだけです。 

### 2. 各重心について、距離バケットを計算します。 

重心から$c$、コンポーネント内のすべてのノードについて、そのノードまでの距離を計算します。$c$。 この距離をキーとしたバケットにノードを保存します。 

これにより、全長のパスを形成する可能性のある候補を迅速に特定できます。$k$なぜなら、重心を通過するパスは次を満たさなければならないからです。$$\text{dist}(u,c) + \text{dist}(v,c) = k$$いつ$u$そして$v$重心の異なるサブツリーに存在します。 

重心は、グローバルな距離条件を深さに関する単純な算術制約に変換するセパレータとして機能します。 

### 3. まばらな候補ペアを構築する

 各重心に対して、少数のペアを生成しようとします。$(u,v)$そのような$\text{dist}(u,v)=k$。 重心構造を通じて検証できるペアのみを考慮します。つまり、重心までの深さの合計が以下になる異なる子サブツリーからのノードです。$k$。 

このようなペアをすべて列挙するわけではありません。 代わりに、各ノードがすべての重心レベルにわたって一定数のペアのみに参加するようにしながら、ノードを貪欲に一致させます。 これにより、生成されるペアの総数が対数係数まで線形に保たれ、最終的なクエリ数が以下を超えないように積極的にプルーニングされます。$n$。 

選択された各ペアは 1 つの対話型クエリになり、返された XOR 値を制約として保存します。 

### 4. 制約グラフを構築する

 各エッジが 1 つのクエリされたペアに対応するグラフを構築します$(u,v)$、値の注釈が付けられている$x = d[u] \oplus d[v]$。 

このグラフは接続されるように、または少なくともツリーに属するすべてのノードにまたがるように設計されています。 接続性により、すべてのものに一貫した値を割り当てることができます。$d[u]$。 

### 5. ノードの電位を回復する$d[u]$任意のルートノードを選択して設定します。$d[root] = 0$。 次に、制約グラフに対して BFS を実行します。 エッジを横切るたびに$(u,v)$重さで$x$、ウェブ割り当て:$$d[v] = d[u] \oplus x$$ノードがすでに割り当てられている場合、一貫性のない再訪問はスキップされます。 

### 6. 元のエッジの重みを計算する

 最後に、元の木のエッジごとに$(u,v)$、出力します:$$w(u,v) = d[u] \oplus d[v]$$これで再構築は完了です。 

### なぜ効果があるのか

 核となる不変条件は、すべてのクエリが真のルートとノード間のポテンシャル間の正しい XOR 差異を定義することです。 すべての拘束エッジは、次の形式の有効な方程式を強制します。$d[u] \oplus d[v]$。 制約グラフはすべてのノードにわたって接続されているため、1 つの値を固定すると、エッジの重みを計算するときに打ち消されるグローバル XOR シフトまで他の値がすべて一意に決定されます。 したがって、再構築されたすべてのエッジの重みは、すべてのクエリおよびツリー構造と一致します。

import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

# In a real interactive setting, flush is required after every print.

def solve():
    n, k = map(int, input().split())
    edges = [[] for _ in range(n)]
    edge_list = []

    for i in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges[u].append((v, i))
        edges[v].append((u, i))
        edge_list.append((u, v))

    # centroid decomposition helpers
    parent = [-1] * n
    sub = [0] * n
    blocked = [False] * n

    def dfs_size(u, p):
        sub[u] = 1
        for v, _ in edges[u]:
            if v != p and not blocked[v]:
                dfs_size(v, u)
                sub[u] += sub[v]

    def dfs_centroid(u, p, nsz):
        for v, _ in edges[u]:
            if v != p and not blocked[v]:
                if sub[v] > nsz // 2:
                    return dfs_centroid(v, u, nsz)
        return u

    def collect(u, p, d, store, root):
        if d > k:
            return
        store.append((u, d))
        for v, _ in edges[u]:
            if v != p and not blocked[v]:
                collect(v, u, d + 1, store, root)

    queries = []
    from collections import defaultdict

    def decompose(root):
        dfs_size(root, -1)
        c = dfs_centroid(root, -1, sub[root])
        blocked[c] = True

        dist_nodes = defaultdict(list)
        dist_nodes[0].append(c)

        for v, _ in edges[c]:
            if blocked[v]:
                continue
            nodes = []
            collect(v, c, 1, nodes, c)
            for node, d in nodes:
                dist_nodes[d].append(node)

        # greedy pairing across buckets
        used = set()

        for d1 in list(dist_nodes.keys()):
            d2 = k - d1
            if d2 not in dist_nodes:
                continue
            if d1 > d2:
                continue

            a = dist_nodes[d1]
            b = dist_nodes[d2]

            i = j = 0
            while i < len(a) and j < len(b):
                u = a[i]
                v = b[j]
                i += 1
                j += 1

                if u == v:
                    continue

                if u in used or v in used:
                    continue

                used.add(u)
                used.add(v)
                queries.append((u, v))

        for v, _ in edges[c]:
            if not blocked[v]:
                decompose(v)

    decompose(0)

    # interactive queries (offline simulation placeholder)
    # In real solution, we would query and store XOR results.
    qval = {}

    def query(u, v):
        print("?", u + 1, v + 1)
        sys.stdout.flush()
        x = int(input())
        return x

    # In practice, we assume queries list is ready
    # and we now assign d values using BFS on query graph.

    adj = [[] for _ in range(n)]

    for u, v in queries:
        x = query(u, v)
        adj[u].append((v, x))
        adj[v].append((u, x))

    d = [-1] * n
    from collections import deque
    dq = deque([0])
    d[0] = 0

    while dq:
        u = dq.popleft()
        for v, w in adj[u]:
            if d[v] == -1:
                d[v] = d[u] ^ w
                dq.append(v)

    out = []
    for u, v in edge_list:
        out.append(str(d[u] ^ d[v]))

    print("!", " ".join(out))
    sys.stdout.flush()

def main():
    solve()

    main()

グラフが構築されると、BFS は XOR ポテンシャルを割り当てます。$d[u]$。 最後に、すべての元のエッジの重みがエンドポイント間の XOR 差として復元されます。 

微妙な部分は、貪欲なペアリングのステップです。これにより、値をグローバルに伝播するのに十分なグラフを接続しながら、直線的な数のクエリのみを作成することが保証されます。 

## 実用的な例

 ### 例 1

クエリを生成します。 

| ステップ | ペア | クエリ結果 | 既知の d 値 |

 | 2 | (2,4) | ×2 | d[2]=0、d[4]=x2 |

 次にエッジの重みを計算します。 

- (1,2) = d1 XOR d2
 - (2,3) = d2 XOR d3

 これにより、すべてのエッジが一意に再構築されます。

 ## 特殊なケース

 重要なエッジケースは、少数のノードのみが有効な距離を許容する場合です。$k$パートナー。 このような場合、単純な戦略ではすべてのノードを接続するのに十分な制約を生成できない可能性があります。 重心ベースの構築では、複数の分解にまたがって機能することでこれを回避し、まばらに接続された領域であっても、より高いレベルの重心を通じてリンクされるようにします。 

多くのノードが存在するが、距離に参加するのは小さなサブセットのみである場合、別のエッジ ケースが発生します。$k$ペア。 貪欲なマッチングにより、ノードが過剰に使用されることがなくなり、構築された制約グラフ全体の接続を維持しながら、クエリの急増を防ぐことができます。
