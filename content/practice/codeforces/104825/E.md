 ## 解決策
 ## 問題の理解

 一連の整数が与えられたので、それを連続した空ではないセグメントに切り分けたいと考えています。 すべてのセグメントは、ビット単位の XOR に関する制約を満たす必要があります。セグメント内のすべての要素の XOR は、指定されたしきい値より厳密に大きくなければなりません。$k$。 

有効な各パーティションには、いくつかのセグメントがあります。$m$。 パーティションを数えたり、何かを最小化したりする代わりに、次の値を合計する必要があります。$m^3$すべての有効なパーティションにわたって。 

したがって、タスクは単に「パーティションが可能かどうか」ではなく、「配列を有効な XOR より大きなセグメントに分割し、そのパーティションが使用するセグメントの数に応じて 3 次の重みを累積するためのあらゆる方法」です。 

入力サイズは次のとおりです$10^6$、次の二次関数は即座に除外されます。$n$。 平$O(n \log n)$ソリューションは慎重に設計する必要があり、セグメントの境界を明示的に列挙するソリューションは、パーティションの数が指数関数的であるため失敗します。 

微妙な困難は、条件がセグメント XOR にあるためであり、これは両端に依存します。 単純な期待としては、有効なセグメントのエンドポイントを事前に計算し、インデックスに対して DP を実行できるかもしれないということですが、有効な以前のカット位置のセットは、次のビット単位の比較により、すべての右エンドポイントに対して単調ではない方法で変化します。$k$。 

典型的な落とし穴は、貪欲な構造または 2 ポインター構造が存在すると仮定することです。 たとえば、左側の境界を修正し、XOR が超えるまで拡張しようとすると、$k$、XOR は拡張下で単調ではないため、これは役に立ちません。 

小さな失敗例:

 もし$a = [1, 2, 3]$そして$k = 2$、有効なセグメントは XOR に依存します。 

- [1] XOR 1 は 2 より大きくありません
 - [1,2] XOR 3 は有効です
 - [2,3] XOR 1 は無効です
 - [1,2,3] XOR 0 は無効です

 1 からの貪欲な拡張は [1,2] が良いことを示唆しますが、それは後のカットを制約するものではなく、異なる開始点が局所的な推論を妨げる方法で相互作用します。 

したがって、XOR 制約の下で以前のすべてのカット位置にわたる寄与を効率的に集約しながら、すべてのプレフィックスにわたるグローバル DP が必要です。 

## アプローチ

 ブルートフォース手法では、すべてのパーティションを列挙し、そのセグメント数を計算しようとします。 これは、カット位置を再帰的に選択し、各セグメントの XOR をチェックすることを意味します。 XORクエリがあったとしても、$O(1)$プレフィックス XOR を介した場合、パーティションの数は$2^{n-1}$したがって、計算は指数関数的に増大し、小さな値を超えると不可能になります。$n$。 

最初の構造の単純化は、パーティションをカット位置間の遷移として書き直すことです。 ポジションに対して DP を定義すると、すべての有効なパーティションがチェーンに対応します。$0 = x_0 < x_1 < \dots < x_m = n$、および各遷移$x_{i-1} \to x_i$セグメント XOR 条件が成立する場合に有効です。 

したがって、問題は、ノードが位置でエッジが有効なセグメントを表す DAG 内のパスにわたる重み付き合計になります。 重みはパス内のエッジの数にのみ依存します。 

重要な問題は、DP 状態が単なる「方法の数」ではないことです。$m^3$、これはパスの長さの完全な分布に依存します。 これにより、ウェイ数、セグメント数の合計、平方和、および立方体の合計など、DP 状態の複数の瞬間を維持する必要があります。 

2 番目の重要な観察は、遷移はプレフィックス値間の XOR のみに依存するということです。$$\text{xor}(l+1 \dots r) = px[r] \oplus px[l]$$したがって、エンドポイントごとに$r$、以前のすべてを集計する必要があります$l$次のような:$$(px[l] \oplus px[r]) > k$$これは、古典的な「XOR 値に制約があるセットに対するプレフィックス XOR」クエリです。 自然な構造は、プレフィックス XOR 値に対するバイナリ トライであり、挿入された各プレフィックスは DP 集合体を保持します。 

それぞれのポジションで$r$、以前のすべてのプレフィックスを 2 つのグループに分けてクエリします。$px[r]$は$\le k$、合計から減算します。 これにより、以前のすべての有効なカットの寄与をビットあたりの対数時間で計算できるようになります。 

最後の工夫は、各プレフィックスがカウントだけを格納するのではなく、セグメント カウント増分の 3 次展開に対応する 4 つの DP 集合のベクトルを格納することです。

 | 瞬間を使った DP + XOR トライ |$O(n \log A)$|$O(n \log A)$| 承認済み |

 ## アルゴリズムのチュートリアル

 プレフィックス XOR を定義します$px[i]$そして、左から右に段階的にソリューションを構築します。 各位置で、それをすべての有効なパーティションの最後のセグメントのエンドポイントとみなします。 

1. これまでに確認されたプレフィックス XOR 値に対するバイナリ トライを維持します。 各トライ ノードには、そのプレフィックスで終わるウェイの数、セグメント数の合計、平方和、セグメント数の 3 乗和の 4 つの集計値が格納されます。 
2. また、XOR 制約に関係なく、すべてのプレフィックスからの寄与を表す、以前のすべてのポジションの合計集計も維持します。 これにより、補完クエリが可能になります。 
3. ポジションごとに$i$、すべての有効な以前のカット位置からの寄与を計算します。$j$、最後のセグメントは$(j+1, i)$。 有効性は次によって決定されます。$$px[j] \oplus px[i] > k$$4. すべてのプレフィックスについてトライをクエリします。$j$そのような$px[j] \oplus px[i] \le k$、これをグローバル合計から差し引いて、有効な貢献度を取得します。 
5. 集計値を有効以上にする$j$なれ：$$f0, f1, f2, f3$$それぞれを表します:

 ウェイの数、セグメント数の合計、2 乗数の合計、3 乗数の合計。 
6. 新しいセグメントを追加すると、セグメント数が 1 増加します。これにより、モーメントは次のように変換されます。$$t \to t+1$$それで：$$(t+1)^3 = t^3 + 3t^2 + 3t + 1$$したがって、新しい集計を計算できます。$$newf0 = f0$$

$$newf1 = f1 + f0$$

$$newf2 = f2 + 2f1 + f0$$

$$newf3 = f3 + 3f2 + 3f1 + f0$$7. これらを位置の DP 状態に蓄積します$i$、次にこの状態を try under キーに挿入します$px[i]$。 
8. すべてのポジションを処理した後、答えは累積されます。$f3$位置で$n$。 

### なぜ効果があるのか

 すべての有効なパーティションは一連のプレフィックス インデックスに一意に対応するため、エンドポイント上の DP は重複することなくすべての可能性をカバーします。 このトライにより、各エンドポイントについて、有効な以前のカット位置のセットが正確に考慮されることが保証されます。 モーメント変換は、1 つのセグメントの追加によってどのように立体重みが変更されるかを正確に追跡し、集計の線形性により、正確さを失うことなく多くのパスからの寄与を組み合わせることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

class Node:
    __slots__ = ("ch", "f0", "f1", "f2", "f3")
    def __init__(self):
        self.ch = [None, None]
        self.f0 = 0
        self.f1 = 0
        self.f2 = 0
        self.f3 = 0

def add(node, val, d=19, f0=0, f1=0, f2=0, f3=0):
    cur = node
    for i in range(d, -1, -1):
        b = (val >> i) & 1
        if cur.ch[b] is None:
            cur.ch[b] = Node()
        cur = cur.ch[b]
        cur.f0 = (cur.f0 + f0) % MOD
        cur.f1 = (cur.f1 + f1) % MOD
        cur.f2 = (cur.f2 + f2) % MOD
        cur.f3 = (cur.f3 + f3) % MOD

def query_leq(node, val, k, d=19):
    # returns (f0,f1,f2,f3) over all px[j] such that px[j] xor val <= k
    if node is None:
        return (0, 0, 0, 0)

    def dfs(u, i, px, tight, tk):
        if u is None:
            return (0, 0, 0, 0)
        if i < 0:
            return (u.f0, u.f1, u.f2, u.f3)

        vb = (px >> i) & 1
        kb = (tk >> i) & 1

        res = [0, 0, 0, 0]

        for b in (0, 1):
            if u.ch[b] is None:
                continue
            xb = b ^ vb
            if tight:
                if xb < kb:
                    child = u.ch[b]
                    res[0] = (res[0] + child.f0) % MOD
                    res[1] = (res[1] + child.f1) % MOD
                    res[2] = (res[2] + child.f2) % MOD
                    res[3] = (res[3] + child.f3) % MOD
                elif xb == kb:
                    r0, r1, r2, r3 = dfs(u.ch[b], i - 1, px, 1, tk)
                    res[0] = (res[0] + r0) % MOD
                    res[1] = (res[1] + r1) % MOD
                    res[2] = (res[2] + r2) % MOD
                    res[3] = (res[3] + r3) % MOD
            else:
                child = u.ch[b]
                res[0] = (res[0] + child.f0) % MOD
                res[1] = (res[1] + child.f1) % MOD
                res[2] = (res[2] + child.f2) % MOD
                res[3] = (res[3] + child.f3) % MOD

        return tuple(res)

    return dfs(node, d, val, 1, k)

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    px = 0
    root = Node()

    # dp over prefix states aggregated in trie
    # initial: empty prefix
    add(root, 0, f0=1, f1=0, f2=0, f3=0)

    total_f0 = 1
    total_f1 = 0
    total_f2 = 0
    total_f3 = 0

    for i in range(1, n + 1):
        px ^= a[i - 1]

        # all previous prefixes
        # subtract those with xor <= k
        l0, l1, l2, l3 = query_leq(root, px, k)

        f0 = (total_f0 - l0) % MOD
        f1 = (total_f1 - l1) % MOD
        f2 = (total_f2 - l2) % MOD
        f3 = (total_f3 - l3) % MOD

        # transition (t -> t+1)
        nf0 = f0
        nf1 = (f1 + f0) % MOD
        nf2 = (f2 + 2 * f1 + f0) % MOD
        nf3 = (f3 + 3 * f2 + 3 * f1 + f0) % MOD

        add(root, px, f0=nf0, f1=nf1, f2=nf2, f3=nf3)

        total_f0 = (total_f0 + nf0) % MOD
        total_f1 = (total_f1 + nf1) % MOD
        total_f2 = (total_f2 + nf2) % MOD
        total_f3 = (total_f3 + nf3) % MOD

    print(total_f3 % MOD)

if __name__ == "__main__":
    solve()
```コードは、プレフィックス XOR のグローバル トライを維持し、それぞれに DP 集合体で注釈が付けられます。 位置ごとに、「不正な XOR」領域を減算して、有効な以前の状態を計算します。 多項式展開は、1 つのセグメントの追加による体積の重みの増加を処理します。 

最もデリケートな部分はモーメント更新です。これは展開から直接派生します。$(t+1)^3$係数が欠落していると、最終的な累積が中断されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのプレフィックス XOR 値が同一であるか、高度にクラスター化されている場合です。 その状況では、多くの XOR 比較が定数値に崩壊し、トライは 1 つのブランチでの密集した蓄積に退化します。 すべての集計がすべてのノードに保存されるため、アルゴリズムは引き続き正しく動作し、偏った挿入でも寄与が失われることはありません。 

もう一つのケースは次のような場合です。$k = 0$。 この場合、XOR が厳密に 0 より大きいセグメントのみが有効になります。 単純な実装では、ゼロ XOR セグメント、特に空のプレフィックス遷移が誤って含まれる可能性があります。 try クエリは明示的に分離します$\le k$それを合計から減算するため、ゼロに等しい XOR は正しく除外されます。 

3 番目のケースは、すべての要素がゼロの場合です。 すべてのセグメントの XOR は 0 であるため、有効なセグメントは存在せず、解釈によっては、有効なパーティションのみが縮退または存在しません。 DP は当然、空ではないすべてのセグメントに対してゼロの寄与を生成し、最終的な累積三次和はゼロのままになります。
