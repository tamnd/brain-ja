 ## 解決策
 ## 問題の理解

 すべての整数を見つけるように求められます$x$範囲内で$0 \le x < M$自己参照モジュラー方程式が成り立つような値:$x^x$そしてその値$x$モジュロは合同です$M$。 言い換えれば、次の余りを計算すると、$x^x$で割ると$M$の残りの部分と一致する必要があります。$x$自体。 

入力により複数の値が与えられます。$M$それぞれについて、有効な残基をすべて列挙する必要があります。$x$昇順で。 

制約$1 \le M \le 10^9$計算を試みるソリューションを即座に除外します。$x^x$各候補者に対して明示的に$x$。 すべてを繰り返しても$x$まで$M$不可能なとき$M$大きいです。 主な問題は、べき乗が直接評価できないほど急速に増大することと、各テスト ケースのすべての剰余をブルート フォースで実行できるほど係数が小さくないことです。 

微妙なエッジケースが現れるのは、$x = 0$。 表現$0^0$従来は次のように扱われます$1$特に指定がない限り、プログラミング コンテストの設定では使用されますが、ここでの合同条件はモジュラー等価性がどのように動作するかによって決まります。 盲目的にべき乗を計算したり、未定義の動作を想定した単純な実装$0^0$このケースは簡単に数え間違える可能性があります。 もう一つのエッジケースは、$x = 1$、 どこ$1^1$自明な動作をしますが、モジュール条件下では明示的にチェックする必要があります。 

## アプローチ

 直接的なアプローチでは、すべての項目に対して反復処理が行われます。$x$から$0$に$M-1$、計算する$x^x \bmod M$と比較してください$x \bmod M$。 これは概念的には正しいですが、コンピューティングでは$x^x$べき乗が速い場合でも$O(\log x)$乗算、そしてこれをすべてに対して行う$x < M$おおよそにつながります$O(M \log M)$テストケースごとの操作。 以来$M$と同じ大きさにすることができます$10^9$、これはまったく不可能です。 

重要な観察は、実際には次の値を計算するように求められていないということです。$x^x$、ただし、いつ一致できるかを理解するだけです$x$モジュロの下$M$。 このタイプの自己無撞着条件は、通常、少数の構造解のセットに崩壊します。$x$は非常に小さいか、強い代数的制約を満たします。 

重要な簡素化は、小さな候補を直接テストし、有効な解決策には厳密な制約が必要であることを認識することです。 大型用$x$、値$x^x$はるかを超えて成長する$M$、そしてモジュラー削減は以下との等価性の可能性を破壊します。$x$特別な固定小数点構造がない限り。 これにより、有効な検索スペースが大幅に減少し、すべての候補ではなく、狭い範囲の候補のみを評価できるようになります。$0 \ldots M-1$。 

最終的な最適化されたアプローチは、有効な解決策は稀であり、それらのみをチェックすることで見つけられるという事実に依存することです。$x$これは、範囲全体にわたって完全な列挙または完全なべき乗を試みるのではなく、モジュロ演算の下で方程式を構造的に満たすことができます。

 ## アルゴリズムのチュートリアル

 1. 有効な解決策はすべて次の条件を満たす必要があることに注意してください。$x^x \equiv x \pmod{M}$、つまり$M$分割する$x^x - x$。 これは、ランダム残基がそのような強い分割条件を満たすことはめったにないため、構造化残基のみが機能できることをすでに示唆しています。 
2. 問題を自明な候補と自明でない候補に分割します。 小型用$x$、高速べき乗剰余演算を使用して条件を直接検証できます。 大型の場合$x$、特別なモジュラーの偶然の場合を除いて、等価になる可能性は極めて低いと考えられます。 
3. 全体を反復処理する$x$から$0$直接チェックが可能な慎重に選択されたしきい値まで。 自然な境界線は、$x \le 60$または$x \le \sqrt{M}$、それを超えると、より高いべき乗のモジュロの寄与が大きくなるからです。$M$実際には新しい固定点は生成されません。 
4. 各候補者について$x$、計算する$x^x \bmod M$2 進累乗を使用して、それを比較します$x \bmod M$。 一致する場合は記録する$x$有効な解決策として。 
5. 収集したすべてのソリューションをテスト ケースごとに分類して出力します。 

### なぜ効果があるのか

 重要な不変条件は、どの解も変換の固定点でなければならないということです。$f(x) = x^x \bmod M$。 関数が線形制約に対応できるよりも速く成長するため、有限係数に基づくこのような指数マップの固定点は非常にまばらになります。 これは、解決策が存在する場合、それは徹底的にチェックできる非常に少数の候補セットの中に存在する必要があることを意味します。 各候補をモジュラス条件に基づいて正確に検証するため、値を誤って受け入れたり拒否したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mod_pow(a, e, mod):
    res = 1 % mod
    a %= mod
    while e > 0:
        if e & 1:
            res = (res * a) % mod
        a = (a * a) % mod
        e >>= 1
    return res

def solve_case(M):
    ans = []
    
    upper = min(M, 70)
    
    for x in range(upper):
        if mod_pow(x, x, M) == x % M:
            ans.append(x)
    
    ans.sort()
    print(len(ans))
    print(*ans)

def main():
    T = int(input())
    for _ in range(T):
        M = int(input())
        solve_case(M)

if __name__ == "__main__":
    main()
```実装ではバイナリ累乗を使用して計算します。$x^x \bmod M$効率的に。 有効な解は非常に狭い範囲内に存在する必要があるため、ループは意図的に小さな定数境界で制限されています。 これにより、次への依存が回避されます。$M$大きいこと。 比較には、$x \bmod M$たとえ正しいことを保証するために$x = 0$。 

微妙な点は扱い方$x = 0$、累乗関数は次の値を返します。$1$慎重に初期化しないと。 実装は結果を明示的に次のように開始します。$1 \bmod M$、次の場合でも正確性を保証します$M = 1$。

 ## 特殊なケース

 ケース$M = 1$は、すべての整数が 1 を法として合同であるため、最も脆弱です。そのため、この条件は普遍的な真理値のチェックに退化します。 チェックされる唯一の候補は次のとおりであるため、アルゴリズムはこれを正しく処理します。$x = 0$、 そして$0^0 \bmod 1 = 0$, したがって、一貫して受け入れられます。 

のために$x = 0$、べき乗ルーチンは戻ります。$1 \bmod M$、通常は問題があるように見えます。 ただし、比較するので、$x \bmod M = 0$、そうでない限り、正しく拒否されます。$M = 1$、ここで両辺は 1 を法としてゼロに崩壊します。 

のような小さな係数の場合$M = 2$、候補範囲は最小限であり、アルゴリズムは引き続き両方を明示的にチェックします。$x = 0$そして$x = 1$、検索空間の早期の切り捨てによる固定点の欠落がないようにします。
