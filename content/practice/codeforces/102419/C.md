 ## 問題の理解

 2 つの値から始めます。`x = 0`そして`a = 1`、作りたい`x`指定されたターゲットと等しい`n`できるだけ少ない操作で。 最初の操作では、現在の値が加算されます。`a`に`x`。 2 番目の操作では、最初に置き換えます`a`流れによって`x`、次にこれを新しく追加します`a`に`x`、その効果は次のとおりです。`(a, x)`の中へ`(x, 2x)`。 タスクは、すべてのテスト ケースに必要な最小限の操作数を出力することです。 元の問題には最大 50 個のターゲットがあり、それぞれ最大で`10^9`。 

バウンド`n <= 10^9`～に比例するものを除外する`n`テストケースごとに。 ユニットごとに 1 つの操作を必要とする単純なシミュレーションでも、1 つのターゲットに対して最大 10 億の操作が必要になりますが、これは 1 秒の制限をはるかに超えています。 シーケンスを明示的に構築するのではなく、演算の算術構造を活用する必要があります。 テストケースの数はわずか 50 なので、`O(sqrt(n))`ケースごとの因数分解は簡単に十分に高速です。 

注目に値する 2 つの特殊なケースがあります。 のために`n = 1`、答えは`1`、最初の加算が変化するため`x`から`0`に`1`。 素因数に基づく式では、これを個別に処理する必要があります。`1`には素因数がありません。 のために`n = 2`、答えは`2`: 最初に取得`x = 1`、次に 2 番目の操作を使用して 2 倍にします。 素因数の寄与のみを返す不注意な実装では、`1`したがって、最終的な式の追加の定数は必須です。 

## アプローチ

 直接的な総当たりアプローチであらゆる状態を処理できる`(a, x)`ノードとして実行し、そこから両方の操作を試してください。 便利な操作が増えるたびに`x`、幅優先検索では、最終的に次の最短パスが見つかります。`n`。 問題は探索空間のサイズです。 最大でも長さの操作シーケンスだけを考慮した場合でも、`n`、あるかもしれません`2^n`異なる操作文字列。 のために`n = 10^9`、それはまったく不可能です。 最初の操作を繰り返し使用するさらに単純な総当たり戦略では、正確に`n`これもすでに大きすぎます。 

有益な観察は、次の事実から得られます。`a`常に分裂する`x`。 最初は`a = 1`分割する`x = 0`、そして追加`a`可分性を保ちます。 2回目の操作が変わります`(a, x)`に`(x, 2x)`、したがって、再び割り算が保存されます。 

現在の状態が`x = ka`。 最初の操作を 1 回実行すると、比率は次のように変化します。`k`に`k + 1`。 最終的に 2 番目の操作を使用する場合、現在の値は`x`にコピーされます`a`そして2倍になりました。 これは、一連の演算全体が、累積値に整数係数を乗算するものとして解釈できることを意味します。 

その因数分解の視点が鍵となります。 ターゲットを素因数の積として書きます

 [
 n = p_1p_2\cdots p_k。 
】

 中間の素因数ごとに`p`、次のようにして紹介できます。`p - 1`操作。 最後の素因数に必要なのは`p - 2`最後の倍加フェーズ後の追加。 から始まる`1`最初の倍増フェーズに入るには 2 回の操作が必要です。 結果の合計は、

 [
 2 + \sum_{i=1}^{k-1}(p_i-1) + (p_k-2)
 = 1 + \sum_{i=1}^{k}(p_i-1)。 
】

 同じ表現が最適であるだけでなく、単に達成可能であるというわけではありません。 すべての整数に対して`m >= 2`、定義します

 [
 S(m)=\sum (p-1)、
 】

 ここで、合計は次のすべての素因数にまたがります。`m`、多重度があります。 我々は持っています`S(m) <= m - 1`。 各中間乗算因子`m`少なくとも費用がかかる`m - 1`、最初の要素のコストはそれより 1 つ多く、最後の要素のコストは 1 つ少なくなります。 すべての要素にわたってこれらの不等式を組み合わせると、下限が得られます。`S(n) + 1`。 上記の構造はまさにその限界に達しています。 

したがって、問題全体は素因数分解に帰着します。

 ## アルゴリズムのチュートリアル

 1. もし`n = 1`、 戻る`1`。 初期値を 1 回追加するだけで目標に到達します。`a = 1`。 
2.セット`answer = 1`。 これは式の定数項です`1 + S(n)`。 
3. 要因`n`約数を試すことで`2`上向きにしながら`p * p <= n`。 いつでも`p`分割する`n`、 追加`p - 1`答えと分け方`n`による`p`。 同じ素数が複数回発生する可能性があるため、割り算を繰り返します。 
4. ループ後、残りの値が`n`より大きい`1`、プライムです。 追加`n - 1`答えに。 
5. 結果の回答を印刷します。 

### なぜ効果があるのか

 無駄な初期操作後の有効なシーケンスを考慮します。`x = 0`は削除されました。 なぜなら`a`常に分裂する`x`、現在の状態を次のように書きます`x = ka`。 連続初回操作増加`k`1つずつ。 2 番目の操作が使用される場合、現在の値は`x`新しいものになります`a`、 そして`x`は古い値の 2 倍になります。 したがって、2 つの 2 秒間の操作間のシーケンスのすべての部分が、最終値の乗算係数に寄与します。 

任意の整数の場合`m >= 2`、その素因数の寄与は満たされます。`S(m) <= m - 1`。 中間要因`m`少なくとも費用がかかる`m - 1`、したがって少なくとも費用がかかります`S(m)`。 初期要素には少なくともコストがかかります`S(m) + 2`、最後の要素には少なくともコストがかかります`S(m) - 1`。 すべての因子にこれらの境界を追加すると、少なくとも次のようになります。`S(n) + 1`操作。 

逆に、次の素因数分解を行ってください。`n`。 から始める`x = 1`。 2 番目の操作を使用して 2 倍化状態に入ります。 最後の素因数を除くすべての素因数に対して、次を使用します。`p - 2`加算に続いて係数を導入する 2 番目の演算`p`の費用で`p - 1`。 最後の素因数には、次を使用します。`p - 2`さらに倍加することなく追加できます。 合計はまさに`1 + S(n)`。 したがって、この式は達成可能であり、かつ最小でもあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n):
    if n == 1:
        return 1

    answer = 1
    p = 2

    while p * p <= n:
        while n % p == 0:
            answer += p - 1
            n //= p
        p += 1

    if n > 1:
        answer += n - 1

    return answer

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        out.append(str(solve_case(n)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```の`solve_case`関数は特別な値を処理します`1`初め。 他のすべてのターゲットについて、`answer`から始まります`1`、証明された式の定数項を表します。 

因数分解ループは、現在の残りの値の平方根までの可能なすべての除数を試行します。 除数が見つかると、内側のループはその素数のすべての出現を削除し、追加します。`p - 1`発生ごとに 1 回。 例えば、`12 = 2 * 2 * 3`貢献する`1 + 1 + 2`。 

ループ後、残りの値が より大きい`1`因数は最大でもその平方根を持つことができないため、それ自体が素数でなければなりません。 追加`n - 1`最後の素因数を処理します。 

使用する`p * p <= n`の代わりに`p <= sqrt(n)`浮動小数点演算を回避し、因数が削除されるとさらに厳密になります。 ここでは Python の整数にはオーバーフローの問題はなく、試算の最大の約数はわずか約です。`31623`。

 ## 特殊なケース

 のために`n = 1`、入力は`1`アルゴリズムはすぐに戻ります`1`。 素因数がないため、素因数分解は試行されません。 直接的なシーケンスは単純に、`(1,0) -> (1,1)`したがって、特殊なケースは実装の便宜ではなく正確です。 

のために`n = 2`、因数分解は`2`。 式は次のようになります`1 + (2 - 1) = 2`。 順序は`(1,0) -> (1,1) -> (1,2)`。 定数を忘れた解決策`1`1 回の操作で十分であると誤って主張することになります。 

のために`n = 4`、繰り返される因数分解は、`2 * 2`。 アルゴリズムは追加します`1`最初の答えを 2 回繰り返すと、`3`。 対応する操作は、`x = 1`、 それから`x = 2`、その後 2 番目の操作が変更されます`(a,x) = (1,2)`の中へ`(2,4)`。 これにより、素因数の繰り返しに関係する間違いが検出されます。 

のために`n = 15`、主因数は次のとおりです。`3`そして`5`、与える`1 + 2 + 4 = 7`。 最適なシーケンスの 1 つは、`x = 1`、 それから`x = 2`、 それから`x = 3`、次に 2 番目の演算により次の結果が得られます。`x = 6`、続いて次を使用して 3 つの加算を行います。`a = 3`、生産`9`、`12`、そして最後に`15`。 7 つの演算は公式と一致します。 

のために`n = 10^9`、因数分解は`2^9 * 5^9`。 貢献度は、`9(2-1) + 9(5-1) = 9 + 36 = 45`、したがって、答えは次のとおりです`46`。 実装は次まで反復されません`10^9`; 小さな因数が削除され、すぐに終了します。これがまさに、因数分解アプローチが制約に適合する理由です。
