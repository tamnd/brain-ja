 ## 問題の理解

 それぞれの木が最後に攻撃されたときのことを考えてください。 ツリーが年後にリセットされた場合`t`、その後、正確に成長します`m - t`数年後、最終的な高さは`m - t`。 同様に、定義します

 [
 t_i = m-h_i。 
】

 値`t_i`ツリーの最後のリセット時間です`i`。 の値`0`木が攻撃されなかったか、植えた直後に攻撃されたかのいずれかを意味します。 唯一のグローバル要件は、少なくとも 1 つの攻撃がどこかで発生することです。 

特定のリセット時間に`t`、最終リセット時間が以下のすべてのツリー`t`はすでに終了しているため、時間間隔に含めることはできません`t`, そうすることで、後で最終的なリセットが行われるためです。 最終リセット時間が少なくともあるツリー`t`はまだ利用可能です。 これらの利用可能な位置のうち、最終リセット時間が正確に一致するすべての木`t`時刻に使用される間隔でカバーされる必要があります`t`。 

これにより、問題は区間接続の問題に変わります。 それぞれについて`t`、すべてのポジションが満足していると考えてください`t_i >= t`。 それらは、いくつかのばらばらの連続したコンポーネントを形成します。 コンポーネントに少なくとも 1 つの位置が含まれている場合、`t_i = t`、そのコンポーネント内には少なくとも 1 つの攻撃間隔が必要です。 させて`c_t`そのようなコンポーネントの数になります。 したがって、すべての有効なソリューションには次のものが必要です。 

[
 k \ge \max_t c_t。 
】

 2 番目の制限があります。 毎回の攻撃`t`正確に含まれている必要があります`k`空ではない間隔があり、使用可能な位置はツリーの数だけ存在します。`t_i >= t`。 このような最小のセットは最大のリセット時間に発生するため、最も強力な制限は次のとおりです。`k`最大のツリー数を超えることはできません`t_i`。 以来`t_i=m-h_i`、これは正確に、最終的な最小の高さを持つ木の数です。 

したがって、もし

 [
 K=\max_t c_t
 】

 そして`freq_min`は最小の高さの木の数です。答えは次のとおりです。`K`いつ`K <= freq_min`、 そして`-1`さもないと。 

入力サイズは、実装が線形である必要がある主な理由です。 最大 (10^6) 個のツリーでは、(O(n\log n)) 個の作業でも 1 回のスキャンよりも大幅にコストがかかりますが、(O(n^2)) は最大 (10^{12}) 個の基本操作を意味します。 年のカウントは (10^9) に達する可能性があるため、配列演算がどれほど小さいかに関係なく、毎年反復するアルゴリズムは不可能です。 解決策は、数値的なサイズではなく、位置とその高さに依存する必要があります。`m`。 

直接解釈すると間違ってしまうケースがいくつかあります。 すべての高さがあれば`m`、 例えば`n=4, m=3`高さのある`3 3 3 3`、答えは`1`、 ない`0`。 アユーブは少なくとも 1 回攻撃する必要があり、植えた直後に攻撃できるため、4 本の木すべてをカバーする 1 つの間隔が機能します。 

同じ最終リセット時間が 2 つの離れた位置に現れる場合、必ずしも 2 つの間隔を必要とするわけではありません。 のために`n=3, m=2`そして高さ`1 0 1`、リセット時間は`1 2 1`。 二本の木は時間とともにリセットされる`1`3 つの位置すべてを含む 1 つの間隔でカバーできます。 その後、中央の木が再び攻撃されます`2`。 答えは`1`。 同じ高さのランを単にカウントする不注意な解決策では、誤って返されます。`2`。 

まったく不可能な構成もあります。 考慮する`n=5, m=3`高さのある`2 1 2 0 2`。 リセット時間は、`1 2 1 3 1`。 時間に`2`、リセット時間付きの 2 つの位置`2`は区切られているため、2 つの間隔が必要です。 したがって、`k`少なくとも`2`。 しかし、時には`3`攻撃できるのは 1 本の木だけであるため、空ではない間隔を正確に 2 つ設けることは不可能です。 正しい答えは、`-1`。

実際の質問は、しきい値を適用した後の接続コンポーネントに関するものであるため、総当り攻撃が機能します。 問題は、これらのしきい値コンポーネントを明示的に再構築すると、ほとんどすべての作業が無駄になることです。 しきい値が 1 つの値だけ変化しても、配列構造の大部分は変化しません。 

重要な観察は、しきい値コンポーネントがデカルト ツリーで表現できることです。 リセット時間ではなく、元の高さを使用した方が若干すっきりします。 リセットタイムに`t`、条件`t_i >= t`と同等です

 ## アルゴリズムのチュートリアル

 1. 最終的な高さを読み取り、最小の高さとその高さの木の本数を見つけます。 最小の高さは最大リセット時間に対応し、それは攻撃の対象となる木がまだ最も少ない年です。 したがって、上限が与えられます。`k <= freq_min`。 
2. スタックの高さを増加しない順序で維持します。 スタックは、これまでに処理されたプレフィックスの最大デカルト ツリーの右境界チェーンを表します。 等しい値は削除されずにスタック上に保持されます。 
3. 身長ごとに`x`、以下のスタック値をすべて削除します。`x`。 Each removed node has just found a strictly larger ancestor, namely`x`。 これはまさに、そのノードを 1 つのしきい値コンポーネントの最大値にする関係です。 小さい値をすべて削除すると、現在のスタックの親がデカルト ツリーの親になるため、ノードがプッシュされたときにカウントをノードに関連付けることができます。 
4. 小さい値をすべて削除した後、新しいスタックのトップを確認します。 スタックが空であるか、スタックの最上部が厳密に次の値よりも小さい場合`x`に関連付けられたコンポーネント数を増加させます。`x`。 上位が等しい場合`x`、新しいオカレンスは既存の等しい値と同じしきい値コンポーネントに属するため、値を増分しないでください。 
5.プッシュ`x`スタックに。 各高さは 1 回プッシュされ、最大 1 回ポップされるため、スタック プロセス全体は直線的です。 
6. しましょう`k`任意の高さに対して保存されている最大のコンポーネント数になります。 これは、攻撃年ごとに必要な間隔の最小数です。 もし`k > freq_min`、印刷`-1`、最新の攻撃年では、形成するのに十分なツリーが存在しないためです。`k`空ではない間隔。 それ以外の場合は印刷します`k`。 

### なぜ効果があるのか

 あらゆるしきい値に対して`H`、最大でも高さのあるポジション`H`連続したコンポーネントを形成します。 最大値が正確に一致するコンポーネント`H`攻撃時に処理する必要があるツリーのグループの 1 つに対応します。`m-H`。 このようなコンポーネントごとに少なくとも 1 つの間隔が必要であるため、これらのコンポーネントの数が下限になります。`k`。 

最大デカルト ツリーは、これらのコンポーネントを正確に編成します。 厳密に大きい親を持つノードは、それ自体の高さでコンポーネントのルートになります。 等しい親値と子の値は、そのしきい値で同じコンポーネントに属するため、意図的に別々にカウントされません。 単調スタックは、ツリーを明示的に構築せずにこの親関係を維持するため、辞書の数は正確に値になります。`c_t`。 

これらのカウントの最大値を取ると、可能な限り最小の値が得られます。`k`すべての下限を満たします。 残る唯一の問題は、必要な攻撃時間ごとに、空ではない間隔がそれだけ多く存在できるかどうかです。 リセット時間が増加すると適格な木の数が減少するため、最も厳しいケースは最大リセット時間であり、これは最終的な最小高さに相当します。 その頻度が少なくとも`k`、以前の攻撃時間には少なくとも同数の適格なツリーがあり、必要に応じて適格なコンポーネントを分割することで必要な間隔を形成できます。 したがって`k <= freq_min`必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    min_h = min(a)
    freq_min = 0

    counts = {}
    stack = []
    answer = 0

    for x in a:
        if x == min_h:
            freq_min += 1

        while stack and stack[-1] < x:
            stack.pop()

        if not stack or stack[-1] < x:
            counts[x] = counts.get(x, 0) + 1
            if counts[x] > answer:
                answer = counts[x]

        stack.append(x)

    if answer > freq_min:
        print(-1)
    else:
        print(answer)

solve()

すべての高さがゼロの場合は、`4 3`高さのある`0 0 0 0`。 リセット時の配列は次のとおりです。`3 3 3 3`、したがって、最終年にはすべての木が攻撃される必要があります。 これらは 1 つの連続したコンポーネントを形成し、1 つの間隔を必要とします。 最小の高さは 4 回出現するため、`freq_min=4`、そして答えは`1`。 

等高分離の場合`3 2`高さのある`1 0 1`リセット時間を生成します`1 2 1`。 早いアタックタイムでは、リセットタイムのある2本の木`1`中央のツリーを含めることができ、後で再びリセットされるため、1 つのコンポーネントにまとめられます。 高さのデカルト スタック数`1`したがって、 は 2 つではなく 1 つになります。 後のリセット時間は真ん中の木しかないので、`k=1`動作します。 

不可能なケース`5 3`高さのある`2 1 2 0 2`リセット時間を生成します`1 2 1 3 1`。 リセット時`2`、位置 2 と 4 は、最終リセットが少なくとも`2`、強制的に`k>=2`。 リセット時`3`、位置 4 のみが最終リセット時間を持っているため、適格なツリーは 1 つだけであり、2 つの空でない間隔は形成できません。 このアルゴリズムは、最大コンポーネント数を計算します。`2`最小高さの周波数は`1`、検出します`2 > 1`、およびプリント`-1`。 

等価境界も重要です。 高所用`0 1 0 1`、最大の高さ`1`2 つの別々のコンポーネントで発生するため、必要な`k`は`2`。 最小高さ`0`も 2 回発生し、最新のリセット時点でちょうど 2 つの適格なツリーが得られます。 下限と上限が一致するので、答えは正確に次のようになります。`2`。
