 ## 解決策
 ## 問題の理解

 文字列が 2 つあります`a`そして`b`同じ長さのもの。 2 つの異なる位置を選択し、両方の文字列のそれらの位置を同時に交換する必要があります。 目標は、結果として得られるものを作ることです`a`結果として得られるものよりも辞書編集的に大きい`b`。 

重要な点は、スワップによってペア全体が移動されるということです。`(a[i], b[i])`。 2 つの文字列から文字を個別に選択することはありません。 位置の場合`i`位置に移動されます`j`、両方のキャラクターが一緒に動きます。 

辞書編集的な比較は、2 つの文字列が異なる最初の位置によって決定されます。 そんな位置で、`a`まさにそのときに勝つ`a[i] > b[i]`。 したがって、どの位置でも、その 2 つの文字間の関係のみが重要です。`a[i] > b[i]`この立場が有利であることを意味します`a`。`a[i] = b[i]`この位置が中立であることを意味します。`a[i] < b[i]`この立場が不利であることを意味します`a`。 

届く長さは`10^5`したがって、位置のすべてのペアを調べて結果の文字列を比較するアルゴリズムは、あまりにも高価すぎます。 くらいあります`n^2 / 2`交換の可能性があり、2 つの文字列の比較には時間がかかる場合があります`O(n)`、与える`O(n^3)`最悪の場合はキャラクターワーク。 と`n = 10^5`、線形または線形に近い解決策が必要です。 

単純な戦略を欺いてしまう可能性のある小さなケースがいくつかあります。 例えば、```
2
ba
ab
```ここで、元の最初の位置は次のようになります。`b > a`、しかし可能な唯一のスワップは不利な 2 番目のペアを前に移動します。 結果は`ab`対`ba`、したがって、答えは次のとおりです`NO`。 単に 1 つの位置を見つけるだけで、`a[i] > b[i]`その位置がすでに最初であり、`n = 2`。 

もう一つのケースは、```
3
abc
abc
```すべてのポジションは中立であるため、スワップによって次のようなポジションが作成されることはありません。`a`より大きな性格を持っています。 答えは`NO`。 スワップによって比較が変更される可能性があると想定するソリューションでは、このケースを誤って受け入れることになります。 

もう一方の極端では、```
3
zzz
aaa
```すでに持っています`a[0] > b[0]`。 交換する必要がありますが、位置を交換することはできます`2`そして`3`、最初の位置はそのまま残ります。 答えは`YES`。 

## アプローチ

 直接的な総当たりアプローチは、すべてのペアを試すことです。`(x, y)`、2 つの文字列のコピーで交換を実行し、結果の文字列を辞書順に比較します。 がある`n(n-1)/2`ペア、つまり`O(n^2)`、それぞれの比較を検査できます`O(n)`文字。 最悪のケースはこうなる`O(n^3)`。 のために`n = 100000`、これはおおよそです`10^15`制限時間をはるかに超えたキャラクターレベルの操作。 

有益な観察は、実際にはすべての位置の正確な文字を気にしていないということです。 辞書編集的な比較の場合、ポジションは、以下の比較に従って有利、中立、または不利に分類されるだけで済みます。`a[i]`そして`b[i]`。 

位置を見つけたとします`p`どこ`a[p] > b[p]`。 もし`p`最初の位置ではありません。位置を入れ替えます`0`そして`p`すぐに問題を解決します。 交換後のポジション`0`からの古いペアが含まれています`p`したがって、新しい文字列は次の条件を満たします。`a[0] > b[0]`。 したがって、後で何が起こるかに関係なく、文字列は正しく順序付けされます。 

有利な位置がすでに位置している場合`0`、それを移動せずに別のスワップの宛先として使用することはできません。 いつ`n >= 3`、単純に位置を交換できます`1`そして`2`。 位置`0`変更されていないため、依然として得られます`a[0] > b[0]`。 これは、スワップを 1 回だけ実行するという要件も満たします。 

のみ`n = 2`有利な位置が既に 1 位の場合は特別な処理が必要です。 可能な交換は 1 つだけであるため、交換後は古い 2 番目の位置が最初の位置になります。 スワップは正確に次の場合に成功します。`a[1] >= b[1]`。 2 番目のポジションが中立の場合、新しい最初のポジションは等しく、有利なペアが 2 番目のポジションに移動します。 2 番目の位置も有利な場合は、1 番目の位置が有利なままです。 不利な場合は、結果として 1 位が決まります。`a < b`。 

この観察により、問題全体が、ある位置の 1 回のスキャンに軽減されます。`a[i] > b[i]`、それに加えて一定量の仕事。

 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を左から右にスキャンし、インデックスを見つけます。`p`そのような`a[p] > b[p]`。 そのようなインデックスが存在しない場合は、出力`NO`。 スワップは既存のペアをポジション間で移動するだけなので、最初にペアが存在しない場合は有利なペアを作成することはできません。 
2. もし`p > 0`、出力位置`1`そして`p + 1`。 それらを交換した後、ペアは元々`p`最初の位置に移動して、`a[0] > b[0]`。 結果の文字列はすぐに次のように並べられます。`a`より大きい`b`。 
3. もし`p = 0`そして`n >= 3`、出力位置`2`そして`3`。 最初の位置は触れられていないため、厳密な不等式は`a[0] > b[0]`最初の決定的な比較が残ります。 この問題では 1 回の操作だけで済むため、スワップは引き続き実行されます。 
4. もし`p = 0`そして`n = 2`、可能な交換はポジションのみです`1`そして`2`。 この交換の後、古い 2 番目の位置が最初の位置になります。 いつでもスワップを受け入れます`a[1] >= b[1]`; それ以外の場合は出力`NO`。 

解の背後にある不変条件は、位置の比較関係がそのペアとともに移動することです。`(a[i], b[i])`。 既知の有利なペアを最初の位置に移動すると、それが最初の決定的な比較となり、次のことが証明されます。`a > b`。 有利なペアがすでに先頭にある場合、そのようなポジションが 2 つ存在する場合、後の 2 つのポジションを交換することでそのペアを維持できます。 それが不可能な唯一の状況は、`n = 2`、唯一の選択肢を直接チェックする必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = input().strip()
    b = input().strip()

    pos = -1

    for i in range(n):
        if a[i] > b[i]:
            pos = i
            break

    if pos == -1:
        print("NO")
        return

    if pos > 0:
        print("YES")
        print(1, pos + 1)
        return

    if n >= 3:
        print("YES")
        print(2, 3)
        return

    # n == 2 and the favorable position is already position 1.
    if a[1] >= b[1]:
        print("YES")
        print(1, 2)
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```スキャンでは最初の位置が保存されます。`a[i] > b[i]`。 そのような位置はどれでも十分です。その位置がまだ最初でない場合は、最初の位置に移動すると、辞書編集上の比較がすぐに解決されるからです。 

の`pos > 0`ブランチは 0 から始まる Python インデックスを使用しますが、1 から始まる位置を出力します。 したがって、位置`0`になる`1`、 その間`pos`になる`pos + 1`。 

いつ`pos == 0`そして`n >= 3`、ポジション`1`そして`2`ゼロベースのインデックス付けでは出力位置に対応します`2`そして`3`。 それらは存在することが保証されているため、`n >= 3`、どちらも有利な1位には影響しません。 

最後の分岐に到達するのは次のとおりです。`n == 2`。 法的なスワップは 1 つだけ存在するため、確認してください`a[1] >= b[1]`で十分です。 交換後は最初の文字が等しい可能性があり、元の最初の位置からの有利なペアが 2 番目の文字での比較を決定できるため、等価性が受け入れられます。 

文字列のコピーや変更は必要ありません。 このアルゴリズムは有効なインデックスのペアのみを決定するため、追加のメモリ使用量は一定です。

## テストケース```python
import sys
import io
from contextlib import redirect_stdout

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = input().strip()
    b = input().strip()

    pos = -1

    for i in range(n):
        if a[i] > b[i]:
            pos = i
            break

    if pos == -1:
        print("NO")
        return

    if pos > 0:
        print("YES")
        print(1, pos + 1)
        return

    if n >= 3:
        print("YES")
        print(2, 3)
        return

    if a[1] >= b[1]:
        print("YES")
        print(1, 2)
    else:
        print("NO")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    output = io.StringIO()

    try:
        sys.stdin = io.StringIO(inp)
        with redirect_stdout(output):
            solve()
    finally:
        sys.stdin = old_stdin

    return output.getvalue()

# Provided samples
assert run("""3
abc
abc
""") == "NO\n", "sample 1"

assert run("""3
zzz
aaa
""") == "YES\n2 3\n", "sample 2"

# Minimum size, favorable position is second.
assert run("""2
ab
aa
""") == "YES\n1 2\n", "minimum size with favorable second position"

# Minimum size, favorable position is first but the second position is unfavorable.
assert run("""2
ba
ab
""") == "NO\n", "minimum size impossible case"

# All positions equal.
assert run("""4
abcd
abcd
""") == "NO\n", "all-equal strings"

# Maximum size, favorable position is the final character.
n = 100000
a = "a" * (n - 1) + "b"
b = "a" * n
assert run(f"{n}\n{a}\n{b}\n") == f"YES\n1 {n}\n", "maximum size and last position"

# Favorable position is first, with exactly three positions.
assert run("""3
baa
abb
""") == "YES\n2 3\n", "favorable first position"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 / ab / aa`|`YES / 1 2`| 有利なペアが 2 番目の位置にある場合の最小の長さ。 |
 |`2 / ba / ab`|`NO`| 特別な`n = 2`スワップのみの場合`a < b`。 |
 |`4 / abcd / abcd`|`NO`| 有利な立場はどこにも存在しません。 |

 ## 特殊なケース

 ### 有利なポジションなし

 検討してください```
3
abc
abd
```どのポジションも満たす`a[i] <= b[i]`。 望ましいペアが見つからないままスキャンが終了してしまうため、`pos = -1`そしてアルゴリズムは出力します`NO`。 交換は既存のペアを再配置するだけなので、どの操作を行っても大きなキャラクターを表示させることはできません。`a`よりも`b`今まで不可能だった位置に。 

### 有利なポジションはすでに 3 ポジション以上で 1 位です

 検討してください```
3
baa
abb
```位置で`1`、`b > a`、スキャンで次のことがわかります。`pos = 0`。 少なくとも 3 つのポジションがあるため、アルゴリズムによってポジションが選択されます`2`そして`3`。 最初のペアが残ります`(b, a)`、したがって、結果の文字列は依然として満たされます`a > b`最初の文字ですぐに。 必要なスワップは、後のポジションのみ変更されます。 

### 好位は２枠１着

 検討してください```
2
ba
ab
```最初の位置には、`b > a`、しかし2番目は`a < b`。 以来`n = 2`、唯一の合法的な操作は 2 つの位置を交換します。 結果は次のようになります`ab`そして`ba`、最初の文字が次の条件を満たす`a < b`。 アルゴリズムチェック`a[1] >= b[1]`、見つけます`a < b`、正しく印刷されます`NO`。

2
ba
aa
```もっている`b > a`最初の位置と`a = a`2番目に。 交換後の文字列は次のようになります。`ab`そして`aa`。 最初の文字は等しく、2 番目の比較は次のようになります。`b > a`なので、結果は有効です。 アルゴリズムは受け入れます。`a[1] >= b[1]`。 

### 最終指数で好位置

 検討してください```

aaab
aaaa
```唯一有利なポジションはインデックス`4`、 どこ`b > a`特に文字列の表記において`b > a`。 ゼロベースのスキャンにより次のことがわかります。`pos = 3`。 ポジションを交換する`1`そして`4`その有利なペアを前に移動し、次の最初の文字の比較を生成します。`b > a`。 アルゴリズムの出力`YES 1 4`。
