 ## 解決策
 ## 問題の理解

 無向グラフがあり、すべての頂点はすでに (2^{20}) より小さい整数を持っています。 頂点のサブセットと 1 つの XOR 値 (x) を選択し、選択したすべての値 (a_i) を (a_i \oplus x) に置き換えます。 目標は、2 つのエンドポイント値をエッジごとに異なる値にすることです。 

1 つのエッジを確認する便利な方法は、その端点が選択されているかどうかによって分類することです。 両方のエンドポイントが選択されている場合、または両方が選択されていない場合、XOR は両方の値に等しく適用されるため、それらの等価関係は変わりません。 エンドポイントが 1 つだけ選択されている場合、2 つの最終値は正確に等しくなります。 

[
 x=a_u\oplus a_v。 
】

 これにより、問題の中心的な構造が得られます。 

端点が最初に等しい値 (a_u=a_v) を持つエッジの場合、両方の端点が同じ選択ステータスを持つことはできません。 このようなエッジは、2 つの頂点を選択したサブセットの反対側に強制的に所属させます。 したがって、等しい値を接続するすべてのエッジは、二部である必要があるグラフを形成します。 

エンドポイント値が異なるエッジの場合、両方のエンドポイントが選択されるか、両方が選択解除されるかについて制限はありません。 エンドポイントが 1 つだけ選択されている場合は、単一の XOR 値 (a_u\oplus a_v) を回避するだけで済みます。 

この制限により、二次探索や指数探索は不可能になります。 最大 (3\cdot10^5) 個の頂点とエッジを使用し、わずか 1 秒で目的のソリューションを実現するには、基本的に線形グラフ処理が必要です。 値の範囲には、(2^{20}=1,048,576) 個の可能な XOR 値が含まれており、最大値 (m=3\cdot10^5) と比較して十分に大きいため、短いスキャンで 1 つの適切な値が見つかることが保証されます。 

直接実装を騙す可能性のあるエッジケースがいくつかあります。 考慮する```
3 3
1 1 1
1 2
2 3
1 3
```すべてのエッジは等しい値を結合するため、すべてのエッジの端点が反対側にある必要があります。 これは奇数サイクルであり、2 つに分割することはできません。 正しい出力は次のとおりです`-1`。 個々のエッジだけをチェックする不注意な解決策では、全体的な矛盾を見逃す可能性があります。 

もう 1 つのケースは、元の値がすでに適切であるグラフです。```
3 2
1 2 3
1 2
2 3
```等しい値のエッジはないため、2 部制約はまったくありません。 1 つの頂点を選択し、選択したエッジ間の XOR 差に等しくない (x) を選択できます。 ソリューションでは、何らかの等しい値のエッジが存在することを想定してはなりません。 

複数のエッジにも注意が必要です。 例えば、```
2 3
7 7
1 2
1 2
1 2
```3 つのエッジはすべてまったく同じ条件 (x\ne0) を課しており、グラフは依然として 2 部構成になっています。 入力を単純なグラフとして扱うことは不必要であり、バグが発生する可能性がありますが、制約の重複自体は問題を引き起こしません。 

最後に、選択した (x) は (2^{20}) 未満でなければなりません。 (1) から (m+1)、および (m+1\le300001<2^{20}) までの値のみをテストするため、境界は自動的に尊重されます。 

## アプローチ

 最も直接的な総当たり攻撃は、頂点のすべてのサブセットと可能なすべての XOR 値を試すことです。 (x) には (2^n) 個のサブセットと (2^{20}) 個の可能な値があります。 各ペアについて、すべてのエッジをチェックするには (O(m)) かかり、次のようになります。 

[
 O(2^n\cdot2^{20}\cdot m)
 】

 最悪の場合はエッジチェックを行います。 (n=3\cdot10^5) では、これは実行可能な計算をはるかに超えています。 

最初に、等しい値のエッジがサブセットが可能であるかどうかを決定することを観察することで、ブルート フォースを大幅に改善できます。 等しい値のエッジの場合、端点を 1 つだけ選択する必要があります。 まさに二部発色状態です。 (2^n) 個のサブセットを列挙する代わりに、単一の BFS または DFS を使用して 1 つの有効なサブセットを構築できます。 

残りの問題は、(x) をどのように選択するかです。 サブセットが固定されると、選択された頂点から選択されていない頂点に交差するエッジのみが (x) を拘束します。 このようなエッジはすべて、厳密に 1 つの値 (a_u\oplus a_v) を禁止します。 禁止値は最大で (m) 個ありますが、(m+1) 個の正の整数の中から選択できます。 鳩の巣原理により、少なくとも 1 つは、

 [
 1,2,\ldots,m+1
 】

 は禁止されていません。 (m+1<2^{20}) なので、その値は常に有効です。 

ブルート フォースが機能するのは、考えられるすべての操作を直接テストするためです。 可能なサブセットの数は指数関数的であるため、失敗します。 等しい値のエッジのみが必要な 2 色分けを決定するという観察により、指数関数的検索を 1 つのグラフ走査に置き換えることができます。その後、巨大な XOR 検索は最大 (m+1) 個の候補に集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(2^n\cdot2^{20}\cdot m)) | (O(n+m)) | 遅すぎる |
 | 最適 | (O(n+m)) 予想実用時間 | (O(n+m)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (a_u=a_v) のエッジ ((u,v)) のみを含む別のグラフを作成します。 これらのエッジは、エンドポイントが異なる選択ステータスを持つことを必要とするエッジです。 
2. BFS を使用して、この等価グラフを 2 分割します。 すべての頂点に 2 つの色 (0) または (1) のいずれかを割り当てます。 等しい値のエッジごとに、その端点は異なる色を受け取る必要があります。 端点がすでに同じ色を持つエッジを見つけた場合、必要なサブセットは存在できないため、次のように出力します。`-1`。 
3. 色 (1) のすべての頂点を選択セットとして選択します。 等値グラフに少なくとも 1 つのエッジがある場合、このセットは自動的に空ではなくなります。 等値グラフにエッジがない場合は、頂点 (1) を手動で選択します。 これは、元のエッジ値がすべてすでに異なる場合を処理します。 
4. 元のエッジをすべて調べます。 端点の選択ステータスが異なるエッジのみが、その等価関係を変更できます。 このようなエッジごとに (a_u\oplus a_v) を計算し、その値を (x) に対して禁止としてマークします。 
5. (x=1,2,\ldots,m+1) を検索し、禁止されていない最初の値を取得します。 禁止値は最大で (m) 個あるため、(m+1) 個の候補をすべて禁止することはできません。 また、(m+1\le300001<2^{20}) であるため、選択された値は必要な範囲を満たしています。 
6. 選択した頂点と選択した (x) を出力します。 すべての等しい値のエッジが 2 つのパーティションを横切るため、そのエンドポイントは異なる最終値を受け取ります。 サブセットを横切るすべての不等値エッジは、その一意の禁止された XOR 値を回避しますが、端点が同じ側にあるエッジは元の不等値を維持します。 

不変条件は、2 部カラーリングの後、すべての等しい値のエッジに反対の選択ステータスを持つ端点があるということです。 このようなエッジは最初は等しい値を持ち、(x\ne0) であるため、XOR を 1 つのエンドポイントに適用すると、2 つの値が異なります。 反対のステータスを持つ値が等しくないエッジの場合、最終値は単一の値 (x=a_u\oplus a_v) についてのみ等しくなる可能性がありますが、この構成では明示的に除外されます。 等しい選択ステータスを持つ値が等しくないエッジでは、XOR が両方のエンドポイントに適用されるか、どちらにも適用されないため、その 2 つの異なる値は異なるままになります。 

したがって、すべてのエッジが最終操作に対して有効になります。 2 部カラーリングが失敗した場合、等しい値の奇数サイクルにより不可能な交互選択パターンが強制されるため、レポート`-1`も正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    edges = []
    equal_adj = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v))

        if a[u] == a[v]:
            equal_adj[u].append(v)
            equal_adj[v].append(u)

    color = [-1] * n

    for start in range(n):
        if color[start] != -1:
            continue

        color[start] = 0
        stack = [start]

        while stack:
            u = stack.pop()

            for v in equal_adj[u]:
                if color[v] == -1:
                    color[v] = color[u] ^ 1
                    stack.append(v)
                elif color[v] == color[u]:
                    print(-1)
                    return

    selected = [i for i in range(n) if color[i] == 1]

    if not selected:
        selected = [0]

    forbidden = set()

    for u, v in edges:
        if (u in selected_set) != (v in selected_set):
            forbidden.add(a[u] ^ a[v])

    x = 1
    while x in forbidden:
        x += 1

    print(len(selected), x)
    print(*(v + 1 for v in selected))

if __name__ == "__main__":
    solve()

## 実用的な例

 ### サンプル 1

 入力は```
3 3
1 1 1
1 2
2 3
1 3
```すべてのエッジのエンドポイント値は等しいため、3 つのエッジすべてが 2 部グラフに入ります。 

| 頂点 | 割り当てられた色 | 理由 |
 | --- | --- | --- |
 | 1 | 0 | BFS 開始 |
 | 2 | 1 | 1 に隣接 |
 | 3 | 0 | 2に隣接 |
 | 1 と 3 | 0、0 | エッジでの競合 (1\text{-}3) |

 エッジ (1\text{-}3) は同じ色の頂点を接続しているため、等値グラフは 2 部ではありません。 3 つの等しいエッジをすべて分離できる選択セットはなく、アルゴリズムによって出力されます。`-1`。 

これは、ローカル エッジだけをチェックするだけでは不十分な理由を示しています。 矛盾は、奇数サイクル全体で交互の色をたどった後にのみ現れます。 

### サンプル 2

 入力は```
3 3
1 1 2
1 2
2 3
1 3
```エッジ (1\text{-}2) のみが等しいエンドポイント値を持ちます。 

| 頂点 | 色 | 選択済み | 理由 |
 | --- | --- | --- | --- |
 | 1 | 0 | いいえ | BFS 開始 |
 | 2 | 1 | はい | 等しい値のエッジには反対の色が必要です |
 | 3 | 0 | いいえ | 頂点 3 は等しい値のエッジによって接続されていません |

 選択されたセットは ({2}) です。 交差するエッジとその禁止値は次のとおりです。 

| エッジ | エンドポイント値 | XOR | 禁断？ |
 | --- | --- | --- | --- |
 | (1,2) | (1,1) | 0 | はい |

 | (1,3) | (1,2) | 3 | いいえ、両方とも選択されていません |

演算後の値は (1,0,2) になります。 3 つのエッジはすべて異なる値を接続しているため、構築は有効です。 

このトレースは、値が等しいエッジがサブセットを決定するのに対し、値が異なるエッジは (x) の可能な値のみを削除する方法を示しています。

import sys
import io

def solve_data(inp: str) -> str:
    data = list(map(int, inp.split()))
    it = iter(data)

    n = next(it)
    m = next(it)
    a = [next(it) for _ in range(n)]

    edges = []
    equal_adj = [[] for _ in range(n)]

    for _ in range(m):
        u = next(it) - 1
        v = next(it) - 1
        edges.append((u, v))
        if a[u] == a[v]:
            equal_adj[u].append(v)
            equal_adj[v].append(u)

    color = [-1] * n

    for start in range(n):
        if color[start] != -1:
            continue

        color[start] = 0
        stack = [start]

        while stack:
            u = stack.pop()

            for v in equal_adj[u]:
                if color[v] == -1:
                    color[v] = color[u] ^ 1
                    stack.append(v)
                elif color[v] == color[u]:
                    return "-1\n"

    selected = [i for i in range(n) if color[i] == 1]

    if not selected:
        selected = [0]

    selected_set = set(selected)

    forbidden = set()
    for u, v in edges:
        if (u in selected_set) != (v in selected_set):
            forbidden.add(a[u] ^ a[v])

    x = 1
    while x in forbidden:
        x += 1

    return str(len(selected)) + " " + str(x) + "\n" + \
           " ".join(str(v + 1) for v in selected) + "\n"

def validate(inp: str, out: str) -> bool:
    data = list(map(int, inp.split()))
    it = iter(data)

    n = next(it)
    m = next(it)
    a = [next(it) for _ in range(n)]

    edges = [(next(it) - 1, next(it) - 1) for _ in range(m)]

    tokens = out.split()

    if tokens[0] == "-1":
        return True

    k = int(tokens[0])
    x = int(tokens[1])

    if not (0 <= k <= n):
        return False
    if not (0 <= x < (1 << 20)):
        return False

    chosen = list(map(lambda z: int(z) - 1, tokens[2:2 + k]))

    if len(chosen) != k:
        return False
    if len(set(chosen)) != k:
        return False
    if any(v < 0 or v >= n for v in chosen):
        return False

    chosen_set = set(chosen)

    for u, v in edges:
        au = a[u] ^ x if u in chosen_set else a[u]
        av = a[v] ^ x if v in chosen_set else a[v]

        if au == av:
            return False

    return True

 ## 特殊なケース

 すべて等しい三角形の場合```
3 3
1 1 1
1 2
2 3
1 3
```等価グラフは三角形全体です。 頂点 1 のカラー (0) から開始すると、頂点 2 がカラー (1) になり、頂点 3 がエッジ (2\text{-}3) までカラー (0) になります。 次に、エッジ (1\text{-}3) が 2 つのカラー (0) 頂点を接続するため、アルゴリズムはすぐに戻ります。`-1`。 

等しい値のエッジがないグラフの場合、```
3 2
1 2 3
1 2
2 3
```等値グラフにはエッジがないため、最初はすべての頂点が色 (0) を受け取ります。 カラー (1) 側は空で、アルゴリズムは代わりに頂点 1 を選択します。エッジの交差は (1\oplus2=3) を禁止しますが、エッジ (2\text{-}3) は選択されたセットと交差しません。 したがって、(x=1) は有効であり、頂点 1 が (1) から (0) に変更され、エッジの値は異なるままになります。 

重複したエッジの場合、```
2 3
7 7
1 2
1 2
1 2
```同じペアが等値グラフに 3 回現れます。 BFS は依然として 2 つの頂点に異なる色を割り当てます。 選択したサイドには 1 つの端点が含まれており、エッジのすべてのコピーが禁止されています (7\oplus7=0)。 最初の候補 (x=1) は、3 つのコピーすべてに対して同時に有効です。 

可能な最大の頂点値については、```
3 2
0 1048575 1
1 2
2 3
```最初の 2 つの値間の XOR は (1048575) ですが、まだ 20 ビットの範囲内です。 このアルゴリズムでは、XOR 値が数値的に小さいとは決して想定されず、XOR 値が (2^{20}) より小さいとのみ想定されます。 その候補検索では (1) から始まる値が使用され、鳩の穴引数は (2^{20}) に達するずっと前に空き値を保証します。 

(m+1) 個の候補を選択すると、禁止された XOR 値の最悪のコレクションも処理されます。 (1,\ldots,m) のすべてが禁止されている場合でも、(m) 個のエッジしかなく、したがって最大でも (m) 個の異なる禁止値があるため、(m+1) を禁止することはできません。 (m+1\le300001<2^{20}) なので、検索では常に正当な XOR 値が見つかります。
