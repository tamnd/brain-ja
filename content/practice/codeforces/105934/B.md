 ## 解決策
 ## 問題の理解

 都市は一本の川の上に順番に並んでいます。 トレジャーハンターは都市 1 から開始します。都市に到達する`i + 1`市内から`i`費用`c_i`コインが必要であり、代替ルートはありません。 

各都市には価値のある宝箱が含まれています`a_i`コイン。 ハンターが所有するのはせいぜい`k`キーなので、遠征中はせいぜい開けることができます。`k`胸。 どの都市を訪れてもスキップする可能性があります。 

ある時点で、彼らは探索をやめることにしました。 下流に戻るのは無料なので、移動費は最も遠い訪問都市に到達するために支払われる費用のみです。 

考えられるすべての停止都市について、最大の利益を決定する必要があります。`coins collected from opened chests - travel costs paid`達成可能な最大値を出力します。 

制約は大きく、最大で`10^5`都市は宝の価値や旅費に達する可能性がありますが、`10^9`。 プレフィックスを繰り返しスキャンしたり、大きな範囲を繰り返し並べ替えたりするソリューションでは、速度が遅すぎます。 アン`O(n^2)`アプローチには前後が必要です`10^10`最悪の場合の操作は完全に不可能です。 に近いものが必要です`O(n log n)`。 

微妙な点は、宝箱を開けるかどうかはオプションであるということです。 仮定する：```
n = 3, k = 2
a = [100, 1, 1]
```最適な選択は、訪問したプレフィックスで利用可能な貴重なチェストのみを開けることです。 同じ到達可能なセット内に大きなチェストが存在する場合に、小さなチェストのキーを無駄にすることは決して望ましくありません。 

もう 1 つの簡単な間違いは、目的地の都市には開いた宝箱があるはずだと考えることです。```
n = 3, k = 1
a = [100, 1, 1000]
c = [10, 10000]
```都市2に立ち寄ると利益が得られます`100 - 10 = 90`。 都市 3 への旅行は、追加の旅費が追加の宝を超えるため、悲惨なものになります。 停止ポイントと開いた宝箱は独立して決定されます。 

3 番目のエッジケースは、以下の場合に発生します。`k`都市は訪問されました。```
n = 2, k = 2
a = [5, 7]
c = [1]
```都市 1 に到達した後、収集可能な最高の宝物は次のとおりです。`5`、「2つの宝の合計」ではありません。 アルゴリズムは当然、長さが以下のプレフィックスを処理する必要があります。`k`。 

## アプローチ

 ブルートフォースソリューションは、あらゆる停止都市を考慮します`i`。 

街に立ち寄ったら`i`、都市のみ`1...i`到達可能です。 これらの都市の中で、最良の戦略は明らかです。最大の値が入った宝箱を開けることです。`k`彼らのうち。 旅行費用は固定であり、次のようになります。```
c1 + c2 + ... + c(i-1)
```したがって、次のように計算できます。```
profit(i) =
(sum of k largest values in a[1..i])
-
(prefix travel cost)
```ブルートフォース実装では、`k`すべてのプレフィックスの最大値を個別に取得します。 各プレフィックスのコストを並べ替える`O(i log i)`、おおよそにつながります`O(n^2 log n)`全体。 と`n = 10^5`、これでは遅すぎます。 

重要な観察は、プレフィックスが一度に 1 つの都市を成長させるということです。 とき市`i`が追加された場合、新しい宝物値は 1 つだけ考慮されます。 上位セット全体を再計算する必要はありません。`k`ゼロからの宝物。 

現状を維持する`k`これまでに確認された最大の宝の価値。 最小ヒープはこれに最適です。 ヒープには、現在開くために選択されている宝物が正確に保存されます。 そのサイズは決して超えられません`k`。 

新しい宝物が到着したら:

 ヒープに含まれる内容が以下の場合`k`要素を含める必要があります。 

それ以外の場合は、最小ヒープの最上位にある選択された最小の宝物と比較します。 新しい値が大きい場合、選択した最小の宝物を置き換えると、選択した宝物の合計が増加します。 それより大きくない場合、選択された宝物の最適なセットは変更されません。 

これにより、最大の合計が得られます`k`すべてのプレフィックスの値`O(log k)`都市ごとの時間。 

交通費もさらにシンプルになります。 させて`cost`現在の都市に到達するまでに支払った累積コストになります。 都市から移動するにつれて`i`街へ`i + 1`、 追加`c_i`。 

すべてのプレフィックスについて次のように計算します。```
current_profit = sum_top_k - cost
```そして最大値を維持します。 

公式見解はまさに、ハンターが都市に立ち寄った場合、`i`、最大の利益は、`k`プレフィックス内の最大の宝の値`a[1..i]`その都市に到達するために必要な交通費を差し引いたもの。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log n) | O(n) | 遅すぎる |
 | 最適 | O(n log k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`k`、宝物の価値`a`、交通費`c`。 
2. 空の最小ヒープと変数を作成します。`selected_sum = 0`。 
3. メンテナンス`travel_cost`、現在の都市に到達するために支払った合計コスト。 
4. 都市を左から右に処理します。 
5.現在のお宝の価値について`a[i]`、選択した宝物のヒープを更新します。 

ヒープ サイズが以下の場合`k`、値をプッシュして追加します`selected_sum`。 
6. ヒープにすでに次のものが含まれている場合`k`要素、比較`a[i]`選ばれた最小の宝物と一緒に。 

もし`a[i]`大きい場合は、選択した最小の宝物を削除し、挿入します`a[i]`、更新します`selected_sum`それに応じて。 
7. ヒープを更新した後、`selected_sum`最大値の合計に等しい`k`現在のプレフィックスの宝物の値。 
8. 以下を計算します。```
profit = selected_sum - travel_cost
```これまでに確認された最大利益を使用して回答を更新します。 
9. 次の都市に移動する前に、対応する交通費を`travel_cost`。 
10. すべての都市が処理された後、最大利益を出力します。 

### なぜ効果があるのか

 立ち止まる街のために`i`、到達可能な都市は正確にプレフィックスです`1...i`。 これらの都市の中で、最適な戦略を実行すると、最も貴重な入手可能な宝箱が開きます。`k`彼らのうち。 手の届く大きなチェストを無視して小さなチェストを選択すると、利益が減るだけです。 

ヒープの不変条件は、常に最大のヒープを格納することです。`k`これまでに処理されたすべての都市の宝物の価値。 新しい宝物がプレフィックスに入るたびに、最適なセットに可能な唯一の変更は、現在選択されている最小の宝物を置き換えることです。 ヒープはまさにこの更新を実行します。 

以来`selected_sum`常に最大値の合計と等しくなります`k`現在のプレフィックス内の宝物、および`travel_cost`がそのプレフィックスの最後の都市に到達するのに必要なコストに等しい場合、計算された利益はまさにその停止点での最良の利益になります。 すべての停止点で最大値を取ると、全体的な最適値が得られます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    c = []
    if n > 1:
        c = list(map(int, input().split()))
    
    heap = []
    selected_sum = 0
    travel_cost = 0
    answer = 0

    for i in range(n):
        x = a[i]

        if len(heap) < k:
            heapq.heappush(heap, x)
            selected_sum += x
        elif x > heap[0]:
            removed = heapq.heapreplace(heap, x)
            selected_sum += x - removed

        answer = max(answer, selected_sum - travel_cost)

        if i < n - 1:
            travel_cost += c[i]

    print(answer)

solve()
```ヒープには、現在選択されている宝物が保存されます。 これは最小ヒープであるため、選択された最小の宝物は常に次の場所で利用可能です。`O(1)`時間。 

ヒープサイズが以下の場合`k`、すべての新しい宝物は自動的に現在のトップに属します。`k`セット。 ヒープがサイズに達したら`k`、新しい宝物は、選択した最小のものよりも大きい場合にのみ重要になります。`selected_sum`段階的に更新されます。 反復ごとにヒープから合計を再計算すると、解は次のようになります。`O(nk)`。 

操作の順序が重要です。 市の利益`i`市内までの交通費を追加する前に計算する必要があります`i + 1`。 その瞬間、`travel_cost`都市に到達するために費やした金額を正確に表す必要があります`i`。 

すべての算術演算では Python 整数が使用され、考えられる最大の答えよりもはるかに大きな値を安全に処理します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log k) | 各都市は最大 1 つのヒープ操作を実行します。 
| スペース | O(k) | ヒープストアは最大でも`k`宝物 |

 と`n ≤ 10^5`、`O(n log k)`一般的な競技プログラミングの制限内に簡単に収まります。 選択された宝物のみがヒープに保持されるため、メモリ使用量はわずかです。

## 特殊なケース

 より遠くに旅行することが有害である場合を考えてみましょう。```
3 1
100 1 1000
10 10000
```都市 1 のヒープには次のものが含まれています`{100}`そして利益は`100`。 シティ2にはやはり最高の宝物がある`100`、しかし利益は に低下します。`90`旅費のせいで。 都市 3 では、ヒープが次のように変化します。`{1000}`それでも利益は得られる`1000 - 10010`、これはマイナスです。 アルゴリズムは最大値を正しく維持します`100`。 

次に、以下より短いプレフィックスを考えます。`k`。```
2 2
5 7
1
```都市 1 以降、ヒープには宝物が 1 つだけ含まれており、`selected_sum = 5`。 アルゴリズムはそれを正確に想定することはありません`k`宝物は存在するはずだ。 都市 2 の後のヒープには両方の宝物が含まれており、答えは次のようになります。`12 - 1 = 11`。 

最後に、重複する値を考慮します。```
4 2
5 5 5 5
1 1 1
```ヒープには常に値のコピーが 2 つ保存されます`5`。 選択した値が置換されるため、同じ値によって不必要な置換がトリガーされることはありません。`5`別の人と`5`何も変わりません。 ヒープに含まれる最大値の不変式`k`値は実行中ずっと有効です。
