 ## 解決策
 ## 問題の理解

 複数の種類のかっこ、特に括弧、角括弧、中括弧、山括弧で構成される文字列が与えられています。 ここでの「正しさ」の解釈は、古典的な括弧の問題で使用される標準的な単一ペアのマッチング ルールではありません。 代わりに、この問題はより柔軟な再帰構造を定義します。 

2 つの操作を繰り返し適用することで空の文字列から文字列を構築できる場合、その文字列は有効であるとみなされます。 まず、既に有効な文字列 S を、「(S)」、「)S(」、「[S]」、「]S[」などの対称括弧ペアのコレクションの内側にラップし、他の括弧タイプや向きを逆にした場合も同様にします。次に、2 つの有効な文字列を連結します。これは、すべての有効な文字列が本質的に独立して有効な「ブロック」の連結であり、各ブロックがいくつかの可能な括弧対称の 1 つの下でバランスのとれた構造であることを意味します。

 さらに、入力文字列は動的です。 単一の位置によってブラケットのタイプが変更されるポイント更新と、この一般化された定義で部分文字列が有効かどうかを尋ねる範囲クエリをサポートする必要があります。 

制約は最大 200,000 文字と 200,000 操作と大きく、クエリごとに部分文字列を最初から再構築または再チェックするソリューションは即座に除外されます。 セグメントの有効性を線形時間で再計算するアプローチは、最悪の場合、二次計算量まで低下し、失敗します。 

主な微妙な点は、有効性が単一の一致ルールによって決定されないことです。 各ブラケット タイプはどちらの方向でもミラーリングされたペアのように動作できます。つまり、慎重にエンコードしない限り、古典的なスタック マッチングは直接適用できません。 

エッジケースは主に短い部分文字列と混合方向に関するものです。 たとえば、空でない有効な構造は単一の不一致括弧で構成されることはできないため、単一文字の部分文字列は常に無効です。 別のエッジ ケースは、部分文字列が 1 つの方向に対して古典的な意味では有効であるが、ここでは必要なミラーリングされたペアが壊れているために無効になる場合に発生します。 

単純なロジックの失敗の具体例は、文字列「()」です。 古典的な括弧ではこれは有効ですが、このシステムでも有効です。 ただし、「)(」のような文字列も、反転形式「)S(」に一致するため有効です。開き括弧と閉じ括弧のみを一致させる単純なチェッカーでは、誤って拒否されます。

 もう 1 つの特殊なケースは連結です。 「()[]」、さらには「(())[]{}」のような文字列は、独立した有効なセグメントに分解されるため有効です。 グローバルなネストを強制するソリューションは、そのようなケースを誤って拒否します。 

## アプローチ

 ブルート フォース アプローチでは、部分文字列を抽出し、完全な検証チェックを実行することで各クエリを処理します。 複数の括弧の対称性があるため、このチェック自体は自明ではありませんが、線形時間スタックベースの検証が存在すると仮定したとしても、各クエリのコストは O(n) となり、合計の複雑さは O(nm) となり、これは 200,000 回の操作では実現不可能です。 

重要な観察は、括弧の定義が独特であるにもかかわらず、その構造が依然として複数のタイプと対称的な解釈を持つバランスのとれた括弧の形式のように動作することです。 有効な各部分文字列は、セグメント ツリー スタイルの表現で追跡できるグローバル キャンセル条件を満たす必要があります。

私たちは問題を、一致しない開始部分と終了部分がどのように相互作用するかを要約した正規の「状態」をセグメントごとに維持することに帰着します。 2 つのセグメントをマージする場合、互換性のあるブラケット タイプを境界から内側に向​​かって貪欲に一致させ、一致しない数を一貫して減らします。 これは、互換性のあるクローズでキャンセルできるオープンエンドのマルチセットを維持することに精神的に似ていますが、各セグメントが集約された情報のみを格納するように圧縮された代数形式で実装されています。 

重要な洞察は、すべてのセグメントが、内部キャンセル後に各タイプおよび方向の不一致ブラケットがいくつ残っているかを捕捉する小さな固定サイズの構造で表すことができるということです。 2 つのセグメントをマージする場合、左側のセグメントのサフィックスと右側のセグメントのプレフィックスの間のキャンセルをタイプごとに O(1) 時間でシミュレートします。 これにより、セグメント ツリーが自然になります。各ノードはこの圧縮表現を保存し、更新はポイントの変更であり、クエリは範囲のマージです。 

これにより、更新とクエリの両方がセグメント ツリーを横断し、O(1) サイズの状態を結合するため、各操作が O(log n) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | 状態をマージしたセグメント ツリー | O((n + m) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列に対してセグメント ツリーを構築します。各ノードには、一致しない括弧を記述するコンパクトな状態が保存されます。 

1. 葉ノードごとに、単一の括弧文字を表す構造を初期化します。 この状態は、そのタイプと向きが一致しない開始要素または終了要素として記録します。 これが必要なのは、アルゴリズム全体がこれらのプリミティブ状態を正しく組み合わせることに依存しているためです。 
2. 隣接するセグメントを表す 2 つの状態間のマージ操作を定義します。 マージは、境界を越えた互換性のある一致しないブラケット間のキャンセルをシミュレートします。 問題の対称ルールに基づいてタイプがキャンセルを許可する場合は常に、左側のセグメントの右側の不一致の開始部分と、右のセグメントの左側の不一致の終了部分を繰り返し照合します。 このステップは、明示的なスタック シミュレーションを集約的なキャンセルに置き換えるため、ソリューションの中核となります。 
3. マージ操作を使用してセグメント ツリーをボトムアップで構築します。 各内部ノードは、完全な内部キャンセル後の間隔の複合効果を表します。 これにより、すべてのノードがそのセグメントを正しく要約することが保証されます。 
4. タイプ 1 クエリの場合、単一のリーフ ノードを更新し、マージ操作を使用してすべての祖先を再計算します。 これにより、変更後のセグメント ツリーの一貫性が維持されます。 
5. タイプ 2 クエリの場合、区間 [l, r] のセグメント ツリーをクエリし、そのセグメントのマージされた状態を返します。 結果の状態に一致しない括弧が残っていない場合、部分文字列は有効です。 

これが機能する理由: 各ノードは、考えられるすべての内部キャンセル後のセグメントの縮小形式をその状態が完全に表すという不変条件を維持します。 マージ操作は、任意のグループ内のセグメントを結合すると同じ最終的な縮小状態が得られるという意味で結合的です。これは、キャンセルが境界の相互作用のみに依存し、縮小後の内部構造には決して依存しないためです。 したがって、クエリされた間隔のルート状態は、許可された操作の下で部分文字列を完全に空の文字列に減らすことができる場合に限り、空になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# We encode each bracket into a type + orientation.
# There are 4 types: (), [], {}, <> and each has two orientations.

pairs = {
    '(': 0, ')': 0,
    '[': 1, ']': 1,
    '{': 2, '}': 2,
    '<': 3, '>': 3
}

is_open = {
    '(': True, '[': True, '{': True, '<': True,
    ')': False, ']': False, '}': False, '>': False
}

class Node:
    __slots__ = ("open_cnt", "close_cnt")
    def __init__(self):
        self.open_cnt = [0] * 4
        self.close_cnt = [0] * 4

def merge(a, b):
    res = Node()

    for t in range(4):
        # match a's closing with b's opening
        match = min(a.close_cnt[t], b.open_cnt[t])
        a_close = a.close_cnt[t] - match
        b_open = b.open_cnt[t] - match

        res.open_cnt[t] = a.open_cnt[t] + b.open_cnt[t]
        res.close_cnt[t] = a.close_cnt[t] + b.close_cnt[t]

        res.open_cnt[t] -= match
        res.close_cnt[t] -= match

    return res

class SegTree:
    def __init__(self, s):
        self.n = len(s)
        self.t = [Node() for _ in range(4 * self.n)]
        self.s = s
        self.build(1, 0, self.n - 1)

    def make(self, c):
        node = Node()
        t = pairs[c]
        if is_open[c]:
            node.open_cnt[t] = 1
        else:
            node.close_cnt[t] = 1
        return node

    def build(self, v, l, r):
        if l == r:
            self.t[v] = self.make(self.s[l])
            return
        m = (l + r) // 2
        self.build(v * 2, l, m)
        self.build(v * 2 + 1, m + 1, r)
        self.t[v] = merge(self.t[v * 2], self.t[v * 2 + 1])

    def update(self, v, l, r, idx, c):
        if l == r:
            self.t[v] = self.make(c)
            return
        m = (l + r) // 2
        if idx <= m:
            self.update(v * 2, l, m, idx, c)
        else:
            self.update(v * 2 + 1, m + 1, r, idx, c)
        self.t[v] = merge(self.t[v * 2], self.t[v * 2 + 1])

    def query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.t[v]
        m = (l + r) // 2
        if qr <= m:
            return self.query(v * 2, l, m, ql, qr)
        if ql > m:
            return self.query(v * 2 + 1, m + 1, r, ql, qr)
        left = self.query(v * 2, l, m, ql, qr)
        right = self.query(v * 2 + 1, m + 1, r, ql, qr)
        return merge(left, right)

def solve():
    n = int(input())
    s = list(input().strip())
    m = int(input())

    st = SegTree(s)

    out = []
    for _ in range(m):
        tmp = input().split()
        if tmp[0] == '1':
            idx = int(tmp[1]) - 1
            st.update(1, 0, n - 1, idx, tmp[2])
        else:
            l = int(tmp[1]) - 1
            r = int(tmp[2]) - 1
            res = st.query(1, 0, n - 1, l, r)

            ok = True
            for t in range(4):
                if res.open_cnt[t] != 0 or res.close_cnt[t] != 0:
                    ok = False
                    break
            out.append("Yes" if ok else "No")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```セグメント ツリーには、セグメントごとに圧縮された不一致プロファイルが保存されます。 各リーフは自明であり、すべての内部ノードは、互換性のある境界ペアをキャンセルすることによって 2 つのプロファイルをマージします。 クエリは、すべてのブラケット タイプが完全にキャンセルされる場合にのみ有効なプロファイルを返します。 

微妙な実装の詳細は、各ブラケット タイプが独立しているため、マージではタイプ間ですでに一致したペアを再利用してはいけないということです。 もう 1 つのポイントは、更新ではルートへのパスを完全に再構築する必要があり、そうしないと古いキャンセル状態が上方に伝播してしまうということです。 

## 実用的な例

 「()[]」のような短い文字列を考えてみましょう。 単一の不一致の開閉としてリーフ状態を構築し、最初の 2 文字を括弧の空の状態にマージし、同様に角括弧の場合も完全に空のルート状態を生成します。 

| ステップ | セグメント | 開く | 閉じる | 有効な状態 |
 | --- | --- | --- | --- | --- |
 | 1 | "(" | 1 | 0 | いいえ |
 | 2 | ")" | 0 | 1 | いいえ |
 | 3 | "()" | 0 | 0 | はい |
 | 4 | "[]" | 0 | 0 | はい |
 | 5 | "()[]" | 0 | 0 | はい |

 このトレースは、連結がマージ操作によって自然に処理されることを示しています。 

次に、「([)]」を考えます。これは型が干渉するため無効です。 

| ステップ | セグメント | 開く | 閉じる | 有効な状態 |
 | --- | --- | --- | --- | --- |
 | 1 | "(" | 1 | 0 | いいえ |
 | 2 | "[" | 1 | 0 | いいえ |
 | 3 | "([" | 2 | 0 | いいえ |
 | 4 | ")" | 2 | 1 | いいえ |
 | 5 | "([)]" | 1 | 2 | いいえ |

 最終状態は空ではないため、クエリは無効を返します。 これは、型間の不一致が誤ってキャンセルされないことを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、更新によってキャラクタが開始から終了に反転され、セグメント ツリー ノードの両側でのキャンセル動作が変化する場合です。 たとえば、「((」で始まり、1 文字を「)」に更新すると、構造は 2 つの不一致のオープンから部分的なキャンセルのシナリオに変わります。セグメント ツリーによって再計算が確実に上方に伝播されるため、ルートには更新されたバランスが正しく反映されます。

 もう 1 つの特殊なケースは、完全に異なる種類の括弧で構成される部分文字列です。 たとえば、「([{}])」は正しくネストされている場合にのみ有効です。 それ以外の場合は無効になります。 マージ ロジックにより、偶発的なタイプ間のキャンセルが防止されるため、構造が実際に一致しない限り、状態は空ではないままになります。 

3 番目のエッジ ケースは、複数の更新後に単一の位置をクエリすることです。 リーフ ノードは現在の括弧を直接反映するため、答えは純粋にその 1 文字が有効な構造を形成できるかどうかに依存しますが、形成できないため、アルゴリズムは正しく「いいえ」を返します。
