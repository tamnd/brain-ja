 ## 問題の理解

 庭園は次のように表現されます。`n × m`グリッド。 各セルにはツリーが含まれているか、空です。 辺がグリッド線に沿った長方形の構築領域を配置する必要があります。 長方形には寸法があります`a × b`、ただし、次のように回転することもできます。`b × a`。 将来の建築予定地にあるすべての木を除去する必要があるため、位置を選択するコストはその長方形内の木の数になります。 タスクは、すべての有効な配置の中から可能な最小コストを見つけることです。 

グリッドの寸法は最大でも 50 x 50 なので、セルの総数はわずか 2500 です。これは、考えられる多数の長方形を調べることができるほど十分小さいですが、それでも不必要な作業を避ける必要があります。 可能なすべての四角形を試し、そのすべてのセルをスキャンするソリューションは、検索スペースが限られているため、ここでは受け入れられますが、グリッドが次のような値に成長すると、同じアイデアが遅くなりすぎます。`10^5`、ここでは二次列挙ですらすでにコストが高すぎるでしょう。 

主なエッジ ケースは、長方形の方向と正確な境界線を正しく処理することで発生します。 

最初のケースは、長方形が回転後にのみ適合する場合です。 例えば：```
2 3
0 0 0
1 1 0
2 1
```答えは次のとおりです。```
0
```長方形のサイズだけをチェックする不注意な実装`a × b`と`a`有効な配置が実際には次のとおりであるため、行に揃えると失敗します。`b × a`。 

もう 1 つのケースは、長方形が庭全体を覆う場合です。```
2 2
1 0
0 1
2 2
```答えは次のとおりです。```
2
```誤って次の時点までのみ反復する実装`n - a`の代わりに`n - a + 1`唯一可能な配置を逃すことになります。 

3 番目のケースは、木のない空の長方形領域です。```
1 3
0 0 0
1 2
```答えは次のとおりです。```
0
```最小の答えを大きな値ではなくゼロに初期化するソリューションは、これらの入力では正しく表示されますが、考えられるすべての四角形に木が含まれている場合は失敗します。 

## アプローチ

 直接的なアプローチは、建築現場の左上隅を可能な限りすべて試してみることです。 角ごとに、選択した長方形の中に木の数が何本あるかを数え、最小数を保持します。 この方法は正しいです。すべての有効な建設現場には左上隅が 1 つだけ存在するため、すべての隅をチェックすると考えられるすべての答えがチェックされます。 

サイズが 50 x 50 のグリッドでは、可能な位置の数は最大でも約 2,500 です。長方形のスキャンには最大でも 2,500 回の操作が必要で、およそ 625 万回のセル チェックが必要になります。 これは、指定された制限に対して十分小さいです。 

入力が小さいため、総当たり攻撃が機能します。 グリッドが小さいという観察により、高度なデータ構造を必要とせずに問題を徹底的な検索に減らすことができます。 プレフィックス合計も機能し、大規模なグリッドには便利な一般的な手法ですが、ここでは、より単純なアプローチがすでに十分に高速で、検証が容易です。 

追加の詳細は、可能な 2 つの方向のみです。 同じ検索を実行します`a × b`そしてのために`b × a`両方が有効な配置である場合。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n × m × a × b) | お(1) | これらの制限については受け入れられます |
 | プレフィックス合計の最適化 | O(n × m) | O(n × m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 庭のグリッドと希望する長方形の寸法を読み取ります。 検索中にすべてのツリーをチェックできるように、グリッド値を保存します。 
2. 長方形の寸法を受け取るプロシージャを定義します。`h`そして`w`。 そのサイズの長方形が庭内に収まる可能性のある左上隅をすべて試します。 
3. 考えられる位置ごとに、選択した行と列の境界間のすべてのセルを訪問して、長方形内の木の数を数えます。 これは、最小限に抑える必要があるコストと直接一致します。 
4. 配置に含まれる木が以前のすべての配置よりも少ない場合は常に、現在の最小値を更新します。 
5. 次の手順を実行します。`a × b`。 回転した長方形の場合`b × a`も適合する場合は、もう一度実行して、より良い結果を取得します。 

両方の方向を確認する必要がある理由は、この問題により構築領域が回転する可能性があるためです。 長方形の寸法は、固定された行と列の方向ではなく、辺の長さを表します。 

機能する理由: すべての有効な建築敷地は、アルゴリズムによって考慮される位置の 1 つに対応します。 考慮された位置ごとに、アルゴリズムはその中にある木の数を正確に計算します。 すべての可能な位置と両方の方向で最小値が採用されるため、最終的な値は、削除する達成可能な最小のツリー数になります。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]
    a, b = map(int, input().split())

    def check(h, w):
        if h > n or w > m:
            return 10**9

        ans = 10**9

        for i in range(n - h + 1):
            for j in range(m - w + 1):
                trees = 0
                for x in range(i, i + h):
                    for y in range(j, j + w):
                        trees += grid[x][y]
                ans = min(ans, trees)

        return ans

    answer = check(a, b)
    answer = min(answer, check(b, a))

    print(answer)

if __name__ == "__main__":
    solve()
```の`check`関数は、1 つの方向に対して完全な検索を実行します。 最初の条件は、適合しない四角形を拒否します。これにより、無効なループ範囲が防止され、回転の場合も適切に処理されます。 

ループが終わる`i`そして`j`可能なすべての左上隅を列挙します。 制限は使用します`n - h + 1`そして`m - w + 1`最後の有効な開始位置は、長方形が庭の下端または右端に触れる正確な位置であるためです。 

内側のループは、現在の四角形内のセルをカウントします。 グリッド サイズが小さいため、この繰り返しカウントは、追加のプレフィックス配列を維持するよりも簡単です。 

最後の 2 つの呼び出しでは、許可されている両方の向きが処理されます。 ディメンションが等しい場合、2 番目の呼び出しで同じ検索が繰り返されますが、コストは依然として制限をはるかに下回ります。

 ## 特殊なケース

 回転のみで配置が可能な場合、アルゴリズムは 2 番目の方向を個別に試行します。 のために：```
2 3
0 0 0
1 1 0
2 1
```最初の検索は拒否される`2 × 1`回転させた状態で、必要な方向に適合しない場合にのみ、`1 × 2`検索は空の領域を見つけて返します`0`。 

長方形が境界線に接触すると、`+1`ループ制限内では、最後の有効な左上隅をチェックできます。 のために：```
2 2
1 0
0 1
2 2
```可能な配置は 1 つだけです。 アルゴリズムはそれにアクセスし、両方のツリーをカウントします。 

すべてのセルに木が含まれている場合、最小値はゼロにはなりません。 答えは大きな値から始まり、実際の配置を評価した後にのみ置き換えられるため、アルゴリズムはデフォルト値の代わりに真の最小木の数を返します。
