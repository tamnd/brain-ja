 ## 問題の理解

 一連の正の数があります。 シーケンスが空ではない連続する 2 つの部分に分割される位置を 1 つ選択する必要があります。 パートの値はその要素の合計であり、カットのスコアは結果として得られる 2 つの合計の積です。 タスクは、この製品ができるだけ大きくなるように、その後にカットを行う必要がある位置を出力することです。 複数の位置が同じ最大値を与える場合、それらのいずれも受け入れられます。 

配列には最大で次のものを含めることができます$2 \cdot 10^5$要素、および各要素の大きさは次のとおりです。$10^9$。 すべての境界線のペアを試したり、すべての可能なカットの合計を再計算したりするソリューションでは、すぐに使用可能な時間を超えてしまいます。 平$O(n^2)$操作は約を意味します$4 \cdot 10^{10}$最大のケースでのチェックですが、これは実用的なレベルをはるかに超えています。 We need a linear or close to linear approach.

 よくある間違いは、最大の要素がカットを決定するべきであると考えることです。 目標は、個々の値ではなく、グループの合計に依存します。 もう 1 つの間違いは、答えが最大積そのものではなく指数であることを忘れていることです。 

次の配列を考えてみましょう。```
3
1 2 3
```正しい出力は次のとおりです。```
2
```2 番目の要素の後に切り取ると合計が得られます$1+2=3$そして$3$、生産$9$。 最初の要素が与えられた後に切り取る$1\cdot5=5$。 最大の要素のみをチェックするソリューションでは、これを捕捉できません。 

もう 1 つのエッジ ケースは、いくつかのカットが同等に優れている配列です。```
4
1 1 1 1
```正しい出力は次のいずれかになります。```
1
2
3
```あらゆるカットが製品を生み出す$1\cdot3$、$2\cdot2$、 または$3\cdot1$したがって、ここでは実際には中央のカットのみが最適です。 最初に発生する最大値が常に許容されると想定する不用意な実装でも、回答ロジックを正しく更新する必要があります。 

より関連性の高い境界ケースは、ベスト カットが終わりに非常に近い場合です。```
2
5 7
```考えられる唯一の答えは次のとおりです。```
1
```2 番目の要素の後には、両方の部分が空であってはいけないため、有効なカットはありません。 

## アプローチ

 直接的なアプローチは、あらゆる可能なカットを試すことです。 カット後のポジションの場合$i$、左側の部分の合計と右側の部分の合計を計算し、それらを乗算して、最適な位置を維持します。 考えられるすべての答えがチェックされるため、これは正解です。 すべての位置について合計を最初から計算する場合、複雑さは次のようになります。$O(n^2)$、あるからです。$n-1$カットの可能性があり、各計算で多くの要素がスキャンされる可能性があります。 と$n=200000$、これはおよそになります$4\cdot10^{10}$追加。 

最初の改善点は、すべてのカットが同じ情報を共有していることを観察することです。 配列全体の合計は決して変わりません。 左側の部分の合計が$x$の場合、右側の部分は単純に$S-x$、 どこ$S$の合計です。 製品は次のようになります。$$x(S-x)$$ここで、問題は 2 つの独立した和に関するものではなくなりました。 各位置の後のプレフィックスの合計を知り、式を最大化する値を見つけることだけが必要です。 

機能$x(S-x)$放物線です。 その最大値に達するのは、$x$にできるだけ近いです$S/2$。 すべての配列要素は正であるため、配列内を移動するにつれてプレフィックスの合計は増加するだけです。 左から右にスキャンして、各プレフィックスの合計をこれまでに確認された最良の値と比較できます。 

ブルートフォース手法は、考えられるすべてのパーティションを検査するため機能します。 以前のカットにすでに含まれている情報を繰り返し計算するため、失敗します。 固定総和に関する観察により、問題全体が配列の 1 回のパスに短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列内のすべての要素の合計を計算します。 この値は、考えられるすべてのカットにおける両方の部品の合計重量を表します。 
2. 現在のプレフィックスの合計を維持しながら配列を走査します。 加工後の位置$i$、このプレフィックスの合計は、後でカットした場合の左側の部分の重みになります。$i$。 
3. 考えられるカットごとに、プレフィックスの合計と残りのサフィックスの合計の積を計算します。 これまでに見つかった最高の製品と比較し、答えが改善された場合はその位置を保存します。 
4. トラバース終了後、保存された位置を出力します。 空ではないすべての可能な左部分が 1 回だけ考慮されています。 

なぜ効果があるのか:

 どのカットでも、結果として得られる 2 つの重みは常に同じ合計値となります。$S$。 スコアは左の重みだけで決まります$x$、なぜなら適切な体重は$S-x$。 スキャン中に、可能なすべての値が$x$有効なカットによって生成されたものが検査されます。 アルゴリズムは可能なカットごとに積を比較するため、保存された位置は最大積に対応する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    total = sum(a)

    best_product = -1
    answer = 1
    prefix = 0

    for i in range(n - 1):
        prefix += a[i]
        product = prefix * (total - prefix)

        if product > best_product:
            best_product = product
            answer = i + 1

    print(answer)

if __name__ == "__main__":
    solve()
```このコードは、まず配列の合計を 1 回計算します。 Python の整数は、可能な最大の積がおよそであるため、大きな積を安全に処理できます。$10^{28}$。 

ループは次で停止します`n - 1`最後の要素を左側の部分の終わりにすることはできないためです。 これを含めると右側の部分が空になってしまいますが、これは許可されません。 

現在のインデックスは左側のセグメントに含まれる要素を表すため、プレフィックスの合計は積を計算する前に更新されます。 保存された回答は次を使用します`i + 1`なぜなら、この問題では 1 から始まるインデックスの位置が求められるからです。 

比較には次のものだけを使用します`>`それよりも`>=`。 複数のカットに同じ製品がある場合、最初のカットを保持することが有効です。

## テストケース```python
import sys
import io

def solve(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))

    total = sum(a)
    prefix = 0
    best = -1
    ans = 1

    for i in range(n - 1):
        prefix += a[i]
        cur = prefix * (total - prefix)
        if cur > best:
            best = cur
            ans = i + 1

    sys.stdin = old_stdin
    return str(ans)

assert solve("""3
1 2 3
""") == "2", "sample 1"

assert solve("""5
10 1 1 1 10
""") == "2", "sample 2"

assert solve("""2
5 7
""") == "1", "minimum size"

assert solve("""5
4 4 4 4 4
""") == "2", "all equal values"

assert solve("""6
1 1000000000 1 1 1 1
""") == "2", "large values"

assert solve("""4
1 1 1 10
""") == "3", "boundary near end"

 ## 特殊なケース

 最小サイズの場合:```
2
5 7
```アルゴリズムは反復を 1 回だけ実行します。 プレフィックスは次のようになります`5`、接尾辞は次のようになります`7`、そして製品は`35`。 有効なパーティションは 1 つだけなので、答えは正解です。`1`。 

繰り返される値の場合:```
5
4 4 4 4 4
```合計は`20`。 考慮されるプレフィックスの合計は次のとおりです。`4`、`8`、`12`、 そして`16`、製品を与える`64`、`96`、`96`、 そして`64`。 アルゴリズムは最初の最大値をその位置に保持します`2`、これは有効な答えです。 

非常に大きな要素の場合:```
6
1 1000000000 1 1 1 1
```積の値が通常の 32 ビット整数の制限を超えています。 Python の整数演算はこれらの値を直接処理するため、特別な変換は必要ありません。 

終わりに近いカットの場合:```
4
1 1 1 10
```プレフィックスの合計は`1`、`2`、 そして`3`、接尾辞の合計は`12`、`11`、 そして`10`。 製品は、`12`、`22`、 そして`30`、したがってアルゴリズムは位置を選択します`3`。 最後の要素はカット位置とはみなされないため、無効な空の接尾辞が発生することはありません。
