 ## 問題の理解

 まず、ドレスと呼ばれるいくつかのオブジェクトを保持するコンテナから始めます。 最初に存在するのは、`x`ドレス。 時間は離散的なステップで進み、`k + 1`合計ステップ数。 

最初のそれぞれで`k`ステップごとに、プロセスの構造は決定的ですが、結果はランダムです。 まず、ドレスの数が2倍になります。 2倍にした直後、ワードローブが空でない場合は、半分の確率で1枚のドレスが削除されます。 最終ステップ (先月) では 2 倍化のみが実行され、その後ドレスが削除されることはありません。 

結局のところ、タスクは予想されるドレスの数を計算することです`k + 1`ステップを実行し、結果のモジュロを返します`1e9 + 7`。 

重要な問題は、潜在的な可能性に対してランダムな分岐が繰り返されるプロセスで期待が引き継がれてしまうことです。`10^18`ステップがあるため、シミュレーションは不可能です。 どのようなソリューションでも、各ステップの効果を閉じた形式の変換に圧縮する必要があります。 

この制約により、総当たり攻撃は完全に不可能になります。 繰り返しても`k`ステップが大きすぎるため、`k`まで可能です`10^18`。 これにより、時間の経過に伴うステップごとのシミュレーションや DP が即座に排除されます。 唯一の実行可能な方向性は、期待が代数的にどのように進化するかを理解することです。 

微妙なエッジケースが現れるのは、`x = 0`。 この場合、2 倍にして削除しても結果はゼロになるため、プロセスではドレスが得られません。 ゼロの動作を保護せずに 2 による除算を伴う代数的漸化式を盲目的に適用する単純な実装はまだ機能しますが、推論は式が正しく縮退していることを確認する必要があります。 

もう 1 つの潜在的な落とし穴は、ランダムな削除を正しく解釈することです。 それは倍増前ではなく倍増後に起こり、最初のときにのみ起こります。`k`トランジション。 最終月には削除ステップがありません。これにより、最後のステップで繰り返しがわずかに変更され、正確さを保つために不可欠です。 

## アプローチ

 直接シミュレーション手法を使用すると、各月の後に可能なワードローブのサイズの正確な分布が維持されます。 各ステップの後、すべての状態は 2 つの可能性に分かれます。1 つは倍増後にドレスが削除されない場合、もう 1 つは倍増後にドレスが削除される場合です。 各ステップで考えられる結果の数が 2 倍になるため、時間の経過とともに状態の数が指数関数的に増加します。 後`k`ステップがあるでしょう`2^k`これは計算可能な限界をはるかに超えています。`k`できる`10^18`。 

重要な観察は、完全な分布は必要なく、期待値のみが必要であるということです。 期待値は線形なので、1 ステップで期待値がどのように変化するかを追跡できます。 

させて`E`ある月に予想されるドレスの数になります。 2倍後の値は次のようになります`2E`。 そうすると確率的に`1/2`、ドレスを 1 枚差し引きます。 この引き算が貢献します`-1`確率的に期待して`1/2`したがって、期待される減算は次のようになります。`1/2`。 したがって、最初のそれぞれの`k`遷移は期待値を次のように変換します。`E -> 2E - 1/2`最後の移行（月）`k+1`) は 2 倍になるだけです。`E -> 2E`したがって、プロセス全体は線形変換の繰り返し適用になります。 これは古典的なアフィン再帰です。`E_{i+1} = 2E_i - 1/2`のために`i < k`、 そして`E_{k+1} = 2E_k`。 

モジュロ演算で端数を削除するには、すべてに 2 を掛けます。`F = 2E`。 それから：`F_{i+1} = 2F_i - 1`のために`i < k`、 そして`F_{k+1} = 2F_k`。 

これで、すべてが整数算術モジュロになります`MOD`。 

アフィン変換を適用する必要があります`k`倍にして、最後に 1 回倍増します。 最初の変身`k`ステップは等比級数を使用して閉じた形式で解くことができます。 

各ステップ:`F -> 2F - 1`展開:`F_k = 2^k * x*2 - (2^k - 1)`そして最後のステップ:`F_{k+1} = 2 * F_k`最後に元に変換します。`E = F / 2`これにより、次のように計算可能な閉じた形式の式が得られます。`O(log k)`べき乗モジュラーを使用します。

 ## アルゴリズムのチュートリアル

 1. 平均値のみが重要であり、完全な分布は不要であることを認識して、漸化式を期待値形式に変換します。 これにより、問題は確率的な分岐から決定的な再発へと軽減されます。 
2. 最終月以外の各月の後の更新ルールを、期待値の線形変換として書き換えます。2 倍すると期待値が 2 倍になり、ランダムな削除により確率 1/2 で 1 が減算され、正味の減算は 1/2 になります。 
3. 状態変数をスケーリングして端数を消去します。 交換する`E`と`F = 2E`、更新をクリーンな整数の繰り返しに変換します。`F -> 2F - 1`。 
4. これが次の形式のアフィン反復であることを特定します。`F_{n+1} = aF_n + b`定数係数を使用します。 このような漸化式は、乗法部分と加法部分を分離することで解決できます。 
5. 繰り返しを展開します`k`反復された減算項から等比級数の寄与を取得するステップ。 乗数は 2 のべき乗として増加し、定数項は 2 のべき乗の合計として累積されます。 
6. 閉じた形式を計算します。`F_k = F_0 * 2^k - (2^k - 1)`どこ`F_0 = 2x`。 
7. 最後のステップを個別に適用します。これは 2 倍だけです。`F_{k+1} = 2 * F_k`。 
8. 2 を法として除算して期待値に戻します。`MOD`、これは 2 の逆剰余を乗算することと同じです。 

### なぜ効果があるのか

 毎月適用される変換は現在の予想では線形であるため、プロセス全体がアフィン関数の構成を形成します。 アフィン関数の合成はアフィンのままであるため、任意の数のステップの後でも期待値が次のように表現できることが保証されます。`A * x + B`。 上記で導出された閉じた形式は、まさに同じアフィン マップを繰り返し構成し、等比級数を介してその一定の寄与を合計した結果です。 期待値は線形であるため、より高いモーメントが結果に影響を与えることはなく、この削減が正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def mod_pow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve():
    x, k = map(int, input().split())
    
    if k == 0:
        print((x * 2) % MOD)
        return

    # compute powers
    p = mod_pow(2, k)
    inv2 = (MOD + 1) // 2

    # F0 = 2x
    F0 = (2 * x) % MOD

    # Fk = F0 * 2^k - (2^k - 1)
    Fk = (F0 * p) % MOD
    Fk = (Fk - (p - 1)) % MOD

    # final doubling
    F = (Fk * 2) % MOD

    # convert back: E = F / 2
    ans = (F * inv2) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```コードは、閉じた形式の式を直接実装します。 べき乗モジュラーの計算`2^k`、ここは大きな制約が課される唯一の場所です。`k`重要です。 繰り返しの単純化により、月単位の繰り返しが完全に回避されます。 

特別な場合`k = 0`最後の月しかなく、したがって削除イベントがない状況を処理します。 

2 の逆数は、スケーリングされた変数をモジュラー演算で期待値に変換するために最後に使用されます。

 ## 特殊なケース

 いつ`x = 0`、漸化式は依然として代数的に適用されますが、すべての中間状態は期待値としてゼロのままです。 スケーリング後には乗法成分と加法成分の両方が 0 に評価されるため、式は正しく減算されます。 

のために`k = 0`、ランダムな削除は発生しません。 このプロセスは、決定的な 2 倍化ステップの 1 つだけです。 アルゴリズムは明示的に繰り返しをバイパスし、次の値を返します。`2x`、プロセス定義と一致します。 

いつ`k`が大きいと、直接反復すると時間制限をオーバーフローしてしまいますが、べき乗剰余演算により対数処理のみが行われることが保証されます。 繰り返しは中間状態に依存しないため、中間状態をスキップしても最終的な期待値に関する情報が失われることはありません。
