 ## 解決策
 ## 問題の理解

 整数のリストが与えられ、非常に特殊な方法で配列を変更する操作を繰り返し適用することができます。つまり、1 回の操作で整数値を選択し、現在ゼロではないすべての要素にそれを追加します。 その操作中、ゼロはそのまま残ります。 すべての要素が同時にゼロになるとプロセスは終了します。タスクは、その状態に到達するために必要な操作の数を最小限に抑えることです。 

重要な点は、各操作がゼロ以外のすべての要素に均一に作用するため、要素を個別に編集しているわけではないということです。 代わりに、配列の構造が一括して進化し、ゼロ値は将来の更新への参加を停止する「固定点」のように動作します。 

n が 10^5 までの制約により、すべての解は線形または線形に近い時間で実行されます。 多くの操作にわたって配列をシミュレートするアプローチは、特に要素を繰り返しスキャンまたは更新する場合、O(n^2) 動作の危険性があり、合格しません。 

配列にゼロ以外のものが混在するゼロが多数含まれている場合、微妙なエッジ ケースが発生します。 たとえば、次のような配列では、`[0, 5, 0, -2]`、ゼロは永続的な区切り文字として機能し、ゼロ以外のセグメントのみが影響を受ける可能性があります。 単純な考えでは、すべての値を一度に正規化しようとするかもしれませんが、ゼロは更新から除外されるため、グローバル同期が妨げられ、セグメントごとに個別の推論が強制されます。 

## アプローチ

 ブルートフォース解釈では、プロセスを直接シミュレートしようとします。 毎秒、値を選択してゼロ以外のすべての要素に適用し、すべてがゼロになったかどうかを確認します。 そうでない場合は、繰り返します。 これは簡単ですが、各操作では配列をスキャンして非ゼロ要素を特定し、それらを更新する必要があります。 最悪の場合、すべての値を削除するために必要な個別の「フェーズ」の数に比例した数の操作が必要になる可能性があり、各フェーズのコストは O(n) になります。 これにより、敵対的なケースでは O(n^2) の動作が発生し、n = 10^5 には遅すぎます。 

重要な観察は、ゼロが影響の観点から配列を独立したセグメントに分割していることです。 要素がゼロになると、その要素は永久に変化しなくなります。 これは、配列の進化は、ゼロで区切られた非ゼロ値の個別の連続ブロックを何回「終了」する必要があるかによって完全に左右されることを意味します。 

演算を適用するたびに、すべてのアクティブな (ゼロ以外の) 値をまとめて効果的に削減します。セグメントに混合符号または異なる大きさが含まれる場合は常に、そのセグメントが完全に折りたたまれる前に複数の削減が必要になります。 ただし、毎回任意の整数を選択できるため、最適な戦略は、最大の連続する非ゼロ セグメントを個別に折りたたむ方法で寄与を排除することであり、これらのセグメントは複数の操作にわたって並行して処理できます。 

これにより、問題が構造的なカウントに還元されます。ゼロ以外の要素の最大の連続セグメントはすべて、答えに正確に 1 単位の時間を寄与します。 直感的には、各セグメントには少なくとも 1 つの個別の「消去フェーズ」が必要であり、ゼロはセグメント間の相互作用をブロックするため、分離されたセグメント間で共有することはできません。 

したがって、答えは単純に、配列内の非ゼロ要素の連続ブロックの数になります。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n²) | お(1) | 遅すぎる |
 | ゼロ以外のセグメントを数える | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を左から右にスキャンし、ゼロ以外のセグメントに入った回数を数えます。 

1. カウンタをゼロに初期化します。 これにより、連続する非ゼロブロックの数が保存されます。 
2. 配列をインデックス 0 から n − 1 まで走査します。 
3. ゼロ以外の要素が見つかり、それが最初の要素であるか、前の要素がゼロである場合、カウンターをインクリメントします。 これにより、新しいセグメントの開始が識別されます。 
4. そのセグメントを離れるまで (つまり、ゼロに遭遇するか、最後に到達するまで) 増分せずにスキャンを続けます。 
5. トラバース終了後、カウンターを戻します。 

ステップ 3 の背後にある理由は、ゼロから非ゼロへの移行のみが新しい独立グループの始まりを示すということです。 セグメントの内部要素はすべて同じ一連の操作で一緒に処理されるため、重要ではありません。 

### なぜ効果があるのか

 この操作は同時に非ゼロ要素にのみ影響を与えることができ、ゼロは配列を分離された領域に永続的に分割します。 ゼロ以外の値の単一の連続領域内では、領域全体が崩壊するまで、すべての要素が常に一緒に更新されます。 ゼロは決して変化しないため、どの操作でも 2 つの分離された領域をマージすることはできません。 したがって、連続する各非ゼロ セグメントは、1 つの有効な「崩壊フェーズ」を必要とする独立したユニットのように動作し、そのようなフェーズの数は正確にセグメントの数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ans = 0
    for i in range(n):
        if a[i] != 0 and (i == 0 or a[i-1] == 0):
            ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```コードはトラバーサル ロジックに直接に従います。 条件`a[i] != 0`アクティブな要素のみを考慮することを保証しますが、`(i == 0 or a[i-1] == 0)`ゼロ以外の各ブロックの最初の要素のみをカウントするようにします。 これにより、セグメント内での二重カウントが回避され、各セグメントが正確に 1 回だけ寄与することが保証されます。 

このソリューションは本質的に完全なストリーミングであり、必要なのは 1 回のパスと一定の追加メモリだけです。

 ## 特殊なケース

 のような入力の場合`1 0 2 0 3`、スキャンでは、ゼロの後の各非ゼロで新しいセグメントが検出されます。 最初の要素はセグメントを開始し、インデックス 2 はゼロの後に別の要素を開始し、インデックス 4 は 3 番目の要素を開始します。 遷移条件はゼロからゼロ以外の境界でのみトリガーされるため、それぞれが 1 回だけカウントされます。 

のような入力の場合`0 0 0`、どの要素も満たさない`a[i] != 0`したがって、カウンターは全体を通してゼロのままです。 これは、配列がすでに終了状態にあるという事実と一致します。 

次のような完全な負の配列の場合`-5 -4 -3`、アルゴリズムは値ではなく構造セグメンテーションのみを追跡するため、符号は無関係です。 配列全体は 1 つの連続した非ゼロ ブロックであるため、答えは 1 になります。
