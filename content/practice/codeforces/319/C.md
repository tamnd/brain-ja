 ## 解決策
 ## 問題の理解

 厳密に高さが増加する一連の木が与えられています。 チェーンソーを使用して、各木を一度に 1 ユニットずつ切り倒すことができます。 チェーンソーは切断するたびに再充電する必要があり、再充電コストはどの木がすでに完全に切断されているかによって異なります。 具体的には、完全に切断された最も高いインデックスのツリーがtree _i_である場合、再充電のコストは_b[i]_です。 目標は、充電に費やす総コストを最小限に抑えながら、すべての木を完全に伐採することです。 

入力は、整数 _n_、高さの配列 _a_、およびコストの配列 _b_ で構成されます。 高さは 1 から開始して厳密に増加し、リチャージ コストは厳密に減少して 0 で終わります。出力は単一の数値、つまりすべての木の高さを 0 に下げるための最小総コストです。 

制約は、_n_ は最大 10^5、_a[i]_ と _b[i]_ は最大 10^9 にできることを示しています。 すべての切断単位をシミュレートする強引なアプローチは、最悪の場合、最大 10^14 の操作が必要になる可能性があるため、実行できません。 _n_ では線形または線形に近い解決策が必要です。 エッジケースには、最初の木の高さがすでに 1 でコストがゼロでない可能性がある _n = 1_ と、コストが 0 に低下するケース (最終的にチェーンソーが無料で充電できるようになる) が含まれます。 

累積コストを考慮せずに、常に次のツリーを即座に 0 にカットするという単純なアプローチは失敗します。 たとえば、`a = [1, 2, 3]`そして`b = [5, 2, 0]`、最初の木が終わる前に 2 番目の木を伐採すると、繰り返し高いコストを支払わなければならない可能性があります。 

## アプローチ

 ブルートフォースアプローチは、チェーンソーが木ごとに切断することをシミュレートし、再充電ごとに現在のコストを更新します。 カット単位ごとに、完成した最大ツリーをチェックし、対応する _b[i]_ を追加します。 これは論理的には正しいですが、演算数の合計がすべての高さの合計 (10^14 になる可能性がある) になる可能性があるため、完全に実行不可能です。 

最適化すべき重要な観察は、両方のアレイの単調な構造から得られます。つまり、高さは厳密に増加し、コストは厳密に減少しています。 各ツリーは完全に切断する必要があるため、問題をブロックの観点から考えるのが安全です。つまり、現在の最大ツリーが _i_ である間に何回切断するかということです。 後の木を伐採しても、それ以前の木のコストは増加しないため、最小総コストは、各木の高さの合計に、その伐採中に適用される最小再充電コストを乗じたものとして定式化できます。 

これは自然に動的プログラミングにつながります。 させて`dp[i]`は、木 1 から _i_ までを伐採するための最小総コストを表します。 木 _i_ については、前の木と比較して、伐採を開始する最適な点を決定できます。 単調性のため、最適な戦略は常に連続的です。再充電コストを最小限に抑えるために、いくつかの連続した木のセットを一緒に切り取ります。 再発は次のとおりです。```
dp[i] = min(dp[j] + (a[i] - a[j]) * b[j])  for all j < i
```ここ、`a[i] - a[j]`木 _j_ が完成した後に木 _i_ を切断するユニットの数です、そして`b[j]`は、そのセグメント中の単位あたりのコストです。 凸性プロパティを使用すると、凸包トリックを適用して、これを O(n) または O(n log n) で効率的に計算し、すべての j < i の二次評価を回避できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(合計(a[i])) | O(n) | 遅すぎる |
 | 動的計画法 + 凸包トリック | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DP アレイを初期化する`dp`サイズは_n_、ここで`dp[i]`は、木を 1 から i まで伐採するための最小コストを表します。 セット`dp[0] = a[0] * b[0]`、最初の木を伐採するコスト。 
2. 両端キューまたはリストを使用して、凸包トリックの候補行を維持します。 各行は前の状態を表します`(slope, intercept)`に対応する`b[j]`そして`dp[j] - a[j]*b[j]`。 
3. それぞれの木について`i`1 から n-1 まで、凸包をクエリして最小化する線を見つけます。`dp[j] + (a[i] - a[j]) * b[j]`。 これにより、ツリー _i_ に到達するための最小コストが得られます。 
4. に対応する新しい行を追加します。`i`凸包に。 新しい回線によって古い回線が冗長になる場合は、それらを削除します。 
5. すべてのツリーを処理した後、`dp[n-1]`すべての木を完全に伐採するための最小限のコストが含まれています。 

機能する理由: DP の定式化では、切断をセグメントに分割し、それぞれのセグメントにその時点で完成した最大の木に応じて請求することで、総コストを正確に把握します。 コスト関数が線形であるため、凸包トリックは有効です。`a[i]`傾きが減少する (単調`b[i]`)、候補線のシーケンスが凸状になり、各ステップで最小限の交差線のみが必要になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def main():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    dp = [0] * n
    dp[0] = a[0] * b[0]
    
    lines = deque()
    lines.append((b[0], dp[0] - a[0]*b[0]))
    
    def value(line, x):
        m, c = line
        return m * x + c
    
    for i in range(1, n):
        while len(lines) >= 2 and value(lines[0], a[i]) >= value(lines[1], a[i]):
            lines.popleft()
        dp[i] = value(lines[0], a[i])
        new_line = (b[i], dp[i] - a[i]*b[i])
        while len(lines) >= 2:
            m1, c1 = lines[-2]
            m2, c2 = lines[-1]
            m3, c3 = new_line
            if (c3 - c2) * (m2 - m1) <= (c2 - c1) * (m3 - m2):
                lines.pop()
            else:
                break
        lines.append(new_line)
    
    print(dp[n-1])

if __name__ == "__main__":
    main()
```DP 配列は、各ツリーまでの総コストを追跡します。 凸包内の線は、前の状態の候補を表します。 ハルをクエリすると、最小限のコストが効率的に得られます。 行の削除条件では、浮動小数点エラーを回避するために交差乗算が使用されます。 

## 実用的な例

 サンプル 1:```
n = 5
a = [1, 2, 3, 4, 5]
b = [5, 4, 3, 2, 0]
```| 私 | dp[i] | i 以降の行 (m, c) |
 | --- | --- | --- |
 | 0 | 5 | [(5,0)] |
 | 1 | 9 | [(5,0),(4,1)] |
 | 2 | 12 | [(5,0),(4,1),(3,3)] |
 | 3 | 14 | [(5,0),(4,1),(3,3),(2,6)] |
 | 4 | 15 | [(5,0),(4,1),(3,3),(2,6),(0,15)] |

 これは、累積最小コストの計算と、関連するラインのみを維持する凸包を示しています。

b = [6,3,0]
```| 私 | dp[i] | 行 |

 ここで、凸包は、より安価なラインが優勢になるまでのみ、初期の高コストラインを選択します。

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(n) | 各行は、両端キューに対して最大 1 回追加および削除されます。 |
