 ## 解決策
 ## 問題の理解

 私たちは、一連の動的な間隔を維持し、それらの間の到達可能性のクエリに答えるように求められます。 各間隔は 2 つの整数で表されます$(x, y)$どこ$x < y$。 間隔は 1 つずつ追加され、新しい間隔は以前のすべての間隔よりも厳密に長くなることが保証されます。 インターバルからの動き$(a, b)$間隔まで$(c, d)$のいずれかのエンドポイントの場合に許可されます$(a, b)$厳密に内側にあります$(c, d)$。 このような動きを連鎖させることができれば、2 つの間隔の間にパスが存在します。 

入力は、新しい間隔を追加するか、以前に追加された間隔から別の間隔へのパスが存在するかどうかを尋ねる、いくつかのクエリで構成されます。 出力は、2 番目のタイプの各クエリに対して「YES」または「NO」で応答する必要があります。 

と$n$まで$10^5$までのコーディネート$10^9$、私たちには余裕がありません$O(n^2)$すべてのクエリで間隔のすべてのペアを比較するアプローチ。 単純な解決策では、新しい間隔を追加したり、到達可能性を確認したりするたびに、設定された間隔全体をスキャンすることになり、その結果、最大で$10^{10}$operations, far beyond a 2-second time limit. 増分更新と効率的な到達可能性クエリを可能にするデータ構造が必要です。 

厳密に長さを増加させると間隔が追加されるため、微妙なエッジケースが発生します。 これにより、新しい間隔は古い間隔に含めることはできませんが、古い間隔は新しい間隔に含めることができることが保証されます。 不注意な実装では、このプロパティを利用せずにすべてのクエリですべての間隔をチェックしようとする可能性があり、二次時間計算量が発生します。 

もう 1 つのエッジ ケースは、間隔がエンドポイントを共有する場合です。 たとえば、次の場合$(1, 5)$そして$(5, 11)$が存在しても、最初の端点のどちらの端点も厳密に 2 番目の端点の内側にないため、最初の端点から 2 番目の端点へのパスは存在しません。 ここでの正しい出力は「NO」です。 

## アプローチ

 ブルート フォース ソリューションは、各クエリに対してこれまでに追加されたすべての間隔を反復します。 タイプ 2 クエリの場合、開始間隔から深さ優先検索を実行し、エンドポイント包含ルールを使用して各間隔の到達可能性をチェックできます。 このアプローチは正しいですが、最悪の場合、クエリごとにすべての間隔を走査する必要があり、その結果、$O(n^2)$時間の複雑さ。 と$n = 10^5$、これは明らかに遅すぎます。 

より高速なソリューションを実現する重要な観察は、厳密に増加する長さのプロパティです。 これは、すべての新しい間隔は古い間隔を「吸収」できますが、古い間隔は吸収できないことを意味します。 その結果、到達可能性は常に小さい間隔から大きい間隔へと順方向に向けられます。 各間隔をノードとして表し、その間隔の 2 つの値、つまり連続する移動によって到達できる最小位置と最大位置を維持できます。 新しい間隔が追加されると、エンドポイントがその中にある以前の間隔の範囲が拡張される場合があります。 この到達可能性を線形時間で効率的に伝播するには、一定の間隔で逆方向に反復し、到達可能な範囲を更新します。 間隔が処理されると、クエリに答えることは、宛先間隔のエンドポイントがソース間隔の到達可能な範囲内にあるかどうかを確認することになります。 これにより、次の問題が軽減されます。$O(n^2)$に$O(n)$すべての追加とクエリを処理するため。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 追加された順序で間隔のリストを維持します。 各間隔には、その開始座標と終了座標が保存されます。 
2. 2 つの配列を維持します。`reach_min`そして`reach_max`、各間隔から到達可能な最小位置と最大位置を表します。 
3. 新たに間隔を追加する場合`(x, y)`、初期化します`reach_min`そして`reach_max`それのために`x`そして`y`。 以前に追加した間隔を逆方向に反復します。 間隔の開始または終了が新しい間隔内にある場合は、前の間隔の値を更新します。`reach_min`そして`reach_max`新しい間隔の範囲が含まれるようにそれらを拡張することによって。 現在の間隔の到達範囲がすでに新しい間隔をカバーしている場合は、伝播を停止します。 
4. お問い合わせの場合`(a, b)`、間隔があるかどうかを確認します`b`完全に到達可能な範囲内にあります`[reach_min[a], reach_max[a]]`。 いずれかのエンドポイントの場合、`b`この範囲内にある場合は、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

厳密に増加する間隔の長さにより、すべての到達可能性の伝播が単調であることが保証されるため、正確性が保証されます。つまり、範囲が一度拡張されると縮小することはなく、すべての移動が包含ルールに準拠します。 これにより、到達可能性の計算が間隔拡張の単一パスと同等になり、すべての可能なパスがキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
intervals = []
reach_min = []
reach_max = []

for _ in range(n):
    parts = input().split()
    if parts[0] == '1':
        x, y = int(parts[1]), int(parts[2])
        intervals.append((x, y))
        reach_min.append(x)
        reach_max.append(y)
        i = len(intervals) - 2
        while i >= 0:
            lx, rx = reach_min[i], reach_max[i]
            nx, ny = reach_min[-1], reach_max[-1]
            a, b = intervals[i]
            if (a > nx and a < ny) or (b > nx and b < ny):
                reach_min[i] = min(lx, nx)
                reach_max[i] = max(rx, ny)
            i -= 1
    else:
        a, b = int(parts[1]) - 1, int(parts[2]) - 1
        bx, by = intervals[b]
        if (bx >= reach_min[a] and bx <= reach_max[a]) or (by >= reach_min[a] and by <= reach_max[a]):
            print("YES")
        else:
            print("NO")
```ソリューションの各部分はアルゴリズムのステップに直接対応します。 間隔とその到達範囲を保存します。 新しい間隔を追加するときは、現在その間隔に到達する可能性がある間隔にのみ、到達可能性を逆方向に伝播します。 クエリは、宛先間隔がソース間隔の到達可能な範囲内にあるかどうかを確認するだけです。 それ以上の拡張が発生しなくなると逆方向伝播が停止し、不必要な更新が防止され、線形合計時間の複雑さが維持されます。
