 ## 問題の理解

 整数として解釈するバイナリ文字列が与えられ、そこから 2 つの順序付けられたサイズのセット間の固定ペアを構築します。$2^n$。 各インデックス$i$左側のインデックスは、指定された 2 進数で XOR 変換を適用することにより、右側の 1 つのインデックスと一致します。 

これらのペアが修正されたら、そのような一致の順序付けされていないペアをすべて調べます。 任意の 2 ペアの場合$(a, b)$そして$(c, d)$、左側のエンドポイントが昇順であり、右側のエンドポイントが降順である場合、それらが複雑さに寄与していると言います。$a < c$しかし$b > d$。 タスクは、XOR マッピングによって引き起こされるすべてのペアの中にそのような反転がいくつ存在するかを数えることです。 

入力サイズが小さいため、$n \le 100$、しかし、暗黙の構造は指数関数的です。$2^n$要素。 これにより、すべてのペアを明示的に構築または反復するアプローチは即座に除外されます。 完全な順列を保存することすら不可能になるため、有効なソリューションでは、任意の順列として扱うのではなく、XOR マッピングの構造を利用する必要があります。 

一般的な障害モードは、すべてのインデックスの順列を直接シミュレートしようとして、$O(N^2)$反転回数。 たとえ慎重に最適化したとしても、このアプローチは一度終了するとすぐに機能しなくなります。$n$20歳くらいを過ぎると成長するので、$2^n$爆発する。 

## アプローチ

 問題は順列を定義します$p(i) = i \oplus x$全体$2^n$インデックス。 この順列における反転の数を計算するように求められます。ここで、反転はペアです。$i < j$そのような$p(i) > p(j)$。 

ブルートフォースアプローチでは、順列を明示的に計算し、すべてのペアをチェックして反転をカウントします。$(i, j)$。 それは定義に直接従っているため、これは正しいです。 ただし、反復処理が必要です$2^n$インデックスをすべてのペアに適用し、すでに指数関数的なドメイン サイズに二次依存性を与えます。 作業数はおおよそになります$O(4^n)$、中程度の人でも不可能です$n$。 

重要な点は、固定数による XOR は任意の順列ではないということです。 これは、マスクに従ってビットを個別に反転するビット単位の変換です。 これにより、要素ごとではなくビットごとに反転を推論できるようになります。 

最上位ビットから最下位ビットまで処理します。 各ビット位置で、XOR マスクはそのビットを保持するか反転します。 2つの指数を比較すると$i < j$、順序は、異なる最初のビットによって異なります。 XOR はまさにその構造に影響を与えます。つまり、各ビット レベルで相対的な順序を反転するペアの数を追跡できることを意味します。 

これにより、分割統治型のカウント プロセスが行われます。 各ビットで、インデックスとその XOR イメージの両方でそのビットが 0 であるか 1 であるかに基づいて数値を分割します。 半分の内側の寄与を再帰的に計算し、XOR 反転により順序が逆転するクロス寄与を追加します。 

この構造により、マスクによって引き起こされたビット フリップの下で異なる動作をするプレフィックスのペアが何組あるかを数えることに問題が効果的に軽減されます。

 ## アルゴリズムのチュートリアル

 1. バイナリ文字列を整数マスクとして解釈します。$x$。 このマスクは順列を定義します$p(i) = i \oplus x$全体$2^n$長さの整数$n$。 目標は、この順列の反転を数えることです。 
2. ビットの固定プレフィックス長で表される数値のサブセットを操作する再帰関数を定義します。 レベルで$k$、頂点が次のすべての数値を考慮します。$k$ビットは固定されており、残りのビットのみが変化します。 これにより、部分問題がバイナリ構造に合わせて維持されます。 
3. 最上位から最下位までの各ビット位置で、インデックス内のビットが 0 であるか 1 であるかに基づいて、現在のセットを 2 つのグループに分割します。 このパーティションは、整数の辞書編集順序を反映します。 
4. 各グループについて、XOR がグループ内の順序にどのような影響を与えるかを再帰的に計算します。 これは、構造が同一であるもののビット数が少ない固定プレフィックス領域内で完全に発生する反転を処理します。 
5. 次に、現在のビットで 2 つの要素が異なる半分にあるペアを考えます。 XOR を使用しない場合、0 半分のすべての要素は 1 半分の要素よりも小さくなります。 XOR は一方のビットを反転し、比較を逆にする可能性があります。 マスクを適用した後にそのようなクロスペアが何個反転するかを数えます。 
6. 再帰カウントとクロスカウントの結果を結合し、合計モジュロを返します。$10^9 + 7$。 

### なぜ効果があるのか

 正確さは、整数の辞書編集上の順序が完全に最上位の異なるビットによって決定されるという事実から来ています。 XOR はビットに独立して影響を与えるため、順序への影響を一度に 1 ビットずつ分析できます。 すべての反転は、2 つのインデックスが異なる最上位ビットによって一意に分類されるため、再帰は重複や省略なしに反転空間を分割します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    s = input().strip()
    n = len(s)
    x = int(s, 2)

    size = 1 << n

    def dfs(bit, base):
        if bit < 0:
            return 0

        half = 1 << bit

        zero_count = 0
        one_count = 0

        for i in range(half):
            zero_count += 1
        for i in range(half, 1 << (bit + 1)):
            one_count += 1

        inv = 0

        inv += dfs(bit - 1, base)

        if (x >> bit) & 1:
            inv += zero_count * one_count

        return inv % MOD

    print(dfs(n - 1, 0) % MOD)

if __name__ == "__main__":
    solve()
```この実装では、ビット単位の再帰的分解が使用されます。 機能`dfs(bit, base)`概念的には、残りの下位ビットによって決定されるすべての数値を処理します。 変数`half`現在の範囲を現在のビット位置で分割します。 

重要な操作は、XOR マスクの現在のビットがアクティブかどうかを検出することです。 そうである場合、そのビットのパーティション全体が反転し、2 つの半分にわたって形成されたすべてのペアが反転カウントに寄与します。 ここでクロスタームが蓄積されます。 

再帰により、より小さいビット位置が独立して寄与することが保証され、より高いビットは順列の構造的分割を定義します。 

の`base`XOR 効果はグローバル マスクのビット シフトによって完全にキャプチャされるため、この簡略化された表現ではパラメーターは使用されません。

 ## 特殊なケース

 エッジ ケースの 1 つは、完全にゼロで構成されるマスクです。 この場合、すべての要素がそれ自体にマップされるため、反転ペアは存在しません。 マスクにビットが設定されていないため、再帰によってクロスビット寄与がトリガーされることはなく、結果はすべてのレベルを通じてゼロのままです。 

もう 1 つの特殊なケースは、すべて 1 であるマスクです。 ここでは、すべてのビットが反転するため、個別のインデックス間のすべての比較は、最上位の異なるビットで反転されます。 このアルゴリズムはあらゆるレベルで寄与を蓄積し、最大限に反転した順列構造を生成します。
