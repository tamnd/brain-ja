 ## 解決策
 ## 問題の理解

 1 から n までの数字を一列に並べた順列が与えられます。 各位置は独自の強度値を持つ「サイコ」を表し、ラインは個別のラウンドで進化します。 

1 ラウンドで、すべてのサイコは自分とすぐ右隣の人物を比較します。 彼の値が大きい場合、彼は右側の隣人を殺します。 すべての比較は同時に行われるため、たとえ同じラウンドで殺されたとしても、サイコは誰かを殺すことができます。 すべての殺害の後、残ったサイコは列を締め切り、次のラウンドに向けて新しい列を形成します。 このプロセスは、これ以上殺害できなくなるまで繰り返されます。 

タスクは、システムが安定するまでに何回ラウンドが発生するかを決定することです。つまり、すぐ右隣のポジションよりも大きな値を持つポジションはないということです。 

入力サイズは最大 100,000 要素に達するため、要素のスキャンと削除を繰り返すシミュレーションは直ちに除外されます。 各ラウンドでリストを再構築する単純なアプローチでは、最悪の場合 O(n²) まで劣化します。これは、Python で 1 秒に収まる値をはるかに超えています。 

同時削除が連鎖反応とどのように相互作用するかについては、微妙な問題が生じます。 値は、後で削除される予定であっても、同じステップで右隣の値が強制終了される可能性があるため、ラウンド中存続する可能性があります。 たとえば、次のような減少する配列では、`[5, 4, 3, 2, 1]`, 最大値以外は徐々にではなく1ラウンドで全て消えます。 左から右に順番に削除する誤った貪欲なシミュレーションでは、崩壊の速度が過小評価されてしまいます。 

もう 1 つのエッジ ケースは、アレイの奥深くに局所的な増加が存在する場合です。 例えば`[1, 3, 2, 4, 3]`異なるセグメントが異なる速度で縮小する複数のラウンドを生成します。 答えは、値がその左側のより大きな値によって保護されるまでの最長の「遅延」によって決まります。 

## アプローチ

 ブルートフォース解釈は簡単です。各ラウンドをシミュレートし、配列をスキャンし、すべての位置にマークを付けます。`a[i] > a[i+1]`、正しい要素を削除し、配列を圧縮し、削除がなくなるまで繰り返します。 各ラウンドは O(n) で、最悪の場合、ラウンドごとに要素を 1 つだけ削除して O(n) ラウンドを生成する可能性があるため、合計の複雑さは O(n²) になります。 n が 100,000 までの場合、これは不可能です。 

重要な観察は、各要素はそれが強制終了されるまでのみ関連しており、その生存はその左側に最も近いより大きな要素にのみ依存するということです。 より大きな要素が左側に表示されると、現在の要素は「破滅」し、最終的には削除されますが、そのタイミングは、その支配的な要素がどれだけ離れているかによって異なります。 

ラウンドをシミュレートする代わりに、各ポジションがいつ削除されるかを追跡します。 左から右に処理し、値が減少するインデックスの単調構造を維持します。 各要素について、その左側のより大きな値によって削除されるまでに生き残るステップの数を見つけます。 これは、追加のタイミング伝播を伴う単調スタックと同様の影響の連鎖を追跡することと同等です。 

この問題の古典的な結果は、各要素の「死亡時間」が、その左チェーンに最も近い大きい要素の最大死亡時間より 1 つ大きい値になるということです。 答えは、すべての要素にわたる最大の死亡時間です。

 ## アルゴリズムのチュートリアル

 値が厳密に降順になっているインデックスのスタックを維持しながら、配列を左から右に処理します。 

1. 配列を初期化する`death[i] = 0`すべてのポジションに。 これは、各サイコが排除されたラウンドを保存します。 
2. 各位置を反復処理します。`i`左から右へ。 
3. スタックが空ではない間に、`a[stack[-1]] < a[i]`、スタックからポップします。 これらの要素は小さいため、将来の要素に対して最も近い主要なブロッカーになることはできません。 彼らは事実上支配されています`a[i]`。 
4. ポップ後にスタックが空でない場合、スタックの先頭は左に最も近い大きい要素になります。 現在の要素は、その要素のために最終的に削除されます。 以下を設定します:`death[i] = death[stack[-1]] + 1`。 

これは、次のような考えを捉えています。`i`最も強力な先行チェーンよりも 1 ラウンド長く生き残ります。 
5. スタックが空の場合、`death[i]`左側に何も支配されていないため、 0 のままです。 
6.プッシュ`i`スタックに。 
7. 答えは次の最大値です。`death`。 

### なぜ効果があるのか

 スタックは、「アクティブな支配ソース」、つまり値が左から右に厳密に減少するインデックスの候補を維持します。 あらゆるインデックスに対して`i`、その左にある最初の大きい要素が、最終的に削除を引き起こすことができる唯一の要素です。 それらの間にある小さな要素はすべて、より早く削除されるか、より早く支配され、より大きな値の影響をブロックできないため、無関係です。 

再発`death[i] = death[j] + 1`最も近いより大きいもの`j`階層化された折りたたみ構造をエンコードします。 各要素は、その支配的な先行要素が除去プロセスでアクティブになった瞬間を超えて、さらに 1 ラウンド生き残ります。 これにより、ラウンドを明示的にシミュレートすることなく、ドミナンス チェーンに沿った消去タイミングの伝播が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    stack = []
    death = [0] * n

    for i in range(n):
        while stack and a[stack[-1]] < a[i]:
            stack.pop()

        if stack:
            death[i] = death[stack[-1]] + 1
        else:
            death[i] = 0

        stack.append(i)

    print(max(death))

if __name__ == "__main__":
    solve()
```この実装は、インデックスの単調スタックに依存しています。 スタックは常に値を降順で格納するため、より大きな値に遭遇したときに、将来の要素に影響を与えることができない小さな候補をすべて正しく破棄できるようになります。 

の`death`配列は増分的に計算され、各エントリは最も近い有効な先行エントリにのみ依存します。 これにより、ラウンドのスキャンやシミュレーションを繰り返す必要がなくなります。 

よくある間違いは、厳密な単調性を維持せずに死亡を計算しようとすることです。これにより、スタックのトップが最も近い関連するより大きな要素を表すという保証が破られます。 もう 1 つの微妙な問題は、答えが全体の最大値であることを忘れていることです。`death[i]`最後の要素だけではありません。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    stack = []
    death = [0] * n

    for i in range(n):
        while stack and a[stack[-1]] < a[i]:

            death[i] = death[stack[-1]] + 1

# strictly increasing (no kills)
assert run("5\n1 2 3 4 5\n") == "0"

# strictly decreasing (one wave collapse)
assert run("5\n5 4 3 2 1\n") == "1"

# alternating pattern
assert run("6\n1 3 2 5 4 6\n") == "2"

# single element
assert run("1\n1\n") == "0"

 ## 特殊なケース

 次のような厳密に増加するシーケンス`1 2 3 4`右側にこれより大きな値を持つ要素はないため、kill は決してトリガーされません。 スタックは増加し続け、すべての要素が取得されます`death[i] = 0`、最終的な答えは 0 です。 

次のような厳密に減少するシーケンス`5 4 3 2 1`左から右へ即座に支配を生み出します。 各要素は最初の値を最も近い大きい先行値として認識するため、すべての死亡はインデックス 0 に依存し、1 ステップに評価され、最大値は 1 になります。 

In alternating structures like`1 3 2 5 4`、各ピークは新しい支配層を作成します。 スタックは繰り返しリセットされ、`death`ローカル反転後に新しいより強力な要素が出現するたびに、値は 1 ずつ増加します。 これは、アルゴリズムが明示的なシミュレーションを行わずにマルチラウンドのカスケード消去をどのようにキャプチャするかを示しています。
