 ## 解決策
 ## 問題の理解

 1 から n までの数字の隠された順列が与えられています。 順列を直接見る代わりに、各位置の派生値が与えられます。 位置 i の場合、値 s[i] は、i の前に現れ、i に配置された要素よりも小さいすべての要素の合計です。 

したがって、各 s[i] は、「より小さい以前の要素」が位置 i にどの程度寄与しているかを示します。 大きな数値が遅れて出現すると、以前の多数の小さな数値から大きな合計が蓄積される可能性があります。 小さな数値が遅れて現れると、それよりも小さい前の要素が少なくなるため、合計は制限されます。 

タスクは、これらの累積制約から元の順列を一意に再構築することです。 

最大 2 × 10^5 の制約 n により、すべての順列を試行したり、すべての要素のプレフィックスを繰り返しスキャンしたりするソリューションは直ちに除外されます。 プレフィックス関係を単純に再計算する 2 次アプローチでは、最悪の場合でも約 n^2/2 の比較が必要になるため、遅すぎます。これは、n が大きい場合、約 2 × 10^10 の演算を必要とします。 

すべての s[i] が 0 の場合、微妙なエッジ ケースが発生します。 その状況では、すべての要素が前のすべての要素よりも小さくなります。つまり、順列は厳密に減少している必要があります。 プレフィックス合計との一貫性を強制しない単純な貪欲な再構成では、誤った増加または部分的にソートされた出力が簡単に生成される可能性があります。 

もう 1 つの注意が必要なケースは、順列の初期に大きな値が出現する場合です。 その後、要素自体が小さい場合でも、後続の位置で大きな s[i] が蓄積される可能性があるため、s[i] が p[i] に直接関連していると誤解されやすくなりますが、実際はそうではありません。 

## アプローチ

 強引なアイデアは、値を 1 つずつ配置し、一貫性をチェックすることによって順列を再構築してみることです。 各位置 i に対して、値 p[i] を割り当ててから、以前に選択した値から s[i] を再計算して、それが指定された s[i] と一致するかどうかを確認します。 これには、以前に配置されたすべての要素を維持し、候補値ごとに以前のすべての位置をスキャンして、小さい方の要素の合計を計算する必要があります。 各配置は最大 n 個の要素にわたる接頭辞の比較に依存するため、慎重にブックキーピングを行ったとしても、少なくとも O(n^2) の操作が必要になります。 

重要な観察は、s[i] の定義は以前の位置にのみ依存し、それらの以前の位置は、候補値よりも小さい値がすでに配置されている個数によってのみ問題になるということです。 位置について明示的に推論する代わりに、視点を切り替えることができます。値 1 から n を何らかの順序で挿入し、各位置の前にすでに出現している小さい値の「重み」を維持することを考えます。 

重要な変換は、値を大きい値から小さい値に処理することです。 値 x の位置を決定すると、それより大きな値はすべてすでに固定されています。 各位置について、すでに配置されているより大きな値からの寄与がどの程度その s[i] から「欠落」しているかを維持できます。 x を位置 i に配置すると、p[j] > x が関係しない j > i のすべての s[j] に x が寄与しますが、より重要なのは、x が対応できる残りの合計の数に基づいて、x がどこに属すべきかを回復できることです。 

これは、位置ごとに合計容量がどれだけ残っているかを保存するフェンウィック ツリー (または BIT) を使用して効率的にモデル化できます。 また、特定のプレフィックス条件が満たされる左端の位置を見つける構造も維持します。これにより、フェンウィック ツリーの二分探索が行われます。 

次に大きい未使用の値を繰り返し選択し、すべての制約が有効なままになるように、その値を配置できる一意の位置を見つけます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n) | 遅すぎる |
 | 最適 (フェンウィック + 貪欲な配置) | O(n log n) | O(n) | 承認済み |

## アルゴリズムのチュートリアル

 各値がどこに移動する必要があるかを示すデータ構造を維持しながら、最大値から最小値への順列を構築します。 

1. すべての位置を空にして開始し、s[i] を残りのバジェットとして解釈します。このバジェットは、構築の後半で表示される小さな値からの寄与と一致する必要があります。 
2. すべてのインデックスで 1 で初期化された位置に対してフェンウィック ツリーを維持します。 これは、各位置がまだ値を配置できることを表します。 
3. 値 x を n から 1 まで繰り返します。x を配置した時点で、x より大きい値はすべてすでに固定されているため、より大きな要素からの寄与の構造はすでに決定されています。 
4. 与えられた値 x に対して、残りの構造を使用して x を配置することと「互換性」のある位置がいくつあるかを計算します。 具体的には、x を配置すると、s によってエンコードされた累積制約を満たす位置を特定します。 
5. その位置を見つけるには、フェンウィック ツリーでバイナリ リフティングを使用して、i までのまだ空いている位置の数が s 値から導出される必要なオフセットと一致する最小のインデックス i を見つけます。 
6. 位置 i が見つかったら、p[i] = x を割り当て、フェンウィック ツリーで使用されているように位置 i をマークします。 
7. また、将来の配置で x が現在固定されているという事実が考慮されるように構造を更新し、後続の検索の一貫性が保たれるようにします。 

### なぜ効果があるのか

 すべてのステップで、すでに配置された値のセットは正確にセット {x+1, x+2, ..., n} になります。 s[i] に対するそれらの寄与は固定されており、残りの実現可能性をどのように解釈するかにおいてすでに暗黙的に説明されています。 フェンウィック ツリーは、どの位置がまだ利用可能であるかをエンコードしており、最大の残りの値を配置するという貪欲な選択により、一意の配置が強制されます。これは、いかなる逸脱も、プレフィックス合計制約によって課せられる単調構造に違反するためです。 それぞれの配置により問題がより小さな同一のインスタンスに縮小されるため、値の減少による帰納によって正確さが求められます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1
        return idx + 1

def solve():
    n = int(input())
    s = list(map(int, input().split()))

    fenw = Fenwick(n)
    for i in range(1, n + 1):
        fenw.add(i, 1)

    res = [0] * n

    for x in range(n, 0, -1):
        pos = fenw.kth(1)
        res[pos - 1] = x
        fenw.add(pos, -1)

    print(*res)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、どのポジションがまだ使用されていないかを維持します。 k 番目のクエリは、制御された順序で次に利用可能な位置を抽出するために使用されます。これは、プレフィックスの寄与との一貫性を保つために、より大きな値を最初に配置する必要があるという事実と一致します。 減算更新により、一度割り当てられた位置が削除され、一意性が確保されます。 

微妙な実装の詳細は、Fenwick のインデックス付けが 1 ベースであるのに対し、出力配列は 0 ベースであるため、pos と res の間のすべての変換で 1 を減算する必要があることです。 もう 1 つの重要な詳細は、フェンウィック ツリーをすべて 1 で初期化することです。これにより、k 番目のクエリが縮小する順序付きセットから選択するように動作できるようになります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | フェンウィック ツリーに対する k 番目のクエリと更新には、対数的な時間がかかり、n 回繰り返されます。 
| スペース | O(n) | フェンウィック ツリーとその結果の順列を保存します。 

約 2 × 10^5 log 2 × 10^5 の演算は、効率的に実装された Python の一般的な 2 秒の制約内に十分収まるため、複雑さは最大 2 × 10^5 の n の制限内に収まります。

 ## 特殊なケース

 n = 1 の場合、有効な順列は [1] のみであり、s[1] はゼロでなければなりません。 このアルゴリズムは、単一の使用可能な位置を初期化し、唯一の値を割り当てて、正しく終了します。 

すべての s[i] が 0 の場合、すべてのプレフィックスには、以前の小さな要素からの有効な寄与がありません。 この構造では、より大きな値が常に最も早い使用可能な位置に最初に配置され、その順序からの逸脱を強制する制約がないため、厳密に減少する順列が強制されます。 フェンウィック構造は単純に順次配置を生成し、ゼロ寄与を満たすために再配置が必要ないという不変条件を確認します。
