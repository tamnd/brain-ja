 ## 解決策
 ## 問題の理解

 一連の数字が与えられ、そこから 1 つの連続したブロックを削除することも、まったく削除しないこともできます。 この 1 つの削除の後、残りの要素はすべて互いに異なるものになる必要があります。 

タスクは、最終的な配列に重複する値が含まれないように、削除するサブ配列を選択することです。すべての有効な選択肢の中で、可能な限り短い削除セグメントが必要です。 配列に既に重複がない場合は、何も削除する必要がないため、答えはゼロになります。 

ここでの重要な制約は、配列の長さが最大 ​​2000 であることです。これは、注意深く実装すれば 2 次または 3 次の解さえも許容できることをすぐに示唆していますが、それより悪いものはすべて許容されます。$O(n^2)$リスクは境界線に達しますが、それでも許容できる可能性があります。 ただし、問題の構造は、完全に再計算された方法ですべての可能なサブ配列をチェックすることを避けるように努めるべきであることを強く示唆しています。 

素朴な解釈は次のようになります: すべてのペアを試してください$(l, r)$、そのセグメントを削除し、残りの要素がすべて異なるかどうかを確認します。 その小切手だけでも費用がかかります$O(n)$、そして、あります$O(n^2)$部分配列、与える$O(n^3)$これは不要ですが、2000 未満の最適化された Python ではまだ合格する可能性があります。それでも、さらに改善できる可能性があります。 

重複がすでに遠く離れている場合、微妙な特殊なケースが発生します。 たとえば、次のような配列では、$[1, 2, 3, 1]$唯一の有効な削除では、重複する値の少なくとも 1 つの出現を削除する必要があります。 プレフィックスまたはサフィックスのみをチェックする不注意なアプローチでは、削除が厳密に中間にある場合に最適なソリューションを見逃す可能性があります。 

もう 1 つの重要なエッジ ケースは、すべての要素が同一である場合です。 例えば$[5, 5, 5, 5]$、できる限り多くても 1 つの要素を保持することなので、削除する必要があります。$n-1$最適なセグメントは、単一の要素を除く任意の場所に配置できます。 

## アプローチ

 強引なアイデアはセグメントを選択することから始まります$[l, r]$削除します。 削除後、プレフィックスを連結します$[1, l-1]$と接尾辞$[r+1, n]$、次に、この結合された配列にすべて個別の値があるかどうかを確認します。 

これは問題の定義に直接従うため機能します。 ただし、すべての一意性をゼロから再計算すると、$(l, r)$ペアには次までのスキャンが必要です$n$要素、$O(n^3)$最悪の場合の全体的な操作。 と$n = 2000$、これは素直に実装すると遅すぎます。 

重要な観察は、保持されたプレフィックスの左側の境界を修正すると、重複が導入されないようにしながら、サフィックスの右側の境界を貪欲に拡張できるということです。 削除されたセグメントごとに有効性を最初から再計算するのではなく、保持されたプレフィックスと保持されたサフィックスへの配列の分割を選択するものとして解決策を扱います。 削除されたセグメントは、まさにそれらの間にあるものです。 

したがって、左側から保持する要素の数を繰り返し、そこに表示される値を維持してから、接頭辞との重複を生じさせない最大の有効な接尾辞を右側から見つけます。 これにより、問題はプレフィックスとサフィックスの有効性の間の 2 ポインタ スタイルの相互作用に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | 2 ポインタのプレフィックス/サフィックス スキャン | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 保持するプレフィックスとサフィックスを選択し、その間のものをすべて削除したいと考えています。 目標は、保持されるすべての値が確実に異なるようにしながら、保持される要素のサイズを最大化することです。 削除されたセグメントを最小化することは、保持されるプレフィックスとサフィックスを最大化することと同じです。 

1. 左側の境界を修正します$i$、プレフィックスを保持することを意味します$a_1 \dots a_i$。 表示された値を追跡することで、このプレフィックスに重複がないことを確認します。 重複が現れた場合、それ以上の拡張は無効であるため、停止します。 
2. この固定プレフィックスについては、配列の末尾から始まるサフィックスを選択しようとします。 プレフィックスですでに使用されている値のセットを維持し、ポインターを拡張します。$j$から$n$これには、プレフィックス セットに存在せず、サフィックス自体で重複していない要素のみが含まれます。 
3. 移動中$j$左側では、suffix 要素のセットを維持します。 値がプレフィックスと競合するか、サフィックスで繰り返される場合、拡張は停止されます。 
4. 有効なプレフィックスごとに、可能な限り最適なサフィックスを計算し、保持される合計の長さを導き出します。 削除されたセグメントはそれらの間のギャップであるため、削除される最小サイズを更新します。 
5. すべての有効なプレフィックス エンドポイントに対してこれを繰り返します。 

微妙なアイデアは、接頭辞が固定されると、接尾辞が右から貪欲に最大化されるということです。これは、後から接尾辞要素を取得しても自由度が低下するだけであり、将来の有効性には決して役立ちません。 

### なぜ効果があるのか

 このアルゴリズムは、有効な最終配列は、値が互いに素で個別に異なるプレフィックスとサフィックスとして表現できるという事実に基づいています。 最適な解決策を得るには、プレフィックス部分が元の配列の一部のプレフィックス (削除の開始位置を選択した後) に対応する必要があり、同様にサフィックスも元の配列のサフィックスに対応する必要があります。 すべてのプレフィックス エンドポイントを列挙し、サフィックスを貪欲に拡張することで、反復の 1 つですべての最適な分割が確実に考慮されます。 貪欲なサフィックス拡張は、重複によりサフィックス要素が除外されると、サフィックスの前にさらに多くの要素を含めても有効性を復元できないため、安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    ans = n

    # try all prefix ends
    for i in range(n + 1):
        seen = set()
        ok = True

        # build prefix [0..i-1]
        for k in range(i):
            if a[k] in seen:
                ok = False
                break
            seen.add(a[k])

        if not ok:
            break

        # now greedily take suffix from right
        used_suffix = set()
        j = n

        while j > i:
            if a[j - 1] in seen or a[j - 1] in used_suffix:
                break
            used_suffix.add(a[j - 1])
            j -= 1

        kept = i + (n - j)
        ans = min(ans, n - kept)

    print(ans)

if __name__ == "__main__":
    solve()
```コードは最初にすべてのプレフィックス長を試します。 各プレフィックスについて、プレフィックス自体に重複が含まれていないことを明示的にチェックします。 これが必要なのは、プレフィックスが無効になるとそれ以上拡張すると状況が悪化するだけなので、早期に停止できるからです。 

有効なプレフィックスを修正した後、それと競合しない最長のサフィックスを計算します。 サフィックスは最後から逆方向に構築され、これ以上含めても有効性が低下するだけであるため、競合が現れるとすぐに停止します。 

保持されるサイズは、プレフィックス長とサフィックス長の合計です。 実質的に配列をプレフィックス、削除されたセグメント、サフィックスの 3 つの部分に分割しているため、削除されたサイズは減算によって求められます。

 ## 特殊なケース

 のような配列の場合$[5, 5, 5, 5]$、アルゴリズムはプレフィックスの長さを試行します。 で$i = 1$、プレフィックスは有効です。 1 つの要素を追加すると、次の要素がサフィックス セットと競合するため、サフィックス スキャンはすぐに停止します。 これにより、サイズが 2 に保たれます。これは、削除サイズが 2 であることを意味しますが、より優れたプレフィックスでは、最適な削除が 3 になります。アルゴリズムは、すべてのプレフィックスの選択肢を正しく評価し、最小値を見つけます。 

のようなケースの場合$[1, 2, 1, 2]$、のプレフィックス$i = 2$は有効ですが、接尾辞に 1 または 2 を含めることはできないため、接尾辞のサイズはゼロになります。 結果は、サイズ 2 の中間セグメントの削除に相当し、分割ロジックによって正しくキャプチャされます。
