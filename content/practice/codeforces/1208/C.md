 ## 解決策
 ## 問題の理解

 記入するよう求められます$n \times n$以下のすべての整数を含むテーブル$0$に$n^2 - 1$正確に 1 回だけなので、すべての数値がグリッド セルの順列で使用されます。 追加の制約はグローバルです。すべての行はそのエントリの同じビットごとの XOR を持つ必要があり、すべての列も同じ XOR 値を持つ必要があります。 

入力はただ$n$、そして私たちはそれを保証します$n$は 4 の倍数です。出力は、XOR 均一性条件を満たす、グリッド内への数値の有効な配置です。 

制約は、これを検索または制約を満たす問題として扱うことができないことを示唆しています。 グリッドのサイズは最大で$1000 \times 1000$つまり、最大 100 万個の個別の値を配置する必要があります。 構築中に行と列の XOR を繰り返しチェックするアプローチは問題ありませんが、指数関数的なものやバックトラッキングを伴うものは直ちに不可能になります。 

単純な考え方による微妙な失敗例は、行優先の順序やチェッカーボードの XOR バランシングなどの単純なパターンで数値を分配することです。 たとえば、連続するブロックの XOR が行または列全体で安定していないため、行ごとに増加する数値を入力することは失敗します。 もう 1 つの魅力的なアイデアは、最初に行 XOR の等価性を強制してから列を調整することですが、単一のエントリを変更すると両方の制約がグローバルに破られるため、ローカルな修正は無効になります。 

問題の構造は、すべての局所領域がすでに XOR 対称性を満たしており、これらの領域がより高いレベルできれいに結合する決定論的な構築が必要であることを示唆しています。 

## アプローチ

 強引な解釈では、1 つずつ番号を割り当てて制約を維持してみることになります。 各ステップで、空のセルに数値を入力し、行と列の XOR 制約が満たされているかどうかを確認します。 枝刈りを行ったとしても、状態空間は膨大です。$(n^2)!$数値の順列、およびそれぞれの部分的な代入は影響を及ぼします。$O(n)$行と列。 メモ化を行ったとしても、制約グラフは密度が高すぎるため、意味のある DP 圧縮はできません。 

重要な観察は、XOR が構造化されたペアリングの下で​​適切に動作するということです。 各行と列が、XOR の寄与が制御された方法でキャンセルされる慎重にペアになった値から形成されていることを確認できれば、明示的に XOR を追跡することなく均一性を強制できます。 

有用な視点は、グリッドをブロック単位で構築することです。$2 \times 2$。 このようなブロック内で、XOR が対称パターンでバランスがとれるように 4 つの値を割り当てると、各ブロックは行と列の交差部分に予測可能な XOR フットプリントをもたらします。 以来$n$が 4 の倍数である場合、グリッドは次のように分割できます。$2 \times 2$すべての行と列が完全なブロックのみで構成されるようにブロックを作成します。 

この構造は、それぞれの内部に番号を割り当てることになります。$2 \times 2$ブロックを一貫したパターンで処理しながら、異なるブロックが互いに素な値の範囲を受け取るようにします。 標準的なトリックは、各ブロック インデックスをより小さなサイズのグリッド内の座標として扱うことです。$(n/2) \times (n/2)$、次にビット操作を使用してそれを 4 つの値に拡張し、次のすべての数値が得られるようにします。$0$に$n^2-1$は 1 回だけカバーされます。 

これが機能するのは、XOR がビット構造に依存しており、インデックスを上位部分と下位部分に分割することで、ブロック全体とブロック内の分布を独立して制御できるためです。 最終的な設計では、すべての行が各高レベルのパターンを 1 回だけ参照することが保証され、列にも同じことが当てはまり、XOR の均一性が強制されます。

 ## アルゴリズムのチュートリアル

 次を使用してグリッドを構築します$2 \times 2$ブロック。 

1. グリッドを座標に分割します$(i, j)$。 各セルは次のブロックに属します。$(i // 2, j // 2)$。 これにより、すべてのブロックが独立し、4 つのセルをカバーすることが保証されます。 
2. ブロック インデックスを使用して、各ブロックに一意の基本値を割り当てます。$$b = (i // 2) \cdot (n // 2) + (j // 2)$$これはブロックを列挙します$0$に$(n/2)^2 - 1$。 
3. ビット シフトを使用して、各ブロック値を 4 つの異なる数値に展開します。 

- 左上:$4b$- 右上:$4b + 1$- 左下:$4b + 2$- 右下:$4b + 3$4 を掛ける理由は、各ブロックがグローバル順列でサイズ 4 の互いに素なチャンクを予約する必要があるためです。 
4. これらの値をすべての内部に一貫して配置します。$2 \times 2$ブロック。 これにより、重複がないことが保証され、次のすべての番号が保証されます。$0$に$n^2 - 1$は 1 回だけ使用されます。 
5. 構築したグリッドを出力します。 

### なぜ効果があるのか

 各行は次のシーケンスで構成されます。$n/2$各ブロック内で、その 4 つの要素の XOR は次のようになります。$$(4b) \oplus (4b+1) \oplus (4b+2) \oplus (4b+3) = 0$$最後の 2 ビットがすべての組み合わせを循環し、XOR でキャンセルされるためです。 

すべての行は完全にこのようなゼロ XOR ブロックで構成されているため、すべての行の XOR は 0 になります。ブロックは垂直パーティション全体で一貫して位置合わせされるため、同じことがすべての列にも当てはまります。 したがって、すべての行と列は同じ XOR 値を共有します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [[0] * n for _ in range(n)]
    
    for i in range(n):
        for j in range(n):
            b = (i // 2) * (n // 2) + (j // 2)
            base = 4 * b
            if i % 2 == 0 and j % 2 == 0:
                a[i][j] = base
            elif i % 2 == 0 and j % 2 == 1:
                a[i][j] = base + 1
            elif i % 2 == 1 and j % 2 == 0:
                a[i][j] = base + 2
            else:
                a[i][j] = base + 3

    for row in a:
        print(*row)

if __name__ == "__main__":
    solve()
```実装はブロック分解の直後に行われます。 重要な詳細は、整数を 2 で除算してブロック インデックスを計算し、行インデックスと列インデックスのパリティを使用してブロック内の各位置をマッピングすることです。 これにより、条件付きの再形成や後処理が不要になります。 

よくある間違いは、各ブロックが 4 つの数値の連続した範囲にマッピングされなければならないことを忘れることです。 4 を乗算しないと、値がブロック間で衝突し、置換要件が破られてしまいます。

 | ブロック (i//2, j//2) | b | 配置された値 |

 ## 特殊なケース

 のために$n = 4$、ブロック分解のレベルは 1 つだけです。 アルゴリズムはちょうど 4 つのサイズのブロックを割り当てます。$2 \times 2$、重複することなく 0 から 15 までの数字を生成します。 XOR 条件は、各ブロックが独立して XOR 0 を持ち、すべての行と列がゼロの XOR 寄与の合計を継承するため成立します。 

大型の場合$n$、 のような$n = 1000$、同じロジックが 250,000 ブロックにわたって繰り返されます。 各ブロックは互いに素な範囲の値を提供するため、最大スケールでも衝突は発生しません。 すべての行は完全なブロックで構成されているため、XOR はグリッド サイズに関係なく安定しています。
