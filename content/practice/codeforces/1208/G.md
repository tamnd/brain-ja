 ## 解決策
 ## 問題の理解

 すべて同じ円上にある複数の正多角形を構築するように求められており、円の境界点をできる限り再利用したいと考えています。 

各ポリゴンは、頂点の数によってのみ決定されます。 ポリゴンが$l$側面、それからそれを使用します$l$円上の等間隔の点。 各ポリゴンを独立して回転させることができます。つまり、選択した頂点のセットを円の周りに移動させることができます。 ただし、任意のポリゴンでポイントが使用されると、そのポイントは円上の個別のポイントのグローバル セットの一部になります。 

課題は正確に選択することです$k$範囲内の異なるポリゴン サイズ$[3, n]$、すべてのポリゴンにわたって使用される個別のポイントの総数ができるだけ少なくなるように、それらを (最適な回転で) 配置します。 

重要な相互作用は、頂点セットが円の共通の離散化に沿って整列している場合、異なるポリゴンが頂点を共有できることです。 

制約$n \le 10^6$サイズのすべてのサブセットを試したり、ジオメトリを明示的にシミュレートしたりするアプローチは直ちに除外されます。 ポリゴン サイズの候補の組み合わせをすべて保存したり反復したりすることさえ不可能です。 有効な解決策は、問題を約数または倍数に関する数論的構造に還元する必要があります。 

単純な間違いは、最小のものを選択すると仮定することです。$k$ポリゴン サイズは常に答えを最小化します。 オーバーラップは可除性に依存するため、これは誤りです。 たとえば、三角形と六角形は、3 が 6 を分割するため完全に整列し、頂点が完全に再利用されますが、4 と 5 を選択すると重なりがほとんどなくなります。 

比較的素なサイズを混合すると、別の微妙な故障モードが発生します。 たとえば、サイズ 4 と 6 のポリゴンは位置合わせ構造を共有しますが、5 が 4 より大きい場合でも、4 と 5 は共有しません。純粋にサイズだけで貪欲な場合は壊れます。 

## アプローチ

 ブルートフォースアプローチでは、次のすべてのサブセットを選択しようとします。$k$からの整数$[3, n]$、各サブセットについて、必要な円点の数をシミュレートします。 固定セットの場合、必要なポイントの数は、すべてのポリゴンの頂点間隔に対応する最小公倍数の構造であり、辺数の最小公倍数に対応します。 これには、すべての組み合わせに対して LCM を計算し、最小値を選択する必要があります。 

部分集合だけの数は、$\binom{n}{k}$、それはたとえ小さくても実行不可能です$n$。 サブセットを修正したとしても、オーバーラップを計算するには、選択したすべての整数間の割り切れる関係について推論する必要があります。 これは制限時間をはるかに超えています。 

重要な洞察は、必要な円点の数が、選択した多角形サイズの最小公倍数によって完全に決定されるということです。 辺の長さを選ぶと$a_1, a_2, \dots, a_k$、その場合、少なくとも必要です$\mathrm{lcm}(a_1, \dots, a_k)$すべてのポリゴンを同時に埋め込むには、等間隔のポイントを使用します。 各ポリゴンは、すべてのポリゴンを選択することに対応します。$\frac{\mathrm{lcm}}{a_i}$- 点目。 

問題は次のとおりです。$k$異なる整数$[3, n]$LCMを最小化します。 

LCM を最小限に抑えることは、必要な最高のプライム電力カバレッジを最小限に抑えることと同じです。 最適な戦略は、互いに大きく分割する数値を詰め込むことです。 任意の集合の観点から考える代わりに、視点を変えます。最大要素を固定すれば$x$の場合、他のすべての選択された数値は次の約数になるはずです。$x$LCMがこれ以上増加しないようにするため$x$。 したがって、固定の場合、$x$、可能な限り最良のセットは、$x$の約数を加えたもの$x$可能な限り少なくとも 3 つです。 

したがって、それぞれについて$x$、有効な約数がいくつあるかを数えます$\ge 3$それはあります。 その数が少なくとも$k$、完全に除数格子内で集合を形成できます。$x$、答えを達成する$x$。 私たちはそのような最小のものを望んでいます$x$。 

これにより、問題は次の数までのすべての数値にわたる約数を数えるふるいに変わります。$n$、各数値がより高い倍数に寄与する適格な約数の数を累積します。

 ## アルゴリズムのチュートリアル

 1. 各整数について$x$3から$n$、それを潜在的な最大ポリゴン サイズとして解釈します。 構築してみます$k$サイズがすべて分割されたポリゴン$x$、LCM が最大であることを保証します。$x$。 
2. 配列を作成する`cnt[x]`有効な数値の数を追跡します$d \ge 3$分ける$x$。 これは、考えられるすべての約数を反復して計算されます$d$の倍数に貢献を追加します$d$。 これは、すべての約数構造が倍数間で共有されるため機能します。 
3.充填後`cnt`、からスキャン$x = 3$を上向きにして確認します。`cnt[x] >= k`。 そのような最初の$x$収容できる最小の円のサイズです$k$ポリゴン。 
4.これを返却してください$x$答えとして。 

微妙な部分は、除数の累積がサブセットごとではなくグローバルに機能する理由です。 明示的にポリゴンを構築しているわけではありません。 代わりに、完全な除数で閉じたサイズのセットが少なくとも以下であるかどうかを検証しています。$k$中に存在する$[3, x]$。 そうであれば、選択した各約数をポリゴン サイズとして割り当て、その中にすべてを埋め込むことができます。$x$ポイント。 

### なぜ効果があるのか

 このアルゴリズムは、選択されたすべてのポリゴン サイズが共通の数値を割るという不変条件に依存します。$x$、すべてのポリゴンを正確に埋め込むことができます$x$競合することなく円上に等間隔に配置された点。 オーバーラップ構造はモジュール調整によって自動的に満たされます。 逆に、最大使用ポイント数を持つ有効な構築$x$LCM が超えることができない一連のポリゴン サイズを誘導します$x$、これらはすべて、$x$。 これにより、除数の容量をチェックするだけで十分な正確性が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())

    cnt = [0] * (n + 1)

    for d in range(3, n + 1):
        for m in range(d, n + 1, d):
            cnt[m] += 1

    for x in range(3, n + 1):
        if cnt[x] >= k:
            print(x)
            return

if __name__ == "__main__":
    main()
```このソリューションでは、標準のふるいのようなループを使用して除数の度数テーブルを作成します。 外側のループは除数の候補を選択します$d$、内側のループはその寄与をすべての倍数に伝播します。$m$、可能な各円サイズを分割するポリゴン サイズを数えます。 

最終スキャンでは最小値が特定されます。$x$それは少なくともサポートします$k$互換性のあるポリゴン サイズ。 

実装の主な落とし穴は、ポリゴン サイズが少なくとも 3 でなければならないことを忘れていることです。そのため、累積は 1 や 2 ではなく 3 から始まります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, k = map(int, input().split())
    cnt = [0] * (n + 1)

    for d in range(3, n + 1):
        for m in range(d, n + 1, d):
            cnt[m] += 1

    for x in range(3, n + 1):
        if cnt[x] >= k:
            return str(x)
    return "-1"

# provided sample
assert run("6 2") == "6"

# custom cases
assert run("3 1") == "3"
assert run("10 1") == "3"
assert run("10 2") in {"6", "8", "9"}
assert run("12 3") == "12"

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$k = 1$。 アルゴリズムは最小値を即座に見つけます。$x \ge 3$少なくとも 1 つの約数があります。$x = 3$。 これは、単一の三角形が常に機能するという事実と一致します。 

もう 1 つのエッジケースは次のような場合です$n$プライムであり、$k$大きいです。 例えば、$n = 11$、$k = 2$。 唯一の約数関係は自明であるため、より大きな複合構造が存在する場合は、それへの移行を余儀なくされます。 それ以外の場合は可能な最小の$x$は、単に十分な除数密度を蓄積した最初の値です。 

アルゴリズムはこれを自然に処理します。`cnt[x]`約数が存在する場合にのみ増加し、素数の寄与が最小限に抑えられるため、誤った早期トリガーが防止されます。
