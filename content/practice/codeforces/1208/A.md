 ## 解決策
 ## 問題の理解

 フィボナッチ数に似たシーケンスを計算するように求められますが、前の 2 つの項を合計する代わりに、前の 2 つの項にビットごとの XOR 演算を適用することで各項が取得されます。 正式には、シーケンスは 2 つの最初の整数によって定義されます。`a`そして`b`として`f(0) = a`、`f(1) = b`、そしてのために`n > 1`、`f(n) = f(n-1) XOR f(n-2)`。 複数のテスト ケースが与えられ、それぞれが指定`a`、`b`、 そして`n`、計算することになります`f(n)`それぞれのケースごとに。 

制約は次のことを示しています`a`、`b`、 そして`n`それぞれ最大 10 億、テスト ケースは最大 1,000 個まで可能です。 シーケンスを繰り返し計算する素朴なアプローチ`n`が遅すぎるときは`n`テスト ケースごとに 10 億回繰り返すことは不可能であるため、この値は大きくなります。 

明らかではないエッジケースは次のような場合です。`n`具体的には非常に小さいです`n = 0`または`n = 1`。 不注意なアプローチは、次から反復を開始する可能性があります。`0`少なくとも 2 回の反復を想定し、範囲外または未定義の結果を生成します。 もう一つの微妙なケースは非常に大きい`n`ブルートフォースアプローチが妥当な時間内に終了しない場合。 

## アプローチ

 ブルートフォース手法では、単純に最初の 2 つの要素で配列を初期化します。`a`そして`b`、その後、前の 2 つの要素を XOR 演算することで次の各要素を繰り返し計算します。 このアプローチはシーケンス定義に忠実に従っているため、正しい答えが得られることが保証されています。 ただし、最悪の場合、`n`10^9 に近づくと、10^9 回の反復が必要になりますが、1 秒の制限時間を考えると遅すぎます。 

高速な解決策を明らかにする重要な観察は、XORinacci 数が長さ 3 のサイクルで周期的であるということです。具体的には、このシーケンスはパターン内の 3 項ごとに繰り返されます。`[a, b, a XOR b, a, b, a XOR b, ...]`。 これは、XOR 演算には次のような特性があるために発生します。`(x XOR y) XOR x = y`、予測可能な繰り返しにつながります。 このパターンが認識されると、次のように計算できます。`f(n)`一定時間内に`n modulo 3`そしてパターンにインデックスを付けます。 

アプローチの比較は次のとおりです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | n が大きいと遅すぎます |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、整数を読み取ります。`a`、`b`、 そして`n`。 
2. コンピューティング`n_mod = n % 3`。 これにより、次の位置が特定されます。`f(n)`繰り返される 3 学期のパターン内で。 
3. もし`n_mod`0、`f(n)`は`a`。 もし`n_mod`は 1、`f(n)`は`b`。 さもないと、`f(n)`は`a XOR b`。 
4. 各テスト ケースの計算値を出力します。 

XORinacci シーケンスがサイクルに従うため、これは機能します。`[a, b, a XOR b]`無期限に。 たとえば、次のように始めます。`[a, b]`、次の学期は`a XOR b`、 それから`(a XOR b) XOR b = a`、 それから`a XOR (a XOR b) = b`、これは繰り返しを確認します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

T = int(input())
for _ in range(T):
    a, b, n = map(int, input().split())
    n_mod = n % 3
    if n_mod == 0:
        print(a)
    elif n_mod == 1:
        print(b)
    else:
        print(a ^ b)
```このソリューションでは、まずテスト ケースの数を読み取ります。 各テスト ケースについて、次のようになります。`a`、`b`、 そして`n`。 モジュロ 3 を使用して、`[a, b, a XOR b]`サイクルに対応する`f(n)`。 の`^`Python の演算子はビットごとの XOR を計算します。 モジュロにより、テスト ケースごとに定数時間の計算のみを実行することが保証され、アルゴリズムは次の処理を実行します。`n = 0`そして`n = 1`余分なチェックなしで自然に。 

## 実用的な例

 **サンプル 1**:`a=3, b=4, n=2`| ステップ | 計算 | 結果 |
 | --- | --- | --- |
 | n%3 | 2%3 | 2 |
 | パターン[2] | a XOR b = 3 ^ 4 | 7 |

 表はそれを裏付けています`f(2)`は`7`予想通り。 

**サンプル 2**:`a=4, b=5, n=0`| ステップ | 計算 | 結果 |
 | --- | --- | --- |
 | n%3 | 0%3 | 0 |
 | パターン[0] | a = 4 | 4 |

 これは次のことを示しています`f(0)`初期値を正しく返します`a`。 

**サンプル 3**:`a=325, b=265, n=1231232`| ステップ | 計算 | 結果 |
 | --- | --- | --- |
 | n%3 | 1231232%3 | 2 |
 | パターン[2] | a XOR b = 325 ^ 265 | 76 |

 これは、ソリューションが非常に大きなデータを処理することを示しています。`n`反復なしで。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(T) | 各テスト ケースには、単一のモジュロ演算と XOR 演算 (一定時間) が必要です。 |
 | スペース | お(1) | 必要な変数は少数のみで、n に比例する配列は必要ありません。 |

 与えられた`T <= 1000`、合計作業量は約 1000 回の定数操作であり、1 秒以内に簡単に収まり、メモリ制限の 256 MB を大幅に下回ります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    T = int(input())
    for _ in range(T):
        a, b, n = map(int, input().split())
        n_mod = n % 3
        if n_mod == 0:
            print(a)
        elif n_mod == 1:
            print(b)
        else:
            print(a ^ b)
    return output.getvalue().strip()

# provided samples
assert run("3\n3 4 2\n4 5 0\n325 265 1231232\n") == "7\n4\n76", "sample 1"

# custom cases
assert run("1\n0 0 0\n") == "0", "minimum values"
assert run("1\n0 0 1\n") == "0", "small n=1"
assert run("1\n1 1 2\n") == "0", "XOR zero result"
assert run("1\n1000000000 1000000000 1000000000\n") == "0", "large values"
assert run("3\n5 7 3\n5 7 4\n5 7 5\n") == "5\n7\n2", "sequence cycle"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`10^9 10^9 10^9`|`0`| 大きな数、大きな`n`|

 ## 特殊なケース

 のために`n = 0`、モジュロ演算`0 % 3 = 0`正しく選択します`a`。 たとえば、入力の場合`0 0 0`、アルゴリズムは次のように計算します。`n_mod = 0`そしてプリント`0`。 のために`n = 1`、`1 % 3 = 1`選択します`b`。 大きい`n`のように`1231232`に減少します`1231232 % 3 = 2`、戻る`a XOR b`。 モジュロ サイクルはループや再帰の必要性を回避し、極端な入力を効率的かつ正確に処理します。
