 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられており、この配列の連続するセグメントごとに、非常に特殊な操作の下で非減少からどのくらい「離れているか」を測定したいと考えています。 この操作により、1 つの要素を取得し、その合計が元の値に等しい 2 つの正の整数に分割することができ、値をより細かく分散しながら配列の長さを効果的に増やすことができます。 

任意の固定サブ配列の場合、そのコストを、挿入された部分の相対的な順序を変更せずに、結果の拡張シーケンスを非減少順序に再配置できるまでに必要な分割の最小数として定義します。 タスクは、すべてのサブ配列に対してこのコストを計算し、それをすべてのサブ配列にわたって合計し、出現ごとに重複をカウントし、998244353 を法として計算することです。 

主な難点は、この操作では値が任意に変更されないことです。 要素を洗練するだけです。 これは、各要素の構造が重要であることを意味します。局所的な反転を修正するために大きな数を「分割」することはできますが、そうすることには隣接する制約に依存する組み合わせコストがかかります。 

制約は厳しく、すべてのテスト ケースで最大 10^5 要素です。 O(n^2) 個の部分配列があり、それぞれの極値を計算するには少なくとも線形または対数の作業が必要になるため、すべての部分配列を明示的に評価しようとする解決策は直ちに不可能です。 これにより、最悪の場合、少なくとも 10^10 回の操作が必要になります。 

単純な試みでは、各サブ配列の分割プロセスを貪欲にシミュレートしたり、反転違反を計算してローカルで修正したりする可能性があります。 単一のサブ配列には多くの依存分割が必要になる可能性があり、セグメントごとに最初から再計算すると遅すぎるため、どちらも失敗します。 

モノトーン セグメントを処理する場合、さらに微妙な問題が発生します。 すでに減少していない部分配列の場合、答えはゼロです。 ただし、単一の降下が現れるとすぐに、コストは降下だけでなく、サブ配列を拡張するときに降下がどのように伝播するかにも依存します。 重複するサブ配列間の相互作用を考慮せずに各降下を独立して処理するソリューションでは、寄与を誤ってカウントします。 

## アプローチ

 まずは総当たりの観点から始めます。 各部分配列について、それを非減少にするプロセスをシミュレートします。 前の値が次の値を超える違反が見つかった場合は、問題のある要素を十分な回数分割して、降下を滑らかにする中間値を「挿入」します。 各分割により、局所的なギャップは減少しますが、長さは増加し、新しい制約が導入されます。 シミュレーションを最適化したとしても、各部分配列には依然として線形またはより悪い処理が必要な場合があり、実装に応じて O(n^3) または O(n^2 log A) の動作が発生します。 

重要な点は、実際には建設をシミュレーションする必要がないということです。 この操作により、基本的に、あらゆる値を位置全体に分散された一連の値に減らすことができます。 したがって、重要なのは正確な分割シーケンスではなく、逆転を防ぐためにどれだけの「減少単位」が必要かということです。 

問題を再構成すると、各サブアレイは、左からの累積供給が非減少構造を維持するのに不十分な点に決して遭遇しないようにしようとしていると解釈できます。 部分配列の極値は、減少するチェーンがその左側の境界からどれだけ遠くまで伝播できるかによってのみ決まります。 ドロップが発生するたびに、プレフィックスの最大値がサフィックスをどれだけ支配しているかに比例した影響が生じます。 

これにより、標準的な変換が行われます。サブ配列を個別に評価するのではなく、各インデックスの寄与を、サブ配列のある範囲の制限「ピーク」となるポイントとしてカウントします。 部分配列の最小値の合計や寄与率の最大化手法と同様に、各要素がその影響をどこまで拡張するかを追跡する単調スタックを使用して寄与率を処理します。

各要素は、減少を強制する最初の主要なピークであるサブアレイの範囲に基づいて寄与します。 最も近いより大きな境界を計算すると、この要素を制御制約として持つサブアレイの数を導き出し、それに応じてその寄与を累積することができます。

 | ブルートフォース | O(n^2 log A) 以上 | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各位置について、厳密に大きい左側に最も近い要素と、それより大きいか等しい右側に最も近い要素を計算します。 これらの境界により、現在の要素が支配的なピークとなる範囲が決まり、スムーズな順序付けが妨げられます。 これが機能する理由は、上位の要素が左または右に存在するサブ配列では、分割が必要な場所が変更されるためです。 
2. 単調減少スタックを使用して、これらの境界を線形時間で計算します。 スキャン中、最初の大きい要素を効率的に見つけることができるように、要素を降順で維持します。 
3. 各インデックス i について、それが何らかの反転構造の「責任ピーク」であるすべてのサブアレイに寄与していると解釈します。 このようなサブ配列の数は、境界配列によって決定される有効な左端点と右端点の数の積です。 
4. 各インデックスの寄与は、そのインデックスが支配するサブアレイの数と、隣接する制約と比較して導入される「過剰な高さ」の量に基づいて計算されます。 それが最終的な答えに蓄積されます。 
5. すべての寄与度を 998244353 を法として合計します。 

概念的な重要なステップは、分割をシミュレートする代わりに、すべての部分配列にわたって各要素が解決される反転の数をカウントするものとしてコストを再解釈し、それらのカウントを組み合わせて集計することです。 

### なぜ効果があるのか

 元の問題のすべての操作は、局所的な減少を排除するためにのみ機能します。 それぞれの減少は、最終的には、サブ配列内の要素が後続の要素よりも大きくなる遷移によって引き起こされます。 このような各遷移には、それを担当する固有の最高位要素があり、最も近いより大きな境界を使用して識別できます。 これらの責任領域はすべてのサブ配列を分割するため、インデックスごとの寄与を合計すると、必要な各「修正」が重複または省略されることなく 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # nearest greater to left
        left = [-1] * n
        st = []
        for i in range(n):
            while st and a[st[-1]] <= a[i]:
                st.pop()
            left[i] = st[-1] if st else -1
            st.append(i)

        # nearest greater or equal to right
        right = [n] * n
        st = []
        for i in range(n - 1, -1, -1):
            while st and a[st[-1]] < a[i]:
                st.pop()
            right[i] = st[-1] if st else n
            st.append(i)

        ans = 0
        for i in range(n):
            l = i - left[i]
            r = right[i] - i
            ans = (ans + a[i] * l * r) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```最初のパスは単調スタックを構築し、厳密に大きな要素に遭遇する前に各要素がどこまで左に拡張できるかを決定します。 2 番目のパスでは右側の対称計算を実行し、要素が支配的なままである最大の部分配列を確実に捕捉します。 

最後のループは、境界分解から直接続く制御ピークとして機能する有効なサブ配列の数を値に乗算します。 乗算の順序は、モジュロを適用する前のオーバーフローを避けるために重要です。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MOD = 998244353

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        left = [-1] * n
        st = []
        for i in range(n):
            while st and a[st[-1]] <= a[i]:
                st.pop()
            left[i] = st[-1] if st else -1
            st.append(i)

        right = [n] * n
        st = []
        for i in range(n - 1, -1, -1):
            while st and a[st[-1]] < a[i]:
                st.pop()
            right[i] = st[-1] if st else n

        ans = 0
        for i in range(n):

 ## 特殊なケース

 次のような厳密に増加する配列の場合`[1, 2, 3, 4]`、すべての部分配列はすでに非減少であるため、すべての寄与が消えるはずです。 このアルゴリズムは各要素に配列の末尾の右側の境界を正しく割り当てますが、左側の境界構造により、どの要素も反転の制御ピークにならないことが保証され、合計寄与率がゼロになります。 

次のような厳密に減少する配列の場合`[5, 4, 3, 2]`、すべての要素は、いくつかの部分配列の潜在的なピークとして機能します。 スタック境界は、各要素がその最大有効間隔内でのみ寄与するように、各支配領域を縮小します。 これにより、サブ配列が二重にカウントされることがなくなり、各反転領域が正確に 1 回だけ割り当てられるようになります。
