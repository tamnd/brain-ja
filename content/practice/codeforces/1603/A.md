 ## 解決策
 ## 問題の理解

 一連の整数が与えられており、目的は非常に特殊な操作を使用してそれを完全に消去することです。 各ステップで、値が 1 から始まるインデックス + 1 で割り切れない** 要素を選択し、それを削除できます。 削除後、シーケンスは縮小し、残りの要素のインデックスは 1 つ左にシフトします。 課題は、最終的にシーケンスを空にする削除の順序が存在するかどうかを判断することです。 

入力は複数のテスト ケースを提供し、それぞれにシーケンスの長さとシーケンス自体が含まれます。 完全な削除が可能であれば出力は「YES」、それ以外の場合は「NO」となります。 

制約が大きい: シーケンスがサイズに達する可能性がある$10^5$、すべてのテスト ケースにわたるすべてのシーケンスの合計は、次の値に達します。$3 \cdot 10^5$。 要素を 1 つずつ削除し、各ステップで分割可能性をチェックする単純なシミュレーションでは、おおよその最悪の場合の複雑さが発生します。$O(n^2)$が遅すぎます。 これは、シーケンスの長さが線形またはほぼ線形であるソリューションが必要であることを意味します。 

エッジケースは、要素が小さくインデックスが大きくなる場合に発生します。 たとえば、単一の要素 2 がインデックス 1 にある場合は削除できません。$2 \% 2 = 0$。 もう 1 つの微妙なケースは、繰り返し番号を含むシーケンスです。要素の削除可能性は、元の位置ではなく、**現在の位置**に依存します。 

## アプローチ

 ブルートフォース手法では、すべての削除シーケンスが試行されます。 各ステップで配列をスキャンし、任意の要素を選択します$a_i$そのような$a_i \% (i+1) \neq 0$を削除してください。 シーケンスが空になるか、削除できる要素がなくなるまで続けます。 これは原理的には正しいですが、$n = 10^5$、最大スキャン$n$の要素$n$ステップが与える$O(n^2)$が遅すぎます。 

重要な洞察は、**逆方向に作業する**ことです。 要素が 1 つだけ残っているときに、最終ステップから位置に番号を付ける場合、その要素は縮小シーケンス内の位置の割り切り条件を満たさなければなりません。 逆に削除をシミュレートできます。最後の要素 (位置) から開始します。$n$元の配列にある)、$a_i$は、縮小されたシーケンス内の**1から始まる最後の位置**で割り切れます。 存在する場合、削除は不可能です。 そうでない場合は、削除できます。 末尾から先頭まで繰り返すことにより、必要な配列のパスは 1 回だけです。 

このアプローチは、各段階で削除するのが「最も難しい」要素は現在の配列の末尾にあるという観察を利用しています。 縮小位置から数えてその要素が削除可能であれば、以前のすべての要素も処理できます。 これにより複雑さが軽減され、$O(n)$テストケースごとに。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n$そしてそのシーケンス$a$。 
3. カウンタの初期化$current\_length = n$。 割り切れ性を確認するための「端からの位置」を表します。 
4. 配列を最後の要素から最初の要素まで逆方向に繰り返します。 要素ごとに$a[i]$:

 ａ． もし$a[i] \% current\_length == 0$、「NO」を出力し、このテスト ケースのチェックを停止します。 

b. それ以外の場合はデクリメント$current\_length$1つずつ続けてください。 
5. 分割可能な要素に遭遇せずにループが終了した場合は、「YES」を出力します。 

**機能する理由**: 各ステップで、縮小シーケンスの最後の要素は、**現在の 1 から始まるインデックス**に従って削除可能である必要があります。 要素を逆にチェックすることで、最後に残った候補となる時点で各要素が割り算要件を満たすことを保証します。 いずれかの要素に障害が発生した場合、その要素を消去できる一連の削除は存在しないため、答えは「いいえ」です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    possible = True
    current_length = n
    for value in reversed(a):
        if value % current_length == 0:
            possible = False
            break
        current_length -= 1
    print("YES" if possible else "NO")
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 要素の分割可能性は、削除が検討されるときの最終的な位置に依存するため、シーケンスを逆に繰り返します。 の`current_length`変数はこの仮想位置を追跡します。 要素がその位置で割り切れる場合、操作は成功しないため、テスト ケースを不可能としてマークします。 それ以外の場合は、カウンターをデクリメントして続行します。 最後の print ステートメントは、期待された形式で回答を出力します。

 ## 特殊なケース

 1 から始まるインデックスに 1 を加えたものに等しい要素が 1 つだけあるシーケンスは削除できません。 例えば、`[2]`失敗する理由$2 \% 1 = 0$。 アルゴリズムは、逆ループの最初の反復でこれを正しく識別し、「NO」を出力します。 

すべての要素が 1 に等しいシーケンスの場合、逆チェックでは次のことが確認されます。`1 % n`、`1 % (n-1)`、など、以下を除いてどれもゼロではありません。`1 % 1`、これは許可されています。 解決策は「YES」を出力します。 

大きな数値を含むシーケンスの場合、割り算チェックがモジュロで実行されます。`current_length`を超えることはありません$10^5$したがって、整数オーバーフローは発生しません。
