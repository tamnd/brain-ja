 ## 解決策
 ## 問題の理解

 長さのシーケンスを数えるように求められます$n$ここで、各要素は範囲内の整数です$[0, 2^k)$、空ではないサブシーケンスは以下に等しいビットごとの XOR を持たないという制限があります。$x$。 基本的に、特定の XOR パターンを避けています。 入力$n$、$k$、 そして$x$シーケンスの長さ、値の範囲、および禁止された XOR 値をそれぞれ定義します。出力は有効なシーケンスの総数を法的に表します。$998\,244\,353$。 

制約は困難です。$n$まで可能です$10^9$、シーケンスを明示的に構築したり、単純な方法で各位置を反復したりするアプローチは除外されます。$k$まで可能です$10^7$、ただしすべての合計$k$テストケース全体の上限は$5 \cdot 10^7$に基づいてテーブルを前処理します。$k$慎重に行えば実現可能です。 値$x$に制約されています$0 \le x < 2^{\min(20, k)}$つまり、可能な XOR 値の管理可能なサブセットのみを処理することになります。 

明らかではないエッジケースは次のような場合です。$x = 0$。 完全にゼロで構成されるシーケンスは、次の場合に条件に違反します。$n \ge 1$したがって、これを個別に処理する必要があります。 もう一つのエッジケースは、$k = 0$これは、すべての要素が 0 でなければならず、空のサブシーケンスのみが有効であることを意味します。 このような特殊なケースの管理を誤ると、不正確なカウントが発生する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、長さのすべてのシーケンスが生成されます。$n$そして、すべてのサブシーケンスで禁止されている XOR をチェックします。 それぞれのシーケンスには、$2^k$要素ごとの可能性、与える$(2^k)^n$シーケンスがあり、各シーケンスには$2^n$後続。 これは明らかに手に負えません。$n$または$k$合計の操作は天文学的に大きくなります。 

重要な洞察は、XOR が集合に対して線形に動作することを観察することで得られます。数値の集合については、動的プログラミングを使用して、達成可能な XOR 値の集合をコンパクトに記述することができます。 させて$f$XOR 値からその XOR を生成するシーケンスの数へのマップになります。 新しい要素ごとに更新できます$f$として$f_{\text{new}}[y] = f_{\text{old}}[y] + f_{\text{old}}[y \oplus a_i]$。 ただし、これでも大規模なアプリケーションには遅すぎます。$n$。 

画期的な点は、任意の長さのシーケンスに対して、$n$すべての数字が入っている$[0, 2^k)$、固定 XOR を回避するシーケンスの総数$x$単純な繰り返しに従います。 もし$x = 0$、完全にゼロの空でないシーケンスは禁止されています。それ以外の場合、シーケンスは次の数値を含むシーケンスに分割されます。$x$そうでない人も。 これは再発に帰着します。$$\text{valid}(n) = (2^k - 1) \cdot \text{valid}(n-1) + \text{valid}(n-2)$$これは、高速な行列のべき乗または繰り返し 2 倍算を使用して効率的に解決できます。$n$まで$10^9$。 最後のモジュロ演算により、結果が 32 ビット整数の範囲内に収まることが保証されます。

 ## アルゴリズムのチュートリアル

 1.読む$t$、テストケースの数。 
2. 各テスト ケースについて、次の内容を読んでください。$n$、$k$、 そして$x$。 コンピューティング$all\_nums = 2^k$個別の整数の合計数として。 
3. もし$x = 0$、公式を使用します$(all\_nums - 1)^n \mod 998244353$ゼロのみを含むシーケンスは除外する必要があるためです。 高速累乗を使用してこれを計算します。 
4. もし$x \neq 0$、数値を 2 つのカテゴリに分割します: に等しい数値$x$そして残りの$all\_nums - 1$数字。 2 つの DP 状態を定義します。$dp_0$XOR が等しくないシーケンスの場合$x$そして$dp_1$XOR が次になるシーケンスの場合$x$。 
5.初期化$dp_0 = 1$そして$dp_1 = 0$。 マトリックスの反復を使用して更新します。$$\begin{pmatrix}dp_0 \\ dp_1\end{pmatrix} =  \begin{pmatrix}all\_nums-1 & 1 \\ all\_nums-1 & 0\end{pmatrix}^{n-1} \cdot  \begin{pmatrix}1 \\ 0\end{pmatrix}$$1. 戻る$dp_0 \mod 998244353$有効なシーケンスの数として。 
2. すべてのテスト ケースに対して繰り返します。 

機能する理由: 反復は XOR の線形的な性質を捉えています。 等しくない数値を追加する$x$既存のシーケンスを乗算します$all\_nums-1$、追加しながら$x$XOR 状態を切り替えます。 これにより、シーケンスが次の XOR に達した場合にはカウントされなくなります。$x$、べき乗全体にわたって不変式を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def fast_pow(a, b):
    result = 1
    a %= MOD
    while b:
        if b % 2:
            result = result * a % MOD
        a = a * a % MOD
        b //= 2
    return result

def solve():
    t = int(input())
    for _ in range(t):
        n, k, x = map(int, input().split())
        total = pow(2, k, MOD)
        if x == 0:
            print(fast_pow(total - 1, n))
            continue
        # matrix exponentiation for n > 1
        dp0, dp1 = 1, 0
        a, b = total - 1, 1
        def mat_pow(n):
            res0, res1 = 1, 0
            m0, m1 = a, b
            while n:
                if n % 2:
                    new0 = (res0 * m0 + res1 * m1) % MOD
                    new1 = (res0 * m0 + res1 * 0) % MOD
                    res0, res1 = new0, new1
                new_m0 = (m0 * m0 + m1 * m0) % MOD
                new_m1 = (m0 * m1 + m1 * 0) % MOD
                m0, m1 = new_m0, new_m1
                n //= 2
            return res0
        print(mat_pow(n))

if __name__ == "__main__":
    solve()
```最初のセクションでは、大きなべき乗に対する高速なべき乗を実装します。 main 関数は入力を効率的に読み取り、入力を区別します。$x = 0$場合。 のために$x \neq 0$、行列のべき乗は漸化式を効率的に計算します。 モジュロにより、整数のオーバーフローが発生しないことが保証されます。 微妙な点は、行列で状態遷移を正しく処理し、累乗を高速に行うことです。
