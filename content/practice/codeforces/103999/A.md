 ## 解決策
 ## 問題の理解

 2 つの文字列、長いテキスト文字列と短いパターン文字列が与えられます。 タスクは、パターンが連続した部分文字列としてテキスト内に何回出現するかを判断することです。 重複も含めてすべての出現がカウントされるため、パターンがテキスト内の複数の隣接する位置で始まる場合、それらすべてが答えに寄与します。 

入力は単純な 2 行で、1 行にはテキストが含まれ、もう 1 行にはパターンが含まれます。 出力は、パターンが完全に一致するテキスト内の開始位置の数を表す単一の整数です。 

この解決策を推進する重要な制約は、文字列が大きくなる可能性があり、一般的な競技プログラミング設定では最大約 10^5 文字になる可能性があることです。 考えられるすべての開始位置でパターンとテキストを比較する単純なアプローチでは、最悪の場合、約 O(nm) 文字の比較が必要になります。両方の文字列が大きく、長さが類似している場合、これは非常に遅くなります。 

いくつかの特殊なケースでは、不注意な実装が壊れる傾向があります。 1 つは、パターンがテキストと同一である場合で、正解は 1 つだけですが、境界やインデックス付けを誤って処理する実装では、それを過剰にカウントしたり、完全に見逃したりする可能性があります。 もう 1 つは、「aaaaaaaa」内の「aaaa」など、パターンに繰り返し構造がある場合です。この場合、重複する一致が頻繁に発生し、強引な解決策が 2 次の動作に低下する可能性があります。 3 番目は、パターンの長さが 1 の場合で、テキスト内のすべての文字一致が有効であり、ループ境界でのオフバイワン エラーが一般的です。 

## アプローチ

 問題を解決する最も直接的な方法は、テキスト内の可能なすべての開始位置にパターンを配置して、文字ごとに比較することです。 テキスト内のインデックス i ごとに、i で始まる部分文字列がパターンに完全に一致するかどうかを確認します。 これは、一致が開始される可能性のあるすべての候補位置を徹底的にテストするため、正しいです。 

ただし、このアプローチでは、開始位置ごとに m 回の比較が実行されます。ここで、m はパターンの長さです。 可能な開始位置は n 個あるため、総作業量は n の m 倍に比例します。 文字が繰り返されるテキストや文字が繰り返されるパターンなどの最悪の場合の入力では、すべての比較シーケンスが失敗する前にほぼ完全に進行し、二次的な動作が生成されます。 

この改善は、パターンの重複するシフト間の繰り返しの比較が無駄であることを認識することによってもたらされます。 パターンのプレフィックスを一致させた後で不一致が発生した場合、そのプレフィックス情報を再利用できます。 文字列の接頭辞がその接尾辞とどのように重なるかを正確に捕捉する構造は、Knuth-Morris-Pratt アルゴリズムで使用される接頭辞関数です。 このプレフィックス構造がパターンに対して事前に計算されると、すでに一致しているパターンの量を維持しながら、単一パスでテキストをスキャンできます。 テキスト内の各文字は 1 回処理され、パターン ポインターは事前に計算されたフォールバック リンクを使用して前方に移動または後退するだけです。 

これにより、一致の繰り返しの再計算が、テキスト上の線形時間ステート マシンの走査に変わります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | KMP（プレフィックス機能） | O(n + m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 KMP 文字列マッチング フレームワークを使用して問題を解決します。

1. パターン文字列のプレフィックス関数を計算します。 パターン内の各位置について、この値は、その位置で終わるサフィックスでもある最長の適切なプレフィックスの長さを表します。 この構造は、不一致が発生した場合に、文字を最初から再チェックすることなくどこでマッチングを再開できるかを示します。 
2. ポインタ j = 0 を初期化し、テキストと現在一致するパターンの文字数を表します。 
3. テキスト内の各文字を左から右に繰り返します。 文字ごとに、現在の一致を拡張しようとします。 
4. 現在のテキスト文字が位置 j のパターン文字と一致する場合、j を 1 つインクリメントします。 これにより、プレフィックス条件が保持されるため、現在の部分一致が拡張されます。 
5. 不一致が発生し、j が 0 でない場合は、プレフィックス関数を使用してフォールバックします。j を j − 1 のプレフィックス関数の値に設定し、再度マッチングを試みます。 このステップでは、処理されたテキストの現在の接尾辞と一致する可能性がある最長の有効な接頭辞を再利用します。 
6. j が 0 になるか、一致が可能になるまで、フォールバック プロセスを繰り返します。 j が 0 で、現在の文字がまだ一致しない場合は、次のテキスト文字に進みます。 
7. j がパターンの全長に達するたびに、出現が 1 つ見つかります。 答えをインクリメントし、重複する一致が自然に処理されるように、j をパターンの最後の位置のプレフィックス関数の値にリセットします。 

これが機能する理由は、スキャン内のすべての点で、 j が現在の位置で終わるテキストの接尾辞と一致するパターンの最長の接頭辞の長さを表すためです。 プレフィックス関数は、不一致が発生した場合に、正確性を失ったり、有効なアライメントを欠落したりすることなく、次に最適なプレフィックスに移行することを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def prefix_function(p):
    n = len(p)
    pi = [0] * n
    j = 0
    for i in range(1, n):
        while j > 0 and p[i] != p[j]:
            j = pi[j - 1]
        if p[i] == p[j]:
            j += 1
        pi[i] = j
    return pi

def count_occurrences(s, p):
    if not p or not s:
        return 0

    pi = prefix_function(p)
    j = 0
    ans = 0

    for i in range(len(s)):
        while j > 0 and s[i] != p[j]:
            j = pi[j - 1]
        if s[i] == p[j]:
            j += 1

        if j == len(p):
            ans += 1
            j = pi[j - 1]

    return ans

def main():
    s = input().strip()
    p = input().strip()
    print(count_occurrences(s, p))

if __name__ == "__main__":
    main()
```このソリューションでは、前処理とスキャンが分離されます。 プレフィックス関数の計算により、パターンのフォールバック構造が構築されます。 スキャン中、変数 j は現在一致するパターンの量を追跡します。 スキャン内の while ループは KMP 遷移ロジックの中核であり、不一致があった場合に比較を最初からやり直すのではなく、制御されたフォールバックを確実にトリガーします。 

実装の微妙な詳細は、完全一致後のリセットです。 j をゼロに設定する代わりに、最後に一致した位置のプレフィックス関数の値を再利用します。 これにより、文字を再スキャンすることなく、重複する一致を正確にカウントできるようになります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、パターンの長さがちょうど 1 文字である場合です。 この場合、テキスト内の一致するすべての文字が出現としてカウントされる必要があります。 各一致がすぐに完全一致条件をトリガーし、全体でゼロであるプレフィックス配列を使用して正しくリセットされるため、アルゴリズムはこれを自然に処理します。 

もう 1 つの特殊なケースは、テキストのどこにも現れないパターンです。 ポインター j は繰り返しゼロに戻りますが、一致イベントはトリガーされないため、答えはゼロのままです。 

3 番目のケースは、同じ文字が繰り返されるテキストや、短いながらも繰り返されるパターンなど、最大限の重複です。 この状況では、一致するたびにプレフィックス関数によって j がゼロ以外に維持されるため、スキャンを再起動せずに効率的に続行でき、有効な開始位置がすべて 1 回だけカウントされることが保証されます。
