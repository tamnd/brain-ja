 ## 解決策
 ## 問題の理解

 このタスクは基本的に、指定された文字列内で使用可能な文字から固定ターゲット単語を構築できるかどうかを確認することです。 各テスト ケースには、大文字で作られた「バナー」が与えられます。 Cora は、これらの文字の一部を再配置し、不要な文字を破棄して、文字列「LUDDYROCKS」を正確に形成したいと考えています。 

したがって、出力はバナー内の複数の文字セットに必要な各文字の十分なコピーが含まれているかどうかによってのみ決まります。 自由に並べ替えることが許可されているため、順序は関係ありません。 重要なのは頻度の一致です。対象となる単語のすべての文字が、少なくとも必要な回数だけ利用可能でなければなりません。 

制約は小さく、テスト ケースの数は最大 100、各文字列の長さは最大 100 です。これにより、各文字列の単純なスキャンでも低コストであることがすぐにわかります。 テスト ケースごとの頻度カウントは、最悪の場合でもおよそ 10,000 文字の操作によって制限されますが、1 秒の制限の下ではわずかです。 

微妙な点は、ターゲット単語内で文字が繰り返される可能性があることです。 たとえば、「LUDDYROCKS」には D が 2 つ含まれます。 個別の文字の存在を検証するだけの単純なチェックでは、ここでは失敗します。 もう 1 つの落とし穴は、順序が重要となるサブシーケンス チェックのように問題を扱うことです。 任意に並べ替えることが許可されているため、これは不正確です。 

小さな失敗例としては、文字列「LUDYROCKS」があります。 D が 1 つだけ含まれているため、他の文字がすべて存在しても、答えは NO でなければなりません。 セットの包含をチェックするだけのアプローチでは、それが誤って受け入れられてしまいます。 

## アプローチ

 この問題を考える強引な方法は、ターゲットの単語を明示的に形成してみることです。 バナーを繰り返しスキャンし、使用されている文字をマークすることで、「LUDDYROCKS」の各文字を照合することもできます。 ターゲット内の文字ごとに、文字列全体を検索して、未使用の一致する文字を見つけます。 これが機能するのは、実際の構築をシミュレートし、重複があっても正確性が保証されるためです。 

ただし、この方法では最大 10 件の一致が実行され、各一致で最大 100 文字のスキャンが必要になる場合があります。 これにより、テスト ケースごとに約 1000 操作という最悪の場合の複雑さが生じますが、ここではまだ問題ありませんが、構造が不必要に重くなり、制約が増加すると拡張できなくなります。 

重要な観察は、順序は無関係であり、再利用は許可されていないため、問題は頻度のカウントに帰着するということです。 繰り返し検索する代わりに、バナー内の各文字の出現回数を 1 回カウントし、ターゲット単語の必要な頻度と直接比較します。 これにより、繰り返しの検索の問題が単一の線形パスに軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォースマッチング | O(n・m) | O(n) | 制約として受け入れられます |
 | 周波数計数 | O(n) | お(1) | 最適 |

 ## アルゴリズムのチュートリアル

 1. ターゲット文字列「LUDDYROCKS」内の各文字の頻度を事前計算します。 これにより、テスト ケース間で変わらない固定要件テーブルが得られます。 
2. 各テスト ケースについて、バナー文字列を読み取ります。 
3. バナー内の各文字の頻度を数えます。 
4. ターゲット単語に必要なすべての文字について、バナー数が必要な数以上であるかどうかを確認します。 
5. すべての要件が満たされている場合は、YES を出力します。 それ以外の場合は NO を出力します。 

すべての必須文字を個別にチェックする理由は、各文字が独立した制約を表すためです。 どれか一つでも失敗すると建設は不可能になります。 

### なぜ効果があるのか

このアルゴリズムは、バナーの頻度テーブルがすべての可能な再配置を完全に記述しているという不変式に依存しています。 再配置によってカウントは変更されないため、有効な構造はすべて、バナーの文字マルチセットのサブマルチセットとして表現可能でなければなりません。 すべての必要な数が使用可能な数以下であることを確認することで、有効な文字の選択が存在することが保証されます。 順序付けの制約が存在しないため、実現可能性は正確にマルチセットの包含に限定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

TARGET = "LUDDYROCKS"

# precompute required frequencies
need = {}
for c in TARGET:
    need[c] = need.get(c, 0) + 1

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    have = {}
    for c in s:
        have[c] = have.get(c, 0) + 1

    ok = True
    for c, cnt in need.items():
        if have.get(c, 0) < cnt:
            ok = False
            break

    print("YES" if ok else "NO")
```コードは、ターゲット単語の固定要件マップを構築することから始まります。 これにより、テスト ケースごとに再計算する必要がなくなります。 入力文字列ごとに、新しい頻度辞書が 1 回のパスで構築されます。 

最後のループは重要な比較ステップです。 これにより、必要なすべての文字が十分な量で存在することが保証されます。 使用する`get(c, 0)`キーのエラーを回避し、欠落している文字をきれいに処理します。 

実装の微妙な詳細の 1 つは、入力文字列を削除することです。 それなし`.strip()`、改行文字が頻度カウントの一部として誤って解釈される可能性があり、誤ったキーが辞書に導入される可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    TARGET = "LUDDYROCKS"
    need = {}
    for c in TARGET:
        need[c] = need.get(c, 0) + 1

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        have = {}
        for c in s:
            have[c] = have.get(c, 0) + 1

        ok = True
        for c, cnt in need.items():
            if have.get(c, 0) < cnt:
                ok = False
                break

        out.append("YES" if ok else "NO")

    return "\n".join(out)

# provided samples

assert run("1\n9\nLUDYROCKS\n") == "NO"

# custom cases
assert run("1\n5\nABCDE\n") == "NO", "missing most letters"
assert run("1\n20\nLLLUDDDYROCKSSSSS\n") == "YES", "extra letters allowed"
assert run("2\n10\nLUDDYROCKS\n9\nLUDDYROCKS\n") == "YES\nNO", "multi-test correctness"
assert run("1\n10\nLUDDYROCKS\n") == "YES", "exact match"

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、「LUDYROCKS」のように、バナーに必要な文字がすべて含まれているものの、多重度が不十分である場合です。 このアルゴリズムは出現回数を明示的にカウントするため、D の要件 (2 個が必要、1 個が使用可能) を比較すると、そのケースは即座に拒否されます。 

もう 1 つの特殊なケースは、バナーが非常に長く、無関係な文字が多く含まれている場合です。 たとえば、頻度の比較ではターゲットにない余分な文字が無視されるため、「ZZZLUDDYROCKSZZZ」のような文字列でも正しい YES が生成されます。 不変条件は、厳密な等価性ではなく、下限のみが重要であるということです。 

最後のケースは、「LUDDYROCKSLUDDYROCKS」のように、完全な構築が繰り返されることです。 カウントは線形にスケールされ、必要なすべての特性が依然として満たされるため、度数テーブルはこれを自然にサポートします。
