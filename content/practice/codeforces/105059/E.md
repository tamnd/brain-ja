 ## 解決策
 ## 問題の理解

 私たちは次のラインを持っています$n$1 から 1 までのラベルが付いた穴$n$。 各穴には 1 つのモグラが含まれており、すべてのモグラはゲーム中に 1 回だけ表示されます。$n$秒。 出現順序はランダムです。各秒ごとに、残りの見えないほくろの 1 つが均一にランダムに選択され、その秒間だけアクティブになります。 

ゲーム開始前に 2 台のロボットがこのラインに配置されます。 1 つはホール 1 から始まり、もう 1 つはホールから始まります$n$。 1 秒ごとに、両方のロボットが同時に移動する可能性があり、各ロボットは最大で移動できます。$v$その 1 秒間のラインに沿った位置。 移動後、ロボットがモグラの穴の上に立っていれば、即座にモグラをたたきます。 すべてのモグラは、出現した瞬間に正確に叩く必要があり、各モグラは 2 台のロボットのうちの 1 つだけで処理されなければなりません。 

このタスクは、ランダムなモグラの出現順序の下で、最適な動きとロボットへのモグラの最適な割り当てを考慮して、ロボットがすべてのモグラを首尾よく捕​​まえることができる確率を計算することです。 

重要な点は、ランダム性が以下の順列にわたるということです。$n$なぜなら、「残りのほくろから均一に」ということは、ランダムな順列を生成することと同じだからです。 

制約$n \le 8$あらゆる解が指数関数的であることを即座に知らせます$n$実行可能です。 サイズの状態空間$2^n$あるいは$2^n \cdot n^2$特に多項式の遷移では許容されます。$n$。 すべての順列を明示的に反復するアプローチは除外されます。$n!$、 それでも$n!$にとっては小さい$n=8$ただし、列挙ではなく、すべての結果に対する確率の集計が必要です。 

最も近いロボットにモグラを貪欲に割り当てると仮定すると、微妙な失敗例が現れます。 両方のロボットがほくろに到達できる短いラインを考えてみましょう。ただし、「局所的に最も近い」割り当てを選択すると、将来必要な到達可能性が妨げられます。 もう 1 つの失敗例は、ロボットの位置が進化し、将来の到達可能性が複合的に制限されるため、ステップ間の独立性を仮定することです。 

## アプローチ

 ブルート フォース ビューは定義から始まります。モグラの出現の考えられるすべての順列を列挙し、ゲームをシミュレートし、ロボットがその順序ですべてのモグラを捕まえられるかどうかを確認します。 各順列について段階的にシミュレーションし、各段階でロボット 1 とロボット 2 のどちらが現在のもぐらを取得するかを決定し、到達可能性の制約を確認します。 これは正しいですが、すべてを繰り返す必要があります$n!$順列と実行$O(n)$順列ごとのシミュレーション。これにより、$O(n \cdot n!)$仕事。 それでも$n=8$この境界線は実現可能ですが、それは不必要で概念的に無駄です。 

重要な観察は、ランダム性には明示的な置換が必要ないということです。 各ステップで、残りのほくろの中から次のほくろが均一に選択されるため、すでに出現したほくろのサブセットに対する確率 DP としてプロセスを順次処理できます。 次数を列挙する代わりに、すべての部分状態にわたる確率質量を蓄積します。 

重要な構造は、どの時点でもシステムの状態が 3 つの要素、つまりどのモグラがすでに出現しているか、および 2 台のロボットの現在位置によって完全に記述されるということです。 その状態から、次のイベントは残りのモグラの中から一様に選択され、動きの制約が許す限り、モグラが 2 台のロボットのうちの 1 つに割り当てられると、遷移は決定的になります。 

これにより、問題がサブセットにわたる階層化された動的プログラムに変換されます。各層は処理されるモルの数に対応します。

 ## アルゴリズムのチュートリアル

 動的プログラミング テーブルを定義します。このテーブルでは、出現したモグラのシーケンスの中でどのくらい離れているか、どのサブセットがすでに出現しているか、両方のロボットが現在どこに立っているかを状態がエンコードします。 

「時間ステップ」をこれまでに明らかにされたほくろの数として解釈します。 時間に$t$、 その通り$t$モグラが現れた。 

### ステップ

 1. 状態をビットマスクで表現する`mask`どのほくろがすでに出現しているかをロボットの位置によって示します`(a, b)`。 
2. 次のコマンドを使用して DP を初期化します。`dp[0][1][n] = 1`、ほくろがまだ出現していないことを意味します。ロボット 1 は位置 1 にあり、ロボット 2 は位置にあります。$n$、確率質量は 1 です。 
3. 州ごとに`(mask, a, b)`と$k = \text{popcount(mask)}$に含まれていないすべてのほくろを考慮します。`mask`。 そのようなほくろはそれぞれ、確率的に次のほくろである可能性が等しくなります。$1/(n-k)$。 
4. 各候補の次のほくろの位置$x$、ロボット 1 が 1 秒以内に到達できる場合は、ロボット 1 に割り当てを試みます。つまり、$|a - x| \le v$、または場合はロボット 2 に$|b - x| \le v$。 
5. ロボット 1 がモグラを捕まえると、ロボット 1 が次の場所に移動する新しい状態に移行します。$x$そしてロボット 2 はそこに留まります$b$。 ロボット 2 がそれを取ると、ロボット 2 は次の場所に移動します。$x$。 
6. 現在の状態の確率をすべての有効な次のモルに均等に分配し、それを後続の状態に累積します。 
7. すべての処理が完了したら$n$ステップごとに、すべての状態の確率を合計します。`mask`すべてのほくろが含まれます。 

### なぜ効果があるのか

 不変条件とは、`dp[mask][a][b]`セットを正確に生成するすべての有効なランダム履歴の合計確率を格納します`mask`明らかにされたモグラのセットとしてロボットを所定の位置に残します`(a, b)`全員にサービスを提供した後。 次の各モルが残りのセットから均一に選択され、そのモルの実行可能なすべての割り当てが 1 回だけ調査されるため、すべての遷移は正確さを維持します。 ロボットの決定は将来のモグラの選択のランダム性に影響を及ぼさないため、DP は確率分布を実現可能性のチェックから明確に分離します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, v = map(int, input().split())

    size = 1 << n
    dp = [[0.0] * (n + 1) for _ in range(size)]
    dp[0][0] = [0.0] * (n + 1)

    dp = {}
    dp[(0, 1, n)] = 1.0

    for mask in range(size):
        k = bin(mask).count("1")
        rem = n - k
        if rem == 0:
            continue

        nxt = {}
        for (m, a, b), prob in dp.items():
            if m != mask:
                continue

            if prob == 0:
                continue

            base = prob / rem

            for i in range(n):
                if mask >> i & 1:
                    continue
                x = i + 1

                if abs(a - x) <= v:
                    key = (mask | (1 << i), x, b)
                    nxt[key] = nxt.get(key, 0.0) + base

                if abs(b - x) <= v:
                    key = (mask | (1 << i), a, x)
                    nxt[key] = nxt.get(key, 0.0) + base

        dp = nxt

    full = (1 << n) - 1
    ans = 0.0
    for (m, a, b), prob in dp.items():
        if m == full:
            ans += prob

    print(f"{ans:.15f}")

if __name__ == "__main__":
    solve()
```多くの状態は到達できないため、実装では、完全な 3D 配列ではなく、アクティブな DP 状態の辞書が維持されます。 各反復は固定サブセット サイズに対応し、確率質量は残りのモル全体に均一に分割されます。 動きの制約は、ロボットにほくろを割り当てるときにローカルに適用されます。 

よくある微妙な点は、各状態の残りのモル数で割ることです。 これは、置換を行わずに均一なサンプリングを繰り返すことによって順列が構築され、各ステップで正規化に失敗すると確率モデルが壊れるため、これが不可欠です。 

もう 1 つの重要な詳細は、両方の割り当ての選択が独立して考慮されることです。 ほくろは両方のロボットから到達可能であり、両方のブランチは異なる有効な履歴に対応するため、両方のブランチを追加する必要があります。 

## 実用的な例

 ### 例 1: n = 4、v = 1

 私たちは小さなサブセットの進行を追跡します。 初期状態は`(mask=0000, a=1, b=4)`確率1で。 

最初のステップでは、4 つのモグラのいずれかが確率で出現します。$1/4$。 ロボット位置から距離 1 以内にあるもののみを割り当てることができます。 

| ステップ | マスク | (a、b) | 残り | 移行ノート |
 | --- | --- | --- | --- | --- |
 | 0 | 0000 | (1,4) | 4 | 開始 |
 | 1 | 0001 | (1,4) または (2,4) | 3 | ロボット 1 側ではモール 1 または 2 のみが可能 |
 | 2 | ... | ... | 2 | 状態はさらに分割されます。

 このトレースは、確率が各層で均一に分割される一方で、実現可能性がどのように遷移を制限するかを示しています。

 これは、到達可能性の制約によってより多くの分岐が強制される、より厳しいケースです。

 ## 特殊なケース

 いつ$n = 1$、ほくろは1つしかなく、すぐに現れます。 位置 1 のロボットが常に DP をキャッチできるため、DP は完全成功状態から開始され、答えは 1 になります。 

いつ$v$に比べて大きい$n$、すべてのほくろは 1 回の動作でどちらのロボットの位置からも到達できるため、DP 遷移がブロックされることはなく、すべての順列が有効なパスに寄与します。 すべての分岐が実行可能であるため、アルゴリズムは自然に合計確率 1 を累積します。 

いつ$v = 0$、ロボットは決して動きません。 すでに位置 1 と位置にあるほくろのみ$n$正しく割り当てることができます。 遷移ステップで到達可能性が失敗するため、DP は他のすべての割り当てを即座にフィルターで除外し、必要なモルが正しい時間に端点に正確に現れる順列からの確率のみを残しますが、これは非常に制限されています。
