 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付けられた停留所のある通りが与えられており、停留所 1 から停留所 n まで移動したいと考えています。 移動はバス路線を通る場合のみ無料で、それ以外の場合は路線に沿って歩いた距離と同じ料金がかかります。 

各バス路線は[L,R]区間です。 バス路線に乗っている間は、その区間内のどの停留所でも出入りできます。さらに重要なのは、その区間内のどの停留所間でも歩行コストゼロで自由に移動できることです。 重要な点は、バス路線内に入ると、その区間内での移動はその区間に沿って「自由に移動」できるということです。 

バスの外では、線に沿って歩くだけで、x から y まで歩くのにかかる費用は |x − y| です。 目標は、バスの間隔を自由移動領域として使用し、1 から n までに移動するのに歩く量を最小限に抑えることです。 

ここでの構造は基本的に、ゼロコスト セグメント (バスでカバーされるゾーン) と、それらのゾーンの外に出た場合にのみプラスコストの移動を含むラインです。 

制約は大きく、テスト ケースごとに最大 2 · 10^5 のストップと 2 · 10^5 のルート、および最大 10^4 のテスト ケースがあります。 これにより、道路に沿ったステップバイステップの動きをシミュレートしようとしたり、停留所全体のグラフを明示的に構築したりするソリューションは即座に除外されます。 どのアプローチでも、問題をテスト ケースごとの並べ替えと線形処理、あるいはそれに近いものに減らす必要があります。 

各バスを個別に扱うと、微妙な障害が発生することがあります。 たとえば、1 台のバスが [1, 2] をカバーし、もう 1 台のバスが [2, 3] をカバーする場合、どちらも単独では全範囲をカバーしていませんが、一緒にすると 1 から 3 までの自由な移動が可能になります。重複する区間やチェーン接続された区間をマージしない単純なアプローチでは、2 と 2 の間の歩行コストが誤って請求されたり、これらのルートが単一の接続されたゼロコスト領域を形成していることを見逃したりする可能性があります。 

もう 1 つのエッジ ケースは、1 または n がどの間隔にもカバーされていない場合です。 その場合、到達可能な最寄りのバス地域まで明示的に歩くか、バスがまったく役に立たない場合は直接目的地まで歩く必要があります。 常にバス領域内で開始することを前提としたアプローチは、ここでは失敗します。 

## アプローチ

 この問題を考える強引な方法は、すべてのストップをグラフ内のノードとしてモデル化することです。 同じバス間隔内のすべての停留所のペアの間に重み 0 のエッジを追加し、歩行を表す連続する停留所 i と i+1 の間に重み 1 のエッジを追加します。 次に、1 から n までの最短パス アルゴリズムを実行します。 

これは正しいですが、まったく実行不可能です。 長さ L の各区間は、完全に拡張した場合の最悪の解釈で O(L^2) 個の重みゼロ エッジを追加し、最適化したとしても、依然として 2 · 10^5 ノードにわたるグラフとなり、潜在的に重複する密な接続が得られます。 ダイクストラのような最短経路アルゴリズムは、区間接続性の暗黙的な構造により遅すぎます。 

重要な点は、バスの間隔によって任意の接続が作成されるのではなく、ライン上の連続した領域がマージされるだけであるということです。 2 つの区間が重なるか接触する場合、それらの結合内のストップは歩かずに他のストップに到達できます。 これは、個々のストップに関するグラフがまったく必要ないことを意味します。 区間が数直線上でどのように結合して最大連結セグメントになるかを理解することだけが必要です。 

重なり合うすべての間隔を結合のないマージされたセグメントに圧縮すると、問題は純粋にこれらのセグメント間を移動することに関するものになります。 各セグメント内ではコストはゼロです。 セグメント間では、前に進む唯一の方法は、あるセグメントの終わりと次のセグメントの始まりの間のギャップを歩くことです。 

次に、セグメントを左から右の順に処理し、重複せずに 1 つのセグメントから次のセグメントに移動する必要がある場合にのみ歩行コストを蓄積します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース グラフ + 最短パス | O(n + k log n + 強力なエッジ拡張) | O(n + k) | 遅すぎる |
 | マージ間隔 + リニア スイープ | O(k log k) | O(k) | 承認済み |

## アルゴリズムのチュートリアル

 問題を区間マージに変換し、その後数直線に沿って貪欲な走査を行います。 

1. すべてのバス間隔を開始点で並べ替えます。 これにより、道路の自然な左から右の順序で処理されるようになります。 
2. 重複または接触している間隔を最大セグメントにマージします。 現在のセグメント [curL, curR] を維持します。 各区間 [L, R] について、L ≤ curR の場合、curR = max(curR, R) を拡張します。それ以外の場合、現在のセグメントを終了し、新しいセグメントを開始します。 オーバーラップによってユニオン内に完全なコストゼロの接続が作成されるため、このステップは正当化されます。 
3. マージ後、自由に移動できるすべての場所を表す互いに素なセグメントが得られます。 
4. ここで、位置 1 から位置 n への移動をシミュレートします。 ポインタ pos を 1 から開始し、昇順にセグメントをスキャンします。 
5. 各セグメント [L, R] について、pos がすでにセグメント内にある場合 (L ≤ pos ≤ R)、自由に R にジャンプして続行できます。 
6. pos がセグメントの左側にある場合 (pos < L)、pos から L まで歩く必要があるため、答えに L − pos を追加してセグメントに「入力」し、その後自由に R に移動できます。 
7. pos がセグメントを超えている場合 (pos > R)、先に進むことができないため無視します。 
8. n に達するか通過するまで続け、その時点で停止します。 

重要なアイデアは、切断された自由領域間のギャップを通過する場合にのみ歩行コストを支払うということです。 

### なぜ効果があるのか

 マージされたセグメントは、すべてのポイントがオーバーラップするバス間隔を介して接続されている最大領域を表します。 このような地域内では、バスの乗車を連鎖させることであらゆる移動をシミュレートできるため、コストはかかりません。 

2 つの連続するマージされたセグメントの間には、ギャップを埋める重複区間はありません。つまり、一連のバス乗車は、バスの適用範囲外に出ずにそのギャップを越えることはできません。 したがって、セグメント間の移行には必ずラインの覆われていない部分を横切る必要があり、迂回はライン メトリック上の距離を増やすだけであるため、そのギャップを正確に歩くという貪欲な戦略が最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        segs = []
        
        for _ in range(k):
            l, r = map(int, input().split())
            segs.append((l, r))
        
        if k == 0:
            print(n - 1)
            continue
        
        segs.sort()
        
        merged = []
        cur_l, cur_r = segs[0]
        
        for l, r in segs[1:]:
            if l <= cur_r:
                cur_r = max(cur_r, r)
            else:
                merged.append((cur_l, cur_r))
                cur_l, cur_r = l, r
        merged.append((cur_l, cur_r))
        
        pos = 1
        ans = 0
        
        for l, r in merged:
            if pos > n:
                break
            if r < pos:
                continue
            if l <= pos <= r:
                pos = r
                continue
            if pos < l:
                ans += l - pos
                pos = r
        
        if pos < n:
            ans += n - pos
        
        print(ans)

if __name__ == "__main__":
    solve()
```コードは、重複する領域を 1 回のパスでマージできるように、すべての間隔を並べ替えることから始まります。 マージ ステップでは、ラインの最大のゼロコスト コンポーネントが構築されます。 

その後、トラバースは左から右への移動をシミュレートします。 変数`pos`は常に、無料で、または蓄積された歩行コストを支払った後に到達できる最も遠い地点を表します。 いつ`pos`マージされたセグメント内にある場合は、コストをかけずにセグメントの右エンドポイントまで拡張します。 いつ`pos`セグメントの前にある場合、そのセグメントに入るためにギャップを正確に支払います。 

微妙な点は、私たちは常にジャンプしているということです`pos`直接に`r`セグメント内では、接続された区間内ではすべての中間停止にコストをかけずに到達できるため、より早く停止する理由がありません。 

## 実用的な例

 ### 例 1

 入力:```
n = 10, k = 2
[2, 4]
[7, 9]
```結合されたセグメント:

 | ステップ | 現在のセグメント | アクション | 位置 | コスト |
 | --- | --- | --- | --- | --- |
 | 初期化 | - | 開始 | 1 | 0 |
 | 1 | [2,4] | 1→2を歩く | 2 | 1 |
 | 1 | [2,4] | 4 に拡張 | 4 | 1 |
 | 2 | [7,9] | 4→7を歩く | 7 | 4 |
 | 2 | [7,9] | 9まで拡張 | 9 | 4 |
 | 最終 | - | 9→10を歩く | 10 | 5 |

 出力は5です。 

このトレースは、セグメント内の移動は無料である一方で、覆われていないギャップを越えて移動する場合にのみコストが蓄積することを示しています。 

### 例 2

 入力:```
n = 8, k = 3
[1,3]
[2,5]
[6,8]
```結合されたセグメントは次のようになります。 

[1,5]、[6,8]

 | ステップ | セグメント | 前の位置 | アクション | 後の位置 | コスト |
 | --- | --- | --- | --- | --- | --- |
 | 1 | [1,5] | 1 | 内側では 5 にジャンプします | 5 | 0 |
 | 2 | [6,8] | 5 | 5→6歩く | 8 | 1 |

 最終コストは1です。 

これは、マージが重要である理由を示しています。 [1,3] と [2,5] をマージしないと、重複領域内で複数の遷移が必要であると誤って考える可能性があります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k log k) | ソート間隔が支配的で、マージとスイープは線形です。 
| スペース | O(k) | 間隔とマージされたセグメントの保存 |

 この制約により、テスト ケースごとに最大 2 · 10^5 の間隔が許可されるため、O(k log k) 解は 3 秒以内で簡単に十分に高速になり、線形スイープによってテストごとのオーバーヘッドが最小限に抑えられます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n, k = map(int, input().split())
            segs = []
            for _ in range(k):
                l, r = map(int, input().split())
                segs.append((l, r))

            if k == 0:
                out.append(str(n - 1))
                continue

            segs.sort()
            merged = []
            cl, cr = segs[0]

            for l, r in segs[1:]:
                if l <= cr:
                    cr = max(cr, r)
                else:
                    merged.append((cl, cr))
                    cl, cr = l, r
            merged.append((cl, cr))

            pos = 1
            ans = 0

            for l, r in merged:
                if pos > n:
                    break
                if r < pos:
                    continue
                if l <= pos <= r:
                    pos = r
                elif pos < l:
                    ans += l - pos
                    pos = r

            if pos < n:
                ans += n - pos

            out.append(str(ans))
        return "\n".join(out)

    return solve()

 ## 特殊なケース

 主なエッジケースは、バス路線がまったくない場合です。 その状況では、マージされたセグメント リストは空であり、答えは 1 から n までの純粋なウォーキングにフォールバックする必要があります。 アルゴリズムはこれを次のように明示的に処理します。`k == 0`チェックして、ラインに沿った必要な距離に一致する n − 1 を生成します。 

もう 1 つの微妙なケースは、バス間隔が正確に位置 1 で始まる場合に発生します。アルゴリズムはこれを正しく処理します。これは、最初のマージされたセグメント内に 1 がある場合、初期位置がそのセグメント内であるとみなされ、セグメントの右エンドポイントへの即時の自由な拡張が可能になるためです。 

最後の重要なケースは、[1,2]、[2,3]、[3,4] などの緊密に連鎖した間隔です。 終点を除いて完全に重なり合うペアがない場合でも、マージ ステップはそれらを単一のセグメントに正しく統合し、アルゴリズムが中間停止間の歩行を誤って請求しないようにします。
