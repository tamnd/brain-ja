 ## 解決策
 ## 問題の理解

 都市を表す接続された無向グラフが与えられます。交差点がノード、道路がエッジです。 車はノード 1 から出発し、ノード n に到達する必要があります。 どの道路も通過するのに正確に 1 単位の燃料がかかります。 

車には固定容量 g の燃料タンクがあり、満タンで始動します。 車が次の道路を横断できない地点に到達した場合は、直ちに燃料を補給しなければなりません。 重要なルールは、ノード n で旅行が終了するときに未使用のまま残っている燃料の代金を乗客 (セバ) が支払うということです。 タンクが x 燃料で終了した場合、セバは g − x を支払います。 

Seba はノード 1 からノード n までの任意のウォークを選択できます。 目標は、到着時にタンク内に残っている燃料の量を最小限に抑えるルートを選択することです。これは、進行状況をリセットする不必要な燃料補給を強制せずに、消費される燃料の量を最大化することと同じです。 

一見すると、これは最短経路の問題ですが、燃料によってセグメントごとに制限された「バジェット」が導入されるという点が異なります。ノードでリセットする必要がある前に、最大で g 個のエッジを通過できます。 

制約 n, m ≤ 2 · 10^5 は、すべてのパスを列挙したり、パスの状態を明示的に保存したりすることを直ちに除外します。 (ノード、残りの燃料) の単純状態空間は O(n・g) となり、大きすぎるため、拡張状態に対するダイクストラでも慎重に構造化する必要があります。 

微妙な問題は、複数のルートに同じ数のエッジがあるが、給油を強制する頻度が異なる場合に発生します。 たとえば、不必要にループするパスは燃料を消費する可能性がありますが、タンクをリセットする給油ポイントも導入するため、最終的には目に見えない形で残りの燃料が増加する可能性があります。 1 から n への素朴な貪欲な最短パスは、給油によって目的地での「残りの燃料の配置」がリセットされることを無視します。 

## アプローチ

 強引な解釈では、1 から n までのすべての単純なパスを列挙し、各パスに沿った燃料消費量をシミュレートします。 これは正しいです。すべての有効なルートを直接評価できるためです。エッジ トラバーサルをシミュレートし、燃料を減らし、必要に応じて燃料を補給します。 答えは、すべての経路にわたる最小残存燃料です。 問題は、一般的なグラフ内の単純なパスの数が指数関数的であり、密な構造では簡単に 2^n を超えるため、このアプローチは n = 30 の場合でも実行不可能であることです。 

重要な観察は、重要なのは満タンのリセットの間にどれだけのエッジを通過するかだけであるということです。 ノードに到着すると、有効な「燃料状態」は最後の燃料補給以降に取得されたエッジの数のみに依存します。 燃料補給は続行できないときに決定論的に行われるため、このプロセスは経路を最大 g の長さのセグメントに分割することに相当します。 

次に、問題を目的地から逆方向に再解釈します。 1 から n までのパスを固定するとします。 車はエッジごとに 1 ユニットを消費しますが、セグメントが g を超えるたびに、給油を強制的に挿入する必要があります。 長さ g の各完全なセグメントは、その終点で g − g = 0 の残余衝撃に寄与しますが、最後のセグメントにはいくらかの残存燃料が残る可能性があります。 

これにより、問題は、(g − 距離 mod g) の剰余を最大化する 1 から n までのパスを見つけることに変わります。これは、距離法 g を最小化することと同じです。 この構造は、g を法として距離を追跡する必要があることを示唆しています。g が素数であるため、モジュラーサイクルは隠れた周期構造を持たずにきれいに動作することが保証されます。 

このグラフを、各ノードが燃料剰余モジュロ g とペアになっている層状状態グラフに変換します。 状態 (u, r) からエッジに沿って移動すると、(v, (r + 1) mod g) に遷移します。 r + 1 が g に等しいときは常に、燃料補給がすぐに行われるため、次のノードで実質的に r = 0 にリセットされます。

したがって、問題は n · g 状態のグラフ内の最短経路になりますが、すべての状態を明示的に展開する必要はありません。 代わりに、ノード n に到達するには g を法とする最小ステップ数のみが必要であることがわかります。これは、剰余に対する BFS のような緩和を使用して計算できます。 

より効率的な再定式化では、すべてのエッジの重みが 1 であるという事実を利用するため、長さによる最短パスが重要になりますが、g を法とする距離を考慮します。 1 からすべてのノードまでの最短距離を計算し、その距離が g とどのように相互作用するかを考慮して、最終的に残る燃料を決定します。 答えは、ノード n に到達するための最小距離 d のみに依存します。なぜなら、経路はサイクルによってのみ長くすることができ、消費量は 1 の倍数で増加しますが、制御された方法で g を法とする剰余構造にのみ影響を与えるからです。 

したがって、1 から n までの最短経路距離 d を計算します。 残りの燃料は g − (d mod g) で、d mod g = 0 の場合、残りは 0 になるという規則に従います。

 ## アルゴリズムのチュートリアル

 1. BFS を使用して、ノード 1 からすべてのノードまでの最短距離を計算します。 各エッジの重みは等しいため、BFS は最小エッジ数を正しく生成します。 この距離は、各ノードに到達するために可能な最小燃料消費量を表します。 
2. d をノード 1 からノード n までの最短距離とします。 これは、有効なルートに沿って消費される最小リットル数です。 
3. d mod g を計算します。 これは、旅行をサイズ g の完全給油ブロックに分割した後、最後の部分タンク セグメントに未使用のまま残されている燃料の量を捕捉します。 
4. d mod g が 0 に等しい場合、タンクは補充境界で正確に終了し、燃料が残っていないことを意味します。 それ以外の場合、残りの燃料は g − (d mod g) です。 

最短経路距離のみが必要な理由は、経路が長くなると燃料消費量が増加するだけであり、余分な迂回を行っても、最短距離ですでに決定されている値を超えて残りの燃料を減らす方法で残りを改善することはできないためです。 サイクルを追加すると、距離に 1 の倍数が追加されますが、これによって、すでに提供されている最短距離よりも優れたモジュラー アライメントを作成することはできません。 

### なぜ効果があるのか

 すべての有効なルートは、その合計コストがエッジの長さになる歩行に対応します。 燃料補給プロセスは、その長さをサイズ g のチャンクにどのように分割するかによってのみ異なります。 可能なすべての歩行の中で、最短のパスが総消費量を最小限に抑え、それより長い歩行では合計が整数 k だけ増加します。 残りの燃料は g − (合計 mod g) のみに依存するため、合計を増やしても、すでに達成されている最小可能距離より厳密に優れた残りを生み出すことはできません。 したがって、最短経路距離によって最適な結果が完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, g = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    dist = [-1] * (n + 1)
    q = deque([1])
    dist[1] = 0

    while q:
        u = q.popleft()
        for v in adj[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)

    d = dist[n]
    r = d % g
    if r == 0:
        print(0)
    else:
        print(g - r)

if __name__ == "__main__":
    solve()
```隣接リストには道路ネットワークが格納されているため、BFS は線形時間でグラフを移動できます。 距離配列は、ノード 1 から各ノードまでのエッジの最小数を追跡します。 BFS では、すべてのエッジの重みが等しいため、正確性が保証されます。 

ノード n までの最短距離を計算した後、それを法 g で減らして、現在の燃料ブロック内のどこでトリップが終了するかを決定します。 最後の減算により、この残りがタンク内の残りの燃料に変換されます。 

よくある落とし穴は、さまざまなパスに沿って燃料を明示的にシミュレートしようとすることです。これにより、給油に関するローカルな決定が全体的な最適性に影響を与えると誤って想定されてしまいます。 BFS 削減では、問題を単一のスカラー距離に集約することで、この問題を完全に回避します。

## Edge Cases

A key edge case occurs when the shortest path length is exactly divisible by g. In that situation, the car always arrives with a full or empty tank boundary condition. For example, if the graph is a simple chain of length 4 and g = 2, the BFS distance is 4. The remainder is 0, so no fuel is left to be paid for. The algorithm handles this directly through the modulo check.

Another edge case is when multiple shortest paths exist. Since BFS assigns distances based only on edge count, all shortest paths yield the same d, so tie structure does not affect the outcome. The algorithm remains stable because it never depends on which shortest path is chosen, only on its length.
