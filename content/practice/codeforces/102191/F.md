 ## 解決策
 ## 問題の理解

 配列を連続したサブ配列に分割する必要があります。 各サブ配列はその要素の合計を 1 つの因子として提供し、目的はそれらすべての因子の積を最大化することです。 出力は元の配列です。`/`連続したパーツの間に挿入されます。 

重要な問題は、積が天文学的に大きくなる可能性があるため、このタスクでは最大積を計算する必要がないことです。 これを達成するパーティションを 1 つ復元するだけで済みます。 制約では最大 (3\cdot10^5) 個の要素が許可されるため、(O(n)) または (O(n\log n)) の解決策が適切です。 指数関数的なものは直ちに不可能であり、(O(n^2)) 動的プログラムであっても、最悪の場合、約 (9\cdot10^{10}) 回の反復が必要になります。 

すべての配列値が正であるという事実により、問題は単純な貪欲な構造に崩壊します。 部分が sum (1) を持つ場合、不注意な実装は失敗する可能性があります。 たとえば、```
2
3 1
```正しい出力は```
3 1
```なぜならパーティションは`[3] / [1]`積(3)がある一方で、`[3 1]`製品(4)があります。 現在の合計が少なくとも (2) に達するたびにカットし、最後のシングルトンを盲目的に出力する戦略では、無効な次善のパーティションが生成されます。`[3] / [1]`。 

もう 1 つの境界ケースは、完全に 1 で構成される配列です。 のために```
3
1 1 1
```正しい出力は```
1 1 1
```それよりも`[1 1] / [1]`。 後者には積 (2) があり、単一部分には和 (3) と積 (3) があります。 最後に残った部分は前の部分とマージする必要があります。 

単一要素の配列についても、明示的な考慮が必要です。 のために```
1
1
```要素をマージできる隣接部分がないため、考えられる唯一の答えは単純です。`1`。 

## アプローチ

 ブルートフォース ソリューションでは、考えられるすべてのカット セットを列挙できます。 隣接する要素間には (n-1) 個のギャップがあり、すべてのギャップにカットが含まれる場合と含まれない場合があり、正確に (2^{n-1}) 個のパーティションが得られます。 各パーティションについて、すべての部分の合計とその積を計算し、最適なパーティションを保持できます。 たとえプロダクトが増分的に保守されたとしても、(2^{n-1}) 個のパーティション評価が必要になります。 配列全体をスキャンしてすべてのパーティションを評価する場合、コストは (O(n2^n)) になります。 (n=3\cdot10^5) では、(2^{n-1}) 自体でも実用的な限界を超えています。 

指数関数的な探索を取り除く観察は不等式です。 

[
 xy \ge x+y
 】

 いつでも (x,y\ge2)。 合計が (x) と (y) である 2 つの隣接する部分を考えます。 カットを維持すると積 (xy) が得られ、カットを削除すると (x+y) が得られます。 両方の合計が少なくとも (2) であれば、カットを維持しても答えが悪化することはありません。 

これは、最適なソリューションでは、合計が少なくとも (2) のパーツをできるだけ多く作成する必要があることを意味します。 唯一危険な部分は、合計 (1) の部分です。 すべての配列値は正であるため、合計が (1) の部分は、(1) に等しい 1 つの配列要素で構成されます。 因数 (1) と因数 (x) を (x+1) で置き換えると厳密には積が増加するため、このような部分は隣接する部分が存在する場合は必ず隣接する部分とマージする必要があります。 

残りの問題は、合計が少なくとも (2) になる部分の数を最大化する方法です。 カットできる最も早い場所は、現在の部分が合計 (2) に達する最初の位置です。 ここでの切断は常に安全であり、後続のパーツに可能な限り最大のサフィックスを残します。 これを貪欲に繰り返すことで、可能な限り多くの完成部品が得られます。 スキャンが未使用の 1 つで終了した場合`1`、最後の要素はそれ自体では有効な収益性の高い部分を形成できないため、前の部分にマージされます。 

ブルートフォース手法は、カットのあらゆる可能な配置を明示的に考慮するため機能しますが、そのような配置が指数関数的に多数あるため失敗します。 (xy\ge x+y) についての観察により、製品の検索から有効な部品の数を最大化することに目的が変わります。これは 1 回の左から右のスキャンで実行できます。

 | --- | --- | --- | --- |
 | ブルートフォース | (O(n2^n)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初の配列要素から開始し、現在の部分の開始位置とその累計を維持します。 現在の部分は、合計が少なくとも (2) に達するまで切り取られません。これは、別の要素が存在する場合、合計が (1) の部分は決して役に立たないためです。 
2. アレイを左から右にスキャンします。 累計が少なくとも (2) になるたびに、現在の要素の直後にカットを記録し、新しいパートを開始します。 可能な限り早い位置で切断すると、後で作成できる完全なパーツの数が最大になります。 
3. スキャン後、一部のサフィックスが切り取られていないか確認します。 以前のカットはすべて、合計が (2) に達するとすぐに行われたため、未完成のサフィックスは合計 (1) のみを持つことができます。 すべての値が正であるため、そのサフィックスは、次の最後の要素と同じになります。`1`。 
4. こんな決勝があったら`1`少なくとも 1 つの前の部分が存在する場合は、前のカットを削除し、その前の部分を最後の要素まで拡張します。 これにより、sum-(1) の部分が削除され、それをマージすると積が増加します。 
5. 配列全体が最後の 1 つの要素で構成されている場合、マージはできません。 単一要素のパーティションが唯一可能なパーティションです。 
6. 結果として得られるすべての部分配列を出力します。`/`連続した部分の間。 

### なぜ効果があるのか

 2 つの隣接する部分の和が (x,y\ge2) であると仮定します。 別々にしておいた場合の寄与は (xy) ですが、それらをマージすると (x+y) になります。 以来

 [
 xy-x-y=(x-1)(y-1)-1\ge0、
 】

 それらを分離しても製品が減少することはありません。 したがって、すべての部分の合計が少なくとも (2) になれば、部分の数を最大化するだけで十分です。 

貪欲スキャンでは、常にすべてのパーツに対して可能な限り最も早いエンドポイントが選択されます。 貪欲なエンドポイントに到達する前に、累積合計は (2) を下回るため、有効な部分がそれより早く終了することはできません。 したがって、最初のグリーディ カットは、少なくとも (2) の和の部分に分割する最初のカットよりも後に発生することはできません。 同じ引数を残りのサフィックスに適用すると、後続のすべてのカットで同じ特性が証明されます。 

貪欲スキャンが最終スキャンで終了した場合`1`、その要素は別個の有効な部分を形成できません。 もう 1 つのパートを持つパーティションは、対応する前のカットの後にサフィックスを残す必要がありますが、そのサフィックスにはこの 1 つのみが含まれます。`1`これは、すべての部分の合計が少なくとも (2) であるパー​​ティションでは不可能です。 決勝戦の結合`1`したがって、前の部分を使用するのが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(data: str) -> str:
    it = iter(data.split())
    n = int(next(it))
    a = [int(next(it)) for _ in range(n)]

    cuts = []
    start = 0
    current_sum = 0

    for i, x in enumerate(a):
        current_sum += x

        if current_sum >= 2:
            cuts.append(i)
            start = i + 1
            current_sum = 0

    # If one element remains, it must be a single 1.
    # Merge it into the previous part.
    if start < n:
        if cuts:
            cuts.pop()
            cuts.append(n - 1)
        else:
            cuts.append(n - 1)

    parts = []
    start = 0

    for end in cuts:
        parts.append(" ".join(map(str, a[start:end + 1])))
        start = end + 1

    return " / ".join(parts)

def main():
    data = sys.stdin.read()
    sys.stdout.write(solve(data) + "\n")

if __name__ == "__main__":
    main()
```入力は次のように読み取られます`sys.stdin.read()`テスト ケースが 1 つしかなく、入力全体がメモリに保持できるほど小さいためです。 これにより、(3\cdot10^5) 要素の配列の問題における繰り返しの解析オーバーヘッドも回避されます。 

の`current_sum`変数は現在構築中のパーツの合計を表します。 (2) に達すると、現在のインデックスがカット エンドポイントになります。 すべての値が正であるため、合計が (2) に達すると、パーツをさらに拡張しても、さらにパーツを作成できなくなります。 

の`cuts`list には、完了したすべてのパーツの包括的なエンドポイントが保存されます。 の`start < n`スキャン後、1 つの要素が残りました。 その値は次のとおりである必要があります`1`。 別の部分が存在する場合、最後のカットが削除され、次の部分に置き換えられます。`n - 1`、残った要素を前の部分にマージします。 

以前のカットがないケースは、配列全体が 1 つの最後の要素である場合にのみ発生します。`n = 1`そして`a[0] = 1`。 その場合、単一の要素がすでに唯一の可能なパーティションになります。 

このソリューションでは積がまったく計算されませんが、Python の整数はオーバーフローしません。 実際の最適な積には数百万桁の 10 進数が含まれる可能性があるため、これはここで役立ちます。 この実装では、入力サイズと値によって制限された合計とインデックス操作のみが実行されます。 

出力は完全な部分文字列から構築され、次を使用して結合されます。`" / "`、必要に応じて、各スラッシュの両側にスペースを 1 つだけ入力します。

 ## 特殊なケース

 最低限の入力に関しては`1 / 1`、スキャンは合計 (2) に到達しないため、完了したカットはありません。 残りのサフィックスは配列全体ですが、それをマージする前の部分がありません。 その結果、アルゴリズムは次のように出力します。`1`、これが唯一可能なパーティションです。 

のために`3 / 3 1`、最初の要素はすぐに sum (3) で完全な部分を形成します。 決勝戦`1`スキャン後も残ります。 前の部分があるため、アルゴリズムは後のカットを削除します。`3`そして最後の要素をマージして、`3 1`。 この製品は (4) であり、別個の製品 (3) よりも優れています。 

のために`3 / 1 1 1`、最初の 2 つは合計 (2) に達するため、アルゴリズムは一時的に`[1,1]`。 最後`1`シングルトンとして残ります。 最後のマージにより、パーティションが次のように変更されます。`[1,1,1]`、その因数は (3) です。 代替積 (2\cdot1) の方が小さいため、これが最適です。 

少なくとも (2) のすべての値の配列の場合、すべての要素はすぐに独自の部分を形成できます。 例えば、`4 / 2 2 2 2`になる`2 / 2 / 2 / 2`。 隣接する因子のすべてのペアは (xy\ge x+y) を満たすため、2 つの部分を組み合わせても積を改善できません。 したがって、貪欲パーティションは可能な限り最大のパーツ数を持ち、最適になります。 

(300000) 個の最大サイズの入力の場合、すべてのペアが合計 (2) に達するため、スキャンは 150000 個のパーツを作成し、残り物なく終了します。 このアルゴリズムは、配列要素ごとに定数時間の決定を 1 つだけ実行し、積の計算を必要としないため、大きな入力がすべて 1 の小さな例と同じように動作します。
