 ## 問題の理解

 移動文字列は、ある初期セルから始まる無限整数グリッド上のウォークを記述します。 各文字は、現在のセルを 4 つの基本方向のいずれかに 1 単位ずつ変更します。 対応するウォークが同じセルを 2 回占有することのない、移動文字列の最も長い連続部分が必要です。 

選択した部分文字列の開始セルは、訪問されたセルとしてカウントされます。 次のような部分文字列があるため、この詳細は重要です。`RL`最初に右に移動し、すぐに開始セルに戻るため、無効です。 

ウォークを表す便利な方法は、接頭辞の位置を使用することです。 P i を最初の i の移動後に到達するセルとし、P 0 を開始セルとします。 move l から move r までの部分文字列は、正確にその位置を訪問します。 

P l−1 ,P l ,…,P r .

 したがって、これらの接頭辞の位置がすべて異なる場合、部分文字列は正確に有効になります。 元の移動問題は、今ではおなじみの配列問題になりました。つまり、重複する値を含まないプレフィックス位置の連続する最長範囲を見つけます。 

長さは 10 6 に達する可能性があります。O(n 2 ) アルゴリズムでは、最悪の場合でもすでに約 5⋅10 11 回の反復が必要となり、1.5 秒の制限時間の許容範囲をはるかに超えています。 線形時間または線形時間に近い方法が必要です。 256 MB というメモリ制限は、Python オブジェクトの大規模なコレクションを不用意に保存すると問題が発生する可能性があることも意味するため、実装では座標タプルを保存するのではなく、コンパクトな座標表現を使用する必要があります。 

誤答を引き起こしやすい特殊なケースがいくつかあります。 のために`R`、訪問されるセルは開始セルとそのすぐ右のセルのみであるため、答えは次のようになります。`1`。```
1R
```正しい出力は次のとおりです`1`。 移動ではなく訪問したセルをカウントする不注意な実装により、次のような出力が出力される可能性があります。`2`、必要な答えは手数です。 

のために`RL`、ヘビは開始セルに戻ります。```
2RL
```正しい出力は次のとおりです`1`。 連続する動きが異なるかどうかだけをチェックするメソッドでは、文字列全体が誤って受け入れられてしまいます。 繰り返されるセルは数回の移動によって分離される可能性があるため、単に方向ではなく位置を追跡する必要があります。 

のために`RULD`、最後の移動は最初のセルに戻ります。```
4RULD
```正しい出力は次のとおりです`3`。 完全なウォークには開始位置が 2 回含まれていますが、最初の 3 つの動きが有効なウォークを形成します。 アルゴリズムは、以前に表示されたものをすべて破棄するのではなく、現在のウィンドウを縮小する必要があります。 

もう 1 つの微妙なケースは、以前の出現位置がすでに現在のウィンドウの外側にある場合です。 たとえば、次のように考えてみましょう`RRLR`。 プレフィックスの位置は 0、1、2、1、2 です。 2番目のとき`1`と表示される場合は、有効なウィンドウを古いウィンドウを超えて移動する必要があります。`1`。 後で、いつ`2`繰り返しますが、重要なのは現在のウィンドウだけです。 スライディング ウィンドウでよくある間違いは、左側の境界を直接に割り当てることです。`last[position] + 1`、境界を後方に移動できます。 境界は前方にのみ移動する必要があります。 

## アプローチ

 直接的なアプローチは、可能なすべての開始位置を選択し、部分文字列を一度に 1 移動ずつ拡張することです。 拡張中、現在の座標と既に訪問したセルのセットを維持します。 次のセルがすでにセット内にある場合、部分文字列を拡張することはできません。 それ以外の場合は、それを挿入して回答を更新します。 これは正しいです。開始位置ごとに、そこから始まるサフィックスの最長有効なプレフィックスが明示的に検索されるからです。 

問題は繰り返し作業の量です。 次のような入力の場合`RRRR...R`、すべての開始位置から最後まで有効な部分文字列が生成されます。 アルゴリズムが調べます

 n+(n−1)+⋯+1= 2 n(n+1)

 これは、n=10 6 の場合、500000500000 です。これは、集合演算を考慮する前でさえ、すでに大きすぎます。 

ブルート フォースが機能するのは、各開始点のセルのセットを独立して維持するためですが、開始点が変更されるたびに情報が破棄されます。 重要な点は、すべての部分文字列が同じ接頭辞位置配列の連続した範囲に対応していることです。 重複のないプレフィックス位置の 1 つのウィンドウを維持する場合、重複が現れたときに、その位置の以前の出現を削除するのに十分なだけ左側の境界を移動するだけで済みます。 

現在のプレフィックス位置 P i がインデックス j で最後に見られたと仮定します。 現在の有効なウィンドウが L で始まる場合、j≥L のときに正確に重複が発生します。 新しいウィンドウは j の後に開始する必要があるため、次のように設定します。 

L=max(L,j+1)。 

j<L の場合、古いオカレンスはすでに現在のウィンドウの外にあり、何も変更する必要はありません。 各プレフィックス位置は 1 回処理され、左側の境界は前方にのみ移動し、O(n) の解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n 2 ) | O(n) | 遅すぎる |
 | 最適 | O(n) が予想されます | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 開始セルをプレフィックス位置 P 0 =(0,0) として表します。 移動するたびに、現在の座標を更新して次のプレフィックス位置を取得します。 
2. 位置がすべて異なるプレフィックス インデックス [L,i] のスライディング ウィンドウを維持します。 対応する移動部分文字列は、移動 L+1,…,i で構成されるため、長さは i−L になります。 
3. すべての座標を訪問した最新のプレフィックス インデックスを保存します。 P i が生成されると、その前のインデックス j を検索します。 
4. j≧L の場合、現在位置はウィンドウ内にあるため、ウィンドウは無効になります。 左側の境界を j+1 に移動します。 私たちが使用するのは`max`なぜなら、左側の境界は決して後方に移動することができないからです。 
5. 記録`i`現在の位置の最新の位置として。 今後の発生では現在のインデックスを知る必要があるため、これは新しい境界を決定した後に行う必要があります。 
6. 現在のウィンドウには以下が含まれています`i-L+1`異なるプレフィックス位置。これは以下に対応します。`i-L`動きます。 答えを更新してください`i-L`。 

これが機能する理由: すべての反復で、 P L から P i までのすべてのプレフィックス位置が異なることが不変です。 新しい位置がこのウィンドウ内で以前に出現していない場合、不変条件は true のままです。 j に出現がある場合、i で終わる有効なウィンドウはすべて j の後に開始する必要があるため、L を j+1 に移動するだけで十分です。 i で終わるすべての有効な部分文字列は、i で終わる重複のないウィンドウで表す必要があるため、そのような最大のウィンドウがそのエンドポイントに対して最良の答えを与えます。 したがって、すべてのエンドポイントの最大値を取ると、グローバルに最も長い有効な部分文字列が得られます。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline

def solve(s):    n = len(s)
    # Encode (x, y) into one integer so that the dictionary    # stores only integer keys instead of coordinate tuples.    base = 2 * n + 3    offset = n + 1
    x = 0    y = 0
    # last[position] = latest prefix index containing this position.    last = {offset * base + offset: 0}
    left = 0    ans = 0
    for i, ch in enumerate(s, 1):        if ch == 'R':            x += 1        elif ch == 'L':            x -= 1        elif ch == 'U':            y += 1        else:            y -= 1
        key = (x + offset) * base + (y + offset)
        previous = last.get(key)        if previous is not None and previous >= left:            left = previous + 1
```の`solve`関数はウォークスルーとまったく同じように動きを処理します。`x`そして`y`現在のプレフィックス位置を保存します。`i`はそのプレフィックスインデックスです。 

n 回の移動しかないため、座標は -n と n の間にあります。 表現```
Pythonkey = (x + offset) * base + (y + offset)
```可能なすべての座標ペアを一意の整数にマップします。 辞書キーとして 1 つの整数を使用すると、訪問したセルごとに 2 要素のタプルを使用するよりもメモリ効率が大幅に向上します。これは、n が 10 6 と大きい場合に重要になります。 

初期位置はインデックスを使用して挿入する必要があります`0`。 これがなければ、開始セルに戻るパスは検出されません。 まさにこれが理由です`RL`答えがあるはずだ`1`それよりも`2`。 

条件`previous >= left`これも重要な境界チェックです。 現在のウィンドウの前に以前に発生したことがあっても、現在のウィンドウは無効になりません。 書き込み`left = previous + 1`無条件にウィンドウを誤って後方に移動させます。 

答えは`i - left`、 ない`i - left + 1`。 ウィンドウにはプレフィックス位置 L から i が含まれていますが、位置よりも移動が 1 つ少なくなります。 Python の整数はオーバーフローしないため、座標のエンコードや答えに特別な処理は必要ありません。

def solve(s):    n = len(s)    base = 2 * n + 3    offset = n + 1
    x = 0    y = 0
    last = {offset * base + offset: 0}
    left = 0    ans = 0

 ## 特殊なケース

 最低限の入力に関しては`1 / R`、アルゴリズムはプレフィックス位置から始まります`(0,0)`。 後`R`、届きます`(1,0)`、これまで登場していませんでした。 窓は`[0,1]`、2 つの異なるポジションが含まれるため、1 つの手が含まれます。 出力は`1`。 

のために`RL`、接頭辞の位置は次のとおりです。`(0,0)`、`(1,0)`、 そして`(0,0)`。 最終的な位置が生成されるとき、その前のインデックスは次のとおりです。`0`、で始まる現在のウィンドウ内にあります。`0`。 アルゴリズムが変わる`left`に`1`、接頭辞の位置を残す`1`そして`2`。 それは単一の有効な手を表します`L`したがって、出力は次のようになります`1`。 

のために`RULD`、4手目は到達します`(0,0)`、その前の出現はインデックスにあります`0`。 左側の境界は次のように変化します。`0`に`1`、有効な 3 移動部分文字列を残します。`ULD`。 答えはもう出ていた`3`したがって、開始セルが繰り返されても、アルゴリズムが以前の最良の部分文字列を失うことはありません。 

のために`RRLR`、接頭辞の位置は次のとおりです。`(0,0)`、`(1,0)`、`(2,0)`、`(1,0)`、`(2,0)`。 インデックス時`3`、`(1,0)`最後にインデックスで見られた`1`、 それで`left`になる`2`。 インデックス時`4`、`(2,0)`最後にインデックスで見られた`2`、これはまさに現在の左側の境界であるため、`left`になる`3`。 最大のウィンドウには長さがありました`2`、最初の 2 つの動きに対応`RR`、出力は次のようになります`2`。 このケースでは特に次のことを確認します`left`必要なところまでのみ進められます。 

100万で構成される最大サイズの入力の場合`R`文字の場合、移動するたびに X 座標が 1 ずつ増加するため、接頭辞の位置はすべて異なります。 重複が見つからないため、`left`残る`0`そして答えは次のようになります`1000000`。 このアルゴリズムは文字ごとに 1 回の反復を実行します。これは、O(n) アプローチでは上限を処理できるのに、二次アプローチでは処理できない理由を示しています。
