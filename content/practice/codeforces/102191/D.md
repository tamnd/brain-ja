 ## 解決策
 ## 問題の理解

 私たちの生徒の数は偶数で、生徒 2 人ごとに友情ペアとして結ばれます。 最後の行はバイトニックである必要があります。高さは、一部のプレフィックスについては同じまままたは増加し、その後は同じまままたは減少する可能性があります。 1 つのペアに属する 2 人の生徒は連続した位置を占めなければなりませんが、ペア内のどちらの順序でも許可されます。 

各友情ペアについて、その 2 つの高さを内部的にソートし、間隔として表します。`[l, r]`、 どこ`l`背が低い学生であり、`r`背の高い学生です。 タスクは、結果として得られるシーケンスがバイトニックになるように、これらの間隔を順序付けし、その方向を選択することです。 

重要な観察は、有効な画像を 2 つの独立した間隔のチェーンとして見ることができるということです。 1 つのチェーンが増加側に配置され、各間隔は次のように記述されます。`l, r`。 もう一方のチェーンは減少側に配置され、間隔は逆の順序で取られ、次のように記述されます。`r, l`。 

最初のインターバルが 2 番目のインターバルの開始前に終了する場合、2 つのインターバルは同じチェーンに属することができます。 のために`[l1, r1]`に続く`[l2, r2]`、 これはつまり`r1 <= l2`。 画像は非減少または非増加であり、厳密には単調ではないため、平等が許可されます。 

制約`n <= 3 * 10^5`せいぜい与える`150000`友情のペア。 二次アルゴリズムはすでに約`2.25 * 10^10`最悪の場合のペア比較。これは 2 秒の制限には多すぎます。 必要なのは`O(n log n)`ソリューション。対数係数はソートから得られます。 

見落としやすい境界ケースがいくつかあります。 まず、ただ触れ合うだけの間隔が相性が良い。 例えば、```
3
1 3
3 5
5 7
```生産できる`1 3 3 5 5 7`隣接する高さが等しいことが許可されるためです。 を使用した不注意な実装`r < l`誤って拒否してしまうでしょう。 

第二に、高さが同じであっても特別な問題は生じません。 のために```
4
3 3
3 3
```答え`3 3 3 3`有効です。 すべての間隔が正の長さであると仮定するコードは、不必要に失敗します。 

第三に、相互に重なり合う 3 つのペアを 2 つのモノトーン面だけに入れることはできません。 例えば、```
6
1 10
2 9
3 8
```すべてのペアが他のすべてのペアと重複するため、これは不可能です。 貪欲なアルゴリズムは、処理時に利用可能な両方のチェーンがブロックされていることを検出する必要があります。`[3, 8]`。 

## アプローチ

 ブルートフォースアプローチでは、すべての友情ペアをブロックとして扱い、すべての組み合わせを試みます。`n/2`ブロックを作成し、ブロックごとに両方の方向を試みます。 がある`(n/2)! * 2^(n/2)`ブロックの可能な配置とその方向。 1 つの取り決めを確認するには時間がかかります`O(n)`時間なので、最悪の場合の合計作業量は次のようになります。`O(n * (n/2)! * 2^(n/2))`。 最大入力サイズでは、これはおおよその意味です`300000 * 150000! * 2^150000`身長の比較は全く不可能です。 

ブルートフォースが機能するのは、増加部分と減少部分の間のあらゆる可能な分割を明示的に調査するためです。 可能なブロック注文の数が階乗的に増加するため、失敗します。 

有用な構造的観察は、実際には最初にピークを決定する必要がないということです。 すべてのペアが間隔として書き込まれると、`[l, r]`、増加側にいくつかのペアを置くことを検討してください。 それらの間隔は、重なり合うことなく左から右に表示される必要があるため、次の条件を満たすチェーンが形成されます。`r_previous <= l_current`。 減少する側をピークから終わりに向かって読むと、まったく同じことが当てはまります。 

したがって、問題全体は次のようになります。すべての間隔を最大 2 つの重複しないチェーンに分割します。 

このようなパーティションが見つかった後、1 つのチェーンが`[l1, r1], [l2, r2], ...`と`r1 <= l2 <= ...`。 直接書いて、`l1, r1, l2, r2, ...`それは減少しないことです。 

もう一方のチェーンについては、その間隔が昇順で次のようになっていると仮定します。`[a1, b1], [a2, b2], ...`。 

チェーンを逆にして、すべてのペアを逆にして、`b_k, a_k, ..., b2, a2, b1, a1`。 

そのシーケンスは増加しません。 2 つのチェーン間の境界では、1 つの値の後に別の値が続きます。 左側の値が小さい場合、ピークは右側にあります。 それが大きい場合、ピークは左側にあります。 いずれにしても、完全なシーケンスはバイトニックです。 

残りの問題は、間隔を 2 つのチェーンに効率的に分割することです。 左側のエンドポイントで並べ替えます。 インターバルの処理中`[l, r]`、各チェーンは、最後の間隔の右端点によって表されます。 チェーンは、最後の右のエンドポイントが最大でも次の場合に使用できます。`l`。 

両方のチェーンが利用可能な場合は、最後の右端点が大きい方のチェーンに新しい間隔を入れます。 これにより、将来の間隔のために小さいエンドポイントを持つチェーンが保存され、将来の間隔に最大限の柔軟性が与えられます。 利用可能なチェーンが 1 つだけの場合は、それを使用する必要があります。 どちらのチェーンも使用できない場合は、現在位置で 3 つの区間が重なっているため、2 つのチェーンでは不足し、答えが存在しません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(n * (n/2)! * 2^(n/2))`|`O(n)`| 遅すぎる |
 | 最適 |`O(n log n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての友情ペアを間隔に変換します`[l, r]`と`l <= r`。 2 人の生徒の元の順序は無関係であるため、チェーンを構築する際には身長の低い方と高い方のみが問題になります。 
2. すべての間隔を昇順に並べ替えます。`l`を使用して`r`必要に応じて二次キーとして使用します。 これは、次のようなときを意味します。`[l, r]`が処理されると、同じチェーン内でそれに先行するすべての間隔がすでに考慮されています。 
3. 2 つのチェーンを維持します。 各チェーンについて、その最後の間隔の右のエンドポイントを保存します。 どちらのチェーンも最初の間隔を受け入れることができるため、最初は両方のエンドポイントが負の無限大になります。 
4. 現在の間隔について`[l, r]`、どのチェーンが満たしているかを確認してください`last_right <= l`。 このようなチェーンは、単調性を壊すことなく安全に間隔を追加できます。 
5. 両方のチェーンが利用可能な場合は、大きい方のチェーンを選択します。`last_right`。 The smaller endpoint is more useful for future intervals, so keeping it unchanged gives the remaining intervals more room to fit.
 6. If exactly one chain is available, append the interval there. There is no useful alternative because placing it in the other chain would immediately create an overlap.
 7. どちらのチェーンも使用できない場合は、戻ります`-1`。 Both chains already end after`l`, そのため、現在の間隔は各チェーンの間隔と重複します。 3 つの重複する間隔には 3 つのチェーンが必要ですが、有効な画像ではピークの両側のみが提供されます。 
8. 各チェーンに割り当てられた間隔インデックスを保存します。 すべての間隔が割り当てられたら、ソートされた順序で最初のチェーンを次のように出力します。`l, r`間隔ごとに。 
9. 2 番目のチェーンを逆の順序で出力し、各間隔を次のように書き込みます。`r, l`。 その高さは、画像の端に向かって減少します。 
10. 2 つのシーケンスを連結します。 各友情ペアは隣接したままで、最初の部分は減少せず、2 番目の部分は増加しません。 

### なぜ効果があるのか

 不変条件は、間隔のプレフィックスを処理した後、次の条件でソートされることです。`l`、維持される各チェーンは有効な重複しないチェーンであり、すべての貪欲な選択の中で、アルゴリズムは可能な限り最小の利用可能なチェーン エンドポイントを保存します。 両方のチェーンが間隔を受け入れることができる場合、大きい方のエンドポイントを持つチェーンにその間隔を割り当てると、小さい方のエンドポイントはそのまま残り、将来の間隔の配置が容易になるだけです。 どちらのチェーンも間隔を受け入れることができない場合は、考えられるすべての 2 チェーン パーティションに、すでに間隔が延長されている必要があります。`l`両方のチェーンにあるため、現在の間隔をどこにも割り当てることはできません。 したがって、貪欲な手順は、2 チェーン パーティションが存在する場合に正確に成功します。 

2 チェーン パーティションも、まさに有効な画像に必要なものです。 増加側を左から右に読み取ると、1 つの重複しない間隔チェーンが得られ、減少側をピークから外側に読み取ると、別のチェーンが得られます。 逆に、そのような 2 つのチェーンは、一方を前方に書き込み、もう一方を後方に書き込むことで、いつでも 1 つのビットニック シーケンスに結合できます。 それらの間の境界は増加し続けるか、減少し始める可能性があるため、2 つの位置のいずれかが必ず有効なピークになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    m = n // 2

    pairs = []
    for idx in range(m):
        a, b = map(int, input().split())
        if a <= b:
            pairs.append((a, b, idx))
        else:
            pairs.append((b, a, idx))

    pairs.sort()

    chains = [[], []]
    last = [-1, -1]

    for l, r, idx in pairs:
        can0 = last[0] <= l
        can1 = last[1] <= l

        if not can0 and not can1:
            print(-1)
            return

        if can0 and can1:
            if last[0] >= last[1]:
                c = 0
            else:
                c = 1
        elif can0:
            c = 0
        else:
            c = 1

        chains[c].append((l, r))
        last[c] = r

    ans = []

    for l, r in chains[0]:
        ans.append(l)
        ans.append(r)

    for l, r in reversed(chains[1]):
        ans.append(r)
        ans.append(l)

    print(*ans)

if __name__ == "__main__":
    solve()
```入力ループはまず、各友情ペアを正規化します。 出力では生徒の ID ではなく身長のみが要求されるため、元のペアのインデックスを保持する必要はありません。 

並べ替えた後、`last[0]`そして`last[1]`は、2 つのチェーンの最終間隔の右端点です。 条件`last[c] <= l`まさに非重複条件です。 の使用`<=`、 それよりも`<`、次のような接触間隔を処理します。`[1, 3]`そして`[3, 5]`。 

両方のチェーンが利用可能な場合、比較すると`last[0]`そして`last[1]`大きい方のエンドポイントを選択します。 これは、後の間隔のために小さいエンドポイントを保存する貪欲な選択です。 割り当ては実際の正規化された間隔として保存されるため、再構成ではソートされた入力を参照する必要はありません。 

最初のチェーンは直接放出されます。 その間隔は左の端点によって並べ替えられ、ペアごとに重複しないため、その順序は減少しません。 2 番目のチェーンは後方にトラバースされ、すべてのペアが高いものから低いものとして出力されます。 これにより、その部分全体が増加しなくなります。 

Python の整数には任意の精度があるため、高さの制限は`10^9`特別な整数の処理は必要ありません。 

## 実用的な例

 提供されたサンプルの正規化された間隔は次のとおりです。`[1, 3]`、`[2, 4]`、`[6, 7]`、 そして`[5, 7]`。 これらは、左側のエンドポイントによってすでにソートされています。 

| 間隔 | チェーン 0 の終わり | チェーン 1 の端 | 選択されたチェーン |
 | --- | --- | --- | --- |
 |`[1, 3]`|`-1`|`-1`| 0 |
 |`[2, 4]`|`3`|`-1`| 1 |
 |`[5, 7]`|`3`|`4`| 1 |
 |`[6, 7]`|`3`|`7`| 0 |

 最初のチェーンは次のようになります`[[1,3], [6,7]]`、生産`1 3 6 7`。 2番目は次のようになります`[[2,4], [5,7]]`; それを反転し、各ペアを反転すると、`7 5 4 2`。 組み合わせた配列は、`1 3 6 7 7 5 4 2`、これは有効な答えです。 サンプル出力では別の有効なパーティションが使用されていますが、同様に許容されます。 

2 番目の例については、次のように考えます。```
6
1 3
3 5
5 7
```間隔はすでに重複していないため、貪欲なアルゴリズムは 3 つすべてを 1 つのチェーンに維持できます。 

| 間隔 | チェーン 0 の終わり | チェーン 1 の端 | 選択されたチェーン |
 | --- | --- | --- | --- |
 |`[1,3]`|`-1`|`-1`| 0 |
 |`[3,5]`|`3`|`-1`| 0 |
 |`[5,7]`|`5`|`-1`| 0 |

 結果は`1 3 3 5 5 7`。 すべてのペアは隣接したままであり、シーケンスは減少しません。 等価性チェックは、接触しているエンドポイントを有効にするものです。 

ありえないケースとしては、```
6
1 10
2 9
3 8
```トレースは次のとおりです。 

| 間隔 | チェーン 0 の終わり | チェーン 1 の端 | 選択されたチェーン |
 | --- | --- | --- | --- |
 |`[1,10]`|`-1`|`-1`| 0 |
 |`[2,9]`|`10`|`-1`| 1 |
 |`[3,8]`|`10`|`9`| なし |

 で`[3,8]`、以前の両方の間隔が超えています`3`, そのため、どのチェーンも受け付けることができません。 アルゴリズムは出力します`-1`。

## テストケース

 以下のテスト ハーネスは、関数インターフェイスを通じて同じアルゴリズムを使用し、1 つの固定された配置と比較するのではなく、返された配置を検証します。 この問題は有効な画像を受け入れるため、これが必要です。```python
# helper: run solution on input string, return output string
import sys
import io

def solve_data(inp: str) -> str:
    data = inp.split()
    it = iter(data)

    n = int(next(it))
    m = n // 2

    pairs = []
    for idx in range(m):
        a = int(next(it))
        b = int(next(it))
        if a <= b:
            pairs.append((a, b, idx))
        else:
            pairs.append((b, a, idx))

    pairs.sort()

    chains = [[], []]
    last = [-1, -1]

    for l, r, idx in pairs:
        can0 = last[0] <= l
        can1 = last[1] <= l

        if not can0 and not can1:
            return "-1\n"

        if can0 and can1:
            c = 0 if last[0] >= last[1] else 1
        elif can0:
            c = 0
        else:
            c = 1

        chains[c].append((l, r))
        last[c] = r

    ans = []

    for l, r in chains[0]:
        ans.extend((l, r))

    for l, r in reversed(chains[1]):
        ans.extend((r, l))

    return " ".join(map(str, ans)) + "\n"

def run(inp: str) -> str:
    return solve_data(inp)

def valid_output(inp: str, out: str) -> bool:
    tokens = inp.split()
    n = int(tokens[0])
    vals = list(map(int, tokens[1:]))

    if out.strip() == "-1":
        return False

    ans = list(map(int, out.split()))
    if len(ans) != n:
        return False

    # Check that every input pair appears as adjacent heights.
    pairs = []
    for i in range(n // 2):
        a = vals[2 * i]
        b = vals[2 * i + 1]
        pairs.append(tuple(sorted((a, b))))

    used = [False] * (n // 2)
    for i in range(0, n, 2):
        p = tuple(sorted((ans[i], ans[i + 1])))
        found = False
        for j, q in enumerate(pairs):
            if not used[j] and p == q:
                used[j] = True
                found = True
                break
        if not found:
            return False

    # Check bitonicity.
    direction = 1
    for i in range(1, n):
        if direction == 1:
            if ans[i] < ans[i - 1]:
                direction = -1
        else:
            if ans[i] > ans[i - 1]:
                return False

    return True

3 3
3 3
```すべての間隔は`[3,3]`。 各間隔はどちらのチェーンにも追加できます。`3 <= 3`。 貪欲なプロシージャはそれらを利用可能なチェーンに配置し続け、結果として得られるシーケンスは完全に次のもので構成されます。`3`s. 増加条件と減少条件の両方が同時に成立します。 

タッチ間隔については、```
6
1 3
3 5
5 7
```最初の間隔は次で終了します`3`、これはまさに 2 番目の左端点です。 条件`last_right <= l`がそれを受け入れるので、間隔は 1 つのチェーンを形成します。 生成されたシーケンスは、`1 3 3 5 5 7`、厳密な不等式がなぜ正しくないのかを示しています。 

無理なケースに関しては、```
6
1 10
2 9
3 8
```最初のペアはチェーン 0 を占有し、それにエンドポイントを与えます`10`。 2 番目のペアはチェーン 0 に適合しません。`10 > 2`したがって、チェーン 1 に移動し、エンドポイントを与えます。`9`。 いつ`[3,8]`が到着し、両方のエンドポイントが`3`。 どちらのチェーンもそれを受け入れることができないため、アルゴリズムは正しく出力します`-1`。 

最大サイズの場合、すべて`150000`間隔は互いに素であり、左側の端点によって並べ替えられます。 貪欲なパスはそれらを 1 つのチェーンに割り当て、最終的な構築ではすべてのチェーンが生成されます。`300000`有効なモノトーンシーケンスの高さ。 コストがかかる部分は並べ替えであり、それには時間がかかります`O(n log n)`、構造自体は直線的ですが。
