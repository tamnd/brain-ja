 ## 解決策
 ## 問題の理解

 私たちは持っています`n`輪になって座っている生徒たち。 入力順列により現在の循環順序が与えられるため、配列内のすべての連続するペアに加えて、最後の生徒と最初の生徒も近傍になります。 

すべての新しい隣接ペアが古い配置では非隣接となるように、まったく同じ生徒の別の循環順序を作成する必要があります。 学生は次の順列で表されるため、`1..n`、既存の配列要素の順序を変更するだけで済みます。 

重要な問題は円形の境界です。 新しい注文の場合、`b[0], b[1], ..., b[n-1]`、すべてのペアをチェックする必要があります`b[i], b[i+1]`そしてまた`b[n-1], b[0]`。 線形部分では機能するが、誤って古い最初と最後の隣接部分を一緒にしてしまう構造は無効です。 

バウンド`n <= 3 * 10^5`多くの順列を試行したり、コストのかかる検索を繰り返し実行したりするものはすべて除外されます。 アン`O(n^2)`このメソッドにはすでに約が必要です`9 * 10^10`基本的なペアのチェックは、1 秒の制限をはるかに超える最大サイズで行われます。 すべての生徒を一定回数だけ処理する構造が必要です。`O(n)`時間。 

単純なパターンでは誤って処理される可能性がある、特に小さなケースが 3 つあります。 のために`n = 3`たとえば、入力`1 2 3`元の円内ですべてのペアが隣接しているため、新しい円は存在せず、正しい出力は次のようになります。`-1`。 のために`n = 4`、入力`1 2 3 4`これも不可能です。各生徒には隣接しない可能性のある生徒が 1 人だけ、つまり向かい側の生徒しかいないため、許可されるグラフは 2 つの切断されたエッジで構成され、円を形成することはできません。 正しい出力は再び`-1`。 

もう 1 つの簡単な間違いは、円形の閉じペアを忘れることです。 のために`n = 5`入力あり`1 2 3 4 5`、アレンジメント`1 3 5 2 4`有効です。 元の位置での連続した差は、最後のペアを含め、すべて 2 のモジュロ 5 です。`4,1`。 出力された配列内の隣接する要素のみをチェックする構成では、この最終条件を見逃す可能性があります。 

## アプローチ

 最も直接的なアプローチは、条件を満たすまで生徒の順列を試みることです。 すべての順列をチェックインできます`O(n)`時間はちょうどあるので`n`検査する循環隣接ペア。 がある`n!`順列があるため、徹底的な検索には時間がかかります`O(n * n!)`最悪の場合の運用。 最大制約では、これはおおよその意味になります。`300000 * 300000!`ペアチェックですが、リモートでは実行できません。 

有益な観察は、実際の学生 ID は重要ではないということです。 重要なのは、古いサークル内での各生徒の立場です。 二人の学生は、彼らの以前の立場が異なる場合にのみ禁止されます。`1`モジュロ`n`。 したがって、最初に古い位置の順列を構築し、次にそれらの位置を使用して学生 ID を取得できます。 

禁止された隣り合うものを分離する非常に自然な方法は、最初にすべての偶数の位置を取得し、その後ですべての奇数の位置を取得することです。 各グループ内では、連続する位置が 2 つずつ異なるため、自動的に安全になります。 奇数の場合`n`、2 つのグループ間の遷移と位置 0 に戻る最後の遷移にも 2 を法とする差があります。`n`, そのため、すぐに工事が始まります。 

偶数の場合`n`、同じ構造には問題のある円形エッジが 1 つあります。 最後の 2 つの奇数の位置を交換すると、他の場所では安全な違いを維持しながら、その問題が正確に修正されます。 これにより、一定時間の決定と線形構造が得られます。 

構造もその理由をすぐに説明します`n < 5`不可能です。 のために`n = 3`そして`n = 4`、元のサイクルの補数にはハミルトニアン サイクルが含まれません。 から始まる`n = 5`、パリティ構造は明示的に 1 を与えます。

 | ブルートフォース |`O(n * n!)`|`O(n)`| 遅すぎる |
 | 最適な施工 |`O(n)`|`O(n)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 古い循環配置を読み込む`a`。 構築はポジションのパリティに基づいているため、ゼロベースのポジションで作業します。 
2. もし`n < 5`、印刷`-1`。 3 人の生徒の場合、すべてのペアはすでに隣接しており、4 人の生徒の場合、反対側の生徒を接続する唯一の許可されたエッジがあり、全員を含む 1 つのサイクルを形成することはできません。 
3. ポジションを取って新しいシーケンスを構築する`0, 2, 4, ...`最初に、次にポジション`1, 3, 5, ...`。 同じパリティの位置を意図的に分離しているのは、それらの元の循環距離が 1 ではなく 2 であるためです。 
4. もし`n`奇数である場合は、そのシーケンスを変更しないでください。 偶数位置セクションには 2 の差があり、奇数位置セクションにも 2 の差があり、最後の偶数位置から最初の奇数位置への移行には循環距離 2 があり、位置 0 に戻る最後の奇数位置にも循環距離 2 があります。 
5. もし`n`が偶数の場合、構築されたシーケンスの最後の 2 つの要素を交換します。 スワップ前の唯一の危険なエッジは、最後の奇数位置からの循環接続です。`n - 1`位置ゼロに戻ります。 交換後、最後の 2 つのポジションは次のようになります。`n - 1, n - 3`、新しい境界は次のとおりです。`n - 3`距離が 3 のゼロまで。 影響を受けるもう一方のエッジの距離は 2 であるため、両方とも有効になります。 
6. の対応するエントリを使用して、構築された位置を学生 ID に変換し直します。`a`を作成し、結果として得られる循環順序で印刷します。 

### なぜ効果があるのか

 不変条件は、構築された順序内の連続する位置の各ペアが 1 以外の元の円周距離を持つということです。 奇数の場合`n`、そのような距離はすべて 2 です。 偶数の場合`n`、通常の同一パリティ遷移の距離は 2、2 つのパリティ グループ間の遷移の距離は 3、スワップされたペアの距離は 2、ゼロに戻る最後の遷移の距離は 3 です。 古い隣接ペアは円周距離 1 によって正確に特徴付けられるため、これらの新しいペアはいずれも以前は隣接していませんでした。 元の位置はすべて 1 回だけ出現するため、結果もすべての生徒の順列になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if n < 5:
        print(-1)
        return

    ans = []

    for i in range(0, n, 2):
        ans.append(a[i])

    for i in range(1, n, 2):
        ans.append(a[i])

    if n % 2 == 0:
        ans[-1], ans[-2] = ans[-2], ans[-1]

    print(*ans)

if __name__ == "__main__":
    solve()
```最初のループは、ゼロから始まるすべての偶数の位置を収集します。 2 番目のループでは、奇数の位置をすべて収集します。 これらにはすべての学生が 1 回だけ含まれるため、別の訪問配列は必要ありません。 

奇数の場合`n`、順序はすでに正しいです。 偶数の場合`n`、`ans[-1]`そして`ans[-2]`は最後の 2 つの奇数位置の生徒であるため、これらを交換することは、構築で説明されている調整とまったく同じです。 

より大きい値を含む算術はありません。`n`、Python の整数にはオーバーフローの問題はありません。 クリティカル境界は構築によって暗黙的に表されるため、別個の検証パスは必要ありません。 特に、スワップは循環シーケンスの終わりを変更するため、両方のパリティ グループが追加された後に実行する必要があります。 

このソリューションでは、学生 ID と役職を区別する必要はありません。 以来`a`は順列であるため、ポジションの有効な順序はすぐに学生の有効な順序になります。

## テストケース

 出力は一意ではないため、生成された配置が順列であること、およびすべての新しい循環隣接ペアが古い循環隣接ペアではないことをテストで検証する必要があります。 出力を 1 つの固定された有効なシーケンスと比較すると、他の正しいソリューションが誤って拒否されてしまいます。 

この問題により、入力が順列であることが保証されます。 したがって、次のような「すべて等しい値」テストが行​​われます。`5 / 1 1 1 1 1`は有効な Codeforces テスト ケースではないため、提出されたソリューション自体のテストには使用しないでください。 問題のあるコントラクトの範囲外にある、不正な入力に対する動作のみをテストできます。```python
import io
import sys

def solve_case(inp: str) -> str:
    data = list(map(int, inp.split()))
    n = data[0]
    a = data[1:]

    if n < 5:
        return "-1"

    ans = []

    for i in range(0, n, 2):
        ans.append(a[i])

    for i in range(1, n, 2):
        ans.append(a[i])

    if n % 2 == 0:
        ans[-1], ans[-2] = ans[-2], ans[-1]

    return " ".join(map(str, ans))

def valid(inp: str, out: str) -> bool:
    data = list(map(int, inp.split()))
    n = data[0]
    a = data[1:]

    result = out.split()

    if n < 5:
        return result == ["-1"]

    if len(result) != n:
        return False

    result = list(map(int, result))

    if sorted(result) != sorted(a):
        return False

    old_pos = {x: i for i, x in enumerate(a)}

    for i in range(n):
        x = old_pos[result[i]]
        y = old_pos[result[(i + 1) % n]]
        diff = (x - y) % n

        if diff == 1 or diff == n - 1:
            return False

    return True

# Provided sample 1
sample1 = """8
6 1 3 5 7 8 4 2
"""
out = solve_case(sample1)
assert valid(sample1, out), "sample 1"

# Provided sample 2
sample2 = """3
1 3 2
"""
assert solve_case(sample2) == "-1", "sample 2"

# Minimum possible n, impossible.
case3 = """4
1 2 3 4
"""
assert solve_case(case3) == "-1", "n=4 must be impossible"

# Smallest possible solvable case.
case4 = """5
1 2 3 4 5
"""
out = solve_case(case4)
assert valid(case4, out), "n=5 construction"

# Even n, catches the special final swap.
case5 = """6
1 2 3 4 5 6
"""
out = solve_case(case5)
assert valid(case5, out), "even n boundary"

# Large valid input, exercising the O(n) construction.
n = 300000
a = list(range(1, n + 1))
case6 = str(n) + "\n" + " ".join(map(str, a)) + "\n"
out = solve_case(case6)
assert valid(case6, out), "maximum n"

 ## 特殊なケース

 のために`n = 3`、 考慮する：```
3
1 3 2
```生徒の各ペアは元のサークル内で隣接しています。 学生`1`隣にあります`3`そして`2`、 学生`3`隣にあります`1`そして`2`と学生`2`隣にあります`3`そして`1`。 新しい円には 3 つの許可されたエッジが必要ですが、それらはありません。 アルゴリズムが検出するのは、`n < 5`すぐに印刷します`-1`。 

のために`n = 4`、 考慮する：```
4
1 2 3 4
```唯一の非隣人`1`は`3`、唯一の非隣人`2`は`4`、その逆も同様です。 したがって、許可されるグラフは次のもののみで構成されます。`1-3`そして`2-4`。 4 頂点サイクルを含めることはできません。 同じく早い段階で`n < 5`正しく印刷されていることを確認してください`-1`。 

解決可能な最小のケースについては、次のことを考慮してください。```
5
1 2 3 4 5
```偶数位置セクションは、`1 3 5`、奇数位置のセクションは`2 4`、与える：```
1 3 5 2 4
```本来のポジションは、`0, 2, 4, 1, 3`。 循環的な違いは次のとおりです。`2, 2, 2, 2, 2`したがって、すべての新しいペアは、古い円内で 2 つの位置離れています。 特に最後のペアは、`4,1`は安全であり、円形境界を適用します。 

偶数の場合`n`特別な調整が必要です。 と：```
6
1 2 3 4 5 6
```パリティ グループ化は最初に次のようになります。```
1 3 5 2 4 6
```決勝戦`6,1`元々隣同士だった生徒達のため、ペアリングは禁止されている。 最後の 2 つの要素を交換すると、次のようになります。```
1 3 5 2 6 4
```昔のポジションは、`0,2,4,1,5,3`。 循環的な違いは次のとおりです。`2,2,3,4,2,3`、どれもそうではありません`1`または`5`。 スワップは、そうでなければ失敗するであろう構築の部分を正確に変更します。 

最大入力サイズについては、同じ構造は学生 ID の値には依存せず、位置のみに依存します。 と`n = 300000`、両方のパリティ ループが一緒に正確に処理します`300000`ポジション、その後 1 回のスワップ。 ネストされたループや繰り返しの検証がないため、許容される最大の入力でも実行時間は線形のままです。
