 ## 解決策
 ## 問題の理解

 から始めます`n`できるだけ多くの友達にキャンディをあげたいと思っています。 1 つのキャンディーを 1 人の友人に与えるのは簡単ですが、2 つ目のキャンディーを友人に与えた後、1 つ残っている場合は自分で 1 つ消費します。 問題は、最適な与える順序を選択したときに、最終的にどれだけのキャンディーが友達に届くかということです。 

入力には単一の整数が含まれています`n`、キャンディーの初期数を表します。 出力は、それぞれが 1 つのキャンディーを受け取ることができる友達の最大数です。 

上限`n <= 10^9`すべてのキャンディーに対して 1 つ以上の操作を実行するアプローチは除外されます。 線形シミュレーションには最大 10 億回の反復が必要ですが、これは、特に事実上 0 秒という制限がある場合、競技プログラミングの制限時間の許容範囲をはるかに超えています。 繰り返し構造を認識し、一定時間内に答えを直接計算する必要があります。 単一の入力値と答えだけが必要なため、メモリ要件はわずかです。 

最小の入力は境界の動作を明らかにします。 のために`n = 1`、正解は`1`, なぜなら、配られるのはキャンディーだけであり、食べるきっかけとなる2番目のキャンディーがないからです。 3 つのグループごとに常に 1 つのキャンディーを減算する式は、この場合も正しく処理する必要があります。 

のために`n = 2`、答えは`2`。 両方のキャンディーを 2 人の友人に渡すことができ、その場合にのみキャンディーを食べる必要がありますが、何も残りません。 すべてのギフトに常に追加のキャンディーがかかると想定する不注意な実装では、誤って返されます。`1`。 

3 の倍数も便利な境界です。 と`n = 6`、キャンディーを 2 つ与えて 1 つ食べ、さらに 2 つキャンディーを与えて最後の 1 つを食べることができます。 答えは`4`、 ない`3`。 食べることは各ペアのプレゼントの後に行われるため、最後に消費されたキャンディーは追加の友達が失われることには対応しません。 

## アプローチ

 直接シミュレーションでは、一度に 1 つのキャンディーのプロセスをモデル化できます。 残りのキャンディーの数とキャンディーを受け取った友達の数を保持します。 別のキャンディーを配るのに十分なキャンディーが手に入ったら、私たちはそれを友達にあげます。 2 つ目のプレゼントごとに、可能であればキャンディーを 1 つ消費します。 このシミュレーションは、問題で説明されているプロセスに正確に従っているので正しいです。また、目標は単にギフトの数を最大化することなので、可能な限りキャンディーを与えることを選択するのが最適です。 

問題は反復回数です。 最悪の場合、シミュレーションは Θ(n) の作業を実行します。これは、およそ最大で次のことを意味します。`10^9`繰り返し。 それは遅すぎます。 

重要な観察は、3 つのオリジナル キャンディーの完全なグループごとに、正確に 2 つのギフトが生成されるということです。 キャンディーを 2 つ友達にプレゼントし、2 つ目をプレゼントした後、キャンディーを 1 つ食べます。 少なくとも 3 つのキャンディーが残っている間、同じパターンを独立して繰り返すことができます。 これは、個々のキャンディーをシミュレートする必要がないことを意味します。 3 つの完全なグループがいくつ存在するかを数えて、最後の 1 つまたは 2 つのキャンディーを個別に処理できます。 

もし`n = 3q + r`、その後、`q`完全なグループが貢献する`2q`友達。 もし`r = 0`、何も残りません。 もし`r = 1`、残りのキャンディーをもう 1 人の友人に与えることができます。 もし`r = 2`, 食事ルールは 2 回目のギフト後にのみ適用され、その後はキャンディーが残らないため、残っている両方のキャンディーを贈ることができます。 

これにより、コンパクトな式が得られます`answer = n - floor(n / 3)`。 

同じ結果はグループ解釈からも理解できます。 キャンディー 3 個ごとに 2 個のキャンディーが友達に届くため、完全なグループごとにちょうど 1 個のキャンディーが事実上食べられなくなります。

 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. キャンディーの数を読み取る`n`。 プロセスは残っているキャンディーの数のみに依存するため、この値のみが必要です。 
2. コンピューティング`n // 3`、3 つのキャンディーの完全なグループの数。 このようなグループごとに、食べるのに 1 個のキャンディーがかかり、友達に 2 個のキャンディーを与えることができます。 
3. 元のキャンディーの数から食べたキャンディーの数を引きます。 結果の値は、`n - n // 3`, フレンドに到達できるキャンディーの最大数です。 
4. 結果を印刷します。 シミュレーションや追加の状態は必要ありません。 

### なぜ効果があるのか

 3 つのキャンディーのすべての完全なブロックを考えてみましょう。 そのうちの 2 つを 2 人の友人に贈り、2 つ目の贈り物の後に 3 つ目を食べることができます。 したがって、3 つのキャンディーからちょうど 2 つの成功したギフトが生まれます。 すべての完全なブロックを処理した後、最大で 2 つのキャンディーが残ります。 残りの 1 つのキャンディーは明らかに配ることができ、残りの 2 つのキャンディーは両方とも配ることができます。これは、食べるアクションが 2 番目のギフトの後にのみ発生し、消費するキャンディーがなくなった場合に限られます。 したがって、友達に届かない唯一のキャンディーは、まさに`floor(n / 3)`キャンディー、3 つの完全なグループごとに 1 つずつ。 結果的に答えは`n - floor(n / 3)`。

```の`solve`この関数は、入力形式で指定された単一の整数を読み取ります。 問題にはテスト ケースが 1 つだけ含まれているため、ループは必要ありません。 

表現`n // 3`3 つのキャンディーの完全なグループが何回発生できるかをカウントします。 これを引くと`n`消費されなかったキャンディーを直接カウントします。 残ったキャンディーは、キャンディーを受け取ることができる友達に正確に対応します。 

Python の整数は、以下よりもはるかに大きな値を処理します。`10^9`したがって、整数のオーバーフローは問題になりません。 整数の除算も意図的に階数の除算になっています。 通常の除算を使用すると浮動小数点値が生成され、完全なグループの数を正しく表すことができません。 

オフバイワン調整はありません。 例えば、`n = 2`与える`2 - 0 = 2`、 その間`n = 3`与える`3 - 1 = 2`。 これらのケース間の移行は、まさに最初の自己消費キャンディーが登場する場所です。

 ## 特殊なケース

 のために`n = 1`、アルゴリズムは次のように計算します。`1 // 3 = 0`、したがって、答えは次のとおりです`1 - 0 = 1`。 キャンディーは 1 人の友人に贈られるだけで、何かを食べさせるような 2 つ目のプレゼントはありません。 

のために`n = 2`、計算は`2 // 3 = 0`、生産`2 - 0 = 2`。 どちらのキャンディーも配布可能です。 これにより、2 人の友人がキャンディーを受け取るたびに、食べられるキャンディーが残っているかどうかを確認せずに、キャンディーを 1 つ減算するというよくある間違いが見つかります。 

のために`n = 3`、計算は次のようになります`3 // 3 = 1`、与える`3 - 1 = 2`。 キャンディー 2 個は友達に贈られ、3 個目は 2 回目のプレゼントの後に食べられます。 これは、実際に自己消費が発生する最小の入力です。 

のために`n = 6`、3 つの完全なグループが 2 つあります。 式は次のようになります`6 - 2 = 4`。 操作上、最初の 2 つのギフトは追加のキャンディを 1 つ消費し、次の 2 つのギフトは最後のキャンディを消費するため、4 人の友人がキャンディを受け取ります。 

のために`n = 8`、 がある`8 // 3 = 2`グループを完成させ、キャンディーを 2 個残します。 2 つの完全なグループは 4 つのギフトを提供し、最後の 2 つのキャンディーはさらに 2 つ、合計 6 つを提供します。 式は次のようになります`8 - 2 = 6`、2 の残りが追加のペナルティなしで処理されることを確認します。
