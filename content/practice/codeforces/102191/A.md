 ## 解決策
 ## 問題の理解

 から始めます`n`キャンディをできるだけ多くの異なる友達に、友達 1 人につき 1 つずつプレゼントしたいと考えています。 友達が 2 つおきにキャンディーを受け取った後、キャンディーが残っている場合は、自分たちで 1 つずつ食べます。 このプロセスは、友人に別のキャンディーを与えることができなくなるまで続きます。 

このタスクは、キャンディーを受け取ることができる友達の最大数を計算することです。 

の値`n`と同じ大きさにすることができます`10^9`。 これにより、キャンディーごとに 1 つの操作を実行するシミュレーションは即座に除外されます。最悪の場合、約 10 億回の反復が実行されるためです。 反復あたりの少量の一定の作業量であっても、それは 1 秒未満の競技プログラミング ソリューションが対応できる量をはるかに超えています。 プロセスの構造から直接答えを導き出す必要があります。 

最も微妙なケースは、食べるキャンディーがなくなった瞬間に発生します。 たとえば、入力の場合`2`、答えは`2`、 ない`1`。 2人の友人にキャンディーを1つずつ渡しますが、食べるものは何も残っていないので、両方の友人に食べさせます。 ペアごとに常にキャンディーを 1 個引くという不注意な計算式では、2 番目の友人が誤って拒否されてしまいます。 

もう一つの境界ケースは、`4`。 正しい答えは、`3`。 最初の 2 人の友達にキャンディーを渡し、キャンディーを 1 つ食べ、3 人目の友達にはキャンディーが 1 つ残ります。 その後、プロセスは停止します。 友人 2 人につき 1 つのキャンディーを食べるという単純な計算では、3 人の友人に 4 つ以上のキャンディーを提供すると誤って期待する可能性があります。 

入力`6`これも有用な境界ケースです。 答えは`4`、 ない`5`。 2人の友人にサービスを提供した後、キャンディーが1つ食べられ、3つが残ります。 次に、さらに 2 人の友人にサービスを提供し、1 人を残し、最後のキャンディーを食べます。 5人目の友人には何も残されていません。 これは、残りのすべてのキャンディーを友人が自動的に利用できるものとして扱う数式をキャッチします。 

## アプローチ

 直接的な総当たりソリューションにより、実際のプロセスをシミュレートできます。 キャンディーの数を維持し、繰り返し新しい友達に 1 つのキャンディーを与え、2 人目の友達ができるたびに 1 つのキャンディーを食べます。 シミュレーションはプロセスのルールに正確に従っているため、正確です。 ただし、Θ(`n`) の繰り返し。 と`n = 10^9`、これは最大 10 億回の反復を意味しますが、これは制限時間に対して遅すぎます。 

有益な観察は、プロセスには単純な繰り返しパターンがあるということです。 3 つのキャンディーを考えてみましょう。 彼らは 2 人の友人を生み出すことができます。2 つのキャンディーが 2 人の友人に行き、3 番目のキャンディーが食べられます。 したがって、3 つのキャンディーの完全なグループごとに、実質的に 2 人の友人が提供されます。 これらの完全なグループの後に残ったキャンディーはすべて、追加の友達に与えることができます。これは、グループの数が 3 つ未満であり、別の完全な食事サイクルを強制することができないためです。 

させて`n = 3q + r`、 どこ`r`は`0`、`1`、 または`2`。 

の`q`3 つのキャンディーの完全なグループが正確に原因を引き起こす`q`キャンディーは食べて、残りは`r`キャンディーは友達に行きます。 よって友達の数は`n - q = n - floor(n / 3)`。 

同じ結果を逆の方向からも理解できます。 奉仕する`k`友達、このプロセスには`k`友達に与えられたキャンディーと、別の友達がフォローするペアごとに 1 つ食べたキャンディー。 これにより、消費される 3 つのキャンディーごとに 2 つの有用なキャンディーが同じ比率で作成され、最後の不完全なグループは残りによって直接処理されます。 

したがって、シミュレーション全体は 1 つの整数除算と 1 つの減算に集約されます。

 ## アルゴリズムのチュートリアル

 1. キャンディーの数を読み取る`n`。 このプロセスではキャンディーと友達が区別されないため、必要な情報は合計数だけです。 

2. コンピューティング`n // 3`。 これは、3 つのキャンディーの完全なグループの数です。 このような各グループには、友人にあげる代わりに食べなければならないキャンディーが 1 つ含まれています。 

3. からその数値を引きます。`n`。 結果、`n - n // 3`, 最終的にフレンドにプレゼントできるキャンディーの数です。 

4. 結果を印刷します。 

最後のグループにキャンディーが 1 つまたは 2 つある場合でも、3 つずつグループ化することが機能するのはなぜですか? 完全なグループには、食べたキャンディー 1 つと友人に与えたキャンディー 2 つが含まれます。 1 つまたは 2 つのキャンディーの残りは、すべての食事サイクルが完了した後に発生し、友人に直接与えることができるため、追加の減算は必要ありません。 

### なぜ効果があるのか

 重要な不変条件は、消費された 3 つのキャンディーの完全なブロックごとに、友達が利用できる数がちょうど 1 つ減るということです。 このようなブロック内の 2 つのキャンディーは友達に与えられ、1 つは食べられます。 もし`n = 3q + r`、まさにあります`q`完全なブロックと`r < 3`残ったキャンディー。 完全なブロックは正確に説明します`q`みんなでキャンディーを食べながら、`r`残ったものは友達にあげることができます。 したがって、まさに`q = floor(n / 3)`キャンディーは食べるとなくなり、友達の最大数は`n - floor(n / 3)`。

表現`n // 3`整数の除算を実行し、完全な 3 つのグループの数を求めます。 それを引くと`n`友達に届くキャンディーの数を示します。 

ループがないため、シミュレーション境界やオフバイワン遷移を管理する必要はありません。 特に、整数除算を使用すると、次のような値が正しく処理されます。`2`、`4`、 そして`5`: それらの 3 による商は次のとおりです。`0`、`1`、 そして`1`、 それぞれ。 

## 実用的な例

 ### サンプル 1

 のために`n = 4`、整数除算は次のようになります。`4 // 3 = 1`。 キャンディーが 1 個食べられなくなり、残り 3 個のキャンディーが友達にプレゼントされます。 

|`n`|`n // 3`| 友達`n - n // 3`|
 |---:|---:|---:|
 | 4 | 1 | 3 |

 対応するプロセスは、2 人の友人にキャンディーを渡し、1 つのキャンディーを食べ、残りのキャンディーを 3 人目の友人に渡すことです。 出力は`3`。 

### サンプル 2

 のために`n = 5`、完全な 3 つのグループはまだ 1 つだけなので、ちょうど 1 つのキャンディーが食べられなくなります。 残りの 4 つのキャンディーは友達に届きます。 

|`n`|`n // 3`| 友達`n - n // 3`|
 |---:|---:|---:|
 | 5 | 1 | 4 |

 このプロセスは 4 人の友人に提供できます。2 人はキャンディーを受け取り、1 つのキャンディーは食べられ、残りの 2 つのキャンディーはさらに 2 人の友人に渡されます。 出力は`4`。 

これらの例は、剰余が重要である理由も示しています。 5 つのキャンディーから 3 つの完全なグループを 1 つ取り除いた後、2 つのキャンディーが残り、別の食事サイクルを作成せずに両方を与えることができます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())
    print(n - n // 3)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()
    output = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return output

# provided samples
assert run("4\n") == "3\n", "sample 1"
assert run("5\n") == "4\n", "sample 2"
assert run("6\n") == "4\n", "sample 3"

# custom cases
assert run("1\n") == "1\n", "minimum input"
assert run("2\n") == "2\n", "no candy remains to eat after the second friend"
assert run("7\n") == "5\n", "two complete groups plus one remainder"
assert run("1000000000\n") == "666666667\n", "maximum input"

 ## 特殊なケース

 のために`n = 1`、アルゴリズムは次のように計算します。`1 // 3 = 0`、したがって、答えは次のとおりです`1`。 キャンディーは 1 つだけで、それは 1 人の友人に直接送られます。 食事サイクルはトリガーされません。 

のために`n = 2`、アルゴリズムは次のように計算します。`2 // 3 = 0`、答えを与える`2`。 両方の友人に提供できますが、2 番目のキャンディーの後は、食べるキャンディーが残りません。 これは、ペアごとにキャンディーを 1 つ盲目的に削除する実装を破る境界です。 

のために`n = 4`、アルゴリズムは次のように計算します。`4 // 3 = 1`、与える`4 - 1 = 3`。 実際の順序は、2 つのキャンディーが与えられ、1 つが食べられ、最後のキャンディーが 3 人目の友人に与えられるというものです。 3 つの完全なグループが 1 つだけ食べられることになります。 

のために`n = 6`、アルゴリズムは次のように計算します。`6 // 3 = 2`、与える`6 - 2 = 4`。 最初の 2 人の友人は 2 つのキャンディーを消費し、1 つの食べたキャンディーをトリガーします。 次の 2 人の友人はさらに 2 つのキャンディーを消費し、2 番目に食べたキャンディーをトリガーします。 残りのキャンディーは 5 人目の友人をサポートできないため、最大 4 つです。 

のために`n = 10^9`の場合、アルゴリズムは、より小さい入力の場合とまったく同じ一定量の作業を実行します。 以来`10^9 // 3 = 333333333`、答えは`1000000000 - 333333333 = 666666667`。 これにより、解が次の大きさに依存しないことが確認されます。`n`反復回数を通じて。
