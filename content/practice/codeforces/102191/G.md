 ## 解決策
 ## 問題の理解

 配列があります`a`の`n`数字。すべての数字は以下の整数です。`0`に`b - 1`。 配列を左から右に読み取ると、`n`-底の桁数`b`。 この数値より厳密に大きく、すべての桁が異なる最小の数値が必要です。 最初の桁はゼロ以外であることがすでにわかっており、答えが存在することが保証されています。 

重要な問題は、「次」が数値順序であることです。これは 2 つの固定長基数の場合です。`b`数値は、その数字配列の辞書編集順に正確に一致します。 したがって、配列をできるだけ遅く変更したいと考えています。 1 つの位置を大きくすると決めたら、すべての桁を区別しつつ、後のすべての位置をできるだけ小さくする必要があります。 

両方`n`そして`b`と同じ大きさにすることができます`3 * 10^5`。 これにより、多くの可能な数値を試行するものや、二次関数さえも除外されます。`n`。 2 秒の制限があるため、ほぼ直線的または`O(n log b)`仕事。 基数が十分に大きい場合があるため、桁範囲全体にわたる演算にも注意する必要がありますが、`O(b)`まだ許容できる理由は、`b`と同じ上限があります`n`。 

単純な実装が静かに失敗する可能性があるエッジケースがいくつかあります。 まず、入力自体に繰り返しの数字が含まれている可能性があります。 例えば、```
3 10
1 1 9
```答えがあります`1 2 0`、最後の桁を変更するだけで得られるものではありません。 接頭語`1 1`はすでに無効であるため、最後の位置を数値を大きくする場所として使用することはできません。 

2 番目の問題は、大きい数字はすべてプレフィックスによってすでに使用されているため、最後の数字を増分できない可能性があることです。 例えば、```
4 4
3 2 0 1
```プレフィックスがすでに使用しているため、最終位置で増やすことはできません`0`、`2`、 そして`3`。 正しい答えは、`3 2 1 0`、3番目の位置を変更することで得られます。 

3 番目のエッジ ケースは、唯一可能な増加が最初の位置で行われる場合に発生します。 例えば、```
3 4
1 3 3
```答えがあります`2 0 1`。 最初の桁がこうなったら、`2`、残りの位置は、未使用の最小 2 桁を使用する必要があります。 不用意に実装すると、元の繰り返しの 1 つが誤って保存される可能性があります。`3`s。ただし、サフィックスには個別の数字が含まれている必要があります。 

最後に、最終ではない位置を変更することで、すでに異なる入力から答えを取得することができます。 のために```
3 4
1 2 3
```答えは`1 3 0`。 プレフィックスを維持する`1`、増加しています`2`に`3`、次にサフィックスを利用可能な最小の数字で埋めると、次の値より大きい最初の有効な数値が得られます。`123`。 

## アプローチ

 最も直接的なアプローチは、入力番号の直後から候補番号を列挙することです。 各候補者について、すべての候補が`n`数字は区別されます。 小切手自体には時間がかかります`O(n)`時間があるので調べてみると`K`連続した候補者のコストは`O(Kn)`。 最悪の場合、有効な数に達するまでに指数関数的に多くの候補が存在する可能性があります。`b^n`可能`n`-数字の配列。 したがって、最悪の場合の限界は次のようになります。`O(n b^n)`、これは完全に不可能です`n`まで`3 * 10^5`。 

ブルートフォース手法には、有益な特性が 1 つあります。それは、望ましい答えがどのようなものであるかを正確に教えてくれるということです。 桁を増やすことができる右から最初の位置が必要ですが、その位置より前はすべて変更されません。 この増加を行った後、サフィックスは可能な限り最小の有効なサフィックスになる必要があります。 

この観察により、数値を列挙する必要がなくなりました。 位置を選択するとします`i`最初に変更された位置として。 接頭語`a[0:i]`すでに個別の数字で構成されている必要があります。 置換数字は厳密に次より大きくなければなりません`a[i]`そのプレフィックス内に出現してはなりません。 そのようなすべての選択肢の中で、私たちは最小のものを望んでいます。 その数字を選択したら、サフィックスには、未使用の最小の数字を昇順に含めるだけです。 

残りのデータ構造の問題は、次の値より大きい未使用の最小の桁を見つけることです。`a[i]`。 以来`b`までです`3 * 10^5`、フェンウィック ツリーは、現在使用されていない数字のセットを維持し、`k`-番目の未使用の桁`O(log b)`時間。 プレフィックスに含まれる数字を動的に維持しながら、右から左に位置をスキャンします。 

候補をチェックすると最終的に最初の有効な大きい数値が見つかるため、総当り攻撃は機能しますが、候補が多すぎる可能性があるため失敗します。 最初に変更された位置のみが重要であるという観察により、指数列挙を単一の右から左へのスキャンと後続のクエリに置き換えることができます。

 | ブルートフォース |`O(n b^n)`最悪の場合 |`O(n + b)`| 遅すぎる |
 | 最適 |`O(n log b + b)`|`O(n + b)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックスの周波数配列を構築する`a[0:n-1]`なぜなら、最初に位置を検査するとき`n-1`、それより前の数字はすべて、変更されていないプレフィックスに属します。 同時に、このプレフィックスで現在使用されていないすべての数字を含むフェンウィック ツリーを初期化します。 
2. メンテナンス`bad`、現在のプレフィックス内の頻度が少なくとも 2 である桁値の数。 プレフィックスはまさに次の場合に使用できます。`bad == 0`。 元の配列には個別の数字が含まれることが保証されていないため、これを明示的に必要とします。 
3. から始める`i = n - 1`そして移動します`i`ゼロに向かって。 位置で`i`、その前の接頭辞`a[0:i]`。 もし`bad`がゼロ以外の場合、このプレフィックスは有効な応答に出現できません。そのため、この位置を最初に変更された位置にすることはできません。 
4. プレフィックスが異なる場合は、厳密に次の値より大きい未使用の最小の数字をフェンウィック ツリーに問い合わせます。`a[i]`。 そのような数字の場合`x`存在するなら`a[0:i] + [x]`位置の元の数値より大きい、可能な最小のプレフィックスです。`i`。 
5. 1回`x`が見つかった場合は、そこから数字をスキャンしてサフィックスを構築します。`0`上向きで、プレフィックスで使用されておらず、次と等しくない最小の数字を取得します。`x`。 これらは辞書編集上可能な最小の接尾辞の数字であるため、この選択により、この固定位置の最小の数値が得られます。`i`。 
6. 有効でない場合`x`位置に存在します`i`に移動します`i - 1`。 新しいプレフィックスを表すには`a[0:i-1]`、 取り除く`a[i-1]`現在のプレフィックスカウントからカウントし、そのカウントがゼロになると、その桁を未使用としてマークします。 アップデート`bad`その出現を削除すると重複が排除される場合。 
7. 答えを構築できる最初の位置が、変更する正しい位置です。 右から左にスキャンするので、後の位置はすべて不可能であることがすでに証明されていますが、前の位置を変更するとより大きな数値が生成されます。 

### なぜ効果があるのか

 最初の位置を考えてみる`i`アルゴリズムが成功した場合。 その後のすべてのポジション`i`が最初にテストされましたが、プレフィックスを保持したまま有効なより大きな数値を生成できませんでした。 したがって、それ以降の答えは元のものと異なることはできません。`i`。 

位置で`i`、接頭辞`a[0:i]`特徴があるので、安全に保存できます。 アルゴリズムは、次の値より大きい未使用の最小の数字を選択します。`a[i]`、これは、この位置での結果の数値を大きくする可能な最小の桁です。 置き換えを小さくすると数値を大きくできなくなりますが、置き換えを大きくすると必要以上に大きな数値が生成されます。 

その置換後、残りのすべての位置は、使用可能な最小の桁で昇順に埋められます。 接頭辞と置換はすでに固定されているため、これが辞書編集上最小の有効な接尾辞になります。 その結果、構築された数値は入力よりも大きく、明確な桁があり、これより小さい有効な大きい数値は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, pos, delta):
        pos += 1
        while pos <= self.n:
            self.bit[pos] += delta
            pos += pos & -pos

    def prefix_sum(self, pos):
        """Number of elements in [0, pos)."""
        res = 0
        while pos > 0:
            res += self.bit[pos]
            pos -= pos & -pos
        return res

    def kth(self, k):
        """Return the 0-based index of the k-th present element."""
        idx = 0
        step = 1 << (self.n.bit_length() - 1)

        while step:
            nxt = idx + step
            if nxt <= self.n and self.bit[nxt] < k:
                idx = nxt
                k -= self.bit[nxt]
            step >>= 1

        return idx

def solve_case(n, b, a):
    # The prefix before position n-1.
    cnt = [0] * b
    for i in range(n - 1):
        cnt[a[i]] += 1

    # Number of digit values appearing at least twice in the prefix.
    bad = sum(c >= 2 for c in cnt)

    # Fenwick tree stores currently unused digits.
    fw = Fenwick(b)
    for d in range(b):
        fw.add(d, 1)

    # Remove all digits used by the prefix from the available set.
    for d in range(b):
        if cnt[d]:
            fw.add(d, -1)

    for i in range(n - 1, -1, -1):
        if bad == 0:
            # Number of unused digits <= a[i].
            le = fw.prefix_sum(a[i] + 1)
            total = fw.prefix_sum(b)

            # We need the first unused digit strictly greater than a[i].
            k = le + 1

            if k <= total:
                x = fw.kth(k)

                # The prefix is already distinct, and x is unused.
                ans = a[:i] + [x]

                # Fill the suffix with the smallest remaining digits.
                need = n - i - 1
                for d in range(b):
                    if need == 0:
                        break
                    if cnt[d] == 0 and d != x:
                        ans.append(d)
                        need -= 1

                return ans

        if i > 0:
            # Move from prefix a[:i] to prefix a[:i-1].
            v = a[i - 1]

            if cnt[v] == 2:
                bad -= 1

            cnt[v] -= 1

            if cnt[v] == 0:
                fw.add(v, 1)

    # The statement guarantees that an answer exists.
    return []

def main():
    n, b = map(int, input().split())
    a = list(map(int, input().split()))

    ans = solve_case(n, b, a)
    print(*ans)

if __name__ == "__main__":
    main()
```周波数配列は、現在変更されていないプレフィックスを記述します。 頻度が 1 より大きい場合は、プレフィックスが有効な回答の一部になり得ないことを意味します。`bad`一定時間内にプレフィックスの有効性をテストしてみましょう。 

フェンウィック ツリーには、プレフィックスに含まれていない数字が正確に含まれています。`prefix_sum(a[i] + 1)`から利用可能な桁を数えます`0`を通して`a[i]`、したがって、次に利用可能な桁にはランクがあります`le + 1`。 の`kth`操作により、そのランクが実際の桁に変換されます。`O(log b)`時間。 

ループは最終位置の前のプレフィックスから始まり、左に移動するたびに 1 つの要素を削除します。 この順序付けが重要な境界の詳細です。 反復時`i`、`cnt`正確に説明しなければならない`a[0:i]`、 ない`a[0:i+1]`。 

周波数がから変わるとき`2`に`1`, 重複した数字が1つ消えますので、`bad`減少します。 周波数がから変わるとき`1`に`0`、その数字がフェンウィック ツリーで再び利用可能になります。 カウントが正の場合は、数字を追加し直す必要はありません。 

接尾辞の構築では、意図的にゼロから上に向かってスキャンします。 選んだ代替品`x`プレフィックスにすでに存在するすべての数字と同様に、除外されます。 ループは正確にかかります`n - i - 1`この問題は、何らかの有効な答えが存在することと、`n`-digital の個別の数値は、次のことも意味します。`b >= n`。 

基数の整数変換はありません。`b`数値なので、Python の整数のサイズは無関係です。 答えは数字の配列として処理されますが、これも必要です。`b`10よりもはるかに大きくなる可能性があります。
