 ## 問題の理解

 を取り揃えております。`n`数字。すべての数字は基数で解釈されます。`b`。 配列は 1 つの塩基を表します。`b`整数であるため、桁数が同じ 2 つの数値を比較することは、それらの配列を辞書順に比較することと同じです。 

必要な答えは、すべての桁が異なる入力より厳密に大きい最小の整数です。 答えはどちらかになります`n`数字または`n + 1`数字。 後者の場合は、入力がすでに有効範囲の終わりにある場合に重要です。`n`-桁の異なる数字。 元の問題は、何らかの答えが存在することを保証します。 citeturn4search0

 境界では両方が許可されます`n`そして`b`到達する`300000`。 考えられるすべての数値を調べるアルゴリズムは絶望的です。`b^n`ベース-`b`一定の長さの文字列`n`。 たとえ`O(n^2)`アルゴリズムはすでに遅すぎるでしょう`n = 300000`。 本質的に線形または線形に近い解決策が必要です。 

見落としがちな特殊なケースがいくつかあります。 まず、入力自体に個別の数字が含まれている必要はありません。 例えば、```text
4 11
10 5 5 1
```繰り返している`5`、しかし答えは`10 5 6 0`。 入力がすでに有効な個別の桁の数値であると想定するソリューションでは、このケースを処理できません。 

次に、数値を増やす位置には別の接頭辞が必要です。 のために```text
5 7
2 6 6 0 1
```2番目の`6`その位置以降で終わるすべてのプレフィックスが無効になります。 正しい答えは、`3 0 1 4 5`。 不注意な実装では、繰り返された数字をローカルで修復しようとして、プレフィックスに重複した数字が誤って保持される可能性があります。 

第三に、答えにはさらに 1 桁必要になる場合があります。 例えば、```text
2 10
9 8
```これより大きい有効な 2 桁の数字はありません。 有効な 3 桁の最小の数字は次のとおりです。`1 0 2`、これは正しい出力です。 答えを必ず正確に持つものとして扱う`n`数字はこのケースを見逃します。 

最後に、最初の位置を除くすべての位置でゼロが許可されます。 答えに複数の桁がある場合は、サフィックスを埋めるときにゼロを考慮する必要があります。これは、ゼロが可能な限り最小の桁であるためです。 たとえば、より大きなプレフィックスを修正した後、最小のサフィックスは多くの場合次で始まります。`0`。 

## アプローチ

 直接的なブルート フォース ソリューションでは、指定された数値から開始し、それを 1 ずつ増分し、そのすべての桁が異なるかどうかを繰り返しテストします。 最初に見つかった有効な数値は入力よりも大きい最小の有効な数値であるため、この方法は正しいです。 ただし、大まかには、`(b - 1)b^(n-1)`正確な数字`n`数字、そして 1 つの数字をチェックするのに時間がかかります`O(n)`時間。 最悪の場合、これにより、`Theta(n(b - 1)b^(n-1))`数字の演算は完全に不可能です。 

便利な構造は、数値比較が辞書編集的であることです。 同じ長さの答えが必要だとします。 ある位置で`i`、最初に答えが入力よりも大きくなる必要があります。 以前のすべてのポジション`i`の数字は変更しないでください。`i`より大きくする必要があり、その後のすべての位置`i`したがって、できるだけ小さくする必要があります。 

これにより、すぐに 2 つの貪欲なルールが得られます。 最初の差分を延期すると、元のプレフィックスがより多く保持され、生成される数値が小さくなるため、最初の増加には可能な限り右端の位置が必要です。 その位置が固定されたら、そこにある元の桁より大きい未使用の最小桁が必要になります。 残りのサフィックスには、使用可能な最小の数字が昇順に含まれている必要があります。 

配列のスキャン中に必要な唯一のデータ構造操作は、少なくともある値で未使用の最小の桁を見つけることです。 プレフィックスが大きくなるにつれて数字が 1 回だけ使用されるため、これには特に便利な構造があります。 素セットの後続構造は、値の削除と、ほぼ一定の償却時間でのまだ使用可能な次の値の検索をサポートします。 

スキャンを簡単にする観察がもう 1 つあります。 プレフィックスにすでに重複が含まれている場合、プレフィックスは区別できなくなります。 したがって、左から右にスキャンしているときに、最初の重複が見つかったら、後の位置を調べる理由はありません。 より大きな未使用の桁が存在する以前のすべての位置の中で、最後のそのような位置が最適なピボットです。 

同じ長さの答えが存在しない場合は、もう 1 桁追加した最小の答えが次から始まります。`1`。 残りの桁は、単に次のような、未使用の可能な最小の桁です。`0`。 答えが存在するという保証は、この構築に十分な桁数が利用できることを意味します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース |`Theta(n b^n)`|`O(n)`| 遅すぎる |
 | 最適 |`O(n + b alpha(b))`|`O(b + n)`| 承認済み |

 ここ`alpha(b)`は逆アッカーマン関数であり、これらの制約に対して事実上一定です。 

## アルゴリズムのチュートリアル

 1. 次のすべての桁を含む後続の DSU を作成します。`0`を通して`b - 1`、さらにセンチネル`b`。 最初はすべての桁が使用可能です。 操作`find(x)`現在利用可能な最小の数字以上を返します。`x`。 

2. プレフィックスにすでに存在する数字のセットを維持しながら、入力を左から右にスキャンします。 位置で`i`、まず次のことを確認してください。`a[i]`すでに登場しています。 存在する場合、次で終わるプレフィックス`i`は無効であり、それより長いプレフィックスも無効であるため、スキャンが停止する可能性があります。 

3. プレフィックスが異なる場合は、クエリを実行します。`find(a[i] + 1)`。 戻り値が以下の場合`b`、それは置き換えることができる最小の桁です`a[i]`この位置で数字を大きくしながら。 このポジションと候補を現在の最良のピボットとして記録します。 

4. 加工後の位置`i`、 マーク`a[i]`後継の DSU で使用されているものと同じです。 数字を削除するということは、その数字を次に利用可能な数字にリダイレクトすることを意味します。 数字はプレフィックスが大きくなるときにのみ削除されるため、後継の DSU はこのプロセスに正確に適合します。 

5. スキャンを続行し、別の有効な位置に利用可能な桁が大きい場合は常に、保存されたピボットを上書きします。 最後に保存されたピボットは、最初の差分をできるだけ右に配置するため、最適です。 

6. ピボットが見つかった場合は、回答を再構築します。 ピボットの前にある元のプレフィックスをコピーし、保存した候補をピボットに配置し、それらの数字を使用済みとしてマークします。 次に、からの数字をスキャンします`0`に`b - 1`、答えが長くなるまで、未使用の最小の数字を取得します`n`。 

7. ピボットが見つからなかった場合は、次の式で最小の有効な数値を構築します。`n + 1`数字。 最初の桁は次のようにする必要があります`1`先行ゼロは禁止されているため、`1`ゼロ以外の最小の数字です。 次に、利用可能な最小の数字を昇順に追加します。 

スキャンの背後にある不変条件は、位置を処理する前の不変条件です。`i`、後続構造には、すでに受け入れられたプレフィックスにない数字が正確に含まれます。 その結果、`find(a[i] + 1)`正確に、その位置の数値を大きくする最小の法定数字です。`i`。 保存されたすべてのピボットは、そのピボットに対して可能な最小の数値を生成し、最も右側の実行可能なピボットを選択すると、すべての実行可能なピボットの中で最小の数値が得られます。 ピボットが存在しない場合、入力よりも大きいすべての同じ長さの数値は不可能であるため、次のようになります。`n + 1`桁数が必要であり、貪欲な構造ではその長さの最小の数値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, b = map(int, input().split())
    a = list(map(int, input().split()))

    # parent[x] is used by the successor DSU.
    # find(x) returns the smallest currently unused digit >= x.
    parent = list(range(b + 1))

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    used = bytearray(b)

    best_pos = -1
    best_digit = -1

    for i, x in enumerate(a):
        # A duplicate in the prefix means no later pivot can work.
        if used[x]:
            break

        # Smallest unused digit strictly greater than x.
        y = find(x + 1)

        if y < b:
            best_pos = i
            best_digit = y

        # Add x to the fixed prefix.
        used[x] = 1
        parent[x] = find(x + 1)

    if best_pos != -1:
        ans = a[:best_pos]

        used_answer = bytearray(b)
        for x in ans:
            used_answer[x] = 1

        ans.append(best_digit)
        used_answer[best_digit] = 1

        # Fill the suffix with the smallest possible unused digits.
        need = n - len(ans)
        if need:
            for d in range(b):
                if not used_answer[d]:
                    ans.append(d)
                    need -= 1
                    if need == 0:
                        break

        print(*ans)
        return

    # No larger valid number has n digits.
    # The smallest valid number with n + 1 digits starts with 1.
    ans = [1]
    used_answer = bytearray(b)
    used_answer[1] = 1

    need = n
    for d in range(b):
        if not used_answer[d]:
            ans.append(d)
            used_answer[d] = 1
            need -= 1
            if need == 0:
                break

    print(*ans)

if __name__ == "__main__":
    solve()
```の`parent`array は、従来の set-union 構造ではなく、後続構造を表します。 最初は`find(x) = x`すべての桁ごとに。 数字の場合`x`固定プレフィックスの一部となり、`parent[x]`に変更されます`find(x + 1)`、効果的に除去します`x`そしてそれを次に利用可能な桁に接続します。 

の`used`元のプレフィックス内の重複を検出する必要があるため、バイト配列は DSU とは分離されています。 チェックは、現在の桁を削除する前に行われます。 もし`used[x]`がすでに設定されている場合、プレフィックスは区別できなくなり、スキャンは終了します。 

候補クエリは次を使用します。`x + 1`、 ない`x`答えはピボットで厳密に大きくなる必要があるためです。 インデックスの番兵`b`は「利用可能な桁がない」ことを表しますので、`y < b`正確な境界チェックです。 

応答を再構築するとき、サフィックスはゼロから上に向かってスキャンされます。 これは、すべての桁がすでにその数値で表されており、基本全体をスキャンするのにかかるコストのみがかかるため、並べ替えよりも望ましい方法です。`O(b)`。 Python には整数オーバーフローの問題はなく、アルゴリズムは潜在的に巨大な基数を変換することはありません。`b`数値をネイティブの整数に変換します。 

の`n + 1`ケースの用途`1`最初の桁として。 元の数値には先頭のゼロがなく、`n + 1`桁数がすべてより大きい`n`桁数なので、先頭の可能な限り小さい桁だけが重要です。 残りの位置は、未使用の最小桁を取得することによって個別に最小化されます。

 ## 特殊なケース

 入力に繰り返し数字がすぐに含まれる場合、アルゴリズムは重複に達するとすぐに停止します。 のために```text

9 2 6
```位置に到達`2`、見つけます`7`、生成します`9 2 7`。 それを認識すること以外に、追加の接尾辞ロジックは必要ありません。`need = 0`。 

すべての位置で大きな数字がすべて利用できない場合、答えは 1 桁増加する必要があります。 のために```text
2 10
9 8
```入力自体は個別の数字を使用しますが、これより大きな個別の 2 桁の数字はありません。 スキャンではピボットが見つからないため、アルゴリズムは最小の 3 桁の個別の数値を構築します。 それはから始まります`1`、 に続く`0`そして`2`、与える`1 0 2`。 

先行ゼロ制限は、同じ長さのピボット選択中に特別なケースを必要としません。 元の最初の数字は正であり、位置 0 にあるピボットにより、それが厳密に大きな数字 (これも正) に置き換えられます。 後の位置では、ゼロは完全に正当であり、サフィックスを埋めるときに最初に正しく選択されます。 

最大サイズの場合も、特別な演算を行わずに処理されます。 と`n = b = 300000`、アルゴリズムは線形サイズの配列のみを保存し、入力の 1 回のスキャンとベースの 1 回のスキャンを実行します。 Python の整数は完全な数値を表すために使用されることはありません。そのため、表現された基数の膨大な数値が`b`整数は実行時間には影響しません。
