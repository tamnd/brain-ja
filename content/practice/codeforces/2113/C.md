 ## 解決策
 ## 問題の理解

 各セルが空、石、または金のいずれかであるグリッドが与えられます。 スミロは空のセルにのみダイナマイトを設置できます。 彼が空のセルで爆発すると、そこを中心とした固定半径の正方形の領域に影響を与えます。`k`, したがって、正方形には辺の長さがあります`2k + 1`。 

爆発の影響は 2 つあります。 厳密に正方形の内側にある金はすべて消滅し、何も貢献しません。 まさに正方形の境界線上にある金が集められます。 爆発後、正方形全体が空になりますが、その後処理は、新たに空になったセルで将来の爆発が可能になることを除いて、スコアには直接関係ありません。 

タスクは、空のセル内の有効な爆発中心のシーケンスを選択することであり、各爆発は、現在の正方形の境界上に正確に存在する金セルの数に等しい金を生成します。 目標は、すべての爆発で収集されたゴールドの合計を最大化することです。 

重要な点は、爆発が固定グリッド内で独立していないことです。 それぞれの爆発によって領域がクリアされるため、今後の爆発で収集できる内容が変化する可能性があります。 ある爆発では内部にあった金の細胞が、後の別の爆発では境界になることもあれば、その逆の場合もあります。 

この制約は、グリッドがテストごとに最大 500 x 500 まで可能であり、テスト全体の合計グリッド サイズが最大 2.5e5 であることを意味します。 これにより、考えられるすべての爆発中心をシミュレートし、境界寄与を爆発ごとに O(k^2) で単純に再計算するソリューションは除外されます。 すべての空のセルを直接シミュレーションすると、最悪の場合、およそ O(nm(nm)) になりますが、これは大きすぎます。 

重要なエッジケースは、金が複数の重なり合う潜在的な正方形の境界近くにある場合に現れます。 たとえば、空の空間に囲まれた金の密なグリッドでは、すべての爆発が同じ境界セルをめぐって競合します。爆発の単純で貪欲な順序付けは、内部の金を早期に除去することが後の境界位置にどのような影響を与えるかを考慮していないため、失敗する可能性があります。 

## アプローチ

 ブルートフォース解釈は簡単です。 すべての空のセルについて、そこで爆弾が爆発することを想像し、その正方形の境界にどれだけの金があるかを計算し、更新されたグリッド上で後続の爆発を再帰的に検討します。 これは、有効な爆発シーケンスをすべて列挙しているため、原理的には正しいです。 ただし、状態空間は爆発します。 単一の爆発でさえ、多数の新しい構成が作成される可能性があり、境界ゴールドを再計算するには各評価に O(nm) 以上のコストがかかります。 これにより、指数関数的な分岐係数に二次評価コストを乗算することになりますが、これはまったく実行不可能です。 

重要な観察は、プロセスを別の方法で解釈する限り、爆発の順序はどの金を収集できるか根本的には変わらないということです。破壊をシミュレートする代わりに、各金セルを、空のセルを中心とする k 半径の正方形の境界上にある爆発によって「要求される」ものとして再解釈します。 

これにより、動的シミュレーションから静的なカバレッジ問題に視点が変わります。 各空のセルは正方形の境界を定義し、各金のセルは、そこからのチェビシェフ距離が正確に k である中心に寄与します。 したがって、各金のセルは、その周囲のダイヤモンド型の境界上にあるすべての空のセルに関連付けられます。 各中心が正確に k の距離にある金のセルの数に寄与するように中心 (空のセル) を選択したいと考えていますが、一度金が使用されると、実現可能性に違反する方法で二重にカウントされるべきではないという追加の制約があります。 

重要な簡素化は、実際には複数の爆発をシミュレートする必要がないことです。 各金セルは独立して属性を付けることができます。正確に k の距離に空のセルが少なくとも 1 つ存在する場合、それを一度収集できる可能性があります。 最適な戦略は、空のセルごとに、その境界上に金セルが何個あるかを数え、過度に複雑な相互作用を回避する方法で寄与を合計することになります。 すべての爆発は静的距離のみに依存するため、プレフィックスの合計を使用して寄与を事前計算し、各空のセルを個別に処理できます。 

したがって、動的変化をシミュレートする代わりに、ゴールド セルの 2D プレフィックス合計を事前計算し、O(1) の各空セルの境界カウントをクエリします。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース シミュレーション | O((nm)^2) 以上 | O(nm) | 遅すぎる |
 | プレフィックス合計を使用した境界カウント | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ゴールド セルの位置を示すグリッド上で 2D プレフィックス合計を構築します。 これにより、任意のサブ長方形内の金の定数カウントが可能になります。 各爆発境界は長方形のクエリに分解できるため、これが必要になります。 
2. 空のセルごとに`(i, j)`、チェビシェフ距離に正確に何個の金セルがあるかを計算したいとします。`k`。 正方形の境界は、正方形の 4 つの辺の結合に対応します。 
3. 辺の正方形内の金セルの数を計算します。`2k + 1`を中心に`(i, j)`プレフィックス合計を使用します。 これにより、距離 ≤ k にあるすべての金が得られます。 
4. 辺の内側の正方形の金セルの数を計算します。`2k - 1`を中心に`(i, j)`、これは距離 ≤ k-1 にあるすべての金に対応します。 
5. これら 2 つの値を減算すると、正確に距離 k にある金セルの数が得られます。これはまさに爆発によって収集されるものです。 
6. この最適な定式化では各爆発を独立して考慮できるため、すべての空のセルにわたってこの値を合計します。 

これが機能する理由は、スコアリングが幾何学的距離の制約のみに依存し、各ゴールド セルが選択された中心ごとに正確に 1 層の距離に寄与するためです。 距離 k の境界層は内部層から切り離されているため、プレフィックス合計の減算により、オーバーラップの問題なく正しい寄与がきれいに分離されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_prefix(grid, n, m):
    ps = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n):
        row = grid[i]
        for j in range(m):
            ps[i + 1][j + 1] = ps[i][j + 1] + ps[i + 1][j] - ps[i][j]
            if row[j] == 'g':
                ps[i + 1][j + 1] += 1
    return ps

def query(ps, x1, y1, x2, y2):
    if x1 > x2 or y1 > y2:
        return 0
    return ps[x2 + 1][y2 + 1] - ps[x1][y2 + 1] - ps[x2 + 1][y1] + ps[x1][y1]

t = int(input())
for _ in range(t):
    n, m, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    
    ps = build_prefix(grid, n, m)
    
    ans = 0
    
    for i in range(n):
        for j in range(m):
            if grid[i][j] != '.':
                continue
            
            x1 = max(0, i - k)
            y1 = max(0, j - k)
            x2 = min(n - 1, i + k)
            y2 = min(m - 1, j + k)
            total = query(ps, x1, y1, x2, y2)
            
            if k == 0:
                ans += total
                continue
            
            x1 = max(0, i - (k - 1))
            y1 = max(0, j - (k - 1))
            x2 = min(n - 1, i + (k - 1))
            y2 = min(m - 1, j + (k - 1))
            inner = query(ps, x1, y1, x2, y2)
            
            ans += total - inner
    
    print(ans)
```コードは最初に、すべてのゴールド セルのプレフィックスの合計を構築します。 各クエリ関数は、O(1) の長方形領域内の金セルの数を抽出します。 

空のセルごとに、チェビシェフ半径 k 内の金セルの数を計算し、半径 k-1 内の金セルを減算します。 これにより、境界層の寄与が分離されます。 

の`k == 0`内側の正方形が存在しないため、ケースは個別に処理されます。 この場合、重要なのは中央のセルのみです。 

よくある実装の落とし穴は、クエリ四角形を形成するときにグリッドの境界を固定する必要があることを忘れていることです。 もう 1 つは、プレフィックス インデックス作成における off-by-one エラーです。これが、プレフィックスが 1 から始まるインデックスで構築される理由です。

            return 0

 ## 特殊なケース

 微妙なケースとしては、`k`正方形がグリッドを超えて広がるのに十分な大きさです。 この状況では、プレフィックス合計クエリは座標を適切にクランプする必要があります。 たとえば、2x2 グリッドでは、`k = 10`、すべてのクエリ四角形をグリッド全体に縮小する必要があります。そうしないと、負のインデックスによって結果が破損します。 アルゴリズムはこれを次のように処理します。`max(0, ...)`そして`min(n-1, ...)`理論上の正方形が部分的にグリッドの外側にある場合でも、正確性が保証されます。 

もう一つのエッジケースは、`k = 0`。 ここで、境界は中央のセルに縮退します。 減算式は負の半径の内側の正方形をクエリするため、コードは明示的に次のように処理します。`k == 0`単一セル内の金の直接カウントとして、幾何学的定義との一貫性を確保します。
