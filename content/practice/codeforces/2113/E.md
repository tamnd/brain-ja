 ## 解決策
 ## 問題の理解

 私たちには都市を表す木が与えられています。 マラートは頂点から始まります`x`時間 1 で頂点に到達したいと考えています`y`。 毎日は離散的な時間ステップで進行し、各ステップで彼はその場に留まるか、木の一方の端に沿って移動することができます。 

同時に、最大200人の敵がいます。 それぞれの敵`i`頂点から始まる`a_i`時間 1 では、固定の最短パスに沿って頂点まで歩きます。`b_i`、単位時間当たり 1 つのエッジを移動します。 したがって、各敵は、時間の経過とともに、固有の木の経路によって完全に決定される一連の頂点を占有します。 

マラートは同時に敵と同じ頂点にいることはできませんが、敵は衝突することなく同じエッジを反対方向に通過することができます。 重要なのは、敵が目的地に到達すると移動を停止し、将来の紛争には関係なくなるということです。 

課題は、マラットが到着できる最も早い時間を決定することです。`y`から始まる`x`同時にどの敵とも頂点を共有することはありません。あるいは、それは不可能であると結論付けます。 

ツリーにはテスト ケース全体で合計最大 100,000 の頂点がありますが、敵の数は少なく、最大 200 です。この不均衡が重要な構造上のヒントです。グラフは大きいですが、動的制約の数は少ないです。 

経路は長くなる可能性があり、時間は敵からの制約を乗算した木の直径にまで及ぶ可能性があるため、時間の経過に伴う単純なシミュレーションは不可能です。 状態空間探索`(node, time)`すぐに爆発してしまうだろう。 

微妙な問題はタイミングに現れます。敵は特定のタイム ステップでのみ頂点をブロックします。 マラーが 1 時間単位早く到着するか遅く到着すると、紛争は解消されます。 時間を無視した単純な最短経路は、これらの時間的制約を無視するため、間違っています。 

2 番目の微妙なエッジケースが待っています。 場合によっては、正しい戦略では、衝突を避けるために Marat が正確に 1 つ以上の時間単位にわたって頂点に留まる必要があります。 貪欲な「常に最短経路に沿って移動する」アプローチは、マラットが通過するのと同時に同じ頂点を横切る単一の敵のような例では失敗します。 

## アプローチ

 強引な解釈では、問題は、各状態が次のような時間展開グラフ内の最短経路として扱われます。`(vertex, time)`。 各状態から、滞在することも、隣接する状態に移動することもできますが、その時点で敵がターゲット頂点を占有している場合、遷移は禁止されます。 

これは正しいですが、まったく実行不可能です。 回答時間が`T`、状態の数は`O(nT)`。 以来`T`に比例する可能性があります`n`、これは次のように縮退します。`O(n^2)`テストケースごとの状態。 Even with pruning, checking enemy presence per state would require scanning up to 200 enemy paths or precomputing per-time occupancy, which is still too large.

 重要な観察は、実際にはフルタイム拡張シミュレーションは必要ないということです。 各敵は、単一の木のパスに沿った頂点に一連の「禁じられた瞬間」を定義します。 グラフはツリーであるため、各パスは一意であり、構造的に処理できます。 

時間をグローバルにシミュレートする代わりに、視点を逆転させます。 各ノードについて、マラットが安全にそこに到着できる最も早い時間を知りたいと考えています。 マラットが時間通りに到着したら`t`、その時点で敵もそのノードにいるかどうかを確認するだけで済みます`t`。 That converts the problem into a shortest path computation with dynamic vertex availability constraints.

 Now the crucial simplification comes from tree structure and small number of enemies. Each enemy path contributes constraints only along one simple path. We can precompute, for every vertex, all time intervals during which enemies occupy it. 各敵は貢献するだけなので、`O(length of path)`イベントと敵の総数は少なく、制約の総サイズは管理可能です。 

次に、変更された BFS/ダイクストラを次から実行します。`(x, 1)`時刻にノードに遷移する場所`t+1`その時点でノードが占有されていない場合にのみ許可されます。 すべての移動には 1 時間単位のコストがかかるため、これは実質的に時間の経過とともに BFS になります。 

2 番目の重要な最適化は、すべての時間を明示的に保存する代わりに、禁止された時間のソートされたリストを頂点ごとに事前計算し、ポインターまたは二分探索でメンバーシップをチェックできることです。 各頂点には最大 200 のパスが接触するため、これは依然として効率的です。 

最後に、「待機」の正確性を確認します。頂点に留まるのは BFS 内の単なる遷移であるため、待機も当然含まれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 時間拡張BFS | O(nT) | O(nT) | 遅すぎる |
 | 頂点時間ブロックを備えた制約ベースの BFS | O((n + 敵の進路の合計長さ) log m) | O(n + 制約) | 承認済み |

 ## アルゴリズムのチュートリアル

 各頂点が占有されるときの表現を構築します。 

1. 敵ごとに、敵間の一意の最短経路を計算します。`a_i`そして`b_i`。 これは、DFS または BFS のルート ツリー トラバーサルからの親ポインターを使用して行われます。 ツリーは一意性を保証するため、パスの再構築に曖昧さは存在しません。 
2. 経路がわかったら、それに沿った時間を割り当てます。 パスが`c_1 ... c_k`、次に敵`i`占める`c_p`時に`p`。 ペアで保管します`(time p, enemy i)`頂点に関連付けられたリスト内`c_p`。 

このステップでは、動きの制約を頂点ごとの静的なタイムスタンプに変換し、動きを動的にシミュレートする必要がなくなります。 
3. すべての頂点について、占有時間のリストを並べ替えます。 これにより、特定の時点で頂点がブロックされているかどうかを効率的にチェックできます。 
4. 以下から開始して BFS (または単位重みを使用したダイクストラ) を実行します。`(x, 1)`。 各状態は、マラットが特定の時点で頂点にいることを表します。 
5. から`(v, t)`、すべての近隣への遷移を考慮します`u`そしてまた滞在`v`。 それぞれの移行は時間につながります`t+1`。 
6. 押す前に`(u, t+1)`、頂点かどうかを確認します`u`時間に占領されています`t+1`。 そうした場合、この動きを破棄する。 
7. 初めて到着したとき`(y, t)`が答えです。 BFS が到達せずに終了した場合`y`、出力`-1`。 

### なぜ効果があるのか

 このアルゴリズムは、キューに入れられたすべての状態が不変であることを維持します。`(v, t)`マラーが頂点に立つための実現可能な方法を表す`v`正確な時間に`t`それまで敵と衝突することはありませんでした。 すべての遷移は、問題のダイナミクスに合わせて、正確に 1 単位だけ時間を進めます。 すべての有効な動きは時間の増加順に探索されるため、最初に到達した時点で`y`は必然的に実現可能な最小到着時間になります。 考えられるすべての移動または待機が BFS エッジとして明示的に表現されるため、有効なパスはスキップされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque, defaultdict

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n, m, x, y = map(int, input().split())
        x -= 1
        y -= 1

        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)

        # parent and depth for LCA/path reconstruction
        parent = [-1] * n
        depth = [0] * n

        stack = [x]
        parent[x] = x

        order = []
        while stack:
            v = stack.pop()
            order.append(v)
            for to in g[v]:
                if parent[to] == -1:
                    parent[to] = v
                    depth[to] = depth[v] + 1
                    stack.append(to)

        def get_path(a, b):
            path_a = []
            path_b = []
            while depth[a] > depth[b]:
                path_a.append(a)
                a = parent[a]
            while depth[b] > depth[a]:
                path_b.append(b)
                b = parent[b]
            while a != b:
                path_a.append(a)
                path_b.append(b)
                a = parent[a]
                b = parent[b]
            path_a.append(a)
            return path_a + path_b[::-1]

        occ = defaultdict(list)

        for _ in range(m):
            a, b = map(int, input().split())
            a -= 1
            b -= 1
            path = get_path(a, b)
            for i, v in enumerate(path, start=1):
                occ[v].append(i)

        for v in occ:
            occ[v].sort()

        q = deque([(x, 1)])
        dist = { (x, 1): True }

        while q:
            v, tcur = q.popleft()

            if v == y:
                print(tcur)
                break

            def ok(node, time):
                lst = occ.get(node)
                if not lst:
                    return True
                # binary search
                lo, hi = 0, len(lst)
                while lo < hi:
                    mid = (lo + hi) // 2
                    if lst[mid] < time:
                        lo = mid + 1
                    else:
                        hi = mid
                return lo == len(lst) or lst[lo] != time

            # stay
            nt = tcur + 1
            if ok(v, nt) and (v, nt) not in dist:
                dist[(v, nt)] = True
                q.append((v, nt))

            for to in g[v]:
                nt = tcur + 1
                if ok(to, nt) and (to, nt) not in dist:
                    dist[(to, nt)] = True
                    q.append((to, nt))
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```実装は、DFS をルート化することから始まります。`x`親と深さの情報を確立します。 これは、任意の 2 つのノード間のパスをパスごとに線形時間で再構築するために使用されます。 

各敵は、そのパスに沿って一連の頂点と時間のペアを提供し、それらは次のように保存されます。`occ`。 これらのリストの並べ替えは、BFS 中の時間チェックを高速に行うために必要です。 

BFS 状態には明示的に時間が含まれており、訪問した状態を次のように保存します。`(vertex, time)`ペアを使用して、同じ構成が再度使用されることを防ぎます。 異なる時間に同じノードに到達すると、将来の可能性も異なるため、これは非常に重要です。 

の`ok`関数は二分探索を実行して、特定の時点で頂点が占有されているかどうかを判断します。 これにより、各遷移がそのノードへの敵の訪問数において対数的なままになることが保証されます。 

微妙な点は、「待機」と「移動」の両方の遷移が対称的に扱われることです。 待機遷移がないと、敵の横断を避けるために移動を遅らせる必要がある場合、アルゴリズムは失敗します。 

## 実用的な例

 ### 例 1

 入力:```
4 1 1 4
1 2
2 3
3 4
4 1
```チェーンに沿って 4 から 1 に移動する敵が 1 人います。 

| ステップ | ノード | 時間 | アクション |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 開始 |
 | 2 | 1 | 2 | 待って |
 | 3 | 2 | 3 | 移動 |
 | 4 | 3 | 4 | 移動 |
 | 5 | 4 | 5 | リーチ |

 マラットはパスに入る前に一度待機する必要があります。そうしないと、時間 2 に頂点 2 で敵と遭遇することになります。BFS は待機と移動の両方を自然に探索し、最も早く安全に到着することを選択します。 

### 例 2

 入力:```
3 1 1 3
1 2
2 3
2 3
```敵は2→3と移動しますが、マラットは1から開始します。 

| ステップ | ノード | 時間 | 紛争 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | なし |
 | 2 | 1 | 2 | 安全にお待ちください |
 | 3 | 2 | 3 | 無事到着 |

 時間 1 で待機せずに、時間 2 で 2 に移動すると、2 で敵と衝突します。アルゴリズムは正しく移動を 1 ステップ遅らせます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + Σパス長) log m) | 各 BFS 状態は、移動ごとにバイナリ チェックを使用して O(deg(v)) で拡張されます。 
| スペース | O(n + Σocc) | 隣接関係とすべての敵の占有イベントを保存します。 

すべての敵を通る経路の合計の長さは次のように制限されます。`m * n`、しかし、`m ≤ 200`実際の共有トラバースでは、グローバル制約の制限内に留まります。`Σn ≤ 10^5`。 BFS 状態空間は、実行可能なパスに沿った時間拡張のみによって制御されます。

 ## 特殊なケース

 重要なエッジケースは、マラットがパスに入る前に、開始時に連続する複数のステップを待たなければならない場合です。 この状況では、近隣住民全員が、`x`早期にブロックされる可能性があり、待機中の遷移のみが有効です。 BFS には繰り返しが含まれます`(x, t)`状態に対応し、特別なケースを使用せずにプログレッシブ待機を可能にします。 

もう 1 つのエッジ ケースは、最適なパスが敵が通過した後、敵が静止する前に頂点に入る必要がある場合です。 占有は正確な時刻で保存されるため、二分探索により、頂点全体の回避ではなく、正確な時刻の衝突のみが確実に拒否されます。 

最後の微妙なケースは、複数の敵が異なる時間に同じ頂点に重なる場合に発生します。 頂点ごとにソートされたリストは、複数の互いに素な禁止タイムスロットを正しく処理し、BFS トランジションは競合する各タイムスタンプを個別にスキップするだけです。
