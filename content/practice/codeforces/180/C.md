 ## 解決策
 ## 問題の理解

 大文字と小文字で構成される文字列が与えられます。 Patrick は、これを「派手な」文字列に変換したいと考えています。これは、左側がすべて大文字、右側がすべて小文字であると定義されています。 1 回のアクションで、どんな文字でも大文字と小文字を変更できます。 私たちの目標は、派手な形式を実現するために必要なそのようなアクションの最小数を計算することです。 

入力文字列は 100,000 文字まで可能です。 これにより、考えられるすべてのパーティションを検査し、線形時間で各パーティションの変更数を最初から計算するソリューションは即座に除外されます。これは O(n²) であり、遅すぎるためです。 文字列を最大でも一定の回数、理想的には O(n) 回スキャンするソリューションが必要です。 文字列は空ではないことが保証されているため、空の入力ケースを処理する必要はありませんが、すでにすべて大文字、すべて小文字、または交互文字になっている文字列を処理する必要があります。 

文字列がすでに派手な場合、明らかではないエッジケースが発生します。 たとえば、入力`ABCdef`変更は必要ありません。常に両側をカウントする単純なアプローチでは、誤って正の数が出力される可能性があります。 もう 1 つのトリッキーなシナリオは、`aAaA`、大文字と小文字が完全に交互に配置されます。 アルゴリズムは、文字列の中央にある可能性のある最適な分割点を正確に計算し、その分割点に一致するように文字を変更する必要があります。 

## アプローチ

 ブルートフォース手法では、0 から n までの文字列のすべての分割を反復し、左側をすべて大文字として扱い、右側をすべて小文字として扱います。 各分割について、左側のセグメントの小文字の数と右側のセグメントの大文字の数を数えます。 これらを合計すると、その分割に必要なアクションの数が得られます。 次に、すべての分割にわたって最小値を取得します。 これは概念的には簡単ですが、n 個の分割のそれぞれについて両側の文字を数えるには O(n) が必要となるため、コストは最悪の場合 O(n²) になります。 これは、n が 100,000 までの場合には遅すぎます。 

最適化のための重要な洞察は、問題をプレフィックス/サフィックスのカウント戦略に帰着できるということです。 各インデックスについて、その位置までの小文字の累積数と、その位置から最後までの大文字の累積数を事前に計算できます。 次に、任意の分割点について、これらの累積カウントを使用して、O(1) で必要な変更の数を計算できます。 これにより、全体の複雑さが O(n) 時間と O(n) 空間に軽減されます。 概念的には、プレフィックス カウントを構築するために左から右に 1 回スキャンし、サフィックス カウントを作成するために右から左に 1 回スキャンして、単一の線形パスですべての分割ポイントを評価します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | プレフィックス/サフィックス数 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックス配列を計算する`lower_prefix`どこ`lower_prefix[i]`小文字の数を数えます`s[0..i-1]`。 これは、後で分割した場合に、左側のセグメントをすべて大文字に変換するのに必要な変更の数を表します。`i-1`。 
2. サフィックス配列を計算する`upper_suffix`どこ`upper_suffix[i]`大文字の数を数えます`s[i..n-1]`。 これは、前に分割した場合に右セグメントをすべて小文字に変換するのに必要な変更の数を表します。`i`。 
3. 変数を初期化する`min_actions`たくさんの数で。 すべての分割点を反復処理する`i`0からnまで。 各分割に必要なアクションの数は次のとおりです。`lower_prefix[i] + upper_suffix[i]`。 アップデート`min_actions`すべての分割で最小限に抑えます。 
4. 出力`min_actions`。 

機能する理由: すべての分割点で、プレフィックス配列は左側で大文字に変換する必要がある小文字の数を正確に示し、サフィックス配列は右側で大文字を小文字に変換する必要がある文字の数を示します。 すべての分割を評価すると、大文字と小文字の分割としてどんな派手な文字列も表現できるため、グローバルに最適な点が確実に見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

lower_prefix = [0] * (n + 1)
for i in range(n):
    lower_prefix[i + 1] = lower_prefix[i] + (1 if s[i].islower() else 0)

upper_suffix = [0] * (n + 1)
for i in range(n - 1, -1, -1):
    upper_suffix[i] = upper_suffix[i + 1] + (1 if s[i].isupper() else 0)

min_actions = n  # maximum possible actions is n
for i in range(n + 1):
    actions = lower_prefix[i] + upper_suffix[i]
    if actions < min_actions:
        min_actions = actions

print(min_actions)
```プレフィックス配列とサフィックス配列には、文字列の繰り返しスキャンを避けるために累積カウントが保存されます。 計算するループ`min_actions`最初の文字の前と最後の文字の後を含む、考えられるすべての分割点を評価します。これにより、すでにすべて大文字またはすべて小文字になっている文字列が正しく処理されます。
