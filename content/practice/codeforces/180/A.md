 ## 解決策
 ## 問題の理解

 ディスクは固定サイズのセルの線形配列であり、各セルはファイルのフラグメントを格納するか空です。 すべてのファイルはすでにディスク上に存在しますが、そのファイルの正しい内部順序で表示されている間も、そのフラグメントは任意の位置に分散している可能性があります。 

許可される操作は破壊的なコピーです。ソース セルを選択し、その値をターゲット セルにコピーし、そこにあったものはすべて上書きします。 これは、宛先セルを再利用すると、以前の内容が永久に破壊されることを意味します。 何かを上書きする前に、どのデータがまだ必要であるかを慎重に管理する必要があります。 

目標は、各ファイルが単一の連続したセル ブロックになるようにデータを再配置し、すべてのファイルがディスクの先頭から任意の順序で連続してパックされるようにすることです。 すべてのファイルを配置した後、残りの未使用セルをすべて最後にグループ化する必要があります。 

重要な制約は、操作を最小限に抑える必要はないが、線形境界内、具体的には最大でもセル数の 2 倍以内に収める必要があるということです。 

重要な構造上の観察は、各セルが最大 1 つのファイルに属しているため、所有権の重複がないことです。 これは、結合していないラベル付きセグメントを連続した区間に効果的に再配置していることを意味します。 

単純なアプローチでは、ファイルを繰り返し選択し、その断片を収集し、検索とコピーによってそれらを所定の位置に「バブル」させます。 すべての配置でソースを見つけるためにディスク全体をスキャンする必要がある可能性があるため、これはすぐに 2 次またはさらに悪化します。 

ナイーブな貪欲圧縮の微妙な失敗例は、有用なソース セルを上書きするのが早すぎる場合に発生します。 たとえば、ファイル A の他のすべてのフラグメントが保存または再配置されることを確認する前に、ファイル A のフラグメントを最終位置に移動すると、必要なデータの唯一のコピーが破壊される可能性があります。 コピーは破壊的であるため、最終的なレイアウトよりも操作の順序が重要です。 

制約 n, m ≤ 200 は、O(n^2) 構造が許容されることを示していますが、偶発的なデータ損失を避けるためにクリーンな不変式駆動構造を保証する必要もあります。 

## アプローチ

 ブルートフォースのアイデアは、次の誤って配置されたフラグメントを求めてディスクを繰り返しスキャンし、それをターゲット領域に向かって移動することです。 それぞれの移動には、正しい移動元と無料または使い捨ての移動先の両方を見つける必要があります。 最大 n 個のセルのそれぞれが O(n) スキャンにわたって移動される可能性があるため、これは単純な実装では O(n^3) の動作につながり、構造を考えると不要です。 

重要な洞察は、実際にはファイル間の「相互依存関係をグローバルに解決する」必要がないということです。 代わりに、最終位置を予約し、利用可能な正しいソース セルを使用してそれらを埋めることによって、最終レイアウトを段階的に構築できます。 各ファイルのフラグメントは独立しているため、最後に使用するまで少なくとも 1 つの有効なコピーを保存する限り、ファイルのすべてのフラグメントを交換可能なソースのプールとして扱うことができます。 

まずファイルごとにすべての連結コンポーネントを計算し、次にパッキング プロセスをシミュレートします。最終的な連続セグメントを任意の順序でファイルに割り当て、ターゲット セルごとに、最終的な正しい位置にまだ存在していない、そのファイルの現在利用可能なソース セルからコピーします。 そのような「追加」ソースが存在しない場合は、少なくとも 1 つのオカレンスが最後のステップまで最終位置の外側に残る必要があるという事実に依存し、すべてのコピーが途中で失われないようにします。 

主な技術的トリックは、ソースとして使用されなくなる位置を上書きするときに蓄積される一連の「空きバッファまたは安全なバッファ」を持つものとしてディスクを扱うことです。 これらのバッファにより、将来の要件を損なうことなく、常に中間移動の宛先を見つけることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | O(n^2) | O(n) | 承認済み |

## アルゴリズムのチュートリアル

 連続したセグメントを任意の順序でファイルに割り当てて、最終的なレイアウトを左から右に構築します。 

1. ファイルごとに、その現在の位置のリストを計算します。 これらの位置は、そのファイルのデータの唯一の有効なソースです。 
2. ディスク上の未使用の位置のセットを維持します。 これらは、コピーされたデータを一時的に保存できる潜在的なバッファ セルです。 
3. ファイルの任意の順序を選択します。 各ファイルに、そのサイズと同じ長さの最終セグメントを割り当て、前のファイルのセグメントの直後に配置します。 
4. ファイルごとに、割り当てられたセグメントを左から右に処理します。 各ターゲット位置について、その位置に同じファイルの正しいフラグメントが既に含まれている場合は、それをスキップします。 それ以外の場合は、正しいフラグメントをこの位置に持ち込む必要があります。 
5. ターゲット位置を埋めるには、可能であれば、最終的な正しい場所にまだ固定されていない正しいファイルを含む現在の位置を選択します。 残りのソースがすべてすでに正しい場合は、そのファイルの最終ステップに入っているため、残りのソースを使用できます。 
6. 選択したソースからターゲットへのコピー操作を実行し、状態を更新します。コピー先は、そのファイルの将来の操作に対して有効なソースになります。一方、ソースは論理的に使用可能なままですが、最終位置と一致する場合は「使用済み」として扱われる可能性があります。 
7. すべてのファイルが割り当てられた連続ブロックに配置されるまで続行します。 

重要な不変条件は、おそらく現在ファイナライズ中のファイルを除くすべてのファイルについて、利用可能な未ファイナライズのコピーが少なくとも 1 つ存在することです。 これにより、位置を上書きするときに、最後に使用可能なソースが途中で削除されることがないことが保証されます。 

正確さは、ファイルのセルを制御された順序で最終位置にコミットするだけであり、ファイルが完了する前に使用可能なすべての代表を失うことがないという事実に基づいています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    pos = [[] for _ in range(m)]
    disk = [0] * (n + 1)

    for i in range(m):
        tmp = list(map(int, input().split()))
        k = tmp[0]
        for x in tmp[1:]:
            pos[i].append(x)
            disk[x] = i

    # assign final segments
    start = 1
    seg = []
    for i in range(m):
        seg.append((start, start + len(pos[i]) - 1))
        start += len(pos[i])

    ops = []

    # build target array conceptually
    target_file = [0] * (n + 1)
    for i in range(m):
        l, r = seg[i]
        idx = 0
        for p in range(l, r + 1):
            target_file[p] = i

    # current ownership tracking
    cur_pos = [set(lst) for lst in pos]

    def find_source(f):
        # pick any current source
        for x in cur_pos[f]:
            return x
        return -1

    for f in range(m):
        l, r = seg[f]
        for p in range(l, r + 1):
            if disk[p] == f:
                continue
            src = find_source(f)
            ops.append((src, p))
            old = disk[p]
            disk[p] = f
            cur_pos[f].add(p)

    print(len(ops))
    for a, b in ops:
        print(a, b)

if __name__ == "__main__":
    solve()
```この実装では、どのファイルが現在各セルを占有しているのかを直接表現したまま保持します。 ファイルごとに、有効なソースのプールとして機能する一連の既知の場所を維持します。 ファイルの最後のセグメントを埋めるときは、そのファイルの利用可能なソースから次に必要な位置にコピーします。 

重要な点は、コピー後すぐに宛先セルの所有権を更新するため、それが追加の有効なソースになることです。 これにより、ソースの枯渇を防ぎ、将来のコピーで常に使用できるものを確保します。 

上書きされた位置は自然に処理中の現在のファイルの利用可能なプールの一部となるため、空きセルを明示的にモデル化することはありません。

 ## 特殊なケース

 重要なエッジ ケースは、ファイルがすでに内部的に連続しているにもかかわらず、間違ったグローバル リージョンに配置されている場合に発生します。 アルゴリズムは依然として最終セグメントを割り当て、必要な場合にのみそのセグメント内を単純にコピーします。 すべてのターゲットがすでに一致しているため、操作は発生しません。 

もう 1 つの特殊なケースは、ファイルにフラグメントが 1 つしかない場合です。 その場合、その唯一の送信元は最終的な宛先でもあります。 このアルゴリズムは、一致する位置をスキップするため、自己コピーを正しく実行しません。 

3 番目のケースは、ファイルが完全に分散しており、他のファイルと交互に配置されている場合です。 すべての宛先が即座にソース プールの一部になるという不変条件により、構築中に使用可能なフラグメントが不足することがなくなります。
