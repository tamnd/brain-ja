 ## 解決策
 ## 問題の理解

 それぞれが _m_ 色のいずれかで塗られた立方体の行があり、すべて同じ色の立方体の連続セグメントの長さを最大化するために、最大 _k_ 個の立方体を削除することができます。 入力は、立方体の数 _n_、色の数 _m_、最大削除数 _k_、および立方体の色の順序を提供します。 出力は単一の整数です。つまり、最大 _k_ 個の立方体を削除した後の、単一色の最も長い連続セグメントの長さです。 

主な課題は、配列が最大 2・10^5 立方体と大きくなる可能性があるため、どの解も _n_ においてほぼ線形または線形でなければならないことです。 すべての部分配列またはすべての削除パターンを試す 2 次アプローチは、最悪の場合、最大 4・10^10 の演算を必要とするため、実行不可能です。 色の数も最大 10^5 と大きくなる可能性があるため、色ごとに大量の操作を行うすべての色を反復するソリューションでは、効率を維持するように注意する必要があります。 

誤って処理されやすいエッジ ケースには、_k_ が 0 の場合が含まれます。この場合、キューブは削除できないため、アルゴリズムは既存の最長の連続セグメントを正しく検出する必要があります。 もう 1 つは、すべての立方体が同じ色の場合です。 最大スコアは _k_ に関係なく _n_ です。 _k_ が大きいものの、他のすべての色を削除するのに十分ではない場合でも、アルゴリズムは _k_ までの削除のみを正しく考慮する必要があります。 小さなシーケンス、色が交互に現れるシーケンス、および 2 色だけのシーケンスも、単純な実装では削除のカウントを間違えたり、位置を間違えたりする可能性があるため、微妙です。 

## アプローチ

 ブルートフォース手法では、シーケンスのすべての部分配列を考慮し、色ごとに、その部分配列全体をその色にするために削除する必要がある立方体の数を数えます。 次に、必要な削除が最大 _k_ である最大のサブ配列を追跡します。 原理的には正しいですが、このアプローチは最悪の場合 O(n^2・m) になります。O(n^2) 個の部分配列があり、各部分配列についてすべての色を検査する可能性があります。 これは、n = 2・10^5 にとっては遅すぎます。 

重要な洞察は、単一色の連続したセグメントのみを考慮しているということです。 固定色 _c_ の場合、立方体が色 _c_ ではない位置を、削除される可能性のある「ギャップ」として扱うことができます。 次に、問題は、非 _c_ キューブの数が _k_ を超えない最長の部分配列を見つけることに帰着します。 これは、2 ポインターまたはスライディング ウィンドウ手法を使用して効率的に解決できます。つまり、ウィンドウ [l, r] を維持し、その中にある非 _c_ キューブを数えます。 _c_ cube 以外の個数が k 以下の間は右端を拡張し、k 個を超えると左端を前方に移動します。 シーケンス内に存在するすべての色に対してこれを繰り返します。 

このアプローチが機能するのは、2 ポインター ウィンドウが常に最大 _k_ 個の削除で特定の色の最大の連続セグメントを維持するためです。 色が _c_ と異なる位置のみを考慮するため、計算は色ごとのシーケンスの長さにおいて線形です。 一意の色の数は最大 _m_ であるため、合計の複雑さは O(n · m_unique) になります。ここで、m_unique は実際に存在する個別の色の数です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2・m) | お(1) | 遅すぎる |
 | カラーごとのスライディング ウィンドウ | O(n·m_unique) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. シーケンス内の固有の色を数え、各色 _c_ を繰り返します。 各色は独立して処理され、それに焦点を当てた場合に達成可能な最大の連続セグメントが見つかります。 
2. 2 つのポインタを初期化します。`l`そして`r`、シーケンスの開始時に。 これらのポインターは、現在検討されているキューブのスライディング ウィンドウを定義します。 カウンターを維持する`bad`ウィンドウ内の色 _c_ ではない立方体の場合。 
3. 右ポインタを展開します`r`一つ一つ。 立方体がその位置にある場合`r`color _c_ ではありません。増分です`bad`。 
4. もし`bad`を超える`k`、増分`l`ウィンドウを左から次まで縮小します。`bad`再び ≤ k。 ウィンドウから出た立方体の色が _c_ ではなかった場合、デクリメントします`bad`。 
5. 各ステップで、グローバル最大値を更新します。`best`現在のウィンドウのサイズ (`r - l + 1`）。 
6. 色のすべての位置を処理した後、次の色に移動します。 すべての色を処理した後、`best`最大 _k_ 個の削除で達成可能な最大スコアが含まれます。 

機能する理由: いつでも、ウィンドウには、k 個以下の削除で形成できる最大の連続する色の部分配列 _c_ が含まれています。 不変条件とは、`bad`は常に、現在のウィンドウ内の非 _c_ キューブの数を正確にカウントします。 ウィンドウを拡大または縮小すると、許可された削除数を超えることがなくなり、すべての色をスキャンすることで絶対最大数が確実に見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())
colors = list(map(int, input().split()))

from collections import Counter
unique_colors = set(colors)

best = 0

for c in unique_colors:
    l = 0
    bad = 0
    for r in range(n):
        if colors[r] != c:
            bad += 1
        while bad > k:
            if colors[l] != c:
                bad -= 1
            l += 1
        best = max(best, r - l + 1)

print(best)
```このソリューションは、スライディング ウィンドウを使用して、現在のセグメント内に非ターゲット カラーの立方体がいくつあるかを追跡することにより、すべての一意の色を反復処理します。 このカウントが _k_ を超えると、セグメントが再び有効になるまでウィンドウの左端が前方に移動します。 各ウィンドウ サイズはグローバル最大値と比較されます。`best`、すべての色にわたる最大の有効なセグメントが累積されます。 一意の色のセットを使用すると、配列に存在しない色に対する不必要な反復が回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n·m_unique) | シーケンスを一意の色ごとに 1 回スキャンします。 各スキャンは n 単位で線形です。 |
 | スペース | O(n) | 色の配列と一意の色のセットを保存します。 |

 n ≤ 2・10^5 および m_unique ≤ n であるため、絶対的な最悪のケースでは合計操作は ≤ 4・10^10 になりますが、実際には m_unique ははるかに小さいことが多く、アルゴリズムは Python で 1 秒未満で快適に実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m, k = map(int, input().split())
    colors = list(map(int, input().split()))
    unique_colors = set(colors)
    best = 0
    for c in unique_colors:
        l = 0
        bad = 0
        for r in range(n):
            if colors[r] != c:
                bad += 1
            while bad > k:
                if colors[l] != c:
                    bad -= 1
                l += 1
            best = max(best, r - l + 1)
    return str(best)

# provided samples
