 ## 解決策
 ## 問題の理解

 入力は、記録されたキーパッド履歴などの固定の一連の数字と、指紋のあるキーに対応する別の一連の数字を記述します。 タスクは、元のシーケンスを左から右にスキャンし、キーがフィンガープリントとしてマークされている数字のみを保持することによって、形成できる可能な限り長いコードを再構築することです。 保持される数字の相対的な順序は変更してはならず、フィルタリングを超えて任意に並べ替えたりスキップしたりすることはできません。 

したがって、出力は、元の順序を維持したまま、フィンガープリント セットのメンバーシップによってフィルター処理された単純な元のシーケンスになります。 

制約は非常に小さく、シーケンスの長さとフィンガープリントされた桁数の両方が 10 で区切られています。これにより、線形フィルタリングから 2 次またはブルートフォースのサブセット チェックに至るまで、あらゆるソリューションが即座に実行されることがすぐに分かりますが、同時に、意図したソリューションが検索問題ではなく単純な実装タスクである可能性が高いこともわかります。 

いくつかの特殊なケースは微妙な意味で重要です。 

シーケンス内のどの数字もフィンガープリントされない場合、出力は空になります。 たとえば、シーケンス`3 4 5`指紋セット付き`1 2 7`何も生み出さない。 少なくとも 1 つの一致を想定し、チェックせずに出力する単純な実装では、誤ってガベージや余分なスペースが出力される可能性があります。 

すべての数字がフィンガープリントされた場合、出力は変更されていない元のシーケンスになります。 たとえば、シーケンス`1 2 3`指紋セット付き`1 2 3`シーケンス全体を正確に再現する必要があります。 

もう 1 つの特殊なケースは、フィンガープリント セットがソートされた順序で表示されない、またはシーケンスの順序と一致しない可能性があることです。 たとえば、シーケンス`5 1 0 7`指紋付き`0 1 7`生産しなければならない`1 0 7`、数値ではなく、シーケンス内の出現順に並べ替えられます。 

## アプローチ

 この問題を考える強引な方法は、指定されたシーケンスのすべてのサブシーケンスを考慮し、そのすべての要素がフィンガープリント セットに含まれているかどうかを確認することです。 これらの有効なサブシーケンスの中で、最も長いものを選択します。 これは、すべての可能性を明示的に探索するため機能しますが、長さ n のシーケンスの部分シーケンスの数は 2ⁿ であり、ここでは n が小さいにもかかわらず、急速に増加します。 各有効性チェックにはスキャン要素も必要となるため、これは不要なオーバーヘッドになります。 

重要な観察は、実際にはサブシーケンス間を検索する必要がまったくないということです。 この問題は、辞書編集上の順序を最大化することや、矛盾するオプションの中から選択することなど、追加の制約を課すことはありません。 唯一の要件は、選択されたすべての数字が許可され、その順序が保持されることです。 これにより、組み合わせの選択が削除されます。シーケンス内の各位置について、フィンガープリント セットのメンバーシップのみに基づいて、それを保持するかどうかを個別に決定します。 

したがって、問題は単一の線形パス、つまりセットのメンバーシップによって要素をフィルター処理するというものに集約されます。 

ブルートフォースアプローチは、すべての可能性を列挙するため概念的には機能しますが、指数関数的な増加により効率が低下します。 異なる位置での決定間に依存関係がないという観察により、タスクは要素ごとの単純なメンバーシップ テスト (集合を使用した O(1)) に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2ⁿ・n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. シーケンスの長さ、フィンガープリント数、シーケンス自体、およびフィンガープリントの桁を読み取ります。 目標は、どの数字が許可されているかを迅速に特定することです。 
2. 指紋の数字をハッシュ セットに保存します。 これは、数字のメンバーシップのクエリに一定時間内に応答できるようにするために行われます。 
3. 元のシーケンスを左から右に繰り返します。 各桁について、それが指紋セットに存在するかどうかを確認します。 
4. 数字がセット内にある場合は、その数字を出力シーケンスに追加します。 そうでない場合は、完全に無視してください。 
5. すべての数字を処理した後、結果として得られるフィルター処理されたシーケンスをスペースで区切って出力します。 何も収集されなかった場合は空行を出力します。 

この手順の背後にある理由は、シーケンス内の各位置が独立しているということです。 数字が含まれるかどうかは、その数字が許可されるかどうかによってのみ決まり、前後に何があるかどうかには依存しません。 

### なぜ効果があるのか

 構築された出力には、フィンガープリント条件を満たす元のシーケンスの要素が正確に含まれます。 順序を変更せずに左から右に繰り返すため、相対的な順序は自動的に保持されます。 すべての有効なサブシーケンスは、すでに順番に出現している数字のみを使用でき、すべての有効な候補を個別に含めるため、これより長い有効なシーケンスを生成する可能性はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    allowed = set(map(int, input().split()))

    res = []
    for x in a:
        if x in allowed:
            res.append(str(x))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```このソリューションでは、オーバーヘッドを回避するために高速 I/O を使用して入力を読み取りますが、制約を考慮すると厳密には必要ありません。 

指紋の数字は、と呼ばれるセットに保存されます。`allowed`これにより、O(1) メンバーシップ チェックが有効になります。 これは、検索やネストされたループの必要性を置き換える中心的な最適化です。 

ループオーバー`a`ダイレクトフィルターです。 最終的な出力フォーマットにはスペースで区切られた整数が必要であるため、各数字は保持される場合にのみ文字列に変換されます。 

結合操作は、空でない出力と空の出力の両方を正しく処理します。 もし`res`空です、`" ".join(res)`空の文字列が生成されます。これは、何も表示されない、または空白行が表示されるという要件を満たします。 

## 実用的な例

 サンプルの順序を検討してください`7 5 3 1 6 2 8`指紋数字付き`1 2 7`。 

各ステップでメンバーシップを確認します。 

| インデックス | 数字 | 指紋で | これまでの出力 |
 | --- | --- | --- | --- |
 | 0 | 7 | はい | 7 |
 | 1 | 5 | いいえ | 7 |
 | 2 | 3 | いいえ | 7 |
 | 3 | 1 | はい | 7 1 |
 | 4 | 6 | いいえ | 7 1 |
 | 5 | 2 | はい | 7 1 2 |
 | 6 | 8 | いいえ | 7 1 2 |

 最終的な出力は次のとおりです`7 1 2`、フィルタリングが要素ごとに純粋にローカルである一方で、順序が保持されることを示しています。 

Now consider a constructed example: sequence`4 0 9 1`指紋付き`0 1`。 

| インデックス | 数字 | 指紋で | これまでの出力 |
 | --- | --- | --- | --- |
 | 0 | 4 | いいえ | |
 | 1 | 0 | はい | 0 |
 | 2 | 9 | いいえ | 0 |
 | 3 | 1 | はい | 0 1 |

 これにより、アルゴリズムが、順序を失うことなく、有効な数字が無効な数字とインターリーブされるケースを正しく処理していることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 要素ごとに O(1) メンバーシップ チェックを行うシーケンスの単一パス |
 | スペース | O(m) | Set は指紋の数字を保存します。 

入力境界は非常に小さいため、この線形スキャンはパフォーマンスの限界をはるかに下回ります。 はるかに大きな制約がある場合でも、定数時間フィルタリングにより、このアプローチの効率は維持されます。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():

    allowed = set(map(int, input().split()))

    res = []
    for x in a:
        if x in allowed:
            res.append(str(x))
    print(" ".join(res))

 ## 特殊なケース

 フィンガープリント セットに一致する数字がない場合、アルゴリズムは空の結果リストを作成します。 たとえば、入力`3 2 / 3 4 5 / 1 2`決して追加をトリガーしないため、`res`は空のままであり、必要に応じて印刷すると空行が生成されます。 

すべての桁が一致する場合、たとえば`4 4 / 1 2 3 4 / 1 2 3 4`、すべての反復が結果に追加されます。 最終出力は入力シーケンスを正確に反映しており、フィルタリングによって順序が歪められていないことが確認されます。 

一致がまばらで離れている場合、次のように`6 2 / 1 0 1 0 1 0 / 1 0`、アルゴリズムは追加とスキップを交互に行います。 各決定はローカルであるため、出力は次のようになります。`1 0 1 0 1 0`、後戻りや再構築を必要とせずに完全な構造を保存します。
