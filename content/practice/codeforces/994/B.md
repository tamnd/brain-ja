 ## 解決策
 ## 問題の理解

 各騎士には、戦闘力とコインの隠し場所という 2 つの属性があります。 ナイトは、厳密に弱い力のナイトのみを倒すことができ、勝利するたびに、倒されたナイトのコインが勝者に譲渡されます。 ただし、全体的な制約があります。つまり、騎士以上のものを倒したい騎士はいないということです。`k`その他。 

課題は、各騎士がこれらのルールに基づいて最適な一連の戦いを個別に計画し、各騎士が最終的に獲得できるコインの最大数を計算することを想像することです。 

入力により、強さの配列と、インデックスによって整列されたコインの値の配列が得られます。 出力は別の配列で、各位置がナイトに対応し、そのナイトから始まる最高の達成可能な合計コインが含まれます。 

制約は解空間を強力に形成します。 最大 100,000 人の騎士がいる場合、すべてのペア間の戦いをシミュレートしようとするアプローチはすぐに二次関数になり、実行不可能になります。 ナイーブ$O(n^2)$戦略はすでに次の順序で実行されます$10^{10}$最悪の場合の比較は、1 秒の制限時間の許容範囲をはるかに超えています。 追加の制限は、$k \le 10$これは重要な構造上のヒントです。各騎士は、すべての弱い騎士の中で最も少数の最良の候補者にのみ関心を持っています。 

強さで分類せずに欲張って考えると微妙な失敗例が現れます。 ナイトが近くのインデックスのみを考慮すると、入力順序で後から現れても実際には有効なターゲットである弱いナイトを見逃す可能性があります。 たとえば、強みがあるとすれば、`[10, 1, 2]`、最初の騎士は他の騎士を両方倒すことができますが、ソートなしで位置ベースのスキャンを行うと、順序付けが意味のあるものとして誤って扱われてしまいます。 もう 1 つのよくある落とし穴は、「最大 k キル」という制約を無視して、弱いコインをすべて合計するだけです。これは、価値の低い弱いナイトが多数あり、価値の高いナイトを少数のみ選択する必要がある場合に失敗します。 

## アプローチ

 直接的な解釈は、すべての騎士を他のすべての騎士と比較して試し、どの騎士が弱いかを確認し、最大で最適なサブセットを選択することを示唆しています。`k`その中で。 これは、考えられるすべての有効な選択肢を評価するため、原理的には正しいですが、各ナイトについて他のすべての選択肢をスキャンしてから並べ替えまたは選択する可能性があるため、時間がかかりすぎます。`k`最適な候補を選択すると、総コストはおよそ$O(n^2 \log n)$。 

構造の単純化は制約を分離することで実現します。 強さは殺害の実現可能性を決定し、コインは望ましさを決定します。 強さの昇順にナイトを処理すると、ナイトを処理した時点で、以前に処理されたすべてのナイトが、まさにそのナイトが殺害を許可されているものになります。 問題は、この順序のプレフィックスごとに、最大でも可能な限り最適なサイズのサブセットを維持することになります。`k`コインの価値によって。 

ナイトごとに最適なサブセットを最初から再計算するのではなく、最上位のみを含む小さな構造を維持します。`k`これまでに確認されたすべての弱い騎士のコインの価値。 以来`k`最大でも 10 の場合、最小ヒープは効率的に機能します。現在の最適な候補を保存し、新しい弱いナイトが現れるたびに、それが上位に属するかどうかを決定します。`k`。 これにより、選択ステップが小さな定数を使用した対数時間に変わります。 

重要な移行点は、各騎士の答えが、最も弱い騎士に属するコインのマルチセットのみに依存することです。`k`要素。

 ## アルゴリズムのチュートリアル

 まず、ナイトの有効なターゲットがすべてその前に表示されるように、強度を増加してナイトの順序を変更します。 

1. 各騎士の強さ、コイン、オリジナルのインデックスを組み合わせて 1 つの構造にし、これらの構造を強さ順に並べ替えます。 これにより、ナイトを処理するときに、以前に処理されたすべてのナイトが厳密に弱いことが保証されます。 
2. ヒープ内容の累計とともに、選択した弱いナイトのコイン価値を保存する最小ヒープを維持します。 ヒープにはそれ以上の内容が含まれることはありません`k`要素。 この構造は、以下の最適なセットを表します。`k`これまでに利用可能なキル数。 
3. ソートされた順序でナイトを繰り返します。 現在のナイトをヒープに挿入する前に、それ自体のコインと現在のヒープの合計としてその答えを計算します。 これが機能するのは、現時点のヒープにはまさに最良のものが含まれているためです。`k`厳密に弱いすべての騎士からのコイン。 
4. 現在の騎士のコインの価値をヒープに挿入し、それを現在の合計に加算します。 ヒープサイズを超える場合`k`、最小の要素を削除し、合計から差し引きます。 これにより、最も収益性の高いものだけが維持されます`k`将来の強い騎士候補。 
5. すべてのナイトを処理した後、保存されているインデックスを使用して結果を元の順序に復元します。 

中心となるアイデアは、各ナイトが強度でソートされた配列に対してプレフィックス構造をクエリし、プレフィックスが最大で可能な限り最良のセットとして継続的に維持されるということです。`k`コインの価値。 

### なぜ効果があるのか

 ナイトを処理する瞬間、ヒープにはまさに`k`強さが小さい騎士の中で最もコインの価値が高い。 この騎士にとって最適な戦略は、これらの弱い騎士からのみ選択できます。`k`、選択したサブセットを最適なサブセットに置き換えます。`k`利用可能な場合は合計を減らすことはできません。 これにより、ヒープが常に将来のすべてのナイトに対して設定された最適な選択肢を表すため、計算された各答えが最適であることが確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

n, k = map(int, input().split())
p = list(map(int, input().split()))
c = list(map(int, input().split()))

knights = [(p[i], c[i], i) for i in range(n)]
knights.sort()

heap = []
heap_sum = 0
ans = [0] * n

for power, coins, idx in knights:
    ans[idx] = coins + heap_sum

    heapq.heappush(heap, coins)
    heap_sum += coins

    if len(heap) > k:
        removed = heapq.heappop(heap)
        heap_sum -= removed

print(*ans)
```ソートのステップにより、各答えを計算するときに有効な弱い対戦相手のみを考慮することが保証されます。 ヒープには常にそれらの中から最良の候補が保存され、累計によりヒープ合計を繰り返し再計算する必要がなくなります。 最小ヒープの使用は、サイズが超過するたびに、最も有用でないコインの価値を効率的に削除できるため、非常に重要です。`k`。 

よくある実装上の間違いは、答えを計算する前に現在のナイトをヒープに挿入することです。 これでは、計算上、騎士が誤って「自殺」する可能性があります。 正しい順序は、最初にクエリを実行し、次に挿入することです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline
    import heapq

    n, k = map(int, input().split())
    p = list(map(int, input().split()))
    c = list(map(int, input().split()))

    knights = [(p[i], c[i], i) for i in range(n)]
    knights.sort()

    heap = []
    heap_sum = 0
    ans = [0] * n

    for power, coins, idx in knights:
        ans[idx] = coins + heap_sum

        heapq.heappush(heap, coins)
        heap_sum += coins

        if len(heap) > k:
            heap_sum -= heapq.heappop(heap)

    return " ".join(map(str, ans))

assert run("""4 2
4 5 9 7
1 2 11 33
""") == "1 3 46 36"

assert run("""3 0
10 5 7
100 20 30
""") == "100 20 30"

assert run("""1 0
5
10
""") == "10"

assert run("""5 1
1 2 3 4 5
5 4 3 2 1
""") == "5 9 8 5 1"

assert run("""5 2
5 1 3 2 4
10 100 20 30 40
""") == "10 100 130 120 150"

 ## 特殊なケース

 いつ`k = 0`、ヒープは蓄積には決して使用されません。 各ナイトにとって、答えは単純に自分のコインであり、処理中ヒープは空のままであるため、アルゴリズムは自然にこれを処理します。 

入力ですべての強度が降順になっている場合、並べ替えステップではそれらが完全に逆になります。 このアルゴリズムは入力順序ではなく並べ替え順序のみに依存するため、引き続き機能します。 各ナイトは、処理される前に、弱いものをすべて正しく認識します。 

いつ`k`等しい`n-1`、ヒープは大きくなる可能性がありますが、それでも制限されたままになります。`k`。 弱いナイトがすべて考慮され、ヒープにはそれらの中で上位の値が保持されるため、アルゴリズムは依然として可能な限り最良のサブセットを正しく選択します。
