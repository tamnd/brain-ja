 ## 解決策
 ## 問題の理解

 私たちは増え続ける長方形紙幣のコレクションを処理しています。 メモが追加されるたびに、それは永久に残ります。 その後、これまでに確認されたすべてのメモを特定の長方形の財布の中に入れることができるかどうかを尋ねるクエリを受け取ります。 

ノートは回転できるので、サイズのノート$x \times y$どちらの向きとしても扱うことができます。 紙幣が財布に入る$h \times w$おそらく回転させた後、紙幣の両方の寸法が対応する財布の寸法を超えない場合。 

重要な点は、すべての音符が独立してフィットする必要があるということです。 紙幣間のパッキングの相互作用はないため、ウォレットの条件は、すべての紙幣を個別に収納できる十分な大きさでなければならないということだけです。 

「add」タイプの各クエリは四角形を挿入し、「check」タイプの各クエリは、これまでに挿入されたすべての四角形が指定されたウォレット内に個別に収まるかどうかを尋ねます。 

制約は次のとおりです$5 \cdot 10^5$したがって、クエリごとに以前のすべてのメモをスキャンするソリューションでは、約$O(n^2)$最悪の場合の動作が遅すぎます。 少量の状態のみを保持し、各クエリに一定時間で応答するものが必要です。 

「最大幅と最大高さを独立して」という観点から考えると、微妙な落とし穴が現れます。 回転によって次元が結合されるため、これは失敗します。 たとえば、メモを持っていると、$100 \times 1$そして$1 \times 100$これは、「最大幅」が 100、「最大高さ」が 100 であることを意味しますが、これは両方のノートが実際に個別にすでに良好であることを反映するものではありません。 実際の制約は、グローバル軸の選択ごとではなく、ノートごとの最適な方向に依存します。 

別の失敗モードは、あたかもすべてのノートを一貫して整列させる必要があるかのように、すべてのノートの境界四角形を維持しようとすることから発生します。 この問題では、複数の音符にわたって一貫した方向性が必要ではありません。 各ノートは独立して回転できます。 

## アプローチ

 ブルートフォース手法では、すべてのメモのリストが保持されます。 タイプチェックのすべてのクエリについて、保存されているすべてのメモを反復処理し、ローテーション後にそれぞれがウォレットに収まるかどうかをテストします。 これは、定義を直接適用するため、正しいです。 ただし、最大で$5 \cdot 10^5$クエリの場合、これは最終的にチェックすることになります。$5 \cdot 10^5$クエリごとのメモ、約$10^{11}$最悪の場合の操作は不可能です。 

重要な点は、すべての四角形を追跡する必要はないということです。 ウォレットが失敗するには、適合しない紙幣が 1 枚存在する必要があります。 したがって、毎回すべてのメモをチェックする代わりに、ウォレットをブロックする「最悪の」メモが少なくとも 1 つ存在するかどうかを維持するだけで済みます。 

それぞれの音符$x \times y$は、次のように辺を順序付けることによって正規化できます。$a = \min(x, y)$、$b = \max(x, y)$。 この変換後、すべての音符は正規の方向で表現されます。$a \le b$。 今は財布$h \times w$として扱うこともできます$(\min(h,w), \max(h,w))$。 

メモは両方の場合にのみ適合します$a \le h$そして$b \le w$。 したがって、ウォレットの向きの候補を修正する場合、関連する唯一の制約は、すべての紙幣がその角の下になければならないということです。 

ここで重要な単純化: すべてのノートをチェックする代わりに、「最大の障害物」を追跡する構造を維持します。 最悪のノートは最大値を持つノートです。$a$、その中で最大のものは、$b$。 これにより、制約セットが 2 つの値のみに減ります。 

クエリが到着すると、このペアに対してウォレットの両方の方向がチェックされます。 どちらの方向も保存されている最大制約を支配しない場合、答えは「いいえ」です。 それ以外の場合は「はい」です。 

これが機能するのは、ウォレットを無効にする可能性のあるメモは、何らかの方向で 2 つの次元のいずれかに違反する必要があり、正規表現により、極点に対する優位性のみをテストする必要があることが保証されるためです。

 ## アルゴリズムのチュートリアル

 すべての音符の小さい辺の最大値と正規化後の大きい辺の最大値の 2 つの値を維持しながら、クエリを順番に処理します。 

1. 追加されたメモごとに$x, y$、計算する$a = \min(x, y)$、$b = \max(x, y)$。 これにより方向の曖昧さがなくなり、すべての四角形が一貫した方法で比較できるようになります。 
2. 2 つのグローバル値を維持します。`max_a`すべての中で最大として$a$、 そして`max_b`すべての中で最大として$b$ノート達成のために`max_a`。 これにより、最も制限の厳しい形状がキャプチャされます。 
3. クエリウォレットの場合$h, w$、また次のように正規化します$h \le w$。 これにより、保存されたメモとの一貫した比較が保証されます。 
4. ウォレットに最悪の紙幣を入れることができるかどうかを確認します。 これは、両方が存在するかどうかを検証することを意味します。`max_a ≤ h`そして`max_b ≤ w`。 
5. ウォレットの向きも交換できるため、交換された状態も確認します。`max_a ≤ w`そして`max_b ≤ h`。 
6. どちらの方向でも機能する場合は、「YES」と出力されます。 それ以外の場合は「いいえ」です。 

### なぜ効果があるのか

 すべての音符は正規のペアに還元されます$(a, b)$どこ$a \le b$。 長方形への有効な包含は、このペアをウォレットの選択された方向に配置することに対応します。 実現可能性を妨げる可能性がある唯一のメモは、少なくとも 1 つの次元に適合させるのが最も難しいメモです。 最大値を追跡する$a$最も厳しい「短辺」を尊重し、最大値を追跡することを保証します。$b$これらのうち、対応する「長辺」制約を確実に尊重するようにします。 他のノートはこれらの極端な値のいずれかによって支配されるため、極端な値が一致すると、すべてのノートが一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    max_a = 0
    max_b = 0
    
    for _ in range(n):
        parts = input().split()
        
        if parts[0] == '+':
            x = int(parts[1])
            y = int(parts[2])
            a = min(x, y)
            b = max(x, y)
            
            if a > max_a:
                max_a = a
                max_b = b
            elif a == max_a:
                if b > max_b:
                    max_b = b
        
        else:
            h = int(parts[1])
            w = int(parts[2])
            
            a1, b1 = min(h, w), max(h, w)
            
            ok = (max_a <= a1 and max_b <= b1)
            print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```コードは、標準的な最悪の四角形を増分的に維持します。 挿入ごとに、辞書編集上の最大のペアが更新されます。$(a, b)$まず、タイ間の短辺を最小化し、次に長辺を最大化します。 各クエリは、この最悪の長方形がウォレットに最適な向きで収まるかどうかを単にチェックするだけです。 

よくある間違いは、両方の次元のグローバル最大値のみを独立して追跡しようとすることです。 これらの最大値は異なるノートから得られる可能性があり、単一の長方形で同時に実現できないため、これは失敗します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    max_a = 0
    max_b = 0
    out = []

    for _ in range(n):
        parts = input().split()
        if parts[0] == '+':
            x, y = int(parts[1]), int(parts[2])
            a, b = min(x, y), max(x, y)
            if a > max_a:
                max_a, max_b = a, b
            elif a == max_a:
                max_b = max(max_b, b)
        else:
            h, w = int(parts[1]), int(parts[2])
            a1, b1 = min(h, w), max(h, w)
            if max_a <= a1 and max_b <= b1:
                out.append("YES")
            else:
                out.append("NO")

    return "\n".join(out)

 ## 特殊なケース

 特殊なケースの 1 つは、最大の短辺が最大の長辺とは異なる音符に由来する場合です。 アルゴリズムはこれを処理します。`max_b`対応する場合にのみ更新されます`a`等しい`max_a`、両方の値が互換性のある候補からのものであることを確認します。 

もう 1 つのエッジ ケースは、短辺の最大値のみを変更する繰り返し更新です。 その場合、長辺を新しい候補の長辺にリセットする必要があります。 そうしないと、保存されたペアが実際の長方形と矛盾してしまいます。
