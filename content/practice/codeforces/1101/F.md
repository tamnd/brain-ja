 **解決時間:** 1 分

 ## 解決策
 ## 問題の理解

 一連の都市が 1 本の道路に沿って、原点からの距離が増加するにつれて配置されています。 各トラックは、この道路に沿って出発都市から目的地の都市まで移動します。 トラックは距離に応じて直線的に燃料を消費し、満タンから始動します。 給油できるのは都市部のみであり、各トラックで実行できる給油回数は限られています。 目標は、すべてのトラックが給油制限を超えずに走行を完了できる最小タンク容量を決定することです。 

重要な問題は、燃料消費量、都市での位置、燃料補給の制限などの組み合わせによって発生します。 トラックは、タンクのサイズを最小限に抑えるために、特定の都市をスキップするか、戦略的に燃料を補給する必要がある場合があります。 都市間の距離は長くなる可能性があり (最大 10^9)、トラックの台数も膨大 (最大 250,000 台) であるため、考えられるすべての給油シーケンスを個別に検討する単純なアプローチは実行不可能です。 

エッジケースには、タンクが一度に全距離をカバーしなければならない燃料補給がゼロのトラックや、複数の有効な燃料補給戦略で目的地に到着できるトラックが含まれます。 たとえば、トラックが位置 2 の都市 1 から位置 14 の都市 5 まで 2 つの許可された給油で移動する場合、都市 2 と 4、または都市 3 と 4 で給油する可能性がありますが、最小タンクは、実行可能な順序でカバーする必要がある最長の 1 つの脚によって決まります。 給油ストップの最適な配置を無視した不注意な実装は、必要なタンクを過大評価することになります。 

## アプローチ

 ブルートフォースアプローチでは、給油都市のすべての組み合わせを試し、各区間に必要な最大燃料を計算することで、各トラックの走行をシミュレートします。 これには、トラックごとに、その経路に沿った都市の組み合わせシーケンスを調べる必要があり、最悪の場合、トラックあたり O(2^n) のオーダーの複雑さにつながります。 250,000 台のトラックと最大 400 の都市では、これは不可能です。 

重要な洞察は、問題は、与えられたタンク サイズ V に対して、各トラックが最大許容給油回数でその経路を通過できるかどうかを見つけることに帰着するということです。 各トラックの経路は一連の都市距離であり、距離と燃料消費量の積が V を超えない場合、トラックは連続するセグメントを横断することができます。これは、都市の位置に沿った動的プログラミング アプローチを使用するか、または、特定の V に必要な最小給油回数が V を超える経路の脚の長さによって決まることを認識することでより効率的に解決できます。 

この観察により、V の二分探索が可能になります。候補となるタンク サイズごとに、すべてのトラックが給油制限内で目的地に到着できるかどうかを確認します。 1 台のトラックのチェックは、開始から終了までの都市数が線形です。 トラックの数が多いため、アルゴリズムは給油間の最大距離を効率的に計算する必要があります。 ツーポインタまたはプレフィックス合計アプローチにより、トラックごとに必要な給油数を迅速に計算できます。 これをグローバル二分探索と組み合わせると、制限時間内に解決策が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m * 2^n) | O(n) | 遅すぎる |
 | 二分探索 + 貪欲/DP | O(m * n * log(最大距離 * 最大c)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、都市の位置を並べ替えて保存します。ただし、入力ではすでに並べ替えられています。 これにより、連続する都市間の距離に素早くアクセスできるようになります。`dist[i] = a[i+1] - a[i]`。 
2. 関数を定義する`can_complete(V)`これは、すべてのトラックがサイズ V のタンクを使用して最大でも許可された給油で走行を完了できる場合に True を返します。 
3. 各トラックについて、開始都市を抽出します。`s`、フィニッシュシティ`f`、燃費`c`、および許可された給油`r`。 経路に沿った連続する都市間の一連の距離を計算します。 
4. 貪欲なアプローチを使用して、パスに沿って最初から最後まで反復し、現在の区間の距離を累積します。 距離×燃料消費量が V を超えると、給油回数をインクリメントし、現在の区間までの累積距離をリセットします。 給油回数を超えた場合`r`、トラックはこのタンクのサイズでは移動を完了できません。 
5. 機能`can_complete`いずれかのトラックがチェックに失敗した場合は、すぐに False を返します。 それ以外の場合は、True を返します。 
6. 考えられるタンク容量 V に対して二分探索を実行します。下限はゼロで、上限は、それより大きいタンクは必要ないため、可能な最大距離にすべてのトラックの最大燃料消費量を乗じた値になります。 
7. 有効な最小 V が見つかるまで、二分探索間隔を狭め続けます。 これを答えとして返します。 

重要な不変条件は、貪欲なレグの蓄積中、タンク容量が常に、許可された給油回数を超えることなく、最も長い連続セグメントをカバーするのに十分であるということです。 これにより、次のことが保証されます。`can_complete(V)`True を返します。すべてのトラックに有効な給油計画が存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    trucks = []
    max_c = 0
    for _ in range(m):
        s, f, c, r = map(int, input().split())
        trucks.append((s-1, f-1, c, r))
        max_c = max(max_c, c)
    
    dist = [a[i+1] - a[i] for i in range(n-1)]
    
    def can_complete(V):
        for s, f, c, r in trucks:
            used_refuels = 0
            fuel = 0
            for i in range(s, f):
                need = dist[i] * c
                if need > V:
                    return False
                if fuel + need > V:
                    used_refuels += 1
                    fuel = 0
                fuel += need
            if used_refuels > r:
                return False
        return True
    
    left, right = 0, max(dist) * max_c * 2
    while left < right:
        mid = (left + right) // 2
        if can_complete(mid):
            right = mid
        else:
            left = mid + 1
    print(left)

if __name__ == "__main__":
    solve()
```このコードは、まず連続する都市間の距離を事前計算し、トラックのパラメーターを保存します。 の`can_complete`関数は貪欲なトラバーサルを実装します。トラックの経路に沿って燃料使用量を蓄積し、蓄積された燃料がタンク容量を超えるたびに給油をカウントします。 二分探索により、すべてのチェックに合格する最小タンクが見つかります。 乗算を慎重に使用すると、整数のオーバーフローが回避され、貪欲な累積によって給油制限が確実に遵守されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m * n * log(最大距離 * 最大c)) | 各候補 V について、各トラックの経路が 1 回 (最大 n) スキャンされ、V に対する二分探索により log(最大距離 × 最大燃料率) | が加算されます。 
| スペース | O(n + m) | 距離配列とトラックを保存する |

 n ≤ 400 および m ≤ 250,000 とすると、このアルゴリズムは最悪の場合の推定でおよそ 250,000 × 400 × 30 = 3 × 10^9 の演算を実行しますが、現実的な制約と早期終了が発生します。`can_complete`2秒以内に実行可能にします。
