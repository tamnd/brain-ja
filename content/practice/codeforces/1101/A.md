 ## 問題の理解

 各クエリは、数直線上の禁止区間と固定ステップ サイズを記述します。 与えられた数値の倍数である最小の正の整数を見つけるように求められます。$d$、ただし厳密には区間の外側にあります$[l, r]$。 

有効な候補はすべてポイントであると考えると便利です。$d, 2d, 3d, \dots$これらのうち、ブロックされたセグメント内に収まらない最初のものが必要です。 ブロックされたセグメントは、1 つまたは複数の倍数を切り取る可能性があります。$d$ただし、答えはこの除外を生き残った最も早い倍数でなければなりません。 

クエリの数という点では制約は小さいですが、各クエリ内の値は最大で大きくなる可能性があります。$10^9$。 これにより、次の値までのすべての倍数を反復しようとするアプローチは即座に除外されます。$r$あらゆるクエリに対して。 たとえ各クエリにコストがかかるとしても$O(r/d)$、最悪の場合こうなります$10^9$クエリごとの操作。1 秒の制限では不可能です。 

重要なエッジケースは、複数が間隔の境界とどのように相互作用するかによって決まります。 まず、もし$d > r$、次に、を除くすべての倍数$d$それ自体はすでにセグメントの外にある可能性があるため、答えは自明です$d$。 第二に、もし$d < l$、 それから$d$はすでに有効であり、答えです。 唯一興味深いケースは、次の倍数の場合です。$d$区間内にあるため、それを「ジャンプ」して通過する必要があります。 

素朴な推論による微妙な失敗例は、チェックするだけでよいと仮定することです。$r$。 たとえば、次の場合$l = 5$、$r = 10$、$d = 4$、倍数は$4, 8, 12, \dots$。 数字の 8 は区間内にあるため、チェックするだけでスキップします$r$チェックだけをした場合、8 を誤って受け入れてしまうでしょう$r$メンバーシップを検証せずに -ベースの境界$[l, r]$。 

## アプローチ

 ブルートフォースアプローチでは、次のような問題が発生します。$d$: から開始$d$、追加し続けます$d$、外側の値が見つかったら停止します$[l, r]$。 これは、答えの定義を明示的にチェックするため、正しいです。 ただし、最悪の場合、$d = 1$そして$l = 1, r = 10^9$までスキャンします。$10^9$これは、許可されている操作をはるかに超えています。 

重要な観察は、区間に関連して 1 つの候補について推論する必要があるだけであるということです。 最初の倍数のいずれか$d$すでにセグメントの外側にあるか、セグメントの内側にあります。 それが内側にある場合、より小さい倍数はすべて無関係となり、厳密に次の倍数よりも大きい最初の倍数に「ジャンプ」するだけで済みます。$r$。 その値はまさに次の倍数です$d$後$r$、反復の代わりに算術を使用して直接計算できます。 

これにより、問題はクエリごとの定数時間の計算に縮小されます。$d$範囲内にある場合、上記の次の倍数を計算します$r$。

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り$l, r, d$。 目標は、次の最初の倍数を見つけることです。$d$それは避けます$[l, r]$。 
2. かどうかを確認します。$d$間隔の中にあります$[l, r]$。 もし$d < l$、 それから$d$はすでに有効であり、次の最小の正の倍数であるため、可能な最小の答えになります。$d$。 
3. もし$d \ge l$かどうかを確認します。$d \le r$。 これが嘘なら、もう一度$d$は区間外であり、これが答えです。 
4. もし$l \le d \le r$、 それから$d$は禁止されているため、間隔内に収まるか重複する可能性のある倍数をすべてスキップする必要があります。 
5. 次の候補の倍数$r$次のように計算されます$\left\lfloor \frac{r}{d} \right\rfloor d + d$。 これにより、厳密に次よりも大きい最小倍数が得られます。$r$。 
6. 計算された値を出力します。 

重要なステップは、単一の倍数が禁止されたセグメント内に到達すると、より小さい倍数はすべてすでにチェックされ拒否されるため、最適な答えはそれより小さい倍数ではあり得ないことを認識することです。 The structure of multiples guarantees that the next valid candidate is the first multiple beyond the right endpoint.

 ### なぜ効果があるのか

 All valid numbers form a strictly increasing sequence of multiples of$d$。 禁止領域は、数直線の連続したセグメントを削除します。 最初の倍数の場合$d$は削除されませんが、最小限であるため最適である必要があります。 それ以外の場合、倍数が禁止されたセグメントに入ると、その後のすべての倍数は、ある時点までその内側または上に順番に残ります。 後の次の倍数$r$外側にあることが保証されている最初のポイントです$[l, r]$、それ以上の小さい倍数$d$割り算や区間制約に違反することなく存在できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

q = int(input())
for _ in range(q):
    l, r, d = map(int, input().split())

    if d < l or d > r:
        print(d)
    else:
        print((r // d + 1) * d)
```このコードは、ウォークスルーで導出されたロジックを直接実装します。 条件`d < l or d > r`最小倍数がすでに間隔を回避している場合をキャプチャしているため、調整は必要ありません。 それ以外の場合は、厳密に次より大きい最初の倍数を計算します。`r`整数の除算を使用します。 

表現`(r // d + 1) * d`次の倍数にジャンプする標準的な方法です。 ループを完全に回避し、フロア分割に依存して、以下を超えない最後の倍数を見つけます。`r`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    q = int(input())
    out = []
    for _ in range(q):
        l, r, d = map(int, input().split())
        if d < l or d > r:
            out.append(str(d))
        else:
            out.append(str((r // d + 1) * d))
    return "\n".join(out)

# provided samples
assert run("5\n2 4 2\n5 10 4\n3 10 1\n1 2 3\n4 6 5\n") == "6\n4\n1\n3\n10"

# custom cases

assert run("1\n10 20 3\n") == "3", "small multiple already valid"
assert run("1\n6 6 2\n") == "8", "tight interval containing multiple"
assert run("1\n1 1 1\n") == "2", "minimal boundary case"

 ## 特殊なケース

 いつ$d > r$の場合、間隔は最小倍数にはまったく影響しません。 たとえば、入力の場合$l=1, r=5, d=10$の場合、すでにセグメントの外にあるため、アルゴリズムはすぐに 10 を返します。 

いつ$d \in [l, r]$、最初の複数がブロックされているため、ジャンプする必要があります。 のために$l=2, r=10, d=3$、倍数は 3、6、9、12 です。最初の 3 つは区間内または区間付近にありますが、正解は 12 で、これはまさに上記の最初の倍数です。$r$。 計算`(r // d + 1) * d`直接 12 を生成し、反復なしで意図したスキップ動作と一致します。
