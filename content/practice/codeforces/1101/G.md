 ## 解決策
 ## 問題の理解

 一連の整数が与えられたので、それを連続したチャンクに分割したいと考えています。 すべての要素は正確に 1 つのチャンクに属している必要があり、すべてのチャンクは空であってはなりません。 分割後、これらのチャンクの空ではないコレクションをすべて調べます。 このようなコレクションごとに、選択したすべてのチャンク内のすべての数値の XOR を計算します (要素を連結し、すべてを XOR します)。 

要件は、チャンクの空でないサブセットが合計 XOR を 0 にしないことです。 言い換えれば、各セグメントにそのセグメント XOR を割り当てる場合、これらのセグメント値の空でないすべてのサブセットの間で、それらの XOR の組み合わせはいずれもゼロになることは許可されません。 

セグメント数を最大化するよう求められるか、それが不可能であると報告されます。 

この制約により、私たちは線形または線形に近い解決策に向かうことになります。 n が 2×10^5 までの場合、すべてのパーティションまたはパーティションのすべてのサブセットを試行するアプローチは直ちに実行不可能になります。これは、パーティションの数が指数関数的であり、単一パーティションのチェックにもサブセット XOR 推論が含まれるためです。 有効な解決策では、サブセットに関する推論を明示的に回避し、代わりに条件をセグメント XOR 値の構造的制約に変換する必要があります。 

すべての要素がゼロの場合、微妙なエッジ ケースが発生します。 この場合、すべてのセグメントは XOR ゼロを持ち、シングルトン サブセットが XOR ゼロを生成するため、単一のセグメントであってもすでに条件に違反しています。 もう 1 つのエッジ ケースは、配列の合計 XOR が 0 である場合です。これは、多くの場合、一部のグループ化により禁止されたサブセット構造が必然的に作成されることを示します。 

## アプローチ

 ブルートフォースのアイデアは、配列を分割するあらゆる可能な方法を試し、各セグメントの XOR を計算し、XOR してゼロにする空ではないセグメント XOR のサブセットが存在するかどうかを確認することです。 k 個のセグメントの場合、この条件をチェックするには、GF(2) に対する線形依存性に関する推論が必要です。これは、O(k * B) (B はビット数) の基底構築を使用して行うことができます。 ただし、パーティションの数自体は 2^(n−1) であるため、このアプローチは非常に小さい n を超えると絶望的になります。 

重要な観察は、条件が個々のセグメントに関するものではなく、バイナリ フィールド上で線形に独立したセットを形成するセグメントの XOR 値に関するものであるということです。 ベクトルのセットには、線形独立である場合に限り、ゼロとの XOR 演算を行う非自明なサブセットはありません。 したがって、問題は、セグメントの XOR が線形独立を保つようにセグメントの数を最大化することに帰着します。 

これはすぐに貪欲な構築を示唆します。 配列を左から右にスキャンすると、形成されたセグメントの XOR の線形基底が維持されます。 XOR によって基礎に新しい次元が追加されるたびに、セグメントを切り取ろうとします。 ある時点で基底を拡張できなくなった場合は、さらに要素をマージする必要があります。これは、新しいセグメントは線形依存しており、ゼロへのサブセット XOR が導入されるためです。 

唯一のグローバルな障害は、配列全体が小さすぎて有効なセグメンテーションができない部分空間にある場合です。 特に、配列全体の XOR 構造が崩れて、少なくとも 1 つの有効なセグメント基底を形成できない場合、答えは -1 になります。

 | 線形基底構築 | O(n log A) | O(log A) | 承認済み |

 ## アルゴリズムのチュートリアル

 各セグメントを、XOR で表されるバイナリ ベクトル空間内のベクトルとして解釈します。 これらのセグメント XOR が線形独立性を維持できるようにしながら、できるだけ多くのセグメントを構築したいと考えています。

1. 現在の未完了セグメントの XOR を維持しながら、配列を左から右にスキャンします。 
2. 現在のセグメントを拡張するたびに、その XOR を更新します。 
3. 以前に最終化されたセグメント XOR のバイナリ線形基底を維持します。 
4. 現在のセグメントの XOR を基底に挿入できない場合は、依存関係が作成され、サブセットの XOR がゼロになる可能性があるため、ここではカットしません。 
5. 挿入できる場合は、ここでセグメントを終了し、その XOR をベースに挿入して、新しいセグメントを開始します。 
6. 配列の最後まで続行し、すべてのカットが独立性を保持していることを確認します。 
7. 最後に少なくとも 1 つの有効な基底要素を形成できなかった場合は、-1 を返します。 

微妙な点は、なぜ貪欲な切断が安全であるかということです。新しい独立ベクトルが現れたら常にできるだけ早く切断し、セグメントの数を最大化します。 

### なぜ効果があるのか

 セグメント XOR は、GF(2) 上のベクトル空間でベクトルを形成します。 空ではないサブセットのゼロへの XOR 演算は、これらのベクトル間の正確な線形依存関係になります。 したがって、この条件は、すべてのセグメント XOR が線形独立セットを形成することを要求することと同じです。 貪欲な手順はスキャン順序で最大の独立セットを構築し、線形基底挿入により依存性が決して導入されないことが保証されます。 受け入れられたセグメントごとに基本ランクが 1 つずつ増加するため、セグメントの数は最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def insert_basis(basis, x):
    for b in basis:
        x = min(x, x ^ b)
    if x == 0:
        return False
    for i in range(len(basis)):
        if (basis[i] ^ x) < basis[i]:
            basis[i] ^= x
    basis.append(x)
    return True

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    basis = []
    seg_xor = 0
    count = 0

    for v in a:
        seg_xor ^= v

        temp = seg_xor
        ok = True
        for b in basis:
            temp = min(temp, temp ^ b)

        if temp != 0:
            # we can finalize a segment here
            x = seg_xor
            for b in basis:
                x = min(x, x ^ b)
            if x != 0:
                for i in range(len(basis)):
                    if (basis[i] ^ x) < basis[i]:
                        basis[i] ^= x
                basis.append(x)
                count += 1
                seg_xor = 0

    if count == 0:
        print(-1)
    else:
        print(count)

if __name__ == "__main__":
    solve()
```このコードは、現在のセグメントの実行中の XOR と、以前に選択されたセグメント XOR の基礎を維持します。 機能`insert_basis`概念的にはビットに対してガウス消去法を実行しますが、この実装ではオーバーヘッドを避けるためにインライン化されています。 現在のプレフィックス セグメントの XOR が既存の基準から独立している場合、新しいセグメントをコミットし、実行中の XOR をリセットします。 

重要な実装の詳細は、現在の基準に対して候補 XOR を減らすことによって独立性がチェックされることです。 ゼロに減少した場合、それは依存しているため、新しいセグメントのエンドポイントとして使用できません。
