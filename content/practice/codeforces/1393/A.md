 ## 解決策
 ## 問題の理解

 次のサイズの正方形グリッドが与えられます。$n \times n$。 目標は、すべてのセルをチェス盤パターンの 2 色で完全に覆うことです。つまり、隣接するセルは常に反対の色でなければなりません。 

構築プロセスには制約があります。最初はグリッドの外側の境界線のみが「利用可能」とみなされ、そこからタイルがターンごとに一度に 1 つ以上追加されます。 新しく配置された各タイルは、エッジに沿って少なくとも 1 つの既存のタイルに接触する必要があります。 1 回のターンでは 1 人のプレイヤーだけが行動しますが、配置ルールが満たされている限り、自分の色のタイルを複数配置することができます。 

問題は純粋にスケジュールに関するものです。つまり、2 人のプレーヤー間の最適な協力を前提として、グリッドの有効なチェスの色を完全に構築するには、どれくらいのターンが必要かということです。 

制約$n \le 10^9$グリッドシミュレーションは即座に除外されます。 基板または配置プロセスをセルごとにモデル化しようとするソリューションでは、$O(n^2)$仕事や記憶、それは不可能です。 平$O(n)$多くのクエリが与えられた場合、最悪の場合、テスト ケースごとの処理が遅すぎる可能性があります。 

重要な難しさは、答えは複雑な意味でのグリッドの幾何学に関するものではなく、隣接制約の下でチェスのパターンをどのように「階層化」できるかに関するものであるということです。 

単純な間違いは、色が 2 つあるため、答えは常に 2 であると仮定することから生じます。これは、次の場合にはすぐに失敗します。$n = 4$。 この場合、サンプル出力は 3 であり、構造上の制限により、2 回の交互の動作ですべてを完了することができないことを示しています。 

もう 1 つの微妙な落とし穴は、偶数と奇数の対称性を仮定することです。$n$。 例えば、$n = 3$2ターン必要ですが、$n = 4$は 3 ターン必要なので、パリティだけですべてが決まるわけではありません。 

## アプローチ

 強引な解釈では、建設プロセスをシミュレートすることになります。 グリッドを維持し、有効なセルのセットをターンごとに繰り返し配置し、隣接制約を明示的に適用します。 たとえ各ターンで有効な拡張を最大限に満たそうと貪欲に試みたとしても、依然として接続性と色の制約を追跡する必要があります。$n \times n$構造。 これにより、少なくとも$O(n^2)$状態または繰り返しスキャンが行われる場合、これは実行不可能です。$n$到達する$10^9$。 

重要な観察は、問題は個々の配置に依存するのではなく、グリッド構造内に強制交互の「層」が何層存在するかに依存するということです。 

チェス盤のカラーリングでは、グリッドは交互に並ぶパリティ セルと考えることができます。 境界から開始すると、それぞれの動きは一貫した色の層を効果的に「内側に押し込む」ことができますが、対角構造により、一部のセルは複数の拡張波の後にのみ到達可能になります。 

重要な単純化は、答えは次のことによってのみ決まるということです。$n$は偶数か奇数か、より正確には、境界から内側に拡張するときに依存関係の完全な「リング」がいくつ存在するかによって決まります。 

奇数の場合$n$、中央のセルは拡張の自然な合流点として機能し、わずかに効率的な階層化が可能になります。 偶数の場合$n$、グリッドはより対称的に分割され、中央のパリティ構造を調整するために追加の 1 ターンが必要になります。 

これにより、単純な閉じた形式が得られます。$$\text{answer} = \left\lfloor \frac{n}{2} \right\rfloor + 1$$これは両方のサンプル ケースに一致します。 

のために$n = 3$、私たちは得ます$1 + 1 = 2$。 

のために$n = 4$、私たちは得ます$2 + 1 = 3$。 

より深い理由は、行 (または列) の各ペアが 1 つの「層」の構築に寄与し、残りのパリティ不一致にわたるチェスの交互制約を最終的に確定するには追加のターンが必要であるということです。

 | 式$\lfloor n/2 \rfloor + 1$|$O(1)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. の各値を読み取ります。$n$。 各テスト ケースは独立しているため、テスト ケース間で状態が共有されることはありません。 
2. コンピューティング$n // 2$。 この値は、境界から内側に拡張するときに、グリッドの完全な「ペアになったレイヤー」が何個存在するかを表します。 
3. 結果に 1 を加算します。 これは、チェスのカラーリング制約により、単純なレイヤーのペアリングを超えて追加のターンが強制される最後の統合ステップを説明します。 
4. 各テスト ケースの計算値をすぐに出力します。 

### なぜ効果があるのか

 構築プロセスは、対称層のグリッドを内側に剥がすことに効果的に減少します。 反対側の各ペアは、拡張の 1 ステップ全体に寄与します。 ただし、チェスのカラーリングのパリティ制約により、あらゆる場合において完全なペアリングが妨げられ、最終的な構成を解決するために 1 つの追加ステップが必要になります。 すべての有効な構築は境界からの隣接関係の伝播を考慮する必要があるため、どの戦略もそれ以下のレイヤーの数を減らすことはできません。$\lfloor n/2 \rfloor$、最後のパリティ調整により追加の定数項が適用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

T = int(input())
for _ in range(T):
    n = int(input())
    print(n // 2 + 1)
```このソリューションは、派生した閉じた形式の式を直接実装します。 唯一の微妙な点は、式がフロアの動作に依存するため、必ず整数の除算が使用されるようにすることです。 各テスト ケースは一定時間内に独立して処理されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 この制約により、最大 100 個のテスト ケースが許可されます。$n \le 10^9$したがって、テストごとの定数時間の式はどれでも十分です。 このソリューションは制限内で快適に動作します。 

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        out.append(str(n // 2 + 1))
    return "\n".join(out)

# provided samples
assert solve("2\n3\n4\n") == "2\n3"

# minimum case
assert solve("1\n1\n") == "1"

# small odd/even mix
assert solve("3\n2\n3\n5\n") == "2\n2\n3"

# large value sanity
assert solve("1\n1000000000\n") == str(1000000000 // 2 + 1)
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 1 | 最小のグリッド |
 | 2,3,5 | 2、2、3 | パリティ動作 |
 | 1e9 | 500000001 | 上限の正確性 |

 ## 特殊なケース

 いつ$n = 1$、グリッドは単一のセルです。 式は次のようになります$1 // 2 + 1 = 1$これは、最初の配置以降は階層化が必要ないという事実と一致します。 

非常に大きい場合$n$、 のような$10^9$、計算は定数時間のままです。 Python にはオーバーフローのリスクがなく、数式は整数の除算のみに依存するため、シミュレーションなしでも結果は正確なままになります。
