 ## 解決策
 ## 問題の理解

 バイナリ文字列から始めます`s`。 当社はキャラクターを削除することができ、削除ごとに 1 コインを支払い、残りのキャラクターのペアを無料で交換することができます。 

すべての操作の後、文字列を取得します。`t`。 長さ`t`から何でも構いません`0`まで`|s|`, 削除が許可されているためです。 の条件は、`t`善であるということは、そこに存在するすべての立場が、`t`元の文字列内の対応する位置とは異なっていなければなりません`s`。 つまり、すべてのインデックスに対して`i ≤ |t|`、必要です`t[i] ≠ s[i]`。 

無料のスワップが問題の重要な部分です。 交換にはコストはかからず、任意に何度でも実行できるため、残りの文字の順序は完全に制御できます。 重要なのはその数だけだ`0`と`1`は削除後も残ります。 

すべてのテスト ケースの合計の長さは最大でも`2·10^5`。 これにより、削除のすべてのサブセットまたはすべての可能な再配置を試行するソリューションは即座に除外されます。 テスト ケースごとに線形に近い時間が必要です。 合計入力サイズ自体は`2·10^5`、`O(n)`ソリューションは理想的であり、`O(n log n)`ソリューションも簡単に十分に高速になります。 

いくつかの特殊なケースは見落とされがちです。 

考慮する`s = "0"`。 私たちが形成できる唯一の空でない文字列は次のとおりです。`"0"`、元の文字列の最初の位置と一致します。 唯一の適切な文字列は空の文字列であるため、答えは次のようになります。`1`。 

考慮する`s = "01"`。 2 つの文字を交換して取得できます`"10"`。 すべての位置がオリジナルとは異なりますので、答えは次のとおりです。`0`。 位置が最初に一致する場合は常に削除が必要であると考えるソリューションは、ここでは失敗します。 

考慮する`s = "111100"`。 There are four ones and two zeros. 最初の 4 つの位置をオリジナルと異なるものにするには、4 つのゼロが必要ですが、存在するのは 2 つだけです。 Some deletions are unavoidable. 答えはローカルのスワップではなく、使用可能な文字のグローバルな数によって決まります。 

これらの例は、実際の問題は、各位置を埋めるのに十分な反対のビットがあるかどうかであることを示唆しています。 

## アプローチ

 総当たり的な視点は構造を理解するのに役立ちます。 

削除する文字のセットを選択するとします。 その後、残りの 0 と 1 の数がわかります。 交換は自由であるため、残りの文字のあらゆる順列が実現可能です。 すべての位置が元の接頭辞と異なるような順列が存在するかどうかを尋ねることができます。`s`。 

ブルートフォース手法では、考えられるすべての削除の数と位置を試し、有効な再配置が存在するかどうかをテストします。 たとえ長い文字列であっても`n`、 がある`2^n`削除の選択肢があるため、これは完全に不可能になります。 

重要な観察は、フリー スワップによってほぼすべての位置情報が破壊されるということです。 削除後は、残っている 0 と 1 の数のみが問題になります。 

最初のものを保持したいとします。`k`ポジション。 元の接頭辞`s[0:k]`いくつかのゼロといくつかの 1 が含まれます。 

を含むすべての位置`0`元のプレフィックスでは、`1`最後の文字列で。 を含むすべての位置`1`元のプレフィックスでは、`0`。 

させて

-`need0`= オリジナルの数`1`プレフィックスの s
 -`need1`= オリジナルの数`0`プレフィックスの s

 これらはまさに、配置する必要がある 0 と 1 の数です。 

ここで、元の文字列を左から右にスキャンして、最長の適切なプレフィックスを構築しようとしていると想像してください。 キャラクターを見るたびに`c`元の文字列では、反対側の文字のコピーが 1 つ必要です`1-c`使用可能な文字のマルチセットから。 

そのような文字が存在する場合は、それを使用します。 そうしないと、その位置では施工できなくなります。 以降の適切な文字列もすべてこの位置を満たす必要があるため、これ以上拡張することはできません。 

この時点で、残っているすべての文字を削除する必要があります。 削除数は、未処理のまま残された文字数と同じになります。 

これにより、非常に単純な貪欲なプロセスが得られます。

 ## アルゴリズムのチュートリアル

 1. 文字列全体の 0 と 1 の合計数を数えます。 
2. これらの数を、任意に再配置できる文字のプールとして扱います。 
3. 元の文字列を左から右にスキャンします。 
4. 現在のキャラクターの場合`c`、反対の文字を対応する位置に配置する必要があります。`t`。 
5. 反対のキャラクターの少なくとも 1 つのコピーがプールに残っているかどうかを確認します。 
6. 存在する場合は、その反対のキャラクターのコピーを 1 つ消費して続行します。 

これは、正常な文字列のもう 1 つの位置との一致に成功したことを意味します。 
7. 存在しない場合は、すぐに停止します。 

すべての適切な文字列はここで反対のビットを必要とするため、この位置を満たす再配置はできません。 
8. ある位置で障害が発生するようにします`i`(0 ベース)。 次に、その位置からのすべての文字`i`それ以降は削除する必要があります。 
9. 答えは次のとおりです。`n - i`。 
10. スキャンが失敗せずに終了した場合は、すべての位置が満たされているため、削除は必要ありません。 答えは`0`。 

### なぜ効果があるのか

 どのポジションでも、要件は完全に決定されます。`0`元の文字列には`1`、そして`1`が必要です`0`。 

スワップは無料であるため、リソースの唯一の制約は、使用可能なゼロと 1 の数だけです。 反対の文字が存在する場合、有効な解決策は必ずこの位置に反対の文字を 1 つ費やす必要があるため、それを使用することは常に安全です。 

ある位置に反対の文字が残っていない場合、残りの文字の配置はその位置を満たすことができません。 その長さの適切な文字列には、プールに存在しない文字が必要になります。 

したがって、最初の障害位置は、まさに、それを超えると良好な文字列を延長できない点になります。 追加の文字を保持することは不可能であるため、残りの文字はすべて削除する必要があります。 削除の数は、正確に、失敗した位置から始まるサフィックスの長さになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    ans = []

    for _ in range(t):
        s = input().strip()
        n = len(s)

        cnt = [0, 0]
        for ch in s:
            cnt[int(ch)] += 1

        answer = 0

        for i, ch in enumerate(s):
            need = 1 - int(ch)

            if cnt[need] == 0:
                answer = n - i
                break

            cnt[need] -= 1
        else:
            answer = 0

        ans.append(str(answer))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```最初の部分は、文字列全体に存在する 0 と 1 の数を数えます。 これらの数は、任意の交換後に使用可能な文字のプールを表します。 

スキャン中に、次の位置が含まれます。`0`が必要です`1`、および次の位置を含む`1`が必要です`0`。 その反対のキャラクターがまだプールに存在するかどうかを確認します。 

そうなった場合、コピーを 1 つ消費します。 概念的には、その文字を最終文字列の現在位置に割り当てます。 

必要な反対ビットが利用できない場合は、最初に不可能な位置に到達したことになります。 残りのサフィックスは削除する必要があるため、答えは次のようになります。`n - i`。 

の`for ... else`ここではconstructが便利です。 の`else`ブロックは、ループが中断されない場合にのみ実行されます。つまり、すべての位置が正常に一致し、答えが`0`。 

微妙な点は、元のキャラクター自体をカウントから削除することは決してないことです。 カウントは、再配置に使用できる文字のマルチセットを表し、文字を何らかの位置に割り当てるたびに、そのマルチセットから 1 文字だけを消費します。 消費される文字は、その位置で必要とされる反対のビットです。

 ## 特殊なケース

 ### 単一の文字列

 入力:```
0
```カウントは`(1 zero, 0 ones)`。 最初の位置には、`1`、しかしどれも存在しません。 その位置ですぐに障害が発生する`0`。 

答えは次のとおりです。```

```アルゴリズムは正しく返します`1`つまり、唯一の有効な結果は空の文字列です。 

### すべての文字が同一

 入力:```
111100
```最初の 4 つの位置にはそれぞれゼロが必要です。 文字列全体にゼロは 2 つだけ存在します。 

ゼロを 2 つ消費すると、3 番目に必要なゼロは使用できなくなります。 位置で障害が発生しました`2`、答えを生み出す`6 - 2 = 4`。 

このアルゴリズムは、反対ビットの供給がいつなくなるかを正確に検出します。 

### 削除は必要ありません

 入力:```
01
```カウントは 0 が 1 つ、1 が 1 つです。 

位置 0 は利用可能な`1`、位置 1 は利用可能な`0`。 

スキャンは正常に終了したため、答えは次のようになります。`0`。 

これにより、バイナリ文字列に完全な乱れが存在する場合でも、アルゴリズムが不必要に文字を削除しないことが確認されます。
