 ## 解決策
 ## 問題の理解

 すべての値が異なる、順列のような配列が与えられます。 許可される唯一の操作は、連続セグメントを取得し、それを最小要素のみに圧縮し、そのセグメント内の他のすべてを削除します。 この操作をさまざまな場所で繰り返すと、最終的に多数の配列が生成される可能性があるため、個別の配列がいくつ出現するかを数えたいと考えます。 

このプロセスについて考えるのに役立つ方法は、常にその間隔の最小値である単一の代表に「間隔を折りたたむ」ことを繰り返しているということです。 1 つの区間を折りたたむと、その後に存在する区間が変わるため、操作の順序が重要になります。そのため、構造は単に独立したローカルな選択ではありません。 

重要な課題は、間隔崩壊の異なるシーケンスが最終的に同じ配列になる可能性があり、操作ではなく個別の結果をカウントしていることです。 これは、答えがシミュレーションではなく構造上の組み合わせであることを直ちに示唆しています。 

この制約により、到達可能な配列または一連の操作を列挙しようとするアプローチは不可能であることが明確になります。 合計 n が最大 3×10^5 の場合、テストごとに O(n^2) でさえもすでに遅すぎ、すべてのサブセグメントにわたる間隔 DP を単純に扱うと、3 次以上の結果になります。 

微妙なエッジ ケースは、配列が厳密に増加または減少している場合です。 増加する配列では、各セグメントの最小値は常にその左端点になります。これにより、一般的な順列と比較してコラプスの動作が大幅に変わります。 たとえば、`[1,2,3,4]`、セグメントの折りたたみは単に左端の要素を保持するだけなので、多くの異なる操作が同じ結果に折りたたまれます。 単純なシミュレーションでは、構造ごとに慎重に重複を排除しない限り、カウントが過剰になりますが、これは自明ではありません。 

もう 1 つのエッジ ケースは、「到達可能」の複数の解釈が混乱を引き起こす可能性がある小さな配列です。 のために`n=1`の場合、答えは明らかに 1 ですが、少なくとも 1 つの操作を前提とする推論フレームワークやパーティション化を必要とする推論フレームワークは、誤ってこの基本ケースを見逃してしまうことがよくあります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての操作シーケンスをシミュレートしようとします。 各操作はセグメントを選択し、その最小値で置き換えて続行します。 シーケンスではなく最終的な配列に限定したとしても、崩壊するたびに将来の有効なセグメントが変更されるため、セグメントを選択できる方法の数は指数関数的に増加します。 ランダムな順列のような最悪の場合、操作のほぼすべてのサブセットが明確な構造進化パスにつながります。 これにより、直接列挙することが不可能になります。 

重要な構造的洞察は、「崩壊の実行」から「どの要素が最終的な代表として生き残るかの決定」に視点を変えることです。 すべての操作は選択されたセグメントの最小値を保持するため、最終的な配列はすべての崩壊を生き残る特定の要素を選択することに対応し、他のすべての要素は、最小値が他の場所にあるセグメント内にあることによって削除されている必要があります。 

次に、要素の存続を妨げるものは何かを考えてみましょう。 ある要素が、生存者間でのみ含まれる選択したセグメントの最小値でない場合、その要素は消えます。 これにより、単調な構造上の制約が生じます。存続可能性は、相対的な順序付けと配列の最小分割方法に依存します。 

中心的な観察は、このプロセスを、生き残った各要素が配列を独立した部分問題に分割する「ピボット ミニマム」として機能する、配列に対するバイナリ分解を構築するものとして解釈できるということです。 各要素は、生き残る最小値として選択されると、配列を独立して展開する左部分と右部分に分割します。 問題は、グローバル最小制約と一致するように、このようなピボットのセットを選択する方法を数えることになります。 

これは、範囲を超えた古典的な分割統治 DP につながります。セグメント内の最小要素を必須の構造的区切り文字として選択し、左側と右側の部分が独立して到達可能な配列を形成できる方法が何通りあるかを数えます。さらに、その周囲で折りたたむかどうかに応じて、最小値自体を存続要素として含めるかどうかの追加の選択肢が追加されます。 

これを効率的に行うために、単調スタックまたはデカルト ツリーのアイデアを使用します。配列は、親子関係が次に小さな要素によって定義されるデカルト ツリーを誘導します。 各ノードは範囲の最小値を表します。 到達可能な配列は、その構造に関するノードのサブセットの選択に対応し、このツリー上の DP によってカウントが得られます。 

最終的な DP は基本的に次のようになります。ノードごとに、現在の最小値が最終的な配列の可視要素に寄与するか、周囲の崩壊によって「吸収」されるかを考慮した追加の係数を使用して、サブツリー内で到達可能な構成を選択する方法の数を計算し、左と右の子を乗算的に組み合わせます。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 | O(n) | 遅すぎる |
 | デカルト ツリー DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 単調スタックを使用して配列からデカルト ツリーを構築します。各要素の親は、セグメントの最小値として支配する最も近い小さい要素です。 これにより、考えられるすべての「最小駆動セグメントの折りたたみ」が静的な構造にエンコードされます。 
2. このツリー内の各ノードは、その値が最小であるセグメントを表すものとして扱います。 その左と右の子は、より小さい最小値で分割された最大サブセグメントに対応します。 
3. サブツリー内で到達可能な構成の数を表す各ノードの DP 値を定義します。 
4. リーフ ノードの場合、単一の要素は、より大きな折りたたみコンテキストによって保存されるかどうかに応じて残るか削除されるため、DP 値は 1 です。 
5. 内部ノードの場合、最初に左右のサブツリーを個別に考慮して DP を計算します。 ルート値は内部のすべての値よりも厳密に小さいため、これらのサブツリーは干渉しません。 
6. 互いに素なサブツリー内の選択は独立しているため、左右の寄与を乗算して結果を結合します。 
7. 現在のノードの最小値が最終配列の一部になるか、より大きなセグメントの崩壊に吸収されて削除されるかに対応する追加の係数を追加します。 
8. 完全な配列の答えは、デカルト ツリーのルートの DP 値です。 

### なぜ効果があるのか

 デカルト ツリーは、「セグメントの最小値」操作によって課されるすべての制約をエンコードします。 すべての有効な崩壊シーケンスは、ツリー最小値に向かって徐々に縮小する間隔として見ることができます。 各ノードはその誘導セグメントの一意の最小値であるため、到達可能な最終配列は、祖先と子孫の関係によって構造的制約が違反されないようにノードのサブセットを選択することに対応します。 このサブツリー間の独立性により、DP がツリー全体できれいに因数分解され、すべての有効な構成が正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def solve_case(n, a):
    # build Cartesian tree using monotonic stack
    parent = [-1] * n
    stack = []

    for i in range(n):
        last = -1
        while stack and a[stack[-1]] > a[i]:
            last = stack.pop()
        if stack:
            parent[i] = stack[-1]
        if last != -1:
            parent[last] = i
        stack.append(i)

    root = stack[0]
    while parent[root] != -1:
        root = parent[root]

    children = [[] for _ in range(n)]
    for i in range(n):
        if parent[i] != -1:
            children[parent[i]].append(i)

    def dfs(u):
        res = 1
        for v in children[u]:
            res = (res * dfs(v)) % MOD
        res = (res * 2) % MOD
        return res

    return dfs(root)

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(solve_case(n, a))
```この実装では、まず単調スタックを使用して線形時間でデカルト ツリーを構築します。 各ポップは親子関係を修正し、すべてのノードが最も近い小さな要素に接続され、「最小セグメント」構造が維持されます。 

次に、DFS は DP をボトムアップで計算します。 各ノードについて、子の結果を乗算し、互いに素なサブセグメント間の独立性を反映します。 係数 2 は、各最小値での 2 値の選択に対応します。つまり、最終的に到達可能な配列の一部として事実上保持されるか、それをバイパスする縮小によって吸収されます。 

微妙な点はルートの識別です。スタック処理後、ルートは親チェーンの最終的な祖先になります。 不正なルート回復は、特に複数のポップが間違った方向に親を割り当てる場合によくある実装バグです。 

## 実用的な例

 ### 例 1

 入力:`[2, 1]`デカルト ツリーを構築します。`1`ルートです、`2`その子です。 

| ノード | こどもDP | 計算 | 結果 |
 | --- | --- | --- | --- |
 | 1 | - | 2 | 2 |
 | 2 | - | 2 | 2 |

 最終的な答えは 2 です。 

これは、最も単純な減少の場合でも、各最小構造により、より大きな元素が吸収されるか分離されるかを反映して、生存について 2 つの一貫した解釈が可能であることを示しています。 

### 例 2

 入力:`[2, 4, 1, 3]`デカルト木のルートは`1`、左側のサブツリー付き`[2,4]`そして右側のサブツリー`[3]`。 

| ノード | 左DP | 右DP | 計算 | 結果 |
 | --- | --- | --- | --- | --- |
 | 2/4 サブツリー | 2 | - | 2×2 | 4 |
 | 3 サブツリー | - | - | 2 | 2 |
 | 1 | 4 | 2 | 4×2×2 | 16 |

 これは、サブツリーの独立性と、ルート乗算器が構造全体に選択をどのように伝播するかを示しています。

 ## 特殊なケース

 単一要素配列は、1 つのノードを持つ自明なデカルト ツリーを生成します。 DP は基本乗算係数を割り当てて 1 を返します。これは、配列が崩壊しないという事実と一致します。 

配列を厳密に増加させると、各要素が以前の最小値の右側の子になる、縮退したデカルト ツリーが生成されます。 サブツリーの独立性がチェーンに縮退し、乗算が正しく累積されるため、DP は依然として均一に適用されます。 

配列を厳密に減少させると、ルートに大域最小値があり、その他すべてが子となる星形のツリーが生成されます。 各サブツリーは独立して寄与し、ルートはそれらを結合して、吸収された要素と保存された要素のすべての組み合わせが一貫してカウントされるようにします。
