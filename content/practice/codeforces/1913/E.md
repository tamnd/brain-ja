 ## 解決策
 ## 問題の理解

 バイナリ行列から始めます。 現在、すべてのセルには 0 または 1 が含まれており、任意のセルをいずれかの値に変更できます。 セルの変更は 1 回の操作としてカウントされます。 

最終的な行列は 2 つの独立した要件を満たさなければなりません。 すべての行について、1 の数が規定の行合計と一致する必要があります。 すべての列について、1 の数が所定の列の合計と一致する必要があります。 

これらの行と列の要件を満たすすべての行列の中で、元の行列からのセル変更が最も少ない行列が必要です。 

マトリックスの次元は最大 50 × 50 なので、セルの数は最大 2500 個になります。 これは、数千の頂点と辺のグラフ アルゴリズムには十分小さいですが、可能な行列を列挙することは完全に除外されます。 2500 個のセルを含むバイナリ行列は次のようになります。$2^{2500}$可能な構成。 

最適化について考える前に、基本的な実現可能性の条件があります。 行によって要求される 1 の合計数は、列によって要求される 1 の合計数と等しくなければなりません。 もし$$\sum A_i \ne \sum B_j,$$その場合、両方の制約セットを同時に満たす行列は存在しません。 

いくつかの特殊なケースは見落とされがちです。 

考慮する```
2 2
0 0
0 0
2 0
1 1
```行の合計には、最初の行に 2 つの 1、2 番目の行に 0 が必要です。 列の合計には、各列に 1 つが必要です。 合計の需要は両方向で 2 であるため、解決策が存在します。 

行要件だけをチェックするか、列要件だけをチェックする不注意なソリューションでは、このケースが誤って拒否される可能性があります。 

もう 1 つの重要なケースは、元の行列がすでにすべてを満たしている場合です。```
2 2
1 0
0 1
1 1
1 1
```答えは 0 です。既存の配置を考慮せずに貪欲にオブジェクトを移動させようとするアルゴリズムは、不必要な変更を実行する可能性があります。 

不可能なケースも即座に検出する必要があります。```
2 2
0 0
0 0
2 2
1 1
```行には 4 つの 1 が必要ですが、列には 2 つだけが必要です。 両方の要件を満たす行列はないため、正解は -1 です。 

最も微妙な問題は、変更を最小限に抑えることが、実行可能なマトリックスを構築することと同じではないということです。 実行可能な行列が異なれば、必要な編集回数も異なる場合があります。 最適化目標はモデルに直接組み込む必要があります。 

## アプローチ

 ブルートフォースソリューションでは、サイズのすべてのバイナリ行列が試行されます。$n \times m$、行の合計と列の合計がターゲットと一致するかどうかを確認し、すべての有効な行列の中で、元の行列からの最小のハミング距離を計算します。 

これは、すべての候補最終行列を明示的に検査するため、正しいです。 残念ながら、10 × 10 行列でもすでに$2^{100}$可能性。 最大 2500 個のセルを使用すると、ブルート フォースは完全に絶望的になります。 

重要な観察は、制約が 2 部構造を記述していることです。 

すべての行によって、必要な行がどこに配置されるかが決まります。 すべての列には、必要な数の 1 が入ります。 セルに 1 を入れようとすると$(i,j)$行間のエッジを選択する場合$i$そしてコラム$j$、その後:

 - 行$i$正確に参加しなければなりません$A_i$選択されたエッジ。 
- カラム$j$正確に参加しなければなりません$B_j$選択されたエッジ。 

これはまさに流れの問題です。 

次に、目的を考えてみましょう。 セルを仮定します$(i,j)$現在 1 が含まれています。 

1のままにしておくとコストは0になります。 

これを 0 に変更すると、コストは 1 になります。 

同様に、セルに現在 0 が含まれている場合:

 - 0 を維持するとコストは 0 になります。 
- 1に変更するとコストが1になります。 

変更を直接最小限に抑えるよりも、変更されないセルの数を最大にする方が簡単です。 

選択された最終行列の場合$x$、$$\text{changes} = nm - \text{unchanged cells}.$$したがって、元の値の最大数を保持する実行可能な行列が必要になります。 

これにより、問題は最小コストのフロー定式化に変わります。 

すべてのセルについて:

 - 最終値 1 を選択すると、その行と列のペアを通じて 1 単位のフローが送信されます。 
- エッジ コストは、この選択により元のセルが保存されるか変更されるかを反映します。 

コストの使用$$\text{cost}(1)= \begin{cases} 0 & a_{ij}=1\\ 1 & a_{ij}=0 \end{cases}$$最終的な行列の作成コストをカウントします。 

ただし、最終的に 0 になるセルも修正コストに寄与する可能性があります。 総編集数をきれいに把握するために、目的を変更します。 

すべての元の 1 が最初に 1 の固定コストを寄与するようにします。 次に:

 - 元の 1 が 1 のままの場合、1 を獲得します。 
・元の0が1になった場合は1をお支払いします。 

これはエッジの重みにつながります$$w_{ij}= \begin{cases} 1 & a_{ij}=1\\ -1 & a_{ij}=0 \end{cases}$$そして総重量を最大化する実現可能な行列を求めます。 

最大重量に達した後$W$、$$\text{answer} = (\#\text{original ones}) - W.$$結果として得られる最適化は、最大コストの 2 部フローであり、エッジ コストを打ち消した後の最小コストのフローと同等です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^{nm})$|$O(1)$| 遅すぎる |
 | 最適な最小コストフロー |$O(V^2E)$このサイズ以上 |$O(E)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 行列を読み取り、元の行列の数を計算します。`ones`。 
2. かどうかを確認します。$$\sum A_i = \sum B_j.$$そうでない場合は、印刷してください`-1`なぜなら、両方の要件を満たす行列は存在しないからです。 
3. フローネットワークを構築します。 

ソースを作成する`S`、各行のノード、各列のノード、およびシンク`T`。 
4. からエッジを追加します`S`容量のある各行ノードに`A_i`そしてコスト`0`。 

これは正確に強制します`A_i`列から出る流量の単位`i`、正確に対応します`A_i`その列にあるもの。 
5. 各列ノードからエッジを追加します。`T`容量あり`B_j`そしてコスト`0`。 

これは正確に強制します`B_j`カラムへの流量の単位`j`。 
6. すべてのセルについて`(i,j)`、行からエッジを追加します`i`列へ`j`容量あり`1`。 

そのコストは次のとおりです。$$-1 \quad \text{if } a_{ij}=1$$

$$+1 \quad \text{if } a_{ij}=0$$標準の最小コスト フローによりコストが最小限に抑えられるため、重みを無効にします。 
7. 正確に送信する$$F=\sum A_i$$ソースからシンクまでの流れの単位。 

ネットワークがこの量を送信できない場合、実行可能な行列は存在せず、答えは次のようになります。`-1`。 
8. しましょう`cost`見つかった最小総コストになります。 

コストが打ち消されたので、$$W=-cost.$$9. 出力$$\text{ones}-W.$$### なぜ効果があるのか

 フローの各単位は、最終値が 1 である行列セルを 1 つだけ選択することに対応します。行と列のエッジの容量 1 により、セルが最大 1 回選択されることが保証されます。 ソース行の容量は行の合計を強制し、列シンクの容量は列の合計を強制します。 

元の 1 の場合、そのセルを選択すると重みが +1 されます。 元の 0 の場合、そのセルを選択すると重みが -1 になります。 総重量は次のとおりです$$(\text{original 1s kept}) - (\text{original 0s turned into 1}).$$元の行列に次のものが含まれている場合、`ones`一つ、それでは$$\text{changes} = (\text{original 1s removed}) + (\text{original 0s added}) = \text{ones}-W.$$したがって、重みを最大化することは、変更されたセルの数を最小化することとまったく同じです。 最小コスト フロー アルゴリズムは最適な実行可能なフローを見つけるため、結果として生じる編集数は最小限になります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

class Edge:
    __slots__ = ("to", "rev", "cap", "cost")

    def __init__(self, to, rev, cap, cost):
        self.to = to
        self.rev = rev
        self.cap = cap
        self.cost = cost

class MinCostFlow:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, fr, to, cap, cost):
        fwd = Edge(to, len(self.g[to]), cap, cost)
        rev = Edge(fr, len(self.g[fr]), 0, -cost)
        self.g[fr].append(fwd)
        self.g[to].append(rev)

    def min_cost_flow(self, s, t, need):
        n = self.n
        pot = [0] * n
        flow = 0
        cost = 0

        INF = 10**18

        while flow < need:
            dist = [INF] * n
            parent_v = [-1] * n
            parent_e = [-1] * n

            dist[s] = 0
            pq = [(0, s)]

            while pq:
                d, v = heapq.heappop(pq)
                if d != dist[v]:
                    continue

                for i, e in enumerate(self.g[v]):
                    if e.cap <= 0:
                        continue

                    nd = d + e.cost + pot[v] - pot[e.to]
                    if nd < dist[e.to]:
                        dist[e.to] = nd
                        parent_v[e.to] = v
                        parent_e[e.to] = i
                        heapq.heappush(pq, (nd, e.to))

            if dist[t] == INF:
                return None

            for v in range(n):
                if dist[v] < INF:
                    pot[v] += dist[v]

            add = need - flow
            v = t

            while v != s:
                pv = parent_v[v]
                pe = parent_e[v]
                add = min(add, self.g[pv][pe].cap)
                v = pv

            v = t
            while v != s:
                pv = parent_v[v]
                pe = parent_e[v]
                e = self.g[pv][pe]

                e.cap -= add
                self.g[v][e.rev].cap += add

                v = pv

            flow += add
            cost += add * pot[t]

        return cost

def solve():
    n, m = map(int, input().split())

    a = [list(map(int, input().split())) for _ in range(n)]
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))

    if sum(A) != sum(B):
        print(-1)
        return

    original_ones = sum(sum(row) for row in a)

    S = 0
    row_start = 1
    col_start = row_start + n
    T = col_start + m
    N = T + 1

    mcf = MinCostFlow(N)

    for i in range(n):
        mcf.add_edge(S, row_start + i, A[i], 0)

    for j in range(m):
        mcf.add_edge(col_start + j, T, B[j], 0)

    for i in range(n):
        for j in range(m):
            cost = -1 if a[i][j] == 1 else 1
            mcf.add_edge(row_start + i, col_start + j, 1, cost)

    required_flow = sum(A)

    cost = mcf.min_cost_flow(S, T, required_flow)

    if cost is None:
        print(-1)
        return

    max_weight = -cost
    answer = original_ones - max_weight
    print(answer)

if __name__ == "__main__":
    solve()
```ネットワークには、行ごとに 1 つのノードと列ごとに 1 つのノードが含まれます。 行と列のエッジを通るフローの単位は、最終的な行列で対応するセルに値 1 が割り当てられることを意味します。 

行の容量と列の容量は、必要な行と列の合計を正確にエンコードします。 すべてのセルエッジの容量は 1 であるため、選択された 1 つ以上のセルに寄与するセルはありません。 

微妙な部分はコストの割り当てです。 オリジナルのものは費用がかかります`-1`、元のゼロはコストを受け取ります`+1`。 min-cost フロー アルゴリズムは総コストを最小化します。これは、証明に記述されている重みを最大化することと同じです。 フローが計算された後、最終的な式はその最大重みを編集数に変換します。 

この実装では、ジョンソン ポテンシャルを使用した連続した最短の拡張パスが使用されます。 負のエッジ コストは前方セル エッジにのみ表示されますが、負のサイクルはありません。 ポテンシャルにより、削減されたコストはすべて非負になり、ダイクストラのアルゴリズムを効率的に使用できるようになります。

```フロー需要は 2 です。最も安価なエッジは、正確に、すでにエッジを含む 2 つのセルであり、それぞれにコストがかかります。`-1`。 アルゴリズムはこれらのセルを介してフローを送信し、総コストを取得します`-2`、重量を計算します`2`、そして戻ります`2 - 2 = 0`。
