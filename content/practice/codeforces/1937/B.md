 ## 解決策
 ## 問題の理解

 ちょうど 2 行のグリッドがあり、`n`列。 すべてのセルには次のいずれかが含まれます`0`または`1`。 

パスは常に左上のセルで始まり、右下のセルで終わります。 行が 2 つしかなく、移動が右と下に制限されているため、有効なパスはすべて非常に単純な形状になります。 上の行に沿っていくつかの列を右に移動し、下に 1 回だけ移動し、最後まで下の行に沿って右に移動し続けます。 

それぞれのパスが正確に訪れる`n + 1`細胞。 これらのセルに書き込まれたビットを読み取ると、次の長さのバイナリ文字列が生成されます。`n + 1`。 

すべての可能なパスの中から、辞書編集的に最小の結果の文字列を見つけなければなりません。 その後、その最小の文字列を正確に生成するさまざまなパスの数を数えなければなりません。 

制約は重要な観察事項です。 すべての合計`n`値は最大でも`2 · 10^5`したがって、テスト ケースごとに線形または線形に近いアルゴリズムは、容易に十分に高速になります。 すべてのパスを他のすべてのパスと比較するアプローチは、コストが高くなりすぎます。`n`下降移動が発生する可能性のある場所。 

最も危険なエッジケースはネクタイから生じます。 

考慮する：```
n = 2
top    = 00
bottom = 00
```考えられる両方のパスで生成されるのは、`"000"`。```
Path down at column 1: 000
Path down at column 2: 000
```答えは次のとおりです。```
000
2
```最適な切り替えポイントを 1 つだけ見つけるソリューションでは、2 番目のパスを見逃すことになります。 

もう 1 つの微妙なケースは、最初の異なる位置が非常に遅れて現れる場合です。```
n = 4
top    = 0011
bottom = 1110
```可能な文字列は次のとおりです。```
01110
00110
00110
00111
```最小の文字列は`"00110"`、2 つの異なるスイッチング位置によって生成されます。 カウントするには、等しいプレフィックスがどこに発生するかを正確に理解する必要があります。 

最後の例外的なケースは、すべての候補文字列が同一である場合に発生します。```
n = 3
top    = 000
bottom = 000
```あらゆる道が与えてくれる`"0000"`、したがって、カウントは可能な下向きのポジションの数に等しくなります。`3`。 

貪欲な構築でも、すべての最適なパスを正しくカウントする必要があります。 

## アプローチ

 ブルートフォースの解決策は簡単です。 

列で上の行から下の行に切り替えると`k`、生成される文字列は次のとおりです。```
top[0..k] + bottom[k..n-1]
```がある`n`可能な値`k`。 すべてを明示的に構築できます`n`文字列の中から最小のものを見つけて、それが出現する回数を数えます。 

各文字列には長さがあります`n + 1`したがって、すべての候補を構築するにはコストがかかります`O(n²)`時間。 

のために`n = 2 · 10^5`、これには大まかに必要になります`4 · 10^10`最悪の場合、キャラクター操作は完全に不可能になります。 

グリッドの構造により、より優れたルートが得られます。 

すべてのパスは、正確に 1 つのスイッチング列に対応します。 生成される文字列は次のとおりです。```
top prefix + bottom suffix
```現在列にいるとします。`i`。 

もし`top[i + 1] < bottom[i]`、次に上の行に留まり、もう 1 つのステップにより、すぐに小さなビットが最後の文字列の次の位置に配置されます。 パスが早く切り替わると、辞書編集的に悪くなる。 

もし`top[i + 1] > bottom[i]`なら、今すぐ切り替えた方が良いでしょう。 

これら 2 つの選択肢が完全に異なる最初の位置によって、最適な切り替え位置が決まります。 これにより、最小の文字列を構築する貪欲な方法が得られます。 

最適なスイッチング列を見つけた後、最適なパスをカウントすることは別の問題になります。 すべての最適なパスは、まったく同じ最小文字列を生成する必要があります。 

結果として得られる最小文字列には、最上行のプレフィックスと、その後に続く最下行のサフィックスが含まれます。 他の切り替え位置では、重複領域が上の行と下の行のセル間の一連の等式を満たす場合にのみ、同じ文字列が生成されます。 これは、最適なスイッチング ポイントの周囲を拡張することでカウントできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n²) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 辞書順に最小の文字列を見つける

 一番上の行を`a`そして一番下の行は`b`。 

列で切り替わるパス`k`生成されるもの:```
a[0] a[1] ... a[k] b[k] b[k+1] ... b[n-1]
```続行するよりも切り替えた方がよい最初の列を検索します。 

1. 列から開始`0`。 
2. 各列について`i`から`0`に`n-2`、 比較する`a[i+1]`そして`b[i]`。 
3. もし`a[i+1] == b[i]`どちらの選択をしても辞書編集上の利点はまだ生じていないため、続行します。 
4. もし`a[i+1] < b[i]`、最上列に留まる方が良いです。 検索を続けます。 
5. もし`a[i+1] > b[i]`、すぐに切り替えた方が良いです。 最適なスイッチングカラムは次のとおりです。`i`、そして私たちは止まります。 
6. そのような列が存在しない場合、最適な切り替え列は次のとおりです。`n-1`。 
7. 最小限の文字列を次のように作成します。```
a[:k+1] + b[k:]
```どこ`k`選択されたスイッチング列です。 

### 最適なパスを数える

 しましょう`k`最適なスイッチングカラムになります。 

同じ最小文字列を生成するすべてのパスは、その文字列のすべての文字を保持する必要があります。 

列で別のパスが切り替わるとします。`j`。 

生成された文字列が一致するには、重複するすべての位置が次の条件を満たす必要があります。```
a[t] = b[t-1]
```間のすべての列に対して`j+1`そして`k`。 

これは、周囲に最も長い連続ブロックが必要であることを意味します`k`これらの等式が成り立つところ。 

1. に対する答えを初期化します。`1`、最適な切り替えポイント自体に対応します。 
2. から左に移動します。`k`その間：```
a[pos] == b[pos-1]
```ステップが成功するたびに、有効な切り替え位置が追加されます。 

1. 有効な位置の合計数は、この一致するセグメントの長さと同じです。 

同等の実装は次のとおりです。```
count = 1
pos = k
while pos > 0 and a[pos] == b[pos-1]:
    count += 1
    pos -= 1
```### なぜ効果があるのか

 辞書編集上の順序は、2 つの候補文字列が異なる最初の位置によって決まります。 列で`i`、選択は配置のどちらかです`a[i+1]`一番上の行に留まるか、`b[i]`今すぐ切り替えてください。 これらのビットが完全に異なる最初の比較により、どのパス ファミリが辞書編集的に小さいかが決まります。 それ以降の文字は無関係になります。 

最適なスイッチング ポイントが固定されると、列間でスイッチを移動しても文字が変化しない場合に限り、別のスイッチング ポイントで同じ文字列が生成されます。 スイッチを 1 列シフトすると、新しく公開された最上行の文字が対応する最下行の文字と等しい場合に、文字列が正確に保存されます。 この条件を繰り返すと、すべての最適なスイッチング位置が特徴付けられるため、連続する一致領域をカウントすると、最適なパスの正確な数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = input().strip()
        b = input().strip()

        k = n - 1

        for i in range(n - 1):
            if a[i + 1] > b[i]:
                k = i
                break

        best = a[:k + 1] + b[k:]

        cnt = 1
        pos = k
        while pos > 0 and a[pos] == b[pos - 1]:
            cnt += 1
            pos -= 1

        out.append(best)
        out.append(str(cnt))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のループでは、最適なスイッチング列を決定します。 辞書編集上の順序は最も古い異なる位置に依存するため、左から右にスキャンします。 

出会ったとき`a[i+1] > b[i]`を切り替えると、パスが異なる可能性がある最初の位置に小さなビットが即座に生成されます。 その後の決定によってその損失を補うことはできないため、最適なスイッチの位置は固定されます。 

次に、対応する上部の接頭辞と下部の接尾辞から最小文字列が直接構築されます。 

カウントするには、選択した切り替え列から左に移動します。 毎回`a[pos] == b[pos-1]`、切り替えポイントを 1 列前に移動すると、生成された文字列は変更されません。 この等価性が満たされない瞬間に、生成される文字列が変更されるため、それ以降の位置は有効になりません。 

計数ループ内のインデックス付けは、オフバイワンの間違いが発生する主な場所です。 等価性は、`a[pos]`そして`b[pos-1]`これらは、スイッチが 1 列左に移動したときに交換される 2 文字そのものであるためです。

 ## 特殊なケース

 ### すべてのパスは同じ文字列を生成します

 入力:```
1
3
000
000
```スイッチの位置ごとに以下が生成されます。```
0000
```貪欲スキャンでは、次の位置が見つかりません。`a[i+1] > b[i]`、 それで`k = 2`。 

カウントループは以下をチェックします。```
a[2] = b[1] = 0
a[1] = b[0] = 0
```両方が一致すると、以下が生成されます。```
count = 3
```これは有効なスイッチ位置の数と同じです。 

### 最適な切り替えがすぐに行われます

 入力:```
1
4
1111
0000
```最初の比較時:```
a[1] = 1
b[0] = 0
```今すぐ切り替えたほうが絶対に良いので、`k = 0`。 

結果の文字列は次のようになります。```
1 + 0000 = 10000
```カウントループは左に移動できないため、回答数は残ります。`1`。 

### 最適な切り替えの前に長い等価性チェーンが存在する

 入力:```
1
5
00111
11110
```スキャンは、以下を検出する前の最後の比較に達します。```
a[4] = 1
b[3] = 1
```そして最後に切り替わります。 

いくつかの隣接する等式は次の条件を満たします。```
a[pos] = b[pos-1]
```生成される文字列を変更せずに、スイッチの位置を左にスライドさせることができます。 

カウント ループは、そのようなすべての位置を正確に累積し、最適なパスの全数を返します。
