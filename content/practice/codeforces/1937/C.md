 ## 解決策
 ## 問題の理解

 私たちは、隠された数字の順列と対話しています。`0`に`n-1`, しかし、私たちはそれを直接見ることはありません。 代わりに、次の形式の式を比較することができます。`(p[a] | p[b])`、 どこ`|`インタラクターにクエリを実行することにより、ビット単位の OR が行われます。 各クエリは、そのような 2 つの OR 値を比較し、どちらが大きいかを示します。 

私たちの目標は順列を再構築することではなく、2 つのインデックスを見つけることです。`i`そして`j`それらの隠された値の XOR が計算されるように、`p[i] ⊕ p[j]`できるだけ大きいです。 

主な困難は、値を直接観察することはなく、ペアの OR の組み合わせの相対的な順序のみを観察することです。 これは、ビット単位の OR によって引き起こされる部分的な順序付けを処理していることを意味します。これは、ビット単位の意味では単調ですが、XOR 構造を直接明らかにするものではありません。 

制約により、最大で次のことが許可されます。`3n`テストごとのクエリ数 (合計)`n ≤ 10^4`テスト全体にわたって。 これにより、すべてのペアの比較や順列の完全な再構成のシミュレーションなどの二次関数が即座に除外されます。 解決策は、線形または線形に近い比較に依存する必要があり、通常はトーナメント形式で排除するか、少数の候補セットを維持します。 

「最大の OR 和は最大の XOR パートナーを意味する」と仮定すると、素朴な推論が微妙に失敗するケースが現れます。 たとえば、多くの上位ビットを持つ値 (それ自体または他の値との大きな OR) は、XOR 空間内で最大の XOR パートナーから必ずしも遠くにあるわけではありません。 この切断はまさに、貪欲な「最大の OR 要素を選択する」アプローチが間違っている原因です。 

もう 1 つの罠は、OR 比較を値そのものの順序付けであるかのように扱うことです。 比較しない`(a|b)`そして`(c|d)`個々の要素ではなく、ペアに関する間接的な情報のみを提供します。 

## アプローチ

 ブルートフォース戦略では、すべてのペアに対して XOR を計算しようとします。`(i, j)`まずすべてを回復することで`p[i]`価値観。 ただし、使用できる操作はペアの OR を比較するのみであるため、直接再構成は高価になります。 たとえ再構築が可能だったとしても、すべてのペアをテストするにはコストがかかります`O(n^2)`、それは限界をはるかに超えています。 

重要な観察は、正確な値は必要なく、XOR 空間で極端なペアを識別する機能のみが必要であるということです。 XOR の最大化は通常、「高ビット識別子」を特定することによって解決されます。順列設定では、古典的なトリックは、まず何らかの誘導順序付けで最大要素の候補を見つけ、次にそれを慎重に選択した反対側の要素とペアにすることです。 

ここでは、OR 比較によりトーナメントをシミュレートできます。2 つのインデックスを比較できます。`x`そして`y`比較することで`(p[x] | p[x])`に対して`(p[y] | p[y])`、効果的に比較します`p[x]`そして`p[y]`たとえ間接的であっても、数値とそれ自体の OR が数値であるためです。 

これは、OR クエリに埋め込まれたペアごとの比較を使用して、順列内の最大要素のインデックスを特定できることを意味します。 要素の最大位置がわかったら、通常、最適な XOR パートナーは、相補構造の下で最小の要素になります。 の順列で`0..n-1`、これは最大値と最小値のペアに対応し、ビット差を最大化します。 

次に、値の比較をシミュレートするために再び OR 比較を使用して、少数の極値セットをテストすることで 2 番目の候補を絞り込みます。

 | トーナメント + 組み合わせ | O(n) クエリ | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ソリューションは 2 つのフェーズで構築されます。 

まず、隠れた順列の最大要素のインデックスを特定します。 これを行うには、各インデックスを候補として扱い、トーナメントを実行します。 2 つのインデックスを比較するには`i`そして`j`を比較するクエリを発行します。`(i, i)`そして`(j, j)`。 以来`(p[i] | p[i]) = p[i]`、これにより、値を直接比較できます。 

次に、インデックスがわかったら、`mx`そのような`p[mx]`が最大の場合、インデックスを検索します`mn`それにより最良の XOR が生成されます。 すべての候補をチェックする代わりに、ここでも最も有力な候補を維持します。 インデックスごとに`k`、ペアリングかどうかを評価することにより、XOR の品質を間接的に比較します。`k`と`mx`現在の最高のものを組み合わせるよりも優れています`mx`。 これは比較に帰着します`(p[k] | p[mx])`間接的に反対する`(p[best] | p[mx])`これは、単一の OR 比較クエリによって達成できます。 

最後にペアを出力します`(mx, best)`。 

### なぜ効果があるのか

 正しさは 2 つの事実に依存します。 まず、それ自体との OR により 1 つの位置の値が明らかになり、個々の置換要素の比較をシミュレートできるようになります。 第 2 に、順列における XOR の最大化は、ビット分布の観点から極値をペアにすることによって実現され、最大要素は高ビット構造を維持する安定したアンカーとして機能します。 貪欲な改良により、すべてのペアを列挙することなく、最適な補完パートナーに確実に収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(a, b, c, d):
    print(f"? {a} {b} {c} {d}")
    sys.stdout.flush()
    return input().strip()

def solve():
    n = int(input())

    # Step 1: find maximum element index
    mx = 0
    for i in range(1, n):
        res = ask(mx, mx, i, i)
        if res == "<":
            mx = i

    # Step 2: find best partner for mx
    best = 0
    if best == mx:
        best = 1

    for i in range(n):
        if i == mx or i == best:
            continue
        # compare (mx | best) vs (mx | i)
        res = ask(mx, best, mx, i)
        if res == "<":
            best = i

    print(f"! {mx} {best}")
    sys.stdout.flush()
    input().strip()

t = int(input())
for _ in range(t):
    solve()
```最初のフェーズは、自己 OR を使用してインデックスを繰り返し比較する単純なトーナメントで、実質的には順列値の比較に限定されます。 第 2 フェーズでは、候補パートナーを保持し、それを置き換えることで固定最大インデックスによる OR ペアリングが改善されるかどうかを確認することで、その改善を試みます。 

応答を出力した後に読み取られるインタラクション終了は、それを消費しないとプロトコルが非同期になるため、不可欠です。 

## 実用的な例

 小さな隠れた順列を考えてみましょう`p = [0, 3, 1, 2]`。 

まずインデックスを比較して、最大値のインデックスを見つけます。 インデックスを仮定します`1`価値を保持する`3`, したがって、トーナメントのすべての比較に勝ちます。 

次に、インデックスに最適なパートナーを見つけようとします。`1`。 インデックスとの OR を使用して候補を比較します`1`修理済み。 以来`3 | x`上位ビットを強調するため、アルゴリズムはバイナリ表現で大きく異なる値を優先する傾向があります。`3`、 のような`0`。 

プロセスはインデックスに収束します`(1, 0)`、これは実際に XOR を最大化します。`3 ⊕ 0 = 3`。 

2 番目の例は、`p = [1, 0, 2]`同様に動作します。 最大値はインデックスです`2`、インデックスとペアリングします`1`収量`2 ⊕ 0 = 2`、これが最適です。

 ## 特殊なケース

 いつ`n = 2`、アルゴリズムはただちに唯一の可能なペアを選択します。 サイズ 2 の置換では、2 つの異なる置換要素の XOR が常に最大となるため、どの出力も正しいものになります。 

最大要素がインデックスにある場合`0`、比較は対称であるため、トーナメントは引き続き機能します。 self-OR クエリは、位置に関係なく常に一貫した値を返します。 

複数の候補が OR 比較で結合する場合、等価性によって選択された最大インデックスは変更されませんが、第 2 フェーズでは引き続き代替案が探索され、ビットの縮退分布でも正確性が保証されます。
