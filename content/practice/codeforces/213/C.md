 ## 解決策
 ## 問題の理解

 各セルに正または負の整数が含まれる _n_×_n_ グリッドが与えられます。 フューリックは左上隅 (1,1) から開始して右または下のみに移動しますが、ルービックは右下隅 (n,n) から開始して左または上のみに移動します。 合計スコアは、訪問するセルのすべての数値の合計ですが、両方のランナーが通過した場合でも、各セルは 1 回だけカウントされます。 私たちの目標は、彼らが一緒に収集できる合計スコアを最大化することです。 

入力はグリッドのサイズであり、その後に各セルの値が続きます。 出力は単一の整数、つまり達成可能な最大スコアです。 

制約は中程度です。_n_ は最大 300、セル値の範囲は -1000 から 1000 です。これにより、_n_ で 3 次以上のアルゴリズムを使用できますが、_n_ で指数関数的なアプローチは失敗します。 パスの数はおよそ 2^(2n) であり、n=300 の場合は天文学的に大きくなるからです。 

明らかではないエッジ ケースには、Furik と Rubik が同じセルから始まる n=1 のような非常に小さなグリッドが含まれます。 ここでは、セルは 1 回だけカウントされる必要があるため、答えはセルの値そのものになります。 もう 1 つの微妙なケースは、すべての値が負の場合です。 ランナーは依然としてグリッドを完全に横断する必要があるため、アルゴリズムはパスに沿って減少する合計を処理する必要があります。 値の高いセルを通過できるランナーが 1 人だけの場合、アルゴリズムは二重カウントを避けるために最適な割り当てを選択する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、Furik の可能なすべてのパスを考慮し、次に Rubik の可能なすべてのパスを考慮して、各ペアの合計スコアを計算します。 それは正しいのですが、パス ペアの数はおおよそ (2^(2n))^2 のように指数関数的に増加します。これは、20 のような小さな n であっても不可能です。主な問題は、ランナーのパスが共有セルを介してのみ相互作用し、すべてのパスの組み合わせを追跡するのが不可能であることです。 

重要な洞察は、両方のランナーの位置を同じタイムラインに沿って同時に追跡できる動的プログラミング問題としてこれをモデル化することです。 ランナーがステップごとに移動していることを考慮すると、各ステップで、Furik と Rubik の両方が同じ手数を実行しています。Furik の位置 (i1,j1) とルービックの位置 (i2,j2) は、i1+j1 = step+2 および i2+j2 = 2n-step を満たします。 これにより、問題を 3 次元の DP: dp[i1][i2][step] に減らすことができます。これは、Furik が行 i1 にあり、Rubik が行 i2 にあるときの最大スコアを表します。`step`動く。 対応する列は、j1 = step+2-i1、j2 = 2n-step-i2 として推論できます。 DP トランジションは、セルの二重カウントを回避しながら、Furik と Rubik の 4 つの動きの組み合わせを処理します。 

すべてのパスが有効であるため総当り攻撃は機能しますが、n > 10 の場合は失敗します。ランナーがステップ番号によって同期できるという観察により、問題は多項式 DP に帰着します。これは n=300 の場合に実現可能です。

 ## アルゴリズムのチュートリアル

 1. DP を dp[i1][i2] として表します。ここで、i1 は Furik の行、i2 はルービックの行、および現在のステップ t = i1 + j1 - 2 = (2n - i2 - j2) です。 対応する列は j1 = t - i1 + 2 および j2 = n - i2 + n - t です。 
2. 両方のランナーがそれぞれのコーナーからスタートするため、dp[1][1] = Grid[0][0] を初期化します。 同じセルで開始する場合は、1 回だけカウントします。 
3. 1 から 2n-2 までの可能なすべてのステップを繰り返します。 各ステップで、j1 と j2 がグリッド境界内に留まるように、すべての実行可能な i1 と i2 の値を繰り返します。 
4. 各 (i1,i2) ペアについて、前のステップから最大 DP 値を計算します。 ランナーには 4 つの可能な動作の組み合わせがあります。両方とも下に移動、両方とも右に移動、1 つは下に移動、1 つは右に移動、およびその逆です。 これらの遷移の最大値を取得します。 
5. 現在のセルの値を DP 値に加算します。 Furik と Rubik が同じセルを占有する場合、それを 1 回だけ追加します。 それ以外の場合は、両方のセルを合計します。 
6. 両方のランナーが目的地 (n,n) のフリクと (1,1) のルービックに到着するまで、このプロセスを続けます。 dp[n][n] の値 (インデックス作成用に調整) には、最大スコアが含まれます。 

機能する理由: 各ステップで、DP はランナーの位置と歩数を考慮して、達成可能な最大合計を保存します。 ステップを同期することにより、重複するセルを 1 回だけ正確に考慮します。 DP トランジションはすべての動きの可能性をカバーするため、潜在的なパスが省略されず、最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
grid = [list(map(int, input().split())) for _ in range(n)]

dp = [[-float('inf')] * n for _ in range(n)]
dp[0][0] = grid[0][0]

for t in range(1, 2 * n - 1):
    new_dp = [[-float('inf')] * n for _ in range(n)]
    for i1 in range(max(0, t-(n-1)), min(n, t+1)):
        j1 = t - i1
        if j1 >= n: continue
        for i2 in range(max(0, t-(n-1)), min(n, t+1)):
            j2 = t - i2
            if j2 >= n: continue
            val = grid[i1][j1]
            if i1 != i2 or j1 != j2:
                val += grid[i2][j2]
            best = -float('inf')
            for pi1, pi2 in [(i1-1,i2-1),(i1-1,i2),(i1,i2-1),(i1,i2)]:
                if 0 <= pi1 < n and 0 <= pi2 < n:
                    best = max(best, dp[pi1][pi2])
            new_dp[i1][i2] = best + val
    dp = new_dp

print(dp[n-1][n-1])
```このコードは、最初にグリッドを読み取り、到達不可能な状態を表すために負の無限大を使用して DP テーブルを初期化します。 考えられるすべての歩数を繰り返し、有効な位置を計算し、前の 4 つの組み合わせを考慮します。 の使用`max`最適な以前の状態が選択されるようにします。 重なっているセルの値は 1 回加算されます。 最終的な DP テーブルには、両ランナーの右下隅に最大スコアが含まれています。
