 ## 解決策
 ## 問題の理解

 ゲームは次のように分割されます。`n`部品。 各部分は特定のコンピューター上で完了する必要があり、一部の部分は他の部分に依存し、循環のない依存関係グラフを形成します。 Rubik はどのコンピュータからでも開始でき、パートを完了するのにちょうど 1 時間かかります。 コンピュータ間の移動には非対称なコストがかかります。指定されたルールに従って、コンピュータ 1 から 2 への移動には 1 時間、コンピュータ 1 から 3 への移動には 2 時間かかります。 目標は、すべてのパートを完了するための最小合計時間を見つけることです。 

入力では、パーツの数、各パーツがどのコンピューターに関連付けられているか、およびパーツ間の依存関係を指定します。 出力は必要最小限の時間です。 なぜなら`n`最大でも 200、時間計算量がおよそ 200 までのアルゴリズム`O(n^2 * 3)`実現可能です。 部分のすべての置換を試みる素朴な解決策は、置換の数が次のとおりであるため失敗します。`n!`これは小さくても天文学的な数字です。`n`。 

エッジ ケースは、依存関係なしに 1 台のコンピューター上ですべてを完了できる部分がある場合に発生します。 最適なコンピューターから始めることを考慮しない単純なアプローチでは、出張費が不必要に追加される可能性があります。 たとえば、コンピュータ 1 上の 1 つの部品の場合、最小時間は 1 であり、それ以上ではありません。 

もう 1 つの微妙なケースには、非対称な移動時間が含まれます。コンピュータ 2 から 1 への移動には 2 時間かかりますが、1 から 2 への移動には 1 時間しかかかりません。アルゴリズムがすべての移動を等しいものとして扱う場合、合計時間が過大または過小評価されます。 依存関係によってパーツを完了できる順序も強制されるため、コンピューターに最適なバッチでパーツを完成させることは簡単ではありません。 

## アプローチ

 ブルートフォース手法では、依存関係を尊重しながらパーツの完成をあらゆる順序で試行し、動きを含む各シーケンスの時間を計算します。 これは原理的には正しいですが、シーケンスの数は因数分解されます。`n`、 その周り`200!`最悪の場合、それは不可能です。 

重要な観察は、依存関係グラフが有向非巡回グラフ (DAG) であるということです。 依存関係を考慮して、トポロジカルな順序でパーツを処理できます。 トポロジー シーケンスを取得したら、問題は、移動時間を最小限に抑えるために 3 台のコンピューター上でパーツをスケジュールすることになります。 コンピュータが 3 台しかないため、いくつかの部分を完了した後に各コンピュータに到達するまでの最小時間を表す動的プログラミング状態を維持できます。 具体的には、`dp[i][c]`最初の作業を完了するまでの最小時間を表します`i`コンピューターで終わる部分`c`。 次のパートに移行するには、次のパートが同じマシン上にある場合は同じコンピュータに留まり、そうでない場合は出張費を支払う必要があります。 

これにより、階乗総当たり問題が、部品の数とコンピュータの数に関する動的計画問題に変換されます。これは、次の場合に実行可能です。`n`200まで。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | お(ん!) | 遅すぎる |
 | トポロジカル + DP | O(n * 3) | O(n * 3) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析して抽出する`n`、各パーツのコンピューター割り当て、各パーツの依存関係リスト。 
2. 各ノードの入次数を追跡して、パーツの DAG 表現を構築します。 
3. カーンのアルゴリズムを使用してトポロジカルソートを実行します。 入次数 0 を持つすべての部分でキューを初期化します。繰り返しキューから部分を削除し、それをトポロジー順序に追加し、その近傍の入次数を減らします。 いずれかのネイバーが次数 0 に到達した場合、それをキューに追加します。 これにより、有効な完了順序が生成されます。 
4. 2D DP 配列を初期化する`dp[i][c]`、 どこ`i`は位相順序のインデックスであり、`c`は現在のコンピュータ (1、2、3) です。 最初の部分を除くすべての値を無限大に設定します。開始コンピューターは最初の部分に割り当てられたコスト 1 のコンピューターです。 
5. トポロジー順序を繰り返します。 各パーツと各現在のコンピューターについて、割り当てられたコンピューター上でパーツを完成させるためのコストを計算します。 割り当てられたコンピュータが現在のコンピュータと異なる場合は、事前定義された非対称移動時間に基づいて移動コストを追加します。 
6.アップデート`dp[next_index][assigned_computer]`以前のすべてのコンピューターに比べて最小限のコストで実現できます。 
7. すべての部分を処理した後、答えは最小値になります。`dp[n-1][1]`、`dp[n-1][2]`、 そして`dp[n-1][3]`。 

維持される不変条件は次のとおりです`dp[i][c]`は常に最初の作業を完了するまでの最小時間を表します`i`コンピュータで終わるトポロジカルな順序の部品`c`。 トポロジカルな順序で前方に遷移するだけなので、すべての依存関係が尊重されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

# travel time matrix
move_time = [
    [0, 1, 2],
    [2, 0, 1],
    [1, 2, 0]
]

n = int(input())
computers = list(map(int, input().split()))
dependencies = [[] for _ in range(n)]
in_deg = [0] * n

for i in range(n):
    parts = list(map(int, input().split()))
    k = parts[0]
    for dep in parts[1:]:
        dependencies[dep-1].append(i)
        in_deg[i] += 1

# Topological sort
queue = deque(i for i, deg in enumerate(in_deg) if deg == 0)
topo_order = []

while queue:
    node = queue.popleft()
    topo_order.append(node)
    for neigh in dependencies[node]:
        in_deg[neigh] -= 1
        if in_deg[neigh] == 0:
            queue.append(neigh)

# DP: dp[i][c] = min time to complete first i parts ending at computer c
INF = 10**9
dp = [[INF]*3 for _ in range(n)]
first_part = topo_order[0]
comp = computers[first_part] - 1
for c in range(3):
    dp[0][c] = move_time[c][comp] + 1

for i in range(1, n):
    part = topo_order[i]
    comp = computers[part] - 1
    for prev_c in range(3):
        for curr_c in range(3):
            cost = dp[i-1][prev_c] + move_time[prev_c][curr_c]
            if curr_c == comp:
                cost += 1
                dp[i][curr_c] = min(dp[i][curr_c], cost)

print(min(dp[n-1]))
```この解決策は、入力を読み取り、DAG と次数配列を構築することから始まります。 トポロジカルな並べ替えにより、すべての依存関係が尊重されることが保証されます。 DP アレイは、各コンピュータで終了する最小限の時間を追跡し、コンピュータを切り替える場合にのみ移動コストを慎重に追加します。 初期化により、固定起動を想定せずにどのコンピュータでも起動できるようになります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n_3_3) = O(n) | n 個の部分のそれぞれは、以前の 3 台のコンピュータと現在の 3 台のコンピュータ間の移行を考慮します。 
| スペース | O(n*3) | DP アレイは、各部品とコンピューターの最小限のコストを保存します。 

n ≤ 200 とすると、これは時間とメモリの制限内に問題なく収まります。
