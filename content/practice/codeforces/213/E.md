 ## 問題の理解

 2 つの順列が与えられ、1 つは長さです。`n`そしてもう一つの長さ`m`(`n ≤ m`）。 順列とは、以下のすべての数値を含むシーケンスです。`1`正確に 1 回だけ長さまで調整します。 異なる整数がいくつあるかを数えるように求められます`d`追加すると次のように存在します`d`最初の順列のすべての要素に対して、結果として得られるシーケンスは 2 番目の順列のサブシーケンスになります。 サブシーケンスとは、すべての要素が 2 番目のシーケンスに同じ順序で現れることを意味しますが、必ずしも連続している必要はありません。 

制約により許可されるのは、`n`そして`m`まで`200,000`。 これにより、すべての可能なソリューションを反復していることがすぐにわかります。`d`または、すべてのサブシーケンスを明示的にチェックする入れ子ループの実行は遅すぎます。そのようなアプローチでは O(n * m) 以上の処理が必要となり、最悪の場合 400 億回の操作に達する可能性があります。 2 秒の制限内に収めるためには、線形時間または線形算術時間 O(n + m) または O((n + m) log n) に近い解が必要です。 

エッジケースには次のような場合が含まれます。`n`等しい`m`、その場合唯一可能なのは`d`は、2 つのシーケンスの対​​応する要素間の差です。 別の微妙なシナリオが発生するのは、`n = 1`、2 番目の順列の任意の位置に以下が含まれるため、`b[i]`有効な結果を得ることができます`d`。 不用意に実装すると、重複のカウントを間違えたり、負の値のラップアラウンドの処理に失敗したりする可能性があります。`d`価値観。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる可能な変更が試みられます`d`すべてのペアを反復処理することによって`(a[0], b[j])`、計算中`d = b[j] - a[0]`、およびすべての要素をシフトするかどうかを確認します`a`による`d`でサブシーケンスを生成します`b`。 どうかを確認しています`a + d`の続きです`b`2 ポインタ スキャンでは O(m) がかかります。 最悪の場合、O(m) 人の候補者が存在します。`d`、各チェックには O(m) がかかり、O(m^2) 時間がかかります。 と`m = 2 * 10^5`、これは完全に不可能になります。 

重要な洞察は、すべての数値が順列で 1 回だけ出現するということです。 これにより、各数値をマッピングできるようになります。`b`そのインデックスに。 次に、候補者のシフトについて`d`、それぞれをマッピングできます`a[i] + d`のインデックスに`b`。 有効なサブシーケンスは、マップされたインデックスが厳密に増加している場合にのみ存在します。 インデックス マップを使用すると、候補シフトのチェックは O(m) ではなく O(n) になります。 

ただ考慮する必要があるのは、`d`どのような値`a[i] + d`範囲内です`[1, m]`そして存在します`b`。 以来`b`の順列です`1..m`、これは次のことを考慮するのと同じです。`d = b[j] - a[0]`それぞれに`b[j]`。 これにより、O(m) 個の候補シフトが得られます。 各候補をチェックするには、インデックス マップで O(n) 時間がかかります。 全体的な複雑さは O(n + m) です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m^2) | O(n) | 遅すぎる |
 | 最適 | O(n + m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.各値を順列にマッピングする辞書を作成する`b`そのインデックスに。 これにより、値が出現する場所の O(1) ルックアップが可能になります。`b`。 
2. すべての有効なシフトを保持するために空のセットを初期化します。`d`。 
3. 各値について`b[j]`で`b`、候補シフトを計算します`d = b[j] - a[0]`。 
4. シフトされたシーケンスの構築を試みます`c = [a[i] + d]`。 各要素について、その位置を検索します。`b`辞書を使って。 
5. これらのポジションが厳密に増加していることを確認します。 から始める`prev_index = -1`。 要素が含まれている場合、`c`以下のインデックスにマップします`prev_index`、 破棄`d`。 
6. すべてのインデックスが厳密に増加している場合は、次の値を追加します。`d`有効なシフトのセットに。 
7. すべての候補をチェックしたら`d`値の場合、答えはセットのサイズです。 

**機能する理由:** インデックスへのマッピングにより、実際の位置を確認していることが保証されます。`b`直線的にスキャンせずに。 インデックスを厳密に増加させると、サブシーケンスの順序が強制されます。 以来`b`1 から m までのすべての整数が 1 回だけ含まれ、候補はありません`d`範囲外の要素が生成される可能性があるため、すべての候補が範囲外にシフトします。`b[j] - a[0]`意味があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

# Map each number in b to its index
index_in_b = {value: idx for idx, value in enumerate(b)}

valid_shifts = set()

for bj in b:
    d = bj - a[0]
    prev_index = -1
    valid = True
    for ai in a:
        ci = ai + d
        if ci < 1 or ci > m or ci not in index_in_b:
            valid = False
            break
        idx = index_in_b[ci]
        if idx <= prev_index:
            valid = False
            break
        prev_index = idx
    if valid:
        valid_shifts.add(d)

print(len(valid_shifts))
```このソリューションはまず、次の逆引き参照を構築します。`b`効率的に位置を確認するために。 各候補シフトは位置合わせから導き出されます。`a[0]`要素を含む`b`。 次に、以下を繰り返します`a`シフトされた値が厳密に昇順で表示されることを確認します。`b`。 セットを使用すると、個別のシフトが確実に 1 回カウントされ、重複が自動的に処理されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    index_in_b = {value: idx for idx, value in enumerate(b)}
    valid_shifts = set()
    for bj in b:
        d = bj - a[0]
        prev_index = -1
        valid = True
        for ai in a:
            ci = ai + d
            if ci < 1 or ci > m or ci not in index_in_b:
                valid = False
                break
            idx = index_in_b[ci]
            if idx <= prev_index:
                valid = False
                break
            prev_index = idx
        if valid:
            valid_shifts.add(d)
    return str(len(valid_shifts))

# provided sample
assert run("1 1\n1\n1\n") == "1", "sample 1"
# minimal n=1, m>1
assert run("1 3\n2\n1 2 3\n") == "1", "single element alignment"
# n=m, full alignment
assert run("3 3\n1 2 3\n3 1 2\n") == "0", "no valid shift"
# general case
assert run("2 5\n2 3\n1 3 4 2 5\n") == "3", "multiple shifts"
# edge: max n=2,000,000, trivial sequence
inp = "2 2\n1 2\n1 2\n"
assert run(inp) == "1", "full match"
