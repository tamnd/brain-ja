 ## 解決策
 ## 問題の理解

 私たちは構築しなければなりません`n`平面上の五芒星の形の星。 それぞれの星は、一辺の長さを持つ正五角形から生まれます。`10`、そしてペイントされたセグメントは正確にその 5 つの対角線です。 

出力されるのは単なるジオメトリではありません。 有効な描画順序も必要です。 ルービックは、ペンが紙に触れるところから始まり、次から次へとセグメントを描きますが、決してペンを持ち上げることはありません。 正の長さのセグメントを 2 回横断することはできません。 異なる星は頂点でのみ接触する場合があります。 

形式はこの構造を反映しています。 まず、構築で使用されるすべてのポイントを出力します。 次に、星ごとに、どの 5 つの点が正五角形を形成しているかを指定します。 最後に、ウォークスルーポイントを出力します。連続するすべてのペアは、「これら 2 つのポイントの間にセグメントを描画する」ことを意味します。 

重要な観察はグラフ理論です。 1 つの五芒星は、5 つの頂点上のオイラー サイクルです。```
1 -> 3 -> 5 -> 2 -> 4 -> 1
```すべての頂点には次数があります`2`, なので星1つだけでも一筆書きしやすいです。 難しいのは、セグメントが重ならないように、多くの星を 1 つの接続されたオイラー図に結合することにあります。 

限界はわずかです。 対処するだけで済みます`n ≤ 100`したがって、線形または二次の構築は自明です。 難しいのはパフォーマンスではなく、ジオメトリの正確さです。 座標は範囲内に収まる必要があります`5000`、星は頂点でのみ交差することができ、浮動小数点精度はバリデーターチェックに耐える必要があります。 

誤って無効な構造を構築してしまう簡単な方法がいくつかあります。 

よくある間違いの 1 つは、星を接続せずに独立して配置することです。 たとえば、次の場合`n = 2`そして、2 つの互いに素な五芒星を配置します。各星は個別にオイラー サイクルを持ちますが、描画グラフ全体は切り離されています。 一筆書きが不可能になります。 

もう 1 つの間違いは、既存のエッジを再利用してスターを接続することです。 1 つの頂点ではなく 2 つの頂点を識別して 2 つの星を結合しようとするとします。 その場合、両方の星に対角線のセグメントが現れる可能性があり、「セグメントは 2 度存在しない」というルールに違反します。 

さらに微妙な問題は、幾何学的な重なりです。 星が近すぎると、異なる星の対角線が頂点以外の点で交差する可能性があります。 バリデーターは、グラフ構造が正しい場合でもこれを拒否します。 安全な構造では、意図した共有頂点のみが存在するように星を十分に分離する必要があります。 

最後に、多くの実装では、すべての星が辺の長さが正確に規則的である必要があることを忘れています。`10`。 拡大縮小や移動は問題ありませんが、座標を個別に歪めると星の定義が壊れます。 

## アプローチ

 力任せの考え方は、オイラー グラフについて直接考えることです。 各星は、五芒星の走査順序で 5 サイクルに寄与します。 グラフ全体が接続され、すべての頂点の次数が均等になるまで、星間の任意の交差を生成することを試みることができます。 

このアプローチは制約が小さいため、理論的には実行可能です。 グラフ接続を介したバックトラッキング検索でも、`n ≤ 100`。 問題は幾何学的一貫性です。 頂点を結合するたびに、正五角形のジオメトリを保持し、セグメントの偶発的な交差を避ける必要があります。 グラフ部分は簡単ですが、幾何簿記は苦痛になります。 

重要な点は、2 つのオイラー コンポーネントを接続するには 1 つの共有頂点で十分であるということです。 2 つの星がちょうど 1 つの頂点を共有する場合、共有頂点次数は次のようになります。`4`、まだ均等です。 これを繰り返すと接続されたオイラーグラフが自動的に作成されます。 

これにより、タスクは純粋に建設的な幾何学問題に縮小されます。 

1. 有効な正五芒星を 1 つ作成します。 
2. 翻訳版を作成します。 
3. 連続する星が 1 つの頂点を共有するようにします。 
4. 他のすべての頂点を離してください。 

チェーン構造がすべてをきれいに解決します。 

一辺の長さを指定した正五角形を取ります`10`。 その 5 つの頂点は固定相対座標です。 新しい星ごとに、前の星から 1 つの頂点を再利用し、図全体を十分に水平方向に移動して残りの 4 つの頂点を配置します。 変換では規則性と辺の長さが維持されるため、すべての星は有効なままになります。 

全体の構造を図示すると次のようになります。```
star1 -- shared vertex -- star2 -- shared vertex -- star3 ...
```すべての頂点の次数は均等に保たれます。 

- 通常の星の頂点には次数があります`2`- 共有頂点には次数があります`4`すべての次数が偶数である接続グラフには、常にオイラー サイクルがあります。 各エッジは正確に 1 つの星に属しているため、セグメントは繰り返されません。 

構造は直線的でシンプルかつ堅牢です。

 ## アルゴリズムのチュートリアル

 1. 辺の長さを指定した 1 つの正五角形の座標を作成します`10`。 

便利なパラメータ化では、円上の点を使用します。 外接半径のある正五角形の場合`R`、隣接する頂点の範囲の角度`72°`。 辺の長さの公式は次のとおりです。$$s = 2R\sin(36^\circ)$$以来`s = 10`、次のようになります。$$R = \frac{10}{2\sin(36^\circ)}$$2. 極座標を使用して 5 つの頂点を生成します。 

頂点の場合`i`:$$(x_i, y_i) = (R\cos(\theta_i), R\sin(\theta_i))$$角度が異なる場合`72°`。 
3. 五芒星の移動順序を修正します。 

星形のエッジは次のように接続します。```
1 -> 3 -> 5 -> 2 -> 4 -> 1
```これにより、すべての対角線が 1 回だけ使用され、サイクルが形成されます。 
4. X 軸に沿って星を 1 つずつ配置します。 

スターのために`k`、たとえば、大きな水平オフセットによってすべての座標を変換します。`40 * k`。 

オフセットは星の直径よりもはるかに大きいため、異なる星が誤って交差することはありません。 
5. 連続する星が 1 つの頂点を共有するようにします。 

隣接するスター間で 1 つの頂点インデックスを再利用します。 便利な選択肢は次のとおりです。 

- 星の5番目の頂点`k`- 星の最初の頂点になります`k + 1`これにより、偶数次数を維持しながらグラフが接続されます。 
6. すべての固有ポイントを保存します。 

1 つの頂点が再利用されるため、すべての新しいスターは 4 つの新しい頂点のみを提供します。 
7. スター定義を出力します。 

各スターは、その 5 つの頂点インデックスを循環的な順序で出力します。 
8. グローバルなオイラー描画順序を構築します。 

星は共有頂点で接続されたチェーンを形成するため、ローカルの五芒星のサイクルを単純に連結することができます。```
1 3 5 2 4 1
```隣接する星を自然に結び付ける共有頂点を持ちます。 

### なぜ効果があるのか

 個々の星は 5 サイクルに寄与するため、すべてのローカル頂点次数は次のようになります。`2`。 2 つの星がちょうど 1 つの頂点を共有する場合、その頂点次数は によって増加します。`2`、イーブンのまま。 すべての星が次の星と頂点を共有するため、グラフ全体がつながっています。 すべての頂点が偶数次数を持つ接続されたグラフでは、常にオイラー サイクルが認められます。 

スターは頂点のみを共有し、セグメントを共有しないため、エッジを繰り返すことはできません。 大きな平行移動により、意図しない幾何学的交差が防止されます。 すべての星は同じ正五角形の平行移動によって得られるため、すべての辺の長さは正確に維持されます。`10`。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    n = int(input())

    # Regular pentagon with side length 10
    R = 10.0 / (2.0 * math.sin(math.pi / 5.0))

    base = []
    start_angle = math.pi / 2.0

    for i in range(5):
        ang = start_angle + 2.0 * math.pi * i / 5.0
        x = R * math.cos(ang)
        y = R * math.sin(ang)
        base.append((x, y))

    points = []
    stars = []

    # add first star completely
    for x, y in base:
        points.append((x, y))

    stars.append([1, 2, 3, 4, 5])

    last_shared = 5

    # each next star shares one vertex
    for k in range(1, n):
        shift_x = 40.0 * k

        ids = [last_shared]

        for j in range(1, 5):
            x, y = base[j]
            points.append((x + shift_x, y))
            ids.append(len(points))

        stars.append(ids)
        last_shared = ids[-1]

    print(len(points))

    for x, y in points:
        print(f"{x:.12f} {y:.12f}")

    for star in stars:
        print(*star)

    path = []

    order = [0, 2, 4, 1, 3, 0]

    for star in stars:
        for idx in order[:-1]:
            path.append(star[idx])

    path.append(stars[-1][0])

    print(*path)

if __name__ == "__main__":
    solve()
```最初のセクションでは、1 つの正正五角形を計算します。 三角関数の公式を使用すると、反復的な回転によって蓄積される幾何学的誤差を回避できます。 

の`base`配列には 5 つのローカル座標が格納されます。 将来のすべてのスターは単なる翻訳されたコピーであり、同一の形状が保証されます。 

この実装では、隣接するスター間で 1 つの頂点を正確に共有します。 変数`last_shared`再利用されたポイントインデックスを追跡します。 星を追加するたびに新しいポイントが 4 つだけ挿入され、ポイントの総数は次のように維持されます。$$5 + 4(n-1) = 4n + 1$$許容範囲を大幅に下回る`5n`。 

走査順序`[0, 2, 4, 1, 3, 0]`標準の五芒星のサイクルです。 連続するスターがすでにエンドポイントを共有しているため、これらのサイクルを連結することは機能します。 

微妙なディテールは、最後に追加された頂点です。 これがないと、パス全体が 1 つのエッジを早く停止してしまいます。 最後の共有頂点は、グローバル オイラー ウォークを正しく閉じます。

    import math

            points.append((x + shift, y))

 ## 特殊なケース

 のために`n = 1`、グラフは 1 つの五芒星にすぎません。 アルゴリズムは 5 つの頂点とサイクルを出力します。```
1 3 5 2 4 1
```すべての頂点には次数があります`2`なので、グラフはオイラー式です。 

のために`n = 2`重要な詳細は共有頂点です。 2 番目の星は、最初の星の 1 つのポイントを再利用します。 共有頂点次数は次のようになります。`4`、まだ均等です。 グラフが接続されているため、オイラー特性は存続します。 

大型用`n`、偶発的な幾何学的交差は危険です。 アルゴリズムは星の間隔をあけることでこれを回避します`40`水平方向には単位が離れていますが、五角形の直径はそれよりもはるかに小さいです。 非共有セグメントは交差できません。 

もう 1 つの微妙なケースは出力サイズです。 不用意に実装すると、`5n`明確な頂点。 これでも制限内には収まりますが、グラフが切断されてしまいます。 私たちの構築では、代わりに以下が作成されます。$$4n + 1$$隣接するペアごとに 1 つのポイントを再利用して頂点を作成し、接続を保証します。
