 ## 解決策
 ## 問題の理解

 正の整数かどうかを判断するように求められます。$x$非常に素晴らしいです。 問題の定義によれば、偶数の約数が奇数の約数とまったく同じ数である場合、その数値は非常に優れています。 入力は単一の整数です$x$数値が非常に優れている場合、出力は単純に「はい」となり、そうでない場合は「いいえ」となります。 

制約を見てみると、$x \le 1000$小さいです。 これは、パフォーマンスの問題を引き起こすことなく、各数値の約数を直接カウントすることを検討できることを意味します。 それぞれの数字$x$多くても$\sqrt{x}$因数分解をチェックするための約数、および$1000 \times \sqrt{1000}$操作数は約 32,000 回で、2 秒の制限時間としてはわずかです。 したがって、ここでは効率は大きな懸念事項ではありませんが、賢明な洞察があれば、ソリューションは大幅に簡素化されます。 

1 ではエッジ ケースが発生します。その唯一の約数はそれ自体であり、これは奇数です。 したがって、1は特別に良いものではありません。 もう 1 つの微妙なシナリオは、2 のべき乗です。約数はすべて 1、2、4 などであり、偶数と奇数を数えるには注意が必要です。 たとえば、2 には約数 {1, 2} (1 つは奇数、1 つは偶数) があるため、条件を満たすことができます。 1 より大きい奇数は偶数よりも奇数の約数が多くなります。1 は常に奇数であり、奇数を掛けると別の奇数の約数が得られるためです。 

これらのパターンを理解すると、単純化につながります。数値が非常に優れているのは 2 の累乗の場合のみです。その場合にのみ、偶数の約数が 1 つの奇数の約数 1 と「バランス」をとることができるからです。 

## アプローチ

 ブルートフォースアプローチは、1 から 2 までのすべての数値を反復処理することです。$x$、それぞれが次の約数であるかどうかを確認します。$x$、偶数が何個か、奇数が何個か数えます。 この方法は簡単で正しいです。 のために$x=1000$、最悪の場合の演算数はおよそ約数の数であり、1000 未満の数値の場合、実際には約 32 です。実現可能ではありますが、このアプローチでは追加の作業が必要になります。つまり、約数の正確なリストは必要なく、偶数と奇数のパターンのみが必要です。 

重要な洞察は因数分解することです$x$として$2^k \cdot m$どこ$m$奇数です。 奇数の約数は完全に次のようなものから来ています。$m$(1 を含む)、偶数の約数は 2 の累乗と約数の乗算から得られます。$m$。 偶数の約数の数が奇数の約数の数と等しくなるようにするには、$m$これにより、問題は以下のことを確認することになります。$x$は 2 の累乗であり、2 による除算を繰り返す単純な演算です。 

この観察により、ブルートフォースの計数問題が、除算またはビット単位の演算を使用した簡単なチェックに変換されます。 ここでの優雅さは、約数の構造的特性を認識していることです。つまり、2 の累乗だけで「非常に優れた」条件を満たすことができます。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$x$。 これはテストする必要がある数値です。 
2. 一時変数を初期化する$y = x$。 これにより、入力の変更が回避されます。 
3.分割を繰り返す$y$偶数の間に2で。 各除算は 2 の因数を 1 つ取り除きます。 
4. ループ後、次のことを確認します。$y$1 に等しい。そうであれば、$x$は純粋な 2 のべき乗であり、非常に優れています。 
5. それ以外の場合は、$y$1 より大きい奇数の因数が含まれています。これは、奇数の約数の数が偶数の約数の数を超えていることを意味します。$x$特別良いものではありません。 
6. 次の場合は「はい」を出力します。$x$は非常に素晴らしいですが、そうでない場合は「いいえ」です。 

このアルゴリズムが機能するのは、2 のべき乗には奇数の約数 1 が 1 つだけあり、他のすべての約数は偶数であり、べき乗数と 1 対 1 の一致が形成されるためです。 1 より大きい奇数の因数がある場合、奇数の約数が偶数の約数を上回り、条件が破られます。 この不変式により正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x = int(input())
y = x

while y % 2 == 0:
    y //= 2

if y == 1:
    print("yes")
else:
    print("no")
```私たちが使用するのは`y`変更を避けるための作業コピーとして`x`。 の`while`ループは 2 の累乗をすべて取り除きます。`y`。 もし`y`1になり、奇数要素が残らないことを確認$x$は 2 の累乗です。整数の除算を使用する`//`整数空間に留まるようにし、微妙な浮動小数点エラーを回避します。 

## 実用的な例

 **例 1: x = 2**

 | ステップ | y | y % 2 == 0? | アクション |
 | --- | --- | --- | --- |
 | 1 | 2 | 本当 | y //= 2 → y = 1 |
 | 2 | 1 | 偽 | ループを終了 |

 チェック`y == 1`→ True → 出力:「はい」。 これは、約数 {1,2} を持つ 2 が非常に優れていることを示しています。 

**例 2: x = 6**

 | ステップ | y | y % 2 == 0? | アクション |
 | --- | --- | --- | --- |
 | 1 | 6 | 本当 | y //= 2 → y = 3 |
 | 2 | 3 | 偽 | ループを終了 |

 チェック`y == 1`→ False → 出力:「いいえ」。 6 には約数 {1,2,3,6} があります。 奇数の約数 {1,3} = 2、偶数の約数 {2,6} = 2。待って、等しいようです。 ただし、約数は奇数 2、偶数 2 となります。実際、これは「はい」です。 うーん、よく考えてみましょう。 

6 の約数: {1,2,3,6}。 奇数: {1,3} → 2。偶数: {2,6} → 2。偶数の数 = 奇数の数 = 2。 

ああ、これは例外です。6 のような数値は 2 の累乗ではありませんが、偶数と奇数の約数は等しくなります。 したがって、2 のべき乗に関する私の以前の主張は改良する必要があります。 

観察結果をさらに洗練させてみましょう。 

- しましょう$x = 2^a \cdot m$、$m$奇数。 
- 奇数の約数は奇数の割り算から生まれます。$m$。 カウント：$\tau(m)$、の約数の数$m$。 
- 偶数の約数は、2^k (k ≥ 1) と次の約数を乗算することで得られます。$m$。 カウント: a * τ(m)? 実際にはもっと微妙です。 

より良いアプローチ: すべての約数を数え、パリティで分割します。 小型用$x \le 1000$、ブルートフォースカウントは安全です。 

安全のための新しい最適アルゴリズム: i を 1 から sqrt(x) まで繰り返し、i が x を除算するかどうかを確認します。 奇数と偶数の約数を正確に数えます。 カウントが等しい場合は「yes」を返します。 これにより、誤分類が回避されます。 

## Python ソリューション (ブルートフォース、すべての場合に正しい)```python
import sys
input = sys.stdin.readline

x = int(input())
odd = 0
even = 0

for i in range(1, x + 1):
    if x % i == 0:
        if i % 2 == 0:
            even += 1
        else:
            odd += 1

print("yes" if odd == even else "no")
```すべての約数を明示的にチェックします。 これにより、偶数と奇数の約数は均衡しているが、数値が 2 の累乗ではない 6 のような数値の欠落を回避できます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    odd = 0
    even = 0
    x = int(input())
    for i in range(1, x + 1):
        if x % i == 0:
            if i % 2 == 0:
                even += 1
            else:
                odd += 1
    return "yes" if odd == even else "no"

# provided sample
assert run("2\n") == "yes", "sample 1"

# custom cases
assert run("1\n") == "no", "minimum input, only odd divisor"
assert run("6\n") == "yes", "balanced divisors"
assert run("8\n") == "no", "power of 2 > 2, odd divisors = 1, evens = 3"
assert run("9\n") == "no", "odd number, all divisors odd"
```
