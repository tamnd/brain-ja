 ## 解決策
 ## 問題の理解

 私たちは、`n × m`グリッド。 一部の行全体が空であり、一部の列全体が空であり、すべての空のセルはそれらの空の行または空の列の少なくとも 1 つに属します。 

残っているすべての細胞には油が含まれています。 1 つの石油セルに坑井を掘削すると、端に隣接する石油セルを介して接続されているすべての石油セルに到達できます。 タスクは、接続された石油地域がいくつ存在するかを計算することです。 

グリッドについての別の考え方は次のとおりです。 

次の場合にのみ、細胞に油が含まれます。```
its row is not empty
and
its column is not empty
```したがって、禁止された行と禁止された列を削除した後、残りのオイルセルはいくつかの長方形のブロックを形成します。 これらのブロックが作成する接続コンポーネントの数を数える必要があります。 

制限は非常に小さく、最大です。`100 × 100`。 グリッド全体にわたる単純な BFS または DFS であっても、完全に安全です。 完全なトラバースは最大でもタッチします`10^4`セルは 2 秒の制限としては小さいです。 

難しいのはパフォーマンスではなく、構造を正しく理解することです。 

次の例を考えてみましょう。```
n = 5, m = 5
empty rows: 3
empty cols: none
```グリッドは次のように分割されます。```
rows 1-2
row 3 removed
rows 4-5
```つまり、接続された石油地域がちょうど 2 つあります。 

次に、次のことを考えてみましょう。```
n = 5, m = 5
empty rows: 3
empty cols: 3
```削除された行と削除された列は十字を形成します。 残りの油セルは 4 つの切り離された長方形に分割されるため、答えは 4 になります。 

不用意に実装すると、答えが次のように誤って認識される可能性があります。```
(#non-empty row segments) + (#non-empty column segments)
```しかし、正しい構造は加算的ではなく乗算的です。 

もう 1 つの簡単な間違いは、すべての行またはすべての列が空の場合に発生します。 

例：```
2 3
2 1 2
0
```すべての列が削除されるため、オイルセルはまったくありません。 答えは`0`、 ない`1`。 

同様に:```
3 3
0
0
```行や列は削除されないため、グリッド全体が 1 つの接続されたコンポーネントになります。 答えは`1`。 

## アプローチ

 最も直接的な解決策は、グリッドを明示的に構築することです。 

空の各行と空の各列にマークを付けます。 それから細胞`(i, j)`まさに次の場合に油が含まれます。```
row i is not empty
and
column j is not empty
```このブール グリッドを構築すると、問題は 2D グリッド上の標準的な接続コンポーネントの問題になります。 未訪問のすべての石油セルから BFS または DFS を実行し、開始したトラバーサルの数をカウントします。 

接続はまさに通常の 4 方向グリッド接続であるため、この強引な方法は完全に正しいです。 すべての DFS は 1 つの石油地域全体を発見します。 

その複雑さは次のとおりです。```
O(n * m)
```各セルは一定の回数処理されるためです。 

と`n, m ≤ 100`、これはもう快適に過ぎます。 

その下には構造観察も隠れています。 

いくつかの行を削除するとします。 残りの行は、連続した行セグメントに分割されます。 列でも同じことが起こります。 

例えば：```
rows:    valid valid removed valid valid removed valid
segments:   [1]                [2]                [3]
```接続されているすべてのオイル コンポーネントは正確に次のとおりです。```
(one row segment) × (one column segment)
```そのような四角形の内部にはすべてのセルが存在し接続されていますが、削除された行または列によって四角形間の交差が妨げられるためです。 

したがって、答えは次のようになります。```
(number of non-empty row segments)
*
(number of non-empty column segments)
```これにより、グラフの走査が完全に回避されます。 

グリッドが小さいため、ブルート フォース ソリューションは機能しますが、重要な洞察は、完全な行と列を削除すると、グリッドが独立した長方形に分割されるということです。 その構造を認識すると、問題は連続する存続間隔を数えるということになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DFS/BFS | O(nm) | O(nm) | 承認済み |
 | 最適なセグメントカウント | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の行と空の列のセットを読み取ります。 

行または列が削除されたかどうかを定期的にチェックする必要があるため、セットまたはブール配列が理想的です。 
2. 空ではない行の連続セグメントがいくつ存在するかを数えます。 

から行をスキャンします`1`に`n`。 

行が空ではない場合、および次のいずれかの場合。```
it is the first row
or
the previous row is empty
```新しい行セグメントを開始します。 

連続する空でない行は、同じ接続された垂直ブロックに属します。 
3. 空ではない列の連続したセグメントがいくつ存在するかを数えます。 

これは行プロセスと同じです。 
4. 2 つのカウントを乗算します。 

各行セグメントは各列セグメントと結合して、オイルセルの 1 つの接続された長方形を形成します。 
5. 縮退ケースを自動的に処理します。 

生き残った行または列が存在しない場合、カウントのいずれかが次のようになります。`0`したがって、最終的な答えも次のようになります。`0`。 

### なぜ効果があるのか

 行を削除すると、横切ることができない水平の障壁が作成されます。 柱を取り除くと、越えることができない垂直の障壁が作成されます。 

すべての除去後、生き残ったすべてのオイルセルは正確に 1 つのペアに属します。```
(row segment, column segment)
```このようなペアの内部では、すべてのセルが完全な長方形を形成するため、任意の 2 つのセルは通常のグリッドの移動によって接続されます。 

異なる行セグメントに属する 2 つのセルは、空の行で区切られているため接続できません。 異なる列セグメントに属する 2 つのセルは、空の列で区切られているため接続できません。 

したがって、接続されたコンポーネントは次のものと 1 対 1 に対応します。```
row segments × column segments
```カウントを乗算すると、石油領域の正確な数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    row_data = list(map(int, input().split()))
    t = row_data[0]
    empty_rows = set(row_data[1:])

    col_data = list(map(int, input().split()))
    s = col_data[0]
    empty_cols = set(col_data[1:])

    row_segments = 0

    for i in range(1, n + 1):
        if i not in empty_rows:
            if i == 1 or (i - 1) in empty_rows:
                row_segments += 1

    col_segments = 0

    for j in range(1, m + 1):
        if j not in empty_cols:
            if j == 1 or (j - 1) in empty_cols:
                col_segments += 1

    print(row_segments * col_segments)

solve()
```この実装は数学的構造を直接反映しています。 

まず空の行と列をセットに格納します。 メンバーシップチェックは次のとおりです。```
i in empty_rows
```一定の予想時間で実行します。 

行スキャンでは、連続する有効な間隔の始まりをカウントします。 新しいセグメントは、現在の行は存続するが、前の行が存続しない場合にのみ開始されます。 

例えば：```
rows: valid valid empty valid
```最初の有効な行が 1 つのセグメントを開始し、空の行の後の行が別のセグメントを開始します。 

列ロジックは同一です。 

乗算ステップは、すべての行間隔が 1 つの接続された長方形内のすべての列間隔と交差するため機能します。 

微妙な点は、完全に空のグリッドの処理です。 すべての行が削除されたとします。 この場合、セグメントを開始するための条件を満たす行がないため、次のようになります。```
row_segments = 0
```最終積は自動的にゼロになります。 特別なケースは必要ありません。 

off-by-one エラーのもう 1 つの一般的な原因は、インデックス作成です。 入力では 1 から始まる行番号と列番号が使用されるため、ループは意図的に次から反復されます。`1`を通して`n`そして`m`。

 ## 特殊なケース

 すべての行が空である場合を考えてみましょう。```
2 3
2 1 2
0
```行スキャン中:```
row 1 -> empty
row 2 -> empty
```行セグメントは作成されないため、次のようになります。```
row_segments = 0
```列は引き続き 1 つのセグメントを形成しますが、次のとおりです。```
0 × 1 = 0
```オイルセルが残らないのでこれは正解です。 

次に、削除をまったく行わないことを考えます。```
3 3
0
0
```すべての行は 1 つの連続した行セグメントに属し、すべての列は 1 つの連続した列セグメントに属します。 

それで：```
1 × 1 = 1
```グリッド全体が接続されています。 

最後に、分離された有効な間隔を考慮します。```
7 1
2 3 6
0
```生き残る行は次のとおりです。```
1-2, 4-5, 7
```これにより、3 つの行セグメントが作成されます。 

唯一の列が残っているため、列セグメントは 1 つあります。 

したがって、答えは次のようになります。```
3 × 1 = 3
```このアルゴリズムは、削除された行の後に生き残った行が続くときに新しいセグメントを正確に検出し、孤立した行や複数のギャップを正しく処理します。
