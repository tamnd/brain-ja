 ## 解決策
 ## 問題の理解

 INI 形式で書かれたテキスト ファイルが与えられます。 意味のある行はすべて、次のようなセクション宣言のいずれかです。`[network]`または次のようなキーと値の割り当て`port=8080`。 キー、値、セクション括弧の周囲のスペースは無関係なので、最終出力では削除する必要があります。 最初の非スペース文字が次の行である行`;`はコメントなので完全に無視してください。 

ファイルは一連の更新のように動作します。 キーは現在のセクションに属するか、まだセクションが宣言されていない場合はグローバル スコープに属します。 同じキーが同じセクション内で複数回出現する場合、最後に出現したキーのみが残ります。 異なるセクションは独立しているため、同じキー名が複数のセクションに存在する場合があります。 

出力は 3 つの方法で正規化する必要があります。 グローバルキーが最初に来ます。 セクションは後で辞書順に印刷されます。 各スコープ内では、キーも辞書編集順に出力されます。 空行、コメント、余分なスペースは完全に消えます。 

ほとんどの競技プログラミングの問題と比較すると、制約はごくわずかです。 行数は最大 510 行で、合計入力サイズはわずか 10000 文字です。 比較的非効率的な解析戦略であっても、快適に通過できます。 主な課題はパフォーマンスではなく、上書き、空白のトリミング、セクション処理の正確なセマンティクスを正しく再現することです。 

いくつかのエッジケースでは、不注意な実装が静かに破壊される可能性があります。 

セクションはファイル内に複数回出現する場合があります。 そのセクションに属するすべてのキーを一緒にマージする必要があります。 

入力：```
4
[a]
x=1
[a]
y=2
```正しい出力:```
[a]
x=1
y=2
```毎回新しいセクションオブジェクトを作成する単純な実装`[a]`と表示されると、2 つの別々のセクションが誤って印刷されてしまいます。 

キーは、同じセクション内の以前の値を上書きする必要があります。 

入力：```
4
[a]
x=1
x=7
y=2
```正しい出力:```
[a]
x=7
y=2
```単純にリストに割り当てを追加すると、両方の`x`lines would remain.

 空白の処理も微妙です。 

入力：```
3
  a   =   5
[b]
   c =  7
```正しい出力:```
a=5
[b]
c=7
```両側のスペースを慎重に取り除かないと、`=`の場合、出力形式は無効になります。 

コメントの検出は、最初のスペース以外の文字に依存します。 

入力：```
2
   ;hello
x=1
```正しい出力:```
x=1
```チェックのみ`line[0] == ';'`セミコロンは文字通り最初の文字ではないため、失敗します。 

## アプローチ

 最も直接的な解決策は、ファイルを記述どおりにシミュレートすることです。 すべての行をスキャンし、現在のセクションを維持し、キーと値のペアをそのセクションに関連付けられた構造に保存します。 重複キーが見つかると、古い値が上書きされます。 解析が完了したら、印刷する前にセクションとキーを並べ替えます。 

真の総当たり実装では、すべての割り当てをリストに保存し、出力中に逆方向にスキャンして各キーの最後の値を見つけることができます。 あれば`m`割り当てを行うには、以前のほぼすべての割り当てを繰り返し確認する必要がある場合があります。 最悪の場合こうなります`O(m^2)`操作。 

入力が小さいため、このアプローチはここでも合格しますが、不必要に複雑でエラーが発生しやすくなります。 問題の構造から、より明確な観察結果が得られます。それぞれの最新値のみが得られます。`(section, key)`ペアが重要です。 以前の割り当ては、後の上書きが表示されるとすぐに無関係になります。 

この観察は必然的にハッシュ マップにつながります。 セクションごとに 1 つの辞書を維持します。 キーの割り当ては次のようになります。```
sections[current][key] = value
```以前の値は自動的に置き換えられます。 解析が完了したら、出力の書式設定のために辞書順に並べ替えるだけで済みます。 

解析自体は主に実装作業です。 スペースを正しくトリミングしながら、コメント、セクションヘッダー、割り当てを区別する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(㎡) | O(m) | 受け入れられるが不要 |
 | 最適 | O(m log m) | O(m) | 承認済み |

 ここ、`m`格納されている個別のキーの数にソートのオーバーヘッドを加えたものです。 

## アルゴリズムのチュートリアル

 1. グローバル キーの辞書と、セクション名を独自の辞書にマップする別の辞書を作成します。 
2. 現在のセクションをグローバル スコープとして初期化します。 空の文字列で表すことができます。 
3. 各行を読み取り、末尾の改行文字のみを削除します。 
4. 行全体から先頭と末尾のスペースを削除します。 これにより、後のチェックが簡素化されます。 
5. トリミング後に行が空の場合は、無視してください。 声明では、冗長な行を削除する必要があると述べています。 
6. 最初の文字が`;`、この行はコメントなので無視してください。 
7. 行がセクションヘッダーを表している場合は、セクション名を抽出します。 

断面線は次で始まります`[`そして次で終わります`]`スペースをトリミングした後。 ブラケットの周囲のスペースは無関係であるため、ブラケットを削除して内側を再度トリムします。 
8. このセクションがこれまでに登場したことがない場合は、空の辞書を作成します。 
9. 現在のセクションをこのセクション名に更新します。 
10. それ以外の場合、その行はキーと値の割り当てである必要があります。 最初の文字列を分割する`=`キャラクター。 

値自体には変更しない方がよいシンボルが含まれている可能性があるため、一度だけ分割することが重要です。 
11. キーと値の周囲のスペースを個別にトリムします。 
12. 割り当てを現在のセクションの辞書に保存します。 

キーがすでにそこに存在する場合は、新しい値が古い値を自動的に上書きします。 
13. すべての行を処理した後、最初にグローバル キーをソート順に出力します。 
14. 次に、すべてのセクションを辞書編集順にソートして印刷します。 セクションごとに、そのキーをソートされた順序で出力します。 

### なぜ効果があるのか

 解析中のあらゆる瞬間に、各ディクショナリには、そのスコープ内のすべてのキーについて確認された最新の値が正確に保存されます。 重複した割り当てが表示された場合、格納されている値を置き換えることは、最後の出現のみが存続するという問題の要件に一致します。 

各セクションには独自の辞書があるため、セクションは独立しています。 同じセクションが繰り返し出現すると、同じ辞書の変更が継続され、ファイル全体に散在する定義が正しくマージされます。 

最後の並べ替えステップでは、元の入力順序に関係なく、辞書編集上の順序が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    sections = {"": {}}
    current = ""

    for _ in range(n):
        line = input().rstrip("\n").strip()

        if not line:
            continue

        if line[0] == ';':
            continue

        if line[0] == '[' and line[-1] == ']':
            section = line[1:-1].strip()

            if section not in sections:
                sections[section] = {}

            current = section
        else:
            key, value = line.split("=", 1)

            key = key.strip()
            value = value.strip()

            sections[current][key] = value

    global_keys = sections[""]

    for key in sorted(global_keys):
        print(f"{key}={global_keys[key]}")

    for section in sorted(s for s in sections if s != ""):
        print(f"[{section}]")

        for key in sorted(sections[section]):
            print(f"{key}={sections[section][key]}")

if __name__ == "__main__":
    solve()
```このソリューションでは、すべてのスコープを辞書に保持します。 最初のセクションの前のキーは他のどこにも属さないため、空の文字列はグローバル スコープを表します。 

解析ロジックは、行全体をトリミングすることから始まります。 コメントは先頭のスペースの後に始まり、セクション括弧には周囲のスペースも含まれる可能性があるため、これは重要です。 

セクションの解析では以下を使用します。```
section = line[1:-1].strip()
```2番目がなければ`strip()`、次のような入力`[  abc  ]`スペースを含むセクション名が誤って保存されます。 

割り当てでは以下を使用します。```
line.split("=", 1)
```2 番目の引数は、偶発的な余分な分割を防ぎます。 公式の制約では値が単純に保たれていますが、これが最も安全な解析スタイルです。 

上書き動作は、辞書の割り当てから自然に発生します。 明示的な重複処理は必要ありません。 

出力中、グローバル スコープが最初に出力され、次にすべての実セクションがソートされた順序で出力されます。 各スコープ内のキーも印刷前にソートされます。

            value = value.strip()

    backup_stdout = sys.stdout

    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result

 ## 特殊なケース

 セクション宣言の繰り返しを考慮してください。 

入力：```
5
[a]
x=1
[b]
y=2
[a]
```パーサーが 2 番目を認識したとき`[a]`、セクションがあるため、新しい辞書は作成されません。`a`すでに存在します。 切り替わるだけです`current`に戻る`"a"`。 保存されたデータは残ります。```
a -> {x:1}
b -> {y:2}
```最終出力には、単一の`[a]`セクション。 

ここで、1 つのセクション内で上書きすることを考えてみましょう。 

入力：```
4
[a]
x=1
x=5
x=9
```辞書の遷移は次のとおりです。```
{x:1}
{x:5}
{x:9}
```各割り当ては前の値を置き換えます。 仕様と正確に一致する最新のものだけが生き残ります。 

ホワイトスペースを多用した解析もバグの一般的な原因です。 

入力：```
3
 [ abc ]
   k   =   v
 ;hello
```トリミング後:```
[ abc ]
k   =   v
;hello
```セクション名は次のようになります。`"abc"`ブラケットを取り外して再度剥がした後。 割り当ては次のようになります`k=v`。 コメントが完全に消えてしまいます。 

最後に、グローバル キーはセクション キーとは別にしておかなければなりません。 

入力：```
4
x=1
[a]
x=2
y=3
```パーサーは以下を保存します。```
global -> {x:1}
a -> {x:2, y:3}
```二人`x`キーは異なるスコープに属しているため、競合しません。 出力は次のとおりです。```
x=1
[a]
x=2
y=3
```
