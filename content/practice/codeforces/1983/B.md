 ## 解決策
 ## 問題の理解

 2 つのグリッドが与えられています。`a`そして`b`、各サイズ`n`による`m`。 グリッド内のすべてのセルには 0 から 2 までの値が含まれています。私たちの目標はグリッドを変換することです。`a`グリッドに`b`特定の操作を何度でも使用できます。 この演算により、少なくとも 2×2 のサイズの任意の部分長方形を選択し、対角線上にある 2 つの角を 1 を法とする 3 だけ増分し、他の 2 つの角を 2 を法とする 3 だけ増分することができます。問題は、このような一連の演算が存在するかどうかです。`a`と同じ`b`。 

制約は中程度です。`n`そして`m`はそれぞれ500までで、合計は`n`そして`m`すべてのテスト ケースで 500 を超えません。これは、アルゴリズムがテスト ケースごとにおよそ O(nm) で実行される必要があることを意味します。 最悪の場合でも O(n²m²) 個の四角形が存在するため、考えられるすべての四角形や一連の動きを試す単純な総当たりアプローチは直ちに実行不可能になります。 

エッジ ケースには、2×2 のような小さなグリッド、均一な値 (すべて 0 またはすべて 1) を持つグリッド、または隅の調整のみが重要なグリッドが含まれます。 セルを個別にインクリメントするか、モジュロ 3 の動作を無視する素朴なアプローチは、値が 2 から 0 に戻る場合には失敗します。たとえば、すべて 0 の 2×2 グリッドをすべて 2 に変換するには、モジュロ演算を満たすためにどのコーナーを 1 または 2 ずつ増加させるかを慎重に選択する必要があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。グリッドになるまで、可能なすべての長方形と両方の対角線の選択を繰り返し試します。`a`マッチ`b`。 各操作は 4 つのセルに影響を与えるため、すべての四角形を繰り返し試行できます。 これにはテスト ケースごとに O(n²m² × 操作数) がかかりますが、n、m ≈ 500 にとっては明らかに遅すぎます。 

重要な洞察は、演算がモジュロ 3 に対して線形であり、各演算は長方形の角にのみ影響するということです。 長方形に対する演算は 3 を法とする加法的な演算であるため、この問題は「角の差の伝播」問題に帰着します。 具体的には、次の違いを判断できます。`a`そして`b`セルごとに、2×2 の部分四角形を使用して左上から右下に「プッシュ」してみます。 各 2×2 ブロックは個別に調整できるため、最後を除くすべての行と最後を除くすべての列を処理した後、グリッドの右下隅が残りのブロックによって一意に決定されます。 これにより、問題は最後の行と最後の列の単純な整合性条件のチェックに減ります。 

言い換えれば、各セル (i, j) (i < n および j < m) から始まる 2×2 部分四角形のみを使用して、行ごと、列ごとに差異を貪欲に修正できます。 2×2 ブロックの左上隅をインクリメントすると、制御された方法で隣接するセルにも影響を与えるため、この操作によりこれが可能になります。 最後の行と列を除くすべてが整列したら、最後の行と最後の列がモジュロ 3 に一致するかどうかを確認します。一致する場合、変換は可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² m² × ops) | O(nm) | 遅すぎる |
 | 貪欲な 2×2 伝播 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力グリッドを読み取る`a`そして`b`そして差分グリッドを計算します`diff[i][j] = (b[i][j] - a[i][j]) % 3`。 これは、各セルを 3 を法としてどれだけ増分する必要があるかを表します。 
2. 最後の行と最後の列を除くすべてのセルを反復処理します (つまり、[0, n-2] の i と [0, m-2] の j について)。 2×2 ブロックの各左上隅について:

 - しましょう`x = diff[i][j]`。 次の方法で 2×2 ブロックの 4 隅に x を追加することで、この違いを「排除」する必要があります。 

- 追加`x`に`diff[i][j]`(左上)、`diff[i][j+1]`(右上)、`diff[i+1][j]`(左下)、および`diff[i+1][j+1]`(右下) 演算のルール モジュロ 3 を使用します。 
- 具体的には、左上を ずつインクリメントします。`x`(mod 3)、右上と左下は次のとおりです。`2*x`(mod 3)、右下は`x`(mod 3)。 この後、`diff[i][j]`はゼロになり、その差は他の 3 つのコーナーに正しく伝播します。 
3. すべての 2×2 ブロックを処理した後、最後の行と最後の列を確認します。 最後の行または列に残っている差分が非ゼロのモジュロ 3 である場合は、「NO」を出力します。 それ以外の場合は「YES」を出力します。 

機能する理由: 各操作は、以前に修正されたセルを壊すことなく、2×2 ブロックの左上の差を修正します。 左上から右下に順番に処理することで、すべての依存関係が正しく処理されます。 モジュロ 3 の算術演算により、伝播された差分が常に最後の行と列内で吸収されることが保証されます。 不変条件は、セル (i, j) を処理した後、`diff[i][j]`はゼロであり、今後も変化しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = [list(map(int, list(input().strip()))) for _ in range(n)]
        b = [list(map(int, list(input().strip()))) for _ in range(n)]
        
        diff = [[(b[i][j] - a[i][j]) % 3 for j in range(m)] for i in range(n)]
        
        for i in range(n - 1):
            for j in range(m - 1):
                x = diff[i][j]
                diff[i][j] = 0
                diff[i][j+1] = (diff[i][j+1] + 2*x) % 3
                diff[i+1][j] = (diff[i+1][j] + 2*x) % 3
                diff[i+1][j+1] = (diff[i+1][j+1] + x) % 3
        
        possible = True
        for i in range(n):
            if diff[i][m-1] != 0:
                possible = False
                break
        for j in range(m):
            if diff[n-1][j] != 0:
                possible = False
                break
        
        print("YES" if possible else "NO")

solve()
```説明:`diff`グリッドは、必要な増分をモジュロ 3 で取得します。ネストされたループは、2×2 演算パターンを使用して差を伝播します。 最後の行と列をチェックすると、一貫性が保証されます。 モジュロ演算を使用すると、オーバーフローがなく、2 から 0 に適切に折り返されます。
