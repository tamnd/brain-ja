 ## 解決策
 ## 問題の理解

 配列が与えられ、少なくとも 2 つの長さの可能なすべての連続した部分配列を調べます。 各サブ配列について、そのサブ配列内のすべてのインデックスのペアの間で最小の XOR として定義された値を計算します。 言い換えれば、セグメント内では要素のすべてのペアを考慮し、それらの XOR を計算し、最小値を保持します。 その最小値がサブアレイの「コスト」になります。 

タスクは、これらすべての値を明示的に計算して並べ替えることではなく、すべての部分配列コストの中で k 番目に小さい値を決定することです。 

制約により、即座に異なる視点が強制されます。 サブ配列の総数は n の 2 次であり、各サブ配列には潜在的に 2 次のペアが含まれます。 単純な方法で 1 つのサブ配列の答えを計算するだけでも、すでに遅すぎます。 テスト全体の n が最大 100,000 であるため、テストごとにほぼ線形または線形演算より悪いアプローチは実行できません。 

明らかではない問題は、サブ配列の値がエンドポイントではなく、その中の最適なペアに依存することです。 隣接するペアのみが重要であると考えがちな単純な誘惑ですが、[a, b, c] のような部分配列は、b を完全にスキップして、(a, c) からの最小の XOR を持つ可能性があります。 

いくつかの特殊なケースが落とし穴を示しています。 

すべての要素が等しい場合、すべての XOR はゼロになるため、すべての部分配列値はゼロになります。 k に関係なく、答えは常に 0 です。 「個別の XOR を見つける」ことを試みるアプローチはいずれも機能しますが、それがすべてのサブ配列にわたる重複を正しく考慮している場合に限ります。 

配列が [1、2、4、8] のように厳密に増加している場合、XOR は単調ではなく、短い範囲よりも長い範囲の方が大きくなる可能性があります。 部分配列サイズにおける単調な動作を想定したアプローチは失敗します。 

配列に [x, y, x] のようなローカル パターンがある場合、隣接する XOR が大きい場合でも、セグメント全体で最適な XOR はゼロを与える等しいエンドポイントから得られる可能性があります。 これにより、貪欲な隣接のみの推論が打ち破られます。 

## アプローチ

 ブルーフォースのアイデアは単純明快です。 すべての部分配列について、その中のすべてのペアを列挙し、それらの XOR を計算し、最小値を取得して保存し、すべての結果を並べ替えて k 番目の要素を選択します。 これは正しいですが、基本的にコストがかかりすぎます。 O(n^2) 個のサブ配列があり、それぞれが O(n^2) 個のペア チェックを実行するため、実行可能な制限をはるかに超える O(n^4) 個の最悪のケースが発生します。 

サブ配列の値が実際に何であるかを再考することで、段階的に改善できます。 セグメント内の最小の XOR は、バイナリ表現の点で「最も近い」2 つの要素によって常に実現されます。 これは、セグメント内のすべてのペアをチェックすることを避け、代わりに増加する一連の数値の中から最小の XOR ペアを効率的に報告できる構造を維持する必要があることを示唆しています。 

重要な変換は、問題を逆転させることです。部分配列の値を直接計算する代わりに、最大 X の値を持つ部分配列の数を数えます。この関数に効率的に答えることができれば、その答えを二分探索することができます。 残りの課題は、固定 X の場合、部分配列に XOR ≤ X のペアが含まれているかどうかを確認することです。 

これは、バイナリ トライ構造を備えた古典的なスライディング ウィンドウです。 ウィンドウを維持し、挿入、削除、および値の最小 XOR パートナーのクエリをサポートします。 いずれかの時点でウィンドウに XOR ≤ X のペアが含まれている場合、その部分配列は有効です。 2 ポインタ アプローチを使用して、すべての有効な部分配列をカウントできます。 

トライを使用すると、新しい要素ごとに、XOR ≤ X を生成するウィンドウ内に以前の要素が存在するかどうかを確認でき、それに応じてウィンドウを縮小または拡張します。 

これにより、問題はチェックあたり O(n log A) に減り、応答空間に対する二分探索により、解決策は効率的になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^4) | O(n^2) | 遅すぎる |
 | 二分探索 + トライウィンドウ | O(n log A log A) | O(n log A) | 承認済み |

 ## アルゴリズムのチュートリアル

 関数を定義します`count(X)`これは、最小ペア XOR ≤ X を持つサブ配列の数を計算します。 

1. 現在ウィンドウ内にある数値のバイナリ表現を保存するバイナリ トライを使用します。 この構造により、任意の値に対して、既存の要素と達成できる最小の XOR をクエリできます。 
2. 2 つのポインタを維持します`l`そして`r`。 できるだけ多くの要素を含めるようにしながら、右のポインターでウィンドウを拡大します。 
3. 位置にある新しい要素ごとに`r`、それをトライに挿入します。 次に、現在のウィンドウに XOR ≤ X であるペアが存在するかどうかを確認します。 
4. そのようなペアが存在する場合、ウィンドウは有効であるため、次で終わるすべての部分配列をカウントします。`r`そしてどこからでも始めてください`l`に`r`、貢献`r - l + 1`サブアレイ。 
5. 条件が無効になった場合、または最小性を強制したい場合は、次の手順に進みます。`l`条件が再び有効になるまで、トライから要素を削除して前方に進みます。 
6.全体のカウントを蓄積します`r`。 
7. 最後に、答えを二分探索します。 XOR の最小値は 0、最大値は約 2^30 であるため、この範囲で検索します。 

### なぜ効果があるのか

 重要な不変条件は、トライには常に現在のウィンドウ内の要素が正確に含まれており、可能な場合は「XOR ≤ X のペアが存在する」という条件を満たすことに関してウィンドウが最小限になるように維持されることです。 右端の拡張時に各サブ配列が 1 回だけカウントされ、左ポインタによって無効なセグメントが過剰にカウントされないことが保証されます。 二分探索は、この単調述語をラップします。値 X が機能する場合、より大きな値も機能します。これは、より大きな XOR を許可しても、有効なペアのセットが増えるだけであるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Trie:
    def __init__(self):
        self.child = [[-1, -1]]
        self.cnt = [0]

    def insert(self, x):
        node = 0
        self.cnt[node] += 1
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            if self.child[node][bit] == -1:
                self.child[node][bit] = len(self.child)
                self.child.append([-1, -1])
                self.cnt.append(0)
            node = self.child[node][bit]
            self.cnt[node] += 1

    def remove(self, x):
        node = 0
        self.cnt[node] -= 1
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            node = self.child[node][bit]
            self.cnt[node] -= 1

    def min_xor(self, x):
        node = 0
        res = 0
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            if self.child[node][bit] != -1 and self.cnt[self.child[node][bit]] > 0:
                node = self.child[node][bit]
            else:
                node = self.child[node][bit ^ 1]
                res |= (1 << b)
        return res

def count_leq(a, x):
    n = len(a)
    tr = Trie()
    l = 0
    ans = 0

    for r in range(n):
        tr.insert(a[r])

        while l <= r:
            best = tr.min_xor(a[r])
            if best <= x:
                break
            tr.remove(a[l])
            l += 1

        ans += (r - l + 1)

    return ans

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        lo, hi = 0, (1 << 30) - 1
        while lo < hi:
            mid = (lo + hi) // 2
            if count_leq(a, mid) >= k:
                hi = mid
            else:
                lo = mid + 1

        print(lo)

if __name__ == "__main__":
    solve()
```トライはバイナリ構造として実装され、各ノードが子ポインタとサブツリーの数を追跡します。 挿入と削除により、スライディング ウィンドウの使用の正確さが維持されます。 の`min_xor`関数は、トライ内のビットを貪欲に一致させることによって、指定された値に対して達成可能な最良の XOR ペアを計算します。 

2 ポインター ループ`count_leq`条件が実現可能なウィンドウのみを保持し、各右端点が有効な開始位置の数に正確に寄与することを保証します。 

二分探索は、「値 ≤ X を持つ部分配列の数」の単調性を利用して、応答空間に適用されます。

| r | 挿入されました | l | ウィンドウ | 有効なペアの条件 | 貢献 |

 ## 特殊なケース

 のような入力の場合`[7, 7, 7, 7]`、すべてのペアは XOR 0 を持つため、すべての部分配列の値は 0 になります。トライではゼロ以外の改善が見つからず、二分探索はすぐに 0 に崩壊します。すべてのウィンドウが X ≥ 0 の条件を満たすため、スライディング ウィンドウは引き続きすべての部分配列を正しくカウントします。 

のために`[1, 1000000000]`、ペアは 1 つだけ存在し、答えはそれらの XOR です。 トライは正確に 2 つの要素を保持し、最小 XOR クエリは曖昧さなくその 1 つの値を返します。これは、アルゴリズムがウィンドウ調整に依存せずに最小限の構造を適切に処理していることを示しています。
