 ## 解決策
 ## 問題の理解

 接続された無向グラフが与えられ、そのエッジを長さ 2 のパスに完全に分解するように求められます。 各出力部分は 3 つの頂点のチェーンのように見える必要があります。$x - y - z$、つまり、中央の頂点を共有する 2 つのエッジを取得します。$y$、元のグラフのすべてのエッジは、まさに 1 つのそのようなチェーンに現れる必要があります。 

したがって、エッジを個別に考えるのではなく、各ペアが共通のエンドポイントを共有するペアにグループ化しようとしています。 各頂点は、そのようないくつかのペアの中間として機能する可能性がありますが、すべてのエッジは正確に 1 つのペアに属している必要があり、正確に 1 回使用する必要があります。 

制約は次のとおりです$10^5$頂点とエッジ。これにより、エッジのすべてのペアの試行やエッジ上のグローバル マッチングなどの 2 次関数が即座に除外されます。 平$O(m \log m)$これは問題ありませんが、隣接リストを繰り返しスキャンしたり、選択を元に戻そうとしたりするものは失敗します。 構造は本質的に直線的な時間内に構築されなければなりません。 

微妙な点は、ペアリングがエッジではグローバルではなく、頂点ではローカルであることです。 単一の頂点はその入射エッジをペアにする必要がある場合がありますが、構造の決定方法に応じて、異なる頂点が同じエッジをめぐって競合します。 エッジを隣接順に見たときにすぐに頂点でエッジをペアにしようとする単純な貪欲な場合、パートナーのエッジが後で使用可能になるかどうかが無視されるため、失敗する可能性があります。 

小さな失敗例は三角形から来ています。 

入力:```
3 3
1 2
2 3
3 1
```ここでは、すべての頂点の次数が 2 であるため、有効な解決策が存在します。各頂点は 1 回中間として機能し、1 つのパスを生成します。 しかし、頂点 1 のエッジを見つけたらすぐに貪欲にペアにすると、(1,2) と (1,3) がペアになり、一貫して完了できない方法で、頂点 2 と 3 に一致しないエッジが残る可能性があります。 正しい解決策は、ローカルでの即時の決定ではなく、グローバルで一貫したペアリング構造に依存します。 

もう 1 つのエッジ ケースはスター グラフです。```
1 4
1 2
1 3
1 4
1 5
```頂点 1 には 4 つのエッジがあるため、2 つのパスを形成できますが、葉は 1 を介してペアにする必要があります。どのソリューションでも、中央のエッジを 2 つのグループに注意深くペアにする必要があります。これは、頂点がエッジがペアで一致する「バッファ」のように動作することを示唆しています。 

## アプローチ

 ブルートフォースアプローチでは、グローバルな一貫性を確保しながら、すべての頂点でインシデントエッジのすべてのペアを効果的に検索し、各エッジをパートナーの隣接エッジが必要であるものとして処理しようとします。 これはすぐに組み合わせになります。 次数の頂点で$d$、 がある$(d-1)!!$入射エッジをペアにする方法、および頂点が共有エッジを通じて相互作用するため、状態空間がグラフ全体に爆発的に広がります。 中程度のグラフであっても、合計の度合いは指数関数的になり、限界を簡単に超えます。 

重要な点は、すべての組み合わせを一度に決定する必要はないということです。 代わりに、DFS ツリーでグラフを処理し、制御された方法で決定を遅らせることができます。 各頂点は「下から来るペアになっていないエッジ」を蓄積し、それらを可能な限りローカルでペアにし、残りの 1 つだけを上に押し上げます。 これにより、グローバル ペアリングの問題が、ツリー構造上のローカル パリティ伝播の問題に変わります。 

DFS ツリーは、すべてのエッジが子に行くか、祖先に戻るかのいずれかであるため、非常に重要です。 これにより、制約を解決するための自然な方向性が与えられます。子は未解決のエッジを上向きに報告し、親は段階的にペアリングを決定します。 これにより、エッジの再訪が回避され、各エッジが最初に適格になったときに確実に 1 回処理されるようになります。

 ## アルゴリズムのチュートリアル

 グラフのルートを任意の場所 (通常は頂点 1) に設定し、どのエッジが DFS ツリーの一部でどのエッジがバック エッジであるかを追跡しながら、グラフに対して DFS を実行します。 

1. 任意のルートから DFS を実行し、親関係をマークし、DFS コンテキスト内で各エッジを 1 回だけ通過するようにします。 DFS ツリーは、ボトムアップ処理のための階層を提供します。 
2. 各頂点について、「処理された子からの現在ペアになっていないインシデント エッジ」のリストを維持します。 このリストは、この頂点以上を含む長さ 2 のパスに一致させる必要があるエッジを表します。 
3. 子から戻るときに、子の残りのエッジ (存在する場合) を収集し、それを現在の頂点のリストに追加します。 これは、未解決のエッジが現在の頂点で解決されるか、さらに上に渡される必要があるという事実をモデル化します。 
4. 現在の頂点で、リストから 2 つのエッジを繰り返し取得し、この頂点を通るパスを形成します。 このようなペアごとに出力トリプルが生成されます$(u, v, w)$、2 つのエッジが共有する場所$v$。 両方のエッジがこの頂点で「待機」していることがすでに確認されており、他の場所では使用されないため、このステップは安全です。 
5. ペアリング後にエッジが 1 つだけ残っている場合、それをローカルで解決できないため、それを親に上向きに渡します。 これは、この頂点が 1 つの未解決の要求をその祖先に貢献しているという考えをモデル化します。 
6. すべての子を処理した後、ルートにいて、まだペアになっていないエッジがある場合、構築は不可能です。 それ以外の場合、ルートは空のリストで終わる必要があります。 

出力パスは、DFS の完了後ではなく、ペアリング手順中に収集されます。 

### なぜ効果があるのか

 DFS は、すべてのエッジが処理済みのサブツリーと未処理のサブツリー間の「境界」の一部となるときに、そのエッジが 1 回だけ考慮されることを保証します。 重要な不変条件は、ルートとなるサブツリーを処理した後、$v$、最大 1 つのインシデント エッジがペアになっていないままになり、サブツリーとグラフの残りの部分の間の唯一の相互作用ポイントになります。 これにより、サブツリーのすべての内部エッジがその内部で完全にペアになるように強制されます。これは、内部の不均衡があると複数のエッジを回避する必要があり、ペアリング プロセスと矛盾するためです。 すべての頂点は、両方のエンドポイントがすでに「利用可能」である場合にのみローカルでエッジをペアにするため、エッジが再利用されることはなく、生成されたすべてのトリプルは 2 つの異なるエッジに対応します。 ルート条件は、一致しない残りのエッジがないことを保証することで、グローバルな一貫性を強制します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for i in range(m):
        a, b = map(int, input().split())
        g[a].append((b, i))
        g[b].append((a, i))
    
    used_edge = [False] * m
    visited = [False] * (n + 1)
    parent = [-1] * (n + 1)
    parent_edge = [-1] * (n + 1)

    # store pairs as (vertex, edge_id)
    ans = []

    def dfs(v):
        visited[v] = True
        stack = []

        for to, eid in g[v]:
            if used_edge[eid]:
                continue
            used_edge[eid] = True

            if not visited[to]:
                parent[to] = v
                parent_edge[to] = eid
                res = dfs(to)
                if res is not None:
                    stack.append(res)
            else:
                # back edge: treat as available at v
                stack.append((v, eid))

        # pair edges at v
        while len(stack) >= 2:
            (v1, e1) = stack.pop()
            (v2, e2) = stack.pop()

            # e1 connects (v1 - v), e2 connects (v2 - v)
            # path is v1 - v - v2
            ans.append((v1, v, v2))

        # leftover
        if len(stack) == 1:
            return stack[0]

        return None

    res = dfs(1)

    if res is not None:
        print("No solution")
        return

    if len(ans) != m // 2:
        print("No solution")
        return

    out = []
    for x, y, z in ans:
        out.append(f"{x} {y} {z}")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```DFS は、すべてのエッジが最初に検出されたときに使用済みとしてマークされるように構造化されており、無向グラフでの二重走査を防ぎます。 各サブツリーは、頂点とエッジのペアとして表される未解決のエッジを最大 1 つ返します。 返されたオブジェクトは、まさにアルゴリズムで言及されている「残りの需要」です。 

ペアリング ループは重要なステップです。同じ頂点にある 2 つの保留中のエッジは、有効な長さ 2 のパスに直ちに結合されます。 中央の頂点は常に現在の DFS ノードであるため、正確性は、両方のエッジがすでにこのノードの処理領域にアタッチされているという不変条件から決まります。 

ルート チェックは、DFS が何も返さないことを検証することによって実装されます。これは、残りがあるとルートに一致しないインシデント エッジがあり、完全なペアリングが不可能になるためです。

 ## 特殊なケース

 三角グラフは、エッジを残さずにサイクルがどのように解決されるかを示しています。 DFS の間、すべてのエッジはルートで保留状態になり、きれいにペアになり、有効な単一パスが生成されます。 このアルゴリズムは、すべてのバック エッジがそのエンドポイントですぐに使用できるものとして扱われ、2 つの保留中のエッジが常に何らかの頂点で交わることを保証するため、これを処理します。 

星形グラフは反対の動作を示します。 すべての葉の端は中心に到達しますが、根元には奇数の葉の端があるため、最大のペアリングの後、必然的に 1 つのエッジがペアリングされないままになります。 DFS はこの残りを上向きに返し、ルートは不可能を検出します。 

4 つのノードのチェーンなどの単一のパスのような構造は、エンドポイントが完全に一致しない場合、中間頂点での内部ペアリングが役に立たないことを確認し、グローバル パリティ条件がルートによって強制されることを強化します。
