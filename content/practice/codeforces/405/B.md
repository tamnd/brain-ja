 ## 解決策
 ## 問題の理解

 私たちにはドミノの列が与えられ、そのうちのいくつかは最初に左または右に倒れるように押されますが、他のものは直立しています。 毎秒、倒れるドミノがすぐ隣のドミノを同じ方向に押します。 ただし、ドミノを両側から同時に押しても倒れません。 目標は、すべての動きが落ち着いた後、直立したままのドミノの数を決定することです。 

入力はドミノの数を与えます。`n`、および文字列`s`長さの`n`初期状態の説明。 出力は、最後に残っているドミノの数を表す単一の整数です。 

制約は控えめです。`n`は最大でも 3000 です。つまり、O(n²) の解は 1 秒の制限内にちょうど収まる可能性がありますが、これより著しく悪いものは安全ではありません。 各ドミノはそのすぐ隣のドミノとのみ対話できるため、ダイナミクスをモデル化するにはローカル伝播ルールで十分であることが示唆されます。 

トリッキーなエッジケースは、ドミノが反対勢力に直面する場合です。 例えば、`.R.L.`右方向への押しと左方向への押しの間にドミノが含まれています。 プッシュが同時に到着するため、中央のドミノは立ったままになります。 単純に右方向に伝播し、次に左方向に伝播する単純なアプローチでは、誤って失敗としてマークされてしまいます。 その他の微妙なケースとしては、行の端のドミノ、プッシュのない連続したドットのシーケンス、および 1 回のプッシュとそれに続くドットのシーケンスが挙げられます。 

## アプローチ

 ブルートフォース手法では、ドミノを秒ごとにシミュレートします。 各タイム ステップで、現在倒れているすべてのドミノの影響を計算し、次に倒れるドミノをマークします。 これは物理プロセスを反映しているため、これは正しいです。 ただし、最悪のシナリオが発生するのは、`n`ドミノは 1 秒ごとに 1 つずつ順番に倒れ、O(n²) 回の操作が必要となり、最大 900 万回の操作に達します。`n = 3000`。 これは実現可能ですが、不格好で不必要です。 

重要な洞察は、最終状態は各方向の最も近い最初の押し込みからの距離のみに依存するということです。 立っているドミノの任意のセグメントに対して、`R`左側と`L`右側では、最も近いプッシュに向かってドミノが倒れます。 ドミノが両方から等距離にある場合、ドミノは立ったままになります。 のみを含むセグメント`R`左側または`L`右側のドミノは完全にその方向に倒れ、隣接するものがない孤立したドミノは直立したままになります。 

この観測により、線形スイープで最も近い距離を計算できるようになります。`R`左から近いものから`L`右から。 これらの距離を比較することで、各ドミノの最終的な向きまたは立っている状態が決まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | n が大きいと遅すぎます |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの長さの配列を初期化します。`n`:`left_force`そして`right_force`、で満たされています`inf`。`left_force[i]`最も近い落下物からの距離を記録します`L`の右側にある`i`、 そして`right_force[i]`最も近い落下物からの距離`R`左に。 
2. 左から右へのパスを実行します。 最後を追跡する`R`観察し、各ドットについて、そこからの距離を記録します。`R`。 距離をリセット`inf`いつ`L`に遭遇したため、`L`右側のドミノには影響しません。 
3. 右から左へのパスを実行します。 最後を追跡する`L`観察し、各ドットについて、そこからの距離を記録します。`L`。 距離をリセット`inf`いつ`R`に遭遇します。 
4. 各ドミノについて、2 つの距離を比較します。 もし`right_force[i] < left_force[i]`、ドミノは右に倒れます。 もし`left_force[i] < right_force[i]`、左に下がります。 距離が等しい場合、ドミノは立ったままになります。 
5. 立っているドミノを数えて結果を出力します。 

それが機能する理由: すべてのドミノの最終状態は、どちらかの側の最も近い力によってのみ決定されます。 距離を事前に計算することで、対立する力の間に挟まれたドミノの相互作用ルールを維持しながら、毎秒のシミュレーションを回避します。 これにより、エッジセグメントや中央の競合ドミノであっても正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()

inf = n + 1
left_force = [inf] * n
right_force = [inf] * n

# Rightward forces
dist = inf
for i in range(n):
    if s[i] == 'R':
        dist = 0
    elif s[i] == 'L':
        dist = inf
    elif dist != inf:
        dist += 1
    right_force[i] = dist

# Leftward forces
dist = inf
for i in range(n-1, -1, -1):
    if s[i] == 'L':
        dist = 0
    elif s[i] == 'R':
        dist = inf
    elif dist != inf:
        dist += 1
    left_force[i] = dist

standing = 0
for i in range(n):
    if left_force[i] == right_force[i]:
        standing += 1

print(standing)
```最初のループは最も近いものまでの距離を計算します。`R`ドミノを右に押していきます。 遭遇すると距離をリセット`L`右方向への伝播を妨げるからです。 2 番目のループは、左方向の力についてのこのロジックを反映しています。 最後のループでは距離を比較し、直立したままのドミノを数えます。 重要な点は正しく処理することです`inf`その側からの影響がないことを示します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    s = input().strip()

    inf = n + 1
    left_force = [inf] * n
    right_force = [inf] * n

    dist = inf
    for i in range(n):
        if s[i] == 'R':
            dist = 0
        elif s[i] == 'L':
            dist = inf
        elif dist != inf:
            dist += 1
        right_force[i] = dist

    dist = inf
    for i in range(n-1, -1, -1):
        if s[i] == 'L':
            dist = 0
        elif s[i] == 'R':
            dist = inf
        elif dist != inf:
            dist += 1
        left_force[i] = dist

    standing = 0
    for i in range(n):
        if left_force[i] == right_force[i]:
            standing += 1
    return str(standing)
