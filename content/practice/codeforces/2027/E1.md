 ## 解決策
 ## 問題の理解

 各テスト ケースでは、いくつかの独立した石の山が得られます。 すべての山は、それ自体で小さなゲームのように動作します。手番では、山を選択し、そこからプラスの数の石を取り除きますが、その動きには大きな制約があります。 If the pile currently has value`x`、その限界は`a`、その後、番号を削除することができます`d`場合のみ`1 ≤ d ≤ a`そして`d`のビットサブセットです`x`、に設定されたすべてのビットを意味します`d`にも設定する必要があります`x`(正式には`x & d = d`）。 

プレイヤーがどのパイルでも有効な動きを行えなかった場合、ゲームは終了します。 プレイヤーが交互に動き、アリスがスタートするため、最適なプレイの下で開始位置が勝ちか負けかを判断することが求められます。 

この構造は、制限まで任意の数を削除できる標準の Nim ヒープではありません。 ここで、許可される移動は、算術制約とバイナリ構造を結合する現在のパイル サイズのビット構造によって異なります。 各パイルは動きの点では独立していますが、ゲームは選言的な合計であるため、最終的な結果は単純なパリティではなく、XOR のようなゲーム値 (グランディ数) に依存します。 

この制約は、テストごとに最大 10^4 パイル、すべてのテストで合計 10^4 を意味します。 これにより、移動をシミュレートしたり、パイルごとに完全な状態グラフを構築したりするソリューションは除外されます。 すべてのサブマスクを反復処理しても、`x_i`最大 2^30 の数値には指数関数的な数のサブマスクが含まれる可能性があるため、パイルごとに実行すると遅すぎます。 

エッジケースは、パイルに有効な動きがまったくない場合に発生します。 たとえば、次の場合`x = 8`そして`a = 3`、8 のサブマスクはありません`[1, 3]`、したがってパイルは不活性です。 すべてのパイルがゲームに何らかの値を提供していると想定する単純なソルバーは、そのようなパイルを非ゼロ コンポーネントとして誤って処理します。 

別の微妙なケースが発生する場合`a`大きいですが`x`ビットが非常にまばらです。 例えば、`x = 16`そして`a = 15`それでも何も動かないのに`a`16 の有効なサブマスクはすべて次のとおりであるため、大きいです。`{16, 0}`16 は範囲外です。 

最後に、最も危険な落とし穴は、ビットが独立していると仮定することです。`x`。 制約`d ⊆ x`これは、最大の任意の値ではなく、設定されたビットのサブセットのみを選択することを意味します。`a`。 

## アプローチ

 ブルートフォースアプローチでは、各パイルをゲーム状態として扱い、そのグランディ数を計算します。 州から`(x, a)`、すべての有効な手を列挙します`d`、に移行します`(x - d, a)`、到達可能な状態の mex を計算します。 しかし、これはすぐに爆発します。`x`最大 2^30 は最大 2^k のサブマスクを持つことができ、パイル全体では、これはテスト ケースごとはおろか、一度でも実行できなくなります。 

重要な観察は、パイル遷移は次のバイナリ構造のみに依存するということです。`x`そしてキャップ`a`、状態空間は小さな組み合わせ構造に崩壊します。 すべての減算を追跡する代わりに、空でないサブマスクを選択する動きを再解釈します。`x`によって制限される`a`、これは、セットビットのサブセットを選択することと同等です。`x`を超えない数値`a`。 

これにより、各パイルがビットセットに対する制約された減算ゲームに変わり、Grundy 値は最上位ビットのみに依存します。`a`そして`x`とその下の構造が異なります。 遷移を分析した後、各パイルは単純な XOR 寄与に帰着することがわかります。各パイルは、次のいずれかに応じてグローバル XOR に 0 または 1 のいずれかに寄与します。`a`少なくとも 1 つの有効な移動を許可するかどうか、および到達可能な状態のパリティが崩れるかどうか。 

ゲームは独立した 1 ビット ゲームの Nim ヒープ合計になるため、答えはパイルごとの条件から導出されたパイル値の XOR を計算することになります。

 ## アルゴリズムのチュートリアル

 私たちは各山を二分法で決定します。つまり、それが勝利の「トークン」に貢献するかどうかです。 

1. 各パイルについて、少なくとも 1 つの有効な手が存在するかどうかを計算します。`d`。 

これは、次のゼロ以外のサブマスクがあるかどうかを確認することと同じです。`x`そのような`d ≤ a`。 
2. そうでない場合`d`存在する場合、杭は終端であり、寄与は 0 です。 
3. それ以外の場合、最初のプレーヤーが全体のゲーム状態の等価性を反転する動きを強制できるという意味で、パイルが「アクティブ」であるかどうかを判断します。 これは、次のことをチェックすることになります。`x`それを超える`a`すべての動きをブロックするかどうか。 
4. この到達可能性条件に応じて、各杭に 0 または 1 のグランディ寄与を割り当てます。 
5. パイル全体のすべての寄与を XOR します。 
6. 最終的な XOR がゼロ以外の場合、アリスが勝ちます。 そうでなければボブが勝ちます。 

重要な削減点は、すべての有効な移動ダイナミクスをパリティ結果に折りたたんだ後、すべてのパイルがサイズ 0 または 1 の単一の Nim ヒープのように動作することです。 

### なぜ効果があるのか

 各パイルは公平なゲームであるため、ゲーム全体はパイルのグランディ値の XOR 合計になります。 許可される移動は、次のサブマスク上で下向きに閉じられたセットを形成します。`x`、切り捨てられます`a`これにより、移動が存在するかどうかを除いて、到達可能なすべての状態が構造的に同等であることが保証されます。 これにより、Grundy 関数はバイナリ状態に強制的に崩壊します。つまり、負けているポジションは、まさに有効なサブマスクが存在しないポジションであり、他のすべては均一な勝ちクラスに評価されます。 すべての勝ちポジションのグランディ値は 1 であり、負けポジションのグランディ値は 0 であるため、グローバル ゲームはこれらの指標の XOR に減少します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        x = list(map(int, input().split()))
        
        xor_val = 0
        
        for ai, xi in zip(a, x):
            # check if any valid move exists: need submask d of x with d <= a
            # equivalent to: there exists bit in x that fits within a's constraints
            # simplest characterization: if xi & ai is non-zero, we can form a move
            if (xi & ai) != 0:
                # pile contributes 1 in reduced game
                xor_val ^= 1
        
        print("Alice" if xor_val else "Bob")

if __name__ == "__main__":
    solve()
```コードは各パイルを単一のバイナリに圧縮します。
