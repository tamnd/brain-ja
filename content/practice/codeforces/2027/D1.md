 ## 問題の理解

 配列があります`a`それは完全に除去する必要があります。 いつでも私たちはある指標にいます`k`配列内`b`から始まる`k = 1`。 

現在の値については`b[k]`、合計が最大以下である残りの配列の空ではないプレフィックスを繰り返し削除する場合があります。`b[k]`。 そうした撤去ごとに費用がかかります`m - k`。 

増やすこともあるかもしれません`k`無料で。 以来`b`厳密に減少している、増加している`k`将来の削除のコストが安くなりますが、許可されるプレフィックスの合計も小さくなります。 

課題は、いつより大きな値に移行するかを選択することです。`k`また、最小限の総コストでアレイ全体を消去できるように、アレイを取り外し可能なプレフィックスに分割する方法も説明します。 

ある時点で有効な削除シーケンスが存在しない場合は、次のように出力する必要があります。`-1`。 

最も重要な制約は次のとおりではありません。`n`または`m`個別ですが保証$$\sum (n \cdot m) \le 3 \cdot 10^5.$$これはすぐに次のことを示唆しています。`O(nm)`動的プログラミング ソリューションは受け入れられます。 すべてのテスト ケースにわたる合計作業量は次の制限を受けるため、テスト ケースごとに両方の次元の二次関数はすべて適合します。`3 · 10^5`。 

考えられるすべての除去シーケンスを探索する総当り攻撃は指数関数的になります。 たとえ`n = 50`、配列をセグメントに分割する方法の数はすでに膨大です。 

いくつかの特殊なケースは見落とされがちです。 

考慮する```
a = [20]
b = [19, 18]
```最初の要素はすでに使用可能な最大制限を超えています。 いかなる場合でも削除は不可能です`k`、したがって、答えは次のとおりです`-1`。 

考慮する```
a = [5, 5]
b = [10, 1]
```に移動します`k = 2`無料ですが、要素は削除できません。`5 > 1`。 最適な戦略は、`k = 1`コストをかけてすべてを削除します`1`。 

もう一つの微妙なケースは、```
a = [4, 4, 4]
b = [8, 4]
```使用する`k = 1`、削除する場合があります`[4,4]`一緒に。 使用する`k = 2`、各操作のコストは低くなりますが、一度に削除できる要素は 1 つだけです。 最も安価なソリューションは、セグメント サイズと運用コストのバランスに依存するため、現在のコストや現在の容量のみに基づいた貪欲な選択では十分ではありません。 

## アプローチ

 自然な強引さは、プロセスを 2 つのアクションのうちの 1 つを繰り返し選択するものとみなすことです。 

増やすこともできます`k`、または現在の制限の下で有効なプレフィックスを削除します。 削除するたびに残りの配列が変更され、増加するたびに将来のコストが変化するため、状態の数は指数関数的に増加します。 配列の異なるセグメント化は、異なる実行パスに対応します。 

この強引な方法が正しい理由は、すべての有効な操作シーケンスが調査されるためです。 失敗する理由は、そのようなシーケンスの数が天文学的な数になるためです。 

より高速なソリューションを得るには、操作の構造を活用する必要があります。 

インデックスを使用して削除を実行すると決めた場合に注目してください。`k`、選択した位置で終わる可能な限り長いプレフィックスを削除する必要があります。 実際の操作では、削除されたセグメントの合計が最大でも次の値であることだけが考慮されます。`b[k]`。 

最初のものをすでに削除したことがわかっているとします。`i`の要素`a`。 値を使用する場合`b[k]`次の操作では、次に削除されたセグメントが任意の位置に延長される可能性があります。`j > i`満足のいく$$prefix[j] - prefix[i] \le b[k].$$ずっと`a_i`が正の場合、プレフィックスの合計は厳密に増加しています。 固定用`(i,k)`到達可能な最大位置があります。 あらゆる小さな位置にも到達可能です。 

これにより、問題は動的計画問題に変換されます。 

させて`dp[k][i]`最初の条件を考慮した後に必要な最小コストを示します。`k`の値`b`、最初の`i`要素はすでに削除されています。 

州から`(k,i)`私たちには2つの可能性があります。 

スキップする場合があります`b[k]`完全に移動して、`(k+1,i)`無料で。 

または、次を使用して 1 つの削除を実行することもできます。`b[k]`。 その削除がその位置で終了する場合`j`、移行コストは`(m-k)`。 

の積極性`a`到達可能な最も遠い場所を見つけることができます`j`プレフィックスの合計に対して二分探索を使用します。 

なぜなら`n · m`グローバルに次のように制限されています`3 · 10^5`、`O(nm)`DPでも十分速いです。

 ## アルゴリズムのチュートリアル

 ### 1. プレフィックスの合計を計算する

 しましょう$$pref[0]=0$$そして$$pref[i]=a_1+\dots+a_i.$$すべての要素がポジティブなので、`pref`厳密に増加しています。 

### 2. すべてのオブジェクトの到達可能性を事前計算します。`k`あらゆる価値観に対して`b[k]`そしてあらゆるポジション`i`、最大のインデックスを見つけます`reach[k][i]`そのような$$pref[reach[k][i]] - pref[i] \le b[k].$$これはまさに、位置の直後から開始される 1 回の削除で到達できる最も遠い位置です。`i`。 

プレフィックスの合計はソートされているため、二分探索によりこの位置が得られます。 

### 3. DP 状態を定義する

 しましょう$$dp[i]$$最初のものを正確に削除するための最小コストを表します`i`のいくつかのプレフィックスを処理した後の要素`b`価値観。 

最初は```
dp[0] = 0
dp[i] = +∞ for i > 0
```まだ要素が削除されていないためです。 

### 4. プロセス値`b`一つ一つ

 インデックスごとに`k`:

 新しい配列を作成する`ndp`のコピーとして初期化される`dp`。 

このコピーは、現在の値をスキップすることを表します`b[k]`。 

### 5. 使用する`b[k]`引越し用

 あらゆるポジションについて`i`有限のコストで:

 次回の手術費用$$m-k-1$$ゼロベースのインデックス付けで。 

操作は次の期間のどこかで終了する可能性があります。`i+1`そして`reach[k][i]`。 

これらすべての位置を単純に更新すると、複雑さは 2 次になります。 

代わりに、差分スタイルのスイープを使用して範囲最小更新を実行します。 

州ごとに`(i)`:```
all positions in [i+1 , reach[k][i]]
can receive dp[i] + cost
```すべての状態を処理した後、補助構造をスイープして最小値を適用します。 

これにより、現在のすべてのトランジションが得られます。`k`線形時間で。 

### 6. 交換する`dp`による`ndp`すべての移行後、`b[k]`が適用されたら、次の値に進みます。`b`。 

### 7. 答えを読む

 全部処理したら`m`値:```
dp[n]
```アレイ全体を削除するための最小コストです。 

無限大のままの場合は出力`-1`。 

### なぜ効果があるのか

 のすべての値に対して、`b`の場合、DP は両方の正当な選択を考慮します。つまり、その容量を完全に無視するか、セグメントの合計がその容量を考慮する追加の削除を 1 つ実行するかのいずれかです。 

各削除によって開始位置、終了位置、および値が選択されるため、すべての有効な操作シーケンスは DP 遷移のシーケンスに対応します。`k`。 

逆に、すべての DP 遷移はステートメントからの有効な操作を表します。 

到達可能性の計算により、選択したセグメントの合計が現在の制限を超えないときに遷移が存在することが保証されます。 考えられるすべての法的移行が表され、DP はそれらの中での最小コストを維持するため、最終値はまさに達成可能な最小総コストとなります。 

## Python ソリューション```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

INF = 10**18

t = int(input())

for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    reach = [[0] * (n + 1) for _ in range(m)]

    for k in range(m):
        limit = b[k]
        for i in range(n):
            r = bisect_right(pref, pref[i] + limit) - 1
            reach[k][i] = r

    dp = [INF] * (n + 1)
    dp[0] = 0

    for k in range(m):
        cost = m - k - 1

        ndp = dp[:]

        add = [INF] * (n + 2)

        for i in range(n):
            if dp[i] == INF:
                continue

            l = i + 1
            r = reach[k][i]

            if l <= r:
                val = dp[i] + cost
                if val < add[l]:
                    add[l] = val

        cur = INF
        for pos in range(1, n + 1):
            cur = min(cur, add[pos])
            if cur < ndp[pos]:
                ndp[pos] = cur

        dp = ndp

    ans = dp[n]
    print(-1 if ans == INF else ans)
```最初の部分では、プレフィックスの合計を構築します。 なぜなら、すべての値は、`a`が正の場合、プレフィックス配列の二分検索により、最も遠い取り外し可能なエンドポイントが正しく検出されます。`reach[k][i]`を使用して 1 回の操作がどこまで続くかを正確に保存します`b[k]`位置から開始すると延長される可能性があります`i`。 

DP には、削除されたプレフィックス長ごとの最小コストが格納されます。 コピーする`dp`の中へ`ndp`現在のファイルをスキップするオプションを実装します。`b[k]`。 

微妙な部分は、すべてのトランジションを効率的に処理することです。 ある州から`i`、連続した区間内のすべての位置は同じ候補値を受け取ります。 各エンドポイントを個別に更新する代わりに、間隔の開始時に値を挿入し、スイープ中に最小値を伝播します。 これにより、レイヤーごとの合計作業量が線形に保たれます。 

すべてのコストは 64 ビット整数内に快適に収まりますが、Python 整数を使用すると、オーバーフローの問題が完全に回避されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from bisect import bisect_right

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    INF = 10**18

    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        pref = [0]
        for x in a:
            pref.append(pref[-1] + x)

        reach = [[0] * (n + 1) for _ in range(m)]

        for k in range(m):
            for i in range(n):
                reach[k][i] = bisect_right(
                    pref,
                    pref[i] + b[k]
                ) - 1

        dp = [INF] * (n + 1)
        dp[0] = 0

        for k in range(m):
            cost = m - k - 1
            ndp = dp[:]

            add = [INF] * (n + 2)

            for i in range(n):
                if dp[i] == INF:
                    continue

                l = i + 1
                r = reach[k][i]

                if l <= r:
                    add[l] = min(add[l], dp[i] + cost)

            cur = INF
            for pos in range(1, n + 1):
                cur = min(cur, add[pos])
                ndp[pos] = min(ndp[pos], cur)

            dp = ndp

        out.append(str(-1 if dp[n] == INF else dp[n]))

    return "\n".join(out)
