 ## 解決策
 ## 問題の理解

 シングルエリミネーショントーナメントが与えられています$n$1 から 1 までのラベルが付けられたチーム$n$。 トーナメントの構造は固定的かつ機械的です。ラウンドごとに、残りのチームが元のラベルによって並べ替えられ、連続してペアになり、チーム 1 が 2 とプレイし、3 が 4 とプレイするというようになります。 勝者は勝ち進み、敗者は退場し、2 チームだけが残るまで同じプロセスが繰り返され、最終試合が行われます。 

問題は、勝者をシミュレーションしたり、チャンピオンを予測したりすることではありません。 代わりに、2つの特定のチームが伝えられます$a$そして$b$、そして、ペア構造と一致している限り、結果は自由に選択できると仮定して、それらが互いに出会う可能性がある最も早いラウンドを知りたいと考えています。 トーナメントの最後の試合でのみ対戦する場合は「決勝!」を出力し、それ以外の場合はラウンド インデックスを出力します。 

制約$n \le 256$は十分に小さいため、繰り返しのシミュレーションや繰り返しの間隔推論も実行可能です。 各ラウンドでチームの数が半分になるため、ラウンドの合計数は最大 8 になります。$O(n \log n)$あるいは$O(n \log^2 n)$推論は簡単だろう。 

主な微妙な点は、対戦が各ラウンド後の順序によって純粋に決定されることです。 これは、2 つのチームが、ブラケット構造を繰り返し崩壊した後、そのレベルで同じ隣接するペアに着地したときに、特定のラウンドで対戦することを意味します。 

よくある間違いは、前方消去のみをシミュレートしたり、勝者を貪欲に割り当てようとしたりすることです。 問題は単一のトーナメント結果に関するものではなく、2 つのチームがペアになるまで生き残ることを可能にする何らかの結果が存在するかどうかであるため、これは失敗します。 

2 番目の微妙な失敗例は、会議ラウンドが最初の距離のみに依存すると仮定していることです。 これは誤りです。勝者は各ラウンドの圧縮後に順位を再シャッフルするため、隣接関係は固定インデックスではなくブロック構造に基づいて進化します。 

## アプローチ

 ブルートフォース解釈では、試合で考えられるすべての結果をシミュレートし、$a$そして$b$各ラウンドでペアリング可能。 これには、すべてのラウンドのすべての試合で勝者となる可能性のある両方を考慮することが含まれます。 ラウンド1には、$n/2$それぞれに 2 つの選択肢があるため、$2^{n/2}$可能性はすでにあり、これはラウンド全体で指数関数的に爆発します。 たとえ$n = 16$、これは手に負えなくなります。 

重要な観察は、実際の勝者は決して必要ないということです。 重要なのは、$a$そして$b$トーナメント ブラケット構造の同じセグメントに十分長く留まることができます。 

どのラウンドでも、トーナメントは現在のセットをサイズの連続したブロックに効果的に分割します。$2^k$ラウンド中$k$、ラウンドごとにチームの数が半分になり、勝者の中での順序が維持されるためです。 2 人のプレーヤーは、半減を繰り返した後、あるラウンドでサイズ 2 の同じ隣接するブロックでペアになったときに対戦します。 

したがって、消去をシミュレートする代わりに、それらの位置を間隔としてシミュレートします。各ラウンドでは、2 で割ることによってインデックスが圧縮されます。2 つのインデックスが最下位ビットのみで異なる場合、それらはそのラウンドで一致します。 

同様に、インデックスが 1 のシーケンス内の現在の位置を追跡すると、ラウンドごとにインデックスが置き換えられます。$x$と$\lceil x/2 \rceil$。 2 つの値が等しくなるまで繰り返します。 両者が互角になる最初のラウンドは、両者が対戦するラウンドです。 最終段階で互角になった場合は「ファイナル！」に相当します。 

これにより、指数関数的なプロセスが対数的なプロセスに変換されます。

 ## アルゴリズムのチュートリアル

 各ラウンドは、連続するインデックスをペアにすることでトーナメントを縮小すると解釈します。 

1. ポジションから始める$a$そして$b$与えられたとおり。 

これらは、2 つのチームが現在のラウンド順序でどの位置に位置するかを表します。 
2. ラウンドカウンターを0から初期化します。 

このカウンターは、適用した圧縮の回数を追跡します。 
3. その間$a \neq b$、それぞれを にマッピングして両方の位置を更新します。$\lceil x/2 \rceil$。 

このステップでは、勝者がペアで進むことをモデル化します。(1,2) は 1 になり、(3,4) は 2 になります。 
4. 各圧縮後にラウンドカウンターをインクリメントします。 

各増分は、トーナメントの 1 ラウンドの奥に移動することに対応します。 
5. Stop when$a = b$。 この時点では、両チームは同じ試合ブロックに属しています。 
6. 2 チームだけが残っている最後の可能なレベルでこれが発生した場合は、「Final!」を出力し、それ以外の場合はラウンド インデックスを出力します。 

重要な考え方は、各圧縮によって相対的なトーナメント構造が保存されるため、最初に両方のインデックスが同じブロックに崩壊するのは、可能な限り最も早い会議ラウンドに正確に対応するということです。 

### なぜ効果があるのか

 すべてのラウンドで、チームは現在の順序のみに基づいてペアにグループ化されます。 その順序は勝者内に保持されます。つまり、重要なのはチームがどのペアブロックに属しているかだけです。 変革$x \to \lceil x/2 \rceil$これは、トーナメント ツリー内のポジションからその親ブロックへの正確なマッピングです。 

2 つのチームが同じブロックに入ると、そのブロックが試合の組み合わせに対応するレベルで対戦します。 このような最初のレベルは、各圧縮によってグループ化構造を維持しながら位置の解像度が厳密に低下するため、独特です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    
    round_num = 0
    
    while a != b:
        a = (a + 1) // 2
        b = (b + 1) // 2
        round_num += 1
    
    # determine if final round
    # number of rounds is log2(n), final happens when only 2 teams remain
    # if they meet at last compression, it's final
    if (1 << round_num) == n:
        print("Final!")
    else:
        print(round_num)

if __name__ == "__main__":
    solve()
```この実装では、各ラウンドがチーム インデックスをその親ペアリング インデックスにマップするという考えが直接適用されます。 表現`(a + 1) // 2`コンパクトなコンピューティング方法です$\lceil a/2 \rceil$、これはペアリング構造を正確にモデル化します。 

このループは、両方のチームがこの暗黙的なトーナメント ツリー内の同じノードに崩壊するまで続きます。 実行されるステップ数は、ブラケット構造内で最初に互換性が得られるラウンドです。 

最終条件では、この会議がトーナメント ツリーの可能な最後のレベル (2 チームだけが残っているレベル) で行われるかどうかがチェックされます。 これはブラケットの深さ全体に相当します。$\log_2(n)$問題の制約を考慮すると。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$a$そして$b$最初のラウンドですでに隣接しています。 入力用`4 1 2`、両方とも同じ初期ペアになっているため、ループが 1 回実行されて 1 が返され、最初のラウンドと正しく一致します。 

別のケースは、次のようにブラケットの反対側の端にある場合です。`8 1 8`。 圧縮のシーケンスは、両方がルートで収束するまでトーナメント ツリーの対称的な半分を通過するため、それらが最終段階でのみ一致することを示しています。 

3 番目のケースは、ローカルの異なるペアに属しているが、早い段階で会う場合です。`8 2 3`。 1 回の圧縮後、両方が同じ親ブロックにマップされるため、ラウンド 1 で会合します。これは、初期の隣接関係ではなく、圧縮後の隣接関係が会合時間を決定することを示しています。
