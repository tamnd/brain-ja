 ## 解決策
 ## 問題の理解

 2 人が整数座標の数直線上に立っています。$a$そして$b$。 これらは同じ整数の位置で終了する必要があり、それぞれが何度でも左または右に 1 ステップ移動できます。 

問題は、移動コストが直線的ではないことです。 人が作ったら$k$合計の動き、彼らの疲労は$1 + 2 + \dots + k$に等しい$k(k+1)/2$。 動きの順序は重要ではなく、人が合計で何歩歩くかだけが重要です。 

課題は集合場所を選択することです$x$、両方の人をに移動します$x$、疲労値の合計を最小化します。 

制約は非常に小さく、ポジションは最大 1000 です。これは、たとえ$O(n)$または$O(n^2)$パフォーマンスを気にせずに、考えられるすべての会議ポイントをスキャンすることが可能です。 本当の難しさは計算ではなく、移動コストがどのように動作するかを認識することです。 

ここでの単純な間違いは、両方が自由に移動できるため、答えは中間点のような動作のみに依存すると仮定することです。 もう一つの間違いは、方向性が重要であると考えることです。 左または右に移動してもコスト構造は同じであり、ステップ数だけが問題となるため、そうではありません。 

微妙なエッジ ケースは、両方の初期点から遠く離れた場所で両方が出会う場合です。 両方が移動する場合でも、距離を分割することで 2 次コストの増加を抑制できるため、1 人だけが移動する場合と比べて最適である可能性があります。 

## アプローチ

 直接的なアプローチは、あらゆる可能なミーティングポジションを試すことです$x$。 それぞれについて$x$、各人がどのくらいの距離を移動する必要があるかを計算します。$|a-x|$そして$|b-x|$。 人が動けば$d$ステップ、そのコストは$d(d+1)/2$。 両方のコストを合計すると、その集合場所での合計の疲労度がわかります。 

以来$a$そして$b$最大 1000 の場合でも、有効なミーティング ポイントはその周囲の狭い範囲内にあります。 外側の任意の点$[\min(a,b), \max(a,b)]$両方の距離を同時に増加させるだけであり、解決策を改善することはできません。 

ブルートフォース方式ですべての候補をチェックします$x$この間隔でコストを計算し、最小値を取得します。 この問題は整数点にわたる 1 次元の凸探索に帰着するため、これは正しいです。 

重要な洞察は、コスト関数は距離で二次関数であるため、個々のコストは線形よりも速く増加しますが、両方のエージェントの合計は整数直線上で単純な単峰関数を形成するということです。 これにより、最小値が間のセグメント付近で発生することが保証されます。$a$そして$b$、その小さな領域を徹底的にチェックするだけで十分です。

 ## アルゴリズムのチュートリアル

 1. 2 つの整数を読み取ります$a$そして$b$、2 人の友人の開始位置を表します。 整数線上で考えられる会合点を評価します。 
2. 間のすべての整数点として検索範囲を計算します。$\min(a,b)$そして$\max(a,b)$。 外側に移動すると両方の距離が同時に増加するため、最適な待ち合わせ場所はこの間隔内にある必要があります。 
3. 応答変数を非常に大きな数値で初期化します。 これにより、すべての候補となる集合場所で観察された最小合計疲労度が追跡されます。 
4. すべての整数点を反復処理します。$x$選択した範囲内で。 それぞれ$x$潜在的な集合場所として扱われます。 
5. それぞれについて$x$、各友人が移動しなければならない距離を計算します。$d_1 = |a-x|$そして$d_2 = |b-x|$。 これらの距離によって疲労度が完全に決まります。 
6. 三角数式を使って各距離を疲労度に換算する$d(d+1)/2$、両方の値を合計します。 これにより、次の場所での会議にかかる合計コストが計算されます。$x$。 
7. すべての計算値の最小値で答えを更新します。 
8. 最終的な最小疲労度を出力します。 

### なぜ効果があるのか

 固定の集合場所の場合、各参加者の費用は経路ではなく、歩数によってのみ決まります。 コストが厳密に増加し、距離が凸になっているため、間のセグメントから離れた動きを分散させます。$a$そして$b$両方を同時に助けることは決してありません。 したがって、最適解は 2 つの開始点を結ぶ区間内に存在する必要があります。 この境界領域内のすべての整数点を徹底的にチェックすることで、グローバル最小値が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cost(d):
    return d * (d + 1) // 2

a = int(input())
b = int(input())

lo = min(a, b)
hi = max(a, b)

ans = float('inf')

for x in range(lo, hi + 1):
    total = cost(abs(a - x)) + cost(abs(b - x))
    ans = min(ans, total)

print(ans)
```機能`cost`三角数の公式をエンコードします。これは、計算の唯一の非線形部分です。 このループでは、実行可能なすべての会議ポイントが考慮され、両方の参加者の正確なコストが評価されます。 

の使用`min(a,b)`そして`max(a,b)`両方の距離が一緒に増加するセグメントの外側の不必要なチェックを回避します。これにより、より悪い結果が生じるだけです。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    a = int(sys.stdin.readline())

 ## 特殊なケース

 重要なエッジ状況は、両方の友人がすでに近くにいる場合です。 入力の場合:```
3
4
```アルゴリズムはチェックのみを行います$x=3$そして$x=4$。 で$x=3$、費用は$0$そして$1$、 合計$1$。 で$x=4$、対称的な結果$1$。 このループにより、両方のエンドポイントが確実に考慮されるため、1 単位の範囲外のエラーによって最適値が失われることはありません。 

もう 1 つの重要なケースは、最適なミーティング ポイントが厳密に 2 つの位置の間にある場合です。 のために：```
1
5
```ループは、1 から 5 までのすべての点を評価します。$x=3$、コストは$3$そして$3$。 合計$6$は最小として正しく識別されます。 これにより、検索をセグメントに制限するだけで十分であり、外部ポイントは必要ないことが確認されます。
