 ## 解決策
 ## 問題の理解

 一連のヒープ サイズが与えられ、個々のヒープ値を繰り返し変更することができます。 それぞれの変更の後、非常に特殊なゲーム理論上の条件を満たすインデックスのサブシーケンスを選択する必要があります。 

ゲーム条件自体は標準的な Nim です。プレイヤーは順番に単一のヒープから正の数のオブジェクトを削除し、最後のオブジェクトを取得したプレイヤーが勝ちます。 よく知られている事実は、現在の位置のすべてのヒープ サイズの XOR が 0 の場合、最初のプレイヤーが負けることです。 

したがって、各クエリでは、常にインデックス 0 を含むインデックスのサブセットを構築するように求められ、選択したヒープ上でのみ Nim を再生すると、それらの値の XOR が 0 になります。 それが負けポジションになる唯一の条件だ。 

微妙な点は、この問題では有効なサブセットが要求されていないことです。 現在の配列状態に対して、両方の制約を満たすサブセットが 1 つだけ存在することが保証されます。 これにより、タスクが「任意のソリューションを見つける」から「更新のたびに独自のソリューションを効率的に再構築する」に変わります。 

n と m はどちらも最大 1000 で、値は 2n 未満であるため、数値のビット幅は小さく、およそ 11 ビットです。 これは、GF(2) 上の線形代数で十分であること、またクエリごとに構造を最初から再計算することが許容されることを強く示唆しています。 

素朴なアプローチでは、インデックス 0 を含むすべてのサブセットを試し、XOR の等価性をテストします。 サブセットが 2^n 個あり、n = 1000 の場合でも限界をはるかに超えているため、これは不可能です。 

さらに危険な間違ったアプローチは、XOR をゼロに近づける要素を貪欲に選択することです。 XOR には順序構造がないため、欲張った選択をすると、後で唯一の有効な表現が簡単にブロックされてしまいます。 たとえば、「大きく見える」要素を早期に削除すると、ターゲット XOR を生成する唯一の正確な分解が破壊される可能性があります。 

重要な観察は、サブセット XOR 制約が GF(2) に対する線形制約であるため、問題は各インデックスがベクトルに寄与する線形システムを解くことであり、ターゲット値を一意に表現する必要があるということです。 

## アプローチ

 ブルート フォース手法では、インデックス 1 ～ n のすべてのサブセットを反復処理し、XOR を計算して、それが a0 に等しいかどうかを確認します。 サブセットが 1 つだけ存在する場合は、それを出力します。 これは正しいですが、クエリごとに 2^n 個の可能性をチェックする必要があり、これは n = 1000 の場合でも完全に不可能です。 

XOR の構造は視点の切り替えを示唆しています。 各ヒープ値は、バイナリ ベクトル空間内のベクトルです。 サブセットの選択はベクトルの合計に相当します。 ターゲット ベクトル a0 を、インデックス 1 から n までの選択されたベクトルの合計として表す必要があります。 これはまさに GF(2) に関する線形表現の問題です。 

このように問題を捉えると、一意性が重要である理由が明らかになります。 表現が一意である場合、関連するベクトルは、線形方程式の解が曖昧さなく決定されるシステムのように動作し、基底表現を通じてその解を再構築できます。 

現在の値のセットに対して GF(2) に対する線形基底を維持します。そして重要なことに、基底ベクトルを形成するために使用された元のインデックスのセットを各基底ベクトルに付加します。 値の範囲が狭いため、基底サイズはビット数によって制限されるため、再構成は効率的です。 基礎を構築した後、標準的なガウス消去法スタイルのリダクションを使用して a0 を表現し、関連するインデックス セットを組み合わせて必要なサブシーケンスを復元します。 

更新は、変更のたびに基礎を最初から再構築することによって処理されますが、制約を考慮するとこれで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(2^n) | O(n) | 遅すぎる |
 | 線形基底再構成 | クエリごとに O(n log A) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

インデックス 1 から n を選択できる変数として扱い、インデックス 0 は常に最終的な答えに含まれます。 

### 1. 現在の配列の線形基底を最初から再構築します。 

インデックス 1 から n までを繰り返し、各値を XOR ベースに挿入します。 各基底ベクトルに加えて、どの元のインデックスがそれに寄与したかを示すビットセットまたはブール配列を保存します。 これにより、値の表現だけでなく、後で再構築することが可能になります。 

再構築が許容される理由は、n と m が両方ともわずか 1000 であるため、全体の n の二乗作業が小さいためです。 

### 2. 基底の不変構造を維持する

 値を挿入するときは、最上位ビットから最下位ビットへの標準の XOR リダクションが実行されます。 ベクトルが既存の基底要素から独立している場合、それは新しい基底ベクトルになります。 それ以外の場合は減少します。 関連するインデックス マスクは、XOR 演算を通じて一貫して更新されます。 

これにより、すべての基底ベクトルが元の要素のサブセットの XOR を表すことが保証されます。 

### 3. 目標値 a0 を基底を使用して表現します。 

ここで、基底ベクトルを使用して a0 を表現しようとします。 同じ基底消去プロセスを使用して、再び a0 を削減します。 そこから基底ベクトルを減算するときは常に、その基底ベクトルに格納されているインデックス セット内で XOR も計算します。 

最後に値がゼロになる場合、収集されたインデックス セットは、XOR が a0 に等しい有効なサブセットに対応します。 

この問題は一意性を保証しているため、この再構成により 1 つの解が得られます。 

### 4. 最終的な回答セットを構築する

 定義により、答えにはインデックス 0 が含まれている必要があります。 次に、インデックス 0 を、インデックス 1 から n にわたる a0 の再構成から得られたすべてのインデックスと結合します。 

最後に、必要なサブシーケンス形式に一致するようにインデックスを昇順に並べ替えます。 

### なぜ効果があるのか

 XOR 演算は、GF(2) 上にベクトル空間を形成します。 各ヒープ値はベクトルであり、サブシーケンスの選択はベクトルの合計に相当します。 基礎構造により、一連の独立した方向性を維持することができます。 表現可能なターゲットはすべて、この基底で分解されます。 

一意性条件により、ターゲットが正確に 1 つの方法でスパン内に存在することが保証されます。これは、再構成プロセスで係数の選択があいまいになることができないことを意味します。 したがって、基底に対する貪欲な消去によって唯一の有効な係数ベクトルが生成され、格納されているサポートの対応する結合によって正しいサブシーケンスが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXB = 12  # since values < 2n <= 2000

def build_basis(arr):
    basis_val = [0] * MAXB
    basis_mask = [0] * MAXB  # bitmask of indices (1..n)

    for i, x in enumerate(arr):
        if i == 0:
            continue
        mask = 1 << i
        v = x

        for b in reversed(range(MAXB)):
            if (v >> b) & 1:
                if basis_val[b] == 0:
                    basis_val[b] = v
                    basis_mask[b] = mask
                    break
                v ^= basis_val[b]
                mask ^= basis_mask[b]
    return basis_val, basis_mask

def represent(target, basis_val, basis_mask):
    res_mask = 0
    v = target

    for b in reversed(range(MAXB)):
        if (v >> b) & 1:
            v ^= basis_val[b]
            res_mask ^= basis_mask[b]

    return res_mask

def solve():
    n, m = map(int, input().split())
    arr = list(map(int, input().split()))

    for _ in range(m + 1):
        basis_val, basis_mask = build_basis(arr)

        mask = represent(arr[0], basis_val, basis_mask)

        ans = [0]
        for i in range(1, n + 1):
            if (mask >> i) & 1:
                ans.append(i)

        ans.sort()

        print(len(ans))
        print(*ans)

        if _ < m:
            p, x = map(int, input().split())
            arr[p] = x

if __name__ == "__main__":
    solve()
```基礎構造はコアコンポーネントです。 各ベクトルには、その数値 XOR 値と、それに寄与するインデックスを記述するビットマスクの両方が格納されます。 挿入中、既存の基底ベクトルを使用して先頭ビットを削除するときは常に、値空間とインデックス空間の間の一貫性を維持するためにマスクの XOR も行います。 

表現ステップはガウス消去法を反映しています。つまり、基底を使用してターゲットを削減し、同時にどの元のインデックスが必要であるかを蓄積します。 

インデックス 0 は常に最終セットに強制的に組み込まれ、表現プロセスの一部ではないため、個別に処理されます。 

## 実用的な例

 ### 例 1

 入力:```
3 1
5 6 2 7
0 3
```配列から始めます`[5, 6, 2, 7]`。 答えではインデックス 0 が固定されているので、インデックス 1..3 を使って 5 を表現しようとします。 

{6, 2, 7} から基底を構築した後、構造に応じて 5 を 6 と 3 番目の要素 7 と 2 の XOR として表すことができます。 消去を実行すると、一意のサブセットが生成されます。たとえば、`{1, 3}`6 XOR 7 = 5 の場合。 

したがって、最終的な答えは次のようになります`{0, 1, 3}`。 

| ステップ | アクション | ターゲット XOR | 選択されたインデックス |
 | --- | --- | --- | --- |
 | ビルドベース | 6、2、7を挿入 | - | 形成された基礎 |
 | 5を表す | 基準を使用して減らす | 0 | {1,3} |
 | 0を追加 | 強制インデックスを含める | - | {0,1,3} |

 これは、再構成がサブセットを検索するのではなく、一次方程式を解くように動作することを裏付けています。 

### 例 2

 入力:```
3 2
1 2 3 4
0 2
2 6
```最初に、インデックス 1..3 を使用して 1 の表現を解きます。 基底が表現を生み出すと仮定します`{1,2}`。 

アップデート後`a2 = 6`、再構築します。 ここで、ターゲットが変更され、それに応じてベースも変更され、異なる固有のサブセットが生成されます。 

| ステップ | 配列状態 | ターゲット | 出力セット |
 | --- | --- | --- | --- |
 | イニシャル | [1,2,3,4] | 1 | {0,1,2} |
 | アップデート後 | [1,2,6,4] | 1 | {0,1} |

 これは、XOR 表現が値の更新に対してどれほど敏感であるか、そしてなぜ再計算が必要なのかを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、インデックス 0 を除くすべての値が 0 の場合に発生します。 この状況では、どのサブセットも XOR ゼロになりますが、この問題では一意性が保証されるため、解にはインデックス 0 のみを含めることになります。基底が空のままで a0 の表現が 0 であるため、アルゴリズムがこれを処理します。結果として空の選択セットが生成され、その後インデックス 0 のみが追加されます。 

もう 1 つの微妙なケースは、複数の更新により基本構造が大幅に変更される場合です。 毎回基礎が最初から再構築されるため、前の状態への依存がなく、古いベクトルが残ることはありません。 

最後のケースは、a0 の表現がすべての基底ベクトルを使用する場合です。 ビットマスク共用体は、寄与するすべてのインデックスを正しく累積し、ソートにより、構築順序に関係なくサブシーケンス形式が有効なままであることが保証されます。
