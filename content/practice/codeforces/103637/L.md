 ## 解決策
 ## 問題の理解

 最初の 10 進数文字列として始まる非常に大きな整数を維持しています。 その後、一連の操作によって数値が段階的に変更されます。 各操作では、現在の数値の右端に 1 桁が追加されるか、右端の桁が削除されます。 変更するたびに、現在の数値の値をモジュロで出力する必要があります。$10^9 + 7$。 

重要な難点は、最初はその数が非常に大きくなる可能性があることです。$10^{100000}$長さが異なるため、標準型に整数として格納することはできません。 それを文字列として保存し、各クエリの後にモジュラスを最初から再計算しても、時間がかかりすぎます。$10^5$クエリと各再計算では現在の長さ全体がスキャンされ、最悪の場合は 2 次の動作が発生します。 

この制約は、どのソリューションも各クエリを償却一定時間で処理する必要があることを意味します。 初期文字列の線形前処理は許可されていますが、その後は各更新を次のように処理する必要があります。$O(1)$または$O(\log n)$、そして現実的には$O(1)$操作ごとに。 

微妙なエッジケースは削除から生じます。 たとえば、以下から始めることを考えてみましょう。$1234$、追加$5$、削除します。 順序は$1234 \rightarrow 12345 \rightarrow 1234$。 素朴なアプローチでは、文字列を切り捨てて再評価することにより、削除後に係数を再計算する可能性がありますが、それは遅すぎます。 もう 1 つの間違いは、数字の削除が単純に 10 を法として除算することで処理できると想定していることです。$MOD$、モジュラー算術では無効です。モジュラー除算には逆数が必要であり、数値は代数的ではなく構造的に変化するためです。 

正しいアプローチでは、値の剰余を維持しながら、追加操作とポップ操作の両方をサポートする必要があります。$MOD$効率的に。 

## アプローチ

 ブルートフォース戦略は簡単です。数値を文字列として保存します。 クエリごとに、それに応じて文字列を変更し、すべての桁を反復処理し、基数 10 で多項式表現を評価することで剰余を再計算します。 現在の数値に長さがある場合$L$、各再計算コスト$O(L)$、そして最大で$10^5$クエリが増加し、長さが大幅に増加する可能性があるため、最悪のケースが発生します。$O(n^2)$またはランタイムが悪化します。 これは明らかに実行不可能です。 

重要な観察は、数値が常に基数 10 で解釈され、モジュロ演算がインクリメンタル構築と互換性があることです。 現在の価値を維持する場合$x$モジュロ$MOD$、数字を追加$d$数値を次のように変換します$x' = (x \cdot 10 + d) \bmod MOD$。 これは標準のローリング ハッシュの動作です。 

難しいのは削除操作です。 最後の数字を削除するということは、変換を逆に行う必要があることを意味します$x \cdot 10 + d$。 そのステップで追加された数字がわかっている場合は、その数字を引いて 10 で割ることで前の値を復元できます。 10 による除算モジュロ$MOD$10 の逆剰余を掛ける必要があります。$MOD = 10^9 + 7$プライムです。 

ただし、操作を正しく元に戻すには、数字の完全な履歴を知る必要もあります。 これは、現在のモジュール値と数字シーケンスの両方の状態のスタックを暗黙的または明示的に維持することを示唆しています。 

したがって、最適なアプローチは、各エントリが現在の値を法的に格納するスタックを維持することです。$MOD$。 追加の場合は、新しい値をプッシュします。 削除の場合はポップします。 各状態はすでに完全なプレフィックス値を表しているため、何も再計算する必要はありません。

 ## アルゴリズムのチュートリアル

 進化する数値をプレフィックスのシーケンスとして扱います。各プレフィックスは既知の値のモジュロを持ちます。$MOD$。 

1. 初期数値文字列をモジュロ値に変換します。$MOD$。 数字を左から右に更新しながら処理します$x = (x \cdot 10 + digit) \bmod MOD$。 これにより基本状態が確立されます。 
2. この値でスタックを初期化します。 スタックは、各操作後の有効な状態の履歴を表します。 
3. 各クエリについて、そのタイプを検査します。 数字を使った追加操作の場合$d$、新しい値を次のように計算します。$new = (stack[-1] \cdot 10 + d) \bmod MOD$、それをスタックにプッシュします。 これは、基数 10 の位置値の拡張から直接続きます。 
4. クエリが削除操作の場合は、スタックから最上位の要素を削除します。 以前の値はすでにその下に保存されているため、再計算は必要ありません。 
5. 各演算の後、スタックの最上位の値を出力します。 

重要な考え方は、数値を代数的に「編集」しようとしないということです。 代わりに、各操作を事前計算された状態間を移動するものとして扱います。 

### なぜ効果があるのか

 いつでも、スタックのトップは、基数 10 の数値モジュロとして解釈される現在の数字シーケンスの値に正確に対応します。$MOD$。 数字を追加すると、遷移式は前のすべての数字の位置シフトを正しく反映します。 削除すると、スタックは正確な以前のプレフィックスを復元します。これは、以前に正しく計算されたことが保証されています。 これにより不変条件が作成されます。i 番目の演算を処理した後、スタックには現在の数値の正しいモジュラー値が含まれるため、出力は常に正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    x0 = input().strip()
    q = int(input())
    
    stack = []
    
    val = 0
    for ch in x0:
        val = (val * 10 + (ord(ch) - 48)) % MOD
    stack.append(val)
    
    for _ in range(q):
        parts = input().split()
        if parts[0] == '+':
            d = ord(parts[1]) - 48
            val = (stack[-1] * 10 + d) % MOD
            stack.append(val)
        else:
            stack.pop()
        
        print(stack[-1])

if __name__ == "__main__":
    solve()
```最初のループは、標準のローリング構造を使用して、開始文字列をモジュール値に変換します。 その後、スタックはすべての中間結果を保存するために使用されます。 

追加の場合、基数 10 のシフト式を明示的に適用します。 これにより、前の数字を再構築したり走査したりする必要がなくなります。 削除の場合は、以前の状態から決定的に構築されたという事実に基づいて、最新の状態を単純に破棄します。 

微妙な点は、数字だけを保存してオンデマンドで再計算しようとするのではなく、完全なプレフィックス値を保存していることです。 これにより、モジュール式の逆変換や複雑なロールバック ロジックが必要なくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    MOD = 10**9 + 7
    data = inp.strip().splitlines()
    
    x0 = data[0].strip()
    q = int(data[1])
    
    stack = []
    val = 0
    for ch in x0:
        val = (val * 10 + (ord(ch) - 48)) % MOD
    stack.append(val)
    
    idx = 2
    out = []
    for _ in range(q):
        parts = data[idx].split()
        idx += 1
        if parts[0] == '+':
            d = ord(parts[1]) - 48
            val = (stack[-1] * 10 + d) % MOD
            stack.append(val)
        else:
            stack.pop()
        out.append(str(stack[-1]))
    
    return "\n".join(out)

# custom 2: repeated deletes back to initial
