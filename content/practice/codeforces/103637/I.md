 ## 問題の理解

 2 つの整数が与えられます。 そのうちの 1 つ、$n$、具体的には、存在するボックスの数を決定します。$2n$合計ボックス数。 2 番目の値は、$a$、各ボックス内に個別のアイテムがいくつ入っているかを示し、各ボックスは他のボックスから独立しています。 

各ボックスから正確に 1 つのアイテムを選択する必要があります。 どの箱にも入っているので、$a$選択肢とすべてのボックスは独立しているため、完全な選択を行う方法の総数は、すべてのボックスにわたる選択肢の積になります。 この raw カウントはモジュロで減算されます。$2n + 2$、その残りが必要な出力になります。 

重要な問題は、両方とも$n$そして$a$と同じ大きさにすることができます$10^9$, したがって、ボックスの総数も多くなり、直接の値は$a^{2n}$は天文学的に大きく、明示的に計算することはできません。 

最も重要な観察は、完全な値が求められるのではなく、指数構造に密接に関係する数値を法とした剰余のみが求められるということです。$2n + 2$。 これにより、問題は基本的に、指数自体に依存する係数を使用したべき乗剰余演算に関するものになります。 

電力を直接計算しようとすると、単純な失敗例がすぐに現れます。 たとえば、次の場合$n = 10^9$そして$a = 2$、値は$2^{2 \cdot 10^9}$、これは計算することも、保存することさえ不可能です。 構造を意識せずにべき乗剰余アプローチを使用する場合でも、複雑さに関しては問題ありませんが、係数は固定されていないため、注意が必要です。 

次の場合、別の微妙な問題が発生します。$a$は弾性率よりも大きいです。 不注意な実装では、早期の削減は無害であると想定する可能性がありますが、弾性率は次のように依存します。$n$、指数と法は自明ではない方法で相互作用するため、べき乗剰余規則の下で正確さを維持する必要があります。 

## アプローチ

 ブルートフォースの解釈は簡単です。ボックスごとに選択肢の数を掛けます。$a$、繰り返しました$2n$回。 これにより、$a^{2n}$。 この値を計算した後、それを剰余演算します$2n + 2$。 

各ボックスが独立した乗算因子に寄与するため、これは概念的に機能します。 ただし、乗算を繰り返して累乗する必要があるため、計算自体は実行できません。$2n$乗算は最大で$2 \cdot 10^9$、合理的な制限時間をはるかに超えています。 

自然な改善は、高速べき乗演算に切り替えることです。 これにより、べき乗コストが線形から対数に削減されます。$n$。 ただし、より深い洞察は、係数が任意ではないということです。 まさにその通りです$2n + 2$、常に偶数であり、指数と強く関連しています。$2n$。 この構造は、剰余縮約と組み合わせた二乗の繰り返しで十分であり、法が必ずしも素数である必要はなく、オイラーの定理のようなさらなる数論のトリックは必要ないことを示唆しています。$a$が共素であることは保証されません。 

したがって、最適なアプローチは単純に係数を使用した 2 進累乗です。$2n + 2$。

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り$n$そして$a$。 箱の数は、$2n$、係数は次のように定義されます。$m = 2n + 2$。 
2. ベースを減らす$a$モジュロ$m$。 剰余乗算では等価性が維持され、中間値が小さく保たれるため、最終結果は変わりません。 
3. 指数を設定する$e = 2n$。 私たちはコンピューティングを行っています$a^e \bmod m$。 
4. 結果を次のように初期化します。$res = 1$。 これは空の積を表し、乗算の中立要素です。 
5. ながら$e > 0$、指数を少しずつ処理します。 最下位ビットの場合$e$が 1 の場合、現在の結果を乗算します。$a$モジュロ$m$。 これにより、指数の 2 値分解に対応するべき乗が正確に含まれることが保証されます。 
6. ベースを直角にする$a = a^2 \bmod m$。 これにより、次の 2 のべき乗に進みます。 
7. 指数を 1 ビット右にシフトし、実質的に 2 で割ります。 

各反復で指数サイズが指数関数的に減少するため、このメソッドは非常に大きな入力に対しても効率的です。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは次の不変条件を維持します。$res \cdot a^e$（どこ$a$は現在のベースです) 元のベースと一致します$a^{2n}$モジュロ$m$。 指数のバイナリ表現により、対応するビットが設定されたときに 2 の累乗が 1 回だけ寄与することが保証されます。 乗算は剰余算術のもとで結合的であり、各約分は合同性を維持するため、最終結果は目的の値と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mod_pow(a, e, mod):
    res = 1
    a %= mod
    while e > 0:
        if e & 1:
            res = (res * a) % mod
        a = (a * a) % mod
        e >>= 1
    return res

def solve():
    n, a = map(int, input().split())
    mod = 2 * n + 2
    exp = 2 * n
    print(mod_pow(a, exp, mod))

if __name__ == "__main__":
    solve()
```機能`mod_pow`バイナリ累乗を実装します。 基数は剰余化されます`mod`二乗中のオーバーフローの増加を避けるために、すぐに実行します。 ループは指数をビットごとに処理し、現在のビットが指数の分解に寄与するたびに結果に乗算します。 

main 関数は係数を計算します。$2n + 2$、指数を次のように設定します。$2n$、計算をべき乗剰余ルーチンに委任します。 

よくある間違いは、基本モジュロを減らすのを忘れることです`mod`ループを開始する前に。 正確さのために厳密に必要なわけではありませんが、中間値が不必要に大きくなるのを防ぎます。 もう 1 つの微妙な問題は、指数と係数を混同することです。これは、どちらも依存するためです。$n$。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$a = 1$。 その場合、すべての乗算は中立であり、結果は常に 1 でなければなりません。$n$。 アルゴリズムが初期化されます`res = 1`すべての乗算は 1 を法として行われるため、決して変更しません。$m$。 

もう一つのエッジケースは小さい$n$、 特に$n = 1$, ここで、係数は$4$。 どれについても$a$、アルゴリズムは次のように計算します。$a^2 \bmod 4$。 次の例に見られるように、中間の 2 乗によってリダクションがゼロになる場合でも、2 進累乗はこれを正しく処理します。$2^2 \equiv 0 \pmod 4$。 

3 番目のケースは次の場合です。$a$はすでに係数よりも大きくなっています。 アルゴリズムはそれを直ちに次のように削減します。`a %= mod`後続の操作が制限され、正しい状態が保たれるようにします。
