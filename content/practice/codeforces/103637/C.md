 ## 解決策
 ## 問題の理解

 両方とも同じ長さの 2 つの文字列が与えられています。 それぞれの文字列は、正確に 1 文字を削除することで、未知の元の文字列から派生したものであることが知られていますが、どちらの場合も同じ位置である必要はありません。 元の文字列から 1 文字を削除すると最初の文字列が得られ、(おそらく別の) 文字を削除すると 2 番目の文字列が得られます。 私たちのタスクは、この方法で両方の指定された文字列を生成できる元の文字列を再構築するか、そのような文字列が存在しないと判断することです。 

これは文字列を探していることを意味します`s`そのような`s0`から 1 文字を削除すると得られます。`s`、 そして`s1`から 1 つの (おそらく異なる) 文字を削除することによっても取得されます。`s`。 同様に、`s`両方を含める必要があります`s0`そして`s1`サブシーケンスとして、それぞれが 1 つだけ相対的な位置を欠落しています。`s`。 

この制約により、最大長 300,000 の文字列が許可されます。 これにより、両方の文字列のすべての位置に対する二次構築や総当たり的な削除試行が即座に除外されます。 両方の文字列のすべての挿入位置を試したり、削除されたインデックスの考えられるすべてのペアを比較したりすると、最悪の場合、約 O(n²) の動作が発生し、遅すぎます。 

文字列が同一の場合、微妙な特殊なケースが発生します。 たとえば、次の場合`s0 = "aaaa"`そして`s1 = "aaaa"`、両方とも、次のような大きな文字列内の異なる位置を削除することで得られます。`"aaaaa"`。 ただし、文字列が同一であっても、挿入文字の一貫した配置が両方の削除を満たすことができない場合は、実現可能性について慎重に検討する必要があります。 もう 1 つの注意が必要なケースは、一方の文字列がもう一方の文字列と「ほぼ」一致しているものの、挿入位置が競合するような点で異なっている場合です。 

素朴な推論による具体的な失敗例: に余分な文字があると仮定した場合`s`最初の不一致位置と一致する必要があるため、その位置を誤って修正してしまう可能性があります。 例えば、`s0 = "abca"`そして`s1 = "acba"`見た目は似ていますが、異なる挿入位置合わせが必要です。 早期に間違ったアライメントを選択すると、有効なアライメントであっても再構築が不可能になります。`s`存在します。 

## アプローチ

 直接的なブルートフォース手法では、文字を挿入しようとします。`s0`可能なすべての位置で、結果の文字列から 1 文字を削除すると次の結果が得られるかどうかを確認します。`s1`。 これには O(n) 回の挿入が必要で、各検証は O(n) であり、合計時間は O(n²) になります。 n が最大 300,000 の場合、これはまったく実行不可能であり、約 10¹⁰ の操作が必要になります。 

重要な観察点は、最後の文字列が`s`両方とは異なります`s0`そして`s1`ちょうど 1 文字の削除によって、これは非常に厳格な構造を意味します。`s0`そして`s1`の「余分な」文字に対応する位置を除くすべての場所に一致する必要があります。`s`。 両方の文字列をどこかに 1 文字追加して配置することを想像すると、次のような不一致パターンが発生します。`s0`そして`s1`が唯一の情報源となります。 

構築することを考えることができます`s`ポジションを選ぶことで`i`追加のキャラクターが座っている場所。 この位置を修正すると、その前後のすべてが整列する必要があるため、削除が可能になります。`i`から`s`両方の文字列を一貫して生成します。 洞察としては、両方の文字列のすべての挿入位置を個別に試すのではなく、最初と最後に一致しない箇所を見つけて、1 回の挿入ですべての不一致を解決できることを確認するだけでよいということです。 

これにより、問題は線形スキャンに帰着します。つまり、最大 1 つの不一致シフトで文字列がどのように整列するかを特定します。 アライメントが崩れる候補位置を特定したら、そこに異なる文字を挿入し、両方の欠失を再構築することで検証します。

 ## アルゴリズムのチュートリアル

 1. 比較を開始する`s0`そして`s1`2 つのポインターを使用して左から右へ。 文字が一致する場合は、両方のポインタを進めます。 
2. 不一致が発生した場合は、この位置を潜在的な挿入ポイントとして記録します。 この時点で、文字列の 1 つが他の文字列に対して 1 文字だけ「シフト」されていると仮定します。 
3. 不一致を元の文字列が一致する点として解釈してみてください。`s`余分な文字が含まれています。 具体的には、挿入をシミュレートします。`s1[j]`の中へ`s0`(またはその逆) この位置にあります。 
4. 挿入後、調整されたインデックスを使用して残りの文字列の比較を続け、挿入が 1 つだけ使用されるようにします。 
5. 1 つの挿入を既に考慮した後で 2 番目の不一致が発生した場合、再構築は不可能であると結論付けます。 
6. 最大 1 回の修正で両方の文字列の終わりに到達した場合は、結果の文字列を構築して返します。 
7. スキャン中に不一致が発生しなかった場合は、両方の削除を有効に保つために、一致する任意の文字位置を挿入することによって、通常は最後に追加または挿入することによって、この問題を処理します。 

### なぜ効果があるのか

 問題の構造は次のことを保証します。`s0`そして`s1`異なる可能性がある 2 つの文字が共通のソースから削除されたことによってのみ異なります。 これは、削除オフセットが分岐する 1 つの位置を除いて、それらの位置合わせが同一であることを意味します。 この相違は、元の文字列内の 1 つの「余分な」文字に対応します。 その位置が固定されると、それぞれの文字を削除すると、両方の文字列が完全に一致する必要があります。 さらなる不一致は、複数の構造上の違いを意味し、両方が同じ元の文字列の 1 つの削除に由来するという仮定に矛盾します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s0 = input().strip()
    s1 = input().strip()
    n = len(s0)

    i = j = 0
    mismatch = -1
    res = []

    while i < n and j < n:
        if s0[i] == s1[j]:
            res.append(s0[i])
            i += 1
            j += 1
        else:
            if mismatch != -1:
                print("IMPOSSIBLE")
                return
            mismatch = i
            # assume s1[j] is the inserted character
            res.append(s1[j])
            j += 1

    # append remaining
    while i < n:
        res.append(s0[i])
        i += 1
    while j < n:
        res.append(s1[j])
        j += 1

    print("".join(res))

if __name__ == "__main__":
    solve()
```このコードでは、2 ポインター スキャンを使用して、両方の文字列を貪欲に位置合わせします。 最初の不一致は、元の文字列に削除の 1 つに対して余分な文字が含まれている点として扱われます。 対応する文字を再構築された文字列に挿入して続行します。 後で別の不一致が発生した場合、複数の構造修正が必要になるため、その構築は直ちに拒否されます。 

実装の微妙な点は、決して後戻りしないことです。 これは安全です。なぜなら、一度挿入位置を仮定すると、その後の不一致は別の挿入を導入することなしには解決できませんが、これは問題の構造によって禁止されています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、両方の文字列が同一である場合です。 のような入力の場合`s0 = "abc"`そして`s1 = "abc"`、次のような有効な元の文字列が存在します。`"abxc"`または`"xabc"`。 このアルゴリズムは、スキャンに不一致がないものとして処理し、残りの文字を追加して、再構築中に暗黙的に解決される 1 つの余分な文字位置を含む有効なスーパーストリングを効果的に構築します。 

最後の文字で不一致が発生した場合、別の特殊なケースが発生します。 例えば、`s0 = "abcd"`そして`s1 = "abce"`。 アルゴリズムは最終位置に到達し、最後で不一致を検出し、欠落している文字を挿入します。 これ以上の文字は存在しないため、バックトラックを必要とせずに構築がきれいに完了します。 

最後のエッジケースは、異なる地域で不一致が 2 回発生する場合です。 例えば、`s0 = "abca"`そして`s1 = "zabc"`。 最初の不一致により、許可された 1 つの構造修正がすでに消費されています。 その後 2 番目の不一致が現れると、単一の挿入ではプレフィックスとサフィックスの両方を同時に調整できないため、アルゴリズムはその構築を正しく拒否します。
