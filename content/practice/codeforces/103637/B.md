 ## 解決策
 ## 問題の理解

 それぞれがタスク セットのコード名を表す文字列のコレクションが与えられます。 このコレクションから、正確に 2 つの異なる文字列を選択する必要があります。それらをどちらの順序で配置しても、次々に連結することができます。 

目的は、連結後にターゲット文字列「BSUIROPENX」を生成する個別のインデックスの順序付きペアが何組あるかをカウントすることです。 区別性は文字列値ではなくインデックスによって定義されるため、2 つの同一の文字列が異なる位置に出現する場合、それらは異なる選択肢として扱われます。 

重要な制約は入力のサイズです。文字列は最大 100,000 個、合計の長さは最大 1,000,000 です。 これにより、文字列のすべてのペアを直接テストしようとするソリューションは即座に除外されます。これは、文字列の数が 2 次になり、実行可能な制限をはるかに超えるためです。 各比較が O(1) である O(n²) チェックでも、最悪の場合、すでに約 10¹⁰ の操作が必要になります。 

より微妙な制約は、ターゲット文字列の長さによって決まります。これは固定で小さい (10 文字) です。 これは、この正確な文字列の形成に寄与できる文字列のみが関連しており、それ以外はすべて無視できることを示唆しています。 

よくある失敗例は、任意のペア間で部分文字列のマッチングまたは重複マッチングが必要であると想定している場合です。 たとえば、すべてのペアに対してサフィックスとプレフィックスを動的に一致させようとすると、分割点が部分一致ではなく完全な一致によって制約される場合、カウントしすぎたり、見逃したりすることが容易になります。 

具体的な落とし穴は、同一の文字列が複数存在する場合に現れます。 たとえば、リストに「BSU」のコピーが 3 つと「IROPENX」のコピーが 2 つ含まれている場合、答えは 3 + 2 ではなく、3 × 2 に、該当する場合は逆の可能性を加えたものになります。 多くの誤った解決策は、順序付けによって寄与が 2 倍になること、および同一の文字列が依然として別個のインデックスとして扱われなければならないことを忘れています。 

## アプローチ

 ブルートフォース手法では、順序付けされた文字列のペアすべてを反復処理し、それらの連結が「BSUIROPENX」と等しいかどうかを確認します。 各チェックのコストは O(L) (L は最大 10)、ペアは O(n²) です。 n が 10⁵ までの場合、約 10¹⁰ の比較が行われることになりますが、これでは遅すぎます。 

重要な点は、実際には任意の連結を考慮する必要がないということです。 ターゲット文字列は固定されているため、有効なペアはすべて「BSUIROPENX」内の分割ポイントに対応する必要があります。 つまり、ターゲットを 2 つの部分に分割し、プレフィックスに等しい 1 つの文字列とサフィックスに等しいもう 1 つの文字列を探すことができます。 

ターゲットを T = “BSUIROPENX” とします。 1 から 9 までのすべての分割位置 i について、T[0:i] と T[i:] を考慮します。 有効な順序ペアは、T[0:i] に等しい 1 つの文字列と T[i:] に等しいもう 1 つの文字列で構成されなければなりません。 これにより、問題は文字列の頻度カウントに限定されます。 

各文字列が入力に出現する回数を単純にカウントし、すべての有効な分割ポイントを合計して周波数の積を計算します。 また、自動的に順序付けを尊重する必要があります。最初のプレフィックスと 2 番目のサフィックスはすでに方向を定義しており、問題で両方の連結順序が必要な場合は、逆の順序を個別に考慮します。 したがって、分割ごとに、プレフィックスとサフィックスが異なる場合は freq(prefix) × freq(suffix) と freq(suffix) × freq(prefix) の両方を加算し、それらが等しい場合は freq(prefix) × (freq(prefix) − 1) のみを加算します。 

これにより、問題は文字列の線形スキャンと固定長ターゲットに対する継続的な作業に軽減されます。

 ## アルゴリズムのチュートリアル

 ターゲット文字列を T = “BSUIROPENX” とします。

1. すべての入力文字列を読み取り、頻度マップを構築します。 それぞれの個別の文字列には、その文字列が出現した回数が格納されます。 これにより、スキャンを繰り返す代わりに、後で一定時間の検索が可能になります。 
2. 1 から len(T) − 1 までのすべての可能な分割位置 i を反復します。各分割は、プレフィックス A = T[0:i] とサフィックス B = T[i:] を定義します。 
3. 各分割について、A と B の両方が周波数マップに存在するかどうかを確認します。 どちらかが欠けている場合は、有効なペアを形成できないため、この分割を完全にスキップします。 
4. A と B が異なる文字列の場合は、freq[A] × freq[B] × 2 を答えに加算します。 因数 2 は、A の後に B が続く、および B の後に A が続くという両方の可能な順序を考慮します。 
5. A と B が同じ文字列の場合、freq[A] × (freq[A] − 1) を加算します。 順序は依然として重要ですが、インデックスとそれ自体のペアを避ける必要があるため、これは、同一の文字列から選択された個別のインデックスの順序付きペアをカウントします。 
6. すべての分割点にわたって結果を累積し、最終的な合計を出力します。 

### なぜ効果があるのか

 すべての有効な連結はターゲット文字列と等しくなります。 したがって、選択した 2 つの文字列間の境界は、ターゲットの内部カット位置の 1 つと正確に一致する必要があります。 文字列の連結では重複やギャップがなく順序が維持されるため、他の構造は不可能です。 これにより、問題空間全体が任意の文字列ペアから最大 9 個の分割候補の有限セットに縮小されます。 頻度ベースのカウントでは、プレフィックスとサフィックスの分割に対応するかどうかに応じて、すべての有効なインデックス ペアが 1 回だけカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    freq = {}

    for _ in range(n):
        s = input().strip()
        freq[s] = freq.get(s, 0) + 1

    target = "BSUIROPENX"
    ans = 0

    m = len(target)

    for i in range(1, m):
        a = target[:i]
        b = target[i:]

        ca = freq.get(a, 0)
        cb = freq.get(b, 0)

        if ca == 0 or cb == 0:
            continue

        if a != b:
            ans += ca * cb * 2
        else:
            ans += ca * (ca - 1)

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、繰り返しの文字列を繰り返しスキャンする必要がないように、入力を頻度テーブルに圧縮することから始まります。 ターゲット文字列の各分割は、最終的な連結がどのように形成されるかについての構造的仮説として扱われます。 等しい半分と等しくない半分の処理は、順序付きペアが 2 つの異なるグループから来たのか、それとも 1 つのグループ内から来たのかを決定するため、重要です。 

個別の部分の 2 の乗算は見落としがちですが、これは両方の連結順序が有効であり、別々にカウントする必要があるという事実に直接対応しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、プレフィックスとサフィックスが同一である場合です。 入力にそのような文字列のコピーが複数含まれている場合は、インデックスをそれ自体とペアにすることなく、順序付きペアをカウントする必要があります。 式 freq × (freq − 1) はこれを正しく処理します。 

たとえば、ターゲット分割で A = B = "XX" が生成され、入力に "XX" が 3 回含まれる場合、有効な順序付きペアは (i, j) (i ≠ j) となり、3 × 2 = 6 となります。 

もう 1 つのエッジ ケースは、ターゲットの複数の分割が有効な文字列に対応する場合です。 各分割は独立しているため、貢献は蓄積されます。 周波数マップにより、有効な各ペアが分割ごとに 1 回だけカウントされることが保証され、分割間の重複がないため、意図した順序対称性を超えて二重カウントが発生しません。
