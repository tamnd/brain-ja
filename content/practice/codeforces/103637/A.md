 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列が与えられており、目標は、それをすべての位置 i に値 i が含まれる恒等順列に変換することです。 

2 つの操作が可能です。 1 回の操作で、任意の 2 つの要素を固定コスト a で交換できます。 もう 1 つの操作は、固定コスト b で順列を完全にランダム化し、すべての n! の一様にランダムな順列を生成します。 可能性。 

これらの操作は、シャッフルを複数回繰り返したり、スワップとシャッフルを混合したりするなど、任意の順序で適用できます。 課題は、決定的な最小コストを見つけることではなく、最適な戦略の下で恒等順列に到達するために予想される最小コストを見つけることです。 

制約は小さく、n は最大 20 です。これは、順列の状態空間 (n!) が概念的に関連していることをすぐに示唆しています。 なのに！ n = 20 の場合、 は天文学的に大きく、遷移の構造 (スワップまたはランダム リセット) は、状態を明示的に列挙することが期待されておらず、その代わりに状態の記述を順列構造の下で不変なものに圧縮することを示唆しています。 

順列がすでに同一である場合、微妙なエッジケースが現れます。 この場合、操作は必要ないため、予想コストはゼロになります。 もう 1 つのエッジ ケースは、スワップが予期したシャッフルよりもコストがかかる場合です。この場合、ローカルで何かを修正するのではなく、シャッフルを繰り返すことが最適である可能性があります。 たとえば、n = 2 で順列がすでに正しい場合、スワップには不必要なコストがかかりますが、シャッフルでは依然としてランダム性が生じますが、すぐに停止することが最適であるため無視できます。 

## アプローチ

 ブルートフォース手法では、各順列をサイズ n! のグラフの状態として扱います。 各状態から、b (シャッフル) を支払うことで他の状態に遷移したり、コスト a でインデックスのペアを交換することで特定の隣接状態に遷移したりできます。 ターゲットは恒等順列であり、それに到達するために予想される最小コストが必要です。 

これはすぐに、巨大な状態空間上の期待値動的計画法の問題になります。 順列ごとに方程式を書くことすら不可能です。 

重要な観察は、恒等構造は、正確な配置ではなく、すでに正しい位置にある要素の数にのみ依存するということです。 ただし、スワップでは順列のサイクルに応じて複数の要素を一度に修正でき、シャッフルではすべての構造が均一に破壊されます。 シャッフル操作は単純化を促進します。これにより、状態が再び均一になります。つまり、シャッフル後の予想される残りのコストは、以前の構成に関係なく同じになります。 

これは、州ごとの DP ではなく、戦略の観点を示唆しています。 どの状態からでも、2 つの選択肢があります。スワップのみを使用して順列を直接修正するか、b を支払って一様にランダムな順列にリセットし、最適に再試行するかのいずれかです。 戦略にコミットする場合、プロセスは決定論的な「現在の状態から解決する」コストと確率論的な再起動ループの間の決定になります。 

E をランダムな並べ替えからの期待コストとします。 すぐにシャッフルすることを選択した場合は、b を支払い、同じ期待値 E に戻ります。そのため、分岐は b + E に寄与します。シャッフルせずにスワップを使用して作業することを選択した場合、順列をソートするために最小数のスワップが必要です (たとえば、k、それぞれのコストが a であるため、コストは k・a です)。 

したがって、初期状態から 2 つの戦略を比較します。スワップを使用して直接終了するか、b を支払ってプロセス全体を再度開始するかです。 最適な期待値は次の固定小数点方程式を満たします。 

E = min(k・a, b + E)

 この形式は、k・a ≤ b + E の場合、直接終了することを好むことを意味します。 そうしないと、シャッフルの繰り返しが優勢となり、方程式は幾何学的再スタートプロセスに崩壊します。

2 番目のケースを並べ替えると、E = b + E が得られますが、その分岐を選択しない限り、これは不可能です。 正しい解釈は、シャッフルに依存することを選択した場合、スワップによる終了が別のシャッフルよりも安くなる順列に達するまで事実上再起動することになり、試行の幾何学的分布につながります。 

これを解決する正しい方法は、必要な最小スワップである k を計算し、決定論的な完了コスト k・a を、成功するまで繰り返しシャッフルする予想コストと比較することです。 シャッフルごとに新しい順列が得られるため、確率 1 では、最終的に終了を決定する状態に到達しますが、予想されるシャッフル数は 1/p です。ここで、p は、ランダムな順列が「終了するのに十分安い」確率です。 

重要な単純化は、唯一の意味のある違いは、そもそもシャッフルを選択するかどうかであるということです。 決してシャッフルしない場合、答えは k·a です。 シャッフルすることを選択した場合、最適なポリシーは、アイデンティティの順列自体が得られるまでシャッフルすることです。これは、アイデンティティがゼロコストのままである唯一の状態であるためです。 非同一状態は対称性の下では同一の構造を持っているため、待機しても部分的な利点は得られません。 

したがって、最適な戦略は以下の比較に集約されます。 

直接コスト = k・a

 同一性コスト = 同一性倍になるまでの予想されるシャッフル数 b = n! までシャッフルします。 ・b

 したがって、答えは簡単です。 

min(k・a, n!・b)

 順列を恒等式に変換するためのスワップの最小数である k を計算する必要があります。これは、n から順列のサイクル数を引いたものであることがよく知られています。

 ## アルゴリズムのチュートリアル

 1. 最初に戻るまで、未訪問の各インデックスからのポインタをたどることにより、順列を素のサイクルに分解します。 順列は全単射であるため、各要素は正確に 1 つのサイクルに属します。 
2. 存在するサイクルの数を数えます。 要素を 1 つずつ回転させて所定の位置に配置できるため、長さ L の各サイクルを修正するには L − 1 回のスワップが必要です。 
3. k = n −cycle_count を計算します。これは、同一性を達成するために必要なスワップの最小合計数です。 
4. 決定論的コストを k · a として計算します。これは、スワップのみを使用してすべてを直接修正することを表します。 
5. シャッフルのみの期待コストを (n 階乗) · b として計算します。これは、アイデンティティが 1/n の確率で出現するため、アイデンティティが 1 回ヒットするまで繰り返されるランダム シャッフルを表します。 シャッフルごとに。 
6. これら 2 つの値の最小値を出力します。 

推論ステップは、スワップ操作は決定論的かつ最適に無秩序を軽減するのに対し、シャッフルは部分的な進歩をもたらさない完全なリセットとして機能するため、戦略はこの比較を超えて有益な方法でインターリーブしないということです。 

### なぜ効果があるのか

 スワップの順列構造はサイクル分解によって完全に捕捉され、スワップはサイクル間で相互作用することなくサイクル内で独立して動作します。 これにより、k = n − サイクルが決定論的解決のための正確な最小コストになります。 一方、シャッフルはすべての構造を消去し、毎回均一な状態を生成するため、シャッフルを含む戦略は、恒等状態のみを吸収するベルヌーイ過程の繰り返しに帰着します。 シャッフル後に生き残る中間構造はないため、部分的な正しさを条件付けする利点はなく、プロセスは同一性が得られるまでの単純な期待された再起動に崩壊します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, a, b = map(int, input().split())
    p = list(map(int, input().split()))
    p = [x - 1 for x in p]

    visited = [False] * n
    cycles = 0

    for i in range(n):
        if not visited[i]:
            cycles += 1
            cur = i
            while not visited[cur]:
                visited[cur] = True
                cur = p[cur]

    swaps = n - cycles

    direct = swaps * a

    # compute n! carefully
    fact = 1
    for i in range(2, n + 1):
        fact *= i

    shuffle = fact * b

    print(min(direct, shuffle))

if __name__ == "__main__":
    solve()
```循環計数セクションは、標準の順列走査パターンに従います。 未訪問のインデックスを見つけるたびに、ループを閉じるまで p に沿って歩き、すべての訪問済みノードをマークします。 これにより、各サイクルが正確に 1 回カウントされるようになります。 

n が小さいため、階乗計算は反復的に実行され、値はオーバーフローの問題なく Python 整数に収まります。 

最後の比較は、問題を 2 つの独立した最適な戦略 (直接修正とランダム リセットの繰り返し) に分割することを反映しています。

 ## 特殊なケース

 n = 4、p = [1, 2, 3, 4] など、すでに恒等である置換の場合、サイクル数は 4 でスワップは 0 であるため、直接コストは 0 になります。 このアルゴリズムでは、結果が改善されない限りシャッフルは考慮されず、シャッフルでは正の期待コストが導入されるため、アルゴリズムは正しくゼロを出力します。 

n = 5、p = [2、3、4、5、1] のような単一の大きなサイクルの場合、サイクル数は 1 なので、スワップ = 4 になります。直接コストは 4a です。 走査では、サイクルを閉じる前にすべてのノードを 1 回だけ訪問し、過剰なカウントが発生しないようにします。 シャッフル コストは構造から独立したままであり、依然として n!·b であるため、比較はサイクルの形状に関係なく有効なままです。 

b が非常に大きい場合、n!·b が優勢であるため、アルゴリズムは決してシャッフルを優先しません。 順列の構造は無関係になり、解決策は純粋にサイクル分解になり、アルゴリズムは分岐や確率論的推論を行わずにこれを処理します。
