 ## 解決策
 ## 問題の理解

 原点が爆発点を表す平面で作業しています。 人々のセットは整数座標に配置され、最大で描画することができます。$m$無限の直線。 各人は、原点からその人までのすべてのセグメントが選択された線の少なくとも 1 つと交差する必要があるという意味で「保護」されなければなりません。 幾何学的に、これは、原点からセット内の任意の点に向かうすべての光線が、少なくとも 1 本のラインによってカットされなければならないことを意味します。 

各ラインには、原点にどれだけ近づくかによって測定されるコストもあります。 すべての線は無限であるため、関連する距離の概念は、原点から線までの垂直距離です。 ポイントへのすべての光線をブロックしながら、選択したすべてのライン間の最小距離を最大化したいと考えています。 

制約は大きく、最大で$10^5$ポイントと$10^5$線。 点と線の各ペアについて独立して推論する解決策は、直ちに遅すぎます。 問題の構造は、答えがグローバル ジオメトリ、具体的には個々の座標ではなく原点の周りの角度範囲に依存することを示唆しています。 

点が原点と一致する場合、微妙なエッジケースが現れます。 この状況では、すべての線が通過するため、有限距離は役に立ちません。 このような点が 1 つでもあれば、答えはゼロになります。$m$。 

すべての点が非常に狭い角度セクター内にある場合、別の特殊なケースが発生します。 その場合、慎重に配置された 1 本の線でも十分である可能性があり、$m$制限要因はライン数ではなく幾何学的分離であるため、達成可能な距離は増加しません。 

3 番目の重要なケースは、点の角度が均等に分布している場合です。 ここでボトルネックとなるのが、サークルを分割することです。$m+1$角度ギャップがあり、解は避けられない最大の角度ギャップによって決まります。 

## アプローチ

 重要な問題は、各線が平面を 2 つの半平面に分割し、すべての点が少なくとも 1 本のそのような線によって原点から「ブロック」されている領域に存在する必要があることです。 これは、原点からのすべての方向について、無限大に到達する前にその方向と交差する少なくとも 1 本の線が存在する必要があると言うのと同じです。 

ブルートフォースアプローチでは、すべてのオブジェクトの位置と方向を推測しようとします。$m$ラインを作成し、すべての光線がカバーされていることを確認します。 角度を離散化するだけでも、膨大な数の構成をチェックすることになります。 考えてみると$k$候補アングルを選択してみてください$m$状態空間は組み合わせ的に拡大し、実現可能性のチェックにはすでにコストがかかります$O(nm)$、これは大きすぎます$10^5$。 

重要な洞察は、平面内の線についての考え方から、単位円上の角度についての考え方に切り替えることです。 各点は原点からの方向に対応します。 原点を通る線は、連続する角度間隔を方向的に「ブロック」します。 線を原点から遠ざける場合、方向をブロックするその有効性はその距離によって決まり、この距離を最大化することは、これらの角度制約をどの程度厳密に詰め込む必要があるかを最小化することに対応します。 

これにより、問題は円上の幾何学的パッキング問題に変換されます。つまり、最大でも次の値を使用してすべての点方向をカバーしたいと考えます。$m$最も近い線の距離は、カバーされないままにしなければならない最悪の角度ギャップによって決まります。 

重要な点は、ソートされた角度順序で連続する点間の最大の空の角度セクターによって最適値が決定されることです。 そのギャップがわかれば、それを切断するのに必要なラインの数を決定し、そこから、弦の距離と原点までの垂直距離の間の単純な幾何学的関係を使用して、可能な最大距離を導き出すことができます。 

答えを二分探索します$R$、原点からの任意のラインの最小許容距離として解釈されます。 固定の場合$R$、各線は、接線構成によって決定される特定の角度範囲内に方向がある点のみをカバーできます。つまり、距離のある線です。$R$に比例した幅の方向の円錐をブロックできます。$2\arcsin(R / r)$どこ$r$は半径方向の距離スケールです。 これにより、実現可能性は、最大で円角配列を貪欲にカバーできるかどうかを確認することに変わります。$m$円弧。 

単調性が重要です。$R$小さいものでも機能します$R$原点に近いラインは光線との交差においてより強力であるため、これも機能します。 これにより二分探索が可能になります。

 ## アルゴリズムのチュートリアル

 1. 各点を極座標に変換し、その角度を計算します。 原点にある点は正の距離を無効にするため、ゼロを返すことによって直ちに処理されます。 
2. すべての角度を並べ替え、各角度にプラスを加えて配列を拡張します。$2\pi$。 この線形化により、循環ラップアラウンドをライン上の間隔カバーとして扱うことができます。 
3. 二分探索で答えを求める$R$ゼロと十分に大きな上限の間で、通常は最大座標の大きさに基づきます。 このステップの目的は、固定バリア距離の実現可能性をテストすることです。 
4. 候補者にとって$R$、ある距離にある単一の線が成す最大角度スパンを計算します。$R$効果的に分離できます。 これは、距離にある線という幾何学的条件から来ています。$R$原点からの光線は、その方向が計算可能な角度ウィンドウ内に収まる光線と交差します。 
5. ソートされた角度に対して貪欲なスイープを実行します。 最初のカバーされていない方向から開始し、次の角度間隔で許容される最大の角度間隔をカバーするラインを配置します。$R$。 すべてのポイントがカバーされるまで続けます。 
6. 使用されている行数を数えます。 超えた場合$m$、候補者$R$実行不可能です。 それ以外の場合は実現可能です。 
7. それに応じて二分探索を絞り込み、実行可能な最大値を出力します。$R$。 

重要な不変条件は、貪欲なスイープ中に、各ステップで角度空間内で可能な限りカバレッジを拡大するラインを常に選択することです。 これは最適です。なぜなら、後で開始するラインは以前のカバーされていない角度をカバーできず、より狭い角度範囲をカバーするラインは厳密に必要なラインの数を増加させるからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def can(R, angles, m):
    n = len(angles) // 2
    best = 0
    cnt = 0
    i = 0

    while i < n:
        cnt += 1
        if cnt > m:
            return False

        start = angles[i]
        j = i

        while j < i + n:
            diff = angles[j] - start
            if diff > 2 * math.acos(min(1.0, R)):
                break
            j += 1

        i = j

    return True

def solve():
    n, m = map(int, input().split())
    pts = []
    for _ in range(n):
        x, y = map(int, input().split())
        if x == 0 and y == 0:
            print(0.0)
            return
        pts.append(math.atan2(y, x))

    pts.sort()
    angles = pts + [a + 2 * math.pi for a in pts]

    lo, hi = 0.0, 1.0

    for _ in range(60):
        mid = (lo + hi) / 2
        if can(mid, angles, m):
            lo = mid
        else:
            hi = mid

    print(lo)

if __name__ == "__main__":
    solve()
```解決策は、次を使用して座標を角度表現に変換することから始まります。`atan2`、象限を含む完全な方向情報が保存されます。 配列をソートして 2 倍にすることにより、循環ラップアラウンドがきれいに処理されるため、有効なカバー間隔は線形配列内の連続したセグメントになります。 

実現可能性チェックは次のように実装されます。`can`。 貪欲にラインを配置します。各ラインは、現在の半径制約によって許可される最大可能な角度間隔をカバーします。 を含む表現`acos`原点からの距離と角度ブロック能力の間の幾何学的関係をエンコードします。 

二分探索により、実現可能な最大半径が絞り込まれます。 約 60 回の繰り返しのループ数は、倍精度の安定性を得るのに十分です。

 ## 特殊なケース

 点が正確に原点にある場合、すべての線は自明に交差し、正解は強制的にゼロになります。 アルゴリズムは角度計算の前にこれをチェックし、無効な幾何学的推論を防ぎます。 

すべての点が非常に狭い角円錐内にある場合、貪欲なスイープでは、$m$。 二分探索は大きな値に収束します。$R$ただし、追加のパーティショニングは必要ないため、実現可能性は変わりません。 

点が円の周りに均一に分布している場合、制限要因は線の数ではなく角度間隔になります。 アルゴリズムは円を実行可能な等しい円弧に繰り返し分割し、貪欲な配置は常に最大の覆われていないギャップに位置合わせされ、最適な構造と一致します。
