 ## 解決策
 ## 問題の理解

 石の山のコレクションが与えられ、各山には負ではない整数の石が含まれています。 2 人のプレイヤーが順番に、山からちょうど 1 つの石を取り除きます。 時津風が先攻。 プレイヤーは、ターンの開始時にすべての山が空の場合、または自分の動きによって 2 つの山が同じ数の石を持つ状況を引き起こした場合 (石がゼロであっても) に負けます。 最適なプレイの下で、どのプレイヤーが勝つかを判断する必要があります。 時津風が勝った場合は「sjfnb」、CSLが勝った場合は「cslnb」が出力されます。 

この制約により、最大 100,000 個の山と石の数が 10^9 まで許可されます。 考えられる一連の動きの数は指数関数的であるため、これにより、すべての動きの単純なシミュレーションが除外されます。 それぞれの動きをシミュレートするのではなく、初期構成を検査し、組み合わせ推論を使用するアプローチが必要です。 

明らかではないエッジケースは、石の数が等しい杭、または石がゼロの杭がある場合に発生します。 たとえば、入力が次の場合`1 0`, 時津風が動けないのでCSLが即勝ち。 2 つの杭の開始時のカウントが同じである場合、時津風は重複の作成を避けなければなりません。また、複数の重複した杭や別の杭に一致するように杭を減らすなど、一部の初期構成は問題ルールの下では無効になります。 これらの無効な開始状態をチェックしない不注意なソリューションでは、誤った出力が生成されます。 

## アプローチ

 ブルートフォースアプローチでは、可能なすべての動きをターンごとにシミュレートします。 各ステップで、空ではないパイルをデクリメントし、移動によって重複したカウントが作成されるかどうかを確認します。 これは小さい n に対して正しい結果を生成しますが、分岐係数は 1 つの手につき最大 n まで可能であり、一連の動きは石の合計まで可能です。 最悪の場合、10^5 の山にそれぞれ 10^9 個の石がある場合、操作数は 10^14 を超え、1 秒の制限時間をはるかに超えます。 

重要な洞察は、これが、等しいカウントを持つ 2 つの山を持つという特別な負け条件を備えた Nim のようなゲームの変形であるということです。 重複が発生するとゲームが即座に終了することを観察すると、問題は、厳密に増加するシーケンスに到達するために必要な総手数のパリティをチェックすることに帰着できます。`[0, 1, 2, ..., n-1]`、このシーケンスは安全で最小限であるためです。 この「最小限の」順序を超える石の数が奇数の場合、時津風は追加の手を持って勝ちます。 互角の場合はCSLが勝ちます。 さらに、無効な開始構成を検出する必要があります。つまり、複数の重複があるか、減少すると負の値または別の重複が生成されるパイルがあります。 

これにより、問題は山を並べ替え、重複を数え、ターゲット シーケンスとの差を合計することに減ります。 このアプローチは n において線形演算的であり、制約内に快適に適合します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(sum(a_i) * n) | O(n) | 遅すぎる |
 | 最適なカウンティングとパリティ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. パイル サイズの配列を降順でない順に並べ替えます。 並べ替えにより、重複を検出し、構成が「最小限の安全なシーケンス」からどれだけ離れているかを測定できるようになります。 
2. 各パイルサイズの頻度をカウントします。 パイルが 2 回以上発生した場合、構成は無効となり、CSL が勝ちます。 
3. 1 つの山が 2 回発生しているかどうかを確認します。 「はい」の場合は、重複がゼロではないこと、および重複を 1 つ減らしても別の重複が作成されないことを確認してください。 それ以外の場合、開始時の設定は無効です。 
4. 厳密に増加するシーケンスに到達するために必要な石の合計数を計算します。`[0, 1, 2, ..., n-1]`。 これは差分を合計することで行われます`a_i - i`各山ごとに i.
 5. これらの差の合計が奇数の場合、最後の有効な手を行うため、時津風が勝ちます。 互角の場合はCSLが勝ちます。 
6. ルールに従って、対応する勝者を出力します。 

機能する理由: ソートされたシーケンスにより、重複を検出し、最小限の安全なシーケンスからの逸脱を測定できます。 ゲームを最小シーケンスを超える「追加の」石の数に変換し、パリティをチェックすることで、どのプレイヤーが最後の有効な手を打つかを効果的に計算しています。 無効な構成は、不正な位置を避けるために早期に除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import Counter

def main():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    count = Counter(a)
    
    # Check for invalid starting conditions
    dup_count = sum(1 for v in count.values() if v > 1)
    if dup_count > 1:
        print("cslnb")
        return
    
    if dup_count == 1:
        # find the duplicated value
        for val, freq in count.items():
            if freq == 2:
                dup_val = val
                break
        # invalid if duplicated value is zero or decrement creates another duplicate
        if dup_val == 0 or count.get(dup_val - 1, 0) > 0:
            print("cslnb")
            return
    
    # Compute the total number of moves above minimal safe sequence
    moves = sum(a[i] - i for i in range(n))
    
    # Determine winner based on parity
    if moves % 2 == 1:
        print("sjfnb")
    else:
        print("cslnb")

if __name__ == "__main__":
    main()
```コードは重複を正しく処理するために山を並べ替えます。 の`Counter`重複を迅速に検出し、無効な条件をチェックするために使用されます。 合計する`a[i] - i`最小の厳密に増加するシーケンスに対して余分な石を測定し、パリティが勝者を決定します。
