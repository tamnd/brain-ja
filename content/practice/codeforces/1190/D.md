 ## 解決策
 ## 問題の理解

 平面内の一連の点が与えられ、特別な種類の領域を選択することができます。つまり、2 つの x 座標の間、たとえば l と r の間の垂直ストリップですが、側面が開いており、厳密にその高さより上の点のみを取得するように水平しきい値 a と組み合わせられます。 この領域は上向きに境界がないため、選択した x 間隔内および選択したカットオフより上のすべての点をキャプチャする垂直スラブのように動作します。 

このような領域ごとに、その中にあるすべての点を取得し、結果として得られる点のセットを記録します。 領域の異なる選択によって同じセットが生成される可能性があり、この方法で取得できる空でない異なる点セットの数を数えるよう求められます。 

制約は最大 200,000 ポイントに達し、左右の境界のすべてのペアを試行したり、サブセットを明示的に列挙したりするソリューションは即座に除外されます。 n の二次関数はすでに大きすぎるため、解決策はソートと線形または線形に近いスキャン、場合によっては分割統治または掃引線のアイデアに依存する必要があります。 

微妙な点は、x 条件が両側で厳密であることです。 正確に境界にある点は決して含まれないため、領域は x オーダーで連続したセグメントを選択するように動作します。 もう 1 つの重要な側面は、高さのしきい値が、選択された x 間隔内で、y でソートされた点の接尾辞を効果的に選択していることを意味することです。 x 順序付けと y しきい値の間のこの相互作用が、有効なセットの構造を制御します。 

よくある失敗例は、x と y について独立して考えることから生じます。 たとえば、すべての点が同じ x 座標を共有する場合、すべての有効な領域は y しきい値によってのみ決定されるため、個別のセットの数は 2^n ではなく、正確に n になります。 単純なサブセット解釈では、ここで完全に過大評価されてしまいます。 

もう 1 つの落とし穴は、「y 内で単調」なすべてのサブセットが達成可能であると仮定していることです。 これは、サブセットが y によるフィルター処理後に x オーダーの連続セグメントにも対応しない限り当てはまりません (これが実際の制約です)。 

## アプローチ

 ブルートフォースアプローチでは、l と r の可能なすべての選択が試行されます。 ソートされた x 順のインデックス i と j の各ペアについて、それらの間の点のセットを考慮し、a をマイナス無限大から上に向かって変化させます。 a が増加すると、y の昇順に点が削除され、間隔ごとに一連のサブセットが生成されます。 この考えは正しいですが、O(n^2) 個の間隔があり、線形時間であっても各間隔を処理すると最悪の場合 O(n^3) になるため、遅すぎます。 

重要な観察は、x 順序でセグメントを選択し、その後、ある y しきい値を超えるすべての点を選択することによって、すべての有効なセットを記述することができるということです。 すべてのセグメントを明示的に列挙する代わりに、視点を逆転させます。 点を x で並べ替え、x で左右にどれだけ拡張するかを制御しながら、y でのカットオフとして機能する「最高点」を選択することでセットを構築することを考えます。 

重要な再構成は、選択したセット内で最小の y を持つ点を固定することです。 その点が閾値 a を決定します。 その点が固定されると、セット内の他のすべての点は y がそれより大きくなければならず、包含の不一致を強制するより高い y を持つセットの外側の点を含めることなく、その周囲の連続する x 間隔内に存在する必要があります。 

これは、x オーダーに関する古典的な分割統治構造につながります。つまり、最小の y アンカーとして点を選択し、含まれるすべての点がしきい値を超える有効な候補であることを保証する制約を維持しながら、左右に展開します。 各アンカーについて、有効な左拡張と右拡張の数は、2 ポインターまたは単調スタック スタイルのマージを使用して効率的に組み合わせることができ、O(n log n) の動作が得られます。

本質的な削減は、領域を列挙する代わりに、考えられる「選択されたセット内の最も低い点」を列挙し、その点より上のすべての点で形成できる有効な連続 x 間隔の数をカウントすることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | x 間隔としきい値に対するブルート フォース | O(n^3) | O(n) | 遅すぎる |
 | y アンカーを使用して x で分割統治する | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべての点を x 座標で並べ替えます。 これにより、すべての有効な領域がこの順序で連続するセグメントの選択に対応することが保証されます。 

次に、各点を有効なセット内の潜在的な最低 y 点として扱います。 選択したセット内でポイントが最も低い場合、選択した他のすべてのポイントの y 値が厳密に大きくなければならないため、これらのポイントはこのピボットより上で独立して考慮できます。 

このようなピボットごとに、このピボットが最小の y である有効なセットがいくつ存在するかを計算します。 

以下のように進めていきます。 

1. 点を x 座標で並べ替え、0 から n-1 までのインデックスを付けます。 これにより、問題は境界線を越えた作業に変わります。 

2. 各点 i について、それを最終的に選択されたセット内の最小の y を持つ候補として扱います。 これにより、しきい値 a が y[i] のすぐ下に固定されます。 セットには、y が y[i] より大きい点のみが含まれている必要があります。 

3. インデックス i から、y[i] より大きい y を持つ点のみを考慮しながら、左右に展開します。 選択したセットは x 内で連続していなければならないため、常に i を含む区間 [L, R] を拡大します。 

4. 拡張中、y[i] より大きい y を持つ除外点が区間内に存在しないという制約に違反せずに区間を拡張する有効な方法がいくつ存在するかを維持します。 これは、単調スタックを使用して最も近いブロッキング ポイントを事前計算するか、y 次数をスイープしてアクティブなセグメントを維持することによって処理されます。 

5. 各ピボット i について、有効な左の選択肢と右の選択肢の数を掛けます。 この積は、最小 y 点として i を持つ間隔の数を表し、選択されたすべての点は自動的に y > y[i] を満たします。 

6. すべての i からの貢献を合計します。 すべてのセットには一意の最小 y 点があるため、結果では、空ではない有効なセットがそれぞれ 1 回だけカウントされます。 

正確さは、有効なセット内の最小 y 点が一意であり、しきい値 a を決定するという事実に依存します。 この点が固定されると、残りの自由はすべて純粋に水平になり、禁止点を含まずに x 次の連続した区間を形成する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    pts.sort()  # sort by x

    # We compute contribution using a monotonic stack idea on y.
    # prev greater / next greater structure over y in x-order.

    x = [p[0] for p in pts]
    y = [p[1] for p in pts]

    # nearest greater element boundaries in x-order based on y
    left = [-1] * n
    right = [n] * n

    stack = []
    for i in range(n):
        while stack and y[stack[-1]] < y[i]:
            stack.pop()
        left[i] = stack[-1] if stack else -1
        stack.append(i)

    stack.clear()
    for i in range(n - 1, -1, -1):
        while stack and y[stack[-1]] < y[i]:
            stack.pop()
        right[i] = stack[-1] if stack else n
        stack.append(i)

    # Each point contributes as minimum-y anchor:
    # number of choices = (i - left[i]) * (right[i] - i)

    ans = 0
    for i in range(n):
        ans += (i - left[i]) * (right[i] - i)

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、すべての有効な選択が区間問題になるように、点を x でソートすることに依存しています。 y 上の単調スタックは、点ごとに、y 以上の点に遭遇する前に左右にどこまで拡張できるかを計算します。これにより、区間内に一意の最小値があるという条件が破られます。 

左右の範囲を乗算すると、各点が y の一意の最小値となる間隔の数がカウントされます。これは、有効な四角形の選択に正確に対応します。 

実装の微妙な詳細は、すべての点が異なるため、比較は y 順序に厳密に基づいて行われ、同点が発生しないようにする必要があることです。 厳密なより大きな処理を使用すると、各間隔が 1 つのピボットに正確に割り当てられるようになります。

 ## 特殊なケース

 重要なエッジ ケースは、すべての点が同じ x 座標を共有する場合です。 その状況では、「間隔」は崩壊し、垂直方向のしきい値のみが重要になります。 すべての点が x オーダーで分離され、各点が最小の y に対応する 1 つの新しい有効なセットに寄与するため、アルゴリズムは引き続き正しいカウントを生成します。 

もう 1 つのエッジ ケースは、x オーダーで厳密に単調な y 値です。 ここでは、すべての点が最大スパンを持つ潜在的なピボットとなり、構造は間隔の完全な組み合わせの成長を生成します。 単調スタックは、各新しい点が、より低い y を持つ以前のすべての点を超えて拡張できるようにすることで、これを正しく捕捉します。 

最後のエッジケースは、y 値がランダムであるが、x がソートされている場合です。 この場合、スタック境界は変動し、各ポイントの寄与は近くの最大値に大きく依存します。 このアルゴリズムは、最も近い大きい要素によって間隔を正しく分割し、各有効なセットが固有の最小 y アンカーを介して正確に 1 回カウントされるようにします。
