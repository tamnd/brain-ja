 ## 解決策
 ## 問題の理解

 私たちには、プログラミング コンテストの参加者によって作成された提出物のリストが渡されます。 各提出は 2 つの数字で表されます: _x_ は、この参加者がこのソリューションより前にすでに提出した一意のソリューションの数を数えます。 _k_ は参加者の ID です。 同じ参加者の提出物は時系列順に表示される必要があります。提出物に _x = 2_ が表示されている場合は、同じ参加者による以前の提出物で _x = 1_ がリストのどこか前にあったはずです。 タスクは、復元されたリストがすべての参加者についてこの時系列順を尊重していることを確認することです。 

この制約は、送信は最大 100,000 件まで可能であり、各参加者 ID とソリューション番号も最大 100,000 件まで可能であることを示しています。 これは、新しい送信ごとに以前のすべての送信をスキャンする二次アルゴリズムでは遅すぎることを意味します。 提出数に応じて線形またはほぼ線形にスケールするソリューションが必要です。 エッジ ケースには、インターリーブされた送信を持つ複数の参加者、_x_ 値にギャップがある参加者、単一の送信を持つ最小のケースが含まれます。 たとえば、次のようなリストです。```
3
0 1
2 1
1 1
```_x = 1_ が後で表示される場合でも、2 番目の送信では参加者 1 の前に _x = 1_ が存在せずに _x = 2_ が主張されるため、「NO」を出力する必要があります。 

## アプローチ

 素朴なアプローチは、参加者ごとに以前のすべての送信のリストを維持し、新しい送信ごとに逆方向にスキャンして、より小さい _x_ 値がすべて表示されていることを確認することです。 これは正しいですが、最悪のケースでは、各提出物で以前のほぼすべての提出物をスキャンする必要があり、時間の複雑さが O(n²) になる可能性があります。 n が 10^5 までの場合、このアプローチは現実的ではありません。 

重要な観察は、各参加者について、これまでに出現した最大の _x_ のみを知る必要があるということです。 参加者 _k_ の新しい送信の _x_ が、_k_ の現在の最大値に 1 を加えたものより大きい場合、リストは無効になります。 _x_ が現在の最大値、または現在の最大値に 1 を加えた値に等しい場合、一貫性があります。 したがって、各参加者の現在の最大 _x_ を辞書に保存できます。 これにより、各送信のチェックが O(1) に減り、全体として O(n) のソリューションが得られます。 考え方としては、時系列順では、参加者ごとに最後に提出されたインデックスを追跡するだけで済みます。 提出物の完全なリストが必要になることはありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の辞書を初期化して、参加者 ID をこれまでに確認された最大の _x_ にマッピングします。 これにより、各参加者の最新の時系列の提出がキャプチャされます。 
2. リスト内の各送信を繰り返します。 提出ごとに、参加者 ID _k_ とソリューション番号 _x_ を読み取ります。 
3. 参加者の現在の最大値を辞書で確認します。 参加者に以前の送信がない場合は、最大値を -1 として扱います。 
4. 新しい _x_ が現在の最大値に 1 を加えた値より大きい場合は、ただちに「NO」を出力して停止します。 これは、スキップされた提出番号があり、時系列の順序が崩れていることを意味します。 
5. それ以外の場合は、参加者の最大値 _x_ を現在の値と _x_ の最大値に更新します。 これにより、シーケンスを壊すことなく、同じ _x_ による繰り返しの送信が処理されます。 
6. 違反を検出せずにループが終了した場合は、「YES」を出力します。 

維持される不変条件は、すべての参加者について、シーケンス内のその時点までに検出された最大の _x_ が辞書に常に格納されるということです。 提出物がルール _x ≤ current_max + 1_ に違反する場合、時系列順序は必ず崩れます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
latest = {}

valid = True
for _ in range(n):
    x, k = map(int, input().split())
    current_max = latest.get(k, -1)
    if x > current_max + 1:
        valid = False
        break
    latest[k] = max(current_max, x)

print("YES" if valid else "NO")
```辞書`latest`参加者ごとの最大の提出インデックスを追跡します。 使用する`get(k, -1)`まだ解決策を提出していない参加者を処理できるようになります。 の`max`同じ _x_ を繰り返し送信しても、保存されている最大値が減らないようにします。 違反を早期に終了することで、不必要な作業を回避できます。

## 複雑さの分析

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    latest = {}
    valid = True
    for _ in range(n):
        x, k = map(int, input().split())
        current_max = latest.get(k, -1)
        if x > current_max + 1:
            valid = False
            break
        latest[k] = max(current_max, x)
    return "YES" if valid else "NO"

# Provided sample
assert run("2\n0 1\n1 1\n") == "YES", "sample 1"

# Edge: single submission
assert run("1\n0 1\n") == "YES", "single submission"

# Skipped submission
assert run("3\n0 1\n2 1\n1 1\n") == "NO", "skipped submission"

# Multiple participants
assert run("4\n0 1\n0 2\n1 1\n1 2\n") == "YES", "multiple participants"

# Interleaved violation
assert run("4\n0 1\n1 2\n2 1\n1 2\n") == "NO", "interleaved violation"

# Large x repeated
assert run("3\n0 1\n0 1\n1 1\n") == "YES", "repeated same x allowed"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1\n0 1`| はい | 最小入力の場合 |
 |`3\n0 1\n2 1\n1 1`| いいえ | 提出番号がスキップされました |
 |`4\n0 1\n0 2\n1 1\n1 2`| はい | 複数の参加者が独立したシーケンスを維持します。 
|`4\n0 1\n1 2\n2 1\n1 2`| いいえ | インターリーブされた送信は順序を壊す可能性があります。 
|`3\n0 1\n0 1\n1 1`| はい | 同じ x を使用した重複した送信は許可されます |

 ## 特殊なケース

 提出スキップの場合`3\n0 1\n2 1\n1 1\n`、アルゴリズムセット`latest[1]`最初の送信後は 0 になります。 x=2 での 2 回目の送信では、チェックが行われます。`2 > 0+1`失敗すると、最後の行を見ずにすぐに「NO」を返します。 これは、順序が乱れたシーケンスを正しく処理する方法を示しています。 繰り返される x 値の場合、次のようになります。`0 1`2回、`latest[1]`は 0 のままで、現在の最大値と一致する x=1 で次の送信を許可し、繰り返しの解が受け入れられることを確認します。
