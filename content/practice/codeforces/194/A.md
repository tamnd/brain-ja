 ## 解決策
 ## 問題の理解

 著者は取らなければならない`n`exams. すべての試験には、2 から 5 までの整数の評定が与えられます。 グレード 2 は試験が不合格であり、再受験する必要があることを意味します。 すべての等級の合計は正確に等しくなければなりません`k`。 

合計が次のような評定の可能なすべての割り当ての中で、`k`、失敗した試験の数を可能な限り少なくしたいと考えています。 再受験の原因となるのはグレード 2 のみであるため、タスクは次のようになります。合計を同じに保ちながら、グレード 3、4、または 5 の試験の数を最大化する。`k`。 

制約はわずかです。`n`せいぜい50歳であり、`k`は最大 250 であるため、強引なアプローチでも簡単に適合します。 それでも、この問題には、解決策全体を 1 つの公式に帰着させる直接的な数学的観察があります。 

最初の微妙なエッジ ケースは、ターゲット合計が既に可能な最小合計である場合に発生します。 例えば：```
Input:
4 8
```各試験は少なくとも 2 つ必要なので、達成可能な最小合計は次のようになります。`4 * 2 = 8`。 これにより、すべての試験が 2 になるため、答えは 4 になります。このベースラインを正しく処理せずに貪欲に成績を上げようとする不注意な解決策では、誤って失敗が可能な限り少なくなる可能性があります。 

もう 1 つの簡単な間違いは、合計が非常に大きい場合に発生します。 考慮する：```
Input:
3 15
```可能な最大グレードは 5 であり、`3 * 5 = 15`なので、すべての試験は 5 になる可能性があります。答えは 0 です。一部の誤った実装では、最小点を超える追加点ごとに不合格の試験が 1 つ削除されると考えられていますが、1 つの試験で最大 3 点の追加点が吸収されるため、これは誤りです。 

さらに興味深いケースは次のとおりです。```
Input:
4 10
```最小合計は 8 です。追加で 2 ポイントが必要です。 1 つの試験は 2 から 4 にアップグレードでき、成績が得られます。`[4,2,2,2]`。 答えは、不合格になった試験が 2 つではなく、依然として 3 つです。これにより、不正確に分割したり、余分な点がすべて不合格になった別の試験を修正すると仮定したりする解が見つかります。 

## アプローチ

 ブルートフォースアプローチでは、可能なすべてのグレードの割り当てが試行されます。 すべての試験は 4 つの値のうちの 1 つを取ることができるため、次のようになります。`4^n`組み合わせ。 と`n = 50`、これは天文学的に大きくなり、完全に実行不可能になります。 

動的プログラミングも可能です。 定義できます`dp[i][s]`処理後の不合格試験の最小数として`i`合計スコアのある試験`s`。 以来`n <= 50`そして`k <= 250`、これは快適に高速に実行されます。 状態カウントはおおよそ次のとおりです`50 * 250`、各遷移は 4 つのグレードを考慮します。 

問題の構造により、はるかに単純なものが可能になります。 

すべての試験はグレード 2 から始まります。これにより、ベースラインの合計は次のようになります。`2n`。 より高いグレードにはさらにポイントが追加されます。 

| グレード | 2以上の追加ポイント |
 | --- | --- |
 | 2 | 0 |
 | 3 | 1 |
 | 4 | 2 |
 | 5 | 3 |

 最終的な合計が必要だとします。`k`。 配布する必要がある追加ポイントの数は次のとおりです。$$k - 2n$$最高評価は 5 であるため、不合格でない各試験は最大 3 ポイントの追加ポイントを与えることができます。したがって、不合格の試験を最小限に抑えたい場合は、合格した各試験にできるだけ多くの追加ポイントを詰め込む必要があります。 

1 つの合格した試験が最大 3 点の追加ポイントに貢献できる場合、必要な合格した試験の最小数は次のとおりです。$$\left\lceil \frac{k - 2n}{3} \right\rceil$$試験の合計数は、`n`したがって、失敗した試験の最小数は次のようになります。$$n - \left\lceil \frac{k - 2n}{3} \right\rceil$$これにより、問題は検索問題から直接の数学的計算に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(4^n) | O(n) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`k`。 
2. 可能な最小合計スコアを計算します。`2 * n`。 これは、すべての試験に 2 級を与えることに相当します。 
3. 追加で必要なポイントの数を計算します。$$extra = k - 2n$$1. 各試験に合格すると、2 を 5 に変更することで最大 3 点の追加ポイントを吸収できます。 
2. 必要な合格試験の最小数を計算します。$$pass\_exams = \left\lceil \frac{extra}{3} \right\rceil$$整数演算では、これは次のようになります。```
(extra + 2) // 3
```1. 残りの試験はグレード 2 のままである必要があるため、答えは次のようになります。```
n - pass_exams
```### なぜ効果があるのか

 すべての試験は最初に 2 ポイントを与えます。 必要な合計に達するために、配布します`extra`試験全体での追加ポイント。 成績は 5 点に制限されているため、1 回の試験で追加できるポイントは最大 3 点です。 

試験の失敗を最小限に抑えるために、追加ポイントをすべて獲得できる試験の数をできるだけ少なくしたいと考えています。 3 つの追加ポイントを 1 つの試験に詰め込むことは、複数の試験に分割するのと少なくとも同じくらい効果的です。2 を超えてアップグレードされた各試験は不合格試験ではなくなるからです。 

天井部門は、必要な追加点をすべて提供できる最小の試験数を計算します。 残りの試験はグレード 2 に留まり、不合格としてカウントされます。 各合格試験には 3 点の追加ポイントがあるため、合格試験の数を減らすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

extra = k - 2 * n
passing = (extra + 2) // 3

print(n - passing)
```実装は数学的導出に直接続きます。 

表現`k - 2 * n`すべての試験に最低グレード 2 を割り当てた後、まだ必要なポイント数を計算します。 この問題によって有効な構成が存在することが保証されるため、この値が式で処理できる範囲を超えて負になることはありません。 

天井の分割部分だけが微妙な部分です。 数学では:$$\left\lceil \frac{x}{3} \right\rceil$$は次のようになります:```
(x + 2) // 3
```負でない整数の場合。 整数の除算の前に 2 を加算すると、正しく切り上げられます。 

最後に、合格した試験の数を引くと、`n`2 年生に残っている試験の数を示します。 

ループや大規模なデータ構造は必要ありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, k = map(int, input().split())

    extra = k - 2 * n
    passing = (extra + 2) // 3

    print(n - passing)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("4 8\n") == "4\n", "sample 1"

# custom cases
assert run("1 2\n") == "1\n", "minimum possible sum"
assert run("1 5\n") == "0\n", "maximum possible score"
assert run("4 10\n") == "3\n", "single upgraded exam"
assert run("3 15\n") == "0\n", "all exams score 5"
assert run("5 11\n") == "4\n", "one extra point only"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 2`|`1`| 有効な最小構成 |
 |`1 5`|`0`| 最大グレードによりすべての失敗が除去されます。 
|`4 10`|`3`| 追加のポイントは 1 つの試験に集中できます |
 |`3 15`|`0`| 達成可能な最大合計 |
 |`5 11`|`4`| 余りのある天井分割 |

 ## 特殊なケース

 合計が最小の場合を考えてみましょう。```
Input:
4 8
```アルゴリズムは以下を計算します。```
extra = 8 - 2*4 = 0
passing = (0 + 2) // 3 = 0
answer = 4 - 0 = 4
```追加のポイントは必要ないため、すべての試験はグレード 2 のままです。出力は正しく 4 です。 

次に、合計が最大の場合を考えてみましょう。```
Input:
3 15
```アルゴリズムは以下を計算します。```
extra = 15 - 2*3 = 9
passing = (9 + 2) // 3 = 3
answer = 3 - 3 = 0
```すべての試験、特にグレード 5 は合格試験になる必要があります。出力は正しく 0 です。 

最後に、天井分割のケースを調べます。```
Input:
5 11
```最小合計は 10 であるため、追加のポイントは 1 つだけ必要です。```
extra = 1
passing = (1 + 2) // 3 = 1
answer = 5 - 1 = 4
```1 つの試験はグレード 3 になり、残りの 4 つはグレード 2 のままになる可能性があります。フロア分割の実装では、ここで合格試験がゼロであると誤って計算されてしまいます。
