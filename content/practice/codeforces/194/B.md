 ## 解決策
 ## 問題の理解

 一辺の長さが次の正方形の境界線の周りを歩いている人がいます。`n`。 彼は左下隅からスタートし、すぐにそこにクロスを上げた。 その後、彼は周囲に沿って時計回りに移動し続け、毎回クロスを配置します。`n + 1`メートル。 

歩きは再びスタートコーナーに到達し、そこにクロスを置くまで続きます。 タスクは、開始コーナーでの両方のクロスを含め、合計で何本のクロスが描かれたかを数えることです。 

テスト ケースごとに、入力により 1 つの整数が得られます。`n`、プロセスが開始位置で繰り返される前に、ペイントされた十字の数を出力する必要があります。 

制約は大きいです。 辺の長さは次のように大きくできます。`10^9`、最大で`10^4`テストケース。 周囲を一歩ずつ歩くシミュレーションは、歩数が少ないことが証明されない限り危険です。 最悪の場合、答え自体が次の値に比例する可能性があります。`n`, そのため、シミュレーションには数十億回の反復が必要になる可能性がありますが、制限時間内では不可能です。 ソリューションはテスト ケースごとに一定時間で実行する必要があります。 

難しいのは、プロセスがいつ停止するかを正確に理解することです。 ジョンは、以前にマークしたポイントを初めて再訪しても立ち止まりません。 彼が止まるのは、左下隅に2本目のクロスが入ったときだけだ。 

よくある間違いは、最初のクロスが答えにカウントされることを忘れることです。 たとえば:

 入力:```
1
1
```正方形の外周は、`4`、ステップ サイズは`2`。 訪問したポジションは次のとおりです。`0 -> 2 -> 0`正しい答えは次のとおりです。```
3
```開始コーナーは最初と最後の両方でカウントされるためです。 

もう 1 つの簡単な間違いは、答えが周長に直接依存すると仮定することです。 次のことを考慮してください。 

入力:```
1
4
```外周は`16`、ステップ サイズは`5`。 答えはそうではありません`16 / 5`。 ウォークは位置をモジュロで訪問します`16`:`0 -> 5 -> 10 -> 15 -> 4 -> ... -> 0`サイクル長はモジュラー算術、具体的には周長とステップ サイズの間の gcd によって決定されます。 

## アプローチ

 最も直接的なアプローチは、歩行をシミュレートすることです。 現在の位置は、開始コーナーからの周囲に沿った距離として表すことができます。 当初のポジションは`0`。 あらゆる動きが追加されます`n + 1`、そしてモジュロを取ります`4n`正方形の外周には長さがあるので`4n`。 

ポジションが決まるまで続けます`0`また。 訪問したポジションの数はまさにクロスの数です。 

この強引なアイデアは正しいです。なぜなら、プロセスは文字通り、周囲を法として加算を繰り返すものとして定義されるからです。 問題はパフォーマンスです。 仮定する`n = 10^9`。 ステップ数は次のオーダーにすることもできます。`10^9`、これは 2 秒に収まる範囲をはるかに超えています。 

重要な観察は、これがモジュールサイクルの問題であるということです。 

私たちは繰り返し適用します:$$x \leftarrow (x + (n+1)) \bmod 4n$$から始まる`0`、シーケンスは に戻ります。`0`後：$$\frac{4n}{\gcd(4n, n+1)}$$ステップ。 

これはモジュラー加算の標準特性です。 繰り返し追加すると`k`モジュロ`m`、サイクルの長さは次のようになります。$$\frac{m}{\gcd(m, k)}$$ここ：$$m = 4n,\quad k = n+1$$次に、gcd を単純化します。$$\gcd(4n, n+1)$$以来：$$4n = 4(n+1) - 4$$得られるもの:$$\gcd(4n, n+1) = \gcd(4, n+1)$$したがって、答えは次のようになります。$$\frac{4n}{\gcd(4, n+1)}$$サイクルには初期位置と最初に繰り返される戻りの両方が含まれるため、これにより開始点への最終的な戻りがすでに正確にカウントされます。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`t`、テストケースの数。 
2. 各テスト ケースについて、次の内容を読んでください。`n`。 
3. 周囲の長さを計算します。$$m = 4n$$4. 歩行歩数を計算します。$$k = n + 1$$5. 以下を計算します。$$g = \gcd(m, k)$$これは、追加を繰り返したときにスキップされる個別の残差クラスの数を示します。`k`モジュロ`m`。 
6. 元の位置に戻るまでの移動回数`0`は：$$\frac{m}{g}$$7. 結果を印刷します。 

### なぜ効果があるのか

 各十字は、追加を繰り返して到達する位置に対応します。`(n + 1)`モジュロ`4n`。 

訪問した位置の順序は次のとおりです。$$0,\ k,\ 2k,\ 3k,\ \dots \pmod{4n}$$次の場合、ウォークは開始点に戻ります。$$tk \equiv 0 \pmod{4n}$$最小のポジ​​ティブ`t`この方程式を満たすのは次のとおりです。$$t = \frac{4n}{\gcd(4n, k)}$$その値は、開始コーナーが 2 番目のクロスを取得する前に描かれたクロスの数と正確です。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    t = int(input())
    nums = list(map(int, input().split()))

    ans = []

    for n in nums:
        perimeter = 4 * n
        step = n + 1

        ans.append(str(perimeter // gcd(perimeter, step)))

    print("\n".join(ans))

solve()
```実装は数学的導出に直接続きます。 

外周は`4 * n`, 正方形には 4 つの等しい辺があるためです。 移動サイズは常に`n + 1`。 

重要な行は次のとおりです。```
perimeter // gcd(perimeter, step)
```これにより、モジュラー加算が繰り返されるサイクル長が計算されます。 

Python 整数を使用すると、オーバーフローが自動的に回避されます。これは重要です。`4 * 10^9`32 ビット符号付き整数の範囲を超えています。 

もう 1 つの微妙な点は、クロスを正確に数えることです。 計算式にはスタート コーナーへの最終リターンがすでに含まれているため、手動で加算または減算する必要はありません。 多くの誤った実装では、ここで off-by-one エラーが発生します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from math import gcd

def solve():
    input = sys.stdin.readline

    t = int(input())
    nums = list(map(int, input().split()))

    ans = []

    for n in nums:
        perimeter = 4 * n
        step = n + 1
        ans.append(str(perimeter // gcd(perimeter, step)))

    print("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("3\n4 8 100\n") == "16\n32\n400\n", "sample"

# minimum size
assert run("1\n1\n") == "2\n", "minimum n"

# gcd = 4 case

# maximum size
assert run("1\n1000000000\n") == "4000000000\n", "large input"

# multiple equal values
assert run("4\n4 4 4 4\n") == "16\n16\n16\n16\n", "repeated inputs"

 ## 特殊なケース

 可能な最小の正方形を考えてみましょう。 

入力:```
1
1
```我々は持っています：$$m = 4,\quad k = 2$$そして：$$\gcd(4, 2) = 2$$したがって、答えは次のとおりです。$$\frac{4}{2} = 2$$訪問したポジションは次のとおりです。$$0 \to 2 \to 0$$不注意に実装すると、誤って印刷される可能性があります`3`サイクル長とは別に開始コーナーの両方の発生をカウントすることによって。 モジュラー サイクルの公式では、戻りステップがすでに考慮されています。 

次に、次のことを考えてみましょう。 

入力:```
1
7
```得られるものは次のとおりです。$$m = 28,\quad k = 8$$そして：$$\gcd(28, 8) = 4$$それで：$$\frac{28}{4} = 7$$これは周囲よりもはるかに小さいです。 ステップ サイズが周囲と約数を共有するため、ウォークでは多くの位置がスキップされます。 すべての境界位置が訪問されることを前提とした実装は、ここでは失敗します。 

最後に、非常に大きな値を考えてみましょう。 

入力:```
1
1000000000
```次のように計算します。$$m = 4000000000$$これは 32 ビットの符号付き整数の範囲を超えています。 固定サイズの整数を使用する言語では、64 ビット演算が必要です。 Python はこれを自動的に処理するため、実装は安全なままです。
