 ## 解決策
 ## 問題の理解

 サイズ N の完全なセットから始めます。各ステップは独立して 1 から N までの数値を均等に選択します。 選択した番号がまだセット内にある場合は、それを削除します。 それ以外の場合、セットは変更されないままになります。 セットが空になるとプロセスは停止します。 

終了までの予想ステップ数が必要です。 

入力には複数のテスト ケースが与えられ、それぞれが N であり、期待値のモジュロ 998244353 を出力する必要があります。 

重要な観察は、要素の同一性は決して重要ではないということです。 どの時点においても、意味のある状態は要素がどれだけ残っているかということだけです。 k 個の要素が残っている場合、システムは、それらがどの特定の要素であるかに関係なく、同じように動作します。 

100000 までの制約 N は、指数サブセット DP を除外します。 O(N^2) でも大きすぎます。 これは、一次元の反復または線形の期待値 DP を直ちに示唆します。 

素朴な考えとして、プロセスを何度もシミュレーションすることですが、各シミュレーションには際限なく時間がかかる可能性があり、制約内で収束しません。 

2 番目の単純なアイデアは、各要素を個別に扱い、予想される削除時間を合計することです。 これは、削除が独立していないため失敗します。すでに削除された要素を選択すると、処理が進まずに時間がかかります。 

N = 1 の場合、微妙なエッジ ケースが発生します。最初の選択では確率 1 の唯一の要素が削除されるため、期待される答えは 1 になります。ここでは、どの式も正しく削減する必要があります。 

もう 1 つのエッジ ケースは N = 2 です。プロセスはすでに削除された要素を繰り返し選択して「スタック」する可能性があるため、期待値は厳密に 2 よりも大きくなります。「各要素には N ステップのコストがかかる」などの誤った線形仮定はここでは失敗します。 

## アプローチ

 ブルートフォースの観点は、プロセスの状態を残りの要素のサブセットとしてモデル化することです。 サイズ k の任意のサブセット S から、各ステップは、確率 k/N で S 内のいくつかの x について S \ {x} に遷移するか、確率 (N-k)/N で S に留まります。 これにより、2^N 状態にわたるマルコフ連鎖が直ちに定義されます。 

これは正しいですが、状態空間が指数関数的であるため使用できません。 トランジションを書くことさえすでに不可能です。 

重要な単純化は、サイズ k のすべてのサブセットが同じように動作することです。 したがって、サブセットを追跡する代わりに、単一の値 dp[k]: k 個の要素がまだ生きている場合の予想残り時間を追跡します。 

状態 k から、ランダムな選択は確率 k/N で成功し、k を 1 減らします。確率 (N-k)/N では何も変化せず、同じ状態に留まり、余分な無駄なステップが発生します。 

この自己ループ構造が鍵であり、期待方程式は直接記述できます。 

E[k] が k 個の要素からの予想される残り時間である場合、次のようになります。 

E[k] = 1 + (k/N) * E[k-1] + (1 - k/N) * E[k]

 右側は、各ステップのコストが 1 であることを反映しており、状態を減らすか、そのままにします。 

再配置すると自己参照が削除され、単純な繰り返しが生成されます。 

これは構造的な洞察です。「無駄なピック」は状態を変更しませんが、k/N に応じた係数で時間を膨張させます。 

代数を計算すると、次のようになります。 

E[k] = E[k-1] + N/k

 したがって、このプロセスは、N でスケールされた高調波のような項を合計することになります。 

したがって:

 E[N] = N * (1/1 + 1/2 + ... + 1/N)

 モジュラー演算では、すべてがプリフィックス高調波数に分解されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース マルコフ DP | O(2^N) | O(2^N) | 遅すぎる |
 | 状態圧縮 DP over k | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. どの項目が残っているかではなく、残っている項目の数だけが重要であることを認識します。 これにより、状態空間がサブセットから 0 から N までの整数 k に縮小されます。 
2. E[k] を、k 個の項目が残っている場合に必要となる予想ステップ数として定義します。 目標はE[N]です。 
3. 1 つのステップのトランジションを記述します。 k 個の項目からランダムに選択すると、確率 k/N で成功し、k が k−1 に減ります。 それ以外の場合、確率 (N-k)/N では、状態は変化しませんが、時間が 1 ステップずつ増加します。 
4. これを期待方程式に変換します。 

E[k] = 1 + (k/N)E[k−1] + (1 − k/N)E[k]。 

項目の削除に失敗すると状態が変化しないため、左側には再び E[k] が含まれます。 
5. 方程式を並べ替えて E[k] を分離します。 自己項を移動すると次のようになります。 

(k/N)E[k] = 1 + (k/N)E[k−1]、これは E[k] = E[k−1] + N/k に簡略化されます。 
6. E[0] = 0 から E[N] までこの繰り返しを使用します。 各ステップでは、N に i の逆剰余を乗じた値が加算されます。 
7. 現在の高調波合計 H = sum(1/i mod MOD) を維持し、最終的な答えを N * H として累積します。 

### なぜ効果があるのか

 重要な不変条件は、E[k] が k のみに依存し、残りの要素の同一性には依存しないということです。 k からのすべての遷移は同じように動作し、唯一のランダム性は、選択したインデックスがまだアクティブであるかどうかです。 自己ループ確率は幾何学的待ち時間効果を生み出します。これはまさに加算的な N/k 項を生み出すものです。 各状態は k を超えると履歴とは無関係に減少するため、再発は情報を失うことなく期待を完全に特徴付けます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    t = int(input())
    inv = [0] * (100000 + 1)

    for i in range(1, 100000 + 1):
        inv[i] = modinv(i)

    for _ in range(t):
        n = int(input())
        H = 0
        for i in range(1, n + 1):
            H = (H + inv[i]) % MOD
        ans = H * n % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```同じ分母がテスト ケース全体で繰り返されるため、実装ではモジュラー逆関数が事前計算されます。 高調波の合計は直接累積され、最終的な N の乗算には、導出された式 E[N] = N * H_N が適用されます。 

よくある落とし穴は、調和構造を分離せずに期待値を繰り返し更新しようとすることです。 もう 1 つは、自己ループ項を代数的に削除する必要があることを忘れていることです。 そのままにしておくと、繰り返しが誤って円形に表示されてしまいます。 

## 実用的な例

 ### 例 1: N = 2

 逆数を計算します: 1/1 = 1、1/2 = 499122177 (mod 998244353)。 

H = 1 + 1/2。 

すると、E[2] = 2 * (1 + 1/2) = 3 となります。 

| k | H 接頭語 | E[k] |
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 1 + 1/2 | 3 |

 これは、N が小さい場合でも、無駄な描画が繰り返されることでプロセスが膨張するため、期待値が N を超えることを示しています。 

### 例 2: N = 3

 H = 1 + 1/2 + 1/3。 

E[3] = 3H。 

| k | H 接頭語 | E[k] |
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 1 + 1/2 | 3 |
 | 3 | 1 + 1/2 + 1/3 | 3時間 |

 これは、高調波の寄与が線形に蓄積されていることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(N) | 1..N にわたる高調波の合計 |
 | スペース | O(1) 余分 (事前に計算された逆数の場合は O(N)) | 必要なのは累計のみです |

 高調波の計算は実行時間の大半を占めますが、N ≤ 100000 であれば、一般的な制限内での実行可能性が保証されます。 

## テストケース```python
import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def solve():
        t = int(input())
        for _ in range(t):
            n = int(input())
            H = 0
            for i in range(1, n + 1):
                H = (H + pow(i, MOD - 2, MOD)) % MOD
            print(H * n % MOD)

    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdout = old_stdout
    return out.strip()

# sample-like checks
assert run("1\n1\n") == "1", "n=1"
assert run("1\n2\n") == str((2 * (1 + pow(2, MOD - 2, MOD))) % MOD), "n=2"
assert run("1\n3\n") == str((3 * (1 + pow(2, MOD - 2, MOD) + pow(3, MOD - 2, MOD))) % MOD), "n=3"

# edge case large structure sanity
assert run("1\n5\n").split()[0], "basic structure"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | n=1 | 1 | ベース終端 |
 | n=2 | 3 | セルフループインフレーション |
 | n=3 | 高調波の累積 | 再発の正確性 |
 | n=5 | 計算値 | 一般的な正しさ |

 ## 特殊なケース

 N = 1 の場合、状態はすでに最小限で開始され、最初の成功した選択は常に即座に行われます。 再帰により E[1] = N * (1) = 1 が得られ、プロセスと直接一致します。 

N = 2 の場合、システムはすでに削除された要素のステップを頻繁に無駄にします。 漸化式では、調和項 1/2 によってこれが正しく説明され、期待値が 3 に膨らみます。 

N が大きくなると、N/k が大きくなるため、k が小さい後期段階からの寄与が支配的になります。 調和構造は、シミュレーションなしでこの爆発を自然に捉えます。
