 ## 解決策
 ## 問題の理解

 正の整数が与えられます$m$。 考えてみましょう$m$「コイン」のセットを定義するものとして、各コインは次の約数です。$m$。 各約数を最大 1 回使用することが許可されており、これらのコインを使用して合計を形成しようとします。 

問題は、以下のすべての整数が$1$まで$m-1$の異なる約数の合計として形成できます。$m$。 これが可能であれば、$m$「良い」、そうでない場合は「悪い」。 

各テスト ケースについて、指定されたテスト ケースが、$m$良いです。 

制約により許可されるのは、$m$まで$10^{12}$まで$100$テストケース。 すべての約数を列挙してからサブセットの合計を試行する単純なアプローチでは、遅すぎます。 約数をリストすることさえ管理可能ですが、数値ごとに潜在的に数十の約数にわたるサブセットの合計は、最悪の場合、指数関数的になります。 

さらに微妙な問題は、構造を持たない貪欲なサブセット合計チェックでも十分ではないことです。 たとえば、$m = 10$、約数は$1,2,5,10$。 使用後$1$そして$2$までしか到達できません。$3$。 次の約数は$5$、これはすでにカバレッジを拡張するには大きすぎ、原則として約数の合計が十分に大きい場合でも、すべてがすぐに壊れます。 

これは、約数の合計だけではなく、約数の順序と「ギャップ構造」が重要であることを示しています。 

## アプローチ

 直接的な総当たりソリューションでは、すべての約数が列挙されます。$m$、すべてのサブセットを試して、すべての値が次の値に達するかどうかを確認します。$m-1$が代表的です。 これは約数の数が指数関数的になります。 周囲の数字$10^{12}$極端な場合には約数が数百程度になる可能性があり、これは完全に不可能になります。 

より良いアプローチは、この問題を古典的なコイン システムの到達可能性の問題として再解釈することから生まれます。 すべての約数を並べ替える$m$昇順に計算し、貪欲な方法で達成可能な合計をシミュレートします。 すでに区間内のすべての合計を計算できていると仮定します。$[1, R]$。 次に小さい約数$d$この範囲を拡張できるのは次の場合のみです$d \le R+1$、そうしないと、にギャップが生じるためです。$R+1$以前に使用したコインを組み合わせても満たすことはできません。 

この貪欲なプロセスはコイン システムでは正しく、制限までのすべての値が表現可能であることを完全に特徴づけます。 

難しいのは、この条件を次の除数セットに対してチェックしなければならないことです。$m$すべてのサブセットを明示的に列挙することなく。 ここで、既知の数理論の特徴付けが入ります。つまり、「実用的な」コイン システムを形成する約数をもつ数字は、まさにいわゆる実用的な数字です。 これらは整数であり、その約数によって以下の値までのすべての値を形成できます。$m$。 必要なのは最大だけであるため、要件はわずかに弱くなります。$m-1$ただし、システムが到達できる場合は同じ構造が当てはまります。$m$、必ず届く$m-1$、そしてすべての失敗はその時点より前にすでに現れています。 

したがって、タスクは次のことを確認することになります。$m$素因数分解によって実際の数値条件を満たします。 

古典的な特性評価は段階的に行われます。 建てたら$m$素因数分解から素数の順序を増加させながら、各ステップで、次の素数が前の因数からすでに達成可能な合計構造と比較して十分小さいかどうかを確認します。

 ## アルゴリズムのチュートリアル

 実際の数値については、標準的な構造定理に依存します。 素因数分解を素数の昇順に処理し、次の 2 つの量を維持します: 現在構築された値$v$と約数の合計$v$で示される$\sigma(v)$。 

1.因数分解$m$プライムパワーに$p_1^{a_1} p_2^{a_2} \dots p_k^{a_k}$、素数の増加順に並べ替えます。 
2.初期化$v = 1$そして$\sigma(v) = 1$。 
3. 最小の素数が存在しない場合$2$、すぐに失敗してしまいます。 これは、2 の因数がなければ、1 から連続して偶数と奇数の両方の小さな整数を形成することができないためです。 
4. 各素数パワーについて$p^a$順番に、現在の番号を拡張することを検討してください$v$。 乗算する前に、$$p \le \sigma(v) + 1.$$これが失敗すると、達成可能な合計額に次のコイン サイズより小さいギャップが生じるため、構築ではすべての値をカバーできなくなります。 
5. 条件が当てはまる場合は、以下を更新します。$$v \leftarrow v \cdot p^a,
\quad
\sigma(v) \leftarrow \sigma(v) \cdot \frac{p^{a+1} - 1}{p - 1}.$$6. すべての素数を処理すると、数値が有効になります。 

### なぜ効果があるのか

 どの時点でも、部分的に構築された数の約数は、達成可能な合計間隔が正確に一致するコイン システムのように動作します。$[1, \sigma(v)]$。 条件$p \le \sigma(v)+1$次の約数のバッチが到達可能な範囲にギャップを生じさせないことを保証します。 この不変条件がすべてのステップで成立すると、到達可能な間隔は穴なしで継続的に増加します。これは、次の値までのすべての整数が意味します。$m$は表現可能であるため、以下のすべての整数は$m-1$も代表的です。 

条件が失敗した場合、最初の到達不可能な整数は完全な範囲に到達する前に出現します。将来のすべての約数はさらに大きいため、その後の乗算ではそのギャップを修復できません。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def factorize(n):
    f = []
    i = 2
    while i * i <= n:
        if n % i == 0:
            cnt = 0
            while n % i == 0:
                n //= i
                cnt += 1
            f.append((i, cnt))
        i += 1
    if n > 1:
        f.append((n, 1))
    return f

def is_practical(n):
    if n == 1:
        return True

    fac = factorize(n)
    fac.sort()

    if fac[0][0] != 2:
        return False

    v = 1
    sigma = 1

    for p, a in fac:
        if p > sigma + 1:
            return False

        sigma *= (p**(a + 1) - 1) // (p - 1)
        v *= p ** a

    return True

def main():
    t = int(input())
    for _ in range(t):
        m = int(input())
        print("Yes" if is_practical(m) else "No")

if __name__ == "__main__":
    main()
```因数分解のステップは、次のような単純な試行除算です。$\sqrt{m}$。 以来$m \le 10^{12}$、これは最大 100 個のテスト ケースに対して効率的です。 

主要な実装の詳細は、決定がすでに構築されたプレフィックスのみに依存するため、シグマ値を更新する前に割り算条件がチェックされることです。 

シグマ更新では素数べき乗拡張に閉形式の除数和を使用し、約数の列挙を完全に回避します。 

## 実用的な例

 検討してください$m = 10$。 その因数分解は、$2 \cdot 5$。 

| ステップ | プライム | | 前の σ(v) 状態$p \le σ(v)+1$| アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 1 | 2 ≤ 2 | 受け入れる |
 | 2 | 5 | 3 | 5 ≤ 4 偽 | 拒否 |

 既存の構造では最大 3 までしか保証されていないため、プロセスは 2 番目の素数で失敗しますが、次のコインは 5 で、ギャップは 4 になります。 

ここで考えてみましょう$m = 12 = 2^2 \cdot 3$。 

| ステップ | プライム | | 前の σ(v) 状態 | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 1 | 2 ≤ 2 | 受け入れる |
 | 2 | 3 | 3 | 3 ≤ 4 | 受け入れる |

 ギャップは表示されないため、次の値までのすべての値が表示されます。$11$形成することができる。 

2 番目の例は、十分に小さい素数によって到達可能な間隔を継続的に拡張できる方法を示しています。

 ## 特殊なケース

 のために$m = 1$、除数セットには 1 のみが含まれており、表現できる 1 未満の正の整数はありません。 条件を空虚に満たすため、アルゴリズムはこのケースを直ちに受け入れます。 

次のような素数の場合$m = 13$、因数分解は 2 以外の単一の素数を生成します。2 から開始する必要があるため、アルゴリズムはすぐに拒否し、約数が次の事実と一致します。$\{1, 13\}$2 や 3 のような整数を形成することはできません。 

次のような数字の場合$m = 10$の場合、失敗は素数 5 によって導入された最初の大きなギャップで発生します。$\{1,2\}$は最大 3 までしかないため、全範囲に達する前に必要な連続性が途切れ、アルゴリズムはその時点で正しく停止します。
