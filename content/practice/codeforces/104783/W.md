 ## 解決策
 ## 問題の理解

 洞窟の部屋のグラフと、表面を表す特別なノードが与えられます。 各部屋は、他の部屋に接続したり、「掘削可能な」エッジを介して表面に直接接続したりできる可能性があります。 これらのエッジのサブセットを掘ると、表面からすべての部屋に到達できる接続された構造が得られます。 

ただし、エッジを恣意的に選択するわけではありません。 探索は厳密な発見命令に従って行われます。 部屋は、完全に利用可能なグラフの表面からの距離が短い順にアクセス可能になる必要があります。 同じ距離にある部屋の中で、部屋のインデックスによってすでにエンコードされている、より小さい危険レベルを優先します。 これにより、部屋に到達できるようになる決定的な順序が作成されます。 

探査が進むにつれて、すでに掘られた水路を機械を使って物理的に何度も横断することになりますが、既存の端を通過するたびにディーゼルが消費されます。 タスクは、最初からすべての部屋が検出されるまで、このプロセス全体でエッジが横断された合計回数を計算することです。 

入力は、ノード 0 を表面、ノード 1 ～ N-1 を洞窟とする無向グラフを記述します。 エッジとは、掘削可能なトンネルを意味します。 ノードの距離は、このグラフのノード 0 からの最短パス長として定義されます。 

この制約により、最大 200,000 のノードとエッジが許可されるため、最短パスを繰り返し再計算したり、プロセスのすべてのステップを単純にシミュレートしたりするアプローチは即座に除外されます。 線形計算または線形に近い複雑さよりも悪いものは生き残れません。 

複数のノードが同じ距離を共有する場合、微妙な問題が発生します。 このルールでは、最小の危険レベルによって関係を解消し、まだ関係がある場合にのみ、掘削にどの開始位置を使用するかを検討します。 この順序付けは、距離によって階層化され辞書編集的に順序付けされた BFS と同様の、非常に特殊な決定論的な走査プロセスを意味します。 

注目に値するエッジ ケースには、すべてのノードに 0 から直接到達する必要があるサーフェス経由を除く切断されたグラフや、複数の最短パスによって多数の同等のフロンティア選択肢が作成され、トラバース数に大きな影響を与えるグラフが含まれます。 

## アプローチ

 直接シミュレーションでは、最初に最短パス ツリーを構築し、次に検出プロセスを段階的にエミュレートします。 BFS を使用してノード 0 からすべての最短距離を計算し、到達可能だがまだ処理されていないノードの優先順位構造を維持し、距離と危険レベルに基づいて次のノードを繰り返し選択し、すでに構築されているエッジに沿ったトラバーサルをシミュレートできます。 

このアプローチは問題の説明を反映しているため、概念的には正しいです。 ただし、ボトルネックは、各ステップで、移動コストを計算するために以前に構築された構造をウォークスルーする必要があり、この繰り返しのトラバースにより、密なグラフで二次関数の動作が発生することです。 最悪の場合、N 個のノードのそれぞれが O(N) 個のエッジのスキャンまたは更新をトリガーし、O(N²) 個の動作が生成される可能性があります。 

重要な観察は、非常に特定の順序で最短パス ツリーを効果的に構築しており、すべての走査コストがこのツリー内ですでに確立されているエッジに沿って歩くことに対応しているということです。 動きを明示的にシミュレートする代わりに、エッジ使用数を蓄積しながらツリーを段階的に構築する優先順位を持つ BFS としてプロセスを再解釈できます。 

正しい観点は、各ノードが距離の短い順に 1 回だけ検出され、ノードが検出されると、そのノードに到達するために使用されるパスが最短パス ツリーの親エッジに対応するということです。 総トラバース コストは、ディスカバリ順序によって引き起こされる前後の移動の繰り返し中に各ツリー エッジが何回トラバースされるかという観点から表すことができます。 これにより、問題は最短パス ツリーの構築と、それに対する構造化された走査回数の計算に軽減されます。

マルチソース BFS をノード 0 から実行しますが、ノード インデックスによる決定的なタイブレークを使用します。 これにより、最短パス ツリーが得られます。 このツリーを取得したら、検出プロセスを暗黙的にシミュレートします。つまり、検出された 1 つのノードから次のノードに順番に移動するとき、コストはそれらの間のツリーの距離に等しくなります。 これらの距離を合計すると、総走査数が得られます。 

LCA または親ジャンプを計算して、発見順序で連続するノード間の距離を効率的に評価します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N² + M) | O(N + M) | 遅すぎる |
 | BFS + ツリー + LCA 距離累積 | O((N + M) log N) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 次に、グラフ構造をトラバーサル シミュレーションから分離する方法でソリューションを構築します。 

1. ノード 0 から BFS を実行して、すべてのノードまでの最短距離を計算します。 その際、複数のノードが同じ距離に到達できる場合は、ノード インデックスの昇順で処理します。 これにより、危険の制約と一致する決定論的な順序付けが保証されます。 
2. BFS 中に、BFS ツリー内の各ノードの親を記録します。 この親は、走査コストの計算に使用する一意の最短パス ツリーを定義します。 
3. 親ポインタを使用して、BFS ツリーの隣接表現を構築します。 
4. このツリーに対する最低共通祖先クエリのバイナリ リフティング テーブルを事前計算します。 これにより、任意の 2 つのノード間の距離を対数時間で計算できます。 
5. ノードの最終検出順序を構築します。これは、タイブレーク ルールに基づいて生成された BFS 訪問順序とまったく同じです。 
6. 総コストをゼロに初期化します。 
7. この順序で連続するノードのペアごとに、深さ[u] + 深さ[v] − 2 * 深さ[lca(u, v)] の式を使用してツリー距離を計算し、それを総コストに追加します。 
8. 最終的な累積コストを出力します。 

これが機能する理由は、BFS の順序が最短距離レイヤーを尊重し、各レイヤー内でノード インデックスの順序が尊重され、強制検出制約と一致するためです。 親ポインタは有効な最短パス ツリーを定義するため、連続する検出間のすべての移動はこのツリーに沿って最適にルーティングされます。 プロセス全体のトラバーサル コストは、連続する訪問ノード間の独立した最短パス距離に分解され、これらを合計すると、発見手順によって引き起こされたすべてのエッジ トラバーサルが二重カウントまたは省略なしで正確にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

from collections import deque

N_MAX = 200000
LOG = 20

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    
    for _ in range(m):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    for i in range(n):
        g[i].sort()

    dist = [-1] * n
    parent = [-1] * n
    order = []

    q = deque([0])
    dist[0] = 0

    while q:
        u = q.popleft()
        order.append(u)
        for v in g[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                parent[v] = u
                q.append(v)

    tree = [[] for _ in range(n)]
    for v in range(1, n):
        if parent[v] != -1:
            tree[parent[v]].append(v)

    up = [[-1] * n for _ in range(LOG)]
    depth = [0] * n

    def dfs(u):
        for v in tree[u]:
            depth[v] = depth[u] + 1
            up[0][v] = u
            dfs(v)

    dfs(0)

    for i in range(1, LOG):
        for v in range(n):
            if up[i - 1][v] != -1:
                up[i][v] = up[i - 1][up[i - 1][v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        diff = depth[a] - depth[b]
        i = 0
        while diff:
            if diff & 1:
                a = up[i][a]
            diff >>= 1
            i += 1

        if a == b:
            return a

        for i in reversed(range(LOG)):
            if up[i][a] != up[i][b]:
                a = up[i][a]
                b = up[i][b]

        return up[0][a]

    def dist_tree(a, b):
        c = lca(a, b)
        return depth[a] + depth[b] - 2 * depth[c]

    ans = 0
    for i in range(1, len(order)):
        ans += dist_tree(order[i - 1], order[i])

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初にグラフを構築し、サーフェス ノードから BFS を実行して、検出順序と親関係を決定します。 隣接リストをソートすると、複数の選択肢が存在する場合に決定的な走査が保証されます。 

親ポインター上の DFS は、ルート付きツリー構造を構築し、深さを割り当てます。 バイナリリフティングテーブル`up`効率的な LCA クエリをサポートするために構築されます。 LCA は、BFS 順序で連続するノード間のツリー内の最短パス距離を計算するために使用されます。 

最後のループでは、BFS 検出シーケンス内の連続するノード間の距離が累積されます。 ここでは、シミュレーション コストが明示的にウォーキング エッジではなく暗黙的にキャプチャされます。 

よくある落とし穴は、ツリーを構築して実際のパス距離を計算せずに、BFS 次数だけで十分であると想定していることです。 もう 1 つの微妙な問題は、走査コストが以前に確立された接続に依存するため、距離が元のグラフではなく BFS ツリー内にあることを忘れていることです。

 ## 特殊なケース

 サーフェスのみが存在する単一ノード システムでは、アルゴリズムが不必要な走査を回避するかどうかをテストします。 BFS が生成するのは、`[0]`したがって、ペアごとの距離の累積は発生せず、出力はゼロのままになります。 

すべてのノードがサーフェスに直接接続されている純粋なスター グラフでは、各ステップで正確に 1 単位の走査が追加されます。 BFS 次数は決定的であり、すべての LCA 距離は正確に 1 であり、予想される線形累積と一致します。 

完全に周期的なグラフは、BFS の親選択の正確さをテストします。 複数の最短パスが存在する場合でも、親割り当てにより一貫したツリーが修正され、LCA ベースの距離計算により、走査コストが任意の BFS キュー順序に依存しないことが保証されます。
