 ## 解決策
 ## 問題の理解

 各頂点にコストがあり、各辺にもコストがある無向グラフが与えられます。 「トリップ」とは、ある頂点から開始し、少なくとも 1 つのエッジを横断し、頂点を再訪問したり、エッジを再利用したりすることはできないウォークのことです。 言い換えれば、トリップは少なくとも 1 つのエッジの長さの単純なパスを形成する必要があります。 

トリップのコストは、訪問したすべての頂点の頂点コストの合計と、通過したすべてのエッジのエッジ コストの合計を加算したものです。 タスクは、少なくとも 1 つのエッジを含むすべての単純なパスの中から可能な最小コストを見つけることです。 

したがって、実際に選択している構造は、少なくとも 2 頂点の長さの単純なパスであり、パス上の頂点の重みとそれに沿ったエッジの重みの合計を最小化したいと考えています。 

制約が意味するのは、$N$まで可能です$10^5$そして$M$くらいまで$2 \cdot 10^5$。 これにより、頂点またはエッジ上の二次関数は直ちに除外され、パス上のサブセット列挙も除外されます。 どのような解も基本的にグラフ サイズが線形またはほぼ線形である必要があります。$O((N+M)\log N)$またはそれ以上です。 

微妙なエッジ ケースは、グラフにエッジがない場合です。 少なくとも 1 つのエッジを通過する必要があるため、有効なトリップは存在しません。 その場合、答えはありませんが、このような典型的な CF スタイルの問題では、意味のあるテストで少なくとも 1 つのエッジが保証されるか、このケースがクエリされないことが期待されます。 

もう 1 つの重要なエッジ状況は、単一のエッジを持つグラフです。 その場合、唯一の有効なトリップはそのエッジとその端点であり、答えは強制されます。 「パスの最適化」を試みる単純なアプローチでは、無効な頂点のみのソリューションを誤って考慮する可能性があります。 

3 番目の微妙なケースは、頂点の重みがエッジの重みと比較して極端に大きい場合です。 これにより、重い頂点を回避できる場合、最適なパスではより長いエッジ シーケンスが優先される可能性があるため、ソリューションでは短いパスや頂点のみでの貪欲なローカル選択を想定することができません。 

## アプローチ

 強引な解釈では、グラフ内のすべての単純なパスを列挙し、そのコストを計算し、最小値を取得します。 すべての有効な旅行はまさに 1 つの単純なパスであり、それらすべてを評価するため、これは概念的には正しいです。 

問題は、一般的なグラフ内の単純なパスの数が指数関数的に増加することです。 疎なグラフであっても、$O(2^N)$完全なグラフや密な二部構造などの最悪の場合は、明確な単純なパス。 各パス コストを明示的に計算するには、パス長に少なくとも線形時間が必要となり、実行時間が天文学的に長くなります。 

これを超えて、コスト関数がどのような構造になっているかを見てみましょう。 各パス コストは、頂点の重みとエッジの重みの合計です。 パス コストは次のように再解釈できます。 

開始頂点コスト + エッジの合計 (エッジの重み + 次の頂点に入るコスト。ただし、二重カウントは慎重に避けます)。 

重要な洞察は、コストがエッジに沿って加算されるため、頂点コストが遷移に吸収される拡張状態で問題を最短経路問題に変換できるということです。 

標準的なトリックは、各頂点を開始/終了状態に分割するか、頂点への訪問が 1 回だけ考慮されるようにエッジの重みを変更することによって、頂点の重みをエッジに「プッシュ」することです。 

きれいな方法の 1 つは、開始頂点を除く各頂点を、入力時にコストが支払われるものとしてモデル化することです。 その後、それぞれの移動から$u$に$v$エッジを通して$w$貢献する$w + v$。 最初の頂点は、その頂点コストのみに寄与します。 

したがって、遷移に重みがあるグラフ内の少なくとも 1 つのエッジの長さの最短パスが必要です。$w(u,v) + v_v$、プラス初期費用$v_u$。 

これにより問題は最短経路の問題に帰着しますが、少なくとも 1 つのエッジが使用されていることを確認する必要があります。 これは、最短パスを計算することによって処理できますが、エッジをまだ使用したかどうかを個別に追跡します。 

最も効率的なアプローチは、少なくとも 1 つのエッジをすでに通過したかどうかをエンコードする状態に対してダイクストラを実行することです。 任意の頂点での開始から、頂点の重みを使用してコストを初期化しますが、エッジをまだ使用していないことをマークします。 エッジをトラバースすると、ある状態から少なくとも 1 つのエッジが使用される状態に移行します。 

少なくとも 1 つのエッジが使用されているすべての状態を最小化します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての単純なパスを列挙する | 指数 | O(N) | 遅すぎる |
 | ダイクストラと状態 (頂点、used_edge_flag) | O((N+M) log N) | O(N+M) | 承認済み |

 ## アルゴリズムのチュートリアル

 状態をペアとして定義します$(v, t)$どこ$v$は現在の頂点であり、$t$少なくとも 1 つのエッジをすでに通過したかどうかを示します。 私たちはこれらの州に対してダイクストラを統治します。 

1. すべての状態の距離配列を無限大として初期化します。 頂点ごとに 2 つの状態を作成します。$t=0$まだエッジが使用されておらず、エッジが使用されていることを意味します$t=1$少なくとも 1 つのエッジが使用されていることを意味します。 
2. 優先キューを初期化し、すべての頂点をプッシュします$v$状態で$(v, 0)$コストが等しい場合$v_v$、頂点の重み。 これは、任意の頂点で旅行を開始し、そのコストを即座に支払うことを反映しています。 
3. 優先キューが空でない間に、コストが最小の状態を抽出します。 このコストが古い場合はスキップしてください。 
4. 状態について$(u, 0)$、それぞれの隣人を考慮します$v$。 エッジに沿って移動$(u,v)$新しい状態を生み出す$(v, 1)$コストが増加して$w(u,v) + v_v$。 トランジションは、少なくとも 1 つのエッジを使用したことを示し、エッジ コストと宛先の頂点コストの両方を支払います。 
5. 状態について$(u, 1)$、再びそれぞれの隣人を考慮します$v$に移行中$(v, 1)$同じコスト増分で$w(u,v) + v_v$。 「エッジが使用されている」状態のままです。 
6. 継続的な移行は決して許可しません。$t=0$, どの動きもすでにエッジを使用しているためです。 
7. すべての状態を処理した後、答えはすべての状態間の最小距離になります。$(v, 1)$すべての頂点に対して$v$。 

考慮しない理由$(v,0)$有効な答えは、これらはエッジがゼロのパスに対応しており、無効であるということです。 

### なぜ効果があるのか

 有効なトリップは、少なくとも 1 つのエッジを持つ単純なパスです。 状態にわたるダイクストラをシミュレートすると、そのようなパスはすべて、状態の最初の頂点から始まる 1 つの遷移シーケンスに正確に対応します。$t=0$そしてに切り替える$t=1$最初のエッジの後。 エッジの使用は単調であり、正の重みを使用して最短パスの意味で頂点が再検討されることはないため、ダイクストラはコストの増加順に候補パスを探索します。 状態の分離により、ゼロエッジ解を誤って受け入れることがなくなり、有効なパスがすべて 1 回だけ表現されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, m = map(int, input().split())
    v = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(m):
        a, b, w = map(int, input().split())
        g[a].append((b, w))
        g[b].append((a, w))
    
    INF = 10**30
    dist0 = [INF] * n
    dist1 = [INF] * n
    
    pq = []
    
    for i in range(n):
        dist0[i] = v[i]
        heapq.heappush(pq, (v[i], i, 0))
    
    while pq:
        d, u, t = heapq.heappop(pq)
        if t == 0 and d != dist0[u]:
            continue
        if t == 1 and d != dist1[u]:
            continue
        
        if t == 0:
            for to, w in g[u]:
                nd = d + w + v[to]
                if nd < dist1[to]:
                    dist1[to] = nd
                    heapq.heappush(pq, (nd, to, 1))
        else:
            for to, w in g[u]:
                nd = d + w + v[to]
                if nd < dist1[to]:
                    dist1[to] = nd
                    heapq.heappush(pq, (nd, to, 1))
    
    ans = min(dist1)
    print(ans if ans < INF else -1)

if __name__ == "__main__":
    solve()
```このコードは隣接リストを構築し、2 層のダイクストラを実行します。 の`dist0`配列はエッジがまだ使用されていない開始状態を表し、`dist1`少なくとも 1 つのエッジの後の状態を表します。 すべての頂点が開始点としてシードされます。 

重要な実装の詳細は、遷移が常に次の場所に到達することです。`dist1`。 これは、少なくとも 1 つのエッジを使用する必要があるという要件をエンコードします。 私たちは心の中で決してリラックスすることはありません`dist0`これにより、無効なゼロエッジ解が伝播するのを防ぎます。 

もう 1 つの微妙な点は、初期シードです。最適なパスはどこからでも開始できるため、すべての頂点を開始点としてプッシュします。 これにより、問題は効果的に、拡張された状態にわたる複数のソースの最短経路に変わります。

 ## 特殊なケース

 単一のエッジを持つグラフにより、アルゴリズムが誤ってゼロエッジのパスを受け入れることがなくなります。 入力中`2 1 / 1 100 / 0 1 1`の場合、アルゴリズムは両方のノードに頂点コストをシードし、すぐにエッジを使用する状態に移行し、唯一の有効なトリップであるコスト 102 を生成します。 

線形チェーンは、複数の遷移にわたる累積をテストします。 で`0-1-2-3`、状態は常に次のようになります。`dist1`、最終的な答えは、プレフィックスとサフィックスの最小の組み合わせに対応します。 このアルゴリズムは、各遷移で宛先の頂点コストを明示的に 1 回だけ追加するため、二重にカウントすることなく、各ステップで頂点コストとエッジ コストの両方を正しく累積します。 

均一な重みのグラフでは、どの頂点にも偏りがないことが保証され、アルゴリズムが純粋にエッジ構造に従って動作することが確認されます。 すべての頂点のコストは同じであるため、有効な最短パスは、エッジの重みとエンドポイントの固定頂点寄与の最小合計を見つけることになります。これは、ダイクストラ層化によって自然に取得されます。
