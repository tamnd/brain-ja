 ## 解決策
 ## 問題の理解

 各桁が階乗を通じて独立して寄与する非負の整数で定義された関数が与えられますが、この関数には 10 進数の点で再帰的に定義されるというひねりが加えられています。 1 桁の数値の場合、値は単にその桁の階乗になります。 複数桁の数値の場合、関数は数値を最後の桁と残りの接頭辞に分割し、最後の桁の階乗を接頭辞の関数値に加算します。 

したがって、数値を一連の数字として書くと、関数の値はその数字の階乗の合計になります。 

課題は逆転評価です。 指定された数値の関数を計算する代わりに、ターゲット値 y が与えられ、x の桁の階乗の合計が y に等しくなるような最小の非負の整数 x を見つけなければなりません。 

重要な制約は、y が最大 10^9 であることです。 これは、任意の大きな構造を構築しているわけではないことを直ちに意味します。数字の階乗は小さな定数です。 実際、0 から 9 までの数字だけが 0 からの固定値に寄与します。 9まで！、そして9まで！ は 362880 に等しいため、y の有効な表現では最大約 10 桁の寄与度スケール 9 を使用する必要があります。 より小さい桁が使用される場合は、より少ない桁数になります。 

x には上限がないため、x 自体が非常に大きいのではないかと想像すると、素朴な懸念が生じます。 ただし、各桁が寄与するのは最大 362,880 であるため、10^9 の合計でも最大約 3000 桁の寄与からしか得られず、実際には答えの長さに限界があることがすでに示唆されています。 

微妙なエッジ ケースは、数字の概念的な構成では先頭のゼロが許可されますが、x の数値には無関係であるということです。 たとえば、0012 のような数字のシーケンスは 12 と同じ整数を表しますが、階乗の合計を推論する場合、数字のシーケンスは重要です。 最小整数の要件により、より短い、または辞書編集的に小さい数字表現を優先する必要があります。 

もう 1 つのエッジ ケースは y = 0 です。0 から! = 1、数字をまったく使用しない場合を除き、どの数字もゼロになります。 y = 0 に対して有効な x は 0 のみです。 

## アプローチ

 ブルートフォース手法では、最初の一致に到達するまで x = 0、1、2、... を繰り返し、毎回 f(x) を計算します。 f(x) の計算は桁数が線形であるため、これは O(x log x) となります。 一致が見つかる前に x 自体が巨大になる可能性があるため、これは実行不可能です。 たとえ答えが約 10^9 だったとしても、これではまだ遅すぎます。 

関数の構造により、問題は数字の構成問題に変わります。 各桁は階乗に等しい独立した重みを与えるため、実質的に y を桁の重みの合計として表現しようとしています。各重みは 0 ～ 9 の桁に対応します。 

これにより、問題は、コインが桁階乗である有限コイン交換問題に変わりますが、結果として得られる数値が可能な限り最小の整数になることも必要です。 この 2 番目の条件では、貪欲な順序付けの原則が強制されます。つまり、x の数値を最小化するには、より多くの有効桁をできるだけ小さくする必要があります。つまり、まず長さを短くし、固定長の範囲内で辞書編集上の最小桁を必要とします。 

重要な観察は、利用可能な桁階乗を使用して残りの合計を確実に完成させながら、これを最上位桁から最下位桁まで選択するものとして扱うことができるということです。 これは、実現可能性チェックを伴う数字 DP または建設的な貪欲になります。 

0 から 9 までの数字の階乗を事前に計算します。次に、階乗の合計が y になる数字の複数セットを決定し、最後にそれらを可能な限り最小の整数に配置します。これは、整数が 0 でない限り最初の数字を 0 にすることはできないという制限付きで、数字を非降順に並べ替えることによって実現されます。

 ## アルゴリズムのチュートリアル

 1. 0 ～ 9 の桁の階乗値を事前計算します。これにより、各桁の選択に固定コストが与えられ、関数が加重和問題に変換されます。 
2. 階乗値の増加順にソートされた候補数字のリストを作成します。これは、最小階乗表現を構築するには一般に階乗が小さいほど有用であるためです。 
3. 最上位桁の位置から始めて、昇順に候補をテストして、どの桁を配置するかを決定します。 各候補数字 d について、残りのターゲットからその階乗値を減算し、残りの値が利用可能な数字を使用して形成できるかどうかを確認します。 
4. 実行可能性チェックは、階乗の最大桁を最初に使用して貪欲に実行されます。 これにより、残りの合計に対する解が存在する場合、それがすぐに検出されることが保証されます。 
5. 残りの合計がゼロになるまで数字を埋め続けます。 この時点で、階乗の合計が y になる桁の複数セットを構築しました。 
6. 結果の数字を昇順に並べ替えて、可能な限り小さい整数を取得します。 この手順により、位置表記では小さい数字が前に表示される必要があるため、最小の数値が保証されます。 
7. 結果の数字リストが空の場合は、0 を返します。 

### なぜ効果があるのか

 この関数は独立した数字の寄与に正確に分解するため、有効な解はすべて、重みの合計が y になる数字の複数セットに対応します。 構築プロセスでは、実現可能性が残りの達成可能な合計に対して常にチェックされるため、実現可能なプレフィックスが決して破棄されないことが保証されます。 桁階乗は固定定数であり、貪欲な構築では常に少なくとも 1 つの有効な完了パスが保存されるため、結果として得られる桁マルチセットは有効です。 後でソートすると、そのマルチセットの最小の数値解釈が生成されます。これは、カウントが固定された後に残る自由度は桁の順序だけであるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

FACT = [1] * 10
for i in range(1, 10):
    FACT[i] = FACT[i - 1] * i

def solve():
    y = int(input().strip())

    if y == 0:
        print(0)
        return

    # We want to use largest digits first to reduce digit count
    digits = []

    # Greedy: take largest factorial digits first
    for d in range(9, -1, -1):
        while y >= FACT[d]:
            y -= FACT[d]
            digits.append(d)

    if y != 0:
        # should not happen for valid inputs, but safe guard
        print(0)
        return

    # To get smallest numeric value, sort digits
    digits.sort()

    # avoid leading zero only if number is non-zero
    if digits and digits[0] == 0:
        # move first non-zero to front if possible
        for i in range(len(digits)):
            if digits[i] != 0:
                digits[0], digits[i] = digits[i], digits[0]
                break

    print("".join(map(str, digits)))

if __name__ == "__main__":
    solve()
```この解決策は、桁コストが O(1) になるように階乗を事前計算することから始まります。 9 から 0 までの貪欲ループは、桁階乗の合計として y の表現を構築し、大きい桁を優先して合計桁数を減らします。 構築後、ソートにより、結果として得られる整数の辞書編集値が最小限になることが保証されます。 

微妙な点は、最初に合計制約を満たすこと、次に数値を最小化するという 2 つの目標の間の分離です。 構築中にこれらの目標を混合すると正確さが複雑になるため、意図的に分離されています。

 ## 特殊なケース

 y = 0 の場合、数字の選択は必要なく、空の表現はゼロとして解釈されるため、アルゴリズムは直ちに 0 を返します。 

y が 6 (3!) や 24 (4!) などの 1 つの階乗に等しい場合、貪欲ループは正確に 1 桁を選択してきれいに停止し、1 桁の答えを生成します。 

y = 10 など、繰り返しの桁が必要な値の場合、アルゴリズムは複数の小さい階乗桁を累積し、最終的な並べ替えに依存して整数が最小化されるようにします。
