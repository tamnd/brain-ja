 ## 解決策
 ## 問題の理解

 バイナリ文字列で表現された通信塔の長い列が与えられます。 各キャラクターは、ラインに沿って順番に 1 つのタワーに対応します。 あ`1`タワーが海岸または島の乾いた地面にあることを意味します。`0`つまり、塔は危険なシアン化物の川の中にあるということだ。 

目標は、すべてのタワーを認定することです。 マークされた塔`1`簡単です。ゼロ日目にすぐに認定できます。 マークされた塔`0`より困難です。このような各タワーの認定には丸 1 日かかり、隣接するタワーの少なくとも 1 つが少なくとも 1 日前にすでに認定されている場合にのみ処理できます。 依存関係ルールが遵守されている限り、複数のタワーを同じ日内で並行して処理できます。 

タスクは、すべてのタワーが認定されるまでに必要な最小日数を決定することです。 

文字列が最大 300,000 文字であるという制約は、数日にわたる二次シミュレーションや 1 日あたり配列全体の繰り返しスキャンが不可能であることを意味します。 アン$O(n^2)$伝播には次のオーダーが必要になります$9 \times 10^{10}$実用的な限界をはるかに超えた最悪の場合の動作。 これにより、1 回または 2 回のパスで答えを計算する線形または線形に近い方法が求められます。 

微妙な問題は、伝播が、後でそれ自体が認定される可能性のある近隣に依存していることです。 オリジナルから拡張しただけの素朴なシミュレーション`1`新しく認定されたポジションも将来の伝播の源となるため、慎重に構成しない限り、1 日 1 ステップでは不十分です。 

文字列が長く続く場合、エッジケースが発生します。`0`s. たとえば、次のことを考えてみましょう。 

入力:`100001`予想される出力: チェーンを介した伝播速度によって異なります。 

もう 1 つのエッジ ケースは単一ブロックです。 

入力:`101`ここが真ん中`0`は認定されたタワーにすぐに隣接しているため、1 日目に認定可能になります。 

よりデリケートなケースは、1 で囲まれたゼロの長いセグメントです。 

入力:`1000001`答えは、両端からの影響がどのくらいの距離まで伝わり、中央で出会う必要があるかによって決まります。 

片側からのみ処理するか、初期からの独立した伝播を想定する単純なアプローチ`1`同時拡張を考慮しないと、長いゼロランで中心位置が誤って計算されます。 

## アプローチ

 ブルートフォース解釈では、日数を明示的にシミュレートします。 どのタワーが認定されているかを管理し、アレイを繰り返しスキャンします。 毎日、未認証の`0`前日から少なくとも 1 つの認定された近隣者がいるタワーが認定されます。 すべてのタワーが認証されるまで繰り返します。 

これはルールを直接反映しているため、これは正しいです。 ただし、毎日文字列の完全なスキャンが必要な場合があり、最悪の場合、長さのゼロの連鎖が必要になります。$n$必要$O(n)$日々。 これは次のことにつながります$O(n^2)$全体的な操作は遅すぎます。$n = 300000$。 

重要な観察は、認証時間は最も近い既に認証されているタワーまでの距離のみに依存するということです。 毎`1`時間ゼロから始まります。 あ`0`最も近い後にのみ認定を受けることができます`1`中間体を介して伝播しました`0`s. 伝播は対称的かつ独立して外側に広がるため、`1`つまり、問題は、各位置について、最も近い位置からどれだけ離れているかを計算することになります。`1`という事実を尊重する形で`1`は最初からアクティブです。 

これにより、プロセスが直線上の最短距離の問題に変換されます。各位置には、最も近い位置までの距離に等しい時間がかかります。`1`、ただし、次の制約があります。`1`s 自体は時間ゼロのソースです。 答えはこれらの距離の最大値です。 

これは 2 つの線形パスで計算できます。1 つは最後に確認されたパスを左から右に追跡します。`1`、右から左に 1 つずつ。 それぞれ`0`までの最小距離を取得します`1`どちらかの側に。

 ## アルゴリズムのチュートリアル

 このプロセスを、各タワーが認証されるまで待機する必要がある時間を計算するものとして再解釈します。 

1. 配列を初期化する`dist`ここで、各ポジションには、そのタワーが認定可能になるまでに必要な最小日数が保存されます。 まず、すべての位置を、ある位置から無限に遠いものとして扱います。`1`。 
2. 最新のインデックスを維持しながら、左から右にスイープします。`1`。 遭遇したとき`1`、トラッカーをリセットします。 遭遇したとき`0`、最後に見られたものまでの距離を測定します`1`左に。 これにより、左側の伝播が到達できる時間の候補が得られます。 
3. 同様に右から左にスイープし、最も近いものを追跡します。`1`右側に。 それぞれについて`0`、最も近いものまでの距離を計算します。`1`右側で最小値を取得して、以前に計算した左側の距離と組み合わせます。 
4. すべての位置について、最終値は、両方の伝播方向を考慮して、そのタワーがどれだけ早く認証されるかを表します。 
5. 最も遅いタワーが認定されるまで待つ必要があるため、最終的な答えはすべてのポジションの最大値になります。 

これが機能する理由は、それぞれ`1`時間ゼロでの同時認証ソースとして機能します。 伝播制約により、情報は 1 日あたり 1 ステップずつ外側に流れることができるため、折れ線グラフ上の最短経路の意味で最も近いソースが各位置に効果的に到達します。 両方の方向を取ることで、方向に関係なく最も近いソースをキャプチャすることが保証され、最大値を取ることでグローバルな完成が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

INF = 10**18
left_dist = [INF] * n

last = -1
for i in range(n):
    if s[i] == '1':
        last = i
        left_dist[i] = 0
    else:
        if last != -1:
            left_dist[i] = i - last

right_dist = [INF] * n
last = -1
for i in range(n - 1, -1, -1):
    if s[i] == '1':
        last = i
        right_dist[i] = 0
    else:
        if last != -1:
            right_dist[i] = last - i

ans = 0
for i in range(n):
    d = min(left_dist[i], right_dist[i])
    ans = max(ans, d)

print(ans)
```最初のパスでは、各位置が最も近い位置からどのくらい離れているかを計算します。`1`その左側にあります。 最初の位置より前の位置`1`左側だけからは事実上到達不可能なままです。 2 番目のパスは右から同じことを行います。 

タワーはどちらの側からも認証できるため、結合手順は最小限で済みます。 最終的な最大値によって最も遅いタワーが選択され、これによって合計完了時間が決まります。 

よくある間違いは、伝播が両方向から発生する可能性があることを忘れることです。 もう一つは初期のみを治療することです`1`をソースとして使用しますが、距離が対称であることを無視するため、非対称レイアウトでは時間を過大評価することになります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = input().strip()
    n = len(s)

    INF = 10**18
    left_dist = [INF] * n

    last = -1
    for i in range(n):
        if s[i] == '1':
            last = i
            left_dist[i] = 0
        else:
            if last != -1:
                left_dist[i] = i - last

    right_dist = [INF] * n
    last = -1
    for i in range(n - 1, -1, -1):
        if s[i] == '1':
            last = i
            right_dist[i] = 0
        else:
            if last != -1:
                right_dist[i] = last - i

    ans = 0
    for i in range(n):
        ans = max(ans, min(left_dist[i], right_dist[i]))

    return str(ans)

# provided samples (assumed from statement style)
assert run("101\n") in ["1", "1\n"]
assert run("100001\n") in ["2", "2\n"]

# custom cases
assert run("1\n") in ["0", "0\n"]
assert run("11111\n") in ["0", "0\n"]
assert run("10001\n") in ["2", "2\n"]
assert run("10101\n") in ["1", "1\n"]

 | --- | --- | --- |
 |`1`|`0`| 単一ノードはすでに認定済み |
 |`11111`|`0`| すべての即時認証 |
 |`10001`|`2`| 中間への対称伝播 |
 |`10101`|`1`| 交互構造の正確性 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、`1`たとえば、文字列の一端に`100000`。 左から右へのパスでは距離が 0 から 5 に増加しますが、右から左へのパスでは何も改善されません。 最も遠いタワーは 1 つのソースのみに依存するため、アルゴリズムは正しく 5 を返します。 

もう 1 つのエッジ ケースは、次のような孤立したゼロを除いて内部ゼロがない場合です。`1110111`。 中心のゼロは両側からの距離が1なので1日で認定され、答えは1になります。 

3 番目のエッジ ケースは、次のような完全に交互のパターンです。`1010101`。 各ゼロは 1 に隣接しているため、すべてのゼロは 1 日で認定されます。 すべての位置の最大値は 1 であり、1 ステップを超える伝播は必要ないという事実と一致します。
