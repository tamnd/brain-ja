 ## 解決策
 ## 問題の理解

 入力は単一の素数を与えます$P$、これは、火星から始まる 1 次元線上の、シルバー スターと呼ばれる最後の小惑星の位置を表します。 この線に沿って、火星から素数に等しい距離に特別な小惑星が配置されています: 2、3、5、7、11 などの昇順です。$P$。 

探査機は距離 2 の小惑星から開始し、距離 2 の小惑星で終了する必要があります$P$。 中間小惑星のどの部分集合でも訪問することができますが、移動の制約を遵守する必要があります。訪問先の小惑星から次の 小惑星に移動する場合、それらの位置間の距離は 14 単位を超えてはなりません。 動きは増加する素数のシーケンスに沿って厳密に前方に進むため、軌跡は単に 2 で始まり で終わる素数の位置の部分列です。$P$、連続して選択された素数の差は最大 14 です。 

タスクは、そのような有効な軌道がいくつ存在するかを数えることです。 

という制約が$P \le 211$これは、非常に小さな素数の接頭辞を扱っていることを意味します。 211 までの素数の数はわずか数十個なので、$O(n^2)$動的プログラミング ソリューションは、パフォーマンスの点では簡単です。 これは、意図したソリューションが大規模な最適化ではなく、小さな DAG に対する単純な組み合わせに基づいていることをすでに示唆しています。 

「最大 14 AU」が隣接する素数のみを考慮できることを意味すると仮定すると、微妙な失敗のケースが発生します。 たとえば、11 − 2 = 9 であるため、2 から 11 に直接ジャンプできます。これは、中間の素数が存在する場合でも許可されます。 単純な隣接のみの解釈では、そのようなスキップを禁止することにより、パスが誤って過小評価されてしまいます。 

すべての素数が等間隔にあると仮定したり、実際の数値距離ではなくカウントによってジャンプのインデックスを付けようとしたりすると、別の間違いが発生します。 制約はシーケンス内の位置ではなく、実際の値に依存します。 

## アプローチ

 ブルートフォースの観点では、各軌道を決定プロセスとして扱います。すべての小惑星で、14 単位以内にある後続の小惑星に行くかどうかを選択します。 これは、最初のプライムから DFS を使用して調査でき、すべての有効な次のステップに再帰的に分岐します。 これは、ジャンプ制約に従ってすべての有効なサブシーケンスを列挙し、最後のノードに到達したサブシーケンスをカウントするため、正しいです。 

ただし、この探索は分岐要素で急速に成長します。 すべてのノードが将来の多くのノードにジャンプできる最悪の概念的なケースでは、再帰パスの数は素数の数に応じて指数関数的に増加する可能性があります。$O(2^n)$。 それでも$n$ここでは が小さいため、このアプローチは構造的に非効率であり、不必要です。 

重要な観察は、素数と有効なジャンプによって形成されるグラフが、値の増加によって順序付けされた有向非巡回グラフであるということです。 DAG 上のパス数の問題は動的プログラミングに帰着できます。ノードに到達する方法の数は、そのノードに遷移できるすべてのノードに到達する方法の合計です。 

素数ごとに$p[i]$、初期の素数のみを考慮する必要があります。$p[j]$そのような$p[i] - p[j] \le 14$。 素数が増加しており、ギャップが小さいため、以前のノードの短いサフィックスのみが現在のノードに到達できます。 これにより、ノードあたりの移行コストが一定の償却時間に削減されます。

 ## アルゴリズムのチュートリアル

 までの素数を扱います$P$ノードとして昇順に配置し、最初から各ノードに到達できる方法の数を計算します。 

1. 2 から 2 までのすべての素数のリストを生成します。$P$。 これはグラフの頂点セットを形成します。 このリストの順序は厳密に増加しているため、すでにトポロジー的です。 
2. DP 配列を作成します。`dp[i]`で終了する有効な軌道の数を表します。$i$-番目の素数。 
3.初期化`dp[0] = 1`なぜなら、最初の小惑星 (2 天文単位) から開始する方法は 1 つだけであり、すべてのパスはそこから開始する必要があるからです。 
4. 各素数インデックスについて$i$左から右に計算します`dp[i]`以前のインデックスからの寄与を合計することによって$j < i$そのような`primes[i] - primes[j] <= 14`。 そういったそれぞれの$j$への有効な最後のステップを表します$i$、つまり、到達するためのあらゆる方法$j$まで拡張できます$i$。 
5. 距離条件が満たされなくなるまで逆方向にスキャンするか、有効な先行データのスライディング ウィンドウを維持することにより、合計を効率的に維持します。 数値が上がるので一旦`primes[i] - primes[j] > 14`、すべて以前の$j$は無効です。 
6. 最終的な答えは次のとおりです。`dp[last]`, すべての有効な軌道はシルバー スターで終了する必要があるためです。 

### なぜ効果があるのか

 すべての有効な軌道は、各小惑星への最後のジャンプによって一意に定義されます。 DP は、各状態が有効な先行状態からその状態に到達するためのすべての方法を蓄積することを保証します。距離制約は実際の小惑星の位置で直接チェックされるため、無効な遷移は決して含まれません。 グラフは昇順で非巡回であるため、各部分問題は計算済みの状態のみに依存し、順序付けされた素数に対する帰納法によって正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sieve(n):
    is_prime = [True] * (n + 1)
    is_prime[0] = is_prime[1] = False
    for i in range(2, int(n ** 0.5) + 1):
        if is_prime[i]:
            step = i
            start = i * i
            for j in range(start, n + 1, step):
                is_prime[j] = False
    return [i for i in range(2, n + 1) if is_prime[i]]

def solve():
    P = int(input().strip())
    primes = sieve(P)

    n = len(primes)
    dp = [0] * n
    dp[0] = 1

    for i in range(1, n):
        total = 0
        j = i - 1
        while j >= 0 and primes[i] - primes[j] <= 14:
            total += dp[j]
            j -= 1
        dp[i] = total

    print(dp[-1])

if __name__ == "__main__":
    solve()
```ふるいは以下のプライムシーケンスを構築します。$P$、これは十分に小さいので、単純な$O(P \log \log P)$方法で十分です。 

DP 配列は、すべての部分軌道カウントをエンコードします。 各位置について、距離条件が崩れるまで逆方向にスキャンします。 素数は厳密に増加しており、ギャップが 14 を超えると、それより前のすべての素数もその値を超えるため、これは安全です。 

よくある実装上の間違いは、遷移がインデックスの差ではなく数値の差に依存することを忘れていることです。 もう 1 つの微妙な問題は初期化です`dp[0] = 1`; この基本ケースがなければ、後続のカウントはすべて 0 のままになります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from math import isqrt

    def sieve(n):
        is_prime = [True] * (n + 1)
        is_prime[0] = is_prime[1] = False
        for i in range(2, isqrt(n) + 1):
            if is_prime[i]:
                for j in range(i * i, n + 1, i):
                    is_prime[j] = False
        return [i for i in range(2, n + 1) if is_prime[i]]

    P = int(sys.stdin.readline().strip())
    primes = sieve(P)

    dp = [0] * len(primes)
    dp[0] = 1

    for i in range(1, len(primes)):
        total = 0
        j = i - 1
        while j >= 0 and primes[i] - primes[j] <= 14:
            total += dp[j]
            j -= 1
        dp[i] = total

    return str(dp[-1])

# minimal case
assert run("2\n") == "1"

# small case
assert run("5\n") == "2"

# slightly larger case
assert run("11\n") == "8"

# boundary case (largest constraint)
assert run("211\n") == run("211\n")

| 11 | 8 | DAG 上のマルチステップ累積 |

 ## 特殊なケース

 可能な限り最小の入力$P = 2$単一の小惑星から構成されています。 唯一の軌跡は、同じノードで始まり同じノードで終わる自明な軌跡であり、DP は初期化するため正しく 1 を返します。`dp[0] = 1`そしてトランジションは決して実行しません。 

のようなケース$P = 5$は、隣接しないジャンプを許可することの重要性を示しています。 差が 3 であるため、2 から 5 への直接のジャンプは有効であり、計算時に DP にはそれが含まれます。`dp[2]`。 単純な隣接のみのアプローチでは、3 をスキップするパスが欠落しているため、2 ではなく 1 が誤って出力されます。 

大型の場合$P$、211 など、アルゴリズムは、先行者の短いサフィックスのみが各状態に寄与するという事実に依存しています。 逆方向ループは距離が 14 を超えるとすぐに停止するため、無関係な素数は決して考慮されなくなり、上限に達しても効率が維持されます。
