 ## 解決策
 ## 問題の理解

 直線上に配置された一連のテラスの高さが与えられます。 各位置は固定幅 1 のテラスを表し、隣接する位置は空間内で事実上連続しています。 

選択したテラスのペアの間に橋を架けたいと考えています。 2 つのインデックス間のブリッジは、2 つのエンドポイントが同じ高さを持ち、厳密にそれらの間のすべてのテラスの高さがその共有エンドポイントの高さよりも厳密に小さい場合にのみ許可されます。 この条件が当てはまる場合、ブリッジはこれら 2 つの位置間の水平距離全体に広がり、インデックス間の距離に等しい長さをもたらします。 

目標は、制限に違反せず、すべてのブリッジの長さの合計が最大になるように、有効なブリッジのコレクションを選択することです。 

制約 N が 3 · 10^5 までであると、インデックスのすべてのペアをチェックする解は直ちに除外されます。 単純な O(N^2) アプローチではすべてのペアを検証しようとしますが、ペア間をスキャンするわずかに改善されたアプローチでも、最悪の場合は O(N^3) に低下します。 意図した解決策は、線形または線形演算に近いものでなければなりません。 

重要な構造的観察は、すべての有効な橋は同じ高さの 2 つの出現によって完全に定義され、その有効性は間に高いまたは同等のブロック要素が存在するかどうかによってのみ決まるということです。 これは、問題が基本的に、中間の最大値によって課される単調性制約の下での等しい値の出現のペアに関するものであることを示唆しています。 

いくつかの特殊なケースは見落とされがちです。 

すべての高さが厳密に増加している場合、2 つの等しい高さは存在しないため、有効な橋は存在せず、そのため答えはゼロになります。 

すべての高さが等しい場合、すべてのペアは技術的にはエンドポイント条件によって適格ですが、すべての内部要素はエンドポイントに等しいため、厳密にはエンドポイントより小さいわけではないため、有効なブリッジはなく、答えは再びゼロになります。 

5 1 5 1 5 のようなパターンがある場合、単純なペアリングは遠い端点を接続しようとする可能性がありますが、中央の等しい高さの出現と中間の最大値に関するルールにより、素の有効なペアを慎重に選択する必要があります。 

これらのケースは、難しいのは等しいペアを数えることではなく、「ブロック」高さによって引き起こされる全体的な構造を強制することであることを示しています。 

## アプローチ

 強引な解釈では、ai = aj となるようなインデックス i < j のすべてのペアを考慮します。 このようなペアごとに、セグメント (i, j) をスキャンしてその最大値を計算します。 その最大値が厳密に ai より小さい場合、ブリッジは有効であるとみなされ、その寄与は j − i となります。 すべての有効なペアを合計し、それらの最も互換性のあるサブセットを取得することは、すでに組み合わせ最適化問題です。 

実現可能性チェックだけでも、ペアごとに O(N) の費用がかかります。 すべての値が等しい最悪のケースでは、Θ(N^2) 個のペアが存在し、これは O(N^3) となり、限界をはるかに超えています。 

重要な洞察は、任意のペアという観点から考えるのをやめ、その代わりに、値が一度に最大 1 つの「アクティブな外部構造」にどのように参加できるかを考えることです。 高さを降順に処理する場合、より高い値を、ラインを独立したセグメントに分割するバリアとして見ることができます。 各セグメント内では、より低い値のみが重要であり、値が処理されると、その内部がより高い障壁に関してすでに解決されている必要がある潜在的なエンドポイントのように動作します。 

これは単調なスタック解釈につながります。 それぞれの高さは、それに遭遇した瞬間にスパンを開始または終了します。より高い障害物が考慮された後、それらが利用可能な最も近い互換性のあるペアであるときはいつでも、同じ高さの出現を貪欲に一致させることができます。

問題は、高さごとにインデックスのスタックを維持することに帰着します。 同じ高さを再び見つけると、最後に一致しないものと一致させようとします。 「間のすべてが下位である」という妥当性条件は、当然強​​制されます。これは、上位または同等の干渉要素が、処理順序の早い段階で構造を分割することによって、そのようなペアリングをすでに防止しているためです。

 ## アルゴリズムのチュートリアル

 それぞれの高さのスタック (またはベクトル) を維持しながら、配列を左から右に処理します。 各スタックには、まだ一致していないその高さのインデックスが格納されます。 

1. 高さによってインデックス付けされたスタックの配列を初期化します。 
2. 位置 i を 1 から N まで繰り返します。現在の高さ h = a[i] について、一致しない以前の h の出現があるかどうかを確認します。 
3. h のスタックが空でない場合は、その最後のインデックス j をポップします。 次に、寄与率 i − j を答えに追加します。 これは、一致しない直近の同一高さと現在位置との間にブリッジを形成することに相当する。 

常に最新の発生とペアリングする理由は、それ以前に発生した場合、不必要に障害物を越える可能性があり、将来の最適なペアリングを妨げる可能性があるより長いスパンを作成するためです。 

1. h のスタックが空の場合、i をスタックにプッシュします。 これは、この発生が将来の一致を待機していることを示します。 
2. 配列の最後まで続けます。 

これが機能する理由は、有効な橋が高さ ≥ h の中間要素を持たずに 2 つの等しい高さを接続する必要があるという事実から来ています。 このような中間要素が存在する場合、構造はすでに「分離」されているでしょう。ペアリングが完全に妨げられるか、より小さなセグメント内で強制的にペアリングが発生するかのいずれかです。 

左から右に処理して貪欲にマッチングすることにより、高さ h に関して現在同じ「アクティブな可視セグメント」にあるインデックスのみが接続されるようになります。 h の各スタックは、ブロック高さ ≥ h がそれらの間に存在しない現在の最大セグメント内の一致しないエンドポイントを暗黙的に表します。 

したがって、一致するたびに、最大の安全な寄与が形成され、遅延すると最適なペアリング構造が失われる危険性があるだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    stacks = {}
    ans = 0

    for i, h in enumerate(a):
        if h not in stacks:
            stacks[h] = []

        if stacks[h]:
            j = stacks[h].pop()
            ans += i - j
        else:
            stacks[h].append(i)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、各高さが独自の保留中のエンドポイントを維持する概念モデルを直接反映しています。 観測された高さのみが格納されるため、ディクショナリは最大 10^6 までの固定配列を不必要に割り当てることを回避します。 

微妙な点は、距離が i − j として直接計算されるため、ゼロベースのインデックス付けです。 もう 1 つは、一致しない最新のインデックスと常に一致し、将来のペアリングが無効になるような形で間隔が重複しないようにすることです。

 ## 特殊なケース

 1 つのテラスを持つ最小限の入力は、一致をトリガーする 2 番目の出現が存在しないため、アルゴリズムが正しく答えを 0 のままにすることを示しています。 その高さのスタックは、決して寄与しない単一の不一致インデックスで終了します。 

1 1 1 1 のような完全に等しい配列では、アルゴリズムはインデックス (0,1) と (2,3) をペアにします。 トレースは、可能であれば各プッシュがすぐに照合され、最新の不一致インデックスが常に使用されるため、それより長い範囲のペアリングが試行されないことを示しています。 

1 2 1 2 1 のような交互構造では、各高さが独立して独自のスタックを維持し、各値の 2 番目の出現のみをペアにすることができます。 スタックを分離することで、異なる高さ間の干渉が正確さに影響を与えないことが保証されます。これは、各ブリッジがエンドポイントの同等性にのみ依存し、順序の一致によるセグメンテーションによってすでに暗黙的に処理されているブロッカーを除き、他の値には依存しないためです。
