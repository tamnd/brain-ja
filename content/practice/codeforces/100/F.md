 ## 解決策
 ## 問題の理解

 すでに線形項に因数分解された多項式が与えられています。$$p(x) = (x + a_1)(x + a_2)\dots(x + a_n)$$タスクは、この積を拡張し、多項式を通常の降べき乗形式で出力することです。$$x^n + b_1x^{n-1} + \dots + b_n$$難しいのは拡張自体ではありません。 難しいのは、結果を必要に応じて正確にフォーマットすることです。 

すべての用語がフォームに含まれている必要があります`C*X^K`ただし、可能な限り短縮します。 係数`1`非定数項が消える前に、指数`1`次のように印刷する必要があります`X`、指数`0`省略する必要があります`X`完全、および係数付きの項`0`絶対に現れてはいけません。 標識も余分なスペースを入れずにコンパクトに印刷する必要があります。 

次数は最大でも 9 であり、非常に小さいです。 ここでは指数関数的な動作をするアルゴリズムでもおそらく生き残るでしょうが、それらを使用する理由はありません。 単純な多項式乗算アプローチは、数百回の演算で実行されます。 

書式設定ルールでは、最も誤った答えが発生します。 多項式自体は計算が簡単です。 

中間係数がゼロになると、微妙なエッジ ケースが 1 つ現れます。 例えば：```
2
-1
1
```多項式は次のとおりです。$$(x-1)(x+1)=x^2-1$$の`x`期間が完全に消滅します。 不注意に実装すると、次のように出力される可能性があります。`X^2+0*X-1`、これは無効です。 

もう 1 つの危険なケースは、係数が次の値に等しい場合です。`1`または`-1`。 考慮する：```
1
1
```多項式は次のとおりです。$$x+1$$正しい出力は次のとおりです。```
X+1
```印刷`1*X+1`は冗長すぎるため拒否されます。 

指数の書式設定も重要です。 例えば：```
2
0
0
```与える:$$x^2$$出力は次のようになります。```
X^2
```ない`X^2+0*X+0`。 

定数多項式も特別な処理が必要です。 例えば：```
1
-3
```生成されるもの:$$x-3$$定数項には何もありません`X`一方、線形項には指数がありません。 

## アプローチ

 最も直接的な強引なアイデアは、すべての係数を明示的に保存しながら、文字通り係数を 1 つずつ乗算することです。 

現在、次の係数がわかっているとします。$$(x+a_1)(x+a_2)\dots(x+a_k)$$次に乗算します`(x + a_{k+1})`次の多項式を作成します。 古い各係数は 2 つの新しい係数に寄与し、1 つは乗算により次数ずつシフトされます。`x`、および乗算により変更されない 1 つ`a_{k+1}`。 

これが機能するのは、多項式の乗算が項全体に自然に分布するためです。 

本当に単純な総当り的なソリューションでは、あらゆる程度に寄与する要因のすべてのサブセットを列挙することになります。 の係数なので、$x^{n-k}$のすべての積の合計です`k`選ばれた`a_i`、そのアプローチではすべてのサブセットをチェックする必要があります。 と`n ≤ 9`、 平$2^9 = 512$サブセットも許容されますが、実装が不必要に複雑になります。 

増分乗算のアプローチはよりクリーンで、概念的にはるかに適切に拡張できます。 各乗算は現在の多項式次数のみに影響するため、複雑さは 2 次になります。 

重要な観察は、線形多項式を乗算すると、隣接する係数のみが変更されるということです。 もし：$$P(x)=c_0+c_1x+\dots+c_dx^d$$それから：$$P(x)(x+a)= ac_0+(c_0+ac_1)x+\dots+c_dx^{d+1}$$この局所的な遷移により、動的な多項式の構築が自然になります。 

係数を計算した後、残る課題は決定論的な書式設定です。 このステートメントは一意の有効な出力を保証するため、最短表現規則に正確に従う必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットの列挙 | O(2^n \cdot n) | O(2^n) | 承認済み |
 | 増分多項式乗算 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての値を読み取る`a_i`。 
2. 定数多項式から始める`1`。 

係数を次数の昇順に保存します。 最初に:$$p(x)=1$$したがって、係数配列は次のようになります。```
[1]
```3. あらゆる要素について`(x + a)`1 度大きい新しい係数配列を作成します。 

現在の係数が$x^i$は`c`、その後:

 乗算`a`貢献する`c * a`程度まで`i`。 

乗算`x`貢献する`c`程度まで`i+1`。 
4. 各因子を処理した後、古い多項式を新しい多項式に置き換えます。 

すべての因数が処理されると、配列には展開された多項式のすべての係数が含まれます。 
5. 最高次数から最低次数まで係数をたどって、応答文字列を構築します。 
6. ゼロに等しい係数をスキップします。 

係数のある項`0`絶対に現れてはいけません。 
7. 標識は慎重に取り扱います。 

最初に印刷される用語は次で始まってはなりません`+`。 

否定的な用語は次で始める必要があります`-`。 
8. 各用語を最短の法的形式にフォーマットします。 

学位について`0`、係数のみを出力します。 

学位について`1`、印刷`X`の代わりに`X^1`。 

係数の場合`1`そして`-1`非定数の場合は数値部分を省略します。 
9. 最後の文字列を出力します。 

### なぜ効果があるのか

 最初の処理後`k`係数配列は正確に次のことを表します。$$(x+a_1)(x+a_2)\dots(x+a_k)$$多項式は次のとおりであるため、この不変式は最初は true です。`1`。 

乗算する場合`(x+a_{k+1})`、すべての項は分布性を通じて新しい多項式に正しく寄与します。 乗算`a_{k+1}`を乗算しながら次数を保持します。`x`度が1つ上がります。 すべての寄与が正確に 1 回追加されるため、結果として得られる係数は正確です。 

各係数はステートメントの最短形式ルールに従って変換され、ゼロ項は完全に省略されるため、フォーマット段階は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def format_term(coef, deg, first):
    if coef == 0:
        return ""

    sign = ""
    if coef < 0:
        sign = "-"
    elif not first:
        sign = "+"

    val = abs(coef)

    if deg == 0:
        body = str(val)
    else:
        if val == 1:
            coef_part = ""
        else:
            coef_part = str(val) + "*"

        if deg == 1:
            body = coef_part + "X"
        else:
            body = coef_part + f"X^{deg}"

    return sign + body

def solve():
    n = int(input())
    a = [int(input()) for _ in range(n)]

    # coefficients by increasing degree
    poly = [1]

    for x in a:
        nxt = [0] * (len(poly) + 1)

        for deg, coef in enumerate(poly):
            nxt[deg] += coef * x
            nxt[deg + 1] += coef

        poly = nxt

    parts = []
    first = True

    for deg in range(n, -1, -1):
        term = format_term(poly[deg], deg, first)

        if term:
            parts.append(term)
            first = False

    print("".join(parts))

solve()
```多項式係数は、乗算中の遷移を簡素化するため、次数の昇順で格納されます。 因子を処理するとき`(x + a)`、既存の各係数は、次の配列内の正確に 2 つの位置に寄与します。 

アップデート内容:```
nxt[deg] += coef * x
nxt[deg + 1] += coef
```は分配乗算から直接得られます。 

フォーマット機能は、すべての出力ルールを 1 か所に分離します。 これにより、散在する特殊なケースが回避され、正しさの推論が容易になります。 

最も間違いが起こりやすい詳細は係数の処理です`1`そして`-1`。 例えば：```
1*X^2
```最短の表現では省略する必要があるため、これは無効です。`1`。 

もう 1 つの微妙な点は、サインの処理です。 最初の正の項は次で始まってはなりません`+`、その後のすべての正の用語は必ず必要です。 

ループは次数を最大から最小まで出力するため、多項式は標準​​形式で表示されます。

 ## 特殊なケース

 次のことを考慮してください。```
2
-1
1
```多項式は次のようになります。$$(x-1)(x+1)=x^2-1$$乗算中、係数配列は次のようになります。```
[-1, 0, 1]
```次数 1 の項の係数は 0 であるため、アルゴリズムは次数 1 の項をスキップします。 最終的な出力は次のとおりです。```
X^2-1
```これにより無効なフォームが回避されます`X^2+0*X-1`。 

ここで次のことを考えてみましょう。```
1
1
```係数配列は次のとおりです。```
[1, 1]
```次数 1 の項をフォーマットするときに、アルゴリズムは係数を検出します`1`数値プレフィックスを抑制します。 出力は次のようになります。```
X+1
```の代わりに`1*X+1`。 

最後に、次のことを考慮してください。```
2
0
0
```多項式は次のとおりです。$$x^2$$係数配列は次のとおりです。```
[0, 0, 1]
```両方の低次項はスキップされます。 アルゴリズムは次のもののみを出力します。```
X^2
```これは必要な最短の表現です。
