 ## 解決策
 ## 問題の理解

 一辺の長さがある正方形の部屋があります`n`、したがって、総面積は次のようになります。`n × n`。 私たちも持っています`k`正方形のカーペット、それぞれに辺の長さがある`n1`。 回転が禁止されているため、すべてのカーペットは常に軸に沿ったままになりますが、カーペットは正方形であるため、回転しても実際には何も変わりません。 

問題は、これらのカーペットが部屋を完全に覆うことができるかどうかです。 カーペットは重なる可能性があるため、余分な領域を使用することができます。 重要なのは、部屋のすべての点を少なくとも 1 枚のカーペットでカバーできるかどうかだけです。 

制約は非常に小さいです。 辺の長さは最大 12 で、カーペットの数は最大 10 です。徹底的な幾何学的検索でも技術的には適合しますが、問題にはもっと単純な数学的観察が隠されています。 答えは数回の算術演算で決定できるため、配置をシミュレーションする必要はありません。 

主な罠は、重複の意味を誤解していることです。 単純な考えは、カーペットの総面積と部屋の面積を比較し、カーペットが十分な面積を提供する場合は常に「YES」と答えることです。 ジオメトリは依然として重要であるため、これでは十分ではありません。 

次の例を考えてみましょう。```
10 1 10
```一枚のカーペットがお部屋にぴったり合うので、答えは「YES」です。 

次に見てください:```
10 4 4
```カーペットの総面積は、`4 × 4 × 4 = 64`、ただし部屋の面積は`100`。 利用可能な総面積が十分ではないため、答えは明らかに「ノー」です。 

さらに興味深いケースは次のとおりです。```
10 4 6
```カーペットの総面積は、`144`、部屋の面積よりも広い。 答えは「はい」です。 4`6 × 6`カーペットは少し重ねることで部屋を覆うことができます。 

不用意に実装すると、カーペットは重なり合うことなく部屋に完全にタイル張りする必要があると誤って想定される可能性があります。 例えば：```
10 4 6
```タイリング解釈は次の理由で失敗します。`10`で割り切れない`6`ですが、重複は許可されているため、正解は依然として YES です。 

実際の条件は、部屋の片側に何枚のカーペットが必要かということです。 それぞれのカーペットがまたがっているので、`n1`ユニットを水平方向と垂直方向に配置すると、その長さをカバーするのに十分なカーペットが必要になります`n`両方向に。 

## アプローチ

 強引な考え方は、部屋のカーペットをあらゆる配置で試してみることです。 座標は小さいため、部屋を離散化し、すべてのセルが覆われているかどうかを確認しながらカーペットを再帰的に配置することができます。 

このアプローチは制約が非常に小さいため機能しますが、配置数は爆発的に増加します。 各カーペットに可能な位置が約 100 個しかないとしても、すべての構成を試すには、大まかな作業が必要になります。`100^10`最悪の場合は状態になりますが、これはまったく非現実的です。 

重要な観察は、一次元の範囲のみが重要であるということです。 

カーペットを格子状に敷くとします。 部屋の片側に沿って、各カーペットは最大でも貢献します`n1`長さ。 一定の長さのセグメントをカバーするには`n`、少なくとも次のものが必要です。$$\left\lceil \frac{n}{n1} \right\rceil$$その寸法に沿ったカーペット。 

部屋は 2 次元であるため、水平方向と垂直方向に同じ枚数のカーペットが必要です。 したがって、必要なカーペットの最小枚数は次のようになります。$$\left\lceil \frac{n}{n1} \right\rceil^2$$少なくとも同じくらいの数のカーペットがすでにある場合は、それらを格子状に配置し、部屋を完全に覆うことができます。場合によっては端近くで重なり合うこともあります。 

これにより、問題全体が 1 つの算術比較に変わります。

 ## アルゴリズムのチュートリアル

 1. 値を読み取る`n`、`k`、 そして`n1`。 
2. 部屋の片側に何枚のカーペットが必要かを計算します。 

各カーペットカバーなので、`n1`一方向の単位の場合、カウントは次のようになります。$$need = \left\lceil \frac{n}{n1} \right\rceil$$整数の上限除算は次のように計算できます。```
need = (n + n1 - 1) // n1
```3. グリッドを完全に覆うために必要なカーペットの総数を計算します。```
required = need * need
```必要です`need`カーペットを横切って`need`カーペットを下ろしているので、合計は彼らの製品です。 
4. 比較する`k`と`required`。 

もし`k >= required`、印刷`YES`。 それ以外の場合は印刷します`NO`。 

### なぜ効果があるのか

 各カーペットは側面の正方形の領域をカバーします`n1`。 単一の次元に沿って、長さをカバーします`n`少なくとも必要です`ceil(n / n1)`すべてのカーペットがせいぜい貢献するため、カーペット`n1`単位。 

部屋は正方形なので、それだけの数の行と列のカーペットが必要になります。 あ`need × need`一部のカーペットが境界線からはみ出していたり​​、他のカーペットと重なっていたりしても、配置は常に部屋全体をカバーします。 

アルゴリズムはこの実行可能な最小数を正確に計算するため、答えは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k, n1 = map(int, input().split())

need = (n + n1 - 1) // n1

if k >= need * need:
    print("YES")
else:
    print("NO")
```最初のステップでは、標準入力から 3 つの整数を直接読み取ります。 

表現:```
(n + n1 - 1) // n1
```整数演算を使用して上限除算を実装します。 これは精度の問題を回避できるため、浮動小数点除算よりも安全です。 

乗算:```
need * need
```は、正方形のグリッドに配置されたカーペットの数を表します。 制約が小さいため、Python ではオーバーフローは不可能ですが、固定サイズの整数を使用する言語でも、値は非常に小さいままです。 

最終的な比較では、利用可能なカーペットがそのカバー グリッドを構築するのに十分であるかどうかを確認します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    n, k, n1 = map(int, input().split())

    need = (n + n1 - 1) // n1

    if k >= need * need:
        print("YES")
    else:
        print("NO")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("10 4 6\n") == "YES\n", "sample 1"

# exact fit with one carpet
assert run("10 1 10\n") == "YES\n", "single carpet fits exactly"

# not enough total coverage
assert run("10 4 4\n") == "NO\n", "insufficient area"

# one carpet short
assert run("10 3 6\n") == "NO\n", "needs 4 carpets"

# maximum style boundary
assert run("12 9 4\n") == "YES\n", "3x3 grid exactly"

# overlap-heavy case
assert run("11 4 10\n") == "YES\n", "large overlap still works"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 次の入力を考えてみましょう。```
10 4 6
```アルゴリズムは以下を計算します。```
need = ceil(10 / 6) = 2
required = 2 × 2 = 4
```以来`k = 4`、答えはYESです。 

この事例は、カーペットは部屋に完璧なタイルを張らなければならないという誤った思い込みを覆します。 あ`6 × 6`カーペットは部屋の寸法を均等に分割しませんが、重なり合うことで完全にカバーできます。 

次に、次のことを考えてみましょう。```
10 4 4
```アルゴリズムは以下を計算します。```
need = ceil(10 / 4) = 3
required = 9
```利用できるカーペットは 4 枚だけなので、答えは NO です。 

これにより、総面積のみを比較するソリューションが捕捉されます。 各カーペットはかなり大きいですが、4 枚で部屋を縦横に広げることはできません。 

最後に、次のことを考慮してください。```
10 1 10
```計算は次のようになります。```
need = 1
required = 1
```1 枚のカーペットがすでに部屋全体を正確に覆っているため、アルゴリズムは正しく YES を出力します。
