 ## 解決策
 ## 問題の理解

 最初の文字列から始めて、それを円の周りに渡します。`n`人々。 すべての人は、次の 2 つの方法のいずれかでのみ文字列を変更できます。 

1. 末尾から 1 文字だけ削除します。 
2. 末尾に 1 文字だけ追加します。 

何もしないという選択をする人もいるでしょう。 

まさにその後`n`送信すると、最終的な文字列が得られます。 最終的な文字列が最初の文字列から合法的に生成されたかどうかを判断する必要があります。 

重要な点は、すべての操作が文字列のサフィックスにのみ影響するということです。 真ん中のキャラクターは直接触れられることはありません。 唯一の変更可能な部分は、文字列の現在の末尾です。 

制約が異常に大きいです。 到達できる移動数は`8 * 10^6`、各文字列の長さは最大です。`10^7`。 二次的な動作を伴うアルゴリズムは不可能です。 線形アルゴリズムであっても、不必要なコピーやスキャンの繰り返しを避ける必要があります。 文字列を繰り返し再構築したり、操作を 1 つずつシミュレートしたりするソリューションでは、タイムアウトになるか、メモリ不足が発生します。 

また、入力サイズが大きいため、プロセス中に実際に何が変化するのかを注意深く考える必要があります。 操作は最後にのみ行われるため、保存された文字の相対的な順序は決して変わりません。 その観察こそが問題のすべてだ。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
n = 2
initial = abc
final = abc
```正しい答えは、`Yes`。 どちらの人も単に何もしないかもしれません。 すべての移動が文字列を変更する必要があると仮定する不注意な解決策は、これを誤って拒否することになります。 

次に、次のことを考えてみましょう。```
n = 1
initial = abc
final = ab
```正しい答えは、`Yes`。 削除は 1 つで十分です。 しかし：```
n = 1
initial = abc
final = a
```正しい答えは、`No`1 回の移動で長さが最大 ​​1 変化する可能性があるためです。 

もう 1 つの微妙なケースは、一方の文字列がもう一方の文字列のプレフィックスである場合です。```
n = 3
initial = abc
final = abcde
```答えは`Yes`。 必要な追加操作は 2 つだけで、残りの移動は使用しなくてもかまいません。 

しかし、これは失敗します:```
n = 1
initial = abc
final = abcde
```答えは`No`2 文字ずつ拡大するには少なくとも 2 つの操作が必要になるためです。 

最も重要な構造上のエッジケースは、短い文字列が終了する前に文字列が一致しない場合です。```
n = 10
initial = abcd
final = abxd
```答えは`No`。 変わるのは終わりだけだから、決して変えることはできない`c`の中へ`x`その後のすべてを削除せずに。 保存される部分は常に共通のプレフィックスである必要があります。 

## アプローチ

 ブルートフォースのアイデアは、考えられるすべての操作シーケンスをシミュレートすることです。 各ステップで、文字を追加したり、最後の文字を削除したり、何もしないこともあります。 追加の選択肢をターゲット文字列に出現する文字に制限したとしても、分岐要素は膨大になります。 後`n`ステップが増加すると、可能な状態の数は指数関数的に増加します。 

もう 1 つの強引な改良は、最終文字列から逆算して考えることです。 可能な限りの数の削除と追加を試すことができます。 文字列には何百万もの文字が含まれる可能性があるため、これは依然として実行不可能になります。 

総当たりの攻撃が魅力的に感じられる理由は、それぞれの動きが単純だからです。 しかし、移動シーケンスの数は膨大ですが、実際の構造的自由度はごくわずかです。 

重要な点は、操作はサフィックスにのみ影響を与えるということです。 つまり、最初の不一致以前のすべての文字は永久に変更されないままにしておく必要があります。 したがって、2 つの文字列が何らかの共通のプレフィックスを共有している場合にのみ変換が可能であり、そのプレフィックス以降のすべてを削除して再構築できるのは最大でも 1 以内です。`n`操作。 

最長の共通プレフィックス長が次であると仮定します。`L`。 

変換するには:```
initial -> final
```私たちは次のことをしなければなりません:

 1.最後のものを削除`len(initial) - L`文字。 
2. 最後に追加`len(final) - L`文字。 

最低限必要な操作は次のとおりです。```
(len(initial) - L) + (len(final) - L)
```この値が最大でも`n`, そうすれば、各人は文字列を変更しないままにすることができるので、何もせずに余分な動きを費やすことができます。 

したがって、問題全体は、最長の共通プレフィックスを計算し、必要な編集数がその中に収まるかどうかを確認することに帰着します。`n`。

 ## アルゴリズムのチュートリアル

 1.読む`n`、最初の文字列`s`、最後の文字列`t`。 
2. 文字が一致する間に両方の文字列を左から右にスキャンします。 

インデックスを維持する`L`、最長の共通プレフィックスの長さ。 

最初の不一致が発生すると、操作はサフィックスのみを変更するため、それ以降の文字は保持できなくなります。 
3. 必要な削除の数を計算します。 

すべての文字を削除する必要があります`s`ポジションの後`L`。 

その数は次のとおりです。```
len(s) - L
```4. 必要な追加操作の数を計算します。 

残りのサフィックスを構築する必要があります`t`。 

その数は次のとおりです。```
len(t) - L
```5. 2 つの値を加算して、最小限必要な演算を取得します。 
6. 必要最小限の操作が最大でも`n`、印刷`Yes`。 

それ以外の場合は印刷します`No`。 

### なぜ効果があるのか

 すべての操作は最後に行われるため、文字列の保存部分は常に接頭辞のままでなければなりません。 2 つの文字列がある位置で異なると、ターゲット サフィックスを構築する前に、最終的に元の文字列の後のすべての文字を削除する必要があります。 

したがって、最も長い共通プレフィックスが、変更せずに保持できる最大部分となります。 有効な変換では、初期文字列の残りの部分を削除し、ターゲット文字列の残りの部分を追加する必要があります。 これにより、必要な操作の最小数が得られ、追加の操作は単に文字列を変更しないままにすることができます。 したがって、この条件は必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()
    t = input().strip()

    l = 0
    limit = min(len(s), len(t))

    while l < limit and s[l] == t[l]:
        l += 1

    operations = (len(s) - l) + (len(t) - l)

    if operations <= n:
        print("Yes")
    else:
        print("No")

solve()
```この実装は数学的引数を直接反映しています。 

このループは、部分文字列を作成せずに最長の共通プレフィックスを計算します。 文字列には最大 1,000 万文字が含まれる可能性があるため、これは重要です。 スライスを繰り返すと、大量のメモリが割り当てられ、プログラムが大幅に遅くなります。 

ループ後、インデックス後のすべての文字`l`元の文字列内のインデックスの後のすべての文字を削除する必要があります`l`ターゲット文字列に を追加する必要があります。 の式は、`operations`その観察から直接得られたものです。 

比較には、`<= n`、 ない`== n`。 これはよくある間違いの原因です。 移動中に文字列を変更しないままにしておくことが許可されているため、未使用の移動を余分に持つことは完全に有効です。 

もう一つの微妙なディテールは、`strip()`文字列を読むとき。 入力行には、文字列の一部になってはいけない末尾の改行が含まれています。

import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()
    t = input().strip()

    l = 0
    limit = min(len(s), len(t))

    while l < limit and s[l] == t[l]:
        l += 1

    operations = (len(s) - l) + (len(t) - l)

    if operations <= n:
        print("Yes")
    else:
        print("No")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()
