 ## 解決策
 ## 問題の理解

 我々に点が与えられる$(x, y)$2D 平面上と角度$k$度単位で。 タスクは、点を原点を中心に反時計回りに正確に回転させることです。$k$度を計算し、新しい点の座標を出力します。 

原点の周りを回転すると、ベクトルの方向を変更しながら原点からの距離が維持されます。 幾何学的には、これは標準の 2D 回転変換です。 

制約は非常に小さいです。 座標の境界は絶対値で 1390 のみであり、処理する点は 1 つだけです。 数学的に重いソリューションであっても即座に実行されるため、時間の複雑さはここでは事実上無関係です。 本当の課題は、幾何学式を正しく実装し、誤差限界を満たすように浮動小数点精度を慎重に処理することです。 

必要な相対誤差は以下です$10^{-1}$、とても寛容です。 標準の倍精度浮動小数点演算で十分です。 

いくつかのエッジケースでは、不注意な実装が静かに破壊される可能性があります。 

0 度回転すると、元の点が変更されずに返されます。 

入力：```
0
5 -3
```正しい出力:```
5.00000000 -3.00000000
```バグのある実装により、誤って度数が誤って変換されたり、反時計回りの代わりに時計回りの回転が適用されたりする可能性があります。 

90 度回転することは、座標の位置が入れ替わり、符号が 1 つ変わるため、もう 1 つの古典的な罠です。 

入力：```
90
1 1
```正しい出力:```
-1.00000000 1.00000000
```回転行列が正しく書かれていない場合、出力は次のようになります。`(1, -1)`または`(-1, -1)`。 

マイナスの座標も重要です。そこでは符号の間違いが明らかになるからです。 

入力：```
180
-2 7
```正しい出力:```
2.00000000 -7.00000000
```間違った角度変換や間違ったサイン/コサインの配置により、実際の回転ではなくミラーリングされた結果が生成されることがよくあります。 

## アプローチ

 この問題を考える強引な方法は、幾何学シミュレーションです。 合計角度が次の角度に達するまで、小さな回転を繰り返し適用することができます。$k$度。 回転は単なる座標の変換であるため、小角度行列を繰り返し乗算することで、最終的には目標の方向に到達します。 

回転がきれいに構成されるため、この考えは数学的に正しいです。 1 度の回転を 90 回適用すると、1 回の 90 度の回転と同じ結果が得られます。 

問題は、浮動小数点演算を繰り返すと数値誤差が不必要に蓄積されることです。 制約が十分小さいので高速に実行できますが、非効率的であり、精度も必要以上に低くなります。 一度に 1 次をシミュレーションした場合、最悪のケースでは 359 回の行列乗算が必要となり、実際の利益は得られません。 

重要な観察は、2D での回転にはすでに直接の閉形式が存在するということです。 ポイントなら$(x, y)$角度だけ反時計回りに回転します$\theta$、新しい座標は次のとおりです。$\begin{aligned}x' &= x\cos\theta - y\sin\theta \\ y' &= x\sin\theta + y\cos\theta\end{aligned}$これは、単位円の幾何学形状と回転行列から直接得られます。 Python の三角関数はラジアンで動作するため、まず度をラジアンに変換します。 

最適な解決策は、これら 2 つの式を 1 回評価するだけです。 これにより、一定の時間計算量が得られ、累積的な浮動小数点ドリフトが回避されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k) | お(1) | 不要 |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 回転角度を読み取る`k`そして点の座標`x`そして`y`。 
2. Python では角度を度からラジアンに変換します。`math.sin`そして`math.cos`関数はラジアンを想定しています。 

変換式は次のとおりです。$\theta = k \cdot \frac{\pi}{180}$1. コンピューティング`cos(theta)`そして`sin(theta)`一度。 

それらを一度計算すると、重複した作業が回避され、コードがクリーンな状態に保たれます。 

1. 2D 回転公式を適用します。$$x' = x \cos\theta - y \sin\theta$$

$$y' = x \sin\theta + y \cos\theta$$これらの式は、点ベクトルと標準の回転行列を乗算して得られます。 

1. 浮動小数点形式を使用して、結果の座標を出力します。 

判定では小さな浮動小数点誤差が許容されるため、標準の 10 進形式で十分です。 

### なぜ効果があるのか

 角度による反時計回りの回転$\theta$は行列で表されます。$\begin{bmatrix}\cos\theta & -\sin\theta \\ \sin\theta & \cos\theta\end{bmatrix}$この行列にベクトルを乗算します。$(x, y)$回転された点の正確な座標を生成します。 行列の回転では距離と角度が維持されるため、変換された点は正確に原点を中心に回転された元の点になります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

# solution

k = int(input())
x, y = map(int, input().split())

theta = math.radians(k)

c = math.cos(theta)
s = math.sin(theta)

nx = x * c - y * s
ny = x * s + y * c

print(f"{nx:.8f} {ny:.8f}")
```プログラムは角度と座標を読み取ることから始まります。 角度は次を使用してラジアンに変換されます。`math.radians`これにより、手動による変換ミスを回避できます。 

変数`c`そして`s`角度のコサイン値とサイン値を保存します。 それらを一度計算すると、よりクリーンになり、わずかに効率的になります。 

の公式`nx`そして`ny`回転行列の乗算を直接実装します。 順序が重要です。 よくあるバグは、符号を混合したり、サイン項とコサイン項を交換したりすることです。 

出力では、小数点以下 8 桁の固定 10 進数形式が使用されます。 この問題は小さな相対誤差のみを必要とするため、これは快適に正確です。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
import math

def solve():
    input = sys.stdin.readline

    k = int(input())
    x, y = map(int, input().split())

    theta = math.radians(k)

    c = math.cos(theta)
    s = math.sin(theta)

    nx = x * c - y * s
    ny = x * s + y * c

    print(f"{nx:.8f} {ny:.8f}")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("90\n1 1\n") == "-1.00000000 1.00000000", "sample 1"

# zero rotation
assert run("0\n5 -3\n") == "5.00000000 -3.00000000", "zero rotation"

# 180 degree rotation
assert run("180\n2 -3\n") == "-2.00000000 3.00000000", "180 degrees"

# point at origin
assert run("270\n0 0\n") == "0.00000000 -0.00000000", "origin"

# maximum coordinate magnitude
out = run("90\n1390 -1390\n")
assert out.startswith("1390.00000000"), "large coordinates"

 ## 特殊なケース

 0 度回転すると、点は変更されないままになります。 

入力：```
0
5 -3
```このアルゴリズムは 0 度を 0 ラジアンに変換します。 以来：$$\cos(0)=1$$そして$$\sin(0)=0$$式は次のようになります。$$x' = 5 \cdot 1 - (-3)\cdot 0 = 5$$

$$y' = 5 \cdot 0 + (-3)\cdot 1 = -3$$出力は入力ポイントと同じままです。 

90 度の回転は符号エラーの影響を受けやすくなります。 

入力：```
90
1 1
```アルゴリズムは以下を計算します。$$\cos(90^\circ)=0$$

$$\sin(90^\circ)=1$$それから：$$x' = 1\cdot0 - 1\cdot1 = -1$$

$$y' = 1\cdot1 + 1\cdot0 = 1$$これにより、回転が時計回りではなく反時計回りであることが確認されます。 

原点は、もう 1 つの有用な境界ケースです。 

入力：```
270
0 0
```角度に関係なく:$$x' = 0$$

$$y' = 0$$式内のすべての項がゼロになるため、アルゴリズムは原点を正しく保持します。
