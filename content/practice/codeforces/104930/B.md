 ## 解決策
 ## 問題の理解

 数字の文字列として書かれた家番号が与えられます。 この都市には対称性のルールがあります。数値を 180 度回転しても、同じ桁数体系を使用して有効な読み取り可能な数値を形成する必要があります。 

回転後も、限られた数字のセット (0、1、6、8、9) のみが残ります。 回転後も変わらない数字 (0、1、8) もあれば、相互に変換される数字もあります (6 が 9 になり、9 が 6 になります)。 このセットの外にある数字は、回転後に読めなくなるため、直ちにルールに違反します。 

有効な番地は 2 つの条件を同時に満たさなければなりません。 まず、逆さまに読むと、回転マッピングの下で​​一貫した数字列が生成される必要があります。 第 2 に、どちらの向きでも先行ゼロは受け入れられないため、元の数値も回転バージョンも 0 で始めることはできません。 

入力は文字列として表される単一の整数であり、その表現には先頭にゼロが含まれる場合があります。 タスクは、この番号がこれらのルールの下で有効なアップサイド ダウンタウンの住宅番号として存在できるかどうかを判断することです。 

制約は十分小さいため、桁全体の線形スキャンで十分です。 数値の長さは最大 10 であるため、O(n) または O(n^2) のアプローチは自明のことながら高速です。 これにより、パフォーマンスではなく、数値マッピング ルールの正確さと慎重な処理に焦点が完全に移ります。 

主なエッジケースは、境界桁と無効な回転に起因します。 680 のような数値は視覚的にはもっともらしく見えますが、回転すると 089 になり、これはゼロから始まり、ルールに違反します。 同様に、0 のような 1 桁の数字は、回転下では有効ですが、先行ゼロ制約により無効となるため、注意が必要です。 もう 1 つの微妙なケースは、ミラーリングされたペアの不一致により構造全体が壊れるため、数字のペアが両端で一貫していることを確認することです。 

## アプローチ

 簡単なアプローチは、回転を明示的にシミュレートすることです。 数値を取得し、文字列を反転して数字のマッピングを適用することでその数値を回転したバージョンを構築し、元の文字列と回転した文字列の両方が有効な数値であるかどうかを確認します。 これは、回転された表現が 180 度回転した後に数字がどのように表示されるかを完全にキャプチャしているため、機能します。 検証したいものを直接構築しているため、正しさはすぐにわかります。 

このブルート フォース手法では、文字列を 1 回スキャンしてローテーションされたバージョンを構築し、いくつかのチェックを実行します。 余分な冗長作業を行ったとしても、入力サイズが非常に小さいため、パフォーマンスは問題になりません。 ただし、無効な数字の検証を忘れたり、回転された結果の先頭のゼロを誤って処理したりすると、不注意な実装でも失敗する可能性があります。 

重要な観察は、ペアごとの検証以外に何も構築する必要がないということです。 各数字は、対称位置にある回転された対応する数字と一致する必要があります。 これにより、固定マッピングを使用してミラーリングされたペアをチェックする問題が軽減され、同時に先頭の数字の制約が両端に個別に適用されます。 

ブルート フォースは、変換された文字列を明示的に構築するため機能しますが、不必要な追加作業が行われます。 回転がローカルのペアごとのマッピングであるという観察により、中間文字列を構築せずに単一パスで構造を検証できます。

 ## アルゴリズムのチュートリアル

 回転マッピングで対称性をチェックすることで数値を検証します。 

### 1. 数値を文字列として読み取ります

 数値変換の問題を発生させずに個々の数字にアクセスできるように、これを文字列として保持します。 

### 2. 無効な数字がある場合は直ちに拒否します

 すべての文字が 0、1、6、8、または 9 のいずれかであることを保証します。その他の数字はローテーションに耐えられません。

### 3. 回転マッピングを定義する

 固定マッピング 0→0、1→1、8→8、6→9、9→6 を使用します。 これは、180 度回転したときに各桁がどのように変形するかを定義します。 

### 4. ミラーリングされた一貫性を確認する

 先頭からすべての位置 i について、s[i] を s[n−1−i] のマップされたバージョンと比較します。 いずれかのペアに矛盾がある場合、その番号はローテーション後に有効な状態を維持できません。 

### 5. 先頭桁の制約を強制する

 元の数値はゼロで始めることができないため、s[0] が「0」ではないことを確認します。 また、回転された数値が 0 で始まらないことも保証します。これは、s[n−1] が '0' になることがないことを意味します。 

### 6. すべてのチェックに合格した場合にのみ有効性を確認します

 すべてのミラーリングされたペアが一致し、両方の境界制約が成立する場合、その数値は有効です。 

### なぜ効果があるのか

 各桁の位置は、回転中のちょうど 1 つの反対の位置とペアになります。 マッピングは許可された数字セットに対して全単射であるため、すべてのミラーリングされたペアの一貫性により、回転された文字列全体が明確に定義され有効であることが保証されます。 境界チェックは、どちらの方向もゼロから始めることができないという外部制約を強制しますが、これはペアごとの対称性だけでは強制されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    allowed = set("01689")
    mp = {
        "0": "0",
        "1": "1",
        "8": "8",
        "6": "9",
        "9": "6"
    }

    n = len(s)

    if s[0] == "0":
        print("NO")
        return
    if s[-1] == "0":
        print("NO")
        return

    for ch in s:
        if ch not in allowed:
            print("NO")
            return

    for i in range(n):
        if mp[s[i]] != s[n - 1 - i]:
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```実装はアルゴリズムに直接に従います。 最初のチェックでは、無効な境界ケース、特にどちらの方向でも先頭にゼロが生成される数値を早期に削除します。 許可されたセットにより、不正な数字が変換に参加しないことが保証されます。 

ミラーリングされたループがコア ロジックです。 各インデックスは、回転マッピングを適用した後、対称の対応するインデックスと比較されます。 これにより、回転された文字列を明示的に構築することが回避され、一定の追加スペースの使用が保証されます。 

よくある間違いは、回転された先頭の数字が元の最後の数字に対応することを忘れることです。 そのため、検証前または検証中に両端を個別にチェックする必要があります。 

## 実用的な例

 ### 例 1:`801`対称性とマッピングについて説明します。 

| 私 | s[i] | s[n-1-i] | マップされた s[i] | チェック |
 | --- | --- | --- | --- | --- |
 | 0 | 8 | 1 | 8 | 8 == 1 はすでに失敗しています |

 最初の比較は、8 は 8 にマップされますが、反対の桁が 1 であり、対称性が崩れているため失敗します。 ただし、これは実際には微妙なケースです。正しい検証では不一致を早期に検出する必要がありますが、回転されたフォームは完全な一貫性が保たれる場合にのみ有効であることにも注意してください。 このサンプルでは、​​構造が一貫している限り、完全な回転ルールの下で対称性が機能するという解釈が意図されています。 ここで、不一致は直ちに無効を示します。 

このトレースは、アルゴリズムがそれ以上のスキャンを行わずに矛盾したペアリングをいかに迅速に拒否するかを示しています。 

### 例 2:`680`| 私 | s[i] | s[n-1-i] | マップされた s[i] | チェック |
 | --- | --- | --- | --- | --- |
 | 0 | 6 | 0 | 9 | 9 == 0 |

 最初の不一致はすでに有効性を破っています。 すべての数字が許可されている場合でも、回転時の構造の不一致により数字が無効になります。 

これは、有効な数字だけでは十分ではなく、構造的な対称性が必要であることを示しています。
