 ## 解決策
 ## 問題の理解

 各スロット マシンは確率的報酬ジェネレーターのように動作します。 マシンを 1 回プルすると、固定された有限セットから 1 つの値が返されます。各値は既知の確率を持ちます。 これらの確率は時間の経過とともに変化せず、すべてのプルは以前のプルとは独立しています。 

正確に実行することが許可されています$n$合計でプルを実行し、各プルをいずれかのプルに割り当てることができます。$k$機械。 これらを配布することが目標です$n$取得される報酬の予想合計を最大化する方法でマシン全体を引っ張ります。 

出力は 1 つの実数です。つまり、すべてを達成した後に予想される最大の合計報酬です。$n$決断。 

定式化に隠された重要な観察は、問題の中にプル間の相互作用を導入するものは何もないということです。 マシンは使用後に悪くなったり良くなったりすることはなく、次にどのマシンを使用しなければならないかという制約もありません。 

制約から、$n, k \le 100$、各分布には最大 1000 件の結果があります。 マシンごとに期待値を再計算するソリューションでも、十分に高速です。 唯一の本当の困難は、この構造により動的プログラミングや組み合わせ割り当ての必要性がなくなることを認識することです。 

最初の試みでよく見られる素朴な解釈は、プルを分散するにはすべての割り当てを検索する必要がある、つまり割り当てを意味すると考えることです。$n$間を引っ張る$k$機械。 それは次のことにつながります$\binom{n+k-1}{k-1}$可能性は、値が小さい場合でも急速に大きくなります。 

小さな例でこの罠を説明します。 

もし$n = 3$、$k = 2$、マシン A の期待値は 5 で、マシン B の期待値は 4 である場合、(2,1)、(1,2)、または (3,0) のような割り当ては総当たりビューで考慮する必要があります。 素朴なアプローチでは、分割が異なれば動作も異なると考えられるかもしれません。 実際には、プルごとの期待値のみが重要であるため、(3,0) が優勢です。 

2 番目の微妙なエッジ ケースは、分布が非整数であるか、著しく偏っている場合です。 たとえば、確率 0.01 で 100 を出力し、それ以外の場合は 0 を出力するマシンの期待値は 1 です。素朴な直感では、頻繁に小さな報酬が得られる方が良いかもしれませんが、期待値はすべてを 1 つのスカラーに崩壊させます。 

## アプローチ

 ブルートフォースアプローチでは、カウントの合計が以下になることを考慮して、各マシンに割り当てられているプルの数を列挙します。$n$。 割り当てごとに、カウントと各マシンの事前計算された期待値を乗算して期待値を計算します。 

期待値は線形であり、プルごとに独立しているため、そのアプローチの正しさは簡単です。 ただし、割り当ての数は指数関数的に増加します。$k$の組成を数えるのと同じなので、$n$の中へ$k$部品。 たとえ$n = 100$、この空間は天文学的に大きくなり、列挙が不可能になります。 

重要な簡素化は、どのマシンが選択されるかを除いて、すべてのプルが同一であることを認識することから生まれます。 期待は加算的で独立しているため、それぞれのプルを個別に処理できます。 これにより、問題は最大の期待値を持つマシンを選択し、それをすべてのマシンに使用することに集約されます。$n$引っ張ります。 

合計数を超えるプル間には収益逓減や共有制約がないため、割り当て構造は完全に消滅します。

 ## アルゴリズムのチュートリアル

 1. 各マシンについて、すべての結果を合計して期待値を計算します。$r_j \cdot p_j$。 これにより、期待値がプルごとの寄与を完全に特徴付けるため、各分布が単一のスカラーに圧縮されます。 
2. すべてのマシンの最大期待値を追跡します。 これは、1 回のプルごとに達成可能な最高の報酬を表します。 
3. この最大期待値に次の値を掛けます。$n$、それぞれの$n$プルは、以前の選択とは関係なく、最適なマシンに割り当てる必要があります。 

### なぜ効果があるのか

 各プルは独立して期待値全体に寄与し、合計の期待値は期待値の合計になります。 プル間の依存関係がなく、同じマシンの再利用にコストがかからないため、最適な戦略を多様化する必要はありません。 期待される最良のマシンを常に選択することから逸脱すると、他のマシンに影響を与えることなく、そのプルの寄与が厳密に減少します。 

不変条件は、1 回のプルに最適なマシンを決定した後、その決定を複数のプルに拡張しても確率構造が変わらないということです。 追加の各プルは、同じ最適化の選択の同一のコピーです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    
    best = 0.0

    for _ in range(k):
        m = int(input())
        r = list(map(int, input().split()))
        p = list(map(float, input().split()))
        
        exp = 0.0
        for rv, prob in zip(r, p):
            exp += rv * prob
        
        if exp > best:
            best = exp

    print(n * best)

if __name__ == "__main__":
    main()
```実装の中核は、各マシンを単一の期待値に削減することです。 報酬と確率のループは、分配構造が使用される唯一の場所です。 

よくある間違いは、プルをシミュレートしたり、残りの操作に対して DP を構築しようとしたりすることです。 状態は進化しないので、それは不要です。 もう 1 つの考えられる間違いは、浮動小数点の確率を間違って合計することです。 ここでは、それらの合計が 1 になることが保証されているため、正規化は必要ありません。

 | --- | --- | --- | --- | --- |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    n, k = map(int, sys.stdin.readline().split())
    best = 0.0

    for _ in range(k):
        m = int(sys.stdin.readline())
        r = list(map(int, sys.stdin.readline().split()))
        p = list(map(float, sys.stdin.readline().split()))
        exp = sum(x * y for x, y in zip(r, p))
        best = max(best, exp)

    return str(n * best)

# sample
assert run("3 2\n2\n10 0\n0.5 0.5\n1\n4\n1.0\n") == "15.0"

# all equal machines
assert run("2 2\n2\n1 2\n0.5 0.5\n2\n1 2\n0.5 0.5\n") == "3.0"

# single machine
assert run("4 1\n2\n3 0\n0.5 0.5\n") == "6.0"

# deterministic best
assert run("5 2\n1\n10\n1.0\n1\n1\n1.0\n") == "50.0"

 ## 特殊なケース

 まれな結果に注目すると、分布が大きく偏ったマシンは誤解を招く可能性があります。 たとえば、確率 0.001 で 1000 を出力し、それ以外の場合は 0 を出力するマシンでも、期待値は 1 のみです。 アルゴリズムは、比較する前にすべてを期待値に下げるため、これを正しく処理します。 

もう 1 つのエッジ ケースは、複数のマシンが同じ期待値を共有する場合です。 この場合、それらのどれもが最適であり、最大値のみが重要であり、その識別性は重要ではないため、アルゴリズムは依然として正しい結果を返します。 

最後に、いつ$n = 1$の場合、解はすべてのマシンの中で最良の単一の期待値を正確に返し、単一選択問題の直感的な解釈と一致します。
