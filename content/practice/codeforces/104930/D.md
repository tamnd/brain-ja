 ## 解決策
 ## 問題の理解

 常に数値 1 である開始点が与えられ、現在の値に任意の正の整数を繰り返し乗算することでシーケンスを構築できます。 これは、シーケンス内の次のすべての値が前の値の倍数でなければならず、毎回乗数を自由に選択できることを意味します。 

この構築ルールに加えて、N 個の異なる「お気に入り」番号の固定セットが存在します。 タスクは、これらのお気に入りの数字をできるだけ多く訪問する、1 から始まる有効な乗法チェーンを構築することです。 番号がシーケンス内のいずれかのステップで出現する場合、その番号は「訪問済み」とみなされます。 

したがって、問題は、シーケンスが 1 から始まり、次のすべての要素が前の要素の倍数になるように、指定された数値のサブセットの順序を選択することに帰着します。 このようなすべての有効なチェーンの中で、指定された N 個の数値がいくつ出現するかを最大化したいと考えます。 

最大 10^18 の値を持つ N ≤ 1000 という制約は、任意の O(N²) 解が許容されることを示唆していますが、三次挙動やペアごとの因数分解の繰り返しを含むものはすべて合格する可能性が高くなりますが、割り算チェックの効率に注意する必要があります。 

微妙な点は、数字 1 が常にシーケンスの開始要素として存在しますが、お気に入りのセットの一部である場合とそうでない場合があるということです。 入力に ​​1 が存在する場合、それは答えに寄与するはずです。 それ以外の場合、それは構造的なルートとして機能するだけであり、スコアには追加されません。 

単純な間違いは、シーケンスが何らかの任意の方法で厳密に増加しているに違いないと仮定したり、次に小さい倍数を貪欲に選択しようとしたりすることです。 たとえば、セットが次の場合、`{2, 3, 4, 6}`、貪欲に選択すると時間がかかるかもしれません`2 → 4`そして恋しい`3 → 6`ですが、最適なチェーンは`1 → 3 → 6`、より多くのお気に入りを実現します。 順序付けの制約は、大きさではなく、割り切れることです。 

もう 1 つの失敗例は、推移的な構造を無視したことに起因します。 たとえば、`{2, 4, 8, 16}`、正しいチェーンは 4 つの要素すべてですが、到達可能な最大の倍数に早すぎる単純な貪欲さにより、中間の包含がブロックされる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、サブセットの可能な順序をすべて試して、それが有効な乗法チェーンを形成するかどうかを確認します。 順列ごとに、各要素が次の要素を分割するかどうかを検証します。 N が存在するため、これはすぐに実行不可能になります。 順列、およびサブセットに制限した場合でも、指数関数的な増加につながります。 N = 1000 では、これは完全に不可能です。 

重要な観察は、シーケンス制約が純粋にローカルであるということです。各遷移は、ある数値が別の数値を除算するかどうかのみに依存します。 これにより、問題は、a が b を割る場合に a から b にエッジを引く、有向非巡回グラフ内の最長のチェーンを見つけることに変わります。 割り切れるということは a ≤ b を意味するため、値による並べ替えでは前方遷移のみを考慮すればよいことが保証されます。 

ソートが完了すると、問題は N 個のノードを持つ DAG における最長パス問題になり、エッジは可分性を表します。 並べ替えられた値に対する標準的な動的プログラミング アプローチでは、O(N²) 時間で最適なソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N!・N) | O(N) | 遅すぎる |
 | 可分性グラフ上の最適な DP | O(N²) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### アルゴリズムのチュートリアル

 1. 与えられたすべての数値を昇順に並べ替えます。 

これにより、ある数値が別の数値を除算するかどうかをチェックするたびに、配列内でのみ前に進み、非循環性が維持されます。 
2. 辞書を作成するか、どの番号が「お気に入り」であるかをマークします。 

これにより、値がスコアに寄与しているかどうかを定期的にチェックできます。 
3. DP 配列を初期化します。ここで、dp[i] は、i 番目の番号で終わる有効なチェーン内のお気に入りの番号の最大数を表します。 

各数字は潜在的にチェーンの終端となる可能性があります。 
4. 入力セットに 1 が含まれるかどうかに応じて、数値 1 の初期仮想状態を値 0 または 1 に設定します。 

すべてのチェーンは 1 から始まるため、これは普遍的な開始点として機能します。 
5. ソートされた順序で各数値 i について、a[j] が a[i] を除算するように、以前のすべての数値 j < i を拡張しようとします。 

有効な場合、 dp[i] = max(dp[i], dp[j] + (a[i] がお気に入りの場合は 1、それ以外の場合は 0)) を更新します。 

この遷移は、j で終わる最適なチェーンを拡張するというアイデアを捉えています。 
6. すべての数値を処理した後の答えは、dp の最大値になります。 

### なぜ効果があるのか

 DP は、dp[i] が a[i] で正確に終了する有効な乗算チェーンの最良のスコアを格納するという不変式を維持します。 すべての遷移は可分性を尊重し、ソートにより後方エッジが存在しないことが保証されるため、すべての有効なチェーンは DP 遷移のシーケンスを通じて 1 回だけ構築されます。 有効なチェーンは以前の DP 状態に対応するプレフィックスに分解でき、最適な部分構造が保証されるため、最適なチェーンが失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))

    a.sort()
    st = set(a)

    dp = [0] * n

    # handle start at 1
    start_gain = 1 if 1 in st else 0

    for i in range(n):
        if a[i] == 1:
            dp[i] = 1
        else:
            dp[i] = 0

        # transition from all previous states
        for j in range(i):
            if a[i] % a[j] == 0:
                gain = 1 if a[i] in st else 0
                dp[i] = max(dp[i], dp[j] + gain)

        # ensure start from 1 if 1 is not explicitly used
        if 1 not in st:
            dp[i] = max(dp[i], start_gain + (1 if a[i] in st else 0))

    print(max(dp))

if __name__ == "__main__":
    solve()
```コア構造は DP 定義の直接実装です。 二重ループでは、考えられるすべての以前の約数のチェックが強制されます。 セットを使用すると、メンバーシップの定数チェックが可能になりますが、この問題では、指定された値に対して反復処理を行うだけであるため、ほとんど冗長になります。 

微妙な点の 1 つは、開始値 1 の処理です。入力に 1 が存在する場合、適切な DP チェーンの開始点が初期化されます。 そうでない場合でも、概念的にはスコアに追加せずに 1 から開始します。 

## 実用的な例

 ### 例 1

 入力:```
4
2 6 10 12
```ソートされた配列は`[2, 6, 10, 12]`。 

| 私 | a[i] | 最高の前任者 | dp[i] |
 | --- | --- | --- | --- |
 | 0 | 2 | 開始(1) | 1 |
 | 1 | 6 | 2 | 2 |
 | 2 | 10 | 2 | 2 |
 | 3 | 12 | 6 | 3 |

 最適を達成するチェーンは`1 → 2 → 6 → 12`, しかし、本命のみがカウントされるため、本命番号は2、6、12の3つとなります。 

これは、DP が単一の貪欲なパスにコミットするのではなく、さまざまなブランチを正しく選択する方法を示しています。 

### 例 2

 入力:```
4
3 4 8 16
```ソートされた配列は`[3, 4, 8, 16]`。 

| 私 | a[i] | 最高の前任者 | dp[i] |
 | --- | --- | --- | --- |
 | 0 | 3 | 開始(1) | 1 |
 | 1 | 4 | 1 | 1 |
 | 2 | 8 | 4 | 2 |
 | 3 | 16 | 8 | 3 |

 ここで最適なチェーンは`1 → 4 → 8 → 16`、きれいな可分性ラダーを示しています。 

2 番目の例は、16 には 4 から到達できますが、8 を経由しなければ到達できないため、中間の約数をスキップすると最適性が失われることを強調しています。

 ## 特殊なケース

 重要なエッジケースは、入力に 1 が存在しない場合です。 アルゴリズムは引き続きそれを有効な開始アンカーとして扱います。 たとえば、次の入力を使用します。```
3
2 3 6
```DP は暗黙の 1 から始まり、2 と 3 への遷移を独立して許可します。 2 からは 6 に到達し、最適なチェーン長として 2 つのお気に入り (2 と 6) が生成されます。DP は両方のブランチを正しく評価します。 

もう 1 つの特殊なケースは、数字が複数の重複するチェーンを形成する場合です。 例えば：```
4
2 4 8 16
```各数値は、以前のすべての小さい 2 のべき乗で割り切れます。 DP は、複数の先行チェーンが存在する場合でも、蓄積された最良のチェーンが常に前方に伝播されることを保証し、時期尚早に選択されたサブチェーンではなく完全な包含を実現します。
