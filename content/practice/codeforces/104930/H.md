 ## 解決策
 ## 問題の理解

 長さのシーケンスを数えるように求められます$N$ここで、各ポジションには、13 の金種の固定順序セットから選択された「ランク」が含まれています。エースが最も小さく、次に 2 からキングまでが続きます。 

シーケンスの制約は特殊です。左から右に移動するにつれて、次の各カードは前のカードと比較してランクが厳密に増加するか、前の値に関係なくエースになるかのどちらかでなければなりません。 したがって、シーケンスはほとんど増加していますが、エースは制限なくどこにでも表示できる特別なリセットシンボルのように動作します。 

2 つのシーケンスは、少なくとも 1 つの位置のランクが異なる場合にのみ異なるとみなされます。そのため、これは純粋にランク文字列に関するカウントの問題です。 

キーの制限はローカルです。各位置は前のカードにのみ依存します。 これは、ポジションと最後に確認されたランクに関する動的プログラミングの定式化を直ちに示唆します。 

以来$N \le 20$、位置ごとに 13 または 14 の状態の指数は問題ありません。 実際の制約は概念的なものであり、計算上のものではありません。 

シーケンスで Ace が繰り返し使用される場合、微妙なエッジケースが発生します。 たとえば、$N=3$、次のようなシーケンス$A, A, A$どこにも「増加」していなくても、有効です。 時折のリセットを除いて厳格な成長を強制する単純な解釈では、A の繰り返しが誤って禁止されたり、A に関係するトランジションが誤って処理されたりする可能性があります。 

もう 1 つの微妙なケースは、Ace を最小値とワイルドカードの両方として扱うことです。 ルールは非対称です。キングの後であっても、エースは常に次の要素として許可されます。 代わりに、厳密な順序でエースをランク 1 としてモデル化した場合でも、キングからエースへの移行は許可されなければなりません。これは、個別に処理しない場合、標準の増加シーケンス DP を破ります。 

## アプローチ

 ブルートフォース手法では、考えられる長さのすべてのシーケンスが生成されます。$N$13 ランク以上のランクについて、それぞれがルールを満たすかどうかを確認し、有効なものをカウントします。 それは与える$13^N$シーケンス。 のために$N = 20$、これについてです$10^{22}$、これは剪定を行っても完全に実行不可能です。 

制約の構造は、最後に選択されたランクに基づいた動的プログラミング状態を示唆します。 重要な観察は、有効性は前のカードと、現在のカードがエースであるか、またはそれより厳密に大きいかどうかにのみ依存するということです。 このローカルな依存性は、履歴全体を覚えていなくてもシーケンスを段階的に構築できることを意味します。 

ポジションと最後のランクに対する DP を定義します。ここで、遷移では許可されるすべての次のランクが考慮されます。 最下位の状態から$x$、どのランクにでも行くことができます$y > x$、またはエースに関係なく$x$。 これにより、Ace がすべての状態から接続するグローバル リセットのように動作することを除いて、状態全体に有向非循環構造が作成されます。 

この最適化は、「より大きなランク」への遷移はプレフィックスの合計を使用して集計できる一方、Ace 遷移はすべての状態からの均一な追加に寄与するという認識から生まれています。

 | ブルートフォース |$O(13^N \cdot N)$|$O(N)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 ランクは 0 ～ 12 の整数として扱われます。0 はエースを表し、12 はキングを表します。 

1. DP 配列を初期化する`dp[r]`ランクで終わる現在の長さのシーケンスの数を意味します`r`。 長さ 1 の場合、すべてのランクは同様に有効であるため、各状態は値 1 から始まります。 
2. 次の位置ごとに、新しい DP 配列を計算します。`ndp`。 考えられるすべての現在のランクについて`r`、そこに移行できる方法が何通りあるかを計算したいと考えています。 
3. ランク移行について`r`、以前のすべての状態を合計します`dp[x]`どこで`x < r`(厳密な増加条件) または`r`エースです。 エースはいつでも選べるので、`dp[x]`エース状態に貢献。 
4. 「すべての x < r の合計」を効率的に計算するために、プレフィックスの合計を維持します。`dp`。 これにより、状態ごとの一定時間で厳密に増加する遷移の寄与を得ることができます。 
5. 特に Ace については、すべての合計の合計として個別に計算します。`dp`なぜなら、以前のどのランクからでもエースを配置できるからです。 
6. すべてのランクを処理した後、置き換えます`dp`と`ndp`までのすべての位置に対して繰り返します$N$。 
7. 最終的な答えは、次のすべての値の合計です。`dp`加工後$N$ポジション。 

### なぜ効果があるのか

 すべてのステップで、DP 状態は最後のランクのみを記憶することによって、指定された長さのすべての有効なシーケンスを完全に要約します。 移行ルールは、その最後のランクと、次のカードがエース以上であるかどうかにのみ依存します。 すべての有効な拡張子は、プレフィックス遷移またはグローバル Ace 遷移を通じて 1 回だけカウントされるため、シーケンスが欠落したり二重にカウントされたりすることはありません。 プレフィックス合計構造により、重複を再計算することなく、「厳密に増加する」制約が正確に適用されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input().strip())
    
    # dp[r] = number of sequences ending in rank r
    # 0 = Ace, 1..12 = 2..King
    dp = [1] * 13
    
    for _ in range(n - 1):
        total = sum(dp) % MOD
        
        # prefix sums for strict increases
        pref = [0] * 14
        for i in range(13):
            pref[i + 1] = (pref[i] + dp[i]) % MOD
        
        ndp = [0] * 13
        
        for r in range(13):
            if r == 0:
                # Ace can be placed after anything
                ndp[r] = total
            else:
                # sum of all x < r
                ndp[r] = pref[r] % MOD
        
        dp = ndp
    
    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```実装は上記の DP に従います。 プレフィックス配列`pref`は、現在のランクより小さい以前のすべてのランクの合計を迅速に計算するために使用され、厳密に増加する条件を強制します。 Ace は順序制約を無視するため、Ace 状態は以前のすべての状態の合計を使用して個別に処理されます。 

正確に繰り返します$N-1$最初の位置が直接初期化されるため、遷移します。 

特に計算する場合、モジュロ演算には注意が必要です。`total`中間合計は、減らさないと整数の制限を超える可能性があるためです。 

## 実用的な例

 ### 例 1

 入力:```
2
```すべての dp 状態を 1 として開始します。 

| ステップ | dp (エース..キング) | 合計 | NDP(エース) | ndp(2..キング) |
 | --- | --- | --- | --- | --- |
 | 初期化 | 13 個 | - | - | - |
 | 1ステップ後 | 計算された | 13 | 13 | プレフィックスベース |

 ランク 2 (インデックス 1) の場合、Ace からのみ取得できるため、値は 1 になります。Ace の場合、13 州すべてから取得でき、13 になります。有効な末尾を合計すると 91 になります。 

これは、短いシーケンスであっても、Ace がリセットとして機能する組み合わせがすでに多く含まれていることを確認します。 

### 例 2

 入力:```
3
```DP はさらに拡張されます。 

| ステップ | dp合計 |
 | --- | --- |
 | 最初の遷移後 | 91 |

 2 番目の遷移は重要な動作を示しています。つまり、より高いランクで終了するシーケンスはより小さなランクからのみ蓄積されますが、Ace は完全な状態の遷移を継続的に注入します。 

これは、Ace が世界的なコネクターとして機能することで、どのように組み合わせの成長を支配しているかを示しています。

 ## 特殊なケース

 のために$N = 1$の場合、すべての単一ランクは 1 要素シーケンスとして有効であるため、答えは正確に 13 になる必要があります。 DP はすべて 1 から始まるため、最終的な合計は 13 のままで、遷移が関与しないというルールと一致します。 

エースが支配するシーケンスの場合、次のようになります。$A, A, A, \dots$、アルゴリズムは、常に前の状態の合計を使用する Ace 遷移を通じてそれらをカウントします。 たとえば、各ステップで、Ace は考えられるすべての終了状態から寄与を受け取るため、繰り返される Ace シーケンスが見逃されることはなく、グローバル合計の一部として正しく蓄積されます。 

Ace のない厳密な増加シーケンスの場合、たとえば$2, 5, 9$、プレフィックス合計メカニズムにより、有効なパスごとに 1 回だけカウントされることが保証されます。 各拡張機能はランクの小さい状態のみを使用するため、無効な後方遷移は導入されません。
