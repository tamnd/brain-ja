 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$N \times M$各セルにバイナリ値が含まれるグリッド。 値 1 はタイルが現在反転されていることを意味し、0 はすでに正しいことを意味します。 許可される唯一の操作はセルの選択です$(R, C)$次に、サブ四角形内のすべてのセルを左上隅から切り替えます。$(1,1)$に$(R,C)$。 このような各操作では、そのプレフィックス四角形内のすべてのビットが反転されます。 

タスクは、グリッド全体がすべてゼロになるように必要な、このようなプレフィックスと長方形の反転の最小数を決定することです。 

重要な構造上の詳細は、すべての操作が左上隅に固定された単調領域に影響を与えるということです。 これは、前の行と列のセルが後で起こることに影響を与えることを直ちに意味します。$(R,C)$すべてのポジションに影響を与える$(i,j)$と$i \le R$そして$j \le C$。 

とすれば$N, M \le 3000$、グリッドには最大 900 万個のセルを含めることができます。 グリッド上で各操作を明示的にシミュレートしようとするソリューションは、非常に遅すぎます。 平$O(N^2 M^2)$不可能ですし、$O(NM \min(N,M))$直線的でない限り、慎重に避ける必要があります。 

素朴だが自然なアイデアは、グリッドを繰り返しスキャンして 1 を見つけ、それを修正する反転を適用して続行することです。 これは、単一のフリップによって大きなプレフィックス領域が変更され、多くのセルの再計算が強制されるため、失敗します。 慎重に実装しても最悪の場合立体的になってしまいます。 

ローカル貪欲性が行ごと、または列ごとに独立して機能すると仮定すると、微妙な落とし穴が発生します。 たとえば、右下隅の反転がほぼすべてに影響を与えるグリッドを考えてみましょう。 以前の操作で累積されたパリティを考慮せずに行単位で処理すると、セルが固定されていないにもかかわらず、すでに固定されていると誤って想定してしまう可能性があります。 

主な問題点は、各セルが選択されたすべての操作の影響を受けることです。$(R,C)$両方の次元でそれを支配します。 これにより、2D パリティの累積問題が発生します。 

## アプローチ

 ブルートフォース戦略は、現在 1 であるセルを繰り返し見つけて、そのセルの座標で反転を適用することです。 反転するたびに接頭辞の四角形が切り替わるので、各操作の後に多くのセルの状態を再計算するか、完全な差分構造を維持する必要があります。 

最悪の場合、各操作に影響を及ぼす可能性があります。$\Theta(NM)$細胞、そして私たちは実行するかもしれません$\Theta(NM)$オペレーション、それにつながる$\Theta(N^2 M^2)$まったく実行不可能な仕事。 

重要な洞察は、「セルの修復」という観点から考えるのをやめ、代わりに「操作の貢献」という観点から考えることです。 それぞれの操作は、$(R,C)$プレフィックス四角形内のすべてのセルにバイナリ トグルを提供します。 つまり、それぞれの細胞が$(i,j)$すべての操作によって正確に反転されます$R \ge i$そして$C \ge j$。 

これは、次の時点での最終値を意味します。$(i,j)$は、南東部地域で選択された作戦の同等性にのみ依存します。 グリッドを右下から左上に処理すると、各セルで操作が必要かどうかを貪欲に決定できます。$(i,j)$、より大きなインデックスからの寄与がすべて修正されたら、次の時点で反転する必要があるかどうかを判断できます。$(i,j)$現在値を修正します。 

これにより、問題は、逆の順序でスイープし、各位置に影響を与えるフリップの数を追跡する 2D パリティ構造の維持に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(N^2 M^2)$|$O(NM)$| 遅すぎる |
 | 最適 |$O(NM)$|$O(NM)$| 承認済み |

 ## アルゴリズムのチュートリアル

 選択した各操作をプレフィックスの四角形を切り替えるものとして扱いますが、前方にシミュレーションする代わりに、答えを後方に再構築します。 

1. 2D 配列を作成する`grid`初期値を保存します。 
2. 2D 配列を作成する`flip`0 に初期化され、処理中に各セルに間接的に影響を与える操作の数のパリティを追跡します。 
3. グリッドを右下から左上に移動します。つまり、行インデックスが減少し、各行内の列インデックスが減少します。 
4. 各セルで$(i,j)$、現在の実効値を次のように計算します。$$current = grid[i][j] \oplus flip[i][j]$$これは、以前に決定されたすべての操作の後にセルが現在反転されているかどうかを表します。 
5. もし`current == 1`で操作を実行する必要があります。$(i,j)$なぜなら、これが今後このセルとそれに依存するすべてのセルに影響を与える唯一の残りの方法だからです。 答えをインクリメントします。 
6. で演算を適用すると、$(i,j)$、その効果をすべてのセルに反映する必要があります$(x,y)$と$x \le i$そして$y \le j$。 すべてを直接更新する代わりに、2D 差分スタイルのパリティ更新を使用して、将来アクセスされるセルがその影響を正しく認識できるようにします。 
7. すべてのセルが処理されるまで続行します。 選択した操作の累積数が答えになります。 

重要な考え方は、逆の順序で処理することで、決定時に$(i,j)$、すべてのセル$(x,y)$と$x > i$または$y > j$すでに最終決定されているため、今後の運用に影響はありません。 

### なぜ効果があるのか

 アルゴリズムは、私たちがその位置にいるときの不変条件を維持します。$(i,j)$、値`flip`リージョン内で選択されたすべての操作からのパリティ寄与を正しく表します$(x,y)$と$x > i$または$y > j$。 でのすべての操作以来、$(R,C)$両方の次元でインデックスが等しいかそれ以下のセルにのみ影響を与えるため、降順で処理すると、将来の決定によって、すでに処理されたセルの正確さが遡って変更されることがなくなります。 

したがって、既知の反転をすべて考慮した後で 1 であるセルを見つけるたびに、その正確な位置での演算を選択する必要があります。 別の配置を行っても、すでに固定されている位置に影響を与えずに修正することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    # 2D difference array for parity
    diff = [[0] * (m + 2) for _ in range(n + 2)]

    def get(i, j):
        return diff[i][j]

    # prefix XOR reconstruction on the fly
    for i in range(n - 1, -1, -1):
        row_acc = 0
        for j in range(m - 1, -1, -1):
            row_acc ^= diff[i][j]
            diff[i][j] = row_acc ^ diff[i + 1][j] ^ diff[i + 1][j + 1] ^ diff[i][j + 1]

    # We rebuild a cleaner model: use BIT-like sweep
    # Simpler and correct greedy reconstruction:

    bit = [[0] * (m + 2) for _ in range(n + 2)]

    def add(i, j):
        for x in range(i, 0, - (x & -x)):
            for y in range(j, 0, - (y & -y)):
                bit[x][y] ^= 1

    def query(i, j):
        res = 0
        x = i
        while x > 0:
            y = j
            while y > 0:
                res ^= bit[x][y]
                y -= y & -y
            x -= x & -x
        return res

    ans = 0

    for i in range(n - 1, -1, -1):
        for j in range(m - 1, -1, -1):
            cur = grid[i][j] ^ query(i + 1, j + 1)
            if cur == 1:
                ans += 1
                add(i + 1, j + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、2D パリティ上のフェンウィック ツリー (XOR 経由で実装) を使用して、選択された操作の数が各プレフィックスに影響を与えるかを維持します。 クエリは、セルに影響を与えるフリップの数を返します。また、将来の操作がすでに処理された決定を妨げないように、常に辞書編集上の逆順でセルを評価します。 

各操作は状態をインクリメントするのではなく切り替えるため、XOR の使用は不可欠です。 Fenwick 構造により、各更新とクエリが確実に実行されます。$O(\log N \log M)$、全体的な複雑さを管理しやすく保ちます。 

実装の微妙な詳細は、off-by-one インデックス付けです。フェンウィック ツリーは 1 ベースなので、クエリまたは更新時にインデックスを常に +1 シフトします。

 ## 特殊なケース

 完全にゼロのグリッドは、計算されたすべての実効値がゼロであるため、アルゴリズムの下では安定しており、操作はトリガーされません。 走査はすべてのセルを訪問しますが、更新はアクティブ化されません。 

完全に 1 で埋められたグリッドは、以前の反転が存在しない場合、最初に訪問したセルで逆の順序で処理されます。 このアルゴリズムは右下隅で 1 つの操作をトリガーし、中間推論では残りのすべての操作を修正しているとみなしますが、この操作は概念モデルのグリッド全体に伝播します。 

単一セルのグリッドは基本不変量を直接表示します。 セルが 1 の場合、1 つの操作が強制されます。 0 の場合は何も必要ありません。 このアルゴリズムは、境界の複雑さなしにきれいに削減され、インデックス作成のシフトが正確であることを確認します。
