 ## 解決策
 ## 問題の理解

 各テスト ケースが独立した、小さな整数の配列が与えられます。 その配列から、配列全体を取得することはできないことを除いて、考えられる要素のすべてのサブセットを考慮します。 空のサブセットはまだサブセットであり、「フルセットではない」条件に違反しないため、許可されます。 

選択したサブセットに対して$S$では、サブセットのサイズとその要素の 3 乗の合計という 2 つの部分から形成される値を計算します。 サブセットのサイズが乗算され、符号はサイズが奇数か偶数かによって異なります。 具体的には、偶数サイズのサブセットはプラスに寄与し、奇数サイズのサブセットはマイナスに寄与し、すべてはサブセット サイズ自体によってスケールされます。 

タスクは、すべての有効なサブセットに対してこの式を評価し、テスト ケースごとの最小値と最大値を報告することです。 

重要な制約は、$N \le 15$。 これは重要なシグナルです。ただし、サブセットの数は$2^N$、せいぜい$2^{15} = 32768$したがって、テスト ケースごとにすべてのサブセットを列挙することが可能です。 最大 1000 のテスト ケースであっても、各サブセットを一定または非常に短い償却時間で処理するソリューションは許容されます。 受け入れられなくなるのは、サブセットごとにサブセットの合計を最初から再計算するアプローチです。これにより、追加の要素が導入されます。$N$、複雑さが 5 億回のオペレーションに向かって押し上げられています。 

エッジケースは主にサブセット選択ルールと符号の動作に関係します。 

よくある間違いは、「厳密なサブセット」という文言のために空のサブセットが許可されていないと考えることです。 これを除外すると、値 0 の有効な候補が失われるため、他のすべての値が厳密に正または負の場合、最小値または最大値に影響を与える可能性があります。 

もう 1 つの微妙なケースは、完全なサブセットの除外です。 誤ってこれを含めると、サブセット サイズ乗数と立方体合計の両方が最大になるため、その寄与が支配的になる可能性があります。 

たとえば、次の場合$A = [1, 1, 1]$の場合、完全なサブセットは次のようになります。$3 \cdot (-1)^3 \cdot 3 = -9$、考慮すべきではないにもかかわらず、誤って最小値になる可能性があります。 

## アプローチ

 最も直接的なアプローチは、ビットマスクを使用してすべてのサブセットを反復処理することです。 各サブセットについて、そのサイズと含まれる要素の立方体の合計を計算し、式を評価します。 これは定義に明示的に従っているため、これは正しいです。 問題は、サブセットの合計を繰り返し計算する際の効率です。 

各サブセットの立方体合計を最初から再計算する場合、サブセットごとに最大 15 個の要素をスキャンします。 それはおおよそ次のことにつながります$2^N \cdot N$これは、テスト ケースごとに約 500,000 回の操作があり、すべてのテスト全体で最悪の場合は最大 5 億回の操作になります。 Python では遅すぎます。 

この改善は、サブセットが自然な DP 構造を形成していることを認識することで実現します。 サブセットをビットマスクとして表すと、各サブセットの 3 乗和を増分的に計算できます。 サブセットは、より小さなサブセットと 1 つの新しく追加された要素に分解できます。 これにより、すべてのサブセットの合計を計算できるようになります。$O(2^N)$要素を再スキャンしない場合のテスト ケースあたりの時間。 

サブセットの合計を効率的に取得したら、各サブセットの式の評価は定数時間で行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (サブセットごとの再スキャン) |$O(2^N \cdot N)$|$O(1)$| 遅すぎる |
 | サブセット合計に対するビットマスク DP |$O(2^N)$|$O(2^N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1.各要素を変換する$A_i$その立方体値に$A_i^3$。 これにより、べき乗を繰り返し再計算することが回避され、演算が整数に対してローカルに保たれます。 
2. ビットマスク DP を使用して、立方体のサブセット合計を事前計算します。 各マスクについて、その最下位設定ビットを分離し、マスクをより小さなマスクに 1 つの要素を加えたものとして表現します。 これにより、既に計算された結果に基づいて、各サブセットの合計が 1 回計算されることが保証されます。 
3. マスクごとに、$0$に$2^N - 1$、サブセットのサイズを計算し、式を評価します。$|S| \cdot (-1)^{|S|} \cdot \text{sum}(S)$。 
4. マスク全体をスキップする$(1 << N) - 1$、問題により配列全体の使用が禁止されているためです。 
5. すべての有効なサブセットにわたるグローバル最小値と最大値を追跡します。 

重要な設計上の選択は、再計算ではなく DP を介してサブセットの合計を計算することです。 これがなければ、たとえ解決策が制限時間を超えてしまうことになります。$N$小さいです。 

### なぜ効果があるのか

 すべてのサブセットは 1 つのビットマスクに正確に対応し、すべてのビットマスクは 1 つの設定ビットを削除することで削減できます。 DP は、サブセットを計算するときに、それが依存するより小さいサブセットがすでにわかっていることを保証します。 これにより、ビット数によるマスクの厳密な順序付けが作成され、再計算や状態の欠落がないことが保証されます。 式はサブセットのサイズと合計にのみ依存し、両方ともマスクごとに完全に決定されるため、各マスクを個別に評価するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        N = int(input())
        A = list(map(int, input().split()))
        
        nmask = 1 << N
        cube = [x * x * x for x in A]
        
        # subset sum DP over bitmasks
        sub_sum = [0] * nmask
        
        for mask in range(1, nmask):
            lsb = mask & -mask
            idx = (lsb.bit_length() - 1)
            sub_sum[mask] = sub_sum[mask ^ lsb] + cube[idx]
        
        full_mask = nmask - 1
        
        mn = float('inf')
        mx = float('-inf')
        
        for mask in range(nmask):
            if mask == full_mask:
                continue
            
            k = mask.bit_count()
            val = k * sub_sum[mask]
            if k % 2 == 1:
                val = -val
            
            if val < mn:
                mn = val
            if val > mx:
                mx = val
        
        print(mn, mx)

if __name__ == "__main__":
    solve()
```キューブの前処理ではべき乗が分離されるため、サブセットの評価は純粋に加算的になります。 DP ステップは、設定された最下位ビットを削除すると、常に処理済みのマスクが厳密に小さくなるというアイデンティティを使用します。 ビットインデックス抽出による`lsb.bit_length() - 1`分離されたビットを配列インデックスに安全に変換します。 

評価中に、サブセット サイズは次のように取得されます。`bit_count()`、小規模な場合に効率的です$N$。 演算子の優先順位による間違いを避けるために、乗算の後に符号反転が適用されます。 

## 実用的な例

 ### 例 1

 小さな配列を考えてみましょう$A = [1, -1, 2]$。 フルセットを除くすべてのサブセットを評価します。 

| マスク | サブセット | サイズ k | 立方体の和 | 式 |
 | --- | --- | --- | --- | --- |
 | 000 | {} | 0 | 0 | 0 |
 | 001 | {1} | 1 | 1 | -1 |
 | 010 | {-1} | 1 | -1 | 1 |
 | 100 | {2} | 1 | 8 | -8 |
 | 011 | {1,-1} | 2 | 0 | 0 |
 | 101 | {1,2} | 2 | 9 | 18 |
 | 110 | {-1,2} | 2 | 7 | 14 |

 フルセット111は除きます。 

最小値は -8、最大値は 18 です。 

このトレースは、偶数のサブセットが符号を維持しながら奇数のサブセットが符号を反転する様子と、サブセット サイズによるスケーリングによって差がどのように増幅されるかを示します。 

### 例 2

 テイク$A = [-2, -2]$。 

| マスク | サブセット | サイズ k | 立方体の和 | 式 |
 | --- | --- | --- | --- | --- |
 | 00 | {} | 0 | 0 | 0 |
 | 01 | {-2} | 1 | -8 | 8 |
 | 10 | {-2} | 1 | -8 | 8 |

 フルセット11は対象外となります。 

どちらの単一要素サブセットも同じ値を生成し、空のサブセットは最小値を 0 に固定します。 

これは、すべての要素が同一である場合、サブセットの対称性によって出力の範囲が崩れることを示しています。

 ## 特殊なケース

 空のサブセットは、概念的な主要なエッジ ケースです。 のような入力の場合$[5]$、許可されるサブセットは空のみであり、単一要素のサブセットは完全な配列と等しいため許可されません。 このアルゴリズムは空のマスクのみを評価し、値 0 を正しく生成します。 

完全なサブセットの除外も重要な条件です。 のために$A = [2, 2]$、両方の要素を含むサブセットは次のようになります。$2 \cdot (+1) \cdot (16 + 16) = 64$、しかしそれは決して考慮されません。 ループはこのマスクを明示的にスキップし、代わりに単一要素のサブセットから最大値が得られるようにします。 

すべての要素が負の場合、立方体は負の値を保持しますが、サブセット サイズからの交互の符号により非直感的な反転が作成されます。 DP は単調性を決して仮定せず、計算された合計から独立して各サブセットを評価するため、これを引き続き正しく処理します。
