 ## 解決策
 ## 問題の理解

 11 個の単語の固定シーケンスが与えられ、各単語はゲームのチート コードでボタンの押下を表します。 これとは別に、既知の参照シーケンスである Konami コードがあり、これも 11 入力の長さです。 

タスクは、指定されたシーケンスがコナミ コードと正確に一致するかどうかを確認することではなく、それらを位置ごとに比較し、一致する位置の数をカウントすることです。 入力内のそのインデックスの文字列がコナミ コード内の対応する文字列と同一である場合、その位置はスコアに寄与します。 

入力サイズは一定です。ちょうど 11 個の文字列で、それぞれの長さは 100 までです。これは、データの総量が非常に小さいことを意味します。 ここでは、大きな定数を使用する O(1) から O(n) までのアルゴリズムはどれも簡単に高速ですが、その構造は、前処理や複雑なデータ構造を使用せずに直接比較に焦点を当てる必要があることを示唆しています。 

エッジケースは主に文字列の等価性動作に関するものです。 比較では大文字と小文字が区別され、正確に比較されるため、余分な文字や異なる単語などの小さな違いも不一致としてカウントされます。 

明示的に注意する価値がある微妙なケースは、すべての文字列が一致する場合 (11 を返す必要があり、どの文字列も一致しない場合は 0 を返す必要があります) です。もう 1 つは、少数の位置のみが一致する部分的な重複であり、セットベースの等価性ではなく、インデックスごとの等価性を確実にカウントする必要があります。 セットの比較または並べ替えを使用すると、位置情報が破壊され、不正確な結果が得られます。 

## アプローチ

 強引な解釈では、各入力文字列をコナミ コードの各位置と比較することになりますが、構造がすでに位置を 1 対 1 に揃えているため、これは不要です。 ネストされたループとして記述したとしても、実行されるのは最大でも 11 × 11 の比較だけであり、無視できる程度です。 

重要な観察は、問題が整列された配列の単一パスに帰着するということです。インデックス i で、input[i] と target[i] を比較し、それらが一致する場合にカウンターをインクリメントします。 位置間の依存関係はなく、ハッシュ化やデータの変換も必要ありません。 

直接比較で十分であるため、総当たりのアイデアは機能しますが、各入力位置には対応するターゲット位置が 1 つだけ存在するため、概念的には冗長です。 最適なソリューションでは、すべてが 1 つのリニア スキャンにまとめられます。

 ## アルゴリズムのチュートリアル

 ### コナミリファレンスシーケンス

 参照コードを固定配列として扱います。`["up","up","down","down","left","right","left","right","b","a","start"]`### ステップ

 1. 11 個の入力文字列を配列に読み取ります。`s`。 

これにより、位置構造が保持されます。一致はインデックスの位置合わせに依存するため、これは不可欠です。 
2. 参照配列を定義する`t`コナミコードシーケンスとして。 

これにより、比較中に参照を再計算または再解析する必要がなくなります。 
3. カウンタの初期化`score = 0`。 

この変数は、一致する位置の数を累積します。 
4. インデックスを反復処理する`i`0から10まで。 

各インデックスは、チート コード シーケンス内の固定ボタンの位置を表します。 
5. 各インデックスについて`i`、 比較する`s[i]`と`t[i]`。 

文字列として正確に等しい場合はインクリメントします`score`。 
6. 11 個の位置をすべて終了したら、出力します。`score`。 

### なぜ効果があるのか

 入力内の各位置は、参照シーケンス内の 1 つの固定位置に正確に対応します。 このアルゴリズムはインデックスごとの同等性テストを計算し、各テストは最終的なカウントに独立して寄与します。 どのポジションも他のポジションに影響を与えないため、ポジションごとの一致を合計することでチート スコアの正確な定義が得られます。 この問題では一致の代替解釈が許可されていないため、カウントは完全かつ正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    ref = ["up", "up", "down", "down", "left", "right", "left", "right", "b", "a", "start"]
    s = input().split()
    
    score = 0
    for i in range(11):
        if s[i] == ref[i]:
            score += 1
    
    print(score)

if __name__ == "__main__":
    solve()
```このソリューションは、次を使用して行全体を一度に読み取ります。`split()`、入力形式ではスペースで区切られた正確に 11 個のトークンが保証されているため、安全です。 

参照配列は固定されており、入力に依存しないため、ハードコードされています。 これにより、不必要な計算や文字列操作が回避されます。 

ループは 11 回の反復に厳密に制限されており、一定時間の実行が保証されます。 比較では文字列の直接等価性が使用されます。これは、ここでは最も効率的で正しい操作です。
