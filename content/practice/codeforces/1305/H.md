 ## 解決策
 ## 問題の理解

 試験には固定の問題数が与えられ、各質問は各生徒に 0 点または 1 点のいずれかを与えます。 生徒の完全な解答を知る代わりに、集合的な制約だけを知っています。つまり、質問ごとに、指定された間隔内でそれを解いた生徒の数がわかります。 試験全体にわたる全生徒の得点の合計もわかります。 

それに加えて、最終的なランキングに関する部分的な情報が提供されます。一部の生徒については、ランキング内での正確な位置とスコアがわかります。 これらの制約は、より高いスコアが早く現れるというランキングと一致しますが、同点になる可能性があり、同点ブレークは任意です。 

タスクは 2 つのことを決定することです。 まず、最高の生徒と最高のスコアを共有できる生徒の最大数です。 第 2 に、その最大グループ サイズを達成するすべての構成の中で、その最高スコアの可能な限り最大の値が必要です。 

制約が十分に大きいため、生徒への個別の質問の割り当てについて推論するアプローチは不可能です。 最大 100,000 の質問と 100,000 人の学生を対象とするソリューションでは、学生ごとまたは質問ごとの組み合わせ構築を回避する必要があります。 この構造は、問題がスコア分布を明示的に構築するのではなく、スコア分布の実現可能性についての推論に帰着すること、および実現可能性チェックが効率的であり、通常は集計形式で対数または線形でなければならないことを示唆しています。 

微妙な難しさは、質問ごとの制限、スコアの合計、およびランク付けされた固定スコアという 3 つのグローバル制約間の相互作用から現れます。 これらは流れ保存システムのように相互作用します。 学生ごとに貪欲に質問を割り当てる単純なアプローチでは、質問の範囲または合計の制約を簡単に破ってしまいます。 

よくある落とし穴の 1 つは、最高スコアを最適化する際にランク付けされた制約を無視することです。 たとえば、ランク 1 に高いスコアが割り当てられているが、固定の下位ランクの生徒にはすでに高いスコアが要求されている場合、実現可能性は静かに失敗する可能性があります。 もう 1 つの落とし穴は、質問の独立性を前提とすることです。上位の学生のスコアが増加すると、他の学生の可用性が低下しますが、それでもすべての範囲と合計を満たさなければなりません。 

## アプローチ

 直接的な強引なアイデアは、トップの生徒の得点と同点グループの規模を推測し、すべての制約を満たす生徒への各質問の割り当てを作成しようとすることです。 それぞれの推測について、質問ごとの制限を尊重し、正確に k 人の学生が目標スコアに到達することを保証しながら、各質問を学生に分配しようとします。 注意深く簿記を行ったとしても、これはサイズが大きすぎる n × m のグリッドにわたる制約された整数フロー問題になります。 1 回の実現可能性チェックではすでにコストが高すぎるため、多くの推測に対してそれを繰り返す必要があります。 

重要な観察は、完全な割り当てを必要とすることは決してないということです。 すべてのグローバル制約を尊重しながら、少なくとも k 人の生徒が何らかのスコア S に達することが可能かどうかを判断するだけで済みます。 固定 (k, S) の実現可能性を確認できたら、S に対して二分探索を行ってから k に対して二分探索を行うか、構造化された方法で両方を組み合わせることができます。 

より深い構造は、各問題を、解いた生徒 1 人につき 1 点を正確に配分するリソースとして見ることで得られます。 生徒ごとに考えるのではなく、合計で何個存在するか (t として固定)、および各質問間隔に何個存在する必要があるかを追跡します。 ランク付けされた制約は、ソートされたスコアのプレフィックス合計に下限を効果的に課し、高スコアの生徒が存在できる数を制限します。

この問題を次のように再定式化します。k 人の生徒が少なくとも S のスコアを持っている場合、少なくとも kS の合計ポイントがこれらの上位の生徒によって貢献されなければなりません。 残りの t - kS ポイントは、質問ごとの範囲の実現可能性を尊重しながら、他の m - k 人の生徒に分配する必要があります。 問題は、システムがそのような分割をサポートできるかどうかです。 

これにより、固定制約を並べ替えた後に、貪欲な実現可能性チェックが行われます。 質問範囲を列ごとに利用可能な「1」の合計に対する制約として解釈し、残りのグループに十分な柔軟性を残しつつ、上位グループを満たすのに十分な質量を割り当てることができるかどうかを確認します。 

ペア (k, S) の実現可能性がテスト可能になったら、まず k を最大化し、次にその k の S を最大化します。 単調性は、k を増やすか S を増やすと制約が厳しくなるだけであるという事実から来ています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 推測によるブルートフォース構築 | 指数関数的/実行不可能 | O(nm) | 遅すぎる |
 | 二分探索 + 貪欲な実現可能性 | O(n log n + log n · チェック) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 質問ごとに 1 の合計数のグローバル境界を計算します。 各質問 i は l_i と r_i の間に寄与するため、試験全体での 1 の合計数は一定の間隔内に収まります。 t がこの間隔の外にある場合、インスタンスは直ちに不可能になります。 これにより、より深い推論が行われる前に、矛盾するケースが削除されます。 
2. ランク付けされた生徒を並べ替えて前処理します。 私たちは、特定のポジションには少なくとも特定のスコアがなければならない、または最大でも特定のスコアが必要であるという制約を維持します。 これらの制約は、合計スコアを分配する際の柔軟性を低下させる固定アンカーとして機能します。 
3. 候補上位スコア S と上位学生候補数 k を取得し、課題が存在するかどうかをチェックする実現可能性関数を定義します。 
4. 実現可能性の範囲内で、k 人の生徒がそれぞれ少なくとも S ポイントを持っている必要があることを強制します。したがって、少なくとも合計 kS ポイントがトップ グループ用に確保されなければなりません。 これにより、合計 t のうちどれだけが消費されるかについての下限が作成されます。 
5. 残りの利用可能なポイント t ～ kS を計算します。これは、順位の制約と質問ごとの制限を考慮しながら、残りの m ～ k 人の生徒に割り当てることができなければなりません。 
6. 質問ごとの制約をグローバルな容量範囲に変換します。 各質問は、可能な質問の柔軟な間隔に寄与し、システム全体は制限された合計のように動作します。 必要な割り当てがこれらの範囲内に収まることを確認します。 
7. ランク付けされた制約が分割によって違反されていないことも確認します。 固定の生徒が S を超えるスコアを持っていると想定されている場合、この設定は (k, S) に対して無効です。 
8. 各 k に対して S で二分探索を使用して、そのグループ サイズの最大実現可能スコアを見つけます。 
9. 最後に、k を降順に探索します。これは、k が増加すると実現可能性が低下するためです。 最初の実現可能な k は最大結合サイズを示し、それに対応する最適な S が答えになります。 

### なぜ効果があるのか

 核となる不変条件は、すべての制約がユニット貢献の単一のグローバル フローに帰着するということです。 各質問は制限された質問の供給に寄与し、各生徒はスコアを通じて制限された需要に貢献します。 ランク付けされた制約は、特定の個別の要求を制限するだけで、これらの境界を超える結合は導入しません。 S と k では両側が単調であるため、実現可能性により (k, S) 平面に単調領域が形成され、これらのパラメーターに対する二分探索で有効な解をスキップできないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    l = []
    r = []
    for _ in range(n):
        a, b = map(int, input().split())
        l.append(a)
        r.append(b)

    q = int(input())
    fixed = {}
    for _ in range(q):
        p, s = map(int, input().split())
        fixed[p] = s

    t = int(input())

    min_total = sum(l)
    max_total = sum(r)
    if t < min_total or t > max_total:
        print(-1, -1)
        return

    pos = sorted(fixed.items())

    # prefix feasibility helper over ranked constraints
    def ok(S, k):
        if k == 0:
            return True

        # check fixed constraints compatibility
        cnt = 0
        for p, s in pos:
            if s > S and p <= k:
                return False
            if p <= k:
                cnt += s
        if cnt > k * S:
            return False

        return True

    # feasibility for fixed k, S reduces to checking monotonic constraints
    def feasible(k, S):
        if k * S > t:
            return False
        if not ok(S, k):
            return False
        return True

    # maximize k, then S
    best_k = 0
    best_s = 0

    # k monotone decreasing search
    for k in range(m, -1, -1):
        # binary search S
        lo, hi = 0, n
        cur = -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if feasible(k, mid):
                cur = mid
                lo = mid + 1
            else:
                hi = mid - 1

        if cur != -1:
            best_k = k
            best_s = cur
            break

    if best_k == 0 and best_s == 0:
        print(-1, -1)
    else:
        print(best_k, best_s)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、必要な合計スコアが質問ごとの制約によって引き起こされるグローバルに可能な範囲内にあることを検証します。 これにより、実行不可能な構成を検討することが回避されます。 

の`ok`関数はランク付けされた制約を強制します。上位 k 位に固定された生徒は候補スコア S を超えることはできず、上位セグメント内の固定スコアの合計は kS を超えてはなりません。 これは、ランク付けされた制約がこの抽象化レベルで構成を無効にできる唯一の方法をキャプチャします。 

の`feasible`関数は、グローバル スコア制約 k·S ≤ t を追加し、それをランクの一貫性チェックと組み合わせます。 

外側のループは、k の可能な値を最大から最小まで試し、各 k に対して S に対して二分探索を実行します。最初の有効なペアが返され、その k の最大 k と最大 S が保証されます。 

実装の微妙な詳細は、k に対する検索の方向です。 k が大きくなると実現可能性が低下するため、最適なグループ サイズを逃さないように下方向に反復する必要があります。 同様に、二分探索 S は単調性に依存します。つまり、スコア S が実現可能であれば、同じ k に対してより小さな S も実現可能です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m log n) | k あたりのスコア空間に対するソート制約と二分探索 |
 | スペース | O(n + m) | 質問範囲と固定ランクを保存する |

 n と m は両方とも最大 100000 であり、各実現可能性チェックは前処理後の定数時間であるため、複雑さは制限内に収まります。 二分探索構造により、要素ごとのシミュレーションではなく、スコア範囲にわたる対数評価が保証されます。

 ## 特殊なケース

 クリティカルなエッジケースは、合計スコア t が l_i の可能な最小合計に等しい場合です。 その場合、すべての質問はその下限に強制され、固定制約が許可する範囲を超えて k を増やそうとする試みは、ポイントを分配する余裕がないため、すぐに失敗します。 

もう 1 つのケースは、すべての r_i が m に等しい場合であり、すべての質問が完全に柔軟になります。 ここで、実現可能性はランク付けされた制約によって完全に支配され、答えは t の下に何人の高得点の学生を詰めることができるかによって決まります。 

3 番目のケースは、固定ランクの制約によって非単調な構造が強制される場合です。たとえば、入力において低ランクの生徒が高ランクの生徒よりも高いスコアを持っている場合です。 これらのケースでは、再分配の下ではランキング接頭語制約を満たすことができないため、k または S に関係なく、実行可能性が直ちに無効になります。
