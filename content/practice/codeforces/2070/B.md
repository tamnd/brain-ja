 ## 解決策
 ## 問題の理解

 整数の直線に沿って移動する 1 次元のロボットをシミュレートしています。 ロボットはその位置からスタートします$x$、これは負でも正でも構いませんが、最初はゼロになることはありません。 長さのコマンドの固定シーケンスが与えられます。$n$, ここで、各コマンドはちょうど 1 単位だけ左または右にシフトします。 

ロボットはコマンドを 1 秒ごとに順番に実行します。 重要な点は、実行ポインタが位置 0 に達するたびにシーケンスの最初のコマンドにリセットされ、ロボットがそこから再び続行することです。 ゼロにならずにコマンド シーケンス全体が終了すると、プロセスは完全に停止します。 

タスクは真上の位置をシミュレートすることではありません$k$秒、以来$k$は非常に大きくなる可能性がありますが、その代わりに、その時間枠内でロボットが正確にゼロに着地した回数を数えます。 

この制約により、単純なシミュレーションが即座に除外されます。 直接的なステップバイステップのシミュレーションは次のとおりです。$O(k)$、そしてそれ以来$k$まで可能です$10^{18}$、単一のテストケースですら不可能です。 代わりに、ソリューションはコマンド シーケンスのサイクルの観点から機能する必要があります。 

微妙な難点は、リセットはシーケンスの完了ではなくゼロに到達することに依存するため、このプロセスが単純な方法で周期的ではないことです。 

いくつかのエッジケースは、素朴な推論がなぜ失敗するのかを明らかにしています。 まず、ある開始位置から決してゼロに到達しないシーケンスを考えてみましょう。 その場合、ロボットはシーケンスを早期に終了して停止する可能性があるため、サイクルのカウントが過大評価される可能性があります。 

次に、ロボットが 1 回のパス内で複数回ゼロに到達するシーケンスを考えます。 このようなヒットが発生するたびに実行がリセットされます。つまり、そのような場合、実際にはシーケンス全体が完了することはなく、完全な実行に関する推論は無効になります。 

第三に、開始位置が負であるか正であるかによって、最初のヒットが早いか遅いかが変わるため、プレフィックスの動作を追跡せずに対称性を仮定することはできません。 

## アプローチ

 ブルート フォース シミュレーションでは、文字通り 1 秒あたり 1 つのコマンドが実行され、位置が更新され、デクリメントされます。$k$、ゼロに達するたびに命令ポインタをリセットします。 これは正しいですが、リセットするたびにシーケンスの先頭に戻る可能性があり、最悪の場合、文字列のプレフィックスを繰り返し走査する可能性があります。 と$k$まで$10^{18}$、このアプローチは完全に実行不可能です。 

重要な点は、プロセスがコマンド文字列内の現在位置と現在のインデックスという 2 つの状態によって完全に決定されるということです。 ただし、考えられるすべての状態を経時的に追跡する必要はありません。 代わりに、特定の状態からゼロに達するまでにかかる時間と、そのリセットの直後に何が起こるかだけを考慮します。 

シーケンスの先頭の固定開始位置から、ロボットが最初にゼロに達するタイミングを事前計算できます。 シーケンスを使い果たす前にゼロに到達しない場合、プロセスは直ちに終了します。 それ以外の場合、最初にゼロに達したのがステップであると仮定します。$t$。 それから私たちは消費しました$t$秒でリセット イベントを 1 つ獲得しました。 リセット後、ロボットは再び完全なシーケンスで位置 0 から再起動します。 

これにより、問題は 2 つのフェーズに分かれます。 まず、最初の時間を次から計算します。$x$ゼロになったとき。 次に、シーケンスの実行中に再びゼロに達したときのゼロからの最初の時間を計算します。 2 番目のフェーズはサイクル ジェネレーターになります。一度ゼロになると、ゼロに戻るたびに同じように再起動し、パターンが繰り返されます。 

したがって、解決策はプレフィックス シミュレーションを使用して 2 つの値を計算することになります。 

1 つは最初のヒット時間です$x$、もう 1 つは、最初のゼロ復帰時間です。$0$。 その後、算術演算を使用して、0 回の発生、1 回の発生、または繰り返しサイクル カウントを取得します。$k$。

 ## アルゴリズムのチュートリアル

 まずコマンド文字列をプレフィックス変位配列に変換して、位置を迅速に計算できるようにします。 

1. コマンド シーケンスのプレフィックス ディスプレイスメントを計算します。ここで、各 L は -1 に寄与し、各 R は +1 に寄与します。 これにより、シミュレーションのオーバーヘッドなしでシーケンスのプレフィックスの後の位置を知ることができます。 
2. 初期位置からのスタート$x$、プレフィックスの合計をスキャンして、最も古いインデックスを見つけます。$i$そのような$x + prefix[i] = 0$。 これは、ロボットが最初の実行中にゼロに到達した場合、最初の瞬間を表します。 
3. そのようなインデックスが存在しない場合$n$ステップを完了すると、ロボットはリセットされることはなく、終了するか時間になるまで実行されます。$k$なくなります。 この場合、開始パスがゼロに達するかどうかに応じて、答えは 0 または 1 になりますが、リセットは発生しないため、最初の実行が終了した後に単純にカウントを停止します。 
4. 時間内に最初のヒットが発生した場合$t_1$、答えを 1 増やして減らします。$k$による$t_1$。 システムは完全なコマンド シーケンスで位置 0 から再起動します。 
5. 次に、位置 0 からシミュレーションして、もう一度最初の時間を見つけます。$t_2$プレフィックスがゼロになるようにします。 そうでない場合$t_2$が存在する場合、それ以上のリセットは発生しないため、現在の答えを返します。 
6. そのような場合は、$t_2$存在する場合、すべての$t_2$数秒でまたリセットされます。 追加します$\lfloor k / t_2 \rfloor$答えて終了します。 

この削減が有効な理由は、ロボットがゼロに到達すると、リセット後の状態は毎回同じ、つまり同じ開始位置、同じ命令ポインタ、同じシーケンスになるためです。 これにより、将来の動作が一定の周期で周期的に行われます。$t_2$, したがって、数えることは単純な割り算の問題になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x, k = map(int, input().split())
        s = input().strip()

        # prefix displacement
        pref = []
        cur = 0
        first_hit_from_x = -1

        for i, c in enumerate(s):
            if c == 'L':
                cur -= 1
            else:
                cur += 1
            pref.append(cur)

            if first_hit_from_x == -1 and x + cur == 0:
                first_hit_from_x = i + 1

        if first_hit_from_x == -1 or first_hit_from_x > k:
            print(0)
            continue

        # first reset
        ans = 1
        k -= first_hit_from_x

        # now start from 0
        cycle = -1
        for i, v in enumerate(pref):
            if v == 0:
                cycle = i + 1
                break

        if cycle == -1:
            print(ans)
            continue

        ans += k // cycle
        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、シミュレーションの繰り返しを避けるためにプレフィックス ディスプレイスメントに依存しています。 変数`cur`コマンド文字列の各プレフィックスの後のネットの動きを維持します。 これにより、ステップごとに一定時間でのゼロへの到達可能性を確認できます。 

最初のループは、プレフィックス配列とロボットがゼロに到達する最も早い時間の両方を計算します。$x$。 最初のセグメントはゼロ以外の開始により、その後のすべてのセグメントとは異なる動作をするため、これは重要です。 

最初のリセット後、システムは常に位置 0 から再起動します。 そのため、2 番目のループではプレフィックス自体がゼロになったときのみチェックし、追加は行われません。$x$。 

微妙な点は、残り時間内のフルリセットのみをカウントすることです。 残り時間がサイクル長よりも小さい場合、整数除算は当然、部分サイクルを正しく処理します。

 ## 特殊なケース

 主なエッジケースは、ロボットが開始位置からであってもゼロに到達しない場合です。 この状況では、最初のループでは有効なプレフィックスが見つからないため、答えはすぐにゼロになります。 たとえば、次の場合$x=3$シーケンスは右に移動するだけで、リセットは発生せず、実行は早期に終了します。 

もう 1 つのケースは、ロボットが最初の部分的な実行中にゼロに到達したものの、再びゼロから戻らない場合です。 その場合、リセットは 1 回だけカウントされます。 アルゴリズムはこれを処理します。`cycle`-1 のままで、除算は防止されます。 

3 番目のケースは、サイクル長が 1 の場合です。これは、プレフィックスが 1 つのステップでゼロから即座にゼロに戻ることを意味します。 整数を 1 で割ると残り時間がすべて累積されるため、アルゴリズムは残り 1 秒ごとをリセットとして正しくカウントします。 

これらのケースでは、ファーストヒット ロジックとサイクル圧縮の両方が縮退コマンド パターン全体で正しく動作することが確認されています。
