 ## 問題の理解

 のストリップがあります`n`セル、最初はすべて赤色です。 ペイント後の各セルは、赤または青の希望の色になります。 私たちがパフォーマンスできるのはせいぜい`k`各操作により、セルの連続したセグメントを選択し、それらを青でペイントすることができます。 すでに青になっているセルを再度再描画することはできますが、青のセルを赤に戻すことはできません。 すべての操作を行った後、一部のセルが目的の色と一致しない場合があります。 各セルには、間違った色になった場合にペナルティが適用されます。 絵画の最終ペナルティは、間違って色の付いたすべてのセルの最大ペナルティ、またはすべてのセルが正しい場合はゼロです。 タスクは、最大でも次の値を使用して、この最終的なペナルティを最小限に抑えることです。`k`操作。 

入力では複数のテスト ケースを指定します。`n`まで`3 * 10^5`そして合計`n`テストケース全体でも最大`3 * 10^5`。 これにより、次のようなアルゴリズムが除外されます。`O(n^2)`何千億もの操作が行われるため、複雑になります。 ほぼ線形または線形に近いアルゴリズムが必要です。`n`テストケースごとに。 罰金は次のような大きさになる可能性があります`10^9`したがって、ペナルティ値によってインデックス付けされた配列を必要とする計数トリックに依存することはできません。 

単純なアプローチを簡単に打ち破る可能性のあるエッジ ケースとしては、すべてのセルがすでに赤くなっている、`k=0`、 または`k >= n`。 たとえば、すべてのセルを赤にする必要がある場合、最小ペナルティは常にゼロになります。`k`ただし、不注意で貪欲なアルゴリズムが不必要にペイントしようとする可能性があります。 もう 1 つの注意が必要なケースは次のような場合です。`k`は非常に小さく、青色の要件が点在しています。どの青色のセルをペイントするかの決定は、最終的なペナルティに直接影響します。 

## アプローチ

 ブルートフォースアプローチでは、考えられる選択肢をすべて列挙します。`k`セグメントを青にペイントしてから、結果として生じるペナルティを計算します。 これは問題を直接モデル化するため機能しますが、可能なセグメントの数が二次関数的に増加するため、実際には劇的に失敗します。`n`そして選択する`k`それらの組み合わせは爆発を引き起こし、処理できなくなります。`n = 3 * 10^5`。 

重要な洞察は、問題が **二分探索による決定問題**に還元できるということです。 候補者のペナルティを修正するとします`x`。 問題は、最大でも再描画できるかということです。`k`以下のペナルティを持つセルが存在しないようなセグメント`x`結局間違ってしまうのか？ この決定問題を効率的に解決できれば、考えられるすべてのペナルティ値に対して二分探索を実行して、達成可能な最小ペナルティを見つけることができます。 

候補者のペナルティを確認するには`x`、すべてのセルに超過ペナルティをマークします`x`「正しくなければならない」ように。 次に、ストリップを次の文字列に縮小します。`0`そして`1`どこ`1`ペナルティを超えないようにするために青でなければならないセルを表します`x`、 そして`0`さもないと。 問題は、すべてをカバーできるかどうかです。`1`せいぜい`k`連続した青いセグメント? これは、左から右にスイープして新しいセグメントを開始することで貪欲に実行できます。`1`前のセグメントではまだカバーされていません。 

この観察により、元の問題はセグメントに対する指数関数的な探索から、`O(n log max_penalty)`アルゴリズムは、制約を考慮すると十分に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² * k) | O(n) | 遅すぎる |
 | 二分探索 + 貪欲 | O(n log P) | O(n) | 承認済み |

 ここ、`P`配列内の最大ペナルティです。 

## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`、`k`、希望の色の文字列`s`、および罰則`a`。 
2. リストを作成する`penalties`すべての一意のペナルティ値が含まれています。 これらの値を二分探索します。 
3. ヘルパー関数を定義する`can_achieve(max_penalty)`を超えるペナルティを回避できるかどうかをチェックします`max_penalty`せいぜい使用`k`操作:

 1. ストリップをバイナリ配列に変換します。`must_paint`それぞれの細胞はどこにあるのか`1`希望の色が青で、ペナルティが超過した場合`max_penalty`、 さもないと`0`。 
2. スイープスルー`must_paint`左から右へ。 すべてをカバーするには、連続する青色のセグメントが何個必要かを数えます。`1`s.
 3. セグメント数が ≤ の場合`k`、 戻る`True`; それ以外の場合は戻る`False`。 
4. 以下を使用して、ソートされた一意のペナルティに対して二分検索を実行します。`can_achieve`。 初期化する`low = 0`そして`high = max(a)`。 
5. それぞれの中間値について`mid`、 チェック`can_achieve(mid)`。 true の場合、より小さいペナルティを試してください (`high = mid`); false の場合、ペナルティを増加します (`low = mid + 1`）。 
6. 最後に、`low`最小達成可能な最大ペナルティが含まれます。 
7. この値を出力します。 

**機能する理由**: 二分探索は、ペナルティを達成できるかどうかという単調な性質に依存しています。`x`、より大きなペナルティを達成することもできます。`x`。 貪欲なセグメントのカウントが有効なのは、大きなセグメントをペイントすることは、小さなセグメントをペイントすることよりも悪いことは決してないためです。隣接する必要なセルを 1 つのセグメントにマージすることで、総操作数が最小限に抑えられます。 したがって、アルゴリズムは最小ペナルティを正確に見つけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        a = list(map(int, input().split()))

        def can_achieve(max_penalty):
            segments_needed = 0
            i = 0
            while i < n:
                if s[i] == 'B' and a[i] > max_penalty:
                    segments_needed += 1
                    while i < n and s[i] == 'B' and a[i] > max_penalty:
                        i += 1
                else:
                    i += 1
            return segments_needed <= k

        low, high = 0, max(a)
        while low < high:
            mid = (low + high) // 2
            if can_achieve(mid):
                high = mid
            else:
                low = mid + 1
        print(low)

if __name__ == "__main__":
    solve()
```の`can_achieve`関数は、候補の上のペナルティを避けるためにペイントする必要がある連続した青いセグメントをカウントします。 二分探索は、最小限の実現可能な最大ペナルティを効率的に導き出します。 次のような境界条件`k = 0`そして、すべてが赤いストリップは、このアプローチによって自然に処理されます。
