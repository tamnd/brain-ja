 ## 解決策
 ## 問題の理解

 シーケンス内で 3 つの固定位置が与えられます: 最初の値`a`、2番目の値`b`、および 3 番目の値`c`。 許可される変更操作は 1 つだけです。これら 3 つの位置のいずれかを選択し、それに正の整数を掛けます。`m`私たちの選択です。 

この 1 つの変更の後、結果のトリプルが指定された順序で等差数列を形成するようにします。 つまり、中間要素は最初と 3 番目のちょうど中間になければならず、同等の条件が必要です。`2 * middle = first + third`保持しなければなりません。 

タスクは、数列を明示的に構築することではなく、インデックスと乗数のそのような選択が存在するかどうかを判断することだけです。 

テスト ケースの数には最大 10⁴ という厳しい制約がありますが、各テスト ケースは一定の作業です。 これにより、値の検索を伴うものは即座に除外されます。`m`あるいは候補者を列挙する。 以来`m`最大 10⁸ になる可能性があるため、可能な乗数を強引に超えることは不可能です。 

この問題の微妙な点は、1 つの値を変更すると構造が非対称に変更されることです。 単純なアプローチでは、インデックスのすべての選択と可能なすべてのことを試してしまう可能性があります。`m`、しかし、それは巨大な検索スペースをもたらします。 

一般に、誤った解を破るエッジ ケースは、対称ケースやゼロ差分ケースから生じます。 たとえば、すべての数値が等しい場合でも、次の条件を選択すると、1 つの要素の乗算によって AP が許可されます。`m = 1`。 もう 1 つの注意が必要なケースは、AP がすでに保持している場合です。操作を適用する必要がありますが、1 を乗算することで保持されます。 不注意な解決策は、「何もしない」ことが許可されていることを忘れてしまう可能性があります。`m = 1`。 

2 番目の重要なコーナーは、AP が「ほぼ有効」であるものの、差分の等しいだけでなく厳密な線形関係を満たす必要がある中間要素を調整する必要がある場合です。 

## アプローチ

 ブルートフォースアプローチでは、すべてのインデックスが試行されます。`i ∈ {a, b, c}`そしてあらゆる可能な乗数`m`、トリプルを再計算し、等差数列を形成しているかどうかを確認します。 これは、許可されているすべての操作を調査するため、原則的には正しいです。 

ただし、これはすぐに失敗します。`m`最大 10⁸ の範囲です。 実現可能性を代数的にチェックすることに上限を設けたとしても、値を反復処理することは不可能です。 本当の問題はサイズだけではありません`m`、しかし、その方法には単調な構造はありません。`m`インデックスのさまざまな選択にわたって AP の状態に影響します。 

重要な点は、検索する必要がないということです。`m`全然。 代わりに、どの位置が変更されたかを想定し、直接解くことができます。`m`等差数列条件を使用します。 

インデックスを固定すると、AP 条件は次のような一次方程式になります。`m`。 各ケースは、派生値が以下であるかどうかをチェックすることに帰着します。`m`は正の整数です。 

これにより、問題は値の検索から一定数の代数チェックに変換されます。

 | 3 つのポジションを試して方程式を解く | O(t) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 3 つの可能性をそれぞれ個別に検討します。 

1. 乗算すると仮定します。`a`による`m`。 新しいシーケンスは次のようになります`[a·m, b, c]`。 これが AP であるためには、以下が必要です`2b = a·m + c`。 これを並べ替えると、`m = (2b - c) / a`。 これは次の場合にのみ機能します`2b - c > 0`で割り切れる`a`。 
2. 乗算すると仮定します`b`による`m`。 シーケンスは次のようになります`[a, b·m, c]`。 AP条件は`2(b·m) = a + c`、 それで`m = (a + c) / (2b)`。 正確な割り算が必要です。`a + c > 0`、これは制約が与えられると常に true になります。 
3. 乗算すると仮定します`c`による`m`。 シーケンスは次のようになります`[a, b, c·m]`。 AP 条件は次のようになります。`2b = a + c·m`、 それで`m = (2b - a) / c`。 私たちは再び積極性と割り切り性を必要とします。 

いつでも、有効な整数が見つかった場合`m ≥ 1`、すぐにYESを返すことができます。 

3 つのケースのいずれも有効な乗数を生成しない場合、答えは「いいえ」です。 

### なぜ効果があるのか

 すべての有効なソリューションは、1 つの変更された位置に正確に対応する必要があります。 その固定位置に対して、AP 条件は、必要な値を一意に決定します。`m`一次方程式を通して。 可能な選択肢は 3 つだけであり、それぞれのケースが徹底的にチェックされるため、有効な構成を検出する必要があります。 逆に、計算されたすべての候補は AP 条件から直接導出されるため、無効な設定はチェックに合格できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(x, y, z):
    # try multiplying x by m: (x*m, y, z)
    num = 2*y - z
    if num > 0 and num % x == 0:
        m = num // x
        if m >= 1:
            return True

    # try multiplying y by m: (x, y*m, z)
    num = x + z
    if num % (2*y) == 0:
        m = num // (2*y)
        if m >= 1:
            return True

    # try multiplying z by m: (x, y, z*m)
    num = 2*y - x
    if num > 0 and num % z == 0:
        m = num // z
        if m >= 1:
            return True

    return False

t = int(input())
for _ in range(t):
    a, b, c = map(int, input().split())
    print("YES" if ok(a, b, c) else "NO")
```このコードは、派生した 3 つの代数チェックを直接実装します。 各ブロックは、1 つのインデックスを変更された要素として固定することに対応します。 整数の除算チェックにより、有効な乗数のみを受け入れることが保証され、正の条件により無効な負の解やゼロの解が阻止されます。 

ここでよくある落とし穴は、乗数が少なくとも 1 でなければならないことを忘れていることです。もう 1 つの微妙な問題は、整数の除算です。誤った切り捨てを避けるために、除算する前に割り切れる可能性を確認する必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        a, b, c = map(int, input().split())

        def check(a, b, c):
            num = 2*b - c
            if num > 0 and num % a == 0 and num // a >= 1:
                return True
            if (a + c) % (2*b) == 0 and (a + c) // (2*b) >= 1:
                return True
            num = 2*b - a
            if num > 0 and num % c == 0 and num // c >= 1:
                return True
            return False

        return "YES" if check(a, b, c) else "NO"

    out = []
    t = int(sys.stdin.readline())
    for _ in range(t):
        out.append(solve())
    return "\n".join(out)

 ## 特殊なケース

 特殊なケースの 1 つは、3 つの数値がすべて等しい場合です。 AP 条件はすでに成立しており、任意の要素に次の値を乗算します。`m = 1`それを保存します。 それぞれのケースで許可されるため、アルゴリズムはこれを処理します。`m = 1`、割り算チェックは自然にパスします。 

もう 1 つのケースは、有効なソリューションで中間要素の変更が必要な場合です。 多くの誤ったソリューションはこれを見逃しているか、エンドポイントを調整する必要があると想定しています。 方程式`m = (a + c) / (2b)`はこの可能性を明示的に捉えており、整数の割り算チェックにより正確性が保証されます。 

最後の微妙なケースは、次のように、計算された分子が非正になる場合です。`2b - c ≤ 0`。 これは、選択された変更に非正の乗数が必要な、不可能な AP 構成に対応します。 アルゴリズムはこれらのケースを明示的に拒否し、無効な算術解がすり抜けるのを防ぎます。
