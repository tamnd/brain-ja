 ## 解決策
 ## 問題の理解

 各エッジが正の整数の重みを持つ接続された無向グラフが与えられます。 このグラフからスパニング ツリーを選択する必要があります。つまり、正確に選択することになります。$n-1$すべての頂点の接続を維持し、サイクルを含まないエッジ。 考えられるすべてのスパニング ツリーの中で、選択されたすべてのエッジの重みのビットごとの OR として定義されるスコアを計算し、そのようなスコアを可能な限り小さくする必要があります。 

したがって、古典的な MST 問題のように総重みを最小化する代わりに、ここでは選択したエッジ間のビット単位の OR を最小化します。 これにより、最適化の性質が変わります。エッジの追加によって情報が「キャンセル」されることはなく、最終結果により多くのビットが設定される可能性があるだけです。 

制約は厳しいですが、極端ではありません。 すべてのテスト ケースにわたる頂点とエッジの合計数は最大で$2 \cdot 10^5$これは、どの解もエッジの総数においてほぼ線形またはほぼ線形になることを意味します。 高密度グラフではスパニング ツリーの数が指数関数的に増加するため、すべてのスパニング ツリーやエッジ上のビットマスク DP を試すようなことは直ちに不可能になります。 

単純なアイデアとしては、Kruskal または Prim を使用して最小スパニング ツリーを構築してみるというものがありますが、これはビットごとの OR ではなく合計を最適化し、ビット伝播を制御できません。 もう 1 つの素朴なアイデアは、スパニング ツリーを形成するエッジのすべてのサブセットを試してみるというものですが、これは中程度のグラフであっても天文学的に大きくなります。 

上位ビットのみが異なるエッジを使用してコンポーネントを接続する複数の代替方法がグラフにある場合、微妙なエッジ ケースが発生します。 たとえば、1 つのエッジの重みが 1 (バイナリ) である場合、`001`)、もう 1 つは重み 2 (バイナリ) を持ちます。`010`)、どちらを選択しても局所的には問題ないように見えますが、接続によってどのエッジが強制されるかに応じて、OR の累積が異なります。 

エッジを重みでソートして小さいエッジを選択するなどの不用意な貪欲な戦略は失敗する可能性があります。これは、エッジがわずかに大きいと他の場所に高いビットが導入されるのを避け、最終的な OR が減少する可能性があるためです。 

本当の難しさは、OR 演算がグローバルで単調であるため、どのビットを含める必要があるかを考える必要があることです。 

## アプローチ

 ブルート フォースの観点は、スパニング ツリーを選択し、その OR 値を計算することを想像することです。 スパニング ツリーの数が急激に増加するため、これは実行不可能です。 ツリーを形成する可能性のあるエッジのサブセットをすべて列挙するだけでも、$O(2^m)$サブセットごとの接続を検証することは別のことです$O(n)$、完全に使用できなくなります。 

重要な観察は、視点を反転することです。 OR を直接最小化しようとする代わりに、「どのビットを回避できるか?」と尋ねることができます。 

回答候補を修正する場合$X$の場合、重みが禁止ビットを導入しないエッジのみを使用するスパニング ツリーが存在するかどうかを尋ねます。つまり、すべてのエッジが次の条件を満たす必要があります。$w \& \sim X = 0$。 言い換えれば、選択するすべてのエッジは次のサブマスクでなければなりません。$X$、そうでない場合は、少し外側に導入されてしまうでしょう$X$。 

したがって、固定の場合$X$、許可されたエッジのみで構成されるサブグラフを構築し、それが接続されているかどうかを検証することで、実現可能性をチェックできます。 接続されている場合、スパニング ツリーはこのサブグラフ内に完全に存在し、そのツリーの OR は自動的に最大で$X$、すべてのエッジは内部のビットのみを提供するため、$X$。 

これにより、問題は最小のビットマスクを見つけることに変わります。$X$に含まれるエッジによって形成されるグラフが$X$接続されています。 以来$X$は最大 30 ビットなので、最上位ビットから下に向かって貪欲に構築できます。接続が含まれるエッジを使用せずに接続がまだ達成できる場合は、ビットを未設定のままにしておこうとします。 

ビットを削除できるかどうかをテストするには、エッジをそのビットを含まないエッジに一時的に制限し、DSU を使用して接続をチェックします。 接続が維持されている場合は、ビットをクリアしたままにします。 それ以外の場合は、それを含める必要があります。 

これにより、最上位ビット (約$10^9$) 0まで下がります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に解決します。 

1. すべてのビットが設定された状態で応答マスクを初期化します。通常は、$(1 << 30) - 1$。 これは、強制される可能性のある最大の OR 値を表します。 
2. 関連する最上位ビットから 0 までビットを処理します。各ビットは、そのビットが設定されているエッジを含めることが許可されているかどうかを表します。 
3. 固定ビットの場合$b$、回答ではそれをオフにしようとします。 一時的に、このビットは最終的な OR には必要ないと仮定します。 
4. この仮定をテストするために、重みにビットが含まれていないエッジのみを考慮します。$b$それを禁止しようとしている場合。 これは、そのビットを完全に禁止するという考えをシミュレートします。 
5. これらのフィルタリングされたエッジ上で DSU を実行し、すべての頂点が接続されるかどうかを確認します。 それらが接続されている場合、ビットを持つエッジを使用せずにスパニング ツリーを構築することが可能です。$b$, したがって、このビットを回答から永久にクリアします。 
6. 接続が失敗した場合は、応答内のビットを復元します。これは、グラフを接続するにはそのビットを持つ何らかのエッジが必要であることを意味します。 
7. すべてのビットを処理した後、結果のマスクは可能な最小の OR になります。 

正確かどうかは、ビットを削除することが、ビットを導入するすべてのエッジを削除することに相当するという事実にかかっています。 グラフがその制限の下で接続されたままであれば、どのスパニング ツリーでもそのビットを完全に安全に回避できます。 

維持される不変条件は、ビットを高値から低値まで処理した後、より小さい OR マスクを生成するすべての構成は接続の制約により実行不可能であることが証明されているということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

def solve():
    t = int(input())
    for _ in range(t):
        input()  # empty line

        n, m = map(int, input().split())
        edges = []
        for _ in range(m):
            u, v, w = map(int, input().split())
            edges.append((u - 1, v - 1, w))

        ans = (1 << 30) - 1

        for b in range(29, -1, -1):
            dsu = DSU(n)
            for u, v, w in edges:
                if (w & ans) == 0 or (w & (1 << b)) == 0:
                    dsu.union(u, v)

            if len({dsu.find(i) for i in range(n)}) == 1:
                ans ^= (1 << b)

        print(ans)

if __name__ == "__main__":
    solve()
```DSU は、サイズによるユニオンを使用した標準のパス圧縮であり、接続チェックのみに使用されます。 主な微妙な点は、各ビット テスト中にエッジがどのようにフィルタリングされるかです。現在のマスク候補と一致するエッジのみを許可し、ビットを削除しても完全な接続が可能かどうかを明示的にテストします。 

接続をチェックする回線では、DSU ルートのセットが使用されます。 これは、コンポーネント数を追跡​​するよりもわずかに効率が劣りますが、制約が与えられている限り許容可能です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、複数のエッジが代替接続を提供するが、ビット構造のみが異なる場合です。 たとえば、あるパスが低重みのエッジを使用しているがビットが削除されると切断され、別のパスが高重みのエッジを使用しているが接続が維持されている場合、制限下では DSU 接続が失敗するため、アルゴリズムはそのビットの削除が不可能であることを正しく検出します。 

もう 1 つのケースは、グラフがすでにツリーになっている場合です。 その状況では、すべてのエッジが必要であり、アルゴリズムはエッジの重みに現れるビットを削除することはできません。ビットを削除するとすぐにグラフが切断されてしまうためです。 

最後に、すべてのエッジが共通の上位ビットを共有する場合、そのビットは避けられなくなります。 DSU チェックは最上位レベルでそのビットに対して失敗し、最終的な答えにロックされ、下位ビットはその制約の下で個別に最適化されます。
