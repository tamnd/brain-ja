 ## 問題の理解

 ワームホールは有向グラフを形成します。 既知の移行はそれぞれ、あるワームホールから別のワームホールに移行し、2 つのコストのいずれかを伴います。 ハイパートランジションのコストは 1 アリ時間ですが、ヌルトランジションのコストはゼロです。 船はワームホール 1 から出発し、ワームホール n に到達する必要があります。 

総コストが最小のルートが必要です。 さらに制限が 1 つあります。ルートは同じワームホールを 2 回訪問してはなりません。 出力には、最小アントアワー数に続いて、ルート内のワームホールの数とルート自体が含まれている必要があります。 ワームホール n がワームホール 1 から到達できない場合、出力は次のようになります。`IMPOSSIBLE`。 

グラフには、最大 100,000 個のワームホールと 100,000 個の有向遷移を含めることができます。 この規模では、考えられるルートを列挙することは完全に不可能です。 (O(n^3)) 時間の Floyd-Warshall など、頂点のすべてのペアを検査するアルゴリズムでさえ、限界をはるかに超えています。 実行時間が本質的に頂点と遷移の数において線形であるグラフ アルゴリズムが必要です。 すべての遷移のコストが 0 または 1 であるという事実が、このようなアルゴリズムを提供する構造的特性です。 

不注意な実装が失敗する可能性のあるエッジケースがいくつかあります。 

可能な限り最小のグラフを考えてみましょう。```

```船はすでに目的地に到着しています。 正しいルートは単一のワームホールです`1`、コストゼロの場合:```

2 番目のケースは、到達不能な宛先です。```

## アプローチ

 最も直接的なアプローチは、頂点が 2 回発生しないように、ワームホール 1 からのルートを列挙し、すでに訪問したワームホールを追跡することです。 目的地に到着するたびに、ルートのコストをこれまでに見つかった最良の答えと比較できます。 

すべての合法的なルートが明示的に考慮されるため、これは正しいです。 問題は路線数です。 分岐遷移が多数あるグラフには、単純なパスが指数関数的に多く存在する可能性があります。 十分に密度の高いグラフでは、単純なパスの数が (n!) 個になる可能性があるため、使用できる頂点が 100,000 個しかない場合でも、入力が最大サイズに達するずっと前に検索は不可能になります。 状態は現在の頂点だけでなく、以前に訪問した頂点の完全なセットでもあるため、繰り返しの頂点に対する制限により、総当たり列挙がさらに複雑になります。 

ブルート フォース アプローチは、合法的なルートの定義を直接表すため機能しますが、検査するルートが多すぎるため失敗します。 

重要な観察は、繰り返されるワームホールに関する制限には、実際には特別な最短パス アルゴリズムが必要ないということです。 すべての遷移コストは非負であるため、ウォークに繰り返し頂点が含まれる場合、その頂点の 2 つの連続した出現の間の部分が 1 サイクルになります。 そのサイクルを削除しても、総コストが増加することはありません。 サイクルのコストが正の場合、ルートは安くなります。 コストがゼロの場合、ルートはまったく同じコストを維持します。 このプロセスを繰り返すと、繰り返されるすべての頂点が削除され、大きなコストをかけずに単純なパスが作成されます。 

したがって、常に最適な単純なルートが存在します。 通常の最短経路問題を解決して、1 つの最短経路を再構成できます。 特別なエッジの重みが 0 と 1 に制限されているため、0 ～ 1 の BFS を使用できます。 

0-1 BFS は本質的に、重み 0 と 1 に特化したダイクストラのアルゴリズムです。 プライオリティ キューの代わりに、デキューを使用します。 ゼロコスト エッジをトラバースすると距離が改善され、その距離が現在の頂点と同じであるため、新しい頂点が前面に配置されます。 1 コストのエッジをトラバースすると距離が改善され、その距離がちょうど 1 大きいため、新しい頂点は後方に移動します。 

これにより、頂点は距離が減少しない順序で処理され、緩和が成功するたびに定数時間のデキュー操作のみが必要になります。

 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合は指数関数的 | (O(n+m)) プラス ルート状態 | 遅すぎる |
 | 最適、0-1 BFS | (O(n+m)) | (O(n+m)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 有向隣接リストを作成します。 あらゆるトランジションに対して`a -> b`タイプ付き`t`、 店`(b, t)`。 トランジションは一方通行になる可能性があるため、方向が重要です。 
2.初期化`dist[1] = 0`他のすべての距離は無限大です。 ストアも`parent[v]`、選択した最短ルート上の以前のワームホールを記憶します。`v`。 頂点 1 を両端キューに入れます。 
3. 頂点を取得します`v`デクの正面から。 すべての発信トランジションに対して`v -> to`費用がかかる`w`、計算します`new_dist = dist[v] + w`。 
4. もし`new_dist`よりも小さいです`dist[to]`、 アップデート`dist[to]`そしてセット`parent[to] = v`。 もし`w`ゼロです、置く`to`デクの先頭にあります。 もし`w`1つです、入れてください`to`後ろに。 

ゼロコスト エッジは現在の距離を増加させないため、そのエンドポイントはすでに 1 アント時間以上離れている頂点より前に処理する必要があります。 1 コストのエッジでは距離が 1 だけ増加するため、その端点は現在利用可能な同じ距離の頂点の後に属します。 
5. デキューが空になるまで続行します。 この時点で`dist[v]`は、ワームホール 1 から到達可能なすべてのワームホールまでの可能な最小コストです。`dist[n]`目的地までの最短の移動時間です。 
6. もし`dist[n]`まだ無限です、印刷します`IMPOSSIBLE`。 それ以外の場合は、次から開始します`n`そして繰り返しフォローする`parent[v]`頂点 1 に到達するまで。これにより、ルートが逆方向に作成されるため、印刷する前に逆方向にします。 
7. 再構築されたルートは、ワームホールを繰り返さないことが保証されます。 繰り返しの頂点が含まれている場合、2 つの頂点の間の部分はサイクルになります。 そのサイクルを削除すると、最短距離で表されるルートと同じくらい高価なルートが得られます。 先行チェーンは厳密に有効な最短距離緩和から形成されているため、結果として得られるパスは単純な最短パスとして選択できます。 

### なぜ効果があるのか

 中心的な不変条件は、頂点が両端キューから処理されるたびに、両端キューが現在の距離の減少しない順序で頂点を維持するということです。 コスト 0 のリラクゼーションは同じ距離を維持して前方に移動しますが、コスト 1 のリラクゼーションは距離をちょうど 1 大きくして後方に移動します。 したがって、ダイクストラのアルゴリズムの最初の最短距離処理動作は、優先キューなしで保存されます。 

すべての緩和は距離を厳密に小さい値に置き換えるだけであり、`parent[to]`新たな飛距離を実現するエッジを記録。 アルゴリズムが終了すると、目的地までの距離は 1 から n までのルートの最小コストになります。 すべてのエッジ コストは負ではないため、サイクルを含むすべてのウォークでは、コストを増加させることなくそのサイクルを削除できます。 したがって、最適な単純なルートが存在し、先行チェーンはそのような最適なルートを提供します。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b, t = map(int, input().split())
        graph[a].append((b, t))

    INF = 10**18
    dist = [INF] * (n + 1)
    parent = [-1] * (n + 1)

    dist[1] = 0
    dq = deque([1])

    while dq:
        v = dq.popleft()

        for to, w in graph[v]:
            nd = dist[v] + w

            if nd < dist[to]:
                dist[to] = nd
                parent[to] = v

                if w == 0:
                    dq.appendleft(to)
                else:
                    dq.append(to)

    if dist[n] == INF:
        print("IMPOSSIBLE")
        return

    path = []
    cur = n

    while cur != -1:
        path.append(cur)
        if cur == 1:
            break
        cur = parent[cur]

    path.reverse()

    print(dist[n], len(path))
    print(*path)

if __name__ == "__main__":
    solve()
```隣接リストは 1 から 1 までのインデックスを使用します。`n`、入力内の番号付けと一致します。 インデックス 0 に要素を追加すると、頂点番号から繰り返し 1 を減算することがなくなります。`dist`現在わかっている最小のアントアワー数を保存します。`parent`再構築に必要な先行ファイルを保存します。 先行要素は、厳密に小さい距離が見つかった場合にのみ変更されるため、常にその頂点に現在割り当てられている距離に対応します。 

両端キューは重要な実装の詳細です。`appendleft`コストゼロのエッジを処理しますが、`append`1コストエッジを処理します。 いずれかのエッジ タイプに間違った端を使用すると、0-1 BFS が依存する距離の順序付けが破壊されます。 

宛先は頂点 1 にすることができます。その場合`dist[1]`はすでにゼロであり、再構築ループはすぐにルートを生成します`[1]`。 

Python の整数は、無限値であってもオーバーフローしません。`10**18`とにかく十分すぎるほどです。 有効な最短パスのコストの最大値は、単純なパスのエッジの数にすぎないため、(10^5) 未満になります。 

再建は両親の後を追って行われます。`n`に戻る`1`、結果のリストを反転します。 明示的な`cur == 1`チェックをオンにすると、誤って続行することが防止されます`parent[1]`、つまり`-1`。

 ## 特殊なケース

 ### 開始は目的地と等しい

 のために```
1 0
```両端キューには最初に頂点 1 が含まれており、`dist[1]`はゼロです。 移行を処理する必要はありません。 再構築は次から始まります`n = 1`、すぐに停止して戻ります`[1]`。 出力は`0 1`に続く`1`。 これは、パスに少なくとも 1 つのエッジが含まれている必要があると想定した実装を捉える境界ケースです。 

### 到達不能な宛先

 のために```
2 0
```デキューには頂点 1 のみが含まれています。発信遷移がないため、頂点 2 は無限大のままです。 アルゴリズムは出力します`IMPOSSIBLE`従おうとする代わりに`parent[2]`。 このため、再構築前に到達可能性チェックを実行する必要があります。 

### コストゼロのサイクル

 検討してください```
3 3
1 2 0
2 1 0
2 3 1
```最初のゼロコスト移行セット`dist[2] = 0`そして`parent[2] = 1`。 処理 2 はエッジを検査して 1 に戻すことができますが、そのエッジは距離を再びゼロにし、厳密には既存の処理よりも優れているわけではありません。`dist[1] = 0`, したがって、1 の親は変更されません。 エッジ`2 -> 3`与える`dist[3] = 1`そして`parent[3] = 2`。 復興が生み出すもの`3 -> 2 -> 1`、これを反転すると、`1 -> 2 -> 3`。 禁止されたサイクルは、先行チェーンには決して入りません。 

### 複数の最適ルート

 のために```
4 4
1 2 1
1 3 1
2 4 0
3 4 0
```どちらの可能なルートでもコストは 1 です。 隣接順序と両端キュー処理に応じて、アルゴリズムは次のいずれかを選択できます。`1 2 4`または`1 3 4`。 距離が最適であり、すべての頂点が 1 回だけ表示されるため、両方とも有効です。 この問題では、そのような解決策が明示的に許可されているため、特定の 1 つの最短パスを決定的に選択する必要はありません。 

### 最大入力サイズ

 100,000 個の頂点と 99,999 個の遷移のチェーンでは、基本的にグラフ全体を処理するアルゴリズムが必要です。 各隣接エントリは緩和の一環として 1 回検査されますが、距離配列と親配列には 1 ベースのインデックス付けのため 100,001 要素のみが含まれます。 実行時間は線形のままで、メモリ消費量は入力サイズに比例します。 

中心的な教訓は、一見難しい「ワームホールを 2 回訪問しない」という条件では、最短パス状態で訪問したセットを追跡する必要がないということです。 非負のエッジ コストにより、最適なウォークから常にサイクルを削除できることが保証されるため、通常の最短パス アルゴリズムで十分です。 次に、ゼロまたは 1 のコスト制限により、ダイクストラの優先キューがデキューに削減され、(O(n+m)) の解が得られます。
