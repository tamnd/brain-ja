## アプローチ

 Самый прямой способ резения буквально повторяет действия администратора. Пока существуют неудалённые программы, можно просмотреть их все и найти такую программу, все зависимости которой ещё установлены。 Как только такая программа найдена, её можно удалить и продолжить. Если после полного прохода удалить ничего не получилось, остаются только программы, которые ждут друг друга, значит ответа нет。 

Такой алгоритм корректен, потому что на каждом заге он удаляет программу, удовлетворяющую исходному условию. Если существует некоторый допустимый порядок, то среди оставлихся программ обязательно существует хотя бы одна программа, которая должна удаляться следующей。 Но стоимость такого подхода слизком велика.

 Пусть`m`равно общему количеству зависимостей。 В худвем случае мы можем делать до`n`Проходов по программам, а проверка программ требует просмотра их зависимостей. Получается`O(n(n + m))`。 При`n = 1000`Їисло зависимостей может достигать`1000 * 999 = 999000`、 поэтому только повторная обработка зависимостей может потребовать до`1000 * 999000 = 999000000`。 1.5 を確認してください。 

Ключевая идея появляется, если посмотреть не на вопрос «можно ли сейчас удалить программу`i`?», а на то, сколько программ должно быть удалено перед каждой верзиной.

 Мы уже построили граф с ребром`i -> p`、`p`нужна для удаления`i`。 Тогда ребро говорит, что`i`должна стоять раньзе`p`और देखें ロシア語`v`её входящая степень показывает количество программ, которые обязаны быть удалены раньзе`v`。 

Если входящая степень верзины равна нулю, перед её удалением ничего делать не требуется. Значит、такая программа доступна прямо сейчас。 После её удаления все её исходящие рёбра становятся неактуальными, поэтому для каждой зависимости`p`уменьзается количество ещё не удалённых предбественников. Когда это количество становится нулём,`p`также становится доступной.

 Это ровно механизм топологической сортировки Кана. Разница только в интерпретации графа: здесь ребро направлено в сторону программы, которая должна быть удалена そうですね。 

Если в какой-то момент очередь доступных программ пуста, но удалены ещё не все программы, оставлийся граф ありがとうございます。 Цикл означает, что каждая программа в нём ждёт другую программу из того же цикла, поэтому начать удаление внутри цикла невозможно。

 ## アルゴリズムのチュートリアル

 1. Считаем зависимости и строим ориентированный граф. ждой строки программы`i`и каждой указанной программы`p`добавляем ребро`i -> p`。 Такое направление выбрано потому, что`i`должна быть удалена раньзе`p`。 
2. Одновременно увеличиваем`indegree[p]`。 Это количество программ, которые ещё должны быть удалены перед`p`。 Если`indegree[p] == 0`、 、 。`p`あなたの人生は、あなたの人生に最も近いものです。 
3. Все верлены снулевой входящей степенью помещаем в очередь. Их можно удалить в любом порядке. Мы используем обычную очередь`deque`、поэтому каждая верлечена будет извлечена ровно один раз.
 4. Извлекаем программу`v`из очереди и добавляем её в ответ。 После этого считаем`v`ユドアラス。 жля каждого ребра`v -> p`君は`indegree[p]`на единицу, потому что одна из программ, которая должна была быть удалена перед`p`、только что удалена。 
5. Если после уменьзения`indegree[p]`значение стало равно нулю, добавляем`p`Сочередь。 Теперь все программы, которые требовались перед удалением`p`、 уже удалены、поэтому`p`必要があります。 
6. Повторяем процесс, пока очередь не опустеет. Если в ответе оказалось ровно`n`программ, найден полный допустимый порядок. Если программ меньзе`n`, оставлиеся версины образуют зависимость, которую невозможно разрезить, поэтому выводим`-1`。 

### なぜ効果があるのか

 Главный инвариант состоит в том, что перед каждым извлечением программы`v`из очереди все её входящие рёбра уже были обработаны, а значит все программы, которые должны быть удалены ありがとう`v`、уже находятся в ответе。 Следовательно、`v`действительно можно удалить в этот момент.

 Когда программа`v`удаляется, каждое ребро`v -> p`означает、что одно требование для`p`теперь выполнено。 Именно поэтому мы уменьзаем`indegree[p]`。 Как только он становится нулём, все необходимые предのようにственники`p`уже удалены, и добавление`p`Ачередь безопасно.

 Если алгоритм не смог удалить все верbolины, то у оставлегося графа нет вер程ины с нулевой входящей степенью. Конечный ориентированный граф с таким свойством содержит цикл。 Внутри цикла каждая программа требует существования дрограммы из этого же цикла, поэтому первой あなたのことを考えてください。 Значит、`-1`действительно является правильным ответом。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n = int(input())

    graph = [[] for _ in range(n + 1)]
    indegree = [0] * (n + 1)

    for i in range(1, n + 1):
        data = list(map(int, input().split()))
        m = data[0]

        for p in data[1:]:
            graph[i].append(p)
            indegree[p] += 1

    q = deque()

    for v in range(1, n + 1):
        if indegree[v] == 0:
            q.append(v)

    answer = []

    while q:
        v = q.popleft()
        answer.append(v)

        for p in graph[v]:
            indegree[p] -= 1
            if indegree[p] == 0:
                q.append(p)

    if len(answer) != n:
        print(-1)
    else:
        print(*answer)

if __name__ == "__main__":
    solve()

|`1 -> 2`、`2 -> 1`、さらに独立した`3`|`-1`| サイクル検出 |
 | 長さのチェーン`1000`|`1 2 ... 1000`| 最大`n`、1 ベースのインデックス付け、および繰り返しのロック解除 |
 |`1 -> {2,3}`、`2 -> 4`、`3 -> 5`|`1 2 3 4 5`| いくつかの頂点が使用可能になり、エッジの方向が修正されました |

 最大サイズのチェーンは、off-by-one エラーを見つける場合に特に役立ちます。 プログラム`1000`プログラムには依存関係はありませんが、`999`正確に必要です`1000`したがって、有効なチェーンの方向は次のとおりです。`1, 2, ..., 1000`。 エッジの解釈を逆にすると、すぐに間違った順序が生成されます。 

## 特殊なケース

 ### 依存関係のない 1 つのプログラム

 のために```
1
0
```グラフには頂点が 1 つあり、エッジはありません。 受信次数は 0 であるため、すぐにキューに入ります。 アルゴリズムはそれを削除し、長さ 1 の答えを取得して出力します。`1`。 

すべてのプログラムに少なくとも 1 つの依存関係があると想定する不注意な実装は、たとえ`mi = 0`明示的に許可されています。 

### すべてのプログラムは独立しています

 のために```
4
0
0
0
0
```入力される 4 つの次数はすべて 0 であるため、最初のキューには次のものが含まれます。`[1, 2, 3, 4]`。 アルゴリズムはそれらをその順序で削除できます。 グラフが空であるため、エッジは処理されません。 

重要な特性は、トポロジー的順序が一意である必要がないことです。 最初に利用可能なプログラムは任意に選択できます。 

### サイクル

 検討してください```
3
1 2
1 1
0
```グラフには次の内容が含まれます`1 -> 2`そして`2 -> 1`。 最初は`indegree[1] = 1`そして`indegree[2] = 1`, そのため、どちらのプログラムもキューに入ることができません。 プログラム`3`は入力次数がゼロなので、最初に削除されます。 その後、キューは空になりますが、2 つのプログラムがまだ答えに含まれていません。 

以来`len(answer) != n`、アルゴリズムは出力します`-1`。 これはまさに、トポロジカルソートがサイクルを検出するポイントです。 

### 後で削除する必要がある依存関係

 検討してください```
3
1 3
1 3
0
```どちらのプログラムも`1`そして`2`プログラムが必要`3`インストールされたままになります。 グラフにはエッジがあります`1 -> 3`そして`2 -> 3`。 最初は`1`そして`2`受信次数がゼロなので、両方が使用可能です。 プログラム`3`その前に 2 つのプログラムを削除する必要があるため、まだ削除できません。 

有効な実行の 1 つは、`1`、 それから`2`、 それから`3`。 実装が誤ってエッジを次のように構築した場合`3 -> 1`そして`3 -> 2`、それは生成します`3`まず、これは元の削除条件に違反します。 

### 1 つのプログラムの複数の依存関係

 のために```
4
2 2 3
1 4
1 4
0
```プログラム`1`両方が必要です`2`そして`3`、一方、両方とも`2`そして`3`必要とする`4`。 グラフは```
1 -> 2
1 -> 3
2 -> 4
3 -> 4
```最初の角度ゼロの頂点は次のとおりです。`1`。 外した後はどちらも`2`そして`3`利用可能になります。 両方が削除された後にのみ、次数の入力が行われます。`4`ゼロに達します。 

アルゴリズムはこれを自然に処理します。`indegree[4]`は 2 から始まり、2 つの入力エッジごとに 1 回デクリメントされます。 

### 最大サイズのチェーン

 のために`n = 1000`、 考慮する```
1000
1 2
1 3
1 4
...
1 1000
0
```パターンが各プログラムで継続する場所`i`に応じて`i + 1`、つまり、プログラムの最後の行は`1000`は`0`。 

初期キューにはプログラムのみが含まれます`1`。 削除中`1`作る`2`利用可能、削除`2`作る`3`利用可能になるまで、など`1000`。 すべての頂点が 1 回処理され、すべてのエッジが 1 回処理されるため、最大許容値にもかかわらず、実行時間は実際の入力サイズに比例したままになります。`n`。 

これらすべてのケースから得られる主な教訓は、条件とは削除時のシステムの状態に関するものであるということです。 その条件が順序付け制約として表現されると、すべての依存関係が有向辺になり、問題全体がトポロジカルなソートにきれいに還元されます。
