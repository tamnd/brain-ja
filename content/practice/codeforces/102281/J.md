 ## 解決策
 ## 問題の理解

 (n) 個の個別のチェーンがあります。 (i) 番目のチェーンには (a_i) 個の環が含まれています。 操作では、1 つのリングを開いて元のチェーンから取り外し、2 つのチェーンの端の周りでそのリングを閉じます。 したがって、開いたリングは 2 つの部分の間のコネクターになります。 

目標は、できるだけ少ないリングを開いたり閉じたりしながら、1 つの接続されたチェーンを取得することです。 リングがどのチェーンから来たものであるかに関係なく、コストは正確に開かれたリングの数になります。 

重要な問題は、開いたリングが単に 2 つの既存のチェーン間の接続ではないことです。 同じ元のチェーンからいくつかのリングを開いた場合、そのチェーンは最終的にコネクタ リングに完全に分解できます。 (a_i) リングを備えたチェーンが完全に分解されると、(a_i) コネクタ リングが得られますが、そのチェーンを削除すると、接続する必要がある元のチェーンの 1 つも削除されます。 

(n) が (10^5) までの場合、(O(n^2)) の解はすでに遅すぎて、指数関数的なものはまったく実行不可能です。 値 (a_i) は (10^9) に達する可能性があるため、アルゴリズムはリングの総数ではなくチェーンの数に依存する必要があります。 並べ替えとそれに続く 1 回のリニア スキャンは、十分に高速です。 

単純な解釈が失敗する可能性があるいくつかの特殊なケースがあります。 チェーンが 1 つだけの場合は、操作は必要ありません。 たとえば、入力`1 / 100`答えがあります`0`、チェーンはすでに接続されているためです。 常に (n-1) 個の接続を想定するソリューションでは、誤った出力が発生します。`1`。 

1 つの環を含むチェーンは特に価値があります。 のために`3 / 1 6666 100500`、答えは`1`。 最初のチェーンの 1 つのリングを開き、それを使用して他の 2 つのチェーンを接続します。 元のマージごとに 1 つの操作を実行することを要求する単純なソリューションでも、依然として次のような問題が発生します。`2`、それは間違いです。 

いくつかの短いチェーンを組み合わせて使用​​することもできます。 のために`4 / 1 1 1 100`、答えは`2`。 2 つの 1 リング チェーンを完全に開いて 2 つのコネクタ リングを提供し、残りのピースをこれら 2 つのコネクタで 1 つのチェーンに配置できます。 コネクタは最終チェーンで隣接する可能性があるため、開いたすべてのリングを接続するために別個の元のチェーンが必要であるものとして扱うと、有効な構造が失われます。 

## アプローチ

 直接的な総当たりアプローチは、どの元のチェーンを完全にオープンするかを決定することです。 選択したセット (S) の場合、それらのチェーン内のすべてのリングを開くにはコストがかかります

 [
 K=\sum_{i\in S} a_i。 
】

 (r=|S|) とします。 (S) のチェーンは、すべてのリングがコネクタとして利用できるため、別個の部分として消えます。 他の (n-r) チェーンは、それぞれ 1 つのピースとしてそのまま残ります。 (K) 個のコネクタ リングを使用すると、1 つのチェーンを形成するために最大で (K+1) 個のそのようなピースが必要になるため、選択はまさに次の場合に実行可能です。 

[
 n-r\le K+1、
 】

 または同様に、

 [
 \sum_{i\in S}(a_i+1)\ge n-1。 
】

 したがって、総当りアルゴリズムは、(n) 個のチェーンのすべてのサブセットを列挙し、この不等式をチェックし、最小値 (\sum a_i) を維持することができます。 (2^n) 個のサブセットがあり、(O(n)) で各サブセットを評価しても (O(n2^n)) 個の演算が行われます。 (n=10^5) の場合、サブセットの列挙だけでも (2^{100000}) 件のケースが必要になるため、このアプローチはリモートでは実行できません。 

有益な観察は、長さ (a_i) のチェーンの選択にはコスト (a_i) がかかりますが、実現可能条件に (a_i+1) が寄与するということです。 貢献とコストの差は常に 1 です。 

正確に (k) 個のチェーンを選択すると決めたとします。 満足するには全長が必要です

 [
 \sum a_i+k\ge n-1。 
】

 (k) 個のチェーンのすべてのセットの中で、(k) 個の最小の長さを持つセットのコストが最小になります。 それらの (k) チェーンですらこの不等式を満たさない場合、他の (k) チェーンのセットはより少ないコストでこの不等式を満たすことはできません。 すべての (a_i) が正であるため、チェーンを追加するとプレフィックスのコストが増加するため、条件が true になるまで長さをソートして最短のチェーンを取得するだけで済みます。 

これにより、指数関数的な検索が、単一のスキャンが後に続く並べ替え問題に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n2^n)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのチェーンの長さを非降下順に並べ替えます。 完全に開いたチェーンのセットを可能な限り安価にしたいので、選択したチェーンの固定数ごとに、最も短いチェーンを優先する必要があります。 
2.初期化`opened = 0`そして`count = 0`。 ここ`opened`はオープンする予定のリングの総数です。`count`完全に開いたチェーンの数です。 
3. ソートされた長さを最小から最大まで処理します。 現在のチェーンの長さを追加します`opened`そして増加します`count`1つずつ。 
4. (a) の長さのチェーンを追加した後、

 [
 開いた+カウント\ge n-1。 
】

 左側は、選択したチェーンのちょうど (\sum(a_i+1)) です。 (n-1) に到達すると、残りのすべての部分を 1 つのチェーンに配置するのに十分な開いたリングと完全に解体されたチェーンが存在します。 
5. 条件を満たす最初のプレフィックスで停止し、出力します。`opened`。 長さが正であるため、選択されたチェーンが追加されるたびに答えが増加するため、最初の実行可能なプレフィックスが最適になります。 

### なぜ効果があるのか

 有効な構造を考えて、(S) をすべてのリングが開かれた元のチェーンのセットとします。 (K) を開いたリングの総数とし、(r=|S|) とします。 外側のすべてのチェーン (S) には、開かれていないリングが少なくとも 1 つ含まれているため、少なくとも 1 つの無傷の部分が含まれています。 そのような部分は (n-r) 個あります。 (K) 個の開いたコネクタ リングを含むシーケンスは、最大で (K+1) 個の空でない部分を分離できます。 

[
 n-r\le K+1。 
】

 並べ替えると

 [
 K+r\ge n-1、
 】

 それはまさに

 [
 \sum_{i\in S}(a_i+1)\ge n-1。 
】

 逆に、この不等式が成り立つ場合は、選択したチェーン内のすべてのリングを開きます。 それらの (K) リングはコネクタ位置として機能し、(n-r) 個の残りの元のチェーンは空ではない部分として機能します。 (n-r\le K+1) なので、これらのピースとコネクタ リングを 1 つのチェーンとして注文できます。 したがって、この不等式は必要かつ十分です。 

固定数 (k) の選択されたチェーンの場合、選択されたチェーンをより短い未選択のチェーンに置き換えても、総コストが増加することはなく、選択の有用性が低下することはありません。これは、そのコストとその寄与の両方がまったく同じ量だけ減少するためです。 したがって、(k) 個の最も短いチェーンが常に最も安価な候補になります。 したがって、プレフィックスをスキャンすると、グローバルな最小コストが見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    opened = 0

    for count, length in enumerate(a, 1):
        opened += length

        if opened + count >= n - 1:
            print(opened)
            return

if __name__ == "__main__":
    solve()
```入力は 1 回読み取られ、最適に選択されたチェーンがソート順のプレフィックスを形成するため、配列がソートされます。 変数`opened`選択したチェーンのリングの総数を保存します。 

の`enumerate(a, 1)`電話をかける`count`ゼロベースのインデックスではなく、選択したチェーンの数に等しくなります。 これにより、条件における簡単なオフバイ 1 エラーが回避されます。 加工後`count`チェーンの場合、実現可能性の式は次のようになります。`opened + count >= n - 1`。 

答えは、最初の実行可能なプレフィックスが見つかるとすぐに出力されます。 すべてのリング数は正であるため、続行する必要はありません。そのため、チェーンを追加しても増加するだけです。`opened`。 

Python の整数には任意の精度があるため、可能な合計の最大値 (10^5\cdot10^9=10^{14}) には、いずれにしても特別なオーバーフロー処理は必要ありません。 

## 実用的な例

 最初のサンプルの入力は次のとおりです。`5 / 3 3 3 3 3`。 

| カウント | 現在の長さ | 開いた | 開封済み + カウント | 実現可能 |
 | --- | --- | --- | --- | --- |
 | 1 | 3 | 3 | 4 | はい |

 最初のチェーンはすでに (3+1=4=n-1) を与えています。 3 つのリングを開くと、他の 4 つのチェーンを結合するために必要な 3 つのコネクタが正確に提供されるため、答えは次のようになります。`3`。 

2 番目のサンプルの入力は次のとおりです。`3 / 1 6666 100500`。 

| カウント | 現在の長さ | 開いた | 開封済み + カウント | 実現可能 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 2 | はい |

 ここでは (n-1=2) となります。 1 リング チェーンは 1 つのコネクタを提供するのに十分であり、元のチェーンを削除すると、個別のチェーンの数が 1 つ減ります。 残りの 2 つのチェーンには接続が 1 つだけ必要なので、答えは次のようになります。`1`。

import sys
import io

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    a.sort()

    opened = 0

    for count, length in enumerate(a, 1):
        opened += length
        if opened + count >= n - 1:
            print(opened)
            return

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

 ## 特殊なケース

 のために`1 / 1000000000`、チェーンの初期数はすでに 1 です。 しきい値は (n-1=0) であるため、アルゴリズムは何も選択する必要がなく、次の値を返します。`0`。 これにより、少なくとも 1 つの開いたリングを盲目的に要求するというよくある間違いが見つかります。 

のために`2 / 1 1`、最初にソートされたチェーンの長さは (1) です。 それを選択した後、`opened = 1`そして`count = 1`、与える`opened + count = 2`、これは少なくとも (n-1=1) です。 答えは`1`。 片方のリングは開いて、2本のオリジナルチェーンを接続するために使用されます。 

のために`4 / 1 1 1 100`、選択された 1 つのチェーンの後、値は (1+1=2) となり、必要な (3) を下回ります。 2 つのチェーンを選択すると (2+2=4) になるため、アルゴリズムは次の値を返します。`2`。 2 つの開いたリングは両方とも、最終チェーンのコネクタ位置として表示されます。 この場合は、コネクタ リングが元のチェーンと 1 対 1 で対応する必要がないため便利です。 

それぞれ 1 つのリングの (100000) チェーンがある最大の場合、(k) チェーンを選択した後、次のようになります。`opened = k`そして`count = k`。 条件は (2k\ge99999) となり、その最小の整数解は (k=50000) になります。 結果的に答えは`50000`。 これは、しきい値の境界と、答えが (n) のおよそ半分になる可能性があるという事実の両方を検証します。
