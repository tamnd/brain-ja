 ## 問題の理解

 同一のジェネレーターのコレクションがあります。 ドキュメントには正確にそれが書かれています`n`発電機が生産する`k`間のジュール`m`分。 必要なシステムは少なくとも`q`間のジュール`p`分。 この要件を満たす最小の整数のジェネレーターが必要です。 

5 つの入力値は次のとおりです。`n`、`m`、`k`、`p`、 そして`q`。 最初の 3 つは発電機の生産速度を表します。`p`そして`q`必要なエネルギー量とそれを生成する必要がある時間を説明します。 出力は、設置する必要がある発電機の最小数です。 

重要なのは、生産は発電機の数と時間の両方において線形であるということです。 もし`n`発電機が生産する`k`ジュール`m`数分後に 1 つのジェネレーターが生成します`k / (n * m)`毎分ジュール。 と`x`発電機、その際に生成される量`p`分は`x * p * k / (n * m)`。 

少なくともこの量が必要です`q`、 それで`x * p * k / (n * m) >= q`。 

正の分母を掛けた後、`x * p * k >= n * m * q`。 

したがって、答えはこの不等式を満たす最小の整数になります。 

5 つの値はすべて最大でも`10^6`。 彼らの製品が到達できるのは、`10^18`したがって、実装はそのサイズの整数値に対応できる必要があります。 答え自体が次のような大きさになる可能性があるため、可能な数のジェネレーターをループすることは実行できません。`10^18`。 目的のソリューションには、一定の時間と一定のメモリが必要です。 

実装を簡単に壊す可能性のある境界ケースがいくつかあります。 必要な量が正確に達成できるのであれば、不必要な発電機を追加する必要はありません。 たとえば、`1 1 1 1 1`、1 つの発電機はちょうど 1 ジュールを生成するため、答えは次のようになります。`1`。 1 を追加した後に常に切り上げられる不注意な実装では、次のエラーが返されます。`2`。 

逆のケースは、必要な量が 1 つの構成で生成される量よりわずかに大きい場合です。 のために`2 2 2 1 3`、2 つのジェネレーターはのみを生成します。`2`3 つの発電機が 1 分間にジュールを生成します。`3`、したがって、正しい答えは次のとおりです。`3`。 上限除算の代わりに通常の整数除算を使用すると、次の結果が不正確になります。`2`。 

大型製品はもう 1 つの実装境界です。 のために`1000000 1000000 1 1 1000000`、必要な数は`10^18`。 固定幅の整数型を使用する言語では、中間積に十分な幅の整数型が必要です`n * m * q`。 Python の整数は自動的に増加するため、この場合は特別なオーバーフロー処理は必要ありません。 

## アプローチ

 直接的なアプローチは、1 つのジェネレーター、次に 2 つ、次に 3 つというように試していくことです。 すべての候補者に対して`x`かどうかを確認できます。`x * p * k >= n * m * q`。 

生産量は単調増加するため、これは正しいです。`x`。 候補者が十分であれば、それより大きな数もすべて十分であるため、最初に成功した候補者がまさに最小値となります。 

問題は、最初の合格者がどのくらいの規模になるかということです。 考慮する`n = m = q = p = 10^6`そして`k = 1`。 答えは`10^6 * 10^6 * 10^6 / 1 = 10^18`。 

ループは最大で実行されます。`10^18`これは妥当な制限時間をはるかに超えています。 このブルートフォース手法の時間計算量は次のとおりです。`O(answer)`、そして最悪のケースは`O(10^18)`操作。 

実行可能な答えの単調なシーケンスが存在するため、ブルート フォースが機能しますが、実際にはそのシーケンスを検索する必要はありません。 不等式は代数的に変換でき、答えが直接得られます。 

させて`A = n * m * q`そして`B = p * k`。 

最小の整数が必要です`x`そのような`x * B >= A`。 正の整数の場合、その最小値は次の上限になります。`A / B`:`x = ceil(A / B)`。 

整数の上限除算は次のように記述できます。`(A + B - 1) // B`。 

ここにさらに安全かつクリーンに記述する方法があります。`A // B + (A % B != 0)`。 

後者は追加を避けます`B - 1`ただし、Python はどちらの形式でも安全に処理できます。 すべての入力が正であるため、`B`決してゼロではありません。

 ## アルゴリズムのチュートリアル

 1.読む`n`、`m`、`k`、`p`、 そして`q`。 これらの値によって、生産速度と必要なエネルギーが完全に決まります。 
2. コンピューティング`required = n * m * q`。 これは、生産不平等から端数を除いた右側に表示される合計金額です。 
3. コンピューティング`per_generator = p * k`。 これは、必要な発電量に対する 1 つの発電機の寄与です。`p`分。以下と同じ整数スケーリングを使用して表現されます。`required`。 
4. 上限を計算します。`required / per_generator`使用して`required // per_generator + (required % per_generator != 0)`。 余りは正確な除算が可能かどうかを示します。 余った場合はさらに1台の発電機が必要となります。 
5. 結果の値を出力します。 生産量がそれ以上になる最小の整数です。`q`ジュール。 

### なぜ効果があるのか

 中心的な不変式は不等式です`x * p * k >= n * m * q`。 可能なすべてのジェネレータの数について`x`、両辺は元の不等式に正の値を乗じることによって得られるため、この不等式は元のエネルギー必要量と等価です。`n * m`。 アルゴリズムはしきい値の数学的上限を計算します。`n * m * q / (p * k)`, したがって、戻り値は要件を満たします。 これより小さい整数はそのしきい値を下回っており、要件を満たすことができず、最小性が証明されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k, p, q = map(int, input().split())

    required = n * m * q
    per_generator = p * k

    answer = required // per_generator
    if required % per_generator != 0:
        answer += 1

    print(answer)

if __name__ == "__main__":
    solve()

剰余チェックは、正確に割り切れる境界を処理します。 もし`required`で割り切れます`per_generator`、商はすでに必要なエネルギーを正確に生成しています。 それ以外の場合、商は定義上不十分であるため、もう 1 つのジェネレーターが必要になります。

 ## 特殊なケース

 最初の特殊なケースは、正確に割り切れる場合です。 のために`2 3 6 2 4`、必要なスケーリング量は次のとおりです。`2 * 3 * 4 = 24`、および 1 つのジェネレーターが貢献します`2 * 6 = 12`同じスケール表現で。 商はまさに`2`剰余はゼロなので、アルゴリズムは次の値を返します。`2`。 整数の除算の後に盲目的に 1 を加算する数式は、誤った値を返します。`3`。 

2 番目のエッジ ケースは、ジェネレーターの 2 つの整数の間に厳密に該当する要件です。 のために`2 2 2 3 4`、閾値は`16 / 6`。 整数除算は次のようになります`2`、 しかし`2 * 6 = 12`では不十分です。 剰余がゼロでないため、アルゴリズムは結果を次のように増分します。`3`、 そして`3 * 6 = 18`要件を満たします。

最大の算術ケースは次のとおりです。`1000000 1000000 1 1 1000000`。 ここで分子は`10^18`そして分母は`1`、つまり、答えは正確に`10^18`。 ループベースのソリューションには、最大で次のものが必要です。`10^18`最適解では 1 回の除算と 1 回の剰余演算が実行されます。 Python の任意精度の整数は、この値を正確に表します。
