 ## 解決策
 ## 問題の理解

 辺の長さが (a)、(b)、(c) である三角形のクッキー カッターと、半径 (r) の円形のクッキー カッターがあります。 クッキーは薄いので、問題は純粋に 2 次元の問題です。円形のクッキーは三角形のカッターの内側に完全に配置できますか?また、三角形のクッキーは円形のカッターの内側に完全に配置できますか?

 最初の質問は、三角形の中に収まる最大の円を尋ねます。 その円は三角形の内接円なので、関連する量は内半径になります。 

2 番目の質問は、三角形全体を含むことができる最小の円を尋ねます。 このような円は三角形の外接円によって決定されるため、関連する量は外周半径です。 

入力には 1 ～ 10000 の 4 つの整数が含まれます。これらの境界は (O(1)) 解としては非常に小さく、処理する三角形が 1 つしかないため、線形アルゴリズムさえも不要です。 主な関心事は実行時間ではなく、数値の正確さです。 Heron の公式を使用した浮動小数点の直接計算では、答えが変わる境界で正確に丸め誤差が発生する可能性があります。 

不注意な実装が失敗する可能性があるエッジケースがいくつかあります。 考慮する```
1 1 1 1
```三角形は正三角形です。 その内半径は (\sqrt{3}/6) で、1 未満ですが、外周半径は (\sqrt{3}/3) で、これも 1 未満です。両方の Cookie が適合するため、両方の答えが正である必要があります。 半径内と円半径を混同する実装では、答えの 1 つが間違ってしまいます。 

より有用な境界ケースは次のとおりです。```
2 2 2 1
```ここで、外周半径は (2/\sqrt{3}) で、1 より大きく、内半径は (1/\sqrt{3}) で、1 より小さいです。 したがって、円は三角形に適合しますが、三角形は円には適合しません。 両方向に同じ半径基準を使用すると、誤った結果が得られます。 

正確な境界も包括的に処理する必要があります。 例えば、```
2 2 2 1
```はたまたま境界上にはありませんが、辺 1 を持つ正三角形とその半径が正確にその内半径である円は適合します。 比較には使用する必要があります`>=`、 ない`>`。 

最後に、辺は 10000 まで大きくなるため、Python では Heron の式を直接計算するのは安全ですが、固定幅整数言語での実装では、算術演算を慎重に選択する必要があります。 関係する最大の積は (10^{16}) 程度で、これは符号付き 64 ビット整数には収まりますが、符号付き 32 ビット整数には収まりません。 

## アプローチ

 素朴な幾何学的なアプローチでは、物理的な挿入プロセスをシミュレートしようとします。 円については、多くの可能な位置と向きを試し、円が 3 つの辺のいずれかを横切るかどうかをテストできます。 円内の三角形についても、同様に位置と回転を列挙できます。 問題は、位置と回転が連続変数であるため、正確で最適な検索を保証する有限総当たり検索が存在しないことです。 角度を (N) 値に離散化し、位置を (M) 値に離散化すると、結果の検索コスト (O(NM)) がチェックされますが、その答えは選択した離散化によって異なります。 最悪の場合、任意に細かいグリッドでも有効な配置を見逃す可能性があるため、このような方法を正確な解決策とする有限の演算回数は存在しません。 

ブルートフォースのアイデアには、有益な特性が 1 つあります。それは、極端な配置を検索するため機能するということです。 円ができるだけ大きい場合は、その中心を特別な点に置く必要があります。円ができるだけ小さい場合は、三角形を特別な囲み円に関連付ける必要があります。 それらの配置を検索する代わりに、数学的に識別できます。 

三角形の場合、最大の内接円の半径は内半径に等しい

 [
 \rho = \frac{A}{s},
 ]

 ここで、(A) は三角形の面積、(s=(a+b+c)/2) はその半周長です。 円形のクッキーは (r\geq\rho) のときに正確に適合します。 

逆に、3 つの頂点をすべて含む最小の円の半径は外周半径と同じになります。 

[
 R = \frac{abc}{4A}。 
]

 (r\geq R) のとき、三角形は円形カッターに正確に収まります。 

残りの問題は、浮動小数点演算を回避することです。 ヘロンの公式は次のことを与えます

 [
 A^2=s(s-a)(s-b)(s-c)。 
]

 すべてに 16 を掛けて定義する方が便利です。 

[
 D=(a+b+c)(-a+b+c)(a-b+c)(a+b-c)=16A^2。 
]

 次に、(4A=\sqrt D) となります。 イン半径条件は次のようになります。 

[
 r\geq\frac{\sqrt D}{2(a+b+c)}。 
]

 両辺は非負なので、二乗することができます。 

[
 4r^2(a+b+c)^2\geq D.
 ]

 外周半径については、

 [
 R=\frac{abc}{\sqrt D},
 ]

 それで

 [
 r\geq R
 ]

 と同等です

 [
 r^2D\geq a^2b^2c^2。 
]

 どちらの決定も正確な整数比較になりました。

 ## アルゴリズムのチュートリアル

 1. 辺の長さ (a、b、c) と円の半径 (r) を読み取ります。 3 つの辺の長さは 1 つの三角形を表すため、最初に必要な幾何学量はその正方形の面積です。 
2. コンピューティング

 [
 D=(a+b+c)(-a+b+c)(a-b+c)(a+b-c)。 
]

 (D=16A^2) なので、その平方根は (4A) です。 実際にその平方根を計算する必要はありません。 

1. 円が三角形の中に収まるかどうかを確認します。 

[
 4r^2(a+b+c)^2\geq D.
 ]

 これはまさに条件 (r\geq\rho) です。(\rho) は三角形の半径です。 

1. 三角形が円の中に収まるかどうかを確認します。 

[
 r^2D\geq a^2b^2c^2。 
]

 これはまさに条件 (r\geq R) です。(R) は外周半径です。 

1. 各比較に対応する文を出力します。 クッキーがカッターに触れることを許可されているため、同等であるとみなされる。 

### なぜ効果があるのか

 三角形の内側に配置できる最大の円はその内円であるため、最初の方向については内半径を確認することが必要かつ十分です。 非縮退三角形のすべての頂点を含む最小の円がその外接円であるため、2 番目の方向については外接半径をチェックするだけで十分です。

(D) の値は (D=16A^2) を満たします。 この恒等式を内半径と外周半径の式に代入すると、両方の幾何学的条件が正確な整数不等式に変換されます。 すべての変換では比較の方向が保持され、二乗されるすべての量は非負であるため、アルゴリズムは元の幾何学的問題と同じ答えを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, b, c, r = map(int, input().split())

p = a + b + c

# 16 * area^2
d = p * (-a + b + c) * (a - b + c) * (a + b - c)

# Circle fits into triangle iff r >= inradius.
circle_in_triangle = 4 * r * r * p * p >= d

# Triangle fits into circle iff r >= circumradius.
triangle_in_circle = r * r * d >= a * a * b * b * c * c

if circle_in_triangle:
    print("Circle gets into the triangle")
else:
    print("Circle doesn’t get into the triangle")

if triangle_in_circle:
    print("Triangle gets into the circle")
else:
    print("Triangle doesn’t get into the circle")
```変数`p`は (a+b+c) を格納します。これは Heron の式と inradius 比較の両方に現れます。 変数`d`は (16A^2) であり、ソリューション全体で次のことを回避できます。`sqrt`。 

最初の比較では、コードは次を使用します。```
4 * r * r * p * p >= d
```なぜなら

 [
 r\geq\frac{\sqrt D}{2p}
 ]

 と同等です

 [
 4r^2p^2\geq D.
 ]

 2 番目の比較では、コードは次を使用します。```
r * r * d >= a * a * b * b * c * c
```なぜなら (R=abc/\sqrt D) だからです。 どちらの場合も平等が意図的に受け入れられています。 

Python の整数には任意の精度があるため、オーバーフローの心配はありません。 C++ などの言語では、これらの制約には 64 ビット整数で十分です。 入力にはテスト ケースが 1 つだけ含まれているため、計算のループはありません。 

正確な出力文字列 (中アポストロフィを含む) を保持する必要があります。`doesn’t`これは、Codeforces が出力テキストを直接比較するためです。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    a, b, c, r = map(int, input().split())

    p = a + b + c
    d = p * (-a + b + c) * (a - b + c) * (a + b - c)

    circle_in_triangle = 4 * r * r * p * p >= d
    triangle_in_circle = r * r * d >= a * a * b * b * c * c

    first = (
        "Circle gets into the triangle"
        if circle_in_triangle
        else "Circle doesn’t get into the triangle"
    )
    second = (
        "Triangle gets into the circle"
        if triangle_in_circle
        else "Triangle doesn’t get into the circle"
    )

    return first + "\n" + second

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve()
    finally:
        sys.stdin = old_stdin

# Provided sample 1
assert run("1 1 1 10\n") == (
    "Circle doesn’t get into the triangle\n"
    "Triangle gets into the circle"
), "sample 1"

# Provided sample 2
assert run("10 10 10 1\n") == (
    "Circle gets into the triangle\n"
    "Triangle doesn’t get into the circle"
), "sample 2"

# Minimum-size valid triangle
assert run("1 1 1 1\n") == (
    "Circle gets into the triangle\n"
    "Triangle gets into the circle"
), "minimum-size values"

# Maximum-size equilateral triangle
assert run("10000 10000 10000 10000\n") == (
    "Circle gets into the triangle\n"
    "Triangle gets into the circle"
), "maximum-size values"

# Exact inradius boundary for a 3-4-5 triangle:
# inradius = 1, circumradius = 2.5
assert run("3 4 5 1\n") == (
    "Circle gets into the triangle\n"
    "Triangle doesn’t get into the circle"
), "inradius boundary"

# Exact circumradius boundary for a 3-4-5 triangle
assert run("3 4 5 3\n") == (
    "Circle gets into the triangle\n"
    "Triangle gets into the circle"
), "circumradius boundary"

print("All tests passed.")

```(D=3) が得られます。 円の条件は (4\cdot1^2\cdot3^2=36\geq3)、三角形の条件は (1^2\cdot3=3\geq1) です。 どちらの比較も成功します。 この例では、方向の 1 つに対して間違った半径式を誤って使用する実装を検出します。 

半径 1 の 3-4-5 三角形の場合、```
3 4 5 1
```面積は 6 なので、半径は (6/6=1) になります。 円は最適な配置で 3 つの側面すべてに正確に触れており、受け入れられる必要があります。 外周半径は (3\cdot4\cdot5/(4\cdot6)=2.5) なので、三角形は当てはまりません。 このケースは厳密な条件を満たしています`>`比較。 

半径 3 の同じ三角形の場合、```
3 4 5 3

10000 10000 10000 10000
