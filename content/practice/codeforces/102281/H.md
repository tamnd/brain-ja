 ## 解決策
 ## 問題の理解

 マッチ箱が 2 つあり、それぞれのマッチ箱には最初から正確な内容が含まれています。`n`一致します。 プロフェッサー X はマッチが必要になるたびに、2 つのポケットのうち 1 つを均一にランダムに選び、その箱からマッチを取り出そうとします。 このプロセスは、彼がすでに空になっている箱を選択した瞬間に終了します。 

タスクは、その時点で他のボックスにまだ存在する一致の予想数を計算することです。 

唯一の入力は、`n`、 と`1 <= n <= 30`。 上限は十分に小さいため、アルゴリズムでも多項式になります。`n`簡単に十分速いでしょう。 ただし、すべてのランダム選択履歴を直接列挙すると指数関数的になるため、問題の興味深い部分は、あらゆる可能性をシミュレートするのではなく、停止履歴の組み合わせ構造を認識することです。 

誤って処理されやすい境界ケースが 2 つあります。 まず、もう一方のボックスにはすべてを含めることができます。`n`一致します。 たとえば、`n = 1`、教授は同じポケットを 2 回選択する可能性があります。最初の選択では唯一の一致が削除され、2 番目の選択ではそのボックスが空であるが、もう一方のボックスにはまだ入っていることがわかります。`1`マッチ。 実際、期待される答えは、`n = 1`は`0.5`。 他のボックスがすでに使用されている状況のみを考慮する実装では、このケースを誤って見逃してしまいます。 

第 2 に、最後の空箱の発見は失敗した選択であるため、特定の履歴の確率に含める必要があります。 のために`n = 2`、正解は`0.875000000000000`。 代わりに、ボックスが最後に成功した一致を受け取ったときにすぐに停止すると、別のランダム実験を解くことになり、間違った期待値が得られることになります。 

上限`n = 30`数値的な懸念も明確にします。 表示される 2 の最大の指数は次のとおりです。`2n = 60`したがって、必要な場合は通常の倍精度で十分です。`1e-6`エラー許容度。 

## アプローチ

 直接的な総当りの解決策では、空のボックスが見つかるまで、考えられるすべてのポケット選択シーケンスを生成できます。 それぞれの選択には 2 つの可能性があるため、失敗した最後の選択を考慮すると、歴史の長さは最大でも長くなります。`2n + 1`。 のために`n = 30`、この最大長のバイナリ文字列をすべて列挙すると、次のようになります。`2^61`、 約`2.3 * 10^18`、候補者の履歴。 すべての履歴について最大 61 の選択肢をシミュレートするには、次のオーダーが必要になります。`61 * 2^61`、 だいたい`1.4 * 10^20`基本的な操作。 それはまったく不可能です。 

すべての可能なシーケンスには単純な確率、つまり次の累乗があるため、ブルート フォースが機能します。`1/2`。 この失敗は、最終的な残りの一致数が同じになる場合でも、異なる順序を別々に扱うことから発生します。 

空の箱が発見されたとき、もう一方の箱には正確に中身が入っていたとします。`k`一致します。 空のボックスが選択されているはずです`n`最終的な選択が失敗するまでに、成功する回数が 2 回に達します。 他のボックスは正確に選択されている必要があります`n-k`回。 その結果、最終的に失敗した選択の前に、正確に`n + (n-k) = 2n-k`成功した選択。 

最終的にどのボックスが空であるかが固定的に選択される場合、最初のボックスは`2n-k`選択肢には正確に含まれます`n`そのボックスの選択と`n-k`他のボックスの選択。 がある`C(2n-k, n)`これらの選択肢を整理する方法。 

そのような取り決めはすべて有効です。 最終的な選択の前に、空になるボックスは正確に使用されました`n`他のボックスには少なくとも`k`マッチが残っています。 したがって、どちらの箱も以前は空ではなかったはずです。 

最後の選択では、すでに使い果たされたボックスを選択する必要があります。 その選択肢を含めると、次の確率が得られます。`C(2n-k, n) / 2^(2n-k+1)`特定の 1 つのボックスが最初の空のボックスになるようにします。 どちらのボックスもその役割を果たすことができ、2 つのケースの確率は等しいです。 したがって`P(k) = C(2n-k, n) / 2^(2n-k)`。 

したがって、予想される残りの一致数は次のようになります。`E = sum(k * P(k))`のために`k = 0..n`。 

しかないので、`n+1`可能な値`k`、私たちは問題を、指数関数的に多くの歴史からたった一つのものに減らしました。`O(n)`確率の用語。 

これらの項は、二項係数を繰り返し計算することなく評価できます。 から始める`k = n`。 この場合、他のボックスは選択されていないため、`P(n) = 1 / 2^n`。 

減少する場合`k`、連続する確率間の比率は次のようになります。`P(k-1) / P(k) = (2n-k+1) / (2(n-k+1))`。 

したがって、次のすべての確率は、一定量の演算を使用して前の確率から取得できます。

 ## アルゴリズムのチュートリアル

 1.読む`n`。 正確に確率を計算します`k`マッチは空ではなかったボックスに残ります。 
2. から始める`k = n`そして確率`p = 2^(-n)`。 これは同じボックスを選択することに相当します`n`何度か成功してから、もう一度同じボックスを選択します。 したがって、もう一方のボックスには一度も触れられていません。 
3.追加`k * p`期待値に。 これは、現在考えられる残りの一致数の寄与です。 
4. から移動する`k`に`k-1`。 を使用して確率を更新します`p *= (2*n-k+1) / (2*(n-k+1))`。 

この漸化式は 2 つの二項確率式の比から直接取得されるため、大規模な組み合わせ計算が回避されます。 
5. まで続けます`k = 0`。 値`k = 0`教授が最終的にどちらかのボックスを発見したときには両方のボックスが空である可能性があるため、これは有効です。 期待値への寄与はゼロですが、確率は依然として分布の一部です。 
6. 必要な精度を満たすのに十分な小数点以下の桁数を使用して累積期待値を出力します。 

### なぜ効果があるのか

 あらゆる可能性に対して`k`、まさに停止履歴`k`他のボックスに残っている一致は正確にあります`n`ボックスからの選択が成功すると空になり、正確に`n-k`最後の選択が失敗する前に、他のボックスから成功した選択が行われます。 それらのポジションの選択`n`選択により得られる`C(2n-k,n)`有効なプレフィックスを選択し、最終的な選択が強制されます。 どちらかのボックスが空であることを考慮すると、正確な確率が得られます。`P(k)`アルゴリズムによって使用されます。 これらのイベントは相互に排他的であり、考えられるすべての停止履歴をカバーするため、合計すると`k * P(k)`必要な期待値を正確に与えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    # Probability that exactly n matches remain in the other box.
    p = 2.0 ** (-n)
    ans = 0.0

    for k in range(n, -1, -1):
        ans += k * p

        if k > 0:
            p *= (2 * n - k + 1) / (2 * (n - k + 1))

    print(f"{ans:.15f}")

if __name__ == "__main__":
    solve()
```変数`p`の現在値の確率を表します。`k`。 から始めます`k = n`その確率は最も単純な形をしているので、`2^-n`。 

ループは、可能なすべての値を訪問します。`k`まさに一度。 表現`ans += k * p`数学的期待値の定義を直接適用します。 

アップデートは次の場合にのみ実行されます。`k > 0`。 で`k = 0`の場合、次に計算する確率はなく、再帰を試みると無効な境界式で除算されます。 

すべての演算は Python 浮動小数点で行われます。 最大の指数はわずか 60 で、反復回数は最大 31 回であるため、累積された数値誤差は必要な誤差をはるかに下回ります。`1e-6`。 

実装では二項係数がまったく構築されないため、整数オーバーフローは発生しません。 反復では、小さな整数因数と浮動小数点除算のみが使用されます。

import sys
import io

def solve():
    import sys
    input = sys.stdin.readline

    n = int(input())
    p = 2.0 ** (-n)
    ans = 0.0

    for k in range(n, -1, -1):
        ans += k * p
        if k > 0:
            p *= (2 * n - k + 1) / (2 * (n - k + 1))

    print(f"{ans:.15f}")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

def reference(n: int) -> float:
    # Independent calculation using the closed-form probability.
    import math

    ans = 0.0
    for k in range(n + 1):
        p = math.comb(2 * n - k, n) / (2.0 ** (2 * n - k))
        ans += k * p
    return ans

# Provided samples.
assert run("2\n") == "0.875000000000000", "sample 1"
assert run("3\n") == "1.187500000000000", "sample 2"

# Minimum-size input. The two possible remaining counts, 0 and 1,
# are equally likely, so the answer is 0.5.
assert run("1\n") == "0.500000000000000", "minimum n"

# Boundary case n = 4, with all possible k values contributing.
assert run("4\n") == "0.992187500000000", "off-by-one boundary"

# Maximum allowed n.
assert abs(float(run("30\n")) - reference(30)) < 1e-12, "maximum n"

# Another symmetric case, checked against the direct combinatorial formula.
assert abs(float(run("5\n")) - reference(5)) < 1e-12, "probability distribution"

 ## 特殊なケース

 のために`n = 1`、2 つのボックスには、最初はそれぞれ 1 つの一致が含まれています。 確率で`1/2`、教授は同じボックスを 2 回選択するため、もう一方のボックスには次のものが含まれます。`1`。 確率で`1/2`、彼は 2 つの異なるボックスを選択するため、2 番目の選択では空のボックスが見つかり、もう 1 つのボックスには次のものが含まれます。`0`。 したがって、期待値は`1/2`、アルゴリズムが取得するもの`P(1) = 0.5`そして`P(0) = 0.5`。 

のために`n = 2`、完全な分布は次のとおりです。`P(2) = 1/4`、`P(1) = 3/8`、 そして`P(0) = 3/8`。 結果として得られる期待値は、`2 * 1/4 + 1 * 3/8 = 7/8`。 の`k = 2`結果は、空のボックスが後で選択されたときではなく、ボックスが空になったときに分析を停止するという間違いを見つけるのに特に役立ちます。 

のために`k = 0`、教授が最初の空の箱を発見したとき、もう一方の箱も空でした。 このケースは、期待値への寄与がゼロであっても、正の確率を持ちます。 たとえば、`n = 2`、その確率は`3/8`。 合計が正になるだけの実装`k`値によって一部の例が偶然正しくなる可能性はありますが、その確率分布は不完全であり、関連する計算はすべて間違っている可能性があります。 

最大入力の場合`n = 30`、使用される 2 の最大累乗は次のとおりです。`2^60`、ループには 31 回の反復しか含まれていません。 反復では、可能性のある履歴の膨大なセットを構築する必要がないため、同じ一定サイズの状態表現が上限で変更されずに機能します。
