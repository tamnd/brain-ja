 ## 解決策
 ## 問題の理解

 次のように、数字ではなく単語で書かれた足し算が与えられます。`VOLVO+FIAT=MOTOR`。 Every distinct letter must be assigned a digit from`0`を通して`9`。 2 つの異なる文字は異なる数字を受け取る必要がありますが、同じ文字が出現するたびに同じ数字を受け取ります。 先頭のゼロは明示的に許可されているため、単語の最初の文字は特別なものではありません。 

このタスクは、最初の単語の数値と 2 番目の単語の数値の合計が結果の単語の数値に等しいすべての割り当てを見つけることです。 有効な各割り当ては、元の式内のすべての文字を割り当てられた数字に置き換えることによって出力されます。 このステートメントは、解が最大 1000 個存在することを保証します。 

3 つの単語はそれぞれ最大 15 文字で構成されます。 これにより、完了した代入を 3 つの整数に変換するのが安くなりますが、すべての代入を試すのが安くなるわけではありません。 数字は 10 個しか存在しないため、異なる文字は最大 10 個使用できます。 10 文字にわたる完全なブラインド検索では、最大で次のことが考慮されます。`10! = 3,628,800`割り当てがあり、割り当てごとに 3 つの単語を評価する必要があります。 すでに何百万もの候補があり、単純な Python 実装では、はるか以前に拒否された可能性がある割り当てのチェックにほとんどの時間を費やすことができます。 

加算の構造により、より強力な制約が与えられます。 すべての文字に数字が含まれるまで待つ代わりに、単位列から最上位列に向かって加算を処理できます。 各列にはキャリーが 1 つだけあり、2 つの加数の桁が判明すると、結果の桁が強制されます。 これにより、グローバルな平等性が一連の非常に小さなローカル チェックに変わります。 

不注意な実装によって誤って処理される可能性のあるエッジケースがいくつかあります。 まず、先頭のゼロは有効です。 例えば、`A+A=B`有効な解決策があります`5+5=0`、それで、割り当ては`A=5, B=0`受け入れなければなりません。 最初の文字にゼロを禁止する実装では、その文字が誤って破棄されてしまいます。 

2 番目の問題は、同じ文字が同じ列構造の複数の位置に出現する可能性があることです。 のために`A+A=A`、唯一の解決策は`0+0=0`1 つの文字はどこでも同じ値を持つ必要があるためです。 次の 2 つの発生を処理するソルバー`A`独立変数として、次のような代入を誤って受け入れる可能性があるため、`1+1=1`。 

3 番目のエッジケースは最終キャリーです。 次のような入力の場合`A+B=CA`、有効な割り当てでは、追加の最上位桁を生成するために加算が必要になる場合があります。 ソルバーはすべての列を処理し、最後の実際の列の後のキャリー左が正確に 0 であることを確認する必要があります。 その最終条件を無視すると、不完全な追加が受け入れられる可能性があります。 

最後に、異なる文字が数字を共有してはなりません。 のために`A+B=C`、課題`A=1, B=1, C=2`算術等価性は満たしますが、有効な暗号割り当てではありません。 数字使用構造は、答えを生成する前にそれを拒否する必要があります。 

## アプローチ

 最も直接的なアプローチは、すべての異なる文字を収集し、あらゆる可能な単射法でそれらに数字を割り当て、3 つの単語を整数に変換し、等しいかどうかをテストすることです。 これは正しいです。考えられるすべての正当な割り当てが 1 回だけ考慮され、最終的な算術テストが問題の条件と正確に一致するからです。 

問題は検索スペースのサイズです。 10 個の異なる文字があると、`10 * 9 * 8 * ... * 1 = 10! = 3,628,800`課題。 すべての割り当てで 3 つの単語にわたって最大 45 文字をスキャンする必要がある場合、最悪のケースでは 1 億 6,000 万文字レベルの操作が必要になります。 また、すべての文字が割り当てられるまで、検索は役に立ちません。 

問題を変える観察は、10 進数の加算がローカルであるということです。 右から 1 列目を考えてみましょう。 2 つの加算桁が`x`そして`y`、そして入ってくるキャリーは`carry`、 それから`x + y + carry = result_digit + 10 * next_carry`。 

一度`x`そして`y`知られている、`result_digit`そして`next_carry`完全に決まっている。 結果の文字にすでに数字が含まれている場合は、それを強制された数字と比較するだけで済みます。 まだ割り当てられていない場合は、強制された数字が未使用かどうかを確認する必要があります。 

これにより、右から左に検索できるようになります。 すべての列に、2 つの加数に出現するまだ未知の文字のみを割り当てます。 結果の数字は推測ではなく導出されます。 間違った部分代入は、算術演算が不可能になる列で即座に消滅します。 

ブルート フォース検索は、すべての完全な代入を個別にチェックできるため機能しますが、すべての算術制約が最後まで延期されるため失敗します。 列単位のバックトラッキングでは、必要な桁が判明するとすぐに、利用可能な最も強力な制約が適用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(L * 10!)`最悪の場合 |`O(U)`| 厳密な Python 実装には遅すぎます |
 | 列ごとのバックトラッキング |`O(L * P(10,U))`最悪の場合、強力な列枝刈りを行う |`O(U + L)`| 承認済み |

 ここ`L`は最大単語長です。`U`は個別の文字の数であり、`P(10,U) = 10!/(10-U)!`。 以来`U <= 10`は 10 進アルファベットで固定されていますが、特にすべての文字が割り当てられる前にほとんどの分岐が拒否されるため、実際の検索は小さくなります。 

## アルゴリズムのチュートリアル

 1. 入力式を次の位置で分割します。`+`そして`=`2 つの加算と結果に代入します。 文字を文字列として保存し、後でその位置を右から左に検査できるようにします。 
2. 異なる文字を数えます。 10 を超える場合は、使用可能な桁が 10 桁しかないため、割り当てはできません。 検索はすぐに終了できます。 
3. 配列を維持する`digit[26]`、最初に含まれる`-1`、各文字に割り当てられた数字を保存します。 10の要素を維持する`used`どの桁がすでに取得されているかを示す配列。 
4. 単位位置から最上位に向かって列を処理します。 コラム用`pos`、追加の数字は次の文字です。`a[-1-pos]`その位置が存在する場合、それ以外の場合はゼロになります。 2 番目の加数と結果にも同じルールが使用されます。 
5. 現在の列の 2 つの加数位置に出現する個別の文字のみを確認します。 いずれかに数字が割り当てられていない場合は、その未使用の数字をすべて試してください。 1 つの列には最大 2 つの加数文字があるため、結果を検討する前に最大 90 個の選択肢が作成されます。 
6. コンピューティング`total = digit_left + digit_right + carry`。 必要な結果の数字は次のとおりです。`total % 10`、次の列のキャリーは次のようになります。`total // 10`。 
7. 結果文字にすでに数字が含まれている場合は、その数字を必要な結果の数字と比較します。 不一致があると、現在のブランチを実行できなくなります。 結果の文字が割り当てられていない場合は、必要な桁が使用されていない場合にのみ、その桁を割り当てます。 結果の数字は決して推測されないため、これは重要な枝刈りステップです。 
8. 新しいキャリーを使用して次の列に戻ります。 戻った後、現在の列で行われたすべての割り当てを元に戻し、別のブランチがまったく前の状態から開始されるようにします。 
9. すべての列が処理された後、キャリーがゼロの場合にのみ割り当てを受け入れます。 代入を使用してすべての単語を変換し、結果の式を保存します。 

不変条件は、列を処理する前に、すでに処理されたサフィックスが必要とするすべての文字が固定桁を持ち、割り当てられたすべての桁が個別であり、処理されたサフィックスが現在のキャリーを含む加算を満たすことです。 すべての再帰的遷移では、現在の列の正確な 10 進方程式がチェックされるため、この不変式が保持されます。 逆に、有効な完全な代入はすべての個々の列方程式を満たさなければならないため、対応する選択肢が枝刈りされることはありません。 したがって、生成されたすべての割り当ては有効であり、すべての有効な割り当ても最終的に生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_expression(expr):
    a, rest = expr.split('+')
    b, c = rest.split('=')

    max_len = max(len(a), len(b), len(c))

    letters = set(a + b + c)
    if len(letters) > 10:
        return []

    digit = [-1] * 26
    used = [False] * 10
    solutions = []

    def get_char(word, pos):
        idx = len(word) - 1 - pos
        if idx < 0:
            return -1
        return ord(word[idx]) - ord('A')

    def build_number(word):
        value = 0
        for ch in word:
            value = value * 10 + digit[ord(ch) - ord('A')]
        return value

    def make_output():
        na = build_number(a)
        nb = build_number(b)
        nc = build_number(c)
        solutions.append(f"{na}+{nb}={nc}")

    def dfs(pos, carry):
        if pos == max_len:
            if carry == 0:
                make_output()
            return

        x = get_char(a, pos)
        y = get_char(b, pos)
        z = get_char(c, pos)

        assigned_now = []

        def assign_operand(ch, d):
            digit[ch] = d
            used[d] = True
            assigned_now.append((ch, d))

        def undo():
            while assigned_now:
                ch, d = assigned_now.pop()
                digit[ch] = -1
                used[d] = False

        # Recursively assign the distinct letters appearing in
        # the two addend positions.
        operands = []
        if x != -1:
            operands.append(x)
        if y != -1 and y != x:
            operands.append(y)

        def assign_operands(idx):
            if idx == len(operands):
                dx = 0 if x == -1 else digit[x]
                dy = 0 if y == -1 else digit[y]

                total = dx + dy + carry
                needed = total % 10
                next_carry = total // 10

                if z == -1:
                    if needed != 0:
                        return
                    dfs(pos + 1, next_carry)
                    return

                if digit[z] != -1:
                    if digit[z] == needed:
                        dfs(pos + 1, next_carry)
                    return

                if used[needed]:
                    return

                digit[z] = needed
                used[needed] = True
                dfs(pos + 1, next_carry)
                digit[z] = -1
                used[needed] = False
                return

            ch = operands[idx]

            if digit[ch] != -1:
                assign_operands(idx + 1)
                return

            for d in range(10):
                if used[d]:
                    continue

                assign_operand(ch, d)
                assign_operands(idx + 1)
                undo()

        assign_operands(0)

    dfs(0, 0)
    return solutions

def main():
    expr = input().strip()
    solutions = solve_expression(expr)

    out = [str(len(solutions))]
    out.extend(solutions)
    sys.stdout.write('\n'.join(out))

if __name__ == "__main__":
    main()
```パーサーは式を正確に 3 つの単語に分割します。 入力フォーマットには 1 つしか含まれていないため、`+`そして1つ`=`、二人`split`操作は十分です。 

の`digit`配列は次の文字インデックスを使用します`0`に`25`。 の値`-1`は、その文字がまだ割り当てられていないことを意味します。 の`used`array は、候補の数字が利用可能かどうかを定数時間チェックします。`get_char`右から数えた列番号を文字インデックスに変換します。 戻る`-1`欠落している加数はその列にゼロを与えるため、欠落している位置の場合は便利です。 この問題では先行ゼロが明示的に許可されているため、特別な先行ゼロの処理はありません。 

入れ子になった`assign_operands`function はバックトラッキングが発生する場所です。 現在の列の 2 つの加数に出現する文字のみを割り当てます。 文字が前の列によって割り当てられている場合、その文字は分岐せずに再利用されます。 

オペランドの数字が利用可能になると、結果の数字は次のように計算されます。`% 10`。 キャリーは次のように計算されます。`// 10`。 結果の数字は現在の列に属し、キャリーは次の列に属するため、この順序は重要です。 

結果の位置が存在しない場合、微妙なケースが発生します。 この場合、結果の数字は概念的にはゼロになります。 コードは、計算された数字がゼロの場合にのみ、その状況を受け入れます。 たとえば、両方の加数がすでに終了しているがキャリーが残っている場合、そのキャリーは最後の加数によって処理されます。`pos == max_len`別の結果の数字を発明するのではなく、チェックします。 

再帰的分岐が終了すると、割り当ては常に元に戻されます。 結果文字も一時的に割り当てられ、明示的に復元されます。 このロールバックがないと、1 つのブランチで選択された数字が次のブランチに漏洩し、有効なソリューションが暗黙的に削除されてしまいます。 

Python の整数はオーバーフローせず、可能な最大の単語は 15 桁しかないため、通常の整数演算で十分です。

## テストケース

        x = get_char(a, pos)
        y = get_char(b, pos)
        z = get_char(c, pos)

        operands = []
        if x != -1:
            operands.append(x)
        if y != -1 and y != x:
            operands.append(y)

        def choose(idx):
            if idx == len(operands):
                dx = 0 if x == -1 else digit[x]
                dy = 0 if y == -1 else digit[y]

                total = dx + dy + carry
                needed = total % 10
                next_carry = total // 10

                if z == -1:
                    if needed == 0:
                        dfs(pos + 1, next_carry)
                    return

                if digit[z] != -1:
                    if digit[z] == needed:
                        dfs(pos + 1, next_carry)
                    return

                if used[needed]:
                    return

                digit[z] = needed
                used[needed] = True
                dfs(pos + 1, next_carry)
                used[needed] = False
                digit[z] = -1
                return

            ch = operands[idx]

            if digit[ch] != -1:
                choose(idx + 1)
                return

            for d in range(10):
                if not used[d]:
                    digit[ch] = d
                    used[d] = True
                    choose(idx + 1)
                    used[d] = False
                    digit[ch] = -1

        choose(0)

    dfs(0, 0)
    return solutions

def run(inp: str) -> str:
    expr = inp.strip()
    ans = solve_expression(expr)
    return str(len(ans)) + (("\n" + "\n".join(ans)) if ans else "")

    lines = s.strip().splitlines()
    count = int(lines[0])
    return count, set(lines[1:])

 ## 特殊なケース

 のために`A+A=A`の場合、アルゴリズムは空のマッピングから始まります。 唯一の列では、同じオペランド文字が 2 回表示されるため、`operands`含まれています`A`一度だけ。 割り当てる`A=0`与える`0+0=0`, したがって、分岐はキャリー 0 で最後に到達し、受け入れられます。 ゼロ以外の代入は次のようになります。`2A`結果として、等しくない`A`明確な 10 進数を使用するため、他のすべての分岐は拒否されます。 出力は正確に`0+0=0`。 

のために`A+A=B`、単位列が割り当てます`A`初め。 いつ`A=5`、合計は 10 なので、必要な結果の桁は 0 で、桁上げは 1 です。 ゼロは未使用なので、`B=0`受け入れられます。 結果として得られる式は、`5+5=0`。 これは、ソルバーが先行ゼロなしルールを課してはならない理由を示しています。 同じ入力により、他のすべての値に対してキャリー遷移も実行されます。`A`。 

最大長入力の場合`AAAAAAAAAAAAAAA+AAAAAAAAAAAAAAA=BBBBBBBBBBBBBBB`、15 列すべてがまったく同じ構造を持っています。 もし`A=1`、最初の列は生成します`B=2`そしてキャリーもありません。 後続のすべての列で同じ計算が繰り返されるため、完全な結果は次のようになります。`111111111111111+111111111111111=222222222222222`。 課題`A=2,3,4`同様に生産する`B=4,6,8`、 その間`A=5`結果には 15 個のゼロが生成されます。 どれでも`A>=6`対応するリレーションですでに割り当てられている結果の数字を再利用するか、以前に使用された値と等しい結果の数字を生成します。 このアルゴリズムは、ワードの絶対的な数値サイズに依存することなく、15 列すべてを処理します。 

のために`ABCDEFGHIJ+K=ABCDEFGHIJK`、11 個の異なる文字が必要です。 正当な割り当てには文字ごとに異なる数字が必要ですが、数字は 10 桁しかないため、ソルバーは再帰検索を開始せずにすぐに戻ります。 このチェックにより、不注意な実装によるインデックス作成や不可能な桁の置換の構築も防止されます。 

ファイナルキャリー境界は、`pos == max_len`状態。 処理された列がキャリー 1 で終了するとします。 その位置には結果文字が残っていないため、加算は有効になりません。 再帰は基本ケースに到達し、分岐を拒否します。`carry != 0`。 有効な解では、最も重要な実列の後に常に正確にゼロを残す必要があります。
