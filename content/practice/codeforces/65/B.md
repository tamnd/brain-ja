 ## 解決策
 ## 問題の理解

 4 桁の年列が与えられます。 各年には間違いが含まれる可能性がありますが、最大 1 桁の変更で修正できます。 すべての修復が完了すると、順序は減少しないようになり、結果として得られるすべての年が 1000 年から 2011 年の間に留まる必要があります。 

課題は、変更の数を全体的に最小限に抑えることではありません。 毎年独立して、元の値とは最大で 1 桁異なる可能性があり、有効な最終順序は許容されます。 

この問題を考える最も自然な方法は次のとおりです。元の年ごとに、修復可能な年はほんのわずかしかありません。 最終的なシーケンスがソートされるように、位置ごとに 1 つの候補を選択する必要があります。 

制約は十分小さいため、積極的な列挙が可能です。 最大で 1000 年があり、各年に変更できる位置は 4 つだけです。 すべての役職について 10 桁を試すことができるため、各年には最大 1 + 4 × 9 = 37 の有効な候補者と、いくつかの重複が含まれます。 すべての候補者をこれまでのあらゆる可能性と比較したとしても、総作業量はわずかにとどまります。 

問題の危険な部分はパフォーマンスではなく、正確さです。 いくつかのエッジケースでは、不注意な実装が静かに破壊される可能性があります。 

よくある間違いの 1 つは、上限の 2011 を忘れることです。次の点を考慮してください。```
2
2009
9999
```素朴な解決策は方向転換するかもしれない`9999`の中へ`2099`、これはまだ 2011 より大きく、無効です。 ここで正解することは不可能です。 

もう 1 つの罠は、先行ゼロを許可することです。 例えば：```
1
1000
```最初の桁を次のように変更すると、`0`作成するだろう`0000`ただし、年は 1000 から 2011 までの 4 桁の数字でなければなりません。 

最小の有効な候補を貪欲に選択すると、さらに微妙な問題が発生します。 考慮する：```
2
1999
1000
```2 年目の場合、有効な 1 桁の変更には次のものがあります。`1000`、`1009`、`1090`、 等々。 少なくともどれも`1999`, したがって、答えは不可能です。 以前に選択された値を手遅れになるまで無視する貪欲なアルゴリズムは、無効なシーケンスを誤って受け入れる可能性があります。 

また、大きすぎて将来のポジションを不必要に妨げる候補者を選択するという、逆の問題もあります。 次のものがあるとします。```
3
1888
1880
1881
```2 番目の値を不必要に上げすぎると、3 番目の値が不可能になる可能性があります。 最も安全な戦略は、実行可能性を維持しながら、選択したすべての年を可能な限り小さく保つことです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての役職について、最大 1 桁の変更で取得可能なすべての年を生成します。 次に、すべての組み合わせを再帰的に試し、結果のシーケンスが減少していないかどうかを確認します。 

これが機能するのは、毎年の候補者が非常に少ないためです。 4 桁の数値では、すべての桁を変更しないことも、4 桁の 1 つを 9 つの代替桁の 1 つに変更することもできます。 つまり、年間およそ 37 人の候補者が誕生することになります。 

問題は、これらの可能性を組み合わせると指数関数的に爆発的に増加することです。 最悪の場合、次のことを検討します。$37^n$シーケンス。 たとえ$n = 1000$、これはまったく不可能です。 

重要な点は、シーケンス制約がローカルであるということです。 候補者が有効かどうかは、選択した前年の年のみに依存します。 プレフィックス全体を覚える必要はありません。 

これが見えてくると、問題は貪欲になります。 すでに前年を何らかの値に固定していると仮定します。`prev`。 現在のポジションについては、以下の候補者`prev`永久に使用できなくなります。 残りの候補すべての中で、最小のものを選択することが常に最適です。 

なぜ？ 値が小さいほど、将来に向けてより多くの余地が残るためです。 より大きな有効な候補者を選択しても、後のポジションに役立つことはなく、さらに制限されるだけです。 

これにより、問題は単純な左から右へのプロセスに変換されます。 

1. 今年の有効な候補者をすべて生成します。 
2. 少なくとも前に選択した年と同じ規模以上の候補者のみを保持します。 
3. その中から最小のものを選択します。 
4. 存在しない場合、答えは不可能です。 

毎年の候補者は約 37 名のみであるため、全体の複雑さは直線的になります。`n`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(37^n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n \cdot 40)$|$O(40)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての年を文字列として読み取るので、数字の置換が簡単になります。 
2. 変数を維持する`prev`、最後に選択された修理年を表します。 最初は次のように設定します`1000`、すべての有効な年は少なくともこの値でなければならないためです。 
3. 現在の年について、最大 1 桁の変更で取得できるすべての数値を生成します。 

元の番号自体を含めることから始めます。 次に、4 つの位置をそれぞれ数字に置き換えてみます。`0`を通して`9`。 
4. 無効な生成された年を拒否します。 

次の場合、候補者は無効です。 

- 先頭にゼロが付いています。 
- 外に落ちる`[1000, 2011]`。 
5. 重複を避けるために、有効な候補をすべてセットに保存します。 

異なる数字を置き換えると、同じ数字が生成される場合があります。 
6. 以上のすべての候補者のうち、`prev`、最小値を選択します。 

これは貪欲なステップです。 現在の値をできるだけ小さく保つことで、後のポジションの柔軟性が最大化されます。 
7. 条件を満たす候補がない場合は、印刷します。`"No solution"`そして終了します。 
8. それ以外の場合は、選択した値を回答リストに追加して更新します。`prev`。 
9. すべての年を処理した後、結果のシーケンスを印刷します。 

### なぜ効果があるのか

 アルゴリズムは次の不変条件を維持します。 

加工後の位置`i`、選択された接頭辞は、辞書編集上可能な最小の有効な非減少接頭辞です。 

あるステップで候補者を選択するとします`x`たとえ他の有効な候補者であっても`y < x`も存在します。 選択後に機能する将来のシーケンス`x`を選択した後にも機能します`y`なぜなら、将来の値は少なくとも前の値であればよいからです。 以前の値を下げても、将来のオプションが削除されることはありません。 

したがって、最小限の有効な候補を選択することは常に安全であり、将来の実現可能性を損なうことはありません。 帰納法により、解決策が存在する場合、貪欲なアルゴリズムが解決策を見つけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def candidates(s):
    res = set()

    original = int(s)
    if 1000 <= original <= 2011:
        res.add(original)

    arr = list(s)

    for i in range(4):
        old = arr[i]

        for d in "0123456789":
            if d == old:
                continue

            arr[i] = d

            if arr[0] != '0':
                val = int("".join(arr))

                if 1000 <= val <= 2011:
                    res.add(val)

        arr[i] = old

    return sorted(res)

def solve():
    n = int(input())
    years = [input().strip() for _ in range(n)]

    ans = []
    prev = 1000

    for s in years:
        cand = candidates(s)

        chosen = None

        for x in cand:
            if x >= prev:
                chosen = x
                break

        if chosen is None:
            print("No solution")
            return

        ans.append(chosen)
        prev = chosen

    print("\n".join(map(str, ans)))

solve()
```ヘルパー関数は、最大 1 桁の変更で到達可能な年を生成します。 文字列を使用すると、数字の置換が簡単になり、算術トリックを回避できます。 

変更は許可されないため、元の値が最初に挿入されます。 次に、各位置が個別に変更されます。 1 桁を変更した後、コードは最初の桁がゼロになったかどうか、および結果の年が許容範囲内にあるかどうかをチェックします。 

セットは重複を自動的に削除します。 たとえば、数字をそれ自体で置き換える操作はスキップされますが、異なる編集を行っても同じ整数が生成される場合があります。 

欲張りステップでは少なくとも次の値と同じ大きさの最小有効値が必要であるため、候補リストがソートされます。`prev`。 リストが小さいため、並べ替えにはほとんどコストがかかりません。 

内部`solve`、アルゴリズムは左から右に年を処理します。 毎年、ソートされた候補者リストをスキャンし、条件を満たす最初の候補者を選択します。`x >= prev`。 

初期化`prev = 1000`意図的です。 すべての有効な年はすでにこの下限を満たしている必要があるため、最初に選択した値は元の問題の制約に従うだけで済みます。 

最も一般的な実装のバグは、置換のテスト後に変更された数字を復元し忘れることです。 行:```
arr[i] = old
```は不可欠です。 これがないと、後の変更で複数の桁の変更が誤って重なってしまう可能性があります。

 ## 特殊なケース

 Consider the case:```
2
2009
9999
```のために`2009`、アルゴリズムは選択できます`1009`。 それから処理します`9999`。 1 桁の変更を行っても 2011 より大きい値が残るため、候補セットは空になります。 アルゴリズムはすぐに出力します`"No solution"`。 

これは、上限制限が候補生成後ではなく候補生成中に適用されることを裏付けています。 

次に、先頭ゼロの危険性を調べます。```
1
1000
```最初の数字を変更するとき、アルゴリズムは一時的に次のような文字列を作成することがあります。`"0000"`または`"9000"`。 条件:```
if arr[0] != '0':
```変換前に無効な先行ゼロの数値を除外します。 有効な候補者`1000`は残っているので、出力は正しいです。 

最後に、貪欲な最小性が重要となるシーケンスを考えてみましょう。```
3
1888
1880
1881
```最初の 1 年間、アルゴリズムは次のような最小の有効な候補を選択します。`1088`。 次に、2番目は次のようになります`1080`、そして3番目`1081`。 

代わりに、最初の位置に大きな修復値を選択していたら、後年は不可能になったかもしれません。 貪欲ルールは、サフィックスの柔軟性を常に最大限に保つことでこれを回避します。
