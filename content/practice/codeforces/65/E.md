 ## 問題の理解

 無向マルチグラフが与えられています。 床は頂点、階段はエッジです。 ハリーは床から始めます`1`少なくとも一度は全フロアを訪れてみたいと思っています。 

グラフは動的です。 ハリーの散歩の合間に、ロンとハーマイオニーは階段を改造するかもしれません。 変更により、エッジの 1 つの端点が選択され、それが別の頂点に再接続されます。 すべての階段は最大 1 回まで変更できます。 

出力されるのは、タスクが実行可能かどうかだけではありません。 また、一連のウォークとエッジ変更を明示的に記述する必要があります。 ハリーは 2 つの変更の間で任意の距離を歩くことができますが、現時点では、彼の歩行の連続する階のペアはすべて階段で接続されている必要があります。 

グラフには、同じ頂点ペアの間に複数のエッジが含まれる場合がありますが、階段はインデックスによって個別に識別されるため、これは重要です。 動く階段`5`動く階段とは違います`8`、現在両方が同じフロアのペアに接続している場合でも。 

制約が大きいため、二次グラフ アルゴリズムは不可能です。 と`n ≤ 100000`そして`m ≤ 200000`、解は線形時間に近くなければなりません。 グラフを一定の回数だけ走査しても問題ありません。 エッジが移動するたびに接続を再計算するようなことを行うと、すぐに制限を超えてしまいます。 

最も危険なエッジケースは、床に接触する階段がないグラフです。`1`。 

例：```
3 1
2 3
```ハリーは床で孤立し始める`1`。 彼はどこにも移動できず、階段での移動もできないため、`1`存在する場合、接続されたコンポーネントに別のフロアを取り込む方法はありません。 正しい答えは次のとおりです。```
NO
```グラフに少なくとも 1 つのエッジがあるかどうかだけをチェックする不注意な解決策は、誤って成功したと主張することになります。 

もう 1 つの微妙なケースは、一部のコンポーネントに予備の階段がない、切断されたグラフです。 

例：```
4 1
1 2
```床`3`そして`4`孤立している。 すべての移動でエッジの総数が維持されるため、階段で到達することはできません。 1 つの階段で接続できる頂点は最大 2 つであるため、エッジが少なすぎるグラフは完全に検索可能になることはありません。 正しい答えは、`NO`。 

3 番目の重要なケースは、グラフがすでに接続されている場合です。 

例：```
4 3
1 2
2 3
3 4
```階段を移動する必要はまったくありません。 アルゴリズムは有効なウォークを出力し、`0`修正。 コンポーネントを常に再接続しようとするソリューションでは、誤って有用なエッジが移動し、接続が切断される可能性があります。 

最後の厄介な状況は、単一の孤立した頂点で構成されるコンポーネントです。 

例：```

1 2
2 3
```頂点`4`そして`5`次数がゼロです。 エッジを変更しても 1 つの端点が変更されるだけであり、すべての階段はすでに別のコンポーネントに属しているため、到達可能になることはありません。 後で取り付けるには、欠落しているコンポーネントごとに少なくとも 1 つの階段が必要です。 孤立した頂点には階段が含まれないため、答えは次のようになります。`NO`。 

## アプローチ

 ブルートフォースアプローチでは、プロセス全体が明示的にモデル化されます。 すべてのステップで、考えられるすべての階段の移動を試し、ハリーの現在位置から到達可能な頂点を再計算し、最終的にすべての階を訪れるシーケンスを検索できます。 

状態空間は即座に爆発します。 各階段は再接続される可能性があります。`O(n)`さまざまな頂点があり、最大で`200000`階段。 可能性の 1 つの層を探索するだけでも、すでに何十億もの移行が必要です。 移動するたびに接続を再計算するとコストがかかります`O(n + m)`。 

重要な点は、階段の正確なレイアウトはほとんど重要ではないということです。 重要なのは、ハリーが接続されたコンポーネント内の少なくとも 1 つの階段に到達できるかどうかです。 

ハリーが現在、接続されているコンポーネントに到達していると仮定します。`A`、および別のコンポーネント`B`少なくとも 1 つの階段が含まれています。 そうすれば、から階段を 1 つ盗むことができます`B`、1 つのエンドポイントをに再接続します`A`をクリックすると、2 つのコンポーネントが即座にマージされます。 その後、ハリーはすべてを横断できるようになります。`B`。 

これにより、問題は構造的な問題に帰着します。 

分離された頂点を除くすべての接続コンポーネントは、成長する探索領域に接続するために 1 つの階段に貢献できますか?

 少なくとも 1 つのエッジを持つコンポーネントは常にそうすることができます。 あらゆるエッジを利かせてください`(u, v)`そのコンポーネントで。 1 つのエンドポイントを削除し、すでに到達可能な頂点に再接続します`x`。 コンポーネントは残りのエンドポイントを通じて内部接続を維持し、現在は`x`。 

唯一不可能な状況は、孤立した頂点コンポーネントです。 このようなコンポーネントには移動する階段が含まれていないため、すでに頂点と等しくない限り、到達可能になることはありません。`1`。 

これにより、明確な基準が得られます。 

このタスクは、おそらく含まれるコンポーネントを除くすべての接続コンポーネントが存在する場合にのみ可能です。`1`少なくとも 1 つのエッジを持っています。 

これがわかれば、実際のプロセスの構築が容易になります。 まず、次のコンポーネントを介して DFS を実行します。`1`。 次に、エッジを持つ他のすべてのコンポーネントについて、次のようにします。 

1. 階段を 1 つ移動して、そのコンポーネントをすでに探索されている領域に接続します。 
2. 新しく接続されたコンポーネント全体を確認します。 
3. 拡張を続けます。 

すべての頂点とエッジが一定の回数だけ処理されるため、すべてが線形になります。

7. 変更後、そのコンポーネントの DFS トラバーサルを実行します。

import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

def solve():
    n, m = map(int, input().split())

    edges = [None] * (m + 1)
    g = [[] for _ in range(n + 1)]

    for i in range(1, m + 1):
        u, v = map(int, input().split())
        edges[i] = (u, v)
        g[u].append((v, i))
        g[v].append((u, i))

    comp_id = [-1] * (n + 1)
    comps = []

    def dfs_comp(start, cid):
        stack = [start]
        comp_id[start] = cid

        vertices = []
        edge_id = -1

        while stack:
            u = stack.pop()
            vertices.append(u)

            for v, idx in g[u]:
                if edge_id == -1:
                    edge_id = idx

                if comp_id[v] == -1:
                    comp_id[v] = cid
                    stack.append(v)

        comps.append((vertices, edge_id))

    cid = 0
    for v in range(1, n + 1):
        if comp_id[v] == -1:
            dfs_comp(v, cid)
            cid += 1

    start_comp = comp_id[1]

    possible = True

    for i, (_, edge_id) in enumerate(comps):
        if i != start_comp and edge_id == -1:
            possible = False

    if comps[start_comp][1] == -1 and n > 1:
        possible = False

    if not possible:
        print("NO")
        return

    print("YES")

    used = [False] * (n + 1)

    walks = []
    moves = []

    def dfs_walk(start):
        path = []

        stack = [(start, -1, 0)]
        used[start] = True
        path.append(start)

        while stack:
            u, parent, ptr = stack[-1]

            if ptr == len(g[u]):
                stack.pop()

                if stack:
                    path.append(stack[-1][0])

                continue

            stack[-1] = (u, parent, ptr + 1)

            v, _ = g[u][ptr]

            if v == parent or used[v]:
                continue

            used[v] = True
            path.append(v)
            stack.append((v, u, 0))

        return path

    initial_vertices = comps[start_comp][0]

    first_start = initial_vertices[0]
    initial_path = dfs_walk(first_start)

    for i, comp in enumerate(comps):
        if i == start_comp:
            continue

        vertices, edge_id = comp

        u, v = edges[edge_id]

        if used[u]:
            attach = u
            other = v
        elif used[v]:
            attach = v
            other = u
        else:
            attach = u
            other = v

        moves.append((edge_id, 1, other))

        path = [1, other]

        if not used[other]:
            extra = dfs_walk(other)
            path.extend(extra[1:])

        walks.append(path)

    print(len(moves))

    all_walks = [initial_path] + walks

    for i in range(len(moves)):
        path = all_walks[i]
        print(len(path), *path)

        idx, a, b = moves[i]
        print(idx, a, b)

    path = all_walks[-1]
    print(len(path), *path)

コンポーネント DFS は 2 つの目的を同時に果たします。 接続されたコンポーネントにラベルを付け、各コンポーネントの任意の階段を 1 つ記憶します。 この階段は、後でコンポーネントを探索領域に接続するために使用される橋になります。 

実現可能性テストは微妙です。 ハリーの開始コンポーネントの外側に孤立した頂点があると、後で頂点を接続するための階段が存在しないため、すぐにタスクが不可能になります。 開始コンポーネントの特別なチェックは、頂点が`1`グラフには他の頂点が含まれていますが、孤立しています。 

トラバーサル DFS は、単なる訪問命令ではなく、実際の歩行を記録します。 DFS が子から戻るたびに、ハリーは物理的に階段に沿って戻らなければならないため、親を再度追加します。 

構築フェーズでは、コンポーネントを 1 つずつ処理します。 コンポーネントごとに、保存された階段を 1 つ移動して、1 つの端点が頂点になるようにします。`1`。 この変更後、コンポーネントが到達可能になり、有効な DFS ウォークスルーを追加します。 

簡単な間違いの 1 つは、エッジの変更後にグラフ自体が更新されないことを忘れることです。 この実装では、概念的にのみ変更を使用することで、これを完全に回避します。 記録されたウォークは元のコンポーネント構造内に構築され、1 つのエンドポイントを再接続した後も引き続き通過可能です。 

もう 1 つのよくあるバグは、ウォーク内に連続した等しい頂点が生成されることです。 追加されたすべての頂点が実際のエッジを横断することに対応するため、DFS 構築ではこれを自然に回避します。
