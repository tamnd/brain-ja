 ## 問題の理解

 私たちは生徒を一人ずつ処理します。 各生徒は、いずれかの文字で表される固定の家を持っています。`G`、`H`、`R`、`S`、または曖昧な祖先を持ち、次のように表されます。`?`。 

その家には決まった生徒が必ず入る。 あ`?`生徒の態度が違う。 4 つの家すべての現在の数を調べます。 学生は、現在数が最小になっている家を選択できます。 

ハーマイオニーは与えられた生徒をすべて追いかけてやって来ます。 もっと早い段階で仮定して、彼女が最終的に住む可能性のあるすべての家を特定しなければなりません`?`学生は正当な方法で自分の家を選択します。 

重要な問題は、以前の選択が後のバランスに影響を与えることです。 最初に 2 つの異なる決定を下すことで、後で利用できる住宅が完全に変わる可能性があります。 

ハーマイオニーの前の生徒の数は最大でも`10000`。 これは、全体にわたる指数関数的な検索には大きすぎます。`?`課題。 平`2^40`それは不可能であり、最悪の場合、`10000`曖昧な生徒たち。 We need something closer to linear or polynomial time.

 A subtle part of the problem is that we are not asked for one reachable configuration. We need all houses Hermione could possibly enter under some sequence of valid choices.

 簡単な間違いの 1 つは、すべての`?`学生は常に、現在最小の家をすべて均等に選択する必要があります。 このプロセスは確率的なものではありません。 私たちが気にするのは到達可能性だけです。

```2人目の生徒は選択できます`G`、`R`、 または`S`。

彼らが選ぶなら`R`、ハーマイオニーが選ぶかもしれない`G`または`S`。 

彼らが選ぶなら`S`、ハーマイオニーが選ぶかもしれない`G`または`R`。 

だからハーマイオニーは決してそれで終わることはできない`H`。 

それぞれの家を1軒ずつ勝手に選ぶ欲張りシミュレーション`?`可能性を逃してしまうでしょう。

ここには対称性の観察も隠されています。 相対的な違いのみが重要です。 以前の選択の正確な順序は、現在のカウントによってのみ重要になります。 

## アプローチ

 ブルーフォースのアイデアは単純明快です。 生徒を左から右に処理します。 固定文字が表示されるたびに、そのハウスをインクリメントします。 私たちが見るたびに`?`、現在最小限の家すべてに分岐します。 

最後に、どの家がハーマイオニーにとって最小限であるかを調べます。 

これは、すべての法的な一連の決定を明示的に調査しているため、正しいです。 

問題は支店の数です。 最悪の場合、最初の多くの生徒が全員死亡する可能性があります。`?`、それぞれ最大 4 つの選択肢に分岐できます。 枝刈りを行っても、パスの数は指数関数的に増加します。 

たとえば、`40`曖昧な生徒たち、`4^40`すでに天文学的な規模になっています。 

重要な観察は、多くの異なる選択シーケンスがまったく同じハウスカウントにつながるということです。 カウントが同一になると、将来の可能性も同一になります。 

これは、動的プログラミングまたはステートを介したメモ化された DFS を即座に示唆します。 

ここで、状態空間が実際にどれくらいの大きさであるかを理解する必要があります。 一見すると、カウントは次のようになります。`10000`、それは非常に大きいように聞こえます。 ただし、バランシング ルールにより構成が大幅に制限されます。 

あ`?`学生は現在最小限の家にしか入ることができません。 つまり、家数がこれ以上異なることはあり得ないということです`1`によってのみ進化した家の間で`?`課題。 固定割り当てはバランスを乱しますが、それは制御された方法でのみです。 

重要な圧縮は次のとおりです。 

正確な履歴を保存する代わりに、現在のカウントのタプルのみを保存します。 

1 つの状態からの遷移は決定的です。 

固定文字 -> 1 カウント増加、

 疑問符 -> すべての最小カウントを個別に増加させます。 

バランス制約によりパスが積極的にマージされるため、到達可能なカウント タプルの数は驚くほど少ないままです。 

到達可能な状態に対するメモ化を使用して DFS を実行できます。 すべての一意の状態は 1 回処理されます。 

これにより、制限内で問題なく受け入れられる解決策が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(4^q) | O(q) | 遅すぎる |
 | 最適 | O(到達可能な状態の数) | O(到達可能な状態の数) | 承認済み |

 ここ`q`の数です`?`文字。 

## アルゴリズムのチュートリアル

 1. 住宅をインデックスとして表現します。`0 = G`、`1 = H`、`2 = R`、`3 = S`。 
2. count タプルから開始する`(0, 0, 0, 0)`。 
3. DFS とメモ化を使用して、生徒を左から右に処理します。 
4. DFS 状態は次のもので構成されます。 

現在の位置`i`、

 そして現在の住居数のタプル。 
5. もし`i == n`、ハーマイオニーの目の前に到着しました。 

4 つのハウスの中から最小の数を求めます。 

この最小限のものを備えたすべての家が有効な答えです。 
6. 現在の学生が固定のハウスレターを持っている場合は、そのハウスのみをインクリメントして DFS を続行します。 
7. 在校生が以下の場合`?`、最小電流カウントを計算します。 

この最低限度の要件を満たすすべての家は、法的な移行を意味します。 

このようなハウスごとに、その数を増やして DFS を続行します。 
8. 訪れた州をメモ化する`(i, counts)`したがって、同じ設定が 2 回処理されることはありません。 

メモ化を行わない場合、多くの異なる選択シーケンスを通じて同じカウントタプルに到達する可能性があります。 

### なぜ効果があるのか

 国家が将来を完全に決定します。 

2 つの異なる履歴が同じ位置を生成すると仮定します。`i`そして同じカウントタプル。 残りのすべての学生にはまったく同じ家番号が表示されるため、今後の法的な移動のセットは同一になります。 以前の決定から得られた情報はもはや重要ではありません。 

DFS は、すべての法的移行を固有の州ごとに 1 回だけ調査します。 すべての最終状態は有効な並べ替えシーケンスに対応し、すべての有効な並べ替えシーケンスが DFS に表示されます。 

つまり、最後に集められた最小限の家は、まさにハーマイオニーが入れる家なのです。 

## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

houses = ['G', 'H', 'R', 'S']
name_map = {
    'G': 'Gryffindor',
    'H': 'Hufflepuff',
    'R': 'Ravenclaw',
    'S': 'Slytherin'
}

idx = {c: i for i, c in enumerate(houses)}

n = int(input())
s = input().strip()

possible = [False] * 4

@lru_cache(maxsize=None)
def dfs(i, g, h, r, s_cnt):
    counts = [g, h, r, s_cnt]

    if i == n:
        mn = min(counts)
        for j in range(4):
            if counts[j] == mn:
                possible[j] = True
        return

    ch = s[i]

    if ch != '?':
        nxt = counts[:]
        nxt[idx[ch]] += 1
        dfs(i + 1, *nxt)
    else:
        mn = min(counts)

        for j in range(4):
            if counts[j] == mn:
                nxt = counts[:]
                nxt[j] += 1
                dfs(i + 1, *nxt)

dfs(0, 0, 0, 0)

for i in range(4):
    if possible[i]:
        print(name_map[houses[i]])
```DFS は並べ替えプロセスを直接反映します。 

メモ化キーには、現在位置と 4 つのハウスカウントの両方が含まれています。 将来の遷移はこれらの値のみに依存するため、同じ値を持つ 2 つの状態は交換可能です。 

末期状態は注目に値する。 ハーマイオニーをどこにも割り当てません。 現時点で最小限の家だけを検査します。それは、彼女が選択できる家だからです。 

もう 1 つの微妙な点は、DFS からセットを返すのではなく、回答をグローバルに更新することです。 大きなセットを繰り返し返すと、不必要なオーバーヘッドが追加されます。 単純なブール配列で十分です。 

タプルは次のように解凍されます。```
dfs(i + 1, *nxt)
```キャッシュキーを不変かつハッシュ可能に保ちます。 リストはハッシュ可能ではないため、リストを直接使用すると失敗します。

import sys
import io
from functools import lru_cache

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    houses = ['G', 'H', 'R', 'S']
    name_map = {
        'G': 'Gryffindor',
        'H': 'Hufflepuff',
        'R': 'Ravenclaw',
        'S': 'Slytherin'
    }

    idx = {c: i for i, c in enumerate(houses)}

    n = int(input())
    s = input().strip()

    possible = [False] * 4

    @lru_cache(maxsize=None)
    def dfs(i, g, h, r, s_cnt):
        counts = [g, h, r, s_cnt]

        if i == n:
            mn = min(counts)

            for j in range(4):
                if counts[j] == mn:
                    possible[j] = True
            return

        ch = s[i]

        if ch != '?':
            nxt = counts[:]
            nxt[idx[ch]] += 1
            dfs(i + 1, *nxt)
        else:
            mn = min(counts)

            for j in range(4):
                if counts[j] == mn:
                    nxt = counts[:]
                    nxt[j] += 1
                    dfs(i + 1, *nxt)

    dfs(0, 0, 0, 0)

    ans = []

    for i in range(4):
        if possible[i]:
            ans.append(name_map[houses[i]])

    return "\n".join(ans) + "\n"
