 ## 解決策
 ## 問題の理解

 あるマテリアルを別のマテリアルに変換する 3 つの変換呪文があります。 

最初の呪文が変わる`a`砂を何グラムも入れる`b`鉛のグラム数。 

2番目の呪文が変わります`c`鉛のグラム数`d`金のグラム数。 

3番目の呪文はターンします`e`金を何グラムも入れる`f`砂のグラム数。 

唱えたい呪文を唱えるのに十分な材料を現在所有している限り、これらの呪文を好きなだけ何度でも、どんな順序でも適用できます。 問題は、最終的に任意の量の金を生産できるような、有限の開始量の砂が存在するかどうかです。 

キーワードは「事前に割り当てられたどの数値よりも大きい」です。 特定の上限金額は求められません。 私たちは、金の生産が際限なく増加できるかどうかを判断する必要があります。 

制約はわずかです。 すべての数字は次の範囲内にあります`0`そして`1000`。 つまり、パフォーマンスを気にせずに直接数学的推論を自由に使用できるということです。 中程度の範囲でのブルートフォース状態探索でも、制限時間内に収まります。 本当の課題は効率ではなく、ゼロを含むすべての縮退状況を正しく処理することです。 

危険な事件はすべて、「無から」物質を作り出す呪文によって引き起こされます。 

次の入力を考えてみましょう。```
1 1 0 1 1 1
```2番目の呪文は変換されます`0`に導く`1`金。 すぐに何度でも無限にキャストできます。 答えは`"Ron"`。 

全サイクルの乗算比のみをチェックする不注意な実装では、これを見逃してしまいます。 

もう一つの微妙なケース:```
1 1 1 1 0 1
```3番目の呪文は変換されます`0`金を入れる`1`砂。 Starting from zero sand, we can generate infinite sand for free, then use the first and second spells to create infinite gold. 答えは`"Ron"`。 

常に正の初期リソースが必要であると仮定した解決策は、ここでは失敗します。 

すべての呪文が物質を保存または破壊する場合もあります。```
100 50 100 50 100 50
```すべての変換ではマテリアルの半分が失われます。 このサイクルを繰り返すとリソースが縮小するだけなので、答えは次のようになります。`"Hermione"`。 

別の特殊なケース:```
0 0 0 0 0 0
```すべての呪文は何もしません。 無限のゴールドは不可能です。 

この問題の最も難しい部分は、本物の増幅と無害なサイクルを正しく区別することです。 

## アプローチ

 自然な強引なアイデアは、到達可能な状態をシミュレートすることです。 ある程度の量の砂から始めて、可能なすべての呪文を繰り返し適用して、到達可能なすべてのトリプルをマークすることができます。`(sand, lead, gold)`。 

システムは決定論的であり、状態遷移が単純であるため、これは概念的に機能します。 無限の成長が存在する場合、資源の価値は増加し続けることが期待されます。 

問題は、状態空間の明確な上限がないことです。 もし答えが`"Ron"`、量は永遠に増加する可能性があります。 すべてのリソースを次のような制限で制限したとしても、`10^6`、まだ正しさを証明できません。 収益性の高いサイクルを維持するには、一時的に多額の資金を蓄積する必要がある場合があります。 

呪文の構造により、ルートがより明確になります。 

材料が有向サイクルを形成していることを観察します。```
sand -> lead -> gold -> sand
```ある程度の量の砂から始めてサイクル全体を 1 回繰り返すと、砂の合計は乗算係数によって変化します。```
(b / a) * (d / c) * (f / e)
```この係数がより大きい場合`1`、その後 1 つの完全なサイクルで砂が増加します。 このサイクルを繰り返すことで資源が飛躍的に増加し、無制限に金を抽出することができます。 

並べ替えると分数が回避されます。```
b * d * f > a * c * e
```これは、すべての分母が正である通常のケースを処理します。 

残りの課題はゼロハンドリングです。 入力がゼロの呪文は、無から物質を生み出すことができます。 このような呪文は乗算引数を完全に回避します。 

たとえば、次の場合`c = 0`そして`d > 0`、2番目の呪文は無料でゴールドを作成します。 無限のゴールドが即座に得られます。 

同様に、`e = 0`そして`f > 0`, 無から無限の砂を生成することができます。 最初の 2 つの呪文で最終的に砂を金に変えることができれば、無限の金が続きます。 

ソリューション全体は、論理チェックの小さなコレクションになります。

 ## アルゴリズムのチュートリアル

 1. 2 番目の呪文が何もないところからゴールドを生成するかどうかを確認します。 

もし`c == 0`そして`d > 0`そうすると、すべての鋳造で鉛を消費せずに金が生成されます。 すぐに無限に何度でもキャストできるので、答えは次のとおりです。`"Ron"`。 
2. 3 番目の呪文が何もないところから砂を生成するかどうかを確認します。 

もし`e == 0`そして`f > 0`, そうすれば無料で無制限に砂を生成できるようになります。 その砂を金に変えるには、実際に鉛を生成する最初の呪文と、実際に金を生成する 2 番目の呪文も必要です。 

具体的には次のものが必要です。`a > 0`、`b > 0`、`c > 0`、 そして`d > 0`。 

すべて当てはまれば、答えは次のようになります。`"Ron"`。 
3. 分母がゼロの不可能なサイクルを処理します。 

そのうちの分母がある場合`a`、`c`、 または`e`がゼロの場合、乗算サイクルの公式は無効になります。 

この時点で、すべての無料制作ケースはすでに処理されていました。 分母がゼロのままでは無限のゴールドを生成できないため、答えは次のようになります。`"Hermione"`。 
4. フルサイクルの増幅率を比較します。 

次のことを計算します。```
b * d * f > a * c * e
```true の場合、1 つの完全なサイクルで砂が厳密に増加します。 このサイクルを無限に何度も繰り返すと、無限のリソースが得られ、したがって無限のゴールドが得られます。 
5. それ以外の場合は出力`"Hermione"`。 

### なぜ効果があるのか

 システムにはリソース サイクルが 1 つだけ含まれています。```
sand -> lead -> gold -> sand
```持続可能な無限の成長戦略は、このサイクルを繰り返し実行する必要があります。 1 回の横断の最終的な効果は、砂を次のように倍増します。```
(b/a) * (d/c) * (f/e)
```この商品が超過した場合`1`、サイクリングを繰り返すと、リソースが際限なく増加します。 せいぜい`1`、完全なサイクルごとに、使用可能なマテリアルの総量が維持または減少するため、無限の成長は不可能です。 

唯一の例外は、呪文が入力を消費しない場合です。 そのような状況では、何もないところから物質が現れる可能性があり、それらのケースを明示的に個別に処理する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, b, c, d, e, f = map(int, input().split())

# Free gold
if c == 0 and d > 0:
    print("Ron")
    sys.exit()

# Free sand
if e == 0 and f > 0:
    if a > 0 and b > 0 and c > 0 and d > 0:
        print("Ron")
    else:
        print("Hermione")
    sys.exit()

# Invalid cycle denominators
if a == 0 or c == 0 or e == 0:
    print("Hermione")
    sys.exit()

# Profitable cycle
if b * d * f > a * c * e:
    print("Ron")
else:
    print("Hermione")
```最初の 2 つのチェックは、危険なゼロ入力呪文を分離します。 これらは、通常の保存スタイルの推論を打ち破るという点で特別です。 マテリアルを消費しない呪文は永久に繰り返すことができます。 

2 番目の条件には特に注意が必要です。 無料の砂だけでは十分ではありません。 最初の 2 つの呪文を使用して、砂を金に変えることができる必要があります。 そのため、コードはこれらの変換に対する正の入力と出力を検証します。 

分母チェックにより、ゼロ除算の論理エラーが防止されます。 無料生産のケースがすべて削除されると、分母がゼロになると、サイクルが利益を上げて機能できないことを意味します。 

最後の比較では、整数演算のみが使用されます。 両辺を乗算すると、浮動小数点の精度の問題が完全に回避されます。 

Python の整数は大きな積を自動的に安全に処理しますが、ここでは最大値は次のとおりです。```
1000 * 1000 * 1000 = 10^9
```これはすでに標準の整数範囲に快適に収まっています。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    a, b, c, d, e, f = map(int, input().split())

    if c == 0 and d > 0:
        print("Ron")
        return

    if e == 0 and f > 0:
        if a > 0 and b > 0 and c > 0 and d > 0:
            print("Ron")
        else:
            print("Hermione")
        return

    if a == 0 or c == 0 or e == 0:
        print("Hermione")
        return

    if b * d * f > a * c * e:
        print("Ron")
    else:
        print("Hermione")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    solve()
    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

# provided sample
assert run("100 200 250 150 200 250\n") == "Ron", "sample 1"

# all zero
assert run("0 0 0 0 0 0\n") == "Hermione", "all zero"

# free gold
assert run("1 1 0 1 5 5\n") == "Ron", "free gold creation"

# free sand but impossible conversion
assert run("0 0 1 1 0 10\n") == "Hermione", "cannot convert sand"

# profitable cycle
assert run("1 2 1 2 1 2\n") == "Ron", "growth factor > 1"

# non-profitable cycle
assert run("2 1 2 1 2 1\n") == "Hermione", "growth factor < 1"

# equality case
assert run("1 1 1 1 1 1\n") == "Hermione", "exact conservation"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`0 0 0 0 0 0`|`Hermione`| 完全に非アクティブなシステム |
 |`1 1 0 1 5 5`|`Ron`| 無料のゴールド生成 |
 |`0 0 1 1 0 10`|`Hermione`| 無料の砂だけでは不十分です。 
|`1 2 1 2 1 2`|`Ron`| 収益性の高い乗算サイクル |
 |`2 1 2 1 2 1`|`Hermione`| 各サイクルのリソース損失 |
 |`1 1 1 1 1 1`|`Hermione`| 正確な保存は無限の成長を許しません。 

## 特殊なケース

 無料のゴールドのケースを考えてみましょう。```
1 1 0 5 1 1
```アルゴリズムは最初に以下をチェックします。```
c == 0 and d > 0
```これは次のようになります。```
0 == 0 and 5 > 0
```これは真実なので、答えはすぐにわかります`"Ron"`。 

それは正しいです。2 番目の呪文は`5`鉛を一切消費せずに金をグラム単位で摂取できます。 無限に何度でもキャストできます。 

ここで、使用可能な変換を行わない自由な砂を考えてみましょう。```
0 0 1 1 0 10
```3 番目の呪文は無料で砂を作成しますが、最初の呪文は砂を鉛に変換できません。`a`そして`b`はゼロです。 

アルゴリズムは自由砂ブランチに入ります。```
e == 0 and f > 0
```次に、最初の 2 つの呪文がゴールドへの有効なパイプラインを形成しているかどうかをチェックします。```
a > 0 and b > 0 and c > 0 and d > 0
```これは失敗するので、答えは次のようになります`"Hermione"`。 

最後に、正確な保存を考慮します。```
1 1 1 1 1 1
```乗算比較は次のようになります。```
1 * 1 * 1 > 1 * 1 * 1
```それは誤りです。 

どのサイクルでもまったく同じ量の砂が返されます。 資源は決して増加しないため、金が勝手に大きくなることはありません。 アルゴリズムは正しく印刷します`"Hermione"`。
