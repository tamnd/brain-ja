 ## 解決策
 ## 問題の理解

 単位長のセグメントと、直角に結合された 2 つのセグメントからなる L 字型のピースの 2 種類の積み木が与えられます。 寸法を持つ長方形のグリッドを構築する必要があります$n \times m$すべての部品が 1 回だけ使用されるようにします。 入力はカウントを提供します$p$単一セグメントの場合と$q$L字型ピース用。 私たちのタスクは、正の整数のペアを見つけることです。$n$そして$m$そのようなグリッドの構築を許可するか、不可能であると報告します。 

制約により許可されるのは、$p$そして$q$まで$10^8$最大 100 のテスト ケース。 これにより、考えられるすべてのことを繰り返すソリューションは除外されます。$n$そして$m$ディメンションの潜在的な検索スペースが膨大になる可能性があるため、単純に値を設定します。 すべての四角形をテストする直接的な総当たりアプローチ$10^8$セグメントが遅すぎます。 また、小さなエッジケースも考慮する必要があります。たとえば、$p=1, q=2$、単純なタイリング仮定により、答えが存在すると誤って結論付ける可能性があります。 もう 1 つの微妙な点は、L 字型のピースは回転できるため、グリッドの周囲への寄与は変化する可能性がありますが、常に正確に 2 つの単位セグメントの領域をカバーすることです。 

最初の重要な観察は、グリッドがカバーする「単位長セグメント」の総数は次のとおりであるということです。$2q + p$。 各 L 字型ピースはカバレッジ内の 2 つのセグメントに寄与し、各単位セグメントは 1 つのセグメントに寄与します。 の面積$n \times m$グリッドは$n \cdot m$。 だから必要なのです$n \cdot m = p + 2q$。 ただし、すべての因数分解ができるわけではありません。$p+2q$これは、ピースによって覆われている垂直方向と水平方向のエッジの数も一致させる必要があるため、機能します。 これは単純な因数分解を無効にする微妙な部分です。行および列に沿ったセグメントの数は、利用可能な部分と一致する必要があります。 

明らかではないエッジケースとしては、次のようなものがあります。 

-$p=1, q=2$: 対象となるセグメントの合計は$5$、長方形領域を形成できません$n \cdot m = 5$整数辺を持つ。 出力は次のようになります$-1$。 
-$p=2, q=10$: セグメントの合計$22$次のように因数分解できます$2 \times 11$または$11 \times 2$。 L 字型ピースの回転制約に一致する因数分解のみが有効です。 

これらのケースは、単にエリアをチェックするだけでは不十分であることを示しています。 L 字型の部分によって課される面積とパリティの両方の制約を考慮する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、可能なすべての四角形サイズが試行されます。$1 \le n \le p+2q$そして計算する$m = (p + 2q)/n$、グリッドのサイズかどうかを確認します$n \times m$与えられたもので完全に満たすことができます$p$そして$q$。 各チェックでは、L 字型の部分と単一セグメントの配置のすべての順列をテストする必要があります。 これは、数値が小さい場合には正しいですが、次の場合には実行できません。$p, q$まで$10^8$関与する可能性があるため$10^8$テストケースごとの反復回数。 

最適なアプローチは 2 つの洞察に基づいています。 まず、すべてのピースによってカバーされる合計面積は正確に次のようになります。$p + 2q$。 第 2 に、グリッド内の各行と列は、完全な L 字型の範囲を超えて必要な「追加のセグメント」が正確に収まるように、L 字型の部分と単一のセグメントの組み合わせでカバーされる必要があります。$p$。 具体的には、行優先または列優先のタイリングを試みた場合、各行は最大で 2 つのデータを格納できます。$\lfloor m/2 \rfloor$幅に沿ってL字型のピース。 これから、次のように解決できます。$n$または$m$整数の除算とモジュロチェックを使用して、係数ごとに定数時間の式を生成します。$p + 2q$。 因数の数は大体こんな感じなので$O(\sqrt{p+2q})$、アルゴリズムは大きな入力に対しても高速に実行されます。 

これにより、解決策はすべての約数を列挙することになります。$p + 2q$残りの単位セグメントが、L 字型のピースで覆われていない残りのスロットを埋めることができるかどうかを確認します。 これは、総当たりのタイリングよりも大幅に高速です。

 | ブルートフォース | O((p+2q) * (p+2q)) | お(1) | 遅すぎる |
 | 因数分解 + チェック | テスト ケースごとの O(√(p+2q)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、合計カバレッジを計算します。$S = p + 2q$。 これは、グリッドを形成するために必要な単位長セグメントの総数を表します。 
2. すべての正の整数のペアを列挙します。$(n, m)$そのような$n \cdot m = S$。 これは反復処理によって行われます$n$から$1$に$\sqrt{S}$そしてさせて$m = S / n$もし$S$で割り切れます$n$。 
3. 各候補者について$(n, m)$、グリッドを正確に埋めることができるかどうかを確認します$q$L字型のパーツや$p$単一セグメント。 有効な構成は次の条件を満たす必要があります。$\max(n, m) - 1 \ge q$そして$p \ge 0$, reflecting that L-shaped pieces need at least 2x1 area and can be rotated.
 4. 有効な場合$(n, m)$が見つかった場合は、それを印刷して次のテスト ケースに進みます。 ペアが機能しない場合は、印刷します$-1$。 
5. すべてのテスト ケースに対して繰り返します。 

機能する理由: このアルゴリズムは、積が利用可能なセグメントの総数と等しい長方形の寸法のみを考慮し、エリアが正確にカバーされることを保証するため、正確性を保証します。 L字ピースや余った単セグメントの配置可能性をチェックすることで、無駄なピースを残さないようにします。 因数分解$S$考えられる整数グリッドの次元をすべて網羅するため、有効な解が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        p, q = map(int, input().split())
        total = p + 2*q
        found = False
        i = 1
        while i * i <= total:
            if total % i == 0:
                n, m = i, total // i
                # check if L-shaped pieces can fit
                if n >= 2 and m >= 2:
                    found = True
                    print(n, m)
                    break
                if n == 1 and m >= 2 and q == (m - 1):
                    found = True
                    print(n, m)
                    break
                if m == 1 and n >= 2 and q == (n - 1):
                    found = True
                    print(n, m)
                    break
            i += 1
        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```コードは、テスト ケースの数を読み取ることから始まります。 テスト ケースごとに、必要なセグメントの合計数が計算されます。 while ループは、最大の約数をすべて列挙します。$\sqrt{S}$候補の寸法を見つけます。 内部の条件は、L 字型のピースを長方形のブロック内に配置できるか、単一の行または列に沿って配置できるかをチェックします。 フラグにより​​、テスト ケースごとに有効な回答が 1 つだけ印刷されることが保証されます。 エッジケースなど$n=1$または$m=1$誤ったタイリング仮定を避けるために明示的に処理されます。
