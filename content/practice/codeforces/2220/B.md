 ## 解決策
 ## 問題の理解

 私たちには 1 から n までの一連のポジションが与えられ、それぞれをボランティアがガードします。 ヘクターは位置 0 から開始し、1 秒ごとに左、右に 1 歩移動するか、静止したままにして、位置 n+1 に到達したいと考えています。 

各ボランティアには、決定的に進化するタイマーがあります。 時間 x における位置 i の値は (a_i + x) mod m です。 位置 i のボランティアは、この値が 0 の場合にのみヘクターを積極的に監視しています。タイマーが 0 のときにヘクターが秒の開始時に位置 i に立っている場合、彼はすぐに捕らえられます。 

重要な難点は、ヘクターが左右に動けるため、順番にポジションを通過する必要がないことです。 進行を遅らせたり、安全な瞬間を待ったり、悪いタイミングを避けるために以前の位置に後退したりすることもあります。 

タスクは、ガードのタイマーが 0 になったときに、ヘクターがガードされた位置にいることなしに位置 0 から位置 n+1 に移動できる一連の移動が存在するかどうかを判断することです。 

制約は大きく、テスト ケース全体の合計 n は最大 2⋅10^5、m は最大 10^9 です。 時間は任意に大きくなり、動きの選択により巨大なグラフが作成されるため、時間の経過に伴うシミュレーションや (位置、時間) の状態空間検索は直ちに除外されます。 

状態 (i, t mod m) に対する単純な BFS は、時間次元に制限がなく、m が大きすぎて拡張できないため、不可能です。 

左に移動する能力から、微妙なエッジケースが発生します。 多くの誤った貪欲なアプローチは、ヘクターが順番にポジションを通過しなければならないことを前提としていますが、左に移動することを使用して、ポジションの制約から時間を「非同期」にすることができます。 

たとえば、ヘクターが通常直線経路でそこに到着するまさにそのときに位置 i が危険になった場合、単純な解決策では「ブロックされている」と言えるかもしれませんが、別の場所で待つか振動することで到着時間をずらし、悪い瞬間を回避することができます。 

もう 1 つの注意が必要なケースは、a_i がすでに 0 である場合です。 その場合、位置 i は時間 0 で危険です。ヘクターが i の到着パリティに一致する安全な時間までその位置に到達するのを遅らせることができない場合、たとえ後の位置が安全であっても、答えは NO になります。 

## アプローチ

 ブルートフォース戦略では、状態 (位置、時間) に関する最短経路問題としてヘクターの動きをシミュレートしようとします。 各状態から 3 つの動きに分岐します。 移動するたびに時間が 1 ずつ進み、その位置に着地するのが安全かどうかを確認します。 

これは、考えられるすべての戦略を検討するため、原則として正しいです。 ただし、時間には制限がなく、人為的に時間に制限を設けたとしても、状態の数は O(n・T) になります。ここで、T は意味のあるサイクルを表すのに十分な大きさである必要があります。 m は最大 10^9 であるため、時間を法 m に組み込もうとしても O(nm) 構造が生成されますが、これは不可能です。 

重要な観察は、ヘクターの動きは、ヘクターが各セグメントにどれくらいの時間滞在するか、そして安全な時間に各位置を訪問できるかどうかの同等性にのみ依存するということです。 左に移動できるということは、単一の増加経路に制約されないことを意味します。 代わりに、各位置 i は、ヘクターが (a_i + t) mod m ≠ 0 となる時刻 t にそこに到着できるかどうかに制約を課すだけです。 

制約を書き直すと、t ≠ -a_i (mod m) の場合、位置 i は時間 t において安全です。 これは、各位置が単一の無限の時間の等差数列を禁止することを意味します。 

重要な洞察は、ヘクターが i-1 と i の間を行き来することで位置 i への到着を「遅らせる」ことを常に選択でき、効果的に到着時間を任意の余分な秒数だけずらすことができるということです。 したがって、各位置について重要なのは、t が前方への進行を許可しながら、その位置で m を法とする禁止された剰余クラスを回避できるような時刻 t ≥base_time(i) が存在するかどうかです。

これにより、問題は貪欲な実現可能性チェックに集約されます。左から右への移動をシミュレートし、ヘクターが各位置に到達できる最も早い時間を追跡します。 これ以上遅らせることができない方法で、可能な限り最も早い到着時間が単一の禁止合同クラス法 m に強制的に組み込まれる位置に到達した場合、失敗します。 

構造はさらに単純化され、各位置 i は、m を法として 1 回だけブロックされます。 ヘクターは i に入る前に位置 i−1 で任意に待機できるため、任意の到着時刻 t ≥ current_time + 1 を選択できます。 したがって、位置 i は、すべての t ≥ current_time + 1 が t ≡ bad_i (mod m) を満たす場合にのみ不可能ですが、これは決して真ではありません。 したがって、実際の失敗が発生するのは、current_time + 1 が既に禁止時刻に正確に到達しており、m = 1 であるが、m ≥ 2 である場合にのみ発生するため、直接的なブロックは発生しません。 

したがって、真の制約はグローバルになります。競合が問題となるのは、2 つの連続した制約により、位置間のタイミング調整において避けられない衝突が強制される場合のみです。 これは既知の単純化につながります。線形前方パスが可能かどうかを追跡し、各ステップで禁止されていない到着時間を常に選択できるかどうかを確認します。これは、開始位置合わせによってチェーン全体にわたって不可能な同期が強制されない限り、常に可能です。 

これは、直線到着 i が制約に違反し、かつ左移動による迂回路がすべての制約を同時に回避するのに十分なパリティをシフトできるような i が存在するかどうかをチェックすることになります。 実際には、問題はダイレクト パスがすべての位置ですでに安全であるかどうかを確認することになります。 

したがって、最終的には、すべての到着時間を均一にシフトする初期待機によって達成されるグローバル オフセットを使用して、ヘクターが単純に毎秒右に移動できるかどうかを検証することになります。 

すべての i について、(t0 + i) mod m ≠ -a_i mod m となるようなシフト t0 が存在するかどうかをチェックすることによって、考えられるすべてのグローバル シフトを暗黙的にのみテストします。 これは古典的な禁止残基のアライメント問題になりますが、i ごとに禁止残基は 1 つだけであるため、一貫した割り当てを妨げる構造的な方法で矛盾が重複しない限り、有効なシフトが存在します。 

これは合同の実現可能性をチェックすることに帰着でき、最終的には強制的な衝突パターンが存在しないことを検証することが単純化され、これは O(n) で実行できます。

 ## アルゴリズムのチュートリアル

 この問題をグローバル開始遅延 t0 を選択するものとして再解釈し、その後ヘクターは位置を再検討することなく厳密に右に移動します。 このビューでは、ヘクターは時刻 t0 + i に位置 i に到達します。 

各位置 i について、禁止された到着条件を計算します。 

t0 + i ≡ -a_i (mod m)、これは t0 ≡ (-a_i - i) mod m に再配置されます。 

これは、各位置が m を法とする t0 の値を 1 つだけ禁止することを意味します。 これらすべての禁止された残基を回避する t0 が存在する場合、Hector は成功します。 

以下のように進めていきます。 

1. 各位置 i について、禁止された剰余 r_i = (-a_i - i) mod m を計算します。 これは、ヘクターが位置 i で捕捉される原因となる正確な開始遅延です。 
2. すべての r_i 値をセットに挿入します。 
3. セット サイズが厳密に m より小さい場合、少なくとも 1 つの有効な t0 が存在するため、Hector はエスケープできます。 
4. 設定サイズが m に等しい場合、考えられるすべての t0 が少なくとも 1 つの位置によって禁止されるため、エスケープは不可能です。 
5. それに応じて YES または NO を出力します。 

これが機能する主な理由は、ヘクターのすべての戦略を、単一の初期待機時間 t0 とその後の継続的な右移動を伴う戦略に変換できることです。 迂回路を残した場合や途中で待機した場合は、t0 にのみ影響し、制約の構造には影響しません。これは、移動が時間的に均一であり、各位置が到着時間に単一のモジュール制限を課すためです。 

### なぜ効果があるのか

各位置は、グローバル オフセット t0 に対して 1 つの禁止された剰余クラスに寄与します。 ヘクターのパスは、初期遅延を伴う単調な右移動パスに常に正規化できます。 この正規化により、中間振動ではなく到着時間のみが重要となるため、安全制約が維持されます。 したがって、問題は、禁止された剰余の結合がモジュロ空間全体をカバーするかどうかをチェックすることに帰着します。 そうなった場合、開始遅延は機能しません。 それ以外の場合は、少なくとも 1 つの遅延によりすべての衝突が回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        
        seen = set()
        for i, ai in enumerate(a, start=1):
            r = (-ai - i) % m
            seen.add(r)
        
        # If we already cover all residues, impossible
        print("NO" if len(seen) == m else "YES")

if __name__ == "__main__":
    solve()
```このソリューションは、移動の問題全体を、位置ごとのモジュール式制約の計算に削減します。 このループは各ガードの禁止された開始遅延を計算し、ヘクターが直線的に増加するパスをたどった場合にそのガードと衝突する正確な瞬間をエンコードします。 

このセットは、すべての個別の禁止されたオフセットを収集します。 m を法とするすべての剰余がカバーされている場合、開始遅延の可能性があるたびに少なくとも 1 回の衝突が発生し、脱出が不可能になります。 それ以外の場合は、安全なオフセットが存在します。 

唯一の微妙な実装の詳細は、位置 i が移動開始後の時間 i に対応するため、式内で慎重に 1 インデックスを付けることです。 

## 実用的な例

 ### 例 1

 次のことを考慮してください。 

n = 3、m = 5

 a = [1, 0, 2]

 禁止された剰余を計算します。 

| 私 | a_i | r_i = (-a_i - i) mod 5 |
 | --- | --- | --- |
 | 1 | 1 | (-2) mod 5 = 3 |
 | 2 | 0 | (-2) mod 5 = 3 |
 | 3 | 2 | (-5) mod 5 = 0 |

 禁止された残基のセットは {0, 3} です。 すべての剰余 mod 5 がカバーされているわけではないため、有効な開始遅延が存在します。 答えは「はい」です。 

これは、複数の位置が同じオフセットを禁止する可能性があることを示しています。そのため、多重度ではなくカバレッジのみを考慮します。 

### 例 2

 n = 2、m = 3

 a = [0, 0]

 | 私 | a_i | r_i |
 | --- | --- | --- |
 | 1 | 0 | 2 |
 | 2 | 0 | 1 |

 禁止されたセットは {1, 2} です。 剰余 0 は引き続き使用できるため、t0 = 0 を選択すると両方の衝突が回避されます。 ヘクトルは逃げる。 

これは、時間 0 で両方のポジションが危険な場合でも、単純なシフトで競合を解決できることを裏付けています。

 ## 特殊なケース

 微妙なケースの 1 つは、多くの位置で同一の禁止残基が生成される場合です。 たとえば、すべての a_i が等しい場合、すべての r_i は小さなセットにまとめられます。 アルゴリズムは個別の残基のみを追跡し、重複は実現可能性に影響を与えないため、これを正しく処理します。 

もう 1 つのケースは、m が n に比べて小さい場合です。 n ≥ m で残基が多様な場合、セットはすぐに飽和し、正しく NO をトリガーできます。 これは、セットサイズチェックによって自然に処理されます。 

最後のケースは、m が大きく、n が小さい場合です。 その場合、飽和は不可能であり、答えは常に YES であり、グローバル遅延の選択には十分な自由があるという直観と一致します。
