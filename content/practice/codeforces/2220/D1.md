 ## 解決策
 ## 問題の理解

 元の対話型問題には、長さの隠し配列があります。$2n+1$。 からのすべての値$1$に$n$3 回出現する 1 つの特別な値を除いて、正確に 2 回出現します。 タスクは、その特別な値を含む 3 つの位置を特定することです。 

ハッキングで使用される非対話型バージョンの場合、配列全体が入力として与えられます。 もうクエリを通じて何かを再構築する必要はありません。 単純に配列を受け取り、頻度 3 の値が出現する 3 つのインデックスを出力する必要があります。 

配列の長さは$2n+1$、およびすべての合計$n$テスト ファイルの値は最大でも$2 \cdot 10^4$。 つまり、配列要素の総数はわずか約$4 \cdot 10^4$。 線形または線形に近いソリューションは、簡単に十分に高速です。 

主な落とし穴は、値そのものではなくポジションが必要であることを忘れないことです。 たとえば、```
1 2 1 3 2 1 3
```3 回繰り返される値は`1`、ただし必要な答えはポジションです```
1 3 6
```インデックスの代わりに値を出力するソリューションは正しくありません。 

もう 1 つの簡単な間違いは、内部で 0 から始まるインデックスを使用し、印刷時に 1 から始まるインデックスに変換し直すのを忘れることです。 のために```
1 1 2 2 1
```正しい答えは```
1 2 5
```ない```
0 1 4
```## アプローチ

 最も直接的な総当り攻撃のアイデアは、すべての個別の値をチェックし、その値が出現する回数をカウントすることです。 値は範囲に制限されているため、$1 \ldots n$、配列を繰り返しスキャンして、頻度が 3 に等しい値を見つけることができます。 その値を特定した後、再度スキャンしてその位置を収集します。 

あれば$n$可能な値と配列の長さは$2n+1$、このアプローチは実行します$O(n(2n+1)) = O(n^2)$仕事。 

入力の構造により、より単純なオプションが提供されます。 すべての値は正確に 2 回現れますが、1 つの値は正確に 3 回現れます。 単一の度数表で特別な値がすぐにわかります。 

配列の読み取り中に、すべての数値の出現をカウントします。 頻度テーブルが構築されると、ちょうど 1 つの値が頻度 3 になります。 配列を 2 回通過すると、その 3 つの位置が収集されます。 

これにより、実行時間が線形の複雑さまで短縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 概念的には遅すぎる |
 | 最適 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む$n$。 
2.長さの配列を読み取ります$2n+1$。 
3. 配列内のすべての値の頻度表を作成します。 
4. 頻度が 3 に等しい一意の値を見つけます。 
5. 配列を再度スキャンし、その値が出現するすべての位置を記録します。 
6. 1 ベースのインデックスを使用して、記録された 3 つの位置を出力します。 

### なぜ効果があるのか

 この問題では、1 つの値が 3 回出現し、他の値が 2 回出現することが保証されます。 度数表はその値を一意に識別します。 値が判明すると、その値を含むすべての位置が答えに属します。 正確に 3 回発生するため、収集された位置は正確に必要な 3 つのインデックスになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1

        target = None
        for x, cnt in freq.items():
            if cnt == 3:
                target = x
                break

        ans = []
        for i, x in enumerate(a, start=1):
            if x == target:
                ans.append(i)

        print(*ans)

solve()
```最初のループは頻度テーブルを構築します。 このステートメントでは、3 回現れる正確に 1 つの値の存在が保証されているため、`cnt == 3`常に成功します。 

特別な値を見つけた後、2 番目のパスでその位置を収集します。 への呼び出し`enumerate(..., start=1)`この問題では 1 から始まるインデックスが使用されているため、これは重要です。 忘れる`start=1`ここで最も一般的な off-by-one エラーです。 

このアルゴリズムは、配列に対してネストされたスキャンを実行することはありません。 すべての要素は一定の回数だけ処理されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n)$| 一定の長さの配列にわたる 2 つの線形パス$2n+1$|
 | スペース |$O(n)$| 頻度テーブルは最大で保存されます$n$個別の値 |

 合計入力サイズは小さく、$\sum n \le 2 \cdot 10^4$。 線形ソリューションは制限内で快適に実行されます。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def solve():
        input = sys.stdin.readline
        t = int(input())
        out = []

        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))

            freq = {}
            for x in a:
                freq[x] = freq.get(x, 0) + 1

            target = next(x for x, c in freq.items() if c == 3)

            pos = []
            for i, x in enumerate(a, start=1):
                if x == target:
                    pos.append(str(i))

            out.append(" ".join(pos))

        return "\n".join(out)

    return solve()

# triple value at end
assert run("1\n3\n1 2 1 2 3 3 3\n") == "5 6 7"

# multiple test cases
assert run(
    "2\n"
    "2\n1 2 1 2 1\n"
    "3\n2 2 3 1 3 1 2\n"
) == "1 3 5\n1 2 7"

 ## 特殊なケース

 最小の有効なインスタンスを考えてみましょう。```
n = 2
a = [1, 1, 1, 2, 2]
```頻度表は次のようになります。`{1: 3, 2: 2}`。 アルゴリズムが選択するのは、`1`特別な値として位置を出力します`1 2 3`。 ロジック内の何も大きな配列に依存しません。 

3 つの出来事が大きく離れている場合を考えてみましょう。```
n = 3
a = [2, 1, 3, 2, 1, 3, 2]
```ポジションは、`1`、`4`、 そして`7`。 アルゴリズムは最初に値を識別してから位置を収集するため、隣接性は無関係です。 

三重値が最大値である場合を考えてみましょう。```
n = 4
a = [1, 2, 1, 2, 3, 4, 3, 4, 4]
```頻度表は、```
1 -> 2
2 -> 2
3 -> 2
4 -> 3
```アルゴリズムは正しく選択します`4`そして出力`6 8 9`。 実際の数値は重要ではなく、その頻度のみが重要です。
