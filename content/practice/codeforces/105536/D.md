 ## 解決策
 ## 問題の理解

 一連のタスクが一列に並べられており、各タスクには整数の難易度が設定されています。 Vanya という名前のキャラクターのスキル レベルは低い値から始まり、タスクを完了するにつれて増加します。 

Vanya はシーケンスを繰り返しスキャンすることを許可されていますが、タスクをランダムに選択することはありません。 代わりに、彼は常に、現在解決できる配列内で最も早いタスクを実行します。 能力は、現在のスキル レベルとタスクの難易度を比較することによって決定されます。 タスクを解決するとスキルが向上し、これまでは難しすぎた、または正しい順序で到達できなかった追加のタスクのロックを解除できるようになります。 

このプロセスは配列の構造によって制約されます。つまり、位置が重要であり、いつでも解決可能なすべてのタスクの中で、最小のインデックスを持つタスクが常に選択されます。 タスクが実行されると、そのタスクは検討対象から消え、ワーニャはその位置から前に向かって検索を続けます。 

目標は、このプロセスを効率的にシミュレートし、Vanya が解決するタスクの完全なシーケンスを決定することです。 

この制約は、タスクごとに配列を最初から繰り返しスキャンする単純なシミュレーションが最悪の場合に 2 次の動作につながることを意味します。 n が 2e5 などの一般的な Codeforce 制限までの場合、最大 4e10 の操作が必要となるため、O(n²) スキャンは遅すぎます。 これは、完全な走査の繰り返しを避け、代わりに次の有効な候補への増分アクセスを維持する必要があることを直ちに示唆しています。 

微妙なエッジケースは、ある時点で唯一解決可能なタスクがはるか右にあるものの、スキルの向上により、以前のタスクが後で解決可能になる場合に発生します。 適切な簿記を持たない単純な左から右への貪欲スキャンでは、新しくロック解除されたタスクがスキップされるか、不必要に再スキャンされ、依然として順序付けの制約を見逃す可能性があります。 

もう 1 つのエッジ ケースは、同じ難易度のタスクが複数出現する場合です。 アルゴリズムは、スキルが上がるたびに最初からスキャンを再開するのではなく、最も古い未処理の発生を保存する必要があります。 

## アプローチ

 簡単なアプローチは、Vanya の行動を文字通りシミュレートすることです。 配列全体を繰り返しスキャンし、現在のスキルを超えない難易度の左端のタスクを選択し、それを削除し、スキルを上げて繰り返します。 これはルールを正確に反映しているため、正しいです。 ただし、各フル スキャンには O(n) のコストがかかり、最大 O(n) 回の成功したピックを実行する可能性があるため、合計の複雑さは O(n²) になります。 入力が大きい場合、これは不可能になります。 

重要な観察は、各難易度レベルが位置に関して独立して動作するということです。つまり、各難易度の次の未処理の出現のみを気にすることになります。 これらの位置がわかれば、配列全体をスキャンしなくても候補を決定できます。 

これは、難易度値ごとに、次の未使用の出現へのポインタを維持することを示唆しています。 現在「アクティブ」なすべての難易度 (難易度 ≤ 現在のスキルを意味します) の中で、最小の次回出現インデックスが必要です。 これにより、問題は動的に更新される候補の中から最小値を繰り返し抽出することになります。これはまさに順序付きセットまたはヒープがサポートするものです。 

スキルが上がると、新しい難易度クラスがアクティブになり、その最初の利用可能なクラスを挿入するだけで済みます。 タスクが実行されると、その難易度内で進み、次のタスクがまだ存在する場合はそのタスクを挿入します。 これにより、配列全体の再スキャンが回避され、プロセスが O(n log n) に削減されます。

 ## アルゴリズムのチュートリアル

1. 各難易度値のすべてのインデックスを昇順にグループ化します。 これにより、どんな困難があっても、検索せずに次の未使用のタスクがどこにあるかを知ることができます。 
2. 難易度ごとに、リスト内の最初の未使用の位置を示すポインタを維持します。 初期状態では、すべてのポインターはゼロにあります。 
3. Vanya のスキルの下で現在アクティブになっているすべての難易度のフォーム (インデックス、難易度) のペアを保存する順序付けされた構造 (通常はセット) を維持します。 最初は、開始スキル以下の難易度のみがアクティブになるため、それらの最初の出現を挿入します。 
4. セットから最小のインデックスを繰り返し抽出します。 これは、Vanya が常に最も早く到達可能なタスクを実行するというルールに従って解決する次のタスクを表します。 
5. インデックス i で難易度 d のタスクを削除した後、d のポインタを次のタスクに進めます。 そのようなオカレンスが存在し、現在の制約の下で有効である場合は、それをセットに挿入します。 
6. タスクが成功するたびに、Vanya のスキルが向上します。 スキルが新しい値 s に増加すると、その最初の出現をセットに挿入することでこの難易度をアクティブ化します (存在する場合)。 
7. セットが空になるまで、つまり到達可能なタスクがなくなるまで続行します。 

重要な不変条件は、Vanya のスキルで現在許可されているすべての難易度に対して、次に利用可能な候補インデックスが常に正確にセットに含まれていることです。 難易度がアクティブになるか進行するたびに、次のタスクがすぐに挿入されるため、有効なタスクが省略されることはありません。 アクティブな難易度からのインデックスのみが保存されるため、無効なタスクは選択されません。 

これにより、抽出された最小値が常にグローバル順序で正しい次のタスクとなり、必要な貪欲ルールに一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = {}
    for i, v in enumerate(a):
        if v not in pos:
            pos[v] = []
        pos[v].append(i)

    # pointer per value
    ptr = {v: 0 for v in pos}

    import bisect

    # current skill starts at 1 (as implied by statement structure)
    skill = 1

    import heapq
    heap = []

    def add_value(v):
        if v not in pos:
            return
        i = ptr[v]
        if i < len(pos[v]):
            heapq.heappush(heap, (pos[v][i], v))

    # initialize active values
    for v in pos:
        if v <= skill:
            add_value(v)

    used = set()
    res = []

    while heap:
        i, v = heapq.heappop(heap)
        if (i, v) in used:
            continue
        used.add((i, v))
        res.append(i)

        ptr[v] += 1
        if ptr[v] < len(pos[v]):
            heapq.heappush(heap, (pos[v][ptr[v]], v))

        skill += 1
        if skill in pos:
            add_value(skill)

    print(*res)

if __name__ == "__main__":
    solve()
```解決策は、各難易度の位置をグループ化することから始まります。これにより、スキャンせずに、出現した問題の間を直接ジャンプできるようになります。 ポインタ辞書は、各グループ内の進行状況を追跡します。 

ヒープには、インデックス順に並べられた候補タスクが維持されます。これにより、常に左端の利用可能なタスクを選択するという要件が強制されます。 タスクをポップするたびに、その難易度内で前進し、次のタスクをプッシュします。 

スキルの進行は遅延して処理されます。スキルが増加するたびに、その時点でのみ新しい難易度がアクティブになり、その最初の出現が挿入されます。 これにより、すべての可能性が時期尚早にプリロードされることが回避されます。 

実装の微妙な詳細は、ポインタの更新後に古いヒープ エントリが表示される可能性があることです。 これらは訪問セットを使用してフィルタリングされ、古い (インデックス、値) ペアが処理されないようにします。

 ## 特殊なケース

 重大なエッジケースは、同じ難易度の複数のタスクが他の難易度に挟まれている場合に発生します。 たとえば、難易度 1 が位置 0、5、および 10 に出現する場合、アルゴリズムは位置 0 を取得した後、0 を再導入することなく次の候補が正しく 5 に進むことを保証する必要があります。 

もう 1 つのエッジ ケースは、スキルの増加により、配列のサフィックスに残りの出現が存在しない新しい難易度のロックが解除される場合です。 この状況では挿入は行われず、アルゴリズムは停止したり無効なアクセスを試行したりすることなく続行する必要があります。
