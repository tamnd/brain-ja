 ## 解決策
 ## 問題の理解

 決められた日数にわたって、決められた数の問題を配布するように求められます。 私たちは毎日、解決する問題の数を選択します。また、毎日の一連のカウントは減少しない必要があります。 つまり、その日に解けた問題の数を表すと、$i$による$a_i$、 それから$a_1 \le a_2 \le \dots \le a_n$。 

日数という 2 つの整数が与えられます。$n$そして問題の総数$m$。 タスクは、負でない整数を割り当てることが可能かどうかを判断することです。$a_1, \dots, a_n$単調性制約を満たし、正確に合計する$m$。 可能であれば、少なくとも 1 つの有効なスケジュールを作成する必要もあります。 

制約構造により、すぐに分散という観点から考える必要が生じます。$m$の中へ$n$単調性条件を持つ順序付けされたバケット。 重要な問題は、合計自体ではなく、早い日が後の日を超えることができないという事実です。 

主な構造上の制限は次のとおりです。$n > m$、答えは不可能です。 1日1題以上課題を課したとしても、すでに総予算を超えてしまいます。 ゼロを許可しようとすると、単調性の制約により、意図したタスクの解釈が崩れます (元のステートメントでは意味のある構成で「待機日数」が暗黙的に禁止されているため)。また、社説の標準的な構成は厳密に前向きな毎日の作業を前提としています。 

単純なエッジケースでこの失敗を説明します。$n = 5$そして$m = 3$、毎日少なくとも 1 つの問題を割り当てる方法はありません。 どのような試みにもある程度の努力が必要です$a_i = 0$、その後、単調性により以前のすべての値も 0 になるため、合計が 3 に達することができなくなります。 

出力は実現可能性だけでなく、明示的に有効なシーケンスであるため、問題は純粋に意思決定に基づくものではなく、建設的なものになります。 

## アプローチ

 ブルート フォース ビューでは、長さが減少しないシーケンスをすべて列挙しようとします。$n$合計付き$m$。 正の整数に限定したとしても、そのようなシーケンスの数は以下の組み合わせで増加します。$m$そして$n$。 単純な生成アプローチでは、順序付け制約のある整数のパーティションが効果的に探索され、最悪の場合は指数関数的に動作します。 

これが不要な理由は、単調性制約が非常に弱いためです。 これは、「質量を右に押し出す」ことを可能にする以外に、相対的な成長パターンを制約するものではありません。 最小値を決定したら、残りは合計によって強制されます。 

重要な観察は、非常に剛性の高い構造がすでにすべての制約を満たしているということです。最初の制約はそのままにしておきます。$n-1$日は同じであり、残りの合計を最後の日に集中させます。 最初のそれぞれの場合、$n-1$days の値が 1 の場合、最後の日は次のようになります。$m - (n-1)$。 これにより、最後の値が常に少なくとも 1 になるため、単調性が自動的に保証されます。$m \ge n$、以前の値はすべて同一です。 

これにより、問題は 1 回の実現可能性チェックと直接構築に減ります。 

もう 1 つの有効な視点は、分散することです。$m$均等に: 割り当てる$\lfloor m/n \rfloor$すべての日に分配し、非減少順序を維持しながら残りを分配します。 与えられた構造は、単にこのアイデアの最も極端なバージョンです。

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り$n$そして$m$。 これらは、埋める必要がある順序付けされたスロットの数と、分配する総質量を定義します。 
2. かどうかを確認します。$n > m$。 そうであれば、有効な構造が存在しないことを出力します。 これは、1 日あたり 1 ユニットを割り当てるだけでも、すでに必要な合計の制約を超えているためです。 
3. それ以外の場合は、最初のそれぞれに 1 つの問題を割り当てます。$n-1$日々。 これにより、これまでの非降順順序が自動的に尊重される、安定した最小限の構成でシーケンスが開始されることが保証されます。 
4. 残りの値を次のように計算します。$m - (n - 1)$。 合計が正確に一致する必要があるため、これが残された唯一の自由度です。 
5. この残りの値を最終日に割り当てます。 
6. 構築されたシーケンスを出力します。 

残りの質量をすべて最後に配置する背後にある重要な考え方は、単調性が自明に維持されるということです。つまり、最後の要素が構造上最大であり、前の要素はすべて同一です。 

### なぜ効果があるのか

 アルゴリズムは、最初の$n-1$実現可能性条件が満たされる場合は常に、要素が等しく、最後の要素がそれらの要素以上である$m \ge n$が成立する。 合計制約は構築によって正確に満たされ、シーケンスはすべての隣接するペアで非減少であるため、単調性が維持されます。 制約に違反することなく、値を前の位置から後の位置にシフトすることで、有効な解をこの標準形式に変換できるため、代替の配置は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    if n > m:
        print(-1)
        return

    res = [1] * (n - 1)
    res.append(m - (n - 1))

    print(*res)

if __name__ == "__main__":
    solve()
```実装は構築の直後に行われます。 唯一の条件付き分岐は、次の場合に実行不可能性を処理します。$n > m$。 配列は最初の 1 で初期化されます。$n-1$位置を調整し、最小の辞書編集的かつ最小限の有効な接頭辞を確保します。 最終値は 1 回の減算で計算され、ループや調整を必要とせずに合計制約が保証されます。 

微妙な点は、初期の値はすべて等しく、実行可能性チェックに合格したときに最後の値が少なくとも 1 であることが保証されるため、単調性を明示的にチェックする必要がないことです。 

## 実用的な例

 ### 例 1

 入力:```

```次のように進めます。 

| ステップ | 最初の n-1 日間 | 前日の値 | シーケンス |
 | --- | --- | --- | --- |
 | 初期化 | - | - | - |

 結果のシーケンスの合計は 10 になり、減少しません。 最後の値は、最小ベースラインを超えるすべての余分な質量を吸収します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, m = map(int, input().split())
    if n > m:
        return "-1"
    res = [1] * (n - 1)
    res.append(m - (n - 1))
    return " ".join(map(str, res))

# basic sample-like cases
assert run("5 10") == "1 1 1 1 6"
assert run("3 3") == "1 1 1"

# edge: impossible
assert run("5 3") == "-1"

# edge: minimal valid
assert run("1 7") == "7"

# edge: tight boundary
assert run("4 4") == "1 1 1 1"

# larger case
assert run("6 20") == "1 1 1 1 1 15"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 5 10 | 1 1 1 1 6 | 典型的な建設的な分割 |
 | 3 3 | 1 1 1 | uniform boundary case |
 | 5 3 | -1 | n > m の場合は不可能 |

 ## 特殊なケース

 いつ$n > m$、 例えば$n = 4, m = 2$の場合、アルゴリズムはすぐに -1 を返します。 これは、厳密にポジティブな構造の下では、1 日に少なくとも 1 ユニットを割り当てることが不可能であることと一致します。 続行しようとすると、負またはゼロベースの再解釈が必要となり、意図した単調な正のスケジュールが崩れてしまいます。 

いつ$n = 1$、 例えば$n = 1, m = 7$の場合、アルゴリズムは 7 に等しい単一の値を生成します。満たすべき順序制約はなく、構造は全体の合計の直接割り当てに退化します。 

いつ$m = n$、 のような$n = 5, m = 5$、出力はすべて 1 になります。 これは、再分配のための余剰質量が存在せず、単調制約が自明に満たされる、最も厳しい実現可能な構成です。
