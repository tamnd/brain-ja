 ## 解決策
 ## 問題の理解

 正規の括弧シーケンスを形成することが保証されている括弧の文字列が与えられています。 私たちの目標は、文字列が空になるまで、2 つの操作タイプに従って文字列の一部を繰り返し削除することです。 最初のタイプでは、それ自体が有効な RBS であるプレフィックスを削除でき、この操作は何度でも使用できます。 2 番目のタイプでは、有効な RBS である連続した部分文字列を削除できますが、最大でも次の文字列に制限されます。`k`この操作の用途。 タスクは、適用できるそのような操作の最大数を決定することです。 

各入力は複数のテスト ケースで構成され、それぞれがシーケンスの長さを持ちます。`n`、限界`k`、および RBS 文字列。 合計から`n`すべてのテスト ケースは最大 200,000 件あり、アルゴリズムは線形または線形に近い必要があります。`n`。 可能なすべての部分文字列を明示的に調べるアプローチは、部分文字列の数が二次関数であるため、非常に遅くなります。`n`。 

微妙な点は、シーケンスが常に RBS であるため、最初の操作で削除するすべてのプレフィックスも RBS である必要があることです。 これは、本質的に、有効な「バランスの取れたチャンク」がいくつ存在するかを数えていることを意味します。 エッジケースには、すでに次のような多くの最小限の RBS 部分に分割されているシーケンスが含まれます。`()()()()`、または次のように深くネストされたシーケンス`(((())))`。 不注意な実装では、残りのシーケンスのバランスが崩れた部分文字列を削除しようとするため、操作が過剰にカウントされる可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのプレフィックスまたはすべてのサブストリングをチェックして有効な RBS を形成しているかどうかを確認し、それを削除しようとします。これを文字列が空になるまで繰り返します。 これは、RBS を残すあらゆる削除が許可されるため機能しますが、考えられるすべての部分文字列の検証には O(n^2) 時間がかかるため、長さが 200,000 までのシーケンスの場合は失敗します。 部分文字列ごとに、開き括弧と閉じ括弧の数を数えてバランスをチェックする必要がありますが、これは法外な作業です。 

重要な洞察は、RBS が 2 種類の構造に分解できるということです。次のような入れ子になったペアです。`(())`そして次のような連続したペア`()()`。 ペアを見るたびに`()`、プレフィックス削除操作を使用して削除できます。 これにより、タイプ 1 操作の最小単位が得られます。 一方、タイプ 2 の操作は「どこでもカット」操作に似ており、より深くネストされたチャンクに適用できます。 したがって、操作の数を最大化するために、最小限の操作をできるだけ多く削除したいと考えています。`()`可能な限りチャンクを分割し、残りのより深くネストされた部分に制限までタイプ 2 操作を適用します。`k`。 の数を数える`()`ペアを順番に並べると効果的に答えが得られます。 

これにより、問題は、ネストの深さを追跡する文字列の単純なスキャンに変換されます。 私たちが遭遇するたびに、`(`、深さを増やしていき、そのたびに、`)`、それを減らします。 比類のない状態から深さが1つ下がるたびに`(`、除去ユニットを形成できる完全なペアを特定します。 このようなユニットの数から適用されるタイプ 2 操作を差し引くと、最大操作数が得られます。

 ## アルゴリズムのチュートリアル

 1. 見つかった完全なペアの数のカウンターを初期化します。`pairs = 0`。 
2. スタック深さカウンターを初期化する`depth = 0`。 
3. 文字列の各文字を繰り返し処理します。 のために`(`、 増加`depth`1による。`)`、 減少`depth`1までに。 
4. 見るたびに`)`そして`depth`まだ負ではないので、以前に開いたものを閉じます`(`ので、増加します`pairs`。 
5. 文字列全体を処理した後の操作数は最小値になります。`pairs`そして`k`タイプ 2 操作と残りの操作の場合`pairs - type2`タイプ 1 操作として。 
6. このテスト ケースの最大操作数として合計を出力します。 

効果がある理由: それぞれ`()`ペアは取り外し可能な最小単位を表します。 これをプレフィックスまたはサブストリングとして削除すると、RBS プロパティが保持されます。 より深くネストされたユニットに対してタイプ 2 操作を使用すると、有効な RBS も削除されるため、将来の削除はブロックされません。 この貪欲なカウントにより、文字列のバランスを崩すことなく操作の最大数が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_operations(n, k, s):
    depth = 0
    pairs = 0
    for c in s:
        if c == '(':
            depth += 1
        else:
            depth -= 1
            if depth >= 0:
                pairs += 1
    # Every pair can be used as a type-1 operation, but up to k can be type-2
    return min(pairs, n // 2, k + (pairs - k))

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    s = input().strip()
    # Each type-1 removal is a single pair, type-2 counts as well
    # Since we only need count, the maximum operations = min(k + remaining type-1, total pairs)
    depth = 0
    ops = 0
    type2_used = 0
    i = 0
    while i < n:
        if s[i] == '(':
            depth += 1
        else:
            depth -= 1
            if depth >= 0:
                ops += 1
        i += 1
    # max operations cannot exceed n//2 (number of pairs)
    print(min(n // 2, ops))
```ソリューションは入力を読み取り、各文字列を 1 回スキャンします。 の`depth`counter は、開始括弧と終了括弧が正しく一致することを保証します。 それぞれの増分`ops`削除できる有効なペアに対応します。 最終的な操作回数を次のように制限します。`n//2`これは文字列内のペアの合計数であるためです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        depth = 0
        ops = 0
        for c in s:
            if c == '(':
                depth += 1
            else:
                depth -= 1
                if depth >= 0:
                    ops += 1
        output.append(str(min(n // 2, ops)))
    return "\n".join(output)
