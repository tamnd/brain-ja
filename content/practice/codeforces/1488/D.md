 ## 解決策
 ## 問題の理解

 一定の日数にわたって減少しない整数のシーケンスを構築するように求められます。ここで、毎日は Polycarp が解決する問題の数を表します。 問題の総数は固定されており、シーケンスでは 2 つの構造ルールを遵守する必要があります。つまり、日が進むにつれて減少することはできず、連続する日の間に 2 倍を超えて増加することはできません。 

私たちが最終的に気にするのはシーケンスの最後の値だけですが、その値は、合計が指定された合計と正確に一致する有効な完全なシーケンスの存在によって間接的に制約されます。 

したがって、問題は次のようになります。少なくとも 1 から始まり、減少せず、各ステップで最大 2 倍まで増加する長さ n のすべてのシーケンスの中で、シーケンス全体の合計が正確に s になるように選択できる、可能な最大の最終要素を見つけます。 

この制約により、テスト ソリューションごとに O(log s) または O(n log s) が求められます。 n と s は最大 10^18 で、テストケースは最大 1000 個あるため、シーケンスを明示的にシミュレートしたり、ネストされた構造で候補を試行したりする試みは失敗します。 制約の構造は単調かつ乗算的であり、通常、答えの二分探索と組み合わせた貪欲な実現可能性チェックを示します。 

実現可能性を無視して最後の要素を最大化することだけを考えると、微妙な問題が発生します。 たとえば、最後の要素をできるだけ大きくしようと貪欲にプッシュしようとすると、合計が s になる一方で、非減少のままではいられないプレフィックスが作成される可能性があります。 もう 1 つの失敗モードは、シーケンスがどのように「逆方向に展開」する必要があるかを慎重にチェックせずに、最後の候補の値が特定の n に対して機能すると、より小さい値もすべて機能すると仮定することです。 

主な難点は、シーケンスがローカル (隣接するもの間の比率) とグローバル (固定和) の両方で制約され、最適な構造が任意ではなく、最後の値が固定されると厳密に決定されることです。 

## アプローチ

 直接的な総当たりアプローチでは、考えられるすべてのシーケンスが試行されます。 各シーケンスについて、単調性、倍加制約、合計制約を検証し、最大の最後の要素を追跡します。 値を妥当な範囲に制限したとしても、各位置は前の位置に依存しますが、依然として多くの有効な選択肢があるため、シーケンスの数は n とともに指数関数的に増加します。 

より構造化されたブルート フォースは、最後の値 x を固定し、最小合計または正確な合計 s を使用して x で終わる有効なシーケンスを構築しようとすることです。 有効なプレフィックスのスペースは依然として n で指数関数的であるため、これでもコストが高くなります。 ボトルネックは、各位置が以前の値に応じた範囲内で変化する可能性があることです。 

重要な観察は、固定された最後の値に対して、合計を最小化するシーケンスが一意に決定されるということです。 x で終わる有効なシーケンスを作成したい場合、合計をできるだけ小さく保つための最良の方法は、後方に移動しながら値を可能な限り低くすることです。 非減少シーケンスが前方に必要なため、同様に後方にも、前の各要素が少なくとも 1 で、多くても次の要素の半分であること、また次の要素より大きくないことを確認する必要があります。 

これは、最終値を修正するときに、貪欲に後方に移動し、許容される最小値を繰り返し取得することによって、最適な (最小和) 構造が得られることを意味します。これは、基本的に、反転したときに 2 倍制約に違反しない最大値です。 

与えられた最後の値に対して可能な最小の合計を計算できると、問題は x において単調になります。 特定の x が実現可能 (最小合計 ≤ s) であれば、それより小さい任意の x も実現可能です。 これにより、答えの二分探索が可能になります。

 ## アルゴリズムのチュートリアル

 a_n の可能な最大値を二分探索し、各候補について、合計が s を超えない長さ n の有効なシーケンスを形成できるかどうかをテストします。 

1. 候補の最後の値 x を修正し、x で終わる有効なシーケンスの最小可能合計の計算を試みます。 目標は、制約によって許容される範囲でシーケンスを「圧縮」できるかどうかを確認することです。 
2. x から始まる現在の値 cur を維持しながら、n 日目から 1 日目まで逆方向に移動します。 前日ごとに可能な最小値は 1 ですが、今後の成長が 2 倍を超えることはできないことも考慮する必要があります。 制約を逆にするということは、不必要なインフレを避けるために、以前の値が少なくとも ceil(cur / 2) でなければならないということを意味します。 
3. より正確には、合計を最小化するために、前の各要素が min(cur, 残りの位置で実現可能な最大値) として選択されます。 最適な構築では、シーケンスを有効に保つ場合に cur = cur // 2 を繰り返し実行します。これは、最後に x に到達する能力を維持しながら値を削減するには、半分にすることが最も強力な方法であるためです。 
4. この逆方向プロセスを n ステップ続けて、合計を累積します。 どこかの時点で合計が s を超えた場合、この x は実行不可能であるため、早期に停止できます。 
5. 計算された合計が ≤ s の場合、x は達成可能です。 次に、二分探索でより大きな値を試します。 それ以外の場合は、x を減らします。 
6. a_n が s を超えることはできないため、二分探索は範囲 [1, s] にわたって実行されます。 

なぜ効果があるのか:

 重要な不変条件は、任意の固定エンドポイント x に対して、貪欲な逆方向構築により、x で終わる辞書編集上最小の (したがって最小合計の) 有効なシーケンスが生成されることです。 中間値をさらに減らそうとすると、単調性または 2 倍化制約に違反します。 したがって、x の実現可能性はこの一意の最小和のみに依存し、x の述語が単調になり、二分探索が可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def feasible(n, s, x):
    total = 0
    cur = x

    for _ in range(n):
        total += cur
        if total > s:
            return False
        # move backwards: best we can do is shrink by factor 2
        cur = cur // 2
        if cur == 0:
            cur = 1

    return total <= s

def solve():
    t = int(input())
    for _ in range(t):
        n, s = map(int, input().split())

        lo, hi = 1, s
        ans = 1

        while lo <= hi:
            mid = (lo + hi) // 2
            if feasible(n, s, mid):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```実装では、実現可能性のチェックと検索が分離されます。 の`feasible`関数は、固定された最終値に対するシーケンスの最適な逆方向構築をシミュレートします。 重要な繊細さは変化です`cur = cur // 2`、これは、倍加制約下でエンドポイントに到達する可能性を維持しながら、許容可能な最も強力な縮小をエンコードします。 

次に、二分探索は、この単調な実現可能性述語を使用して、最後の要素を最大化します。 

## 実用的な例

 ### 例 1

 入力: n = 3、s = 9

 a3 の候補値をテストします。 

| × | シーケンス構築（逆発想） | 合計 | 実現可能 |
 | --- | --- | --- | --- |
 | 4 | [1、2、4] | 7 | はい |
 | 5 | [1, 2, 5] は無効です。有効な最良の合計は依然として 9 個の制約を超えています。 >9 | いいえ |

 x = 4 の場合、[2, 3, 4] を構築でき、これは sum 9 と正確に一致します。 二分探索は 4 に落ち着きます。 

これは、実現可能性は、初期の値を小さく保ちながら、シーケンスが 2 倍化の下で「上向きに伸びる」ことができるかどうかに依存することを示しています。 

### 例 2

 入力: n = 2、s = 6

 | × | シーケンス | 合計 | 実現可能 |
 | --- | --- | --- | --- |
 | 3 | [3、3] | 6 | はい |
 | 4 | [2、4] | 6 | はい |
 | 5 | 不可能 | >6 | いいえ |

 ここでは 3 と 4 の両方が可能ですが、4 の方が大きいため、それが答えになります。 これは、応答空間の単調性を示しています。

import sys, io

def run(inp: str) -> str:

    output = io.StringIO()

        total = 0
        cur = x
        for _ in range(n):
            total += cur
            if total > s:
                return False
            cur = cur // 2
            if cur == 0:
                cur = 1
        return total <= s

    def solve():
        t = int(input())

            lo, hi = 1, s

            while lo <= hi:
                mid = (lo + hi) // 2
                if feasible(n, s, mid):
                    ans = mid
                    lo = mid + 1
                else:
                    hi = mid - 1
            print(ans)

    solve()
    return output.getvalue()

 ## 特殊なケース

 n = 1 の場合、1 つのエッジ ケースが発生します。シーケンスには 1 つの要素があり、合計制約を除くすべての制約が消えるため、答えは s でなければなりません。 x の実現可能性は単に x ≤ s かどうかであり、二分探索では当然 s が返されるため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、s が n に対して非常に小さい場合です。 たとえば、n = 5、s = 5 では、すべての値が 1 に強制されます。逆方向シミュレーションでは、cur がすぐに 1 に減らされ、合計が最小限に保たれるため、すべての候補 x > 1 は実行不可能になり、二分探索は 1 に崩壊します。 

最後の構造的なエッジ ケースは、s が大きく、n が小さい場合です。 n = 2 の場合、最適な分割は 2 倍化制約の下で a1 と a2 の間でバランスをとる傾向があります。 実現可能性チェックでは、暗黙の合計が s を超えるまで大きな x が許可され、その領域では最適な a_n がおよそ s/2 であることが正確に捕捉されます。
