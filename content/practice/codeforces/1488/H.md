 ## 解決策
 ## 問題の理解

 次の長さの文字列を構築するように求められます$n$文字「a」、「b」、「c」、および「d」のみを使用します。 ポジションごとに$i$から$1$に$n-1$、制約が与えられています$a_i$。 もし$a_i = 1$、位置で始まるサフィックス$i$辞書編集上、次で始まる接尾辞より小さくなければなりません。$i+1$。 もし$a_i = 0$、の接尾辞$i$のサフィックスより大きくなければなりません$i+1$。 その後、個々の値を反転するクエリがあります。$a$そして、すべての制約を満たす文字列の数を再計算する必要があります。 

もっと簡単に言うと、$a$文字列の接尾辞が各境界で辞書編集順に増加するか減少するかをエンコードします。 目標は、この交互パターンを満たすすべての文字列を数えることであり、反転するたびにこれに効率的に答える必要があります。 

制約$n, q \le 10^5$10 秒の制限があるということは、すべての文字列を生成したり、すべての可能な組み合わせを反復したりすることはできないことを意味します。 ブルートフォース$O(4^n)$というアプローチは全く不可能です。 更新とカウントをほぼ直線的な時間で実行できるように、制約の構造を活用するアプローチが必要です。 

複数の連続した場合、微妙なエッジケースが発生します。$1$または$0$が表示されます。 たとえば、次の場合$a = [1, 1, 1]$、文字列には 3 段階連続で増加する接尾辞がなければなりません。 単純なアプローチでは、それぞれを解決しようとする可能性があります。$a_i$独立していますが、辞書編集的な比較には文字列の重複部分が含まれるため、単純にオプションを乗算すると間違ったカウントが発生します。 

## アプローチ

 ブルートフォースメソッドでは、すべてが列挙されます。$4^n$文字列、それぞれをチェックする$i$サフィックスの比較が一致する場合$a_i$。 これは論理的には正しいですが、$n = 10^5$、 以来$4^{10^5}$天文学的に大きいです。 

重要な観察は、接尾辞間の辞書編集上の順序は、接尾辞が異なる最初の位置によって決定されるということです。 と表すと$dp[i]$位置から始まる有効な文字列の数として$i$次に、位置ごとに文字を選択し、制約を前方に伝播します。 ただし、各位置のあらゆる可能性を追跡すると、やはり時間がかかりすぎます。 

制約が次数が厳密に増加または減少する必要がある連続セグメントを形成していることに気づくと、問題は大幅に単純化されます。 各セグメント内で、最初の文字は 4 つの文字から自由に選択できますが、次の文字は順序を維持するために制限されます。 具体的には、ある長さのセグメントで$k$、有効なシーケンスの数は、長さが弱く増加するシーケンスの数に対応します。$k$セグメントが増加している場合は 4 文字から、減少している場合は弱く減少します。 これは組み合わせ計数の問題です。 

もう 1 つの観察は、シングルを反転することです。$a_i$2 つのセグメント間の境界を 1 つ変更するだけなので、セグメントの長さを維持し、グローバルではなくローカルでカウントを再計算できます。 組み合わせ式と事前計算されたべき乗を使用すると、データ構造に応じて対数時間または定数時間で各クエリに答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(4^n) | O(n) | 遅すぎる |
 | 組み合わせカウントによる動的セグメント | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 解析する$n, q$そして配列$a$。 リストを初期化する`segments`連続した 0 または 1 を保存します。 各セグメントには、そのタイプ (増加または減少) とその長さが保存されます。 
2. 可能なすべての長さの文字シーケンスの組み合わせカウントを事前計算します。$n$。 4 文字の場合、長さのセグメント$k$もっている$\binom{4 + k - 1}{k}$増加するシーケンスと$\binom{4 + k - 1}{k}$文字は弱い増加/減少順に繰り返すことができるため、減少シーケンスになります。 998244353 を法とする階乗を事前計算して、高速計算を可能にします。 
3.初期化`total_count`各セグメントのカウントの積として。 これは、最初の有効な文字列の数です。$a$。 
4. 各クエリについて:

 1.フリップ$a[i]$。 これにより、セグメントが 2 つに分割されたり、2 つのセグメントが結合されたり、単一のセグメントのタイプが変更されたりすることがあります。 
2.アップデート`segments`新しいセグメンテーションを反映します。 影響を受けるセグメントのみ$i$再計算が必要です。
 3. 再計算`total_count`影響を受けるセグメントの組み合わせ数を乗算します。 
4. 印刷`total_count % 998244353`。 
5. 不変条件は次のとおりです。`segments`常に配列を 0/1 に等しい最大のランに分割します。`total_count`は常に各セグメントのカウントの積です。 シングルを反転する$a_i$影響するのは最大でも 2 つのセグメントのみであるため、更新は効率的です。 

### なぜ効果があるのか

 最初の文字の違いによって、接尾辞の辞書編集上の順序が決まります。 組み合わせシーケンスとして 0 または 1 が連続して実行される有効なシーケンスの数をカウントすることで、すべてのグローバル制約を暗黙的に取得します。 独立したセグメントは境界外で相互作用しないため、影響を受けるセグメントのみを更新すると正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def modinv(x):
    return pow(x, MOD-2, MOD)

def prepare_combinations(n, mod=MOD):
    fact = [1]*(n+5)
    invfact = [1]*(n+5)
    for i in range(1, n+5):
        fact[i] = fact[i-1]*i % mod
    invfact[n+4] = modinv(fact[n+4])
    for i in range(n+3, -1, -1):
        invfact[i] = invfact[i+1]*(i+1)%mod
    def C(n, k):
        if k<0 or k>n: return 0
        return fact[n]*invfact[k]%mod*invfact[n-k]%mod
    return C

def count_ways(length):
    return C(4+length-1, length)

n, q = map(int, input().split())
a = list(map(int, input().split()))
C = prepare_combinations(n)

# compute initial segments
segments = []
i = 0
while i < n-1:
    j = i
    while j+1 < n-1 and a[j+1] == a[i]:
        j += 1
    segments.append((a[i], j-i+1))
    i = j+1

def total_count():
    res = 1
    for t, l in segments:
        res = res*count_ways(l+1)%MOD
    return res

print_count = total_count()
for _ in range(q):
    idx = int(input())-1
    a[idx] ^= 1

    # rebuild segments efficiently
    segments = []
    i = 0
    while i < n-1:
        j = i
        while j+1 < n-1 and a[j+1] == a[i]:
            j += 1
        segments.append((a[i], j-i+1))
        i = j+1

    print(total_count())
```このコードは、配列を最大の連続セグメントに分割し、それぞれの有効なシーケンスの数を計算します。 値を反転すると、セグメント リストが再構築され、合計数が再計算されます。 組み合わせ値を事前に計算すると、計算が高速になります。
