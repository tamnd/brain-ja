 ## 解決策
 ## 問題の理解

 このタスクでは、双方向の橋で接続された島のグラフについて説明します。災害は島 1 から 1 日あたり 1 層ずつ外側に広がります。 魔術師は島 1 から開始し、橋に沿って移動するかテレポートして大陸から脱出しようとしますが、テレポートは消耗品のリソース、つまり橋にある魔法の石によって制限されます。 各橋には正確に 1 つの石があり、石は一度拾えば、朽ちるまでの限られた時間枠内でのみ使用できます。 

主な目標は、生存をシミュレートすることではなく、石が無効になる前に、また拡大する悪魔の前線によって殺される前に、十分な使用可能な石を蓄積することで、何人の魔術師が「外の世界」にうまく到達できるかを決定することです。 

各魔術師は、すでに橋を渡ったり、同時に捕らえられたノードに入ったりすると死の危険を冒しながら毎日橋に沿って移動することも、集めた石を使ってテレポートすることもでき、各テレポートは有効な石をちょうど 2 つ消費します。 石の有効期限は 2 日であるため、石の有用性は、腐敗やデーモンの拡大によって収集が不可能になる前に、魔術師がどれだけ早く石を収集して集約できるかによって決まります。 

出力は単一の整数、つまり保存できるメイジの最大数です。 

制約は大きく、最大 100,000 個のノード、エッジ、およびメイジがあります。 これにより、各メイジを個別にシミュレートしたり、メイジごとに複数のソースの最短パスを実行しようとするアプローチは即座に除外されます。 解決策は、おそらく単一の BFS または DFS と貪欲な集約またはフロー定式化を使用して、問題をグラフ全体の構造計算 (ほぼ確実に線形またはほぼ線形) に削減する必要があります。 

悪魔の拡大、石の崩壊、魔術師の動きという 3 つの時間に敏感なプロセスの相互作用から、微妙な困難が生じます。 単純なアプローチでは、これらを個別に扱い、失敗する可能性があります。 たとえば、到達可能なすべての石が使用可能であると仮定すると、減衰タイミングが無視されます。 最短経路のみが生存を決定すると仮定すると、複数の魔術師が同じ石をめぐって競争することが無視されます。 

小規模な失敗例として、石が発生源から遠く離れた場所に存在する折れ線グラフを示します。 

入力:```
4 3 2
1 2
2 3
3 4
```タイミングを無視すると、両方のメイジがチェーンに沿って十分な石を集めることができると仮定するかもしれません。 ただし、デーモン スプレッドは距離の長い順にノードに到達するため、メイジが安全に移動できる距離が制限され、収集できる石が減少します。 

もう 1 つの失敗モードは、各石が独立して使用できると想定していることです。 テレポーテーションは石のペアを消費するため、本当の問題は、制約の下で収集された使用可能なリソースをペアにすることです。 

## アプローチ

 単純な考えは、プロセス全体を毎日シミュレーションすることです。 私たちは、毎日どの島が占領され、各魔術師がどこにいるか、どの石が収集されたか、どの石が腐ったかを追跡します。 各魔術師はあらゆる可能な道を試し、貪欲に石を集め、脱出の成功を数えました。 

このアプローチは原理的には正しいですが、複雑さの点ですぐに失敗します。 毎日、すべてのエッジ、すべてのメイジ、すべての石の処理が含まれる場合があります。 最大 100,000 のノードとエッジがあり、完全にキャプチャされるまでの日数が直線的になる可能性があるため、運用全体が指数関数的に増加します。 

重要な観察は、デーモン スプレッドがノード 1 からの BFS 階層化を定義していることです。各島は、ノード 1 からの最短距離に等しい既知の最も早い日に安全でなくなります。これにより、動的な危険が横断深度に関する静的な制約に変換されます。 

距離が固定されると、いずれかのエンドポイントが安全でなくなる前に橋を通過できる場合にのみ、各橋が使用可能になります。 これにより、問題は、「安全時に実行可能な」エッジのみが重要となるフィルター処理されたグラフに変わります。 

ここで問題は、これらの制約の下で使用可能な石がいくつ存在するかを数え、次に実行できるテレポートの回数を決定することになります。 各テレポートは 2 つの石を消費するため、答えは基本的に、使用可能な石の互いに素なペアの数になりますが、各魔術師がテレポートを 1 回しか実行できないことも考慮する必要があります。 

最終的な構造的洞察は、メイジの数が計算を直接制限するものではないということです。 代わりに、成功した脱出の数は、利用可能な魔術師の最小数と、有効な石から形成される可能なテレポートの数によって制限されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 1 日あたりの魔術師ごとの完全なシミュレーション | O(k・n・m) | O(n + m) | 遅すぎる |
 | BFS 距離 + フィルタリング + グリーディ ペアリング | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは問題を、安全に収集してテレポートに変換できる使用可能な石の数を計算することに落とし込みます。 

1. BFS を使用して、アイランド 1 から他のすべてのアイランドまでの最短距離を計算します。 これにより、各島が悪魔に占領される日が決まります。 

その理由は、デーモンの拡大は 1 日に 1 つのエッジを移動する波面のように動作するからです。 
2. すべての橋 (u、v) について、安全に通過できるかどうかを判断します。 どちらかのエンドポイントが安全でなくなる前にメイジが厳密に橋を通過できる場合、橋は使用可能です。 これは、到着時または到着前に、そこを移動しても魔術師が捕獲されたノードに着陸しないかどうかをチェックすることになります。 
3. 使用可能な橋ごとに、収集可能な石の機会を 1 つ提供するものとして扱います。 石は、崩壊の制約によって無効になる前に、そこに到達した魔術師によって拾うことができます。 
4. 使用可能な石の総数を数え、それを S とします。 
5. 各テレポートにはちょうど 2 つの石が必要なので、可能なテレポートの最大数は S // 2 です。 
6. メイジは k 人だけなので、最終的な答えは min(k, S // 2) です。 

### なぜ効果があるのか

 BFS レイヤ化により、すべてのアイランドのキャプチャ時間が固定されることが保証されます。 これにより、動的なデーモンプロセスが静的な期限に変わります。 すべての有効な動作はこれらの期限を遵守する必要があるため、実現可能性はエッジごとのローカル条件になります。 エッジが分類されると、石は独立したリソースになります。 テレポーテーションは正確に 2 つの区別できないユニットを消費し、その数を超えて石をリンクする追加の構造的制約がないため、ペアリングのステップは有効です。 唯一のグローバル制約はメイジの数であり、これが最終的な答えの上限となります。

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, k = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    edges = []
    for _ in range(m):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)
        edges.append((u, v))

    # BFS from node 1: capture times
    dist = [-1] * (n + 1)
    q = deque([1])
    dist[1] = 0

    while q:
        u = q.popleft()
        for v in g[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)

    # count usable bridges
    usable = 0
    for u, v in edges:
        # edge usable if both endpoints are reachable before capture frontier blocks it
        # i.e., we can traverse before either endpoint is "effectively dead"
        if dist[u] == -1 or dist[v] == -1:
            continue
        # ensure traversal can happen before capture overtakes endpoint
        if abs(dist[u] - dist[v]) <= 1:
            usable += 1

    # each stone gives one teleport resource
    # teleport uses 2 stones
    ans = min(k, usable // 2)
    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、ノード 1 からの BFS から始まり、各アイランドが感染した最も早い日を計算します。 この距離は、その島を含むあらゆる横断の期限制約として機能します。 

次に、各ブリッジを調べます。 条件`abs(dist[u] - dist[v]) <= 1`エッジが BFS フロンティアに沿って存在するか隣接して存在するかをキャプチャします。つまり、デーモン ウェーブによって同時移動が不可能になる前にエッジを横断できることを意味します。 このような各エッジは、使用可能な石を 1 つ提供します。 

最後に、テレポーテーションは石を 2 つ消費するので、次のように計算します。`usable // 2`。 各メイジは 1 回しか脱出できないため、メイジの数 k が結果の上限となります。 

微妙な点は、特定の魔術師に石を割り当てることは決してないということです。 最終的なペアリング モデルでは石が交換可能であり、空間割り当てが最大数に影響を与えないため、これは安全です。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべてのノードがノード 1 に直接接続されている場合です。この場合、BFS 距離はすべての隣接ノードに対して 1 であり、ノード 1 からのすべてのエッジが使用可能です。 それぞれが距離差の条件を満たし、過剰にカウントすることなくストーンに寄与するため、アルゴリズムはそのようなエッジをすべて正確にカウントします。 

もう 1 つのエッジ ケースは、連続したエッジのみが使用できる長いチェーンです。 ここで、BFS 距離はノードごとに 1 だけ増加し、すべてのエッジが適格になります。 このアルゴリズムは、単純なパスを形成している場合でもすべてのエッジを正確にカウントし、それらを正しく組み合わせてテレポートを作成します。 

最後のエッジケースは、k が利用可能な石と比較して非常に小さい場合に発生します。 グラフが多くの使用可能なエッジを生成する場合でも、結果は k によって制限される必要があります。 決勝戦`min(k, S // 2)`これを直接強制し、過剰なリソースによって答えが膨らまないようにします。
