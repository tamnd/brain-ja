 ## 解決策
 ## 問題の理解

 アンは、数日間にわたってドージコインのマイニングと販売を行うことで利益を最大化したいと考えています。 彼女は採掘で 1 日あたりちょうど 1 コインを稼ぎ、コインの価格は指定されたリストに従って毎日変わります。 開始日によって定義される複数のプランのそれぞれについて`l`そして終わりの日`r`、彼女は間隔で毎日採掘しなければなりません`[l, r]`そしてその日までにすべてのコインを売ります`r`。 各プランの出力は、指定された間隔で採掘されたコインの販売から得られる最大合計利益です。 

入力により提供されるのは、`n`、日数、その後に毎日のコイン価格の配列が続きます。 それから、`q`計画、それぞれがマイニング間隔を指定する`[l, r]`。 制約は、両方のことを示します。`n`そして`q`は最大 200,000 まで可能です。これは、各クエリの間隔で反復する単純なソリューションでは、最大 200,000 が必要になることを意味します。`O(n * q)`操作。 最悪の場合はおおよそ`4*10^10`これは 2 秒の制限時間には遅すぎるため、各クエリに効率的に答えるためにデータを事前計算するアプローチが必要です。 

素朴なアプローチでは、アンが採掘された各コインを販売するのに最適な日を選択できるという事実が無視される可能性があり、単に採掘された日の価格でコインを販売した場合、次善の利益が得られることになります。 エッジケースは、価格が変動するときに発生します。たとえば、価格が次のような場合です。`[1, 100, 1]`彼女は 3 日間マイニングを行い、単純な毎日販売アプローチでは合計で`1 + 100 + 1 = 102`、すべてのコインを最高価格で販売するのに対し、`100`収量`1 + 1 + 1`コイン回数`100 = 300`。 もう 1 つの特殊なケースは、間隔に 1 日しか含まれていない場合です。 この場合、最大の利益は単にその日のコインの価格です。 

## アプローチ

 ブルートフォース ソリューションでは、各計画を個別に検討し、間隔内の毎日のコインの販売をシミュレートします。 これまでに採掘されたコインの数を追跡し、常にその日の価格で販売します。 これは正しいですが、クエリ間隔ごとに毎日繰り返されるため、`O(n*q)`複雑さは最大の制約では受け入れられません。 のために`n = 200,000`そして`q = 200,000`、これには約 400 億回の操作が必要になります。 

重要な観察は、アンはいつでも任意の量のコインを販売できるため、マイニング間隔内で最高価格の日に常にコインを販売したいということです。 一定期間の利益の合計`[l, r]`単純に上位の合計です`k`彼女が毎日販売できる価格は、`k`コインは日によって入手可能です`r`。 彼女は 1 日にちょうど 1 コインを採掘するので、`r - l + 1`最適な戦略は、その日にすべてのコインを最高価格で売却することです。`[l, r]`。 これにより、問題は、間隔内の最大プレフィックス合計の合計を計算することに軽減されます。 

これを効率的に実装する簡単な方法は、価格のプレフィックス合計配列とセグメント ツリーまたはスパース テーブルを使用して、任意の間隔の最大値を計算することです。`O(1)`(疎テーブルの場合) または`O(log n)`(セグメント ツリーの場合) クエリごとの時間。 ここでは、配列が静的であるため、スパース テーブルが特に効率的です。 更新は行われず、クエリのみが行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*q) | お(1) | 遅すぎる |
 | 範囲最大のスパース テーブル/セグメント ツリー | O(n log n + q) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 日数を読み取る`n`そして価格配列`c`。 これにより、間隔クエリを実行する配列が設定されます。 
2. 以下からスパーステーブルを構築します。`c`任意の間隔で最大価格を返すことができます`[l, r]`で`O(1)`時間。 標準のスパース テーブル構造を使用して、ログとテーブル行を事前計算します。 
3. クエリ数を読み取る`q`そしてマイニング計画のリスト。 クエリごとに`[l, r]`、配列アクセスを容易にするために、インデックスをゼロベースに変換します。 
4. 各プランについて、以下から価格の合計を計算します。`l`に`r`。 次に、スパース テーブルを使用して、その間隔内の最大価格を見つけます。 最大の利益は採掘されたコインの数を乗算することで得られます`(r - l + 1)`その間隔内の最高価格によって決定されます。 
5. 各クエリの最大利益を出力します。 

機能する理由: 間隔内で最高価格の日に常にコインを販売することで、アンは収益を最大化します。 スパーステーブルは、その後のクエリごとに一定時間内にこの最大値を見つけることができることを保証します。`O(n log n)`前処理中。 すべてのコインは同一であり、最終日までにすべてのコインを売らなければならないため、この戦略は最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_sparse_table(arr):
    import math
    n = len(arr)
    K = n.bit_length()
    st = [[0] * n for _ in range(K)]
    st[0] = arr[:]
    for k in range(1, K):
        for i in range(n - (1 << k) + 1):
            st[k][i] = max(st[k-1][i], st[k-1][i + (1 << (k-1))])
    return st

def query_max(st, l, r):
    import math
    k = (r - l + 1).bit_length() - 1
    return max(st[k][l], st[k][r - (1 << k) + 1])

def main():
    n = int(input())
    c = list(map(int, input().split()))
    st = build_sparse_table(c)
    q = int(input())
    res = []
    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        num_coins = r - l + 1
        max_price = query_max(st, l, r)
        res.append(num_coins * max_price)
    print(" ".join(map(str, res)))

if __name__ == "__main__":
    main()
```スパーステーブル構造の構築`K`レイヤー。各レイヤーには長さの間隔にわたる最大値が格納されます。`2^k`。 クエリ中に、2 の最大累乗値が適合します。`[l, r]`どの 2 つの重複する間隔を考慮するかを決定します。 1 ベースのインデックスを 0 ベースに変換すると、正確さが保証されます。 コインの数と最大価格を乗算すると、最大の利益が直接得られます。
