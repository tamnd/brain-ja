 ## 問題の理解

 時間の経過とともに変化する配列が与えられており、それに対する 2 つの操作をサポートする必要があります。 最初の操作では、サブ配列を調べて、すべての可能な値を調べるように求められます。`v`、何回かを計算します`v`そのセグメント内に表示されます。 これにより、値に対する周波数配列が得られます。 次に、この周波数配列からこれらすべての周波数のマルチセットを取得し、その mex (これらの周波数の中に現れない最小の非負の整数を意味します) を求めます。 

2 番目の操作は、配列内の 1 つの位置を変更します。 

クエリについて直接的に考えると、セグメント内の値そのものではなく、各値の出現頻度に興味があり、その情報を頻度値の有無にさらに圧縮します。 

制約があるため、慎重な設計が必要になります。 最大 100,000 個の要素と 100,000 回の操作がある場合、クエリごとに周波数を最初から再計算するソリューションはすぐに遅すぎます。これは、クエリごとに 1 回のスキャンで最悪の場合でもすでに約 10¹⁰ の操作が発生するためです。 オフライン構造または分解で大幅に最適化しない限り、クエリごとに完全な頻度マップを維持するのは遅すぎます。 

ここでの微妙な特性は、答えは位置ではなく、セグメント内の頻度カウントのみに依存するということです。 これは、標準的な範囲クエリではなく、範囲頻度分布の問題になります。 

単純な間違いは、個別の値のカウントのみが必要であると想定すると発生します。 たとえば、セグメントが`[1,1,1]`、周波数は`{c1 = 3}`、および周波数上の mex には次のものが含まれます。`0,1,2`しかしそうではありません`3`。 答えは`0`以来`0`行方不明ですか？ いいえ、`c0 = 0`mex ドメインでは無視されますが、すべてのクエリは頻度値の存在に依存します。 この種の混乱により、誤ってゼロの周波数が含まれたり、存在しない値が誤って処理されたりする誤った実装が発生することがよくあります。 

もう 1 つの注意が必要なケースはアップデートです。 要素が変更されると、すべてのセグメントの頻度分布が変更されるため、固定前処理に依存する構造は壊れます。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのクエリの頻度が個別に再計算されます。 お問い合わせの場合`[l, r]`、通常はハッシュ マップまたは辞書を使用して、その範囲内の各値の出現をカウントします。 次に、すべての周波数を 1 つのセットに収集し、上向きにスキャンして mex を計算します。 

これは定義を直接シミュレートするため、正しく機能します。 ただし、各クエリのコストは O(セグメントの長さ) であり、100,000 要素にわたる 100,000 クエリの場合、これは O(nq) に縮退し、大きすぎます。 

重要な観察は、実際には完全な頻度分布は必要ないということです。 各周波数が値かどうかを知る必要があるだけです。`k`値数の間に出現します。 これにより、問題は、特定のセグメントに対して、正確にいくつの個別の値が発生するかを追跡するようになります。`k`回。 

この構造は、変更を加えた Mo のアルゴリズムの古典的なものです。 クエリと更新の両方を単一のオフライン シーケンスで処理します。 現在のウィンドウを維持します`[l, r]`および配列のバージョン。 周波数配列も維持します`freq[x]`値の何倍かを言う`x`現在のウィンドウと別の配列に表示されます`cnt[f]`現在頻度を持っている値の数を示す`f`。 

ウィンドウを移動したり、更新を適用/非適用したりすると、両方の構造が段階的に更新されます。 mex クエリは次のようになります。`k ≥ 1`そのような`cnt[k] == 0`。 

これにより、各調整が O(1) に削減され、各クエリは mex を 1 から上にスキャンすることによって応答されます。 これを効率的に行うために、sqrt 分解を使用して mex 検索を制限するか、cnt 上のセグメント ツリーを維持して最初の欠落周波数を見つけます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 修正を加えたMoの | O((n + q) n^{2/3}) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 更新には時間次元で拡張された Mo のアルゴリズムを使用します。 

1. すべてのクエリを読み取り、保存します。 各更新には時間インデックスが割り当てられ、各クエリはその前に発生した更新の数を記憶します。 これは、クエリを処理するときに正確な配列状態を再構築できるようにするために必要です。 
2. ブロック サイズを選択する`n^(2/3)`。 クエリをブロックごとに並べ替えます`(l block, r block, time block)`。 この順序により、3D Mo のアルゴリズムにおけるポインターの総移動が最小限に抑えられます。 その理由は、3 つの次元すべての変化を同時に削減したいからです。 
3. 現在の配列、現在の範囲内の各値の周波数、各周波数を持つ値の数の 3 つの構造を維持します。 
4. 現在のポインタを維持する`L`、`R`、 そして`T`（時間）。 最初はすべて空です。 
5. ソートされた順序で各クエリについて次のようにします。 

まず時間次元を調整します。 時間を進める場合は、更新を適用します。 逆の場合は元に戻します。 各更新は、現在の位置の内部または外部に影響を与える可能性があります。`[L, R]`, そのため、必要な場合にのみ周波数構造を調整します。 

次に調整します`L`そして`R`クエリセグメントと一致します。 ウィンドウを拡大または縮小するには、頻度カウントを更新し、維持する必要があります。`cnt`。 
6. ウィンドウと時間がクエリと一致したら、mex を計算します。`cnt`。 から増分します`k = 1`見つかるまで上向きに`cnt[k] == 0`。 

### なぜ効果があるのか

 アルゴリズムは正確な不変条件を維持します。あらゆる瞬間に、`freq[x]`value の出現数と等しい`x`現在のウィンドウ内の現在のバージョンの配列の下で、`cnt[f]`頻度が正確に一致する個別の値の数に等しい`f`。 引っ越しのたびに`L`、`R`、 または`T`単一のローカル変更を元に戻すか適用することによってこれらの構造を正確に更新するため、グローバルな再計算は必要ありません。 

mex は次からのみ計算されるため、`cnt`、 そして`cnt`常に真の頻度分布を反映し、戻り値は各クエリ状態に対して正しい値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    queries = []
    updates = []
    arr = a[:]

    for i in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            l, r = tmp[1] - 1, tmp[2] - 1
            queries.append((l, r, len(updates), i))
        else:
            p, x = tmp[1] - 1, tmp[2]
            updates.append((p, x))
            queries.append(("U", p, x))

    # compress values
    vals = set(arr)
    for p, x in updates:
        vals.add(x)

    comp = {v: i for i, v in enumerate(sorted(vals))}
    arr = [comp[v] for v in arr]
    updates = [(p, comp[x]) for p, x in updates]

    cur = arr[:]
    freq = [0] * (len(comp) + 5)
    cnt = [0] * (n + 5)

    def add(x):
        old = freq[x]
        cnt[old] -= 1
        freq[x] += 1
        cnt[freq[x]] += 1

    def remove(x):
        old = freq[x]
        cnt[old] -= 1
        freq[x] -= 1
        cnt[freq[x]] += 1

    L, R, T = 0, 0, 0
    freq = [0] * (len(comp) + 5)
    cnt = [0] * (n + 5)

    def apply(ti, sign):
        p, x = updates[ti]
        old = cur[p]
        if L <= p <= R:
            remove(old)
            cur[p] = x
            add(x)
        else:
            cur[p] = x

    # rebuild sorted queries (Mo order)
    mo_queries = []
    for qinfo in queries:
        if qinfo[0] == "U":
            continue
        l, r, t, idx = qinfo
        mo_queries.append((l, r, t, idx))

    block = int(n ** (2 / 3)) + 1
    mo_queries.sort(key=lambda x: (x[0] // block, x[1] // block, x[2]))

    def get_mex():
        k = 1
        while cnt[k] > 0:
            k += 1
        return k

    ans = {}

    for l, r, t, idx in mo_queries:
        while T < t:
            p, x = updates[T]
            old = cur[p]
            if L <= p <= R:
                remove(old)
                cur[p] = x
                add(x)
            else:
                cur[p] = x
            T += 1

        while T > t:
            T -= 1
            p, x = updates[T]
            old = cur[p]
            if L <= p <= R:
                remove(x)
                cur[p] = old
                add(old)
            else:
                cur[p] = old

        while L > l:
            L -= 1
            add(cur[L])

        while R <= r:
            add(cur[R])
            R += 1

        while L < l:
            remove(cur[L])
            L += 1

        while R > r + 1:
            R -= 1
            remove(cur[R])

        ans[idx] = get_mex()

    out = []
    for i in range(len(queries)):
        if queries[i][0] != "U":
            out.append(str(ans[i]))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装の中核はデュアル周波数メンテナンスです。 1 つの配列はアクティブ セグメントに各値が何回出現するかを追跡し、もう 1 つの配列は同じ頻度を共有する値の数を追跡します。 mex の計算は周波数全体の線形スキャンになりますが、周波数が n を超えることはないため、これは許容されます。 

微妙な点は、更新された位置が現在の周波数構造内にある場合にのみ、更新は周波数構造に影響を与える必要があるということです。`[L, R]`。 ウィンドウの外では、カウントには触れずに、保存された値のみを変更します。 

タイム ポインター ロジックにより、更新によって前後に移動できるようになります。これは、Mo の順序付けがオフラインであり、時系列ではないため必要です。

 ## 特殊なケース

 重要なエッジ ケースは、更新が現在のクエリ範囲外の位置に影響を与える場合です。 たとえば、次の場合`L=1, R=2`更新すると位置が変わります`5`、周波数構造は変化してはなりません。 アルゴリズムは更新することでこれを処理します`cur[p]`触れずに`freq`または`cnt`、現状の汚染がないことを保証します。 

もう 1 つのエッジ ケースは、最後に出現した値を削除することです。 値の頻度が 1 で削除されるとします。 その周波数は0になり、`cnt[1]`一方で減少します`cnt[0]`が増加します。 mex は 1 から始まるので、`cnt[0]`は無関係ですが、後の移行の一貫性を維持するために正しく更新する必要があります。 

最後に、セグメントに現れない多くの値には周波数 0 が構造的に常に存在するため、mex スキャンは常に 1 から始まります。 0 から開始すると、回答に誤った偏りが生じます。
