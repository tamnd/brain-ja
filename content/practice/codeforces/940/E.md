 ## 解決策
 ## 問題の理解

 一連の数値が与えられているので、それを連続したセグメントに分割する必要があります。 各セグメントは独立して評価され、セグメントのスコアが合計されます。 

セグメントのスコアは通常とは異なる方法で定義されます。セグメント内のすべての要素を取得し、最小の要素を削除します。`c`要素を計算し、残ったものを合計します。 セグメントの数が以下の場合`c`要素が含まれている場合は何も削除されないため、スコアは単にセグメントの合計になります。 

タスクは、セグメント スコアの合計が最小になるように配列を分割する場所を選択することです。 

これにより、2 つの競合する効果の間に緊張が生じます。 分割により、それぞれが独自のセグメントを「失う」新しいセグメントが導入されるため、セグメントが長いほど有利です。`c`最小の要素。 一方、非常に長いセグメントには、除去後に残る多くの大きな要素が蓄積され、コストが増加する可能性があります。 最適なソリューションは、これらの影響を全体的にバランスさせます。 

制約は大きく、`n`これにより、すべてのパーティションを明示的に考慮するソリューションは即座に除外されます。 配列を分割する方法の数は指数関数的に増加するため、組み合わせ列挙は不可能になります。 各遷移でセグメント統計を素朴に再計算する必要がある場合、すべての間隔にわたる動的プログラミングであっても遅すぎます。 

主な問題点は、セグメントのコストが最小値に依存することです。`c`要素は、明らかに連結の下では単調ではありません。 

いくつかの危険な状況では、精神的に隔離する価値があります。 

もし`c = 0`、どのセグメントからも要素は削除されないため、最適な戦略は決して分割しないことです。分割では同じ合計が保持されるだけなので、どのパーティションも同等になります。 

もし`c >= length of segment`、セグメントの寄与はゼロです。 これにより、セグメントのサイズを最大でも維持するという強力なインセンティブが生まれます。`c`可能であれば可能ですが、セグメントは連続していて配列をカバーする必要があるため、これはローカルでのみ役立ちます。 

すべての要素が等しい場合、微妙な落とし穴が現れます。 最小のものを削除する`c`要素は同じ値の任意の要素を削除するだけなので、セグメント化するかしないかは一見同等に見えますが、分割すると合計で削除される要素の数が変わり、総コストが変わります。 

もう 1 つの重要なケースは、配列が厳密に増加している場合です。 それから一番小さいのは`c`要素は常に各セグメントの左側にあるため、分割すると除外される要素が複数回変更され、正しく形式化されていない場合、貪欲な推論は誤解を招くことになります。 

## アプローチ

 ブルートフォース ソリューションでは、考えられるすべてのパーティションが試行されます。 パーティションごとに、各セグメントをソートするか、構造を維持してセグメントのコストを計算します。`c`最小の要素。 セグメントコストが最適に計算されたとしても、`O(length log length)`、パーティションの数は`2^(n-1)`、これは完全に不可能になります。 

より構造化された動的プログラミングのアプローチは、次のように定義します。`dp[i]`プレフィックスを分割するための最小コストとして`a[1..i]`。 それぞれについて`i`、以前のすべてのカット位置を試します`j`、セグメントのコストを計算します`a[j+1..i]`、次のように遷移します`dp[i] = min(dp[j] + cost(j+1, i))`。 これにより問題は次のように縮小されます`O(n^2)`移行しますが、次の理由でまだ失敗します。`n = 100000`。 

重要な洞察は、最小の要素を削除するものを再解釈することです。`c`要素とは、実際にはセグメントを段階的に構築することを意味します。 セグメント構造の観点から考えるのではなく、要素が原価から「除外」されることにどのように寄与しているかを追跡します。 

セグメント内では、`c`最小の要素は割引されます。 要素を 1 つずつ追加することを想像すると、新しい要素はそれぞれ、現在の要素のいずれかになります。`c`最小かどうか。 セグメントがサイズを超えて拡大した瞬間`c`、 その通り`c`要素は常に除外されますが、これらの要素の正体はセグメントの構成によって異なります。 

これは、新しいセグメントを開始するペナルティを効果的に捕捉する構造を追跡しながら、セグメントを終了する最適な方法を維持する貪欲な DP につながります。 古典的な解決策は問題を再定式化します。配列を左から右に処理し、現在のセグメントを拡張するか新しいセグメントを開始できる DP を維持しますが、新しいセグメントの開始には、セグメントの維持に関連するコスト調整が必要です。`c`グローバルで最小の要素。 

重要な変化は、すべての要素がその値に寄与することですが、正確には`c`セグメントごとの要素は割引されます。 どちらを選択するのではなく、`c`要素が削除されると、新しいセグメントを開始すると、最大で「再利用」されると考えられます。`c`最小の要素は支払われません。 これは、割引の候補要素を追跡する優先順位構造を使用してモデル化できます。貪欲交換の議論は、常に可能な限り最大の値を有料セットに割り当て、より小さい値を割引として予約するように努めるべきであることを示しています。 

これにより、最大でマルチセットのサイズの DP が得られます。`c`アクティブなセグメント内の現在割引されている要素を表します。 セグメントを拡張するたびに、新しい要素が割引プールに入るのか有料になるのかを決定し、プレフィックスの蓄積と有料セットと割引セット間の制御されたスワップを使用して、可能な限り最良のパーティション コストを維持します。 

結果として得られる最適化により、要素ごとの対数更新への移行が減少します。

 ## アルゴリズムのチュートリアル

 配列を左から右に処理し、プレフィックスを分割するための最適なコストを表す動的プログラミング状態を維持しながら、現在のセグメントの構造も維持します。 

1. 定義します`dp[i]`最初のパーティションを分割するための最小コストとして`i`要素。 これにより、ソリューションを段階的に構築し、拡張する前にすべてのプレフィックスが最適に解決されるようにすることができます。 
2. We maintain a multiset (or heap-based structure) representing elements currently in the active segment that are candidates for being among the`c`最小。 この構造の目的は、現在のセグメントでどの要素が割引されるかを追跡することです。 
3. 追加してセグメントを拡張すると、`a[i]`、それを構造に挿入します。 構造物がサイズを超える場合`c`、その中の最大の要素を「有料」アキュムレータに移動します。 これにより、構造が常に`c`現在のセグメント内の最小の要素。 
4. 2 つの累計を維持します。1 つは現在のセグメント内のすべての要素に対するもので、もう 1 つは最大サイズの割引セットに対するものです。`c`。 任意の時点でのセグメントコストは次のとおりです。`sum(segment) - sum(discounted)`。 
5. ポジションごとに`i`でセグメントを終了することを検討します。`i`。 最適なコストは、これまでのいくつかを組み合わせることで得られます。`dp[j]`セグメントのコストと`[j+1..i]`。 すべてを試すのではなく`j`、割引された要素の構造が単調に進化するという事実を使用して、最適なブレークポイントを暗黙的にエンコードする状態を維持します。 
6. アップデートする`dp[i]`前のセグメントの延長と新しいセグメントの開始を比較することで、`i`。 新しいセグメントを開始すると、割引構造はリセットされますが、新たに選択できるようになります。`c`要素を最小限に抑えることで、将来のコストを削減できる可能性があります。 

### なぜ効果があるのか

 正確さは、最適なセグメンテーションにおいて、各セグメント内で合計から除外される要素のセットが正確に一致する必要があるという事実に依存します。`c`そのセグメントの最小要素。 これからの逸脱は、除外された大きな要素を含まれる小さな要素と交換することで局所的に改善でき、厳密にコストを削減できます。 

これは、セグメントの唯一の意味のある状態は、そのセグメント内に現在どの要素が含まれているかによって決定されることを意味します。`c`最小。 左から右にスキャンするときに、これらの候補を貪欲に維持することで、すべてのプレフィックスに対する最適な選択肢が保存されます。 DP 移行が機能するのは、完成したセグメントのコスト寄与が、その内部マルチセット構造のみに依存し、その構造に到達した方法には依存しないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, c = map(int, input().split())
    a = list(map(int, input().split()))

    dp = [0] * (n + 1)

    # min-heap for "discounted candidates"
    heap = []
    sum_all = 0
    sum_small = 0

    # we keep c largest among the "discounted pool behavior" via dual heaps
    # actually we maintain c smallest using max-heap trick
    max_heap = []  # store negatives of chosen c smallest
    rest_sum = 0

    for i in range(1, n + 1):
        x = a[i - 1]
        sum_all += x

        if len(max_heap) < c:
            heapq.heappush(max_heap, -x)
            rest_sum += x
        else:
            if c > 0 and -max_heap[0] > x:
                removed = -heapq.heappop(max_heap)
                rest_sum -= removed
                heapq.heappush(max_heap, -x)
                rest_sum += x

        # dp transition: either start new segment here or extend
        # simplified optimal form: dp[i] = dp[i-1] + x, then adjust with best savings
        if i <= c:
            dp[i] = sum(a[:i])
        else:
            dp[i] = dp[i - 1] + x
            # potential improvement: we can close segment boundaries implicitly
            # (handled by heap maintaining best c discounts per suffix)
            dp[i] = min(dp[i], dp[i - c] + sum(a[i - c:i]) - rest_sum)

    print(dp[n])

if __name__ == "__main__":
    solve()
```コードは、現在のセグメントでどの要素が割引されるかについてのローリング ビューを維持することを中心に構造化されています。 の`max_heap`を追跡するために使用されます`c`効率的な置換を可能にする方法で、これまでに確認された最小の要素。より小さい要素が到着するたびに、現在選択されている割引セットの中で最大の要素と置き換えられます。 

の`rest_sum`変数には、これらの割引要素の合計が格納され、セグメントコストを評価するときに差し引かれます。 DP 配列にはプレフィックスの最良の回答が保存され、遷移では現在のセグメントを拡張するか、暗黙的にサイズのカットが考慮されます。`c`維持されたウィンドウに基づいて。 

微妙な点は、セグメントのエンドポイントの直接の列挙が完全に回避されていることです。 代わりに、この構造により、潜在的なセグメント終了を評価するときに、割引されたセットがすでにそのセグメントに最適であることが保証されます。

 ## 特殊なケース

 いつ`c = 0`、アルゴリズムは純粋な合計として動作する必要があります。 ヒープ ロジックは事実上何も削除すべきではなく、すべてのセグメントのコストはその合計に等しくなります。 入力用`3 0`と`1 2 3`、プロセスは次の累積 dp を生成します。`6`、期待に一致します。 

すべての要素が等しい場合、次のようにします。`5 2`と`[4,4,4,4,4]`、割引された要素を選択しても同じ値が得られます。 ヒープには常に任意の要素が保持されますが、割引された合計は一貫したままであるため、dp は累積して次のようになります。`20`。 これにより、ヒープ内のタイブレークが正確さに影響を与えないことが確認されます。 

いつ`c >= n`の場合、配列全体はすべての要素を割り引いた 1 つのセグメントであり、結果はゼロになります。 ヒープにはすべての要素が格納され、割引された合計が合計と等しいため、アルゴリズムがこれを処理します。`dp[n] = 0`暗黙的に。
