 ## 問題の理解

 整数のシーケンスと、未知の間隔で駆動される非常に特殊な「ステート マシン」によって生成された 2 番目のビットのシーケンスが与えられます。$[l, r]$。 私たちのタスクは、指定されたビット シーケンスを生成した可能性のあるそのような間隔を復元することです。 

このマシンは、スライド式の記憶プロセスのように機能します。 出力ビットを生成します$b_i$最後の 5 つの出力がすべて同一かどうか、および配列の最後の 5 つの値が同じかどうかに基づいて$a$完全に上に座る$r$または完全に下に$l$。 最後の 5 つの出力がすべて 0 で、最近の値が$a$最後の 5 つの出力がすべて 1 で、最近の値が 1 の場合、マシンは 1 を強制します。$a$それ以外の場合は、単純に前の出力を繰り返します。 

この構造により、システムは一度決定的になります。$l$そして$r$修正されていますが、再構築しています$l$そして$r$プロセスは履歴に依存するため、観察された動作から得られる結果は自明ではありません。 問題は、以前の出力の十分に長い均一なセグメントが、値のスライディング ウィンドウのしきい値条件と一致する場合にのみ遷移が発生することです。$a$。 

制約により、最大で次のことが許可されます。$10^5$要素、可能なすべてを試みるアプローチを即座に除外します。$(l, r)$候補区間を個別にペアにしたりシミュレーションしたりできます。 単一の候補をチェックするだけでも線形シミュレーションが必要なため、ブルート フォースは少なくとも$O(n^2)$あるいはさらに悪いことに。 

出力文字列が一定またはほぼ一定の場合、微妙なエッジ ケースが発生します。 このような場合、遷移ルール​​は決してアクティブにならない可能性があります。つまり、観察された動作では、弱い制約しか提供されません。$l$そして$r$。 もう 1 つのエッジ ケースは、交互の遷移が頻繁に発生し、厳しい制限を強いられる場合です。$l$そして$r$、しかし、それらの境界は単一のインデックスにローカライズされていません。 

## アプローチ

 強引なアイデアでは、可能なすべての間隔を試すことになります。$(l, r)$、プロセスをシミュレートし、ターゲット配列と比較します。 両方なので$l$そして$r$値の範囲を超えます$[-10^9, 10^9]$、これは直接的には不可能です。 からの値に離散化しても$a$まだ与えるだろう$O(n^2)$候補と各シミュレーション費用$O(n)$、につながる$O(n^3)$最悪の場合の行動。 

重要な観察は、最後の 5 つの出力が均一である特定のインデックスでのみ出力が変化するということです。 そのときの価値は、$a_i$完全に上である必要があります$r$または完全に下に$l$、マシンが 1 から 0 に切り替わるか、0 から 1 に切り替わるかに応じて異なります。したがって、すべての遷移は、次の 5 つの値の連続ブロックに制約を課します。$a$。 

推測する代わりに$l$そして$r$、ロジックを反転します。 出力が強制される可能性があるすべての位置を制約ジェネレーターとして扱います。 インデックスごとに$i$、マシンが 0 から 1 に変化する場合、前の 5 つがわかります。$a$-値はすべて以下である必要があります$l$。 1 から 0 に変化する場合、前の 5 つはすべて上記を超えている必要があります$r$。 これにより、問題は 2 つのグローバル境界を維持することになります。$r$そして上限$l$、すべての有効な遷移ウィンドウから導出されます。 

すべての制約が収集されたら、任意の制約を選択できます$l$厳密にはすべての「低強制力」セグメントと$r$すべての「高強制力」セグメントを厳密に下回っており、$l \le r$満足しています。 解が存在するという保証により、これらの間隔が互いに矛盾しないことが保証されます。

 ## アルゴリズムのチュートリアル

 1. まず、指定された出力文字列で 0 と 1 の間の遷移がいつ発生するかという観点から、何が起こったはずかをシミュレートします。 すべてのインデックスが$b_i \ne b_{i-1}$マシンの強制遷移イベントに対応します。 
2. 各遷移インデックスについて$i$で前の 5 つの位置を見てみましょう。$a$。 このルールは長さ 5 のスライディング ウィンドウに依存するため、変更を正当化できるのはこれらの立場だけです。 
3. 遷移が 0 から 1 への場合、マシンは以下の 5 つの連続した値を認識したはずです。$l$。 これはつまり$l$は、そのウィンドウ内の最大値より厳密に大きくなければなりません。 次の形式の候補制約を記録します。$l > \max(a_{i-5}, \dots, a_{i-1})$。 
4. 遷移が 1 から 0 への場合、マシンは上記すべての 5 つの連続した値を認識している必要があります。$r$。 これにより、$r < \min(a_{i-5}, \dots, a_{i-1})$。 この制約を記録します。 
5. すべての遷移を処理した後、可能な限り最も狭い境界を計算します。$l$「下位セグメント」で見られる最大値より少なくとも 1 つ大きい値でなければなりません。$r$「高セグメント」に見られる最小値より最大でも 1 つ小さい値でなければなりません。 
6. 最後に、いずれかを選択します$l$そして$r$これらの不等式を満たし、必要に応じてわずかに調整して、$l \le r$、問題ステートメントによって可能であることが保証されています。 

### なぜ効果があるのか

 出力のすべての変更は、以前の 5 つの状態の均一なウィンドウによってのみトリガーされます。 これらのウィンドウは、間隔が変更される唯一の瞬間です。$[l, r]$実際にはプロセスによって「テスト」されます。 他の位置はすべて前の値をコピーするだけであり、追加情報は提供されません。 したがって、真の間隔はこれらのウィンドウから導出されるすべての制約を満たす必要があり、それらを満たす間隔は同じ遷移構造を再現し、シーケンス全体が強制的に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    s = input().strip()

    INF = 10**18

    # l must be greater than all maxima of windows causing 0 -> 1
    # r must be smaller than all minima of windows causing 1 -> 0
    low_bound_for_l = -INF
    high_bound_for_r = INF

    for i in range(4, n):
        if s[i] == s[i-1]:
            continue

        window = a[i-4:i+1]

        if s[i] == '1' and s[i-1] == '0':
            # need all window < l => l > max(window)
            low_bound_for_l = max(low_bound_for_l, max(window) + 1)

        elif s[i] == '0' and s[i-1] == '1':
            # need all window > r => r < min(window)
            high_bound_for_r = min(high_bound_for_r, min(window) - 1)

    l = low_bound_for_l
    r = high_bound_for_r

    # guarantee existence
    if l > r:
        r = l

    print(l, r)

if __name__ == "__main__":
    solve()
```それらの位置のみがマシンのルールをアクティブにするため、コードは出力が変化する位置のみを処理します。 そのような位置ごとに、次の 5 要素ウィンドウを抽出します。$a$そのインデックスで終了し、下限のいずれかを更新します$l$または上限$r$。 

最終的な調整により、制約が厳しいが一貫性があるという縮退ケースでの実現可能性が保証されます。 設定$r = l$この問題は少なくとも 1 つの解決策を保証するため、妥当性が保たれます。

 ## 特殊なケース

 エッジ ケースの 1 つは、出力文字列に遷移がまったく含まれていない場合です。 その状況では、アルゴリズムは制約を生成せず、両方の制約を残します。$l$そして$r$完全に無料です。 実装では、初期境界を変更せずに任意の有効な間隔を許可することで、これを自然に処理します。 

もう 1 つのエッジ ケースは、両方のタイプの遷移が別々の位置で発生する場合です。 ここで、アルゴリズムは独立して下限を累積します。$l$と上限$r$。 制約は独立したウィンドウから発生するため、ローカルで相互作用することはありません。 正確性は、一貫したグローバル間隔が存在するという保証に依存しているため、これらの境界は重複している必要があります。 

最後のエッジ ケースは、配列の先頭付近で遷移が発生した場合に発生します。 ルールは前の 5 つの値に依存するため、インデックス$i < 5$制約には影響しません。 この実装では、ルールが適用できる最初の有効なウィンドウと一致するインデックス 4 から開始することにより、範囲外のアクセスを回避します。
