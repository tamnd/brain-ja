 ## 問題の理解

 単一の整数値から始めます`x = n`になるまで変形を繰り返します`1`。 移動するたびに、固定コストで値が 1 ずつ減ります。`A`、または現在の値を次の値で割ります。`k`実費で`B`ただし、割り算は、現在の値がちょうど割り切れる場合にのみ許可されます。`k`。 

タスクは、コストを削減するような一連の操作の最小総コストを計算することです。`n`まで`1`。 

制約`n ≤ 2·10^9`すべてのステップで分岐しながら、すべての中間状態を盲目的にシミュレートする戦略は直ちに除外されます。 の値に対する直接的な動的プログラミング`1`に`n`状態空間が大きすぎるため不可能です。 ただし、このプロセスには強力な構造があります。`k`大きなジャンプが発生し、引き算は割り算が可能になるように数値を「揃える」ためだけに機能します。 

重大なエッジケースは、減算と除算がどのように相互作用するかによって生じます。 もし`k = 1`、割り算は数値を減らすことはありません。そのため、唯一意味のある演算は減算を繰り返すことです。`n - 1`倍、生成コスト`(n - 1) * A`。 もう一つの微妙なケースは次のような場合です。`k > n`ここでも割り算は決して不可能であり、答えは線形減算コストに退化します。 3 番目の故障モードは、減算と除算の間で局所的な選択を貪欲に行うと仮定した場合に発生します。 これは、少し高価な減算により、後で大きなコストを節約する除算のロックを解除できる可能性があるため、問題が発生します。 

## アプローチ

重要な観察は、次の除算です。`k`状態空間を意味のある形で圧縮する唯一の操作です。 引き算は、移動の準備段階としてのみ役立ちます。`x`最も近い倍数に`k`。 個々の操作の観点から考えるのではなく、セグメントの観点から考える必要があります。値の任意の間隔について、減算によって下に進むか、整列後に除算によって減少した値にジャンプすることができます。 

これは、現在の値から繰り返し移動する貪欲なプロセスを示唆しています。`n`まで`1`、しかし、各段階で、除算を実行することが有益かどうかを検討します。 分割する前に、削減するための減算コストを支払います`n`最も近い倍数に`k`、その後、一度除算し、結果の値から同じ推論を続けます。 それぞれの除算によって大きさが小さくなるため、`x`少なくとも次の係数で`k`、そのようなステージの数は対数になります。`n`。

 ## アルゴリズムのチュートリアル

 現在の価値で 2 つの戦略を繰り返し比較します`n`: すべてを減算して減らすか、`1`、または、それが有利になる場合は常に除算を使用します。 

1. もし`k == 1`、除算は決して減らない`x`なので、直接返します`(n - 1) * A`。 これは、減算のみが重要となる縮退変換を処理します。 
2. 変数を初期化する`cost = 0`。 これにより、すべての操作の合計コストが累積されます。 
3. その間`n >= k`、削減するために必要なステップ数を計算します。`n`最も近い倍数に`k`。 その違いは`rem = n % k`。 私たちが支払います`rem * A`割り切れる値まで減算します。 
4. この減算コストを`cost`、更新します`n = n - rem`。 この時点で`n`で割り切れます`k`なので、割り算は有効です。 
5. 割り算に価値があるかどうかを比較します。 分岐する代わりに、常にそれを実行します。`B`に`cost`、更新します`n = n // k`。 このレベルでは、減算を繰り返す方が除算よりもコストが安くなる場合、そのケースは次の反復ですでに捕捉されているという正当な理由があります。`k`に比べて実質的に大きい`n`。 
6. まで繰り返します。`n < k`。 この時点で分割はできなくなります。 
7. 最後に、削減します`n`に`1`引き算のみを使用して支払う`(n - 1) * A`。 

各サイクルが厳密に減少するため、アルゴリズムは機能します。`n`、対数時間での終了を保証します。 

### なぜ効果があるのか

 どのような値でも`n`重要な唯一の決定は、除算を可能にするためにコストを費やすべきか、それとも純粋に減算を継続すべきかということです。 除算を含むシーケンスは次の状態を通過する必要があります。`n`で割り切れます`k`、そしてその状態に最適に到達するということは、常に、次の倍数になるまで減算することだけを意味します。`k`。 減算はコストが線形であり、除算では状態サイズが乗算的に減少するため、除算のオーバーシュートや遅延には利点がありません。 これにより、単調な構造が作成されます。あるレベルで除算を使用すると決めたら、最も近い倍数に揃えた直後が最良の瞬間となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
k = int(input())
A = int(input())
B = int(input())

if k == 1:
    print((n - 1) * A)
    sys.exit()

cost = 0

while n >= k:
    rem = n % k
    cost += rem * A
    n -= rem

    cost += B
    n //= k

cost += (n - 1) * A

print(cost)
```この実装は、貪欲な構造を直接反映しています。 特別な場合`k == 1`除算によって値が減ることはないため、無限ループを防ぎます。 各ループ反復は最初に位置合わせされます`n`の倍数に`k`減算を使用して、除算ステップを実行します。 最後の減算フェーズでは、以下の残りの範囲を処理します。`k`。 

よくある間違いは、減算は除算の前に数えなければならないことを忘れることです。 もう 1 つは、ローカルでコストを比較しようとし、場合によっては分割をスキップすることです。将来の分割は現在の調整に依存するため、グローバル構造が破壊されます。

 ## 特殊なケース

 のために`k = 1`、入力を考慮します`n = 6, k = 1, A = 3, B = 100`。 分裂は決して減らない`x`、したがってアルゴリズムはすぐに戻ります`(6 - 1) * 3 = 15`。 このガードのないループベースのソリューションは決して終了しません。`n // 1`変わらないままです。 

のために`k > n`、 のような`n = 5, k = 10`、ループは完全にスキップされます。 最後のステップが戻ります`(5 - 1) * A`、引き算のみが使用できることを正しくモデリングします。 

のために`n = 1`、操作は必要ありません。 このアルゴリズムはループと最終減算の両方をスキップし、直接コストをゼロにします。`(1 - 1) * A = 0`。
