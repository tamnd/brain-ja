 ## 解決策
 ## 問題の理解

 私たちは、すべての道路を清掃し、雇ったすべての清掃員が許可された時間内に作業を終え、支払総額ができるだけ少なくなるように、清掃員の雇用方法を決定する必要があります。 掃除機にはそれぞれ速度があります`H`、1つの通りがかかることを意味します`H`何時間も。 清掃業者にも許容される支払い間隔があります`[L, U]`通りごとに。 

公平性ルールでは、雇われたすべての清掃員は時間当たり同じ支払いを受けなければならないと定められています。 その一般的なレートが`r`、クリーナー`i`受け取ります`r * H_i`通りごとに。 値`r`満たさなければなりません`L_i <= r * H_i <= U_i`雇われた清掃員全員に。 

クリーナーが掃除できるのはせいぜい`floor(K / H_i)`道路は、割り当てられたすべての道路が以内に終了する必要があるため、`K`何時間も。 タスクは、クリーナーと割り当てを正確に選択することです`S`道路はカバーされており、最終的な支払いは最小限に抑えられます。 

制約は大きく、最大で`100000`清掃員と街路。 すべてのサブセットを試したり、多数の街路に対して動的プログラミングを実行したりするソリューションは、非常に遅すぎます。 に近いものが必要です`O(N log N)`または`O(N log^2 N)`。 

難しいのは、支払いレートが整数ではないことです。 清掃員の間隔から導出される有理数です。 もう 1 つのよくある間違いは、料金を最小化するだけで、料金をわずかに大きくすると掃除がはるかに速くなり、総支払い額が減るという事実を無視することです。 

たとえば、次のことを考えてみましょう。```
2 100 100
100 1 1
1 100 100
```最初の清掃員は 100 時間あたり 1 つの道路を掃除でき、2 番目の清掃員は 1 時間あたり 100 つの道路を掃除できます。 最初の清掃員からは可能な限り最小の割合が得られますが、十分な通りを清掃することはできません。 正解は 2 番目のクリーナーを使用する必要があります。 

もう 1 つのエッジ ケースは、時間制限によって各クリーナーの容量が小さすぎる場合です。```
2 10 5
1 1 1
10 1 100
```最初の清掃員は 5 つの通りを実行できますが、2 番目の清掃員は何も実行できません。 掃除できるのは 5 つの道路だけなので、答えは不可能です。 支払いの互換性をチェックするだけの不注意なソリューションでは、支払いを誤って受け入れてしまう可能性があります。 

## アプローチ

 直接的なアプローチは、可能な限り一般的な時間料金を試し、どの清掃業者が利用できるかをシミュレートし、最速の清掃業者に貪欲に道路を割り当てることです。 これが機能するのは、料金が固定されると、どの清掃業者も道路ごとに固定コストがかかり、最も安価な選択は常に最小の清掃業者を使用することになるためです。`H`まず価値観。 ただし、可能性のあるレートが多すぎて確認できません。 すべてのクリーナーは可能な境界値を作成し、`100000`候補者全員の割り当てを再計算するとコストがかかりすぎます。 

重要な観察は、最適なレートは下限の 1 つでなければならないということです。`L_i / H_i`。 選択した清掃業者のグループが料金を使用すると仮定します。`r`。 減れば`r`これらのクリーナーの 1 つが最低許容支払い額に達するまで、選択されたすべてのクリーナーは引き続き有効であり、支払い総額は減少するだけです。 最適なレートはまさにそのような境界でなければなりません。 

さて、問題はこれらの候補者の割合をめぐる全体的な問題となる。 小さいレートから大きいレートに移行する際、スイープが下限に達するとクリーナーが使用可能になり、上限を過ぎると使用できなくなります。 現在のレートについては、最小合計額のみを知る必要があります。`H`カバーするために必要な値`S`通り。 

可能性を超えたフェンウィックの木`H`値はアクティブなクリーナーを維持します。 アクティブなクリーナーごとに、その容量をインデックスのカウントとして追加します。`H`、と追加します`capacity * H`2番目のフェンウィックツリーへ。 最初のクエリ`S`通りとは、最小のものを見つけることを意味します`H`十分な合計容量を持つ値。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N² log N) | O(N) | 遅すぎる |
 | 最適 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのクリーナーを可能な時間料金の間隔に変換します。 クリーナー`i`～からのレートを受け入れます`L_i / H_i`に`U_i / H_i`。 また、このクリーナーが処理できる通りの最大数も計算します。`floor(K / H_i)`。 
2. すべての一意の左端点を並べ替えます。 これらは、最適値を生成できる唯一のレートです。 それらを最小のものから最大のものまで徹底的に調べます。 
3. スイープが一定のレートに達したとき`r`、間隔が で始まるすべてのクリーナーを追加します。`r`。 このようなクリーナーは、最小許容レートに達しているため使用可能になります。 
4. 上限が以下のクリーナーを削除します。`r`。 They can no longer be hired at the current rate.
 5. フェンウィックの木で現在使用可能なすべてのクリーナーを維持します。 最初のツリーには、各速度でカバーできる道路の数が格納され、2 番目のツリーには、それらの道路の合計時間の寄与が格納されます。 
6. If the active cleaners cannot cover`S`通りでは、このレートは不可能です。 それ以外の場合は、最小のものを見つけます`H`提供する価値観`S`通り。 結果として得られる合計は、`H`値に現在のレートを乗算すると、このレートの最低支払い額が求められます。 
7. この支払いをこれまでに見つかった最良の回答と比較します。 換算した分数として保存します。 

機能する理由: スイープは常に、最適なソリューションが存在できるレートを正確に考慮します。 固定料金の場合、雇われた清掃業者はすべて同じ乗数を持ちます。`r`したがって、支払いを最小限に抑えることは、総額を最小限に抑えることと同じです。`H`割り当てられた通りの。 高速のクリーナーを低速のクリーナーに置き換えても合計が増えるだけであるため、利用可能な最速のクリーナーを最初に使用するのが最適です。 フェンウィック ツリーはまさにこの貪欲な選択を維持するため、すべての候補率が正しく評価されます。 

## Python ソリューション```python
import sys
from fractions import Fraction
import heapq

input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        res = 0
        while i:
            res += self.bit[i]
            i -= i & -i
        return res

    def kth(self, k):
        idx = 0
        step = 1 << (self.n.bit_length() - 1)
        while step:
            nxt = idx + step
            if nxt <= self.n and self.bit[nxt] < k:
                idx = nxt
                k -= self.bit[nxt]
            step >>= 1
        return idx + 1

def solve():
    n, S, K = map(int, input().split())

    cleaners = []
    start = {}

    for i in range(n):
        h, l, u = map(int, input().split())
        cap = K // h
        if cap == 0:
            continue
        left = Fraction(l, h)
        right = Fraction(u, h)
        cleaners.append((h, cap, left, right, i))
        start.setdefault(left, []).append(len(cleaners) - 1)

    cleaners.sort(key=lambda x: x[2])

    hs = sorted(set(x[0] for x in cleaners))
    pos = {v: i + 1 for i, v in enumerate(hs)}

    cnt = Fenwick(len(hs))
    total = Fenwick(len(hs))

    events = []
    active = [False] * len(cleaners)
    for idx, x in enumerate(cleaners):
        heapq.heappush(events, (x[3], idx))

    best = None
    ptr = 0

    rates = sorted(start.keys())

    for rate in rates:
        while ptr < len(cleaners) and cleaners[ptr][2] == rate:
            h, cap, _, _, idx = cleaners[ptr]
            p = pos[h]
            cnt.add(p, cap)
            total.add(p, cap * h)
            active[ptr] = True
            ptr += 1

        while events and events[0][0] < rate:
            _, idx = heapq.heappop(events)
            h, cap, _, _, _ = cleaners[idx]
            if active[idx]:
                p = pos[h]
                cnt.add(p, -cap)
                total.add(p, -cap * h)
                active[idx] = False

        if cnt.sum(len(hs)) >= S:
            hpos = cnt.kth(S)
            before = cnt.sum(hpos - 1)
            need = S - before
            hours = total.sum(hpos - 1) + need * hs[hpos - 1]

            value = rate * hours
            if best is None or value < best:
                best = value

    if best is None:
        print("*")
    else:
        print(best.numerator, best.denominator)

solve()
```フェンウィック ツリーの実装はプレフィックスの合計を保存するため、特定の速度まで利用できる道路の数と、それに対応する合計時間をカウントできます。 の`kth`累積容量が到達する最初の速度を検出します。`S`、まさに貪欲な選択が終了する時点です。 

スイープでは正確な値が使用されます`Fraction`ここでは浮動小数点の比較が危険であるため、オブジェクトを削除します。 次の 2 つのレート`1/3`そして`2/6`同一のものとして扱う必要があります。 ヒープは、クリーナーの上限を超えるとクリーナーを削除し、アクティブ セットを正しい状態に保ちます。 

最後の掛け算も分数で行われるため、プリントされた答えはすでに縮小されています。 すべての算術は Python の整数に簡単に適合します。

 ## 特殊なケース

 掃除機が持っている場合`H_i > K`、彼らの能力はゼロです。 1本でも制限時間をオーバーしてしまうため雇うことができません。 アルゴリズムは、容量がゼロのクリーナーを無視して、それらを即座に削除します。 

複数のクリーナーが同じレート境界を持つ場合、それらはすべて一緒に利用可能になる必要があります。 例えば：```
2 5 5
1 2 4
2 4 8
```どちらのクリーナーも料金でご利用いただけます`2`。 スイープ グループは小数に等しいため、実行可能性をチェックする前に両方が挿入されます。 

一般的なオフバイワンエラーは容量計算にあります。 条件は`s_i * H_i <= K`、したがって、ストリートの最大数は次の整数の下限になります。`K / H_i`、四捨五入された値ではありません。 フェンウィック ツリーはまさにこの容量を保存するため、最終的な選択が許容時間を超えることはありません。
