 ## 解決策
 ## 問題の理解

 この問題では、群衆の反応の流れを表す文字列が得られます。 この文字列内では、3 つの特定の音のパターンがスコアに影響を与えます。 部分文字列が`ha`と表示されるとスコアが1つ増えます。 毎回`boooo`と表示されるとスコアが1つ減ります。 毎回`bravo`と表示されるとスコアが 3 増加します。 重複した出現を含むすべての出現がカウントされ、文字列の他のすべての部分は影響を受けません。 タスクは、最終スコアを計算することです。 

入力は単一の小文字文字列です。 出力は 1 つの整数で、文字列内のすべての可能な開始位置をチェックした後の累積スコアです。 

文字列の長さは最大 1000 ですが、これは十分に小さいため、すべての文字について一定の作業量をチェックするのは容易に制限内に収まります。 リニア スキャンは数千回の操作しか実行しないため、理想的です。 二次アプローチでもこの限界には合格しますが、はるかに大きな限界でも同じパターンが現れるため、直接スキャンを認識する習慣を身につけることは役に立ちます。 

主な実装のトラップは、一致が重複することや、パターンが文字列の終わり近くから始まる可能性があることを忘れることによって発生します。 

たとえば、入力```
hahaha
```出力があります```
2
```なぜなら`ha`位置 0、2、および 4 から始まりますか? 実際には位置 0、2、および 4 のみがチェックされますが、位置 4 の後には 1 文字しかないため、無効になります。 有効な出現箇所は位置 0 と 2 で、スコアは 2 になります。パターンを見つけた後に一致したテキストを削除する不注意な実装では、誤って 2 番目の出現箇所が失われる可能性があります。 

別の例は次のとおりです。```
brhavo
```出力あり```
1
```部分文字列`bravo`インデックス 2 から表示され、3 に貢献しますが、`ha`どこにも現れず、`boooo`どこにも現れない。 文字列の先頭からのみチェックするソリューションでは、後から始まる有効なパターンを見逃してしまいます。 

最終的な境界ケースは次のとおりです。```
booo
```出力あり```
0
```文字列は次のように見えます`boooo`, ただし、含まれているのは 3 つだけです`o`以降の文字`b`。 不完全な長さチェックを使用するソリューションでは、誤って無効な位置にアクセスしたり、これをマイナスのスコアとしてカウントしたりする可能性があります。 

## アプローチ

 簡単なアプローチは、文字列内の可能な開始位置をすべて試して、それに続く文字を各ターゲット パターンと比較することです。 パターンの長さが固定されているため、どの位置でも一定の作業のみが必要です。 これは正しいです。パターンの出現ごとに一意の開始インデックスがあり、すべての開始インデックスをチェックすることであらゆる可能性がカバーされるからです。 

ブルートフォース実装では、すべての位置で 3 つの文字列をテストします。 長さ 1000 の文字列では、これは無害です。 長さがはるかに長い場合は、ほとんどの位置が一致しないため、部分文字列を繰り返し比較する作業は不要になります。 一般的な部分文字列検索アルゴリズムが役立ちますが、ここでの構造はより簡単な解決策を提供します。 

重要な観察は、パターンが固定されており、パターンが 3 つしかないということです。 任意の単語の集合を検索する必要はありません。 各位置の次の数文字を検査するだけで済みます。 左から右への 1 回のスキャンで十分です。 インデックス時`i`、3 つのパターンのそれぞれがそこから始まるかどうかを確認し、すぐにその寄与を追加します。 

これにより、重複する発生が自然に維持されます。 一致を見つけた後に先に進むことはありません。そのため、次のインデックスが引き続き検査されます。

 ## アルゴリズムのチュートリアル

 1. 反応文字列を読み取り、答えをゼロに初期化します。 
2. 文字列のすべてのインデックスを反復処理します。 各インデックスは、意味のある反応の 1 つが始まる可能性があると考えられます。 
3. 現在のインデックスで始まる部分文字列が`ha`、答えに 1 つ追加します。 重複する一致は有効であるため、チェックでは将来の位置をスキップしてはなりません。 
4. 現在のインデックスで始まる部分文字列が`boooo`、答えから1を引きます。 
5. 現在のインデックスで始まる部分文字列が`bravo`、答えに 3 を加えます。 
6. 最終的な累積スコアを印刷します。 

機能する理由: カウントされた反応のすべての発生には、開始位置が 1 つだけあります。 アルゴリズムはすべての開始位置を訪問し、そこから始まる可能性のあるすべての反応をチェックします。 文字を削除したりインデックスをスキップしたりすることはないため、重複する出現は必要に応じて正確にカウントされます。 すべてのスコアの変化は実際の発生に対応し、すべての実際の発生が検出されるため、最終的な値は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    ans = 0
    n = len(s)

    for i in range(n):
        if s.startswith("ha", i):
            ans += 1
        if s.startswith("boooo", i):
            ans -= 1
        if s.startswith("bravo", i):
            ans += 3

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは入力文字列を保存し、それを 1 回スキャンします。 の`startswith`関数は境界処理を自動的に実行するため、文字列の終わり近くのチェックではインデックス エラーが発生するのではなく、単純に false が返されます。 

3 つの条件は独立しています。 理論的には 1 つの位置で複数のパターンが始まる可能性があるため、それらは別のものになります。`if`ステートメントではなく、`if`そして`elif`鎖。 

ループはすべての有効な開始位置にわたって実行されます。 別の一致が次の文字から始まったり、現在の文字と重なったりする可能性があるため、一致を見つけた後も停止しません。

 ## 特殊なケース

 重複する一致については、次の点を考慮してください。```
hahaha
```アルゴリズムはインデックス 0 をチェックし、`ha`、スコアが 1 に増加します。インデックス 2 で別のインデックスが見つかります。`ha`、スコアが 2 に増加します。索引 4 には十分な文字がありません。 結果は 2 で、一致したテキストの削除ではなく、開始位置によって一致がカウントされていることを示します。 

先頭から離れて表示されるパターンの場合:```
brhavo
```アルゴリズムは最初にインデックス 0 をチェックしますが、そこからは反応が始まりません。 インデックス 2 で次のことがわかります。`ha`そして1つ追加します。 文字列全体を単一の単語として誤って扱うことはないため、答えは 1 になります。 

ほぼ一致する否定的な反応の場合:```
booo
```インデックス 0 でアルゴリズムがチェックします。`boooo`, しかし、文字列が短すぎるため、チェックは失敗します。 スコアの変更は発生せず、出力は 0 です。同じ境界処理が文字列の終わりに近いすべての位置で機能します。
