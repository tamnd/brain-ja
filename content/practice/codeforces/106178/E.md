 ## 解決策
 ## 問題の理解

 私たちは箱のコレクションを管理しており、各箱には正の数の食料が保管されています。 コレクションは時間の経過とともに変化します。更新ごとに、指定された量の新しいボックスが挿入されるか、その正確な量の既存のボックスが削除されます。 

更新のたびに、仮定の質問が行われます。 その瞬間に緊急事態が始まった場合、最適な戦略のもとで、すべてのボックスを空にするのに必要な最小限の日数が必要です。 毎日、私たちは 2 つのアクションのうち 1 つを正確に選択することができます。 1 つの箱を完全に空にするか、現在空になっていないすべての箱から 1 つの配給分だけを取り出します。 

このプロセスは時間の経過とともにシミュレーションされません。 代わりに、各更新の直後に最適な合計日数を計算するように求められます。 

重要な問題は、最適な戦略が 2 つの競合するアクション間のトレードオフに依存することです。 2 番目の操作を繰り返し使用すると、すべてのボックスが同時に減少しますが、完全には何も除去されない場合でも 1 日かかるというコストがかかります。 最初の操作はローカルであり、1 つのボックスを完全に削除しますが、他のボックスを減らすには役立ちません。 

制約は大きく、更新数は最大 300,000 です。 これにより、変更のたびに答えを最初から再計算する必要が直ちに排除されます。 どのソリューションも、演算ごとに対数時間または対数に近い時間で答えを更新する必要があります。$O(Q \sqrt{Q})$はすでに遅すぎるでしょう。 

素朴に考えると微妙な問題が見えてきます。 両方の操作を貪欲にシミュレートしたり、最初に最大のボックスを削除してみたりすることもできます。 最適な決定はローカルな順序ではなく値のグローバルな分布に依存するため、どちらのアプローチも失敗します。 

たとえば、現在のボックスが次のとおりであるとします。 

入力:```
3
1 100 101
```単純な考えでは、常に一番大きな箱を最初に空にすることを提案するかもしれません。 単純に解釈すると 1 + 100 + 1 = 102 日となりますが、これは、「すべてのボックスを減らす」操作を繰り返し使用すると、しきい値を超えた後に複数のボックスが同時に消えてしまい、最適なバランスが変化する可能性があることを無視しています。 

中心的な問題は、その答えが貪欲な一連の削除ではなく、グローバルなしきい値の選択に依存するということです。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての操作シーケンスが試行されます。 各ステップで、すべてのボックスを 1 つ減らすか、単一のボックスを完全に削除し、すべてが 0 になるまでの最小日数を検索します。 メモ化を行ったとしても、各ボックスが独立して進化し、値が最大になる可能性があるため、状態空間は膨大になります。$10^9$。 これは組み合わせ的に爆発的に発生し、非常に小さなインスタンスを超えると完全に実行不可能になります。 

より良い観点は、プロセスを 2 つのフェーズに分けることです。 「すべてのボックスを 1 減らす」操作を正確に実行することにしたとします。$k$回。 これらの後$k$グローバルな削減、最大でも価値のあるすべてのボックス$k$自動的に空になります。 残りのすべてのボックスにはまだポジティブなコンテンツが含まれていますが、その時点ではボックスごとに 1 回の操作で個別に削除できます。 

したがって、固定の場合$k$、合計日数は次のようになります。$$f(k) = k + \#\{a_i > k\}$$最初の項はグローバルな減少をカウントし、2 番目の項はその後も残っているボックスの数をカウントします。 

問題は、動的なマルチセットを維持し、すべての整数にわたってこの関数の最小値を継続的に見つけることになります。$k$。 重要な構造観察は次のとおりです。$f(k)$は離散的な意味で凸です。$k$が増加すると、生き残るボックスの数は単調に減少しますが、線形項は着実に増加します。 

これは、最適値が常に配列のソートされた値によって決定される「ブレークポイント」にあることを意味するため、任意の値を考慮する必要はありません。$k$、既存のボックス サイズに近い値のみ。 

主な困難は、挿入と削除の際にこれらのカウントを効率的に維持することです。

 ## アルゴリズムのチュートリアル

 1. まず、ボックス サイズとしきい値の比較のみを考慮するため、入力に出現するすべての値を圧縮します。 これにより、問題は最大でも次の座標範囲に縮小されます。$3 \cdot 10^5$。 
2. フェンウィック ツリーを使用して、これらの圧縮値の周波数配列を維持します。 これにより、指定されたしきい値を超える値を持つボックスの数をすばやく計算できます。 

私たちが必要とする重要な量は$\#(a_i > k)$、合計カウントからプレフィックスの合計を引いたものから導き出すことができます。 
3. 更新のたびに、可能な限り最良の値を再計算します。$k$。 目的は既存の値のしきい値のみに依存するため、生の整数ではなく圧縮されたインデックスを検索します。 
4. 閾値インデックス候補の場合$i$、次を計算します。$$f(i) = val[i] + (total\_boxes - prefix\_freq(i))$$これは選択に相当します$k = val[i]$関数は連続する個別の値の間で定数であるため、これで十分です。 
5. 二分探索を使用して、関数の減少が停止する点を見つけます。 この関数は凸関数であるため、傾きの符号がちょうど 1 回変わるため、隣接する値に基づく単調条件が有効になります。 
6. 評価する$f(i)$最適な候補を中心にして最小値を出力します。 

### なぜ効果があるのか

 機能$f(k) = k + \#(a_i > k)$より大きい要素の数によって決定される離散的な傾きがあります。$k$。 として$k$増加しても、このカウントは減少するだけであり、全体の傾きは減少しません。 それは凸性を保証します。 凸離散関数には単一のグローバル最小値があり、その最小値は傾きが負から非負に移行する点で発生する必要があり、入力値の 1 つによって引き起こされる境界と常に一致します。 正しいカウントを動的に維持するため、すべての評価が$f(k)$現在のマルチセットを正確に反映しているため、各ステップで計算される最小値は常に正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    q = int(input())
    arr = input().split()

    vals = []
    ops = []

    for x in arr:
        x = int(x)
        if x > 0:
            ops.append((x, 1))
            vals.append(x)
        else:
            ops.append((-x, -1))
            vals.append(-x)

    vals = sorted(set(vals))
    idx = {v: i + 1 for i, v in enumerate(vals)}

    fw = Fenwick(len(vals))
    total = 0

    def get_answer():
        if total == 0:
            return 0

        def f(i):
            prefix = fw.sum(i)
            return vals[i - 1] + (total - prefix)

        lo, hi = 1, len(vals)
        while lo < hi:
            mid = (lo + hi) // 2
            if f(mid) <= f(mid + 1):
                hi = mid
            else:
                lo = mid + 1

        best = lo
        return min(f(best), f(max(1, best - 1)))

    out = []
    for x, t in ops:
        if t == 1:
            fw.add(idx[x], 1)
            total += 1
        else:
            fw.add(idx[x], -1)
            total -= 1

        out.append(str(get_answer()))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、各値クラスに現在存在するボックスの数を維持します。 これにより、候補のしきい値を超えるボックスの数を対数時間で計算できるようになります。 

目的関数はそれらの点でのみ変化するため、二分探索は圧縮された並べ替えられた値に対して適用されます。 各クエリは最適なしきい値を最初から再計算しますが、それぞれの評価は$O(\log n)$、全体の複雑さを制限内に保ちます。 

実装におけるよくある間違いは、プレフィックスの合計が静的なスナップショットではなく、各ステップの現在のマルチセットを反映する必要があることを忘れていることです。 もう 1 つの微妙な問題は評価です。$f(i)$正確なインデックスのみ。 インデックス間では関数は定数であるため、境界のみをチェックするだけで十分です。

 ## 特殊なケース

 重要なエッジケースは、すべてのボックスが同一である場合です。 次のものがあるとします。 

入力:```
+10 +10 -10
```最初の 2 つの挿入の後、最適な戦略により、2 つの同一の大きなボックスに対するグローバル削減のバランスがとられます。 アルゴリズムは値 10 でのみしきい値を評価します。この場合、関数は 2 つのボックスが小さい k より上に残ることを反映します。 1 つのボックスが削除されると、構造が変更され、グローバル削減の効果がすぐに高まります。 

ボックスが 1 つしかない場合、別の特殊なケースが発生します。 次に、任意のしきい値$k$その値までは 2 番目の項が 0 になり、最初の挿入後の答えは常に 1 になります。 凸関数は平坦になり、ブレークポイントの後に増加するため、二分探索は単一の候補に正しく折りたたまれます。 

最後の微妙なケースは、最大要素を交互に削除することです。 圧縮されたフェンウィック構造により、プレフィックス数が正しく更新されることが保証されるため、アルゴリズムは古い最大値に依存せず、構造が変更されるたびに常に正しいグローバル最小値を再計算します。
