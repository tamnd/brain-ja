 ## 解決策
 ## 問題の理解

 一人ずつクラブに参加する人がいます。 の`i`- 番目の人がいくつかの風船を持ってきて、`1`そして`K`。 到着するたびに、それまでに集められた風船の合計数が、現在クラブにいる人の数で割り切れる必要があります。 

タスクは、すべてのプレフィックスについてこの条件を満たす寄与のシーケンスがいくつあるかをカウントすることです。 少なくとも 1 人が異なる数の風船を持ってきた場合、2 つのシーケンスは異なります。 答えは必須です`998244353`。 問題の説明と制限は Codeforces Gym 106178B からのものです。`N`と同じ大きさにすることができます`10^9`その間`K`せいぜい`2000`。 

最初の課題は、`N`巨大です。 すべての人をシミュレートするアプローチは不可能です。`10^8`すでに一般的なコンテストの制限時間には多すぎる作業があり、ここでは参加者数が 10 倍になることもあります。 小さな限界`K`これは、活用すべき重要な制限です。 

各到着後の 1 人当たりの風船の平均数を考えてみましょう。 すべてのプレフィックスの合計はその長さで割り切れるため、この平均は常に整数になります。 すべての貢献は次の間であるため、`1`そして`K`、すべての平均も間にあります`1`そして`K`。 これにより得られるのは、`K`たとえステップ数が膨大になる可能性があるとしても、可能な状態はすべて含まれます。 

扱いにくいケースは、ほとんどが非常に小さな値に関するものと、プロセスが安定する点に関するものです。 

たとえば、次のようになります。```
1 3
```答えは`3`、本人しか持ち込めないので`1`、`2`、 または`3`風船。 2 人称からトランジションを開始するソリューションは、誤ってゼロを返します。 

別のケースは次のとおりです。```
4 1
```答えは`1`。 風船は一人一人必ず 1 個持参する必要があります。 平均が変化する可能性があるかどうかだけをチェックするアプローチでは、有効な状態は平均だけであるため、誤って不可能な変化をカウントしてしまう可能性があります。`1`。 

より微妙なケースは次のとおりです。```
5 2
```十分な人数が参加すると、平均は変更できなくなります。 平均からの移行`1`平均する`2`人に`6`6人目の人が持参する必要がある`7`風船、それは不可能です。 同じ遷移が永遠に続くと仮定したソリューションでは、過大なカウントが発生します。 

## アプローチ

 直接的な解決策は、現在の風船の総数を維持し、すべての人に対して可能な限りの貢献を試みることです。 人それぞれに、`K`選択肢があるので、これは次のようになります`K^N`可能性。 これは文字通りすべての有効なシーケンスを列挙するため正しいですが、すぐに使用できなくなります。 

もう少し優れた試みは、現在の平均を超える動的プログラミングです。 後の状態にします`i`人々は現在の平均になる`a`。 あるのは`K`州。 平均からの移行`a`新たな平均へ`b`次の寄与によって決定されます。$$x = i \cdot b - (i-1)\cdot a$$もし`x`の間にあります`1`そして`K`の場合、この遷移は有効です。 

すべての平均ペアに対するブルート フォース DP により、可能な限りすべてのチェックが行われます。`a`そして`b`すべての人にとって。 それには費用がかかります`O(NK^2)`、それはまだ不可能です。`N`できる`10^9`。 

重要な観察は、十分な数の人が参加すると、平均はそれ以上動かなくなるということです。 現在の平均が`a`そして次の平均は より大きくなります`d`。 次の貢献は次のようになります。$$x = a + i \cdot d$$ポジティブな変化については、貢献度は次のように増加します。`i`。 それを超える貢献はできないので、`K`、これが不可能になるのは、`i > K`。 平均を下げる場合にも同じ議論が機能します。 立ち寄り`d`必要：$$x = a - i \cdot d$$これは次の場合に非陽性になります。`i`十分な大きさです。 したがって、その後、`K`- 人目では、平均値は永久に変更されないことを強制され、将来的に寄与できる唯一の可能性があるのは、まさに現在の平均値です。 

最初のシミュレーションのみが必要です`K`到着。 残り`N-K`人々はそれぞれ 1 つの強制値を提供するため、有効なシーケンスの数は変更されません。 

トランジションも効率的に生成できます。 州から`a`ステップで`i`、平均を増加させます`d`次の場合に可能です。$$a+i d \leq K$$そして減少`d`次の場合に可能です。$$a-i d \geq 1$$すべてのステップで生成されるトランジションの合計数は次のとおりです。$$\sum_{i=1}^{K} \frac{K^2}{i}$$周りにあるのは`K^2 log K`、簡単に十分に高速です`K = 2000`。

 | --- | --- | --- | --- |
 | ブルートフォース |`O(K^N)`|`O(N)`| 遅すぎる |
 | 最適化なしの平均を上回る DP |`O(NK^2)`|`O(K)`| 遅すぎる |
 | 平均を上回る最適化された DP |`O(K^2 log K)`|`O(K)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 参加者が 1 人の場合、すべての寄付`1`に`K`は有効なので、答えは`K`。 
2. 動的プログラミング配列を次の場所に保存します。`dp[a]`現在の平均人数の後の有効なシーケンスの数です。`a`。 

最初の人以降の平均は、その人が持ってきた風船の数とまったく同じなので、最初の人のすべての平均は`1`に`K`には有効なシーケンスが 1 つあります。 
3.本人からの到着処理`2`人まで`min(N, K)`。 

現在のステップについて`i`、状態の新しい配列を作成します。 現在の平均ごとに`a`、このステップで到達可能な次の平均をすべて試してください。 
4. 平均が等しくなる遷移を処理します。 

平均が残っている場合`a`、新しい投稿も`a`、これは常に有効です。 
5. 平均が増加する遷移を処理します。 

からの移動`a`に`a+d`以下の貢献が必要です。$$a+i d$$増加`d`この値が最大である間は`K`。 
6. 平均が減少する遷移を処理します。 

からの移動`a`に`a-d`必要：$$a-i d$$減少`d`この値が少なくとも`1`。 
7.加工後`min(N,K)`人々、すべての状態を合計してください。 もし`N`よりも大きいです`K`、後の人々は各州からの可能な貢献順序を 1 つだけ持っているため、答えは変わりません。 

なぜ効果があるのか:

 不変条件は、人を処理した後のものです。`i`、`dp[a]`有効なプレフィックスを正確にカウントします。`i`人々は`a`。 考えられるすべての次の寄与は、正確に 1 つの次の平均に対応し、生成されたすべての遷移は、結果の平均が整数であるため、割り算の要件を満たします。 遷移生成では、存在する可能性のあるすべての寄与がチェックされるため、有効なシーケンスが失われることも、無効なシーケンスが追加されることもありません。 人数を超えたら`K`、平均を変更するには、許容範囲外の寄与が必要となり、自己遷移のみが残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    N, K = map(int, input().split())

    if N == 1:
        print(K % MOD)
        return

    dp = [0] * (K + 1)
    for i in range(1, K + 1):
        dp[i] = 1

    limit = min(N, K)

    for people in range(2, limit + 1):
        ndp = [0] * (K + 1)

        for avg in range(1, K + 1):
            cur = dp[avg]
            if cur == 0:
                continue

            ndp[avg] = (ndp[avg] + cur) % MOD

            increase = 1
            while avg + people * increase <= K:
                ndp[avg + increase] = (ndp[avg + increase] + cur) % MOD
                increase += 1

            decrease = 1
            while avg - people * decrease >= 1:
                ndp[avg - decrease] = (ndp[avg - decrease] + cur) % MOD
                decrease += 1

        dp = ndp

    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```最初の部分では、移行元となる以前の平均がないため、1 人の特殊なケースを扱います。 

の`dp`配列にはバルーンの合計数ではなく、平均のみが保存されます。 これは、の大きな価値を生み出す圧縮です。`N`管理可能。 

ループ内では、`people`は新規到着後の人数です。 遷移式はこの値に依存するため、演算の順序が重要になります。 置き換える前に古い平均から新しい状態を生成します`dp`。 

増加と減少のループにより、すべてのチェックが回避されます。`K`次に考えられる平均値。 これらは有効な変更のみを直接生成します。 境界チェック`avg + people * increase <= K`そして`avg - people * decrease >= 1`無効な平均を防ぎ、通常、オフバイワンの間違いが発生する場所です。 

Python の整数はオーバーフローせず、すべての加算は剰余化されます。`998244353`保存される値を小さく保つためです。

## テストケース```python
import sys
import io

MOD = 998244353

def solution(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    import sys
    input = sys.stdin.readline

    N, K = map(int, input().split())

    if N == 1:
        ans = K % MOD
        sys.stdin = old_stdin
        return str(ans) + "\n"

    dp = [0] * (K + 1)
    for i in range(1, K + 1):
        dp[i] = 1

    for people in range(2, min(N, K) + 1):
        ndp = [0] * (K + 1)

        for avg in range(1, K + 1):
            if dp[avg] == 0:
                continue
            cur = dp[avg]

            ndp[avg] = (ndp[avg] + cur) % MOD

            d = 1
            while avg + people * d <= K:
                ndp[avg + d] = (ndp[avg + d] + cur) % MOD
                d += 1

            d = 1
            while avg - people * d >= 1:
                ndp[avg - d] = (ndp[avg - d] + cur) % MOD
                d += 1

        dp = ndp

    ans = sum(dp) % MOD
    sys.stdin = old_stdin
    return str(ans) + "\n"

assert solution("4 1\n") == "1\n", "sample 2"

assert solution("1 5\n") == "5\n", "single person"
assert solution("2 2\n") == "3\n", "all possible averages after two people"
assert solution("5 2000\n").strip() != "", "large K boundary"
assert solution("10 1\n") == "1\n", "forced contribution case"
