 ## 問題の理解

 2 匹のウサギは数直線上の異なる整数の位置から開始し、離散時間ステップで同時に移動します。 左のウサギは の位置から開始します`x`、右のウサギは の位置から開始します`y`、 と`x < y`。 毎秒、左のウサギが一定量右に移動します`a`、右のウサギは一定量だけ左に移動します`b`。 

問題は、非負の整数時間が存在するかどうかです。`t`両方のウサギが正確に同じ位置を占めるようにする`t`移動する場合、そのような最小の`t`。 

連続的な動きを追跡しているのではなく、各秒後の離散的な位置のみを追跡しています。 これは、彼らの動きから導出された一次方程式の整数解を探していることを意味します。 

この制約により、最大 10^9 の位置とステップ サイズで、最大 1000 のテスト ケースが許可されます。 これにより、時間の経過に伴うシミュレーションが即座に除外されます。 たとえ会議が開催されたとしても、それは数十億のステップを経た後である可能性があり、秒ごとにシミュレーションするのは遅すぎます。 

ある時点でウサギ同士の距離が縮まったにもかかわらず、ウサギ同士が会わない場合、微妙な問題が発生します。 単純な実装では、1 匹のウサギがもう 1 匹のウサギを捕まえたり追い抜いたりした場合、出会いがあったに違いないと想定するかもしれませんが、同時に同じ位置に着地しない限り、それは当てはまりません。 

両方のウサギが同じ速度で移動する場合、別の失敗ケースが発生します。 もし`a == b`そして`x != y`、距離は変わらないので、会うことはできません。 移動方向または相対速度のみをチェックする単純なアプローチでは、これを見逃す可能性があります。 

## アプローチ

 ブルートフォース シミュレーションでは、両方の位置が接触するか、距離が長時間増加し始めるまで、段階的に両方の位置を進めます。 時間に`t`、位置は次のとおりです。 

左のウサギ：`x + t * a`右のウサギ：`y - t * b`これらが等しいかどうかを確認します。 これは正しいですが、最良の場合は最大 O((y - x) / (a + b)) のステップが必要となり、それらが満たされない最悪の場合は無制限のステップが必要になる可能性があります。 値が 10^9 までの場合、これは実行できなくなります。 

重要な観察は、整数で線形方程式を解いているということです。 私たちが望んでいるのは:`x + t * a = y - t * b`並べ替えると次のようになります。`y - x = t * (a + b)`したがって、解決策は、初期距離が結合速度で割り切れる場合にのみ存在します。 割り切れる場合、商は会議の正確な時間を示します。 そうしないと、整数タイム ステップで整列することはありません。 

これにより、問題は動的シミュレーションからテスト ケースごとに 1 回の算術チェックに軽減されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に解決します。 

1. ウサギ間の初期距離を次のように計算します。`d = y - x`。 これは、時間ゼロでの両者の距離がどれだけ離れているかを表します。 問題全体は、このギャップをいつ正確に埋めることができるかを判断することに帰着します。 
2. 1 秒あたりの複合閉速度を次のように計算します。`s = a + b`。 1秒ごとにギャップが正確に減少します`a + b`というのは、一匹のウサギは右に動き、もう一匹のウサギは左に動くからです。 このステップでは、動きの対称性をキャプチャします。 
3. かどうかを確認します。`d`で割り切れます`s`。 そうでない場合、整数時間はありません`t`位置が正確に一致するようにします。 これは、ギャップが固定整数の増分で縮小するため、正確にゼロに達するのは次の倍数だけであるためです。`s`。 
4. 割り切れる場合は計算する`t = d // s`。 両者の立場が初めて対等になる瞬間です。 
5. 出力`t`テストケースの場合、または`-1`割り切れない場合。 

### なぜ効果があるのか

 重要な不変条件は、ウサギ間の距離が 1 秒ごとに正確に減少することです。`a + b`。 遠くから始める`d`、 後`t`距離は秒です`d - t(a + b)`。 この式が 0 に等しい場合に、会議が開催されます。 すべての項は整数であるため、可能な唯一の解決策は次の場合です。`d`の倍数です`a + b`、対応する商が最初の有効な会議時間になります。 両方の位置が線形かつ同期的に進化するため、この方程式を満たさずに両者が出会う中間状態は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x, y, a, b = map(int, input().split())
        d = y - x
        s = a + b
        if d % s == 0:
            print(d // s)
        else:
            print(-1)

if __name__ == "__main__":
    solve()
```この実装は、導出された方程式を直接反映します。 距離`d`はテスト ケースごとに 1 回計算され、結合された速度は`s`ギャップが 1 秒あたりに縮む速度を表します。 可算性のチェックが重要な決定点です。 失敗した場合は、整数のタイム アライメントが存在しないため、すぐに戻ります。`-1`。 成功すると、整数除算によって正確な集合時間が得られます。 

計算には注意が必要です`d = y - x`負の値を避けるためです。 入力保証なので`x < y`、これは安全ですが、それでも正確さを強化します。

 ## 特殊なケース

 いつ`a == b`、結合速度は`2a`、そして距離は均等なステップでしか縮まりません。 初期ギャップが奇数の場合、アルゴリズムは正しく返します。`-1`なぜなら、整数のステップでは偶数の減少で奇数の距離を埋めることはできないからです。 例えば、`x = 0, y = 1, a = 1, b = 1`与える`d = 1`、`s = 2`、そして割り切れず、対称的に跳ね返り決して一致しないという事実と一致します。 

ギャップが結合速度よりも小さい場合でも、除算ロジックは有効です。 例えば`x = 1, y = 3, a = 1, b = 2`与える`d = 2`、`s = 3`、これは割り切れないので、答えは次のようになります。`-1`。 ウサギは急速に近づいても、正確に一緒に着地することなくオーバーシュートし、算術演算はこれを直接捉えます。
