 ## 解決策
 ## 問題の理解

 私たちには、時間の経過とともに進化するグリッドが与えられています。 毎日、一連の森林セクション全体であらゆる動物の数が生成されます。 2 台のカメラを数日間にわたって繰り返し配置し、各カメラが常に連続するセグメントを正確にカバーしたいと考えています。$k$森林セクション。 

重要な問題は、時間が構造化されていることです。1 台のカメラは奇数日に使用され、もう 1 台は偶数日に使用され、それぞれの使用は最大 2 日間続きます。 したがって、事実上、毎日 1 つのアクティブなカメラが存在し (シーケンスがウィンドウの途中で終了する境界の場合を除く)、そのカメラは 1 つの長さを選択します。$k$その日のインターバル。 1 日のスコアは、選択した間隔の値の合計であり、両方のカメラが同じ日に重複するセクションをカバーした場合、重複する寄与は二重にカウントされません。 

したがって、タスクは、毎日、長さの間隔を 1 つ選択することです。$k$アクティブなカメラの場合、2 つの独立した「スレッド」 (赤と青) を交互に選択するという制約があり、すべての日の総和を最大化します。 

制約により、計算上の形状が即座に決定されます。 最大 50 日、最大 20,000 列がありますが、$k \le 20$。 この組み合わせが重要なシグナルです。1 日あたりの間隔数で二次関数を処理する余裕はありますが、すべての間隔を繰り返しスキャンする余裕はありません。$m$単純な動的プログラムにおける遷移ごとの位置。 

素朴な解釈では、毎日の推移についてすべての間隔のペアを考慮しようとします。 毎日約$m$可能なウィンドウがあるため、トランジションは次のようになります。$O(m^2)$ステップごとに、おおよその結果が得られます$50 \cdot 400\,\text{million}$運用はすでに境界線に達しており、重複処理が含まれるとさらに悪化します。 

さらに微妙な落とし穴は、オーバーラップを正しく処理しないことです。 両方のカメラが同じ日に同じセグメントをカバーできるため、2 つの独立した DP 状態を単純に合計すると、共有領域が 2 倍にカウントされます。 この結合を無視した単純なソリューションでは、最適な間隔が大幅に重複する場合、特に両方のカメラが高密度領域に収束する場合に、膨張した結果が生成されます。 

## アプローチ

 ブルートフォース戦略では、毎日を独立して扱います。すべてを列挙します。$m-k+1$アクティブなカメラの考えられるセグメントを選択し、それらの合計を計算して、日数と選択範囲にわたって DP を実行します。 トランジションでは、連続する日の間でセグメントのすべてのペアがチェックされ、重複部分が明示的に減算されます。 すべての制約を直接尊重するため、これは正しいですが、移行ステップが実行時間に影響を及ぼします。 各ペアは交差コストを計算する必要があります。$O(k)$素朴に行うと、$O(n \cdot m^2 \cdot k)$、限界をはるかに超えています。 

重要な構造的洞察は、重複はセグメントの位置のみに依存し、その日自体には依存しないということです。 これにより、セグメントのペアごとに、オーバーラップ ペナルティを 1 回事前計算することができます。 その後、DP 遷移は事前計算された値の純粋な加算になります。 

2番目のより重要な削減は、$k \le 20$これは、プレフィックスの合計と事前計算されたセグメントの重みを使用して、2 つの間隔間の相互作用を圧縮できることを意味します。 グリッドを 1 日ごとのウィンドウ合計の配列に変換し、各状態をサイズの小さいインデックス セットに縮小します。$m$。 この場合、DP は階層化された最適化問題になり、遷移は生の配列ではなく間隔インデックスのみに依存します。 

これにより、古典的な最適化が可能になります。隣接する日のペアごとに、すべてのペアにわたる遷移を再計算する代わりに、ローリング DP を維持し、事前に計算された重複調整ゲインを使用して更新します。

 ## アルゴリズムのチュートリアル

 まず、毎日をすべての長さの 1D 配列に圧縮します。$k$ウィンドウの合計。 これにより、グリッドが管理可能な一連の配列に変わります。 

次に、赤カメラと青カメラの交互構造を尊重しながら、現在のカメラ状態に最適な配置を追跡する動的プログラミング プロセスを実行します。 

### ステップ

 1. 毎日、配列を計算します。$W_d[i]$、区間内の値の合計$[i, i+k-1]$。 

これはプレフィックスの合計を使用して行われるため、各ウィンドウは次のように計算されます。$O(1)$。 このステップにより、問題の空間的複雑さが完全なセグメントからインデックス付き状態に軽減されます。 
2. 最後に選択された間隔が特定の位置にあるときに、その日までに達成可能な最高のスコアを表す DP 状態を定義します。 

以前の決定はすべてすでに集約されているため、状態は最後に選択されたセグメント インデックスのみに依存します。 
3. プロセスは常に 1 日目に開始されるため、赤いカメラのみを使用して 1 日目の DP を初期化します。 

考えられるすべての間隔は、そのウィンドウの合計に等しいスコアを持つ有効な開始状態です。 
4. 赤と青のレイヤーを交互に数日間繰り返します。 毎日、前の DP 配列から新しい DP 配列を計算します。 
5. 前の間隔の考えられる各ペアについて$i$と現在の間隔$j$、遷移ゲインを次のように計算します。$$dp_{new}[j] = \max(dp_{new}[j], dp[i] + W_{day}[j] - overlap(i, j))$$オーバーラップ機能は、両方のカメラが同日に交差する範囲を選択した場合に、重複したカバレッジを減算します。 
6. すべての間隔ペア間のオーバーラップ値を 1 回事前計算することで遷移を最適化します。オーバーラップ値は位置と位置のみに依存するためです。$k$、当日ではありません。 
7. すべての日を処理した後、すべての最終 DP 状態にわたる最大値を取得します。 

### なぜ効果があるのか

 どの時点でも、DP 状態は最後の間隔の選択を完全にエンコードし、以前のすべての寄与はすでに累積スコアに含まれています。 間隔間の重複はペア単位であり、以前の履歴とは独立しているため、各遷移での重複を減算すると、1 日に 1 回正確に二重カウントが計算されます。 このプロセスでは、すべての日にわたる合計組合額の有効な分解が形成されるため、寄付が失われたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    arr = [list(map(int, input().split())) for _ in range(n)]
    
    # prefix sums per day
    pref = []
    for d in range(n):
        p = [0] * (m + 1)
        row = arr[d]
        for i in range(m):
            p[i + 1] = p[i] + row[i]
        pref.append(p)
    
    def window_sum(day, l):
        return pref[day][l + k] - pref[day][l]
    
    w = []
    for d in range(n):
        wd = [0] * (m - k + 1)
        for i in range(m - k + 1):
            wd[i] = window_sum(d, i)
        w.append(wd)
    
    sz = m - k + 1
    
    # overlap between segments i and j
    overlap = [[0] * sz for _ in range(sz)]
    for i in range(sz):
        for j in range(sz):
            l1, r1 = i, i + k - 1
            l2, r2 = j, j + k - 1
            L = max(l1, l2)
            R = min(r1, r2)
            if L <= R:
                overlap[i][j] = R - L + 1
    
    dp = w[0][:]
    
    for d in range(1, n):
        ndp = [0] * sz
        for j in range(sz):
            best = 0
            wj = w[d][j]
            for i in range(sz):
                val = dp[i] + wj - overlap[i][j]
                if val > best:
                    best = val
            ndp[j] = best
        dp = ndp
    
    print(max(dp))

if __name__ == "__main__":
    solve()
```コードは、各行をプレフィックスの合計に圧縮することから始まります。$k$間隔合計は一定時間で計算されます。 次に、1 日あたりのすべてのウィンドウの合計を構築し、元のグリッドを管理可能な一連の配列に縮小します。 

オーバーラップ テーブルはセグメントの位置のみに依存するため、一度だけ事前計算されます。 これにより、DP 遷移中の交差の再計算が回避されます。 

その後、DP ループは毎日順番に処理し、可能な間隔ごとに達成可能な最高のスコアを更新します。 各トランジションは重複を減算して、共有カバレッジが二重にカウントされないようにします。 

最終的な答えは、考えられるすべての終了間隔にわたる最良の値です。

 ## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    n, m, k = map(int, input().split())
    arr = [list(map(int, input().split())) for _ in range(n)]

    pref = []
    for d in range(n):
        p = [0] * (m + 1)
        for i in range(m):
            p[i+1] = p[i] + arr[d][i]
        pref.append(p)

    def get(d, l):
        return pref[d][l+k] - pref[d][l]

    w = [[get(d, i) for i in range(m-k+1)] for d in range(n)]
    sz = m-k+1

    overlap = [[0]*sz for _ in range(sz)]
    for i in range(sz):
        for j in range(sz):
            l1, r1 = i, i+k-1
            l2, r2 = j, j+k-1
            L, R = max(l1,l2), min(r1,r2)
            if L <= R:
                overlap[i][j] = R-L+1

    dp = w[0]
    for d in range(1, n):
        ndp = [0]*sz
        for j in range(sz):
            best = 0
            for i in range(sz):
                best = max(best, dp[i] + w[d][j] - overlap[i][j])
            ndp[j] = best
        dp = ndp

    return max(dp)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return str(solve())

## 特殊なケース

 いつ$n = 1$、カメラのアクティベーションは 1 つだけ発生し、意味のある遷移はありません。 DP は単一のウィンドウ最大化ステップに縮退し、2 番目の選択が存在しないため、オーバーラップ ロジックはトリガーされません。 

すべての値がゼロの場合、すべての間隔のスコアは同一であり、オーバーラップ減算によって負のドリフトが発生することはありません。 DP はこれを保証します。これは、すべての候補値が遷移全体を通じて 0 のままであり、最大値が 0 で安定しているためです。 

いつ$k = m$、有効な間隔は 1 つだけです。 DP は、オーバーラップが常にいっぱいになる単一のチェーンに折りたたまれ、解決策は、固有の日の寄与を重複なしで合計することになります。これは、オーバーラップの減算によって正しく適用されます。
