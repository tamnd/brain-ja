 ## 解決策
 ## 問題の理解

 サイズの順列における連続する位置間の厳密な比較のパターンが与えられています。`n`。 それぞれの位置によって、次の値が現在の値より大きくなければならないか小さくなければならないかがわかります。 この制約から、多くの置換が可能です。 

タスクは、有効な順列だけを構築することではなく、すべての有効な順列の中の 2 つの極端な順列を構築することです。 1 つの順列は最長の増加部分列を可能な限り短くする必要があり、もう 1 つの順列は可能な限り長くなるようにする必要があります。 

したがって、入力は位置に対する有向ローカル構造を記述し、数値を割り当てる必要があります。`1`を通して`n`これにより、LIS の動作をグローバルに制御しながら、ローカルな不平等がすべて満たされます。 

この制約は、テスト ケースごとにソリューションが線形またはほぼ線形である必要があることを意味します。 の合計`n`せいぜい`2⋅10^5`したがって、二次構築や LIS を繰り返し再計算するアプローチは遅すぎます。 たとえ`O(n log n)`LIS 計算は、構築ループ内ではなく、一定の回数だけ許容されます。 

微妙な問題は、値の割り当て方法に応じて、同じローカル パターンでも非常に異なる LIS 値が生成される可能性があることです。 有効な順列を生成するだけの単純なアプローチでは、この全体的な効果が無視されます。 

最初の失敗ケースは、問題を左から右に貪欲に処理し、可能な場合は常に利用可能な最小値を配置することです。 これにより、意図せずに長い増加ランが作成されることがよくあります。 たとえば、`"<<<..."`、自然増加順列`1 2 3 ... n`制約を満たし、LIS も最大化しますが、最小ではありません。 

もう 1 つの失敗例は、ランダムな構築やバックトラッキング構築を試みることです。 制約を満たすことはできますが、LIS 構造を制御せず、次のような敵対的な長い交互パターンでは失敗します。`"><><><..."`。 

素朴なアプローチに欠けている重要な洞察は、LIS の長さが局所的な比較だけによってではなく、単調セグメント全体に値を割り当てる方法によって左右されるということです。 

## アプローチ

 比較文字列は、方向が一定である最大の連続セグメントに順列を自然に分割します。 のセグメント`'<'`内部で厳密に増加するチェーンを強制する一方で、`'>'`厳密に減少するチェーンを強制します。 

各セグメント内で唯一自由なのは、単調性を維持するために実際の数値をどのように割り当てるかです。 グローバル LIS の動作は、これらのセグメントが増加する値のブロックに配置されるか減少する値のブロックに配置されるかによって決まります。 

強引なアイデアは、制約を満たすすべての順列を生成し、それぞれの LIS を計算することです。 LIS はチェックインできるため、これは概念的に機能します。`O(n log n)`順列ごとに。 ただし、有効な順列の数は、実行が減少するにつれておおよそ階乗分割のように指数関数的に増加します。 中程度の場合でも`n`、列挙が不可能になります。 

解決策を明らかにする観察は、LIS が内部順序ではなくセグメント間の相対順序に依存しているということです。 モノトーン セグメント内では、常に連続した数字のブロックを割り当てることができます。 残る唯一の選択肢は、これらのブロックをセグメント全体の値の昇順で割り当てるか、降順で割り当てるかです。 

LIS を最小限に抑えるために、セグメントの境界を越えてグローバルに増加する長いチェーンを作成することは避けたいと考えています。 これは、セグメント間の遷移が増加構造を壊すようにセグメント値を降順で割り当てることによって実現されます。 LIS を最大化するには、その逆を行います。値がセグメントの増加方向に揃うように、セグメント値を昇順で割り当てます。 

この構築は、セグメントにわたる 2 パスの貪欲な割り当てになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n log n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、比較文字列を、すべての文字が同じである最大のランに圧縮します。 各ランは、順列内の単調ブロックに対応します。 

### 最大の LIS 順列の場合

 1. 文字列を連続したセグメントに交互に分割します。`'<'`または`'>'`。 
2. から始まる次の未使用の番号へのポインタを維持します。`1`。 
3. 順番にセグメントごとに、利用可能な最小の番号を昇順にそのセグメントに割り当てます。 
4. セグメントが以下に該当する場合`'>'`、それでもその中で増加する数値を割り当てますが、グローバル シーケンス内でのセグメントの配置により、セグメント間の値境界の構築によってローカルの減少動作が確実に尊重されます。 

重要な効果は、セグメント全体で割り当てを増やすと、グローバルな単調増加が可能な限り維持され、LIS が境界を越えて拡張できるようになることです。 

### 最小の LIS 順列の場合

 1. 同じセグメントに分割します。 
2. から始まるポインタを維持します。`n`。 
3. セグメントごとに、利用可能な最大の番号を下向きに割り当てます。 
4. 各セグメント内で、位置の昇順に番号を割り当てますが、グローバル プールから降順になります。 

これにより、セグメント間の値の階層が逆転します。 増加するサブシーケンスを形成しようとすると、各セグメント境界で強制的に再起動され、LIS の増大が制限されます。 

### なぜ効果があるのか

 不変条件は、各セグメントに連続した値の範囲が割り当てられ、これらの範囲の相対的な順序によって、サブシーケンスがセグメントの境界を越えることができるかどうかが決定されることです。 最大構成では、範囲が増加するため、LIS は多くのセグメントを横断できます。 最小の構成では、範囲が減少するため、増加するサブシーケンスは単一のセグメントまたは少数の隣接する互換性のあるセグメント内にトラップされます。 

セグメントは最大の単調ブロックであるため、有効な置換は内部順序を尊重する必要があります。 セグメントごとの範囲が固定されると、すべての有効な順列はこれらの範囲のブロック順列に減らされ、LIS の動作はブロックの順序の関数となり、これを直接制御します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build(n, s, maximize: bool):
    # split into monotone segments
    segs = []
    i = 0
    while i < n - 1:
        j = i
        while j < n - 1 and s[j] == s[i]:
            j += 1
        segs.append((i, j, s[i]))
        i = j

    res = [0] * n

    if maximize:
        cur = 1
        for l, r, ch in segs:
            size = r - l + 1
            vals = list(range(cur, cur + size))
            cur += size

            if ch == '>':
                vals = vals[::-1]

            for k in range(size):
                res[l + k] = vals[k]
    else:
        cur = n
        for l, r, ch in segs:
            size = r - l + 1
            vals = list(range(cur - size + 1, cur + 1))
            cur -= size

            if ch == '<':
                vals = vals[::-1]

            for k in range(size):
                res[l + k] = vals[k]

    return res

t = int(input())
for _ in range(t):
    parts = input().split()
    n = int(parts[0])
    s = parts[1].strip()

    max_perm = build(n, s, True)
    min_perm = build(n, s, False)

    print(*min_perm)
    print(*max_perm)
```この解決策はセグメントの分解に依存します。 各ブロックには連続した範囲が割り当てられ、局所的な実現可能性が保証されます。 セグメント内の反転により、比較の正しい方向が強制されます。 

よくある実装上の間違いは、セグメント境界が位置を含むこと、つまりセグメントの長さが一定であることを忘れていることです。`k`スパン`k+1`配列の位置。 コードはセグメントをエッジ上のインデックス間隔として扱い、次の方法で頂点の長さに変換することでこれを回避します。`r - l + 1`。 

もう 1 つの微妙な点は、両方の構造ですべての制約を正確に保持する必要があることです。 交差は元の比較文字列に違反するため、反転はセグメント内でのみ適用され、セグメント間では決して適用されません。 

## 実用的な例

 インプットを考慮する`n = 5`、`s = ">>><"`。 

セグメントに分割します。`"<<<"`実際にはここには存在しません。 代わりに私たちは`">>>"`そして`"<"`。 

最大の構築のために、増加するブロックを割り当てます。 

| セグメント | 割り当てられた値 | 結果セグメント |
 | --- | --- | --- |
 | >>>" | 1 2 3 4 | 内側を反転 → 4 3 2 1 |
 | "<" | 5 | 5 |

 これにより、制約を満たし、セグメントの境界を越えて比較的長く増加するサブシーケンスを許可する構造が得られます。 

最小限の構築の場合:

 | セグメント | 割り当てられた値 | 結果セグメント |
 | --- | --- | --- |
 | >>>" | 5 4 3 2 | 必要に応じて反転 → 2 3 4 5 構造が内部的に効果を減少 |
 | "<" | 1 | |

 これにより、増加するサブシーケンスはセグメント境界で強制的に再開され、LIS の長さが制限されます。 

トレースは、アルゴリズムの主なメカニズムが局所的な貪欲な選択ではなく、モノトーン ブロックごとの値範囲のグローバルな割り当てであることを示しています。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def build(n, s, maximize: bool):
        segs = []
        i = 0
        while i < n - 1:
            j = i
            while j < n - 1 and s[j] == s[i]:

            cur = 1
            for l, r, ch in segs:
                size = r - l + 1
                vals = list(range(cur, cur + size))
                cur += size
                if ch == '>':
                    vals = vals[::-1]
                for k in range(size):
                    res[l + k] = vals[k]
        else:
            cur = n
            for l, r, ch in segs:
                size = r - l + 1
                vals = list(range(cur - size + 1, cur + 1))
                cur -= size
                if ch == '<':
                    vals = vals[::-1]
                for k in range(size):
                    res[l + k] = vals[k]

        return res

    t = int(input())
    out = []
    for _ in range(t):
        parts = input().split()
        n = int(parts[0])
        s = parts[1].strip()
        a1 = build(n, s, False)
        a2 = build(n, s, True)
        out.append(" ".join(map(str, a1)))
        out.append(" ".join(map(str, a2)))

    return "\n".join(out)

 ## 特殊なケース

 主なエッジケースは、文字列が完全に均一である場合です。`'<'`。 この状況ではセグメントが 1 つしかないため、両方の構造が崩れて単一の連続ブロックが割り当てられます。 このアルゴリズムは、最小 LIS と最大 LIS の両方に対して同一の順列を生成します。これは、LIS が次のように固定されているという事実と一致します。`n`。 

もう 1 つのケースは、次のような交互パターンです。`"><><><"`。 ここでは、すべての位置が独自のセグメントになります。 このアルゴリズムは単一要素ブロックを繰り返し割り当てます。LIS に対する唯一の制御は、それらのブロックの順序によって行われます。 最大の構築では、ほぼソートされた順列が作成されますが、最小の構築では、ステップごとに値の方向が逆転するため、増加するチェーンが大幅に中断されます。 

3 番目のケースは、長いランの後に短いランが続く場合です。`"<<<<>>"`。 このアルゴリズムは、最初に大きな連続ブロックを割り当て、次に小さなブロックを割り当てます。 各ブロックは値の範囲内で分離されているため、off-by-one 境界の相互作用は発生せず、比較は遷移点全体で有効なままになります。
