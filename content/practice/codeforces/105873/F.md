 ## 解決策
 ## 問題の理解

 一連の番号を維持します。 最初はすべての位置に特定の値があり、その後一連の操作を処理します。 クエリでは、選択した間隔内の最大値が求められます。 加算操作では、間隔内のすべての値が 1 ずつ増加します。 この異常な操作により、いくつかの値がリセットされます。選択された間隔内の位置のうち、値がシーケンス全体の現在の最大値に等しいすべての位置がゼロになります。 

入力は、配列のサイズ、演算の数、開始値、そして演算を記述します。 出力は、クエリが出現するのと同じ順序で、最大数のクエリに対する回答のみで構成されます。 

この制限により、単純なシミュレーションは不可能になります。 最大 100,000 の位置と 100,000 の操作がある場合、更新ごとに間隔全体をスキャンすると、最悪の場合、約 10^10 の操作が実行される可能性があります。 ソリューションは、操作ごとに O(log n) に近い値を維持するか、少なくとも強力な償却限界を持つ必要があります。 

難しいのはリセット操作です。 クエリされた範囲の最大値はリセットされず、配列全体のグローバル最大値に等しい要素のみがリセットされます。 各セグメントの最大値のみを保存するソリューションでは、情報が失われます。これは、2 つのセグメントの最大値は同じでも、それを達成する要素の数が異なる可能性があるためです。 

たとえば、次のことを考えてみましょう。```
Input
3 2
5 5 1
R 1 2
Q 1 3
```グローバル最大値は 5 です。リセットは位置 1 と 2 に影響するため、配列は次のようになります。`[0, 0, 1]`。 答えは次のとおりです。```
1
```リセットを「範囲内の最大値をゼロに設定する」と解釈する不注意な実装では、グローバル最大値とローカル最大値を混合した後、誤って間違った要素をリセットする可能性があります。 

もう 1 つのエッジ ケースは、セグメントに最大値が含まれていても、そのセグメント内のすべての値がその最大値と等しいわけではない場合です。```
Input
4 2
7 7 3 7
R 1 3
Q 1 4
```グローバル最大値は 7 です。位置 3 の値は 3 であるため、位置 1 と 2 のみがリセットされます。最終的な配列は次のようになります。`[0,0,3,7]`、したがって、答えは次のようになります。```
7
```最大値のみを格納するセグメント ツリーでは、セグメント全体を安全にクリアできるかどうかを知ることができません。 

最後の注意が必要なケースは、ノード内のすべての値が等しい場合です。```
Input
5 2
4 4 4 4 4
R 2 5
Q 1 5
```影響を受ける値はすべてグローバル最大値であるため、配列は次のようになります。`[4,0,0,0,0]`。 答えは次のとおりです。```
4
```データ構造は、セグメント全体を一度に更新できることを認識する必要があります。 

## アプローチ

 簡単なアプローチは、配列を直接保存し、影響を受けるすべての位置にアクセスして各操作を処理することです。 間隔をスキャンして最大値を取得できるため、クエリが簡単です。 すべての要素をインクリメントするため、追加操作も簡単です。 リセット操作では範囲をスキャンし、グローバル最大値を見つけて、一致する値をクリアします。 

これは、すべての操作の定義に直接従うため、正しいです。 問題は速度です。 最悪の場合、すべての操作がほぼすべての位置に影響し、O(NK) 作業が発生し、約 10^10 要素操作に達する可能性があります。 

重要な点は、リセット操作では現在の最大値に等しい値のみが考慮されるということです。 最大値だけではセグメント全体が最大値で構成されているかどうかが明らかにならないため、通常のセグメント ツリーでは十分ではありません。 もう 1 つの情報が必要です。それは、各セグメント内で 2 番目に大きい値です。 

セグメントに最大値がある場合`x`そしてその 2 番目の最大値は以下より小さい`x`の場合、そのセグメント内のすべての要素は正確に`x`。 いつ`x`が全体的な最大値である場合、セグメント全体をすぐにリセットできます。 それ以外の場合は、いくつかの要素をまだ調査する必要がある部分のみに進みます。 

これはセグメント ツリー ビートの背後にあるのと同じ考え方です。 この構造体には、最大値、2 番目に大きい値、最大値が出現する回数、および範囲の追加に関する遅延情報が格納されます。 ノードで終了できない場合は、より小さなグループが見つかるまでのみ深く進むため、最大値をリセットすると効率的です。 実際にリセットされた値は最大レイヤーから消え、必要な償却が行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NK) | O(N) | 遅すぎる |
 | セグメントツリービート | O((N + K) log N) 償却 | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. セグメントツリーを構築します。 すべてのノードについて、最大値、2 番目に大きい値、最大値を持つ要素の数、および子にプッシュする必要がある遅延加算を保存します。 2 番目の最大値は、セグメント全体を安全にリセットできるかどうかを判断するために必要です。 
2. 追加操作の場合`[l, r]`、カバーされたノードに遅延増分を適用します。 セグメント内のすべての値を増やすと、最大値と 2 番目の最大値が同じ量だけ変更されるため、ノード情報は有効なままになります。 
3. お問い合わせについて`[l, r]`、カバーされたノードに格納されている最大値を返します。 遅延値は下降する前にプッシュされるため、子の値は正しくなります。 
4. リセット操作では、まずルートから配列全体の最大値を取得します。 これは削除する必要がある値です。 
5. 交差するセグメント ツリー ノードにアクセスします。`[l, r]`。 カバーされるノードの最大値がグローバル最大値と等しく、その 2 番目の最大値が小さい場合、そのノードのすべての値がグローバル最大値になります。 ノード全体をゼロに設定します。 
6. それ以外の場合は、遅延値をプッシュし、子に続行します。 一部のノードには最大値と小さい値が混在しているため、リセットが安全に適用されるまでノードを分割する必要があります。 

なぜ効果があるのか:

 不変条件は、すべてのノードがそのセグメント内の値の複数セットを常に正確に表すことです。 最大値と 2 番目の最大値は、すべての値が現在の最大値と等しいかどうかを示します。 そうであれば、セグメント全体をゼロに置き換えることがまさに必要な操作です。 そうでない場合は、少なくとも 1 つの子に最大値とは異なる値が含まれるため、降順にすることで正確さが保たれます。 追加操作では、影響を受けるセグメント内のすべての要素が同様に変更されるため、値の順序が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

class SegTree:
    def __init__(self, arr):
        n = len(arr)
        self.n = n
        size = 4 * n
        self.mx = [0] * size
        self.smx = [-INF] * size
        self.cnt = [0] * size
        self.lazy = [0] * size
        self.build(1, 0, n - 1, arr)

    def build(self, v, l, r, a):
        if l == r:
            self.mx[v] = a[l]
            self.cnt[v] = 1
            return
        m = (l + r) // 2
        self.build(v * 2, l, m, a)
        self.build(v * 2 + 1, m + 1, r, a)
        self.pull(v)

    def apply_add(self, v, x):
        self.mx[v] += x
        if self.smx[v] != -INF:
            self.smx[v] += x
        self.lazy[v] += x

    def apply_zero(self, v):
        self.mx[v] = 0
        self.smx[v] = -INF
        self.cnt[v] = self.length[v]
        self.lazy[v] = 0

    def push(self, v):
        if self.lazy[v]:
            x = self.lazy[v]
            self.apply_add(v * 2, x)
            self.apply_add(v * 2 + 1, x)
            self.lazy[v] = 0

    def pull(self, v):
        a = v * 2
        b = v * 2 + 1
        if self.mx[a] > self.mx[b]:
            self.mx[v] = self.mx[a]
            self.cnt[v] = self.cnt[a]
            self.smx[v] = max(self.smx[a], self.mx[b])
        elif self.mx[a] < self.mx[b]:
            self.mx[v] = self.mx[b]
            self.cnt[v] = self.cnt[b]
            self.smx[v] = max(self.mx[a], self.smx[b])
        else:
            self.mx[v] = self.mx[a]
            self.cnt[v] = self.cnt[a] + self.cnt[b]
            self.smx[v] = max(self.smx[a], self.smx[b])

    def add(self, v, l, r, ql, qr):
        if qr < l or r < ql:
            return
        if ql <= l and r <= qr:
            self.apply_add(v, 1)
            return
        self.push(v)
        m = (l + r) // 2
        self.add(v * 2, l, m, ql, qr)
        self.add(v * 2 + 1, m + 1, r, ql, qr)
        self.pull(v)

    def query(self, v, l, r, ql, qr):
        if qr < l or r < ql:
            return -INF
        if ql <= l and r <= qr:
            return self.mx[v]
        self.push(v)
        m = (l + r) // 2
        return max(self.query(v * 2, l, m, ql, qr),
                   self.query(v * 2 + 1, m + 1, r, ql, qr))

    def reset(self, v, l, r, ql, qr, target):
        if qr < l or r < ql or self.mx[v] < target:
            return
        if ql <= l and r <= qr and self.mx[v] == target and self.smx[v] < target:
            self.length[v] = r - l + 1
            self.apply_zero(v)
            return
        if l == r:
            self.apply_zero(v)
            return
        self.push(v)
        m = (l + r) // 2
        self.reset(v * 2, l, m, ql, qr, target)
        self.reset(v * 2 + 1, m + 1, r, ql, qr, target)
        self.pull(v)

def solve():
    n, k = map(int, input().split())
    arr = list(map(int, input().split()))

    tree = SegTree(arr)
    tree.length = [0] * (4 * n)

    def fill_len(v, l, r):
        tree.length[v] = r - l + 1
        if l != r:
            m = (l + r) // 2
            fill_len(v * 2, l, m)
            fill_len(v * 2 + 1, m + 1, r)

    fill_len(1, 0, n - 1)

    ans = []
    for _ in range(k):
        c, l, r = input().split()
        l = int(l) - 1
        r = int(r) - 1
        if c == 'Q':
            ans.append(str(tree.query(1, 0, n - 1, l, r)))
        elif c == 'A':
            tree.add(1, 0, n - 1, l, r)
        else:
            cur = tree.mx[1]
            tree.reset(1, 0, n - 1, l, r, cur)

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```ツリーはノードごとに 4 つの情報を保持します。`mx`セグメント内の最高値を表し、`smx`はそれより厳密に小さい最高値を表し、`cnt`最大値に達する要素の数を格納します。 セグメントに 1 を追加すると、すべての値が均等にシフトされるため、遅延値は加算のみに使用されます。 

リセット操作では、次の関係が使用されます。`mx`そして`smx`。 最大値がターゲットであり、2 番目の最大値が小さい場合、セグメントにはターゲット値のみが含まれます。 ノード全体をクリアしても安全です。 それ以外の場合、コードは遅延加算をプッシュし、子を調べます。 

の`length`配列にはセグメント サイズが格納されるため、完全なリセットによって最大値のカウントが正しく更新されます。 これを分離しておくと、再帰中に長さが再計算されるのを避けることができます。 境界処理は包含インデックスに基づいているため、入力インデックスからゼロベースのインデックスへの変換は処理前に 1 回行われます。

 ## 特殊なケース

 リセット間隔にすべてではなく一部の最大値が含まれる場合、ノード全体をクリアするのではなく、ツリーが下降します。 で：```
4 2
7 7 3 7
R 1 3
Q 1 4
```ルートは最大値を参照します`7`、しかしセグメント`[1,3]`2 番目の最大値は次のとおりです`3`。 リセットは下方向に継続し、次の内容を含む葉のみをクリアします。`7`。 最終的な最大値が残ります`7`。 

すべて等しい場合:```
5 2
4 4 4 4 4
R 2 5
Q 1 5
```カバーされたノードには`mx = 4`そして`smx = -INF`。 アルゴリズムは、そのノード内のすべての値が次のとおりであることを認識しています。`4`, したがって、セグメント全体がすぐに置き換えられます。 残りの最初の位置は値を保持します`4`、これはクエリ結果です。 

重複する追加の場合:```
3 3
1 2 3
A 1 3
R 1 3
Q 1 3
```追加後の配列は次のようになります`[2,3,4]`。 これはグローバル最大値であるため、リセットでは最後の値のみが削除されます。 答えは次のようになります`3`、遅延追加とリセットが正しく相互作用することを示しています。
