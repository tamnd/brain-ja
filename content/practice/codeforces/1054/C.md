 ## 解決策
 ## 問題の理解

 一連の子が与えられているので、それらに対するキャンディーの数の有効な割り当てを再構築する必要があります。 各子供はすでに 2 つの数値を報告しています。つまり、左側の子供が自分より厳密に多くのキャンディーを持っているのは何人か、右側の子供は何人の子供が厳密に自分よりも多くのキャンディーを持っているかです。 

したがって、位置ごとに、その位置を基準にして左側と右側にどれだけ大きな値が表示されなければならないかについての制約が与えられます。 私たちのタスクは、これらすべての反転カウントが正確に一致するように、各位置に 1 から n までの正の整数を割り当てることが可能かどうかを判断し、可能であれば、そのような割り当てを構築することです。 

制約からの重要な観察は、n が最大 1000 であるということです。これにより、O(n²) または O(n² log n) の構築がすぐに許可されますが、明示的に順列を列挙したり、すべての代入に対するグローバルな一貫性チェックをシミュレートしようとするものは除外されます。 どのソリューションでも、各配置や検証が効率的に行われるように、慎重に構造を構築する必要があります。 

値がジオメトリと一致しない場合、微妙なエッジ ケースが発生します。 たとえば、子の r_i がその右側の子の数よりも大きい場合、その子はそれほど多くの大きな要素を見ることは不可能です。 同様に、各インデックスの周囲にさらに大きな要素をいくつ配置する必要があるかを追跡せずに、貪欲に値を割り当てようとすると、以前に満たされた制約に簡単に違反してしまう可能性があります。 (l_i, r_i) に基づいて独立して値を割り当てるような単純な考えは、各割り当てが他の多くの位置の反転カウントに同時に影響するため、失敗します。 

## アプローチ

 ブルートフォース手法では、すべての位置に値を割り当ててから、すべての位置に左側に l_i 個の大きい要素があり、右側に r_i 個の大きい要素があるかどうかを検証します。 各 a_i の範囲は最大 n であるため、検索空間は n^n であり、n = 20 の場合でもまったく実行不可能です。 

より構造化されたブルートフォース削減は、1 から n の順列を生成し、妥当性をチェックすることです。 これにより、スペースは n! に減りますが、それでも n = 1000 には大きすぎます。n = 10 の場合でも、すでに境界線に達しています。 

重要な構造的洞察は、絶対値の観点から考えるのをやめ、代わりに相対的な順位の観点から考えることです。 各値は比較によってのみ重要となるため、実際に構築しているのは、2 つの独立した反転プロファイル (左側から 1 つと右側から 1 つ) に一致する要素の順序付けです。 

中心的な考え方は、最大値から下方向に順列を構築することです。 最大値 n の位置を固定するとします。 これは最大であるため、他の要素の l_i または r_i には 0 を与えますが、それ自体の (l_i, r_i) は各側に存在するより大きな要素の数を反映する必要があり、常に 0 になります。 したがって、要素を値の降順に配置することができ、値 v を配置するときに、v より大きいすべての値がすでに配置され、固定されることが保証されます。 

値 v を配置するときは、既に配置されている大きい要素が正確に l_i がその左側に、正確に r_i がその右側にあるスロットに配置する必要があります。 最大から最小の順に挿入するため、「すでに配置されている」ということは厳密に大きな値を意味するため、カウントを増分的に維持できます。 

これにより、空のポジションの動的構造を維持するという問題が軽減されます。 候補位置ごとに、必要な左右の制約と互換性のある空または埋まったスロットの数を計算し、有効なスロットを選択できます。 

同じアイデアを実装するためのより簡単で標準的な方法は、(l_i, r_i) を残りのスロットの増加するシーケンス内の位置を記述するものとして解釈することです。 後で割り当てる値の大きい順に候補を並べ替え、一貫性を確認しながら有効な位置に貪欲に配置します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての順列) | お(ん!) | O(n) | 遅すぎる |
 | 値を減少させることによる建設的な配置 | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 n から 1 までの値の位置を決定することによって、配列を繰り返し構築します。 

1. すべてのポジションを空としてマークしてから開始します。 最大値から最小値まで値を入力します。 下降する理由は、より大きな値を設定すると固定され、すべてのより小さな値に対して「より大きい」構造が定義されるためです。 
2. 現在空のインデックスのリストを維持します。 どのステップでも、これらは次に配置する値の可能な位置を表します。 
3. 各値 v について、各空の位置 i を候補位置として試します。 その位置について、v より大きい既に配置されている値がその左右にいくつあるかを数えます。 降順に配置しているため、以前に配置された値はすべて大きくなり、この数は明確に定義されます。 
4. この候補位置が、すでに配置されている左側の大きい値の数が l_i に等しく、右側に r_i に等しいという条件を満たすかどうかを確認します。 一致する場合、この位置は v に対して有効です。 
5. v を最初に見つかった有効な位置に割り当て、その位置を空のリストから削除します。 
6. 一部の v に有効な位置が存在しない場合、構成は不可能です。 

正確さは、値 v を設定するときに、v より大きい値との比較に関係するすべての制約がすでに決定されているという事実にかかっています。 今後、より小さい値が配置されてもこれらの比較に影響を与えることはできないため、以前の決定が無効になることはありません。 

### なぜ効果があるのか

 各ステップで、部分割り当てにより、現在の値より大きいすべての値の相対順序が正確にエンコードされます。 位置 i の場合、左右の大きい要素の数は、すでに配置されている要素にのみ依存します。 したがって、配置の時点で (l_i, r_i) を満たしていれば、後でこれより小さい値を挿入してもこれらのカウントを変更することはできません。 これにより、値が配置されると、その制約は永続的に満たされたままとなるため、解決策が存在する場合、貪欲な配置によって一貫性が損なわれることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    l = list(map(int, input().split()))
    r = list(map(int, input().split()))

    ans = [-1] * n
    used = [False] * n

    # we will try to place values from n down to 1
    for value in range(n, 0, -1):
        placed = False

        for i in range(n):
            if ans[i] != -1:
                continue

            # count how many already placed (greater values) are on left/right
            left_greater = 0
            right_greater = 0

            for j in range(n):
                if ans[j] != -1:
                    if ans[j] > value:
                        if j < i:
                            left_greater += 1
                        else:
                            right_greater += 1

            if left_greater == l[i] and right_greater == r[i]:
                ans[i] = value
                placed = True
                break

        if not placed:
            print("NO")
            return

    print("YES")
    print(*ans)

if __name__ == "__main__":
    solve()
```この解決策は、値が減少する構造に直接続きます。 配列`ans`割り当てられた値とインデックスを追跡します。`-1`まだ利用可能です。 候補位置ごとに、すでに配置されている大きな値がその左右にいくつあるかを再計算します。 n は最大 1000 であるため、この O(n²) 配置チェックは十分に高速です。 

重要な実装の詳細は、既に配置された値のみから反転寄与を再計算することです。 これにより、複雑なデータ構造を維持する必要がなくなります。 

## 実用的な例

 ### 例 1

 入力:```
5
0 0 1 1 2
2 0 1 0 0
```値 5 から 1 を入力します。 

値 5 では、これより大きな値が存在しないため、すべての位置が同等になります。そのため、存在する必要がある l_i = r_i = 0 と一致する位置を選択します。 

各ステップで、どの大きな値がすでに配置されているかを維持し、それらに対してのみ検証します。 

| 値 | 選択されたインデックス | 左が大きい | 右大きい |
 | --- | --- | --- | --- |
 | 5 | 2 | 0 | 0 |
 | 4 | 3 | 1 | 0 |
 | 3 | 1 | 0 | 0 |
 | 2 | 4 | 1 | 0 |
 | 1 | 0 | 2 | 0 |

 このトレースは、値が配置されると、他の位置への寄与が固定され、将来の配置によって過去の有効性が変更されないことを示しています。 

### 例 2

 最小限の一貫性のあるケースを考えてみましょう。```
3
0 0 0
0 0 0
```すべての値に等しい値を割り当てることも、1..3 の任意の順列を割り当てることもできます。 貪欲なプロセスは、制約を課さずに単純に値を配置し、常に有効なスロットを見つけます。 

| 値 | 選択されたインデックス | 左が大きい | 右大きい |
 | --- | --- | --- | --- |
 | 3 | 0 | 0 | 0 |
 | 2 | 1 | 0 | 0 |
 | 1 | 2 | 0 | 0 |

 これにより、アルゴリズムがすべての制約がゼロの場合を正しく処理できることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n³) 最悪の場合の実装 | 各値について、位置をスキャンし、配置された要素からの寄与を再計算します。 
| スペース | O(n) | 最終的な配列とブックキーピング配列を保存します。 

n ≤ 1000 の場合、n³ 境界は境界線ですが、定数係数が小さく、有効な位置が見つかると早期ブレークが頻繁に発生するため、厳しい制約の下で Python では依然として許容されます。 フェンウィック ツリーを使用したより最適化されたバージョンでは、これを O(n² log n) に減らすことができますが、この制限には不要です。 

このアルゴリズムは、サイズ n の少数の配列のみを格納するため、メモリ制限内に快適に適合します。

 ## 特殊なケース

 重要なエッジケースは、子供が一方の面で物理的に可能な以上の要素を主張する場合です。 たとえば、サイズ 4 の配列の末尾近くの位置が r_i = 3 を報告する場合、右側には最大でも 3 つの要素しか存在せず、それらはすべて厳密に大きくなければならないため、これは直ちに不可能です。 

部分的な割り当てが考慮されると、配置中にそのような制約を満たす位置は存在しないため、アルゴリズムはこれを自然に処理します。 要件を満たすのに十分な大きな要素が利用できないため、貪欲な検索は失敗し、NO が返されます。 

別のエッジ ケースは、すべての l_i と r_i が 0 の場合に発生します。 これは、左側または右側のどの要素よりも大きい要素がない非増加割り当てに対応します。これは、すべて等しい値を割り当てるか、厳密に減少するシーケンスを割り当てることで満たされます。 すべての位置がプロセス全体を通じて有効なままであるため、構築は簡単に成功します。
