 ## 解決策
 ## 問題の理解

 空の配列から開始して段階的に構築されると主張されるシーケンスが与えられます。 各ステップで、ビルダーは配列内にすでに存在する要素のサブセットを調べ、そのサブセットの mex を計算し、その mex を次の要素として追加することができます。 

マルチセットの mex は、その中に現れない最小の非負の整数です。 したがって、このプロセスは非常に柔軟です。各ステップで、過去のサブセットを「クエリ」し、欠落している値を追加できます。 

タスクは構造自体を再構築することではなく、一貫性を検出することです。 最終的な配列が与えられたので、それを生成できる一連のサブセット選択が存在するかどうかを判断する必要があります。 「はい」の場合は、-1 を出力します。 それ以外の場合は、有効な構築において何らかのステップがすでに不可能であるはずの最も古いプレフィックスを出力する必要があります。 

n が 100000 までの制約により、あらゆる解が線形または線形に近いものになります。 サブセットの数が指数関数的に増加するため、多数のサブセットにわたって mex を再計算したり、すべての選択肢をシミュレートしようとすることは、直ちに実行不可能になります。 ステップごとに動的構造を維持する場合でも、O(log n) 以上でなければなりません。 

重要な微妙な点は、操作が選択したサブセットに存在する値のセットのみに依存し、存在を超えた値の順序や多重度には依存しないことです。 つまり、推論は基本的に、どの値が各ステップですでにグローバルに利用可能であるかについて行われることを意味します。 

見落としがちないくつかの失敗例:

 最初の要素が 0 でない場合、構築は直ちに不可能になります。 初期配列は空であるため、サブセットのみが空であり、その mex は 0 であるため、最初の要素は常に 0 でなければなりません。 

現在の「利用可能な」値のセットでは生成できない数値が表示される場合、別の厄介な状況が発生します。 たとえば、値 x が表示されても、0 から x−1 までのすべての値がプレフィックスの前のどこかに出現していることをまだ確認していない場合、x をサブセットの mex として生成することはできません。 

最後に、数値が判明すると、サブセット内で使用できるようになる可能性があるため、将来の実現可能性に影響します。 したがって、私たちは増加する「利用可能な数」を維持する必要があります。 

## アプローチ

 直接的な総当たり解釈では、すべてのステップをシミュレートしようとします。各位置 m について、前の要素のすべてのサブセットを考慮し、各サブセットの mex を計算し、現在の値が達成可能かどうかを確認します。 これは定義を正確に反映しているため、原則として正しいです。 ただし、単一のステップであっても 2^(m−1) 個のサブセットがあり、これは指数関数的になります。 n = 100000 では、これは完全に不可能です。 

重要な観察は、実際にはサブセットを列挙する必要がないということです。 サブセットの mex は、そのサブセット内に 0 から上のどの値が存在するかによってのみ決まります。 サブセットが mex x を生成できる場合、そのサブセットには 0 から x−1 までのすべての整数が含まれている必要があり、x が欠落している必要があります。 したがって、本当の質問は次のとおりです。ステップ i で、コンテンツが mex = a[i] を許可する、以前に見た要素のサブセットが存在する可能性はありますか?

 これは、グローバル プレフィックスの構造的条件に帰着します。 a[i] より小さいすべての数値が以前の要素のどこかに存在することを保証できなければなりません。そうしないと、サブセットにそれらを同時に含めることができません。 また、a[i] が現在「構築可能な」ものより大きい場合、矛盾が生じる可能性があります。 

実現可能性を追跡する明確な方法は、プレフィックスにどの値がすでに出現しているかを維持することです。 次に、現在の値が mex の結果であることと一致しているかどうかを確認できます。 利用可能なセット構造を考慮して、サブセットの mex ではない値を生成するように要求された場合、構築は正確に失敗します。これは、必要なときにすべての小さい値がプレフィックスに存在するかどうか、および順序付けの制約に違反しているかどうかをチェックすることになります。

最終的な解決策は、周波数セットを維持し、最小の欠損値パターンを暗黙的に追跡するシングルパスになります。

 | ブルートフォース | O(n・2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 どの値が出現したかを維持しながら、配列を左から右にスキャンします。 

1. ブール値のセットまたは配列を初期化します`seen`これまでに出現した整数とポインタを記録する`mex`0から始まります。 

ポインタは、プレフィックスにまだ存在しない最小の非負の整数を表します。 
2. 1 から n までの各位置 i について、a[i] を読み取ります。 
3. a[i] が mex より大きい場合、構築は不可能であると直ちに結論付けます。 

その理由は、前の要素のサブセットの mex がプレフィックスのグローバル mex を超えることができないためです。これは、どのサブセットもプレフィックスにすでに存在する値しか使用できないためです。 
4. a[i] が mex に等しい場合、これは常に実現可能です。0 から mex−1 までのすべての値を含むサブセット (プレフィックスに存在する必要があります) を取得し、mex 自体を省略して、結果として mex を生成できます。 したがって、このステップを受け入れます。 
5. a[i] が mex より小さい場合、0 から a[i]−1 までのすべての数値を含み、a[i] を除外するサブセットを選択できるため、これも達成可能です。これは、mex が大きいため、つまりこれらの値がすべて存在することを意味するため可能です。 
6. a[i] を処理した後、それを seen としてマークし、seen[mex] が true の間 mex を進めます。 

ステップ 3 がトリガーされる最も早い位置を追跡します。 このインデックスは、間違いなく最初に間違いとなるものです。 

### なぜ効果があるのか

 不変条件とは、`mex`は常に、プレフィックスのどこにも存在しない最小の数値を表します。 サブセット mex は 0 から mex までの範囲内になければなりません。 mex より大きい値が出力に表示される場合は、サブセットがプレフィックスで許容される値を超える mex を生成したことを意味し、mex の定義に矛盾します。 逆に、プレフィックスには必要なすべての小さい数値がすでに含まれているため、mex 以下の値はすべて達成可能であり、mex がターゲットと一致するサブセットの構築が可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    seen = set()
    mex = 0

    for i, x in enumerate(a):
        if x > mex:
            print(i + 1)
            return

        seen.add(x)
        while mex in seen:
            mex += 1

    print(-1)

if __name__ == "__main__":
    solve()
```このコードは、配列内に既に存在する値の実行セットを維持し、現在のグローバル mex を継続的に更新します。 キーのチェックは、現在の値を挿入する前に行われます。値が現在の mex を超える場合、グローバルに欠落しているものより大きい mex をサブセットが生成できないという構造的境界に違反します。 

更新ステップにより、mex が常にプレフィックス状態を反映することが保証されます。これは、将来の有効性がこれまでに導入された値に依存するため、不可欠です。 

## 実用的な例

 ### 例 1

 入力:```
4
0 1 2 1
```私たちは追跡します`seen`そして`mex`:

 | 私 | a[i] | 前に見た | 前にメキシコ | アクション | 後のメキシコ |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | {} | 0 | 0を追加 | 1 |
 | 2 | 1 | {0} | 1 | 1を追加 | 2 |
 | 3 | 2 | {0,1} | 2 | 2を追加 | 3 |
 | 4 | 1 | {0,1,2} | 3 | 1を追加 | 3 |

 どの時点でも値が mex を超えることはないため、シーケンスは一貫しています。 アルゴリズムは -1 を出力し、構築が実行可能であるという事実と一致します。 

### 例 2

 入力:```
3
0 2 1
```| 私 | a[i] | 前に見た | 前にメキシコ | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | {} | 0 | OK、mex は 1 になります |
 | 2 | 2 | {0} | 1 | 2 > 1、失敗 |

 ステップ 2 では、mex が 1 であるときに 2 が発生します。{0} のサブセットが mex 2 を生成できないため、これは不可能です。アルゴリズムは 2 を出力します。 

これにより、構造境界が壊れたときに最初の違反が即座に検出されることが確認されます。

 | 測定 | 複雑さ | 説明 |

| スペース | O(n) | セットには最大 n 個の個別の値が格納されます。 

この制約では最大 100,000 個の要素が許可されるため、定数更新または償却定数更新を伴う単一の線形パスは制限内に問題なく収まります。

 ## 特殊なケース

 重要なエッジ ケースは、最初の要素がゼロ以外の場合です。 入力用`1`、ステップ 1 の唯一のサブセットは空であり、その mex は 0 であるため、0 以外の値は直ちに不可能を意味します。 アルゴリズムはこれを処理します。`x > mex`mex がまだ 0 の場合、最初のステップでは true になります。 

もう 1 つのケースは、値が現在の mex を超えてジャンプする場合です。`0 5 ...`。 ステップ 2 では、mex は 1 であるため、5 が表示されると即時に失敗がトリガーされます。 これは、次のサブセットが存在しないという事実を正しく捉えています。`{0}`1 を超える mex を生成することはできます。 

微妙なケースとしては、次のような小さな値が繰り返されます。`0 0 0 0`。 ここで、 mex は最初の挿入後も 1 のままで、空のサブセットまたは欠落した 0 を選択することでサブセットは常に 0 を生成できるため、後続のゼロはすべて有効です。 mex を超える値がないため、アルゴリズムは正しく失敗をトリガーすることはありません。
