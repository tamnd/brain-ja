 ## 解決策
 ## 問題の理解

 各値が正確に表現される整数の配列が与えられます。$k$ビット。 配列とともに、非常に特殊な変換が許可されています。どの位置でも、数値のすべてのビットを反転して、それをビット単位の補数に変換できます。$k$-ビットスペース。 

目標は、配列値を直接最適化することではなく、配列に対して定義された組み合わせ量、つまり XOR が 0 以外である部分配列の数を最大化することです。 サブ配列は、そのすべての要素の XOR がゼロに等しくない場合に「良好」としてカウントされます。 

したがって、このタスクはグローバルな最適化問題になります。オプションでいくつかの要素を補完することにより、できるだけ多くの部分配列 XOR がゼロ以外になるようにプレフィックス XOR の動作を形作る必要があります。 

主な問題は、サブ配列 XOR 構造がプレフィックス XOR の等価性に依存することです。 2 つのプレフィックス XOR 値が一致する場合、サブ配列は XOR ゼロになります。 したがって、良好なサブ配列を最大化することは、繰り返されるプレフィックス XOR 衝突を最小化することと同じです。 

制約は大きく、最大 200,000 個の要素と 30 ビット整数があります。 演算のすべてのサブセットをシミュレートしたり、サブ配列を直接評価しようとするソリューションは、直ちに実行不可能になります。 平$O(n^2)$周りに影響を与える可能性があるため、遅すぎます$4 \times 10^{10}$最悪の場合の運用。 

操作自体には微妙な構造が導入されています。値のすべてのビットを反転することは、固定マスクを使用した XOR と同等です。$M = (2^k - 1)$。 これは、各要素が元の状態または XOR された状態の 2 つの状態を持つことを意味します。$M$、ポジションごとに状態を選択しています。 

ローカルな決定で十分だと考えると、素朴な間違いが生じます。 たとえば、各プレフィックス XOR を一意にするために貪欲に反転を選択すると、1 つの要素を反転すると後続のすべてのプレフィックス XOR 値が変更されるため、失敗する可能性があります。 

もう 1 つの一般的な落とし穴は、問題をプレフィックス XOR 衝突に変換せずに、サブ配列数を直接最適化しようとすることです。 このアプローチでは、二重にカウントされたり、セグメント間のインタラクションが見逃されたりする傾向があります。 

## アプローチ

 ブルート フォースの解釈は簡単です。インデックスのサブセットごとに、各要素を反転するかどうかを決定し、結果の配列を計算して、ゼロ以外の XOR を持つサブ配列の数を数えます。 これは、目的を直接評価するため、概念的に機能します。 ただし、必要なのは$2^n$構成と各評価コスト$O(n^2)$または$O(n)$プレフィックス XOR を使用すると、完全に実行不可能になります。 

重要な構造的変化は、目的を書き直すことからもたらされます。 サブアレイ$[l, r]$プレフィックス XOR の場合に限り、XOR が 0 になります。$l-1$プレフィックス XOR に等しい$r$。 したがって、適切な部分配列を最大化することは、プレフィックス XOR 値間の等しいペアを最小化することと同じです。 

これにより、問題は、要素ごとのローカル バイナリ選択を使用してプレフィックス XOR のマルチセットを制御することに変換されます。 補数演算は XOR と明確に相互作用します。要素を反転すると、固定マスクによる寄与が切り替わるため、プレフィックス XOR 値は予測可能な線形方法でシフトされます。 

重要な観察は、個々の要素について推論する代わりに、マスク変換の下で各プレフィックス XOR の「値クラス」について推論できることです。 各プレフィックス状態はその補数状態と組み合わせることができ、遷移は同じクラスに留まるか切り替えるかに影響します。 

これにより、問題は、各位置が 2 つの可能な次の状態に寄与するプレフィックス XOR 状態に対する貪欲な構築に帰着され、プレフィックス XOR シーケンスでの衝突を最小限に抑えるものを選択します。 最適な戦略は、各 XOR 状態またはその補数が出現する頻度を追跡し、プレフィックス XOR 値の多様性に向けてシーケンスにバイアスを確実に適用することで導き出すことができます。 

実際には、各ノードに 2 つの可能な出力遷移があり、個別のプレフィックス XOR を最大化するように遷移を選択するグラフ内にパスを構築しています。

 ## アルゴリズムのチュートリアル

 私たちは定義します$M = 2^k - 1$したがって、値を補完することは、次の XOR と同等です。$M$。 

各要素を反転するかどうかを決定する間、実行中のプレフィックス XOR を維持します。 

1. 配列をスキャンするときにプレフィックス XOR を計算しますが、各要素がどちらかに貢献できるようにします。$a_i$または$a_i \oplus M$。 

位置のプレフィックス XOR$i$制御したい状態になります。 
2. 各プレフィックス XOR 値が何回出現したかをカウントするハッシュ マップまたは配列を維持します。 
3. 各ポジションで$i$では、2 つの可能な次プレフィックス XOR 値を考慮します。1 つは反転せずに取得され、もう 1 つは反転して取得されます。 
4. これまでのところ「使用」が少ないプレフィックス XOR 状態を生成するオプション、つまりプレフィックス XOR 履歴での出現回数が少ないオプションを選択します。 
5. 選択したプレフィックス XOR の周波数を更新して続行します。 
6. すべての要素を処理した後、標準恒等式を使用して適切な部分配列の数を計算します。 

サブ配列の合計から、等しいプレフィックス XOR 値のペアを差し引いた値。 

この最後のステップは、プレフィックス XOR 値のすべての等しいペアが 1 つのゼロ XOR サブ配列を定義するため機能します。 

### なぜ効果があるのか

 プロセス全体は、プレフィックス XOR 値間の衝突の制御に依存しています。 各決定は、現在の状態と固定マスクによって反転された 2 つの対称状態の間でローカルに選択されます。 これらの状態は状態空間全体で素のペアを形成するため、貪欲な選択により常に、異なる値間でプレフィックス XOR の出現が分散するように構築が推進されます。 

重要な不変条件は、すべてのステップで、これまでに処理されたプレフィックスを考慮してプレフィックス XOR 状態の可能な限り最良の分布を維持し、各選択は更新された周波数構造を通じて将来の衝突にのみ影響するということです。 コスト関数は等しいプレフィックス ペアに対して純粋に加算的なため、繰り返し状態の局所的な最小化により全体的に最適な構成が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    mask = (1 << k) - 1
    
    # prefix xor frequencies
    freq = {}
    
    px = 0
    freq[0] = 1
    
    for x in a:
        # option 1: no flip
        v1 = px ^ x
        
        # option 2: flip
        v2 = px ^ (x ^ mask)
        
        # choose less frequent prefix state
        if freq.get(v1, 0) <= freq.get(v2, 0):
            px = v1
        else:
            px = v2
        
        freq[px] = freq.get(px, 0) + 1
    
    # count pairs of equal prefix XORs
    total = 0
    for c in freq.values():
        total += c * (c - 1) // 2
    
    # total subarrays = n*(n+1)/2
    total_subarrays = n * (n + 1) // 2
    
    print(total_subarrays - total)

if __name__ == "__main__":
    solve()
```このコードは、元のコントリビューションと補完されたコントリビューションの間で貪欲に選択しながら、実行中のプレフィックス XOR を維持します。 マスクはフルビット フリップ操作をエンコードするため、両方のオプションは常に有効な状態になります。 

頻度辞書は、各プレフィックス XOR が出現する頻度を追跡します。 等しいプレフィックス XOR ペアはゼロ XOR サブ配列に正確に対応するため、サブ配列全体からそのようなペアの数を減算すると、最終的な答えが得られます。 

微妙な点は、構築中にサブ配列を明示的に追跡しないことです。 代わりに、すべてのサブアレイ構造を単一の周波数計算ステップに圧縮するプレフィックス XOR 多重度に完全に依存します。

 ## 特殊なケース

 重要なエッジ ケースは、ビットマスクの下ですべての要素が同一であるか、高度に対称性がある場合です。 このような場合、単純な貪欲な選択により、同じプレフィックス XOR 値の間で変動し、繰り返し衝突が発生する可能性があります。 正しい処理は、プレフィックス XOR 周波数追跡を通じて、各決定で現在の寄与と反転された寄与の両方を一貫して考慮し、状態の異常なクラスタリングを防止することにかかっています。
