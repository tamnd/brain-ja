 ## 問題の理解

 すべての行を左の頂点、すべての列を右の頂点と考えてください。 独房の風船`(r, c)`行間のエッジです`r`そしてコラム`c`。 

風船を割ると`(r, c)`、残りのバルーンインシデントごとに漕ぎます`r`または列`c`消えます。 したがって、両方とも直接ポップされた 2 つのバルーンが行または列を共有することはできません。 直接ポップされたバルーンは、この 2 部グラフでのマッチングを形成します。 

もう一つ条件があります。 すべてのダーツを投げ終わると、風船はすべて消えたはずです。 直接ポップされなかったバルーンは、直接ポップされたバルーンとその行または列を共有する必要があります。 グラフの用語では、直接ポップされたマッチングは最大でなければなりません。 したがって、問題は、サイズごとに最大の一致をカウントし、ダーツが順序に従って投げられるという事実を考慮することです。 

あらゆる人にとって`x`から`1`を通して`k`、出力は、正確に順序付けられたシーケンスの数を求めます。`x`このようなクリアリングプロセスを形成するバルーンの位置。 順序は重要なので、`x`有効な割れた風船が見つかり、貢献します`x!`異なるダーツシーケンス。 

グリッドには最大でも`12`行と`20`列。 寸法が小さいことが重要な制約です。 すべての行を記述する状態には、行ごとに 3 つの可能性があります。`3^12 = 531441`せいぜい州。 これは大規模ですが、注意深く実装された動的プログラムで管理可能です。 全てを巻き込んだ状態`20`列には`3^20`、これはすでに大きすぎるため、グリッドは 3 値状態で表される次元が小さい方になるように方向付けする必要があります。 

ダーツの数は最大でも`20`、ただし、最大でも存在する可能性があります`12`直接ポップされたバルーンは行を共有できないため、直接ポップされたバルーン。 パラメータ`k`以上の状態を枝刈りするのに依然として役立ちます。`k`ダーツですが、漸近状態の数は変わりません。 

公式声明では、7 秒の制限と 256 MB のメモリが使用されています。 そのサンプルは 4 つのテスト ケースで構成されており、出力があります。`1, 2`、`2, 0`、`1, 8, 0`、 そして`2`、 それぞれ。

## アプローチ

 ブルートフォースアプローチは、割る最初のバルーンを選択し、その行と列がクリアされることをシミュレートし、次に残っているバルーンを選択し、すべてのバルーンが消えるか、または消えるまで続けることです。`k`ダーツが使われていました。 これは正しいです。すべての合法的なダーツ シーケンスが直接調査され、シミュレーションがゲーム ルールに正確に従っているからです。 

問題は分岐要素です。 あ`12 x 20`グリッドには次のものを含めることができます`240`風船。 それらがすべて存在し、順序付けされたすべてのシーケンスを正確に試してみると、`20`ダーツ、葉の数は`240 * 239 * 238 * ... * 221 = 240! / 220!`。 

それはもうそのくらいです`10^47`シーケンス。 順序付けられたシーケンスではなくサブセットのみをチェックする場合でも、数百のバルーンにわたる指数関数的な検索が可能になります。 

有益な観察は、実際に直接割られた風船が一致を形成しているということです。 どの行がすでに選択されているかを決定したら、前の列に関して必要な情報は、その行がすでに選択されているかどうか、その行が選択されていない列に表示されているがまだ選択する必要があるかどうか、または関連する列に一度も表示されていないかどうかだけです。 

これにより、行ごとに 3 つの状態が得られます。 行の状態に 3 値マスクを使用して、グリッドを列ごとに処理します。 列は意図的に州の外に置いておきます。`20`彼らのうち。 

固定列の場合、アクションは 2 種類のみです。 その列にはダーツを投げません。その場合、列内のすべての風船は最終的にその行を選択する義務が生じます。あるいは、列内の 1 つの風船にダーツを投げます。 2 番目のケースでは、その行が選択されますが、列内の他のすべてのバルーンはすぐに消え、将来の義務は発生しません。 

したがって、DP は、昇順の列順序を正規表現として使用して、すべての可能な一致を 1 回列挙します。 最後の列の後、未選択のバルーンが存在する行がない場合、状態は成功となります。 状態に次のものが含まれている場合`x`選択された行、サイズの 1 つの標準的な最大一致を表します`x`。 

ダーツの位置を任意に順序付けることができます。 選択したバルーンは一致するため、行や列を共有するバルーンは 2 つなく、選択したバルーンのすべての順列が有効なダーツ順序となります。 サイズの正規一致の数を乗算します`x`による`x!`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(P(B, k))`、 どこ`B <= 240`|`O(B)`| 遅すぎる |
 | 最適 |`O(n * m * 3^m)`|`O(3^m)`| 承認済み |

 ここ`m <= 12`は三元状態によって表される次元であり、`n <= 20`処理された列の数です。 

## アルゴリズムのチュートリアル

 1. 各バルーンを行と列の間のエッジとして扱います。 直接ポップされた 2 つのバルーンは行または列を共有できないため、直接ポップされたセットは一致する必要があります。 
2. グリッドを列ごとに処理します。 せいぜいあるので`20`列、最大でも`12`行の場合、行全体に 3 値状態を保存するのがより小さい表現です。 
3. 各行に 3 つの状態のいずれかを与えます。 州`0`は、この行のバルーンがポップされずに放置された列に表示されていないことを意味します。 州`1`は、その行がすでにダーツによって選択されていることを意味します。 州`2`これは、この行のバルーンがポップされなかった前の列に表示されているため、この行を後で選択する必要があることを意味します。 
4. 状態から始める`0`すべての行と 1 つの DP ウェイに対して。 
5. 現在の列については、まずそこにダーツを投げないことを検討してください。 その列内のすべてのバルーンは、後でその行が選択された場合にのみ消えるため、現在状態にあるすべての行は`0`この列にバルーンが含まれる状態は に変わります。`2`。 行はすでに状態にあります`2`行が状態にある間、そこに留まります`1`選択されたままになります。 
6. 次に、行がまだ選択されていない現在の列の各バルーンにダーツを投げることを考えます。 選択した行が状態に変わります`1`。 現在の列にある他のすべての風船はこのダーツによって吹き飛ばされるため、新しい状態は作成されません`2`義務。 
7. 選択された行数が超過する状態を拒否します`k`。 選択されたすべての行が 1 つのダーツに対応するため、そのような状態が答えに寄与することはありません。 
8. すべての列が処理された後、数字を含まない状態のみを保持します。`2`。 このような状態にはまだダーツを必要とする行がないため、すべてのバルーンは直接、または直接ポップされたバルーンと行または列を共有することによってクリアされます。 
9. 成功した各状態の DP 値を、状態の数によってインデックス付けされた回答に加算します。`1`数字。 選択された列は昇順に処理されるため、これにより、最大一致が 1 回ずつカウントされます。 
10. あらゆる人にとって`x`、正規一致の数に次の値を掛けます。`x!`。 乗算により、正規の列順序が、可能なすべての順序に変換されます。`x`ダーツを投げる。 

番号付きのステップの後、重要な不変条件は、最初のステップの処理後であることです。`j`列の状態は、どの行がすでに選択されているか、およびそれらの列でクリアされていないバルーンが見つかったためにどの行をまだ選択する必要があるかを正確に記録します。 遷移では、現在の列が選択されていない状態のままになり、まさに新しい義務が作成されるか、有効なバルーンを 1 つ選択してその列の残りの部分がすぐにクリアされます。 したがって、すべての DP パスは 1 つのマッチングに対応し、選択された列を左から右の順に考慮すると、すべてのマッチングには 1 つのパスが含まれます。 数字のない最終状態`2`はまさに最大のマッチングであり、まさにすべての風船を消すダーツのセットです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(m, n, k, grid):
    # We keep m as the smaller dimension.
    # The input already guarantees m <= 12 and n <= 20.
    #
    # For every column, mask bit r is set when grid[r][col] == 'Q'.
    columns = []
    for col in range(n):
        mask = 0
        for r in range(m):
            if grid[r][col] == 'Q':
                mask |= 1 << r
        columns.append(mask)

    states = 3 ** m

    pow3 = [1] * m
    for r in range(1, m):
        pow3[r] = pow3[r - 1] * 3

    # sum3[mask] = sum(pow3[r]) over all set bits r.
    # It lets us change all selected zero digits to digit 2 at once.
    sum3 = [0] * (1 << m)
    for mask in range(1, 1 << m):
        bit = mask & -mask
        r = bit.bit_length() - 1
        sum3[mask] = sum3[mask ^ bit] + pow3[r]

    # one[s]: rows whose ternary digit is 1.
    # two[s]: rows whose ternary digit is 2.
    # cnt[s]: number of digits equal to 1.
    #
    # Row 0 is the least significant ternary digit.
    one = [0] * states
    two = [0] * states
    cnt = [0] * states

    for s in range(1, states):
        q, d = divmod(s, 3)
        one[s] = (one[q] << 1) | (1 if d == 1 else 0)
        two[s] = (two[q] << 1) | (1 if d == 2 else 0)
        cnt[s] = cnt[q] + (1 if d == 1 else 0)

    dp = [0] * states
    dp[0] = 1

    full_rows = (1 << m) - 1

    for col_mask in columns:
        ndp = [0] * states

        for s in range(states):
            ways = dp[s]
            if ways == 0:
                continue

            used = cnt[s]
            if used > k:
                continue

            one_mask = one[s]
            two_mask = two[s]

            # Case 1: do not shoot this column.
            #
            # Every row containing a balloon in this column and currently
            # in state 0 becomes state 2.
            zero_rows = col_mask & ~(one_mask | two_mask) & full_rows
            base = s + 2 * sum3[zero_rows]

            ndp[base] += ways

            # Case 2: shoot one balloon in this column.
            #
            # A row already in state 1 cannot be shot again.
            # Starting from 'base', the chosen row would have digit 2,
            # but becomes digit 1, so subtract one power of 3.
            if used < k:
                available = col_mask & ~one_mask & full_rows

                while available:
                    bit = available & -available
                    ns = base - pow3[bit.bit_length() - 1]
                    ndp[ns] += ways
                    available ^= bit

        dp = ndp

    # Successful states have no digit 2.
    # Digit 1 counts directly popped rows, hence darts.
    ans = [0] * (min(k, m) + 1)

    for s in range(states):
        ways = dp[s]
        if ways and two[s] == 0:
            x = cnt[s]
            if 1 <= x <= k:
                ans[x] += ways

    # The DP stores each matching in increasing column order.
    # The actual darts may be thrown in any order.
    fact = 1
    result = []
    for x in range(1, k + 1):
        if x <= m:
            fact *= x
            result.append(str(ans[x] * fact))
        else:
            result.append("0")

    return "\n".join(result)

def solve(data):
    tokens = data.split()
    it = iter(tokens)

    t = int(next(it))
    out = []

    for _ in range(t):
        m = int(next(it))
        n = int(next(it))
        k = int(next(it))

        grid = [next(it).decode() if isinstance(next_val := next(it), bytes) else next_val
                for _ in range(m)]

        out.append(solve_case(m, n, k, grid))

    return "\n".join(out) + "\n"

def main():
    t = int(input())
    out = []

    for _ in range(t):
        m, n, k = map(int, input().split())
        grid = [input().strip() for _ in range(m)]
        out.append(solve_case(m, n, k, grid))

    sys.stdout.write("\n".join(out) + "\n")

if __name__ == "__main__":
    main()
```コア表現は 3 進整数です。 3 進数の最下位桁は行 0 に属しているため、行の状態を変更することは、3 の累乗を加算または減算するだけです。 配列`one`そして`two`3 進数を繰り返しデコードせずに、どの行が選択されているか、どの行にまだ未解決のバルーンがあるかをトランジションによって判断させます。`sum3`この状態空間では重要な小さな最適化です。 列がポップされていない場合、現在表示されていないバルーン行はすべて数字から変更されます。`0`数字に`2`。 各行を個別に変更する代わりに、コードはそのような行をすべて 1 つのビットマスクに収集し、対応する 3 の累乗を 2 倍に加算します。 

射撃のトランジションは特に注目に値します。 変数`base`現在の列がポップされなかった場合に何が起こるかを表します。 ダーツの位置として選択された行の場合、その行には数字が含まれます。`2`で`base`、しかしダーツはそれを数字に変えます`1`。 したがって、3 のべき乗 1 つを正確に減算すると、元の数字が`0`または`2`。 

数字の入った行`1`再度選択することはできません。 以前のダーツはその列のすべての風船をすでに削除しているため、そこに正規の風船が残ることはありません。 これが理由です`available`削除します`one_mask`。 

Python の整数には任意の精度がありますが、これはここで必要です。 有効なダーツ シーケンスの数は 64 ビット整数よりもはるかに大きくなる可能性があるため、一般的なモジュラー カウンティング問題とは異なり、法は適用されません。

 ## 特殊なケース

 空のグリッドの場合、次のような```
1
1 1 1
.
```初期状態`0`どの列マスクにもバルーン ビットがないため、すべての列が存続します。 これは有効なゼロダート状態ですが、出力ループは次から始まります。`x = 1`, そのため何も報告されません。 結果は`0`。 

以下を含む単一行の場合`QQQ`、```
1
1 3 3
QQQ
```民進党には三元国家が 3 つしかない。 1 列目、2 列目、または 3 列目を撮影すると、1 行が選択され、未解決の状態がない状態が作成されます。 これらは 3 つの異なるワンダーツ ポジションです。 最終的な答えは、`3, 0, 0`。 

斜めのバルーンの場合は、```
1
2 2 2
Q.
.Q
```最初のダーツはどちらかの斜めのバルーンを割ることができますが、そうした後、行も列もクリアされていないため、もう一方のバルーンは残ります。 したがって、DP は 2 ダーツの状態のみを成功として保持します。 ダーツのオーダーは 2 つあります。`2`。 

最も繊細な遷移は、列に複数のバルーンが含まれており、そのうちの 1 つが選択されたときに発生します。 現在の状態の行 1 に未解決のバルーンがあり、行 2 に関する以前の情報がない一方で、現在の列の両方の行にバルーンが含まれているとします。 行 1 を撮影すると、行 1 と列のバルーンがすぐに削除されます。 行 2 は、単に風船が存在していたというだけの理由で (その風船が吹き飛ばされただけなので) 未解決としてマークされてはなりません。 撮影の変遷`base - pow3[r]`まさにこの状況に対処します。 

いつ`k > m`、すべての答え`x > m`は必ずゼロになります。 直接割られた 2 つのバルーンが 1 つの行を共有することはできないため、最大でも`m`ダーツは有効な順序で使用できます。 実装でも正確に出力されます`k`行ですが、階乗 DP の結果は次の場合にのみ使用されます。`x <= m`; それより大きな値はすべてゼロとして出力されます。
