 ## 解決策
 ## 問題の理解

 1 から 9 までの数字を 1 回だけ含む 3 × 3 配列があります。 配列は、重なり合う 4 つの 2 × 2 ブロックに分割されます。```
1 23 4
```ブロック 1 は左上の 2 × 2 ブロック、ブロック 2 は右上、ブロック 3 は左下、ブロック 4 は右下です。 

次のようなコマンド`1C`ブロック 1 を時計回りに 90 度回転することを意味します。 次のようなコマンド`4R`ブロック 4 を反時計回りに 90 度回転させることを意味します。 選択した 2 × 2 ブロック内の 4 つのセルのみが移動します。 残りのセルはそのままの位置に残ります。 

各テスト ケースの入力により、回転数、最初の 3 × 3 配列、および正確な順序での回転が与えられます。 これらの回転をシミュレートし、結果の配列を出力する必要があります。 

制約は非常に小さいです。 テスト ケースは最大 100 個あり、各テスト ケースには最大 100 回のローテーションが含まれます。 ボードには 9 つのセルしかないため、1 回転あたり数回の一定量の作業でも十分に高速です。 グラフ アルゴリズム、検索、動的プログラミング、またはその他の漸近的に高度なテクニックは必要ありません。 

バグの主な原因はパフォーマンスではなくインデックス作成です。 2 × 2 回転では、4 つの特定のセルを正しい方向に移動する必要があり、4 つのブロックが重なり合います。 たとえば、ブロック 1 を時計回りに回転すると、```
123456789
```与える```
413526789
```なぜならブロックは```
1245
```になる```
4152
```不用意に実装すると、4 つの値が逆方向に回転する可能性があります。 もう 1 つの一般的なエラーは、ブロック 2、3、および 4 に間違った開始行または列を使用していることです。たとえば、ブロック 4 は、行 2、列 2 ではなく、ゼロベースのインデックスを使用して行 1、列 1 から始まります。 

有用な妥当性観察もあります。 公式入力には常にすべての数字が 1 回だけ含まれるため、手が有効な魔方陣を生成するかどうかを確認する必要はありません。 すべての操作は、既存の 9 つの値の単なる並べ替えです。 

## アプローチ

 最も文字通りのアプローチは、各コマンドを直接シミュレートすることです。 回転ごとに、新しい 3 × 3 配列を構築し、9 つのセルすべてを新しい位置にコピーできます。 ローテーションは最大 100 回であるため、テスト ケースごとに最大 900 個のセル割り当て、または 100 個のテスト ケース全体で最大 90,000 個の割り当てが実行されます。 それはすでに快適な制限内にあります。 

よりコンパクトな実装では、回転が正確に 4 つのセルに影響を与えることが観察されます。 選択した 2 × 2 ブロックが次から始まる場合`(r, c)`、その細胞は```
a bc d
```時計回りに回転すると、```
c ad b
```反時計回りに回転すると```
b da c
```したがって、コマンドごとに 4 つの位置を更新するだけで済みます。 問題の構造により、ボードのサイズが決して変化せず、移動の局所的な効果が固定されているため、これが可能になります。 

8 つの可能な手のすべての可能なシーケンスを列挙する仮説的な総当たり検索では、検査する必要があります。`8^n`シーケンス。 最大でも`n = 100`、つまり`8^100`、それは完全に不可能です。 一連の動きは入力によってすでに提供されているため、このような検索は不要です。 直接シミュレーションでは、指数関数的な分岐が完全に削除されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 可能なすべての移動シーケンスを列挙する | O(8^n) | シミュレートされた状態ごとに O(9) | 遅すぎる |
 | 移動するたびにボード全体を再構築する | O(9n) = O(n) | お(9) | 承認済み |
 | 影響を受ける 4 つのセルのみを回転します。 O(n) | お(9) | 承認済み |

 意図した実装では最後のアプローチが使用されます。 ボード サイズは固定されているため、受け入れられた両方のメソッドは事実上コマンドごとに一定の作業ですが、回転マッピングが正しく書き込まれれば、影響を受けるセルのみを更新する方が簡単になります。 

## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 すべてのテストケースについて、以下をお読みください。`n`現在の 3 × 3 ボードを表す 3 つの文字列。 各行を変更可能なリストとして保持すると、個々のセルの更新が便利になります。 
2. それぞれについて`n`コマンドでブロック番号と回転方向を読み取ります。 ブロック番号によって、影響を受ける 2 × 2 ブロックの左上隅が決まります。 
3. ブロック番号をゼロベースの座標にマッピングします。 ブロック 1 は次から始まります`(0, 0)`、ブロック 2 で`(0, 1)`、ブロック 3 で`(1, 0)`、ブロック 4 で`(1, 1)`。 
4. 選択したブロックから 4 つの値をローカル変数に読み取ります。 左上の座標が`(r, c)`、名前を付けます```
a = board[r][c]b = board[r][c+1]c = board[r+1][c]d = board[r+1][c+1]
```一時変数を使用すると、ボード上で直接割り当てを実行するより安全です。これは、初期の割り当てによって、後の割り当てでまだ必要な値が上書きされる可能性があるためです。 
5. コマンドが次で終わる場合`C`、時計回りの変換に従って値を割り当てます。```
a b    c ac d -> d b
```6. それ以外の場合、コマンドは次のように終了します。`R`なので、反時計回りの変換に従って割り当てます。```
a b    b dc d -> a c
```7. すべての回転が処理された後、結果として得られるボードの 3 行を印刷します。 

### なぜ効果があるのか

 不変条件は、すべてのコマンドを処理する直前に、`board`は、以前に処理されたすべてのコマンドを元の正方形に適用することによって得られる正方形です。 コマンドは、4 つの可能な 2 × 2 ブロックの 1 つを選択し、その 4 つの現在の値を読み取り、対応する 90 度の回転によって生成された値と正確に置き換えます。 他のすべてのセルは変更されません。 したがって、不変条件はすべてのコマンドの後でも true のままです。 最後のコマンドの後、ボードはまさに必要な最終状態になります。 

## Python ソリューション```python
Pythonimport sysinput = sys.stdin.readline

def rotate(board, block, direction):    # Zero-based top-left corner of each 2 x 2 block.    positions = {        1: (0, 0),        2: (0, 1),        3: (1, 0),        4: (1, 1),    }
    r, c = positions[block]
    a = board[r][c]    b = board[r][c + 1]    d = board[r + 1][c + 1]    e = board[r + 1][c]
    if direction == 'C':        # a b      e a        # e d  ->  d b        board[r][c] = e        board[r][c + 1] = a        board[r + 1][c] = d        board[r + 1][c + 1] = b    else:        # a b      b d        # e d  ->  a e        board[r][c] = b        board[r][c + 1] = d        board[r + 1][c] = a        board[r + 1][c + 1] = e

def solve():    t = int(input())    output = []
    for _ in range(t):        n = int(input())        board = [list(input().strip()) for _ in range(3)]
        for _ in range(n):            command = input().strip()            block = int(command[0])            direction = command[1]
            rotate(board, block, direction)
        for row in board:            output.append(''.join(row))
    sys.stdout.write('\n'.join(output))

if __name__ == "__main__":    solve()
```の`positions`辞書は、重なり合う 4 つのブロックのジオメトリをエンコードします。 ゼロベースのインデックスを使用すると、考えられる 4 つの左上隅は正確に次のようになります。`(0, 0)`、`(0, 1)`、`(1, 0)`、 そして`(1, 1)`。 

一時変数には、割り当てが行われる前の元の 4 つの値が保持されます。 これにより、1 つの宛先を書き込むと別の宛先に必要な値が破壊されるという古典的なローテーションのバグが回避されます。 

時計回りの割り当ては、```
old bottom-left -> new top-leftold top-left    -> new top-rightold bottom-right -> new bottom-leftold top-right   -> new bottom-right
```反時計回りの割り当てでは、そのサイクルが逆になります。 コマンドは順番に処理されるため、各回転は前の回転によって生成されたボード上で動作します。 

アルゴリズムには整数演算がないため、オーバーフローは発生しません。 唯一のインデックス作成操作で使用されるのは、`r`、`r + 1`、`c`、 そして`c + 1`; 選択されたすべてのブロックは行と列 0 または 1 から始まるため、これらのインデックスは常に 3 × 3 ボード内に留まります。 

ソリューションは出力を蓄積します。`output`最後に一度書きます。 これは、このような小さな入力には必要ありませんが、I/O をシンプルかつ効率的に保ちます。
