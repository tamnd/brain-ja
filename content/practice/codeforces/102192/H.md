 ## 解決策
 ## 問題の理解

 2 つの空でない文字列が、再帰的に定義された k 類似度の概念に基づいて同じ同値クラスに属するかどうかを判断する必要があります。 関係は、それ自体に似ている文字列から始まります。 k に直接依存する唯一のルールは、2 つの空でない文字列 S と T は、その全長が最大でも k であり、連結 ST と TS が類似していることがすでにわかっている場合に関連する可能性があることを示しています。 同様の部分文字列は、より大きな文字列内で置き換えることができ、推移性により置換を連鎖させることができます。 

定義を再帰的な文字列比較として考えるのではなく、書き換えシステムとして考えると便利です。 ルール 2 は、基本的な置換ルールの小さなコレクションを作成します。一方、ルール 3 と 4 は、これらの置換をどこにでも、任意の順序で適用できることを示しています。 全体の問題は、これらの基本的なルールが k の考えられる値ごとにどのようなものかを理解することです。 

すべての入力文字列の合計の長さは最大 300 万ですが、1 つの個別の文字列には 200,000 文字を含めることができます。 これにより、文字列の大きな状態空間を探索するアルゴリズムは即座に除外され、O(n log n) の解であっても、構造を少数のケースに減らすことができれば、必要以上に機械的になるでしょう。 テスト ケースごとの線形スキャンは問題なく制限内に収まりますが、二次関数では最大サイズのテスト ケースで約 4 × 10^10 文字の演算が必要になる可能性があります。 

一見合理的に見える実装が間違った答えを与えるというエッジケースがいくつかあります。 たとえば、k = 2 の場合、入力```
2
ab
ab
```答えがあります`yes`、 その間```
2
a
aa
```答えがあります`no`。 全長が k 以下の部分文字列を比較する機能を文字の削除または複製の許可として扱う不注意な実装では、2 番目のケースが誤って受け入れられてしまいます。 k = 2 の場合、唯一の自明でないルールは次の形式になります。`a -> a`, したがって、実際には何も変更できません。 

k = 4 と k = 5 の間の境界は別の罠です。 考慮する```
4
abcba
aba
```答えは`no`。 k = 4 の縮小は崩壊しない`abcba`～と同じ正規形に`aba`。 ただし、k = 5 の場合、```
5
abcba
aba
```答えがあります`yes`なぜなら、k が 5 に達すると、関係は最初と最後の文字によって完全に特徴づけられるようになるからです。 すべての k >= 4 を同様に扱うと、この区別が失われます。 

3 番目のよくある間違いは、最初と最後の文字だけを使用するのが早すぎることです。 のために```
3
aab
ab
```答えは`yes`なぜなら、同じ文字の連続したコピーを挿入または削除できるからです。 しかし、```
4
abca
aba
```答えは`no`両方の文字列が同じ文字で始まり、終わる場合でも。 終点条件は k = 5 以降でのみ十分になります。 

これらの分類とその通常の形式は、コンテストの公式論説にも記載されています。 

## アプローチ

 直接的なアプローチでは、文字通り定義に従おうとします。 既知の類似した文字列のペアをすべて書き換えルールとみなして、A から到達可能なすべての文字列を生成し、B が出現したときに停止することができます。 ルール 3 と 4 は、k 類似性がルール 2 によって生成された置換の再帰的、対称的、推移的閉包であると正確に述べているため、これは概念的に正しいです。 

問題は可能な状態の数です。 長さが最大 n の文字列に限定しても、次のようなものがあります。 

[
 \sum_{i=1}^{n} 26^i = \frac{26^{n+1}-26}{25}
 】

 小文字の文字列も可能です。 n = 200000 の場合、これは天文学的に大きくなります。 再帰的検索では、異なる置換シーケンスを通じて同じ同値クラスを再訪することもできるため、メモ化によってこのアプローチが解決されるわけではありません。 ブルート フォースは、小さな文字列の構造を発見する場合にのみ役立ちます。 

重要な観察は、ルール 2 が k が重要となる唯一の場所であるということです。 ルール 2 によって生成された基本ルールがわかったら、残りのルールは単純に、それらの置換をより大きな文字列内で使用できるようにします。 公式分析では、最初に 2 つの k 類似文字列が同じ最初の文字と同じ最後の文字を持たなければならないことを観察し、次に k に従って有用な置換ルールを分類します。 

k = 1 および k = 2 の場合、有用な変更は不可能であるため、文字列は文字通り等しい必要があります。 k = 3 の場合、有用なルールは次のとおりです。`a -> aa`そして`aa -> a`、キャラクターごとに独立して。 したがって、1 つの文字のすべての最大ランを 1 つのコピーで置き換えることができ、一意の縮小文字列が得られます。 

k = 4 の場合、以下に対応する追加のルールがあります。`a -> aba`そしてその逆。 最初に連続する重複を削除した後、これらのルールはリダクションによって表すことができます。`aba -> a`。 スタックはまさに​​この削減を行います。新しい文字が最上位の 2 つ下の文字と等しい場合、最上位の文字を削除できます。 結果として得られるスタックは、同値クラスの正規形式です。 

k = 5 では、新しく利用可能なルールにより、任意の文字列を 2 つのエンドポイント文字に減らすことができます。 k = 5 で現れる追加のルール自体は k = 4 のルールから取得できるため、この時点からは新しい不変式は必要ありません。 最初と最後の文字は両方とも必要かつ十分です。 同じ分類は、すべての k > 5 に対して引き続き有効です。 

これにより、文字列の検索ではなく、一定数の線形スキャンが行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合の O(26^n) 状態 | O(26^n) | 遅すぎる |
 | 最適 | O( | A | + | B | ) | O( | A | + | B | ) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. k、A、B を読み取ります。k が 1 または 2 の場合、2 つの文字列を直接比較します。 このような場合、どちらの文字列も変更できる有用な置換はありません。 
2. k が 3 の場合、等しい文字の最大ランをすべて 1 文字に圧縮します。 例えば、`aaabbccca`になる`abca`。 2 つの圧縮文字列を比較します。 これが機能するのは、実行に 1 つのコピーを追加または削除することしか有用な操作がないためです。 
3. k が 4 の場合、最初に同じ連続重複圧縮を実行します。 次に、結果の文字列をスタックでスキャンします。 各文字 c について、次の文字と比較します。`stack[-2]`その立場が存在するとき。 それらが等しい場合は、c を押す代わりに現在のスタックトップを削除します。 それ以外の場合は、c を押します。 
4. 同じ k = 4 リダクションを両方の文字列に適用し、結果のスタックを比較します。 スタックが等しいということは、利用可能な k = 4 の置換によって 2 つの文字列を相互に変換できることを意味します。 
5. k が少なくとも 5 の場合、A と B の最初と最後の文字のみを比較します。両方のエンドポイントが一致する場合、それらは正確に k 類似しています。 
6. 出力`yes`対応する標準形式が一致する場合、および`no`さもないと。 

これが機能する理由: 不変式は、アルゴリズムで使用される各変換がルール 2 によって生成された同値クラスを正確に保持するためです。k = 3 の場合、不変式は個別の実行のシーケンスです。 k = 4 の場合、スタック削減は、k = 3 で既に利用可能なルールを含め、すべての基本置換によって変更されないため、同じ同値クラス内の 2 つの文字列は同じスタック結果になります。 逆に、スタックによって実行されるすべてのリダクションは有効な k = 4 置換に対応するため、有効な置換を通じて等しいスタック結果を結び付けることができます。 k >= 5 の場合、基本規則により、端点を保持したまま文字列のすべての内部部分を削除でき、端点のペアが完全な不変条件になります。 最初と最後の文字自体はすべてのルールによって保持されるため、異なるエンドポイントが同等になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def compress_runs(s):
    res = []
    for c in s:
        if not res or res[-1] != c:
            res.append(c)
    return res

def reduce_k4(s):
    stack = []
    for c in s:
        if stack and stack[-1] == c:
            continue

        if len(stack) >= 2 and stack[-2] == c:
            stack.pop()
        else:
            stack.append(c)

    return stack

def similar(k, a, b):
    if k <= 2:
        return a == b

    if k == 3:
        return compress_runs(a) == compress_runs(b)

    if k == 4:
        return reduce_k4(a) == reduce_k4(b)

    return a[0] == b[0] and a[-1] == b[-1]

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        k = int(input())
        a = input().strip()
        b = input().strip()

        ans.append("yes" if similar(k, a, b) else "no")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`similar`関数は 4 つの構造ケースを直接実装します。 k が 1、2、3、4、または少なくとも 5 であるかどうかを超えて、k を検査する必要はありません。`compress_runs`リストを個別の連続文字のスタックとして使用します。 文字は前の文字と異なる場合にのみ追加されるため、次のような実行`aaaa`ちょうど 1 つ貢献します`a`。`reduce_k4`わずかに微妙な実装のみが含まれています。 最初`if`は、連続する等しい文字を処理します。k = 4 の場合、k = 3 のルールが使用できるため、すでに削除可能です。2 番目の条件は、新しい文字が先頭の 2 つ下の文字と一致するかどうかをチェックします。 この場合、先頭の文字は文字列の中央を表します。`aba`パターンを削除することができます。 

これら 2 つの条件の順序が重要です。 k = 3 のリダクションがすでに組み込まれた後に k = 4 の正規形が定義されているため、連続する重複はツーバック文字をチェックする前に無視する必要があります。 

このアルゴリズムでは文字とインデックスのみが保存されるため、整数オーバーフローの懸念はありません。 入力文字列自体がメモリ使用量の大部分を占め、合計入力サイズは 300 万文字に制限されます。
