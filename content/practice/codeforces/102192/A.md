 ## 解決策
 ## 問題の理解

 長さの言葉`m`の配列で表すことができます`m`エンコードされた文字値。 すべての位置が独立して次から整数を選択します`0`を通して`n - 1`。 合計が正確に得られる配列がいくつあるかを数える必要があります。`k`。 

たとえば、`n = 2`そして`m = 3`、すべての位置に次のいずれかが含まれます`0`または`1`。 言葉`[0, 1, 1]`合計があります`2`、 その間`[1, 1, 1]`合計があります`3`。 文字の選択肢は順序付けされているため、異なる配列は異なる単語を表します。 

答えはモジュロで計算されます`998244353`有効な配列の数が非常に多くなる可能性があるためです。 

この境界により、すべてのテスト ケースの語長と目標合計の両方にわたって通常の動的プログラミングが除外されます。 DP と`O(mk)`操作には約`10^10`両方の場合の 1 つのテスト ケースの操作`m`そして`k`は`10^5`。 総計の境界。すべての合計が`n`、`m`、 そして`k`それぞれせいぜい`5 * 10^6`、アルゴリズムがほぼ線形であることを示唆しています。`m + k`テストケースごと、またはそれ以上のものが必要です。 以来`k <= 10^5`、階乗および逆階乗もグローバルに事前計算できるため、二項係数を一定時間で評価できます。 

直接実装では誤って処理される可能性のある境界ケースがいくつかあります。 と`n = 1`、すべての文字には値が必要です`0`、入力のために`1 5 0`答えは`1`、 その間`1 5 1`答えがあります`0`。 からのすべての値を仮定する数式`0`に`n - 1`少なくとも 2 つの選択肢を与えると、このケースが間違ってしまう可能性があります。 

可能な最大合計は`m(n - 1)`。 したがって`2 3 3`答えがあります`1`、唯一の配列があるため、`[1,1,1]`、 その間`2 3 4`答えがあります`0`。 かどうかだけをチェックする実装`k`非負であると、誤って不可能な合計を数えてしまう可能性があります。 

下限も同様に動作します。 有効なすべての`n`そして`m`、合計を含む唯一の配列`0`は`[0,0,...,0]`。 したがって、`5 4 0`答えがあります`1`。 これは、二項係数式におけるオフバイワン誤差のテストにも役立ちます。 

## アプローチ

 ブルートフォース手法では、考えられるすべての単語を直接列挙します。 それぞれの`m`ポジションは`n`選択肢があるので、`n^m`検査する配列。 すべての配列について、その合計を計算できます。`O(m)`時間、与えること`O(m n^m)`仕事。 合計が増分的に維持される場合でも、列挙自体には依然としてコストがかかります`O(n^m)`。 のために`n = m = 10^5`、これは単に遅すぎるだけでなく、実際の操作数を天文学的に超えています。 

標準の動的プログラミング公式の方がはるかに優れています。 させて`dp[i][s]`長さの数値になります-`i`合計を含む配列`s`。 文字を 1 つ追加すると、`dp[i][s] = dp[i-1][s] + dp[i-1][s-1] + ... + dp[i-1][s-(n-1)]`。 

スライディング ウィンドウを使用すると、各遷移を次のように減らすことができます。`O(1)`、DP全体を作成します`O(mk)`。 これはすでに大幅な改善ですが、最悪の場合でもまだ約`10^10`操作なので適合しません。 

重要な観察は、すべての位置の選択肢が区間内の整数とまったく同じであるということです。`[0,n-1]`。 上限がない場合、非負の解の数は`x1 + x2 + ... + xm = k`は星と棒の値です`C(k + m - 1, m - 1)`。 

上限`xi <= n-1`包含排他で扱うことができます。 選択したセットについては、`j`上限に違反する位置を減算します`n`それぞれから。 元の値が少なくとも`n`、 書く`xi = yi + n`、 どこ`yi >= 0`。 残りの変数は制限のない非負の整数であり、それらの新しい合計は次のようになります。`k - jn`。 

がある`C(m,j)`違反している位置を選択する方法、および減算後の非負の解の数`n`は`C(k - jn + m - 1, m - 1)`。 

したがって、答えは次のようになります。`sum (-1)^j C(m,j) C(k - jn + m - 1, m - 1)`全体`j`誰のために`jn <= k`。 との規約`j > m`以上のものを選択できないため、存在しません。`m`立場に違反している。 

ブルート フォースはすべての有効な配列を個別に考慮するため機能しますが、配列の数が指数関数的なため失敗します。 DP は部分和によって配列をグループ化しますが、それでも処理する状態が多すぎます。 包含/除外観察では、どの位置が許容値を超えているかに応じてすべての配列がグループ化され、計算が最大で次のように削減されます。`min(m, floor(k/n)) + 1`二項項。

 | ブルートフォース |`O(n^m)`または`O(m n^m)`明示的な合計計算を使用する |`O(m)`| 遅すぎる |

 | 包含-除外 |`O(min(m, k/n))`前処理後のテスト ケースごと |`O(max(m+k))`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのテスト ケースを読み取り、次の最大値を決定します。`m + k`それが必要になるでしょう。 この最大値まで階乗および逆階乗を事前計算します。 すべての項には二項係数が含まれるため、これらの配列が必要です。 
2. 式を適用する前に、`k > m(n-1)`。 すべての文字に値がある場合、可能な最大の合計が得られます。`n-1`したがって、そのようなターゲットには有効な単語がなく、答えはすぐに返されます。`0`。 
3. 残りのケースについては、答えを次のように初期化します。`j = 0`包含-除外用語、`C(k + m - 1, m - 1)`。 

これは、すべての非負の配列を合計でカウントします。`k`、上限を強制することなく。 
4. のために`j = 1, 2, ...`、いずれかの場合に停止します`j > m`または`jn > k`。 それぞれの有効な`j`、計算します`C(m,j) * C(k - jn + m - 1, m - 1)`。 

最初の要素はどちらを選択しますか`j`位置が上限を超えています。 2 番目の要素は、減算後の割り当てをカウントします。`n`選択した各位置から。 
5. 「とき」という用語を追加します。`j`が偶数で、次の場合はそれを減算します。`j`奇数です。 これは、選択された違反位置の数に対応する包含/除外記号です。 
6.実行中の応答モジュロを小さくします`998244353`各操作の後。 最後に正規化された結果を出力します。 

二項係数は次を使用して計算されます。`C(a,b) = fact[a] * invfact[b] * invfact[a-b] mod MOD`。 

階乗は 1 回計算され、逆階乗は 1 つの逆モジュラーとその後の後方再帰から取得されます。 

### なぜ効果があるのか

 長さが負でないすべての整数配列のセットを考慮します。`m`合計は誰の`k`。 スターとバーはこのセットを数えます`C(k+m-1,m-1)`。 少なくとも次の値を持つ 1 つ以上の位置を含む配列を削除する必要があります。`n`。 

選択した任意のセットに対して、`j`違反ポジション、減算`n`選択した各値から。 これにより、合計が次のような非負の配列を持つ全単射が作成されます。`k-jn`。 がある`C(k-jn+m-1,m-1)`そのような配列があり、`C(m,j)`選択したポジションの選択肢。 

包含-除外では、偶数の違反を含むセットを追加し、奇数の違反を含むセットを減算します。 すべての無効な配列`r`ポジション違反が寄与する`C(r,0) - C(r,1) + C(r,2) - ... + (-1)^r C(r,r) = 0`、

 一方、すべての有効な配列には違反はなく、寄与するのは 1 回だけです。 したがって、最終的な合計では有効な単語が正確にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    tests = [tuple(map(int, input().split())) for _ in range(t)]

    max_size = 0
    for n, m, k in tests:
        max_size = max(max_size, m + k)

    fact = [1] * (max_size + 1)
    for i in range(1, max_size + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (max_size + 1)
    invfact[max_size] = pow(fact[max_size], MOD - 2, MOD)
    for i in range(max_size, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def comb(a, b):
        if b < 0 or b > a or a < 0:
            return 0
        return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

    out = []

    for n, m, k in tests:
        if k > m * (n - 1):
            out.append("0")
            continue

        if k == 0:
            out.append("1")
            continue

        ans = 0
        max_j = min(m, k // n)

        for j in range(max_j + 1):
            remaining = k - j * n
            ways = comb(m, j) * comb(
                remaining + m - 1, m - 1
            ) % MOD

            if j & 1:
                ans -= ways
            else:
                ans += ways

        out.append(str(ans % MOD))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```テスト ケースの最初のパスでは、必要となる最大の階乗インデックスが見つかります。 最大の二項引数は次のとおりです。`k + m - 1`したがって、階乗を割り当てると、`m + k`これで十分であり、テストケースごとに個別に割り当てる必要がなくなります。 

の`comb`関数は無効な引数に対してゼロを返します。 メインループでは、その引数は常に有効です。`remaining = k - jn`は負ではありませんが、境界チェックを維持するとヘルパーが安全になり、微妙な負のインデックス動作が防止されます。 

可能な最大合計チェックは、包含/排他ループの前に実行されます。 これにより、不必要な作業が回避され、不可能なターゲットが直接処理されます。 

ループには以下が含まれます`j = 0`。 その用語は、無制限のスターとバーの数です。 ループ制限は`min(m, k // n)`、以上のものを選択しているため、`m`ポジションを選択することは不可能です`j`ポジションには少なくとも`jn`合計額。 

Python の整数はオーバーフローしませんが、すべての乗算結果は剰余化されます。`MOD`。 これにより、中間値が小さく保たれ、必要な演算が一致します。 

逆階乗配列は 1 つのべき乗剰余演算から生成されます。 以来`998244353`が素数である場合、フェルマーの小定理は次のようになります`fact[max_size]^(MOD-2)`そのモジュラーの逆として。 より小さな逆階乗ごとに次の結果が得られます。`invfact[i-1] = invfact[i] * i`。

 ## 特殊なケース

 いつ`n = 1`、すべての文字に値を付けることが強制されます。`0`。 のために`1 5 0`、可能な最大合計は`5(1-1)=0`したがって、ターゲットは実行可能であり、唯一の配列は`[0,0,0,0,0]`。 アルゴリズムは戻ります`1`。 のために`1 5 1`、目標が最大合計を超えています`0`、したがって、それは返されます`0`すぐに。 これにより、包含/排他ループが存在しない正の文字値に依存することがなくなります。 

正確に最大値を目標とする場合は、次のことを考慮してください。`2 3 3`。 各ポジションは最大で`1`、合計に達します`3`力`[1,1,1]`。 式は次のようになります`C(5,2) - C(3,1)C(2,2) = 10 - 9 = 1`。 境界は正しくカウントされます。`j = 1`修正は、少なくとも値を含むすべての無制限の解を削除します。`2`。 

最大値を超える目標の場合、`2 3 4`可能な最大の合計がある`3`。 アルゴリズムが検出するのは、`4 > 3`そして戻ってきます`0`二項係数を評価せずに。 この境界を明示的に考慮していない DP または包含/除外の実装では、かなりの作業が無駄になる可能性があり、負の剰余が誤って処理された数式によって無効なカウントが生成される可能性があります。 

ゼロ目標については、次のことを考慮してください。`5 4 0`。 すべての文字値は負ではないため、ゼロの合計はすべての値を強制的にゼロにします。 の`j = 0`期間は`C(3,3)=1`、 そして`k // n = 0`, したがって、修正条項はありません。 答えはまさに`1`。 

上限修正が明らかになる小規模なケースについては、次のことを考慮してください。`3 2 2`。 制限なしで`xi <= 2`、 がある`C(3,1)=3`解決策:`[0,2]`、`[1,1]`、 そして`[2,0]`、それらはすべてすでに有効です。 包含-排他ループには、`j = 0`そして`j = 1`、しかし、`j = 1`の場合、残りの合計は負になります。`k-n = -1`、 それで`j=1`全く届いていない。 結果は残る`3`。 これにより、ループ条件が成立することが確認されます。`j <= k/n`無効な負の残余合計が導入される前に正しく停止します。
