 ## 問題の理解

 リンゴの高さを左から右にスキャンします。 常に最初のリンゴが選ばれます。 その後、リンゴの高さが最後に摘んだリンゴの高さよりも厳密に大きい場合にのみ、リンゴが摘み取られます。 したがって、選択された高さは、厳密に増加するプレフィックス最大値のシーケンスを形成します。 

各クエリは独立しています。 ちょうど 1 つの位置が変わります`p`元の高さから`h[p]`に`q`、次に、結果の配列内でリンゴがいくつ選択されるかを尋ねます。 元の配列は、次のクエリの前に復元されます。 問題と公式のコンテストの解決策では、これを、変更された位置の両側で必要な情報を維持することとして説明しています。 

の値`n`そして`m`どちらも到達できる`100000`、最大 10 個のテスト ケースを含めることができます。 すべてのクエリを直接シミュレーションするには、最大で`10^10`すべてのクエリがほぼ配列全体をスキャンする場合、1 つのテスト ケースで配列検査を実行します。 これは 2 秒の制限がサポートできる範囲をはるかに超えています。 線形またはに近い前処理が必要です。`O(n log n)`、クエリごとにほぼ対数の作業が続きます。 

最初の微妙なケースは、置換値が、位置の前にすでに確認されている最適な高さより大きくない場合です。`p`。 たとえば、次のように考えてみましょう```

2 3
```変更された配列は`[1, 3, 6]`、したがって、答えは次のとおりです`3`。 不注意な解決策では、明示的に変更されたため、変更されたリンゴが常にカウントされる可能性がありますが、`3`以前選択した高さより高くありません`1`この例では、実際にそうなっているので、それが選択されます。 さらに明らかなケースは、```
1
3 1
1 5 6
2 1
```変更された配列は`[1, 1, 6]`、そして答えは`2`。 リンゴの位置`2`は以前に選択した高さに等しいため、厳密な比較では拒否されます。 条件を次のように扱う`>=`誤って生成してしまう`3`。 

2 番目の微妙なケースは、変更されたリンゴが新しいレコードになる場合です。 考慮する```

1 2 3 4

```答えは`1`、配列は次のようになるため、`[5, 2, 3]`。 左側のプレフィックスがまったくないため、置換値自体が初期しきい値となります。 位置情報にアクセスする実装`p - 1`扱わずに`p = 1`個別に無効な結果が生成される可能性があります。

## アプローチ

 ブルート フォース ソリューションは、概念的に元の配列をコピーし、置き換えるだけです。`h[p]`による`q`、すべてをスキャンします`n`ポジション。 スキャン中、最後に摘んだリンゴの高さを維持し、現在の高さが厳密に大きくなるたびに答えを増分します。 これはまさにピッキングルールなので、方法は正しいです。 

問題はそのコストです。 1 つのクエリにかかる時間`O(n)`時間と`m`クエリにかかる`O(nm)`。 と`n = m = 100000`、最悪の場合は約`10^10`要素検査。 Python のオーバーヘッドを考慮する前でさえ、これは数桁大きすぎます。 

スキャンの状態は、これまでに抽出された最大の高さという 1 つの数値のみであるため、総当たり法が機能します。 有益な観察は、位置を変えることです。`p`以前の決定に影響を与えることはできません`p`。 サフィックスが認識するしきい値のみが変更されます。 

プレフィックスについては`[1, p-1]`、リンゴが何個摘まれるか、摘まれる最大の高さはどれくらいかを事前に計算できます。 その後は 2 つのケースのみが存在します。 もし`q`プレフィックスの最大値、位置を超えていない`p`はスキップされ、サフィックスは古いプレフィックスの最大値を継続します。 もし`q`プレフィックスの最大値、位置より大きいです`p`が選択され、サフィックスが続きます`q`その閾値として。 

残る操作は 1 つです: で始まるサフィックスを指定します。`l`そして閾値`x`、高さが厳密に次より大きい最初の要素を見つけます。`x`。 その要素が見つかると、残りの回答を前処理から再利用できます。 

その再利用を可能にするには、次のように計算します。`nxt[i]`、右の最初の位置`i`身長が厳密により大きいのは`h[i]`。 そのような立場が存在しない場合、`nxt[i]`はゼロです。 させて`dp[i]`スキャン時に選択したリンゴの数になります。`i`そして治療する`h[i]`現在の最初のしきい値として。 それから`dp[i] = 1 + dp[nxt[i]]`いつ`nxt[i]`存在し、そして`dp[i] = 1`さもないと。 の`nxt`配列は、減少する単調スタックを使用して線形時間で構築できます。 

残りの上位検索は、各間隔の最大高さを格納するセグメント ツリーによって処理できます。 クエリ位置から開始して、ツリーは最大値がしきい値を超えないすべての間隔を破棄できます。 間隔に有効な位置を含めることができる場合は、最初のそのような位置が必要であるため、最初にその左の子に向かって下降します。 これにはかかります`O(log n)`時間。 

これにより、線形の前処理フェーズと対数的なクエリ時間が得られます。

 ## アルゴリズムのチュートリアル

 1. 事前計算`prefix_count[i]`、元の接頭辞で選ばれたリンゴの数`[1, i]`、 そして`prefix_max[i]`、そのプレフィックス内で選択された最大の高さ。 左から右にスキャンしているときに、リンゴの高さが現在の最大値よりも大きい場合に正確に寄与します。 これら 2 つの配列は、前の部分からクエリに必要なすべてを完全に記述します。`p`。 
2. コンピューティング`nxt[i]`単調なスタックで。 右から左に位置をスキャンします。 スタックトップの高さが以下である間、`h[i]`、その位置が位置の厳密に上位の最初のリンゴになることは決してないので、それを削除します。`i`。 残りの上部は右の最初の位置であり、高さは厳密に次の値よりも大きくなります。`h[i]`。 
3. コンピューティング`dp[i]`右から左へ。 もし`nxt[i]`がゼロの場合`i`はこのチェーンで最後に選ばれたリンゴであり、`dp[i] = 1`。 それ以外の場合は、ピッキング後`i`、次に摘んだリンゴはまさに`nxt[i]`、 それで`dp[i] = 1 + dp[nxt[i]]`。 
4. 元の高さに基づいてセグメント ツリーを構築し、各ノードの間隔の最大値を保存します。 その目的は、リンゴを直接数えることではありません。 これにより、高さが指定されたしきい値より厳密に大きい、指定されたインデックス以降の最初の位置を見つけることができます。 
5. お問い合わせの場合`(p, q)`、まず次の情報を取得します。`[1, p-1]`。 もし`p = 1`、このプレフィックスは空であるため、考えられるすべての高さよりも小さいしきい値と、選択されたカウントとしてゼロを使用します。 さもないと、`prefix_count[p-1]`はすでに選択されている番号であり、`prefix_max[p-1]`は現在のしきい値です。 
6. 比較する`q`そのプレフィックスを最大値にします。 もし`q`より大きい、位置`p`が選択されるので、回答をインクリメントし、サフィックスのしきい値を に設定します。`q`。 もし`q`より小さいか等しい、位置`p`はスキップされ、サフィックスしきい値はプレフィックスの最大値のままになります。 
7. セグメントツリーで最初の位置を検索します。`i > p`と`h[i] > threshold`。 そのようなポジションがない場合、サフィックスの寄与はありません。 それ以外の場合、その位置は、変更された位置の後に選択された最初のリンゴとなり、残りの完全な寄与は次のようになります。`dp[i]`。 
8. 接頭辞の寄与、位置の寄与の可能性を追加します。`p`、およびサフィックスの貢献。 クエリは独立しているため、元の配列が変更されることはありません。 

### なぜ効果があるのか

 重要な不変点は、プレフィックスをスキャンした後、残りの位置に関連する情報は最後に摘んだリンゴの高さだけであるということです。 位置でのクエリの場合`p`、元のプレフィックスは変更されていないため、選択された数と最後に選択された高さはすでにわかっています。 変更された位置は、新しく選択された最大値になるか、その最大値が変更されないままになります。 接尾辞が始まると、最初に選ばれたリンゴは、厳密にこのしきい値より大きい最初の要素でなければなりません。 最初の要素が選択された後のプロセスは、次で表されるプロセスとまったく同じになります。`dp[i]`。 したがって、答えに寄与するすべてのリンゴは 1 回カウントされ、選択できないすべてのリンゴは除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())
        h = [0] + list(map(int, input().split()))

        # prefix_count[i] = number of picked apples in [1, i]
        # prefix_max[i] = last picked height in [1, i]
        prefix_count = [0] * (n + 1)
        prefix_max = [0] * (n + 1)

        cur_max = 0
        cur_count = 0

        for i in range(1, n + 1):
            if h[i] > cur_max:
                cur_max = h[i]
                cur_count += 1
            prefix_max[i] = cur_max
            prefix_count[i] = cur_count

        # nxt[i] = first j > i with h[j] > h[i]
        nxt = [0] * (n + 1)
        stack = []

        for i in range(n, 0, -1):
            while stack and h[stack[-1]] <= h[i]:
                stack.pop()

            if stack:
                nxt[i] = stack[-1]

            stack.append(i)

        # dp[i] = number of picked apples in the chain
        # starting by picking position i.
        dp = [0] * (n + 1)

        for i in range(n, 0, -1):
            if nxt[i] == 0:
                dp[i] = 1
            else:
                dp[i] = dp[nxt[i]] + 1

        # Segment tree for range maximum.
        size = 1
        while size < n:
            size <<= 1

        seg = [0] * (2 * size)

        for i in range(1, n + 1):
            seg[size + i - 1] = h[i]

        for i in range(size - 1, 0, -1):
            seg[i] = max(seg[i << 1], seg[i << 1 | 1])

        def first_greater(left, value):
            """First index >= left with h[index] > value, or 0."""
            if left > n:
                return 0

            def search(node, nl, nr):
                if nr < left or seg[node] <= value:
                    return 0

                if nl == nr:
                    return nl

                mid = (nl + nr) >> 1

                res = search(node << 1, nl, mid)
                if res:
                    return res

                return search(node << 1 | 1, mid + 1, nr)

            return search(1, 1, size)

        out = []

        for _ in range(m):
            p, q = map(int, input().split())

            if p == 1:
                answer = 0
                threshold = 0
            else:
                answer = prefix_count[p - 1]
                threshold = prefix_max[p - 1]

            if q > threshold:
                answer += 1
                threshold = q

            first = first_greater(p + 1, threshold)

            if first:
                answer += dp[first]

            out.append(str(answer))

        sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```プレフィックスの前処理は、クエリ分解の最初の部分に直接対応します。`prefix_count`すでに選択されているリンゴの数を記録します。`prefix_max`変更された位置に渡されたしきい値とそのサフィックスを記録します。 

単調スタックは計算します`nxt`線形時間で。 比較には、`<=`、 ない`<`、ルールでは次のリンゴが厳密に高いことが求められているためです。 同じ高さのリンゴが次に摘まれることはありません。 

の`dp`再発は右から左に評価されます。`dp[i]`に依存します`dp[nxt[i]]`、 そして`nxt[i]`は常により大きいです`i`。 すべての値は最大でも`n`したがって、通常の Python 整数で十分です。 

セグメント ツリーには、1 から始まる配列位置でインデックスが付けられます。`first_greater(left, value)`以下のインデックスを意図的に検索します。`left`、クエリは合格します`p + 1`また、変更された位置自体を誤って考慮することはありません。 

検索では、最初に左側の子がチェックされます。 いくつかの要素がしきい値を超える可能性があるが、必要な要素は最初の要素であるため、この順序付けが必要です。 サブツリー全体は、その最大値がしきい値を超えた場合、直ちに破棄されます。これは、サブツリー内の要素が厳密な不等式を満たすことができないためです。 

クエリは決して変わりません`h`、セグメントツリー、`nxt`、 または`dp`。 すべてのクエリは、一連の累積的な変更ではなく、個別の仮説的な変更を記述するため、これは不可欠です。

# Maximum-size stress case.
# Every original value is 1. A replacement of 1 gives one picked apple,
# while a replacement of 2 gives exactly two picked apples.
n = 100000
m = 100000
queries = []
expected = []

for i in range(1, m + 1):
    q = 1 if i & 1 else 2
    p = (i - 1) % n + 1
    queries.append(f"{p} {q}")
    expected.append("1" if q == 1 else "2")

maximum = (
    "1\n"
    f"{n} {m}\n"
    + ("1 " * (n - 1))
    + "1\n"
    + "\n".join(queries)
    + "\n"
)

assert run(maximum) == "\n".join(expected), "maximum-size stress case"

 ## 特殊なケース

 いつ`p = 1`、プレフィックスは空です。 例えば、```
1
3 1
1 2 3
1 5
```アルゴリズムセット`answer = 0`そして`threshold = 0`。 以来`5 > 0`、変更された最初のリンゴが選択され、しきい値が作成されます`5`。 サフィックス検索では、次の値を超える値は見つかりません。`5`したがって、出力は次のようになります`1`。 

いつ`p = n`、サフィックスは空です。 例えば、```
1
3 2
1 2 3
3 4
3 1
```のために`(3,4)`、プレフィックスは 2 つのリンゴと`4 > 2`、だから位置`3`が選ばれ、答えは`3`。 のために`(3,1)`、 位置`3`スキップされるのは、`1 <= 2`、したがって答えは残ります`2`。 通話検索元`p + 1 = 4`すぐにポジションを返しません。 

置換がプレフィックスの最大値と等しい場合は、スキップする必要があります。 例えば、```
1
3 1
2 5 8
3 5
```位置の前の接頭辞`3`最大値があります`5`。 交換品もあるので、`5`、 位置`3`選ばれていない。 サフィックスが空なので、答えは次のようになります。`2`。 使用する`>=`の代わりに`>`3 番目のリンゴを間違って数えてしまいます。 

置換がプレフィックスの最大値よりも大きい場合、それが新しいしきい値となり、どのサフィックス レコードが生き残るかが完全に変わります。 例えば、```
1
4 1
1 2 3 4
3 10
```接頭辞が貢献します`2`最大のリンゴ`2`。 代替品`10`が選択され、現在の答えが得られます。`3`。 接尾辞には次のものが含まれます`4`、 しかし`4`より大きくない`10`, したがって、接尾語 apple は追加されません。 結果は`3`。 

プレフィックスの最大値がすでに高く、置換が小さい場合、サフィックスは置換ではなく古い最大値を使用して検索する必要があります。 例えば、```
1
5 1
2 5 5 7 9
4 1
```ポジション前`4`、摘んだリンゴは、`2`そして`5`したがって、しきい値は次のようになります。`5`。 代替品`1`スキップされます。 位置の後の最初の値`4`より大きい`5`は`9`位置にある`5`、 そして`dp[5] = 1`。 答えは`2 + 1 = 3`。 

単調スタック内の等しい場合も同様に重要です。 のために```
1
4 1
5 5 5 6
1 5
```変更された配列は`[5,5,5,6]`。 最初だけ`5`そして決勝`6`選ばれたので、答えは`2`。 構築中`nxt`、高さのある位置`5`等しい値は決して有効な厳密に大きい次の選択ではないため、以前の同じ高さの候補を削除する必要があります。 使用する`<`の代わりに`<=`スタック状態では、無効な等高リンクが残り、DP が破損します。
