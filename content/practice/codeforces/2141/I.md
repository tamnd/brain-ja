 ## 解決策
 ## 問題の理解

 私たちは、すべての頂点が無色で始まるツリーを扱っています。 1 回の操作で、任意の 2 つの頂点 (場合によっては同じ頂点を 2 回) を選択し、それらの間の一意のパス上のすべての頂点を「再カラー」します。 移動するたびに新しいカラー インデックスが導入されるため、最初の操作ではパスがカラー 1 でペイントされ、2 番目の操作ではパスがカラー 2 でペイントされ、以下同様になります。 後の操作で前の操作が上書きされるため、各頂点の最終的な色は、選択されたパスがそれをカバーする最後の操作にすぎません。 

すべての頂点が少なくとも 1 回の操作でペイントされていれば、カラーリングは完了したとみなされます。 重要な数量は、カバレッジを確保するだけではなく、必要なパス操作の数を最小限に抑え、すべての最適な戦略の中で最終的な色の割り当てがいくつ発生するかを数えることです。 

制約 n ≤ 32 が中心信号で​​す。 頂点、パーティション、または一連の操作のサブセットを列挙しようとするアプローチは、おおよそ O(2^n) または O(3^n) で実行される場合には実行可能である可能性がありますが、階乗増加に近いものはすぐに除外されます。 これは、最適なソリューションの構造が、段階的な貪欲な構築ではなく、ツリーのグローバル パーティションに依存していることも強く示唆しています。 

ツリーがすでに単純なパスである場合、微妙なエッジ ケースが発生します。 その場合、パスの終端としてエンドポイントを使用する 1 つの操作ですべてが色付けされ、1 つの色のみが生成されます。 もう 1 つのエッジ ケースはスターです。2 つの葉を選択すると、中心を通るパスが強制されますが、オーバーラップ操作により自明ではない方法で色が上書きされる可能性があります。つまり、最適なシーケンスが異なると、最終的な頂点の色も異なる可能性があります。 

最も危険な誤解は、頂点を独立してカバーするという観点から考えることです。 たとえば、「T」のような形のツリーでは、中央で重なるパスで各枝を個別にカバーしようとすると、カウントしすぎたり、誤った最小性推論につながります。これは、エンドポイントに応じて 1 つのパスで複数の枝を同時にカバーできるためです。 

## アプローチ

 強引な解釈では、各操作で頂点のペアを選択し、そのパスをペイントする一連の操作を考慮することになります。 最適解には O(n^2) 個の可能なペアがあり、潜在的に最大 n 個の操作が存在するため、状態空間が天文学的に大きくなります。 最小長のシーケンスに制限したとしても、分岐因子が大きすぎるため、異なるシーケンスが最終的に同じカラーリングに崩壊する可能性があり、単純な列挙が無駄になります。 

重要な点は、頂点の最終的な色は、その頂点をパスが通過する最後の操作にのみ依存するということです。 これは、各頂点が 1 つの「最後に責任のあるパス」に割り当てられることを意味し、これらのパスは、各操作が単純なパスによって引き起こされる接続された頂点のサブセットに対応する構造を形成します。 重要な構造上の事実は、最適なソリューションでは、各操作が事実上、ツリーの縮小表現内のリーフ ペアの選択に対応しており、操作の数は、すべての分岐の曖昧さを排除するために必要な「独立したパス カバー」の数に密接に関係しているということです。 

この問題は古典的な観点に帰着します。つまり、すべての頂点がカバーされ、各操作が 1 つのパスに対応するように、ツリーを一連のパスに分解していますが、順序は各頂点でどのパスが最後になるかのみが重要です。 最小操作数は、特定の誘導構造における最小パス カバーのサイズであることが判明します。また、ツリー内にいるため、これは、残りの分岐を最小限に抑える方法で葉のペアを繰り返してツリーを縮小することに相当します。

n は非常に小さいため、代わりに頂点のサブセットにわたる状態の観点から考えることができ、最終的な「最後の色の割り当て」の構築を直接シミュレートします。 各頂点には、それをカバーする最後の操作のインデックスが割り当てられ、実現可能性は、同じラベルを共有する頂点が単一の単純なパスでカバーできるかどうかを確認することになります。 

したがって、最適なアプローチは、ビットマスク上のサブセット DP になります。頂点をグループに分割し、各グループが有効なパスを形成することを試み、最小数のグループでそのような分割を選択する方法が何通りあるかを数えます。 ツリー構造を使用すると、サブセットが接続されていること、および誘導されたサブグラフ内に次数 1 の頂点が最大 2 つあることを確認することで、サブセットが単純なパスを形成しているかどうかを効率的にテストできます。 

パーティションを段階的に構築し、パーツの最小数とそれを達成するための方法の数の両方を追跡します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 操作シーケンスに対するブルート フォース | 指数関数的 (事実上超指数関数的) | O(n) | 遅すぎる |
 | 頂点パーティション上の DP をパスにサブセット化する | O(n · 2^n + 遷移) | O(2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 頂点セットをグループに分割するという問題を再構成します。各グループは、単一の操作で最後にペイントされた頂点のセットに対応します。 このような各グループは、ツリー内の正確に単純なパスでなければなりません。 

1. すべての有効なパス サブセットを事前計算します。 頂点 u と v のすべてのペアについて、それらの間の一意のパス上の頂点のセットを計算します。 これにより、O(n^2) 個の候補サブセットが得られます。 それらをビットマスクとして保存します。 
2. ブール配列を構築する`is_path[mask]`頂点のすべてのサブセットに対して、最初は false で、有効な u-v パスに対応するすべてのマスクを true としてマークします。 これにより、単一の操作として現れる可能性のあるサブセットのみを考慮することが保証されます。 
3. サブセットにわたる DP を定義します。 させて`dp[mask]`頂点を正確にカバーするために必要なパス操作の最小数を保存します。`mask`素の有効なパス グループとして。 初期化する`dp[0] = 0`他のすべての状態は無限大です。 
4. マスクごとに、サブマスクを選択して拡張しようとします。`sub`これは有効なパスであり、残りの頂点に完全に含まれています。 から移行します`mask`に`mask | sub`これが機能する理由は、各操作が 1 つのパス グループにのみ寄与し、選択されたパスの結合がすべての頂点をカバーする必要があるためです。 
5. DP と並行して、2 番目のアレイを維持します`ways[mask]`最適な構造が何回達成されたかを数えます`dp[mask]`。 複数の方法が同じ最小値を達成する場合、それらを 998244353 を法として合計します。 
6. 答えは次のとおりです。`dp[full_mask]`そして`ways[full_mask]`。 

正確さは、最適な解法において、各操作がまさに単純なパスである頂点のセットに寄与し、これらのセットがツリーの互いに素な分割を形成するという事実にかかっています。 カラーの上書き動作は、頂点ごとに最後の操作のみが重要であることを意味するため、最適なシーケンスを、最後にペイントされた別々のパス セットへのパーティションとして常に再解釈できます。 

### なぜ効果があるのか

 有効な最終カラーリングはすべて、最後の操作によって頂点の分割を引き起こします。 1 回の操作でペイントされるすべての頂点は単一の単純なパス上にあるため、各パーツは接続されたパスである必要があります。 逆に、後の操作で有効性を損なうことなく前の操作が上書きされるため、頂点セットを有効なパス サブセットに分割することは、それらのパスを適切に順序付けることで実現できます。 したがって、操作を最小化することは、そのようなパーティション内のパス サブセットの数を最小化することと同等であり、解をカウントすることは、最小サイズのパーティションをカウントすることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input())
adj = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append(v)
    adj[v].append(u)

# precompute parent and path masks using BFS from each node
from collections import deque

path_masks = []

def get_path(u, v):
    # BFS parent reconstruction
    parent = [-1] * n
    q = deque([u])
    parent[u] = u
    while q:
        x = q.popleft()
        if x == v:
            break
        for y in adj[x]:
            if parent[y] == -1:
                parent[y] = x
                q.append(y)
    # reconstruct
    mask = 0
    cur = v
    while True:
        mask |= (1 << cur)
        if cur == parent[cur]:
            break
        cur = parent[cur]
    return mask

for i in range(n):
    for j in range(i, n):
        path_masks.append(get_path(i, j))

# mark valid path subsets
is_path = [False] * (1 << n)
for m in path_masks:
    is_path[m] = True

INF = 10**18
dp = [INF] * (1 << n)
ways = [0] * (1 << n)

dp[0] = 0
ways[0] = 1

for mask in range(1 << n):
    if dp[mask] == INF:
        continue
    sub = (~mask) & ((1 << n) - 1)
    t = sub
    while t:
        low = t & -t
        i = (low.bit_length() - 1)
        # try all submasks of sub but we only consider valid path masks
        # iterate over all precomputed paths instead for simplicity
        t -= low

    # instead directly try all path masks
    for pm in path_masks:
        if pm & mask:
            continue
        nm = mask | pm
        nd = dp[mask] + 1
        if nd < dp[nm]:
            dp[nm] = nd
            ways[nm] = ways[mask]
        elif nd == dp[nm]:
            ways[nm] = (ways[nm] + ways[mask]) % MOD

full = (1 << n) - 1
print(dp[full], ways[full] % MOD)
```このコードは、すべての単純なパス頂点セットを構築し、ビットマスクに対してサブセット DP を実行します。 BFS ベースのパス再構築により、頂点のペア間の一意のパスを正確に識別できます。 

実装上の微妙な問題は、DP がサブマスクを動的に生成しようとするのではなく、各状態のすべてのパス サブセットを反復処理する必要があることです。これは、制約 n ≤ 32 により、O(n^2) パスの事前計算が可能になりますが、2^n 状態にわたるサブマスクの列挙が正しく行われなかった場合、遅すぎるためです。 

の`ways`配列は、厳密に最適な、または同等に最適な遷移が見つかった場合にのみ更新され、モジュロ演算で正しいカウントが保証されます。 

## 実用的な例

 ### 例 1

 入力ツリー: 1-2-3

 すべての有効なパス マスクをリストします: {1}、{2}、{3}、{1,2}、{2,3}、{1,2,3}。 完全なセット {1,2,3} 自体がパスであるため、DP はすべての頂点をカバーする単一の操作をすぐに見つけます。 

| マスク | DP | 使用されるトランジション | 説明 |
 | --- | --- | --- | --- |
 | 000 | 0 | 開始 | 空集合 |
 | 111 | 1 | {1,2,3} | 1 つのパスですべてをカバー |

 DP は、1 つの操作で十分であり、代替の最小パーティションが存在しないことが判明するため、答えは (1, 1) になります。 

### 例 2

 中心 1 が 2、3、4 に接続されている星を考えてみましょう。 

有効なパス サブセットには、すべてのエッジ {1,2}、{1,3}、{1,4}、およびシングルトンが含まれます。 パス構造を壊さずに 1 つのパスに 2 つ以上のリーフを含めることはできないため、完全なカバレッジには少なくとも 2 つの操作が必要です。 

最小パーティションは、{2,1,3} と {4} のような 2 つのパスを使用します。 

| ステップ | 選択したパス | カバーされたセット |
 | --- | --- | --- |
 | 1 | {2,1,3} | 1、2、3 |
 | 2 | {4} | 1、2、3、4 |

 これは、葉と中心の組み合わせには複数の選択肢が存在するため、最適解が一意ではないことを示しています。

 ## 特殊なケース

 エンドポイント (1, n) 間の BFS が完全な頂点セットに等しいマスクを生成し、即座に dp[full] = 1 を与えるため、線形チェーンは正しく処理されます。 

星形のツリーにより、DP は複数の互いに素なパスを結合するように強制され、アルゴリズムは単純なパスではない不正なサブセットを正しく回避し、最小操作数が少なくとも 2 であることを保証します。その後、カウント コンポーネントは、各操作でどの葉が中心でグループ化されるかを選択するためのさまざまな方法を列挙し、複数の最適な色付けを生成します。
