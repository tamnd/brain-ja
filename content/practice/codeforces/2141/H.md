 ## 解決策
 ## 問題の理解

 無向の単純なグラフから始めます。$n$頂点。 グラフは、2 つの既存の頂点を削除し、その近傍が削除された頂点の近傍の交差に正確に一致する新しい頂点に置き換える操作を通じて進化します。 言い換えれば、新しい頂点は、選択したペアの共通の近傍のみを継承します。 

グラフに残りのすべての頂点に隣接する頂点が含まれるまで、このようなマージを実行し続けます。その時点でプロセスは直ちに停止します。 このようなユニバーサル頂点が最初からすでに存在している場合は、いかなる操作も実行できません。 

タスクは、考えられる 1 つのプロセスをシミュレートすることではなく、すべての有効なマージ シーケンスについて全体的に推論し、終了が避けられなくなる前に可能な最小および最大の操作数を決定することです。 

主な問題点は、各操作で頂点数が減り、集合の縮小のように動作する交差を通じてのみ隣接構造が維持されることです。 グラフは単に縮小しているだけではなく、非常に構造化された形で情報が失われています。 

制約$n \le 2 \cdot 10^5$そして$m \le 2 \cdot 10^5$近傍を再計算したり、マージを明示的にシミュレートしたりするアプローチは除外してください。 動的なプロセスは調査するには大きすぎるため、有効な解決策は問題を元のグラフの静的な特性に帰着させる必要があります。 

最初の微妙なケースは、ユニバーサル頂点がすでに存在する場合です。 たとえば、中心が 1 でエッジのある星形グラフの場合$(1,2),(1,3),(1,4)$、頂点 1 はすでにユニバーサルなので、答えは次のようになります。$0,0$。 頂点をマージしようとすると、そのような頂点が存在すると操作が禁止されるというルールに違反します。 

もう 1 つの重要なケースは、グラフがほぼ完成しているものの、いくつかのエッジが欠けている場合です。 2 つの頂点をマージしても交差点の外側に新しい隣接関係を作成できないため、1 つの欠落エッジでも複数のマージが強制される可能性があります。そのため、収縮によって強制されない限り、欠落エッジが直接修復されることはありません。 

## アプローチ

 この操作は別の方法で解釈することもできます。各頂点は「依存する」元の頂点のセットを表し、マージによって 2 つのセットが交差近傍構造に置き換えられます。 これは、このプロセスが基本的に、ある頂点が他のすべての頂点に隣接するまで、隣接関係のあいまいさを徐々に減らすことであることを示唆しています。 

ブルート フォース アプローチでは、考えられるすべてのマージ ペアを明示的にシミュレートし、各ステップで隣接交差を再計算します。 各マージには隣接リストのスキャンが必要です。$O(n)$最悪の場合はマージし、少なくとも$O(n^2)$表現によっては、それ以上の場合もあります。 すべての頂点のペアが候補となるため、分岐要素も膨大になり、列挙が不可能になります。 

重要な洞察は、プロセスの構造は、正確な隣接リストではなく、補数グラフの接続されたコンポーネントのみに依存するということです。 補完グラフでは、元のグラフで隣接していない 2 つの頂点が接続されます。 ユニバーサル頂点の存在は、補グラフにおける次数 0 の頂点に対応します。 

元のグラフでのマージ操作は、補グラフでは非近傍制約の結合を取得するように動作する方法で頂点を結合することに対応します。 ユニバーサル頂点を作成するプロセスは、接続された領域ごとに有効な代表が 1 つだけ残るまで、補体内のすべての「競合構造」を除去することに相当します。 

これは分解につながります。補グラフの接続された各コンポーネントは、内部の競合を排除することがどれほど難しいかという観点から独立して動作します。 操作の数は、存在するコンポーネントの数と最大のコンポーネントの大きさによって決まります。これは、交差が非エッジを保持するという制約を尊重しながら、マージを積極的に (ステップを最小化) または無駄に (ステップを最大化) にスケジュールできるためです。 

最小限の答えを得るために、私たちは常に複数の競合を一度に解決する方法でマージし、各補完コンポーネントをできるだけ早く単一の代表に効果的に削減します。 これにより、補数成分の数によって決まる下限が得られます。 

最大の答えを得るために、コンポーネント間のマージをできる限り遅らせ、基本​​的に各コンポーネントを結合する前に個別に折りたたむことにより、プロセスをほぼ最大まで延長します。$n-1$ユニバーサル頂点が早期に出現しない限りマージされます。 

したがって、核となる削減は、暗黙的に補数グラフを構築し、その連結成分を見つけ、それらのサイズに基づいて答えを計算することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数関数 /$O(n^2)$ステップごと |$O(n^2)$| 遅すぎる |
 | コンポーネントの補完 + 貪欲な推論 |$O(n + m)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 欠落しているエッジの観点からグラフを再フレーム化します。 

1. 隣接セットを使用して暗黙的に補完構造を構築します。 欠落しているエッジを明示的に構築する代わりに、未訪問の遷移に対してセットまたは DSU を使用して接続されていない頂点を追跡します。 
2. ユニバーサル頂点がすでに存在するかどうかを確認します。 これは、頂点に次数があるかどうかを確認することと同じです。$n-1$。 そのような頂点が存在する場合、両方の答えがゼロになるため、すぐに停止します。 The rule forbids any operation in this case.
 3. 補数グラフの連結成分を構築します。 We do not explicitly build all complement edges; 代わりに、BFS/DSU 手法を使用して、未訪問の頂点のセットを維持し、現在のノードの非隣接頂点をすべて検索することでコンポーネントを展開します。 
4. これらの補体コンポーネントのサイズを次のようにします。$s_1, s_2, \dots, s_k$。 これらは、欠落したエッジのチェーンを通じて相互に到達可能な頂点のグループを表しており、構造的な「非互換性」を共有していることを意味します。 
5. 最小の操作数は、各コンポーネントを効率的に折りたたむことによって得られます。 マージごとにコンポーネント内のアクティブな代表の数を減らすことができ、最適なマージにより各コンポーネントのサイズが削減されます。$s_i$1つに$s_i - 1$操作。 合計すると得られる$n - k$。 
6. 操作の最大数は、コンポーネント間の相互作用を遅延させることによって取得されます。 各コンポーネントは依然として内部で削減する必要がありますが、結果を結合するのが早すぎることは避けます。 最も長い有効プロセスは、最終的に、頂点が 1 つだけグローバルに残るまでコンポーネント内で繰り返しマージするように動作します。$n - 1$。 
7. ペアを出力します$(n - k, n - 1)$。 

### なぜ効果があるのか

 補数グラフは普遍性への障害を正確に捉えます。 同じ補完コンポーネント内の頂点のペアは、両方とも無期限に「欠落した隣接関係の独立したソース」のままであることはできません。これは、交差マージを繰り返すと、それらのコンポーネント内の差異のみが徐々に除去されるためです。 したがって、各コンポーネントは独立したブロックのように動作し、グローバルな普遍性を実現するにはその頂点を統合する必要があります。 最小戦略は各ブロックを最適に折りたたみますが、最大戦略は単一頂点への避けられない総削減を変更せずに、ブロック間の統合を可能な限り延期します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    adj = [set() for _ in range(n)]
    
    deg = [0] * n
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].add(v)
        adj[v].add(u)
        deg[u] += 1
        deg[v] += 1

    # check universal vertex
    for i in range(n):
        if deg[i] == n - 1:
            print(0, 0)
            return

    # complement BFS using unvisited set
    unvis = set(range(n))
    components = []

    while unvis:
        start = next(iter(unvis))
        unvis.remove(start)
        stack = [start]
        comp_size = 1

        while stack:
            u = stack.pop()

            # all vertices not adjacent to u in original graph
            # are neighbors in complement graph
            to_add = []
            for v in list(unvis):
                if v not in adj[u]:
                    to_add.append(v)

            for v in to_add:
                unvis.remove(v)
                stack.append(v)
                comp_size += 1

        components.append(comp_size)

    k = len(components)

    min_ops = n - k
    max_ops = n - 1

    print(min_ops, max_ops)

if __name__ == "__main__":
    solve()
```隣接セットを使用することで、エッジが欠落しているかどうかを確認できます。$O(1)$。 補数 BFS は完全な補数グラフの構築を回避し、代わりに残りの未訪問の頂点を反復処理し、隣接していない頂点をフィルタリングします。 

この問題では、その状況ではいかなる操作も明示的に禁止されるため、ユニバーサル頂点を早期に終了することが重要です。 この条件が欠けていると、すべての密グラフで off-by-one 動作が発生します。 

コンポーネントのカウントは構造の中核です。新しい補完コンポーネントを発見するたびに、内部統合がなければ普遍性にすぐに貢献できない頂点のブロックが特定されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    adj = [set() for _ in range(n)]
    deg = [0]*n

    for _ in range(m):
        u,v = map(int, input().split())
        u-=1; v-=1
        adj[u].add(v)
        adj[v].add(u)
        deg[u]+=1
        deg[v]+=1

    for i in range(n):
        if deg[i]==n-1:
            return "0 0"

    unvis = set(range(n))
    comps = []

    while unvis:
        start = next(iter(unvis))
        unvis.remove(start)
        stack=[start]
        size=1

        while stack:
            u=stack.pop()
            rem=[]
            for v in list(unvis):
                if v not in adj[u]:
                    rem.append(v)
            for v in rem:
                unvis.remove(v)
                stack.append(v)
                size+=1

        comps.append(size)

    k=len(comps)
    return f"{n-k} {n-1}"

 ## 特殊なケース

 完全なグラフでは、普遍的な頂点ルールがすぐに明らかになります。 入力用$n=3$すべてのエッジが存在する場合、すべての頂点には次数があります$n-1$したがって、アルゴリズムは補数 BFS の前に終了します。 この条件を無視する実装では、誤ってマージが試行され、肯定的な応答が生成されます。 

他のすべてに接続された 1 のようなスター グラフは、ノード 1 にユニバーサル頂点を生成します。次数チェックがすぐにトリガーされ、答えは次のようになります。$0,0$たとえコンポーネントに関する単純な推論がさらなる分解を示唆するかもしれないとしても。
