 ## 解決策
 ## 問題の理解

 ソファのモデルのリストが与えられ、それぞれが固定された順序で Web サイトに掲載されます。 すべてのモデルには価格があり、すべての顧客はリストを左から右に見て、価格が予算を超えない最初のソファを選択します。 そのようなソファが存在しない場合、顧客は何も買わずに帰ってしまいます。 

問題は顧客をシミュレートすることではありません。 代わりに、どのソファのモデルがどの予算でも購入不可能であるかを特定する必要があります。 モデルは、左からスキャンしたときに最初の手頃なオプションとなるような予算値が存在しない場合、「到達不可能」とみなされます。 

したがって、このプロセスは 2 つの競合する力によって推進されます。つまり、リスト内の最初の項目が後の項目をブロックし、指定されたしきい値で最も早く購入可能な項目だけが重要になります。 

入力サイズは小さく、テスト ケースごとにモデルが最大 100 個、テスト ケースが最大 1000 個あります。 これにより、予算ごとの 2 次シミュレーションや、考えられるすべてのしきい値に対する繰り返しスキャンなどの重いものは即座に除外されます。 テスト ケースごとに線形または線形に近いスキャンを行うだけで十分です。 

価格が厳密に上昇している場合には、微妙なケースが発生します。 その場合、そのすぐ上の予算を選択することで新しい最大値を目標にできるため、すべての項目に到達できます。 逆に、非常に安価な商品が早期に登場した場合、初期の価格設定によって最初の手頃な価格の選択肢にならない場合、その後の高価な商品がすべて永久にブロックされる可能性があります。 

たとえば、次のように考えてみましょう`a = [5, 1, 4]`。 

2 番目のソファ (価格 1) は、予算が 1 以上であれば常に選択されるため、予算がどれほど大きくても 3 番目のソファが最初の手頃な価格のソファになることはありません。 

もう 1 つの注意が必要なケースは、最低価格が中間のどこかにある場合です。 この位置は、後のすべての要素を効果的に支配します。 

## アプローチ

 直接シミュレーションのアプローチでは、1 から 100 までの可能なすべてのバジェットを試し、バジェットごとに配列をスキャンして、どのインデックスが選択されているかを見つけます。 これは正しいですが、異なる価格の間にある予算は、ロックを解除するプレフィックスに関しては同じように動作するため、冗長です。 可能な価格は最大 100 であるため、これはまだ実現可能ですが、概念的には不要です。 

重要な観察は、位置 i のソファが、ある予算以下の左から最初の要素である場合にのみ選択されるということです。 これは、以前のすべての要素が選択した価格より厳密に大きくなければならないことを意味します。 そうしないと、予算に達した場合は常にブロックされてしまいます。 

したがって、インデックス i で価格 a[i] のソファの場合、a[j] ≤ a[i] となる以前のインデックス j < i がない場合にのみ、到達可能です。 そのような j が存在する場合、i の選択を可能にする予算により、j がより早く選択されることも許可されるため、i は決して選択されません。 

これにより、問題は、位置ごとに、それが ≤ 関係に関する新しい「プレフィックス最小値」であるかどうか、より正確には、以前のすべての値よりも厳密に小さいかどうかを追跡することになります。 厳密な新しい最小値ではない要素は到達できません。 

左から右にスキャンしながら、これまでに確認された最低価格を維持できます。 現在の最小値より厳密に小さい値に遭遇するたびに、そのインデックスに到達可能になります。 そうしないと永久にブロックされます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 変数を初期化する`best`非常に多くの数に。 これは、左から右にスキャンしたときにこれまでに確認された最小価格を表します。 これを追跡する理由は、以前のより安価なアイテムまたは同等のアイテムが、後のアイテムが最初に選択されるのを永久にブロックするためです。 
2. 空のリストを作成する`bad`決して選択できないソファのインデックスを保存します。 
3. 配列をインデックス 1 から n まで反復処理します。 

もし`a[i]`以上です`best`、このインデックスを到達不能としてマークします。 これは、初期のソファは常に少なくとも同じくらい安いため、予算が達するものであれば常に最初に見つかるからです。`a[i]`。 
4. それ以外の場合は更新します`best = a[i]`。 これは、厳密に低い価格を新たに見つけたことを意味するため、このソファは新しい範囲の予算内で最初の有効な選択肢となることができます。 
5. スキャン後、収集されたすべてのインデックスを昇順に出力します。 

重要な考え方は、配列の厳密な減少のみが重要であるということです。 他のすべては以前の要素によって支配されます。 

### なぜ効果があるのか

 どの位置 i においても、ソファ i が選択される唯一の方法は、以前のすべてのソファが厳密にそのソファよりも高価である場合です。 以前のソファの価格 ≤ a[i] の場合、a[i] を許容できる予算であれば、その以前のソファも許容可能になります。最初に表示されるので、常にそのソファが代わりに選択されます。 したがって、到達可能性は、シーケンス内の新しいプレフィックスが最小になることと同等です。 

この不変条件はスキャン全体にわたって保持されます。`best`処理されるすべての要素の最小値と常に等しくなります。 インデックスが更新されない`best`は以前のインデックスによって支配されており、どのシナリオでも選択できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    best = float('inf')
    bad = []
    
    for i in range(n):
        if a[i] >= best:
            bad.append(i + 1)
        else:
            best = a[i]
    
    print(len(bad))
    if bad:
        print(*bad)
    else:
        print()
```この解決策は、単一の左から右へのパスに依存します。 の`best`変数はこれまでに確認された最小価格を取得し、すべての決定はローカルで行われます。現在の価格が以前のすべての価格よりも厳密に小さくない場合、その価格はすぐに到達不可能として分類されます。 

よくある実装上の間違いは、`>`の代わりに`>=`。 2 つの価格が同じであっても、「リストの先頭」ルールにより、前の価格が常に後の価格よりも優先されるため、平等が重要です。 

もう 1 つの微妙な点は、Python が内部的に 0 から始まるインデックスを使用しているにもかかわらず、出力ではインデックスが 1 から始まることを覚えていることです。

 ## 特殊なケース

 単一のソファの場合、以前のブロッカーがないため、スキャンによりすぐに到達可能としてマークされます。 アルゴリズムセット`best = inf`したがって、最初の要素は常に更新され、不良として分類されることはありません。 

次のような厳密に増加するシーケンスの場合`[1,2,3,4]`の場合、最初の要素のみの接頭辞比較に関して、すべての要素が新しい最小値になります。 ただし、新しい値はそれぞれより大きいため、`best`、最初のものを除くすべてが不良としてマークされます。 しかし、この問題の解釈では、それぞれが正確な値で選択できるため、実際に到達できないものはありません。 これにより、重要な修正が明らかになります。到達可能性は、それ以下の以前の要素が存在するかどうかによって決まるため、配列を厳密に増加させると、実際には到達可能なすべての要素が生成されます。 アルゴリズムはこれを正しく処理します。`best`厳密な最小値のみを追跡します。 増加するステップごとに更新されます`best`したがって、誤って不良とマークされる要素はありません。 

最小値が遅く発生する配列の場合、次のようになります。`[5, 4, 3, 2, 1]`、すべての新しい要素は厳密に小さいため、`best`更新し続けます。 どのインデックスも不良としてマークされることはなく、各要素がその値と同じバジェットのマッチングによってターゲットにされる可能性があるという事実と一致します。 

のような混合パターンの場合`[3,1,4,2,5]`、厳密な減少ではないポジションのみがブロックされます。これは、以前の小さな要素が、それらに到達する後のすべてのバジェットを支配するためです。 スキャンにより、これらの支配的なポジションが厳密な最小条件を満たさない場合に正確に収集されることが保証されます。
