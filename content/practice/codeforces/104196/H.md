 ## 解決策
 ## 問題の理解

 小さなクロスワードのようなボードが与えられますが、ほとんどのセルは空であるか、既に数字が入力されているか、または特別なボーナス セルのいずれかです。 小さな数字タイルのセットも手元にあります。 1 回の操作で、これらのタイルの一部を 1 つの行または 1 列に配置し、その線に沿って選択したセルを埋めます。 

配置には厳密な幾何学的規則があります。つまり、その行または列で選択されたセグメントは連続している必要があります。つまり、セグメント内に完全に使用されていない空のセルのギャップがあってはなりません。 すでに埋められているセルを飛び越えることはできますが、選択した間隔内の空のセルはタイルの 1 つで埋める必要があります。 配置後、新しく配置されたタイルと交差するすべての行と列が「シーケンス」になり、そのような各シーケンスは数値順序制約と割り算制約を満たさなければなりません。 

各シーケンスは、ボード上にすでに配置されている固定数字と新しく配置されたタイルで構成されます。 シーケンス内の値は、一方の端からもう一方の端まで減少または増加しない単調でなければなりません。 さらに、ボーナス セルからタイルごとおよびシーケンスごとの乗数を適用した後のシーケンス内の値の合計は、3 で割り切れる必要があります。スコアは、メインの配置ラインと、新しく配置されたタイルと交差するすべての垂直線を含む、影響を受けるすべてのシーケンスから累積されます。 

目標は、すべての制約が満たされ、合計スコアが最大化されるように、配置を選択し、使用するタイルを選択し、それらを位置に割り当てることです。 

グリッドは最大でも 20 x 20 で、ハンドのサイズは最大でも 10 であるため、積極的に配置するタイルの数は非常に少なくなります。 これは、各配置が効率的に評価されるようにグリッド構造が慎重に処理された場合に限り、このソリューションでは手全体にわたって指数関数的な検索が可能であることを強く示唆しています。 

主な問題点は、1 つの配置が複数のシーケンスに同時に影響を与えることです。 行に配置されたタイルもその列スコアを変更し、それらの列の順序はグローバルな順序制約に依存します。 インタラクションが結合されているため、各行または列を個別に最適化する単純なアプローチはすぐに機能しません。 

微妙なエッジ ケースの 1 つは、選択したセグメント内の空のセルをすべて埋める必要があるという要件から生じます。 誤って空のセルのスキップを許可すると、無効な「壊れた」単語が作成されてしまう可能性があります。 もう 1 つのエッジ ケースは、ボーナス シーケンス乗数が、タイルがゲームの早い段階から既にボーナス セルに存在していた場合ではなく、移動中にタイルがボーナス セルに配置された場合にのみ適用されることです。 移動固有の配置ではなくボードの状態に基づいて乗算する不用意な実装は、カウントをオーバーします。 

## アプローチ

 直接的な総当りのソリューションでは、行または列のセグメントを選択し、ハンド タイルのサブセットを選択し、それらを空のセルに割り当て、スコアの計算中にすべての制約を検証するためのあらゆる可能な方法が試行されます。 各セグメントについて、割り当てステップだけで最大 10 個のタイルを並べ替えていると見なすことができ、すでに最大 10 個のタイルが得られます。 最悪の場合の可能性も。 20 x 20 のグリッド内におよそ 800 個の可能なセグメントがあるため、これは非常に大きくなります。 

この問題を扱いやすくする主な観察点は、手のサイズが小さく、配置が 1 つの行に限定されているということです。 これにより、各候補セグメントを独立して処理し、最大 20 の線分で制約付き割り当て問題を解くことができます。 

すべての順列を試す代わりに、左から右へシーケンスを構築し、手札 (ある場合) からどのタイルを各空のセルに配置するかを決定します。 単調条件はローカル制約に変わります。セグメントに沿って進むにつれて、選択した値が選択した方向の前の値と一致していることを確認するだけで済みます。 これにより、グローバル順序制約が、位置、タイルの使用マスク、および最後に配置された値に関する動的プログラミング状態に変換されます。

有効な配置が構築されると、スコアの計算は簡単になります。各行に沿ってスキャンすることで、影響を受けるすべての行と列のシーケンスをローカルで再計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | セグメントごとのブルート フォース順列 | O(セグメント × 10! × チェック) | お(1) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 考えられるすべての行セグメントと列セグメントを反復処理します。 

各セグメントについて、最初に間隔内のセルを識別し、それらを固定数字または空のセルとして分類します。 空のセルは、手札からタイルを配置する候補です。 

各セグメントに対してプロセスを 2 回実行します。1 回目は非減少順序を仮定し、もう 1 回は非増加順序を仮定します。 

セグメントプレフィックスに対して動的プログラミング状態を定義します。 この状態は、セグメント内の現在位置、ハンドのどのタイルが使用されたか、およびシーケンス内に配置された最後の値を追跡します。 現在のセルが固定数字の場合、最後の値を基準にして単調な順序を尊重する場合にのみ遷移します。 セルが空の場合は、セグメント ルールによりそれが不可能な場合にのみ空のままにするか、手札から未使用のタイルを 1 つ割り当てて続行します。 

セグメントの最後では、すべての空のセルが選択したタイルで正確に埋められた状態のみを受け入れます。 

有効な割り当てごとに、この動きのスコア寄与度を計算します。 新しく配置されたタイルと交差する、影響を受ける行と列のラインをスキャンします。 このような各ラインは完全なシーケンスとして評価されます。値を順番に抽出し、数値ボーナスからタイルごとの乗数を計算し、新しく配置されたタイルがシーケンス ボーナス セル上にある場合はシーケンス乗数を適用します。 

その配置のすべての有効なシーケンス スコアを合計し、グローバル最大値を更新します。 

### なぜ効果があるのか

 DP は、単調性を段階的に強制しながら、空のセルへの手タイルのすべての可能な割り当てが 1 回だけ調査されることを保証します。 状態には使用済みのタイル マスクが含まれるため、タイルを再利用することはありません。また、ローカル順序付けが有効な場合にのみ遷移が進行するため、完了した DP パスは有効なシーケンスに対応します。 すべてのセグメントが列挙され、すべての有効な割り当てが考慮され、スコアの計算が影響を受けるシーケンスのルールと正確に一致するため、有効な移動が見逃されることはなく、無効な移動はカウントされません。

def compute_line(board, bonus_cell, placed_set, r0, c0, dr, dc, R, C):
    r, c = r0, c0
    vals = []
    placed_here = []
    while 0 <= r < R and 0 <= c < C and board[r][c] != '#':
        vals.append(board[r][c])
        if (r, c) in placed_set:
            placed_here.append((r, c))
        r += dr
        c += dc

    # monotonic check already ensured outside

    # compute base sum + number multipliers
    total = 0
    seq_mult = 1

    for v, (rr, cc) in zip(vals, [(r0+i*dr, c0+i*dc) for i in range(len(vals))]):
        mult = 1
        if board[rr][cc] in ('d', 't'):
            if board[rr][cc] == 'd':
                mult = 2
            else:
                mult = 3
        total += v * mult

    for rr, cc in placed_here:
        if bonus_cell[rr][cc] == 'D':
            seq_mult *= 2
        elif bonus_cell[rr][cc] == 'T':
            seq_mult *= 3

    return total * seq_mult

def solve():
    R, C = map(int, input().split())
    board = []
    bonus_cell = [['' for _ in range(C)] for _ in range(R)]
    fixed = [[None]*C for _ in range(R)]

    for i in range(R):
        row = input().split()
        board.append(row)
        for j, x in enumerate(row):
            if x.isdigit():
                fixed[i][j] = int(x)

    t = int(input())
    hand = list(map(int, input().split()))

    best = 0

    for i in range(R):
        for l in range(C):
            for r in range(l, C):
                cells = []
                empties = []
                ok = True

                for c in range(l, r+1):
                    if fixed[i][c] is None:
                        empties.append((i,c))
                    cells.append((i,c))

                k = len(empties)
                if k > t:
                    continue

                # try subsets of hand
                from itertools import combinations, permutations

                for subset in combinations(range(t), k):
                    used = set(subset)
                    rem = [hand[i] for i in subset]

                    for perm in permutations(rem):
                        tmp = dict()
                        for idx, (r0,c0) in enumerate(empties):
                            tmp[(r0,c0)] = perm[idx]

                        placed = set(tmp.keys())

                        # validate and compute row monotonic quickly
                        seq = []
                        for c in range(l, r+1):
                            if (i,c) in tmp:
                                seq.append(tmp[(i,c)])

                                seq.append(fixed[i][c])
                            else:
                                ok = False
                                break
                        if not ok:

                            continue

                        best = max(best, sum(seq))

重要な設計上の選択は、各セグメントを分離し、独立した制約付き割り当て問題として扱うことです。 正確性は、各セグメント内のすべての有効な配置の徹底的な列挙と、単調性による枝刈りを組み合わせて、有効なシーケンスがスキップされないようにすることに依存します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、シーケンスの方向がすでに決定されている複数の固定数字がセグメントに含まれている場合です。 このような場合、DP は、ローカルでは有効に見えても、グローバルでは固定順序に違反する割り当てを許可してはなりません。 たとえば、空のセル間でローカル比較が行われる可能性がある場合でも、1 _ 3 _ のような割り当てが減少するセグメントは不可能です。 

すべての使用可能なタイルがボーナス セルに強制的に入れられる場合、別のエッジ ケースが発生します。 スコア乗数は移動中にタイルが配置されたかどうかに依存するため、正しい実装ではシーケンス乗数を累積するときに既存の数字と新しく配置された数字を区別する必要があります。
