 ## 解決策
 ## 問題の理解

 ファイルのリストが与えられ、各ファイルには 1 から n までの一意のラベルが付いています。 エディターは常にこれらのファイルの順序を維持しますが、この順序は 2 つの連続する部分に分割されます。 最初の部分には、固定されたすべてのファイルが現在の相対的な順序で含まれ、2 番目の部分には、固定されていないすべてのファイルが現在の相対的な順序で含まれます。 

移動は、単一ファイルの固定状態を切り替えることで構成されます。 ファイルは現在の位置から物理的に削除され、新しい状態に応じて別の領域にすぐに再挿入されるため、これは単なるフラグの反転ではありません。 ファイルが固定されると、そのファイルは固定されたセグメントの最後に挿入されます。 固定が解除されると、固定が解除されたセグメントの先頭に挿入されます。 ピン留めされたブロックとピン留めされていないブロックの内部の相対順序は、これらの挿入と削除を除いて保持されます。 

初期構成とターゲット構成が与えられ、両方とも完全な順序とどのプレフィックスが固定されているかが記述されます。 タスクは、初期状態をターゲット状態に変換するために必要なトグルの最小数を計算することです。 

重要な制約は、n が最大 100 であるため、2 次または 3 次の推論が許容されることです。 これは、順列と組み合わせたすべての 2^n サブセットにわたる指数関数的状態検索を避けるべきであることを強く示唆しています。 

ピン留めされたブロックまたはピン留めされていないブロック内の相対的な順序が変化すると、微妙なエッジ ケースが発生します。 トグルはファイルを境界を越えて移動したり、セグメント内の位置を変更したりできるため、位置の単純な貪欲なマッチングは失敗します。 

たとえば、両方の状態ですべてのファイルの固定が解除されているが、順列が異なる場合、セグメント構造を無視する単純なアプローチでは、移動は必要ないと考えられますが、セグメント内での並べ替えには依然として切り替えが必要なため、これは誤りです。 

もう 1 つの失敗例は、ファイルが固定されたセクションと固定されていないセクションの間で位置のみを変更する場合です。 たとえ配列全体での相対的な順序が似ていても、境界構造により移動が強制されます。 

## アプローチ

 ブルート フォース アプローチでは、各状態を順列とバイナリ固定マスクで構成されるペアとして扱い、すべての状態に対して BFS を実行し、各遷移で 1 つのファイルを切り替えます。 構造を再構築するには各移動が O(n) であり、n 回あります。 初期状態から到達できるのは小さなサブセットのみですが、原則として順列と 2^n のマスクの積です。 到達可能な状態に制限しても、BFS は n * n のオーダーで探索できます。 最悪の場合は移行しますが、これは完全に不可能です。 

重要な観察は、ピン留めされたセグメントとピン留めされていないセグメント内の内部順序が決して任意ではないということです。 すべての状態は n 個の要素の順列によって完全に決定され、ファイルを切り替えることは、ファイルを削除して、その新しい状態のみに依存する境界位置にファイルを再挿入することと同じです。 この構造は、ピン留めされたグループとピン留めされていないグループへの分割によって引き起こされる制約を考慮した場合、重要なのは、ターゲットに対して「誤って配置された」要素の数であることを意味します。 

より有用な視点は、要素のペア間の順序制約の観点から考えることです。 各トグルでは、要素が境界および相対順序制約に対してどのように配置されるかという構造上の矛盾を最大 1 つ修正できます。 これにより、セグメントの内部順序を維持する制限された移動の下で、ある置換を別の置換に変換するために必要な最小限の操作数を計算するという問題が軽減されます。

重要な単純化は、最終的な答えは、ターゲット位置とターゲット セグメントの両方と一致する構成にまだ存在していない要素の数だけによって決まることを理解することです。 相対的な順序制約をすでに満たしている要素を整列させたら、残りの要素を移動する必要があり、移動するたびに結合された構造内に 1 つの要素が正しく「配置」されます。 これにより、ターゲット状態から誘導された順序に関して、一貫したサブシーケンスにいくつの要素を保持できるかを計算する作業が削減されます。 

これは、初期順序付けとターゲット順序付けの間の最長共通部分列問題になりますが、工夫が必要です。ピン留めされたセグメントとピン留めされていないセグメントへの分割を考慮する必要があります。 両方の状態が線形化されると、最小移動数は、要素の数から、すでに正しい相対順序で表示されている最長のサブシーケンスを引いたものと等しくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 状態を超えたブルート BFS | O(n! · n) | O(n!) | 遅すぎる |
 | マッピングされた順列上の LCS | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 初期設定とターゲット設定の両方を完全なシーケンスに変換し、当面は固定された分割を無視します。 固定された要素は常に固定されていない要素の前に来るため、固定された構造は順序を定義する場合にのみ重要になります。 

次に、次のように進めます。 

1. 指定されたとおりに、長さ n の配列 A として初期シーケンスを構築します。 
2. ターゲット シーケンスを長さ n の配列 B として構築します。 
3. pos[value] が B 内のその値のインデックスを与えるように、位置マップ pos を構築します。 
4. A を、各要素が pos[A[i]] である配列 C に変換します。 これにより、問題は、ターゲット内のインデックス順序を介して 2 つの順列を比較することに変換されます。 
5. C の最も長く増加するサブシーケンスの長さを計算します。これは、ターゲット構成に関してすでに正しい相対順序になっている要素の最大のサブセットに対応します。 
6. 答えは、n から LIS の長さを引いたものです。 

ステップ 4 の背後にある理由は、2 つの要素が両方の構成で正しい相対順序で出現する場合、ターゲット順序におけるそれらのインデックスが、変換された配列内で増加するということです。 したがって、順序を維持するということは、増加する部分列を見つけることになります。 

### なぜ効果があるのか

 有効な移動シーケンスはすべて、境界挿入によってのみ要素の位置を変更できます。これにより、タッチされていない要素の相対的な順序が保持されます。 したがって、私たちができる最善のことは、ターゲット内で正しい相対順序ですでに表示されている要素のサブセットを移動しないようにすることです。 そのサブセットは、まさに、ターゲット インデックス マッピングの下で​​最も長​​く増加するサブシーケンスです。 他のすべての要素は少なくとも 1 回移動する必要があり、各移動で LIS 構造を乱すことなく 1 つの要素を正しく配置できるため、最小移動数は n から LIS を引いた値に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def lis_length(arr):
    import bisect
    d = []
    for x in arr:
        i = bisect.bisect_left(d, x)
        if i == len(d):
            d.append(x)
        else:
            d[i] = x
    return len(d)

def solve():
    p, u = map(int, input().split())
    A = list(map(int, input().split()))
    input()  # skip p u line format redundancy if present
    B = list(map(int, input().split()))
    input()

    pos = {}
    for i, v in enumerate(B):
        pos[v] = i

    C = [pos[x] for x in A]
    print(len(A) - lis_length(C))

if __name__ == "__main__":
    solve()
```実装では、まず 2 つの構成を読み取り、それらを完全な配列に平坦化します。 マッピングのステップは、構造的な順序付けの問題を純粋な順列比較の問題に変換するため、重要です。 

LIS の計算では、二分探索による標準的な忍耐ソート方法が使用され、O(n log n) 時間が確保されますが、n ≤ 100 の場合は O(n²) でも十分です。 n からの減算により、トグルによって再配置する必要がある要素の数が直接得られます。 

微妙な点は、リスト全体を 1 つのシーケンスとして扱わなければならないことです。 固定された境界は順序付け自体ですでにエンコードされているため、フラット化後に特別な処理は必要ありません。 

## 実用的な例

 ### 例 1

 初期 A = [2, 1, 4, 3] とターゲット B = [4, 2, 3, 1] を考えてみましょう。 

B のインデックスを 4→0、2→1、3→2、1→3 にマッピングするため、C は [1, 3, 0, 2] になります。 

| ステップ | C | LISプロセス | これまでのLIS |
 | --- | --- | --- | --- |
 | 開始 | [1,3,0,2] | 空から始める | 0 |
 | 1 | [1] | 追加 1 | 1 |
 | 2 | [1,3] | 追加 3 | 2 |
 | 3 | [1,3,0] | 1 を 0 に置き換えます | 2 |
 | 4 | [1,3,0,2] | 3 を 2 に置き換えます | 2 |

 LIS の長さは 2 なので、答えは 4 − 2 = 2 となります。 

これは、正しい相対順序を維持できる要素は 2 つだけであることを示しています。 残りは、ターゲットと一致する構成に到達するために、それぞれ少なくとも 1 つのトグルを必要とします。 

### 例 2

 初期 A = [1, 2]、ターゲット B = [1, 2]。 

マッピングにより C = [0, 1] が得られます。 LIS は 2 なので、答えは 0 です。 

| ステップ | C | LISプロセス | これまでのLIS |
 | --- | --- | --- | --- |
 | 開始 | [0,1] | 0を追加 | 1 |
 | 1 | [0,1] | 追加 1 | 2 |

 構造はすでに正確に一致しているため、要素を再配置する必要はありません。 

これにより、順列がすでに一致している場合、切り替えが必要ないことが確認されます。

 ## 特殊なケース

 主なエッジ ケースは、固定された境界だけが変更されるが、相対的な順序は同一のままである場合です。 たとえば、イニシャルが固定 [1,2] 固定解除 [3,4] で、ターゲットが固定 [1,2,3] 固定解除 [4] の場合、フラット化されたシーケンスに対する LIS は正しく保存された大きなサブシーケンスを生成し、再配置が必要な要素は 1 つだけです。 

もう一つの特殊なケースは、完全な逆転です。 A が [1,2,3,4] で B が [4,3,2,1] の場合、マッピングされたシーケンスは厳密に減少するため、LIS は 1 になります。アルゴリズムは正しく 3 を出力します。これは、順序制約により 1 つを除くすべての要素を少なくとも 1 回移動する必要があることを反映しています。 

最後の微妙なケースは、ピン留めされたセットが同一であるが、内部順序が異なる場合です。 LIS 定式化は固定ラベルを正しく無視し、セグメント内での並べ替えにはターゲット インデックス空間での昇順を破るのと同等の移動が必要であることを捉えます。
