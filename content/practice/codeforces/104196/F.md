 ## 解決策
 ## 問題の理解

 平面内に一連の円が与えられます。 各円は、固定中心、初期半径、および線形成長速度で始まります。 時間が経過するにつれて、すべての円は外側に拡大するため、その半径は直線的に増加します。 

2 つの円が最初に接触すると、つまり境界間の距離がゼロになり、それらはすぐに 1 つの新しい円に結合されます。 その統合されたサークルは元のサークルに取って代わり、成長を続けます。 その中心は、マージに参加したすべての元の中心の算術平均になります。 その「サイズ」は面積の合計によって定義されます。つまり、これを半径に変換し直すと、新しい半径は元の半径の二乗の合計の平方根になります。 結合したサークルの成長速度は、そのサークルを構成する全サークルの中で最大の成長速度となります。 

重要な問題は、マージがまったく同時にカスケードされる可能性があることです。 新しく形成された円がすぐに別の円に同時に接触すると、それらも即座に融合し、完全な連鎖反応が形成され続ける可能性があります。 最終的には、すべての円が 1 つの最後の円にマージされます。この最後のマージされた円が作成されるまさにその瞬間に、その中心と半径を計算する必要があります。 

入力サイズは小さく、最大 100 円です。 これは、重度の組み合わせまたは状態爆発のアプローチを除外しますが、これは、$O(n^2 \log n)$ペアの相互作用に関するシミュレーションは実行可能です。 すべての円のペアは潜在的に相互作用する可能性があるため、次のオーダーで計算および処理することを期待する必要があります。$n^2$候補イベント。 

微妙な点は、マージによってシステムが動的に変更されることです。中心、半径、成長速度はすべて変更されます。 これにより、すべてのイベントを一度だけ事前計算し、決して更新しないアプローチは無効になります。 

単純な間違いは、ペアごとのマージ時間が静的であると仮定することです。 たとえば、円 A と B が C に結合した場合、C の中心は A と B の中点になるため、C は A または B が個別に到達するよりも早く別の円に到達する可能性があります。 したがって、マージのたびにインタラクションを再計算することが不可欠です。 

もう 1 つの落とし穴は、瞬間的な連鎖反応を無視することです。 A と B が時刻 t でマージし、その結果生じる円がちょうど時刻 t ですでに C と重なっている場合、C も同じマージ イベントに含まれている必要があり、後のイベントとして扱われません。 

## アプローチ

 ブルートフォース シミュレーションでは、継続的に時間を進め、現在のすべての円の間で次の衝突を見つけ、それらをマージし、繰り返します。 次の衝突を見つけるには、ステップごとにアクティブな円間のすべてのペアごとの交差時間を再計算します。 

これは正しいですが、非効率的です。 最大 100 個の円では、最大 99 回のマージが可能で、各マージ ステップでは再計算が必要です$O(n^2)$相互作用により、$O(n^3)$総仕事量。 一部の設定では許容範囲内ですが、より深刻な問題は、同じジオメトリを再利用せずに繰り返し再計算することです。 

重要な観察は、各マージ イベントが線形成長から計算されたペアごとの「最初の接触時間」によって決定されるということです。 クラスターが進化しても、新しいクラスターはそれぞれ 1 回だけ形成され、他のクラスターとの相互作用時間は、集約されたジオメトリから直接計算できます。 これにより、各クラスターをノードとして扱い、潜在的な衝突をグローバル優先キュー内のイベントとして扱うことができます。 

私たちは一連のアクティブなクラスターを維持します。 新しいクラスターが形成されるたびに、既存のすべてのクラスターとの対話時間を計算し、これらのイベントを最小ヒープにプッシュします。 最初のイベントを処理するときに、両方のエンドポイントがまだアクティブであることを確認します。 存在する場合は、マージを実行して新しいクラスターを作成します。 

マージ後はイベントが古くなっている可能性があるため、古いイベントはポップ時に遅延して破棄されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各マージ後にすべてのペアを再計算します。$O(n^3)$|$O(n)$| 遅すぎる |
 | 増分クラスター作成によるイベント駆動型ヒープ |$O(n^2 \log n)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 現在の各クラスターを、その中心、総面積、成長速度、およびエリア再構築に必要な元の半径寄与のリストを保存するオブジェクトとして扱います。 

1. 各サークルを独自のクラスターとして開始します。 各クラスターには、その中心座標、半径、成長速度、派生面積が保存されます。$r^2$。 また、アクティブであることをマークする一意の ID も追跡します。 
2. 初期クラスターのすべてのペアについて、線形成長下で最初に接触する時間を計算します。 中心間の距離が$d$、半径は次のように増加します$r_i + s_i t$の場合、接触条件は次のようになります。$$d = (r_i + r_j) + (s_i + s_j)t$$それで$$t = \frac{d - r_i - r_j}{s_i + s_j}.$$3. このようなすべてのイベントを、時間でキー設定された優先キューにプッシュします。 
4. キューから最も古いイベントを繰り返し抽出します。 いずれかのクラスターがアクティブでなくなった場合は、イベントを破棄します。 
5. 時刻 t におけるクラスター A と B の間の有効なイベントを取得すると、それらを新しいクラスター C にマージします。そのプロパティは次のように計算されます。 中心は、A と B のすべての元の中心を組み合わせた算術平均です。 合計面積はそれらの面積の合計であるため、半径は次のようになります。$\sqrt{r_A^2 + r_B^2}$。 成長スピードは、$\max(s_A, s_B)$。 
6. クラスター C を作成した後、同じ線形公式を使用して他のすべてのアクティブなクラスター D との衝突時間を計算し、これらのイベントをキューにプッシュします。 
7. C を作成した直後に、連鎖反応を同時に処理する必要があります。 ヒープ内の最小のイベントが C に関係し、その時間が現在のマージ時間と等しい場合、同じカスケードの一部として直ちに処理されます。 これは、その時点のイベントがなくなるまで続きます。 

### なぜ効果があるのか

 どの時点でも、アクティブな各クラスターは、すでに結合されているすべての円の結合を正確に表します。 中心と半径は、平均化と面積合計の不変定義によって完全に決定されるため、同じタイムスタンプ内のマージ順序には依存しません。 

将来のクラスター間のマージの可能性はすべて、線形成長の下で計算された最初の接触時間によって捕捉されます。 常に最小の利用可能な時間を処理するため、2 つのクラスターが初めて接触する時間がスキップされることはありません。 遅延削除により、正確さに影響を与えることなく、古いインタラクションが確実に無視されます。 

## Python ソリューション```python
import sys
import math
import heapq

input = sys.stdin.readline

def dist(a, b):
    dx = a[0] - b[0]
    dy = a[1] - b[1]
    return math.hypot(dx, dy)

def solve():
    n = int(input())
    nodes = []

    for i in range(n):
        x, y, r, s = map(float, input().split())
        nodes.append({
            "id": i,
            "x": x,
            "y": y,
            "area": r * r,
            "s": s,
            "cnt": 1,
            "active": True
        })

    active = set(range(n))
    heap = []

    def add_event(i, j):
        if i not in active or j not in active:
            return
        d = math.hypot(nodes[i]["x"] - nodes[j]["x"],
                       nodes[i]["y"] - nodes[j]["y"])
        ri = math.sqrt(nodes[i]["area"])
        rj = math.sqrt(nodes[j]["area"])
        si = nodes[i]["s"]
        sj = nodes[j]["s"]

        denom = si + sj
        if denom == 0:
            return
        t = (d - ri - rj) / denom
        if t < 0:
            t = 0.0
        heapq.heappush(heap, (t, i, j))

    for i in range(n):
        for j in range(i + 1, n):
            add_event(i, j)

    next_id = n

    while len(active) > 1:
        t, i, j = heapq.heappop(heap)
        if i not in active or j not in active:
            continue

        # start cascade at time t
        stack = [(t, i, j)]

        while stack:
            tcur, a, b = stack.pop()

            if a not in active or b not in active:
                continue

            # merge a and b
            na = nodes[a]
            nb = nodes[b]

            x = (na["x"] * na["cnt"] + nb["x"] * nb["cnt"]) / (na["cnt"] + nb["cnt"])
            y = (na["y"] * na["cnt"] + nb["y"] * nb["cnt"]) / (na["cnt"] + nb["cnt"])

            area = na["area"] + nb["area"]
            s = max(na["s"], nb["s"])
            cnt = na["cnt"] + nb["cnt"]

            nodes.append({
                "id": next_id,
                "x": x,
                "y": y,
                "area": area,
                "s": s,
                "cnt": cnt,
                "active": True
            })

            nodes[a]["active"] = False
            nodes[b]["active"] = False
            active.remove(a)
            active.remove(b)

            active.add(next_id)

            # generate new events
            for k in list(active):
                if k != next_id:
                    d = math.hypot(nodes[next_id]["x"] - nodes[k]["x"],
                                   nodes[next_id]["y"] - nodes[k]["y"])
                    ri = math.sqrt(nodes[next_id]["area"])
                    rk = math.sqrt(nodes[k]["area"])
                    denom = nodes[next_id]["s"] + nodes[k]["s"]
                    if denom > 0:
                        tt = (d - ri - rk) / denom
                        if tt < 0:
                            tt = 0.0
                        heapq.heappush(heap, (tt, next_id, k))

            next_id += 1

            # continue cascade at same time tcur
            while heap:
                tt, u, v = heap[0]
                if abs(tt - tcur) > 1e-12:
                    break
                heapq.heappop(heap)
                if u in active and v in active:
                    stack.append((tcur, u, v))

    # final cluster
    last = next(iter(active))
    print(f"{nodes[last]['x']:.10f} {nodes[last]['y']:.10f}")
    print(f"{math.sqrt(nodes[last]['area']):.10f}")

if __name__ == "__main__":
    solve()
```このソリューションはクラスターを段階的に構築し、常に最初の有効な衝突をマージします。 各マージでは、合計面積の保存と中心の一様平均から得られる、中心と半径の正確な幾何学的再構成を備えた新しい集約ノードが作成されます。 

カスケード処理は、同じタイムスタンプで発生するヒープ イベントを繰り返し消費することによって実行され、時間が進む前に完全なオブジェクトが確実に解決されます。 

## 実用的な例

 2 番目のサンプルを考えてみましょう。複数の円が連鎖反応によって最終的に結合します。 ヒープには、最初は線形成長から計算されたすべてのペアワイズ衝突時間が含まれています。 最小の時間は、最初に接触したペアに対応します。 

| ステップ | アクティブなクラスター | 処理されたイベント | 時間 |
 | --- | --- | --- | --- |
 | 1 | A、B、C、D、E | AB | t |
 | 2 | F、C、D、E | F-C (カスケード) | t |
 | 3 | G、E | G-E | t |

 各マージの後、新しいクラスターが導入され、すぐに残りのクラスターと比較してチェックされます。 同じタイムスタンプのすべてのマージは、単一のカスケードに吸収されます。 

トレースは、その時点で接続されているマージ コンポーネント全体が解決されるまで、アルゴリズムが時間を進めないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n^2 \log n)$| それぞれの$O(n^2)$ペア イベントは 1 回挿入され、各ヒープ操作には対数的な時間がかかります。 
| スペース |$O(n^2)$| 優先キューには、潜在的なペアの相互作用がすべて保存されます。 

境界は簡単に十分です$n \le 100$。 最悪の場合でも、ヒープには数千のイベントしか含まれず、マージのたびにアクティブなクラスターの数が減ります。

 ## 特殊なケース

 重要なエッジ ケースは、新しく形成されたクラスターが、まったく同じタイムスタンプで別のクラスターにすぐに接触する場合です。 アルゴリズムは、進行する前に現在時刻を共有するヒープ イベントを繰り返し処理することでこれに対処します。 これにより、接触する円の完全に接続されたコンポーネントが 1 つのオブジェクトにマージされることが保証されます。 

もう 1 つの特殊なケースは精度です。 時間は浮動除算を使用して計算されるため、同じ瞬間に発生するはずのイベントがわずかな数値誤差によって異なる場合があります。 このソリューションは、カスケードを処理するときに、ほぼ等しいタイムスタンプを同一のものとして扱うことでこれを処理します。 

最後のエッジ ケースは、2 つを超えるサイズのクラスターが 1 つのイベント チェーンで形成されることです。 すべてのマージでは、含まれるすべての円からジオメトリが再計算されるため、同じタイムスタンプ内のマージ順序に関係なく、中心と半径は正確な集計のままになります。
