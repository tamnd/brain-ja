 ## 解決策
 ## 問題の理解

 1 から m までの数字がランダムに並べられます。 m 個の異なるトークンをシャッフルし、それらを 1 つずつ明らかにすることと考えてください。 

これに加えて、n 個の互いに素な数字のペアで構成される「カード」が与えられます。 1 から m までの各数値は最大 1 つのペアで出現するため、構造は別個の頂点上の n 個のエッジのセットとなり、残りの m − 2n 数値は使用されません。 

ペアは、その 2 つの数字のうち少なくとも 1 つが明らかにされたシーケンスに現れるとすぐに完了したとみなされます。 すべてのペアが完成する瞬間が p 番目の明らかにされた番号で正確に発生した場合、プレーヤーは正確に勝ちます。 これは 2 つの同時条件を意味します。 最初の p 番号が明らかになった後、すべてのペアが少なくとも 1 回はヒットしています。 最初の p − 1 数値が明らかになった後、少なくとも 1 つのペアはまだ完全に手付かずであり、p 番目のステップで、最後の欠けているペアが完成します。 

タスクは、1 から m までの一様にランダムな置換でこのイベントの確率を計算し、それを縮小分数として出力することです。 

制約は十分に小さいため、ペアのサブセットに対する指数関数的推論が可能です。 重要なパラメーターは m ≤ 33 で、これは n ≤ 16 を意味します。これは、ペア マスクに対する 2^n 包含-除外や DP など、ペアのサブセットを反復するアプローチが実行可能であることを直ちに示唆します。 ただし、順列または数値のサブセットを直接反復処理することは不可能です。 m = 33 であっても成長が早すぎます。 

p = 0 の場合、微妙なエッジ ケースが発生します。この場合、描画の前にすべてのペアがすでに完了しているかどうかを確認します。これは、n = 0 の場合にのみ可能です。もう 1 つのエッジ ケースは、p が小さすぎて n ペアをカバーできない場合です。これは、各ステップで完了できる新しいペアが最大 1 つであるため、一部の構成が不可能になり、確率がゼロになります。 

## アプローチ

 ブルートフォース解釈では、m 個の数値のすべての順列を列挙し、プロセスをシミュレートし、最後のカバーされていないペアがステップ p で正確にカバーされるかどうかをチェックします。 これは概念的には正しいですが、すぐには実行不可能です。 m = 20 でもすでに m になります。 天文学的に大きく、ここでの m は 33 にもなります。 

この問題を解決できる構造は、イベントが最初の p − 1 の位置にどの数値が現れるか、およびどの要素が位置 p にあるかにのみ依存するということです。 残りのサフィックスの内部順序は、有効性には影響せず、多重度をカウントする場合にのみ重要です。 

これにより、順列から組み合わせ分解に切り替えることができます。最初の p − 1 要素を表すサイズ p − 1 の集合 T と、T から独立した位置 p の単一要素 x を選択します。そのようなペア (T, x) はすべて、正確に (p − 1) に対応します。 ・（m−p）！ T とサフィックスの内部順序は自由に並べ替えることができるため、並べ替えが可能です。 

ここで、セットに関して条件を再定式化します。 両方の端点が T に存在しないペア k が 1 つだけ存在する必要があります。他のすべてのペアは、T に少なくとも 1 つの端点を持たなければなりません。さらに、時刻 p に正確に完了するように、x はその特別なペア k に属している必要があります。 

中核となる困難は、1 つのペアを完全に回避しながら、1 つを除くすべてのペアに「ヒット」するサイズ p − 1 のサブセット T を数えることになります。 n ≤ 16 であるため、特別なペア k を固定し、残りの n − 1 ペアに対して包含-排他を使用して有効な T をカウントできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順列を列挙する | O(m!) | お(1) | 遅すぎる |
 | ペアに対するサブセット + 包含/除外 | O(n · 2^n) | O(2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 最後にアクティブになるペアを修正することで、ソリューションを構築します。

1. ペア k を「ステップ p 前の最後のカバーされていないペア」の候補として固定します。 k の両方の要素が最初の p − 1 位置に存在せず、そのうちの 1 つが位置 p に現れると仮定します。 
2. 最初の p − 1 位置の使用可能な要素のプールを定義します。 このプールには k の 2 つの要素を除くすべての数値が含まれるため、サイズは m − 2 になります。 
3. ここで、他のすべてのペア j ≠ k がその 2 つの要素の少なくとも 1 つを T に寄与するように、このプールから抽出されたサイズ p − 1 のサブセット T を数えます。これは、ペアに対する標準的な制約をカバーします。 
4. 残りの n − 1 ペアに対して包含-排他を使用します。 これらのペアのサブセット S について、T が S 内のすべてのペアの両方のエンドポイントを回避する構成をカウントします。S が選択された場合、2|S| が削除されます。 プールから要素を取り除き、m − 2 − 2|S| を残す 利用可能な選択肢。 この制限された宇宙で T を選択する方法の数は C(m − 2 − 2|S|, p − 1) です。 包含排他符号は (−1)|S| です。 
5. すべての S を合計すると、この固定 k に対する有効な T の数が得られます。 
6. 有効な T ごとに、ペア k の 2 つの端点に対応して、p 番目の要素 x を正確に 2 つの方法で選択できます。 
7. 各構成 (T, x) は (p − 1) に対応します。 T の内部置換と (m − p)! 接尾辞の順列。 それに応じて乗算します。 
8. k のすべての選択肢を合計し、m で割ります。 最低条件での最終確率を取得します。 

正しさは、「k を除くすべてのペアが T でヒットする」というイベントが、まさに n − 1 個の独立した 2 要素セットにわたるヒット条件であり、包含排他がきれいに解決されるという事実にかかっています。 

### なぜ効果があるのか

 このプロセスでは、順列が 3 つの独立したコンポーネント、つまりサイズ p − 1 のサブセット、識別された p 番目の要素、および接尾辞の順列に分離されます。 条件は、プレフィックスにどの要素が含まれるか、および各ペアが少なくとも 1 回ヒットするかどうかによってのみ決まります。 各ペアはちょうど 2 つの要素に寄与し、n が小さいため、ペア間の依存関係は、ペア回避イベントに対するサブセットの包含と除外によって完全に捕捉されます。 プレフィックス内の順序付け情報はメンバーシップを超えた有効性に影響を与えないため、削減は効果的です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def nCk(n, k):
    if k < 0 or k > n:
        return 0
    k = min(k, n - k)
    num = 1
    den = 1
    for i in range(k):
        num *= (n - i)
        den *= (i + 1)
    return num // den

def solve():
    m, n, p = map(int, input().split())

    if n == 0:
        return "1/1" if p == 0 else "0/1"
    if p == 0:
        return "0/1"

    if p < n:
        return "0/1"

    pairs = n
    others = pairs - 1

    # factorials for counting permutations
    fact = [1] * (m + 1)
    for i in range(1, m + 1):
        fact[i] = fact[i - 1] * i

    prefix_fact = fact[p - 1]
    suffix_fact = fact[m - p]

    favorable = 0

    for k in range(pairs):
        # inclusion-exclusion over remaining pairs
        res = 0
        for mask in range(1 << others):
            bits = 0
            avail = m - 2
            for j in range(others):
                if mask & (1 << j):
                    bits += 1
                    avail -= 2

            ways = nCk(avail, p - 1)
            if bits % 2 == 1:
                res -= ways
            else:
                res += ways

        # two choices for the p-th element
        res *= 2

        favorable += res

    favorable *= prefix_fact * suffix_fact

    total = fact[m]

    g = gcd(favorable, total)
    favorable //= g
    total //= g

    return f"{favorable}/{total}"

if __name__ == "__main__":
    print(solve())
```この実装は、組み合わせ分解を直接反映しています。 階乗は、有効な接頭辞と接尾辞の分割のそれぞれに対応する順列の数を考慮するために使用されます。 包含/除外ループは、残りのペアのサブセットを列挙し、それに応じて利用可能な要素プールを調整します。 

微妙な点は、選択された最終ペア k がプレフィックスから完全に除外されるため、プール サイズが m − 2 から始まることです。 包含-排他サブセット内の除外された各ペアは、ちょうど 2 つの要素を削除します。これが、項 m − 2 − 2|S| の理由です。 が表示されます。 

## 実用的な例

 ### 例 1

 入力:```
10 4 5
```最後のペア k の候補を決定します。 そのペアについては、その 2 つの要素を除外し、最初の 4 つの位置に 8 つの要素を残します。 包含排除を使用して、残りの 3 ペアにヒットするサイズ 4 のサブセットをカウントします。 有効な各サブセットは、最終位置の 2 つの選択肢に対応します。 

| ステップ | 意味 | 値 |
 | --- | --- | --- |
 | プールサイズ | m−2 | 8 |
 | プレフィックス サイズ | p − 1 | 4 |
 | 有効な T カウント | ペア上の IE | 計算値 |
 | x の選択肢 | k | のエンドポイント 2 |

 すべての k を合計し、10! で正規化すると、結果は 8/45 に単純化され、予想される出力と一致します。 

この例は、複数のペアが最終的にカバーされないペアになるために競合し、k にわたる対称性が n の乗算係数に寄与することを示しています。 

### 例 2

 入力:```

```ここでは p = 3 ですが、ヒットする必要があるペアが少なくとも 4 つ存在します。 各プレフィックス要素は最大でも 1 つのペアをカバーできるため、2 回のドローの後、1 つのペアを除くすべてのペアがすでにヒットしていることは不可能です。 サイズ 2 のサブセットは 4 ペアから 1 を引いたものを完全にカバーできないため、包含と除外の合計はゼロになります。 

| ステップ | 意味 | 値 |
 | --- | --- | --- |
 | カバーする必要のあるペア | n | 4 |

 ## 特殊なケース

 n = 0 の場合は、満たすべき制約がないため、個別に処理されます。 唯一の有効な結果は、p = 0 での即時成功です。それ以外の場合は、「最終完了の瞬間」が存在しないため、確率はゼロです。 

p < n の場合は構造的に不可能です。なぜなら、少なくとも n 個の異なるペアに触れる必要があり、各プレフィックス要素が最大 1 つの新しいペアの完成に寄与できるからです。 アルゴリズムは、組み合わせ作業の前にこれらのケースを正しく排除します。 

最後のペア k の除外は重要です。 誤ってプレフィックス内にその要素を許可すると、最後のペアが早く完了する構成が過大にカウントされ、「正確に p」条件に違反します。
