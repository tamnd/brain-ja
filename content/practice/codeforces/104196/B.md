 ## 解決策
 ## 問題の理解

 各章にページコストが設定されている章のコレクションが与えられます。 「章 a は章 b の前に読まれなければならない」という形式の有向依存関係があり、各章は最大でも 1 つの前の章に依存できます。 この制限は、各章には最大でも 1 つの前提条件があることを意味するため、依存関係グラフは任意ではなく、前提条件から後の章に向かうルート付きツリーのコレクションになります。 

一部の章には送信依存関係がありません。 これらは「頂点」の章であり、学習パスの終点であることを意味します。 最後の章を読むには、学生はその章と、前提条件のリンクを介してその章に到達するために必要なすべての章を、依存関係チェーンの最初にまで遡って読む必要があります。 

課題は、共通の前提条件を 1 回だけ数えて、読まなければならない総ページ数が最小限になるように、2 つの異なる最終章を選択することです。 

出力は単一の整数です。これは、選択された 2 つの最終的な章の前提条件の結合をカバーするために必要な最小合計ページ数です。 

各章には最大でも 1 つの前提条件があるため、各ノードには最大でも 1 つの次数があります。 これにより、グラフが根付きの木の森の中に強制的に配置されます。 各ノードは正確に 1 つのツリーに属し、最終的な各章はそのツリーの葉になります。 主要な構造は、各リーフがツリーのルートへの一意のパスを持っていることです。 

制約 n ≤ 1000 は十分小さいため、O(n²) または O(n² log n) の解が実行可能です。 これは、ノードごとに情報を事前計算してから、最終的なチャプターのすべてのペアを試行できることをすぐに示唆しています。 

DFS または BFS を使用して各リーフの完全な前提条件セットを再計算する単純なアプローチでは、共有プレフィックスを繰り返し走査することになります。これは冗長ではありますが、この規模では依然として通過します。 ただし、完全に正しく効率的なソリューションでは、パス計算を再利用する必要があります。 

選択した両方の頂点の章が同じツリー内にある場合、微妙な特殊なケースが発生します。 その場合、それらの前提条件セットが大きく重複するため、それらを個別にカウントすると、共有祖先が二重にカウントされることになります。 もう 1 つのエッジ ケースは、選択された 2 つのリーフが異なるツリーに属しており、重複がまったくなく、結合が単純に加算される場合です。 

## アプローチ

 ブルートフォース手法では、頂点に達する各章を開始点として扱い、ルートに到達するために必要なすべての前提条件を繰り返したどって、訪問したノードをセットに蓄積します。 最終的なチャプタのペアごとに、2 回のトラバーサルを実行して結果をマージすることで、必要なチャプタの結合を再計算できます。 最悪の場合、各トラバーサルは O(n) 個のノードに接触し、最大 O(n²) 個のペアが存在する可能性があり、最悪の場合は O(n³) 個の動作が発生します。 

重要な観察は、次数制約から得られます。 各ノードには最大でも 1 つの前提条件があるため、すべてのノードは上向きの 1 つの単純なチェーン上に存在します。 これは、上向きに分岐するパスがないことを意味するため、頂点に達する各章は単一の根から葉へのパスに対応します。 各ツリーをルート化すると、すべてのノードの親と深さを計算でき、ルートからそのノードまでのページ合計の合計も事前計算できます。 

この構造では、頂点に達する各章は、既知のパス合計を持つ単なるリーフになります。 唯一の複雑な問題は、2 つのリーフが祖先を共有する場合ですが、これは最小共通祖先推論を使用して処理できます。 各ノードには 1 つの親があるため、親ポインターと O(高さ) での深さの位置合わせを使用して LCA を計算できます。これは n ≤ 1000 で許容されます。 

これにより、問題は、リーフのすべてのペアを評価し、プレフィックスの合計とオーバーラップ減算を使用して 2 つのルートからリーフへのパスの和集合コストを計算することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ペアごとにセットを再計算) | O(n3) | O(n) | 遅すぎる |
 | ツリー前処理 + ペアワイズ LCA | O(n²) | O(n) | 承認済み |

## アルゴリズムのチュートリアル

 グラフを親表現に変換し、各ノードが最大 1 つの入力エッジを持つという事実を利用します。 

### ステップ

 1. 隣接構造を構築し、各ノードの親を計算します。 各ノードには最大でも 1 つの前提条件があるため、ノードごとに 1 つの親ポインターを保存できます。 
2. 頂点に達するすべてのチャプタを、出力エッジのないノードとして識別します。 まさに森の紅葉です。 
3. 各ルート (親のないノード) に対して、トラバーサルを実行して、ルートからすべてのノードまでのページの深さとプレフィックスの合計を計算します。 ノードのプレフィックスの合計は、依存関係チェーンの開始点からそのノードに到達するために必要なページの合計を表します。 
4. すべてのノードについて、その親ポインタと深さを保存します。これにより、必要に応じて最も低い共通祖先を計算できるようになります。 
5. 最終的な章のすべてのペアを繰り返します。 
6. 各ペアについて、両方のノードが同じ深さになるまで深いノードを上に持ち上げ、次にそれらが出会うまで両方を一緒に上に移動することにより、最も低い共通祖先を計算します。 
7. プレフィックス合計を使用して結合コストを計算します。 LCA が l、ノードが u および v の場合、総コストは次のようになります。 

プレフィックス[u] + プレフィックス[v] − プレフィックス[l]。 
8. すべてのペアの最小値を追跡し、出力します。 

### なぜ効果があるのか

 頂点に達する各章は、まさに 1 つの根から葉へのパスに対応します。 したがって、必要なチャプター セットは、まさにそのパスに沿ったノードになります。 このような 2 つのセットの結合は、最下位の共通祖先で終わる共有プレフィックスに沿ってのみ重複する可能性がある 2 つのパスで構成されます。 上向きの分岐がないため、このプレフィックスの外側に複数の共有サブ構造が存在する可能性はありません。 プレフィックス合計表現により、各パス コストが独立して格納されることが保証され、LCA での重複を減算することで、共有ノードごとに 1 回だけ二重カウントが回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    pages = list(map(int, input().split()))

    parent = [-1] * n
    children = [[] for _ in range(n)]
    has_child = [False] * n

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        parent[b] = a
        children[a].append(b)
        has_child[a] = True

    roots = [i for i in range(n) if parent[i] == -1]

    depth = [0] * n
    pref = [0] * n

    sys.setrecursionlimit(10**7)

    def dfs(u, p):
        for v in children[u]:
            depth[v] = depth[u] + 1
            pref[v] = pref[u] + pages[v]
            dfs(v, u)

    for r in roots:
        depth[r] = 0
        pref[r] = pages[r]
        dfs(r, -1)

    leaves = [i for i in range(n) if not children[i]]

    def lca(u, v):
        while depth[u] > depth[v]:
            u = parent[u]
        while depth[v] > depth[u]:
            v = parent[v]
        while u != v:
            u = parent[u]
            v = parent[v]
        return u

    ans = float('inf')

    for i in range(len(leaves)):
        for j in range(i + 1, len(leaves)):
            u, v = leaves[i], leaves[j]
            a = lca(u, v)
            cost = pref[u] + pref[v] - pref[a]
            ans = min(ans, cost)

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず親配列を使用してフォレストを再構築し、次に各ルートから DFS で深さとプレフィックスの合計を計算します。 プレフィックス合計の定義は、各ノードに独自のページ コストが 1 回含まれるように選択され、パスの集約が簡単になります。 

LCA 機能は、上向きポインター リフティングを使用して実装されます。 グラフの深さは最大でも n であるため、制約の下ではこれで十分であり、バイナリ リフティングの複雑さを回避できます。 

最後に、頂点に達するすべての章が列挙され、すべてのペアがチェックされます。 各ペアについて、LCA 計算後の一定時間内に結合コストが計算されます。

 ## 特殊なケース

 重要なケースの 1 つは、選択された両方の最高潮の章が同じ長いチェーン上にある場合です。 その状況では、すべての祖先が共有され、結合コストはより深いノードのコストにまで縮小するはずです。 LCA 減算により、共有プレフィックス全体が 1 回だけ削除されることが保証されます。 

もう 1 つのケースは、グラフが多数の小さな独立したツリーで構成されている場合です。 ここでは、重複は存在せず、アルゴリズムは 2 つの最小の根と葉の和を選択することになります。 ペアごとの列挙はこれを自然に捉えます。 

最後のケースは、木が極端に歪んでいる場合です。 それでも、構造が単一の親チェーンを保証するため、深さベースの LCA リフティングは引き続き機能し、上向きのトラバースは曖昧さなく常に正しく収束します。
