 ## 解決策
 ## 問題の理解

 1 から n までの数値のすべての順列を調べ、各順列に含まれる反転数を計算し、すべての順列にわたってそれらの反転数を合計するように求められます。 

順列における反転は、単純に、大きい数が小さい数よりも先に現れる位置のペアです。 順列ごとに、そのようなペアをカウントし、サイズ n! の順列空間全体にわたってこのカウントを集計します。 

したがって、各テスト ケースの出力は単一の数値、つまり長さ n のすべての置換によって寄与される反転の合計数になります。 

この制約は、テスト ケースの数が最大 10^6 と極端であり、n 自体も最大 10^6 になります。 これにより、順列を反復したり、テストごとに階乗サイズの推論を構築したりするアプローチは即座に排除されます。 ソリューションでは、事前計算後に各クエリを O(1) または O(log n) に減らす必要があります。そうでない場合は合格しません。 

ここでよく見られる素朴な誤解は、順列ごとの反転数を計算したり、スワップをシミュレートしようとしたりすることです。 n! 以来、順列の生成という観点から考えるだけでもすでに遅すぎます。 n = 10 では実現可能性を超えて増大します。 

微妙なエッジ ケースは n = 1 です。順列は 1 つだけであり、ペアは存在しないため、答えは 0 でなければなりません。n で割る式や、ペアごとに少なくとも 1 つの反転を仮定する式は、依然としてこの基本ケースを尊重する必要があります。 

## アプローチ

 直接的なアプローチでは、すべての順列を列挙し、反転を個別にカウントします。 各順列について、標準的な O(n^2) スキャンによって反転が検出されます。 んがあるから！ これは O(n! · n^2) となり、n = 10 の場合でもすぐに爆発します。 

重要な観察は、グローバルな順列について考えるのをやめ、代わりに、i < j である位置 i と j の単一の固定ペアを分析することです。 すべての順列にわたって、このペアが反転に寄与する頻度はどれくらいでしょうか?

 個別の値 x と y のペアを修正します。 すべての順列にわたって、対称性から、順列のちょうど半分では x が y の前に現れ、残りの半分では y の後に現れることが分かります。 これは、任意の順列で x と y を交換すると、そのペアが反転を形成するかどうかを反転する全単射が作成されるためです。 

したがって、順序付けされていないすべての値のペアについて、合計反転への寄与は同一であり、純粋に組み合わせによるものです。 

同等の視点が 2 つあります。 1 つは位置を固定することです。インデックスの各ペアは均等に寄与します。 もう 1 つは値を固定することです。値の各ペアは順列全体にわたって対称的に動作します。 価値ベースのビューはより明確です。 

異なる要素の任意のペア (a、b) については、すべての順列にわたっていずれかの順序で同じ頻度で表示されます。 あるよ！ 順列は合計で、ちょうど半分が a を b の前に置きます。 a が b の後に来る場合、そのペアは 1 回の反転に寄与します。 

したがって、順序のない各ペアは正確に n! に寄与します。 / 反転計2回。 

このようなペアは C(n, 2) 個あるため、最終的な答えは次のようになります。 

C(n, 2) · n! / 2

 次のように単純化できます。 

C(n, 2) = n(n−1)/2

 したがって、答え = n(n−1)/2 · n! / 2 = n(n−1)n! / 4

 これにより、問題は n までの階乗の計算とクエリごとの単純な算術の乗算に軽減されます。 

t が大きく、計算を繰り返すのは無駄であるため、すべてのテスト ケースにわたって最大 n までの階乗を事前計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n^2) | O(n) | 遅すぎる |
 | 最適 | O(最大 n + t) | O(最大n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ここで、組み合わせ公式を実用的な計算戦略に変換します。

1. すべてのテスト ケースを読み取り、その中の最大 n を決定します。 これにより、階乗は必要な制限まで 1 回だけ計算されるようになります。 
2. 反復乗算を使用して、1 から最大 n までの階乗を事前計算します。 各階乗は前の階乗から直接構築されるため、繰り返しの再計算が回避されます。 
3. テスト ケース n ごとに、式 n(n−1)n! を使用して答えを計算します。 / 4.
 4. 各テスト ケースの結果を出力します。 

唯一の微妙な点は、整数演算が正確であることを保証することです。 すべての値は整数ですが、n(n−1)n! であるため、4 による除算は正確でなければなりません。 n ≥ 2 の場合、は常に 4 で割り切れます。n = 0 または 1 の場合、直接 0 を返します。 

### なぜ効果があるのか

 順序付けされていない値のペアはすべて、対称性により、すべての順列にわたって同じように動作します。 任意の 2 つの値の間の交換操作では、順列が同じサイズのクラスに分割され、そのペアの順序が反転します。 これにより、各ペアが反転としてすべての順列のちょうど半分に寄与することが保証されます。 すべてのペアを合計すると、順列内の構造に依存しない均一な閉形式の式が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = None  # no modulus specified

t = int(input())
ns = []
max_n = 0

for _ in range(t):
    n = int(input())
    ns.append(n)
    if n > max_n:
        max_n = n

fact = [1] * (max_n + 1)
for i in range(1, max_n + 1):
    fact[i] = fact[i - 1] * i

def solve(n):
    if n < 2:
        return 0
    return fact[n] * n * (n - 1) // 4

out = []
for n in ns:
    out.append(str(solve(n)))

print("\n".join(out))
```階乗配列は 1 回だけ事前計算されるため、最大 10^6 のクエリにわたる再計算が回避されます。 その後、各クエリは定数時間の算術式に変換されます。 

n ≥ 2 の場合、n! のうち、4 による除算は安全です。 順列、対称性により n(n−1)n! これにより、浮動小数点の問題が回避され、正確な整数出力が保持されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    t = int(input())
    ns = []
    mx = 0
    for _ in range(t):
        n = int(input())
        ns.append(n)
        mx = max(mx, n)

    fact = [1] * (mx + 1)
    for i in range(1, mx + 1):
        fact[i] = fact[i - 1] * i

    def solve(n):
        if n < 2:
            return 0
        return fact[n] * n * (n - 1) // 4

    return "\n".join(str(solve(n)) for n in ns)

 ## 特殊なケース

 n = 1 の場合、インデックスのペアは存在しないため、反転カウントはゼロでなければなりません。 この式では n(n−1)n!/4 = 0 が直接与えられるため、実装では特別な処理を行わなくても安全に 0 が返されます。 

n = 2 の場合、2 つの順列 [1,2] と [2,1] があります。 2 番目のみが 1 つの反転に寄与します。 計算式は 2 × 1 × 2 となります。 / 4 = 4 / 4 = 1、列挙と正確に一致します。 

n が大きい場合、階乗値は急速に増加しますが、Python 整数は任意の精度を安全に処理します。 主なリスクはパフォーマンスです。これは、事前計算を 1 回実行し、結果をすべてのクエリで再利用することで回避されます。
