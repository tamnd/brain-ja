 ## 解決策
 ## 問題の理解

 文字列と複数の独立したクエリが与えられます。 各クエリは文字列のセグメントを指定し、そのセグメントの内部を調べることのみが許可されます。 私たちのタスクは、回文であり、可能な最大長を持つ、クエリされたセグメントに完全に含まれる単一の連続した部分文字列を見つけることです。 各クエリの答えは、その最良の回文の長さにすぎません。 

したがって概念的には、各クエリは文字列のウィンドウを定義し、そのウィンドウ内で最も強い対称パターンを検索します。 

テスト ケースごとの制約は小さく、文字列の長さとクエリの数は最大 1000 ですが、すべてのテスト ケースの合計は、n 倍 q の形式で約 100 万回の操作に達する可能性があります。 これにより、クエリごとに回文情報を最初から再計算したり、クエリごとにすべての中心を中心に拡張しようとするソリューションは即座に除外されます。 クエリごとにほぼ 2 次のソリューションでは、すでに遅すぎます。 

主な問題点は、回文はグローバル構造であるが、クエリはローカルな制限であることです。 文字列内に存在する回文は、間隔内に完全に含まれている場合にのみクエリに役立ちます。 

いくつかの特殊なケースについては、明示する価値があります。 

クエリ間隔の長さが 1 の場合、すべての文字が回文であるため、答えは常に 1 になります。 偶数長の回文のみを考慮する単純な解決策では、ここで誤って 0 が返される可能性があります。 

文字列にすべて同一の文字が含まれている場合、すべての部分文字列は回文であるため、各クエリは間隔全体の長さを返す必要があります。 中心付近の最大回文を追跡するだけで、位置全体を集計できないソリューションは、このケースを過小評価することになります。 

最良の回文が大きいものの、クエリ範囲からわずかに外れた場合は、カウントしないでください。 たとえば、`abacaba`、回文`abacaba`グローバルですが、クエリ`[2,6]`だけを考慮すべきです`bacab`、完全な文字列ではありません。 

## アプローチ

 直接的な総当たりソリューションは、各クエリを個別に処理します。 固定クエリの場合`[l, r]`、その区間内のすべての部分文字列を列挙し、最大長を維持しながら各部分文字列が回文であるかどうかを確認します。 

部分文字列が回文であるかどうかのチェックは、その長さの線形時間で行うことも、動的プログラミングで事前に計算することもできます。 いずれにせよ、単一のクエリについて大まかに調べます。$O((r-l+1)^3)$素朴に行われた場合、または$O((r-l+1)^2)$DPチェック付き。 クエリが最大 1000 件になると、最悪の場合、非常に遅くなります。 

この問題を解決できる構造は、任意の部分文字列の回文メンバーシップを一度に事前計算できることです。$O(n^2)$を再利用します。 残りの課題は、回文を検出することではなく、事前に計算された一連の「回文間隔」にわたる範囲最大クエリに答えることです。 

視点を反転させます。 「クエリごとに、どの回文が最適ですか?」と尋ねる代わりに、すべての回文部分文字列を 1 回列挙します。 各回文は、その長さに等しい値を持つ間隔になります。 次に、各クエリは、完全に含まれる最大値の間隔を要求します。`[l, r]`。 

これにより、問題は間隔にわたる 2 次元の範囲最大クエリに変換され、これを開始ごとまたは終了ごとの集計に再構築し、前処理とスパース テーブルを使用して効率的に回答できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース |$O(n^3)$クエリごとの最悪のケース |$O(1)$または$O(n^2)$| 遅すぎる |
 | 回文 + 範囲最大構造体を事前計算する |$O(n^2 \log n)$前処理、$O(1)$クエリごと |$O(n^2 \log n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 回文の検出から始まり、高速なクエリ応答で終わるソリューションを階層的に構築します。 

### ステップ 1: 回文テーブルを事前計算する

 テーブルを作ります`pal[i][j]`これは部分文字列かどうかを示します`s[i..j]`回文です。 これは標準 DP を使用して行われます。単一の文字は回文であり、2 文字の部分文字列は等しい場合は回文であり、より長い部分文字列はエンドポイントと内部の部分文字列に依存します。 

これにより、どの部分文字列が有効な回文であるかについて完全な情報が得られます。 

### ステップ 2: 回文を「r で終わる最適な」値に変換する

 各エンドポイントについて`r`、あらゆる可能な開始位置について知りたいのです。`l`、で終わる最長の回文は何ですか?`r`以降に開始します`l`。 

配列を定義します`bestStart[r][l]`意味: 次で終わるすべての回文の中で`r`そして開始します`[l, r]`、最大長はどれくらいですか。 

これを計算するには、スキャンします。`l`固定ごとに右から左へ`r`。 もし`s[l..r]`は回文であり、候補の長さに寄与します`r-l+1`。 左に移動しながら、実行最大値を維持します。`bestStart[r][l]`チェック後に一定時間で入力できます`pal[l][r]`。 

このステップでは、で終わるすべての回文を圧縮します。`r`「左制約の下でここで終わる最良の回文」に答えることができる構造にします。 

### ステップ 3: クエリをエンドポイント全体の最大範囲に変換する

 お問い合わせの場合`[l, r]`、選択した回文は次の間のどこかで終わる必要があります。`l`そして`r`。 考えられるエンドポイントごとに`e`、で終わる最高の回文はすでにわかっています。`e`以降に始まる`l`、つまり`bestStart[e][l]`。 

したがって、クエリに対する答えは次のようになります。 

全体的に最大の`e`で`[l, r]`の`bestStart[e][l]`。 

ここで問題となるのは、固定配列に対する範囲最大クエリです。`l`。 

### ステップ 4: 範囲最大クエリの前処理

 固定ごとに`l`、スパーステーブルを構築します`e`配列の場合`bestStart[e][l]`。 これにより、任意の間隔で最大のクエリに応答できるようになります`[l, r]`一定時間内に。 

以来`n`最大でも 1000、建物`n`スパーステーブルは十分効率的です。 

## なぜ機能するのか

 すべての回文部分文字列は、そのエンドポイントによって一意に決定されます`(i, j)`。 このアルゴリズムにより、そのようなすべての部分文字列が 1 回だけ考慮されることが保証されます。`bestStart[j][i]`、有効な回文が欠落することはありません。 

どのようなクエリでも、すべての候補回文は終了位置によってグループ化され、その構造により、有効な開始位置の最大値のみが取得されることが保証されます。 スパース テーブルにより、エンドポイントがスキップされなくなります。`[l, r]`したがって、すべての有効な回文の最大値が常に保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        s = input().strip()
        s = " " + s  # 1-indexed

        pal = [[False] * (n + 1) for _ in range(n + 1)]
        best_start = [[0] * (n + 2) for _ in range(n + 2)]

        for i in range(1, n + 1):
            pal[i][i] = True

        for i in range(1, n):
            if s[i] == s[i + 1]:
                pal[i][i + 1] = True

        for length in range(3, n + 1):
            for i in range(1, n - length + 2):
                j = i + length - 1
                if s[i] == s[j] and pal[i + 1][j - 1]:
                    pal[i][j] = True

        for r in range(1, n + 1):
            for l in range(r, 0, -1):
                best_start[r][l] = best_start[r][l + 1]
                if pal[l][r]:
                    best_start[r][l] = max(best_start[r][l], r - l + 1)

        LOG = 10
        st = [[[0] * (LOG + 1) for _ in range(n + 1)] for _ in range(n + 1)]

        for l in range(1, n + 1):
            for r in range(1, n + 1):
                st[l][r][0] = best_start[r][l]

            j = 1
            while (1 << j) <= n:
                for r in range(1, n + 1):
                    if r + (1 << j) - 1 <= n:
                        st[l][r][j] = max(st[l][r][j - 1],
                                          st[l][r + (1 << (j - 1))][j - 1])
                j += 1

        def query(l, r):
            length = r - l + 1
            k = (length).bit_length() - 1
            return max(st[l][r][k], st[l][r - (1 << k) + 1][k])

        for _ in range(q):
            l, r = map(int, input().split())
            print(query(l, r))

if __name__ == "__main__":
    solve()
```コードは最初に標準の回文 DP テーブルを構築します。 次に、すべての回文をエンドポイントごとに圧縮します。`best_start`。 最後に、各クエリがエンドポイントにわたる定数時間範囲最大クエリになるように、固定左境界ごとにスパース テーブルを構築します。 

ここでよくある落とし穴は、クエリに直接答えようとすることです。`pal[i][j]`実際にどの回文が含まれているかを追跡せずに`[l, r]`。 これにより、封じ込めへの依存が失われます。 「エンドベースの集計」への分離により、ソリューションに一貫性が生まれます。

 ## 特殊なケース

 次のような同一の文字列の場合`aaaaa`、すべての部分文字列は回文です。 アルゴリズムはすべてをマークします`(l, r)`DP テーブルで有効なものとして、および`best_start`全長を伝播します。 クエリが尋ねたとき`[2, 4]`、エンドポイント集約により、最大の`3`部分文字列から返されます`aaa`、密な回文領域が正しく処理されることを確認します。 

次のような単一文字のクエリの場合`[3, 3]`で`abc`、斜めのエントリーのみ`pal[i][i]`本当です。 の`best_start`配列は各位置で長さ 1 を記録し、単一のエンドポイントに対するクエリは正確に 1 を返し、すべての文字が回文であるという定義と一致します。 

次のような、最適な回文が中心を越えて広がりますが、境界を越えないクエリの場合`abacaba`と`[2, 6]`の場合、完全な回文は、その端点が区間外にあるため、自動的に除外されます。 セグメントに完全に含まれる回文のみが寄与します。`best_start`したがって、結果は最大の内部対称部分文字列に正しく変換されます。
