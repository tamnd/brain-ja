 ## 問題の理解

 サイズの配列が与えられます$2n$戦闘力を表す$2n$友達。 タスクは、全員が 1 つのチームに所属するように、メンバーを 2 つの独立したチームに分割し、両方のチームに奇数のメンバーが含まれるようにすることです。 

各チームの強さは、そのチームを内部で分類した後のメンバーの中央値として定義されます。 2 つの中央値間の絶対差ができるだけ小さくなるように分割を選択したいと考えています。 

主な難しさは、分割では 2 つのサブセットを選択するだけでなく、両方のサブセット サイズが奇数であることを確認し、任意の分割の下で中央値がどのように動作するかを理解する必要があることです。 

制約が意味するのは、$n$まで可能です$10^5$、 それで$2n$まで可能です$2 \cdot 10^5$テストごと、合計$2 \cdot 10^5$すべてのテストにわたって。 これにより、パーティションを列挙したり、サブセットをシミュレートしようとするソリューションは即座に除外されます。 平$O(n^2)$遅すぎます。 目的のソリューションは、ソートと線形またはほぼ線形のスキャンに依存する必要があります。 

「奇数サイズ」の制約により、微妙な問題が発生します。 単純な試みでは、要素を交互に配置したり、数のバランスをとったりすることで貪欲に分割しようとする可能性がありますが、そのようなアプローチでは偶発的に均等なサイズのチームが作成されたり、局所的には最適に見えても全体的には無効になる方法で中央値の不一致が発生したりする可能性があります。 

たとえば、次のような小さな配列について考えてみましょう。```
[1, 2, 3, 100]
```近い価値観をグループ化しようとすると、チームを形成する可能性があります`[1, 2, 3]`そして`[100]`。 これは奇数のサイズを満たしますが、中央値は 2 と 100 であり、大きな差が生じます。 ただし、より適切な構造化が存在し、単純で貪欲なグループ化では、すべての有効な中央値の配置が体系的に調査されるわけではありません。 

もう 1 つの落とし穴は、選択した要素間の差を最小化すると、中央値の差が自動的に最小化されると想定していることです。 中央値は、選択された代表だけではなく、各サブセット内の相対的な順序に依存します。 

## アプローチ

 ブルートフォースアプローチでは、すべての有効なパーティションが試行されます。$2n$要素を 2 つの奇数サイズのサブセットに分割し、両方の中央値を計算し、最小の差を追跡します。 指数関数的なパーティション数を無視しても、パーティションごとの中央値を計算するのはコストがかかります。 パーティションの数は次のとおりです。$2^{2n}$、たとえ小規模であっても完全に実行不可能です。$n$。 

重要な構造的洞察は、並べ替えが中央値の動作を完全に決定するということです。 配列がソートされると、中央値はランクがグローバルに固定されている要素に対応します。 本当の問題は、有効な奇数サイズのサブセットの中央値として同時に機能できる 2 つの要素を選択することになります。 

両方のサブセットが奇数でなければならないという制約が、構造を厳格にする原因です。 1つのチームに規模がある場合$2x+1$、もう一方は自動的にサイズを持ちます$2(n-x)-1$。 各中央値はそのサブセットの「中心」要素に対応します。これは、サブセットの半分がそのサブセット内の中央値の両側にあることを意味します。 これにより、バランス条件が強制されます: ランクで 1 つの中央値が選択された場合$i$、奇数のサイズを維持しながら両方のチームに分配するのに十分な要素がそれらの間にない限り、もう一方の中央値を任意に近づけることはできません。 

これは強力な再定式化につながります。配列全体をソートした後、インデックス空間で要素を対称的にペアにします。 中央値の候補を 2 つ選ぶと$a[i]$そして$a[i+n]$、それらの間の要素は、両方の中央値を有効に保ちながら、奇数サイズの制約を満たすために両方のチームに分散するのにちょうど十分です。 

したがって、最適な答えは、そのような有効なペアをすべてスキャンし、最小の差を取得することになります。

 ## アルゴリズムのチュートリアル

 1. 配列全体をソートします。 中央値は順序によって定義され、有効な中央値に関する推論はサブセットのローカル構造ではなくグローバル ランクに依存する必要があるため、並べ替えが必要です。 
2. 2 つの有効な奇数サイズのサブセットの中央値として同時に機能する要素のペアのみを考慮する必要があることに注目してください。 
3. 位置の小さい値のチームの候補中央値を修正します$i$ソートされた配列内。 残りの要素が有効な中央値を持つ 2 番目の奇数チームを形成できるようにするには、一致する中央値の順位が十分に離れている必要があります。 
4. 正しいペアリングはインデックスと一致することです$i$インデックス付き$i+n$。 このギャップはまさにそれを保証します$n$要素は選択した 2 つの中央値の間にあり、中央値の有効性を維持しながら要素を 2 つの奇数サイズのグループに分散するのに十分な柔軟性があります。 
5. 差を計算します$a[i+n] - a[i]$すべて有効な$i$から$0$に$n-1$、そして最小限のものを取ります。 
6. 見つかった最小値を返します。 

### なぜ効果があるのか

 並べ替えによりグローバル ランクが固定されるため、中央値は並べ替え順序の固定位置に対応します。 2 つの中央値候補を選択したら、各中央値がそのチーム内で小さい要素と大きい要素の数が同じになるように、他のすべての要素を割り当てる必要があります。 奇数サイズの制約により、各チームには明確に定義された中心要素を持つことが強制されます。重複競合を発生させずに両方の中央値を同時に満たす唯一の方法は、それらを正確に分離することです。$n$ソートされた配列内の位置。 これにより、両方の中央値の定義を独立して保持しながら、対称的に分布するのに十分な要素が中央領域に確実に含まれるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()

        ans = float('inf')
        for i in range(n):
            ans = min(ans, a[i + n] - a[i])

        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、中央位置が連続するインデックスに対応するように配列を並べ替えることから始まります。 ソート後、ペアのみをチェックします$(i, i+n)$、これらは、2 つの有効な奇数サイズのグループを形成するのに十分な分離を保持する唯一のペアです。 ループが走り抜ける$n$制約を考慮すると安全な候補です。 

ここでよくある間違いは、すべてのペアを反復処理したり、サブセットを明示的に構築しようとしたりすることです。 ソートされた構造はすべての有効な中央値構成を暗黙的にエンコードしているため、これは不要です。
