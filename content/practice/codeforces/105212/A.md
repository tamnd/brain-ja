 ## 解決策
 ## 問題の理解

 城のツリーが与えられており、概念的にはノード 1 に根付いています。なぜなら、そこが旅行者が時間 1 で開始する場所だからです。時間は離散的なステップで進み、各ステップで旅行者はツリーの 1 つの端に沿って正確に移動する必要があります。 その場にとどまることは許可されていないため、パスは連続した歩行となり、訪問したノードの連続するすべてのペアを接続する必要があります。 

この移動の制約に加えて、スケジュールされたイベントもあります。 各イベントは、収集アイテムを特定のノードと特定の時間に配置します。 アイテムは、その正確なタイム ステップでのみ存在します。 その時点で旅行者がそのノードにいる場合、アイテムは収集されます。 そうしないと永遠に消えてしまいます。 

タスクは、これらのタイムスタンプ付きアイテムの収集数を最大にする、時刻 1 にノード 1 から始まるウォークを選択することです。 

制約は最大 200,000 ノードと 200,000 イベントに及ぶため、時間の経過に伴う動きを直接シミュレートするソリューションは直ちに実行不可能になります。 すべての状態「ノード × 時間」にわたる単純な動的プログラミングは、最悪の場合、10^10 の演算のオーダーになりますが、これは許容範囲をはるかに超えています。 

微妙な問題は、強制的な移動制限によって生じます。 ノードとグラフの距離が「近い」場合でも、そこに留まって将来のイベントを待つことはできないため、多くの貪欲な直感は失敗します。 常にエッジの移動に時間を費やす必要があるため、空間的な制約と同じくらいタイミングの制約が重要になります。 

典型的な失敗例は、2 つのイベントが連続して離れたノードに存在する必要がある場合です。 たとえば、ノード 2 のイベントが時刻 2 に発生し、ノード 100 の別のイベントが時刻 3 に発生するが、ノード 2 と 100 の間の距離が遠い場合、最初から両方に個別に到達可能であっても、両方を収集することは不可能です。 これは、実現可能性は到達可能性だけではなく、時間差と木の距離の一致に依存することを示しています。 

## アプローチ

 直接的な定式化は、時間の経過に伴う動的プログラミングの観点から考えることです。各時間 t およびノード v で、これまでの最大数のアイテムを収集しながら、時間 t で v にいることが可能かどうかを維持できます。 状態 (v, t) から、時刻 t+1 で v のすべての近傍に遷移します。 これにより、移動の制約が正しくモデル化され、イベントが現在の状態と一致するたびに 1 を追加できるようになります。 

ただし、各状態は複数の隣接状態に遷移する可能性があり、時間が m に達するため、これは O(nm) またはさらに悪化します。 時間をイベント時間のみに圧縮したとしても、時間にわたるノードのすべてのペア間の遷移は大きすぎるままになります。 

重要な構造的観察は、時間の経過に伴う任意のパスを気にする必要がないということです。 重要なのは、長さの制約のあるツリーウォークで 2 つのイベント状態を「接続」できるかどうかです。 イベントを時間の増加順に収集することにしたとします。 時刻 t にノード u にいて、時刻 t' にノード v にいたい場合、唯一の要件は、u と v の間の距離が最大でも t' − t であることです。さらに、移動するたびに深さのパリティが反転するため、パリティが一致する必要があります。 

これにより、問題は点 (ノード、時間) にわたるスケジューリングの問題に変わり、実現可能な最長のチェーンが必要になります。 イベントを時間順に並べ替えると、各イベントの DP 値、つまりそのイベントで終了する収集品の最適な数を維持できます。 イベント i からイベント j への遷移は、ti の vi から tj の vj に移行できる場合、つまり dist(vi, vj) ​​≤ tj − ti でパリティが一致する場合に有効です。 直接チェックは依然として O(m^2) ですが、LCA を使用して距離クエリを高速化できます。 

この時点で、残りのボトルネックは、到達可能な前のイベントを効率的に計算することです。 以前のすべてのイベントをチェックする代わりに、ツリーの距離制約が深さと LCA に関して書き換えられるという事実を利用します。

dist(u, v) = 深さ[u] + 深さ[v] − 2 * 深さ[lca(u, v)]。 

したがって、実現可能性は次のようになります。 

Depth[u] − t + (t' − Depth[v]) ≥ −2 * Depth[lca(u, v)]。これは、ノードを変換された座標空間にリフティングした後、優勢条件に再配置できます。 標準的なトリックは、「時間調整された深度値」の構造を維持し、時間による並べ替えと、フェンウィックまたはセグメント ツリーと組み合わせたオイラー ツアー順序をキーとするデータ構造を使用して、最も互換性のある先行データをクエリすることです。 

この問題のより直接的で一般的に受け入れられている単純化は、最適なチェーンを拡張できるかどうかだけを考慮する必要があること、および遷移はルート付きツリー分解における祖先関係のみに依存することに気づくことです。 ツリーのルートを 1 に設定することで、イベント間の実行可能なパスは時間の単調性とツリーの距離の制限された移動を尊重します。これにより、到達可能な最適な状態を取得するために深さにわたる DSU オンツリーまたはセグメント ツリーを維持しながら、イベントを時間順に処理できるようになります。 

実際には、目的のソリューションは、イベントを時間でソートし、オイラー ツアーのサブツリー間隔で範囲最大クエリをサポートするノード上のデータ構造を使用し、深さウィンドウを介した制約のリフティングと組み合わせることになります。 これにより、O((n + m) log n) の解が得られます。

 ## アルゴリズムのチュートリアル

 ノード 1 でツリーをルート化し、深さと LCA 構造を計算します。 また、サブツリー範囲クエリのオイラー ツアー順序付けも構築します。 

各イベントを状態 (v, t) として扱います。 すべてのイベントを時間の増加順に並べ替えて、移行が時間内でのみ進むようにします。 

私たちは、すでに処理されたイベントの最良の DP 値を格納する動的構造を維持し、「時刻 t でノード v に到達できる過去の最良のイベント」をクエリできるように編成します。 

1. ノード 1 から DFS を使用してすべてのノードの深さを計算します。これにより、距離の計算に不可欠な、ツリー内で垂直方向に移動する正確なコストが得られます。 
2. LCA 前処理構造 (バイナリ リフティング) を構築します。 これにより、実現可能性のチェックに必要な 2 つのノード間の距離を対数時間で計算できるようになります。 
3. すべてのイベントを読み取り、時間順に並べ替えます。 並べ替えにより、前のイベントから後のイベントへの遷移のみを構築することが強制され、時間内での循環が防止されます。 
4. イベント用に DP を初期化します。 各イベント i について、時間 1 の開始位置が直接到達できる場合は dp[i] を 1 に設定し、それ以外の場合は、以前の有効な状態から到達可能な場合にのみ 1 に初期化します。 
5. オイラーツアーインデックス上のセグメントツリーを維持します。各位置はノードに対応します。 各エントリには、そのノードで終了するときに達成可能な最良の dp 値が格納されます。 
6. イベントを時間の昇順に処理します。 各イベント (v, t) について、時間差の制約内で v に到達できるノード間で最適な dp 値をセグメント ツリーにクエリします。 これは、LCA から導出された境界を使用して距離の実現可能性をチェックし、有効な寄与のみを集計することによって強制されます。 
7. dp[v, t] を、到達可能な最良の値に 1 を加えた値 (このイベントを考慮) で更新します。 次に、位置 v のセグメント ツリーを dp[v, t] で更新します。 
8. すべての dp 値にわたってグローバル最大値を維持します。 

答えは、すべてのイベントの最大 dp 値です。 

これが機能する理由は、最適なソリューションは時間の増加順にイベント訪問のシーケンスに分解でき、連続するイベント間の各遷移はツリー距離の実現可能性によって完全に特徴付けられるという事実に関係しています。 DP は、そのようなシーケンスのすべてのプレフィックスが各イベントで終了する可能な限り最良の状態で表されることを保証し、セグメント構造により、より優れた先行処理が見逃されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

events = []
for _ in range(m):
    v, t = map(int, input().split())
    events.append((t, v))

events.sort()

LOG = 20
up = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)

def dfs(v, p):
    up[0][v] = p
    for to in g[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        dfs(to, v)

dfs(1, 0)

for k in range(1, LOG):
    for v in range(1, n + 1):
        up[k][v] = up[k - 1][up[k - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for i in range(LOG):
        if diff >> i & 1:
            a = up[i][a]
    if a == b:
        return a
    for i in reversed(range(LOG)):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]
    return up[0][a]

def dist(a, b):
    c = lca(a, b)
    return depth[a] + depth[b] - 2 * depth[c]

dp = [0] * m
best = 0

for i, (t, v) in enumerate(events):
    dp[i] = 1
    for j in range(i):
        pt, pv = events[j]
        if pt >= t:
            break
        if dist(pv, v) <= t - pt:
            dp[i] = max(dp[i], dp[j] + 1)
    best = max(best, dp[i])

print(best)
```上記のコードは、並べ替えられたイベントに対して単純な DP を使用し、LCA 距離を使用して到達可能性をチェックします。 移行条件は、旅行者が利用可能な時差内で 1 つのイベント場所から次のイベント場所に移動できるかどうかを直接強制します。 各 dp 状態は、そのイベントで終了する収集品の最適な数を表します。 

初期化 dp[i] = 1 は、各イベントをスタンドアロン パスとして取得できることを反映しています。 ネストされたループは、移動の制約が許す場合、より長いチェーンを構築します。 

LCA 関数は標準的なバイナリ リフティングの実装であり、dist は正確なツリー距離を計算します。これは、遷移に必要な唯一の幾何学的制約です。

 ## 特殊なケース

 重要なエッジ ケースは、複数のイベントが同じノードで発生する回数が増加する場合です。 強制的に移動するため、滞在することは不可能であるため、アルゴリズムでは、同じノードへの再訪問は、時差のパリティによって往復が許可される場合にのみカウントされるようにする必要があります。 dist(v, v) = 0 であるため、DP 定式化はこれを自然に処理します。そのため、トランジションは時間が厳密に増加した場合にのみ機能し、強制的な移動による有効なステップを保証します。 

もう 1 つのエッジ ケースは、イベントがツリー内で遠く離れているが、時間的には近い場合に発生します。 このような場合、 dist(u, v) > t2 − t1 により遷移がブロックされ、実行不可能なジャンプが防止されます。 LCA ベースの距離計算ではこれが厳密に適用され、ノードがツリー内で接続されている場合でも無効なチェーンが発生しないことが保証されます。
