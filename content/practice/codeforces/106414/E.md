 ## 解決策
 ## 問題の理解

 私たちは、`n`による`m`グリッド。 パスは左下のセルから始まり、右上のセルで終わる必要があります。 移動するたびに、パスは 1 セル上、1 セル左、または 1 セル右に進みます。 決してダウンすることはなく、セルを 2 回踏むこともできません。 タスクは、答えを法にして、異なる有効なパスがいくつ存在するかを数えることです。`998244353`。 

移動ルールの重要な部分は、行番号は減少することしかできないということです。 パスが上に移動して列を離れると、その列に戻ることはありません。 これは、すべての行を独立して考慮することができ、ある行から次の行に渡される情報は、パスが上に移動する列だけであることを意味します。 

制約により許可されるのは、`n`そして`m`テスト ケースが多数あるため、最大 100 まで大きくなります。 パスの数は指数関数的に増加するため、すべてのパスを探索するソリューションは不可能です。 数学的パターンを見つけて直接計算する必要があります。 答えには累乗と剰余演算のみが含まれるため、`O(n)`または`O(log n)`解決策で十分です。 

よくある間違いは、柱に到達した後、パスが真っ直ぐ上に移動することを強制されると考えることです。 たとえば、`2 x 3`グリッドでは、答えは 1 ではありません。一番下の行は、開始列 0 から列 0、1、または 2 に移動してから上に移動することができ、3 つのパスが得られます。 

もう 1 つの間違いは、行内でパスが逆になることです。 たとえば、行の列 0 から開始して列 2 に移動し、その後列 1 に戻ることは、列 1 がすでに訪問されているため無効です。 すべての行の訪問セルは、1 つの連続したセグメントを形成する必要があります。 

## アプローチ

 強引なアイデアは、考えられるすべてのパスをシミュレートすることです。 訪問した各セルから、許可されたすべての移動を試み、ターゲットに到達するか行き詰まったときに停止します。 これは有効なパスの定義に直接従うため、これは正しいです。 

問題は、選択肢の数が爆発的に増えることです。 パスは行ごとに多くの水平方向の選択を行うことができ、可能なパスの数はグリッドの寸法とともに指数関数的に増加します。 小さなグリッドでも、すぐに非常に多くの再帰的分岐が作成されます。 

重要な点は、行内のパスの動作が単純であるということです。 パスが行に入るとき、それはどこかの列にあります`x`。 上に移動する前に、任意の列を選択できます`y`出発する場所としてその列にあります。 間のセル`x`そして`y`1 つの連続した水平セグメントとして訪問されます。 水平方向を変更するにはセルを再度訪問する必要があるため、他の形状は使用できません。 

一番上の行を除くすべての行について、終了する列は次のいずれかになります。`m`列。 一番下の行は列 0 から始まりますが、まだ`m`それが離れることができる可能な列。 次の行も同様に動作します。 一番上の行を入力すると、パスは右上のセルに到達するまで水平に移動するだけなので、選択する必要はありません。 

がある`n - 1`終了列を選択する行、および各選択肢には`m`可能性。 したがって、パスの総数は次のようになります。`m^(n-1)`。

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`m`現在のグリッドの場合。 パスでは、最後の行を除くすべての行で終了列を選択できるため、計算する必要があります。`m`力を上げた`n - 1`。 
2. コンピューティング`m^(n-1)`べき乗モジュラーを使用します。 指数は入力サイズ全体で大きくなる可能性があるため、乗算を繰り返すことは意図したアプローチではありません。 
3. 計算値のモジュロを出力します。`998244353`。 

なぜ効果があるのか:

 すべての行遷移は、パスが上に向かう列によって完全に記述されます。 行を入力した後、任意の出口列を選択すると、有効な水平セグメントが 1 つだけ生成され、すべての有効なセグメントが 1 つの出口列に正確に対応します。 行は独立しており、一番上の行には遷移の選択肢がないため、可能なパスの数は次の積になります。`m`以上の選択肢`n - 1`行。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    data = input().split()
    if not data:
        return
    t = int(data[0])
    ans = []
    idx = 1
    for _ in range(t):
        n = int(data[idx])
        m = int(data[idx + 1])
        idx += 2
        ans.append(str(pow(m, n - 1, MOD)))
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```この実装では、Python に組み込まれた剰余累乗を使用します。 の`pow(base, exponent, mod)`form は 2 進累乗を実行するため、対数的に多くの演算のみが必要になります。 

指数は`n - 1`なぜなら、一番下の行とその上の一番上の行までのすべての行では、どこに上に移動するかを決定する必要があるからです。 一番上の行はパスを終了するだけであり、追加の分岐には影響しません。 

証明によってすでに問題が選択肢を数えることに限定されているため、境界チェックやシミュレーションはありません。 大きな中間値を避けるために、べき乗中にモジュロが適用されます。 

## 実用的な例

 最初のサンプルのグリッドは次のとおりです。`2 x 3`。 

| ステップ | 処理された行 | 行ごとの選択肢 | 現在のカウント |
 | --- | --- | --- | --- |
 | 開始 | Need to choose bottom row exit | 3 | 3 |
 | 仕上げ | 上の行がターゲットに到達 | 選択の余地はありません | 3 |

 答えは 3 です。3 つのパスは、一番下の行を列 0、1、または 2 のままにすることに対応します。 

For the second sample, the grid is`3 x 4`。 

| ステップ | 処理された行 | 行ごとの選択肢 | 現在のカウント |
 | --- | --- | --- | --- |
 | 開始 | 最下段の出口 | 4 | 4 |
 | 続ける | 中列出口 | 4 | 16 |
 | 仕上げ | 上の行がターゲットに到達 | 選択の余地はありません | 16 |

 最初の 2 行がそれぞれ 4 つの可能な終了列に寄与するため、答えは 16 です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log n) | べき乗剰余演算には対数的に多くの乗算が必要です。 
| スペース | お(1) | 現在の回答と入力値のみが保存されます。 

各テスト ケースに必要な高速累乗は 1 つだけで、グリッドの構築は必要ないため、このソリューションは簡単に制限に適合します。 

## テストケース```python
import sys, io

MOD = 998244353

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        out.append(str(pow(m, n - 1, MOD)))
    return "\n".join(out)

assert solution("""2
2 3
3 4
""") == "3\n16", "samples"

assert solution("""1
2 2
""") == "2", "minimum grid"

assert solution("""1
100 100
""") == str(pow(100, 99, MOD)), "large grid"

assert solution("""3
5 1
4 5
2 100
""") == "\n".join([
    str(pow(1, 4, MOD)),
    str(pow(5, 3, MOD)),
    str(pow(100, 1, MOD))
]), "boundary cases"

## 特殊なケース

 のために`2 x 3`グリッドでは、最短ルートを選択した後、開始点と終了点が同じ列に垂直に整列するため、単純なアプローチではパスが 1 つだけであると考える可能性があります。 アルゴリズムは、一番下の行が 3 つの列のいずれかで終了できることを確認し、次のように計算します。`3^(2-1) = 3`。 

列が 1 つあるグリッドの場合、次のようになります。`5 x 1`、可能な移動は上方向のみです。 式は次のようになります`1^(5-1) = 1`、単一の有効なパスと一致します。 

次のような大きなグリッドの場合、`100 x 100`、パスを列挙することは不可能です。 このアルゴリズムはパスをまったく作成せず、べき乗剰余を使用して独立した列の選択肢の数を評価するだけです。
