 ## 解決策
 ## 問題の理解

 整数のリストと目標値が与えられます。 タスクは、これら 3 つの数値の合計がターゲットにできるだけ近づくように、リストから任意の 3 つの異なる要素を選択することです。 「可能な限り近づける」とは、選択した 3 つの合計とターゲット値の間の絶対差を最小限に抑えることを意味します。要素のインデックスではなく、その最小偏差のみを考慮します。 

入力は数直線上の点の集合と考えることができ、結合された位置が固定のゴール位置に最も近い 3 つの点を選択しようとしています。 すべての有効な答えは、ローカルの隣接関係ではなく、配列のグローバル構造に依存するため、並べ替えや並べ替えによって正しさは変化せず、推論の容易さのみが変化します。 

この種の問題で一般的な制約レベルは、配列サイズが数千を超えて大きくなると、すべてのトリプルに対する 3 次列挙が遅すぎることを意味します。 すべてのトリプルをチェックするソリューションは次の順序で実行されます。$n^3$加算と比較は、すぐに実行不可能になります。$n = 10^5$あるいは$n = 10^4$。 これにより、合計を最初から再計算するのではなく、多くの組み合わせにわたって部分構造を再利用する方法が推進されます。 

複数のトリプルがターゲットと同じ絶対差を生成する場合、微妙なエッジケースが発生します。 たとえば、配列が次の場合、`[1, 2, 3, 4]`そしてターゲットは`10`、 両方`(1, 3, 4)`そして`(2, 3, 4)`同様に近い合計が得られる可能性があります。 厳密に良い場合にのみ更新する単純な実装 (`<`) 等価性を許可する代わりに (`<=`) might accidentally lock onto the first found solution and ignore other valid equal-optimal triples, which is harmless for correctness of the final numeric answer but can become dangerous if the implementation mistakenly depends on a specific selection rule for pruning.

 もう 1 つのエッジ ケースは、配列に大きな負の値と正の値が含まれる場合です。 A careless pruning strategy that assumes monotonicity without sorting can miss combinations where extreme negatives balance large positives to get closer to the target.

 ## アプローチ

 ブルートフォースアプローチは簡単です。 可能なすべてのインデックスのトリプルを反復処理します$i, j, k$、合計を計算し、それをターゲットと比較し、これまでに確認された最小の絶対差を追跡します。 これは、検索空間全体を漏れなく探索するため機能します。 その問題は純粋に計算上の問題です。トリプルの数は次のとおりです。$\binom{n}{3}$、次のように展開されます。$O(n^3)$。 と$n = 5000$、これはすでに約に達しています$2 \times 10^{10}$時間に制約のある環境では、実際の限界をはるかに超えて作業を行うことができます。 

重要な構造的観察は、トリプルの 1 つの要素を修正すると、残りの問題は固定値から導出されるターゲットを使用した 2 和の問題になるということです。 配列をソートした後、順序を利用して 2 つのポインターを内側に移動し、固定位置ごとにすべての実行可能なペアを線形時間で評価できます。 これにより、各ペアが 3 番目の要素ごとに個別に再計算されるのではなく、制御されたスイープで考慮されるため、冗長性が削減されます。 

ブルートフォース手法が機能するのは、すべての可能性を明示的に列挙するためです。 各トリプルを独立して処理するため、失敗します。 この改善は、固定された最初の要素の場合、ネストされた列挙の代わりに方向移動を使用して、ソートされた配列内で最適な相補ペアを効率的に検索できることを認識したことに由来します。

 ## アルゴリズムのチュートリアル

 1. 配列を非降順で並べ替えます。 インデックスを増加しても値を維持または増加させることしかできないため、並べ替えにより、合計を調整するときに予測可能な動きを可能にする構造が作成されます。 
2. 変数を初期化する`best_diff`非常に大きな数で。 これには、これまでに確認されたターゲットとの最小絶対差が保存されます。 
3. 各インデックスを反復処理します。`i`トリプルの最初の要素として。 それぞれについて`i`、最高のペアを探します`(j, k)`その右側にあります。 固定する`i`問題の次元が 3 つの選択肢から 2 つに減ります。 
4. 2 つのポインターを設定します。`j = i + 1`そして`k = n - 1`。 これらは、残っている最小の候補と最大の候補を表します。 和をコントロールしながら内側にスイープするという考え方です。 
5. ながら`j < k`、計算する`current_sum = a[i] + a[j] + a[k]`そして更新します`best_diff = min(best_diff, |current_sum - target|)`。 これにより、関係するすべての有効なトリプルが保証されます。`i`構造化された方法で考慮されます。 
6. もし`current_sum`目標を下回っている場合、増加します`j`。 増加中`j`配列がソートされているため、合計が増加します。これにより、合計がターゲットに向かって上方に移動します。 
7. もし`current_sum`ターゲット以上である場合、デクリメント`k`。 減少中`k`合計を減らし、ターゲットに向かって下向きに近づけます。 

ポインタの動きは重要なメカニズムです。 各ペアが次のことを保証します。`(j, k)`固定ごとに最大 1 回アクセスされます`i`、組み合わせを繰り返し再計算するのではなく。 

### なぜ効果があるのか

 固定の場合`i`、右側の配列セグメントがソートされます。 任意のペア`(j, k)`合計の単調な風景を形成します: 増加`j`合計が増加し、減少します`k`それを減らします。 2 ポインター プロセスは、改善が存在する可能性のある領域をスキップすることなく、この領域を体系的に探索します。 すべてのステップで、移動方向は、順序を考慮して現在の状況を改善できないペアのみを破棄し、潜在的に最適な構成をすべて保持します。 これにより、スキャン中に発生する最小絶対偏差がすべてのトリプルにわたって真の最適値であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, target = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    best_diff = float('inf')

    for i in range(n):
        j, k = i + 1, n - 1

        while j < k:
            s = a[i] + a[j] + a[k]
            diff = abs(s - target)
            if diff < best_diff:
                best_diff = diff

            if s < target:
                j += 1
            else:
                k -= 1

    print(best_diff)

if __name__ == "__main__":
    solve()
```実装は、単調なポインターの移動を可能にするソートから始まります。 外側のループは各トリプルの最初の要素を選択し、内側の while ループは残りの 2 つの位置に対して制約付き検索を実行します。 この問題では実際のトリプルではなく近さを求めるため、更新ステップでは最良の絶対偏差のみを追跡します。 

ここでよくある間違いは、ポインターの移動条件を逆にしてしまうことです。 もし`s < target`、移動`k`の代わりに`j`単調性の保証が破壊され、有効な構成が失われることになります。 もう 1 つの微妙な問題は、3 つのインデックスがすべて異なるものである必要があることを忘れていることです。これは、開始することで自然に強制されます。`j`で`i + 1`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        n, target = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        best_diff = float('inf')

        for i in range(n):
            j, k = i + 1, n - 1
            while j < k:
                s = a[i] + a[j] + a[k]
                best_diff = min(best_diff, abs(s - target))
                if s < target:
                    j += 1
                else:
                    k -= 1

        return best_diff

    return str(solve())

# small case
assert run("3 6\n1 2 3\n") == "0", "exact match"

# negative numbers
assert run("5 0\n-4 -1 2 5 9\n") == "0", "balanced triple"

# no good match
assert run("5 50\n1 2 3 4 100\n") == "42", "closest only"

# minimum size
assert run("3 10\n1 2 3\n") == "5", "single triple"

# duplicates
assert run("6 3\n1 1 1 2 2 2\n") == "0", "repeated values"

 ## 特殊なケース

 配列に大きな負の数と大きな正の数の両方が含まれている場合、最適な解決策は多くの場合、極端な値を組み合わせることによって得られます。 たとえば、`[-10, -5, 1, 3, 20]`ターゲット付き`0`、アルゴリズムは正しく考慮します`-10 + -5 + 20 = 5`ポインタを両端から内側に調整することで、可能な限り最も近い値に収束します。 ソートにより、特別なケースを使用せずにポインターの初期化を通じてこれらの極限に到達できることが保証されます。 

すべての数字が同じ場合、たとえば`[2, 2, 2, 2]`ターゲット付き`7`、すべての三重和は同一です。 アルゴリズムは依然として、1 つの代表セットを正確に評価します。`i`、そして最大の差は全体を通して一定のままです。 ポインタの動きがすぐに崩れてしまうので、`j`そして`k`すぐに収束する。 

最適なトリプルに 2 つの小さな値と 1 つの大きな値が含まれる場合、2 ポインター法では当然、この構成が早期に探索されます。`j`最小でも、そして`k`最大で。 たとえば、`[1, 2, 3, 100]`ターゲット付き`10`、その組み合わせ`(1, 2, 3)`最初にチェックされるのは`i = 1`最適な領域を早期に発見できるようにします。
