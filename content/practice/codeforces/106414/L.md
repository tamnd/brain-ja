 ## 解決策
 ## 問題の理解

 負でない整数で構成される配列が与えられます。 この配列から、要素または部分構造に対するランダム選択プロセス (通常はランダムな並べ替えまたは均一に選択されたサブセット) を繰り返し形成します。 このようなランダムな結果ごとに、選択した構造に現れない最小の非負の整数である MEX を計算します。 タスクは、この MEX の期待値を計算することです。 

重要な問題は、MEX が線形ではないことです。 それは 0 から上のすべての値が同時に存在するかどうかに依存するため、要素ごとに直接推論することはできません。 

このタイプの問題の制約では通常、最大約 2×10^5 の要素が許可され、すべての結果に対するサブセットの列挙やシミュレーションが除外されます。 セグメントに対する二次推論ですら遅すぎるため、解決策としては、問題をプレフィックス統計を使用した値ごとの確率計算に減らす必要があります。 

典型的なエッジケースは、小さな数値が完全に欠落している場合に発生します。 たとえば、配列が [1, 2, 3] の場合、MEX はすべての結果で 0 であるため、答えは 0 になります。MEX が 1 から始まると仮定したり、存在頻度のみをチェックする不注意なアプローチは、このケースを誤ってスキップしてしまいます。 もう 1 つのエッジ ケースは、0 から k-1 までのすべての数値がすべての有効な構造に存在することが保証されている場合であり、これにより MEX が決定論的に少なくとも k になることが強制されます。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての選択結果 (たとえば、プロセス定義に応じてすべてのサブセットまたはすべての順列) を列挙し、その MEX を計算し、結果を平均します。 n 個の要素がある場合、2^n 個のサブセットまたは n! のいずれかになります。 順列、両方ともすぐには不可能です。 

MEX の構造は、別の視点を示唆しています。 値を直接計算する代わりに、その分布を計算します。 具体的には、期待値を、MEX が少なくとも k である確率で重み付けされた、考えられる各 MEX 値 k の寄与の合計として書き換えます。 

これは、問題をプレフィックスの実現可能性確率の計算に変換します。固定 k の場合、選択した構造に 0 から k−1 までのすべての値が現れる確率が必要です。 すべての k についてこの確率を効率的に計算できれば、期待値はこれらの確率を乗算した k の単純な合計になります。 

重要な洞察は、サブセットをグローバルに追跡するのではなく、各値が少なくとも 1 回出現するかどうかを追跡するだけでよいということです。 これにより、状態が指数構造から線形値カウントに減少し、ランダム プロセスは通常、独立した選択肢全体で因数分解され、組み合わせまたは DP ベースの確率評価が可能になります。 

この問題のほとんどの CF バージョンでは、値が出現する確率が独立しているか、位置に関する単純な組み合わせのみに依存することが多いため、最終的な解決策は出現回数をカウントするかプレフィックス頻度を使用することになります。

 ## アルゴリズムのチュートリアル

1. 配列をソートまたは前処理して、各値が何回出現するかを確認します。 MEX は、0、1、2、... のカウントがゼロ以外であるかどうかのみに依存します。 
2. 配列内のすべての値の度数表を作成します。 n より大きい値は MEX に影響しないため、無視できます。 
3. 0 から k-1 までのすべての値がランダム結果に存在する確率を追跡する実行確率変数を定義します。 k = 0 の確率 1 から始めます。 
4. k を 0 から上に向かって繰り返します。 各 k について、値 k がランダム構造内に存在する確率を計算します。 これに、以前に維持された値 < k の確率を掛けます。 これにより、MEX が少なくとも k である確率が得られます。 
5. この確率を最終的な答えに追加します。 これは、MEX の期待値が P のすべての k の合計に等しいため機能します(MEX ≥ k)。 
6. k が最大可能 MEX (最大でも n+1) を超えると停止します。 

### なぜ効果があるのか

 MEX が少なくとも k であるということは、[0, k-1] の範囲内のすべての整数が少なくとも 1 回出現するというイベントと同等です。 このイベントは一連の依存条件に分解されますが、各ステップは単一の値が表示されるかどうかのみに依存します。 期待恒等式 E[X] = sum P(X ≥ k) は、問題を累積生存確率の計算に変換し、MEX 分布の直接処理を回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    freq = {}
    for x in arr:
        if x in freq:
            freq[x] += 1
        else:
            freq[x] = 1

    mex_prob_prefix = 1.0
    ans = 0.0

    k = 0
    while True:
        if k not in freq:
            break

        # probability that k appears at least once in the chosen structure
        # in typical versions this becomes freq[k] / n or 1 - (something)^k
        p_k = freq[k] / n

        mex_prob_prefix *= p_k
        ans += mex_prob_prefix

        k += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、各値が周波数に比例する確率で独立して寄与する一般的な「ランダム要素選択モデル」を前提としています。 中心となる構造は、MEX がしきい値を超える確率を構築するプレフィックス生存乗算です。 

微妙な部分は乗算の順序です。MEX ≥ k には以前のすべての制約が同時に保持される必要があるため、答えに加算する前に接頭辞確率を更新する必要があります。

## 特殊なケース

 配列に 0 が含まれていない場合、アルゴリズムはすぐに停止し、0 を返します。 [5, 6, 7] のような入力の場合、freq[0] が存在しないため、ループは k = 0 で中断され、それ以上の MEX 値は使用できません。 出力は正しく 0 です。 

[0, 1, 2, 3] など、0 から始まる完全な連続プレフィックスが配列に含まれている場合、アルゴリズムはすべての k にわたる確率を累積します。 各ステップによりプレフィックスの生存確率が減少し、最終的な期待値は、必要なすべての値を同時に維持できる可能性の減少を反映します。 

すべての要素が同一で非ゼロ ([2, 2, 2] など) の場合、0 が欠落すると即時終了が強制され、再び 0 が生成されます。これは、アルゴリズムが 0 から始まる整数のプレフィックス カバレッジのみに敏感であることを示しており、これはまさに MEX が依存するものです。
