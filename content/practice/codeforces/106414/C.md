 ## 解決策
 ## 問題の理解

 からのすべての数値を意味する順列が与えられています。`1`に`n`は 1 回だけ表示されます。 操作では、現在の配列の一部のプレフィックスを取得し、そのプレフィックスを反転して、変更されたプレフィックス全体を配列の末尾に移動します。 タスクは、操作の数を最小限に抑えることではありません。 最大でも次のシーケンスを印刷するだけで済みます。`2n`順列を昇順に変換するプレフィックスの長さ。 

入力には複数のテスト ケースが含まれています。 各テスト ケースの配列は、現在の数値の順序を表します。 出力はプレフィックス長のリストであり、これらの操作を順番に適用すると、配列は次のようになります。`[1, 2, ..., n]`。 

の合計`n`すべてのテストケース全体で最大でも`5000`。 要素の総数が少ないため、二次解は許容されます。 私たちは過ごすことができます`O(n^2)`繰り返し位置を見つけるには時間がかかりますが、多くの不必要な操作をシミュレートするソリューションは、それが時間を超えると失敗します。`2n`動作限界。 主な課題は速度ではなく、限界が保証された構造を見つけることです。 

よくある間違いは、これを通常の並べ替えと考え、プレフィックスまたはサフィックスを固定したまま要素を 1 つずつ最終位置に配置しようとすることです。 すべての操作で配列全体の先頭が変更されるため、これは機能しません。 たとえば、`[1, 4, 2, 3]`、修正後`4`最後にローカルに見える操作を行うと、後の操作で再び移動できます。 この構築では、操作のグローバル回転動作を使用する必要があります。 

もう 1 つの特殊なケースは、すでにソートされた順列です。 入力の場合:```
1
5
1 2 3 4 5
```正しい出力はゼロ操作です。 常に最後のローテーションを実行するソリューションは依然として有効ですが、不必要に作業を行うと推論が複雑になる可能性があります。 

2 番目のエッジケースは、`n = 1`。 配列はすでにソートされており、実行する有用な操作はありません。 正しい出力は次のとおりです。```
0
```実装が注意していないと、ローテーション ステップを無条件に追加しようとすると、無効なプレフィックス長が作成される可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、考えられる操作シーケンスを検索しようとします。 順列の各状態には、次のものがあります。`n`可能な動き、可能な順列の数は`n!`。 たとえメモ化を行ったとしても、状態空間は階乗的に増大するため、これはすぐに不可能になります。 操作制限は、有効なシーケンスを検索によって直接見つける必要がないことも意味します。 

重要な観察は、数字を昇順で前に持ってくると、予測可能な循環配置が作成されるということです。 値を処理するとします。`1, 2, ..., n - 1`。 値が`x`はまだ先頭にないため、直前で終わるプレフィックスを選択します`x`動く`x`前へ。 これは、変更されていないサフィックスが次で始まるため機能します。`x`、選択されたプレフィックスは反転され、その後ろに移動されます。 

以下のすべての値に対してこれを実行した後、`n - 1`、順列は完全にソートされていませんが、非常に特殊な形式になっています。```
[n - 1, n, 1, 2, ..., n - 2]
```これはソートされた配列の回転です。 プレフィックス長を使用した 2 つの操作`1`このシーケンスを回転させてソート順に戻します。 建設全体で最大で使用されるのは、`n - 1 + 2 = n + 1`操作、これは安全に下にあります`2n`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | お(ん!) | 遅すぎる |
 | 建設的なフロントビル | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の操作リストから開始します。 値を昇順に前に移動して答えを構築します。 
2. あらゆる値について`x`から`1`に`n - 1`、現在位置を見つけます`p`。 

もし`p`は最初の位置ではありません。プレフィックス長を使用して操作を適用します`p - 1`。 先ほどの要素`x`その後ろに移動されるので、`x`最初の要素になります。 もし`x`がすでに最初であるため、操作は必要ありません。 
3. すべての値を処理した後、`1`に`n - 1`、プレフィックス長を使用した操作を適用します`1`2回。 

各プレフィックス長`1`この操作により、最初の要素が後ろに移動します。 残りの回転は`[n - 1, n, 1, ..., n - 2]`に`[1, 2, ..., n]`。 

機能する理由: 値の処理後`x`、その値は、後で処理されるすべての値の前に配置されます。 したがって、先頭にある選択された値のシーケンスは昇順で構築されますが、すべての操作で配列も回転するため、最終的な配置はソートされた順列の 1 つの巡回シフトになります。 最後の 2 つの回転により、そのシフトが正確に除去されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(a):
    n = len(a)
    ans = []

    for x in range(1, n):
        p = a.index(x) + 1
        if p > 1:
            k = p - 1
            ans.append(k)
            a[:] = a[k:] + a[:k][::-1]

    if n > 1:
        ans.append(1)
        a[:] = a[1:] + a[:1]
        ans.append(1)
        a[:] = a[1:] + a[:1]

    return ans

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = solve_case(a)

        out.append(str(len(ans)))
        if ans:
            out.append(" ".join(map(str, ans)))
        else:
            out.append("")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```構築は各値の現在の位置に依存するため、実装では現在の順列が維持されます。 合計から`n`だけです`5000`を使用して`list.index`各値を見つけるのは十分に高速です。 

選択されたすべての操作後のシミュレーションは、答えを構築する際に現在の状態を維持するためにのみ実行されます。 操作自体は、最初のオブジェクトを削除するように実装されます。`k`要素を反転して、残りの接尾辞の後に配置します。 Python のスライスはこれを直接処理します。 

最後の 2 つの操作は、次の場合にのみ追加されます。`n > 1`。 単一要素配列の場合、順列はすでにソートされており、有効なプレフィックス長は次のとおりです。`1`が存在するため、これらの操作を回避すると、境界ケースがクリーンな状態に保たれます。 

## 実用的な例

 順列を考えてみましょう。```
[2, 1, 3]
```| ステップ | 処理された値 | 値の位置 | 操作 | 配列 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 |`1`|`[1, 3, 2]`|
 | 2 | 2 | 3 |`2`|`[2, 1, 3]`|
 | 3 | 最終回転 | |`1`|`[1, 3, 2]`|
 | 4 | 最終回転 | |`1`|`[3, 2, 1]`|

 このトレースは、個々の回転のシミュレーションのみが誤解を招く理由を示しています。 すべての値を処理した後の正確な状態は循環不変式に従い、構築を完了するには最後の 2 つの回転が必要です。 

考慮する：```
[1, 4, 2, 3]
```| ステップ | 処理された値 | 値の位置 | 操作 | 配列 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | なし |`[1, 4, 2, 3]`|
 | 2 | 2 | 3 |`2`|`[2, 3, 4, 1]`|
 | 3 | 3 | 2 |`1`|`[3, 4, 1, 2]`|
 | 4 | 最終回転 | |`1`|`[4, 1, 2, 3]`|
 | 5 | 最終回転 | |`1`|`[1, 2, 3, 4]`|

 この例は主なアイデアを示しています。最初のフェーズでは配列を直接並べ替えません。 回転された並べ替え順序が作成され、最後に修正されます。

 ## 特殊なケース

 すでにソート済みの順列の場合は、次のようになります。```
1
5
1 2 3 4 5
```からのすべての値`1`に`n - 1`は処理時にすでに先頭にあるため、操作は追加されません。 最後の 2 つの回転は、最初のフェーズで作成された循環シフトを修正するためにのみ必要なため、アレイがそのシフト状態に入らなかったため、省略されます。 

単一要素の場合:```
1
1
1
```使用する意味のあるプレフィックス長がないため、値のループは実行されず、最後の回転ステップはスキップされます。 答えには演算が含まれていません。 

次のような、最初から最小値が前面付近にない場合:```
1
5
5 3 1 4 2
```アルゴリズムは位置を見つけます`1`、それを前面に移動し、次のように続けます。`2`、`3`、 そして`4`。 最初のフェーズでは、最終状態がソートされたシーケンスの回転であることが保証されるため、最後の 2 つのプレフィックスの長さは`1`この操作により、特別な処理を必要とせずに並べ替えが完了します。
