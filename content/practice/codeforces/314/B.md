 ## 問題の理解

 2 つの文字列が与えられています。`a`そして`c`、および 2 つの整数、`b`そして`d`。 文字列`a`繰り返される`b`長い文字列を形成するのに何回もかかる`w`、および文字列`c`繰り返される`p`別の文字列を形成する回数`q`。 タスクは最大の整数を見つけることです`p`そのような`q`から入手できます`w`残りの文字を再配置せずに一部の文字を削除します。 言い換えると、`q`の部分列である必要があります`w`。 出力はこれが最大です`p`、 または`0`正の整数が機能しない場合。 

境界`b`そして`d`まで行く$10^7$、一方、文字列自体の長さは最大 100 です。これは、完全な文字列を明示的に構築できないことを示しています。`w`そして`q`、長さが届く可能性があるため、$10^9$。 代わりに、どのソリューションも基本文字列とその繰り返し回数を効率的に処理する必要があります。 繰り返される文字列を繰り返し構築する単純なソリューションでは、メモリ制限と実行時間の制約を超えてしまいます。 

明らかではないエッジケースとしては、次のような場合があります。`c`に存在しない文字が含まれています`a`、またはいつ`c`よりも長いです`a`そして`b`小さいです。 たとえば、次の場合`a = "abc"`、`b = 2`、`c = "abcd"`、`d = 1`、形成する方法はありません`c`一度でもから`a`2 回繰り返されるため、出力は 0 になるはずです。文字の頻度の不一致を無視する不用意な解決策や、適切な考慮なしに貪欲なアプローチを試みると、不正確な答えが生成される可能性があります。 

## アプローチ

 ブルートフォースアプローチは、次のように構築してみることです。`w`繰り返すことで明示的に`a` `b`回してから形成を試みます`q`マッチングによって`c`繰り返し。 各試行は次のように繰り返されます`w`何回数えるか`c`サブシーケンスとして適合します。 これは原理的には機能しますが、最悪の場合の複雑さは次のとおりです。$O(b \cdot |a| \cdot p \cdot |c|)$、到達できる$10^{16}$操作 - 明らかに非現実的です。 

重要な洞察は、文字列全体が必要ないということです。 問題は、何回見つけられるかを数えるということになります。`c`繰り返されるパターン内のサブシーケンスとして`a`。 インデックスと内部の推移に焦点を当てることで、`a`、どのようにシミュレーションすることができますか`c`を何度も繰り返すことで進歩します`a`効率的に。 開始位置ごとに事前計算します。`a`そして各キャラクターごとに`c`、次に一致する文字が出現します。 これにより、「ジャンプ」できるようになります。`a`文字ごとに反復することなく、線形時間の解を与えます。`|a| * |c|`。 

このアプローチでは、この事前計算されたサブシーケンス マッチングを使い果たすまで繰り返し適用します。`b`の繰り返し`a`。 結果は最大回数です`c`フィットします(`p`)、で割る`d`以来`q`は`c`繰り返された`d`回。

 ## アルゴリズムのチュートリアル

 1. 長さを計算します。`a`(`la`） そして`c`(`lc`）。 ポインタを初期化する`pos`で`a`ゼロに。 このポインタは、繰り返される領域の横断をシミュレートします。`a`実際に文字列を構築せずに文字列を作成します。 
2. カウンタの初期化`count_c`ゼロに。 これにより、マッチングに成功した回数が追跡されます`c`繰り返しのサブシーケンスとして`a`。 
3. 合計を移動しながら反復します`a`繰り返しは以下です`b`。 の各キャラクターごとに、`c`、次にその文字が出現する箇所を検索します。`a`から始まる`pos`。 終わりに達したら`a`、繰り返しカウンタをインクリメントしてリセットします。`pos`ゼロに。 これは、次のコピーへの移動をシミュレートします。`a`。 
4. マッチングが完了するたびに`c`1回、増分`count_c`。 マッチングできなくなるまで続ける`c`もう全部使ってしまったので`b`の繰り返し`a`。 
5. 最後に分割します`count_c`による`d`(整数除算) 最大値を取得します`p`、 以来`q`で構成されています`c`繰り返された`d`回。 

**機能する理由**: このアルゴリズムは、次の不変条件を維持します。`pos`繰り返し内の現在位置を表します`a`次の文字の一致が開始される場所。 必要な文字の次の出現にジャンプし、その繰り返しを数えることで、`a`では、完全な文字列を構築せずに部分シーケンスのマッチングを正確にシミュレートします。 これにより、次のことが保証されます`count_c`の正確な数を表します`c`から取得可能な配列`w`、およびによる整数除算`d`正しい最大値を生成します`p`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

b, d = map(int, input().split())
a = input().strip()
c = input().strip()

la, lc = len(a), len(c)

# Precompute next occurrence positions in `a` for each character
next_pos = [{} for _ in range(la)]
last_seen = {}
for i in reversed(range(la)):
    last_seen[a[i]] = i
    next_pos[i] = last_seen.copy()

# Helper to find next position of char `ch` from index `i` in `a`
def find_next(i, ch):
    if ch in next_pos[i]:
        return next_pos[i][ch]
    return None

pos = 0
rep_count = 0
count_c = 0

while rep_count < b:
    for ch in c:
        next_i = find_next(pos, ch)
        if next_i is None:
            rep_count += 1
            if rep_count >= b:
                print(count_c // d)
                sys.exit()
            pos = 0
            next_i = find_next(pos, ch)
            if next_i is None:
                print(count_c // d)
                sys.exit()
        pos = next_i + 1
        if pos == la:
            pos = 0
            rep_count += 1
            if rep_count > b:
                print(count_c // d)
                sys.exit()
    count_c += 1

print(count_c // d)
```このソリューションはマッチングを慎重にシミュレートします`c`繰り返された結果として`a`。 線形反復を避けるために、各文字の次の出現を事前計算します。`a`毎回、繰り返し間の境界遷移を処理し、繰り返しの数を正確に追跡します。`c`シーケンス。
