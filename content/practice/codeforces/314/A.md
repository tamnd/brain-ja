 ## 解決策
 ## 問題の理解

 参加者は最終順位順にリストされます。 参加者`i`評価があります`a[i]`。 

サイズ表については`m`、参加者が現在ポジションを占めている場合`p`、彼の評価の変更は$$d = \sum_{\text{participants before him}} a_j (pos_j-1)     - a_i (p-1)(m-p)$$元のステートメントでは、この式は直接与えられています。 問題は、テーブルが動的であることです。 

参加者がいるときはいつでも、`d < k`、そのようなすべての参加者の中で最高の現在のランクを持つ参加者が削除されます。 削除後はポジションが圧縮され、すべてのポジションが圧縮されます。`d`値が再計算されます。 削除されたすべての参加者の元のインデックスを、消滅した順序で出力する必要があります。 

制約`n ≤ 2·10^5`すべての評価変更を繰り返し再計算するシミュレーションは直ちに除外されます。 たとえ`O(n^2)`ソリューションは次のように実行されます`4·10^10`最悪の場合の運用。 

厄介な点は、除去によって位置が変わるため、参加者の値は`d`は固定されていません。 単純な実装では、評価するため、間違った参加者を簡単に削除してしまう可能性があります。`d`古いポジションを使用している。 

考慮する：```
5 0
5 3 4 1 2
```参加者 2 が最初に削除されます。 その後、参加者 3 は前進し、彼の評価の変更は新しい位置を使用して再計算する必要があります。 元のテーブルを全面的に使用すると、間違ったシーケンスが生成されます。 

参加者が現在安全な場合には、別の微妙なケースが発生します。```
3 0
10 1 10
```参加者 2 に連絡したときに参加者 2 が削除されていない場合、後で削除しても参加者 2 を削除することはできません。`d`より小さい。 以前の参加者を繰り返し再検討するソリューションは、不必要な作業を行うことになります。 

の値`k`マイナスになることもあります。 否定的な意見を持つ参加者`d`は自動的に削除されません。 条件は厳密に`d < k`。 

## アプローチ

 ブルート フォース シミュレーションは文字通りこのステートメントに従います。 すべての参加者の現在の電流を繰り返し計算します。`d`、最初のものを見つけます`d < k`、彼を削除し、テーブルを圧縮し、繰り返します。 

これはプロセスを正確に再現しているため、これは正しいです。 残念ながら、1 回の再計算にはすでにコストがかかります`O(n)`、そしてそれがあるかもしれません`O(n)`撤去。 全体の複雑さは次のようになります。`O(n^2)`が遅すぎます。`n = 200000`。 

重要な点は、削除は常に元のインデックスの左から右に行われるということです。 

参加者を想定します`i`現在も生き残っている。 彼の後の参加者が削除された場合、その後の参加者の数は`i`減少します。 式を見てみると、$$d_i = \text{constant} - a_i (p_i-1)(m-p_i),$$要因`(m-p_i)`小さくなります。 マイナス記号が掛けられているので、`d_i`増やすことしかできない。 

なので一度参加すると`i`という状態に達する`d_i ≥ k`、将来の解雇により、彼が再び資格を得ることはできません。 

つまり、参加者を左から右にスキャンすると、参加者の決定は`i`以前にすでに行われた削除にのみ依存します`i`。 もし`d_i < k`、彼はすぐに削除されなければなりません。 もし`d_i ≥ k`、彼は永遠に生き残ります。 

これにより、動的プロセスが単一の線形スキャンに変わります。 

させて`r`現在のインデックスの前に削除された参加者の数になります。`i`。 

参加者の現在位置`i`は$$p = i-r.$$現在のテーブルのサイズは$$m = n-r.$$以前に生き残った参加者の間で`i`、位置は正確に`1,2,\dots,p-1`。 

維持すれば$$S=\sum_{\text{surviving } j<i} a_j (pos_j-1),$$それから$$d_i = S - a_i (p-1)(m-p).$$評価に必要なものすべて`d_i`で利用可能です`O(1)`時間。

 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`removed = 0`。 
2. メンテナンス`S`、の合計`a_j * (current_position_j - 1)`すでに処理されたすべての生存参加者を対象としています。 
3. 参加者を元の順序で左から右に処理します。 
4. 参加者向け`i`、彼の現在の位置を計算します。$$p = i - removed.$$現在のテーブルのサイズは次のとおりです。$$m = n - removed.$$5. コンピューティング$$d = S - a_i (p-1)(m-p).$$これはまさに、現在の動的テーブルに適用される評価変更の式です。 
6. もし`d < k`、この参加者を削除します。 

増加`removed`そして、元のインデックスを回答に保存します。 

何も加えないでください`S`削除された参加者は後の計算に存在しないためです。 
7. そうでない場合、参加者は生き残ります。 

追加$$a_i (p-1)$$に`S`, この参加者は、後のすべての生存者の式の最初の項に貢献するためです。 
8. すべての参加者が処理されるまで続行します。 

### なぜ効果があるのか

 参加者がインデックスを作成した後、`i`値が削除されると、`(m-p_i)`他のすべてが入っている間は減少します`d_i`は変わらないままです。 結果として、`d_i`決して減りません。 

したがって、参加者の場合`i`満足する`d_i ≥ k`私たちが彼を処理した瞬間、彼は後で削除できなくなります。 逆に、もし`d_i < k`、彼の前に削除可能なすべての参加者がすでに処理されているため、ルールでは彼をすぐに削除する必要があります。 

したがって、スキャンでは、声明で説明されている動的プロセスとまったく同じ一連の削除が再現されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    removed = 0
    s = 0
    ans = []

    for i in range(1, n + 1):
        ai = a[i - 1]

        p = i - removed
        m = n - removed

        d = s - ai * (p - 1) * (m - p)

        if d < k:
            removed += 1
            ans.append(str(i))
        else:
            s += ai * (p - 1)

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```変数`removed`すでに失踪した初期の参加者の数を追跡します。 その 1 つの数値から、現在の位置の両方を取得できます。`p`そして現在のテーブルサイズ`m`。 

変数`s`式の最初の項を格納します。 生き残った参加者のみがそれに貢献します。 参加者が削除された場合、更新をスキップします。`s`は不可欠です。 彼の貢献を追加すると、削除された参加者が後の計算に誤って影響を与えることになります。 

すべての算術演算は Python の整数を使用して行われます。 中間値はおおよその値に達する可能性があります$$10^9 \cdot 2\cdot10^5 \cdot 2\cdot10^5,$$これは 32 ビットの範囲をはるかに超えています。 Python はこれを自動的に処理します。 

操作の順序も重要です。 評価しなければなりません`d`参加者が生き残るかどうかを判断する前に。 更新中`s`1 つ目は、参加者が自分自身の評価変更の計算に誤って貢献することになります。

 ## 特殊なケース

 可能な最小の入力を考えてみましょう。```
1 0
100
```唯一の参加者が持っているのは、`p = 1`、 それで`(p-1) = 0`そして`d = 0`。 以来`0 < 0`が false の場合、誰も削除されません。 アルゴリズムは何も出力しませんが、これは正しいことです。 

参加者が生き残り、その後削除が発生する場合を考えてみましょう。```
4 0
10 1 10 1
```参加者 4 が消えた後、参加者 3 は危険に見えるかもしれませんが、彼の後ろにいる人を排除しても危険は減るだけです`(m-p)`。 彼の`d`増やすことしかできない。 アルゴリズムは彼を一度処理し、再度アクセスすることはありません。これは、数式の数学的動作と一致します。 

すべてが等しい配列を考えてみましょう。```
4 0
1 1 1 1
```スキャンは、各削除後に次を使用して現在の位置を計算します。`p = i - removed`。 多くの誤った解決策が失敗するのはまさにここです。 元の位置を使用すると不正確な結果が生じる`d`最初の削除後の値。 維持された`removed`カウンタは、圧縮された位置が常に正しいことを保証します。
