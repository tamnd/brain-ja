 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 

配列のすべての**個別の空でない非減少サブシーケンス**を考慮してください。 そのようなサブシーケンスごとに$y = (y_1,\dots,y_k)$、すべての正の整数シーケンスをカウントします。$x = (x_1,\dots,x_k)$満足のいく$$x_i \le y_i$$あらゆるポジションに。 

固定サブシーケンスの場合$y$、有効なシーケンスの数$x$単純に$$y_1 \cdot y_2 \cdots y_k$$各ポジションは独立して任意の値を選択できるため、$1$に$y_i$。 

タスクは、元の配列のすべての**個別の非減少サブシーケンス**にわたってこれらの積の合計を計算することです。 

配列の長さが次の値に達しました$10^5$、値は次の値に達します$10^6$。 配列の長さがあるため、サブシーケンスを列挙することは直ちに不可能です。$10^5$指数関数的に多くのサブシーケンスを持つことができます。 平$O(n^2)$ここでは遅すぎます。$10^{10}$操作。 

値の境界は、可能なサブシーケンスの数よりもはるかに小さくなります。 これは、サブシーケンスではなく値によってインデックスを付けた動的プログラムを構築することを示唆しています。 

微妙な点は、**distinct** という単語です。 異なる位置から選択されたが、同じ値シーケンスを生成する 2 つのサブシーケンスは、1 回だけカウントする必要があります。 

例えば：```
2
1 1
```非減少部分列は次のとおりです。```
[1]
[1]
[1,1]
```ただし、異なるものは次のとおりです。```
[1]
[1,1]
```彼らの貢献は、```
1 + 1 = 2
```サブシーケンスの出現を盲目的にカウントする DP では、2 ではなく 3 が生成されます。 

同じ値が何度も出現する場合、もう 1 つの簡単な間違いが発生します。```
3
2 2 2
```個別の非減少サブシーケンスは次のとおりです。```
[2]
[2,2]
[2,2,2]
```答えは```
2 + 4 + 8 = 14
```ソリューションでは、重複したシーケンスを蓄積するのではなく、値 2 の古い寄与を慎重に上書きする必要があります。 

## アプローチ

 ブルーフォースのアイデアは単純明快です。 すべてのサブシーケンスを生成し、減少しないもののみを保持し、それらをセットに保存して重複を削除し、各シーケンスの積を計算し、結果を合計します。 

これは正しいです。なぜなら、個別の非減少サブシーケンスはすべて明示的に生成され、1 回カウントされるからです。 

問題は部分列の数です。 長さの配列$10^5$もっている$2^{100000}$後続。 たとえ$n=50$、列挙はすでに絶望的です。 

重要な観察は、サブシーケンス自体は決して必要ないということです。 彼らの積の合計だけが必要です。 

配列を左から右に処理するとします。 させて$$F(v)$$最後の値が正確に一致する、すべての個別の非減少サブシーケンスの合計寄与度を示します。$v$。 

新しい配列要素に遭遇したとき$x$、最大でも値で終わる既存のすべてのサブシーケンス$x$によって延長できます$x$。 追記してから$x$後続の積に次の値を掛けます$x$、で終わるすべての新しく形成されたサブシーケンスの合計寄与度$x$は$$x \cdot \sum_{t \le x} F(t).$$1 要素のサブシーケンスも含める必要があります$[x]$、その製品は$x$。 

それは与える$$\text{new}(x) = x \cdot \left(1 + \sum_{t \le x} F(t)\right).$$残りの課題は、区別性の処理です。 

値が$x$は以前に表示され、一部のサブシーケンスは次で終わります。$x$すでに表現されています$F(x)$。 標準的なトリックは、古い貢献を価値に置き換えることです$x$新しく計算されたものによって。 新しいオカレンスでは、次で終わるすべての個別のシーケンスが生成される可能性があります。$x$現在はそれが可能であるため、古い値は廃止されます。 

効率的に 2 つの操作が必要です。 

1. クエリ$\sum_{t \le x} F(t)$。 
2. 交換する$F(x)$新しい価値観で。 

値は最大でも$10^6$、値座標上のフェンウィック ツリーは、次の両方の操作をサポートします。$O(\log 10^6)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n)$| 指数 | 遅すぎる |
 | 最適 |$O(n \log V)$|$O(V)$| 承認済み |

 ここ$V = 10^6$。 

## アルゴリズムのチュートリアル

 1. 1 から 1 までの値でインデックス付けされたフェンウィック ツリーを作成します。$10^6$。 
2. 配列を維持する`last[v]`、現在の貢献度を保存します$F(v)$。 
3. 入力配列を左から右に処理します。 
4. 現在値について$x$、フェンウィック ツリーにクエリを実行します。$$S = \sum_{t \le x} F(t).$$これは、最後の要素が最大で$x$。 
5. コンピューティング$$cur = x \cdot (1 + S).$$用語$1$単一要素のサブシーケンスを作成します$[x]$。 用語$S$最大でも値で終わるすべての有効なサブシーケンスを拡張します$x$。 
6. しましょう`old = last[x]`。 

価値の貢献全体を置き換えます$x$、追加するわけではありません。 これは、同じ値が繰り返し出現することによって作成された重複を削除するものです。 
7.追加してフェンウィックツリーを更新します。$$cur - old.$$この操作の後、フェンウィック ツリーは再び正しい値を保存します。$F(v)$。 
8.セット`last[x] = cur`。 
9. すべての要素が処理されると、答えはすべての要素の合計になります。$F(v)$、これは範囲全体のフェンウィック プレフィックスの合計に等しくなります。 

### なぜ効果があるのか

 配列のプレフィックスを処理した後、$F(v)$最終値が以下に等しいプレフィックスから取得可能なすべての**別個**の非減少部分列の積和の合計として定義されます。$v$。 

新しい価値観が生まれるとき$x$到着し、すべてのサブシーケンスは最大でも値で終わります$x$によって延長できます$x$、すべての積に次の乗算が行われます。$x$。 1 要素のサブシーケンスを追加すると、正確に次のようになります。$$x \cdot \left(1 + \sum_{t \le x} F(t)\right).$$もし$x$前に示したように、新しく計算された値はすでに、で終わる個別のサブシーケンスの完全なセットを表しています。$x$現在のプレフィックスから形成できます。 以前のものと置き換える$F(x)$同一の値シーケンスが重複してカウントされるのを防ぎます。 処理された位置にわたる帰納法により、不変式はすべての値に対して真のままになります。 すべての最終的な合計$F(v)$まさに必要な答えです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007
MAXV = 1000000

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, delta):
        n = self.n
        bit = self.bit
        while idx <= n:
            bit[idx] = (bit[idx] + delta) % MOD
            idx += idx & -idx

    def sum(self, idx):
        res = 0
        bit = self.bit
        while idx > 0:
            res += bit[idx]
            res %= MOD
            idx -= idx & -idx
        return res

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    fw = Fenwick(MAXV)
    last = [0] * (MAXV + 1)

    for x in a:
        s = fw.sum(x)
        cur = x * (1 + s) % MOD

        old = last[x]
        last[x] = cur

        fw.add(x, (cur - old) % MOD)

    print(fw.sum(MAXV))

if __name__ == "__main__":
    solve()
```フェンウィック ツリーには現在の値が保存されます$F(v)$。 接頭辞クエリにより得られるのは、$\sum_{t \le x} F(t)$、これはまさに再発に必要な量です。 

配列`last`重要な詳細です。 これがないと、繰り返される値が置き換えられるのではなく寄与分を蓄積し、重複したサブシーケンスが複数回カウントされることになります。 

アップデートで使用されるのは、`cur - old`フェンウィックツリーには現在の値が保存されているため、$F(x)$。 私たちは増分ではなく割り当てを実行しています。 作業モジュロ$10^9+7$これは、差分も挿入前にモジュラスで削減する必要があることを意味します。 

最終的な答えはすべての合計です$F(v)$、完全な Fenwick プレフィックス クエリによって取得されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

MOD = 1000000007
MAXV = 1000000

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def add(self, idx, delta):
            while idx <= self.n:
                self.bit[idx] = (self.bit[idx] + delta) % MOD
                idx += idx & -idx

        def sum(self, idx):
            res = 0
            while idx > 0:
                res = (res + self.bit[idx]) % MOD
                idx -= idx & -idx
            return res

    n = int(input())
    a = list(map(int, input().split()))

    fw = Fenwick(MAXV)
    last = [0] * (MAXV + 1)

    for x in a:
        s = fw.sum(x)
        cur = x * (1 + s) % MOD
        fw.add(x, (cur - last[x]) % MOD)
        last[x] = cur

    return str(fw.sum(MAXV)) + "\n"

assert run("2\n1 1\n") == "2\n", "duplicate values"
assert run("2\n1 2\n") == "5\n", "strictly increasing"
assert run("3\n2 2 2\n") == "14\n", "all equal values"

 ## 特殊なケース

 次のことを考慮してください。```
2
1 1
```最初の値の後、`F(1)=1`。 2 番目の値の後、1 までのプレフィックスの合計も 1 となり、次のようになります。`cur=2`。 アルゴリズムが置き換えられます`F(1)`by 2. 最終的な答えは 2 で、次のように正確に対応します。`[1]`そして`[1,1]`。 単純な累積では誤って 3 が生成されてしまいます。 

次のことを考慮してください。```
3
2 2 2
```状態は次のとおりです。```
F(2)=2
F(2)=6
F(2)=14
```更新ごとに以前の値が置き換えられます。 最終的な答えは 14 になります。これは、```
2 + 4 + 8
```個別のサブシーケンスに対して`[2]`、`[2,2]`、 そして`[2,2,2]`。 

考慮する：```
2
2 1
```続いて`[2,1]`は減っていないので貢献できません。 拡張は値からのみ許可されるため、アルゴリズムは当然これを強制します。`<= x`。 加工時`1`、で終わるシーケンスからの寄与`2`はプレフィックス クエリから除外されます。 答えは次のようになります```
2 + 1 = 3
```有効なサブシーケンスと一致するもの`[2]`そして`[1]`。
