 ## 解決策
 ## 問題の理解

 化学物質と反応は無向グラフを形成します。 各頂点は化学物質を表し、2 つの頂点間のエッジはそれら 2 つの化学物質が反応することを意味します。 

危険度 1 から開始します。化学物質は任意の順序で一度に 1 つずつ注入されます。 新たに追加された化学物質が、すでにチューブ内にある化学物質に対して少なくとも 1 つの反応エッジを持っている場合、現在の危険性は 2 倍になります。それ以外の場合、危険性は変化しません。 

課題は、最終的な危険を最大化する注湯順序を選択することです。 

直接読むと、答えは順序に依存することがわかりますが、グラフ構造にはもっと単純なパターンが隠されています。 重要な問題は、2 の乗算を何回強制できるかということです。 

制約は十分に小さいため、線形または線形に近いグラフ アルゴリズムは容易に受け入れられます。 たとえ$n$そして$m$元の問題にはわずか数十個しかありませんが、意図したソリューションは接続されたコンポーネントに基づいており、次のように実行されます。$O(n+m)$。 ブルートフォースによる置換には次のことが必要です$n!$可能性はありますが、それはすぐに不可能になります。 

いくつかの特殊なケースは誤解されやすいものです。 

エッジのないグラフを考えてみましょう。```
3 0
```以前に挿入された化学物質と反応することはありません。 危険は決して変わらないので、答えは次のとおりです。```
1
```反応ではなく頂点を数える不注意なアプローチでは、誤って大きな値が生成される可能性があります。 

接続されたチェーンを考えてみましょう。```
3 2
1 2
2 3
```最適な順序の 1 つは 1、2、3 です。最初の化学物質は乗算を行いません。 2 番目と 3 番目は両方ともすでに存在するものに反応するため、危険は 2 倍になります。 答えは次のとおりです。```
4
```よくある間違いは、すべてのエッジが乗算に寄与すると考えることです。 ここには 2 つのエッジがありますが、最初の頂点の後に成功した挿入は 2 つだけです。 

2 つの接続されていないコンポーネントを考えてみましょう。```
4 2
1 2
3 4
```各コンポーネントは 1 つの乗算に寄与します。 答えは次のとおりです。```
4
```グラフ全体を単一の構造として扱うと、誤った結果が得られます。$2^3=8$。 

## アプローチ

 強引なアイデアは、可能な限りの注ぎ注文をすべて試してみることです。 それぞれの順列についてプロセスをシミュレーションし、すでに挿入されている化学物質との反応を引き起こす挿入の数を数えます。 

これは、すべての有効な順序を明示的に評価するため、正しいです。 残念ながら、$n!$順列。 たとえ$n=15$、これはすでに1兆を超える可能性があり、完全に実行不可能です。 

より良いアプローチを見つけるには、1 つの接続されたコンポーネントの内部で何が起こっているのかを理解する必要があります。 

以下を含む連結コンポーネントを取得します。$k$頂点。 そのコンポーネントから注がれた最初の化学物質は、そのコンポーネントの合致要素がまだ存在していないため、同じコンポーネントの何とも反応できません。 他の頂点はすべて反応するように配置できます。 

なぜ？ コンポーネントの任意の頂点から開始します。 コンポーネントが接続されているため、DFS または BFS の順序で残りの頂点を表示できます。 新たに明らかになったすべての頂点には、以前に明らかになった頂点に対するエッジがあるため、それらの挿入ごとに危険が 2 倍になります。 

それはサイズの連結成分を意味します$k$まさに貢献する$k-1$掛け算。 

接続されているさまざまなコンポーネントは独立しています。 各コンポーネントは独自の貢献をします$k-1$乗算し、すべての成分を合計すると次のようになります。$$\sum (k_i - 1)$$どこ$k_i$のサイズです$i$- 番目の連結コンポーネント。 

コンポーネントのサイズを合計すると、$n$、$$\sum (k_i - 1) = n - c$$どこ$c$接続成分の数です。 

したがって、最後の危険は、$$2^{\,n-c}.$$残っているのは、DFS、BFS、または DSU を使用して接続されているコンポーネントをカウントすることだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n! \cdot (n+m))$|$O(n)$| 遅すぎる |
 | 最適 |$O(n+m)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 反応ペアから無向グラフを構築します。 
2. DFS を使用して、接続されているすべてのコンポーネントを検索します。 
3. 未訪問の頂点ごとに、DFS を開始し、そのコンポーネントに属する頂点の数を数えます。 
4. コンポーネントに次のものが含まれている場合$k$頂点、追加$k-1$危険の乗算の合計数に。 

コンポーネントの最初の頂点はリアクションを作成できません。 残りの頂点はすべて、すでに存在する隣接頂点の後に挿入できます。 
5. すべてのコンポーネントを処理した後、乗算の合計数を次のようにします。$cnt$。 
6. 答えは次のとおりです。$2^{cnt}$。 
7. 答えを印刷します。 

### なぜ効果があるのか

 サイズの接続されたコンポーネントの内部$k$、最初に少なくとも 1 つの頂点を挿入する必要があります。 コンポーネントの他の頂点が存在しないため、その挿入によって危険が倍増することはありません。 

1 つおきの頂点は、DFS または BFS トラバーサルを通じて頂点に到達した後に挿入できます。 この時点で、隣接するものの 1 つがすでに存在しているため、挿入すると危険が 2 倍になります。 

したがって、コンポーネントは正確に貢献します$k-1$掛け算、それ以上でもそれ以下でもありません。 すべての成分を合計すると、乗算の合計数が得られます。 各乗算により危険は 2 倍になり、最初の危険は 1 であるため、最終的な答えは次のようになります。$2^{\sum(k-1)}$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    visited = [False] * n
    multiplications = 0

    for start in range(n):
        if visited[start]:
            continue

        stack = [start]
        visited[start] = True
        size = 0

        while stack:
            v = stack.pop()
            size += 1

            for to in graph[v]:
                if not visited[to]:
                    visited[to] = True
                    stack.append(to)

        multiplications += size - 1

    print(1 << multiplications)

if __name__ == "__main__":
    solve()
```入力は化学物質間のエッジを自然に記述するため、グラフは隣接リストとして保存されます。 

DFS は、接続されている各コンポーネントのサイズをカウントします。 コンポーネントのサイズがわかったら、次のように追加します。`size - 1`危険倍増に成功した回数。 

最終的な答えは 2 の累乗です。 Python の整数には任意の精度があるため、最大の有効な答えでも問題なく適合します。 使用する`1 << multiplications`計算する$2^{\text{multiplications}}$直接的かつ効率的に。 

入力の頂点には 1 から番号が付けられますが、Python リストでは 0 から始まるインデックスが使用されるため、エッジを読み取るときに各エンドポイントが 1 回だけデクリメントされます。

import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, m = map(int, input().split())

    graph = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    visited = [False] * n
    mult = 0

    for i in range(n):
        if visited[i]:
            continue

        visited[i] = True
        size = 0

        while stack:
            v = stack.pop()
            size += 1

            for to in graph[v]:
                if not visited[to]:
                    visited[to] = True
                    stack.append(to)

        mult += size - 1

    return str(1 << mult)
