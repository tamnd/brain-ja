 ## 解決策
 ## 問題の理解

 接続された無向グラフから始めます。 すべてのエッジに方向を割り当てる必要があります。 すべての方向が選択された後、いくつかの順序付けされた頂点のペアが$(u,v)$からの有向パスが存在することを満足します。$u$に$v$。 

目標は、グラフを強く結び付けることではありません。 目標は、到達可能な順序ペアの総数を最大化する方向を選択することです。 フォームのペア$(u,u)$すべての頂点がそれ自体に到達できるため、カウントします。 

グラフはオリエンテーションの前に接続されます。 方向付け後は、強く接続されたコンポーネントと到達可能性構造が選択された方向に完全に依存する有向グラフになります。 

この問題の興味深い部分は、元のグラフにサイクルが含まれている可能性があることです。 サイクル内では、多くの場合、すべての頂点が他のすべての頂点に到達するようにエッジを方向付けることができます。 橋の上で選択された方向はその端を横切る移動を永続的に制限するため、橋の動作は大きく異なります。 

制約は十分に小さいので、$O(n^2 / 64)$最終的な圧縮構造の subset-sum スタイル DP ですが、すべての方向を試すには大きすぎます。 グラフ$m$エッジには$2^m$可能性のある向きですが、それはすぐに不可能になります。 

よくある間違いは、すべての橋が世界的に同じ方向を向いているはずだと考えることです。 考慮する```
1 - 2 - 3
```向きを変えると$1 \to 2 \to 3$、6 つの到達可能なペアを取得します。 

代わりに私たちが向きを変えるなら$1 \to 2 \leftarrow 3$、5つしか得られません。 

橋の向きはローカルではなくグローバルに重要です。 

もう 1 つの簡単な罠は、サイクルを無視してグラフをツリーとして扱うことです。 考慮する```
1 - 2
| \ |
4 - 3
```このグラフにはブリッジがありません。 これを有向サイクルとして方向付けることができ、すべての頂点が他のすべての頂点に到達し、次のようになります。$4^2 = 16$到達可能なペア。 ツリーベースの推論では、答えが過小評価されてしまいます。 

3 番目の微妙なケースは、ブリッジで接続されたいくつかの 2 エッジ接続ブロックで構成されるグラフです。 例えば：```
(triangle) -- bridge -- (triangle)
```それぞれの三角形を内部で強く接続することができます。 唯一の実際の決定は、橋の方向です。 ブロックを圧縮する代わりに個々の頂点をカウントするソリューションは、不必要に複雑になります。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのエッジのすべての方向を試し、結果として得られる有向グラフを構築し、到達可能性を計算して、最良の答えを維持します。 

それは文字通りすべての可能性をチェックするので、それは正しいです。 残念ながら、$m$エッジがあります$2^m$方向性。 たとえ$m=50$これは絶望的だ。 

最初の観察は、グラフを分離できるエッジはブリッジだけであるということです。 ブリッジではないエッジは、2 つのエッジで接続されたコンポーネントに属します。 ロビンスによる古典的な結果によれば、ブリッジのない接続グラフはすべて、強く接続された方向性が認められます。 したがって、すべてのブリッジを見つけた後、すべての最大のブリッジのないコンポーネントのすべての頂点が互いに到達するように方向を設定できます。 

コンポーネントに次のものが含まれているとします。$s$頂点。 強く接続して配向した後、正確に貢献します$s^2$内部的に到達可能な順序ペア。 

これは、すべての 2 エッジ接続コンポーネントを、そのサイズが重みとなる単一の重み付きノードに圧縮することを示唆しています。 ブリッジは、それらの重み付けされたノード間のエッジになります。 圧縮されたグラフはツリーであり、ブリッジ ツリーと呼ばれることがよくあります。 

ここで問題は次のようになります。 

重み付きツリーが与えられた場合、重み付きノード間で到達可能な順序付きペアの数が最大になるようにエッジの向きを設定します。 

これははるかに簡単です。 公式社説で言及されている重要な特性は、他のすべてのコンポーネントがルートに到達するか、ルートから到達可能であるように、特別なルート コンポーネントに最適な方向が存在するということです。 

そのルートは重み付けされたツリーの重心でなければなりません。 重心を削除すると、残りのすべての部分の重量は最大でも全体の半分になります。 重心の周囲では、隣接する各辺にある程度の重みがかかります$a_i$。 

いくつかの辺を図心の方を向くように選択し、残りの辺を重心から遠ざけるように選択します。 

させて

-$r$重心の重みになります。 
-$T = n-r$。 
-$X$重心に向かう辺の合計重量になります。 
-$T-X$重心から離れる方向の辺の合計重量になります。 

次に、ツリー構造によって提供される追加の到達可能なペアは次のようになります。$$Xr + r(T-X) + X(T-X)$$これを単純化すると$$rT + X(T-X).$$固定用$r$、答えを最大化するということは、最大化することを意味します$X(T-X)$。 これは古典的なパーティションの問題です。 私たちが欲しいのは$X$できるだけ近くに$T/2$、 しかし$X$は隣接する側の重み全体の合計でなければなりません。 

それは辺サイズの部分集合合計 DP になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^m \cdot (n+m))$|$O(n+m)$| 遅すぎる |
 | 最適 |$O(n+m+n^2/64)$|$O(n+m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元のグラフで Tarjan のブリッジ アルゴリズムを実行し、すべてのブリッジをマークします。 
2. 概念的にすべてのブリッジを削除し、残りのエッジを介して DFS を実行します。 各連結領域は 1 つの 2 エッジ連結コンポーネントになります。 
3. すべてのコンポーネントのサイズを記録します。 コンポーネントに次のものが含まれている場合$s$頂点、追加$s^2$答えに。 これは、そのコンポーネントが強く接続されている方向を向くことによって得られる寄与です。 
4. ブリッジツリーを構築します。 各コンポーネントは、重みがそのサイズに等しい重み付きノードになります。 元のブリッジはすべて、2 つのコンポーネント ノード間のエッジになります。 
5. ブリッジ ツリー内のサブツリーの重みを計算し、すべての重み付けされた重心を見つけます。 重心とは、ノードを削除しても、以下の重量を超える部分が残らないノードです。$n/2$。 
6. 各重心について:

 1. その重さを次のようにします。$r$。 
2. 隣接するすべての辺について、その総重量を計算します。$a_i$。 
3. 値に対してサブセット合計 DP を実行します。$a_i$。 
4. 達成可能な金額ごとに$X$、 評価する$$r(n-r) + X((n-r)-X).$$5. 最大値を維持します。 
7. 最大ツリー寄与をステップ 3 で計算された内部寄与に加算します。 

### なぜ効果があるのか

 ブリッジ以外のすべてのエッジは、2 つのエッジで接続されたコンポーネントの内側にあります。 このようなコンポーネントは強く接続して配向できるため、その内部の頂点のすべてのペアが到達可能になります。 各コンポーネントを加重ノードに圧縮しても、最適化に関連する情報は失われません。 

圧縮後のグラフはツリーになります。 最適な方向では、異なるブランチ間の到達可能性を生み出すすべてのパスが単一の重心コンポーネントを通過する必要があります。 重心が固定されると、隣接する各辺は完全に「入力」側になるか、完全に「出力」側になります。 異なる側間の到達可能性は、これら 2 つのグループに割り当てられた合計の重みによってのみ決まります。 

受信重量が$X$そして出て行く重みは$T-X$、入力グループのすべての頂点は、重心を介して出力グループのすべての頂点に到達できます。 結果として得られる貢献はまさに$$rT + X(T-X).$$他の方向性ではこれ以上のグループ間の到達可能性を生み出すことはできず、この式を最大化すると、上で説明したサブセット合計パーティションに減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    g = [[] for _ in range(n)]
    edges = []

    for eid in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        edges.append((u, v))
        g[u].append((v, eid))
        g[v].append((u, eid))

    tin = [-1] * n
    low = [0] * n
    timer = 0
    is_bridge = [False] * m

    sys.setrecursionlimit(1 << 20)

    def dfs_bridge(v, pe):
        nonlocal timer
        tin[v] = low[v] = timer
        timer += 1

        for to, eid in g[v]:
            if eid == pe:
                continue

            if tin[to] != -1:
                low[v] = min(low[v], tin[to])
            else:
                dfs_bridge(to, eid)
                low[v] = min(low[v], low[to])

                if low[to] > tin[v]:
                    is_bridge[eid] = True

    dfs_bridge(0, -1)

    comp = [-1] * n
    comp_size = []

    def dfs_comp(start, cid):
        stack = [start]
        comp[start] = cid
        sz = 0

        while stack:
            v = stack.pop()
            sz += 1

            for to, eid in g[v]:
                if is_bridge[eid]:
                    continue
                if comp[to] == -1:
                    comp[to] = cid
                    stack.append(to)

        return sz

    cc = 0
    base = 0

    for v in range(n):
        if comp[v] == -1:
            sz = dfs_comp(v, cc)
            comp_size.append(sz)
            base += sz * sz
            cc += 1

    if cc == 1:
        print(base)
        return

    tree = [[] for _ in range(cc)]

    for eid, (u, v) in enumerate(edges):
        if is_bridge[eid]:
            a = comp[u]
            b = comp[v]
            tree[a].append(b)
            tree[b].append(a)

    total_weight = n

    parent = [-1] * cc
    sub = [0] * cc

    def dfs_sub(v, p):
        parent[v] = p
        s = comp_size[v]

        for to in tree[v]:
            if to == p:
                continue
            dfs_sub(to, v)
            s += sub[to]

        sub[v] = s

    dfs_sub(0, -1)

    centroids = []

    for v in range(cc):
        mx = total_weight - sub[v]

        for to in tree[v]:
            if to == parent[v]:
                continue
            mx = max(mx, sub[to])

        if mx * 2 <= total_weight:
            centroids.append(v)

    best_extra = 0

    for c in centroids:
        sides = []

        for to in tree[c]:
            if to == parent[c]:
                sides.append(total_weight - sub[c])
            else:
                sides.append(sub[to])

        r = comp_size[c]
        T = total_weight - r

        bits = 1
        for a in sides:
            bits |= bits << a

        best_partition = 0

        for x in range(T + 1):
            if (bits >> x) & 1:
                best_partition = max(best_partition, x * (T - x))

        best_extra = max(best_extra, r * T + best_partition)

    print(base + best_extra)

if __name__ == "__main__":
    solve()
```最初の DFS は、標準のローリンク技術を使用してすべてのブリッジを検索します。 エッジは、その下のサブツリーがその親の祖先に到達できない場合にまさにブリッジとなります。 

2 番目の DFS はブリッジを無視し、2 つのエッジで接続されたコンポーネントにラベルを付けます。 各コンポーネントのサイズは、ブリッジ ツリー内のノードの重みになります。 

変数`base`の合計を格納します$s^2$すべての圧縮されたコンポーネントに適用されます。 答えのその部分は、橋の方向とは無関係です。 

その後、ブリッジ ツリーが構築されます。 サブツリーの重みは 1 回計算されるため、重心の隣接するすべての辺を一定時間内に取得できます。 

サブセットサム DP は、Python 整数としてエンコードされたビットセットを使用します。 噛まれたら`k`が設定されている場合、側面の総重量は`k`達成可能です。 ずらして`a`OR-ing は、標準的なナップザック移行を非常に効率的に実行します。 

最終的な答えは、内部寄与とコンポーネント間の最良の寄与を加えたものです。

1 2
2 3
3 4
4 1
1 3
```グラフ全体がサイズ 4 の 1 つのコンポーネントになります。ブリッジ ツリーには 1 つのノードが含まれます。 アルゴリズムはすぐに戻ります$$4^2 = 16.$$サブセットサムフェーズは必要ありません。

2 1
1 2
```各頂点は独自のコンポーネントになります。 ブリッジ ツリーには重み 1 の 2 つのノードがあります。重心の重みは 1、唯一の側面の重みは 1、式は次のようになります。$$1 + (1 \cdot 1) + 0 = 3.$$これはサンプルと一致します。 

最後に、ブリッジで接続された 2 つの大きなブロックについて考えます。```

```分解によりコンポーネントの重みが生成されます$3$そして$3$。 内部到達可能性が寄与する$18$。 ブリッジの向きが貢献します$9$。 答えは$27$。 

このケースは、ソリューションの中心的な不変条件を示しています。つまり、2 つのエッジで接続されたコンポーネントが圧縮されると、追加の到達可能性に影響を与えるのはブリッジ ツリーのみになります。
