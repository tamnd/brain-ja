 ## 解決策
 ## 問題の理解

 バスのレイアウトは固定されており、すでに描画されています。 乗客席は全部で34席あります。 乗客は常に非常に特定の順序で座席に座ります。最後尾の列から開始し、左から右に座席を埋め、次に 1 列ずつ上に移動します。 現在の列に複数の座席がある場合は、左端の空いている座席が選択されます。 

入力には単一の整数が含まれています`k`、現在バスに乗っている乗客の数。 6 行の ASCII アート バス図を印刷し、最初の行に正確にマークを付ける必要があります。`k`搭乗順の座席が占有されている場合 (`O`）。 残りの助手席はすべて空席のままです (`#`）。 

制約は非常に小さいです。 乗客数は最大でも34名で、まさに座席数です。 すべての座席を個別に検査する強引なシミュレーションでも、実行される操作はわずか数十回です。 ここでは実行時間は関係ありません。課題は、必要な出力形式を正確に再現することです。 

間違いの最も一般的な原因は、搭乗順序を誤解することです。 乗客はバスの最前列から下に向かって埋まるわけではありません。 特別な 4 人掛けの列から始まり、残りの列に進みます。 

考慮する`k = 1`。 占有座席は最後列の最初の座席である必要があります。```
+------------------------+
|O.#.#.#.#.#.#.#.#.#.#.|D|)
|#.#.#.#.#.#.#.#.#.#.#.|.|
|#.......................|
|#.#.#.#.#.#.#.#.#.#.#.|.|)
+------------------------+
```左上隅から座席を埋めるソリューションでは、乗客は間違った場所に配置されてしまいます。 

別の簡単な間違いが現れるのは、`k = 34`。 すべての乗客の座席に着席する必要があります。 4 列シートの追加のシートを忘れた実装では、33 の座席しか埋まりません。 

最後のエッジケースは、`k = 0`。 どの座席にも含まれてはなりません`O`。 実装によっては、座席が残っているかどうかを確認する前に乗客カウンターをデクリメントするため、誤って少なくとも 1 つの座席が占有されてしまうことがあります。 

## アプローチ

 最も直接的なアイデアは、乗客が座っている正確な順序ですべての座席をリストすることです。 次に、そのリストを最初から処理し、最初のリストをマークします。`k`占領された位置。 シートは 34 個しかないため、このシミュレーションでは最大 34 回の更新が実行されます。 

これでも十分な速度ですが、バスの構造を確認するのに役立ちます。 バスの描画が修正されました。 席のキャラクターだけが変わります。 列内を移動する乗客をシミュレートする代わりに、最終的な ASCII テンプレートを構築し、乗車順序に従って座席の位置を 1 つずつ置き換えることができます。 

重要な観察は、搭乗順序が、所定の順序で座席の位置をスキャンすることに正確に対応しているということです。 これら 34 個の座標がわかれば、問題は単純な文字列操作になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース乗客シミュレーション | お(34) | お(34) | 承認済み |
 | 最適なテンプレートの充填 | お(34) | お(34) | 承認済み |

 席数は固定されているため、どちらのアプローチも常に複雑さを伴います。 テンプレートを入力するバージョンはよりクリーンで、必要な出力に直接マッピングされます。 

## アルゴリズムのチュートリアル

 1. 必要な空のレイアウトを表す文字列のリストとしてバスを保存します。 
2. 各文字列を変更可能な文字リストに変換して、個々の座席の位置を変更できるようにします。 
3. 搭乗順の 34 の座席座標すべてを含むリストを作成します。 
4. 最初の 4 つの座標は、4 席の特別な列に対応します。 
5. 残りの座標は他の行に対応し、乗客が座っているときと同じように上から下、左から右に正確にスキャンされます。 
6. 最初の処理を繰り返します`k`このリストの座標を取得し、各位置の座席文字を次のように置き換えます。`O`。 
7. 残りの座席位置はすべてそのままにしておきます。`#`。 
8. 各文字リストを文字列に変換し、6 行を出力します。 

### なぜ効果があるのか

 座標リストは、乗客が座席を選択する順序とまったく同じ順序で作成されます。 最初の座標は最初に利用可能な座席を表し、2 番目の座標は 2 番目に利用可能な座席を表し、34 席すべてがリストされるまで同様に続きます。 最初のマークを付ける`k`占有された座標は、の到着をシミュレートすることと同等です。`k`乗客。 すべての座席はリストに 1 回だけ表示されるため、スキップされたり 2 回カウントされたりする座席はなく、固有の正しい最終構成が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input())

    bus = [
        list("+------------------------+"),
        list("|#.#.#.#.#.#.#.#.#.#.#.|D|)"),
        list("|#.#.#.#.#.#.#.#.#.#.#.|.|"),
        list("|#.......................|"),
        list("|#.#.#.#.#.#.#.#.#.#.#.|.|)"),
        list("+------------------------+")
    ]

    seats = []

    seats.append((3, 1))

    for c in range(1, 22, 2):
        seats.append((1, c))

    for c in range(1, 22, 2):
        seats.append((2, c))

    for c in range(1, 22, 2):
        seats.append((4, c))

    for r, c in seats[:k]:
        bus[r][c] = 'O'

    print("\n".join("".join(row) for row in bus))

if __name__ == "__main__":
    solve()
```バス テンプレートは、すべての座席が最初にマークされている点を除き、ステートメントに表示されているとおりに保存されます。`#`。 

座席リストは搭乗順をエンコードします。 図の 3 列 1 列の座席は、4 人掛け列の独自の追加座席なので、最初になります。 その後、普通乗客用の 3 列がそれぞれ 11 席となり、`1 + 11 + 11 + 11 = 34`合計ポジション。 

ループ`for r, c in seats[:k]`オフバイワンエラーを自然に回避します。 もし`k = 0`、スライスは空であり、シートは変更されません。 もし`k = 34`、すべての座標は 1 回だけ訪問されます。

 ## 特殊なケース

 いつ`k = 0`、スライス`seats[:0]`は空です。 座標は変更されないため、すべての座席がそのまま残ります`#`。 これは、バスに乗客がいないという要件と一致します。 

いつ`k = 1`、最初の座標のみ`(3, 1)`が選択されます。 その座標は4列シートの特等席に相当します。 搭乗順は座標リストに直接エンコードされているため、アルゴリズムが誤って上の行を埋め始めることはありません。 

いつ`k = 34`、ループは、に保存されているすべての座標を訪問します。`seats`。 リストには正確に 34 個の一意の座席位置が含まれているため、すべての乗客の座席が占有され、2 回処理される座席はありません。 

微妙な境界が発生します`k = 12`。 最初の座標は特等席を埋め、次の 11 座標は上部の通常列全体を埋めます。 次の乗客は中央の列からスタートします。 座標リストは正しく順序付けされているため、行間の遷移は特別なロジックを必要とせずに自動的に行われます。
