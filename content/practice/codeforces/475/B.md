 ## 解決策
 ## 問題の理解

 私たちは、各道路が一方通行になったときに、水平方向と垂直方向の道路の格子を持つ都市が「強く接続されている」かどうかを判断するように求められます。 都市は交差点のグリッドとして視覚化できます。`n`水平な道路と`m`垂直の街路が形成される`n × m`ジャンクション。 各水平道路には、許可される方向が 1 つあります。つまり、すべての交通が西から東に流れるか、東から西に流れるかのいずれかです。 それぞれの垂直の通りには、北から南または南から北という単一の方向もあります。 ドライバーは、道路の方向に従って道路に沿って移動し、交差点で横断道路に切り替えることができます。 

入力では、水平および垂直の道路の数と、それに続く長さの文字列が提供されます。`n`と`<`または`>`水平方向の道路と長さの文字列の場合`m`と`^`または`v`垂直道路用。 道路の指示に従って他の交差点から交差点に到達できる場合、出力は「YES」、そうでない場合は「NO」になります。 

制約は、`n, m ≤ 20`は、交差の総数が最大 400 であることを意味します。これは十分に小さいため、すべての交差に対するブルート フォース グラフ トラバースが可能です。 エッジケースはすぐには明らかではありませんが、方向が境界線に沿って「行き止まり」を形成している道路から発生する可能性があります。 たとえば、最上部の水平道路が左を指し、最も左の垂直道路が上を向いている場合、左上隅の交差点は特定の地点から到達できなくなり、強力な接続が切断されます。 

単純な実装では、たった 1 つの交差点からの接続をチェックする可能性がありますが、これは誤りです。 強力な接続には、すべてのジャンクションが他のすべてのジャンクションから到達可能であることが必要です。 不注意なアプローチは、指示を誤解する可能性もあります。`<`東から西ではなく西から東という意味です。 

## アプローチ

 ブルートフォースアプローチは、各ジャンクションを有向グラフのノードとしてモデル化し、道路の方向に従ってエッジを追加することです。 次に、すべてのジャンクションに対して、DFS や BFS などのグラフ走査アルゴリズムを実行し、他のすべてのジャンクションが到達可能であることを確認します。 ノードが最大 400 個ある場合、これには最大 400 回のトラバーサルが必要となり、それぞれが 400 個のノードを訪問することになり、結果として約 160,000 回の操作が発生します。これは、問題の制約には許容されますが、不要です。 

重要な洞察は、境界上の道路が 4 つの端すべてに沿った移動を許可する場合に限り、均一な道路方向を持つグリッド内の強力な接続が保証されるということです。 言い換えれば、一番上と一番下の水平方向の道路が反対方向を向いており、一番左と一番右の垂直方向の道路が反対方向を向いている場合、すべてのジャンクションは他のすべてのジャンクションに到達できます。 これにより、問題は 4 つのコーナー ジャンクションのチェックに軽減されます。方向パターンでコーナーからコーナーへの移動が許可されている場合、水平および垂直の通りに沿った移動によって到達可能性が伝播されるため、内側のジャンクションは自動的に到達可能になります。 

この観察により、完全なグラフの構築と複数の走査の実行を回避できます。 左上、右上、左下、右下の角が相互に到達可能かどうかをチェックするだけで済みます。これは、水平文字列と垂直文字列の最初と最後の文字が反対方向を向いていることを確認するのと同じです。

 | --- | --- | --- | --- |
 | すべてのジャンクションからのブルート フォース DFS | O(n_m_(n*m)) | O(n*m) | 受け入れられるが不要 |
 | コーナーチェックインサイト | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 水平方向のストリートの数を読み取ります。`n`そして垂直の通り`m`、その後に水平方向と垂直方向の道路の方向を表す文字列が続きます。 
2. 一番上の水平ストリートと一番下の水平ストリートを調べます。 両方が同じ方向を向いている場合、左端または右端の列に到達できない可能性があり、強力な接続が不可能になります。 
3. 左端の垂直ストリートと右端の垂直ストリートを調べます。 両方が同じ方向を向いている場合、最上行または最下行に到達できなくなり、強力な接続が切断される可能性があります。 
4. 水平方向と垂直方向の両方の境界チェックに合格した場合は、「YES」と出力します。 それ以外の場合は、「NO」を出力します。 

これが機能する理由: 道路の方向が一定であるグリッドでは、交差点に到達できなくなる唯一の方法は、境界道路によって交差点への出入りが妨げられる場合です。 反対側のエッジが反対方向を向いていることを確認することで、グリッドの周りの移動が可能であることが保証され、その結果、すべてのジャンクションが他のすべてのジャンクションに到達できるようになります。 これにより、正確性を維持しながら、明示的なグラフの構築と複数の走査が回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    h_dirs = input().strip()
    v_dirs = input().strip()

    horizontal_ok = h_dirs[0] != h_dirs[-1]
    vertical_ok = v_dirs[0] != v_dirs[-1]

    if horizontal_ok and vertical_ok:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    main()
```コードは次を使用して入力を読み取ります。`sys.stdin.readline`効率化のために。 最初と最後の水平方向の道路方向と、最初と最後の垂直方向の道路方向をチェックします。 それらが等しくない場合、グリッドは強く接続されていることが保証されているため、「YES」が出力されます。 それ以外の場合は「いいえ」。 境界条件は慎重に処理されます。`h_dirs[0]`最北の通りであり、`h_dirs[-1]`最南端の通りです、`v_dirs[0]`最西端であり、`v_dirs[-1]`最東端です。

 このチェックでは、最初と最後の水平方向のストリートが両方とも「>」であるため、上の行が下の行に到達できないことが確認されます。 同様に、垂直境界は両方とも「v」を指し、左右の接続が妨げられます。 したがって「いいえ」です。

```| 変数 | 値 |

 | 出力 | はい |

 すべてのコーナージャンクションに到達可能であり、内部接続が方向に沿って伝播するため、強力な接続が得られます。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()
    main()

# Provided samples
assert run("3 3\n><>\nv^v\n") == "NO", "sample 1"

assert run("3 2\n<><\nvv\n") == "NO", "vertical boundaries same"

 ## 特殊なケース

 両方の水平方向の通りが同じ方向を向いている場合、たとえば、`<<`垂直の通りがある`^v`、上の行は下の行に到達できません。 アルゴリズムチェック`h_dirs[0] != h_dirs[-1]`そして「いいえ」を返します。 同様に、垂直の通りが同じ場合、たとえば、`v^v^`の場合、左端の列は右端の列に到達できず、出力は正しく「NO」になります。 このアルゴリズムは、サイズ 2×2 のグリッドを同じロジックで正しく処理し、境界が逆の方向を向いている場合にのみ強い接続性を確認します。
