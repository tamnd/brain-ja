 ## 解決策
 ## 問題の理解

 私たちには、一定のラインに配置されたダンサーのシーケンスが与えられ、各ダンサーには高さが設定されています。 この行から、「ドラゴン ダンス」を実行する (元の順序を維持した) サブシーケンスを形成したいと考えています。 

制限はローカルです。選択された 2 人の隣接するダンサーが最終ラインナップで隣り合って立つとき、それらの身長の差は指定されたしきい値を超えてはなりません。\(k\)。 その差が超えた場合\(k\)、その隣接性は最終的な選択では許可されません。 

タスクは、サブシーケンス内のすべての連続するペアがこの高さの差の制約を満たすように、可能な最大長のサブシーケンスを選択することです。 

入力により提供されるのは、\(n\)、ダンサーの数、そして\(k\)、許容される最大の高さの差。 2 行目は高さを元の順序で示します。 出力は単一の整数、つまり有効なサブシーケンスの最長の長さです。 

制約\(n \le 2 \cdot 10^5\)二次または三次のアプローチを除外します。 すべてのサブシーケンス、または動的プログラミング遷移を含む位置のすべてのペアをテストしようとするソリューションは、制限時間を超えてしまいます。 線形または線形に近い構造、通常はアレイをスキャンするときに徐々に維持できるものを探しています。 

多くの場合失敗する単純な解釈は、高さによる並べ替えや貪欲な選択など、これをグローバルな範囲の問題として扱うことです。 並べ替えは許可されていないため、これにより順序の制約が破られます。 

もう 1 つの微妙な問題は、有効なチェーンがローカルに形成されると、いつでも貪欲に拡張できると想定していることです。 これは、互換性のないギャップにより、局所的に最適なステップが将来のより長いチェーンをブロックする場合には誤りです。 

たとえば、次の場合\(k = 2\)そして高さは\([1, 10, 2, 3, 4]\)、ピッキング\(1 \to 2 \to 3 \to 4\)最適ですが、選ぶのは単純で貪欲です\(1 \to 10\)すぐにシーケンスを早期に中断し、それ以上の有効な拡張を妨げます。 

## アプローチ

 ブルートフォースのアイデアは、すべての位置で終わる最長の有効なサブシーケンスを計算することです。 ポジションごとに\(i\)、以前のポジションをすべてチェックします\(j < i\)、そしてもし\(|h_i - h_j| \le k\)で終わる有効なチェーンを拡張できます。\(j\)。 これにより、標準的な動的プログラミングの公式が導き出されます。\[
dp[i] = 1 + \max(dp[j]) \quad \text{over all } j < i \text{ with } |h_i - h_j| \le k.
\]これは、すべての有効な先行処理を明示的に探索するため、正しいです。 問題はパフォーマンスです。各状態は潜在的に \(O(n)\) 個前の状態をスキャンし、\(O(n^2)\) 個の遷移を引き起こします。\(4 \cdot 10^{10}\)最悪の場合、限界をはるかに超えた運用が可能になります。 

重要な観察は、遷移条件が位置構造ではなく高さの値のみに依存するということです。 固定高さの場合\(h_i\)、高さが間隔内にある以前の要素のみを考慮します。\([h_i - k, h_i + k]\)。 これにより、DP 遷移が値に対する範囲クエリに変換されます。 

以前のすべてのインデックスをスキャンする代わりに、要素を処理するときに dp 値を挿入する操作と、高さの範囲内で最適な dp 値をクエリする操作の 2 つの操作をサポートする高さにわたるデータ構造を維持します。 これは、高さの座標圧縮後のフェンウィック ツリーまたはセグメント ツリーの場合にまさに当てはまります。 

ダンサーを左から右に処理します。 各高さについて、互換性のある高さの範囲で終わる最適なサブシーケンスをクエリし、それを 1 だけ拡張します。 現在の位置の dp を計算した後、それを構造に挿入して、将来の位置でそれを使用できるようにします。

 これにより、線形スキャンから対数クエリへの各移行が減少します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | すべてのペアに対するブルート フォース DP | \(O(n^2)\) | \(O(n)\) | 遅すぎる |
 | 高さを超える DP + セグメント ツリー | \(O(n \log n)\) | \(O(n)\) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての高さをより小さな座標系に圧縮します。 高さは次のとおりであるため、これは必要です。\(10^9\)そして、順序を維持しながらそれらをコンパクトなインデックス範囲にマップする必要があります。 

2. 高さインデックスごとに、その高さでこれまでに達成された最大 dp 値を格納するセグメント ツリー (またはフェンウィック ツリーのバリアント) を構築します。 

3. サイズ n の配列 dp を初期化します。 各 dp[i] は、位置 i で終了する最良の有効なサブシーケンスを表します。 

4. ダンサーを左から右にスキャンします。 各ダンサー i について、高さに対応する圧縮インデックスの範囲を決定します。\([h_i - k, h_i + k]\)。 この範囲は、i に接続できるすべての有効な先行接続を表します。 

5. この範囲にわたるセグメント ツリーをクエリして、以前の有効な高さの中でこれまでに確認された最大 dp 値を取得します。 有効な先行処理が存在しない場合、結果は 0 になります。 

6. 許容範囲内で終了する最も有効なサブシーケンスを拡張するため、dp[i] をその値に 1 を加えた値に設定します。 

7. 圧縮インデックスでセグメント ツリーを更新します。\(h_i\)dp[i] を使用すると、将来のポジションをそれに基づいて構築できるようになります。 

最終的な答えは dp の最大値です。 

### なぜ効果があるのか

 スキャンのどの時点でも、セグメント ツリーには、以前に処理されたすべてのダンサーの各高さで終了する最良のサブシーケンスが保存されます。 DP 移行では、現在の高さに法的に先行できる以前の州だけが考慮され、その他の州は考慮されません。 左から右に処理するため、ツリー内のすべての候補は位置の順序によって有効になり、高さの制約は範囲クエリによって強制されます。 これにより、すべての dp[i] が i で終わる最良のサブシーケンスを表し、有効な遷移がスキップされることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (4 * n)

    def update(self, v, l, r, i, val):
        if l == r:
            if val > self.t[v]:
                self.t[v] = val
            return
        mid = (l + r) // 2
        if i <= mid:
            self.update(v * 2, l, mid, i, val)
        else:
            self.update(v * 2 + 1, mid + 1, r, i, val)
        self.t[v] = max(self.t[v * 2], self.t[v * 2 + 1])

    def query(self, v, l, r, ql, qr):
        if qr < l or r < ql:
            return 0
        if ql <= l and r <= qr:
            return self.t[v]
        mid = (l + r) // 2
        return max(
            self.query(v * 2, l, mid, ql, qr),
            self.query(v * 2 + 1, mid + 1, r, ql, qr)
        )

n, k = map(int, input().split())
h = list(map(int, input().split()))

vals = sorted(set(h))
idx = {v: i for i, v in enumerate(vals)}

seg = SegTree(len(vals))
ans = 0

for i in range(n):
    hi = h[i]
    left_val = hi - k
    right_val = hi + k

    l = 0
    r = len(vals) - 1

    while l <= r:
        mid = (l + r) // 2
        if vals[mid] < left_val:
            l = mid + 1
        else:
            r = mid - 1
    L = l

    l = 0
    r = len(vals) - 1
    while l <= r:
        mid = (l + r) // 2
        if vals[mid] <= right_val:
            l = mid + 1
        else:
            r = mid - 1
    R = r

    best = 0
    if L <= R:
        best = seg.query(1, 0, len(vals) - 1, L, R)

    dp = best + 1
    seg.update(1, 0, len(vals) - 1, idx[hi], dp)
    ans = max(ans, dp)

print(ans)
```セグメント ツリーは、圧縮された高さの値に対する最大範囲構造として使用されます。 二分検索は、数値制約を圧縮配列内のインデックス境界に変換します。 各更新では、指定された高さで終わる最適なチェーンが挿入され、各クエリでは最適な拡張可能なチェーンが取得されます。 

よくある間違いは、クエリの前に更新することです。これにより、現在の要素自体が誤って拡張されてしまいます。 正しい順序は、最初にクエリ、次に更新です。 

もう 1 つの微妙な点は、空のクエリ範囲の処理です。これは、現在の位置から始まる新しいサブシーケンスを表すために 0 を返す必要があります。

 ## 特殊なケース

 特殊なケースの 1 つは、すべての高さが相対的に狭い範囲内に収まる場合です。\(k\)。 入力用`5 100`と`1 2 3 4 5`、すべてのペアは互換性があり、アルゴリズムは事実上、各位置が以前の最大値を拡張して 5 を生成する単純な増加 DP に減少します。 

もう 1 つのエッジケースは次のような場合です\(k = 0\)。 同じ高さのみが接続できるため、最適なサブシーケンスは同じ値の頻度によって決まります。 クエリ範囲は単一の圧縮インデックスに折りたたまれるため、セグメント ツリーはこれを自然に処理します。 

3 番目のケースは、次のような孤立したスパイクです。`1 100 2 3 4`小さいもので\(k\)。 100 でのスパイクはチェーンをリセットしますが、それ以降の値は、チェーンとは独立して長いサブシーケンスを形成する可能性があります。 有効な先行データがクエリ範囲内にないため、DP は正しく再起動されます。
