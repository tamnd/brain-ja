 ## 解決策
 ## 問題の理解

 提灯が並んでいます。 ランタン`i`高さがある`a[i]`、そしてドラゴンは選ばれた1つのランタンから始まります。 ジャンプの瞬間に 2 つのランタンが同じ高さである場合にのみ、隣接するランタンにジャンプできます。 

ドラゴンは現在立っているランタンの高さを変更できます。 高さを 1 増やすと 1 エネルギーを消費し、高さを 1 減らすと 1 エネルギーが戻ります。 タスクは、ドラゴンが最終的にすべてのランタンを訪問できるように、すべてのクエリ開始位置に必要な最小の初期エネルギーを見つけることです。 ランタンの高さはクエリ間で更新することもできます。 この問題は、更新または開始位置のクエリのたびに答えを求めます。 

制約により、最大で`2 * 10^5`提灯と`2 * 10^5`イベント。 すべてのクエリに対してすべてのランタンをスキャンするソリューションには、次のものが必要になります。`4 * 10^10`最悪の場合、通常のコンテストの制限時間をはるかに超えた場合の操作。 更新とクエリの両方が対数時間付近になるようにする必要があります。これは、配列全体でデータ構造を維持することを意味します。 

主なエッジケースは、現在のランタンの高さと元の高さを混同すること、および開始時のランタン自体が低くすることでエネルギーを供給できることを忘れることから発生します。 

たとえば、次のようになります。```
2 1
5 10
1 1
```答えは`5`。 ドラゴンは最初のランタンからスタートし、ランタンを下から下ろします。`5`に`10`エネルギーがなければ不可能なので、彼には正確に必要です`5`上げてジャンプするエネルギー。 隣接するランタン間の違いのみをチェックするソリューションでは、最初の移動に直接コストがかかることを見落とす可能性があります。 

別の例は次のとおりです。```
3 1
10 5 10
1 2
```答えは`5`。 中央のランタンは両側よりも低いため、ドラゴンはどちらかのジャンプの前にランタンを上げるのに十分なエネルギーが必要です。 片方だけをチェックするようないい加減な解決策は逆戻りする可能性があります`0`間違っています。 

最後の境界ケースは単一のランタンです。```
1 1
100
1 1
```答えは`0`実行するジャンプがないためです。 空の左または右の範囲を処理せずにクエリする実装は、ここで失敗する可能性があります。 

## アプローチ

 強引なアプローチは、ドラゴンの動きをシミュレートすることです。 選択したランタンから始めて、左右の側面を訪問するさまざまな順序を試し、ジャンプごとにどれだけのエネルギーが必要かを追跡することができます。 すべての有効な動作シーケンスを直接チェックできるため、これは正しいことです。 しかし、それは遅すぎます。 と`n = 2 * 10^5`、単一のクエリですべてのランタンを検査でき、これを繰り返します。`q = 2 * 10^5`クエリは二次的な動作を与えます。 

重要な観察は、アレイの側面を横切る移動には単純なエネルギー要件があるということです。 

ドラゴンが の位置から開始すると仮定します。`p`そして右のみに歩きます。 ランタンに辿り着く前に`i + 1`、これまでのジャンプのたびに、現在のランタンが次のランタンの高さに変更されます。 ランタン到達後の総エネルギー変化`i`まさに`a[p] - a[i]`。 次のジャンプを行うには、ドラゴンは現在のランタンを上げるのに十分なエネルギーを持っている必要があります。`a[i + 1]`の方が高いです。 これらの値を組み合わせると、重要なのはその側で検出されるランタンの最高の高さだけであることがわかります。 

右側のすべてのランタンに到達するのに必要なエネルギーは次のとおりです。`max(0, maximum height on positions p+1 through n - a[p])`左側は対称です。`max(0, maximum height on positions 1 through p-1 - a[p])`ドラゴンは両方の側を処理する必要があるため、答えはこれら 2 つの値の大きい方になります。 これにより、ポイント更新による範囲最大クエリの問題が軽減されます。 セグメント ツリーには各間隔の最大高さが格納され、両方の操作に対数時間が与えられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n) | お(1) | 遅すぎる |
 | 最適 | 操作ごとに O(log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ノードがその間隔内のランタンの最大高さを格納するセグメント ツリーを構築します。 範囲から必要な唯一の情報は、その最も高いランタンです。 
2. 更新クエリの場合、セグメント ツリーで選択したランタンの値を置き換え、ルートへのパスの最大値を再計算します。 
3. 開始位置クエリの場合`p`の左側にあるすべてのランタンの中で最大の高さを取得します。`p`。 
4. 右側にあるすべてのランタンの最大の高さを求めます。`p`。 
5. 各側に必要なエネルギーを計算します。 片側の最大高さが`mx`、ドラゴンが必要とする`max(0, mx - a[p])`あちら側に到達するためのエネルギー。 
6. 最終的には両方の側を訪問する必要があるため、2 つの側の要件のうち大きい方を返します。 

なぜ効果があるのか:

 一方向への歩行中、ジャンプするたびに高低差が効果的にドラゴンのエネルギーバランスに変換されます。 ランタンに到達した後に利用できるエネルギーの総量は、開始時の高さと現在のランタンの高さにのみ依存します。 エネルギーを消費する必要がある唯一の状況は、より高いランタンに到達することであるため、最大の障害は常に到達しなければならない最も高いランタンです。 セグメント ツリーは両方向の最も高い障害物を正確に返すため、計算された値は可能な最小の初期エネルギーになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegmentTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, node, left, right, arr):
        if left == right:
            self.tree[node] = arr[left]
            return
        mid = (left + right) // 2
        self.build(node * 2, left, mid, arr)
        self.build(node * 2 + 1, mid + 1, right, arr)
        self.tree[node] = max(self.tree[node * 2], self.tree[node * 2 + 1])

    def update(self, node, left, right, pos, value):
        if left == right:
            self.tree[node] = value
            return
        mid = (left + right) // 2
        if pos <= mid:
            self.update(node * 2, left, mid, pos, value)
        else:
            self.update(node * 2 + 1, mid + 1, right, pos, value)
        self.tree[node] = max(self.tree[node * 2], self.tree[node * 2 + 1])

    def query(self, node, left, right, ql, qr):
        if ql > right or qr < left:
            return -1
        if ql <= left and right <= qr:
            return self.tree[node]
        mid = (left + right) // 2
        return max(
            self.query(node * 2, left, mid, ql, qr),
            self.query(node * 2 + 1, mid + 1, right, ql, qr)
        )

def solve(data):
    it = iter(data.split())
    n = int(next(it))
    q = int(next(it))
    a = [int(next(it)) for _ in range(n)]

    seg = SegmentTree(a)
    ans = []

    for _ in range(q):
        t = int(next(it))
        if t == 1:
            p = int(next(it)) - 1
            left_max = seg.query(1, 0, n - 1, 0, p - 1)
            right_max = seg.query(1, 0, n - 1, p + 1, n - 1)

            need = 0
            if left_max != -1:
                need = max(need, left_max - a[p])
            if right_max != -1:
                need = max(need, right_max - a[p])

            ans.append(str(max(0, need)))
        else:
            p = int(next(it)) - 1
            x = int(next(it))
            a[p] = x
            seg.update(1, 0, n - 1, p, x)

    return "\n".join(ans)

def main():
    data = sys.stdin.read()
    print(solve(data))

if __name__ == "__main__":
    main()
```すべてのクエリは動きを妨げる最大の高さを要求するため、セグメント ツリーには最大値のみが格納されます。 更新操作により 1 つのランタンが変更され、影響を受ける間隔が更新されます。 

クエリで使用されるのは、`-1`空範囲マーカーとして。 すべてのランタンの高さは負ではないため、この値を実際のランタンの高さと混同することはできません。 決勝戦`max(0, need)`関連する側のすべてのランタンが開始ランタンよりも低い場合を処理します。これは、ドラゴンが開始ランタンを下げることで十分なエネルギーを得ることができることを意味します。 

すべてのインデックスは、すぐにゼロベースのインデックスに変換されます。 範囲`0`に`p - 1`そして`p + 1`に`n - 1`開始位置が誤って含まれないように、開始ランタンの 2 つの側面を表します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log n) | 各更新および各範囲最大クエリは、セグメント ツリー内の 1 つのパスに従います。 |
 | スペース | O(n) | ツリーには、ランタンごとに一定数のノードが含まれます。 |

 この制約では、何十万もの操作を処理する必要があります。 対数演算により全体的な回避策が維持されます`n log n + q log n`、意図した制限内に快適に収まります。

 ## 特殊なケース

 この場合の場合:```
2 1
5 10
1 1
```セグメントツリーが返されます`10`右側の最大高さとして。 開始時の高さは、`5`、したがって、必要なエネルギーは`10 - 5 = 5`。 アルゴリズムは最初のジャンプ コストを正確に取得します。 

この場合の場合:```
3 1
10 5 10
1 2
```左右の最大値は両方とも`10`。 スタートランタンは高さがある`5`、したがって、両側が必要です`5`エネルギー。 結果は`5`, これは移動前に中ランタンを上げるのに必要な量です。 

この場合の場合:```
1 1
100
1 1
```隣接するランタンがないため、どちらの範囲クエリでも空のマーカーが返されます。 アルゴリズムは答えをそのまま残します`0`これは、動きが必要ないという事実と一致します。
