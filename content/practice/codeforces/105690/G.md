 ## 解決策
 ## 問題の理解

 位置 1 から位置 m まで、一次元の地面線の上に描かれた一連の水平な「ドラゴン セグメント」が与えられます。 各ドラゴンは、この線上で li から ri までの連続した間隔を占めます。 その間隔内のすべての整数位置で、ドラゴンはドラゴンの力と間隔内の位置の両方に依存する多数の「スケール」を提供します。 

重要な点は、ドラゴンの間隔内の位置がグローバルではなく、そのドラゴンにとってローカルであるということです。 ドラゴンが li から始まる場合、位置 li はそのドラゴンのインデックス 1 に対応し、li + 1 はインデックス 2 に対応し、以下同様になります。 ローカル インデックス j での寄与は pi · j です。 したがって、各ドラゴンはそのセグメントにわたって等差数列に寄与し、左端の pi から右端の pi · (ri − li + 1) まで線形に増加します。 

1 から m までのすべての地上位置 x について、x をカバーするすべてのドラゴンの鱗の合計数が必要です。 

制約は n、m ≤ 2 · 10^5 まであり、各 pi は 2 · 10^6 までの大きさになります。 すべてのドラゴンに対して反復される位置ごとの直接の計算は、最悪の場合、最大 4 · 10^10 の操作が必要になるため、遅すぎます。 ドラゴンごとに反復してカバーされたすべての位置を個別に更新するだけでも O(nm) となり、これは実現不可能です。 

したがって、正しいソリューションでは、すべてのセルに明示的に触れることを回避する方法で範囲寄与を処理する必要があります。 

よくある失敗例は、各ドラゴンをその間隔全体で一定の値を追加するかのように扱うことから発生します。 たとえば、ドラゴンが (1, 3, 1) である場合、単純なアプローチでは、すべての位置 1、2、3 に誤って 1 が加算される可能性があります。正しい寄与はそれぞれ 1、2、3 です。 この間違いにより、重複するケースがすべて破棄されます。 

線形成長を適切に処理せずに寄与分を「シフト」しようとすると、別の微妙な失敗が発生します。 傾きの変化だけを追跡し、オフセットを正しく無視すると、複数の重複する区間間の寄与の位置が簡単にずれてしまう可能性があります。 

## アプローチ

 ブルートフォースソリューションは各ドラゴンを処理し、それがカバーするすべての位置を更新します。 ドラゴン i の場合、j を 1 から ri − li + 1 まで計算し、pi · j を位置 li + j − 1 に追加します。これは定義に直接従うため、簡単で正しいです。 ただし、更新の総数は ∑ (ri − li + 1) であり、最悪の場合は n · m となり、実現可能な制限をはるかに超えます。 

貢献の構造から、さらに有用なことが明らかになります。各ドラゴンはセグメント上で線形関数を生成します。 [li, ri] 内の位置 x では、その寄与は pi · (x − li + 1) = pi · x − pi · (li − 1) に等しくなります。 これにより、各ドラゴンがその間隔にわたって 2 つの独立したコンポーネントに分離されます。1 つは x に比例し、もう 1 つは定数です。 

これにより、問題は、位置 x ごとに 2 種類の範囲更新の合計を維持することに変わります。 1 つのタイプは [li, ri] にわたる「傾きアキュムレータ」に pi を加算し、もう 1 つのタイプは同じ範囲にわたる「定数アキュムレータ」に -pi · (li − 1) を加算します。 両方のアキュムレータが各位置で既知になると、x での最終的な答えは、x での傾き合計の x 倍と x での定数合計を加算したものになります。 

これにより、問題は 2 つの標準的な範囲加算、ポイントクエリ構造に軽減され、差分配列と 1 つのプレフィックス スキャンを使用して実装できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | O(nm) | O(m) | 遅すぎる |
 | 最適 (差分配列) | O(n + m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 区間内の位置 x での各ドラゴンの寄与を pi · x − pi · (li − 1) として書き換えます。 これにより、x に依存する項と x に依存しない項が分離されます。 

2. 2 つの配列を維持し、1 つは累積傾斜寄与を追跡し、もう 1 つは定数オフセットを追跡します。 各ドラゴンは、スロープ配列の間隔内のすべての位置に pi を提供します。

3. 定数配列の場合、各ドラゴンはその区間全体で −pi · (li − 1) を寄与します。 

4. 各更新が O(1) になるように、差分配列を使用して両方のタイプの範囲更新を適用します。 差分配列にはエンドポイントでの変更が保存され、後でプレフィックス合計によって完全な配列が再構築されます。 

5. すべてのドラゴンを処理した後、両方の配列のプレフィックス合計を個別に計算して、位置ごとの傾きと定数値を取得します。 

6. 1 から m までの各位置 x について、最終的な答えを傾き[x] · x + 定数[x]として計算します。 

傾きと定数に分割する理由は、すべての寄与がその区間にわたって x 内でアフィンであるためです。 アフィン関数は加算の下で閉じられるため、すべてのドラゴンを加算するとこの構造が維持されます。 

### なぜ効果があるのか

 任意の固定位置 x では、すべてのドラゴンは寄与しないか、pi · x − pi · (li − 1) に寄与します。 x をカバーするすべてのドラゴンを合計すると、x 内の線形式の合計が得られます。これは、常に (アクティブなドラゴンの円周率の合計) · x とそれらの左端点から導出される定数の合計にグループ化できます。 アルゴリズムは、すべての x についてこれら 2 つの集計量を正確に維持するため、計算結果はすべての位置の直接の定義と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    slope_diff = [0] * (m + 3)
    const_diff = [0] * (m + 3)

    for _ in range(n):
        l, r, p = map(int, input().split())

        slope_diff[l] += p
        slope_diff[r + 1] -= p

        const_val = -p * (l - 1)
        const_diff[l] += const_val
        const_diff[r + 1] -= const_val

    slope = [0] * (m + 2)
    const = [0] * (m + 2)

    for i in range(1, m + 1):
        slope[i] = slope[i - 1] + slope_diff[i]
        const[i] = const[i - 1] + const_diff[i]

    out = []
    for i in range(1, m + 1):
        out.append(str(slope[i] * i + const[i]))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```コードは 2 つの差分配列を保持します。 1 は、各ドラゴンがその間隔にわたって x の係数をどれだけ増加させるかを表します。 もう 1 つは、左端点オフセットによってもたらされる一定のシフトを追跡します。 

プレフィックス合計ステップは、各位置での実際の傾きと定数寄与を再構築します。 勾配はすでに位置 i で有効な寄与のみを集計しているため、勾配 i を乗算することは安全です。 最終的な組み合わせは 1 回のパスで実行されます。 

一般的な実装上の落とし穴は、定数項の負の符号を忘れたり、(l − 1) の代わりに l を誤って適用したりすることです。 もう 1 つは、r + 1 での off-by-one 処理です。これは、更新が間隔の境界で正確に停止するようにするために不可欠です。

 ## 特殊なケース

 1 から始まり 1 で終わる 1 つのドラゴンは、(l − 1) にオフバイワンエラーを導入することなく、数式が j = 1 を正しく処理するかどうかをテストします。 アルゴリズムは定数シフトを −p · 0 に設定するため、答えは位置 1 で p のままになります。 

[1, m] のように完全にオーバーラップするケースを何度も繰り返すと、傾きの累積と定数の累積の両方が正しくスタックされることが保証されます。 各位置 x は、すべての pi の合計の x 倍になり、すべての l − 1 項が均一なカバレッジの下で一貫してキャンセルされるため、定数部分は 0 のままになります。
