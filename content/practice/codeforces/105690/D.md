 ## 解決策
 ## 問題の理解

 廊下は一連の柱です。 カラム`i`含まれています`k_i`プラットフォームは垂直に積み重ねられ、すべて`n`ダンサーはその列の異なるプラットフォームに立つ必要があります。 ダンサーは身長順に並べられているので、ダンサーは`1`常に最も低い位置にあるプラットフォームとダンサーでなければなりません`n`常に最も占有率の高いプラットフォームでなければなりません。 タスクは、完全なパフォーマンスが何回可能であるかを数えることであり、パフォーマンスは各列のダンサーの位置の選択です。 

単一列の場合、`k_i`唯一の本当の決定は、どのプラットフォームかです。`n`プラットフォームの位置が占有されています。 これらのポジションが選択されると、順序付けルールによって選択された最も低いポジションが自動的にダンサーに割り当てられます。`1`、次はダンサーへ`2`、 等々。 その列の可能性の数は、選択する方法の数です。`n`からのポジション`k_i`、二項係数です`C(k_i, n)`。 

列は相互に影響しません。 ダンサーは各列内での順序を維持するだけでよく、ある列で選択したプラットフォームを次の列で選択したプラットフォームに接続することに制限はありません。 パフォーマンスの合計数は、各列の選択肢の数の積です。 

制約はこの観察に基づいて設計されています。 到達できる列数は`100000`、 その間`n`せいぜい`100`。 ダンサーの位置を列挙したり、考えられるすべての配置をシミュレートしようとするソリューションは、単一の列ですら膨大な数の有効な状態を持つ可能性があるため、不可能です。 各列を一定時間または非常に短い時間で処理するアプローチが必要です。 以来`n`が小さい場合は、短いループで組み合わせを計算するだけで十分です。 

いくつかの特殊なケースでは、不用意な実装が失敗する可能性があります。 いつ`n = 1`、各列は正確に寄与します`k_i`一人のダンサーはどこにでも立つことができるので、可能性があります。 例えば：```
Input:
1 3
2 5 4

Output:
40
```順序付けルールを特別な配置が必要なものとして扱うソリューションでは、誤って小さい値が出力される可能性がありますが、答えは単純です。`2 * 5 * 4`。 

列に正確な値がある場合`n`プラットフォームの場合、すべてのプラットフォームを使用する必要があり、その列は 1 つの選択肢のみを提供します。 例えば：```
Input:
3 2
3 5

Output:
10
```最初の列が貢献します`C(3,3) = 1`、2番目は貢献します`C(5,3) = 10`。 このケースを忘れると、不必要な引き算や、常に複数の選択肢があるという誤った仮定につながる可能性があります。 

大きな値にも注意が必要です。 列には次のものを含めることができます`100000`プラットフォームなので階乗まで`100000`モジュラー逆計算が正しく処理される場合に限り使用できます。 以来`n`だけです`100`、各組み合わせを最大で次の積で計算します。`100`用語は不必要な複雑さを避けます。 

## アプローチ

 直接的な総当たりアプローチは、可能なすべてのセットを生成することです。`n`各列の占有プラットフォームを特定し、それらの選択を列全体で組み合わせます。 これは正しいです。すべての有効なパフォーマンスは、列ごとに 1 つのプラットフォームを選択するだけであるためです。 ただし、1 つの列の選択肢の数はすでに`C(k_i, n)`。 と`k_i = 100000`そして`n = 50`, この数字は数え切れないほどです。 ブルートフォースアプローチでは、天文学的な数の状態を処理する必要があります。 

重要な観察は、ダンサーのアイデンティティによって余分な選択肢が追加されるわけではないということです。 プラットフォームのセットが選択されると、順序付けルールによって割り当てが強制されます。 とのコラム`k_i`プラットフォームは組み合わせ値のみを提供し、順列値は提供しません。 

これにより、問題全体が独立した寄与の増加に変わります。 なぜなら`n`小さいので計算できます`C(k_i, n)`直接次のように:`k_i * (k_i - 1) * ... * (k_i - n + 1) / n!`除算はモジュロで実行する必要があります`1e9 + 7`なので、モジュラー逆関数を事前に計算します。`n!`そして、すべての列の寄与にそれを乗算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(k_i, n) の積) | O(C(k_i, n) の積) | 遅すぎる |
 | 最適 | O(m * n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`m`、およびすべての列の高さ。 各列の選択は独立しているため、答えは一度に 1 つの列を考慮して作成されます。 
2. コンピューティング`n!`モジュロ`1e9 + 7`高速累乗を使用してその逆モジュラーを求めます。 すべての組み合わせの計算には除算が必要です`n!`、およびモジュラー逆関数は、モジュロ演算で同等の演算を提供します。 
3. 列の高さごとに`k_i`、占有されているプラ​​ットフォームを選択する方法の数を計算します。 から始める`1`と乗算します`n`からの連続値`k_i - n + 1`を通して`k_i`。 次に、次の逆数を掛けます。`n!`。 
4. この列の寄与をグローバルな答えのモジュロに乗算します。`1e9 + 7`。 ある列でプラットフォームを選択しても、別の列の選択が制限されることはないため、乗算は有効です。 
5. 最終製品を印刷します。 

機能する理由: アルゴリズムは、列ごとに、占有されているプラ​​ットフォームの可能なセットを正確にカウントします。 選択された各セットには、最も低いプラットフォームから最も高いプラットフォームまでのダンサーの割り当てが 1 つだけあるため、順序付け条件によって追加の可能性が生じることはありません。 完全なパフォーマンスは、列ごとに 1 つの有効な状態を個別に選択することで構成されるため、乗算ルールによって正確なパフォーマンス数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def mod_pow(a, b):
    res = 1
    while b:
        if b & 1:
            res = res * a % MOD
        a = a * a % MOD
        b >>= 1
    return res

def solve():
    n, m = map(int, input().split())
    k = list(map(int, input().split()))

    fact = 1
    for i in range(1, n + 1):
        fact = fact * i % MOD

    inv_fact = mod_pow(fact, MOD - 2)

    ans = 1
    for height in k:
        cur = 1
        for x in range(n):
            cur = cur * (height - x) % MOD
        cur = cur * inv_fact % MOD
        ans = ans * cur % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```階乗計算は次までしか行われません。`n`列の最大高さではありません。 これは意図的なものであるため、`n`は選択したプラットフォームの数であり、式には分母のみが必要です`n!`。 

逆モジュラーはフェルマーの小定理を使用して計算されます。`1e9 + 7`プライムです。 指数`MOD - 2`の逆数を与えます`n!`モジュロ演算の下で。 

各列に対して、ループは正確に乗算されます。`n`価値観。 最初の値は`height`、次は`height - 1`、 等々。 これは、組み合わせ式の分子を直接構築します。 レンジはその後停止します`n`したがって、1 つずつずれることはありません。 

Python の整数はオーバーフローしませんが、すべての乗算は剰余化されます。`MOD`すぐに値を小さく保ち、必要な演算に一致させます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m * n) | それぞれの`m`列に必要なもの`n`乗算してその組み合わせを計算します。 |

 ## 特殊なケース

 ダンサーが1人の場合、組み合わせ方程式は次のようになります。`C(k_i, 1) = k_i`。 入力の場合:```
1 3
2 5 4
```アルゴリズムは列の寄与を計算します`2`、`5`、 そして`4`。 製品は`40`、ダンサーが各列で 1 つのプラットフォームを独立して選択するという事実と一致します。 

列にダンサーの数と同じ数のプラットフォームがある場合、すべてのプラットフォームが占有されている必要があります。 のために：```
3 2
3 5
```最初の列は`C(3, 3) = 1`。 2番目は与えます`C(5, 3) = 10`。 アルゴリズムはこれらの値を乗算して返します。`10`。 

すべての列の高さが次の場合`n`、あらゆる動作が強制されます。 のために：```
2 4
2 2 2 2
```各列が貢献します`C(2, 2) = 1`、最終的な答えは残ります`1`。 これにより、アルゴリズムが異なるダンサーの割り当てを誤って別のパフォーマンスとしてカウントしないことが確認されます。
