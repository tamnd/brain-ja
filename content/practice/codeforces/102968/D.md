 ## 解決策
 ## 問題の理解

 各エッジにラベルが付けられた無向グラフが与えられます。 各ラベルは 0 から 0 までの範囲の整数です。$2^k - 1$、値の制限は次の形式であるため、$VAL = 2^k - 1$。 グラフ内の各サイクルのエッジ ラベルの XOR が 0 に等しい場合、すべてのエッジのラベル付けが有効であると見なされます。 

同様に、グラフ内の閉じたウォークを選択し、それに沿ったすべてのエッジ ラベルを XOR した場合、結果はゼロになる必要があります。 タスクは 1 つのラベルを作成することではなく、この制約を満たす異なるラベルがいくつあるかを数えるということです。 少なくとも 1 つのエッジに異なる値が割り当てられている場合、2 つのラベル付けは異なります。 

グラフは時間の経過とともに変化します。 最初のエッジのセットから開始し、次にエッジを切り替えるクエリを処理して、欠落しているエッジを挿入するか、既存のエッジを削除します。 初期状態の後と各クエリの後に、有効なラベルの数を出力する必要があります。 

制約は大きく、最大で$10^5$ノード、$2 \cdot 10^5$初期エッジ、および$10^5$更新情報。 これにより、クエリごとに構造を最初から再計算したり、サイクルを明示的にチェックしたりするソリューションは即座に除外されます。 単純にサイクルを列挙したり、サイクルの完全な基礎を維持しようとするアプローチは、遅すぎるでしょう。 

グラフがフォレストになると、微妙なエッジケースが現れます。 この場合、サイクルはまったく存在しないため、ラベルのすべての割り当ては有効になります。 制約が常にエッジを制限していると誤って解法が仮定すると、解は過小評価されてしまいます。 たとえば、2 つのノード間に 1 つのエッジがある場合、$[0, 2^k-1]$は有効なので、答えは次のようになります。$2^k$、小さいものではありません。 

もう 1 つの重要なエッジ ケースは、グラフが接続されているが複数のサイクルが含まれている場合です。 サイクル制約は独立していないため、単純なサイクル チェック方法では制約が過大にカウントされる可能性があります。 

## アプローチ

 この問題の鍵は、k ビット ベクトルに拡張された GF(2) 上の線形代数における XOR 制約を再解釈することです。 

各エッジ ラベルは k ビット ベクトルです。 すべてのサイクルでゼロへの XOR が行われるという条件は、ラベル付けが各頂点ポテンシャルへの値の割り当てと一致していることを意味します。 具体的には、各ノードに k ビット値を割り当てることができます。$p[v]$、各エッジラベルを次のように定義します$p[u] \oplus p[v]$。 このような割り当てを行うと、すべての内部頂点が XOR テレスコープでキャンセルされるため、すべてのサイクルの合計が自動的にゼロになります。 

これは、有効なラベル付けが、連結成分ごとのグローバル シフトに至るまで、すべての頂点のポテンシャルを選択することによって引き起こされるものであることを意味します。 接続コンポーネントの場合、$c$ノードは自由に選択できます$p$1 つのルートを除くすべてのノードの値があるため、$k \cdot (c-1)$独立したビット。 各ノード値は k ビットであるため、割り当ての総数は次のようになります。$2^{k(c-1)}$。 

ただし、ノードの電位を直接割り当てているわけではありません。 エッジ ラベルを割り当てているため、複数のノードの潜在的な割り当てによって同じエッジ ラベルが生成される可能性があります。 カウントするための正しい方法は、制約の観点から考えることです。各接続コンポーネントでは、サイクル空間によって正確に制約が課されます。$m - n + 1$ビットごとの GF(2) に対する独立した制約。 つまり、各ビットが寄与するということです$n - c$自由度、ここで$c$そのコンポーネント構造内の接続されたコンポーネントの数です。 

ビットは独立しているため、k ビットにわたる合計の自由度は次のようになります。$$k \cdot (n - c)$$したがって、有効なラベルの数は次のようになります。$$(2^k)^{m - n + c}$$エッジが提供するため$m$変数と制約により次元が削減されます。$m - n + c$、循環数。 

したがって、最終的な答えは、現在のグラフの連結成分の数にのみ依存します。$$\text{answer} = (2^k)^{m - n + c}$$グラフは動的に変化するため、エッジの挿入と削除の下で接続されたコンポーネントの数を維持する必要があります。 これは古典的な動的接続の問題です。 標準的なアプローチは、ロールバックをサポートする DSU と組み合わせたセグメント ツリーを使用して、すべてのクエリをオフラインで処理することです。 

各エッジをアクティブな時間間隔にマッピングします。 各間隔は、エッジがクエリのセグメントにわたって継続的に存在することを意味します。 これらの時間範囲をカバーするセグメント ツリーにエッジを挿入します。 次に、セグメント ツリーを走査し、ロールバックを使用して DSU にエッジを適用し、リーフ ノードでのコンポーネント数を計算します。 

ブルート フォース ソリューションでは、クエリごとに DSU を最初から再計算するため、コストがかかります。$O(Q (N+M))$、大きすぎます。 セグメント ツリー + ロールバック DSU により、繰り返しの再計算が削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに DSU を再構築する |$O(Q(N+M))$|$O(N+M)$| 遅すぎる |
 | セグメント ツリー + ロールバック DSU |$O((N+Q)\log Q \cdot \alpha(N))$|$O(N+Q)$| 承認済み |

 ## アルゴリズムのチュートリアル

 動的グラフを一連のエッジ アクティブ間隔として処理し、経時的な接続性を評価します。 

1. 各トグル操作を各エッジのアクティブな時間間隔に変換します。 エッジから最後のアクティブ化時間までのマップを維持します。 エッジが挿入されると、その開始時間を記録します。 取り外した場合は間隔を詰めて保管いたします。 
2. すべてのクエリを処理した後、まだアクティブなエッジは、最終時間まで延長された間隔で閉じられます。 これにより、各エッジが存在する時間間隔の完全なセットが得られます。 
3. 0 から Q までの時間軸にわたってセグメント ツリーを構築します。このセグメント ツリーの各ノードには、その間隔にわたって完全にアクティブなエッジが格納されます。 
4. セグメント ツリーを再帰的に走査します。 各ノードで、そのノードに保存されているすべてのエッジを一時的に DSU 構造に適用します。 DSU は接続されたコンポーネントを維持し、ロールバックをサポートするため、サブツリーの終了後に結合を元に戻すことができます。 
5. 時間 t に対応するリーフに到達すると、現在の DSU 状態の連結成分 c の数を計算します。 
6. 前に導出した式を使用して、次のように計算します。$m - n + c$ここで、m は時間 t におけるアクティブなグラフ内の現在のエッジの数です。 m は時間の経過とともに変化するため、カウンターを介して暗黙的に維持するか、間隔の寄与から再計算します。 
7. 出力$(2^k)^{m - n + c} \bmod (10^9+7)$。 

重要な設計上の選択は、接続構造を時間から切り離すことです。 各セグメント ツリー ノードは、その時間範囲全体に対して有効なエッジのバッチを処理し、ロールバックによりバックトラック時の正確性が保証されます。 

なぜ効果があるのか

 セグメント ツリー ノードの DSU は、セグメント ツリー内の現在のルートからリーフへのパスに沿ってアクティブなエッジのセットを正確に表します。 すべてのエッジは有効期間全体をカバーするノードにのみ挿入されるため、それらのノードをトラバースするときにエッジは正確にアクティブになります。 ロールバックでは、サブツリーの終了後に DSU が前の状態に戻ることが保証されるため、無関係な時間間隔に影響を与えるエッジは存在しません。 これにより、クエリ時間ごとにグラフの正確なシミュレーションが保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)
        self.cc = n
        self.stack = []

    def find(self, x):
        while self.parent[x] != x:
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            self.stack.append((-1, -1, -1))
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.stack.append((b, self.parent[b], a))
        self.parent[b] = a
        self.size[a] += self.size[b]
        self.cc -= 1

    def snapshot(self):
        return len(self.stack)

    def rollback(self, snap):
        while len(self.stack) > snap:
            b, prev_parent, a = self.stack.pop()
            if b == -1:
                continue
            self.size[a] -= self.size[b]
            self.parent[b] = prev_parent
            self.cc += 1

def solve():
    N, M, Q, VAL = map(int, input().split())
    k = VAL.bit_length()

    edges = {}
    active = {}
    seg = [[] for _ in range(4 * (Q + 2))]

    def add(l, r, u, v, idx=1, nl=0, nr=Q):
        if l > nr or r < nl:
            return
        if l <= nl and nr <= r:
            seg[idx].append((u, v))
            return
        mid = (nl + nr) // 2
        add(l, r, u, v, idx * 2, nl, mid)
        add(l, r, u, v, idx * 2 + 1, mid + 1, nr)

    def dfs(idx, l, r, dsu, res, edge_count):
        snap = dsu.snapshot()
        for u, v in seg[idx]:
            dsu.union(u, v)
            edge_count[0] += 1

        if l == r:
            c = dsu.cc
            m = edge_count[0]
            exp = m - N + c
            res[l] = pow(2, k * exp, MOD)
        else:
            mid = (l + r) // 2
            dfs(idx * 2, l, mid, dsu, res, edge_count)
            dfs(idx * 2 + 1, mid + 1, r, dsu, res, edge_count)

        dsu.rollback(snap)
        for _ in seg[idx]:
            edge_count[0] -= 1

    active = {}
    intervals = {}

    def toggle(u, v, t):
        if (u, v) in active:
            intervals[(u, v)].append((active[(u, v)], t - 1))
            del active[(u, v)]
        else:
            active[(u, v)] = t

    for u, v in [tuple(map(int, input().split())) for _ in range(M)]:
        active[(u, v)] = 0

    for t in range(1, Q + 1):
        u, v = map(int, input().split())
        if (u, v) in active:
            intervals.setdefault((u, v), []).append((active[(u, v)], t - 1))
            del active[(u, v)]
        else:
            active[(u, v)] = t

    for e, st in active.items():
        intervals.setdefault(e, []).append((st, Q))

    for (u, v), segs in intervals.items():
        for l, r in segs:
            if l <= r:
                add(l, r, u, v)

    dsu = DSU(N)
    res = [0] * (Q + 1)
    edge_count = [0]

    dfs(1, 0, Q, dsu, res, edge_count)

    print("\n".join(map(str, res)))

if __name__ == "__main__":
    solve()
```この解決策は、まず各エッジを存在の時間間隔に変換します。 セグメント ツリーは各間隔を対数的に多くのノードに分散するため、クエリ時間はその時点でアクティブなエッジによって正確にカバーされます。 

DSU は接続されたコンポーネントを動的に追跡します。 各結合はスタックに記録されるため、再帰が戻ったときに元に戻すことができます。 セグメント ツリー トラバーサルでは、多くの独立した時間範囲にわたって同じ DSU インスタンスが再利用されるため、このロールバック動作は不可欠です。 

表現$m - n + c$葉で評価されます。 変数`edge_count`現在の再帰パスでアクティブなエッジの数を追跡します。 DSU コンポーネント数と組み合わせると、指数に必要な循環数が得られます。 

## 実用的な例

 ### 例 1

 入力:```
3 3 2 1
1 2
2 3
3 1
1 3
3 2
```ここ$k = 1$, したがって、各エッジは 0 または 1 のいずれかになります。 

時間 0 では、3 つのエッジすべてが三角形を形成します。 DSU には 1 つのコンポーネントがあり、エッジは 3 なので、指数は次のようになります。$3 - 3 + 1 = 1$。 答えは$2^1 = 2$。 

最初の削除後、エッジは長さ 2 のパスを形成します。今度はコンポーネントは 1、エッジ 2、指数のままになります。$2 - 3 + 1 = 0$、 答え$1$構造の点では異なりますが、各エッジは独立してラベル付けできるため、最終結果は次のようになります。$2^2 = 4$。 これは、ツリーには制約がないという考えと一致します。 

2 回目の削除後は 1 つのエッジだけが残り、2 つのラベルの選択肢が与えられます。 

| 時間 | コンポーネント c | エッジ m | 指数 m-n+c | 答え |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 3 | 1 | 2 |
 | 1 | 1 | 2 | 0 | 4 |
 | 2 | 2 | 1 | 0 | 2 |

 このトレースは、サイクルを削除することでラベル付けの自由度がどのように高まるかを示しています。 

### 例 2

 4 つのノード上の正方形のサイクルを考えてから、斜めのエッジを追加します。 最初は、サイクル制約によってビットごとに 1 ずつ自由度が減少します。 対角線を追加すると、グラフに追加の独立サイクルが追加され、自由度がさらに低下します。 DSU は、エッジ数が増加する間コンポーネントを固定し、指数に直接影響します。

 ## 特殊なケース

 重大なエッジ ケースは、すべてのエッジが削除され、グラフが完全に空になる場合です。 この状況では、すべてのエッジ セットは実質的に有効であるため、ラベル付けの数は最大となり、次のようになります。$2^{k \cdot 0}$これは事実上、すべてのエッジの選択が独立していることを意味します。 DSU は正しくレポートします$c = N$、作る$m - n + c = 0$、指数は構造コンポーネントごとに 1 に評価され、正確性が維持されます。 

もう 1 つのエッジ ケースは、エッジが複数の重なり合うサイクルを形成する完全に接続されたグラフです。 DSU はコンポーネント数を 1 に固定し、エッジ数は増加します。 これにより、追加の独立サイクルごとに自由度が 1 回だけ減少し、XOR 制約の代数構造と一致することが保証されます。
