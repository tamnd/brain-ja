 ## 解決策
 ## 問題の理解

 都市のコレクションが与えられ、各都市は人口を表す整数値を持ちます。 都市のペアの間に道路を建設することは許可されています。 人口のある2つの都市を結ぶと`a`そして`b`、その道の「利益」は`gcd(a, b)`。 

構造上の要件としては、道路を建設した後、すべての都市が他のすべての都市からアクセス可能でなければならないため、選択された道路がすべてのノードにわたって接続されたグラフを形成する必要があります。 目標は、接続を維持しながら使用する道路をできるだけ少なくすることであるため、有効なソリューションでは必ず正確に使用する必要があります。`N - 1`つまり、事実上スパニングツリーを構築していることになります。 すべてのスパニング ツリーの中で、エッジの重みの合計を最大化するスパニング ツリーが必要です。ここで、各エッジの重みは 2 つのエンドポイントの gcd です。 

したがって、このタスクは、完全なグラフ上の最大スパニング ツリー問題です。`i`そして`j`は`gcd(xi, xj)`。 問題は、グラフが暗黙的かつ高密度であるため、すべてのエッジを列挙することは不可能であるということです。`N = 10^5`。 

この制約は、厳しい計算予算を意味します。 ナイーブ`O(N^2 log N)`あるいは`O(N^2)`アプローチには最大で以下が含まれます`10^10`候補エッジは完全に手の届かないところにあります。 すべてのエッジを格納することさえ不可能です。 これにより、明示的なペアごとの比較を回避し、代わりに gcd の数論的構造を活用することが直ちに強制されます。 

「各番号を最適な GCD パートナーに接続する」などの貪欲なローカル接続を想定すると、微妙な失敗例が発生します。 たとえば、値の場合`[6, 10, 15]`、ローカル gcd の最適な選択は誤解を招く可能性があります。6 ～ 10 を接続すると 2、6 ～ 15 は 3、10 ～ 15 は 5 を与えます。グローバル接続制約を無視してエッジを貪欲に選択すると、重みの高いエッジがコンポーネントをリンクする代わりにコンポーネント内で無駄になる可能性があるため、サイクルが発生したり、より適切なグローバル構造を見逃したりする可能性があります。 

もう 1 つの失敗モードは、素数の観点のみで考えることから生じます。gcd 構造は独立した素因数に関するものではなく、多くのノードにわたる共有約数に関するものであり、これらの重複はセット全体にわたって相互作用します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのペアごとの gcd 値を計算し、エッジを重みでソートし、最大全域木に対するクラスカルのアルゴリズムを実行します。 これは正しいです。MST プロパティは、あらゆる重み付けされたグラフに対する最適性を保証するからです。 ただし、グラフには、`N(N-1)/2`エッジ、つまり約`5 * 10^9`いつ`N = 10^5`。 エッジを生成するだけでもすでに遅すぎて、gcd 計算だけでは壊滅的な結果になります。 

重要な観察点は、エッジの重みが高度に構造化されていることです。 大きな gcd 値`d`両方とも の倍数である数値の間にのみ出現できます。`d`。 エッジについて考える代わりに、考えられる値ごとに視点を反転します。`d`で割り切れるすべての数値をグループ化します。`d`。 ウェイトのあるスパニング ツリー エッジ`d`そのグループ内から来ている必要があります。 

これで、降順に考えることができます`d`。 ウェイトのエッジを使用してコンポーネントを接続しようとします`d`より小さい値に移行する前に。 課題は、割り切れる数を使用してどれだけのコンポーネントをマージできるかを効率的に知ることです。`d`。 これは、逆除数集計と同様に、除数に対するふるいのようなプロセスになります。 

ペアを反復する代わりに、値を反復します。`d`から`1`に`maxA`、すべての倍数を収集し、それらを結合します。 値を処理するとき`d`で割り切れる数の代表的な要素を接続します。`d`。 成功した組合はそれぞれ貢献します`d`これは、重みレベルで効果的にスパニング フォレストを追加しているためです。`d`。 

これが機能するのは、MST 内のすべてのエッジがそのエンドポイントを接続できる最大の除数にチャージされ、より高い gcd エッジが最初に考慮されることが保証されるためです。

 ## アルゴリズムのチュートリアル

 私たちは都市全体にわたってバラバラな集合組合構造を維持しています。 バケットも用意して、値ごとに`v`、どのインデックスに母集団があるかがわかります。`v`。 

候補の gcd 値を大きいものから小さいものまで処理します。 

1. インデックスを値ごとにグループ化して、指定された人口で割り切れる人口を持つすべての都市をすばやく取得できるようにします。`d`。 これにより、すべてのノードを繰り返しスキャンすることが回避されます。 
2. 反復する`d`から`max_value`まで`1`。 それぞれについて`d`、の倍数であるすべての数値を集めます。`d`スキャンすることで`d, 2d, 3d, ...`。 
3. このような複数の値ごとに、その値を持つすべてのインデックスを反復処理し、この除数で見つかった最初の代表とそれらを結合しようとします。 結合が成功するたびに、重みを付けたエッジの追加に対応します。`d`。 
4. 結合が成功するたびに、`d`このエッジは、可能な限り最高の重みレベルで貪欲に構築されているスパニング ツリーの一部であるため、全体的な答えが得られます。 
5. すべての除数レベルが処理されるまで続行します。 DSU はサイクルを決して作成しないことを保証するため、最終的には常に次のようになります。`N - 1`グラフが接続されると結合が成功します。 

### なぜ効果があるのか

 このアルゴリズムは、エッジを列挙することなく、クラスカルのプロセスを効果的にシミュレートします。 それぞれの潜在的なエッジ`(i, j)`最大で最初に遭遇する`d`両方とも`xi`そして`xj`で割り切れます`d`、まさにその通りです`gcd(xi, xj)`除数を下方向に処理すると。 DSU は、2 つのコンポーネントが高い重みで接続されると、それらが低い重みで再接続されなくなり、最大のスパニング ツリー プロパティを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    maxa = max(a)

    pos = [[] for _ in range(maxa + 1)]
    for i, v in enumerate(a):
        pos[v].append(i)

    parent = list(range(n))
    size = [1] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(a, b):
        ra, rb = find(a), find(b)
        if ra == rb:
            return False
        if size[ra] < size[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        size[ra] += size[rb]
        return True

    ans = 0

    for d in range(maxa, 0, -1):
        first = -1
        for m in range(d, maxa + 1, d):
            for idx in pos[m]:
                if first == -1:
                    first = idx
                else:
                    if union(first, idx):
                        ans += d

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは都市に対して DSU を構築し、除数の値に対して逆ふるいを使用します。 の`pos`配列はインデックスを正確な値でグループ化し、複数の値を反復するときに高速アクセスを可能にします。`d`。 

の`find`そして`union`関数はサイズによるパスの圧縮と結合を実装し、操作ごとにほぼ一定の償却された複雑さを保証します。 キーループはすべての約数を反復します。`d`大きいものから小さいものまで、各約数についてすべての倍数をスキャンし、対応するインデックスを結合します。 

変数`first`これは、約数を共有するすべてのノード間で完全なクリークを構築することを回避するため、非常に重要です。 代わりに、それらをツリー構造に接続するだけで、接続をまたぐにはこれで十分です。 

## 実用的な例

| d | 見られるインデックス | 最初 | ユニオン操作 | 追加しました |

 で`d = 5`、有用な共用体は発生しません。 

このトレースは、より高い gcd エッジがどのように優先されるか、および DSU が接続を確保しながら冗長接続をどのように防止するかを示します。 

2 番目の例:```

values = [2, 4, 8]
```で`d = 8`、ノード 2 のみ。

これは、最適なスパニング ツリーと一致する除数の減少によるチェーンの形成を示しています。

 ## 特殊なケース

 単一の都市のケースは簡単ですが、DSU ロジックが少なくとも 1 つの組合を想定している場合、誤って処理されやすくなります。 入力用`n = 1`、アルゴリズムは除数和集合を実行せず、正しく返します。`0`、道路が存在しないため。 

すべての値が同じ場合、たとえば`[6, 6, 6, 6]`、すべてのペアには gcd 6 があります。アルゴリズムは処理します。`d = 6`まず、すべてのノードを正確に使用してツリーに接続します。`n - 1`それぞれが 6 を提供し、結果をもたらす共用体`18`。 すべてのノードがすでに統合されているため、より低い除数は何も行われません。これは、DSU が過剰カウントを正しく防止していることを示しています。 

次のような疎な共有約数の場合`[2, 3, 5, 7]`、それ以上では結合は発生しません`d > 1`、そして`d = 1`このアルゴリズムは、スパニング ツリーが形成されるまでコンポーネントを重み 1 で接続します。 これにより、gcd 構造が強力なエッジを提供しない場合でも、フォールバック接続が正しく処理されることが確認されます。
