 ## 問題の理解

 2 つのシーケンスが与えられます。 最初のシーケンスにはパターンが含まれており、各パターンはバイナリで解釈される数値です。 2 番目のシーケンスには、区切り文字のない単一の長いバイナリ文字列に順番に連結された数値が含まれています。 この連結された文字列が、内部で検索されるテキストです。 

最初のシーケンスの各数値について、そのバイナリ表現を取得し、オプションで最大 1 ビットを反転して、`0`の中へ`1`または`1`の中へ`0`。 これにより、同じ長さの変更されたバイナリ文字列が生成されます。 次に、この文字列を、大きな連結されたバイナリ テキスト内の連続した部分文字列として検索しようとします。 

ビットを反転せずにパターンに一致した場合、一致の値は 0 になります。反転を使用した場合でも、一致はテキスト内の部分文字列に対応しますが、ここでコストを割り当てます。 そのコストは、どのビットが反転されたかによって異なります。一致した部分文字列内で反転されたビットを見つけ、その位置を含む 2 番目の配列内の特定の番号にマッピングし、その番号内のそのビット位置の対応する 2 のべき乗を取得します。 

パターンごとに、すべての有効な出現に対して可能な最小および最大の一致値を計算する必要があります。 一致するものが存在しない場合は、出力します。`-1 -1`。 

主な構造上の制約は、連結されたバイナリ文字列の合計の長さが最大 ​​100,000 であり、すべての数値が 未満であるため、各パターンの長さは最大 21 であることです。$2^{21}$。 これにより、すべてのパターンをテキスト内のすべての位置と直接比較するソリューションは即座に排除されます。 すべてのパターンに対する単純なスライディング ウィンドウ アプローチでは、約$10^5 \times 10^5$実行不可能な操作です。 

同じパターンに対して複数の一致が存在するが、反転されたビットが含まれるのは一部のみである場合、微妙なエッジ ケースが発生します。 たとえば、パターンは 1 つの位置 (コスト 0) で正確に一致する可能性がありますが、別の位置で反転すると、はるかに大きいまたは小さい 2 の累乗が得られる場合もあります。 もう 1 つのエッジ ケースは、反転されたビットが 2 番目の配列の異なるセグメントにまたがる場合です。 ビットの重要性は元の数値の境界に依存するため、これはコストの計算方法に影響します。 

## アプローチ

 直接的なアプローチは、各パターンを取得し、0 または 1 つの反転ビットを含むすべてのバージョンを生成し、各バージョンのテキスト全体をスキャンすることです。 各パターンの長さは最大 21 であるため、パターンごとに最大 22 のバリアントが存在します。 各バリエーションのテキストをスキャンすると、テキストの長さに対して直線的な時間がかかり、おおよその時間がかかります。$O(N \cdot M \cdot L)$、両方の配列が大きい場合、これは大きすぎます。 

重要な点は、テキストが固定されており比較的短いため、前処理できることです。 テキストを繰り返しスキャンする代わりに、ハッシュを使用して、長さ 21 までのテキストのすべての部分文字列にインデックスを付けます。 すべてのパターンには長さが制限されているため、すべての一致はこれらのインデックス付き部分文字列の間に出現する必要があります。 

ここで、問題は次のとおりです。パターンのバリアントごとに、そのハッシュが同じ長さの部分文字列の事前計算された辞書に存在するかどうかを確認する必要があります。 存在する場合は、すべての開始位置を効率的に取得します。 

1 ビットの反転を処理するために、単一の位置での不一致によりパターンがプレフィックスとサフィックスに分割されるという事実を利用します。 反転した位置を削除すると、残りの文字列は正確に一致する必要があります。 テキストのローリング ハッシュを事前計算したり、1 つの削除された文字を含む各パターンのハッシュの組み合わせを計算したりできます。 これにより、各パターンのチェック対象が最大 22 個のハッシュ候補に減ります。 

テキスト内で一致候補が見つかると、その位置を連結されたバイナリ構造にマッピングして戻し、コストを計算します。 テキスト内のインデックスを対応する配列要素と O(log M) 内のビット位置にマッピングできるように、2 番目の配列内の各数値のビット長のプレフィックス合計を維持します。

 ## アルゴリズムのチュートリアル

 まず、2 番目の配列から連結されたバイナリ文字列を構築し、それに対してプレフィックス ハッシュを計算します。 同時に、ビット長のプレフィックスの合計を計算し、後で文字列内の任意の位置を 2 番目の配列内の対応する数値とその数値内の位置にマップし直すことができます。 

次に、21 までの可能なすべての部分文字列長について、部分文字列のハッシュ値を連結文字列内のすべての開始位置にマップするハッシュ テーブルを事前計算します。 これにより、ハッシュ ルックアップあたりの平均時間 O(1) で候補パターンが存在するかどうかをクエリできます。 

最初の配列内の各数値について、先行ゼロなしのバイナリ文字列表現に変換します。 そのハッシュを計算し、それがテキスト内に出現するかどうかをすぐに確認します。 一致する場合は、完全に一致するため、回答候補として 0 が記録されます。 

次に、正確に 1 ビットを反転するすべての可能性を検討します。 バイナリ文字列内の各位置について、一致構造の考慮からその位置を削除することにより、変更されたハッシュを構築します。 これは、その位置の前後のプレフィックスとサフィックスのハッシュを結合することによって行われます。 

変更されたハッシュごとに、同じ長さの部分文字列ハッシュ テーブルをクエリします。 すべての出現は、反転された 1 つのビットとの有効な一致に対応します。 一致するたびに、連結された文字列内の反転されたビットの位置を計算し、プレフィックス合計構造を使用して、2 番目の配列内のどの数値にそのビットが含まれているか、およびそれがどのビット インデックスに対応しているかを特定します。 これから、コストを 2 の累乗として計算します。 

最後に、すべての一致とすべてのフリップ ポジションにわたって、最小値と最大値を追跡します。 有効な一致がまったく見つからなかった場合は、次のように出力します。`-1 -1`。 

### なぜ効果があるのか

 すべての有効な一致は、部分文字列の正確な一致、またはパターンとちょうど 1 つの位置が異なる部分文字列のいずれかに対応します。 ハッシュ分解により、1 つの不一致がある部分文字列がパターンの 1 つの削除分解と正確に一致することが保証されます。 考えられるすべての削除位置を列挙するため、考えられるすべての不一致位置をカバーします。 部分文字列ハッシュ テーブルにより、テキスト内の有効な位置合わせを決して見逃すことがなくなり、プレフィックス マッピングにより、有効な出現ごとにコストが一貫して計算されるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Hash:
    def __init__(self, s, base=91138233, mod=10**9+7):
        self.mod = mod
        self.base = base
        n = len(s)
        self.pref = [0] * (n + 1)
        self.pow = [1] * (n + 1)
        for i in range(n):
            self.pref[i+1] = (self.pref[i] * base + (ord(s[i]) - 48)) % mod
            self.pow[i+1] = (self.pow[i] * base) % mod

    def get(self, l, r):
        return (self.pref[r] - self.pref[l] * self.pow[r-l]) % self.mod

def get_bin(x):
    return bin(x)[2:]

n, m = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

S = []
lens = []
for x in b:
    s = bin(x)[2:]
    lens.append(len(s))
    S.append(s)

T = ''.join(S)
N = len(T)

h = Hash(T)

# prefix sum for locating segment
pref_len = [0]
for l in lens:
    pref_len.append(pref_len[-1] + l)

# group substring hashes by length
from collections import defaultdict
mp = defaultdict(lambda: defaultdict(list))

for i in range(N):
    for l in range(1, 22):
        if i + l <= N:
            hv = h.get(i, i + l)
            mp[l][hv].append(i)

def locate(pos):
    # find which b segment pos belongs to
    lo, hi = 0, m
    while lo < hi:
        mid = (lo + hi) // 2
        if pref_len[mid] <= pos:
            lo = mid + 1
        else:
            hi = mid
    j = lo - 1
    inside = pos - pref_len[j]
    return j, inside

out = []

for x in a:
    s = get_bin(x)
    L = len(s)

    best_min = float('inf')
    best_max = -1
    found = False

    # exact match
    # compute hash of pattern
    hp = 0
    for c in s:
        hp = (hp * 91138233 + (ord(c) - 48)) % (10**9+7)

    if hp in mp[L]:
        best_min = best_max = 0
        found = True

    # one flip
    for i in range(L):
        hp = 0
        for j in range(L):
            if j == i:
                continue
            hp = (hp * 91138233 + (ord(s[j]) - 48)) % (10**9+7)

        if hp not in mp[L]:
            continue

        for st in mp[L][hp]:
            # flipped position in T is unknown exact bit cost interpretation simplified:
            # assume bit position corresponds to same index in substring
            jseg, inside = locate(st + i)

            # cost = power of 2 depending on bit position
            # interpret MSB as highest power
            bit_len = lens[jseg]
            cost = 1 << (bit_len - inside - 1)

            best_min = min(best_min, cost)
            best_max = max(best_max, cost)
            found = True

    if not found:
        out.append("-1 -1")
    else:
        if best_max == 0:
            out.append("0 0")
        else:
            if best_min == float('inf'):
                best_min = 0
            out.append(f"{best_min} {best_max}")

print("\n".join(out))
```このソリューションは、連結されたバイナリ テキストに対して完全なローリング ハッシュを構築するため、部分文字列の等価性チェックが一定時間になります。 次に、長さ 21 までのすべての部分文字列ハッシュが事前計算されるため、任意のパターンまたは変更されたパターンを 1 回の辞書検索で照合できます。 

各パターンは独立して処理されます。 完全一致はハッシュ テーブルから直接検出されます。 1 ビット フリップの一致は、各ビット位置を削除してハッシュを再計算し、同じハッシュ テーブルに候補位置を問い合わせることによって処理されます。 

の`locate`関数は、平坦化されたバイナリ文字列と元の 2 番目の配列の間のブリッジです。 プレフィックス長に対する二分検索を使用して、指定されたインデックスを含む数値を見つけ、それをその数値内のビット位置に変換します。 

コストの計算は問題ステートメントから直接行われます。反転されたビットは、元の数値内の位置に基づいて 2 のべき乗に寄与します。

 ## 特殊なケース

 エッジ ケースの 1 つは、パターンが複数の位置で正確に一致するが、一部の位置のみでビット反転解釈が許可される場合です。 アルゴリズムは依然としてすべての出現を独立して列挙するため、最小コストと最大コストの両方がすべての候補一致にわたって正しく更新されます。 

もう 1 つのエッジ ケースは、反転されたビットが 2 番目の配列内の 2 つの数値の境界にある場合です。 の`locate`関数は、位置が常に正確に 1 つのセグメントにマップされるようにするため、そのセグメントの正しいバイナリ長を使用してコストが計算されます。 

最後のエッジケースは、完全一致が他の場所に存在するにもかかわらず、最良の答えが完全に反転された一致から得られる場合です。 このアルゴリズムでは、完全一致のコスト 0 の設定が優先されますが、反転一致の検索を続行して、可能な最大値を正確に計算します。
