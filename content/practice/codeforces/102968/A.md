 ## 解決策
 ## 問題の理解

 部族の有向グラフが与えられます。各部族はノードであり、それらの間にはすでにいくつかの有向道路が存在します。 目標は、グラフ全体を強力に接続することです。つまり、すべての部族が指示された道路に従って他のすべての部族に到達できる必要があります。 

新しい誘導道路を追加することができます。 トライブ x からトライブ y への道路を追加するコストは任意ではありません。これは 2 つのノードの重み Cx + Cy の合計です。 したがって、考えられるすべての有向エッジには、そのエンドポイントにのみ依存する固定の構築コストがあります。 

タスクは、最小コストを計算するだけでなく、その最小コストで強力な接続を実現するためにどの新しい道路を追加する必要があるかを明示的に出力することでもあります。 

N が 4000 まで、M が 20000 までという制約は、慎重に実装すれば O(N^2) または O(NM) 個のアイデアさえも受け入れられるが、N の 3 次のものは遅すぎることを示唆しています。 これは、強引な接続強化ではなく、グラフ圧縮アプローチを強く指しています。 

素朴な解釈では、グラフが強く結合されるまでエッジを追加してみて、コンポーネントを任意に貪欲に結合することになります。 これが失敗するのは、コスト構造が均一ではないためです。そのため、コンポーネントを接続するノードの選択が重要になります。 

グラフがすでに強く結びついている場合、微妙なエッジケースが現れます。 その場合、正解はコストゼロ、エッジなしです。 常にコンポーネントを接続しようとする単純な実装では、不必要なエッジが誤って追加されてしまいます。 

別の障害モードは、接続エンドポイントとして使用するノードについて凝縮グラフに複数の選択肢がある場合に発生します。 エッジコストはコンポーネントだけでなく特定のエンドポイントに依存するため、コンポーネント内の任意のノードを選択するとコストが膨らむ可能性があります。 

## アプローチ

 重要な観察は、問題は根本的に強く接続されたコンポーネントに関するものであるということです。 グラフを SCC に圧縮すると、結果として得られる構造は有向非巡回グラフになります。 グラフ全体を強く接続するには、この凝縮 DAG が単一の強く接続されたコンポーネントになるようにエッジを追加する必要があります。 

ブルートフォースアプローチでは、SCC のすべてのペア間にエッジを追加するシミュレーションを試み、結果のグラフが強く接続されるかどうかを確認します。 各候補の追加には到達可能性チェックが必要となり、コストは O(N + M) になります。 O(N^2) 個の追加エッジが存在する可能性があるため、実行不可能な O(N^3) 個の最悪のケースが発生します。 

構造的な洞察は、DAG のソースとシンクをサイクルで接続することで、DAG を強力に接続できるということです。 凝縮グラフでは、入次数が 0 のノードがソースであり、出次数が 0 のノードがシンクです。 古典的な結果として、必要なエッジの最小数は max(ソースの数、シンクの数) であり、最適な方法はそれらを循環的にペアにすることです。 

ここで唯一複雑になるのはコストです。 エッジコストはエンドポイントに依存するため、SCC 代表者を恣意的に接続するだけではありません。 代わりに、各 SCC に対して代表ノード (通常はそのコンポーネント内の最小コスト C のノード) を選択します。これは、そのコンポーネントに関係する接続は、そのノードを介した方が安価になるためです。 

各 SCC が最小コストのノードで表されると、SCC DAG を構築し、ソースとシンクを特定して、それらを接続して、追加コストを最小限に抑えながら強力な接続を確保するサイクルのような構造を形成します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースエッジ追加 + チェック | O(N^3) | O(N^2) | 遅すぎる |
 | SCC 圧縮 + 貪欲なマッチング | O(N + M) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

1. Kosaraju または Tarjan アルゴリズムを使用して、元のグラフの強接続成分を計算します。 各ノードにはコンポーネント ID が割り当てられます。 このステップによりサイクルが崩壊し、各コンポーネント内ですべてがすでに相互に到達可能になります。 
2. 各コンポーネントについて、C 値が最小のノードを見つけます。 このノードは、そのコンポーネントの代表として機能します。 このコンポーネントに関係する発信または着信接続では、可能な限り安価なエンドポイントを使用する必要があるため、これを選択します。 
3. 元のすべてのエッジを反復処理して凝縮グラフを作成します。 comp[u] ≠ comp[v] であるすべてのエッジ u → v に対して、有向エッジ comp[u] → comp[v] を追加します。 このグラフは DAG であることが保証されています。 
4. 凝縮グラフ内の各 SCC の入次数と出次数を計算します。 すべてのソース コンポーネント (入次ゼロ) とシンク コンポーネント (出次ゼロ) を特定します。 
5. SCC が 1 つだけの場合、グラフはすでに強く接続されているため、ゼロコストとエッジが出力されません。 
6. それ以外の場合、ソースを S1、S2、...、Sk とし、シンクを T1、T2、...、Tm とします。 これらをペアにしてサイクルを構築します。[1, m-1] の i に対して Ti → S(i+1) を接続し、最後に Tm → S1 を接続します。 k ≠ m の場合、短いリストの要素を循環的に繰り返すことで、max(k, m) を効果的に使用します。 
7. コンポーネント A → B 間の必要な接続ごとに、代表ノード rep[A] → rep[B] を使用して実際のエッジを出力します。 各エッジのコストは C[rep[A]] + C[rep[B]] です。 

### なぜ効果があるのか

 圧縮後、すべての SCC は DAG 内のノードになります。 DAG は、すべてのソースが受信エッジを取得し、すべてのシンクが送信エッジを取得する場合にのみ強力に接続されます。 サイクル構造では、シンクとソースを周期的にペアリングすることで両方の条件を同時に確保し、方向性の不均衡をすべて排除します。 代替ノードを使用しても接続性は改善されずに C 値が増加するだけであるため、代表を使用するとコンポーネント接続あたりのコストが最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    c = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    gr = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        gr[v].append(u)

    visited = [False] * n
    order = []

    def dfs1(u):
        visited[u] = True
        for v in g[u]:
            if not visited[v]:
                dfs1(v)
        order.append(u)

    def dfs2(u, comp_id):
        comp[u] = comp_id
        for v in gr[u]:
            if comp[v] == -1:
                dfs2(v, comp_id)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * n
    cid = 0

    for u in reversed(order):
        if comp[u] == -1:
            dfs2(u, cid)
            cid += 1

    comp_count = cid

    rep = [0] * comp_count
    for i in range(comp_count):
        rep[i] = -1

    for i in range(n):
        if rep[comp[i]] == -1 or c[i] < c[rep[comp[i]]]:
            rep[comp[i]] = i

    indeg = [0] * comp_count
    outdeg = [0] * comp_count
    dag_edges = []

    for u in range(n):
        for v in g[u]:
            if comp[u] != comp[v]:
                dag_edges.append((comp[u], comp[v]))
                outdeg[comp[u]] += 1
                indeg[comp[v]] += 1

    sources = []
    sinks = []

    for i in range(comp_count):
        if indeg[i] == 0:
            sources.append(i)
        if outdeg[i] == 0:
            sinks.append(i)

    if comp_count == 1:
        print(0)
        print(0)
        return

    k = len(sources)
    m = len(sinks)

    edges = []
    L = max(k, m)

    for i in range(L):
        u = sinks[i % m]
        v = sources[(i + 1) % k]
        edges.append((rep[u], rep[v]))

    total_cost = 0
    for u, v in edges:
        total_cost += c[u] + c[v]

    print(total_cost)
    print(len(edges))
    for u, v in edges:
        print(u + 1, v + 1)

if __name__ == "__main__":
    solve()
```実装は、SCC を計算するための Kosaraju のアルゴリズムから始まります。到達可能性に関して重要なのは SCC 構造のみであるため、これは必要です。 逆グラフは、コンポーネント ID を割り当てるために 2 番目の DFS で使用されます。 

SCC の割り当て後、すべてのノードをスキャンし、コストを最小限に抑えたノードを維持することにより、コンポーネントごとに代表的なノードを計算します。 これにより、後のすべてのエッジが各コンポーネント内の可能な限り安価なエンドポイントを使用するようになります。 

次に、入次数と出次数を計算するためだけに凝縮グラフを暗黙的に構築します。 ソースとシンクの識別のみが重要であるため、これ以降、DAG の実際の隣接リストは必要ありません。 

最終的なペアリング ロジックは、ソースとシンクのバランスをとるために必要な数のエッジを正確に構築します。 モジュロインデックスにより、カウントが異なる場合でも正しいラッピングが保証されます。 

## 実用的な例

 ### 例 1

 入力グラフは、複数のコンポーネントが存在する SCC につながります。 凝縮後にソース [1、2] とシンク [3、4] があると仮定します。 

| ステップ | 情報源 | シンク | 追加されたエッジ |
 | --- | --- | --- | --- |
 | 1 | [1、2] | [3、4] | 4→2 |
 | 2 | [1、2] | [3、4] | 3→1 |

 これにより、すべてのコンポーネントを接続するサイクルのような構造が生成され、強力な接続が確保されます。 

このトレースは、SCC カウントが異なる場合でも、循環ペアリングによりすべてのコンポーネントが受信接続と送信接続の両方を取得できることを示しています。 

### 例 2

 すでに強く結びついているグラフを考えてみましょう。 この場合、SCC カウントは 1 になります。 

| ステップ | SCC 数 | アクション |
 | --- | --- | --- |
 | 1 | 1 | 出力 0 エッジ |

 これにより、グラフがすでに要件を満たしている場合、アルゴリズムが不必要なエッジの追加を正しく回避していることが確認できます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、グラフがすでに強く接続されている場合です。 その状況では、SCC 分解により 1 つのコンポーネントが生成されるため、アルゴリズムは即座にゼロ エッジを返します。 たとえば、入力```
3 3
1 2 3
1 2
2 3
3 1
```1 つの SCC を生成します。 DFS の順序付けでは、すべてが 1 つのコンポーネント ID にまとめられるため、ソースとシンクの両方に含まれる要素は 1 つだけであり、早期終了トリガーが発生します。 

もう 1 つの微妙なケースは、複数の SCC が存在するが、すべての SCC が発信構造のみまたは着信構造のみを不均衡に持っている場合です。 インデックスがラップアラウンドするため、循環ペアリングは依然として機能し、すべてのシンクがエッジの開始点として使用され、すべてのソースがエンドポイントとして使用されることが保証されます。 これにより、最終的な拡張グラフでコンポーネントが切断されたままになることが回避されます。
