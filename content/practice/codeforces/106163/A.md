 ## 解決策
 ## 問題の理解

 村は円形に配置されており、各村には単一の作物タイプがあります。 有効な「カット」とは、円を空ではない 2 つの接続された部分に分割することを意味します。 村はサイクルを形成しているため、そのようなカットは円上の連続するセグメントを 1 つの部分として選択することと同等であり、残りの頂点は他の連続するセグメントを形成します。 

選択したパーティションについて、各作物の種類が両側にどのように配分されているかを比較します。 固定タイプの場合、そのタイプの村が最初の部分にいくつあるのか、2 番目の部分にある村がいくつあるのかを数え、絶対的な差をとります。 カットの不均衡は、すべての作物タイプにわたるこれらの絶対的な差異の合計です。 タスクは、すべての有効なカットにわたって可能な限り最小の不均衡を見つけることです。 

入力サイズは大きく、テスト ケース全体の村の総数は最大 300,000 です。 これにより、すべての O(n^2) セグメントを明示的に試行するソリューションは即座に除外されます。 テスト ケースごとに O(n^2) さえも不可能であり、慎重に最適化しない限り O(n√n) さえも危険になります。 

微妙な点は、「カット」は任意のサブセット選択ではないということです。 両方の部分はサイクル上で接続されたままでなければならないため、すべての有効な分割は、1 つの循環区間を X として選択し、その補数を Y として選択することに正確に対応します。これにより、組み合わせサブセット DP の可能性がすべて除去されますが、それでも O(n^2) 個の候補区間が残ります。 

いくつかの危険な状況については、覚えておく価値があります。 

すべての村が同じ作物の種類を持っている場合、両側で合計数が異なるだけで、すべての種類が同じように動作し、完全にキャンセルされるため、どのカットでも不均衡 0 が生成されます。 

n = 2 の場合、考えられるカットは 1 つだけであり、答えは単純に 2 つの単一ノード間の不均衡です。 

単純な間違いは、問題をサイズ n/2 のサブセットを選択するか、またはカウントをグローバルにバランスさせるものとして扱うことです。 接続が連続したセグメントのみに制限されるため、これは失敗します。 たとえば、次のような配列では、`[1, 2, 1, 2]`、たとえどの音程よりも周波数のバランスが良くなるとしても、交互の要素を選択することは不可能です。 

## アプローチ

 ブルートフォースアプローチは簡単です。 円形配列上のすべての可能な間隔を列挙し、両側の周波数カウントを計算し、不均衡を直接評価します。 間隔ごとにカウントを最初から再計算すると O(n) のコストがかかり、間隔が O(n^2) になるため、合計の複雑さは O(n^3) になります。 プレフィックス頻度表を使用しても、分割構造を更新するために単一区間の評価を O(n) に減らすことができますが、区間の数により、このアプローチは依然として遅くなります。 

重要な観察は、セグメント X を固定すると、各色の寄与は X 内での出現回数のみに依存するということです。ある色が X 内で x 回出現し、配列全体の cnt の合計が C の場合、その寄与は |2x − C| になります。 これにより、問題が色ごとの独立した寄与に分割されます。セグメントの更新はセグメントに出入りする要素の数にのみ影響するため、これは重要です。 

この構造により、円形アレイ上にスライディング ウィンドウを維持できるようになります。 配列を長さ 2n まで拡張し、長さが 1 から n − 1 までのすべてのウィンドウを考慮します。ウィンドウごとに、頻度カウントを増分的に維持し、影響を受ける色のみを調整することによって、追加または削除操作ごとに O(1) の不均衡を更新します。 

これにより、問題は、間隔ごとにゼロから再計算するのではなく、シーケンス全体にわたって動的ウィンドウ コストを維持することに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | 増分更新を伴うスライディング ウィンドウ | テスト ケースあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての円形セグメントが通常の連続セグメントになるように、二重化された配列を処理します。 

1. アレイを構築する`b`長さの`2n`元の配列をそれ自体と連結することによって。 これにより、任意の円セグメントを通常の部分配列として表すことができます。 
2. 事前計算`total[c]`、完全な配列内の各色の出現の合計数。 これは、補完側の寄与を暗黙的に計算できるようにするために必要です。 
3. スライディングウィンドウを維持する`[l, r]`の上`b`、頻度表とともに`cur[c]`現在のウィンドウに各色が何回表示されるかを表します。 
4. 現在のウィンドウの不均衡を表す関数を定義します。$$cost = \sum_c |2 \cdot cur[c] - total[c]|.$$この値は動的に維持されます。 
5.初期化`l = 0`、`r = 0`を選択し、その長さが超えないようにしながらウィンドウを拡大します。`n - 1`両方の部分が空であってはいけないためです。 
6. 新しいポジションごとに`r`、追加します`b[r]`窓の中へ。 から色が増えると`x`に`x + 1`、上記の式を使用してその寄与を再計算することで、その色のコストのみを調整します。 これにより、合計の再計算が回避されます。 
7. 拡張後`r`、ウィンドウが大きすぎるときに左から縮小しようとし、要素を削除するときに影響を受ける色のみを再び更新します。 
8. スイープ中、すべての有効なウィンドウが削減の可能性を表すため、すべての状態にわたる最小コストを追跡します。 

重要な考え方は、各更新は 1 つの色にのみ影響し、コスト関数は色ごとに完全に分解されるということです。 

### なぜ効果があるのか

 重要な不変条件は、アルゴリズムが常に、問題によって定義されたとおりに現在のウィンドウの正しい不均衡を維持することです。 これは、コストが独立した色の寄与の合計であり、周波数が変化するたびに、更新の前後で正確な式を使用してその色の寄与のみを再計算するためです。 すべての有効な円形セグメントは 2 倍の配列内のウィンドウとして 1 回だけ現れるため、維持されるすべての状態の最小値は全体的な最適値に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        total = [0] * (n + 1)
        for x in a:
            total[x] += 1

        b = a + a

        cur = [0] * (n + 1)

        def contrib(c):
            return abs(2 * cur[c] - total[c])

        cost = 0
        ans = 10**18

        l = 0

        for r in range(2 * n):
            if r - l == n:
                c = b[l]
                cost -= contrib(c)
                cur[c] -= 1
                cost += contrib(c)
                l += 1

            c = b[r]
            cost -= contrib(c)
            cur[c] += 1
            cost += contrib(c)

            if 1 <= r - l + 1 <= n - 1:
                ans = min(ans, cost)

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、現在のウィンドウの周波数配列とランニングコストが保持されます。 微妙な部分は更新の順序です。周波数を変更する前に、常に色の古い寄与分を減算してから、新しい寄与分を追加します。 これにより、コストが公式と一致することが保証されます。 

ウィンドウ サイズの制約は、ウィンドウ サイズの制限に達しないように強制されます。`n`両方のパーティションが空ではない必要があるためです。 

## 実用的な例

 次のサンプルを考えてみましょう。`a = [4, 4, 1, 1]`。 

それを複製します`[4, 4, 1, 1, 4, 4, 1, 1]`。 合計数は`4:2`、`1:2`。 

有効なサイズのウィンドウをスライドさせます。 たとえば、ウィンドウが選択した場合、`[4, 4]`、 それから`x_4 = 2`、したがって、その貢献度は`|4 - 2| = 2`、色を付けながら`1`貢献する`|0 - 2| = 2`ウィンドウを拡大すると、両方の色が均等に分割されるとバランスが改善され、一方の色がカット全体でわずかにアンバランスになると最小値 1 に達します。 

| ウィンドウ | キュア[4] | キュア[1] | コスト |
 | --- | --- | --- | --- |
 | [4,4] | 2 | 0 | 4 |
 | [4,4,1] | 2 | 1 | 2 |
 | [4,4,1,1] | 2 | 2 | 0 (無効な完全分割は無視されます) |

 両側が空でないことを強制すると、最良の有効な分割はコスト 1 を達成します。 

このトレースは、不均衡が位置ではなく、純粋に各色の分割方法にどのように依存するかを示しています。

 ## 特殊なケース

 すべて等しい場合については、次のようにします。`a = [7, 7, 7, 7]`。 すべてのウィンドウは同じ周波数の動作をします。ウィンドウに x 要素が含まれる場合、寄与率は次のようになります。`|2x − 4|`唯一の色のため。 アルゴリズムはすべてのウィンドウを正しく評価し、最小値は次の時点で発生します。`x = 2`、不均衡がゼロになります。 スライディング ウィンドウはこの構成を自然に通過し、コスト更新メカニズムにより値の一貫性が維持されます。 

最小のケースの場合`a = [1, 2]`、有効なウィンドウのサイズは 1 のみです。`[1]`、貢献は`|2·1 − 1| + |0 − 1| = 2`。 同じことが当てはまります`[2]`。 アルゴリズムは両方をチェックし、2 を返します。これは、任意のカットが 1 つの頂点を他の頂点から分離しているという事実と一致します。
