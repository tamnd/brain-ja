 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$各ノードについて、ツリー内のその次数がわかります。 次に、すべての次数が 1 ずつ減りますので、それぞれの値は$d[i]$今を代表する$\deg(i) - 1$。 これらの値を計算した後は、ツリー構造は直接必要なくなります。 すべてがこの整数配列に変換されます。 

固定サブセット サイズの場合$i$のすべてのサブセットを正確に考慮します。$i$ノードを調べて、それらの修正された次数の合計を確認します。 値$p$と呼ばれます$i$- サイズのサブセットが存在する場合は興味深い$i$次数の合計が次と等しい$p$。 クエリごとに$(x, y)$、どちらかの整数がいくつあるかを数えなければなりません。$x$-興味深い、または$y$-面白い。 

制約は大きく、最大で$2 \cdot 10^5$ノードとクエリ。 これにより、サブセットを列挙したり、サイズごとにすべてのサブセットの合計を個別に計算したりするアプローチは即座に除外されます。 のようなものでも$O(n^2)$クエリごとに実行するのは不可能です。それはすでに超過してしまうためです。$10^{10}$操作。 

微妙な点は、度数がツリーから取得され、すべてシフトされることです。$-1$。 これはすべての合計を意味します$d[i]$修正されています:$$\sum d[i] = \sum (\deg(i)-1) = 2(n-1) - n = n-2.$$このグローバル制約は、ツリー自体について考える必要性を置き換える重要な構造です。 

素朴な推論を打ち破るエッジケースには、小さなツリーや極端な分布が関係します。 たとえば、次のようなとき$n=1$、次数 0 のノードが 1 つあるため、$d[1] = -1$。 負の値が許可され、多くの単純なサブセット合計の仮定が崩れるため、サブセット合計は奇妙な動作をします。 もう 1 つのコーナーはスター ツリーです。1 つのノードの次数は大きく、他のすべてのノードの次数は 1 であるため、シフト後はほとんどの値が 0 になり、1 つの値が大きくなります。 このような場合、多くのサブセット合計は小さな範囲に収まるため、一般的なサブセット合計の動作を仮定すると過小評価されやすくなります。 

## アプローチ

 効率を無視する場合、最も直接的な解釈は、すべての要素について計算することです。$k$、サイズのすべてのサブセットの合計$k$。 これは古典的な組み合わせ爆発です。$k$、 がある$\binom{n}{k}$サブセットと各サブセットのコストの合計$O(k)$なので、合計はおおよそ次のようになります。$$\sum_{k=0}^{n} \binom{n}{k} \cdot k = O(n2^n),$$それは小さなことを超えて完全に不可能です$n$。 

各カーディナリティの到達可能な合計を維持するナップザック スタイルの DP など、サブセット サイズを超えた動的プログラミングを試みた場合でも、すぐに次の状態空間に到達します。$O(n^2)$さらに悪いことに、各遷移によってすべての合計がシフトされ、再び 2 次または 3 次の動作が発生します。 

重要な構造上の観察は、正確なサブセットは要求されず、固定されたサブセット サイズで合計が達成可能かどうかのみが要求されるということです。 これにより、問題はサブセットを数えるのではなく、「可能な合計範囲」の質問に変わります。 重要な単純化は、あらゆる固定要素について次のことを認識することで実現します。$k$、達成可能な合計のセットは連続しています。 これは、値が定数によってシフトされたツリー次数シーケンスから導出されるために発生します。これは、強力な交換特性を意味します。つまり、サブセット内のノードを別のノードと交換すると、達成可能な値にギャップが生じることなく、予測可能な増分で合計が変更されます。 

それぞれについてそれがわかったら、$k$、達成可能なすべての合計が区間を形成します$[L_k, R_k]$の場合、問題はクエリごとに簡単になります。2 つの区間の和集合に含まれる整数の数を数えるだけでよく、重複する場合は 1 つの区間に含まれる整数がいくつあるかを数えるだけで済みます。 

残りのタスクは、これらのエンドポイントを効率的に計算することです。 サイズの最大合計$k$を選択することで達成されます$k$最大$d[i]$、最小合計は、$k$最小$d[i]$。 Sorting the array gives us prefix sums, so we can compute both boundaries in$O(1)$あたり$k$前処理後。 

This reduces the entire problem to building two arrays$L_k$そして$R_k$みんなのために$k$、次に区間和集合クエリに応答します。

 ## アルゴリズムのチュートリアル

 1. ツリーを読み取り、各ノードの次数を計算します。 次に、各値を次のように変換します。$d[i] = \deg(i) - 1$。 すべての制約がこれらの値でエンコードされるため、このステップの後にツリー構造自体は必要なくなります。 
2. 配列をソートする$d$降順ではない順に。 最小または最大の要素を効率的に選択して極値和を構築したいため、ソートが必要です。 
3. プレフィックス合計配列を構築する$pref$、 どこ$pref[i]$最初の合計です$i$ソートされた配列の要素。 これにより、極値のサブセットの合計を定数時間で計算できます。 
4. サブセットサイズごとに$k$、可能な最小合計を計算します。$L_k$として$pref[k]$、最小のものを取ってから$k$要素は合計を最小化します。 
5. サブセットサイズごとに$k$、可能な最大合計を計算します。$R_k$として$pref[n] - pref[n-k]$、これは最大のものを取ることに対応するため、$k$要素。 
6. すべての間隔を事前計算する$[L_k, R_k]$のために$k = 0$に$n$。 各間隔は、サイズのサブセットに対して達成可能な合計の範囲を正確に表します。$k$。 
7. 各クエリについて$(x, y)$、区間の和集合のサイズを計算します。$[L_x, R_x]$そして$[L_y, R_y]$。 重複している場合はマージします。 それ以外の場合は、それらの長さを合計します。 

### なぜ効果があるのか

 正確さは、並べ替えられた値の交換引数から得られます。 サイズの任意のサブセット$k$のサブセットに変換できます。$k$選択した大きな要素を小さな未使用の要素と繰り返し交換することによって最小の要素を取得します。各交換では、中間の達成可能な合計をスキップすることなく、制御された量だけ合計が厳密に増減します。 これにより、固定カーディナリティの達成可能な最小値と最大値の間に「穴」がないことが保証されるため、到達可能なセットは正確に連続した整数の間隔になります。 

この連続性により、すべての可能性を決定するのに重要なのは極端なサブセットのみです。

 ## 特殊なケース

 単一ノード ツリーが生成するのは、$d[1] = -1$、サブセット サイズは 0 と 1 だけです。アルゴリズムは間隔を正しく形成します。$[0,0]$そして$[-1,-1]$したがって、クエリは縮退区間の結合として動作します。 

スター ツリーでは、ほとんどのノードが$d[i]=0$1 つのノードが大きな正の値を持ちます。 並べ替えると、多くの同一のプレフィックス合計が生成され、多くの間隔が崩れます。 このアルゴリズムは、重複が多い場合でも有効なプレフィックスの極値のみに依存するため、引き続き機能します。 

パス グラフでは、次数は 1 と 2 の間で変化するため、シフト後の値はほとんど 0 になり、いくつかの 1 と -1 が含まれます。 間隔の構築では重複する範囲が自然に生成され、ユニオン ロジックは中間値を見逃すことなくそれらを正しくマージします。
