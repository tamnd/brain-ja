 ## 解決策
 ## 問題の理解

 配列と多数のクエリが与えられます。 クエリごとに、配列のセグメントを調べ、そのセグメント内のさまざまな開始点を試します。 

インデックス L から R までの部分配列を修正します。その中の開始位置 i を選択して a[i..R] を確認すると、各位置に左からこれまでに確認された最大値が格納される別の配列が構築されます。 これにより、一連の「ランニング最大値」が生成されます。 i で始まるサフィックスの美しさは、実行中の最大シーケンス内にどれだけ多くの個別の値が現れるかによって定義されます。 

同様に、i から R までスキャンするときに、そのサフィックス内の以前のすべての値よりも厳密に大きい値が見つかった場合にのみ、実行最大値を増やします。 したがって、美しさはまさに、そのサフィックスで新しいレコードの最大値が表示される回数です。 

クエリごとに、[L, R] 内のすべての開始位置 i を試し、サフィックスが生成する最大レコード数を計算し、その最大値を返さなければなりません。 

この制約により、クエリごとに何かを再計算する必要がなくなります。 n が最大 10^6、q が最大 3×10^5 の場合、クエリごとに O(n) さえも不可能であり、すべてのクエリの合計で O(n log n) であっても、注意深い前処理とオフライン処理が必要です。 セグメントにわたってサフィックス統計を繰り返し再計算するソリューションは失敗します。 

素朴な考え方では、接尾辞の美しさは i の単調ではないという微妙な問題が生じます。 初期の要素が大きいと、表示される将来のレコード最大値の数が減少する可能性があるため、早期に開始することが常に役立つとは限りません。 たとえば、[1, 2, 3, 4] のような増加配列では、すべてのサフィックスの美しさ 1 が 1 になりますが、[5, 1, 4, 2, 3] のようなジグザグ配列では、開始点が異なるとレコード最大値の異なるチェーンが生成されます。 これは、問題を単純なプレフィックスまたはサフィックスの集約に帰着させることができないことを意味します。 

## アプローチ

 直接的なアプローチでは、各クエリを個別に評価します。 固定 (L, R) の場合、[L, R] 内のすべての i を試し、サフィックスをシミュレートし、レコードの最大値をカウントします。 最悪の場合、各シミュレーションは O(n) になるため、単一のクエリは O(n) となり、全体では O(nq) になります。 制約があるため、これは実現可能な限界をはるかに超えています。 

重要な観察は、位置 i から開始したときに何が起こるかを再構成することです。 開始値 a[i] を選択すると、次に実行最大値が変化するのは、a[i] よりも大きい値を持つ右の最初の位置になります。 その後、新しい最大値を超える最初の位置で次の変更が行われ、以下同様に続きます。 これにより、各位置がその右側の次に大きな要素を指す決定的なジャンプのチェーンが作成されます。 

これは、すべてのインデックス i が、厳密に大きい値が表示される次のインデックスへのポインターを持ち、これらのポインターに従うと、厳密に増加する値のチェーンが生成されることを意味します。 R で終わるサフィックスの美しさは、[i, R] 内にあるこのチェーン内のノードの数になります。 

この構造が構築されると、問題は R で動的になります。R が大きくなるにつれて、より多くのジャンプが有効になり、一部のサフィックスは追加のレコード最大値を取得します。 クエリごとに再計算する代わりに、R を左から右に処理し、開始インデックス i ごとに、チェーン内のすでにアクティブになっているジャンプの数を維持します。 位置 x に到達するたびに、ジャンプ ポイントの 1 つとして x を使用するすべてのチェーンの値が 1 ずつ増加します。 

次に、各 R で [L, R] の i にわたる範囲最大クエリに答える必要があります。これは、セグメント ツリーを使用した古典的なオフライン スイープになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 次に大きいチェーン + オフライン スイープ + セグメント ツリー | O(n log n + q log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を、各インデックスが右側の次に大きい要素を指す構造に変換します。 これは将来のすべての推論のバックボーンです。 

### ステップ

1. すべてのインデックス i について、その右隣の位置で厳密に大きい値を計算します。 これを nxt[i] と呼びます。 これは、O(n) の単調スタックで実行できます。 このポインターは、i から開始した場合に実行最大値が次に増加する場所をキャプチャします。 
2. 各インデックス i について、nxt[i]、nxt[nxt[i]] などをたどって、増加する「レコード チェーン」を構築します。 このチェーン内の各ノードは、i で始まるいくつかの接尾辞に対して新しい最大値が現れる位置を表します。 
3. 各 i について、最初の位置を除くそのチェーン内のすべての位置を記録します。 このような各位置 x は、R が x に達すると、i で始まるサフィックスが最大レコードを 1 つ追加することを意味します。 
4. バケットを構築します。bucket[x] には、位置 x にレコード イベントを持つチェーンのすべての開始インデックス i が含まれます。 
5. インデックスに対するセグメント ツリーを維持します。 i に格納されている値は、i で始まるサフィックスが現在の R までに持つ最大レコード数を表します。 
6. 空でないすべてのサフィックスには少なくとも 1 つの最大レコード (最初の要素) があるため、すべての値を 1 に初期化します。 
7. R を 1 から n までスイープします。 位置 R に到達すると、bucket[R] を処理し、そのバケット内の i ごとにセグメント ツリーの値をインクリメントします。 
8. 右端点 R を持つ各クエリについて、区間 [L, R] の最大値をセグメント ツリーにクエリすることによって答えます。 

### なぜ効果があるのか

 i で始まる各サフィックスは、次に大きいチェーン内のどのノードが [i, R] 内にあるかによって完全に決まります。 R がこれらのノードの 1 つを通過するたびに、そのサフィックスに対して最大 1 つの追加レコードが有効になります。 次に上位の構造が実行最大値のすべての可能な増加をすでにエンコードしているため、他のメカニズムはレコード最大値を作成または破棄することはできません。 セグメント ツリーは、開始インデックスごとにアクティブ化されたチェーン ノードの正確な数を常に維持するため、[L, R] にわたる範囲最大クエリによって最適な開始点が正確に特定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
q = int(input())

queries = [[] for _ in range(n + 1)]
for qi in range(q):
    L, R = map(int, input().split())
    queries[R].append((L, qi))

# next greater element
nxt = [n] * n
stack = []
for i in range(n - 1, -1, -1):
    while stack and a[stack[-1]] <= a[i]:
        stack.pop()
    nxt[i] = stack[-1] if stack else n
    stack.append(i)

# bucket of events
bucket = [[] for _ in range(n + 1)]

for i in range(n):
    cur = nxt[i]
    while cur < n:
        bucket[cur].append(i)
        cur = nxt[cur]

# segment tree for range max
size = 1
while size < n:
    size <<= 1

seg = [1] * (2 * size)

def seg_update(i):
    i += size
    seg[i] += 1
    i //= 2
    while i:
        seg[i] = max(seg[2*i], seg[2*i+1])
        i //= 2

def seg_query(l, r):
    l += size
    r += size
    res = 0
    while l <= r:
        if l & 1:
            res = max(res, seg[l])
            l += 1
        if not (r & 1):
            res = max(res, seg[r])
            r -= 1
        l //= 2
        r //= 2
    return res

ans = [0] * q

for r in range(1, n + 1):
    for i in bucket[r]:
        seg_update(i)
    for l, idx in queries[r]:
        ans[idx] = seg_query(l - 1, r - 1)

print("\n".join(map(str, ans)))
```次に優れた計算は、標準の単調スタック ロジックです。 バケットの構築により、各チェーンが明示的な「アクティベーション イベント」に変換されるため、R の処理は 1 回の前方スイープになります。 

セグメント ツリーは純粋に開始インデックスに対する範囲最大値クエリに使用されますが、ポイント更新は新しくアクティブ化されたレコード最大値を反映します。 この組み合わせにより、各イベントが 1 回だけ処理されることが保証されます。 

よくある落とし穴は、nxt[i] だけで十分だと想定していることです。 徐々に大きな要素に遭遇すると、レコード最大値が複数回繰り返される可能性があるため、完全なチェーンが必要です。 

## 実用的な例

 ### 例 1

 複数のレコードの最大値が表示されるように値が交互に配置される小さな配列を考えてみましょう。 

スイープによってサフィックスの寄与がどのようにアクティブ化されるかを追跡します。 

| R | アクティブ化されました | 更新された値 (概念) | クエリ結果 |
 | --- | --- | --- | --- |
 | 1 | なし | すべて 1 | 依存します |
 | 2 | 私は2でイベントを持っています | いくつかの私は2になる | 最大値が増加します |
 | 3 | 私は3でイベントを持っています | さらに増分 | 最終的な答え |

 クエリ [1, 3] の場合、アルゴリズムは、最良の i から開始すると増加する最大値の連鎖が得られることを捕捉し、セグメント ツリーは常にその最良の i を選択することを保証します。 

このトレースは、寄与が i の連続したセグメントに関連付けられているのではなく、イベント駆動型の更新に関連付けられていることを示しています。 

### 例 2

 厳密に減少するセグメントを取り上げます。 この場合、nxt[i] は常に i+1 であり、すべてのチェーンは全長です。 

R が増加すると、すべての接尾辞はすぐに最大レコード数の最大値に達します。 

| R | 状態 |
 | --- | --- |
 | 1 | すべて 1 |
 | 2 | いくつか 2 |
 | 3 | もっと見る 3 |

 どのクエリでも、範囲の左端の位置から開始して最大値が常に達成され、セグメント ツリーが均一な成長の下でグローバル最大値を正しく識別していることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + q log n) | 次に優れた計算、チェーン処理、セグメント ツリー操作 |
 | スペース | O(n log n) | バケット、nxt 配列、セグメント ツリー |

 前処理は線形からほぼ線形であり、各クエリは対数的です。 n が最大 10^6、q が最大 3×10^5 であるため、これは一般的な制約内に問題なく収まります。

    from collections import deque

    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())
    queries = [[] for _ in range(n + 1)]
    for qi in range(q):
        L, R = map(int, input().split())
        queries[R].append((L, qi))

    nxt = [n] * n
    stack = []
    for i in range(n - 1, -1, -1):
        while stack and a[stack[-1]] <= a[i]:
            stack.pop()
        nxt[i] = stack[-1] if stack else n
        stack.append(i)

    bucket = [[] for _ in range(n + 1)]
    for i in range(n):
        cur = nxt[i]
        while cur < n:
            bucket[cur].append(i)
            cur = nxt[cur]

    size = 1
    while size < n:
        size <<= 1
    seg = [1] * (2 * size)

    def upd(i):
        i += size
        seg[i] += 1
        i //= 2
        while i:
            seg[i] = max(seg[2*i], seg[2*i+1])
            i //= 2

    def qry(l, r):
        l += size; r += size
        res = 0
        while l <= r:
            if l & 1:
                res = max(res, seg[l]); l += 1
            if not (r & 1):

        for i in bucket[r]:
            upd(i)
        for l, idx in queries[r]:
            ans[idx] = qry(l - 1, r - 1)

    return "\n".join(map(str, ans))

 ## 特殊なケース

 すべてが等しい値を持つ配列の場合、nxt[i] は常に空であるため、すべてのバケットは空で、すべてのサフィックスの美しさは 1 のままです。セグメント ツリーは更新を受け取ることはなく、クエリは常に 1 を返します。これは、新しいレコードの最大値が決して出現しないという事実と一致します。 

厳密に増加する配列の場合、nxt[i] は常に i+1 を指し、各チェーンは完全に線形になります。 すべての R は多くのサフィックス値を急速に増加させ、最大値は常にクエリ範囲内の最も早い開始によって達成されます。セグメント ツリーはすべてのイベントを順番に蓄積するため、これをキャプチャします。 

単一要素クエリの場合、初期化により各位置のビューティがすでに 1 に設定されているため、更新は必要ありません。 イベント処理を行わなくても、アルゴリズムは正しく 1 を返します。
