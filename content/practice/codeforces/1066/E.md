 ## 問題の理解

 2 つの非常に大きな 2 進数が、整数ではなく文字列として与えられます。 最初の数値はプロセス全体を通じて固定されますが、2 番目の数値は減少し続けます。 

このプロセスは機械的です。次の完全な値から開始します。`b`。 各ステップで、次の間のビットごとの AND を計算します。`a`そして現在`b`、その AND 結果を通常の整数値 (バイナリ文字列ではない) として解釈し、それを累積応答に追加します。 次に、次の最下位ビットを破棄します。`b`それを 2 で割って、次まで繰り返します。`b`ゼロになります。 

これについて考えるのに役立つ方法は、縮小バージョンを繰り返しスライドさせているということです。`b`横切って`a`、毎回ビット単位の重複を取得し、それらの数値を合計します。 

制約は大きく、どちらの文字列も最大 200,000 ビットになる可能性があります。 シフトごとに完全なビット単位の AND を再計算するソリューションでは、実質的に最大 O(nm) の作業が実行されますが、これは非常に遅すぎ、最悪の場合は 400 億回のオーダーの演算が必要になります。 これにより、フル スキャンで各ステップを明示的にシミュレートするアプローチは即座に除外されます。 

単純な実装で発生する微妙な問題は、各 AND 結果をバイナリ文字列として扱い、それを繰り返し整数に変換することです。 ビット操作が最適化されたとしても、シフトごとに完全な数値の再構築を繰り返すと、二次的な動作が発生します。 

エッジケースは主にサイズではなく構造に関係します。 1 つの文字列がすべて 1 の場合、すべてのシフトが大きく寄与し、単純な再計算は非常に高価になります。 もし`b`ゼロが長く続く場合、最終的な答えには何の貢献もしないにもかかわらず、単純な実装では依然として不必要にそれらを反復処理します。 

## アプローチ

重要な点は、シフトごとに完全な AND 文字列を個別に再計算する必要が実際にはまったくないということです。 代わりに、一致する各ビット ペアの寄与を、最終的な数値重みの観点から直接再解釈できます。

これにより、問題全体がプレフィックスまたはサフィックスのカウントオーバーに軽減されます。`b`。

 ## アルゴリズムのチュートリアル

 1. 両方のバイナリ文字列を文字の配列に変換し、インデックス 0 が最上位ビットを表すようにインデックスを維持します。 これにより、後でビット重みを一貫して解釈できるようになります。 
2. のすべての位置について 2 のべき乗を法 998244353 で事前計算します。`a`。 インデックスのビット`j`価値に貢献する`2^(n-1-j)`AND 結果に出現する場合。 これにより、べき乗を繰り返し再計算することが回避されます。 
3. サフィックス配列を構築します`b`どこ`suf[j]`1の数を格納します`b[j..m-1]`。 このステップでは、将来のシフトによって指定された位置が何回整列するかを取得します。`a`と`1`で`b`。 
4. 各位置を反復処理します。`j`で`a`。 もし`a[j]`がゼロの場合、何も寄与しないため、完全にスキップできます。 
5. もし`a[j]`が 1 つ、次にすべて`1`で`b`位置にある`k >= j`最終的にはちょうど 1 つのシフトでそれに合わせます。 このようなアライメントの数は、`suf[j]`。 
6.追加`pow2[j] * suf[j]`答えには、998244353 を法として累積します。 
7. 最終的な累積合計を出力します。 

正しさは、一致するすべてのペアが一致するかどうかにかかっています。`(a[j], b[k])`シフト時に 1 回だけ貢献します`i = k - j`、そして正確に貢献します`2^(n-1-j)`答えに。 

### なぜ効果があるのか

 インデックスの各ペア`(j, k)`そのような`a[j] = 1`そして`b[k] = 1`厳密に 1 つの AND 計算に寄与します。`b`その位置になるようにシフトされます`k`位置を合わせます`j`。 この寄与は他のすべてのビットから独立しています。 この意味では、ビット単位の AND は寄与に対して線形であるため、シフトごとに完全な 2 進数を再計算する代わりに、寄与をペアごとに合計することができます。 これにより、シフト畳み込みのようなプロセスが、整列されたものに対する単純な計数問題に変換されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    a = input().strip()
    b = input().strip()

    # suffix count of ones in b
    suf = [0] * (m + 1)
    for i in range(m - 1, -1, -1):
        suf[i] = suf[i + 1] + (1 if b[i] == '1' else 0)

    # precompute powers of 2
    pow2 = [1] * (n)
    for i in range(n - 2, -1, -1):
        pow2[i] = (pow2[i + 1] * 2) % MOD

    ans = 0

    for j in range(n):
        if a[j] == '1':
            ans = (ans + pow2[j] * suf[j]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```サフィックス配列`suf`これは、シフトされたオーバーラップの繰り返しの再計算に代わる重要な最適化です。 べき乗配列は、次の各ビット位置の固定寄与をエンコードします。`a`。 最後のループは両方の部分を直接結合し、シフト プロセスの明示的なシミュレーションを回避します。 

よくある間違いはインデックス作成です`pow2`間違っています。 以来`a[0]`は最上位ビットであり、その重みは`2^(n-1)`したがって、増加する指数を使用するのではなく、それに応じてべき乗配列を調整する必要があります。

 ## 特殊なケース

 いつ`a`単一で構成されています`1`後にゼロが続く場合、最初の位置のみが寄与し、答えは 1 を数えることになります。`b`。 他の位置はすべてスキップされるため、アルゴリズムはこれを直接処理します。 

いつ`b`は高度にスパースであるため、サフィックス配列により、各位置が累積構造内で 1 回カウントされるため、シフト間で繰り返しゼロをスキャンすることがなくなります。 

両方の文字列が 1 で完全に密集している場合、単純なシフトでは同じオーバーラップが繰り返し再計算されますが、最適化されたソリューションでは冗長性を持たずにすべての寄与が 1 つのパスに集約され、最大入力サイズでも安定性が保証されます。
