 ## 問題の理解

 バイナリ配列として表される 1 次元の家が与えられます。 一部の位置にはヒーターがあり、 のマークが付いています。`1`、空のポジションは`0`。 すべてのヒーターは、作動すると、その位置の周囲を連続的に温めます。 加熱半径は固定パラメータによって決定されます`r`、位置にあるヒーターを意味します`pos`からのすべてのインデックスをカバーします`pos - r + 1`に`pos + r - 1`。 

タスクは、ヒーターの位置だけをカバーすることではなく、配列全体のすべてのインデックスが`1`に`n`少なくとも 1 つのアクティブ化されたヒーターの適用範囲内にあります。 存在するすべてのヒーターの中で、それらの適用範囲の合計が家全体を完全にカバーできるように、アクティブにする最小の数を選択する必要があります。 これが不可能な場合、つまり、どのヒーターを選択しても、ある位置をヒーターでカバーできないことを意味します。`-1`。 

制約`n, r ≤ 1000`これは、二次または三次の解法でもまだ許容できることを暗示していますが、問題の構造は、貪欲な区間をカバーするアプローチを示唆しています。 各ヒーターは一定間隔となり、線分をカバーすることが目標となります`[1, n]`最小限の間隔で。 

主なエッジケースは、そのポジションをカバーできる範囲内にヒーターがない場合です。 たとえば、すべてが`a[i] = 0`の場合、間隔は存在せず、答えはすぐに得られます。`-1`。 もう 1 つの微妙なケースは、ヒーターは存在するが、そのカバー範囲の間にギャップが残っている場合です。 たとえば、`r = 2`、各位置のヒーター`1`そして`4`ポジションを離れる`3`範囲が重なっていないかギャップを埋めていない場合はカバーされず、複数のヒーターがあるにもかかわらず完全にカバーすることは不可能です。 

## アプローチ

 ブルートフォースアプローチでは、これをインターバルにわたるセットカバーの問題として扱います。 すべてのヒーター間隔を生成し、再帰的にまたはビットマスク DP を介してすべてのサブセットを試し、それらの和集合がカバーされているかどうかを確認できます。`[1, n]`。 これは正しいですが、次のような問題が発生する可能性があるため、すぐに実行不可能になります。`n`ヒーターなど`2^n`サブセットは、たとえ`n = 1000`。 

問題の構造は一般的なセットカバーよりも具体的です。 各ヒーターはライン上の一定の間隔に対応しており、すべての間隔は独立しています。 位置ごとに並べ替えたりスキャンしたりすると、どのヒーターをアクティブにするかの決定は局所的に貪欲になります。最も左のカバーされていないポイントに立っているとき、その前またはそのポイントでカバーを開始し、可能な限り右端までカバーを拡大するヒーターを選択する必要があります。 

これにより、問題はセグメントをカバーする古典的な最小間隔に変わります。 各ステップで、現在のカバーされていないポイントを維持し、左側の境界が手の届く範囲にあるすべてのヒーターを探します。 その中で、通信範囲が最も広いものを選択します。 この貪欲な選択が機能するのは、より短い間隔を選択すると、将来のリーチが減少するだけであり、後の決定にはまったく役に立たないためです。

 ## アルゴリズムのチュートリアル

 各ヒーターの位置`i`（どこ`a[i] = 1`) 間隔を定義します`[i - r + 1, i + r - 1]`。 これらの間隔は外側に広がる可能性があります`[1, n]`, そこでクランプします。 

次に、家を左から右にスキャンし、常に最初に覆われていない位置をカバーしようとします。 

1. すべての有効なヒーター間隔を構築します。 ヒーターが存在する場合`i`、その左右のカバレッジ境界を計算して保存します。 
2. 間隔を左側のエンドポイントで並べ替えて、順番にスキャンできるようにします。 
3. ポインタを初期化する`i = 1`最初にカバーされていない位置を表すインデックス`idx = 0`インターバルにわたる、およびアクティブ化されたヒーターのカウンター。 
4. ながら`i ≤ n`、左端が以下であるすべての間隔を検索します。`≤ i`。 これらの中で、最大の右端点を持つものを見つけます。 
5. 位置をカバーする間隔がない場合`i`、その場合、ヒーターはこの点に到達できず、タスクは不可能です。 
6. それ以外の場合は、見つかった最適な間隔をアクティブにし、答えを増分して、移動します。`i`に`best_right + 1`。 
7. 範囲全体がカバーされるまで続けます。 

重要な不変条件は、各反復の前にすべての位置が`< i`はすでにカバーされており、位置をカバーできる最適な間隔を選択しています`i`。 間隔は固定されているため、どのソリューションにも少なくとも 1 つの間隔をカバーする必要があります。`i`、そして最も遠くまで伸びるものを選択しても、将来のポジションの実現可能性が低下することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, r = map(int, input().split())
    a = list(map(int, input().split()))

    intervals = []
    for i in range(n):
        if a[i] == 1:
            l = max(1, i + 1 - r + 1)
            rr = min(n, i + 1 + r - 1)
            intervals.append((l, rr))

    intervals.sort()

    i = 1
    idx = 0
    ans = 0
    m = len(intervals)

    while i <= n:
        best = -1
        while idx < m and intervals[idx][0] <= i:
            best = max(best, intervals[idx][1])
            idx += 1

        if best < i:
            print(-1)
            return

        ans += 1
        i = best + 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各ヒーターをカバレッジ間隔に変換し、0 ベースのインデックスから 1 ベースのインデックスに慎重に変換します。 クランプにより、エッジ付近のヒーターが無効な範囲を生成しないようにします。 

メインループは現在のカバーされていない位置を維持します。`i`。 内側のループは、その前またはちょうどその時刻に開始できるすべての間隔を進みます。`i`。 その中で、到達可能な最も遠いエンドポイントを追跡します。 これは重要な貪欲なステップです。1 つのパスで現在の位置の実行可能なオプションをすべて消費し、最適な拡張にコミットします。 

ポインタ`idx`は前方にのみ進むため、各間隔が 1 回処理され、並べ替え後の解が線形に保たれます。

 ## 特殊なケース

 重要なエッジ ケースは、ヒーターが存在するものの、半径の制約により、現在のカバーされていない位置をカバーしていない場合です。 このような状況では、内側のループは左側のエンドポイントとの間隔を見つけません。`≤ i`それは過去に広がる`i`、アルゴリズムは正しく返します`-1`。 たとえば、`n = 5, r = 1`およびヒーターは位置のみにあります`1`そして`5`、各ヒーターはそれ自身のみをカバーするため、中央の位置はカバーされないままになり、その位置で貪欲スキャンは失敗します。`2`。 

もう 1 つの微妙なケースは、間隔が大きく重なる場合です。 ヒーターがたくさんあっても、必要なヒーターは少数だけです。 貪欲な選択により、同じ決定点で利用可能な別のオプションよりも延長が少ないヒーターを無駄にすることがなくなります。
