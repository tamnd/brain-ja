 ## 解決策
 ## 問題の理解

 小さな整数の配列が与えられ、選択したセグメント内の 2 つの位置を繰り返し選択し、後のインデックスの値と前のインデックスの値を XOR することができます。 この操作は時間順で一方向です。前の位置からの情報を後の位置に注入できますが、何も逆流することはありません。 

各クエリは、サブ配列に関する構造的な質問をします。 そのサブ配列内では、インデックスのペア間でこれらの XOR の「加算」を任意の数実行することができます。そして、最終的なシーケンスが厳密に増加するように値を再配置できるかどうかを知りたいと考えています (スワップではなく、これらの XOR 更新によってのみ)。 

両方のインデックスがクエリ間隔内になければならないという制約は、すべてのクエリが GF(2) 上の独立した線形代数のようなシステムであり、そのセグメントに限定されることを意味します。 

境界が非常に狭いため、セグメント全体にわたって基底を最初から再計算するクエリごとのソリューションは遅すぎます。 要素とクエリの合計が最大 2⋅10^5 の場合、クエリごとに O(n) のアプローチでは O(nq) になりますが、これは実行不可能です。 目的のソリューションでは、各クエリがほぼ対数時間または定数時間で応答できるように情報を前処理する必要があります。 

配列に多くの重複またはゼロが含まれる場合、微妙なエッジケースが発生します。 たとえば、[1,1,1] のようなセグメントは厳密に見えるかもしれませんが、この操作では要素を (i=j を選択することで) 消滅させ、ゼロを生成し、別の場所で構造を再構築することができます。 XOR では値が不変であるという単純な解釈は、そのようなケースを誤って拒否してしまいます。 

もう 1 つのエッジ ケースは、実際の値ではなく、セグメント内に存在する独立したビットの数に依存する単調な実現可能性です。 同じマルチセット合計を持つ 2 つのセグメントは、算術絶対値ではなく XOR スパンが重要であるため、動作が異なる場合があります。 

## アプローチ

 ブルート フォース ビューは、許可された操作の下でセグメントの閉鎖をシミュレートすることです。 部分配列から始めて、 a[j] := a[j] XOR a[i] という形式の変換を繰り返し許可します。これは、事実上、前の値を取得して後の位置に追加できることを意味します。 時間の経過とともに、各位置は前の位置の線形結合 (XOR) になる可能性があるため、到達可能な値のセットはプレフィックス ベクトルの線形スパンになります。 

ブルート フォース試行では、クエリごとに、到達可能なすべてのベクトルを再計算するか、構成に対して BFS を試行します。 これはすぐに爆発します。各要素は以前の要素のサブセットの XOR になる可能性があるため、状態空間はセグメントの長さが指数関数的になります。 

重要な観察は、この演算が組み合わせ的な意味での順序には依存せず、GF(2) に対する線形独立性にのみ依存するということです。 どのセグメント内でも、その要素の線形スパンを正確に生成できますが、そのスパンの外側には到達できません。 

これにより、問題が基底問題に変換されます。各セグメントはベクトル空間に対応します。 「厳密に増加するシーケンスに変換できるか」という質問は、「それぞれがスパン内で表現可能な、昇順に配置された r−l+1 個の個別の値のシーケンスが存在するか」になります。 

重要な再定式化は、(XOR の組み合わせを使用したゼロ化と再構築によって) 到達可能な値を独立して割り当てることができるため、実際の制約は、厳密に増加するシーケンスを構築するのに十分な個別の表現可能な値がスパンに含まれているかどうかであるということです。 最小限の要件は、少なくとも r−l+1 個の個別の値を生成できることですが、より正確には、可能な限り最小の構造で順序付けの衝突が強制されないセットを生成できることを保証する必要があります。

決定的な洞察は、XOR 演算によりセグメントの線形基礎を完全に制御できるということです。 セグメントの表現可能な空間はその線形基底によって決定され、厳密に増加するシーケンスを形成する際の唯一の障害は、基底がビット単位の順序付け制約の下でセグメント サイズと同じ長さのチェーンを構築するのに「十分な密度」であるかどうかです。 これは、XOR 基礎とセグメントごとの派生構造不変式の追跡に帰着します。 

到達可能なすべての値が GF(2) 上のベクトル空間の要素であることが認識されると、接頭辞に対する線形基底構造を前処理し、基底をマージすることでクエリに答えることができます。

 ## アルゴリズムのチュートリアル

 セグメント ツリーまたはスパースのマージ可能な構造を使用して、サブ配列に対する線形 XOR ベースを維持します。 値は 2^20 未満であるため、各ノードには最大 20 個のベクトルの基底が格納されます。 

1. 各ノードがその間隔の線形基底を格納するセグメント ツリーを構築します。 リーフ ノードには、a[i] に等しい単一のベクトルが含まれます。 内部ノードは、ベクトルを一方からもう一方に挿入することによって 2 つの塩基をマージします。 

マージ プロセスは GF(2) に対するガウス消去法であり、独立性が維持されます。 
2. クエリ [l, r] の場合、セグメント ツリーから O(log n) 個のノードを結合することによって、そのセグメントのマージされた基底を抽出します。 これにより、サブ配列の完全な線形基底が得られます。 
3. この基底の次元を計算し、d と呼びます。 これにより、セグメント内に独立した方向がいくつ存在するかがわかります。 
4. d をセグメント長 k = r − l + 1 と比較します。d が、XOR 閉包の下で k 個の別個の表現可能な値をサポートするのに十分な大きさであれば、続行します。 それ以外の場合は、「いいえ」と答えてください。 
5. 重要な構造チェックは、スパンが値を厳密に増加させる k のチェーンを生成できなければならないことです。 次元 d の XOR 空間には 2^d の個別の値が含まれるため、実現可能性は 2^d ≥ k かどうかをチェックすることになりますが、これは必要なだけで十分ではありません。 
6. より厳しい条件は、空間に強制的な等価性制約を回避するのに十分な自由度がある限り、昇順で個別の値を割り当てる基底縮小シーケンスを常に構築できるという観察から得られます。 この問題では、既知の特徴付けは、セグメント基底が衝突することなくすべてのプレフィックス最小増分を表現できるかどうかを検証することに正確に崩壊します。これは、基底を使用して貪欲な増加構造で数値を挿入することが成功するかどうかを確認するのと同じです。 
7. 実行中の目標値を維持することにより、厳密に増加するシーケンスを構築しようと貪欲に試みます。 0 から開始して、各位置について、基底を使用して前の値より厳密に大きい表現可能な最小値を見つけようとします。 いかなる段階でもこれが不可能な場合は拒否します。 

XOR 基底を使用すると、基底ベクトルに対するビット操作を介して到達可能な値を昇順で列挙できるため、この貪欲な動作は機能します。 

### なぜ効果があるのか

 不変条件は、どの時点でも、維持される基底が処理されたセグメントの到達可能な線形スパンを正確に表すということです。 増加するシーケンスに対して構築した値はすべて、このスパンのメンバーになります。 貪欲な構造により、常に前の値よりも小さい実行可能な値が選択されます。そのような値が存在しない場合は、必要な長さの厳密に増加するチェーンの形成を妨げるギャップがスパンにあることを意味します。 基礎は到達可能なすべての値を完全に特徴付けるため、このギャップを回避できる代替構築はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXB = 20

def insert_basis(basis, x):
    for b in range(MAXB - 1, -1, -1):
        if (x >> b) & 1:
            if basis[b] == 0:
                basis[b] = x
                return
            x ^= basis[b]

def merge(a, b):
    res = a[:]
    for x in b:
        if x:
            insert_basis(res, x)
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.tree = [[0] * MAXB for _ in range(2 * self.size)]
        for i in range(self.n):
            self.tree[self.size + i] = [0] * MAXB
            insert_basis(self.tree[self.size + i], arr[i])
        for i in range(self.size - 1, 0, -1):
            self.tree[i] = merge(self.tree[2 * i], self.tree[2 * i + 1])

    def query(self, l, r):
        l += self.size
        r += self.size
        left = [0] * MAXB
        right = [0] * MAXB

        def add_to(dst, src):
            for x in src:
                if x:
                    insert_basis(dst, x)

        while l <= r:
            if l & 1:
                add_to(left, self.tree[l])
                l += 1
            if not (r & 1):
                add_to(right, self.tree[r])
                r -= 1
            l >>= 1
            r >>= 1

        return merge(left, right)

def can_make_increasing(basis, length):
    vals = []
    for i in range(length):
        cur = i
        for b in range(MAXB):
            if basis[b] and ((cur >> b) & 1):
                cur ^= basis[b]
        vals.append(cur)

    vals.sort()
    for i in range(1, length):
        if vals[i] <= vals[i - 1]:
            return False
    return True

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        arr = list(map(int, input().split()))
        st = SegTree(arr)

        for _ in range(q):
            l, r = map(int, input().split())
            l -= 1
            r -= 1
            basis = st.query(l, r)
            length = r - l + 1
            print("YES" if can_make_increasing(basis, length) else "NO")

if __name__ == "__main__":
    solve()
```セグメント ツリーには、各間隔の XOR スパンの圧縮表現が保存されます。 各ノードは縮小された基底を保持するため、マージは 20 ベクトルによって制限されたままになります。 クエリでは O(log n) ベースを結合し、それらを最終的な正規ベースに縮小します。 

機能`can_make_increasing`基底から候補の縮小セットを列挙することによって、ベクトル空間が十分な順序付けられた個別の値を生成できるかどうかをシミュレートします。 重要な実装上の選択は、基底ベクトルをすべての到達可能な値のジェネレーターとして扱い、正規に生成されたサブセットで順序付けの実現可能性をテストすることです。 

塩基をマージする際には注意が必要です。各挿入では、縮小形式を維持するために最初に上位ビットを削除する必要があります。 逸脱すると、到達可能な空間を歪める非最小表現が許可される可能性があるため、正確性が損なわれます。 

## 実用的な例

 ### 例 1

 入力:```
n = 4, arr = [1, 2, 2, 1]
query = [1, 4]
```一歩一歩基礎を築いていきます。 

| ステップ | セグメント | 基準寸法 |
 | --- | --- | --- |
 | 1 | [1] | 1 |
 | 2 | [1,2] | 2 |
 | 3 | [1,2,2] | 2 |
 | 4 | [1,2,2,1] | 2 |

 セグメントには 4 つの要素にわたる次元 2 がありますが、XOR の組み合わせにより、0、1、2、3 を含む複数の値を作成できます。生成されたスペースは、長さ 4 の厳密に増加するチェーンを構築するのに十分であるため、クエリは YES を返します。 

このトレースは、基準次元を過度に崩壊させない限り、複製によって実現可能性が低下しないことを示しています。 

### 例 2

 入力:```
n = 3, arr = [1, 1, 1]
query = [1, 3]
```| ステップ | セグメント | 基準寸法 |
 | --- | --- | --- |
 | 1 | [1] | 1 |
 | 2 | [1,1] | 1 |
 | 3 | [1,1,1] | 1 |

 独立した方向は 1 つだけ存在するため、空間には 0 と 1 の 2 つの値のみが含まれます。長さ 3 の厳密に増加するシーケンスを形成することは不可能です。答えは NO です。 

この例では、キーの障害モード (線形独立性が不十分) を分離します。

 ## 特殊なケース

 単一要素を超える順序制約は存在しないため、長さ 1 の最小セグメントは常に成功します。 

完全に一定のセグメントは、次元 1 までの XOR 基底の崩壊を示しています。これにより、到達可能な値が 2 つだけであるため、厳密に増加するより長いシーケンスを構築することができなくなります。 

値が 2 のべき乗であるセグメントは基底独立性を最大化し、フルランク セグメントにより増加シーケンスを構築する際に完全な柔軟性が得られることを示しています。
