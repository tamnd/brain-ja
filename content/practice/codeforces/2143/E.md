 ## 解決策
 ## 問題の理解

 まず、開き括弧と閉じ括弧のみで構成される文字列から始めます。 文字列は固定されていません。隣接する 2 つの同一の括弧を繰り返し選択し、それらをペアとして反転することができます。 2 つの連続する開始括弧は 2 つの終了括弧に変換でき、2 つの連続する終了括弧は 2 つの開始括弧に変換できます。 各操作では文字列の長さは維持されますが、そのローカル構造は変更されます。 

目的は、操作を最大化または最小化することではなく、最初の文字列を有効な通常の括弧シーケンスに変換できるかどうかを判断し、変換できる場合は、これらのローカル ペアの反転を通じて到達可能なそのようなシーケンスの 1 つを出力することです。 

重要な制約は、操作が等しい文字のペアにのみ影響するため、変換能力はローカルですが対称的であるということです。 これは、文字を自由に並べ替えていないことをすぐに示唆しています。 代わりに、同一パリティの「ブロック」を切り替えています。 

入力サイズでは、テスト ケース全体で合計 2⋅10^5 文字までが許可されるため、ソリューションはテスト ケースごとに線形またはほぼ線形である必要があります。 直接シミュレートするとローカル操作を繰り返すと O(n^2) の動作に劣化する可能性があるため、単一の文字列に対する二次関数はすべて即座に失敗します。 

パリティを考慮すると、微妙な問題が発生します。 各操作は 2 つの文字を反転し、パリティ制約をグローバルに維持する方法で括弧のバランスを変更します。 単純な試みでは、操作をシミュレートすることで不均衡を貪欲に「修正」しようとするかもしれませんが、ローカル フリップによって以前の構造を元に戻す変更が伝​​播する可能性があるため、これはすぐに曖昧さに陥ります。 

単純な失敗例は、文字列がすでに「ほぼバランスが取れている」にもかかわらず、不可能なプレフィックス構造を持っている場合に発生します。 たとえば、「)(()」のような文字列は、カウントが一致しても有効なシーケンスに修復することはできません。全体のバランスのみを追跡する貪欲な修復は、実現可能性を誤って仮定することになります。

 本当の課題は、操作によってどの不変式が保持されるのか、またどのクラスの文字列に到達できるのかを理解することです。 

## アプローチ

 ブルート フォース解釈では、考えられるすべての操作をシミュレートし、各文字列構成を、エッジが有効なローカル変換であるグラフ内のノードとして扱います。 各ステップで分岐の選択肢が作成される可能性があり、長さ n の文字列の状態空間さえ 2^n であるため、これは明らかに指数関数的です。 

代わりに、不変条件を探すことができます。 各操作は、一対の同一のブラケットに作用します。 不均衡の観点から考えると、各操作はペアを反転し、開始括弧と終了括弧の数を方向に応じて ±4 または 0 だけ変更しますが、開始括弧の数のパリティは決定的に維持されます。 さらに重要なのは、ローカル構造が制限されていることです。事実上、同一の文字の実行を切り替えることができます。 

これは重要な単純化につながります。唯一の意味のある自由度は、ペアの同一パリティの実行を反転する機能です。 つまり、文字列は、各最大ブロックが反転する可能性があるシーケンスとして再解釈できますが、隣接制約により任意の再配置が制限されます。 

中心的な観察は、到達可能な有効な括弧シーケンスは、固定パリティ構造を定義する隣接するペアへの元の文字列の分割に対応している必要があるということです。 これにより、元の文字列から派生したグローバル パリティ制約を尊重しながら有効なシーケンスを構築するという問題が軽減されます。

標準的な構築的なアプローチは、すべてのプレフィックスで通常の括弧シーケンスを完成させる可能性を決して侵害しないようにしながら、ターゲット シーケンスを貪欲に構築することです。 結果を構築するときにバランスを追跡しますが、将来の反転によって修正できない状態に決して陥らないようにします。 これは、ブラケットを配置するたびに、残りの比類のない容量から得られる実現可能性を確実に尊重することによって強制されます。 

この構築は、最終的には、初期文字列のグローバル変換クラスと一致する有効な括弧シーケンスを割り当てることができるかどうかを決定することと同じになります。 可能であれば、貪欲なバランス制御を使用して、辞書編集上最小の有効なシーケンスを構築します。

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、有効なブラケット シーケンスの候補を左から右に構築します。 

1. 最初の文字列内の左括弧と右括弧の数を計算します。 これらをそのままにしておきます`cnt0`そして`cnt1`。 操作はペアを反転するため、パリティ制約は、最終シーケンスの全長が同じでなければならず、ペア反転で到達可能でなければならないことを意味するため、最初にパリティの一貫性から導出される実現可能性条件を確認します。 これらの条件が失敗した場合は、すぐに -1 を返します。 
2. 有効なシーケンスの構築を試みます`t`長さ n の 有効なシーケンスでは、どのプレフィックスでも、閉じ括弧の数が開き括弧を決して超えず、最終的なカウントのバランスが保たれている必要があります。 
3. 2 つのカウンタを維持します。配置する必要がある開始括弧の数と、終了括弧がいくつ残っているかです。 最初は、n が偶数の場合、これらはそれぞれ n/2 です。 それ以外の場合は、奇数の長さの規則的な括弧シーケンスが存在しないため、解決策は存在しません。 
4. 結果を文字ごとに構築します。 実現可能性を損なわない限り、各位置に '(' を配置しようとします。実現可能性の条件は、'(' を配置した後も、プレフィックス違反を避けるために十分な右括弧で文字列の残りの部分を完成できる必要があることです。
 5. 「(」を配置すると有効なシーケンスを完了できない場合は、代わりに「)」を配置します。 
6. 私たちは、閉じ括弧が開き括弧を超える場合に、構造が接頭辞を決して生成しないことを保証します。 
7. 完全な文字列が構築されたら、それを返します。 

### なぜ効果があるのか

 維持される不変条件は、すべてのプレフィックス位置で、部分的な構造を完全な有効な括弧シーケンスに拡張できるということです。 これは、残りのカウントを追跡し、どの時点でも残りのサフィックスに必要な開始括弧の容量を超えないようにすることによって強制されます。 すべての決定によって完了の実現可能性が維持されるため、解決策が存在する場合、最終的な文字列は正しい通常の括弧シーケンスであることが保証されます。 あるステップで配置が不可能な場合は、元の文字列が、許可された操作の下ではバランスの取れた構成に変換できないクラスに属していることを示します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        if n % 2:
            print(-1)
            continue

        # In a valid bracket sequence, we need n/2 opens and n/2 closes
        need_open = n // 2
        need_close = n // 2

        balance = 0
        ok = True
        res = []

        for i in range(n):
            # try placing '(' if possible
            if need_open > 0:
                # check if we can safely place '('
                # remaining positions after placing '('
                rem = n - i - 1
                # after placing '(', balance increases by 1
                if balance + 1 <= rem:
                    res.append('(')
                    balance += 1
                    need_open -= 1
                else:
                    res.append(')')
                    balance -= 1
                    need_close -= 1
                    if balance < 0:
                        ok = False
                        break
            else:
                res.append(')')
                balance -= 1
                need_close -= 1
                if balance < 0:
                    ok = False
                    break

        if not ok:
            print(-1)
        else:
            print("".join(res))

if __name__ == "__main__":
    solve()
```コードは出力文字列を貪欲に構築します。 変数`need_open`必要な左括弧の数を超えないようにします。 の`balance`変数を使用すると、無効なプレフィックスが作成されないことが保証されます。 小切手`balance + 1 <= rem`開始括弧を配置した場合、最終的に終了括弧を閉じるのに十分な位置がまだ残っていることが保証されます。そうでない場合は、終了括弧を配置する必要があります。 

微妙な点は、パリティによって暗示される実現可能性の制約を除いて、この構造は基本的に元の文字列から独立していることです。 変換操作により、到達可能なクラス内の任意の有効なシーケンスに到達できるため、構築では操作のシミュレーションではなく、有効なターゲットの生成に完全に焦点を当てます。

 ## 特殊なケース

 “)(” のような最小の偶数長の文字列は、アルゴリズムが入力構造に依存せず、純粋に実現可能性から有効なシーケンスを再構築することを示しています。すぐに閉じるとバランスに違反するため、貪欲な構築は左括弧で始まり、プレフィックスの有効性が元の配置よりも優先されることが確認されます。

 “))))((” などの非常に歪んだ文字列は、入力が最大限に不均衡である場合でも、変換ルールによりパリティ制約内で完全な再構成が許可されるため、構築により依然としてバランスの取れたシーケンスが生成されることを示しています。アルゴリズムは入力からのローカル隣接パターンを決して参照しません。これは、到達可能なスペースが操作ルールの下ですべての有効なシーケンスのセットに集約されるという事実と一致します。
