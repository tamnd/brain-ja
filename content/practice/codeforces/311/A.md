 ## 解決策
 ## 問題の理解

 2D 平面上の一連の点が与えられます。 元の幾何学的タスクは通常、すべての点のペアの間で最小のユークリッド距離を計算することです。 ただし、この問題では、その値を直接要求するのではなく、特定のブルート フォース アルゴリズムに指定された数を超える距離チェックを実行させる点の構成を構築するよう求められます。 

アルゴリズムは点を x 座標で並べ替え、各点 i に対して点 j > i を順方向にスキャンします。 i からの x 距離が少なくとも現在の最良の答え d である点が見つかるまで距離を計算し、その点でその i のスキャンを停止します。 量 tot は、この枝刈りがさらなる作業を停止する前に、実際に検査される (i, j) ペアの数をカウントします。 

私たちの出力は計算問題に対する答えではなく、一連の座標です。 どの構築でも tot が k を超えることができないことを証明するか、アルゴリズムが厳密に k を超えるペア チェックを実行するように n 個の別個の整数座標点 (絶対値で 10^9 によって制限される) を明示的に構築する必要があります。 

制約 n ≤ 2000 は十分小さいため、2000² は約 400 万回の操作であるため、O(n^2) の動作は実現可能かぎりぎりです。 これが重要です。アルゴリズムは最悪の場合でも 2 次的ですが、条件によって早期に停止します。`p[j].x - p[i].x >= d`点が x 内に分散されている場合、作業を大幅に削減できます。 

微妙な点は、d が実行中に変化することです。 初期のペアが非常に近い場合、d が小さくなり、ブレーク条件がトリガーされにくくなり、内側のループの実行時間が長くなります。 これはまさに私たちが利用するものです。早期終了がほとんど起こらないように、できるだけ長く d を小さく保ちたいと考えています。 

素朴な誤解は、x によるソートによって常に枝刈りが有効になると想定することです。 これは、点が x 内に十分に分散している場合にのみ当てはまります。 x 内で点を密にクラスター化すると、次のようになります。`p[j].x - p[i].x`は小さいままで、ブレーク条件がほとんどトリガーされず、アルゴリズムは完全な O(n²) スキャンに縮退します。 

## アプローチ

 ブルートフォースの観点は単純明快です。 ソート後、各点 i について、点がなくなるか、x ギャップが現在の最適距離 d を超えるまで、後のすべての点 j をスキャンします。 すべての x 座標が同一またはほぼ同一になるように点が配置されている場合、条件は次のようになります。`p[j].x - p[i].x >= d`d が非常に大きくならない限り、真になることはほとんどありません。 ただし、d は無限として始まり、より近いペアが見つかった場合にのみ減少するため、初期の動作は本質的に完全な入れ子ループになります。 

重要な洞察は、枝刈り条件は x の差のみに依存するのに対し、対物レンズの距離は x と y の両方に依存するということです。 同一の x 座標を持つ点を構築した場合、ブレーク条件は決してトリガーされません。`p[j].x - p[i].x = 0`すべてのペアに。 これにより、アルゴリズムが純粋なペアの列挙に​​折りたたまれ、tot は正確に n(n−1)/2 になります。 

したがって、構築問題は単純になります。必要なのは tot > k だけです。 この縮退幾何学では tot が n で固定されるため、n(n−1)/2 が k を超えるような n を選択します。 次に、同じ x 座標を共有する n 個の異なる点を出力します。 

これが機能するのは、アルゴリズムが依存する幾何学的な枝刈り構造を意図的に破壊しているためです。

 ## アルゴリズムのチュートリアル

 アルゴリズムをシミュレートするのではなく、最悪の場合の構成を構築します。 

1. まず、n 点を使用して k 回の演算を超えることが可能かどうかを判断します。 最悪の場合、アルゴリズムはすべてのペアを検査するため、可能な最大合計は n(n-1)/2 になります。 この値が k より大きくない場合、どの構造も TLE を強制できません。 
2. n(n−1)/2 ≤ k の場合、直ちに「解なし」を出力します。 考えられる最悪の幾何学的構成であっても、アルゴリズムはすべてのペア以上を検査できないため、これは正当化されます。 
3. それ以外の場合は、枝刈りが決してアクティブにならないようにポイントを構築します。 これは、すべての x 座標を等しく設定することによって実現します。たとえば、すべての点について x = 0 に設定します。 
4. y = 0、1、2、...、n−1 などの個別の y 座標を割り当て、すべての点が個別であり、境界内にあることを保証します。 
5. これらの点を出力します。 すべての x の差がゼロであるため、条件は`p[j].x - p[i].x >= d`は有限 d に対して常に false であるため、内側のループが早期に中断されることはありません。 
6. その結果、アルゴリズムはすべてのペア (i, j) を評価するため、tot は n(n-1)/2 に等しくなります。これは構造上、厳密に k より大きくなります。 

### なぜ効果があるのか

 アルゴリズムの枝刈りは、x 座標の分離に完全に依存します。 すべての点を垂直線上に折りたたむことにより、水平方向の分離が除去されます。 ブレーク条件は d を超える x 距離のみに基づいており、x 距離は常に 0 であるため、トリガーされることはありません。 したがって、アルゴリズムは完全なペアごとの列挙に縮退し、tot を最大化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    max_pairs = n * (n - 1) // 2
    if max_pairs <= k:
        print("no solution")
        return

    # construct all points on a vertical line
    for i in range(n):
        print(0, i)

if __name__ == "__main__":
    solve()
```最初の部分では、アルゴリズムが実行できるペア チェックの数に関する理論上の上限を計算します。 これは、何も構築せずに不可能なケースを即座に除外するため、非常に重要です。 

この構築では、すべての点に x = 0 を使用し、y 値を分散して区別性を確保します。 Y 間隔により有効なジオメトリが保証されますが、さらに重要なのは、制約に違反する偶発的な重複を防止することです。 

すべての x 座標が同一になると、最悪の場合の動作が完全に決定されるため、アルゴリズムをシミュレートする必要はありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as _io

    out = _io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    n, k = map(int, input().split())
    if n * (n - 1) // 2 <= k:
        return print("no solution")
    for i in range(n):
        print(0, i)

assert run("3 3\n") == "no solution", "tight bound case"

 ## 特殊なケース

 重要なエッジ ケースは、k がすでにペア評価の最大可能数を超えている場合です。 たとえば、n = 3 および k = 10 の場合、完全な O(n²) スキャンでも 3 つの評価しか生成されません。 この場合、正しい出力は「解決策なし」です。 アルゴリズムは、出力の前に k を n(n−1)/2 と比較することによってこれを処理します。 

もう 1 つのエッジ ケースは、最小の n = 2 です。ここでは、ペアがちょうど 1 つ存在します。 k ≥ 1 の場合、解は存在しません。 k = 0 の場合でも 2 つの点を生成でき、アルゴリズムは常に 1 つのペアを調べて、tot = 1 > 0 を生成します。 

最後の微妙なケースは、点の明確性を確保することです。 x = 0 を固定し、厳密に増加する y 値を使用することで、すべてのペアの x 差を同一に保ちながら一意性を保証します。 これにより、制約に違反することなく最悪の場合の動作が維持されます。
