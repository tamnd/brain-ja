 ## 解決策
 ## 問題の理解

 私たちの農場には、まっすぐな道路と、1 から _n_ までの番号が付けられたいくつかの丘があります。 各丘は、既知の距離だけ前の丘から分離されています。 _m_ 匹の猫がいて、それぞれが特定の時間に特定の丘で歩き回りを終え、そこで餌やりを待ちます。 _p_ フィーダーがいて、すべて丘 1 から始まり、道路に沿って歩き、待っているすべての猫を拾います。 フィーダーは速度 1 で移動し、任意の数の猫を運ぶことができます。 各猫の待機時間は、餌やり手がその丘に到着する時間と猫の終了時間の差です。餌やり手が猫の終了時間よりも遅れて到着する場合、餌やり人が早く到着する場合はゼロになります。 すべての待機時間の合計が最小になるように、すべてのフィーダーの出発時刻をスケジュールしたいと考えています。 

入力により、丘の数 _n_、猫の数 _m_、フィーダーの数 _p_、丘間の距離、各猫の丘と終了時間が得られます。 出力は単一の整数、つまり最小合計待機時間です。 

制約を考慮すると、_n_ と _m_ は 10^5 に達する可能性があります。 10^10 演算は 2 秒を超えるため、どちらのアルゴリズムも 2 次であることは除外されます。 フィーダー _p_ の数は最大 100 と少ないため、猫全体での動的プログラミングまたは凸型最適化が実現可能である可能性があることが示唆されます。 エッジケースとしては、最初の丘で猫がゴールする（決して待たない場合がある）、複数の猫が同じ丘で同時にゴールする、猫がいる丘よりも餌台の数が多いなどが挙げられます。 

フィーダー出発の可能なすべてのスケジュールを試す単純な実装は明らかに不可能です。 もう 1 つの微妙なケースは、複数の猫がまったく異なる時間に同じ丘をゴールする場合です。 最初の猫が終わったらすぐに 1 つのフィーダーを送信するだけでは、別のフィーダーのスケジュールを慎重に設定しないと、後の猫が長く待たされる可能性があります。 

## アプローチ

 強引なアプローチでは、猫の餌やり担当者と出発時刻のすべての割り当てを考慮し、それぞれの待機時間を計算し、最小値を取得します。 _m_ 猫と _p_ フィーダーでは、可能なパーティションの数は _m_ で指数関数的に増加します。 _m_ ≤ 10^5 であるため、フィーダーの猫のすべてのサブセットを反復処理するだけでも実行不可能です。 

重要な観察は、フィーダーが厳密に左から右に移動し、決して後戻りしないことです。 これにより、猫が待つ必要がある時間調整された距離 (猫の終了時間から丘 1 からその丘までの距離を引いたもの) によって猫を並べ替えることができます。 これを分類したら、調整された時間のシーケンスを _p_ 個の連続するグループに分割するものとして問題を扱うことができます。各グループは 1 つのフィーダーによって処理されます。 グループ内の最も早い猫の調整された時間に給餌器が出発する場合、グループの合計待ち時間は最小限に抑えられます。 これにより、問題は古典的な凸型コスト分割問題に帰着し、分割統治最適化を使用した動的プログラミングによって解決できます。 

最適化を行わないと、_p_ 個のフィーダーの _m_ 頭の猫の DP は O(m^2 * p) となり、_m_ = 10^5 には遅すぎます。 コスト関数の凸性特性を使用することにより、分割統治 DP はこれを O(m * p log m) に削減しますが、これは制約を考慮すると許容可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m) | O(m) | 遅すぎる |
 | 凸最適化を使用した DP | O(m * p log m) | O(m * p) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 丘間の距離のプレフィックスの合計を計算し、丘 1 を基準とした各丘の正確な位置を取得します。これにより、フィーダーが時刻 0 に出発した場合に、猫の丘を正確な到着時刻に変換することができます。 
2. 猫ごとに、調整された終了時間を計算します。`adjusted_time = t_i - prefix_distance[h_i]`。 これは、猫が終了したときに正確に到着するために、フィーダーが丘 1 を出発する最後の時間です。 この調整された時間によって猫を分類することで、必要なフィーダー出発時間の早い順に猫を処理することが保証されます。 
3. 調整された時間順に猫を並べ替えます。 最適なソリューションでは、フィーダーを逆方向に送る必要はなく、猫を分類された順序でグループ化することで、各フィーダー グループ内での待ち時間が最小限に抑えられます。 
4. DP 配列を定義する`dp[i][k]`最初の待ち時間の最小値として`i`猫が使っている`k`フィーダー。 連続する猫のグループのコスト関数は、各猫の調整時間とそのグループの最小調整時間の差の合計です。 
5. 調整された時間のプレフィックス合計を事前計算して、単一のフィーダーが猫に給餌するときの猫の任意の間隔の合計待ち時間をすばやく計算します。 
6. 分割統治最適化を DP に適用します。コスト関数は凸であり、最適な分割点を意味します。`dp[i][k]`は最適な分割の左側にあります`dp[i+1][k]`。 これにより、内部ループが DP 状態ごとに O(m) から O(log m) に減少します。 
7. 答えは次のとおりです。`dp[m][p]`、すべての待ち時間の最小合計を表します。`m`全部使ってる猫たち`p`フィーダー。 

正確さを保証する不変条件は、各フィーダーが分類された猫の連続するグループにサービスを提供し、各グループの出発時間がそのグループ内の最小調整時間であることです。 他の割り当てを行うと、シーケンスの早い段階で猫が後で処理されると待ち時間が長くなるため、待ち時間が長くなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m, p = map(int, input().split())
    d = list(map(int, input().split()))
    
    pos = [0] * n
    for i in range(1, n):
        pos[i] = pos[i-1] + d[i-1]
    
    cats = []
    for _ in range(m):
        h, t = map(int, input().split())
        cats.append(t - pos[h-1])
    
    cats.sort()
    
    prefix = [0] * (m+1)
    for i in range(1, m+1):
        prefix[i] = prefix[i-1] + cats[i-1]
    
    INF = 10**18
    dp = [INF] * (m+1)
    dp_prev = [0] + [INF]*m

    def cost(l, r):
        total = prefix[r] - prefix[l-1]
        count = r - l + 1
        return total - cats[l-1]*count

    for k in range(1, p+1):
        def compute(l, r, optl, optr):
            if l > r:
                return
            mid = (l + r) // 2
            best = (INF, -1)
            start = max(optl, 1)
            end = min(mid, optr)
            for j in range(start, end+1):
                val = dp_prev[j-1] + cost(j, mid)
                if val < best[0]:
                    best = (val, j)
            dp[mid] = best[0]
            opt = best[1]
            compute(l, mid-1, optl, opt)
            compute(mid+1, r, opt, optr)
        
        compute(1, m, 1, m)
        dp_prev, dp = dp, [INF]*(m+1)
    
    print(dp_prev[m])

if __name__ == "__main__":
    main()
```最初のセクションでは、プレフィックスの合計を使用して丘の位置を計算します。 次に、猫ごとに調整された終了時間が計算されます。 並べ替えにより、フィーダーからの出発が最小である順に猫を処理することが保証されます。 プレフィックス合計により、グループ待ち時間の O(1) 計算が可能になります。 DP は分割統治の最適化を実装します。`compute`関数は、各 DP 状態に最適な分割を再帰的に見つけます。 

注意点としては、プレフィックス合計規則に一致させるために猫に 1 から始まるインデックスを使用すること、大きな整数を次のように処理することが含まれます。`INF`、必要なデータの上書きを避けるために、反復ごとに DP 配列を個別に保ちます。
