 ## 解決策
 ## 問題の理解

 線形配置があります`h`1 から 1 までの番号が付けられたセル`h`。 これらのセルの一部には宝物が含まれており、それぞれが正のドル値を持っています。 Freda は最初のセルから開始し、最初はステップ サイズが 1 つだけあります。`k`、彼女が正確に前進できるようにします`k`セルを繰り返し移動するか、最初のセルに戻ります。 時間が経つにつれて、彼女は新たなステップサイズを得るかもしれないし、宝の価値が減らされるかもしれないし、あるいは最も貴重な到達可能な宝を取るように求められるかもしれない。 各操作により、彼女の移動能力または宝物の状態が変化します。 課題は、これらの操作を効率的にシミュレートし、宝物を取得したときに宝物の価値を報告することです。 

この問題にはいくつかの厳しい制約があります。`h`最大 10^18 になる可能性があり、すべてのセルを明示的に追跡するアプローチは除外されます。 宝の数`n`と操作`m`は最大 10^5 になる可能性があり、O(n・m) アプローチでは遅すぎることを意味します。 ステップサイズ`k`追加される移動は小さく、最大 10^4 であり、追加のステップ サイズは最大 20 です。これは、すべての位置を明示的に追跡する代わりに、数学的構造 (モジュラー算術または剰余に対する BFS) を使用することを示唆しています。 

重要なエッジケースは、現在のステップ サイズでは手の届かないところに宝が存在する場合です。 たとえば、到達可能なセルが次の倍数のみである場合、`k`、これらの倍数にない宝物は、タイプ 3 クエリでは無視される必要があります。 同様に、複数の宝物が同じ価値を持つ場合があります。 取得するインデックス付きの最小の宝物を常に選択する必要があります。 

タイプ 3 のクエリごとにすべての宝物を反復処理する単純なソリューションは失敗します。`n * m`最大 10^10 になる可能性があり、これは許容できないほど大きくなります。 到達可能性を素早く確認し、最大の宝物を見つける方法が必要です。 

## アプローチ

 ブルート フォース アプローチでは、すべてのトレジャーのリストを保持し、タイプ 3 のクエリごとにすべてのトレジャーを反復処理して、現在のステップ サイズで到達可能かどうかを確認し、最大値を選択します。 タイプ 1 の各操作 (ステップ サイズの追加) では、到達可能なセルを再計算する必要があります。 n と m が最大 10^5 で、タイプ 3 の各クエリが n 個の宝物すべてをスキャンする可能性がある場合、O(n・m) 操作が必要となり、これは非常に遅すぎます。 

重要な洞察は、問題が利用可能なステップ サイズの最大公約数 (GCD) を法とした到達可能性に帰着するということです。 セル 1 から到達可能な位置は、1 に現在のステップ サイズの線形結合を加えたものとして表現できます。 すべてのステップ サイズの GCD を追跡すると、その位置にあるすべての宝物が`a_i`であれば到達可能です`(a_i - 1) % gcd == 0`。 これにより、到達可能性チェックが単純なモジュロ演算に削減されます。 

タイプ 3 のクエリを効率的に処理するために、到達可能なステータスごとにグループ化された、優先キュー (最大ヒープ) またはトレジャー値をキーとしたマルチセットを維持します。 タイプ 2 の操作によってトレジャーが変更されるたびに、構造内のその値が更新されます。 タイプ 3 の場合、到達可能なセットから単純に最大値を抽出します。 タイプ 1 は GCD を更新し、以前は到達できなかった宝物を到達可能なものに変換する可能性があります。 新しい GCD に基づいて到達可能な宝物を再計算できますが、追加されるステップ サイズは最大 20 であるため、再計算はめったに発生せず、許容可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・m) | O(n) | 遅すぎる |
 | GCD ベース + ヒープ | O(m log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 読み取り入力: セル数`h`、宝の数`n`、操作数`m`、および初期ステップ サイズ`k`。 宝物をペアで保管する`(position, value)`そして入力インデックスによってそれらを追跡します。 
2. ステップ サイズのセットを初期化します。`{k}`そして電流を計算します`gcd`すべてのステップ サイズの。 この GCD は、どの位置に到達できるかを定義します。`a_i`であれば到達可能です`(a_i - 1) % gcd == 0`。 
3. 最初に到達可能な宝物の最大ヒープまたは順序付きマルチセットを構築します。 高速更新のために、トレジャー インデックスからそのヒープ エントリへのマッピングを維持します。 
4. 各操作について:

 - タイプ 1: ステップ サイズを追加します。`x`。 設定されたステップ サイズを更新し、GCD を再計算します。 まだ到達できない宝物の到達可能性を再評価します。新しい GCD で到達可能になった宝物はヒープに挿入されます。 
- タイプ 2: 宝の価値の減少`x`による`y`。 宝物がヒープ内にある場合は、その値を適切に更新します。 ヒープの実装によっては、ヒープの順序を維持するために削除して再挿入することがあります。 
- タイプ 3: ヒープから到達可能な最大値の宝物を抽出します。 その値を出力します。 ヒープから削除して、取得されたことを示します。 ヒープが空の場合は 0 を出力します。 
5. すべての操作が処理されるまで続行します。 

正確性は、ヒープに到達可能な宝物が常に正確に含まれるという不変条件に依存します。 GCD プロパティは、到達可能な位置が現在のステップ サイズの線形結合として表現できることを保証します。`(a_i - 1) % gcd == 0`到達可能性を正確に把握します。 宝物の値が変更されたり、到達可能性が変化したりすると常に宝物が更新されるため、タイプ 3 のクエリは常に正しい最大到達可能な宝物を返します。 

## Python ソリューション```python
import sys
import math
import heapq

input = sys.stdin.readline

def main():
    h, n, m, k = map(int, input().split())
    treasures = []
    for _ in range(n):
        a, c = map(int, input().split())
        treasures.append([a, c, _])  # store position, value, index

    step_sizes = [k]
    gcd = k
    reachable = []
    unreachable = []

    for idx, (a, c, i) in enumerate(treasures):
        if (a - 1) % gcd == 0:
            heapq.heappush(reachable, (-c, i, idx))  # max-heap by value, break ties by index
        else:
            unreachable.append(idx)

    treasure_values = [c for a, c, _ in treasures]

    for _ in range(m):
        op = input().split()
        if op[0] == '1':
            x = int(op[1])
            step_sizes.append(x)
            new_gcd = gcd
            for s in step_sizes:
                new_gcd = math.gcd(new_gcd, s)
            if new_gcd != gcd:
                gcd = new_gcd
                # move treasures that became reachable
                still_unreachable = []
                for idx in unreachable:
                    a, c, i = treasures[idx]
                    if (a - 1) % gcd == 0:
                        heapq.heappush(reachable, (-treasure_values[idx], i, idx))
                    else:
                        still_unreachable.append(idx)
                unreachable = still_unreachable

        elif op[0] == '2':
            x = int(op[1]) - 1
            y = int(op[2])
            treasure_values[x] -= y
            a, _, i = treasures[x]
            if (a - 1) % gcd == 0:
                # re-insert updated value
                heapq.heappush(reachable, (-treasure_values[x], i, x))
        else:  # op[0] == '3'
            while reachable:
                val, i, idx = heapq.heappop(reachable)
                if treasure_values[idx] == -val:
                    print(treasure_values[idx])
                    treasure_values[idx] = 0  # mark as taken
                    break
            else:
                print(0)

if __name__ == "__main__":
    main()
```このソリューションは、到達可能な宝物と到達不可能な宝物を分離します。 ヒープにより、最大限の宝を効率的に入手できるようになります。 GCD は到達可能性を維持し、慎重な更新により値の削減に対処します。 マークを付けて宝物を削除する`treasure_values[idx] = 0`複雑なヒープ削除操作を回避します。
