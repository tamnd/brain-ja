 ## 解決策
 ## 問題の理解

 整数の配列と一連のクエリが与えられます。 各クエリは、部分配列の合計を求めるか、部分配列内のすべての要素を 3 乗するように指示します。 出力は、95542721 を法として計算された合計クエリに対する回答で構成されます。 

配列の長さは最大 100,000 個の要素にすることができ、最大 100,000 個のクエリを実行できます。 各クエリの配列を直接合計または更新する単純なアプローチでは、最悪の場合、最大 10^10 の演算が実行されます。これは、数秒以内に計算できる量をはるかに超えています。 これは、範囲合計クエリと範囲変更の両方を効率的に実行できるデータ構造が必要であることを意味します。 

この問題の厄介な点は、立方体演算です。 繰り返しの立方体化は線形ではないため、加算や代入のための遅延伝播などの標準的な範囲加算手法は直接機能しません。 さらに、法 95542721 は素数であり、繰り返しの立方体を効率的に事前計算できるほど十分に小さいです。 

単純な実装では、更新ごとにすべての要素をキューブ化しようとする可能性があります。 たとえば、配列が次の場合、`[2, 3]`配列全体を 2 回 3 乗します。不注意なループで十分です。`2**3 = 8`、 それから`8**3 = 512`、`3**3 = 27`、 それから`27**3 = 19683`。 原理的には正しいですが、範囲が広い場合、これは遅すぎます。 立方体ごとにすべての要素に触れないようにする方法が必要です。 

## アプローチ

 ブルートフォース手法では、配列を直接反復処理します。 合計クエリの場合、範囲内のすべての要素をループし、95542721 を法として加算し、結果を出力します。 立方体更新の場合、範囲内のすべての要素をループし、それぞれを 95542721 を法とする 3 乗して、書き戻します。 このアプローチは正しいですが、遅すぎます。 n と q が最大 10^5 の場合、配列全体に対する最悪の場合のクエリでは 10^10 の演算が発生する可能性があります。 

重要な洞察は、3 乗法が 95542721 を法として周期的であるということです。95542721 を法とする数値の繰り返し 3 乗法を計算すると、最終的にはシーケンスが循環します。 実際、この素数を法として、任意の整数 x は最大 48 回の 3 乗反復後に元の値に戻ります。 この観察により、各要素を最大 48 の長さのサイクルとして扱うことができます。値を配列上で直接 3 乗する代わりに、各セグメントに対して事前に計算された 48 個の累乗を保存し、セグメントが 3 乗された回数へのポインターを維持します。 その後、Sum クエリは現在のポインターに基づいて値を結合し、範囲全体を 3 乗するとポインターが 48 を法として増加するだけです。 

遅延伝播を備えたセグメント ツリーを使用してこれを実装します。 各ノードは、その間隔の繰り返しの 3 乗を表す 48 個の合計の配列を格納します。 遅延値は、その間隔の保留中のキューブの数です。 伝播するとき、遅延値に従って合計配列を回転させます。 クエリは、要素ごとにキューブを再計算することなく、正しい合計にアクセスします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * q) | O(n) | 遅すぎる |
 | キューブ サイクルを使用したセグメント ツリー | O(q * log n) | O(n * 48) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各要素の 95542721 を法とする立方数シーケンスを事前計算します。 要素 x について、次を計算します。`x^(3^k) % 95542721`k = 0 ～ 47 の場合。これらの 48 個の値を配列に格納します。 これにより、各要素のキューブ化サイクルが定義されます。 
2. セグメントツリーを構築します。 各ノードは範囲を表します`[l, r]`配列の。 単一の合計を保存する代わりに、48 個の合計の配列を保存します。ここで、k 番目の要素は、k 回 3 乗した後のその範囲内のすべての要素の合計です。 これにより、任意の数の保留中のキューブに対する合計クエリに答えることができます。 
3. 遅延伝播を使用してキューブの更新を処理します。 各ノードには遅延カウンターがあります`lazy`間隔を何倍にするかを示します。 ノードがキューブ更新を受信すると、インクリメントされます。`lazy`モジュロ 48 を生成し、必要になるまで子の更新を延期します。 
4. 保留中の遅延値をノードに適用するには、その 48 個の合計の配列を次のように回転させます。`lazy`ポジション。 たとえば、次の場合`lazy = 1`、さらに 1 つの 3 乗後の合計はインデックス 1 の合計になり、2 つの 3 乗後の合計はインデックス 2 になり、以下同様にラップアラウンドが発生します。 
5. 合計クエリの場合は、通常のセグメント ツリー クエリと同様にツリーを走査します。 ノードにアクセスするときは、保留中の遅延回転を適用し、現在の遅延値に対応する合計配列から正しい値を合計します。 
6. 2 つの子を結合するときは、遅延回転を考慮して、それらの合計配列を要素ごとに結合します。 これにより、親ノードの合計がその子ノードと常に一致することが保証されます。 

機能する理由: 各ノードは、48 の可能な立方体状態をすべて維持します。 遅延伝播により、更新が失われないことが保証されます。キューブ化操作を反映するために配列を回転するだけです。 正しい回転インデックスから読み取られた合計クエリ。 回転とモジュラー演算は一貫性があり、可逆的であるため、これにより正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 95542721
CYCLE = 48

class Node:
    __slots__ = ('sums', 'lazy')
    def __init__(self):
        self.sums = [0] * CYCLE
        self.lazy = 0

def cube_cycle(x):
    arr = [x % MOD]
    for _ in range(CYCLE-1):
        arr.append(pow(arr[-1], 3, MOD))
    return arr

def merge(left, right):
    node = Node()
    for i in range(CYCLE):
        node.sums[i] = (left.sums[i] + right.sums[i]) % MOD
    return node

def rotate(arr, k):
    k %= CYCLE
    return arr[k:] + arr[:k]

class SegmentTree:
    def __init__(self, data):
        self.n = len(data)
        self.tree = [Node() for _ in range(4*self.n)]
        self.build(1, 0, self.n-1, data)
        
    def build(self, v, l, r, data):
        if l == r:
            self.tree[v].sums = cube_cycle(data[l])
            return
        m = (l+r)//2
        self.build(2*v, l, m, data)
        self.build(2*v+1, m+1, r, data)
        self.tree[v] = merge(self.tree[2*v], self.tree[2*v+1])
    
    def push(self, v):
        lazy = self.tree[v].lazy
        if lazy:
            self.tree[2*v].lazy = (self.tree[2*v].lazy + lazy) % CYCLE
            self.tree[2*v+1].lazy = (self.tree[2*v+1].lazy + lazy) % CYCLE
            self.tree[v].sums = rotate(self.tree[v].sums, lazy)
            self.tree[v].lazy = 0
    
    def update(self, v, l, r, ql, qr):
        if qr < l or r < ql:
            return
        if ql <= l and r <= qr:
            self.tree[v].lazy = (self.tree[v].lazy + 1) % CYCLE
            self.tree[v].sums = rotate(self.tree[v].sums, 1)
            return
        self.push(v)
        m = (l+r)//2
        self.update(2*v, l, m, ql, qr)
        self.update(2*v+1, m+1, r, ql, qr)
        self.tree[v] = merge(self.tree[2*v], self.tree[2*v+1])
    
    def query(self, v, l, r, ql, qr):
        if qr < l or r < ql:
            return 0
        if ql <= l and r <= qr:
            return self.tree[v].sums[self.tree[v].lazy]
        self.push(v)
        m = (l+r)//2
        return (self.query(2*v, l, m, ql, qr) + self.query(2*v+1, m+1, r, ql, qr)) % MOD

n = int(input())
a = list(map(int, input().split()))
tree = SegmentTree(a)
q = int(input())
for _ in range(q):
    t,l,r = map(int, input().split())
    l -= 1; r -= 1
    if t == 1:
        print(tree.query(1,0,n-1,l,r))
    else:
        tree.update(1,0,n-1,l,r)
```このコードは、事前に計算された立方体シーケンスを使用してセグメント ツリーを構築します。 遅延伝播では、毎回電力を再計算するのではなく、これらのシーケンスをローテーションします。 更新により、遅延カウンターがインクリメントされ、配列が回転します。 クエリは、現在の遅延値を考慮して正しい合計を読み取ります。
