 ## 解決策
 ## 問題の理解

 映画のチケットを買うために行列ができています。 各人は 25、50 ルーブル、または 100 ルーブル相当の紙幣を持ち、チケットの価格は 1 枚あたり 25 ルーブルです。 店員はお金を持たずに開始し、列の正確な順序でチケットを販売し、必要に応じて正しいおつりを渡さなければなりません。 課題は、店員が全員にうまくサービスを提供できるかどうかを判断することです。 

入力により人数が提供されます$n$そして各人が保有する紙幣を表す一連の整数。 すべての人が正しいお釣りでチケットを購入できる場合、出力は「YES」、そうでない場合は「NO」です。 

と$n$まで$10^5$2 秒の制限がある場合、線形または線形に近いソリューションが必要です。 現在保有している現金を繰り返し検索するアプローチにはリスクが伴います。$O(n^2)$複雑なため、制限時間を超える可能性があります。 

明らかではないエッジ ケースには、小銭を提供するのに十分な少額紙幣がないにもかかわらず、高額紙幣が早期に出現するシーケンスが含まれます。 たとえば、次のような行がある場合、`[50, 25]`, 店員はお金がない状態からスタートするため、初めての人にはお釣りを渡すことができません。 もう一つの厄介なケースは、`[25, 25, 50, 100]`対`[25, 50, 25, 100]`、100ルーブル紙幣のお釣りを渡すときに利用可能な紙幣を慎重に扱う必要があります。 

## アプローチ

 ブルートフォースアプローチでは、キューをシミュレートし、各人に対して、利用可能な請求書のすべての組み合わせを試して、正確な釣り銭を提供します。 100 ルーブルの紙幣の場合、これには、以前に収集された 25 ルーブルと 50 ルーブルの複数のサブセットをチェックすることが含まれる場合があります。 原理的には正しいですが、最悪の場合の複雑さは急速に増大します。$n$人、最大$O(n)$変更を見つけるために操作が必要になる場合があります。$O(n^2)$。 のために$n = 10^5$、これは遅すぎます。 

重要な観察は、すべての紙幣を保管する必要はなく、25 枚と 50 枚を数えるだけでよいということです。 50 ルーブル紙幣には常に 25 が 1 枚必要で、100 ルーブル紙幣には 50 と 25 が 1 枚、または 25 が 3 枚必要です。 これにより、問題は貪欲な戦略に帰着します。つまり、常に可能な限り最大の紙幣を使用しておつりを渡すということです。 これが機能するのは、より安価な組み合わせでは、少額の紙幣が高額の紙幣の代わりにならないためです。そのため、高額な紙幣を優先しても有効な解決策が妨げられることはありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのカウンターを初期化します。`c25`25ルーブル紙幣の場合と、`c50`50ルーブル紙幣の場合。 どちらもゼロから始めてください。 これらは、店員が現時点で何枚の請求書を持っているかを追跡します。 
2. 列に並んでいる各人を繰り返し調べて、彼らが持っている請求書を調べます。 
3. その人が 25 ルーブル紙幣を持っている場合は、増額します。`c25`変更する必要がないため、1 つずつ増えます。 これにより、店員が将来の取引に使用できる現金が増加します。 
4. その人が 50 ルーブル紙幣を持っている場合は、`c25`少なくとも 1 つです。 その場合はデクリメントします`c25`1つずつ増加します`c50`1つずつ。 そうしないと店員はおつりが渡せないので「NO」を出力して終了します。 
5. その人が 100 ルーブル紙幣を持っている場合は、まず 50 ルーブルを 1 枚と 25 ルーブルを 1 枚使っておつりを渡すようにします。これは、使用する 25 ルーブルの数が少なくなるからです。 もし`c50 >= 1`そして`c25 >= 1`、それに応じて両方をデクリメントします。 それ以外の場合は、次のことを確認してください`c25 >= 3`おつりとして 25 を 3 つ与える。 どちらのオプションも不可能な場合は、「NO」を出力して終了します。 
6. ループが失敗せずに完了した場合は、「YES」を出力します。 

機能する理由: 各ステップで、店員の状態が 25 ルーブル紙幣と 50 ルーブル紙幣の数によって完全に把握されます。 つり銭には常に可能な限り最大の紙幣を使用することで、将来の取引を妨げることはありません。 不変条件は、店員の現金構成が常に以前のすべての取引を許可し、貪欲な選択が失敗した場合、他の組み合わせは成功しないということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
bills = list(map(int, input().split()))

c25 = 0
c50 = 0

for bill in bills:
    if bill == 25:
        c25 += 1
    elif bill == 50:
        if c25 == 0:
            print("NO")
            sys.exit(0)
        c25 -= 1
        c50 += 1
    else:  # bill == 100
        if c50 >= 1 and c25 >= 1:
            c50 -= 1
            c25 -= 1
        elif c25 >= 3:
            c25 -= 3
        else:
            print("NO")
            sys.exit(0)

print("YES")
```コードはアルゴリズムのステップを正確に反映しています。 カウンターを初期化すると、店員のリソースを常に把握できるようになります。 100 ルーブル紙幣の貪欲な選択は明らかであり、25 ルーブルの枯渇を最小限に抑えるために 50 ルーブルの使用を優先しています。 使用する`sys.exit(0)`釣銭が提供できない場合は即時終了が可能です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 多数の請求書を 1 回渡すだけで、1 人当たりの作業は一定 |
 | スペース | お(1) | 維持されるカウンターは 2 つだけ |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    bills = list(map(int, input().split()))

    c25 = 0
    c50 = 0

    for bill in bills:
        if bill == 25:
            c25 += 1
        elif bill == 50:
            if c25 == 0:
                return "NO"
            c25 -= 1
            c50 += 1
        else:  # bill == 100
            if c50 >= 1 and c25 >= 1:
                c50 -= 1
                c25 -= 1
            elif c25 >= 3:
                c25 -= 3
            else:
                return "NO"
    return "YES"

# Provided sample
assert run("4\n25 25 50 50\n") == "YES", "sample 1"

# Custom cases
assert run("2\n25 100\n") == "NO", "cannot give change for 100 early"
assert run("5\n25 25 25 50 100\n") == "YES", "enough 25s to cover 100"
assert run("3\n50 25 25\n") == "NO", "50 first, no change"
assert run("6\n25 25 50 50 25 100\n") == "YES", "mixed sequence handled correctly"
assert run("1\n25\n") == "YES", "single person, no change needed"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2\n25 100 | いいえ | 100 ルーブル札の早期お釣りは提供できません |
 | 5\n25 25 25 50 100 | はい | 100 をカバーするには 25 秒で十分 |
 | 3\n50 25 25 | いいえ | 最初は 50、変更はありません |
 | 6\n25 25 50 50 25 100 | はい | 混合シーケンスが正しく処理されました。 
| 1\n25 | はい | 単身者、変更不要 |

 ## 特殊なケース

 入力用`[50, 25]`、アルゴリズムは一人称ではすぐに失敗します。`c25`はゼロなので、正しく「NO」が出力されます。 のために`[25, 25, 50, 100]`、店員は 25 を 1 つ使って 50 の小銭を渡し、次に 100 の小銭を渡します。
