 ## 解決策
 ## 問題の理解

 イゴールさんは、限られた量の絵の具を使って、フェンスにできるだけ多くの絵を描きたいと考えています。 1 から 9 までの各桁には特定のペイント コストがあり、ゼロは使用できません。 入力は利用可能なペイントの合計で構成されます$v$9 つの正の整数の配列$a_1$を通して$a_9$各桁に必要なペイントを示します。 出力は、Igor が塗料の供給で形成できる最大数でなければなりません。 ペイントできる数字がない場合、出力は -1 になります。 

制約によって与えられるのは、$v$まで$10^6$塗装費用は最大で$10^5$。 これは、桁数が数百万ある可能性があり、すべてのサブセットを試すと指数関数的にコストがかかるため、考えられるすべての桁の組み合わせを単純に試すことはできないことを意味します。 私たちは、次の点で線形または線形に近いアプローチを目指す必要があります。$v$。 

明らかではないエッジケースには、最も安い桁が最大ではない状況が含まれます。 たとえば、次の場合$v = 5$そしてコストは$[5, 4, 3, 2, 1, 2, 3, 4, 5]$、各ステップで手頃な最大の桁を選択する素朴な貪欲なアプローチでは、5 を繰り返し選択する可能性があります。 もう 1 つのエッジケースは次のような場合です$v$はどの桁のペイント コストよりも小さく、結果は -1 になります。 

## アプローチ

 ブルートフォース ソリューションでは、すべての数字のシーケンスを試し、ペイント コストを合計し、最大の数値を選択します。 これは概念的には正しいですが、シーケンスの数は次のように指数関数的に増加します。$v$これを最低塗装コストで割ると、数百万ドルに達する場合もあります。 すべての数値を明示的に構築して比較することは、計算上不可能です。 

重要な点は、最初に数値の長さを最大化することによって最大の数値が得られるということです。 残りのペイントを使用して、各位置に可能な最大の数字を保持する必要があります。 これにより、問題は、最初に最も安価な桁を使用してペイントできる最大桁数を計算し、残りのペイントにより安価な桁をより高価な桁で置き換えることができる場合は、左から右に反復的に桁をアップグレードするというものに軽減されます。 このアプローチは、長さが固定されると、より高い桁をより高い位置に配置することで数値が最も大きくなるという事実を利用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(9^(v/min_cost)) | O(v/min_cost) | 遅すぎる |
 | 最適 | O(n * 9) ≈ O(v) | O(v/min_cost) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最も安い桁を特定します。 コストの配列を反復処理し、ペイント コストが最小となる桁を見つけます。 これをそのままにしておきます$d_\text{min}$費用がかかる$c_\text{min}$。 
2. 最も安い桁のみを使用してペイントできる最大桁数を計算します。 もし$v < c_\text{min}$, 数字をペイントできないため、-1 を出力します。 
3. 最大桁数に等しい長さの配列を初期化し、全体を最も安価な桁で埋めます。 減算$c_\text{min} \times \text{length}$から$v$塗料の残りを計算します。 
4. 各桁の位置を左から右に繰り返します。 各位置について、現在の数字を残りのペイントを超えない最大の数字に置き換えてみてください。 具体的には、9 桁目から 9 桁目までを確認します。$d_\text{min}+1$。 置換桁に費用がかかる場合$c$、それを確認してください$v + c_\text{min} \ge c$元の数字のコストがかかるため、$c_\text{min}$すでに費やされています。 可能であれば、交換を実行し、残っている塗料を更新します。 
5. すべての位置を処理した後、結果の数値を文字列として出力します。 

機能する理由: このアルゴリズムは、最初に最大長を保証し、桁数の点で数値を直接最大化します。 残りのペイントを尊重しながら左端の数字を大きな数字に置き換えると、長さを減らすことなく最大値が保証されます。 この不変式は各位置に独立して適用されるため、グローバル数は最大になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

v = int(input())
costs = list(map(int, input().split()))

min_cost = min(costs)
min_digit = costs.index(min_cost) + 1

if v < min_cost:
    print(-1)
    sys.exit()

length = v // min_cost
v -= length * min_cost

number = [min_digit] * length

for i in range(length):
    for d in range(9, min_digit, -1):
        c = costs[d - 1]
        if v + min_cost >= c:
            number[i] = d
            v -= c - min_cost
            break

print(''.join(map(str, number)))
```最初のセクションは入力を読み取り、最も安い桁を決定します。 次に、最大桁数を計算し、残りの塗料が正確に追跡されるようにします。 ネストされたループは、追加コストのみを差し引いて、実行可能な最大の桁から最小の桁に慎重にアップグレードします。 このアルゴリズムは、複数のアップグレードが可能な場合を正しく処理し、左端の桁が最大化されることを保証します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    v = int(input())
    costs = list(map(int, input().split()))
    min_cost = min(costs)
    min_digit = costs.index(min_cost) + 1
    if v < min_cost:
        return "-1"
    length = v // min_cost
    v -= length * min_cost
    number = [min_digit] * length
    for i in range(length):
        for d in range(9, min_digit, -1):
            c = costs[d - 1]
            if v + min_cost >= c:
                number[i] = d
                v -= c - min_cost
                break
    return ''.join(map(str, number))

assert run("5\n5 4 3 2 1 2 3 4 5\n") == "55555", "sample 1"
assert run("10\n1 2 3 4 5 6 7 8 9\n") == "9111111111", "custom 1"
assert run("3\n5 5 5 5 5 5 5 5 5\n") == "-1", "custom 2"
assert run("15\n1 1 1 1 1 1 1 1 1\n") == "999999999999999", "custom 3"
assert run("7\n1 3 3 3 3 3 3 3 3\n") == "7111111", "custom 4"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 5\n5 4 3 2 1 2 3 4 5 | 55555 | アップグレードは不可能、最も安い数字が優勢 |
 | 10\n1 2 3 4 5 6 7 8 9 | 9111111111 | 左端の桁を部分的にアップグレード |
 | 3\n5 5 5 5 5 5 5 5 5 | -1 | どの桁にもペイントが足りません |
 | 15\n1 1 1 1 1 1 1 1 1 | 999999999999999 | すべてのコストは同等、実現可能な最大限のアップグレード |
 | 7\n1 3 3 3 3 3 3 3 | 7111111 | 最初の桁のみをアップグレードし、残りの最小桁をアップグレードします。 

## 特殊なケース

 もし$v$などのどの桁のコストよりも小さい$v=3$すべてのコストが 5 以上の場合、アルゴリズムは直ちに -1 を出力し、不可能性を正しく処理します。 

複数の桁の最小コストが同じ場合、アルゴリズムはその数値を埋めるために最小の数値を選択し、最大コストを保証します。
