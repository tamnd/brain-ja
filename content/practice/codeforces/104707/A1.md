 ## 解決策
 ## 問題の理解

 私たちは毎日タスクを受け取り、それを 2 人のワーカーのうち 1 人に正確に割り当てる必要があります。 Arda にタスクを与えると、価値が得られます`a_i`、そしてそれをビマラに与えると、私たちは得をします`b_i`。 目標は、得られる合計値を最大化しながら、すべてのタスクを割り当てることです。 

各ワーカーがこれまでに受けたタスクの数の差に応じた公平性ルールがあります。 どのような日の接頭辞であっても、Arda と Bimala に割り当てられたタスクの数は 1 を超えてはなりません。`k = 1`。 これは、割り当てを自由に選択できる一方で、中間点で 1 人のワーカーがカウントで大幅に先に進むことを許可しないことを意味します。 

重要な問題は、決定が連続的であり、プレフィックスのバランスによって制約されるため、1 日ごとに欲張って選択するのは危険であるということです。 局所的に最適な割り当ては、割り当ての順序が異なっていれば同じ最終カウントが実現可能だったとしても、制約に違反する将来の不均衡を強制する可能性があります。 

と`n ≤ 1000`、`O(n^3)`あるいは`O(n^2)`解決策は受け入れられます。 割り当てを超える指数関数的なものは不可能です。`2^n`割り当てが大きすぎます。 

1 人のワーカーが初期段階では一貫して優れているにもかかわらず、そのワーカーを繰り返し選択するとすぐにバランスの制約が破られる場合、微妙な失敗ケースが発生します。 たとえば、Arda が常に優れているとしますが、`k = 1`たとえそれが局所的に最適であると思われる場合でも、彼を 2 回続けて割り当てることは無効です。 これにより、純粋な選択ではなく、交互のような動作が強制されます。 

## アプローチ

 ブルートフォース解釈では、すべてのプレフィックスでカウントの差が最大 1 であるという制約の下で、すべての有効な代入シーケンスを探索するものとして問題を扱います。 これは、州を越えた DFS として見ることができます。`(i, diff)`どこ`i`は日のインデックスであり、`diff`Arda と Bimala の間で割り当てられたカウントの現在の差です。 各ステップは、現在のタスクをいずれかのワーカーに割り当てるように分岐します。`diff`内で`[-1, 1]`。 

これは、すべての法的な順序を調査するため、正しいです。 しかし、州の数は急速に増加しています。 それでも`diff`は小さく、各状態は 2 回分岐し、メモ化がなければこれは指数関数的になります。`n`。 メモ化により、動的プログラミングのソリューションが得られます。`O(n * 3)`州、以来`diff`しかありません`-1, 0, 1`。 各トランジションでは、両方の割り当ての選択がチェックされます。 

重要な洞察は、制約が履歴ではなくカウントの違いのみに依存するということです。 わかったら`(i, diff)`、過去は関係ありません。 これにより、指数関数的な検索空間が小さな固定ステート マシンに崩壊され、遷移は差分をインクリメントまたはデクリメントし、対応する報酬を追加することによってのみ決定されます。 

したがって、次のように DP を計算します。`dp[i][d]`最初の処理後に最大の総合品質を保存します`i`差分がエンコードされたタスク`d`、次のようにシフトされました`d ∈ {0,1,2}`実際の差異に対応する`-1,0,1`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DFS | O(2^n) | O(n) | 遅すぎる |
 | 差異状態の DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 あるワーカーが他のワーカーよりもどれだけ多くのタスクを抱えているかを追跡しながら、タスクを 1 つずつ実行するというプロセスをモデル化します。 以来`k = 1`、この違いは常に次のように制限されます。`-1`、`0`、 または`1`。 

1. DP テーブルを定義する`dp[i][d]`どこ`i`は処理したタスクの数です。`d`Arda と Bimala の間の現在の差分をエンコードします。 シフトします`d`+1 することでインデックスは次のようになります`0, 1, 2`。 
2.初期化`dp[0][1] = 0`、処理されたタスクがゼロで、割り当て数が等しいことを表します。 他のすべての状態は不可能として開始されます。 
3. タスクごとに`i`、到達可能なすべての状態からの遷移を考慮します。`dp[i][d]`。 
4. タスクを割り当てる場合`i`Arda に送信すると、差は 1 ずつ増加します。これは、新しい差が次を超えない場合にのみ許可されます。`1`。 DP 用語では、次のようになります。`d`に`d + 1`そして追加します`a_i`合計に。 
5. タスクを割り当てる場合`i`ビマラへの場合、差は 1 減少します。これは、新しい差が以下にならない場合にのみ許可されます。`-1`。 DP 用語では、次のようになります。`d`に`d - 1`そして追加します`b_i`。 
6. すべてのタスクを処理した後、次の値のうちの最大値を取得します。`dp[n][0..2]`。 

これが機能する理由は、すべての有効な割り当てシーケンスがこれらの DP 状態を通る 1 つのパスに正確に対応し、すべての DP 遷移がプレフィックス制約の実現可能性を維持するためです。 すべての有効なパスが暗黙的に列挙され、各パスが 1 回だけスコア付けされるため、最大 DP 値は最適な割り当てと一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = []
    b = []
    for _ in range(n):
        x, y = map(int, input().split())
        a.append(x)
        b.append(y)

    NEG = -10**18
    dp = [[NEG] * 3 for _ in range(n + 1)]
    dp[0][1] = 0

    for i in range(n):
        for d in range(3):
            if dp[i][d] == NEG:
                continue

            cur = dp[i][d]

            if d + 1 < 3:
                dp[i + 1][d + 1] = max(dp[i + 1][d + 1], cur + a[i])

            if d - 1 >= 0:
                dp[i + 1][d - 1] = max(dp[i + 1][d - 1], cur + b[i])

    print(max(dp[n]))

if __name__ == "__main__":
    solve()
```DP 配列のサイズが設定されている`(n+1) × 3`差分状態空間は 3 つの値に固定されているためです。 定数`NEG`は到達不可能な状態を表すため、遷移に影響を与えることはありません。 各タスクは両方の割り当てオプションを独立して処理し、次のレイヤーのみを更新します。 

ここでよくある間違いは、トランジションは前のレイヤーからのみ適用する必要があることを忘れていることです。 インプレースで更新すると、同じステップ内の状態が破損します。 もう 1 つの微妙な点は初期化です。割り当てが行われていないため、最初は平衡状態のみが有効です。 

## 実用的な例

 ### サンプル 1

 入力:```
2 1
2 3
1 1
```私たちは追跡します`dp[i][diff]`差分はどこにありますか`-1, 0, 1`。 

| 私 | 差分 -1 | 差分0 | 差分1 |
 | --- | --- | --- | --- |
 | 0 | -inf | 0 | -inf |
 | 1 | 3 | -inf | 2 |
 | 2 | -inf | 4 | -inf |

 1 日目では、Bimala に代入すると値 3 が与えられ、diff は -1 にシフトし、Arda に代入すると値 2 が与えられ、+1 にシフトします。 2 日目には、各州は反対側のワーカーに割り当てることによってのみバランスを取り戻すことができます。 最終的に最もバランスのとれた割り当てでは、合計 4 が得られます。 

このトレースは、たとえ 1 つのタスクでは Arda の方が優れていたとしても、連続した割り当てがブロックされ、代替が強制されることを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | n ステップのそれぞれは、2 つの遷移を持つ定数 3 状態 DP を処理します。 
| スペース | O(n) | サイズ (n+1) × 3 の DP テーブル |

 線形の複雑さは制約内に快適に収まります。`n ≤ 1000`、さらに大きな制限であっても、定常状態構造により効率が維持されます。

 ## 特殊なケース

 1 つのタスクによる最小限の入力により、初期化の正確さが明らかになります。 入力あり`1 1`と価値観`a=5, b=10`、両方のワーカーがバランスの取れた状態で開始され、選択ごとに 1 つの遷移のみが有効であるため、DP はすぐに Bimala を選択する必要があります。 正しい出力は次のとおりです`10`、複数の開始状態を誤って初期化するソリューションは、過大にカウントされたり、誤って評価されたりする可能性があります。 

1 人のワーカーが両方のタスクを支配する 2 つのタスクのシナリオでは、制約の影響がわかります。 と`a=[10,9]`そして`b=[1,2]`、最適なものが強制的に交互に生成され、`10 + 2 = 12`。 両方を Arda に割り当てる貪欲なアプローチは、不均衡のため 2 番目の割り当てですぐに失敗します。これは、極大値が無効である理由を強調しています。 

すべての値が等しい対称的なケースは、有効な代替パスが最適であることを示しており、DP はすべての等価な状態を偏りなく正しく集約します。
