 ## 解決策
 ## 問題の理解

 各訪問者は、最初の訪問日に時を刻み始める決定的な時計のように動作します。 その瞬間から、彼らは個人的な期間ごとに一定の間隔をあけて、無限の訪問を繰り返します。 訪問者にパラメータがある場合$a_i$そして$b_i$、その後、それらは日に表示されます$a_i, a_i + b_i, a_i + 2b_i, \dots$。 複数の訪問者が同じ日に現れる可能性があり、その場合、訪問者は入力内のインデックスに従って順序付けされます。 

世界的なプロセスは数日ではなく、一連の出来事が統合されたものです。 すべての訪問者からのすべての訪問は、最初に日ごとに並べ替えられ、次に訪問者インデックスごとに並べ替えられた単一のタイムラインに挿入されます。 タスクは、どの訪問者が$k$このマージされたタイムラインの - 番目のイベント。ここで、$k$非常に大きくなる可能性があり、最大で$10^{12}$そのため、訪問を明示的にシミュレートすることはできません。 

この制約により、直接シミュレーションが不可能になります。 各訪問者がわずか数百万の訪問に貢献していると仮定しても、イベントの総数は簡単に超える可能性があります。$10^{12}$、そしてそのシーケンスの一部を生成することすら不可能です。 訪問を 1 つずつ列挙するソリューションは、すぐにタイムアウトになります。 

微妙な難しさは同日の引き分けによるものです。 たとえば、2 人の訪問者が両方とも 6 日目に現れた場合、インデックスが小さい方を最初にカウントする必要があります。 注意深い順序付けを行わずに単純に日ごとに集計すると、その日のうちに不正確なランキングが生成されてしまいます。 

もう 1 つのエッジケースは次のような場合です$k$最初の訪問に比べて非常に小さいです。 もしすべてなら$a_i$規模が大きい場合、最初のいくつかのイベントは 1 人の初期訪問者から繰り返し発生する可能性があるため、「すべての訪問者が最初から均等に貢献する」という誤った仮定は崩れます。 

最後に、大きな期間では寄与がまばらになります。 非常に大きなものを持った訪問者$b_i$妥当な時間の接頭辞の中で 1 回しか出現しない可能性がありますが、それでも重要です。$k$- 番目のイベントの場合$k$大きいです。 これにより、最初の日数のみを考慮する戦略は除外されます。 

## アプローチ

 直接的な総当たりアプローチは、プロセスをイベントごとにシミュレートすることです。 各ステップで、すべての訪問者の次回の訪問を計算し、最小日を選択し (インデックスによって関係を破る)、その訪問者を出力し、次の訪問を進めます。 これは、各訪問者の次回訪問時間を保存する優先キューを使用して実装できます。 

このアプローチは、イベントの順序付け定義を正確に反映しているため、正しいです。 ただし、訪問ごとにヒープ操作が実行され、最悪の場合、$k$- 番目のイベントは$10^{12}$、それは完全に実行不可能になります。 均一に生成$10^8$イベントはすでに遅すぎるため、訪問を明示的にステップスルーすることは避けなければなりません。 

重要な点は、実際には訪問を順番に生成する必要はないということです。 代わりに、指定された時間内で、計数の質問に答えるだけで済みます。$T$、今日までに発生した訪問数$T$? これにより、問題はシーケンス生成からプレフィックスカウントの問題に変換されます。 このカウントを効率的に計算できれば、時間通りに二分探索を行って、少なくとも次の場所で最も早い日を見つけることができます。$k$訪問が行われました。 

1日1回修正したら$T$、各訪問者は予測可能な訪問数に貢献します。$T < a_i$、何も貢献しません、そうでない場合は貢献します$\left\lfloor \frac{T - a_i}{b_i} \right\rfloor + 1$。 すべての訪問者を合計すると、合計訪問数は次のようになります。$T$。 

正しい日を見つけた後$T$、最後のステップは、どの訪問者が$k$その日のうちの - 番目のイベント。 訪問数を厳密に減算します。$T$、次に訪問者を順番にスキャンし、当日の訪問のみをシミュレートします。$T$、その日にヒットするアクティブな等差数列の数によって制限されるため、これは小さくなります。 

これにより、不可能なイベントのシミュレーションが、時間の経過に伴う対数検索とチェックごとの線形パスに変換されます。

 ## アルゴリズムのチュートリアル

 1. 指定された日までに発生した合計訪問数をカウントする関数を定義します。$T$。 訪問者ごとに、その等差数列の項がいくつあるかを計算します。$[a_i, T]$。 これにより、シミュレーションではなく直接式に基づいたカウントが得られます。 
2. 当日二分探索を行います$T$。 目標は、その日までの訪問数が少なくとも 1 になるような最小の日を見つけることです。$k$。 これが機能するのは、プレフィックス数が時間の経過とともに単調増加するためです。$T$訪問数が削除されることはなく、追加されるだけです。 
3. 二分探索の各中間点は、カウント関数を使用して評価されます。 カウントが未満の場合$k$、検索を右に移動します。 それ以外の場合は左に移動します。 これにより、累積訪問数が到達またはそれを超えた最初の日が特定されます。$k$。 
4. 対象日を特定したら$T$、厳密に以前に発生した訪問数を計算します。$T$。 これによりオフセットが得られます$k'$、その日の訪問を示します。$T$見つける必要があります。 
5. すべての訪問者を反復処理し、その日に訪問した人を収集します$T$。 訪問者は一日に貢献します$T$もし$T \ge a_i$そして$(T - a_i) \bmod b_i = 0$。 それらのインデックスを昇順に追加します。これにより、当然のことながら、タイブレーク ルールが尊重されます。 
6. を選択します。$k'$このリストの - 番目の訪問者とそのインデックスを出力します。 

正確かどうかは、グローバルな順序付けが日ごとに辞書順に行われ、次に索引ごとに行われるという事実にかかっています。 最初にプレフィックス数によって正しい日を特定することで、問題を 1 日内の選択に軽減し、順序付けが簡単になります。 

### なぜ効果があるのか

 このアルゴリズムは、すべての訪問を数日に分けて管理します。 二分検索により、累積訪問数が交差する一意の日が特定されます。$k$。 訪問は厳密に日順に順序付けされるため、前の日のすべての訪問が完了するまでは、後の日からの訪問は行われません。 固定日内では、インデックスによる順序付けは定義に直接一致します。 プレフィックス カウント関数は、暗黙的にマージされたシーケンス内のイベントの総数と正確に一致するため、バイナリ検索はイベントを見逃したり二重にカウントしたりすることなく正しい境界に収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = []
    b = []
    max_a = 0
    for _ in range(n):
        ai, bi = map(int, input().split())
        a.append(ai)
        b.append(bi)
        if ai > max_a:
            max_a = ai

    def count_upto(t):
        total = 0
        for i in range(n):
            if t >= a[i]:
                total += (t - a[i]) // b[i] + 1
                if total >= k:
                    return total
        return total

    lo, hi = 1, max_a + k  # safe upper bound
    while lo < hi:
        mid = (lo + hi) // 2
        if count_upto(mid) < k:
            lo = mid + 1
        else:
            hi = mid

    day = lo

    before = 0
    for i in range(n):
        if day >= a[i]:
            cnt = (day - a[i]) // b[i] + 1
            before += cnt

    before -= sum(1 for i in range(n) if day == a[i] + ((day - a[i]) // b[i]) * b[i])

    remaining = k - (before)

    cur = []
    for i in range(n):
        if day >= a[i] and (day - a[i]) % b[i] == 0:
            cur.append(i + 1)

    cur.sort()
    print(cur[remaining - 1])

if __name__ == "__main__":
    solve()
```実装の中核は、各訪問者を閉形式の等差数列カウントに変換するプレフィックス カウント関数です。 二分探索はこの単調関数に基づいて、その場所が存在する正確な日を特定します。$k$- 番目のイベントが発生します。 最後の選択ステップでは、その日にアクティブな訪問者のみが考慮され、タイブレークを満たすためにインデックスによる並べ替えに依存します。 

唯一の微妙な部分は、バイナリ検索範囲が十分に大きいことを確認することです。 使用する$max(a_i) + k$来場者全員が遅れてスタートしても進行するので安心です$k$最大開始日を超えた日数では、十分な累積訪問数が保証されます。

 ## 特殊なケース

 重要なエッジ ケースは、複数の訪問者が二分探索で選択された同じ境界日に到達したときに発生します。 このアルゴリズムは、その日にアクティブだったすべての訪問者を正確に分離し、インデックス順に並べ替えることでこの問題を解決します。 例えば：```
3 4
1 2
1 2
1 2
```すべての訪問者は、1 日目、3 日目、5 日目などに訪問を行います。 4 番目の訪問は 3 日目に到着します。3 日目には 3 人の訪問者全員が現れ、インデックスで選択すると訪問者 1、次に訪問者 2、その後 3 が得られるため、4 番目のイベントの正解は 3 です。 日レベルの分離により貢献者の完全なセットが保存されるため、アルゴリズムはこれを正しく再構築します。 

もう 1 つのエッジ ケースは、1 人の訪問者の期間が非常に長く、二分探索範囲内で 1 回だけ貢献する場合です。 それでも、カウント機能には、該当する場合はそれらが 1 回だけ含まれるため、まばらなタイムラインで失われることはありません。
