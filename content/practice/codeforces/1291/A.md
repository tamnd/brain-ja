 ## 解決策
 ## 問題の理解

 数字列が与えられ、残りの数字を同じ相対順序に保ちながら、その数字の一部を削除することができます。 目標は、2 つの条件を同時に満たす数値を表す空ではない部分列を形成することです。つまり、その桁の合計が偶数で、数値の最後の桁が奇数である、つまり数値自体が 2 で割り切れないことを意味します。 

演算空間は純粋に部分列であるため、入力の構造は固定順序であり、オプションで削除が行われます。 数字の順序を変更したり、新しい数字を導入したりすることはできないため、唯一の柔軟性はインデックスのサブセットを選択することになります。 

テスト ケース全体にわたる全長の制約は十分に小さいため、テスト ケースごとに線形または線形に近い貪欲な戦略で十分です。 テスト ケースごとに 2 次の解は最悪の場合でもすでに許容可能ですが、サブシーケンスにわたる指数関数的なものは不可能です。n が 3000 までの場合、2^n として爆発するためです。 

文字列に奇数桁がまったく含まれていない場合、微妙なエッジケースが発生します。 この場合、すべてのサブシーケンスは偶数の数字で終わるため、数値は常に偶数となり、数値自体が奇数でなければならないという要件に違反します。 別の失敗例は、奇数の最後の桁を選択したものの、最後の桁を失わずに桁の合計のパリティを調整できない場合に発生します。この場合、すべての桁を単純に貪欲に選択するのではなく、慎重に選択する必要があります。 

## アプローチ

 ブルートフォース手法では、すべての部分列を試し、それらの桁の合計を計算し、結果の数値が奇数桁で終わるかどうかを確認します。 これは概念的に機能します。有効な答えはすべて部分列であるため、存在する場合は徹底的な検索で確実に見つかります。 ただし、部分列の数は指数関数的に増加し、具体的には 2^n となり、n が 3000 までになると、これは完全に不可能になります。 

重要な点は、この条件が 2 つのプロパティ (桁の合計のパリティと最後の桁のパリティ) のみに依存していることです。 数値自体や辞書編集上の最適性は気にしません。 これは、選択したすべての数字の合計が偶数であることを確認しながら、奇数の数字で終わるサブシーケンスを構築するだけでよいことを意味します。 

これは、最初に最後の桁を修正することを即座に示唆します。 数値は奇数である必要があるため、最後に選択する数字は {1、3、5、7、9} のいずれかでなければなりません。 最後の桁が決まったら、合計パリティを均等にするために前のどの桁を含めるかを決定するだけで済みます。 これにより、問題はパリティ制約のあるサブセットの選択に軽減され、パリティ条件が満たされるまで桁を累積することで常に貪欲に処理できます。 

右から逆に作業して、考えられる奇数末尾の候補を試し、その前に有用な数字をできるだけ多く取得すると、構造は単純になります。

 ## アルゴリズムのチュートリアル

 有効な最後の数字を選択し、その前にプレフィックスを構築することで答えを構築します。

1. 文字列を右から左にスキャンして、数字が奇数であるすべての位置を見つけます。 このような各位置は、答えの最後の桁の候補になります。 最終的な数値は奇数でなければならないため、それらを考慮する必要があります。 
2. 候補の最後の位置ごとに、その左側の数字から有効なプレフィックスを構築しようとします。 選択した桁の累計のパリティを維持します。 目標は、最後の桁を含む選択した桁の合計を均等にすることです。 
3. 文字列の先頭から選択した最後の数字の直前までを繰り返します。 貪欲に数字を含めますが、パリティを制御することだけに興味があります。 2 を法とする合計を追跡します。 
4. 前の数字をすべて処理した後、最後の数字を加算すると合計が偶数になるかどうかを確認します。 そうでない場合は、パリティを反転する 1 つ前の桁を削除することで調整を試みます。 数字を削除すると、その値のモジュロ 2 によってパリティが変更されるため、必要に応じて除外できる奇数の数字がプレフィックスに少なくとも 1 つ存在することを確認するだけで済みます。 
5. 有効な構成が見つかった場合は、構築されたサブシーケンスを直ちに出力します。 奇数末尾の選択が機能しない場合は、-1 を出力します。 

これが機能する理由は、唯一のグローバル制約が合計のパリティと最後の桁の制約であるためです。 最後の桁が固定されると、残りのすべての桁はそのパリティによってのみ寄与するため、それらを含めるかどうか以外に、正確な値や位置について考える必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    odd_positions = [i for i, ch in enumerate(s) if (ord(ch) - 48) % 2 == 1]

    if not odd_positions:
        print(-1)
        return

    for last in reversed(odd_positions):
        total = 0
        prefix_digits = []

        for i in range(last):
            d = ord(s[i]) - 48
            total += d
            prefix_digits.append(s[i])

        last_digit = ord(s[last]) - 48
        total += last_digit

        if total % 2 == 0:
            ans = ''.join(prefix_digits) + s[last]
            if ans and ans[0] != '0':
                print(ans)
                return
        else:
            found = False
            for i in range(last - 1, -1, -1):
                if (ord(s[i]) - 48) % 2 == 1:
                    adjusted = prefix_digits[:i] + prefix_digits[i+1:] + [s[last]]
                    print(''.join(adjusted))
                    found = True
                    break
            if found:
                return

    print(-1)

if __name__ == "__main__":
    solve()
```最後の桁は奇数である必要があるため、コードは最初に考えられるすべての奇数終了位置を収集します。 各候補について、プレフィックスの合計を計算し、パリティ条件がすでに満たされているかどうかを確認します。 存在する場合は、直接出力します。 それ以外の場合は、プレフィックスから奇数桁を削除することで小さな修正を試行し、パリティを反転して状態を修正します。 

微妙な実装の詳細は、最終的な答えを出力するときを除いて、探索中に完全なサブシーケンスを構築しないことです。 これにより、文字列連結を繰り返す際の 2 次オーバーヘッドが回避されます。 もう 1 つの重要な点は、候補を右から左に繰り返すことです。これは、後の位置ほどプレフィックスの柔軟性が維持される傾向があるためです。

 ## 特殊なケース

 重要なエッジケースは、文字列に偶数桁しか含まれていない場合です。 のような入力の場合`2468`の場合、有効な最後の桁の選択肢がないため、アルゴリズムは構築を試行せずにすぐに -1 を返します。 

もう 1 つのケースは、奇数桁が最後にある場合です。 この状況では、パリティのみを満たすようにプレフィックスを選択する必要があります。 このアルゴリズムは、最後の桁を考慮し、空または完全なプレフィックスに対してプレフィックスの合計を計算し、実現可能性を正しく評価するため、これを処理します。 

3 番目のケースは、複数の奇数桁が存在するが、パリティ アラインメントが許可されるのは 1 桁だけである場合です。 候補に対する逆反復により、すべての可能性が確実に試行され、グローバル最適化を必要とせずに最初に成功した構築が返されます。
