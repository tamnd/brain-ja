 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられます。 負でない限り、任意の要素を繰り返し 1 減らすことができます。 目標は、最初にあるピーク位置まで厳密に増加し、その後厳密に減少する形状に配列を変換できるかどうかを決定することです。 

重要な点は、要素を再配置しないということです。 値を減らすだけです。 したがって、各位置には初期値によって与えられる上限がありますが、0 からその上限までの任意の最終値を選択できます。 

私たちは、厳密な「山」シーケンスを形成する最終値の選択が存在するかどうかを知りたいと考えています。 

制約は大きく、すべてのテスト ケースの合計の長さは最大 3·10^5 です。 考えられるすべてのピーク位置をテストし、調整を単純にシミュレートしようとするソリューションは、テスト ケースごとに O(n^2) でも遅すぎるため、失敗します。 

厳密さを正しく強制せずに貪欲に考えると、微妙な問題が発生します。 たとえば、配列がすでに非増加または非減少である場合、それは自動的に有効になりますが、次のような中間の形状は`[2, 1, 2]`中間要素は厳密なピークになることができず、単調構造を維持できないため、修正できません。 

もう 1 つの注意が必要な状況は、値が等しい場合です。 厳密な不等式が必要なため、隣接する値が等しいと少なくとも一方の側を強制的に減らすことになり、それがカスケードして実現可能性を破壊する可能性があります。 

## アプローチ

 強引なアイデアは、考えられるすべてのピーク インデックスを試すことです`k`。 選択ごとに、元の値を決して超えないように、左から厳密に増加するシーケンスと右から厳密に減少するシーケンスを構築しようとします。 

固定ピークの場合、元の配列以下に留まりながら、厳密性を満たす可能な限り最小の値を貪欲に割り当てることができます。 たとえば、左から次のように強制できます。`b[i] = min(a[i], b[i-1] + 1)`増加する場合、同様に右から。 これが機能するのは、制約を尊重しながら常に値をできるだけ大きく保ちたいためです。 

ただし、この構築を毎回繰り返すと、`k`最悪の場合、テスト ケースあたり O(n^2) になります。 合計要素が 3·10^5 であるため、これでは遅すぎます。 

重要な観察は、実現可能性は単一の「可能な限り最良のピーク」建設が世界的に存在するかどうかに依存するということです。 ピークを明示的に選択する代わりに、厳密に増加する達成可能な最大のプレフィックスと厳密に減少する達成可能な最大のサフィックスの 2 つの配列を計算できます。 次に、左からの増加建設と右からの減少建設が矛盾なく満たすことができる指標があるかどうかを確認します。 

これにより、問題は 2 つのリニア スキャンに減ります。

 ## アルゴリズムのチュートリアル

 2 つのヘルパー配列を構築します。 1 つは左から構築できる最適な厳密に増加するシーケンスをシミュレートし、もう 1 つは右から最適な厳密に減少するシーケンスをシミュレートします。 

### 段階的なプロセス

 1. アレイを構築する`inc`どこ`inc[i]`位置に割り当てることができる最大値です`i`シーケンスは厳密に左から右に増加し、それを超えることはありません`a[i]`。 設定しました`inc[0] = a[0]`、それぞれについて`i > 0`、計算します`inc[i] = min(a[i], inc[i-1] + 1)`。 これにより、価値の無駄を最小限に抑えながら、厳密な増加を維持することが保証されます。 
2. アレイを構築する`dec`どこ`dec[i]`位置に割り当てることができる最大値です`i`シーケンスを右から左に厳密に減少させながら。 設定しました`dec[n-1] = a[n-1]`、それぞれについて`i < n-1`、計算します`dec[i] = min(a[i], dec[i+1] + 1)`。 
3. ポジションごとに`k`、それが頂点として機能するかどうかをテストします。 有効なピークの場合、増加部分は次の位置で終了する必要があります。`k`減少部分は次から開始する必要があります`k`。 だから必要なのです`inc[k] > 0`互換性と`inc[k]`一貫した方法で、その周囲の両側よりも厳密に大きくなければなりません。 クリーンな状態が存在するかどうかを確認することになります`k`そのような`inc[k]`と互換性があります`dec[k]`ピークとして扱われる場合 (どちらの構造も同じ値を実現できます)`k`）。 
4. 少なくとも 1 つのインデックスが存在するかどうかを確認します`k`そのような`inc[k] == dec[k]`。 そのような位置が存在する場合、両方の構造を整列させて有効な山を形成することができます。 
5. そのようなインデックスが存在しない場合、答えは「いいえ」、それ以外の場合は「はい」です。 

### なぜ効果があるのか

 の建設`inc`そして`dec`単調な制約の下で各インデックスで実現可能な最大の高さを取得します。 有効なシャープ化された配列は、点的に両方の構造の下に存在する必要があります。 両方の構造が一致する点を見つけることができれば、その点は、厳密さに違反することなく左右の制約が一致する一貫したピークとして機能することができます。 両方の配列はそれぞれの制約の下で貪欲な最大値であるため、有効な解はこのアライメントを通じて表現可能であり、完全性が保証されている必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        if n == 1:
            print("Yes")
            continue

        inc = [0] * n
        dec = [0] * n

        inc[0] = a[0]
        for i in range(1, n):
            inc[i] = min(a[i], inc[i-1] + 1)

        dec[n-1] = a[n-1]
        for i in range(n-2, -1, -1):
            dec[i] = min(a[i], dec[i+1] + 1)

        ok = False
        for i in range(n):
            if inc[i] == dec[i]:
                ok = True
                break

        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```の`inc`配列は、制約を超えることなく、可能な限り厳密に増加するプレフィックスを強制します。 の`dec`array はサフィックスに対しても同じことを行います。 最終スキャンでは、両方の構造が交わる場所に一貫したピーク高さが存在するかどうかを確認します。 

実装によくある落とし穴は、双方が厳密性を尊重する必要があることを忘れていることです。 の`+1`遷移は、厳密な増加または減少を暗黙的に強制するものです。

 ## 特殊なケース

 厳密な不等式は必要ないため、単一要素の配列は常に定義を満たします。 アルゴリズムはこれを明示的に処理します。 

次のような値が繰り返される配列`[1, 1, 1]`厳密な単調セグメントを形成しようとすると少なくとも 1 つの縮小が強制され、ピークに必要な対称性が崩れるため、失敗します。 

厳密に単調な配列は常に受け入れられます。`inc`または`dec`元の配列と同一になり、構造全体での完全な一致が保証されます。
