 ## 解決策
 ## 問題の理解

 各カフェが正確に 1 つの整数の「コーヒー品種」を生産する、カフェ タイプの隠されたシーケンスが与えられています。 順序自体はわかりませんが、カフェを 1 つずつ調査することはできます。 

インタラクション ツールは、スライディング ウィンドウのメモリ システムのように動作します。 カフェにクエリを実行するたびに、システムはそのカフェの種類が最新のカフェの中に登場したかどうかを教えてくれます。`k`隠れた記憶のキューの中でコーヒーを味わった。 回答後、カフェの種類がメモリに追加され、メモリがサイズを超えた場合`k`、最も古い要素が削除されます。 場合によっては、この記憶を完全にリセットすることができます。 

タスクは配列を再構築することではなく、非表示の配列にいくつの個別の値が現れるかを判断することだけです。 

主な問題は、クエリが独立していないことです。 クエリごとにメモリの状態が変化するため、同じカフェについて異なる時間に 2 回質問すると、異なる答えが得られる可能性があります。 これにより、対話は静的ではなく基本的にステートフルになります。 

という点では制約は小さい`n`(最大 1024) ですが、インタラクションの制限は入力サイズに関するものではなく、クエリ バジェットとメモリのリセットに関するものです。 については許可されています`2n^2 / k`テイストクエリと最大30000のリセット。 以来`n`が小さい場合、二次戦略は受け入れられますが、メモリ干渉を注意深く制御する場合に限ります。 スライディング ウィンドウを管理せずに等価関係をグローバルに推定しようとするソリューションは、答えが履歴に依存するため機能しません。 

微妙なエッジ ケースは、適応動作から発生します。つまり、非表示の配列は事前に修正されません。 つまり、推論は固定されたグラウンドトゥルースではなく、応答との一貫性のみに基づいていなければなりません。 メモリを制御せずに繰り返されるクエリに対して安定した応答を想定する戦略は、何も言わずに失敗します。 

もう 1 つの失敗モードは、「YES」は最後のメンバーシップを意味するだけであることを忘れていることです。`k`純粋な意味での等価検出ではなく、メモリ内の個別の観測値です。 リセットを行わないと、構造が繰り返されるため、クエリ間でリークする誤検出が発生します。 

## アプローチ

 単純なアイデアは、カフェのすべてのペアを比較することで、すべての個別の値を識別しようとすることです。クエリ カフェ`i`、その後カフェ`j`を選択し、「YES」の繰り返しから同じ品種かどうかを推測します。 メモリの汚染によりクロストークが発生するため、これはすぐに失敗します。「はい」は、最近メモリに挿入された 3 番目のカフェから返される可能性があります。`i`そして`j`マッチ。 

頻繁にリセットしようとしても、ブルートペアワイズ比較アプローチでは次のことが必要になります。`O(n^2)`比較サイクルごとにクエリが実行されるため、比較間のメモリ状態を完全に制御しない限り、各比較の信頼性は低くなります。 適応的な動作では、隔離を強制しない限り、サイクル全体で安定性を保証することもできません。 

重要な観察は、実際にはアイデンティティを直接比較する必要がないということです。 管理された「最近のセット」に含まれることが現在知られていない値に遭遇した回数を数えるだけで済みます。 解釈するすべてのクエリがリセット後に作成されたことを確認すると、白紙の状態に制御されたシーケンスを加えた場合、それぞれの「YES」または「NO」が意味を持つものになります。 

これは、新しいメモリ ウィンドウを繰り返し再構築し、それをフィルターとして使用する戦略につながります。リセットするたびに、クエリの新しいブロックが開始され、そのブロック内で応答を既知の制限された履歴との比較として安全に扱うことができます。 現在のフェーズで明示的に挿入したもののみがメモリに含まれるようにクエリを慎重に構造化することで、「YES」がこのフェーズですでに観察されたものと等しいことを意味することを保証できます。 

次に、一種の増分個別カウントをシミュレートし、発見された品種の代表者のリストを維持します。 各カフェ インデックスについて、制御されたリセットの下で、すでに検出された代表と一致するかどうかをテストします。 いずれにも一致しない場合は、新しい品種が導入されます。 

なぜなら`n ≤ 1024`、各比較はメモリ サイズによって制限されます`k`、クエリの合計の複雑さは以下の範囲内に収まります。`O(n^2 / k)`に合わせたブロックで構成された場合の予算`k`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ペアごとの非制御比較 | O(n²) クエリ (インタラクション ノイズのため無効) | お(1) | 間違った答え |
 | 制御されたリセット + ブロックベースの分類 | O(n² / k) クエリ | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のリストから始める`rep`発見されたコーヒー品種ごとに 1 つのインデックスを保存します。 その考えは、各代表者がこれまでに確認した異なるクラスを代表しているということです。 
2. すべてのカフェを反復処理します。`1`に`n`。 
3. カフェを試す前に`i`、リセットを発行します`R`。 これによりメモリがクリアされ、以前のインタラクションが次の分類に影響を与えることができなくなります。 そうしないと、現在の比較セットではなく古いエントリから「YES」が返される可能性があるため、これが必要です。 
4. 各代表者ごとに`r`すでに入っている`rep`、クエリカフェ`r`、次にクエリカフェ`i`、この管理された環境で。 メモリは空から始まるため、「YES」はこのフェーズで明示的に作成したシーケンスから得られる必要があります。 両方が同じ制御ウィンドウ内で一貫して動作する場合、次のことを検出できます。`i`既存のクラスと一致します。 
5.カフェなら`i`代表的なものと一致しますが、新しい品種ではないため省略します。 
6.カフェなら`i`どの代表とも一致しない場合は追加します`i`に`rep`、新しく発見された品種をマークします。 
7. すべてのカフェを処理した後、答えは単にカフェのサイズになります。`rep`。 

### なぜ効果があるのか

 核となる不変条件は、すべての代表者が`rep`は個別の基礎となる値に対応し、新しいカフェは、リセット分離された比較セッションで以前の代表値と一致しない場合にのみ追加されます。 すべての比較セッションは空のメモリから開始されるため、「YES」の唯一の原因は、同じセッションの前に明示的に挿入された値と等しいことです。 これにより、スライディング ウィンドウからの干渉が除去され、等価性検出の一貫性が保証されます。 その結果、それぞれの異なる品種が 1 回だけ発見され、フェーズをまたいで偽陽性が持続することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    rep = []

    for i in range(1, n + 1):
        sys.stdout.write("R\n")
        sys.stdout.flush()

        found = False

        for r in rep:
            sys.stdout.write(f"? {r}\n")
            sys.stdout.flush()
            _ = input().strip()

            sys.stdout.write(f"? {i}\n")
            sys.stdout.flush()
            ans = input().strip()

            if ans == "Y":
                found = True
                break

        if not found:
            rep.append(i)

    sys.stdout.write(f"! {len(rep)}\n")
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```この実装では、代表的なリストが維持され、新しい候補カフェが作成される前にリセットが使用されます。 各候補者は、ペアのクエリを使用してすべての既知の代表者に対してテストされます。 ペア構造は、「はい」が残留履歴ではなく制御された記憶状態から確実に生じるため、重要です。 

リセットは、単純な解釈の正しさのために厳密に必要ではない場合でも発行されますが、これにより各比較フェーズの分離が保証されます。これは、適応動作を備えた対話型環境では不可欠です。

 ## 特殊なケース

 のために`n = 1`、アルゴリズムはただちに唯一のカフェを`rep`、答えを生み出す`1`。 比較は行われず、リセットは正確さに影響しません。 

すべての値が同一である配列の場合、すべてのカフェが分離された比較で最初の代表と照合されるため、最初のステップの後に新しいエントリは追加されず、出力はそのまま残ります。`1`。 

完全に別個の配列の場合、各カフェは以前の代表と一致しないため、代表リストのサイズが大きくなります`n`。 リセットにより、偶発的な相互汚染によって誤った一致が引き起こされることがなくなり、適応応答下でも正確さが維持されます。
