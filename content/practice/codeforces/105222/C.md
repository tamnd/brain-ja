 ## 解決策
 ## 問題の理解

 座標を持つセルの 3D グリッドが与えられます。$(i, j, k)$。 各セルには最初は黒または白の色があり、指定されたコストでその色を反転することができます。 目標は、2 種類の要件を満たしながら、総反転コストを最小限に抑える最終的なカラーリングを選択することです。 

まず、要件によって 2 つの特定の境界セルが固定されます。$(1,1,1)$最終的には黒になる必要があり、セルは$(N,M,L)$最終的には白くなるはずです。 

第 2 に、個別のセルのすべてのペアに対してグローバルな一貫性ルールが存在します。 任意の 2 つのセルについて、少なくとも 1 つの座標において最初のセルが 2 番目のセルよりも厳密に大きいか、最初のセルが黒であるか、2 番目のセルが白であるかの少なくとも 1 つが真である必要があります。 このルールは見た目は非対称ですが、すべての順序付きペアに適用されるため、暗黙的に両方向が適用されます。 

この制約の重要な効果は、禁止パターンの観点から書き直すとより明確になります。 2つの細胞を取ると$A$そして$B$と仮定します$A$黒ですが$B$が白の場合、座標条件により次のことを防ぐ必要があります。$A$座標的に以下になることはありません$B$。 言い換えれば、3 次元すべてにおいて同時に黒いセルが白いセルの「下と後ろ」にあることは許可されていません。 これは、単調な構造を明らかにします。つまり、座標によって定義される自然な部分順序で、黒セルが白セルの下に位置してはなりません。 

各次元は大きくなる可能性がありますが、グリッド サイズは合計で小さく、全体で最大 5000 個のセルです。 これにより、レイヤーごとまたは軸ごとの高密度処理に依存するソリューションは即座に排除されます。 セル上の二次解は依然として実行可能です。$5000^2 = 25 \times 10^6$特に各インタラクションが単純な場合、最適化されたコードで管理可能です。 

すべてのセルが最初から同じ色である場合、微妙なエッジ ケースが表示されます。 たとえば、すべてが白の場合、少なくとも反転する必要があります。$(1,1,1)$これにより、単調構造を通じて制約が伝播される可能性があります。 同様に、すべてが黒の場合、$(N,M,L)$は白になる必要があり、これにより再び制約が逆方向に伝播されます。 これらのケースが問題になるのは、構造がローカルではなく、単一の強制割り当てがすべての同等のノードに影響を与えるためです。 

## アプローチ

 直接的なアプローチは、考えられる最終的なカラーリングをすべて試してみることです。 5000 個のセルがあるため、これは次のようになります。$2^{5000}$完全に不可能な構成です。 

もう少し構造化されたアイデアは、これを半順序に対する制約システムとして見ることです。 各セルは、その座標を支配する他のすべてのセルと相互作用します。 この制約は基本的に、3 つの座標すべてにおいて黒のセルが白のセルの下にある「悪い反転」を禁止します。 これは、ポセットに対する単調なラベル付け問題の特徴です。 

重要な洞察は、色をバイナリ値として再解釈し、ルールを単調性条件として再解釈することです。 黒を 0、白を 1 としてエンコードすると、禁止パターンは次のようになります。下位の要素が 0 に等しく、上位の要素が 1 であることは決してあってはならない。これはまさに、座標比較によって引き起こされる半順序にわたる単調非減少関数の定義です。 

したがって、問題は次のようになります。$u \le v$座標的には、$color(u) \le color(v)$、割り当てコストを最小限に抑えながら。 これは古典的な最小カットの定式化です。各ノードには 0 または 1 のコストがあり、単調制約は無限容量の有向エッジになります。 

問題をグラフ内の最小の s-t カットに縮小します。 各セルはノードです。 比較可能なすべてのペアを接続します$u \le v$有向エッジ付き$u \to v$、強制的に割り当てることができません$u = 1$そして$v = 0$。 コスト構造は、初期構成からの反転コストに基づいて、各ノードで黒を好むか白を好むかをエンコードします。 

ブルートフォースアプローチは推移的構造を無視するため失敗しますが、フロー定式化ではすべてのペアごとの制約が単一のグローバル最適化問題に圧縮されます。

 ## アルゴリズムのチュートリアル

 各グリッド セルを有向グラフのノードとして扱い、座標方向の優位性によって定義される半順序全体にわたって単調性を強制する最小カットを計算します。 

1. 各セルをマッピングする$(i,j,k)$一意のノードインデックスに設定します。 これにより、順序情報を失うことなく 3D 構造を平面グラフとして扱うことができます。 
2. 最終的な色のバイナリ エンコーディングを決定します。黒は 0、白は 1 です。この選択は、次の必要な境界条件と一致します。$(1,1,1)$黒くて、$(N,M,L)$白いです。 
3. 各ノードについて、黒であるコストと白であるコストを計算します。 初期色がターゲットと一致する場合、コストは 0 ですが、そうでない場合は反転コストとなります。 これにより、各ノードが重み付けされた決定変数に変わります。 
4. 個別のノードのペアごとに$u, v$、 もし$u \le v$3 つの座標すべてに有向エッジを追加します$u \to v$無限の容量を備えています。 これにより、割り当てができなくなります$u = 1$（白）ながら$v = 0$(黒)、単調性に違反します。 
5. 各ノードにソースとシンクの構造を追加します。ソースからのエッジは黒を割り当てるコストをエンコードし、シンクへのエッジは白を割り当てるコストをエンコードします。 これにより、ノードの重みがフロー コストに変換されます。 
6. 標準の最大流量アルゴリズムを実行して、最小 s-t カットを計算します。 このカットでは、すべての無限容量制約を尊重しながら、ノードを白と黒のセットに分割します。 
7. 最終的な割り当てをカット側から読み取り、総コストを計算します。 

### なぜ効果があるのか

 セルのペアに対する制約は、座標方向の比較によって定義される半順序に対する正確な単調性条件です。 すべての違反はペアに対応します$u \le v$割り当て付き$u = 1$そして$v = 0$これはまさに、カット表現において無限容量エッジが防止するものです。 

すべての有効なカラーリングは、すべてのエッジを尊重するカットに対応し、そのようなすべてのカットは有効なカラーリングに対応します。 カット キャパシティは、選択した割り当ての合計フリッピング コストと等しくなります。 これにより、実現可能なソリューションとカットの間に 1 対 1 のマッピングが作成され、最小カットによって最適なソリューションが選択されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

class Dinic:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.adj[u].append([v, c, len(self.adj[v])])
        self.adj[v].append([u, 0, len(self.adj[u]) - 1])

    def bfs(self, s, t, level):
        from collections import deque
        q = deque([s])
        level[s] = 0
        while q:
            u = q.popleft()
            for v, c, _ in self.adj[u]:
                if c > 0 and level[v] < 0:
                    level[v] = level[u] + 1
                    q.append(v)
        return level[t] != -1

    def dfs(self, u, t, f, level, it):
        if u == t:
            return f
        for i in range(it[u], len(self.adj[u])):
            it[u] = i
            v, c, rev = self.adj[u][i]
            if c > 0 and level[v] == level[u] + 1:
                ret = self.dfs(v, t, min(f, c), level, it)
                if ret:
                    self.adj[u][i][1] -= ret
                    self.adj[v][rev][1] += ret
                    return ret
        return 0

    def max_flow(self, s, t):
        flow = 0
        while True:
            level = [-1] * self.n
            if not self.bfs(s, t, level):
                break
            it = [0] * self.n
            while True:
                f = self.dfs(s, t, INF, level, it)
                if not f:
                    break
                flow += f
        return flow

def solve():
    N, M, L = map(int, input().split())
    n = N * M * L

    color = []
    for _ in range(L * N):
        color.append(input().strip())

    cost = []
    for _ in range(L * N):
        cost.append(list(map(int, input().split())))

    def idx(i, j, k):
        return (k - 1) * (N * M) + (i - 1) * M + (j - 1)

    S = n
    T = n + 1
    dinic = Dinic(n + 2)

    def add_cost(u, black_cost, white_cost):
        dinic.add_edge(S, u, black_cost)
        dinic.add_edge(u, T, white_cost)

    for k in range(1, L + 1):
        for i in range(1, N + 1):
            row_c = color[(k - 1) * N + (i - 1)]
            row_w = cost[(k - 1) * N + (i - 1)]
            for j in range(1, M + 1):
                u = idx(i, j, k)

                is_black = (row_c[j - 1] == 'B')
                if is_black:
                    black_cost = 0
                    white_cost = row_w[j - 1]
                else:
                    black_cost = row_w[j - 1]
                    white_cost = 0

                add_cost(u, black_cost, white_cost)

    nodes = [(i, j, k) for k in range(1, L + 1)
                        for i in range(1, N + 1)
                        for j in range(1, M + 1)]

    def id_of(p):
        i, j, k = p
        return idx(i, j, k)

    for a in nodes:
        ia, ja, ka = a
        ua = id_of(a)
        for b in nodes:
            ib, jb, kb = b
            ub = id_of(b)
            if ia <= ib and ja <= jb and ka <= kb and ua != ub:
                dinic.add_edge(ua, ub, INF)

    print(dinic.max_flow(S, T))

if __name__ == "__main__":
    solve()
```このソリューションは、各セルが決定ノードとなるフロー ネットワークを構築します。 ソースからノードへのエッジはセルを強制的に黒にするコストをエンコードし、ノードからシンクへのエッジはセルを強制的に白にするコストをエンコードします。 無限容量エッジは、色の割り当てが座標方向の順序を尊重する必要があるというルールをエンコードします。 

主要な実装の詳細は、3D 座標を単一の配列インデックスに平坦化するインデックス関数です。 これにより、すべてのグラフ操作がアクセスごとに O(1) のままになります。 もう 1 つの重要な点は、最適なカットでは単調性の違反が決して選択されてはならないため、無限の容量は考えられるコストの合計を支配するのに十分な大きさでなければならないということです。 

ノードの総数は 5000 で制限されており、最悪の場合のエッジ数は約 2500 万になるため、すべてのペアにわたるネストされたループは許容されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、グリッドに 1 つの次元にチェーンが 1 つしか含まれていない場合です。$1 \times 1 \times L$。 この状況では、問題は線に沿って黒から白への単一の遷移点を選択することになります。 ポセットが単純なチェーンになり、無限のエッジが単一のモノトーン カットを強制するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、すべてのセルが最初は同じ色である場合です。 フロー構築では引き続き有効なコストが割り当てられますが、境界制約によりカットでは少なくとも 1 つの遷移を導入する必要があります。 min-cut フレームワークは、この遷移を可能な限り安価な場所に正しく配置します。 

最後のケースは、コストが直観に反することを大きく支持する場合に発生します。たとえば、下位の座標を黒にするのは高価で、上位の座標を安価にするなどです。 単調制約により孤立した反転が防止されるため、解決策はローカルで貪欲な選択ではなく、グローバルなトレードオフになります。
