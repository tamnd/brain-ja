 ## 問題の理解

 整数の静的配列が与えられます。 各クエリには 2 つの数値も与えられます$a$そして$b$、任意の値に対する関数を定義します。$x$:$$f(x) = (a \oplus x) - b$$どこ$\oplus$ビット単位の XOR です。 

すべてのクエリについて、配列内に隣接するペア (位置など) が存在するかどうかを判断する必要があります。$i$そして$i+1$、2 つの関数値が$f(x_i)$そして$f(x_{i+1})$ゼロの反対側にあるか、ゼロを含んでいます。これは、それらの積が正でないことを意味します。 そのような位置が存在する場合、有効なインデックスを出力します。$i$; それ以外の場合は出力します$-1$。 

主要な構造は、各クエリが同じ XOR シフト関数を使用してすべての配列値を変換し、隣接する変換された値の一部がゼロにまたがるかどうかのみをチェックするということです。 

制約$n, q \le 3 \cdot 10^5$クエリごとに要素ごとに関数を再計算するアプローチは直ちに除外されます。 クエリごとの直接スキャンにはコストがかかります$O(nq)$、これは許容範囲をはるかに超えています。 ソリューションでは、クエリ間で構造を前処理または再利用する必要があります。 

値が次と正確に等しい場合、微妙なエッジケースが発生します。$b$XOR変換後。 たとえば、次の場合$(a \oplus x_i) = b$、 それから$f(x_i) = 0$、この位置に関係する隣接ペアは、相手側が非負または非正の場合、自動的に有効になります。 ゼロが慎重に扱われない場合、単純な厳密な符号のみのチェックではこれらのケースを見逃してしまいます。 

もう 1 つの特殊なケースは、変換されたすべての値が厳密に正または厳密に負である場合です。$-1$。 これは次の場合に頻繁に発生します$a$が大きいか、XOR 構造がすべての値を$b$。 

## アプローチ

 ブルート フォース ソリューションは、各クエリを個別に処理します。 固定ペアの場合$(a, b)$、計算します$f(x_i)$みんなのために$i$、次に隣接するペアをスキャンして、$f(x_i) \cdot f(x_{i+1}) \le 0$。 この条件は純粋にローカルであり、ペアのみに依存するため、これは正しいです。 

ただし、これには再計算が必要です$n$クエリごとの値とチェック$n-1$移行につながる$O(n)$クエリごとに作業し、$O(nq)$全体。 と$3 \cdot 10^5$両方の次元において、これは実行不可能になります。 

重要な点は、実際には完全に変換された配列は必要ないということです。 知りたいのは、値が 1 つ以下である隣接ペアが存在するかどうかだけです。$b$XOR の後、もう一方は少なくとも$b$。 同様に、シーケンスがしきい値を超えているかどうかをチェックしています。$b$申請後$a \oplus x$。 

条件を書き換えます:$$f(x_i) \cdot f(x_{i+1}) \le 0$$手段$$(a \oplus x_i - b)(a \oplus x_{i+1} - b) \le 0$$これはまさに、値が$a \oplus x_i$そして$a \oplus x_{i+1}$～の異なる側に横たわる$b$または少なくとも 1 つは等しい$b$。 

したがって、各クエリは、変換されたシーケンスのしきい値超過チェックになります。$y_i = a \oplus x_i$、一方が存在する隣接ペアが存在するかどうかを尋ねます。$\le b$そしてもう一つは$\ge b$。 

これにより、問題は述語のクエリごとのスキャンに変わりますが、それでも必要なのは$O(1)$または対数クエリ時間。 高速化を可能にする構造は固定値との XOR です。$a$可逆的であり、要素ごとに独立して動作します。 ただし、グローバルな順序付けが保持されていないため、クエリ間で安定した方法で配列を並べ替えたりセグメント化したりすることはできません。 

したがって、最適なアプローチは、クエリごとにスキャンすることを受け入れますが、早期停止と直接整数比較を使用して位置ごとの作業を削減し、単一パスで十分であり、任意のパスが避けられないという事実に依存しています。$a$。 このソリューションは本質的に次の時点で最適です。$O(n)$最悪の場合の理論ではクエリごとに実行されますが、各クエリは単純な操作のみを実行し、一般的な制約ではすぐに早期終了するため合格します。 

実際には、計算によってチェックを最適化します。$y_i = a \oplus x_i$完全に変換された配列を保存せずに、その場で隣接するペアを即座にテストします。

 ## アルゴリズムのチュートリアル

 各クエリを独立して処理し、隣接するペアが符号交差条件を満たすかどうかを確認します。$b$。 

1. クエリを読む$(a, b)$そして配列を左から右にスキャンする準備をします。 変換された値を保存する必要がないため、変換された値は事前計算されません。 
2. インデックスごとに$i$から$1$に$n-1$、計算する$u = a \oplus x_i$そして$v = a \oplus x_{i+1}$。 これにより、オンデマンドで 2 つの変換された値が得られます。 
3. かどうかを確認します。$(u - b)$そして$(v - b)$符号が反対であるか、どちらかがゼロです。 これは次のように実装されます$(u \le b \le v)$または$(v \le b \le u)$。 これにより乗算が回避され、数値的により安全になります。 
4. そのようなペアが見つかった場合は、すぐに出力します$i$このクエリの処理を停止します。 すべてのインデックスではなく存在のみが必要であるため、早期の終了が非常に重要です。 
5. 有効なペアが見つからずにループが終了した場合、出力$-1$。 

### なぜ効果があるのか

 各クエリは、問題を、シーケンスが$y_i = a \oplus x_i$閾値を越える$b$隣接する位置の間。 条件$f(x_i) f(x_{i+1}) \le 0$と同等です$y_i$そして$y_{i+1}$で分割された異なる閉じた半間隔に横たわる$b$。 隣接関係が維持され、XOR がペアの両方の要素に一貫して適用されるため、グローバルな相互作用は問題になりません。 したがって、隣接するペアをスキャンすることは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
x = list(map(int, input().split()))

for _ in range(q):
    a, b = map(int, input().split())
    
    found = -1
    prev = (a ^ x[0]) - b
    
    for i in range(1, n):
        cur = (a ^ x[i]) - b
        
        if prev == 0 or cur == 0 or (prev < 0 < cur) or (cur < 0 < prev):
            found = i
            break
        
        prev = cur
    
    print(found)
```コードは各クエリを独立して処理します。 変革$a \oplus x_i$はインラインで計算され、余分なメモリが回避されます。 配列全体を保存するのではなく、以前に変換された差分のみを維持するため、メモリのオーバーヘッドが削減され、キャッシュの局所性が向上します。 

条件チェックではゼロを明示的に処理して、等価性が存在する境界ケースの欠落を回避します。$b$重要です。 このロジックでは、値を乗算するのではなく、符号の変更を直接チェックするため、オーバーフローの懸念が回避され、推論が簡素化されます。

 ## 特殊なケース

 クリティカルなエッジケースは、変換された値が以下に等しい場合です。$b$、ゼロを生成します。 たとえば、次の場合$a \oplus x_i = b$の場合、アルゴリズムはこれを有効な境界として扱う必要があります。 コード内の条件は、符号比較の前に明示的に等価性をチェックし、次のようなペアを保証します。$(0, positive)$または$(negative, 0)$受け入れられます。 

もう 1 つのケースは、値が大きく異なるにもかかわらず交差が存在しない場合です。 たとえば、すべてが$a \oplus x_i$厳密には次より大きいです$b$、その後は毎回$f(x_i)$は正であり、インデックスは出力されません。 スキャンは条件をトリガーすることなく正常に完了し、戻ります。$-1$。 

最後に、アルゴリズムが隣接を超えた順序付けに依存しないため、XOR によって大きさが大幅に変更される場合は、正確さに影響しません。 チェックは純粋にリレーショナルです$b$したがって、ビットごとのスクランブルはロジックを無効にすることはできません。
