 ## 問題の理解

 各セルには、L 字型のトリオミノで構成されるタイルにどのように参加するかを説明するシンボルが含まれるグリッドが与えられます。 各 L 字型は、マークが付いた中央のセルで構成されます。`C`とラベルが付けられた 4 つの基本方向に伸びる 3 つの隣接するアーム`U`、`D`、`L`、 そして`R`。 有効な構成は、1 つの特別な空セルを除くすべてのセルをカバーする、結合されていない完全な L 字型で構成されている必要があります。 空のセルは、グリッドの右上隅にある場合にのみ許可されます。そうでない場合は、すべてのセルが 1 つの L 字型に属し、すべての L 字型が完全に一貫している必要があります。 

中心以外の各セルは、方向的に中心を指すことによって、どの中心に属するかをエンコードします。 あ`U`細胞はその中心が自分の真上にあると主張します。`D`セルはその中心がその真下にあると主張し、同様に左右についても同様です。 有効な構成は一貫性と完全性の両方を満たさなければなりません。すべてのアームが実際の構成を指している必要があります。`C`、 毎`C`正確に 3 本のアームを周囲に持つ有効な L 字型を形成する必要があり、セルを複数の L 字型で要求することはできません。 

出力はテスト ケースごとの単純な妥当性チェックであり、出力されます。`Yes`これらのルールに基づいてグリッド全体が完璧なタイルを形成している場合、および`No`さもないと。 

制約は総グリッド領域が大きく、すべてのテスト ケースで最大 10^6 セルになります。 これにより、セルごとに繰り返し探索を実行したり、バックトラッキングを実行したりするソリューションは即座に排除されます。 この構造は、各セルが一定の回数処理されるリニア スキャン ソリューションを示唆しています。 

いくつかの失敗例は見落とされがちです。 

1 つのケースは不完全な L 字型です。 たとえば、`C`位置 (2,2) では、一方向に有効な近傍が存在しないか、アームの 1 つが欠落している可能性があります。 

もう1つのケースは、主張が矛盾していることです。 2 つの異なる中心が、L 字型の一部として同じ腕細胞を主張する可能性があり、これを検出する必要があります。 

3 番目のケースは、無効な方向ポインターです。 セルがグリッドの外側を指している場合や、中心以外のセルを指している場合があります。 

最後に、特別な空セルのルールは微妙です。 グリッドには 1 つだけを含めることができます`.`ただし、(1, m) に出現する場合にのみ有効です。 他のすべてが正しい場合でも、他の位置は無効です。 

## アプローチ

 グリッドを検証する直接的な方法は、各 L 字型から開始してすべての L 字型を明示的に再構築することです。`C`。 すべてのセンターについて、その 4 つのアームを展開し、対応するセルが存在し、正しく戻っていることを確認し、それらを訪問済みとしてマークすることを試みます。 すべてのセンターを処理した後、空でないすべてのセルが正確に 1 回訪問され、セルが共有されていないことを確認します。 

各セルが最大 1 つの L 字型に参加するため、この総当たりスキャンはすでに最適に近い状態になっており、各アームは一定の回数検証されます。 チェックの総数はグリッド サイズに比例します。 ただし、実装を不注意にすると、誤って隣接セルを繰り返し再スキャンしたり、セルごとに再帰的な検証を実行したりして、不要なオーバーヘッドが発生する可能性があります。 

重要な観察は、すべての有効な構成が決定論的なマッピングを定義していることです。中心以外の各セルはその方向によって中心を一意に識別し、各中心はその 4 つの隣接セルを決定論的に定義します。 これにより、グローバル検索を行わずにローカルで検証できるようになります。 構造を探索する代わりに、各セルの制約を検証し、相互ポインタの一貫性を確認するだけです。 

したがって、問題は 1 回のパスで 3 つの条件を検証することに帰着します。 まず、すべての`C`正確に 4 本の有効なアームを正しい位置に形成する必要があります。 第 2 に、すべての方向性セルが正しくポイントしている必要があります。`C`そしてそれ`C`逆の関係に同意する必要があります。 第三に、すべてのセルは 1 回だけ考慮される必要があります。 

これにより、グラフの構築からグリッド上のローカルな整合性チェックまでの問題が軽減されます。

 ## アルゴリズムのチュートリアル

 グリッドをローカル制約のシステムとして扱い、各セルをその役割に基づいて検証します。 

1. まず、空のセルが 1 つ存在するかどうかを確認します。 正確に 1 つある場合`.`それが行 1、列 m にあるかどうかを確認します。 ドットがゼロであるか、ドットの位置が間違っている場合は、正確なルール解釈に応じて、直ちに拒否または続行されます。 このステップにより、L 字型の構造上の制約から特別な例外が分離されます。 
2. グリッド内のすべてのセルを反復処理します。 私たちが何かに遭遇するたびに、`C`、L 字型の中心として検証しようとします。 予想される 4 つのアームは、4 方向に直接隣接するセルです。 
3. 周囲の 4 つの方向ごとに、`C`、2 つの条件を同時にチェックします。 隣接するものはグリッド内にある必要があり、中心を指す正しい方向文字が含まれている必要があります。 たとえば、上のセルには次の内容が含まれている必要があります。`D`、下のセルには次の内容が含まれている必要があります`U`、左側には次のものが含まれている必要があります`R`、権利には次のものが含まれている必要があります`L`。 これにより、センターとアーム間の双方向の一貫性が保証されます。 
4. 必要な 4 つの近傍のいずれかが無効または不一致の場合、中心が完全な L 字型を形成していないため、直ちに拒否されます。 
5. 検証済みの L 字型に属するすべてのセルをマークする訪問済み配列を維持します。 センターとその 4 つのアームの検証に成功するたびに、関与する 5 つのセルすべてが使用済みとしてマークされます。 
6. すべての中心を処理した後、グリッド内のすべてのセルが有効な L 字型の一部であるか、または許可された空のセルであることを確認します。 未訪問のセルまたは複数回使用されたセルは、無効な重複またはカバレッジの欠落を意味します。 

### なぜ効果があるのか

 核となる不変条件は、すべての有効な構成が中心とその 4 つのアームの間で厳密な全単射を強制することです。 それぞれ`C`は、正確に 4 つの一意に決定された近傍によって囲まれている必要があり、各アーム セルは正確に 1 つの中心を指している必要があります。 これらの関係は決定論的でローカルであるため、各センターを個別に検証すると、グローバルな不一致を見逃すことはできません。 2 つの中心が重なっている場合、一部のセルが 2 回マークされるか、方向の一貫性が失われます。 センターが不完全な場合、少なくとも 1 つの隣接性チェックが失敗します。 したがって、グローバルな正確性を保証するには、ローカル チェックで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

DIRS = {
    'U': (-1, 0, 'D'),
    'D': (1, 0, 'U'),
    'L': (0, -1, 'R'),
    'R': (0, 1, 'L')
}

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        g = [input().strip() for _ in range(n)]

        visited = [[False] * m for _ in range(n)]
        dot_count = 0
        dot_pos = (-1, -1)

        for i in range(n):
            for j in range(m):
                if g[i][j] == '.':
                    dot_count += 1
                    dot_pos = (i, j)

        if dot_count not in (0, 1):
            print("No")
            continue

        if dot_count == 1:
            if dot_pos != (0, m - 1):
                print("No")
                continue

        ok = True

        for i in range(n):
            for j in range(m):
                if g[i][j] != 'C':
                    continue

                cells = [(i, j)]
                for c, (di, dj, need) in DIRS.items():
                    ni, nj = i + di, j + dj
                    if ni < 0 or ni >= n or nj < 0 or nj >= m:
                        ok = False
                        break
                    if g[ni][nj] != need:
                        ok = False
                        break
                    cells.append((ni, nj))

                if not ok:
                    break

                for x, y in cells:
                    if visited[x][y]:
                        ok = False
                        break
                    visited[x][y] = True

            if not ok:
                break

        if not ok:
            print("No")
            continue

        for i in range(n):
            for j in range(m):
                if g[i][j] == '.':
                    continue
                if not visited[i][j]:
                    ok = False
                    break
            if not ok:
                break

        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```解決策は、オプションのドット セルを数えて検証することから始まります。これは、グリッド内で唯一の非 L 字型の例外であるためです。 このチェックは、構造検証への干渉を避けるために、早期に分離されます。 

メインループはそれぞれの処理を行います。`C`潜在的なL字型センターとして。 各中心について、固定オフセットを使用してその 4 つの隣接点を直接チェックします。 方向文字と必要な反対側の記号の間のマッピングにより一貫性が保証されます。隣接するものが特定の方向の中心に接続されていると主張する場合、その関係は対称でなければなりません。 

訪問された配列は、非結合性を強制するために重要です。 これがなければ、ローカル チェックだけではセルの共有使用を妨げないため、重複する L 字型は確実に検出されません。 

最後に、フル スキャンによって完全性が保証されます。すべての非ドット セルは、正確に 1 つの有効な L 字型に属している必要があります。

 ## 特殊なケース

 エッジケースの 1 つは、`C`境界線上に置かれます。 たとえば、(0,0) にある中心には、境界外にある上と左に隣接するものが必要です。 このアルゴリズムは、近傍にアクセスする前にグリッド境界を明示的にチェックするため、これにより即座に拒否がトリガーされます。
