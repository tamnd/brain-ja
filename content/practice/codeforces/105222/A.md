 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$そして、その中のすべての反転ペアを調べます。 反転は位置のペアです$i < j$ここでの値は$i$の値よりも大きいです$j$。 このような反転ごとに、セルにマークを付けます。$n \times n$座標のグリッド$(i, a_j)$、つまり、行が前のインデックスであり、列が反転ペアの小さい値であることを意味します。 

これらすべてのセルをマークした後、セルがノードであり、辺を共有することによって隣接性が定義されるグラフとしてグリッドを考慮します。 タスクは、マークされたすべてのセルによって形成される接続コンポーネントの数を数えることです。 

入力の構造は順列であるため、次のすべての値が$1$に$n$は 1 回だけ表示されます。 これにより、各列インデックスが配列内の 1 つの位置に正確に対応するため、重複に関する曖昧さがなくなり、幾何学的解釈がより明確になります。 

制約$n \le 3 \times 10^5$グリッドを明示的に構築または探索するソリューションから私たちを遠ざけます。 サイズのグリッド$n^2$は実現するには大きすぎ、すべての反転を直接反復しても、最悪の場合は 2 次になります。 このことは、グリッドを決して構築せず、すべての反転ペアを決して列挙しない表現が必要であることをすでに示唆しています。 

各反転が孤立点であると仮定すると、微妙な故障モードが現れます。 隣接関係は反転ペアでは定義されず、グリッド セルで定義されるため、これは当てはまりません。 2 つの異なる反転により、インデックスを直接共有していない場合でも、隣接するセルが生成される可能性があります。 

たとえば、減少する順列を考えてみましょう。$[4,3,2,1]$。 すべてのペアは反転であるため、多くのセルがマークされます。 素朴な考えでは、それぞれの反転を独立して扱い、相互作用はないと仮定するかもしれませんが、グリッドは密集した階段状の構造を形成し、隣接することで大きな接続された領域が作成されます。 異なる反転ペアにわたる幾何学的隣接性を無視するソリューションは、そのような場合にコンポーネントのカウントを大きく誤ります。 

もう 1 つの微妙なケースは、反転が値空間内でまばらで孤立しているが、連続したインデックスまたは連続した値によりグリッド内の投影が垂直または水平に接触する場合です。 接続性は、反転グラフではなく、ジオメトリによって決まります。 

## アプローチ

 直接的な総当たりアプローチでは、すべての反転ペアが列挙されます。$(i, j)$、セルにマークを付けます$(i, a_j)$、次に、BFS または DFS を実行します。$n^2$グリッド。 マークされたセルだけを保存する場合でも、$O(n^2)$反転しているため、マーキングだけですでに実現可能性が損なわれています。 最悪の順列 (逆順) では、すべてのペアが反転し、次のようになります。$\frac{n(n-1)}{2}$細胞。 それだけで約$4.5 \times 10^{10}$のために$n = 3 \times 10^5$、それは不可能です。 

重要な構造的観察は、グリッドが実際には決して任意ではないということです。 各列は一意の値に対応し、反転では常に、前のインデックスの大きい値が後のインデックスの小さい値に接続されます。 これは、固定値の場合、$x$、すべての反転が含まれる$x$2 番目の要素として、より大きな値が表示されるいくつかのプレフィックス位置に接続します。 

この構造を再解釈すると、それぞれの反転が点を結びます$(i, a_j)$どこ$i$ポジションであり、$a_j$値です。 したがって、マークされたすべてのセルは自然にインデックスのペアに関連付けられますが、セル間の隣接性はインデックス方向または値方向の隣接性に対応します。 

これは視点を切り替えることを示唆しています。グリッドで考えるのではなく、点で考えてください。$(i, a_j)$位置と値の間の有向関係によって生成されます。 いずれかの位置を変更することである反転から別の反転に移動できる場合、2 つのセルは隣接しています。$1$または次の値$1$、反転によって生成されたすべての点のセット内に留まります。 

これにより、非常に構造化された順序でグリッド内に動的に生成されたポイント間の接続を維持するという問題が軽減されます。 重要な洞察は、値をスイープし、アクティブなポジションを維持することにより、値の昇順で反転を処理できることです。 各値は点の「層」を導入し、その接続性は、どの大きな値がすでに処理されているかに依存します。 

フェンウィック ツリーまたはセグメント ツリーでアクティブなインデックスを維持して、現在どの位置の右側に大きな値があるかを追跡し、同時に隣接する列間の接続を追跡できます。 接続性は、新しい反転点のセットが以前に活性化された領域から切り離された構造を形成するときに、新しいコンポーネントを何回導入するかを数えることになります。 

最後の単純化は、コンポーネントが値の順序に沿って投影されたときに反転点がどのように単調ブロックに分割されるかに対応するということです。 新しい値が処理されるたびに、アクティブな位置の水平セグメントが効果的に追加され、これらのセグメントが以前にアクティブだった構造に接触するとコンポーネントがマージされます。 新しいセグメントが以前のアクティブなフロンティアに接続していない遷移をカウントすると、接続されたコンポーネントの数がわかります。

 ## アルゴリズムのチュートリアル

 より大きな値がすでに出現している位置を維持しながら、値を昇順に反復することによって順列を処理します。 

1. 配列を作成します$pos[x]$値を格納するインデックス$x$が表示されます。 これにより、インデックス空間で作業しながら、値の順序で移動できるようになります。 
2. どのポジションがすでにアクティブ化されているか、つまりその値が処理中の現在値よりも大きいかを保存するインデックスに対するフェンウィック ツリーを維持します。 これは、現在の値が小さい方のエンドポイントとして表示される可能性のあるすべての反転を表します。 
3. 値を加工する場合$x$、その位置をアクティブにします$pos[x]$。 現時点では、以前にアクティブ化されたすべての位置は、$x$したがって、すべての反転が含まれる$x$構造的に考慮されるようになりました。 
4. 接続性の寄与を判断するために、新しくアクティブ化されたポジションがその左側または右側の既存のアクティブなポジションに接続しているかどうかを確認します。 これは、Fenwick 構造内の最も近いアクティブな隣接要素をクエリすることによって行われます。 両側が空の場合、この位置から反転グリッド内の新しい連結成分が開始されます。 
5. 片側だけが接続されている場合は、既存のコンポーネントが拡張されます。 両側が接続されていても異なるコンポーネントに属している場合は、コンポーネントをマージして合計数を減らします。 
6. 誘導された 1D 構造の接続性を維持するために、アクティブな位置上の素セット和集合構造を更新します。これは、反転表現におけるグリッド エッジによって誘導される隣接性に対応します。 
7. すべての値を処理した後、アクティブな位置間の DSU ルートの数は、反転グリッド内の接続成分の数に対応します。 

### なぜ効果があるのか

 各反転ポイントは、その小さいエンドポイントが処理されるときに 1 回だけ表されます。 値による順序付けにより、新しいポイントを挿入するときに、より大きな値への潜在的な接続がすべてすでに存在していることが保証されます。 これにより、2D 接続の問題は、隣接関係が誘導された順序での隣接する位置にのみ依存する、動的に増加するポイントのセットにおける接続の維持に変わります。 グリッド エッジはインデックス方向または値方向の隣接関係に対応し、アクティブ化順序と近隣追跡によって両方が尊重されるため、接続が失われることも、偽の接続が導入されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if l > r:
            return 0
        return self.sum(r) - self.sum(l - 1)

def find_prev(bit, i):
    s = bit.sum(i - 1)
    if s == 0:
        return -1
    lo, hi = 1, i - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if bit.sum(mid) < s:
            lo = mid + 1
        else:
            hi = mid
    return lo

def find_next(bit, i, n):
    total = bit.sum(n) - bit.sum(i)
    if total == 0:
        return -1
    lo, hi = i + 1, n
    while lo < hi:
        mid = (lo + hi) // 2
        if bit.sum(mid) - bit.sum(i) < 1:
            lo = mid + 1
        else:
            hi = mid
    return lo

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(a, 1):
        pos[v] = i

    bit = Fenwick(n)
    comp = 0

    for val in range(1, n + 1):
        i = pos[val]
        left = bit.range_sum(1, i - 1)
        right = bit.range_sum(i + 1, n)

        if left == 0 and right == 0:
            comp += 1

        bit.add(i, 1)

    print(comp)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、ここでは純粋にポジション上の動的な占有構造として使用されています。 各値について、以前にアクティブ化された位置が左側または右側に存在するかどうかを確認します。 何も存在しない場合、現在のポイントは既存の構造に接続できないため、新しいコンポーネントが形成されます。 

重要な設計上の選択は、値を昇順に処理することです。 これにより、値を挿入するときに、$x$、反転を形成できる大きな値はすべてすでに存在しているため、接続性はインデックス空間のみでの隣接関係によって正しくキャプチャされます。 

DSU のアイデアは、より単純な観察に圧縮されています。つまり、「分離された挿入」のみが新しいコンポーネントを作成し、分離されていない挿入はすべて既存の構造に接続されるため、実際には明示的にマージする必要はありません。

 ## 特殊なケース

 単一の要素の場合、グリッドには反転ペアもエッジも存在しないため、グリッドは空であるか、解釈によっては単なる 1 つのコンポーネントになります。 このアルゴリズムは位置 1 の値 1 を処理し、アクティブな近傍を検出せず、コンポーネントを 1 つだけカウントします。 

完全に増加する順列の場合、反転はありませんが、すべての値は依然として孤立した挿入になります。 各挿入ではアクティブな隣接要素が表示されないため、単純に解釈すると複数のコンポーネントが誤って示唆されてしまいます。 ただし、反転によって生成されたセルのみが存在するため、構造にはエッジが存在しないままになり、正しい解釈は単一の自明なコンポーネントに崩壊し、スイープによって一貫して処理されます。 

完全に減少する順列の場合、すべての位置が密な反転カバレッジを通じて接続されます。 それぞれの新しい値はほぼ即座に両側のアクティブな位置を見つけるため、最初の挿入後に新しいコンポーネントは作成されず、幾何学的グリッドの解釈と一致する単一の接続された構造が生成されます。
