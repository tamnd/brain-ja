 ## 解決策
 ## 問題の理解

 固定 2D コンテナとして機能する長方形のデッキが与えられます。その左下隅が原点、右上隅が原点になります。$(l, h)$。 この空間に、軸を揃えた一連の長方形のボックスを配置する必要があります。 各ボックスの向きは固定されており、回転することはできません。また、以前に配置されたボックスと重ならないように完全にデッキ内に配置する必要があります。 

箱は厳密な順序で到着します。 各ボックスについて、その時点で有効な配置が存在しない場合は、ボックスを配置するか、すぐに破棄する必要があります。 配置は貪欲かつ決定的です。ボックスが以前のボックスと重ならずに収まり、境界内に残るすべての有効な位置の中から、左下隅の x 座標が最小のものを選択します。 このような位置が複数存在する場合は、最小の y 座標を選択して関係を解消します。 

主な問題点は、配置された各四角形が将来のスペースをブロックするため、有効な位置のセットが配置のたびに進化することです。 プロセスはオンラインで行われるため、決定は取り消せません。 

この制約では、最大 50 個のボックスと最大 50 個の座標が許可されます。$10^9$。 小さいもの$n$をする余裕があることを強く示唆しています。$O(n^2)$あるいは$O(n^3)$幾何学的シミュレーション。 重要なのは数値の大きさではなく、配置候補の組み合わせ構造です。 

素朴な落とし穴は、貪欲にボックスを配置できると想定してしまうことです。$(0,0)$可能であれば、または 1 つの軸に沿ってのみスキャンします。 これは、最適な配置が以前に配置された長方形によって形成された角に「スナップ」することが多く、有効な位置が x 制約と y 制約の両方に同時に依存するため、失敗します。 

複数の長方形が互いに素な候補コリドーを作成する場合、微妙な失敗例が発生します。 たとえば、大きな長方形が左下をブロックし、たとえ下位の y スペースが右端に存在していても、次の長方形がより高い y で開始することを強制する場合があります。 垂直方向の制約を考慮せずに左から右のみをチェックする欲張りスキャンでは、誤って有効な配置を見逃してしまいます。 

## アプローチ

 この強引なアイデアは、新しい四角形が配置される可能性のあるすべての左下隅を明示的にテストすることです。 長方形は軸に沿って配置され、回転しないため、有効な配置では、その x 座標が 0 または既存の長方形の右端のいずれかに等しく、同様に、その y 座標が 0 または既存の長方形の上端のいずれかに等しい必要があります。 これは、有効な「タイトな」配置は境界または他の長方形に触れなければならないためです。 そうしないと、最小性と矛盾して左または下にシフトする可能性があります。 

したがって、単純なシミュレーションでは、既存の長方形から候補となるすべての x 位置と y 位置を収集し、すべてのペアを形成し、その長方形が重なりなく収まるかどうかをテストします。 入ってくる四角形ごとに、すべての候補をスキャンし、辞書順に最小の有効なものを選択します。 

これが機能するのは、実現可能性の定義を直接エンコードするためです。 ただし、挿入するたびに長方形の数が増加し、候補位置の数も増加します。 最悪の場合、それぞれの$n$長方形が貢献する$O(n)$x と y の候補エッジ、$O(n^2)$クエリごとの掲載順位と$O(n^3)$合計の重複チェック。 各オーバーラップ チェック自体は、既存のすべての四角形をスキャンして、それを次の方向に押し出す可能性があります。$O(n^4)$素朴な実装では。 

重要な点は、実際にはすべての候補座標を列挙する必要はないということです。 問題の構造により、最適な配置は常に、既存の四角形のすぐ右または真上の座標、または原点で行われます。 これは古典的な「長方形のスカイライン」構造です。すべての実行可能な配置は、以前の配置によって定義された境界点の有限セット上にあります。 

増加する候補位置のセットを維持し、新しい四角形ごとに、x、y の順に並べ替えてテストできます。 長方形を配置すると、新しい角の候補が導入されます。$(x + w, y)$そして$(x, y + h)$。 また、重複または範囲外の制約により有効でなくなった候補はすべて破棄されます。 

以来$n \le 50$、配置されたすべての四角形を維持し、候補位置ごとに、以前のすべての四角形と照合して重複をテストする余裕があります。 これにより、実装が簡単になりながらも十分な速度が保たれます。

 ## アルゴリズムのチュートリアル

 1. すでに配置されている長方形のリストを維持します。 各長方形は次のように格納されます。$(x, y, w, h)$。 これは、すべての重複検証に使用されるグランド トゥルースです。 
2. 新しい四角形が開始される候補位置のセットを維持します。 当初、これには次の内容のみが含まれます$(0, 0)$。 これは、配置が存在する前の唯一の有効な開始コーナーを反映します。 
3. サイズの入力長方形ごとに$(w, h)$、x、次に y でソートされたすべての候補位置を反復します。 この順序により、実行可能な配置の左端とその中で最も低い配置を選択するという問題の要件が強制されます。 
4. 各候補ポジションについて$(cx, cy)$、まず長方形がデッキ境界内にあるかどうかを確認します。$cx + w \le l$そして$cy + h \le h$。 境界に違反する場合は、有効ではないため、すぐにスキップしてください。 
5. 境界内にある場合は、以前に配置されたすべての長方形との重なりをチェックします。 2 つの長方形の投影が x 次元と y 次元の両方で厳密に交差する場合、2 つの長方形は重なり合います。 重複が見つかった場合は、この候補を拒否します。 
6. 両方のチェックに合格した最初の候補が、この長方形の配置として選択されます。 回答の一部として記録してください。 
7. 機能する候補がない場合は、この四角形に対して -1 を出力します。 
8. 配置が成功した場合は、配置されたリストに新しい四角形を挿入し、追加することで候補を更新します。$(cx + w, cy)$そして$(cx, cy + h)$これらは、新しく配置された長方形の右端または上端に触れることによって形成される、新しい潜在的な左下隅を表すためです。 

### なぜ効果があるのか

 このアルゴリズムは、長方形の有効な配置はすべて、境界に当たるか別の長方形に接触するまで左または下に「押す」ことができるという不変式に依存しています。 これは、最小限の有効な配置は、既存の構造によって定義されたコーナーと一致する必要があることを意味します。 このようなすべてのコーナーを候補として維持することにより、辞書編集順で最初の実行可能な候補が正確に必要な配置であることが保証されます。 オーバーラップ チェックにより、以前の制約に違反する位置が決して受け入れられないことが保証され、候補の拡張により、将来の有効なコーナーが見逃されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def overlaps(a, b):
    x1, y1, w1, h1 = a
    x2, y2, w2, h2 = b
    if x1 >= x2 + w2 or x2 >= x1 + w1:
        return False
    if y1 >= y2 + h2 or y2 >= y1 + h1:
        return False
    return True

def can_place(x, y, w, h, L, H, rects):
    if x + w > L or y + h > H:
        return False
    for rx in rects:
        if overlaps((x, y, w, h), rx):
            return False
    return True

def solve():
    n, L, H = map(int, input().split())
    rects = []
    candidates = {(0, 0)}
    
    for _ in range(n):
        w, h = map(int, input().split())
        cand_list = sorted(candidates)
        placed = None
        
        for x, y in cand_list:
            if can_place(x, y, w, h, L, H, rects):
                placed = (x, y)
                break
        
        if placed is None:
            print(-1)
            continue
        
        x, y = placed
        print(x, y)
        rects.append((x, y, w, h))
        
        candidates.add((x + w, y))
        candidates.add((x, y + h))

if __name__ == "__main__":
    solve()
```コードは候補セットのシミュレーションに直接従います。 オーバーラップ チェックは軸分離ロジックを使用して明示的に記述されるため、浮動小数点ジオメトリの問題が完全に回避されます。 

候補セットは重複排除のために Python セットとして保存され、辞書編集的な選択を強制するためにクエリごとに並べ替えられます。 与えられた$n \le 50$、繰り返しの並べ替えは無視できます。 

重要な実装の詳細は、次の厳密な分離条件です。`overlaps`。 使用する`>=`接触するエッジが重なりとみなされないことを保証します。これは、長方形は接触することはできますが交差することはできないため、重要です。

 ## 特殊なケース

 重要なエッジケースは、長方形が重ならずに別の長方形に正確に接触する場合です。 たとえば、$5 \times 5$(0,0) の長方形と (5,0) の長方形。 エッジ接触が許可されるため、2 番目の配置は有効です。 重複検出では厳密な分離が使用されるため、アルゴリズムはこれを正しく処理します。`>=`、境界に触れる構成が可能になります。 

もう 1 つのケースは、大きな長方形がすべての低 x 位置をブロックし、より右側に小さな y 領域が存在する場合でも、より高い y に配置することを強制する場合です。 候補拡張ステップにより、長方形が配置されると、その上端と右端が新しい有効な開始点になることが保証されます。 これにより、アルゴリズムが原点に隣接していない有効な構成を見逃すことがなくなります。 

最後に、幅と高さの両方の制約により適合する候補がない場合を考えてみましょう。 このアルゴリズムはすべての候補を網羅し、-1 を正しく出力します。これは、すべての潜在的なコーナーが境界条件とオーバーラップ条件の両方に対して明示的にテストされ、隠れた配置の可能性が検討されないままになるためです。
