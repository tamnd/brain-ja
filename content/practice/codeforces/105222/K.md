 ## 解決策
 ## 問題の理解

 一連の要素の使用法が与えられ、各ステップで最大 17 種類の要素の 1 つが適用されます。 エレメントがモンスター上で使用されると、そのエレメントはモンスター上の現在の「アクティブなエレメント」と相互作用します。 モンスターにアクティブな要素がない場合は、使用された要素が単純にアクティブになります。 すでにアクティブな要素が存在する場合、2 つの要素は、次の条件によって決定されるダメージを生成します。$m \times m$反応後、活性元素は新たに使用される元素になります。 

1 つ工夫があります。各要素タイプは独立して「遅延」または「非アクティブ」としてマークできます。 要素が遅延している場合、その要素がシーケンス内に出現するたびに完全に無視され、ダメージは発生せず、モンスターの状態も変更されません。 あるので$m$要素、あります$2^m$可能な遅延/非遅延構成があり、各構成について、そのルールに基づいてシーケンス全体を処理することによって生成される合計ダメージを計算する必要があります。 

シーケンスの長さは最大です$10^5$、 その間$m \le 17$。 この組み合わせは、配列に依存するもの以外は指数関数的であることを即座に示唆します。$m$許容可能ですが、構成ごとに線形であっても遅すぎます。 サブセットごとの直接シミュレーションには、$O(2^m \cdot n)$、これは限界をはるかに超えています。$2^{17} \approx 1.3 \cdot 10^5$、配る$10^{10}$操作。 

微妙なエッジ ケースは、構成内のすべての要素が非アクティブである場合です。 この場合、すべての要素は無視され、答えはゼロでなければなりません。 単純な実装では、依然として遷移をシミュレートしようとして、初期化されていない「現在の要素」に誤ってアクセスし、ガベージや誤ったダメージの蓄積が発生する可能性があります。 

もう 1 つの特殊なケースは、同じ要素が繰り返されるシーケンスです。 「同じタイプも反応を引き起こす」というルールがあるため、アクティブな要素が$x$そして私たちは申請します$x$繰り返しになりますが、さらに追加します$a_{x,x}$そして保管してください$x$。 連続する等しい要素をスキップする不用意な最適化では、これらの寄与が誤って削除されてしまいます。 

## アプローチ

 ブルートフォースアプローチは単純なシミュレーションです。 それぞれについて、$2^m$サブセットの場合、シーケンスを反復処理して、現在のアクティブな要素を維持します。 キャラクターに遭遇すると、それが非アクティブかどうかを確認します。 そうでない場合は、行列を使用してダメージを計算し、状態を更新します。 これは、定義どおりのプロセスに従っているため、正しいです。 ただし、それぞれのシミュレーションは、$O(n)$したがって、全体の複雑さは次のようになります。$O(2^m \cdot n)$。 と$n = 10^5$そして$2^m \approx 10^5$、これは不可能になります。 

重要な観察は、シーケンスは長いにもかかわらず、システムの状態空間が小さいということです。 いつでも、モンスターは現在アクティブな要素または「なし」によってのみ記述されます。 したがって、このプロセスは次のようなグラフ上を歩くことになります。$m + 1$アクティブな要素のセットが与えられると、状態と遷移は決定的になります。 本当の難しさは、アクティブな要素のすべてのサブセットに対する答えが必要なことです。 

サブセットごとに最初から再計算するのではなく、問題をサブセットにわたる動的なプロセスとして再解釈します。 固定サブセットの場合、各キャラクターの動作は「スキップ」または「トランジションの適用」のいずれかになります。 これは、要素上のビットマスク DP を使用し、位置ごとの遷移の事前計算と組み合わせて、すべてのサブセットを同時に処理することを示唆しています。 

要素のすべてのペアについて、前のアクティブな要素が固定されているセグメントを処理すると何が起こるかを事前計算します。 次に、SOS スタイルの DP アイデアを使用してサブセット全体に寄与を伝播します。シーケンスの各プレフィックスについて、各サブセットがどのように進化するかを維持しますが、次の事実を使用して圧縮されます。$m$小さいです。 

重要な簡素化は、要素ごとにシーケンスを維持しながら 1 回処理することです。$x$、アクティブな要素で終わるトランジションの合計寄与度$x$そして、サブセット畳み込みロジックを使用して、サブセット全体でこれらの寄与を結合します。 各位置は前のアクティブな要素にのみ依存するため、その要素がアクティブであるかどうかを決定するまで、選択したサブセットとは独立した方法で寄与を蓄積します。 

これにより、シミュレーションによる問題が軽減されます$2^m$オートマトンはトランジションごとに寄与を集約し、サブセット変換を適用します。

 ## アルゴリズムのチュートリアル

 まず、状態間の遷移という観点から反応プロセスを再解釈します。 モンスターの状態は空であるか、何らかの要素と等しいかのいずれかです$x$。 文字を加工するとき$c$アクティブな場合は、空の要素から開始するか、前の要素から開始します。$x$、その移行に応じてコストを追加します。 

重要なのは、シーケンス処理をサブセット フィルタリングから分離することです。 ペアごとに計算します$(x, y)$、前のアクティブな要素が存在する場所での発生によってどの程度のダメージが寄与するか$x$そして要素を適用します$y$。 これは、実行状態変数を使用してシーケンスを 1 回スキャンすることで直接取得されます。 

## アルゴリズムのチュートリアル

 1. 入力文字列をインデックスに変換します。$0 \ldots m-1$。 これにより、文字マッピングのオーバーヘッドを発生させずに、反応マトリックスに直接インデックスを付けることができます。 
2. ベース遷移アキュムレータを初期化する$cnt[x][y]$、合計貢献度を表します。$x$は現在アクティブな要素であり、$y$が適用されます。 すべての要素がアクティブであると仮定して完全なシーケンスを一度シミュレートし、現在のアクティブ状態からの遷移を追跡します。 
3. シミュレーション中、要素を適用するたびに$y$以前の状態で$x$、追加します$a[x][y]$に$cnt[x][y]$。 次に、現在の状態を次のように更新します。$y$。 これにより、すべてのインタラクション イベントが圧縮された周波数形式でキャプチャされます。 
4. 次に、サブセットを考慮する必要があります。 サブセットごとに$S$、両方の場合にのみ遷移します。$x \in S$そして$y \in S$有効です。 これは、すべてのサブセットについて、すべての合計が必要であることを意味します。$cnt[x][y]$と$x, y \in S$。 
5. 私たちは変身します$cnt$ビットマスク上の標準サブセット DP を使用して、サブセット上の関数に変換します。 配列を定義します$f[mask]$そのマスクに含まれるすべてのペアからの寄与を集計します。 
6. 計算する$f$すべてを反復してペアに対して包含を使用する$x, y$、追加$cnt[x][y]$両方を含むすべてのマスクに$x$そして$y$。 これは、サブマスク上のビットマスク DP を使用して効率的に行われます。 
7. 最後に出力します。$f[mask]$すべてのマスクに対して$0$に$2^m - 1$。 

これが機能する理由は、サブセット内のすべての有効な反応シーケンスが、完全な遷移シーケンスを許可された要素に正確に制限するためです。 要素がサブセットにないステップはすべて消え、残りのトランジションは変更されません。 寄与度は独立した遷移にわたって線形であるため、最初に寄与度を集計し、後で合計を変更せずにサブセットによってフィルタリングできます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    m, n = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(m)]
    s = input().strip()
    
    seq = [ord(c) - 97 for c in s]

    cnt = [[0] * m for _ in range(m)]

    cur = -1
    for x in seq:
        if cur != -1:
            cnt[cur][x] += a[cur][x]
        cur = x

    # subset aggregation
    size = 1 << m
    f = [0] * size

    for x in range(m):
        for y in range(m):
            if cnt[x][y] == 0:
                continue
            mask = (1 << x) | (1 << y)
            sub = mask
            while sub < size:
                if (sub & mask) == mask:
                    f[sub] += cnt[x][y]
                sub = (sub + 1) | mask  # iterate supersets trick

    print(*f)

if __name__ == "__main__":
    solve()
```コードはまずシーケンスを整数インデックスに圧縮します。 次に、以前のアクティブな要素を維持した単一パスを実行します。 遷移が発生するたびに、対応するダメージが 2D アキュムレータに追加されます。 

2 番目のフェーズでは、蓄積された各ペアの寄与を両方のエンドポイントを含むすべてのサブセットに分配します。 ビットマスクの反復により、各有効なサブセットが寄与を 1 回だけ受け取ることが保証されます。 

デリケートな部分は、正しい以前の状態を維持することです。 変数`cur`固定されたフルラン解釈の最後の非遅延要素を常に反映する必要があります。 そうしないと、遷移が誤ってカウントされます。 もう 1 つの微妙な点は、自己遷移が自然に含まれていることです。`cur == x`それでも貢献をトリガーします。 

## 実用的な例

 ### 例 1

 入力:```
m=3, s="abca"
```遷移を追跡します。 

| ステップ | 文字 | 前へ | 貢献 |
 | --- | --- | --- | --- |
 | 1 | | - | 0 |
 | 2 | b | | [a][b] |
 | 3 | c | b | a[b][c] |
 | 4 | | c | [c][a] |

 それで:

 - cnt[a][b] += 1
 - cnt[b][c] += 1
 - cnt[c][a] += 1

 これで、各サブセットはその内部に完全にペアだけを蓄積します。 たとえば、サブセット {a,b} には a→b のみが含まれ、サブセット {a,b,c} には 3 つの遷移すべてが含まれます。 

これにより、貢献は順序ではなく、どのエンドポイントが含まれるかによってのみ依存することが確認されます。

 このパターンは状態の繰り返しの切り替えを示していますが、問題となるのは連続したアクティブなペアだけです。 次に、サブセット フィルタリングにより、遷移数を変更せずに無効な要素が選択的に削除されます。 

これは、長いシーケンスが少数の状態遷移に圧縮されることを示しています。

 ## 特殊なケース

 サブセット内のすべての要素が遅延している場合、すべての文字は無視され、答えはゼロでなければなりません。 アルゴリズムでは、そのようなサブセットには、カウントされる遷移の両方のエンドポイントが含まれることはありません。そのため、当然のことながら、寄与は受けられません。 

「aaaa」のような同じ文字が繰り返されるシーケンスの場合、すべての遷移は自己反応です。 アキュムレータは正しく加算します$a[a][a]$サブセット フィルタリングでは、サブセットにその要素が含まれている場合にのみそれが保存されます。 

いつ$n = 1$、トランジションはまったくありません。 アキュムレータはすべてのペアでゼロのままであるため、すべてのサブセットは正しくゼロに評価され、反応がまったく発生しないという事実と一致します。
