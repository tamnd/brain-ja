 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられたピースを m × m のグリッドに配置するように求められます。 各ピース i は整数座標のセルに配置されます。 制約はジオメトリをインデックスに結び付けます。任意の 2 つの部分 i と j について、それらの位置間のマンハッタン距離は少なくともそれらのラベルの絶対差でなければなりません。 

したがって、2 つの駒の番号が近い場合は、ボード上で近くにあることが許可されますが、インデックスが離れている場合は、物理的にも遠くなければなりません。 タスクは、実現可能性を確認するだけでなく、可能な限り小さな正方形のボード上で機能する配置を構築することです。 

入力はピースの数である n だけです。 出力は、最初に可能な最小の辺の長さ m、次に 1 から n までのすべての部分の座標です。 

n ≤ 1000 という制約は、候補基板サイズごとに 3 次構造またはそれより悪い構造を複数の可能性にわたって繰り返すとすでに遅すぎることを意味しますが、実際の制限は概念的なものであり、基板をテストするのではなく、最適な m の直接構造を導出する必要があります。 

素朴な考え方による微妙な失敗例は、隣接するインデックスのみを考慮する貪欲な配置を想定することです。 たとえば、(i, 1) のようにピースを直線に配置することは失敗します。これは、インデックスは離れているものの、空間的には離れていないペアでは、一方向の距離が不十分であるためです。 もう 1 つの間違いは、条件がすべてのペアにわたって 2 次であるため、すべてのペアが大域不等式を満たすことを保証せずにランダムまたはスパイラル配置を試みることです。 

重要な問題は、この条件がインデックスの差とマンハッタン距離を結合していることです。これは、インデックスの順序が単調な幾何学的パスと一致する必要があることを示唆しています。 

## アプローチ

 強引なアイデアは、ボード サイズ m を固定し、すべてのペアの制約をチェックしながら n 個のポイントすべてを配置しようとすることです。 特定の配置では、これは O(n²) であり、m にわたって検索するか、バックトラッキングによって配置を構築しようとすると、状態空間は指数関数的になります。 単一の候補配列をチェックすることさえ、最大 1000 までの n については処理可能ですが、実際の問題は 1 つを生成することです。 

重要な観察は、この条件が |i − j| のみに依存するということです。 右側にあります。 これは、インデックスの増分ごとに点がマンハッタン距離で最大 1 だけ移動するように点を配置することを強く示唆しています。これは、任意の 2 つの点 i と j がチェーンに沿った三角不等式を満たすためです。 

distance(i, j) ≥ ステップ距離の合計 ≥ |i − j| 各ステップが正確に 1 に寄与する場合。 

したがって、n 個の位置を訪問するグリッド セルを通るパスが必要です。ここで、連続する位置はマンハッタン距離がちょうど 1 にあります。これを行うと、パスに沿ったステップごとに少なくとも 1 が蓄積されるため、i と j の間のグリッド内の最短パスは少なくとも j − i の距離になります。 

これにより、境界ボックスを最小限に抑えながら、グリッド上に長さ n の単純なパスを埋め込むという問題が軽減されます。 このようなパスを詰める最も厳密な方法は、列を蛇行することです。左から右に進み、次に右から左に進み、毎回 1 列ずつ下に移動します。 これにより、ハミルトニアン パスのような長方形の横断が作成されます。 

m を最小化するには、n 個の位置を収容するのに十分なセルが必要なので、m は m² ≥ n を満たす必要があります。 m x m グリッド上のスネーク トラバースはすべての m² セルを訪問し、必要なステップ プロパティを保持するため、これで十分であることがわかります。 

したがって、答えは m = ⌈√n⌉ となり、単純にグリッドを行ごとに交互の方向に埋めていきます。

 ## アルゴリズムのチュートリアル

1. m × m が少なくとも n になるような最小の整数 m を計算します。 これにより、すべてのピースを配置するのに十分なセルが確保されます。 
2. グリッドの行を中心にピースを配置しますが、各行の方向は交互になります。 偶数行では左から右に進み、奇数行では右から左に進みます。 
3. この走査で i 番目に訪問したセルにピース i を割り当てます。 
4. 残りのセルを無視して、n 個のピース​​を配置したら停止します。 

交互の方向により、連続するインデックスが常に隣接するセル間で水平方向または行境界での垂直方向のステップで移動することが保証されます。 これにより、インデックス内のすべてのステップがマンハッタン距離に正確に 1 に対応することが保証されます。 

### なぜ効果があるのか

 連続するインデックス i と i+1 を考慮します。 構造上、それらはスネーク パス内で隣接しているため、それらのマンハッタン距離は正確に 1 です。任意のペア i < j の場合、シーケンスに沿ったそれらの間のパスは、j − i 個の単位ステップで構成されます。 三角不等式により、端点間のマンハッタン距離は少なくともステップ距離の合計であるため、少なくとも j − i になります。 これは必要な条件に正確に一致するため、構築は有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

m = 1
while m * m < n:
    m += 1

coords = []

for r in range(m):
    if len(coords) >= n:
        break
    if r % 2 == 0:
        for c in range(m):
            coords.append((r + 1, c + 1))
            if len(coords) == n:
                break
    else:
        for c in range(m - 1, -1, -1):
            coords.append((r + 1, c + 1))
            if len(coords) == n:
                break

print(m)
for r, c in coords:
    print(r, c)
```m の計算により、最小のグリッド サイズが確保されます。 トラバーサルでは、m × m グリッド上にハミルトニアン パスが構築され、n ステップ後に切り捨てられます。 行パリティ スイッチがないと行エンドポイント間の垂直ジャンプが大きくなりすぎるため、行パリティ スイッチは不可欠です。

この例は、ヘビが行の遷移時にルール違反を回避する方法を示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    m = 1
    while m * m < n:
        m += 1

    coords = []
    for r in range(m):
        if len(coords) >= n:
            break
        if r % 2 == 0:
            for c in range(m):
                coords.append((r + 1, c + 1))
                if len(coords) == n:
                    break
        else:
            for c in range(m - 1, -1, -1):
                coords.append((r + 1, c + 1))
                if len(coords) == n:
                    break

    out = [str(m)]
    out += [f"{r} {c}" for r, c in coords]
    return "\n".join(out)

# provided samples
assert run("2\n") != "", "sample 1 basic sanity"

# custom cases
assert run("1\n").splitlines()[0] == "1", "minimum case"
assert len(run("5\n").splitlines()) == 6, "small fill"
assert run("9\n").splitlines()[0] == "3", "perfect square case"
assert run("10\n").splitlines()[0] == "4", "next square boundary"

 ## 特殊なケース

 n = 1 の場合、アルゴリズムは m = 1 を設定し、単一のセル (1, 1) を出力します。 制約に違反するペアはないため、この構造は自明に有効です。 

n = m² の場合、トラバースはグリッド全体を満たします。 すべての隣接するペアは依然として単位マンハッタン ステップによって接続されており、すべての長い距離はこれらのステップの連結によってカバーされるため、不等式はすべてのペアに当てはまります。 

完全な正方形のすぐ上の n、たとえば 10 の場合、m = 4 に移動し、最後の行を部分的に埋めます。 パス プロパティはグリッドの完全性に依存せず、連続する隣接性にのみ依存するため、切り捨てによって正確性が損なわれることはありません。
