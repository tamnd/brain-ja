 ## 問題の理解

 私たちは持っています`n`バイナリ行、それぞれの長さ`m`。 1 回の操作で 2 行と 1 列を選択し、それらの 2 行間でその列の値を交換します。 

スワップは同じ列内で発生するため、`1`行列全体の s は決して変化しません。 何が変わるかというと、`1`は行間に分散されます。 

目標は、すべての行に同じ数のデータが含まれるようにすることです。`1`s. それが不可能な場合は、出力します`-1`。 それ以外の場合は、最小操作数と目標を達成する有効なスワップ シーケンスを出力する必要があります。 

最初の観察は、`1`s は不変です。 合計数が`1`s は割り切れません`n`の場合、すべての行に同じ整数カウントが必要となるため、等化は不可能です。`1`は。 
入力サイズが大きいです。 それでも`n`そして`m`個別に到達できる`10^5`、の合計`n·m`すべてのテストケース全体で最大でも`10^6`。 これは、行列サイズにおいて線形またはほぼ線形のアルゴリズムが必要であることを強く示唆しています。 操作ごとにすべての行を繰り返しスキャンするアプローチでは、時間がかかりすぎます。 

難しいのは、解決策が存在するかどうかを判断することではありません。 課題は、最小限のスワップ数を構築することです。 

よくある間違いは、1 つの行に多すぎるものがあると考えることです。`1`s と別のものが少なすぎる場合は、いつでも を転送できます。`1`直接。 それは真実ではありません。 転送は、ドナー行が含まれている列でのみ可能です。`1`そしてレシーバー列には`0`。 

考慮する：```
2 2
1 1
1 1
```両方の行にすでに 2 つが含まれています`1`したがって、答えは操作がゼロです。 

ここで次のことを考えてみましょう。```
2 2
1 0
1 0
```の合計数`1`s は 2 なので、ターゲットは行ごとに 1 つです。 両方の行にすでに 1 つあります`1`、したがって、やはり答えはゼロです。 

行数ではなく「列のバランス」をとろうとする不注意な実装では、不必要なスワップが実行される可能性があります。 

別の微妙なケースは次のとおりです。```
2 2
1 1
0 0
```ターゲットは1人`1`行ごとに。 交換は 1 回だけ必要です。 行間で列 1 または列 2 を交換します。 2 つのスワップを使用する解決策は、最終状態では正しいですが、最小ではありません。 

最小動作要件が重要です。 

## アプローチ

 ブルートフォース戦略は、オーバーフル行とアンダーフル行を繰り返し選択し、転送可能な位置が見つかるまですべての列を検索することです。 転送のたびに、すべてを再計算して続行します。 

これは、スワップが成功するたびに不均衡が 1 ずつ減少するため、機能します。 最終的にはすべての行が目標数に達します。 

問題は効率です。 あると仮定します`O(nm)`必要な転送。 転送ごとにマトリックス全体を再度スキャンすると、複雑さはさらに大きくなる可能性があります。`O(nm·min(n,m))`さらに悪いことに、制限をはるかに超えています。 

重要な観察は、有用なスワップは常に同じに見えるということです。 

目標を超えるカウントを持つ行は、いくらかを寄付する必要があります`1`s.

 カウントがターゲットより小さい行は、何らかの値を受け取る必要があります。`1`s.

 固定列の場合、1 つの行に`1`別の列が寄付をしている間に寄付する必要があります`0`受信する必要がある場合、その列は必要な転送を 1 つだけ実行できます。 

これは、列を独立して処理することを示唆しています。 各列について、以下を収集します。 

まず、現在含まれている行`1`この列にはまだ余剰があります`1`全体的に。 

次に、現在含まれている行`0`このコラムではさらに追加が必要です`1`全体的に。 

最初のグループの 1 行と 2 番目のグループの 1 行を一致させると、有効なスワップが生成されます。 このような交換のたびに、黒字と赤字が同時に 1 つずつ減少します。 

なぜこれが最適なのでしょうか?

 各スワップでは、ちょうど 2 行のカウントが 1 単位ずつ反対方向に変更されます。 行が目標を超えた場合`d`、少なくともドナーとして参加する必要があります`d`回。 すべての余剰行を合計すると、必要な最小転送数が得られます。 私たちの構築では、転送ごとに 1 回のスワップを実行します。`1`, したがって、この下限に達します。

 ## アルゴリズムのチュートリアル

 1. マトリックスを読み取り、次の数を計算します。`1`すべての行に が表示されます。 
2. の合計数を計算します。`1`s in the matrix.
 3. 合計が割り切れない場合`n`、出力`-1`。 
4. しましょう`target = total // n`。 
5. すべての列について、2 つの一時リストを作成します。 

最初のリストには、カウントが次より大きい行が含まれています。`target`この列の値は`1`。 

2 番目のリストには、カウントが以下の行が含まれています。`target`この列の値は`0`。 
6. 2 つのリストの行を順番に照合します。 

一致した各ペアは 1 つの有効な転送を表します。 ドナーとレシーバーの間で列の値を交換します。 
7. 操作を記録した後、ドナーの行数を 1 つ減らし、レシーバーの行数を 1 つ増やします。 

十分な転送が行われると行はドナーまたはレシーバーでなくなる可能性があるため、この更新は非常に重要です。 
8. すべての列を続けます。 
9. 記録されたすべての操作を出力します。 

### なぜ効果があるのか

 しましょう`target`希望の数になる`1`すべての行に が表示されます。 

余剰のある列`s = count - target`正確に寄付しなければなりません`s`もの。 赤字の連続`d = target - count`正確に受け取らなければなりません`d`もの。 総黒字は総赤字に等しい。 

スワップを実行するときは常に、ドナーが持っている列を選択します。`1`そして受信機は`0`。 スワップ後、寄付者は 1 つを失います`1`そして受信者は1を得る`1`。 他の行数は変わりません。 

各操作により、全体の不均衡は 2 単位、つまり 1 つの黒字と 1 つの赤字によって減少します。 すべての操作で必要なものが 1 つだけ転送されるため、`1`、操作の数は総余剰に等しく、これは可能な限り最小のスワップ数です。 したがって、この構造は正確かつ最小限です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m = map(int, input().split())

        a = []
        cnt = []

        total = 0

        for _ in range(n):
            row = list(map(int, input().split()))
            a.append(row)

            s = sum(row)
            cnt.append(s)
            total += s

        if total % n != 0:
            print(-1)
            continue

        target = total // n
        ops = []

        for col in range(m):
            donors = []
            receivers = []

            for row in range(n):
                if cnt[row] > target and a[row][col] == 1:
                    donors.append(row)
                elif cnt[row] < target and a[row][col] == 0:
                    receivers.append(row)

            k = min(len(donors), len(receivers))

            for i in range(k):
                x = donors[i]
                y = receivers[i]

                cnt[x] -= 1
                cnt[y] += 1

                a[x][col] = 0
                a[y][col] = 1

                ops.append((x + 1, y + 1, col + 1))

        print(len(ops))
        for x, y, z in ops:
            print(x, y, z)

solve()
```解決策は、次の数を数えることから始まります。`1`すべての行に が表示されます。 これらの数は、誰が寄付し、誰が受け取らなければならないかを決定するために重要な唯一の数量です。 

一連のスワップによって総数が変わることはないため、割り算のチェックが最初に行われます。`1`s in the matrix.

 各列について、最新の行数を使用して現在のドナーとレシーバーを特定します。 カウントはスワップのたびにすぐに更新されます。 この詳細は不可欠です。 余剰の 3 で始まった列は、ちょうど 3 回の転送後に寄付を停止する必要があります。 

マトリックス自体も、操作のたびに更新されます。 列の値を更新しないと、後の処理で同じ値が誤って再利用される可能性があります。`1`複数回。 

記録された操作`(x+1, y+1, col+1)`ステートメントで必要な 1 から始まるインデックスに従います。
