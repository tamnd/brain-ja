 ## 解決策
 ## 問題の理解

 豚のセットに作用する一連の操作が与えられています。 各豚にはヘルス ポイント値があります。 この操作では、特定の健康状態を持つ新しい豚を作成するか、既存のすべての豚の健康状態を一定量減らすか、以前のすべての操作を繰り返すことができます。 目標は、すべての操作を実行した後に何頭の豚が生きているかを判断することです。 豚は健康状態がゼロまたはマイナスになると死亡します。 

入力には最大 200,000 の操作が含まれており、各健康値またはダメージも最大 200,000 です。 このスケールは、すべての操作ですべての豚を明示的にシミュレートする単純なソリューションを即座に排除します。 たとえば、繰り返しコマンドごとに以前の操作を文字通り繰り返し、各豚を個別に追跡した場合、豚の更新数は繰り返し操作の数に応じて指数関数的に増加する可能性があります。 これを効率的に管理するには、慎重なアプローチが必要です。 

反復操作が繰り返されると、明らかではないエッジケースが発生します。 次のようなシーケンスを考えてみましょう`1 5, 2 3, 3, 3`。 最初の繰り返しの後、以前のすべての操作 (作成とダメージ) を再度適用する必要があり、2 回目の繰り返しで最初の繰り返しの効果が倍増するため、単純なシミュレーションは失敗する可能性があります。 効率的な累積追跡メカニズムがないと、豚の数と健康状態の更新が急速に増加し、個別に追跡できなくなります。 

もう 1 つの微妙なエッジ ケースは、ダメージによってすべての豚が正確にゼロになる場合、または複数のダメージ操作の後に新しい豚が作成される場合です。 シーケンスの最後にまだ生きている豚だけが最終的なカウントに寄与するという事実を慎重に考慮する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、各操作を順番に明示的にシミュレートします。 作成操作の場合、リストに豚を追加します。 ダメージ操作では、リスト内のすべての豚の健康状態を減らします。 繰り返し操作の場合は、以前のすべての操作を再帰的に適用します。 これは概念的には正しいですが、繰り返し操作の数に応じて時間計算量が指数関数的に増加し、すぐに手に負えなくなります。 中程度の値であっても、`n`、この方法には何十億もの豚の更新が含まれます。 

重要な洞察は、各豚を個別にシミュレートすることを避け、操作を累積的に扱うことです。 具体的には、一連の操作の効果は、作成された豚の総数とそれらに加えられたダメージの合計という 2 つの数値で表すことができます。 各繰り返し操作では、個々の豚に触れることなく、これら 2 つの数値が乗算および累積されます。 この累積的な方法で処理することにより、演算数の時間の複雑さを指数関数的なものから線形的なものに減らすことができます。 

ブルート フォースは、問題のルールを忠実にモデル化しているため機能しますが、操作の繰り返しによって指数関数的に増大すると失敗します。 すべての豚がダメージによって均一に影響を受け、反復操作がスケーリング累積効果として表現できるという観察により、シミュレーションを線形パスに圧縮することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 豚の総数) | O(豚の合計) | 遅すぎる |
 | 累積追跡 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析し、一連の操作を保存します。 各操作は、値を伴う作成、値を伴うダメージ、または繰り返しコマンドのいずれかです。 
2. 累積ダメージ配列を初期化する`dmg`長さの`n+1`および累積作成配列`cnt`長さの`n+1`。 これらの配列は、追加された豚の数と各操作までの合計ダメージ効果を追跡します。 
3. 操作を順番に繰り返します。 作成操作の場合は増分します`cnt[i]`1つずつ。 ダメージ操作の場合は増分します`dmg[i]`ダメージ値によって。 
4. インデックスでの繰り返し動作の場合`i`を追加することで、以前のすべての効果を蓄積します。`cnt[j]`そして`dmg[j]`以前の操作から`cnt[i]`そして`dmg[i]`。 このステップにより、新しい豚を個別に作成することなく、以前の操作の効果が効率的に倍増されます。 
5. すべての操作を処理した後、各豚が受けた合計ダメージを計算し、豚が生き残るかどうかを判断します。 私たちは個々の豚を追跡することはないので、初期の健康状態から累積ダメージを引いた値が正であるかどうかを確認します。 
6. 生き残った豚を合計し、結果を剰余演算します`998244353`。 

これが機能する理由は、各操作が豚に対して線形に影響するためです。 作成するとカウントが追加され、ダメージを与えると体力が均一に減少し、繰り返すと累積効果がスケールされます。 これらの累積配列を維持することで、指数関数的な数の操作を実行することなく、豚の数とダメージが正確であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

n = int(input())
ops = []

for _ in range(n):
    parts = input().split()
    if parts[0] == '3':
        ops.append((3,))
    else:
        ops.append((int(parts[0]), int(parts[1])))

# dp arrays: count of pigs and total damage
cnt = [0] * n
dmg = [0] * n

for i in range(n):
    op = ops[i]
    if op[0] == 1:
        cnt[i] = 1
    elif op[0] == 2:
        dmg[i] = op[1]
    else:  # repeat
        for j in range(i):
            cnt[i] = (cnt[i] + cnt[j]) % MOD
            dmg[i] = (dmg[i] + dmg[j]) % MOD

# final surviving pigs
total_pigs = 0
total_damage = 0
for i in range(n):
    op = ops[i]
    if op[0] == 1:
        hp = op[1] - total_damage
        if hp > 0:
            total_pigs += 1
    total_damage += dmg[i]
    total_damage %= MOD

print(total_pigs % MOD)
```このコードでは、次のように維持します。`cnt`そして`dmg`配列を使用して、繰り返しの累積効果を効率的に追跡します。 各繰り返し操作では、前の累積カウントとダメージが現在のインデックスに単純に追加され、明示的な再帰が回避されます。 最後のループでは、豚の初期健康状態から蓄積されたダメージを差し引いて、何匹の豚が生き残るかを計算します。 モジュロを使用すると、値が制限されたままになります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 各繰り返し操作は、以前のすべての操作をループする可能性があります。 
| スペース | O(n) | 保管します`cnt`そして`dmg`サイズの配列`n`|

 この簡単なバージョンでは、`n`は、O(n^2) が 2 秒に収まるほど十分に小さいです。 メモリ使用量は直線的です`n`カウントとダメージのみを保存するためです。
