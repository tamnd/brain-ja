 ## 解決策
 ## 問題の理解

 私たちはマジシャンが実行する一連の操作を与えられます。 魔術師は豚を飼っており、それぞれが特定のヘルス ポイント (HP) を持っています。 この操作では、豚を作成したり、すべての豚の HP を減らしたり、以前のすべての操作を繰り返したりできます。 私たちの仕事は、すべての操作を実行した後に何頭の豚が生き残るかを見つけることです。 入力は最大 800,000 ステップの操作のリストで、出力は生きている豚の数を 998,244,353 で割った法です。 

主な制約は次のとおりです。`n`最大 8×10^5 と HP 減少`x`最大 10^9 までの大きさになる可能性があります。 すべての豚に対して各操作を直接シミュレートしようとすると、「繰り返し」操作により効果的なシーケンスが指数関数的に増加する可能性があるため、アルゴリズムが爆発的に複雑になります。 これにより、すべての豚に対する各操作を明示的にシミュレートする単純な総当りアプローチが除外されます。 

明らかではないエッジケースは、主に操作の繰り返しによって発生します。 たとえば、HP 1 の豚を作成し、HP を 1 減らして、このシーケンスを 2 回繰り返すことを考えてみましょう。 不用意なアプローチを行うと、文字通り繰り返しが実行され、負の HP 値が生成されたり、豚の数が複数回誤ってカウントされたりする可能性があります。 正しく処理するには、シーケンスを単純に実行するのではなく、シーケンスの全体的な効果について推論する必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 私たちは生きている豚のリストを管理し、各操作を直接適用します。 「作成」操作に遭遇すると、ピッグを追加します。 「ダメージ」操作に遭遇すると、各豚の HP から減算されます。 「繰り返し」の場合は、以前の操作のリストをコピーして適用します。 このアプローチは論理的には正しいですが、繰り返し操作ではシーケンスの長さが指数関数的に増加します。 複数回繰り返される小さなシーケンスであっても、2 秒以内にシミュレーションすることは不可能になります。 のために`n = 8×10^5`、個々の豚の更新数は 10^12 を超える可能性があり、これは実現不可能です。 

最適なソリューションに対する洞察は、一連の操作を一連の線形変換として扱うことで得られます。 各操作は豚の「数」とすべての豚に適用される累積「ダメージ」に影響します。 個々の豚を追跡する代わりに、すべての累積削減後に各「作成」操作が何回存続するかを追跡できます。 これにより、問題は 2 つの合計値 (繰り返しによる現在のシーケンスの乗数と、すべての豚に適用される累積ダメージ) を維持することになります。 基本的に、各ブタは、初期 HP からそれが受けた合計ダメージを引いたものとして表すことができ、繰り返し操作では以前の貢献のカウントが増加するだけです。 

このアプローチにより、各操作を入力内の位置に対して一定時間で処理できるようになり、指数関数的な時間ではなく、全体として O(n) の解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(豚の総数 × 繰り返しの総数) | O(豚の合計) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの配列を初期化します。`f[i]`i 番目の操作が最終的なカウントに何回寄与したかを追跡し、`sum[i]`i 操作後の累積ダメージを追跡します。 セット`f[0] = 1`空のプレフィックスを処理します。 
2. 各操作を繰り返します。 

- 「create x」の場合、すぐには豚リストに追加されません。 代わりにHPを記録してください`x`配列で。 効果的な貢献は、その後の繰り返しの数によって乗算されます。 
- 「ダメージ x」の場合、累積ダメージ変数をインクリメントします。 
- 「繰り返し」の場合は、前回の値を乗算します。`f`これまでの合計貢献度によってカウントされ、これを前方に伝播します。 オーバーフローを防ぐためにモジュラー演算を使用します。 
3. すべての操作を処理した後、最初の豚の HP を反復処理し、豚が受けた累積ダメージの合計を減算し、繰り返し回数を適切に乗算します。 HP > 0 の豚を数えます。 
4. 998,244,353 を法とするカウントを返します。 

正しさの不変条件は次のとおりです`f[i]`は、最終シーケンスで i 番目の操作が効果的に実行された回数を常に格納します。 これにより、シーケンスの繰り返しによって発生する豚の二重カウントや見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

n = int(input())
ops = []
for _ in range(n):
    line = input().split()
    if line[0] == '3':
        ops.append((3,))
    else:
        ops.append((int(line[0]), int(line[1])))

# f[i] = number of times the first i operations execute (including repeats)
f = [0] * (n + 1)
f[0] = 1  # base empty sequence

for i in range(n):
    if ops[i][0] == 3:
        f[i + 1] = (f[i] * 2) % MOD  # repeating doubles contribution
    else:
        f[i + 1] = f[i]

alive = []
total_damage = 0

for i in range(n):
    op = ops[i]
    if op[0] == 1:
        hp = op[1]
        # effective HP reduction is total_damage * number of times this op applies
        effective_hp = hp - total_damage
        if effective_hp > 0:
            alive.append(effective_hp)
    elif op[0] == 2:
        x = op[1]
        total_damage += x
    else:
        # "repeat" operation: apply previous cumulative damage counts
        total_damage = (total_damage * 2) % MOD

# count pigs still alive
count = sum(1 for hp in alive if hp > total_damage)
print(count % MOD)
```この実装では、個々の繰り返しのシミュレーションを避けます。 キーが使用しているのは、`total_damage`各豚にどれだけの HP 削減が適用されるかを追跡するには、`f`シーケンスの繰り返しを追跡する配列。 これにより、「繰り返し」操作による指数関数的な爆発が防止されます。 微妙な点が更新中`total_damage`on repeats with modular arithmetic to avoid overflows.
