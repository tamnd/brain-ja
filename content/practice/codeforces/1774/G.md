 ## 解決策
 ## 問題の理解

 巨大な数直線上の間隔の集合と、それぞれが固定された目標間隔について尋ねる多くのクエリが与えられます。$[l, r]$。 各クエリについて、和集合が正確に一致する指定された間隔のすべてのサブセットを調べます。$[l, r]$、内部のすべての点を意味します$[l, r]$は覆われており、外側は何も覆われていません。 

各有効なサブセットは、サイズが偶数であるか奇数であるかに応じて +1 または -1 のいずれかを与え、クエリはすべての有効なサブセットの符号付き合計を要求します。 

タスクを再解釈する便利な方法は、各クエリで、利用可能な間隔を使用して、セグメントのすべての正確なカバーのパリティ加重カウントを要求することです。 

制約により、ほぼ線形または$O((m+q)\log m)$行動。 まで$2 \cdot 10^5$セグメントやクエリ、サブセットの列挙、さらにはサブセットに対する動的プログラミングを伴うものは、直ちに不可能になります。 クエリごとの間隔グラフを構築する場合でも、大幅に償却または前処理しない限り、時間がかかりすぎます。 

複数の異なるサブセットが同じ結合を生成する場合、微妙なエッジ ケースが発生します。 たとえば、間隔が重なり合う場合、キャンセルを注意深く追跡しない限り、サブセットに対する単純な包含/除外により、構成が誤って二重カウントされる傾向があります。 もう 1 つの障害モードは、最小限の範囲のみが重要であると想定していることです。 たとえば、セグメントを 2 つの方法でカバーできるが、両方の方法に冗長な間隔が含まれている場合、両方とも寄与し続けますが、パリティに応じてキャンセルされる可能性があります。 

重要な問題は、答えはカバーのカウントではなく、署名されたカウントであるということであり、これは強力なキャンセル構造を示唆しています。 

## アプローチ

 ブルートフォースのアイデアは簡単です。クエリごとに、クエリのすべてのサブセットを列挙します。$m$セグメント、それらの和集合が等しいかどうかを確認します$[l, r]$、サブセットのサイズに応じて符号を付けてカウントします。 これは正しいですが、指数関数的に複雑になります$O(2^m)$クエリごとに、これは非常に小さい場合でも不可能です$m$。 

Even improving this to “only consider segments intersecting$[l, r]$」は、最悪の場合、すべてのセグメントがクエリ範囲と重複するため、あまり役に立ちません。本当の問題は、候補サブセット自体の数が指数関数的であることです。 

重要な観察は、答えが区間カバーにわたる母関数の係数であるということです。 サブセットを列挙する代わりに、セグメントが点にどのように重なるかについて構造化された包含/除外を計算したいと考えています。 The signed nature$f-g$各セグメントを次の重みで置き換えることを強く示唆しています。$-1$そして、独立したコンポーネントに対して製品のような構造を計算します。 

正しい観点は、端点上でスイープライン方式で区間を処理し、実線を関連する座標に圧縮することです。 次に、各クエリは、すべての位置にアクティブな「選択肢」がいくつ存在するかを追跡する構造に対する範囲クエリになり、符号付きカウントは独立したカバレッジ決定の積になります。 組み合わせキャンセルにより、各ポイントがカバーするセグメントの数に応じて乗算係数に寄与するという方法で、間隔の寄与を維持するという問題が軽減されますが、これはカバレッジ構造がクエリ間隔全体にわたって一貫している場合に限ります。 

これにより、座標圧縮 + セグメント イベント処理 + コントリビューションのプレフィックス蓄積に基づくソリューションが得られ、前処理後に対数または定数時間で各クエリに応答できるようになります。

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、問題をサブセットの列挙から区間カバレッジの移行にわたる構造的な計数問題に変換することです。 

1. すべての間隔のエンドポイントを収集し、それらを並べ替えられた座標系に圧縮します。 これが必要なのは、カバレッジにおけるすべての意味のある変更はセグメントのエンドポイントでのみ発生し、エンドポイント間の構造は一定であるためです。 
2. 現在アクティブなセグメントの数を維持しながら、これらの圧縮された座標上にスイープ ラインを作成します。 ある座標から次の座標に移動すると、どのセグメントが開始または終了するのかが正確にわかります。 
3. 連続する座標間の各基本セグメントについて、そのスライス上の正確なカバレッジの一貫性を維持するセグメントを選択するための選択肢がいくつ存在するかを表すローカル寄与を計算します。 問題の符号付きの性質は、アクティブな各セグメントが次の要因に寄与することを意味します。$-1$関数項を生成する際には乗算的に累積します。 
4. これらの基本セグメントに対してプレフィックス積配列を事前計算します。 各プレフィックス値は、開始点からその座標までの範囲を完全にカバーする符号付き寄与度の合計を表します。 
5. 質問に答えるため$[l, r]$、それを圧縮座標にマッピングし、次のプレフィックス値の比率を計算します。$r$そして$l$。 これが機能するのは、寄与分が独立したセグメントにわたって因数分解され、キャンセルによってグローバルに一貫したカバーのみが確実に残るためです。 
6. 結果のモジュロを返します$998244353$、プレフィックス積を分割するときはモジュラー逆数を使用するように注意してください。 

実装の重要な詳細は、接頭辞積が生の座標ではなく、_カバレッジ一貫性のあるセル_上で定義されていることを確認することです。そうしないと、重複する間隔が誤ってカウントされます。 

### なぜ効果があるのか

 このアルゴリズムは、任意のサブセットの符号付き寄与が、ソートされたエンドポイントによって形成される互いに素な基本セグメント全体にわたって因数分解されるという不変式に依存します。 各基本セグメントは完全にカバーされているか、カバーされていないかのいずれかであり、一連の間隔を選択することによる影響は、これらのセグメントにわたる独立した乗法選択に分解されます。 サイン$(-1)^{|S|}$サブセットが積展開内の単項式に対応することを保証し、Exact-cover 制約によりすべての無効な構成が強制的にキャンセルされます。 その結果、プレフィックス積は有効なカバーリングの完全な生成関数をエンコードし、クエリの応答はプレフィックス状態の差になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    m, q = map(int, input().split())
    segs = [tuple(map(int, input().split())) for _ in range(m)]
    
    coords = set()
    for x, y in segs:
        coords.add(x)
        coords.add(y)
    
    queries = []
    for _ in range(q):
        l, r = map(int, input().split())
        queries.append((l, r))
        coords.add(l)
        coords.add(r)
    
    coords = sorted(coords)
    idx = {v:i for i, v in enumerate(coords)}
    
    n = len(coords)
    
    start = [[] for _ in range(n)]
    end = [[] for _ in range(n)]
    
    for x, y in segs:
        start[idx[x]].append(idx[y])
        end[idx[y]].append(idx[x])
    
    active = 0
    pref = [1] * n
    
    # sweep over compressed points
    for i in range(n - 1):
        for _ in start[i]:
            active += 1
        for _ in end[i]:
            active -= 1
        
        length = coords[i + 1] - coords[i]
        if length > 0:
            # each active segment contributes a factor (-1)
            pref[i + 1] = pref[i] * pow(-1, active, MOD) % MOD
        else:
            pref[i + 1] = pref[i]
    
    out = []
    for l, r in queries:
        li = idx[l]
        ri = idx[r]
        ans = pref[ri] * modinv(pref[li]) % MOD
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```コードは最初に座標を圧縮して、間隔構造のすべての変更が局所化されるようにします。 次に、左から右にスイープし、現在アクティブなセグメントの数を維持します。 基本間隔ごとに、実行中の積に、その時点でアクティブなセグメントの数によって決定される寄与を乗算し、パリティ重み付けされた選択構造をエンコードします。 

最後に、各クエリはプレフィックス値を分割することによって回答されます。これは、プレフィックス値間の寄与が次のとおりであるという事実に基づいています。$l$そして$r$独立した乗算ブロックを形成します。 

実装上の微妙な問題は、モジュラー逆変換です。プレフィックス積を分割するため、モジュロでフェルマー逆変換を使用する必要があります。$998244353$。 もう 1 つの問題は、すべての座標境界が確実に含まれるようにすることです。そうしないと、クエリがセグメント構造と一致しなくなります。

 ## 特殊なケース

 重要なエッジ ケースは、セグメントがエンドポイントでのみ接触する場合です。$[1,3]$そして$[3,5]$。 スイープ ラインはこれらを個別のアクティブ化間隔として扱いますが、結合は依然として連続しています。 座標圧縮により点が保証されるため、アルゴリズムはこれを正しく処理します。$3$は明示的に境界であるため、カバレッジの遷移によって誤ってギャップが作成されることはありません。 

もう 1 つの特殊なケースは、多数の同じ長さの重複セグメントです。 たとえば、次の 5 つのコピー$[1,2]$。 内部のすべてのポイントでアクティブ カウントは 5 であるため、寄与は符号内で振動し、プレフィックスの蓄積により自然にキャンセルが発生し、偶数/奇数のサブセットがバランスするという事実と一致します。 

最後のエッジケースは、クエリが単一セグメントのエンドポイント間隔に正確に一致する場合です。 クエリは生の算術演算ではなく圧縮されたインデックスに基づいて評価されるため、両方のエンドポイントが同じ構造ブロックに含まれ、プレフィックス除算で 1 によるオフの不一致が発生しないことが保証されます。
