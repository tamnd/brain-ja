 ## 解決策
 ## 問題の理解

 ノードにルートを持つルート付きツリーがあります`1`。 

2 つのチェスの駒はルートから始まります。 ピース A は、指定されたセットのすべてのノードを訪問する必要があります`A`、ピース B は別のセットのすべてのノードにアクセスする必要があります`B`。 順序は任意です。 必要な訪問がすべて完了したら、両方の部分がルートに戻る必要があります。 

移動は、木の 1 つの端を越えて正確に 1 つのピースを移動することで構成されます。 プロセス全体を通じて、2 つのピース間の距離がこれを超えることは決して許可されません。`d`。 

タスクは、最小合計移動数を見つけることです。 

ツリーには以下が含まれます`2 · 10^5`頂点。 頂点のペアを調べたり、グラフ検索を繰り返し実行したり、ノードごとにサブツリーのサイズに比例した作業を実行したりするソリューションは、非常に遅すぎます。 この入力サイズでは、`O(n)`または`O(n log n)`解決。 

微妙な部分は距離制限です。 それがなければ、2 つの部分は完全に独立しています。 これを使用すると、必要な頂点がそこにない場合でも、単に他のピースに十分近くにとどまるために、ピースがサブツリーに入ることを強制される可能性があります。 

パスを検討する`1 - 2 - 3 - 4`と`d = 2`。 ピース A がノードにアクセスする必要があるとします。`4`ピース B にはルートのみが必要です。 

素朴なアプローチでは、部分 B はルートから離れる必要はないと言えるかもしれません。 それは不可能です。 ピースAがノードに到達したとき`4`、ルートからの距離は次のようになります。`3`を超える`d`。 ピース B はノードまで下に移動する必要があります`2`一方、A はパスのより深い部分を探索します。 距離の制約により、追加の強制的な移動が発生します。 

もう 1 つの簡単な間違いは、必要な頂点のみが重要であると想定することです。 仮定する`d = 2`およびピース A はノードを訪問する必要があります`5`長い鎖の中で。 ピース B のブランチに必要な頂点がない場合でも、A が深すぎるため、いくつかの中間頂点を入力する必要がある場合があります。 これらの頂点は答えに寄与するため、無視することはできません。 

## アプローチ

 ブルートフォースビューとは、システムの完全な状態を考えることです。 

状態には、両方のピースの位置と、各ピースがすでに訪問している必要な頂点のセットが含まれます。 この巨大な状態グラフで最短経路探索を実行できます。 定式化は正しいですが、小さなツリーであっても状態の数は爆発的に増加します。 まで`2 · 10^5`頂点、これは完全に不可能です。 

重要な観察は、単一の部分を見ることから得られます。 

距離制限がなかったと仮定します。 次に、ピースは、ルートとその必要なすべての頂点を接続する最小限のルート付きサブツリーをトラバースするだけで済みます。 そのサブツリーのすべてのエッジは、1 回は下り、もう 1 回は上りと、正確に 2 回トラバースされます。 

ここで距離制限を再導入します。 

いくつかのノードを取得します`u`。 ピース A のサブツリー内に必要な頂点がないことを想像してください。`u`。 通常、A はそのサブツリーに入ることはありません。 A が依然としてそれに入力する必要がある唯一の理由は、B がそこにある深い必要な頂点を探索するときにピース B に付随するためです。 

A が助けざるを得なくなるまでに、B はどのくらい深く潜らなければなりませんか?

 B に必要な頂点が内側にある場合`u`のサブツリーは深さにあります`mxB`、B がその頂点に到達すると、A はその頂点に留まることができます。`u`場合のみ`mxB - depth(u) ≤ d - 1`。 

そうしないと距離が超えてしまいます`d`, したがって、A も経由して入力する必要があります。`u`。 

これにより、問題はすべての頂点に対する純粋に局所的な状態になります。 

各ノードについて、そのサブツリー内の各タイプの最も深い必要な頂点を知る必要があります。 それらの深さがわかったら、各ピースがそのノードにアクセスする必要があるかどうかを決定できます。 

最終的なソリューションは、ツリー上の単一の DFS になります。

 ## アルゴリズムのチュートリアル

 1. ノードでツリーをルート化します`1`そしてすべてのノードの深さを計算します。 
2. すべてのノードについて`u`、 維持する：`mxA[u]`= サブツリー内の A に必要な頂点の最大深さ`u`。`mxB[u]`= サブツリー内の任意の B 要求頂点の最大深さ`u`。 

そのような頂点が存在しない場合、値は次のようになります。`0`。 
3. ポストオーダー DFS を使用してこれらの値を計算します。 

もし`u`それ自体はセット A に属しており、初期化します`mxA[u] = depth[u]`。 

もし`u`それ自体はセット B に属しており、初期化します`mxB[u] = depth[u]`。 

次に、最大値を取得して子からの情報をマージします。 
4. 両方のピースがルート以外のすべての頂点を訪問する必要があるという仮定の状況から開始します。 

次に、各木の端が各部分によって 2 回横断されます。 

最初の答えは`4 · (n - 1)`。 
5. ピース A に実際にノードが必要かどうかを判断する`u`。 

必見の作品`u`いずれかの場合:

 - そのサブツリーに A に必要な頂点があり、これは意味します`mxA[u] > 0`、または
 - ピース B には距離よりも深い必要な頂点があります`d - 1`下に`u`、 意味`mxB[u] - depth[u] >= d`。 

どちらの条件も当てはまらない場合、A は通過する必要はありません。`u`。 

その場合、エッジ上の A の往復コストを次から削除します。`u`親に減算する`2`答えから。 
6. ピース B に対称ルールを適用します。 

もし`mxB[u] == 0`そして`mxA[u] - depth[u] < d`B はノードを必要としません`u`なので、さらにもう1つ差し引きます`2`。 
7. すべての非ルート ノードをこの方法で処理します。 残りの値は最小手数です。 

### なぜ効果があるのか

 ピースがエッジを通過してサブツリーになるには、理由がある必要があります。 

考えられる最初の理由は明らかです。サブツリーには、それ自体に必要な頂点の 1 つが含まれています。 

2 番目の理由は、距離の制限にあります。 他のピースが少なくとも必要な頂点に到達する必要がある場合`d`現在のノードの下のレベルにある場合、サブツリーの外側に留まると、最大許容距離に違反します。 そのノードから入ることが必須になります。 

ピースがエッジを越える必要がある理由はこの 2 つだけです。 

両方の部分がすべてのエッジを 2 回横断するという仮定から開始して、可能なすべての横断をカウントします。 各ピースと各ノードについて、決して必要とされないトラバースを正確に削除します。 DFS はどのノードが引き続き必要であるかを正確に計算するため、結果の合計が最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 20)

n, d = map(int, input().split())

g = [[] for _ in range(n + 1)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

needA = [False] * (n + 1)
needB = [False] * (n + 1)

arr = list(map(int, input().split()))
for x in arr[1:]:
    needA[x] = True

arr = list(map(int, input().split()))
for x in arr[1:]:
    needB[x] = True

depth = [0] * (n + 1)
mxA = [0] * (n + 1)
mxB = [0] * (n + 1)

ans = 4 * (n - 1)

def dfs(u, p):
    global ans

    if needA[u]:
        mxA[u] = depth[u]

    if needB[u]:
        mxB[u] = depth[u]

    for v in g[u]:
        if v == p:
            continue

        depth[v] = depth[u] + 1
        dfs(v, u)

        mxA[u] = max(mxA[u], mxA[v])
        mxB[u] = max(mxB[u], mxB[v])

    if u != 1:
        if mxA[u] == 0 and mxB[u] - depth[u] < d:
            ans -= 2

        if mxB[u] == 0 and mxA[u] - depth[u] < d:
            ans -= 2

dfs(1, 0)

print(ans)
```DFS は 3 つの情報を同時に計算します。 

の`depth`配列はルートからの距離を示します。 配列`mxA`そして`mxB`各タイプの必要な最も深い頂点をすべてのサブツリー内に格納します。 

最初の答えは、各部分がツリー全体の完全な DFS ツアーを実行することを前提としています。 それには費用がかかります`2(n - 1)`ピースごとに移動するため、`4(n - 1)`合計で。 

サブツリーを処理すると、その部分にその部分を入力する理由があるかどうかがわかります。 そうでない場合は、そのサブツリーをその親に接続するエッジを横切るちょうど 1 ラウンド トリップを削除します。 往復が貢献します`2`動き、引き算を説明します。 

ルートには親エッジがないため、別個に扱われます。 ルートを減算すると、存在しない動きが誤って削除されてしまいます。 

すべての算術演算は Python の整数に簡単に適合します。 考えられる最大の答えは、`4(n - 1)`, これは100万を下回ります。
