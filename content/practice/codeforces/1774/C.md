 ## 解決策
 ## 問題の理解

 1 から 1 までの番号が付けられたプレーヤーによるトーナメントがあります。$n$、各プレイヤーは自分の番号に等しい「温度」を持っています。 戦闘は 0 または 1 とラベル付けされた環境で行われます。環境 0 では温度の低いプレイヤーが勝ち、環境 1 では温度の高いプレイヤーが勝ちます。 環境のシーケンスは文字列として与えられます。$s$長さの$n-1$、各戦闘の結果ルールを順番に指定します。 

それぞれについて$x$2から$n$、プレイヤーの数を決定するように求められます。$[1,x]$全員参加すれば勝てるかもしれない。 重要なのは、戦いは任意の順序で配置できるため、最後に残ったプレーヤーとして残る排除順序が少なくとも 1 つ存在する場合、プレーヤーには勝つチャンスがあります。 

制約により許可されるのは、$n$まで$2 \cdot 10^5$テスト ケースごとに、すべてのテスト ケースの合計を最大で$3 \cdot 10^5$。 これにより、可能なシーケンスの数は階乗的に増加するため、すべての戦闘または除去のすべての順列をシミュレートするアプローチは除外されます。 ソリューションは、テスト ケースごとに線形または線形演算時間で実行する必要があります。 

明らかではないエッジ ケースには、エクストリーム プレーヤーが優勢な「0000」や「1111」などの文字列や、除去順序によってはミッドレンジ プレーヤーが勝者になる可能性がある「0101」などの交互パターンが含まれます。 最初または最後の環境のみをチェックする単純な貪欲なアプローチでは、これらの可能性を逃してしまいます。 

## アプローチ

 ブルートフォース手法では、プレイヤーのサブセットごとに試合のすべての順列をシミュレートし、誰が勝つ可能性があるかをチェックします。 これは正しいですが、順列の数はプレイヤー数の因数分解であり、天文学的な操作数につながるため、実行不可能です。$n\sim10^5$。 

重要な洞察は、プレイヤーが勝つチャンスを得るためには、厳密に強いまたは弱い対戦相手が最初にプレイヤーを排除する可能性がある一連の戦闘をすべて生き残る必要があるという観察から得られます。 これにより、問題は組み合わせ特性に帰着します。つまり、プレイヤーが勝つことができるのは、プレイヤーがプレイヤー リストの先頭または末尾の連続セグメントの一部であり、連続するすべての環境タイプによって即座に排除されない場合に限られます。 具体的には、左から右に向かって先頭で終わる連続 0 の長さを数え、右から左に最後のプレイヤーで終わる連続 1 の長さを数えることができます。 これによりそれぞれが決まります$x$最低気温または最高気温のプレーヤーのうち何人が勝者になれるか。 

トーナメントでは戦いの順序を柔軟に選択でき、環境は隣接するプレイヤーの相対的な生存にのみ影響を与えるため、ブルート フォースからリニア スキャンへの変更は正当化されます。 最大の接頭辞 0 と接尾辞 1 をカウントすると、最適に戦えば生き残れる可能性のあるすべてのプレイヤーが捕捉されます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n$および環境文字列$s$。 
3. 配列を初期化する`res`サイズの$n+1$それぞれの潜在的な勝者の数を保存する$x$。 
4. プレイヤーの最小サブセットから始めます。 誰でも簡単に勝つことができます。 
5. プレイヤーごとに$i$左から右に、その前に連続する 0 が何個あるか数えます。 これにより、低温に適した環境で生き残ることができる低温プレーヤーが特定されます。 
6. 各プレイヤーについて$i$右から左に、その後に 1 が何回連続して現れるかを数えます。 これにより、高温に適した環境で生き残ることができる高温プレイヤーが識別されます。 
7. それぞれについて$x$2から$n$、左側の 0 プレフィックスと右側の 1 サフィックスからのカウントに、境界にあるプレーヤーの 1 を加えたものを合計します。 これにより、次の中で勝つ可能性のあるプレイヤーの総数が得られます。$[1,x]$。 
8. 結果を出力します。 

機能する理由: これらの連続セグメント外のプレイヤーは、戦闘順序に関係なく敗退を避けることはできません。 プレフィックスの最大値が 0 であるため、体格の大きなプレイヤーを最初に排除することで、最も小さなプレイヤーが勝つことができます。 最大のサフィックスが 1 であるため、最初に小さいプレーヤーを排除することで、最大のプレーヤーが勝つことができます。 これらのセグメントをカウントすると、各サブセットの潜在的な勝者がすべて捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        ans = [0]*(n+2)

        # Compute left-to-right 0-prefix counts
        left = [0]*(n+1)
        for i in range(n-1):
            if s[i] == '0':
                left[i+1] = left[i]+1
            else:
                left[i+1] = 0

        # Compute right-to-left 1-suffix counts
        right = [0]*(n+1)
        for i in range(n-2,-1,-1):
            if s[i] == '1':
                right[i+1] = right[i+2]+1
            else:
                right[i+1] = 0

        res = []
        for x in range(2,n+1):
            low = left[x-1]
            high = right[n-x+1]
            res.append(low + high + 1)
        print(' '.join(map(str,res)))

if __name__ == "__main__":
    solve()
```左側の配列は、最小のプレイヤーが生き残ることを可能にする先行する 0 の数をカウントします。 右側の配列は、最大のプレーヤーが生き残ることを可能にする後続の 1 の数をカウントします。 合計に 1 を加えた値が境界プレイヤーをカウントし、勝者となる可能性のある正確な数が得られます。

 ## 特殊なケース

 のような入力の場合`3\n11\n`、プレーヤー 2 と 3 が参加します。 右側のサフィックス 1 は最後のプレイヤーと次のプレイヤーの両方をカウントし、プレイヤー 3 が勝つことを正しく許可しますが、プレイヤー 2 は勝つことができません。 このアルゴリズムは、環境文字列の長さが 1 の場合でも左右のカウントを正しく計算し、off-by-one エラーを回避します。 最小と最大のすべてにおいて$n$シナリオでは、スキャン境界がインデックスを正確に処理し、正確さを確認します。
