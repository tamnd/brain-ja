 ## 解決策
 ## 問題の理解

 1 から 1 までの番号が振られたカードのデッキが与えられます。$n$、そして特定の値が最大になるようにこれらの数値の順列を構築するように求められます。 順列の値は、長さの連続する部分配列の最小合計として定義されます。$k$。 より簡単に言うと、すべての連続したシーケンスを調べます。$k$カードの数字を合計し、これらの合計の最小値を取得します。 この最小の合計をできるだけ大きくする順列を選択したいと考えています。 

入力は複数のテスト ケースで構成されます。 テスト ケースごとに 2 つの整数を受け取ります。$n$そして$k$、 どこ$n$は順列のサイズであり、$k$合計を計算するために使用されるウィンドウの長さです。 出力では、可能な最大値が得られ、その後にそれを達成する順列が続く必要があります。 以来$n$まで行くことができます$10^5$と合計$n$テストケース全体では$2 \cdot 10^6$、どのソリューションもテスト ケースごとにほぼ直線的な時間で実行する必要があります。$O(n^2)$または、完全な総当たりアプローチは実行不可能です。 

明らかではないエッジケースが発生するのは次の場合です。$k$より 1 つだけ少ないです$n$。 このようなシナリオでは、合計は 2 つだけ可能です。$k$要素と最後$k$要素。 最初に大きな数値を配置するだけの単純なアルゴリズムでは、これら 2 つの重要なウィンドウのいずれかに小さな数値が残る可能性があるため、最小合計を最大化できない可能性があります。 

## アプローチ

 ブルートフォースアプローチは、すべてを生成することです。$n!$順列、長さの各ウィンドウの合計を計算します$k$各順列について、最大最小合計を持つものを追跡します。 これは正しいですが、制約内では不可能です。$n=10$作る$10!$許容される操作をはるかに超えた順列$n=10^5$。 

重要な洞察は、最小合計が最後の金額によって制御されることを認識することです。$k$どのウィンドウにも表示される数字。 問題は最大値の合計を最大化することになります。$k$隣接するウィンドウ内の要素。 最大の数値を配列のできるだけ後ろに、ただしすべてのウィンドウが大きな数値と十分にオーバーラップする順序で配置すると、最小ウィンドウの合計が最大になります。 実際には、これは最高の位置に配置することで達成できます。$k-1$順列の最後にある数値を降順で並べ、残りを任意の順序で小さい数値で埋めます。 最小合計は最大合計の合計になります。$k-1$数値に、そのクリティカル ウィンドウの前面にある次に大きい数値を加えたものです。 

この観察により、線形時間で直接解を構築できます。順列をテストすることなく、どの数値がどの位置に入るのかがわかります。

 ## アルゴリズムのチュートリアル

 1. 達成可能な最大値を計算することから始めます。 これは単に最大値の合計です$k$セット内の数字$[1, n]$。 この合計を次のように表します$S = n + (n-1) + \dots + (n-k+1)$。 
2. サイズの空の置換配列を初期化します。$n$。 
3. 一番大きなものを配置します$k-1$順列の最後の番号を降順に並べます。 これにより、最後のウィンドウを含むすべてのウィンドウが$k-1$要素の合計は大きくなります。 
4. 残りを埋めます$n-(k-1)$残りの最小番号が昇順で開始位置に配置されます。 これにより、最小合計を決定するウィンドウから小さな数値が遠ざけられます。 
5. 計算された最大値を出力します$S$構築された順列が続きます。 

これが機能する理由: 不変条件は、最小ウィンドウ合計には常に最大ウィンドウの少なくとも 1 つが含まれるということです。$k$最後だから数字$k-1$末尾に数字が連続します。 これらを含まないウィンドウは、合計は小さくなりますが、含まれる数値は$k$- 番目に大きい。これは、前セクションに次に大きい数値を含めることですでに説明されています。 これにより、他の順列がこれより高い最小合計を生成できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        # Maximum value is the sum of largest k numbers
        max_val = sum(range(n, n-k, -1))
        # Construct the permutation
        perm = list(range(1, n-k+1)) + list(range(n, n-k, -1))
        print(max_val)
        print(" ".join(map(str, perm)))

if __name__ == "__main__":
    solve()
```このソリューションは、テスト ケースの数を読み取ることから始まり、テスト ケースをループします。 それぞれのケースについて、最大の合計を計算します。$k$単純な算術範囲を使用した数値。 順列は、小さい数値の昇順と最大の数値の降順を連結することによって構築されます。 これにより、範囲を慎重に定義することで、off-by-one エラーが回避されます。`range(1, n-k+1)`少数の場合と`range(n, n-k, -1)`大きいもののために。 整数をスペースで区切られた文字列に結合すると、印刷が簡単になります。 

## 実用的な例

 ### サンプル入力 1

## 特殊なケース

 エッジケースの場合、$k = n-1$、例えば、$n=5, k=4$、長さ 4 のウィンドウは [最初の 4] と [最後の 4] です。 順列を [1, 4, 5, 3, 2] として構築すると、両方のウィンドウに異なる位置に最大の数値 5、4、3 が含まれるようになり、最小合計が最大化されます。 合計をたどると、1+4+5+3=13、4+5+3+2=14; 最小値は 13 で、これは実際に可能な最大値であり、アルゴリズムがこの重要なシナリオを正しく処理していることを示しています。
