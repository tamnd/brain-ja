 ## 解決策
 ## 問題の理解

 私たちには細胞からなる 1 次元のパスが与えられています。 各セルは空であるか、コインが入っているか、またはトゲでブロックされています。 必ず空であることが保証されている最初のセルから開始し、コインを集めながらできるだけ右に移動したいと考えています。 

各ステップで、1 つまたは 2 つのセルを前方に移動できますが、着地できるのはとげのないセルのみです。 コインセルに着地すると、そのコインを回収します。 着地位置の障壁として効果的に機能する棘細胞を通過したり、着地したりすることはできません。 

このタスクは、インデックス 0 から開始して収集できるコインの最大数を計算することです。 

制約は非常に小さく、テスト ケースは最大 1000 個、各パスの長さは最大 50 です。これにより、3 次または指数解でも問題なく通過することがすぐに分かりますが、意図した解がテスト ケースごとに線形になるのに十分単純であることも示唆されます。 

重要な構造的観察は、動きは厳密に前方に進み、唯一の分岐は 1 歩ジャンプするか 2 歩ジャンプするかであるということです。 後戻りやサイクルはありません。 

主な微妙な点は、とげが着陸を妨げることで、常にすべてのコインに到達できると想定している場合、貪欲な「コインを見つけたら必ず取る」戦略が失敗する状況を引き起こす可能性があります。 

たとえば、次のようなセグメントについて考えてみましょう。 

入力:```
. @ * @ @
```最初のセルから、最初のコインを集めて続行することを考えるかもしれませんが、ステップを誤ると、有効なステップ ポイントがトゲでブロックされ、後のコインに到達できなくなる構成に陥る可能性があります。 

もう 1 つの微妙なエッジ ケースは、連続したとげです。```
. @ * * @
```後にコインがあっても、ジャンプの経路がすべてトゲに着地するため、到達できない場合があります。 

これらの状況は、ローカルでの貪欲な決定だけでなく、到達可能性を追跡するための体系的な方法が必要であることを示唆しています。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる可能な一連の動きを調査することになります。 目的地が有効であれば、各位置から 1 つまたは 2 つのセルを前方に進めてみることができます。 各状態は最大 2 つの選択肢に分岐し、最大 n の深さの再帰ツリーを形成します。 

最悪の場合、各位置が 2 つの選択肢に分岐する可能性があるため、およそ O(2^n) 個のパスが生成されます。 n がわずか 50 であっても、2^50 は依然として大きすぎます。また、ほとんどの分岐は異なるパスを介して同じインデックスを複数回再訪問するため冗長です。 

冗長性は動的プログラミングを示唆しています。 重要な観察は、問題には最適な下部構造があるということです。つまり、位置 i から始まる最良の答えは、位置 i+1 と i+2 の最良の答えにのみ依存します (これらの位置が到達可能である場合)。 

前向きに考える代わりに、視点を反転します。i 上に立つことが許可されていると仮定して、セル i から開始して収集できる最大コインとして dp[i] を定義します。 常に前進するため、遷移は i+1 または i+2 にのみ進み、状態空間は線形になります。 

dp を右から左に計算します。 セルがとげの場合、dp[i] は無効になります。 それ以外の場合、dp[i] は、i のコインに、dp[i+1] と dp[i+2] の最大値 (状態が有効な場合) を加えたものになります。 

最後に、dp[0]を返します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (DFS オーバームーブ) | O(2^n) | O(n) | 遅すぎる |
 | 動的プログラミング | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各位置がそのセルから開始して収集可能なコインの最適な数を表す DP 配列を定義します。 

1. 0 に初期化されたサイズ n+2 の配列 dp を作成します。余分なパディングにより、i+1 および i+2 にアクセスするときの境界チェックが防止されます。 
2. 最後のセルから最初のセルまで繰り返します。 逆に処理して、dp[i] を計算するときに、値 dp[i+1] と dp[i+2] がすでにわかっているようにします。 
3. 現在のセルにとげが含まれている場合は、そこに着地できないため、dp[i] を 0 に設定します。 ただし、ソーンから開始することはないため、以前のセルを暗黙的に考慮する場合は、それを介した遷移を引き続き許可します。 
4. 現在のセルがソーンではない場合、コインが含まれていれば 1、それ以外の場合は 0 に等しい基本値を計算します。 
5. dp[i] を基本値に dp[i+1] と dp[i+2] の最大値を加えた値として更新しますが、有効な遷移のみを考慮します。 両方が有効な場合は、最大値を採用します。 事実上到達不可能な場合は無視します。 
6. 各テスト ケースの答えは dp[0] で、これは最初のセルから開始することに対応します。 

### なぜ効果があるのか

 正しさは、任意の位置 i からは、将来の決定は i+1 と i+2 から始まる独立した部分問題のみであるという事実に依存します。 動きは厳密に前進するため、後の選択が以前の決定に影響を与えることはできません。 i からのすべての有効なパスは、これら 2 つの動きのうちの 1 つで開始する必要があるため、最適な結果は、これら 2 つの継続と i で収集されたコインの最良のものになります。 これにより、考えられるすべてのパスが完全に分解され、構成の欠落や二重カウントがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        dp = [0] * (n + 2)

        for i in range(n - 1, -1, -1):
            if s[i] == '*':
                dp[i] = 0
                continue

            best_next = max(dp[i + 1], dp[i + 2])
            dp[i] = best_next + (1 if s[i] == '@' else 0)

        print(dp[0])

if __name__ == "__main__":
    solve()
```このソリューションは文字列を右から左に処理して、すべての状態の将来がすでに計算されているようにします。 パディングされた dp 配列を使用すると、i+2 にアクセスする際の明示的な境界チェックが回避されます。 

よくある間違いは、左から右への動きを貪欲にシミュレートしようとすることです。 初期のコインを集める手を選択すると、将来のより良いシーケンスへのアクセスがブロックされる可能性があるため、これは失敗します。 DP 定式化では、両方の順方向オプションを常に評価することでこれを回避します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    input = sys.stdin.readline

    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        dp = [0] * (n + 2)

        for i in range(n - 1, -1, -1):
            if s[i] == '*':
                dp[i] = 0
            else:
                dp[i] = max(dp[i + 1], dp[i + 2]) + (1 if s[i] == '@' else 0)

        output.append(str(dp[0]))

    return "\n".join(output)

 ## 特殊なケース

 特殊なケースの 1 つは、トゲが連続した位置に現れる場合です。 入力の場合:```
.@@**
```DP は、ソーンの後の dp 値を 0 に正しく設定し、dp[i+1] と dp[i+2] がそれらの位置で両方とも 0 と評価されるため、以前のセルは自動的にソーンへのジャンプを回避します。 これにより、パスがブロックされたゾーンを誤って通過することがなくなります。 

もう 1 つのエッジ ケースは、コインがとげブロックの直後にある場合です。```
.@**@.
```とげの前の位置では、可能な両方の前進移動が最終的に無効または値ゼロの状態につながるため、DP は当然そのルートを破棄します。 ブロックされたパスはゲインに寄与しないため、max 演算では決して選択されないため、このアルゴリズムでは明示的な「到達不能」マーカーは必要ありません。
