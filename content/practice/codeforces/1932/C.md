 ## 解決策
 ## 問題の理解

 一連の命令に基づいて両端から縮小する配列が与えられます。 すべてのステップで、何かを削除する前に、固定数を法とした残りのすべての要素の積を計算する必要があります。$m$。 次に、コマンドは左端の要素を削除するか右端の要素を削除するかを指示します。 

したがって、プロセスは純粋に動的です。配列は 2 つのポインターによって定義されるスライディング ウィンドウであり、各クエリの後にそのウィンドウを両側から 1 つずつ縮小します。 課題は、要素が両端から消える一方で、高速に繰り返される製品クエリをサポートすることです。 

制約が十分に大きいため、削除するたびに積を最初から再計算すると時間がかかりすぎます。 単純なアプローチでは費用がかかる$O(n^2)$各ステップが最大で倍増する可能性があるため、最悪のケースではテスト ケースごとに$n$再び要素。 合計あり$n$まで$2 \cdot 10^5$、これは受け入れられません。 

微妙なエッジケースが現れるのは、$m = 1$。 その場合、配列に関係なくすべての答えはゼロになるため、正しい解は不必要な計算を回避し、削除を繰り返しても正しく動作する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、現在の配列を明示的に維持し、積の剰余を再計算します。$m$各操作の後。 これは正しいですが、非効率的です。 各ステップには直線的な時間がかかります。$n$ステップがあり、全体的に 2 次の複雑さが得られます。 

重要な観察点は、配列では末尾の要素のみが失われるということです。 これは、値を挿入または変更することはなく、値を削除するだけであることを意味します。 これは、実行中の製品を保守し、段階的に更新することを示唆しています。 ただし、モジュロ逆算を安全に計算できない限り、モジュロでの除算は直接利用できません。$m$が素数ではない、または要素が因数を共有する$m$。 

これは私たちを別の視点へと押し上げます。 可逆的な製品を維持しようとする代わりに、削除を逆に処理します。 配列を逆方向に再構築することを想像すると、すべての削除が挿入になります。 最初にすべてを削除し、次に逆の順序で答えを再構築することで、プロセスをシミュレートできます。 再構築中は要素を追加するだけなので、乗算は安全です。 

この逆転手法は、問題を、要素を乗算して積にするだけで、決して除算しない標準的なプレフィックス構造に変換します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各ステップを再計算する |$O(n^2)$|$O(n)$| 遅すぎる |
 | インクリメンタル乗算による逆処理 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列とコマンド文字列を読み取ります。 何も残らなくなるまで、左または右から繰り返し削除するプロセスとして解釈します。 
2. 削除を順にシミュレートする代わりに、削除された要素のシーケンスを構築します。 最初に最終状態 (空) を追跡し、次に削除の逆の順序で要素を再挿入することによって逆方向にシミュレーションします。 
3. これを行うには、2 つのポインタを維持します。$l$そして$r$。 コマンドごとに、そのステップでどの要素が削除されるかを記録します。 
4. 削除順序を記録した後、この順序を逆に実行します。 次に、配列を空から完全に再構築します。 
5. 実行中の積を 1 から維持します。要素を追加し直すたびに、それを積のモジュロに乗算します。$m$。 
6. 挿入後は毎回製品を保管してください。 これらは、元のプロセスとは逆の順序で回答に対応します。 
7. 最後に、印刷する前に回答配列を反転します。 

### なぜ効果があるのか

 重要な不変条件は、逆のプロセスでは、各ステップで現在の要素セットが順方向で削除されたものを正確に補うものであるということです。 乗算は結合的かつ可換的であるため、逆の順序で再構築すると、各段階でアクティブ セットにわたるプレフィックス積の正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        s = input().strip()

        l, r = 0, n - 1
        removed = []

        for c in s:
            if c == 'L':
                removed.append(a[l])
                l += 1
            else:
                removed.append(a[r])
                r -= 1

        res = []
        prod = 1

        for x in reversed(removed):
            prod = (prod * x) % m
            res.append(prod)

        print(*reversed(res))

if __name__ == "__main__":
    solve()
```## コードがアイデアとどのように一致するか

 最初のループは、2 つのポインターを使用して配列の縮小をシミュレートすることにより、正確な削除順序を再構築します。 これにより、コストのかかる再計算が回避されます。 

2 番目のループではプロセスが反転します。要素を削除してプロダクトを再計算する代わりに、要素を 1 つずつ追加して戻し、実行中のプロダクトを維持します。 これは、集合に対する乗算が順序に依存しないため機能します。 

最後の反転により、再構築されたタイムラインが元のクエリ順序に揃えられます。

 ### 例 1

 入力:```

s = LRRL

```これは、サフィックスで構築されたセットの積を蓄積しているという考えと一致します。 

### 例 2

 入力:```

```すべてのステップで 1 が削除されるため、積は 0 モジュロ 1 から変化することはありません (または m に応じて安定したままになります)。 このプロセスでは、すべての要素が同一である場合、削除の順序が重要ではないことが確認されます。

 ## 特殊なケース

 いつ$m = 1$、すべての乗算結果は直ちにゼロになる必要があります。 すべての積演算はモジュロであるため、アルゴリズムは引き続き機能します。$m$したがって、すべての中間状態は有効なままであり、最後の逆の再構成では特別なケースを使用せずにゼロのシーケンスが生成されます。 

すべての要素が同一の場合、削除順序は正確さに影響を与えず、再構成でも同じ積のシーケンスが生成され、対称の場合には解が順序に依存しないことが確認されます。
