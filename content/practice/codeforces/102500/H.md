 # 問題の理解

 レースのプロフィールは、整数キロメートルごとの道路の高さによって表されます。 連続する 2 つのキロメートルマークの間の道路は直線であるため、すべてのセグメント内の勾配は一定です。 要求された傾斜勾配ごとに、平均勾配が少なくともその勾配である最長の水平間隔が必要です。 

直接的な解釈は、ルート上の 2 つの点を選択し、それらの高低差と水平距離を比較することです。 難しいのは、エンドポイントが整数の位置である必要がないことです。 最適な間隔は、キロメートルセグメントの途中で開始または終了できます。 

レースの長さには 100,000 のセグメントを含めることができ、50 の異なるグレード クエリを含めることができます。 エンドポイントのすべてのペアをチェックするソリューションでは、約 10^10 の比較が必要になりますが、これは適合範囲をはるかに超えています。 可能なペアごとに線形スキャンを実行することさえ不可能であるため、ターゲットはクエリごとに O(n) に近くなければなりません。 

よくある間違いは、整数のキロメートル位置のみを確認することです。 たとえば、次の入力を使用すると、```
2 1
0 30 30
2.0
```答えは`1.5`, なぜなら、キロ0からキロ1.5までの区間は1キロあたり20メートルの勾配があり、これは2%の勾配に相当します。 頂点のみをチェックすると、この間隔が失われます。 

もう 1 つの罠は、最適な間隔が頂点で終了する必要があると仮定することです。 考慮する```
3 1
0 10 0 0
5.0
```変換されたプロファイルはセグメント内で必要な値に達するため、答えは小数点の距離になる可能性があります。 整数座標での回答のみを更新するアプローチでは、より短い結果が返される可能性があります。 

3 番目のエッジ ケースは、必要なグレードに到達しない場合に発生します。```
2 1
0 0 0
1.0
```正しい出力は次のとおりです`-1`。 不用意に実装すると、常に同じ位置のペアが見つかるため、ゼロが出力される可能性があります。 

# アプローチ

 ブルート フォース ソリューションでは、考えられるすべてのエンドポイントのペアが試行されます。 各ペアについて、平均傾斜を計算し、クエリを満たす最長の間隔を維持します。 n 位置の場合、O(n^2) チェックが必要になります。これは、最大入力サイズに対して約 10^10 の演算に相当します。 

重要な観察は、条件を書き換えることから得られます。 クエリグレード g の場合、次のように定義します。 

f(x) = 身長(x) - (g / 100) * x

 2 つの位置 a < b の場合、a から b までの傾斜は正確に少なくとも g です。 

f(b) >= f(a)。 

問題は、後の点が前の点と少なくとも同じ大きさの値を持つ 2 点間の最長距離を見つけることです。 

左から右にスキャンしているときに、これまでに確認された f の最小値と、それが発生した最も早い位置がわかっている場合、すべての現在位置から、そこで終了する可能な限り最良の間隔が得られます。 残る唯一の問題は、f が各キロメートルセグメント内で連続的かつ線形であることです。 線分は単調であるため、二分探索を行わずに線分内の最適な端点を直接見つけることができます。 

ブルートフォース方式は、考えられるすべてのペアをチェックするため機能します。 ペアが多すぎるため失敗します。 上記の変換により、問題は n 個の線形部分のみを処理しながらプレフィックスの最小値を維持することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n^2) | お(1) | 遅すぎる |
 | 最適 | クエリごとに O(n) | O(1) 入力ストレージ以外 | 承認済み |

 # アルゴリズムのチュートリアル

 1. クエリグレード g の場合、高さプロファイルから傾き g/100 の線を引きます。 位置 x の新しい値は次のとおりです。`height(x) - g*x/100`。 この変換された値が左端から右端まで減少しない場合、間隔は正確に有効になります。 
2. 左から右へルートのスキャンを開始します。 これまでに確認された最小変換値と、その最小値が表示される最も早い位置を維持します。 これにより、現在の位置で終了する間隔の最適な開始点が得られます。 
3. 2 つの整数キロメートル間のすべてのセグメントについて、変換された線分がその最大の有効な終点に到達する場所を決定します。 セグメントが増加している場合、遠端は常に有効です。 減少している場合、セグメントが現在のプレフィックスの最小値に達すると、有効な部分は終了します。 
4. この終点と保存された最小位置の間の距離を使用して答えを更新します。 セグメントの終了後、セグメントのエンドポイントを使用してプレフィックスの最小値を更新します。これは、将来の間隔がそこから開始される可能性があるためです。 
5. 要求されたグレードごとにスキャンを繰り返し、見つかった最長の長さを印刷します。 正の長さの間隔が存在しない場合は、出力します。`-1`。 

なぜ効果があるのか:

 考えられる終了点 y の場合、最適な開始点は、y より前の最小変換値の最も早い出現点です。 スキャンでは常にこの情報が正確に保存されます。 各セグメント内では、変換された関数は線形であるため、有効な終了点のセットはセグメント全体またはセグメントのプレフィックスのいずれかになります。 アルゴリズムは最も遠い有効な終了点をチェックします。これが答えを改善できる唯一の点です。 考えられるすべてのエンドポイントが考慮されるため、最大間隔を逃すことはできません。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_query(h, g):
    n = len(h) - 1
    slope_need = g / 100.0

    def value(i):
        return h[i] - slope_need * i

    cur_min = value(0)
    min_pos = 0
    ans = 0.0

    cur = value(0)

    for i in range(n):
        nxt = value(i + 1)
        seg_slope = nxt - cur

        if seg_slope >= 0:
            end = i + 1.0
        else:
            t = (cur_min - cur) / seg_slope
            if t >= 1.0:
                end = i + 1.0
            else:
                end = i + t

        if end - min_pos > ans:
            ans = end - min_pos

        cur = nxt

        if cur < cur_min:
            cur_min = cur
            min_pos = i + 1.0

    if ans <= 1e-12:
        return "-1"
    return f"{ans:.10f}"

def main():
    n, k = map(int, input().split())
    h = list(map(int, input().split()))

    grades = []
    for _ in range(k):
        grades.append(float(input()))

    out = []
    for g in grades:
        out.append(solve_query(h, g))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```変換は要求された勾配に依存するため、コードは各勾配を個別に処理します。 機能`solve_query`現在の変換値、これまでに確認された最小の変換値、およびその最小値に達した位置を保持します。 

表現`seg_slope = nxt - cur`は、変換されたセグメントの傾きです。 負でない場合、セグメント内のすべての点は少なくともセグメントの開始点と同じ大きさの値を持つため、遠い端点が最良の選択となります。 負の場合、線は最終的に保存された最小値を下回り、式は正確な交差点を計算します。 

最適なエンドポイントはセグメント内にある可能性があるため、すべての座標は浮動小数点値として保存されます。 Python の整数は元の高さを安全に処理し、変換された計算のみが浮動小数点精度を必要とします。 

# 実用的な例

 最初のサンプルの場合、クエリは 2.0% です。 変換されたプロファイルは、1 キロメートルあたり 2 メートルを差し引くことによって作成されます。 

| セグメント | 現在の最小位置 | 現在の変換値 | 最適なエンドポイント | 答え |
 | --- | --- | --- | --- | --- |
 | 開始 | 0 | 0 | 1 | 1 |
 | 1から2 | 0 | -2 | 2 | 2 |
 | 2から3 | 0 | -4 | 3 | 3 |
 | 残りのセグメント | 0 | 最低値は低いまま | 改善なし | 3 |

 キロメートル 0 からキロメートル 3 までの区間には、必要な平均勾配が正確に存在するため、答えは 3 になります。 

2 番目のサンプルの場合、クエリは 2.0% です。 

| セグメント | 現在の最小位置 | 現在の変換値 | 最適なエンドポイント | 答え |
 | --- | --- | --- | --- | --- |
 | 0から1 | 0 | 0 | 1 | 1 |
 | 1から2 | 0 | 28 | 1.5 | 1.5 |

 2 番目のセグメントは変換後は平坦になり、端点が小数点に達することが可能になります。 アルゴリズムは長さ 1.5 の間隔を見つけます。

# エッジケース

 最良のエンドポイントがセグメント内にある場合、アルゴリズムは減少セグメント交差式を通じてそのエンドポイントに到達します。 入力用```
2 1
0 30 30
2.0
```変換された値は 0、28、および 26 です。最小値は位置 0 に留まります。2 番目のセグメントは 28 から 26 に減少し、最小値との交差は 1.5 キロメートル後に発生し、正しい答えが得られます。 

すべての間隔が必要なグレードを満たしていない場合、プレフィックスの最小値は正の有効距離を許可しません。 のために```
2 1
0 0 0
1.0
```変換されたプロファイルはすぐに減少し、すべての可能な間隔は負の調整された傾きを持ちます。 保存された答えはゼロのままなので、プログラムは次のように出力します。`-1`。 

ルート全体が有効な場合、最小値は先頭に残り、最後のエンドポイントで答えが得られます。 のために```
2 1
0 100 200
50.0
```変換されたプロファイルは平坦であるため、スキャンはキロメートル 2 に到達し、全長を返します。
