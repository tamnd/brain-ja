 ## 解決策
 ## 問題の理解

 すべてのケーブルの長さが既知である無向ネットワークがありますが、ケーブルの実際の伝送時間は 2 つの未知のグローバル パラメーターに依存します。 一定の長さのケーブルの場合`l`、その時間は`l / v + c`、同じ`v`そして`c`すべてのケーブルに適用されます。 スイッチからの最速ルートに決して現れないスイッチを見つける必要があります`1`切り替える`n`、これら 2 つのパラメーターがどの有効な値をとるかに関係なく。 

未知のパラメータが重要な問題です。 パスは全長だけでは比較されません。 オーバーヘッドが大きい場合には、より少ないケーブルを使用するパスがより適切になる可能性があります。`c`は大きいですが、伝播が優勢な場合は、ケーブルの合計長が短いパスが勝つ可能性があります。 

制約によって与えられるのは、`n`2000年までと`m`最大 10000。3 次時間を使用するアルゴリズムはすでに大きすぎます。`2000^3`事業規模は約80億です。 意図したソリューションは次のようなものでなければなりません`O(n(n+m))`これは、これらの制限に対して約 4,000 万回のグラフ操作になります。 

よくある間違いは、元の公式でダイクストラを 1 回実行してしまうことです。 数式に不明な値が含まれているため、これは機能しません。 もう 1 つの間違いは、最短長のパスまたは最小エッジのパスのみを考慮することです。 どちらかが他方を支配することはありません。 たとえば、次のことを考えてみましょう。```
4 4
1 2 1
2 4 100
1 3 10
3 4 10
```オーバーヘッドが非常に小さい場合、パスは`1-3-4`長さがあるため勝ちます。`20`。 非常に大きなオーバーヘッドの場合、パスは`1-2-4`エッジが少ないため勝ちます。 1 つの目的のみを考慮する方法では、考えられる最適なパスが誤って破棄されてしまいます。 

もう 1 つの特殊なケースは引き分けです。 スイッチは、パラメータ選択に対する最適なパス上にある場合に有効です。 2 つの異なるルートの一部のパラメーターのコストがまったく同じである場合、両方のルートが頂点を提供する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、未知のパラメータの可能な値をすべて試して、最短パスを計算します。 パラメータ空間は連続的であり、無限に多くの異なる最短経路の変更が存在する可能性があるため、これは不可能です。 

有用な観察は、パス コストを書き換えることから得られます。 すべてのエッジコストを乗算すると、`v`考えられるすべてのルートに同じ正の値を乗算するため、どのパスが最適であるかは変わりません。 パスのコストは次のようになります。```
total_length + number_of_edges * x
```どこ`x = v*c`、 そして`x`負でない実数を指定できます。 

これで、すべてのパスが線で表されます。```
y = edges * x + length
```傾きはエッジの数、切片はケーブルの全長です。 

可能なすべてのエッジ数に対して`k`、正確に使用する最短長のパスのみを考慮します。`k`エッジ。 同じ数のエッジを持つ他のパスは切片が大きくなり、勝つことはできません。 

したがって、問題は次のようになります。 

すべて検索`k`どこの線```
y = k*x + best[k]
```の下部凸包の一部です。`x >= 0`。 

これらはまさに、最適なルート上で発生する可能性のあるエッジの数です。 

残りのタスクは、これらのエッジ数を持つパス上にどの頂点が発生するかを回復することです。 動的計画表を計算します。`forward[k][v]`到達するために必要な最小の長さを格納します`v`スイッチから`1`正確に使用して`k`エッジ。`backward[k][v]`スイッチに到達するために必要な最小の長さを格納します`n`から`v`正確に使用して`k`エッジ。 

頂点`v`最適なパス上に現れることができます`k`パスを分割できる場合はエッジ`v`:```
prefix edges + suffix edges = k
```そして```
forward[prefix][v] + backward[suffix][v] = best[k]
```最終的な答えは、この条件を決して満たさないすべての頂点です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パラメータに対するブルートフォース | 不可能 | 不可能 | 遅すぎる |
 | 動的計画法と凸包を使用してすべてのエッジ数を列挙する | O(n(n+m)) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. エッジの数ごとに可能な最短のケーブル長を計算します。 

有効なパス内のエッジの最大数は次のとおりです。`n-1`なぜなら、サイクルを含むパスはそのサイクルを削除して厳密に改善できるからです。 階層化された動的プログラミング プロセスを実行します。 各レイヤーは、これまでに使用されたエッジの正確な数を表します。 

あらゆる人にとって`k`を取得します。`best[k]`全長が最も短い`1`に`n`正確に使用するパス`k`エッジ。 

1. 可能なパスを線に変換します。 

有効なエッジ数ごとに`k`、次の行を作成します。```
y = k*x + best[k]
```一部の非負数では、下から見える線だけが最短になる可能性があります。`x`。 船体の下部を計算して、他のすべてのラインを削除します。 

1. 最適なルートを生成できるすべてのエッジ数を見つけます。 

残りの各行は、次の少なくとも 1 つの値に対応します。`x`その数のエッジを使用するパスが最適です。 頂点についてチェックする必要があるのは、これらのエッジ数のみです。 

1. 宛先から同じ階層動的計画法を計算します。 

逆テーブルを使用すると、最適なパスの中央に頂点を配置できるかどうかを確認できます。 完全なルートをすべて列挙する必要がなくなります。 

1. 最適なパスに現れるすべての頂点にマークを付けます。 

下部ハルのエッジ カウントごとに、前方状態と後方状態を組み合わせます。 2 つの部分を合わせると、そのエッジ数に対して可能な最小の長さがあれば、頂点は使用可能になります。 

1. マークされていない頂点をすべて出力します。 

これらはまさに、未知のパラメータの考えられる値に対して最適なルートに現れることができないスイッチです。 

### なぜ効果があるのか

 考えられるすべての送信時間は、次の 1 つの値を選択することで表されます。`x`行の家族の中で`k*x + best[k]`。 下部ハルの外側のラインは常に他のラインよりも悪いため、その数のエッジを使用するパスが最適になることはありません。 船体下部の線は、あるパラメータ値にとって最適であるため、その線で表されるすべての最短パスを考慮する必要があります。 

順方向および逆方向の動的プログラミング テーブルには、すべてのプレフィックスおよびサフィックスの長さの最小可能な長さが含まれています。 それらが組み合わされると、`best[k]`、結果のルートは、次を使用したすべてのルートの中で最短のルートになります。`k`エッジ。 考えられるすべての最適なルートには船体上のエッジ数があるため、使用できるすべての頂点はマークされますが、マークされていないすべての頂点は不可能です。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

INF = 10**30

def solve():
    n, m = map(int, input().split())

    adj = [[] for _ in range(n)]
    for _ in range(m):
        a, b, l = map(int, input().split())
        a -= 1
        b -= 1
        adj[a].append((b, l))
        adj[b].append((a, l))

    size = n * n

    def build(start):
        dp = array('q', [INF]) * size
        dp[start] = 0

        for k in range(n - 1):
            base = k * n
            nxt = (k + 1) * n
            for u in range(n):
                cur = dp[base + u]
                if cur == INF:
                    continue
                for v, w in adj[u]:
                    val = cur + w
                    if val < dp[nxt + v]:
                        dp[nxt + v] = val
        return dp

    forward = build(0)

    rev_adj = [[] for _ in range(n)]
    for u in range(n):
        for v, w in adj[u]:
            rev_adj[v].append((u, w))

    old = adj
    adj = rev_adj
    backward = build(n - 1)
    adj = old

    best = [forward[k * n + n - 1] for k in range(n)]

    hull = []
    for k in range(n):
        if best[k] == INF:
            continue
        while len(hull) >= 2:
            a, b = hull[-2], hull[-1]
            # intersection(a,b) >= intersection(b,k)
            if (best[b] - best[a]) * (k - b) >= (best[k] - best[b]) * (b - a):
                hull.pop()
            else:
                break
        hull.append(k)

    possible = [False] * n

    for k in hull:
        target = best[k]
        for v in range(n):
            f = forward[v]
            if f == INF:
                continue
            for i in range(k + 1):
                if i * n + v >= size:
                    break
                if forward[i * n + v] + backward[(k - i) * n + v] == target:
                    possible[v] = True
                    break
            if possible[v]:
                continue

    ans = [str(i + 1) for i, ok in enumerate(possible) if not ok]

    print(len(ans))
    if ans:
        print(" ".join(ans))

if __name__ == "__main__":
    solve()
```実装では、動的プログラミング テーブルが次の場所に保存されます。`array('q')`通常の Python リストの代わりに。 テーブルには最大で 400 万の値が含まれており、Python の整数はメモリを大量に消費します。 

DP 遷移は直接層状緩和です。 インデックス`k*n+v`到達した頂点を表す`v`まさにその後`k`エッジ。 

凸包の計算では整数演算のみが使用されます。 ケーブルの長さは最大でも長くできるため、交差部分を比較すると浮動小数点の精度の問題が回避されます。`10^9`。 

逆 DP は、すべてのエッジを反転することによって計算されます。 グラフには方向性がないため、これは宛先から同じプロセスを実行することと同じです。 

マーキング ループは、頂点が最適なパスを分割できるかどうかをチェックします。 等価比較では整数値のみが使用されるため、等コスト ルートは正しく処理されます。
