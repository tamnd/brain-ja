 ## 解決策
 ## 問題の理解

 一連のコメントスコアがあります。 ニックは、偽のアカウントを作成することに時間を費やすことができます。各アカウントは、選択したスコアをどちらかの方向に 1 ずつ変更でき、コメントを削除することもできます。 最後に残ったシーケンスには、すべてのスコアがゼロ以外であり、隣接するスコアが反対の符号を持つ必要があります。 

ニックが作ったら`f`偽アカウント、絶対値が以下のスコア`f`ポジティブにもネガティブにも変えることができます。 このようなスコアはワイルドカードのように動作します。 ゼロ以外のスコアはすべて元の符号を維持します。 タスクは、合計時間を最小限に抑えるために、作成するアカウントの数と削除するコメントの数を選択することです。 

配列の長さは次のとおりです`5 * 10^5`そのため、考えられるすべての数のアカウントをチェックしてシーケンス全体を再構築すると、時間がかかりすぎます。 アカウント数の増加によって生じる変化をほぼ直線的に処理する必要があります。 スコアは次のように大きくなります。`10^9`, ただし、問題となるのはスコアがワイルドカードになる瞬間だけなので、数値範囲が膨大であること自体は問題ではありません。 

いくつかの特殊なケースは見落とされがちです。 偽のアカウントがなければ、スコアが 0 のままシーケンスに残ることはできません。 例えば：```
1 5 7
0
```アカウントがゼロの場合、コメントを削除する必要があり、コストがかかります`7`。 1つのアカウントで使用可能になり、費用がかかります`5`、したがって、答えは次のとおりです`5`。 ゼロを通常の固定符号として扱う解決策では、誤った結果が得られます。 

もう 1 つの罠は、連続する等号を複数回削除する必要がある場合があることです。 例えば：```
3 1 100
1 1 1
```アカウントを作成しない場合は、1 つを除く 3 つのコメントをすべて削除する必要があり、コストがかかります`200`。 1 つのアカウントを作成すると、すべての値が柔軟になり、コストがかかります`1`。 隣接する不良ペアのみをカウントするソリューションでは、必要な削除の数を誤解する可能性があります。 

## アプローチ

 直接的なアプローチでは、あらゆる数の偽アカウントを試します。 の各値に対して、`f`、すべてのスコアを分類し、残せる最長の交互サブシーケンスを計算し、削除されたコメントの料金を支払います。 これは、考えられるすべての戦略を明示的にチェックするため、正しいです。 ただし、次のようなことが考えられます。`O(10^9)`考えられるアカウント数や、意味のある値に制限したとしても、依然として問題は残ります。`O(n)`アレイの再構築にコストがかかる可能性`O(n)`。 最悪のケースとなるのは、`O(n^2)`不可能な操作`n = 5 * 10^5`。 

重要な観察は、スコアの動作が 1 回だけ変更されるということです。 価値のあるスコア`x`アカウントの数が より多くなった場合にのみ柔軟になります。`|x|`。 この間、柔軟なコメントのセットは変更されないため、回答はそれらの時点でのみ確認する必要があります。`n + 1`興味深いアカウント数。 

アカウントの数が固定されている場合、ワイルドカード以外のコメントのみが問題になります。 元の順序で連続する 2 つの非ワイルドカード コメントを考えてみましょう。 ありましょう`k`それらの間のワイルドカードコメント。 その隙間を通ってサインを交互に作ることができないときに、まさに衝突が生じます。 これは、等号のギャップが偶数である場合、または反対の符号のギャップが奇数である場合に発生します。 このような競合ごとに 1 つの削除が必要です。 

コメントがワイルドカードになると、固定記号のリストから消えます。 隣接する 2 つの固定コメントのみが影響を受けるため、競合の数は一定時間で更新されます。 二重リンクリストを使用すると、新しく柔軟なコメントを効率的に削除できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのスコアを、固定正符号、固定負符号、またはワイルドカードとなるイベントのいずれかに分類します。 ゼロ以外のスコア`s`で柔軟になる`|s| + 1`アカウントはゼロになりますが、`1`アカウント。 
2. 偽アカウントゼロから始めます。 ゼロ以外のスコアはすべて、固定記号のリンクされたリストに保持されます。 スコアがゼロの場合、それぞれ 1 つの必須削除が発生します。 不良な隣接固定ペアの初期数を計算します。 
3. すべてのワイルドカード イベントを、発生したアカウント数で並べ替えます。 これらのアカウント数のみをテストする必要があります。 
4. イベントが処理されると、固定標識のリンクされたリストからその位置が削除されます。 削除する前に、その前後の固定隣接要素に関係する競合を差し引きます。 削除後、これら 2 つの隣接する 2 つの隣接する競合がまだ存在する場合は、それらの間に新しい競合を追加します。 
5. 特定のアカウント数のすべてのイベントを処理した後`f`、現在必要なレポートの数がわかっています。 The total cost is:```
f * c + removals * r
```最小の回答を更新します。 

機能する理由: 固定数のアカウントの場合、すべての柔軟なコメントに、隣接するコメントが必要とする記号を常に割り当てることができます。 避けられない唯一の問題は、符号と距離が等価であるため、交互が不可能な連続する固定コメント間です。 このような競合ごとに 1 つのコメントを削除するだけで十分であり、必要です。 アカウントの数を増やしても、この縮小された表現から固定コメントが削除されるだけなので、削除するたびに競合カウントを維持することで、レポートの正確な最小数が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, c, r = map(int, input().split())
    s = list(map(int, input().split()))

    sign = [0] * n
    events = {}

    zero = 0
    for i, x in enumerate(s):
        if x == 0:
            zero += 1
            t = 1
        else:
            sign[i] = 1 if x > 0 else -1
            t = abs(x) + 1
        events.setdefault(t, []).append(i)

    prev = [-1] * n
    nxt = [-1] * n

    last = -1
    for i in range(n):
        if sign[i]:
            if last != -1:
                nxt[last] = i
                prev[i] = last
            last = i

    def bad(a, b):
        if a == -1 or b == -1:
            return 0
        gap = b - a - 1
        return 1 if ((sign[a] == sign[b]) == (gap % 2 == 0)) else 0

    removals = zero
    cur = -1
    for i in range(n):
        if sign[i]:
            if cur != -1:
                removals += bad(cur, i)
            cur = i

    ans = removals * r

    for f in sorted(events):
        for i in events[f]:
            if sign[i] == 0:
                removals -= 1
                continue

            a = prev[i]
            b = nxt[i]

            removals -= bad(a, i)
            removals -= bad(i, b)

            if a != -1:
                nxt[a] = b
            if b != -1:
                prev[b] = a

            removals += bad(a, b)

            sign[i] = 0

        ans = min(ans, f * c + removals * r)

    print(ans)

if __name__ == "__main__":
    solve()
```リンクされたリストには、依然として元の符号が強制されているコメントのみが含まれています。 コメントがワイルドカードになると、後からいつでも必要な記号を割り当てることができるため、競合には影響しなくなります。 

の`bad`機能はソリューションの中核です。 2 つの固定コメント間の距離によって、ワイルドカード ギャップが必要なパリティを反転するかどうかが決まります。 リンクされたリスト内の隣接するノード間には固定コメントがないため、それらのインデックスの差がそれらの間のワイルドカードの数を直接示します。 

Python の整数はすでに任意精度をサポートしているため、製品のコストは最大で`10^9`そして`5 * 10^5`コメントは安全です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old

    n, c, r = map(int, data[:3])
    arr = list(map(int, data[3:]))

    sign = [0] * n
    events = {}
    zero = 0

    for i, x in enumerate(arr):
        if x == 0:
            zero += 1
            t = 1
        else:
            sign[i] = 1 if x > 0 else -1
            t = abs(x) + 1
        events.setdefault(t, []).append(i)

    prev = [-1] * n
    nxt = [-1] * n
    last = -1
    for i in range(n):
        if sign[i]:
            if last != -1:
                nxt[last] = i
                prev[i] = last
            last = i

    def bad(a, b):
        if a == -1 or b == -1:
            return 0
        return int(((sign[a] == sign[b]) == ((b - a - 1) % 2 == 0)))

    rem = zero
    last = -1
    for i in range(n):
        if sign[i]:
            if last != -1:
                rem += bad(last, i)
            last = i

    ans = rem * r
    for f in sorted(events):
        for i in events[f]:
            if sign[i] == 0:
                rem -= 1
            else:
                a, b = prev[i], nxt[i]
                rem -= bad(a, i) + bad(i, b)
                if a != -1:
                    nxt[a] = b
                if b != -1:
                    prev[b] = a
                rem += bad(a, b)
                sign[i] = 0
        ans = min(ans, f * c + rem * r)

    return str(ans)

 ## 特殊なケース

 単一のゼロ コメントは、ゼロ アカウントで使用できないスコアの特別な処理を示しています。```

```アルゴリズムは、必要な 1 つの削除から始まります。 アカウントカウント時`1`、ゼロはワイルドカードになるため、除去数はゼロに減り、答えは次のようになります。`5`。

```最初のリンク リストには不良な隣接ペアが 2 つあるため、2 つの削除が必要です。 アカウントを 1 つ作成すると、すべてのコメントが柔軟になり、リンクされたリストは空になり、レポートは必要なくなります。 アルゴリズムはこの状態をチェックして返します。`1`。
