 ## 解決策
 ## 問題の理解

 私たちは循環リストを持っています`n`モンスターの種類。 更新する前に、次のように入力します。`i`確率で出現する`s[i]`パーセント。 スポーン場所は現在のみ保持されます`k`ランダムに選ばれたタイプ。 選択されたタイプは独自の確率を保持しますが、削除されたタイプはすべて、円の周りを前進するときに最初に遭遇した選択されたタイプにその確率を与えます。 

タスクは、すべての可能なランダムな選択を平均した後、各タイプの予想される最終確率を計算することです。`k`保存されたタイプ。 

重要な部分は、ランダム プールをシミュレートする必要がないということです。 可能なプールの数は次のとおりです。`C(n, k)`、これはたとえにとっても巨大です`n = 500`。 循環順序の対称性を利用し、すべての元の確率の寄与を独立して計算する必要があります。 

以来`n`最大でも 500、`O(n^2)`アルゴリズムは簡単に十分に高速です。 アン`O(n^3)`このアプローチはすでに約 1 億 2,500 万の操作を必要とし、Python では危険ですが、すべてのサブセットを含むものは不可能です。 

間違った解決策が失敗するケースがいくつかあります。 いつ`k = n`、すべてのタイプが常に選択されるため、答えは入力と等しくなければなりません。 例えば：```
3 3
10 20 70
```出力は次のとおりです。```
10 20 70
```誤って隣接する型の貢献を許可する数式は、ここで間違った答えを生成します。 

いつ`k = 1`、ちょうど 1 つのタイプが生き残り、それがすべての確率質量を受け取ります。 のために：```
3 1
10 20 70
```出力は次のとおりです。```
33.333333333333 33.333333333333 33.333333333333
```元の確率に関係なく、どのタイプも同じように唯一選択されたタイプとなる可能性があります。 

循環ラップアラウンドも間違いの原因です。 のために：```
2 1
30 70
```どちらの答えも`50`。 2 番目のタイプはラップ後に最初のタイプの確率を受け取ることができ、最初のタイプは 2 番目のタイプの確率を受け取ることができます。 

## アプローチ

 直接的なアプローチは、考えられるすべてのセットを列挙することです。`k`選ばれたタイプ。 各セットについて、円の周囲を歩き回り、削除されたすべてのタイプを次に選択されたタイプに割り当て、結果として得られる確率を加算することができます。 これは生成ルールに正確に従っているため、これは正しいです。 

問題はセット数です。 たとえ`n = 500`、`C(500, 250)`処理できる範囲をはるかに超えています。 ブルート フォースは必要な複雑さに達していません。 

重要な観察は、期待によって貢献を分離できるということです。 選択されたタイプが確率をどこから受け取るかを尋ねる代わりに、固定された元のタイプの確率がどこへ行くかを尋ねます。 

タイプを考慮する`i`。 その元の確率はタイプに寄与します`i + d`その宛先が選択されている場合、`d`直前のタイプは選択されていません。 残りの選択されたタイプを選択する方法の数は、`d`、実際の位置ではありません。 これにより、円の周囲の距離ごとに固定係数が作成されます。 

遠くまで`d`、距離にあるタイプが存在する確率`d`後ろに`i`に貢献する`i`は：```
C(n-d-1, k-1) / C(n, k)
```分子はもう一方を選択します`k-1`ソースと宛先の間でブロックされていない位置からタイプを選択します。 

これらの係数を 1 回計算すると、すべての回答位置は元の確率の循環加重和にすぎません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(n,k) * n) | O(n) | 遅すぎる |
 | 最適 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 考えられるすべての円形距離の係数を計算します。 距離の場合`d`、タイプが存在する確率を格納します。`d`現在のタイプの後ろの位置は、その確率を現在のタイプに転送します。 これはのみに基づいています`n`、`k`、 そして`d`, したがって、すべての回答位置で再利用できます。 
2. 浮動小数点値を使用して組み合わせを計算します。 二項値自体は非常に大きくなる可能性がありますが、必要なのはその比率だけです。 以来`n`が小さい場合は、double のパスカル三角形で十分です。 
3. 宛先タイプごとに`i`、すべての距離を反復します`d`。 タイプの元の確率を次の位置に追加します。`(i - d) mod n`の係数を掛ける`d`。 
4. 結果として得られる期待確率を出力します。 

アルゴリズムの背後にある不変条件は、すべての元の確率が、考えられる各目的地の確率に従って正確に分布されるということです。 距離の係数`d`目的地が生存し、近くの生存者がすべて不在であるイベントを正確にカウントします。 考えられるすべてのソース寄与が独立して追加されるため、期待値の線形性により、正確な期待される最終確率が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = list(map(float, input().split()))

    comb = [[0.0] * (n + 1) for _ in range(n + 1)]
    comb[0][0] = 1.0
    for i in range(1, n + 1):
        comb[i][0] = 1.0
        comb[i][i] = 1.0
        for j in range(1, i):
            comb[i][j] = comb[i - 1][j - 1] + comb[i - 1][j]

    total = comb[n][k]

    coef = []
    for d in range(n):
        coef.append(comb[n - d - 1][k - 1] / total)

    ans = [0.0] * n
    for i in range(n):
        cur = 0.0
        for d in range(n):
            cur += s[(i - d) % n] * coef[d]
        ans[i] = cur

    print(*ans)

if __name__ == "__main__":
    solve()
```組み合わせテーブルには、`C(a,b)`浮動小数点数としての値。 整数ストレージは、これらの値が大きくなりすぎるため、最終的な計算には比率のみが必要となるため、適切ではありません。 

係数ループは次を使用します。`n - d - 1`それよりも`n - d`。 宛先自体はすでに選択されている必要があり、ソースに近い位置は存在しない必要があります。 この境界は、この問題で最も一般的な 1 つ違いの間違いです。 

モンスター リストが循環しているため、最後の二重ループではモジュロ インデックスが使用されます。 目的地に向けて`i`そして距離`d`、ソースは`(i-d) mod n`。

import io

def solve_case(inp):
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    s = list(map(float, input().split()))

    comb = [[0.0] * (n + 1) for _ in range(n + 1)]
    comb[0][0] = 1.0

        comb[i][0] = comb[i][i] = 1.0

 ## 特殊なケース

 のために`k = n`、すべてのモンスターは生き残ります。 この式では、移動を作成するのに十分な未選択の位置がないため、距離ゼロを除くすべての係数がゼロになります。 このアルゴリズムは、元の配列を返すことになります。 

のために`k = 1`、すべての係数は次のようになります`1/n`。 選択されたモンスターは 1 体だけであり、元の確率はすべて、最終的に同じ選択確率でその 1 体のモンスターに属します。 円形構造は結果には影響しません。 

ラップアラウンドの場合、モジュロインデックスはリストを円として扱います。 始点近くの発信元は終点近くの終点に寄与する可能性があり、距離は周期的に測定されるため、同じ係数計算が引き続き適用されます。
