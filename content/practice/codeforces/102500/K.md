 ## 解決策
 ## 問題の理解

 レースはポジションからの一次元のパスです`0`位置を決める`s`。 このパスの一部の部分は島で占められており、重複しない間隔で表されます。 ノラは島内を移動できないように、常にラインを維持しなければなりません。 彼女は、時間と距離が等しい、途切れることのない水面をサーフィンすることも、距離内の 2 つの安全な位置の間をジャンプすることもできます。`d`、すべてのジャンプに正確なコストがかかります`t`秒。 

課題は、ゴールに到達するまでの最短時間を見つけることです。 答えはルート自体を尋ねるのではなく、最短の移動時間だけを尋ねます。 

島の数は少なく、最大でも 500 です。これが重要な制約です。 座標自体は次のように大きくできます。`10^9`したがって、メートルごとに繰り返すことは不可能です。 レースの長さに比例するソリューションには、最大 10 億回の操作が必要になります。 代わりに、アルゴリズムは島の数と島が作成する重要な位置の数に依存する必要があります。 

よくある間違いは、あるアイランド エンドポイントから別のアイランド エンドポイントに直接ジャンプすることのみを考慮することです。 これにより、ジャンプが水セグメントの中央で開始または終了する最適なルートが失われます。 もう 1 つの間違いは、島のエンドポイントをブロックされた位置として扱うことです。 この問題によりエンドポイントにアクセスできるようになるため、エンドポイントを有効な場所として含める必要があります。 

たとえば、島がない場合は次のようになります。```
5 3 10
0
```答えは`5`, なぜなら、サーフィンを全行程行ったほうが、2回ジャンプするよりも速いからです。 ジャンプのみを考慮する実装では、誤った値が返されます。`20`。 

もう 1 つのエッジ ケースは、アイランドのエンドポイントに正確に到達するジャンプです。```
10 5 1
1
5 6
```答えは`2`。 ノラはそこから飛び降りることができます`0`に`5`、その後から`6`に`10`。 実装で厳密なメソッドが使用されている場合、`< d`代わりに比較`<= d`、これらのジャンプを見逃します。 

最後のエッジケースは、島が 2 つの水域を分離している場合です。```
10 10 100
1
4 6
```答えは`100`、 ない`4`。 からのサーフィン`0`に`4`そしてそれから`6`に`10`可能ですが、反対側に到達するにはジャンプで島を渡る必要があります。 

## アプローチ

 最も直接的な解決策は、考えられるすべての有用な位置をグラフの頂点としてモデル化することです。 頂点は、開始点、終了点、またはアイランドの終点のいずれかを表します。 サーフィンでは、アイランドで区切られていない連続する頂点間にエッジが作成されます。 ジャンプすると、距離が最大で 2 つの頂点の間にエッジが作成されます。`d`。 

この問題には、強引なグラフ構築ですでに十分です。 多くてもあります`2n + 2`頂点の数は最大 1002 です。頂点のすべてのペアをチェックすると、およそ 100 万個の可能なジャンプ エッジが作成されます。 このグラフでダイクストラを実行すると、十分に高速になります。 

より単純なアプローチでは、レースに沿って可能な限りすべてのメートルをシミュレートしようとします。 それはすぐに失敗します。`s`できる`10^9`。 

エンドポイント グラフが有効である理由は、移動モードの有用な変更はすべて島の境界または開始と終了で発生するためです。 ノラが任意の水点に着地した場合、ジャンプを難しくしたりサーフィンの距離を長くしたりすることなく、その途切れることのない水域の残りの動きを最も近い関連するエンドポイントに移動できます。 2 つの連続した関連する位置の間には障害物がないため、エンドポイントのみが問題になります。 

ブルートフォース座標シミュレーションはすべての可能性を表すため機能しますが、座標範囲が膨大であるため失敗します。 島の境界だけが動きに影響を与えるという観察により、考えられる位置の無限のセットを約 1,000 頂点を持つグラフに圧縮することができます。

 | --- | --- | --- | --- |
 | あらゆるメートルにわたる総当たり攻撃 | O(s) | O(s) | 遅すぎる |
 | アイランドエンドポイント上のグラフ | O(n² log n) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 重要なポジションをすべて収集します。 追加`0`そして`s`、次にすべてのアイランドの両方のエンドポイントを追加します。 左から右に並べ替えます。 
2. すべての重要な位置がノードとなるグラフを作成します。 ノードのすべてのペアについて、ジャンプ エッジを考慮します。 それらの間の距離が最大でも`d`、コストでエッジを追加します`t`。 
3. 隣接する重要な位置の間にサーフィン エッジを追加します。 2 つの隣接する位置は、間に島が存在できないため、サーフ エッジによって接続されます。 エッジコストはそれらの座標の差です。 
4. 開始位置からダイクストラのアルゴリズムを実行します。 それぞれのリラクゼーションは、サーフィン動作またはジャンプ動作の選択を表します。 
5. フィニッシュノードの距離を出力します。 

隣接する重要な位置のみがサーフ エッジを受け取る理由は、遠いペアの間に島があるか、隣接するサーフ エッジをチェーンすることですでに到達できるためです。 サーフ エッジをさらに追加しても、最短パスは改善されません。 

機能する理由: Nora が実行できるすべての法的な動きは、このグラフのパスで表されます。 サーフィンは連続した水域を歩くことで表され、すべてのジャンプは開始位置と終了位置の間のジャンプ エッジで表されます。 逆に、グラフのすべてのエッジは、元の問題における法的な動きに対応します。 ダイクストラは負ではないエッジの重みを使用してグラフ内の最短経路を見つけるため、結果として得られる距離は正確に最小レース時間になります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    s, d, t = map(int, input().split())
    n = int(input())

    points = [0, s]
    for _ in range(n):
        l, r = map(int, input().split())
        points.append(l)
        points.append(r)

    points.sort()
    m = len(points)

    graph = [[] for _ in range(m)]

    for i in range(m):
        for j in range(i + 1, m):
            dist = points[j] - points[i]
            if dist <= d:
                graph[i].append((j, t))
                graph[j].append((i, t))

    for i in range(m - 1):
        dist = points[i + 1] - points[i]
        graph[i].append((i + 1, dist))
        graph[i + 1].append((i, dist))

    inf = 10**30
    dist = [inf] * m
    dist[0] = 0

    pq = [(0, 0)]
    while pq:
        cur, u = heapq.heappop(pq)
        if cur != dist[u]:
            continue

        for v, w in graph[u]:
            if cur + w < dist[v]:
                dist[v] = cur + w
                heapq.heappush(pq, (dist[v], v))

    print(dist[-1])

if __name__ == "__main__":
    solve()
```入力処理では、問題の状態が変化する可能性がある座標のみが保存されます。 これらの座標の総数は最大 1002 です。 

グラフの構築では、最初にジャンプを処理します。 頂点の数が少なく、完全なジャンプ グラフを管理できるため、すべてのペアがチェックされます。 サーフ エッジは、並べ替えられた隣接する位置の間にのみ追加されます。これは、これらの位置が障害物のない最大限の部分であるためです。 

ダイクストラ実装では優先キューを使用します。 古いエントリのチェックにより、より適切な距離がすでに見つかった後の古いキュー エントリの処理が回避されます。 

Python の整数はオーバーフローしませんが、無限値は考えられる答えよりもはるかに大きい必要があります。 ルートには多くのジャンプが含まれる可能性があるため、センチネル値が小さいと安全ではありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n² log n) | O(n) 個の頂点と O(n²) 個のエッジがあります。 ダイクストラが走行タイムを独占。 |
 | スペース | O(n²) | 完全なジャンプ グラフには O(n²) 個のエッジが含まれています。 |

 頂点が最大 1002 個ある場合、グラフには約 100 万個の可能なエッジがあります。 これは記憶にぴったりと収まり、ディクストラは制限時間内に終了することができます。 

## テストケース```python
import sys
import io
import heapq

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    def solve():
        input = sys.stdin.readline
        s, d, t = map(int, input().split())
        n = int(input())

        points = [0, s]
        for _ in range(n):
            l, r = map(int, input().split())
            points += [l, r]

        points.sort()
        m = len(points)
        graph = [[] for _ in range(m)]

        for i in range(m):
            for j in range(i + 1, m):
                if points[j] - points[i] <= d:
                    graph[i].append((j, t))
                    graph[j].append((i, t))

        for i in range(m - 1):
            w = points[i + 1] - points[i]
            graph[i].append((i + 1, w))
            graph[i + 1].append((i, w))

        dist = [10**30] * m
        dist[0] = 0
        pq = [(0, 0)]

        while pq:
            cur, u = heapq.heappop(pq)
            if cur != dist[u]:
                continue
            for v, w in graph[u]:
                if cur + w < dist[v]:
                    dist[v] = cur + w
                    heapq.heappush(pq, (dist[v], v))

        return str(dist[-1]) + "\n"

    result = solve()
    sys.stdin = old_stdin
    return result

 ## 特殊なケース

 アイランドがない場合:```
5 3 10
0
```このアルゴリズムでは頂点が 2 つだけ作成されます。`0`そして`5`。 コスト面での優位性が追加されます`5`。 距離が大きいためジャンプエッジは不可能です`d`。 Dijkstra returns`5`。 

正確な距離でジャンプする場合:```
10 5 1
1
5 6
```頂点は`0, 5, 6, 10`。 アルゴリズムは、からのジャンプを追加します。`0`に`5`そしてから`6`に`10`、どちらも費用がかかります`1`。 最終的な答えはこうなります`2`、距離の比較には等価性が含まれている必要があることを示しています。 

水を隔てる島の場合:```
10 10 100
1
4 6
```グラフにはサーフエッジが含まれています`0-4`そして`6-10`、しかし島を横切るサーフエッジはありません。 からのジャンプエッジ`4`に`6`距離が正確なので利用可能です`2`したがって、最短ルートは`100 + 0`ジャンプと2つのサーフセクションは？ 実は一番安い方法は、`0 -> 4`サーフィンによって、`4 -> 6`ジャンプすることで、そして`6 -> 10`サーフィンすること、与えることによって`4 + 100 + 4 = 108`。 このアルゴリズムは、島を必須の障害物として正しく維持し、違法なサーフィンが島を通過することを決して許可しません。
