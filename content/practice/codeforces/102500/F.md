 ## 解決策
 ## 問題の理解

 私たちは持っています`n`人々。 各人物は一連の数字で表されます。 両方の説明に現れる数字が存在する場合、2 人を直接結び付けることができます。 必要な出力は、可能な接続のグラフ全体ではなく、正確に含まれる証明です。`n - 1`このような直接的なつながり。 これらの接続により、すべての人が他のすべての人から連絡できるようにする必要があります。 

これは、人々が頂点であり、共有される数字がエッジを作成するグラフ内でスパニング ツリーを見つけるのと同じです。 問題は、多くの人が同じ番号を共有できるため、すべてのエッジを明示的に構築するとコストがかかりすぎる可能性があることです。 

到達できる人数は`2 * 10^5`、すべての人々の説明の合計数も最大で`2 * 10^5`。 これは、アルゴリズムが指定された各数値を少数回のみ処理する必要があることを意味します。 価値を共有する人々のすべてのペアを構築すると、最悪の場合、二次関数になる可能性があります。 たとえば、すべての人のリストに 1 つの数字が含まれている場合、明示的なグラフには約`n * (n - 1) / 2`エッジ、つまり周囲にある`2 * 10^10`いつ`n = 2 * 10^5`、利用可能な時間と記憶をはるかに超えています。 

いくつかのケースでは注意が必要です。 誰も番号を共有しない場合、異なるグループを接続するエッジが存在しないため、答えは不可能です。 

例えば：```
2
1 5
1 6
```正しい出力は次のとおりです。```
impossible
```すべての人のペアが何らかの形で接続できると想定する不注意な実装では、無効なリレーションが出力される可能性があります。 

もう 1 つのケースは、すべての人々がチェーンを通じてつながっているものの、最初の人物とは直接つながっていない場合です。```
3
1 1
2 1 2
1 2
```有効な答えは次のとおりです。```
1 2 1
2 3 2
```人物 1 を人物 3 に直接接続しようとすると、番号を共有していないため間違っています。 

3 番目の特殊なケースは、非常に一般的な番号が繰り返し使用されることです。 出力には正確に含まれている必要があります`n - 1`関係、すべての可能な関係ではありません。 たとえば、すべての人が番号を持っているとすると、`7`必要なのは、次のツリーだけです。`n - 1`すべての可能なペアではありません。 

## アプローチ

 直接的な解決策は、人々のグラフを構築することになります。 すべての番号について、その番号を含むすべての人々を保存し、そのグループ内のすべてのペアを接続することができます。 生成されたすべてのエッジが有効な共有数を表すため、このグラフは正しいです。 これを構築した後、深さ優先検索または共用体検索構造によってスパニング ツリーを見つけることができます。 

問題は生成されるエッジの数です。 全ての数字の中に一つの数字が出た場合`n`説明、その 1 つの値が作成する`n * (n - 1) / 2`エッジ。 最大入力サイズでは、これを保存または処理することは不可能です。 

重要な点は、考えられるすべてのエッジが必要なわけではないということです。 すべての人々を結び付けるのに十分なエッジだけが必要です。 多くの人が共有する番号の場合は、その番号を使用したチェーンまたはスターで十分です。 各番号に対して 1 人の代表者を保持し、その後その番号を持つすべての人をその代表者に接続することができます。 これにより、数値の出現ごとに最大 1 つの有用なエッジが作成されます。 

人物を処理する際、数字をコネクタとして扱うことができます。 最初に番号が付いた人がそのコネクタの所有者になります。 同じコネクタを使用する後続の人はすべて、その所有者に接続できます。 すべての数値が処理された後、生成されたエッジは有効な接続のみを使用してグラフを形成します。 そのグラフに次の内容が含まれている場合`n - 1`エッジを作成し、すべての頂点を接続する、スパニング ツリーです。

 | ブルートフォース | 最悪の場合は O(S²) (S は記述の総数 | O(S²) | 遅すぎる |
 | 最適 | O(S) | O(S) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての人の数字のリストを読みます。 各番号からその番号を最初に見た人までの地図を管理します。 
2. 個人に属するすべての番号について、別の人がその番号をすでに導入していないかどうかを確認します。 そうでない場合は、現在の人物を代表者として保存します。 「はい」の場合、この番号を使用して現在の人物と代表者の間にエッジを作成します。 

代表者がハブとして機能します。 両方のエンドポイントに同じ番号が含まれているため、この方法で作成されたすべての接続は有効です。 
3. すべての入力が処理された後、作成された接続の数を確認します。 以下の場合は、`n - 1`、グラフが接続できないので出力`impossible`。 
4. それ以外の場合は、保存されているすべての接続を出力します。 

なぜ効果があるのか:

 すべての番号について、その番号を含むすべての人々は、その番号に選ばれた代表者を通じてつながります。 これは、エッジの小さなサブセットのみを保持しても、考えられるすべての元の接続グループが接続されたままであることを意味します。 最終的なグラフにスパニング ツリーを形成するのに十分なエッジがある場合、生成された接続によってすべての人々がつながります。 そうでない場合、一部の人々のグループは番号を共有したことがないため、有効な証拠は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    owner = {}
    ans = []

    for i in range(1, n + 1):
        data = list(map(int, input().split()))
        m = data[0]
        for x in data[1:]:
            if x in owner:
                ans.append((i, owner[x], x))
            else:
                owner[x] = i

    if len(ans) != n - 1:
        print("impossible")
    else:
        out = []
        for a, b, x in ans:
            out.append(f"{a} {b} {x}")
        print("\n".join(out))

if __name__ == "__main__":
    solve()
```辞書`owner`各番号に関連付けられた最初の人物を保存します。 値が最初に出現しても、他に接続する人がまだいないため、エッジは作成されません。 それ以降の出現ごとに、正確に 1 つのエッジが作成されます。 

このアルゴリズムは、リストされた数値の合計数が`2 * 10^5`したがって、すべての説明を 1 回繰り返すだけで十分です。 Python の辞書操作は定数時間であることが期待され、ソリューション全体が線形になります。 

最終的なエッジ数のチェックが必要です。 接続されたグラフ`n`少なくとも頂点が必要です`n - 1`この構造により、同じ出現に対して重複する不要なエッジが作成されることはありません。 カウントが正確でない場合`n - 1`、生成されたグラフは必要な証拠にはなりません。

 ## 特殊なケース

 孤立したグループの場合、両方のグループに数値が出現しないため、アルゴリズムはエッジを挿入しません。 入力では:```
