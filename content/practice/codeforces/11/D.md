 ## 解決策
 ## 問題の理解

 無向グラフ内の単純なサイクルの数を数えるように求められます。 単純なサイクルは、頂点やエッジが繰り返されない閉ループです。 入力により頂点の数が得られます`n`そしてエッジの数`m`、 に続く`m`どの頂点が接続されているかを表す整数のペア。 出力は、単純なサイクルの合計数を表す単一の整数です。 

ここでの重要な制約は、`n`は最大でも 19 です。これは、頂点のサブセットに基づく指数関数アルゴリズムが実行できるほど十分に小さいため、$2^{19}$およそ50万です。 エッジの数`m`問題文では制限されていませんが、実際にはこれを超えることはできません$n(n-1)/2$グラフが単純なので。 これは、考えられるすべての頂点シーケンスを調べる強引なアプローチは、階乗増加によりすぐに実行不可能になることを意味します。 頂点のすべての順列を列挙し、それがサイクルを形成しているかどうかを確認しようとする不用意なアプローチは、たとえ`n=10`。 

考慮すべきエッジ ケースは、エッジがないか、頂点が 1 つしかないグラフです。 例えば、`n=1, m=0`サイクルが存在しないため、0 を出力する必要があります。 もう 1 つの微妙なエッジ ケースは、ツリーを形成するグラフです。 ツリーにはサイクルがありません。適切な記録を行わずにパスをチェックする単純なアルゴリズムでは、それ自体をループバックするパスを誤ってサイクルとしてカウントする可能性があります。 クリークはサイクル数を最大化するため、チェックする価値があります。 

## アプローチ

 ブルートフォースアプローチは、頂点のすべてのサブセットを試し、各サブセットのすべての順列を生成し、それがサイクルを形成しているかどうかを確認することです。 これは正しいです。単純なサイクルは頂点のサブセットの何らかの順列に対応する必要があるからです。 ただし、順列の数は増加します。`n!`、そしてさらには`n=10`これはサブセットあたり 300 万回を超える操作となり、実行不可能になります。 

重要な洞察は、2 つの事実を利用できるということです。 まず、グラフが小さい（`n <= 19`)、これにより頂点のサブセットをビットマスクとして表現できるようになります。 第 2 に、サイクルは各頂点が 1 回だけ訪問される閉じたパスであり、動的プログラミングはサブセットにわたる頂点間のパスを効率的にカウントできます。 定義できます`dp[mask][v]`頂点に到達する方法の数として`v`の頂点を正確に訪問する`mask`の最小頂点から開始`mask`。 したがって、サイクルは単なるサブセットです。`dp[mask][v]`エッジを通って開始頂点に戻ることができ、最小の頂点を開始点として固定することで、各サイクルが正確に 1 回カウントされることを保証できます。 

ブルートフォースは構築によって正確性が保証されているため機能しますが、階乗増加により失敗します。 ビットマスク動的プログラミングのアプローチは、階乗の複雑さを次のように削減するため機能します。`O(n * 2^n)`、管理可能です`n = 19`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n) | 遅すぎる |
 | ビットマスク DP | O(n * 2^n) | O(n * 2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点数を読み取る`n`そしてエッジ`m`隣接行列を構築します`adj`そのような`adj[u][v] = True`間にエッジがある場合`u`そして`v`。 隣接マトリックスにより、接続性を一定時間チェックできます。 
2. DP テーブルの初期化`dp[mask][v]`どこ`mask`訪問した頂点のセットを表すビットマスクです。`v`パスの最後の頂点です。 テーブルには、頂点を正確に訪問するパスの数が保存されます。`mask`で終わる`v`の最小頂点から開始します。`mask`。 
3. 頂点ごとに`v`、 セット`dp[1 << v][v] = 1`。 これは頂点からパスを開始することを表します`v`だけで`v`道中で。 
4. 全体を反復処理する`mask`1から`(1 << n) - 1`。 頂点ごとに`u`で`mask`、すべての隣人に配慮する`v`の`u`。 もし`v`まだ入っていない`mask`そして`v`の最小頂点より大きいです`mask`(二重カウントサイクルを防ぐため)、更新します`dp[mask | (1 << v)][v] += dp[mask][u]`。 これにより、で終わるすべてのパスが拡張されます。`u`追加することで`v`。 
5. DP テーブルを埋めた後、サイクルをカウントします。 サブセットごとに`mask`少なくとも 3 つの頂点がある場合は、最小の頂点を見つけます`s`。 頂点ごとに`v`で`mask`以外の`s`、間にエッジがある場合`v`そして`s`、 追加`dp[mask][v]`答えに。 修正したため、各サイクルは 1 回だけカウントされます。`s`サイクル内の最小の頂点として。 
6. 合計カウントを出力します。 

ここでの不変条件は、`dp[mask][v]`の最小頂点からのすべてのパスを正しくカウントします。`mask`に`v`の頂点を正確に使用して`mask`。 パスを開始点より大きい頂点にのみ延長することで、異なる回転で同じサイクルが複数回カウントされるのを防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
adj = [[False] * n for _ in range(n)]
for _ in range(m):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    adj[a][b] = adj[b][a] = True

dp = [[0] * n for _ in range(1 << n)]
for v in range(n):
    dp[1 << v][v] = 1

for mask in range(1, 1 << n):
    # find smallest vertex in mask
    s = (mask & -mask).bit_length() - 1
    for u in range(n):
        if not (mask & (1 << u)):
            continue
        for v in range(n):
            if adj[u][v] and not (mask & (1 << v)) and v > s:
                dp[mask | (1 << v)][v] += dp[mask][u]

ans = 0
for mask in range(1, 1 << n):
    if bin(mask).count("1") < 3:
        continue
    s = (mask & -mask).bit_length() - 1
    for v in range(n):
        if v != s and (mask & (1 << v)) and adj[v][s]:
            ans += dp[mask][v]

print(ans)
```隣接行列により、定数時間の近隣チェックが可能になります。 DP の初期化では、各頂点から始まるパスが設定されます。 重複したカウントを避けるために、マスク内の最小の頂点よりも大きい頂点のみを慎重に拡張します。 最後のループは、開始頂点に戻ることができるパスを合計して、少なくとも 3 の長さのサイクルのみをカウントします。
