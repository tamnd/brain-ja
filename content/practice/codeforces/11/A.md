 ## 解決策
 ## 問題の理解

 整数の配列があり、すべての要素がその前の要素よりも厳密に大きくなるようにしたいと考えています。 許可される唯一の操作は、単一の要素を選択し、それを正確に増加させることです`d`。 この操作を使用するたびに 1 回の移動としてカウントされます。 

タスクは、配列を厳密に増加するシーケンスに変換するために必要な最小移動数を見つけることです。 

制約は十分に小さいため、二次解でも快適に通過できます。 と`n ≤ 2000`、`O(n²)`アルゴリズムは最悪の場合でも約 400 万回の操作を実行しますが、これは Python の 1 秒の制限には問題ありません。 同時に、問題の構造は、単一パスで配列を貪欲に処理できる必要があることを示唆しています。 

重要な観察は、各位置は前の位置にのみ依存するということです。 最終的な値を決定したら、`a[i-1]`、有効な最小値`a[i]`は修正されています: 少なくとも次のようになる必要があります`a[i-1] + 1`。 

いくつかの特殊なケースでは、不注意な実装が簡単に壊れてしまう可能性があります。 

すでに増加している配列を考えてみましょう。```
3 5
1 7 20
```答えは`0`。 間違った実装でも操作が適用される可能性があります。`<=`値が間違っているか、不必要に値が更新されます。 

隣接する値が等しいということもよくある落とし穴です。```
3 2
1 1 1
```正しい答えは、`3`。 

シーケンスは次のように展開します。```
1 1 1
1 3 1
1 3 5
```2 番目の要素には 1 回の操作が必要ですが、3 番目の要素は 1 回の操作を超える必要があります。`3`、オリジナルではありません`1`。 変更後に配列の更新を忘れると、間違ったカウントが生成されます。 

ギャップが次で割り切れない場合には、より微妙なケースが発生します。`d`:```
2 3
5 6
```配列はすでに増加しているため、答えは次のとおりです。`0`。 

ただし、次の場合:```
2 3
5 5
```2 番目の値は少なくとも次の値になる必要があります`6`。 ワン操作で次のように変わります。`5`に`8`、したがって、答えは次のとおりです`1`。 

次のような通常の整数除算を使用します。```
needed = (target - current) // d
```ここで失敗するのは、`1 // 3 = 0`。 天井分割が必要です。 

もう 1 つの厄介な例は次のとおりです。```
2 4
10 1
```2 番目の値は次の値を超える必要があります`10`、したがって、少なくとも到達する必要があります`11`。 

到達可能な値のシーケンスは次のとおりです。```
1 -> 5 -> 9 -> 13
```必要な手は 2 つではなく 3 つです。 

## アプローチ

 ブルートフォースアプローチは簡単です。 配列を左から右にスキャンします。 いつでも`a[i]`厳密には以下より大きくありません`a[i-1]`を繰り返し追加します`d`条件が真になるまで。 各追加は 1 つの移動としてカウントされます。 

すべての操作で現在の要素が増加するだけであり、以前に要素を大きくしても将来の位置が損なわれることはないため、この方法は正しいです。 問題は効率です。 もし`d = 1`ギャップが大きい場合は、個別に多くの追加を実行する可能性があります。 最悪の場合、値が数百万に達し、ループの反復回数が不必要に大きくなる可能性があります。 

例えば：```
2 1
1000000 1
```2 番目の要素では、1,000,000 回のループ反復が必要になります。 

重要な洞察は、追加を 1 つずつシミュレートする必要がないということです。 現在の値の場合`x`そして必要最低限​​の`need`、必要な加算の数を直接計算できます。 

私たちが望んでいるのは:```
x + k*d > previous
```同様に:```
x + k*d >= previous + 1
```それで：```
k >= (previous + 1 - x) / d
```有効な最小の整数`k`はその割合の上限です。 

これにより、繰り返される更新のブルートフォースが直接的な数学的計算に変わります。 引き続き配列を左から右に処理しますが、すべての位置は定数時間で処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(総操作数) | お(1) | 遅すぎる可能性があります |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、応答カウンターを初期化します。`0`。 
2. インデックスから開始して左から右に配列を処理します。`1`。 
3. 各位置について、次のことを確認します。`a[i] > a[i-1]`。 
4. 条件がすでに成立している場合は、この位置を変更する必要がないため、次の要素に移動します。 
5. それ以外の場合、現在の要素が到達する必要がある最小値を計算します。```
target = a[i-1] + 1
```6. の加算数を計算します。`d`少なくとも到達する必要がある`target`。 

必要な増加量は次のとおりです。```
target - a[i]
```すべての操作が正確に加算されるため、`d`、操作の数は次のとおりです。```
ceil((target - a[i]) / d)
```整数演算の場合:```
ops = (target - a[i] + d - 1) // d
```7.追加`ops`答えに。 
8. 現在の配列値を更新します。```
a[i] += ops * d
```この更新された値は、次の要素の基準になります。 

### なぜ効果があるのか

 アルゴリズムは、インデックスの処理後も不変条件を維持します。`i`、接頭辞`a[0...i]`可能な限り最小限の操作数で厳密に増加しています。 

加工時`a[i]`、前の値はすでに最適に固定されています。 の有効な最終値`a[i]`より大きくなければなりません`a[i-1]`。 このような到達可能な最小値を選択することが常に最適です。`a[i]`不必要に大きくすると、将来の要素を満たすことが難しくなるだけです。 すべての操作で値が正確に変更されるため、`d`、天井除算は、必要な操作の正確な最小数を計算します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, d = map(int, input().split())
a = list(map(int, input().split()))

answer = 0

for i in range(1, n):
    if a[i] <= a[i - 1]:
        target = a[i - 1] + 1
        ops = (target - a[i] + d - 1) // d

        answer += ops
        a[i] += ops * d

print(answer)
```この解決策は、貪欲な左から右への戦略に直接従います。 

ループはインデックスから始まります`1`最初の要素は変更する必要がないためです。 各位置については、直前の値のみが考慮されます。 初期の要素はすでに最適な増加プレフィックスを形成しています。 

天井分割式は最も重要な実装の詳細です。```
(target - a[i] + d - 1) // d
```通常の除算を使用すると、必要な増加が次の倍数にならない場合は失敗します。`d`。 

配列の更新:```
a[i] += ops * d
```も不可欠です。 今後の要素は、元の値ではなく、変更された値と比較する必要があります。 

Python の整数は大きな値を自動的に処理するため、オーバーフローは心配ありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, d = map(int, input().split())
    a = list(map(int, input().split()))

    answer = 0

    for i in range(1, n):
        if a[i] <= a[i - 1]:
            target = a[i - 1] + 1
            ops = (target - a[i] + d - 1) // d

            answer += ops
            a[i] += ops * d

    print(answer)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("4 2\n1 3 3 2\n") == "3\n", "sample 1"

# minimum size, already increasing
assert run("2 1\n1 2\n") == "0\n", "minimum increasing"

# all equal values
assert run("3 2\n1 1 1\n") == "3\n", "all equal"

# ceiling division case
assert run("2 3\n5 5\n") == "1\n", "needs ceiling division"

# large gap
assert run("2 4\n10 1\n") == "3\n", "large jump"

# strictly decreasing
assert run("5 1\n5 4 3 2 1\n") == "20\n", "decreasing sequence"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`3 2 / 1 1 1`|`3`| カスケード更新 |

 ## 特殊なケース

 隣接する値が等しいとみなします。```
3 2
1 1 1
```インデックス時`1`、前の値は`1`, したがって、ターゲットは次のようになります`2`。 1 回の操作で値が変更されます`1`に`3`。 

現在の配列は次のようになります。```
1 3 1
```インデックス時`2`、以前の値は現在です`3`, したがって、ターゲットは次のようになります`4`。 2つの操作が変わります`1`の中へ`5`。 

合計操作:```
1 + 2 = 3
```アルゴリズムは常に更新された以前の値と比較するため、成功します。 

ここで、必要な増加量が次の式で割り切れない場合を考えてみましょう。`d`:```
2 4
7 4
```2 番目の値は少なくとも次の値になる必要があります`8`。 

必要な増加量は次のとおりです。```
8 - 4 = 4
```1 回の操作で十分です。```
4 + 4 = 8
```式は以下を計算します。```
(4 + 4 - 1) // 4 = 1
```それは正しいです。 

最後に、すでに有効なシーケンスを考えてみましょう。```
4 10
1 20 30 40
```すべての要素はすでに厳密な不等式を満たしています。 条件:```
if a[i] <= a[i - 1]:
```決してトリガーされないため、答えは残ります`0`。 

これにより、アルゴリズムが不必要な操作を実行しないことが確認されます。
