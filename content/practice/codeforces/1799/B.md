 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 2 つの異なるインデックスを繰り返し選択できます$i$そして$j$、要素をインデックスに設定します$i$インデックスの要素による除算の上限まで$j$。 タスクは、この操作を何度でも実行して配列のすべての要素を等しくできるかどうかを判断し、可能であればそれを行うための一連の操作を生成することです。 

入力により次のことが保証されます。$n$配列サイズは最大 100 であり、すべての合計$n$テスト ケースの数は最大 1000 です。各配列要素は次のような大きさにすることができます。$10^9$。 これらの制約は、立体的な操作を行う余裕がないことを示唆しています。$n$、しかしおおよそまで何でも$O(n^2)$最大配列サイズが小さい場合には実現可能です。 

明らかではないエッジケースは、配列に次のものが含まれる場合に発生します。`1`または繰り返しの要素。 例えば、`[2, 1]`1 による除算は他の数値を減らすことはできますが、増やすことはできないため、2 は 2/1=2 → 2 になり、その後 2/2=1 になり、最終的に 1 に一致するため、不可能です。最小の数値が 1 であり、他の数値がその累乗ではないシナリオを検出する必要があります。 すべての要素が既に等しい配列は、たとえサイズが大きくても、すぐにゼロ演算を出力する必要があります。 小さいほうが 1、大きいほうが 1 より大きい 2 つの数値を含む配列は不可能です。大きいほうの数値が小さいほうの数値に正確に割り切れない限り、上限分割を繰り返しても等価性を「作り出す」ことはできないからです。 

## アプローチ

 素朴なアプローチは、すべての可能な操作をブルートフォース方式でシミュレートすることです。つまり、すべてのペアを選択します。$i, j$すべての数値が収束するまで、上限分割を繰り返し適用します。 これは正しいですが、各演算が最悪の場合、大きな数値を一連の小さな数値に分割する可能性があるため、遅すぎます。$O(\log(\text{max\_value}))$要素ごとのステップ。 と$n=100$そして最大の数字$10^9$、これは手に負えません。 

重要な洞察は、すべての要素を等しくする一連の操作では、最終的にはすべてを配列内の最小要素に削減する必要があるということです。 より大きな数で除算しても要素を増やすことはできないため、配列内の最小要素が増えることはありません。 これにより、貪欲な戦略を構築できます。つまり、すべての数値が最小値と一致するまで、最大の数値を小さい数値で割って繰り返し減らすというものです。 最小値が 1 で、一部の要素が 1 より大きい場合、無制限のステップ数未満で 1 より大きい別の数値を使用して数値を 1 に減らすことはできないため、この問題は不可能ですが、制約により、すべての有効な解には最大 30n 回の操作が必要であることが保証されます。 

チェックする必要があるのは 2 つのプロパティだけです。 まず、最小要素が 1 で、すべての要素が 1 でない場合は不可能です。 2 番目に、それ以外の場合は、配列をソートし、すべての数値が等しくなるまで、現在の最小値で大きな数値を繰り返し減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log(max(a))) | O(n) | 遅すぎる |
 | 最小値による貪欲な削減 | O(n log(max(a))) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、最小の要素を特定します。`m`配列内で。 これは、すべての要素が達成したい目標値になります。 
2. もし`m`は 1 であり、配列はまだ`[1, 1, ..., 1]`、許可された操作では他の数値を 1 に減らすことができないため、-1 が出力されます。 
3. それ以外の場合は、より大きいすべての配列要素を反復処理します。`m`。 それぞれの要素について`a_i`を繰り返し選択します`a_j = m`そして割り当てます`a_i := ceil(a_i / a_j)`それまで`a_i`等しい`m`。 各操作が結果リストに追加されます。 
4. すべての操作をペアとして追跡する`(i, j)`どこ`i`は削減される要素のインデックスであり、`j`は現在の最小値のインデックスです。 
5. すべての要素を処理した後、一連の操作に続いて操作の合計数を出力します。 

機能する理由: すべての操作により、数値が最小値に向かって減少します。 上限分割により、可能な整数を決してスキップしないことが保証されます。 不変条件は、最小要素が決して増加しないため、他のすべての要素が最終的にそれに一致することです。 最大要素は分割することしかできず、要素ごとのステップ数は最小要素との相対値が対数であるため、アルゴリズムは次の時間内で完了します。`30n`問題ステートメントで保証されている動作。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        min_val = min(a)
        
        if min_val == 1 and any(x != 1 for x in a):
            print(-1)
            continue
        
        operations = []
        while True:
            max_val = max(a)
            if max_val == min_val:
                break
            for i in range(n):
                if a[i] > min_val:
                    a[i] = math.ceil(a[i] / min_val)
                    operations.append((i+1, a.index(min_val)+1))
        
        print(len(operations))
        for op in operations:
            print(op[0], op[1])

if __name__ == "__main__":
    solve()
```この解決策は、テスト ケースの数を読み取ることから始まります。 各テスト ケースについて、最小値が特定されます。 最小値が 1 で、すべての数値が 1 ではない場合は、-1 が出力されます。 それ以外の場合は、上限分割を実行し、各操作を記録することで最小値より大きい数値を繰り返し減らします。 操作を記録する場合、インデックスは 1 から始まります。 

微妙な点は、`a.index(min_val)`常に最小値の最初の出現を返します。 すべての演算には除算を実行するための最小限の要素のみが必要であるため、これで十分です。 使用する`math.ceil`決してアンダーラウンドにならないようにします。 

## 実用的な例

 **例 1**:`[4, 3, 2]`| ステップ | 配列 | 操作 |
 | --- | --- | --- |
 | 0 | [4、3、2] | - |
 | 1 | [2、3、2] | 1 / 3 |
 | 2 | [2、2、2] | 2 / 3 |

 これは、アルゴリズムが最大の要素を最小値まで削減し、その後、残りのより大きな要素を削減することを示しています。 すべての要素が 2 に達します。 

**例 2**:`[2, 1]`| ステップ | 配列 | 操作 |
 | --- | --- | --- |
 | 0 | [2、1] | - |
 | - | - | 不可能 |

 ここで最小値は 1 ですが、他の要素は 2 です。アルゴリズムはすぐに -1 を出力します。
