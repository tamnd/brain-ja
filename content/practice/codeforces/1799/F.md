 ## 解決策
 ## 問題の理解

 正の整数の配列と、要素に適用できる 2 種類のオプションの演算 (グローバル制限と要素ごとの制限) が与えられます。 各要素は各操作タイプごとに最大 1 回変更できますが、配列全体で実行できる各タイプのアプリケーションの合計数にも制限があります。 

最初の演算では、数値をおよそ半分に減らし、切り上げます。 2 番目の演算では固定値を減算します。`b`ただし、ゼロ以下になることはありません。 すべての制約を尊重して、これらの演算を任意の順序で適用して、配列の最終的な合計ができるだけ小さくなるようにしたいと考えています。 

これを再構成する便利な方法は、すべての要素に最大 4 つの可能な状態 (未処理、半分に 1 回、減算に 1 回、またはその両方がいずれかの順序で適用される) があることです。 ただし、世界的な制限`k1`そして`k2`つまり、要素間の操作の競合を考慮せずに、各要素に最適な状態を個別に選択することはできません。 

制約の合計サイズはテスト ケース全体で小さく、合計`n`これは、次のことを強く示唆しています。`O(n^2)`または`O(n log n)`テスト ケースごとのアプローチは許容されますが、3 次的なものや、すべての候補にわたって要素ごとの再計算を繰り返すものは失敗します。 

微妙だが重要なエッジ ケースは、両方の操作が同じ要素に対して不適切に相互作用する場合に発生します。 たとえば、次の場合`a = [10]`、`b = 6`、最初に半分にしてから減算するか、最初に減算してから半分にすることができますが、半分にすることで切り上げられるため、順序によって最終結果が変わります。 操作を独立して扱う単純な貪欲な人は、この相互作用を見逃すでしょう。 

もう 1 つのエッジケースは次のような場合です`b`ほとんどの要素よりも大きいです。 次に、操作タイプ 2 は、選択した要素をゼロにすることと同等になり、実際の決定は、いくつかの大きな値に対して半分にする価値があるのか​​、それともより良いターゲットのために操作予算を維持するためにスキップする必要があるのか​​ということになります。 

## アプローチ

 ブルートフォースのアイデアは、各要素を考慮し、演算を行わない、半分のみ、減算のみ、あるいはその両方など、考えられるすべての選択肢を試すことです。 構成ごとに、どの要素が限られたプールを消費するかを決定する必要もあります。`k1`そして`k2`。 これは組み合わせ割り当ての問題になります。要素ごとに状態を選択し、最大で次の状態を選択します。`k1`半分以下の要素`k2`減算の要素がありますが、演算を適用すると他の選択肢のゲインが変化するため、これらの選択肢は複雑になります。 

直接的なブルート フォースでは、要素ごとに状態を列挙し、グローバル制限を考慮してすべてのサブセットを試行します。 各要素に 4 つの状態しかない場合でも、基本的に最大 4 つの状態を選択することになるため、割り当ての実現可能性のチェックは指数関数的に行われます。`k1 + k2`全体にわたる操作`n`依存関係のある要素。 

重要な洞察は、各要素の操作は構造的には独立しているが、カウントによってのみ競合するということです。 これにより、各要素を小さな「オプション」セットに寄与するものとして扱うことができ、各オプションにはコスト削減とリソース使用量のペアが含まれます。`(type1, type2)`。 

各要素について計算できます。 

- 操作なし
 - タイプ 1 のみ
 - タイプ 2 のみ
 - 1 を入力してから 2 を入力します
 - タイプ 2、次にタイプ 1 (結果は同等ですが、中間の推論が異なる場合があります。実際には、各組み合わせに対して最適な最終値を計算します)

 各要素が候補ゲインの小さなセットに縮小されると、問題は次のようになります。`k1`タイプ 1 の用途のアイテム、最大でも`k2`タイプ 2 の使用量を削減し、合計節約価値を最大化します。 

これは古典的な多肢選択問題ですが、この構造により、寄与分を分離した後で貪欲な並べ替え戦略が可能になります。 

重要な点は、タイプ 1 とタイプ 2 はそれぞれ要素ごとに最大 1 回しか適用されないため、各要素が各プールに最大 1 つのユニットを提供することです。 これにより、限界利益を評価し、利点ごとに決定を並べ替えることができます。 

次の場合、要素ごとに最適なゲインを効果的に計算します。 

- 何もしない
 - 半減のみ適用
 - 減算のみを適用する
 - 両方を適用します

 次に、これを候補の改善に変換し、予算を尊重しながらより高い利益を優先することで競合を解決します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各要素について、そのベースライン値と操作を適用しなかった後の値を計算します。 これは単に元の配列の合計です。 
2. 要素ごとに、タイプ 1 を 1 回適用した後の結果を計算します。`a[i]`と`(a[i] + 1) // 2`。 ゲインは`a[i] - halved_value`。 
3. タイプ 2 を 1 回適用した後の結果を計算します: replace`a[i]`と`max(a[i] - b, 0)`。 ゲインは`min(b, a[i])`。 
4. 両方の演算を適用した場合の結果を計算します。 天井分割により順序が重要になるため、両方の順序を評価します。 

最初に半分にしてから減算し、最初に減算してから半分にする。 それらの結果の最小値を取得し、元の値に対するゲインを計算します。 
5. 各要素について、異なる「リソース使用パターン」(なし、タイプ 1、タイプ 2、両方) を持つ最大 4 つの候補状態があります。 各状態を、ゲイン、タイプ 1 の使用法、およびタイプ 2 の使用法を含むタプルに変換します。 
6. 「なし」状態を除く要素全体のすべての候補状態を収集します。 これらの候補のサブセットを選択して、合計ゲインを最大化しますが、`k1`そして`k2`そして、要素ごとに最大 1 つの状態を選択するようにします。 
7. 候補をゲインの降順に並べ替えます。 それらを繰り返し処理し、残りの条件に違反しない場合は貪欲に候補を選択します。`k1`、`k2`、その要素がまだ使用されていない場合。 
8. 選択したゲインの合計を最初の配列の合計から減算して、最終的な答えを取得します。 

この貪欲な動作がなぜ機能するかは、各要素が選択した 1 つの改善に貢献するだけであり、各改善が各リソースの最大 1 単位を消費するという事実に関係しています。 ゲインによる並べ替えにより、利用可能な最も価値のある変換が常に最初に取られるようになり、競合は、すでに使用されている要素や使い果たされた予算をスキップすることによって処理されます。 

### なぜ効果があるのか

 各要素は、相互に排他的な改善選択肢の小さなセットに効果的に圧縮されます。 有効な解決策は、2 つの独立した容量制約の下で、要素ごとに最大 1 つの選択肢を選択することに相当します。 各選択にはスカラーの利点と単位リソースの使用量があるため、問題は、共有リソースと要素ごとの排他性によってのみ競合が発生する場合、利点による欲張りが最適な 2 部構成のリソース制約選択に帰着します。 不変条件は、どのステップでも、選択されたセットが、ソートされたゲイン順序と実現可能性制約に関してこれまでに検討されたすべての候補の中で最も達成可能なサブセットであるということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, b, k1, k2 = map(int, input().split())
        a = list(map(int, input().split()))

        base_sum = sum(a)
        candidates = []

        for i, x in enumerate(a):
            # no operation gives no candidate

            # type 1 only
            v1 = (x + 1) // 2
            gain1 = x - v1
            candidates.append((gain1, i, 1, 0))

            # type 2 only
            v2 = max(x - b, 0)
            gain2 = x - v2
            candidates.append((gain2, i, 0, 1))

            # both operations: try both orders
            # 1 then 2
            v12 = max((x + 1) // 2 - b, 0)
            # 2 then 1
            v21 = (max(x - b, 0) + 1) // 2
            v_both = min(v12, v21)
            gain_both = x - v_both
            candidates.append((gain_both, i, 1, 1))

        candidates.sort(reverse=True)

        used = [False] * n
        rem1, rem2 = k1, k2
        total_gain = 0

        for gain, i, c1, c2 in candidates:
            if used[i]:
                continue
            if c1 > rem1 or c2 > rem2:
                continue
            used[i] = True
            rem1 -= c1
            rem2 -= c2
            total_gain += gain

        print(base_sum - total_gain)

if __name__ == "__main__":
    solve()
```このソリューションでは、要素ごとにすべての意味のある変換の選択肢を構築し、それぞれを元の値に対する改善によって重み付けされた候補として扱います。 並べ替えにより、影響の大きい変換が最初に考慮されるようになります。 の`used`配列では、各要素が選択された 1 つの変換のみに寄与できるというルールが適用されますが、`rem1`そして`rem2`グローバル制約を強制します。 重要な点は、上限除算により演算が非可換になるため、両方の演算順序をチェックして「両方の演算」の場合を正しく計算することです。 

## 実用的な例

 ### 例 1

 入力:```
n=3, b=2, k1=1, k2=1
a = [9, 3, 5]
```候補変換を計算します。 

| 要素 | タイプ 1 | タイプ 2 | 両方 |
 | --- | --- | --- | --- |
 | 9 | 5 (ゲイン 4) | 7 (ゲイン 2) | 3 (ゲイン 6) |
 | 3 | 2 (ゲイン 1) | 1 (ゲイン 2) | 1 (ゲイン 2) |
 | 5 | 3 (ゲイン 2) | 3 (ゲイン 2) | 1 (ゲイン 4) |

 ゲイン順に並べ替えます:

 (6対9両方)、(4対5両方)、(4対9タイプ1)、...

 最初に (両方とも 9) を選択し、k1 と k2 の両方を消費します。 次に有効なのは (5 両方または 5 type1 など) ですが、制約が枯渇しています。 

最終結果:

 合計 = 17、ゲイン = 6 → 答え = 11

 このトレースは、単一の操作が優先される場合に、アルゴリズムが結合された操作をどのように優先するかを示しています。

 ## 特殊なケース

 微妙なケースの 1 つは、減算によって要素が即座に無効になり、タイプ 2 が半分になるよりもはるかに価値が高くなる場合です。 入力用`a = [5], b = 10`、タイプ 2 は 0 を生成し、タイプ 1 は 3 を生成します。ゲインの計算により完全な効果が直接取得されるため、アルゴリズムはより高いゲインをタイプ 2 に正しく割り当て、予算が許せばそれを選択します。 

もう 1 つのケースは、両方の操作の対話順序です。 のために`a = 7, b = 3`、最初に半分にすると 4、次に 1 が得られ、最初に減算すると 4、次に 2 が得られます。アルゴリズムは両方の次数を明示的に評価し、結果の最小値を選択するため、非可換性にもかかわらず正確性が保証されます。 

最後のエッジケースは、限られた要素を巡る要素間の競合です。`k1`そして`k2`。 2 つの要素のゲインは同じだが、リソースの使用パターンが異なる場合、予算の都合で競合が生じた場合、貪欲な順序付けにより 1 つだけが選択されるようになります。`used`配列により、同じ要素への変換の二重代入が防止されます。
