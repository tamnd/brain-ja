 ## 解決策
 ## 問題の理解

 入力は、交差点の三角形グリッドを記述します。 行$i$含まれています$i$ノードがあるため、ノードの総数は次のようになります。$n(n+1)/2$。 常に最上位ノードから開始します$(1,1)$右下のノードに到達したい$(n,n)$。 

各ノードから$(i,j)$並んで$1$に$n-1$、方向のない道が 3 つあります。 

1つは左下に進みます$(i+1,j)$重さで$a_{i,j}$、右下に進みます$(i+1,j+1)$重さで$b_{i,j}$、1 つは次の行の内側で水平に接続します。$(i+1,j)$そして$(i+1,j+1)$重さで$c_{i,j}$。 重要な幾何学的ステートメントは、各トリプルが$(a_{i,j}, b_{i,j}, c_{i,j})$は有効な三角形を形成します。これは、エッジが縮退しておらず、2 つの辺が 3 つ目の辺よりも厳密に長いことを意味します。 

課題は上から下への道を見つけることだけではありません。 各道路は最大 1 回しか使用できないという制約のもとで、可能な限り最長のパスを見つけなければなりません。 グラフは無向であり、それぞれの小さな三角形構造内にサイクルが含まれているため、エッジが再利用されない限り、ノードを再訪することができます。 出力には、最大合計長と訪問ノードの明示的なシーケンスの両方が含まれている必要があります。 

制約によって与えられるのは、$n \le 300$テストごとと合計$n$までのオーバーテスト$5000$。 これは、3 次またはわずかに超 3 次の動的計画法ソリューションは受け入れられるが、パス上の指数関数的なものは不可能であることを強く示唆しています。 グラフには、$O(n^2)$ノードと$O(n^2)$したがって、エッジ状態の再訪を回避するのであれば、状態にわたる最短パスまたは最長パスのバリアントは妥当です。 

素朴な考えは、これをエッジの繰り返しのない一般的なグラフの最長パスとして扱うことです。これはトレイル最大化問題の変形と同等です。 これは一般的なグラフでは NP 困難であり、ここでは三角形によりサイクルがどこにでも存在するため、パス上のブルートフォース DFS はすぐに爆発します。 

貪欲な下向きの動きの微妙な失敗例は、水平エッジによって迂回が可能になり、後ではるかに長い垂直方向の移動が可能になる場合です。 たとえば、最大の下向きエッジを局所的に選択すると、後で長いジグザグ パスが可能になる三角形の水平エッジへのアクセスがブロックされる可能性があります。 この構造はグローバルな推論を強制します。 

## アプローチ

 強引な解釈では、考えられるすべての痕跡を考慮します。$(1,1)$に$(n,n)$、エッジに使用済みのマークを付けます。 各ステップは最大 3 つの近傍に分岐するため、ウォークの数は周囲の深さに応じて指数関数的に増加します。$3^{O(n^2)}$最悪の場合、構造を見直すことは、たとえ$n=10$。 

重要な観察点は、グラフにはサイクルが含まれていますが、すべてのサイクルは 2 つの連続する行の間にある単一の「セル三角形」に限定されているということです。 このような各三角形は 2 つのノードを一列に接続します$i+1$行に 1 つのノード$i$。 エッジは三角形メトリックを形成するため、後で再検討する必要なく、その三角形を最適に完全に横断することができます。また、最適なグローバル パスは、同じ三角形領域の複雑な繰り返しの横断から恩恵を受けることはありません。 

これにより、行ごとに決定が行われる層状グラフとして構造を再解釈することができ、各行内で隣接するノード間の移動を最適に配置できます。 三角形不等式は、ローカル サイクルを構造化された遷移に「平坦化」することで最適性を失わないよう、三角形内の迂回を再配置できることを保証します。 

核となる削減は、最大の累積コストを維持しながら、行内の各ノードに到達する最適な方法を記述する状態を含む行にわたる動的プログラミングであり、訪問の順序を並べ替えるために次の行の水平エッジを横断する機能を慎重に処理します。 

このように見ると、問題はローカルな再配線を伴う階層化された最大パス問題になり、次のように解決できます。$O(n^2)$または$O(n^3)$実装の詳細に応じて。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | トレイル上のブルートフォース DFS | 指数関数 | O(n^2) 再帰 | 遅すぎる |
 | 三角形の再構成による行 DP | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 各行をフロンティアとして扱います。 DP 状態は、前の行のすべてのエッジを完全に解決した後、現在の行の各ノードに到達する可能な最良の値を表します。 

1. 行 1 の DP 配列を初期化します。$(1,1)$そこから開始し、どのエッジも横断していないため、値は 0 になります。 
2. 行を上から下に処理します。 列で$i$、この行のすべてのノードに最適な値がすでにあると仮定します。 
3. 行への貢献を構築する$i+1$行の下向きの 2 つのエッジを使用する$i$。 各ノードについて$(i,j)$、私たちはに行くことができます$(i+1,j)$または$(i+1,j+1)$。 これにより、DP 値と対応するエッジの重みが転送されます。 
4. 水平エッジを組み込みます$c_{i,j}$内側の列$i+1$。 この縁が繋がる$(i+1,j)$そして$(i+1,j+1)$。 エッジを通過できるのは最大 1 回であるため、これを同じ行内の隣接する DP 状態間で追加の緩和が可能であると解釈します。 
5. 制約を適切に処理するために、行の DP を計算します。$i+1$左から右への伝播と右から左への伝播の両方を可能にする方法で。 2 つのスイープを実行します。1 つは左から右へのリラックスです。$c_{i,j}$、右から左に 1 つ。 これにより、水平エッジを使用するかどうかのあらゆる組み合わせが二重にカウントされることなくキャプチャされます。 
6. 列を終えた後$n$、の値$(n,n)$が答えです。 
7. パスを再構築するために、DP 値が改善されるたびに親ポインターを保存します。 水平緩和の場合、隣接するノード間の遷移を保存します。 垂直方向の移動の場合、前の行のどの親が使用されたかを保存します。 

なぜこれで十分なのかというと、それぞれの三角形では、異なる複雑なパターンでセル構造を複数回再訪しても何のメリットも得られないからです。 三角形の不等式により、三角形内の任意の複数ステップの迂回を総重量を減少させることなく一連の単調緩和に再配置できることが保証されるため、局所緩和に対する DP が最適なトレイルを捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        
        a = [None] * (n)
        b = [None] * (n)
        c = [None] * (n)
        
        for i in range(1, n):
            a[i] = list(map(int, input().split()))
        for i in range(1, n):
            b[i] = list(map(int, input().split()))
        for i in range(1, n):
            c[i] = list(map(int, input().split()))
        
        dp = [[-10**30] * (i + 1) for i in range(n + 1)]
        par = [[None] * (i + 1) for i in range(n + 1)]
        
        dp[1][1] = 0
        
        for i in range(1, n):
            ndp = [[-10**30] * (j + 1) for j in range(n + 1)]
            npar = [[None] * (j + 1) for j in range(n + 1)]
            
            for j in range(1, i + 1):
                if dp[i][j] < 0:
                    continue
                
                v = dp[i][j]
                
                if v + a[i][j-1] > ndp[i+1][j]:
                    ndp[i+1][j] = v + a[i][j-1]
                    npar[i+1][j] = (i, j)
                
                if v + b[i][j-1] > ndp[i+1][j+1]:
                    ndp[i+1][j+1] = v + b[i][j-1]
                    npar[i+1][j+1] = (i, j)
            
            for j in range(1, i):
                if ndp[i+1][j] + c[i][j-1] > ndp[i+1][j+1]:
                    ndp[i+1][j+1] = ndp[i+1][j] + c[i][j-1]
                    npar[i+1][j+1] = (i+1, j)
            
            for j in range(i, 1, -1):
                if ndp[i+1][j] + c[i][j-1] > ndp[i+1][j-1]:
                    ndp[i+1][j-1] = ndp[i+1][j] + c[i][j-1]
                    npar[i+1][j-1] = (i+1, j)
            
            dp = ndp
            par = npar
        
        m = n
        path = []
        i, j = n, n
        while i is not None:
            path.append((i, j))
            if i == 1:
                break
            ni, nj = par[i][j]
            i, j = ni, nj
        
        path.reverse()
        
        print(dp[n][n])
        print(len(path))
        print(*[x for p in path for x in p])

if __name__ == "__main__":
    solve()
```DP テーブル`dp[i][j]`ノードで終了する達成可能な最良のパス合計を保存します$(i,j)$。 行からの移行$i$に$i+1$2 つの下向きエッジを使用します。 新しい行内の追加の 2 つのスイープは、次を使用して水平方向の動きをシミュレートします。$c_{i,j}$、隣接するスワップのシーケンスが確実にキャプチャされるようにします。 親配列は、ノードが上から到達したか、水平緩和から到達したかを記録します。これは、有効なトレイルを再構築するのに十分です。 

主な実装の詳細は、配列のインデックス付けを注意深く行うことです。`a[i][j-1]`、`b[i][j-1]`、 そして`c[i][j-1]`行間のエッジに対応します$i$そして$i+1$。 1 つずつずれた位置合わせは、最も一般的な失敗の原因です。

 ## 特殊なケース

 主なエッジケースは、水平エッジが垂直エッジよりもはるかに大きい場合です。 その状況では、最適なパスはドロップダウンする前に行内で繰り返し「振動」する可能性があります。 DP スイープはこれを捉えます。これは、行が計算されると、水平緩和によって最適な値が行全体に完全に伝播されるため、任意の数の行内スワップが効果的に 1 つのパスに圧縮されるからです。 

もう 1 つのケースは、垂直エッジが大きいが水平エッジが小さい場合です。 その場合、DP は状態を改善しないため、水平方向の伝播を自然に回避し、まっすぐな下向きのパスを維持します。
