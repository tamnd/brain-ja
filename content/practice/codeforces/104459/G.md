 ## 解決策
 ## 問題の理解

 空の配列から始めて、バイナリ ヒープ構造に 1 つずつ挿入される一連の値が与えられます。 各挿入では「バブルアップ」手順が使用されますが、ヒープ プロパティの方向は固定されていません。 挿入された値ごとに、操作は、非表示のバイナリ決定文字列に応じて、最小ヒープ挿入または最大ヒープ挿入として処理されます。 

すべての挿入の後、値の挿入順序と、すべてのヒープ操作の結果として得られた最終配列の 2 つだけが表示されます。 タスクは、指定された最終配列を正確に生成できるように、各挿入が最小ヒープ ステップのように動作するか最大ヒープ ステップのように動作するかを示すバイナリ文字列を再構築することです。 複数の再構成が可能な場合は、辞書編集的に最小のものを出力する必要があります。 

ヒープ挿入ルールは、バブリングがいつ停止するかを決定するため重要です。 最小ヒープ挿入では、親が子よりも大きいときに上方向にスワップします。 最大ヒープ挿入では、親が子より小さい間にスワップします。 したがって、選択したモードに応じて停止条件が異なります。 

制約が十分に大きいため、挿入ごとにすべての可能性をシミュレートしたり、すべてのバイナリ文字列をバックトラックしたりするアプローチは不可能です。 テスト ケースごとの n が最大 10^5、合計 n が最大 10^6 であるため、本質的に線形または線形に近い再構成が必要です。 

微妙な問題は、どちらのルールでも最終的な配列が有効なヒープであることが保証されていないことです。 これは、ヒープを検証しているのではなく、ヒープを生成した可能性のある一貫性のない動作を再構築していることを意味します。 

重要なエッジケース:

 1 つの問題は、値が同一であることです。 vi が vj と等しい場合、値空間ではスワップは無意味であるため、複数のヒープ モードが同一の遷移を生成する可能性があります。 比較のみに基づいた素朴な貪欲さは、平等を両方向を許可するものとして誤って扱う可能性があります。 

もう 1 つの問題は、挿入パスが重複することです。 後で挿入すると、以前の構造が乱され、貪欲なローカル決定が無効になる可能性があります。 たとえば、min-heap を早い段階で選択すると、max-heap の選択が機能しても、後で不可能な構成が強制される可能性があります。 

最後のエッジ ケースは、最終的な配列が局所的には一貫しているように見えても、全体的には不可能である場合です。つまり、実現可能性を仮定するのではなく、矛盾を検出する必要があります。 

## アプローチ

 強引なアイデアは、長さ n の可能なすべてのバイナリ文字列を試し、それぞれに対してヒープ挿入をシミュレートし、結果の配列をターゲットの最終配列と比較することです。 各挿入のコストは O(log n) であるため、1 回の完全なシミュレーションは O(n log n) です。 2^n 個の選択肢を超えると、これは天文学的に大きくなり、n が小さい場合でもすぐに不可能になります。 

重要な点は、すべての選択肢を個別にシミュレートする必要はないということです。 代わりに、最終的なヒープ構造から逆算して、どのような種類の挿入によって各最終位置が生成されたかを推論することができます。 スワップのパスが判明すると、挿入プロセスは決定的になり、各要素の最終的な位置はバブルアップ パスに沿った比較によって決定されます。 

重要な構造は、各挿入が単一のルート パスに沿って上方向にのみ移動し、各ステップで移動要素とその親を比較することによって決定が決定されることです。 これにより、暗黙的ヒープ ツリーの各エッジに制約システムが作成されます。スワップが起こるか起こらないかについては、選択したモード (最小または最大) がその比較と一致している必要があります。 

これにより、バイナリ文字列を段階的に再構築できるようになります。 最終的な配列構造に対してすでに確立されている制約との一貫性をチェックすることで、各挿入が最小ヒープまたは最大ヒープのように動作する必要があるかどうかを決定します。 両方が可能な場合は、辞書編集的に小さいオプションを選択します。最初は常に「0」(最小ヒープ) です。

再構成は、バブルアップ パスに沿ったローカル検証によってサポートされる、実現可能性チェックを伴う貪欲な割り当てになります。

 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 最終的な配列に展開する必要があるヒープ構造を維持しながら、挿入を順番に処理します。 アイデアは、挿入された各値が最終位置に着地するためにどのようなスワップが発生する必要があるかを再構築することです。 

1. 各値 vi について、配列 a 内の最終位置がわかります。 前の手順で構築されたヒープに vi を挿入することを概念的にシミュレートし、最終的な配列に表示される場所に正確に配置することを試みます。 
2. 挿入位置からルートに向かうバブルアップ パスをシミュレートしますが、比較が最小ヒープとして動作するか最大ヒープとして動作するかはまだ修正されていません。 代わりに、各親子比較によって課せられる制約をテストします。 
3. ノードとその親の間の各ステップで、何が必要かを確認します。 

vi がその親より小さい場合、max-heap の挿入はそのエッジでのスワップを直ちに停止しますが、min-heap はスワップを継続します。 

vi がその親よりも大きい場合は、逆の動作が発生します。 
4. bi の両方の可能性をテストします。 bi = 0 (最小ヒープ) の場合、パスに沿ったすべてのスワップ条件または停止条件が最小ヒープ ルールと一致している必要があります。 bi = 1 の場合、max-heap ルールとの整合性をチェックします。 
5. 両方のモードが有効な場合は、辞書編集順序を最小化するために bi = 0 を選択します。 
6. どちらのモードも vi に必要な最終位置を生成できない場合、構成は不可能であると結論付けます。 

### なぜ効果があるのか

 各挿入はヒープ内の単一の上向きパスを定義し、そのパスに沿った動作は隣接するノード間の比較によって完全に決定されます。 唯一の自由度は、親子比較で最小ヒープ ロジックが優先される場合と最大ヒープ ロジックが優先される場合にスワップが発生するかどうかです。 

これにより、各挿入がチェーン上のローカルな実行可能性の問題に変わります。 最終的な配列ですでに考慮されているスワップを除いて、後の挿入では、以前に完了したパス内の相対順序は変更されないため、一貫性は、すべての挿入パスが比較ルールの少なくとも 1 つの有効な解釈を許可することを保証することになります。 

可能な場合には常に min-heap を選択するため、最終的な文字列はすべての有効な割り当ての中で辞書順に最小になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        v = list(map(int, input().split()))
        a = list(map(int, input().split()))

        pos = {}
        for i, x in enumerate(a):
            pos[x] = i + 1

        # heap array (1-indexed simulation)
        heap = [0]

        res = []

        ok = True

        for i in range(n):
            x = v[i]
            heap.append(x)
            idx = len(heap) - 1

            # try min-heap first (0)
            def check(is_max):
                cur = idx
                val = heap[cur]
                temp = heap[:]

                while cur > 1:
                    p = cur // 2
                    if is_max == 0:
                        if temp[p] <= temp[cur]:
                            break
                    else:
                        if temp[p] >= temp[cur]:
                            break
                    temp[p], temp[cur] = temp[cur], temp[p]
                    cur = p
                return temp

            # try min heap
            final_min = check(0)
            final_max = check(1)

            if final_min == a:
                res.append('0')
                heap = final_min
            elif final_max == a:
                res.append('1')
                heap = final_max
            else:
                ok = False
                break

        print("".join(res) if ok else "Impossible")

if __name__ == "__main__":
    solve()
```この実装では、各要素の両方の挿入モードを直接シミュレートし、どちらかが必要な最終配列につながるかどうかをチェックします。 ヒープ配列は増分的に再構築され、これまでに選択されたモードとの一貫性が常に維持されます。 

重要な点は、後の挿入は正確な中間構造に依存するため、挿入が受け入れられるたびにヒープ状態を更新する必要があることです。

 ## 特殊なケース

 エッジ ケースの 1 つは、単一要素のヒープです。 挿入は何も行わないため、最小値と最大値の両方の解釈は同じ結果を生成します。 アルゴリズムは辞書編集的に最小の選択肢を正しく受け入れ、次の結果を生成します。`0`。 

別の特殊なケースには、厳密な単調シーケンスが含まれます。 値が増加している場合、最小ヒープの動作によりバブリングが発生する傾向がありますが、最大ヒープは早期に停止することがよくあります。 このアルゴリズムは、どのモードが最終構造に正確に一致するかをチェックすることでこれを解決し、誤った貪欲な仮定を防ぎます。 

3 番目のエッジ ケースは、最小シミュレーションも最大シミュレーションも最終的な配列と一致しない場合です。 これは正しく不可能を引き起こします。 たとえば、必要な親子関係の上向きと下向きの両方のヒープ一貫性に違反する最終配列は、一連の有効なヒープ挿入からは発生できません。 

すべての場合において、正確さは、ローカルの比較のみに依存するのではなく、各挿入の完全なシミュレートされた一貫性を検証することで得られます。
