 ## 解決策
 ## 問題の理解

 それぞれが隠れた数値を表す一連の変数が与えられます。 それらの値はわかりませんが、「変数 a は変数 b よりも厳密に大きい」という形式の厳密な順序付け制約のコレクションが与えられています。 これらの制約は、各エッジが 1 つのノードに別のノードよりも大きな値を強制する有向グラフを定義します。 

各インデックス k について、すべての制約が満たされ、k 番目の変数がすべての n 変数の中央値になるように、すべての変数に実数値を割り当てることが可能かどうかが尋ねられます。 n は奇数であるため、中央値は、正確に (n-1)/2 値より小さい値と (n-1)/2 値より大きい値を持つ要素になります。 

一般に制約は矛盾する可能性がありますが、この問題では有効な割り当てを作成する必要はありません。 代わりに、候補中央値として各ノードの実現可能性を個別に判断するだけで済みます。 

重要な制約は、テスト ケースごとの n が最大 100 であり、テスト ケースの合計が最大 2000 であることです。これは、テスト ケースごとに O(n³) が許容されることをすぐに示唆していますが、指数列挙やノードごとの重いグラフの再計算の繰り返しなどは慎重に制御する必要があります。 

単純な間違いは、直接エッジのみが重要であると想定することです。 たとえば、k に少なくとも (n−1)/2 個の入力エッジまたは出力エッジがあるかどうかだけをチェックすると、推移的な意味が重要になるため、間違ってしまいます。 1 > 2 および 2 > 3 の場合、直接エッジがない場合でも 1 > 3 になります。 

もう 1 つの微妙な失敗例は、グラフが常に非循環であると想定している場合です。 矛盾が含まれる可能性がありますが、値は実数であるため、有向サイクルは不可能を強制します。 たとえば、1 > 2、2 > 3、3 > 1 は不可能です。 正しいソリューションでは、直接のエッジだけではなく、到達可能性の構造を暗黙的または明示的に考慮する必要があります。 

## アプローチ

 強引なアイデアは、制約と一致する実際の数値を割り当ててから、選択したノードを中央値として配置できるかどうかをテストすることです。 すべての位相順序または部分順序のすべての線形拡張を生成し、次に k 番目のノードが中央位置に着地できるかどうかをチェックすることを想像できます。 最悪の場合、線形拡張の数が階乗的に増加し、O(n!) 構成に達するため、これはすぐに実行不可能になります。 

重要な観察は、実際の値は必要なく、相対的な到達可能性だけが必要であるということです。 ノード u が有向辺を介して v に到達できる場合、有効な代入では u は常に v より大きくなければなりません。 これは、任意の候補 k について、k から到達可能なすべてのノードは厳密に k より小さくなければならず、k に到達できるすべてのノードは厳密に k より大きくなければならないことを意味します。 これら 2 つのセットは、k を基準とした強制位置を定義します。 

したがって、k が中央値になるには、k より小さくなるように強制されるノードの数は最大でも (n−1)/2 でなければならず、k より大きくなるように強制されるノードの数も最大でも (n−1)/2 でなければなりません。 いずれかの側が制限を超えた場合、これらの関係はすべての有効な割り当てで避けられないため、k を中央値に配置することはできません。 

これにより、BFS/DFS または推移閉包法を使用して実行できる、有向グラフ内の各ノードからおよび各ノードへの到達可能性の計算の問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 命令に対する暴力 | お(ん!) | O(n) | 遅すぎる |
 | 各ノードからの到達可能性 (ノードごとの Floyd / BFS) | O(n³) または O(n(n+m)) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 制約を有向グラフとしてモデル化します。エッジ a → b は、a が b より大きくなければならないことを意味します。 

次に、ノードのすべてのペア間の到達可能性を計算します。 n が小さいため、Floyd-Warshall または各ノードからの DFS/BFS の繰り返しで十分です。 

到達可能性を計算した後、各ノード k を独立して評価します。

1. 制約から有向グラフを構築します。 各関係 a > b は辺 a → b になります。 
2. 到達可能性を計算して、直接的または間接的に u が v より大きくなるように強制されるかどうかを確認します。 これにより、グラフの推移閉包が得られます。 
3. 各ノード k について、到達できるノードの数を数えます。 これらはすべて、有効な割り当てにおいて厳密に k より小さくなければならないノードです。 
4. また、k に到達できるノードの数を数えます。 これらはすべて、厳密に k より大きくなければならないノードです。 
5. small[k] を k から到達可能なノードの数、larger[k] を k に到達できるノードの数とする。 
6. 小さい[k]と大きい[k]の両方が最大でも(n−1)/2である場合に限り、ノードkを中央値にすることができます。 

残りのすべてのノード (k と比較できないノード) には、強制的に小さいグループと大きいグループの間で柔軟に値を割り当てることができるため、この条件は対称的です。 

### なぜ効果があるのか

 到達可能性関係は、制約によって暗示されるすべての強制比較をキャプチャします。 有効な割り当ては、直接エッジだけでなく、すべての有向パスを尊重する必要があります。 したがって、k から到達可能なすべてのノードは、実行可能なすべての割り当てにおいて厳密にその下にあり、k に到達するすべてのノードは厳密にその上にあります。 

どちらかの側が (n−1)/2 を超える場合、その側に強制要素が多すぎるため、k を中央の位置に配置できません。 両方が制限内にある場合は、すべての強制的に小さいノードを 0 より下に配置し、強制的に大きいノードを 0 より上に配置し、制約に違反することなく残りの制約されていないノードを 0 の周囲に任意に分散することで値を割り当てることができます。 これにより実現可能性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [[False] * n for _ in range(n)]

    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a][b] = True

    # Floyd-Warshall transitive closure
    for k in range(n):
        for i in range(n):
            if g[i][k]:
                for j in range(n):
                    if g[k][j]:
                        g[i][j] = True

    res = []
    limit = (n - 1) // 2

    for i in range(n):
        smaller = 0
        larger = 0

        for j in range(n):
            if g[i][j]:
                smaller += 1
            if g[j][i]:
                larger += 1

        if smaller <= limit and larger <= limit:
            res.append('1')
        else:
            res.append('0')

    print("".join(res))

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```このソリューションでは、まず、厳密な比較を表すブール隣接行列を構築します。 Floyd-Warshall は推移性を伝播するために使用され、到達可能なすべての関係が正しくマークされます。 

各候補中央値インデックスについて、発信到達可能性を強制的に小さい要素としてカウントし、受信到達性を強制的に大きい要素としてカウントします。 しきい値の比較は、ノードをランク​​ (n+1)/2 に配置できるかどうかを直接エンコードします。 

よくある実装の間違いは、到達可能性が推移的である必要があることを忘れていることです。 Floyd-Warshall または DFS クロージャがないと、カウントは制約を過小評価し、無効な中央値を誤って有効としてマークします。 

## 実用的な例

 n = 5、制約 1 > 2、3 > 2、2 > 4、2 > 5 の小さなケースを考えてみましょう。推移閉包の後、ノード 2 は 4 と 5 に到達し、さらに 1 と 3 によって到達されます。 

| ノード k | 小さい (k →) | 大きい (→ k) | 有効 |
 | --- | --- | --- | --- |
 | 1 | 2,4,5 カウント 3 | 0 | はい |
 | 2 | 4,5 カウント 2 | 1,3 カウント 2 | はい |
 | 3 | 2,4,5 カウント 3 | 0 | はい |
 | 4 | 0 | 1、2、3 カウント 3 | はい |
 | 5 | 0 | 1、2、3 カウント 3 | はい |

 このトレースは、推移閉包が直接エッジを超えて制約をどのように伝播するか、および中央値の実現可能性が強制順序数のみにどのように依存するかを示しています。 

ここで、1 > 2、2 > 3、3 > 1 である n = 3 の循環矛盾のケースを考えてみましょう。 

| ノード k | 小さい | 大きい | 有効 |
 | --- | --- | --- | --- |
 | 1 | 2,3 | 2,3 | いいえ |
 | 2 | 3,1 | 1,3 | いいえ |
 | 3 | 1,2 | 1,2 | いいえ |

 すべてのノードが他のノードの上下に強制されすぎて、直ちに実現可能性が侵害されます。 両方のカウントが中央値のしきい値を超えているため、アルゴリズムはすべてのノードを正しく拒否します。

 ## 特殊なケース

 微妙なエッジケースは、あるノードが他の多くのノードと比較できない場合です。 たとえば、k へのパスまたは k からのパスがない場合、両方のカウントはゼロになり、ノードは順序付けの中央半分のどこにでも配置できるため、常に有効になります。 

もう 1 つのケースは、1 つのノードが他の多くのノードを圧倒しているものの、依然として中央値のしきい値内に留まっている、ほぼ完全な順序です。 このアルゴリズムでは、グラフが大きく歪んでいるように見えても、強制的に小さいセットと大きいセットが (n−1)/2 を超えない限り、そのようなノードを正しく許可します。 

最後に、循環コンポーネントはノード間の相互到達可能性を自動的に作成し、小さいカウントと大きいカウントの両方を同時にインフレートし、サイクルが中央値の容量に違反するほど大きい場合に強制的に拒否します。
