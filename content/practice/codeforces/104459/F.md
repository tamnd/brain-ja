 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースは一連のバケットで構成され、各バケットには負でない数の石が含まれます。 1 つの操作で、空ではないバケツから 1 つの石を削除するか、空ではないバケツから石を取り出して他のバケツに入れることができます。 どちらの操作にも 1 ユニットのコストがかかります。 

目標構成は、すべてのバケツに正確に同じ数の石が入ることです。 目標は、このような均一な状態に到達するために必要な操作の数を最小限に抑えることです。 

主な特徴は、石を移動すると石の総数が維持され、削除すると石の総数が減少することです。 これは、最終的な合計が事前に固定されていないことを意味します。 イコライズが必要な場合は、余分な石を破棄することができます。 

この制約により、テスト ケースごとに最大 10^5 バケット、すべてのテスト ケース全体で最大 10^6 のバケットが許可されます。 これにより、テスト ケースごとに二次関数または n log^2 n のアプローチが除外されます。 ソートとリニア スキャンは、プレフィックス合計ベースの評価と同様に許容されます。 どのソリューションでも基本的に各配列を O(n log n) または O(n) で処理する必要があります。 

すべてのバケットがすでに等しい場合、微妙なエッジケースが発生します。 その場合、答えはゼロであり、どの配合でも誤って不必要な除去を実行してはなりません。 もう 1 つの重要なケースは、最適な戦略で石を再分配するのではなく破棄する必要がある場合、たとえば合計が n で割り切れない場合です。 

## アプローチ

 このプロセスを直接考える方法は、目標値 x を固定し、すべてのバケットを x に変換しようとすることです。 x が固定されると、各バケツには余剰石または不足石が存在します。 余った石は他のバケツに移動するか削除できますが、不足分は余ったバケツから出た石を使用して埋める必要があります。 

これを直接シミュレートしようとすると、余剰バケツを選択し、石を不足バケツに移動し、場合によっては余剰バケツを削除することを繰り返します。 これは概念的には機能しますが、各操作でストーンが 1 つだけ変更されるため、遅すぎます。S がストーンの総数である O(S) 操作が発生する可能性があり、最悪の場合、最大 10^14 になる可能性があります。 

重要な観察は、手の正確な内容は問題ではなく、目標レベルの上または下の石の数だけが重要であるということです。 x を固定すると、すべてのバケットは max(ai − x, 0) 個の余剰石を提供します。 これらの余剰石は、不足分を補うことができる唯一のシステム内で有用なリソースです。 赤字を補うために使用されなかった剰余金は削除されなければなりません。 

固定の x について、P(x) を余剰合計 max(ai − x, 0) として定義すると、すべての余剰石は移動に参加するか、削除されます。 余剰の各単位は、移動されるか削除されるかに関係なく、正確に 1 つの操作に寄与するため、驚くほど単純なコスト表現が得られます。 

残りのタスクは、このコストを最小化する x を選択することです。 関数 P(x) は区分線形であり、ai の値でのみ傾きが変化するため、最適な x はこれらのブレークポイントの 1 つ、または総和制約によって課される境界に存在する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 動きのブルートフォースシミュレーション | O(石の合計) | O(n) | 遅すぎる |
 | 並べ替えを使用して候補 x の値を評価する | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ここで、推論を正確な手順に変換します。

1. すべてのバケット値の合計 S を計算します。 これにより、平均レベル S/n が決まります。これは、再分配が完全に効率的である場合の自然なバランス ポイントです。 
2. バケット値の配列を並べ替えます。 選択したターゲット x が既存の AI と交差する場合にのみコスト構造が変化するため、ソートが必要になります。 
3. ソートされた配列に対してプレフィックスの合計を構築し、サフィックスの合計を迅速に計算できるようにします。 
4. 候補目標値 x を検討します。 最適解は、x = S // n またはバケットの値 x = ai のいずれかで発生する必要があります。 これは、2 つの連続する別個の ai 値の間では、x を超えるバケットのセットが変化しないため、そこでのコスト関数は線形であり、内部で新しい最小値を達成できないためです。 
5. 各候補 x について、次のようにコストを計算します。 ai > x となる最初のインデックスを見つけます。 k をそのような要素の数とします。 余剰寄与は sum(ai over ai > x) − x * k です。 これは、目標レベルを超えるバケツから処理 (移動または除去) する必要がある石の数を正確に表します。 
6. すべての候補にわたってこのコストの最小値を追跡し、出力します。 

唯一の微妙な点は、x が実行可能範囲外とみなされないようにすることです。 S / n より大きい値は、全体で存在するよりも多くの石を必要とするため、有効なターゲットにはなりません。 

### なぜ効果があるのか

 固定 x の場合、x より上のすべてのユニットは構造的に独立しており、転送または削除する必要があります。 このシステムには新しい石を作成するメカニズムがないため、すべての赤字は黒字と一致する必要があります。 したがって、総コストは、質量がどのようにルーティングされるかではなく、しきい値 x を超える質量がどれだけあるかによってのみ決まります。 これにより、元のグラフ状の移動プロセスが x に関する 1 次元の最適化問題に分解されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        a.sort()
        S = sum(a)

        # prefix sums
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        def cost(x):
            # find first index > x
            l, r = 0, n
            while l < r:
                m = (l + r) // 2
                if a[m] <= x:
                    l = m + 1
                else:
                    r = m
            
            k = n - l
            if k <= 0:
                return 0
            sum_gt = pref[n] - pref[l]
            return sum_gt - x * k

        candidates = set()
        for v in a:
            candidates.add(v)
        candidates.add(S // n)

        ans = 10**30
        for x in candidates:
            ans = min(ans, cost(x))

        print(ans)

if __name__ == "__main__":
    solve()
```この解決策では、まず配列をソートし、プレフィックスの合計を準備することで問題の構造を安定させます。 コスト関数は、選択したしきい値 x を厳密に超えるすべてのバケットの寄与を分離する方法で実装されます。 二分探索により、余剰に寄与するバケットとそうでないバケットの境界が見つかります。 

候補セットは意図的に小さくなっています。剰余セットの構造が変化する値と、グローバル バランス ポイント S // n のみが加えられています。 これにより、すべての整数を探索する必要がなくなります。 

## 実用的な例

 次の入力を考えてみましょう。```
1
3
0 1 4
```S = 5 および n = 3 を計算するため、S // n = 1 となります。 

ソートされた配列は [0, 1, 4] です。 候補 x = {0, 1, 4, 1} を評価すると、{0, 1, 4} になります。 

x = 0 の場合、すべての要素は余剰になります。 コストは0 + 1 + 4 = 5です。 

x = 1 の場合、上にあるのは 4 だけです。 コストは (4 − 1) = 3 です。 

x = 4 の場合、上に要素はありません。 コストは0です。 

ただし、S / n = 1 であるため、再分配の観点から x = 4 は実行不可能であり、x = 4 を選択するには、存在しない石を作成する必要があります。 正しい評価では、実行不可能な候補を無視し、x = 1 をコスト 3 の最良の有効な選択肢として残す必要があります。 

| × | 余剰要素 | コスト |
 | --- | --- | --- |
 | 0 | 0、1、4 | 5 |
 | 1 | 4 | 3 |

 このトレースは、実行可能性の制約が優勢になるまで、x を大きくすると総余剰がどのように減少するかを示しています。 

2 番目の例:```
1
4
2 2 2 2
```ここでは、S = 8 および S / n = 2 です。配列はすでに均一です。 

| × | 余剰要素 | コスト |
 | --- | --- | --- |
 | 2 | なし | 0 |

 アルゴリズムは、x = 2 でコストがゼロであることを即座に識別します。

 ## 特殊なケース

 すべてのバケットがすでに一致している場合、ソートされた配列には選択された x = ai を厳密に上回る値がないため、コストは直ちにゼロになります。 このアルゴリズムは、不必要な余剰計算を引き起こすことなく、その共通値に等しい x を正しく評価し、ゼロを返します。 

バケットが 1 つしかない場合、その値に等しい x は余剰もコストもゼロになります。 候補生成には、同じ値に等しい S // n が含まれており、正確性が保証されます。 

単一の大きなバケットと多数のゼロなど、値が大きく偏っている場合、S // n に近い x を選択することでコストが最小限に抑えられます。 このような場合、バイナリ境界は大きな値の大部分を再分配または削除する必要があることを正確に識別し、剰余公式はこれを直接捉えます。
