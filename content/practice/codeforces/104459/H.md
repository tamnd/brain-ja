 ## 解決策
 ## 問題の理解

 グリッド上に描画されたいくつかの水平セグメントが与えられます。 各セグメントは別個の水平線上にあります。i 番目のセグメントは高さ y = i にあり、x = li から x = ri まで広がり、これらの端点間のすべての整数 x をカバーします。 

整数グリッド点にトークンを配置することは許可されていますが、2 つのトークンが同じ x 座標を共有してはいけないという厳しい制約があります。 言い換えれば、各整数の x 位置はすべてのトークンにわたって最大 1 回しか使用できませんが、その x には任意の整数 y を選択できます。 

セグメント上に少なくとも 1 つのトークンが存在する場合、セグメントは「カバーされている」とみなされます。これは、区間 [li, ri] 内の x を選択し、(x, i) にトークンを配置したことを意味します。 私たちの目標は、少なくとも 1 つのそのようなトークンを受け取るセグメントの数を最大化することです。 

この構造により、選択されたすべての x 値がグローバルに異なることが保証されながら、セグメントごとに最大 1 つの整数 x を選択するという問題が軽減されます。 選択された各 x は、それが含まれる間隔に含まれる 1 つのセグメントにのみ割り当てることができます。 

この制約により、複数のテスト ケースを使用して、テスト ケースごとに最大 10^5 のセグメントが許可されます。 したがって、どのような解も O(n log n) に近いか、それ以上である必要があります。 すべての候補割り当てに対する 2 次または O(n^2) の貪欲なチェックでは拡張できません。 

セグメントが重なり合うと、微妙なエッジケースが発生します。 たとえば、多くのセグメントが [1, 2] のような共通の小さな間隔を共有する場合、x = 1 ともう 1 つの x = 2 を使用できるのはそのうちの 1 つだけであるため、セグメントが多くても満たせるのは最大 2 つです。 全体的な調整を行わずに「間隔内で最初に利用可能な x」を割り当てる単純なアプローチは、このような密なオーバーラップではすぐに失敗します。 

間隔がネストされている場合、別の特殊なケースが発生します。 たとえば、[1, 10]、[2, 9]、[3, 8]。 左側のエンドポイントで処理する単純な貪欲な場合、初期の大きな間隔が適切に割り当てられず、より狭い間隔がブロックされ、合計数が誤って減少する可能性があります。 

## アプローチ

 効率を無視する場合、最も直接的なアイデアは、各セグメントを独立して扱い、各セグメントに対して可能なすべての x 位置を試し、個別の x 値をグローバルに割り当てることができるかどうかを確認することです。 これは、セグメントと整数点の間のマッチング形式の問題になります。 x の範囲は 10^9 までなので、グラフを明示的に構築することは不可能であり、すべての候補の x 値を反復処理することさえ不可能です。 

もう少し構造化された総当たり攻撃は、すべてのエンドポイントを圧縮し、競合をチェックしながら貪欲に割り当てを試みることです。 それでも、セグメントごとに多くの候補 x 値をスキャンする可能性があり、間隔が大きく重なり合う最悪のケースでは O(n^2) の動作が発生します。 

重要な観察は、実際には x 座標を超えたグリッドの幾何学的構造を気にしていないということです。 各セグメントは、単一の整数リソース (x 値) に対して間隔制約のみを提供し、各 x は 1 回のみ使用できます。 したがって、問題は次のようになります。選択した各間隔内で個別の整数を選択できるように、できるだけ多くの間隔を選択します。 

これは古典的なスケジューリング スタイルの最大化ですが、ひねりが加えられています。タイム スロットに間隔を割り当てる代わりに、タイム スロット (X 値) を間隔に割り当てており、各スロットは 1 回だけ使用できます。 正しい貪欲な方向は、最も早く行動することを強制するセグメントを常に選択しながら、x の昇順にトークンを割り当てることです。 

標準的な変換では、x を左から右にスイープし、開始されたすべてのセグメント (li ≤ x) を維持し、常に利用可能なセグメントの中で最小の右端点を持つセグメントに x を割り当てます。 最も早く期限切れになるセグメントに x を使用すると、より長い間隔でも柔軟性が保たれるため、これは最適です。 

これにより、ri をキーとする min-heap を使用した貪欲な結果が得られます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべてのセグメントを左端点 li の昇順に並べ替えます。 これにより、x を左から右にスイープするときにセグメントがいつ利用可能になるかを知ることができます。 スイープにより、未使用の x が割り当てられている可能性のあるセグメントを決して見逃すことがなくなります。 
2. ソートされたセグメント、空の最小ヒープ、およびカウンター応答 = 0 に対するポインター i を初期化します。ヒープには、現在の x を取得する資格があるすべてのセグメントの右エンドポイント ri が格納されます。 
3. 概念的には x を 1 から上に向かって繰り返しますが、実際には、ソートされたエンドポイントを使用して、関連する座標間を直接ジャンプします。 各ステップで、最初に li ≤ x でまだ考慮されていないすべてのセグメントをヒープに挿入します。 これらはまさに、この x を依然として使用できる可能性のあるセグメントです。 
4. ri < x のセグメントは、将来の x によって満たされなくなるため、ヒープから削除します。 これらの間隔はすでに不可能であり、破棄する必要があります。 この枝刈りは、割り当ての無駄を避けるために不可欠です。 
5. ヒープが空でない場合は、現在の x を最小の ri を持つセグメントに割り当てます (ヒープの最小値をポップします)。 1 つのセグメントを正常に満たしたので、答えを 1 つ増やします。 この選択は、最も制限されたセグメントを最初に消費し、より柔軟なセグメントを後の x 値に残すため、最適です。 
6. x 方向に進み続け、すべてのセグメントが処理され、アクティブな候補がなくなるまでこのプロセスを繰り返します。 

この順序付けが機能する理由は、期限の構造に関係しています。 各セグメントは、その区間内で一意の x を必要とします。 利用可能な小さい x 値を最も制限された間隔に割り当てることで、後で存続する可能性のあるセグメントで小さな x を「無駄に」することがなくなり、より狭いセグメントがブロックされることになります。 

維持される不変条件は、任意の x において、将来の x ≧ 現在の x を使用して満足できるセグメントがヒープに正確に含まれており、常に現在の x をそれらの中で可能な限り最小の期限を持つセグメントに割り当てるということです。 これにより、将来の実現可能性が最大限に保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        segs = []
        for _ in range(n):
            l, r = map(int, input().split())
            segs.append((l, r))
        
        segs.sort()
        
        import heapq
        heap = []
        ans = 0
        i = 0
        
        # We simulate events: either new segment starts or we assign a point
        # Instead of iterating x up to 1e9, we jump by processing events implicitly
        current_x = 0
        
        while i < n or heap:
            if not heap:
                current_x = segs[i][0]
            
            while i < n and segs[i][0] <= current_x:
                heapq.heappush(heap, segs[i][1])
                i += 1
            
            while heap and heap[0] < current_x:
                heapq.heappop(heap)
            
            if heap:
                heapq.heappop(heap)
                ans += 1
                current_x += 1
            else:
                if i < n:
                    current_x = segs[i][0]
        
        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、右エンドポイント順に並べられたヒープ内のアクティブ セグメントを維持しながら、x にわたるスイープ ラインを実装します。 ポインタ i により、各セグメントが 1 回だけ挿入されることが保証されます。 ヒープ クリーンアップでは、現在の x で満足できなくなったセグメントが削除されます。 有効なセグメントが選択されたら、x を 1 単位消費して先に進みます。 

微妙な点は、ジャンプ ロジックです。ヒープが空の場合、次のセグメントまで x を 1 つずつインクリメントせず、次のセグメントの左のエンドポイントに直接ジャンプします。 これにより、未使用の整数座標の反復処理が回避され、ソートおよびヒープ操作に至るまでランタイムの入力サイズが線形に保たれます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    import heapq

    input = sys.stdin.readline
    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        segs = [tuple(map(int, input().split())) for _ in range(n)]
        segs.sort()

        heap = []
        i = 0
        ans = 0
        cur = 0

        while i < n or heap:
            if not heap:
                cur = segs[i][0]
            while i < n and segs[i][0] <= cur:
                heapq.heappush(heap, segs[i][1])
                i += 1
            while heap and heap[0] < cur:
                heapq.heappop(heap)
            if heap:
                heapq.heappop(heap)
                ans += 1
                cur += 1
            else:
                if i < n:
                    cur = segs[i][0]
        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 [1,2]、[1,2]、[1,2]、[1,2] のような同一間隔の場合、ヒープには x = 1 で常に 4 つの候補が含まれます。アルゴリズムは x = 1 で 1 つを割り当て、x = 2 でもう 1 つを割り当てます。その後、残りのセグメントはすべてすでに使用されているか、期限切れになります。 ヒープにより、利用可能な x 値を超える値を割り当てようとしないことが保証されます。 

[1,10]、[2,9]、[3,8] などのネストされた間隔の場合、初期 x のヒープには 3 つの間隔すべてが含まれますが、アルゴリズムは可能な限り 8 で終わる間隔を最初に優先します。 各割り当ては 1 つの x を消費し、3 つすべてが正常に一致します。これは、初期の貪欲な選択が実現可能性を妨げないことを示しています。 

[1,1] や [100,100] のような疎な間隔の場合、ポインターは関連する x 値の間を直接ジャンプします。 ヒープが空の場合、未使用の座標を反復処理する代わりに、次の li にジャンプします。 これにより、連続割り当てに関する誤った仮定が回避され、アクティブなセグメントのみに関連付けられた正確さが維持されます。
