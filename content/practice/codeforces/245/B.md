 ## 解決策
 ## 問題の理解

 Vasya はノートにインターネット アドレスを走り書きしましたが、急いでいたため、次のような句読点をすべて省略しました。`:`、`/`、 そして`.`。 元のアドレスは従来の URL 構造に従っており、プロトコル (`http`または`ftp`)、小文字で構成されるドメイン名、`.ru`トップレベル ドメイン、およびオプションでスラッシュの後のコンテキスト パス。 私たちの仕事は、Vasya が記録した圧縮文字列から妥当な住所を再構築することです。 

入力は、区切り文字を含まない小文字の単一の文字列です。 出力は、次の形式で有効に再構築された URL である必要があります。`<protocol>://<domain>.ru[/<context>]`。 入力は有効なアドレスからのものであることが保証されているため、入力が不可能であるかどうかを検証する必要はありません。 複数の再構成が存在する可能性があり、有効な再構成であればどれでも受け入れられます。 

文字列の長さは 50 文字に制限されており、これは O(n²) アルゴリズムでも 2 秒の時間枠で快適に実行できるほど十分に小さいです。 エッジ ケースは、プロトコル プレフィックスがドメインの一部と重複する可能性がある場合、またはコンテキスト文字列が最小限である場合に発生します。 例えば、`httpsunrux`次のように解析できます`http://sun.ru/x`または`https://unru.x`したがって、再構築ではプロトコルをドメインから慎重に分離し、ドメインを特定する必要があります。`.ru`境界を設定し、残りの文字をコンテキストに割り当てます。 

単純なアプローチでは、特に文字列に次のような埋め込みプレフィックスが含まれている場合、プロトコルを誤って分割したり、ドメインやコンテキストの一部が欠落したままになったりする可能性があります。`ftphttpabc`。 私たちのソリューションでは、プロトコル、ドメイン、およびオプションのコンテキストを曖昧さなく体系的に決定する必要があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。文字列のすべてのプレフィックスを試して、それが有効なプロトコルと一致するかどうかを確認します (`http`または`ftp`)、残りの文字列をスキャンして、ドメインが終了する分割ポイントを探します。`.ru`が始まります。 その後`.ru`、残った文字 (存在する場合) がコンテキストになります。 文字列の長さは最大 50 であるため、考えられるすべての分割を反復処理することは可能ですが、ブルート フォース アプローチにはプレフィックスとドメイン分割に対するネストされたループが含まれており、これは不必要です。 

重要な洞察は、プロトコルの長さが常に 4 文字または 3 文字であるということです (`http`または`ftp`)、ドメインはその直前で終了する必要があります。`.ru`サフィックス。 これにより、検索スペースが削減されます。最初の 4 文字をチェックするだけで済みます。`http`または最初の 3 つ`ftp`、2 文字が残るまで文字列の次の部分をドメインとして割り当てます。`.ru`。 その後に残った文字`.ru`はオプションのコンテキストになります。 この観察により、ネストされたループの代わりに単純な線形スキャンを使用して URL を再構築できるようになります。

 ## アルゴリズムのチュートリアル

 1. 文字列の先頭をチェックしてプロトコルを特定します。 最初の 4 文字が次の場合`http`、プロトコルを次のように設定します。`http`。 それ以外の場合は、次のように設定します`ftp`(最初の 3 文字)。 これにより、プロトコル プレフィックスを曖昧さなく正確に識別できることが保証されます。 
2. 文字列からプロトコル プレフィックスを削除して、ドメイン、つまりドメインで構成される残りの部分のみで動作するようにします。`.ru`接尾辞、および場合によってはコンテキストも含まれます。 
3. ドメインを特定します。 ドメインは次の位置で終了します。`.ru`始まるだろう。 以来`.ru`が 2 文字の場合、最後の 2 文字を除くすべての文字 (およびコンテキストがある場合は残りの文字) をドメインとして受け取ります。 
4.追加`.ru`ドメイン境界を明示的にマークします。 
5. 最後の2文字以降に文字が残っている場合`.ru`、それらをコンテキストとして扱い、先頭に`/`。 
6. プロトコルを連結します。`://`、ドメイン`.ru`、および最終的に再構築された URL を形成するためのオプションのコンテキスト。 

機能する理由: 不変条件は、プロトコルが先頭で固定数の文字を占有し、ドメインが常に前に来ることです。`.ru`、残りの文字はコンテキストに組み込まれます。 入力文字列は有効な URL からのものであることが保証されているため、これらのルールにより常に有効な再構成が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

if s.startswith("http"):
    protocol = "http"
    rest = s[4:]
else:
    protocol = "ftp"
    rest = s[3:]

# The domain ends just before the .ru suffix
domain = rest[:-2]
context = rest[-2:]

# If context is exactly 'ru', no additional context exists
if context == "ru":
    context = ""
else:
    # split 'ru' from the end
    domain = rest[:-len(context)-2]
    context = rest[-len(context):]

# final URL assembly
url = protocol + "://" + domain + ".ru"
if context:
    url += "/" + context

print(url)
```説明: まずプロトコルを決定し、それを文字列から削除します。 次に、`.ru`ドメインの末尾にサフィックスを付けます。 以降の文字`.ru`コンテキストです。 難しいのは、次の場合の処理​​です。`.ru`文字列の最後の 2 文字と一致します。 ドメインとコンテキストが誤って結合されないように、これらを慎重に分離します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = input().strip()
    if s.startswith("http"):
        protocol = "http"
        rest = s[4:]
    else:
        protocol = "ftp"
        rest = s[3:]
    domain = rest[:-2]
    context = rest[-2:]
    if context == "ru":
        context = ""
    else:
        domain = rest[:-len(context)-2]
        context = rest[-len(context):]
    url = protocol + "://" + domain + ".ru"
    if context:
        url += "/" + context
    return url

# provided samples
assert run("httpsunrux\n") == "http://sun.ru/x", "sample 1"
assert run("ftphttpruru\n") == "ftp://http.ru/ru", "sample 2"

# custom cases
assert run("httpabcde\n") == "http://abc.ru/de", "basic domain + context"
assert run("ftpxyzru\n") == "ftp://xyz.ru", "context empty"
assert run("httpabcdefru\n") == "http://abcd.ru/ef", "longer context"
assert run("ftpabcdefghijru\n") == "ftp://abcdefghi.ru/j", "max length small"

 プロトコルを削除した後に残った文字列の最後の 2 文字が正確に一致する場合、微妙なケースが 1 つ発生します。`ru`。 その状況では、コンテキストはありません。 たとえば、入力`ftpxyzru`生成する`ftp://xyz.ru`空のコンテキストを使用します。 アルゴリズムはこの状態を明示的にチェックし、誤ってスプリアスが作成されることを防ぎます。`/ru`URLにあります。 もう 1 つのエッジ ケースは、残りの文字列にドメイン内のプロトコルのように見えるシーケンスが含まれている場合です。 私たちのソリューションは、プロトコルの最初とそれ以降のすべてをチェックするだけなので、それらを誤解することはありません。`.ru`ドメインとして扱われます。
