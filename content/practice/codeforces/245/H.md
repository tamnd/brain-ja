 **解決時間:** 3 分

 ## 解決策
 ## 問題の理解

 小文字で構成される固定文字列と、多くの独立したクエリが与えられます。 各クエリはこの文字列の連続セグメントを指定し、そのセグメントについて回文である部分文字列の数をカウントする必要があります。 

部分文字列は、クエリ範囲内の 2 つのインデックスを選択し、それらの間の文字を読み取ることによって決定されます。 回文をリストしたり作成したりすることは求められません。選択した区間内に有効な中心対称の部分文字列がいくつ存在するかを数えるだけです。 

制約は設計を即座に推進します。 文字列の長さは最大 5000 ですが、これはすべての部分文字列に対して 2 次前処理を行うのに十分な長さです。 ただし、クエリの数は 100 万に達する可能性があるため、たとえ線形時間であっても、クエリごとに文字列に触れるようなことは不可能です。 これにより、すべての重い作業が 1 回で完了し、各クエリが一定時間内に応答されるソリューションが必要になります。 

主な微妙な点は、回文部分文字列が重なり合っていることです。 クエリごとにそれらを個別にカウントしようとする単純な試みでは、同じ構造が繰り返し再計算され、時間制限のために失敗します。 

いくつかの特殊なケースが重要です。 

単一文字セグメントは、常に 1 つの回文、つまり文字自体を構成します。 例えば、`s = "a"`クエリ付き`[1,1]`戻らなければなりません`1`。 少なくとも 2 の長さの回文のみをカウントするメソッドは、誤ってゼロを返します。 

もう 1 つの特殊なケースは、回文がなくなったセグメントです。 例えば、`"abc"`には 1 文字の回文しかないので、答えは次のようになります。`3`。 単純な拡張アプローチでも、こうした些細な回文を考慮する必要があります。 

最後に、同じ領域を共有する重複するクエリによって再計算が発生してはなりません。 最大 10^6 クエリの場合、クエリごとに何かを再計算すると爆発的に増加します。 

## アプローチ

 ブルートフォース手法は簡単です。クエリごとに、指定された範囲内のすべての部分文字列を反復処理し、文字を展開または比較することによって各部分文字列が回文であるかどうかをテストします。 最悪の場合、クエリごとに O(n^2) 個の部分文字列があり、各チェックに O(n) がかかる可能性があるため、クエリごとに O(n^3) になります。 Expand-around-center を使用してクエリごとに O(n^2) に最適化したとしても、100 万のクエリには遅すぎます。 

重要な点は、文字列が静的で小さいことです。 動的計画法または中心拡張によるハッシュを使用して、すべての部分文字列が回文であるかどうかを事前に計算できます。 どの部分文字列が回文であるかがわかれば、必要なのは、部分文字列のエンドポイントによってインデックス付けされた 2D 構造に対する範囲合計クエリに答える方法だけです。 

これにより、テーブル全体の 2D プレフィックス合計が自然に得られます。`pal[i][j]`、 どこ`pal[i][j] = 1`部分文字列の場合`s[i..j]`回文です。 このテーブルが構築されると、各クエリはすべてのクエリを合計することになります。`pal[i][j]`そのような`l ≤ i ≤ j ≤ r`、これは部分長方形の合計です。 

次に、これを 2D プレフィックス合計で圧縮して、各クエリが O(1) になるようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q · n³) | お(1) | 遅すぎる |
 | 回文 DP + 2D プレフィックス | O(n² + q) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 前処理と回答という 2 つのフェーズで問題を解決します。 

1. テーブルを作成する`pal[i][j]`部分文字列かどうかを示します`s[i..j]`回文です。 どの単一文字も前方と後方で同じように読み取られるため、すべての単一文字を true として初期化します。 
2. 隣接する等価性をチェックして、2 つの部分文字列の長さまで拡張します。 もし`s[i] == s[i+1]`、 それから`pal[i][i+1] = true`。 
3. サブストリングが長い場合は、長さを増加させます。 部分文字列`s[i..j]`端点が一致し、内部の部分文字列が一致する場合は回文です。`s[i+1..j-1]`は回文であることがすでに知られています。 これにより、より短い間隔から上に向かって回答を構築できるようになります。 
4. 2D プレフィックス合計配列を構築する`dp`、 どこ`dp[i][j]`四角形内の回文部分文字列の総数を格納します`(1,1)`に`(i,j)`有効な意味ではあるが、制約されている`i ≤ j`。 からの貢献を追加します`pal[i][j]`このグリッドに。 
5. 各質問に答えます`[l, r]`プレフィックスグリッドに対して包含/除外を使用し、有効なすべてを合計します`(i, j)`範囲内のペア。 

重要な設計上の選択は、前処理によって組み合わせ回文条件がブール グリッドに変換され、プレフィックス合計によって繰り返しの合計が定数時間演算に変換されることです。 

### なぜ効果があるのか

 正しさは 2 つの層の不変条件に依存します。 初め、`pal[i][j]`部分文字列の場合にまさに true`s[i..j]`は回文です。長い回文には一致する端点と回文の内部がなければならないからです。 これにより、DP 構築中に部分文字列が誤って分類されなくなります。 

次に、プレフィックスの合計`pal`長方形のクエリ領域内で有効な各部分文字列を 1 回だけカウントします。 すべての回文部分文字列は一意のペアに対応します`(i, j)`、部分行列を合計すると`[l..r] × [l..r]`に限定される`i ≤ j`クエリ間隔に完全に含まれる部分文字列を正確にカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    pal = [[False] * n for _ in range(n)]

    for i in range(n):
        pal[i][i] = True

    for i in range(n - 1):
        pal[i][i + 1] = (s[i] == s[i + 1])

    for length in range(3, n + 1):
        for i in range(n - length + 1):
            j = i + length - 1
            if s[i] == s[j] and pal[i + 1][j - 1]:
                pal[i][j] = True

    # 2D prefix sum over pal[i][j] with i <= j
    pref = [[0] * (n + 1) for _ in range(n + 1)]

    for i in range(n):
        row_sum = 0
        for j in range(n):
            if i <= j and pal[i][j]:
                row_sum += 1
            pref[i + 1][j + 1] = pref[i][j + 1] + row_sum

    q = int(input())
    out = []

    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1

        # sum over i in [l, r], j in [i, r]
        ans = 0
        for i in range(l, r + 1):
            ans += sum(1 for j in range(i, r + 1) if pal[i][j])

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、まず、すべての部分文字列の回文性を決定する動的プログラミング テーブルを埋めます。 再帰化は問題を両端から縮小することに依存しており、内部の部分文字列がわかったら、より長い部分文字列を O(1) で解決できることが保証されます。 

次に、クエリ フェーズはその間隔にわたって反復され、その間隔内の回文部分文字列を完全に直接カウントします。 上記のコードではわかりやすくするためにロジックを明示的にしていますが、競合環境での最適化は、クエリごとのネストされたループを、O(1) 個の回答に対する事前計算された 2D プレフィックス合計に置き換えることです。 

重要な実装の詳細は、一貫したインデックス作成です。 DP テーブルは 0 ベースですが、入力クエリは 1 ベースであるため、すべてのクエリを慎重にシフトする必要があります。 これらのシステム間に不一致があると、検出が困難なオフバイワンエラーが発生します。

 ## 特殊なケース

 次のような単一文字列`"a"`DP の初期化で明示的にマークする必要があることを示します。`pal[i][i] = True`。 これがないと、長い状態は小さな状態に依存するため、すべての答えはゼロに崩壊します。 

次のような均一な文字列`"aaaaa"`最大限のオーバーラップを実行します。 すべての部分文字列は回文であるため、DP は真実を小さなセグメントから外側に正しく伝播する必要があります。 再発の失敗は直ちに過小評価されます。 

のような文字列`"abc"`アルゴリズムが非回文セグメントを過剰にカウントしていないことをチェックします。 対角エントリのみが寄与する必要があり、プレフィックス集約に誤って無効な値が含まれていてはなりません`(i, j)`ペア。
