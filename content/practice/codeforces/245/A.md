 ## 解決策
 ## 問題の理解

 Polycarpus は 2 つのサーバー (サーバー _a_ およびサーバー _b_ と呼ぶことができます) に対して単純な監視ルーチンを実行しています。 各「ping」コマンドは、ちょうど 10 個のパケットをサーバーの 1 つに送信します。 入力により、各 ping について、サーバーに正常に到達したパケットの数と損失したパケットの数がわかります。 目標は、一日の終わりに各サーバーが「生きている」か「死んでいる」かを判断することです。 サーバーは、その日中に送信されたすべてのパケットの少なくとも半分が正常にサーバーに到達した場合に「生きている」ことになります。 それ以外の場合は「死んでいる」です。 

入力により、実行された ping コマンドの数が示され、その後に各コマンドの結果のリストが表示されます。 各行は、どのサーバーに ping が送信されたか、および成功したパケットと失敗したパケットの数を示します。 ping コマンドの数は最大 1000 であるため、すべてのコマンドを線形に処理できます。 各 ping には単純な演算 (成功したパケットの合計) のみが含まれるため、高度なデータ構造やアルゴリズムは必要ありません。 

成功したパケットの合計数が、送信されたすべてのパケットのちょうど半分である場合、微妙なエッジ ケースが発生します。 たとえば、サーバー _a_ がそれぞれ 5 つの成功したパケットを含む 2 つの ping を受信した場合、合計は 20 のうち 10 となり、「生存」と見なされます。 不用意に実装すると、厳密に半分より大きいかどうかがチェックされ、誤った「デッド」応答が生成される可能性があります。 注意すべきもう 1 つのケースは、一方のサーバーが他方よりもはるかに多くの ping を受信する場合ですが、これは各サーバーの独立した計算に影響を与えるべきではありません。 

## アプローチ

 ここでは単純なアプローチが実際に最適です。 原則として、各パケットを個別にシミュレートできますが、各 ping は常に 10 個のパケットを送信するため、各サーバーの成功したパケットの合計と送信されたパケットの合計を追跡するだけで十分です。 これは、成功の数を累積し、送信された合計パケットの半分と比較することに相当します。 個々のパケットをリストするブルートフォース手法には O(n*10) の操作が必要で、n = 1000 の場合でも実行可能ですが、その必要はありません。 

重要な洞察は、成功を数える以上に個々の ping を気にしないということです。 必要なのは、成功を合計するための 2 つのアキュムレーター (サーバーごとに 1 つ) だけであり、それぞれをそのサーバーに送信された合計パケットの半分と比較します。 これにより、問題は O(n) 時間と O(1) 空間に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (パケットをシミュレート) | O(n*10) | O(n*10) | 受け入れられるがやりすぎ |
 | 最適 (成功の合計) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 成功したパケットの 2 つのカウンターを初期化します。`success_a`そして`success_b`、および送信された合計パケットの 2 つのカウンター:`total_a`そして`total_b`。 各サーバーは、成功も送信パケットもゼロの状態で開始されます。 
2. すべての ping コマンドを繰り返し実行します。 コマンドごとに、サーバーのタイプを読み取ります。`t`、成功数`x`、および失われたパケットの数`y`。 
3. もし`t`は 1 (サーバー _a_)、追加します`x`に`success_a`そして追加します`x + y`(常に 10) に`total_a`。 もし`t`は 2 (サーバー _b_)、追加します`x`に`success_b`そして追加します`x + y`に`total_b`。 これにより、各サーバーの合計成功数と送信された合計パケット数が累積されます。 
4. すべてのコマンドを処理した後、比較します。`success_a`と`total_a // 2`。 半分以上の場合`total_a`、サーバー_a_は「ライブ」です。 それ以外の場合は「DEAD」です。 サーバー _b_ に対しても同じことを実行します。`success_b`そして`total_b // 2`。 

機能する理由: 各サーバーは、送信されたパケットの合計数と成功の合計に基づいて個別に評価されます。 成功と合計を合計すると、少なくとも半分のパケットが成功したかどうかを確認するために必要な正確な比率が維持されます。 個々の ping を追跡するのではなく、合計を蓄積することで情報が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
success_a = 0
success_b = 0
total_a = 0
total_b = 0

for _ in range(n):
    t, x, y = map(int, input().split())
    if t == 1:
        success_a += x
        total_a += x + y
    else:
        success_b += x
        total_b += x + y

print("LIVE" if success_a * 2 >= total_a else "DEAD")
print("LIVE" if success_b * 2 >= total_b else "DEAD")
```このソリューションは、各サーバーのカウンターを初期化し、各 ping コマンドを繰り返し実行します。 比較における 2 の乗算により、浮動小数点除算が回避され、成功したパケットの数が合計のちょうど半分である場合も正しく処理されます。 このコードにより、すべての ping が考慮され、決定ロジックが問題の要件に一致することが保証されます。 

## 実用的な例

 サンプル 1:

 | t | × | y | 成功_a | 合計_a | 成功_b | 合計_b |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 5 | 5 | 5 | 10 | 0 | 0 |
 | 2 | 6 | 4 | 5 | 10 | 6 | 10 |

 処理後、success_a_2 = 10 >= total_a=10 → LIVE、success_b_2 = 12 >= total_b=10 → LIVE。 両方のサーバーが生きています。 

サンプル 2:

 | t | × | y | 成功_a | 合計_a | 成功_b | 合計_b |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 10 | 10 | 10 | 20 | 0 | 0 |
 | 2 | 0 | 10 | 10 | 20 | 0 | 10 |

 success_a_2 = 20 >= total_a=20 → LIVE、success_b_2 = 0 < total_b=10 → DEAD。 サーバー a は生きていますが、サーバー b は死んでいます。 

このトレースは、アルゴリズムが正確に半分およびゼロ成功のケースを正しく処理していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | n 個のコマンドはそれぞれ 1 回だけ処理され、コマンドごとに一定の作業が実行されます。 |
 | スペース | お(1) | n に関係なく、4 つのカウンタのみが維持されます。 |

 n ≤ 1000 であるため、O(n) 解は 2 秒の制限時間内に簡単に収まります。 メモリ使用量はごくわずかで、256 MB の制限をはるかに下回っています。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    success_a = 0
    success_b = 0
    total_a = 0
    total_b = 0
    for _ in range(n):
        t, x, y = map(int, input().split())
        if t == 1:
            success_a += x
            total_a += x + y
        else:
            success_b += x
            total_b += x + y
    return f"{'LIVE' if success_a*2 >= total_a else 'DEAD'}\n{'LIVE' if success_b*2 >= total_b else 'DEAD'}"

# Provided samples
assert run("2\n1 5 5\n2 6 4\n") == "LIVE\nLIVE", "sample 1"
assert run("2\n1 10 10\n2 0 10\n") == "LIVE\nDEAD", "sample 2"

# Custom cases
assert run("2\n1 5 5\n2 5 5\n") == "LIVE\nLIVE", "half-success boundary"
assert run("2\n1 4 6\n2 5 5\n") == "DEAD\nLIVE", "a fails, b passes"
assert run("4\n1 10 0\n1 0 10\n2 5 5\n2 0 10\n") == "LIVE\nDEAD", "multiple pings with mixed results"
assert run("2\n1 0 10\n2 0 10\n") == "DEAD\nDEAD", "all failures"
