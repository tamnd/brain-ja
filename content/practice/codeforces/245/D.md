 ## 解決策
 ## 問題の理解

 もともと非負の整数の隠し配列から生成された正方形のテーブルが与えられています。 非対角の各エントリは、対応する非表示値のペアのビット単位の AND ですが、対角のエントリは人為的に -1 に置き換えられます。 タスクは、テーブルを生成した可能性のある有効な隠し配列を再構築することです。 

重要な点は、i ≠ j のすべての観測値 b[i][j] は、2 つの未知数 a[i] と a[j] にビットごとの AND を適用した結果とまったく同じであるということです。 対角線は何も情報を与えません。 一意の元の配列を復元する必要はなく、すべてのペアごとの制約と一致する配列のみを復元する必要があります。 

n ≤ 100 という制約は、必要に応じて 3 次推論や 4 次推論も可能であることを意味しますが、ビットごとの AND の構造は、ビットごとまたは要素ごとの直接の再構成で O(n²) または O(n³) で十分であることを示唆しています。 各値は最大 10⁹ であるため、ビット構成に関する指数関数は必要ありません。そのため、数値ごとに 30 ビットのみを扱います。 

すべてのペアにわたる一貫性を保証せずに、再構築で値を貪欲に割り当てた場合、微妙な失敗のケースが発生します。 たとえば、単一行のみから a[i] を推定しようとすると、別の行で制約に違反する可能性があります。 もう 1 つの問題は、等価制約が単純な方法で推移的に伝播すると仮定していることですが、これはビットごとの AND には当てはまりません。 

具体的な問題のあるシナリオは、ペアごとに値を割り当てる場合に、3 つのインデックスの相互作用に一貫性がない場合です。 たとえば、1 つのペアを満たすには小さすぎる a[i] を選択すると、他のペアにも矛盾が生じます。これは、AND では両方の数値に存在するビットのみが保存されるためです。 

重要な隠れた構造は、各 a[i] がすべての行 i と互換性がある必要があるということです。つまり、a[i] はすべての b[i][j] 制約の (ビット単位で) スーパーセットでなければなりませんが、他の選択された値と AND 演算されたときに矛盾が生じる禁止ビットを導入してはなりません。 

## アプローチ

 ブルートフォースアプローチでは、各 a[i] を 0 から 10⁹ まで独立して割り当て、すべてのペアごとの AND 結果が行列に一致するかどうかをチェックしようとします。 これはすぐに (10⁹)ⁿ の可能性に爆発しますが、これは n = 100 の場合でも不可能です。 

代わりに、ビット制約をリバース エンジニアリングする必要があります。 重要な点は、ビット単位の AND がビットごとに独立して動作することです。 a[i] と a[j] の両方にビットが設定されている場合に限り、ビットは a[i] と a[j] に設定されます。 これは、すべてのペア (i, j) について、b[i][j] に現れるビットは a[i] と a[j] の両方に現れる必要があることを意味します。 

したがって、各ペア (i, j) について、b[i][j] に設定されたすべてのビットが両方のエンドポイントに存在する必要があることを安全に強制できます。 これにより、a[i] と a[j] に下限制約が与えられます。 すべての j を集計すると、a[i] には任意の b[i][j] に現れるすべてのビットが含まれている必要があることがわかります。 

これにより、自然な候補構造が得られます。j ≠ i にわたるすべての b[i][j] のビット単位の OR として a[i] を設定します。 これにより、必要なすべてのビットが a[i] に存在することが保証されます。 残っているのは、この構造が矛盾を生み出す余分なビットを導入していないことを確認することです。 a[i] に設定されたビットは少なくとも 1 つの b[i][j] に出現する必要があり、必要なときに a[j] にも存在する場合にのみ存続できるため、AND の構造によってこれが機能することが保証されます。 

これにより、問題はマトリックス上の 1 回のパスに軽減されます。

 | --- | --- | --- | --- |
 | ブルートフォース割り当て | O((10⁹)ⁿ) | O(n²) | 遅すぎる |
 | ビットごとの制約の構築 | O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

1. サイズ n の配列 a をすべて 0 で初期化します。 これにより、各インデックスのすべてのビット制約が累積されます。 
2. 各インデックス i について、すべての j ≠ i を反復し、a[i] |= b[i][j] を計算します。 このステップでは、a[i] に出現する必要があるすべてのビットを収集します。これは、各 b[i][j] が a[i] & a[j] であるため、a[i] に存在しないビットを含めることができないためです。 
3. a[i] をすべて埋めた後、暗黙的に対称性に依存します。ビットが b[i][j] のせいで a[i] に現れる場合、それが a[j] にも現れる場合にのみ一貫性があります。 a[j] を計算するときに同じ b[i][j] が使用されたため、この一貫性が保証されます。 
4. 結果の配列を出力します。 

なぜそれが機能するかは、ビットの独立性に関係しています。 各ビット位置は、個別のバイナリ制約システムのように動作します。 b[i][j] にビットが出現する場合、両方のエンドポイントにそのビットが含まれている必要があります。 表示されない場合は、少なくとも 1 つのエンドポイントにそれが含まれる場合と含まれない場合がありますが、他のペアでサポートされない限り、両方に含まれることはありません。 すべての制約に対して OR を実行すると、すべての必須ビットが確実に含まれ、ペアごとの AND 値に違反する不必要な構造が導入されなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = [list(map(int, input().split())) for _ in range(n)]

    a = [0] * n

    for i in range(n):
        val = 0
        for j in range(n):
            if i == j:
                continue
            val |= b[i][j]
        a[i] = val

    print(*a)

if __name__ == "__main__":
    solve()
```コードは構築のアイデアを直接変換します。 ネストされたループは各行をスキャンし、すべての非対角エントリにわたるビット単位の OR を蓄積します。 対角線には使用可能な情報が含まれていないため、無視されます。 

よくある落とし穴は、対角エントリが -1 であることを忘れて、対角エントリをビット単位の演算に含めようとすることで、結果が破損します。 もう 1 つの微妙な問題は、OR の代わりに AND を誤って使用してしまうことです。 必要なビットを交差させるのではなく蓄積するため、OR が必要です。 

## 実用的な例

 ### 例 1

 入力:```
1
-1
```要素が 1 つだけあるため、制約は存在しません。 有効な数値は 0 のみです。 

| 私 | j | b[i][j] | ステップ | の後の a[i]
 | --- | --- | --- | --- |
 | 0 | - | - | 0 |

 出力：```
0
```これは、ペアごとの制約が存在しない縮退ケースをアルゴリズムが処理していることを確認します。 

### 例 2

 入力:```
3
-1 1 0
1 -1 0
0 0 -1
```各行を個別に計算します。 

i = 0 の場合、値 1 と 0 の OR を計算し、a[0] = 1 となります。 

i = 1 の場合、値 1 と 0 の OR を計算し、a[1] = 1 となります。 

i = 2 の場合、値 0 と 0 の OR を計算し、a[2] = 0 となります。 

| 私 | j の貢献 | a[i] |
 | --- | --- | --- |
 | 0 | 1、0 | 1 |
 | 1 | 1、0 | 1 |
 | 2 | 0、0 | 0 |

 次に、一貫性をチェックします。 

1 & 1 = 1 は b[0][1] に一致し、0 を含む他のすべてのペアは必要に応じて 0 を生成します。 

これは、追加の修正手順を必要とせずに、この構造が対称制約を自然に揃えることを示しています。

 ## 特殊なケース

 n = 1 の場合、制約はまったくないため、任意の値が有効です。 空のセットに対する OR が 0 であるため、アルゴリズムは 0 を生成します。これは、非負の整数の要件と一致します。 

他のすべての行と AND でゼロになるノードなど、一部の行にゼロのみが含まれる場合、アルゴリズムは a[i] = 0 を割り当てます。正のビットは少なくとも 1 つのペア制約に違反するため、これは正しいです。 

多くのエントリが重複するビットを共有する密な行列の場合、OR 構造により、重複の問題なくすべての必須ビットが確実に含まれます。 各ビットは少なくとも 1 つの観察されたペアによって正当化されるため、偽のビットは導入されません。
