 ## 解決策
 ## 問題の理解

 ログ エントリの時系列順のストリームが提供されます。各エントリには秒までの正確なタイムスタンプと、プログラムの警告を説明する関連メッセージが含まれています。 タスクはメッセージ自体を処理することではなく、純粋にこれらの警告のタイミングについて推論することです。 

過去を振り返ってみると、最も早い瞬間を特定する必要があります。`n`その時点で終了する秒数、その時間枠内に発生した警告の数は少なくとも`m`。 レポートする時刻は既存のログ エントリに対応する必要はありませんが、このしきい値に最初に到達した時刻と一致する必要があります。 

問題をタイムライン上で増加する点のシーケンスとして見ると便利です。 各ログは、正確な秒に 1 つのイベントに寄与します。 私たちは初めてが欲しいです`t`間隔が`[t - n + 1, t]`少なくとも含まれています`m`イベント。 

この制約では最大 10^4 のログ エントリが許可されますが、文字数での入力サイズは 5·10^6 に達する可能性があるため、解析は合計入力サイズにおいて線形である必要があります。 ログに対してウィンドウを繰り返しスキャンするソリューションでは、ログが高密度である場合、二次的な動作が発生する危険があります。 

複数のログが同じタイムスタンプを共有できるという事実から、微妙な問題が発生します。 正しいソリューションでは、同じ秒数で発生した場合でもすべてのイベントをカウントする必要があり、イベント間の厳密な分離を想定してはなりません。 

もう 1 つのエッジ ケースは、応答がどのログのタイムスタンプとも一致しない場合です。 正しい瞬間は、カウントを押し上げるログの処理直後に発生する可能性があります。`m`したがって、単にタイムスタンプを返すのではなく、正確なしきい値時間を返すように注意する必要があります。`m`-回目のイベント。 

最後に、しきい値に決して到達しない場合、答えは次のようになります。`-1`。 これは、ログの合計数が以下の場合に発生します。`m`または、ログが時間的に分散しすぎて、長さのスライディング ウィンドウが存在しない場合`n`十分なイベントが含まれています。 

## アプローチ

 単純なアプローチでは、各ログのタイムスタンプがウィンドウのエンドポイント候補として扱われます。 位置のログごとに`i`、逆方向にスキャンして、最後の範囲に含まれるログの数を数えます。`n`で終わる秒数`t[i]`。 これは正しいです。答えが存在する場合、ウィンドウが十分に密になったログのタイムスタンプまたはその前に答えが存在する必要があるからです。 

ただし、これにより入れ子になったループが発生します。 それぞれについて、`N`ログをスキャンしてバックアップする場合があります`N`要素が含まれるため、最悪の場合、O(N²) 回の操作が発生します。 10^4 ログの場合、これは Python ではすでに境界線に達しており、解析コストが高くなるため安全ではなくなります。 

重要な点は、ログがすでに時間順にソートされていることです。 これにより、問題は単調シーケンスに対する古典的なスライディング ウィンドウになります。 すべてのエンドポイントのカウントを再計算する代わりに、最後のログ内にある最も古いログを追跡する左移動ポインタを維持します。`n`現在の右エンドポイントの秒数。 右ポインタを進めると、左ポインタは前方にのみ移動し、後方には移動しません。 これにより、各ログが最大 2 回処理されることが保証されます。 

また、カウントが最初に到達した正確な瞬間を検出する必要もあります。`m`。 ログのタイムスタンプをチェックするだけでなく、正確にその時点でウィンドウが有効になるものとして扱うことができます。`m`ウィンドウ内の - 番目の要素が含まれており、時間範囲条件が成立します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | お(1) | 遅すぎる |
 | スライディングウィンドウ | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ログ行を解析し、そのタイムスタンプを固定基準 (2012 年の初めなど) からの秒数を表す整数に変換します。 これにより、時間間の定数比較が可能になります。 
2. すべてのタイムスタンプを配列に保存する`t[]`昇順で。 入力では時系列順が保証されるため、並べ替えは必要ありません。 
3. 2 つのポインタを維持します。`l`(ウィンドウの左境界) および`r`(現在のイベントのインデックス)。 どちらも0から始まります。 
4. それぞれについて`r`、 前進`l`その間`t[r] - t[l] + 1 > n`。 これにより窓が確保されます`[t[r] - n + 1, t[r]]`有効です。 ウィンドウが収まるまで左から縮小していきます。 
5. ウィンドウ サイズを次のように計算します。`r - l + 1`。 これが少なくとも`m`、条件が true になった最初の瞬間を特定しようとします。 
6. 条件が最初に満たされる瞬間は必ずしも満たされるとは限らない`t[r]`、むしろ最小の時間`t*`ウィンドウが次で終わるようにする`t*`含まれています`m`イベント。 イベントは離散的でソートされているため、これは次のようになります。`t[l + m - 1] + n - 1`。 
7. 最初のものを見つけたらすぐに`r`どこ`r - l + 1 >= m`、後の時刻を早くすることはできないため、この候補時刻を計算してすぐに返します。 

### なぜ効果があるのか

 任意の固定右エンドポイントで`r`、アルゴリズムは可能な限り最小の左境界を維持します。`l`すべてが点になるように`[l, r]`一定の長さの範囲内にある`n`。 これは、ウィンドウがそのエンドポイントに対して最大の密度であることを意味します。 このウィンドウに少なくとも`m`ポイントがある場合、有効な間隔が存在し、この設定より遅くまで終了します。 時間は増加するだけなので、それ以降のウィンドウでは以前の有効なタイムスタンプを生成できないため、スキャンによって最初に見つかったタイムスタンプが`r`順序はグローバルに最小です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def to_seconds(date, time):
    # date: YYYY-MM-DD, time: HH:MM:SS, fixed year 2012 so we can simplify
    y, m, d = map(int, date.split('-'))
    hh, mm, ss = map(int, time.split(':'))

    # days per month in 2012 (leap year but Feb handling irrelevant since fixed)
    days = [0, 31, 29, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]

    total_days = 0
    for i in range(1, m):
        total_days += days[i]

    total_days += d - 1

    return total_days * 86400 + hh * 3600 + mm * 60 + ss

def format_time(x):
    days = x // 86400
    rem = x % 86400

    hh = rem // 3600
    rem %= 3600
    mm = rem // 60
    ss = rem % 60

    # reconstruct month/day
    days_in_month = [31, 29, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]
    m = 1
    while m <= 12 and days >= days_in_month[m - 1]:
        days -= days_in_month[m - 1]
        m += 1

    d = days + 1
    return f"2012-{m:02d}-{d:02d} {hh:02d}:{mm:02d}:{ss:02d}"

def parse_line(line):
    date = line[:10]
    time = line[11:19]
    return to_seconds(date, time)

def main():
    n, m = map(int, input().split())
    logs = []

    for line in sys.stdin:
        line = line.strip()
        if not line:
            continue
        logs.append(parse_line(line))

    l = 0
    ans = -1

    for r in range(len(logs)):
        while logs[r] - logs[l] + 1 > n:
            l += 1

        if r - l + 1 >= m:
            # earliest moment this window becomes valid
            start_time = logs[l + m - 1]
            ans = start_time + n - 1
            print(format_time(ans))
            return

    print(-1)

if __name__ == "__main__":
    main()
```解析ステップでは、各タイムスタンプをスカラー秒値に変換するため、比較とウィンドウ演算が簡単になります。 スライディング ウィンドウ ロジックにより、次で終了する最大有効間隔が常に維持されます。`r`。 

主要な実装の詳細は、次のように答えを計算することです。`logs[l + m - 1] + n - 1`。 これは、`m`- ウィンドウ内の th イベントが有効なイベントに完全に含まれるようになります。`n`-2番目のスパン。

 ## 特殊なケース

 エッジ ケースの 1 つは、複数のログが同じタイムスタンプを共有する場合に発生します。 その状況では、ウィンドウ サイズが 1 秒間に 1 つ以上増加する可能性があるため、アルゴリズムはそれらを別個のイベントとして扱う必要があります。 各ログを配列内の個別のエントリとして保存するため、スライディング ウィンドウは特別な処理を行わなくても自然にログを正しくカウントします。 

最後のログが処理される前に有効な間隔が完全に形成される場合、別のエッジ ケースが発生します。 最初の有効なウィンドウが表示されるとすぐに戻るため、正しい最も早い時間をオーバーシュートすることはありません。 計算`logs[l + m - 1] + n - 1`これにより、エンドポイントではなくウィンドウ内の正しいイベントに結果が固定されるようになり、イベントが密集している場合に発生する 1 つずつのずれが防止されます。
