 ## 解決策
 ## 問題の理解

 テスト ケースごとに 2 つの大きな整数が与えられ、2 つの相補的な部分の利用可能な数を表します。 これらのカウントから、トーマスは 2 つの値の最大公約数に等しい数の完全なペアを効果的に生成します。 その gcd 値を呼び出します$g$は、両方の供給から一貫して形成できる完全なアイテムの数を表すため、実際に気にする唯一の数量です。 

テスト ケースごとに 1 回$g$と判断された場合、タスクは出力しないことです$g$それ自体を素因数形式で表現します。 すべての異なる素数の除算が必要です$g$、ますますソートされ、そのような素数ごとに、因数分解で何回出現するかを出力する必要があります。 

制約のテスト ケースの数は少ないですが、値自体は最大で大きくなります。$10^{12}$。 これにより、候補者を繰り返し列挙するアプローチは直ちに除外されます。$g$または最大で試行分割を実行します$g$。 素朴な因数分解でも、$10^{12}$最悪のケースを 100 回繰り返すと、テスト ケースごとの処理が遅すぎます。 

したがって、主な計算構造は明確です。gcd を効率的に計算し、次に数値を因数分解する必要があります。$10^{12}$効率的に。 

いくつかの特殊なケースが重要です。 もし$b$そして$l$互いに素である場合、$g = 1$そして、そのテスト ケースの終了マーカーのみを、その前に素数を付けずに出力する必要があります。 もし$g$が素数である場合、その素数を多重度 1 で含む行を 1 行だけ出力する必要があります。よくある間違いは、多重度が因数分解の指数を指すことを忘れていることです。$g$、元の入力のものではありません。 

## アプローチ

 単純なアプローチでは次のように計算されます。$g = \gcd(b, l)$、次に 2 から 2 までのすべての整数をチェックして因数分解します。$\sqrt{g}$そして分割を繰り返します。 これは正しいです。すべての合成数には、その平方根までに少なくとも 1 つの素因数があるからです。 ただし、最悪の場合、$g \approx 10^{12}$、 それで$\sqrt{g} \approx 10^6$。 テスト ケースごとに最大 100 万の試行分割を実行し、これを最大 100 のケースに対して繰り返すと、おおよその結果が得られます。$10^8$Python では、各除算ステップは簡単ではありません。 これは境界に近く、TLE の危険性があります。 

重要な改善点は、因数分解に必要なのはすべての整数ではなく、素数のみであることに気づいたことです。 までのすべての素数を事前計算できます。$10^6$一度ふるいを使用してから、それぞれを因数分解します$g$これらの素数だけで割ることによって。 までの合成数なので、$10^{12}$少なくとも 1 つの素因数がある ≤$10^6$、これで十分です。 小さな素数を削除した後、残った値が 1 より大きい場合、それ自体が素数です。 

これにより、各テスト ケースが削減されます。$O(\sqrt{g})$大まかにチェックする$O(\pi(\sqrt{g}))$これは素数約 78,000 個ですが、実際には早期の削減によりさらに少なくなります。

 ## アルゴリズムのチュートリアル

 ### 1. までの素数を事前計算します。$10^6$エラトステネスのふるいを作ります。 これにより、任意の数を因数分解するために必要なすべての素数が得られます。$10^{12}$、その範囲内の合成数は最大でも素因数を持つ必要があるため、$10^6$。 

### 2. 各テストケースを処理する

 各ペアごとに$(b, l)$、計算する$g = \gcd(b, l)$。 This step is fast,$O(\log \min(b,l))$、そして何も支配しません。 

### 3. 要因$g$using precomputed primes

 素数を昇順に反復処理します。 素数ごとに$p$、分けます$g$に限って$p \mid g$、これが何回起こるかを数えます。 

成功した各部門は縮小します$g$, そのため、後の小切手が安くなります。 これが、次の場合に早期に停止する理由です。$p^2 > g$。 

### 4. 残った値を処理する

 以下のすべての素数を処理した後、$\sqrt{g}$、 残り$g > 1$の場合、それは素数であり、指数 1 を持つ最後の 1 つの因数に寄与します。 

### 5. 出力のフォーマット

 各素因数とその指数を昇順に出力します。 テスト ケースが終了したら、0 を含む 1 行を出力します。 

### なぜ効果があるのか

 正しさは、素因数分解の一意性と、すべての合成数が平方根を超えない素約数を持つという事実に基づいています。 ふるいは、考えられるすべての素数を順番にテストすることを保証するため、すべての因子が 1 回だけ完全に抽出されます。 各除算では次に進む前に素数の出現をすべて削除するため、多重度は正確にカウントされ、素数を昇順に繰り返すことによって順序付けが維持されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

MAX = 10**6

is_prime = [True] * (MAX + 1)
is_prime[0] = is_prime[1] = False
primes = []

for i in range(2, MAX + 1):
    if is_prime[i]:
        primes.append(i)
        for j in range(i * i, MAX + 1, i):
            is_prime[j] = False

def factorize(n):
    res = []
    for p in primes:
        if p * p > n:
            break
        if n % p == 0:
            cnt = 0
            while n % p == 0:
                n //= p
                cnt += 1
            res.append((p, cnt))
    if n > 1:
        res.append((n, 1))
    return res

t = int(input())
out = []

for _ in range(t):
    b, l = map(int, input().split())
    g = math.gcd(b, l)

    if g == 1:
        out.append("0")
        continue

    factors = factorize(g)
    for p, c in factors:
        out.append(f"{p} {c}")
    out.append("0")

sys.stdout.write("\n".join(out))
```ふるいは最初に 1 回構築され、すべてのテスト ケースで再利用されます。 因数分解ルーチンは慎重に一度停止します$p^2 > n$これにより、残りの数値がすでに素数になった場合、不要な反復が防止されます。 

gcd の計算では、2 つの大きな入力ではなく、テスト ケースごとに 1 つの縮小された数値のみを因数分解することが保証されます。 

ループ内で繰り返し発生する I/O オーバーヘッドを回避するために、出力はリストに蓄積されます。これは、時間制限が厳しい Python では重要です。

    is_prime[0] = is_prime[1] = False
    primes = []
    for i in range(2, MAX + 1):
        if is_prime[i]:

            for j in range(i * i, MAX + 1, i):

        res = []

            if p * p > n:
                break
            if n % p == 0:
                cnt = 0
                while n % p == 0:
                    n //= p
                    cnt += 1
                res.append((p, cnt))
        if n > 1:
            res.append((n, 1))
        return res

    t = int(input())

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、gcd が 1 の場合です。たとえば、次のように入力します。`83 24`生成する$g = 1$。 因数分解ループは完全にスキップされ、必要な出力は 1 つだけです。`0`。 因数分解関数は空のリストを返し、呼び出し元はターミネータを直接追加するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、次のような gcd が素数パワーである場合です。`49 49`、 どこ$g = 49 = 7^2$。 このループは 7 で割り切れることを検出し、2 つの割り算をカウントして追加します。`(7, 2)`。 減算した値が1になるため余りが追加されず、重複出力が防止されます。 

最後の微妙なケースは、gcd 自体が より大きい大きな素数である場合です。$10^6$、 例えば`1000000000039 1000000000039`。 その場合、ふるい素数による分割は行われないため、ループは終了し、残りは`n > 1`これにより、ふるいの範囲を超えても正確さが保証されます。
