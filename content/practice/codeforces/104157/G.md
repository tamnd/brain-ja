 ## 解決策
 ## 問題の理解

 固定の順序で立っている一連の従業員が与えられ、各従業員のタイピング時間は既知です。 同一のコンピュータが M 台あり、これらのコンピュータは並列プロセッサのように動作し、キュー内の次に利用可能な人を継続的に受け入れます。 

時間 0 で、最初の M 人の従業員が、コンピューターごとに 1 人ずつ、すぐに入力を開始します。 各コンピューターは独立して動作します。ユーザーが仕事を終えると、同じコンピューターがすぐに次の列に並んでいる人を引き継ぎます。 このプロセスはすべての従業員がテストを完了するまで続き、最後の従業員が終了した時点でコンテストは終了します。 

このタスクは、キュー全体の合計完了時間が期限 D を超えないように、コンピュータの最小数 M を決定することです。 

この制約により、考えられるすべての M にわたる直接シミュレーションは、単純に実行すると実行不可能になります。 N は最大 100000、D は最大 10^9 まで可能です。 各候補 M の完全なスケジューリングを再計算する単純な試みでは、最悪の場合 O(N^2) のコストがかかりますが、これは制限に対して遅すぎます。 M が線形にテストされる場合、チェックあたり O(N log N) であってもコストが高くなります。 

1 人の従業員の時間がすでに D より大きい場合、微妙なエッジ ケースが発生します。その状況では、無限のコンピューターがあっても、その従業員を並列化できないため、答えは依然として個々の最大実行時間によって制限されます。 たとえば、N = 3、D = 5、t = [10, 1, 1] の場合、問題が実現可能性を保証しない限り、答えは存在しません。 これは、意図した解空間に常に有効な M が含まれていると仮定しなければならないことを示しています。 

すべての処理時間が等しい場合、別の特殊なケースが発生します。 その場合、完了時間は ceil(N / M) にほぼ線形に依存し、素朴で貪欲な直観は M = N が常に必要であると誤解する可能性がありますが、キューの再利用により、D が十分に大きい場合には、より小さい M でも制約を満たすことができます。 

## アプローチ

 強引なアイデアは、1 から N までのすべての可能な数のコンピューター M を試してみることです。M ごとに、各コンピューターがいつ空になるかを追跡する優先キューまたは最小ヒープを使用して、スケジューリング プロセス全体をシミュレートします。 最初の M 個のタスクをプッシュし、最も早い仕上げマシンを繰り返しポップし、次のタスクを割り当て、すべてのタスクが処理されるまで続行します。 合計実行時間は、このシミュレーションによって生成される最大終了時間です。 

これは実際のシステムを正確に再現するため機能します。 問題は、各シミュレーションのコストが O(N log M) であり、すべての M に対してそれを実行すると、最悪の場合は O(N^2 log N) になり、これは制限をはるかに超えています。 

重要な観察は、特定の M の実現可能性が単調であるということです。 M 台のコンピュータが時間 D 以内に終了できる場合、M' > M のコンピュータも D 以内に終了できます。これは、マシンを追加しても待ち時間が短縮されるか、待ち時間が変わらないだけであるためです。 これにより、問題は M に関する単調述語に変換され、直ちに二分探索が示唆されます。 

残るのは、固定 M の実現可能性をチェックする効率的な方法です。ヒープを使用した自然なシミュレーションはすでに O(N log M) で許容されますが、二分探索により O(log N) チェックのみが必要となるため、全体の複雑さは O(N log N log N) になり、これで十分です。 

私たちは、同一のマシンに対する負荷分散と、グローバルな時間制約を満たすために必要なマシン数に対する二分探索という 2 つのアイデアを効果的に組み合わせています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N^2 log N) | O(N) | 遅すぎる |
 | 二分探索 + ヒープ シミュレーション | O(N log N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 実現可能性テストに合格する最小の M を検索することで問題を解決します。

1. M 台のコンピュータが時間 D 内にすべてのタスクを完了するのに十分であるかどうかを判断する関数 can(M) を定義します。終了時間の優先キューを使用して、問題で説明されているとおりにプロセスを正確にシミュレートします。 
2. can(M) では、まず最初の M 個のタスクを M 個のコンピュータに割り当てます。 ヒープ内の各エントリは、コンピュータが空きになる時間を表すため、i が 0 から M−1 までの t[i] で初期化します。 これは、これらの各タスクが時間 0 に開始されることを反映しています。 
3. 残りのタスクごとに、ヒープから利用可能な最も古いコンピュータを繰り返し取り出します。 そのマシンは current_time に終了し、次のタスクをそのマシンに割り当て、新しい終了時刻を current_time + t[i] として更新します。 この更新された値をヒープにプッシュして戻します。 
4. すべてのタスクが割り当てられると、この M の答えはヒープ内で見られる最大値になります。 ヒープには終了時刻が常に保存されるため、最大値は最後の従業員が完了した時刻を表します。 
5. この最大値が D 以下の場合は、M で十分です。 
6. can(M) を述語として使用して、M を 1 から N まで二分探索します。 can(M) が true の場合、より小さい M を試します。 それ以外の場合は、M を増加します。 

二分探索が機能する主な理由は、can(M) が単調であるためです。 マシンの数を増やしても完了時間が悪化しない場合は、M の値が有効になると、それより大きな値はすべて有効のままになります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def can(M, t, D):
    if M >= len(t):
        return max(t) <= D

    heap = t[:M]
    heapq.heapify(heap)

    for i in range(M, len(t)):
        earliest = heapq.heappop(heap)
        finish = earliest + t[i]
        heapq.heappush(heap, finish)

    return max(heap) <= D

def solve():
    N, D = map(int, input().split())
    t = list(map(int, input().split()))

    lo, hi = 1, N
    ans = N

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, t, D):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```関数 can(M) は、システムをマルチマシンのスケジューリング プロセスとして正確にシミュレートします。 ヒープには現在の終了時間が保存されるため、常に最も早い利用可能なマシンを再利用します。 割り当てを遅らせても完了時間が長くなるだけであるため、この貪欲な割り当てが必要です。 

二分探索により、すべての M 値を明示的にテストしないことが保証されます。 代わりに、単調性を利用して検索スペースを対数的に削減します。 

微妙な点は、最初の M 個のタスクによるヒープの初期化です。 これは時間ゼロでの同時開始をモデル化しますが、これは重要です。 マシンを最初はアイドル状態として扱うと、すべての完了時間が誤ってずれてしまいます。 

## 実用的な例

 ### サンプル 1

 入力:```
N = 6, D = 151
t = [56, 94, 95, 33, 62, 28]
```二分探索によって候補 M 値をテストします。 

| M | ヒープの進化 (終了時間) | 最終最大値 | 実現可能 |
 | --- | --- | --- | --- |
 | 1 | [56] → [150] → [245] → ... | >151 | いいえ |
 | 2 | [56, 94] → [56, 127] → [150, 127] → ... | >151 | いいえ |
 | 3 | [56, 94, 95] → 更新 → 最大 ≤ 151 | 151 | はい |

 M = 3 の場合、スケジューリングによって十分な負荷のバランスがとれるため、どのマシンも期限を超えなくなります。 

これにより、M を増やすと個々のマシンへの負荷が軽減され、しきい値が 3 と厳しくなっていることが確認されます。 

### サンプル 2

 入力:```
N = 9, D = 83
t = [10, 47, 53, 9, 83, 33, 15, 24, 28]
```| M | 行動の概要 | 最終最大値 | 実現可能 |
 | --- | --- | --- | --- |
 | 4 | キューには遅延タスクが蓄積されます。 >83 | いいえ |
 | 5 | 負荷は均等に分散されます。 ≤83 | はい |

 M = 5 の場合、長いタスク (83) は依然として正確に適合し、残りのすべてのタスクはカスケード遅延なしで完了します。 

このトレースは、十分なマシンが使用できない場合、単一の長いタスクがどのようにスケジューリングを支配するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log N log N) | 各実現可能性チェックには O(N log M) のコストがかかり、二分探索では別の log N 係数が追加されます。 
| スペース | O(N) | ヒープには最大 M 個の要素が格納されます。 

この制約では最大 10^5 の従業員が許可され、対数係数は 2 秒の制限に対して十分小さいままです。 ヒープ操作は、定数が小さいため、実際には効率的です。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import heapq

    def can(M, t, D):
        if M >= len(t):
            return max(t) <= D
        heap = t[:M]
        heapq.heapify(heap)
        for i in range(M, len(t)):
            earliest = heapq.heappop(heap)
            heapq.heappush(heap, earliest + t[i])
        return max(heap) <= D

    def solve():

        t = list(map(int, input().split()))

        lo, hi = 1, N
        ans = N
        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, t, D):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1
        print(ans)

    solve()
    return sys.stdout.getvalue().strip()

 ## 特殊なケース

 重要なエッジ ケースは、M が 1 に等しい場合です。この場合、すべてのタスクが 1 台のマシン上で順番に実行されるため、アルゴリズムは単純なプレフィックス合計に縮退します。 ヒープ ロジックは引き続き正しく動作しますが、事実上不要なオーバーヘッドとなります。 入力用`[5, 5, 5]`D = 10 の場合、シミュレーションでは終了時間 15 が生成され、M = 1 が正しく拒否されます。 

もう 1 つの重要なケースは、M が N 以上である場合です。ここでは、すべてのタスクが独自のマシンを取得するため、答えは単純に t の最大値になります。 コードはこれを明示的に処理し、ヒープ操作が無駄にならず、正確さが保たれるようにします。 

3 番目のケースでは、多くの小さなタスクの中の 1 つの非常に大きなタスクが含まれます。 ヒープにより、この大きなタスクが常に早い段階でマシンを占有することが保証され、二分探索により、D を満たすのに十分な効果を分離する最小の M が確実に見つかります。
