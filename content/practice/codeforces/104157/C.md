 ## 解決策
 ## 問題の理解

 2D 平面上の円形のターゲットと、さまざまな従業員が物体を投げた場所を表す点のリストが与えられます。 タスクは、これらの投げられた点が円の内側、または正確にその境界上に着地する数を数えることです。 

各スローは単なる座標ペアです。 円は中心と半径によって定義されます。 中心からのユークリッド距離が半径以下の場合、スローは成功します。 

制約は十分に大きいため、どのソリューションでも各ポイントを一定時間で処理する必要があります。 最大 100,000 回の投球で、$O(n)$解決策が期待されています。 並べ替えやペアごとの比較を伴うものはすべて不必要であり、遅すぎます。 

このような問題でよく現れる微妙な問題は、距離を計算するときの数値的安全性です。 単純な式には平方根が含まれており、浮動小数点の比較では精度誤差が生じる可能性があります。 もう 1 つのよくある落とし穴は、座標を 2 乗するときに 32 ビット整数を使用することです。$10^9$、すぐに溢れてしまいます。 

いくつかの危険な状況が重要になります。 

境界上にある点は成功したと見なされます。 たとえば、中心が$(0,0)$そして半径は$5$、ポイント$(3,4)$数えなければならないので、$3^2 + 4^2 = 25$。 

2 番目の微妙なケースは、大きな座標です。 計算してみると$(x - c_x)^2$32 ビット整数を使用、値に近い$10^9$周りに生産する$10^{18}$、これには 64 ビット演算が必要です。 間違った型を使用すると、不正な結果が暗黙的に生成されます。 

## アプローチ

 問題を解決する直接的な方法は、各スローを個別に処理し、円の中心までの距離を計算することです。 各点について、次の式を使用してユークリッド距離を計算します。$\sqrt{(x_i - c_x)^2 + (y_i - c_y)^2}$、以下であるかどうかを確認します。$r$。 これは正しいです。なぜなら、「円の内側」の定義はまさにその距離条件だからです。 

ただし、これにはすべての点の平方根が必要になります。 その間$O(n)$漸近的な複雑さの点では問題ありませんが、平方根演算は比較的高価であり、不必要です。 さらに重要なのは、浮動小数点の比較では、境界付近で精度誤差が発生する可能性があり、点が含まれる必要があるにもかかわらず、丸めのために除外される可能性があります。 

重要な観察は、実際の距離は決して必要ないということです。 半径と比較するだけで済みます。 両辺が負ではないため、不等式の両辺を安全に二乗できます。$$(x_i - c_x)^2 + (y_i - c_y)^2 \le r^2$$これにより、平方根が完全に削除され、問題が単純な整数演算に変換されます。 これで、各点に必要な整数演算はわずか数回だけになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ポイントあたりの平方根) | O(n) | お(1) | 受け入れられるが壊れやすい |
 | 二乗距離チェック | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 点の数、円の中心座標、半径を読み取ります。 すぐに計算してみます$r^2$したがって、処理中に再計算する必要はありません。 これにより、乗算の繰り返しが回避され、比較が均一に保たれます。 
2. カウンタをゼロに初期化します。 これにより、円の条件を満たすポイントの数が追跡されます。 
3. 投げるごとに$(x_i, y_i)$、中心からの水平オフセットと垂直オフセットを計算します。$dx = x_i - c_x$、$dy = y_i - c_y$。 これらのオフセットは、中心から点までの変位ベクトルを表します。 
4. 二乗距離を計算します$dx^2 + dy^2$。 これは中心からの正確な二乗ユークリッド距離です。 平方根は比較には不要なため、意図的に避けています。 
5. 二乗距離を次と比較します。$r^2$。 以下の場合は、カウンターをインクリメントします。 これは、円の内側または境界上にあるという定義に直接対応します。 
6. すべてのポイントを処理した後、カウンタを出力します。 

### なぜ効果があるのか

 正しさは、二乗が非負の値に対して単調であるという事実に基づいています。 二乗距離と$r^2$は常に負ではないため、それらを比較すると元の距離の順序が維持されます。 これは、二乗後の不等式が元の幾何学的条件と同等であることを意味します。 すべての点は、真のユークリッド距離に基づく場合とまったく同じように分類されますが、浮動小数点計算は導入されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, cx, cy, r = map(int, input().split())
    r2 = r * r

    cnt = 0
    for _ in range(n):
        x, y = map(int, input().split())
        dx = x - cx
        dy = y - cy
        if dx * dx + dy * dy <= r2:
            cnt += 1

    print(cnt)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムに直接に従います。 前処理ステップでは、$r^2$、各クエリが固定数の算術演算のみを実行するようにします。 

減算ステップは、座標を円の原点を中心とするローカル フレームに縮小するため、重要です。 これにより、絶対位置が必要なくなります。 

すべての算術演算は Python 整数を使用して実行され、自然に大きな値がサポートされるため、オーバーフローのリスクはありません。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、点が円の境界上に正確に位置する場合です。 入力を考慮してください。```
1 0 0 5
3 4
```アルゴリズムは計算します$dx = 3$、$dy = 4$、 そして$dx^2 + dy^2 = 25$。 以来$r^2 = 25$、条件が満たされ、ポイントがカウントされます。 これにより、浮動小数点許容値を必要とせずに、境界点が正しく含まれていることを確認できます。 

もう 1 つの特殊なケースは、大きな座標値です。```
1 1000000000 -1000000000 1
1000000000 -999999999
```ここ$dx = 0$、$dy = 1$なので、二乗距離は 1 です。中間座標値が巨大であっても、Python の整数演算はそれらを安全に処理し、比較は正しいままです。
