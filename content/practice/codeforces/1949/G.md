 ## 解決策
 ## 問題の理解

 各建物には 2 つの独立した情報があります。 

最初の文字列は、そこで開催されるクラスを記述します。 建物には数学の教授やコンピュータ サイエンスの教授が必要な場合もあれば、まったく教授が必要ない場合もあります。 

2 番目の文字列は、最初にそこに配置されている教授を記述します。 建物には数学の教授がいる場合もあれば、コンピュータ サイエンスの教授がいる場合もあれば、誰もいない場合もあります。 

あなたはちょうど 1 人の教授を乗せることができるスクーターを運転します。 各建物への訪問は最大 1 回までです。 訪問した建物で、最初に現在同乗している教授を降ろし、その後、元々そこにいた教授を迎えに行くことができます。 

目標は、何かを最小化することではありません。 必要なのは、正しい専門分野の教授が担当するすべてのクラスで終了する有効な旅程を出力することだけです。 

バウンド$n \le 2000$は十分に小さいため、二次作業は完全に許容されます。 課題は効率ではなく、有効な旅程を簡単に構築できる隠れたグラフ構造を発見することです。 

よくある間違いは、建物を個別に考えることです。 建物は一度しか訪問できないという制限は、建物を離れると、その建物の最終的な教授の割り当てが永久に固定されることを意味します。 

考慮する```
c = "M"
p = "M"
```建物はすでに正しいです。 訪問は不要です。 すべての教授を動かそうとする解決策は、存在する必要のない仕事を生み出すことになります。 

もう一つの微妙なケースは、```
c = "CM-"
p = "-CM"
```これがサンプルです。 クラスのない建物は、輸送チェーンの開始点として機能します。 そのような教授のソースがなければ、人々を動かし始めることはできません。 

重要な観察は、スクーターには常に 1 種類の教授タイプが搭載されており、すべてのピックアップが降ろされたばかりの教授とすぐに置き換わることです。 その行動により、教授のタイプ間の移行が自然に形成されます。 

## アプローチ

 強引なアプローチでは、建物の可能なすべての訪問命令をシミュレートしようとします。 たとえ$n=20$、 がある$20!$注文数はすでに天文学的な規模になっています。 探索スペースは、実際の制限である 2000 棟に達するずっと前に爆発的に増加します。 

有益な観察は、教授タイプが 3 つだけ存在するということです。```
-
M
C
```クラスタイプの建物の場合$c_i$そして初期の教授タイプ$p_i$、有向エッジを想像してください$$c_i \rightarrow p_i$$なぜこの方向なのでしょうか？ 

タイプの教授を連れて到着したとします。$c_i$。 私たちはその教授を建物に降ろして、そのクラスを満足させることができます。 次に、タイプの元の教授をピックアップします$p_i$そしてそのタイプを持ち続けます。 

したがって、この建物を訪れると、運ばれるタイプが$c_i$の中へ$p_i$。 

これで、すべての建物が、頂点が 3 つだけのグラフ内の有向エッジになります。```
-, M, C
```有効な旅程は、ある建物の出力タイプが次の建物の必要な入力タイプと等しくなるように、エッジを横断することに対応します。 それはまさにオイラートラバーサルの定義です。 

このステートメントは有効な旅程が存在することを保証するため、結果のグラフはオイラー型になります。 オイラー回路を見つけて、そのエッジをスクーターの演算に変換するだけです。 

グラフには頂点が 3 つしかないため、Hierholzer のアルゴリズムで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n!)$|$O(n)$| 遅すぎる |
 | オイラーツアー建設 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. グラフを作成する

 以下に対応する 3 つの頂点を作成します。```
0 = -
1 = M
2 = C
```あらゆる建物に$i$、有向エッジを追加します$$c_i \rightarrow p_i$$そしてそのエッジに建物のインデックスを保存します。 

### 2. オイラー回路を見つける

 Hierholzer のアルゴリズムを頂点から実行する`-`。 

すべてのエッジは 1 回だけ使用する必要があります。 

Hierholzer によってエッジが生成される順序は、建物が輸送チェーンに参加する順序になります。 

### 3. オイラー回路を建物に変換する

 オイラー回路がエッジ シーケンスを返すようにします$$e_1, e_2, \dots, e_k$$ここで、各エッジは建物に対応します。 

連続するエッジは次の条件を満たす$$p(e_i)=c(e_{i+1})$$これはまさにスクーターに必要な互換性条件です。 

### 4. コマンドを生成する

 最初の端の建物まで車で向かいます。 

最初の教授がそうでない場合`-`、 問題`PICKUP`。 

後続のすべての建物について:

 1.`DRIVE`あの建物へ。 
2. 教授を乗せている場合は、`DROPOFF`。 
3. 建物に最初から教授がいる場合は、`PICKUP`。 

最後の建物を処理した後、教授がまだ運ばれている場合は、最後の建物を発行します`DROPOFF`。 

オイラー回路は、すべてのドロップオフ教授がその建物に対して適切な専門知識を持っていることを保証します。 

### なぜ効果があるのか

 各エッジは、転送された教授タイプをそのクラス タイプから元の教授タイプに変換する建物を表します。 

オイラー回路では、すべてのエッジの終了頂点は次のエッジの開始頂点と等しくなります。 したがって、ある建物で選択された教授のタイプは、次の建物で必要とされるタイプとまったく同じになります。 

教授を建物に送り届けるとき、エッジはそのクラス タイプから始まるため、その教授の専門分野はその建物のクラス タイプと一致します。 次に、ピックアップは、キャリーされるタイプをエッジの宛先頂点に変更します。 

すべてのエッジが 1 回だけ使用されるため、すべての建物が 1 回だけ処理されます。 トラバースはオイラー式であるため、すべての型要件がチェーン全体で一致します。 すべてのクラスは、適切な専門分野の教授によって終了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = input().strip()
    p = input().strip()

    mp = {'-': 0, 'M': 1, 'C': 2}
    rev = ['-', 'M', 'C']

    g = [[] for _ in range(3)]

    for i in range(n):
        u = mp[c[i]]
        v = mp[p[i]]
        g[u].append((v, i + 1))

    ptr = [0] * 3
    stack_v = [0]
    stack_e = []
    euler = []

    while stack_v:
        v = stack_v[-1]

        if ptr[v] < len(g[v]):
            to, idx = g[v][ptr[v]]
            ptr[v] += 1

            stack_v.append(to)
            stack_e.append(idx)
        else:
            stack_v.pop()
            if stack_e:
                euler.append(stack_e.pop())

    euler.reverse()

    ops = []

    if not euler:
        print(0)
        return

    first = euler[0]
    ops.append(f"DRIVE {first}")

    carrying = False

    if p[first - 1] != '-':
        ops.append("PICKUP")
        carrying = True

    for b in euler[1:]:
        ops.append(f"DRIVE {b}")

        if carrying:
            ops.append("DROPOFF")
            carrying = False

        if p[b - 1] != '-':
            ops.append("PICKUP")
            carrying = True

    if carrying:
        ops.append("DROPOFF")

    print(len(ops))
    print("\n".join(ops))

solve()
```グラフには頂点が 3 つしか含まれていませんが、エッジは最大 2000 個含まれています。 最終的な旅程はグラフのエッジではなく建物を参照する必要があるため、各エッジには建物のインデックスが格納されます。 

Hierholzer のアルゴリズムは反復的に実装されます。 の`stack_v`stack は現在の DFS パス上の頂点を保存しますが、`stack_e`対応するエッジ識別子を格納します。 頂点が出ていくエッジがなくなると、最新のエッジがオイラー回路の一部になります。 

生成されたエッジ リストを反転した後、走査順序を取得します。 

コマンド生成フェーズは、エッジの解釈を直接反映します。 ピックアップは、運ばれるプロフェッサータイプを端の目的地に変更します。 ドロップオフは前の端から運ばれた教授を消費します。 オイラー プロパティは、すべての降車特殊化が次の建物のクラス要件と一致することを保証します。 

最も繊細な細部は順序です`DROPOFF`それから`PICKUP`。 この声明では、建物内での降車と乗車は、この順序で最大 1 回まで許可されます。 逆にするとルール違反になります。

 ## 特殊なケース

 検討してください```
1
M
M
```建物にはすでに正しい教授がいます。 グラフ用語で言えば、これは自己ループです。`M → M`。 Hierholzer は自己ループを自然に処理します。 建物を訪問すると、同じ専門分野をドロップして取得するだけで、正確性が保たれます。 

考慮する```
3
CM-
-CM
```教授の唯一の供給源は、授業のない建物です。 そのエッジは`- → M`、これがオイラー回路の自然な始まりになります。 アルゴリズムはそこから始まり、数学教授を選択し、チェーンを通じて専門分野を伝播させます。 

考慮する```
4
MMCC
MMCC
```すべてのエッジは自己ループです。 実際に移動する必要がある教授はいません。 各建物がそのクラス要件をすでに満たしているため、オイラー トラバーサルは依然として存在し、有効なままです。 生成された旅程では 1 回の訪問制限が尊重され、互換性のない割り当てが作成されることはありません。 

これらすべての場合における重要な不変条件は変更されません。`c → p`処理され、そこに落とされた教授は専門性を持っています`c`、そして持ち去られた教授は専門を持っています`p`。 オイラー トラバーサルにより、これらのタイプが連続する建物全体で一致することが保証されます。
