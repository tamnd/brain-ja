 ## 解決策
 ## 問題の理解

 一連のモンスターを倒すまでの合計時間を最小限に抑えるために、2 つの属性 (ヒットあたりのダメージと秒あたりのヒット数) の間で固定数のスキル ポイントを配分するように求められます。 各モンスターには健康値があります$h_i$、そしてそれを倒すまでの時間は、体力の上限をヒットあたりのダメージで割ったもの、さらに1秒あたりのヒット数で割ったものによって決まります。 正式に割り当てると、$x$ヒットごとのダメージポイントと$y$1秒あたりのヒット数のポイント、モンスターを倒すまでの時間$i$は$\lceil h_i / x \rceil / y$、合計時間はすべてのモンスターの合計です。 

制約は大きいです:$n$最大 200,000 まで可能で、$h_i$到達できる$10^{13}$。 これは、すべての攻撃をシミュレートしたり、あらゆる小さな増分を考慮したりすることはできないことを意味します。$x$そして$y$個別に。 の合計$x$そして$y$を超えてはなりません$k$、これも最大200,000です。 モンスターの数が多いため、モンスターごとの仕事は O(1) または対数でなければなりません。 考えられるすべてのペアを総当たりでチェックする$(x, y)$これには O(k^2) の操作が含まれますが、これは最悪の場合約 4*10^10 であり、明らかに不可能です。 

すべてのモンスターの体力が非常に小さい場合、微妙なエッジケースが発生しますが、$k$大きいです。 たとえば、次の場合$n = 1$、$k = 7$、 そして$h_1 = 1$、バランスを取ろうとする素朴な試み$x$そして$y$均等に物事を複雑にしすぎる可能性があります。 同様に、1 つのモンスターの体力が非常に大きく、他のモンスターの体力が小さい場合、単純にポイントを均等に分割するだけでは最適とは程遠い可能性があります。 

## アプローチ

 素朴なアプローチは、スキル ポイントの可能なすべての割り当てを反復することです。すべて試してみます。$x$1から$k-1$、 セット$y = k - x$、すべてのモンスターの合計時間を計算します。 これは正しいですが、最悪の場合の時間計算量は次のとおりです。$O(n \cdot k)$、大まかに言うと$4 \cdot 10^{10}$最悪のシナリオでの運用。 明らかに、これは妥当な時間内に実行されません。 

重要な洞察は、合計時間が反比例するという認識から得られます。$y$そして減少しています$x$区分的線形方式で。 あらゆる可能性をチェックするのではなく、$x$、合計時間に対して二分探索を実行できます。 一定の時間$T$、割り当てが存在するかどうかを確認できます$(x, y)$満足のいく$x + y \le k$合計時間 ≤ T を達成します。チェックは最小値の計算に限定されます。$y$各候補者に必要な$x$:$y \ge \lceil \sum_i \lceil h_i / x \rceil / T \rceil$。 次に、最小のものを選択します$x$それは満足する$y \le k - x$。 

これにより、二次総当たり検索が時間どおりの二分検索に変換されます。これは、両方に関して合計時間が単調であるため、効率的です。$x$そして$y$検索が正しいことを確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * k) | お(1) | 遅すぎる |
 | 最適 | O(n * log(max_h * n)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのモンスターの健康状態の合計を計算します。 これは、1 秒あたり 1 つのヒットのみを割り当てる場合の合計時間の上限です。 
2. 合計時間の二分探索範囲を初期化します。$T$。 下限は$0$、上限は次の合計になります。$\lceil h_i / 1 \rceil$1ヒットあたり1ダメージ、1秒あたり1ヒットと仮定します。 
3. 検索範囲が有効な間に、中点を選択します。$T$。 整数が存在するかどうかを確認する$x$1との間$k-1$そのように割り当てる$x$ダメージを与えたり、$y = \lceil \sum_i \lceil h_i / x \rceil / T \rceil \le k - x$時間要件を満たしています。 
4. このチェックを効率的に実行するには、次の手順を繰り返します。$x$1 から順に合計を計算します。$\lceil h_i / x \rceil$すべてのモンスターにわたって。 対応する場合は、$y$可能であれば、ペアを記録します$(x, y)$二分探索を調整して、より小さいものを探します。$T$。 
5. 検索が完了したら、ペアを出力します$(x, y)$見つかった最小合計時間を達成します。 

機能する理由: どちらの場合も合計時間は単調です$x$そして$y$。 増加中$x$モンスターごとに必要なヒット数は減少しますが、増加します。$y$直接比例して時間が減少します。 二分探索はこの単調性を利用して、すべての割り当てを明示的に評価することなく最小時間に収束します。 切り上げ演算 ($\lceil \cdot \rceil$) は、オフセットを使用した整数除算を使用して処理され、正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import ceil

def main():
    n, k = map(int, input().split())
    h = list(map(int, input().split()))

    def feasible(T):
        best_x = None
        best_y = None
        for x in range(1, k):
            total_hits = sum((hi + x - 1) // x for hi in h)
            y = (total_hits + T - 1) // T
            if y <= k - x:
                return (x, y)
        return None

    # Binary search over time
    left, right = 1, max(h) * n
    ans_x, ans_y = 1, k - 1
    while left <= right:
        mid = (left + right) // 2
        res = feasible(mid)
        if res:
            ans_x, ans_y = res
            right = mid - 1
        else:
            left = mid + 1

    print(ans_x, ans_y)

if __name__ == "__main__":
    main()
```の`feasible`関数は指定された合計時間があるかどうかをチェックします$T$すべてを試すことで達成できる$x$1から$k-1$必要な計算を行います$y$。 二分探索は反復的に時間の上限を減らし、最終的なペアは$(x, y)$実行可能な最小時間を満たすことが保証されています。 使用する`(hi + x - 1) // x`浮動小数点エラーなしで天井除算を効率的に計算します。
