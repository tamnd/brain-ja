 ## 解決策
 ## 問題の理解

 各ユーザーは一連のアクティビティとして表示できます。 

セットが 3 つの条件を同時に満たす 2 人のユーザーを見つける必要があります。 

1. 彼らは少なくとも 1 つのアクティビティを共有します。 
2. 最初のユーザーは、2 番目のユーザーが持たないアクティビティを少なくとも 1 つ持っています。 
3. 2 番目のユーザーは、最初のユーザーが持たないアクティビティを少なくとも 1 つ持っています。 

セットの用語では、交差部分が空ではないが、どちらのセットももう一方のサブセットではない 2 つのセットを探します。 

入力には最大 200,000 人のユーザーが含まれますが、リストされる全ユーザーのアクティビティの合計数は最大 1,000,000 です。 この 2 番目の境界が重要です。 これは、入力データの総量に比例した作業を行う余裕はありますが、ユーザーのすべてのペアを比較する余裕はないことを意味します。 

すべてのペアのブルート フォース チェックには、大まかに次のものが必要になります。$$\binom{200000}{2} \approx 2 \cdot 10^{10}$$比較することは完全に不可能です。 

アクティビティの世界は非常に大きく、$10^6$、ただしせいぜい$10^6$アクティビティの発生が実際に表示されます。 どのソリューションも、一定のサイズの構造を構築しようとするのではなく、入力で発生するアクティビティで機能する必要があります。$m$。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

2 人の同一のユーザーを考えてみましょう。```
2 3
2 1 2
2 1 2
```正しい答えは、`NO`。 彼らはアクティビティを共有しますが、どちらのユーザーも他方に欠けているものを持っていません。 空ではない交差点のみをチェックするソリューションでは、誤って返される可能性があります。`YES`。 

2 人の素のユーザーを考えてみましょう。```
2 3
1 1
1 2
```正しい答えは、`NO`。 各ユーザーは独自のアクティビティを持っていますが、何も共有していません。 

サブセットの関係を考えてみましょう。```
2 4
1 1
2 1 2
```正しい答えは、`NO`。 これらはアクティビティ 1 を共有しますが、最初のセットは 2 番目のセットの中に含まれています。 両方のユーザーが、相手が持っていないものを持っている必要があります。 

最後の微妙なケースは、多数のユーザーがまったく同じアクティビティを含む場合です。 アクティビティの頻度だけを見るだけでは十分ではありません。 私たちは同一の集合と比較できない集合を区別しなければなりません。 

## アプローチ

 最も直接的な解決策は、ユーザーのすべてのペアを比較します。 

ペアセットの場合$A$そして$B$、次のことを確認できます。$$A \cap B \neq \varnothing$$そして$$A \setminus B \neq \varnothing$$そして$$B \setminus A \neq \varnothing.$$これは、適切な一致の定義を直接実装しているため、正しいです。 

問題はペアの数です。 ユーザーが 200,000 人いると、ペア数は約 200 億になります。 たとえすべての比較が非常に安かったとしても、これは限界をはるかに超えています。 

進歩するには、制約の特殊な構造を利用する必要があります。 

重要な観察点は、アクティビティ発生の総数はわずか 2 回であるということです。$10^6$。 これは、古典的なヘビーライトのアイデアを示唆しています。 

多くのユーザーに表示されるアクティビティを「ヘビー」と呼び、それ以外の場合は「ライト」と呼びます。 

しきい値を選択するとします$$B \approx \sqrt{10^6}=1000.$$すべての重いアクティビティは少なくとも 1000 個の重いアクティビティに影響を与えるため、最大で約 1000 個の重いアクティビティが存在する可能性があります。$B$出現回数は最大で 1 回です。$10^6$。 

ここでユーザーセットを考えてみましょう$S$。 

もし$|S| \ge B$、それをヘビーユーザーと呼びます。 すべてのセットの合計サイズは最大でも 1000 人程度であるため、ヘビー ユーザーは最大でも約 1000 人になる可能性があります。$10^6$。 

この平方根分解により、管理可能な 2 つの世界が作成されます。 

ヘビーユーザーの場合、その数は約 1000 しかありません。 メンバーシップ構造を迅速に構築し、効率的に比較できます。 

ライト ユーザーの場合、各セットに含まれる内容は以下のとおりです。$B$活動。 アクティビティ発生率リストを通じてそれらを処理できます。 各ライトセットは小さいため、全体の作業量はほぼ同じです$O(10^6 \sqrt{10^6})$。 

重要な特性は、2 人のユーザーが交差する場合には正確に一致するが、包含される場合には比較できないということです。 

編集ソリューションは、セット間の包含情報を構築し、実際にアクティビティを共有するペア間のみを検索して、二次爆発を回避します。

 ## アルゴリズムのチュートリアル

 しましょう$$T=\sum k_i.$$選ぶ$$B=\lfloor\sqrt{T}\rfloor+1.$$すべてのユーザーのアクティビティを並べ替えられたリストとして表します。 

### 1. すべてのアクティビティの発生を発生リストに圧縮します。 

すべてのアクティビティについて、それを含むユーザーを保存します。 

これにより、実際に少なくとも 1 つのアクティビティを共有するユーザーのペアのみを列挙することができます。 

### 2. ユーザーをヘビーまたはライトに分類する

 設定されたサイズが少なくとも次の場合、ユーザーはヘビーです$B$。 

すべてのセットの合計サイズは$T$、ヘビーユーザーの数は最大でも$T/B = O(\sqrt T)$。 

この境界により、後の処理が可能になります。 

### 3. ヘビーユーザー向けに迅速なメンバーシップ構造を構築する

 ヘビー ユーザーごとに、そのすべてのアクティビティをハッシュ テーブルに保存します。 

これにより、一定の予想時間内でメンバーシップをテストできます。 

### 4. すべてのユーザーに対してヘビー ユーザーを処理する

 ヘビーユーザー向け$H$、すべてのユーザーとの交差数を計算します。 

の各アクティビティを反復します。$H$。 そのアクティビティを含むユーザーごとに、カウンターを増やします。 

このスキャンの後、すべてのユーザーに対して$U$、カウンターは次と等しい$$|H \cap U|.$$かどうかを確認してください$$0 < |H\cap U| < |H|$$そして$$0 < |H\cap U| < |U|.$$これらの不等式は次のことを意味します。 

- 交差点が空いていない、
 -$H$外に何かがある$U$、
 -$U$外に何かがある$H$。 

それらが成立する場合、有効なペアが見つかったことになります。 

### 5. ライトユーザーのペアを処理する

 すべてのライトユーザーには以下の内容が含まれます$B$活動。 

各アクティビティについて、そのアクティビティを含むライト ユーザーのリストを確認します。 

2 人のライト ユーザーが何らかのアクティビティを通じて出会うと、少なくとも 1 つのアクティビティを共有します。 

一方が他方のサブセットであるかどうかを判断する必要があります。 

候補ペアをカウント構造に保存します。 共有アクティビティごとに、ペアの共通アクティビティ数を増やします。 

すべてのアクティビティが処理された後、ペア$(A,B)$価値がある$$c = |A \cap B|.$$このペアはまさに次のような場合に適しています。$$c > 0,$$

$$c < |A|,$$そして$$c < |B|.$$これらの条件が当てはまる場合、どちらのセットにももう一方のセットが完全に含まれておらず、少なくとも 1 つのアクティビティを共有します。 

### 6. 最初の有効なペアを出力します。 

いずれかのフェーズで有効なペアが見つかった場合は、出力します。`YES`および対応するインデックス。 

すべてのチェックが成功せずに終了した場合は、印刷します`NO`。 

### なぜ効果があるのか

 アクティビティを共有するユーザーのペアごとに、アルゴリズムは交差部分の正確なサイズを計算します。 

ペアは、交差部分が両方のセット サイズよりも厳密に小さい場合にのみ受け入れられます。 これは、各ユーザーが交差点の外側で少なくとも 1 つのアクティビティを所有していることを意味します。 同様に、どちらのセットももう一方のセットには含まれません。 

交差部分が空であるか、設定されたサイズのいずれかに等しい場合、ペアは拒否されます。 このような場合、ユーザーは何も共有していないか、一方のプロファイルがもう一方のプロファイルのサブセットであり、適切な一致の定義に違反します。 

ヘビーユーザー処理では、ヘビーユーザーが関与するすべてのペアを検査します。 ライトユーザー処理では、ライトユーザーだけで構成されるすべてのペアを検査します。 考えられるすべてのペアは、これらのカテゴリのいずれかに正確に属するため、有効な答えを見逃すことはできません。 

## Python ソリューション```python
import sys
from math import isqrt
from collections import defaultdict

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    sets = []
    total = 0
    activity_users = defaultdict(list)

    for idx in range(n):
        row = list(map(int, input().split()))
        k = row[0]
        arr = row[1:]
        sets.append(arr)
        total += k

        for x in arr:
            activity_users[x].append(idx)

    B = isqrt(max(total, 1)) + 1

    heavy = []
    is_heavy = [False] * n

    for i in range(n):
        if len(sets[i]) >= B:
            is_heavy[i] = True
            heavy.append(i)

    # Heavy versus all users
    cnt = [0] * n

    for h in heavy:
        touched = []

        for act in sets[h]:
            for u in activity_users[act]:
                if cnt[u] == 0:
                    touched.append(u)
                cnt[u] += 1

        hs = len(sets[h])

        for u in touched:
            if u == h:
                continue

            c = cnt[u]

            if c > 0 and c < hs and c < len(sets[u]):
                print("YES")
                print(h + 1, u + 1)
                return

        for u in touched:
            cnt[u] = 0

    # Light-light pairs
    pair_cnt = defaultdict(int)

    for users in activity_users.values():
        light_users = [u for u in users if not is_heavy[u]]

        s = len(light_users)

        for i in range(s):
            a = light_users[i]
            for j in range(i + 1, s):
                b = light_users[j]
                if a > b:
                    a, b = b, a
                pair_cnt[(a, b)] += 1

    for (a, b), c in pair_cnt.items():
        if c < len(sets[a]) and c < len(sets[b]):
            print("YES")
            print(a + 1, b + 1)
            return

    print("NO")

if __name__ == "__main__":
    solve()
```最初の部分では、すべてのセットを読み取り、同時にアクティビティ発生リストを作成します。 今後のすべての操作は共有アクティビティによって推進されるため、これらの発生リストはソリューションの中心的な構造となります。 

ヘビー ユーザー フェーズでは、ヘビー ユーザーを他のすべてのユーザーのすべてのアクティビティと比較することはありません。 代わりに、ヘビー ユーザーのアクティビティを追跡し、正確な交差サイズを蓄積します。 の`touched`配列はどのカウンタがゼロ以外になったかを記録するため、クリーンアップは実際に実行された作業に比例したままになります。 

ライト-ライトフェーズでは、実際に何かを共有するライトユーザーのペアごとに共通のアクティビティをカウントします。 アクティビティを共有しないペアは決して保存されません。これは効率のために不可欠です。 

条件```
c < len(sets[a]) and c < len(sets[b])
```これは、「両方のユーザーが、もう一方に欠けているアクティビティを少なくとも 1 つ持っている」ということを正確に数学的に翻訳したものです。 保存されているすべてのペアはすでに`c > 0`、これは有効な一致を完全に特徴づけます。 

すべてのカウントが最大値であるため、整数オーバーフローの問題は存在しません。$10^6$、Python の整数の範囲内に十分収まります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(T\sqrt{T})$| 重軽度分解、$T=\sum k_i$|
 | スペース |$O(T)$| アクティビティリストとペア簿記 |

 アクティビティ発生の合計数は最大で次のとおりです。$10^6$。 と$B \approx \sqrt T$、ヘビーユーザーの数と重い処理によってもたらされる作業量の両方が、引き続き制限されます。$O(T\sqrt T)$。 これは、意図したソリューションの 3 秒の制限に問題なく適合します。

from collections import defaultdict

    input = sys.stdin.readline

    n, m = map(int, input().split())

    sets = []
    total = 0
    activity_users = defaultdict(list)

    for idx in range(n):
        row = list(map(int, input().split()))
        k = row[0]
        arr = row[1:]
        sets.append(arr)
        total += k

        for x in arr:
            activity_users[x].append(idx)

    B = isqrt(max(total, 1)) + 1

    heavy = []
    is_heavy = [False] * n

    for i in range(n):
        if len(sets[i]) >= B:
            is_heavy[i] = True
            heavy.append(i)

    cnt = [0] * n

    for h in heavy:
        touched = []

        for act in sets[h]:
            for u in activity_users[act]:
                if cnt[u] == 0:
                    touched.append(u)
                cnt[u] += 1

        hs = len(sets[h])

        for u in touched:
            if u != h:
                c = cnt[u]
                if c > 0 and c < hs and c < len(sets[u]):
                    return "YES\n"

        for u in touched:
            cnt[u] = 0

    pair_cnt = defaultdict(int)

    for users in activity_users.values():
        light_users = [u for u in users if not is_heavy[u]]

        for i in range(len(light_users)):
            for j in range(i + 1, len(light_users)):
                a, b = sorted((light_users[i], light_users[j]))
                pair_cnt[(a, b)] += 1

    for (a, b), c in pair_cnt.items():
        if c < len(sets[a]) and c < len(sets[b]):
            return "YES\n"

    return "NO\n"
