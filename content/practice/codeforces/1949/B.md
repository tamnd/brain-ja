 ## 解決策
 ## 問題の理解

 サイズの配列が 2 つあります`n`。 

配列`a`前菜の辛さの値と配列が含まれます。`b`メイン料理の辛さの値が含まれています。 すべての前菜は 1 つのメイン料理と組み合わせる必要があり、すべてのメイン料理は 1 回だけ使用する必要があります。 

ペア用`(a[i], b[j])`、食事の魅力は、`|a[i] - b[j]|`。 生み出される料理の中で、最も小さな魅力に注目します。 私たちの目標は、この小さな魅力ができるだけ大きくなるようにペアリングを選択することです。 

これは古典的な「最小値の最大化」問題です。 問題で最大値が求められるときは常に`X`何らかの条件が考えられる場合、通常は二分探索が適切な候補となります。 

制約が重要な手がかりとなります。 各テスト ケースには、`n ≤ 5000`、との合計`n²`すべてのテストケース全体で最大でも`25 · 10⁶`。 解決策`O(n²)`テスト ケースごとは許容されますが、階乗や指数関数は不可能です。 すべての一致を列挙するには、`n!`可能性さえも絶望的になる`n = 15`。 

微妙な点は、この条件には絶対的な違いが含まれることです。 固定閾値の場合`x`の場合、ペアは有効です。`|a[i] - b[j]| ≥ x`。 

これは、皿がはるかに小さいものまたははるかに大きなものと組み合わせることができることを意味します。 一面だけを見ている無邪気な貪欲さは、簡単に失敗する可能性があります。 

考慮する：```
a = [4, 5]
b = [1, 8]
```のために`x = 3`、両方のペアリングが機能します。```
4 ↔ 1
5 ↔ 8
```そして```
4 ↔ 8
5 ↔ 1
```常に最も近い有効な値を取得するグリーディーは、有効な一致が存在する場合でも、後の割り当てをブロックする可能性があります。 

多くの値が等しい場合には、別の注意が必要なケースが発生します。```
a = [1, 1, 1]
b = [1, 1, 1]
```すべての魅力は等しい`0`、したがって、答えは次のとおりです`0`。 個別の値を仮定するアルゴリズムや厳密な不等式に依存するアルゴリズムはここで機能しません。 

3 番目のエッジ ケースは、一方の配列のすべての値が他方のすべての値を大幅に下回る場合です。```
a = [0, 0, 0]
b = [100, 100, 100]
```あらゆるマッチングが魅力を生み出す`100`、したがって、答えは次のとおりです`100`。 最適なマッチングは複雑なものではなく、すべてのペアは同等です。 

## アプローチ

 ブルートフォースのアイデアは単純です。 2 つの配列間で可能な限り完全な一致を生成し、その一致内の最小魅力を計算して、最良の結果を維持します。 

これが機能するのは、すべての有効なペアリングの配置を直接チェックするためです。 問題はマッチング数です。 がある`n!`完璧なマッチング。 たとえ`n = 15`、これは 1 兆の可能性を超えています。 アプローチは使えない。 

目標の構造は、別の視点を示唆しています。 

誰かが答えの候補を教えてくれたとします。`x`。 最適な答えをすぐに求めるのではなく、「はい/いいえ」で答えられる質問をしてください。 

「どのペアにも少なくとも魅力があるような、完璧なマッチングを作り出すことはできないだろうか」`x`？」

 これに効率的に答えることができれば、二分探索を行うことができます。`x`実現可能な最大値を与えます。 

残りの課題は実現可能性の確認です。 

両方の配列をソートします。 

固定閾値の場合`x`、ペア`(a, b)`の場合に許可されます```
b ≤ a - x
```または```
b ≥ a + x
```禁止領域は間隔です```
(a - x + 1 ... a + x - 1)
```ソート後、特定の値に対してすべての値が禁止されます`a[i]`並べ替えられた範囲内で 1 つの連続した間隔を形成します。`b`配列。 

重要な観察は、すべての有効なパートナーが、`a[i]`のプレフィックスのいずれかにあります`b`または接尾辞で`b`。 

正確に仮定してください`k`の要素`b`「小さい側」から割り当てられます（`b ≤ a - x`）。 それから残りは`n-k`要素は「大きい側」から取得する必要があります (`b ≥ a + x`）。 

両方の配列がソートされているため、そのような分割が可能かどうかを確認できます。 

まず最初に`k`最小の前菜、私たちはそれらに合わせます`k`最小のメインディッシュ。 必要です```
a[i] - b[i] ≥ x
```みんなのために`i < k`。 

残りの要素については一致します```
a[i] with b[i-k+k] = b[i]
```接尾辞間で整列された順序で、```
b[i] - a[i] ≥ x
```みんなのために`i ≥ k`。 

あるスプリットポジションに対して両方の条件が当てはまる場合`k`の場合、有効な完全一致が存在します。 

実現可能性テスト全体は、考えられるすべての分割点をスキャンすることになります。

## アルゴリズムのチュートリアル

 ### 修正の実現可能性チェック`x`両方の配列がすでにソートされていると仮定します。 

1. 配列を計算する`pref`。`pref[i]`すべての位置かどうかを示します`0..i`満足する```
a[j] - b[j] ≥ x
```もし`pref[i]`が true の場合、最初の`i+1`最小の前菜は最初のものと合わせることができます`i+1`「小さなサイド」条件を使用した最小のメインディッシュ。 
2. 配列を計算する`suff`。`suff[i]`すべての位置かどうかを示します`i..n-1`満足する```
b[j] - a[j] ≥ x
```もし`suff[i]`true の場合、次で始まるサフィックスは`i`「大きい側」条件を使用して照合できます。 
3. すべての分割位置を試してください`k`から`0`に`n`。 

最初`k`ペアはスモールサイド条件を使用します。 

最後`n-k`ペアはラージサイド条件を使用します。 
4. プレフィックス部分は、次のいずれかの場合に有効です。`k = 0`または`pref[k-1]`それは本当です。 
5. サフィックス部分は、次のいずれかの場合に有効です。`k = n`または`suff[k]`それは本当です。 
6. 両方の部分がいくつかの場合に有効な場合`k`、次にしきい値`x`達成可能です。 
7. 実現可能な最大の二分探索`x`。 

### なぜ効果があるのか

 並べ替え後、前菜の有効なパートナーはすべて、並べ替えられた領域の十分に左か十分に右に位置します。`b`配列。 しきい値を満たす完全な一致では、左側から一致する要素と右側から一致する要素の間に境界が生じます。 

固定境界の場合`k`、左側の部分は、最初のすべての整列されたペアが正確に一致する場合に実行可能です。`k`少なくとも順位が違う`x`方向に`a ≥ b + x`。 同様に、右側の部分は、サフィックス内のすべての整列されたペアが少なくとも異なる場合に正確に実行可能です。`x`方向に`b ≥ a + x`。 

ソートされたシーケンスの再配置引数は、これらの整列チェックが失敗した場合に、同じサイド内の代替の一致によってそれらを修復できないことが保証されます。 したがって、すべての分割位置をチェックすることで、実現可能性を完全に特徴付けることができます。 

実現可能性は単調なので、閾値であれば`x`が達成可能であれば、より小さなしきい値もすべて達成可能です。 二分探索は有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    ans = []

    for _ in range(t):
        n = int(input())
        a = sorted(map(int, input().split()))
        b = sorted(map(int, input().split()))

        def check(x):
            pref = [False] * n
            ok = True

            for i in range(n):
                ok &= (a[i] - b[i] >= x)
                pref[i] = ok

            suff = [False] * (n + 1)
            suff[n] = True

            ok = True
            for i in range(n - 1, -1, -1):
                ok &= (b[i] - a[i] >= x)
                suff[i] = ok

            for k in range(n + 1):
                left_ok = (k == 0) or pref[k - 1]
                right_ok = (k == n) or suff[k]

                if left_ok and right_ok:
                    return True

            return False

        lo, hi = 0, 10**9

        while lo < hi:
            mid = (lo + hi + 1) // 2

            if check(mid):
                lo = mid
            else:
                hi = mid - 1

        ans.append(str(lo))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```解決策は、両方の配列をソートすることから始まります。 実現可能性の評価は要素の相対的な順序に依存するため、並べ替えは不可欠です。 

の`check(x)`すべての食事に少なくとも魅力があるかどうかを検証する機能`x`。`pref[i]`すべての位置合わせされたペアがその位置まであるかどうかを保存します`i`満足する`a[j] - b[j] ≥ x`。 位置が失敗すると、より大きなプレフィックスもすべて失敗するため、実行中のブール値で十分です。`suff[i]`サフィックス内のすべての整列されたペアが次の条件を満たすかどうかを格納します。`b[j] - a[j] ≥ x`。 

スプリットポジションの場合`k`、 最初`k`ペアは左側の条件から取得され、残りは右側の条件から取得されます。 対応する範囲が両方とも有効な場合、完全な一致が存在します。 

二分検索では、標準の上中パターンが使用されます。```
mid = (lo + hi + 1) // 2
```これにより、値が 2 つだけ残った場合の無限ループが回避されます。 

値が次を超えることはないため、すべての算術演算は Python 整数に快適に適合します。`10^9`。
