 ## 解決策
 ## 問題の理解

 正の整数のマルチセットと 3 つの必要なグループ サイズが与えられています。 すべての数値は 3 つのグループのいずれかに正確に属している必要があり、各グループには要求された数の要素が正確に含まれている必要があります。 

数値を分割した後、3 つのグループの合計のみを確認します。 それらの合計が$s_a$、$s_b$、 そして$s_c$、それらは非縮退三角形を形成する必要があります。 すべての値が正であるため、三角形の条件は 1 つの不等式になります。$$\max(s_a,s_b,s_c) < s_a+s_b+s_c-\max(s_a,s_b,s_c)$$言い換えれば、全周の少なくとも半分を占める辺はないということです。 

すべてのテスト ケースにわたる要素の合計数は最大で$200\,000$。 これにより、指数関数、サブセット DP、さらには$O(n^2)$テストケースごとに。 に近いものが必要です$O(n \log n)$これは、ソートと貪欲な構造を強く示唆しています。 

難しいのは、グループのサイズが固定されていることです。 グループがいっぱいになると、要素を任意に移動することはできません。 

簡単な間違いの 1 つは、最大の要素のみが重要であると考えることです。 

考慮する：```
n = 6
sizes = (2,2,2)
values = [3,1,1,1,1,1]
```合計金額は$8$したがって、すべてのグループの合計は厳密に次の値より小さくなければなりません。$4$。 最大の要素はただ$3$、無害に見えます。 

ただし、すべてのグループには 2 つの数値が含まれている必要があります。 を含む唯一の可能なグループは、$3$合計があります$4$、残りのグループには合計があります$2$そして$2$。 結果として得られる辺は、$(4,2,2)$、これは退化しています。 正しい答えは、`NO`。 

もう 1 つの危険なケースは、解は存在するが、最大数を単純にまとめることはできない場合です。```
sizes = (1,2,2)
values = [2,2,2,1,1]
```最大の 2 つの数値を同じグループに入れると合計が得られます$(2,4,2)$、失敗します。 

有効なパーティションは次のとおりです。```
2
2 1
2 1
```合計で$(2,3,3)$。 

アルゴリズムは、現在の合計だけでなく、将来の配置についても推論する必要があります。 

## アプローチ

 ブルートフォース ソリューションでは、あらゆる方法で最初のグループを選択し、次にあらゆる方法で 2 番目のグループを選択し、残りの数字を 3 番目のグループに配置します。 

たとえば、サイズが次の場合、$n_a,n_b,n_c$、パーティションの数は$$\binom{n}{n_a}\binom{n-n_a}{n_b}.$$たとえ$n=40$、これはすでに天文学的な規模です。 と$n$まで$200\,000$、強引な方法は完全に不可能です。 

重要な観察は、三角形の妥当性は最終的なグループの合計にのみ依存するということです。 

させて$$T = \sum x_i.$$三角形の条件は、すべてのグループの合計が厳密に以下であることを要求することと同じです。$T/2$。 

ここで、数値を最大から最小の順に処理することを想像してください。 

グループに現在合計があるとします。$S$そしてまだ必要です$k$より多くの要素。 最も楽観的なシナリオであっても、これらの将来の要素は少なくとも合計に寄与する必要があります。$k$残っている最小の数字。 

これにより、最終的なグループ合計の下限が決まります。 

その下限にさえすでに達している場合$T/2$、このグループは有効になることはありません。 

これにより、問題は貪欲な実現可能性チェックに変換されます。 残りの最大の数値を割り当てながら、その数値を、可能な限り最善の将来が最終合計を下回るグループにのみ配置します。$T/2$。 

グループが 3 つしかないため、すべての要素についてすべての候補グループをチェックすることは、ソート後に継続的な作業となります。

 ## アルゴリズムのチュートリアル

 1. 合計を計算する$T$。 
2. すべての数値を昇順に並べ替えます。 
3. ソートされた配列のプレフィックスの合計を事前計算します。 

プレフィックスの合計を使用すると、最小値の合計をすばやく取得できます。$k$数字。 
4. グループごとに、以下を保存します。 

- 現在の合計、
 - まだ空のスロットがいくつあるか、
 - 割り当てられた実際の番号。 
5. 数値を最大から最小の順に処理します。 
6. 現在の数値を次のようにします。$x$。 
7. 3 つのグループをそれぞれ試してください。 

グループに現在合計があるとします。$S$そしてまだ必要です$r$要素を含む$x$。 

配置後$x$、グループにはまだ必要があります$r-1$より多くの要素。 

可能な最小の追加寄与は、最小の合計です。$r-1$すべての番号のうち、まだ処理されていない番号。 

最大から最小の順に処理するため、将来の数値は正確に小さい方の値になります。 世界最小のものを使用する$r-1$値は常に安全な下限を与えます。 
8. 定義する$$\text{best\_possible} = S + x + \text{sumSmallest}(r-1).$$もし$$2 \cdot \text{best\_possible} < T,$$その場合、最も楽観的な完了の下でも、このグループは有効な三角形の辺のままになる可能性があります。 

1.場所$x$その条件を満たす最初のグループに入れます。 
2. If no group can accept$x$、出力`NO`。 
3. すべての番号が正常に割り当てられた場合は、次のように出力されます。`YES`そして3つのグループ。 

### なぜ効果があるのか

 不変条件は次のとおりです。 

どのグループにも、最終合計を厳密に下回らないようにしながら残りのスロットを完了する方法が少なくとも 1 つあります。$T/2$。 

数字を置くとき$x$、この不変条件を維持する代入のみを許可します。 

数量$$S + x + \text{sumSmallest}(r-1)$$グループが取得後に達成できる最終的な最小金額です。$x$。 その最小値さえすでに少なくとも$T/2$、次に配置します$x$それは成功を不可能にします。 

逆に、不平等が成立する場合、そのグループにはまだ下位にとどまる余地がある。$T/2$。 

数値を最大から最小まで処理することが重要です。 大きな数字を配置するのが最も困難です。 大きな数が不変式に違反せずにどのグループにも収まらない場合は、それより小さな数で状況を修復することはできません。 

アルゴリズムが終了すると、すべてのグループは依然として不変条件を満たし、残りのスロットはゼロになります。 下限が正確な最終合計となるため、すべてのグループ合計は厳密に以下になります。$T/2$。 まさに三角関係ですね。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n, na, nb, nc = map(int, input().split())
        a = list(map(int, input().split()))

        total = sum(a)

        a.sort()

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        groups = [[], [], []]
        sums = [0, 0, 0]
        rem = [na, nb, nc]

        ok = True

        for i in range(n - 1, -1, -1):
            x = a[i]

            placed = False

            for g in range(3):
                if rem[g] == 0:
                    continue

                need_after = rem[g] - 1

                min_final_sum = sums[g] + x + pref[need_after]

                if 2 * min_final_sum < total:
                    groups[g].append(x)
                    sums[g] += x
                    rem[g] -= 1
                    placed = True
                    break

            if not placed:
                ok = False
                break

        if not ok:
            out.append("NO")
            continue

        out.append("YES")
        out.append(" ".join(map(str, groups[0])))
        out.append(" ".join(map(str, groups[1])))
        out.append(" ".join(map(str, groups[2])))

    sys.stdout.write("\n".join(out))

solve()
```最初のステップは値を並べ替えることです。 将来の実現可能性のチェックはすべて、どの数値が現在よりもまだ小さいかを知ることにかかっています。 

プレフィックス合計配列は、貪欲なチェックを高速化する実装の詳細です。 最小値を繰り返し合計するのではなく、$k$値を指定すると、その量を次のように取得します。$O(1)$。 

表現```
min_final_sum = sums[g] + x + pref[need_after]
```アルゴリズムの中核です。 これは、このグループが次のように配置した場合に得られる最終的な合計の最小値を表します。$x$今すぐそこに入れてください。 

厳密な不平等```
2 * min_final_sum < total
```厳格さを保たなければなりません。 それを次のものに置き換えると、`<=`これにより、1 つの辺が他の 2 つの辺の合計に等しい縮退三角形が許可されます。 

もう 1 つの微妙な点は、実際の値をグループに直接保存していることです。 このステートメントでは、インデックスではなく数値が求められます。

 ## 特殊なケース

 次のことを考慮してください。```
6 2 2 2
1 1 1 1 1 3
```合計金額は$8$。 を含むグループ$3$すべてのグループ サイズが異なるため、もう 1 つの要素も含める必要があります。$2$。 可能な最小の最終合計は次のとおりです。$4$。 

アルゴリズムは以下を計算します。```
min_final_sum = 3 + 1 = 4
```そしてチェックします:```
2 * 4 < 8
```それは失敗します。 

どのグループも受け入れることはできません$3$、したがって、答えは正しいです`NO`。 

次に、次のことを考えてみましょう。```
5 1 2 2
2 2 2 1 1
```合計金額は$8$。 

最初$2$サイズに入ることができます-$1$グループの最終合計が残るため$2$、安全に以下に$4$。 

残りの２つ$2$値を同じグループにマージすることはできません。マージすると、将来の合計が強制されるためです。$4$。 実現可能性チェックではその配置が拒否され、それらが別のグループに分配されます。 

最終的な合計は次のようになります。```
2, 3, 3
```三角不等式を満たします。 

これはまさに、現在の合計のみに基づいた単純な貪欲型は失敗し、実現可能性に基づいた貪欲型は成功するようなケースです。 

このソリューションは、将来の寄与を最小限に抑えて先を見据えることに依存しているため、これらの境界ケースを正しく処理します。
