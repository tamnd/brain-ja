 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、`n`ノードと`n-1`エッジ。エッジには重みのラベルが付けられていません。 代わりに、1 から 2 までの連続するノード間のパスに沿った重みの合計が提供されます。`n`。 私たちのタスクは、ノードからのパスに沿った重みの合計が次のように各エッジに正の整数の重みを割り当てることです。`i`ノードへ`i+1`指定された距離と一致します`d_i`みんなのために`i`。 正の整数を代入してもこれらすべての距離を満たすことができない場合は、次のように報告する必要があります。`-1`。 

各エッジの重みは正の値でなければなりません。 この制約は、複数のパスに現れないエッジにゼロを割り当てるような単純な解決策を防ぐため、非常に重要です。 距離は次のように大きくすることができます`10^{12}`そして`n`まで可能です`10^5`。 これにより、可能なすべてのエッジの重みまたはすべてのパスを明示的に列挙しようとするソリューションは即座に除外されます。エッジまたはノード上の 1 つのネストされたループでも、次のような問題が発生するためです。`10^{10}`操作。 

単純な実装では、連続するノード間のすべてのパスを反復処理して、既知の重みを減算することによって、各エッジを個別に解決しようとする可能性があります。 複数のパスがエッジを共有している場合、一貫した割り当てを決定できないため、パスが重複するツリーではこれは失敗します。 たとえば、ノード 1 がノード 2、3、4 に接続されているスター ツリーとその距離を考えてみましょう。`d_1=5`、`d_2=5`、`d_3=5`。 素朴なアプローチでは、1 から葉までの各エッジに 5 を割り当てる可能性がありますが、パスが重なっている場合は、正の整数の重みと矛盾する異なる分割が必要になる場合があります。 

距離がそのパスに沿ったエッジの数よりも小さい場合、別の微妙なエッジ ケースが発生します。 たとえば、パスに 3 つのエッジが含まれているが距離が 2 の場合、正の整数を割り当てる方法はないため、アルゴリズムは不可能を検出する必要があります。 

## アプローチ

 ブルートフォース手法では、各エッジに変数を割り当て、次のシステムを解決しようとします。`n-1`距離によって与えられる一次方程式。 各方程式は、ノードからのパス上のエッジに対応する変数を合計します。`i`ノードへ`i+1`。 これは理論的には機能しますが、これを直接解決するには、潜在的にスパース行列を操作する必要があります。`10^5`変数と制約を使用すると、時間がかかりすぎてメモリを大量に消費します。 

重要な洞察は、パスに沿った差分を効率的に計算できるツリー構造を備えた、整数に関する線形方程式系として問題を扱うことができるということです。 ノード 1 でツリーをルート化することで、距離ラベルを割り当てることができます`L[v]`各ノードのルートからの合計距離を表します。 次に、ノードからのパスについては、`i`に`i+1`、エッジの重みの合計は次のようになります。`L[i+1] - L[i]`これらのラベルに関しては。 連続するノードとツリー構造の間の距離を使用してこれらのラベルを伝播し、問題を接続されたノード間の一貫した差の割り当てに変換できます。 

これを 2 色分けまたは差分割り当て問題として形式化できます。ラベル 0 のルート ノードを選択し、ツリーを横断し、エッジに沿った絶対的な差分が距離から推測される制約と一致するように各子にラベルを割り当てます。 いずれかの時点で、割り当てによってエッジの重みが負またはゼロになる場合、または既存のラベルと競合する場合は、不可能であると宣言します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n^2) | 遅すぎる |
 | ルート化されたラベルの伝播 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノード 1 でツリーをルートします。 距離ラベルを初期化します。`L[1] = 0`根のために。 
2. 各エッジについて`(u,v)`、DFS トラバーサルをサポートするためにネイバーのリストを維持します。 
3. BFS または DFS を使用してツリーを横断し、距離ラベルを割り当てます`L[v]`連続するノードのペアごとに`(i, i+1)`入力の違い`|L[i+1] - L[i]| = d_i`。 一貫性を維持するには、パス長のパリティに応じて差の符号を選択​​する必要がある場合があります。 
4. 各ノードを訪問するたびに、ノードをその親に接続するエッジの暫定的な重みを次のように計算します。`abs(L[v] - L[parent[v]])`。 この重みがゼロであるか、以前に割り当てられた値と競合する場合は、次のコマンドで終了します。`-1`。 
5. すべてのノードにアクセスした後、エンドポイントのラベルから各エッジの重みを抽出します。 ツリーは接続されており、ラベルはすべての距離を考慮しているため、有効な割り当てが得られます。 
6. エッジ重みを入力順に出力します。 

機能する理由: アルゴリズムは、次の不変条件を維持します。`L[v] - L[parent[v]]`正のエッジの重みに対応します。 ラベルをルートから伝播し、各ステップで一貫性をチェックすることで、連続するノード間のすべての距離が満たされていることを確認します。 ツリー構造により、各エッジが少なくとも 1 つのパスに表示されることが保証されるため、未割り当てのエッジは存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

def solve():
    n = int(input())
    edges = []
    adj = defaultdict(list)
    for _ in range(n-1):
        u,v = map(int,input().split())
        edges.append((u,v))
        adj[u].append(v)
        adj[v].append(u)
    d = list(map(int,input().split()))
    
    parent = [0]*(n+1)
    label = [None]*(n+1)
    label[1] = 0
    
    # BFS to assign labels
    q = deque([1])
    while q:
        u = q.popleft()
        for v in adj[u]:
            if label[v] is None:
                parent[v] = u
                q.append(v)
    
    # propagate distances for consecutive nodes
    for i in range(1,n):
        diff = d[i-1]
        # ensure direction
        if label[i+1] is None:
            label[i+1] = label[i] + diff
        else:
            if abs(label[i+1] - label[i]) != diff:
                print(-1)
                return
    
    # compute edge weights
    res = []
    for u,v in edges:
        w = abs(label[u] - label[v])
        if w <= 0:
            print(-1)
            return
        res.append(w)
    print('\n'.join(map(str,res)))

solve()
```最初のセクションはツリーを読み取り、トラバースを容易にするために隣接リストを保存します。 また、各ノードの親も追跡します。 BFS は、各ノードが 1 回だけアクセスされることを保証し、`O(n)`操作。 距離の伝播により、パスに沿った合計が入力と一致することが保証されます。`d_i`。 ラベルを整数として割り当てると、小数部分の重みが回避され、正の値が維持されます。 最後にエッジの重みを抽出するのは、ラベルの絶対差を使用して直接的に行われます。
