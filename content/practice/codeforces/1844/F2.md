 ## 解決策
 ## 問題の理解

 正の整数の配列と整数が与えられます。$c$、マイナスになる可能性があります。 タスクは、絶対差の合計が最小になる順列に配列を並べ替えることです。$|b_{i+1} - b_i - c|$すべての連続する要素にわたって、この最小値を達成するすべての順列の中で、辞書編集的に最小のものを選択する必要があります。 

実際には、連続する要素間の差異を一致するように調整します。$c$できるだけ近くに。 もし$c = 0$、これは、連続する数値間の差を最小限に抑え、非減少順序を優先することと同じです。 もし$c$が大きいため、連続する差分がほぼ一致するようにしたい$c$、小さい数値と大きい数値を交互に使用する必要がある場合があります。 

制約は次のことを教えてくれます$n$到達できる$2 \cdot 10^5$と合計$n$すべてのテストケースにわたって、$2 \cdot 10^5$。 これにより、順列の総当り列挙が除外されます。$n!$～には完全に不可能です$n > 10$。 必要なのは$O(n \log n)$または線形解。 エッジ ケースには、長さ 1 の配列、すべて等しい値を持つ配列、および非常に負または正の値が含まれます。$c$、自然な増加/減少順序が逆転する可能性があります。 

たとえば、不注意な実装では、配列を単純に並べ替えて、常に最小の合計が生成されると想定する可能性があります。 それが失敗するのは、$c$は負であり、最適な置換には最初に大きな要素が必要です。 たとえば、$a = [1, 3, 5]$そして$c = 2$、昇順$[1, 3, 5]$コストはゼロですが、次のような順列になります$[5, 1, 3]$より高いコストが発生します。 辞書編集的な順序付けは、最小和を達成する順列間でのみ考慮する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてが生成されます。$n!$の順列$a$そして合計を計算します$\sum |b_{i+1}-b_i-c|$それぞれに。 これにより、ミニマイザー間の最小和と辞書編集上最小の順列が正しく識別されます。 しかし、階乗増加ではそれが不可能になります。$n > 10$したがって、問題の制約を考慮すると実行不可能です。 

重要な洞察は、絶対的な違いを分析することで得られます。 任意の 2 つの数字について$x$そして$y$、$|y-x-c|$最小化されるのは$y-x$にできるだけ近いです$c$。 配列をソートすると、正の場合$c$私たちは数値を昇順に選択する傾向がありますが、負の場合は$c$、多くの場合、降順が必要になります。 しかしそれ以来$c$は任意の符号と大きさを持つことができるため、単純な単調順序が常に最適であるとは限りません。 

代わりに、ソートされた配列を 2 つの連続したセグメントに分割し、1 つは「ピボット」の左側に、もう 1 つは右側に配置し、それらをピボットの周囲に織り込むことによって最小和が達成できることを認識することで、最適なシーケンスを見つけることができます。 配列をソートすると、辞書編集上の順序を制御できます。 並べ替えたら、次の値に基づいて分割する場所を決定します。$c$最初の絶対差を小さくする要素を貪欲に配置します。 これにより、問題はソートされた配列に対する単純な線形スキャンに帰着します。

 ## アルゴリズムのチュートリアル

 1. 配列をソートする$a$昇順で。 これにより、位置が決定されると、辞書編集的に最小の順列を常に生成できることが保証されます。 
2. 配列の末尾にある 2 つのポインターを初期化します。`left`0で、そして`right`n-1で。 これらは、両端から要素を選択して、相対的な差異のバランスをとることによって順列を構築するのに役立ちます。$c$。 
3. 最初の要素から順列の構築を開始します。 最小化する要素を選択してください$|next - prev - c|$。 最初の要素については、比較する前の要素がないため、並べ替えられた配列内の最小の要素を選択します。 
4. 現在の端から候補を選択して、要素をシーケンスに繰り返し追加します (`a[left]`または`a[right]`) との絶対差のコストが小さい方を生成します。`c`。 コストが等しい場合は、辞書編集上の最小性を維持するために小さい方の数値を選択します。 
5. すべての要素が配置されるまで続行します。 このプロセスにより、すべての連続するペアの和への寄与が最小限に抑えられ、この和を達成するすべてのシーケンスの中で順列全体が辞書編集的に最小になることが保証されます。 

機能する理由: このアルゴリズムは、各ステップで、選択された要素の順序を変更することによって、部分的に構築された順列をより低コストの順列に拡張できないという不変条件を保持します。 ソートにより辞書編集上の最小性が確保され、貪欲な選択により合計の増分コストが最小限に抑えられます。 端から処理することで、目標の差に近づくために次にどの数字を配置するかを制御します$c$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()
        
        # For single element, just output it
        if n == 1:
            print(a[0])
            continue
        
        # Two pointers approach
        b = [a[0]]  # start with the smallest for lexicographical minimal
        left, right = 1, n-1
        
        while left <= right:
            prev = b[-1]
            cost_left = abs(a[left] - prev - c)
            cost_right = abs(a[right] - prev - c)
            if cost_left < cost_right:
                b.append(a[left])
                left += 1
            elif cost_right < cost_left:
                b.append(a[right])
                right -= 1
            else:
                # Equal cost, pick smaller for lex minimal
                b.append(a[left])
                left += 1
        print(" ".join(map(str, b)))

if __name__ == "__main__":
    solve()
```コードは最初に、要素が 1 つしかないような簡単なケースを処理します。 ソートにより、辞書編集上の優先順位が保証されます。 2 ポインター戦略により、各ステップで次の数値が合計に最小限に寄与することが保証されます。 両方の候補が同等に優れている場合は、辞書編集上の順序を維持して、小さい方の番号が選択されます。
