[CF 203A - 2 つの問題](https://codeforces.com/problemset/problem/203/A)

 **評価:** 1200
 **タグ:** ブルート フォース、実装
 **解決時間:** 1 分 6 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 0 分から t - 1 分まで続くコンテスト中に利用できる 2 つの独立したタスクがあります。各タスクのスコアは時間とともに直線的に減少します。 最初のタスクを i 分に解決すると、最初の a から減算された da ポイントを乗算したマイナス i を受け取ります。 2 番目のタスクは、初期値 b と 1 分あたりの db の減少を使用して同様に動作します。 

出場者はタスクをスキップすることも、タスクを 1 回だけ解決することもでき、各解決はコンテスト ウィンドウ内の整数分で行われなければなりません。 合計スコアは、選択した時間に解決されたすべてのタスクの値の合計です。 問題は、合計点をちょうど x 個取得できるかどうかです。 

重要な点は、時間は各タスクの値に独立して影響するだけであり、タスクは 2 つだけであるため、解決策は各タスクの時間を選択するか、タスクを解決しないことを選択するかによって完全に決定されるということです。 

制約は十分に小さいため、すべての時間の選択に対する二次推論も実行可能です。 最大 t は 300 であるため、すべての分のペアをチェックすると最大 90,000 の組み合わせとなり、これは十分に制限内です。 多少効率の悪いアプローチでも簡単に通過してしまいます。 

微妙な点は、後でタスクを解決すると、その貢献度は常に減少しますが、ステートメントの保証により、貢献度がマイナスになることは決してないことです。 これにより、マイナスのスコアを伴う、または無効な提出を考慮する必要があるという特殊なケースが回避されます。 

エッジ ケースは、x が 0 の場合、1 つのタスクのみが必要な場合、または両方のタスクが必要な場合に発生します。 単純な間違いは、常に両方のタスクを解決する必要があると想定することであり、x が a に等しい、または x が b に等しいなどのケースを誤って拒否してしまいます。 たとえば、x が a に等しく、b が大きいが不要な場合、時間 0 の最初のタスクのみを解決すれば、正解は依然として「はい」になる可能性があります。 

もう 1 つのエッジ ケースは、両方のタスクを異なる時点で解決する必要がある場合です。 不用意なアプローチでは、スコアを最大化するには両方を時間 0 で解決する必要があると想定する可能性がありますが、問題は最大化ではなく、正確な値の一致にあり、その寄与を減らすために 1 つのタスクを遅らせる必要がある場合があります。 

## アプローチ

 効率の問題を無視する場合、最も直接的なアイデアは、考えられるすべての決定を試みることです。つまり、両方のタスクをスキップする、有効な分で最初のタスクのみを実行する、有効な分で 2 番目のタスクのみを実行する、または分 i と j を選択して両方のタスクを実行するなどです。 各タスクは個別にスケジュールできるため、これは時間のすべてのペアにわたる完全な列挙になります。 

このブルート フォース ビューは、[0, t-1] のすべての i と [0, t-1] のすべての j をチェックし、両方のタスクが実行されたときに結果として得られるスコアの合計を計算します。 また、1 つのタスクを「選択されなかった」ものとして処理してスキップするケースも暗黙的に含めます。 すべての有効な戦略は 1 つのペア (i, j) または欠落している選択肢に正確に対応するため、正確性は簡単です。 

ペアの総数は最大 300 × 300、つまり 90,000 評価です。 各評価は一定時間であるため、総当たり攻撃はすでに時間制限内に問題なく収まります。 ただし、2 つのタスクを分離することで、構造をさらに簡素化できます。 

可能な時間 i ごとに、最初のタスクのスコアを計算できます。 可能な時間 j ごとに、2 番目のタスクのスコアを計算します。 次に問題は、これら 2 つのセットから合計が x になる値のペアが存在するかどうかを確認することになります。 これは小さな配列に対する古典的な 2 和であり、線形時間でハッシュ セットを使用して解決できます。 

2 番目のタスクのすべての可能な値を事前計算してセットにし、最初のタスクのすべての可能な値を反復して、x からその値を引いた値がセット内に存在するかどうかを確認できます。 これにより、同じ最悪の場合のパフォーマンスを維持しながら、概念的な複雑さが軽減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | (i, j) 全体に対するブルート フォース | O(t²) | お(1) | 承認済み |
 | 事前計算 + ハッシュ セット | O(t) | O(t) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 分 i を 0 から t マイナス 1 まで繰り返し、a マイナス i 倍 da を計算することで、最初の問題の可能なすべてのスコアを構築します。 これにより、最初のタスクを解決する有効なすべての方法が捕捉されます。 
2. 分 j を 0 から t マイナス 1 まで繰り返し、b マイナス j 倍 db を計算することにより、同様に 2 番目の問題のすべての可能なスコアを構築します。 これにより、2 番目のタスクからの達成可能な貢献の完全なセットが得られます。 
3. すべての 2 番目のタスクのスコアをハッシュ セットに挿入して、メンバーシップのクエリを一定時間内に実行できるようにします。 これにより、後で高速ペアリングが可能になります。 
4. すべての最初のタスクのスコアを繰り返します。 各値 s1 について、必要な補数値 x から s1 を引いた値を計算します。 
5. この補数値が 2 番目のタスク セットに存在するかどうかを確認します。 そうであれば、正確に x を生成する 2 つの送信時間の有効な組み合わせが見つかったので、すぐに停止できます。 
6. 最初のタスクの値をすべて使い尽くした後でどの組み合わせも機能しない場合は、x を形成できないと結論付けます。 

それが機能する理由は、各タスクが独立して、最大 1 回だけ貢献するという事実に依存します。 有効なコンテストの結果はすべて、最初のセットから 1 つの値を選択し、2 番目のセットから 1 つの値を選択する (または事実上要素を選択しないことでスキップする) ことに対応します。 このような値はすべて列挙されているため、すべての合計をチェックすることで、漏れや重複がなく、考えられるすべての戦略がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, t, a, b, da, db = map(int, input().split())

    A = []
    for i in range(t):
        A.append(a - i * da)

    Bset = set()
    for j in range(t):
        Bset.add(b - j * db)

    for v in A:
        if x - v in Bset:
            print("YES")
            return

    print("NO")

if __name__ == "__main__":
    solve()
```最初のループでは、有効な分ごとに最初の問題を解くために考えられるすべてのスコアを構築します。 2 番目のループは、2 番目の問題のすべての可能なスコアをハッシュ セットに保存し、補数の定数時間検索を可能にします。 最後のループでは、最初のタスクのすべての値を試し、残りの必要なスコアが 2 番目のタスクのタイミングまでに達成できるかどうかを確認します。 

微妙な点は、問題のスキップが暗黙的に処理されることです。問題ではマイナスでないスコアが保証されているため、有効な選択は常に何らかの分を選択することに対応し、貢献度がゼロの場合は明示的なオプションとして必要ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t) | サイズ t の 2 つの配列を生成し、定数時間のハッシュ ルックアップで単一パスを実行します。 
| スペース | O(t) | 可能なすべての 2 番目のタスクの値をセットに保存します |

 t が 300 までという制約により、この解は実際には非常に小さくなります。 最悪の場合の定数要因も無視できる程度であり、アルゴリズムは制限内で快適に実行されます。

## 特殊なケース

 x が 0 に等しい場合、成功する唯一の方法は、合計が 0 になるような正の値を避けることです。 生成される値はすべて非負であるため、これはゼロを生成する有効な組み合わせが存在する場合にのみ機能します。 アルゴリズムはすべてのペアをチェックし、両方のセットにゼロが含まれている場合は合計が一致するため、このアルゴリズムは自然にこれを処理します。 

必要なタスクが 1 つだけの場合、正しい解決策は、一方のセットの値をもう一方の暗黙的なゼロ寄与と組み合わせることで得られます。 この実装では、スキップは 2 番目の選択を必要としないことによって表されます。 ただし、セットには時間ベースの値が含まれているため、他のタスクが x を正しく補完する値を提供する場合、有効な単一タスクの解は直接一致として表示されます。 

両方のタスクの初期値が大きくても減少が大きい場合、後で寄与が非常に小さいかゼロになる可能性があります。 毎分独立してテストされ、有効な遅延ソリューションが見逃されないことが保証されるため、列挙にはこれらのケースが正しく含まれます。
