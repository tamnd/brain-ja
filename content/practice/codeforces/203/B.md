 ## 解決策
 ## 問題の理解

 私たちは、`n × n`完全に白から始まるグリッド。 セルは 1 つずつ黒く塗られ、移動するたびに異なるセルが描画されます。 各手ごとに、ボードにすでに完全に黒のカードが含まれているかどうかを知りたいと考えています。`3 × 3`四角。 

タスクは、そのような正方形が最初に出現する最も早い移動インデックスを出力することです。 いいえの場合`3 × 3`ブロックが真っ黒になると印刷します`-1`。 

グリッドのサイズは最大です`1000 × 1000`これは、ボードに含まれるセルが最大 100 万個であることを意味します。 塗装作業の回数は最大で`10^5`。 これにより、すべての動きの後にボード全体を繰り返しスキャンするようなアプローチは即座に排除されます。 考えられるすべてのことを再確認する`3 × 3`毎回の正方形の所要時間はおおよそ次のとおりです。$$10^5 \times 10^6 = 10^{11}$$限界をはるかに超えた最悪の場合の操作。 

小さい固定正方形サイズがここでの重要な詳細です。 任意の長方形や大きなパターンを探しているわけではありません。 すべての有効な構成は正確に`3 × 3`したがって、新しくペイントされた各セルは、近くのごく少数の候補正方形にのみ影響を与えることができます。 

見落としやすいエッジケースがいくつかあります。 

ボードが小さすぎて、`3 × 3`四角。 

入力：```

```正しい出力:```

```不注意な実装では、依然として隣接する位置をチェックしようとして、無効なインデックスに誤ってアクセスしようとする可能性があります。 

もう 1 つの微妙なケースは、最終的にペイントされたセルが完成した正方形の左上隅ではない場合に発生します。

## アプローチ

 最も直接的な解決策はブルートフォースです。 移動するたびに、可能な限りすべてのスキャンを行います`3 × 3`サブグリッドを作成し、9 つのセルすべてが黒かどうかを確認します。 

がある`(n - 2)^2`候補四角形を選択し、各チェックで 9 個のセルを検査します。 複雑さは次のようになります。$$O(m \cdot n^2)$$のために`n = 1000`そして`m = 10^5`、これはあまりにも大きくなりすぎます。 

重要な点は、1 つのセルをペイントすると、そのセルを含む正方形のみが変更されるということです。 ターゲットとなる正方形のサイズは固定されているため、`3 × 3`、単一のセルは最大 9 つの異なるセルに属します。`3 × 3`正方形。 

たとえば、セルをペイントすると、`(x, y)`、次に影響を受けるすべての左上隅`3 × 3`正方形は次の場所になければなりません:$$(x-2 \dots x,\ y-2 \dots y)$$可能性は9つしかありません。 ボード上の 1 つおきのマスは変更されないため、再度チェックする必要はありません。 

これにより、問題は、グリッド全体を繰り返しスキャンすることから、各移動後に一定数のローカル構成のみをチェックすることに変わります。 

結果として生じる複雑さは、移動数に比例します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m · n²) | O(n²) | 遅すぎる |
 | 最適 | O(m) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.`n × n`ブール値グリッドは次のように初期化されます`False`。 

各セルは、すでに黒く塗られているかどうかを格納します。 
2. 入力された順序で 1 つずつ手を処理します。 

有効な状態を作り出す最初の動き`3 × 3`正方形が答えなので、手を順番に評価する必要があります。 
3. 現在のセルをマークします`(x, y)`黒として。 
4. 考えられるすべての左上隅を列挙します。`3 × 3`を含む可能性のある正方形`(x, y)`。 

これらのコーナーは次のとおりです。```
(x-2, y-2) ... (x, y)
```候補者は最大で 9 人です。 
5. 各候補の左上隅`(r, c)`、まず正方形がボード内に留まっていることを確認します。 

必要なものは次のとおりです。```
0 ≤ r ≤ n-3
0 ≤ c ≤ n-3
```6. その中の9つのセルをすべてチェックします`3 × 3`四角。 

すべてのセルが黒の場合は、現在の手の番号をすぐに出力して終了します。 
7. 有効なマスが見つからずにすべての動きが終了した場合は、次のように出力します。`-1`。 

### なぜ効果があるのか

 あ`3 × 3`正方形は、そのセルの 1 つがペイントされている場合にのみステータスを変更できます。 塗装前`(x, y)`、影響を受けないすべての正方形には以前とまったく同じセルが含まれるため、その有効性は変更されません。 

つまり、移動後、チェックする価値のある唯一の正方形は、新しくペイントされたセルを含む正方形です。 このようなすべての正方形が明示的に検査されるため、アルゴリズムは最初に完成した正方形を見逃すことはできません。`3 × 3`ブロック。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())

    grid = [[False] * n for _ in range(n)]

    for move in range(1, m + 1):
        x, y = map(int, input().split())
        x -= 1
        y -= 1

        grid[x][y] = True

        for r in range(x - 2, x + 1):
            for c in range(y - 2, y + 1):

                if r < 0 or c < 0 or r + 2 >= n or c + 2 >= n:
                    continue

                ok = True

                for i in range(r, r + 3):
                    for j in range(c, c + 3):
                        if not grid[i][j]:
                            ok = False
                            break

                    if not ok:
                        break

                if ok:
                    print(move)
                    return

    print(-1)

if __name__ == "__main__":
    main()
```このソリューションでは、ボードをブール行列として保存します。 ブール値を使用すると、各検索が配列への直接アクセスになるため、実装がシンプルかつ効率的に保たれます。 

座標は、入力を読み取った直後に 0 から始まるインデックスに変換されます。 これにより、繰り返しを避けることができます`-1`後で調整できるようになり、境界条件の推論が容易になります。 

ループ:```
for r in range(x - 2, x + 1):
    for c in range(y - 2, y + 1):
```考えられるすべてを列挙する`3 × 3`を含む正方形`(x, y)`。 よくある間違いは、チェックだけを行うことです`(x, y)`左上隅にあるため、多くの有効な構成が欠落しています。 

境界テスト:```
if r < 0 or c < 0 or r + 2 >= n or c + 2 >= n:
```ボードの端付近での無効なインデックス作成を防ぎます。 

ネストされたループは、`3 × 3`白いセルが 1 つ見つかるとすぐに領域が停止します。 これにより、定数係数が小さく保たれます。 

有効な四角形が現れた瞬間、プログラムは移動インデックスを出力し、ただちに終了します。 手は時系列で処理されるため、最初に検出されたマスが最も早いマスであることが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m) | 各移動は最大 9 つの候補正方形をチェックします。各候補正方形には 9 つのセルが含まれます。
