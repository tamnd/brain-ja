 ## 問題の理解

 私たちには、それぞれが負ではない難易度の値と総精神的予算を持つ問題のコレクションが与えられます。$S$。 合計の難易度が次を超えない問題のサブセットを選択する場合があります。$S$、これらは「正常に解決された」とみなされます。 

この最初の選択が完了すると、「洞察」と呼ばれる 1 つの追加アクションが許可されます。 この洞察により、もう 1 つ問題を無料で選択できますが、これはすでに解決済みの問題の少なくとも半分が、選択した問題の難易度以上の難易度を持っている場合に限ります。 この追加の問題が解決されると、プロセスは終了します。 

目標は、最初に解決されたサブセットと 1 つの考えられるボーナス問題の両方を数えて、解決された問題の総数を最大化することです。 

入力サイズは最大$3 \cdot 10^5$すべてのサブセットを試行したり、コストのかかる状態探索を実行したりするソリューションは除外されます。 平$O(n^2)$ソートと二次スキャンは時間制限を超えるため、メソッドはすでに大きすぎます。 これは、ソートと線形または線形に近い走査に基づく戦略を即座に示唆し、各候補構造は償却定数または対数時間で評価されます。 

この問題の微妙な点は、ボーナス条件が、難易度の合計だけではなく、選択したサブセット内の難易度の_相対的な順序_に依存することです。 もう 1 つのデリケートなケースは、最初のサブセットが空の場合です。つまり、条件が空虚に true になり、単一の問題がボーナス手として受け取られる可能性があることを意味します。 

多くの場合失敗する単純なアプローチは、以下の可能な限り最小のサブセットを貪欲に取得することです。$S$そして可能な限り最大のボーナスを追加するようにしてください。 「少なくとも半分」という制約は、そのサイズや合計だけではなく、サブセット内の値の分布に依存するため、これは破綻します。 

たとえば、選択したサブセットが非常に小さな値に偏っている場合、よりバランスの取れたサブセットを可能にする他の構成で予算が未使用のままであっても、適度に大きなボーナス候補が失敗する可能性があります。

### なぜ効果があるのか

 ソート後、最適な選択が行われます。$k$コストを最小化する要素はまさに長さの接頭辞です$k$。 逸脱すると、選択した要素がより大きな要素に置き換えられ、実現可能性が向上することなくコストが増加します。 ボーナス条件は、ソートされた構造で保存されるしきい値に対する相対的なカウントのみに依存します。 したがって、問題をプレフィックス評価に落とし込んでも最適な解決策が排除されるわけではなく、関連するすべてのしきい値をチェックすることで、可能な限り最適な拡張子が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, S = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + a[i]

    def feasible(k):
        return prefix[k] <= S

    # best answer without bonus
    ans = 0
    for k in range(n + 1):
        if feasible(k):
            ans = max(ans, k)
        else:
            break

    # try each value as bonus threshold
    # we precompute positions of each value
    from collections import defaultdict
    pos = defaultdict(list)
    for i, v in enumerate(a):
        pos[v].append(i)

    # iterate over all possible bonus values
    for i in range(n):
        x = a[i]

        # find how many elements in prefix can support x
        # we want subset of size k such that at least ceil(k/2) elements >= x
        # among prefix k, count of >= x is k - lower_bound(x)
        lo, hi = 0, n
        best_k = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if not feasible(mid):
                hi = mid - 1
                continue

            # count of elements >= x in prefix mid
            import bisect
            idx = bisect.bisect_left(a, x)
            cnt_ge = mid - min(mid, idx)

            if cnt_ge * 2 >= mid:
                best_k = mid
                lo = mid + 1
            else:
                hi = mid - 1

        if best_k > 0:
            ans = max(ans, best_k + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```コードの最初の部分では、配列を並べ替えてプレフィックスの合計を構築するため、予算内での実現可能性を一定時間内にテストできます。 変数`ans`ボーナスムーブを使用せずに最適な解決策を追跡します。 

2 番目の部分では、考えられるボーナスしきい値を繰り返し、プレフィックス サイズのバイナリ検索を実行します。$k$。 実現可能性チェックでは、次の 2 つの制約を組み合わせます。$S$そして、選択されたプレフィックス要素の少なくとも半分が少なくとも候補ボーナス値であるという要件。 条件を満たす要素の数は、ソートされた配列の二分探索を使用して計算されます。 

微妙な点は、コストに使用されるプレフィックスとボーナス条件に使用される分布が同じソートされた順序を参照するため、両方のチェックに単一の配列を再利用できることです。
