 ## 問題の理解

 カードのコレクションが与えられ、各カードには長さの配列が含まれています`n`。 がある`n`選手たち、そしてまさに`m`カードが利用可能です。 プレーヤーはプレーヤー 1 からプレーヤー n まで固定の順序で交代し、各プレーヤーはまだ利用可能なカードから 1 枚だけを選びます。 

すべてのカードが取られると、各プレイヤーは自分が選んだカードの特定の座標のみを確認します。`j`位置に書き込まれた値をスコアします`j`彼らが選んだカードの。 この中で最も高いスコアを獲得したプレイヤーが勝者となります`n`最終スコア。 

各プレイヤーは結果に対して辞書的な好みを持っています。まず最初に唯一の勝者になることを望み、複数の選択肢により勝者になれなかった場合にのみ、自分のスコアを最大化することを気にします。 

タスクは、すべてのプレイヤーがこの優先順位構造の下で最適に行動した場合に、どのプレイヤーが最終的に勝つかを決定することです。 

制約により許可されるのは、`n, m ≤ 2000`、したがって、3 次以上の依存性は`m`または`n`遅すぎます。 アン`O(m^2 n)`このアプローチは境界線にありますが、厳密な定数であれば許容できる可能性がありますが、すべての戦略を列挙するようなことは不可能です。 

複数のカードが異なるプレイヤーにとって同様に優れている場合、微妙な問題が発生します。 各プレイヤーが独立して自分に最適なカードを選択するという単純な考えがありますが、これは、前のプレイヤーが後のプレイヤーの選択肢を減らし、最適な反応を変えるという事実を無視しています。 

もう 1 つの失敗モードは、勝者が単に最大スコアを獲得したプレイヤーであると仮定することです。`max_i a[i][j]`が最大です。 これは戦略的ブロックを無視しています。プレイヤーは、他のプレイヤーが支配的な値にアクセスするのを防ぐために、わずかに最適ではないカードを選ぶかもしれません。 

3 番目のエッジケースは、プレイヤーが自分自身に最適なカードが、他のプレイヤーが勝つためにも重要である場合に発生します。 構造例:```
n = 2, m = 2
card 1: [10, 1]
card 2: [9, 100]
```プレイヤー 1 はスコア 10 のカード 1 を優先しますが、カード 1 を獲得した場合、プレイヤー 2 が 100 を取得して勝ちます。 最適なプレイでは、プレイヤー 1 は局所的な最大値ではなく、全体的な結果を考慮する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、プレーヤーに個別のカードを割り当てるあらゆる方法を試し、結果のスコアを評価し、逸脱によってプレーヤーが勝者になる可能性が高まるかどうかをシミュレートします。 これにより、基本的にカード割り当てのすべての順列をチェックすることになります。`O(m!)`、たとえ非常に小さいものであっても実現可能をはるかに超えています`m`。 

より構造化されたブルートフォースにより、問題はサイズのすべてのサブセットの評価に軽減されます。`n`およびそれらのカードのプレイヤーへの割り当てのすべての順列。 それでさえも与えます`O( C(m, n) · n! )`、まだ完全に難治です。 

重要な構造的観察は、各カードが異なるプレイヤーのスコアに独立して寄与しており、プレイヤー間の唯一の相互作用はカードの争奪によるものであるということです。 カードが割り当てられると、それは 1 つの位置の 1 つのスコアにのみ影響します。 

これは視点を逆転させることを示唆しています。プレイヤーがカードを選択すると考えるのではなく、カードは、競争上の意味で最も価値のあるプレイヤーによって「要求される」ものと考えてください。 カードは、どのプレイヤーが他のプレイヤーがそれを超えるのを防ぎながら、自分自身の達成可能な最高スコアを確保できるかを決定する場合にのみ役立ちます。 

決定的な洞察は、プレイヤーごとに、可能な限り最良の「保証された勝利のしきい値」が何なのか、そしてカードがそのしきい値をどのように強制またはブロックできるのかを理解するだけでよいということです。 これは、各プレイヤーの座標に従ってカードを並べ替え、支配力がどのように伝播するかをシミュレートすることでモデル化できます。 

これにより、`O(n m log m)`または`O(n m)`最も影響力のある残りのカードを、結果を変えることができるプレイヤーに繰り返し割り当てる貪欲なスタイルのシミュレーション。

 ## アルゴリズムのチュートリアル

 1. 各プレイヤーごと`j`、すべてのカードをその位置の値の降順で並べ替えます`j`。 

これにより、他のカードとは独立して、各プレイヤーにとって各カードがどの程度望ましいかというランク付けが行われます。 
2. まだ利用可能なカードのセットを維持します。 最初は全部`m`カードが利用可能です。 

選択の決定を段階的にシミュレートし、割り当てられたカードを削除します。 
3. 各プレイヤーごとに 1 から`n`、残りの選択肢を考慮して、彼らが取ることができる最良のカードを決定します。 

彼らはまず勝利のチャンスを最大化したいと考えているため、どのカードが最も強力な競争力を与えてくれるのかをチェックします。 
4. カードはプレイヤーにとって「安全」であると見なされます`j`他のプレイヤーが、まだ利用可能なカードを使用して得られるスコアに達するか、それを超えることができない場合。 

これにより、それを選択すると、スコアを向上させるだけでなく、勝利を確実にできる可能性があります。 
5. 各プレイヤーは、優先順位で最高ランクの安全なカードを選択します。 

安全なカードが存在しない場合は、そのポジションで自分のスコアが最大になるカードを選択します。`j`。 
6. 選択したカードを取り除き、次のプレイヤーに進みます。 
7. すべての選択後、最終スコアを計算し、最大スコアを持つプレーヤーを特定します。 

### なぜ効果があるのか

 プロセスのどの時点でも、プレイヤーがローカル最高得点カードから外れる唯一の理由は、そのカードが最終結果で他のプレイヤーを上回ることを許可する場合です。 安全性の概念は、後のプレイヤーが勝者をひっくり返すためにカードを悪用できない条件を正確に捉えています。 各削除は将来の探索スペースを厳密に削減し、残りのプレイヤーに対する最適な応答の実現可能性を維持するため、貪欲な選択は将来のすべての最適な応答と一貫したままになります。 

不変条件は、最初の処理後の`k`プレイヤーは、残りのカードを使用して、残りのすべてのプレイヤーが、以前の選択を条件として、最適なプレイの下で可能な限り最高の結果を達成することができます。 これにより、早期の決定により全体的に最適な勝利構成が排除されるのを防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(m)]

    # sort cards by each player's value
    order = []
    for j in range(n):
        order.append(sorted(range(m), key=lambda i: a[i][j], reverse=True))

    used = [False] * m
    ans_card = [-1] * n

    for j in range(n):
        chosen = -1

        for idx in order[j]:
            if used[idx]:
                continue

            # check if safe: no remaining card beats it for any player
            ok = True
            for p in range(n):
                if p == j:
                    continue
                # find best remaining for player p
                best = 0
                for i in range(m):
                    if not used[i]:
                        best = max(best, a[i][p])
                if best > a[idx][p]:
                    ok = False
                    break

            if ok:
                chosen = idx
                break

        if chosen == -1:
            for idx in order[j]:
                if not used[idx]:
                    chosen = idx
                    break

        used[chosen] = True
        ans_card[j] = chosen

    scores = [0] * n
    for j in range(n):
        i = ans_card[j]
        scores[j] = a[i][j]

    winner = max(range(n), key=lambda x: scores[x]) + 1
    print(winner)

if __name__ == "__main__":
    solve()
```実装は、プレイヤーごとの貪欲な選択順序に従います。 の`order`配列は、選択が効率的に行われるように、各プレイヤーの好みのランキングを事前に計算します。 の`used`アレイは残りのカードを維持します。 

安全チェック内の入れ子になったループは、候補カードごとに、他のプレイヤーが残りのカードを使用してその値を超えることができるかどうかを再計算します。 これは最もデリケートな部分です。ローカルなランキングだけではなく、グローバルな競争上の制約がエンコードされます。 

最後の採点ステップでは、構築された課題の結果を直接計算します。

 ## 特殊なケース

 最小限のケースが発生するのは、`n = 2`そして、1 枚のカードが、異なる座標にいる両方のプレイヤーにとって同時に最適になります。 このアルゴリズムにより、安全性チェックによりより強力な残りの代替カードの存在が検出されるため、2 番目のプレーヤーがそれを超えることができる場合、最初のプレーヤーが盲目的に最初の座標の最高のカードを取得することがなくなります。 

すべてのカードが座標間の値の並べ替えまで同一である構成では、すべての選択が事実上対称になります。 貪欲なオーダーは最初に任意のカードを選択し、残りのカードはすべて同等であるため、後のプレイヤーがアドバンテージを得ることはありません。 勝者は純粋に、どの座標が選択された最大値と一致し、計算された最大値と一致するかによって決まります。 

1 人のプレイヤーが多くのカードにわたってグローバルに優勢な座標を持っている場合、安全でない選択をすると別のプレイヤーがスコアを超えて選択条件に違反する可能性があるため、アルゴリズムは常にそのプレイヤーをその優勢を維持するカードにルーティングします。
