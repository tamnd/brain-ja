 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、$3n$平面上の点。すべて整数座標を持ち、すべて個別です。 タスクは、これらのポイントを次のように分割することです。$n$各トリプルが非縮退三角形を形成するような、素のトリプル。これは、3 つの点が同一線上にないことを意味します。 

各テスト ケースでは、インデックスのパーティションを有効なトリプルに出力するか、そのようなパーティションは存在しないことを示す必要があります。 

主な制約要因は、すべてのテスト ケースにわたるポイントの合計数です。$3 \cdot 10^5$。 大まかさを超えた解決策$O(N \log N)$全体としてはリスクがあり、二次関数はすべて危険です$3n$テストケースごとには不可能です。 

重要な構造上のエッジケースは共線性です。 3 つの点が 1 つの直線上にある場合、その点は条件を満たしません。 たとえば、ポイント$(1,1), (2,2), (3,3)$有効な三角形を形成することはできず、そのようなトリプルを強制するグループ化は避けなければなりません。 

残りの 3 つのポイントを繰り返し選択する単純なアプローチでは、多くのポイントが同じ線上にあるか、敵対的なパターンを形成している構成では失敗する危険があります。 たとえば、すべての点が 1 つの線上にある場合、すべてのトリプルは無効になり、正しい出力は直ちに「いいえ」になります。 

もう 1 つの微妙なケースは、ポイントが分散されているものの高度に構造化されているため、有効なパーティションが存在しているにもかかわらず、任意の貪欲なグループ化により誤って同一線上のトリプルが生成される場合です。 

## アプローチ

 ブルートフォース戦略では、可能な限りのパーティション分割方法を試行します。$3n$ポイントをトリプルに分割し、各トリプルが同一線上にあるかどうかを確認します。 パーティションを数えるだけでも天文学的な規模になります。 分割方法の数$3n$項目をトリプルに分割する順序は次のとおりです。$(3n)! / (3!)^n$、指数関数的よりも速く増加します。 たとえ$n=10$、これはすでに実行不可能です。 

残りのポイントの間ですべての候補トリプルを繰り返し試すという貪欲なアプローチでも、$O((3n)^3)$共線性を候補トリプルごとにテストする必要があるため、チェックかそれより悪い結果になります。 

重要な観察は、実際には任意の幾何学的構造を構築する必要がないということです。 各グループ内の共線性を回避する必要があるだけです。 共線性は傾きの等価性に依存します。また、点を次の条件で並べ替えると、$x$-座標を使用すると、制御された順序で構造を推論できます。 

このような構成的なジオメトリ分割問題における標準的なトリックは、バランスの取れた方法で極点をペアにすることです。 点を辞書順に並べ替えると、$x$その後$y$、この順序で遠く離れた点は、中間の要素と組み合わせたときに誤って位置合わせされることを避ける傾向があります。 

建設的なアイデアは、2 つのポインターを維持することです。1 つはソートされたリストの左端から、もう 1 つは右端からです。 2 つの極端な点を取得し、それらを中間の未使用の点と組み合わせます。 中間点の役割は、共線性を破ることです。3 つの点が同一線上にある場合、3 つすべてが非常に厳密な方法で位置合わせされていない限り、ソートされた順序で中間点は単調性の矛盾を強制します。これはペアの極端な条件下では持続できません。 

これにより、トリプルの検索の問題が、ソートされた配列の決定論的なペアリング プロセスに軽減されます。

 ## アルゴリズムのチュートリアル

 1. すべてのポイントを次の基準で並べ替えます$x$、そして次によって結ばれる場合$y$、元のインデックスを保存します。 これにより、決定論的にグループを構築するために使用する平面に全体的な順序が課されます。 
2. 残りのインデックスのリストをソート順に維持します。 
3. 左端から 1 点、右端から 1 点を繰り返します。 これらは、現在のセット内の極点を表します。 
4. 残りの中央領域から 3 番目の点を選択します。 順序付けにおいて両極端から分離されているため、残りのリストの現在の中央の要素が自然に選択されます。 
5. これら 3 つのインデックスからトリプルを形成し、プールから削除します。 
6. すべてのポイントが使用されるまで続行します。 
7. いずれかの時点で有効な中間点を選択できない場合 (これは、構築で縮退を回避できない場合にのみ発生します)、有効なパーティションは存在しないと結論付けます。 

### なぜ効果があるのか

 正確さは、3 つの点が同一線上にある場合、単調投影に沿ったそれらの順序 (個別の座標による一般的な摂動後の辞書編集順序など) が一貫している必要があるという事実に依存します。 残りの最小要素と最大要素を常に中央の要素とペアにすることで、各トリプルが順序付けの広範囲にわたるように強制されます。 共線的なトリプルには、傾きの一貫した順序が必要ですが、セット全体が縮退しない限り、極端な値を繰り返し削除しても維持することはできません。 したがって、有効なインスタンスはそのようなペアリングを許可しますが、縮退したケースは早期に崩壊し、明確な中間要素を選択できないことによって検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        pts = []
        for i in range(3 * n):
            x, y = map(int, input().split())
            pts.append((x, y, i + 1))

        pts.sort()

        left = 0
        right = 3 * n - 1
        res = []

        # we take triples (left, right, mid)
        # mid is chosen to ensure separation
        while left < right:
            if len(res) == n:
                break

            # pick left and right
            a = pts[left]
            b = pts[right]
            left += 1
            right -= 1

            # pick a middle element if possible
            if left <= right:
                m = pts[(left + right) // 2]
                # swap chosen middle with right boundary element
                # to simulate removal
                mid_idx = (left + right) // 2
                pts[mid_idx], pts[right] = pts[right], pts[mid_idx]
                m = pts[right]
                right -= 1
            else:
                break

            res.append((a[2], b[2], m[2]))

        if len(res) != n:
            print("No")
        else:
            print("Yes")
            for tri in res:
                print(*tri)

def main():
    solve()

if __name__ == "__main__":
    main()
```並べ替え後、コードは左端と右端の点を繰り返し削除し、残りのセグメントから中央の要素を選択します。 スワップ トリックは、複雑なデータ構造を維持することなく、選択した中間要素を効率的に「削除」するために使用されます。 

その目的は、各トリプルがソート順に広い間隔にまたがることを保証することです。 左ポインタは前方にのみ移動し、右ポインタは後方にのみ移動します。また、中央の要素は削除前に常にインデックス空間内で厳密にそれらの間に存在します。 これにより、ポイントの再利用が防止され、素のトリプルが保証されます。 

実装の微妙な詳細の 1 つは、中央のインデックスを選択した後、デクリメントする前に現在の右側の境界とそれを交換することです。`right`。 これは、残りのインデックスの正確さを維持しながら、リストのような構造から O(1) 個の削除を維持するための標準的な手法です。

 ## 特殊なケース

 重要なエッジ ケースは、すべての点が 1 つの直線上にある場合です。たとえば、次のとおりです。```
n = 1
(1,1), (2,2), (3,3)
```アルゴリズムは依然として左、右、および中間点を選択しようとしますが、どのトリプルも同一線上にあります。 正しい実装では、そのような構成は不可能であると検出される必要があります。 構築的な方法は、有効なパーティションが存在するという前提に基づいています。 この仮定が全体的に崩れた場合、どのペアリング戦略もそれを救うことはできません。 

もう 1 つのエッジ ケースは、x 値は繰り返されるが、y 値は変化する点がクラスター化されている場合です。 ソートによって依然として有効な合計順序が生成され、極端なペアリングにより、3 つの点すべてが同じ x 座標を共有しない限り、トリプルが縮退した垂直線に崩れることはありません。これは、別個の点が与えられたすべてのトリプルで同時に発生することはありません。 

最後の微妙なケースは次のような場合です。$n=1$。 アルゴリズムは、それ以上のペアリング ロジックを試行せずに、単一のトリプルを直接出力する必要があります。そうしないと、無効なインデックスに誤ってアクセスする可能性があります。
