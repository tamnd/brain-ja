 ## 解決策
 ## 問題の理解

 それぞれのサイズが異なる 2 つの文字列コレクションが与えられます。$n$。 それらを単一の長さのシーケンスに配置する必要があります$2n$ただし、位置はパリティによって固定されます。すべての奇数の位置には最初のコレクションの文字列が含まれる必要があり、すべての偶数の位置には 2 番目のコレクションの文字列が含まれる必要があります。 

この交互シーケンスを構築した後、それを隣接するペアに分割します。$(1,2), (3,4), \dots, (2n-1,2n)$。 各ペアは、そのペア内の 2 つの文字列が共有する最長のサフィックスの長さに等しいスコアを与えます。 目標は、すべてのペアにわたるこれらの接尾辞の類似性の合計が最大になるように文字列を割り当てることです。 

重要な構造上の制約は、セット内またはセット間で自由に任意にペアリングできないことです。 最初のセットのすべての要素は、2 番目のセットの 1 つの要素と必ずペアにする必要があり、ペアの寄与は、それらの共有サフィックス構造にのみ依存します。 

制約は大きいです:$n \le 2 \cdot 10^5$、各セットにわたるすべての文字列の合計の長さは次のように制限されます。$2 \cdot 10^5$。 これにより、文字列のすべてのペアを直接比較するソリューションは除外されます。すべてのクロスペアをチェックするだけでも、すでに最大で$O(n^2)$比較。 

各文字列を最も一致する候補と個別にペアリングすることを貪欲に考えると、微妙な落とし穴が現れます。 他の多くの文字列と長いサフィックスを共有する文字列が繰り返し選択され、より適切なグローバル ペアリングがブロックされる可能性があります。 たとえば、複数の文字列が同じ長いサフィックスで終わる場合、調整せずにそれらをローカルでペアにすると、それぞれのローカルな選択が最適に見えても、合計スコアが低下する可能性があります。 

したがって、このタスクは、一連の独立した最適化ではなく、接尾辞の類似性に関するグローバルなマッチング問題です。 

## アプローチ

 直接的なアプローチは、最初のセットと 2 番目のセットの間のすべてのペアのサフィックスの類似性を計算し、エッジの重みがこれらのサフィックスの長さである重み付けされた 2 部マッチング問題を解くことです。 有効なペアリングはそれぞれ独立して寄与するため、これは原理的には正しいです。 ただし、グラフは完全に二部構成になっており、$n^2$この制約の下では、これらの重みを計算したり保存したりすることさえ不可能です。 

重要な観察は、サフィックス構造は、反転された文字列に基づいて構築されたトライを使用して段階的にエンコードできるということです。 すべての文字列を反転すると、サフィックスは反転した表現のプレフィックスになります。 これにより、問題は最長共通プレフィックス (LCP) に基づくペアリング文字列に変換されます。 

逆向きの文字列のトライでは、各ノードはプレフィックスに対応し、長いサフィックスを共有する文字列は、このトライの深いノードの共有に対応します。 ペアの寄与は、まさにトライ内の最も低い共通祖先の深さになります。 

すべてのペアを明示的に評価する代わりに、トライをボトムアップで処理します。 各ノードで、そのノードを通過する 2 つのグループからの不一致の文字列を結合します。 より深いノードはより長い共通サフィックスを表すため、ペアリングは常に、それらが共有する最も深いノードでできるだけ早く行うのが最適です。 これは当然、トライでの貪欲なマッチング戦略につながります。そこでは、カウントを上方に伝播し、ローカルで一致を蓄積します。 

ブルート フォースは、すべてのペアを明示的に比較し、最適な割り当てを選択するため機能しますが、次の場合には失敗します。$n^2$相互作用が不可能になります。 トライベースの集計では、ペアごとの推論が構造的なグループ化に置き換えられ、問題が文字列の全長にわたる線形トラバースに軽減されます。

 ## アルゴリズムのチュートリアル

 1. 両方のセットのすべての文字列を反転します。 これにより、接尾辞の一致が接頭辞の一致に変換され、トライ構造を使用できるようになります。 これが重要な理由は、共有プレフィックスを共有パスとして自然にエンコードしようとするためです。 
2. すべての反転文字列を含む単一のトライを構築します。 各終端ノードで、文字列が最初のセットから来たのか、2 番目のセットから来たのかを保存します。 
3. トライの深さ優先トラバースを実行します。 各ノードで、子から 2 つの値、つまりセット A とセット B の不一致文字列がこのサブツリー内にいくつ存在するか、を収集します。 
4. 子を現在のノードにマージした後、このノードで形成できる一致の数を計算します。 もし持っていれば$a$最初のセットのストリングと$b$第2セットからは勝負できる$\min(a, b)$この深さでペアになります。 
5. 答えに次のように追加します。$\min(a, b) \times \text{depth}$。 これにより、最長の共通プレフィックスがまさにこのノードで終わるすべてのペアの寄与がキャプチャされます。 
6. 残り物を上に伝播します。マッチング後、パスします。$|a - b|$一致しない文字列を親ノードに送信し、どちらの側が依然として優勢であるかを追跡します。 

### なぜ効果があるのか

 すべての有効な文字列ペアには、パスが交差する一意の最も深いトライ ノードがあります。 このノードは、反転された文字列の最長の共通接頭辞を表し、元の文字列の最長の共通接尾辞に正確に対応します。 そのノードでのマッチングにより、その貢献度がすべて取得されます。 トライ内の上位のマッチングを遅らせようとすると、より短い共通プレフィックスを持つ文字列のみがペアになり、合計の寄与が減少します。 マッチングは常に可能な限り最も深い点で貪欲に実行されるため、フローの各単位は正しい深さで 1 回だけ考慮され、最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("next", "cntA", "cntB")
    def __init__(self):
        self.next = {}
        self.cntA = 0
        self.cntB = 0

def add(root, s, typ):
    v = root
    for ch in s:
        if ch not in v.next:
            v.next[ch] = Node()
        v = v.next[ch]
    if typ == 0:
        v.cntA += 1
    else:
        v.cntB += 1

def dfs(v, depth, res):
    a = v.cntA
    b = v.cntB

    for u in v.next.values():
        da, db = dfs(u, depth + 1, res)
        a += da
        b += db

    m = min(a, b)
    res[0] += m * depth
    a -= m
    b -= m

    return a, b

n = int(input())
root = Node()

for _ in range(n):
    s = input().strip()[::-1]
    add(root, s, 0)

for _ in range(n):
    s = input().strip()[::-1]
    add(root, s, 1)

res = [0]
dfs(root, 0, res)
print(res[0])
```この解決策は、トライに挿入する前にすべての文字列を反転することから始まり、接尾辞の関係が接頭辞の関係になるようにします。 各リーフ ノードは、最初のセットに属するか 2 番目のセットに属するかに応じてカウンターをインクリメントします。 

DFS 集計では子から順にカウントされます。 重要なステップは、次を使用してローカル マッチングを行うことです。`min(a, b)`これは、現在のプレフィックスとできるだけ多くの文字列をペアにすることを表します。 の乗算`depth`これらの一致を、答えへの実際の寄与に変換します。 

戻り値`a`そして`b`は、より深いノードではペアにできなかった一致しない文字列を表し、共通のプレフィックスが短い上位レベルで考慮する必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    sys.setrecursionlimit(10**7)

    class Node:
        def __init__(self):
            self.next = {}
            self.cntA = 0
            self.cntB = 0

    def add(root, s, typ):
        v = root
        for ch in s:
            if ch not in v.next:
                v.next[ch] = Node()
            v = v.next[ch]
        if typ == 0:
            v.cntA += 1
        else:
            v.cntB += 1

    def dfs(v, depth):
        a = v.cntA
        b = v.cntB
        res = 0
        for u in v.next.values():
            da, db, sub = dfs(u, depth + 1)
            a += da
            b += db
            res += sub
        m = min(a, b)
        res += m * depth
        a -= m
        b -= m
        return a, b, res

    n = int(sys.stdin.readline())
    root = Node()

    for _ in range(n):
        add(root, sys.stdin.readline().strip()[::-1], 0)
    for _ in range(n):
        add(root, sys.stdin.readline().strip()[::-1], 1)

    _, _, ans = dfs(root, 0)
    return str(ans)

 ## 特殊なケース

 1 つのエッジケースは、両方のセットのすべての文字列が同一である場合に発生します。 その状況では、すべてのペアが文字列全体の長さに寄与する必要があります。 トライは単一のパスに崩壊し、両方のカウンターが各深度で完全に蓄積されます。 各ノードでは、`min(a, b)`最初に最も深いレベルでのみ一致を抽出し、すべてのペアが最大の深さで正確に 1 回カウントされるようにします。 

もう 1 つの特殊なケースは、接尾辞の重複がまったく存在しない場合です。 トライはルートですぐに分岐し、両方のタイプを含む深いノードはありません。 全て`min(a, b)`計算は正の深さではゼロのままであるため、答えはゼロのままであり、空ではないサフィックスを共有するペアがないことを正しく反映しています。
