 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$、からのすべての値を意味します$1$に$n$配列内に 1 回だけ出現します。 各クエリについて、連続したセグメントを調べ、左側の部分のすべての値が右側の部分のすべての値より厳密に小さくなるように、連続する 2 つの部分に分割できるかどうかを尋ねます。 

より操作的に言い換えると、セグメント内に左側のすべての数値が右側のすべての数値よりも小さいカット位置が存在する場合、そのセグメントは「良好」です。 カットでは配列の順序を尊重する必要があるため、要素の順序を変更するのではなく、分割点を選択するだけです。 

制約は大きく、両方とも$n$そして$q$まで$3 \cdot 10^5$。 セグメントをスキャンして各クエリを処理するソリューションにはコストがかかります$O(n)$クエリごとに、$O(nq)$、これは実現可能な限界をはるかに超えています。 これにより、ほぼ次のような前処理が可能になります。$O(1)$または対数クエリ時間。通常はプレフィックス情報とグローバル構造を使用します。 

微妙な問題は、「ほぼ順序付けられている」ように見えるセグメントに現れますが、境界を越える単一の反転が原因で失敗します。 たとえば、次のようなセグメントでは、$[3,1,4,2]$、両方の半分にローカルに小さい要素と大きい要素が含まれている場合でも、有効な分割はありません。 障害物はグローバルです。小さな要素が大きな要素の右側に現れ、きれいな分離が妨げられます。 

## アプローチ

 ブルート フォース手法では、各クエリ セグメント内の考えられるすべての分割ポイントが試行されます。 固定クエリの場合$[l, r]$、すべてをテストします$i \in [l, r-1]$かどうかを確認してください$\max(a_l \dots a_i) < \min(a_{i+1} \dots a_r)$。 これには、範囲の最大値と最小値を繰り返し計算する必要があります。 RMQ の前処理を行っても、引き続きチェックします。$O(n)$クエリごとにポイントを分割することで、$O(nq)$最悪の場合の行動。 

重要な観察は、「分裂が存在する」という条件はグローバルに再構成できるということです。 有効な分割は、左側のセットのすべての要素が右側のセットのすべての要素よりも小さくなるように、元の順序を尊重してセグメントを 2 つのセットに分割できる場合にのみ存在します。 これは、マージを強制する「クロス反転」がない場合、セグメントを連続したブロックに分割できると言っているのと同じです。 

すべての分割ポイントをテストするのではなく、順番にスキャンするときにセグメント内にいくつの素の「ソートされたブロック」が存在するかを追跡します。 現在のブロック内で必要な最小値を維持できない場合は常に、新しいブロックが開始されます。 具体的には、貪欲なパーティションを維持できます。つまり、ランクの連続性を満たすために必要なすべての値が含まれるまで現在のブロックを拡張します。これは、プレフィックスの最大値を追跡し、位置マッピングとの一貫性を確保することに相当します。 

より標準的でクリーンな再定式化では、順列プロパティを使用します。 させて`pos[x]`価値のある立場になる$x$。 どのセグメントでも$[l, r]$、セグメント内の値を並べ替えるときに、その位置がインターリーブせずに値の境界で分割できる間隔の和集合を形成する場合に限り、セグメントは適切です。 これは、セグメントを「カット値」で分割できるかどうかをチェックすることになります。$k$すべての値が$\le k$すべての値の前に完全に出現する$> k$セグメント内。 この状態は、値の順序でスキャンしながら、値の最大位置範囲と最小位置範囲を追跡することで検証できます。 

配列を前処理します`pos[x]`、次に、値の範囲に対して最小位置と最大位置をクエリできるように、値の順序に関するデータ構造を維持します。 セグメントの場合$[l, r]$、値のしきい値が存在するかどうかを見つけようとします$k$次のような:

 値の最小位置$1..k$中にある$[l, r]$、および値の最大位置$1..k$中にもあります$[l, r]$、残りの値についても同様です。 これにより、問題はセグメントが値空間にマッピングされたときに連続した構造を形成するかどうかをチェックすることになり、値インデックスを格納するセグメント ツリーを使用して答えることができます。$(minPos, maxPos)$。

 ## アルゴリズムのチュートリアル

 1. アレイを構築する`pos`そのような`pos[v]`値のインデックスを与える$v$順列の中で。 これにより、問題がインデックス空間から値空間に変換されます。値は順列であり、順序付けされた軸として扱うことができるため、これは重要です。 
2. 値ドメイン上にセグメント ツリーを構築する$[1, n]$ここで、各ノードはその範囲内の値の最小位置と最大位置を格納します。 これにより、元の配列内の値の間隔がどこにあるかをクエリできるようになります。 
3. 各クエリセグメントについて$[l, r]$、このセグメントの値を、位置をインターリーブせずに 2 つの連続する値の間隔に分割できるかどうかを検出したいと考えています。 セグメント ツリーを使用して、値の境界を暗黙的に検索します。 
4. 値 1 から始めて、範囲の最小位置と最大位置をクエリすることによって、候補の左グループを繰り返し拡張します。 ある時点で位置間隔が外れた場合$[l, r]$、この境界は有効なカットを形成できないことがわかっているので、マージを続行します。 
5. 左グループの位置間隔が完全に含まれるサブセットと正確に一致する点に到達するたびに、$[l, r]$、分割を試みます。残りの値も完全に$[l, r]$位置が重ならないように。 このようなパーティションが存在する場合、そのセグメントは良好です。 
6. 有効な境界が見つかった場合は「はい」と答え、そうでない場合は「いいえ」と答えます。 

### なぜ効果があるのか

 順列構造により、各値が一意の位置に対応することが保証されるため、2 つの値セット間にインターリーブがない場合にのみ、値空間内の候補分割によって位置空間に連続した間隔が生じます。 セグメント ツリーは、最小/最大位置範囲を介してこのインターリーブを正確にキャプチャします。 値の範囲を、クエリ セグメント内で位置範囲が重複しない 2 つの連続した値のブロックに分割できる場合に、有効な分割が存在します。 これにより、正確さが保証されます。インターリーブがあると、最小値と最大値の位置間隔でオーバーラップが強制され、きれいな分離が妨げられるからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, pos):
        self.n = len(pos) - 1
        self.minv = [0] * (4 * self.n)
        self.maxv = [0] * (4 * self.n)
        self.pos = pos
        self.build(1, 1, self.n)

    def build(self, v, l, r):
        if l == r:
            self.minv[v] = self.maxv[v] = self.pos[l]
        else:
            m = (l + r) // 2
            self.build(v * 2, l, m)
            self.build(v * 2 + 1, m + 1, r)
            self.minv[v] = min(self.minv[v * 2], self.minv[v * 2 + 1])
            self.maxv[v] = max(self.maxv[v * 2], self.maxv[v * 2 + 1])

    def query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.minv[v], self.maxv[v]
        m = (l + r) // 2
        res_min = 10**18
        res_max = -1
        if ql <= m:
            mn, mx = self.query(v * 2, l, m, ql, qr)
            res_min = min(res_min, mn)
            res_max = max(res_max, mx)
        if qr > m:
            mn, mx = self.query(v * 2 + 1, m + 1, r, ql, qr)
            res_min = min(res_min, mn)
            res_max = max(res_max, mx)
        return res_min, res_max

n = int(input())
a = list(map(int, input().split()))
pos = [0] * (n + 1)

for i, x in enumerate(a, 1):
    pos[x] = i

st = SegTree(pos)

q = int(input())
out = []

for _ in range(q):
    l, r = map(int, input().split())

    lo, hi = 1, n
    ok = False

    while lo < hi:
        mid = (lo + hi) // 2
        mn, mx = st.query(1, 1, n, 1, mid)
        if mn >= l and mx <= r:
            ok = True
            hi = mid
        else:
            lo = mid + 1

    if ok:
        mn, mx = st.query(1, 1, n, 1, lo)
        if mn >= l and mx <= r and lo < n:
            mn2, mx2 = st.query(1, 1, n, lo + 1, n)
            if mn2 >= l and mx2 <= r:
                ok = True
            else:
                ok = False
        else:
            ok = False

    out.append("Yes" if ok else "No")

print("\n".join(out))
```中心となる実装の詳細は、値インデックスに対するセグメント ツリーです。 各ノードは、元の配列内で値の範囲が出現する場所を要約します。 その後、クエリは、特定の値の範囲がクエリ間隔に完全に含まれているかどうかを確認することになります。 二分探索では、値空間内の有効な分割を見つけようとします。 

最もデリケートな部分は、封じ込めチェックの正確性を維持することです`mn >= l and mx <= r`これにより、候補値ブロックがクエリ セグメントの外に漏れないようになります。

 ## 特殊なケース

 主なエッジ ケースは、配列が局所的には単調であるが、セグメントの自然な分割の外側にある値がグローバルにインターリーブされているセグメントです。 たとえば、`[1, 3, 2, 4]`、2 は右側にありますが 3 より小さいため、3 と 2 の間の分割は無効です。セグメント ツリーはこれを検出します。これは、値ブロックが存在するためです。`[1,3]`すでにクリーンな境界の外側の位置にまたがっています。 

もう 1 つのエッジ ケースは、連続した値を含むが位置が分散しているセグメントです。`[2, 1, 4, 3]`。 値は次のように分割できますが、`[2,1]`そして`[4,3]`、位置はまだ分離可能であるため、アルゴリズムは位置の間隔を考慮した有効な値のしきい値を見つけて「はい」を正しく返します。 

これらのケースは、正確さが順序のみに依存するのではなく、値の間隔が連続した位置範囲に対応するかどうかに依存することを確認します。
