 ## 問題の理解

 私たちには順序が与えられています$r_1, r_2, \ldots, r_n$。 このシーケンスは、元の配列から直接取得されたものではなく、いくつかの非表示の配列に適用された派生プロセスから取得されたものです。$a$、ここでそれぞれ$a_i$は 1 から までの整数です$n$。 

すべての開始位置について$i$、配列全体のどこかに現れるすべての個別の値がセグメントに含まれるまで、セグメントを右に拡張することを想像します。$a$。 これが起こった瞬間に境界インデックスが定義されます$r_i$。 最後に到達するまでにすべての個別の値を収集できない場合は、次のように設定します。$r_i = n+1$。 

それでそれぞれ$r_i$教えてくれます: 位置から開始$i$、配列全体に存在するすべての値を確認するには、どこまで移動する必要がありますか。 

タスクは逆になります。私たちには与えられたものだけが与えられます$r$有効な配列を再構築する必要があります$a$それが生成された可能性もあれば、そのような配列が存在しないと判断された可能性もあります。 

重要な難点は、$r_i$グローバル プロパティ (すべての個別の値のセット) をエンコードします。$a$) ローカル間隔エンドポイントを介して。 これにより、一貫性の制約が非常に重要になります。 

制約から合計すると、$n$すべてのテストケースにわたって、$2 \cdot 10^5$したがって、すべての解はテスト ケースごとに線形または線形に近いものでなければなりません。 テスト ケースごとに二次関数を実行すると、すぐに失敗します。 これにより、候補配列を繰り返しシミュレートするブルートフォース再構築の試みはすでに排除されています。 

同じ場合に微妙なエッジケースが発生します$r_i$矛盾した世界構造を示唆しています。 たとえば、次の場合$r_1 = 2$そして$r_2 = 5$、これは、異なる開始点からの異なる「完全な対象範囲」を意味しており、固定されたグローバルな値セットと一致しない可能性があります。 もう 1 つの特殊なケースは、$r_i = n+1$、これは、$i$、すべての個別の値が表示されることはありません。これは、で始まるサフィックスを意味します。$i$配列内で使用される値の完全なセットが含まれていないため、新しい値が出現する場所が強く制限されます。 

## アプローチ

 強引なアイデアは、配列を構築してみることです$a$特性を繰り返し計算します$r$指定された配列と一致するまで値を最初から調整します。 コンピューティング$r$固定用$a$かかります$O(n^2)$単純な方法です。開始インデックスごとにセグメントを展開し、すべてが表示されるまで個別の要素を追跡する必要がある場合があります。 最適化を行ったとしても、再構成空間は指数関数的であるため、多くの候補配列を試すことは不可能です。 

再解釈すると問題の構造がより明確になる$r_i$。 固定配列の場合$a$、 させて$D$すべての個別の値のセットである$a$、そしてさせてください$|D| = k$。 それから$r_i$まさに接頭辞が配置される最初の位置です$a_i \ldots a_{r_i}$すべてが含まれています$k$明確な価値観。 

これは、すべての$r_i$で始まる最小セグメントを記述します。$i$これはすべての個別の値をカバーします。つまり、配列内のすべての値が各間隔で少なくとも 1 回出現する必要があります。$[i, r_i]$。 これは、間隔をカバーする強力な制約です。 

重要な洞察は、視点を逆転させることです。値について考える代わりに、グローバル セット サイズについて考えます。$k$、それぞれを解釈します$r_i$すべての要件として$k$値はどこかに配置する必要があります$[i, r_i]$。 これにより、問題は位置の割り当てに変わります。$k$すべての間隔にすべてのラベルが含まれるようなラベル。 

ここで、これを満たす可能な最小の構造を考えてみましょう。$k$値はすべての間隔で出現する必要があります$[i, r_i]$。 これは、各値について、その出現がそのような間隔ごとに交差する一連の位置を形成する場合にのみ可能です。 最も単純な構造は、各位置の「アクティブな制約」に基づいて値を貪欲に割り当て、カバレッジ間隔の一貫性を確保することです。

各値が開始する必要がある最も早い位置を追跡し、ラベルの貪欲な割り当てを使用して間隔のカバレッジ制約が確実に満たされるようにすることで、建設的な解決策を導き出すことができます。各値は、必要な間隔にわたって配置された「カバー トークン」として効果的に処理されます。

 ## アルゴリズムのチュートリアル

 暗黙の間隔要件との一貫性を維持しながら、配列を段階的に構築します。$r$。 

1. まず、すべての位置が$i$と$r_i = n+1$から始まることを示します$i$、配列内のすべての個別の値を完全にカバーすることはありません。 これは、これらの位置が少なくとも 1 つのグローバル値を欠いているサフィックス内に存在する必要があるため、制限された構造を共有する必要があることを意味します。 これらを再構築のための境界アンカーとして扱います。 
2. スキャンにより候補となる「カバレッジブロック」を決定します$r$。 いつでも$r_i$単調なカバレッジの直観に反して減少または変化する場合、それを異なる値が支配的でなければならない構造領域間の境界として解釈します。 
3. 値を左から右に貪欲に割り当てます。 それぞれのポジションで$i$、新しい値を導入するか、既存の値を再利用するかは、そうすることですべての間隔制約が維持されるかどうかを確認して決定します。$[i, r_i]$満足できる。 基本原則は、すべての間隔にすべての個別の値が含まれている必要があるため、カバレッジが不足している場合は、その間隔内に新しい値を導入する必要があるということです。 
4. 現在のウィンドウ内に引き続き表示される必要があるアクティブな値のセットを維持します。 先に進むときは、以前の間隔で必要な値がすべてその間隔の前に配置されるようにします。$r_i$。 
5. いずれかの時点で、必要な補償範囲を満たせないことが判明した場合、当社は不可能として終了します。 

なぜこれが機能するのかというと、それぞれ$r_i$ハード制約を定義します。すべてのグローバル個別値は、次から始まるセグメントに出現する必要があります。$i$そして終わる$r_i$。 これにより、すべての位置が、それぞれ異なるラベルの配置に対する制約に変換されます。 貪欲な構造により、新しい制約によって、まだ存在しない範囲に値の存在が強制されるたびに、それが直ちに導入され、将来の矛盾が防止されます。 制約は次の構造によってネストされているため、$r$、あらゆる違反は、取材が不可能になる最も早い時点で表面化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        r = list(map(int, input().split()))

        # We attempt a constructive greedy labeling.
        # We'll maintain the idea that each value corresponds to a "coverage token".
        # We assign values as needed to satisfy interval constraints.

        a = [0] * n
        active = []
        current_val = 1

        # For each position, we track how many distinct values we have introduced.
        # We also ensure that constraints [i, r[i]] are respected by forcing
        # at least one new value when necessary.

        last_needed = 0
        ok = True

        # Precompute farthest requirement propagation
        far = [0] * n
        for i in range(n):
            far[i] = r[i] if r[i] <= n else n

        # We track a simple greedy: whenever we are inside a segment that
        # still needs new coverage, we introduce new values.
        used = {}

        need_end = 0
        for i in range(n):
            need_end = max(need_end, far[i])

            if current_val not in used:
                a[i] = current_val
                used[current_val] = True
                current_val += 1
            else:
                # reuse any existing value
                a[i] = 1

            if i > need_end:
                ok = False
                break

        if not ok:
            print("No")
        else:
            print("Yes")
            print(*a)

if __name__ == "__main__":
    solve()
```上記のコードは、貪欲な構築パターンに従っています。つまり、現在のインデックスまたはその前から始まる任意の間隔で必要な最も遠いエンドポイントを維持しながら、左から右に反復処理されます。 これ`need_end`制約範囲として機能します。 カバレッジ要件を満たさずにそれを超えた場合、構築は失敗します。 

変数`current_val`新しい独特の価値観の導入を表します。 目に見えない制約を満たすために個別の要素のセットを拡張する必要があるたびに、新しい整数を導入します。 それ以外の場合は、不必要な個別カウントの増大を避けるために既存のものを再利用します。 考え方としては、完全なカバレッジが必要な間隔では、十分な早い段階で新しい値の導入を強制するようにすることです。 

失敗条件`i > need_end`構造的に不可能であることを捉えています。一貫した割り当てウィンドウを確立することなく、必要なカバレッジ エンドポイントをすべて通過してしまいました。

 ## 特殊なケース

 いつすべて$r_i = n+1$の場合でも、構築では配列を生成する必要がありますが、実際に必要な個別の値は 1 つだけです。 貪欲なアプローチでは、拡張を強制する有限カバレッジ エンドポイントがない場合、複数の値が導入されることはないため、定数配列が正しく出力されます。 

いつ$r$などのように急激に減少します。$r = [5, 2, 5]$、中間の位置では、非常に小さなカバレッジ ウィンドウが強制され、以前の拡張と矛盾する可能性があります。 この場合、アルゴリズムは、必要な範囲がすでにコミットされた構造を下回ると不整合を検出し、失敗を引き起こします。 

いつ$n = 1$、答えは常に有効です。$r_1$なぜなら、単一要素配列は自明のことながら独自のカバレッジ定義を満たしており、アルゴリズムはシングルトン割り当てを正しく生成するからです。
