 ## 解決策
 ## 問題の理解

 最初の配列と、次々に適用される一連の範囲更新から始めます。 これらの操作の各プレフィックスの後、配列の新しいバージョンを取得します。 タスクは、すべての更新を完全に処理することではなく、プレフィックスの長さを選択し、操作がゼロになる可能性も含め、正確にその数の操作を適用した後に配列を取得することです。 これらすべてのプレフィックス状態の中で、辞書編集的に最小の結果の配列が必要です。 

キー オブジェクトは、時間によってインデックスが付けられた配列のファミリーです。 j 番目の配列は、最初の j 範囲の加算を適用した後に取得されるため、各状態はセグメント上でのみ、また一定のシフトによってのみ前の状態と異なります。 

辞書編集的な比較では、2 つの候補配列が異なる最初の位置に注意が向けられます。 これは、他のすべての差よりも前のインデックスに影響を与えない限り、全体的な合計や全体の大きさは無関係であることを意味します。 

この制約により、強引な再構築は不可能になります。 すべてのテスト ケースにわたる配列の合計長と演算数は 50 万回に達します。 プレフィックスごとに完全な配列を再計算したり、操作ごとに影響を受けるすべての位置を更新したりするアプローチは、最悪の場合、すぐに二次関数になります。 

運用について貪欲に考えると、微妙な落とし穴が現れます。 操作によって配列のある位置が小さくなったら、常にそれを取得する必要があると考える人もいるかもしれません。 これは失敗します。なぜなら、後の操作によって前のインデックスが改善されたとしても、後の操作によって前のインデックスが悪化する可能性があり、辞書編集上の順序は、変更が発生した最初のインデックスによって完全に支配されるからです。 

2 番目の問題は、インデックスごとの独立性を仮定することです。 各インデックスは範囲更新の重複を通じて進化するため、2 つのプレフィックスを比較するには、ローカルな変更だけでなく、すべてのインデックスにわたるそれらの組み合わせの影響を理解する必要があります。 

## アプローチ

 直接的なアプローチでは、すべてのプレフィックスを個別にシミュレートします。 j 回の操作を処理した後、完全な配列 b_j が得られ、それをこれまでに見つかった最良の配列と比較します。 b_j の構築には O(n) のコストがかかり、これを q 個のプレフィックスに対して実行すると O(nq) となり、これは制限をはるかに超えています。 

差分配列を使用してこれを改善しても、構築の問題が解決されるだけであり、比較の問題は解決されません。 2 つの完全な配列を効率的に比較する必要があり、辞書編集的な比較では、それらが異なる最初のインデックスを見つける必要があります。 構造がないと、これも比較ごとの線形スキャンに堕してしまいます。 

重要な点は、実際にはすべてのプレフィックス配列を保存する必要がないということです。 どの接頭辞インデックス j が最適な配列を生成するかを特定することだけが必要です。 j が判明すると、最終的な配列を 1 回のスイープで再構成できます。 

これにより、問題は配列の 2 つのバージョン間の比較問題に変わります。つまり、2 つの接頭辞状態 j1 と j2 が与えられた場合、どちらが辞書編集的に小さいかを判断します。 任意の 2 つのバージョンを効率的に比較できれば、j に対する単純なスキャンを使用して最適なプレフィックスを維持できます。 

2 つのプレフィックス状態を比較するには、蓄積された寄与が 2 つの時点間で異なるように最小のインデックス i を見つける必要があります。 2 つの状態の差は、それ自体、区間 (j1, j2] 内の操作に対する範囲加算の差であり、これらの操作の影響を受けるインデックスに限定されます。これは、インデックスの任意のセグメントについて、2 つの時間プレフィックスがそのセグメントで同一の値を生成するかどうかを答えることができる構造を示唆しています。

 インデックス上のセグメント ツリーは空間分解を提供します。 各ノードは位置の範囲に対応します。 各ノードについて、そのセグメントを完全にカバーするすべての操作を保存します。 これらの操作については、それらの寄与を時間順に維持し、操作の任意のプレフィックス間隔に制限された寄与の合計をクエリできるようにします。

これにより、セグメント内のどこかで 2 つのプレフィックス状態が異なるかどうかをテストでき、最初に異なるインデックスを二分探索できます。 

これは、インデックスに対する対数二乗検索を使用して候補プレフィックス状態を繰り返し比較するという解決策につながります。各比較は、O(log q) でクエリされる O(log n) セグメント ツリー ノードからの寄与の集約に依存します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | プレフィックス状態のセグメント ツリー比較 | O(n log² n log q) | O(n log n + q log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列インデックス上にセグメント ツリーを構築します。各ノードは位置のセグメントを表します。 各ノードには、更新範囲がそのノードを完全にカバーするすべての操作が保存されます。 

この分離により、後で任意のセグメントについて、個々の要素に触れることなく、演算のプレフィックスの全体的な効果を計算できるようになります。 
2. 各ノードについて、その操作を時間インデックスでソートして保存します。 同時に、演算値に対するプレフィックスの合計を維持します。 

これにより、2 つの二分検索を使用して、任意の時間間隔における操作の合計寄与度をクエリすることが可能になります。 
3. 2 つの接頭辞状態 j1 および j2 が与えられた場合に、それらがインデックスのセグメント上で等しいかどうかを判断できる関数を定義します。 

固定セグメントの場合、それをカバーするすべてのノードからの寄与を集計し、2 つの時間プレフィックス間の合計の差を計算します。 
4. セグメントの等価性チェックを使用して、インデックスに対して二分探索を実行し、b_{j1} と b_{j2} が異なる最初の位置を見つけます。 

各中間点で、プレフィックス [1..mid] が両方の状態で同一であるかどうかをテストします。 そうであれば、違いは右側にあります。 それ以外の場合は左側にあります。 
5. 最初の異なるインデックス i がわかったら、同じセグメント ツリー集約を使用して両方のプレフィックス状態のそのインデックスの値を計算し、それらを直接比較します。 
6. j = 0 から始まる最良のプレフィックス インデックスを維持します。1 から q までの各 j について、b_j を現在の最良のものと比較し、b_j が辞書編集的に小さい場合は更新します。 

これにより、完全な配列を保存せずに、グローバルに最適なプレフィックスが生成されます。 
7. 最適なプレフィックス インデックスを特定した後、標準的な差分配列またはフェンウィック ツリーを使用してこれらの操作を順番に正確に適用することにより、最終的な配列を再構築します。 

### なぜ効果があるのか

 このアルゴリズムは、各配列状態が範囲更新の累積寄与によって完全に決定されること、および 2 つの状態間の差異が演算の独立した寄与に分解できるという事実に依存しています。 セグメント ツリーは、各操作が完全に適用される場所で正確に考慮されるようにインデックスを編成し、二重カウントを回避します。 辞書編集的な順序は最も古い異なるインデックスのみに依存するため、最初の差分クエリとの比較を減らすことで正確さが維持されます。 すべての比較では関連する操作間隔にわたって正確な合計が計算されるため、近似は導入されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.f = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.f[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.f[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

# We build segment tree storing operations per node
def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    ops = [None] * q
    for i in range(q):
        l, r, x = map(int, input().split())
        ops[i] = (l - 1, r - 1, x, i)

    seg = [[] for _ in range(4 * n)]

    def add(node, l, r, ql, qr, op):
        if ql <= l and r <= qr:
            seg[node].append(op)
            return
        mid = (l + r) // 2
        if ql <= mid:
            add(node * 2, l, mid, ql, qr, op)
        if qr > mid:
            add(node * 2 + 1, mid + 1, r, ql, qr, op)

    for l, r, x, i in ops:
        add(1, 0, n - 1, l, r, (i, x))

    seg_ops = [None] * (4 * n)
    bit = None

    def build(node, l, r):
        seg[node].sort()
        seg_ops[node] = seg[node]
        if l == r:
            return
        mid = (l + r) // 2
        build(node * 2, l, mid)
        build(node * 2 + 1, mid + 1, r)

    build(1, 0, n - 1)

    # For each node we build BIT over time indices
    bits = [None] * (4 * n)

    def build_bits(node):
        arr = seg_ops[node]
        if not arr:
            bits[node] = None
            return
        arr.sort()
        b = BIT(q)
        for idx, val in arr:
            b.add(idx + 1, val)
        bits[node] = b
        if node * 2 < len(seg_ops):
            if seg_ops[node * 2] is not None:
                build_bits(node * 2)
            if seg_ops[node * 2 + 1] is not None:
                build_bits(node * 2 + 1)

    build_bits(1)

    def query_node(node, j, l, r):
        if bits[node] is None:
            return 0
        return bits[node].sum(j)

    def diff_on_segment(node, l, r, j1, j2):
        if bits[node] is None:
            return 0
        return bits[node].sum(j2) - bits[node].sum(j1)

    def equal_prefix(j1, j2, idx):
        def check(node, l, r, ql, qr):
            if qr < l or r < ql:
                return 0
            if ql <= l and r <= qr:
                return diff_on_segment(node, l, r, j1, j2)
            mid = (l + r) // 2
            return check(node * 2, l, mid, ql, qr) + check(node * 2 + 1, mid + 1, r, ql, qr)

        def has_diff(i):
            return check(1, 0, n - 1, 0, i) != 0

        lo, hi = 0, n - 1
        while lo < hi:
            mid = (lo + hi) // 2
            if has_diff(mid):
                hi = mid
            else:
                lo = mid + 1
        return lo

    def get_val(i, j):
        res = a[i]
        def dfs(node, l, r):
            if bits[node] is None:
                return 0
            if l == r == i:
                return bits[node].sum(j)
            mid = (l + r) // 2
            if i <= mid:
                return dfs(node * 2, l, mid)
            else:
                return dfs(node * 2 + 1, mid + 1, r)
        return res + dfs(1, 0, n - 1)

    def less(j1, j2):
        i = equal_prefix(j1, j2, 0)
        v1 = get_val(i, j1)
        v2 = get_val(i, j2)
        return v1 < v2

    best = 0
    for j in range(1, q + 1):
        if less(j, best):
            best = j

    res = [0] * n
    for i in range(n):
        res[i] = get_val(i, best)

    print(*res)

t = int(input())
for _ in range(t):
    solve()
```このコードは、問題を 2 つの部分に分割します。1 つは 2 つのプレフィックス状態の比較、もう 1 つは最終的な最良の状態の再構築です。 比較は、二分探索によって最初の異なるインデックスを特定することによって行われますが、再構成では、蓄積されたセグメントの寄与を使用して、選択されたプレフィックスを単純に評価します。 

最もデリケートな部分は、各ノードが完全にカバーされる間隔を表すように、操作がセグメント ツリー ノードごとに保存されることです。 これにより、操作ごとに個々のインデックスを再処理することがなくなり、時間の経過とともに寄与クエリがプレフィックス合計に減少することが保証されます。 

## 実用的な例

 異なるプレフィックスが目に見えて異なる初期変更を作成する小さな配列を考えてみましょう。 

| ステップ j | 適用された操作 | これまでで最高のプレフィックス | 最初の異なるインデックスと最良のインデックス |
 | --- | --- | --- | --- |
 | 0 | なし | 0 | なし |
 | 1 | セグメントの更新は後の位置に影響します。 1 | 0 |
 | 2 | 更新により最初の要素が減少します | 2 | 0 |

 このトレースは、プレフィックスが以前のインデックスを改善すると、その後の改善に関係なく、すぐに後のすべてのプレフィックスを支配することを示しています。 

2 番目の例では、オーバーラップを強調しています。 

| ステップ j | インデックス 1 への影響 | インデックス 2 への影響 | ベストを選択 |
 | --- | --- | --- | --- |
 | 0 | 5 | 5 | 0 |
 | 1 | 4 | 6 | 1 |
 | 2 | 6 | 3 | 1 |

 ここで、2 番目の演算は後の位置を改善しますが、最初の比較点を悪化させるため、配列の一部を改善しても最適にはなりません。 

これらの例は、辞書編集上の優位性が、集合的な改善によってではなく、常に最初に影響を受けたインデックスによって決定されることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log² n log q) | プレフィックス状態間の各比較ではインデックスに対する二分検索が使用され、各チェックではセグメント ツリー ノードの寄与がノードごとの対数時間で集計されます。 
| スペース | O(n log n + q log n) | 各操作はセグメント ツリーの O(log n) ノードに保存され、それぞれが時間インデックス付きの寄与リストを維持します。 

n と q の合計が 5e5 で制限され、対数係数が中程度に保たれるため、解は制限内に留まります。 すべてのプレフィックスにわたって比較を繰り返した場合でも、この構造により、比較ごとに配列に対する線形スキャンが回避されます。

 ## 特殊なケース

 重要なエッジ ケースは、2 つのプレフィックスが、初期のインデックスに影響を与えない後の操作によってのみ異なる場合です。 たとえば、配列のサフィックスに完全に適用される操作は有益に見えるかもしれませんが、前のプレフィックスがすでに以前の位置を改善している場合は無関係です。 累積寄与が異なる最初のインデックスで比較が停止し、サフィックスのみの違いがその決定に影響を与えることがないため、アルゴリズムはこれを処理します。 

別のケースにはキャンセルが含まれます。同じ範囲にわたるポジティブな更新に続いてネガティブな更新を行うと、異なるプレフィックス長で同一の配列が生成される可能性があります。 セグメント ツリーは時間の経過に伴う操作寄与の正確な合計を集計するため、比較メカニズムではそれらが等しいものとして扱われ、そのためすべてのインデックスにわたって正味の差がゼロとなり、誤った順序付けではなく等価性が得られます。
