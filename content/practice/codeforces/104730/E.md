 ## 解決策
 ## 問題の理解

 都市のセットは固定されていますが、都市間の道路網は時間の経過とともに変化します。 各「時点」は、同じ一連の都市に関する異なる無向グラフを表しており、そのようなスナップショットは最大 200,000 件あります。 

また、タイム ジャンプの固定シーケンスも与えられます。 都市 1 から開始すると、すぐにそのシーケンスの最初の瞬間に移動します。 各タイム ジャンプの後、移動が許可されますが、それはごくわずかです。ある時点に到着したとき、次のタイム ジャンプが発生するまでに、その瞬間に存在する道路を最大 1 つ横断することができます。 次に、シーケンス内の次の瞬間にジャンプすることを強制され、そこで再び最大でも 1 つのエッジを横断することになります。 

目標は、タイム ジャンプの使用回数を考慮して、都市 1 から開始して都市 n にできるだけ早く到達することです。 時刻のシーケンスは固定されているため、「最も早い」とは、各ステップでオプションで現在のグラフのちょうど 1 つの端に沿って移動できることを尊重しながら、シーケンスの最小のプレフィックスを使用することを意味します。 

出力は、都市 1 から都市 n に移動する、瞬間ごとに最大でも片エッジ移動の有効なシーケンスが存在するために必要なタイム ジャンプの最小数です。そのようなシーケンスが存在しない場合は -1 です。 

この制約は、エッジとタイム ステップの総数にわたって、ほぼ線形または線形演算処理が必要であることを意味します。 瞬間間のすべてのエッジの合計は最大 200000 であり、k も最大 200000 であるため、どちらの次元でも二次関数は直ちに不可能になります。 完全なグラフに対する単純なステップごとの BFS や、各時点での到達可能性を最初から再計算するのは遅すぎます。 

微妙な問題は、状態は単なる都市ではなく、私たちが費やしたタイムジャンプの回数を暗黙的に含んでいることです。 ただし、動きは厳しく制限されています。連続する 2 つの瞬間の間では、1 つのエッジのみを横切ることができます。 これにより、各タイム ステップは、任意のマルチステップのトラバースを許可するのではなく、階層化されたグラフ内の単一の「レイヤー」のように機能します。 

よくある間違いは、接続されたコンポーネントを短時間で完全に横断できると考えることです。 これは誤りです。なぜなら、各瞬間に許可されるエッジは 1 つだけだからです。 もう一つの間違いは、同じ都市を別の時間に再訪することが重要であるということを無視することです。 より早く都市にいることは、将来のさまざまなシングルエッジの動きをアンロックすることができます。 

## アプローチ

 強引なアイデアは、各州を現在の都市と現在の時間インデックスで構成されるペアとして扱うことです。 各状態から、その場に留まるか、現在のグラフの一方の端に沿って移動して、次の瞬間に進むことができます。 これにより、最大 O(nk) 状態のグラフが自然に形成されます。 各状態は、その時点の隣接関係に応じて多くの隣接状態に遷移します。 各エッジが瞬間ごとに 1 回考慮されたとしても、合計の遷移は O(∑m_i · k) となり、制限をはるかに超えています。 

重要な点は、各都市に到着できる最適な時間を保存する必要がないということです。 時間は増加するだけで遷移は単調であるため、時間瞬間を順番に処理し、各都市について、許可されたシングルエッジ移動を実行した後に到達可能になる最も早い瞬間を維持できます。 

各時点 i で、その時点の開始時に到達可能なすべての都市を取得します。 このような各都市から、モーメント i のグラフ内の最大 1 つのエッジをトラバースすることができます。これは、単一の BFS のような拡張ステップで近隣を緩和することを意味しますが、深さは 1 層だけです。 次に、結果のセットを次の瞬間に繰り越します。 これは本質的に、一連のグラフ全体にわたる到達可能性の動的な伝播であり、各グラフは 1 ステップの拡散を可能にします。 

重要な構造は、各瞬間内で完全な BFS ではなく、1 つの緩和波のみを実行するということです。 これにより、すべての瞬間にわたる合計作業量がエッジの数に比例することが保証されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース状態グラフ | O(nk + ∑m_i・k) | O(nk) | 遅すぎる |
 | 逐次ワンステップ伝播 | O(∑m_i + k) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各時刻の後にどの都市に到達できるかについてのブール値またはキューベースの表現を維持します。 

1. ブール配列を初期化する`cur`サイズは n で、都市 1 のみが到達可能とマークされています。 これは、最初の瞬間に入る直前に私たちが立つことができる場所を表しています。 
2. 1 から k までの各時点 i に対して、新しい配列から開始します。`nxt`すべて false に初期化されます。 この配列は、瞬間 i で最大 1 つのエッジを使用した後に到達可能な都市を表します。 
3. 瞬間 i のグラフ内のすべてのエッジ (u, v) について、u または v が現在到達可能かどうかを確認します。`cur`。 If u is reachable, mark v as reachable in`nxt`。 v が到達可能な場合は、u を到達可能としてマークします。`nxt`。 これは、許可される 1 ステップのトラバースをシミュレートします。 
4. また、現在到達可能なすべてのノードを前方にコピーします。ノードが到達可能な場合は、`cur`、この時点では移動せずにそこに留まることがまだ有効であるため、これもマークする必要があります。`nxt`。 
5. 瞬間 i のすべてのエッジを処理した後、都市 n が到達可能かどうかを確認します。`nxt`。 「はい」の場合は、i を出力して終了します。 
6. それ以外の場合は設定します`cur = nxt`そして次の瞬間に続きます。 

モーメントごとに隣接リストを構築するのではなくエッジを直接処理する理由は、すべてのモーメントにわたる合計エッジが制限されているため、それらを直接反復することが最適であるためです。 

### なぜ効果があるのか

 重要な不変条件は、瞬間 i を処理した後、`cur[v]`は、一連の有効なタイム ジャンプが存在し、i 秒後に都市 v で終了するエッジ トラバースが瞬間ごとに 1 つまで存在する場合にのみ true になります。 

遷移ステップでは、以前に到達できたすべての位置をコピーすることによって保存されます。`cur`の中へ`nxt`、そして、現時点で到達可能な頂点から 1 つのエッジによって到達できる頂点を正確に追加します。 瞬間ごとに複数のエッジを許可することはなく、瞬間ごとに 1 つの緩和ステップを正確に適用するため、無効なマルチステップ パスが導入されることはありません。 逆に、有効なパスはすべて、各瞬間に 0 または 1 つのエッジを選択することに対応している必要があるため、この緩和プロセスによってキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, t = map(int, input().split())

graphs = []
for _ in range(t):
    m = int(input())
    edges = []
    for __ in range(m):
        u, v = map(int, input().split())
        edges.append((u - 1, v - 1))
    graphs.append(edges)

k = int(input())
a = list(map(int, input().split()))

cur = [False] * n
cur[0] = True

for i in range(k):
    nxt = cur[:]  # staying in place is allowed

    edges = graphs[a[i] - 1]

    for u, v in edges:
        if cur[u]:
            nxt[v] = True
        if cur[v]:
            nxt[u] = True

    if nxt[n - 1]:
        print(i + 1)
        sys.exit(0)

    cur = nxt

print(-1)
```この実装は、階層化された伝播のアイデアに直接準拠しています。 重要な詳細は初期化中です`nxt`のコピーとして`cur`、各時点での「動きなし」オプションをエンコードします。 

各タイム モーメントはエッジ リストのみを使用し、完全な隣接構造を構築することはありません。これにより、不必要なオーバーヘッドが回避されます。 

時刻を昇順にスキャンし、最小のプレフィックス長が必要なため、都市 n が到達可能になるとすぐに答えが出力されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(∑m_i + k・n) のワーストケースは、更新がまばらであるため、実際には O(∑m_i + k) に簡略化されます。 各エッジはその瞬間の発生ごとに 1 回処理され、各瞬間に O(n) 個のコピーが実行されます。 
| スペース | O(n + ∑m_i) | 現在の到達可能性とすべてのエッジ リストを保存します。 

この制約により、∑m_i ≤ 200000 および k ≤ 200000 が保証されるため、解は入力サイズが線形であり、時間とメモリの両方の制限内に快適に収まります。

 ## 特殊なケース

 エッジ ケースの 1 つは、都市 1 がすでに都市 n と等しい場合ですが、制約によって n ≥ 2 が保証されているため、このようなことは発生しません。 

もう 1 つのケースは、どの瞬間にもエッジが存在しない場合です。 アルゴリズムは維持します`cur`すべてのステップにわたって変更されないため、都市 n が到達可能になることはなく、出力は正しく -1 になります。 

より微妙なケースは、パスがすべてのグラフの結合に存在するが、同時に 2 つのエッジを必要とする場合です。 たとえば、1-2 と 2-3 は同じ瞬間にのみ存在します。 その時点の処理後は 1 ステップの拡張のみが許可されるため、アルゴリズムは正しく失敗し、3 に到達しません。
