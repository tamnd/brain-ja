 ## 解決策
 ## 問題の理解

 私たちは一列に並んだ座席を与えられ、左から右へ昇順にラベルが付けられています。 がある$m$座席、そして$nm$人々、しかしそれ以来$n = 1$、長さの行は 1 つだけです$m$正確に含む$m$合計で人。 

各人には、可視性をどの程度重視するかを表す値があります。 値が小さいほど、より良い座席を確保する必要があることを意味し、座席番号のインデックスが低くなります。 正式には、ある人が他の人よりも視力値が厳密に小さい場合、その人には厳密に小さい座席指数が割り当てられなければなりません。 

人は同時に座ることはありません。 順番に入場していきます$1$に$m$、そしてそれぞれが席から自分の列に沿って歩きます$1$指定された席まで。 すでに占有されている席を通過するたびに、不便さは 1 つ増加します。 

タスクは、これらの歩行中に横切る占有座席の総数を最小限に抑えながら、視覚値によって引き起こされる順序制約を尊重して座席を割り当てることです。 

制約$n = 1$構造を大幅に簡素化します。 私たちは基本的に人々を単一の立場の配列に並べ替えていますが、その価値観によって決まる単調性の制約があります。 

すべてのテスト ケースにわたる入力サイズは最大です。$10^5$したがって、どのような解決策も大まかに次のようにする必要があります。$O(m \log m)$テストケースごとにそれ以上です。 歩行をシミュレートしたり、すべての割り当てを試したりする二次アプローチは、一度実行すると遅すぎます。$m$各取り決めにはすでに必要なため、数千に達します$O(m)$、そして動的配置内の反転を列挙またはシミュレートすると、$O(m^2)$行動。 

多くの人が同じ視覚値を共有している場合、微妙な特殊なケースが発生します。 その場合、彼らの間で任意の順序で座席を割り当てることができます。 値のみでソートし、等しいグループを考慮せずに厳密に左から右に割り当てる単純な貪欲型では、実装によっては誤って固定順序や過大カウントまたは過少カウントの反転を想定してしまう可能性があります。 

## アプローチ

 ブルートフォース戦略では、視覚値による並べ替えを考慮した席への人々の有効な割り当てをすべて試行します。 割り当てごとに、着席プロセスをシミュレートし、座席の左側に既に配置されている人数を各人ごとに確認することで、不便さの合計を計算します。 並べ替えと一致する割り当てに限定したとしても、同じ値の要素を並べ替える方法はまだたくさんあり、各割り当てのコストをシミュレートすることができます。$O(m)$。 これにより、多くの値が等しい場合、最悪の場合には階乗動作が発生します。 

重要な単純化は、2 つの効果を分離することです。 まず、順序制約により、視覚値が降下しない順序で人物を処理する必要があります。 第 2 に、割り当て順序が固定されると、座席によってもたらされる不便さは、その左側に以前に割り当てられた座席の数とまったく同じになります。 これは、以前に割り当てられたポジションが現在のポジションよりも小さい数を数えるのと同等であり、反転に似た量です。 

これで、構造がより明確になります。要素を 1 つずつ 1 行に配置し、各配置はその左側にすでに占有されている位置の数に寄与します。 この合計を最小限に抑えるために、早期の割り当てが将来のブロックを最小限に抑える位置を占めるようにしたいと考えています。 具体的には、処理が早い（値が小さい）人をできるだけ左に配置する必要がありますが、値が等しい場合は柔軟性があります。 

これは古典的な貪欲な順序になります。視覚値で人々を並べ替え、昇順に座席を割り当てますが、同じ値の中から順序を慎重に選択する必要があります。 正しい方法は、等しい値のグループを処理し、それらを任意の順序で割り当てることですが、以前に割り当てられた座席の左側の数を使用してそれらの寄与を計算することです。 これは、ポジションに対するフェンウィック ツリーを使用して、どの座席がすでに占有されているかを追跡することで維持できます。 

並べ替えた人々を繰り返し処理し、選択した座席ごとに、その前に占有されている座席の数を数えます。 これは、動的セットに対する標準のプレフィックス合計クエリです。

 ## アルゴリズムのチュートリアル

 1. すべての人々を視力値によって降順でない順に並べ替えます。 

これにより、ある人の値が他の人よりも小さい場合、その人が最初に処理され、昇順に座席を選択すると、より小さい座席インデックスが与えられます。 
2. 2 つの操作をサポートする座席位置に関するデータ構造を維持します。1 つは座席を占有済みとしてマークし、指定された位置の厳密に左側にある占有座席の数をカウントすることです。 

対数時間でのプレフィックス合計をサポートしているため、シートの配列に対するフェンウィック ツリーで十分です。 
3. ソートされた順序で人物を反復処理します。 お一人様ごとに座席をお選びください。 

将来の混雑を最小限に抑えたいため、制約内で左から右に座席を処理します。 実際には、同じ値のグループ間でインデックスの昇順に座席を割り当てます。 
4. 選択した各座席のインデックスについて$s$、範囲内で占有されている座席の数をフェンウィック ツリーにクエリします。$[1, s]$。 

この値は、以前に占有されていたすべての座席がその経路上にあるため、現在の人が通過しなければならない人の数を正確に表します。 
5. このカウントを解答とマークシートに追加します$s$フェンウィックの木に占領されているように。 
6. すべての人が割り当てられるまで続行します。 

微妙な点は、コストは各挿入前の占有位置の最終セットにのみ依存し、人々のアイデンティティには依存しないことです。 値による順序付けにより実現可能性が保証され、左から右への配置により将来の不必要なプレフィックス密度が最小限に抑えられます。 

### なぜ効果があるのか

 いつでも、人をその位置に配置することによって生じる不便さ$s$すでに占有されているポジションの数に等しい$[1, s]$。 これは将来の配置とは独立しているため、以前の選択が行われると、各ステップの貢献度が固定されます。 

視覚価値によって分類すると、後で制約によって価値の小さい人が価値の大きい人よりも悪い立場に強制されることがなくなります。 等しい値の範囲内では、割り当ての交換は制約に違反しないため、任意の順序で自由に処理できます。また、貪欲な左から右への処理により、シートのプレフィックスに不必要な初期の密度が作成されることが回避されます。 

フェンウィック ツリーは、各クエリが現在占有されているプレフィックス構造を正確に反映するという不変条件を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        # pair (value, original index)
        arr = [(a[i], i + 1) for i in range(m)]
        arr.sort()

        ft = Fenwick(m)
        ans = 0

        # assign seats in sorted order of values
        for _, pos in arr:
            # inconvenience = number of occupied seats to the left
            ans += ft.sum(pos)
            ft.add(pos, 1)

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、座席インデックスにフェンウィック ツリーを構築します。 各人は入力内の元の位置で表され、この縮小では座席インデックスとして扱われます。 値による並べ替えにより割り当て順序の有効性が保証され、フェンウィック ツリーに各位置を挿入すると、その前に以前に割り当てられた座席の数が累積されます。 

肝心の操作は、`ft.sum(pos)`、左側または現在のインデックスにある占有席の数をカウントします。 追加するだけで削除はしないため、構造は進化するプレフィックス密度を明確に追跡します。

## 特殊なケース

 すべてのサイトの値が等しい場合、並べ替えによって意味のある構造は強制されません。 このアルゴリズムは純粋にインデックス順に基づいて座席を割り当てます。新しい座席は常にソートされた順序で追加されるため、以前の座席がその左側に配置されることはなく、不便は生じません。 

値が入力順序で厳密に減少している場合、並べ替えによって割り当て順序が完全に逆になります。 ソート後もすべての位置がインデックスの昇順で挿入されるため、ここでも新しく割り当てられたシートの左側に以前に占有されていたシートは存在せず、合計はゼロに保たれます。 

インデックスの非自明なインターリーブを強制する方法で値が交互に配置される場合、フェンウィック ツリーは、以前に選択されたインデックスが各挿入の左側にいくつあるかを正確にカウントします。 各ステップの寄与はアクティブなプレフィックスの数と一致しており、データ構造が行の進化する輻輳を正確に追跡していることが確認されます。
