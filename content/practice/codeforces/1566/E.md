 ## 解決策
 ## 問題の理解

 頂点 1 にルートを持つルート付きツリーが与えられます。 

頂点に子がない場合、頂点はリーフになります。 頂点がルートではなく、少なくとも 1 つの子を持ち、そのすべての子が葉である場合、頂点は芽です。 

操作により芽が選択され、芽サブツリー全体が構造内で 1 レベル上に移動します。 より正確には、芽はその葉の子をすべて保持しますが、現在の親との接続は削除され、他の有効な頂点への接続に置き換えられます。 

この操作によって、芽サブツリーの内部構造が変更されることはありません。 唯一変わるのは、その芽がどこに付くかだけです。 

私たちの目標は、一連の操作を構築することではありません。 任意の数の操作を実行した後、必要なのは最小限の葉だけです。 

ツリーには以下が含まれます$2 \cdot 10^5$すべてのテスト ケースにわたる頂点。 任意の再ハングをシミュレートしたり、考えられる操作シーケンスを検索しようとするソリューションは、直ちに絶望的になります。 二次アルゴリズムでも約$4 \cdot 10^{10}$最悪の場合の運用。 ツリーのサイズが本質的に線形であるものが必要です。 

難しいのは、許可された操作がグローバルに見えることです。 つぼみはほぼどこにでも移動できます。 一見すると、さまざまなツリー構成について推論する必要があるように思えます。 重要な観察は、再吊り下げの正確な目的地はほとんど無関係であるということです。 重要なのは、どの頂点を最終的に寄与するリーフから「除去」できるかということです。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

頂点が 2 つだけあるツリーを考えてみましょう。```
1
|
2
```入力：```
1
2
1 2
```唯一の非ルート頂点はすでにリーフです。 全く蕾がありません。 答えは 1 です。 

すべての内部構造がさらに変形できると仮定したソリューションでは、誤って 0 が生成されます。 

ここで次のことを考えてみましょう。```
    1
   /
  2
 / \
3   4
```入力：```
1
4
1 2
2 3
2 4
```頂点 2 は芽です。 別の場所に移動すると、頂点 3 と 4 は葉のままになります。 答えは 1 ではありません。つぼみ自体を取り外し可能なものとして扱うことは、答えを過小評価することになります。 

もう 1 つの微妙なケースはチェーンです。```
1 - 2 - 3 - 4 - 5
```入力：```
1
5
1 2
2 3
3 4
4 5
```唯一の葉は頂点 5 です。いかなる操作も葉の数を 1 未満に減らすことはできません。芽のカウントのみに基づいた式はここでは失敗します。 

正しい解決策では、操作によって吸収できる葉と根本的に避けられない葉を区別する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、到達可能な各ツリー構成を状態として扱います。 すべての状態から、現在の芽をすべて列挙し、考えられるすべての目的地を試し、新しい木を生成し、最小数の葉を検索します。 

あらゆる法的な操作シーケンスが調査されるため、これは理論的には正しいです。 問題は状態空間です。 木には多くの芽が含まれており、各芽はほぼすべての頂点に移動できます。 到達可能な構成の数は指数関数的に増加します。 数十頂点であっても検索は不可能になります。 

画期的な進歩は、操作が実際に何を達成するかを観察することから生まれます。 

芽は頂点であり、その子はすべて葉です。 その芽が動かされても、その子供たちはそれに執着したままになります。 この操作では、これらのリーフを直接作成したり破棄したりすることはありません。 実際の影響は親側にあります。 芽を切り離すと、元の親が葉になったり、新しい芽になったりすることがあります。 

これは、特定の再ハングについて考えるのをやめ、代わりに最適な最終構成でどの頂点が生き残るかを特徴付ける必要があることを示唆しています。 

重要な観察は、根以外のすべての芽は、その下のすべての葉とともに最終的に考慮から「削除」される可能性があるということです。 ツリーを下から上に処理すると、すべての最大芽サブツリーは単一ユニットのように動作します。 

驚くほどシンプルな DFS が登場します。 

頂点を再帰的に分類してみましょう。 

頂点に子がない場合、それはリーフになります。 

内部頂点の場合、すべての子孫が処理された後、一部の子がすでに芽で「覆われている」可能性があります。 すべての子がそのような覆われた構造に属している場合、この頂点自体が芽になり、同様に覆うことができます。 

根は特別で、芽になることはありません。 

最終的な答えは次のようになります。$$\text{leaves} - \text{buds}$$ここで、葉は元の葉をすべてカウントし、芽はこのボトムアップ プロセスによって特定された根以外の頂点をすべてカウントします。 

DFS は両方の量を線形時間で計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適な DFS | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### DFS 状態

 すべての頂点について、すべての子孫が処理された後にそれが芽になるかどうかを計算します。 

させて`bud[v]`この性質を表します。 

### ステップ

 1. ツリーを頂点 1 にルートし、DFS を実行します。 
2. ルートツリーに頂点に子がない場合、それは元のリーフです。 葉のカウンターを増やします。 
3. 頂点のすべての子を処理した後`v`、つぼみではない子供の数を数えてください。 
4. もし`v`が根ではなく、すべての子がすでに芽になっているか、芽以外の子が残っていない場合、`v`それ自体が芽になります。 
5. 頂点が芽になるたびに、芽カウンターが増加します。 
6. DFS が完了したら、次のように出力します。$$\text{leaf\_count} - \text{bud\_count}$$### なぜ効果があるのか

 重要な不変条件は、芽が子孫からの未解決の葉の寄与をすべて完全に吸収することです。 

リーフは、不可避のリーフを 1 つカウントに加えます。 親が芽になると、その芽サブツリー内のすべての葉の寄与を単一の可動構造にマージできます。 このような構造は後で最適に取り付けることができ、最終的な答えに独立して寄与する必要はありません。 

DFS は、この役割を果たすことができる頂点を正確に識別します。 発見された芽ごとに、最終合計から 1 枚の葉の寄与が削除されます。 つぼみは下から上に向かって処理されるため、取り外し可能な構造が見逃されることはなく、2 回カウントされることもありません。 

芽の定義では根が芽であることが明示的に禁止されているため、根は除外されます。 

その結果、各芽は避けられない葉の数をちょうど 1 つ減らし、次の式が得られます。$$\text{answer} = \text{leaves} - \text{buds}$$## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())

        g = [[] for _ in range(n + 1)]

        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        leaves = 0
        buds = 0

        def dfs(v, p):
            nonlocal leaves, buds

            child_count = 0
            non_bud_children = 0

            for to in g[v]:
                if to == p:
                    continue

                child_count += 1

                if not dfs(to, v):
                    non_bud_children += 1

            if child_count == 0:
                leaves += 1
                return False

            if v != 1 and non_bud_children == 0:
                buds += 1
                return True

            return False

        dfs(1, 0)
        print(leaves - buds)

if __name__ == "__main__":
    solve()
```DFS は、現在の頂点が芽になるかどうかを示すブール値を返します。 

葉っぱは見つけやすいです。 DFS によって生成されたルート付きツリーでは、子のない頂点が元のリーフになります。 数えて返す`False`葉は芽ではないからです。 

内部頂点の場合、その子によって返された状態を調べます。 すべての子が既に芽として分類されている場合、現在の頂点は再帰芽条件を満たします。 芽としてマークして返します`True`。 

ルートは芽であることが定義で明示的に禁止されているため、特別な処理が必要です。 すべてのルートの子が芽である場合でも、頂点 1 は芽カウンターに寄与しません。 

よくある間違いは、すべての子が元のツリーの葉であるかどうかをテストしてしまうことです。 芽のステータスは、子孫がすでに処理された後に計算する必要があります。 再帰的定式化はこれを自動的に処理します。 

再帰では各エッジを各方向に 1 回ずつ、正確に 2 回訪問するため、実装は線形のままです。

 | 測定 | 複雑さ | 説明 |

        g = [[] for _ in range(n + 1)]

                return True

            return False
