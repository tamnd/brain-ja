 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、それを任意の数の連続する部分に分割できます。 すべてのキャラクターは正確に 1 つの作品に属している必要があります。 

各部分について、その MEX を計算します。 文字列にはのみが含まれているため、`0`そして`1`、可能な値は次の 3 つだけです。 

| 作品内容 | メキシコ |
 | --- | --- |
 | 含まれていません`0`| 0 |
 | 含まれています`0`でもいいえ`1`| 1 |
 | 両方が含まれています`0`そして`1`| 2 |

 私たちの目標は、すべてのピースの MEX 値の合計ができるだけ小さくなるようにカットを選択することです。 

すべてのテスト ケースの合計の長さは最大でも$10^5$。 つまり、線形時間に近い解が期待できるということです。 二次アプローチでは次のことが必要になります$10^{10}$限界をはるかに超えた最悪の場合の動作。 

難しいのは、カットがどのような場合に効果的で、どのような場合に痛みを伴うのかを理解することです。 

文字列を考えてみましょう`1111`。 文字列全体に含まれるのは次のとおりです`1`s、つまりその MEX は`0`。 答えは`0`。 常により多くの部分を作成しようとするソリューションでは、これを見逃してしまいます。 

文字列を考えてみましょう`0000`。 文字列全体に含まれるのは次のとおりです`0`s、つまりその MEX は`1`。 答えは`1`。 それをいくつかのすべてゼロの部分に分割すると、MEX が得られます。`1`各ピースごとに合計が増加するだけです。 

文字列を考えてみましょう`01010`。 文字列全体には両方の数字が含まれるため、その MEX は次のようになります。`2`。 不用意に観察すると、両方の数字を含むすべての文字列に答えがあると思われるかもしれません。`2`。 それは誤りです。 次のようにカットできます`0 | 1010`、与える`1 + 1 = 2`、しかし、これ以上のことはできません。 

ここで考えてみましょう`100001`。 文字列全体に MEX が含まれています`2`、しかし次のようにカットします`1 | 0000 | 1`与える`0 + 1 + 0 = 1`。 答えは次のようになります`1`。 なぜこれが起こるのかを理解することが、問題を理解するための重要な鍵となります。 

## アプローチ

 ブルートフォース ソリューションでは、考えられるすべてのカット位置セットを試します。 長さの文字列$n$もっている$n-1$切断の可能性のある場所を示し、各場所に切断が含まれる場合と含まれない場合があります。 それは与える$2^{n-1}$パーティション。 

各パーティションについて、すべての部分の MEX を計算し、最小合計を維持できます。 これはすべての有効な回答を調べるため正しいですが、$n=50$、ましてや$10^5$。 

パターンを見つけるために、何がプラスのコストに寄与するのかを見てみましょう。 

のみを含む任意の作品`1`s は MEX を持っています`0`, そのような作品は無料です。 

少なくとも 1 つを含む作品`0`少なくとも費用がかかる`1`。 

これは、私たちが本当に気にする文字はゼロだけであることをすぐに示唆しています。 

たとえば、すべてのゼロが単一の連続したブロックに属していると仮定します。`111000111`。 ゼロブロックを分離し、それをすべて 1 つのピースで囲むことができます。`111 | 000 | 111`費用は`0 + 1 + 0 = 1`。 

ここで、文字列に 2 つの別々のゼロ ブロックがあるとします。たとえば、`0011100`。 

2 つのゼロ グループは、それらの間に 1 があるため、1 つのすべてゼロの部分にマージすることはできません。 選択肢は 2 つあります。 

両方の数字を含む 1 つのピースを作成し、支払いを行うことで、すべてをまとめておくことができます。`2`。 

または、両方のゼロ グループを分離することもできます。`00 | 111 | 00`どの費用がかかりますか`1 + 0 + 1 = 2`。 

いずれにしても答えは`2`。 

この観察は問題を完全に特徴づけています。 

If there are no zeros at all, the answer is`0`。 

連続するゼロのブロックが 1 つだけ存在する場合、答えは次のようになります。`1`。 

ゼロブロックが 2 つ以上ある場合、答えは次のようになります。`2`。 

これより大きいものはありません`2`常に最適です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. バイナリ文字列を読み取ります。 
2. 連続したブロックの数を数えます。`0`文字列に現れます。 
3. ゼロブロックの数が`0`、出力`0`。 

文字列全体は次のもので構成されます`1`s なので、文字列全体が MEX になります。`0`。 
4. ゼロブロックの数が`1`、出力`1`。 

そのゼロブロックを、ゼロのみを含む 1 つの部分に分離できます。 残りのピースはすべて 1 のみを含み、コストはゼロです。 
5. ゼロブロックの数が少なくとも`2`、出力`2`。 

少なくとも 2 つの別個のゼロ グループが存在します。 これらは 1 で区切られているため、単一のすべてゼロの部分にマージすることはできません。 可能な限り最高のコストはまさに`2`。 

### なぜ効果があるのか

 重要な特性は、ゼロを含むすべての部分が少なくとも貢献するということです。`1`答えに。 

文字列に 1 つのゼロ ブロックが含まれている場合、すべてのゼロを 1 つのすべてゼロの部分の中に入れることができ、合計コストが計算されます。`1`。 

文字列に複数のゼロ ブロックが含まれている場合、2 つの可能性があります。 いくつかの 1 と 0 を一緒に保持して、MEX が次のような部分を作成することもできます。`2`、またはゼロブロックを分離して支払います`1`関連する作品ごとに。 どちらの戦略でもコストは達成できます`2`そしてどのような戦略もコストを達成することはできません`1`なぜなら、単一のオールゼロのピースは複数の分離されたゼロブロックをカバーできないからです。 

したがって、答えはゼロブロックの数のみに依存します。$$\min(2,\text{number of zero blocks})$$ゼロブロックがゼロに等しいと答えが生成されるという特殊な場合`0`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        s = input().strip()

        blocks = 0
        n = len(s)

        for i in range(n):
            if s[i] == '0' and (i == 0 or s[i - 1] == '1'):
                blocks += 1

        ans.append(str(min(blocks, 2)))

    sys.stdout.write("\n".join(ans))

solve()
```この実装では、連続するゼロ セグメントのみがカウントされます。 

新しいゼロブロックは、`0`前の文字が存在しないか、または等しい`1`。 この条件により、各ゼロランの最初の文字が識別されます。 

ゼロブロックの数がわかれば、答えは簡単です。`min(blocks, 2)`。 このコンパクトな公式はすべてのケースを自然にカバーしています。 

もし`blocks = 0`、結果は`0`。 

もし`blocks = 1`、結果は`1`。 

もし`blocks >= 2`、結果は`2`。 

追加の処理は必要ありません。
