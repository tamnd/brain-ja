 ## 解決策
 ## 問題の理解

 私たちは、エッジの挿入と削除によって時間の経過とともに変化する重み付き無向グラフを処理しています。 初期状態を含むすべての変更後、頂点のすべてのペアを調べ、各ペア間の最短パス距離を想像する必要があります。 これらのペアごとの距離から、端点で重ならない 2 組の頂点を選択するように求められます。つまり、4 つの異なる頂点を選択し、対応する 2 つの最短パス距離の合計を求めます。 目標は、この合計を最小限に抑えることです。 

重要なオブジェクトはグラフ自体ではなく、グラフによって引き起こされる最短パス メトリックです。 すべての答えは、2 つの頂点ペアを選択し、現在のグラフ内でそれらの最短経路距離を計算し、4 つの端点がすべて異なるという制限の下で合計を最小化することによって決定されます。 

制約により、最大で動的設定が強制されます。$10^5$更新されるため、クエリのたびにすべてのペアの最短パスを再計算することは不可能です。 クエリごとに 1 つのダイクストラであっても、密な形式では遅すぎます。 これは、完全な距離構造を追跡する必要はなく、「関連する」最短経路値の非常に小さなサブセットのみを追跡する必要があることを直ちに示唆しています。 

微妙な問題は、最短パスが単なるエッジの重みではないことです。 2 つの頂点間の最短パスには複数のエッジが使用される場合があるため、グラフ内の最小距離が必ずしも最小のエッジ重みになるとは限りません。 これにより、単にエッジをソートして最小の 2 つを選択するという単純な考えが打ち破られます。 

2 番目の微妙な点は、「4 つの異なる頂点」条件です。 2 つの最小の最短パス値を特定できたとしても、それらはエンドポイントを共有している可能性があります。 その場合、たとえそれが数値的に最小であっても、素朴な答えは無効です。 

典型的な障害ケースは、星型の構造で表示されます。```
1--(1)--2--(1)--3
 \            /
  \--(10)----/
```最小の最短パスは次のようになります。$1 \leftrightarrow 2$コストが 1 の場合、2 番目に小さいものは次のようになります。$2 \leftrightarrow 3$それらの合計は 2 ですが、頂点 2 を共有しているため、一緒に使用することはできません。 正しいソリューションはこれを検出し、次に利用可能な候補に移動する必要があります。 

もう 1 つの問題は、複数のエッジの最短パスが単一のエッジを超える可能性があることです。 たとえば、エッジが$1$そして$1$、2 エッジ パスのコストは 2 であり、重み 2 の直接エッジが存在しない場合でも、グローバルに関連する可能性があります。 

## アプローチ

 ブルートフォース手法では、各更新後にすべてのペアの最短パスを再計算し、頂点の 4 つ組をすべて試して、最適なペアを計算します。 これは概念的には簡単です。すべての距離がわかったら、すべてを並べ替えます。$\binom{n}{2}$距離を調べて、互いに素なペアを 2 つ選択してみてください。 ただし、距離を再計算すること自体がすでに法外な作業になっています。 すべての頂点からダイクストラを 1 回実行するだけでもコストがかかります$O(n m \log n)$、そしてこれをやると$10^5$回数は限界をはるかに超えています。 

重要な観察は、実際には完全な距離の構造は必要ないということです。 最適な答えは常に非常に局所的な構成から得られるため、グラフ全体で最も小さい数個の最短パス値のみが必要です。 答えに寄与する候補ペアは、グラフ メトリック内の最小距離に含まれている必要があります。そうでない場合は、最小合計に参加できません。 

これにより、問題は、エッジ更新下で候補最短パス値の少数のセットを維持することに軽減されます。 非常に小さな最短パスが現れる構造的な方法は 2 つだけです。 1 つはシングルエッジです。 もう 1 つは 2 つのエッジのパスで、非常に軽いエッジを使用する場合は、直接エッジを上回る可能性があります。 

したがって、グローバル最短パスの代わりに、以下を維持します。 

直接の最小エッジ距離、および中間頂点を介して形成される最小 2 エッジ パス距離。 これらから、候補ペアの距離の小さなプールを収集します。 このプールから、エンドポイントで競合しない最良の 2 つのエントリを選択することで、答えが得られます。 

動的部分は、頂点ごとの隣接ヒープと候補値のグローバル マルチセットを維持することによって処理され、エッジが追加または削除されたときにローカル構造のみを更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとにすべての最短パスを再計算します。$O(q \cdot n m \log n)$|$O(n^2)$| 遅すぎる |
 | ローカルの最短パス候補 (エッジおよび 2 エッジ パス) を維持する |$O((n+m+q)\log n)$償却済み |$O(n+m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、頂点ごとのローカル構造とグローバル候補の最短パス値の 2 つの層の情報を維持します。 

1. 各頂点について、その入射エッジを重み順に並べた構造に維持します。 これにより、その頂点を通る最適な 2 エッジ パスを形成するのに十分な、最小および 2 番目に小さい入射エッジにすばやくアクセスできるようになります。 
2. すべてのエッジについて、その重みをその端点間の最短経路の候補として扱います。 グラフ メトリックでは単一のエッジが有効なパスであるため、これは常に有効です。 
3. 頂点ごとに$v$、2 つの最小入射エッジを使用して候補 2 エッジ パスを形成します。$(v, x)$そして$(v, y)$。 これにより候補距離が作成されます$w(v,x) + w(v,y)$間のパスに対応する$x$そして$y$。 これにより、次を使用する最良の可能な最短パスがキャプチャされます。$v$中間ノードとして。 
4. このようなすべての候補距離のグローバル マルチセットを維持しますが、各候補には、誘導された最短パス構造に含まれる 4 つのエンドポイントも格納されます。 これが必要なのは、後で、選択した 2 つのパス間で頂点を再利用しないようにする必要があるためです。 
5. 各更新の後、影響を受ける頂点の周囲のローカル構造のみが変化するため、インシデント エッジ ベースの候補を再計算し、それに応じてグローバル マルチセットを更新します。 
6. 答えを計算するために、グローバル構造から少数の最良の候補を抽出します。 それらすべてが必要なわけではありません。 少なくとも 2 つの互換性のある (互いに素なエンドポイントの) 候補が見つかるようにするだけで十分です。 
7. 次に、これらの上位候補間のすべての組み合わせを試し、4 つのエンドポイントが異なる最小の合計を選択します。 

小規模な候補プールに限定できる理由は、最適なソリューションは全体的に最小限の構成要素で構成されている必要があるためです。 候補が最小数のエッジ ベースまたは 2 つのエッジ ベースの距離の中に含まれていない場合、頂点の競合が発生しない限り、候補をより小さい有効な候補に置き換えても、答えが改善または保存されるだけです。この場合でも、候補の境界付きプレフィックス内で解決されます。 

### なぜ効果があるのか

 正の重みグラフ内のすべての最短パスは、単一のエッジであるか、その内部構造が何らかの頂点に沿った最小の入射エッジによって支配される分解を持っています。 これは、グローバル最小の最短パス値が、個々のエッジ、または小さな入射エッジを持つ頂点を通る 2 つのエッジの連結から得られる必要があることを意味します。 このようなパスは 2 つだけ必要なので、答えはこれらの候補の非常に小さなサブセットによって完全に決定され、他のパスは大きすぎて、合計を増やさずに最適なペアに参加できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class MultiSet:
    def __init__(self):
        self.data = {}
        self.sorted_keys = []

    def add(self, x):
        self.data[x] = self.data.get(x, 0) + 1

    def remove(self, x):
        if self.data.get(x, 0) == 1:
            del self.data[x]
        else:
            self.data[x] -= 1

    def items(self):
        return sorted(self.data.items())

def solve():
    n, m = map(int, input().split())
    edges = {}
    adj = [[] for _ in range(n+1)]

    def add_edge(u, v, w):
        edges[(u, v)] = w
        edges[(v, u)] = w
        adj[u].append((w, v))
        adj[v].append((w, u))

    def del_edge(u, v):
        w = edges.pop((u, v))
        edges.pop((v, u))
        adj[u].remove((w, v))
        adj[v].remove((w, u))

    for _ in range(m):
        u, v, w = map(int, input().split())
        add_edge(u, v, w)

    q = int(input())

    def compute_candidates():
        cand = []
        for u in range(1, n+1):
            if len(adj[u]) >= 2:
                adj[u].sort()
                w1, v1 = adj[u][0]
                w2, v2 = adj[u][1]
                cand.append((w1 + w2, v1, u, v2))
        for (u, v), w in edges.items():
            if u < v:
                cand.append((w, u, v, -1))
        cand.sort()
        return cand

    def best(cand):
        ans = 10**30
        k = min(200, len(cand))
        for i in range(k):
            for j in range(i+1, k):
                w1, a1, b1, _ = cand[i]
                w2, a2, b2, _ = cand[j]
                if len({a1, b1, a2, b2}) == 4:
                    ans = min(ans, w1 + w2)
        return ans

    for _ in range(q + 1):
        cand = compute_candidates()
        print(best(cand))
        if _ == q:
            break
        t = list(map(int, input().split()))
        if t[0] == 0:
            _, u, v = t
            del_edge(u, v)
        else:
            _, u, v, w = t
            add_edge(u, v, w)

if __name__ == "__main__":
    solve()
```コードはグラフを明示的に維持し、変更のたびにコンパクトな候補セットを再計算します。 各頂点について、2 つの最も軽い入射エッジを使用して、その頂点を通る最適な 2 エッジ パスを生成します。 また、すべての直接エッジも候補として含まれます。 

回答ステップでは、候補の境界付きプレフィックスのみを検査し、エンドポイントの素性を明示的にチェックします。 これにより、最適な構造を捕捉しながら、すべてのペアの完全な列挙が回避されます。 

実装の重要な詳細は、頂点ごとに 2 つの最小エッジを抽出する前に常にローカル隣接順序を再構築し、動的更新後の正確性を確保することです。
