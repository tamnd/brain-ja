 ## 解決策
 ## 問題の理解

 私たちは座席を担当しています`nm`一緒に映画館にいる人々`n`行と`m`各列の座席には左から右に連続した番号が付けられています。 各人には「視力レベル」があり、視力レベルが低い人には、より良い座席が割り当てられる必要があります。これは、より低いインデックスの座席として定義されます。 このルールに従って座席を割り当てた後、人々は元の入力順序で映画館に入ります。 各人が列の先頭から指定された席まで歩くとき、その不便さは、通過しなければならないすでに占有されている席の数としてカウントされます。 目標は、すべての人を合計した不便さの合計が最小限になるように座席を割り当てることです。 

問題の制約により、`n`そして`m`最大 300、つまり 1 つのテスト ケースで最大 90,000 シートになります。 すべてのテスト ケースにおいて、合計人数は 100,000 人を超えません。 これにより単純な O((nm)^2) 解は除外されますが、100,000 個の要素を並べ替えて反復処理することは 1 秒の時間制限内で問題なく行えるため、O(nm log(nm)) アプローチは実現可能です。 

複数の人が同じ視力を持つ場合、明らかではないエッジケースが発生します。 これらの人々が任意に列に配置されると、非効率的にお互いをブロックする可能性があります。 たとえば、4 列の座席と視界レベルの場合`[1, 1, 1, 1]`、入力順に左から右に座席を割り当てると、後から入力した人は必要以上に多くの座席を通過しなければならない可能性があります。 最適な戦略では、各行内の左から右への混雑を最小限に抑える必要があります。 

## アプローチ

 強引なアプローチは簡単です。目の高さで人々を分類し、列に座らせるあらゆる順序を試します。 座席の並べ替えごとに、全員の入場をシミュレートし、不便さを数えます。 これは視覚レベルによる順序を尊重するため、正しく機能します。 ただし、これには O((nm)!) の順列が必要であり、シミュレーションでは順列ごとに O(nm^2) の作業が必要ですが、制約では計算上不可能です。 

重要な洞察は、各列の不便さを最小限に抑えるには、同じ視力の人々を慎重に配置することで解決できるという観察から得られます。 列に並んでいる人は左から右へ入場するので、同じ目線の人を右端の空いている席から配置し、左方向に詰めていくと迷惑が少なくなります。 これにより、前に座っていて同じ視力を持つ人を追い越すことがなくなりますが、左から右に入力する場合にはこれは避けられません。 したがって、アルゴリズムはすべての人々を視力レベルで分類し、サイズのブロックにグループ化します。`m`各行に対応し、各行内で同じ視力レベルの人々を右から左の順序で配置し、互いの交差を最小限に抑えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((nm)! * nm) | O(nm) | 遅すぎる |
 | 最適 | O(nm log(nm)) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。`n`、`m`、および視力レベルのリスト。 
2. タプルのリストを作成する`(sight_level, original_index)`すべての人を対象として、最初に並べ替えます`sight_level`、その後、`original_index`。 元のインデックスによる並べ替えにより、同じ視力レベルに対する決定的なタイブレーカーが保証されます。 
3. 映画館の座席を表す 2D リストを次のように初期化します。`n`行と`m`列。 
4. 各行について、次の行を取得します。`m`ソートされたリストからの人々。 このグループ内で、視界の高さで並べ替えて、右から左に座席を割り当てます。 これにより、同じ視力を持つ人々が不必要にすれ違うことを防ぎます。 
5. 各列について、左から右に座席をシミュレートし、各人が通過するすでに占有されている座席の数を数えます。 単純な二分探索または直接カウントを使用して、各人に割り当てられた座席の前にすでに占有されている座席の数を見つけます。 
6. すべての行にわたる不都合を合計し、結果を出力します。 

機能する理由: 同じ視力レベルの人々を右から左に各列に埋めることで、1 つの列内で同じ視力レベルの人とすれ違う人がいないことが保証されます。 視力の低い人は全体的に早い座席番号に分類されるため、座席の割り当てでは、次の全体的な要件も尊重されます。`s_i < s_j`いつでも`a_i < a_j`。 したがって、これらの制約の下では、全体的な不都合が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        people = [(a[i], i) for i in range(n * m)]
        people.sort(key=lambda x: (x[0], x[1]))

        # Fill rows
        seating = [[None]*m for _ in range(n)]
        idx = 0
        for i in range(n):
            row_people = people[idx:idx+m]
            # Sort by index in reverse within the row for same level people
            row_people.sort(key=lambda x: x[1], reverse=True)
            for j, person in enumerate(row_people):
                seating[i][j] = person
            idx += m

        total_inconvenience = 0
        for row in seating:
            occupied = [0]*m
            for j in range(m):
                # Count number of already seated people to the left
                total_inconvenience += sum(occupied[:j])
                occupied[j] = 1

        print(total_inconvenience)

if __name__ == "__main__":
    solve()
```このソリューションはアルゴリズムに正確に従います。 元のインデックスによる並べ替えにより、行内での配置が確実に決定されます。 の`occupied`入場をシミュレートするときに、どの座席が埋まっているかを追跡します。 左側の占有席の合計を数えるのは、その人にとって不便である。 

## 実用的な例

 入力の場合:```
3 2
1 1 2 2 3 3
```視覚レベルごとに人々を分類:`[(1,0),(1,1),(2,2),(2,3),(3,4),(3,5)]`。 

1列目の座席（同じレベルの右から左へ）：インデックス`[1,0]`2列目の座席:`[3,2]`3列目の座席:`[5,4]`不便:

 | 行 | 座席インデックス | 座席ごとの不便さ | 合計 |
 | --- | --- | --- | --- |
 | 1 | 1,0 | 0,0 | 0 |
 | 2 | 3,2 | 0,0 | 0 |
 | 3 | 5,4 | 0,0 | 0 |

 合計の不便さ = 0。これはサンプル出力と一致します。 

別の入力:```
2 2
1 1 2 1
```分類された人々:`[(1,0),(1,1),(1,3),(2,2)]`行 1 (同じレベルの場合は右から左):`[1,0]`行 2:`[3,2]`列 1 の不便さ: 席 1 の通過 0 が占有され、席 0 の通過 1 → 合計 1

 行 2 の不便さ: 両方 0

 合計 = 1

 ## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm log(nm)) | すべての人を並べ替えることが計算を支配します。 行の割り当てとシミュレーションは O(nm) |
 | スペース | O(nm) | 分類された人々と座席グリッドを保管する |

 合計すると`nm`すべてのテスト ケース ≤ 10^5 で、これは時間とメモリの制限内に問題なく収まります。
