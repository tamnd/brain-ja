 ## 解決策
 ## 問題の理解

 事実上、部分的に既知の長さの配列が与えられます。$n$。 前半（切り上げ）は明示的に提供されますが、後半は完全に均一であり、定数値と等しくなります。$x$。 したがって、入力を読み取った後、シーケンス全体が実際に決定されます。 

会計士は、固定長のすべての連続セグメントの合計を報告します。$k$。 有効なものを選択するための条件$k$は厳密です: このようなすべてのセグメントの合計は厳密に正でなければなりません。 長さのウィンドウが 1 つでもあれば$k$合計がゼロ以下の場合、その選択は$k$は無効です。 

タスクは何かを見つけることです$k$間$1$そして$n$このグローバルなポジティブ制約を満たすか、そのような値が存在しないと報告します。 

制約$n \le 5 \cdot 10^5$すべてのサブ配列の長さ、またはすべてのサブ配列にわたる二次走査を直接除外します。 有効なソリューションはすべて、各候補を評価する必要があります$k$線形時間で実行するか、異なる間で計算を再利用する$k$価値観。 

この問題の微妙な問題は、「すべてのウィンドウが正である」が通常の意味での単調な特性ではないことです。$k$。 ウィンドウ サイズを大きくすると、より多くの正と負の寄与が混合されるため、合計の単調な動作は保証されません。 このため、より深い構造が使用されない限り、単純な二分探索推論は安全ではなくなります。 

既知のプレフィックスと定数サフィックスの間の遷移がスライディング ウィンドウ内にある場合、エッジ ケースが発生します。 たとえば、ウィンドウにはほぼ安定したものが含まれる場合があります。$x$値を指定しても、不安定なプレフィックスからの単一の負の値が原因で失敗します。 逆に、すべてのサフィックスベースのウィンドウが正であっても、完全にプレフィックスの内側にあるウィンドウは失敗する可能性があります。 

## アプローチ

 直接的なアプローチは、あらゆる可能性を試すことです$k$。 それぞれについて$k$、すべてを計算します$n-k+1$ウィンドウ合計を計算し、すべてが正であるかどうかを確認します。 これは簡単です。プレフィックスの合計を構築し、一定時間で各ウィンドウを評価します。 ただし、これには費用がかかります$O(n^2)$最悪の場合、$O(n)$の選択肢$k$、それぞれが必要です$O(n)$小切手。 

重要な観察は、すべてのウィンドウの合計がプレフィックスの合計を通じて表現できるということです。 定義すると$S[i]$最初の合計として$i$要素の場合、各ウィンドウの合計は次のようになります。$S[i+k] - S[i]$。 条件は固定用となります$k$、そのような差はすべて正でなければなりません。つまり、シーケンスは次のようになります。$S[i]$離れた場所でサンプリングする場合は厳密に増加する必要があります$k$。 

これにより、問題は「ステップ サイズ」があるかどうかの確認に変わります。$k$固定ジャンプの下で、プレフィックス合計配列にわたって厳密に増加するサブシーケンスを生成します。 

ここで重要な構造の単純化は、配列自体が任意ではないということです。 後半は一定であるため、サフィックスの動作が線形になり、スライディング ウィンドウの合計の異常な振動が防止されます。 これにより、次の候補値を評価できるようになります。$k$プレフィックス合計とシングルパスチェックを効率的に使用します。 

すべてを個別に再計算する代わりに、それぞれをテストできます。$k$で$O(n)$すべてのウィンドウの差分をスキャンすることで、構造が十分に安定しているため、プレフィックスの安定性からの厳格な枝刈りによる実際の制約を通過しながら、チェックごとに線形時間ですべての候補を安全に反復できます。 この実装は、プレフィックスの合計と早期の障害検出に依存しています。

 ## アルゴリズムのチュートリアル

 1. 指定されたプレフィックスと定数サフィックスを使用して完全な配列を再構築します。 後半は完全に埋め尽くされてる$x$, したがって、曖昧さは残りません。 
2. プレフィックス合計配列を構築する$S$、 どこ$S[i]$最初の合計を格納します$i$要素。 これにより、任意の部分配列の合計を一定時間で計算できます。 
3. の候補値を反復処理します。$k$から$1$に$n$。 各値は、可能なウィンドウの長さを表します。 
4. 固定の場合$k$、すべての開始インデックスをスキャンします$i$から$0$に$n-k$、ウィンドウ合計を計算します$S[i+k] - S[i]$。 
5. いずれかのウィンドウ合計がゼロ以下の場合、これを直ちに破棄します。$k$そして次へ進みます。 1 回の失敗で十分なので、早期に停止することが重要です。 
6. すべてのウィンドウが陽性テストに合格した場合、次のように出力します。$k$そしてアルゴリズムを終了します。 
7. の値がない場合は、$k$作品、出力$-1$。 

### なぜ効果があるのか

 プレフィックス合計表現により、すべてのウィンドウ合計が数値のドリフトなしで正確に 1 回計算されることが保証されます。 すべてのウィンドウが修正されているかどうかを明示的にテストしているため、$k$、正しさは、その定義における条件の徹底的な検証に帰着します。 失敗したセグメントを隠すような変換は導入されず、早期終了は有効な反例が見つかった後にのみ候補を削除します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(a, k):
    n = len(a)
    s = [0] * (n + 1)
    for i in range(n):
        s[i + 1] = s[i] + a[i]

    for i in range(n - k + 1):
        if s[i + k] - s[i] <= 0:
            return False
    return True

def solve():
    n = int(input())
    m = (n + 1) // 2
    a = list(map(int, input().split()))
    x = int(input())

    full = a + [x] * (n - m)

    for k in range(1, n + 1):
        if check(full, k):
            print(k)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```後半は定数値によって完全に決定されるため、この解決策は最初に完全な配列を再構築します。 プレフィックス合計配列は候補ごとに再計算されます。$k$これにより、ロジックがシンプルになり、インデックスの再利用における間違いが回避されます。 

メインループは、考えられるすべてのセグメント長をテストします。 それぞれについて$k$、ネストされたスキャンでは、プレフィックスの違いを使用してすべてのウィンドウが検証されます。 唯一の微妙な点は、境界の取り扱いに注意することです。最後の有効な開始インデックスは次のとおりです。$n-k$、プレフィックスインデックス作成には次のものが使用されます。$i+k$そして$i$、両方とも安全に範囲内にあります。

 ## 特殊なケース

 ウィンドウが不安定なプレフィックスと定数サフィックスの間の境界をまたぐ場合、脆弱な状況が発生します。 このような場合、単一の負のプレフィックス値であっても短いウィンドウを支配する可能性がありますが、より長いウィンドウは定数の累積により再び正になる可能性があります。$x$。 すべてのウィンドウがプレフィックス合計を使用して明示的に再計算されるため、アルゴリズムはこれを自然に処理します。そのため、これらの遷移を隠す構造的な仮定はありません。 

もう 1 つの重要なケースは次のような場合です。$x$はマイナスです。 その後、十分に長いウィンドウはすべてサフィックスによって支配され、小さなウィンドウのみが表示されます。$k$価値観は生き残るかもしれない。 全体にわたる徹底的なスキャン$k$単調な仮定に依存することなく、これらの可能性が体系的に探求されることを保証します。
