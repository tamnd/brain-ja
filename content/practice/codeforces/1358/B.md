 ## 解決策

 ## 問題の理解

 私たちには、群衆の規模に関する個人的な要件を持つおばあちゃんのコレクションが与えられました。 マリアは中庭で一人で始め、徐々に何人かを招待したいと考えています。 おばあちゃんにはそれぞれ閾値がある$a_i$つまり、彼女が現れた瞬間に、少なくとも$a_i$他のおばあちゃんもすでに出席しています（マリアも「他の人」の一人として数えます）。 

重要な問題は、マリアが複数のおばあちゃんを同時に招待することができ、彼ら全員が入場の瞬間に中庭の同じスナップショットを観察することです。 したがって、グループの決定は、すでに内部に存在するグループと追加されるグループの合計サイズによって決まります。 

課題は、マリアが招待状の順序とグループ分けを自由に選択できることを前提として、最終的に招待できるおばあちゃんの最大数を決定することです。 

入力サイズの制約が十分に大きいため、テスト ケースごとの線形計算より悪い解は危険です。 まで$10^5$テスト全体にわたるおばあちゃんの合計、$O(n^2)$すべてのサブセットを試すシミュレーションや反復的な貪欲なスキャンは遅すぎます。 私たちが目指すべきは、$O(n \log n)$または、ソートとシングルパスを含む可能性が高い、より優れた戦略。 

しきい値の大きなおばあちゃんが多数のしきい値の小さなおばあちゃんと並んで存在する場合、微妙な特殊なケースが発生します。 たとえば、あるおばあちゃんが最終的な群衆のサイズをほぼすべて必要とする場合、正しく延期されない限り、彼女は単純に貪欲なアプローチをブロックする可能性があります。 もう 1 つの特殊なケースは、すべての値が より大きい場合です。$n$, この場合、最小の要件さえ満たされないため、マリア以外の誰も参加できません。 

## アプローチ

 強引な解釈としては、おばあちゃんをグループに招待するすべての可能な方法をシミュレートすることです。 どの段階でも、現在中に何人いるのかがわかっているので、現在のサイズにサブセットのサイズを加えたものによって制約が満たされる残りのおばあちゃんのサブセットを試します。 これはすぐに組み合わせになります。各サブセットの選択は他のすべての選択に依存し、グループ化の可能性が指数関数的に高まります。 

これをより構造化して考える方法は、最初はグループ化を無視し、最終的な順序に焦点を当てることです。 すべてのおばあちゃんをある順序で並べることができたら、$k$- 番目のおばあちゃんが入ります、まさにそこにいます$k$彼女の前のおばあちゃんとマリア。 それで彼女は見る$k$その他（マリアは常に存在するため）。 つまり、条件は位置に対する制約になります。つまり、位置におばあちゃんが配置されます。$k$の場合は有効です$a_i \le k$。 

これにより、各位置がしきい値を満たすように配置できるグラニーの可能な最大のプレフィックスを選択するという問題が軽減されます。 最善の戦略は、より柔軟でプレフィックス サイズを増やすのに役立つため、より簡単なグラニー、つまり要件が小さいものを最初に優先することです。 

ソートにより、最小の要件から順にポジションを貪欲に割り当てることができます。 私たちはすでに配置したおばあちゃんの数のカウンターを維持しており、彼女の要件が現在達成可能な群衆のサイズを超えていない場合は、おばあちゃんを含めます。

 ## アルゴリズムのチュートリアル

 1. 配列をソートする$a$降順ではない順に。 これにより、常に最も寛容なおばあちゃんを最初に考慮することが保証され、全体的により多くの人が適合する可能性が最大化されます。 
2. カウンタの初期化`cnt = 1`、中庭に一人でいるマリアを表しています。 このカウンターは、マリアを含めた場合に現在中に何人のおばあちゃんがいるかを追跡します。 
3. ソートされた配列を最小の要件から最大の要件までたどります。 おばあちゃんごとに$a_i$、現在の群衆のサイズを考慮して彼女が参加できるかどうかを確認してください。 
4. もし$a_i \le cnt$, そうすれば、このおばあちゃんも安全に含めることができます。 増加`cnt`中庭にさらに 1 人追加することに成功したため、1 人ずつ増えます。 
5. もし$a_i > cnt$、彼女を永久にスキップします。 配列はソートされているため、後のおばあちゃんにはさらに大きな要件または同等の要件が必要になるため、この位置には収まりません。 
6. すべてのおばあちゃんを処理した後、出力します`cnt`、これにはすでにマリアが含まれています。 

### なぜ効果があるのか

 いつでも、`cnt`マリアを含む中庭内の実行可能な人数を表します。 ソートにより、おばあちゃんを配置しようとするときに、残っている最小の制約が常に考慮されるようになります。 おばあちゃんを現在のサイズで配置できない場合は、すでにスキップされた大きなサイズを再配置しても、以前の割り当てに違反することなく彼女を適合させることができます。 この構築では、すべての位置がしきい値を満たす、可能な最大のプレフィックスを貪欲に構築します。これは、達成可能な最終的なグループ サイズの最大値に直接対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        a.sort()
        
        cnt = 1  # Maria
        
        for x in a:
            if x <= cnt:
                cnt += 1
        
        out.append(str(cnt))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、要件リストを並べ替えることから始まり、常に最も要求の少ないおばあちゃんに最初に対応できるようにします。 変数`cnt`マリアだけから始めて、中庭にいる現在の人数を追跡します。 

これを繰り返すと、現在の群衆のサイズで要件が満たされるおばあちゃんが見つかるたびに、すぐに彼女を含めてサイズを増やします。 将来のおばあちゃんを満足させるのは難しいだけなので、この貪欲な受け入れは安全です。したがって、実現可能なおばあちゃんを遅らせても実現可能性は決して向上しません。 

最終的な値は、`cnt`にはすでに Maria が含まれており、必要な出力定義と一致します。

 ## 特殊なケース

 重要なエッジケースは、すべてのしきい値が利用可能なおばあちゃんの数よりも大きい場合です。 たとえば:

 入力:```
3
10 10 10
```並べ替えてもまだ残っています`[10, 10, 10]`。 マリアはから始まります`cnt = 1`。 すべての値は 1 より大きいため、どれも受け入れられず、最終的な答えは 1 のままです。アルゴリズムは、不可能な包含の試みを正しく回避します。 

もう 1 つのエッジ ケースは、多くの小さな値が早期に出現し、カスケード効果が可能になる場合です。 たとえば:

 入力:```
4
1 1 1 1
```ソートされた配列は変更されません。 各ステップは条件を満たしているため、`cnt`これは、受け入れられた各おばあちゃんが厳密にキャパシティを増加させ、それによって連鎖反応が成功することを示しています。
