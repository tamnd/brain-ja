 ## 解決策
 ## 問題の理解

 私たちは、ジェラルドがすべて同じものを 3 着購入する最も安い方法を見つけるように求められました。 各衣類アイテムには価格があり、一部のアイテムには一致するものとしてマークが付けられています。 入力により、アイテムの総数、価格、および一致するペアのリストが得られます。 出力は、完全に接続された一致するトリプルを形成する 3 つの項目の最小合計である必要があります。そのようなトリプルが存在しない場合は -1 になります。 

この問題は当然グラフ問題として解釈できます。 各衣類アイテムはノードであり、一致する各ペアは無向エッジです。 ジェラルドは、このグラフで三角形を見つけたいと考えています。すべての三角形の中で、ノードの重み (価格) の合計が最小のものを探します。 

制約を考慮すると、`n`最大 100 まで上げることができ、`m`最大 n(n-1)/2、つまりグラフが密になる可能性があります。 と`n`これほど小さい場合は、ノードのトリプルをすべてチェックするソリューションが実現可能です。 ただし、冗長な計算を行わずに、トリプルが三角形を形成するかどうかを効率的にチェックするように注意する必要があります。 

微妙なエッジ ケースは、項目がちょうど 3 つあるのに、そのすべてが一致しない場合です。 例えば、`n=3`エッジは 2 つだけ存在します。有効なトリプルを形成することはできず、答えは -1 でなければなりません。 別のエッジ ケースは、複数のトリプルが存在するが、その 1 つに非常に高価なアイテムが含まれている場合に発生します。 単なる三角形ではなく、最小和を持つトリプルを見つけなければなりません。 

## アプローチ

 単純なアプローチは強引です。3 つの項目のすべての組み合わせを検討し、一致するリストに 3 つのペアすべてが存在するかどうかを確認します。 これは正しいですが、確認が必要です`O(n^3)`トリプル、およびトリプルごとに 3 つのエッジの存在を検証します。 と`n=100`、`n^3`は 1,000,000 ですが、2 秒の制限を考慮すると許容範囲です。 

もう少し効率的なアプローチは、各ノードのセットに隣接情報を保存することです。 次に、トリプル候補については、`(i, j, k)`、エッジかどうかを一定時間で検証できます。`(i, j)`、`(i, k)`、 そして`(j, k)`存在する。 これにより、元のエッジのリストでの繰り返し検索によるオーバーヘッドが軽減されます。 

重要な点は、この問題は O(n^3) 回の反復を許容できるほど小さいため、複雑なグラフ アルゴリズムは必要ないということです。 隣接セットを使用するとエッジ チェックが簡素化され、i<j<k を繰り返すことで、同じトリプルが複数回考慮されることがなくなります。

 | --- | --- | --- | --- |
 | 隣接リストを使用したブルート フォース トリプル チェック | O(n^3) | O(n^2) | 承認済み |
 | 隣接セットを使用したブルート フォース トリプル チェック | O(n^3) | O(n^2) | 受け入れられ、よりシンプル |

 ## アルゴリズムのチュートリアル

 1. アイテム数を読み取る`n`と一致するペアの数`m`。 各アイテムの価格リストをお読みください。 
2. 各ノードの隣接関係セットを構築し、どの項目と一致するかを保存します。 これにより、O(1) エッジ チェックが可能になります。 
3. 変数を初期化する`min_sum`非常に大きな数に設定すると、有効なトリプルの最小合計が追跡されます。 
4. すべてのトリプルを反復処理します。`(i, j, k)`そのような`0 <= i < j < k < n`。 これにより、トリプルが繰り返されず、すべての組み合わせが考慮されることが保証されます。 
5. 各トリプルについて、3 つのエッジすべてが隣接セットに存在するかどうかを確認します。`i-j`、`i-k`、`j-k`。 存在する場合は、その価格の合計を計算します。 
6. この合計が以下の場合`min_sum`、 アップデート`min_sum`。 
7. すべてのトリプルをチェックした後、次の場合は`min_sum`更新されましたので、印刷してください。 それ以外の場合は、有効なトリプルが存在しないことを示すために -1 を出力します。 

機能する理由: このアルゴリズムは、考えられるすべてのトリプルを体系的に考慮し、一致するグラフ内で三角形を形成するトリプルのみを受け入れます。 最小額を維持することで、結果が最も安価な組み合わせとなることが保証されます。 隣接セットは高速エッジ ルックアップを保証するため、冗長な計算を行わずにすべての有効なトリプルが正しく識別されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
prices = list(map(int, input().split()))

# adjacency sets for fast edge lookup
adj = [set() for _ in range(n)]
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].add(v)
    adj[v].add(u)

min_sum = float('inf')
for i in range(n):
    for j in range(i+1, n):
        if j not in adj[i]:
            continue
        for k in range(j+1, n):
            if k in adj[i] and k in adj[j]:
                total = prices[i] + prices[j] + prices[k]
                if total < min_sum:
                    min_sum = total

print(min_sum if min_sum != float('inf') else -1)
```このソリューションは、まず価格とエッジを読み取り、隣接情報をセットに保存します。 3 回の反復により、重複した組み合わせがないことが保証され、3 つのエッジすべての存在が一定時間内にチェックされます。 使用する`float('inf')`初期として`min_sum`これにより、有効なトリプルが存在しないことを確実に検出できるようになります。
