 ## 解決策
 ## 問題の理解

 私たちは電車の予定時刻を与えられました。 各駅ごとに`i`、時刻表によれば、電車は時間通りに到着するはずです`a[i]`そして定刻に出発`b[i]`。 

悪天候により駅間の移動に遅れが発生します。 セグメントごとに追加の遅延がわかっています`tm[i]`。 駅からの実際の所要時間`i - 1`駅まで`i`は次のようになります:$$(a_i - b_{i-1}) + tm_i$$と`b[0] = 0`。 

電車は駅に到着してもすぐに出発するとは限りません。 出発時刻は 2 つの要件を満たす必要があります。 

まず、電車は少なくとも一定時間駅に留まらなければなりません。$$\left\lceil \frac{b_i-a_i}{2} \right\rceil$$時間単位。 

第二に、出発予定時刻より前に出発することはできません。`b[i]`。 

タスクは、最終駅への実際の到着時間を決定することです。 

制約は非常に小さいです。 テスト ケースは最大 100 個あり、テスト ケースごとにステーションは最大 100 個あります。 たとえ$O(n^2)$ソリューションは簡単に適合しますが、各ステーションは前のステーションにのみ依存するため、プロセス自体は当然直線的です。 

主な困難は、出発ルールを正確にシミュレートすることです。 よくある間違いは、常に次の状態のままにしてしまうことです。`max(arrival + required_stay, b[i])`終着駅も含めて。 電車が駅に到着する`n`が答えです。 駅からいつ出発しても構いません`n`。 

もう一つの微妙な点は、天井の分割です。 所要待ち時間は、$$\left\lceil \frac{b_i-a_i}{2} \right\rceil$$これは慎重に計算する必要があります。 たとえば、次の場合`a=1`そして`b=4`、区間の長さは`3`ですので、必要な滞在時間は`2`、 ない`1`。 

考慮する：```
1
1
1 4
0
```電車は時間どおりに到着します`1`。 少なくとも残る必要があるだろう`2`出発前の単位ですが、ここは終点なので、答えは単純です。`1`。 最終駅からの出発をシミュレートするソリューションでは、誤った出力が行われます。`4`。 

もう 1 つの簡単な間違いは、天井分割ではなく床分割を使用することです。```
1
2
1 4
10 11
0 0
```ステーション 1 での必要滞在時間は`ceil(3/2)=2`。 電車は～に到着します`1`、まで待ちます`4`、ステーション 2 に到着します。`10`。 

フロア分割を使用すると、わずか 1 単位の待ち時間で出発でき、間違ったタイムラインが生成されます。 

## アプローチ

 総当たりシミュレーションが駅ごとに追跡されます。 

現在時刻を追跡します。 駅に到着したら、実際の到着時間を計算します。 次に、両方の出発条件を確認して、最も早い有効な出発時刻を決定します。 終点の駅に到着するまで繰り返します。 

文字通り、説明どおりにプロセスをシミュレートしたとしても、ステーションごとの作業量は一定です。 ステーションが最大 100 個ある場合、作業の合計は、すべてのテスト ケース全体でわずか約 10,000 ステーションの更新だけです。 

重要な観察は、ステートメント内に最適化の問題が隠されていないことです。 すべての到着時間と出発時間は、前の時間によって一意に決定されます。 現在の出発時刻がわかれば、指定された旅行公式から次の到着時刻がすぐにわかります。 

させて`cur`は、前の駅からの実際の出発時刻を示します。 それでは駅到着時間`i`は$$cur + (a_i - b_{i-1}) + tm_i.$$到着後、待機ルールにより許可される最も早い出発は次のとおりです。$$arrival + \left\lceil \frac{b_i-a_i}{2} \right\rceil.$$スケジュールで許可されている最も早い出発は次のとおりです`b[i]`。 

実際の出発時間は、これら 2 つの値のうち大きい方です。 

この直接シミュレーションはすでに線形時間で実行されており、最適です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n) | お(1) | 承認済み |
 | 最適なシミュレーション | O(n) | お(1) | 承認済み |

 この問題では、プロセスが本質的に逐次的であり、すでに線形であるため、総当たりアプローチと最適アプローチは実際には同じです。 

## アルゴリズムのチュートリアル

 1.初期化`cur = 0`、ターミナルからの出発時間を表します。 
2. からのプロセスステーション`1`に`n`。 
3. 駅への実際の到着時間を計算する`i`:$$arrival = cur + (a_i - b_{i-1}) + tm_i.$$これは、声明に記載されている移動時間の計算式から直接得られます。 
4. もし`i = n`、出力`arrival`そしてやめてください。 

この問題は終点駅からの出発ではなく、終点駅への到着を求めています。 
5. 最低限必要な滞在期間を計算します。$$wait = \left\lceil \frac{b_i-a_i}{2} \right\rceil.$$整数演算では次のようになります。$$(b_i-a_i+1)//2.$$6. 滞在条件を満たす最も早い出発は次のとおりです。$$arrival + wait.$$7. 電車も直前に発車することはできません`b[i]`。 

セット$$cur = \max(arrival + wait,\; b_i).$$8. 次のステーションに進みます。 

### なぜ効果があるのか

 アルゴリズムは単純な不変条件を維持します。`cur`は常に前の駅からの実際の出発時刻です。 

この不変条件を考慮すると、ステートメントは次の駅までの移動時間を一意に決定するため、計算された到着時間は正確になります。 出発規則では、両方の条件が満たされた場合にのみ列車が出発できると定められています。 そのような最も早い瞬間は、まさに 2 つの下限の最大値です。$$arrival + wait$$そして$$b_i.$$したがって、計算された出発時刻が真の出発時刻となります。 すべての駅にわたる帰納法により、シミュレーションによって生成されるすべての到着時刻と出発時刻が実際の列車のタイムラインと一致します。 いつ駅`n`に達すると、計算された到着時間はまさに必要な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())

        a = [0] * n
        b = [0] * n

        for i in range(n):
            a[i], b[i] = map(int, input().split())

        tm = list(map(int, input().split()))

        cur = 0
        prev_b = 0

        for i in range(n):
            arrival = cur + (a[i] - prev_b) + tm[i]

            if i == n - 1:
                print(arrival)
                break

            wait = (b[i] - a[i] + 1) // 2
            cur = max(arrival + wait, b[i])

            prev_b = b[i]

if __name__ == "__main__":
    solve()
```配列`a`そして`b`スケジュールを保存します。 変数`cur`は常に、前の駅からの実際の出発時刻を保持します。これは、前に説明した不変式です。 

駅用`i`、ステートメントから旅行公式を使用して実際の到着時間を計算します。 値`prev_b`は、その式に現れる前の駅の出発予定時刻を表します。 

最もデリケートなラインは次のとおりです。```
wait = (b[i] - a[i] + 1) // 2
```これは、正の整数の上限除算を実行します。 使用する`(b[i] - a[i]) // 2`間隔の長さが奇数の場合は常に不正確になります。 

もう一つの細かい点は、終点付近の運行順序です。 到着時刻を計算した直後に、現在の駅が最終駅であるかどうかを確認します。 駅からの出発をシミュレーションすることはありません`n`、答えは到着時間そのものだからです。 

Python の整数はこの問題のすべての値を簡単に処理できるため、オーバーフローの心配はありません。

            prev_b = b[i]

    return "\n".join(out)
