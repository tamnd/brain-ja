 ## 解決策
 ## 問題の理解

 ケーキを層ごとに構築していきます。 を配置した後、`i`- 番目の層、注ぐ`a[i]`クリームの単位を上に置きます。 そのクリームは下に伸びて上を覆う`a[i]`現在存在するレイヤー。 以下の場合は、`a[i]`レイヤーごとに、既存のすべてのレイヤーがカバーされます。 

各層について、少なくとも 1 回のクリーム操作で覆われているかどうかを決定する必要があります。 出力は、下から上に並べられた 0 と 1 の配列です。 の値`1`層がびしょ濡れであることを意味しますが、`0`乾燥したままであることを意味します。 

すべてのテスト ケースにわたるレイヤーの合計数は最大で`2·10^5`、これは線形解には十分小さいですが、二次解には大きすぎます。 注入操作ごとに影響を受けるすべての層を検査する方法では、約`n²`最悪の場合は動作します。 と`n = 2·10^5`、これは約 400 億の操作を意味し、制限時間をはるかに超えています。 

誤って対処しやすい状況がいくつかあります。 

1 つのケースは、クリームの量が既存の層の数を超える場合です。 

入力：```
1
4
5 0 0 0
```最初の操作で既存のすべてのレイヤーがすでにカバーされているため、答えは次のようになります。```
1 0 0 0
```最下層より下のレイヤーにアクセスしようとする不注意な実装により、無効なインデックスが生成される可能性があります。 

もう 1 つの注意が必要なケースは、間隔が重複している場合に発生します。 

入力：```
1
6
0 3 0 0 1 3
```正しい答えは、```
1 1 0 1 1 1
```複数のクリーム操作で一部の層を繰り返しカバーしますが、1 つの層をカバーする必要があるのは 1 回だけです。 すべての操作を個別にシミュレートすると時間の無駄になります。 

3つ目はクリームを注がない場合です。 

入力：```
1
3
0 0 0
```答えは```
0 0 0
```以前のカバレッジが終了するはずだった後に誤って伝播すると、一部のレイヤーには、操作が到達していないにもかかわらず、カバーされたものとしてマークされる可能性があります。 

## アプローチ

 最も直接的な解決策は、すべての注入操作を処理し、影響を受けるレイヤーを明示的にマークすることです。 私たちが位置にいるとき`i`層からクリームが届く`i`下向きに`a[i]`ポジション。 これらのレイヤーを反復処理して、カバー済みとしてマークを付けることができます。 

影響を受けるすべてのレイヤーが少なくとも 1 回はアクセスされるため、このアプローチは正しいです。 この問題は、多くの値が大きい場合に発生します。 たとえば、すべての場合、`a[i] = n`、最初の操作は 1 つのレイヤーにタッチし、2 番目の操作は 2 つのレイヤーにタッチするというように、おおよその結果が得られます。$$1 + 2 + \dots + n = O(n^2)$$操作。 

問題の構造は、より良い見方を示唆しています。 注入操作ごとに、覆われた層の連続セグメントが作成されます。 セグメント全体をすぐにマークする代わりに、レイヤーを上から下に処理し、アクティブなクリームの間隔内に下方向にまだ何個の位置が残っているかを覚えておくことができます。 

現在レイヤーにいると仮定します`i`そしてそこにあります`cur`上で開始したインターバルから残っているレイヤー。 次にレイヤーを重ねます`i`いつでもカバーされます`cur > 0`。 もし`a[i]`それ自体はより大きいです`cur`、から始まる新しい間隔`i`カバレッジをさらに下方に拡張するため、更新します```
cur = max(cur, a[i])
```現在のレイヤーを処理した後、レイヤーを 1 つ下に移動して、レイヤーを減らします。`cur`1つずつ。 

上から下に処理すると、多くの重複する間隔が 1 つのカウンターに変換され、線形の複雑さが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 上のレイヤーから始めて、下のレイヤーに向かって移動します。 
2. 変数を維持する`cur`は、現在のレイヤーを含め、上にあるレイヤーからのクリームで覆われている連続レイヤーの数を表します。 
3. 位置で`i`、 アップデート`cur = max(cur, a[i])`。 

新しい注入操作が以前の注入操作よりもさらに下方に到達すると、その効果が古い範囲に置き換わります。 それ以外の場合は、以前の適用範囲ですでに十分です。 
4. もし`cur > 0`、マークレイヤー`i`カバーされているように。 

正の値は、少なくとも 1 つのクリーム間隔にこの層が含まれていることを意味します。 
5. レイヤーを処理した後、減少します`cur`1 ずつ増加しますが、ゼロを下回ることはありません。 

1 ステップ下に移動すると、残りのカバレッジのレイヤーが 1 つ消費されます。 
6. 最下層に到達するまで続けます。 

### なぜ効果があるのか

 下方向にスキャンしながら、`cur`は常に、既に発生したクリーム操作によってカバーされることが保証されている、現在のレイヤーから始まる連続レイヤーの数に等しくなります。 すべての注湯操作はそれぞれの位置から始まり、正確に下方向に延長されます。`a[i]`層。 既存の値と`a[i]`現在下位層に影響を与えている最長の間隔を維持します。 減少中`cur`各ステップの後、残りの範囲から 1 つのレイヤーが正しく削除されます。 一定の間隔に到達すると、レイヤーはカバーされたとマークされるため、アルゴリズムは正しい答えを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
out = []

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    ans = [0] * n
    cur = 0

    for i in range(n - 1, -1, -1):
        cur = max(cur, a[i])
        if cur > 0:
            ans[i] = 1
        cur = max(0, cur - 1)

    out.append(" ".join(map(str, ans)))

print("\n".join(out))
```最上層が最大のインデックスに対応するため、スキャンは右から左に実行されます。 変数`cur`残りのカバレッジの深さを保存します。 レイヤーの状態を決める前に`i`その層に注がれたクリームを最大限に活かして組み込んでいます。`a[i]`。 

操作の順序が重要です。 まずは更新します`cur`、次に、現在のレイヤーがカバーされているかどうかを判断し、その後でのみ減少します。`cur`。 これらの手順を逆にすると、すべての間隔が 1 つずつ短くなり、不正確な答えが生成されます。 

への呼び出し`max(0, cur - 1)`負の値を防止します。 負の数でも条件は成立しますが、`cur > 0`false、維持`cur`非負の場合、変数の意味が正確になります。
