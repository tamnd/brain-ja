 ## 解決策
 ## 問題の理解

 私たちに与えられるのは、テニスの試合の最終試合の統計だけです: アリスが勝ちました`a`個人戦、ボリスが勝利`b`個人的なゲーム。 私たちはこれらのゲームの順序を知りませんし、誰が最初にサーブをしたのかも知りません。 私たちが知っていることは、サービスは厳密にゲームごとに切り替わるということです。 

各ゲームには指定されたサーバーがあります。 サーバーがゲームに勝った場合、それはホールドです。 レシーバーが勝てばブレークです。 タスクは、試合全体、試合シーケンスと最初のサーバーのすべての有効な再構成にわたって、考えられるすべてのブレークの合計数を決定することです。 

入力について考えるのに役立つ方法は、1 つの固定一致をシミュレートするのではなく、2 つの自由のもとで構造的に可能なものをカウントしているということです。つまり、カウントを維持しながら勝者のシーケンスを並べ替えることができます。`a`そして`b`、開始サーバーを選択できます。 すべての有効な再構成では、何らかの整数が生成されます。`k`、レシーバーが勝ったゲームの数。 

出力は、そのような達成可能なすべての値のセットです。`k`。 

この制約により、最大 1000 のテスト ケースと、それら全体で合計 200,000 のゲームが許可されます。 これにより、結果のすべての順列を列挙したり、考えられるすべてのゲームごとの割り当てをシミュレートしようとするアプローチは除外されます。 どのようなソリューションでも、理想的には一定時間内に、テスト ケースごとに問題を閉じた形式の特性評価に還元する必要があります。 

1 人のプレイヤーがすべてのゲームに勝利した場合、微妙なエッジケースが発生します。 たとえば、次の場合`a = 0`そして`b = 5`、すべてのゲームはサーブ パターンに応じて必然的にボリスまたはアリスにとってブレークになりますが、最初のサーバーの選択によって、より強いプレーヤーがサーブを行う回数が変わるため、達成可能なブレーク数のセットは依然として単一の値ではありません。 プレイヤー間の対称性を前提とする単純なアプローチでは、サーバーの起動に対するこの依存性を見逃してしまいます。 

もう 1 つの落とし穴は、休憩の数が一意に決定されると仮定していることです。`a`そして`b`。 例えば、`(2, 1)`サンプルに示すように、0 ～ 3 の範囲の異なるブレーク カウントを持つ複数の有効なシーケンスを許可します。 これは、答えが単一の計算値ではなく間隔であることをすでに示しています。 

## アプローチ

 総当りの力で問題を解決しようとすると、次のすべての順列を列挙することになります。`a + b`ゲームで各ゲームの勝者を割り当て、開始サーバーの両方の選択肢を試します。 それぞれの配置について、交互サーバー パターンをシミュレートし、受信側が勝った回数をカウントします。 これはすぐに実行不可能になります。勝者の順列の指数関数的な数を無視しても、固定カウントと一致するインターリーブが指数関数的に多く存在します。`a`そして`b`。 

重要な観察は、重要な唯一の構造は、各プレーヤーが勝利したときに何回サーブを打っているかであるということです。 勝利の順序は、カウントが一致することを保証すること以外には実現可能性に影響しません。 試合は次のシーケンスとして見ることができます。`n = a + b`アリスまたはボリスのいずれかから開始する交互サーバーでのゲームで、勝者のポジションへの割り当てを自由に選択できます。 

ブレークの数は、単純に勝者がサーバーと異なるポジションの数です。 開始サーバーを固定した場合、各ポジションのサーバー ID は固定され、アリスの勝利のうちアリスが提供するポジションに着いた数とボリスが提供したポジションに着いた数だけを決定します。 

これにより、問題は組み合わせの実現可能性の範囲の問題に集約されます。固定開始サーバーの場合、勝者とサーバー間の一致の最小数と最大数はいくらですか? 極端なケースは、勝者を有利または不利なサービングスロットに貪欲に揃えることによって達成されます。 各開始サーバーの可能な範囲を計算すると、2 つの間隔の結合によって最終的な答えが得られます。 

どちらの構造も単調であるため、達成可能なブレーク カウントのセットは連続した間隔を形成します。

 ## アルゴリズムのチュートリアル

 と表します。`n = a + b`。 

1. アリスが最初に奉仕する場合を考えてみましょう。 提供パターンは固定されます (アリス、ボリス、アリス、ボリス、というように)。 アリスが務めるポジションとボリスが務めるポジションが何人存在するかを数えてください。`n`ゲーム。 これらのカウントはパリティのみに依存します。`n`。 
2. アリスが務めているポジションの数を計算し、それを呼び出します`sa`、そしてボリスが奉仕している場所に電話してください`sb`。 アリスが最初にサーブすると、`sa = (n + 1) // 2`そして`sb = n // 2`。 ボリスが最初にサービスを提供した場合、役割が入れ替わります。 
3. ブレークは、勝利が相手のサービングポジションに置かれたときに発生します。 アリスが勝つ場合は、ボリスが提供するスロットにアリスを配置するとブレイクが生まれます。 アリスを提供するスロットにそれらを配置すると、中断を回避できます。 同じ対称性がボリスの勝利にも当てはまります。 
4. 固定スタートサーバーのブレークを最小限に抑えるために、自分のサーブに合わせて勝利数を最大化します。 これは、できるだけ多くのアリスの勝ちをアリスが担当するスロットに割り当て、できるだけ多くのボリスの勝ちをボリスが担当するスロットに割り当てることと同じです。 
5. ブレイクを最大化するために、逆の調整を行います。つまり、キャパシティーまで、対戦相手のサービングスロットに勝利を優先的に割り当てます。 
6. これにより、各開始サーバーの最小および最大ブレーク カウントが得られます。 それぞれの選択肢は、可能な値の間隔を示します。 
7. 最終的な答えは、2 つの区間 (アリス優先とボリス優先) の和集合です。 これらの間隔は重なったり接触したりするため、結合したものは再び単一の連続した間隔になります。 

### なぜ効果があるのか

 固定のサーブ パターンの場合、各ゲームは、そのポジションにサービング プレーヤーとレシーブ プレーヤーのどちらが勝利を割り当てたかにのみ応じて、独立してブレーク カウントに寄与します。 唯一のグローバル制約は、各プレーヤーが何回勝利するかということであり、これは、「良い」スロットまたは「悪い」スロットをいくつ埋めることができるかという容量の制約に変換されます。 有利なスロットから不利なスロットに勝利を交換するたびにブレーク カウントが 1 つだけ変化し、ポジション間に依存関係が存在しないため、貪欲な割り当てが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        a, b = map(int, input().split())
        n = a + b

        def interval(first_alice: bool):
            if first_alice:
                sa = (n + 1) // 2
                sb = n // 2
            else:
                sa = n // 2
                sb = (n + 1) // 2

            # minimize breaks: fill own serve first
            min_breaks = max(0, a - sa) + max(0, b - sb)

            # maximize breaks: push wins to opponent serve
            min_own = min(a, sa) + min(b, sb)
            max_breaks = n - min_own

            return min_breaks, max_breaks

        l1, r1 = interval(True)
        l2, r2 = interval(False)

        L = min(l1, l2)
        R = max(r1, r2)

        res = list(range(L, R + 1))
        out.append(str(len(res)))
        out.append(" ".join(map(str, res)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、考えられる 2 つの開始条件を分離し、それぞれについて明確な極値範囲を計算します。 重要な詳細は、「ずれ」によるブレークを表現することです。ブレークを直接追跡する代わりに、互換性のあるサーブ ポジションで何勝が着いたかを追跡します。 

最小計算では、1 人のプレイヤーが利用可能なサービング スロットよりも多くの勝利を獲得した場合に、避けられない不一致がカウントされます。 最大の計算では、正しく揃えることができる勝ちの数をカウントし、総ゲーム数から減算することで視点が反転します。 

2 つのケースが重なる可能性があるため、最後の間隔和集合を形成するときは注意が必要です。 取る`min(l1, l2)`そして`max(r1, r2)`実行可能セットが連続しており、それらの和集合も連続しているため、機能します。

 ## 特殊なケース

 いつ`a = 0`、すべての勝利はボリスに属します。 唯一の柔軟性は、注文を提供することによって得られます。 アルゴリズムは、開始サーバーに応じてボリーのすべての勝利をサーブまたはレシーブのポジションに割り当て、可能なブレークの全インターバルを生成します。 計算は正確に比較に帰着します`sb`と`b`、および無効な負のカウントは表示されません。`max(0, ...)`構造。 

いつ`b = 0`、状況は対称的です。 すべての勝利はアリスのものであり、唯一の違いは、それらの勝利のうち何個がアリスが提供するスロットに該当するかです。 間隔の計算でも、特別な分岐を必要とせずに両方の極端な値が得られます。 

いつ`a = b`、どちらのサービス パターンでも同一のスロット分布が生成されます。 このアルゴリズムは 2 つの同一の間隔を正しくマージし、実現可能な範囲全体を維持しながら二重カウントを防止します。
