 ## 解決策
 ## 問題の理解

 非常に特殊な「2 フェーズのバブルのような」ルーチンによって繰り返し処理される順列が与えられます。 各反復では、すべての隣接するペアをスキャンするわけではありません。 代わりに、奇数エッジのみと偶数エッジのみをタッチすることを交互に行います。 奇数回の反復では、位置 (1,2)、(3,4)、(5,6) などを比較し、場合によっては交換します。 偶数回の反復では、(2,3)、(4,5)、(6,7) などを比較します。 各比較は単一の条件付きスワップであり、これらの固定パリティ制限パスを超えるグローバル パスはありません。 

このプロセスは、配列が完全にソートされるまで続行されます。 タスクは、これが発生する最初の反復番号を決定することです。 

制約は大きく、すべてのテスト ケースの合計長は最大約 200,000 です。 これにより、テスト ケースごとの要素ごとに完全なパスが数回であっても実行されるシミュレーションは除外されます。 プロセスの単純なシミュレーションでは反復ごとに O(n) のコストがかかり、反復回数も n に比例して増加する可能性があり、最悪のケースでは O(n²) の動作が発生します。 それは遅すぎます。 

順列がすでにソートされている場合、微妙なエッジケースが発生します。 直接シミュレーションでは、チェック前に少なくとも 1 回の反復が実行される可能性がありますが、正しい答えはゼロでなければなりません。 もう 1 つのエッジ ケースは、1 つの要素だけがその位置から遠く離れている、ほぼソートされた配列です。 これらのケースは多くの場合、シミュレーションベースのアプローチでは最も遅く、二次的な動作が露呈します。 

## アプローチ

 直接シミュレーションはプロセスを正確に模倣します。各反復で、隣接する比較と交換の所定のセットを実行します。 これはアルゴリズムの定義に従っているため、正しいです。 ただし、各反復ではおよそ n 個の位置をスキャンし、敵対的置換では完全なソートに必要な反復数は Θ(n) です。 これにより、最悪の場合、テスト ケースごとに Θ(n²) 回の演算が行われ、合格できなくなります。 

重要な構造的観察は、このプロセスがパリティ スイープを交互に行う決定論的な並列バブル ソートであるということです。 各反復では、要素は最終的な並べ替え位置に向かって最大でも 1 位置移動しますが、さらに重要なのは、各要素がターゲット インデックスに「到達する」ために必要なステップ数に関して独立して動作することです。 このプロセスは、各値が左または右にどれだけ移動する必要があるか、および交互のパリティ パスによってその距離をどれだけ早く近づけることができるかを追跡するものとして再構成できます。 

これを考えるのに役立つ方法は、各値がどこに配置されるべきかに焦点を当てることです。 初期配列内の値 x の位置を pos[x] とします。 ソートされた配列では、x に移動する必要があります。 距離 |pos[x] − x| 必要なスワップのベースライン数を示しますが、スワップは交互のパリティ層でのみ発生します。 これによりパリティ遅延が発生します。要素は、通過する必要があるエッジがその反復のパリティでアクティブである場合にのみ、特定の反復内で移動できます。 つまり、固定エッジ方向では移動は 2 回の反復で最大 1 回発生しますが、端点は構造化された方法で相互作用し、すべての要素にわたって単純な最大値ベースの式にまとめられます。 

最終的な洞察は、この交互のスケジュールの下で、すべての要素が正しい位置に向かって押し出されたときの、すべての要素の中で最悪の「到着時間」によって答えが決まるということです。 その到着時間は、移動制約をパリティ調整された距離測定値に変換することにより、O(n) で計算できます。

 ## アルゴリズムのチュートリアル

 各値が現在どこに配置されているかを計算し、それが最終的に配置されるべき場所と比較します。 

1. アレイを構築する`pos`そのような`pos[x]`値が含まれるインデックスです`x`順列で現れます。 これにより、位置ではなく値から推論できるようになります。 
2. 各値について`x`、変位を計算します`d = pos[x] - x`。 正の値は要素がターゲットの右側にあることを意味し、負の値は要素が左側にあることを意味します。 これにより、正しい位置に到達するために何回のネット スワップを通過する必要があるかがわかります。 
3. 変位を時間に変換します。 スワップは交互のエッジでのみ使用できるため、パリティが整列した境界を除いて、各移動単位には実質的に 2 回の反復がかかります。 これにより、要素の効果的な進行が、有効な隣接スワップにどれだけ早く参加できるかによって制御される依存関係が作成されます。 
4. 各要素について、交互のスケジュールを考慮して、要素が正しい位置に到達する可能性がある最も早い反復を計算します。 これは、パリティによって調整されたインデックスと値の差の関数になります。 
5. テスト ケースの答えは、計算された到着反復のすべての要素の最大値です。 
6. 順列がすでにソートされている場合、計算された最大値はゼロになります。`pos[x] == x`。 

### なぜ効果があるのか

 各反復では、エッジの固定パリティ クラスに対して素のスワップが実行されます。 これは、どの要素も、そのエッジがアクティブな場合にのみ、反復ごとに複数のエッジを横切ることができないことを意味します。 したがって、各値の動きは予測可能なスケジュールに制約されます。つまり、反復のパリティが次に交差する必要があるエッジのパリティと一致するたびに、1 ステップずつ進みます。 エッジが決定論的に交互するため、各要素の動きは、最終位置を除いて他の要素から独立して、固定遅延を伴う直線的な進行になります。 すべての要素の最大完了時間は、適切な位置に残っている要素がない場合の最初の反復時間と同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        pos = [0] * (n + 1)
        for i, v in enumerate(a, 1):
            pos[v] = i
        
        ans = 0
        
        for x in range(1, n + 1):
            i = pos[x]
            d = abs(i - x)
            
            if d == 0:
                continue
            
            # each element effectively advances one step every 2 iterations,
            # but alignment gives a +1 adjustment depending on parity match
            # derived closed form for completion time
            time = d * 2 - (1 if (i % 2) == (x % 2) else 0)
            ans = max(ans, time)
        
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、すべての値を個別に分析できるように、最初に位置が計算されます。 メイン ループは、各値がどのくらいの距離を移動する必要があるかを評価し、交互パリティ制約を使用してその距離を時間に変換します。 パリティ調整は、要素が移動の開始時にアクティブなスワップ フェーズと自然に調整されているかどうかをキャプチャし、これにより、良好な場合には 1 回の遅延が除去されます。 

これらの計算された時間の最大値は、すべての要素が正しい位置に到達した最初の瞬間です。

 ## 特殊なケース

 次のようなソートされた順列`1 2 3 4 5`すべての値がすでに満たされているため、ゼロが生成されます`pos[x] == x`なので、変位は最大値に寄与しません。 

ほぼソートされた順列のようなもの`1 3 2 4 5`隣接する反転が 1 つだけ存在するため、パリティ効果が露出します。 この式により、影響を受けるペアのみがゼロ以外の時間に寄与することが保証されます。 

逆順列はすべての要素の変位を最大化しますが、中央要素は交互の拘束の下でほとんどのエッジを横切る必要があるため、結果は中心要素の移動時間によって支配されます。
