 ## 解決策
 ## 問題の理解

 私たちにはトンネルでつながった洞窟のグラフが与えられ、主人公はある程度の初期パワーを持って洞窟 1 から開始します。 1 つおきの洞窟には最初はモンスターがいます。 主人公の仕事は、すべての洞窟を少なくとも 1 回訪れてモンスターを倒すことです。 

それぞれの洞窟$i$(洞窟 1 を除く) にはしきい値があります$a_i$。 主人公は、彼の現在の力が厳密に次の値を超えている場合にのみ、最初に洞窟に入ったときにその洞窟のモンスターを倒すことができます。$a_i$。 倒した後、主人公のパワーが増加します$b_i$、そしてその洞窟への今後の訪問は無料です。 

動きは方向のないエッジに沿って発生します。 追加の制約があります: ヒーローがエッジを横切る場合$u$に$v$、同じエッジをすぐに横断して戻ることはできません。$v$に$u$。 これにより、些細な発振は防止されますが、他のエッジを介してノードを再訪問することは防止されません。 

目標は、すべてのモンスターを倒すことを可能にする有効な洞窟の横断順序が存在するように、最小の開始パワーを決定することです。 

グラフは接続されており、テスト全体の合計サイズは比較的小さいですが、それでも指数関数的な探索が不可能なほど十分に大きいです。 合計最大 1000 のノードと 2000 のエッジがあるため、すべてのパスまたは訪問順序の順列を列挙しようとするソリューションは実行不可能です。 平$O(n^2)$状態ごとの拡張や電力状態にわたる単純な最短パスの拡張は、検索内で繰り返されると遅すぎます。 

微妙な問題は、すべてのノードが少なくとも次数 2 を持っているため、グラフが行き止まりを強制することがないため、実際にはトラバース制限が到達可能性を有意に制限しないことです。 この制限は主に、同じエッジに沿った即時の後戻りを防止しますが、最適な戦略は、エッジの反転に依存せずにスパニング探索構造を通過するものと見なすことができます。 

いくつかの失敗例から、単純なアプローチが失敗する理由が明らかになります。 

単純な考えは、現在の電力でノード 1 から DFS を試し、到達可能な未訪問のノードに貪欲にアクセスすることです。 これは、ローカルで到達可能な洞窟が、早期に訪問するのに世界的に最適ではない可能性があるため、失敗します。 たとえば、しきい値は低いが報酬が低い洞窟は、パワーを蓄積するために早めに訪問する必要がある報酬が高い洞窟へのアクセスをブロックする可能性があります。 

もう 1 つの間違ったアプローチは、ノードを次の基準で並べ替えることです。$a_i$到達可能性を動的に確認しながら、その順序でアクセスを試みます。 到達可能性は、ソートされたしきい値だけでなく、すでにクリアされているノードとグラフ構造に依存するため、これは失敗します。 

主な問題は、ノードを訪問する順序が実現可能性 (電力制約) と将来の実現可能性 (他のノードのロックを解除する電力増加) の両方に影響することです。 これは、グラフの接続性によって制約されるグローバルな順序付けの問題です。 

## アプローチ

 強引な観点は、洞窟をクリアできるすべての可能な順序を考慮することです。 順序ごとに、接続性と電力制約を考慮して、そのシーケンスでグラフを移動できるかどうかをシミュレートします。 これは直ちに実行不可能です。$n!$順列、および 1 つの順序を検証する場合でも、グラフ到達可能性の推論が必要です。 これは一度限界をはるかに超えて成長します$n$小さな値でも超えてしまいます。 

この問題を、明示的な順序列挙を回避しながらも依存関係構造を把握できるものに縮小する必要があります。つまり、洞窟はそのしきい値が満たされている場合にのみ訪問できますが、そこを訪問するとパワーが増加し、他の洞窟のロックが解除されます。 

重要な観察は、初期パワーを固定すると、$P$、問題を到達可能性プロセスとして扱うことができます。ノード 1 から開始し、ノードに入ることが許可されます。$v$すでに訪問したノードを介して到達可能な場合のみ、$P > a_v$。 一度訪れてみると、$v$によってパワーが増加します$b_v$、より多くのノードのロックが解除される可能性があります。 

これは、修正の実現可能性チェックを示唆しています。$P$、これは最良優先の拡張プロセスとして実装できます。 現在到達可能なクリアされたノードのセットから、しきい値が満たされている隣接する未訪問のノードに拡張できます。 

However, naive BFS from the current frontier is still insufficient because reachability is not just adjacency, it depends on being able to walk through already cleared nodes. This naturally leads to maintaining a frontier of reachable cleared nodes and expanding outward, but we must ensure we never “forget” nodes that are reachable but not yet affordable.

 ここで、グラフ構造と単調性が組み合わされます。接続性の点でノードが到達可能になると、そのノードは到達可能なままになります。 唯一の動的な条件は、電力が増加するにつれてそのしきい値が満たされるかどうかです。 これにより、プロセスを、現在到達可能なノードを繰り返し選択するものとして扱うことができます。$a_i$は満足されており、それをプールに追加して到達可能性を拡張します。 

最小初期電力を効率的に決定するために、二分探索を行います。$P$。 候補者ごとに$P$では、到達可能だがまだクリアされていないノードに対する優先順位構造に基づいた貪欲な実現可能性プロセスを使用して、すべてのノードをクリアできるかどうかをシミュレーションします。 

最終的な構造は制約付き拡張プロセスに似ています。つまり、到達可能なノードのセットを維持し、その中でしきい値が満たされているノードを繰り返し取得し、その報酬を受け取り、到達可能性を拡張します。

 ## アルゴリズムのチュートリアル

 初期電力を二分探索することで問題を解決します$P$。 それぞれの推測について、すべての洞窟をクリアできるかどうかを確認します。 

1. 候補の初期パワーを固定する$P$。 洞窟 1 から開始し、訪問済みとしてマークし、現在の電力を に設定します。$P$。 洞窟 1 にはモンスターがいないため、これは有効です。 
2. グラフのエッジを介して訪問セットから到達可能であるが、まだ訪問されていないすべての洞窟の構造を維持します。 これは、隣接リストを使用して訪問ノードから拡張することによって計算されます。 
3. 到達可能なすべての未訪問の洞窟のうち、しきい値が以下の洞窟のみを考慮します。$a_i$現在の電力よりも厳密に小さいです。 現時点でクリアできる洞窟はこれらだけです。 
4. そのような洞窟はないが、到達可能な未訪問の洞窟がまだ存在する場合、プロセスはこのために停止します。$P$力不足でブロックされてしまうからです。 これは、この候補者が不合格であることを示しています。 
5. それ以外の場合は、しきい値条件が満たされている利用可能な洞窟を選択し、訪問済みとしてマークし、その報酬を追加します$b_i$現在のパワーに。 実行可能なノードを取得する有効な順序によって到達可能性の拡張が維持されるため、複数の利用可能な洞窟の中からの選択は任意に行うことができます。 この段階で必要なのは存在だけであり、最適な順序付けは必要ありません。 
6. 洞窟を訪れた後、新しいノードが到達可能になる可能性があるため、近隣の洞窟を使用してそこから到達可能なフロンティアを拡張します。 
7. すべての洞窟を訪問するか、まったく進めなくなるまで、この作業を繰り返します。 
8. すべての洞窟を訪問すると、候補者は$P$実現可能です。 そうでなければそうではありません。 

二分探索が機能するのは、実行可能性が単調であるためです。$P$すべての制約があるため、より高いべき乗も完了を許可します。$P > a_i$満足しやすくなるだけで、報酬の構造は変わりません。 

なぜ効果があるのか

 どの時点でも、アルゴリズムはすでにクリアされた洞窟から到達可能なすべてのノードのフロンティアを維持します。 唯一の制限は、現在の電力がそのしきい値を満たしているかどうかです。 ノードへのアクセスは電力を増加させるだけで、到達可能性を低下させることはないため、電力が増加するにつれて、到達可能なノードのセットは単調に増加し、手頃な価格のノードのセットも単調に増加します。 これにより、シーケンスが存在する場合、貪欲な実行可能性シミュレーションで最終的に有効な順序が見つかることが保証されます。これは、有効なソリューションであれば、将来のアクセス性を失うことなく、常に利用可能な到達可能なノードを選択するソリューションに変換できるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def can(start_power, n, g, a, b):
    visited = [False] * (n + 1)
    reachable = [False] * (n + 1)

    q = deque()
    visited[1] = True
    reachable[1] = True
    q.append(1)

    power = start_power

    # expand initial reachability from node 1
    for v in g[1]:
        reachable[v] = True
        q.append(v)

    # we maintain a deque of reachable nodes
    # but we repeatedly scan it, so we use a list as pool
    pool = set()
    for v in g[1]:
        if not visited[v]:
            pool.add(v)

    changed = True
    while True:
        progress = False

        # try to take any feasible node
        to_remove = None
        for v in list(pool):
            if not visited[v] and reachable[v] and power > a[v]:
                to_remove = v
                break

        if to_remove is None:
            break

        v = to_remove
        pool.remove(v)
        visited[v] = True
        power += b[v]
        progress = True

        # expand reachability
        for to in g[v]:
            if not reachable[to]:
                reachable[to] = True
                if not visited[to]:
                    pool.add(to)

    return all(visited[1:])

def solve_case(n, m, edges, a, b):
    g = [[] for _ in range(n + 1)]
    for u, v in edges:
        g[u].append(v)
        g[v].append(u)

    # node 1 has no monster; set dummy values
    a = [0] + a
    b = [0] + b

    lo, hi = 1, 10**18
    ans = hi

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, n, g, a, b):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        edges = [tuple(map(int, input().split())) for _ in range(m)]
        out.append(str(solve_case(n, m, edges, a, b)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装では、問題を初期電力に対する二分探索と実現可能性チェックに分離します。 

隣接リストは洞窟の接続性を表します。 配列`a`そして`b`インデックスが洞窟番号と直接一致するようにパディングされます。 機能`can`指定された始動電力が十分であるかどうかをシミュレートします。 

内部`can`、`reachable`すでに訪問したノードを介してアクセス可能になったノードを追跡します。`visited`洞窟をクリアした跡。 の`pool`には到達可能だが訪問されていないノードが含まれており、しきい値が満たされているノードを探して繰り返しスキャンします。 

ノードを選択すると、その隣接リストを使用して出力が増加し、到達可能性が拡張されます。 実行可能なノードがそれ以上存在しない場合、プロセスは停止します。 

二分探索は単調性を利用します。開始パワーが高くても、以前に有効だったシーケンスが無効になることはありません。

 ## 特殊なケース

 エッジ ケースの 1 つは、代替ブランチが存在するにもかかわらず、ノードに早期に到達可能であるが、電力が大幅に増加するまでクリアできない場合です。 このような場合、貪欲な選択は停止しているように見えるかもしれませんが、二分探索により、少なくとも 1 つの完全に成功した順序付けを可能にする初期パワーのみを受け入れることが保証されます。 

もう 1 つのエッジ ケースは、複数の決済注文が存在する対称グラフです。 このアルゴリズムは、全体的に最適な次のノードの選択には依存しません。 必要なのは、使用可能なときに少なくとも 1 つの有効なノードが常に選択されていることだけです。 到達可能性は単調でパワーは増加するだけであるため、有効なパスは常に利用可能な実行可能ノードを選択することでシミュレートでき、対称性の下でも正確性が保証されます。
