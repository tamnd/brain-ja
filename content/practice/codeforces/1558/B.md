 ## 問題の理解

 位置に配置されたトークンが与えられます$n$～とラベル付けされたセルの垂直線上$1$一番上にある$n$一番下にあります。 目標は、何回の一連の動きでトークンをもたらすことができるかを数えることです。$n$まで$1$。 

ある立場から$x > 1$、2種類の動きが許可されます。 最初のタイプは正の整数を減算します。$y$、範囲内の任意の目的地を効果的に選択できます$[1, x-1]$。 2 番目のタイプは分割します$x$整数で$z \ge 2$そしてに移動します$\lfloor x / z \rfloor$、潜在的にはるかに小さなジャンプを生成します。 パラメータのそれぞれの選択$y$または$z$複数の選択肢が同じ目的地につながる場合でも、個別の移動を定義します。 

出力は、次の異なる移動シーケンスの合計数です。$n$に$1$、剰余を取得$m$、 どこ$n$と同じ大きさにすることができます$4 \cdot 10^6$そして$m$は大きな素数です。 パスの数は指数関数的に増加するため、このスケールでは、すべてのパスを明示的に探索するソリューションは除外されます。 有効な解決策はすべて、重複する部分問題を利用し、状態をまたいで結果を再利用する必要があります。 

微妙なエッジケースは、減算によって次のことが可能になるという事実から生じます。$y = x - 1$に直接移動します。$1$どれからでも$x$、分割では複数も可能になります$z$同じターゲットにマッピングする値。 単純な BFS スタイルで状態のすべてのペア間のエッジをカウントすると、状態ごとの減算の選択肢が 2 次数になるため、遷移が過大にカウントされたり、時間制限を超えたりします。 

もう 1 つの重要なエッジケースは、$x = 2$。 から$2$、減算のみが可能です$1 \to 1$、および除算のみ$z = 2$与える$\lfloor 2/2 \rfloor = 1$したがって、両方の移動タイプは同じエンドポイントに折りたたまれますが、別個の遷移のままになります。 これは、トランジションが個別の宛先によってではなく、パラメータの選択肢の数によって重み付けされることを強調します。 

## アプローチ

 ブルートフォース解釈で各位置を処理する$x$有向グラフのノードとして。 から$x$、引き算が作成します$x-1$すべての小さなノードにエッジを追加し、分割により追加のエッジを作成します。$\lfloor x/z \rfloor$みんなのために$z \in [2, x]$。 同一の目的地を集計した場合でも、減算だけですでに寄与します。$O(n^2)$各ノードがすべてのより小さなノードに接続するため、合計の遷移が増加します。 この構造上の DFS または BFS は部分問題を繰り返し再計算するため、次の時点で実行不可能になります。$n = 4 \cdot 10^6$。 

重要な観察は、減算遷移を宛先ごとにグループ化できることです。 「から」と考えるのではなく、$x$私たちはすべてに行きます$y < x$」では、視点を逆転させて、それぞれの立場を説明します。$i$全員から寄付を受け取ります$x > i$減算によるもので、まさにプレフィックスの合計構造です。 これにより、二次遷移セットが、プレフィックス合計を使用して償却された一定時間範囲の累積に変換されます。 

ディビジョントランジションの構造は異なります。 固定の場合$x$、の値$z$の繰り返し値を多数生成する$\lfloor x/z \rfloor$、しかし、これらの繰り返しは、連続した範囲を形成します。$z$同じ商を共有します。 これは標準的な除数グループ化のトリックです。次の個別の値を反復処理できます。$\lfloor x/z \rfloor$で$O(\sqrt{x})$またはインターバルジャンプを使用するとより効果的です。 

両方のアイデアを組み合わせると、次のような DP が得られます。$dp[x]$プレフィックスの合計に依存します$dp[1..x-1]$部門グループからの寄付の合計。 これにより、すべてのエッジの明示的な列挙が回避され、問題が大まかに軽減されます。$O(n \log n)$または$O(n)$実装に応じて償却されます。

 ## アルゴリズムのチュートリアル

 私たちは定義します$dp[x]$セルに到達する方法の数として$1$から始まる$x$。 以下から値を計算します$1$まで$n$遷移は常により小さな値に向かうためです。 

1.初期化$dp[1] = 1$トークンはすでにターゲットにあるためです。 
2. プレフィックス合計配列を維持する$pref[x] = dp[1] + \dots + dp[x]$。 この構造は、すべての減算遷移をコンパクトにエンコードします。 
3. それぞれについて$x > 1$、減算寄与を次のように計算します。$pref[x-1]$、どの州からでも$x$どれでも減算できます$y$どれかに着陸できるように$[1, x-1]$そして、そのような着陸のたびに、その目的地からあらゆる方法で貢献します。 
4. すべてをグループ化して部門の寄与を計算する$z$そのような$\lfloor x/z \rfloor = k$。 このようなブロックごとに、次のように累積します。$(r - l + 1) \cdot dp[k]$、 どこ$[l, r]$の範囲です$z$生産商$k$。 これは反復処理によって行われます$l = 2$、にジャンプします$r = x // (x // l)$。 
5. 減算と除算の寄与分をモジュロで合計する$m$入手する$dp[x]$。 
6. 各プレフィックスの合計を計算した後、増分的に更新します。$dp[x]$。 

### なぜ効果があるのか

 からのすべての有効な動き$x$減算対象の選択のいずれかに対応します$y < x$または除算パラメータを選択する$z \ge 2$。 減算はターゲット状態ごとに 1 回だけ寄与し、除算は有効な状態ごとに 1 回だけ寄与します。$z$。 DP は最初の動きを分解することですべてのシーケンスをカウントし、プレフィックスの合計により、すべての減算によって引き起こされる遷移が損失や重複なく集約されることが保証されます。 除算グループ化では、正確な多重度が保持されます。$z$選択により、すべての個別の移動シーケンスが 1 回カウントされるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    dp = [0] * (n + 1)
    pref = [0] * (n + 1)
    
    dp[1] = 1
    pref[1] = 1
    
    for x in range(2, n + 1):
        res = pref[x - 1]
        
        l = 2
        while l <= x:
            k = x // l
            r = x // k
            res += (r - l + 1) * dp[k]
            l = r + 1
        
        dp[x] = res % m
        pref[x] = (pref[x - 1] + dp[x]) % m
    
    print(dp[n] % m)

if __name__ == "__main__":
    solve()
```DP 配列は位置ごとの最終カウントを保存しますが、プレフィックス合計配列はすべての減算遷移を次の値に圧縮します。$O(1)$州ごとに。 除算ループは、次の事実を利用します。$\lfloor x/z \rfloor$変更のみ$O(\sqrt{x})$回なので、それぞれ$x$効率的に処理されます。 

よくある落とし穴は、それぞれが異なるものであることを忘れることです。$z$同じ結果につながる場合でも、別々に貢献する$\lfloor x/z \rfloor$。 間隔グループ化は、次のような方法で多重度を明示的に保持します。$(r - l + 1)$。 

## 実用的な例

 検討してください$n = 3$、$m = 998244353$。 昇順に計算します。 

| × | dp[x]の計算 | dp[x] |
 | --- | --- | --- |
 | 1 | 基本ケース | 1 |
 | 2 | pref[1] + 除算(z=2 による 2→1) | 2 |
 | 3 | pref[2] + 減算 + 除算グループ | 5 |

 のために$x = 3$、減算が貢献します$dp[1] + dp[2] = 1 + 2 = 3$。 Division は 2 つのケースに貢献します。$z = 2$与える$1$そして$z = 3$も与えます$1$、それぞれが貢献$dp[1] = 1$、追加$2$合計。 したがって、$dp[3] = 5$。 

このトレースでは、減算ではすべての小さな状態が正しく集約されるのに対し、除算では個別のエンドポイントではなくパラメーターの選択に基づいて多重度が得られることが確認されています。

 ## 特殊なケース

 のために$n = 2$、直接的な遷移のみです。$1$減算と除算によって、エンドポイントが同じであるにもかかわらず、それぞれが異なる動きに寄与します。 アルゴリズムは両方を正しくカウントします。$dp[2]$は、プレフィックス合計と除算ループを通じて両方の寄与を明示的に集計します。 

小型用$n$、分割グループは単一の間隔に分割され、アルゴリズムは単純なプレフィックスの累積に縮小されます。 これにより、範囲が単一の要素に縮退した場合でも両方のループが有効なままとなるため、特別なケースを使用しなくても正確さが保証されます。
