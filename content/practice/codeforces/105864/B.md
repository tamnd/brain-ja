 ## 解決策
 ## 問題の理解

 私たちに与えられた一行は、$n$人々はそれぞれ同じアイテムをいくつか持っています。 アイテムの総数は次のように割り切れます。$n$したがって、明確に定義された目標値があり、全員が最終的に正確に目標値を達成する必要があります。$s/n$アイテム。 

当初の配布は、$a_1, a_2, \dots, a_n$。 次に、一連の更新によってこの分布が永続的に変更されます。更新ごとに、ある人から別の人にいくつかのアイテムが移動するため、各更新後に新しい配列を取得します。 更新のたびに、同じ質問に答える必要があります。つまり、非常に具体的な移動ルールが与えられた場合に、全員が正確な平均値に達するように、グループがアイテムをどれだけ早く再配布できるかということです。 

キーの再配布プロセスには制限があります。 十分なアイテムがある限り、誰もが 1 分以内に、左隣の人に最大 1 つのアイテム、右隣の人に最大 1 つのアイテムを同時に送信できます。 これは、フローが隣接するエッジに沿って並行して発生することを意味しますが、各エッジは 1 分あたり各方向に最大 1 つのアイテムを運ぶことができ、各ノードは 1 分あたり最大 1 つのユニットを各サイドに送信できます。 

各更新後の出力は、これらの移動ルールに基づいて完全な平等に達するために必要な最小時間 (分) です。 

制約は大きいです:$n$そして$q$すべてのテストの合計は最大でも$3 \cdot 10^5$。 これにより、再分配プロセスの二次シミュレーションや線形スキャンを多用したシミュレーションを使用して、クエリごとに回答を最初から再計算することが直ちに排除されます。 ソリューションでは、配列のコンパクトな概要を維持し、操作ごとに対数または一定の償却時間で更新する必要があります。 

最も微妙な問題は、全体的な不均衡だけが答えではないということです。 ローカル構造は重要です。たとえグローバル合計が正しいとしても、制限要因はエッジを越える不均衡の程度であり、それはプレフィックスの動作に依存します。 

単純な間違いは、赤字または黒字の最大値のみが重要であると考えることです。 たとえば、次のような構成を考えてみましょう。$[2, 0, 2]$ターゲット付き$2$。 合計の不均衡はゼロですが、両方のユニットが中間ノードを通過する必要があるため、再分配には時間がかかります。 誤って世界の黒字だけを見てしまうと、時間はゼロになると予測することになります。 

もう 1 つの失敗モードは、方向の競合を無視することです。 のような場合には$[0, 3, 0]$ターゲット付き$1$、2 つのユニットが左に移動し、1 つが右に移動する必要があり、中心で相互作用するため、慎重にモデル化しないと、単純な距離の推定を超える時間が増加します。 

本当に難しいのは、エッジを通過する同時フローによって引き起こされるボトルネックを把握することです。 

## アプローチ

 再配布プロセスの直接シミュレーションでは、毎分モデル化を試みます。すべてのノードが項目を左右にプッシュし、配列を繰り返し更新します。 1分ごとにコストがかかります$O(n)$、最悪の場合の分数も$O(n)$、につながる$O(n^2)$クエリごとに。 まで$3 \cdot 10^5$操作、これは不可能です。 

静的配列の答えを事前計算しようとしても、更新によって値が恣意的に変更されるため、依然として動的な問題に直面します。 したがって、完全なシミュレーションではなく、構造的な要約から答えを再計算する方法が必要です。 

重要な洞察は、個々の項目について考えるのをやめ、代わりに累積的な不均衡を追跡することです。 定義する$b_i = a_i - \text{avg}$。 問題は、1 分あたり両方向の単位容量エッジを使用してすべての不均衡を解消するのにどれくらいの時間がかかるかということです。 

ここで、これをパス グラフ上のフロー問題として解釈します。 各プレフィックスには純過剰または純不足があります。 このプレフィックスの不均衡は、次の境界を越えて転送される必要があります。$i$そして$i+1$。 必要な時間は、必要なすべての転送が最適にスケジュールされている場合、エッジ上の最大輻輳によって決まります。 

これをモデル化する標準的な方法は、プレフィックスの合計を定義することです。$$p_i = \sum_{j=1}^i b_j$$それぞれ$p_i$間のカットを通過する必要がある余剰の量を表します。$i$そして$i+1$。 再分配プロセスは、各エッジにわたって 1 分あたり 1 方向あたり最大 1 ユニット移動できます。つまり、各エッジには 1 分あたり各方向に 1 の容量があります。 これにより、問題は、各エッジを同時に通過する必要があるフローの量を測定することに変わります。 

重要な観察は、最適なスケジューリングの後、最小時間がエッジを通過する必要がある絶対ネット フローのエッジ上の最大時間に等しいということです。これはプレフィックスの極値を使用して表現できます。 実際、その答えは、グローバルな制約とバランスをとったときに、正または負のプレフィックスの合計がどのくらい大きくなるかを追跡することに帰着します。 

これにより、動的な構造が得られます。更新のたびに、配列内の 2 つの位置のみが変更されるため、プレフィックスの合計は構造化された方法で変化します。 各セグメントのプレフィックス合計の最小値と最大値の差を保存するセグメント ツリーを維持できるため、必要な最大輻輳を効率的に計算できます。 

したがって、各クエリは、ポイント更新に加えて、セグメント情報から導出されるグローバル最大値のセグメント ツリーの再計算になります。

 ## アルゴリズムのチュートリアル

 平均値を暗黙的に減算することにより、配列を不均衡形式に変換します。 合計は一定であり、次で割り切れるため、$n$、偏差を扱うことができます。 

これらの偏差に関するプレフィックス合計の配列を維持します。 目標は、この構造内での位置を調整することで値が変更される更新をサポートすることです。 

### ステップ

 1. の初期値を計算します。$b_i = a_i - \frac{s}{n}$。 

これにより、問題は絶対数ではなく、正と負のフローのバランスをとることに変わります。 の合計額を保証します。$b_i$はゼロです。 
2. プレフィックス合計を構築する$p_i$以下を維持するセグメント ツリーを通じて暗黙的に:

 任意のセグメントにわたるプレフィックスの合計の最小値と最大値の両方。 

これにより、すべてのプレフィックスを明示的に保存しなくても、間隔にわたって不均衡がどのように蓄積するかを理解できるようになります。 
3. アップデートごとに$u \to v$価値のあるもの$x$、基礎となる配列を調整します。 

引き算$x$から$a_u$、 追加$x$に$a_v$。 

これは次の 2 つの位置にのみ影響します。$b$したがって、セグメント ツリーに 2 つのポイント更新を適用します。 
4. 更新するたびに、グローバル メジャーを再計算します。 

必要な時間は、いずれかの方向の最悪のプレフィックス偏差の最大値です。 

これは、あるエッジを通過する必要がある最大の輻輳に相当します。 
5. 各クエリに対してこの値を直接出力します。 

### なぜ効果があるのか

 再分配プロセスは、パス グラフのエッジに沿ってユニット フローを押し出すことと同等で、各エッジには 1 分あたり方向ごとに 1 の容量があります。 位置のアンバランス$i$全体的な平衡に達するには、エッジを越えて輸送する必要があります。 プレフィックス合計は、各境界を通過する必要がある正味フローの量を正確にエンコードします。 

セグメント ツリーは、更新時に考えられるすべてのプレフィックスの極端な値を維持します。 すべての更新では 2 つのポイントのみが変更されるため、影響を受けるすべてのプレフィックス構造はローカルにキャプチャされますが、ツリーを通じて伝播されます。 最大絶対プレフィックス偏差はボトルネック エッジに対応し、すべてのフローをルーティングするのに必要な最小時間を決定します。 

配列内の他の構造はプレフィックスの不均衡と無関係に時間を増加させることができないため、この値が答えを完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.mx = [0] * (4 * self.n)
        self.mn = [0] * (4 * self.n)
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            self.mx[v] = self.arr[l]
            self.mn[v] = self.arr[l]
            return
        m = (l + r) // 2
        self.build(v * 2, l, m)
        self.build(v * 2 + 1, m + 1, r)
        self.mx[v] = max(self.mx[v * 2], self.mx[v * 2 + 1])
        self.mn[v] = min(self.mn[v * 2], self.mn[v * 2 + 1])

    def update(self, v, l, r, i, val):
        if l == r:
            self.mx[v] += val
            self.mn[v] += val
            return
        m = (l + r) // 2
        if i <= m:
            self.update(v * 2, l, m, i, val)
        else:
            self.update(v * 2 + 1, m + 1, r, i, val)
        self.mx[v] = max(self.mx[v * 2], self.mx[v * 2 + 1])
        self.mn[v] = min(self.mn[v * 2], self.mn[v * 2 + 1])

    def answer(self):
        return max(abs(self.mx[1]), abs(self.mn[1]))

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        s = sum(a)
        avg = s // n

        b = [x - avg for x in a]
        st = SegTree(b)

        for _ in range(q):
            u, v, x = map(int, input().split())
            u -= 1
            v -= 1

            st.update(1, 0, n - 1, u, -x)
            st.update(1, 0, n - 1, v, +x)

            print(st.answer())

if __name__ == "__main__":
    solve()
```コードは不均衡配列を直接維持し、各転送をポイント更新のペアとして適用します。 更新のたびに、基礎となる不均衡構造のグローバルな最大値と最小値を追跡するセグメント ツリーが変更されます。 

各クエリの後の答えは、すべての位置にわたる最大絶対偏差です。 これにより、暗黙のフロー システムにおける最悪の輻輳ポイントが捕捉され、必要な最小時間数が決まります。 

## 実用的な例

 小さな例を考えてみましょう。$n = 3$、初期配列$[2, 2, 2]$、平均は$2$したがって、初期の不均衡はどこでもゼロです。 更新により 1 ユニットが位置 1 から 3 に移動すると、不均衡が生じます$[-1, 0, 1]$。 

| ステップ | 更新 | 配列 | アンバランス | セグメントツリー最大値 | セグメントツリーの最小値 | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | イニシャル | [2,2,2] | [0,0,0] | 0 | 0 | 0 |
 | 2 | 1→3 | [1,2,3] | [-1,0,1] | 1 | -1 | 1 |

 これは、合計が均衡している場合でも、流れは 1 つのユニットを運ぶ少なくとも 1 つのエッジを横断する必要があり、1 つのステップが必要であることを示しています。 

次に、もう少し大きなケースを考えてみましょう。$n = 4$、 イニシャル$[0,4,0,4]$、 平均$2$。 

初期アンバランスは$[-2, 2, -2, 2]$。 

| ステップ | 更新 | アンバランス | 最大 | 分 | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 1 | イニシャル | [-2,2,-2,2] | 2 | -2 | 2 |
 | 2 | 1 を 2 から 3 に移動します | [-2,1,-1,2] | 2 | -2 | 2 |

 ボトルネックは局所的な平滑化ではなく最大のプレフィックス偏差によって決定されるため、答えは安定しています。 

これにより、更新はローカルな不均衡にのみ影響を及ぼし、グローバルなボトルネック構造が支配的であることが確認されます。

 ## 特殊なケース

 重要なケースの 1 つは、更新によって不均衡が生じ、グローバルにはキャンセルされるが、ローカルには集中する場合です。 たとえば、離れたノード間でアイテムをやり取りすると、合計の合計は変わりませんが、ピーク プレフィックスの偏差が増加する可能性があります。 各更新で 2 つのポイントが変更され、プレフィックス構造を通じて変更が伝播されるため、セグメント ツリーはこれを正しくキャプチャします。 

もう 1 つのケースは、同じインデックスに対して繰り返し更新が行われる場合です。 各更新はデルタとして適用されるため、構造には自然に変更が蓄積されます。 プレフィックスの最大/最小は、最初から再計算する必要なく、真の輻輳を反映し続けます。 

最後に、更新後にすべての値が等しい場合は、常にゼロを返す必要があります。 すべてのプレフィックスの合計はゼロになるため、保存されている両方の極値はゼロになり、答えは正しく最小になります。
