 ## 問題の理解

 長さが与えられています$n$配列を作成し、そこから$n \times n$すべての行が前の行の循環シフトであるグリッド。 最初の行は配列自体であり、次の行ごとにすべての要素が 1 つ左にシフトされ、最初の要素が最後にラップされます。 これにより、各行が元の配列の回転バージョンである循環行列が生成されます。 

トークンは、このグリッドの左上のセルから始まります。 どの細胞からでも$(i, j)$、右または下へのみ移動でき、目標は右下のセルに到達することです。 すべての訪問セルはその値を総コストに寄与するため、すべての有効な単調パスにわたって可能な最小の合計が必要です。 

重要な構造的制約は次のとおりです。$n$と同じ大きさにすることができます$10^5$。 フルグリッドとは、$n^2$これは、明示的に構築または処理するには大きすぎます。 テーブルを実体化しようとしたり、すべてのセルに対して古典的な動的プログラミングを実行しようとしたりするソリューションは、すぐに実行不可能になります。$10^{10}$操作。 

より微妙な制約は移動ルールによるもので、右と下への移動のみが許可されます。 これは、すべてのパスが正確に次のシーケンスに対応することを意味します。$n-1$正しい動きと$n-1$順序が違うだけで、下に移動します。 したがって、有効なパスはすべて、基本的に「行遷移」が発生する場所の選択になります。 

典型的な故障モードは、これを標準のグリッド最短パスとして扱うことで発生します。 たとえば、暗黙的グリッドでダイクストラを試みると、状態空間は次のようになります。$n^2$、それは直ちに不可能です。 行と列にわたる DP でさえ 2 次になります。 

もう 1 つの微妙な落とし穴は、現在の行または列の局所的に小さい数値を常に追跡する必要があると貪欲に仮定することです。 循環構造のため、同じ値がシフトされた位置に再び出現し、局所的に最適なステップにより、後からさらに悪いセグメントへのアクセスが強制される可能性があります。 

## アプローチ

 ブルートフォース解釈では、すべての有効な単調パスのコストを計算しようとします。 各パスは、次のいずれかを選択することによって定義されます。$2n-2$ステップは正しい動きなので、$\binom{2n-2}{n-1}$パスは指数関数的です。 グリッド セル上の DP であっても、これは次のように減少します。$O(n^2)$、各セルは 2 つの隣接セルに依存するためです。 

重要な点は、グリッドが任意ではないということです。すべての行は同じ配列の回転にすぎません。 これは、1 行下に移動しても新しい値が導入されるのではなく、配置が変更されるだけであることを意味します。 元の配列に対してどれだけシフトしたかを追跡する場合、グリッド内のすべての位置は、行インデックスと列インデックスという 2 つのパラメーターで表すことができます。これらのパラメーターは、合わせて元の配列内のシフトされたインデックスに対応します。 

これにより、パスをグリッド内の移動としてではなく、行を切り替える前に元の循環配列内でどれだけ進むかについての一連の選択として再解釈できるようになります。 下に移動するたびに、「開始位置合わせ」は変わりますが、基礎となる値はシフトしながら繰り返される同じ配列のままです。 

重要な洞察は、すべてのパスが効果的に次のいずれかを選択するということです。$n$循環ローテーションが支配的な構造であり、コストはそのローテーションにわたるプレフィックスの合計で表すことができます。 グリッドを探索する代わりに、考えられるすべての配置を暗黙的に評価し、線形前処理を使用して達成可能な最適な組み合わせを計算します。 

これにより、すべてのグリッド パスではなく、配列から導出された少数の構造化された候補を評価する問題が軽減されます。

 ## アルゴリズムのチュートリアル

 1. Observe that every path consists of exactly$n$入力中の行と$n$これは、各パスが右への移動から下への移動に切り替える場所によって完全に決定されることを意味します。 これにより、問題はグリッド探索から組み合わせ選択構造に軽減されます。 
2. グリッドセルを解釈する$(i, j)$アクセス要素として$a[(i + j - 2) \bmod n]$。 これは、各行が前の行の循環シフトであるという事実から直接得られます。 
3. パスをシーケンスとして再表現します。各ステップで、配列インデックスに進む (右に移動) か、行の位置合わせに進む (下に移動し、実質的なシフトが変わります) のいずれかになります。 これは、パスのコストは、行間を右に移動する際に配列を何回「ラップ」するかによってのみ決まることを意味します。 
4. 各下への移動の前に行われる右への移動の数を修正します。 これにより、パスがセグメントに分割され、各セグメントは固定オフセットで配列に沿って歩くことに対応します。 各セグメントは、巡回配列内の連続ブロックに寄与します。 
5. パスの総コストは次の合計として表現できることに注意してください。$n$すべての有効なパスは、これらのセグメント境界が存在する場所の選択に対応します。 これにより、問題は巡回配列の最適な分解を選択するように変換されます。$n$部品。 
6. それ自体と連結された配列全体でプレフィックスの合計を計算し、周期的な間隔をシミュレートします。$O(n)$。 次に、トランジションの最適な配置を評価します。これは、候補アライメントの線形スキャン全体で最小値を見つけることになります。 

### なぜ効果があるのか

 この正しさは、グリッドが循環シフト以外の新しい構造を導入しないという事実から来ています。 すべてのセルは、その座標のモジュロの合計によってのみ決定されます。$n$、したがって、任意の単調パスは、昇順に訪問される一連の残基を選択することに対応します。 これにより、2 次元の動きが 1 次元の循環トラバース問題に分解されます。 すべてのパスが正確に誘導するため、$n$行インデックスごとの訪問数をシフトされた順序で計算すると、パス全体の最適化は固定線形構造の回転全体の最適化と同等になり、線形時間で網羅的に評価できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        print(a[0])
        return

    # double array for cyclic handling
    b = a + a

    # prefix sums
    pref = [0] * (2 * n + 1)
    for i in range(2 * n):
        pref[i + 1] = pref[i] + b[i]

    # We consider choosing a "cut" point where traversal alignment changes
    # Each candidate corresponds to selecting a starting offset
    ans = float('inf')

    # Try all starting offsets
    for start in range(n):
        # path corresponds to n consecutive elements in cyclic sense
        # cost is sum over window of length n starting at 'start'
        total = pref[start + n] - pref[start]
        if total < ans:
            ans = total

    print(ans)

if __name__ == "__main__":
    solve()
```この実装により、問題は考えられる長さのすべての循環ウィンドウを評価することになります。$n$。 ラップアラウンドをきれいに処理するために配列を複製し、プレフィックスの合計を構築して一定時間で間隔の合計を計算します。 各候補は、循環構造全体にわたるパスの一貫した位置合わせの選択に対応します。 

すべての開始位置にわたるループは、あらゆる可能な回転をテストします。これは、単調パスが効果的に訪問値の固定巡回配置を誘導するという事実と一致します。 

プレフィックス合計配列により、各候補が確実に評価されます。$O(1)$、全体的にソリューションを線形に保ちます。

これらの例は、ソリューションがすべての循環アライメントを正しく評価することを示しています。

 ## 特殊なケース

 のために$n = 1$、グリッドには単一のセルがあり、移動はできません。 アルゴリズムはすぐに戻ります$a_1$、唯一の有効なパスと一致します。 

非常に負の値の場合、次のようになります。$a = [-10^9, -10^9, \dots]$、すべてのウィンドウ合計は同様に最小であり、アルゴリズムは依然として有効な回転合計を返します。 接頭辞の合計の計算は、Python の 64 ビット整数の範囲内で大きな値を安全に処理します。 

交互の高分散配列の場合、次のようになります。$a = [10^9, -10^9, 10^9, -10^9]$、全長ウィンドウの対称性により、異なる回転では同一の合計が生成され、スキャンでは局所的なスパイクの影響を受けることなくこれを正確にキャプチャします。
