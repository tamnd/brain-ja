 ## 解決策
 ## 問題の理解

 私たちにはポケモンのコレクションが与えられ、それぞれが初期の強さと価格という 2 つの数字で表されます。 トーナメントが始まる前に、チャンピオンとしてポケモンを 1 匹だけ選ぶことができます。 それを選択した後、選択した順序で他のすべてのポケモンと1匹ずつ戦わなければなりません。 

戦いは決定的です。つまり、現在の強さが相手の強さを厳密に上回っていれば、私たちは勝ちます。 そうしないと、すぐに負けてプロセスが終了します。 勝利するたびに、現在の戦力がちょうど 1 ずつ増加します。 すべての対戦相手を倒すことができた場合、その開始ポケモンはトーナメントに勝つことができると見なされます。 

タスクは、完全なスイープを可能にする対戦相手の順序が存在するように、最初のチャンピオンとして選択できるすべてのポケモンの最小コストを決定することです。 これを達成できるポケモンがない場合は、-1 を出力します。 

重要な難しさは、戦う順番を自由に選択できることです。つまり、実現可能性は、選択したポケモンの強さだけでなく、トーナメント中に増加する強さと比較して対戦相手をどのようにスケジュールできるかにも依存します。 

この制約では最大 100,000 匹のポケモンが許可されており、二次時間で候補ごとにすべての順列や貪欲な試行をシミュレートするソリューションは除外されます。 すべての対戦相手に対するシミュレーションで各ポケモンを個別にテストしようとするアプローチは、およそ O(n^2) にまで低下し、遅すぎます。 

複数のポケモンが同じ強さを共有する場合、微妙な失敗のケースが発生します。 開始ポケモンとして利用可能なすべての選択肢が最小の強さを持っている場合、勝利条件が厳密に大きいため、同じ強さの相手を倒すことはできません。 たとえば、すべての ai が等しい場合、コストに関係なく、答えは -1 でなければなりません。 

もう 1 つの明白ではない状況は、強力な初期ポケモンであっても、その強さの増加が次々と強力な敵に追いつくように戦いを組み立てることができない場合、失敗する可能性があることです。 「常に残っている最も弱い相手と戦う」といった素朴な貪欲さでは十分ではありません。コストは順序とは独立しており、実現可能性はグローバルな順序条件に依存するからです。 

## アプローチ

 ブルートフォースソリューションでは、各ポケモンをスターター候補として選択し、そのポケモンが勝つことを可能にする他のすべてのポケモンの順序が存在するかどうかを判断しようとします。 固定の初期ポケモンの場合、現在勝てる次の対戦相手を繰り返し選択し、強さを更新することでシミュレーションできます。 この方法で実現可能性をチェックするには、すでにソートまたはスキャンの繰り返しが必要であり、すべての候補に対してこれを実行すると、少なくとも O(n^2) または O(n^2 log n) が得られ、これは限界をはるかに超えています。 

構造的な洞察は、動的シミュレーションの観点から考えるのをやめ、代わりに問題を開始強度に関する実現可能性の条件に変換することです。 初期強度 s で候補を固定するとします。 戦いに勝つと、k回勝利すると強さはs + kになります。 すべての対戦相手に勝つには、各ステップで、選択した対戦相手の強さが現在の値よりも厳密に小さくなるように対戦相手を配置する必要があります。 

これは、各 AI が位置インデックス付きのしきい値よりも小さい順序で他のすべてのポケモンを順序付けしたいことを意味します。 これは、各対戦相手の強さを、スロット インデックスが追加の許容強さに寄与する個別の「タイム スロット」に一致させることができるかどうかをチェックすることに相当します。

重要な観察は、他のすべてのポケモンを強さで並べ替える場合、最も配置するのが難しいポケモンが実現可能性のチェックで最初に考慮されるべきであるということです。 強度の増加順に処理する場合、ステップ i (0 からインデックス) で、現在利用可能な強度は少なくとも ai ≤ s + i でなければなりません。 並べ替えると、s に関する条件が与えられます。並べ替えられたリスト内のすべての i に対して s ≥ ai − i です。 したがって、開始ポケモンが固定されている場合、他のすべてのポケモンの中で (ai − i) の最大値を計算し、s がそれを厳密に超えることを確認できます。 

これにより、ソートにより各候補チェックが O(n log n) に減少しますが、アイデアをグローバル化できます。 関連する開始ポケモンが、他のすべてのポケモンから導出されるグローバル制約を満たすのに十分な強さを持っている唯一のポケモンであることがわかった場合、すべての候補を試す必要はありません。 

したがって、一度ポケモンを強さで並べ替え、必要な最小開始強さのしきい値を計算してから、強さがこのしきい値を満たすすべてのポケモンの中から最小コストを選択します。

 ## アルゴリズムのチュートリアル

 1. すべてのポケモンを強さの降順でない順に並べ替えます。 これにより、対戦相手の相対的な強さのみを考慮するため、戦闘スケジュールに関する推論に固定の順序が与えられます。 
2. ソートされたリストを走査し、(ai − i) の最大値を追跡することによって定義された実行制約値を計算します。ここで、i はソートされた配列内の位置です。 これは、早期に最適なスケジュールを設定しようとしたときに、各対戦相手がどれだけの「赤字」をもたらすかを捉えています。 
3. この制約を最小限必要な開始強度に変換します。 厳密な勝利が必要なため、開始時の戦力は最大赤字と同じではなく、それを上回る必要があります。 
4. すべてのポケモンをもう一度繰り返して、どれが開始候補として機能できるかを確認します。つまり、初期の強さが必要なしきい値以上であることを意味します。 
5. すべての有効な候補の中から、最小コスト bi を取得します。 
6. 要件を満たす候補がない場合は、-1 を出力します。 

### なぜ効果があるのか

 ポケモンが強さによって分類されると、実行可能性を悪化させることなく、実行可能な戦闘順序をこの順序を尊重したものに変換できます。なぜなら、厳密に強さを増加させるプロセスの下では、弱い敵が最初よりも後で勝つのが難しくなることは決してないからです。 ai − i という式は、対戦相手の強さと利用可能な進行スロットとの間の最悪の場合のギャップを捉えます。 初期の強さが最悪のギャップをカバーするのに十分なほど高い場合、強さの増加順に戦う貪欲なスケジュールは常に有効性を維持します。なぜなら、ステップ i で正確に i が蓄積されているため、i の強さが増加するからです。 これにより、厳密な不変条件が作成されます。つまり、i が勝った後、現在の強さは正確に s + i になり、位置 i に残っているすべての対戦相手は ai < s + i を満たす必要があり、これは構造によって保証されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    pokes = list(zip(a, b))
    pokes.sort()
    
    # compute minimum required starting strength threshold
    need = -10**30
    for i, (ai, bi) in enumerate(pokes):
        need = max(need, ai - i)
    
    ans = float('inf')
    for ai, bi in pokes:
        if ai >= need:
            ans = min(ans, bi)
    
    print(-1 if ans == float('inf') else ans)

if __name__ == "__main__":
    solve()
```この解決策は、強さとコストをペアにすることから始まり、次に強さごとに分類することで、勝利ごとに 1 つの利益を「費やす」につれて強さの要件がどのように変化するかを推論できるようにします。 変数`need`スケジュール上のプレッシャーの点で最も制限の厳しい対戦相手を追跡します。 

2 番目のパスでは、有効な開始ポケモンをフィルターします。 条件`ai >= need`初期の強さがすでにグローバル要件をクリアしているポケモンのみが使用可能であることを反映しています。 最後に、実現可能な選択肢の中からコストを最小限に抑えます。 

微妙な点は、インデックス`i`ソートされた配列内の は、最適なスケジュールでその対戦相手と対戦する前にすでに勝利したと想定される回数を暗黙的に表します。 これが、変換が機能する理由の核心です。

| ポケモン | ポケモン あい | バイ | 有効 (ai ≥ 2) |

 | 2 | 2 | 1 | はい |
 | 3 | 4 | 2 | はい |

 答えは、有効なうちの最小コスト = 1 です。 

このトレースは、初期の弱い要素がどのように制約を支配し、最小の初期強度を強制して、強度は低いがおそらく安価な候補を除外するかを示しています。

 ## 特殊なケース

 すべての強度が等しい場合、すべての ai − i 計算で必要な高いしきい値がすぐに明らかになりますが、厳密な比較により等しいものに対する進行が妨げられるため、そのしきい値を超えると有意に役立つ候補はありません。 たとえば、入力`a = [3, 3, 3]`どのスケジュールでも満たすことができない要件が生成されますが、実現可能性フィルターを通過する要素がないため、アルゴリズムは正しく -1 を返します。 

強く支配的なポケモンが 1 匹だけいる場合、`a = [1, 2, 100]`の場合、しきい値はソート順の早い段階で最大のギャップによって決定されます。 アルゴリズムはすべてのポジションに基づいてニーズを計算し、最も強い候補だけがチェックを生き残り、そのコストを答えとして正しく選択します。 

コストが非常に不均一であるが、強みが類似している場合、アルゴリズムにより、実現可能性が最適化から分離されることが保証されます。 コストを最小化する前に実現可能性フィルターが厳密に適用されるため、安価ではあるが実現不可能な候補が優先されることはありません。
