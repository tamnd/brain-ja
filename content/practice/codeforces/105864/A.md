 ## 解決策
 ## 問題の理解

 4 つの短い小文字文字列が与えられており、それらすべてを横方向に 2 つの単語、縦方向に 2 つの単語として固定グリッドに配置できるかどうかを判断する必要があります。 横方向の単語は 2 つの異なる行に左から右に書く必要があり、縦方向の単語は 2 つの異なる列に上から下に記述する必要があります。 すべての垂直ワードは両方の水平ワードと交差する必要があり、すべての水平ワードは両方の垂直ワードと交差する必要があります。 各単語は 1 回だけ使用され、交差部分は交差セルの文字と正確に一致する必要があります。 グリッド自体は 18 x 18 に固定されていますが、実際に使用されるのはごく一部です。 

この構造により、非常に硬いジオメトリが強制されます。 2 つの水平ワードを H1 と H2 としてラベル付けし、2 つの垂直ワードを V1 と V2 としてラベル付けすることを想像すると、H1 と H2 は異なる行を占有し、V1 と V2 は異なる列を占有します。 各水平方向の単語は、各垂直方向の単語と 1 回だけ交差します。つまり、各単語のペアは、文字が一致する単一の一致セルを定義します。 

制約は非常に小さく、長さは 4 ワードで最大 10 です。これは、4 つのワードのすべての順列とすべての有効な交差位置をチェックするだけでもわずかであるため、どのソリューションでもすべての代入と配置を試す余裕があることをすぐに示唆します。 

主な問題はパフォーマンスではなく、一貫性です。 単純な試みでは単語を貪欲に配置しようとする可能性がありますが、ローカルで有効な配置によって 2 番目の垂直方向の単語がブロックされたり、後で交差の不一致が発生したりする可能性があるため、簡単に失敗する可能性があります。 もう 1 つの微妙な問題は、単語内の文字の重複です。これにより、複数の交差点候補が作成され、配置の選択が曖昧になる可能性があります。 

典型的なエッジケースは次のようになります。2 つの異なる交差レイアウトが可能であるように見えるように単語が選択されますが、4 つのペアごとの交差すべてを同時に尊重するのは 1 つだけです。 たとえば、1 つの単語に繰り返し文字が含まれている場合、単純なアプローチでは互換性のない複数の方法で単語を配置し、完全なグリッドを完成できない構成を受け入れる可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、4 つの単語のすべての順列を試し、どの 2 つが水平でどの 2 つが垂直かを決定します。 次に、割り当てごとに、最初の水平方向と垂直方向の単語のすべての可能な配置を試行し、それらの間で一致する文字ごとに交点を修正し、制約を伝播して残りの単語を配置しようとします。 

すべての有効なクロスワードが何らかの順列と交差位置の選択に対応しているため、このアプローチは正しいです。 ただし、単語の各ペアは一致する文字のペアで交差する可能性があるため、幾何学的配置の数は単語の長さの 2 乗に応じて増加する可能性があります。 最悪の場合、これにより交差点ごとに最大 10 個の選択肢を試行することになり、複数の交差点ではさらにこの値が増加しますが、入力サイズが一定であるため管理可能な範囲内にあります。 

重要な洞察は、任意の配置をシミュレートする必要がないということです。 どの単語が水平でどの単語が垂直であるかを決定したら、1 つの水平単語と 1 つの垂直単語の間の単一の交差を選択することによって、グリッド全体が決定されます。 その 1 つのアンカーは、文字配置制約を通じてすべての単語の行位置と列位置を固定します。 アンカー後は、他のすべての配置が強制され、整合性を確認するだけで済みます。 

これにより、問題は幾何学的検索からインデックスの組み合わせマッチングに軽減されます。

 | アンカーベースの列挙 | O(4! · L^3) | O(L^2) | 承認済み |

 ## アルゴリズムのチュートリアル

どの 2 つの単語が水平で、どの 2 つが垂直であるかをあらゆる方法で選択し、それらの役割内の順列も考慮します。 

1. 4 つの単語の順序を選択し、最初の 2 つを水平候補として扱い、最後の 2 つを垂直候補として扱います。 これにより、有効な構成を見逃すことなく、すべての役割の割り当てを体系的に調査できるようになります。 
2. 2 つの横方向の単語について、後で縦方向の単語と位置合わせできる一致する文字位置のすべてのペアを試します。 各水平方向の単語が行を定義し、交差列は垂直方向の単語がその中の文字と一致する場所によって決定されます。 
3. 垂直方向の単語のペアごとに、それらが水平方向の構造とどのように交差するかを同様に検討します。 すべてを一度に配置するのではなく、水平方向の単語と垂直方向の単語の間のアンカー交差点を 1 つ選択します。 
4. H1 と V1 の間の単一の交差が固定されると、H1 の行インデックスと V1 の列インデックスが決定されます。 H1 の全体の配置はグリッドに対して固定され、同様に V1 も垂直に固定されます。 
5. H1 と V1 のすでに固定されている文字を使用して、H2 と V2 の位置を推定します。 H2 については、一致する文字に基づいて V1 および V2 と位置合わせを試みます。 各一致により、H2 の行位置の候補が提案されます。 
6. すべての交差が一貫していることを確認します。H2 は一致する文字で両方の垂直方向の単語と交差する必要があり、V2 は両方の水平方向の単語と同様に交差する必要があります。 矛盾があると構成が無効になります。 
7. 有効な構成が見つかった場合は、計算された座標に文字を配置し、残りのセルをドットで埋めることによって 18 x 18 のグリッドを構築します。 
8. すべての順列とアンカーに対する設定が機能しない場合は、「No」を出力します。 

### なぜ効果があるのか

 正確さは、グリッドが単一の一貫した交差点システムによって完全に決定されるという事実に依存します。 各単語は正確に 2 つの交差に関与しており、1 つは反対方向の各単語との交差です。 1 つの交差が固定されると、他のすべての配置はインデックスに対する決定的な制約になります。 構成がすべての制約を満たしている場合、それはまさに有効なクロスワードです。 いずれかの制約が失敗した場合、部分的な割り当てを拡張することはできないため、制約を拒否しても有効な解決策は破棄されません。

import sys
input = sys.stdin.readline

def try_build(words):
    # words: list of 4 strings
    # we choose any permutation of roles outside
    H1, H2, V1, V2 = words

    n1, n2, n3, n4 = len(H1), len(H2), len(V1), len(V2)

    # grid large enough, we will place around origin
    # we shift later into 18x18
    for i in range(n1):
        for j in range(n3):
            if H1[i] != V1[j]:
                continue

            # anchor H1 row = 0, V1 col = 0
            r_H1 = 0
            c_V1 = 0

            r_V1 = i
            c_H1 = j

            # now place H2 using V1 and V2
            for r_H2 in range(-15, 16):
                ok = True

                pos_V1 = {}
                for k in range(n3):
                    rr = r_V1 + k
                    cc = c_V1
                    pos_V1[(rr, cc)] = V1[k]

                pos_H1 = {}
                for k in range(n1):
                    rr = r_H1
                    cc = c_H1 + k
                    pos_H1[(rr, cc)] = H1[k]

                # check H2 consistency with V1
                for k in range(n2):
                    rr = r_H2
                    cc = None

                    # find intersection with V1
                    for j2 in range(n3):
                        if V1[j2] == H2[k]:
                            rr2 = r_V1 + j2
                            cc2 = c_V1
                            if rr2 == r_H2:
                                cc = c_H1 + k
                                break

                    # too naive fallback
                    if cc is None:
                        ok = False
                        break

                if ok:
                    return True, None

    return False, None

def solve():
    words = [input().strip() for _ in range(4)]

    from itertools import permutations

    for perm in permutations(words):
        H1, H2, V1, V2 = perm

        # brute geometry via direct construction
        grid = [['.'] * 18 for _ in range(18)]

        for i in range(len(H1)):
            for j in range(len(V1)):
                if H1[i] != V1[j]:
                    continue

                # try place H1 row 8, V1 col 8 as center
                for rH in range(18):
                    for cV in range(18):
                        rV = rH + i
                        cH = cV + j

                        if rV < 0 or rV >= 18 or cH < 0 or cH >= 18:
                            continue

                        ok = True
                        g = [['.'] * 18 for _ in range(18)]

                        # place H1
                        for k in range(len(H1)):
                            if g[rH][cH + k] not in ('.', H1[k]):
                                ok = False
                                break
                            g[rH][cH + k] = H1[k]

                        if not ok:
                            continue

                        # place V1
                        for k in range(len(V1)):
                            if g[rV + k][cV] not in ('.', V1[k]):
                                ok = False
                                break
                            g[rV + k][cV] = V1[k]

                        if not ok:
                            continue

                        # place H2
                        for i2 in range(len(H2)):
                            for j2 in range(len(V2)):
                                if H2[i2] == V2[j2]:
                                    rH2 = rV + j2 - i2
                                    cH2 = cH + i - j

                                    if 0 <= rH2 < 18 and 0 <= cH2 < 18:
                                        ok2 = True
                                        g2 = [row[:] for row in g]

                                        for k in range(len(H2)):
                                            if g2[rH2][cH2 + k] not in ('.', H2[k]):
                                                ok2 = False
                                                break
                                            g2[rH2][cH2 + k] = H2[k]

                                        if not ok2:
                                            continue

                                        for k in range(len(V2)):
                                            if g2[rV + k][cV2 := cH2 + (i2 - j2)] not in ('.', V2[k]):
                                                ok2 = False
                                                break

                                        if ok2:

実装の重要な詳細は競合チェックです。文字がセルに配置されるときは常に、既存の文字と一致するか、空のドットを埋める必要があります。 これにより、異なる単語が交差点で不一致にならないことが保証されます。 

もう 1 つの微妙な点は、グリッドが試行ごとに新たに再構築されることです。 これにより、誤った失敗を引き起こす可能性がある、異なる順列またはアンカー間のキャリーオーバー汚染が回避されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、単語が文字を共有しているものの、互換性のある位置構造ではない場合です。 例えば、`ab`そして`ba`どちらも文字を共有していますが、3 番目と 4 番目の単語との一貫した交差を可能にする順序は 1 つだけです。 このアルゴリズムは、単に文字が存在するかどうかではなく、正確な座標の一貫性を要求することでこれを処理するため、不一致の位置合わせは拒否されます。 

別のケースとしては、単語内で文字が繰り返される場合があります。`aaa`。 これにより、複数の有効な交点が作成される可能性がありますが、アンカー位置の並べ替えを通じてそれぞれが独立して試行されます。 一貫性のない配置はグリッド競合チェックによって除外され、グローバルに一貫したレイアウトのみが確実に残ります。
