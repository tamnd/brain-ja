 ## 解決策
 ## 問題の理解

 私たちは、垂直方向の構造は固定されていますが、水平方向の配置が重要な 1 次元の幾何学的セットアップで作業しています。 高さ 2 に天井線、高さ 0 に床、そして高さ 1 に指定された x 座標に固定穴を含む中央の「スクリーン」があります。 ランプは天井のラインにのみ設置でき、各ランプはこの穴を通って床までまっすぐな光を放射します。 

所定の位置に 1 つのランプ$c$フロアポイントを直接選択しません。 代わりに、その光はその位置の穴を通過する必要があります。$a_i$、そしてその光線は床に当たるまで直線として続きます。 それぞれのペア$(c, a_i)$床上の照明点を 1 つだけ決定します。 重要な制約は、規定の床座標セットのみを照明できること、そして照明されたすべての点がこのセットに属していなければならず、他の床位置が光を受けてはいけないことです。 

入力により、2 セットの x 座標が与えられます。つまり、中央線上の穴の位置と、床上の必要な照明位置です。 課題は、穴を通過するすべての光線の結合が必要な床セットに正確に当たり、その外側には何も当たらないように、天井にいくつかのランプを配置できるかどうかを決定することです。 これが可能であれば、有効なランプ構成も 1 つ構築する必要があります。 

制約$n, m \le 2000$二次推論またはわずかに超二次推論は受け入れられるが、暗黙的にすべてを探索するものは何でもよいことを暗示しています。$O(nm)$構造化されていない方法でペアリングを行うと、何千万もの派生状態に影響を与える危険があります。 つまり、各候補構成を迅速に検証できる定式化、または有効な構成の構造が大幅に制限された定式化が必要です。 

微妙なエッジケースは、過剰な照明によって発生します。 構成は、必要なすべてのフロア ポイントに正しくヒットする可能性がありますが、誤って他の穴を介して余分なポイントを生成することもあります。 たとえば、ランプが 1 つの穴を介して 1 つの正しいフロア ポイントを生成する場合でも、他のすべての穴を介して追加のポイントを生成し、それらもターゲット セットに属している必要があります。 全体的な一貫性をチェックせずに、いくつかの穴をいくつかの床点に一致させるだけの単純なアプローチでは、無効な構造が受け入れられてしまいます。 

もう 1 つの問題は重複生成です。 1 つのランプで複数のフロア ポイントが生成される可能性があるため、ランプとターゲット ポイント間の 1 対 1 マッピングと考えることは、そのような削減が常に可能であることを証明しない限り誤りです。 

## アプローチ

 最初の自然な試みは、幾何学の観点から直接考えることです。 ランプの位置を修正する$c$そして穴$a$。 通るライン$(c,2)$そして$(a,1)$予測可能な x 座標で床まで伸びます。 直線方程式を解くと、直接代数マッピングが得られます。$$b = 2a - c$$したがって、各ランプは、ランプの位置を中心とした鏡映対称性によって、すべての穴の位置をフロア ポイントに変換します。 

これは、ブルートフォース戦略を即座に示唆します。つまり、穴と必要なフロア ポイントの組み合わせから導き出されるすべての可能なランプ位置を試します。 穴があったら$a_i$フロアポイントに貢献することを目的としています$b_j$、ランプの位置は強制的に次のようになります。$c = 2a_i - b_j$。 このようなランプを仮定すると、そのすべての出力をシミュレートし、それらが許容される下限値内に収まるかどうかを検証できます。 

これは正しいですが、高価です。 がある$O(nm)$候補ランプをすべてチェックする必要があり、各検証ではすべてのランプをチェックする必要があります。$n$穴、につながる$O(n^2 m)$最悪の場合、処理が大きすぎます。 

重要な観察は、有効なランプには非常に制約があるということです。 ランプの位置が変わると$c$固定されているため、すべての穴が独立してフロアポイントを生成します$2a_i - c$であり、それらはすべてターゲット セット内に存在する必要があります。 これは、各候補ランプが、1 つの一致するペアだけではなく、すべての穴にわたるグローバルな一貫性条件によって完全に決定されることを意味します。 問題は値を見つけることになります$c$すべての穴の変換されたセットが指定された床セットに含まれるようにし、必要なすべての点を正確にカバーするのに十分な数のランプを選択します。 

これにより、マッピングの構築から、ターゲットのフロア位置に設定されたハッシュを使用して変換候補を効率的に検証することに視点を移すことができます。

 ## アルゴリズムのチュートリアル

 1. 定数メンバーシップチェックのために、必要なすべてのフロアポイントをハッシュセットに保存します。 これが必要なのは、すべての妥当性テストで、生成されたポイントが許可されるかどうかを繰り返し照会するためです。 
2. すべてのペアを列挙します$(a_i, b_j)$候補ランプ位置を計算します$c = 2a_i - b_j$。 これは、ランプが少なくとも 1 つの必要なフロア ポイントを生成する少なくとも 1 つの穴と一致する唯一の方法です。 
3. 各候補者について$c$、すべてのホールを反復して検証します。 穴位置ごとに$a_k$、誘導されたフロアポイントを計算します$2a_k - c$。 そのようなポイントが必要なフロア セットにない場合は、この候補を破棄します。 
4. 候補が検証に合格した場合、それを有効なランプ位置として保存します。 複数のペアが同じものを生成する可能性があるため、$c$、セットを使用して結果の重複を排除します。 
5. すべての有効なランプ位置を出力します。 有効な各ランプは許可されたフロア ポイントのみを個別に生成するため、そのようなランプをすべて結合しても禁止ポイントが導入されることはありません。 

正しさは、すべての有効な解に、少なくとも 1 つの穴と床のペアから導出された反射として位置が表示されるランプが含まれている必要があるという事実にかかっています。 有効なランプは次の条件を満たす必要があります。$c = 2a_i - b_j$したがって、このように候補を制限することで、実現可能な構成を見逃すことはありません。 

### なぜ効果があるのか

 ランプは、すべてのホールが許可されたフロア セットにマッピングされている場合にのみ有効です。 これは単一の値に対するグローバル制約です。$c$、どのように発見されたかは関係ありません。 有効なランプは、少なくとも 1 つのホールを通じて少なくとも 1 つの観察されたフロア ポイントを説明する必要があるため、1 つのサポート ペアから導出されたすべての値を列挙することで完全性が保証されます。 そのような候補が見つかると、完全な検証により、無効なフロア位置を生成する穴がないことが強制されます。これはまさに問題の要件です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    B = set(b)
    candidates = set()

    # generate all possible lamp positions from one supporting pair
    for ai in a:
        for bj in b:
            c = 2 * ai - bj
            candidates.add(c)

    good = []

    for c in candidates:
        ok = True
        for ai in a:
            if (2 * ai - c) not in B:
                ok = False
                break
        if ok:
            good.append(c)

    if not good:
        print("No")
        return

    print("Yes")
    print(len(good))
    print(*good)

if __name__ == "__main__":
    solve()
```実装は、ハッシュ セット内のターゲット フロア ポイントをエンコードすることから始まります。これは、検証中の定数メンバーシップ チェックに不可欠です。 ネストされたループは、導出された公式を使用して、すべての候補ランプ位置を構築します。$c = 2a_i - b_j$。 これにより生成されますが、$O(nm)$複数のサポート ペアが同じランプ位置につながる可能性があるため、これは重要です。 

次に、すべてのホールからのすべてのフロア出力を再構成することによって、各候補が検証されます。 内側のループは重要な正確性のステップです。これにより、穴によって無効なフロア ポイントが生成されないことが保証されます。 障害発生時に早期に中断することで、ほとんどの無効なケースで不必要な作業が防止されます。 

最終出力は単にすべての有効なランプをリストするだけであり、これは候補の空間内で見つかったすべての一貫した変換を選択することに対応します。 

## 実用的な例

 穴があるサンプルを考えてみましょう$[0, -1, 1]$必要なフロアポイントは次のとおりです。$[4, 0, -2, 2]$。 

ペアごとに、次のような候補ランプを生成します。$c = 2 \cdot 0 - 4 = -4$、$c = 2 \cdot 1 - 2 = 0$、 等々。 フィルタリング後のみ$c = 0$フロアポイントが生成されるため、有効なままです。$\{0, 2, -2, 2\}$、それらはすべてターゲット セットに含まれています。 

| 候補者$c$| ホールチェック結果 | 有効 |
 | --- | --- | --- |
 | -4 | 設定外の値を生成します | いいえ |
 | 0 | セット内のすべてのマップされた値 | はい |
 | 2 | 設定外の値を生成します | いいえ |

 これは、アルゴリズムが局所的に妥当なランプだけではなく、グローバルに一貫したランプのみを分離していることを裏付けています。 

次に、より小さなケースを考えてみましょう。$n=2, m=2$の穴$[3,4]$、および必要なフロア ポイント$[2,6]$。 1 つの穴が常にセットにないフロア ポイントを生成するため、ペアリングから導出されたすべての候補ランプは検証に失敗します。 これは、グローバル チェックによって部分的に一貫した構成がどのように排除されるかを示しています。

 ## 特殊なケース

 重大なエッジ ケースは、複数の候補が同じランプ位置に収まる場合です。 たとえば、異なるホールとフロアのペアが同じ値を生成する可能性があります。$c$重複排除に失敗すると、ランプの数が過剰にカウントされ、下流の推論を誤解する可能性があります。 アルゴリズムは、検証前に候補をセットに保存することでこれを処理します。 

もう 1 つのエッジ ケースは、候補者が 1 ホールを除くすべてのホールでパスし、無効なフロア ポイントが 1 つ生成される場合に発生します。 たとえその無効な点が数値的に有効な点に「近い」としても、それは完全に拒否されなければなりません。 すべてのホールの完全なスキャンにより、部分的な有効性が受け入れられないことが保証されます。 

最後のエッジケースは、候補がまったく存在しない場合です。 これは、ホールとフロアの関係の構造に一貫性がなく、候補セットが空になった場合に発生します。 穴を通る単一のフロア ポイントを局所的に説明する実現可能なランプ位置がないため、アルゴリズムは正しく「いいえ」を即座に出力します。
