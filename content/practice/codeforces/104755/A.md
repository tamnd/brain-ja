 ## 解決策
 ## 問題の理解

 私たちには短いポスターテキストと、3 つの固定色を使用して書くことができるペンが与えられます。 各色には、使用できる文字数に制限があります。 重要な制約は、個々の文字を自由に色付けすることではなく、文字の種類を 3 つの色に分割することです。 

テキスト内のすべての文字は、文字、数字、句読点の 3 つのカテゴリのいずれかに正確に属します。 スペースはテキスト内に存在しますが、これらのカテゴリの一部ではないため、どの色のインクも消費しません。 ここでのタスクは、そのカテゴリ内の文字の総数がその色で使用可能なインクを超えないように、各カテゴリを個別の色に割り当てることができるかどうかを決定することです。 

言い換えれば、文字、数字、句読点を青、黄、赤の色のセットに注入的にマッピングする必要があり、このマッピングを選択した後、各カテゴリの数が割り当てられた容量内に収まる必要があります。 

入力制限は小さく、テキストの長さは最大 1000 です。これは、カテゴリーが 3 つしかなく、したがって可能な割り当てが 6 つしかないため、一定数の構成を数えてチェックすれば十分であることをすぐに示唆しています。 

素朴だが重要な落とし穴は、1 つのカテゴリ内で色が混合できると想定することです。 たとえば、文字を複数の色に分割しようとすると、各カテゴリに 1 つの色を正確に割り当てる必要があるというルールに違反します。 もう 1 つの微妙な問題は、どのカテゴリにも属さないスペースを無視することを忘れていることです。 

間違いが起こり得る小さな例は次のとおりです。 

入力:

 ICPC

 1 1 10

 文字 = 4、句読点 = 0、数字 = 0。文字を色間で分割することを誤って許可すると、実現可能性を誤って結論付ける可能性がありますが、問題はそれを許可しません。 

正しい出力は次のとおりです。 

いいえ

 割り当ての制約に応じて、一部のマッピングでは 4 が 1 と 10 の両方を超えるためです。 

## アプローチ

 この強引なアイデアは、3 つのカテゴリの 3 つの色への割り当てをすべて試してみることです。 課題ごとに、テキスト内の文字、数字、句読点の合計数を計算し、各カテゴリが割り当てられた容量に収まるかどうかを確認します。 

正確に 3 つのカテゴリと 3 つの色があるため、マッピングの数は 3 階乗、つまり 6 になります。マッピングごとに、テキスト全体を 1 回スキャンしてカテゴリの頻度をカウントします。 最大長が 1000 の場合、最大約 6000 文字のチェックが行われますが、これは厳しい制限の下でもわずかです。 

重要な洞察は、構造が動的でも、順列を超えた組み合わせでもないということです。 カテゴリ内の文字間に依存関係はなく、集計数と固定容量の間にのみ依存関係があります。 これにより、問題は、代入や DP のように見えるものから、定数因数の順列チェックの問題に縮小されます。 

ブルート フォースはすでに十分に高速に実行されますが、概念的な簡略化により、唯一の自由度がカテゴリからカラーへのマッピングの 6 つの順列であることが認識されます。

 ## アルゴリズムのチュートリアル

 まず、テキスト内の文字数、桁数、句読点文字の数という 3 つの値を計算します。 スペースは完全に無視されます。 

その後、3 つのカテゴリを利用可能な 3 つの色に可能な限り割り当ててみます。 各割り当ては、1 つのカテゴリ数と 1 つの容量制限を組み合わせます。 

割り当てごとに、3 つのカテゴリの数がすべて、割り当てられた容量以下であるかどうかを確認します。 少なくとも 1 つの有効な割り当てが見つかった場合、投稿者は可能であるとすぐに結論付けることができます。 

6 つの割り当てのいずれも制約を満たさない場合、答えは不可能です。

### なぜ効果があるのか

 それぞれの有効な解決策は、3 つのカテゴリと 3 つの色の間で全単射を選択することに正確に対応します。 容量は色ごとに固定されているため、実現可能性は、選択した組み合わせが 3 つの不等式すべてを同時に考慮するかどうかによってのみ決まります。 すべての全単射を列挙することで、有効なマッピングが欠落していないことが保証され、カテゴリが割り当てられると相互作用しないため、それらを個別にチェックすることで正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    b, y, r = map(int, input().split())
    s = input().rstrip('\n')

    letters = digits = punct = 0

    punct_set = set([',', '-', ';', ':', '.', '!', '?'])

    for ch in s:
        if ch == ' ':
            continue
        if ch.isalpha():
            letters += 1
        elif ch.isdigit():
            digits += 1
        else:
            punct += 1

    counts = [letters, digits, punct]
    caps = [b, y, r]

    import itertools

    for perm in itertools.permutations(caps):
        ok = True
        for i in range(3):
            if counts[i] > perm[i]:
                ok = False
                break
        if ok:
            print("Yes")
            return

    print("No")

if __name__ == "__main__":
    solve()
```コードはまず、単純な文字分類を使用してテキストを 3 つの必須カテゴリに分類します。 文字は次の方法で検出されます。`isalpha`、数字を使用して`isdigit`、スペース以外のすべては句読点として扱われます。 句読点は既知の小さなセットに明示的に制限されているため、これは問題定義と一致しますが、分類ルールはフォールバック ブランチによって安全にキャプチャされます。 

次に、3 つのカウントと 3 つの容量をマルチセットとして扱います。 容量を並べ替えることにより、カテゴリへの色の割り当てをすべてシミュレートします。 各順列は一定時間内に独立してチェックされます。 

微妙な点は、スペースがテキスト内に表示されますが、どのカテゴリにも属さないため、スペースを確実に除外することです。 明示的な`continue`これをきれいに処理します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from __main__ import solve
    import sys as _sys
    from io import StringIO
    out = StringIO()
    _stdout = _sys.stdout
    _sys.stdout = out
    solve()
    _sys.stdout = _stdout

assert run("21 8 2\nICPC Programming Season 2023-2024!\n") == "No"

# sample-like case: possible

# minimum size, single letter
assert run("1 1 1\na\n") == "Yes"

## 特殊なケース

 1 つのカテゴリが空の場合、微妙なエッジ ケースが発生します。 たとえば:

 入力:```
1 1 1
abc123
```ここでは句読点はゼロです。 アルゴリズムは依然として句読点をカウント 0 のカテゴリとして扱い、0 ≤ 容量が常に成り立つため、句読点が任意の色にマッピングされる割り当ては有効なままになります。 順列チェックでは、特別な処理を行わずにこれに自然に対応します。 

もう 1 つのエッジ ケースは、すべての文字が 1 つのカテゴリに属する場合です。 

入力:```
10 10 10
abcdef
```カウントは文字 = 6、数字 = 0、句読点 = 0 です。アルゴリズムはすべての順列をチェックし、文字が 6 以上の容量に割り当てられているマッピングは成功します。 このようなマッピングが少なくとも 1 つ存在するため、出力は正しくなります。`Yes`。 

最後のエッジ ケースには、特定の 1 つの置換のみが機能する密結合が含まれます。 すべての全単射が独立してテストされ、ヒューリスティックな枝刈りは適用されないため、ブルート順列ループにより、これが引き続き見つかることが保証されます。
