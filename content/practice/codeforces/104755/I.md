 ## 解決策
 ## 問題の理解

 すべての頂点が正の整数のラベルを持つ有向グラフが与えられます。 頂点からの各有向エッジ\(u\)頂点へ\(v\)\(\log_{a_u}(a_v)\) として定義された重みに寄与します。 有効なパスは、連続するすべてのペアが有向エッジによって接続されている、少なくとも 2 つの異なる頂点のシーケンスです。 パスの値はこれらのエッジの重みの積であり、すべての単純な有向パスにわたって可能な最大値を見つける必要があります。 

構造は重要です。グラフにはサイクルが含まれている可能性がありますが、有効なパスは頂点を繰り返すことができないため、常に単純なパスを扱います。 各エッジの量は乗法的であり、可変底の対数を通じて両方の端点に依存します。 

制約は次のとおりです\(n, m \le 2 \cdot 10^5\)。 パスを列挙しようとしたり、頂点のすべてのペアに対してペアごとの動的プログラミングを実行しようとしたりするソリューションは、直ちに実行不可能になります。 \(O(n^2)\) 遷移でさえすでに大きすぎるため、ノードごとの最短パスの計算を繰り返すものは通過しません。 唯一実行可能な方向は、エッジ上で線形または線形に近い伝播を伴うグラフ DP です。 

サイクルが存在する場合、微妙な障害が発生することがあります。 パスは単純でなければならないため、任意にノードを再訪できるベルマンフォードのよ​​うな単純な緩和を行うことはできません。 

三角形のサイクルを考えてみましょう。```
1 → 2 → 3 → 1
a1 = 2, a2 = 4, a3 = 8
```各エッジは以下に貢献します。\(\log_2 4 = 2\)、\(\log_4 8 = 1.5\)、\(\log_8 2 = 1/3\)。 

循環を続ける単純なアルゴリズムでは、「頂点を繰り返さない」という制約を無視すると、値が誤って増幅されてしまいます。 正しい答えは、散歩ではなく、単純な道から導き出される必要があります。 

もう 1 つの微妙な問題は、数値の安定性です。 答えは多くの対数の積であるため、値は急速に縮小または拡大する可能性があり、浮動小数点精度は慎重に制御する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、グラフ内のすべての単純なパスを試し、エッジ積を計算し、最大値を取得します。 この定義はすべての単純なパスに直接及ぶため、これは概念的には正しいです。 ただし、一般的な有向グラフ内の単純なパスの数は、次のように指数関数的に増加する可能性があります。\(n\)、高密度の DAG のような構造では \(O(2^n)\) に達します。 非常に小さいものを超えると、それらを保存したり列挙したりすることさえ不可能です\(n\)。 

この問題を軽減するために、エッジの重みが代数的にどのように動作するかに焦点を当てます。 各エッジは \(\log_{a_u}(a_v)\) に寄与し、自然対数を使用して書き換えることができます。\[
\log_{a_u}(a_v) = \frac{\ln a_v}{\ln a_u}.
\]次にパスを考えてみましょう\(v_1 \to v_2 \to \dots \to v_k\)。 その値は次のようになります。\[
\prod_{i=1}^{k-1} \frac{\ln a_{v_{i+1}}}{\ln a_{v_i}}.
\]この表現は望遠鏡になります。 すべての中間条件はキャンセルされます。\[
\frac{\ln a_{v_2}}{\ln a_{v_1}} \cdot \frac{\ln a_{v_3}}{\ln a_{v_2}} \cdots \frac{\ln a_{v_k}}{\ln a_{v_{k-1}}}
= \frac{\ln a_{v_k}}{\ln a_{v_1}}.
\]したがって、パス全体の重みは、内部構造ではなく、そのエンドポイントのみに依存します。 

これが重要な構造崩壊です。パスを検索する代わりに、頂点のペアのみを考慮します。\(u \to v\)からの単純なパスが存在するように、\(u\)に\(v\)。 このような到達可能性については、そのペアからの最良の寄与は \(\ln(a_v)/\ln(a_u)\) として固定されます。 

したがって問題は、有向グラフ内の到達可能なすべてのペアのうち、\(\ln(a_v)/\ln(a_u)\) を最大化することです。 

これは、到達可能性の制約に対する比率を最大化するものとして再構成できます。 到達可能なコンポーネントごとに可能な限り最適な開始ノードを追跡する方法で、到達可能性を伝播する必要があります。 

有用な解釈は、各ノードを、そこから始まるパスの候補値「可能な限り最良の分母」を運ぶものとして扱うことです。 頂点を昇順に処理すると、\(a_v\)の場合、分母を最小化すると比率が最大化されるため、各到達可能な領域で可能な限り最小の \(\ln(a_u)\) を維持しながら到達可能性を伝播できます。 

これは、トポロジー的には無関係だが値でソートされた伝播プロセスに対する DP につながります。頂点を次の基準でソートします。\(a_v\)、隣接構造を介して到達可能性情報を維持しながら、それらを段階的にアクティブ化します。 アクティブ化されたノード上でのユニオンのような伝播または BFS のような拡張により、到達可能な最適なペアが得られます。

 |---|---|---|---|

 | 値別に分類された到達可能性 DP | \(O((n + m)\log n)\) | \(O(n + m)\) | 承認済み |

 ## アルゴリズムのチュートリアル

 対数の比率がエッジの寄与を定義するため、問題をラベルの対数を扱う問題に変換します。 \(w_v = \ln(a_v)\) を事前計算します。 

1. すべての頂点を降順に並べ替えます。\(a_v\)、等価的に減少します\(w_v\)。 この順序により、ノードを潜在的なエンドポイントとして処理するときに、より大きなラベルを持つすべての候補がすでに考慮されることが保証されます。 より大きなエンドポイント値が比率を支配する傾向があるため、これは非常に重要です。 

2. どの頂点がすでに「アクティブ化」されているかを追跡する構造を維持します。つまり、検討中のパスの開始点として機能できます。 

3. ソートされた順序で頂点を処理します。 頂点をアクティブにするとき\(v\)、エッジを許可します\(u \to v\)どこ\(u\)有効な遷移を形成するためにすでにアクティブになっています。 このようなエッジごとに、次で終わる到達可能な最良の値を更新しようとします。\(v\)ログ間の関係を使用します。 

4. アクティブエッジごとに\(u \to v\)、候補値を計算します。\[
\frac{\ln(a_v)}{\ln(a_u)}.
\]私たちは、そのようなすべての移行にわたって世界最大値を維持します。 

5. 受け取った寄付を処理した後、\(v\)、 マーク\(v\)アクティブとして、ソートされた順序で将来の頂点のソースとして機能できるようにします。 

各ステップでは、エッジを考慮するときに、そのソースが最適な分母と一致する有効な到達可能性コンテキストにすでに配置されていることを確認します。 

### なぜ効果があるのか

 伸縮プロパティは、すべての単純なパスをそのエンドポイントのみの関数に折りたたみます。 したがって、パスの中間構造は、到達可能性を除いて無関係です。 ラベルによる並べ替えにより、頂点が潜在的な終点とみなされるときに、パスの開始点の有効な候補がすべてすでに導入されていることを確認できます。 これにより、到達可能なすべてのペアが比率の最大化と一致する方向に 1 回だけ評価され、無効なマルチアクセス パスが構築されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math
from collections import defaultdict, deque

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    rg = [[] for _ in range(n)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        rg[v].append(u)

    # work with log values
    w = [math.log(x) for x in a]

    order = sorted(range(n), key=lambda i: w[i], reverse=True)

    active = [False] * n
    ans = 0.0

    # For each node as endpoint candidate in decreasing order
    for v in order:
        # try all incoming active edges
        for u in rg[v]:
            if active[u]:
                ans = max(ans, w[v] / w[u])

        active[v] = True

    # path must have at least 2 vertices, so ans already covers edges
    print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```この実装は、ノード ラベルの対数の事前計算に依存しています。 ノードをエンドポイントとして処理するときに、潜在的なすべての先行ノードを効率的に検査できるように、グラフを反転します。 アクティブな配列では、ソート順の構造と一致して、すでに処理されたノードのみがパスの開始点として機能できることが強制されます。 

部門`w[v] / w[u]`は、伸縮パスの値に正確に対応します。 このような到達可能なペアすべての最大値が答えです。

 ## 特殊なケース

 重要なエッジ ケースは、サイクルは存在するが、一部のエッジのみが寄与する必要がある場合です。 ラベルが増加する 3 サイクルでは、アルゴリズムにより、すでにアクティブ化されたノードからのエッジのみが考慮されるため、無効なマルチステップ サイクリングは発生しません。 

もう 1 つのケースは、最適なパスが長いパスではなく直接エッジである場合です。 すべての頂点は最終的にアクティブ化され、すべての入力エッジはエンドポイントの処理時に 1 回だけチェックされるため、直接エッジは引き続き正しいコンテキストで評価され、スキップすることはできません。 

最後のケースは、チェーンを厳密に減少または増加させることです。 これらのグラフでは、アクティブ化順序により、エンドポイントが処理されるときに各エッジが正確に評価されることが保証され、最大比率は複数ステップの累積ではなく、エッジごとの 1 つの比較から得られます。
