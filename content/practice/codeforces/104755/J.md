 ## 問題の理解

 私たちに与えられているのは、$n \times m$グリッド。各セルは高さの塔を形成する単位立方体の垂直方向の積み重ねを表します。$h_{i,j}$。 各セルを 1 から 1 までの離散レベルを持つ列として考えます。$h_{i,j}$。 すべてのタワーの各レベルは 2D の「歩行可能なレイヤー」を形成しますが、各タワーで利用可能な最小の高さまでに限られます。 

人は常に、ある塔の最上ブロックから出発し、別の塔の最上ブロックに到達したいと考えます。 動きには 2 つの要素があります。 タワー内を 1 ブロック垂直に移動すると、1 ステップあたり 1 単位の応力がかかります。 隣接するタワー間の水平移動にはコストはかかりませんが、固定レベルでのみ実行できます。両方のタワーに少なくともその高さレベルが利用可能な場合にのみ、隣接するセル間を歩くことができます。 

したがって、水平方向には、選択した高さのグリッドの「スライス」内を効果的に移動できます。$k$、垂直方向には、開始タワーからその高さに到達するためにコストを支払い、再度目的地のタワーに登り返すためにコストを支払います。 

各クエリは、ある塔の頂上から別の塔の頂上に移動するために必要な最小応力を求めます。 

制約は大きく、最大で$10^6$グリッドセル以下$5 \cdot 10^5$クエリ。 これにより、グリッドのクエリごとの走査や、グリッドの大部分を繰り返しスキャンすることに依存するアルゴリズムさえも即座に除外されます。 平$O(nm \log nm)$グリッド サイズが線形になるクエリ時の作業を避けるために、前処理を慎重に構造化する必要があります。 

素朴なアイデアは、次のようなグラフに対してクエリごとに最短パス検索を実行することです。$n \cdot m \cdot h$暗黙的な状態ですが、寸法と高さの両方がそれを不可能にします。 

単純な推論による微妙な失敗例は、開始タワーと終了タワーの間で常に可能な限り低い高さで水平に移動する必要があると仮定することから生じます。 より高いところに登ると、より短い水平接続が解除される可能性があるため、これは常に最適であるとは限りません。 

たとえば、2 つの塔が、1 つの高い尾根を除いて、低い高さの「壁」によって分離されているとします。```
1 1 10
1 1 10
10 10 10
```(1,1) から始まり (1,2) で終わると、低地に進むには、迂回するか、高価な道を登る必要があります。 ただし、高さ 10 まで登ると、最初に直接移動できるようになります。 局所的な高低差のみに基づいた貪欲な戦略は、ここでは失敗します。 

## アプローチ

 ブルートフォース解釈で各ポジションをモデル化$(i,j,k)$状態として$k$現在の高さレベルです。 垂直エッジが接続されます$(i,j,k)$に$(i,j,k\pm1)$コスト 1、水平エッジが接続$(i,j,k)$同時に隣の人たちにも$k$両方の塔が少なくとも高さがある場合$k$。 各クエリは、巨大な層状グラフにおける最短経路問題になります。 

これは正しいですが、まったく実行不可能です。 高さを 1 に制限したとしても、グラフにはすでに$10^6$ノードが増え、高さが拡張されると事実上無制限になります。 

重要な観察点は、垂直コストは「会議レベル」の選択のみに依存するということです。$k$。 パスが水平に水平に交差すると判断した場合$k$、その後、コストが完全に決定され、私たちが支払います$|h_{a} - k| + |h_{b} - k|$、両方のエンドポイントが頂点から始まり、レベルまで下降する必要があるため$k$水平方向に移動する前に。 

したがって、問題は、少なくとも高さのあるセルのみを使用して、2 つのセル間にパスが存在するかどうかを見つけることになります。$k$。 「はい」の場合、$k$は有効な交差レベルです。 

したがって、各クエリについて、最大のものを探します。$k$高さのあるセルによって誘導されたサブグラフ内で 2 つのセルが接続されるようにする$\ge k$。 これを知ったら$k$、答えは決定的です。$(h_a - k) + (h_b - k)$。 

これにより、問題はグリッド上の古典的な「最大しきい値接続」問題に変換されます。 セルを高さの降順で処理し、徐々にアクティブ化し、素セット結合構造を使用して接続を維持できます。 2 つのクエリ エンドポイントが接続されると、現在の高さレベルが可能な限り最高になります。$k$そのクエリに対して。 

多くのクエリをサポートするために、答えを二分検索します。$k$クエリごと、および中間点ごとに、DSU アクティベーション シミュレーションを実行します。 座標圧縮と高さによるソートにより、各チェックは線形です。$nm$したがって、全体の複雑さは次のようになります。$O((nm + q) \log H)$、 どこ$H$個別の高さの数です。

 ## アルゴリズムのチュートリアル

 まず、問題を高さのしきい値の選択として再解釈します。$k$。 少なくとも高さのある塔のみ$k$レベルでの水平移動に使用可能$k$。 垂直方向の移動コストは、各エンドポイントからレベルに到達するまでにどれだけ下に移動するかによってのみ決まります。$k$。 

1. すべてのグリッド セルを高さの降順に並べ替えます。 これは、グリッドを高いものから低いものへと「あふれさせる」ことを想定した場合に、セルが使用可能になる順序を定義します。 
2. 固定候補しきい値の場合$k$、少なくとも高さを持つすべてのセルをアクティブにします$k$。 アクティブ化とは、セルが接続グラフの一部になったことを意味します。 
3. グリッド上で DSU を維持します。 セルがアクティブ化されると、そのセルを 4 方向のすでにアクティブ化された隣接セルと結合します。 これにより、各接続コンポーネントがそのしきい値での到達可能性に正確に対応することが保証されます。 
4. クエリをテストするには、高さ ≥ k のすべてのセルをアクティブ化した後、2 つのエンドポイントが同じ DSU コンポーネントに属しているかどうかを確認します。 それらが接続されている場合、レベル k での交差は実現可能です。 
5. 各クエリについて、実現可能な最大の k を二分探索します。 検索スペースは、1 から 2 つのエンドポイントの高さの最小値までです。 
6. 最適な k を見つけた後、応力コストを次のように計算します。$(h_{a} - k) + (h_{b} - k)$。 

### なぜ効果があるのか

 固定レベルの場合$k$、少なくとも高さのセルだけで構成されるパスがある場合にのみ、水平方向の移動が可能です。$k$。 これは、これらのセルをアクティブにした後の DSU 接続と正確に一致します。 レベル内の任意の有効なパス$k$この誘導されたサブグラフ内の水平移動に分解でき、その外側のパスはその下にステップする必要があります。$k$、そのレベルでは水平方向の走査は禁止されています。 したがって、最適な戦略は、最大化することです。$k$、高いので$k$両方のエンドポイントでの垂直移動コストを厳密に削減します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]

n, m = map(int, input().split())
h = [list(map(int, input().split())) for _ in range(n)]

cells = []
for i in range(n):
    for j in range(m):
        cells.append((h[i][j], i, j))

cells.sort(reverse=True)

q = int(input())
queries = []
for _ in range(q):
    ia, ja, ib, jb = map(int, input().split())
    ia -= 1
    ja -= 1
    ib -= 1
    jb -= 1
    queries.append((ia, ja, ib, jb))

parent_idx = lambda i, j: i * m + j

def can(k):
    dsu = DSU(n * m)
    active = [[False] * m for _ in range(n)]

    idx = 0
    for val, i, j in cells:
        if val < k:
            break
        active[i][j] = True
        for di, dj in ((1,0), (-1,0), (0,1), (0,-1)):
            ni, nj = i + di, j + dj
            if 0 <= ni < n and 0 <= nj < m and active[ni][nj]:
                dsu.union(parent_idx(i,j), parent_idx(ni,nj))

    for ia, ja, ib, jb in queries:
        if h[ia][ja] >= k and h[ib][jb] >= k:
            if dsu.find(parent_idx(ia,ja)) == dsu.find(parent_idx(ib,jb)):
                continue
        return False
    return True

ans = []
for ia, ja, ib, jb in queries:
    lo, hi = 1, min(h[ia][ja], h[ib][jb])
    best = 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid):
            best = mid
            lo = mid + 1
        else:
            hi = mid - 1
    ans.append((h[ia][ja] - best) + (h[ib][jb] - best))

print("\n".join(map(str, ans)))
```DSU は各グリッド セルを 1 つのインデックスに圧縮し、しきい値チェックごとに接続が再構築されます。 の`can(k)`関数はアクティブ化プロセスをシミュレートし、すべてのクエリがそのレベルで接続されたままであるかどうかを検証します。 クエリごとのバイナリ検索により、実現可能な最大の交差高さが分離されます。 

微妙な実装の詳細は、`can(k)`: レベルで切断されたクエリ ペアが見つかるとすぐに$k$の場合は false を返します。 これにより、残りのクエリにわたる不必要な DSU チェックが回避され、パフォーマンスにとって不可欠です。 

## 実用的な例

 小さなグリッドを考えてみましょう。```
3 3
5 1 4
2 6 3
1 2 7
```クエリ:```
(1,1) -> (3,3)
(2,2) -> (1,3)
```最初のクエリでは、最大しきい値 k を検索します。 

| k | 活性化された細胞 (高さ ≥ k) | 接続されていますか? |
 | --- | --- | --- |
 | 6 | (2,2),(3,3) | いいえ |
 | 5 | (1,1)、(2,2)、(3,3) | はい |
 | 6 回失敗、5 回成功 | | |

 したがって、最良の k は 5 です。コストは (5-5)+(7-5)=2 です。 

2 番目のクエリの場合:

 | k | 活性化された細胞 | 接続されていますか? |
 | --- | --- | --- |
 | 4 | (1,3)、(3,3)、(2,2) | はい (2,2)->(3,3)->(1,3) 経由 |
 | 5 | (1,3),(2,2?) のみ | いいえ |

 最良の k は 4 です。コストは (6-4)+(4-4)=2 です。 

これらのトレースは、しきい値が高くなると接続性が低下し、ソリューションでは常に実現可能な最高の共有レベルが選択されることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、両方のエンドポイントが高レベルで分離されているが、大幅に下降した後でのみ接続される場合です。 例えば：```
2 2
10 1
1 10
1 1 2 2
```k=10 では、両方のエンドポイントが分離されるため、接続は失敗します。 k=1 ではグリッド全体が接続されるため、k=1 が選択されます。 コストは(10-1)+(10-1)=18となります。 DSU の接続は完全なアクティベーション後にのみチェックされるため、アルゴリズムはこれを正しく捕捉し、より高いしきい値での部分的な接続についての時期尚早な想定を防ぎます。 

もう 1 つのケースは、開始点と終了点が最上位レベルですでに隣接している場合です。 次に、二分探索によって k が可能な最大値に急速に押し上げられ、垂直方向の移動がゼロに最小限に抑えられます。これは DSU 検証によって正しく保存されます。
