 ## 解決策
 ## 問題の理解

 部分的に埋められた 4 × 4 のグリッドが与えられ、これを有効な「4 倍数独」のバリエーションに完成させる必要があります。 各セルには 1 から 4 までの数字が含まれていますが、一部のセルはゼロであり、入力する必要があります。 

ルールはシンプルですが厳格です。 すべての行には、数字 1、2、3、4 がそれぞれ 1 回ずつ含まれている必要があります。 すべての列には、各数字が 1 回だけ含まれている必要があります。 最後に、4 つの 2 x 2 のサブ正方形のそれぞれに、4 桁すべてが 1 回だけ含まれている必要があります。 

このインスタンスの特別な構造は、左上の 2 x 2 ブロックと右下の 2 x 2 ブロックがすでに完全に埋められており、有効であることです。 右上と左下のブロックは空です。これは、すべてのセルがゼロであることを意味します。 このタスクは、グリッドを有効なソリューションに完成させることができるかどうかを判断し、完成した場合は完成したグリッドを出力することです。 

グリッド サイズは 4 x 4 に固定されているため、制約によってブルート フォースが排除されません。 唯一の本当の課題は、行、列、ブロックの制約を同時に処理する際の推論上の間違いを避けることです。 

最も危険なエッジ ケースは、ローカル行補完が可能であるように見えても、列制約または 2 x 2 ブロック制約に違反する場合です。 たとえば、列の左上のブロックにすでに 1 が含まれている場合、同じ列の左下のブロックに別の 1 を配置すると、行がまだ正しいように見えても、すぐに有効性が失われます。 

グリッドが非常に小さく、塗りつぶされた領域が構造化されているため、制約の伝播を無視する素朴なアプローチでもすぐに終了しますが、割り当てのたびに 3 つの制約すべてを注意深く遵守しないと、簡単に桁を間違えてしまう可能性があります。 

## アプローチ

 直接的なアプローチは、これを制約充足問題として扱うことです。 空のセルは合計 8 つあり、すべて右上と左下の 2 x 2 ブロックにあります。 これらの各セルは 4 つの値のいずれかをとります。 ブルートフォース戦略では、これらの空のセルに対するすべての割り当てが試行され、最大 4^8 の可能性が与えられます。 

完全な割り当てごとに、すべての行、列、およびサブグリッドの制約をチェックします。 これはすべての可能性を列挙しているため正しいですが、構成の数は 65536 であり、各検証ではグリッドを複数回スキャンする必要があります。 これでもまだ十分小さいですが、不必要な作業です。 

重要な観察は、ここでの数独制約の構造は、固定された 4 x 4 サイズと、すでに完成した対角ブロックの存在により、非常に厳密であるということです。 各行は、1 つの塗りつぶされた 2 x 2 ブロックと 1 つの空の 2 x 2 ブロックと正確に交差します。 つまり、行が部分的に埋められると、欠落している 2 つの値がセット {1,2,3,4} からの削除によって強制されます。 同じことが列にも当てはまります。 

自由に推測する代わりに、制約の伝播を使用して空のセルを徐々に埋めることができます。 行にちょうど 2 つの欠落セルがある場合、その行でまだ使用されていない残りの桁によって値が決定されます。 値が配置されると、すぐにその列とブロックが制約され、さらに強制配置がカスケードされます。 

グリッドが非常に小さく、最初に満たされたブロックがすでに完全な順列であるため、この伝播は深いバックトラックを必要とせずに収束します。 空のセルに有効な数字がないなど、どこかの時点で矛盾が発生した場合は、不可能であると結論付けます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O(4^8) | お(1) | 受け入れられるが不要 |
 | 制約の伝播 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 進歩が不可能になるまで、制約の除去の下でグリッドが進化するものとして扱います。

1. 指定された 4 × 4 グリッドから開始し、各行、列、および 2 × 2 ブロックにすでに表示されている数字を記録します。 すべての意思決定は、何が存在するかではなく、何が欠けているかによって決まるため、この簿記は不可欠です。 
2. すべての空のセルを繰り返しスキャンします。 各セルについて、行、列、ブロックでまだ使用されていない 1 から 4 までの数字のセットを計算します。 正確に 1 桁が可能な場合は、すぐにそれを割り当てます。 他の値は直ちに制約に違反するため、これは強制的な移動です。 
3. セルに値を割り当てた後、行、列、ブロックのレコードを更新します。 これにより、他のセルの可能性が減少する可能性があるため、新しい強制割り当てが表示されなくなるまでプロセスを繰り返し続行する必要があります。 
4. スキャン中に有効な候補がゼロのセルが見つかった場合は、終了して「いいえ」を返します。これは、すべての制約を満たすことができないためです。 
5. すべてのセルが埋まると、完成したグリッドが出力されます。 

これが効率的に機能する理由は、配置ごとに複数の方向のエントロピーが同時に減少するためです。 4 x 4 のラテン方陣構造では、各数字は行と列ごとに 1 回だけ出現するため、数字を配置すると、その数字が 3 つの制約ドメインから同時に削除されます。 

### なぜ効果があるのか

 このアルゴリズムは、すべてのステップで一貫した部分ラテン方陣を維持します。 不変条件は、すべての塗りつぶされたセルが行、列、およびブロックの一意性制約を満たし、すべての塗りつぶされていないセルが少なくとも 1 つの有効な数字が残っている位置を表すことです。 

すべての割り当ては、3 つの独立したセット (行、列、ブロック) によって制約されたサイズ 4 のドメインにわたる消去によって強制されます。 グリッドは非常に小さいため、有効なソリューションは最終的に完了するまで強制的な移動を公開する必要があります。 ある時点で強制的な移動が存在しない場合、残りのあいまいさには分岐が必要になりますが、初期条件が存在する場合には解の一意性が保証され、あいまいさの持続が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def block_id(r, c):
    return (r // 2) * 2 + (c // 2)

def solve():
    g = [list(map(int, input().split())) for _ in range(4)]

    row = [set() for _ in range(4)]
    col = [set() for _ in range(4)]
    blk = [set() for _ in range(4)]

    empty = []

    for r in range(4):
        for c in range(4):
            v = g[r][c]
            if v == 0:
                empty.append((r, c))
            else:
                row[r].add(v)
                col[c].add(v)
                blk[block_id(r, c)].add(v)

    changed = True
    while changed:
        changed = False
        new_empty = []
        for r, c in empty:
            if g[r][c] != 0:
                continue
            b = block_id(r, c)
            candidates = []
            for v in range(1, 5):
                if v not in row[r] and v not in col[c] and v not in blk[b]:
                    candidates.append(v)

            if len(candidates) == 0:
                print("No")
                return
            if len(candidates) == 1:
                v = candidates[0]
                g[r][c] = v
                row[r].add(v)
                col[c].add(v)
                blk[b].add(v)
                changed = True
            else:
                new_empty.append((r, c))
        empty = new_empty

    for r in range(4):
        for c in range(4):
            if g[r][c] == 0:
                print("No")
                return

    print("Yes")
    for row_vals in g:
        print(*row_vals)

if __name__ == "__main__":
    solve()
```この実装では、行用、列用、および 2 x 2 ブロック用の 3 つのセットの配列を使用して制約を追跡します。 機能`block_id`各セルが 4 つのブロックの 1 つにマッピングされるようにブロック構造をエンコードします。 

メイン ループは、すべての未解決のセルを繰り返しスキャンし、有効な候補を計算します。 重要な実装の詳細は、値が固有の有効なオプションである場合にのみ値をコミットすることです。 これにより、推測による推測が回避され、後戻りすることなく正確さが保証されます。 

微妙な点は、`empty`各パスの後にリストを作成します。 これにより、すでに解決されたセルを繰り返し再検討することがなくなり、ループが効率的かつ有限に保たれます。 

## 実用的な例

 ### 例 1

 入力:```
1 2 0 0
3 4 0 0
0 0 4 3
0 0 1 2
```初期状態:

 | ステップ | (0,2) | (0,3) | (1,2) | (1,3) | 進捗状況 |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | {3,4} | {3,4} | {1,2} | {1,2} | 0 が埋められています |

 最初のパスでは (0,2)=3、(0,3)=4 が割り当てられます。これは、行 0 に正確にこれらの桁が欠落しているためです。 同様に、行 1 は欠損値を強制します。 伝播後、列制約により、左下のブロックに残りの配置が強制されます。 

最終グリッドは矛盾なく完全に決定されます。 

このトレースは、行制約だけでもすでに伝播を開始するのに十分な強度があり、列/ブロック制約はプロセスを改良するだけであることを示しています。

 ## 特殊なケース

 1 つのエッジ ケースは、行が 1 つのセルを除いて完全に決定されているが、そのセルが列制約に違反している場合に発生します。 たとえば、行が`[1, 2, 0, 4]`列制約により禁止されています`3`最後の位置では、アルゴリズムは唯一の候補セットが空であることを正しく識別し、ただちに「いいえ」を出力します。 

もう 1 つのケースは、解が存在するにもかかわらず、伝播によってセルが一意に決定されない状況が生じる場合です。 この問題では、最初の対角ブロックが決定論的なカスケードを強制するのに十分な構造を固定しているため、そのような状況は発生しません。そのため、進歩の欠如は、指定された制約の下では不可能であることを意味します。 

最後のケースは、強制的な動きが現れる前に複数のパスが必要な場合です。 ループ構造により、安定するまで更新のたびに候補が再計算されるため、これが確実に処理されます。
