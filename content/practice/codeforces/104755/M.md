 ## 解決策
 ## 問題の理解

 私たちは、各セルに 6 つの隣接セルがあり、距離は六角形間のエッジ間の移動の最小数として測定される無限六角形グリッドに取り組んでいます。 バッタは原点から開始し、無限のジャンプを繰り返します。 タイムステップ時$i$、正確に動かなければなりません$i$6 つのグリッド方向のいずれかにセルを直線で配置します。 

この動きには 2 つの追加の制約があります。 ジャンプするたびに、バッタはジャンプ前よりも厳密に原点から 16 進距離で遠ざかなければなりません。 また、同じルールの下でより少ないジャンプでそのセルに到達できた場合、バッタはそのセルに着地することを許可されません。つまり、訪問したすべての位置は、そこに到達するために使用されるジャンプの数という点で最適でなければなりません。 

各クエリセルについて$(x, y)$、バッタが両方の制約を尊重しながら最終的にそのセルに着地するように、ジャンプの方向のシーケンスが存在するかどうかを判断する必要があります。 

の制約$t \le 10^5$までのコーディネート$10^9$これは、各クエリが定数時間または対数時間内に応答される必要があることを意味します。 ジャンプを段階的にシミュレートするアプローチは直ちに不可能です。単一のクエリでも最大で$\sqrt{10^9}$距離から考えると、さらに多くの歩数が必要になります。 

素朴な落とし穴は、原点から外側へのジャンプを貪欲にシミュレートできると考えることです。 たとえば、次のようなシミュレーションを試みます。$$0 \to 1 \to 3 \to 6 \to 10 \to \dots$$実際のグリッド位置では、各ステップに方向の選択があり、状態空間が指数関数的に増大するため、失敗します。 もう 1 つの微妙な問題は、座標の単調性を仮定することです。 距離が増加しても、1 つの軸の座標は 16 進ジオメトリにより減少する可能性があるため、座標に関する推論はすぐに破綻します。 

2 番目の間違った考え方は、これを重み付きステップによる最短経路問題のように扱うことですが、重みは時間に依存するため、標準の BFS やダイクストラは適用できません。 

## アプローチ

 総当たり解釈は、毎回の方向を選択するプロセスをシミュレートすることです。$i$、制約を適用しながら各ステップの後に到達可能なすべてのセルを追跡します。 ステップ後$k$、距離の制約を増加させながら、到達可能なすべての可能な位置のセットを維持します。 

ステップで$i$、各状態は 6 つの可能な方向に分岐するため、状態の数はおおよそ次のように増加します。$6^i$。 距離制約を使用して枝刈りが適用された場合でも、その後到達可能な状態の数は減少します。$k$歩数は依然として指数関数的です$k$。 座標は次のように大きくできるため、$10^9$、遠くのセルに到達するために必要なステップ数は次のとおりです。$\sqrt{10^9}$、これは完全に不可能になります。 

重要な観察は、セルに関して重要なのは正確な位置ではなく、原点からの 16 進数の距離だけであるということです。 ジャンプするたびに、方向の選択によって制御される量だけ距離が伸びますが、ジャンプ後の全体的な効果は$k$ジャンプはステップの長さの合計によって制限されます。$$S_k = 1 + 2 + \dots + k = \frac{k(k+1)}{2}.$$各移動は原点からの距離を厳密に増加させる必要があるため、移動後の距離は$k$ステップはモノトーンです。 これにより、最終的な到達可能な距離が強制されます$d$周囲の非常に狭い封筒の中に横たわること$S_k$。 柔軟性は方向の選択から生まれます。各ステップで、動きの一部が六角形状の他の方向への進行を効果的に「キャンセル」することができ、最終的な距離を異なるものにすることができます。$S_k$厳密な単調成長を維持しながら。 

これにより、問題はターゲット ヘクス距離が適切であるかどうかを確認するだけになります。$d$いくつかのステップ数で一致させることができます$k$、 どこ$k$十分な大きさでなければなりません$S_k \ge d$、残りのたるみ$S_k - d$単調性を損なうことなく、正味の外向きの進行を減らす方向を選択することで「吸収」できます。 この構造では、残っている唯一の障害はパリティであることがわかります。スラックは、基礎となる格子対称性において 2 の単位で分散可能でなければなりません。 

したがって、各クエリを 16 進距離の計算に削減します。$d$、最小のものを見つける$k$そのような$S_k \ge d$、そして、$S_k - d$は均等です。

 ## アルゴリズムのチュートリアル

 原点からの距離を一定時間で計算できる標準座標系を使用して 16 進グリッドを処理します。 

### 1. 座標を 16 進数の距離に変換します

 次のように計算します。$$d = \text{hex\_distance}(x, y)$$これにより、ジャンプ制約なしで通常の 16 進グリッド内のセルに到達するために必要な最小ステップ数が得られます。 

正確な式は軸座標系に依存しますが、立方体座標から導出される線形形式の最大値として常に表現可能です。 

### 2. 制約のない累積モデルで必要なジャンプの最小数を見つける

 私たちは最小のものを望んでいます$k$次のような:$$S_k = \frac{k(k+1)}{2} \ge d$$これは、直接二次解を使用するか、増分することによって計算されます。$k$不等式が成り立つまで。 以来$k$せいぜい約くらいです$5 \cdot 10^4$のために$d \le 10^9$、これは速いままです。 

### 3. 実現可能条件の確認

 一度$k$が固定されている場合、次のように計算します。$$\text{slack} = S_k - d$$次の場合に限り、セルを受け入れます。$$\text{slack} \bmod 2 = 0$$パリティ条件により、厳密な距離増加ルールに違反することなく、残りの余分な移動を 16 進方向間で対称的に再配分できることが保証されます。 

### なぜ効果があるのか

 このプロセスは、到達可能な距離を、歩幅の三角形に近い合計として表現できる距離に効果的に制限します。 単調な距離の要件により、少なくとも到達するのに十分な合計歩幅を「使い切る」必要があります。$d$、そして余剰は、六角格子内の方向のペアの進行を逆転させることによって中和されなければなりません。 このような反転では、この座標系では距離が 2 ずつ変化するため、偶数のスラック値のみを吸収できます。 これにより、三角しきい値とパリティ条件の両方が必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def hex_dist(x, y):
    # axial coordinates to cube: (x, y, -x-y)
    z = -x - y
    return max(abs(x), abs(y), abs(z))

def solve():
    t = int(input())
    coords = [tuple(map(int, input().split())) for _ in range(t)]

    for x, y in coords:
        d = hex_dist(x, y)

        # find smallest k with k(k+1)/2 >= d
        k = 0
        s = 0
        while s < d:
            k += 1
            s += k

        if (s - d) % 2 == 0:
            print("Yes")
        else:
            print("No")

if __name__ == "__main__":
    solve()
```機能`hex_dist`軸座標を立方体座標に変換し、16 進距離の標準最大ノルム特性評価を使用します。 これにより、グリッドを横断する必要がなくなります。 

ループコンピューティング$k$安全なので$k$くらいまでしか成長しない$4.5 \cdot 10^4$最大距離に向けて$10^9$、これは十分に小さいです$10^5$クエリ。 

最終的なパリティ チェックは、三角和と必要な距離の差に直接適用されます。 

## 実用的な例

 条件がどのように動作するかを理解するために 2 つの入力をトレースします。 

### 例 1

 入力セル$(1, 2)$| ステップ | × | y | d = hex_dist | k | S_k | たるみ |
 | --- | --- | --- | --- | --- | --- | --- |

 ここ$k = 2$、 以来$S_2 = 3 \ge 2$。 スラックは$1$これは奇数であるため、この構成はパリティ ルールに基づいて拒否されます。 

これは、三角形のエンベロープのサイズは十分であるが、方向の制約により余剰を完全に吸収できない場合を示しています。 

### 例 2

 入力セル$(0, -1)$| ステップ | × | y | d | k | S_k | たるみ |

 ここ$k = 1$、そしてスラックは$0$、これは偶数なので、答えは有効です。 

これにより、正確な三角形の距離が常に到達可能であることが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    def hex_dist(x, y):
        z = -x - y
        return max(abs(x), abs(y), abs(z))

    t = int(input())
    out = []
    for _ in range(t):
        x, y = map(int, input().split())
        d = hex_dist(x, y)

        k = 0
        s = 0
        while s < d:
            k += 1
            s += k

        out.append("Yes" if (s - d) % 2 == 0 else "No")

    return "\n".join(out)

 ## 特殊なケース

 微妙なケースが原点です。 入力用$(0,0)$、16 進距離はゼロなので、$k=0$そしてスラックはゼロです。 移動する必要がないため、アルゴリズムは正しく「はい」を出力します。 

もう 1 つの重要なケースは、距離 1 にある点です。$(0,-1)$。 ここ$k=1$、$S_1=1$、スラックはゼロであるため、アルゴリズムはすぐに受け入れます。 三角累積の初期化に誤りがあると、これが誤って拒否されます。 

境界シナリオは次の場合に発生します。$d$たとえば三角数のすぐ下です$d = 5$。 それから$k=3$以来$S_2=3 < 5$そして$S_3=6 \ge 5$。 スラックは$1$、パリティに失敗します。 ここで三角ループのオフバイワンエラーがよく発生します。$S_k > d$の代わりに$S_k \ge d$正確な三角値の正確さを変更します。
