 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられた駅の行が与えられます。 どの駅からも、ちょうど 2 本の下り道路があります。 各道路は列車をステーション 1 に戻すか、ステーション i + 1 に送ります。ただし、ステーション n からは両方の道路が常にステーション 1 に向かう点が異なります。 

電車はどこかの駅から出発します。 次に、正確に l 回の動作を実行します。 あらゆる瞬間にステーションに立ち、すでに各ステーションを訪れた回数を記録します。 主要なルールは、列車が現在駅 i にあるときに、現在の到着を含めてこれまでに駅 i を訪れた回数を調べるということです。 この番号が奇数の場合は、i からの最初の往路を使用し、そうでない場合は 2 番目の往路を使用します。 

各クエリは、指定された開始ステーションから l 個の移動を実行した後の最終ステーションを要求します。 

この制約により、n と q が 2 · 10^5 まで、l が 10^18 までの大きさになる設定が強制されます。 1 つのクエリでも 10^18 の遷移が必要になる可能性があり、ステップごとの推論が O(n) であっても制限をはるかに超えるため、クエリごとの直接シミュレーションは不可能です。 したがって、意図したソリューションでは、個々の動きのシミュレーションを避け、代わりに長い軌道を圧縮する必要があります。 

微妙な難しさは、トランジションが固定されていないという事実から来ています。 発信エッジは、ステーションが奇数回訪問されたか偶数回訪問されたかによって決まるため、グラフは単純な関数グラフではありません。 代わりに、すべてのステーションは、アクセスされるたびに 2 つの発信エッジ間で切り替わる 2 状態デバイスのように動作します。 

単純な間違いは、パスが現在のステーションのみに依存していると仮定することです。 たとえば、ステーション 5 への 2 回の訪問は同等ではありません。最初の訪問では、発信エッジが 2 回目の訪問とは異なる可能性があります。 もう 1 つのよくある間違いは、ステーション 1 へのリセットによって引き起こされる再訪問間の相互作用を無視することです。多くのパスは繰り返し 1 に戻るため、ステーションは何度も再訪問される可能性があり、その結果、ステーションの動作が静的ではなく振動的になります。 

具体的な障害ケースとして、両方の発信エッジが異なるステーション i を考えてみましょう。たとえば、1 つは 1 に、もう 1 つは i + 1 に進みます。訪問パリティを追跡せずに選択を盲目的に切り替えると、決定論的なグラフを誤って仮定することになりますが、実際の軌道は、以前のサイクルで i に遭遇した回数に応じて、リセットと進行の間で切り替わる可能性があります。 

## アプローチ

 強引な方法は簡単です。列車を段階的にシミュレートします。 ステーション i が何回訪問されたかを格納する配列 cnt[i] を維持します。 各ステップで、現在のステーションで cnt をインクリメントし、そのパリティをチェックして、対応する出力エッジを選択します。 これはプロセスの正確なルールに従っているため、これは正しいです。 

ただし、各クエリには最大 l 個の遷移が必要になる可能性があり、l は 10^18 になる可能性があります。 q 個のクエリにわたってさえ、これは完全に不可能になります。 ボトルネックは、各ステップに一定の時間が必要ですが、ステップ数に制限がないことです。 

重要な構造的観察は、プロセスは訪問数に依存しますが、各ステーションには可能な動作が 2 つだけあり、それらが決定論的に交互になるということです。 i 番目のステーションはトグルのように動作します。最初に使用されるときは一方のエッジが使用され、2 回目にはもう一方のエッジが使用され、3 回目には最初のエッジが繰り返されます。 したがって、各ステーションは事実上、アクセスされるたびに状態が切り替わる 2 状態のオートマトンです。 

これにより、各ステーションがパリティ状態を持つ、より大きな状態空間上の決定論的なウォークとしてシステムを再解釈することができます。 完全なグローバル状態は大きいですが、遷移は依然として決定的かつローカルです。現在のステーションのパリティのみが次の動きに影響します。 これにより、位置とパリティの動作の両方をエンコードする状態に対してダブリング スタイルの手法を適用することが可能になります。

私たちは問題を、各「状態」が既知のトグルフェーズを持つステーションにある構成として考えることができる機能構造を飛び越えることに効果的に還元し、遷移の繰り返し適用がどこにつながるかを事前計算します。 これにより、ステップバイステップのシミュレーションではなく、時間をかけてバイナリ リフティングが可能になります。

 ## アルゴリズムのチュートリアル

 私たちは、移動に関連する唯一のメモリが現在のステーションが最初の使用フェーズにあるか、2 回目の使用フェーズにあるかということだけである、拡張された状態空間にわたってプロセスが決定論的であるというアイデアをエンコードします。 このフェーズはステーションを訪問するたびに切り替わります。 

特定のフェーズで特定のステーションから開始して 2^k 移動した後にどこに到達するかを示す遷移を事前計算します。 各ステーションには正確に 2 つの出力選択肢があり、グラフ構造は 1 へのジャンプまたは i + 1 への移動のいずれかに制限されているため、2 倍化を使用してこれらの遷移をボトムアップで構築できます。 

### ステップ

 1. 各ステーション i に対して、2 つの発信ターゲットを定義します。1 つは初回使用用、もう 1 つは二次使用用です。 これらは入力文字によって直接与えられます。 これらは 1 または i + 1 として解釈されます。 
2. 状態を (i, p) として定義します。ここで、i は現在のステーションであり、p は i からの次の出発が最初の発信エッジを使用するか 2 番目の発信エッジを使用するかを示します。 i にアクセスするたびにパリティが反転するため、p は常に次の出力エッジを決定的に決定します。 
3. 状態 (i, p) から 1 移動した後に次のステーションを与えるベース遷移 nxt[i][p] を構築します。 この遷移により、宛先ステーションのパリティも反転されますが、ジャンプの目的では、位置を追跡するだけであり、パリティが暗黙的に 2 倍化構造内に運ばれます。 
4. l ≤ 10^18 であるため、バイナリ リフティング テーブルを最大 60 レベルまで構築します。 各テーブル エントリには、(i, p) から開始して 2^k 移動後のどこに着地するかが格納されます。 これは、サイズ 2^(k-1) の 2 つのジャンプを適用する、より小さなジャンプを構成することによって構築されます。 
5. クエリごとに、開始ステーションがすでに 1 回訪問されているという事実によって決定される初期パリティを使用して状態を開始ステーション s として初期化します。そのため、その初期フェーズは奇数の訪問に対応します。 
6. l をバイナリに分解し、対応する事前計算されたジャンプを適用します。 各ジャンプは現在のステーションを更新し、テーブルにエンコードされた遷移ルール​​に従ってパリティ フェーズを暗黙的に更新します。 
7. l の全ビットを処理した後、最終局を出力します。 

### なぜ効果があるのか

 各ステーションは、発信エッジ上で周期 2 を持つ決定的なトグル マシンとして動作します。 グローバル システムには再訪問によるステーション間の相互作用が含まれていますが、すべての遷移は現在のステーションとそのローカル フェーズにのみ依存します。 これにより、長い一連の動きの効果を、固定遷移関数の繰り返しの構成に分解できることが保証されます。 これらの決定論的遷移の合成は結合的であり、すべての 2^k ステップ関数は情報を失うことなく 2 つの 2^(k-1) ステップ関数の合成として表現できるため、バイナリ リフティングが有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LOG = 60

n = int(input())
a = input().strip()
b = input().strip()

def nxt_node(i, c, parity):
    if parity == 1:
        ch = a[i]
    else:
        ch = b[i]
    if ch == '<':
        return 0
    return i + 1

# we will store next position ignoring full global parity,
# using lifting over (position, implicit phase)
up = [[[0, 0] for _ in range(n + 2)] for _ in range(LOG)]

for i in range(1, n + 1):
    # parity 0 means second edge next, parity 1 means first edge next
    up[0][i][0] = 1 if b[i - 1] == '<' else i + 1
    up[0][i][1] = 1 if a[i - 1] == '<' else i + 1

for k in range(1, LOG):
    for i in range(1, n + 1):
        for p in range(2):
            mid = up[k - 1][i][p]
            up[k][i][p] = up[k - 1][mid][p ^ 1]

q = int(input())
out = []

for _ in range(q):
    s, l = map(int, input().split())
    parity = 1  # start is visited once
    cur = s

    for k in range(LOG):
        if (l >> k) & 1:
            cur = up[k][cur][parity]
            parity ^= 1

    out.append(str(cur))

print("\n".join(out))
```この実装では、各エントリが特定のローカル パリティ状態に基づく特定のステーションからの長さ 2^k の移動シーケンスの結果を表す 2 倍テーブルを構築します。 各セグメントは中間ノードへの奇数の訪問に対応するため、セグメントをトラバースするたびにパリティ ビットが反転されます。 

開始ステーションは最初の移動の前に訪問したとみなされるため、初期パリティは 1 に設定され、その最初の出発には最初の発信エッジが使用されます。 

## 実用的な例

 いくつかのステーションがあり、両方の発信エッジ ストリングが与えられている小規模な構成を考えてみましょう。 l = 3 のステーション 2 から始まるクエリをトレースします。 

| ステップ | 現在 | 現在のパリティ | アクション | 次へ |

 | 1 | 2 | 1 | 最初のエッジを使用 | 入力によって決定される |
 | 2 | 次へ | 切り替え | | に応じて 2 番目/1 番目を使用します。 次へ |
 | 3 | ... | ... | ... | 最終 |

 このトレースは、ステーションの訪問ごとにパリティがどのように反転するかを示しています。これは、同じステーションが履歴に応じて異なる動作をする可能性があることを意味します。 

任意のステーションからの l = 1 の 2 番目の例は、答えが単に初期奇数パリティを持つそのステーションからの最初の強制遷移であることを示し、初期条件が正しく処理されていることを確認します。

 ## 特殊なケース

 重要なエッジ ケースは、ステーションからのすべての遷移がステーション 1 に戻る場合に発生します。この場合、列車は繰り返しリセットされ、各ステーションでのパリティが急速に切り替わります。 このアルゴリズムは、リフティング テーブルが同じリセット遷移の繰り返しの適用を正しくエンコードしているため、これを処理します。そのため、繰り返しのジャンプは同じ関数のべき乗に自然に崩壊します。 

もう 1 つのエッジ ケースは、パスが i から i + 1 まで厳密に前方に移動し、n に到達してからリセットされる場合です。 ここでの動作は非常に周期的です。長い実行は、リセットが挟まれた決定的な前方スイープで構成されます。 順方向エッジが遷移テーブルで明示的にエンコードされ、リセットが状態 1 への通常の遷移として扱われるため、二重構造はこれを捉えています。 

最後に、n = 1 の場合、ステーションは常に自分自身にリダイレクトしますが、2 つの発信ルールを交互に使用します。 リフティング テーブルは単純なトグル サイクルに縮退し、繰り返し適用すると、長い l 値にわたる変更が正しく保存されます。
