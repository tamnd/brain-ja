 ## 解決策
 ## 問題の理解

 都市は交差点の長方形のグリッドであり、各セルには受け取りが必要な顧客の荷物が含まれている可能性があります。 移動は一方通行によって制限されており、交差点からは南または東のどちらかにしか移動できません。 すべてのドライバーは左上隅からスタートし、最終的には右下隅で終了し、これらの指示された道路規則に常に従わなければなりません。 

各ドライバーは出発地から目的地まで有効な経路をたどり、途中で訪問したセルにある荷物を受け取ります。 ドライバーは、経路に沿って到達可能なセルからのみ荷物を受け取ることができます。 タスクは、パーセルを含むすべてのセルに少なくとも 1 つのパスが訪れるように、必要なそのような単調パスの最小数を決定することです。 

グリッド サイズは最大 2000 x 2000 で、これは最大 400 万個のセルを意味します。 考えられるすべてのパスをシミュレートしたり、パスを明示的に列挙しようとするソリューションは不可能です。 O(nm log nm) のアプローチでも慎重な設計が必要であり、パス上のより直接的な意味での二次関数は実行不可能です。 この構造は、問題が基本的に、部分的に順序付けられたグリッド内の点のセットを、単調な動きによって引き起こされる支配関係を尊重する最小数のチェーンに分解することであることを示唆しています。 

区画が対角線のような構造を形成する場合、微妙なエッジケースが現れます。 

たとえば、次のことを考えてみましょう。```
C _ _
_ C _
_ _ C
```移動が厳密に左上から東/南の場合、ドライバーごとに収集できる区画は 1 つだけであるため、答えは 3 になります。単調性の制約を無視して複数の C セルを「蛇行」しようとする単純な貪欲な人は、ドライバーの数が少なくても十分であると誤って想定する可能性があります。 

もう 1 つのケースは、すべての区画が 1 つの行または列にある場合です。 例えば：```
C C C C
```ここでは、1 人のドライバーが東に移動することですべての荷物を収集できるため、答えは 1 になります。隣接関係またはクラスタリングを十分なものとして誤って扱うアプローチは過大評価になります。 

主な問題点は、到達可能性が行方向と列方向の両方で同時に制限され、単純なグラフではなく 2D の部分的な順序が生成されることです。 

## アプローチ

 この問題を考える強引な方法は、各ドライバーのパスを個別に検討することです。 左上から右下へのパスを構築し、可能な限り多くの未回収のパーセルを貪欲に拾い上げ、それらのセルにサービス済みのマークを付け、すべてのパーセルがカバーされるまでこれを繰り返します。 これはすぐに曖昧さに陥ります。単調なパスが指数関数的に多く存在し、残りのほとんどのパーセルをカバーするのにどのパスが最適であるかを決定することさえ局所的に決定的ではありません。 最悪の場合、単一の最適なパスを探索するだけでも、すべての右/下シーケンスにわたる組み合わせ推論が必要となり、グリッド次元では指数関数的になります。 

失敗点は、異なるパーセル間の相互作用がローカルではないことです。 1 つのセルを通過するという決定は、単調性により、将来到達可能なすべてのセルを制約します。 

重要な観察は、有効な各ドライバー パスが両方の座標において単調増加シーケンスであるということです。 パーセルをポイントとして考える場合、1 つのパスは、行インデックスと列インデックスの両方で増加チェーンを形成するパーセルのみをカバーできます。 これにより、問題は 2D 点のセットを最小数の増加するチェーンに分割することに変換されます。 

これは古典的な変換です。2D 部分順序を連鎖分解問題に還元します。 標準的な結果 (この設定におけるディルワースの定理と同等) によれば、必要なチェーンの最小数はアンチチェーンの最大サイズと等しくなります。 グリッド用語では、これは、支配関係の下で相互に比較できない最長のパーセルのセットになります。 

この特定のジオメトリでは、アンチチェーン構造は、座標変換後に最大の 2 部マッチング、または同等の最長増加サブシーケンスに崩壊します。 正しい削減は、セルを行ごとに処理し、列の貪欲一致を使用して可能な限り最適なチェーン割り当てを維持することです。 

これにより、グリッド到達可能性によって暗黙的に定義された DAG 内の最小パス カバーを計算するのと同等の貪欲な構造を使用した効率的なソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパス列挙 | 指数 | O(hw) | 遅すぎる |
 | 貪欲なマッチングによる最適なチェーン分解 | O(hw log w) または O(hw) | O(w) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. パーセルを含むすべてのセルを点 (i, j) として半順序で解釈します。i1 ≤ i2 および j1 ≤ j2 の場合にのみ、(i1, j1) が (i2, j2) に先行することができます。 これは、南と東のステップの移動制約と一致します。 
2. すべてのパーセル セルを行インデックスの昇順で、各行内で列の昇順で処理します。 この順序は、有効なパスの単調な構造と一致しています。 
3. アクティブなチェーンを表すデータ構造を維持します。 各チェーンはドライバー パスに対応し、到達した最後の列位置によって特徴付けられます。 
4. 各パーセル セル (i, j) について、最後の列が ≤ j である既存のチェーンに割り当ててみます。 このようなすべてのチェーンの中で、制約を満たす最大の最後の列を持つチェーンを選択します。 この貪欲な選択により、将来の配置に対する柔軟性が保たれます。 
5. そのようなチェーンが存在する場合は、その最後の列を j に更新して拡張します。 どのチェーンも荷物を収容できない場合は、新しいドライバーを雇うことに相当する新しいチェーンを開始します。 
6. 各チェーンは、割り当てられたパーセルをカバーする有効な単調パスに対応するため、最後に維持されるチェーンの数が答えになります。 

### なぜ効果があるのか

どの時点でも、チェーンは、処理済みのパーセルをすでにカバーしている、結合されていない単調なパスを表します。 貪欲な割り当てにより、現在のパーセルに到達できる最も制限された既存のパスが常に再利用されます。 これにより、将来の実現可能性が低下する、より柔軟なチェーンを時期尚早に消費することが防止されます。 パーセルは行の昇順で処理されるため、有効な割り当てはこの順序を尊重する必要があり、列方向の貪欲な配置により、チェーン エンドポイントが最小限のアンチチェーン フロンティアを形成するという不変条件が維持されます。 これにより、チェーンの数がすべてのポイントをカバーするために必要な真の最小値を決して超えないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import bisect

def solve():
    h, w = map(int, input().split())
    rows = []
    for _ in range(h):
        s = input().strip()
        rows.append(s)

    # We maintain a list of chain endpoints (columns)
    # Each chain represents a driver path.
    chains = []

    for i in range(h):
        for j in range(w):
            if rows[i][j] != 'C':
                continue

            # find rightmost chain with last_col <= j
            # we want largest last_col <= j
            idx = bisect.bisect_right(chains, j) - 1

            if idx >= 0:
                # extend that chain
                chains[idx] = j
            else:
                # start new chain
                chains.append(j)

            # keep chains sorted for greedy correctness
            chains.sort()

    print(len(chains))

if __name__ == "__main__":
    solve()
```実装では、チェーン エンドポイントのソートされたリストが維持されます。 各パーセルに対して二分探索を実行して、列次元の単調性を損なわずに拡張​​できる最適なチェーンを見つけます。 存在しない場合は、新しいチェーンが作成されます。 ソートにより、将来のバイナリ検索が有効なままになるようにチェーンの順序が維持されることが保証されますが、完全に最適化されたバージョンでは、より特殊な構造によりソートの繰り返しを回避できます。 

微妙な点は、`bisect_right`最も右の実行可能なチェーンを見つけます。 これにより、よりタイトなチェーンで現在のパーセルを処理できる場合でも、低容量のチェーンを無駄にせず、将来のより大きな列インデックスに対する高い柔軟性が維持されます。

 ## 特殊なケース

 完全に空のグリッドには区画が含まれていないため、ドライバーは必要ありません。 チェーンが作成されないため、アルゴリズムは正しくゼロを生成します。 

拡張する既存のチェーンが存在しないため、左上隅にある 1 つのパーセルは 1 つのチェーンをただちに作成します。 

厳密に対角配置すると、すべてのパーセルが新しいチェーンを開始するように強制されます。これは、連続する各パーセルが、グリーディ構造内の以前のすべてのエンドポイントの下および左に位置するためです。 アルゴリズムはこれを反映して、すべての拡張試行を失敗し、新しいチェーンを繰り返し追加します。 

完全に塗りつぶされたグリッドでは、行優先のトラバーサルでは列構造が減少しないため、次のすべてのセルが前のチェーンを拡張できるため、1 つのチェーンがすべてのセルに伝播できます。
