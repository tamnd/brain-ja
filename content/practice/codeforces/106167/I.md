 ## 解決策
 ## 問題の理解

 n 個の位置からなる円形の線が与えられ、各位置は 1 から m までの値を保持します。 また、この円上の 3 つの連続する値を取得し、中央のポジションの翌日の値を生成する決定的な更新ルール f も与えられます。 

言い換えれば、今日の隠れ状態が配列 a[1..n] である場合、明日観察される配列 s0 は、すべてのインデックス i について、i の値が循環的に取得されるインデックスで f(a[i−1], a[i], a[i+1]) になるという規則によって完全に決定されます。 

問題は、順方向のシミュレーションではなく、逆方向の一貫性をチェックすることです。 提案された状態 s0 が与えられ、ルールを適用すると正確に s0 が生成されるような以前の構成が少なくとも 1 つ存在するかどうかを判断する必要があります。 再構築する必要はなく、有効な先行データが存在するかどうかを判断するだけです。 

制約はアルファベットのサイズという点では小さいですが、長さではありません。n は最大 200、m は最大 10 です。遷移関数 f はすべての m^3 入力トリプルに対して完全に指定されているため、固定ルックアップ テーブルのように動作します。 

主な問題は、各位置が 3 つの連続する未知の値に依存することです。これは、素朴な独立性の仮定がすぐに崩れることを意味します。 すべてのセル制約は隣接セルと重なり合い、密結合した周期的制約システムを形成します。 

単純な試みとしては、左から右へ貪欲に値を割り当てようとする可能性があります。 これは、各選択が将来の実現可能性に一度に 2 つの方向に影響を及ぼし、最後のラップアラウンド制約によって終わりが最初に結合されるため、失敗します。 

境界ラップを除くどこでもローカルの一貫性が保たれる場合、微妙なエッジ ケースが発生します。 

入力:

 n = 4、m = 2

 s0 = [1, 2, 1, 2]

 貪欲な構築では、位置 1 ～ 3 のローカルで有効なシーケンスが見つかる可能性がありますが、位置 4 の値はインデックス 3 のローカル ルールとインデックス 4 のラップ制約の両方を同時に満たすことができません。 正しい答えは、部分的な構築が成功するかどうかではなく、完全な循環代入が存在するかどうかに応じて「はい」または「いいえ」になります。 

別の失敗例は、複数のローカル選択肢が存在するが、有効なグローバル サイクルが 1 つだけである場合に発生します。 ローカル ヒューリスティックでは、グローバルに一貫性のある唯一のブランチを早期に破棄する可能性があります。 

## アプローチ

 この問題は、すべてのインデックス i がトリプル ウィンドウ (a[i−1]、a[i]、a[i+1]) に制約を課し、f の下で s0[i] に正確に評価される必要があるような、サイズ m のアルファベットに対する代入 a[1..n] を検索するものとして再解釈できます。 これは、3 項制約のあるサイクルにわたる制約充足問題です。 

ブルートフォース手法では、先行状態の m^n 個の可能な割り当てをすべて列挙し、それぞれが s0 を生成するかどうかを検証します。 これは概念的には簡単です。候補配列ごとに、O(n) 内の n 個の制約をすべてチェックし、O(n · m^n) を求めます。 m が最大 10、n が最大 200 であるため、これは天文学的に大きく、まったく実行不可能です。 

制約がローカルであり、長さ 3 のみであることが観察されると、この構造は管理可能になります。これは、連続したペアに対する動的プログラミングを示唆しています。 完全なプレフィックスを決定する代わりに、先行配列の最後の 2 つの値を維持します。 位置 i の各制約は (a[i−1]、a[i]、a[i+1]) に正確に依存するため、これら 2 つの値は有効な拡張を決定するのに十分です。 

これにより、実行可能なペアを伝播しながらサイクルを実行するという問題が軽減されます。 ただし、円形の境界は複雑な問題を引き起こします。最初に選択した 2 つの値は、サイクルを囲む最後の制約と一致する必要があります。 

最初の 2 つの値を固定し、残りの位置に対して線形 DP を実行し、同時に最後のラップ制約を明示的に適用することで、この問題を解決します。 m が小さいため、考えられるすべての開始ペアを試し、それぞれに対して DP を実行し、いずれかの構成が成功した場合は早期に停止できます。

これにより、開始ペアあたり O(n · m^2) の管理可能な状態空間 (m^2 開始) が得られますが、これは許容範囲内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | アレイ全体に対するブルート フォース | O(n · m^n) | O(n) | 遅すぎる |
 | DP を固定スタートとペアにする | O(m^2・n・m^2) = O(n・m^4) | O(m^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 先行配列を未知の変数 a[1..n] として扱います。 目標は、少なくとも 1 つの循環割り当てがすべてのローカル制約を満たすかどうかをテストすることです。 

1. 開始ペア (a[1]、a[2]) を固定します。 すべての m^2 の可能性を反復処理します。 以降のすべての状態はこれらの初期値に依存するため、これにより DP が固定されます。 
2. (a[i−1], a[i]) と目的の出力 s0[i] が与えられた場合に、a[i+1] のどの値が許可されるかを示す遷移テーブルを構築します。 これは、m 個の候補をすべてチェックし、f(a[i−1], a[i], x) = s0[i] を満たす候補を維持することから直接得られます。 
3. 位置 2 から n-1 まで DP を実行します。 DP 状態は (a[i-1], a[i]) です。 各状態から、s0[i] と互換性のあるすべての可能な a[i+1] を試し、(a[i], a[i+1]) への遷移を生成します。 これが機能するのは、位置 i+1 まで拡張した時点で各制約が完全に決定されるためです。 
4. 位置 n に到達した後、すぐには停止しません。 (a[n−1], a[n], a[1]) に依存する最後の巡回制約をインデックス n で強制する必要があります。 位置 n で到達可能な状態が f(a[n−1], a[n], a[1]) = s0[n] を満たすかどうかを確認します。 
5. いずれかの開始ペアが、ラップ制約を満たす少なくとも 1 つの有効な終了状態につながる場合は、すぐに「yes」を返すことができます。 すべての開始ペアが失敗した場合、答えはノーです。 

正確さは、DP が先行配列のローカルで一貫した部分割り当てをすべて列挙する一方、最終チェックでは循環性によって導入された唯一の非ローカル制約を強制するという事実に依存します。 

### なぜ効果があるのか

 すべてのステップ i で、DP 状態 (a[i-1]、a[i]) は、a[i+1] の正当な値を決定するために必要なすべての情報を取得します。 最後の 2 つの要素を除いて、以前の値が将来の遷移に影響を与えることはないため、さらに拡張できる先行構成はこの状態空間に表示される必要があります。 これにより、DP はすべての有効な部分割り当てにわたって完了します。 

ローカルで処理されない唯一の制約は、a[n]、a[n−1]、および a[1] を結び付けるインデックス n でのラップアラウンド依存関係です。 最初に (a[1], a[2]) を修正し、この最後の制約を明示的に検証することにより、すべての循環依存関係が 1 回だけチェックされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    f = [[[0] * m for _ in range(m)] for _ in range(m)]
    vals = []
    for _ in range(m * m * m):
        vals.append(int(input()))
    
    idx = 0
    for x in range(m):
        for y in range(m):
            for z in range(m):
                f[x][y][z] = vals[idx] - 1
                idx += 1
    
    s0 = list(map(int, input().split()))
    s0 = [x - 1 for x in s0]
    
    for a1 in range(m):
        for a2 in range(m):
            dp = [[False] * m for _ in range(m)]
            dp[a1][a2] = True
            
            for i in range(1, n - 1):
                ndp = [[False] * m for _ in range(m)]
                target = s0[i]
                
                for x in range(m):
                    for y in range(m):
                        if not dp[x][y]:
                            continue
                        for z in range(m):
                            if f[x][y][z] == target:
                                ndp[y][z] = True
                
                dp = ndp
            
            for x in range(m):
                for y in range(m):
                    if not dp[x][y]:
                        continue
                    if f[x][y][a1] == s0[n - 1]:
                        print("yes")
                        return
    
    print("no")

if __name__ == "__main__":
    solve()
```この実装では、関数 f を 0 から始まる値でインデックス付けされた 3D テーブルとしてエンコードします。 DP テーブルには、位置 i までの処理後にペア (a[i-1], a[i]) が到達可能かどうかが格納されます。 

各反復は、必要な出力 s0[i] と一致するすべての可能な拡張を試行することによって 1 ステップ進みます。 最後のループでは、元の開始値 a[1] を使用してラップアラウンド条件をチェックします。 

一般的な微妙な点はインデックス付けです。最初の 2 つの値が固定されているため、DP は位置 2 以降から実行され、最後の制約は s0[n] を使用して個別にチェックされます。 

## 実用的な例

 n = 4 および m = 2 で、単純なルール f と候補 s0 = [1, 2, 1, 2] を持つ小さなインスタンスを考えてみましょう。 開始ペア (a1, a2) = (0, 1) をテストするとします。 

| ステップ | DP 状態ペア (x,y) | アクション |
 | --- | --- | --- |
 | 開始 | (0,1) | 初期化 |
 | i=2 | {(y,z) は s0[1] に有効} | f | を使用して拡張します。 
| i=3 | フィルタリング後の到達可能なペア | 伝播する |
 | 最終 | f(x,y,a1) = s0[3] | をチェックします。 ラップ制約 |

 このトレースは、DP が完全な配列を保存せずに、ローカルで有効な構成のみを段階的に構築する様子を示しています。 

ここで、s0 が f と互換性のない方法で交互になるなど、先行処理が存在しない場合を考えてみましょう。 DP はある層で空のセットに崩壊し、すべての開始ペアが失敗します。 

| ステップ | DP サイズ | 結果 |
 | --- | --- | --- |
 | 開始 | m^2 状態 | 可能なすべてのスタート |
 | ミッド | 0 州 | 矛盾に達しました |
 | 最終 | スキップしました | 有効な前任者がありません |

 これは、実行不可能な枝の早期剪定を示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、複数の先行選択がローカルに存在するが、サイクルを終了するのは 1 つだけである場合です。 DP はすべての部分ペアを個別に保持するため、コミットが早すぎることはなく、最後にクロージャーのみを検証して正確さを維持します。 

もう 1 つのエッジ ケースは、正しい先行処理が局所的に最適ではないと思われる特定の開始ペアを必要とする場合です。 すべての m^2 の開始ペアが試行されるため、有効な構成は除外されません。 

最後のエッジケースは、最初のステップの後に拡張が不可能な即行き止まりです。 このような場合、DP テーブルはすぐに空になり、アルゴリズムは他のペアに影響を与えることなく、その開始ペアを正しく拒否します。
