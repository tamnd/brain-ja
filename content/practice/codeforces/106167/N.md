 ## 解決策
 ## 問題の理解

 交差点がノード、歩道が重み付けされた有向エッジである有向グラフが与えられます。 各エッジには移動時間と、目に見える色のセットがあります。 ナビゲーション システムは独特の方法で動作します。どの交差点でも、単一の色が表示されます。 次に、トラベラーは、カラー セットにその色を含む、現在のノードからの発信エッジを選択します。 複数の発信エッジが一致する場合、旅行者は敵対的であり、目的地までの総移動時間の観点から常に最悪のものを選択します。 

時間の経過とともに表示される色の順序を制御します。 各ステップで 1 つの色を選択し、旅行者はその色に一致するエッジの中から敵対的に選択された 1 つのエッジを正確に移動します。 目標は、ノード 1 からノード n への到達を保証するか、不可能であると判断するために必要な総移動時間を最小限に抑えることです。 

重要な問題は、単一の色の選択が複数の出力エッジに対応する可能性があり、ユーザーは常に最終的な到着時間をできるだけ長くするものを選択することです。 

制約は非常に大きく、ノードとエッジは最大 500,000 個、色の出現総数も最大 500,000 個に達します。 これにより、すべてのカラー シーケンスを明示的にシミュレートしたり、タイム ステップごとにノードごとにカラーごとの状態を維持しようとするソリューションは即座に除外されます。 単純に繰り返すと、色の決定ごとに O(m log m) であっても遅すぎます。 

このプロセスを単純に解釈すると、各状態がノードと選択した色の両方に依存するグラフ上の動的なゲームが示唆されますが、敵対的な遷移により多くのエッジが崩壊し、色ごとの最悪の遷移になります。 この構造は最短パスに近いですが、遷移は色ごとにグループ化されたエッジのセットによって定義されます。 

現在のノードからの出力エッジに色が表示されない場合、微妙なエッジ ケースが発生します。 その場合、その色はそのノードでは事実上無効となり、移動に使用できなくなります。 もう 1 つのエッジ ケースは自己ループです。エッジは正のコストで同じノードに戻り、敵対者の選択を支配する可能性があります。 

たとえば、ノード 1 から、色 1 が 2 つのエッジに存在するとします。コスト 1 の 1 対 2 と、コスト 100 の 1 対 1 です。色 1 を選択すると、トラベラーは自己ループの方が悪いため、自己ループを選択します。そのため、事実上 100 時間単位が発生し、ノード 1 に留まります。各エッジを個別に扱う単純な最短パスの定式化では、この敵対効果が過小評価されてしまいます。 

## アプローチ

 ブルートフォース解釈では、現在のノードと現在の色の命令のペアとして各状態をモデル化し、その色を含むそのノードのすべての出力エッジを考慮して、最大コストの結果を取得することで遷移をシミュレートしようとします。 これにより、各ノードと色から別のノードに移動できる状態グラフが得られますが、これを明示的に構築および緩和するには、色の決定ごとにすべてのエッジを繰り返し繰り返す必要があります。 最悪の場合、各ステップですべての出力エッジが検査される可能性があり、パスが長い可能性があるため、エッジの数は 2 次になります。 

重要な洞察は、視点を逆転させることです。 ノードでの色を選択することを考えるのではなく、各ノードと色について決定論的な最悪の出力エッジを定義することとして敵対者の影響を考えます。 ノード u で色 c を選択した場合、次のノードは任意ではありません。 これは、色 c を持ち、最終的なコストを最大化する u からの発信エッジの終点です。 そのようなエッジが存在しない場合、その色は u では無効です。

これにより、問題は派生グラフ上の標準的な最短経路問題に変換されます。この問題では、各状態は単なるノードですが、色の選択によって遷移が引き起こされます。 ただし、複数のエッジが同じ色を共有する可能性があるため、ノードと色ごとに、敵対的な選択の下で「最良の応答」エッジを計算する必要があります。 これは、エッジを (u, c) でグループ化し、最悪の継続につながる出力エッジを各ペアに保持することで事前に計算できます。これは、逆最短経路推論によって捕捉されます。 

これを確認するためのより堅牢な方法は、ノード n から後方への距離を計算することです。 ノード v から n に到達するコストがわかっている場合、任意のノード u および色 c について、c を選択すると、色 c を持つ u の出力エッジの中から t + dist[v] を最大化する後続 v が得られます。 それは敵の選択です。 したがって、遷移は距離に依存し、ミニマックス最短パスを解決します。これは、各状態がノードであり、遷移が色ごとの最適な出力エッジを介して計算されるダイクストラのような緩和によって自然に処理されます。 

各ノードと色について、t + dist[v] を最大化する出力エッジを維持し、距離が改善するにつれて更新します。 これにより、各緩和で色ごとにグループ化された関連エッジのみが考慮される多層ダイクストラが得られ、カラー エッジの発生全体でほぼ線形の複雑さが実現されます。

 ## アルゴリズムのチュートリアル

 私たちはこの問題を、色の選択によって遷移が引き起こされるミニマックス最短経路を計算するものとして扱います。 

1. 各発信エッジがその宛先、重み、およびそれに関連付けられた色のセットを保存する隣接リストを構築します。 効率的にアクセスするために、この構造を各ノードと色ごとに、その色を含む出力エッジのリストに反転します。 これにより、ノードで特定の色を選択した場合に何が起こるかを迅速に評価できます。 
2. 距離配列を初期化します`dist`0 に設定されているターゲット ノード n を除くすべてのノードに対して無限大を使用します。宛先から逆方向に最短保証コストを計算します。 
3. ノード n でシードされた優先キューを使用します。 各エントリは、その最良の既知の距離が最終決定または改善されたばかりのノードを表します。 
4. キューからノード v をポップするとき、v につながる可能性のあるすべての入力「カラー遷移」を考慮します。入力エッジを直接反復する代わりに、反転した構造を使用します。各ノード u とカラー c について、現在の距離推定の下で最適な出力エッジ候補を維持します。 
5. 各ノード u について、各色 c を可能な命令として概念的に評価します。 その色については、c を含む u から出るすべてのエッジを考慮し、値 t + dist[next] を計算します。 敵はそれらの中から最大のものを選択します。 したがって、各 (u, c) について、実行中の最大候補後継コストを維持します。 
6. u のすべての色を評価した後、これらの最悪の場合のコストの最小値を色ごとに取得します。 これにより、ノード u で与えることができる最良の命令が得られます。 この値が dist[u] を改善する場合、それを更新し、u を優先キューにプッシュします。 
7. キューが空になるまで繰り返します。 dist[1] が無限のままの場合、ノード n に到達することは不可能です。 それ以外の場合は dist[1] が答えになります。 

中心的な考え方は、各ノードの値が 2 つの入れ子になった最適化に依存するということです。つまり、私たちは結果を最小化する色を選択し、敵対者はそれを最大化するエッジを選択します。 

### なぜ効果があるのか

 距離値`dist[u]`は、最適な色の選択と敵対的なエッジの選択の下で、u から始まるノード n に到達するために必要な最小の最悪の場合の時間を表します。 このアルゴリズムでは、すべての更新が`dist[u]`は、u で考えられるすべての色を評価することで得られます。各色は、後続距離の現在の推定によって引き起こされる決定論的な最悪の場合の遷移に還元されます。 ダイクストラのプロセスでは常に、真のミニマックス コストが降らない順にノードをファイナライズするため、ノードがポップされると、その値は最適になり、再度変更する必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq
from collections import defaultdict

def solve():
    n, m, k = map(int, input().split())
    
    # For each node and color: list of (v, t)
    out_edges = [defaultdict(list) for _ in range(n + 1)]
    
    for _ in range(m):
        u, v, t = map(int, input().split())
        data = list(map(int, input().split()))
        l = data[0]
        colors = data[1:]
        
        for c in colors:
            out_edges[u][c].append((v, t))
    
    INF = 10**18
    dist = [INF] * (n + 1)
    dist[n] = 0
    
    pq = [(0, n)]
    
    # Reverse-style Dijkstra on states (node only)
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        
        # Try to improve predecessors u via all nodes and colors
        # We recompute lazily: for each node, evaluate best color
        for x in range(1, n + 1):
            best = INF
            
            for c, edges in out_edges[x].items():
                worst = -1
                for v, t in edges:
                    if dist[v] == INF:
                        continue
                    worst = max(worst, t + dist[v])
                
                if worst != -1:
                    best = min(best, worst)
            
            if best < dist[x]:
                dist[x] = best
                heapq.heappush(pq, (best, x))
    
    print("impossible" if dist[1] == INF else dist[1])

if __name__ == "__main__":
    solve()
```コードは、各ノードと色から、その色を運ぶすべての出力エッジへのマッピングを構築します。 それ自体からターゲットに到達するコストはゼロであるため、距離配列はターゲット ノードから逆方向に初期化されます。 

プライオリティ キューはノード上でダイクストラのようなプロセスを駆動しますが、緩和ステップは、ノードですべての色を評価し、現在の後続距離を考慮して色ごとに最悪の場合の出力エッジを計算することによって表現されます。 敵対的な動作は、同じ色グループ内のエッジ上の最大値を取ることによって捕捉されます。 

実装の微妙な詳細は、到​​達不能状態の処理です。隣接ノードの距離が無限である場合、最大化ステップで無視する必要があります。無視しないと、最悪の場合の計算が誤って膨張したり破損したりする可能性があります。 

この素朴な実装でのノード全体のフル スキャンの使用は概念的には正しいですが、最適化されていません。 運用グレードのソリューションでは、このステップはノードと色のペアごとの増分メンテナンスに置き換えられます。

 ## 特殊なケース

 重大なエッジ ケースは、ノードの色が、すでに到達できないノードにつながるエッジにのみ表示される場合に発生します。 その場合、その色は有効な遷移に寄与しません。 アルゴリズムは、目的地までの距離が無限であるエッジを無視することでこれを処理し、そのような色が有効な改善として誤って表示されないようにします。 

もう 1 つのケースは、ノードでの最適なカラーが自己ループのみにつながる場合です。 最大化ステップでは、自己ループ エッジが繰り返し選択され、コストが無限に蓄積されます。これにより、すべての選択肢がさらに悪化しない限り、その色が選択されることが正しく防止されます。 

出力エッジがまったくないノードも、ターゲット ノードでない限り、当然ながら無限の距離に残ります。これは、そのような位置から目的地に到達することは不可能であるという要件と一致します。
