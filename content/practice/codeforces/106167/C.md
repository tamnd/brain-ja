 ## 解決策
 ## 問題の理解

 各カード タイプには、特定の価格レベルに関連付けられた売買オファーのコレクションが付属しています。 価格での購入オファー`p`誰かが最高の市場価格で購入する意思があることを意味します`p`。 価格での販売オファー`p`誰かが次から始まる任意の市場価格で売りたいことを意味します`p`。 

市場価格を固定すると`x`、互換性のあるオファーのみが重要です。すべての購入者が対象となります。`buy_price ≥ x`そしてすべての販売者は`sell_price ≤ x`。 一致したペアごとに価格で 1 つのトランザクションが生成されます`x`なので、取引数は`min(total_qualified_buyers, total_qualified_sellers)`。 収益はこの数値を乗算したものになります`x`。 

入力は価格レベルごとにオファーを圧縮します。 各線は価格ポイントと、その価格に正確に存在する買い注文と売り注文の数を示します。 概念的には、しきい値価格を選択しており、そのしきい値以上で購入する意思のある買い手の数と、そのしきい値以下で販売する意思のある売り手の数を評価する必要があります。 

目標は、次のように定義される総売上高を最大化する価格を見つけることです。`turnover(x) = x × number_of_trades(x)`。 

価格が少なくとも 1 回の取引をもたらさない場合、答えは「不可能」です。 

制約により、最大で`10^5`価格ポイント。 候補価格ごとに買い手と売り手の数をゼロから再計算するソリューションは、最悪の場合二次関数となり、合格しません。 これにより、ソートと増分プレフィックスまたはサフィックスの蓄積が推進されます。 

大量の売買が非常にアンバランスである場合、微妙なエッジケースが現れます。 たとえば、すべての買い手がすべての売り手を下回っている場合、どの価格も取引を生み出すことはできません。 もう 1 つのエッジ ケースは、複数の価格帯が同じ最大売上高を生み出す場合です。 いずれも有効ですが、価格の小数点以下がちょうど 2 桁であるため、価格の浮動小数点表現は注意して扱う必要があります。 

## アプローチ

 直接的なアプローチは、あらゆる価格を潜在的な市場価格として試してみることです。 各候補価格について、すべてのレベルをスキャンして、その価格またはそれ以上にある買い手の数と、その価格またはそれ以下にある売り手の数を数えます。 これにより正確性が得られますが、各評価にコストがかかります`O(n)`、そして全員のためにそれを行う`n`価格は～につながります`O(n^2)`操作は大きすぎます`10^5`。 

重要な構造は、価格を並べ替えると、買い手と売り手の貢献度が両方とも単調になるということです。 すべての価格ポイントを並べ替えると、市場価格が上昇するにつれて、有効な売り手の数は減少するだけであり、有効な買い手の数は増加するだけです。 この単調性により、累積カウントを再計算する代わりに維持することができます。 

この問題は、ソートされた価格配列内のすべての「カット」を評価するものであると解釈できます。 各カットで、右側に何人の買い手 (有効な買い手) がいるか、左側に何人の売り手 (有効な売り手) がいるのかが正確にわかります。 これら 2 つの値を維持するには、1 回の線形スイープで十分です。

 | プレフィックス/サフィックス数を使用したソートされたスイープ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての価格ポイントを読み取り、トリプルとして保存します`(price, buys, sells)`。 実現可能性は相対的な位置に依存するため、価格は単なる値ではなく順序キーとして扱う必要があります。 ソートにより、単調推論の一貫した方向性が確立されます。 
2. リストを価格の昇順に並べ替えます。 これにより、問題は、潜在的な市場価格を最低価格から最高価格まで網羅するものに変わります。 
3. すべての価格帯にわたる購入者の合計数を計算します。 これは、市場価格がすべてのオファーを下回っている初期状態を表しているため、すべての購入者が引き続き資格を持っています。 
4. 2 つのアキュムレータを初期化します。`active_buy`購入者の総数として、そして`active_sell`ゼロとして。 スイープのどの位置でも、`active_buy`価格が現在のしきい値以上である購入者を表し、`active_sell`価格が現在のしきい値以下の売り手を表します。 
5. 並べ替えられた価格を繰り返し処理します。 それぞれの価格帯で`i`、まず売り手を`active_sell`、これらの販売者はこの価格レベルから対象となるためです。 次に、この価格で候補となるトランザクション数を評価します。 
6. この価格での取引を次のように計算します。`t = min(active_buy, active_sell)`。 売上高は`t × price[i]`。 これまでに見られた最高の結果を追跡します。 
7. 評価後、この価格での購入者をから削除します。`active_buy`、より高い価格の場合は対象外となるためです。 
8. スイープ終了後、最良の取引数がゼロの場合は、「不可能」と出力します。 それ以外の場合は、最良の状態に対応する価格と売上高を出力します。 

### なぜ効果があるのか

 各価格レベルで、アルゴリズムは購入者をまだ有効な購入者とすでに除外されている購入者に正確に分割し、有効な販売者のプレフィックスを増加させます。 すべての候補市場価格は、このパーティションの 1 つの状態に正確に対応します。 どちらのセットも価格とともに単調に進化するため、潜在的な構成がスキップされることはありません。 最小演算子は、各しきい値での需要と供給の間のボトルネックを正確に把握し、固定価格を乗算することで、その構成の正しい収益が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
data = []

total_buy = 0
for _ in range(n):
    p, b, s = input().split()
    p = float(p)
    b = int(b)
    s = int(s)
    data.append((p, b, s))
    total_buy += b

data.sort()

active_buy = total_buy
active_sell = 0

best_turnover = 0.0
best_price = 0.0
best_trades = 0

for p, b, s in data:
    active_sell += s

    trades = min(active_buy, active_sell)
    turnover = trades * p

    if turnover > best_turnover:
        best_turnover = turnover
        best_price = p
        best_trades = trades

    active_buy -= b

if best_trades == 0:
    print("impossible")
else:
    print(f"{best_price:.2f} {best_turnover:.2f}")
```コードはスイープ ロジックを正確に反映しています。 重要な設計上の選択は、ループ内の順序です。価格を評価する前に売り手が追加され、評価後に買い手が削除されます。 これにより、各価格ポイントが正しい不等式の解釈で評価されることが保証されます。 

使用する`float`すべての入力には小数点以下 2 桁が正確に含まれており、正確な算術演算を必要とするキーの構築には使用されず、比較と最終的な書式設定にのみ使用されるため、価格の場合はここでは安全です。

 ## 特殊なケース

 最初のエッジケースは、買い手と売り手が完全に分離されていることです。 すべての買い手の価格がすべての売り手の価格を厳密に下回っている場合、スイープ状態はオーバーラップを生成しません。 アルゴリズムは維持します`active_sell`売り手が現れて初めて成長しますが、`active_buy`その時にはすでにゼロになっている可能性があり、どこでも取引がゼロになる可能性があります。 最終チェックでは正しく「不可能」がトリガーされます。 

もう 1 つのエッジ ケースは、最適なソリューションが極端な価格ではなく、スイープの途中にある場合です。 売上高は単調な要素と乗算的な価格要因の両方に依存するため、取引件数がまだ増加しているが価格がまだ大きくなっていない場合に最大値が発生することがよくあります。 スイープはそのようなすべてのブレークポイントを明示的に評価するため、内部最適値がスキップされることはありません。 

最後のエッジケースは、複数の同一の価格またはクラスター化された値です。 価格は入力において一意であるため、このようなことは起こりませんが、たとえ拡張されたとしても、各ステップが個別のしきい値状態に対応し、同一の価格は正確さに影響を与えることなく同一の評価を生成するため、アルゴリズムは依然として正しいでしょう。
