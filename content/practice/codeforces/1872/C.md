 ## 解決策
 ## 問題の理解

 複数の独立したクエリが与えられます。 各クエリは間隔を提供します$[l, r]$、そして 2 つの正の整数を構築する必要があります$a$そして$b$それらの合計がこの間隔内のどこかにあり、同時に$a$そして$b$1 より大きい公約数を共有します。 そのようなペアが存在しない場合は、不可能であることを報告する必要があります。 

タスクを理解するもう 1 つの方法は、整数を表現しようとしているということです。$s \in [l, r]$互いに素でない 2 つの数値の合計として。 以来$\gcd(a, b) \neq 1$、両方の数値は少なくとも 1 つの素因数を共有する必要があり、その構造が強く制限されます。両方とも何らかの整数の倍数でなければなりません。$d \ge 2$。 

制約は非常に厳しいため、すべての解はテスト ケースごとに定数または対数でなければなりません。 最大 500 個のクエリと最大値$10^7$、二次関数の何か$r-l$または、候補ペアの列挙を伴うと、すぐに失敗します。 間隔が数百万に及ぶ場合、最悪の場合、その間隔にわたる線形スキャンはすでに遅すぎます。 

間隔が極端に小さい場合、特に次の場合に、微妙なエッジ ケースが発生します。$r - l = 0$または$1$。 たとえば、次のようなとき$l = r = 2$、唯一可能な合計は次のとおりです。$2$、唯一の分解は次のとおりです。$(1,1)$、gcd を持っています$1$。 同様に、$l = 2, r = 3$、可能な和 2 と 3 はどちらも非共素ペアでは形成できません。 より大きな間隔は通常は簡単ですが、これらの小さな間隔は不可能を強います。 

中心的な難しさは、適切な合計が選択された後にペアを構築することではなく、そのような合計が区間内にいつ存在するかを判断することです。 

## アプローチ

 ブルートフォースアプローチでは、可能な限りの合計額を試行します$s \in [l, r]$、それぞれについて$s$、すべてのペアを反復処理します$(a, b)$そのような$a + b = s$かどうかを確認します$\gcd(a, b) \neq 1$。 これはすぐに実行不可能になります。 定額の場合$s$、 がある$O(s)$ペアを作成し、長い間隔で合計すると、次のようになります。$10^{14}$最悪の場合の運用。 

重要な観察は、視点を逆転させることです。 任意のペアを構築する代わりに、それらに構造を強制します。 もし$\gcd(a, b) \ge 2$の場合、両方の数値はいくつかの数で割り切れます。$d \ge 2$。 書けます$a = d x$、$b = d y$、すると合計は次のようになります$a + b = d(x + y)$。 これは、合計自体が制御された方法で合成される必要があることを意味します。具体的には、少なくとも次のとおりである必要があります。$2d$、そしてそれは次の倍数として表現できる必要があります。$d$。 

最も単純な構造では、因子に関する推論が完全に回避されます。 偶数を選ぶと$s$、設定できます$a = s/2$そして$b = s/2$、与える$\gcd(a, b) = a \ge 1$。 gcd が厳密に 1 より大きいことを確認するには、次のようにします。$a = b$少なくとも 2 である必要があるため、$s \ge 4$そして完璧に動作することさえあります。 

したがって、問題は偶数の整数を見つけることに帰着します$s \in [l, r]$と$s \ge 4$。 そのようなものができたら、$s$、出力します$(s/2, s/2)$。 

さて、残る唯一の問題は、そのような偶数がいつ存在するかということです。 もし$r < 4$の場合、使用可能な最小の合計は 4 であるため、有効な合計は存在しません。それ以外の場合、区間に少なくとも 4 の偶数が含まれていれば、答えを作成できます。 もし$l$は均等であり、$l \ge 4$、すぐに完了します。 もし$l$奇妙です、次の候補は$l+1$, そしてそれが間隔内であるかどうかを確認します。 

これにより、各テスト ケースが一定時間に短縮されます。

 ## アルゴリズムのチュートリアル

 1. もし$r < 4$、出力$-1$。 

gcd が 1 より大きい最小のペアは次のとおりであるため、有効な構成には少なくとも 4 の合計が必要です。$(2,2)$。 
2. 最小の偶数整数を見つける$s$そのような$s \ge l$。 

もし$l$偶数であれば、$s = l$。 さもないと$s = l + 1$。 これにより、両方の成分が整数になることを保証する最初の候補合計が選択されます。 
3. もし$s > r$、出力$-1$。 

これは、間隔に偶数が含まれていないため、有効な対称構築が不可能であることを意味します。 
4. それ以外の場合は出力$a = s/2$、$b = s/2$。 

これにより保証されます$a + b = s \in [l, r]$そして$\gcd(a, b) = a \ge 2$。 

### なぜ効果があるのか

 この構造により、両方の数値が同一になることが強制されるため、それらの gcd は数値自体と等しくなります。 偶数の合計を選択すると、この値が少なくとも 2 になり、gcd が自明ではなくなります。 唯一の実際の制約は、間隔内で有効な偶数和が利用できるかどうかであり、パリティ チェックはその条件を正確に捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    l, r = map(int, input().split())

    if r < 4:
        print(-1)
        continue

    s = l if l % 2 == 0 else l + 1

    if s > r:
        print(-1)
    else:
        a = b = s // 2
        print(a, b)
```コードは各テスト ケースを個別に処理します。 早めのチェック`r < 4`最小の有効なペアさえも不可能なすべてのケースを削除します。 変数`s`は範囲内の最初の偶数候補であり、単純なパリティ調整を使用して計算されます。 この候補者が超過した場合`r`の場合、区間には偶数が含まれていないため、対称ペアを形成できません。 それ以外の場合は、合計を均等に分割して必要なペアを生成します。 

よくある間違いは、任意の gcd 構造を検索しようとすることです。 同一のペアはすでに gcd を最大化し、制約を最小化しているため、これは不要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        l, r = map(int, input().split())
        if r < 4:
            out.append("-1")
            continue
        s = l if l % 2 == 0 else l + 1
        if s > r:
            out.append("-1")
        else:
            a = b = s // 2
            out.append(f"{a} {b}")
    return "\n".join(out)

# custom cases

assert run("1\n4 4\n") == "2 2", "exact boundary even sum"
assert run("1\n5 5\n") == "-1", "single odd point"
assert run("1\n2 10\n") in ["1 1"], "smallest valid construction"

 ## 特殊なケース

 いつ$l = r < 4$の場合、両方の数値が自明ではない約数を共有できるほど大きな合計が存在しないため、アルゴリズムはすぐに拒否します。 例えば、$l = r = 3$可能な分解のみを生成します$(1,2)$そして$(2,1)$、両方とも gcd 1 です。 

間隔に奇数のみが含まれる場合、次のようになります。$[5,5]$または$[7,9]$範囲内に偶数がない場合、パリティ調整により候補が生成されます。$s = l + 1$、しかし、それは間隔の外にあります。 アルゴリズムは正しく出力します$-1$、等しい半分を形成することが不可能であることを反映しています。 

区間に偶数が1つ含まれる場合$s \ge 4$、構造は正確になります:$a = b = s/2$。 例えば、$l = r = 8$与える$(4,4)$、gcd は 4 に等しく、最大の強度で要件を満たします。
