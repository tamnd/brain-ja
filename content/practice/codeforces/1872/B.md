 ## 解決策
 ## 問題の理解

 私たちは 1 次元の廊下の部屋 1 に立っていて、ある部屋 k に進み、その後部屋 1 に戻りたいと考えています。時間は 1 ステップごとに正確に 1 ずつ増加するため、部屋 x に初めて到達するのに x − 1 秒かかり、戻るときも同じ速度に従います。 

一部の部屋には罠が設置されています。 各トラップは特定の部屋に配置され、最初にその部屋に入ったときからカウントされる遅延後にアクティブになります。 罠が作動すると、その部屋は永久に安全ではなくなり、出入りすることもできなくなります。 

重要な制約は、時刻 t に部屋 d に入ると、その瞬間から s 秒後に部屋が封鎖されるため、時刻 t + s では安全ではないということです。 k への前方ウォークと 1 への後方ウォークの両方が、アクティブ化の瞬間またはその後にどの部屋にも存在しないようにするための k の値が必要です。 

制約は十分に小さいので、n ≤ 100 および t ≤ 1000 であるため、各テスト ケースについて、考えられる制限トラップを O(nk) または O(n log n) で推論する余裕があります。これは、時間の経過とともにグローバルな動的プログラミングやシミュレーションを試みるのではなく、パス上のすべての部屋の中で最も制限的なトラップを直接計算することによって各テスト ケースを解決できることを示唆しています。 

複数のトラップが同じ部屋を共有している場合、微妙な失敗のケースが発生します。 部屋ごとに最初のトラップのみを処理したり、値を誤って上書きしたりする単純なアプローチでは、部屋が安全でなくなるまでの時間を過小評価する可能性があります。 もう 1 つの一般的な問題は、順方向と逆方向のタイミングが混在していることです。復路は往路よりも部屋 i に入るのが遅いため、両方向を同じアクティブ化しきい値に対してチェックする必要があります。 

## アプローチ

 ブルート フォース アプローチでは、考えられる k の値をすべて試します。 k ごとに、時間を追跡し、罠が作動した後に部屋に入るかどうかを確認しながら、旅を段階的にシミュレートします。 これはルールに直接従うため正しいですが、各シミュレーションのコストは O(k) であり、200 までのすべての k に対してこれを実行すると、テスト ケースごとに O(n^2) になります。 これは単独では許容されますが、実現可能性の条件は部屋ごとに局所的に表現できるため、不要になります。 

重要な観察は、各部屋がどこまで到達できるかについて独立した上限を課しているということです。 部屋 d に到達した場合は、前進パスと後進パスの両方でそのトラップが作動する前に確実に到着する必要があります。 到着時間は決定論的であるため、各トラップは k ≤ f(d, s) の形式の制約を与えます。 すべてのトラップに対して最小制約を取ると、答えが直接得られます。 

ブルート フォースは、各 k の有効性を明示的にチェックするため機能しますが、有効性がすべてのトラップ間の相互作用ではなく、すべてのトラップの中で最も厳しい制約にのみ依存することに気づくと失敗します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(nk) | お(1) | 許容できるが不要 |
 | 制約集約 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テスト ケースについて、各トラップを到達可能な最大 k の制限に変換します。

1. 遅延 s のある部屋 d のトラップの場合、前進中にその部屋にいることができる最新の安全な瞬間を計算します。 順方向到着時刻は d−1 であるため、d−1 < s でなければなりません。そうでない場合は、すでに遅すぎます。 これにより、d を介して間接的に k に前方制約が与えられます。 
2. 復路で、k に到着して戻ってきた場合、時間 2k − d + 1 に再び部屋 d に入ります。これも厳密に s より小さくなければなりません。 
3. 両方の条件を組み合わせて、そのトラップの k の上限を導き出します。 前方制約と後方制約のどちらが厳しいかによって、そのトラップによってもたらされる実際の制約が決まります。 
4. 非常に大きな値に初期化されたグローバル応答を維持し、各トラップに対して許容最大値 k を計算し、最小値で応答を更新します。 
5. すべてのトラップを処理した後、答えはすべての制約が満たされる最大 k になります。 

これが機能する理由は、各トラップがパスを安全に延長できる距離を個別に制限しているためです。 パスは線形で決定的であるため、トラップ間の組み合わせ依存性はなく、点単位の時間制約のみが存在します。 すべての制約の最小値により、実現可能な最大の k が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        d = []
        s = []
        for _ in range(n):
            x, y = map(int, input().split())
            d.append(x)
            s.append(y)

        ans = 10**18

        for i in range(n):
            di = d[i]
            si = s[i]

            # forward constraint: arrive at time di-1
            # must satisfy di-1 < si
            if di - 1 >= si:
                ans = 0
                continue

            # backward constraint:
            # time when returning and entering di is (2k - di + 1)
            # must satisfy 2k - di + 1 < si
            # => k < (si + di - 1) / 2
            limit = (si + di - 2) // 2

            ans = min(ans, limit)

        print(max(1, ans))

if __name__ == "__main__":
    solve()
```このソリューションは、トラップごとに、そのトラップで許可される最大 k を計算し、すべてのトラップの最小値を取得します。 順方向条件は、実現不可能な場合として早期にチェックされます。 逆方向条件は、戻り時間の式から導出される k の単純な不等式に変換されます。 

制約が厳しいため、整数の除算には注意が必要です。到着時間はアクティブ化時間よりも厳密に短くする必要があります。 

## 実用的な例

 部屋 2 に 1 つのトラップがあり、s = 2 の単純なケースを考えます。部屋 2 への前方到着は時刻 1 に発生しますが、これはまだ安全ですが、部屋 1 に戻ると時刻 3 に再び部屋 2 を通過し、これは制約に違反するため、k は 2 に制限されます。 

| トラップ | 順方向条件 | 後方制限 | 結果の k キャップ |
 | --- | --- | --- | --- |
 | (2, 2) | OK | タイト | 2 |

 ここで、1 つは非常に早く、もう 1 つは遠くにある複数のトラップについて考えてみましょう。 答えは常に最小の上限によって決定され、最も厳しい制約のみが重要であることがわかります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

 ## 特殊なケース

 重要なエッジケースは、私たちが復路で再び部屋に入ろうとしたまさにそのときにトラップが作動するときに発生します。 このアルゴリズムは、下限分割限界に変換された厳密な不等式を使用し、等価性が確実に拒否されるため、これを正しく処理します。 もう 1 つのエッジケースは、トラップがすでに前進を妨げている場合です。 その場合、k が大きくなるとリターン パスが考慮される前に安全性が侵害されるため、直ちに答えに上限を設けます。
