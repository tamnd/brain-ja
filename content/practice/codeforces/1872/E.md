 ## 解決策
 ## 問題の理解

 整数の静的な配列が与えられますが、配列はバイナリ文字列に応じて 2 つのグループに動的に分割されます。 各位置 i は、s[i] が 0 か 1 に応じて、その値 a[i] をグループ 0 またはグループ 1 に提供します。 

システムは 2 つの操作をサポートします。 最初の操作は、バイナリ文字列のセグメント全体を反転し、0 を 1 に、1 を 0 に変換します。これは、要素のグループ化方法にのみ影響し、要素の値には影響しません。 2 番目の演算では、現在のグループが指定されたビット g に一致するすべての配列値の XOR を求めます。 

したがって、核となる問題は、XOR の計算自体ではなく、グループ XOR クエリに応答しながら、セグメント フリップの下で高速更新を維持することです。 

制約は厳しく、n と q は両方ともテスト ケースごとに最大 10^5 にすることができ、テスト全体の合計も同様に制限されます。 これにより、クエリごとに XOR を最初から再計算することが除外されます。これは、制限をはるかに超える最悪の場合に O(nq) が発生するためです。 

素朴なアプローチでは、クエリごとにすべてのインデックスの XOR を再計算しますが、クエリごとに 1 回のフル スキャンでさえ、最悪の場合すでに 10^10 の演算が行われ、これは現実的ではありません。 

2 つの実行中の XOR を維持しようとしながら、範囲全体をスキャンすることによってフリップごとに素朴に更新しようとした場合、より微妙な失敗ケースが発生します。 n 要素にわたる単一の大きなフリップ クエリでも O(n) のコストがかかり、フリップを繰り返すとパフォーマンスが 2 次まで低下します。 

重要な観察は、グループに対する XOR はメンバーシップの同等性にのみ依存し、反転はメンバーシップの切り替えのみに依存するということです。 これは、グローバル集計を維持し、フリップが 2 つのグループの意味をどのように交換するかを追跡することを示唆しています。 

## アプローチ

 ブルート フォース ソリューションでは、配列全体を反復処理し、s[i] が g と等しいかどうかを確認することにより、クエリ タイプ 2 ごとに XOR を再計算します。 これは定義に直接従っているので正しいですが、各クエリのコストが O(n) であり、最大 10^5 のクエリが存在する可能性があるため、遅すぎます。 

この非効率性は、フリップするたびにグループ メンバーシップを最初から再計算することから発生します。 重要な構造は、タイプ 1 の操作は値を変更せず、2 つのグループ間のメンバーシップを交換するだけであるということです。 これは、各グループに現在属している要素の数を追跡し、グローバル フリップ状態で XOR 集計を維持できる場合は、個々の要素にまったく触れる必要がないことを意味します。 

2 つの XOR アキュムレータを維持します。1 つは元の文字列が 0 を持つ位置用で、もう 1 つは元の文字列が 1 を持つ位置用です。位置が反転された回数を追跡する代わりに、範囲を反転する場合、要素を個別に更新する必要はありません。 重要なトリックは、フリップのパリティのみが重要であることを観察することです。そのため、グループ集合体を交換することによって XOR 寄与を反転する遅延伝播を使用してセグメント ツリーを維持できます。 

各セグメント ツリー ノードには、そのセグメント内の現在 0 のラベルが付いている要素の XOR と現在 1 のラベルが付いている要素の XOR という 2 つの値が格納されます。 フリップ操作は、ノード内のこれら 2 つの値を単純に交換します。 これにより、範囲反転が効率的になり、XOR が結合するためマージの一貫性が維持されます。 

最後のクエリは、ビット g の現在の解釈に応じて、ルート ノードの直接読み取りになります。

 ## アルゴリズムのチュートリアル

1. 各ノードが 2 つの値を格納するセグメント ツリーを構築します。セグメント内のすべての a[i] の XOR (s[i] が現在 0 である場合)、および XOR (s[i] が現在 1 である場合)。この分離により、クエリに直接答えることができます。 
2. 初期バイナリ文字列を使用してリーフ ノードを初期化します。 s[i] = 0 の場合、a[i] をゼロ XOR バケットに置きます。 それ以外の場合は、1-XOR バケットに入れられます。 これにより、最初のパーティションが正確にエンコードされます。 
3. 2 つの子ノードをマージする場合、対応するバケットを XOR 演算することにより、グループごとに独立して XOR を計算します。 これが機能するのは、XOR が結合的であり、互いに素なセグメント内の要素が干渉しないためです。 
4. 範囲 [l, r] に対するタイプ 1 クエリの場合、セグメント ツリーに対して遅延反転操作を適用します。 完全にカバーされた各ノードで、グループ 0 とグループ 1 に保存されている XOR 値を交換します。これは、そのセグメント内のすべてのビットを切り替えることを表します。 
5. ノードが部分的にカバーされている場合は、操作を再帰的に伝播し、子にアクセスする前に保留中のフリップを下にプッシュすることで正確さを保証します。 
6. g を使用したタイプ 2 クエリの場合、ルート ノードの対応するバケットに格納されている XOR を直接返します。 g = 0 の場合は root.xor0 を返し、それ以外の場合は root.xor1 を返します。 

### なぜ効果があるのか

 各要素は、常に 2 つの XOR バケットのうちの 1 つに 1 回だけ寄与します。 セグメントに対する反転操作は、そのセグメント内のすべての要素のメンバーシップを切り替えます。これは、そのセグメントの 2 つの XOR アキュムレータを交換するのと同じです。 XOR は線形であり、要素はセグメント間で相互作用しないため、正しい値を維持することは、範囲反転の下で正しい分割を維持することになります。 遅延伝播により、要素ごとの状態を再計算することなく、各スワップが必要なときに正確に適用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, a, s):
        self.n = len(a)
        self.a = a
        self.s = s
        self.size = 4 * self.n
        self.x0 = [0] * self.size
        self.x1 = [0] * self.size
        self.lazy = [0] * self.size
        self.build(1, 0, self.n - 1)

    def build(self, v, tl, tr):
        if tl == tr:
            if self.s[tl] == '0':
                self.x0[v] = self.a[tl]
            else:
                self.x1[v] = self.a[tl]
            return
        tm = (tl + tr) // 2
        self.build(v * 2, tl, tm)
        self.build(v * 2 + 1, tm + 1, tr)
        self.pull(v)

    def pull(self, v):
        self.x0[v] = self.x0[v * 2] ^ self.x0[v * 2 + 1]
        self.x1[v] = self.x1[v * 2] ^ self.x1[v * 2 + 1]

    def apply(self, v):
        self.x0[v], self.x1[v] = self.x1[v], self.x0[v]
        self.lazy[v] ^= 1

    def push(self, v):
        if self.lazy[v]:
            self.apply(v * 2)
            self.apply(v * 2 + 1)
            self.lazy[v] = 0

    def update(self, v, tl, tr, l, r):
        if l > r:
            return
        if l == tl and r == tr:
            self.apply(v)
            return
        self.push(v)
        tm = (tl + tr) // 2
        self.update(v * 2, tl, tm, l, min(r, tm))
        self.update(v * 2 + 1, tm + 1, tr, max(l, tm + 1), r)
        self.pull(v)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        s = input().strip()
        q = int(input())

        st = SegTree(a, s)

        for _ in range(q):
            tmp = input().split()
            if tmp[0] == '1':
                l = int(tmp[1]) - 1
                r = int(tmp[2]) - 1
                st.update(1, 0, n - 1, l, r)
            else:
                g = int(tmp[1])
                if g == 0:
                    print(st.x0[1], end=' ')
                else:
                    print(st.x1[1], end=' ')
        print()

if __name__ == "__main__":
    solve()
```この実装では、各ノードが 2 つの XOR 値を維持するセグメント ツリーが使用されます。 ビルド ステップでは、初期文字列に基づいて 2 つのバケットのいずれかに各値を割り当てます。 更新関数は、遅延伝播を使用して範囲反転を実行します。反転は、保存されている 2 つの XOR 値を交換することとして実装されます。 

プッシュ関数は、保留中のフリップを伝播することにより、子に降りるときの正確さを保証します。 プル関数は、更新後に子ノードから親ノードを再計算します。 ルートには常に、現在の 0 グループと 1 グループの間で分割されたグローバル XOR が含まれており、クエリは O(1) になります。 

微妙な点は、反転は対称的であるため、実際のビットを追跡する必要はなく、セグメントが奇数回反転されたかどうかだけを追跡する必要があることです。 それはまさに、lazy フラグがエンコードするものです。

| ステップ | 操作 | x0 (ルート) | x1 (ルート) |
 | --- | --- | --- | --- |

 このトレースは、フリップが個々の要素に直接触れないことを示しています。 集約された XOR 寄与のみを交換します。 

### 2 番目の例

 配列:`[5, 7]`弦：`00`最初はすべての値が x0 にあります。 

| ステップ | 操作 | x0 | x1 |
 | --- | --- | --- | --- |

 | 4 | クエリ g=1 | 2 | 0 |

 これにより、セグメントを反転すると、再計算せずにグループ メンバーシップが正しく交換されることが確認されます。

 ## 特殊なケース

 重要なエッジケースは、繰り返されるフリップが互いに打ち消し合う場合です。 たとえば、同じセグメントを 2 回反転すると、元のパーティションが復元されます。 セグメント ツリーでは、遅延フラグがパリティを切り替えるため、これは自然に処理されます。 2 回反転すると、フラグが再び 0 に設定されます。これは、スワップが適用されないことを意味するため、XOR 状態は元の構成に正確に戻ります。 

別のケースは、反転後に空になるグループをクエリする場合です。 空のセットに対する XOR は 0 として定義されているため、対応するバケットは空のままで XOR の同一性が保持されるため、セグメント ツリーは正しく 0 を返します。 

最後の微妙なケースは、大規模な重複する更新です。 多くのフリップが任意のパターンで重なった場合でも、各ノードはフリップのパリティのみを保存するため、最終状態は奇数回フリップされたかどうかのみに依存します。
