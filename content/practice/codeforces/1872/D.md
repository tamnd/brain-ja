 ## 解決策
 ## 問題の理解

 1 から n までの数字の順列が与えられており、これらの数字を任意の順序で配置することができます。 配置が決まったら、特定の位置だけを見るルールで評価します。 

2 セットのポジションが重要です。 x で割り切れるすべてのインデックスはスコアにプラスに寄与し、y で割り切れるすべてのインデックスはマイナスに寄与します。 位置が x と y の両方で割り切れる場合、その値は 1 回だけ減算されますが、同じ位置も正のセットにカウントされるため注意が必要です。 

したがって、スコアは、x のみで割り切れるもの、y のみで割り切れるもの、および両方で割り切れるものの 3 つのインデックス カテゴリにどれだけ大きな値が配置されるかによって完全に決まります。 

目標は、大きな数字がプラスに貢献する位置に着地し、小さな数字がスコアを減らす位置に着地するように順列を調整することです。 

制約は n = 10^9 までで、テスト ケースは最大 10^4 です。 これにより、すべての位置を反復したり、順列を明示的に構築したりするアプローチは即座に除外されます。 テスト ケースごとの線形でも大きすぎます。 

唯一の実行可能な解決策は、反復ではなく算術を使用して、各カテゴリに該当する位置の数を数えることに問題を減らす必要があります。 

一般的な失敗例は、x と y が等しいか、一方が他方を割る場合に発生します。 たとえば、x = y の場合、すべてのインデックスは正と負の両方であるため、すべての寄与がキャンセルされ、配置に関係なく、答えは常に 0 になる必要があります。 もう 1 つの微妙なケースは、x と y が倍数を共有する場合です。これは、慎重に扱わないと、これらのインデックスが二重にカウントされるためです。 

## アプローチ

 ブルートフォース戦略では、すべての順列を試し、それぞれのスコアを計算します。 順列ごとに、すべてのインデックスをスキャンし、寄与を蓄積します。 これは n の階乗であり、n = 10 の場合でも不可能です。 

もう少し素朴なアイデアは、順列を修正し、貪欲な配置をシミュレートすることですが、それでも、すべての n 位置について明示的に推論する必要があります。 中心となる問題は、位置の寄与が局所構造ではなく、可分性のみに依存するため、位置ごとのシミュレーションが O(n) になることです。 

重要な観察は、ポジションの実際のアイデンティティは個別には問題ではないということです。 各カテゴリに該当するポジションの数のみが重要であり、その数がわかれば、常に最も有利なポジションに最大の番号を割り当てることができます。 

インデックスを 3 つのグループに分類します。 A を x で割り切れるインデックスとします。 B を y で割り切れるインデックスとします。 オーバーラップ C は lcm(x, y) で割り切れるインデックスです。 C のインデックスは A と B の両方に表示されます。つまり、加算と減算がそれぞれ 1 回行われるため、正味の効果はゼロになります。 

したがって、A \ C のインデックスのみがプラスに寄与し、B \ C のインデックスはマイナスに寄与します。 したがって、最適な戦略は単純です。最大の数値を A \ C に割り当て、最小の数値を B \ C に割り当てます。その他はすべて中立です。 

問題を、A、B、C に該当するインデックスの数を数えるという問題に落とし込みます。これはフロア分割で実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | テストごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. n // x を使用して、x で割り切れるインデックスの数を計算します。 これらは候補ポジションです。 
2. n // y を使用して、y で割り切れるインデックスの数を計算します。 これらは候補となるネガティブなポジションです。 
3. n // lcm(x, y) を使用して、x と y の両方で割り切れるインデックスの数を計算します。 これらは、寄与が相殺される重複ポジションです。 
4. 両方のカウントから重複を削除します。 有効な正の位置は pos = n // x - n // lcm(x, y) となり、有効な負の位置は neg = n // y - n // lcm(x, y) になります。 
5. 概念的にロジックを並べ替えます。値 1..n を割り当てます。 最大値は正の位置に配置され、最小値は負の位置に配置されます。 
6. 正の位置からの寄与を最大の位置番号の合計 (n-pos+1 から n までの合計) として計算します。 
7. 負の位置からの寄与を、最小の負数の合計 (1 から負までの合計) から引いたものとして計算します。 
8. 差分を出力します。 

これが機能する理由: 順列の自由により、位置に値を任意に割り当てることができ、スコアは値が線形です。 並べ替えに対する線形目標は、整列を並べ替えることによって最大化されるため、位置の重みによる貪欲な割り当てが最適です。 唯一重要な部分は、位置が二重にカウントされないように、重複するインデックスを正しく解決することです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def lcm(a, b):
    import math
    return a // math.gcd(a, b) * b

t = int(input())
for _ in range(t):
    n, x, y = map(int, input().split())

    g = lcm(x, y)

    pos = n // x - n // g
    neg = n // y - n // g

    # sum of largest pos numbers
    pos_sum = pos * (2 * n - pos + 1) // 2

    # sum of smallest neg numbers
    neg_sum = neg * (neg + 1) // 2

    print(pos_sum - neg_sum)
```コードはまず最小公倍数を計算して、重複するインデックスを特定します。 これらの立場は相殺され、どちらの側にも影響を与えてはいけないため、この重複は非常に重要です。 

次に、除外後にプラスおよびマイナスに寄与するポジションの数を計算します。 これらのカウントが判明すると、問題は算術シーケンスの合計、つまり正の寄与の最大値と負の寄与の最小値に集約されます。 

算術式は配列の構築を回避し、テスト ケースごとの定数時間の計算を保証します。 

## 実用的な例

 2 つのケースを追跡して、カウントが最終的な答えにどのように変換されるかを確認します。 

### 例 1

 入力: n = 7、x = 2、y = 3

 まず、lcm(2,3) = 6 を計算します。 

ポジションを数えます:

 | ステップ | 値 |
 | --- | --- |
 | n // x | 3 |
 | なし // はい | 2 |
 | n // lcm | 1 |
 | 位置 | 2 |
 | 否定 | 1 |

 次に寄与を計算します。 

| コンポーネント | 式 | 値 |
 | --- | --- | --- |
 | pos_sum | 6,7の合計 | 13 |
 | マイナスサム | 1の合計 | 1 |
 | 答え | 13-1 | 12 |

 これは、最適な配置の直感と一致します。2 つの最大の数値はインデックス 2 と 4 に割り当てられ、最小の数値はインデックス 3 に割り当てられます。 

### 例 2

 入力: n = 12、x = 6、y = 3

 lcm(6,3) = 6 を計算します。 

| ステップ | 値 |
 | --- | --- |
 | n // x | 2 |
 | なし // はい | 4 |
 | n // lcm | 2 |
 | 位置 | 0 |
 | 否定 | 2 |

 現在の貢献:

 | コンポーネント | 値 |
 | --- | --- |

 これは、すべてのプラスのポジションがオーバーラップによって完全にキャンセルされ、マイナスの影響だけが残ることを示しています。

 各テスト ケースがいくつかの整数演算に削減されるため、このソリューションは最大 10^4 のテスト ケースを簡単に処理します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def lcm(a, b):
        import math
        return a // math.gcd(a, b) * b

    t = int(input())
    out = []
    for _ in range(t):
        n, x, y = map(int, input().split())
        g = lcm(x, y)
        pos = n // x - n // g
        neg = n // y - n // g

        pos_sum = pos * (2 * n - pos + 1) // 2
        neg_sum = neg * (neg + 1) // 2

        out.append(str(pos_sum - neg_sum))

    return "\n".join(out)

 ## 特殊なケース

 x が y と等しい場合、すべてのインデックスはプラスとマイナスの両方に寄与します。 その場合、n // x は n // y に等しく、n // lcm にも等しいため、pos と neg は両方ともゼロになります。 このアルゴリズムは、特別な分岐を行わずに直接 0 を返します。 

x が y を割る場合、または y が x を割る場合、重複はセットの 1 つを支配します。 たとえば、x = 2 および y = 4 の場合、4 で割り切れるインデックスはすべて、2 で割り切れるインデックスとしてすでにカウントされています。 n // lcm を減算すると、これらの重複が正しく除去され、真の排他的寄与のみが残ります。 

x または y が 1 の場合、セットの 1 つにすべてのインデックスが含まれます。 フロア分割ではすべての位置が正しくカウントされ、オーバーラップ処理により二重カウントが防止されるため、算術演算は引き続き正確に適用されます。
