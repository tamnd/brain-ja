 ## 解決策
 ## 問題の理解

 すべての要素が 6 つの固定値 (4、8、15、16、23、42) のいずれかであることが保証されている長いシーケンスが与えられています。タスクは、値を並べ替えたり変更したりするのではなく、残った要素を長さ 6 の完全な順序付けされたチェーンに分割できるように要素を削除することだけです。 有効な各チェーンは、4 → 8 → 15 → 16 → 23 → 42 という厳密な順序に従う必要があり、残りの配列の各要素は、そのようなチェーン位置の 1 つに正確に属している必要があります。 

目標は、元の順序から形成できる完全なチェーンの数を最大化することです。これは、6 つの完全なチェーンがすべて保持される要素に寄与し、これらのチェーンの外側にあるものはすべて削除する必要があるためです。 完全なチェーンの最大数がわかれば、答えは単純に要素の合計からその数の 6 倍を引いたものになります。 

制約は大きく、最大 500,000 個の要素があります。 これにより、二次関数や偶数関数が即座に除外されます。$O(n \log n)$要素ごとに重い状態でアプローチします。 解は線形であるか、線形に非常に近く、単一パスまたは少数の一定数のパスで配列を処理する必要があります。 

貪欲な戦略が各数値の頻度を個別に追跡するだけである場合、微妙な失敗例が発生します。 たとえば、4 の前に 8 がたくさんある場合、または 16 の前に 23 がたくさんある場合、単純に数えるとチェーンの可能性が過大評価されてしまいます。 順序の依存関係は厳密であるため、合計だけでなく順序を尊重する必要があります。 もう 1 つの注意が必要なケースは、複数の部分シーケンスをインターリーブすることです。 以前の要素がどのように消費されたかに応じて、同じ値が異なるチェーンで使用できる場合があります。 

## アプローチ

 強引なアイデアは、考えられるすべてのチェーンの構築をシミュレートすることです。 部分的に構築されたシーケンスをすべて維持しながら、各要素をシーケンスに貪欲に割り当てることを試みることもできます。 新しい番号はそれぞれ、互換性のある部分チェーンを拡張しようとするか、それが 4 の場合は新しい番号を開始しようとします。潜在的に多くの不完全なチェーンを追跡する必要があるため、これはすぐに複雑になります。 最悪の場合、要素が敵対的なパターンで交互に現れると、次のような結果になる可能性があります。$O(n)$アクティブな部分チェーンが存在し、更新のたびにそれらの多くがスキャンされる可能性があるため、$O(n^2)$行動。 

重要な観察点は、すべてのチェーンが同一であり、厳密に順序付けされているということです。 個々のチェーンを追跡する必要はなく、完了の各段階で現在待機しているチェーンの数だけを追跡する必要があります。 シーケンスを追跡する代わりに、各プレフィックスに到達した部分チェーンの数 (4 を見た数、4→8 を見た数、4→8→15 を見た数など) を追跡します。 

これにより、問題がパイプラインに変わります。 各数字はステージからチェーンを進めます。$i$に$i+1$、またはその段階で利用可能なチェーンがない場合は無視されます。 貪欲なルールは、常に可能な限り早い段階を延長することです。 

これにより、問題は固定の 6 段階の DP のようなシミュレーションに縮小されます。

 ## アルゴリズムのチュートリアル

 各値をシーケンス内の位置にマップします。4 はステージ 0、8 はステージ 1、15 はステージ 2、16 はステージ 3、23 はステージ 4、42 はステージ 5 です。 

配列を維持します`cnt[6]`、 どこ`cnt[i]`ステージで現在値を待っている部分シーケンスの数です。`i`。 

また、完了した完全なチェーンの数も管理します。 

1. すべてのカウントをゼロに初期化します。 順序の制約を自然に維持しながら、数値を左から右に処理します。 
2. 値を読み取るときに、そのステージインデックスを決定します。 
3. 値が 4 (ステージ 0) の場合、常に増加して新しい部分チェーンを開始します。`cnt[0]`。 これはチェーンを開始できる唯一の値です。 
4. ステージ上のその他の値の場合`i > 0`、現在この値を待っているチェーンを拡張しようとします。 もし`cnt[i-1] > 0`、デクリメントします`cnt[i-1]`そして増加します`cnt[i]`。 これは、以前に開始された部分チェーンを消費し、それを進めることを表します。 
5. 値が 42 (ステージ 5) の場合、チェーンをステージ 5 に拡張した後、直ちにチェーンを完了します。 したがって、減少した後`cnt[4]`では、ステージ 5 のチェーンを保存する代わりに、完了したチェーンの数を増やします。 
6. 拡張できるチェーンがない場合は、何もせずに要素を暗黙的に破棄します。 これは、最適解で削除された要素の 1 つであることに対応します。 

重要な考え方は、割り当てを決して遅らせないということです。 各要素は可能であればすぐに使用され、常に互換性のある最も早い段階で使用されます。 

### なぜ効果があるのか

 部分チェーンの構造は、次に必要な各値を待っているチェーンの数によって常に完全に把握されます。 すべてのチェーンは同一の構造を持ち、すべての要素が順番に処理されるため、前のステージが使用可能である間に値を後のステージに割り当てる決定は、将来の柔軟性を低下させるだけです。 可能な限り初期の段階を貪欲に拡張することで、後で完全なシーケンスを完了する能力を最大限に維持できます。 これにより、次の不変条件が維持されます。`cnt[i]`は常に、ステージに到達できる部分シーケンスの最大可能数です。`i`処理されたプレフィックスを使用します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    order = {4: 0, 8: 1, 15: 2, 16: 3, 23: 4, 42: 5}
    cnt = [0] * 6
    completed = 0
    
    for x in a:
        i = order[x]
        
        if i == 0:
            cnt[0] += 1
        else:
            if cnt[i - 1] > 0:
                cnt[i - 1] -= 1
                if i == 5:
                    completed += 1
                else:
                    cnt[i] += 1
    
    print(n - completed * 6)

if __name__ == "__main__":
    solve()
```このソリューションでは、各要素が 1 回だけ処理されます。 ディクショナリは各値をそのステージ インデックスにマップするため、遷移は一定時間になります。 の`cnt`配列は、各ステージで待機している部分チェーンの数を追跡します。 42 に達すると、完了したチェーンは今後の遷移に参加しないため、完了のみをカウントし、それ以上は保存しません。 

よくある実装の落とし穴は、42 がチェーンを終了する代わりに新しい状態を作成することを誤って許可してしまうことです。 もう 1 つは、各要素が最大でも 1 つのチェーンだけ進むことを確認することを忘れていることです。

 ## 特殊なケース

 重要なエッジケースは、要素が部分的に正しい順序で到着しても、完了する前に「壊れて」しまう場合です。 のような入力の場合`4 8 15 16 42 23`、アルゴリズムはステージ 3 まで正常に進み、42 でチェーンを完了できず、その後 23 を役に立たないものとして扱います。 最終的な完了カウントはゼロのままで、完全なチェーンが存在しないという事実と一致します。 

もう 1 つの特殊なケースは、4 の前に多くの 8 が表示されるなど、初期のミドル要素が過剰であることです。 このアルゴリズムは単純に一致しない 8 を破棄します。`cnt[0]`はゼロです。 これにより、無効なチェーン構築が防止され、早期に進行することがなくなります。 

最後のエッジケースは、複数のチェーンの大量のインターリーブです。 各ステージ カウンターは独立したチェーン容量を表すため、このアルゴリズムでは、利用可能なステージが複数の部分チェーンに自然に分散されます。 これにより、最適なマッチングを維持しながら、明示的なチェーン追跡の必要性が回避されます。
