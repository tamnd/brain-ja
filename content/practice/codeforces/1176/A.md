 ## 解決策
 ## 問題の理解

 開始整数が与えられ、小さな固定セットの割り算演算を使用して繰り返し縮小することができます。 各操作は、現在の値をより小さい値に置き換えますが、これは、現在の値が特定の数 (2、3、または 5) で割り切れる場合に限られます。目標は、できるだけ少ない操作を使用して、その数値を正確に 1 に変換することです。 これらのルールを使用して 1 に到達する方法がない場合は、不可能であることを報告する必要があります。 

各クエリは独立しているため、この変換問題をさまざまな開始値に対して複数回解決します。$10^{18}$。 重要な考え方は、すべての演算は厳密に数値を減らすため、有効なプロセスは有限であるが、許可される演算は構造化された比率の特定の素因数を削除するだけであるため、すべての整数を 1 に減らすことはできないということです。 

制約$n \le 10^{18}$考えられるすべての変換パスをシミュレートするアプローチは直ちに除外されます。 状態空間には制限がなく、分岐が中程度であっても爆発するため、値を超える BFS または DP は不可能です。 残されたのは、数列を探索するのではなく、数値の構造を直接推論する方法です。 

数値に 2、3、または 5 以外の素因数が含まれる場合、微妙なエッジケースが発生します。たとえば、次のようになります。$n = 14$係数 7 が含まれています。係数 7 を削除する操作は存在しないため、いかなる操作も即座に失敗します。 正しい出力は -1 です。 可能な場合にのみ操作を試行する不注意な貪欲なリダクションは、最終的な到達可能性を明示的に検証しない場合、依然としてループしたり、誤って成功と結論付けたりする可能性があります。 

別のエッジケースは、数値がすでに 1 である場合に発生します。この場合、演算は必要なく、答えは 0 です。常に除算を試行する単純なループは誤って不要な演算を試行する可能性があるため、これは重要です。 

## アプローチ

 ブルートフォース解釈では、エッジが有効な操作を表すグラフ内の状態として各数値を扱います。 どの番号からでも$n$、私たちはに行くことができます$n/2$、$2n/3$、 または$4n/5$割り切れる条件が満たされたとき。 BFS は、1 に到達するための最小ステップ数を保証します。 

すべての操作のコストが等しく、BFS は距離の増加順に状態を探索するため、このアプローチは正しいです。 ただし、重大な欠陥は、到達可能な状態の数が有効な方法で制限されていないことです。 全体的に値が減少しても、さまざまな因子除去順序間で分岐すると多くの中間状態が作成され、数値が大きい場合、これは実行不可能になります。 

重要な観察点は、操作の構造が恣意的ではないということです。 各演算では素因数 2、3、または 5 のみが削除され、固定比率で削除されます。 これは、操作の順序は重要ではないことを意味します。 重要なのは、各素因数を何回削除するかです。 問題は、2、3、5 の多重度を数えるということになります。$n$他の素因数が存在しないことを確認しながら。 

これを認識すると、最適解は単純な因数分解ループになります。つまり、2 を繰り返し、次に 3、次に 5 を除算し、それぞれの除算を何回実行したかを追跡します。 考えられる 2、3、5 をすべて削除した後、1 以外が残っている場合、答えは不可能です。

 ## アルゴリズムのチュートリアル

 各クエリを個別に処理し、段階的に数を減らします。 

1. 番号を読み取ります$n$。 もし$n = 1$、操作は必要ないため、すぐに 0 を出力します。 これにより、ループに入らずに縮退ケースがきれいに処理されます。 
2. カウンタの初期化`moves = 0`。 これにより、実行された操作の合計数が保存されます。 
3. その間$n$2で割り切れる場合は、2で割って増加します`moves`。 このような各除算は 1 つの有効な演算に正確に対応するため、2 のすべての因数を貪欲に抽出しています。 
4. 3 についても同じプロセスを繰り返します。$n$は 3 で割り切れます。除算して増分します。`moves`。 これにより、2 番目の操作タイプからのすべての寄与が確実に考慮されます。 
5. 5 をもう一度繰り返します: while$n$は 5 で割り切れます、割って増分します`moves`。 これにより、3 番目の操作タイプに対応するすべての要素が抽出されます。 
6. 2、3、5 のすべての因数を削除した後、残りの値が 1 であるかどうかを確認します。そうでない場合は、-1 を出力します。これは、これが意味することです。$n${2, 3, 5} の外側に少なくとも 1 つの素因数が含まれており、許可された操作では決して削除できません。 
7. 残りの値が 1 の場合、出力`moves`。 

### なぜ効果があるのか

 すべての操作では、制御された方法で数値から 1 種類の素因数のみが削除されます。 新しい素数を導入したり、{2, 3, 5} の外側の素数を変更したりする操作はありません。 したがって、有効な一連の演算は、次の因数分解から 2、3、および 5 の出現をすべて削除することに正確に対応します。$n$。 素因数分解では乗算が可換であるため、削除の順序は重要ではありません。 これらの素数を削除した後に何かが残った場合、その残りの要素はルールの下では不変であるため、1 に到達することは不可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(n: int) -> int:
    moves = 0

    for p in (2, 3, 5):
        while n % p == 0:
            n //= p
            moves += 1

    return moves if n == 1 else -1

q = int(input())
for _ in range(q):
    n = int(input())
    print(solve(n))
```このソリューションでは、素数 2、3、5 に対する小さなループを使用して、各数値を独立して処理します。各除算は、許可された 1 つの演算に正確に対応するため、除算を数えることで直接答えが得られます。 最終チェックにより、無効な素因数が残っていないことが確認されます。 

各ループは独立しており、その素数の寄与のみを削除するため、素数の処理順序は重要ではありません。

 ## 特殊なケース

 のために$n = 1$の場合、アルゴリズムは要素チェックの前にすぐに 0 を返します。 これにより、不必要な除算を誤って数えることを避けられます。 

のような数値の場合$n = 1000000000000000000$、アルゴリズムは 2、次に 3、次に 5 で繰り返し除算します。数値が大きい場合でも、許可された素因数のみが含まれているため、数値はすぐに 1 に崩壊します。 The loop structure guarantees correctness since each removal is exact and irreversible.

 のために$n = 14$、この数値は、残りの因数 7 ですべての許可された除算を生き残ります。アルゴリズムは、最終チェックでこれを正しく検出します。$n \neq 1$部分的な削減が早期に発生した場合でも、誤検知が発生しないようにします。
