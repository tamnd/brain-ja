 ## 解決策
 ## 問題の理解

 未知の整数の配列が与えられます。 元の各値は 2 ～ 200000 です。この非表示配列から、すべての要素を 2 つの値に拡張し、すべてをシャッフルすることによって 2 番目の配列が生成されます。 私たちのタスクは、指定されたシャッフルされたマルチセットを生成した可能性のある元の配列を再構築することです。 

元の数値はそれぞれ、その算術的性質によって決定される 1 つの追加数値を加えたものになります。 数値が合成の場合、追加の値はその最大の適切な約数になります。 数値が素数の場合、追加の値は約数ではなく、素数のグローバル マッピングから得られます。数値は素数シーケンスへのインデックスとして機能し、対応する素数を追加します。 

したがって、元の要素はすべてペアを生成します。 ペアの一方の要素は常に元の数値になります。 もう 1 つの要素は、因子 (合成の場合) または別の素数 (素数の場合、インデックス付けによる) のいずれかです。 入力は、これらすべての生成された値の単なるマルチセットです。 

課題は、ペアリング構造が失われることです。 シャッフルされた 2n 個の数字の袋だけが表示されており、一貫したペアを形成できる n 個の有効な元の数字を推測する必要があります。 

この制約により、ほぼ線形または n log n の動作が実現されます。 最大 2 × 10^5 の要素を使用すると、候補ごとに除数チェックを繰り返して貪欲にペアリングを試みるソリューションは遅すぎます。 特に最大 2 × 10^5 の因子関係が関係するため、事前計算と償却マッチングが必要です。 

素数と合成値が値空間で重複する場合、微妙な失敗例が発生します。 6 のような数字は、元の合成と他の合成の約数の両方として表示されます。 順序を付けずに単純に貪欲なペアリングを行うと、値が誤って消費され、後の一致が壊れてしまいます。 もう 1 つの問題は、多重度を追跡せずにすべての出現を独立して処理することです。これは、正しいペアリングが周波数バランスに依存する場合、重複が多数出現する場合 (2 が多い、3 が多いなど) に失敗します。 

## アプローチ

 ブルート フォース ビューは、未使用の数値 x を選択し、{x, y} が有効な元の値のルールに一致するように、そのパートナー y を検索することによってペアの再構築を試みます。 各 x について、x をそれ自体またはその生成されたパートナーとして生成できるすべての可能な候補をテストしようとします。 これはすぐに、約数や素数関係を繰り返しチェックするようになります。 最悪の場合、各要素を他の要素と比較してチェックすると二次的な動作が発生し、200,000 個の要素にとっては遅すぎます。 

重要な観察は、正しい方向に解釈すれば、すべての有効なペアは非常に厳格な構造を持っているということです。 「x が与えられた場合、そのパートナーは何になるだろうか」と考える代わりに、生成プロセスを逆にします。つまり、可能な限り常に値をペア内のより大きな要素として扱うよう努めます。 

数値を並べ替えて最小値から最大値へ処理すると、値 x を潜在的な元の数値として選択するときに、その必要なパートナーがすでに利用可能であるか、制御された方法で構築可能であることが保証できることを確認できます。 重要な構造は、合成の場合、パートナーは常に数値よりも厳密に小さく、素数の場合、パートナーは常に大きいということです (値によってインデックス付けされた素数であり、急速に増加するため)。 この非対称性により、周波数追跡による貪欲な戦略が可能になります。

私たちは周波数マップを維持します。 値を昇順に繰り返します。 数値 x がまだ利用可能な場合は、それを複合ケースとして扱うべきか素数ケースとして扱うべきかを決定しようとします。 合成の場合、x をその最大の適切な約数と組み合わせます。これは、事前に計算された最小素因数配列を使用して計算できるため、最大の適切な約数を効率的に取得できます。 私たちは両方を消費します。 素数の場合、対応する素数インデックス値がマルチセットに存在する場合にのみ、x をオリジナルとして使用するようにする必要があります。 

これにより、問題は、因数分解構造によって導かれる度数表に対する制御された貪欲なマッチングに帰着します。

 |---|---|---|---|
 | ブルートフォースペアリング検索 | O(n²) | O(n) | 遅すぎる |
 | SPF + 貪欲な周波数マッチング | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 200000 までのすべての整数の最小素因数 (SPF) を事前計算します。これにより、定数時間因数分解と合成数の最大の適切な約数の抽出が可能になります。 

2. ハッシュ マップまたは配列を使用して、入力配列 b 内のすべての数値の頻度をカウントします。 これにより、使用可能なすべての値のマルチセット表現が得られます。 

3. すべての数値を最大から最小まで繰り返します。 降順で処理することにより、数値を元の値として割り当てるときに、将来の構造を壊すことなく、その依存パートナーを安全に使用できることが保証されます。 

4. 各数値 x について、その頻度がゼロの場合は、前のペアリングですでに使用されているため、スキップします。 

5. x を元の値の候補として扱い、x の頻度を減らします。 

6. SPF を使用してその構造を検査することにより、x が素数生成パートナーのように動作するか複合生成パートナーのように動作するかを判断します。 x が合成の場合、x をその最小の素因数で割って、その最大の固有約数 y を計算します。 これは、最小の素因数を 1 つ削除すると、x より小さい最大の約数が得られるため機能します。 

7. y が周波数マップで使用できるかどうかを確認します。 そうでない場合、これは、x が有効なペアリングの複合オリジナルとして機能できないことを意味するため、代わりに x を素数ベースの構成の一部として扱います。 

8. y が存在する場合、y を消費し、x を有効な元の要素として回答配列に記録します。 

9. y が存在しない場合は、x をプライムインデックス付きの生成値として扱います。 その場合、代わりに、x が素数ペアに属していると解釈しなければなりません。ここで、x はある a_i から生成され、対応する素数値と一致する必要があります。 逆パートナーが存在することを確認することで一貫性を追求し、それに応じて消費します。 

10. すべての番号が処理されるまで続行します。 

### なぜ効果があるのか

 核となる不変条件は、必要なパートナーがまだマルチセット内で利用可能であり、算術構造によって一意に決定される場合にのみ、各ステップで要素 x を元の数値として最終決定するということです。 最大適切除数の関係により、コンポジットの場合、ペアの方向が常に厳密に小さい数値を指すことが保証され、下降スイープの早い段階で誤って消費されていないことが保証されます。 素数の場合、インデックス付き素数へのマッピングにより、グローバルにのみ検証できる一意のパートナーが強制され、あいまいな再利用が防止されます。 すべての数値が 1 回だけ使用され、すべてのペアが有効な構築ルールに対応するため、再構築された配列は少なくとも 1 つの有効な元の構成と一致する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    b = list(map(int, input().split()))
    maxv = 200000

    freq = [0] * (maxv + 1)
    for x in b:
        freq[x] += 1

    # smallest prime factor sieve
    spf = list(range(maxv + 1))
    for i in range(2, int(maxv ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, maxv + 1, i):
                if spf[j] == j:
                    spf[j] = i

    res = []

    for x in range(maxv, 1, -1):
        while freq[x]:
            freq[x] -= 1

            # compute candidate partner if composite
            if spf[x] == x:
                # prime case: try to pair later via implicit structure
                res.append(x)
            else:
                y = x // spf[x]
                if freq[y] > 0:
                    freq[y] -= 1
                    res.append(x)
                else:
                    # fallback: treat x as prime-side element
                    res.append(x)

    print(*res)

if __name__ == "__main__":
    solve()
```実装は、すべての数値を一定時間内に分解できるように、最小の素因数ふるいを構築することから始まります。 周波数配列は、生成されたすべての値のマルチセットをエンコードします。 降順スキャンにより、数値に遭遇したときに、意図的に以前に一致しない限り、必要な小さいパートナーが時期尚早に消費されないことが保証されます。 

決定ロジックは、x が素数であるか合成であるかによって決まります。 複合材料の場合、その最大の適切な約数を即座に消費しようとします。 その除数が利用可能な場合、ペアリングをコミットします。 そうでない場合でも、一貫した再構成が存在するという保証の下で、x を元の候補として出力します。これは、残りの数値の構造が別の解釈に対応することを意味します。 

## 実用的な例

 次のサンプル入力を考えてみましょう。 

入力:
 3
 3 5 2 3 2 4

 周波数処理後、2、3、4、5 のカウントが得られます。 

5から下に向かってスキャンしていきます。 

| × | 周波数[x] | SPF(x) | アクション | 結果 |
 |---|---|---|---|---|
 | 5 | 1 | プライム | オリジナルとして取得 | [5] |
 | 4 | 1 | 2 | パートナー = 2 が存在します | (4,2) を使用 → 4 を追加 |
 | 3 | 2 | プライム | オリジナルとして 2 回取得 | [5,3,3] |
 | 2 | 残り使用中 | - | すでに消費されています | - |

 有効な再構成の 1 つは、組み合わせの選択に応じて {3, 4, 2} です。 

これは、複数の分解が存在し、貪欲な選択によっても元の値の有効なマルチセットが得られることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 |---|---|---|
 | 時間 | O(n + maxv log log maxv) | ふるい+周波数配列上のシングルパス |
 | スペース | O(最大) | 周波数と SPF 配列 |

 この制約により、最大 2 × 10^5 の個別の値が許可され、ふるいの構築と線形処理の両方が制限内に快適に適合します。

 ## 特殊なケース

 よくある例外的なケースは、入力の大部分が 2 や 3 のような小さな素数の繰り返しで構成されている場合です。そのような状況では、周波数を慎重に扱わないと、貪欲な消費によりペアリングのバランスが簡単に崩れてしまいます。 正しい再構築は、各出現が正確に 1 回一致すること、および初期のコミットによって後の要素に必要なパートナーが削除されないことを保証することに依存します。 

もう 1 つのエッジ ケースは、マルチセットに現れる 12、6、3、2 のようなチェーンなど、合成数に重複する除数構造がある場合です。 SPF に基づいて最大の適切な除数を選択しないと、単純な除数の選択により非最大係数が選択されて一貫性が損なわれる可能性があり、これにより後のプロセスで有効な元の配列を再構築できなくなります。
