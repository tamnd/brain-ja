 ## 解決策
 ## 問題の理解

 私たちには 4 つの別々の袋が与えられ、それぞれにいくつかのキャンディーが入っています。 各バッグは分割できず、2 人の友人のうち 1 人に完全に渡さなければなりません。 課題は、両方の友人が最終的にキャンディーの合計数がまったく同じになるように、4 つのバッグのそれぞれをどちらかの友人に割り当てることができるかどうかを判断することです。 

言い換えれば、4 つの整数のマルチセットを 2 つのグループに分割しており、2 つのグループの合計が等しくなるようにしたいのです。 

制約は非常に小さく、各値は最大 100 で、バッグは 4 つだけです。 これにより、効率性に関する懸念が即座に排除されます。 すべての代入またはサブセットを試行するソリューションは、可能性の総数が次のように固定されているため、十分に高速になります。$2^4 = 16$。 

項目が 4 つしかないため、主な微妙な点はパフォーマンスではなく、すべてのパーティションを一貫して処理する正確さです。 

よくある間違いは、最小値と最大値を一致させたり、少数の組み合わせだけをチェックしたりするなど、貪欲なペアリングが機能すると考えることです。 これは、構造が順序付けられておらず、最適なパーティションが非明白な方法で極端なものを混在させる可能性があるため、失敗します。 

たとえば、次のことを考えてみましょう。```
1 2 3 4
```貪欲な試行では (1,4) と (2,3) をペアにする可能性があり、これは機能しますが、代わりにヒューリスティックが (1,2) と (3,4) をペアにすると、有効なパーティションが存在しても失敗します。 これは、すべてのパーティションを考慮しない限り、ペアに関する部分的な推論は信頼できないことを示しています。 

合計が奇数の場合、別の失敗ケースが発生します。 例えば：```
1 1 1 2
```合計は 5 なので、割り当てに関係なく均等分割は不可能です。 正しい解決策は、そのようなケースを暗黙的に拒否する必要があります。 

## アプローチ

 この強引なアイデアは、4 つのバッグをそれぞれどちらかの友人に割り当てるためにあらゆる方法を試みることです。 各バッグには 2 つの選択肢があるため、次のようになります。$2^4 = 16$課題。 課題ごとに、友人 A と友人 B のキャンディーの合計を計算し、それらが一致するかどうかを確認します。 

これは、このような小さな入力サイズにはすでに最適です。 正確さは網羅性から生まれます。すべての有効なパーティションは、4 つのバッグの 1 つのバイナリ割り当てに正確に対応します。 

推論を単純化する唯一の観察は、代わりにサブセットの観点から考える場合、実際には割り当てを明示的に列挙する必要がないということです。最初の友人のバッグのサブセットを選択すると、2 番目の友人が自動的に決定されます。 

もう少し概念的な近道は、合計が偶数でなければならないことを観察し、合計が合計の半分になるバッグのサブセットを探すことです。 4 つの要素を使用すると、サブセットの列挙は簡単になります。

 ## アルゴリズムのチュートリアル

 1. 4 つのバッグの値の合計を計算します。 合計が奇数の場合は、2 つの等しい整数の合計が偶数になる必要があるため、均等分割は不可能であると直ちに結論付けます。 
2. 目標合計を合計の半分として定義します。 これは各友人が受け取らなければならない金額です。 
3. 4 つのバッグのすべてのサブセットを繰り返します。 0 ～ 15 のビットマスクを使用して各サブセットを表します。各ビットは、バッグが最初の友人に割り当てられているかどうかを示します。 
4. サブセットごとに、選択したバッグの合計を計算します。 これは最初の友達に与えられたキャンディーを表しています。 
5. このサブセットの合計がターゲットと等しい場合、残りのバッグを 2 番目の友人に暗黙的に割り当てたことになり、両方の合計が一致します。 すぐにYESを返してください。 
6. 目標合計を達成するサブセットがない場合は、NO を返します。 

### なぜ効果があるのか

 すべての有効な分布は、最初の友人に割り当てられたバッグの 1 つのサブセットに正確に対応します。 残りのバッグは補体サブセットを形成します。 すべてのサブセットをテストするため、必然的にすべての可能なパーティションをテストすることになります。 正しさは、合計が等しいということは、合計が合計の半分に等しいサブセットを見つけることと同じであるという事実に帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a = list(map(int, input().split()))
    total = sum(a)
    
    if total % 2 != 0:
        print("NO")
        return
    
    target = total // 2
    
    # try all subsets of 4 elements
    for mask in range(1 << 4):
        s = 0
        for i in range(4):
            if mask & (1 << i):
                s += a[i]
        if s == target:
            print("YES")
            return
    
    print("NO")

if __name__ == "__main__":
    solve()
```コードは最初に 4 つの値を読み取り、それらの合計を計算します。 パリティ チェックにより、等価性が不可能な場合に不必要なサブセットの列挙が防止されます。 

ビットマスク ループは、最初の友人に対するバッグの割り当ての可能性をすべて列挙します。 内側のループはサブセットの合計を累積します。 有効なサブセットが見つかった瞬間に、存在するだけで十分であるため、関数は早期に終了します。 

実装の微妙な点は、2 番目の友人の合計を明示的に計算する必要がないことです。 最初の合計が合計の半分と一致すると、補数も自動的に一致します。

これにより、選択したサブセットとその補数の合計が 12 になる有効なパーティションが存在することが確認されます。 

### 例 2

```合計は 5 で奇数です。 

| ステップ | 合計 | パリティチェック | 決定 |

これは、パリティ チェックが不可能なケースを正しく排除していることを示しています。

assert run("1 2 3 6") == "YES", "exact partition exists"

 ## 特殊なケース

 パリティ エッジ ケースは最初に処理されます。 次のような入力の場合:```
1 1 1 2
```アルゴリズムは合計 5 を計算し、すぐに NO を返します。 これにより、不必要なサブセットの列挙が防止されます。 

次のような対称入力の場合:```
2 2 2 2
```このアルゴリズムはサブセットでも機能しますが、合計が 4 になる 2 つのバッグを選択するなど、複数の有効なマスクを迅速に見つけます。 

次のような、多数の無効な分割の中に 1 つの有効な分割が隠れている場合:```
100 1 1 98
```サブセット検索により、直感的でない組み合わせでも確実にテストされ、{100, 1} を選択するマスクで十分に 101 に到達し、ターゲット 101 と一致します。
