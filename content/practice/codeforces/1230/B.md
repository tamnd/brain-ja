 ## 解決策
 ## 問題の理解

 正確に数値を表す非常に大きな 10 進数の文字列が与えられました。`n`数字。 せいぜい変更が許される`k`これらの数字のうち、一度に 1 桁ずつ、ある数字を別の数字に置き換えます。`0`に`9`。 まで演奏した後、`k`このような変更を行う場合は、表現を有効に保ちながら、可能な限り最小の数値を取得する必要があります。`n`- 桁の数字。最初の桁は次の桁にはならないことを意味します。`0`ない限り`n = 1`。 

このタスクは純粋に、限られた編集数での数字の操作に関するものです。 各編集には同じコストがかかるため、唯一の問題は、結果として得られる辞書編集上の値を最小限に抑えるためにどの位置を優先するかということです。 

制約は非常に大きく、`n`200,000まで。 これにより、変更のすべてのサブセットを考慮したり、位置ごとにネストされたスキャンを実行したりするアプローチは即座に除外されます。 変更を分散するためにあらゆる方法を試したり、変更のたびに最良の結果を再計算したりするような二次戦略は遅すぎます。`O(n^2)`最悪の場合、4e10 オペレーション程度になります。 

この問題の重要な微妙な点は、貪欲さと限られた数の変更との間の相互作用です。 グローバルな優先順位を考慮せずに「ローカルで数値を改善」しようとする単純なアプローチは失敗する可能性があります。 たとえば、前の桁ではなく後の桁に変更を加えると、たとえ局所的な改善が有益であるように見えても、先頭部分が最適ではないままになる可能性があります。 

一般的な失敗例は、以前の位置を優先せずに、まだゼロではない数字を貪欲に減らそうとした場合に発生します。 

入力:```
3 1
909
```不注意な戦略により、最後の桁が次のように変更される可能性があります。`0`生産する`909 -> 900`これはここでは最適ですが、次のような構造があれば`901`と`k=1`、最後の桁を変更すると、`900`、最初の桁を変更すると、`001`これは先頭にゼロがあるため無効です。 最初の桁の制約を慎重に処理しないと、単純に貪欲なアプローチによって正確性が簡単に侵害される可能性があります。 

別の特殊なケースが発生するのは、`k`は、多くの桁をゼロにするのに十分な大きさですが、最適な解決策では、辞書編集的に前の桁が優先されることを考慮する必要があります。 

これらの観察結果は、位置を左から右に扱い、最も重要な箇所で変更を使用する必要があることを示唆しています。 

## アプローチ

 強引なアイデアは、最大サイズのポジションのすべてのサブセットを試してみることです。`k`そしてそれらの数字をあらゆる方法で置き換えます。 単純化して、選択した数字を常に最適なものに置き換えると仮定したとしても、サブセットの数だけでも次のようになります。$$\sum_{i=0}^{k} \binom{n}{i}$$これは指数関数的です`n`。 と`n = 200000`、これはまったく不可能です。 

問題の構造は、より強い貪欲な方向性を示唆しています。 最終的な数値は辞書編集的に左から右に比較されるため、前の数字が後のすべての数字よりも優先されます。 これは、位置の数字を改善することを意味します`i`位置の数字を改善するよりも常に価値があります`j > i`ただし、どちらの改善にも同じ数の操作が必要になります。 

これから、正しい戦略が浮かび上がります。左から右にスキャンし、余裕があるときはいつでも、現在の桁を強制的に変更します。`0`(可能な最小の数字) ただし、次の場合を除き、最初の数字がゼロでないことを確認する必要があります。`n = 1`。 数字を変更するたびに、デクリメントします。`k`。 一度数字が最適に設定されると、再度変更しても操作が無駄になるだけであるため、以前の決定を再考することはありません。 

これが機能するのは、最初の位置で数字を可能な限り小さい値に設定すると、操作ごとに辞書編集上の最大の削減が行われるためです。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適な貪欲さ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 数字を左から右に処理し、残っている変更の数を維持します。 

1. 数値を文字のリストとして読み取り、個々の数字をその場で変更できるようにします。 これにより、文字列連結の繰り返しによるコストが回避されます。 
2. 各インデックスを反復処理します。`i`から`0`に`n - 1`。 各ポジションで、1 チェンジを費やすかどうかを決定します。 
3. もし`k > 0`、この桁を改善できないか検討します。 可能な限り最善の改善は、それを行うことです`0`。 これは、数を最小限に抑えるために常に最適です。`0`は最小の桁です。 
4. 最初の桁については (`i = 0`）、に設定することはできません`0`もし`n > 1`先行ゼロが導入され、数値が無効になるためです。 したがって、次の場合にのみ変更します`n == 1`。 
5. 他のすべてのポジションの場合 (`i > 0`)、数字がまだない場合`0`まだ変更が残っているので、次のように設定します`0`そして減少します`k`。 
6. すべての桁が終了するか使い果たされるまで続けます。`k`。 

### なぜ効果があるのか

 不変条件は、すべてのステップで、これまでに構築された数値のプレフィックスが、すでに費やされた操作の数を使用して達成可能な最小のプレフィックスであるということです。 辞書編集上の順序は最初の異なる位置にのみ依存するため、できるだけ早く各位置を最小化することで全体的な最適性が保証されます。 残りの演算を後で使用しても、前の桁を改善することはできないため、有益な削減が現れたらすぐに、後の位置の演算を保存することが、それらの演算を使用することを上回ることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
s = list(input().strip())

for i in range(n):
    if k == 0:
        break

    if i == 0:
        if n > 1 and s[i] != '1':
            # we cannot set to 0, best is 1
            if s[i] != '1':
                s[i] = '1'
                k -= 1
    else:
        if s[i] != '0':
            s[i] = '0'
            k -= 1

print("".join(s))
```このソリューションは、各位置で可能な限り最小の数字を貪欲に適用することで機能します。 最初の桁は、数値の長さが 1 でない限りゼロになることができないため、別個に扱われます。 他のすべての桁については、演算が残っている場合、ゼロ以外の桁はすぐにゼロに減らされます。 

微妙な点は、桁を減らすなどの部分的な改善は決して試みないことです。`7`に`6`。 それを作るのに1回の操作を費やすので、それは不要です`0`プレフィックスが固定されると、ゼロ以外の数字は将来の位置と比較してその効果が同等になるため、常に少なくとも辞書編集順に良好です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各桁は 1 回のパスで 1 回処理されます。 
| スペース | O(n) | 数値を変更可能な数字のリストとして保存します。 

リニアスキャンは以下の用途に最適です。`n`最大 200,000 で、キャラクターごとに単純な一定時間の操作のみを実行するため、制限時間内に簡単に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    s = list(input().strip())

    for i in range(n):
        if k == 0:
            break

        if i == 0:
            if n > 1 and s[i] != '1':
                s[i] = '1'
                k -= 1
        else:
            if s[i] != '0':
                s[i] = '0'
                k -= 1

    return "".join(s)

# provided sample
assert run("5 3\n51528\n") == "10028", "sample 1"

# minimum size
assert run("1 0\n7\n") == "7", "single digit no change"

# maximum reduction
assert run("3 3\n999\n") == "100", "force minimal prefix"

# no operations
assert run("4 2\n1234\n") == "1034", "only two zeros possible"

# already optimal
assert run("4 2\n1000\n") == "1000", "no improvement"

# edge leading digit
assert run("2 1\n10\n") == "10", "cannot reduce leading digit to 0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 桁、k=0 | 7 | 変更は許可されません |
 | 999、k=3 | 100 | 完全な最小化 |
 | 1234、k=2 | 1034 | 部分的な貪欲なアプリケーション |
 | 1000、k=2 | 1000 | すでに最小限の構造 |
 | 10、k=1 | 10 | 先行ゼロ制約 |

 ## 特殊なケース

 重要なエッジケースは、最初の桁が次より大きい場合です。`1`そして`k > 0`。 アルゴリズムはそれを強制します`1`、 ない`0`、有効性を維持します。 たとえば:

 入力:```
3 2
902
```最初の桁`9`になる`1`、出発`k = 1`。 残りの桁は貪欲に最小化されます。 このアルゴリズムにより、辞書編集上最小の接頭辞が優先されながらも、数値が有効なままであることが保証されます。 

もう 1 つのケースは、すべての数字がすでに`0`最初のものを除いて。 すでに最適な位置に配置されているため、無駄な操作はありません。`s[i] != '0'`不必要な減少を防ぎます`k`。 

最終的な動作は、使用されるすべての操作が辞書編集上の可能な限り最も早い改善をもたらすという不変条件を一貫して保持します。
