 ## 解決策
 ## 問題の理解

 順列が与えられ、それを 1 位置ずつ左に回転させることを繰り返し、最初の要素が最後に移動します。 回転するたびに新しい順列が得られ、各バージョンには独自の反転数があり、これは、より大きな値がより小さな値の前に現れるインデックスのペアを意味します。 

タスクは、順列がすべての循環シフトの中で可能な限り最小の反転数を持つ状態に到達するまでに必要な回転数を見つけることです。 複数の回転が同じ最小値に達する場合は、n 未満の有効な答えが受け入れられます。 

n を 200000 までの制約にすると、回転ごとに反転カウントを最初から再計算することは直ちに除外されます。これは、それが O(n^2 log n) 以上になるためです。 O(n^2) の演算でも大きすぎます。 以前の計算を再利用しながら、n 個の回転状態すべてを評価する必要があります。 

最適な構成がすでに初期の順列になっている場合、微妙なエッジ ケースが発生します。 たとえば、配列が [1, 2, 3, 4] のように既にソートされている場合、単位を除くすべての回転で反転が増加するため、答えは 0 になるはずです。もう 1 つの例外的なケースは、[2, 1, 3] のような小さな循環パターンなど、複数の回転が同じ反転数を生成する、複数の回転が最小の反転につながる場合です。 n 未満の有効なインデックスはどれでも受け入れられます。 

主な問題は、ローテーションによってグローバルな反転構造が非ローカルな方法で変更されるため、シフトごとに反転カウントを O(1) または O(log n) で更新する方法が必要であることです。 

## アプローチ

 直接的なアプローチは、n 回転のそれぞれの反転数を独立して計算することです。 ローテーションごとに、配列を再構築し、フェンウィック ツリーを使用して反転をカウントするか、O(n log n) でのマージ ソートを行うことができます。 これを n 回実行すると O(n^2 log n) になりますが、これは 2・10^5 要素にとっては遅すぎます。 

重要な点は、回転後に反転を最初から再計算する必要がないことです。 左回転では、最初の要素 x が削除され、最後に追加されます。 他のすべての相対順序は変更されないため、反転数は x を含むペアによってのみ変化します。 

回転の前に、x は、その右側にある x より小さい要素との反転に寄与します。 回転後、x は最後の要素になるため、どのペアにも左のインデックスとして表示されなくなります。 代わりに、それは正しいインデックスとなり、その前にある要素とそれよりも大きい要素との反転に寄与します。 

これは、接尾辞に x より小さい要素がいくつあるか、残りのマルチセットに x より大きい要素がいくつあるかという 2 つの量を使用して反転変化を表現できることを意味します。 どちらも、値に対するフェンウィック ツリーを使用し、位置に対するプレフィックス/サフィックス構造と組み合わせて維持できます。 

初期反転回数を 1 回計算します。 次に、各位置 i について、a[i] を最後に移動される要素として扱い、そのステップで回転した場合に反転カウントがどのように変化するかを計算します。 これにより、すべての回転状態を O(n log n) で評価できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各回転を再計算する | O(n^2 log n) | O(n) | 遅すぎる |
 | フェンウィックベースの回転ごとのデルタ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各回転を「要素 a[i] を先頭から削除して最後に追加する」ものとして扱いますが、元の配列と接頭辞/接尾辞の範囲を使用して効果を計算します。 

1. 値に対するフェンウィック ツリーを使用して、配列の初期反転数を計算します。

左から右にスキャンし、値 x ごとに、以前の値が x より大きい値がいくつあるかを数えます。 これにより、ベースライン反転カウント inv0 が得られます。 
2. 別のフェンウィック ツリーを使用して値のプレフィックス情報を事前計算します。これにより、任意の値 x について、配列全体で x 以下の要素がいくつあるかをクエリできるようになります。 
3. 各インデックス i について、サフィックス情報 (位置 i+1 から n にある要素の数が a[i] より小さいか) も必要です。 これは、サフィックス マルチセットを維持するフェンウィック ツリーを右から左に反復することによって計算できます。 
4. 各 i について、a[i] を最後に移動した場合の効果を計算します。 x = a[i] とします。 

削除前、x は、サフィックス内の x より小さい要素の数に等しい反転に寄与します。 
5. x を最後まで移動すると、それが最後の要素になります。 これで、x より大きい残りの要素の数に等しい反転が提供されます。 この量は、位置ではなく、値の頻度のみに依存します。 
6. これら 2 つの寄与の差を計算して、i で回転が発生した場合の反転カウントの変化である delta[i] を取得します。 
7. インデックス 0 から始まる回転をシミュレートしながら、delta[i] にわたるプレフィックスの合計を構築します。最小反転値と対応する回転インデックスを追跡します。 

### なぜ効果があるのか

 すべての反転には、移動された要素が含まれないか、または移動された要素が 1 回だけ含まれます。 a[i] を含まないすべての反転は、他の要素間の相対的な順序が保持されるため、回転後も変更されません。 したがって、反転カウントの唯一の可能な変化は、a[i] を含むペアから得られます。 回転の前後で a[i] が反転の左要素であるか右要素であるかを注意深く区別することで、グローバル更新を値の範囲にわたる 2 つのカウント クエリに削減します。 これらのクエリは回転順序とは独立しているため、前処理後にすべての候補回転を線形時間で評価できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

n = int(input())
a = list(map(int, input().split()))

# 1) initial inversion count
bit = BIT(n)
inv0 = 0
for x in a:
    inv0 += bit.range_sum(x + 1, n)
    bit.add(x, 1)

# 2) suffix structure: suffix_less[i]
bit2 = BIT(n)
suffix_less = [0] * n
for i in range(n - 1, -1, -1):
    x = a[i]
    suffix_less[i] = bit2.sum(x - 1)
    bit2.add(x, 1)

# 3) global value counts
bit3 = BIT(n)
for x in a:
    bit3.add(x, 1)

def total_leq(x):
    return bit3.sum(x)

best = inv0
ans = 0
cur = inv0

for i in range(n):
    x = a[i]

    old = suffix_less[i]
    remaining_leq = total_leq(x) - 1
    new = (n - 1) - (remaining_leq - 0)

    # new formula simplifies to: (n - total_leq(x))
    new = n - total_leq(x)

    delta = new - old

    cur += delta
    if cur < best:
        best = cur
        ans = i

print(ans)
```コードは、値に対してフェンウィック ツリーを使用する標準的な方法で反転数を計算することから始まります。 これにより、すべての回転が比較されるベースライン構成が確立されます。 

サフィックス配列`suffix_less[i]`右から左にスキャンして、各位置の後に出現する小さな値の数を保存することによって構築されます。 これは、移動時に関与する反転の左端点としての各要素の「回転前」の寄与に直接対応します。 

機能`total_leq(x)`配列全体に対してフェンウィック ツリーを使用して、値以下の要素の数を数えます。 これにより、O(log n) 内で x より大きい要素がいくつあるかを計算できます。 

各回転候補 i について、最後に移動したときに x の反転寄与がどのように変化するかを計算します。 現在のインバージョン合計を更新します`cur`そのため、ローカル デルタのみを適用しながら、すべての回転を順番に効果的にシミュレートします。 すべての状態の最小値が追跡されます。

 ## 特殊なケース

 重要なエッジ ケースは、順列がインデックス 0 ですでに最適になっている場合です。その状況では、各要素の接尾辞の寄与は最小限であり、計算されたデルタ値が開始状態よりも優れた反転カウントを生成することはありません。 アルゴリズムが初期化されます`best = inv0`そして`ans = 0`したがって、反復中に改善が見られない場合、出力は 0 のままになります。 

もう 1 つのケースは、複数の回転で同じ最小反転数が得られる場合です。 アルゴリズムは厳密に小さい値が見つかった場合にのみ答えを更新するため、最初に出現した最小値が保持されます。これは、n 未満のインデックスが許容されるという要件の下では常に有効です。 

最後に、循環構造により、ステップ間に隠れた依存関係が導入されません。 各デルタは元の配列とは独立して計算されるため、累積的な更新をシミュレートしても、正確さは中間配列が元の位置と一致すると仮定することに依存しません。
