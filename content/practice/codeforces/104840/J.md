 ## 解決策
 ## 問題の理解

 いくつかの文字列が与えられ、それらを並べ替えたり、接着して 1 つの長い文字列にすることができます。 2 つの文字列を接着するとき、単に盲目的に連結しているわけではありません。 現在の文字列のサフィックスが次の文字列のプレフィックスと一致する場合、文字が重複しないように、その重複部分をマージする必要があります。 

目標は、指定されたすべての文字列の順序を選択し、それらを最適にオーバーラップして、すべての元の文字列が最終結果の連続した部分文字列としてどこかに表示され、最終結果ができるだけ短くなることです。 

これは古典的な「すべての部分を 1 つの超文字列にマージする」問題で、コストは隣接する文字列がどの程度重なり合うかによって異なります。 問題は、最適な順序が明らかではなく、順序が間違っていると長さが大幅に長くなる可能性があることです。 

制約はソリューションを大きく左右します。 テストあたりの文字列の数は最大 17 であり、これはサブセットに対する指数関数的な検索が可能であることを直ちに示唆しています。 ただし、文字列自体は最大 5·10^4 文字と長いため、ペアごとに文字列を 1 文字ずつ単純に比較する場合は、慎重に制御する必要があります。 すべてのテスト ケースにわたって、文字列の総数は少ないため、O(n^2) または O(n^2 log n) タイプの前処理でも許容されます。 

いくつかの特殊なケースは見落とされがちです。 1 つは、文字列が別の文字列の中に完全に含まれている場合です。 たとえば、「abc」と「zabcx」がある場合、「abc」は最終的な答えに個別に寄与する必要はまったくありません。 すべての文字列を保持する不注意な解決策は依然として正しい可能性がありますが、時間が無駄になり、オーバーラップ ロジックが複雑になる可能性があります。 

もう 1 つの問題は、文字列の重複です。 同じ文字列が 2 回出現する場合は、両方とも部分文字列として含める必要があります。つまり、それらを削除することはできませんが、それらの間のコストがゼロで完全に重複する可能性があります。 多重性を考慮せずに積極的に重複排除を行うソリューションは失敗します。 

最後に、複数の異なるオーバーラップが存在する場合でも、オーバーラップを正しく計算する必要があります。 たとえば、「aaaaa」と「aaa」の間では、最適な重複は曖昧ではありませんが、一般的な文字列間では、サフィックスとプレフィックスの最大の一致のみが問題となります。 

## アプローチ

 この強引なアイデアは、文字列の可能な順序をすべて試してみることです。 順列ごとに、可能な限り重複する次の文字列を現在の結果に繰り返し追加することで、文字列がどのようにマージされるかを計算します。 これは、可能なすべての順序を明示的に探索するので正しいですが、n 個あるため、非常にすぐに実行不可能になります。 順列は、n = 10 の場合にはすでに約 360 万回あり、n = 17 の場合は完全に不可能です。 

重要な点は、文字列を結合するときに重要なのは、境界でどれだけ重複するかだけであるということです。 文字列 i と j のすべてのペアについて、i の後に j が続くときの最大の重複がわかったら、文字列の内部構造はもう重要ではなくなります。 問題は、総オーバーラップを最大化する、または同等に追加の長さを最小化するノードの順序を選択することに帰着します。 

これにより、問題は、文字列の完全な有向グラフにわたる最短のハミルトニアン パスの変形に変換され、エッジ コストはペアごとのオーバーラップのみに依存します。 n は最大 17 であるため、ビットマスク動的プログラミングを使用して文字列のすべてのサブセットを試し、各文字列で終了する最適な方法を追跡できます。 

ブルート フォースはすべての順列を探索するため概念的には機能しますが、階乗増加により失敗します。 DP が機能するのは、同じ訪問セットと終了文字列を共有するすべての順列を 1 つの状態に圧縮し、再計算の繰り返しを回避するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n!・L) | O(n・L) | 遅すぎる |
 | ビットマスク DP (SCS) | O(n^2・2^n+n^2・L) | O(n · 2^n) | 承認済み |

 ## アルゴリズムのチュートリアル

この問題を、オーバーラップの計算とサブセット DP の実行の 2 つのフェーズに分割します。 

1. まず、文字列 i と j の各ペアを前処理して、j の文字を i のサフィックスに何文字オーバーラップできるかを計算します。 これは、i のサフィックスを j のプレフィックスと照合し、最大一致長を取得することによって行われます。 KMP などの線形文字列マッチング手法を使用すると、長い文字列であってもこれを効率的に計算できます。 
2. この重なりを行列に保存します`overlap[i][j]`、j が i に続く場合、j の何文字がすでにカバーされているかを表します。 これにより、i から j に移行するときの増分コストを計算できます。 
3. DP 状態を定義します`dp[mask][i]`、内の文字列を正確に使用するスーパー文字列の最小長を意味します。`mask`そして文字列 i で終わります。 
4.初期化する`dp`単一要素マスクの場合。 文字列 i のみが使用される場合、最適な超文字列は文字列そのものです。`dp[1<<i][i] = len(s[i])`。 
5. すべてのマスクを反復処理します。 各マスクとその中の最後の文字列 i ごとに、マスクにない新しい文字列 j を追加しようとします。 i を j で拡張し、j の重複しない部分のみを追加することによって、新しい状態を更新します。 
6. トランジションは新しい長さを次のように計算します。`dp[mask][i] + len(s[j]) - overlap[i][j]`。 可能なすべての前の状態の最小値を取得します。 
7. DP テーブルに記入すると、答えは全体の最小値になります。`dp[all_mask][i]`。 
8. 実際の文字列を再構築するために、どの前の状態が最適な遷移につながったかを記録する親ポインターを保存し、その後、最良の終了状態からバックトラックします。 

正確さは、すべての有効な順序付けがこの DP 状態グラフ内の 1 つのパスに正確に対応し、そのパスのコストがマージされた文字列の合計長に正確に一致するという事実に基づいています。 このようなパスすべてで最小値を取るため、最適なスーパーストリング長を取得する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_kmp_table(s):
    n = len(s)
    pi = [0] * n
    j = 0
    for i in range(1, n):
        while j and s[i] != s[j]:
            j = pi[j - 1]
        if s[i] == s[j]:
            j += 1
            pi[i] = j
    return pi

def overlap(a, b):
    # maximum suffix of a that matches prefix of b
    s = b + "#" + a
    pi = build_kmp_table(s)
    return pi[-1]

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = [input().strip() for _ in range(n)]

        # remove strings contained in others
        used = [True] * n
        for i in range(n):
            for j in range(n):
                if i != j and s[i] in s[j]:
                    used[i] = False
                    break

        a = [s[i] for i in range(n) if used[i]]
        n = len(a)

        if n == 0:
            print("")
            continue

        # recompute overlaps
        ov = [[0] * n for _ in range(n)]
        for i in range(n):
            for j in range(n):
                if i != j:
                    ov[i][j] = overlap(a[i], a[j])

        INF = 10**18
        dp = [[INF] * n for _ in range(1 << n)]
        parent = [[(-1, -1)] * n for _ in range(1 << n)]

        for i in range(n):
            dp[1 << i][i] = len(a[i])

        for mask in range(1 << n):
            for i in range(n):
                if dp[mask][i] == INF:
                    continue
                for j in range(n):
                    if mask & (1 << j):
                        continue
                    nmask = mask | (1 << j)
                    val = dp[mask][i] + len(a[j]) - ov[i][j]
                    if val < dp[nmask][j]:
                        dp[nmask][j] = val
                        parent[nmask][j] = (mask, i)

        full = (1 << n) - 1
        best_len = INF
        last = -1
        for i in range(n):
            if dp[full][i] < best_len:
                best_len = dp[full][i]
                last = i

        mask = full
        order = []
        cur = last
        while cur != -1:
            order.append(cur)
            pmask, pcur = parent[mask][cur]
            mask, cur = pmask, pcur

        order.reverse()

        res = a[order[0]]
        for k in range(1, len(order)):
            i, j = order[k - 1], order[k]
            add = a[j][ov[i][j]:]
            res += add

        print(res)

if __name__ == "__main__":
    solve()
```KMP ヘルパーは、線形時間で最大の接尾辞と接頭辞の一致を見つけることができるように、連結された文字列に対して接頭辞関数の値を計算します。 これにより、文字列が大きい場合に遅すぎる、文字列のペアごとの 2 次スキャンが回避されます。 

DP テーブルには、すべてのサブセットと終了状態の最適な長さが格納されます。 親テーブルは再構築に不可欠です。 これがなければ、実際の文字列ではなく、長さだけがわかります。 

部分文字列の削除ステップにより、不要な状態が削減されます。 文字列が別の文字列に完全に含まれている場合、それを保持しても遷移には役に立たず、DP サイズが増加するだけです。 これを削除すると、正確さを変えることなく計算が簡素化されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

| スペース | O(n · 2^n) | すべてのサブセットにわたる DP および親テーブル |

 ## 特殊なケース

 厄介な状況は、ある文字列が別の文字列の中に完全に含まれている場合です。 たとえば、文字列「abc」と「zabcy」を入力します。 「abc」は 2 番目の文字列内に出現するため、アルゴリズムは前処理中に削除します。 残りの DP は「zabcy」上でのみ実行され、出力は正しく「zabcy」になります。 最終的な答え内に「abc」が出現すると、それが満たされることがすでに保証されるため、消去ステップでは必要な出現が失われることはありません。 

重複した文字列は異なる動作をします。 「abc」と「abc」の場合は、どちらにも含まれないため、両方が残ります。 同一の文字列間のオーバーラップは完全長であるため、遷移コストはゼロになります。 DP はそれらを連続して配置し、再構築により「abcabc」が生成され、両方の出現が必要な部分文字列として存在することが保証されます。
