 ## 問題の理解

 スタックのような構造に配置された順列が与えられています`a`、最後の要素のみ`a`直接アクセスできます。 2 番目の空のスタックがあります`b`。 すべての番号を削除する必要があります`1`に`n`ただし、許可されるアクションのセットは非常に制限されており、一方のスタックの最上位要素をもう一方のスタックに移動したり、どちらかのスタックの最上位要素を削除 (解放) したりすることができます。 このようなアクションごとに 1 回の操作が必要になります。 

したがって、システムは 2 つの相互作用するスタックのように動作し、常に最上位の要素のみが表示されます。 タスクは、初期構成を一連の削除に変換することです。`1, 2, ..., n`操作の数を最小限に抑えながら。 

制約は次のとおりです`n = 2 · 10^5`したがって、状態を探索したり、貪欲に選択をシミュレートしようとするソリューションは機能しません。 平`O(n log n)`それは問題ありませんが、構成上の BFS やスタック状態上の動的プログラミングに似たものは、各状態遷移にコストがかかり、構成の数が指数関数的に増加するため、すぐに大きすぎます。 

この問題の微妙な問題は、「正しい」要素が常に一番上にあるわけではないことです。`a`埋め込まれた場合でも、ブロック要素を一時的に移動する必要がある場合があります。`b`。 主な問題点は、要素の移動にもコストがかかるため、次に必要な数が表示されるまでやみくもにシミュレーションすることは、構造なしで行うと非効率になる可能性があることです。 

一般的な障害モードは、常に消耗しようとすることです`a`の中へ`b`ブロックされるたびに。 これにより、たとえば、操作の順序をより慎重に選択していれば要素をより早く解放できたはずの場合に、不要なやり取りが発生する可能性があります。 

もう 1 つの落とし穴は、要素が一度移動されると仮定することです。`b`、必要になるまでそこに留まるべきです。 実際、要素を元に戻すことが最適な場合があります。`b`必要な数がアクセスできる唯一の場所になる可能性があります。

 ## アルゴリズムのチュートリアル

 2つのスタックを維持します`a`そして`b`、およびポインタ`need`最初は等しい`1`。 

1. その間`need ≤ n`、私たちは繰り返し暴露と削除を試みます`need`。 
2. 上部の場合`a`等しい`need`から削除します。`a`そして増加します`need`。 追加の作業が必要ないため、これは理想的なケースです。 
3. それ以外の場合は、`b`等しい`need`から削除します。`b`そして増加します`need`。 これは、要素が一時的に保存され、準備ができたことを意味します。 
4.そうでない場合はブロックされます。 この状況では、要素を移動してアクセシビリティを変更する必要があります。 もし`a`は空ではないので、その最上位要素を に移動します`b`。 これは、元のスタックから妨害要素を剥がす制御された方法です。 
5. もし`a`が空の場合は、上部を移動します`b`に戻る`a`。 これは次のような場合に起こります。`b`必要な値へのアクセスをブロックする要素が含まれているため、アクセシビリティを再調整する必要があります。 

各移動には 1 回の操作が必要で、各削除にも 1 回の操作が必要です。 

重要な考え方は、長い一連の動きを決して「推測」しないということです。 両方のスタックが必要な値を公開できない場合にのみ移動を実行し、すべての操作が進捗に貢献するようにします。 

### なぜ効果があるのか

 いかなる瞬間においても、前進する唯一の方法は、お互いの距離を縮めることです。`need`および現在表示されている構造内でのその位置。 そうでない要素を移動する`need`情報は失われません。一時的に非表示になる要素が変更されるだけです。 すべての要素は最終的には 1 回だけ削除する必要があるため、その移動を遅らせても、現在の状況を直接明らかにするのに役立つ場合を除き、総コストは決して改善されません。`need`。 

これにより、すべての操作が最終的な削除であるか、将来の削除を公開するために必要な再配置であることが保証され、最終的なアクセシビリティに寄与しないという意味で冗長な操作は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # treat a as stack: end is top
    a = a[::-1]
    b = []
    
    need = 1
    ops = 0
    
    while need <= n:
        if a and a[-1] == need:
            a.pop()
            need += 1
            ops += 1
        elif b and b[-1] == need:
            b.pop()
            need += 1
            ops += 1
        else:
            if a:
                b.append(a.pop())
            else:
                a.append(b.pop())
            ops += 1
    
    print(ops)

if __name__ == "__main__":
    solve()
```実装では入力配列を反転して、最後の要素がスタックの先頭になるようにします。`a`。 これによりインデックスの混乱が回避され、`pop()`許可された操作を自然に表します。 

ループは、次に必要な番号が表示されている場合は、その番号を削除することを常に優先します。 表示されない場合にのみ、スタック間の転送が実行されます。 これにより、すべての操作が意味のあるものになることが保証されます。つまり、必要な削除が完了するか、システムが必要な値の公開に近づくかのいずれかになります。 

微妙な点は、ブロックされたときに両方のスタックが対称的に扱われることです。 もし`a`は空です、頼らなければなりません`b`, そのため、要素を元に戻します。 これにより、残りのすべての要素がデッドロック状態になるのを防ぎます。`b`しかし、注文のためアクセスできません。

 ## 特殊なケース

 のために`n = 1`、両方のスタックは自明であり、単一の要素にすぐにアクセスできるため、アルゴリズムは削除を 1 回だけ実行します。
