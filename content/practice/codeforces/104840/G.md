 ## 解決策
 ## 問題の理解

 数直線上のセグメントの集合が与えられます。 各セグメントは、単一の項目として検索する必要があるさまざまな「現実」を表します。 私たちが実行する操作はこれらのセグメントをグループ化することです。グループには複数のセグメントが含まれており、1 つのグループを処理するということは、そのグループ内のすべてのセグメントを一緒に処理することを意味します。 

単一グループ内では、2 つのセグメントが交差することはできません。 ここでの交差とは、少なくとも 1 つの共通点を共有することを意味するため、一方が他方が終了する前に開始した場合、2 つのセグメントは互換性がありません。 

タスクは、すべてのセグメントをそのようなグループの最小数に分割し、各グループの構成も出力することです。 

入力サイズは 20 万セグメントに達し、各エンドポイントは 10 億にも達します。 これにより、セグメントのすべてのペアを比較しようとするアプローチは即座に除外されます。これは、二次関数であり、制限時間を大幅に超えるためです。 明示的な互換性マトリックスを維持することさえ不可能です。 

微妙な点は、セグメントが閉じた間隔であることです。 これは、次のような隣接関係の場合に重要です。`[1, 3]`そして`[3, 5]`、点 3 で交差するため、同じグループに属することはできません。 これにより、互換性のための厳密な条件が強制されます。`r < l`。 

素朴な間違いは、接触するエンドポイントを結合しても安全であると仮定することです。 たとえば:

 入力:```
3
1 3
3 5
6 7
```不用意にグループ化すると、最初のセグメントと 2 番目のセグメントが一緒になる可能性がありますが、これらは 3 で交差するため、これはルールに違反します。 正しい解決策では、その境界を競合するものとして扱う必要があります。 

もう 1 つのよくある落とし穴は、グローバルな順序付け戦略を持たずに、最初に利用可能なグループにセグメントを貪欲に詰め込んでしまうことです。 開始時間で並べ替えないと、グループ化が順序に依存し、必要以上のグループが生成される可能性があります。 

## アプローチ

 強引なアイデアは、グループを 1 つずつ構築することです。 未割り当てのセグメントを繰り返し選択し、新しいグループを開始し、残りのすべてのセグメントをスキャンして、グループ内の既存のセグメントと交差しないセグメントを追加します。 追加ごとに、グループの現在のすべてのメンバーとの互換性をチェックする必要があります。 

これは、非交差制約を明示的に強制するため、論理的に機能します。 問題はパフォーマンスです。 最悪の場合、セグメントが重なり合っている場合、各グループは 1 つのセグメントのみを取得し、グループを埋めようとするたびに残りのほぼすべてのセグメントがスキャンされる可能性があります。 これにより、n の 2 乗程度の二次関数の動作が発生しますが、これは 200,000 個の要素では許容範囲をはるかに超えています。 

重要な点は、これが古典的な区間色分け問題であるということです。 必要なグループの最小数は、任意の点で重複する間隔の最大数に等しくなります。 任意の順序で貪欲にグループを構築する代わりに、開始点によってソートされたセグメントを処理し、現在アクティブなグループの構造を維持します。各グループは、割り当てられた最後の終了点によって表されます。 

現在のセグメントが開始する前に最後のセグメントが終了する場合、グループはいつでも再利用できます。 したがって、この条件を満たす、終了時間が最小のグループをすぐに見つけたいと考えます。 グループ終了時刻にわたる最小ヒープは、まさにこの機能を提供します。 

可能であれば、各セグメントは既存の互換グループに割り当てられます。そうでない場合は、新しいグループが作成されます。 これにより、グループの最適な再利用が保証され、最小数が保証されます。

 ## アルゴリズムのチュートリアル

 1. すべてのセグメントを左の端点で並べ替えます。 これにより、インターバルは常に開始順に処理されます。これは、「現在オープンしている」グループの一貫した概念を維持するために不可欠です。 
2. 各要素がグループを表す最小ヒープを維持し、そのグループに配置された最後のセグメントの右エンドポイントをキーにします。 各ヒープ エントリにはグループ識別子も格納されます。 
3. ソートされた順序でセグメントを繰り返します。 各セグメントごとに`[l, r]`、ヒープを検査します。 
4. ヒープが空ではなく、最小の終了グループが終了している場合`< l`をクリックしてポップし、現在のセグメントをそのグループに割り当てます。 最も小さい端を選択するのは、最も早く解放され、将来の再利用の機会が最大化されるためです。 
5. それ以外の場合、既存のグループはこのセグメントを受け入れることができないため、新しいグループを作成し、そのグループにセグメントを割り当てます。 
6. 割り当て後、更新されたグループを現在のセグメントの終了時刻でヒープにプッシュして戻します。 
7. グループ メンバーシップ リストを保存して、最後に出力できるようにします。 

### なぜ効果があるのか

 いつでも、ヒープには、使用できなくなるまでに順序付けされたすべてのアクティブなグループが保存されます。 終了時間が最小のグループにセグメントを割り当てると、そのセグメントを収容できるグループが最も制約されるため、安全です。 それができないなら、他のグループもできません。 この貪欲な選択により、将来の可能性がすべて保存され、不必要なグループの作成が回避されます。 

不変条件は、各セグメントの処理後、ヒープ内のすべてのグループが有効な重複しないセグメントのチェーンを表し、後で割り当てられたセグメントはそのグループ内の既存のすべてのセグメントと互換性があるということです。 可能な限り互換性のあるグループを常に再利用するため、重複構造によって強制されない限り、グループ数が増加することはありません。 これは、間隔分割の最適性の定義と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    segs = []
    for i in range(n):
        l, r = map(int, input().split())
        segs.append((l, r, i + 1))

    segs.sort()

    import heapq
    heap = []
    groups = []
    
    for l, r, idx in segs:
        if heap and heap[0][0] < l:
            end, gid = heapq.heappop(heap)
        else:
            gid = len(groups)
            groups.append([])

        groups[gid].append(idx)
        heapq.heappush(heap, (r, gid))

    print(len(groups))
    for g in groups:
        print(len(g))
        print(*g)

if __name__ == "__main__":
    solve()
```この解決策は、左側のエンドポイントで間隔を並べ替えることから始まります。これにより、常に時系列順にグループを拡張できるようになります。 ヒープには次のペアが格納されます。`(end_time, group_id)`これにより、最も早く空いたグループを効率的に見つけることができます。 

条件`heap[0][0] < l`重要な詳細です。 厳密な非交差を強制します: グループが時刻に終了する場合`r`、から始まる新しい間隔のみを受け入れることができます。`l`いつ`r < l`。 

ヒープからポップするとき、そのグループを再利用することを約束します。 有効なグループがない場合は、新しいグループを割り当てます。これは、間隔グラフの彩度の増加に相当します。

これは、再利用が到着順ではなく、最も早く終了したグループにどのように依存するかを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | ソートが優先され、ヒープ操作は間隔ごとに対数的になります。 
| スペース | O(n) | セグメント、ヒープ、およびグループ割り当てのストレージ |

 この制約では最大 200,000 間隔が許可されるため、n log n アプローチは時間制限内に問題なく収まります。 ヒープにより、各間隔の挿入と削除が最大 1 回行われるようになり、オーバーヘッドが最小限に抑えられます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    segs = []
    for i in range(n):
        l, r = map(int, input().split())
        segs.append((l, r, i + 1))

    segs.sort()
    import heapq

    heap = []
    groups = []

    for l, r, idx in segs:
        if heap and heap[0][0] < l:
            end, gid = heapq.heappop(heap)
        else:
            gid = len(groups)
            groups.append([])

        groups[gid].append(idx)
        heapq.heappush(heap, (r, gid))

    out = []
    out.append(str(len(groups)))
    for g in groups:
        out.append(str(len(g)))
        out.append(" ".join(map(str, g)))
    return "\n".join(out)

# minimum size
assert run("1\n1 10\n") == "1\n1\n1"

# all overlap
assert run("3\n1 5\n2 6\n3 7\n") == "3\n1\n1\n1\n2\n1\n3"

# chain overlap via endpoints
assert run("3\n1 2\n2 3\n3 4\n") == "3\n1\n1\n1\n2\n1\n3"

# disjoint intervals
assert run("3\n1 2\n5 6\n9 10\n") == "1\n3\n1 2 3"

 ## 特殊なケース

 主なエッジケースは、間隔がエンドポイントでのみ接触する場合です。 例えば、`[1,2]`そして`[2,3]`2 で交差するためグループ化できません。ヒープ状態`end < l`これを厳密に強制し、無効な再利用を防ぎます。 

もう 1 つのエッジ ケースは、間隔が逆の順序で到着する場合です。 左端で並べ替えると、グループ化は順序ではなく構造のみに依存するため、入力順序に関係なく正確さが保証されます。 

最後に、多くの間隔が同じ時点で始まる場合、アルゴリズムは迅速に複数のグループを作成します。 ヒープは、新しい各間隔が既存のチェーン間で最適に配置されることを保証し、グループの数がその時点での最大同時オーバーラップと一致するようにします。
