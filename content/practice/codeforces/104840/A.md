 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 各シナリオには、$n$クローン個体は一定の順序で配置されていますが、観察できるのはそれらに書かれた複数のラベルだけです。 各ラベルは 1 から 1 までの整数です。$n$。 

これらのラベルの割り当て方法は、非常に特殊なルールに従っています。 クローンが未知の最終順序で一列に並んでいると想像してください。 各クローンには、左端からの位置または右端からの位置に基づいて番号が割り当てられました。 それで、あるポジションについては$i$、割り当てられる値は次のいずれかです$i$または$n - i + 1$。 割り当て後、クローンは任意に並べ替えられるため、最終的な入力配列はこれらの割り当てられた値の並べ替えにすぎません。 

タスクは、指定された長さの配列かどうかを判断することです。$n$このような標識スキームによって生成することができる。 

入力サイズが大きく、最大$10^5$すべてのテスト ケースにわたる要素の合計。 これにより、すべての順列を試行したり、配置を明示的にシミュレートしたりするソリューションは即座に除外されます。 平$O(n^2)$単一のテスト ケースがすでに完了している可能性があるため、このアプローチは遅すぎます。$10^5$。 

重要な点は、入力配列内の順序が、ラベル付け中に使用された元の位置に対応していないことです。 マルチセットのみが重要であり、配置は重要ではありません。 

よくある間違いは、固定された順序で貪欲に順列を再構築しようとすることです。 実際の割り当て順序が不明であり、最終的な配列が並べ替えられるため、これは失敗します。 

たとえば、次のように考えてみましょう$n = 4$、 配列$[1, 4, 1, 3]$。 誤って左から右へ貪欲に位置を一致させようとする可能性がありますが、元の配置は任意に変更できるため、重要なのは周波数構造だけです。 

もう 1 つの微妙な失敗例は、各値が一意の位置に対応している必要があると想定していることです。 複数の位置が同じ値を生成する可能性があるため、これは誤りです。$i = n - i + 1$、つまり真ん中のとき$n$奇数です。 

## アプローチ

 直接的な総当りのアイデアは、各位置に左インデックス値または右インデックス値を割り当てるすべての可能な方法を試し、結果のマルチセットが入力と一致するかどうかを確認することです。 がある$2^n$そのような割り当てを行い、それぞれについてマルチセットを比較します。$O(n)$、指数関数的な複雑さにつながります。 たとえ$n = 30$、これはすでに実行不可能であり、ここでは$n$まで上がります$10^5$。 

重要な観察は、最終的な配列は非常に構造化されたマルチセットの単なる並べ替えであるということです。 ポジションごとに$i$、次の 2 つの可能な値を生成します。$i$そして$n - i + 1$。 したがって、私たちが期待するマルチセットは、まさにすべての位置にわたるこれらのペアの結合です。 

これは、1 から 2 までのすべての数字を意味します。$n$非常に制約された方法で表示されます: 各ペア$(i, n - i + 1)$は 2 つの値に寄与し、これらの寄与は対称的に重なり合います。 位置という観点から考える代わりに、周波数の一致という観点から考えることができます。 

推論するためのより簡単な方法は、値を昇順に処理し、貪欲な構造を使用して出現を「消費」しようとすることです。小さい値は初期のインデックスに対応する必要があります。これは、小さいインデックスのみが ID 割り当てを通じて小さい値を生成でき、大きい値はリフレクト側からのみ生成できるためです。 

これにより、問題は配列の頻度分布とペアの強制構造の間の一貫性チェックに変換されます。$(i, n - i + 1)$。 正しい構築とは、左右からの位置の割り当てを貪欲にシミュレートしたときに、必要な値の利用可能性を決して侵害しないことを検証することになります。 

左右の次の未使用位置を表す 2 つのポインターを維持します。 各ステップで、配列内の現在の最小残り値が左ポインタまたは右ポインタのいずれかに一致するかどうかを確認します。 どちらも一致しない場合、設定は不可能です。 

これが機能するのは、どの時点においても、ポジションに対する有効な割り当ては 2 つの決定的な候補だけであり、順列によって順序付けの制約がなくなるため、プロセスは一連の強制的な選択になるからです。

 ## アルゴリズムのチュートリアル

 配列をソートするのは、順序は無関係であり、使用可能な値についてのみ推論する必要があるためです。 次に、外側の位置から内側に向​​かって有効な割り当てを構築するシミュレーションを試みます。 

1. 配列をソートします。 これにより、最も制約が大きい、残りの不一致値の最小値を常に推論することができます。 
2. 2 つのポインタを初期化します。$l = 1$そして$r = n$、有効な構造における次の割り当ての可能な 2 つのソースのみを表します。 
3. ソートされた配列を反復処理します。 それぞれの値について$x$、現在の左位置に対応できるかどうかを決定します$l$または正しい位置$r$。 もし$x = l$、左側のエンドポイントを消費してインクリメントします$l$。 もし$x = r$、適切なエンドポイントを消費してデクリメントします$r$。 
4. もし$x$どちらのエンドポイントにも一致しない場合は、有効な構造が存在しないと即座に結論付けられ、失敗が返されます。 
5. すべての要素が処理されるまで続行します。 すべての値が一貫して消費される場合、構成は有効です。 

この手順の背後にある理由は、すべての有効な構造が端から内側に向​​かって対称的な位置のペアに対応し、各ステップでどちらかの端からちょうど 1 自由度が削除されるということです。 

### なぜ効果があるのか

 いつでも、残りの未割り当ての位置が連続した間隔を形成します。$[l, r]$。 有効なラベル付けでは、次のいずれかを割り当てる必要があります。$l$または$r$すべての内部位置がすでに固定された構造上の選択に対応するため、次の消費値に変換されます。 値がどちらのエンドポイントにも一致しない場合、その値は有効な割り当てに属することはできません。これは、左/右のラベル付けの固定構造に違反せずに値を生成できる内部位置がないためです。 この不変式により、一度不一致が発生すると、再配置しても修正できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        a.sort()
        
        l, r = 1, n
        ok = True
        
        for x in a:
            if x == l:
                l += 1
            elif x == r:
                r -= 1
            else:
                ok = False
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```この解決策は、構造的制約を明らかにするための並べ替えに依存しています。 2 つのポインタは、任意の段階で有効な値の 2 つのみの「アクティブなソース」を表します。 割り当てごとに間隔が短縮され、仮説上の元の順序との一貫性が常に維持されます。 

よくある実装の落とし穴は、不一致が発生した場合にすぐに中断することを忘れることです。 無効な割り当て後に続行すると、後で一貫性を誤って復元する可能性がありますが、これは論理的に不可能です。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
array = [1, 2, 1]
```ソートされた配列は$[1, 1, 2]$。 

| ステップ | l | r | × | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 3 | 1 | l、l → 2 に一致 |
 | 2 | 2 | 3 | 1 | 不一致 (1 ≠ 2 および 1 ≠ 3) |

 ステップ 2 でプロセスは失敗します。これは、この配置が一貫した左右のラベル構造に対応できないことを意味します。 

ただし、これは重要な特性を強調していることに注意してください。順序は、頻度だけではなく、エンドポイントの一貫性によってのみ重要であるということです。 

### 例 2

 入力:```
n = 4
array = [1, 4, 2, 3]
```ソートされた配列は$[1, 2, 3, 4]$。 

| ステップ | l | r | × | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 4 | 1 | 1 → 2 |
 | 2 | 2 | 4 | 2 | 1 → 3 |
 | 3 | 3 | 4 | 3 | 1→4 |
 | 4 | 4 | 4 | 4 | r→3 |

 すべての値が正常に消費されます。 

これは、すべての値が処理時に 1 つのエンドポイントと正確に一致する、きれいな内向き縮小を示しています。

 ## 特殊なケース

 微妙なエッジケースの 1 つは、$n = 1$。 唯一可能な配列は次のとおりです$[1]$、単一の位置が同時に左右両方にあるため、この条件は自明に満たされます。 アルゴリズムはそれを正しく受け入れます。$l = r = 1$単一の値が一致します。 

もう 1 つのケースは、すべての値が同一である場合です。たとえば、$n = 4$、$[2, 2, 2, 2]$。 収量の選別$[2, 2, 2, 2]$ただし、どちらのエンドポイントも 2 ではないため、最初の不一致がすぐに発生します。$l = 1$そして$r = 4$。 対称的な構築では均一な値を生成できないため、これはこのケースを正しく拒否します。 

さらにエッジケースは、配列が有効な順列であるが、激しくシャッフルされている場合に発生します。$[3, 1, 4, 2]$。 並べ替えにより順序付けの問題が解決され、アルゴリズムによって有効な内部一致シーケンスが再構築されます。 このプロセスは、エンドポイントの一貫性が各ステップで維持される限り、順列は問題ではないことを示しています。
