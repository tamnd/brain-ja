 ## 問題の理解

 シーケンス内のどこにも出現していない自然数を繰り返し選択し、そこから導出された 3 つの値を追加することによって、無限シーケンスを構築するプロセスが与えられています。 選択した番号について$x$、シーケンスがすぐに追加されます$x$、 に続く$2x$、 それから$3x$、これは永遠に続き、常に次に小さい未使用の自然数が新しい基数として選択されます。 

これは、シーケンスが任意のインターリーブまたは倍数のソートではないことを意味します。 代わりに、厳密なブロックで構築され、各ブロックは単一の整数から構成され、ブロックはその整数の昇順に処理されます。 

このタスクは、最大 1000 個のクエリに答えることです。各クエリは位置の値を要求します。$n$、 そして$n$と同じ大きさにすることができます$10^{15}$。 これにより、シーケンスを要素ごとに構築するシミュレーションは即座に除外されます。$10^9$要素はすでに遅すぎるでしょう、ましてや$10^{15}$。 

プロセスの構造は、すべての正の整数が基底として 1 回だけ出現し、連続する 3 つの要素に寄与することを意味します。 単純なアプローチでは、これまでに出現した数値をシミュレートしようとしますが、選択ルールにより、次の基数が単純に昇順で次の整数であることが常に保証されるため、これは不要です。 

よくある失敗例は、「使用された番号」を動的に追跡しようとしたときに発生します。 たとえば、加工後$x=1$発生の内部追跡に応じて、次の未使用の番号が 2 または 3 のようなものになる可能性があると誤って考える人もいるかもしれませんが、実際には 2 と 3 の両方がすでに出現しており、次の有効な塩基は単純に 4 です。塩基選択の厳密な単調構造を認識しないシミュレーションは、すぐに不正確になるか、遅すぎるものになります。 

## アプローチ

 直接シミュレーションでは、出現したすべての数値のセットを維持し、1 から上へ繰り返しスキャンして、未使用の最小の数値を見つけます。 そのような数字ごとに$x$、3 つの値を追加します。 ハッシュ セットを使用してメンバーシップ チェックを最適化したとしても、プロセスでは依然としてスキャンが必要になる可能性があります。$n$それぞれが 3 つの出力に寄与するため、演算の合計数は出力サイズに比例して増加します。 のために$n$まで$10^{15}$、これはまったく実現不可能です。 

重要な観察は、「未使用の数値」ルールが生成されたシーケンスと複雑に相互作用しないことです。 すべての整数が最終的に基数として 1 回だけ使用されることがわかると、プロセスは決定論的になります。$k$-番目に選択された塩基は単純に$k$自体。 これにより、シーケンスが固定ブロックの連結に変わります。$k = 1, 2, 3, \dots$、追加します$k, 2k, 3k$。 

この観点から見ると、シーケンスは動的に構築されなくなりました。 これは、連続する 3 つの位置ごとに 1 つの基数に対応する静的パターンです。 これにより、位置がどのブロックに属しているのか、ブロック内のどの乗算器が必要なのかを特定するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 全体の問題は、フラット シーケンス内の位置をペアにマッピングすることに帰着します。$(k, r)$、 どこ$k$はブロックの基数であり、$r$そのブロック内の位置です。 

1. すべての基数が次のとおりであることを観察します。$k$シーケンス内にちょうど 3 つの連続する要素を生成します。 これは、シーケンスがサイズ 3 のブロックに分割されることを意味します。$k$貢献するポジション$3k-2$、$3k-1$、 そして$3k$。 
2. クエリインデックスを指定する$n$、次のようにして、それがどのブロックに属しているかを計算します。$k = \frac{n+2}{3}$整数の除算を使用します。 これが機能するのは、すべてのブロックがちょうど 3 つの要素を提供するためです。そのため、インデックスをサイズ 3 のチャンクにグループ化することが正確で損失がありません。 
3. 次を使用してブロック内のオフセットを決定します。$r = (n-1) \bmod 3$。 これにより、ブロックの 1 番目、2 番目、または 3 番目の要素のどれを見ているのかが識別されます。 
4. 対応する値を返します。$r = 0$、答えは$k$; もし$r = 1$、答えは$2k$; もし$r = 2$、答えは$3k$。 

ブロック間でインターリーブや並べ替えが発生しないため、各ステップは構造の構造によって強制されます。 

### なぜ効果があるのか

 正確さは、シーケンスが独立したブロックに分割され、それぞれが単一の整数によってのみ生成されるという不変条件から得られます。$k$、ブロックは厳密に昇順で表示されます。$k$。 選択ルールは常に最小の未使用整数を選択するため、将来のブロックは以前のブロックに要素を挿入したり、その内部順序を変更したりすることはできません。 これにより、位置が固定サイズ 3 のブロック境界にグローバルに整列されることが保証され、直接算術マッピングが有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        k = (n + 2) // 3
        r = (n - 1) % 3

        if r == 0:
            print(k)
        elif r == 1:
            print(2 * k)
        else:
            print(3 * k)

if __name__ == "__main__":
    solve()
```このソリューションは算術に完全に依存しているため、各クエリは一定時間内に独立して処理されます。 の計算$k$は、インデックスを 3 つのグループに整列させる整数除算を使用しますが、モジュロ演算は各グループ内の位置を分離します。 ループオーバーはありません$n$、非常に大きな制約を考慮すると、これは不可欠です。 

微妙な点は、1 つずつずれていることです。 使用する$(n+2)//3$位置 1、2、3 がブロック 1 にマッピングされ、位置 4、5、6 がブロック 2 にマッピングされる、というようになります。 モジュロ式では次を使用する必要があります$n-1$それよりも$n$この位置合わせを維持するために。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        k = (n + 2) // 3
        r = (n - 1) % 3
        if r == 0:
            output.append(str(k))
        elif r == 1:
            output.append(str(2 * k))
        else:
            output.append(str(3 * k))
    return "\n".join(output)

 ## 特殊なケース

 主なエッジケースはブロック間の境界であり、オフバイワンの間違いが最も起こりやすい場所です。 たとえば、$n = 3$の場合、出力は依然として最初のブロックに属している必要がありますが、$n = 4$すぐに 2 番目のブロックにジャンプします。 

のために$n = 3$、計算により次のことが得られます。$k = (3+2)//3 = 1$そして$r = 2$、生産$3$、最初のブロックの終わりと一致します。 

のために$n = 4$、私たちは得ます$k = (4+2)//3 = 2$そして$r = 0$、生産$2$、正しく 2 番目のブロックを開始します。 

これにより、整数除算のアラインメントにより、重複や曖昧さなしにブロックがきれいに分離されることが確認されます。
