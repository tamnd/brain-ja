 ## 解決策
 ## 問題の理解

 英語の小文字で構成される文字列が与えられます。 2 人のプレーヤーがこのストリングで交代でゲームをプレイします。 それぞれの動きで、プレイヤーは現在文字列に表示されている 2 つの異なる文字を選択します。 次に、最初に選択された文字が出現するたびに、2 番目に選択された文字に変換されます。 このグローバル置換を実行すると、プレーヤーは、結果のターゲット文字が更新された文字列に出現した回数に等しいポイントをすぐに獲得します。 このプロセスが繰り返され、文字列が 1 つの異なる文字だけで構成されたらゲームは終了します。 両方が最適にプレイしていると仮定すると、合計スコアがより大きいプレーヤーが勝者となります。 

主な難点は、移動するたびにある文字タイプが別の文字タイプにマージされ、ターゲット文字の頻度が増加し、アルファベットが縮小されることです。 移動で得られるスコアは、統合後のマージされたレターの結果の頻度のみに依存します。 

入力サイズは最大 100,000 文字です。 マージのシーケンスを明示的にシミュレートしようとするソリューションは失敗します。各移動には文字列全体にわたるグローバルな置換が含まれ、最大 25 個のマージが可能ですが、各マージのコストは単純に O(n) となり、境界線に達する O(25n) になりますが、非効率な更新や移動ごとの頻度の再計算で繰り返し実行すると、それでも遅すぎます。 さらに重要なのは、最適な選択を推論するには、ゲームプレイをシミュレートするのではなく、構造を分析する必要があるということです。 

複数の文字が同様の頻度を持つ場合、微妙な問題が発生します。 現在最も頻繁に使用されるキャラクターに常にマージするなどの貪欲なアイデアは、初期の選択が将来の利用可能なスコアに影響を与えるため、失敗する可能性があります。 もう 1 つの罠は、ゲームが対称的であるか、ターン交代を考慮せずに周波数順序のみに依存していると仮定していることです。 

中心的な課題は、プロセスを段階的なゲームではなく決定論的な評価に減らすことです。 

## アプローチ

 ブルート フォース ビューは、ゲームの状態をシミュレートすることです。 現在の文字列を維持するか、より現実的には各文字の数を維持します。 それぞれの動きで、異なる文字の可能なすべてのペアを試し、一方を他方にマージすることをシミュレートし、結果として得られるスコアゲ​​インを計算し、結果をミニマックスで再帰的に評価します。 これはルールを正しくモデル化しますが、組み合わせ的に爆発します。 最大 26 文字の場合、分岐係数は約 26 で 2 を選択し、深さは最大 25 ですが、これはすでに大きすぎます。 獲得されるスコアは動的周波数に依存し、遷移を繰り返し再計算すると大きなオーバーヘッドが発生するため、枝刈りさえも困難です。 

重要な観察は、このゲームは基本的に、頻度によって文字を順序付けし、プレーヤー間で利益を交互にする方法で最小の寄与者を繰り返し削除することであるということです。 それぞれの動きは、あるキャラクター タイプを考慮から事実上削除し、その重みを別のキャラクター タイプに移します。 すべてのアクションは 1 文字が残るまでアルファベットを折りたたむため、すべての文字の貢献度の合計は固定されます。唯一の問題は、これらの貢献度が移動順序に応じて 2 人のプレイヤー間でどのように分配されるかです。 

これをより明確に確認する方法は、文字の頻度を並べ替えることです。 最適なプレイでは、貪欲な蓄積パターンで最小文字から最大文字まで消費するという問題が常に軽減されます。これは、大きな周波数の文字の吸収を遅らせることは、後で対戦相手がより多くの総質量を捕捉するのに役立つだけであるためです。 これにより、問題はソートされた周波数の交互の合計に変わり、プレーヤーは事実上、決定論的な順序で周波数を順番に「要求」します。 

したがって、最終的な結果は、実際の文字の識別ではなく、演算のパリティと周波数の配置のみに依存します。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 文字列内の各文字の頻度を数えます。 これにより、問題が最大 26 個の値のマルチセットに圧縮されます。 実際の文字はもはや重要ではなく、その数だけが重要です。 
2. ゼロ以外の周波数をすべてリストに収集します。 各エントリは、ゲーム中に最終的にマージされる 1 つの文字タイプの重みを表します。 
3. 周波数を昇順に並べ替えます。 最適なプレイでは常に、敵対的交代の下でより小さなコンポーネントが最初に消費されるよう強制されるため、順序付けは重要です。 
4. ソートされたリストを反復処理し、ターン順にプレイヤーに貢献度を割り当てることにより、交代をシミュレートします。 最初のプレイヤーは 1 つの蓄積パターンから効果的に恩恵を受けますが、2 番目のプレイヤーはマージごとに大量の転送が行われるため、次の蓄積パターンから恩恵を受けます。 
5. これらのソートされた頻度の加算と減算を交互に行うことにより、スコアの差を計算します。 この蓄積された値の最終的な符号によ​​って勝者が決まります。 

ソートされた周波数を交互に行うことが有効な理由は、質量が大きいほど対戦相手にとって遅延させる価値が常に高いため、最適な結果を変えることなく、あらゆる技シーケンスを周波数の降順以外の順序でマージが適用されるシーケンスに変換できるためです。 

### なぜ効果があるのか

 各文字の頻度は、最終的に最後に生き残る文字に吸収される分割不可能な重みとして見ることができます。 すべての動きはグループ間で重量を移動するだけであり、総重量は保存されます。 ゲームは、各ウェイトが最終的なキャラクターに吸収される前に、どのプレイヤーが各ウェイトを効果的に「制御」するかを決定することに要約されます。 最適なプレイでは、最小の重みが最初に解決されるように強制されます。これは、重みを遅らせても、対戦相手が後続のより大きなマージを蓄積する能力を高めるだけであるためです。 これにより、安定した貪欲な順序付けが引き起こされ、プレイヤーは交互にターンするため、結果として得られる利得は、ソートされた頻度の交互の合計となり、これは決定的です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    if not s:
        return

    freq = [0] * 26
    for ch in s:
        freq[ord(ch) - 97] += 1

    arr = [x for x in freq if x > 0]
    arr.sort()

    diff = 0
    turn = 0

    for x in arr:
        if turn == 0:
            diff += x
        else:
            diff -= x
        turn ^= 1

    if diff > 0:
        print("First")
    else:
        print("Second")

if __name__ == "__main__":
    solve()
```この解決策は、文字列をアルファベット上の周波数配列に圧縮することから始まります。 すべての操作は位置ではなくカウントのみに依存するため、これは非常に重要です。 

次に、ゼロ以外の周波数を抽出して並べ替えます。 ソートされた順序は議論の根幹であり、文字塊の最適な消費順序をエンコードします。 

交互の合計は、最適なプレイがこれらの集団の交互のコントロールに変換されると仮定して、最初のプレーヤーの純利益を計算します。 最終的な比較により勝者が決まります。

 ## 特殊なケース

 ### 単一の文字列

 入力`a`。 異なる文字のペアが存在しないため、有効な手はありません。 試合はもう終わっています。 最初のプレイヤーは移動できないため、ターンベースの評価のデフォルトのルールでは、当然のことながら 2 番目のプレイヤーが勝ちます。 ステートメントの解釈で必要な場合は、どのソリューションでもこのケースを明示的に処理する必要があります。 

### 統一文字列

 入力`aaaaaa`。 最初は異なる文字が 1 つだけ存在するため、ゲームはすぐに終了します。 手は発生せず、最初のプレーヤーにポイントを獲得または失う機会はないため、結果は空のスコアの規則に依存し、通常は最初が有利になります。 

### 非常にアンバランスな周波数

 入力`aaaaab`。 周波数は`[5,1]`。 マージすると、小さな文字がすぐに大きな文字に吸収され、最初の動きが全体のスコア分布を決定します。 アルゴリズムは、寄与を並べ替えて交互に配置することでこれを正確に捕捉し、支配的な重みが結果を決定することを保証します。
