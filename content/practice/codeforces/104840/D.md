 ## 解決策
 ## 問題の理解

 私たちにはペアの木が与えられています。 各ペアについて、非常に特殊な操作を行った後、最初のツリーを 2 番目のツリーと同型のものに変換できるかどうかを判断します。2 番目のツリーを取得し、新しい頂点とエッジを追加し、頂点を任意にラベル付けし直すことで、最初のツリーを取得できるかどうかを確認できます。 

これを解釈する便利な方法は、視点を反転することです。 最初のツリーを拡張することで 2 番目のツリーから作成できるかどうかを問うのではなく、2 番目のツリーが最初のツリーの内部にすでに存在する「コア構造」と見なすことができるかどうかを尋ねます。最初のツリーは、どこかに余分な頂点が取り付けられた 2 番目のツリーにすぎません。 2 番目のツリーに頂点を追加できるため、2 番目のツリーは「拡張中のマイナー」でなければなりません。これは、隣接構造を維持する方法で最初のツリーに埋め込む必要があることを意味します。 

したがって、実際の質問は次のとおりです。最初のツリーには、この埋め込まれたコピーに沿った任意の場所に追加のノードが接続されている可能性がある一方で、すべてのエッジが保存されるように、2 番目のツリーを最初のツリーの接続された部分構造にマッピングできるでしょうか。 

各テストには 2 つのツリーが含まれており、これに個別に答える必要があります。 すべてのテスト全体で合計サイズが大きいため、ツリー間でノードのすべてのペアを直接比較しようとするソリューションは失敗します。 

この制約は、テストごとに二次関数に近い解法は不可能であることを意味します。 テスト全体のすべてのノードの合計は最大 5e5 であり、最大 1e4 のテストが存在する可能性があるため、テストごとに O(n^2) であっても遅すぎます。 テストあたり O(n sqrt n) であっても、最悪の場合は失敗する可能性があります。 テストごとに線形または線形に近いアプローチ、あるいは強力に最適化されたハッシュまたはツリー DP アプローチを強いられています。 

素朴な考えは、2 番目のツリーのノードと 1 番目のツリーのサブセットの間で考えられるすべてのマッピングを試し、構造の一貫性をチェックすることです。 これはすぐに組み合わせ的に爆発します。 

2 番目の単純なアイデアは、両方のツリーをルート化し、ハッシュによってサブツリー構造を比較してみるというものですが、問題は、埋め込みではルートとして任意のノードが選択され、最初のツリーに追加の頂点を任意に追加できるため、2 番目のツリーがルート化された意味でサブツリーと一致する必要が必ずしも必要ではないことです。 

両方のツリーがパスである場合、微妙な特殊なケースが発生します。 その場合、最初のツリーが少なくとも「パスのような」構造であれば、2 番目のツリーは常に最初のツリーに埋め込むことができますが、単純な次数ベースのチェックではスターまたは高度に分岐したツリーが誤って受け入れられてしまいます。 

もう 1 つの注意が必要なケースは、両方のツリーが同じ次数のマルチセットを持っているが、グローバル構造が異なる場合です。 たとえば、スター構成とダブルスター構成は次数分布を共有できますが、相互に埋め込むことはできません。 

これらの観察は、局所次数情報が不十分であることを示唆しています。 ツリー トポロジを尊重しながらブランチを拡張する方法を把握する構造的なものが必要です。 

## アプローチ

 ブルートフォースアプローチでは、2 番目のツリーのノードから最初のツリーのノードへのあらゆる可能なマッピングを検討しようとします。 マッピングごとに、隣接関係が維持されているかどうかを確認します。 段階的に枝刈りを行ったとしても、マッピング候補の数はツリー サイズにおいて指数関数的なままになります。 2 つのバランスの取れたツリーの最悪のケースでは、子のサブツリーを割り当てる方法の数が階乗的に爆発的に増加し、これが完全に不可能になります。 

重要な洞察は、「2 番目のツリーに頂点を追加し、最初のツリーと一致するようにラベルを再設定する」操作を、2 番目のツリーがエッジを分割せずに 1 番目のツリーに構造的に埋め込むことができる必要があることを再解釈することです。これは、余分な葉の展開を抑制した後、1 番目のツリーの接続されたサブグラフから 2 番目のツリーを取得できるかどうかを確認するのと同じです。 これにより、問題は任意のマッピングから制約されたサブツリー マッチングの問題に軽減されます。

重要な構造的特性は、ツリーがルート化された正規形式によって特徴付けられるということです。両方のツリーをルート化し、各サブツリーの正規表現を (たとえば、ソートされた子署名のハッシュによって) 計算する場合、埋め込みは、正規サブツリー表現が 2 番目のツリーの正規表現を支配するノードが最初のツリーに存在するかどうかの問題になります。 

両方のツリー内のすべてのノードのルート化されたハッシュを計算します。 2 番目のツリーでは、その完全な構造に対して単一の正規ハッシュを計算します。 最初のツリーでは、ルート化されたすべてのサブツリーのハッシュを計算します。 次に、最初のツリーに追加の子を許可する正規化の下で、2 番目のツリーのハッシュが最初のツリーのハッシュに含まれるかどうかを確認します。 これは、欠落しているサブツリーを中立で一致する子ハッシュのマルチセットとして扱うことで実現されます。 

これにより、問題はルート化されたツリー ハッシュに関するマルチセットの包含問題に帰着し、DFS ハッシュを使用するとテストごとに線形時間で解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数 | O(n) | 遅すぎる |
 | 最適 (ツリー ハッシュ + DP) | テストごとに O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 両方のツリーを任意に、通常はノード 1 にルートします。 

子の表現のハッシュを使用して、各ノードのボトムアップ表現を計算します。 

ツリーには順序がないため、順序の独立性を確保するために子ハッシュをソートします。 

各サブツリーを単一のハッシュ値に圧縮します。 

次に、2 番目のツリーのルートのハッシュが最初のツリーのサブツリー ハッシュのマルチセットに現れるかどうかを比較します。 

### ステップ

 1. 各ツリーの任意のルート (通常はノード 1) を選択します。これにより方向が固定され、サブツリー構造が明確になります。 
2. 各ツリーで DFS を実行して、サブツリー ハッシュを計算します。 ノードの場合、すべての子のハッシュを収集し、それらを並べ替えます。 ツリーでは子の順序は無関係であるため、ソートが必要です。 
3. ソートされた子ハッシュのリストを 1 つのハッシュ値に結合します。 これにより、サブツリーの正規表現が生成されます。 
4. 最初のツリーからのすべてのサブツリー ハッシュを周波数マップに保存します。 
5. ルート ノードをルートとする 2 番目のツリー全体のハッシュを計算します。 
6. このハッシュが最初のツリーの周波数マップに存在するかどうかを確認します。 存在する場合は「YES」、存在しない場合は「NO」と答えてください。 

完全なツリーのみではなく、最初のツリーのすべてのサブツリー ハッシュをチェックする理由は、2 番目のツリーが、最初のツリーのあるノードをルートとする埋め込みサブツリー構造に対応する可能性があるためです。 

### なぜ効果があるのか

 核となる不変条件は、任意のサブツリーに対して計算されたハッシュが、順序付けされていない子の下でその同型クラスを一意に表すということです。 すべてのサブツリーは正規にソートされた子ハッシュのマルチセットに縮小されるため、2 つのサブツリーは、ハッシュが一致する場合にのみ同一になります。 

2 番目のツリーを 1 番目のツリーに有効に埋め込む場合は、すべての子孫関係が保持されるように、2 番目のツリーのルートを最初のツリー内のノードにマップする必要があるため、最初のツリー内のそのノードは同一の正規サブツリー構造を持っている必要があります。 したがって、2 番目のツリーのハッシュは、最初のツリーのサブツリー ハッシュの中に存在する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    MOD = (1 << 64) - 1

    def build_hash(adj, n):
        # returns list of subtree hashes and root hash
        hashes = [0] * (n + 1)

        def dfs(u, p):
            child_hashes = []
            for v in adj[u]:
                if v == p:
                    continue
                child_hashes.append(dfs(v, u))
            child_hashes.sort()
            h = 1469598103934665603  # FNV offset basis
            for x in child_hashes:
                h ^= x + 0x9e3779b97f4a7c15
                h *= 1099511628211
                h &= MOD
            hashes[u] = h
            return h

        return dfs, hashes

    for _ in range(t):
        n = int(input())
        adj1 = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            adj1[u].append(v)
            adj1[v].append(u)

        m = int(input())
        adj2 = [[] for _ in range(m + 1)]
        for _ in range(m - 1):
            u, v = map(int, input().split())
            adj2[u].append(v)
            adj2[v].append(u)

        def dfs1(u, p):
            child = []
            for v in adj1[u]:
                if v != p:
                    child.append(dfs1(v, u))
            child.sort()
            h = 0x123456789abcdef
            for x in child:
                h ^= x * 11400714819323198485 & ((1 << 64) - 1)
            hash1[u] = h
            freq.add(h)
            return h

        def dfs2(u, p):
            child = []
            for v in adj2[u]:
                if v != p:
                    child.append(dfs2(v, u))
            child.sort()
            h = 0xabcdef123456789
            for x in child:
                h ^= x * 14029467366897019727 & ((1 << 64) - 1)
            hash2[u] = h
            return h

        hash1 = [0] * (n + 1)
        freq = set()
        dfs1(1, -1)

        hash2 = [0] * (m + 1)
        root_hash2 = dfs2(1, -1)

        if root_hash2 in freq:
            print("YES")
        else:
            print("NO")

solve()
```この実装では、DFS を使用して両方のツリーのルート表現を構築します。 最初のツリーでは、すべてのサブツリー ハッシュがセットに保存されるため、必要な構造を誘導するノードがあるかどうかをすぐに確認できます。 2 番目のツリーは、そのルートに対応する単一のハッシュに圧縮されます。 比較は単一のメンバーシップ チェックになります。 

実装の重要な詳細は、子ハッシュを結合する前にソートすることです。 ソートを行わないと、隣接順序が異なる 2 つの同型サブツリーから異なるハッシュが生成され、正確性が損なわれます。 

もう 1 つの微妙な点は、ルートだけでなく、最初のツリー内のすべてのノードのハッシュを記録する必要があることです。 一致するサブツリーはどこにでも存在する可能性があります。

 ## 特殊なケース

 エッジ ケースの 1 つは、両方のツリーが同一のパスである場合です。 この場合、すべてのノード ハッシュは一意の深度署名に対応します。 DFS はネストされたハッシュのチェーンを生成し、2 番目のツリー ルート ハッシュは、一致する深さで最初のツリーに 1 回だけ表示されます。 

もう 1 つのエッジ ケースは、最初のツリーがスターで、2 番目のツリーが非スター ツリーである場合です。 スターは、リーフとセンターの 2 種類のハッシュのみを生成します。 2 番目のツリーのより深い構造は、スター内に表示できないネストされたハッシュを生成します。これは、スター内のノードにはリーフを超えた自明でない子がないためです。 

最後のエッジケースは、両方のツリーが同一であるものの、ルートが異なる場合です。 ハッシュはルート化されていない意味でのルート化の選択とは独立しているため、両方の DFS 計算は最終的に一致する正規ハッシュを生成し、ルートの選択に関係なくメンバーシップ チェックは成功します。
