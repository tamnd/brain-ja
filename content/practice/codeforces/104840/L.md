 ## 解決策
 ## 問題の理解

 私たちには、すべて異なる単語のセットと、それらの間で許可される置換の指示されたシステムが与えられています。 各置換ルールでは、ある単語を別の単語に置き換えることができ、このプロセスは置換の連鎖に従って何度でも繰り返すことができます。 

タスクは、残っている個別の単語の数ができるだけ少なくなるように、これらの置換を任意の順序で任意の回数適用することです。 最終的な単語自体を見つけることは求められません。すべての置換の可能性を十分に活用した後、可能な限り最小限の個別の単語を見つけることだけが求められます。 

この構造は当然、各単語がノードであり、各置換が有向エッジである有向グラフです。 一連の置換は、有向エッジに沿って歩くことに対応します。 

この制約では、最大 200,000 個の単語と 200,000 個の置換ルールが許可され、二次推論や変換の繰り返しシミュレーションが即座に除外されます。 O(n²) の演算でも限界をはるかに超えるため、どのような解もグラフのサイズが線形または線形に近い必要があります。 

微妙な問題は、置換が必ずしも対称的ではないということです。 a を b に置き換えることができるとしても、それは b が a を置き換えることができることを意味するものではありません。 もう 1 つの重要な点は、複数のチェーンが同じ単語にマージできることです。つまり、異なる最初の単語が共通の目的地に到達した場合、最終的に 1 つの代表単語に変換される可能性があります。 

単純な考え方による典型的な失敗シナリオは、置換を独立したものとして扱ったり、貪欲なローカル マージを実行したりすることです。 たとえば、a → b → c → a のようなサイクルがある場合、3 つの単語すべてが 1 つに折りたたまれますが、直接の置換のみに注目すると、そのグローバルなサイクル構造を見逃してしまう可能性があります。 

長いチェーンが存在する場合、別の失敗ケースが発生します。 a → b、b → c、c → d の場合、a と d の間に直接のエッジが存在しない場合でも、4 つの単語すべてが d に折りたたまれます。 推移閉包を考慮しないアプローチでは、マージの可能性が過小評価されます。 

## アプローチ

 ブルートフォース解釈では、すべての単語から可能なすべての変換をシミュレートし、到達可能なすべての単語を計算します。 単語ごとに、有向グラフに対して DFS または BFS を実行し、到達可能なすべてのノードをマークできます。 次に、到達可能なセットを折りたたんだ後に、一意の最小代表がいくつ存在するかを判断しようとします。 

これはすでに深刻な効率上の問題に直面しています。 すべてのノードからグラフ トラバーサルを実行すると、最悪の場合 O(n(n + m)) になりますが、これは 200,000 ノードではまったく実行不可能です。 

重要な洞察は、個々の到達可能性セットの観点から考えるのをやめ、代わりに相互の到達可能性によって引き起こされる等価性に焦点を当てることです。 単語 A が単語 B に到達でき、単語 B が置換シーケンスによって単語 A に到達できる場合、A と B は、強く結合された構造に属しているという意味で交換可能です。 このような構造内では、すべての単語が相互に変換できるため、単一の表現に折りたたむことができます。 

これにより、有向グラフ内の強連結成分 (SCC) を見つける問題が軽減されます。 SCC に凝縮すると、DAG が得られます。 各 SCC 内ではすべての単語が同等であるため、最終的な答えには 1 つの単語のみが含まれます。 

残りの問題は、SCC もエッジを越えてマージできるかどうかです。 エッジでは前方置換のみが許可されるため、SCC では個別のワードの数をコンポーネントごとに 1 つを超えて減らすことはできません。 したがって、最終的な答えは単純に SCC の数になります。

 | --- | --- | --- | --- |
 | ブルートフォース到達可能性 | O(n(n + m)) | O(n + m) | 遅すぎる |

 ## アルゴリズムのチュートリアル

単語を有向グラフの頂点としてモデル化し、置換ルールから隣接リストを構築します。 

1. 各単語から整数インデックスへのマッピングを構築します。 これにより、この規模では遅すぎる文字列ベースの検索ではなく、効率的なグラフ表現が可能になります。 
2. 置換ルールを使用して有向グラフを構築します。 各ルール a → b は、index(a) から Index(b) への有向辺になります。 
3. グラフ上で強連結成分アルゴリズムを実行します。 標準的な方法は、Kosaraju のアルゴリズムまたは Tarjan のアルゴリズムです。 目標は、各コンポーネントに、有向パスを介して相互に到達可能なノードが正確に含まれるようにノードを分割することです。 
4. 結果として生じる SCC の数を数えます。 各 SCC は、置換を繰り返すことで相互に変換できる単語のグループを表します。 
5. このカウントを、個別の単語の可能な最小数として出力します。 

SCC が重要な主な理由は、コンポーネント内であらゆる単語を他の単語に変換できるため、コンポーネントを常に選択した 1 つの代表的な単語に折りたたむことができるためです。 コンポーネント間では、相互に到達可能性がないため、このような完全な変換は不可能です。 

### なぜ効果があるのか

 強く接続されたコンポーネント内では、すべてのノードが他のすべてのノードに到達できます。 これは、そのコンポーネント内のあらゆる単語が、有効な置換チェーンを通じて他の単語に変換できることを意味します。 したがって、コンポーネント全体は単一の交換可能なエンティティのように動作し、複数の単語をコンポーネントから保持する必要はありません。 

異なる SCC 間で、少なくとも 1 つの到達可能方向が欠落しています。 2 つのコンポーネントが 1 つの単語にマージされた場合、それらの間の相互到達可能性が必要になりますが、これは SCC の定義に矛盾します。 したがって、各 SCC は少なくとも 1 つの別個の避けられない単語に寄与しており、正確に 1 つあれば十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def kosaraju(n, g, gr):
    visited = [False] * n
    order = []

    def dfs1(v):
        visited[v] = True
        for to in g[v]:
            if not visited[to]:
                dfs1(to)
        order.append(v)

    def dfs2(v):
        visited[v] = True
        for to in gr[v]:
            if not visited[to]:
                dfs2(to)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    visited = [False] * n
    scc_count = 0

    for v in reversed(order):
        if not visited[v]:
            dfs2(v)
            scc_count += 1

    return scc_count

def solve():
    n, m = map(int, input().split())
    idx = {}
    words = []

    for i in range(n):
        w = input().strip()
        idx[w] = i
        words.append(w)

    g = [[] for _ in range(n)]
    gr = [[] for _ in range(n)]

    for _ in range(m):
        a, b = input().split()
        u = idx[a]
        v = idx[b]
        g[u].append(v)
        gr[v].append(u)

    print(kosaraju(n, g, gr))

if __name__ == "__main__":
    solve()
```この実装では、まず、ハッシュ マップを使用して文字列ノードを整数インデックスに圧縮します。これは、エッジごとの操作を O(1) に保つために不可欠です。 隣接リスト`g`有向置換グラフを保存します。`gr`Kosaraju の 2 回目のパスに必要な反転グラフを保存します。 

最初の DFS は、元のグラフに基づいて終了順序を構築します。 この順序により、逆方向の終了時間でノードを処理するときに、常に逆方向のグラフ内のコンポーネントの有効なルートから SCC 探索が開始されることが保証されます。 

2 番目の DFS は反転グラフで実行され、新しいトラバーサルを開始した回数をカウントします。これは SCC の数に直接対応します。

## 特殊なケース

 完全に切り離されたグラフは、最も単純なストレス ケースです。 各単語には置換がないため、結合はできません。 このアルゴリズムは、2 番目の DFS パス中に各ノードを独自の SCC に割り当てます。 たとえば、ワードが 3 つでエッジがない場合、反転したグラフも空になり、各 DFS2 呼び出しはちょうど 1 つのノードに触れ、3 つのコンポーネントが生成されます。 

完全に循環するグラフはその対極です。 すべてのワードがサイクルを通じて他のワードに到達できる場合、DFS2 は 1 回の走査でグラフ全体をスイープするため、DFS1 からの終了順序は無関係になります。 これにより、SCC が 1 つだけ生成されます。 

長いチェーンは推移的な到達可能性をテストします。 a → b → c → d のような場合、DFS2 は逆の終了順序でノードを処理し、c が処理されるときに、逆グラフ走査で b と a に到達できるようにし、相互に到達可能な場合にのみそれらを SCC に正しくグループ化します。
