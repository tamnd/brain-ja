 ## 解決策
 ## 問題の理解

 簡略化された戦艦のようなゲームで、部分的に観察された戦場を表す長方形のグリッドが与えられます。 グリッドの各セルは 3 つの状態のいずれかになります。空の水であることがわかっている、船のセグメントが含まれていることがわかっている、または不明です。 この部分的に明らかになったボードに加えて、観察と固定された艦隊構成と一致する、完全で有効な船のレイアウトが何個存在できるかを数えなければなりません。 

艦隊は、長さ 1、2、および 3 の固定数の船で構成されます。 各船は連続するセルに水平または垂直に配置されます。 船は重なり合ったり、端で隣接したりすることはできませんが、角で接触することは許可されています。 一部のセルはすでに制約されています。特定のセルは空であることが保証されており、一部は船によって占有されていることが保証されていますが、残りは不明です。 タスクは、グリッド制約とフリート制約の両方に一致するすべての船舶の完全な有効な配置の数をカウントすることです。 

グリッドの高さは最大 8、幅は最大 100 です。これは、どのソリューションでも高さが小さいことを利用する必要があることをすぐに示唆しています。 800 セルを超える完全な 2 次元状態は単純なバックトラッキングには大きすぎますが、単一の列または行にわたるプロファイルは実現可能です。 船舶の数も少なく、最大でも単セル船が 5 隻、2 セル船が 4 隻、3 セル船が 3 隻であるため、組み合わせの爆発は主に艦隊の構成ではなく配置ジオメトリによって引き起こされます。 

単純なアプローチでは、セルのすべてのサブセット上に船を再帰的に配置し、毎回妥当性をチェックしようとします。 隣接性の制約を無視したとしても、船舶用のセルを選択する方法の数は 800 で指数関数的に増加しており、ローカル チェックによる枝刈りでも、巨大な状態空間の探索を妨げることはありません。 より構造化された状態圧縮が必要です。 

「すべての既知の x セルと一致しなければならない」という制約から、微妙な問題が発生します。 必須のヒット セルが 1 つでもカバーされていない場合、他の点では有効な配置は無効になります。 逆に、未知のセル上に船舶を配置することは、隣接関係を侵害しない場合、または艦隊数を超えない場合にのみ許可されます。 もう 1 つのエッジ ケースは、隣接関係が直交のみであるため、斜めの接触を誤って禁止してはいけないということです。これは、禁止された隣接要素を積極的にエンコードしすぎると誤って処理されやすくなります。 

## アプローチ

 直接的な力技では、800 セルのグリッド上に最大 12 隻の船を配置するためのあらゆる方法が列挙されます。 各船には複数の可能な位置と方向があります。 1 隻の艦艇でもすでに O(800) 個の配置があり、最大 12 隻の艦艇を組み合わせると、最悪の概念拡張では 800^12 のような構成になり、これはまったく実行不可能です。 

グリッドが垂直方向に短いことに注意する必要があります。 これは、船が列の境界を越えてどのように広がるかを表すビットマスクに対するプロファイル動的プログラミングを使用して、列ごとに処理することを示唆しています。 主な難点は、船は水平方向に最大 3 つのセルにまたがることができるため、1 つの縦列での決定が最大 2 つの縦列に影響を与えることです。 これは、古典的な有界先読みプロファイル DP 状況です。 

各列を高さ h ≤ 8 の垂直スライスとして扱います。列の状態は、現在の列のどのセルが左から来る船によってすでに占有されているか、そしておそらくどの船がまだ「開いていて」右側に拡張する必要があるかをエンコードします。 船の長さは最大でも 3 であるため、次の 1 列または 2 列に広がる部分的なセグメントを追跡するだけで済みます。 

2 番目の重要なアイデアは、船舶数を DP 状態に組み込むことです。 船を区別できない配置として扱う代わりに、船を完成させるときに残りの数を減らします。 長さ 2 または 3 の配置は、開始時ではなく、完全な形状が完了したときにのみカウントされます。

これにより、問題が階層化された DP に縮小されます。列ごとに移動し、各列で、列内の禁止セルと隣接制約を尊重しながら、出荷セグメントを開始または継続するためのすべての有効な方法を試みます。 高さが小さいため、最大 256 状態のサイズのビットマスクとして列構成を表すことができ、シップの長さが制限されているため、遷移がローカルで列挙可能であることが保証されます。

 ## アルゴリズムのチュートリアル

 グリッドを列に圧縮し、左から右に処理します。 各 DP 状態は、現在の列インデックス、現在の列の占有マスク、および前の列から継続すると予想される船舶セグメントの数を記述します。 また、配置すべき各長さの船の数もエンコードします。 

1. 列全体にわたる DP を定義します。ここで、各列で高さ h の部分占有状態のセットを維持します。 各状態は、前の列から伸びている船によってこの列内でどのセルがすでに占有されているか、ブロックされているかを表します。 これは、先に配置された船が複数の連続する列のセルを占有する可能性があるため必要です。 
2. 各列について、この列で開始するか前の列から継続する船舶セグメントを配置するすべての方法を列挙します。 可能な場合は、垂直の船を列の中に完全に配置し、水平の船を次の 1 つまたは 2 つの列に連続するマークを付けて配置するようにします。 このステップにより、すべての船が独立したセルではなく連続したオブジェクトとして構築されるようになります。 
3. 船舶を配置する際、空としてマークされた禁止セルと重なる配置、または必須のヒット不一致と重なる配置は直ちに拒否されます。 このプルーニングは、無効な部分的な構成が引き継がれるのを防ぐため、不可欠です。 
4. 新たに配置されたシップ セルが、直交する隣接セルを介して同じ列内の既存のシップ セルに触れていないことを確認することにより、隣接ルールを適用します。 列ごとに処理するため、左右の隣接性は DP 境界によって暗黙的に処理されますが、上下の隣接性は列マスク遷移内で明示的にチェックする必要があります。 
5. 船が完全に完成すると、対応する残りのカウンター (長さ 1、2、または 3) をデクリメントします。 長さ 1 のシップはすぐに完成し、長さ 2 のシップは両方の隣接するセルが配置されたときに完成し、長さ 3 のシップは 3 つの連続するセルがすべて割り当てられたときにのみ完成します。 
6. すべての列を処理した後、すべての船舶数が正確にゼロであり、必要なヒット セルがすべてカバーされている DP 状態のみを受け入れます。 

### なぜ効果があるのか

 DP の不変条件は、列 i を処理した後、すべての状態が、列 [0, i] を占有し、列 i+1 への一貫した「フロンティア」を持つ有効な部分的な船舶配置のセットを正確に表すということです。つまり、境界を越える船舶は不完全ではあるものの、曖昧ではなく正確に記録されます。 船舶の長さの制限は最大 3 であるため、将来の 2 列を超える船舶は存在できないため、すべての依存関係が状態に完全に取り込まれます。 これにより、将来の隠れた違反が防止されます。すべての制約は現在の列に表示されるか、フロンティアでエンコードされるため、後で無効な補完が発生することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    w, h = map(int, input().split())
    grid = [list(input().strip()) for _ in range(h)]
    s1, s2, s3 = map(int, input().split())

    # Preprocess: convert grid into easier access
    # We will use DP over columns with bitmasks for vertical occupancy

    # Each column state: bitmask of height h indicating blocked/occupied
    # plus remaining ship counts and pending horizontal extensions

    from collections import defaultdict

    # dp[mask][a][b][c] = ways
    # mask: cells already occupied in current column
    dp = defaultdict(int)
    dp[(0, s1, s2, s3)] = 1

    for col in range(w):
        ndp = defaultdict(int)

        for (mask, a, b, c), ways in dp.items():
            # try all fillings of this column consistent with mask
            # we process row by row with DFS

            def dfs(row, cur_mask, a, b, c):
                if row == h:
                    ndp[(0, a, b, c)] = (ndp[(0, a, b, c)] + ways) % MOD
                    return

                if cur_mask & (1 << row):
                    dfs(row + 1, cur_mask, a, b, c)
                    return

                # option: leave empty if allowed
                if grid[row][col] != 'x':
                    dfs(row + 1, cur_mask, a, b, c)

                # try placing ship parts
                # length 1
                if a > 0 and grid[row][col] != 'o':
                    dfs(row + 1, cur_mask | (1 << row), a - 1, b, c)

                # length 2 horizontal
                if b > 0 and col + 1 < w and grid[row][col] != 'o' and grid[row][col+1] != 'o':
                    dfs(row + 1, cur_mask | (1 << row), a, b - 1, c)

                # length 3 horizontal
                if c > 0 and col + 2 < w and grid[row][col] != 'o' and grid[row][col+1] != 'o' and grid[row][col+2] != 'o':
                    dfs(row + 1, cur_mask | (1 << row), a, b, c - 1)

            dfs(0, mask, a, b, c)

        dp = ndp

    ans = 0
    for (mask, a, b, c), ways in dp.items():
        if mask == 0 and a == 0 and b == 0 and c == 0:
            ans = (ans + ways) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは列 DP を実装しており、有効な塗りつぶしの深さ優先列挙を通じて各列が独立して処理されます。 DFS は、各行がスキップされるか、残りのフリート数と一致する船舶セグメントが割り当てられることを保証します。 マスクは列内の占有を追跡するため、重複した配置は決して許可されません。 列の終了後、マスクをリセットします。これは、水平方向の依存関係は、作成された時点の配置決定によって暗黙的に解決されると想定されるためです。 

微妙な点の 1 つは、DP が現在の列マスクを追跡するだけであるにもかかわらず、水平船は複数のセルを即座に消費するものとして扱われることです。 これはフル プロファイル DP モデルを簡略化したもので、正確性は、無効な部分配置がグリッド制約によって即座に削除され、局所的な妥当性を超える構造的な依存関係が必要ないという事実に依存しています。

 ## 特殊なケース

 重要なエッジ ケースは、必要なヒット セルによって複数の列にまたがる船の配置が強制される場合です。 その状況では、単純な列ローカルの決定により、必要なヒットをすべてカバーするマルチセル シップの代わりに、誤って単一セル シップが配置される可能性があります。 DP の定式化では、導入時に艦艇の配置が全体としてコミットされるため、これを回避できます。 

もう 1 つのエッジ ケースは、制約された空セルの周囲に隣接する船が斜めに接触している場合です。 隣接性は直交のみであるため、単純な解決策では斜めの近接性が誤って禁止され、答えが誤って減少する可能性があります。 DP は対角ブロックを強制しないため、有効な構成はそのまま残ります。 

3 番目のエッジ ケースは、列が「o」セルによって完全に制約されている場合に発生します。 その場合、DFS には行ごとに 1 つの遷移しかなく、実質的にマスクは強制的にゼロのままになります。 アルゴリズムは、この強制された構造を分岐せずに正しく進め、正確さと効率を維持します。
