 ## 解決策
 ## 問題の理解

 特別なスライディング ウィンドウ プロパティを使用して N 桁の 10 進数を作成する必要があります。 答え内の連続する 5 桁のすべてのブロックは、それ自体が素数でなければなりません。 たとえば、6 桁の候補が`123457`、チェックされた 2 つのブロックは次のとおりです。`12345`そして`23457`、両方とも素数でなければなりません。 

入力は必要な長さ N のみです。出力は任意の有効な N 桁の数値であるため、このタスクは値を数えたり最適化したりするよりも建設的です。 

N を 100000 までに制限すると、可能性のある文字列の検索が直ちに除外されます。 すべての桁で分岐する直接生成では、検索空間が膨大になり、多数の候補をチェックすることすら不可能になります。 前処理ステップがわずかで、作業が N にほぼ線形に依存するメソッドが必要です。 

主なトラップは、スライディング ウィンドウの長さに関連しています。 最初の数個の 5 桁ブロックのみをチェックするソリューションは、後で新しい桁が複合ブロックを作成するときに失敗する可能性があります。 もう 1 つのよくある間違いは、最後の 4 桁の内部表現で先頭のゼロを失うことです。 たとえば、プライムの接尾辞`10009`4桁の文字列です`0009`、整数ではありません`9`桁の遷移について考えるとき。 

可能な限り最小の入力の場合、出力には 5 桁の素数が 1 つだけ必要になります。 入力用`5`、有効な答えは次のとおりです`10009`なぜなら、チェックするウィンドウは 1 つだけだからです。 答えを生成する前に常にサイクルを作成しようとする不注意な実装は、この境界ケースで不必要に失敗する可能性があります。 

遷移がゼロで終了する場合、別のエッジ ケースが発生します。 5桁の素数`10007`州から移動する`1000`州へ`0007`。 2 番目の状態を次のように扱う`7`その後、パディングなしで印刷すると、数字のシーケンスが破壊され、無効なウィンドウが作成される可能性があります。 

## アプローチ

 ブルートフォース ソリューションでは、数字を 1 つずつ追加しようとします。 新しい数字を選択すると、最新の 5 桁の接尾辞が素数かどうかがチェックされます。 これは正しいです。無効な選択はすべて、不正なウィンドウが作成されるとすぐに検出されるためです。 問題は、使用可能なプレフィックスの数が急速に増加することです。 枝刈りを行ったとしても、探索される状態の数が多すぎて、必要な長さ 100,000 を処理できません。 

条件の構造により、より適切に表現されます。 5 桁の素数は、2 つの 4 桁の文字列間の遷移を決定します。 現在の下 4 桁が`abcd`そして数字を追加します`e`、新しい 5 桁の番号は`abcde`、次の状態は次のようになります`bcde`。 

これにより有向グラフが作成されます。 各頂点は 4 桁の文字列であり、5 桁のすべての素数は最初の 4 桁から最後の 4 桁までのエッジになります。 有効な無限シーケンスを見つけることは、有向サイクルを見つけることと同じになります。 サイクルに入ると、そのサイクルを永久にトラバースし続けることができ、トラバースされたすべてのエッジが有効な 5 桁の素数に対応します。 

グラフは完全に構築できるほど小さいです。 テストできる 5 桁の数値は 100,000 しかなく、状態の数も 10,000 しかありません。サイクルを見つけた後、必要な長さに達するまでその数値を繰り返し使用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合の N の指数 | O(N) | 遅すぎる |
 | 最適 | O(100000 + N) | O(10000) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ふるいを使って 10000 から 99999 までのすべての素数を生成します。 このような各素数は、1 つの有効な 5 桁のウィンドウになります。 
2. 0 ～ 9999 の整数で表される 4 桁の文字列を頂点とするグラフを作成します。`p`最初の 4 桁から最後の 4 桁までエッジを作成します。 エッジには、エッジに沿って移動するときに追加される 5 番目の桁が格納されます。 
3. このグラフに対して深さ優先検索を実行して、有向サイクルを見つけます。 DFS 中に、アクティブな頂点を追跡します。 エッジが現在アクティブな頂点を指している場合、サイクルが見つかりました。 
4. サイクルエッジによって追加された桁を保存します。 最初の 4 桁はサイクルの開始頂点から取得され、後続のすべての桁はサイクルの反復トラバースから取得されます。 
5. N がちょうど 5 の場合、5 桁の素数があればすぐに出力します。 それ以外の場合は、サイクルプレフィックスを出力し、長さが N になるまでサイクル桁を追加します。 

このサイクルが十分である理由は、サイクル内のすべてのエッジが素数の 5 桁ウィンドウを表すためです。 サイクル内を移動すると、既知のプライム エッジからウィンドウが作成されるだけなので、サイクルを繰り返しても無効なブロックが発生することはありません。 

これが機能する理由: 維持される不変条件は、構築中に到達するすべての 4 桁の状態が、これまでのすべての 5 桁ウィンドウが素数であるシーケンスの最後の 4 桁であるということです。 グラフのエッジ自体は 5 桁の素数であるため、グラフのエッジはこの特性を保持します。 サイクルは状態を繰り返すため、その後のすべての遷移は、これらのすでに検証されたプライム エッジの 1 つになります。 したがって、最後の文字列はその全長にわたって有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(20000)

def solve():
    n = int(input())

    if n == 5:
        print("10009")
        return

    limit = 100000
    prime = [True] * limit
    prime[0] = prime[1] = False
    for i in range(2, int(limit ** 0.5) + 1):
        if prime[i]:
            step = i
            start = i * i
            prime[start:limit:step] = [False] * (((limit - 1 - start) // step) + 1)

    adj = [[] for _ in range(10000)]

    for x in range(10000, 100000):
        if prime[x]:
            s = str(x)
            u = int(s[:4])
            v = int(s[1:])
            adj[u].append((v, s[4]))

    color = [0] * 10000
    parent = [-1] * 10000
    parent_digit = [''] * 10000
    cycle_digits = None
    cycle_start = None

    def dfs(u):
        nonlocal cycle_digits, cycle_start
        color[u] = 1

        for v, d in adj[u]:
            if color[v] == 0:
                parent[v] = u
                parent_digit[v] = d
                if dfs(v):
                    return True
            elif color[v] == 1:
                path = [u]
                while path[-1] != v:
                    path.append(parent[path[-1]])
                path.reverse()

                digits = []
                for node in path[1:]:
                    digits.append(parent_digit[node])
                digits.append(d)

                cycle_digits = digits
                cycle_start = v
                return True

        color[u] = 2
        return False

    for i in range(10000):
        if color[i] == 0 and adj[i]:
            if dfs(i):
                break

    answer = str(cycle_start).zfill(4)
    idx = 0
    while len(answer) < n:
        answer += cycle_digits[idx]
        idx = (idx + 1) % len(cycle_digits)

    print(answer[:n])

if __name__ == "__main__":
    solve()
```ふるいは、グラフの構築中に素数テストが繰り返されることを回避します。 私たちが気にする最大の数値は 99999 であるため、単純なブール値のふるいで十分です。 

グラフでは頂点に整数が使用されますが、4 桁の状態が出力されるたびにゼロが埋め込まれます。 これが必要となるのは、次のような州があるためです。`0007`そして`7`同じ整数を表していても、異なる数字のシーケンスになります。 

DFS カラー配列には 3 つの意味があります。 0 は頂点が訪問されていないことを意味し、1 は頂点が現在の再帰スタック上にあることを意味し、2 はその検索が終了したことを意味します。 カラー 1 頂点へのエッジは、まさに有向サイクルを回復するために必要な条件です。 

サイクルの再構築では、ツリー パスの数字と最後のバック エッジを収集します。 これらの数字は、最初の 4 桁の後に繰り返される接尾辞です。 大きな整数演算は使用されないため、実装ではオーバーフローの問題が回避され、N = 100000 が快適に処理されます。

 ## 特殊なケース

 最低限の入力に関しては`5`、アルゴリズムの出力`10009`直接。 必要なウィンドウは 1 つだけであるため、サイクルを延長する必要はありません。`10009`はすでにプライムです。

最大長さについては`100000`、アルゴリズムは新しい数値を桁ごとに検索しません。 サイクルを 1 回見つけて、答えが必要なサイズに達するまでその数字をコピーします。 追加されたすべての桁は、すでに検証された 1 つのグラフ エッジに対応するため、出力サイズが大きくても検索の問題が発生することはありません。
