 ## 問題の理解

 タスクは、数学関数に関する多くの独立した質問に答えることです。 価値のために`a`、機能は製品です$$f(a)=1^a \cdot 2^{a-1}\cdot 3^{a-2}\cdots (a-1)^2\cdot a^1$$特別な値を使って`f(0)=1`。 各クエリはこの値のモジュロを要求します$10^9+7$。 公式声明でも同じ定義が示されており、クエリされる値は次のように制限されています。$10^5$。 

入力には最大で次のものが含まれます$10^5$クエリとすべてのクエリ`a`それもせいぜい$10^5$。 これにより、クエリごとに積を最初から再計算する必要が直ちに排除されます。 1 つのクエリのニーズを直接計算する$O(a)$乗算、これは約になります$10^{10}$最悪の場合の運用。 2 秒の時間制限があるため、クエリ間で作業を共有する方法を見つける必要があります。 

厄介なケースはほとんどが境界付近にあります。 1つ目は`a = 0`、式には因子がまったく含まれていませんが、答えは次のように明示的に定義されています。`1`。 から掛け算を開始するソリューション`1`すべてのクエリには、このケースを誤って処理する可能性のある要素が少なくとも 1 つあると想定しています。 

例えば：```
Input
1
0
```正しい出力は次のとおりです。```
1
```に対する答えを初期化する不用意な実装`0`または、製品の最初の要素にアクセスしようとすると失敗します。 

もう一つのエッジケースは、`a = 1`。 この積には次の用語が 1 つだけ含まれています。$$f(1)=1^1=1$$例えば：```
Input
1
1
```正しい出力は次のとおりです。```
1
```繰り返しに基づく実装では、この遷移を正しく処理する必要があります。これは、次の値を乗算する必要があるためです。`1!`値を変更しないままにします。 

## アプローチ

 簡単なアプローチは、すべてのクエリを個別に評価することです。 お問い合わせの場合`a`からすべての数値をループできます。`1`に`a`そして、各数値に必要な累乗を掛けます。 これは定義に直接従っているため、正しいです。 ただし、可能な限り最大のクエリが必要になります。$10^5$要因、そしてこれを行うために$10^5$クエリはおおよその値を返します$10^{10}$モジュラー操作。 それは制限時間内に収まる限界をはるかに超えています。 

重要な観察は、関数の 2 つの連続する値を比較することから得られます。 毎回製品全体を拡張するのではなく、比較してください。`f(a)`と`f(a-1)`:$$f(a)=1^a\cdot2^{a-1}\cdots(a-1)^2\cdot a$$そして$$f(a-1)=1^{a-1}\cdot2^{a-2}\cdots(a-1)^1$$からの既存のすべての番号`1`に`a-1`指数内でちょうど 1 つの余分なコピーを取得し、新しい因数を取得します`a`が一度出現します。 比率は次のようになります。$$\frac{f(a)}{f(a-1)}=1\cdot2\cdot3\cdots a=a!$$したがって、再発は次のようになります。$$f(a)=f(a-1)\cdot a!$$これにより問題は完全に変わります。 階乗を事前計算してから、一連の応答を一度構築するだけで済みます。 その後、すべてのクエリは単一の配列検索によって回答されます。 

定義が値を直接記述しているため、ブルート フォースが機能しますが、隣接するクエリに対してもほぼ同じ作業が繰り返されます。 連続する答えが階乗によってのみ異なるという観察により、繰り返される積を接頭辞の計算に置き換えることができます。

 ## アルゴリズムのチュートリアル

 1. 最初にすべてのクエリを読み取り、要求された最大の値を見つけます。 この最大値が必要なのは、この最大値までのすべての値を事前に準備できる一方で、より小さなクエリでは同じ事前計算された回答を再利用できるためです。 
2. から階乗を計算します。`1`最大値まで。 させて`fact[i]`店$i!$モジュロ$10^9+7$。 これらの値は、から移動するために必要な乗数を表します。`f(i-1)`に`f(i)`。 
3. 回答配列を構築します。 から始める`f(0)=1`。 あらゆる人にとって`i`から`1`最大値まで、前の答えに次の値を掛けます。`fact[i]`。 結果の値は次のとおりです。`f(i)`すべての遷移には 1 つの階乗が適用されるためです。 
4. すべての入力クエリに対して`a`、インデックスに格納されている事前計算された値を出力します`a`。 考えられるすべての値がすでに生成されているため、追加の数学的作業は必要ありません。 

なぜ効果があるのか:

 前処理中の不変条件は、インデックスの処理後の不変条件です。`i`、保存された値は正確に$f(i)$。 最初は、保存されている値が次のとおりであるため、これは true です。$f(0)=1$。 から移動するとき`i-1`に`i`を掛けます`i!`、そして導出された漸化式は、これが正確に生成することを証明します`f(i)`。 すべてのクエリはこれらの検証済みの状態のいずれかを要求するため、返される値は常に正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    n = int(input())
    queries = [int(input()) for _ in range(n)]

    mx = max(queries)

    fact = [1] * (mx + 1)
    for i in range(1, mx + 1):
        fact[i] = fact[i - 1] * i % MOD

    ans = [1] * (mx + 1)
    for i in range(1, mx + 1):
        ans[i] = ans[i - 1] * fact[i] % MOD

    print("\n".join(str(ans[x]) for x in queries))

if __name__ == "__main__":
    solve()
```最大のクエリによって前処理がどこまで行われる必要があるかが決まるため、入力は処理前に保存されます。 その最大値が分からないと、メモリを無駄にするか、配列を動的に拡張する必要があります。 

の`fact`配列には、必要な素数を法とする通常の階乗値が格納されます。 2 番目のループでは、再帰関数を使用して実際の関数値を構築します。$f(i)=f(i-1)\cdot i!$。 これら 2 つの配列を分離しておくと、階乗を繰り返し再計算する必要がなくなります。 

の初期化`ans[0]`として`1`の特別な定義を処理します`f(0)`。 ループは次から始まります`1`、したがって、空の製品にはオフバイの問題はありません。 Python の整数はオーバーフローしませんが、すべての乗算は剰余化されます。`MOD`値を小さく保ち、必要な出力に一致させるためです。
