 ## 解決策
 ## 問題の理解

 単一の小文字のラテン文字列が与えられます。 文字列に 3 つの連続する母音が含まれず、また 3 つの連続する子音も含まれない場合、その文字列は良好であるとみなされます。 これらの状況のいずれかが文字列内のどこかに現れた場合、その文字列は不良です。 

タスクは、入力文字列がどのカテゴリに属する​​かを判断するだけです。 禁止されたシーケンスが存在する場合は、出力します。`BAD`。 それ以外の場合は、印刷します`GOOD`。 

文字列の長さは最大でも`100000`これは、すべての文字が 1 回だけ処理されるべきであることを即座に示唆しています。 すべての部分文字列を個別にチェックするなど、文字列の一部を繰り返し再スキャンするアルゴリズムでは、最悪の場合、非常に多くの操作が実行されます。 一方、リニア スキャンでは約 10 万文字のチェックのみが実行され、制限内に簡単に収まります。 

いくつかの特殊なケースは注目に値します。 

3 文字より短い文字列には、連続する 3 つの母音または子音を含めることはできません。 例えば：```
ab
```正しい出力は次のとおりです。```
GOOD
```長さをチェックせずにトリプルを盲目的に検査する不注意な実装は、文字列の外側の文字にアクセスする可能性があります。 

シーケンスは連続している必要があります。 例えば：```
ababa
```正しい出力は次のとおりです。```
GOOD
```Although there are many vowels and many consonants overall, they are constantly interrupted, so no run reaches length three.

 Runs may appear at the very beginning or the very end of the string. 例えば：```
aaab
```正しい出力は次のとおりです。```
BAD
```同様に、```
baaa
```もです`BAD`。 文字列の途中のみをチェックする実装では、これらのケースを見逃す可能性があります。 

手紙`y`この問題では母音です。 例えば：```
yyy
```以下を生成する必要があります:```
BAD
```治療中`y`子音だと間違った答えが返ってきます。 

## アプローチ

 最も直接的な解決策は、連続する 3 文字のグループをすべて調べることです。 各トリプルについて、3 つすべてが母音であるか、3 つすべてが子音であるかを判断します。 どちらかの条件が成立すれば、答えはすぐに得られます`BAD`; それ以外の場合は、文字列の終わりまで続行します。 

すべての禁止パターンは正確に 3 つの連続する文字で構成されているため、この方法はすでに正しいです。 4 つの連続母音など、より長い文字列には必ずその中にトリプルが含まれます。 

はるかに効率的ではない総当たりのアイデアは、すべての部分文字列を列挙し、それに 3 つの連続する母音または子音が含まれているかどうかを検査することです。 長さの文字列`100000`約持っています`5 × 10^9`部分文字列を使用するため、そのようなアプローチは完全に非現実的になります。 

重要な観察は、現在の連続実行のみが重要であるということです。 現在の文字が前の文字と同じタイプ (母音または子音) を持つ場合、ランレングスは増加します。 それ以外の場合、ランレングスは 1 にリセットされます。 どちらかのランが 3 に到達すると、答えはすでにわかっています。`BAD`となり、それ以上の処理は必要ありません。 

これにより、少数の変数のみを使用して、文字列を 1 回の左から右へのパスで処理できるようになります。

 ## アルゴリズムのチュートリアル

 1. すべての母音を以下を含むセットに保存します。`a`、`e`、`i`、`o`、`u`、 そして`y`。 セット内のメンバーシップ チェックは一定時間行われます。 
2. 2 つのカウンタを初期化します。1 つは現在の連続する母音用、もう 1 つは現在の連続する子音用です。 どちらもゼロから始まります。 
3. 文字列を左から右にスキャンします。 
4. 現在の文字が母音の場合、母音カウンタを 1 つ増やし、子音カウンタを 0 にリセットします。 これは、子音の実行が中断されたことを示しています。 
5. 現在の文字が子音の場合、子音カウンタを 1 つ増やし、母音カウンタを 0 にリセットします。 
6. カウンタを更新した後、どちらかのカウンタが 3 に達しているかどうかを確認します。 その場合は印刷してください`BAD`禁止された走行が発見されたため、直ちに。 
7. どちらのカウンタも 3 に達せずにスキャンが終了した場合は、印刷します。`GOOD`。 

### なぜ効果があるのか

 どの位置でも、母音カウンタは完全に連続する母音で構成される現在の接尾辞の長さに等しく、子音カウンタは完全に連続する子音で構成される現在の接尾辞の長さに等しくなります。 新しい文字が処理されるたびに、一方のカウンターが増加し、もう一方のカウンターがリセットされるため、これらの値は正しく維持されます。 すべての禁止パターンは、同じ種類の少なくとも 3 つの連続する文字の連続であるため、カウンタ値が 3 に達することは、文字列が不良であると宣言するために必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    vowels = set("aeiouy")

    vowel_run = 0
    consonant_run = 0

    for ch in s:
        if ch in vowels:
            vowel_run += 1
            consonant_run = 0
        else:
            consonant_run += 1
            vowel_run = 0

        if vowel_run >= 3 or consonant_run >= 3:
            print("BAD")
            return

    print("GOOD")

if __name__ == "__main__":
    solve()
```この解決策は、各文字を一定時間内に分類できるように母音のセットを作成することから始まります。 

2 つのカウンターは現在のランレングスを表します。 それらのうちの 1 つが各反復で増加しますが、もう 1 つは現在の実行が中断されたためにリセットされます。 

長さ 3 のランのチェックは、カウンターを更新した直後に行われます。 これにより、答えが判明次第、プログラムを早期終了することができます。 

使用する`strip()`実際の文字列は変更せずに、入力から末尾の改行を削除します。 インデックスは使用されないため、文字列が 3 文字未満の場合でも境界の問題は発生しません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline
    s = input().strip()
    vowels = set("aeiouy")

    vowel_run = 0
    consonant_run = 0

    for ch in s:
        if ch in vowels:
            vowel_run += 1
            consonant_run = 0
        else:
            consonant_run += 1
            vowel_run = 0

        if vowel_run >= 3 or consonant_run >= 3:
            print("BAD")
            return

    print("GOOD")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return out

# provided samples
assert run("good\n") == "GOOD", "sample 1"
assert run("bad\n") == "GOOD", "sample 2"
assert run("zashtsheeshtschayjushtsheekhsya\n") == "BAD", "sample 3"
assert run("dlinnosheee\n") == "BAD", "sample 4"

# custom cases
assert run("a\n") == "GOOD", "single character"
assert run("yyy\n") == "BAD", "y is a vowel"
assert run("bcdf\n") == "BAD", "four consecutive consonants"
assert run(("ab" * 50000) + "\n") == "GOOD", "maximum length alternating pattern"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`a`|`GOOD`| 可能な最小の長さ |
 |`yyy`|`BAD`| 正しい治療法`y`母音として |
 |`bcdf`|`BAD`| 長い子音ランの検出 |

 ## 特殊なケース

 次の入力を考えてみましょう。```
ab
```アルゴリズムの処理`a`、 それから`b`。 カウンターは、`(1, 0)`その後`(0, 1)`。 どちらも 3 に達しないため、出力は次のようになります。`GOOD`。 アルゴリズムでは文字列に少なくとも 3 文字があるとは想定されていないため、境界の問題は発生しません。 

ここで次のことを考えてみましょう。```
ababa
```カウンタは、スキャン中に 1 つの母音と 1 つの子音の間で交互に表示されます。 タイプが変更されるたびに反対側のカウンターがリセットされるため、どちらの実行も 1 を超えることはありません。 出力は正しく行われています`GOOD`。 

入力の場合:```
aaab
```母音カウンターは次のように進化します。`1`、`2`、`3`。 3 に達すると、アルゴリズムはすぐに出力します。`BAD`残りの文字をスキャンせずに。 これにより、禁止されたプレフィックスが正しく検出されます。 

最後に、次のことを考慮してください。```
yyy
```以来`y`母音セットに属している場合、母音カウンターは次のようになります。`1`、`2`、`3`、アルゴリズムの出力`BAD`。 This matches the problem's definition of vowels and avoids the common mistake of treating`y`子音として。
