 ## 解決策
 ## 問題の理解

 ボタンを押す順序は固定されており、それを順番に押す必要があります。 それぞれの押下は 3 つのボタンのいずれかに属し、押された瞬間に対応するダイヤルに特定の値が表示される必要があります。 すべてのダイヤルは値 1 から始まります。 

順序はすでに決まっているため、目的はどのボタンを押すかを選択することではありません。 唯一の決定は、次のボタンを押すまでの準備に何秒を費やすかです。 ボタンが押されていない場合、各ダイヤルは 1 秒間に最大 1 つ移動でき、ボタンが 1 回だけ押される可能性があります。 課題は、最後に必要なプレスが完了する最も早い秒数を見つけることです。 

入力には、必要なプレスが最大 1000 回含まれます。 このサイズでは、状態の数が 1 秒の制限で処理できる範囲をはるかに超えて増加するため、3 つのダイヤル値のすべての可能な組み合わせなど、大きな状態空間にわたるシミュレーションは除外されます。 ソリューションでは、O(n) アルゴリズムを使用して、各押下を一定の回数だけ処理する必要があります。 

ダイヤルの値も 1000 で制限されますが、重要な点は、考えられるすべてのダイヤル位置を保存する必要がないということです。 同じボタンを 2 回押すまでにどれくらいの時間が経過するかを理解することだけが必要です。 

よくある間違いは、すべてのダイヤルを毎秒調整できると考えることです。 その秒間にボタンが押されたダイヤルについては、これは誤りです。 たとえば、入力が次の場合:```
2
1 5
1 1
```答えは 9 です。最初の押しには 4 秒の移動が必要で、2 番目の 5 で起こります。2 回目のダイヤル変更には 5 から 1 への移動が必要で、さらに 4 秒かかり、その後 2 回目の押しが起こります。 不用意な解決策は、プレス自体にも 1 秒かかることを忘れて、8 と答える可能性があります。 

もう 1 つの特殊なケースは、最初に押す前にいくつかの異なるボタンの準備が必要な場合です。 例えば：```
3
1 2
2 2
3 3
```答えは 4 です。最初の 1 秒間は 3 つのダイヤルすべてを動かすことができますが、3 つのボタンを押すにはやはり 3 秒かかります。 ダイヤルの動きと押すことを完全に別個の段階として扱う解決策は、答えを過大評価してしまいます。 

最後のトリッキーなケースは、同じボタンを隙間なく繰り返し押すことです。 例えば：```
2
1 3
1 4
```答えは 4 です。最初の押しは、1 から 3 に移動した後、2 番目の 3 で行われます。その押しの間、ダイヤルは変更できないため、次の押しの前に 4 に移動するにはさらに 1 秒かかります。 答えは3ではありません。 

## アプローチ

 直接的な総当たりアプローチは、考えられるすべてのアクションを毎秒シミュレートすることです。 それぞれの瞬間において、ダイヤルの動きと次のボタンの押し方のあらゆる組み合わせを試すことができました。 考えられるすべてのスケジュールを検討するため、これは正しいと考えられますが、分岐要素は膨大です。 文字盤は 3 つしかありませんが、1 秒ごとにさまざまな動きの組み合わせがあり、秒数は数千に達することがあります。 考えられる履歴の数が急激に増加するため、このアプローチは使用できなくなります。 

重要な観察は、任意の瞬間後の実際のダイヤル値は問題ではないということです。 ダイヤルには、ボタンを押した瞬間にのみ制限があります。 同じボタンを 2 回押す間、そのダイヤルには、移動可能な 2 回押した秒を除くすべての秒が表示されます。 

同じボタンが何度も押されたとします。`a`そして`b`、その必要な値は次のとおりです。`x`そして`y`。 これらの印刷機の間には、`b - a - 1`ダイヤルが移動できる秒数。 少なくとも必要です`abs(x - y)`数秒間の移動なので、条件は次のようになります。```
b - a - 1 >= abs(x - y)
```これは次のように書き換えることができます。```
b >= a + abs(x - y) + 1
```これにより、押すたびに直接の下限が決まります。 同じ考え方が、時間 0 で値 1 の仮想的な押下があったとみなして、最初にボタンが発生した場合にも機能します。 

最も早い有効なスケジュールを貪欲に構築できます。 押下を処理するとき、同じボタンの前回の発生について知る必要があるのは 2 つのことだけです。それがいつ発生したか、およびそれに必要な値は何かです。 現在の印刷機は、以前のグローバル印刷機の後に来て、独自のダイヤルに十分な移動時間を与えるために、十分に遅くなければなりません。

 ## アルゴリズムのチュートリアル

 1. 最後に処理された印刷機の時間を記録します。 2 つのボタンを同時に押すことはできないため、次の操作は少なくとも 1 秒後に行われる必要があります。 
2. 3 つのボタンのそれぞれについて、前回押した時間と必要な値を覚えておきます。 最初に、すべてのボタンを、時刻 0 にダイヤル値 1 で押されたかのように扱います。これは、初期ダイヤル設定を表します。 
3. 必要なプレスを順番に処理します。 現在のボタンとターゲット値については、前回の全体的な押下と、この同じボタンの前回の押下に基づいて、可能な限り最も早い時間を計算します。 時間は次の両方の制限を満たす必要があります。 

1. 前回のプレスの後である必要があります。 
2. ダイヤルには、以前の必要な値から新しい必要な値に移動するのに十分な秒数が必要です。 
4. これら 2 つの制限のうち大きい方を実際のプレス時間として選択します。 この時間を修正した後、このボタンの保存情報を更新します。 
5. すべてのプレスが処理された後、最後のプレスの時間がロック解除の最小時間となります。 

機能する理由: 押す操作を遅らせることができるのは、その直前に別の押す操作が発生するか、必要なダイヤルを所定の位置に移動する必要がある場合だけです。 貪欲な選択では、常にこれら 2 つの条件が許す最も早い時点ですべての印刷機が配置されます。 前のボタンを押すのを遅らせても、後のボタンを押すまでの時間が短くなるだけなので、何の解決にもなりません。 あらゆる制限が維持されるため、最終的なスケジュールは実行可能であり、すべてのプレスができるだけ早く行われるため、最終的な時間は最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    last_time = [0, 0, 0]
    last_value = [1, 1, 1]

    current_time = 0

    for _ in range(n):
        button, value = map(int, input().split())
        button -= 1

        current_time = max(
            current_time + 1,
            last_time[button] + abs(value - last_value[button]) + 1
        )

        last_time[button] = current_time
        last_value[button] = value

    print(current_time)

if __name__ == "__main__":
    solve()
```配列`last_time`そして`last_value`各ボタンの仮想的な前回の押下情報を保存します。 時間をかけて始める`0`そして価値観`1`同じ式で、特別な場合を除いて最初の実際のプレスを処理できます。 

変数`current_time`は、最後にスケジュールされたプレスの時間を表します。 押すたびに一意の秒が占有されるため、次のボタンを押す前に 1 ずつ増加します。 

の第 2 部`max`式は、現在のボタンの移動要件です。 前回このボタンが押されたのが次の場合`last_time[button]`、その後、ダイヤルには、その押した後、現在押して移動するまでの正確な秒数がありました。 追加の`+1`現在のプレス秒数自体が考慮されます。 

ダイヤルシミュレーションは必要ありません。 このアルゴリズムは、今後のプレスを遅らせる可能性のある制約のみを追跡するため、アルゴリズムはメモリ内で一定のままになります。

 ## 特殊なケース

 最初のエッジケースの場合:```
2
1 5
1 1
```アルゴリズムは仮想情報を持つボタン 1 から始まります`(time = 0, value = 1)`。 最初のプレスには時間がかかります`5`1 から 5 に移動するには 4 秒かかり、プレスは 5 秒目を占有するからです。 2 回目のプレスは少なくとも`5 + |5 - 1| + 1 = 10`, したがって、答えは10になります。 

2 番目のエッジケースの場合:```
3
1 2
2 2
3 3
```各ボタンはこれまで押されたことがないため、仮想的な前の値はすべて 1 です。必要な回数は 2、3、4 です。アルゴリズムでは、特定のボタンが押されたときのみ制限をカウントするため、動きの最初の 1 秒ですべてのダイヤルを準備できるようになります。 

3 番目のエッジケースの場合:```
2
1 3
1 4
```ボタン 1 の 2 回目の押下は、ボタン 1 の最初の押下に依存します。保存されている前回の値は 3 で、保存されている前回の時間は 3 です。次に押すには、次のボタンが必要です。`3 + |4 - 3| + 1 = 5`? 世界的な報道規制により、`3 + 1 = 4`なので、大きい方の値は 5 です。スケジュールは、3 秒目に押す、4 秒目に移動、5 秒目に押すというものです。正しい出力は 5 で、同じボタンを押す間の 2 秒目の移動をカウントする必要がある理由を示しています。
