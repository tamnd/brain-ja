 ## 解決策
 ## 問題の理解

 桜の木のコレクションを取り揃えております。 それぞれの木は 3 つの数字で表されます。つまり、咲き始めた日、新しい花が追加される最後の日、そして 1 日の変化で花が現れる数または消える数です。 

パラメータを持つツリーの場合`a`、`b`、 そして`k`、前日までに花の数はゼロです`a`。 当日`a`それは持っています`k`花、そして毎朝から日中まで`b`それは別のものを得る`k`花。 その日の夕方以降`b`、木は負けます`k`毎日花が空になるまで花を咲かせます。 タスクは、すべての木の花の総数が最大に達する最も早い日を見つけることです。 

入力には最大で次のものが含まれます`10^5`木々、そして日数と花の数は次のように大きくなる可能性があります。`10^9`。 日数の範囲は前後する可能性があるため、これにより、考えられるすべての日を反復することは直ちに除外されます。`10^9`、木の数も多いです。 ソリューションは、毎日ではなく機能の重要な変更を処理する必要があります。 アン`O(N log N)`解決策は適切です。`3N`イベントが快適にフィット`N = 10^5`。 

いくつかの境界ケースは誤って処理されやすいものです。 開花期間が 1 日しかない木でも、正しく処理する必要があります。 

例えば：```
1
5 5 10
```答えは次のとおりです。```
5
```この木には5日目に10個の花が咲きましたが、その後は0個になりました。 成長間隔を空として扱うソリューションは、次の理由によります。`a == b`ピークを逃す可能性があります。 

もう 1 つの注意が必要なケースは、最後の開花日の後の正確な推移です。 

例えば：```
1
3 4 7
```花の数は、3 日目は 7 個、4 日目は 14 個、5 日目は 7 個です。答えは次のとおりです。```
4
```日を追うごとに減り始める軽率な実施`b`翌日の代わりに`b`最大値を誤って移動してしまう可能性があります。 

絆も重要です。 必要な答えは、花の数が最も多い初日です。 

例えば：```
2
1 1 5
3 3 5
```合計は 1 日目に 5 に達し、3 日目にも再び増加するため、答えは次のようになります。```
1
```同じ値で答えを更新すると、間違った日が返されます。 

## アプローチ

 簡単なアプローチは、毎日庭をシミュレーションすることです。 毎日、すべての木の寄与を計算し、これまでに確認された最高の合計を維持することができます。 これは、関心のある関数を直接評価するため、正しいです。 しかし、それは遅すぎます。 可能な最大の日の値が近くにあります`10^9`したがって、毎日アクセスするだけでもすでに数十億回の反復が必要になります。 それに掛けると`10^5`木が存在すると、利用可能な制限をはるかに超える最悪のケースが発生します。 

重要な点は、毎日の花の数を個別に計算する必要はないということです。 木は非常に規則的に変化します。つまり、しばらくの間一定量だけ増加し、その後同じ一定量だけ減少します。 花の数自体を保存する代わりに、ある日から翌日までの合計の変化量を保存できます。 

単一の木については、次のようにします。`D(day)`前日から今日までの花の変化です。 木が貢献する`+k`この日との違いに`a`一日中`b`、毎朝花の数が増えていくからです。 それなら貢献するよ`-k`その日から`b + 1`一日中`2b - a + 1`、花が消えていくからです。 それ以降は貢献度はゼロになります。 

これにより、すべてのツリーが、現在の日次差異を変更する 3 つのイベントに変換されます。```
day a:       increase daily change by k
day b + 1:   decrease daily change by 2k
day 2b-a+2:  increase daily change by k
```すべてのイベントを収集したら、順番にスイープします。 2 つのイベント日の間では、日次差は一定のままであるため、花の総数は差に間隔の長さを乗算することで更新できます。 これにより、可能な数十億日が 1 つに圧縮されます。`3N`意味のあるポジション。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(最大日 × N) | お(1) | 遅すぎる |
 | 最適 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各キーが日であり、値がその日の日差に適用される変更であるイベント マップを作成します。 それぞれの木に`(a, b, k)`、 追加`+k`で`a`、`-2k`で`b + 1`、 そして`+k`で`2b - a + 2`。 これら 3 つのイベントは、花数の傾きがいつ変化するかを正確に表しています。 
2. すべてのイベント日を並べ替えます。 現在の日差を変更できるのはこれらの日のみであるため、1 日おきは、動作が予測可能な間隔に属します。 
3. 次の処理日までの花の現在の数と現在の日次差の 2 つの値を維持しながら、並べ替えられたイベント日をスイープします。 イベント日を処理する前に`x`、前の位置からのギャップを飛び越えて、`x - 1`追加することで`daily_difference * gap_length`。 
4. 当日イベントを適用する`x`日次差を更新し、新しい差を使用して 1 日進めます。 結果の値はその日の花の数です`x`, したがって、これまでに見つかった最良の回答と比較してください。 
5. 花の数が厳密に大きくなった場合にのみ、回答を更新します。 最初の出現を維持すると、最大値が等しい日が自動的に処理されます。 

なぜ効果があるのか:

 スイープでは、すべてのイベント境界で花の合計数の正確な値が維持されます。 連続する 2 つのイベント日の間では、成長率が変化する木はないため、合計は一定の日差で直線的に変化します。 イベント表現は、ちょうど一部のツリーが動作を切り替える日にその差を変更します。 整数日にわたる区分線形シーケンスの考えられるすべての最大値は、間隔の境界または一定方向の間隔の開始時に発生する必要があるため、これらの圧縮された位置をチェックすることで、真の最も早い最大日が見つかります。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    n = int(input())
    events = defaultdict(int)

    for _ in range(n):
        a, b, k = map(int, input().split())
        events[a] += k
        events[b + 1] -= 2 * k
        events[2 * b - a + 2] += k

    days = sorted(events)

    current_change = 0
    flowers = 0
    position = 1

    best_flowers = 0
    answer = 1

    for day in days:
        flowers += current_change * (day - position)

        current_change += events[day]

        flowers += current_change

        if flowers > best_flowers:
            best_flowers = flowers
            answer = day

        position = day + 1

    print(answer)

if __name__ == "__main__":
    solve()
```最初のループのイベント構築が核となる変換です。 最初のイベントはツリーの増加部分を開始します。 2 番目のイベントは、前の増加を削除して減少を開始します。これにより、日次差が次のように変化します。`-2k`。 3 番目のイベントは、ツリーが空になった後の減少をキャンセルします。 

スイープは維持します`current_change`ある日から次の日に移動するときの花の合計の変化として。 変数`flowers`現在処理されている位置に合計を保存します。 新しいイベント日に到達する前に、同じ差異がその間隔全体に適用されるため、コードはすべての中間日を一度にスキップします。 

ループ内の順序は重要です。 イベントはその日にアクティブになる違いを記述するため、イベントはイベント日の花を追加する前に適用する必要があります。 1 日後に適用すると、すべての境界で 1 つずつずれたエラーが発生します。 

Python の整数は任意の精度で自動的に使用されるため、最終的な答えが 64 ビットに収まることが保証されている場合でも、オーバーフローが回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log N) | ツリーごとにちょうど 3 つのイベントがあり、イベント日の分類が作業の大半を占めます。 |
 | スペース | O(N) | イベント マップには、ツリーごとに最大 3 つのエントリが保存されます。 |

 ## 特殊なケース

 一日開花の場合:```
1
5 5 10
```イベント日は5日、6日、7日です。5日目は日替わりが変わります。`10`、10個の花を与えます。 6日目の日次変化は次のようになります。`-10`、合計がゼロになります。 アルゴリズムは次に進む前に 5 日目をチェックするため、正しく 5 が返されます。 

最後の成長日の後の境界の場合:```
1
3 4 7
```イベントは次のとおりです。```
3: +7
5: -14
7: +7
```3日目には7個の花が咲き、4日目には14個の花が咲き、5日目には減少が始まります。 アルゴリズムが適用するのは、`-14`イベントは 4 日目ではなく 5 日目に行われ、4 日目の正しい最大値が維持されます。 

最大値が等しい場合:```
2
1 1 5
3 3 5
```スイープは 1 日目に 5 つの花に達し、それを最良の結果として保存します。 同じ花の数で 3 日目に達すると、厳密な比較により、以前の答えを置き換えることができなくなります。 

非常に大きな座標の場合:```
1
1000000000 1000000000 1000000000
```アルゴリズムは、大きい日の値の周囲に 3 つのイベントのみを作成します。 開花前の 10 億日間をループすることはありません。これが、イベント スイープが制約に適合する主な理由です。
