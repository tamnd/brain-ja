 ## 解決策
 ## 問題の理解

 N by N ボードがあります。 すべてのセルは 3 つのカテゴリのいずれかに属します。 マークされたセル`h`現在の駒を騎士に変え、セルにマークを付けます`p`それを問題の移動ルールに従って移動できる特別なポーンに変え、セルにマークを付けます`x`全く入力できません。 1 つの有効なセルから開始し、可能な限り少ない移動で別の有効なセルに到達する必要があります。 

重要な詳細は、駒のタイプは、駒が現在存在するセルによって決定されるということです。 移動オプションは旅全体で固定されていないため、同じマス目に到着してナイトに変身したか、ポーンに変身したかに応じて、異なる動きをする可能性があります。 答えは、目的地に到達するために必要な最短移動回数、または`-1`一連の法的措置が存在しない場合。 

ボードのサイズは最大 100 x 100 であるため、使用可能なポジションは最大 10000 個です。 これは、セル数が線形または線形に近いグラフ アルゴリズムには十分小さいです。 パスの数は指数関数的に増加する可能性があるため、考えられるすべてのパスを試行するソリューションは不可能です。 すべてのセルのペアを繰り返し探索する方法でも、すでに 1 億回の操作に近づき、移動シミュレーションの余地はあまり残されていません。 

実装上の主な落とし穴は、セルをその座標だけで扱うことにあります。 同じ座標が常に同じグラフ状態であるとは限りません。`h`セルに到着`p`細胞はさまざまな未来の可能性を創造します。 

例えば：```
1
h
1 1
1 1
```正しい答えは、`0`。 目的地を確認する前に少なくとも 1 つの移動を強制するソリューションは失敗します。 

別のケースは次のとおりです。```
2
hp
xx
1 1
1 2
```正しい答えは、`1`騎士は最初のセルから 2 番目のセルに移動できるからです。 駒の種類を変更した後でのみ目的地を確認したり、すべての駒が同じ手を共有すると仮定したりする不用意な解決策は、誤った結果を生み出す可能性があります。 

3 番目のケースは次のとおりです。```
3
xxx
xpx
xxx
2 2
2 2
```正しい答えは、`0`。 開始セルは孤立している可能性がありますが、すでに目的地であるセルに到達するには移動する必要はありません。 

## アプローチ

 直接的な総当たりアプローチは、考えられるすべての動作シーケンスを検索することです。 現在のセルから、すべての正当な手を試し、再帰的に続行し、最短の成功ルートを維持します。 考えられるすべてのパスが考慮されるため、これは正しいです。 問題はパスの数です。 到達可能なセルが多数あるボードでは、検索ツリーが繰り返し分岐し、探索される状態の数が膨大になる可能性があります。 

最初の改善点は、これが重み付けされていないグラフ上の最短経路の問題であることを認識することです。 考えられるそれぞれの状況はグラフの頂点として扱うことができ、すべての正当な手はコスト 1 のエッジになります。 

微妙な部分は、グラフの状態を正しく定義することです。 状態は単なる座標ではありません。 そこで活躍中のピースタイプと合わせたコーディネートです。 ただし、到達可能なブロックされていないセルはすべて駒のタイプを即座に決定するため、単純に座標を保存し、そのセル上のキャラクターから手を生成することができます。 各セルには、出力エッジの固定セットが 1 つあります。 

すべてのエッジのコストは同じであるため、幅優先検索では距離の増加順に状態を探索します。 BFS が初めてターゲット セルに到達するとき、その距離は最小になります。 ボードには 10,000 個のセルしかなく、各セルには一定の数の可能な移動があるため、全体の検索は簡単に十分に高速になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 到達可能なセル数の指数関数 | O(N²) 再帰状態 | 遅すぎる |
 | 最適 | O(N²) | O(N²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初のセルから幅優先検索を開始します。 すべてのセルまでの距離を保存します。`-1`セルがまだ訪問されていないことを意味します。 開始セルは距離を受け取ります`0`そこにとどまるために移動する必要がないからです。 
2. BFS キューからセルを削除し、そのタイプを検査します。 そうであれば`h`、すべてのナイトの動きを生成します。 そうであれば`p`、すべての特別なポーンの動きを生成します。 移動ルールは現在のセルにのみ依存するため、考えられるすべての次の状態を知るにはこれで十分です。 
3. 生成されたすべての位置について、それがボード内にあり、ブロックされていないことを確認します。 訪問されていない場合は、現在の距離に 1 を加えた値を割り当ててキューに入れます。 
4. キューが空になるか、目的地に到着するまで続行します。 目的地が距離を受信した場合は、それを印刷します。 それ以外の場合は、印刷します`-1`。 

なぜ効果があるのか:

 BFS は、セルがキューから削除されるとき、保存される距離は開始点からそのセルまでの最短パスの長さであるという不変条件を維持します。 すべてのエッジは 1 つの動きを正確に表すため、BFS は長さのすべてのパスを処理します。`k`ある程度の長さのパスの前に`k + 1`。 セルは最初にセルに到達したときに訪問済みとしてマークされるため、その後同じセルへのパスが長くなっても応答を改善することはできません。 したがって、目的地までの最短距離が得られます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())
    board = [input().strip() for _ in range(n)]

    sr, sc = map(int, input().split())
    tr, tc = map(int, input().split())

    sr -= 1
    sc -= 1
    tr -= 1
    tc -= 1

    dist = [[-1] * n for _ in range(n)]
    dist[sr][sc] = 0

    knight_moves = [
        (-2, -1), (-2, 1), (-1, -2), (-1, 2),
        (1, -2), (1, 2), (2, -1), (2, 1)
    ]

    pawn_moves = [
        (-1, 0), (1, 0), (0, -1), (0, 1)
    ]

    q = deque([(sr, sc)])

    while q:
        r, c = q.popleft()

        if r == tr and c == tc:
            print(dist[r][c])
            return

        moves = knight_moves if board[r][c] == 'h' else pawn_moves

        for dr, dc in moves:
            nr = r + dr
            nc = c + dc

            if 0 <= nr < n and 0 <= nc < n:
                if board[nr][nc] != 'x' and dist[nr][nc] == -1:
                    dist[nr][nc] = dist[r][c] + 1
                    q.append((nr, nc))

    print(-1)

if __name__ == "__main__":
    solve()
```ボードは指定されたとおりに保存されるため、現在のセルのタイプをチェックすると、利用可能な手がすぐにわかります。 距離配列は、訪問済みマーカーと回答ストレージの両方として機能し、2 番目の構造を回避します。 

ピースの変換はボード キャラクターによってすでにエンコードされているため、キューには座標のみが含まれます。 座標が削除されると、コードは近傍を探索する前に正しい移動リストを選択します。 

境界チェックはボードにアクセスする前に行われます。 これにより、無効なインデックスが有効なセルとして解釈されるのを防ぎます。 宛先チェックはキューからポップするときに行われます。これは、BFS によってすでに最短距離であることが保証されているため安全です。

## テストケース```python
import sys
import io
from collections import deque

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)

    n = int(input())
    board = [input().strip() for _ in range(n)]
    sr, sc = map(int, input().split())
    tr, tc = map(int, input().split())

    sr -= 1
    sc -= 1
    tr -= 1
    tc -= 1

    dist = [[-1] * n for _ in range(n)]
    dist[sr][sc] = 0
    q = deque([(sr, sc)])

    knight = [(-2,-1),(-2,1),(-1,-2),(-1,2),
              (1,-2),(1,2),(2,-1),(2,1)]
    pawn = [(-1,0),(1,0),(0,-1),(0,1)]

    ans = -1
    while q:
        r, c = q.popleft()
        if (r, c) == (tr, tc):
            ans = dist[r][c]
            break
        for dr, dc in (knight if board[r][c] == 'h' else pawn):
            nr, nc = r + dr, c + dc
            if 0 <= nr < n and 0 <= nc < n:
                if board[nr][nc] != 'x' and dist[nr][nc] == -1:
                    dist[nr][nc] = dist[r][c] + 1
                    q.append((nr, nc))

    sys.stdin = old
    return str(ans) + "\n"

 ## 特殊なケース

 最初のエッジケースの場合:```
1
h
1 1
1 1
```BFS は、宛先がすでにキューに入っている状態で開始されます。 最初に削除された状態の距離はゼロであるため、アルゴリズムはすぐに戻ります。`0`。 

2 番目のエッジケースの場合:```
2
hp
xx
1 1
1 2
```開始セルは`h`セルなので、BFS はナイトの動きを生成します。 ターゲットセルは 1 回の移動で到達可能であり、距離を受け取ります`1`。 あらゆる場所でポーンの移動を使用するソリューションでは、失敗が誤って報告されます。 

3 番目のエッジケースの場合:```
3
xxx
xpx
xxx
2 2
2 2
```中央のセルは孤立していますが、目的地でもあります。 BFS を離れる必要はありません。 保存された初期距離はそのまま残ります`0`、これが正解です。
