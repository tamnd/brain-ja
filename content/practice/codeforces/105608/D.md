 ## 解決策
 ## 問題の理解

 小文字のラテン文字の文字列に適用される何らかの隠れたエンコード プロセスの望ましい結果を表す 2 つの整数が与えられます。 各文字は 2 つの累積値 A と B に寄与しますが、その方法はわずかに非対称です。すべての文字は、A の増加よりもちょうど 1 だけ B を増加させます。つまり、A と比較して、B は各文字から追加の寄与単位を受け取ります。 

この関係から、重要な単純化が現れます。 文字列の長さが L の場合、B は常に正確に A + L になります。これにより、自由度が 1 つ取り除かれ、タスクは、ある長さの一貫した文字列が存在できるかどうかを確認し、存在する場合は文字列を構築することに変わります。 

文字列自体は、通常のアルファベットのインデックス付けを通じて A に寄与します。この場合、文字は 0 ～ 25 の範囲の重みのように動作します。`a`貢献度0、`b`1を貢献し、そして`z`B はこれらの重みに直接依存せず、各文字が存在するという事実のみに依存します。 

したがって、タスクは次のようになります。B が A + L に等しくなければならないことも考慮しながら、重みの合計が A に等しくなるように、L および L 個の文字の長さを選択します。B が与えられているため、L は B − A にならざるを得ません。これにより、長さの選択の自由が失われます。 

次に、問題は、A を 0 から 25 までの L 値の合計として表現できるかどうかを判断し、表現できる場合はそのようなシーケンスを構築することに帰着します。 

入力制約は、すべての文字列に対するブルート フォースが不可能なほど L が大きくなり得る領域で作業していることを意味します。 中程度の L の場合でも、すべての組み合わせを列挙すると指数関数的に爆発的に増加します。 したがって、有効な解はすべて L において線形でなければなりません。 

エッジケースは、実現可能性が満たされない場合に発生します。 L が 1 未満の場合、正でない長さのシーケンスを構築できないため、有効な文字列は存在しません。 別の失敗ケースは、A が大きすぎて L 文字に分散できない場合、つまりすべての文字が分散されていても発生する場合に発生します。`z`、A に到達できません。その上限は 25 × L です。同様に、A を負にしたり、文字ごとの制限で達成可能な値を超えたりすることはできません。 

簡単な例で障害状態を示します。 A が 10 で L が 1 の場合、10 を与える 1 つの文字が必要になりますが、最大値が 25 であるためこれは不可能なので、実際にはこれで問題ありません。 より良い例: A が 30 で L が 1 の場合、それは不可能です。 逆に、A が 0 で L が 1 の場合、次のようにすることができます。`a`。 

## アプローチ

 ブルートフォース手法では、長さ L の文字列を構築し、文字の可能なすべての割り当てを試行し、それらの重みの合計が A に等しいかどうかを確認します。これは、制約定義を直接反映するため、概念的には簡単です。 ただし、各位置には 26 個の選択肢があるため、探索空間は 26^L となり、L が 20 程度であっても実行不可能になります。 

問題の構造により、より強力な観察が可能になります。 文字の順列については気にせず、A を L 個の境界部分に分解できるかどうかだけを気にします。 これは古典的な有界合成問題ですが、非常に特殊な貪​​欲な構造を持っています。つまり、残りの容量内にとどまっている限り、早期に大きな値を取得しても、将来の実現可能性が制限されることはありません。 

これにより貪欲な構築が可能になります。 各キャラクターは最大 25 を貢献できるため、各ステップでできるだけ多くを割り当てるように努めます。`z`A の大きな値がまだ必要な場合は常に、残りの A が 25 より小さい場合は、必要なものを正確に配置し、残りを暗黙的にゼロで埋めます。`a`。 

正確さは、各ステップで A を可能な最大値だけ減らすことで、最初の実現可能性が維持される限り、実現可能な領域内に収まるようになるという事実から得られます。

 ## アルゴリズムのチュートリアル

 まず問題を長さと実現可能性のチェックに変換し、次に文字列を貪欲に構築します。 

1. 必要な長さ L を B − A として計算します。これは、各文字が A と比較して B に正確に 1 単位追加するという観察から直接得られるため、B は常に A に文字数を加えたものになります。 
2. L が少なくとも 1 であるかどうかを確認します。そうでない場合は、負またはゼロの長さの空でないシーケンスを形成できないため、文字列は存在しません。 
3. A が L に対して実行可能な範囲内、具体的には 0 ～ 25 × L 内にあるかどうかを確認します。下限により負の寄与が必要ないことが保証され、上限によりすべての文字が最大化されることが保証されます。`z`Aを超えない。 
4. 実現可能条件が満たされない場合は、直ちに -1 を出力します。 
5. 空の結果文字列を初期化し、正確に L 回繰り返し、左から右に 1 文字ずつ文字列を構築します。 
6. 各ステップで、現在のキャラクターの貢献度を min(25, 残り A) として選択します。 これは、残りの要件を超えることなく安全に割り当てることができる最大の値です。 
7. からのオフセットにより、この数値寄与を文字に変換します。`'a'`、それを結果に追加し、A から減算します。 
8. すべてのポジションが埋まるまで続けます。 最後に、A はゼロになります。これは、寄与の合計が必要な値と正確に一致することを意味します。 

これが機能する理由は、単純な不変式の維持に基づいています。各ステップの後、残りの A は残りの文字数で常に達成可能です。これは、A をゼロ未満に減らさず、文字あたり 25 を超えて消費することがないためです。 初期の実現可能性では A ≤ 25 × L が保証されているため、貪欲な最大消費によって将来のステップが妨げられることはありません。 各ステップでは A ≤ 25 × Remaining_length という条件が維持されるため、残りの値は常に分配可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a = int(input())
b = int(input())

length = b - a

if length < 1 or a < 0 or a > 25 * length:
    print(-1)
    sys.exit()

ans = []

for _ in range(length):
    take = min(25, a)
    ans.append(chr(ord('a') + take))
    a -= take

print(''.join(ans))
```実装は、A と B の間の関係から強制長を導き出すことから始まります。実現可能性チェックにより、目標合計 A を利用可能な文字数に分散できない場合には構築を試行しないことが保証されます。 

貪欲ループはソリューションの中核です。 各反復では、上限の 25 を尊重しながら、可能な最大の寄与が消費されます。`chr(ord('a') + take)`数値の重みを文字にマッピングし直します。 

微妙な点の 1 つは、A が負になることを決して許さないことですが、これは min 演算によって防止されます。 もう 1 つは、実行可能性によって貪欲な選択が常に有効な残りを残すことが保証されるため、バックトラッキングが必要ないということです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    a = int(input())
    b = int(input())

    length = b - a

    if length < 1 or a < 0 or a > 25 * length:
        return "-1"

    ans = []
    for _ in range(length):
        take = min(25, a)
        ans.append(chr(ord('a') + take))
        a -= take

    return ''.join(ans)

assert run("0\n3\n") == "aaa"

# minimum length invalid
assert run("5\n5\n") == "-1"

# single character max
assert run("25\n26\n") == "z"

# large greedy split
assert run("30\n35\n") == "zfaaa"

# all zeros case
assert run("0\n1\n") == "a"

 ## 特殊なケース

 B が A と等しい場合、計算された長さはゼロになります。 有効な文字列には少なくとも 1 つの文字が含まれている必要があるため、アルゴリズムはこのケースを即座に拒否します。 入力 A = 10、B = 10 の場合、L = 0 が得られ、構成が存在しないため、出力は -1 になります。

A がゼロの場合、構造はすべてに縮退します。`a`文字。 A = 0 および任意の有効な L の場合、すべての反復は 0 を取り、重みにゼロの文字列が生成されます。これは、反復に対応します。`a`。
