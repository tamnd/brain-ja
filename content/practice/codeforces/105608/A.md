 ## 解決策
 ## 問題の理解

 辺の長さが 3 つある長方形のチェストが与えられています。$X$、$Y$、 そして$Z$。 チェストは任意の方向に向けることができます。つまり、その側面のどのペアも、長方形のポータルを通過しようとする「ベース」になることができます。 ポータル自体には側面があります$A$そして$B$ただし、その方向も柔軟であるため、回転後に小さいものから小さいもの、および大きいものから大きいものの一致のみを考慮します。 

タスクは、次のいずれかを選択したときに、次のような胸の面が少なくとも 1 つ存在するかどうかを判断することです。$(X, Y, Z)$、その長方形は、最適に回転するとポータルを通過できます。 フィッティングとは、小さい辺が一緒に比較され、大きい辺が一緒に比較されるように両方の長方形を並べ替えた後、選択した胸面の両方の寸法がポータルの対応する寸法を超えないことを意味します。 

入力は、胸部の 3 次元とポータルの 2 次元を表す 5 つの整数で構成されます。 出力は単一の単語で、胸部のいずれかの面がポータルを通過できる場合は「YES」、そうでない場合は「NO」です。 

胸の可能な面は 3 つだけであるため、計算は一定時間になります。 たとえ制約が大きかったとしても、解決策は自明なままであるため、複雑さのプレッシャーに対処する必要はありません。 固定された順序で側面を比較すると誤った結果が生じるため、方向を正しく処理することが唯一の潜在的な落とし穴になります。 

よくある間違いは、次のような 1 つのアライメントのみをチェックする場合に発生します。$X \le A$そして$Y \le B$。 ポータルが回転すると、これは失敗します。 たとえば、次の場合$X = 5$、$Y = 3$、$A = 4$、$B = 6$の場合、順序によっては直接比較が失敗する可能性がありますが、正しい向きのチェックは成功します。$(3, 5)$に適合する$(4, 6)$。 

もう 1 つの微妙な間違いは、3 つの面をそれぞれ個別にチェックする必要があることを忘れていることです。 ポータルの通過は、すべてではなく、少なくとも 1 つの有効なペアに依存します。 

## アプローチ

 ブルートフォースの見方は簡単です。 胸の各面を取り出します。$(X, Y)$、$(X, Z)$、 そして$(Y, Z)$それぞれについて、ポータルに対して可能な両方の向きを試します。 試行ごとに、回転した胸の面の両方の寸法が回転したポータル内に収まるかどうかを確認します。 各面には正確に 2 つの方向があるため、一定数のチェックが行われることになります。 

これが機能するのは、候補ペアが 3 つしかなく、各ペアの順列が 2 つだけであるため、合計作業量が 6 回の比較に固定されているためです。 ここではブルート フォースがすでに最小限に抑えられていますが、ブルート フォースの観点から考えることは、正確さを明確にするのに役立ちます。すべての幾何学的構成を明示的に列挙しています。 

重要な観察は、この列挙を超える最適化は必要ないということです。 問題の構造は完全に有界であり、離散的です。 唯一の要件は、方向が正しく処理されるように、並べ替えられたディメンションを比較することです。 両方の順列を手動でチェックする代わりに、ソートされたペアを単純に比較することができます。 

したがって、ブルート フォースから最適解への移行は、複雑さを軽減することではなく、各ペアを正規化することで比較を簡素化することです。

 ## アルゴリズムのチュートリアル

 1. チェストの 3 次元とポータルの 2 次元を読み取ります。 これらは 2D 空間で 2 つの長方形を定義し、複数の方向で比較します。 
2. 胸囲の寸法のペアごとに、候補となる長方形を形成します。 候補者は３名です$(X, Y)$、$(X, Z)$、 そして$(Y, Z)$。 それぞれは、ポータルを通過する可能性のある顔を表しています。 
3. 各候補ペアについて、小さい方の辺と小さい方の辺、大きい方の辺と大きい方の辺が常に一致するように、両方の長方形を概念的に並べ替えることによってポータルと比較します。 これにより、両方の回転を明示的に試行する必要がなくなります。 
4. いずれかの候補ペアが両方の比較を満たす場合、チェストはポータルを通過できると直ちに結論付けます。 有効な構成が見つかったら、残りのペアを確認する必要はありません。 
5. 3 つのペアのいずれも適合しない場合は、どの向きも通過できないと結論付けます。 

これが機能する理由: 軸に揃えられた別の長方形に長方形を挿入する有効な方法はすべて、各ペアの 2 つの可能な順序のいずれかに対応します。 胸部の面とポータル側の両方をソートされた順序に正規化することで、すべての可能な回転が 1 回の比較で表現されるようになります。 すべての幾何学的構成はこれらの離散的なケースに帰着するため、3 つの面すべてをチェックすることで探索空間全体を漏れなくカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x = int(input())
y = int(input())
z = int(input())
a = int(input())
b = int(input())

def fits(u, v, a, b):
    return (u <= a and v <= b) or (u <= b and v <= a)

ok = False
ok |= fits(x, y, a, b)
ok |= fits(x, z, a, b)
ok |= fits(y, z, a, b)

print("YES" if ok else "NO")
```このソリューションは、5 つの整数すべてを直接読み取ります。 ヘルパー関数を使用して、胸部エッジの各ペアがポータルの両方の方向に対してテストされます。 ヘルパーは、有効な構成を誤って見逃さないように、ローテーション ロジックをカプセル化します。 最終的な答えはブール値フラグを使用して蓄積されますが、ここではパフォーマンスは問題ではありませんが、論理的には短絡されます。 

よくある実装エラーは、2 番目の方向チェックを忘れることです。`(u <= b and v <= a)`これにより、有効な回転フィットが誤って拒否されてしまいます。

 ## 特殊なケース

 微妙なケースは、次のように 3 つの次元がすべて等しい場合です。$X = Y = Z = 3$とポータル$A = 2, B = 5$。 すべての面は同一であるため、アルゴリズムは同じ有効条件を繰り返しチェックします。 

ペア (3, 3) については、(2, 5) に対する両方の方向がテストされます。 

最初の方向チェック$3 \le 2$どちらが失敗するか、そして$3 \le 5$これは合格しますが、両方の次元が同じペアを一貫して満たす必要があるため、この方向は無効です。 2 番目の方向は同一であるため、同じ結果が得られます。 アルゴリズムは正しく「NO」を返します。 

もう 1 つのエッジ ケースは、1 つの寸法がポータルの側面と正確に等しい場合です。 例えば$X = 5, Y = 4, Z = 3$とポータル$A = 5, B = 4$。 ペア (5,4) の場合、両方の軸で等しいことが許可されるため、チェックはどちらの方向でもすぐに成功し、3 番目の次元を調べる必要なく「YES」が生成されます。
