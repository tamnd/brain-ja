 ## 問題の理解

 平面上に 2 つの円形のターゲットが与えられます。 各ターゲットは、その中心座標と半径によって定義されます。 これら 2 つの円から、0 から 3 までの 4 つの「スコア」のうちどれが達成可能かを判断するように求められます。各スコアは 2 つの円間の幾何学的関係に対応します。 

最初の円は、2 番目の円の中に完全に含まれていない場合、スコア 1 を与える可能性があります。 対称的に、2 番目の円は、最初の円の内側に完全に含まれていない場合、スコア 2 に寄与する可能性があります。 2 つの円が交差するか、互いに接触している場合、スコア 3 が得られます。 スコア 0 は定義上常に可能であるため、常に回答セットに含まれます。 

重要な量は、円の中心間の距離です。 このステートメントではユークリッド距離として定義されていますが、提供されているコードでは平方根の下の二乗距離が使用され、実際の距離が浮動小数点形式で効率的に計算されます。 

問題には複数の条件が関係しているように見えますが、出力は集合 {0, 1, 2, 3} のサブセットにすぎず、昇順に出力されます。 

制約は十分に小さいため、各テスト ケースは独立しており、一定時間で解決できます。 計算には数回の算術演算しか含まれないため、目的のソリューションはテスト ケースごとに O(1) で実行する必要があります。 

主なエッジケースは幾何学的境界条件から生じます。 正確に接している円は、不等式が厳密か非厳密かに応じて条件を簡単に反転できます。 もう 1 つの微妙なケースは、一方の円がもう一方の円の中に完全に収まっているにもかかわらず、その境界がちょうど 1 点で接触している場合に発生します。 このような構成では、包含条件と交差条件が相互作用するため、厳密な不等式が誤って使用されると、誤った実装が混乱する可能性があります。 

たとえば、円 1 が完全に円 2 の内側にある場合、スコア 1 は含めるべきではありません。 中心がオフセットされている場合、半径のみを比較するような単純なチェックは失敗します。 

## アプローチ

 検索する大規模な構造がないため、ここでは総当たりアプローチは実際には組み合わせ的ではありません。 代わりに、素朴なアイデアは、文字通りの方法で各条件を幾何学的に解釈することです。包含の場合は、1 つの円のすべての点が別の円の内側にあるかどうかを確認しようとし、交差の場合は、第一原理から導出された幾何公式を使用して重複領域について推論しようとします。 

このようなアプローチはすぐに不必要に複雑になり、間違いが発生しやすくなります。 連続ジオメトリでは、点ごとに包含をチェックすることは不可能であり、点を離散化することさえ無意味で非効率的です。 ジオメトリはサンプリングや列挙の必要性を置き換える閉形式の距離条件を提供するため、総当り解釈は失敗します。 

重要な洞察は、必要なすべての条件が中心と半径の間の距離のみを含む比較に帰着するということです。 その距離を計算すると、3 つの非自明なスコアのそれぞれが単純な不等式に対応します。 

円 1 が円 2 に含まれるかどうかは、円 1 の最も遠い点がまだ円 2 の内側にあるかどうかによって異なります。これは、中心間の距離と円 1 の半径を加えたものが円 2 の半径を超えているかどうかを確認することになります。同じロジックが逆の包含条件にも対称的に適用されます。 

交差は、半径の合計が少なくとも中心間の距離であるかどうかによって決まります。 これにより、適切な交差と接線の両方がキャプチャされます。 

したがって、問題全体は 3 つの独立した不等式を評価することに集約されます。

 ## アルゴリズムのチュートリアル

2 つの円の中心間のユークリッド距離を計算し、3 つの独立した幾何学的条件を評価します。 

1. 両方の円の座標と半径を読み取ります。 これにより、完全な幾何学的構成が定義されます。 
2. ユークリッドの公式を使用して中心間の距離を計算します。 この 1 つの値によって、円間のすべての空間関係が完全に決定されます。 
3. ジオメトリに関係なく常に回答セットが含まれるため、回答セットは 0 から開始します。 
4. 円 1 の距離に円 1 の半径を加えた値が円 2 の半径よりも大きいかどうかをテストして、円 1 が円 2 に完全に含まれていないことを確認します。真の場合、答えに 1 を含めます。 
5. 円 2 が円 1 に完全に含まれていないという対称条件を確認します。真の場合、答えに 2 を含めます。 
6. 中心間の距離が半径の合計以下であることを確認して、円が交差または接触しているかどうかを確認します。 true の場合、答えに 3 を含めてください。 
7. 収集されたすべての値を昇順に出力します。 

各条件の背後にある推論は純粋に幾何学的なものです。 封じ込めのために、一方の円のもう一方の中心に対して可能な限り遠い点を測定します。 交差については、中心間の距離と円が外側に広がる距離を比較します。 

### なぜ効果があるのか

 このアルゴリズムは、2 つの円間の関係は 2 つの半径と中心間の距離という 3 つの量によって完全に決定されるという事実に基づいています。 問題ステートメント内のすべての条件は、これらの値を含む直接不等式として書き直すことができます。 これらの不等式は必要かつ十分であるため、それらを個別に評価することによって有効なスコアを見逃したり、無効なスコアを含めたりすることはできません。 条件が独立しているため、チェック間に隠れた依存関係が存在しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x1, y1, r1 = map(int, input().split())
x2, y2, r2 = map(int, input().split())

dx = x1 - x2
dy = y1 - y2
d = (dx * dx + dy * dy) ** 0.5

ans = [0]

if r1 + d > r2:
    ans.append(1)

if r2 + d > r1:
    ans.append(2)

if d <= r1 + r2:
    ans.append(3)

print(*ans)
```実装は幾何学的な導出に直接従います。 距離の計算は、差の二乗と平方根を使用して行われ、目的のユークリッド計量と一致します。 各条件は個別にチェックされ、0 から開始してラベルの昇順で条件を評価するため、結果は自動的に昇順に追加されます。 

実装の微妙な詳細は、距離に浮動小数点演算を使用することです。 距離の二乗比較により浮動小数点精度の問題を回避できますが、問題の意図した解決策では平方根形式が使用されるため、これは一般的な制約の下では正しいままです。

 ## 特殊なケース

 重要なエッジ ケースは、円が正確に 1 点で接触する接線です。 たとえば、中心距離が r1 + r2 に等しい円は、依然として交差しているものとしてカウントされます。 条件 d ≤ r1 + r2 にはこのケースが正しく含まれており、アルゴリズムによりスコア 3 が追加されます。 

もう 1 つの微妙なケースは、両方の円の中心と半径が同じである完全な重なりです。 この状況では、各円は退化した意味でのみ他の円に完全に含まれますが、不等式 r + d > r は両方向で成立しないため、スコア 1 と 2 は除外されます。 同時に、距離がゼロ、つまり半径の合計以下であるため、交差は依然として成立します。 

3 番目のケースは、分離を伴う厳密な封じ込めです。この場合、1 つの円が別の円の中に完全に収まりますが、境界には触れません。 たとえば、(0,0) を中心とする半径 10 の大きな円と、(1,0) にある半径 1 の小さな円は d = 1 を生成します。条件 r1 + d > r2 は非対称を正しく検出し、交差部分を true としてマークしながら、適切なスコアのみが確実に含まれるようにします。
