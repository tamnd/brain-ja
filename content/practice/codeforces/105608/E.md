 ## 解決策
 ## 問題の理解

 0 と 1 のみで構成されるバイナリ文字列が与えられます。 1 つの操作では、隣接する文字のペアを取得し、XOR のようなルールを適用して、単純なローカル インタラクションに従ってそれらを 1 つの文字に圧縮します。 両方の文字が 1 の場合、消滅して 0 になります。 少なくとも 1 つが 0 の場合、0 は消滅し、もう 1 つの文字が生き残ります。 

このプロセスは、文字列全体が均一になるまで繰り返され、文字列が段階的に縮小されます。つまり、残りの文字がすべて 0 になるか、残りの文字がすべて 1 になります。 タスクは、これら 2 つの最終状態のいずれかに到達するために必要な操作の最小数を決定することです。 

重要な構造上の制約は、操作がローカルであり、隣接する要素をマージするため、コストは文字を個別にカウントすることではなく、隣接変換によって文字をどのようにペアにして削除できるかにかかっています。 

文字列の長さが最大約 10 万の場合、操作を段階的にシミュレートしようとするソリューションは失敗します。各操作で長さが 1 ずつ減りますが、決定には線形またはさらに悪い作業が必要になる可能性があり、最悪の場合は 2 次の動作が発生する可能性があります。 このため、カウントとリニア スキャンのみに依存するソリューションを探す必要があります。 

1 の数が奇数の場合、微妙なエッジケースが発生します。 その状況では、1 を削除する各操作で 1 がペアで消費されるため、1 をペアにしてすべての 1 を削除することは不可能になります。 たとえば、次のような文字列では`101`、周囲にゼロがどのように再配置されるかに関係なく、対になっていない 1 つが残らなければならないため、すべてゼロで終わる方法はありません。 常にすべてゼロにできると仮定する素朴な戦略は、ここでは失敗します。 

文字列がすでに均一である場合、別の例外的なケースが発生します。 すべてゼロの場合は、ゼロ操作が必要です。 すべて 1 で長さが偶数の場合でも、ペアリング ロジックが必要です。 奇数の場合は、すべてゼロのターゲットが直ちに除外されます。 

## アプローチ

 直接シミュレーションでは、文字列を繰り返しスキャンし、隣接するペアを選択し、XOR ルールを適用し、文字列を再構築し、均一性が達成されるまで続行しようとします。 これは、許可された操作に正確に従っているため、原則的には正しいです。 ただし、各操作では動的構造を更新し、有効なペアを再度スキャンする必要があるため、文字列が大きく、リダクションが頻繁に行われる場合、二次関数またはさらに悪い動作が発生します。 

重要な点は、このプロセスは実際には文字列の進化に関するものではなく、文字を最適に照合および削除する方法に関するものであるということです。 意味のあるターゲットは 2 つだけです。すべて 1 で終わるか、すべて 0 で終わるかです。両方を独立して評価できます。 

すべてのものを 1 つに変換するのは簡単です。 すべてのゼロは、少なくとも 1 つのゼロを含む隣接する要素と組み合わせることで削除でき、効果的に各ゼロを個別に削除できます。 これは、すべて 1 に到達するコストがちょうど 0 の数であることを意味します。 

すべてをゼロに変換すると、より構造化されます。 人は個別に消えることはできません。 相互作用する 2 つのみが 0 を生成するため、それらはペアで削除する必要があります。 これは、1 の数が奇数であれば、この目標は不可能であることを直ちに意味します。 

1 の数が偶数の場合、出現順に 1 をペアにするのが最適な戦略です。 1 のすべてのインデックスをリストし、1 番目と 2 番目、3 番目と 4 番目などをペアにします。 これらのゼロはプロセス中に「バイパス」または削除する必要があるため、各ペアはそれらの間にあるゼロの数に等しいコストを持ちます。 これらのギャップを合計すると総移動コストが得られ、各ペアは 2 つの 1 を消費するため、ペアリングによって寄与される操作の数は 1 の数の半分になります。 

ブルート フォースはローカル マージを明示的にシミュレートするため機能しますが、文字列が大きい場合は失敗します。 1 の相対的な位置のみが重要であるという観察により、線形スキャンとインデックスの単純な算術への削減が可能になります。

 ## アルゴリズムのチュートリアル

 1. 文字列にゼロが何個あるか数えます。 すべてのゼロは有効なローカル操作シーケンスを通じて独立して削除できるため、これにより、すべてを 1 に変換するコストが即座に発生します。 
2. 文字列を 1 回スキャンしながら、リスト内のすべての 1 のインデックスを収集します。 これ以降の推論はすべて、0 ではなく 1 の相対位置にのみ依存するため、これが必要になります。 
3. 1 の数が偶数である場合にのみ、0 に変換するコストを計算します。 奇数の場合は、すべての 1 をペアにすることは不可能なので、このブランチを完全にスキップしてください。 
4. 1 の数が偶数の場合は、インデックスのリストを取得し、連続する 1 を順番にペアにします。 各ペアについて、それらの間のゼロの数をインデックスの差から 1 を引いたものとして計算します。 
5. すべてのペアにわたるこれらのギャップ値を合計します。 これは、対を成すものをまとめて消滅させるために必要な追加の作業を表しています。 
6. 1 の各ペアは、まとめられた後、正確に 1 回の操作で削除されるため、この合計に 1 の数の半分を加算します。 
7. すべてを 1 に変えるコストとすべてを 0 に変えるコストの間の最小値を取ります。 

正確さは、最適な組み合わせが順序を維持する必要があるという事実に依存します。 交差するペアリングは距離が増加するだけでコストが増加するため、インデックス順に隣接するペアリングが最適です。

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    
    zeros = s.count('0')
    ones_positions = []
    
    for i, ch in enumerate(s):
        if ch == '1':
            ones_positions.append(i)
    
    ans = zeros
    
    if len(ones_positions) % 2 == 0:
        cost = 0
        for i in range(0, len(ones_positions), 2):
            cost += ones_positions[i+1] - ones_positions[i] - 1
        cost += len(ones_positions) // 2
        ans = min(ans, cost)
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず、単一の線形カウントを使用して、すべての文字を文字に変換するという自明なターゲットを計算します。 次に、1 つのパスで 1 の位置リストを構築します。 条件付きブロックにより、ゼロターゲット計算が有効な場合にのみ試行されることが保証されます。 

ペアリング ループは 2 つずつ増加し、それぞれが 1 つのペアに正確に参加することが保証されます。 引き算`ones_positions[i+1] - ones_positions[i] - 1`は、厳密にペアになった 0 の間の 0 のみを正確にカウントします。

## 特殊なケース

 次のような単一文字の文字列`0`はすでに有効な最終状態になっています。 このアルゴリズムではゼロは 1 としてカウントされますが、1 がないため、ペアリング コストがゼロの最小値が取得され、結果は正しくゼロになります。 

のような文字列の場合`111`、1の数が奇数であるため、ペアリング分岐はスキップされます。 すべてのゼロを 1 に変換するコストだけが残ります。これは、ゼロがないためゼロです。 したがって、単純なペアリング試行が実現可能性を誤って仮定したとしても、アルゴリズムは正しくゼロを返します。 

次のようなぎっしり詰まった文字列の場合`11110000`、それらは連続しているため、対になっているものの間のギャップはすべてゼロになります。 コストは純粋にペアの数に減少し、移動コストは絶対位置ではなくゼロによる分離のみに依存することが確認されます。
