 ## 解決策
 ## 問題の理解

 Polycarpus は、日次収益レポートをフォルダーに整理する必要があります。各フォルダーには連続した日が含まれます。 重要な制限は、上司がフォルダーごとに 2 日を超える損失を許容できないため、フォルダーに利益がマイナスの日を 3 日以上含めることはできないということです。 目標は、フォルダーの総数を最小限に抑え、フォルダーの数と各フォルダーのサイズの両方を順番に出力することです。 

入力は整数です`n`日数を表し、その後に毎日の利益を表す一連の整数が続きます。 出力は、フォルダーの最小数を表す整数と、各フォルダー内の日数を示すシーケンスです。 

と`n`100 までは、O(n²) がまだ実現可能であるため、このアルゴリズムでは適度なサイズのネストされたループを許容できることがわかります。 ただし、配列を順番にスキャンし、負の日数の単純なカウントを維持するだけでよいため、線形 O(n) アプローチを目指す必要があります。 

マイナスの日が連続して現れる場合、微妙な特殊なケースが発生します。 たとえば、次のシーケンスでは、`[1, -1, -2, -3, 4]`、3 つのマイナス日をすべて 1 つのフォルダーに含めることはできません。 負の数を追跡せずに累積フォルダー サイズのみを調べる単純な貪欲な場合、誤って 3 つすべてをまとめて配置し、無効なフォルダーが作成される可能性があります。 もう 1 つのエッジ ケースは、マイナスの日数が 3 日未満のシーケンスです。 位置に関係なく、すべて 1 つのフォルダーに収まります。 

## アプローチ

 ブルート フォース手法では、配列の可能なすべてのパーティションを連続セグメントに生成し、各パーティションの有効性をテストします。 各セグメントは、マイナスの日が最大 2 日含まれている場合に有効です。 と`n`100 まではパーティションの数が急激に増加するため、これは実行不可能になります。 

重要な洞察は、複雑なパーティショニングを考慮する必要がないということです。 唯一の制約は、フォルダーにマイナスの 3 日を含めることはできないということです。 配列を左から右にスキャンして、現在のフォルダー内のマイナスの日数を追跡できます。 翌日を追加すると 3 つのマイナスが発生する場合は常に、新しいフォルダーを開始します。 この貪欲なアプローチは、制約が絶対的な位置や合計ではなく、マイナスの日数のみに依存するため機能します。 負の数を 3 未満に保ちながら、可能な限り連続した日をグループ化することで、フォルダーの数を最小限に抑えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 負のカウントによる貪欲なスキャン | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のリストを初期化する`folders`各フォルダーのサイズを保存します。 セット`current_folder_size`そして`neg_count`ゼロに。 
2. 毎日の利益を反復処理する`a[i]`最初から最後まで。 
3. インクリメント`current_folder_size`現在の日を考慮して 1 ずつ加算します。 
4. もし`a[i]`負の場合は増分します`neg_count`。 
5. 日を含めた後、次のことを確認します。`neg_count`3. 到達した場合、現在のフォルダーにこの日を含めることはできません。 前のフォルダーのサイズを確定します`current_folder_size - 1`そして、現在の日付で新しいフォルダーを開始します。 リセット`neg_count`現在の日が負の場合は 1 に、それ以外の場合は 0 に設定します。`current_folder_size`1に。 
6. ループの後、最後のフォルダーのサイズを`folders`。 
7. フォルダーの数とフォルダーのサイズを順番に印刷します。 

このアルゴリズムが機能するのは、どのフォルダーにも 2 日を超えるマイナスの日が含まれないという不変条件が維持されているためです。 負の数が 3 に達したときに正確に新しいフォルダーを開始することで、有効性と最小性の両方が保証されます。制約に違反せずにフォルダーを拡張することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

folders = []
current_folder_size = 0
neg_count = 0

for x in a:
    if x < 0:
        neg_count += 1
    current_folder_size += 1
    if neg_count == 3:
        folders.append(current_folder_size - 1)
        current_folder_size = 1
        neg_count = 1 if x < 0 else 0

folders.append(current_folder_size)

print(len(folders))
print(' '.join(map(str, folders)))
```毎日繰り返して、フォルダーのサイズとマイナス数を更新します。 マイナスのカウントが 3 に達すると、当日の前にフォルダーを閉じ、新しいフォルダーを開始し、カウンターを適切にリセットします。 最後に、最後のフォルダーを追加します。 Off-by-one エラーは、リセットする前にフォルダーのサイズを調整することで回避できます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    folders = []
    current_folder_size = 0
    neg_count = 0
    for x in a:
        if x < 0:
            neg_count += 1
        current_folder_size += 1
        if neg_count == 3:
            folders.append(current_folder_size - 1)
            current_folder_size = 1
            neg_count = 1 if x < 0 else 0
    folders.append(current_folder_size)
    return f"{len(folders)}\n{' '.join(map(str, folders))}"

# Provided samples
assert run("11\n1 2 3 -4 -5 -6 5 -5 -6 -7 6\n") == "3\n5 3 3", "sample 1"
assert run("5\n1 2 3 4 5\n") == "1\n5", "sample 2"

# Custom cases
assert run("3\n-1 -2 -3\n") == "2\n2 1", "all negatives split"
assert run("1\n0\n") == "1\n1", "single day, zero"
assert run("6\n-1 2 -3 4 -5 6\n") == "3\n3 2 1", "interleaved negatives"
assert run("100\n" + " ".join(["1"]*100) + "\n") == "1\n100", "all positives max size"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3 つのネガティブ | 2 つのフォルダー | 負の数が 2 を超えた場合の分割 |
 | 1 日ゼロ | 1 フォルダー | 最小サイズの入力 |
 | インターリーブネガ | 3 つのフォルダー | ギャップのある正しい分割 |

 ## 特殊なケース

 のために`[ -1, -2, -3 ]`、アルゴリズムは負のカウントを追跡します。 2日目以降は、`neg_count = 2`、次の日には`neg_count = 3`、分割を引き起こします。 フォルダーのサイズ`[2,1]`制約を満たします。 

のために`[1, 2, 3, 4, 5]`、すべて肯定的、`neg_count`3 に達することはないため、サイズ 5 のフォルダーが 1 つだけ作成されます。 

一日だけ`[0]`、`current_folder_size = 1`、`neg_count = 0`、そして最後の追加は次のようになります`[1]`、最小限の入力を正しく処理します。 

このアルゴリズムは、マイナスのカウントとフォルダーの分割を体系的に管理し、特殊なコードを使用せずに考えられるすべてのエッジ ケースをカバーします。
