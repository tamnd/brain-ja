 ## 解決策
 ## 問題の理解

 完全な形式の IPv6 アドレスは、8 つのブロックで構成される固定構造です。 各ブロックは 16 ビットを表し、必要に応じて先頭のゼロを含めて、正確に 4 つの 16 進数文字として書き込まれます。 ブロックはコロンで区切られるため、完全に展開されたアドレスは常に同じ長さのパターンを持ち、常に 7 つのコロンが含まれます。 

私たちが受け取る入力は、そのようなアドレスの短縮版です。 2 つの独立した圧縮が適用された可能性があります。 まず、各ブロック内で先頭のゼロが削除されている可能性があるため、次のようなブロックが`00ea`次のように表示されるかもしれません`ea`。 第 2 に、すべてゼロだった単一の連続したブロックが二重コロンに置き換えられた可能性があります。`::`、これは 1 つ以上の完全なゼロ ブロックを表します。 重要なのは、この置換はアドレスごとに 1 回だけ使用できるということです。 

タスクは、元の完全な 8 ブロック表現を再構築することです。 つまり、失われたゼロブロックを両方とも回復する必要があります。`::`先頭にゼロを追加して、各ブロックを正確に 4 桁の 16 進数に復元します。 

制約は小さく、最大でも 100 アドレスなので、単純な解析アプローチでも十分に高速です。 主な困難はパフォーマンスではなく、あいまいな構造を正確に処理できるかどうかです。`::`、特に、省略されたゼロブロックがどこに属するか、およびその数を区別します。 

いくつかのエッジな状況では、単純な解決策が崩れる傾向があります。 入力が正確であれば、`::`、これは 8 つのゼロ ブロックを表し、多くの実装ではこれを空または単一のブロックとして誤って扱います。 もし`::`が最初または最後に表示されると、分割の片側が空になりますが、これは正しく解釈される必要があります。 もう 1 つの微妙なケースは、拡張時に次のことを保証することです。`::`の場合、周囲に表示される明示的なブロックの数に関係なく、ブロックの合計数は正確に 8 つになります。 

## アプローチ

 完全な IPv6 拡張の問題は、主に非可逆エンコーディングの逆転に関するものです。 強引なアイデアは、すべてのブロックに対してゼロブロックの可能な配置をすべて試してみることです。`::`そして、どの再構成が正確に 8 つのブロックを生成し、可視部分と一致するかを検証します。 これには文字列を分割する必要があります`::`、圧縮されたゼロブロックの数を推測し、一貫性をチェックします。 概念的には単純ですが、実際には構造が答えを一意に決定するにもかかわらず、不必要な組み合わせ推論が導入されます。 

重要な観察は、非`::`ブロックはすでに修正されています。 文字列を分割したら、`::`、欠落しているブロックの数は、すでに存在するブロックの数によって完全に決まります。 最終アドレスにはちょうど 8 つのブロックが含まれている必要があるため、挿入されるゼロ ブロックの数は単純に次のようになります。`8 - (left_blocks + right_blocks)`。 

これにより、曖昧さが解消されます。 もう検索は行わず、必要なゼロ ブロックの数を計算し、それらを正しい位置に挿入するだけです。 

8 つのブロックの完全なリストを再構築した後、各ブロックは先頭にゼロを埋め込むことによって独立して 4 桁の 16 進数に拡張されます。 この段階ではブロック間の相互作用はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースによるゼロ配置の推測 | O(指数関数的`::`) | お(1) | 遅すぎる/不必要 |
 | 直接解析と再構築 | アドレスごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各アドレスを個別に処理します。 

1. 文字列に次のものが含まれているかどうかを確認します。`::`。 そうでない場合、アドレスにはすでに 8 つのブロックすべてが明示的にリストされています。 で割るだけです`:`各ブロックを 4 文字に埋め込みます。 
2. もし`::`存在する場合は、文字列を 2 つの部分に分割します。`::`そしてその後のすべて。 各部分は空の場合があります。 
3. 両方の部分を次のように分割します。`:`ブロックのリストに変換します。 空の部分は空のリストを生成します。これは先頭または末尾のような場合に重要です。`::`。 
4. 両方のリストを合わせて、すでに存在するブロックの数を数えます。 これをそのままにしておきます`k`。 
5. ゼロブロックをいくつ挿入する必要があるかを計算します。`z = 8 - k`。 入力は有効であることが保証されているため、この値は常に負ではありません。 
6. 完全なブロック リストを次のように作成します。ブロックを左にし、次に`z`ゼロブロック、次に右ブロック。 ゼロブロックは次のように表されます。`"0"`または空の文字列ですが、次のステップで正規化されます。 
7. ゼロ埋め込みを使用して、すべてのブロックを 4 文字の 16 進文字列に変換します。 これは、元のブロックと挿入されたブロックの両方に対して一律に行われます。 
8. コロンを使用して 8 つのブロックすべてを結合し、最終的な拡張 IPv6 アドレスを形成します。 

正確さは、構造全体のサイズが固定されているという事実から得られます。 明示的に存在するブロックの数がわかったら、残りは次のようにして導入されたゼロブロックでなければなりません。`::`、単一のギャップを超えると配置に自由はありません。 

維持される不変条件は、ステップ 6 の後、構築されたブロック リストには常に、元の値または推定されたゼロ ブロックのいずれかで満たされるちょうど 8 つの論理位置があるということです。 ステップ 7 のパディングはフォーマットのみを変更し、構造は変更しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def expand_ipv6(s: str) -> str:
    if "::" in s:
        left, right = s.split("::")

        left_blocks = left.split(":") if left else []
        right_blocks = right.split(":") if right else []

        # remove empty strings caused by edge cases like ":" splitting artifacts
        left_blocks = [b for b in left_blocks if b]
        right_blocks = [b for b in right_blocks if b]

        k = len(left_blocks) + len(right_blocks)
        z = 8 - k

        blocks = left_blocks + (["0"] * z) + right_blocks
    else:
        blocks = s.split(":")

    # pad each block to 4 hex digits
    res = []
    for b in blocks:
        res.append(b.zfill(4))

    return ":".join(res)

def main():
    n = int(input())
    out = []
    for _ in range(n):
        s = input().strip()
        out.append(expand_ipv6(s))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装は再構築ロジックを直接反映しています。 最もデリケートな部分は取り扱いです`::`分割すると空の文字列が生成され、実際のブロックとして扱ってはならないためです。 フィルタリングを使用すると、欠落しているゼロ ブロックの数を決定するときに、実際の 16 進トークンのみをカウントすることが保証されます。 

パディングステップ`zfill(4)`すべてのブロックは圧縮後に有効な 16 進数で最大 4 文字であることが保証されているため、これで十分です。

 ## 特殊なケース

 入力用`::`、アルゴリズムは空の左右のリストに分割されます。 計算された欠落ブロック数は 8 になるため、8 つのゼロ ブロックが挿入されます。 パディング後、すべては次のようになります`0000`、有効な完全な IPv6 アドレスが生成されます。 

のために`::1:2:3:4:5:6:7`、左側は空で、右側には 7 つのブロックが含まれています。 アルゴリズムは先頭に 1 つのゼロ ブロックを挿入し、合計が 8 ブロックに達するようにします。 パディングにより、正しい完全な表現が生成されます。 

のために`1:2:3:4:5:6:7::`の場合は、逆のことが起こります。右側は空で、最後に 1 つのゼロ ブロックが追加されます。 これは、`::`特別な大文字と小文字を区別せずに、ゼロが先頭に挿入されるか末尾に挿入されるかを自然に決定します。
