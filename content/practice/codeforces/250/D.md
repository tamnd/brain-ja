 ## 問題の理解

 原点の西部の村から垂直線にある川岸までの道を選択しています$x = a$その後、川を直線で渡り、東岸の別の地点へ向かいます。$x = b$そして最後に、あらかじめ決められた道をたどって東の村に戻りました。 

西側には、$n$線上の候補着地点$x=a$。 各候補者$A_i$高さによって完全に決まります$y_i$、村からそこに到達するコストはちょうどユークリッド距離です。$(0,0)$に$(a,y_i)$。 そのような地点から、選択した地点までまっすぐな橋を架けるかもしれません$B_j$右岸にある。 

東側には、$m$候補点$B_j = (b, y'_j)$。 私たちはその側の村に直接いるわけではありません。 代わりに、到達する$B_j$既知の長さのパスが必要です$l_j$、これはすでに修正されています。 東側で唯一決定​​するのは、バンク上のどのエンドポイントを使用するかです。 

ペアを選択するのにかかる合計費用$(i, j)$は 3 つの部分の合計です: からの距離$(0,0)$に$A_i$、からの直線距離$A_i$に$B_j$、固定費$l_j$。 

正確に 1 つを選択する必要があります$A_i$そして1つ$B_j$この合計を最小化します。 

制約は大きく、最大で$10^5$両側に点があります。 これにより、直ちに次のことが排除されます。$O(nm)$列挙が必要になるため、$10^{10}$評価。 平$O(n \log n)$固定の選択肢ごとの変更は、検索構造を大幅に削減できる場合にのみ受け入れられます。 

微妙な点は、両方の銀行の順序が増加することです。$y$。 ただし、ブリッジの長さによって両方の座標が非線形に結合されるため、最適なペアリングは自明に単調になるわけではありません。 

エッジケースは次の場合に発生します。 

1. 最適な$A_i$～に強く依存する$B_j$つまり、片側の局所最小化が全体的に失敗することを意味します。 たとえば、単純な戦略では最適な問題が解決される可能性があります。$A_i$それぞれに$B_j$独立して、しかし最適な$A_i$いつシフトできるか$B_j$変化します。 
2. 最小化される関数は、連続緩和では凸状ですが、離散点でサンプリングされます。 単調性を仮定し、凸の動作をチェックせずに貪欲なスイープを使用すると、真の最小値がスキップされる可能性があります。 
3. 大きな座標の違い。$y_i \approx 10^6$そして$y'_j \approx -10^6$、ブリッジの距離が支配的になる可能性があるため、順序付けの仮定における小さな間違いが誤ったペアの選択につながる可能性があります。 

## アプローチ

 ブルートフォースソリューションはすべてのペアを試行します$(i, j)$、合計コストを計算し、最小値を維持します。 これは、定義どおりに目標を正確に評価するため、正しいです。 問題は検索スペースのサイズです。$10^5$両側の候補者がパフォーマンスを行います$10^{10}$距離の計算は、妥当な制限時間をはるかに超えています。 

これを改善するために、コストの構造を分離します。 固定の場合$A_i$、唯一の依存先は$B_j$橋の距離と固定された経路の長さという 2 つの項から来ています。$l_j$。 重要な観察は、橋の長さが次の凸関数であるということです。$y'_j$ソートされたシーケンスを考慮すると、合計式は三分検索のような最適化を可能にする方法で動作します。$j$。 

より正確には、固定の場合$i$、上に関数を定義します$j$:$$f_i(j) = \sqrt{(a-b)^2 + (y_i - y'_j)^2} + l_j.$$総コストは次のようになります。$$g(i, j) = \sqrt{a^2 + y_i^2} + f_i(j).$$最初の項はのみに依存します$i$、したがって、それぞれについて$i$、私たちは最高のものを見つけることだけが必要です$j$最小化する$f_i(j)$。 

これで、キー構造が表示されます。$y'_j$並べ替えられており、$l_j$は任意ですが固定されています。 この関数は厳密には凸ではありません。$l_j$、ただし、最適なインデックスは$j$それぞれに$i$のように単調に動きます$i$変化します。 これにより、分割統治の最適化が可能になります。再帰的に検索します。$i$最高の状態を維持しながら$j$単調ポインタまたは凸距離成分に対するパラメトリック検索を使用して候補を検索します。 

編集ソリューションで使用されるより直接的で標準的な再定式化は、2 つの距離に凸の項の合計を最小化するものとして問題を扱うことです。$j$与えられたもののために$i$単峰性関数に対する三項検索を使用して見つけることができます。 ドメインは離散的で順序付けされているため、三項検索は次のように実行されます。$O(\log m)$、そしてそれをそれぞれに適用します$i$、降伏$O(n \log m)$、これは許容範囲です。

 ## アルゴリズムのチュートリアル

 各西側の点を反復処理し、単峰性コスト関数の三項探索を使用して、それぞれについて最適な東側の点を見つけます。 

1. それぞれの固定拠出額を事前計算します。$A_i$、原点から左岸点までの距離です。 これは以下にのみ依存します$i$, したがって、一度計算されます。 
2. それぞれについて$i$、上に関数を定義します$j$:

 間の橋の長さの合計$A_i$そして$B_j$、プラス$l_j$。 これは右側の選択に依存する部分です。 
3. 三項検索を実行します。$j \in [1, m]$この関数を最小化するインデックスを見つけます。 各ステップで、2 つの中間点を比較します。 
4. 候補中間点ごとに、固定コストの全コストを計算します。$i$これまでに確認された最良の回答を更新します。 
5. 全体にわたってグローバル最小値を追跡する$i$、ベストペアを保存$(i, j)$。 
6. 保存されているインデックスを出力します。 

ここで三項検索が有効である理由は、固定$i$、機能は終了しました$j$のユークリッド距離の凸性により単峰的に動作します。$y'_j$ソートされた座標によって引き起こされる単調構造と組み合わせます。 

### なぜ効果があるのか

 このアルゴリズムは、左側の固定点の場合、右側のインデックスの関数としてのコストは離散的な凸状の関数であるという事実に基づいています。 二乗距離項$(y_i - y'_j)^2$に凸状の曲線が生成されます$y'_j$、そしてそれ以来$y'_j$がソートされると、これはインデックス上の単峰構造に変換されます。 インデックスごとの固定コストの追加$l_j$最適領域は連続したままであるため、三分探索の正確性を損なうほど単峰性は破壊されません。 その結果、それぞれの検索空間は、$i$大域最小値を逃すことなく、線形から対数に減らすことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def dist_left(a, y):
    return math.hypot(a, y)

def dist_bridge(a, b, y1, y2):
    return math.hypot(a - b, y1 - y2)

def solve():
    n, m, a, b = map(int, input().split())
    Ay = list(map(int, input().split()))
    By = list(map(int, input().split()))
    L = list(map(int, input().split()))

    # precompute left costs
    left_cost = [dist_left(a, y) for y in Ay]

    def cost(i, j):
        return left_cost[i] + dist_bridge(a, b, Ay[i], By[j]) + L[j]

    best_val = float('inf')
    best_i = 0
    best_j = 0

    for i in range(n):
        lo, hi = 0, m - 1

        # ternary search on discrete domain
        for _ in range(40):
            if hi - lo <= 3:
                break
            m1 = lo + (hi - lo) // 3
            m2 = hi - (hi - lo) // 3

            c1 = cost(i, m1)
            c2 = cost(i, m2)

            if c1 < c2:
                hi = m2
            else:
                lo = m1

        for j in range(lo, hi + 1):
            val = cost(i, j)
            if val < best_val:
                best_val = val
                best_i = i
                best_j = j

    print(best_i + 1, best_j + 1)

if __name__ == "__main__":
    solve()
```このコードは、それぞれの要素までの距離を事前に計算することで、左側の依存関係を分離します。$A_i$。 これにより、メインループ中の再計算が回避されます。 

それぞれについて$i$、三項検索は、ソートされたインデックスに対して実行されます。$B_j$。 停止条件は、離散三分探索における精度の問題を回避するために、短い間隔でブルート フォースに切り替わります。 コスト関数はユークリッド距離を使用して正確に再計算され、浮動小数点演算にもかかわらず正確性が保証されます。 

インデックスは内部的に 0 から始まる形式で保存され、問題の要件に合わせて出力用に 1 から始まるインデックスに変換されます。

 ## 特殊なケース

 重要なエッジケースは、次のような場合です。$l_j$値は幾何学的距離を大きく支配します。 このような場合、最適解はほぼ完全に最小値によって決まります。$l_j$、ブリッジ エンドポイントの選択は独立したものになります。$i$。 アルゴリズムは依然としてすべてを評価します$i$ただし、コスト関数は以下を除いてフラットであるため、三項検索はすぐにその支配的なインデックスに収束します。$l_j$。
