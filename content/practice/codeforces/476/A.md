 ## 解決策
 ## 問題の理解

 Dreamoon は、ある階段の頂上に到達したいと考えています。`n`ステップ。 すべての動きは 1 ステップまたは 2 ステップのいずれかをカバーできます。 正確にステップに到達するためのあらゆる方法の中で`n`で割り切れるのに使用される移動数が必要です。`m`。 

このタスクは、異なるシーケンスの数を要求しません。 の倍数である可能な最小の移動数を要求します。`m`それでもDreamoonがまさにトップに到達することを可能にします。 そのような移動カウントが存在しない場合は、次のように出力する必要があります。`-1`。 

制約は非常に小さいです。 階段の高さは最大 10000 であり、`m`可能なすべての移動カウントに対する単純な線形スキャンでも、十分に高速になります。 動的計画法、グラフ検索、または組み合わせ論は必要ありません。 

重要な観察は、どの移動カウントが可能かを理解することから始まります。 

すべての手が 2 歩の手であれば、手数はできるだけ少なくなります。 その最低限度というのは、`ceil(n / 2)`。 

すべての手が 1 歩の手であれば、手数はできるだけ多くなります。 その最大値は`n`。 

これら 2 つの値の間のすべての整数移動カウントが達成可能です。 すべての 2 ステップ移動から開始して、1 つの 2 ステップ移動を 2 つの 1 ステップ移動に置き換えると、総登坂距離は変化せずに、移動数がちょうど 1 増加します。 

間違いを引き起こしやすい特殊なケースがいくつかあります。 

考慮する：```
3 5
```最小可能な移動回数は次のとおりです。`2`そして最大値は`3`。 の倍数はありません`5`その間隔では、答えは次のようになります。```
-1
```最小手数を単純に次の倍数に切り上げる不用意な解決策`m`入手するだろう`5`、5手で正確に3段を登ることはできないため、これは不可能です。 

もう 1 つの重要なケースは次のとおりです。```
1 2
```唯一可能な移動回数は次のとおりです。`1`。 以来`1`で割り切れない`2`、正解は次のとおりです。```
-1
```常に答えがあると想定する解決策は、ここでは失敗します。 

ついに：```
10 2
```最小可能な移動回数は次のとおりです。`5`。 以来`6`の最初の倍数です`2`それは少なくとも`5`、答えは次のとおりです。```
6
```アルゴリズムは、どちらかのエンドポイントを盲目的に取得するのではなく、実行可能な間隔内で検索する必要があります。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべての移動カウントを列挙し、それが有効な登りに対応できるかどうかを確認することです。 移動回数`k`であれば実現可能です`ceil(n/2) ≤ k ≤ n`。 すべての実現可能な値の中から、次の値で割り切れる最小の値を選択します。`m`。 

この問題の場合、間隔には最大 10,000 個の値が含まれるため、線形スキャンでも完全に許容されます。 

興味深いのは、実行可能な間隔が正確に からである理由を認識することです。`ceil(n/2)`に`n`。 

できるだけ多くの 2 ステップ移動を使用すると、移動数が最小になります。 それは与える`ceil(n/2)`動く。 

すべての移動が 1 ステップの移動である場合に、最大の移動数が発生します。 それは与える`n`動く。 

1 つの 2 ステップ移動を 2 つの 1 ステップ移動に置き換えると、総登坂距離を変えることなく移動回数が 1 つだけ増加するため、その間のすべての値に到達可能です。 

この性質を理解すると、問題は非常に単純になります。 次の最小倍数だけが必要です`m`それは間隔の中にあります`[ceil(n/2), n]`。 

間隔全体をスキャンする代わりに、次の最初の倍数を直接計算できます。`m`それは少なくとも`ceil(n/2)`。 その倍数を超えない場合`n`、それが答えです。 それ以外の場合は、有効な移動カウントが存在しません。

 ## アルゴリズムのチュートリアル

 1. 可能な最小移動数を計算します。 

これは`ceil(n / 2)`、次のように書くことができます`(n + 1) // 2`整数演算を使用します。 
2. 次の最小倍数を見つけます。`m`それは少なくともこの最小値です。 

させて`mn`最小移動回数になります。 望ましい倍数は次のとおりです。`((mn + m - 1) // m) * m`これは、数値を次の倍数に切り上げる標準的な方法です。 
3. この倍数が依然として実行可能な移動回数であるかどうかを確認します。 

倍数がより大きい場合`n`、それは達成可能な間隔の外にあり、答えは存在しません。 
4. 可能な場合は倍数を出力し、そうでない場合は出力します。`-1`。 

### なぜ効果があるのか

 有効な登りはすべて、ある程度の数の 1 ステップ移動といくつかの 2 ステップ移動を使用します。 移動数をこれより小さくすることはできません`ceil(n/2)`そして決して超えることはできません`n`。 

さらに、これらの境界間のすべての整数が達成可能です。 最小移動ソリューションから開始すると、1 つの 2 ステップ移動を 2 つの 1 ステップ移動に置き換えるたびに、合計の登坂距離を維持しながら移動カウントが 1 つだけ増加します。 

間隔内のすべての移動カウントが実行可能であるため、問題は次の最小倍数を見つけることになります。`m`その間隔の中で。 アルゴリズムはその値を正確に計算します。 最初の倍数が上限を超える場合`n`の場合、有効な倍数は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

mn = (n + 1) // 2
ans = ((mn + m - 1) // m) * m

if ans <= n:
    print(ans)
else:
    print(-1)
```最初の計算では、達成可能な最小移動数が求められます。 使用する`(n + 1) // 2`浮動小数点演算を回避し、上限演算を正しく実装します。 

次の行は、この最小値を最も近い倍数に切り上げます。`m`。 これにより、最小の候補の答えが直接得られます。 

最終チェックが重要です。 実行可能な間隔を超えて倍数が存在する可能性があります。 たとえば、`n = 3`そして`m = 5`、四捨五入された値は`5`, しかし5手は3段しか登れません。 と比較する`n`この状況を捉えて生み出す`-1`。 

すべての計算は標準の整数型に快適に適合し、Python はそれらを自然に処理します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    n, m = map(int, input().split())

    mn = (n + 1) // 2
    ans = ((mn + m - 1) // m) * m

    print(ans if ans <= n else -1)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("10 2\n") == "6", "sample 1"

# sample-like impossible case
assert run("3 5\n") == "-1", "sample 2"

# minimum staircase
assert run("1 2\n") == "-1", "minimum size"

# exact multiple at lower bound
assert run("4 2\n") == "2", "lower bound already valid"

# answer requires rounding up
assert run("7 3\n") == "6", "round to next multiple"

# large boundary
assert run("10000 10\n") == "5000", "maximum n"

```アルゴリズムは以下を計算します。`mn = (1 + 1) // 2 = 1`少なくとも 1 の 2 の最初の倍数は 2 です。 

以来`2 > 1`、値は実行可能な間隔の外にあります`[1, 1]`。 アルゴリズムは次のように出力します。```

```それは正しいです。 

ここで次のことを考えてみましょう。```

```実行可能な手数は 2 と 3 のみです。 

アルゴリズムは以下を計算します。`mn = 2`少なくとも 2 の 5 の最初の倍数は 5 です。 

以来`5 > 3`、実行可能な倍数は存在しないため、出力は次のようになります。```
-1
```最後に次のことを考慮してください。```

```最小移動回数は次のとおりです。`mn = 2`2 はすでに 2 で割り切れるため、四捨五入された倍数は 2 のままです。
