 ## 解決策
 ## 問題の理解

 Drazil は一連の移動コマンドを送信します。 それぞれ`'+'`Dreamoon を右に 1 歩ずつ移動すると、`'-'`左に 1 ステップ移動します。 

私たちは元のコマンド文字列と、Dreamoon が受け取る文字列を知っています。 受信した文字列には次のものが含まれる場合があります`'?'`認識できなかったコマンドを表す文字。 あらゆる人にとって`'?'`、Dreamoonが独自に選択`'+'`または`'-'`等しい確率で。 

タスクは、Dreamoon が元のコマンド シーケンスに従っていた場合に到達したであろう位置とまったく同じ位置で終了する確率を計算することです。 

文字列の長さは最大 10 です。この制約により、問題の性質が完全に変わります。 受信した文字列のすべての文字が`'?'`、あるだけです$2^{10} = 1024$考えられる解釈。 制限時間内にあらゆる可能性を列挙するのは簡単なことです。 

主な課題は効率ではなく、確率を正確に計算することです。 すべての割り当て`'?'`各未知のコマンドは独立した公平なコイントスによって決定されるため、文字の可能性も同様です。 

よくある間違いは、最終的な位置を比較するのではなく、文字列を文字ごとに比較することです。 例えば：```
s1 = "++--"
s2 = "+?+-"
```異なるコマンド シーケンスでも、同じ最終位置が生成される場合があります。 重要なのは移動の正確な順序ではなく、目的地です。 

もう 1 つの簡単な間違いは、すべての割り当てが同じ確率であることを忘れていることです。 考慮する：```
s1 = "+"
s2 = "?"
```考えられる結果は 2 つあります。`'+'`そして`'-'`。 目標位置に到達できるのは 1 つだけなので、答えは次のようになります。`0.5`、 ない`1`。 

3 番目のエッジ ケースは、どのように設定してもターゲット位置に到達できない場合に発生します。`'?'`文字が選択されます:```
s1 = "+++"
s2 = "?--"
```目標の位置は、`+3`。 受信した文字列は次の位置でのみ終了できます。`-1`または`-3`。 正しい確率は`0`。 

## アプローチ

 最も直接的な解決策はブルートフォースです。 

まず、Drazil が意図した目的地を計算します。 次に、可能なすべての置き換えを検討します。`'?'`受信した文字列内の文字。 割り当てごとに、結果として生じる動作シーケンスをシミュレートし、その最終位置を計算します。 目標位置に到達した割り当ての数を数えます。 

あれば`k`不明なコマンド、正確にあります`2^k`課題。 文字列の長さが 10 を超えることはないため、最悪の場合でも割り当ては 1024 個のみになります。 単純な再帰検索でも非常に高速です。 

このブルートフォース手法が機能する理由は、各割り当てがコイントスの同じ確率の 1 つの結果に対応しているためです。 もし`good`課題は目標を達成し、`2^k`合計割り当ての場合、望ましい確率は次のようになります。$$\frac{good}{2^k}$$組み合わせ観察もあります。 割り当てを列挙する代わりに、割り当ての数を計算することもできます。`'+'`未知の位置の中から選択が必要であり、二項係数を使用します。 最終的な変位だけが重要なので、これは機能します。 

この問題に関しては、小さな制約により列挙がより単純になり、正しく実装することが容易になります。 すでに十分に最適化されています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O(2^k \cdot n) | O(k) | 承認済み |
 | 組み合わせ計数 | O(n) | お(1) | 承認済み |

 ここ`k`の数です`'?'`キャラクターと`n ≤ 10`。 

## アルゴリズムのチュートリアル

 1. 元の文字列によって生成されたターゲット位置を計算します。 

扱う`'+'`として`+1`そして`'-'`として`-1`、すべての動きを合計します。 
2. 何個数えるか`'?'`受信した文字列に文字が出現します。 

これらの位置は、プロセスの中で唯一不確実な部分です。 
3. 深さ優先検索を使用して、未知のコマンドの可能なすべての置換を生成します。 

それぞれに`'?'`、次の 2 つの可能性に分岐します。`'+'`そして`'-'`。 
4. すべての位置が処理されたら、結果の最終位置を計算します。 

目標位置と等しい場合は、成功した割り当ての数を増やします。 
5. 調査された割り当ての合計数を追跡します。 

再帰の各リーフは、同様に可能性の高い 1 つの結果に対応します。 
6. 出力:$$\frac{\text{successful assignments}}{\text{total assignments}}$$### なぜ効果があるのか

 それぞれ`'?'`独立した公正なコイントスを表します。 すべての未知の位置を置き換えると、考えられる結果のサンプル空間が正確に生成されます。 再帰では、すべての結果が 1 回だけ訪れます。 

すべての結果について、最終位置が目標位置と等しいかどうかを確認します。 成功した結果の数を結果の総数で割った値は、すべての結果の可能性が等しい場合の確率の定義となります。 未知のコマンドの割り当てには確率があるため、$(1/2)^k$、有利な割り当てを数えるだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s1 = input().strip()
s2 = input().strip()

target = 0
for ch in s1:
    target += 1 if ch == '+' else -1

good = 0
total = 0

def dfs(idx, pos):
    global good, total

    if idx == len(s2):
        global target
        total += 1
        if pos == target:
            good += 1
        return

    if s2[idx] == '+':
        dfs(idx + 1, pos + 1)
    elif s2[idx] == '-':
        dfs(idx + 1, pos - 1)
    else:
        dfs(idx + 1, pos + 1)
        dfs(idx + 1, pos - 1)

dfs(0, 0)

print("{:.12f}".format(good / total))
```最初の部分では、Drazil が意図した目的地を計算します。 

再帰関数は、受信した文字列を左から右に処理します。 パラメータ`pos`インデックスで終わるプレフィックスを処理した後に到達した位置を格納します`idx - 1`。 

既知のコマンドの場合、継続は 1 つだけです。 のために`'?'`継続は 2 つあり、コイントスの同じ確率で起こり得る 2 つの結果に対応します。 

再帰が文字列の終わりに達すると、1 つの完全な割り当てが構築されます。 合計カウントをインクリメントし、結果の位置がターゲットと一致するかどうかを確認します。 

答えは、すべての割り当てに対する成功した割り当ての割合です。 代入の数は最大 1024 であるため、再帰は完全に安全です。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    s1 = input().strip()
    s2 = input().strip()

    target = sum(1 if c == '+' else -1 for c in s1)

    good = 0
    total = 0

    def dfs(idx, pos):
        nonlocal good, total

        if idx == len(s2):
            total += 1
            if pos == target:
                good += 1
            return

        if s2[idx] == '+':
            dfs(idx + 1, pos + 1)
        elif s2[idx] == '-':
            dfs(idx + 1, pos - 1)
        else:
            dfs(idx + 1, pos + 1)
            dfs(idx + 1, pos - 1)

    dfs(0, 0)
    return "{:.12f}".format(good / total)

# sample 1
assert run("++-+-\n+-+-+\n") == "1.000000000000"

# sample 2 from statement explanation
assert run("+-+-\n+-??\n") == "0.500000000000"

# minimum length
assert run("+\n+\n") == "1.000000000000"

# one unknown command
assert run("+\n?\n") == "0.500000000000"

# impossible target
assert run("+++\n?--\n") == "0.000000000000"

# all unknowns, target position 0
assert run("+-\n??\n") == "0.500000000000"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`+\n+\n`|`1.000000000000`| 可能な最小のインスタンス |
 |`+\n?\n`|`0.500000000000`| シングルコイントス |
 |`+++\n?--\n`|`0.000000000000`| 到達不能なターゲット位置 |
 |`+-\n??\n`|`0.500000000000`| 複数の割り当てが目標に到達 |

 ## 特殊なケース

 次のことを考慮してください。```
+
?
```目標の位置は、`+1`。 不明なコマンドは次のいずれかになります。`'+'`または`'-'`。 再帰により、正確に 2 つの代入が生成されます。 1 人がポジションに到達`+1`、もう一方は到達します`-1`。 アルゴリズムは戻ります`1/2 = 0.5`。 

考慮する：```
+++
?--
```目標の位置は、`+3`。 受信した文字列から可能な最終位置は次のとおりです。`-1`そして`-3`。 列挙中に、どの割り当てもターゲットと一致しません。 成功回数はゼロのままなので、答えは次のようになります。`0.0`。 

考慮する：```
+-
??
```目標の位置は、`0`。 再帰では 4 つの割り当てを調べます。 2 つの位置が終了する`0`、1 時に`+2`、そして 1 回目`-2`。 アルゴリズムは、成功した 2 つの割り当てと出力をカウントします。`2/4 = 0.5`。 

これらの例では、確率がわずかである場合、ターゲットが不可能である場合、および複数の異なる割り当てが同じ目的地につながる場合など、難しい状況をカバーしています。 カウントするアプローチでは、それらすべてを自然に処理します。
