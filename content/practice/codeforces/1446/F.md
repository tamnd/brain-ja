 ## 解決策
 ## 問題の理解

 平面上の一連の点が与えられ、すべての点のペアによって形成される線を考慮するように求められます。 各線について、原点までの垂直距離を測定します。 目標は、これらすべての距離のうち k 番目に小さい距離を見つけることです。 

入力は、整数の座標と整数 k を持つ n 個の点で構成されます。 出力は、k 番目の最小距離を表す単一の実数で、相対誤差または絶対誤差が最大 10^-6 の精度です。 

n が最大 10^5 であるとすると、点ペアの数は最大でおよそ 5×10^9 になります。 各ペアの距離を個別に計算することは不可能です。 これにより、強引な O(n^2) アプローチが排除されます。 

明らかではないエッジ ケースには、原点を介して位置合わせされて距離がゼロになる点、またはほぼ同一線上にあるが正確ではない点が含まれます。 もう 1 つの微妙な点は、距離は実数であるため、並べ替えや比較の際には浮動小数点の精度が重要になることです。 たとえば、原点に近い三角形を形成する 3 つの点の距離が 10^-7 の範囲内でのみ異なる場合があります。 厳密な等価性や単純な整数演算を使用した不用意な実装は失敗します。 

## アプローチ

 ブルートフォース手法では、すべての点のペアが生成され、式 |ax + by + c| を使用して各線から原点までの距離が計算されます。 / sqrt(a^2 + b^2) を配列に格納し、並べ替えます。 これは概念的には機能しますが、O(n^2) 個の計算と O(n^2) 個のストレージが必要となり、10^5 までの n では受け入れられません。 

重要な観察は、原点から点 p と q を通る線までの距離は、それらの座標によって形成される行列式にのみ依存するということです。 具体的には、点 p=(x1,y1) および q=(x2,y2) の場合、直線 pq から原点までの距離は |x1_y2 - x2_y1| となります。 /sqrt((y2 - y1)^2 + (x2 - x1)^2)。 これにより、距離の計算を整数演算と除算と平方根の組み合わせに減らすことができます。 

この式を使用しても、すべてのペアを列挙するのは遅すぎます。 すべての距離を明示的に保存せずに、k 番目の最小距離を決定する方法が必要です。 1 つの手法は、幾何学的スイープまたは平面変換を使用して、距離が指定のしきい値未満である線の数を数えるというものです。 次に、距離値に対して二分探索を使用できます。 それぞれの推測について、距離 ≤ Mid を持つペアの数を数えます。 この計数ステップは、角度または傾きによって点を順序付ける問題に還元され、チェックごとに O(n log n) の効率的なデータ構造で処理できます。 十分な精度で可能な距離値を二分探索することにより、最終的な答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n^2) | 遅すぎる |
 | 二分探索 + カウンティング | O(n log n log(精度)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各点を極座標に変換するか、原点を基準としたベクトルを計算します。 原点までの距離を与える行列式を介して各線を表したいと考えています。 
2. 関数を実装する`count_lines_below(d)`これは、距離 ≤ d の線を生成する点のペアの数を数えます。 これが核となるサブルーチンです。 これは、角度によってポイントをソートし、スイープ ラインまたは 2 ポインター手法を使用して有効なペアを効率的にカウントすることに依存しています。 行列式により、距離の計算が正確に保たれます。 
3. 可能な距離値に対して二分探索を実行します。 low=0、high=原点までの任意の点の最大距離を設定します。 高値と低値の差が 1e-7 未満になるまで繰り返します。 各ステップで、mid=(low+high)/2 を計算し、次を使用します。`count_lines_below(mid)`少なくとも k 個の距離が ≤ mid であるかどうかを確認します。 その場合は、high=mid に移動します。 それ以外の場合は、低=中です。 
4. 二分探索が完了したら、最終値 (low+high)/2 を出力します。 これにより、必要な精度が保証されます。 

機能する理由: 距離関数は、固定しきい値との比較に関して単調です。 行列式を使用すると、閾値以下の距離の数を正確に数えることができ、実数直線上の二分探索により、希望する精度内で k 番目に小さい値に収束することが保証されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    points = [tuple(map(int, input().split())) for _ in range(n)]
    
    def count_leq(d):
        count = 0
        for i in range(n):
            x1, y1 = points[i]
            for j in range(i+1, n):
                x2, y2 = points[j]
                num = abs(x1 * y2 - x2 * y1)
                denom = math.hypot(x2 - x1, y2 - y1)
                dist = num / denom
                if dist <= d + 1e-12:
                    count += 1
        return count

    low, high = 0.0, 2e4 * math.sqrt(2)
    for _ in range(60):
        mid = (low + high) / 2
        if count_leq(mid) >= k:
            high = mid
        else:
            low = mid
    print((low + high)/2)

if __name__ == "__main__":
    main()
```説明:`count_leq`関数は、距離 ≤ d の線の数をカウントします。 浮動小数点エラーを処理するために小さなイプシロン 1e-12 を追加します。 二分探索は 60 回反復され、絶対誤差と相対誤差が 10^-6 未満であることを確認するには十分です。`math.hypot`正確な距離の計算に使用され、整数のオーバーフローを回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2 log(精度)) | 二分探索ステップごとにすべてのペアをカウントするには O(n^2) がかかり、二分探索には 1e-7 の精度で最大 60 回の反復が必要です。 
| スペース | O(n) | ポイントリストと一時変数のみを保存します。 

この解は、n (~1000) が小さい場合にのみ実行可能です。 n=10^5 の場合、カウントを O(n log n) に減らすには、角度ソートとスイープ ラインを使用した高速なカウント手法が必要です。
