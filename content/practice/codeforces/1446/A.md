 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースにはアイテムのコレクションがあり、各アイテムには重量があり、固定容量のナップザックがあります。$W$。 タスクは、これらのアイテムの一部のサブセットを選択して、その総重量が$C$特定の間隔内に着陸します。それは、ナップザックの容量の少なくとも半分 (切り上げ) である必要があり、それを超えてはなりません$W$。 

言い換えれば、私たちは実現可能性を超えて何かを最適化しようとはしていません。 合計が「十分大きいが安全である」サブセットを見つけるだけで済みます。 そのようなサブセットが存在する場合は、どの項目をインデックスによって選択したかを出力する必要があります。そうでない場合は、不可能であると報告します。 

この制約は、すべてのサブセットを試すことができないことを強く示唆しています。 まで$2 \cdot 10^5$テスト全体にわたる項目の数を増やすと、指数関数的なアプローチは不可能であり、テストごとの二次関数でさえ遅すぎます。 これにより、テスト ケースごとに線形または線形に近い構築が求められ、並べ替えや貪欲な選択が含まれる可能性が高くなります。 

すべてのアイテムが個別に大きすぎたり、小さすぎたりして正しく組み合わせることができない場合、微妙な失敗のケースが発生します。 

エッジケースの 1 つは、すべての項目が超過する場合です。$W$。 たとえば、次の場合$W = 5$そして重みは$[6, 7]$の場合、有効なサブセットは存在しないため、次のように出力する必要があります。`-1`。 

もう 1 つのエッジ ケースは、すべてのアイテムが非常に小さいにもかかわらず、慎重に組み合わせた場合にのみ合計がしきい値にほとんど達しない場合です。 小さなアイテムを選びすぎる素朴な貪欲さは行き過ぎてしまう可能性があります$W$有効な組み合わせが存在する場合でも。 

3 番目の重要なケースは、単一の項目がすでに必要な間隔内にある場合です。 たとえば、次の場合$W = 10$の場合、重み 5 ～ 10 のアイテムは即座に有効な答えとなり、不必要にアイテムを組み合わせるべきではありません。 

## アプローチ

 ブルート フォース ソリューションでは、アイテムのすべてのサブセットを試し、それらの合計を計算し、合計が有効な間隔内にあるかどうかを確認します。 これはすべての可能性を徹底的に探索するため、原則として正しいです。 ただし、サブセットの数は$2^n$であっても天文学的に大きくなります。$n = 40$、ましてや$2 \cdot 10^5$。 各サブセット合計の計算でもオーバーヘッドが追加されるため、これは完全に不可能になります。 

重要な点は、間隔を正確に指定したり、何かを最大化したりする必要がないということです。 目標の下限を維持しながら目標の下限に到達する必要があるだけです$W$。 これは、しきい値を超えるまで徐々に体重を蓄積するという貪欲な戦略を示唆しています。 

このタイプの問題に対する標準的な手法は、累計を維持しながら項目を任意の順序で選択することですが、同時にオーバーシュートを確実に回避することです。$W$不要なとき。 より構造化された方法は、まず、以下より重いアイテムをすべて無視することです。$W$、決して使用できないからです。 次に、少なくとも到達するまでアイテムを蓄積しようとします$\lceil W/2 \rceil$。 成功すると、選択した項目が出力されます。 

ただし、追加の構造的洞察があります。$W$場合は、項目を追加しても問題を解決できないため、合計が範囲内に収まっている間のみ項目を追加するようにする必要があります。 これにより、問題は純粋な部分集合和探索ではなく、制御された累積問題に変わります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に解決します。 

1. 最低限必要な合計を計算します。$L = \lceil W/2 \rceil$。 これは許容可能な最小総重量です。 
2. 重量が次の値を超えるすべてのアイテムを除外します。$W$なぜなら、それらは決して有効なソリューションの一部ではないからです。 それらのインデックスは完全に無視されます。 
3. 残りの項目を繰り返し、現在の合計と選択したインデックスのリストを維持します。 各項目について、それを含めるようにしてください。 
4. 合計がそれを超えない場合は項目を追加します$W$容量を超えるとサブセットが即座に無効になるためです。 
5. 現在の合計が少なくとも一定に達したら、早めに停止します$L$。 現時点では、すでに有効な解決策があり、これ以上追加する必要はありません。 
6. すべての項目を処理した後でも合計がまだ下回っている場合$L$、出力`-1`。 

### なぜ効果があるのか

 正しさは、すべての有効な解が構造ではなく、その合計によってのみ特徴付けられるという事実にかかっています。 すべての項目には正の重みがあるため、項目を追加しても合計は増加するだけです。 したがって、一度それを超えると、$L$を超えない限り、実現可能性が保証されます。$W$建設中。 

到達できなかった場合$L$これは、使用可能なすべての項目の合計でも不十分であるため、どのサブセットも下限制約を満たすことができないことを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, W = map(int, input().split())
    w = list(map(int, input().split()))

    L = (W + 1) // 2

    chosen = []
    total = 0

    for i, x in enumerate(w, 1):
        if x > W:
            continue
        if total + x <= W:
            chosen.append(i)
            total += x
        if total >= L:
            break

    if total < L:
        print(-1)
    else:
        print(len(chosen))
        print(*chosen)
```このソリューションは各項目を 1 回処理し、現在の合計と選択したインデックスのリストを維持します。 重要な判断ポイントはチェックです`total + x <= W`、これにより、建設中にナップザックの容量制限が厳密に適用されます。 早期停止条件により、下限が満たされた後に余分な項目が不必要に含まれないことが保証されます。 

この問題では元の項目インデックスが必要であるため、インデックス付けでは 1 から始まる位置が使用されます。

 ## 特殊なケース

 主なエッジ ケースは、すべての項目が個別に有効であるにもかかわらず、それらを組み合わせると制約が破られる場合です。 考慮する$W = 10$、重み$[6, 6]$。 それぞれ単体でも大丈夫ですが、両方摂取すると容量を超えてしまいます。 アルゴリズムは、次の値を超える追加を拒否するため、これを処理します。$W$、項目を 1 つだけ選択し、到達できない場合にのみ失敗します。$L = 5$。 この場合、いずれかの 6 を選択するとすでに条件が満たされているため、アルゴリズムはすぐに成功します。 

もう 1 つのケースは、すべてのアイテムが小さい場合です。$W = 9$、重み$[1,1,1,1,1,1,1,1,1]$。 アルゴリズムは少なくとも 5 に達するまで累積され、最初の 5 つの項目が選択されます。 超過するリスクは決してありません$W$、合計が十分であるため、累計は最終的な成功を保証します。
