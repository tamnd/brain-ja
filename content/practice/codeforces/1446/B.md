 ## 解決策
 ## 問題の理解

 文字列として表現された 2 つのエッセイがあり、それらの間で最も疑わしい重複部分を見つけたいと考えています。 重複は、2 つの部分文字列の最も長い共通部分列の長さの 4 倍からそれらの長さの合計を引いたものとして定義される類似性スコアを使用して測定されます。 言い換えれば、2 つの部分文字列が同じ順序で多くの文字を共有している場合、共有部分がそれらの合計の長さに比べて長い場合、スコアはプラスになり、より大きくなります。 

入力では、2 つのエッセイの長さが提供され、その後にエッセイ自体が続きます。 出力は、最初のエッセイの任意の部分文字列と 2 番目のエッセイの任意の部分文字列の間で達成可能な最大の類似性スコアを表す単一の整数である必要があります。 

この制約により、各エッセイの長さは最大 5000 文字になります。 すべての部分文字列のペアを調べる単純なアプローチでは、部分文字列を列挙するだけで O(n² * m²) の演算が必要になります。これは最悪の場合で約 6.25 × 10¹³ となり、1 秒の制限時間内ではまったく実行不可能です。 これは、すべての部分文字列ペアに対する反復処理を避けるために、問題の構造を利用する必要があることを示しています。 

明らかではないエッジ ケースには、単一の一致する文字など、最適な部分文字列が極端に短い場合や、あるエッセイが他のエッセイと完全に異なる状況が含まれます。 たとえば、次の場合`A = "aaa"`そして`B = "bbb"`、すべての LCS 値がゼロであるため、最大スコアは負になります。 不用意なアプローチでは、部分文字列が長いほど常に高いスコアが得られると想定する可能性がありますが、スコアによって部分文字列の全長が減点されるため、これは保証されません。 

## アプローチ

 ブルートフォースソリューションでは、次のすべての部分文字列を反復処理します。`A`そして`B`、LCS を計算し、スコアを評価します。 このアプローチは問題ステートメントを直接実装しているため、原理的には正しいですが、O(n² * m² * min(n,m)) の演算が必要です。 n、m = 5000 の場合、これは実現可能性をはるかに超えているため、より賢明な方法が必要です。 

重要な点は、この問題では完全な文字列の LCS が必要ではなく、任意の位置で開始および終了する部分文字列の LCS が必要であるということです。 文字列の位置に対する動的プログラミングを考慮すると、任意の位置のペアで終わる最大スコアを計算できます。`(i,j)`O(n*m) 時間で。 具体的には、`dp[i][j]`で終わる部分文字列の最高スコアを表します`A[i-1]`そして`B[j-1]`。 もし`A[i-1]`マッチ`B[j-1]`、前の部分文字列スコアを 2 だけ拡張できます (4×1 − 1 − 1 = 2 であるため)。それ以外の場合、スコアは 0 にリセットされます。 これにより、問題は標準の最長共通部分文字列 DP の変形に変換されますが、スコアリング ルールが変更されます。 

移行は、`dp[i][j] = max(0, dp[i-1][j-1] + 2)`文字が一致する場合はゼロ、そうでない場合はゼロ。 すべてのペアを反復処理する`(i,j)`表示された最大スコアを追跡します。 この DP の時間と空間の複雑さは O(n*m) であり、制約を考慮すると実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² * m² * 分(n,m)) | お(1) | 遅すぎる |
 | 部分文字列上の DP | O(n * m) | O(n * m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力の読み取り: 長さ`n`そして`m`、および文字列`A`そして`B`。 
2. 2D 配列を初期化する`dp`サイズの`(n+1) x (m+1)`ゼロ付き。 これにより、各位置で終わる部分文字列の最大類似性スコアが保存されます。 
3. 変数を初期化する`answer`ゼロにすると、全体の最大スコアが追跡されます。 
4. 各文字位置を反復処理します。`i`で`A`そして`j`で`B`。 
5. もし`A[i-1]`マッチ`B[j-1]`、 セット`dp[i][j] = max(0, dp[i-1][j-1] + 2)`。 それ以外の場合は、設定します`dp[i][j] = 0`。 
6.アップデート`answer`現在の値の最大値になり、`dp[i][j]`。 
7. すべての位置を処理した後、印刷します。`answer`。 

このアルゴリズムが機能する理由は、`dp[i][j]`は常に、次で終わる部分文字列の最大類似性スコアを表します。`i-1`そして`j-1`。 文字が一致したときに以前のスコアを引き継ぐことにより、合計の長さに自動的にペナルティを課しながら、共有文字の寄与を正しく蓄積します。 ゼロ リセットは、部分文字列定義に合わせて、一致しないシーケンスの拡張を防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
A = input().strip()
B = input().strip()

dp = [[0] * (m + 1) for _ in range(n + 1)]
answer = 0

for i in range(1, n + 1):
    for j in range(1, m + 1):
        if A[i - 1] == B[j - 1]:
            dp[i][j] = max(0, dp[i - 1][j - 1] + 2)
        else:
            dp[i][j] = 0
        answer = max(answer, dp[i][j])

print(answer)
```の`dp`簡単にするために配列のインデックスは 1 です。 に2を加えます`dp[i-1][j-1]`新しい一致文字が寄与するために文字が一致する場合`4*1 - 1 - 1 = 2`スコアに。 ゼロ リセットにより、部分文字列制約を考慮して、連続した一致シーケンスのみが寄与することが保証されます。
