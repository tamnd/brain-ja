 ## 問題の理解

 課題は、各桁が固定数の点灯セグメントを消費するデジタル表示モデルを使用して、可能な最大の整数を構築することです。 各テストケースには予算が与えられます`n`、これはオンにできるセグメントの合計数です。 セグメントコストの合計が超えない限り、必要な数の桁を配置できます。`n`。 目標は、結果として得られる数値の数値を最大化することです。 

重要な微妙な点は、桁数を最大化しようとしたり、未使用のセグメントを最小化しようとしているのではなく、制約の下で辞書編集上最大の数を試行していることです。 これは、高い桁が優先されるべきであることをすぐに示唆しますが、より多くのセグメントを消費する可能性があるため、桁の値とコストの間にはトレードオフがあります。 

制約`n ≤ 10^5`テスト ケースごとの合計は次のとおりです`10^5`、数字パーティションに対する指数検索または組み合わせ検索を除外します。 どのソリューションも、テスト ケースごとに線形またはほぼ線形の時間で実行する必要があります。 

素朴な間違いは、残ったセグメントを考慮せずに、可能な限り最大の桁を貪欲に繰り返し選択する必要があると想定することです。 たとえば、常に選択する`9`最初の数字が小さければ、最終的な数字を長くしたり、大きくしたりできたとしても、残りのセグメントが有効な数字の組み合わせを形成できないという行き止まりにつながる可能性があります。 もう 1 つの微妙な失敗は、最初に桁数を最大化しようとすることで発生します。これにより、生成される桁数は多くなりますが、先頭の桁が小さくなり、最終的な数値が減少する可能性があります。 

正しいアプローチは、1 つの数字の配置戦略だけが他のすべての戦略を支配することを認識することにかかっています。つまり、セグメント コストが最小の数字をできるだけ多く使用し、同時に左から数字をアップグレードして価値を最大化することです。 

## アプローチ

 各桁には固定のセグメントコストがあり、総予算内で可能な限り最大の数を組み立てたいと考えています。 ブルートフォース解釈では、コストの合計が最大で`n`、次に最大数値を計算します。 これは正しいですが、シーケンスの数が指数関数的に増加するため、実行不可能です。`n`、おおよそ次のオーダーです`10^n`最悪の場合。 

すべての数字のうち、数字が`1`使用するセグメントが最も少ない (2)。 これにより、長さを最大化するのに最適になります。より高いコストで数字を置き換えるソリューションは、潜在的に複数の数字に置き換えられる可能性があります。`1`s、正しく配置されていれば、桁数が増加し、したがって辞書編集上の値が増加します。 したがって、最適な戦略は、次を使用して桁数を最大化することです。`1`次に、コスト予算を尊重しながら、いくつかの上位の順位をより大きな桁にアップグレードすることで、結果を改善します。 

重要な洞察は、最初に のみを使用して可能な限り長い数値を構築するということです。`1`s. 次に、大きい桁は常に上位にあるほど価値があるため、先頭を貪欲に置き換えようとします。`1`s は、置換が残りのセグメント バジェットを超えない最大の桁を持ちます。

 ## アルゴリズムのチュートリアル

 1. 各桁のセグメントコストを次から事前計算します。`0`に`9`。 これにより、置換を評価するときに定数時間の検索が可能になります。 
2. 各テストケースについて、数字のみを使用した場合に配置できる数字の数を計算します。`1`、コストが最小 (2 セグメント) であるためです。 これにより、`k = n // 2`。 
3. もし`k`がゼロの場合、一桁の数字を置くことさえできませんが、`n ≥ 2`、これは決して起こりません。 結果を次の文字列として初期化します。`k`もの。 
4. このベースライン数を形成した後に余分なセグメントがいくつ残るかを計算します。`remaining = n % 2`。 
5. 左から右に数値を改善しようとします。 位置ごとに、現在の数字を置き換えることができるかどうかを確認します`1`より大きな桁で`d`。 価格差があれば交換は有効です`(cost[d] - cost[1])`残りの予算以下です。 
6. 交換が可能な場合は、その桁を割り当て、それに応じて残りの予算を減らします。 辞書編集上の値を最大化するために、常に最初に大きな桁を試します。 
7. これ以上アップグレードできなくなるか、すべてのポジションが処理されるまで続行します。 

### なぜ効果があるのか

 構築は常に可能な最大桁数から始まります。桁の配置を制御できる場合、桁数を増やすと常に辞書編集上の順序が改善または維持されるため、これが最適です。 長さが固定されたら、より高い位置の桁を増やすことで改善する必要があります。 より重要な位置にある数字を置き換えることは、後の数字を置き換えるよりも常に優先されるため、可能な限り最大の数字で貪欲に左から右にアップグレードすることで最適性が維持されます。 不変条件は、すべてのステップにおいて、これまでに構築されたプレフィックスが、残りの予算内で最適なソリューションを実現するための最良のプレフィックスであるということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

cost = [0] * 10
cost[0] = 6
cost[1] = 2
cost[2] = 5
cost[3] = 5
cost[4] = 4
cost[5] = 5
cost[6] = 6
cost[7] = 3
cost[8] = 7
cost[9] = 6

for _ in range(int(input())):
    n = int(input())

    k = n // 2
    res = ['1'] * k

    remaining = n - 2 * k

    for i in range(k):
        for d in range(9, -1, -1):
            if i == 0 and d == 0:
                continue
            if cost[d] <= 2 + remaining:
                if d != 1:
                    remaining -= (cost[d] - 2)
                res[i] = str(d)
                break

    print("".join(res))
```コードは、セグメント コストをエンコードすることから始まります。これにより、桁構造を繰り返し再計算することが回避されます。 各テスト ケースのベースライン構築では数字のみが使用されます。`1`長さを最大化するために。 からの数字のループ`9`まで`0`常に最も価値のある置換を最初に試みることが保証されます。 

条件`i == 0 and d == 0`数値を増やさずに人為的に桁数を増やす先行ゼロを防ぎます。 残りの予算は、実際にアップグレードした場合にのみ調整されます。`1`、ベースラインですでにコストが考慮されているため、`2`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    cost = [0] * 10
    cost[0] = 6
    cost[1] = 2
    cost[2] = 5
    cost[3] = 5
    cost[4] = 4
    cost[5] = 5
    cost[6] = 6
    cost[7] = 3
    cost[8] = 7
    cost[9] = 6

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        k = n // 2
        res = ['1'] * k
        rem = n - 2 * k

        for i in range(k):
            for d in range(9, -1, -1):
                if i == 0 and d == 0:
                    continue
                if cost[d] <= 2 + rem:
                    if d != 1:
                        rem -= (cost[d] - 2)
                    res[i] = str(d)
                    break

        out.append("".join(res))

    return "\n".join(out)

 ## 特殊なケース

 最小の有効な入力の場合`n = 2`、アルゴリズムは正確に 1 桁を生成します`"1"`アップグレードは不可能なので。 建設は次から始まります`k = 1`、以外の数字はありません`1`桁数を減らすことなくコスト制約内に収まるため、出力が安定します。 

場合については、`n`2 の倍数のすぐ上の値です。たとえば、`n = 3`、アルゴリズムは依然として 1 桁を構築し、追加のセグメントを使用してその桁をアップグレードします。 これは、残りの容量が常に長さの増加ではなく桁値の改善に消費されることを示しており、これは整数を最大化するための最適な構造と一致します。
