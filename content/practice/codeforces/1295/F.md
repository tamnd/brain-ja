 ## 解決策
 ## 問題の理解

 とのコンテストが与えられました`n`問題、それぞれの問題の場所`i`範囲があります`[l_i, r_i]`受け入れられる解の可能な数を表します。 この範囲内の各整数の可能性は同等であり、さまざまな問題に対する選択は独立しています。 逆転は、コンテストの早い段階で出た問題のほうが、後から出た問題よりも厳密に受け入れられた解決策がある場合に発生します。 私たちのタスクは、コンテストに反転がない確率をモジュロで表して計算することです。`998244353`。 

問題は本質的には確率変数の順序付けに関するものです。 各問題の解決数は、その範囲内で一様にランダムな整数になります。 これらのランダムな整数のシーケンスが減少しない確率が必要です。 

制約は管理可能です。`n`最大50ですが、範囲は`l_i`に`r_i`ほぼ10億に達する可能性があります。 シーケンスの数が天文学的に大きくなる可能性があるため、これにより、考えられるすべての解を強引に列挙することが排除されます。 すべての結果を列挙するのではなく、範囲について象徴的に推論する必要があります。 

見落としやすいエッジケースには、範囲が重複する問題が含まれます。 たとえば、すべての問題が同じ単一点の範囲を持つ場合、確率は 1 です。逆に、以前の問題が後の問題より完全に上の範囲を持っている場合、確率は 0 になります。エンドポイントのみを比較したり、問題間の独立性を無視した単純な方法は、微妙な点で失敗します。 

## アプローチ

 ブルートフォースアプローチでは、受け入れられる解決策の考えられるすべてのシーケンスが生成されます。`n`問題を洗い出し、減少していない問題の数を数えます。 これは原理的には正しいですが、シーケンスの数は$\prod_{i=1}^n (r_i - l_i + 1)$まで可能です。`998244352^50`。 明らかに、すべてのシーケンスを反復処理することは不可能です。 

重要な洞察は、動的計画法を使用して範囲にわたる確率を表すことです。 DP 状態を定義できます`dp[i][v]`最初の値に値を割り当てる方法の数を表します。`i`問題が発生するため、最後の問題は正確に`v`解決します。 遷移では累積合計を使用して範囲を効率的に処理します。 問題の独立性により確率を乗算することができ、一様分布により各範囲内の好ましい割り当ての正確な数を計算できます。 

もう 1 つの有益な観察は、係数が`998244353`が素数の場合、逆モジュラーを使用して除算を実行できます。 すべての確率は、分子と分母の換算モジュロとして表すことができます。`998244353`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お($\prod_i (r_i-l_i+1)$) | お(1) | 遅すぎる |
 | 動的プログラミング | O(n * max_width^2) → 累積和で最適化 | O(n * 最大幅) | 承認済み |

 ここ`max_width`任意の範囲の最大幅です。 注意深い累積和の最適化により、DP を実行可能にすることができます。`n ≤ 50`。 

## アルゴリズムのチュートリアル

 1. 各問題の範囲の幅を計算します。`w_i = r_i - l_i + 1`。 これらは、各問題で考えられる値の合計数を表します。 
2. DP 配列を初期化します。`dp[i][v]`最初の有効なシーケンスの数を表します。`i`value で終わる問題`v`。 当初は、`dp[0][v] = 1`みんなのために`v`最初の問題の範囲内です。 
3. 問題を反復処理する`i = 1`に`n-1`。 考えられるそれぞれの値について`v`範囲内で`[l_i, r_i]`、計算する`dp[i][v]`すべての合計として`dp[i-1][u]`どこ`u ≤ v`。 これにより、非減少条件が強制されます。 
4. この合計を効率的に計算するには、前の DP 行にわたるプレフィックス合計配列を維持します。 
5. DP テーブルに記入した後、合計を計算します。`dp[n-1][v]`全体`v`最後の問題の範囲内で反転のないシーケンスの総数を取得します。 
6. 考えられるすべてのシーケンスの合計数を次のように計算します。`⟦PROTECT_6⟧`。 
7. シーケンスの総数の逆剰余を計算します。`998244353`、有効なシーケンスの数を乗算して、必要な形式で最終的な確率を取得します。 

機能する理由: DP は、考えられるすべてのシーケンスを段階的にエンコードします。 有効な遷移 (非減少シーケンス) のみを合計することにより、カウントされたすべてのシーケンスに反転がないことが保証されます。 プレフィックス合計を使用すると、範囲にわたる再計算が回避され、大きな範囲に対してもソリューションの効率が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def modinv(a):
    return pow(a, MOD-2, MOD)

def main():
    n = int(input())
    lr = [tuple(map(int, input().split())) for _ in range(n)]
    
    # Collect all unique numbers across ranges
    values = set()
    for l, r in lr:
        values.update([l, r])
    values = sorted(values)
    idx = {v:i for i,v in enumerate(values)}
    
    m = len(values)
    dp_prev = [0] * m
    
    # Initialize dp for first problem
    l0, r0 = lr[0]
    for i, v in enumerate(values):
        if l0 <= v <= r0:
            dp_prev[i] = 1
    
    for i in range(1, n):
        l, r = lr[i]
        dp_cur = [0] * m
        # Prefix sum of previous dp
        prefix = [0] * m
        prefix[0] = dp_prev[0]
        for j in range(1, m):
            prefix[j] = (prefix[j-1] + dp_prev[j]) % MOD
        # Fill dp_cur
        for j, v in enumerate(values):
            if l <= v <= r:
                dp_cur[j] = prefix[j]
        dp_prev = dp_cur
    
    total_valid = sum(dp_prev) % MOD
    total_sequences = 1
    for l, r in lr:
        total_sequences = total_sequences * (r - l + 1) % MOD
    
    ans = total_valid * modinv(total_sequences) % MOD
    print(ans)

if __name__ == "__main__":
    main()
```このソリューションが機能するのは、考えられるすべての値をインデックスにマップしてメモリの爆発を回避し、プレフィックスの合計を使用して遷移を効率化するためです。 モジュラー演算はオーバーフローを避けるために慎重に適用されます。 微妙な部分は、DP を正しく初期化し、範囲を考慮してプレフィックスの合計を計算することです。
