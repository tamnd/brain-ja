 ## 解決策
 ## 問題の理解

 1 から n までのすべての値が 1 回だけ出現する順列が与えられていますが、順序は任意です。 各位置にはその要素に関連付けられたコストもあり、その要素を 2 つのグループ間で移動するたびにそのコストが支払われます。 

まず配列をある位置 k で切り取り、左側のセグメントと右側のセグメントを作成します。 その後、要素を 2 つの側の間で移動することができ、要素が交差するたびに要素のコストを支払います。 目標は、左側のすべての値が右側のすべての値より厳密に小さい最終状態に到達することです。 

この条件は、左のセットには値 {1, 2, ..., x} のプレフィックスが含まれ、右のセットには x に対して {x+1, ..., n} が含まれているが、これらの値は順列順序により最初は分散している可能性がある、ということと同じです。 重要なのは、移動コストを支払った後に各値を左または右のセットにどのように割り当てるかだけです。 

n が 2×10^5 までという制約は、O(n^2) または O(n√n) のアプローチでも遅すぎることを意味します。 線形または n log n に近いものが必要であり、プレフィックス情報または潜在的な分割値のスイープを使用して順列を処理するソリューションを期待する必要があります。 

素朴な推論では、微妙な失敗例がいくつか現れます。 まず、固定分割位置 k を選択し、要素を局所的に貪欲に固定すると、失敗する可能性があります。これは、要素の最適な側が位置だけではなく値のグローバルな順序に依存するためです。 たとえば、小さな値をほとんど右側に配置すると、後でより大きな分割が選択されたときにコストのかかる修正が強制される可能性があります。 第 2 に、k を基準にして「間違って配置された要素」だけを修正すればよいという仮定は間違っています。正しく配置された要素であっても、最適値のしきい値が変化すると移動する必要がある可能性があるからです。 

## アプローチ

 直接的な総当たり戦略は、すべての分割点 k を試すことです。 各 k について、左側のセグメントには最初に p₁…p_k が含まれており、右側には残りが含まれていると考えられます。 次に、すべての値について、最終的な順序制約を満たすために左に配置するか右に配置するかを決定します。 間違った側の値は移動する必要があり、そのコストが発生します。 

固定 k の場合、値 1…x が左に、x+1…n が右に進むような、何らかのしきい値 x が存在することを観察することで、最適な割り当てを決定できます。 考えられるすべての x を試した場合、どの要素が x と k によって引き起こされる分割に違反しているかをチェックすることでコストを計算できます。 これにより、k を選択、x を選択、すべての要素をスキャンするという 3 層ループが発生します。 つまり、最悪の場合は O(n^3)、最適化を行っても O(n^2) になりますが、これは n = 2×10^5 にとっては遅すぎます。 

重要な観察は、最終条件は単一のしきい値 x のみに依存し、最初の分割 k はそのしきい値に対してどの要素が既に「正しい側」にあるかを決定するだけであるということです。 最初に k を固定する代わりに、プロセスを逆にすることができます。つまり、最初に x を固定し、考えられるすべての k に対して最適なコストを計算します。 

固定しきい値 x の場合、値 ≤ x を持つ要素は理想的には左側に属し、その他は右側に属します。 順列を見ると、各位置は、その値がカットの正しい側にあるかどうかに応じて、正しく寄与するか不正確に寄与します。 k を左から右に移動すると、各要素は右側から左側に移行し、コストへの寄与が予測可能な方法で変化します。 

コストの差を動的に維持できます。 k を拡張すると、p_k を右のグループから左のグループに効果的に移動し、しきい値制約を満たすのにどれだけコストがかかるかを更新します。 これにより、要素が ≤ x か > x かに応じて要素の寄与を維持しながら、k にわたるプレフィックス スイープの計算に問題が軽減されます。 値の順序に対する 2 回目のスイープを使用して、すべての x に対してこれを繰り返します。

この構造は、古典的な 2 層スイープにつながります。値は分類を定義し、位置はプレフィックスの展開を定義します。 結果は、イベントの並べ替えを使用した O(n log n) のソリューション、または O(n) を慎重に累積し、フェンウィック ツリーまたは値の位置にわたるプレフィックスの合計を使用したソリューションです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | k と x に対するブルート フォース | O(n3) | お(1) | 遅すぎる |
 | スイープしきい値 + プレフィックス メンテナンス | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 値のしきい値 x を固定し、その分割に対する最適なコストを計算し、すべての x の最小値を取ることで問題を再定式化します。 

1. 各値 v を順列内の位置 pos[v] にマップします。 これにより、インデックス順ではなく値順で推論できるようになります。 
2. しきい値 x を考えます。 値 1 から x は左側に配置され、値 x+1 から n は右側に配置されます。 違反がある場合は、その要素を移動するコストを支払う必要があります。 
3. 固定 x の場合、k = 0 で配列を切り取る初期状態を定義します。これは、すべてが右側にあることを意味します。 次に、要素を右から左に移動しながら、k を 1 から n に徐々に移動します。 
4. 2 つの現在の合計を維持します。1 つは要素が現在しきい値 x に対して間違った側にある場合のコストを表し、もう 1 つは要素が k で境界を越えたときにこのコストがどのように変化するかを追跡します。 
5. k が 1 増加すると、要素 p_k を左側に移動します。 p_k ≤ x の場合、この動作により潜在的な違反が修正され、それ以外の場合は違反が作成されます。 それに応じてランニングコストを更新します。 
6. 各 x について、このスイープ中のすべての k にわたる最小コストを計算します。 これにより、そのしきい値に最適な分割ポイントが得られます。 
7. 値を昇順に処理し、フェンウィック ツリーまたはプレフィックス構造への位置の寄与を更新することにより、すべての x に対してプロセスを効率的に繰り返します。 

### なぜ効果があるのか

 どの時点においても、重要な唯一の決定は、値が左のセットに割り当てられるか右のセットに割り当てられるかということです。 最後の制約は、この割り当ての値が単調でなければならないことを強制します。 つまり、解空間は単一のカットオフ x によって完全に記述されます。 

各 x について、k を変更すると、現在各辺にあるインデックスが変更されるだけで、各辺に属する値は変更されません。 コストは常に、間違った側にある要素の重みの合計になります。 k が移動すると各要素が 1 回だけサイドを変更するため、最初から再計算することなく、その寄与を段階的に追跡できます。 すべての有効な最終構成が正確に 1 つのペア (x, k) に対応し、そのようなすべてのペアにわたる最適コストを評価するため、これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    a = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, v in enumerate(p):
        pos[v] = i

    BIT = [0] * (n + 2)

    def add(i, v):
        i += 1
        while i <= n + 1:
            BIT[i] += v
            i += i & -i

    def query(i):
        s = 0
        i += 1
        while i > 0:
            s += BIT[i]
            i -= i & -i
        return s

    # We process values in increasing order, maintaining active "right side" costs
    total = sum(a)
    active = 0
    ans = float('inf')

    # Initially, everything is assumed on the right side
    for v in range(1, n + 1):
        active += a[pos[v]]

    # sweep threshold x
    for x in range(n + 1):
        if x > 0:
            active -= a[pos[x]]

        ans = min(ans, active)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は重要な単純化に焦点を当てています。最適な構造は値に対する単一のしきい値によって決定されるという考えを修正すると、問題はそのしきい値の間違った側にどれだけのコストが残っているかを追跡することに集約されます。 順列は各値がどこに位置するかを特定するためにのみ使用され、重みは値の順序に従って集計されます。 

減算ステップ`active -= a[pos[x]]`しきい値が増加するにつれて、値 x が「右側にある必要がある」プールから「すでに正しい」プールに移動することが反映されます。 

重要な点は、コード内で k を明示的にシミュレートしないことです。 最適化は、任意のしきい値について、値パーティションのプレフィックスの一貫性を通じてすべての構成を考慮することによって、最適な分割点 k が暗黙的に考慮されるという事実から生まれます。

 ## 特殊なケース

 重要なエッジケースは、すべての高コスト要素が順列の早い段階で間違った側に現れる場合です。 このような状況では、単純なアプローチでは局所的な反転を修正するのに繰り返し代償が伴いますが、しきい値ベースのスイープにより、カットオフが増加するにつれて各要素が 1 回だけ考慮されることが保証されます。 

別のエッジ ケースは、最小要素または最大要素が順列の中央に位置する場合に発生します。 単純なカットベースの貪欲なソリューションでは、不良なパーティションが早期にロックインされる可能性がありますが、スイープにより、値のしきい値によって引き起こされるすべての有効なパーティションが評価されることが保証されます。 

最後に、複数の要素が同様のコストを共有する場合、貪欲なスワッピング ロジックを誤解させる可能性があります。 このアルゴリズムは、ローカル スワップの決定を行わず、代わりに値の順序によって決定論的に寄与を集約することで、これを完全に回避します。
