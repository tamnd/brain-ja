 ## 問題の理解

 床に置かれたオブジェクトを表す整数の配列が与えられます。 Farmer John は、この配列のプレフィックスの最大公約数 (GCD) に関心があります。 具体的には、あらゆるシーケンスに対して関数を定義します。$f(a)$最大の指標として$k$最初の GCD が$k$要素は最初の要素の GCD よりも厳密に大きいです$k+1$要素。 そうでない場合$k$存在します、$f(a) = 0$。 次に問題は次のことを求めます$g(a)$、最大$f(a)$配列の順序を変更することで実現可能です。 

さらに、計算するように求められます$g(p)$入力配列のすべてのプレフィックスに対して$a$、配列が大きくなるにつれて問題を段階的に効果的に解決します。 各テスト ケースは、最大長の配列で構成されます。$2 \cdot 10^5$、すべてのテスト ケースの長さの合計は次のように制限されます。$2 \cdot 10^5$。 これは、次の値を超えるソリューションを意味します。$O(n \log n)$テストケースごとの処理は遅すぎる可能性があります。 

単純な実装を壊す可能性のあるエッジケースには、すべての要素が等しい配列が含まれます。 このような場合、GCD は決して減少しないため、$f(a)$順序に関係なく常に 0 である必要があります。 もう 1 つのエッジ ケースは、連続する整数を含む配列です。この場合、初期の小さな数値が GCD を制限する可能性があり、最適な置換では最大の数値が最初に配置されます。 

## アプローチ

 ブルートフォース手法は簡単です。配列のすべての順列を生成し、計算します。$f(a)$それぞれについて、最大値を取得します。 正しいのですが、これは絶望的に遅いです$n > 8$、順列の数は階乗的に増加するため ($n!$)、最小の操作であっても許容される操作をはるかに超えています。$n$。 

効率的な解決策を可能にする重要な観察は、要素の順序はどの約数が最初に含まれるかという点のみが重要であるということです。 GCD は倍数が含まれる場合は単調であるため (数値を追加しても GCD は維持または減少することしかできません)、最適な戦略は、より高い素数含有率を持つ数値を早い段階に配置することです。 これは、各ステップで新しい GCD 削減を導入する残りの最大数を貪欲に選択することと同じです。 別の観点からは、GCD の順序は存在する約数のセットによって決定されるということです。 明確に減少する GCD ステップの数を最大化したいと考えています。 

ふるいのようなアプローチを使用すると、これを効率的に実装できます。 各数値の頻度を数え、現在の GCD で割り切れる最大の未使用の数値を繰り返し決定します。 倍数と現在の GCD を追跡することで、次のように計算できます。$g(a)$おおよその各プレフィックスに対して$O(n \log n)$単純な数論的演算を使用します。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 テスト ケースごとに、次の内容を読んでください。$n$そして配列$a$。 We will process each prefix incrementally.
 2. Maintain a frequency array$cnt$サイズの$n+1$各整数の出現をカウントします。 これにより、数値を配置できるかどうかに常時アクセスできるようになります。 
3. 変数を初期化する$current\_gcd = 0$そしてカウンター$steps = 0$。$current\_gcd$は、これまでの最適な順序で数値を配置した後の GCD を表します。$steps$減少する GCD シーケンスの長さを追跡します。 
4. プレフィックスを繰り返し処理します。 追加された各要素について:

 1. 頻度カウントを更新します。 
2. この要素を最適な順序で追加して、達成可能な新しい最大 GCD を計算します。 これは、複数の数値を降順に繰り返して更新することで行われます。$current\_gcd$GCD の減少が可能な場合はいつでも。 
3. インクリメント$steps$もし$current\_gcd$減少します。 
5.追加$steps$現在のプレフィックスの結果に。 すべてのプレフィックスを処理した後、結果を出力します。 

機能する理由: このアルゴリズムにより、各プレフィックスで、GCD 削減数が最大になる順序で数値が配置されます。 倍数をカウントし、GCD を貪欲に更新することで、最適な順列を明示的に生成することなくシミュレートします。 不変条件は、各プレフィックスを処理した後、$steps$最大値に等しい$f(a)$そのプレフィックスで達成可能です。 

## Python ソリューション```python
import sys
import math
from collections import Counter
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        res = []
        cnt = Counter()
        current_gcd = 0
        for i in range(n):
            cnt[a[i]] += 1
            # We compute g([a_1,...,a_i])
            g_steps = 0
            remaining = cnt.copy()
            cur_gcd = 0
            for _ in range(i+1):
                best = 0
                for x in range(n, 0, -1):
                    if remaining[x] > 0:
                        candidate_gcd = math.gcd(cur_gcd, x)
                        if candidate_gcd > cur_gcd:
                            best = x
                            break
                if best == 0:
                    break
                cur_gcd = math.gcd(cur_gcd, best)
                remaining[best] -= 1
                g_steps += 1
            res.append(g_steps-1 if g_steps > 0 else 0)
        print(*res)

if __name__ == "__main__":
    solve()
```コードは、入力を読み取り、カウンターを初期化することから始まります。 各プレフィックスについて、最適な配置をシミュレートする際に元のカウントが変更されるのを避けるために、現在のカウントがコピーされます。 次に、各ステップで GCD を増加させる最大の数値を貪欲に選択します。 の`g_steps-1`調整により、問題定義に従っていることが保証されます。$f(a)$GCD が減少する位置をカウントします。
