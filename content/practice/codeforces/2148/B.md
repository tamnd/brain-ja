 ## 解決策
 ## 問題の理解

 原点から目標点まで格子状の平面上で作業を行っていますが、その平面には壁によって遮られる代わりに、無限に薄い障害物が含まれています。 それらの中には、固定の Y レベルで長方形の全幅に広がる水平セグメントもあれば、固定の X 位置で下から上に伸びる垂直セグメントもあります。 

連続曲線を使用して左下隅から右上隅に移動する場合、これらのセグメントの 1 つを横切るたびに 1 のコストを支払います。 交差が水平セグメントと垂直セグメントの交差点で正確に発生した場合、両方がカウントされます。 

課題は、そのような交差点の数を最小限に抑えるパスを選択することです。 

この制約は、パスをシミュレートしたり、幾何学的検索を実行したりできないことを即座に示唆しています。 テストごとに最大 200,000 のセグメントと 10,000 のテスト ケースがあるため、パスについて明示的に推論しようとしたり、交差点を幾何学的に処理したりするアプローチは爆発的に増加します。 唯一の実行可能な解決策は、ソートされた座標セット間の構造的相互作用をカウントすることに問題を縮小するものです。 

水平線と垂直線の両方が同じ点で交差する場合、微妙なエッジケースが発生します。 素朴な直感では、飛行機を複数の領域に分割されたものとして扱い、それらの間の遷移をカウントしようとするかもしれませんが、それは交差点ペナルティを過小評価する危険性があります。 たとえば、y = 1 の水平線と x = 1 の垂直線の両方を同時に横切った場合、コストは 1 ではなく 2 になります。 

もう 1 つの故障モードは、水平方向と垂直方向の交差を独立してカウントできると仮定することで生じます。 これはベースラインを提供しますが、連続空間内で交差点の周りを「ルーティング」することで、いくつかの交差点を完全に回避するパスを選択できることを無視しています。 

## アプローチ

 最適なパス設計を無視し、代わりに単に (0,0) から (x,y) まで単調に移動すると仮定すると、パスが a の下から a 上に移動する場合、高さ a にあるすべての水平線は少なくとも 1 つの交差に寄与し、b の左から b の右に移動する場合、位置 b にあるすべての垂直線は少なくとも 1 つの交差に寄与します。 これはすでに単純な上限を示唆しています。つまり、すべての水平線とすべての垂直線を横切ることになります。 

これは正しいですが、最小限ではありません。 重要な観察は、不必要な交差を避ける方法で、水平方向と垂直方向の動きを交互に配置するパスを自由に選択できるということです。 すべての垂直線を一度に横断する代わりに、ソートされた垂直レーザーの x 座標間、および同様に水平レーザーの y 座標間での移動を「段階的に」構造化できます。 

連続する 2 本の垂直線の間は、垂直方向の横断帯を通過することなく自由に上下に移動できる垂直帯の中にいます。 このようなストリップ内では、y 軸順序のストリップ間の遷移を強制する水平線からのみ避けられないコストが発生します。 対称的に、x 間隔を越えて移動する場合、水平線の間で垂直方向の交差が避けられません。 

重要な洞察は、最適なパスは、ソートされた x および y レーザー位置によって引き起こされるグリッドを交互に通過するものとして解釈できるということです。 垂直線を通過するたびに、まだ「クリア」していないすべての水平線と相互作用する可能性があり、その逆も同様です。 ただし、すでに考慮されている構造を繰り返し通過しないようにトラバースを調整することで、繰り返しのペナルティを最小限に抑えることができます。 

これは、非常に単純な組み合わせ構造に帰着します。最適な交差数は、ペアリング構造によってキャンセルされずに残っている「アクティブな」水平および垂直セグメントの数によって決まり、答えは最終的に n と m で線形になりますが、エンドポイントの相互作用パターンによって調整されます。

最後の単純化は、各水平セグメントは、垂直セグメントによって「分離」されているかどうかに応じて 1 つまたは 2 つの避けられない交差に寄与し、垂直セグメントについても同様です。 配列はソートされているため、それらを貪欲に処理し、事実上「ペアになっている」セグメントと「ペアになっていない」セグメントの数をカウントできます。

 ## アルゴリズムのチュートリアル

 1. ソートされた水平座標 a と垂直座標 b の配列を読み取ります。 ソートの保証は、単調な順序でセグメントを推論できるため、非常に重要です。 
2. 水平配列と垂直配列の 2 つのポインター i と j を初期化します。 これらのポインタは、2 つのファミリー間の交差がどの程度「同期」されているかを表します。 
3. 両方の配列を貪欲に移動し、結合されたスイープ内の小さい次の境界を表すポインタを常に進めます。 この選択の理由は、次に避けられないイベントが常にどちらかの軸に沿った次に小さい座標であるためです。 
4. 1 つの配列内を進むたびに、そのセグメントを他の配列内のセグメントとペアにすることができるかどうかを決定します。 ペアリングは、構造上の最小値を超えて余分な迂回を強いることがないように、水平方向と垂直方向の交差点を整列させることができる状況に対応します。 
5. 一致しないセグメントのカウンタを維持します。 セグメントをペアにできないたびに、避けられない交差コストが 1 単位発生します。 
6. 1 つの配列が使い果たされると、もう 1 つの配列に残っているすべてのセグメントは必然的にペアが解除され、答えに直接寄与します。 

### なぜ効果があるのか

 (0,0) から (x,y) への移動は、水平線と垂直線で形成されたグリッドを横切ると解釈できます。 両方のセットがソートされているため、最適なパスは、交差の数を変えることなく、座標の昇順で線と交差するパスに連続的に変形できます。 これにより幾何学的な自由がなくなり、問題は順序付けの制約に帰着します。 

この秩序構造内で唯一の自由度は、同じ構造段階で、あるファミリーとの交差を他のファミリーとの交差に「吸収」できるかどうかです。 グリーディ ポインタ プロセスは、まさにこの吸収を捉えています。小さい境界を前進させるたびに、可能な限り早い段階でそのラインを越えるように努め、後で強制的に追加で越えるのを最小限に抑えます。 これにより、再配置を行わなくても、避けられない交差点の総数を減らすことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, m, x, y = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        i = j = 0
        ans = 0
        
        while i < n and j < m:
            if a[i] < b[j]:
                ans += 1
                i += 1
            else:
                ans += 1
                j += 1
        
        ans += (n - i) + (m - j)
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、ソートされた両方の配列に対して同時にスイープを実行します。 ポインタの比較により、常に次に小さい座標が最初に処理されます。これは、パスの単調変形に沿った次の構造交差イベントに対応します。 

処理されたすべての境界が有効な走査で少なくとも 1 つの交差に寄与するため、各ステップで答えが増加します。 使い尽くされていない配列の残りの要素は、もう反対側の要素とペアにすることができないため、直接追加されます。 

実装の微妙な詳細は、比較の両方の分岐で答えが増加することです。 これは、最適なパスではすべての水平線または垂直線が少なくとも 1 回交差する必要があることを反映しており、ペアリングによってイベントをカウントする必要がなくなるわけではなく、通過順序をグループ化する方法にのみ影響します。

 ## 特殊なケース

 最初のエッジケースは、レーザーのファミリーが 1 つだけ存在する場合です。 水平線のみがある場合は、y を単調増加させることによって、各線を正確に 1 回交差するパスを選択できます。 垂直方向のポインター ループが実行されず、残りの水平方向がすべて直接追加され、n 個の交差が生成されるため、アルゴリズムはこれを処理します。 

2 番目のエッジ ケースは、両方の配列の最初の要素が、トラバーサルに関して大きさの順序が等しい場合です。 たとえば、a1 = b1 です。 この場合、アルゴリズムは一貫して垂直優先または水平優先の選択として扱います。 両方が存在する場合でもコストは全体で 2 増加し、交差点が 2 つの交差点に寄与するという要件と一致します。 

3 番目のエッジ ケースは、一方の配列が他方の配列よりもはるかに大きい場合です。 メイン スイープの後、残りのサフィックスが完全に追加されます。 これは、1 つのファミリーが使い果たされると、それ以上のペアリングは不可能になり、残りのセグメントはすべて独立して交差する必要があることを正しく反映しています。
