 ## 解決策
 ## 問題の理解

 私たちは、時間軸に沿った非常に単純な移動プロセスをシミュレートしています。ファーマー ジョンは毎分、ジムの現在の側に留まるか、反対側に走ります。 彼が走ることを選択するたびに、彼は 1 ポイントを獲得します。 ねじれは、特定の固定分ごとに、「オーディオ システム」によって、その分の開始時に彼がジムの特定の側にいることを強制されることです。 

面 0 の 0 分から開始します。時間は分 m まで離散的なステップで進み、各分の境界で面を反転するか、そのままになります。 ただし、一部の分には制約があります。分 a_i では、位置は b_i に等しくなければなりません。 これらの制約は時間に従って順序付けされます。 

目標は、強制的なポジションを決して侵さずに、走ることを選択した回数、つまり裏返しの回数を最大化することです。 

この構造は基本的に、強制チェックポイントを備えた時間の経過に伴うパスです。 2 つの連続する制約の間では、何度でも自由に反転できますが、2 回反転すると相殺されるため、重要なのはパリティだけです。 

この制約は、すべてのテストにわたって n が最大 2×10^5 であるのに対し、m は 10^9 まで大きくできることを意味します。 これにより、分単位のシミュレーションが即座に除外されます。 どのようなソリューションも、テスト ケースごとに最悪でも O(n) または O(n log n) で機能し、できれば線形で機能する必要があります。 

制約によって不可能な遷移が強制される場合、微妙なエッジ ケースが発生します。 たとえば:

 入力:```
1
2 5
2 0
2 1
```2 分の時点で、私たちは同時に両側にいることが求められます。 これは不可能であるため、有効なスケジュールは存在しません。 制約間の競合を無視する単純な貪欲な場合、誤って続行され、フリップを過剰にカウントしてしまいます。 

もう 1 つのエッジ ケースは、制約がまばらな場合です。```
1
1 10
5 1
```0 から開始し、5 分にはサイド 1 になければなりませんが、それ以外は完全に自由です。 単純なアプローチでは、強制的な遷移のみがカウントされ、制約の前後で振動する可能性があることを見逃してしまう可能性があります。 

主な難しさは、チェックポイント間の自由と強制的なパリティ変更を正しく組み合わせることです。 

## アプローチ

 ブルートフォース解釈では、0 から m までの各分をシミュレートし、考えられる両方の状態を追跡し、滞在と反転の両方を試行します。 これは概念的には正しいです。毎分、2 つの状態の間で分岐しますが、強制的な制約に達するたびに、無効な状態が除外されます。 

ただし、これによりテスト ケースあたり O(m) になりますが、m は最大 10^9 であるため、これは不可能です。 構造を使用せずに状態を圧縮しても、遷移は長い間隔にわたるパリティに依存するため、依然として行き詰まってしまいます。 

重要な観察は、連続する制約時間の間では、必要なエンドポイントの状態と、それらを接続するために奇数または偶数のフリップが必要かどうかという 2 つのことだけが重要であるということです。 すべてのフリップはサイドを切り替え、正確に 1 つのポイントを提供するため、間隔内のポイントを最大化するには、パリティを尊重しながらできるだけ多くのフリップを使用することになります。 

長さ L の任意の間隔について、その中に制約がなければ、1 分ごとに反転して L 点を与えることができます。 唯一の制限は、結果のパリティが次の強制状態と一致する必要があることです。 パリティが一致しない場合は、どこかで 1 つのフリップをスキップして調整する必要があるため、最大値と比較してちょうど 1 つのフリップが失われます。 

したがって、問題は、連続する制約ペアを処理し、エンドポイントの一貫性を確保しながら各セグメントで何回フリップできるかを計算することに帰着します。

 ## アルゴリズムのチュートリアル

 制約を時間の増加順に処理し、固定チェックポイントとして扱います。 また、時間 0 で状態 0 の暗黙的なチェックポイントと、強制状態を持たない時間 m での最終チェックポイントも含めます。 

1. 最後に既知の位置を時間 0 のサイド 0 として初期化し、初期応答を 0 として初期化します。これは開始条件を表します。 
2. 各制約を順番に繰り返します。 必要な辺 s を持つ時刻 t での制約の場合、前の制約時刻 p から t までの間隔を考慮します。 
3. 間隔の長さを L = t - p として計算します。 L ステップの自由間隔では、1 分ごとに反転することで L ポイントを獲得できる可能性があります。 
4. エンドポイント要件を満たすことができるかどうかを確認します。前のサイド prev_side から開始して、L ステップの後、サイド s で終了する必要があります。 これには、フリップのパリティが一致する必要があります (prev_side XOR (フリップ数 % 2) = s)。 
5. prev_side == s の場合、偶数回の反転で終了できます。 最適な戦略は 1 分ごとに裏返すことなので、L ポイントを獲得します。 
6. prev_side != s の場合、奇数パリティで終了する必要があります。 可能な限り反転したいと考えていますが、パリティを修正するにはカウントをちょうど 1 だけ減らす必要があります。 したがって、L - 1 ポイントを取得します。 
7. prev_side を s に更新して続行します。 
8. すべての制約を処理した後、最後の制約時間から m までの最終セグメントを同様に処理しますが、強制エンドポイントは使用しません。 

重要な考え方は、パリティを除いてすべてのセグメントが独立して動作し、パリティ調整のコストはセグメントごとに最大 1 つのロスト フリップであるということです。 

### なぜ効果があるのか

 制約間の各間隔は、必要な開始パリティと終了パリティを除いて独立しています。 長さ L のフリーインターバル内では、1 分ごとに +1 ポイントに貢献する潜在的な反転が提供されます。 唯一の制限は、フリップの合計数が偶数である必要があるか奇数である必要があるかということです。 

反転は常に有益であるため、最適な戦略は、必要に応じてパリティを修正するために予約されている 1 分を除いて、可能な限りすべての分で反転することです。 追加のフリップをスキップしても、最初の修正以降のパリティには影響せずにスコアが減少するだけであるため、複数のフリップをスキップしてもメリットはありません。

これにより、厳密な構造が作成されます。各セグメントは、エンドポイントの互換性にのみ応じて L ポイントまたは L − 1 ポイントのいずれかを提供し、セグメント間のグローバルな相互作用によって結果を改善することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    constraints = []
    for _ in range(n):
        a, b = map(int, input().split())
        constraints.append((a, b))

    ans = 0
    prev_t = 0
    prev_side = 0

    for t_i, s_i in constraints:
        L = t_i - prev_t

        if prev_side == s_i:
            ans += L
        else:
            if L > 0:
                ans += L - 1
            else:
                ans += 0

        prev_t = t_i
        prev_side = s_i

    L = m - prev_t
    ans += L

    print(ans)
```コードは、制約された各間隔を 1 回処理し、パリティが一致するかどうかに基づいて寄与を蓄積します。 

反転を明示的にシミュレートすることはありません。 代わりに、各間隔をブロックとして扱い、パリティの不一致により 1 つの潜在的なフリップが失われるかどうかを判断します。 最後のセグメントには強制的なエンドポイントがないため、常に利用可能なすべての手を実行します。 

長さがゼロの間隔には注意が必要です。 L = 0 の場合、そのセグメントでは移動が不可能なため、パリティが不一致であっても何も減算しません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())
        constraints = [tuple(map(int, input().split())) for _ in range(n)]

        ans = 0
        prev_t, prev_s = 0, 0

        for t_i, s_i in constraints:
            L = t_i - prev_t
            if prev_s == s_i:
                ans += L
            else:
                ans += max(0, L - 1)
            prev_t, prev_s = t_i, s_i

        ans += m - prev_t
        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、2 つの制約が同時にまたは連続して発生し、長さ 0 のセグメントが生成される場合です。 その場合、アルゴリズムは L = 0 を計算するため、必要な辺が一致するかどうかに関係なく、何も寄与しません。 例えば：```
1
2 5
2 0
2 1
```時間 2 付近の両方のセグメントの長さはゼロであるため、その間隔では答えは 0 のままです。 反転を実行する時間がないため、アルゴリズムは、負の調整または追加の調整を使用してパリティを「修正」しようとしません。 

もう 1 つのエッジ ケースは、次のような制約が一貫しているが疎である場合です。```
1
1 10
5 1
```0 から 5 までは L = 5 で、サイド 1 で終了する必要があるため、潜在的な反転が 1 つだけ失われ、4 になります。5 から 10 までは完全な 5 が得られ、合計 9 になります。アルゴリズムは、最初のセグメントにのみ 1 つのパリティ補正を適用することで、これを自然に処理します。 

最後の微妙なケースは、m が大きく、制約がまったくない場合です。 次に、アルゴリズムはセグメントを処理せず、m を直接返します。これは、制限なく毎分反転できることを反映しています。
