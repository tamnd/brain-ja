 ## 問題の理解

 正の整数の配列とパラメータが与えられます。$k$。 選択したセグメントに対して$[l, r]$では、配列をセグメントの内側とセグメントの外側の 2 つの部分に分割することを想像します。 

セグメント内のすべての要素は、バケット 1 と呼ばれる区別されたマルチセットに強制的に入れられます。セグメントの外側のすべての要素は、すべての要素に任意に分散できます。$k$バケット 1 を含むマルチセット。 

外側の要素を分散できる場合、セグメントは有効であるとみなされます。$k$マルチセットはマルチセットと同じになります。 これは、すべての値に対して、$v$、各バケットには、まったく同じ数の出現が含まれている必要があります。$v$。 

出力ではセグメントの数が求められます。$[l, r]$このような完璧なバランスを可能にします。 

重要な制約は、外部要素を自由に割り当てることができるが、内部要素はバケット 1 で固定されるため、強制的な不均衡が生じ、外部要素を使用して補正する必要があることです。 

入力サイズは最大です$2 \cdot 10^5$したがって、すべての部分配列を試して周波数情報を個別に再計算するソリューションは二次関数となり、合格しません。 平$O(n \sqrt{n})$危険です。 テスト ケースごとに線形または線形演算に近いものを期待する必要があります。 

素朴な推論による微妙な失敗例は、「各値が少なくとも出現するだけでよい」と仮定することです。$k$分散制約はセグメントごとにあり、内部の要素がバケット 1 に強制的に挿入される方法と相互作用するため、これでは十分ではありません。 

たとえば、次の場合$k=2$そして配列は$[1, 2, 1]$、セグメントを取得$[2,2]$バケット 1 の内側に 2 が 1 つだけ分離されます。外側には 2 が 1 つだけ残っているため、両方のバケットのバランスを均等にすることはできません。 単純な global-count 引数ではこれが見逃されます。 

別の失敗例は、有効なセグメントの単調性を仮定することです。 たとえ$[l, r]$は有効なので、次のように拡張します$[l, r+1]$バケット 1 に強制要素を追加すると不均衡が増大し、修正不可能になる可能性があるため、実現可能性が損なわれる可能性があります。 

## アプローチ

 ブルートフォースアプローチはすべてのセグメントを試みます$[l, r]$。 各セグメントについて、内部に各値が何回出現するかを計算します。 次に、外側の部分が次のように分割できるかどうかを確認します。$k$同一のマルチセット。 

これには、値ごとに次のことを確認する必要があります。$v$、の合計数$v$内部オカレンスのマイナスは次で割り切れます。$k$外部要素は均等に分散されなければならないため、$k$バケツ。 その条件は必要ですが、十分ではありません。 また、バケット 1 の強制内部要素が最終的な等しい構成と一致することを確認する必要もあります。 

すべてのセグメントの内部カウントを個別に計算しようとすると、各チェックにコストがかかります$O(n)$、につながる$O(n^3)$素朴に行われた場合、または$O(n^2)$プレフィックス合計付き。 平$O(n^2)$には遅すぎる$2 \cdot 10^5$。 

重要な洞察は、視点を逆転させることです。 すべてのバケットのバランスを考えるのではなく、バケット 1 が何を強制するかに焦点を当てます。 

させて$cnt_v$value の合計出現数になります$v$、そしてさせてください$x_v$そのうち何人が中にいるか$[l,r]$。 最終状態では、各バケットには同じ数の$v$、 言う$t_v$。 すると合計は$k \cdot t_v$、 それで$cnt_v$で割り切れる必要があります$k$、 そして$t_v = cnt_v / k$。 

ここで、バケット 1 には正確に含まれている必要があります$t_v$それぞれのコピー$v$。 つまり、セグメント内で強制的に$x_v \le t_v$、残りは外部から供給する必要があります。$t_v - x_v$。 外部要素は自由に割り当てることができるため、唯一の制約は、すべての値についてバケット 1 のターゲット割り当てを超えてはいけないことです。 

したがって、セグメントはすべての値に対して正確に有効です$v$、$$x_v \le \frac{cnt_v}{k}$$これにより、問題は古典的なスライディング ウィンドウ制約問題に変換され、周波​​数がしきい値を超えない部分配列を見つけます。 

事前計算します$t_v$。 次に、2 つのポインター ウィンドウを維持し、現在の周波数を追跡します。 右のポインタを拡大し、周波数がそのしきい値を超えるたびに、すべての制約が復元されるまで左から縮小していきます。 各右端点について、有効な左端点の数は現在のウィンドウ サイズとまったく同じです。 

これにより、テスト ケースごとに線形の解決策が得られます。

 ## アルゴリズムのチュートリアル

 1. 配列内のすべての値の出現をカウントします。 

これが必要なのは、バケットごとの最終ターゲットがローカル セグメントではなくグローバル周波数に依存するためです。 
2. 各値の目標容量を次のように計算します。$t_v = cnt_v / k$。 

もし$cnt_v$で割り切れない$k$の場合、有効なサブ配列には、このグローバル要件に違反する出現パターンを含めることはできません。 ただし、私たちが使用するのは$t_v$値ごとの上限として。 
3. 2 つのポインターを使用してスライディング ウィンドウを維持する$l$そして$r$、およびウィンドウ内の値の周波数マップ。 

ウィンドウは候補部分配列を表します$[l, r]$。 
4. 拡張する$r$段階的に、追加する$a[r]$ウィンドウ周波数に入力します。 

挿入するたびに、$freq[a[r]] > t_{a[r]}$。 その場合、バケット 1 では許可されているよりも多くの値のコピーが必要になるため、このウィンドウは実現可能性に違反します。 
5. 違反が発生した場合は移動する$l$すべての周波数が満足するまで$freq[v] \le t_v$。 

これが機能するのは、縮小によってウィンドウから制約のみが削除されるため、実現可能性が向上するだけです。 
6. ウィンドウが有効になると、次で終わるすべてのサブ配列が有効になります。$r$そしてどこからでも始めてください$[l, r]$有効です。 追加$r - l + 1$答えに。 

### なぜ効果があるのか

 任意の固定値の場合$v$、最終的な構成では、バケット 1 に正確に含まれるように強制します。$t_v$コピー。 ウィンドウにこれ以上の内容が含まれている場合、$t_v$の場合、そのセグメントには少なくとも配置する必要があります。$t_v + 1$のコピー$v$バケット 1 に入れることは不可能です。$t_v$ターゲットのバランスの取れた構成にコピーが存在します。 

逆に、ウィンドウ内のすべての値がその上限を尊重する場合、各バケットがバケット 1 と正確に一致するように、ウィンドウの外側の残りの要素を常にバケットに割り当てることができます。 外側の部分には制約がなく、残りの必要なカウントのみを一致させる必要があるため、十分な柔軟性があります。 

したがって、スライディング ウィンドウは実現可能条件を正確に維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1

        cap = {}
        for x, c in freq.items():
            cap[x] = c // k

        cur = {}
        l = 0
        ans = 0

        for r in range(n):
            x = a[r]
            cur[x] = cur.get(x, 0) + 1

            while cur[x] > cap[x]:
                y = a[l]
                cur[y] -= 1
                l += 1

            ans += (r - l + 1)

        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、現在のウィンドウの頻度ディクショナリと、グローバル カウントから導出される事前計算されたキャップ ディクショナリに依存します。 重要な点は、ウィンドウが常に左から最小に維持されるため、右ポインタを拡張するたびに、有効な開始位置の数が現在のウィンドウの長さとまったく同じになることです。 

よくある間違いの 1 つは、最後に挿入された要素が再び有効になるまで縮小を続行する必要があることを忘れていることです。 もう 1 つは、整数除算の代わりに合計カウントを誤って使用しています。$k$キャップの場合、実現可能条件を破ります。

 ## 特殊なケース

 すべての要素が同一の場合、キャップは次のようになります。$n/k$、スライディング ウィンドウはその制限に達するまで拡大します。 それを超えて拡張しようとすると、左ポインタが強制的に移動し、有効なセグメントの連続したブロックが生成されます。 これにより、ウィンドウが値ごとのクォータを超えることはないという不変条件が確認されます。 

いつ$k = n$、すべてのキャップは周波数に応じて 0 または 1 になるため、ほとんどのウィンドウはすぐに折りたたまれます。 すべての違反は縮小によって解決され、無効な部分配列がカウントされないことが保証されるため、アルゴリズムは引き続き正しく動作します。 

ペアが繰り返されるなど、値が均等に分布している場合、頻繁にリセットすることなくウィンドウがスムーズに拡大します。 このケースでは、アルゴリズムが過度に縮小せず、すべてのサブ配列を効率的にカウントするための最大有効間隔が維持されることが確認されています。
