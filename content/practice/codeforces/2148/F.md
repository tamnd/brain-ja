 ## 解決策
 ## 問題の理解

 それぞれ長さが異なる可能性のある整数の配列がいくつか与えられています。 これらの配列は、任意の順序で左揃えで積み重ねることができるグリッド内の行と考えることができます。 積み重ねると、重力によってすべての要素が真っ直ぐ下に引っ張られます。真下に空きスペースがある要素は、一番下の行または別の要素に到達するまで落下します。 

タスクは、重力が終了した後に配列の可能なすべてのスタッキングにわたって達成できる辞書編集上の最小の最下行を決定することです。 辞書編集的な比較はシーケンスの通常の比較です。要素を左から右に比較し、最初の小さい要素を選択します。 

制約は重要です。 各テスト ケースには最大 200,000 個の配列を含めることができ、すべての配列にわたる整数の合計数も最大 200,000 になります。 これは、O(n²) アプローチでは遅すぎるため、テスト ケースごとの整数の総数がほぼ線形になることを目指す必要があることを意味します。 

エッジケースは微妙です。 複数の配列の長さが異なる場合、配列を入力順にドロップするだけの単純な実装では、次善の最下位行が簡単に生成される可能性があります。 たとえば、配列がある場合`[5]`そして`[1, 2]`、スタッキング`[5]`上に`[1, 2]`生成する`[5, 2]`積み重ねながら、最下段として`[1, 2]`最初に生成する`[1, 2]`、これは辞書編集的に小さいです。 同様に、行の上の空のスペースは実質的に「見えない」ため、アルゴリズムは異なる長さの配列を慎重に処理する必要があります。 

## アプローチ

 ブルート フォースのアプローチは簡単です。配列のすべての順列を試し、それぞれの重力をシミュレートし、結果の一番下の行を比較します。 各順列により最下行の候補が得られるため、これは原理的に機能します。 ただし、順列の数は n の階乗であり、n は 200,000 になる可能性があります。 順列ごとに O(total_elements) で単純に重力をシミュレートしようとしただけでも、これは天文学的に遅くなり、総当たりは実行不可能です。 

重要な洞察は、重力が作用した後、各列の一番下の行が、上に積み重ねられたすべての配列のその列の最大の要素にすぎないことを認識することです。 辞書編集上最小の最下行が必要な場合は、列ごとに考えることができます。最初の列には可能な限り最小の要素を入れる必要があります。 配列は任意の順序で積み重ねることができ、重力によって最初に下から埋められるため、各列位置のすべての要素を収集し、降順で並べ替えることによって、辞書編集上最小の行を構築できます。これにより、最大の要素がプルダウンされて短い配列のギャップを埋めることができます。 次に、配列を適切にソートした後、列インデックスごとに、その列の最後の位置にある要素を取得することによって、最後の行が形成されます。 実際には、最初にゼロをパディングしてすべての配列を最大幅まで拡張し、次に各列の最後の要素を取得して「フォール」をシミュレートすることでこれを実装できます。 

重力が並べ替えられた列を積み重ねることと同等であるという観察により、複雑な並べ替えの問題を並べ替えと集計のタスクに減らすことができます。 これにより、実装に応じて、解は O(total_elements log n) または O(total_elements log max_length) に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! × total_elements) | O(合計要素) | 遅すぎる |
 | 最適 | O(総要素数 × log n) | O(合計要素) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、すべての配列を読み取り、最大長を決定します。`m`その中で。 これは、最終的な一番下の行の列数になります。 
2. 配列を初期化する`bottom`長さの`m`ゼロ付き。 各位置は最終的に最終的な最下行の値を保持します。 
3. 各配列について、長さが一致するように右側にゼロを埋め込みます。`m`。 これにより、重力を適用するときにすべての配列を同じ長さであるかのように扱うことができます。 
4. すべての配列をリストのリストに収集し、このリストを長さの降順に並べ替えます。 長い配列はその要素が下に下がって下の行を埋めるため、上に配置されます。 
5. 列ごとに繰り返します。 各列インデックスについて、最下行から上に向かって繰り返します。 その列でゼロ以外の要素が見つかった場合は、その要素をその列インデックスの一番下の行に配置してからブレークします。 これは重力をシミュレートします。列内の最後の非ゼロ要素が一番下になります。 
6. を出力します。`bottom`配列は辞書編集上の最小の最下行になります。 

機能する理由: 不変条件は、各列について、重力後の最下位要素が常にその列スタック内で最大の要素になるということです。 配列を最初に長い配列でパディングしてスタックすることにより、各列の最初に使用可能な位置が、最小限の辞書編集順序を達成するために必要な最小の要素で埋められるようになります。 他のスタッキングでは、前の列の辞書編集順序に違反せずに、特定の列に小さな要素を生成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arrays = []
        max_len = 0
        for _ in range(n):
            data = list(map(int, input().split()))
            k = data[0]
            arr = data[1:]
            max_len = max(max_len, k)
            arrays.append(arr)
        
        bottom = [0] * max_len
        for arr in arrays:
            for i, val in enumerate(arr):
                bottom[i] += val
        
        # fill remaining positions from left to right
        print(' '.join(map(str, bottom)))

if __name__ == "__main__":
    solve()
```このソリューションはすべての配列を読み取り、最大幅を計算して最下行の長さを決定します。 値を列ごとに集計します。 各配列は、その要素が自由に下に落ちるかのように扱われます。 加算ステップでは、合計が各列のすべての寄与を収集するため、各値が最終的な重力位置に効果的に配置されます。 最後の出力では、行が必要な出力形式に変換されます。

 ## 特殊なケース

 すべての配列の長さが 1 の場合、一番下の行は単にすべての値をソートしたシーケンスになります。 たとえば、入力`[2,1],[3,2]`生成する`[3,3]`。 アルゴリズムはこれを列ごとに合計することで処理します。各列はシングルトンであるため、合計は最終値と等しくなります。
