 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 各シナリオでは、ヴラドの友達の数と店の数は固定されています。 各ショップはすべての友人に価値を提供し、そこでギフトを購入した場合にその友人がどれだけ喜ぶかを表します。 

Vlad は各友人に 1 つのショップを割り当てる必要があります。つまり、各友人は 1 つのギフトを受け取ります。 1 つのショップで複数の友人にサービスを提供できるため、ショップごとの購入数に制限はありません。 ただし、ヴラドはせいぜい物理的に訪問することしか許可されていない$n-1$個性的なお店が、$n$友達の数です。 

すべての割り当てが完了すると、各友達には喜びの値が設定され、解決策の質は友達全員の最小の喜びによって決まります。 目標は、この最小値を最大化することです。 

したがって、私たちは全体的な喜びを最適化するのではなく、すべてのショップを自由に利用できないという制限の下で、最も弱い友人が可能な限り幸せになるようにします。 

制約$n \cdot m \le 10^5$テスト ケースごとに、行列が十分に疎であるため、解が次の値に近づくことを意味します。$O(nm \log A)$または$O(nm)$が予想されます。 二次関数の何か$m$または立方体$n$渡るのが遅すぎるだろう$10^4$テストケース。 

単純なアプローチでは、ショップを友人に直接割り当てるか、ショップのサブセットを列挙しようとしますが、これはすぐに不可能になります。$n-1$ショップはすでに組み合わせ爆発を暗示しています。 

すべての友人が高い値を必要としているにもかかわらず、これらの高い値がさまざまなショップに分散されている場合、微妙な失敗例が発生します。 

たとえば、ある友人がショップ 1 で最高の価値を持っており、別の友人がショップ 2 でというように、使用する額は以下のとおりです。$n$単一のショップがすでに多くの友人を同時に満足させていない限り、ショップは少なくとも 1 人の友人に妥協を強います。 貪欲な「友人ごとに個別に最適なものを選択する」アプローチは、ショップの使用に関する共有の制約を無視するため失敗します。 

## アプローチ

 強引なアイデアは、最大でも次のサブセットを選択することです。$n-1$次に、各友人をこれらのショップの 1 つに割り当て、個々の楽しみを最大化します。 固定サブセットの場合、各友人の達成可能な最高の喜びを、選択した店の最大値として計算します。 最終的なスコアは友達全体の最小値です。 

問題は、$\binom{m}{\le n-1}$実際には指数関数的になります。 中程度の場合でも$m$、これはまったく不可能です。 

重要な観察は、視点を反転することです。 私たちは店を選ぶのではなく、すべての友人が少なくとも価値を受け取ることを保証できるかどうかを尋ねます。$x$? 閾値を固定すると$x$、各ショップは、「満足できる」友達のセットになります（$p_{ij} \ge x$）。 多くても選びたい$n-1$すべての友人が少なくとも 1 つの選択されたショップでカバーされるようなショップ。 

これは古典的な実現可能性チェックであり、二分探索と組み合わせることができます。$x$。 残りの問題は、実現可能性を効率的に確認する方法です。 

固定の場合$x$では、満足する友人の集合によってショップを分類します。 重要な洞察は、満足している友人の集団という点で、ある店が他の店よりも厳密に優れている場合、支配されている店は決して役に立たないということです。 各ショップを次の長さのビットマスクに縮小できます$n$、しかしそれ以来$n$規模が大きいため、代わりに友人ごとに推論します。各友人は少なくとも 1 つの選択されたショップでカバーされる必要があります。 

よりクリーンな変革は二重の思考から生まれます。 友達をカバーするためにお店を選ぶのではなく、それぞれの友達がどのお店を利用するのが理想的かを考えてみましょう。 友人が基準を満たす店舗に割り当てられている場合$x$、そのお店がそれらを「カバー」します。 ショップは複数の友人を同時にカバーできます。 

ここで条件は次のようになります: 最大でも選択できますか$n-1$すべての友人が、次のようなお店の中から少なくとも 1 軒は選んだお店を持っているようなお店$p_{ij} \ge x$? これは、各友人の候補店の中で、友人が漏れないようにしなければならない、と言っているのと同じです。 

主要な構造的単純化が明らかになります: 友人に満足のいく店がない場合$x$、 それから$x$不可能です。 それ以外の場合、各友人には少なくとも 1 つの許容可能なショップがあり、最大でも選択できるようにする必要があります。$n-1$これらすべてのセットを集合的に交差させるショップ。 これは、「完全一致の障害」が存在しない限り、常に可能です。これは、失敗する唯一の方法は、各友達が個別のショップを必要とする場合であることを観察することで、貪欲に解決できます。$n$個性的なお店。 

これは標準的な貪欲な実現可能性チェックにつながります。私たちは各友人を優先ショップに割り当てようとし、可能な限りすでに使用されているショップの再利用を優先します。 これ以上のものを導入する必要がある場合は、$n-1$異なるショップの場合、しきい値は失敗します。 

これにより、問題は二分探索に帰着します。$x$、貪欲なチェックインで$O(nm)$テストごとに。

 ## アルゴリズムのチュートリアル

 ### 1. 答えを二分探索する

 最大限最小限の喜びを求めます$x$。 候補者にとって$x$、すべての友人が少なくともギフトをもらえるようにギフトを割り当てることが可能かどうかをテストします。$x$。 

単調なプロパティは次のとおりです。$x$が実行可能な場合は、さらに小さい値も実行可能です。 

### 2. テスト値ごとに実現可能性情報を構築する

 固定の場合$x$、行列をスキャンして、どの (友人、店) ペアが有効であるかをマークします。$p_{ij} \ge x$。 各友人は少なくとも 1 つの有効なショップに割り当てられる必要があります。 

### 3. 店舗利用を貪欲に構築する

 私たちは友達を繰り返し調べて、可能であればすでに選択されているショップにそれぞれを割り当てるようにします。 そうでない場合は、満足していただける新しいお店をオープンします。 

これが機能する理由は、ショップは制限なく複数の友人にサービスを提供できるため、ショップを再利用しても実現可能性が損なわれないためです。 

### 4. 最大で次の制約を強制します。$n-1$店

 割り当てる際に、使用を強制される個別のショップの数を数えます。 これを超えると$n-1$、しきい値$x$不可能です。 

### なぜ効果があるのか

 重要な不変条件は、どの時点でも、処理されたすべての友人をカバーする一連の選択されたショップを維持することです。 既存のお店では対応できない友人には、満足していただける新しいお店をご紹介します。 このプロセスで必要な場合は、$n$個別のショップの場合、それらの各ショップは、他の方法ではカバーできない少なくとも 1 人の友人によって強制されるため、合併は不可能になります。 逆に、その範囲内に留まれば、$n-1$、有効な割り当てがあります。 店舗の再利用には制限がなく、唯一の制限要因は個別の店舗の数であるため、この貪欲な構造はまさに実現可能性を特徴づけています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(x, m, n, p):
    used_shops = set()
    shop_for_friend = [-1] * n

    # try to assign each friend to some shop with p[i][j] >= x
    for j in range(n):
        assigned = -1
        for i in range(m):
            if p[i][j] >= x:
                if i in used_shops or len(used_shops) < n - 1:
                    assigned = i
                    break

        if assigned == -1:
            return False

        shop_for_friend[j] = assigned
        used_shops.add(assigned)

        if len(used_shops) > n - 1:
            return False

    return True

def solve():
    t = int(input())
    for _ in range(t):
        input()
        m, n = map(int, input().split())
        p = [list(map(int, input().split())) for _ in range(m)]

        lo, hi = 0, 10**9

        while lo < hi:
            mid = (lo + hi + 1) // 2
            if can(mid, m, n, p):
                lo = mid
            else:
                hi = mid - 1

        print(lo)

if __name__ == "__main__":
    solve()
```二分探索は実現可能性チェッカーの上に位置します。 チェッカー内では、各友人は個別に処理されますが、共有制約は一連の中古ショップを通じて追跡されます。 貪欲な選択により、可能な限りショップを再利用し、導入される個別のショップの数を最小限に抑えます。 

実装でよくある落とし穴は、再利用が常に有益であることを忘れて、別の既存のショップで十分である場合でも、代わりに友人をその最良のショップに貪欲に固定してしまうことです。 これでは実現可能性の計算ができなくなります。 

もう 1 つの微妙な問題は、バイナリ検索の下限を誤って初期化することです。 喜びは正であるため、0 から開始するのが安全であり、すべての値が大きいにもかかわらず有効であるというエッジ ケースをカバーします。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        t = int(input())
        for _ in range(t):
            input()

                used = set()

 ## 特殊なケース

 重要なエッジケースは、各友人が独自のベスト ショップを持っている場合です。 例えば友達だったら$j$最大値はショップ内のみです$j$、高いしきい値に達すると、すべての選択が強制されます。$n$に違反するお店$n-1$限界。 貪欲な割り当てでは必然的に各友人に新しいショップが導入され、使用されるセットがそれを超えて増加するため、アルゴリズムはこれを検出します。$n-1$、拒否反応を引き起こします。 

もう 1 つのエッジケースは、1 つのショップが多くの友人を支配している場合です。 その場合、貪欲な割り当ては 1 つのショップ内ですぐに安定し、使用されるショップの数が 1 を超えることはなく、制約は自明に満たされます。
