 ## 問題の理解

 マルチテーブルゲームの公平なスケジュールを編成するよう求められています。 がある$n$選手、$m$テーブル、および$k$ラウンドします。 各ラウンド、すべてのテーブルは次のいずれかをホストする必要があります$\lfloor n/m \rfloor$または$\lceil n/m \rceil$選手たち。 全ラウンドを通して、各プレイヤーは「満席」のテーブル (大きいサイズのテーブル) に何回座ったかを記録します。$\lceil n/m \rceil$）、このカウントに 2 人のプレーヤーの差異が 1 を超えない場合、スケジュールは公平です。 

入力はテスト ケースの数と、各テスト ケースの数値を示します。$n, m, k$。 出力には、各ゲームの各テーブルのプレーヤーの割り当てを記述する必要があります。 プレイヤーインデックスは1から$n$、制約を満たす任意のスケジュールが受け入れられます。 

制約は次のことを示唆しています$n$そして$k$まで可能です$2 \cdot 10^5$すべてのテスト ケースにわたって結合されます。 これにより、あらゆることが排除されます$O(n^2)$可能なすべてのテーブル割り当ての総当たり列挙以上が必要になるため、$O(n \cdot k \cdot m)$すべての分布をシミュレートする単純なアプローチの操作。 

次の場合には、明らかではないエッジケースが発生します。$n$で割り切れない$m$。 たとえば、次の場合$n=5, m=2, k=2$、その場合、テーブル サイズは 2 名と 3 名の間で交互に行う必要があります。 不注意なラウンドロビンまたは純粋な逐次割り当てにより、あるプレーヤーが大きなテーブルに過剰に割り当てられ、別のプレーヤーが過小に割り当てられる可能性があり、公平性条件に違反します。 

もう 1 つの注意を要するシナリオは次のような場合です。$k$に比べて大きい$n$。 すべてのプレイヤーがより大きなテーブルにほぼ均等に参加できるようにするために、ゲーム間でプレイヤーを効率的にローテーションする必要があります。 慎重に処理しないと、単純なモジュロベースの割り当てにより、最初の数人のプレイヤーが誤って偏ってしまう可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各ゲームの各テーブルのプレーヤーのすべての組み合わせを生成し、最後に公平性条件を検証しようとします。 これは技術的には正しいですが、実行不可能です。各ゲームでは、次のパーティションを生成する必要があります。$n$の中へ$m$ほぼ等しい部分であり、次のように指数関数的に増加します。$n$そして$m$。 テストケースが 1 つであっても、$n=100, m=10, k=50$すでに計算限界を超えているでしょう。 

最適なアプローチは問題の構造を利用します。 ゲーム内のすべてのテーブルは床または天井のサイズでなければならず、各プレーヤーはほぼ同じ数の天井テーブルを経験する必要があるため、プレーヤーをテーブル間で循環的にローテーションできます。 概念的には、すべてのプレイヤーを一定の順序で並べて割り当てます。$\lceil n/m \rceil$プレーヤーは各ラウンドの最初のテーブルに移動し、その後ラップアラウンドします。 このラインをゲームごとにローテーションすることで、自然に配分のバランスが取れます。 各プレーヤーが正確に正しい数の大きなテーブルに出現し、最大 1 の差だけであるため、公平性の不変条件が維持されます。 

この方法は建設的であり、プレーヤーとゲーム テーブルの割り当ての総数に対して線形時間で実行されます。

 | テーブルの循環回転 | O(n*k) | O(n*k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ゲームの基本的なテーブル サイズを計算します。 させて`small = n // m`そして`big = n // m + 1`。 各ゲームでより大きなサイズを持つテーブルの数を計算します。`num_big = n % m`。 残りのテーブルのサイズは小さくなり、`num_small = m - num_big`。 
2. 1 から n までのすべてのプレーヤーのインデックスのリストを作成します。 これは、テーブル間でプレーヤーをローテーションするための循環キューとして機能します。 
3. k 個のゲームごとに次のようにします。 

1. 現在のゲームの m 個のテーブルごとに次のようにします。 

1. テーブルのサイズを決定します。最初の`num_big`テーブルの取得`big`プレイヤーは残りを獲得します`small`。 
2. 次の項目を割り当てます`table_size`サイクリック リストからこのテーブルにプレーヤーを追加します。 
3. 次のテーブルが次のプレイヤーから続くように循環リストを回転します。 
4. すべてのゲームを割り当てたら、その割り当てを印刷します。 各テーブルは、そのサイズに続いてプレーヤーのインデックスのリストが印刷されます。 

機能する理由: 循環ローテーションにより、すべてのプレイヤーが大きなテーブルに正確に割り当てられます。`floor(k*num_big/n)`または`ceil(k*num_big/n)`回。 以来`num_big`そして`num_small`単一のゲームでテーブルを分割する、不変条件`|b_i - b_j| ≤ 1`すべてのプレイヤーにわたって維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        small = n // m
        big = small + 1
        num_big = n % m
        players = list(range(1, n + 1))
        idx = 0
        for _ in range(k):
            table_assignments = []
            for t_idx in range(m):
                if t_idx < num_big:
                    size = big
                else:
                    size = small
                table = [players[(idx + i) % n] for i in range(size)]
                idx = (idx + size) % n
                print(size, *table)
            print()
            
if __name__ == "__main__":
    solve()
```コードは、アルゴリズムで説明されているとおりに循環回転を正確に実装します。 モジュロ演算により、プレーヤー リストのラップアラウンドが保証され、すべてのプレーヤーが大きなテーブル間で均等に分散されます。 わかりやすくするために、空白行でゲームを区切ります。

## 特殊なケース

 のために`n=5, m=2, k=2`、各ゲームの最初のテーブルには 3 人のプレイヤーが必要になる場合があります。 循環ローテーションにより、すべてのプレイヤーが順番に大きなテーブルに参加することが保証されるため、公平性が保たれます。`|b_i - b_j| ≤ 1`維持されている。 モジュロ演算により、最初のプレーヤーを過剰にカウントしたり、最後のプレーヤーを過小カウントしたりすることがなくなります。 

のために`n`で割り切れる`m`、
