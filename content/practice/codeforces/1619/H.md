 ## 解決策
 ## 問題の理解

 1 から 1 までの整数の順列が与えられます。$n$。 概念的には、これは長さの配列です$n$ここで、1 から 1 までのすべての整数は、$n$は 1 回だけ出現するため、すべてのインデックスは一意の値にマップされます。 この配列に加えて、2 種類のクエリがあります。 最初のタイプは、順列内の 2 つの要素を交換します。 2 番目のタイプは、指定されたインデックスから順列を繰り返し適用し、その後の値が何になるかを尋ねます。$k$アプリケーション。 たとえば、次の場合$p = [5, 3, 4, 2, 1]$そして、インデックス 1 を次のようにクエリします。$k = 2$、フォローします$p[1] = 5$その後$p[5] = 1$, したがって、答えは 1 です。 

制約は重要です。$n$そして$q$どちらも到達できる$10^5$。 シミュレートする単純なソリューション$k$各クエリのステップでは、最大で次のことが実行される可能性があります。$10^5 \times 10^5 = 10^{10}$これは 4 秒の制限時間をはるかに超えています。 繰り返しの作業を減らし、値の不必要な再計算を避けるアプローチが必要です。 

明らかではないエッジケースが発生する場合$k = n$または$k > n$、順列が循環を形成するためです。 ただ繰り返すだけの不用意なアプローチ$k$スワップによってサイクル構造が変更された場合、時間が遅すぎて失敗する可能性もあります。 もう 1 つの注意が必要な状況は、スワップを繰り返すとサイクル内の要素が移動する場合です。 すべてを最初から再計算することなく、サイクルの理解を効率的に更新する方法が必要です。 

## アプローチ

 ブルート フォース アプローチは簡単です。タイプ 2 の各クエリについて、インデックスから開始します。$i$そしてフォローしてください$p[i]$ $k$回。 各タイプ 1 クエリは、単純に 2 つの要素を交換します。 これは小さな入力では正しく機能しますが、入力が遅い場合は遅すぎます。$n$または$q$タイプ 2 の各クエリにはコストがかかる可能性があるため、サイズが大きくなります。$O(n)$、最大で$10^5$そのようなクエリ。 

重要な観察は、順列が互いに素なサイクルで構成されているということです。 繰り返し適用する$p$あるインデックスから始まる$i$を含むサイクルに沿って移動することと同等です。$i$。 したがって、繰り返す代わりに、$k$回、計算できる$k \mod \text{cycle\_length}$そして直接ジャンプします。 スワップはサイクル分解を変更するため、サイクルを効率的に更新できるデータ構造が必要です。 以来$n$そして$q$が比較的大きい場合、最も簡単なアプローチは、スワップ後に影響を受けるサイクルのみを再構築することです。これは、各要素が正確に 1 つのサイクルに属するため効率的です。 

これにより、タイプ 2 のクエリが減少します。$O(k)$に$O(1)$サイクルを明示的に保存し、タイプ 1 クエリを次のように処理できる場合$O(\text{cycle\_size})$、各要素は交換されたときにのみサイクルを変更するため、これは許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*q) | O(n) | 遅すぎる |
 | サイクル分解 | O(n + q) 償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列を読み取る$p$そしてクエリ。 変換する$p$Python での配列操作を容易にするために、0 ベースのインデックスを作成します。 
2. 配列を初期化して、サイクル検出で要素が訪問されたかどうかをマークします。 また、`cycle`各インデックスをそのサイクルのリストにマッピングする配列。 
3. まだサイクルに割り当てられていないインデックスごとに、ループバックするまで順列をたどります。 サイクルをリストに記録し、参照を`cycle`配列。 
4. タイプ 2 クエリの場合、クエリされたインデックスのサイクルを見つけます。 サイクル内のターゲット インデックスを次のように計算します。$(\text{position in cycle} + k) \mod \text{cycle length}$。 その位置の要素を出力します。 
5. タイプ 1 クエリの場合、2 つの要素を交換します。 スワップはサイクルに影響を与えるため、スワップされた要素を含むサイクルを再構築します。 これら 2 つのインデックスを含むサイクルを再処理するだけで済みます。 
6. クエリの処理を順番に続け、スワップを適用し、更新されたサイクルを使用してタイプ 2 クエリに応答します。 

不変条件は、すべてのインデックスが正確に 1 つのサイクルに属し、サイクル構造が各スワップ後に正しく更新されることです。 これにより、タイプ 2 のクエリが、複数のスワップの後でも常に正しい要素を返すことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, q = map(int, input().split())
    p = list(map(int, input().split()))
    p = [x-1 for x in p]  # convert to 0-based indexing

    # each element's cycle index and position in the cycle
    cycle_id = [-1] * n
    pos_in_cycle = [-1] * n
    cycles = []

    def build_cycle(start):
        cycle = []
        x = start
        while cycle_id[x] == -1:
            cycle_id[x] = len(cycles)
            pos_in_cycle[x] = len(cycle)
            cycle.append(x)
            x = p[x]
        cycles.append(cycle)

    for i in range(n):
        if cycle_id[i] == -1:
            build_cycle(i)

    for _ in range(q):
        t, x, y = map(int, input().split())
        if t == 1:
            x -= 1
            y -= 1
            # swap values
            p[x], p[y] = p[y], p[x]
            # rebuild cycles affected by x and y
            for idx in (x, y):
                # reset old cycle info
                cid = cycle_id[idx]
                for v in cycles[cid]:
                    cycle_id[v] = -1
                    pos_in_cycle[v] = -1
                cycles[cid] = []
            for idx in (x, y):
                if cycle_id[idx] == -1:
                    build_cycle(idx)
        else:
            x -= 1
            k = y
            cid = cycle_id[x]
            cycle = cycles[cid]
            pos = pos_in_cycle[x]
            result = cycle[(pos + k) % len(cycle)]
            print(result + 1)

if __name__ == "__main__":
    main()
```このソリューションでは、最初に初期順列のサイクルを構築します。 タイプ 2 クエリの場合、モジュラー演算により一定時間で結果を計算します。 スワップの場合、スワップの影響を受けるサイクルのみを再構築するため、アルゴリズムの効率が維持されます。 リビルド前にサイクルデータをリセットする場合は注意が必要です。
