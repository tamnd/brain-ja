 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられ、任意の要素を何度でも 1 ずつインクリメントできます。 このタスクは、0 から配列の長さまでの各整数について、MEX (最小除外値) がその整数と等しくなるように配列を変換できるかどうかを判断し、可能であれば、必要な最小増分数を計算します。 配列の MEX は、配列内に存在しない最小の非負の整数です。 

たとえば、配列が次の場合、`[0, 1, 3]`、メキシコは`2`なぜなら`0`そして`1`存在しますが、`2`が欠けています。 インクリメント`3`に`2`数字を減らすことはできないので、役に立ちません。 MEXを達成するには`3`、すべての数字`0, 1, 2`が存在する必要があります。この配列では既存の数値を変換する必要がありますが、増分だけでは不足している数値を作成できません。`2`それが存在せず、より小さい数値がすべてすでに存在している場合。 

制約は、すべての合計が次のようになります。`n`オーバーテストケースは最大でも`2*10^5`、テスト ケースの数は最大です。`10^4`。 これにより、潜在的な MEX 値ごとにすべての増分をシミュレートするブルートフォース ソリューションが即座に除外されます。`O(n^2)`テストケースごとの操作。 テスト ケースごとに線形または線形演算時間で機能するアプローチが必要です。 

エッジケースには、すべての要素が同じである配列、0 が欠落している配列、すべての値がすでに含まれている配列が含まれます。`0..n`、大きなギャップのある配列。 例えば、`[1, 1, 1]`MEXは持てません`0`インクリメントなし、ただし MEX`2`複数の増分が必要になる場合があります。 不注意なアプローチは、これらのギャップや、数値を増やすことしかできないという事実を無視し、無効な答えを生み出す可能性があります。 

## アプローチ

 素朴なアプローチは、すべてのターゲット MEX を試すことです`i`から`0`に`n`。 ターゲットごとに、すべての数値が形成されるまで、欠落している数値の増分をシミュレートできます。`0..i-1`。 これには、配列をスキャンして値を増やす必要があり、これには最大で 3 分かかる場合があります。`O(n^2)`欠落している数値ごとにスキャンまたは繰り返しの増分が必要になる可能性があるため、最悪の場合は操作が行われなくなります。 明らかに、これでは遅すぎます。 

重要な観察結果は、MEX の場合です。`i`可能であれば、すべての数字`0`を通して`i-1`ある程度の増分後に配列内に存在する必要があります。 以下の欠落番号`i`より小さな数値を増分して「作成」する必要があります。 逆に、以下の任意の数`i`MEX をブロックしません`i`。 

頻度カウントを活用できます。 各数字が何回出現するかを数えると、以下の数字を処理できます。`0`上向きに。 数値が欠落している場合は、より小さい数値の余分な出現を「借用」してその数値を作成することができます。 以下の数字の余分な出現`i`ギャップを埋めるために増分することができ、上記の数値を増やすことができます`i`そのままにしておくこともできます。 余剰要素の実行カウントを維持することにより、最小増分数を 1 回のパスで効率的に計算できます。 

これにより、余剰を追跡しながら周波数配列を 1 回線形スキャンするだけで問題が軽減され、すべての増分をシミュレートするよりもはるかに高速になります。

 ## アルゴリズムのチュートリアル

 1. 配列内の各数値の頻度を数えます。`n`。 配列を初期化する`freq`サイズの`n+1`。 これにより、各番号がいくつあるかにすぐにアクセスできます。 
2. 変数を初期化する`surplus`ゼロに。 これにより、不足している数値、つまり、すでに処理された数値の追加コピーを埋めるために使用できる要素の数が追跡されます。 
3. 反復処理`mex`から`0`に`n`。 それぞれについて`mex`、数値が配列内に存在するかどうかを確認します。 

- もし`freq[mex] > 0`、番号をご用意しております。 追加`freq[mex] - 1`に`surplus`これは、MEX 要件を満たすために 1 つのオカレンスが必要であり、残りは将来のギャップを埋めるために使用できるためです。 
- もし`freq[mex] == 0`、番号がありません。 余剰要素の 1 つをインクリメントすることによってのみ作成できます。 もし`surplus > 0`、デクリメント`surplus`そして操作数を増やします。 もし`surplus == 0`、次にメキシコ`mex`は不可能であり、これより大きな MEX 値もすべて不可能です。 
4. 各 MEX について、ギャップを埋めるために使用される増分と厳密に大きい要素の数の合計として演算の合計数を計算します。`mex`上記の重複を削除したい場合は、値を増やす必要があります`mex`(MEX のブロックを避けるため)。 
5. 結果を順番に出力します。`0`に`n`。 MEXが不可能な場合は出力`-1`。 

なぜ機能するのか: MEX の処理後に不変条件が維持されます。`i`、すべての数字`0..i-1`配列内に存在します。 の`surplus`変数は、追加のコピーを使用して不足している数値を埋めることができることを保証します。 余剰が存在しないためにある時点で数値を作成できない場合、より高い MEX 値も不可能であり、これは論理的に一貫しています。 この貪欲なアプローチにより、新しい要素を作成する前に常に既存の追加要素を使用するため、最小限の操作が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

for _ in range(int(input())):
    n = int(input())
    a = list(map(int, input().split()))
    freq = [0] * (n + 2)
    for x in a:
        freq[x] += 1

    result = []
    ops = 0
    surplus = 0
    for mex in range(n + 1):
        if mex == 0:
            if freq[0] == 0:
                result.append(1)
                surplus = 0
            else:
                result.append(0)
                surplus = freq[0] - 1
        else:
            if freq[mex] == 0:
                if surplus > 0:
                    ops = ops + 1
                    result.append(ops)
                    surplus -= 1
                else:
                    result.extend([-1] * (n + 1 - mex))
                    break
            else:
                ops += freq[mex - 1]
                result.append(ops)
                surplus += freq[mex] - 1
    print(*result)
```まずは頻度を数えることから始めます。これにより、空き状況を即座に確認できるようになります。 の`surplus`変数は、欠落している数値を埋めるために増分できる要素の数を追跡します。 更新します`ops`これまでに必要な増分数を反映します。 MEX の特別な取り扱い`0`要素が欠落している場合でも要素をインクリメントする必要がある場合があるため、これは必要です。 貪欲なアプローチでは、常にギャップを最初に余剰で埋めることにより、最小限の操作が保証されます。
