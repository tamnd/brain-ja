 ## 解決策
 ## 問題の理解

 純粋に数字の構造によって定義された特別なクラスの整数を扱うように求められます。 境界にない数字を見たとき、その数字が隣り合う数字の両方よりも厳密に上にあるか、隣り合う数字よりも厳密に下にある場合、その数字は「波状」と呼ばれます。 言い換えれば、数字は局所的な山と谷で交互になり、平坦または単調な中間セグメントは許可されません。 

2 つの整数 n と k が与えられた場合、概念的には、この波状条件を満たすすべての正の整数をリストし、それらをさらにフィルタリングして、n で割り切れる整数だけを保持します。 数値の昇順に並べ替えられたフィルタリングされたリストのうち、k 番目の要素が必要です。 その要素が 10^14 を超えるか存在しない場合は、-1 を出力します。 

重要な問題は、波状の数値のセットが非常にまばらであるにもかかわらず、桁の長さが指数関数的に大きいことです。 割り算条件を適用する前でも、最大 14 桁の有効な数字列をすべて列挙することはすでに組み合わせになっています。 可分性制約により、検索空間を構造化しないと効率的にチェックできない 2 番目のフィルタリング層が追加されます。 

この制約は、10^14 までのすべての数値を生成して波状条件をテストしようとする解法は失敗することを意味します。これは、最悪の場合、最大 10^14 の候補を反復することを意味するためです。 すべての波状数値を整数として生成することさえ不可能です。なぜなら、波状数値の数は桁の長さに応じて指数関数的に増加するからです。 

DFS によって波状数値を生成し、それぞれについて n による割り切りをチェックする 2 番目の単純なアプローチも、割り切りチェックだけでは十分な枝刈りではないため失敗します。 ほとんどの枝が早期に剪定されたとしても、分岐係数は依然として大きすぎます。 

微妙なエッジケースは、先頭の数字の選択と交互の制約から生じます。 正しくバックトラックしない貪欲な構造または桁ごとの構造では、有効な波形構造が簡単にスキップされる可能性があります。 もう 1 つの問題は、ウェーブ番号が単純な単調な方法ではプレフィックス拡張で閉じられないため、増分生成では隣接関係の制約を注意深く考慮する必要があることです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。10^14 までのすべての整数を生成し、それぞれが波状であるかどうかをテストし、波状である場合は n で割り切れるかどうかを確認します。 これは定義に直接従っているため、正しいです。 ただし、検索空間には最大 10^14 の候補が含まれており、単一の数値をチェックするだけでも O(d) (d は最大 14 桁) のコストがかかるため、これは実行不可能です。 これにより、合計約 10^14 の操作が必要となり、時間制限をはるかに超えます。 

もう少し構造化されたブルート フォースは、DFS を使用して波状プロパティを満たすすべての数字シーケンスを生成することです。 それぞれの位置で、その数字が隣接する数字に対して山である必要があるか、谷である必要があるかを強制します。 これにより無効な状態は早期に減少しますが、長さ d の有効な波状シーケンスの数は依然として指数関数的に増加します。 d が 14 までの場合、これは数百万個以上のシーケンスになるため、それぞれについて数値を計算し、n で割り切れるかどうかを確認する必要があります。 たとえ最適化されていても、k が大きい場合、または枝刈りが弱い場合、このアプローチは依然として遅すぎます。 

重要な観察は、波形制約がローカルであるということです。つまり、各桁はそのすぐ隣の桁にのみ依存します。 これにより、この構造はデジット DP と互換性があります。 数値を直接列挙するのではなく、最後の桁と次のステップが上がるか下がるかをエンコードする DP 状態を使用して、辞書編集的に数値を数えて構築します。 指定されたプレフィックスと長さに対して有効な波状数値がいくつ存在するかを数えることができたら、二分探索を行うか、k 番目の有効な数値を直接構築することができます。

割り算制約により 2 次元が導入されますが、n が大きくなる可能性があるため (最大 10^14)、すべての可能な剰余に対して不用意にモジュロ DP を使用することはできません。 ただし、数値を構築しながら、モジュロ n を増分的に追跡することはできます。 これにより、問題は、位置、最後の桁、方向制約、および法 n の現在の剰余を組み合わせたステート マシンに変換されます。 

次に、デジット DP を実行して、特定の状態に対して有効な完了がいくつ存在するかをカウントし、それを使用して、k 番目の有効な数値を昇順に貪欲に構築します。 これにより、すべての候補を列挙することが回避され、代わりに検索スペースを直接ナビゲートします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(10^14・d) | お(1) | 遅すぎる |
 | 最適な桁 DP + 構造 | O(14 · 10 · 2 · n 状態) メモ化で償却 | O(14 · 10 · n 状態) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、k 番目の数字に到達するのに十分な有効な補完がまだ許可されている状態にのみ移行することを常に保証しながら、回答を 1 桁ずつ構築することで問題を解決します。 

1. 辞書編集的にも数値的にも常に小さい数値が最初に来るため、長さを増やすことによって有効な数値を列挙することにします。 1 から 14 までの長さを試します。k はすべての有効な数値のソート順序を参照するため、これが必要です。 
2. 固定長の場合、部分的に構築されたプレフィックスを記述する数字の DP 状態を使用します。 状態には、現在位置、選択された最後の桁、次の桁が大きいか小さいか (または最初は未決定)、および n を法とする現在の剰余が含まれます。 
3. 波形条件を考慮して、0 から 9 までのすべての可能な次の数字を試す DP 遷移を定義します。 前の比較が「上」の場合、次の桁はより小さい必要があり、その逆も同様です。 最初のステップにいる場合は、ゼロ以外の数字を許可します。 
4. 各遷移は剰余モジュロ n を更新します。 これにより、最後の桁に到達するまでに、作成された数値が n で割り切れるかどうかがわかるようになります。 
5. DP 結果を事前計算またはメモ化して、どの状態からでも有効な補完がいくつ存在するかを迅速に計算できるようにします。 構築中に同じサブ問題を繰り返しクエリするため、これは不可欠です。 
6. k 番目の数値を見つけるには、空のプレフィックスから開始して 1 桁ずつ繰り返します。 各ステップで、候補の数字を昇順に試し、各候補について、有効な補完がいくつ存在するかをクエリします。 カウントが k 未満の場合は、それを減算して続行します。 それ以外の場合は、その数字をコミットし、対応する状態に移行します。 
7. 全長に達したら、残りがゼロかどうかを確認します。 そうであれば、n で割り切れる有効な波形数が見つかったことになります。 それ以外の場合は続行します。 
8. 14 までのすべての長さにわたって数値が見つからない場合は、-1 を出力します。 

### なぜ効果があるのか

 正確さは、DP がすべての有効な波形数値の空間をプレフィックス状態によって定義された互いに素なサブツリーに分割するという事実に基づいています。 各状態は、波形制約に違反することなく従うことができる一連の完了を正確に表します。 遷移では有効性とモジュロの正確性の両方が維持されるため、すべての完全なパスは一意の番号に対応し、すべての有効な番号は 1 つのパスにのみ対応します。 カウントを使用した貪欲な選択は安全です。カウントは、各候補分岐の下に有効なソリューションがいくつあるかを正確に測定するためです。そのため、分岐をスキップしても、ソート順で前に表示されるはずの有効な候補を削除することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache

sys.setrecursionlimit(1000000)

def solve():
    n, k = map(int, input().split())

    LIMIT = 10**14

    # We will generate numbers by length
    # For each length, we do digit DP with state:
    # pos, last_digit, direction (-1 decreasing, +1 increasing, 0 unset), remainder, started

    @lru_cache(None)
    def dp(pos, last, dir, rem, started, length):
        if pos == length:
            return 1 if started and rem == 0 else 0

        res = 0
        for d in range(10):
            if not started and d == 0:
                continue

            if not started:
                ndir = 0
                nlast = d
                nstarted = 1
                ok = True
            else:
                if dir == 0:
                    if d == last:
                        continue
                    ndir = 1 if d > last else -1
                    nlast = d
                    nstarted = 1
                    ok = True
                else:
                    if dir == 1 and d < last:
                        ndir = -1
                    elif dir == -1 and d > last:
                        ndir = 1
                    else:
                        continue
                    nlast = d
                    ok = True
                    nstarted = 1

            nrem = (rem * 10 + d) % n
            res += dp(pos + 1, nlast, ndir, nrem, nstarted, length)

        return res

    def kth_for_length(length):
        nonlocal k
        # try to construct lexicographically smallest within this length
        pos = 0
        last = 0
        dir = 0
        rem = 0
        started = 0
        res_digits = []

        for pos in range(length):
            for d in range(10):
                if not started and d == 0:
                    continue

                if not started:
                    nstarted = 1
                    nlast = d
                    ndir = 0
                    ok = True
                else:
                    if dir == 0:
                        if d == last:
                            continue
                        ndir = 1 if d > last else -1
                        nlast = d
                        nstarted = 1
                    else:
                        if dir == 1 and d < last:
                            ndir = -1
                        elif dir == -1 and d > last:
                            ndir = 1
                        else:
                            continue
                        nlast = d
                        nstarted = 1

                nrem = (rem * 10 + d) % n
                cnt = dp(pos + 1, nlast, ndir, nrem, 1, length)

                if cnt < k:
                    k -= cnt
                else:
                    res_digits.append(d)
                    last = nlast
                    dir = ndir
                    rem = nrem
                    started = 1
                    break
            else:
                return None

        if rem == 0 and started:
            return int("".join(map(str, res_digits)))
        return None

    for length in range(1, 15):
        dp.cache_clear()
        ans = kth_for_length(length)
        if ans is not None:
            print(ans)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```DP は、遷移に直接エンコードされた制約を持つ有効な数字シーケンスの完全な列挙を中心に構造化されています。 状態空間は固定ターゲット長に依存するため、メモ化は長さごとにリセットされます。 構築中、DP カウントに基づいて k 番目の解がサブツリー内にあるかどうかを判断し、それに応じてカウントを減算します。 

微妙な点は、初期方向の処理です。2 つの異なる数字を選択するまでは、方向は未定義です。 実装では、特別なゼロ状態を使用してこれをエンコードし、最初の比較後にのみ定義された上方向または下方向に遷移します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、答えが 1 桁の数字の間にある場合です。 入力用`n = 5, k = 1`、すべての単一の数字は自明に波状であるため、アルゴリズムは時期尚早に方向制約を強制しようとしてはなりません。 方向が設定されておらず、遷移は最初の桁に対して有効なままであるため、DP はこれを処理します。 

もう 1 つのエッジ ケースは、n で割り切れる有効な波状数値が 10^14 内に存在しない場合です。 たとえば、n が大きく、互換性のある桁構造がない場合、DP は最終的に 14 までの長さをすべて使い尽くして -1 を返します。 構築ループはすべての長さを明示的にチェックし、途中で停止したために有効な候補がスキップされないようにします。
