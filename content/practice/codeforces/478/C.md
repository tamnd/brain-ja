 ## 解決策
 ## 問題の理解

 風船は赤、緑、青の3種類をご用意しております。 宴会の各テーブルにはちょうど 3 つのバルーンが必要ですが、3 つのバルーンすべてを同じ色のテーブルにすることはできません。 このタスクは、特定の数の赤、緑、青の風船を考慮して装飾できるテーブルの最大数を計算することです。 

入力は、各色のバルーンの数を表す 3 つの整数で構成されます。 出力は単一の整数、つまり制約を満たすテーブルの最大数です。 バルーン数の上限は 2×10^9 までです。これは、考えられるすべての組み合わせを反復するアルゴリズムを用意できないことを意味します。 入力値に対して本質的に一定時間で実行されるソリューションが必要です。 

単純なアプローチでは、使用可能な各色から常に 1 つのバルーンを取得して、ループ内のカウントを減らそうとする可能性があります。 1 つの色が優勢な場合、これは失敗します。緑と青よりも多くの赤い風船がある場合、常にそれぞれ 1 つを取得する単純な貪欲なアプローチでは、より効果的に組み合わせることができた未使用の赤い風船が残る可能性があります。 例としては、赤 10 個、緑 1 個、青 1 個の風船があります。 単純に各色を 1 つ選択すると、テーブルが 1 つだけ作成されますが、すべて同じ色の繰り返しを避ける必要があるため、それ以上のテーブルを作成することはできません。 正しい出力は確かに 1 ですが、もう少しバランスの取れた数値を使用すると貪欲な選択が自明でなくなる可能性があるため、アルゴリズムは相対的なサイズについて推論する必要があります。 

もう 1 つの潜在的な落とし穴は、バルーンの合計を 3 で割る整数に依存することです。 テーブルの最大数を超えることはできませんが、`(r + g + b) // 3`、これは単なる上限です。 不注意な方法では、個々の色の制限を考慮せずにこの値を直接返す可能性があります。 

## アプローチ

 強引な方法は、すべてが同じ色ではないことを確認しながら、3 つの風船を繰り返し選択することです。 実際には、最大の 3 つのカウントを選択し、それぞれをデクリメントします。 これにより正確性が保証されますが、すべてのカウントが大きい場合、最悪の場合、最大 2×10^9 の反復が必要になる可能性があります。 明らかに、これを何度も繰り返すのは現実的ではありません。 

最適な解決策を得る上で重要な点は、問題が風船の総数と最大の個別色の両方によって制約されるということです。 各テーブルには 3 つのバルーンが必要なので、テーブルの最大数は次のとおりです。`(r + g + b) // 3`。 一方、1 つの色が他の 2 つの色の合計よりも多い場合、余分なバルーンを組み合わせてテーブルを形成することはできないため、テーブルの有効数も 2 つの小さい色の合計によって制限されます。 したがって、テーブルの真の最大数は、次の 2 つの量の最小値になります。`(r + g + b) // 3`そして`r + g + b - max(r, g, b)`(同等に、2 つの小さい数値の合計)。 これにより、ドミナントカラーを過剰に割り当てたり、テーブルごとのカラールールに違反したりすることがなくなります。

 ## アルゴリズムのチュートリアル

 1. 赤、緑、青の風船の数を変数に読み込みます`r`、`g`、 そして`b`。 これにより、作業に使用できるリソースの合計がわかります。 
2. すべてのバルーンの合計を計算します。 整数除算を使用してこの合計を 3 で割ると、色のバランスが完全に取れている場合のテーブルの理論上の最大数が得られます。 これを次のように保存します`max_by_total`。 これにより、利用可能なバルーンの総数を超えることがなくなります。 
3. 3 つの色の中で最大のバルーン数を特定します。 2 つの小さい数の合計が、テーブルごとの色の制限に違反することなく実際に形成できるテーブルの最大数になります。 これを次のように保存します`max_by_balance`。 
4. 答えは最小値です。`max_by_total`そして`max_by_balance`。 これにより、バルーンの合計制限と配布制約の両方が遵守されることが保証されます。 

機能する理由: このアルゴリズムは 2 つの不変条件を維持します。 初め、`(r + g + b) // 3`バルーンの総数を超えるテーブルを作成できないようにします。 次に、2 つの小さいカウントの合計により、テーブルに 3 つの同じ色が含まれることがなくなります。 各テーブルは 3 つの色を組み合わせて 1 つのバルーンを削除するため、この境界はすべての可能な配置を捕捉します。 最小限の保証を考慮すると、両方の制約を同時に尊重します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

r, g, b = map(int, input().split())

total = r + g + b
max_total_tables = total // 3
max_by_balance = total - max(r, g, b)

print(min(max_total_tables, max_by_balance))
```コードはまず、以下を使用して 3 つの整数を効率的に読み取ります。`sys.stdin.readline`。 風船の総数を計算し、3 で割ることにより理論上の上限を導き出します。 次に、2 つの小さいカウントの合計を次のように計算します。`total - max(r, g, b)`、これは他の 2 色の合計を取ることと同じです。 最後に、両方の制約を考慮して 2 つの境界の最小値を出力します。 並べ替えの代わりに減算を使用すると、不必要な操作を避けるための微妙な最適化が行われます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    r, g, b = map(int, input().split())
    total = r + g + b
    return str(min(total // 3, total - max(r, g, b)))

# Provided samples
assert run("5 4 3\n") == "4", "sample 1"
# Custom cases
assert run("10 1 1\n") == "2", "dominant red"
assert run("0 0 0\n") == "0", "no balloons"
assert run("6 6 6\n") == "6", "all equal"
assert run("2 3 7\n") == "5", "large imbalance"
assert run("2000000000 2000000000 2000000000\n") == "2000000000", "maximum values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 10 1 1 | 2 | 1 つの色が優勢で、テーブルが制限される |
 | 0 0 0 | 0 | バルーンなし、テーブルなし |
 | 6 6 6 | 6 | すべての色が均等で、完璧にバランスが取れています。 
| 2 3 7 | 5 | 不均衡は正しく処理されました |
 | 2×10^9 2×10^9 2×10^9 | 2×10^9 | 最大入力値 |

 ## 特殊なケース

 入力用`10 1 1`、合計を 3 で割ると 4 になりますが、最大の色は 10 で、他の 2 つの合計は 2 になります。アルゴリズムは次のように計算します。`total - max(r, g, b) = 12 - 10 = 2`、テーブルを 2 に正しく制限します。入力の場合`0 0 0`、 両方`total // 3`そして`total - max(...)`yield 0、正しくゼロテーブルを生成します。 すべてのカウントが等しい場合、合計を 3 で割って、`total - max(...)`同じ番号を生成し、off-by-one エラーが発生しないようにします。 これは、このアプローチが極端な不均衡と完全にバランスのとれた入力の両方を正しく処理することを示しています。
