 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、$n$正確に分割する必要がある人々$m$空ではないグループ。 グループ分けが固定されると、同じグループ内のすべてのペアが友情になります。 サイズのグループ$k$貢献する$\frac{k(k-1)}{2}$したがって、友情の合計数は、すべてのグループにわたるこの式の合計になります。 

課題は、すべての有効な分割方法において、そのような友情ペアの可能な最小数と最大数を決定することです。$n$人が入り込む$m$空ではないグループ。 

制約$n \le 10^9$グループを列挙したり、分布をシミュレートしたりするソリューションは直ちに除外されます。 どのアプローチでも、閉形式推論のみを使用して一定時間内に答えを計算する必要があります。 

次の場合、微妙なエッジケースが発生します。$m = n$。 この場合、どのグループもサイズ 1 になるため、友情は形成されません。 もう一つは$m = 1$、すべての人が単一のグループに属し、答えが固定されます。 単純な貪欲シミュレーションでは、誤ってグループを段階的に構築しようとする可能性がありますが、$n$が大きい場合、直線的な建設さえ不可能であり、不必要です。 

## アプローチ

 重要な観察は、友人関係の数はグループのサイズとその機能にのみ依存するということです。$\frac{k(k-1)}{2}$で二次的に成長します$k$。 この凸状性により、最小構成と最大構成の両方が決まります。 

最大の目的として、人々を 1 つの大きなグループに集中させたいと考えています。これは、2 つのグループを一緒にすると、内部ペアの総数が、分割することで減少するよりも常に増加するためです。 多数の小さなグループから開始すると、マージによってペアの数が、グループ サイズ間の交差項に依存する量だけ増加します。この量は常に正になります。 したがって、最適な構成は次のようになります。$n - (m-1)$人々を一つのグループにまとめ、残りは離れる$m-1$グループをシングルトンとして扱います。 

最小値については、逆の直感が当てはまります。 二次成長は大規模なグループにペナルティを与えるため、すべてのグループにできるだけ均等に人々を分配したいと考えています。 グループ サイズが 1 より大きく異なる場合、1 つの要素を大きいグループから小さいグループに移動すると二乗和が減少するため、内部ペアの数が減少します。 これにより、グループ サイズが次のいずれかになる、最もバランスのとれたパーティションが得られます。$\lfloor n/m \rfloor$または$\lceil n/m \rceil$、正確なカウントは剰余によって決定されます。 

次のように書くことで最小値を正確に導き出すことができます。$n = m \cdot q + r$、 どこ$0 \le r < m$。 それから$r$グループにはサイズがある$q+1$、 そして$m-r$グループにはサイズがある$q$。

 ## アルゴリズムのチュートリアル

 最適なグループ構造から導出された式を使用して、両方の極値を直接計算します。 

### 最大限の友情

 1.割り当て$m-1$サイズ 1 のグループ。これは$m-1$社内の友人関係がゼロの参加者。 
2.残りをすべて入れる$n - (m-1)$参加者を 1 つのグループにまとめます。 
3. この大規模なグループ内の友人関係を次のように計算します。$\frac{k(k-1)}{2}$、 どこ$k = n - m + 1$。 
4. この値を最大値として返します。 

その理由は、2 つのグループを合併するたびに、友情となる新しいクロスペアが導入されるため、統合によって常に合計が増加するということです。 

### 最低限の友人関係

 1. 基本サイズを計算する$q = n // m$そして残り$r = n \% m$。 
2.構築する$r$サイズのグループ$q+1$そして$m-r$サイズのグループ$q$。 
3. 寄与を計算します。$$r \cdot \frac{(q+1)q}{2} + (m-r) \cdot \frac{q(q-1)}{2}$$4. 合計を最小値として返します。 

これが機能する理由は、1 つの要素を大きいグループから小さいグループに移し、ペア数の合計を厳密に減らすことで、2 つのグループ間の不均衡を軽減できるためです。 

### なぜ効果があるのか

 機能$f(k) = \frac{k(k-1)}{2}$に凸です$k$。 凸性は、境界分布で極端な構成が発生することを意味します。つまり、最大限に歪んでいる (1 つの大きなグループ) か、最大限にバランスが取れている (等しいサイズ) かのいずれかです。 固定総和制約の下で凸関数の和を最適化しているため、これら 2 つの構造はそれぞれ最大値と最小値に対して最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    # maximum: one large group, rest singletons
    k = n - (m - 1)
    kmax = k * (k - 1) // 2

    # minimum: balanced partition
    q, r = divmod(n, m)
    kmin = r * (q + 1) * q // 2 + (m - r) * q * (q - 1) // 2

    print(kmin, kmax)

if __name__ == "__main__":
    solve()
```最大の計算により、単一の大きなグループが暗黙的に直接構築されます。 引き算$n - (m-1)$正確に保証します$m-1$シングルトンは残りますが、ペアのカウントに関しては中立です。 

最小値の場合、商と剰余に分割することで、グループ サイズの差が最大 1 になることが保証されます。 この式では、ペアカウント式を各グループ サイズに適用し、明示的にグループを構築せずにそれらを合計します。 

実装上の主な落とし穴は、整数の除算の処理です。 使用する`divmod`不一致を回避し、剰余の分布が正しいことを保証します。

 ## 特殊なケース

 のために$m = n$、私たちは得ます$q = 1, r = 0$。 各グループが寄与するため、最小の式はすべてゼロのグループになります。$\frac{1 \cdot 0}{2} = 0$、最大値は次のようになります$n - (n-1) = 1$、これもゼロペアを与えます。 

のために$m = 1$、 我々は持っています$k = n$最大の場合、完全な$\frac{n(n-1)}{2}$。 最小の式は同じ単一グループの計算に折りたたまれます。$q = n, r = 0$。 

大型用$n$、どちらの数式も、次の値までの整数の乗算のみを使用するため、安全なままです。$10^9$、これは Python では 64 ビット整数の範囲内に快適に収まります。
