 ## 解決策
 ## 問題の理解

 赤と緑の 2 種類のブロックで階段状の構造物を構築するように求められます。 構造にはいくつかのレベルがあり、レベルはサイズが厳密に減少する順序を形成します。最上位レベルにサイズがある場合`n`、次は`n-1`、 それから`n-2`など、以下に至るまで`1`。 

すべてのレベルは単色である必要があります。つまり、各レベルは完全に赤または完全に緑ですが、異なるレベルは独立して色を選択できます。 高さを選択すると、使用されるブロックの総数が固定されます`n`、構造では常に三角数が使用されるため`n(n+1)/2`ブロック。 

最初のタスクは、可能な最大の高さを決定することです`h`必要なブロックの総数が利用可能な供給量を超えないようにします。`r`赤と`g`緑色のブロックを組み合わせたもの。 この高さを固定した後、有効な色の数を数えなければなりません。`h`レベルが存在するため、各レベルに色を割り当てることができ、使用可能な赤または緑のブロックの数を超えることはありません。 

主な難点は、制約が合計使用量だけではなく、異なるサイズのレベル間で色ごとに分割されることです。 総ブロックのみをチェックする単純なアプローチでは、色の割り当ての実現可能性が無視されます。 

この制約により、各色のブロックは最大 200,000 個まで許可されます。 レベルへのすべての色の割り当てを直接列挙すると、指数関数的になります。`h`、各レベルは二者択一であるため。 これにより、すべての割り当てに対するブルートフォースが即座に排除されます。 指数関数的な決定空間を圧縮する動的プログラミング アプローチが必要です。 

エッジケースは、1 つの色がゼロの場合に発生します。 もし`r = 0`の場合、すべてのレベルは緑色でなければならず、三角形の合計が範囲内に収まる場合にのみ最大の高さを構築できます。`g`。 その場合、答えは実現可能性に応じて 1 か 0 になります。 対称的な議論は次のように成り立ちます`g = 0`。 もう 1 つの微妙なケースは、最大高さは小さいが、両方のリソースが大きい場合です。これにより、カウントする次元が支配的な部分になります。 

## アプローチ

 直接的なアプローチは、最初に可能な最大の高さを計算することです。`h`。 レベルが上がるごとに追加されるので、`i`レベルのブロック`i`、必要な合計は`h(h+1)/2`。 増やします`h`この合計を超えるまで`r + g`。 この部分は簡単です。 

本当の複雑さは、これらの色の割り当てを数えることから生まれます。`h`レベル。 各レベル`i`赤または緑に着色できます。 レベルが赤の場合、消費します`i`赤いブロック。 緑色の場合は消費します`i`緑のブロック。 赤の使用量の合計が次を超えないようにする必要があります`r`、およびグリーン使用量の合計が以下を超えないこと`g`。 

ブルートフォースソリューションはすべてを試します`2^h`割り当てを行い、実現可能性を確認します。 これは非常に小さい場合にのみ機能します`h`。 のために`h`約 200,000 ですが (ただし、実際には三角形の成長によりこれははるかに小さくなります)、これは不可能です。 

重要な点は、実際には両方の色を詳細に対称的に追跡する必要はないということです。 レベルのどのサブセットが赤であるかを決定すると、緑が自動的に決定されます。 問題は次のようになります:`{1,2,...,h}`合計は最大で誰の`r`、補数和は最大でも`g`。 

合計を`S = h(h+1)/2`。 サブセットの合計が次の場合`x`、その後、赤は使用します`x`そしてグリーンユース`S-x`。 したがって、次のものが必要です。`x ≤ r`そして`S - x ≤ g`、これは次と同等です。`S - g ≤ x ≤ r`。 

したがって、問題は次の部分集合の合計を数えることに帰着します。`{1..h}`制限された間隔内にあるもの。 

DP を次のように定義します。`dp[i][j]`最初に選択する方法の数です`i`選択したレッドサムが正確に一致するようなレベル`j`。 各レベル`i`どちらかが赤になります（追加）`i`) または緑 (赤の合計には何も追加しません)。 これは古典的なナップサックスタイルのトランジションです。 

までのDPのみが必要です`r`、有効な値を合計します`j`で`[S-g, r]`。 

これにより、指数割り当て空間が合計値にわたる多項式 DP に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | レベルを超える総当たり攻撃 | O(2^h) | O(h) | 遅すぎる |
 | サブセット合計に対する DP | O(h・r) | O(r) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最大高さを計算する`h`そのような`h(h+1)/2 ≤ r + g`。 これにより、構造の合計サイズが固定されます。 その理由は、有効なタワーは、色の分割に関係なく、使用可能なブロックの合計内に収まる必要があるためです。 
2. 必要なブロックの合計を計算する`S = h(h+1)/2`。 これにより、2 つのリソース制約を赤の使用量に関する単一の間隔制約に変換できます。 
3. 赤の使用の有効範囲を次のように導出します。`[L, R] = [S - g, r]`。 赤レベルの割り当てはすべてこの範囲内に収まる必要があり、そうでない場合は緑または赤の容量を超えます。 
4. DP 配列を初期化する`dp`サイズの`r + 1`、 どこ`dp[j]`赤和を達成する方法の数を表します`j`処理されたレベルを使用します。 
5.セット`dp[0] = 1`、赤レベルを選択しないと合計がゼロになるためです。 
6. 以下のレベルを反復します。`1`に`h`。 レベルごとに`i`、DP を逆の順序で更新します。`r`まで`i`。 これにより、各レベルが最大 1 回使用されることが保証されます。 
7. 到達可能な金額ごとに`j`、遷移を伝播します: いずれかのレベルを維持します`i`緑 (何もしない)、または赤を割り当てて寄与を移動します。`dp[j - i]`に`dp[j]`。 
8. すべてのレベルを処理した後、すべてを合計します。`dp[j]`のために`j`で`[L, R]`。 これにより、すべての有効な構成が集約されます。 

### なぜ効果があるのか

 各レベルは独立して赤または緑に割り当てられます。 緑は補数によって決定されるため、赤のレベルのみをエンコードするだけで十分です。 DP は、サブセット合計の構築を通じて、レベルのすべてのサブセットが正確に 1 回カウントされることを保証します。 間隔制約により、両方の色の実現可能性が同時に強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    r, g = map(int, input().split())

    # find maximum height h such that h(h+1)/2 <= r+g
    total = r + g
    h = 0
    while (h + 1) * (h + 2) // 2 <= total:
        h += 1

    S = h * (h + 1) // 2

    L = max(0, S - g)
    R = min(S, r)

    if L > R:
        print(0)
        return

    dp = [0] * (r + 1)
    dp[0] = 1

    for i in range(1, h + 1):
        for j in range(r, i - 1, -1):
            dp[j] = (dp[j] + dp[j - i]) % MOD

    ans = sum(dp[L:R+1]) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、三角形の成長を使用して実現可能な高さを決定します。 次に、問題をレベル サイズに対するサブセット合計 DP に変換します。 DP ループでの逆方向の反復は、同じレベルを複数回再利用することを避けるために不可欠です。 最後の合計ステップでは、2 色の制約から導出された有効な赤の範囲が適用されます。 

よくある実装上の間違いは、制約が単なる合計ではなく、サブセット合計の制限された間隔であることを忘れていることです。 もう 1 つは、DP を逆方向ではなく前方向に反復することで、誤って同じレベルを複数回再利用することを許可します。 

## 実用的な例

 ### 例 1

 入力:```
4 6
```ここで、利用可能なブロックの合計は 10 です。`h`と`h(h+1)/2 ≤ 10`は`h = 4`, 4・5/2 = 10 なので。 

したがって、レベルは`{1,2,3,4}`、合計`S = 10`。 

有効なレッドサムは満たす必要があります`S - g ≤ x ≤ r`、 それで`10 - 6 ≤ x ≤ 4`、つまり`4 ≤ x ≤ 4`。 したがって、赤の和は正確に 4 でなければなりません。 

以下の部分集合の合計を計算します。`{1,2,3,4}`4 に等しい。これらは`{4}`そして`{1,3}`。 

| レベル | アクション | dp 状態 (ゼロ以外のエントリ) |
 | --- | --- | --- |
 | 0 | 初期化 | {0:1} |
 | 1 | 1を追加 | {0:1、1:1} |
 | 2 | 2を追加 | {0:1、1:1、2:1、3:1} |
 | 3 | 3を追加 | {0:1、1:1、2:1、3:2、4:1、5:1、6:1} |
 | 4 | 4を追加 | {4:2、...} |

 最終的な答えは 2 です。 

このトレースは、DP が有効な赤の割り当てを生成する個別のサブセットを正確にカウントしていることを示しています。 

### 例 2

 入力:```
3 3
```合計は6なので最大です`h = 3`, 3・4/2 = 6なので。 

赤の合計が必要です`[6-3, 3] = [3,3]`、つまり正確には 3 です。 

のサブセット`{1,2,3}`合計すると 3 になります`{3}`そして`{1,2}`。 

DP は正確に 2 つの方法で蓄積され、正しさを確認します。

 ## 特殊なケース

 1 つのリソースがゼロの場合、完全な三角和が適合する場合に限り、DP は単一の有効な構成に縮退します。 有効な間隔は単一の値に集約され、1 つのサブセット合計のみがそれに一致するため、アルゴリズムはこれを自然に処理します。 

いつ`r + g`非常に小さな塔を形成するのに十分な大きさであるため、DP は非常に少数のレベルにわたって実行されます。 サブセットサム構造により、小さなインスタンスであっても特別なケースを使用せずに確実に処理されます。 

いつ`r`よりもはるかに大きいです`g`、有効な間隔`[S-g, r]`ゼロより上で開始する場合があり、これにより多くの DP 状態が除外されます。 合計ステップにより、実行可能な構成のみがカウントされるようになり、グリーン キャパシティを超えるサブセットの過剰カウントが回避されます。
