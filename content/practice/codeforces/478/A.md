 ## 解決策
 ## 問題の理解

 非常に厳密なルールの下でゲームを開始した 5 人の参加者によるシステムの最終状態が与えられています。つまり、誰もが同じ未知の正の数のコインから開始します。$b$。 この初期化の後、コインはプレイヤー間でのみ移動されます。 プロセス中にコインが作成または破壊されることはありません。 すべての操作は、ある人から別の人に 1 つのコインを転送するだけです。 

最後に、5 人のプレイヤーがそれぞれ何枚のコインを持っているかを観察します。 この最終的な分布から、すべてのプレイヤーがもともと同じ正の数のコインを持っていた可能性があるかどうかを判断する必要があり、そうであれば、その初期値を回復する必要があります。$b$。 そのルールに基づいて最終状態を説明する方法がない場合は、それは不可能であると報告する必要があります。 

重要な構造上の制約は、コインの総量を維持することです。 送金によってコインの総数は変化しないため、最終値の合計は初期値の合計と等しくなければなりません。$5b$。 これは、最終的な配列の合計が 5 で割り切れる必要があり、商が次の候補値になることを直ちに意味します。$b$。 

制約は非常に小さく、各最終カウントは最大 100 で、値は 5 つだけです。 これにより、高度なデータ構造や最適化が不要になります。 直接計算すれば十分です。 

主な微妙な点は、有効な再配布と無効な再配布を区別することにあります。 たとえば、次のような状態$1, 1, 1, 1, 1$で有効です$b = 1$。 のような状態$2, 2, 2, 2, 2$で有効です$b = 2$。 しかし、次のような状態$1, 1, 1, 1, 2$の合計は 6 であり、5 で割り切れないため、転送に関係なく等しい開始値から求めることはできません。 

さらに誤解を招きやすいケースは、合計が 5 で割り切れるが、否定的な推論によって不可能性が示唆される場合です。 例えば、$0, 0, 0, 0, 5$和は5なので、$b = 1$。 これは有効です。1 人のプレイヤーが最終的にすべてのコインを寄付することになります。 全体的な保存を使用せずに個々の実現可能性について推論しようとするアプローチは、基本的に単一の算術条件であるものを過度に複雑にする危険があります。 

## アプローチ

 強引なアイデアとしては、考えられるすべての初期値を試してみることです。$b$1 から 100 までの値を計算し、5 つの等しい山の初期状態からターゲット構成に達するまでコインを再分配できるかどうかをシミュレートします。 これは概念的には単純ですが、任意の転送下での到達可能性の決定という難しい副次的問題が隠れています。 コインは 2 人のプレイヤー間で自由に移動できるため、状態空間は大きくなりますが、グラフ構造や移動制限には制約されません。 したがって、シミュレーションでは一連の転送を再構築する必要がありますが、これは不必要です。 

重要な単純化は、転送では合計額が正確に保持されることを認識することです。 これにより、問題は動的な到達可能性の問題から静的な算術条件に分解されます。 最終的な構成は、その合計が次の値に等しい場合にのみ有効です。$5b$、 どこ$b$正の整数でなければなりません。 

したがって、問題全体は、和を計算し、割り切れるかどうかを確認することに帰着します。

 ## アルゴリズムのチュートリアル

 1. 各プレイヤーの最終的なコイン数を表す 5 つの整数を読み取ります。 
2. それらの合計を計算します。 この合計はシステム内のコインの総数を表し、ゲーム全体を通じて変わることはありません。 
3. 合計が 5 で割り切れるかどうかを確認します。割り切れない場合は、均等な初期分配は不可能です。$5b$合計と等しくなければなりません。 
4. 割り切れる場合は計算する$b = \frac{\text{sum}}{5}$。 
5. 確認する$b > 0$。 合計がゼロの場合、すべてのプレーヤーがコインゼロで終了したことになり、最初の賭け金が厳密にプラスであるという要件に矛盾します。 
6. 出力$b$有効な場合、そうでない場合は -1 を出力します。 

### なぜ効果があるのか

 不変条件はコインの総保存です。 ゲーム内のすべての操作はプレーヤー間のユニット転送であり、すべてのコインの合計が保持されます。 したがって、最終的な合計は最初の合計と正確に等しくなければなりません。 初期設定では同じ値が 5 つあるため、$b$、合計は次のようにする必要があります$5b$。 これは一意に決定されます$b$解決策が存在するときはいつでも、可分性や肯定的な規則に違反すると、直ちに不可能であることがわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    c = list(map(int, input().split()))
    total = sum(c)

    if total % 5 != 0:
        print(-1)
        return

    b = total // 5

    if b <= 0:
        print(-1)
        return

    print(b)

if __name__ == "__main__":
    solve()
```実装は不変式ベースの推論に直接従うものです。 唯一の計算は 5 つの値の合計です。 可分性チェックにより、初期分布が等しいモデルとの一貫性が保証されます。 この問題ではゼロではなくプラスの初期ベットが明示的に必要とされるため、陽性チェックが必要です。 

よくある間違いは、陽性条件をスキップすることです。 それがなければ、次のような入力`0 0 0 0 0`間違って結果を出してしまいます$b = 0$たとえルールが最初の賭け金をゼロにすることを禁じているとしてもです。

 ## 特殊なケース

 微妙なエッジケースは、すべてのプレイヤーがコインをゼロで終了する場合です。 合計はゼロであり、5 で割り切れますが、これは次のことを意味します。$b = 0$。 この問題では厳密にプラスの初期ベットが必要なため、これは拒否する必要があります。 アルゴリズムは明示的にチェックすることでこれを処理します。$b > 0$、ゼロが有効な解として通過しないことを保証します。 

もう 1 つのケースは、次のような非常に偏った分布です。`0 0 0 0 5`。 ここで合計は 5 となり、$b = 1$。 初期の 5 枚のコインはすべて時間の経過とともに 1 人のプレイヤーに転送できるため、不変条件は有効性を保証し、アルゴリズムはそれを正しく受け入れます。 

最後に、合計が 5 で割り切れない入力は即座に拒否され、これ以上の理由を必要とせずに無効な状態の大部分がカバーされます。
