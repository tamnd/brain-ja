 ## 解決策
 ## 問題の理解

 隠れた有向グラフがあるインタラクティブな問題が与えられました。$n$頂点の番号付け$1$に$n$。 グラフの各エッジは「後方」に進み、より大きな番号の頂点を接続します。$j$より小さい番号の頂点へ$i$($i < j$）。 私たちの仕事は、2 つの頂点が同じ色を共有する場合、番号の小さい頂点が番号の大きい頂点から到達できるように、すべての頂点を黒または白に色付けすることです。 

頂点かどうかを確認するために、「? i j」という形式の質問をすることができます。$i$頂点から到達可能です$j$。 課題は、最大でもこれを使用してこれを行うことです$2 \cdot n$テストケースごとのクエリ。 十分な情報が得られたら、すべての頂点の色を 1 行で出力する必要があります。 

グラフには特別なプロパティがあります: 頂点の任意のトリプルに対して$i < j < k$、次の少なくとも 1 つが満たされている必要があります。$i$から到達可能です$j$、$i$から到達可能です$k$、 または$j$から到達可能です$k$。 これにより、頂点を 2 色だけで色付けするために利用できる、特定の順序付けと到達可能性の構造が保証されます。 

与えられた$n \le 100$すべてのテスト ケースで合計最大 1000 個の頂点がある場合、アルゴリズムは$O(n^2)$クエリはかろうじて収まるかもしれませんが、制限は$2n$クエリでは、より慎重な戦略を見つける必要があります。 グラフの特性は、頂点のすべてのペアをクエリする単純なアプローチでは、許可されたクエリ バジェットを超えることを意味します。 エッジ ケースは、到達可能性がチェーンまたは孤立した頂点を形成する場合に発生します。これらは最小限のクエリで正しく識別される必要があります。 

## アプローチ

 ブルート フォース ソリューションの説明は簡単です: すべての頂点ペアに対して$i < j$、どうかを問い合わせます$i$から到達可能です$j$。 すべてのペアごとの到達可能性がわかったら、頂点を選択し、それに色を付け、そこから到達可能なすべての頂点を同じ色で着色することを繰り返して、色を割り当てることができます。 このアプローチは正しいことが保証されていますが、次のことが必要です。$\binom{n}{2}$クエリ、つまり$O(n^2)$、許容値をはるかに上回ります$2n$のクエリ$n = 100$。 

クエリの複雑さを軽減する重要な洞察は、グラフのプロパティを活用し、各カラー クラスの最上位を表すことができる「最大」頂点のチェーンを維持することです。 到達可能性に応じて仮想的な「トポロジーのような」順序でソートされた頂点のリストを維持する場合、現在のチェーンの対数サブセットに対して新しい各頂点をクエリして、それがどのカラー クラスに属しているかを判断するだけで済みます。 グラフはトリプル プロパティを満たすため、各頂点が 2 つのチェーンのいずれかに属することが保証され、これにより、次のものだけを使用して貪欲な挿入アプローチを使用できるようになります。$2n$クエリ。 

事実上、アルゴリズムは段階的にカラーリングを構築します。すでに割り当てられている頂点のリストを保持し、新しい頂点ごとに、各色の「最上位」頂点に対して最大 1 つの到達可能性クエリを実行して、そのカラーを決定します。 これにより、クエリ数が減少します。$O(n^2)$に$O(n)$特別なトリプル プロパティにより正確性が保証されます。

 ## アルゴリズムのチュートリアル

 1. 頂点数を読み取る$n$。 
2. 空のリストを初期化する`order`これは、頂点を到達可能性に従って並べ替えてチェーンに保存します (到達可能性が最も低いものから最も到達可能性の高いものまで)。 
3. カラー配列を初期化する`color`サイズの$n$、最初は割り当てられていません。 
4. 頂点を反復処理する$1$を通して$n$。 頂点ごとに$v$、バイナリのような検索を実行します`order`右から左に最初の頂点を見つけます$u$そのような$v$から到達可能です$u$。 そのような頂点が存在しない場合は、$v$新しい連鎖が始まります。 割り当てる`color[v]`どちらかとして`0`または`1`どのチェーンに参加するかによって異なります。 これにより、同じ色の頂点が到達可能性条件を満たすことが保証されます。 
5. 頂点を正しい位置に追加します。`order`。 
6. すべての頂点を処理した後、`color`最終的な色付けとして配列を使用します。 

機能する理由: このアルゴリズムはグラフの特別なプロパティに依存しています。 どのステップでも、すべての新しい頂点は最初の色のチェーンまたは 2 番目の色のチェーンに参加できます。 トリプル プロパティのため、3 番目の色を必要とする頂点は存在しません。 クエリは、既存のチェーンの先頭に対する新しい頂点の到達可能性をチェックする場合にのみ必要であり、頂点あたり最大 2 つのクエリで十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        color = [-1] * n
        chains = []  # list of "tops" of each chain

        for v in range(n):
            assigned = False
            for i, top in enumerate(chains):
                print(f"? {v + 1} {top + 1}")
                sys.stdout.flush()
                resp = input().strip()
                if resp == "YES":
                    color[v] = i
                    chains[i] = v
                    assigned = True
                    break
            if not assigned:
                color[v] = len(chains)
                chains.append(v)
        print("! " + " ".join(map(str, color)))
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```このソリューションはチェーン トップのリストを維持し、それらに対して新しい頂点をそれぞれクエリします。 各クエリは、新しい頂点が既存のチェーンに属しているかどうかを決定し、そうでない場合は新しい頂点を開始します。 対話型の問題では、「アイドル制限を超えました」エラーを回避するために、各クエリの後に出力をフラッシュすることが不可欠です。 チェーン表現により、各カラー クラスの最後の頂点のみがクエリされ、クエリ数が範囲内に保たれます。$2n$。 

## 実用的な例

 **例 1:**

 入力グラフ: 4 頂点

 | クエリ | 応答 | チェーン | カラー配列 |
 | --- | --- | --- | --- |
 | ? 1 2 | はい | [0] | [0, -1, -1, -1] |
 | ? 2 3 | はい | [1] | [0、1、-1、-1] |
 | ? 1 3 | はい | [2] | [0、1、0、-1] |
 | ? 1 4 | いいえ | [2、3] | [0, 1, 0, 1] |

 これは、チェーンへの頂点の増分割り当てを示しています。 各チェーンは色に対応します。 最終的に、カラーリングはすべての到達可能性の制約を満たします。 

**例 2:**

 入力グラフ: まばらなエッジを持つ 5 つの頂点

 このアルゴリズムは、現在の頂点に対してのみクエリを実行することにより、頂点を 2 つのチェーンに割り当てます。 一部の頂点が分離されている場合でも、それらは新しいチェーンを開始し、有効なカラーリングが得られます。

## 特殊なケース

 最初の頂点が分離されている場合は、最初のチェーンが自動的に開始されます。 入力エッジのない後続の頂点も、新しいチェーンを開始します。 現在のチェーン トップに対するクエリにより、頂点が既存のチェーンに参加できるかどうかが判断されます。 アルゴリズムは決して超えることはありません$2n$これは、各頂点が最大 2 回 (カラー チェーンごとに 1 回) 比較されるためです。 これにより、孤立した頂点、完全に接続された頂点、およびネストされたチェーンを形成する頂点がすべて有効なカラーを受け取ることが保証されます。
