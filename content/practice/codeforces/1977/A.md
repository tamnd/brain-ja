 ## 解決策
 ## 問題の理解

 ニキータのタワーは空から始まり、移動ごとに 2 つの操作のうち 1 つを実行できます。つまり、上に 1 つの立方体を置くか、上から 1 つの立方体を取り除くかのいずれかです。 問題は、正確に実行した後、`n`移動すると、タワーは正確に持つことができます`m`立方体。 各テスト ケースは移動数を提供します。`n`そして希望の高さ`m`。 これが可能であれば出力は「Yes」、そうでない場合は「No」となります。 

制約は小さいです:両方とも`n`そして`m`は最大 100 であり、テスト ケースも最大 100 です。 これは、おおよそ複雑なアルゴリズムを意味します`O(n)`各テスト ケースは制限時間内で快適に実行されます。 この問題は本質的に、徹底的なシミュレーションではなく、パリティと到達可能性に関するものです。 

明らかではないエッジケースが発生するのは次の場合です。`m`より大きい`n`またはいつ`m`そして`n`パリティが異なります。 たとえば、次の場合`n = 2`そして`m = 3`、わずか 2 回の手で 3 つのキューブに到達する方法はありません。 同様に、`n = 3`そして`m = 2`、移動は 3 回の操作後に高さ 2 でタワーを離れる必要がありますが、移動するたびに高さがちょうど 1 だけ変化するため、次のパリティが得られます。`n`そして`m`可能にするためには一致する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、キューブの追加と削除のすべてのシーケンスをシミュレートしようとします。 移動ごとに、再帰的に立方体の追加または削除を試み、最終的な高さが一致するかどうかを確認できます。`m`。 これは非常に小さな入力に対しては機能しますが、指数関数的に複雑になります。`n`移動には 2 つの選択肢があるため、`2^n`可能なシーケンス。 たとえ`n = 100`、これは不可能です。 

重要な洞察は、最終的なタワーの高さを制限する唯一の要因は総移動数であるということです。`n`とのパリティ`m`。 移動するたびにタワーの高さがちょうど 1 だけ変化します。`n`移動する場合、開始点 (ゼロ) からの高さの差は、次の値と同じパリティの数値でなければなりません。`n`。 さらに、達成可能な最大高さは次のとおりです。`n`ニキータがキューブを追加するだけの場合。 したがって、正確に到達するための条件は、`m`キューブはそれです`m`せいぜい`n`そして`m`と同じパリティを持っています`n`。 これにより、問題はシミュレーションなしの単純なチェックに減ります。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、整数を読み取ります。`n`そして`m`。 
3. 次のことを確認します。`m`以下である`n`。 そうでない場合は、「No」を出力して続行します。 
4. パリティが正しいかどうかを確認します。`n`そして`m`一致する、意味`(n - m) % 2 == 0`。 存在する場合は、「はい」を出力します。 それ以外の場合は「いいえ」を出力します。 

これが機能する理由は、移動するたびにタワーの高さがちょうど 1 だけ変化するためです。`n`そして`m`正確に到達するには偶数でなければなりません`m`後`n`動く。 条件`m <= n`ニキータが希望の高さに達するまでに許容以上の動きを必要としないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    if m <= n and (n - m) % 2 == 0:
        print("Yes")
    else:
        print("No")
```コードは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 各テスト ケースについて、次の 2 つの条件がすぐにチェックされます。`m <= n`高さに到達するのに十分な移動量を確保し、`(n - m) % 2 == 0`上下移動の回数を正確に調整できるようにする`m`。 これにより、不要なループや再帰が回避されます。 

## 実用的な例

 **例 1:**`n = 3, m = 3`| n | メートル | n - m | パリティチェック | 結果 |
 | --- | --- | --- | --- | --- |
 | 3 | 3 | 0 | 0 % 2 == 0 | はい |

 差はゼロ、偶数、そして`m <= n`, したがって、各移動でキューブを追加することで、3 つのキューブに到達することが可能です。 

**例 2:**`n = 2, m = 4`| n | メートル | n - m | パリティチェック | 結果 |
 | --- | --- | --- | --- | --- |
 | 2 | 4 | -2 | -2 % 2 == 0 | いいえ |

 パリティチェックは満たされていますが、`m > n`わずか 2 回の移動で高さ 4 に到達することは不可能になります。 

これらのトレースは、両方の条件が必要かつ十分であることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        if m <= n and (n - m) % 2 == 0:
            print("Yes")
        else:
            print("No")
    return out.getvalue().strip()

# provided samples
assert run("3\n3 3\n2 4\n5 3\n") == "Yes\nNo\nYes", "sample 1"

# custom cases
assert run("4\n1 1\n2 2\n2 1\n100 100\n") == "Yes\nYes\nNo\nYes", "edge and max"
assert run("2\n1 2\n3 0\n") == "No\nYes", "parity and zero"
assert run("3\n10 10\n10 0\n10 5\n") == "Yes\nYes\nNo", "all-even, all-zero, mismatched parity"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1、2 2、2 1、100 100 | はい、はい、いいえ、はい | 最小サイズ、完全一致、不可能な高さ、最大サイズ |
 | 1 2、3 0 | いいえ、はい | パリティの不一致、キューブがゼロに達します。 
| 10 10、10 0、10 5 | はい、はい、いいえ | 偶数最大、ゼロ、不可能なパリティ |

 ## 特殊なケース

 いつ`m = 0`そして`n`が偶数の場合、ニキータはキューブを交互に追加したり削除したりして空のタワーで終了できるため、アルゴリズムは正しく「はい」を出力します。 例えば、`n = 4, m = 0`結果として`(n - m) % 2 = 0`そして`m <= n`したがって、出力は「はい」になります。 

いつ`m > n`、アルゴリズムは即座に「いいえ」を出力し、否定的な手についての誤った仮定を回避します。 例えば、`n = 3, m = 5`パリティが一致しても、高さに到達できないため、「いいえ」が返されます。 

いつ`n`そして`m`パリティが異なる場合、アルゴリズムは「いいえ」を出力し、パリティの不一致により一連の ±1 の手がターゲットに到達できないという微妙なケースを検出します。`n = 5, m = 2`。
