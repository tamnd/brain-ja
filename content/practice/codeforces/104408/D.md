 ## 問題の理解

 私たちに与えられているのは、$n \times n$すべての行とすべての列に正確に 1 人の兵士が含まれるグリッド。 この構造は次の順列と同等です。$i$、兵士は列に配置されます$p_i$。 したがって、各ペア$(i, p_i)$グリッド内の単一の占有セルをマークし、2 人の兵士が行または列を共有することはありません。 

このタスクは、このグリッド内の空の正方形領域がどのくらいの大きさになるかを測定することを中心に展開します。 あらゆる軸に合わせて$k \times k$サブスクエアに兵士がまったくいない場合、それは空であるとみなされます。 構成の「弱点」は、そのような最大のものとして定義されます。$k$空の$k \times k$正方形はグリッド内のどこにでも存在します。 

指定された順列に対してこの値を計算した後、この構成が可能な限り最良の配置よりも悪いかどうかを判断する必要もあります。 考えられる最良の配置は、すべての有効な順列の中でこの弱点の値を最小化する配置です。 指定された弱点よりも厳密に小さい弱点を持つ設定が存在する場合、兵士の計画は間違っていると見なされ、兵士は「ブラックホールに陥る」ことになります。 

重要な制約は、$n \le 5 \cdot 10^4$。 これにより、すべての部分正方形の 3 次または 2 次チェックが除外されます。 たとえ$O(n^2)$すべての可能な正方形のスキャンは、次の順序をチェックする必要があるため、遅すぎます。$10^9$地域。 これにより、候補サイズごとに対数または線形に近いアプローチが必要になり、構造のソートや二分探索が含まれる可能性が高くなります。 

たとえば、すべての兵士が対角線の近くに位置する場合、微妙なエッジ ケースが表示されます。$p_i = i$。 この場合、大きな対角線に並んだ空の正方形がグリッドのさまざまな部分に依然として存在する可能性があり、点の局所的な近傍のみを検査する単純なアプローチではそれらを見逃す可能性があります。 もう 1 つの注意が必要なケースは、空の正方形が境界近くに形成される場合です。この場合、グリッドの片側はほとんど自由ですが、まだいくつかの点在する点によって拘束されています。 

## アプローチ

 この問題を直接考える方法は、考えられるすべての正方形を試して、そこに兵士が含まれているかどうかを確認することです。 がある$O(n^2)$左上隅から最大まで$O(n)$可能なサイズ、与える$O(n^3)$最悪の場合のチェック。 プレフィックス構造を使用してチェックを最適化したとしても、最終的には次のような結果になります。$O(n^2)$候補者が多すぎるため、$n = 5 \cdot 10^4$。 

重要な点は、実際にはすべての正方形を検査する必要はないということです。 代わりに、条件を再構成することができます。 正方形は、どの点も存在しない場合にのみ空になります。$(i, p_i)$選択された同じ長さの行間隔と列間隔内に収まります。 したがって、固定正方形サイズの場合$k$、問題は次のとおりです。$k$対応する列位置が連続するブロックを避ける連続行$k$コラム？ 

これで、構造はスライディング ウィンドウ内で 1 次元になります。 行の固定範囲の場合、列インデックスのセットのみを考慮します。$p_i$。 これらの値を並べ替えると、長さの空の列間隔が存在します。$k$少なくともサイズのギャップを見つけることと同等です$k$連続する占有列間 (境界を含む)$0$そして$n+1$）。 

これにより、二分探索が行われます$k$。 候補者ごとに$k$のウィンドウをスライドさせます。$k$行を管理し、その列位置のマルチセットを維持します。 各ウィンドウについて、ソートされた順序で最大ギャップを計算します。 いずれかの窓に少なくとも隙間がある場合$k$、次に空$k \times k$正方形が存在します。

 ## アルゴリズムのチュートリアル

 解決策を 2 つの部分に分けます。修正されたかどうかを確認します。$k$が実現可能であり、そのような最大値を検索します。$k$。 

1. 候補となる正方形のサイズを修正する$k$。 存在するかどうかを確認します$k \times k$空の広場。 
2. 一定の長さのウィンドウをスライドさせます$k$列の上に。 各位置で、列インデックスのセットを考慮します。$p_i$ウィンドウ内の行の場合。 
3. これらの列インデックスをソートされた構造で維持します。 これにより、占有位置間のギャップを効率的に推論できるようになります。 
4. 現在の列セットに対して、仮想境界を追加します。$0$そして$n+1$、次に、連続する要素間の最大差から 1 を引いた値を計算します。 この値は、空き列の最大の連続ブロックを表します。 
5. この最大空きブロックが少なくとも$k$の場合、この行ウィンドウは有効な空の行をサポートできます。$k \times k$四角。 
6. いずれかのウィンドウが成功した場合、そのサイズは次のとおりであると結論付けます。$k$実現可能です。 
7. 二分探索オーバー$k$から$1$に$n$、実現可能な最大値を維持します。 

正しさは、空のものが存在するかどうかに依存します。$k \times k$正方形は、長さの行間隔を定義します$k$。 その間隔内では、その列はすべての点を避ける必要があります。つまり、占有列セットの補数には、同じサイズの連続したブロックが含まれている必要があります。$k$。 ソートギャップ条件は、この要件を正確に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(k, p, n):
    import bisect

    window = sorted(p[:k])

    def ok(arr):
        best = 0
        prev = 0
        for x in arr:
            best = max(best, x - prev - 1)
            prev = x
        best = max(best, n + 1 - prev - 1)
        return best >= k

    if ok(window):
        return True

    for i in range(k, n):
        out_val = p[i - k]
        in_val = p[i]

        window.pop(bisect.bisect_left(window, out_val))
        bisect.insort(window, in_val)

        if ok(window):
            return True

    return False

def solve():
    n = int(input().strip())
    p = list(map(int, input().split()))

    lo, hi = 1, n
    ans = 1

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, p, n):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    weakness = ans
    best_possible = 1  # for permutation grid, minimum achievable weakness is 1

    print(weakness)
    print("YES" if weakness > best_possible else "NO")

if __name__ == "__main__":
    solve()
```コアの実装では、答えに対する二分探索と、各候補サイズの実現可能性チェックが使用されます。 チェック内では、行上のスライディング ウィンドウが列位置の並べ替えられたリストを維持します。 ヘルパー関数は、並べ替えられたリストをスキャンし、グリッドの端の境界ギャップを含む連続する差分を比較することによって、列内の最大の空のギャップを計算します。 

の使用`bisect.insort`そして`bisect_left`挿入と削除が平均して対数的であることを保証し、ソリューション全体を時間制限内に保ちます。$n = 5 \cdot 10^4$。 

よくある落とし穴は、柱の境界ギャップを忘れることです。$1$そして$n$。 これらは仮想センチネルを処理することで処理されます$0$そして$n+1$これにより、端の空きスペースが正しくカウントされます。

 ## 特殊なケース

 次のような最小限のグリッド$n = 1$セルが 1 つしか含まれていないため、可能な正方形のサイズは次のとおりです。$1$。 スライディング ウィンドウは単一の要素に縮退し、最大ギャップの計算には依然として境界処理が含まれているため、アルゴリズムはこれを正しく処理し、次の有効な結果を生成します。$1$。 

順列が厳密に増加している場合、すべての点は主対角線上にあります。 この場合でも、最大の空きマスは存在しません。$n$, なぜなら、大きな正方形は必然的に対角線と交差するからです。 すべてのウィンドウが大きなギャップのない高密度の列セットを生成するため、アルゴリズムはこれを捉えます。 

極端な値の間を交互に繰り返す順列の場合、次のようになります。$p = [1, n, 2, n-1, ...]$、列は大きな内部ギャップを作成しますが、それは特定の行ウィンドウ内に限られます。 スライディング ウィンドウ メカニズムにより、これらの構成が引き続きローカルでテストされることが保証され、最大ギャップの計算により、これらのウィンドウ内の最適な空き領域が正確に特定されます。
