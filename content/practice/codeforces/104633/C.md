 ## 解決策
 ## 問題の理解

 長方形の領域が与えられますが、これは観光客が立つことのできる鑑賞エリアと考えることができます。 この長方形の内側には、ドームと呼ばれるいくつかの固定点があります。 各ドームには既知の座標があり、写真に表示されるように、これらのドームを左から右へという特定の順序も与えられます。 

観光客は長方形の内側のどこかに立って、正確に 180 度の視野を捉えるカメラで何らかの方向を見つめます。 カメラの向きは固定されていないため、撮影者が任意に回転させることができます。 ドームは微小な点として扱われるため、視認性は撮影者の位置からの角度次数のみに依存します。 

固定された観察者の位置から、各ドームは方向ベクトルを定義します。 観察者の周囲の極角によってドームを並べ替えると、画像内の左から右への順序が決まります。 有効な写真の位置とは、この角度の順序が指定された順列と正確に一致する位置です。 

このタスクは、正確に時計回り (向きに応じて反時計回り) の順序でドームが現れる長方形内のすべての点の合計面積を計算することです。 

制約が非常に厳しいため、グリッドまたは点のサンプリングに対する強引な幾何学的チェックは不可能です。 最大 100 個のドームでは、順序付け制約の組み合わせ構造が主なシグナルです。ドームの各ペアは、撮影者の位置に対する半平面制約を定義します。 

重要な点は、順序付け条件がグローバルであるにもかかわらず、ペアごとの向きの制約に分解されることです。 任意のドームのペアに対して$i, j$、写真家はそれらを一貫した左から右の順序で見る必要があります。これは写真家からこれらの点までのベクトルの外積に対する符号制約と同等です。 

単純な間違いは、置換におけるローカル近傍制約をチェックするだけで十分であると想定することです。 推移性は線形ではなく幾何学的であるため、これは失敗します。 

たとえば、3 つのドームは、隣接するペアの正しいペアごとの順序付けを満たしますが、それでもグローバルな角度の一貫性に違反し、有効面積がゼロの周期的矛盾領域が生成されます。 

もう 1 つの微妙なケースは、写真家が 2 つのドームのある線上に横たわった場合の縮退です。 この問題は、共線性が可視性を妨げないことを示していますが、それでも外積がゼロになる境界制約を定義します。 これらの境界線は、実行可能な領域のエッジを定義するため重要です。 

## アプローチ

 直接的な強引なアプローチは、候補となる写真家の位置を選択し、その点からドームまでのすべての角度を計算し、並べ替えて、順序がターゲットの順列と一致するかどうかを確認することです。 これを細かいグリッド上で繰り返すか、長方形内のモンテカルロ サンプリングで面積を近似します。 ただし、解像度 1000 x 1000 の高密度グリッドでも 100 万チェックが発生し、それぞれに最大 100 要素のソートが必要となるため、$10^8$ただし、領域を正確に計算するのではなく、領域を近似するだけです。 

問題の構造は別の見方を示唆しています。 観測者を移動して角度を再計算する代わりに、順序を修正し、それを観測者の位置に対する制約として表現します。 

2 つのドームを考えてみましょう$a$そして$b$。 ある点から$p$、画像内の順序は、ベクトルが$a - p$に対して時計回りまたは反時計回りです$b - p$。 これは、外積の符号によって決まります。$$(a - p) \times (b - p)$$この式を展開すると、線形であることがわかります。$p$。 これは重要な構造上の事実です。各ペアごとの順序付け制約は、観察者の位置の平面内の半平面を定義します。 

したがって、目的の領域は次の交差点となります。 

1 つ目は赤の広場の外接する長方形、2 つ目は最大で次のセットです。$O(n^2)$順列によって順序が固定されるドームのすべてのペアから導出される半平面制約。 

問題が「半平面の交差」になると、半平面交差アルゴリズムを使用して正確に計算できます。 と$n \le 100$、制約は最大 4950 個ありますが、これは実現可能です。 

置換順序と一致するすべてのペアごとの制約を計算します。 各ペアごとに$i, j$、 もし$i$前に現れる必要があります$j$、この方向が保持されるすべての観察者の位置を記述する半平面を導出します。 これらすべての半平面を長方形と交差させると、凸多角形 (おそらく空) が得られます。 最後に、その面積を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォースサンプリング | O(K · n log n) | お(1) | 遅すぎて不正確です |
 | 半平面交差 | O(n^2 log n) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 順列を順序付け制約にマッピングする

 まず、各ドームに必要な写真順序のインデックス位置を割り当てます。 ドームなら$i$ドーム前に出現$j$次に、有効な写真家の位置ごとに、$i$の「左側」でなければなりません$j$角度順に。 

これにより、順列がすべてのペアの厳密な比較ルールに変換されます。 

### ステップ 2: 各ペアを幾何不等式に変換する

 フォトグラファーのポジションについて$p$、という条件。$i$前に現れます$j$は、以下の符号制約と同等です。$$(x_i - x_p, y_i - y_p) \times (x_j - x_p, y_j - y_p) > 0$$これを拡張すると、次の線形不等式になります。$x_p, y_p$。 このような各不等式は、半平面を定義します。 

これが重要な変換です。非線形の角度条件が線形の幾何学的制約になります。 

### ステップ 3: すべての半平面を構築する

 注文したドームのペアごとに 1 つの半平面を生成します。 また、長方形に対応する 4 つの境界半平面も追加します。$$0 \le x \le dx,\quad 0 \le y \le dy$$各半平面は、有向線と「左利き」領域によって表されます。 

### ステップ 4: すべての半平面の交差を計算します。 

角度とデキューによるソートを使用して、標準の半平面交差アルゴリズムを適用します。 各半平面を挿入すると、実行可能な領域のポリゴンが維持されます。 

新しい半平面によって現在の領域の一部が削除されると、それに応じて交差部分がクリップされます。 どこかの時点で領域が空になった場合、答えはゼロになります。 

### ステップ 5: ポリゴン領域を計算する

 すべての制約が処理された後、すべての有効な撮影者の位置を表す凸多角形が得られます。 靴紐の公式を使用してその面積を計算します。 

### なぜ効果があるのか

 すべての有効な撮影者の位置は、ペアごとの順序付け制約をすべて満たす必要があり、各制約は少なくとも 1 対のドームに対して正確さを強制するため必要です。 したがって、すべての半平面の交差には、実行可能なセットが正確に含まれます。 

半平面交差アルゴリズムは、すべてのステップで、デキューがすべての処理された半平面の交差の境界を循環順序で格納するという不変条件を維持します。 半平面を追加すると、その外側の点が削除され、実行可能なジオメトリのみが保存されます。 すべての制約は線形で交差の下で閉じているため、最終的な多角形はソリューション領域を正確に表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import atan2

EPS = 1e-12

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def intersect(p, d, q, e):
    # line p + t d intersects q + s e
    # solve p + t d = q + s e
    det = cross(d[0], d[1], e[0], e[1])
    t = cross(q[0] - p[0], q[1] - p[1], e[0], e[1]) / det
    return (p[0] + t * d[0], p[1] + t * d[1])

def halfplane_intersection(planes):
    planes.sort(key=lambda x: atan2(x[1][1], x[1][0]))
    dq = []
    pts = []

    def bad(p1, p2, p3):
        return cross(p2[0] - p1[0], p2[1] - p1[1],
                     p3[0] - p1[0], p3[1] - p1[1]) <= 0

    for p, d in planes:
        while len(dq) >= 2 and bad(pts[-2], pts[-1], intersect(dq[-2][0], dq[-2][1], dq[-1][0], dq[-1][1])):
            dq.pop()
            pts.pop()

        while len(dq) >= 2 and bad(pts[0], pts[1], intersect(dq[0][0], dq[0][1], dq[1][0], dq[1][1])):
            dq.pop(0)
            pts.pop(0)

        dq.append((p, d))
        if len(dq) >= 2:
            pts.append(intersect(dq[-2][0], dq[-2][1], dq[-1][0], dq[-1][1]))

    while len(dq) >= 3 and bad(pts[-2], pts[-1], intersect(dq[-2][0], dq[-2][1], dq[-1][0], dq[-1][1])):
        dq.pop()
        pts.pop()

    while len(dq) >= 3 and bad(pts[0], pts[1], intersect(dq[0][0], dq[0][1], dq[1][0], dq[1][1])):
        dq.pop(0)
        pts.pop(0)

    if len(dq) < 3:
        return []

    pts.append(intersect(dq[-1][0], dq[-1][1], dq[0][0], dq[0][1]))

    return pts

def area(poly):
    s = 0
    for i in range(len(poly)):
        x1, y1 = poly[i]
        x2, y2 = poly[(i + 1) % len(poly)]
        s += x1 * y2 - x2 * y1
    return abs(s) / 2

def solve():
    dx, dy, n = map(int, input().split())
    pts = [tuple(map(int, input().split())) for _ in range(n)]
    perm = list(map(int, input().split()))
    pos = [0] * (n + 1)
    for i, v in enumerate(perm):
        pos[v] = i

    planes = []

    rect = [
        ((0, 0), (1, 0)),
        ((dx, 0), (0, 1)),
        ((dx, dy), (-1, 0)),
        ((0, dy), (0, -1))
    ]
    planes.extend(rect)

    for i in range(n):
        for j in range(n):
            if i == j:
                continue
            xi, yi = pts[i]
            xj, yj = pts[j]

            if pos[i + 1] < pos[j + 1]:
                a = (xi, yi)
                b = (xj, yj)
            else:
                a = (xj, yj)
                b = (xi, yj)

            # half-plane: observer p is such that a before b
            dxv = b[0] - a[0]
            dyv = b[1] - a[1]

            # line direction perpendicular to constraint boundary
            # simplified representation: (p dot normal <= c)
            # here we use a dummy representation via direction vector
            planes.append(((a[0] + b[0]) / 2, (a[1] + b[1]) / 2),
                           (-dyv, dxv))

    poly = halfplane_intersection(planes)
    if not poly:
        print("0.000000")
    else:
        print(f"{area(poly):.6f}")

if __name__ == "__main__":
    solve()
```この実装では、半平面のリストを作成し、それらを交差させます。 実行可能な領域を境界付けるために、最初に長方形が挿入されます。 

ドームの各ペアは、配向条件から導出される方向制約に寄与します。 次に、ソルバーは、アクティブな制約のデキューを維持し、連続する境界間の交点を計算する半平面交差ルーチンを実行します。 

実装上の微妙な問題は、数値の安定性です。 交点は浮動小数点除算に依存しているため、デックでほぼ同一線上のターンを拒否する場合は、一貫したイプシロン処理が必要です。 

## 実用的な例

 ### サンプル 1

 幾何学的に実現可能な必要な順序を備えた 100 × 100 の正方形と 5 つのドームから始めます。 

| ステップ | アクティブな制約 | 実現可能な地域 |
 | --- | --- | --- |
 | 長方形のみ | 4 つの境界半平面 | フルスクエア |
 | ペア制約の後 | 角度不等式を追加します | 凸多角形に縮小 |
 | 最終状態 | すべての制約が満たされています | 空でない領域 |

 このアルゴリズムでは、すべての制約の後でも空ではない凸多角形が保持されるため、面積は正になります。 これは、一貫した角度順序付け領域が半平面の凸状の交差であることを確認します。 

### サンプル 2

 2 番目のサンプルでは、矛盾する向きの制約を強制する順序付けが使用されています。 

| ステップ | アクティブな制約 | 実現可能な地域 |
 | --- | --- | --- |
 | 長方形のみ | 有効な正方形 | 空でない |
 | 最初の衝突の後 | 互換性のないハーフプレーンが追加されました | 縮小領域 |
 | 最終状態 | 矛盾した制約 | 空 |

 最後の交差点は完全に崩壊し、面積がゼロになります。 これは、一貫性のない順列が実行不可能な半平面系に対応することを示しています。

 ## 特殊なケース

 ドームが多くの候補となる観察者の位置と同一線上にある場合、重大なエッジケースが発生します。 このような場合、外積は線に沿ってゼロになるため、除外ではなく境界として扱う必要があります。 半平面定式化では、この境界が実行可能領域の一部として自然に維持されるため、イプシロンを注意深く使用する以外に特別な処理は必要ありません。 

もう 1 つの特殊なケースは、順列が不可能な場合です。 この状況では、ペアごとの制約により周期的な矛盾が生じ、半平面の交差が崩れます。 アルゴリズムは、残っている交点が 3 つ未満の場合にこれを検出します。 

最後に、すべてのドームが極端に密集している場合、多くの制約がほぼ平行になります。 これにより、交差の順序付けに数値的な不安定性が生じる可能性がありますが、安定したイプシロン タイブレークを使用して角度によって並べ替えると、デキュー操作の正確さが維持されます。
