 ## 解決策
 ## 問題の理解

 球上に 2 組の点が与えられ、各点は緯度と経度で表されます。 緯度は惑星の形状によって固定されるため、両方のマップで同一のままです。 2 つのデータセット間の唯一の自由は、すべての点の経度を均一にシフトする、惑星自身の軸を中心とした惑星の回転によってもたらされます。 

タスクは、最初のマップ内のすべての点をその角度だけシフトした後、結果として得られる座標セットが 2 番目のマップと正確に一致するような、経度方向に沿った単一の回転角度が存在するかどうかを判断することです。 

したがって、構造は純粋に幾何学的なものです。つまり、緯度が不変で経度が 360 度を法として定義される球上の点の 2 つのマルチセットです。そして、経度座標に一様な円シフトを適用することによって 2 番目のセットが取得できるかどうかをテストしたいと考えています。 

n が 400,000 までの制約により、すべての点ペア間の二次比較が即座に除外されます。 2 回ソートすることさえ許容されますが、両方のセットにわたって単純にポイントをペアにするアプローチは失敗します。 おそらくハッシュまたは正規表現に依存する、線形または線形演算時間に近いものが必要です。 

微妙な問題は浮動小数点の精度です。 座標は小数点以下 4 桁までで指定されるため、慎重に正規化しない限り、直接の浮動小数点比較は危険です。 もう 1 つの問題は、経度が -180 と 180 で折り返すため、シフトは 360 を法として処理する必要があることです。最後に、緯度グループ内の重複が問題になります。複数のポイントが緯度を共有しても経度が異なる可能性があるため、マッチングでは各緯度バンド内の多重度を維持する必要があります。 

素朴なアプローチでは、最初のセットの 1 つの点を 2 番目のセットの 1 点と位置合わせし、候補の回転を導出し、すべての点を検証しようとします。 これは概念的には正しいですが、すべてのペアリングを試すと時間がかかりすぎます。 重要なのは、ローテーションの候補を構造から導出された小さなセットに減らすことです。 

## アプローチ

 この強引なアイデアは単純な観察から始まります。最初のマップのどの点が 2 番目のマップのどの点に対応するかを推測すると、それらの経度の差として必要な経度シフトを計算できます。 次に、このシフトを最初のマップ内のすべてのポイントに適用し、変換されたセットが 2 番目のマップと等しいかどうかを確認できます。 

これは正しいですが、ペアリングの数は n 乗になります。 各チェックのコストは n であるため、単純に実行すると合計は O(n^3) になり、チェックを最適化しようとすると少なくとも O(n^2) になります。 n が 400,000 までの場合、O(n log n) でさえ現実的な上限であるため、これは完全に実行不可能です。 

重要な洞察は、緯度が回転しても変化しないということです。 つまり、各緯度は経度に沿った点の独立した循環順序を定義します。 2 つの地図が同じ惑星に対応する場合、固定緯度ごとに、複数セットの経度が同じ地球規模のシフトに一致する必要があります。 さらに重要なのは、同じシフトがすべての緯度で同時に機能する必要があることです。 

これにより、問題は、単一のグローバル回転値によってすべて位置合わせされた、各緯度での円形マルチセットの一致に変わります。 すべての回転をテストする代わりに、回転下でも不変である各マップの正規表現を計算できます。 標準的な方法は、点を緯度で並べ替えてから、各緯度グループ内で経度の循環シーケンスを考慮し、基準点を減算して正規化するなど、回転不変の方法でエンコードすることです。 

浮動小数点の不安定性を回避するために、座標を整数にスケールします。 精度は 1e-4 までなので、10000 を掛けるとすべての値が安全な整数になります。

最後に、各緯度グループをソートされた循環シーケンスに縮小し、開始点に依存しないハッシュを計算します。 次に、地図全体がこれらの緯度ごとの正規ハッシュのマルチセットとして表されます。 両方のマップが同一のマルチセットを生成する場合、答えは同じです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) 以上 | O(n) | 遅すぎる |
 | グループ + 正規ハッシュ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 緯度と経度をスケーリングした後、各点を整数のペアとして扱います。 

緯度ごとにポイントをグループ化します。 各緯度グループ内ですべての経度を収集し、並べ替えます。 これにより、360 度を法とする直線上の循環シーケンスが得られます。 

各グループに対して、回転不変署名を構築します。 これは、最後から最初に戻るラップアラウンドを含め、ソートされた連続する経度の差を計算することによって行われます。 これにより、どこから円を読み始めるかに関係なく、循環構造が生成されます。 次に、この巡回差分シーケンスをハッシュにエンコードします。 

これを緯度グループごとに繰り返し、マップごとにグループ署名のマルチセットを生成します。 最後に、2 つのマルチセットを比較します。 

1. 最初のマップと 2 番目のマップのすべてのポイントを読み取り、座標を整数にスケールします。 
2. 辞書を使用して、各マップのポイントを緯度ごとにグループ化します。 
3. 緯度グループごとに、その経度を並べ替えます。 
4. ソートされた経度リストごとに、ラップアラウンドを含む循環差を計算します。 
5. 結果として得られる差分シーケンスを正規値にハッシュします。 
6. すべてのハッシュをマップのマルチセット表現に収集します。 
7. 2 つのマルチセットが等しいかどうかを比較し、結果を出力します。

 絶対経度の代わりに差を使用する理由は、グローバル回転によりすべての経度が同じ定数だけシフトしますが、円上の連続する点間の差は変化しないためです。 

### なぜ効果があるのか

 各緯度は点の独立した円形配置を形成します。 惑星の回転は、そのようなすべての配置における均一な周期的シフトに対応します。 循環シフトは、循環シーケンス内の隣接する差分のマルチセットを変更しません。 したがって、各緯度グループは回転の下で不変表現に還元されます。 すべてのグループが同じ回転を共有するため、マップが一致するためには、すべての緯度にわたってこれらの不変条件が等しいことが必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def normalize_group(lons):
    lons.sort()
    m = len(lons)
    if m == 0:
        return 0
    if m == 1:
        return 1
    diffs = []
    for i in range(m):
        j = (i + 1) % m
        diff = lons[j] - lons[i]
        if j == 0:
            diff += 3600000  # scaled 360 degrees
        diffs.append(diff)
    diffs.sort()
    h = 1469598103934665603
    for d in diffs:
        h ^= d + 0x9e3779b97f4a7c15
        h *= 1099511628211
        h &= (1 << 64) - 1
    return h

def build_signature(points):
    groups = defaultdict(list)
    for a, b in points:
        la = int(round(a * 10000))
        lo = int(round(b * 10000))
        groups[la].append(lo)

    sig = []
    for la in groups:
        sig.append(normalize_group(groups[la]))
    sig.sort()
    return sig

def solve():
    n = int(input())
    p1 = [tuple(map(float, input().split())) for _ in range(n)]
    p2 = [tuple(map(float, input().split())) for _ in range(n)]

    s1 = build_signature(p1)
    s2 = build_signature(p2)

    print("Same" if s1 == s2 else "Different")

if __name__ == "__main__":
    solve()
```このソリューションでは、浮動比較の問題を回避するために、まず座標を離散化します。 回転によって緯度が混合されないため、各緯度グループは分離されます。 各グループ内で経度をソートすると、円構造が線形表現に縮小されます。 ラップアラウンドの差により、開始点に関係なく循環構造が確実に保持されます。 

ハッシュ関数は、差分シーケンスを固定サイズのフィンガープリントに圧縮するための標準的な乗算ローリング ハッシュです。 グループ ハッシュを並べ替えることにより、緯度帯の順序付けされたリストではなく、複数のセットを比較できるようになります。 

微妙な点の 1 つは、浮動丸めが両方のマップで一貫している必要があることです。 10000 を掛けて丸めることにより、安定した整数表現が保証されます。 

## 実用的な例

 ### 例 1

 最初のマップには緯度ごとにグループ化されたポイントがあり、2 番目のマップは同じ構成ですが、経度が回転されています。 グループ化と正規化の後、両方とも同一の署名を生成します。 

| ステップ | マップ 1 グループ ハッシュ | マップ 2 グループ ハッシュ | 比較 |
 | --- | --- | --- | --- |
 | グループ化後 | [H1、H2] | [H1、H2] | 同じマルチセット |
 | 並べ替え後 | [H1、H2] | [H1、H2] | 等しい |

 これは、地球規模の経度のシフトが巡回差分ハッシュに影響を与えないことを示しています。 

### 例 2

 2 番目のサンプルでは、少なくとも 1 つの緯度内の経度の分布が構造的に異なります。これは、循環シフトによってセットを整列させることができないことを意味します。 

| ステップ | マップ 1 グループ ハッシュ | マップ 2 グループ ハッシュ | 比較 |
 | --- | --- | --- | --- |
 | グループ化後 | [H1、H2] | [H1、H3] | 不一致 |

 これにより、合計カウントが一致しても、内部の環状構造の違いが検出されることが確認できます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ポイントが 1 つだけある緯度グループです。 この場合、意味のある循環構造は存在しないため、ハッシュはどの単一点グループでも一定でなければなりません。 このアルゴリズムは、m = 1 の固定値を返し、回転により誤った区別が生じないようにします。 

もう 1 つのエッジ ケースは、経度が -180/180 の境界付近にある場合です。 スケーリングされた整数で作業し、差を法 3600000 で処理するため、最後の差の計算にはラップアラウンドが明示的に含まれます。 たとえば、-179.9999 と 179.9999 の点では、大きな直線ギャップではなく小さな円形ギャップが生成され、正確さが維持されます。 

最後の微妙なケースは、複数のポイントが同じ緯度を共有しているが、経度が大きく離れている場合です。 ソートにより一貫した順序付けが保証され、循環差分によりローテーション時の不変性が保証されます。
