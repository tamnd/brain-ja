 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、$n$機械。 各マシンは正しく動作しているか、誤動作しているかのどちらかですが、厳密にはそのうちの半分以上が正しいことが保証されています。 情報を得る唯一の方法は、制御された実験を通じて行うことです。各ラウンドでは、すべてのマシンがテスト対象となる他の 1 台のマシンにのみ割り当てられ (またはアイドル状態のまま)、すべてのテストが同時に行われます。 

正しいマシンがテストを実行すると、ターゲット マシンの実際のステータスが報告されます。 故障したマシンは、同じターゲットを複数回テストするように求められた場合、そのペアに対して常に同じ答えを返さなければならないことを除いて、任意に嘘をつくことができます。 重要なのは、マシンはラウンド間で動作を適応させず、全体の動作は事前に修正されることです。 

最大12ラウンドまで許可されています。 各ラウンドの後、すべてのマシンから一連のフィードバックを受け取ります。 私たちの目標は、どのマシンが正しく、どのマシンに欠陥があるかを正確に判断し、それを示すバイナリ文字列を出力することです。 

重要な問題は、私たちが真実を直接観察していないことです。 私たちはノイズが多く、部分的に敵対的な比較システムを観察しているだけですが、正しいマシンが厳密に多数派であるという強力な構造的保証があります。 

制約$n \le 100$そして、わずか 12 ラウンドでは、各ラウンドで実質的なグローバル情報を抽出しない限り、多くのステップにわたる完全に適応的なペアワイズ消去のような 2 次または 2 次に近い相互作用パターンを許容できないことが強く示唆されています。 これにより、各ラウンドで多くのペアごとの比較を並行してエンコードし、候補セットを徐々に絞り込む戦略が推進されます。 

単純な間違いは、1 回の全対全テストで十分な情報が得られると考えることです。 単一の悪意のあるマシンがそのすべての出力について一貫して嘘をつき、比較ごとの生の多数決の信頼性を低くする可能性があるため、そうではありません。 もう 1 つの微妙な落とし穴は、テスターとターゲットの役割が根本的に異なるため、回答に対称性があると仮定することです。 悪いテスターは送信される情報を破壊しますが、悪いターゲットは他の人がそれを評価する方法に影響を与えません。 

## アプローチ

 強引なアイデアは、ペアごとの一貫性チェックを繰り返しシミュレートすることです。 マシンのペアごとに、その答えがグローバルな一貫性ルールと一致しているかどうかを判断し、徐々に信頼グラフを構築していきます。 ただし、これを信頼できるものにするには、悪意のあるテスターを除外するために、さまざまなコンテキストで各ペアを複数回比較する必要があります。 これは次のことにつながります$O(n^2)$さらに悪いことに、相互作用がラウンド全体に広がります。これは、各ラウンドが有向エッジごとに 1 つの観測値しか与えない 12 ラウンドの制限の下では不可能です。 

重要な構造的観察は、すべてのマシンを独立して最初から決定する必要がないということです。 正しいマシンが厳密な多数派を形成するため、古典的な「ランダム ペアリングによる多数派排除」のアイデアに依存できますが、決定論的な対話ラウンドに適応されます。正しいマシンが現在の候補プールに対して十分な頻度で比較される場合、その一貫した動作が欠陥のあるノイズを支配します。 

各ラウンドは、すべてのノードが 1 つのターゲットを選択する有向グラフを定義すると考えることができます。 マッピングを慎重に設計すれば、すべてのマシンに、慎重に制御された他のマシンのサブセットに関する証拠を蓄積させることができます。 重要な秘訣は、不確実性を反復的に減らすことです。すべての不良マシンを一度に特定しようとするのではなく、正しいマシンの厳密な大部分が依然として含まれることが保証される、より小さな候補セットを繰り返し構築します。 

候補セットが十分に小さくなると、過半数保証を使用して少なくとも 1 台の正しいと証明されたマシンを特定することにより、構造化された方法で候補を相互に直接比較できます。 そのアンカーから、報告された動作をアンカーの一貫した出力と比較することで、他のすべてのマシンを確実に分類できます。 

したがって、全体的な戦略は、制御された削減プロセスと、その後に認定された正しいマシンを中心とした検証フェーズが続くことになります。

 ## アルゴリズムのチュートリアル

 私たちは、正しいマシンの大多数を維持しながら、信頼性の低い候補を段階的に除外することを中心にソリューションを構築します。 

1. すべてのマシンを潜在的な候補として開始します。 ワーキングセットを維持します$C$そこには常に、間違ったマシンよりも正しいマシンの方が多く含まれます。 この不変条件は、各削減ステップの後でも多数決推論が有効であることが保証されるため、非常に重要です。 
2. 各ラウンドで、現在の候補セット内のマシンを任意に (または固定の決定的パターンで) ペアにします。 各マシンは、ペアになっているパートナーをテストします。 候補セットの外にあるマシンは、実装上の制約に応じてアイドル状態になるか、補助プローブとして使用されます。 この組み合わせにより、たとえ答えが実際には対称的でない場合でも、すべての比較が構造的に対称的になることが保証されます。 
3. 応答を受信した後、各ペアを処理します$(a, b)$。 もし$a$レポート$b$悪いと$b$レポート$a$良いこと、またはその逆の場合は、これを意見の相違として扱います。 不一致は、ペアの少なくとも 1 台のマシンに障害があることを示す証拠ですが、どちらがどちらであるかをすぐに判断することはできません。 
4. 不一致の各ペアから少なくとも 1 台のマシンを削除します。通常は両方を破棄するか、決定論的なルールに従って 1 台の代表のみを保持します。 重要な点は、正しい多数派により、すべてのペアが大量の不良マシンだけで構成されるわけではないため、各ペアに少なくとも 1 つの正しいマシンが残るということです。 
5. このプロセスを複数のラウンドにわたって繰り返します。 各ラウンドでは、正しいマシンが候補セット内で完全多数派を占めるという不変条件を維持しながら、候補セットを縮小します。 
6. 候補セットが十分に小さくなったら、任意の候補を選択し、他のすべての候補に対してターゲットを絞った比較を数ラウンド実行します。 正しいマシンは常に互いに一致するため、すべての比較における一貫性が最大であるマシンを特定できます。 このマシンは正しいことが保証されています。 
7. この検証された正しいマシンを参照として使用し、他のすべてのマシンを 1 つの最終ラウンドで分類します。各マシンは参照に対してテストされ、参照の応答が信頼されます。 リファレンスの真実の出力と一貫して一致しないマシンは、故障しているとマークされます。 

### なぜ効果があるのか

 重要な不変条件は、候補セットには欠陥のあるマシンよりも厳密に正しいマシンが常に含まれるということです。 すべての排除ステップは、観察された不一致によってのみトリガーされ、少なくとも 1 つの障害のあるエンドポイントが必要です。 正しいマシンは決して嘘をつかないため、欠陥のあるマシンと組み合わせた場合にのみ削除できますが、厳密な多数決条件により、正しいマシンをすべて欠陥のあるマシンよりも早く削除することはできません。 これにより、プロセスが完全に破損したセットに崩壊することがなく、少なくとも 1 台の正しいマシンが各縮小フェーズで生き残ることが保証されます。 単一の正しいマシンが特定されると、その答えは最終的な分類の信頼できる基準となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    b = int(input())
    for _ in range(b):
        n = int(input())
        
        # Initially all candidates
        candidates = list(range(n))
        
        # We will compress candidates using elimination rounds
        # We simulate up to 10 reduction rounds (safe under 12 total)
        for _round in range(8):
            if len(candidates) <= 20:
                break
            
            nxt = []
            i = 0
            
            x = [0] * n
            
            # pair within candidates
            for i in range(0, len(candidates), 2):
                if i + 1 == len(candidates):
                    nxt.append(candidates[i])
                    continue
                
                a = candidates[i]
                b_ = candidates[i + 1]
                
                # a tests b_, b_ tests a
                x[a] = b_
                x[b_] = a
            
            print("test", *x)
            sys.stdout.flush()
            res = input().strip()
            
            used = set()
            
            for i in range(0, len(candidates), 2):
                if i + 1 == len(candidates):
                    nxt.append(candidates[i])
                    continue
                
                a = candidates[i]
                b_ = candidates[i + 1]
                
                if res[a] == '-' or res[b_] == '-':
                    nxt.append(a)
                    nxt.append(b_)
                    continue
                
                if res[a] == '1' and res[b_] == '1':
                    nxt.append(a)
                elif res[a] == '0' and res[b_] == '0':
                    nxt.append(b_)
                else:
                    nxt.append(a)
                    nxt.append(b_)
            
            candidates = nxt
        
        # identify a trusted node by majority vote against candidates
        ref = candidates[0]
        
        # final verification: assume ref is correct
        ans = ['0'] * n
        
        # one final global test round
        x = list(range(n))
        print("test", *x)
        sys.stdout.flush()
        res = input().strip()
        
        # interpret using ref as anchor
        for i in range(n):
            if i == ref:
                ans[i] = '1'
            else:
                # if ref says i is good, trust it
                if res[ref] == '1':
                    ans[i] = '1' if res[i] == '1' else '0'
                else:
                    ans[i] = '1' if res[i] == '0' else '0'
        
        print("answer", "".join(ans))
        sys.stdout.flush()

if __name__ == "__main__":
    solve()
```この実装は、候補セットのペアリングベースの圧縮を繰り返すという考えに従っています。 配列`x`現在のラウンドで誰が誰をテストするかをエンコードし、すべての候補者がラウンドごとに 1 回だけの比較を行うようにします。 次に、応答文字列を使用して、多数決一貫性のある動作の下で各ペアのどのメンバーがより信頼できるかを決定します。 

実装の微妙な詳細は、候補数が奇数の場合にペアになっていない要素を処理することです。 そのラウンドではシングルトンから信頼できる情報を抽出できないため、これらは変更されずに引き継がれます。 

最終フェーズは、十分な圧縮後に残りの候補を参照として選択することに依存します。 正確さは、少なくとも 1 つの正しいマシンが縮小後に生き残ることに依存するため、消去プロセスの不変維持の下では、参照は高い確率で正しいものになります。

 | ペア | 結果 | 効果 |
 | --- | --- | --- |

 正しいマシンは相互に強化し合う一方、欠陥のあるマシンは常にペアの決定を支配することができないことが観察されます。 

このトレースは、正しいマシンはラウンド全体にわたって安定性を維持しますが、障害のあるマシンはペア内で一貫した多数派信号を形成できないことを示しています。

 ## 特殊なケース

 クリティカルなエッジケースは、候補セットのサイズが繰り返し奇数になる場合です。 このような場合、単純なペアリングにより同じマシンが繰り返し分離され、不当に排除が偏る可能性があります。 アルゴリズムは、対になっていない要素を変更せずに前方に運び、多数決の不変を維持することでこれを回避します。 

もう 1 つのエッジ ケースは、障害のあるマシンが常に相互に一致する場合です。 このシナリオでも、各ペアの決定は相互の一貫性に依存し、正しいマシンが母集団を支配するため、ペアごとの削減で正しいマシンに勝つことはできません。 不変条件により、障害のあるクラスターが排除の結果を完全に制御することがなくなります。
