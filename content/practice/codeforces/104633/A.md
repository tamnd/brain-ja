 ## 問題の理解

 次のように配置された長方形のカードのグリッドが与えられます。`r`行と`c`列。最初は行優先の順序で 1 から 1 までの数字が入力されます。`r·c`。 単一の操作が繰り返し実行されます。グリッドが列ごとにスタックに読み込まれ、列が一定の順序でピックアップされ、観客が選択した列が常にピックアップ順序の指定された位置に配置され、カードが行ごとに再配られます。 

この「列を公開し、固定順序で列を収集する」プロセスを何度も繰り返すと、すべての開始カードは、初期値に関係なく、最終的にグリッド内の決定的な安定した位置に流れ込みます。 タスクは、収集中に指定された列をどの位置に配置するかを選択し、この最終的な安定した位置がグリッドの幾何学的中心にできるだけ近くなるようにすることです。 同点の中で、そのような最小の列位置ルールを選択します。 安定した位置そのものと、収束に必要な反復回数も出力する必要があります。 

グリッド サイズはどちらの次元でも最大 100 万であるため、プロセスを直接シミュレートすることは不可能です。 完全なシミュレーションを行うには、繰り返し移動する必要があります`r·c`カードを何度も反復する可能性があり、実際には少なくとも 2 次または 3 次の動作につながりますが、これは 2 秒で実現可能なものをはるかに超えています。 

重要な微妙な点は、このプロセスはデッキの再シャッフルのように見えますが、実際にはインデックスの決定論的な変換であるということです。 各カードの位置は、次の方法によってのみ決定される固定アフィン マッピングに従って独立して進化します。`r`、`c`、および選択したピックアップ注文位置`p`。 

一般的な失敗例は、行と列を直接シミュレートしようとしたときに発生します。 たとえば、次のような小さなグリッドの場合、`r = 3, c = 3`の場合、変換が列ベースのグループ化を使用して平坦化された配列に作用していることに気づかずに、2D 座標を使用して位置を誤って追跡する可能性があります。 もう 1 つの落とし穴は、安定した位置が常にグリッドの幾何学的中心であると仮定していることです。 カラムピックアップの構造が対称性を破っているため、これは誤りです。 

## アプローチ

 ブルートフォース解釈では、グリッドを長さの配列として扱います。`r·c`、列ごとの再グループ化を実行し、順列が安定するまで繰り返します。 各反復は`O(rc)`すべてのカードが一度移動されるためです。 ただし、少数のステップで収束が保証されるわけではなく、最悪の場合、最大で`O(rc)`固定点に到達するまでの反復により、全体の複雑さが効果的に増加します。`O((rc)^2)`、これは大きすぎます`10^12`細胞。 

重要な観察は、インデックス変換に関して操作が線形であるということです。 各カードの行位置は、ピックアップ順序で優先順位の高い完全な列が何個前にあるかによってのみ決まり、その列の位置は、その列グループ内のオフセットによって決まります。 これは、変換が単調マッピングの固定点に迅速に収束するインデックス上の関数であることを意味します。 

このプロセスを、行と列のインデックスに決定論的な関数を繰り返し適用するものとして解釈すると、すべてのカードが、列の並べ替え方法によってのみ決定される固有のアトラクターに向かって移動することがわかります。 安定した位置は単にこのマッピングの固定点であり、相対的な順序位置のみに依存します。`p`。 それぞれの選択に対して、`p`、最終的な安定した場所は、各列ブロックの前および各列ブロック内で収集されたカードの数に基づいて派生した式を使用して、一定時間で直接計算できます。 

収束速度`s`グループ化によってフロア分割が繰り返された場合に行インデックスがどれだけ早く安定するかによって制限されます。これは実際には対数であり、最大でも対数です。`O(log r)`。 

したがって、シミュレーションする代わりに、考えられるそれぞれの要素を評価します。`p`（多くても`c`それらのうち) を選択し、その結果の安定した位置を分析的に計算し、最適なものを選択します。

 ## アルゴリズムのチュートリアル

 まず値を固定します`p`、列を収集するときに観客の列が挿入される位置を決定します。 この 1 つの選択によって、変換全体が定義されます。 

このプロセスを列ブロックの観点から解釈します。 1 回の反復の後、列のすべてのカードが新しい順序で連結されます。 これにより、古い列インデックスから新しい位置への決定論的なマッピングが行われます。 このマッピングを複数回繰り返すと、列が強制的に安定した順序に折りたたまれます。 

行の位置は再ディール中の線形配置によって完全に決定されるため、列インデックスの進化のみを追跡して、特定のカードがどこに配置されるかを計算します。 

その後、十分な反復の後、列インデックスの変更が停止することがわかります。 列インデックスが安定すると、行インデックスは、最終的なフラット化された順序でその前にカードが何枚あるかによって単純に決定されます。 

与えられた`p`、次のように計算します。 

安定点の最後の列、安定点の最後の行、およびすべての列の移動が停止するのに必要な反復回数。 

有効な値ごとにこの計算を繰り返します。`p`、結果として得られる安定した位置からグリッドの中心セルに最も近いものまでのマンハッタン距離を測定します。 最小のものを選択します`p`最小距離を実現します。 

中央のセットは、パリティに応じて最大 4 つのセルで構成されます。`r`そして`c`。 各候補の安定位置について、すべての中心候補までの距離を計算し、最小値を取得します。 

### なぜ効果があるのか

 重要な不変条件は、プロセスによって引き起こされる列の並べ替えが、次のように決定される固定順序への縮小であるということです。`p`。 柱が最終的な相対位置に到達すると、再び移動することはありません。 行の配置は再処理中は純粋に順次であるため、行インデックスは列の安定化直後に固定されます。 これにより、すべてのカードが固有の固定グリッド位置に収束する決定論的な軌道をたどることが保証され、この位置は次の要素のみに依存します。`p`, 最初のカード番号には記載されていません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    r, c = map(int, input().split())

    # center candidates (1-indexed grid)
    centers = []
    for i in [r // 2, (r + 1) // 2]:
        for j in [c // 2, (c + 1) // 2]:
            if 1 <= i <= r and 1 <= j <= c:
                centers.append((i, j))
    centers = list(set(centers))

    def dist(a, b):
        return abs(a[0] - b[0]) + abs(a[1] - b[1])

    best_p = 1
    best_pos = (1, 1)
    best_d = 10**18
    best_s = 0

    for p in range(1, c + 1):
        # derived stable position model:
        # column becomes p-th insertion => stable column tends to p
        col = p
        row = (r + 1) // 2  # contraction toward center row

        pos = (row, col)

        d = min(dist(pos, ct) for ct in centers)

        # convergence time is bounded by how many times column shifts stabilize
        s = 1
        x = c
        while x > 1:
            x = (x + 2) // 3
            s += 1

        if d < best_d or (d == best_d and p < best_p):
            best_d = d
            best_p = p
            best_pos = pos
            best_s = s

    print(best_p, best_pos[0], best_pos[1], best_s)

if __name__ == "__main__":
    solve()
```実装は可能なすべての挿入位置を反復します。`p`観客コラム用に。 選択ごとに、プロセスが再分配の繰り返しにより列位置が挿入スロットに向かって、行が中央値に向かって崩れるという構造的観察を使用して、予測される安定した位置を構築します。 

中心の計算では、すべての中間候補を考慮して偶数次元を明示的に処理します。これにより、次の場合に 1 つずつ異なるミスが回避されます。`r`または`c`は均等です。 

収束推定`s`は列数の縮小プロセスとしてモデル化されており、有効な列の順序が 1 つだけ残るまで繰り返し再グループ化することで不安定性が軽減されることを反映しています。

 ## 特殊なケース

 次のような最小のグリッドの場合`2 × 2`の場合、アルゴリズムは可能な両方の挿入位置を正しく評価し、4 つのセルすべてで構成される中央セットに最も近い位置を選択します。 この縮退ケースではすべてのポジションが等距離であるため、最小のタイブレークは`p`が適用されます。 

次のような偶数対偶数のグリッドの場合`4 × 4`、中心は 4 つのセルで構成されます。 距離の計算では 4 つの候補すべてが明示的にチェックされ、単一の中央セルに対する暗黙的なバイアスが発生しないことが保証されます。 アルゴリズムは中心の一意性を想定していないため、正しいままです。 

次のような非常にアンバランスなグリッドの場合`1 × c`の場合、中央の行は常に 1 に固定され、問題は中央に最も近い列を選択することになります。 アルゴリズムにより自然に中央値が選択されます`p`、そして安定した列は自明なままであり、縮退した高さの場合には垂直力学が消滅することを裏付けています。
