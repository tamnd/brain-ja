 ## 解決策
 ## 問題の理解

 小文字で構成される暗号文文字列があります。 文字列内のすべての文字は同じシーザー暗号オフセットによってシフトされていますが、オフセットは不明です。 ターゲットフレーズもいくつか与えられています。 暗号文に正しい逆シフトを適用した後、これらのフレーズはすべて、連続した部分文字列としてどこかに出現する必要があります。 

タスクは、暗号文をすべての指定されたフレーズを含む文字列に変換できるシフト値を見つけることです。 出力はデコードされた文字列であるため、検出されたシフトを実際に適用して結果を出力する必要があります。 

暗号文の長さは最大 1000 で、最大 1000 のフレーズを含めることができます。 各フレーズは短く、長さは最大 30 です。これらの制限は十分に小さいため、考えられるすべてのシーザー シフトを試すことができます。 シーザー暗号には可能なオフセットが 26 個しかないため、主な作業は 26 個のデコードされた文字列の候補をチェックすることです。 文字列の長さが約 1000 および 1000 フレーズの場合、二次形式のチェックでも制限をはるかに下回ります。 任意の置換を試みるなど、はるかに大きな検索空間に依存するアルゴリズムは、問題の構造に適合しません。 

主なエッジ ケースは、シフト方向の処理が間違っていたり、1 つのフレーズのみをチェックすれば十分であると想定したりすることによって発生します。 たとえば、次のことを考えてみましょう。```
abc
1
b
```正しくデコードされた文字列は次のとおりです。```
bcd
```のすべての文字をシフトするため、`abc`1 つ進むとフレーズになります`b`現れる。 常に後方にシフトするソリューションは失敗します。 

別のケースは、答えのシフトがゼロの場合です。```
hello
2
hell
llo
```出力は次のようになります。```
hello
```ゼロ以外の動きが必要であると想定する不用意な実装は、この有効な答えを見逃してしまいます。 

最後の微妙なケースは、繰り返しの出現と重複するフレーズです。```
aaaa
2
aa
aaa
```正しい出力は次のとおりです。```
aaaa
```部分文字列チェックは重複に対して機能する必要があります。 使用されている文字を手動でマークして検索すると、このケースは誤って拒否されます。 

## アプローチ

 直接的なアプローチは、考えられるすべてのシーザー シフトをシミュレートすることです。 可能な変換は 26 個しかないため、それぞれの文字列全体をデコードできます。 デコードされた文字列の候補ごとに、すべてのフレーズをスキャンし、各フレーズが部分文字列であるかどうかを確認します。 すべてのフレーズが表示されれば、有効な答えが見つかったことになります。 

シーザー暗号には有限の可能性があるため、この強引な方法は正しいです。 元のメッセージは、これら 26 のシフトのうちの 1 つに正確に対応する必要があるため、すべてのシフトをテストすることで、確実にそのメッセージに到達することが保証されます。 

非効率性が考えられる唯一の原因は、部分文字列のチェックが繰り返されることです。 最悪の場合、各シフトに 1000 個のフレーズを含む 26 回のシフトを試みますが、各部分文字列の検索には暗号文とほぼ同じ長さがかかる可能性があります。 これにより、約 26 * 1000 * 1000 の演算が行われますが、これは大まかに見積もっても約 2,600 万回の基本文字比較にすぎません。 これは、指定された制限内では完全に許容されます。 

重要な観察は、暗号空間が小さいことです。 シフトを数学的に回復したり、高度な文字列マッチング構造を構築したりする必要はありません。 未知の値は 0 から 25 までの 1 つの数値であるため、列挙するのが自然な解決策です。 この問題は文字列の問題のように見えますが、検索スペースが小さいため、複雑さが大きく左右されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26 * n * m * l) | O(n) | 承認済み |
 | 最適 | O(26 * n * m * l) | O(n) | 承認済み |

 ここ、`n`は暗号文の長さ、`m`はフレーズの数であり、`l`フレーズの最大長です。 

## アルゴリズムのチュートリアル

 1. 暗号文と必要なフレーズをすべて読みます。 考えられるすべてのデコードされた文字列に対して同じリストをテストする必要があるため、フレーズを保存します。 
2. 0 から 25 までの可能なすべてのシーザー シフトを試します。シフトごとに、すべての暗号文文字をその量だけ移動して、復号化された文字列の候補を作成します。 
3. すべての語句を候補文字列と照合します。 1 フレーズでも不足している場合は、このシフトを破棄して続行します。 
4. シフトによってすべてのフレーズが表示されると、デコードされた文字列がすぐに出力されます。 答えが存在することが保証されているため、何らかのシフトは成功します。 

これが機能する理由は、暗号文の復号化可能なバージョンが 26 しかないためです。 正しい候補がその中にあることが保証されているため、最初に見つかった有効な候補で十分です。 

### なぜ効果があるのか

 検索の不変条件は、テストするすべての候補文字列が暗号文の有効なシーザー変換であるということです。 0 から 25 までのすべてのシフト値が検査されるため、デコードされる可能性のある文字列をスキップすることはありません。 

正しいシフトを行うには、問題保証までに必要なすべてのフレーズが出現する必要があります。 チェックフェーズでは、すべてのフレーズが存在する文字列を正確に受け入れるため、正しいシフトがテストに合格して返されます。 まれに、間違ったシフトが合格することもありますが、有効なデコードされた文字列は受け入れられるため、最初に合格した候補を返すだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = int(input())
    phrases = [input().strip() for _ in range(n)]

    length = len(s)

    for shift in range(26):
        decoded = []
        for ch in s:
            decoded.append(chr((ord(ch) - ord('a') + shift) % 26 + ord('a')))
        decoded = ''.join(decoded)

        ok = True
        for p in phrases:
            if p not in decoded:
                ok = False
                break

        if ok:
            print(decoded)
            return

if __name__ == "__main__":
    solve()
```ソリューションでは、26 個の候補すべてに対してフレーズを再利用する必要があるため、まずフレーズを保存します。 それらを再計算または再読み込みすると、不必要な作業が追加されます。 

デコード ループは、各文字を 0 から 25 までの数値に変換し、モジュロ算術でシフトを適用して、変換して戻します。 モジュロ演算はシフトなどのラップアラウンドケースを処理します。`z`に進む`a`。 

フレーズの検証には Python の部分文字列検索が使用されます。 合計の入力サイズが小さいため、これは安全です。 フレーズが欠落しているときに早めに休憩することで、候補が不合格になった後の不必要なチェックが回避されます。 

コードは、ゼロを含むすべてのシフトをチェックします。 暗号文がすでにデコードされたメッセージである可能性があるため、これは重要です。

## テストケース```python
import sys, io

def solve_case(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    s = input().strip()
    n = int(input())
    phrases = [input().strip() for _ in range(n)]

    for shift in range(26):
        decoded = ''.join(
            chr((ord(c) - ord('a') + shift) % 26 + ord('a'))
            for c in s
        )

        if all(p in decoded for p in phrases):
            return decoded + "\n"

    return ""
