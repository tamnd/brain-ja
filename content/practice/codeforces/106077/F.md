 ## 解決策
 ## 問題の理解

 ターゲット文字列が与えられています`t`それはシャニが証明したい主張を表しています。 彼女は一連の記録されたデータ文字列を持っています。 これらの文字列のサブセットを選択できますが、選択した文字列は連結時に元の順序を維持する必要があります。 その後、委員会はあらゆる発生箇所を検索します。`t`最終的に連結されたテキスト内には、重複する出現も含めて含まれており、シャニはその数を最大化したいと考えています。 

入力にはターゲット パターンが含まれ、その後に使用可能な文字列の数と文字列自体が続きます。 出力は、文字列の最適なサブシーケンスを選択した後にターゲット パターンが出現できる最大可能回数です。 

重要な制約がソリューションを形成します。 データ文字列は最大 1000 個あり、それぞれの長さは最大 100 ですが、ターゲットの長さは最大 20 です。`O(n^2)`文字列の数については問題ないかもしれませんが、実際の課題は文字列を連結する効果を処理することです。 長さが 100000 に達する可能性があるため、以前の連結全体を保存することは避ける必要があります。ターゲットの長さが小さいということは、ターゲット パターンに関連する情報のみが重要である可能性があることを示唆しています。 

エッジ ケースは、選択した文字列の境界を越える一致から生じます。 各文字列内の一致を個別にカウントするソリューションは失敗します。 例えば：```
Input
abc
2
a
bc
```正しい出力は次のとおりです。```
1
```両方の文字列を選択すると、`abc`、ここでの一致では、最初の文字列の終わりと 2 番目の文字列の始まりが使用されます。 各文字列を個別にスキャンするだけのメソッドでは、文字列の出現は検出されません。 

もう 1 つの注意が必要なケースは、重複する一致です。 考慮する：```
Input
aa
1
aaa
```正しい出力は次のとおりです。```
2
```一致は位置 1 から 2 および 2 から 3 です。重複を許可せずに一致したテキストを通過する不注意な実装では、1 つだけカウントされます。 

## アプローチ

 簡単なアプローチは、文字列の可能なすべてのサブセットを試し、選択したものを連結し、パターンの出現数をカウントすることです。 すべての有効な最終テキストが 1 つのサブセットに正確に対応するため、これは正しいです。 ただし、文字列は最大 1000 個あるため、`2^1000`可能なサブセット。 候補を生成することさえ不可能です。 

次の観察は、将来は連結全体に依存しないということです。 別の文字列を追加すると、その前の文字だけが新しい文字列の出現に影響を与える可能性があります。`t`は、現在のテキストの接尾辞であり、接頭辞になる可能性があります。`t`。 これはまさに、文字列照合オートマトンによって維持される情報です。 

KMP オートマトンを構築できます。`t`。 状態は、処理されたテキストの最長の接尾辞の長さを表し、接頭辞でもあります。`t`。 文字を追加するたびに、オートマトンは新しい状態に移行し、完全な一致が作成されたかどうかを教えてくれます。 パターンの長さは最大 20 であるため、状態の数はわずかです。 

すべてのデータ文字列について、すべてのオートマトンの状態に対するその影響を事前計算できます。 文字列を含めると、ある程度の数の一致が得られ、別の状態に移行します。 スキップしても状態とスコアは変わりません。 これにより、問題は文字列とオートマトンの状態に関する動的なプログラムに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * 全長) | O(全長) | 遅すぎる |
 | 最適 | O(n * | t | * 文字列の合計長) |

 ## アルゴリズムのチュートリアル

 1. ターゲット文字列の KMP プレフィックス関数を構築します。 プレフィックス関数を使用すると、文字を読み取った後、次のオートマトンの状態をすばやく見つけることができます。 

状態は、ターゲットのどれだけが既にサフィックスとして一致したかを保存するだけです。 今後の発生はこのサフィックス情報のみに依存するため、これで十分です。 
2. データ文字列ごとに遷移テーブルを作成します。 考えられるすべての開始 KMP 状態について、文字列全体の読み取りをシミュレートし、終了状態とシミュレーション中にターゲットが表示された回数を記録します。 

これを一度実行すると、動的プログラミング中に同じ文字列を繰り返しスキャンすることがなくなります。 
3. 動的プログラミング配列を初期化します。`dp[state]`データリストの一部のプレフィックスを処理し、そのオートマトン状態で終了した後に達成可能な一致の最大数を格納します。 

文字列を選択する前、オートマトンは状態 0、スコア 0 にあります。 
4. データ文字列を 1 つずつ処理します。 文字列のスキップは常に許可されているため、文字列ごとに現在の DP 値をコピーします。 次に、以前のすべての状態から文字列を取得し、事前に計算された遷移を適用して、得られた一致を追加してみます。 

このステップでは、各文字列について、無視するか追加するかの 2 つの選択肢を正確に検討します。 
5. 答えは、すべての最終状態の最大値です。 これ以上文字は追加されないため、終了時のオートマトンの状態は重要ではありません。 

不変条件は、最初の処理後の`i`文字列、すべて`dp[state]`は、オートマトンをその状態のままにする文字列からのすべての選択肢の中で可能な最高のスコアを表します。 スキップすると既存の有効な可能性が保持されますが、文字列を取得すると、考えられるすべての以前の状態が考慮され、それを追加することによる正確な効果が適用されます。 可能なアクションはこれら 2 つだけであるため、処理されるすべての文字列に対して不変式が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = input().strip()
    n = int(input())
    s = [input().strip() for _ in range(n)]

    m = len(t)

    pi = [0] * m
    for i in range(1, m):
        j = pi[i - 1]
        while j > 0 and t[i] != t[j]:
            j = pi[j - 1]
        if t[i] == t[j]:
            j += 1
        pi[i] = j

    def advance(state, ch):
        while state > 0 and t[state] != ch:
            state = pi[state - 1]
        if t[state] == ch:
            state += 1
        if state == m:
            return pi[m - 1], 1
        return state, 0

    trans = []
    for word in s:
        cur = []
        for start in range(m):
            state = start
            gain = 0
            for ch in word:
                state, add = advance(state, ch)
                gain += add
            cur.append((state, gain))
        trans.append(cur)

    dp = [-10**9] * m
    dp[0] = 0

    for word_id in range(n):
        ndp = dp[:]
        for state in range(m):
            if dp[state] < 0:
                continue
            nxt, gain = trans[word_id][state]
            if dp[state] + gain > ndp[nxt]:
                ndp[nxt] = dp[state] + gain
        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```プレフィックス関数の構築は通常の KMP 前処理です。 これにより、オートマトンは、すでに処理されたテキストを再スキャンすることなく、不一致から回復できます。 

の`advance`関数は 1 文字を処理します。 完全な一致が完了すると、オートマトンは状態 0 ではなく、パターンの最も長い境界に戻ります。 これにより、重複する一致を正しくカウントできるようになります。 

遷移テーブルには、考えられるすべての状態からのすべての文字列の影響が保存されます。 状態の数は最大 20 であるため、事前計算は DP 内の文字列を繰り返しスキャンするよりも安価です。 

すべての文字列をスキップできるため、DP 更新ではコピーされた配列が使用されます。 文字列を取得すると、古い配列から読み取り、新しい配列に書き込みます。これにより、同じ文字列が誤って複数回再利用されることがなくなります。 どのような接尾辞の状態でも受け入れられるため、最終的な最大値が使用されます。

import sys, io

def solve_case(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = input().strip()
    n = int(input())
    s = [input().strip() for _ in range(n)]

    m = len(t)

    pi = [0] * m
    for i in range(1, m):
        j = pi[i - 1]
        while j > 0 and t[i] != t[j]:
            j = pi[j - 1]
        if t[i] == t[j]:
            j += 1
        pi[i] = j

    def advance(state, ch):
        while state > 0 and t[state] != ch:
            state = pi[state - 1]
        if t[state] == ch:
            state += 1
        if state == m:
            return pi[m - 1], 1
        return state, 0

    trans = []
    for word in s:
        cur = []
        for start in range(m):
            state = start
            gain = 0
            for ch in word:
                state, add = advance(state, ch)
                gain += add
            cur.append((state, gain))
        trans.append(cur)

    dp = [-10**9] * m
    dp[0] = 0

    for i in range(n):
        ndp = dp[:]
        for st in range(m):
            nxt, gain = trans[i][st]
            ndp[nxt] = max(ndp[nxt], dp[st] + gain)
        dp = ndp

    return str(max(dp)) + "\n"
