 ## 解決策
 ## 問題の理解

 私たちに与えられたプローブのコレクションは、それぞれが許容できる温度と風に耐えられるという 2 つの制限によって特徴付けられます。 各プローブには構築コストもかかります。 これに加えて、天王星の複数の着陸地点が与えられ、それぞれが気温と風のレベルで記述されます。 

すべての着陸地点について、両方の条件に同時に耐えられる十分な強度を持つ探査機を選択する必要があります。つまり、温度制限は少なくとも現場の温度であり、風速限界は少なくとも現場の風速です。 このようなすべての有効なプローブの中で、最も安価なプローブが必要です。 両方の制約を満たすプローブがない場合、答えは -1 になります。 

この構造は 2 次元の古典的な支配フィルタリング問題であり、各プローブは機能の 2D 空間内の点であり、各クエリはコストを最小限に抑えながらしきい値点を支配する点を要求します。 

この制約により、最大 100,000 のプローブと 100,000 のクエリが許可され、すべての値は最大 10^9 になります。 クエリごとの単純な 2 次比較は直ちに実行できません。 プローブの並べ替えやクエリごとのスキャンでも、最悪の場合は依然として遅すぎる可能性があります。 クエリ間での繰り返しスキャンを減らす前処理戦略が必要です。 

複数のプローブがさまざまな方法でクエリを支配する場合、微妙なエッジ ケースが発生します。 たとえば、あるプローブは温度耐性が非常に高いが風耐性が弱い場合がありますが、別のプローブはその逆である可能性があります。 1 つの軸だけで並べ替えて最小限のコストを選択する単純なアプローチは失敗する可能性があります。 

次のことを考慮してください。 

入力:

 n = 2

 プローブ:

 (10、1、コスト5)

 (1、10、コスト5)

 クエリ:

 (5, 5)

 どちらのプローブも、1 つの次元では優勢ですが、もう 1 つの次元では失敗します。 正しい出力は -1 です。 温度によって並べ替え、剪定中に風の制約を無視する単純なソリューションでは、誤ってコスト 5 が返される可能性があります。 

もう 1 つの落とし穴は、1 つの属性を単調に増加させると実現可能性が維持されると想定していることです。 より高い温度耐性を備えたプローブは、より優れた耐風性を保証するものではないため、追加の構造なしに問題を 1 つのソートされたスイープに帰着させることはできません。 

## アプローチ

 ブルート フォースのアイデアは簡単です。クエリごとに、すべてのプローブをスキャンし、両方の制約を満たすかどうかを確認します。 存在する場合は、最小コストを更新します。 これは、すべてのプローブの実現可能性を明示的に評価するため正しいですが、クエリごとに n 回のチェックが必要となり、O(nq) 操作が発生します。 n と q の両方が最大 10^5 であるため、最大 10^10 の比較が行われますが、これは 2 秒で処理できる範囲をはるかに超えています。 

重要な観察は、各プローブが 2D 空間内の静的な点であり、各クエリが長方形の支配領域内の点間の最小コストを求めることです。 これは、点の静的なセットに対する 2D 範囲の最小クエリです。 2 番目の座標に関する構造を維持しながら、1 つの座標でプローブをソートし、クエリをスイープで処理することで、問題を変換できます。 

標準的な方法は、温度によってプローブを降順に並べ替え、クエリも温度の降順に処理することです。 温度のしきい値を通過すると、今後のすべてのクエリに対して有効なプローブが「アクティブ化」されます。 探査機がアクティブになると、風力発電能力とコストに貢献します。 次に、風力 ≥ w のすべてのアクティブなプローブの中で、最小コストを見つけることをサポートする必要があります。 

これは、風の値に関する動的なプレフィックス最小値の問題になります。 Wind の値は大きいため (最大 10^9)、プローブとクエリの両方にわたって値を圧縮します。 次に、風インデックスに対する最小コストを格納するセグメント ツリーまたはフェンウィック ツリーを維持します。 各プローブは単一の位置を更新し、各クエリはサフィックスの最小クエリを要求します。 

温度 t でクエリを処理する時点で、x ≥ t のすべてのプローブがすでにアクティブ化されており、不適格なプローブが含まれていないため、スイープによって正確さが保証されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | スイープ + セグメント ツリー | O((n+q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのプローブとクエリを収集し、座標圧縮のためにすべての風の値を抽出します。 これは、最大 10^9 の風域に直接インデックスを付けることができないため、必要です。 
2. プローブを温度の降順に並べ替えます。 これにより、しきい値 t を使用してクエリを処理するときに、十分な温度を持つすべてのプローブがすでに考慮されることが保証されます。 
3. 元のインデックスを維持しながら、クエリを温度の降順に並べ替えます。 これにより、正しい依存関係の順序でクエリに答えることができます。 
4. 圧縮された風座標でセグメント ツリーを初期化し、最初に非常に大きな値を保存します。 このツリーは、風速ごとにアクティブ化されたすべてのプローブの最小コストを表します。 
5. プローブ リスト上にポインタを置き続けます。 クエリごとに、温度が降順で、温度がクエリしきい値以上であるすべてのプローブを繰り返しアクティブにします。 アクティブ化とは、風の位置でセグメント ツリーにコストを挿入し、最小値を更新することを意味します。 
6. すべての有効なプローブがクエリに挿入されたら、セグメント ツリーに対して風 ≥ 必要な風に対するサフィックス クエリを実行します。 これにより、両方の制約を満たすすべてのプローブの最小コストが返されます。 
7. 結果が無限大から変化しない場合は、-1 を出力します。 それ以外の場合は、計算された最小値を出力します。 

セグメント ツリーは風の制約によるフィルタリングの作業を実行しますが、スイープによって温度の制約が常に満たされることが保証されます。 

### なぜ効果があるのか

 温度しきい値 t で処理されるクエリでは、アクティブ セットには、温度要件が満たされるプローブが正確に含まれます。 プローブは決して削除されないため、アクティブ セットは正確性が増すだけであり、無効なプローブが含まれることはなく、後で必要になる有効なプローブが除外されることもありません。 セグメント ツリーでは、十分な風を伴うプローブのみが各クエリで考慮されるように強制されるため、返される最小値は実行可能なセットを正確に上回ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

class SegTree:
    def __init__(self, n):
        self.n = 1
        while self.n < n:
            self.n *= 2
        self.t = [INF] * (2 * self.n)

    def update(self, i, v):
        i += self.n
        if v >= self.t[i]:
            self.t[i] = min(self.t[i], v)
        else:
            self.t[i] = v
        i //= 2
        while i:
            self.t[i] = min(self.t[2*i], self.t[2*i+1])
            i //= 2

    def query(self, l):
        # minimum on [l, n)
        l += self.n
        r = self.n + self.n - 1
        res = INF
        while l <= r:
            if l % 2 == 1:
                res = min(res, self.t[l])
                l += 1
            if r % 2 == 0:
                res = min(res, self.t[r])
                r -= 1
            l //= 2
            r //= 2
        return res

def main():
    n, q = map(int, input().split())
    x = list(map(int, input().split()))
    y = list(map(int, input().split()))
    c = list(map(int, input().split()))

    probes = [(x[i], y[i], c[i]) for i in range(n)]

    qs = []
    ws = []

    for i in range(q):
        t, w = map(int, input().split())
        qs.append((t, w, i))
        ws.append(w)

    coords = sorted(set(ws))
    comp = {v:i for i,v in enumerate(coords)}

    probes.sort(reverse=True)
    qs.sort(reverse=True)

    st = SegTree(len(coords))

    ans = [-1] * q
    j = 0

    for t, w, idx in qs:
        while j < n and probes[j][0] >= t:
            _, yy, cc = probes[j]
            st.update(comp[yy], cc)
            j += 1

        pos = comp[w]
        res = st.query(pos)
        if res < INF:
            ans[idx] = res

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    main()
```このコードは、セグメント ツリーがコンパクトなままになるように、最初に風の値を圧縮します。 活性化が単調になるように、プローブは温度の降順で並べ替えられます。 各アクティベーションにより、風インデックスにプローブ コストが挿入され、セグメント ツリーは風しきい値ごとの最小コストを維持します。 

クエリ関数は、必要な風から上に向かって最小のサフィックスを実行します。 これは「風≧w」という条件に合致します。 メイン ループは、プローブのアクティベーションとクエリ処理を慎重に調整して、プローブが見逃されたり、時期尚早に組み込まれたりしないようにします。 

微妙な点は、複数のプローブが同じ風の座標を共有できることです。 セグメント ツリーは、各位置の最小コストのみを保存することでこれを自然に解決します。最も安価な有効なプローブのみを考慮するため、これで十分です。 

## 実用的な例

 次のサンプル入力を考えてみましょう。 

プローブ:

 (1,3,3)、(2,1,1)、(3,2,2)

 クエリ:

 (1,2)、(1,3)、(3,3)

 風 [1、2、3] を圧縮した後、温度を下げながらクエリを処理します。 

| クエリ | アクティブプローブ | セグメント ツリーの状態 (風:最小コスト) | 答え |
 | --- | --- | --- | --- |
 | (3,3) | (3,2,2) | 風=2で2 | -1 |
 | (1,3) | すべてのプローブ | 風=1 で 1、風=2 で 2、風=3 で 3 | 3 |
 | (1,2) | すべてのプローブ | 同じ | 1 |

 トレースは、サフィックス クエリを介してウィンド フィルタリングが行われる一方で、アクティベーションによって実行可能なセットが徐々に拡張される様子を示しています。 

2 番目の例:

 プローブ:

 (10,1,5)、(1,10,5)

 クエリ: (5,5)

 | クエリ | アクティブプローブ | セグメントツリーの状態 | 答え |
 | --- | --- | --- | --- |
 | (5,5) | なし (最初のみ 10≥5、ただし、wind=1 <5; 2 番目の温度は無効) | 部分的 | -1 |

 これは、1 つの次元だけを満足させるだけでは不十分であることを裏付けています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | 各プローブ更新とセグメント ツリー上の各クエリ範囲の最小値 |
 | スペース | O(n + q) | プローブ、クエリ、セグメント ツリー用のストレージ |

 各演算は圧縮された座標構造上で対数時間のみを必要とするため、合計 2×10^5 までの演算の制約はこの複雑さ内に快適に収まります。

 ## 特殊なケース

 特殊なケースは、複数のプローブが同じ温度を共有しているが、異なる風の値を共有している場合に発生します。 その場合、アクティブ化の順序は重要ではありません。これは、温度が低いか等しいクエリの前にすべてが挿入され、セグメント ツリーが独立して風のフィルタリングを処理するためです。 

もう 1 つのエッジ ケースは、すべてのプローブがクエリに対して無効である場合です。 セグメント ツリーはそのサフィックス範囲に対して無限大のままであり、アルゴリズムは特別な処理を必要とせずに -1 を正しく出力します。
