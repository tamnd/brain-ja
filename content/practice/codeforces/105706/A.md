 ## 解決策
 ## 問題の理解

 整数配列が与えられます$A$。 任意の連続セグメントに対して$A[L..R]$、別の配列を構築するように求められます$B$いくつかの構造上の制約を満たす同じ長さ: のすべての値$B$正の値である必要があり、シーケンスは左から右へ非減少であり、すべての位置で指定する必要があります。$i$元の値をコピーすることは避けなければなりません。つまり、$B_i \neq A_i$。 

そのようなすべての有効な構造の中で、$B$、最後の値を最小化することだけに興味があります。$B_R$。 クエリ セグメントごとに、この最小可能最終値を計算します。 

重要な難点は、$B$インデックスごとに独立した式で固定されるわけではありません。 非減少制約はすべての位置を結合するため、セグメントの早い段階で値を選択すると、後で起こる可能性が制限されます。 それぞれの位置は事実上、「次の値とは異なる値を選択する必要があります」と言っています。$A_i$ただし、同じままにするか、前の選択と比較して増やすかは自由です。」

 制約が意味するのは、$N$そして$Q$テスト ケース全体で大きく、合計サイズは最大約$2 \cdot 10^5$。 これにより、明示的に構築しようとするソリューションが除外されます。$B$各クエリについて、偶数であるため、$O(R-L+1)$最悪の場合、クエリごとの動作は二次関数に低下します。 通常は事前計算や貪欲な状態追跡を使用して、クエリごとに線形または対数に近いものを求められます。 

微妙なエッジ ケースは、禁止値と単調制約の間の相互作用から発生します。 たとえば、次の場合$A = [1, 2, 3]$、素朴な選択$B = [1, 2, 3]$は、単調性を満たしているにもかかわらず、すべての位置が一致するため無効です。 もう 1 つのケースは、配列が強制的に「ジャンプ」する場合です。$A = [1, 1, 1]$、 それから$B = [1, 2, 3]$は有効で、最終値 3 が得られますが、不用意に貪欲なアプローチを行うと、1 を誤って再利用し、違反でスタックする可能性があります。$B_i \neq A_i$最後に。 

## アプローチ

 直接的な総当たりアプローチでは、次のように構築しようとします。$B$クエリごとにスキャンして$L$に$R$。 それぞれのポジションで$i$、最小の整数を選択します$\ge B_{i-1}$それは等しくありません$A_i$。 必要以上に大きな値を選択すると、禁止された値を回避することができず、将来の制約が増えるだけであるため、この貪欲なルールは正しいです。 

この構築には時間がかかります$O(R-L+1)$クエリごとに。 最悪の場合、大きなセグメントに対して多くのクエリがある場合、これは次のようになります。$O(NQ)$、両方が到達できる場合は大きすぎます。$2 \cdot 10^5$。 

重要な観察は、貪欲なプロセスは決定論的であり、現在の値と、によって定義された禁止セットのみに依存するということです。$A_i$。 状態は現在の値にすぎず、完全な履歴ではないため、問題は、実行中の値が禁止点を繰り返し「ジャンプ」するときにどのように変化するかを追跡することになります。 これは、各ステップが単に「現在以上の最小許容値に移動する」だけであるため、遷移を事前計算したり、範囲全体で同一の動作を圧縮したりできる古典的な設定です。 

各位置は、ちょうど 1 つの値をブロックしているとみなすことができます。 それでステップで$i$、現在の値が等しい場合$A_i$、それを 1 つ増やす必要があります。 それ以外の場合はそれを保持できます。 これにより、プロセスが特定の位置で強制的に増分される整数のウォークに変換され、セグメントベースまたは次発生推論で効率的にシミュレートできます。

 ## アルゴリズムのチュートリアル

 このアイデアを実装するクリーンな方法は、各クエリを個別に処理しますが、現在の値が衝突した場合にのみ増加するという事実を利用して貪欲なステップを加速することです。$A_i$。 

1. 初期値から始める$cur = 1$。 すべての値が 1 であるため、1 から開始します。$B$は正である必要があり、できるだけ小さい値から始めると、最終的な答えを最小限に抑えることができます。 
2. 以下のセグメントを反復処理します。$L$に$R$。 各インデックスで$i$、 比較する$cur$と$A_i$。 
3. もし$cur = A_i$、 それから$cur$この位置では禁止されているため、インクリメントします$cur$と等しくなくなるまで$A_i$。 増加するだけなので、単調性を破ることはありません。 
4. ポジションの競合を解決した後$i$、私たちは保管します$cur$の値として$B_i$。 後で減少させないため、シーケンスは自動的に減少しないままになります。 
5. 次の位置に移動します。 クエリの最終的な答えは次の値です。$cur$インデックス処理後$R$。 

重要な実装の詳細は、ステップ 3 では繰り返しのインクリメントが必要であるように見えるかもしれませんが、実際には、各インクリメントでインデックスごとに 1 つの禁止された一致のみを「解決」できるため、全体として各競合を 1 回ずつ請求できることです。 

### なぜ効果があるのか

 アルゴリズムは、各インデックスにおける不変条件を維持します。$i$、$cur$プレフィックスが次のような可能な最小値です。$B_L..B_i$は有効であり、減少しません。 これより小さい値は、単調性に違反するか、等しいかのいずれかになります。$A_i$。 早く増加させると後の制約が難しくなるだけなので、常に可能な限り早い時点で競合を解決することで、最終的な値が全体的に最小になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []
    for _ in range(T):
        n, q = map(int, input().split())
        a = [0] + list(map(int, input().split()))

        for _ in range(q):
            l, r = map(int, input().split())
            cur = 1

            for i in range(l, r + 1):
                if cur == a[i]:
                    cur += 1
                # cur always stays non-decreasing, so no reset needed

            out.append(str(cur))

        print(" ".join(out[-q:]))

if __name__ == "__main__":
    solve()
```このソリューションは、貪欲な構築をシミュレートすることによって各クエリを処理します。 変数`cur`で現在選択されている値を表します$B$。 各インデックスで、次の値と衝突する場合にのみ上方調整します。$A_i$。 これにより、両方の制約が直接強制されます。次の理由により、単調性が保証されます。`cur`が減少することはなく、禁止値をスキップすることによって不等式制約が適用されます。 

微妙な点はインデックス付けです。1 から始まるインデックス付けを使用します。`a`クエリ範囲の調整が簡素化され、セグメントを読み取る際のオフバイワンの間違いを回避します。

 ## 特殊なケース

 現在の値が連続する要素と繰り返し一致する場合、重要なエッジ ケースが発生します。$A$。 たとえば、次の場合$A = [1, 2, 3, 4]$1 から開始すると、すぐに最初の位置で競合し、2 にジャンプして、再び競合し、増加し続けます。 各競合によって正確に 1 つの増分がトリガーされ、値は前方にのみ移動するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジケースは、競合がまったく発生しない場合です。$A = [5, 6, 7]$。 1 から開始すると、どの値とも一致することはありません。そのため、答えは 1 のままです。これにより、アルゴリズムが過剰にインクリメントせず、最小性が真に維持されることが確認されます。 

A third edge case is a long plateau like$A = [2, 2, 2, 2]$。 ここで、値は 1 から始まり、衝突することはありません。これは、禁止された制約が疎であり、単調規則だけでは成長が強制されないことを示しています。
