 ## 解決策
 ## 問題の理解

 2 つの有効なグレゴリオ暦の日付が形式で与えられます。`yyyy:mm:dd`。 タスクは、それらの間の日数を計算することです。 

グレゴリオ暦には、おなじみの閏年のルールがあります。$\text{Leap year} \iff (y\bmod 400=0) \lor (y\bmod 4=0 \land y\bmod 100\neq 0)$2 月は 29 日なので、閏年には 365 日ではなく 366 日が含まれます。 

この問題の興味深い部分は、「間」の意味です。 サンプルを見ると、答えにはエンドポイントが 1 つだけ含まれています。 都合の良い解釈は次のとおりです。 

両方の日付を「固定起点からの日数」に変換すると、答えは次のようになります。$\text{answer}=|f(d_2)-f(d_1)|$どこ`f(date)`その日付までに丸何日が経過したかをカウントします。 

年の範囲は 1900 年から 2038 年までです。その期間の合計日数でも約 50,000 日であるため、多くのアプローチは十分に高速です。 2 つの日付の間を毎日ループするソリューションでも、2 秒以内に快適に通過します。 つまり、問題は高度な最適化に関するものではなく、カレンダーの計算を正しく行うことにあるということです。 

危険なのは閏年と境界の処理です。 小さな間違いが静かに間違った答えを生み出します。 

これらの例を考えてみましょう。 

入力：```
2000:02:28
2000:03:01
```正しい出力:```
2
```2000 年は 400 で割り切れるので、2 月は 29 日になります。 4 で割り切れるかどうかだけをチェックする単純な実装はここでは誤って機能しますが、世紀年を誤って処理する実装は他の場所で失敗する可能性があります。 

次に見てください:

 入力:```
1900:02:28
1900:03:01
```正しい出力:```
1
```1900 年は 100 で割り切れますが、400 では割り切れないため、うるう年ではありません。 これは古典的な罠です。 

もう 1 つの微妙なケースは、日付が等しい場合です。 

入力：```
2012:05:17
2012:05:17
```正しい出力:```
0
```実装が誤って両方のエンドポイントをカウントした場合、代わりに 1 が生成される可能性があります。 

月単位の累積も、off-by-one エラーの一般的な原因です。 

入力：```
2016:03:01
2016:03:02
```正しい出力:```
1
```日付を絶対日数に変換するときは、現在の月自体ではなく、過去のすべての月の長さを加算する必要があります。 

## アプローチ

 最も直接的な解決策は、総当たりシミュレーションです。 前の日付から開始して、2 番目の日付に到達するまで 1 日ずつ繰り返し、遷移が行われた回数を数えます。 

これは、合計の日付範囲が小さいため機能します。 1900 年から 2038 年までは約 50,000 日しかないため、1 日ごとのシミュレーションでも安価です。 

厄介な点は、「翌日」を正しく実装することです。 各月の日数を把握し、うるう年の 2 月を更新し、月と年の境界を適切にロールオーバーする必要があります。 

より洗練されたアプローチでは、シミュレーションが完全に回避されます。 ある日付から別の日付に移動するのではなく、各日付を絶対的な日数に変換します。 

次のように定義するとします。`days(date) = total days before this date`したがって、2 つの日付間の距離は、タイムライン上の絶対的な位置の差にすぎません。 

日付のこの値を計算するには:

 1. 現在の年より前の完全な年からのすべての日を追加します。 
2. 当月より前の完全な月のすべての日を追加します。 
3. 月内の日付オフセットを追加します。 

重要な点は、カレンダーは加算的なものであるということです。 すべての日付は、「固定原点から何日経過したか」として一意に表現できます。 日付が整数になると、問題は減算になります。 

これにより、反復的な日付遷移がすべて削除され、正当性の推論が大幅に簡素化されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(日付間の日数) | お(1) | 承認済み |
 | 最適 | O(年+月) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 両方の入力文字列を整数に解析します。`(year, month, day)`。 

日付は次のように到着します`yyyy:mm:dd`なので、次のように分割します。`:`3 つのコンポーネントを直接与えます。 
2.関数を書く`is_leap(year)`。 

年が 400 で割り切れる場合、または 4 で割り切れるが 100 では割り切れない場合、その年は閏となります。 
3. 関数を書く`to_days(y, m, d)`日付を絶対日数に変換します。 

この関数は、指定された日付までに何日が経過したかを計算します。 
4. 完全な年からの貢献を追加します。 

毎年から`0`に`y - 1`、閏かどうかに応じて 365 または 366 を追加します。 

必要なのは 2038 年までの年だけなので、単純なループでも小さいです。 
5. 今年の完全な月からの拠出金を追加します。 

標準的な月の長さを使用します。`[31,28,31,30,31,30,31,31,30,31,30,31]`閏年の場合は、2 月を 29 に設定します。 

月の前にすべての月を追加`m`。 
6. 月内にオフセットを追加します。 

その日から`1`は、その月内に丸 0 日が経過したことを意味します。`d - 1`。 
7. 2 つの変換された値間の絶対差を計算します。 

その差は正確に日付間の日数です。 

### なぜ効果があるのか

 変換関数は、カレンダーの日付と連続した日のタイムライン上の位置との間に 1 対 1 のマッピングを確立します。 

完全な年ごとに、その正確な日数が反映されます。 完全な月ごとに、現在の年の正確な日数が反映されます。 ついに、`d - 1`現在の日付が始まるまでに、現在の月内で経過した日数をカウントします。 

両方の日付は同じ基準起点を使用して変換されるため、2 つの合計を減算すると、それらを区切る正確な日の推移が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_leap(year):
    return year % 400 == 0 or (year % 4 == 0 and year % 100 != 0)

def to_days(y, m, d):
    total = 0

    for year in range(y):
        total += 366 if is_leap(year) else 365

    month_days = [31, 28, 31, 30, 31, 30,
                  31, 31, 30, 31, 30, 31]

    if is_leap(y):
        month_days[1] = 29

    for month in range(m - 1):
        total += month_days[month]

    total += d - 1

    return total

def solve():
    y1, m1, d1 = map(int, input().strip().split(':'))
    y2, m2, d2 = map(int, input().strip().split(':'))

    ans = abs(to_days(y2, m2, d2) - to_days(y1, m1, d1))

    print(ans)

solve()
```この実装は、アルゴリズムのウォークスルーからの数学的分解を反映しています。`is_leap`グレゴリオ暦のうるう年のルールを直接エンコードします。 順序が重要です。 400 で割り切れる年は、100 で割り切れる場合でも、閏年のままでなければなりません。 

の`to_days`関数は、日付の絶対位置を 3 段階で構築します。 

最初のループは、現在の年よりも完全に数年前に蓄積されます。 最大の年はわずか 2038 年であるため、何年にもわたって反復してもコストはわずかです。 

month 配列は、28 に等しい 2 月から始まります。現在の年がうるう年の場合は、前の月を合計する前に 29 で上書きされます。 これにより、月テーブルの重複が回避されます。 

行:```
total += d - 1
```最も重要な境界の詳細です。 1 日目は、その月に経過した日数が完全にゼロであることを意味します。 使用する`d`代わりに、すべての日付を 1 日ずらし、日付が等しいケースを壊します。 

最後に、絶対的な差を取得すると、日付をどちらの順序でも表示できるようになります。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def is_leap(year):
    return year % 400 == 0 or (year % 4 == 0 and year % 100 != 0)

def to_days(y, m, d):
    total = 0

    for year in range(y):
        total += 366 if is_leap(year) else 365

    month_days = [31, 28, 31, 30, 31, 30,
                  31, 31, 30, 31, 30, 31]

    if is_leap(y):
        month_days[1] = 29

    for month in range(m - 1):
        total += month_days[month]

    total += d - 1

    return total

def solve():
    y1, m1, d1 = map(int, input().strip().split(':'))
    y2, m2, d2 = map(int, input().strip().split(':'))

    print(abs(to_days(y2, m2, d2) - to_days(y1, m1, d1)))

def run(inp: str) -> str:
    global input
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue()

# provided sample
assert run(
    "1900:01:01\n2038:12:31\n"
) == "50768\n", "sample 1"

# equal dates
assert run(
    "2012:05:17\n2012:05:17\n"
) == "0\n", "equal dates"

# non-leap century year
assert run(
    "1900:02:28\n1900:03:01\n"
) == "1\n", "1900 is not leap"

# leap century year
assert run(
    "2000:02:28\n2000:03:01\n"
) == "2\n", "2000 is leap"

# month boundary
assert run(
    "2016:01:31\n2016:02:01\n"
) == "1\n", "month rollover"

print("All tests passed.")
