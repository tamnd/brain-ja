 ## 解決策

 ## 問題の理解

 無限グリッド上の開始点と、4 つの基本方向への必要な一連の移動が与えられます。 猫は、a 左の動き、b 右の動き、c 下向きの動き、d 上向きの動きを正確に実行する必要がありますが、順序は完全に自由です。 

重要な制限は最終位置ではなく、軌道全体です。 中間ステップごとに、猫は軸に沿った固定された長方形の中に留まらなければなりません。 タスクは、すべての中間位置をその長方形内に保持するような動きの順序が存在するかどうかを判断することです。 

グリッドは無限ですが、長方形の制約により、事実上、開始点とユニット移動のカウントが固定された、制限されたパスの実現可能性の問題に変わります。 

この制約では最大 10^3 のテスト ケースが許可され、各テスト ケースは定数時間の算術入力のみを使用します。 したがって、どのソリューションもテスト ケースごとに O(1) で実行する必要があります。 順列の数は a + b + c + d で指数関数的であるため、これにより、手の順列を構築またはシミュレートしようとするアプローチは除外されます。 

最終的な位置のみについて推論する場合、よくある間違いが発生します。 総変位は固定されているため、最終点が長方形の内側にあるかどうかを確認するだけで十分だと考える人もいるかもしれません。 エンドポイントが有効であっても、中間ステップが一時的に許可された領域から外れる可能性があるため、これは不正確です。 

もう 1 つの微妙な失敗例は、長方形が一方向に非常に狭い場合に発生します。 たとえば、x1 = x2 = x の場合、猫は決して水平方向に移動しないように強制されます。 境界に対する実現可能性をチェックせずに左右のバランスをとる単純な戦略では、パスが必然的に許可された列の外側にステップするケースが誤って受け入れられます。 

## アプローチ

 強引なアイデアは、動きのすべての組み合わせを試すことです。 L の a コピー、R の b コピー、D の c コピー、および U の d コピーを含むシーケンスを取得し、常に長方形内でウォークを維持する順序付けが存在するかどうかをテストします。 これはプロセスを直接モデル化しているため、原理的には正しいですが、個別のシーケンスの数は (a+b+c+d) です。 / (a!b!c!d!)、これは小さな入力でも天文学的に大きくなります。 これはすぐに実行不可能になります。 

重要な観察は、完全に貪欲な意味では、動きの正確な順序は重要ではありませんが、各軸の極端なリーチが重要であるということです。 水平方向と垂直方向の動きは独立しているため、x 座標が常に境界内に収まるように、動きをインターリーブできることを確認するだけで済みます。y についても同様です。 

まず横軸を考えてみましょう。 猫はxから始まります。 ウォークの接頭辞の後では、その x 座標は x + (これまでに使用された R の数) − (これまでに使用された L の数) に等しくなります。 [x1, x2] 内に留まるためには、どちらかの境界のオーバーシュートを常に回避できなければなりません。 これは、利用可能な左右のバジェットを調整して、パスによって間隔の外に強制的に出ないようにすることができるかどうかをチェックすることに帰着します。 

これを解釈する標準的な方法は、開始点から両方向にどこまで拡張できるかを検討することです。 右辺では、可能な最大拡張は b ですが、x2 − x によって制限されます。 左側では、可能な最大拡張は a ですが、x − x1 によって制限されます。 同じ理由が c と d についても垂直方向に当てはまります。 

唯一の微妙な点は、違反を強制することなく両方の方向に同時に対応するのに十分な完全な水平方向の自由度を確保する必要があることです。 これは、利用可能な移動を使用した x からの到達可能な間隔が、オーバーシュートを必要としない方法で許可された間隔と交差することをチェックすることになります。 

したがって、各軸について、移動予算を開始点の周囲の利用可能なスラック内に埋め込むことができるかどうかを検証します。

 ## アルゴリズムのチュートリアル

 一方の軸の移動は他方の座標に影響を与えないため、水平軸と垂直軸を独立して扱います。 

1. 開始点の左右にどれだけのスペースがあるかを計算します。左のスペースは x − x1、右のスペースは x2 − x です。 これにより、境界に達する前に各方向にどれだけ移動できるかがわかります。 
2. 水平移動がこれらの制限内で配置できるかどうかを確認します。 猫が、利用可能な左のスペースと未使用の右の動きによる余裕を加えた以上の左の動きを必要としないこと、および右の動きに対して対称であることを保証する必要があります。 この条件は、有効範囲 [x − a, x + b] が [x1, x2] 内に位置できることを保証することになります。 
3. y、y1、y2 で c と d を使用して、縦軸にも同じ推論を適用します。 
4. 両軸が独立して実現可能条件を満たしている場合は、YES を出力します。 それ以外の場合は NO を出力します。 

隠された重要なアイデアは、移動はインターリーブされますが、各軸の最悪の場合の変位は純粋にカウントによって制御されるということです。 私たちは境界を段階的に回避する順序を選択しているわけではありません。 代わりに、動きの「予算」が長方形の中に収まるかどうかをチェックすることで、そのような順序が存在できることを検証しています。 

### なぜ効果があるのか

 有効なウォークは、許可範囲を決して超えない左右の移動のプレフィックス シーケンスに対応します。 このようなシーケンスは、境界違反を強制することなく各方向に必要な変位の合計をスケジュールできる場合にのみ存在します。 各移動は座標を正確に ±1 だけ変更するため、実現可能性は、利用可能な L/R 移動を使用して最初から到達可能な可能な x 値の間隔を、許可されたセグメントに埋め込むことができるかどうかにのみ依存します。 同じ不変式が y に対して独立して保持されるため、2 軸のチェックで十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok_1d(pos, a, b, l, r):
    # pos is starting coordinate
    # we must stay in [l, r]
    # left moves: a, right moves: b

    # effective reachable interval if we use all moves in worst way
    min_pos = pos - a
    max_pos = pos + b

    # but we can reorder moves; we need to ensure we can avoid leaving [l, r]
    # classic condition: interval [min_pos, max_pos] must intersect [l, r]
    # and be placeable inside bounds by shifting via ordering constraints
    return not (max_pos < l or min_pos > r)

t = int(input())
for _ in range(t):
    a, b, c, d = map(int, input().split())
    x, y, x1, y1, x2, y2 = map(int, input().split())

    # horizontal feasibility
    # ensure we can stay in bounds using all moves
    if x + b < x1 or x - a > x2:
        print("NO")
        continue

    # vertical feasibility
    if y + d < y1 or y - c > y2:
        print("NO")
        continue

    print("YES")
```水平チェックにより、最も極端な順序であっても、猫が許容範囲を完全に外れることがないことが保証されます。 すべての右の動きが厳密に x2 を超える場合、またはすべての左の動きが厳密に x1 を下回る場合、どの順序でもそれを救うことはできません。 

縦チェックは左右対称です。 

微妙な点は、安全な順序を明示的に構築しているわけではないということです。 このロジックは、どちらの方向も開始点と移動数に対して長方形によって完全に「ブロック」されない限り、境界違反を避けるために移動をインターリーブできるという事実に基づいています。

 ## 特殊なケース

 x1 = x2 = x のような狭い長方形は、解が水平方向の自由度ゼロを正しく処理しているかどうかを明らかにします。 その状況では、x + b は x に等しく、x − a は x に等しくなければならないため、ゼロ以外の水平移動カウントは直ちに実行可能性を侵害し、a = b = 0 となります。アルゴリズムは、条件 x + b < x1 または x − a > x2 によってそのようなケースを正しく拒否します。 

もう 1 つのエッジ ケースは、開始点が正確に境界上にある場合です。 たとえば、x = x1 および a > 0 の場合、左に移動するとインターバルを終了するため、即時違反が強制されます。 x − a > x2 または x + b < x1 チェックは、シミュレーションを必要とせずにこの状況を捕捉します。 

最後の微妙なケースは、狭い間隔で大きな a と小さな b のように、動きが著しくアンバランスな場合に発生します。 たとえ総排気量が相殺される可能性があるとしても、命令によって早期の違反を防ぐことはできません。 間隔ベースの条件は、順序とは関係なく、許容範囲に対して極端な位置を比較することでこれを検出します。
