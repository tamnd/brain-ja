 ## 解決策
 ## 問題の理解

 数値の配列とサブセグメントに対する多くのクエリが与えられます。 クエリ間隔ごとに$[L, R]$、選択した値に 3 つのインデックスが含まれないように、この間隔内のインデックスのサブシーケンスを昇順で選択する必要があります。長さは少なくとも 3 です。$i < j < k$ここで、値は非減少または非増加のいずれかです。 

同様に、選択したサブシーケンス内に、インデックス順に取得したときに増加パターンまたは減少パターンを形成する 3 つの要素を含めることは禁止されます。 存在を単独で判断するのではなく、クエリごとにこの制限を満たす最長の部分列を構築し、最大長に達するものを出力することがタスクとなります。 

この制約により、オフラインまたはクエリごとの対数ソリューションが求められます。 まで$2 \cdot 10^5$クエリと配列のサイズも最大$2 \cdot 10^5$、クエリごとに二次関数を実行することは不可能です。$O(\sqrt n)$クエリごとの速度が遅すぎます。 The only viable direction is a segment tree or sparse-table style structure that can produce a small candidate set per query, followed by a constant-time or near-constant-time reconstruction step.

 重要な構造的事実により、すべてが単純化されます。単調トリプルを回避するシーケンスには、長さの制限があり、長さの制限はありません。$n$。 エルデシュ・セーケレスの定理によれば、長さ 5 のシーケンスには必ず長さ 3 の単調部分シーケンスが含まれるため、クエリの答えは最大でも長さ 4 になります。これにより、長いシーケンスに対する複雑な動的プログラミングの必要がなくなります。 最大 4 つのインデックスを見つけるだけで済みます。 

微妙なエッジケースは、間隔に多くの要素があるが、サイズが少なくとも 3 の有効なサブシーケンスが存在しない場合です。 ただし、サイズ 3 のセットは単調性に対してすでにチェックされており、有効なサブシーケンスを出力することが許可されているため、失敗する唯一のケースはサイズ 3 さえ不可能な場合であり、これは間隔が制約されすぎて単調トリプルの形成を回避できない場合にのみ発生します。 その場合、構築自体は当然ながら有効な候補セットを見つけることができません。 

## アプローチ

 ブルート フォース戦略では、間隔のすべてのサブシーケンスを試し、単調トリプルが含まれているかどうかを確認し、最も長い有効なトリプルを追跡します。 単一の間隔の長さがあるため、これはすぐに実行不可能になります。$m$もっている$2^m$サブシーケンスを作成し、それぞれの単調トリプルをチェックするには少なくともコストがかかります$O(m^3)$単純な形式のサブシーケンスごと。 サイズを最大 4 に制限しても、組み合わせ論は次のように減少します。$\binom{m}{4}$、まだ限界をはるかに超えています$m = 2 \cdot 10^5$。 

重要な観察は、有効な回答が非常に少ないということです。 有効なサブシーケンスの長さは最大 4 であるため、各クエリは、グローバル パターン制約を満たす最大 4 つの「代表」インデックスを選択することになります。 これにより、問題はシーケンス最適化問題ではなく選択問題に変わります。 

次の構造的洞察は、サイズが最大 4 の有効なセットには必ず値の順序で極端な要素が含まれている必要があるということです。 選択したインデックスを値でソートすることを想像すると、単調トリプルを避けると強力なインターリーブが強制されます。すでに単調チェーンを形成している 3 つの要素を持つことはできません。 これは、解には区間内の最小値と最大値に近い要素が含まれている必要があることを意味します。 セグメントごとに一定数の最小要素と最大要素を格納するセグメント ツリーを使用すると、クエリごとに小さな候補プールを収集できます。 このプールから、サイズ 3 と 4 のすべてのサブセットをブルート チェックするのは継続的な作業です。

 ## アルゴリズムのチュートリアル

 1. 配列上にセグメント ツリーを構築します。各ノードはセグメント内の最小 4 要素と最大 4 要素をペアとして格納します。$(value, index)$。 順序付けは値によって行われますが、後で出力を順序付けするためにインデックスが保持されます。 サイズが最大 4 の有効な答えは、セグメントのマージ後に生き残る極端な候補を使用して表現できる必要があるため、これで十分です。 
2. 質問に答えるため$[L, R]$、セグメント ツリーをクエリし、ノード サマリーをマージすることで候補要素を収集します。 マージされたプールには最大で 8 つの最小候補と最大 8 つの候補が含まれるため、全体で最大 16 の個別のインデックスが含まれます。 
3. この候補プールから、サイズ 3 と 4 のすべてのサブセットを生成します。各サブセットは、インデックス順に並べたときにその内部のトリプルが単調パターンを形成するかどうかをチェックすることによって、有効性がテストされます。 サブセットのサイズは最大 4 であるため、このチェックは一定時間になります。 
4. すべての有効なサブセットの中から、最大サイズのものを選択します。 サイズ 3 が存在しない場合は、0 を出力します。それ以外の場合は、最良のサブセットのインデックスを昇順で出力します。 
5. 出力は最大長の有効な回答の間で任意にできるため、追加のランキングなしで同点が処理されます。 

### なぜ効果があるのか

 クエリの最適解のサイズは最大 4 です。そのような最適なセットを検討してください。 要素がそのセグメント内の極端な 4 つの最小値または 4 つの最大値の中に含まれない場合、その要素は厳密に他の選択された要素の値の範囲内に存在する必要があります。 内部要素を適切な極値で置き換えても、非単調トリプル集合を形成する能力を維持しながら実現可能性を損なうことはありません。これは、単調トリプルの違反は相対的な順序にのみ依存し、極値置換は値空間の分離を維持または増加させるためです。 したがって、すべての最適解には、セグメントの極値から構築された候補プールに含まれる代表が含まれており、そのプールに対する総当たりの列挙で最適な答えを得るのに十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("mn", "mx")
    def __init__(self):
        self.mn = []  # list of (val, idx)
        self.mx = []

def merge_lists(a, b, limit=4, reverse=False):
    c = a + b
    c.sort(key=lambda x: x[0], reverse=reverse)
    if len(c) > limit:
        c = c[:limit]
    return c

def merge_nodes(left, right):
    res = Node()
    res.mn = merge_lists(left.mn, right.mn, 4, reverse=False)
    res.mx = merge_lists(left.mx, right.mx, 4, reverse=True)
    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.data = [Node() for _ in range(2 * self.size)]
        for i, v in enumerate(arr):
            self.data[self.size + i].mn = [(v, i)]
            self.data[self.size + i].mx = [(v, i)]
        for i in range(self.size - 1, 0, -1):
            self.data[i] = merge_nodes(self.data[2*i], self.data[2*i+1])

    def query(self, l, r):
        l += self.size
        r += self.size
        left_res = Node()
        right_res = Node()

        def add(res, node):
            res.mn = merge_lists(res.mn, node.mn, 4, False)
            res.mx = merge_lists(res.mx, node.mx, 4, True)

        while l <= r:
            if l & 1:
                add(left_res, self.data[l])
                l += 1
            if not (r & 1):
                add(right_res, self.data[r])
                r -= 1
            l >>= 1
            r >>= 1

        return merge_nodes(left_res, right_res)

def check_valid(indices, arr):
    vals = [(i, arr[i]) for i in indices]
    vals.sort()
    v = [x[1] for x in vals]
    n = len(v)
    if n < 3:
        return True
    for i in range(n):
        for j in range(i+1, n):
            for k in range(j+1, n):
                if (v[i] <= v[j] <= v[k]) or (v[i] >= v[j] >= v[k]):
                    return False
    return True

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    st = SegTree(a)

    out = []
    for _ in range(q):
        L, R = map(int, input().split())
        L -= 1
        R -= 1

        node = st.query(L, R)

        cand = node.mn + node.mx
        # unique indices
        seen = set()
        uniq = []
        for v, i in cand:
            if i not in seen:
                seen.add(i)
                uniq.append(i)

        best = []

        m = len(uniq)
        from itertools import combinations

        for sz in (4, 3):
            for comb in combinations(uniq, sz):
                if check_valid(comb, a):
                    best = list(comb)
                    break
            if best:
                break

        if not best:
            out.append("0")
        else:
            best.sort()
            out.append(str(len(best)))
            out.append(" ".join(str(x+1) for x in best))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```セグメント ツリーには、セグメントごとに一定数の極端な要素のみが保存されるため、マージとクエリの両方が高速になります。 各クエリの候補セットは小さいままです。これが、ソリューションがクエリへの依存を回避する主な理由です。$R-L$。 

妥当性チェックは総当りですが、最大 16 個の候補にのみ適用されるため、三次チェックでも実際には一定時間になります。 チェック前の順序付けステップにより、定義に一致するインデックス順でモノトーン トリプルを常にテストしていることが保証されます。 

よくある落とし穴は、連続したセグメントではなくサブシーケンスをテストする必要があることを忘れていることです。 そのため、インデックスによるソート後に有効性がチェックされます。 

## 実用的な例

 ### 例 1

 入力配列:$[3, 1, 4, 1, 5, 9]$、クエリ$[1, 3]$| ステップ | 候補者プール | チェックされたサブセット | 最もよく見つかった |
 | --- | --- | --- | --- |
 | クエリ | {3,1,4} | 3 つのサブセットすべて | {3,1,4} |

 クエリ範囲にはすでにサイズ 3 の有効なセットが含まれています。これは、モノトーンでソートされていない限り、3 つの要素のみ内でモノトーン チェーンを形成できるトリプルは存在しないためです。 アルゴリズムは利用可能なすべての候補を選択し、サイズ 3 のサブセットを直ちに受け入れます。 

### 例 2

 次のように、値が厳密に増加している範囲を検討します。$[1,2,3,4,5]$クエリ上で。 

| ステップ | 候補者プール | チェックされたサブセット | 最もよく見つかった |
 | --- | --- | --- | --- |
 | クエリ | {1,2,3,4} (極端) | すべての 3/4 サブセット | 有効なものはありません |

 選択したサブセット内のすべてのトリプルは増加するため、サイズ 3 のサブセットは条件に違反します。 アルゴリズムは正しく 0 を返します。 

これは、制約が根本的には、単に極端な値を選択するのではなく、誘導された順序構造を回避することであることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、完全に単調な間隔です。 のような入力の場合$[1,2,3,4]$、選択された 3 つの要素は増加するトリプルを形成するため、正しい出力は 0 になります。候補プールは引き続きサブセットを生成しますが、どれも妥当性チェックに合格しないため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、有効な回答が存在するが、最小または最大の要素のみで構成されていない場合です。 それでも、回答のサイズは最大 4 であるため、すべての有効な構成はセグメントごとに維持される極端なセットと交差し、候補プールに確実に表示される必要があります。 これにより、リダクション中に最適な解が失われないことが保証されます。
