 ## 解決策
 ## 問題の理解

 大文字で構成される文字列が与えられますが、最初からのみです。$k$アルファベットの文字。 タスクは文字列を並べ替えたり変更したりすることではなく、順序を維持しながら文字のサブシーケンスを選択することです。 このようなすべてのサブシーケンスの中で、特別なプロパティを持つものが必要です。つまり、からのすべての文字です。`'A'`に$k$-番目の文字は、サブシーケンス内で同じ回数出現する必要があります。 目標は、そのようなサブシーケンスの長さを最大化することです。 

別の考え方としては、ある数字を選択しようとしているということです。$x$それぞれの$k$合計の長さは次のようになります。$k \cdot x$、この選択は元の文字列のサブシーケンスとして可能でなければなりません。 

制約$n \le 10^5$これより悪いアプローチはすぐにわかります。$O(n \cdot k)$または$O(n \log n)$苦戦し始めるだろう。 すべてのサブシーケンスに対するブルートフォースは不可能です。$2^n$彼らのうち。 考えられるすべての値を試しても、$x$スキャンを繰り返しても、慎重な最適化が必要になります。 

いくつかのエッジの状況が重要です。 

一部の文字が完全に欠落している場合、有効な部分列にはその文字を含めることができないため、答えはゼロになる必要があります。 たとえば、次の場合$k = 3$しかし、文字列には次のものしか含まれていません`'A'`そして`'B'`そうすると、決してバランスが取れなくなります`'C'`、結果は次のようになります$0$。 

もう 1 つの微妙なケースは、周波数が非常に不均一である場合です。 仮定する$k = 3$そして文字列は`"AAAAABBBBBCC"`。 各文字が存在する場合でも、制限要因は 3 つの中で最も小さい頻度になります。 

スプレッドを最大化するには慎重にポジションを選択する必要があると考えるのは単純な間違いです。 実際には、サブシーケンスは順序を保持しますが、可用性を超えてカウントを制限しないため、順序はカウントの実現可能性とは無関係です。 

## アプローチ

 強引なアイデアは、可能なすべてのサブシーケンスを試して、バランスが取れているかどうかを確認することです。 サブシーケンスごとに、各文字の出現回数をカウントし、等しいことを検証します。 これは正しいですが、完全に実行不可能です。$2^n$サブシーケンス、さらには 1 つのテイクをチェックする$O(n)$、指数関数的な時間につながります。 

より良い方向性は、問題を再構成することです。 サブシーケンスを明示的に選択するのではなく、各文字が何回出現できるかに焦点を当てます。 それぞれが次のように決定したとします。$k$文字が正確に表示される$x$回。 すると全長は$k \cdot x$、そして質問は次のようになります: 選択することは可能ですか?$x$順序を尊重しながら文字列内のすべての文字を出現させるか?

 しかし、サブシーケンスには連続した構造ではなく、十分な出現数だけが必要であるため、実際には順序は実現可能性にとって重要ではありません。 存在する場合は、いつでもスキャン順に貪欲にそれらを選択できます。 

したがって、実際の制約は、単純なカウント条件に集約されます。各文字に対して、少なくとも次の条件が必要です。$x$出来事。 もし$cnt[c]$手紙の頻度です$c$、 それから$x \le \min cnt[c]$。 私たちにできる最善のことは設定することです$x$その最小周波数まで。 

したがって、答えは簡単です。$$k \cdot \min_{c \in [A, A+k-1]} cnt[c]$$重要な洞察は、サブシーケンスの順序付けによって可用性を超える追加の制約が導入されないため、問題は純粋な周波数の最小化になるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブシーケンス |$O(2^n \cdot n)$|$O(n)$| 遅すぎる |
 | 最小周波数 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初のそれぞれの回数を数えます。$k$文字列に文字が表示されます。 これが機能するのは、サブシーケンスでは既存の文字のみを使用できるため、可用性が唯一の制約となるためです。 
2. これらの中から最小の周波数を見つけます$k$カウントします。 この値は、すべての文字にわたって形成できる完全な「バランスの取れたレイヤー」の最大数を表します。 
3. この最小値に次の値を掛けます。$k$、各レイヤーは各文字の 1 つだけを提供するためです。 
4. 結果を出力します。 

### なぜ効果があるのか

 有効な各サブシーケンスには、すべてのサブシーケンスの等しい数が含まれている必要があります。$k$手紙、言う$x$それぞれの。 これは、元の文字列内に出現する文字の合計を超える文字は存在しないことをすぐに暗示します。$x \le cnt[c]$みんなのために$c$。 したがって$x \le \min cnt[c]$。 逆に、私たちが選択すると、$x = \min cnt[c]$、サブシーケンスでは位置の選択のみが必要であり、再配置や隣接性の尊重は必要ないため、常に文字列からその数の各文字を順番に選択できます。 これにより、最適性と実現可能性の両方が確立されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
s = input().strip()

cnt = [0] * k

for ch in s:
    cnt[ord(ch) - ord('A')] += 1

ans = min(cnt) * k
print(ans)
```実装は、カウントへの削減の直後に行われます。 配列`cnt`最初の周波数を追跡します$k$文字。 これらすべての周波数の最小値を計算し、次の値を掛けます。$k$。 

微妙な点はインデックス付けです。文字は最初の文字列内にあることが保証されているためです。$k$、 マッピング`'A'`インデックス 0 までは安全です。 条件チェックは必要ありません。 

の乗算$k$最小限のものを摂取した後にのみ起こります。 独立した最大値を合計するのではなく、すべての文字にわたって等価性を強制するため、順序を逆にすることは正しくありません。 

## 実用的な例

 ### 例 1

 入力:```

```カウントは次のように変化します。

 最小頻度は$2$, したがって、完全な 2 つの層を形成できます。`A`、`B`、`C`、全長を与える$3 \cdot 2 = 6$。 

これは、たとえ`'A'`そして`'C'`の方が頻繁にある場合、答えは完全に次の条件によって制限されます。`'B'`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k = map(int, input().split())
    s = input().strip()

    cnt = [0] * k
    for ch in s:
        cnt[ord(ch) - ord('A')] += 1

    return str(min(cnt) * k)

# provided sample
assert run("9 3\nACAABCCAB\n") == "6"

# k = 1, always full string
assert run("5 1\nAAAAA\n") == "5"

# missing character forces zero
assert run("5 3\nAABBB\n") == "0"

# all equal frequencies
assert run("6 2\nAABBAB\n") == "4"

# large balanced case
assert run("4 2\nBABA\n") == "4"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 9 3 アカABCCAB | 6 | 制限文字を使用した通常の場合 |
 | 5 1 ああああ | 5 | k=1 のエッジケース |
 | 5 3 ああああ | 0 | 不足している文字 |
 | 6 2 アーバブ | 4 | バランスのとれた周波数 |
 | 4 2 馬場 | 4 | 交互構造の正確性 |

 ## 特殊なケース

 1 文字も出現しない場合、最小頻度は 0 になり、バランスのとれたサブシーケンスにはその文字が含まれないため、アルゴリズムは正しく 0 を返します。 

具体的なトレースについては、次のようにします。```
4 3
ABAB
```カウント:

 | あ | B | C |
 | --- | --- | --- |
 | 2 | 2 | 0 |

 最小値は 0 であるため、出力は 0 です。アルゴリズムは欠落している文字を「スキップ」しようとしません。これは、すべてを最初に行うという要件に一致します。$k$文字は均等に表示される必要があります。 

もう 1 つのエッジケースは次のような場合です$k = 1$。 のために：```
5 1
ABCDE
```のみ`'A'`が考慮され、カウントは 1 であるため、答えは 1 になります。単一の値の最小値はそれ自体であり、1 を乗算することで最小値が維持されるため、アルゴリズムは正しく削減されます。
