 ## 解決策

 ## 問題の理解

 2 人のプレーヤーはそれぞれ整数のマルチセットを保持します。 A から順に順番に行動します。ターンでは、プレーヤーは自分の残りの数字の 1 つを消費してスコアに追加するか、相手のコレクションから 1 つの数字を破棄します。これはスコアに直接影響しませんが、後で対戦相手が獲得できるものを減らします。 両方のマルチセットが空になるとゲームは終了し、両プレイヤーは常に A の合計スコアと B の合計スコアの間の最終的な差を最大化する決定を下すものと想定されます。 

困難は、直接的な利益と拒否の間の相互作用から生じます。 自分のリストの高い値は価値がありますが、相手のリストの高い値も後で得点するのを防ぐため価値があります。 

制約は n が最大 100,000 と大きいため、考えられるすべての動きのシーケンスをシミュレートしたり、ゲームの状態を調査したりするソリューションは不可能です。 各動きが両方のリストに繰り返し影響し、二次的な動作につながる可能性があるため、O(n²) 推論でも遅すぎます。 

素朴だが魅力的な考えは、各プレイヤーが自分のリストをソートし、常に最大の残りの値を取得すると考えることです。 これは、代わりに対戦相手から非常に大きな値を削除する可能性を無視するため、失敗します。 たとえば、A の数値が小さく、B の数値が巨大な場合、A は自分自身の小さな利益を得る代わりに、その巨大な数値を削除することを好む可能性があります。 この相互作用により、両方のリストを一緒にモデル化しない限り、純粋にローカルな貪欲な選択の信頼性が低くなります。 

両方のプレイヤーが同じセットを持っている場合、微妙なエッジケースが発生します。 たとえば、A と B が両方とも [1, 100] を持っている場合、対称性は結果のバランスが取れていることを示唆しており、実際に最適なプレイでは差がゼロになります。 単純な「常に最大値を取得する」戦略は、相互ブロックを考慮せずに誤って早期に 100 を優先し、先手の利点を過大評価することになります。 

もう 1 つのエッジ ケースは、一方のプレイヤーが多くの大きな値を持ち、もう一方のプレイヤーが多くの小さな値を持っている場合に発生します。 一方がより多くの総額を「所有」しているとしても、積極的な除去は回収よりも拒否を優先することでその利点を無効にする可能性があります。 

## アプローチ

 ブルートフォース解釈では、2 つのマルチセットと方向指示器にわたる状態検索としてゲームをシミュレートします。 各状態で、プレイヤーは自分の要素の 1 つを取得するか、対戦相手から 1 つを削除するかを選択できます。 これにより、リストのサイズに比例した分岐係数が作成され、アクションごとに合計要素が 1 ずつ減少するため、最悪の場合、状態の合計数は階乗的に増加します。 メモ化を行ったとしても、状態空間は残りの要素のすべてのサブセットに依存しますが、これは実現可能な限界をはるかに超えています。 

重要な観察は、ゲームは両方のリストにわたる要素の相対的な順序によって完全に決定されるということです。 すべての最適なアクションには、いずれかのリスト内の現在使用可能な最大要素との対話が含まれるため、常に、残りの最大値のみが問題になります。 より大きな有利な手が存在する間は、より小さな要素が選択されることはありません。これは、両方のプレイヤーが最終スコアの差を最大化しており、偏差はより大きな値を含む手によって支配されるためです。 

これにより、問題は、A の残りの要素と B の残りの要素の現在の最大値を繰り返し比較することになります。 誰が行動しても、直接利益を与えるか、後で相手がさらに利益を得るのを防ぐため、2 つのうち大きい方を取ることになります。 これにより、ソートされた配列に対する 2 ポインター スタイルの貪欲なプロセスが発生します。

両方の配列を降順に並べ替え、ポインターを使用してプロセスをシミュレートし、各側から現在残っている最大の候補を常に考慮します。 各移動は、現在どちらの側がより大きな値を保持しているかに応じて、所有者から 1 つの要素を消費するか、対戦相手から 1 つを削除します。

 ## アルゴリズムのチュートリアル

 2 つのソートされた配列 (A 用と B 用) を両方とも降順で維持します。 現在最大の未使用要素を表す配列ごとに 2 つのインデックスを追跡します。 

A から始まるターンもシミュレーションします。 

1. 両方の配列を降順に並べ替えます。 これにより、ポインタを使用してステップごとに O(1) 時間で各側の最適な候補を常に知ることができます。 
2. A と B の 2 つのポインタ i と j をそれぞれ 0 に初期化します。 これらは、各リストに残っている最大の要素を表します。 
3. スコアscoreAとscoreBを維持します（両方とも最初はゼロ）。 
4. A のターンで、A[i] と B[j] が両方存在する場合は比較します。 A[i] が大きいか等しい場合、A は A[i] を取得し、それをスコア A に追加し、i をインクリメントします。 それ以外の場合、A はスコアを獲得せずに B[j] を削除するため、j はインクリメントされます。 
5. B のターンで、対称操作を実行します。B[j] が大きいか等しい場合、B は B[j] を取得し、それをスコア B に追加し、j をインクリメントします。 それ以外の場合、B は A[i] を削除するため、i が増加します。 
6. 両方のポインタが配列の最後に到達するまで交互に回転します。 

即時の利益と拒否の影響の両方の観点から、より小さな値が厳密に支配されるため、決定ルールは常に利用可能な最大値に基づいています。 プレイヤーが利用可能な最大のオプションを無視すると、対戦相手が最初にそれを悪用することを許可し、最終的な差が減少します。 

### なぜ効果があるのか

 各ステップで、ゲームの状態は両方のリストに残っている最大の要素によって要約できます。 最適な動きには、これら 2 つの要素のいずれかが含まれている必要があります。これは、ゲインとブロッキングの可能性の両方において、より小さい要素はすべて厳密に悪い選択であるためです。 移動するたびにグローバル プールから要素が 1 つだけ削除されるため、プロセスは、現在の最大値をどちらが「制御」するかを繰り返し解決することになります。 この不変条件により、最適な戦略が現在の 2 つの最大値を超えて検討する必要がないことが保証されるため、貪欲なシミュレーションが最適なプレイに一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    a.sort(reverse=True)
    b.sort(reverse=True)
    
    i = j = 0
    scoreA = 0
    scoreB = 0
    turnA = True
    
    while i < n or j < n:
        a_top = a[i] if i < n else -1
        b_top = b[j] if j < n else -1
        
        if turnA:
            if i < n and (j == n or a_top >= b_top):
                scoreA += a_top
                i += 1
            else:
                j += 1
        else:
            if j < n and (i == n or b_top >= a_top):
                scoreB += b_top
                j += 1
            else:
                i += 1
        
        turnA = not turnA
    
    print(scoreA - scoreB)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に両方のリストを順序付けして、残りの最良のオプションに常にアクセスできるようにします。 2 つのポインターは、結合されたマルチセットの縮小をシミュレートします。 各ステップでは、可能な限り個人的な利益を得るか、相手の最大の脅威を除去するかのどちらかという、最適なローカル決定が強制されます。 

交互のターン ロジックにより、決定へのアクセスの公平性が保証され、比較ステップにより、ゲインの最大化と対戦相手の拒否の両方が同じルールで処理されることが保証されます。 

実装でよくある落とし穴は、対戦相手から除去するかどうかは、どのポインタが動くかを決定する以上のターンには依存しないということを忘れていることです。 もう 1 つの微妙な問題は、等価性の処理が間違っていることです。等しい値を一貫性なく扱うと、要素が繰り返される場合に対称性が崩れる可能性があります。

 ## 特殊なケース

 両方の配列に同一のマルチセットが含まれている場合、アルゴリズムは完全に対称的なアクションを交互に実行します。 一方のリスト内のすべての高値要素はもう一方のリストにもミラーリングされるため、各ゲインは最終的に反対側の同等のゲインによってキャンセルされます。 ポインタベースのシミュレーションでは、同一の最大値が常に一貫した順序で処理され、最終的な差分がゼロになることが保証されます。 

一方の配列に 1 つの非常に大きな要素が含まれ、もう一方の配列に多数の小さな要素が含まれている場合、大きな要素は早いターンでブロックするためにすぐに消費されます。 このアルゴリズムは、自己採点よりも削除を正しく優先し、大きな値が最終結果を誤って支配しないようにします。 

すべての要素が等しい場合、A と B のトップ間のすべての比較は等しいものとして解決されるため、タイブレーク ルールにより一貫して対称的な結果が得られます。 このアルゴリズムは除去とゲインを均等に交互に行い、両方のプレイヤーのバランスを保ちます。
