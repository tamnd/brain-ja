 ## 解決策
 ## 問題の理解

 各エッジが整数値を保持するツリーが与えられます。 ツリーは固定されていますが、エッジの値は時間の経過とともに変化します。 システムは 2 つの操作をサポートします。 

最初の操作では 2 つのノードと値 z を選択し、次にこれら 2 つのノード間の一意の単純なパス上にあるすべてのエッジの値を、z とのビット単位の XOR を適用することによって変更します。 これは置換ではなく、バイナリ表現の切り替えであり、そのパス上の各エッジに個別に適用されます。 

2 番目の操作は単一のノードを要求し、そのノードに現在発生しているすべてのエッジ値の XOR を計算する必要があります。 

ツリーには最大 500,000 のノードがあり、操作の数も最大 500,000 であるため、パス上のすべてのエッジを明示的に検査するソリューションは失敗します。 単一の長いパスの更新でも O(n) エッジに触れる可能性があり、それを q 個の操作にわたって繰り返すと O(nq) になり、これは実行可能な限界をはるかに超えています。 

微妙な点は、更新ではパスの合計やパスのクエリは要求されず、代わりにエッジの状態が変更され、クエリはノードに対してローカルですが、隣接するすべてのエッジに依存することです。 この不一致は、単純な走査アプローチが破綻する場所です。 

典型的な失敗例は、チェーン状のツリー内の長いパスを繰り返し更新する場合に発生します。 たとえば、100,000 ノードのチェーンでは、一方の端からもう一方の端まで 1 回の更新でほぼすべてのエッジにアクセスすることになり、それを繰り返し行うとすぐに時間制限を超えてしまいます。 

## アプローチ

 直接シミュレーションのアプローチでは、DFS または BFS を使用して x と y の間のパスを見つけ、そのパス上のすべてのエッジを反復処理して値を切り替えることによって各パスを再計算します。 ツリー構造によって一意のパスが保証されるため、これは概念的には簡単です。 ただし、このような各操作には、最悪の場合、直線的な時間がかかる可能性があります。 操作が 500,000 回になると、これは不可能になります。 

重要な観察は、エッジが更新されているにもかかわらず、クエリはパスやサブツリーについて質問しているのではなく、ノードに付随するエッジの XOR についてのみ質問しているということです。 これにより、更新後に各エッジを明示的に追跡することを回避できます。 

単一のエッジ (u, v) の値が z によって XOR 演算された場合に何が起こるかを考えてみましょう。 両方のエンドポイントが隣接リストでそのエッジを認識するため、この変更はちょうど 2 つのノード u と v に影響します。 ノードの寄与という観点から考えると、すべてのエッジの更新は、そのエッジの両方のエンドポイントに XOR z を適用することと同じになります。 

ここで、x から y へのフルパスの更新を考えてみましょう。 そのパスは一連のエッジで構成されます。 パス上のすべての内部ノードは、更新されたエッジのうちの 2 つと一致し、エンドポイント x と y は 1 つと一致します。 XOR はそれ自体の逆数であるため、z を 2 回適用すると相殺されます。 したがって、内部ノードは正味の効果をまったく受け取りませんが、エンドポイントはちょうど 1 つの XOR z を受け取ります。 

これにより、パス更新全体が定数時間操作に集約されます。必要なのは、z を x と y に XOR することだけです。 

また、各ノードについて、初期入射エッジの重みの XOR も維持します。 すべての更新は、エンドポイントへの追加の切り替えに貢献します。 クエリは、初期値と蓄積されたすべてのトグルを単純に組み合わせます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 更新ごとのブルート フォース パス トラバーサル | O(nq) | O(n) | 遅すぎる |
 | エンドポイントトグル集約 | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを任意の場所にルート化しますが、正確さを保つためにルート化は実際には必要ありません。 まず、すべてのノードのすべてのインシデント エッジの重みの初期 XOR を計算します。 

各エッジはその重みを両方のエンドポイントに提供するため、配列を初期化できます。`base[x]`この XOR を直接保存します。 

別の配列も維持します`delta[x]`、最初はすべてゼロで、すべてのパス更新の累積効果を保存します。 

ここで、操作を順番に処理していきます。 

1. ノード x と y、値 z によるタイプ 1 の操作の場合、次のように適用します。`delta[x] ^= z`そして`delta[y] ^= z`。 これは、まさにパスのエンドポイントが z の正味 XOR 効果を受けるという事実を表しています。 
2. ノード x でのタイプ 2 操作の場合、次のように出力します。`base[x] ^ delta[x]`。 これにより、元のインシデントの XOR と、パス更新を通じて x にインシデントされたエッジに影響を与えたすべての変更が結合されます。 

ステップ 1 が正しいかどうかは、ノード x がパス上の更新されたエッジの終点として出現する回数を数えることに依存します。 内部ノードは 2 回表示されてキャンセルされ、エンドポイントは 1 回表示されて残ります。 

### なぜ効果があるのか

 すべてのエッジ更新は、その 2 つのエンドポイントに正確に影響します。 パス更新は、単純なパスに沿ったエッジ更新のコレクションです。 どのノードでも、そのパス内のインシデント更新エッジの数は、それがパスの外側にあるのか、パスの終点にあるのか、パス上の内部ノードにあるのかに応じて、0、1、または 2 のいずれかになります。 XOR 累積により、「2 回発生」の場合は変更なし、「1 回発生」の場合は 1 回のトグルに変わります。 これにより、パス構造全体がエンドポイントのみの効果に縮小され、各ノードがすべての変更されたエッジから受け取るべき正確な寄与が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, q = map(int, input().split())

    base = [0] * (n + 1)
    delta = [0] * (n + 1)

    edges = []

    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        base[u] ^= w
        base[v] ^= w
        edges.append((u, v, w))

    out = []

    for _ in range(q):
        tmp = input().split()
        op = int(tmp[0])

        if op == 1:
            x = int(tmp[1])
            y = int(tmp[2])
            z = int(tmp[3])

            delta[x] ^= z
            delta[y] ^= z

        else:
            x = int(tmp[1])
            out.append(str(base[x] ^ delta[x]))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```実装は事前計算を行います`base[x]`エッジを読み取るときに、すべての入射エッジの重みを直接 XOR 演算します。 これにより、隣接リストの保存が回避されます。 の`delta`配列には、各エンドポイントに関わるすべてのパス更新の効果が蓄積されます。 

タイプ 1 の操作の場合、2 つのエンドポイントのみが更新されます。 これは、経路長への依存を取り除く重要な最適化です。 

タイプ 2 の操作の場合、答えは、元の値と累積されたすべてのエンドポイント トグルとして再構築された、すべての入射エッジの現在有効な XOR です。

 ノード 1 にはエッジ (1,2)=1 および (1,3)=2 があるため、base[1]=3 になります。 

ノード 2 のbase[2]=1。 

ノード 3 には、base[3]=2 があります。 

最初はデルタはすべてゼロです。 

| ステップ | 操作 | デルタ[1] | デルタ[2] | デルタ[3] | クエリ結果 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | クエリ 1 | 0 | 0 | 0 | ベース[1]=3 |
 | 2 | z=2 で 1 ～ 3 を更新 | 2 | 0 | 2 | - |
 | 3 | クエリ 1 | 2 | 0 | 2 | 3 ^ 2 = 1 |

 2 番目のステップでは、パス更新のエンドポイントのみが影響を受けることを反映して、XOR 2 をノード 1 と 3 にのみ適用します。 

このトレースは、内部エッジが明示的に処理されずにどのように暗黙的に処理されるかを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、更新パスが単一ノードに縮退する場合、つまり x が y に等しい場合です。 この状況では、エッジは影響を受けないため、操作によって何も変更されてはなりません。 アルゴリズムはこれを正しく処理します。`delta[x] ^= z`x に対して 1 回、y に対して 1 回の計 2 回、同じノードであるため、XOR はキャンセルされます。 

もう 1 つのケースは、多くの更新が中心ノードをターゲットとする星型ツリーです。 葉の間のすべてのパスは中心を通過するため、中心を大幅に更新する必要があるように見える場合があります。 実際には、エンドポイント ルールにより、操作ごとにリーフのみが切り替えられ、エンドポイントでない限りセンターは安定したままになります。 

3 番目のケースは、同じパス上で同じ更新が繰り返される場合です。 XOR はそれ自体の逆であるため、同じ更新を 2 回適用すると完全にキャンセルされます。 の`delta`累積では、各更新が個別にエンドポイントを切り替え、繰り返し切り替えると状態が元に戻るため、このプロパティが自然に保持されます。
