 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付けられた都市の行が与えられ、それぞれが数直線上の異なる座標に配置されます。 隣接する都市は道路で接続されているため、最初はグラフは単なる鎖です。 

すべての都市の完全なペアを形成する必要があります。つまり、すべての都市が他の 1 つの都市と正確に一致し、各ペアがその端点間の線分に沿ったパスを定義します。 ペア (a、b) を接続するたびに、概念的には、それらの間のすべての道路に沿って 1 単位の流れが送信されるため、チェーン上のすべてのエッジには、選択したペアの数に等しい負荷が蓄積されます。 各道路には容量制限があり、有効なペアリングはこれらすべての制限を同時に遵守する必要があります。 

有効な組み合わせごとに、元の座標を使用して、ペアになった都市間の距離の合計に等しいスコアを計算します。 タスクは、すべての有効なペアに対するこれらのスコアの合計を、998244353 を法として計算することです。 

完全一致の数はすでに指数関数的であるため、制約 n ≤ 2000 とすべてのエッジに容量が存在するため、ペアの列挙は直ちに除外されます。 実現可能性のチェックを無視したとしても、単純な列挙は (n−1) のオーダーになります。 成長が早すぎて表現することさえできません。 これにより、行のプレフィックスに対して動的プログラミング アプローチが強制されます。 

容量が小さい場合、微妙なエッジケースが発生します。 いずれかのエッジの容量が 0 の場合、どのペアもその境界を越えることはできず、事実上、すべてのペアが連続したブロック内にとどまることになります。 エッジ制約を無視した単純なマッチング DP では、禁止された境界を越えるマッチングが生成され、無効な構造が過剰にカウントされます。 

もう 1 つのデリケートなケースは、すべての容量が大きい (少なくとも n/2) 場合です。 この状況では、問題はすべての完全なマッチングにわたる重み付けされた寄与を合計することになり、正しい DP はマッチングの数をカウントするだけでなく、距離を正しく累積する必要があります。 

## アプローチ

 ブルートフォース手法では、n 都市のすべての完全なマッチングを生成し、過負荷になっているエッジがあるかどうかを確認し、有効な場合はそのマッチングの合計距離の合計を計算します。 すべてのマッチングを構築するだけでもすでに指数関数的な時間がかかり、制約をチェックするとマッチングごとにさらに O(n) が追加されるため、n が 20 に達するずっと前に実行不可能になります。 

重要な観察は、構造が本質的に連続的であるということです。 左から右にスイープすると、各都市はペアを開始するか、以前に開始したペアを終了します。 これにより、問題は、現在位置を横切る間隔の不一致の左端を表す「開いた端点」の複数セットを維持することに変わります。 位置 i にあるオープン エンドポイントの数は、エッジ i を横切るパスの数と正確に一致するため、容量制約はこの数に関する単純な境界になります。 

この方法でプロセスを表現したら、オープン エンドポイントがいくつ存在するか、各構成を生成する方法がいくつあるか、部分ペアリングによって寄与される距離の累積寄与を追跡するだけで済みます。 唯一の重要な問題は、ペアを閉じるには、考えられるすべてのオープン エンドポイントを合計する必要があり、それぞれが異なる座標値に寄与することです。 

これにより、オープンエンドポイントに関する追加の集約情報を使用したポジションに対する動的プログラミングが可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O((n−1)!!) | O(n) | 遅すぎる |
 | オープンエンドトラッキングを備えた DP | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 都市を左から右に処理します。 どの時点でも、処理済みの都市間にアクティブなオープン エンドポイントがいくつ存在するかを示す状態と、それらに関する 2 つの集計 (状態に到達する方法の数と、それらの方法にわたる現在オープンしているすべてのエンドポイントの座標の合計) を維持します。

1. DP テーブルを初期化します。ここで、dp[k] は、正確に k 個のオープン エンドポイントを残して最初の i 都市を処理する方法の数です。また、sumX[k] を、そのようなすべての構成にわたって、構成全体にわたる多重度でカウントされたオープン エンドポイントの座標の合計として維持します。 
2. 都市を処理する前に、dp[0] = 1 および sumX[0] = 0 のみから開始します。 
3. i = 1 から n まで都市を 1 つずつ処理します。 各都市では、以前の DP 州から新しい州に移行します。 
4. k 個のオープン エンドポイントがある固定状態の場合、都市 i を処理するときに 2 つの選択肢があります。i で新しいペアリング エンドポイントを開くか、i で既存のオープン エンドポイントの 1 つを閉じることができます。 
5. i でオープンすると、オープン エンドポイントの数は k+1 に増加し、オープン エンドポイントの合計に x[i] を追加します。 ウェイの数は変わりません。 
6. i で閉じる場合は、k 個のオープンエンドポイントの 1 つを選択します。 任意のオープン エンドポイントが一致する可能性があるため、これは dp[k] の k 倍の新しい方法に寄与します。 距離の寄与は、各オープン j の (x[i] − x[j]) のすべての選択肢の合計であり、単純化すると、k・x[i] から sumX[k] を引いたものになります。 
7. 都市 i を処理した後、開いているエンドポイント k の数が s[i] を超えてはならないという制約を適用します。これは、エッジ i から i+1 までのパスの数を正確に表すためです。 これに違反する状態はすべて破棄されます。 
8. 最後の都市 n では、一致しないままになるため、新しいエンドポイントを開くことができません。 したがって、終了遷移のみが許可され、最後には k = 0 が必要です。 

### なぜ効果があるのか

 どのプレフィックスでも、開いている各エンドポイントは、そのプレフィックスの後に境界を横切る 1 つのアクティブなパスに正確に対応します。 これは、DP 状態パラメータ k がエッジの輻輳情報を完全に捕捉することを意味します。 集計値 sumX は、ペアを閉じるときに距離の寄与を計算するために必要な情報をすべてエンコードします。これは、考えられるすべてのパートナー j が x[i] − x[j] に寄与し、すべての選択肢の合計は k と sumX の一次式に帰着するためです。 これにより、エンドポイントの合計数と座標の合計を超えて、オープンなエンドポイントに関する隠れた構造が必要なくなることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input().strip())
    x = list(map(int, input().split()))
    s = list(map(int, input().split()))

    # dp[k] = number of ways
    # sx[k] = sum of x-values of open endpoints across all ways (weighted)
    # val[k] = total contribution sum of distances
    dp = [0] * (n + 1)
    sx = [0] * (n + 1)
    val = [0] * (n + 1)

    dp[0] = 1

    for i in range(n):
        ndp = [0] * (n + 1)
        nsx = [0] * (n + 1)
        nval = [0] * (n + 1)

        xi = x[i]

        if i == n - 1:
            # last city: cannot open new, only close
            for k in range(n + 1):
                if dp[k] == 0:
                    continue
                if k == 0:
                    ndp[0] = (ndp[0] + dp[0]) % MOD
                    nsx[0] = (nsx[0] + sx[0]) % MOD
                    nval[0] = (nval[0] + val[0]) % MOD
                else:
                    ways = dp[k]
                    # close transition
                    ndp[k - 1] = (ndp[k - 1] + ways * k) % MOD

                    # sumX contribution
                    nsx[k - 1] = (nsx[k - 1] + sx[k]) % MOD

                    # distance contribution
                    contrib = (ways * k % MOD) * xi % MOD
                    contrib = (contrib - val[k]) % MOD
                    nval[k - 1] = (nval[k - 1] + contrib) % MOD
        else:
            cap = s[i]
            for k in range(n + 1):
                if dp[k] == 0:
                    continue

                ways = dp[k]

                # open new endpoint
                nk = k + 1
                ndp[nk] = (ndp[nk] + ways) % MOD
                nsx[nk] = (nsx[nk] + sx[k] + ways * xi) % MOD
                nval[nk] = (nval[nk] + val[k]) % MOD

                # close with existing endpoint
                if k > 0:
                    nk = k - 1
                    ndp[nk] = (ndp[nk] + ways * k) % MOD

                    nsx[nk] = (nsx[nk] + sx[k]) % MOD

                    contrib = (ways * k % MOD) * xi % MOD
                    contrib = (contrib - val[k]) % MOD
                    nval[nk] = (nval[nk] + contrib) % MOD

        # apply capacity constraint except at last step
        if i < n - 1:
            for k in range(n + 1):
                if k > s[i]:
                    ndp[k] = 0
                    nsx[k] = 0
                    nval[k] = 0

        dp, sx, val = ndp, nsx, nval

    print(val[0] % MOD)

if __name__ == "__main__":
    solve()
```この実装では、3 つの同期された DP アレイが維持されます。 1 つ目は部分一致の数を追跡し、2 つ目はすべての構成にわたるオープン エンドポイントの座標の合計を追跡します。 3 番目は、完了したペアからの合計距離寄与を累積します。 

重要な微妙な点は、終了トランジションが開いているエンドポイントの数とそれらの合計座標の両方に依存することです。 式 k·x[i] − sumX[k] は、開いているすべてのエンドポイントに対する明示的な反復を置き換え、O(n) の内部ループを回避します。 

最終状態はオープンエンドポイントなしで終了する必要がありますが、実際のエッジには対応しないため、最後を除く各位置の後に容量制約が適用されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n²) | n 個の位置のそれぞれは、n までのすべての k にわたって遷移します。 
| スペース | O(n) | 現在と次の DP 配列のみが保存されます。 

二次計算量は n ≤ 2000 の場合に十分であり、オープン エンドポイントに対する明示的な列挙が集計和に置き換えられるため、各遷移は定数時間になります。

 ## 特殊なケース

 容量境界が狭いことは、枝刈りがいかに重要であるかを示しています。 エッジの容量が 0 の場合、k>0 の状態はその位置の処理直後に削除され、すべてのペアがそのエッジと交差しないセグメント内に強制的に残ります。 k が交差点を直接測定するため、DP は当然これを強制します。 

逆に、容量が非常に大きい場合、枝刈りは行われず、DP はすべての有効な開閉構造を探索します。 この場合、正確さは終了遷移で使用される代数恒等式に完全に依存します。この場合、すべての可能なパートナーの合計は k·x[i] − sumX[k] に減り、明示的な列挙が必要ないことが保証されます。 

最後の都市は k をゼロに戻すことを強制します。 最後の位置でオープンしようとする状態は、後で閉じることができないため、最終的な答えには決して寄与しません。DP 構造は、そのような状態が最終結果に伝播するのを防ぎます。
