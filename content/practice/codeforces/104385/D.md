 ## 解決策
 ## 問題の理解

 1 から n までの数値を昇順に処理する一連の操作をスタック上で生成しています。 いつでも、次の未使用の番号を取得してスタックにプッシュするか、スタックの現在の先頭が空でない場合はポップします。 各プッシュはプッシュされた値を正の数としてシーケンス Q に追加し、各ポップはポップされた値を負の数として追加します。 

プッシュは 1、2、3、…、n の順序に従う必要があるため、唯一の自由は、標準のスタック有効性ルールに基づいてプッシュとポップをインターリーブすることです。 すべての数値は正確に 1 回プッシュされ、正確に 1 回ポップされるため、Q の長さは常に 2n で、各値 i が 2 回 (正の 1 回と負の 1 回) 含まれます。 

目標は、そのような有効な操作シーケンスが「k-good」の Q を生成する数を数えることです。 Q 内のどこかに少なくとも k 個の連続した負の値の連続ブロックがある場合、シーケンスは k-good です。 ポップするときに負の値が正確に現れるため、この条件は、操作シーケンス内で少なくとも k 個の連続したポップ操作が実行されることと同等です。 

したがって、問題は、連続するポップの少なくとも 1 つのセグメントの長さが少なくとも k である有効なスタック操作シーケンス (Dyck のようなシーケンス) をカウントすることに帰着します。 

制約 n ≤ 3000 は、およそ O(n^2) または O(n^2 log n) より悪い解は遅すぎるリスクがあることを意味します。 スタック高さとランレングスの両方を含む状態にわたる 3 次 DP は、注意深く制御しない限り大きすぎます。 

k = 1 の場合、微妙なエッジ ケースが発生します。この場合、単一のポップはすでに有効なランを形成しているため、すべての有効なスタック シーケンスは自動的に k-good になります。 もう 1 つのエッジ ケースは k = n です。ここでは、残りのすべての要素が連続してポップされる瞬間が存在するかどうかを本質的に尋ねていますが、これは完全に減少するポップ シーケンスでのみ発生します。 

## アプローチ

 操作シーケンスは正確に長さ 2n の Dyck パスです。プッシュはアップステップに対応し、ポップはダウンステップに対応します。どの時点でもプッシュした以上のポップをしないという制約があります。 有効な各シーケンスはカタロニア語の構造に一意に対応します。 

ブルートフォース手法では、有効な Dyck シーケンスをすべて生成し、連続したポップの実行が長さ k に達するかどうかをシミュレートします。 このようなシーケンスの数は n 番目のカタロニア数であり、指数関数的に増加します。 n = 20 の場合でもこれは実行不可能になるため、列挙は不可能になります。 

重要な点は、シーケンス構造全体をグローバルに知る必要はなく、十分な長さの連続したポップをすでに作成したかどうかだけを知る必要があるということです。 これは、構築プロセスの現在の状態、つまりプッシュされた要素の数、ポップされた要素の数、および現在の連続ポップ ストリークの長さにのみ依存するローカル プロパティです。 

これは当然、プレフィックス状態に対する動的プログラミングにつながります。 プッシュされた番号の数、ポップされた番号の数、および最後の連続ポップ セグメントの現在の長さを追跡します。 すべての遷移は、スタックの有効性を尊重しながら、このストリークをリセットするか (プッシュ時)、増加させます (ポップ時)。 

すべての有効なシーケンスを計算し、長さ k のポップ ストリークに到達しないシーケンスを減算します。 これにより、構築中に不正なイベントが明示的に検出されることが回避され、代わりに状態の制限を通じて強制されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての有効なシーケンスのブルート フォース列挙 | O(C_n) | O(n) | 遅すぎる |
 | (プッシュ、ポップ、ポップストリーク) 状態の DP | O(n^2k) | O(n^2k) | 承認済み |

 ## アルゴリズムのチュートリアル

DP 状態 dp[i][j][t] を、i 個の数値がプッシュされ、j 個の数値がポップされ、現在の連続ポップ ストリークの長さが正確に t である有効な操作シーケンスの数として定義します。 値 t は、最後の操作がポップだった場合にのみ意味を持ちます。 押すと0になります。 

空のスタックからポップすることはできないため、j ≤ i の状態のみが許可されます。 

t を k − 1 に制限します。これは、k 個の連続ポップに達すると、シーケンスが「不良」であるとみなされ、DP から除外されるためです。 

### ステップ

 1. dp[0][0][0] = 1 を初期化します。これは、操作やポップ ストリークのない空のシーケンスを表します。 
2. 任意の状態 dp[i][j][t] から、i < n の場合はプッシュ操作を追加することを検討します。 これは dp[i+1][j][0] に遷移します。これは、プッシュによって連続するポップ ストリークがゼロにリセットされるためです。 固定順序でプッシュするため、プッシュは常に有効です。 
3. 任意の状態 dp[i][j][t] から、j < i の場合にポップ操作を追加することを検討します。 これは、スタックが空でない場合にのみ有効です。 k 個の連続ポップに達すると制約に違反するため、t + 1 < k の場合、遷移は dp[i][j+1][t+1] に進みます。 
4. i と j の昇順で状態を反復し、すべての遷移がソースの後に処理されるようにします。 
5. すべての状態を満たした後、0 から k − 1 までのすべての t について dp[n][n][t] を合計し、k 個の連続したポップが実行されない有効なシーケンスの数を取得します。 
6. 有効なスタック シーケンスの総数からこの結果を減算します。これは、DP または組み合わせ論によって計算された n 番目のカタロニア数です。 

よりシンプルでクリーンなバリアントでは、有効な状態に対してのみ DP を定義し、dp[n][n][t] を直接計算してそれらを合計することで、カタロニア語の減算を完全に回避します。 これにより、k 個の連続ポップを回避するシーケンスがすでに正確にカウントされます。 この問題では k-good シーケンスが求められるため、カタロニア語の合計から減算します。 

### なぜ効果があるのか

 DP 状態は、部分シーケンスを拡張するために必要なすべての情報を完全にキャプチャします。プッシュの数によって使用可能な値が決まり、ポップの数によってスタックの高さが決まり、ストリークの長さによってすでに制約に違反したかどうかが決まります。 これら 3 つの値を超える以前の構造に依存する将来の決定はありません。 すべての有効なシーケンスは、一意の遷移を通じて 1 回だけ構築されるため、DP は完全であり、重複しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def catalan(n):
    # C_n = (1/(n+1)) * binom(2n, n)
    fact = [1] * (2*n + 1)
    inv = [1] * (2*n + 1)
    for i in range(1, 2*n + 1):
        fact[i] = fact[i-1] * i % MOD
    inv[2*n] = pow(fact[2*n], MOD-2, MOD)
    for i in range(2*n, 0, -1):
        inv[i-1] = inv[i] * i % MOD

    def C(n, r):
        return fact[n] * inv[r] % MOD * inv[n-r] % MOD

    return C(2*n, n) * pow(n+1, MOD-2, MOD) % MOD

def solve():
    n, k = map(int, input().split())

    # dp[i][j][t]
    dp = [[[0] * k for _ in range(n+1)] for _ in range(n+1)]
    dp[0][0][0] = 1

    for i in range(n + 1):
        for j in range(i + 1):
            for t in range(k):
                val = dp[i][j][t]
                if not val:
                    continue

                # push
                if i < n:
                    dp[i+1][j][0] = (dp[i+1][j][0] + val) % MOD

                # pop
                if j < i and t + 1 < k:
                    dp[i][j+1][t+1] = (dp[i][j+1][t+1] + val) % MOD

    no_bad = 0
    for t in range(k):
        no_bad = (no_bad + dp[n][n][t]) % MOD

    total = catalan(n)
    print((total - no_bad) % MOD)

if __name__ == "__main__":
    solve()
```実装は DP 状態に直接に従います。 3 次元テーブルはプレフィックスの決定をエンコードします。i はプッシュされた値の数を追跡し、j はポップされた値の数を追跡し、t は現在の連続ポップ ラン長を追跡します。 プッシュ遷移は常に t をゼロにリセットします。これは、プッシュによって連続したポップ ストリークが中断されるためです。 ポップ遷移は t を増加させ、スタックが空でなく、ストリーク制限を超えていない場合にのみ許可されます。 

カタロニア語の計算により、有効なスタック シーケンスの総数が得られます。これから、長さ k のランに到達しないシーケンスの数が減算されます。 

## 実用的な例

 n = 3 および k = 2 のサンプルを考えてみましょう。DP が大きいため、概念的にのみ状態を追跡しますが、重要な動作は、単一のポップがすでに「k 個の連続ポップなし」条件に違反していることです。 したがって、2 つの連続ポップがないシーケンスをカウントし、すべてのカタロニア語シーケンスからそれらを差し引いています。 

2 番目の例は、n = 3、k = 3 です。ここでは、3 つの連続したポップを含むシーケンスのみを除外します。これは、すべてのプッシュ後に完全に減少するポップ順序でのみ発生します。 DP では他のすべてのインターリーブが許可されるため、カタロニア語の合計から除外されるシーケンスは 1 つだけです。 

## 複雑さの分析

 ## 特殊なケース

 k = 1 の場合、ポップはすでに長さ 1 の連続した負のセグメントを形成しているため、すべての有効なスタック シーケンスは自動的に k-good になります。 DP は依然として制約違反のないシーケンスの数を計算し、減算により完全なカタロニア語カウントが残り、予期される動作と一致します。 

k = n の場合、唯一の禁止パターンは、連続して発生するポップの完全なシーケンスです。 DP では当然、他のすべてのインターリーブが許可され、完全に降順のポップ順序のみが長さ n のランに寄与するため、合計から 1 回だけ除外されます。 

n = 1 の場合、プッシュとポップは 1 回だけです。 DP には正確に 2 つの有効な状態があり、単一のシーケンスには常に長さ 1 のポップ ランが含まれます。これは、k = 1 の場合は k-good に一致しますが、それ以外の場合は一致しません。
