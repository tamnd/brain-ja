 ## 解決策
 ## 問題の理解

 一連の単語に分割された文が与えられます。 各単語は英大文字のみで構成されています。 タスクは、文が最初の単語に関する特定の構造特性を満たしているかどうかを判断することです。 

このルールは、文内のすべての単語の最初の文字を順番に取得して最初の単語を再構成できる場合、その文を「かわいい」と定義します。 言い換えれば、文を単語のリストとして書き留め、各単語の最初の文字を抽出して連結した場合、結果の文字列は余分な文字や欠落文字がなく、最初の単語と正確に一致する必要があります。 

入力サイズは非常に小さく、最大 100 単語、各単語は 100 文字までです。 これは、すべての文字にわたって線形時間で動作するソリューションは自明に十分に高速であることを直ちに意味します。 単語を複数回繰り返しスキャンするソリューションであっても、制約の下では依然として安全です。 

主なリスクはパフォーマンスではなく正確さです。 いくつかの微妙なケースが重要です。 

エッジ ケースの 1 つは、最初の単語の長さが単語数と異なる場合です。 たとえば、文に 3 つの単語が含まれているが、最初の単語の長さが 5 である場合、頭字語は単語の数と同じ長さしか持てないため、それらを一致させることは不可能です。 

もう 1 つの特殊なケースは、単語が 1 文字である場合です。 これは実際には通常のケースであり、頭字語の構築は単語の長さに関係なく各単語の最初の文字のみに依存するため、一貫して処理する必要があります。 

3 番目のケースは、最初の文字は一致するが、順序が整列を壊す場合です。 たとえば、単語間にすべての文字が存在する場合でも、シーケンスは集合比較としてではなく、順序どおりに正確に一致する必要があります。 

## アプローチ

 直接的なアプローチは、すべての単語を反復処理し、各単語の最初の文字を取得し、それらを新しい文字列に連結することによって、頭字語文字列を明示的に構築することです。 次に、この構築された文字列を最初の単語と比較します。 

「かわいい文」の定義は純粋に構造的なものであり、抽出と比較以外の変換は必要ないため、これは正しいです。 各ワードを 1 回スキャンすることでコストが大きく左右されるため、総作業量はワード長の合計に比例します。 

ブルートフォースの亜種では、単語を繰り返しスキャンするか、ネストされたループで一致する位置をチェックすることによって、最初の単語の各文字を検証しようとする場合があります。 制約の下ではまだ実行可能ですが、不必要に複雑になり、インデックス作成の間違いが発生する可能性があります。 最悪の場合、このようなアプローチでは O(N^2) 個の文字チェックが実行される可能性がありますが、ここではまだ小さいですが、入力が大きくなるとスケーリングが不十分になります。 

重要な点は、頭字語は各単語の最初の文字によって一意に決定されるため、他の構造を考慮する必要がないということです。 これにより、問題は単一パスの構築と比較に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | お(1) | 受け入れられるが不要 |
 | 最適 | O(合計文字数) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 単語の数と単語のリストを読み取ります。 位置構造は重要なので、順番に保ちます。 
2. 各単語の最初の文字を抽出し、新しい文字列を構築します。 この文字列は、文の定義によって暗示される頭字語を表します。 
3. 構築された頭字語と文の最初の単語を比較します。 
4. 一致する場合は「Yes」を出力し、一致しない場合は「No」を出力します。 

各ステップは定義を直接反映するため、単純な反復以外に補助構造や前処理は必要ありません。 

### なぜ効果があるのか

最初の単語は、すべての単語の最初の文字を連結したものと正確に等しい必要があります。 各単語はちょうど 1 文字で頭字語に寄与し、順序は保持されるため、構築された文字列が唯一の候補となります。 したがって、構築された文字列と最初の単語が等しいことは、正確さのために必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    words = input().split()

    acronym = ''.join(w[0] for w in words)

    if acronym == words[0]:
        print("Yes")
    else:
        print("No")

if __name__ == "__main__":
    solve()
```このソリューションは、まず整数カウントを読み取り、次に文を読み取ります。 使用する`split()`間隔の不規則さに関係なく、単語を正しく分離できるようになります。 

核となる操作はジェネレータ式です`w[0] for w in words`、各単語の最初の文字を安全に抽出します。 すべての単語が空ではないことが保証されているため、インデックス エラーのリスクはありません。 

最後に、構築された頭字語を次と比較します。`words[0]`、必要なターゲット単語を表します。

 このトレースは、アルゴリズムが頭字語を順番に正しく蓄積し、直接比較を実行していることを確認します。 

次に、次のことを考えてみましょう。

 頭字語は「IM」であり、「IME」とは一致しません。 The output is “No”.

 これは、長さまたは末尾の文字における小さな不一致であっても、すぐに検出されることを示しています。

 ## 特殊なケース

 重要なエッジケースは、単語が 1 つしかない場合です。 入力の場合:

 1

 あ

 アルゴリズムは、唯一の単語の最初の文字を取得して「A」を生成することによって頭字語を構築します。 次に、これを最初の単語 (これも「A」) と比較するため、出力は「Yes」になります。 これにより、文が単一の単語で構成される退化したケースが正しく処理されます。 

もう 1 つのケースは、最初の単語が単語数より長い場合です。 For example:

 3

 ABCD A B

 頭字語は「AAB」となり、最初の単語は「ABCD」になります。 文字列はすぐに異なるため、アルゴリズムは特別な処理を行わなくても「No」を正しく出力します。 

最後に、次のように、すべての単語が同一の単一文字である場合:

 4

 X X X X

 頭字語は「XXXX」で、最初の単語と完全に一致するため、出力は「Yes」になります。 これにより、繰り返される文字と均一な入力が同じロジックの下で正しく動作することが確認されます。
