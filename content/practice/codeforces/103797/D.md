 ## 問題の理解

 長さの配列が与えられます$N$、最初はゼロで埋められ、各生徒が現在持っている箇条書きの数を表します。 2 種類の操作がオンラインで実行されます。 

最初の操作は範囲の更新です: セグメントが与えられた場合$[l, r]$そして値$x$、そのセグメントのすべての生徒が受け取ります$x$追加の弾丸。 重要なのは、これは置き換えではなく増分であり、時間の経過とともに複数の更新が蓄積されることです。 

2 番目の操作は、指定された位置に対するポイント クエリです。$p$、その位置の現在の弾丸の数が少なくとも$x$。 そうである場合、私たちは肯定的に応答し、概念的に学生はすぐに正確に使用します$x$弾丸を使用すると、彼の貯蔵量が減少します$x$。 それ以外の場合は否定的に応答し、状態は変化しません。 

制約$N, Q \le 10^5$範囲の追加とポイント クエリの両方を効率的にサポートする必要があります。 操作ごとにある範囲の値を再計算するソリューションでは、次のような問題が発生します。$O(NQ)$が遅すぎます。 繰り返される範囲更新は操作ごとに線形であるため、単純な配列を維持するだけでは不十分です。 

微妙なエッジケースとして、クエリが成功すると配列が変更されることがあります。 たとえば、学生がまさに$x$箇条書きを使用して 2 回クエリを実行すると、最初のクエリで箇条書きが消費されるため、2 番目のクエリは負の値を返す必要があります。 減分を維持しない単純な「範囲合計のみ」のアプローチでは、黙って過大カウントされてしまいます。 

## アプローチ

 ブルートフォースのアイデアは単純で、配列を明示的に維持します。 アップデートの場合$[l, r, x]$、セグメント内のすべてのインデックスを反復処理し、追加します。$x$。 位置でのクエリの場合$p$、単純に値を確認して減算します。$x$もし可能なら。 

これは正しいですが、更新ごとにコストがかかります$O(r-l+1)$となり、$O(N)$最悪の場合。 と$10^5$操作の合計の複雑さは次のように低下​​します。$10^{10}$、これは実行不可能です。 

重要な点は、配列のすべての要素を明示的に知る必要がないということです。 必要な機能は 2 つだけです。範囲にわたる値の追加と、単一のインデックスのクエリです。 これは、遅延伝播を備えたフェンウィック ツリーまたはセグメント ツリーが適用できる古典的な設定です。 

ただし、さらに単純化することもできます。 ポイントクエリ構造による範囲の追加は、差分配列を使用して処理できます。配列を維持します。$diff$追加する$x$に$[l, r]$翻訳すると$diff[l] += x$そして$diff[r+1] -= x$。 次に、位置の値$p$プレフィックスの合計は次のとおりです$p$。 これにより、範囲の更新が減少します。$O(1)$クエリがプレフィックス合計を指すようにします。 

残る唯一の問題は、クエリが純粋な読み取りではないことです。 クエリが成功したら、減算する必要があります$x$永久に。 これは、基になる配列のポイント更新としてモデル化することもでき、差分配列の 2 つの更新に変換されます。 

したがって、最終的なソリューションでは、差分配列とフェンウィック ツリーを組み合わせて、プレフィックスの合計とポイントの変更を効率的にサポートします。

 ## アルゴリズムのチュートリアル

 弾丸数の差分配列表現に対してフェンウィック ツリーを維持します。 

1. サイズのフェンウィック ツリーを初期化します。$N+1$、最初はすべてゼロです。 これは、実際の値がプレフィックスの合計から導出される差分配列を表します。 
2. アップデートを処理するには$!\ l\ r\ x$、追加します$x$位置にある$l$そして引きます$x$位置にある$r+1$それが範囲内であれば。 This ensures that every prefix sum beyond$l$増分とそれ以降のすべてが含まれます$r$それを取り消します。 
3. 位置で質問に答えるには$p$、プレフィックスの合計を計算します。$p$、その生徒の現在の弾丸数がわかります。 
4. 値が少なくとも$x$、成功を出力し、すぐに減算します$x$位置から$p$。 これはフェンウィック ツリーのポイント更新であり、追加として実装されます。$-x$で$p$そして$+x$で$p+1$。 
5. 値が以下の場合$x$、失敗を出力し、何も変更しません。 

重要な設計上の選択は、範囲更新とポイント変更の両方が同じプリミティブ、つまり差分配列更新の観点から表現され、フェンウィック ツリーが効率的に処理することです。 

### なぜ効果があるのか

 差分配列により、元の配列のすべての要素が接頭辞の合計として表現されるようになります。 範囲の追加は、制御された方法でプレフィックス構造に正確に影響を与えます。つまり、範囲の追加によってステップアップが導入されます。$l$そしてステップダウン$r+1$、したがって、すべてのインデックスは正しい累積値を反映します。 

ポイント減算は対称的に機能し、単一の位置を次のように減らします。$x$これは、そのインデックスに負の単位ステップを導入し、その後それを復元することと同等であり、他のすべての位置の正確性が維持されます。 すべての操作はプレフィックス寄与の線形結合であるため、フェンウィック ツリーの不変条件により、各更新後の一貫性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

n, q = map(int, input().split())
fw = Fenwick(n)

for _ in range(q):
    tmp = input().split()
    if tmp[0] == '?':
        p = int(tmp[1])
        x = int(tmp[2])
        cur = fw.sum(p)
        if cur >= x:
            print("yes sir")
            fw.add(p, -x)
        else:
            print("negative")
    else:
        l = int(tmp[1])
        r = int(tmp[2])
        x = int(tmp[3])
        fw.add(l, x)
        if r + 1 <= n:
            fw.add(r + 1, -x)
```フェンウィック ツリーは、差分配列に対するプレフィックス合計エンジンとして使用されます。 の`add`関数は、範囲更新とポイント削減の両方を、局所的な増分にマッピングすることによって実装します。 

範囲更新の場合、標準的な差分トリックを適用します。つまり、左端で増分し、右端の直後で減分します。 これにより、範囲内のプレフィックス合計が加算値を 1 回だけ反映することが保証されます。 

クエリの場合、位置でプレフィックスの合計を計算します。`p`。 十分な場合は、フェンウィック更新の別のペアを実行して、その時点の値をすぐに減らし、それを長さ 1 の局所的な範囲更新として事実上扱います。 

境界線には注意が必要`r + 1`、フェンウィックのサイズを超えてはなりません。 また、Fenwick の実装と完全に一致するように、すべてのインデックスは 1 から始まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    
    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 2)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i

        def sum(self, i):
            s = 0
            while i > 0:
                s += self.bit[i]
                i -= i & -i
            return s

    n, q = map(int, sys.stdin.readline().split())
    fw = Fenwick(n)

    for _ in range(q):
        tmp = sys.stdin.readline().split()
        if tmp[0] == '?':
            p = int(tmp[1]); x = int(tmp[2])

            l, r, x = map(int, tmp[1:])
            fw.add(l, x)
            if r + 1 <= n:
                fw.add(r + 1, -x)

    return "\n".join(output)

 ## 特殊なケース

 重要なエッジ ケースは、同じ位置でクエリが繰り返し成功する場合です。 1 人の生徒が 5 つの弾丸を受け取り、その後 3 つの弾丸を 2 回要求されたとします。 最初のクエリは成功し、値が 2 に減りますが、2 番目のクエリは失敗します。 フェンウィックベースの実装では、減算が論理的に想定されるだけでなく、ポイントの更新として即座に適用されるため、これが正しく反映されます。 

もう 1 つのエッジ ケースは、最後のインデックスで終了する範囲更新です。 たとえば、$[1, N]$更新を試みてはなりません$N+1$フェンウィックの木の中。 実装では境界チェックによってこれを明示的に保護し、プレフィックス合計の正確性を維持しながら範囲外の更新が発生しないようにします。
