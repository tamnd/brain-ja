 ## 解決策
 ## 問題の理解

 このタスクは、学生のグループがバスの座席をどのように占有するかをシミュレートし、全員が着席するまでに費やした合計時間を累積することです。 バスは N 列のグリッドとして見ることができ、各列には 4 つの固定座席 (窓側の座席が 2 つ、通路側の座席が 2 つ) があります。 学生は文字列で指定された固定順序で 1 人ずつ入場し、各学生は通常通りに振る舞うか、または座席の好みが少し異なる内向的な態度をとります。 

物理的なレイアウトの制約が重要です。学生は常に、できるだけ入り口から離れたところに座ろうとします。 つまり、すべての決定は、最後の列から最初の列に向かってスキャンし、座席条件を満たす最初の列を選択することから始まります。 列が選択されると、正確な座席の種類によって追加の着席時間が決まりますが、列の間を歩くと、列のインデックスに比例して移動時間が決まります。 

N は最大 30、学生の数は最大 120 であるため、行と学生に対する直接シミュレーションは十分に高速です。 O(N·|S|) または O(N²·|S|) であるアプローチは、これらの制限の下では依然として無視できます。 

主な微妙な点は、「内向的な」学生は一般に単に窓側の席を好むわけではないということです。 彼らは、たとえその列の他の位置に通路が空いていたとしても、あるいは近い列の方が全体的な構成が優れていたとしても、窓側の席にまだ空きがある最も遠い列を特に検索します。 窓側の座席がどこにも残っていない場合にのみ、通常の動作に戻ります。 

行の選択を動的に再評価せずに、内向的な人を窓側の席に貪欲に求める人として扱うと、素朴な間違いが生じます。 もう 1 つのよくある失敗は、内向的な生徒が窓側の席に座った後、後続の生徒には同じ列の通路側の席が引き続き有効であることを忘れていることです。これにより、将来の決定が目に見えない形で変わる可能性があります。 

たとえば、2 つの列があり、1 列目に窓側の席が 1 つだけ残っているとします。すべての列が部分的に埋まった後に内向的な人が入場した場合、たとえ 2 列目にまだ通路側の席があったとしても、内向的な人は 1 列目を選択する必要があります。 不用意に実装すると、代わりにどの席でも最も遠い列が選択される可能性があり、これは内向的な人にとっては間違っています。 

## アプローチ

 ブルートフォース シミュレーションは、問題について考える最も直接的な方法です。 私たちは各列の各座席の状態を維持し、各入学生に対して、入り口に向かって最も遠い列からスキャンして、ルールに従って有効な列を見つけます。 一般の学生の場合は、空いている席の最前列を選択し、次に通路側の窓側を選択します。 内向的な人の場合は、まず窓側の席が空いている列を見つけようとします。 何も存在しない場合にのみ、通常のルールに戻ります。 

これは、問題で説明されているプロセスを正確に反映しているため、正しく機能します。 ただし、スケールアップすると非効率になります。各生徒は N 行すべてをスキャンする必要があり、各スキ​​ャンには空席状況の確認が必要になる場合があります。 これにより、およそ O(|S|·N) の操作が発生し、ここではまだ問題ありませんが、構造なしで実装すると、概念的なブルートフォースは簡単に O(|S|·N·seat_checks) に劣化する可能性があります。 

重要な観察は、N が非常に小さく固定されているため、クリーンな状態表現以上の最適化は必要ないということです。 各列は、残りの窓側席と通路側席の単純なカウンターを使用して表すことができます。 これにより、個々の座席を明示的に追跡する必要がなくなり、行選択ロジックが簡素化されます。 

したがって、このソリューションは、列の選択と座席の割り当てについて慎重に定義された優先順位ルールを使用した単純な貪欲なシミュレーションに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N· | S | ) |
 | 最適化された状態のシミュレーション | O(N· | S | ) |

 ## アルゴリズムのチュートリアル

列ごとに 2 つの値 (窓側の席がまだ何席残っているか、通路側の席が何席残っているか) を維持します。 最初は、両方とも各行に 2 です。 

各生徒は順番に処理され、最終的に使用する列と座席の種類に応じて、歩行時間と着席時間の両方が計算されます。 

### ステップ

 1. 行数と生徒の順序を読み取ります。 各列を窓側座席 2 つと通路側座席 2 つで初期化します。 
2. 順番に各生徒について、彼らが普通か内向的かを判断します。 
3. 生徒が内向的な場合は、最も遠い列から最も近い列までスキャンして、窓側の席が少なくとも 1 つある最初の列を見つけます。 そのような列があれば、そこの窓側の席を割り当てます。 それ以外の場合は、通常の学生として扱います。 
4. 生徒が普通の生徒 (または内向的で空いている窓がない生徒) の場合は、最も遠い列から最も近い列までスキャンして、空いている席がある最初の列を見つけます。 
5. 選択した列内で、空いている場合は窓側の席を割り当てます。 それ以外の場合は通路側の席を割り当ててください。 
6. 入口を越えて通過する各行の移動時間を 2 秒として計算します。これは (行インデックス − 1) に比例します。 
7. 着席時間を追加: 窓側の席の場合は 10 秒、通路側の席の場合は 5 秒。 
8. 列の残りの座席数を更新し、合計時間を累積します。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは搭乗規則に記述されている厳密な優先順位を尊重します。 最も遠い列の優先は端からスキャンすることによって適用され、座席タイプの優先は選択した列内でローカルに適用されます。 各決定は現在の状態にのみ依存し、以前の割り当てを再検討する必要がないため、シミュレーションは正確さを維持します。 州の代表は、一度席を獲得すると再利用できないことを保証し、すべての学生が同じ決定論的な選択ルールを独立して適用します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    # each row: [window_left, aisle_left]
    rows = [[2, 2] for _ in range(n)]
    total = 0

    for ch in s:
        chosen_row = -1
        seat_type = None  # 'W' or 'A'

        if ch == 'I':
            # try to find farthest row with a window seat
            for i in range(n - 1, -1, -1):
                if rows[i][0] > 0:
                    chosen_row = i
                    seat_type = 'W'
                    break

            # fallback to normal if no window seats exist
            if chosen_row == -1:
                for i in range(n - 1, -1, -1):
                    if rows[i][0] + rows[i][1] > 0:
                        chosen_row = i
                        if rows[i][0] > 0:
                            seat_type = 'W'
                        else:
                            seat_type = 'A'
                        break

        else:
            # normal student: farthest row with any seat
            for i in range(n - 1, -1, -1):
                if rows[i][0] + rows[i][1] > 0:
                    chosen_row = i
                    if rows[i][0] > 0:
                        seat_type = 'W'
                    else:
                        seat_type = 'A'
                    break

        # update state and time
        if seat_type == 'W':
            rows[chosen_row][0] -= 1
            total += (chosen_row) * 2 + 10
        else:
            rows[chosen_row][1] -= 1
            total += (chosen_row) * 2 + 5

    print(total)

if __name__ == "__main__":
    solve()
```この実装では、行ごとのカウンターのみを使用してバス状態をコンパクトに保ちます。 行の選択は逆スキャンによって行われ、追加のデータ構造を使用せずに「最も遠い行を最初に」ルールを直接エンコードします。 時間の計算では、行インデックスを入り口からの距離として使用します。行 0 は入り口に隣接しているため、歩行コストは次のようになります。`2 * row_index`。 

微妙な点は、内向的な人にとっては後戻りです。窓側の席がどこにも存在しなくなると、彼らの行動は通常の学生と同じになります。 これは、ウィンドウが枯渇しても選択ロジックが壊れないように、明示的に実装されています。 

## 実用的な例

 2 列の小さなバスとそのシーケンスを考えてみましょう。`IE`。

 | 私 | 内向的 | (2,2)、(2,2) | 行 2 | ウィンドウ | 2*1 + 10 = 12 | 12 |

 このトレースは、内向的な人が、たとえ他の席がある場合でも、窓側の席をできるだけ遠い列に予約する様子を示しています。 

ここで考えてみましょう`EII`２列バスで。 

| 学生 | タイプ | | 前の状態 選択された行 | シート | 合計 |

 | E | 通常 | いっぱい | 行 2 | ウィンドウ | 12 |

 これは、内向的な人が以前の選択に固執するのではなく、常に利用可能なウィンドウで最も遠い列から再評価する方法を示しています。

 ## 特殊なケース

 重要なエッジケースの 1 つは、窓側の席がすべてなくなった後に内向的な人が現れる場合です。 そのような状況では、アルゴリズムは窓側の席を割り当てようとせずに、ただちに通常の動作に切り替える必要があります。 たとえば、入力のある 1 列のバスの場合、`WWII`(この抽象化では W を E に相当すると解釈します)、両方の窓側の席が取られると、残りの内向的な人は通路側の席を占有する必要があり、フォールバック ロジックにより、無効な窓側の選択を試行することがなくなります。 

もう 1 つの特殊なケースは、初期の内向型の人が異なる列の窓側の席を部分的に埋める場合です。 選択は常に最も遠い列から行われるため、前の列にすでに混合座席が含まれている場合でも、後の生徒は別の列を好む可能性があります。 状態ベースのスキャンでは、各決定がローカル履歴ではなく現在のグローバル構成を反映することが保証されます。
