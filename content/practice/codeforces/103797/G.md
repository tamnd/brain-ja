 ## 解決策
 ## 問題の理解

 私たちには、学生登録番号の固定セットが与えられており、それぞれが正確に 6 桁で構成されています (先頭のゼロは許可されているため、次のような数字が使用されます)。`000123`は有効であり、とは異なります`123000`）。 この前処理ステップの後、複数のクエリを受け取ります。各クエリは、管理者の要求を表す別の 6 桁の数字です。 

クエリ番号ごとに、桁モジュラー和と呼ばれる特別な桁ごとの演算を最大化する、指定されたセットから 1 つの学生番号を選択する必要があります。 この演算は桁の位置ごとに独立して定義されます。6 つの桁のそれぞれについて、学生番号とクエリ番号の桁を加算し、その結果のモジュロ 10 を取得します。結果として得られる 6 桁は新しい数値を形成し、その値が最大化したいスコアになります。 

したがって、タスクはすべてのクエリについて、辞書編集上最良の (または数値的に最大の) 桁ごとの合計を法 10 で計算した結果を生成する学生番号を見つけることです。 

制約は厳しく、学生番号は 100,000 件まで、クエリは 100,000 件まで、各比較には 6 桁の位置が含まれます。 すべてのクエリに対してすべての生徒をチェックする単純なソリューションでは、最悪の場合でも約 10^10 の比較が実行されますが、これは 1 秒の制限をはるかに超えています。 これにより、O(NQ) アプローチが即座に除外されます。 

微妙だが重要なエッジ ケースは、先頭のゼロから発生します。 数値は長さ 6 の固定幅文字列であるため、数値を整数として扱うと位置の意味が破壊されます。 たとえば、比較すると、`000999`そして`999000`演算は数字単位で行われるため、ここでは数値的には意味がありません。 正しい解決策では、それらを文字列または数字配列として扱う必要があります。 

もう 1 つの重要な例外ケースは、演算が通常の数値的な意味では単調ではないことです。 通常の整数値が大きい生徒番号は、特定のクエリに対して必ずしも大きい桁修飾和の結果を生成するとは限りません。 たとえば、クエリの場合`999999`、ベストマッチは`000000`なぜなら、各桁の合計は 9 になるからです。一方、「大きな」生徒は`123456`次のような桁の合計が得られます`0,1,2,...`、それははるかに悪いです。 

## アプローチ

 ブルート フォース アプローチは簡単です。クエリごとに、すべての生徒番号を反復処理し、6 つの位置すべてについて 10 を法とする桁ごとの合計を計算し、最良の結果を追跡します。 各評価には O(6) のコストがかかるため、合計の複雑さは O(NQ) になります。 両方のディメンションに 100,000 があると、クエリ バッチごとに約 6 億桁の操作となり、全体で数百億に達し、遅すぎます。 

重要な観察は、各桁の位置が寄与の点で独立しているということですが、制約として、結合された桁ベクトルが 6 つの桁すべてで同時に最適になる単一の生徒番号を選択しなければならないということです。 これは古典的な「多次元数値変換」最適化問題です。 

各番号の長さは 6 桁のみであるため、各学生番号を 6 レベルの桁空間内のパスとして扱うことができます。 重要な洞察は、考えられるすべてのクエリ パターンに対して、可能な限り最善の生徒の反応を事前に計算することです。 各桁が入っているので、`[0..9]`理論的には、可能なクエリは 10^6 個だけですが、これは大きすぎて直接保存できません。 ただし、代わりに、数字 DP スタイルのアイデアを活用することができます。つまり、学生番号に対するトライを構築し、数字ごとの伝播を使用して各数字構成の最適な候補を事前計算できます。 

より効率的な観点は、固定のクエリ数字の場合、各生徒の数字が結果の数字に独立して寄与すると考えることです。 したがって、クエリごとに、少数の候補セットにわたってベクトル スコアを最大化する必要があります。これは、「桁ごとのスコアリングでの最良の一致」に効率的に答えることができる構造を維持することを示唆しています。 これを行う実際的な方法は、各位置の考えられるクエリ数字ごとに、最良の学生数字の寄与を事前に計算し、検索をフル スキャンではなく構造化ルックアップに効果的に減らすことです。 

これは、生徒番号のトライを使用して効率的に実装できます。各ノードは、そのサブツリーから到達可能な最良の候補者を集約します。 次に、各クエリは桁ごとに処理され、常に結果の桁合計を最大化する遷移に従い、各クエリを O(N) ではなく O(6 * 10) の探索に効果的に変換します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NQ) | O(N) | 遅すぎる |
 | トライ + 貪欲な数字 DP | O((N + Q) · 6 · 10) | O(N・6) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての生徒番号から数字のトライを構築し、それを使用して、数字ごとの最大化を尊重しながらクエリに貪欲に答えます。 

1. 各生徒番号をトライに挿入します。各レベルは、最上位から最下位までの 1 桁に対応します。 各ノードは、その子への参照と、必要に応じて、到達可能な最適な値に関するメタデータを保存します。 この構造により、すべての候補を桁順にたどることができます。 
2. 各クエリについて、トライのルートから開始して左から右に数字を処理します。 位置 i で、クエリ数字 d を調べ、0 から 9 までの子数字 k へのすべての可能な遷移を評価します。 
3. 各候補数字 k について、結果の数字の寄与を計算します。`(d + k) % 10`。 この値を最大化したいだけでなく、パスがトライ内に存在することも確認したいと考えています。 したがって、有効な子のみを考慮します。 
4. すべての有効な子の中で、最も高い値を生み出す数字 k を選択します。`(d + k) % 10`。 複数の数字が同じ値を生成する場合、辞書編集上最大の残りの接尾辞や保存されている最良の葉など、事前に計算されたルールを使用して関係を解消します。 
5. 選択した子ノードに移動し、結果の学生番号に k を追加します。 
6. 6 桁すべてが処理されるまで繰り返し、桁ごとのモジュラー和を最大化する 1 つの完全な候補学生番号が生成されます。 

### なぜ効果があるのか

 各桁の位置での最終スコアへの寄与は、有効な学生番号を記入する可能性を除いて、将来の桁とは無関係です。 トライは実現可能性を保証し、目的関数はキャリー相互作用なしで桁ごとの制限された寄与の合計として分解されるため、貪欲な選択は有効です。 各桁の位置はグローバルに有効なすべての候補間でローカルに最適化されるため、後の決定によって以前の桁のモジュラー寄与を遡って改善することはできず、トライ制約の下で貪欲な選択がグローバルに最適化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("child",)
    def __init__(self):
        self.child = {}

def insert(root, s):
    node = root
    for ch in s:
        if ch not in node.child:
            node.child[ch] = Node()
        node = node.child[ch]

def best_match(root, q):
    node = root
    res = []
    for ch in q:
        dq = ord(ch) - 48

        best_digit = None
        best_val = -1

        for k in node.child.keys():
            dk = ord(k) - 48
            val = (dq + dk) % 10
            if val > best_val or (val == best_val and k > best_digit):
                best_val = val
                best_digit = k

        res.append(best_digit)
        node = node.child[best_digit]

    return "".join(res)

def main():
    n = int(input())
    root = Node()

    for _ in range(n):
        s = input().strip()
        insert(root, s)

    q = int(input())
    out = []

    for _ in range(q):
        query = input().strip()
        out.append(best_match(root, query))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```trie 構造では、すべての生徒番号を 1 桁ずつ保存します。 各クエリは、トライをたどり、モジュラー合計ルールに従って各レベルでローカルに最適な数字を選択することによって解決されます。 タイブレークにより、複数の候補者が同じ桁のスコアを生成した場合に、出力が確定的に保証されます。 

微妙な実装の詳細は、各ノードで既存の子を反復処理するだけであり、これにより遷移が効率的に保たれます。 もう 1 つは、先頭のゼロと位置の正確さを維持するために、整数ではなく文字列の数字に依存していることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 重要なエッジケースは、先行ゼロを正しく処理することです。 たとえば、学生が次のような場合`000999`、これを整数 999 として扱うと、桁が正しく整列されず、トライ構造が壊れます。 アルゴリズムは生の文字を保存するため、パスは`0 → 0 → 0 → 9 → 9 → 9`は正確に保持され、クエリは歪みなく数字方向に整列します。 

もう 1 つのエッジ ケースは、複数の桁が同じモジュラー和を生成する場合のタイブレークです。 たとえば、クエリ桁が 5 の場合、学生の桁 5 と 15 mod 10 の両方に相当することは不可能ですが、桁 5 と 15 は存在しないため、有効な桁間の関係を一貫して解決する必要があります。 トライは、値が等しい場合に大きい数字キーを優先することにより、決定的な選択を保証します。 

最後に、すべての生徒がプレフィックスを共有すると、トライ パスは初期の桁については直線になります。 アルゴリズムは、分岐が現れるまで分岐せずに正しく続行され、探索中に候補が人為的に失われることはありません。
