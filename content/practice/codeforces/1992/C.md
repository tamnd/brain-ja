 ## 解決策
 ## 問題の理解

 1 から 1 までの数値の順列を作成するように求められます。$n$特定の表現が最大化されるように。 式は、「大きな」数値 (以上) のすべての接頭辞の合計の合計です。$k$) 「小さい」数値 (以下の) のすべての接頭辞の合計の合計を引いたもの$m$）。 順列には 1 から 1 までの各数字が含まれている必要があります。$n$まさに一度。 

各テスト ケースの入力は 3 つの整数です。$n$(順列の長さ)、$m$(小さい数値のしきい値)、および$k$(大きな数値のしきい値)。 出力は 1 ～ の任意の順列です。$n$これは、すべてのプレフィックスにわたる大きな数値と小さな数値の累積合計の差を最大化します。 

主な制約は次のとおりです。$n$まで可能です$10^5$、との合計$n$すべてのテストケースにわたって、$2 \cdot 10^5$。 これは、$O(n \log n)$または$O(n)$解決策は受け入れられますが、$O(n^2)$解決策が遅すぎるでしょう。 

明らかではない点は、数値が厳密に次のとおりであるということです。$m+1$そして$k-1$どちらの合計にも寄与しないため、それらの位置はスコアとは無関係です。 もう 1 つの微妙な点は、小さい数値を早く入れるとペナルティ (g(i) 寄与) が増加するのに対し、大きい数値を早く入れると報酬 (f(i) 寄与) が最大化されることです。 

たとえば、$n=5$、$m=2$、$k=5$、1 つの順列 [5,3,4,1,2] が生成されます。$f(i)$そして$g(i)$最大の差を与える値。 [1,2,3,4,5] のような単純な順列では、小さな数値が大きな数値の前に表示され、ペナルティが増加するため、差は小さくなります。 

## アプローチ

 ブルートフォースアプローチは、すべてを試すことです$n!$順列、計算$f(i)$そして$g(i)$それぞれを選択し、最大値を選択します。 これは、あらゆる順列の合計を正しく計算するため、理論的には機能しますが、中程度の場合でも実行不可能です。$n$、 以来$5! = 120$そして$10! \sim 3.6 \cdot 10^6$、最大値を大幅に下回ります$n = 10^5$。 

重要な洞察は、最終的な合計に対する各数値の寄与が、その数値が含まれるプレフィックスの数に線形であるということです。 f(i) 寄与の合計を最大化するには、すべての数値を次の値以上に配置する必要があります。$k$できるだけ早く。 g(i) の寄与の合計を最小化するには、すべての数値を以下に配置する必要があります。$m$できるだけ遅くまで。 間の数字$m+1$そして$k-1$スコアに影響を与えないため、どこにでも配置できます。 

したがって、最適な順列は、最初に k ≧ の数値を降順でリストし、次に中央の数値を任意の順序でリストし、m 未満の数値で昇順で終わることによって構築されます。 これにより、最大の数値ができるだけ多くのプレフィックスで f(i) に寄与し、最小の数値ができるだけ少ないプレフィックスで g(i) に寄与することが保証されます。

 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、次の内容を読んでください。$n$、$m$、 そして$k$。 
3. 3 つのリストを初期化します。`large`数値 ≥ k の場合、`middle`(m, k) の数値の場合、および`small`数値 ≤ m の場合。 
4. 1 から n までのすべての数値を繰り返します。 

- 数値≧ k の場合、それを追加します。`large`。 
- 数値 ≤ m の場合、それを追加します。`small`。 
- それ以外の場合は、以下に追加します`middle`。 
5. 連結して順列を構築します。`large`降順で、`middle`任意の順序 (簡単にするために昇順)、および`small`昇順で。 
6. 順列を出力します。 

機能する理由: k 以降のすべての数値を先頭に置くと、その数値を含むすべてのプレフィックスへの寄与が最大化されます。 数値 ≤ m を最後に置くと、その寄与が最小限に抑えられます。 m から k までの数値はスコアに影響しないため、順序は重要ではありません。 この戦略により、どの順列もより大きな差を達成できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m, k = map(int, input().split())
    large = []
    middle = []
    small = []
    for i in range(1, n + 1):
        if i >= k:
            large.append(i)
        elif i <= m:
            small.append(i)
        else:
            middle.append(i)
    permutation = large + middle + small
    print(*permutation)
```このソリューションは、次を使用して入力をすばやく読み取ります。`sys.stdin.readline`、数値を 3 つのカテゴリに分割し、それらを連結してスコアを最大化します。 リスト演算を使用すると、off-by-one エラーが回避され、出力が有効な順列になることが保証されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        large, middle, small = [], [], []
        for i in range(1, n + 1):
            if i >= k:
                large.append(i)
            elif i <= m:
                small.append(i)
            else:
                middle.append(i)
        print(*large, *middle, *small)
    return out.getvalue().strip()

## 特殊なケース

 トリッキーなエッジケースは次のような場合です`m+1 = k-1`、中間の数字が 1 つだけあることを意味します。 のために`n=5, m=2, k=4`、数字は`[1,2,3,4,5]`。 私たちのアルゴリズムの場所`[4,5]`(大) まず、それから`[3]`(中)、そして`[1,2]`（小）最後。 結果として得られる順列`[4,5,3,1,2]`早期に最大の f(i) 寄与を保証し、後期に最小の g(i) 寄与を保証し、シングルトンの中間数を正しく処理します。 これは、中間セグメントに要素が 1 つしかない場合でもアルゴリズムが機能することを示しています。
