 ## 問題の理解

 私たちに与えられた川は、直線的な板のように振る舞います。`n`細胞。 各セルは、丸太の形をした安全な地面、危険な水、または即時に失敗するワニのタイルのいずれかです。 目標は、最初のセルの前の左岸から最後のセルの後の右岸に移動することです。 

動きは 2 つの独立した方法で制限されます。 ErnKor が安全な面、つまり土手または丸太に立っているとき、彼は最大で前方ジャンプをすることができます。`m`細胞。 彼が水の中にいるとき、動きははるかに遅くなります。彼は泳いで一度に 1 つのセルしか進むことができず、消費される水のすべてのセルが世界的な制限に寄与します。`k`。 ワニの房はいかなる状況においても着陸位置として禁止されています。 

最大の難点は、丸太の上にいるか水中にいるかによって状態が変わることです。 丸太は、走り幅跳びが「モード」をリセットする安全なチェックポイントとして機能しますが、水のセグメントは泳ぐ距離の点で直線的なコストを課します。 私たちは、ワニを踏むことなく、また限界を超えずに向こう岸に到達する有効なジャンプと水泳の順序が存在するかどうかを判断しなければなりません。`k`通過した水のセルの総数。 

この制約は、テスト ケースごとに線形または線形に近い解決策が必要であることを示唆しています。 合計`n`すべてのテスト ケースで最大でも`2·10^5`なので、それ以上のアルゴリズムは`O(n log n)`全体として、遅すぎるリスクがあります。 以来`m ≤ 10`、大規模な動的構造を維持するのではなく、ジャンプ到達可能性をローカルに扱うことが推奨されます。 

貪欲なジャンプが水のセグメントとジャンプの機会の間の相互作用を無視した場合、微妙な失敗のケースが発生します。 たとえば、到達可能な最も遠くの安全なセルに常にジャンプする戦略は、私たちを長い水の回廊に閉じ込めてしまう可能性があります。`k`たとえ、ジャンプシーケンスをわずかに短くすれば、水をより小さなセグメントに安全に分割できたであろうが。 

もう 1 つの特殊なケースは、丸太の間に長く途切れることのない水域がある場合に発生します。 たとえ丸太が存在するとしても、それらの間の水を必要とする場合があります。`k`中間ジャンプなしで横断する必要がある場合は、水泳ステップを実行します。 これが問題の中心となるバランス調整です。 

## アプローチ

 ブルートフォースアプローチでは、各表面位置で可能なすべての選択を明示的にシミュレートします。 各ログまたはバンクの位置から、すべてのジャンプ距離を試すことができます。`1`に`m`、プロセスを再帰的に継続し、水に着水すると、次の表面に到達するまで強制的なシングルステップ水泳をシミュレートします。 これにより、位置と現在泳いでいるのか立っているのかによって定義される状態の検索が形成されます。 

これはすべての有効なパスを探索するため正しく機能しますが、組み合わせ的に爆発します。 各表面セルは最大で分岐します。`m`ジャンプや水のセグメントでは長時間の強制トランジションが導入されます。 最悪の場合、特に川の大部分が丸太で水が頻繁に入れ替わる場合、これは丸太の数が増えるにつれて指数関数的な挙動に陥ります。 

重要な観察は、丸太が問題をセグメントに分割しており、各セグメント内で必要なのは、そのセグメントを越えられるかどうかと、それがどれだけの水コストに寄与するかを知ることだけであるということです。 ジャンプには限界があるので、`m ≤ 10`あらゆる丸太から、すべての可能性を考慮する必要はなく、次に到達可能ないくつかの丸太または水の侵入点を考慮するだけで済みます。 

このプロセスを貪欲な到達可能性スイープとしてモデル化できます。 左岸からスタートして、ジャンプ範囲内で一番遠くまで到達できる位置を目指します`m`、ワニを尊重しながら。 水に着水すると、丸太か堤防にぶつかるまで確実に前に泳ぎ続け、水のコストが蓄積されます。 これにより、問題は、水の消費量を追跡しながら、到達可能な最も遠い「地表フロンティア」を維持することに変わります。 

中心的な考え方は、ワニを避けるか、水への露出を減らすことがない限り、中間ジャンプは厳密に支配されるため、私たちが地表にいるときは常に、最も遠くに到達できる次の地表のみが重要であるということです。 以来`m`小さいです、までチェックしています`m`前のポジションで十分です。

 ## アルゴリズムのチュートリアル

 現在の位置と残りの許容水域距離という 2 つの状態を維持しながら、左から右への移動をシミュレートします。 

1. 位置から開始`0`(左岸)あり`k`残りの遊泳可能距離の単位。 バンクは安全な路面なので、ジャンプ モードで開始します。 
2. 任意の表面位置から`i`、最も遠い有効な位置にジャンプしようとします。`j`そのような`1 ≤ j - i ≤ m`そして`a[j]`ワニではありません。 ジャンプを短くしても到達可能性が向上したり、水のコストが削減されたりすることはないため、そのようなすべての候補の中で、最も遠くに到達可能な有効な着地点を優先します。 
3. 範囲内に有効な着地面が存在しない場合は、代わりに、最も近い可能な非クロコダイル水セルにジャンプします。 これは、意図的に水に入る唯一のケースです。そうでない場合は、常に丸太か堤防を好むからです。 
4.所定の位置に水に入ったら`i`、私たちは一度に一歩ずつ確実に前進する必要があります。 ステップごとに、デクリメントします`k`ワニにぶつかったかどうかを確認します。 ワニにぶつかった場合、そのパスは無効になります。 もし`k`ネガティブになってしまうと失敗もしてしまいます。 
5. 泳ぎながら、丸太か右岸に到達するまで泳ぎ続けます。 丸太に到達した瞬間にサーフェス モードに戻り、ジャンプ プロセスを繰り返します。 
6. いずれかの時点で位置に到達した場合`n+1`、右岸、承ります。 

### なぜ効果があるのか

 正しさは、表面上の位置が意思決定を圧迫するという事実に基づいています。 地上セルからは、到達可能な最も遠くのセル内にのみ安全に着陸できます。`m`追加のオプションを提供しないと、途中で着陸すると残りの到達距離が減少するか、後で水への露出が増加するため、重要です。 水セグメントは分岐のない強制的なパスであるため、その寄与は純粋に加算的であり、どのようにしてその入口点に到達したかとは無関係です。 この分離により、水のコストを決定的に考慮しながら、表面の進歩を貪欲に最大化することができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = input().strip()
        
        pos = 0
        water_left = k
        
        # we treat bank at n+1 as implicit safe 'L'
        while True:
            if pos == n + 1:
                print("YES")
                break
            
            # surface: try jump up to m
            nxt = -1
            
            # try farthest valid landing (log or bank)
            for jump in range(1, m + 1):
                np = pos + jump
                if np == n + 1:
                    nxt = np
                elif np <= n and a[np - 1] != 'C':
                    nxt = np
            
            if nxt == -1:
                print("NO")
                break
            
            # if landing is bank, finish
            if nxt == n + 1:
                print("YES")
                break
            
            # if landing is log, move there
            if a[nxt - 1] == 'L':
                pos = nxt
                continue
            
            # otherwise must be water start -> swim
            pos = nxt
            while pos <= n and a[pos - 1] == 'W':
                water_left -= 1
                if water_left < 0:
                    print("NO")
                    break
                pos += 1
            else:
                continue
            break

水セルが選択されると、内側のループは減分しながら水の中の強制的な動きをシミュレートします。`water_left`。 の`while-else`この構造により、内側の水泳に失敗しなかった場合にのみ外側のプロセスを続行できるようになります。

    def solve():
        t = int(input())

            a = input().strip()

                    if water < 0:

                        break
                    pos += 1

                    break

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 主なエッジ ケースは、丸太までの短いジャンプが存在するにもかかわらず、最適なパスで意図的に水に入る必要がある場合です。 このような場合、常にログを優先する単純な貪欲な戦略は失敗する可能性があります。 シミュレーションは、ジャンプ範囲内の丸太のみを優先し、安全な水面が存在しない場合にのみ水に進入するため、これを正しく処理します。 

別の微妙なケースが発生する場合`k = 0`。 ここでは、強制的な水泳は即座に失敗します。 すべての水の遷移が明示的に減少するため、アルゴリズムは引き続き機能します。`water_left`、最初の減少は拒否をトリガーし、水の通過が許可されないという要件と一致します。 

最後に、ワニの長い伸びが国内のすべての着陸オプションをブロックしたとき、`m`、スキャンは正しく生成します`nxt = -1`、無効なスイムを試行することなく即時終了が保証されます。
