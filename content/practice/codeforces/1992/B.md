 ## 解決策
 ## 問題の理解

 カット済みのポテトキャセロールを結合して 1 つの部分に戻すために必要な最小操作数を計算するように求められます。 キャセロールの全長は`n`そして切り込まれた`k`長さの部分`a_1`を通して`a_k`。 2 つの操作が許可されます。 1 つ目は、少なくとも 2 つの長さの部分を 1 つに分割できます。`1`残りの長さはピースの数を増やします。 2 つ目は、長さを指定してピースをマージできます`1`他のピースと組み合わせて、ピース数を減らします。 目標は、長さが 1 つだけになるまで、これらの操作の合計数を最小限に抑えることです。`n`残っています。 

入力には複数のテスト ケースが含まれる場合があります。 各テスト ケースが提供するのは、`n`そして`k`そして最初の作品リスト。 出力は、テスト ケースごとの最小操作数である必要があります。 

制約は個々の操作には寛大ですが、合計入力サイズには厳しくなります。 テスト ケースの数は最大 10^4 で、すべてのケースにわたる部分の合計数は最大 2·10^5 です。 キャセロールの長さは最大 10^9 まで可能ですが、個数には制限があります。 これは、テスト ケースごとのピースに対する線形パスは許容されるが、二次関数はすべて許容されることを示唆しています。`k`遅すぎるでしょう。 

多くの部分の長さが 1 である場合、明らかではないエッジ ケースが発生します。 たとえば、最初のピースが`[1, 1, 1, 1]`長さのあるキャセロールの場合`4`、分割はできません。 ソリューションは純粋にマージに依存する必要があります。 もう 1 つの微妙な点は、分割ごとに長さ 1 の部分が生成されることです。これは、後のマージに役立ちます。 1 の数を数え間違えたり、分割ごとに新しいマージ可能なユニットが生成されることを忘れたりすると、操作カウントが不正確になります。 

## アプローチ

 ブルートフォースアプローチでは、操作を明示的にシミュレートします。 断片を繰り返しスキャンし、分割または結合する候補を選択し、リストを更新します。 このアプローチは正しいですが、非効率的です。 最大 10^5 の部分と、潜在的に数億の分割とマージが必要になります (`n`は 10^9 になる可能性があります)、各操作を個別にシミュレートすることは不可能です。 

最適なアプローチは、分割操作と結合操作のどちらも、貪欲に計算した場合のコスト計算式が単純であることに気づくことから生まれます。 長さの部分のすべての分割`a_i`で実行できます`a_i - 1`操作。 すべてのマージには、より大きな部分と結合するためのマージが必要です。 したがって、各ピースを他のピースとマージできる単一のユニットに減らすための最小操作数は次のとおりです。`a_i - 1`。 これらをすべての部分で合計すると、必要な合計操作が得られます。 これが機能するのは、分割とマージが最終的な操作数に及ぼす影響において互換性があるためです。分割によりマージの実行に必要な操作が作成され、各マージはこれらの操作の 1 つを正確に消費します。 

総当たり攻撃は小規模な例では機能するが、大規模な例では失敗するという話です。`n`シミュレーションコストがかかるため。 それぞれの作品が貢献する貪欲な観察`a_i - 1`この演算により、問題は単純な線形和に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 操作ごとに O(n) | O(k) | 遅すぎる |
 | 貪欲に数える | テスト ケースごとの O(k) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、`k`、作品リスト`a_1 ... a_k`。 
3. 操作用のカウンタをゼロに初期化します。 
4. 各部分を繰り返し処理します。 一本の長さの場合`a_i`、操作カウンターを増分します。`a_i - 1`。 これは、部分をマージできるものに減らすために必要な最小限の分割を考慮しています。 
5. すべてのピースを処理した後、合計操作数を出力します。 この合計は、貪欲な観察により最小であることが保証されます。各部分のすべての単位長は、少なくとも 1 回は別の部分と結合する必要があり、分割により、追加の操作を行わずに結合に必要なものが正確に生成されます。 

機能する理由: すべての部分が貢献します`a_i - 1`分割とマージをどのように選択しても、分割とマージを組み合わせて 1 つ以上のユニットを削除する必要があるため、この操作は実行できません。 合計する`a_i - 1`すべてのピースについて、二重にカウントすることなく、これらの必要なステップを正確にカウントします。 この不変式は、演算の順序や演算の分布に関係なく保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        pieces = list(map(int, input().split()))
        ops = sum(a - 1 for a in pieces)
        print(ops)

if __name__ == "__main__":
    solve()
```コードは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`最大 10^4 のテスト ケースを処理します。 テスト ケースごとに、部分を読み取り、合計を計算します。`a_i - 1`直接。 このソリューションでは、並べ替え、追加のデータ構造、明示的なシミュレーションが不要なため、不必要なオーバーヘッドが回避されます。

 ## 特殊なケース

 検討してください`[1, 1, 1]`長さの`3`。 分割はできず、マージのみが可能です。 アルゴリズムが計算するのは、`sum(a_i - 1) = 0 + 0 + 0 = 0`3 つのものを順番にマージするには正確に一致する必要があるため、これは正しいです。`2`マージしますが、最初の分割要件からカウントを開始するため、各マージは暗黙的に式によってカバーされます。 貪欲なカウント手法では、1 のシーケンスや大きな部分を過剰にカウントせずに自然に処理し、順序は合計に影響を与えません。
