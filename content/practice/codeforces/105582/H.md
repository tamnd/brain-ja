 ## 解決策
 ## 問題の理解

 友達のグループがいくつかあるのですが、グループごとに、そのグループの中でできるだけ多くの人が幸せになれるカフェを選びたいと考えています。 

各人には、短い文字列としてエンコードされた小さな要素セットによって記述される好みがあります。 ハンバーガーは材料のセットによっても表現されます。 人はハンバーガーに自分の好きな具材がすべて入っていれば満足します。 ハンバーガーの少なくとも 1 つがその人を満足させれば、そのカフェはその人にとって良いカフェであるとみなされます。 

各グループの課題は、そのグループ内の満足者の数を最大化するカフェを 1 つ選択することです。 複数のカフェが同じ最大値を達成した場合、インデックスが最も小さいカフェが選択されます。 

ここでの重要な構造は、各好みと各バーガーが最大 6 つの異なる文字を使用するため、アルファベットが 26 文字あるにもかかわらず、各セットは非常に小さいということです。 これは、6 要素セットのサブセットの総数が 64 のみであるため、サブセットとビットマスク推論が効率的であることを直ちに示唆しています。 

主な困難は、すべてのグループをすべてのカフェと比較することですが、両方とも最大 1,000 人になる可能性があるのに対し、人とバーガーの合計数は 50,000 に達する可能性があります。各カフェ内の人とバーガーの間の単純な全ペアのマッチングでは、あまりにも時間がかかりすぎます。 

カフェにある複数のハンバーガーが部分的に人の好みと一致するものの、完全に一致するものがない場合、微妙なエッジケースが発生します。 たとえば、ある人が好きだったら、`{a, b}`そしてカフェにはハンバーガーがあります`{a}`そして`{b}`、その人は満足していません。 部分的な重複ではなく、完全な封じ込めのみが重要です。 

もう 1 つの特殊なケースは、カフェにグループの誰もが満足できるハンバーガーがない場合です。 そのカフェはまだ検討する必要があり、すべてのカフェのパフォーマンスが同様に悪い場合に選択される可能性があります。これは、依然として同点の最小のインデックスを選択しているためです。 

## アプローチ

 問題を解決する直接的な方法は、文字通りすべてをシミュレートすることです。 各グループと各カフェについて、すべての人を反復処理し、次にそのカフェのすべてのハンバーガーを反復処理して、ハンバーガーにその人の必要な材料がすべて含まれているかどうかを確認します。 これは定義を正確に反映しているため、これは正しいです。 ただし、その複雑さはグループ、カフェ、人々、ハンバーガーの産物となり、制約を考慮するとあまりにも大きすぎます。 

重要な観察は、それぞれのハンバーガーとそれぞれの好みが最大 6 つの異なる文字のセットであるということです。 サブセットの関係を繰り返しチェックする代わりに、逆方向を事前に計算することができます。つまり、特定のハンバーガーについて、その材料セットの考えられるすべてのサブセットを列挙できます。 そのようなすべてのサブセットは、そのハンバーガーで満足する人に対応します。 ハンバーガーには最大 6 つの材料が含まれるため、この拡張では最大 64 のサブセットが作成されます。 

これにより、各カフェが、満たすことができるすべてのプリファレンス セットの事前計算されたセットに変換されます。 これができれば、人物のチェックは簡単なメンバーシップテストになります。 次に、すべての人々をスキャンし、カフェの事前計算セットに含まれる好みのマスクの数を数えることによって、各カフェを評価します。 

この改善は、繰り返されるサブセット チェックをバーガーごとの小さな定数拡張とその後の高速ハッシュ ルックアップに置き換えることによってもたらされます。

 ## アルゴリズムのチュートリアル

 1. すべての成分文字列を 26 文字以上のビットマスクに変換します。 各文字はビット位置に対応します。 これにより、サブセット チェックをビット操作にすることができます。 
2. カフェごとに、誰かを間接的に満足させることができるハンバーガーの全成分マスクのセットを作成します。 すべてのバーガー マスクについて、そのマスクのすべてのサブセットを生成し、カフェのセットに挿入します。 これが機能するのは、そのハンバーガーで満足する人は、これらのサブセットのいずれかに等しい好みを持っているはずだからです。 
3. 前処理の後、各カフェには、少なくとも 1 つのハンバーガーによって満たされるすべての好みマスクの完全な表現が含まれています。 
4. 各グループについて、その人々の間で同一の好みマスクの頻度を数えます。 これにより、同じ設定を何度も繰り返しスキャンすることが回避されます。 
5. カフェごとに、グループ内のすべての個別の好みマスクを反復処理し、そのマスクがカフェの事前計算セットに存在するかどうかを確認することにより、グループ内の何人が満足しているかを計算します。 周波数を掛けます。 
6. 各グループの最大スコアを持つカフェを追跡し、最小のインデックスを選択して同点を破ります。 

### なぜ効果があるのか

 すべての人は、材料セットが自分の好みセットのスーパーセットであるハンバーガーが少なくとも 1 つ存在する場合にのみ満足します。 各バーガーのすべてのサブセットを列挙すると、そのバーガーが満たすことができるすべての可能な嗜好セットが正確に取得されます。 カフェ内のすべてのハンバーガーの和集合を取得すると、この等価性が維持されるため、最終セットのメンバーシップは論理的に元の満足条件と同一になります。 各グループのスコアは独立した人々の合計にすぎないため、頻度に基づいてカウントすると、基礎となる組み合わせ構造を変更することなく正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mask_of(s):
    m = 0
    for ch in s.strip():
        m |= 1 << (ord(ch) - 97)
    return m

def all_submasks(mask):
    # generate all subsets of up to 26-bit mask, but actual size <= 6 bits
    bits = []
    for i in range(26):
        if mask & (1 << i):
            bits.append(i)
    res = []
    k = len(bits)
    for sub in range(1 << k):
        m = 0
        for j in range(k):
            if sub & (1 << j):
                m |= 1 << bits[j]
        res.append(m)
    return res

n = int(input())
groups = []

for _ in range(n):
    k = int(input())
    freq = {}
    for _ in range(k):
        m = mask_of(input())
        freq[m] = freq.get(m, 0) + 1
    groups.append((k, freq))

m = int(input())
cafes = []

for _ in range(m):
    l = int(input())
    s = set()
    for _ in range(l):
        bm = mask_of(input())
        for sm in all_submasks(bm):
            s.add(sm)
    cafes.append(s)

for _, freq in groups:
    best_cafe = 1
    best_score = -1

    for idx, cafe_set in enumerate(cafes, start=1):
        score = 0
        for pm, cnt in freq.items():
            if pm in cafe_set:
                score += cnt

        if score > best_score or (score == best_score and idx < best_cafe):
            best_score = score
            best_cafe = idx

    print(best_cafe)
```実装は、すべての成分文字列をビットマスクとしてエンコードすることから始まります。 これにより、サブセット関係が安価になり、文字列操作が完全に回避されます。 サブマスクを生成するヘルパー関数は、ハンバーガーのアクティブなビットのすべてのサブセットを列挙します。これは、文字列ごとの個別の材料の数が最大 6 であるため安全です。 

各カフェは、満足できるすべての設定マスクを含むハッシュ セットを構築します。 このセットは重要な高速化構造であり、繰り返されるサブセット チェックを O(1) メンバーシップ テストに置き換えます。 

グループごとに、周波数マップを使用して同一の好みを圧縮します。 グループには繰り返しの設定文字列が含まれる可能性があり、それらを個別に扱うと同じ作業を不必要に繰り返すことになるため、これは重要です。 最後のスコアリング ステップでは、各カフェのセット内の各固有のマスクのメンバーシップを単純にチェックし、その頻度を乗算します。 

タイブレークは、スキャン中に最大スコアを達成する最小のインデックスを追跡することによって処理されます。

カフェ2については、`{b}`生成する`{}`、`{b}`。 の拡大`{ac}`生成する`{}`、`{a}`、`{c}`、`{ac}`。 カフェ2なら満足できる`{a}`そして`{b}`そしてスコアは3です。 

| カフェ |`{a}`|`{ab}`|`{b}`| スコア |

次に、すべての人が同じ好みを持っているグループを考えてみましょう。`{a}`そしてカフェにはハンバーガーがあります`{b}`、`{c}`のみ。 そのサブセットクロージャには何も含まれていません`{a}`、したがってスコアはゼロのままであり、これは定義と一致しています。

 ## 特殊なケース

 どのカフェにも所定の材料セットを含むハンバーガーがない場合でも、すべてのカフェのスコアが 0 で最小のインデックスが選択されるため、有効な答えが得られます。 たとえば、すべての人が好きであれば、`{a}`しかし、すべてのハンバーガーには次のものしか含まれていません`{b}`、どのカフェにも空の満足セットがあり、答えはカフェ 1 です。 

もう 1 つのケースは、ハンバーガーにちょうど 6 つの材料が含まれている場合です。 その場合でも、サブセットの拡張は 64 要素に制限されたままであるため、前処理のコストが爆発的に増加することはありません。 アルゴリズムはこれを小さなハンバーガーと同じように扱い、極端な場合でも一貫した動作を保証します。 

グループ内で繰り返される好みは、スコアリングの前に頻度マップに集約されるため、正確さに影響しません。 これにより、冗長な反復による二重カウントが防止されます。
