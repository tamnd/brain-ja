 ## 解決策
 ## 問題の理解

 惑星の有向完全なグラフが与えられます。このグラフでは、順序付けされた惑星のペアごとにハイパージャンプが利用できる場合と、そうでない場合があります。 惑星 i から惑星 j へのジャンプの存在は、隣接行列内の文字によってエンコードされ、各文字は少数のジャンプ タイプの 1 つに対応します。 各ジャンプ タイプは 4 つのパラメータによって定義され、移動時間はジャンプを開始するタイミングによって異なります。 

重要な問題は、惑星に到着したときにすぐにジャンプする必要がないことです。 次のジャンプを開始するまで、任意の整数時間待機できます。 タイプ i のジャンプを時刻 s で開始すると、期間は固定されず、((a s + b) mod c) + d として計算されるため、開始時刻とモジュロ相互作用の両方が移動時間に影響します。 

タスクは、初期時間 s に惑星 1​​ から開始し、中間の惑星で任意に待機できるように、可能な限り最小限の時間で惑星 n に到達することです。 

n が 2000 まで、m が 50 までという制約は、O(n^2) グラフの走査が許容されることをすぐに示唆していますが、エッジごとに高価な遷移を繰り返し再計算するものは、注意せずに遅くなりすぎる危険があります。 2000 までの ci によって制限されたモジュロ演算の存在は、エッジごとの事前計算または制限された検索が可能であることを示す主な構造上のヒントです。 

エッジを固定の重みを持つものとして扱う素朴な最短経路アプローチは失敗します。待機するとすべてのエッジの実効重みが非線形に変化するためです。 さらに微妙な問題は、最適な決定は「すぐにエッジを取る」または「ヒューリスティックな時間まで待つ」ではなく、開始時間を法 ci で調整することに依存することです。 

いくつかの失敗例がその難しさを示しています。 

いつも到着したらすぐにジャンプをすると、待っていることで開始時間がより有利な残留クラスにシフトされる、厳密に有利なスケジュールを逃す可能性があります。 逆に、ci の倍数まで待機することのみを考慮すると、最適なアライメントが任意の残基で発生する可能性があるため、最適な解を逃す可能性があります。 

もう 1 つの微妙なケースは、線形項 a s により ci よりも長く待機することが有益であるように見える場合に発生しますが、実際には、フル サイクルを超えて待機時間が長くても、モジュロ部分は改善されず、合計時間が増加するだけであるため、固定エッジの最適な開始時間は常に、到着時間に対して制限されたウィンドウ内に収まります。 

## アプローチ

 直接モデリングでは、各状態を (惑星、現在時刻) のペアとして扱い、遷移には待機とジャンプの両方が含まれます。 これにより、無限状態グラフが生成されます。 時間をある限界まで離散化したとしても、到着時間は入力サイズによって有効に制限されないため、可能な時間の範囲は大きすぎます。 

正しい観点は、グラフを惑星上にのみ保持しますが、エッジ緩和を再定義することです。時刻 t に惑星にいるとき、エッジを取る前に最適な待機時間を選択することによって、隣接する惑星への可能な限り最良の到着時間を計算します。 

パラメーター a、b、c、d、および現在時刻 t を持つ固定エッジ タイプの場合、s + ((as + b) mod c) を最小化する開始時刻 s ≥ t を選択する必要があります。 定数 d と t の減算は、最小化中に無視できます。 

重要な構造的観察は、モジュロ項は c を法とする s のみに依存するのに対し、線形項は s とともに増加するということです。 任意の固定剰余 r について、s ≡ r mod c となる最小の s ≥ t が最良の選択です。 同じ剰余でより大きな選択をしても、モジュロ部分を変更せずにコストが c の倍数だけ増加するだけなので、厳密にはさらに悪くなります。 

これにより、エッジごとの最適化が最大 c 個の候補開始時間 (各剰余クラスの最初の有効時間) をチェックするだけになります。 

これにより、各緩和が残基に対する有界スキャンに変わります。これは、ci ≤ 2000 および m ≤ 50 であるため実現可能です。

次に、惑星上でダイクストラを実行し、各緩和によって各出力エッジ タイプを通じて達成可能な最良の到着時間を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 時間の経過に伴う状態グラフ | O(無限) | O(無限) | 不可能 |
 | 時間軸に沿ったエッジごとのブルート シミュレーション | O(n・m・T) | O(nT) | 遅すぎる |
 | エッジごとの残差スキャン + ダイクストラ | O(n^2 + n · m · c) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 dist[v] が惑星 v への既知の最も早い到着時刻である距離配列を維持します。ダイクストラとまったく同じですが、非標準のエッジ緩和を伴う優先キューを使用して、現在の最良の到着時刻の昇順で惑星を処理します。 

1. dist[1] を開始時間 s に初期化し、他のすべての dist 値を無限大に初期化します。 (s, 1) を最小ヒープにプッシュします。 これは、時間 s に遅延なく惑星 1 にいることを表します。 
2. 最小時間 t の状態 (t, u) をヒープからポップします。 この値が dist[u] と比べて古い場合は、無視してください。 これにより、最適な既知の到着のみを展開することが保証されます。 
3. u から v へのジャンプがあるすべての惑星 v について、対応するジャンプ タイプとそのパラメータ a、b、c、d を特定します。 これにより、このエッジの時間依存のコスト関数が得られます。 
4. 現在時刻 t から開始して、u から v までの可能な最良の到着時間を計算します。 0 から c − 1 までの各剰余 r について、s ≡ r mod c となる最も早い時刻 s ≥ t を計算します。 次に、コスト = s + ((a s + b) mod c) + d を評価します。 すべての残基の最小値を維持します。 このステップは、無限の時間をスキャンせずにすべての意味のある開始時間を調査するため、最適化の中核となります。 
5. 計算された到着時間が dist[v] を改善する場合、それを更新し、(dist[v], v) をヒープにプッシュします。 
6. ヒープが空になるまで続行します。 答えは dist[n]、または到達しなかった場合は -1 です。 

### なぜ効果があるのか

 時間 t における任意の惑星 u において、特定のエッジを取るための有効な戦略は、開始時間 s ≥ t を選択する必要があります。 このようなすべての s の中で、そのエッジに最適な s は常に、与えられた剰余 c を法とする最小の s です。これは、s を c ずつ増やすと、モジュロ式は変更されずに合計時間が正確に c だけ増加するためです。 したがって、すべての最適な選択は、残基クラスごとに 1 つの代表をチェックすることによって取得されます。 ダイクストラは常に既知の最小到着時間を最初に最終決定するため、ノードが処理されると、その後の代替パスはそのノードを経由するより良い到着時間を生成できなくなり、これらの修正されたエッジの重みの下で標準の最短パスの不変条件が維持されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

def solve():
    n, m, start = map(int, input().split())
    
    types = {}
    params = {}
    
    for _ in range(m):
        line = input().split()
        z = line[0]
        a, b, c, d = map(int, line[1:])
        types[z] = (a, b, c, d)
    
    adj = [[] for _ in range(n)]
    
    for i in range(n):
        row = input().strip()
        for j, ch in enumerate(row):
            if ch != '.':
                adj[i].append((j, types[ch]))
    
    dist = [INF] * n
    dist[0] = start
    
    pq = [(start, 0)]
    
    while pq:
        t, u = heapq.heappop(pq)
        if t != dist[u]:
            continue
        
        for v, (a, b, c, d) in adj[u]:
            best = INF
            
            base = t % c
            
            for r in range(c):
                if r >= base:
                    s = t + (r - base)
                else:
                    s = t + (c - (base - r))
                
                val = s + ((a * s + b) % c) + d
                if val < best:
                    best = val
            
            if best < dist[v]:
                dist[v] = best
                heapq.heappush(pq, (best, v))
    
    print(-1 if dist[n - 1] == INF else dist[n - 1])

if __name__ == "__main__":
    solve()
```隣接リストには、惑星ごとに出力エッジとそのパラメーター セットが保存されます。 ダイクストラ ループは標準ですが、緩和ステップでは、固定の重みが剰余整列開始時間にわたって計算された最小値に置き換えられます。 

よくある落とし穴は、現在の時刻とは関係なく移行コストを事前計算しようとすることです。 最適な開始時間は到着時間 t に依存するため、これは失敗します。 もう 1 つの微妙な問題は、各残基の最も古い有効な s で十分であるということを忘れていることです。 複数のサイクルをスキャンする必要はなく、実行時間が増大してもメリットはありません。 

## 実用的な例

 剰余の動作を明示的に確認できるように、c が小さい単一エッジ タイプの単純化されたシナリオを考えてみましょう。 時刻 t = 3 および c = 5 に惑星に到着するとします。残基ごとの開始時刻の候補は、残基 0 ～ 4 を 5 で割った次の時刻 ≥ 3、つまり 5、6、7、8、および 9 です。これらはそれぞれ 1 回評価され、結果として最良の到着時刻が選択されます。 

| 残差 r | 開始時刻 s | 計算されたコストコンポーネント |
 | --- | --- | --- |
 | 0 | 5 | 5 + (a·5 + b mod c) + d |
 | 1 | 6 | 6 + (a·6 + b mod c) + d |
 | 2 | 7 | 7 + (a·7 + b mod c) + d |
 | 3 | 8 | 8 + (a·8 + b mod c) + d |
 | 4 | 9 | 9 + (a·9 + b mod c) + d |

 このトレースは、待機中の決定が残基アラインメントによって完全に捕捉され、より大きな待機ウィンドウを考慮する必要がないことを示しています。 

2 番目のシナリオとして、すぐに到着するが不利な残差に次善のパスを介してより早く到達できるノードを想像してください。 ダイクストラは、たとえ早期の到着が最初に処理されたとしても、より良い時間に到着した後続の改善によって状態が更新され、遷移が正しく再処理されることを保証します。これは、緩和ごとに新しい時間から最適な待機決定が再計算されるためです。

 ## 特殊なケース

 開始時間がすでに残差に対して最適である場合、アルゴリズムは待機せずにその残差に対して s = t を選択し、即時の出発を正確に捕捉します。 より良い残基を待機する必要がある場合、計算された s は同じサイクル内で前方にシフトされ、アライメントが失われることがなくなります。 

c = 1 の場合、すべての s は同じ剰余を持つため、剰余のループは単一の候補 s = t に崩壊し、モジュロ項が常に 0 であるため、エッジはコスト t + (a t + b mod 1) + d = t + d の固定重みエッジのように動作します。 アルゴリズムは、特別なケースを使用せずにこれを自然に処理します。 

複数のエッジが同じ惑星ペアに接続している場合、それぞれが独立して評価され、ダイクストラは結果として得られる最良の到着時間を正確に選択します。
