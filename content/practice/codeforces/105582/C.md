 ## 解決策
 ## 問題の理解

 いくつかの種類の建設部品が与えられます。 各タイプには固定質量があり、供給量が限られています。 これらのパーツから、いくつかの同一のキットを組み立てたいと思います。 「同一」とは、すべてのキットが各タイプのまったく同じ数の部品を使用することを意味します。 1 つのキットで 2 つのネジと 1 つのビームを使用する場合、他のすべてのキットではまったく同じ 2 つのネジと 1 つのビームを使用する必要があります。 

各キットには総質量の制約があります。つまり、選択した部品の質量の合計が、最小許容質量から最大許容質量までの所定の範囲内に収まらなければなりません。 

課題は、両方の制約を尊重しながら同一のキットをいくつ構築できるかを決定することです。どの部品タイプでも利用可能な供給量を超えることはできず、各キットは質量間隔を満たさなければなりません。 

入力境界のタイプの数は少ないですが、各タイプの項目の数は大きくなる可能性があります。 これにより、パーツを一度に 1 キットずつ配布したり、考えられるすべてのキット構成を直接列挙したりすることをシミュレートするアプローチは直ちに除外されます。 質量制限は比較的小さいため、多重度を制御できればサブセット和スタイルの推論が可能であることが示唆されます。 

微妙な難しさは、キットの数とキットの構成が関係していることです。 より豊富なキットを選択すると、構築できるコピーの数が減りますが、最小限のキットを選択すると、多くのコピーが可能になる可能性がありますが、最小質量要件を満たさない可能性があります。 

質量が許容範囲に入るまで貪欲に部品を選択しようとすると、単純な間違いが発生します。 同じ貪欲な構成をすべてのキットで再利用する必要があるため、これは失敗します。そのため、ローカルな決定がグローバルな実現可能性に影響します。 

具体的な失敗例として、軽いけど豊富な部品と、重いけど希少な部品の2種類があったとします。 欲張って重いパーツを追加するとキットとしては成立しますが、すぐに消耗してしまい必要以上に枚数が減ってしまいます。 正しい答えは、ただ 1 つの有効なキットを構成するだけではなく、構成と繰り返しのバランスに依存します。 

もう 1 つのエッジ ケースは、単一の組み合わせが最小質量にまったく達しない場合です。 その場合、供給が豊富であっても答えはゼロです。 

## アプローチ

 すべてのキットが同一である必要があるという要件を無視すると、問題は境界のあるナップザックの変形になります。つまり、総質量が許容範囲内にある部品の有効なサブセットを形成できるかどうかを確認しようとします。 ただし、ここでの注意点は、同じサブセットを複数回繰り返す必要があることです。 

直接的な総当たりアプローチでは、単一のキットを記述するすべての可能なベクトルが試行されます。 候補組成ごとに、その総質量を計算し、最も制限のある部品タイプに基づいて許容できるコピー数を計算します。 n 個の型があり、それぞれの型を ci 回まで使用できる場合、xi を [0, ci] に制限するだけでも、n でほぼ指数関数的に増大する膨大な検索空間が生じます。 これは完全に不可能になります。 

重要な観察は、2 つの決定を分離することです。 まず、構築するキット k の数を決定します。 k が固定されると、各パーツ タイプ i は 1 つのキット内で最大で Floor(ci / k) 回使用できます。 これにより、問題は、合計重みが範囲内にある項目の制限された組み合わせが存在するかどうかを確認することに変わります。 実現可能性チェックは、古典的な境界付きナップザック到達可能性問題になります。 

mmax は最大 10^4 であるため、達成可能な合計を超える動的プログラミング ソリューションを実行する余裕があります。 残る唯一の課題は、各項目数の制限が大きくなる可能性があるため、バイナリ分割を使用して制限を圧縮することです。 容量 U の各タイプは O(log U) 個の擬似アイテムに分割され、これにより境界付きナップザックが標準の 0/1 ナップザックに縮小されます。 

最後に、実現可能性は単調であるため、k を二分探索します。k 個のキットを構築できれば、さらに小さい数のキットを構築することもできます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 作曲に対するブルートフォース | 指数 | お(1) | 遅すぎる |
 | 二分探索 + 有界ナップザック DP | O(n * mmax * log ci * log 答え) | O(mmmax) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、同じキットをいくつ作りたいかを推測し、その推測が可能かどうかを検証します。 

1. キット k の候補数を決定します。 各パーツ タイプ i について、1 つのキット内で使用できるそのパーツのコピーの数 (ci // k) を計算します。 これにより、k 個の同一のキットが利用可能な在庫を超えないようになります。 このステップでは、グローバルな繰り返し制約をローカルなキットごとの制限に変換します。 
2. バイナリ分解を使用して、各境界項目 (制限 Ui = ci // k を持つ mi) を複数の 0/1 項目に変換します。 たとえば、13 という制限は 1、2、4、6 になります。これらのそれぞれは、キット内の同じパーツ タイプのコピーをその数だけ取得することを表します。 
3. mmax までの達成可能な質量に対してナップザック DP を実行します。 ブール配列 dp を維持します。ここで dp[s] は、分解されたアイテムを使用して総質量が正確に s のキットを形成できることを意味します。 
4. すべての項目を処理した後、[mmin, mmax] の s に対して dp[s] が true であるかどうかを確認します。 「はい」の場合、この k は実行可能ですが、そうでない場合は実行可能ではありません。 
5. 二分探索 k は 0 から安全な上限までで、通常は部品の総数をキットごとの可能な最小要件で割った値です。 実現可能な最大の k が答えです。 

### なぜ効果があるのか

 固定 k の場合、すべての有効な解決策は、タイプごとの制限 ci // k を尊重する項目のマルチセットを選択することに正確に対応します。 バイナリ分解では、制限された使用法のすべての有効な組み合わせが保存されます。 DP は、これらの制約の下で到達可能なすべての合計を列挙します。 すべての有効なキットには必要な間隔内の総質量がなければならないため、その間隔内の到達可能性をチェックすることで実現可能性を正確に把握できます。 k の単調性により、二分探索で可能な最大数の同一キットが確実に見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_make(k, n, mmin, mmax, m):
    # build bounded knapsack using binary splitting
    dp = [False] * (mmax + 1)
    dp[0] = True

    for mi, ci in m:
        if k == 0:
            u = ci
        else:
            u = ci // k
        if u == 0:
            continue

        cnt = 1
        while u > 0:
            take = min(cnt, u)
            weight = mi * take

            # 0/1 knapsack transition
            for s in range(mmax, weight - 1, -1):
                if dp[s - weight]:
                    dp[s] = True

            u -= take
            cnt <<= 1

    for s in range(mmin, mmax + 1):
        if dp[s]:
            return True
    return False

def solve():
    n, mmin, mmax = map(int, input().split())
    m = [tuple(map(int, input().split())) for _ in range(n)]

    # binary search answer
    lo, hi = 0, 10**6 + 5

    while lo < hi:
        mid = (lo + hi + 1) // 2
        if can_make(mid, n, mmin, mmax, m):
            lo = mid
        else:
            hi = mid - 1

    print(lo)

if __name__ == "__main__":
    solve()
```このコードでは、まず、固定数のキットの実現可能性チェックを定義します。 このチェック内では、各アイテム タイプが複数の境界のあるチャンクに変換され、ナップザックがそれらのチャンクの標準サブセット合計になります。 それを超える合計は無関係であるため、DP 配列のサイズは mmax までとなります。 

二分探索はこのチェックをラップします。 k 個のキットが可能であれば、すべてのより小さい値も可能であり、これにより単調探索の正確さが保証されます。 

実装の微妙な詳細は、各チャンクを追加するときにナップザックを逆方向に反復することです。 これにより、同じチャンクを複数回再利用することがなくなり、分解後の 0/1 の性質が維持されます。

 ## 特殊なケース

 mmin が非常に小さいが mmax がきつい場合、特殊なケースが発生します。 その場合、DP は、多くの合計が到達可能であっても、上限に制限する必要があります。そうしないと、有効範囲外の合計を誤って受け入れる可能性があります。 

もう 1 つのエッジ ケースは、k が十分に大きくなり、すべての型で ci // k が 0 になる場合に発生します。 その状況では、k = 0 または k = 1 (解釈に応じて) のみが実行可能です。 DP はアイテムを受け取らず、間隔内にゼロ質量があるかどうかのみをチェックするため、アルゴリズムはこれを自然に処理します。 

3 番目のケースは、単一のタイプがソリューションを支配する場合です。 たとえば、1 つの項目が正確に間隔内の質量を持つ場合、DP は、他のタイプを混合することなく、k あたりの制限された制限まで複数のコピーを選択できるようにする必要があります。 バイナリ分割により、これらの繰り返しの寄与が過剰にカウントされることなく正しく処理されることが保証されます。
