 ## 解決策
 ## 問題の理解

 最大 100 個の頂点と 100 個のエッジを持つ無向の単純なグラフが与えられます。 課題は、計算上の意味で幾何学的に何かを「描く」ことではなく、このグラフがリンゴと呼ばれる非常に特殊な構造として解釈できるかどうかを判断することです。 

リンゴは、共通の開始頂点を 1 つだけ共有する 2 つの頂点が切り離された単純な構造で構成されます。 1 つの構造は単純なサイクルであり、もう 1 つは単純なパスです。 サイクルには少なくとも 3 つの頂点が含まれている必要があり、パスには少なくとも 2 つの頂点が含まれている必要があります。 共有開始頂点とは別に、サイクルとパスが互いに接触したり、頂点を再利用したりしてはなりません。 問題は、これらの厳しい構造的制約の下で、グラフのエッジを共通のルートを持つ 1 つの単純なサイクルと 1 つの単純なパスに分割できるかどうかを判断することになります。 

制約は十分小さいため、指数関数的推論は理論的には可能ですが、その必要はありません。 n、m ≤ 100 の場合、O(n³) または O(n・m) のグラフ分析でも快適に高速です。 これは、強引な幾何学的配置や埋め込みの列挙ではなく、構造的分解を目指すべきであることを直ちに示唆しています。 

グラフが尾部のあるサイクルに「ほぼ似ている」が、尾部がサイクルの頂点を再利用しているか、サイクルが小さすぎる場合、微妙なエッジ ケースが発生します。 たとえば、三角形 1-2-3-1 とパス 1-4 がある場合、これは有効です。 しかし、パスが頂点 2 にも接し、1-2-4 のような形を形成する場合、パスとサイクルがルートの外側で交差するため、分解は無効になります。 もう 1 つの故障モードは、サイズ 2 のサイクルがある場合です。これは単純なグラフでは不可能ですが、次数ベースのアプローチについて推論する際の概念的な罠として注意する価値があります。 

## アプローチ

 ブルートフォース解釈では、ルート頂点を推測し、どのインシデントエッジがサイクルに属し、どのエッジがパスに属するかを決定し、すべての制約を満たす 1 つの単純なサイクルと 1 つの単純なパスを正確に形成できるかどうかを確認します。 これにより、当然のことながら、エッジのサブセットを列挙したり、ルートに付随するエッジのバックトラッキング割り当てを実行したりすることになります。 n ≤ 100 の場合でも、これは組み合わせになります。頂点の次数が d の場合、その入射エッジを 2 つのグループに分割すると、すでに 2^d の可能性が生じ、すべての頂点にわたって、これは実現可能な限界をはるかに超えて爆発的に増加します。 

重要な観察は、構造が非常に硬いということです。 グラフは、1 つの頂点でのみ交差する 2 つの接続されたコンポーネントで構成されており、各コンポーネントは非常に特殊な形式を持っています。 1 つのコンポーネントはサイクルです。これは、そのサブグラフ内のすべての頂点が次数 2 を持つことを意味します。 もう 1 つはパスです。つまり、サブグラフ内のちょうど 2 つの頂点が次数 1 を持ち、パス コンポーネント内で次数 1 を持つがグローバルに共有される共有ルートを除き、他のすべての頂点は次数 2 を持ちます。 

この厳密性により、問題を「図面の検索」から「グラフを、正確に 1 つの関節点を共有する 2 つの非常に特殊なサブグラフに分解できるかどうかの確認」へと切り替えることができます。 自然な方向性は、各頂点を潜在的な共有ルートとして試し、そのインシデント構造が 1 つのサイクル コンポーネントと 1 つのパス コンポーネントに分割できるかどうかを検証することです。 

サイクル条件は、ルートに「固定」できるグラフ内に完全に含まれるサイクルが存在するかどうかのチェックとなり、ルートからの残りのエッジは単純なパスを形成します。 グラフが小さいため、各候補に基づいた DFS ベースのサイクル検出とパス検証を明示的に試みることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースエッジ割り当て | 指数 | O(n + m) | 遅すぎる |
 | DFS によるルートベースの構造チェック | O(n · (n + m)) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. グラフの隣接リストを作成します。 これにより、構造上の制約を検証する際に、近傍を効率的に走査することができます。 
2. 各頂点をサイクルとパスの潜在的な共有ルートとして扱い、各頂点を反復処理します。 正しい構成では、そのような頂点を 1 つだけ使用する必要があるため、すべての可能性を試しても安全です。 
3. 固定ルートの場合、任意の方法でルートを通過しないが、「サイクル構成要素」と見なすことができるサイクルを特定しようとします。 親エッジを追跡しながらグラフ内で DFS を実行し、サイクルを形成するバックエッジを検出します。 
4. サイクルが見つかったら、そのサイクルに属するすべての頂点をマークします。 サイクルは内部的に一貫している必要があるため、これは非常に重要です。サイクル内のすべての頂点は、サイクル構造内に正確に 2 つの隣接頂点を持たなければなりません。 
5. ルートがサイクル内のちょうど 2 つの頂点に接続されているか、共有頂点であることと一致する方法で参加していることを確認します。 サイクルをきれいに分離できない場合、このルートは無効です。 
6. サイクルエッジを削除または無視し、残りの構造を確認します。 ルートに付随する残りのエッジは、単純なパスを形成する必要があります。 これは、ルートから開始して、残りのエッジにわたる DFS は、分岐することなく、線形チェーン構造内の残りのすべての頂点を正確に 1 回訪問する必要があることを意味します。 
7. 残りのコンポーネントが実際にパスであることを検証します。残りのサブグラフでは、端点を除くすべての頂点が次数 2 を持つ必要があり、正確に 2 つの端点が次数 1 を持つ必要があります。 
8. サイクル条件とパス条件の両方を満たすルートがあれば、「Yes」を返します。 

有効な分解を生成するルートがない場合は、「No」を返します。 

### なぜ効果があるのか

 正確さは、ターゲット オブジェクトの構造的剛性によって決まります。 有効な構成には、両方のコンポーネントに属する頂点が 1 つだけ存在する必要があります。 その頂点は、サイクルとパスを分離する関節点です。 これを削除すると、グラフが固定次数制約を持つ 2 つの接続された構造に分割されます。1 つはサイクル (内部的にはすべて次数 2) でなければならず、もう 1 つはパス (2 つの端点、休止次数 2) である必要があります。 すべての有効なリンゴにはそのような分解ポイントが 1 つだけあるため、すべての頂点を反復処理することで、正しいものが存在する場合には最終的にそれをテストすることが保証されます。 DFS チェックは、無向グラフ内のサイクルとパスを一意に特徴付けるローカル制約を強制します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def find_cycle(n, adj, start):
    parent = [-1] * (n + 1)
    visited = [False] * (n + 1)
    stack = [(start, -1)]
    visited[start] = True

    while stack:
        u, p = stack.pop()
        for v in adj[u]:
            if v == p:
                continue
            if not visited[v]:
                visited[v] = True
                parent[v] = u
                stack.append((v, u))
            else:
                # found a cycle, reconstruct it
                cycle = set()
                x = u
                cycle.add(v)
                while x != v and x != -1:
                    cycle.add(x)
                    x = parent[x]
                return cycle
    return set()

def is_path_component(n, adj, root, banned):
    visited = [False] * (n + 1)

    def dfs(u):
        visited[u] = True
        for v in adj[u]:
            if v in banned:
                continue
            if not visited[v]:
                dfs(v)

    dfs(root)

    nodes = [i for i in range(1, n + 1) if visited[i] and i not in banned]
    if not nodes:
        return False

    deg = {}
    for u in nodes:
        deg[u] = 0
        for v in adj[u]:
            if v not in banned:
                deg[u] += 1

    endpoints = [u for u in nodes if deg[u] == 1]
    internal = [u for u in nodes if deg[u] == 2]

    return len(endpoints) == 2 and len(endpoints) + len(internal) == len(nodes)

def solve():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    for root in range(1, n + 1):
        cycle = find_cycle(n, adj, root)
        if not cycle:
            continue
        if root not in cycle:
            continue
        if is_path_component(n, adj, root, cycle):
            return "Yes"

    return "No"

print(solve())
```実装では、各頂点を共有ジャンクションとして試行します。 各候補ルートに対して、バックエッジが見つかったときに 1 つのサイクルを再構築する DFS ベースのサイクル検出を実行します。 そのサイクルはサイクルコンポーネントとして扱われます。 残りのチェックでは、サイクル頂点を除外した後、グラフの残りの部分がきれいなパスを形成しているかどうかを確認します。 重要な点は、サイクル検出ではすべてのサイクルを列挙しようとするのではなく、必要なコンポーネントとして機能できる有効なサイクルを 1 つだけ列挙しようとすることです。有効なソリューションには、正しいルートを通過するそのようなサイクルが少なくとも 1 つ含まれている必要があるため、これで十分です。 

パス検証では、制限されたグラフ内の次数を明示的に計算します。 これにより、複数の分岐を持つグラフでは脆弱になる可能性がある、走査順序のみに依存することが回避されます。

 ## 特殊なケース

 重大なエッジ ケースは、サイクルは存在するが、残りの構造がルートで分岐している場合です。 たとえば、同じ頂点からの 2 つの余分なエッジを持つ三角形です。 サイクルが存在する場合でも、残りのコンポーネントではルートの次数が 1 を超えるため、残差グラフはパス次数条件を満たしません。 

もう 1 つの微妙なケースは、複数のサイクルが存在する場合です。 このアルゴリズムはルートごとに 1 つのサイクルを検出することに依存していますが、すべてのサイクルが有効であるわけではありません。 検出されたサイクルに正しい分解構造が含まれていない場合、ルートは後のパス検証ステップで失敗します。これにより、間違ったサイクルの選択によって誤検知が発生することがなくなります。 

最後のケースは、グラフは接続されているが、単純なサイクルが含まれていない場合です。 その状況では、サイクル検出はすべてのルートに対して空を返し、アルゴリズムは不必要なパス チェックを試行することなく正しく「いいえ」を出力します。
