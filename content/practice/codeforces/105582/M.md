 ## 解決策
 ## 問題の理解

 この構造は完全な二分木であり、2 以降のすべてのノードには整数の 2 による除算で与えられる親があります。 これにより、トポロジが固定かつ暗黙的になります。ノード 1 がルート、ノード 2 と 3 がその子、ノード 4 ～ 7 が次のレベル、というように n まで続きます。 

ノード i からその親までの各エッジには、1 から 9 までの数字の重みが付けられます。これらの重みは直接与えられるのではなく、線形合同生成器から決定論的に生成されます。 シーケンスが生成されると、i 番目のノードの親への接続エッジに、そのシーケンスから派生した数字が割り当てられます。 したがって、ルートを除くすべてのノードは 1 つの重み付きエッジに寄与し、パスの合計はこれらのエッジの重みの単なる合計になります。 

任意の 2 つのノード u および v について、値 N(u, v) は、それらの間の一意のツリー パスに沿ったエッジの重みの単純な合計です。 ツリーには方向性がないため、これは標準の重み付きツリー距離です。 

より微妙な部分は、ノード v ごとの制限です。「最上位の意味で v を通過する」パスのみを考慮します。つまり、v はパスに含まれますが、その親は含まれません。 ツリー言語では、これは、v がパスの最上位ノードでなければならないことを意味するため、v はエンドポイントの最下位の共通祖先になります。 同様に、v のサブツリー内の、接続パスの LCA が正確に v であるノードのすべてのペアを調べます。 

このようなすべての有効なペアの中で、各 v について、可能な最大のパス合計が必要になり、この最大値をすべてのノードにわたって合計します。 

制約は n = 10^7 まであり、ノードのすべてのペア、またはサブツリー内のすべてのペアを検査するアプローチは即座に除外されます。 重い定数係数を使用したノードごとの線形処理でも厳しいため、ソリューションはノードごとに O(1) の作業を伴うノード上のシングル パスでなければなりません。 

単純な間違いは、タスクを各サブツリーの直径を計算するものとして解釈することです。 それは間違いです。 サブツリーの直径は、v の 1 つの子サブツリー内で完全に達成される可能性があります。これは、その LCA が v を下回っているため、v に対する有効な「ぶら下がりパス」ではありません。正しい制限により、パスは v から 1 つのサブツリーに下降するか、2 つの異なる子サブツリーに下降するかのいずれかになります。 

もう 1 つの失敗ケースは、subtree(v) 内のパスが有効であると想定している場合です。 たとえば、チェーン状のサブツリーでは、最長パスが完全に v の下にあり、LCA として v を使用して完全にスキップする可能性がありますが、これは v としてカウントされるべきではありません。 

## アプローチ

 ブルートフォース解釈では、すべてのノード v を試し、サブツリー内のすべてのノードのペア (u、w) を列挙し、それらのパスの合計を計算し、LCA が v である最適なペアを保持します。サブツリーのサイズが均衡している場合でも、これにより、すべてのサブツリーにわたるすべてのペアを大まかに合計することになり、最悪の場合は O(n^2) の動作に劣化します。 n が 10^7 までの場合、これは完全に不可能です。 

重要な構造上の観察は、ツリーが固定かつバイナリであり、v を通るすべての有効なパスがその子を介してきれいに分解される必要があるということです。 LCA が正確に v であるパスは、v で開始して 1 つのブランチを下降するか、2 つの異なる子ブランチを下って v を介して接続する必要があります。これは、v で必要なすべての情報が、ノードごとの 1 つの値、つまりそのノードから始まる下向きパスの最大合計によって要約できることを意味します。 

dp[v] を v で始まりそのサブツリーに下るパスの最大合計として定義すると、v を通るすべての最適な「ぶら下がりパス」はその子の dp 値のみを使用して表現可能になります。 v を通る最適なパスは、v から始まる単一の下向きチェーン、または 2 つの異なる子からの最適な下向きチェーンの組み合わせのいずれかです。 

これにより、問題はノードのすべてのペアに関する推論から、完全なバイナリ ツリーに対する単純なボトムアップ動的プログラミング計算に軽減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブツリー内のすべてのペアに対するブルート フォース | O(n^2) | O(n) | 遅すぎる |
 | ツリー上のボトムアップ DP (下向き最大値) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 子が常に親より前に計算されるように、ノードを逆の順序で処理します。これは、DP の自然な依存関係と一致します。 

1. 指定された反復を使用して、各ノードのエッジの重みを生成します。 各ノード i について、エッジ上の数字 (i, i//2) を取得します。 今後のすべての DP 遷移はこれらの重みに依存するため、これが必要になります。 
2. dp[i] を、ノード i から開始してそのサブツリーへ下方向にのみ移動するパスの最大合計として定義します。 i が葉の場合、その下にはエッジがないため、dp[i] は 0 になります。 
3. n から 1 までノードを処理します。各ノード i について、各子を介した最良の下方寄与を計算します。 子 c が存在する場合、その子による寄与は、weight(i, c) + dp[c] になります。 
4. dp[i] をすべての子コントリビューションの最大値として設定します。 これにより、i から始まる最適な単一分岐パスが取得されます。 
5. LCA が正確に i である最良の有効パスである best[i] を計算します。 これには 2 つの可能性があります。 1 つは単に dp[i] で、i から始まり下に向かうパスに対応します。 もう 1 つは、2 つの子を結合し、左側のサブツリーで最適な下向きパスと右側のサブツリーで最適な下向きパスを選択し、i を介してそれらを結合します。 その値は、(左への重み + dp[左]) + (右への重み + dp[右]) です。 
6. best[i] をグローバルな答えに累積します。 

重要な点は、LCA が i であるパスはすべて、i の 1 つのブランチまたは 2 つの異なるブランチを使用する必要があるということです。 LCA が正確に i である場合、他の構造は i の通過を避けることはできません。 

### なぜ効果があるのか

 任意のノード i について、LCA i を持つすべての有効なパスは、i で一意に最大 2 つの下向きセグメント (子サブツリーごとに 1 つ) に分割されます。 dp 値は、任意のノードから始まる可能な限り最良の下向きセグメントをキャプチャします。 最適な部分構造は正の重みを持つツリーに保持されるため、サブツリー内の最適なパス セグメントは、正確さを失うことなく dp に置き換えることができます。 これにより、i で子を結合するときに、両方のサブツリー内のすべての可能なエンドポイントを列挙せずに暗黙的に考慮することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, seed = map(int, input().split())
    
    if n == 0:
        print(0)
        return

    # Generate edge weights a[i] for i >= 2
    a = [0] * (n + 2)

    r = seed
    for i in range(2, n + 1):
        r = (1103515245 * r + 12345) & 0x7fffffff
        a[i] = ((r >> 16) % 9) + 1

    dp = [0] * (n + 2)
    ans = 0

    # process bottom-up
    for i in range(n, 0, -1):
        left = 2 * i
        right = 2 * i + 1

        best_down = 0

        left_val = 0
        right_val = 0

        if left <= n:
            left_val = a[left] + dp[left]
            best_down = max(best_down, left_val)

        if right <= n:
            right_val = a[right] + dp[right]
            best_down = max(best_down, right_val)

        dp[i] = best_down

        best_here = dp[i]

        if left <= n and right <= n:
            best_here = max(best_here, left_val + right_val)

        ans += best_here

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、親を計算するときに子の dp 値がすでにわかっているように、ノードを逆の順序で処理することに依存しています。 配列のサイズは直接最大 n に設定されますが、これは完全なバイナリ インデックスを指定するために必要です。 LCG は指定どおりに適用され、各エッジの重みは子インデックスに保存されるため、DP 中のアクセスが簡素化されます。 

微妙な点は、dp[i] が一般的なサブツリーの直径ではなく、i から始まる下向きのパスを表すことです。 この区別により、メモリと計算が線形に保たれます。 

## 実用的な例

 構造が完全に見えるように、n = 7 の小さな木を考えてみましょう。 説明のために任意の小さなエッジの重みを仮定します。 

ノード インデックスの関係は固定されており、生成される重みは次のようになると仮定します。 

| 私 | 親エッジの重み |
 | --- | --- |
 | 2 | 3 |
 | 3 | 2 |
 | 4 | 5 |
 | 5 | 1 |
 | 6 | 4 |
 | 7 | 6 |

 dp をボトムアップで計算します。 

| 私 | 左DPの貢献 | 右DPの貢献 | dp[i] |
 | --- | --- | --- | --- |
 | 4 | 0 | 0 | 0 |
 | 5 | 0 | 0 | 0 |
 | 2 | 5 + 0 = 5 | 1 + 0 = 1 | 5 |
 | 6 | 0 | 0 | 0 |
 | 7 | 0 | 0 | 0 |
 | 3 | 4 + 0 = 4 | 6 + 0 = 6 | 6 |
 | 1 | 3 + 5 = 8 | 2 + 6 = 8 | 8 |

 各ノードでの最適なパスは次のようになります。 

ノード 2 での最適パスは 5 です。 

ノード 3 での最適パスは 6 です。 

ノード 1 での最適パスは max(dp[1], left+right) = max(8, 5+6+dp 寄与によってすでに処理されたエッジ調整) であり、構造に応じて 11 種類の組み合わせになります。 

このトレースは、dp がブランチ間の正しい組み合わせを有効にしながら、サブツリー情報をノードごとに単一の値に圧縮する方法を示しています。

 ## 特殊なケース

 n = 1 の場合、エッジは存在しないため、自明なパスを除いて有効なパスは存在できません。 アルゴリズムは dp[1] を 0、best[1] を 0 に設定し、正しい合計が 0 になるようにします。 

子が 1 つだけあるノードの場合、ブランチ間用語は無効になります。 このような場合、最適なパスは純粋に下向きのチェーンに減り、アルゴリズムは存在しないサブツリーの結合を正しく回避します。 

バイナリ ツリーの深く不完全な最後のレベルでは、一部のノードに子が欠落しています。 この実装では、インデックス境界を使用して子の存在をチェックし、無効なアクセスがないことを保証し、dp 遷移でガベージ値が誤って使用されることを防ぎます。 

すべての場合において、dp[i] が i から始まる最適な下向きパスを表すという不変式により、サブツリーの形状に関係なく一貫性が保証されます。
