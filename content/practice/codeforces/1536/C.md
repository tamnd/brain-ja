 ## 解決策
 ## 問題の理解

 文字のみからなるバイナリ文字列が与えられます。`D`そして`K`。 この文字列のすべてのプレフィックスについて、すべての部分の内部バランスが同じになるように、そのプレフィックスを連続する部分にどの程度細かく分割できるかを決定したいと考えています。`D`そして`K`。 

各部分は、どれだけの割合であるかを示す比率によって要約されます。`D`と`K`含まれています。 正規化後に比率が一致する場合、2 つの部分は互換性があるとみなされます。つまり、間の比率が一致します。`D`そして`K`絶対数が異なっても同一です。 

位置で終わる各プレフィックスについて`i`、すべてのセグメントが同じ比率になるように、分割できるセグメントの最大数が必要です。 

重要な問題は、これをすべてのプレフィックスに対して計算する必要があるため、すべてのプレフィックスに対してパーティションを最初から再計算すると時間がかかりすぎることです。 

制約は、テスト ケースごとの線形または線形に近い解決策を意味します。 すべてのテスト ケースの合計の長さは最大 500,000 であるため、プレフィックスを繰り返しスキャンしたり、プレフィックスごとにすべての分割ポイントを試行したりするソリューションは、制限時間を超えることになります。 これにより、計算を再開する 2 次または接頭辞ごとの動的計画法が即座に排除されます。 

弦が均一である場合、微妙なエッジケースが現れます。 たとえば、文字列が次の場合、`DDDDD`、すべての接頭辞は 1 文字のセグメントに分割でき、答えは直線的に増加します。 意味のあることを強制しようとする素朴なアプローチ`D:K`比率は両方の文字がすべてのセグメントに出現する必要があると誤って想定する可能性がありますが、比率は次のようなものであるため、これは誤りです。`a:0`有効です。 同様に、次のようなプレフィックス`DKDK`バランスの取れた交互分割が可能ですが、グローバルな実現可能性を追跡せずに貪欲なセグメンテーションを行うと、有効なパーティションが失われる可能性があります。 

もう 1 つの注意が必要なケースは次のような場合です。`K`決して現れません。 たとえば、`DDDD`、すべての接頭辞がすべての単一文字に分割できるようにする必要があります。 比率を定義するために両方の文字が必要であると想定するメソッドは、ここで中断されます。 

## アプローチ

 ブルートフォース ソリューションでは、プレフィックスごとに、考えられるすべてのパーティショニングを試し、すべてのセグメントが同じ比率を共有しているかどうかを確認します。 長さのプレフィックスの場合`i`、分割する方法は指数関数的に多くあり、単一のパーティションを検証する場合でも、すべてのセグメントをスキャンして比率を比較する必要があります。 可能なすべての数のセグメントをテストし、貪欲な検証を試みることに制限したとしても、テスト ケースごとにほぼ二次的な動作が得られます。 

重要な構造的洞察は、必要なセグメントの数を決定すると、有効なパーティションがプレフィックス全体の比率によって完全に決定されるということです。 プレフィックスを分割できる場合`k`有効なセグメントの場合、各セグメントは合計の固定比率に対応する必要があります。`D`そして`K`カウントします。 これは、有効な分割がプレフィックスの縮小比率構造の約数に正確に対応することを意味します。 

明示的にパーティションを構築する代わりに、プレフィックスの各正規化状態がどのくらいの頻度で出現するかを追跡します。 各接頭辞の状態は、比率の等価性を維持する方法で、前の状態からどれだけ離れているかをエンコードします。 状態を再検討するときは常に、プレフィックスを同一構造のより多くのセグメントに分割できると言っていることになります。 

これにより、問題は、プレフィックスの正規化された表現のカウントを維持し、周波数の累積を使用して各プレフィックスの一貫したセグメントの最大数を導出するという問題に軽減されます。

 ## アルゴリズムのチュートリアル

 各プレフィックスの縮小表現を通じて解釈します。`D`そして`K`バランス。 生のカウントを保存する代わりに、プレフィックスの比率の動作を一意に識別する正規化された署名を維持します。 

1. 累積カウントを維持しながら文字列を走査します。`D`そして`K`。 各文字を処理した後、これら 2 つのカウント間の比率の正規形式を計算します。 
2. 比率を比較できるようにするために、次のように削減します。`(d, k)`両方がゼロ以外の場合、両方を最大公約数で割ることによって。 それらの 1 つがゼロの場合、状態を次のような特別な形式で表します。`(1, 0)`または`(0, 1)`どのキャラクターが支配するかによって異なります。 
3. 頻度マップを維持します`freq`これは、正規化された各プレフィックス状態がこれまでに出現した回数をカウントします。 
4. 各プレフィックスについて、その正規化された状態のカウントを増やします。`freq`。 
5. 現在のプレフィックスの答えは、これまでに確認された状態の最大頻度にすぎません。同じ正規化された状態を繰り返すということは、出現間でセグメントを位置合わせできることを意味するからです。 
6. すべてのプレフィックスに対して回答を出力する必要があるため、反復中に現在の最大値を保存します。 

微妙なアイデアは、同じ正規化されたプレフィックス状態が複数回出現するたびに、同じ比率のセグメントが開始および終了できる自然なカット ポイントを定義するということです。 したがって、最も一般的な状態の頻度は、等比セグメントの最大数を直接的に与えます。 

### なぜ効果があるのか

 各プレフィックス状態は、正規化までのプレフィックスの比率構造をエンコードします。 同じ状態の 2 つの位置は、それらの間のセグメントが同一であることを意味します`D:K`スケーリング下で比較した場合の比率。 文字列を最適に分割することは、同一の状態の発生をグループ化することと同じです。有効な分割は、比率が同一の構成にリセットされる境界に位置合わせする必要があるためです。 最も頻繁な状態によって、そのような一貫したセグメントがいくつ共存できるかが決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        d = 0
        k = 0
        freq = defaultdict(int)

        ans = []
        best = 0

        for ch in s:
            if ch == 'D':
                d += 1
            else:
                k += 1

            # normalize ratio
            if d == 0:
                key = (0, 1)
            elif k == 0:
                key = (1, 0)
            else:
                import math
                g = math.gcd(d, k)
                key = (d // g, k // g)

            freq[key] += 1
            if freq[key] > best:
                best = freq[key]

            ans.append(str(best))

        print(" ".join(ans))

if __name__ == "__main__":
    solve()
```コードは実行中のカウントを維持します。`D`そして`K`各プレフィックスを縮小率形式に圧縮しながら。 の`gcd`このステップにより、比例状態が同一のキーに集約されるため、構造的に同等のプレフィックスが同じ識別子にマップされます。 辞書は各構造が出現する頻度を追跡し、最も頻繁に出現する構造が増加するにつれて答えも進化します。 

唯一の微妙な実装の詳細は、ゼロのケースを個別に処理することです。 これがないと、カウントの 1 つがゼロの場合に gcd ベースの正規化の計算が失敗し、あいまいな表現が発生します。

| 私 | プレフィックス | D | K | 正規化された状態 | 頻度の更新 | 最高 |

 ## 特殊なケース

 のような文字列の場合`KKKK`、すべてのプレフィックスは同じ正規化された状態を維持します`(0,1)`。 アルゴリズムはこの状態の繰り返し発生をカウントし、着実に増加する応答を生成します。 これは、追加の各文字が別の有効な単一文字セグメントを形成できるという事実と一致します。 

のために`DKK`、最初の文字が状態を作成します`(1,0)`、2番目は作成します`(1,1)`、3番目は生成します`(1,2)`これは次のようになります`(1,2)`また。 周波数メカニズムは、構造的に異なるプレフィックスを正確に区別しながら、繰り返し状態が縮小された形で再び現れるときに蓄積することを可能にします。
