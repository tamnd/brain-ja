 ## 解決策
 ## 問題の理解

 短い小文字の文字列が与えられ、その中で非常に具体的な「欠落しているパターン」を見つけるように求められます。 タスクは、指定された入力の連続部分文字列としてどこにも現れない、小文字を超えた可能な限り短い文字列を識別することです。 複数の文字列がこの最小長を共有する場合、その中から辞書編集的に最も小さい文字列が選択されます。 

これについて考えると便利な方法は、文字列内の最初の「存在しないブロック」をアルファベット順に、長さ 1 から始めて、次に長さ 2 というように検索するということです。 文字列のどこにも連続セグメントとして含まれない最小のパターンが必要です。 

入力サイズは十分に小さく、各テスト ケースの文字数は最大 1000 文字であり、すべてのテスト ケースの合計長も 1000 で制限されます。これにより、単純な総当たりアプローチで総作業量が管理可能なままであるため、すべての部分文字列を生成するか、長さ 3 または 4 までの候補文字列を列挙するソリューションが実現可能であることがすぐにわかります。 

重要な点は、「最小長が最初」と組み合わせられた辞書編集順序の定義にあります。 優先されるのは常に長さであり、アルファベットではありません。 これは、2 文字の文字列を考慮する前に、すべての 1 文字の文字列が入力内のどこかに存在することを確認する必要があることを意味します。 1 文字でも欠けている場合は、その文字が自動的に答えになります。 

よくある失敗例は、「欠落している最短の文字列」が辞書編集上の順序を支配していることを無視したことに起因します。 たとえば、次のような文字列では、`"abc"`、答えは`"d"`、 ない`"aa"`、 それでも`"aa"`辞書編集上、多くの 2 文字の文字列よりも小さいです。 長さの制約はすべてをオーバーライドします。 

もう 1 つの微妙なエッジ ケースは、すべての単一文字が存在するが、すべてのペアが存在するわけではない場合です。 次に、単なる欠損ペアではなく、辞書編集上最小の欠損ペアを慎重に選択する必要があります。 

## アプローチ

 ブルートフォースの考え方は簡単です。長さ 1 の文字列をすべて試し、次に長さ 2 の文字列をすべて試し、というようにして、各候補が部分文字列として現れるかどうかを確認します。 アルファベットは 26 文字なので、長さ 1 の候補は 26 個、長さ 2 の候補は 26² = 676 個、長さ 3 の候補は 26³ = 17576 個あります。長さ 3 の場合でも、各メンバーシップ チェックは長さ 1000 までの文字列の部分文字列検索で実行できるため、すべての候補をチェックすることは可能です。 

これは、応答の最大長が非常に短いため機能します。 実際、長さ n の文字列の場合、n より長い部分文字列は存在することが不可能であるため、n が 1000 までの場合、答えは最大でも長さ 3 でなければなりません。鳩の穴の原理により、長さ 1 と 2 の部分文字列をすべて使い尽くしたら、文字列が非常に構造化されていない限り、欠落している長さ 3 の文字列が存在することが保証されますが、最悪の場合でも長さ 3 で十分です。 

最適化の洞察は、文字列に対してすべての候補を動的にチェックするのではなく、固定長のすべての部分文字列を事前計算し、それらをハッシュ セットに保存するということです。 次に、メンバーシップ チェックは O(1) になり、候補を長さおよび辞書編集順に体系的にテストします。 

長さ 1 から始めて、すべての文字をチェックします。 何も欠落していない場合は、長さ 2 に進み、辞書編集順にすべてのペアを生成し、長さ 2 のすべての部分文字列の事前計算済みセットに対してメンバーシップをテストします。長さ 3 についても同様に続行します。 

これにより、スキャンの繰り返しが減り、ソリューションがクリーンかつ高速に保たれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | O(26^3 · n) | O(n) | 承認済み |
 | 最適 | O(n + 26^3) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 候補の長さを増やして、段階的にソリューションを構築します。 

1. 入力から長さ 1 のすべての部分文字列を抽出し、セットに格納します。 これにより、どの文字が存在するかが正確にわかります。 
2. から各キャラクターを確認`'a'`に`'z'`。 欠落している文字列がある場合は、それが可能な限り最も短い欠落文字列であるため、すぐに返します。 
3. すべての単一文字が存在する場合は、入力から長さ 2 のすべての部分文字列のセットを構築します。 このステップでは、文字列内のすべての隣接するペアをキャプチャします。 
4. すべてのペアを列挙する`"aa"`を通して`"zz"`辞書順に。 セット内で見つからない最初のペアが返されます。 
5. すべてのペアが存在する場合は、長さ 3 のすべての部分文字列のセットを構築します。 
6. すべてのトリプルを列挙する`"aaa"`を通して`"zzz"`辞書順に並べて、最初に欠落しているものを返します。 

長さ 3 までしか必要ない理由は、1000 文字の文字列では、長さ 2 の部分文字列が 999 個と長さ 3 の部分文字列が 998 個しかないためです。 使用可能な文字列のスペースは、入力で使用可能なスロットの数よりもはるかに速く増加するため、欠落しているパターンは長さ 3 までに出現する必要があります。 

### なぜ効果があるのか

 このアルゴリズムは、階層化された完全性チェックに依存しています。 長さ k のすべての文字列が入力に現れることを確認した後でのみ、長さ k+1 に移動します。 これにより、あるレベルで候補を返すときに、その候補の長さが最小限であることが保証されます。 固定長内で辞書順に反復するため、そのレベルで最初に欠落している候補も辞書順に最小になります。 検索スペースは長さの増加順に使い尽くされるため、より短い、または辞書編集的により小さい有効な回答がスキップされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        # length 1 check
        present1 = set(s)
        for c in "abcdefghijklmnopqrstuvwxyz":
            if c not in present1:
                print(c)
                break
        else:
            # length 2 check
            present2 = set()
            for i in range(n - 1):
                present2.add(s[i:i+2])

            found = False
            for a in "abcdefghijklmnopqrstuvwxyz":
                for b in "abcdefghijklmnopqrstuvwxyz":
                    cur = a + b
                    if cur not in present2:
                        print(cur)
                        found = True
                        break
                if found:
                    break
            if found:
                continue

            # length 3 check
            present3 = set()
            for i in range(n - 2):
                present3.add(s[i:i+3])

            for a in "abcdefghijklmnopqrstuvwxyz":
                for b in "abcdefghijklmnopqrstuvwxyz":
                    for c in "abcdefghijklmnopqrstuvwxyz":
                        cur = a + b + c
                        if cur not in present3:
                            print(cur)
                            found = True
                            break
                    if found:
                        break
                if found:
                    break

solve()
```実装は段階的チェック戦略に直接に従います。 各フェーズでは、固定長の部分文字列の完全なセットを構築し、不足しているものが見つかるまで辞書編集順に候補を繰り返します。 ネストされたループにより、並べ替えを必要とせずに正しい順序が適用されます。 

微妙な点は、`for ... else`長さ-1チェックで。 これにより、すべての単一文字が存在する場合にのみ長さ 2 に進むことが保証されます。 

## 実用的な例

 文字列を考えてみましょう`"aannttoonn"`。 

長さ 1 の場合、現在の文字のセットは次のとおりです。`{a, n, t, o}`。 アルファベット順で最初に欠けている文字は次のとおりです。`"b"`、だから答えはすぐにわかります`"b"`。 常に短い回答が優先されるため、それ以上の計算は必要ありません。 

ここで、すべての文字が構造化された方法で存在する場合を考えてみましょう。`"abcdefghijklmnopqrstuvwxyz"`小さなアルファベットに切り詰められます。 あるとします。`"abcabc"`。 

長さ 1 の場合、次のすべて`"a"`、`"b"`、`"c"`が存在するので次に進みます。 

長さ 2 の場合、部分文字列を抽出します。 
| 私 | 部分文字列 |
 |---|----------|
 | 0 | アブ |
 | 1 | 紀元前 |
 | 2 | ca |
 | 3 | アブ |
 | 4 | 紀元前 |

 セットは`{ab, bc, ca}`。 辞書順にスキャンします。`aa`はすぐに見つからないので、答えは`"aa"`。 

これは、文字列が循環的に完全な文字であっても、辞書編集順の非常に早い段階で欠落ペアが現れる可能性があることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 |---|---|---|
 | 時間 | O(n + 26³) | 部分文字列の抽出は線形であり、候補の列挙は定数の範囲内です。 
| スペース | O(n) | 最大 3 の長さの部分文字列を格納します。 

テスト ケース全体の合計 n が最大 1000 であるとすると、解は容易に制限内に収まります。 26³ による定数係数は無視できるほど小さいです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        present1 = set(s)
        for c in "abcdefghijklmnopqrstuvwxyz":
            if c not in present1:
                out.append(c)
                break
        else:
            present2 = set(s[i:i+2] for i in range(n-1))
            found = False
            for a in "abcdefghijklmnopqrstuvwxyz":
                for b in "abcdefghijklmnopqrstuvwxyz":
                    if a+b not in present2:
                        out.append(a+b)
                        found = True
                        break
                if found:
                    break
            if found:
                continue

            present3 = set(s[i:i+3] for i in range(n-2))
            for a in "abcdefghijklmnopqrstuvwxyz":
                for b in "abcdefghijklmnopqrstuvwxyz":
                    for c in "abcdefghijklmnopqrstuvwxyz":
                        if a+b+c not in present3:
                            out.append(a+b+c)
                            found = True
                            break
                    if found:
                        break
                if found:
                    break

    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、文字列に繰り返される文字が 1 つだけ含まれている場合です。`"aaaaa"`。 アルゴリズムは、長さ 1 で多くの文字が欠落していることを正確に検出し、すぐに返します。`"b"`、 以来`'a'`存在しますが、`'b'`そうではありません。 

もう 1 つのエッジ ケースは、すべての文字が存在するが、ペアが非常に限られている場合です。`"abcdefghijklmnopqrstuvwxyz"`あるパターンで繰り返されます。 この状況では、長さ 2 の候補は次のようになります。`"aa"`または`"ba"`文字列が文字レベルで「完全」であるように見えても、欠落している可能性があります。 段階的なアプローチにより、単一の文字が完全にカバーされた後はペアのチェックをスキップすることがなくなります。 

最後のエッジ ケースは、文字列が長さ 1 など、非常に短い場合です。ここでは、長さ 2 または 3 の部分文字列がまったくないため、セットは空です。 長さ 1 または 2 の辞書編集上の最初の候補が、存在に応じて即座に答えとなり、アルゴリズムは特別な大文字と小文字を区別せずに空の部分文字列セットを自然に処理します。
