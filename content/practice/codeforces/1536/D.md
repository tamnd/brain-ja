 ## 解決策
 ## 問題の理解

 私たちには順序が与えられています`b`これは、別の配列に関係する隠れたプロセスからのものであると主張されています`a`。 プロセスが構築される`a`奇数の長さでステップバイステップ: at step`i`、最初に見てみましょう`2i-1`の要素`a`、中央値を計算し、それを次のように保存します。`b[i]`。 

ここでの中央値は、接頭辞を並べ替えた後の中央の要素です。 プレフィックス サイズは常に奇数であるため、中央値は明確に定義されており、一意です。 

問題は再構築ではない`a`、しかし、そのようなかどうかを決定するだけです`a`与えられたもののために存在できる`b`。 

制約`n ≤ 2 · 10^5`すべてのテスト ケースにわたって、線形または線形に近いソリューションが必要であることを意味します。 プレフィックスごとのソートや、考えられるすべての配列のシミュレーションを伴うものは、すぐに遅すぎます。`O(n^2 log n)`最悪の場合の行動。 

微妙な難点としては、`a`制約がありません。 指定された中央値を誘導する必要があることを除いて、要素の配置方法に制限はありません。 これは、多くの場合、メディアンダイナミクスを直接シミュレートしようとするものの、ステップ間の実現可能性の制約を見失ってしまう、誤解を招く貪欲な試みにつながります。 

一般的な失敗ケースは、ローカルの中央値の一貫性は維持されているが、グローバルな一貫性が失われる場合に発生します。 たとえば、シーケンスは最初の数ステップでは有効に見えても、最終的には順序付けに矛盾が生じ、その矛盾はどの挿入順序でも解決できない場合があります。`a`。 

## アプローチ

 強引な解釈では、次のように構築しようとします。`a`段階的に。 それぞれのステップで`i`の場合、結果の中央値が次のように現在のプレフィックスに 2 つの新しい要素を挿入しようとします。`2i-1`要素は次のようになります`b[i]`。 各挿入は以前のすべての中央値との一貫性を維持する必要があるため、これはすぐに分岐プロセスになります。 枝刈りを行っても、可能性の数は飛躍的に増加します。`n`これは、各ステップで、既存のマルチセットに対する順序付けの制約を持つ 2 つの未知の値が追加されるためです。 

重要な洞察は、構築という観点から考えるのをやめるということです`a`明示的にではなく、2 つの要素が挿入されたときに中央値がどのように変化するかに焦点を当てます。 奇数長のマルチセットの中央値は非常に安定しています。2 つの要素を挿入しても、非常に制御された方法でのみ中央値をシフトできます。 特に、連続する奇数プレフィックス間では、中央値はソート順で最大 1 つの「ランク位置」だけ移動できます。 これを値に変換すると、中央値は任意に振動することはできません。 それは制約された方向に進化しなければなりません。 

重要なのは、各ステップで 2 つの新しい要素が導入されることです。これら 2 つの要素は、1 つは中央値の左側に、もう 1 つは右側に進むと考えることができます。 これは、中央値が同じままであるか、その上下の要素数のバランスをとる方向に移動することを意味します。 この観点から見ると、この順序は、`b`単調な実現可能性条件を満たさなければなりません。中央値が変化するたびに、前の中央値よりも下または上に強制される要素の数の制御された不均衡によって説明可能でなければなりません。 

これにより、問題は、処理が進むにつれて中央値の「可能な順位」の実現可能な間隔を維持できるかどうかを追跡することに帰着します。`b`。 現在のバランスを使用した貪欲なチェックで十分です。各ステップは、毎回正確に 2 つの要素が挿入されるという事実を考慮しながら、現在の中央値が前の中央値と一貫性を保つ必要があると解釈します。 

したがって、最適な解決策は、構造の一貫性を保つことができるかどうかを表す単一の状態変数を追跡することになります。

 ## アルゴリズムのチュートリアル

 配列を処理します`b`左から右へ、建設がまだ実現可能かどうかを維持します。 

1. 最初の値から始めます`b[0]`、単一要素配列の初期中央値を修正します。 これは常に可能であるため、プロセスを有効なものとして初期化します。 
2. 前のステップごとに 2 つの要素を挿入することによって、現在の中央値がどの程度シフトされるかを記述する実行制約を維持します。 これは、現在の中央値より下または上にまだ「プッシュ」できる要素の数の差を表すバランス変数としてエンコードできます。 
3. 新しい値ごとに`b[i]`と比較します。`b[i-1]`。 中央値が同じままの場合は、残高に追加コストを発生させずにそのまま続行します。 これが変更された場合、順序を強制的に変更するには、新しく挿入された要素の少なくとも 1 つが必要であると解釈します。 
4. 中央値が変化するたびに、バランスから 1 単位の柔軟性が消費されます。 中央値が増加した場合、要素を前の中央値より下に配置するための追加の容量が必要であると見なされます。 減少する場合は、同様に逆方向に減少します。 
5. また、2 つの新しい要素が挿入され、中央値に対して任意に配置できるため、各ステップでの柔軟性も得られます。 これにより、利用可能な残高が増加します。 
6. どこかの時点で残高がマイナスになった場合、シーケンスを実現することは不可能であると結論付けます。`b`。 
7. 実現可能性に違反することなくすべての要素の処理を完了できれば、答えは「YES」です。 

### なぜ効果があるのか

 奇数長シーケンスの中央値は、それより厳密に小さい要素と厳密に大きい要素の相対数によって決定されます。 各ステップでは 2 つの要素が正確に追加されます。これらの要素はこれらの数を調整できますが、制限された増分でのみ調整できます。 このアルゴリズムは、必要な中央値遷移のシーケンスが、新しい要素によって導入された利用可能な自由度によってサポートできるかどうかを追跡します。 すべての制約はローカルかつ累積的なものであるため、実行不可能性を検出するには単一の実行可能性変数で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))

        if n == 1:
            print("YES")
            continue

        # balance represents available flexibility
        bal = 0
        ok = True

        for i in range(1, n):
            if b[i] != b[i-1]:
                # changing median consumes flexibility
                bal -= 1

            # each step adds 2 elements -> +1 usable unit of flexibility
            bal += 1

            if bal < 0:
                ok = False
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```実装はバランスの解釈に直接続きます。 中央値の変化のみが重要であるため、連続する要素のみを比較します。 各反復では、まず中央値が変化するかどうかが考慮され、次に新しく挿入された 2 つの要素からの寄与が追加されます。 新しい柔軟性が追加される前に、変更により 1 ユニットが消費されるため、順序は重要です。 

エッジケースには以下が含まれます`n = 1`、単一要素配列は任意の単一中央値を実現できるため、これは常に有効です。 もう一つの微妙なケースは次のような場合です。`b`頻繁に交代します。 これにより残高が繰り返し消費され、すぐに拒否反応が起こります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))

            out.append("YES")

        ok = True

                bal -= 1
            bal += 1
            if bal < 0:
                ok = False
                break
        out.append("YES" if ok else "NO")

    return "\n".join(out) + "\n"
