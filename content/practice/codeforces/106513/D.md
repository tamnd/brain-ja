 ## 解決策
 ## 問題の理解

 潜在的な高速道路で接続された一連の都市が与えられており、各高速道路には固定の建設コストがかかります。 これらの道路はすでに接続された無向グラフを形成しているため、これらのエッジの一部のサブセットを使用してスパニング ツリーが常に存在することがわかります。 

提案されたすべての高速道路の中で、1 つの特定のエッジが強制されます。それは、最終的に接続されたネットワークに何があっても表示されなければなりません。 課題は、この必須のエッジを含めながら、すべての都市を接続する最小コストの道路セットを構築することです。 

グラフ用語で言えば、これは最小のスパニング ツリー問題であり、1 つのエッジが事前に選択されており、スパニング ツリーに属している必要があるという追加の制約が付いています。 

入力サイズを見れば、これが自明ではない理由が明らかになります。 まで$10^5$頂点と$2 \cdot 10^5$エッジの場合、すべてのサブセットを考慮したり、エッジの変更ごとにスパニング ツリーを最初から再計算したりするソリューションは遅すぎます。 考えられる各エッジを強制した後でスパニング ツリーを単純に再計算すると、Kruskal または Prim のコストが 2 倍になります。$m$、これは実現可能な限界をはるかに超えています。 

微妙な点は、エッジを強制すると、そのエッジが最も高価なメンバーになるサイクルが生じる可能性があるため、実際には最適解がグローバル MST よりも悪くなる可能性があることです。 通常の MST を構築して、必要なエッジを「追加」するだけの不注意な実装は間違っています。 

具体的な失敗例として、エッジのある三角形を形成する 3 つのノードを想像してください。```
1 - 2 (cost 1)
2 - 3 (cost 2)
1 - 3 (cost 100)
```必須エッジが$1-3$、正解にはそれが含まれている必要があるため、自然な MST エッジを選択することはできません。 結果は 1 ～ 3 に他のエッジの 1 つを加えたものになり、コストは 101 になります。単純な MST では 3 が得られますが、制約が無視されるため無効です。 

## アプローチ

 強引なアイデアは、必須エッジを固定として扱い、すでに接続されているエンドポイントを持つ残りのグラフに対して最小スパニング ツリーを再計算することです。 概念的には、必要なエッジの 2 つのエンドポイントを「縮小」し、Kruskal を再度実行します。 

これが機能するのは、固定エッジを含むスパニング ツリーが、そのエッジがすでに選択されており、その端点がマージされているグラフのスパニング ツリーと同等であるためです。 ただし、Kruskal 自体が$O(m \log m)$。 

重要な点は、特別な方法で何も最初から再構築する必要がないということです。 他のすべてのエッジを処理する前に、単純にエッジを DSU 構造に強制的に挿入することができます。 必須エッジのエンドポイントが結合されたら、すべてのエッジに対して標準の Kruskal 順序付けを続行します。 

これが機能するのは、Kruskal のアルゴリズムが 2 つの異なるコンポーネントを接続する最小のエッジを常に取得して MST を構築するためです。 必要なエッジのエンドポイントを事前に結合し、そのコストを事前に追加することで、このエッジがすでに選択されているという条件をシミュレートし、その後のすべての決定が自然に適応します。 

唯一の微妙な点は、サイクルを形成するためにクラスカルによってスキップされる場合でも、必須エッジをカウントする必要があることです。 それはまさに強制労働組合が保証するものである。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | グラフ縮小によりエッジを強制した後に MST を再計算する |$O(m \log m)$リビルドごと |$O(m)$| 単純に繰り返したり実装すると遅すぎます。 
| あらかじめ組み込まれたエッジ付きのKruskal |$O(m \log m)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 必須のエッジを個別に識別したまま、コストの増加順にすべてのエッジを並べ替えます。 ソートにより、常に安価な接続を最初に考慮することが保証されます。これがクラスカルの正しさの基礎です。 
2. 各都市が独自のコンポーネントで始まる DSU 構造を初期化します。 これにより、構築中にどのノードがすでに接続されているかが追跡されます。 
3. 必須エッジのエンドポイントを直ちに結合し、そのコストを答えに追加します。 このステップにより、他の決定の前にエッジが構造に強制的に組み込まれ、後から除外されることがなくなります。 
4. ソートされた順序ですべてのエッジを繰り返します。 各エッジについて、そのエンドポイントが異なる DSU コンポーネントに属しているかどうかを確認します。 
5. 異なるコンポーネントにある場合は、答えにエッジを含めてコンポーネントを結合します。 これにより、標準の MST 構築とまったく同様に、サイクルを回避しながら接続が維持されます。 
6. すでに接続されている場合は、エッジをスキップします。 これを追加するとサイクルが形成され、スパニング ツリーのコストを削減できません。 

### なぜ効果があるのか

 Kruskal のアルゴリズムは、どの時点でも、選択されたエッジが処理されたエッジのプレフィックスに対して最小コストのフォレストを形成するという特性に依存しています。 必須エッジのエンドポイントを事前結合することにより、このエッジがその重みに関係なく初期フォレストの一部となるように強制します。 その時点以降、すべての決定は、これら 2 つの頂点が既に接続されているグラフ上で Kruskal を実行することと同じになります。これは、そのエッジをスパニング構造に強制することと同じです。 残りのエッジはすべてグローバルな昇順で処理されるため、貪欲な選択のプロパティは保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        return True

def main():
    n, m = map(int, input().split())
    j = int(input()) - 1

    edges = []
    forced = None

    for i in range(m):
        u, v, c = map(int, input().split())
        edges.append((c, u, v, i))
        if i == j:
            forced = (c, u, v)

    edges.sort()

    dsu = DSU(n)
    ans = 0

    fc, fu, fv = forced
    ans += fc
    dsu.union(fu, fv)

    for c, u, v, _ in edges:
        if dsu.union(u, v):
            ans += c

    print(ans)

if __name__ == "__main__":
    main()
```DSU の実装では、サイズによる半分と結合の反復によるパス圧縮を使用し、操作を効果的に一定の時間に保ちます。 実装の重要な詳細は、強制エッジ コストを処理の後ではなく前に追加することです。そうしないと、最終構造でサイクルを形成する場合に誤ってスキップされる可能性があるためです。 

ソートのステップにより、クラスカルのグローバルな貪欲な順序が確実に保持されます。 共用体チェックにより、サイクルが作成されないことが保証されます。これは、1 つのエッジが必須の場合でもスパニング ツリーが非循環のままでなければならないため、不可欠です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(m \log m)$| エッジのソートが優先されます。 DSU の操作はほぼ一定の償却時間です。 
| スペース |$O(n + m)$| エッジおよび DSU アレイ用のストレージ |

 制約により、最大で$2 \cdot 10^5$エッジ、および対数係数は一般的な制限内で簡単に管理できます。 ソートと DSU は 2 秒の制約内に十分収まります。

 ## 特殊なケース

 強制エッジがすでに自然な MST に属している場合でも、事前結合によって後の決定が変更されないため、アルゴリズムは引き続き正常に動作します。 たとえば、折れ線グラフでは、中央のエッジを強制することは、標準的なクラスカルの動作を単純に反映しています。 

強制エッジがサイクル内で最も高価な場合でも、DSU はそれを最初に受け入れ、最終的にはすべての安価なエッジがコンポーネントを接続します。 これは、貪欲な構造が違反されておらず、初期化時にのみ制約されることを示しています。 

グラフがすでに最小限に正確に接続されている場合$n-1$エッジを強制すると、そのコストが追加されるだけで、残りのアルゴリズムは結合を実行しないため、必要なエッジを含む一意のスパニング ツリーが正しく生成されます。
