 ## 解決策
 ## 問題の理解

 辺の長さが偶数の単位ブロックで構成される正方形のターゲットを構築しています。$x$。 正方形の色は均一ではありません。 代わりに、同心の正方形の「リング」で構成されます。 最も外側のリングには 1 つの色があり、次のリングには反対の色があり、この交互は内側に向かって中心まで続きます。 

各リングの厚さは 1 セルです。 したがって、当然のことながら$x \times x$正方形の場合、リングの数は$x / 2$。 外側のリングは最大の正方形の境界線であり、内側のリングはすべて、前の境界線を剥がして得られる小さな正方形です。 

重要な制約は、赤い羊毛が限られていることです。 私たちは持っていると言われています$n$赤いブロック、辺の長さを最大化したい$x$この交互リング構造に必要な赤血球の数が以下を超えないようにします。$n$。 

入力により得られるのは、$n$、出力は最大偶数です$x$記載されたターゲット内の赤血球の数が最大で$n$。 

制約$4 \le n \le 1000$これは、検索空間が十分に小さいため、可能なすべてのシミュレーションを直接行うことさえできないことを意味します。$x$実現可能でしょう。 ただし、パターンの構造により、赤血球の数を直接計算することができます。 

微妙なエッジ ケースとして、外側のリングの色がステートメント内で固定されていないことがありますが、最大化には問題ありません。 外側のリングが赤の場合、赤の使用量が最大になります。 白の場合、赤の使用は最小限に抑えられます。 私たちは可能な限り最大限のものを望んでいますので、$x$最大でも形成できる$n$赤のブロックでは、赤の消費が最悪のケース、つまり赤が​​外側の層から始まる場合を想定します。 

もう 1 つの微妙な点は、リングが個別であることです。 小型用$x$、完全な正方形のシェルを数える代わりに比例面積を仮定すると、手動の直感は失敗する可能性があります。 

たとえば、次のようなとき$x = 4$、リングは2つあります。 外側のリングが赤の場合は、すでに消費されています$16 - 4 = 12$細胞は内側から$2 \times 2$四角は白です。 ここでは、リングを連続レイヤーとして扱うか、色を平均する近似は失敗します。 

## アプローチ

 直接的なアプローチは、すべての辺の長さを均等にしてみることです。$x = 2, 4, 6, \dots$そして、それぞれに必要な赤血球の数を計算します。 それぞれについて$x$、同心リングをシミュレートします。 各リングは、その色に応じて、その全周囲領域 (実際には全正方形領域から内側の正方形を差し引いた領域) のいずれかを提供します。 これらを合計すると、赤色の使用法が得られます。 

候補者ごとに$x$、この計算コストは$O(x^2)$正方形内のすべてのセルにマークを付けたり、数えたりする可能性があるためです。 すべての候補者にわたって、$x \approx \sqrt{n}$スケールの場合、これは指定された制約に対して小さいままですが、不要です。 

重要な観察は、パターンが完全に決定的であり、分析的に表現できることです。 各リングには辺の長さがあります$x, x-2, x-4, \dots$。 辺のリング内のセルの数$s$は：$$s^2 - (s-2)^2 = 4s - 4$$最も外側のリングが赤であると仮定すると、赤のセルは、最大のものから始まる交互のリングの合計になります。 これにより、問題は、減少する算術シーケンスに対する単純な交互の合計を計算することに縮小されます。 

ジオメトリをシミュレートする代わりに、存在する赤いレイヤーの数を直接計算し、それらの寄与を合計します。 以来$n \le 1000$、すべての偶数の値を安全に事前計算することもできます。$x$数百まで。 

主な改善点は、ジオメトリをレイヤー サイズの算術演算に置き換えることです。

 ## アルゴリズムのチュートリアル

 1. 辺の長さの候補を反復処理する$x$偶数サイズのみが有効であるため、2 から開始して 2 ずつ増加します。 それぞれをテストします$x$潜在的な答えとして。 
2. それぞれについて$x$、リングの数を計算します。$x / 2$。 各リングは辺の正方形の境界線に対応します$s = x, x-2, x-4, \dots, 2$。 
3.恒等式を使用して各リングのサイズを計算します。$s^2 - (s-2)^2 = 4s - 4$。 これにより、グリッドを明示的に構築することが回避され、そのリングに属するセルの数が直接カウントされます。 
4. 一番外側のリングを赤から順に色を割り当てます。 1 つおきのリング (シーケンス内の位置 0、2、4 など) のサイズを合計します。 これにより、その赤の合計使用量が得られます$x$。 
5. 計算された赤の使用量が以下の場合$n$、ベストアンサーを更新します$x$。 それ以外の場合は、サイズが大きくなるため、必要に応じて早めに停止してください。$x$総面積が増加するだけなので、赤の使用量が増加します。 

### なぜ効果があるのか

 重要な不変条件は、リングへの分解によって正方形が、サイズが辺の長さのみに依存する互いに素なセルのセットに分割されることです。 有効な色はすべて、これらのリングを交互に配置することによって完全に決定されるため、赤血球の数は次の要素のみに依存します。$x$、内部取り決めによるものではありません。 ジオメトリとカラーリングは両方とも固定されており決定論的であるため、リングの寄与を計算すると、近似せずに赤血球の真の数が正確に再構築されます。 総面積の単調増加$x$サイズが超過すると、$n$、より大きなサイズもすべてそれを超えます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def red_needed(x):
    total = 0
    color_red = True
    s = x
    while s > 0:
        ring = s * s - (s - 2) * (s - 2) if s > 2 else 4
        # simpler: ring = 4*s - 4 for s > 2, and 4 for s = 2
        if color_red:
            total += ring
        color_red = not color_red
        s -= 2
    return total

n = int(input().strip())

ans = 0
x = 2
while True:
    need = red_needed(x)
    if need <= n:
        ans = x
    else:
        break
    x += 2

print(ans)
```機能`red_needed`固定の赤血球の数を計算します。$x$リングの側面の長さを反復することによって。 各反復では、現在の正方形のサイズから 2 が減算され、内側に向かって次のレイヤーに移動します。 

交互のブール値`color_red`これにより、外側のリングから始まる色の交互が正しくモデル化されることが保証されます。 蓄積は、現在のリングが赤の場合にのみ発生します。 

メインループはインクリメントします$x$2 ずつ増加し、必要な赤血球の数を超えるとすぐに停止します$n$、構造の単調性に依存します。 

## 実用的な例

 ### 例 1:$n = 4$私たちもテストします$x$。 

| × | リング | 赤の計算 | 赤の合計 | 有効 |
 | --- | --- | --- | --- | --- |
 | 2 | 1 | 4 | 4 | はい |
 | 4 | 2 | 16 - 4 = 12 (外側の赤のみ) | 12 | いいえ |

 のために$x = 2$、サイズのリングは 1 つだけです$2 \times 2$なので、赤の使用量は 4 です。$x = 4$, 外環はすでに予算を超えているので、答えは2です。 

### 例 2:$n = 20$| × | リング | 赤いレイヤー | 赤の合計 | 有効 |
 | --- | --- | --- | --- | --- |
 | 2 | 1 | 2×2 | 4 | はい |
 | 4 | 2 | 4×4のみ | 12 | はい |
 | 6 | 3 | 6×6 + 2×2 | 36 + 4 = 40 | いいえ |

 ここでそれがわかります$x = 6$、外側の理由により、赤の要件が大幅に上昇します$6 \times 6$リングが優勢。 有効な最大値$x$は4です。 

これらのトレースは、成長が直線的ではないことを示しています。$x$、しかし正方形層の蓄積に依存します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return main()

def main():
    n = int(input().strip())

    def red_needed(x):
        total = 0
        color_red = True
        s = x
        while s > 0:
            ring = s * s - (s - 2) * (s - 2) if s > 2 else 4
            if color_red:
                total += ring
            color_red = not color_red
            s -= 2
        return total

    ans = 0
    x = 2
    while True:
        if red_needed(x) <= n:
            ans = x
        else:
            break
        x += 2
    return str(ans)

# provided sample-like checks
assert run("4") == "2", "small boundary"

# custom cases
assert run("12") == "4", "just enough for 4x4"
assert run("20") == "4", "6x6 too large"
assert run("4") == "2", "minimum case"

 ## 特殊なケース

 1 つのエッジ ケースは最小の入力です。$x = 2$有効です。 のために$n = 4$、アルゴリズムは次のように評価します$x = 2$、それを受け入れてから試してください$x = 4$、予算を超えていることがわかり、正しく 2 が返されます。 

もう 1 つのエッジケースは次のような場合です$n$複数のレイヤーが寄与するのに十分な大きさです。 のために$n = 1000$、アルゴリズムは増加し続けています$x$赤い領域の累積が制限を超えるまで。 各ステップで正確なリングの合計が再計算されるため、浮動誤差が蓄積したり、部分的なレイヤーを誤ってカウントしたりするリスクはありません。 

3 番目のケースは、新しい外側のリングを追加すると赤の使用量が大幅に増加する移行点です。 これは自然に処理されます。$x$は最初から独立して評価されるため、以前の近似は引き継がれません。
