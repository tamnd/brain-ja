 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$長方形のグリッドであり、各セルを 0 または 1 で埋める必要があります。セルは、隣接するセル間でのみ移動が許可される等しい値の最大グループの一部である場合、連結コンポーネントに属します。 2 つのセルが同じコンポーネント内にあるのは、それらが同じ値のパスを介して接続されている場合のみです。 

タスクは、最大でもこれら 2 つのシンボルを使用し、正確に一致するグリッドを構築することです。$k$接続されているコンポーネントの合計。 

制約により、最大サイズのグリッドが許可されます$1000 \times 1000$、したがって、構造はセルの数において線形である必要があります。 セルごとの二次演算や変更ごとにフラッド フィルを繰り返すと、すぐに遅すぎます。 

重要な点は、コンポーネントが両方の値にわたってグローバルにカウントされることです。 すべてを 0 で埋めてからローカルで「コンポーネントを追加」するような素朴なアプローチは失敗します。1 つの領域を変更すると、隣接効果によって離れた構造が意図せずマージまたは分割される可能性があるためです。 

重要なエッジケースの 1 つは次のような場合です。$k = 1$。 これは簡単なことです。グリッド全体を 1 つの値で埋める必要があります。 

もう 1 つのエッジケースは次のような場合です$k = n \cdot m$。 これには、すべてのセルが独自のコンポーネントであることが必要ですが、これは、隣接する 2 つのセルが同じ値を共有しない場合にのみ可能です。 

3 番目の、それほど明白ではないケースは、構築で孤立したセルが作成されるが、構築の後半で形成された同じ値の隣接セルのチェーンを介してそれらのセルを誤って接続する場合です。 これは、貪欲なローカル カラーリング戦略の主な失敗モードです。 

## アプローチ

 強引なアイデアは、グリッドをグラフとして扱い、セルごとに値を割り当て、各割り当て後にフラッド フィルを実行して接続されたコンポーネントの数を追跡することです。 すべての可能性を検討すれば常に正しい答えが得られますが、各ステップにはコストがかかります$O(nm)$、そして、あります$nm$につながるステップ$O(n^2 m^2)$、それは限界をはるかに超えています。 

重要な点は、実際には検索する必要がないということです。 必要なのは、コンポーネントを制御しやすい基本構成と、コンポーネントを 1 つずつマージするための制御された方法だけです。 

開始点として非常に便利なのは、市松模様のパターンです。 設定すると$a[i][j] = (i + j) \bmod 2$の場合、隣接する 2 つのセルは等しくありません。 すべての単一セルは独自の連結成分であるため、成分の合計数は正確に次のようになります。$n \cdot m$、これは可能な最大値です。 

この最大値から、タスクは純粋に制御された削減になります。$n \cdot m$コンポーネントまで$k$。 2 つの隣接するセルを強制的に等しくするたびに、正確に 2 つのコンポーネントが 1 つにマージされ、合計数が 1 つ減ります。 正確に実行すれば$n \cdot m - k$このようなマージを行うことで、目標を達成できます。 

グリッド グラフの構造では、グリッドのスパニング ツリーがすでに提供しているため、必要なすべてのマージをサポートするのに十分な隣接エッジがあることが保証されます。$nm - 1$独立したマージ操作。 チェッカーボードの初期化により、マージが適用された時点でクリーンなローカル操作であることが保証されます。

 ## アルゴリズムのチュートリアル

 現在の有効なグリッドを維持しながら、段階的に答えを構築します。 

1. チェッカーボード パターンを使用してグリッドを初期化します。$grid[i][j] = (i + j) \bmod 2$。 これにより、最初にすべてのセルが独自の連結コンポーネントを形成することが保証されるため、次から始めます。$n \cdot m$コンポーネント。 
2. カウンターを維持する`components = n * m`。 
3. 行優先の順序でグリッドを移動します。 各セルについて、コンポーネントの数がまだ多くある場合にのみ、コンポーネントの数を減らすように試みます。$k$。 
4. 細胞の場合$(i, j)$マージすることにした場合は、すでに処理された隣接する 1 つのセル (通常は左のセル) の値を強制的に取得します。$(i, j-1)$存在する場合は上のセル、存在しない場合は上のセル$(i-1, j)$。 これにより、以前は別々だった 2 つのコンポーネント間に意図的な接続が作成されます。 
5. 新しい値を割り当てた後、値を減らします。`components`ちょうど 2 つのコンポーネントが 1 つにマージされているため、1 倍になります。 
6. マージの適用を一度停止します`components == k`、残りのセルはすべてチェッカーボード パターンから変更しないままにします。 

以前に処理された隣接ノードと常にマージする理由は、グリッド全体に予期せず広がる可能性のあるマージのサイクルが誤って作成されるのを防ぐためです。 

### なぜ効果があるのか

 チェッカーボード グリッドにより、変更前にすべてのセルが確実に分離されます。 すべてのマージ操作は、選択したセルごとに 1 回だけ適用され、以前は分離されていた 2 つのコンポーネントのみを接続します。 各マージは、グリッド上に広がるフォレストの 1 つのエッジを追加することに対応するため、プロセスは正確にフォレストを構築します。$k$接続されたコンポーネント。 

そのステップで適用される明示的なマージ操作を介する場合を除き、すでに等しい値になっている 2 つの領域間に新しい隣接関係を作成する値を割り当てることがないため、意図しないマージは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    grid = [[(i + j) & 1 for j in range(m)] for i in range(n)]
    
    components = n * m
    
    for i in range(n):
        for j in range(m):
            if components == k:
                break
            if i == 0 and j == 0:
                continue
            
            # try to merge this cell with a processed neighbor
            if j > 0:
                grid[i][j] = grid[i][j - 1]
            else:
                grid[i][j] = grid[i - 1][j]
            
            components -= 1
        if components == k:
            break
    
    print("YES")
    for row in grid:
        print("".join(map(str, row)))

if __name__ == "__main__":
    solve()
```実装は、最大の分解状態であるチェッカーボードを構築することから始まります。 すでに訪問した近傍にのみマージし、割り当ての一貫性を確保するため、走査順序が重要になります。 

停止条件は重要です。正確に到達したら$k$そうしないと、オーバーシュートして最終構造の制御を失うことになります。 

変換ステップ`grid[i][j] = grid[i][j - 1]`または、上のセルからの操作が、実際にコンポーネントの数を減らす唯一の操作です。

 ## 特殊なケース

 のために$k = 1$、アルゴリズムはチェッカーボードから始まりますが、すべてのコンポーネントが単一の接続された領域に折りたたまれるまで、すぐにマージを実行します。 すべてのマージは単純に隣接する処理済みセル間で同等性を伝播し、最終的には均一なグリッドを生成します。 

のために$k = n \cdot m$の場合、最初のチェッカーボードがすでに最大数のコンポーネントを提供しているため、マージはまったく実行されません。 トラバーサル ループは、停止条件により直ちに終了します。 

次のような非常に薄いグリッドの場合$1 \times m$または$n \times 1$、チェッカーボードは依然として値を正しく交互に配置し、各マージ操作は厳密に線形チェーン内のコンポーネントを削減します。隣接関係は 1 次元であるため、意図しないマージが作成されることはありません。
