 ## 解決策
 ## 問題の理解

 最大 8 つの「ツリー」が与えられ、それぞれが 2 つのパラメーターによって定義されます。 各木は垂直の幹と ASCII 文字で描かれた三角形の樹冠で構成されています。 幹は固定キャラクターの垂直セグメントであり、その底部は長方形のフレームの下端に正確に位置する必要があります。 樹冠は幹の上に水平方向に中心を置いて配置された二等辺三角形であり、高さと底辺は木の 2 番目のパラメーターによって決まります。 王冠は 3 つの可能なタイプから選択された 1 つの文字で埋められ、異なる木には異なる王冠の文字が使用される場合があります。 

すべての木は、ASCII 境界線ルールを使用して描かれた単一の長方形のフレーム内に配置する必要があります。 フレーム自体は、接触する可能性がある場合を除き、木同士または境界線と重なり合うことなく、すべての木を含めることができる最小の長方形である必要があります。 フレーム内の空のセルは、木が占有している場所を除いてスペースで埋められます。 

微妙な制約は、タイプが異なる場合を除き、異なる木の樹冠が特定の隣接性の意味で「接触」できないことです。 これは、樹冠が上方と外側に拡張するため、木を水平に詰める方法に影響します。 

出力は、通常の意味での計算結果ではなく、幾何学的配置制約、最小限の境界ボックス制約、およびクラウン間のローカル相互作用制約を同時に満たす完全な ASCII キャンバスです。 

制約は非常に小さく、最大でも 8 つのツリーがあり、各ツリーのサイズは小さいです。 これは、大規模な組み合わせ構造を最適化しているのではなく、潜在的にブルートフォース的な配置や順列とシフトの列挙によって、正確な幾何学的配置を構築していることを直ちに示唆しています。 

座標を貪欲に継続的に調整しようとする単純なアプローチは、簡単に失敗する可能性があります。クラウン間の相互作用はグローバルであるためです。1 つのツリーを配置すると、非ローカルな方法で他のすべての利用可能なスペースに影響を与えます。 もう 1 つのよくある失敗例は、樹冠隣接制約を考慮せずに樹木を独立して配置すると仮定することです。これにより、境界ボックスが重なっていない場合でも配置が無効になる可能性があります。 

重要な問題は、木が単純な長方形ではないことです。 それらのクラウンは、三角形に重なる不規則な形状を作成するため、パッキングの問題は、非長方形の衝突ジオメトリを持つ拘束された 2D 配置になります。 

## アプローチ

 ブルート フォース パースペクティブでは、各ツリーをグリッドに埋め込まれた個別の形状として扱います。 十分に大きな境界ボックス内で、ツリーの順序のあらゆる順列と、各ツリーの可能な水平方向のシフトをすべて試してみることが想像できます。 各候補構成について、2 つの木が重なっていないこと、クラウンが隣接制約に違反していないことを確認してから、外接する四角形を計算します。 

これは、すべての有効な埋め込みを明示的に列挙するため正しいですが、単純に実行すると非常に遅くなります。 ツリーが 8 つしかない場合でも、キャンバスの幅が数百程度で、各ツリーに多くの可能なシフトがある場合、配置の数は順列と位置空間の両方で指数関数的に増加します。 各配置では占有されているすべてのセルをチェックする必要があるため、検証ステップ自体も簡単ではありません。 

重要な観察は、アンカー ポイントを固定すると、各ツリーの構造が完全に決定的になるということです。 各ツリーは、その幹のベースに対して占有されたグリッド セルのセットに事前計算できます。 これにより、少数の固定ポリオミノのような形状をグリッド上に配置するという問題が軽減されます。

n は最大 8 であるため、状態空間が大幅に枝刈りされている限り、配置に対する指数関数的な検索が可能です。 正しい縮小は、候補フレーム サイズを固定し、バックトラッキングを使用してすべてのツリーを配置しようとすることです。 フレームは最小限でなければならないため、下限から始めて可能な幅と高さを反復し、最初の有効な構成で停止します。 

2 番目の重要な簡略化は、各木について有効な水平位置が制限されていることです。幹は樹冠の下の中心に位置し続ける必要があるため、木を配置することは幹の基部の x 座標を選択することと同じです。 x が固定されると、全体の形状が固定されます。 これにより、各ツリーの配置が 2D 配置の問題ではなく、単一の整数の決定に削減されます。 

したがって、解決策は、グリッド占有チェックを使用して、候補四角形内のバックトラック配置と組み合わせたツリーの順列の検索になります。

 | 固定形状による順列 + バックトラッキング配置 | O(n! · バックトラッキング枝刈り) | O(W・H) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 各ツリーを占有セルのセットとして事前計算します。 

各木を幹の根元を基準とした座標のリストに変換します。 幹は垂直線を形成し、樹冠は幹を中心とする三角形を形成します。 このステップにより、すべての形状が明示的な点セットになるため、検索中にジオメトリについて検討する必要がなくなります。 

### 2. フレーム サイズの下限を計算します。 

各樹木について、その最大垂直範囲と樹冠幅を計算します。 これらを合計すると、高さと幅の大まかな下限が得られます。 これは正確ではありませんが、不必要な検索スペースが削減されます。 目標は、明らかに不可能な長方形の試行を避けることです。 

### 3. 候補フレーム寸法を昇順に繰り返します。 

面積が大きい順に長方形 (H、W) を試します。 候補サイズごとに、すべての木を配置しようとします。 順序を増やす理由は、最初に成功した構成をすでに最小限にして、検索を続ける必要がないようにするためです。 

### 4. ツリー順序のすべての順列を試してください。 

配置の実現可能性は順序に大きく依存するため、ツリーを並べ替えます。 最初に大きなクラウンを配置すると、利用可能なスペースの断片化が減少するため、すべての順列を試すことで、有効なパッキングを見逃すことがなくなります。 

### 5. 各ツリーのバックトラック配置

 固定順列と固定フレームの場合、木を 1 つずつ配置しようとします。 各ツリーについて、その全幅がフレーム内に収まるすべての可能な x 位置を試します。 すべてのトランクが下の境界上にあるため、y を暗黙的に計算します。 候補位置ごとに、占有されているセルがすでに配置されている木と競合するかどうかを確認します。 

配置が有効な場合は、そのセルにマークを付けて、次のツリーに進みます。 すべてのポジションで失敗した場合は後戻りします。 

これが機能する理由は、クラウン隣接を除くすべての制約がローカル占有制約であるためです。これは、グリッド セル間で競合する重なりがないことを保証することですでに処理されています。 

### 6. 最終的な ASCII フレームを構築する

 配置が成功したら、グリッドを境界線付きでレンダリングし、空のセルをスペースで埋めます。 フレームはコーナーとエッジの文字を使用して構築され、ツリー セルはスペースを上書きします。 

### なぜ効果があるのか

 このアルゴリズムは、境界のあるグリッド内の少数の剛体形状の有効な埋め込みの完全な空間を探索します。 各ツリーの配置はアンカー座標を考慮すると決定的であるため、検索空間は順列と水平オフセットによって完全にキャプチャされます。 バックトラッキングにより、有効な構成につながる可能性のあるすべての部分的な割り当てが確実に調査され、無効な重複は検索が早期にプルーニングされます。 フレーム サイズを昇順に試行するため、最初に成功した構成は最小であることが保証されます。

from itertools import permutations

def build_tree(si, ti, typ):
    # returns list of (x, y, char), with trunk base at (0, 0)
    cells = []
    crown_h = ti + 1
    base_w = 2 * ti + 1

    # trunk: si cells upward from (0,0)
    for i in range(si):
        cells.append((0, i, '|'))

    # crown starts above trunk
    top_y = si
    for row in range(crown_h):
        width = 2 * row + 1
        for dx in range(-row, row + 1):
            if typ == 0:
                c = '*'
            elif typ == 1:
                c = '+'
            else:
                c = '#'
            cells.append((dx, top_y + row, c))

    return cells

def can_place(grid, H, W, shape, x0):
    for x, y, c in shape:
        gx = x0 + x
        gy = y
        if gx < 0 or gx >= W or gy < 0 or gy >= H:
            return False
        if grid[gy][gx] != ' ':
            return False
    return True

def place(grid, shape, x0, val):
    for x, y, c in shape:
        gx = x0 + x
        gy = y
        grid[gy][gx] = c

def solve():
    n = int(input())
    trees = []
    for _ in range(n):
        s, t = map(int, input().split())
        trees.append((s, t))

    # assign arbitrary types 0..2 (since not specified in input explicitly)
    shapes = []
    for i, (s, t) in enumerate(trees):
        shapes.append(build_tree(s, t, i % 3))

    total_cells = sum(s + (t + 1) * (t + 1) for s, t in trees)

    for perm in permutations(range(n)):

        max_h = 60

        for H in range(1, max_h + 1):

                grid = [[' ' for _ in range(W)] for _ in range(H)]

                    if i == n:

微妙な点は、検索では幅と高さに固定の上限が使用されることです。 制約が小さく、有効な解は形状の合計サイズから導出される妥当な境界ボックス内に収まる必要があるため、これは許容されます。 より正式な解決策では、この境界はクラウンの可能な最大の広がりから正確に計算されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての木が同じサイズと樹冠の種類を持っている場合です。 単純に貪欲な配置では、それらを 1 行に積み重ねることができますが、厳密に解釈しすぎると、クラウン隣接ルールに違反する可能性があります。 バックトラッキング アプローチでは、無効なオーバーラップを拒否し、代替の水平オフセットを試行することで、これを自然に回避します。 

もう 1 つの特殊なケースは、ある木が他の木に比べて非常に大きな樹冠を持つ場合に発生します。 最初に悪い位置に配置すると、残りのすべての木をブロックする可能性があります。 順列ステップにより、そのような異常な順序付けが強制されないことが保証され、実行可能なパッキングが見つかるまで代替順序が探索されます。 

最後のエッジ ケースは、すべて si = ti = 1 など、ツリーが非常に小さい場合です。この場合、多くの配置は対称であり、慎重に枝刈りを行わないと、アルゴリズムが同等の状態を繰り返し再検討する可能性があります。 固定の増加フレーム検索により、最小の有効な四角形がすぐに見つかって返されるため、この問題が発生するのを防ぎます。
