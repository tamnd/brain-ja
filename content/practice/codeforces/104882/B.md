 ## 解決策
 ## 問題の理解

 2 人のプレーヤーが、2 つの異なる公式を使用して同じ問題に数値スコアを割り当てます。 1 つはステートメントの長さを取得してコードの長さで累乗し、もう 1 つは役割を交換します。 正の整数 x と y の各ペアについて、x を y に累乗したものが、y を x に累乗したものより小さいか、等しいか、または大きいかを判断する必要があります。 

入力は単一の整数ペアです。 各整数は最大 10 億まで大きくなり、累乗の直接計算は即座に除外されます。 単一の単純な電力計算であっても、乗算を繰り返して実装すると標準の整数範囲をオーバーフローし、桁数に指数関数的な時間がかかります。 これにより、式を明示的に評価せずに比較するソリューションが推進されます。 

値が小さいか等しい場合、単調な直感を壊すような微妙な困難が生じます。 たとえば、(2, 4) と (4, 2) は基数が異なっていても、どちらも 16 と評価されるため、等しい値を生成します。もう 1 つのエッジ ケースは、数値のいずれかが 1 である場合です。x が 1 で y が大きい場合、1^y は常に 1 ですが、y^1 は y と等しいため、比較は完全に y が 1 を超えるかどうかによって決定されます。対称的に、y が 1 の場合、比較は反転します。 

これらの境界状況では、対数などの一般的な近似手法が正確な比較と一致する必要があるため、これらの特殊なケースが重要になります。 

## アプローチ

 直接的なブルート フォース アプローチでは、x^y と y^x を明示的に計算し、結果を比較します。 これは問題の定義と正確に一致するため、概念的には正しいです。 問題は、結果がすぐに 64 ビットの制限をはるかに超えて大きくなり、その計算には y の乗算が必要になるため、大きな入力では x^y を表すことさえ不可能であることです。 

x と y が両方とも大きい最悪のケースでは、およそ O(y + x) の乗算が必要になりますが、それぞれの乗算が最大 10^9 になる場合はまったく実行不可能です。 

重要な点は、正確な値は必要ではなく、その順序だけが必要であるということです。 単調変換を適用すると、指数式の大きさの比較を軽減できます。 対数は厳密に増加するため、x^y と y^x を比較することは、y * log(x) と x * log(y) を比較することと同じです。 これにより、べき乗が完全に削除され、テスト ケースごとの定数時間演算に置き換えられます。 

ただし、この変換では両方の数値が 1 より大きいことを前提としています。どちらかの値が 1 の場合、対数は数値的に適切に動作せず、元の式が直接単純化されるため、これらのケースは個別に処理する必要があります。 小さなエッジ値に対する直接推論と一般的なケースに対する対数比較を組み合わせることで、完全な解決策が得られます。

 ## アルゴリズムのチュートリアル

 アイデアは、比較を x または y で増加しないものに減らすことです。 

1. 2 つの整数 x と y を読み取ります。 これらは、明示的に計算することのない 2 つの指数式を定義します。 
2. x が y と等しい場合は、すぐに等価性を返します。 値が同じ場合、基数と指数を交換しても何も変わらないため、両方の式は同一になります。 
3. x が 1 の場合、x^y は y に関係なく常に 1 になります。 y^1 は y と等しいため、比較は y が 1 より大きいかどうかをチェックすることになります。 
4. y が 1 の場合、状況は対称です。 y^x は 1 に等しく、x^y は x に等しいため、結果は x が 1 を超えるかどうかによって異なります。 
5. どちらの値も 1 でない場合は、量 y * log(x) と x * log(y) を比較します。 対数はべき乗の下で順序を維持するため、より大きな積はより大きな元の指数表現に対応します。 
6. どちらが大きいかに基づいて比較結果を返します。

重要なアイデアは、非常に大きな数値の比較を、標準の浮動小数点演算で安定した 2 つの実数値式の比較に変換するということです。 

### なぜ効果があるのか

 変換は対数関数の単調性に依存します。 ログは正の引数に対して厳密に増加するため、これを適用すると順序が維持されます。 したがって、x^y と y^x は対数を介して比較できます: log(x^y) = y log x および log(y^x) = x log y。 この等価性は実算術でも正確に当てはまり、数値の不安定性が問題となる唯一のケースは、x または y が 1 に等しい場合、つまり対数がゼロに近づき、式が崩壊して個別に処理される単純な整数の比較になる場合です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def solve():
    x, y = map(int, input().split())

    if x == y:
        print("=")
        return

    if x == 1:
        print("<" if y > 1 else "=")
        return

    if y == 1:
        print(">" if x > 1 else "=")
        return

    left = y * math.log(x)
    right = x * math.log(y)

    if abs(left - right) < 1e-12:
        print("=")
    elif left > right:
        print(">")
    else:
        print("<")

if __name__ == "__main__":
    solve()
```コードの構造は、問題の論理的分解を反映しています。 最初の等価性チェックにより、不必要な浮動小数点演算が回避されます。 x が 1 に等しい、または y が 1 に等しい場合の 2 つの分岐により、数値比較が不安定になる縮退対数のケースが除去されます。 一貫した底が機能し、乗算構造が相殺されるため、最後の比較では自然対数が使用されます。 

2^4 や 4^2 のような値は正確に一致する必要がありますが、ログを通じて計算されるときにわずかなイプシロンで異なる可能性があるため、許容しきい値は浮動小数点の丸め誤差を処理します。

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    x, y = map(int, sys.stdin.readline().split())

    if x == y:
        return "="

    if x == 1:
        return "<" if y > 1 else "="

    if y == 1:
        return ">" if x > 1 else "="

    left = y * math.log(x)
    right = x * math.log(y)

    if abs(left - right) < 1e-12:
        return "="
    elif left > right:
        return ">"
    else:
        return "<"

assert run("3 5") == ">", "sample 1"
assert run("7 7") == "=", "sample 2"

assert run("1 10") == "<", "x is 1"
assert run("10 1") == ">", "y is 1"
assert run("2 4") == "=", "classic equality case"
assert run("5 2") == ">", "reverse comparison"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 10 | < | ベースは 1 つのエッジケースです。 
| 10 1 | > | 対称エッジケース |
 | 2 4 | = | 自明でない等価の場合 |
 | 5 2 | > | 一般的な順序付けの正確さ |

 ## 特殊なケース

 x が 1 に等しく、y が大きい場合、アルゴリズムはすぐに小さい値を返します。 入力 1 10 の場合、チェックは 3 番目のステップでトリガーされ、1^10 が 10^1 より小さいことが出力されます。 対数分岐には決して入らないため、log(1) の計算が回避され、不必要な浮動小数点比較が防止されます。 

y が 1 で、x が 10 1 のように大きい場合、対称分岐は対数を使用せずに正しい順序付けを保証します。 これにより、log(1) への誤った依存 (ゼロになり、比較が歪む) が防止されます。 

x と y が両方とも小さいが自明ではない配置 (2 4 など) の場合、両方の式が 16 と評価されるため、対数比較で等価性が正しく捉えられます。 y log x と x log y の計算値は一致し、イプシロンしきい値によってそれらが等しいと分類され、浮動小数点丸めの下で正確さが維持されます。
