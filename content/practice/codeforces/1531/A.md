 ## 解決策
 ## 問題の理解

 シンガー ハウス ドームの照明の色を制御するチャットボットの動作をシミュレートする必要があります。 

最初はドームに色が付いています`blue`、色の変更は許可されています。 ボットは一連のメッセージを受信します。 ロック状態を変更するメッセージもあれば、色の変更を要求するメッセージもあります。 

メッセージ`lock`今後の色の変更を無効にします。 システムがすでにロックされている場合は、何も起こりません。 

メッセージ`unlock`色の変更を再度有効にします。 システムがすでにロック解除されている場合は、何も起こりません。 

などのカラーメッセージ`red`、`green`、 または`violet`システムが現在ロック解除されている場合にのみ、ドームの色が変更されます。 システムがロックされている場合、メッセージは無視されます。 

入力すると、完全なメッセージ履歴が時系列で表示されます。 すべてのメッセージを処理した後、最終的なドームの色を決定する必要があります。 

制約は非常に小さいです。 メッセージは最大 100 件なので、単純なシミュレーションでも適切な制限時間内に簡単に収まります。 各メッセージは現在の状態にのみ影響するため、高度なデータ構造や最適化は必要ありません。 

間違いの主な原因は、無視された操作を正しく処理することです。 

次の例を考えてみましょう。```
3
lock
red
green
```正しい答えは次のとおりです。```
blue
```後`lock`、色の変更は無効になります。 どちらのカラー メッセージも無視されるため、初期カラーは変更されません。 

もう 1 つの微妙なケースは、ロック操作が繰り返されることです。```
4
lock
lock
unlock
red
```正しい答えは次のとおりです。```
red
```2番目`lock`システムはすでにロックされているため、何も行われません。 明示的に設定せずに状態を切り替える不注意な実装では、誤った結果が生成されます。 

もう 1 つのケースでは、ロック解除操作が繰り返されます。```
3
unlock
unlock
violet
```正しい答えは次のとおりです。```
violet
```システムはすでにロックが解除されているため、ロック解除メッセージは効果がありません。 最終的な色の変更は通常どおり適用されます。 

## アプローチ

 最も直接的なアプローチは、説明どおりにボットをシミュレートすることです。 現在の色と色の変更がロックされているかどうかという 2 つの変数を維持します。 メッセージを 1 つずつ処理し、ルールに従ってこれらの変数を更新します。 

すべてのメッセージは状態を変更する可能性があるため、問題の総当り解釈はすでに最適です。 正しいソリューションでは、すべてのメッセージを少なくとも 1 回検査する必要があります。 メッセージが最大 100 個の場合、必要な操作は 100 回のみであり、無視できる程度です。 

重要な点は、システム全体の状態が、現在の色とロック ステータスという 2 つの情報だけで表されるということです。 メッセージが処理されると、履歴情報は必要ありません。 各メッセージは現在の状態にのみ影響するため、単一のリニア スキャンで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n) | お(1) | 承認済み |
 | 最適な状態の追跡 | O(n) | お(1) | 承認済み |

 この問題では、総当たりシミュレーションと最適解は実際には同じアルゴリズムです。 

## アルゴリズムのチュートリアル

 1. 現在の色を次のように初期化します。`"blue"`なぜなら、ドームは青いイルミネーションから始まるからです。 
2. ロック状態を次のように初期化します。`False`色の変更は最初は許可されているためです。 
3. 各メッセージを時系列に処理します。 
4. メッセージが表示された場合、`"lock"`、ロック状態を に設定します。`True`。 

これは、将来の色の変更がブロックされるという仕様と一致します。 
5. メッセージが表示された場合、`"unlock"`、ロック状態を に設定します。`False`。 

これにより、色の変更が再び有効になります。 
6. それ以外の場合、メッセージは色を表します。 

ロック状態が`False`、現在の色をこのメッセージに更新します。 

ロック状態が`True`、メッセージを無視してください。 
7. すべてのメッセージが処理された後、現在の色を出力します。 

### なぜ効果があるのか

 処理中のあらゆる瞬間に、ペアは`(current_color, locked)`同じメッセージのプレフィックスを処理した後の実際のボットの状態と正確に一致します。 

初期化は問題のステートメントと一致します。 各メッセージは公式ルールに従って処理され、ロック状態または色のいずれかが更新されます。 すべての状態遷移が正確に再現されるため、維持される状態は各ステップの後でも実際のシステムと同じままになります。 最後のメッセージの後、保存された色が正確にドームの最終色になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    color = "blue"
    locked = False

    for _ in range(n):
        msg = input().strip()

        if msg == "lock":
            locked = True
        elif msg == "unlock":
            locked = False
        else:
            if not locked:
                color = msg

    print(color)

if __name__ == "__main__":
    solve()
```このソリューションでは、アルゴリズムの説明で特定された 2 つの状態が正確に保持されます。 

変数`color`現在のドームの色を保存します。 それは次のように始まります`"blue"`それがステートメントで指定された初期条件だからです。 

変数`locked`色の変更が現在ブロックされているかどうかを記録します。 それは次のように始まります`False`、色の変更が許可されていることを意味します。 

すべてのメッセージについて、最初にそれがロック コマンドであるかロック解除コマンドであるかを確認します。 これらのコマンドはロック状態を直接設定します。 繰り返しのため状態を切り替えません`lock`または`unlock`メッセージは無害でなければなりません。 

残りのメッセージは必ず 7 つの色の名前のいずれかになります。 システムがロックされていない場合にのみ色が更新されます。 ロックされている場合、メッセージは必要に応じて無視されます。 

入力によってすべてのメッセージが許可されたセットに属することが保証されるため、特別な境界処理は必要ありません。
