 ## 解決策
 ## 問題の理解

 私たちに与えられたコレクションは、$n$それぞれが同じ長さの異なる文字列$m$。 単語内の任意の 2 つの位置は何度でも交換できるため、文字列に対して許可される唯一の操作は文字を自由に並べ替えることです。 これは、各単語について、実際にはその元の順序には制約されず、単語に含まれる複数の文字セットによってのみ制約されることを意味します。 

インデックスごとに$i$、すべての単語を独立して並べ替えることができるかどうかを尋ねます。$i$-番目の単語は厳密に辞書順にすべての単語の中で最小になります$n$結果の文字列。 

したがって、単語ごとに、その文字の任意の順列を選択することができ、最終的な文字列を辞書の順序で比較します。 選択した単語が正しくなるように順列を割り当てる方法が存在するかどうかを知りたいのです。$w_i$他のものよりも厳密に小さいです。 

重要な制約は、再配置に関しては各単語が独立しているということですが、すべての単語はグローバルな順序条件を満たす方法で同時に配置されなければならないということです。 

以来$n, m \le 3000$、順列のすべてのペアを比較する、または配置をシミュレートしようとするソリューションは遅すぎます。 各単語に対して最適な形式を生成し、他のすべての単語と比較するという素朴な試みは、すでに次のようになります。$O(n m \log m)$、候補単語ごとにこれを行うとコストがかかりすぎます。 

複数の単語が同様の文字分布を共有する場合、微妙な問題が発生します。 単独では「小さい」ように見える単語でも、他の単語も順序を最適化すると、強制的に大きくなることがあります。これは、すべての単語が同じ目的に向けて同時に最適化されるためです。 

## アプローチ

 強引なアイデアは、各単語を考慮することです$i$、次に、可能性を最大化するすべての単語の順列を構築しようとします。$i$辞書編集的に最小であること。 固定の場合$i$、可能な限り最小の文字列を貪欲に構築しようとすることもできます。$w_i$、他のすべての単語については、同じ複数の文字セットを使用しながら、できるだけ大きな文字列を構築します。 

単一の単語の場合、その文字をソートすると辞書編集上可能な最小の順列が得られ、逆にすると最大の順列が得られます。 したがって、それぞれについて単純なチェックを行います$i$次のようになります: 並べ替えて比較$w_i$ソートに対して$w_j$または逆転に対して$w_j$、解釈によって異なります。 

ただし、辞書編集的な比較は単語ごとに独立していないため、このアプローチは失敗します。 相対的な順序は最初の異なる位置にのみ依存し、異なる単語は単純なグローバル選択を壊す形でその違いを「遅らせる」可能性があります。 本当の難しさは、単に固定文字列を比較しているだけではなく、位置で厳密な最小値を誘導する一貫した順列の割り当てが存在するかどうかを尋ねていることです。$i$。 

重要な観察は、どんな単語でも、辞書編集上可能な限り最小の形式は単にそのソートされたバージョンであるということです。 他の順列はこれに勝るものはありません。 同様に、すべての単語には固定の「下限」文字列があります。$s_i$、その並べ替えられた形式であり、これより小さいものを作成できる配置はありません。 

だから唯一の方法は$w_i$厳密な最小値は、その最良の形式が他のすべての単語の最良の形式よりも厳密に小さい場合です。 なぜなら、別の単語の最良の形式であってもそれより小さいか等しい場合は、$i$決して勝つことはできません。 

したがって、問題は各単語をソートし、これらの標準的な最小形式を比較することに帰着します。

 ## アルゴリズムのチュートリアル

 文字をソートすることにより、各単語の正規表現を構築します。 

1. 単語ごとに$w_i$、その文字をソートして取得します$s_i$。 これは、辞書編集的に達成可能な最小の文字列を表します。$w_i$なぜなら、どんな順列もマルチセットを並べ替えることしかできず、並べ替えは辞書編集順を最小化するからです。 
2. すべてを比較する$s_i$文字列を辞書編集順でグローバル最小値を検索します。 この最小文字列を次のようにします$s_k$。 
3. インデックスごとに$i$、次の場合にのみ 1 を出力します。$s_i = s_k$それ以外の場合は 0 を出力します。 

これが機能する理由は、単語のソートされた形式が全体的に最小でない場合、ソートされた形式が厳密に小さい別の単語が存在するためです。 単語はソートされた形式よりも小さくすることはできないため、$i$どのような構成でも厳密な最小値になることはありません。 

### なぜ効果があるのか

 各単語には、許可されるすべての操作、つまり並べ替えられた順列の下で固定の下限があります。 達成可能な最終文字列は、辞書編集的にこの境界以上である必要があります。 したがって、すべての単語のすべての可能な構成の中で、任意の単語が達成できる最も早い可能な辞書編集候補は、そのソートされたバージョンになります。 

単語の並べ替えられたバージョンがすべての並べ替えられたバージョンの中で最小でない場合、達成可能な最小表現がより小さい別の単語が存在し、順列の選択方法に関係なく、その単語が常に優先されます。 逆に、ある単語がグローバル最小のソートされた文字列を共有する場合、その形式を達成するように調整できますが、他の単語は独自の境界を下回ることはできないため、厳密に最小にすることが可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
words = [input().strip() for _ in range(n)]

sorted_words = [''.join(sorted(w)) for w in words]
min_sorted = min(sorted_words)

res = []
for s in sorted_words:
    res.append('1' if s == min_sorted else '0')

print(''.join(res))
```このソリューションはすべての単語を読み取り、それぞれをソートされた標準形式に変換し、その中で最小のものを見つけます。 最終出力では、この最小値との等しいかどうかがチェックされます。 

重要な実装の詳細は、元の単語を直接比較しないことです。 ソートされたフォームは許可された操作の範囲全体を表すため、ソートされたフォームのみが重要です。 各文字列のソートはランタイムに影響を及ぼしますが、Python の組み込みソートは十分に効率的です。$n, m \le 3000$。

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    n, m = map(int, input().split())
    words = [input().strip() for _ in range(n)]
    sorted_words = [''.join(sorted(w)) for w in words]
    mn = min(sorted_words)
    print(''.join('1' if s == mn else '0' for s in sorted_words))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old_stdin
    return out.getvalue().strip()

# provided sample
assert run("4 7\nabandon\nbananaa\nabaanna\nnotnotn") == "1110"

# minimum size
assert run("1 3\nabc") == "1"

# all identical multisets
assert run("2 3\nabc\nbca") == "11"

# strict ordering
assert run("3 3\ncba\nbca\nabc") == "001"

# duplicate minimum only
assert run("3 4\nbaca\nabca\ncaaa") == "010"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 一言 | 1 | 基本ケース |
 | 同一の順列 | 11 | ネクタイの取り扱い |
 | 厳密な順序付け | 001 | 正しい最小値の選択 |
 | 混合ケース | 010 | 一般的な正しさ |
