 ## 解決策
 ## 問題の理解

 変数システムが与えられ、それぞれが True、False、Unknown の 3 つの値のいずれかをとります。 一連の代入操作が順番に実行され、各操作で変数が定数値、別の変数の値、または別の変数の否定に更新されます。 

これらの操作を実行する前に、すべての変数の初期割り当てを選択します。 この初期状態から始まるすべての操作を実行した後、すべての変数が開始時の値とまったく同じ値になることが必要です。 このような有効な初期割り当ての中で、最初に不明に設定される変数の数を最小限に抑えたいと考えています。 

主な困難は、操作が状態の決定論的な変換を定義することであり、不定値に依存する頻度を最小限に抑えるという追加の目標とともに、Kleene の 3 値ロジックに基づいてこの変換の固定点を探していることです。 

これについて考えると、各変数は一連の代入によって引き起こされる関数グラフ内のノードであると考えると便利です。 すべてのステートメントは、別の変数またはその否定に基づいて 1 つの変数を書き換えるため、すべての変数の最終値は初期変数の関数になります。 制約は、このグローバル関数の固定小数点を要求します。 

制約は大きく、テスト ケースごとに最大 100,000 個の変数と 100,000 回の操作があります。 これにより、割り当てを列挙したり、すべての可能性をシミュレートしようとするアプローチは除外されます。 どのようなソリューションも、テスト ケースごとに本質的に線形である必要があります。 

否定を伴う循環によって矛盾が生じる場合、微妙な問題が発生します。 たとえば、次のようなチェーン$x_1 \leftarrow \lnot x_2$、$x_2 \leftarrow \lnot x_3$、$x_3 \leftarrow \lnot x_1$一貫したブール代入が存在せず、クリーン否定の下では Unknown が唯一の安定した値になるため、すべての変数を強制的に Unknown にします。 

もう 1 つの特殊なケースは、割り当てのオーバーライドです。 変数は複数回割り当てられる場合があります。 順方向実行では最後の代入のみが重要ですが、固定小数点推論では、伝播構造内の依存関係を定義するため、以前の代入が重要です。 

## アプローチ

 ブルートフォース戦略は、各変数に 3 つの値のいずれかを割り当て、すべてのステートメントの実行をシミュレートして、最終状態が初期状態と一致するかどうかを確認することです。 条件を直接検証するため、これにより正確さがすぐに得られます。 ただし、課題の数は、$3^n$、たとえ小規模であっても完全に実行不可能です。$n$。 逐次代入によって作成された依存構造は制約をグローバルに伝播する可能性があるため、枝刈りや部分的なメモ化でも役に立ちません。 

重要な点は、これは実際には更新のシーケンスに関するものではなく、変数の最終値間の制約に関するものであるということです。 各代入は、2 つの変数を同等にするか、1 つの変数を別の変数の否定と同等にするか、変数を強制的に定数にします。 ソリューションを、すべてのルールを適用した後も変更されない最終的な一貫した割り当てとして考えると、すべてのステートメントは、最終的な値によって同時に満たされる必要がある制約になります。 

これにより、問題は、エッジが等価または否定関係をエンコードする制約グラフに関する推論に変わります。 3 値ロジックの標準的なトリックは、値 Unknown の動作が異なることを観察することです。これは、否定を「吸収する」普遍的な値ですが、ブール値のように動作しません。 重要な構造的洞察は、一貫性が必要な場合、接続されたコンポーネントに矛盾があると、コンポーネント全体が不明になることを強制するということです。 

したがって、グラフは制約の下で連結コンポーネントに分解できます。各コンポーネントは、符号付きグラフとして一貫しているか (ブール代入が可能)、一貫していないか (すべてのノードを強制的に不明にします) のいずれかです。 目標は、Unknown が割り当てられる頂点の数を最小限に抑えることです。これは、パリティ制約の下で一貫して True/False を割り当てることができる頂点の数を最大化することと同じです。 

したがって、問題は、定数の割り当てを尊重しながら、符号付きエッジを持つグラフの二部性をチェックすることになります。 一貫性のある各コンポーネントは、未知数に寄与しません。 一貫性のない各コンポーネントは、そのフルサイズに影響します。

 ## アルゴリズムのチュートリアル

 各変数がノードとなる制約グラフを構築することで、各テスト ケースを処理します。 各操作は、変数間のエッジ制約または固定ラベル制約に変換されます。 

エッジをパリティで維持します。等しいエッジは両方のエンドポイントが同じ値を共有することを意味し、否定エッジは反対の値を意味します。 

1. すべての割り当てを最終値間の制約に変換します。 変数に定数が割り当てられている場合、それを固定ラベル制約を持つノードとして扱います。 別の変数が割り当てられている場合は、等価エッジを追加します。 否定が割り当てられている場合は、パリティ反転されたエッジを追加します。 固定小数点では最終的な一貫性のみが重要であるため、このステップでは逐次プログラムを静的制約システムに圧縮します。 
2. 接続されたコンポーネントごとに、BFS または DFS を使用して値を割り当てようとします。 任意の開始ノードを選択し、それに暫定的なブール値 (たとえば True) を割り当て、エッジを介して伝播します。 等価エッジは値を保持し、否定エッジは値を反転します。 これにより、候補 0/1 ラベルが作成されます。 
3. 伝播中に、固定された制約に対する一貫性をチェックします。 ノードが True または False になるように強制され、伝播が一致しない場合、コンポーネントは矛盾しています。 
4. 矛盾が見つからない場合、コンポーネントは有効であり、不明な値なしで割り当てることができます。 その中のすべてのノードは、答えに寄与しないものとしてカウントされます。 
5. 矛盾が発生すると、このコンポーネントに対して一貫したブール代入を実現できなくなります。 固定小数点の要件を満たす唯一の方法は、コンポーネント内のすべての変数を Unknown に割り当て、コンポーネントのサイズを答えに寄与することです。 

最終的な答えは、矛盾するすべてのコンポーネントのサイズの合計です。 

### なぜ効果があるのか

各接続コンポーネント内では、すべての制約は 2 状態システムにわたる線形パリティ制約です。 これらの制約が満たされる場合、固定小数点の要件をすでに満たしている一貫したブール値のラベルが存在するため、変数が不明である必要はありません。 これらが満たされない場合、ブール値を代入しようとすると矛盾が生じ、クリーン ロジックは矛盾を避けるために Unknown への伝播を強制します。つまり、そのコンポーネント内のすべての変数は有効な固定小数点で Unknown でなければなりません。 これにより、コンポーネントごとに明確な二分法が作成され、一貫性のないコンポーネント サイズのみをカウントする最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    t = int(input().split()[1])
    out = []

    for _ in range(t):
        n, m = map(int, input().split())

        # adjacency list: (neighbor, parity)
        # parity 0 = same, 1 = flipped
        g = [[] for _ in range(n + 1)]

        # fixed constraints: None, 0 (False), 1 (True)
        fixed = [None] * (n + 1)

        def add_edge(a, b, p):
            g[a].append((b, p))
            g[b].append((a, p))

        for _ in range(m):
            tmp = input().split()
            op = tmp[0]

            if op == 'T':
                i = int(tmp[1])
                fixed[i] = 1
            elif op == 'F':
                i = int(tmp[1])
                fixed[i] = 0
            elif op == 'U':
                i = int(tmp[1])
                fixed[i] = None
            elif op == '+':
                i, j = map(int, tmp[1:])
                add_edge(i, j, 0)
            else:  # '-'
                i, j = map(int, tmp[1:])
                add_edge(i, j, 1)

        vis = [False] * (n + 1)
        color = [0] * (n + 1)

        def bfs(start):
            from collections import deque
            dq = deque([start])
            vis[start] = True
            color[start] = 0

            nodes = [start]
            ok = True

            while dq:
                v = dq.popleft()

                for to, p in g[v]:
                    expected = color[v] ^ p
                    if not vis[to]:
                        vis[to] = True
                        color[to] = expected
                        dq.append(to)
                        nodes.append(to)
                    else:
                        if color[to] != expected:
                            ok = False

            # check fixed constraints
            if ok:
                for v in nodes:
                    if fixed[v] is not None and color[v] != fixed[v]:
                        ok = False
                        break

            if ok:
                return 0
            return len(nodes)

        ans = 0
        for i in range(1, n + 1):
            if not vis[i]:
                ans += bfs(i)

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は、各ステートメントを符号付きグラフに変換することから始まります。 等価と否定はパリティを持つエッジになり、定数はノード上の固定ラベルになります。 

BFS は、色を反転するか保持するかをパリティによって決定する標準的な 2 色の伝播を実行します。 色付けの矛盾や固定割り当てとの不一致を検出した瞬間に、コンポーネント全体を無効としてマークします。 

微妙な点は、固定制約はコンポーネントを完全に走査した後でのみチェックされることです。 これにより、すべての暗黙の値が判明する前にコンポーネントが時期尚早に拒否されることが回避されると同時に、開始値が選択されると伝播が決定的になるため、正確性が保証されます。 

最終的な累積は、無効なコンポーネントのサイズを単純に合計するもので、矛盾した部分のみを強制的に Unknown にする必要があるという解釈と一致します。

 ## 特殊なケース

 重要なエッジケースは、変数が複数の矛盾する定数の割り当てを受け取る場合です。 たとえば、変数を最初に True に設定し、後で False に設定すると、固定制約の競合が発生します。 グラフ モデルでは、これは互換性のないラベルを持つノードになり、BFS 中にノードはすぐに整合性チェックに違反し、そのコンポーネントを完全に不明としてマークします。 

もう 1 つのケースは自己否定制約です。$x_i = \lnot x_i$。 これにより、単一ノードの矛盾ループが形成されます。 BFS は暫定的な値を割り当て、自己ループを通じてすぐに反対の値を導出し、不一致を検出します。 結果として、この 1 つのノードが答えに 1 を寄与することになります。 

最後の微妙なケースは、制約が、後で再割り当てされる中間変数を介してのみ接続された複数のコンポーネントを形成する場合です。 最終的な制約のみが重要であるため、グラフ モデルはそのようなシーケンスをすべて自然に崩壊させ、BFS はコンポーネントを正しく分離して、矛盾の相互汚染がないことを保証します。
