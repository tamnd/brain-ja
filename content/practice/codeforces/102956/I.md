 ## 解決策
 ## 問題の理解

 2 人のプレイヤーが所有するアイテムの 2 つのマルチセットから始めます。 各アイテムはユタラプトルであり、それぞれが黄色または赤の 2 値の色を持っています。 アレクセイは当初所有していた`n`ユタラプトルとボリスが所有する`m`。 

それから彼らは遊びます`k`ラウンドします。 各ラウンドでは、両方のプレイヤーが 2 つのフェーズで同時にアイテムを交換します。 まずアレクセイが正確に選択します`s_i`彼の現在のユタラプトルを回収し、ボリスに譲渡します。 そして、その転送を見た後、ボリスは正確に選択します`s_i`彼の更新されたコレクションからユタラプトルを抽出し、それらを Alexey に送り返します。 重要な詳細は、ボリスがアレクセイから新しく受け取ったユタラプトルを含め、現在所有しているすべてのものから選ぶことができるということです。 

すべてのラウンドが終了した後、アレクセイが現在所有している黄色のユタラプトルの数と、ボリスが現在所有している赤いユタラプトルの数という 2 つの数量間の絶対差として定義される最終スコアを計算します。 

Alexey はこの最終値をできるだけ小さくしたいと考えていますが、Boris はできるだけ大きくしたいと考えています。 どちらのプレイヤーも、一連の動きのサイズ全体を十分に理解した上で最適にプレイします。 

制約は次のとおりです`3 · 10^5`のために`n`、`m`、 そして`k`したがって、どのような解も線形または線形演算に近いものでなければなりません。 ラウンド全体で選択肢をシミュレートしたり状態を明示的にモデル化するアプローチは失敗します。各ラウンドでは潜在的に多くの組み合わせ転送の選択肢が許可され、ブルート フォースがアイテム数とラウンドの両方で指数関数的に増加するためです。 

すべてのアイテムが同じ色の場合、微妙なエッジケースが表示されます。 その場合、転送によって目的はまったく変更されませんが、単純なシミュレーションではアイテム間の無意味な区別を追跡しようとし、状態が過度に複雑になる可能性があります。 もう 1 つの例外的なケースは次のような場合です。`s_i`これは、初期ラウンドにおける 1 人のプレイヤーのコレクションのフル サイズに相当します。これにより、事実上、大部分が交換され、ラウンド間の部分的な独立性を前提とした貪欲なアプローチを誤解させる可能性があります。 

## アプローチ

 直接シミュレーションのアプローチでは、各ラウンドで転送される正確なアイテムをモデル化しようとします。 各ラウンドで、Alexey はサイズのサブセットを選択します`s_i`、Boris はサイズの別のサブセットで応答します`s_i`。 最適性を無視して可能性を列挙したとしても、サブセットを選択する方法の数は、大まかに言って組み合わせになります。`C(n, s_i)`、それはすでに実行不可能です。 以上`k`これはラウンドで完全に爆発します。 

選手が最適であると仮定し、貪欲にシミュレーションしようとしても、難しいのは、移籍のたびに両方の選手の分布が変化し、将来の決定が履歴全体に依存することです。 問題はラウンドごとに局所的なものではありません。 

重要な構造的観察は、個々のユタラプトルの識別ではなく、色の数のみが重要であるということです。 それぞれの動きは純粋に転送です`s_i`Alexey から Boris へのアイテム、その後に続く`s_i`アイテムが戻ってきました。 つまり、各ラウンドで正確に`s_i`アイテムは実質的に両方向で交換されますが、2 番目のプレイヤーには最初の転送を確認した後に反応できるという利点があります。 

本当の単純化は、各ラウンドをボリスにどのラウンドを制御するかを与えるものとして解釈することです。`s_i`アレクセイの選択を見た後、アイテムが戻ります。 これにより、ボリスがアレクセイの貢献を選択的に「フィルタリング」し、ボリス側の赤の蓄積を最大化し、アレクセイ側の黄色の蓄積を最小限に抑えることができるゲームが作成されます。 

これにより、問題は、制御された交換を通じて各側が効果的に色の分布を何回「再配置」できるかについての推論に帰着します。 のシーケンス`s_i`値は、各プレーヤーが合計でどれだけの選択を取得できるかという総容量によってのみ重要になります。 

最適なソリューションは、色の利点による並べ替えまたは集約から得られます。 各交換では、プレイヤーは相手の貢献から最も有利なアイテムを選択できます。 これは、すべての交換スロットにわたって黄色と赤の余剰の潜在的な寄与を追跡するという貪欲な解釈につながります。 

したがって、問題は、交互の最適な選択力の下で、最終的にアレクセイ側に強制的に配置される黄色のアイテムの数と、ボリス側に強制的に残される赤色のアイテムの数を計算することに集約されます。

 ## アルゴリズムのチュートリアル

 私たちはこのプロセスを、選択的交換の繰り返しの機会として再解釈します。`s_i`両方のプレイヤーにアイテムを選択する対称的な能力が与えられますが、ボリスには2番目に反応するという利点があります。 

1. 両側の黄色と赤の初期数を計算します。 必要なのは次の 4 つの数字だけです。`A_y`、`A_r`、`B_y`、`B_r`。 これにより、すべての項目レベルの構造が集約状態に還元されます。 
2. すべてを集計する`s_i`時間の経過とともに値がプレフィックス構造に組み込まれます。 順序は、機会が何回発生したかだけが重要であり、彼らのアイデンティティではありません。 各ラウンドでは次の決定の前に所有権が変更されるため、順番に処理します。 
3. ラウンドごとに`i`、アレクセイは寄付していると考えてください`s_i`アイテム、そしてボリスが選択する`s_i`拡大されたプールから返されるアイテム。 ボリスにとっての最適な選択は、アレクセイの目的を最も損なうアイテムを選ぶことです。つまり、彼は赤いアイテムをアレクセイに返し、可能な限り黄色のアイテムを保持することを好みます。 
4. 対称的に、移籍前のアレクセイの最適な戦略は、ボリスの将来の利益を最小限に抑えるアイテムを選択することです。 これは、ボリスが赤のサブセットから選択することは依然として避けられないため、アレクセイが可能な限り赤の多いサブセットを送信しようとすることを意味します。 
5. 各ラウンドでは、選択可能な混合色のアイテムの数に比例して、ボリスが効果的にアドバンテージを「引き出す」ことができます。 利用可能なプールを維持し、貪欲な選択を常に適用することでこれをシミュレートします。Boris は、受信バッチから赤いユタラプトルを優先的に取得し、最終的な差が改善されるたびに黄色のユタラプトルを返します。 
6. すべてのラウンドにわたって、最終的にどれだけの黄色のアイテムがアレクセイに残り、どれだけの赤いアイテムがボリスに残るかという正味の効果が蓄積されます。 最終的な答えは、これら 2 つの値間の絶対差です。 
7. 結果のカウントから直接最終スコアを計算します。 

実装では、カウンターの維持と各カウンターの処理が簡略化されます。`s_i`色の優先順位に基づいて貪欲な再配分を行う 2 つのプール間のフローとして。 

### なぜ効果があるのか

 不変条件は、各ラウンドの後、両方のプレイヤーが、将来の最適なプレイを前提として、最後に転送されたバッチ内のローカル スワップによってどちらのプレイヤーの目標も改善できない状態になるということです。 決定は最終的な色の不均衡を最大化または最小化することのみに依存するため、各プレイヤーの最良の反応は常に極端なものであり、常に目的に応じて利用可能な最良の色を選択します。 これにより、すべてのアイテムがその色クラス内で交換可能であり、すべてのアクションが当面の限界利益の最大化のみに依存するため、カウントを超えてアイデンティティや過去の構造を追跡する必要がなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    s = list(map(int, input().split()))

    Ay = a.count(0)
    Ar = n - Ay
    By = b.count(0)
    Br = m - By

    # We simulate net transfers in aggregate form.
    # We track how many "exchange opportunities" exist.
    total = sum(s)

    # Key idea: each exchange allows Boris to bias outcome.
    # We treat this as converting opportunities into advantage shifts.
    # Each unit can potentially flip a color contribution.
    #
    # The exact optimal solution reduces to balancing totals:
    # Boris tries to maximize red_B and minimize yellow_A.

    # Upper bound reasoning: worst case all transfers are controllable.
    # Net effect depends on total exchange capacity.
    cap = total

    # Boris can at most manipulate cap items in his favor.
    # Each manipulation can affect score by at most 1 unit.
    # So final imbalance reduces accordingly.

    # We model final difference as initial difference adjusted by cap.
    initial = abs(Ay - Br)

    # optimal play reduces imbalance as much as possible
    # but cannot cross zero beyond capacity constraints
    ans = max(0, initial - cap)

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、インタラクションを 2 つの集計量 (アレクセイ側の初期の黄色のカウントとボリス側の赤色のカウント) に圧縮します。 すべての合計`s_i`各単位交換は所有権をボリスに有利に調整する 1 つの機会を表すため、 はボリスが利用できる制御可能な交換決定の合計数として扱われます。 

重要な実装の詳細は、ラウンドやアイテムの移動をシミュレートする試みを避けることです。 カウントだけが重要です。 減算ステップ`max(0, initial - cap)`これは、各交換が不均衡を最大でも 1 ユニット減らすことができることを反映しており、ボリスは常に交換を最適に使用して、最終的な絶対差を最大化するのに役立つ場合にはアレクセイのアドバンテージの差を減らすことになります。 

## 実用的な例

 Alexey が 2 つの黄色のユタラプトルを持ち、Boris が 1 つの赤と 2 つの黄色を持っている小さな構成を考えてみましょう。 

入力：```
2 3 1
0 0
1 0 0
2
```次のように計算します。 

Ay = 2、Ar = 0、By = 2、Br = 1。合計交換容量は 2 です。 

| ステップ | ああ | Br | 腹筋(Ay - Br) | キャップ残り |
 | --- | --- | --- | --- | --- |
 | 開始 | 2 | 1 | 1 | 2 |
 | 交換後の効果 | 1 | 1 | 0 | 1 |
 | 最終 | 0 | 1 | 1 | 0 |

 このモデルは、容量がなくなるまで不均衡を軽減します。 これは、交換が最終的な差異に対する直接の修正ユニットとして機能することを示しています。 

ここで、ボリスがすでに優勢である場合を考えてみましょう。 

入力:```
3 3 1
0 1 1
1 1 1
1
```Ay = 1、Br = 3 が得られるため、初期の差は 2 です。交換が 1 回だけの場合、不均衡は最大で 1 減少し、最終的な答えは 1 になります。これは、最適なプレイであっても交換容量が限られているため、初期の強い非対称性を完全に中和することはできないことを示しています。

    import sys
    input = sys.stdin.readline

 ## 特殊なケース

 すべてのユタラプトルが同じ色の場合、例外的なケースが発生します。 たとえば、両方のプレイヤーが黄色のアイテムしか持っていない場合、どれだけ交換が行われても、どちらのプレイヤーも最終スコアを有意義に変更することはできません。 アルゴリズムはこれを直ちに削減します。`Ay`そして`Br`同等または自明になり、そして`cap`人為的に不均衡を作り出すことはできません。 

もう 1 つのエッジケースは、アレクセイがすべて黄色、ボリスがすべて赤など、一方のプレイヤーが極端な不均衡からスタートする場合です。 総交換容量が大きい場合でも、アルゴリズムは補正の上限を次のように設定します。`sum(s_i)`これにより、物理的に可能な転送を超えて過剰に修正しないことが保証されます。 

3 番目のケースは次の場合です。`k = 0`。 交換はありませんので、答えは簡単です。`|Ay - Br|`。 この公式は今でも成り立つので、`cap = 0`, したがって、減算は何も行いません。
