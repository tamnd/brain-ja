 ## 解決策
 ## 問題の理解

 私たちには一連のルーターが与えられており、それぞれが数値周波数を伝送します。 これらのルーターのサブシーケンスを選択できますが、そのサブシーケンスには少なくとも 2 つの要素が含まれており、元の順序が保持されている必要があります。 選択したサブシーケンスの品質は、その中のすべての隣接するペアを調べ、それらのビット単位の AND を合計することによって定義されます。 

つまり、インデックスを選択すると、$i_1 < i_2 < \dots < i_k$、スコアは$$(f_{i_1} \& f_{i_2}) + (f_{i_2} \& f_{i_3}) + \dots + (f_{i_{k-1}} \& f_{i_k})$$この値を最大化したいと考えています。 

主要な構造上の制約は、要素の順序を変更することはできず、スキップすることのみが許可されることです。 これにより、問題は、選択した連続する要素間のどの「リンク」を保持するかを選択することになります。 

制約は非常に大きく、$n$まで$10^6$および最大値$10^{12}$。 これにより、二次関数や偶数関数が即座に除外されます。$n \log n$以前のすべての状態に依存する要素ごとの DP。 解は線形に近いか、要素ごとに小さい定数係数を持つ線形である必要があります。 

微妙なエッジケースは、スキップによって間接的に貢献度が向上する場合です。 たとえば、次のような場合です。```
f = [8, 7, 7, 8]
```すべての要素を選択すると、次のようになります。```
8&7 + 7&7 + 7&8 = 0 + 7 + 0 = 7
```ただし選択するだけ`[7, 7]`与える:```
7&7 = 7
```そして選択する`[8, 8]`最適なサブシーケンスは必ずしも配列全体である必要はなく、元の配列内の貪欲な隣接ペアリングである必要もありません。 

もう 1 つの重要なケースは、スパースの上位ビットを除くすべての値がゼロである場合です。 例えば：```
[1, 2, 4, 8]
```隣接するすべての AND は 0 であるため、長さが 2 以上のサブシーケンスのスコアは 0 になります。答えは 0 ですが、単純な直感では、離れたビットを誤って「接続」しようとする可能性があります。 

これらの例は、順序が保持されることを除いて、元の配列の隣接関係が選択後に無関係であることを示しています。 実際の決定は、シーケンスを連続した選択された要素に分割する方法です。 

## アプローチ

 ブルートフォースアプローチでは、すべての有効なサブシーケンスを列挙し、そのスコアを計算し、最大値を追跡します。 長さの各部分列$k$費用$O(k)$評価すること、そして、$2^n$後続。 長さを少なくとも 2 に制限したとしても、これは依然として指数関数的であり、次の場合には直ちに実行不可能です。$n = 10^6$。 

より構造化された DP は、ポジションごとに、ここで終了するサブシーケンスの最高のスコアを維持しようとします。 させて`dp[i]`で終わる有効なサブシーケンスの最高スコアであること`i`。 その後、それまでのすべての`j < i`、次のように移行できます。$$dp[i] = \max(dp[j] + (f[j] \& f[i]))$$これは正しいですが、次のことが必要です$O(n^2)$トランジション。 

重要な観察は、遷移の値はビット単位の構造のみに依存するということです。`f[i]`。 以前のすべてのインデックスを考慮する代わりに、インデックスが提供する情報をビットごとの要約に圧縮できます。 

各ビット位置について、そのビットが設定されている以前の要素の中で最良の DP 値を維持します。 新しい値を処理するとき`x`の場合、前の要素からの寄与は、どのビットが共有されるかによってのみ決まります。その理由は次のとおりです。$$f[j] \& x$$は、両方の数値の 1 であるビットの正確な合計です。 

したがって、すべてを繰り返すのではなく、`j`、ビットを反復処理します。`x`。 設定ビットごとに`b`で`x`、ビットも含む数値の間で以前の最良の DP 状態を使用して拡張しようとします。`b`。 これにより、次からの移行が減少します。$O(n)$州ごとに$O(\log A)$。 

また、各要素が新しいチェーンを開始するか、既存のチェーンを拡張できるように、新しいサブシーケンスの開始を許可する必要もあります。 

これにより、ビットごとの小さな最適値を維持し、スキャン中にそれを更新するという問題が生じます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n)$|$O(1)$| 遅すぎる |
 | ナイーブDP |$O(n^2)$|$O(n)$| 遅すぎる |
 | ビットごとに最適化された DP |$O(n \log A)$|$O(\log A)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各ビット コンテキストで終わる最良のサブシーケンス スコアと、これまでのグローバルな最良の回答という 2 つの構造を維持しながら、配列を左から右に処理します。 

1.各要素について$x$、新しいサブシーケンスの開始を表す候補値を計算します。$x$。 サブシーケンスには少なくとも 2 つの要素が必要なので、単一の要素を答えとして最終決定しないため、これは少なくとも 0 です。 
2. 各ビットについて$b$そのような$x$ビットがある$b$セットしたら、ビットに関連付けられた最もよく知られている DP 状態を調べます。$b$。 これは、このビットを共有する以前の要素で終わる最適なサブシーケンスを表します。 
3. を追加して候補遷移値を計算します。$x \& y$ただし、ビットごとに反復しているため、共有ビットを集計することで寄与が自然に取得されます。 
4. で終わる最適なサブシーケンスを更新します。$x$これらすべての遷移の最大値を使用します。 
5. で終わる最も完成度の高いサブシーケンスで全体的な回答を更新します。$x$、少なくとも 1 つの前の要素があることを確認します。 

重要な考え方は、すべてのサブシーケンスが次で終わるということです。`x`は、以前に選択された要素によって決定され、その前の要素は、次の要素とのビット単位の交差によってのみ重要になります。`x`。 

### なぜ効果があるのか

 このアルゴリズムは、すべてのビット位置について、このビットを含む以前のインデックスで終わる達成可能な最良のサブシーケンス スコアがわかっているという不変条件を維持します。 で終わる任意の最適なサブシーケンス`i`最後に選択した要素から取得する必要があります`j`、および寄与する値`j`に`i`それらが共有するビットのみに依存します。 したがって、候補をビットごとの最良の状態に制限しても、最適な遷移は破棄されません。 すべての最適な最終ステップは、共有ビットに対応するビット バケットの少なくとも 1 つで表されるため、常に考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    MAXB = 60
    best_bit = [-10**30] * MAXB
    ans = 0

    for x in a:
        best_here = 0

        for b in range(MAXB):
            if x >> b & 1:
                best_here = max(best_here, best_bit[b] + (1 << b))

        ans = max(ans, best_here)

        for b in range(MAXB):
            if x >> b & 1:
                best_bit[b] = max(best_bit[b], best_here)

    print(ans)

if __name__ == "__main__":
    solve()
```実装は配列を維持します`best_bit[b]`最後に選択された要素がビットを持つサブシーケンスの中で、これまでに達成可能な最高のサブシーケンス スコアを保存します。`b`セット。 新しい番号ごとに`x`で終わる最適なサブシーケンスを計算します。`x`それに含まれるすべてのビットを試し、対応する最良の状態から拡張します。 

微妙な点は、共有ビットのみを介して遷移することです。 貢献`(1 << b)`ビットからの可能な最大の寄与を表します`b`AND演算で。 AND は両方の数値に存在するビットのみを保持するため、ビットごとの遷移を分解するのは安全です。 

また、更新することで正確性を保証します`best_bit`計算後にのみ`best_here`したがって、同じ要素を 2 回再利用することはありません。

 ## 特殊なケース

 最小入力サイズの場合`n = 2`、アルゴリズムは可能な唯一のサブシーケンスを正しく処理します。`[f1, f2]`そして計算します`f1 & f2`。 以前の状態が存在しないため、`best_here`0のままで、`ans`AND がゼロ以外で、定義に一致する場合にのみ更新されます。 

次のようなすべてゼロの配列の場合、`[0, 0, 0, 0]`、すべてのビットバケットは全体を通してゼロのままです。 DP は正の値を蓄積することはなく、すべての AND 演算がゼロであるという事実と一致して、答えはゼロのままです。 

次のようなまばらな高ビットの場合`[1, 2, 4, 8]`2 つの要素が少しも共有されていないため、トランジションが改善されることはありません`best_here`。 アルゴリズムは維持します`ans = 0`これは、すべてのサブシーケンスのスコアがゼロであることを正しく反映しています。
