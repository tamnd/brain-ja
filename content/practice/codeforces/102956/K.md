 ## 解決策
 ## 問題の理解

 垂直方向に積み重ねられた棚が与えられ、それぞれの棚には耐久性のしきい値が設定されています。 上から i 番目の棚は、カスケード プロセスを通じて間接的にその上にある限られた数のボールのみを許容します。 同じボールを選択した棚に繰り返し落とします。 棚に十分な荷重が蓄積されてしきい値を超えると、棚が壊れ、壊れた原因となったボールが、荷重を分割してその一部を本棚のさらに下に押し込むという固定ルールに従って下に「こぼれ」ます。 

重要な点は、ボールの 1 つの配置が 1 つの棚だけに影響するわけではないということです。 より高いシェルフでの障害は下方に伝播し、連鎖反応で複数の連続するシェルフが破損する可能性があります。 個々のボールを最初に配置する場所を選択できますが、最終的に上位 k 個の棚が壊れることを保証するために、使用するボールの数をできるだけ少なくしたいと考えています。 

出力は n 個の値のシーケンスです。 k 番目の値は、最適配置戦略により、ある時点で上位 k 個の棚がすべて壊れるのに必要なボールの最小数です。 

n ≤ 70 という制約は十分に小さいため、サブセットまたは状態にわたる指数構造は原理的には妥当ですが、これは状態が大幅に圧縮されている場合に限られます。 ai の値も小さい (≤ 150) ため、このプロセスは比較的小さい整数の容量によって支配されており、繰り返される 2 倍または 2 倍の動作が関連している可能性が高いことが示唆されます。 

素朴な解釈では、考えられるすべての配置シーケンスをシミュレートし、その結果生じるカスケードを追跡することを示唆するかもしれません。 k が小さい場合でも、可能な配置シーケンスの数はボールの数に応じて指数関数的に増加するため、これはすぐに失敗します。 もう 1 つの魅力的だが間違ったアイデアは、シェルフを独立して扱うというものですが、カスケード ルールにより独立性が誤ってしまいます。つまり、1 つのシェルフを破壊すると、下位のすべてのシェルフに到達する実効荷重が変化します。 

負荷分散の単調性を仮定すると、微妙な失敗のケースが発生します。 たとえば、すべてのボールを棚 1 に置くことが常に最適であると仮定するかもしれません。 一般的にはそうではありません。下位の棚にターゲットを絞って配置すると、無駄なオーバーフローが減り、複数の棚を壊す効率が向上します。 

## アプローチ

 ブルートフォース戦略では、各ボールの配置を決定としてモデル化しようとします。つまり、シェルフを選択し、カスケードをシミュレートし、すべてのシェルフの結果の状態を追跡します。 各ステップで全体の構成が変更されるため、状態空間は膨大になります。 たとえ最上位 k 個の棚に限定したとしても、棚間でボールを分配できる方法の数はボールの数で指数関数的に増加し、各シミュレーション自体が破壊イベントの連鎖を引き起こす可能性があります。 最悪の場合、最大 O(2^n) 個の配置パターン、または m 個のボールに対して O(n^m) 個の分布を試みても、これは実行不可能です。 

重要な観察は、このプロセスには非常に強力な構造的単純化があるということです。棚が壊れたとき、下に伝わる荷重の量は任意ではなく、棚のしきい値によって決定的に決定されます。 各シェルフは、入力負荷を固定出力負荷に変換するしきい値アンプのように動作します。 これは、個々のボールをシミュレートする代わりに、k 回の連続ブレイクをトリガーするために必要な最小限の「有効負荷」を追跡する必要があることを示唆しています。 

重要な洞察は、システムを変換の構成物として見ることです。 各棚は、入ってくる荷物 x が破損すると、新しい荷物床 (x/2) に変換します。 すべてのシェルフは同様に動作しますが、しきい値は異なるため、システムは階層化された変換チェーンになります。 問題は、しきい値でトリガーされる変換を繰り返した後、上位 k 層が順番にアクティブ化されることを保証する最小の初期負荷を見つけることに帰着します。

これは当然、シェルフのプレフィックスに対する動的プログラミングの定式化につながります。 プレフィックスの長さ k ごとに、上から始めて k 個のシェルフを正確に破壊するカスケードを強制するのに必要なボールの最小数を維持し、残留荷重が下方に伝播する量を考慮します。

 ## アルゴリズムのチュートリアル

 シェルフを上から下に処理し、接頭語 k ごとに、最初の k 個のシェルフすべてが最終的に最適な配置で壊れることを保証するために必要な最小初期負荷を計算します。 

1. 状態 dp[k] を、最初の k 個の棚がいくつかの配置シーケンスと誘発されたカスケードを完全に突破できるようにするために必要なボールの最小数として定義します。 この定義は戦略全体にわたってグローバルなものであり、固定された配置順序に結び付けられるものではありません。 
2. ゼロシェルフの破壊にはボールが必要ないため、dp[0] = 0 を初期化します。 
3. k を 1 から n まで反復し、k 番目のシェルフをサイズ k-1 の既に解決されたプレフィックスの上でどのように強制的にブレークできるかを考慮して dp[k] を決定しようとします。 
4. 前状態 j < k の候補ごとに、棚 j+1 から k までがカスケード障害チェーンに関与するようにボールを配置する効果を考慮します。 j から k に拡張するコストは、中間の中断を繰り返して半分になった後にしきい値 a_k に達するために、シェルフ j+1 にどれだけの負荷を注入する必要があるかによって決まります。 
5. 重要な移行は、k-1 から下方への一連の休憩の後に棚 k を休憩させるには、k 番目の休憩の前に入力される荷重が少なくとも a_k であることを確認する必要がありますが、その荷重は、前の休憩を通じてフロアを 2 で繰り返し分割することによって減少している可能性があります。 これにより、逆に倍増構造が誘発されます。つまり、より高いシェルフに必要な負荷は、ターゲット シェルフからの距離に応じて指数関数的に増加します。 
6. これらの 2 倍効果を使用して候補コストを計算し、以前の可能なすべてのブレーク ポイントにわたって最小値を累積します。 
7. 各 k の答えは dp[k] で、順番に出力されます。 

### なぜ効果があるのか

 不変条件は、dp[k] の処理後、最初の k シェルフでブレークの完全なカスケードを強制する、可能な最小限の初期構成をキャプチャしていることです。 有効な戦略はいずれも一連のシェルフ障害を引き起こす必要があり、各障害により、現在のシェルフのみに依存する決定的な方法で受信負荷が変換されます。 これらの変換は構成的で単調であるため、最適な戦略は、一般性を失うことなく、シェルフがトップダウンの順序で分割される標準的な形式に再配置できます。 これにより、インターリーブや混合配置戦略を考慮する必要がなくなり、DP がすべての最適な動作を確実に捕捉できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # dp[k] = minimal balls to break first k shelves
    dp = [0] * (n + 1)

    # We interpret dp incrementally
    for k in range(1, n + 1):
        best = float('inf')

        # try last "activation point"
        for j in range(k):
            cost = dp[j]

            # compute cost to force shelf j+1..k cascade
            # effective load amplification over (k-j) layers
            x = a[k-1]
            for _ in range(k - j - 1):
                x = 2 * x + 1

            cost += x
            if cost < best:
                best = cost

        dp[k] = best

    print(*dp[1:])

if __name__ == "__main__":
    solve()
```コードは、プレフィックスに対して段階的に応答を構築します。 各 k について、プロセスを以前に解決されたプレフィックス j と j+1 から k までの新しいカスケード セグメントに分割することを検討します。 内側のループは、各シェルフ ブレークの半減効果を逆にすることによって、そのセグメントの上部に必要な最小限の荷重を構築します。これにより、再帰 x = 2x + 1 が説明されます。この再帰は、カスケード荷重の床分割効果を反転することで得られます。 

遷移コスト dp[j] + x は、最初に最初の j シェルフを最適にブレークし、次に残りのセグメントのカスケードを個別にトリガーすることを反映しています。 j に対する最小化により、最終的なカスケード構造の考えられるすべての分解点が捕捉されます。 

この実装は、n ≤ 70 であるという事実に依存しているため、O(n) 個の内部再構成を伴う O(n^2) ループで十分です。

 ## 特殊なケース

 重要なエッジケースは、すべてのシェルフのしきい値が同じである場合です。 この状況では、複数のブレークをカスケード接続しようとしてもコストは削減されません。これは、各シェルフが依然として独立したアクティブ化を必要とするためです。 DP は各分割 j を個別に正しく評価し、多層増幅によって結果が改善されないことがわかります。 

最後のシェルフのしきい値がそれまでのすべてのシェルフよりもはるかに大きい場合、別のエッジ ケースが発生します。 より小さいしきい値を介したカスケードは必要な負荷を不必要に増幅するため、アルゴリズムは自然に最後の遷移点を分離します。 

最後のエッジ ケースは n = 1 です。唯一の有効な戦略は、ボールのしきい値と正確に一致する単一の棚を直接破ることであるため、アルゴリズムは直ちに a[1] を返します。
