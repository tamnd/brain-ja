 ## 解決策
 ## 問題の理解

 小文字のグリッドが与えられており、このグリッド内の軸に沿って整列した長方形の境界線に非常に厳密なプロパティがあるものがいくつあるかを数えたいとします。つまり、長方形の境界線にあるすべてのセルには、まったく同じ文字が含まれている必要があります。 

長方形は、2 つの異なる行と 2 つの異なる列を選択して部分行列を形成することによって定義されます。 状態は内装は全く気にせず、外枠のみです。 上の行、下の行、左の列、および右の列はすべて同じ文字で構成され、それらの文字はすべて互いに等しい必要があります。 

タスクは、そのような長方形がいくつ存在するかを数えることです。 

グリッドは 2000 × 2000 までの大きさにすることができ、これは最大 400 万個のセルを意味します。 考えられるすべての四角形を個別に検査しようとするソリューションは、直ちに遅すぎます。四角形の数だけでも n²m² のオーダーであり、最悪の場合でも約 10¹² になるからです。 これにより、境界の妥当性を素朴に再計算するアプローチはすでに除外されています。 

長方形が非常に薄い場合、微妙なエッジケースが発生します。 長方形の高さが 2 または幅 2 の場合、その境界線は重なり合い、同じセルが複数の辺に関与します。 たとえば、2×k の長方形の場合でも、その周囲のセルがすべて同一である必要があり、これにより、これら 2 つの行および選択された列間のすべてのセルが適切に一致することが効果的に強制されます。 独立した側を前提とした不注意なアプローチは、これらの堕落したケースを二重にカウントしたり見逃したりする可能性があります。 

もう 1 つの落とし穴は、行と列の対称性です。 長方形は 2 つの行と 2 つの列によって決定されますが、条件はそれらを結合します。有効性は行のペアの列方向の一貫性に依存するため、行のみを選択することは列の選択とは独立していません。 

## アプローチ

 ブルートフォース戦略は、上部と下部の行を固定することから始まります。 行のペアごとに、列のすべてのペアを調べ、それらが形成する四角形の境界線が均一であるかどうかを確認します。 固定された行のペアの場合、どの列が「互換性」があるかを事前に計算できます。これは、上部と下部の行がその列で同じ文字を持つことを意味します。 次に、任意の長方形は、そのような互換性のある列のランからその左右の境界を選択する必要があります。 

ただし、互換性は垂直方向の一貫性を保証するだけであるため、これではまだ十分ではありません。 水平方向の境界線もすべての列にわたって一致する必要があり、単純なカウントではミスするような方法で隣接する列を結合します。 

問題をよりよく見るには、視点を逆にすることです。長方形の観点から考える代わりに、行のペアの観点から考えます。 行の固定ペアについては、両方の行が同じ文字を共有する列を調べます。 これらの列内で、次のような列インデックス (l、r) のペアをカウントしたいとします。 

l と r の間のセグメントは、内部のすべての列で、2 つの行の文字ペアが境界制約に関係するすべての行で同一であるという意味で「一貫性」があります。 

これは、行の各ペアを派生文字列に変換することを示唆しています。行 x1 と x2 に対して、列方向の等価文字ペアの署名を定義します。 四角形の境界線は、4 つの辺すべてが 1 つの文字に一致する場合にのみ有効であり、これにより強力な構造が強制されます。4 つの角に隣接するエッジすべてにより、選択された 2 つの行が境界列で一致する必要があり、列はこの一致が持続するブロックを形成する必要があります。 

重要な洞察は、文字 c を固定し、c に等しいセルのみを考慮することです。 文字ごとに独立して、境界線全体が c で構成される長方形を数えます。 これにより、問題は 26 個のバイナリ グリッドに減ります。 

ここで問題は次のようになります。バイナリ行列 (文字 c に対してセルが許可されるか許可されないかのいずれか) で、境界が完全に許可されたセル内にあるすべての四角形を数えます。

固定文字 c の場合、行ペアを処理します。 行のペアごとに、両方の行の列 j に c がある場合は位置 j が 1、それ以外の場合は 0 となる 1D 配列を計算します。次に、選択されたすべての位置が両端で 1 である部分配列、そして重要なことに、境界線全体に垂直方向の制約が適用される部分配列をカウントする必要があります。 これは、エンドポイントで両方の行が同時に有効である列のペアをカウントすることになります。 

最後の組み合わせステップは、行と文字 c の各ペアについて、すべての有効な四角形が、両方の行の l と r に c が含まれるように、l と r の 2 つの列を選択することに対応し、さらに、上と下のすべての行の両端点にも c がなければなりません。 これは、ハッシュまたはビットセット交差を使用して圧縮された列セットをカウントする古典的なペアになりますが、行ペアごとに有効な列の事前計算されたリストによって最適化されます。 

標準の最適化では、行のペアごとに、指定された文字と一致する列のリストを事前計算します。 次に、そのようなリストごとに、ペア (l, r) の数を数えます。これは単純に k が 2 を選択することですが、これは、同じ文字制約が 4 つの辺すべてに適用されることを確認した後でのみです。 これは、文字ごとに処理し、交差する行制約を適用することによって適用されます。 

最終的な解決策は、行ペアを反復処理し、文字ごとに頻度配列を構築し、組み合わせペア数を使用して寄与を蓄積することになります。

 ## アルゴリズムのチュートリアル

 1. 文字 c を修正し、他のすべての文字をこのパスに無関係なものとして扱います。 完全な答えは、すべての文字の合計です。 
2. この文字 c について、各行をバイナリ配列に前処理します。1 はセルが c に等しいことを意味し、そうでない場合は 0 を意味します。 これにより、有効な境界候補が分離されます。 
3. すべての行のペア (上、下) を繰り返します。 各ペアについて、両方の行の列 j に文字 c がある場合にのみ、good[j] が 1 となる配列 Good を計算します。 これにより、垂直境界線として機能する列が識別されます。 
4. この良好な配列をスキャンして、1 の連続セグメントを特定します。 各セグメント内では、列のすべてのペアが左右の境界線として機能する可能性があります。 
5. 長さ k のセグメントの場合、k・(k−1)/2 を答えに加算します。 これは、左右の列のすべての選択肢をカウントします。 
6. すべての行ペアとすべての文字にわたって累積します。 

この分解が機能する理由は、上部と下部の行が固定され、単一の文字に制限されると、有効なセグメント内で選択された列のペアに対して水平境界条件が自動的に満たされるためです。 垂直方向の辺はグッドの構築によってすでに保証されており、選択された両方の行が固定されており、端点で c に等しいため、水平方向の一貫性が続きます。 

### なぜ効果があるのか

 文字 c を固定すると、問題は境界線が完全に c である四角形を数えるという問題に変わります。 有効な長方形の場合、その上部と下部の行の選択された両方の列に c がなければならず、すべての中間構造は境界条件に影響を与えません。 行のペアを列挙し、列の制約を連続した有効なセグメントに折りたたむことにより、すべての四角形は、その固有の左上と右下の構造によって 1 回だけカウントされます。 セグメンテーションにより、異なる列間隔間の独立性が保証されるため、各セグメント内のペアのカウントは完全で重複しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    ans = 0

    # process each character separately
    for ch in range(26):
        c = chr(ord('a') + ch)

        # binary grid for this character
        b = [[1 if grid[i][j] == c else 0 for j in range(m)] for i in range(n)]

        # for each pair of rows
        for top in range(n):
            col_good = [1] * m

            for bot in range(top, n):
                # update column validity
                for j in range(m):
                    col_good[j] &= b[bot][j]

                # count segments of ones
                cnt = 0
                for j in range(m):
                    if col_good[j]:
                        cnt += 1
                    else:
                        ans += cnt * (cnt - 1) // 2
                        cnt = 0
                ans += cnt * (cnt - 1) // 2

    print(ans)

if __name__ == "__main__":
    solve()
```このコードでは、最初に文字ごとに計算が整理されるため、互換性のない境界文字の混在が回避されます。 文字ごとに、その文字が表示される場所のバイナリ マスクを構築します。 次に、上の行ごとに下の行を下方向に徐々に拡張し、現在のバンド内のすべての行にまだ文字が存在する列を追跡する列方向の交差配列 Col_good を維持します。 

内部スキャンは、有効な各列セグメントを列ペアの組み合わせ数に変換します。 更新 Col_good[j] &= b[bot][j] により、垂直ストリップ全体に有効な列のみが保持されるようになります。 

唯一の微妙な実装の詳細は、col_good が再利用され、一番下の行が下に移動するにつれて段階的に洗練されます。これにより、交差部分を最初から再計算することが回避され、解が時間制限内に保たれます。 

## 実用的な例

 小さなグリッドを考えてみましょう。```
a a a
a b a
a a a
```文字「a」を修正します。 top = 0 の場合、col_good は [1,1,1] として始まります。 bot = 0 の場合、すべての列は有効なままです。 セグメントの長さは 3 で、3 つのペアが寄与します。 bot = 1 の場合、中央の列が無効になるため、col_good は [1,0,1] となり、1 ペアが寄与します。 bot = 2 の場合、col_good は [1,1,1] に戻り、再び 3 ペアを提供します。 

| トップ | ボット | コル_グッド | セグメント | 貢献 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | [1,1,1] | 3 | 3 |
 | 0 | 1 | [1,0,1] | 1 + 1 | 0 |
 | 0 | 2 | [1,1,1] | 3 | 3 |

 これは、行間の垂直方向の一貫性によって有効な列がどのように動的に制限されるかを示しています。 

ここで次のことを考えてみましょう。```
z z
z z
```文字「z」の場合、すべての列が常に有効です。 行の各ペアは長さ 2 のセグメントを 1 つだけ提供し、1 つの長方形を与えます。 トレースにより、2×2 の完全な均一グリッドによって有効な境界四角形が 1 つだけ生成されることが確認されます。

 ## 特殊なケース

 少なくとも 2 つの異なる行と列が必要であるため、1×m または n×1 グリッドは長方形にはなりません。 行ペアの反復では有効なペアが生成されないため、アルゴリズムはこれを自然に処理します。 

完全に均一なグリッドが最も密度の高いケースです。 固定文字の場合、すべての Col_good がすべての行ペアでいっぱいのままになり、最大のセグメントが生成されます。 このアルゴリズムは、各行ペアのすべての列ペアをカウントし、組み合わせの期待値と一致します。 

2 文字のチェッカーボードなど、高度に交互に配置されたグリッドでは、ほとんどのcol_good 配列が単一長のセグメントに分割されます。 k selected 2 は 0 であるため、各セグメントの寄与は 0 になります。そのため、多くの行ペアが処理されているにもかかわらず、アルゴリズムは過大なカウントを正しく回避します。
