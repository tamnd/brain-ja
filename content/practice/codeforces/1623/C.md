 ## 解決策
 ## 問題の理解

 私たちには一連の石の山が与えられています。 3 番目の山から始まる 1 回の左から右へのスイープでは、各山の石を前の 2 つの山に固定比率で再分配することができます。量を選択した場合$d$、削除します$3d$現在の山から石を追加します$d$前のパイルに追加します$2d$その前のものへ。 

主な目標は、最終的な構成を任意に見つけることではなく、そのようなすべての動きを順番に実行した後に最小パイル サイズを最大化することです。 すべてのパイルは、ソース (スイープ中に到達したとき) として、および受信者 (後のパイルから) の両方として貢献します。 

制約は大きく、最大で$2 \cdot 10^5$テストケースの合計要素。 これにより、テスト ケースごとに二次関数が除外されます。 どのソリューションでも、基本的に線形または線形に近い時間で各配列を処理する必要があります。そうでないと、スケールできません。 

微妙な問題は、再分配が対称的または可逆的ではないことです。 インデックスを処理したら$i$、以前のパイルはスイープで再訪問されないため、その寄与は事実上「ロックイン」されます。 これにより、方向性の依存関係が生じ、単純な貪欲な推論では簡単に誤って処理してしまう可能性があります。 

典型的な失敗例は、初期の山が小さすぎるように見え、補償を誤って遅らせた場合に発生します。 たとえば、大きなサフィックスが以前のパイルを大幅にサポートできる構成では、各サフィックス要素からどれだけ抽出されるかを適切に制御した場合に限ります。 

もう 1 つのよくある間違いは、各ステップでのローカル バランシングが最適であると仮定することです。 たとえば、各インデックスの現在の最小値を貪欲に最大化すると、将来の移転の可能性が減少し、全体的に悪い結果につながる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての選択肢をシミュレートしようとします。$d$各インデックスで。 各ヒープで$i$のすべての有効な値に分岐できます。$d$、すべての構成を再帰的に探索し、結果として得られる最小の山を追跡します。 各ヒープが最大で寄与する可能性があるため、これは明らかに指数関数的です。$O(h_i)$考えられる選択肢とプロセスの範囲$n$ポジション。 

たとえ選択を離散化したとしても、各決定は結合された方法で以前の 2 つの位置に影響を与えるため、状態空間は依然として巨大です。 ヒープ間の相互作用は逆方向に伝播するため、ローカルな決定を独立して評価することはできません。 

重要な観察は、実際には正確な再配分には関心がなく、すべての山が少なくともあるしきい値に達することが保証できるかどうかだけを気にしているということです。$x$。 これにより、答えに対する二分探索が即座に提案されます。 

確定候補者の場合$x$、単一の左から右へのパスで実現可能性をチェックします。 重要な考え方は、各ヒープを、後方に押し出すことができる「過剰供給」を運ぶものとして解釈することですが、厳密な変換コストがかかります。つまり、3 ユニットを前方に送信すると、1 ユニットが生成されます。$i-1$そして2ユニットへ$i-2$。 

この構造により、貪欲なシミュレーションが可能になります。各インデックスで、それに到達できるすべての利用可能な供給を蓄積し、必要なしきい値を満たしていることを確認します。$x$、残りの余剰を正しい比率で以前のインデックスに転送します。 

これが機能する理由は、すべての移動が一方向 (より小さい指数に向かう方向) に単調であるため、集計された剰余を除いて、以前の決定は将来の調整から恩恵を受けることがないためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 二分探索 + 貪欲チェック | O(n log A) | O(n) | 承認済み |

 ここ$A$最大パイルサイズです。 

## アルゴリズムのチュートリアル

 最小値が固定されているかどうかをテストしたい$x$すべての杭で達成できます。 

1. 答えに対して二分探索を実行します。$x$0から$\max h_i$。 実現可能性は単調であるため、これは有効です。$x$、さらに小さな値を達成することもできます。 
2. 与えられた条件に対して$x$、配列を維持する`cur`これは、プロセスをシミュレートするときに各位置で有効に利用可能な石を表します。 当初は、`cur[i] = h[i]`。 
3. 左から右にスイープします。 インデックス時$i$、最初にインデックスから伝播された残りのコントリビューションを追加します。$i+1$そして$i+2$前のステップで。 概念的には、各将来の山は余剰を後方に貢献します。`cur`。 
4. もし`cur[i] < x`の場合、今後の操作では、すでに逆方向に伝播されたものを超えてこのインデックスを増やすことができないため、この構成は実行不可能です。 
5. もし`cur[i] >= x`、正確に保ちます$x$必要に応じて石を追加し、残りの余剰分を以前のインデックスに移管できるものとして扱います。 この余剰金は寄付金に変換されます。$i-1$そして$i-2$操作によって決定される固定比率で。 
6. すべてのインデックスに対してこのプロセスを続けます。 最後に、違反が発生しなかった場合、候補者は$x$実現可能です。 

重要な微妙な点は、余剰は常に正しい比率で直ちに後方に押し戻される必要があるということです。 後のインデックスはすでに集計された寄与に依存するため、遅延すると変換の構造が失われます。 

### なぜ効果があるのか

 すべてのインデックスで、現在のパイルに少なくとも次のものがあることを強制します。$x$サフィックスから可能なすべての貢献を受け取った後。 それを超える追加分$x$未使用のままにしておくと、初期の杭を支える将来の容量が減少するだけであるため、最適に使用されます。 剰余の各単位には固定の決定論的な後方効果があるため、貪欲な伝播により将来のすべての可能性が保存されます。 これにより、不変条件が作成されます: インデックスの処理後$i$、すべての山$j \ge i$少なくとも次の時点で固定されています$x$、残りの柔軟性はすべて、最大限に役立つ形で左に押し出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(a, x):
    n = len(a)
    cur = [0] * (n + 2)
    
    for i in range(n):
        cur[i] += a[i]

    for i in range(n - 1, 1, -1):
        if cur[i] < x:
            return False

        extra = cur[i] - x

        # extra from i can be split:
        # 3 units -> +1 to i-1, +2 to i-2
        if i - 1 >= 0:
            cur[i - 1] += extra // 3
        if i - 2 >= 0:
            cur[i - 2] += 2 * (extra // 3)

    return cur[0] >= x and cur[1] >= x

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        lo, hi = 0, max(a)
        ans = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if check(a, mid):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```このコードは、実現可能性のチェックと検索を分離します。 二分探索では、候補の最小値が試行され、それに依存します。`check`アレイ全体でそのターゲットを維持できるかどうかをシミュレートします。 

内部`check`、作業用配列を構築します`cur`伝播された余剰を受け取った後に各杭がどれだけの有効なリソースを持っているかを表します。 逆方向ループは非常に重要です。これにより、インデックスを処理するときに次のことが保証されます。$i$、後の指数からの寄与はすべてすでに考慮されています。 

転送ステップは、操作の固定比率をエンコードします。 問題の制約の下では部分的に使用すると有効な再分配が生成できないため、余剰の 3 単位の完全なグループのみを使用します。 

よくある実装の落とし穴は、間違った方向に更新することです。 内部を左から右に処理した場合`check`、将来の杭が現在の赤字を補うことができると誤って仮定することになりますが、それは不可能です。

 ## 特殊なケース

 最後のいくつかの杭は小さいが、以前の杭が大きい場合、障害が発生しやすい状況が発生します。 その場合、単純なフォワード シミュレーションでは、初期の杭がサポートをサフィックスに「押し込む」ことができると誤って想定する可能性がありますが、これは方向性のために不可能です。 このアルゴリズムは、実現可能性が右から左に厳密にチェックされ、サフィックス制約が最初に強制されるようにするため、これを回避します。 

もう 1 つのエッジ ケースは、余剰が大きいが 3 で割り切れない場合です。3 つの完全なグループのみを使用できるため、完全な転送を形成できない残りの石は未使用のままにしておく必要があります。 これは、伝播ステップの整数除算によって正しく処理されます。 

最後に、すべてのパイルが同一である場合、再分配は必要ありません。 小切手はすぐに通過します$x = h_i$、二分探索は転送をトリガーせずに収束し、アルゴリズムが不必要に演算を過剰に適用していないことを確認します。
