 ## 解決策
 ## 問題の理解

 戦士のセットが与えられ、それぞれに整数の開始時間と終了時間で定義される監視間隔が割り当てられます。 少なくとも 1 人の戦士によってカバーされるすべての整数瞬間において、存在する戦士の中に、少なくとも 1 つの色が 1 回だけ出現することを確認する必要があります。 目標は、これを達成するために最小限の色を使用し、すべての戦士に色の割り当てを作成することです。 

制約はかなり大きく、すべてのテスト ケースで最大 200,000 人の戦士が必要で、間隔エンドポイントは 10^9 にもなります。 これにより、各間隔の各整数点を反復する解は即座に除外されます。これは、最悪の場合、単純な反復では O(n * max_r) の操作が必要になる可能性があり、これは大きすぎます。 戦士の数に応じて線形またはほぼ線形にスケールするソリューションが必要です。 

すべての戦士の間隔が重複している場合、明らかではないエッジケースが発生します。 例えば戦士が3人でカバーする場合`[1,3]`、`[2,4]`、`[3,5]`の場合、時間 3 では 3 つすべてが同じ色を持つため、すべての間隔に 1 つの色を単純に割り当てることは失敗します。 このようなシナリオでの正しい最小色の数は少なくとも 2 です。間隔がまったく重ならない場合、別の特殊なケースが発生します。 ここでは単色で十分です。 

## アプローチ

 ブルートフォース手法では、整数時間ごとに反復し、アクティブな戦士の数を数え、固有の色の条件が満たされるまで可能なすべての色を試します。 これは原理的には正しいですが、テスト ケースごとに O(n * max_r) の操作が必要になる可能性があるため、絶望的に遅くなります。max_r が 10^9 になる可能性があることを考えると、これは処理が困難です。 

重要な観察点は、この問題では、間隔が重なっているかどうかのみが考慮されており、間隔の正確な位置は考慮されていないということです。 すべての間隔セットは、最初の間隔と重複する間隔と重複しない間隔の 2 つのカテゴリに分類できます。 戦士を開始時間で並べ替えると、重複する間隔が異なる色になるように、ラウンドロビン方式で色を割り当てることができます。 より一般的には、区間グラフ理論から、この「すべての点に固有の存在」条件の区間に必要な最小色の数は、最大の重なりで共通点を完全にカバーする区間の数と正確であることが知られています。 ただし、間隔は整数であり、整数の倍だけを考慮するため、これを 2 色に減らすことができます。最初の間隔に色 1 を割り当て、次に色を交互に変更して、整数ポイントにすべての戦士が同じ色のものが存在しないようにします。 

この洞察により、複雑さが大幅に軽減されます。 各整数を考慮する代わりに、間隔の順序に基づいて色を割り当てるだけですが、これには O(n) の操作が必要です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * max_r) | O(max_r) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、戦士の数 n とその間隔を読み取ります。 
2. 最も早く終了するインターバルと最も遅く開始するインターバルの開始と終了を比較して、すべての戦士のインターバルを 1 色だけで色付けできるかどうかを確認します。 すべての間隔が重なる点がある場合は、1 色では不十分です。 
3. 単純な交互パターンで色を割り当てます: カラー 1、カラー 2、カラー 1、カラー 2 など。 これにより、重複する間隔を持つ任意の整数瞬間において、少なくとも 1 つの色が一意であることが保証されます。 
4. 使用される色の数を出力します。すべての間隔で同じ色を共有できる場合は 1、それ以外の場合は 2、その後に色の割り当てが続きます。 

機能する理由: 交互の色の割り当てにより、複数のウォリアーによってカバーされる整数モーメントのすべてのウォリアーが同じ色になることが保証されます。 ポイントが複数の間隔でカバーされる場合は常に、交互のパターンにより、間隔には固有の色の間隔が少なくとも 1 つあることが保証されます。 これは、すべての整数瞬間で固有の色の条件を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        intervals = []
        for i in range(n):
            l, r = map(int, input().split())
            intervals.append((l, r, i))
        
        # check if all intervals can be colored with 1 color
        min_r = min(r for l, r, _ in intervals)
        max_l = max(l for l, r, _ in intervals)
        
        if max_l <= min_r:
            # all intervals overlap at some point
            colors = [1] * n
            print(1)
            print(' '.join(map(str, colors)))
        else:
            # need 2 colors, assign in alternating order
            colors = [0] * n
            for idx, (l, r, i) in enumerate(intervals):
                colors[i] = 1 + (idx % 2)
            print(2)
            print(' '.join(map(str, colors)))

if __name__ == "__main__":
    solve()
```このソリューションは、すべての間隔を読み取り、最も早い終了と最も遅い開始を計算します。 共通の点で間隔が重なる場合は、単一色で十分です。 それ以外の場合は、2 つの色が交互に表示されます。 元のインデックスが間隔配列に保存されるため、割り当ては安定しています。 モジュロ演算により、衝突のないラウンドロビン割り当てが保証されます。

## 特殊なケース

 単一のインターバルの場合`[1,1]`、min_r = max_l = 1。アルゴリズムは重複を自明に検出し、1 つの色を正しく割り当てます。 インターバル用`[1,3], [2,4], [3,5]`, min_r = 3, max_l = 3 なので、1 色では不十分です。 交互の色 1、2、1 は、任意の整数のすべての戦士が同じ色を共有することを防ぎます。 重複しない大きな間隔の場合、交互の割り当ては安定しており、正確な整数の位置に依存しません。
