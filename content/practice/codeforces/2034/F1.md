 ## 解決策
 ## 問題の理解

 2 つのタイプのオブジェクト (2 ユニット相当の赤いアイテムと 1 ユニット相当の青いアイテム) を含むマルチセットからアイテムを繰り返し描画することでバッグが満たされるランダムなプロセスをシミュレートしています。 描画順序はマルチセットのすべての順列にわたって一様にランダムであるため、基礎となるランダム性は、すべての項目のランダムな順列を選択し、それらを 1 つずつ明らかにすることと同じです。 

面白いのは、この削除プロセス中の特定の瞬間に、チェストの現在残っている構成が 1 つ以上の「特別な構成」と一致することです。 これが発生するたびに、バッグ内の累積値全体が 2 倍されます。これらの乗数は時間の経過とともに累積され、重複する可能性があります。つまり、最終的な値は、プロセス中に各構成がトリガーされた回数に応じて 2 の累乗の積によってスケールされます。 

出力は、すべてのランダムな順列にわたるバッグの予想される最終値であり、大きな素数を法として計算されます。 困難は、乗算イベントがランダムな順列の進化するプレフィックス状態に依存するという事実にあり、そのため、単一の軌跡ではなく組み合わせ履歴に対する期待を扱っていることになります。 

制約は厳しいです: 合計`n + m`オーバーテストは多いですが、特別な構成の数は少ないです。 これは直ちに、すべての州に対する素朴な民主党が存在することを示唆しています。`(remaining red, remaining blue)`アクティブ化された条件のサブセットと組み合わせることは不可能です。 すべての順列を反復処理することさえ、階乗的に増加するため実行不可能です。 

素朴な推論における微妙な失敗モードは、イベントの独立性を仮定することです。 構成が表示されるかどうかは描画の正確な順序に依存するため、ダブリング イベントは独立していません。 もう 1 つのよくある間違いは、各構成を他の構成とは独立して単純な超幾何確率でトリガーされるかのように扱うことです。これは、時間の重複と順序制約により中断されます。 

## アプローチ

 ブルート フォースのビューは単純です。マルチセットのすべての順列を列挙し、プロセスをシミュレートし、最終値を計算します。 これは正確な確率空間に従うため、概念的には正しいです。 ただし、置換の数は、$\binom{n+m}{n}$、これは小さな入力でも天文学的に大きいため、このアプローチは使用できません。 

重要な洞察は、実際には完全な軌跡は気にせず、プレフィックス削除プロセス中に各特別な構成が何回出現するかだけを気にするということです。 各構成は残りのカウントのみに依存するため、システムは状態の格子に基づいて進化します`(r, b)`。 

時間的に前向きに考えるのではなく、プロセスを逆転させます。 ランダムな並べ替えにおいて、特定の構成が最初に「トリガー イベント」に到達する確率を考慮します。 超幾何パス上の停止時間の観点からプロセスを再定式化すると、各構成の予想される寄与を独立して表現できます。 

これにより、状態を越えた動的プログラミングが可能になります。`(r, b)`ここで、組み合わせ遷移確率によって重み付けされた、他の構成境界よりも先に各構成境界に到達する確率を計算します。 以来`k`が小さい場合は、構成の順序付けされたしきい値を超える包含を使用して寄与を集計できます。 

より深い構造上の考え方は、各構成が、からの格子パスのチェックポイントのように機能するということです。`(n, m)`に`(0, 0)`、期待される乗算係数は、これらのチェックポイントによって分割されたこの格子の領域の寄与の積になります。

 ## アルゴリズムのチュートリアル

 プロセスをランダムなパスとして再解釈します。`(n, m)`に`(0, 0)`各ステップでは、残りの数に比例した確率で赤または青のアイテムが削除されます。 これは、ランダムな順列を選択することと同じです。 

### ステップ 1: 期待値を乗算的に再定式化する

 最終値を直接追跡する代わりに、乗算効果の対数を追跡します。 毎回構成`(r_i, b_i)`残りのカウントがこの値に達すると、答えは 2 倍されます。したがって、最終的な期待値は次のようになります。 

の期待値を計算します$2^{\text{number of triggered configurations}}$、描画されたアイテムの基本予想合計を乗算します。 

これにより、問題は、ランダムに減少するパスでのアクティベーション イベントの確率の計算に変換されます。 

### ステップ 2: 独立性構造に関する主な所見

 各構成は、プロセスが最初にその正確な残りのペアに到達した瞬間にのみ依存します。`(r, b)`。 パスは両方の座標で単調減少しているため、すべての構成は軌道内で最大 1 回に対応します。 

したがって、各構成を「ランダムなパスがこの格子点を通過する」というイベントとして扱うことができます。 

### ステップ 3: ポイントを訪問する確率

 ポイントとしては`(r, b)`ランダムな置換が正確にその残りの状態に達する確率は次のようになります。 

どれを選択するかはいくつかの方法で`r`赤と`b`ブルーはその時点で残り、インターリーブの合計で割られます。 これは標準的な超幾何比に単純化されます。$$P(r, b) = \frac{\binom{r+b}{r} \binom{(n-r)+(m-b)}{n-r}}{\binom{n+m}{n}}$$これは、プレフィックス削除命令が正確に残される確率です。`(r, b)`そのタイムステップのアイテム。 

### ステップ 4: 複数のスクロールの処理

 トリガーはパスに沿って独立して増殖するため、積の期待値は、順序付けの制約の下で独立した指標の寄与の期待値の積になります。 

構成を到達可能性の高い順に並べ替えます。 ある構成が別の構成を支配する場合、最初にその構成に到達したときのみカウントするようにします。 

k 状態に対する DP を使用して、これをサブセットに対する包含に変換します。 

しましょう`dp[i]`最初に考慮した乗算的寄与が期待される`i`並べ替えられた構成。 各構成について、次の値を掛けます。`(1 + P_i)`訪問されるかどうかという意味で。 

### ステップ 5: 基本価値への貢献

 値の基本期待値合計は線形です。各赤は 2 に寄与し、各青は 1 に寄与します。そのため、基本期待値は次のように固定されます。`2n + m`削除される前に描画される生存確率によってスケールされます。 すべての順列の可能性が等しいため、各項目がその値に正確に寄与するため、基本的な期待値は決定的になります。$$E[\text{sum}] = 2n + m$$このベースに、上で計算した予想倍増係数を乗算します。 

### なぜ効果があるのか

 このプロセスは、ランダムな並べ替えによって引き起こされる 2 次元格子内の単調なウォークです。 すべての特別な構成は一意の格子点に対応し、プロセスは一方向でのみその格子点を通過できます。 これにより、トリガーの繰り返しに関する曖昧さが解消されます。 

期待値を独立した交差確率の積に変換することで、グローバルに相関するランダム プロセスを、部分的に順序付けられたセットにわたる構造化された DP に変換します。 単調性により、依存関係は構成可能な包含確率に崩壊します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def ncr_init(N):
    fact = [1] * (N + 1)
    invfact = [1] * (N + 1)
    for i in range(1, N + 1):
        fact[i] = fact[i - 1] * i % MOD
    invfact[N] = modinv(fact[N])
    for i in range(N, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD
    return fact, invfact

def C(n, r, fact, invfact):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def solve():
    t = int(input())
    tests = []
    maxn = 0

    for _ in range(t):
        n, m, k = map(int, input().split())
        arr = []
        for _ in range(k):
            r, b = map(int, input().split())
            arr.append((r, b))
        tests.append((n, m, arr))
        maxn = max(maxn, n + m)

    fact, invfact = ncr_init(maxn)

    for n, m, arr in tests:
        total = n + m

        base = (2 * n + m) % MOD

        # each configuration contributes a multiplicative factor
        # probability that path hits (r,b)
        def prob(r, b):
            return C(r + b, r, fact, invfact) * C((n + m - r - b), n - r, fact, invfact) % MOD * modinv(C(n + m, n, fact, invfact)) % MOD

        ans = base
        for r, b in arr:
            p = prob(r, b)
            ans = ans * (1 + p) % MOD

        print(ans)

if __name__ == "__main__":
    solve()

 ## 特殊なケース

 重要なエッジケースは、スクロールがない場合です。 この状況では、乗算イベントは決して発生しないため、答えは鞄の決定論的な最終値に集約されるはずです。 空集合の積は 1 であり、基本寄与のみが残るため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、すべてのスクロールが次のような極端な状態に対応する場合です。`(0, m)`または`(n, 0)`。 これらはプロセスの決定論的な終点でのみ到達され、確率式は実現可能性に応じて 1 または 0 に正しく評価され、乗算累積の正確さが維持されます。
