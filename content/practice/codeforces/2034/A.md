 ## 解決策
 ## 問題の理解

 この問題では、指定された 2 つの数値に関して 2 つの特性を満たす数値を見つけるように求められます。$a$そして$b$。 具体的には、最小の整数が必要です$m$そのような$m$少なくとも 2 つの数値のうちの 1 つと残りの数値と同じ大きさです。$m$で割ると$a$で割ったときの余りに等しい$b$。 言い換えれば、次の段階で数えることを想像すると、$a$そして$b$ゼロから始めて、$m$は、2 つのシーケンスの残りが「整列」する最初の数値です。 

入力は複数のテスト ケースで構成され、それぞれが提供するもの$a$そして$b$。 どちらの値も 1000 までに制限されており、テスト ケースの数は最大 100 です。$a$そして$b$が比較的小さい場合、時間制限を超えずに反復または倍数を計算するアプローチを検討できます。 

微妙なエッジケースが発生する場合$a = b$。 以上の任意の数値$a$自動的に剰余条件を満たしますので、最小値は$m$単純に$a$（または$b$）。 別のシナリオは次のような場合です。$a$そして$b$は互いに素である。 剰余は最小公倍数以降でのみ一致するため、アルゴリズムはどちらの入力よりも大幅に大きい数値を処理する必要があります。 不注意なブルート フォース チェックでは、すべての整数に対して不必要に反復処理が行われ、最初の有効な数値が正確に最小公倍数 (LCM) であることを見逃す可能性があります。 

## アプローチ

 ブルートフォースアプローチは次から始まります$\max(a, b)$そして増加します$m$それまで$m \bmod a = m \bmod b$。 これは問題の条件を直接実装するため機能しますが、入力が大きいとパフォーマンスが低下します。 たとえば、次の場合$a = 999$そして$b = 1000$、剰余条件を満たす最初の数値は、$999 \cdot 1000 = 999000$。 ここでは、テスト ケースごとに 100 万近くの数値を反復処理することは可能ですが、非効率的であり、より大きな範囲では遅くなります。 

重要な洞察は条件を書き直すことで得られます$m \bmod a = m \bmod b$。 これは言うのと同じです$m$の最大公約数を法とした同じ剰余を残します$a$そして$b$。 もっと具体的に言うと、$d = \gcd(a, b)$、次に数字$m$剰余等式を満たすものは、まさに次の形式のものです。$m = k \cdot \mathrm{lcm}(a, b)$ある整数に対して$k \ge 1$。 そのような最小のもの$m$それは少なくとも$\max(a, b)$はまさに次の最小公倍数です$a$そして$b$。 

したがって、最適なアプローチは、次の LCM を計算することです。$a$そして$b$テストケースごとにそれを返します。 これは標準的な整数理論を使用します。$\mathrm{lcm}(a, b) = \frac{a \cdot b}{\gcd(a, b)}$。 これにより、反復が完全に回避され、指定された制約に対して効率的に機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(a*b) 最悪の場合 | お(1) | 正しいですが、特殊なケースでは遅くなります。 
| 最適 (GCD 経由の LCM) | O(log(min(a,b))) | お(1) | 迅速かつ受け入れられます |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 これにより、処理する数値のペアの数が決まります。 
2. テスト ケースごとに、整数を読み取ります。$a$そして$b$。 
3. 最大公約数を計算する$d = \gcd(a, b)$。 これはユークリッド アルゴリズムを使用します。これは効率的で、$O(\log \min(a, b))$ステップ。 
4. 次を使用して最小公倍数を計算します。$\mathrm{lcm}(a, b) = a \cdot b // d$。 これにより、両方で割り切れる最小の数が保証されます。$a$そして$b$、これも満たします$m \bmod a = m \bmod b$。 
5. 計算された LCM を出力します。 これが最小限です$m$テスト ケースの両方の条件を満たします。 

機能する理由: 任意の数$m$と$m \bmod a = m \bmod b$の倍数でなければなりません$\mathrm{lcm}(a, b)$剰余は最小公倍数の倍数ごとに繰り返されるためです。 最初の倍数をとることで最小性が保証され、LCM は常に両方以上であるため、$a$そして$b$、「次の少なくとも 1 つ」を満たします。$a, b$ユークリッド アルゴリズムにより、LCM が正確かつ効率的に計算されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b = map(int, input().split())
    lcm = a * b // math.gcd(a, b)
    print(lcm)
```コードは高速入力の読み取りから始まります。 For each test case, it parses the two numbers, computes their GCD using Python's built-in`math.gcd`、浮動小数点エラーを避けるために、整数除算によって LCM を計算します。 最後に、結果をすぐに出力します。 複数のテスト ケースの処理は簡単で、LCM は本質的に最小条件を満たしているため、off-by-one エラーは発生しません。

## テストケース```python
import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = []
    t = int(input())
    for _ in range(t):
        a, b = map(int, input().split())
        lcm = a * b // math.gcd(a, b)
        output.append(str(lcm))
    return "\n".join(output)

# Provided samples
assert run("2\n4 6\n472 896\n") == "12\n52864", "Sample test cases"

# Custom cases
assert run("1\n1 1\n") == "1", "Minimum equal values"
assert run("1\n1000 1000\n") == "1000", "Maximum equal values"
assert run("1\n2 3\n") == "6", "Small coprime numbers"
assert run("1\n5 7\n") == "35", "Another coprime example"
assert run("1\n8 12\n") == "24", "Shared divisors"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 1 1 | 1 | 最小入力、a = b |

 | 2 3 | 6 | 小さな互いに素数 |

 ## 特殊なケース

 入力用`1 1`、GCD は 1、LCM は 1 です。アルゴリズムは正しく 1 を返し、すぐに剰余条件を満たします。 

のために`1000 1000`、GCD = 1000、つまり LCM = 1000。この出力は、最小条件と剰余の等式の両方を満たす最初の数値です。 

次のような共素数の場合`2 3`、剰余の最初の位置合わせは 6 で行われ、LCM アプローチが互いに素数を正しく処理することが確認されます。 

公約数のある数値の場合、`8 12`、LCM = 24、これは確かに、剰余が等しい場合のどちらの入力よりも大きい最小の数です。 これらの各トレースは、アルゴリズムが最小値、最大値、互いに素、および共有除数の入力を正確に処理していることを示しています。
