 ## 解決策
 ## 問題の理解

 乗算ボーナスを伴う確率的プロセスの後に、宝石のコレクションの期待合計値を計算するように求められます。 Khayyam は、次のものが入ったチェストから始まります。`n`赤いルビー、それぞれの価値`2`、 そして`m`ブルーサファイア、それぞれの価値`1`。 各ターンで、彼は宝箱から均一にランダムに宝石を取り出し、それを鞄に移します。 チェスト内の特定の宝石の数により、現在かばんに入っているすべての宝石の価値を 2 倍にする王令が発動されます。 このプロセスはすべての宝石が描画されるまで続き、最終的な期待値の剰余を計算することが目標となります。`998,244,353`。 

入力により複数のテスト ケースが提供され、それぞれに初期カウントが含まれます。`n`そして`m`とセット`k`それぞれ条件を指定したスクロール`(r_i, b_i)`残りのジェムで倍増をトリガーします。 制約により許可される`n + m`まで`2*10^5`すべてのテストケースと合計`k`まで`5000`。 これは、ステップごとの複雑さを持つアルゴリズムは次のとおりであることを示します。`n*m`実現可能ですが、二次関数は何でも`n + m`テストケースごとの処理は遅すぎる可能性があります。 

スクロールが存在しない場合、特殊なケースが発生します。 たとえば、次の場合`n=3, m=4, k=0`、期待値は常に`3*2 + 4*1 = 10`。 もう 1 つの微妙なケースは、最初に描画された宝石でスクロールがトリガーされる場合です。 単純な線形シミュレーションでは、法令の確率重み付けが無視され、誤った期待値が生成される可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるあらゆる描画シーケンスをシミュレートし、乗算効果を追跡します。 期待はすべてのシーケンスにわたる線形結合であるため、これは正しいですが、大規模なシーケンスでは失敗します。`n + m`シーケンスの数が階乗的に増加するためです。 具体的には、シーケンスの数は次のようになります。`(n + m)! / (n! m!)`を超える`10^100`適度な入力サイズ向け。 

重要な洞察は、かばんの期待値が宝石に対して線形であるということです。 各宝石について独立して推論することができます。赤いルビーの場合、その基本値は 2 であり、かばんの中にある間に経験する各法令ごとに 2 を掛けます。 同様に、ブルー サファイアの基本値は 1 です。すべてのシーケンスをシミュレートする代わりに、潜在的な宝箱の状態ごとに、宝石が引き出された瞬間にそれが発生する確率と布告がトリガーされるかどうかを計算します。 赤と青の宝石の残りの数に対して動的プログラミングを使用し、予想される乗算因数を計算することにより、問題を階乗から多項式の時間に短縮します。`n*m`そして直線的に`k`。 さらに、浮動小数点演算を回避するために確率計算に逆モジュラーを利用できます。 

最適なソリューションは、次の定義に依存します。`dp[r][b]`かばんの中の宝石の予想乗数として、`r`赤と`b`青が残っています。 残りのカウントを小さい値から大きい値に反復し、正確な状態で倍増命令を適用することにより、期待値を効率的に伝播することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O((n+m)!) | O(n+m) | 遅すぎる |
 | 残りのカウントに関する動的プログラミング | O(n*m + k) | O(n*m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. セットまたは辞書を初期化する`scrolls`特定の残りの状態かどうかをすばやく確認する`(r, b)`政令を発動する。 これにより、DP 中の定時間ルックアップが可能になります。 
2. 2D 配列を作成する`dp`サイズの`(n+1) x (m+1)`描画されたジェムの予想乗数を保存します。`r`赤と`b`胸に青が残る。 セット`dp[0][0] = 1`基本ケースとして、宝石は残っておらず、それ以上の倍増は不可能であるためです。 
3. 反復する`r`0から`n`そして`b`0から`m`。 それぞれについて`dp[r][b]`、もう 1 つの宝石が描画されたときに期待される乗数を計算します。 

- もし`r > 0`、赤いルビーを引く確率は`r / (r + b)`。 追加`dp[r-1][b] * prob_red`に`dp[r][b]`。 
- もし`b > 0`、ブルーサファイアを引く確率は`b / (r + b)`。 追加`dp[r][b-1] * prob_blue`に`dp[r][b]`。 
4. 現在の状態の場合`(r, b)`いる`scrolls`、乗算する`dp[r][b]`法令を考慮して2で。 モジュラー演算はすべてのステップで適用されます。 
5. 記入後、`dp`テーブルでは、すべての宝石を合計し、その基本値に次の値を掛けて期待値を計算します。`dp[n][m]`。 赤いルビーの場合、これは貢献します`2 * n * dp[n][m]`、ブルーサファイアの場合`1 * m * dp[n][m]`。 
6. モジュラー算術で確率を処理するには、モジュラー逆数を使用して分数を表します。 もし`p/q`は確率です、計算します`p * q^{-1} % MOD`。 

ここでの不変条件は、`dp[r][b]`チェストに残っているジェムの期待される乗算係数を常に表します。`r`赤と`b`青い宝石。 ジェムの少ない州からジェムの多い州に値を伝播することで、期待に対する各ジェムの寄与が、それに影響を与える可能性のあるすべての法令を確実に考慮します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD-2, MOD)

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        scrolls = set()
        for _ in range(k):
            r, b = map(int, input().split())
            scrolls.add((r, b))
        
        dp = [[0]*(m+1) for _ in range(n+1)]
        dp[0][0] = 1

        for r in range(n+1):
            for b in range(m+1):
                if r == 0 and b == 0:
                    continue
                total = r + b
                val = 0
                if r > 0:
                    val += dp[r-1][b] * r * modinv(total)
                if b > 0:
                    val += dp[r][b-1] * b * modinv(total)
                val %= MOD
                if (r, b) in scrolls:
                    val = (val * 2) % MOD
                dp[r][b] = val

        result = (2 * n * dp[n][m] + 1 * m * dp[n][m]) % MOD
        print(result)

solve()
```の`modinv`関数は確率が分数であるため、モジュラー除算を処理します。`dp[r][b]`ジェムの予想される乗数を保存します。`r`赤と`b`青が残っています。 状態がスクロールと一致すると、ダブリングがすぐに適用されます。 最後に、すべての宝石の合計により、基本値に予想される乗数が乗算されます。 

## 実用的な例

 **例 1**:`n=1, m=1, k=1`、スクロール`(1,0)`。 

| r | b | dp[r][b] | 説明 |
 | --- | --- | --- | --- |
 | 0 | 0 | 1 | 基本ケース |
 | 1 | 0 | 2 | 赤だけが残り、スクロールトリガーが2倍になります |
 | 0 | 1 | 1 | 青だけが残り、スクロールはありません |
 | 1 | 1 | 3/2 | 確率: 赤 1/2 -> 2、青 1/2 -> 1 |

 最終的な期待値：赤が貢献`2*dp[1][1] = 2*3/2 = 3`、 青`1*dp[1][1] = 3/2`。 和`4.5`、モジュロ`998244353`は`499122180`。 

**例 2**:`n=3, m=4, k=0`。 

巻物が存在しないため、すべての宝石は基本価値を維持します。 期待値は`3*2 + 4*1 = 10`。

 | 測定 | 複雑さ | 説明 |
