 ## 解決策
 ## 問題の理解

 この問題では、ラクシュの体を次の線としてモデル化します。$n$スポット、各スポットが弱い ($0$) または強い ($1$）。 ロスタムは、連続した間隔で次のことを保証したいと考えています。$m$斑点があれば、少なくとも 1 つの斑点が強いです。 彼は、連続したあらゆる攻撃を即座に強化する操作を実行できます、ティマール$k$それらすべてをスポットに変えます$1$s. タスクは、次の間隔が発生しないことを保証するために必要な Timar 操作の最小数を決定することです。$m$連続スポットは依然として完全に弱いままです。 

入力には複数のテスト ケースがあり、それぞれが文字列の長さを指定します。$n$、安全な間隔の最小長$m$、ティマールセグメントの長さ$k$、およびバイナリ文字列$s$。 各テスト ケースの出力は、必要な操作の最小数を示す単一の整数です。 

制約は次のことを意味します$n$まで可能です$2 \cdot 10^5$テストケースごと、すべての合計$n$テストケース全体でも以下に限定されます$2 \cdot 10^5$。 これにより、より複雑なアルゴリズムは使用できなくなります。$O(n)$テストケースごとに。 すべてを繰り返しチェックする素朴なアプローチ$m$-長さの間隔は次のようになります$O(nm)$テストケースごとに、遅すぎます。 エッジケースには、すでに条件を満たしている文字列、すべての条件を満たしている文字列が含まれます。$0$s、および次の場合$m>k$、隙間なくすべての弱い間隔をカバーするには、演算を慎重に配置する必要がある場合があります。 

## アプローチ

 ブルートフォースアプローチでは、それぞれをスキャンします。$m$-length ウィンドウ、およびそれが完全に長さの場合$0$s、そのウィンドウ内の任意の位置に Timar 操作を適用します。 これは原理的には正しいですが、単純に操作をスキャンして適用すると、$O(nm/k)$複雑さが高すぎる場合$n$アプローチ$2 \cdot 10^5$。 

重要な観察は、問題は、次の連続するセグメントの処理に帰着できるということです。$0$s. 長さ 0 の連続するブロックごとに$L$、それを完全にカバーするのに十分なティマール操作を適用し、すべての$m$-そのブロック内の長さの間隔には、少なくとも 1 つが含まれます$1$。 最小操作数は次のとおりです。$\lceil L / k \rceil$そして、ティマールを常に左端の弱点から開始し、右に移動します。$k$毎回、最小限の補償範囲を保証します。 これにより問題は次のように縮小されます$O(n)$文字列を 1 回反復して、連続するゼロの長さをカウントするだけでよいため、テスト ケースごとに実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nm)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`ops = 0`使用された Timar 操作の数を保存します。 
2. 文字列を反復処理します。`s`インデックス付き`i`0から始める。 
3. もし`s[i]`は`1`、増分`i`このスポットはすでに強力なので、続けてください。 
4. もし`s[i]`は`0`、弱点の新しいセグメントが始まります。 初期化する`length = 0`。 
5. ながら`i < n`そして`s[i]`は`0`、両方を増分します`length`そして`i`。 これにより、ゼロの連続セグメント全体がキャプチャされます。 
6. このセグメントに必要な Timar 操作の数を次のように計算します。`ceil(length / k)`として実装できます。`(length + k - 1) // k`。 
7. この数字を`ops`。 
8. 文字列の終わりまで繰り返します。 
9. 出力`ops`現在のテスト ケースの最小操作数として。 

機能する理由: このアルゴリズムは、以前に処理されたすべての弱いセグメントが Timar 演算によって完全にカバーされ、各演算が正確にカバーするという不変条件を維持します。$k$セグメントの左から始まるスポット。 セグメントを順番に処理することにより、カウントに重複がなく、すべてのセグメントが$m$-length ゼロの間隔には、少なくとも 1 つが含まれることが保証されます。$1$操作が適用された後。 これにより正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        s = input().strip()
        ops = 0
        i = 0
        while i < n:
            if s[i] == '1':
                i += 1
            else:
                length = 0
                while i < n and s[i] == '0':
                    length += 1
                    i += 1
                ops += (length + k - 1) // k
        print(ops)

if __name__ == "__main__":
    solve()
```このソリューションは、まずテスト ケースの数を読み取ります。 各テスト ケースについて、次のようになります。`n`、`m`、`k`そしてバイナリ文字列`s`。 インデックス`i`ストリング内を順番に移動し、強いスポットをスキップします。 ゼロに遭遇すると、連続する弱いセグメントをカウントし、上限を実装するために必要な Timar 演算の最小数を整数除算を使用して計算します。 結果はテスト ケースごとに出力されます。 使用する`strip()`末尾の改行が処理を妨げないようにします。

## 特殊なケース

 文字列がすでに安全である場合、アルゴリズムはすべての 1 をスキップし、操作数が 0 であることを報告します。 より長い連続ゼロの場合`k`、次のように操作の数が正しく計算されます。`(length + k - 1) // k`。 1 が散在する単一のゼロの場合、長さ 1 の各ゼロ セグメントが 1 つの演算につながり、アルゴリズムがまばらな弱点を正しく処理することが確認されます。 左から右への貪欲なカバレッジにより、間隔が確保されません。`m`連続したゼロはカバーされないままになります。
