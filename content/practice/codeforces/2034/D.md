 ## 解決策
 ## 問題の理解

 一連の石柱が与えられ、それぞれの柱には底面があり、その上部には 0、1、または 2 の少数の碑文が刻まれています。この列は整数の配列と考えることができます。`a[i]`i 番目の列の碑文の数を表します。 目標は、一連の移動を使用して、この配列を非降順に並べ替えることです。 移動するたびに、ある列から碑文を取得して別の列に移すことができますが、現在の碑文数の差がちょうど 1 である場合に限ります。言い換えれば、碑文を 1 つ多い列から 1 つ少ない列に移動することしかできません。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、列の数と碑文の初期構成が指定されます。 出力では、最大でも次の有効なシーケンスを記述する必要があります。`n`移動します（どこで`n`は列の数です)、非減少シーケンスが生成されます。 

問題の制約は重要です。 各列には 0、1、または 2 つの刻印しか含めることができないため、可能な構成の数が大幅に制限されます。 すべてのテスト ケースにわたる列の合計数は最大 200,000 になる可能性があるため、考えられるすべての転送をシミュレートしようとしたり、O(n²) 操作を実行したりするソリューションは遅すぎます。 テスト ケースごとに線形またはほぼ線形のソリューションが必要です。 

複数の 2 と 0 があり、それらの間に介在する 1 が 1 つだけある場合、微妙なエッジ ケースが発生します。 たとえば、次のように考えてみましょう`[2, 0, 2]`。 単純に要素を間違った順序で交換すると、2 と 0 の間を直接移動できないため、シーケンスがソートされないままになる可能性があります。アルゴリズムは常に、`|difference| = 1`制限。 

## アプローチ

 ブルートフォース手法は単純です。配列を反復処理し、左の列が右の列より大きく、差が 1 である列のペアを見つけ、移動を実行し、配列がソートされるまで繰り返します。 このアプローチは原理的には正しいですが、最悪の場合、たとえばシーケンスが`[2, 0, 2, 0, 2, ...]`。 と`n`200,000 までになると、これは計算上不可能になります。 

重要な点は、列の高さの値が 0、1、2 の 3 つだけであるということです。したがって、配列のソートは、各値の出現回数をカウントし、ソートされた順序で配列を再構築することになります。 動き自体は体系的に決定できます。1 の前に現れる各 2 は碑文を 1 に転送でき、0 の前に現れる各 1 は碑文を 0 に転送できます。常に、正確に 1 つの碑文を持つ列が少なくとも 1 つあるため、この 1 は 0 と 2 の間の転送を仲介するピボットとして機能します。 

この観察により、問題を単純な線形スキャンに帰着させることができます。 すべての 0、1、2 のインデックスを記録します。 次に、1 を 2 から 0 に順番に移動するシミュレーションを行い、非降順を保証するために常に左端の候補列を選択します。 各移動には 2 つのインデックスが含まれており、値の差がちょうど 1 であるため、すべての移動が有効になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | カウンティング + 貪欲な転送 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 3 つのリストを初期化します。`zeros`、`ones`、 そして`twos`、それぞれ 0、1、2 の刻印を持つ列のインデックスを保持します。 
2. 配列を反復処理する`a`一度。 各列について、その値に基づいて、そのインデックスを適切なリストに追加します。 これにより、現在の高さによるインデックスの完全な分割が得られます。 
3. 空のリストを初期化する`moves`操作を保存します。 
4. 1 を 2 から 1 に転送して、高列と中列の間を仲介します。 の各インデックスについて`twos`それはインデックスの前です`ones`配列内で 2 から 1 への移動を実行し、それを記録します`moves`。 を更新します`a`それに応じて配列します。 
5. 1 を 1 から 0 に転送して、中列と低列の間を仲介します。 の各インデックスについて`ones`それはインデックスの前です`zeros`、1 から 0 への移動を実行し、それを記録します。`moves`。 を更新します`a`それに応じて配列します。 
6. すべての転送が完了すると、アレイが`a`降順ではない順にソートされます。 移動回数に続いて移動操作のリストを出力します。 

機能する理由: 各ステップで、アルゴリズムは 1 だけ異なる列間の碑文のみを転送します。最初に 2 を 1 に処理し、次に 1 を 0 に処理することで、すべての 2 が右にシフトされ、すべての 0 が左にシフトされることが保証されます。 列の合計数が少なく、値が制限されているため、これにより、最終的なシーケンスがソートされ、どの移動も差分制約に違反しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        zeros, ones, twos = [], [], []
        for i, val in enumerate(a):
            if val == 0:
                zeros.append(i)
            elif val == 1:
                ones.append(i)
            else:
                twos.append(i)
        
        moves = []
        
        z_ptr, o_ptr, t_ptr = 0, 0, 0
        
        while t_ptr < len(twos) and o_ptr < len(ones):
            if twos[t_ptr] < ones[o_ptr]:
                moves.append((twos[t_ptr] + 1, ones[o_ptr] + 1))
                t_ptr += 1
                o_ptr += 1
            else:
                o_ptr += 1
        
        o_ptr, z_ptr = 0, 0
        while o_ptr < len(ones) and z_ptr < len(zeros):
            if ones[o_ptr] < zeros[z_ptr]:
                moves.append((ones[o_ptr] + 1, zeros[z_ptr] + 1))
                o_ptr += 1
                z_ptr += 1
            else:
                z_ptr += 1
        
        print(len(moves))
        for u, v in moves:
            print(u, v)

if __name__ == "__main__":
    solve()
```コードはまずインデックスを値ごとに分割します。 次に、2 ポインター手法を使用して、必要な差を正確に 1 に維持しながら、より高い値からより低い値への有効な転送をシミュレートします。`+1`ゼロベースの Python インデックスを 1 ベースの問題インデックスに変換します。 while ループを慎重に順序付けすることで、無効な移動が試行されることがなくなります。
