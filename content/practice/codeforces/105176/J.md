 ## 解決策
 ## 問題の理解

 石のコレクションが与えられ、各石は正の整数の重みを持ちます。 このプロセスでは、入手可能な 2 つの最も重い石を繰り返し取り、両方を破壊し、それらの重さが異なる場合は、2 つの石の差に等しい重さの新しい石が生成されます。 これは、石が最大 1 つ残るまで続きます。 タスクは、最終的な残りの重量、または石が残っていない場合はゼロを決定することです。 

入力は、石の重量の初期マルチセットを表します。 出力は、「最大 2 つの値を潰す」操作を繰り返し適用した後に最後に残った重みを表す単一の整数です。 

問題の構造から、主な困難は算術ではなく、2 つの最大要素を繰り返し選択することであることがすぐにわかります。 最大 n 個の石がある場合、毎回リスト全体をスキャンして最大の 2 つの要素を見つける単純なシミュレーションでは、操作ごとに O(n) のコストがかかります。 各操作で石の数が 1 つずつ減るため、合計操作数は O(n) となり、最悪の場合は O(n²) 時間がかかります。 n が大きい場合 (10⁵ など)、これは遅すぎます。この場合、二次関数の動作は実現可能な限界をはるかに超えます。 

すべての石が互いに打ち消し合うため、最終結果がゼロになる場合、微妙なエッジケースが発生します。 たとえば、入力が [2, 7, 4, 1, 8, 1] の場合、プロセスは重み 1 の 1 つの石で終了します。しかし、入力が [1, 1] の場合、両方の石が破壊されて何も残らないため、正解は 0 になります。空であることをチェックせずに最後に計算された差分を返す不注意な実装では、この場合、初期化されていない値または古い値が誤って出力される可能性があります。 

## アプローチ

 ブルート フォース シミュレーションでは石のリストが維持され、それを繰り返しスキャンして 2 つの最大の要素を見つけます。 それらを削除した後、それらの差分を挿入するか、何も挿入しません。 このアプローチは、説明されているプロセスを正確に反映しているため、正しいです。 失敗のポイントはパフォーマンスです。上位 2 つの要素の各抽出には O(n) のコストがかかり、これが O(n) 回発生するため、合計作業量は O(n²) になります。 入力が大きい場合、これは不可能になります。 

重要な観察は、プロセスが現在の最大要素への高速アクセスのみを必要とするということです。 最大値を繰り返し抽出する以上に順序を維持する必要はありません。 これはまさに max-heap (優先キュー) の使用例です。 すべての石をヒープに格納することにより、最大の 2 つの要素をそれぞれ O(log n) 時間で抽出し、新しい値を O(log n) に挿入し直すことができます。 これにより、全体の複雑さが O(n log n) に軽減され、一般的な制約には十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース スキャン | O(n²) | O(1)-O(n) | 遅すぎる |
 | 最大ヒープのシミュレーション | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 最大ヒープを使用してシステムをモデル化します。これにより、現在の 2 つの最大のストーンを常に効率的に取得できます。 

1. すべての石の重りを最大ヒープに挿入します。 ほとんどの標準ライブラリは最小ヒープのみを提供するため、最小ヒープ実装を使用する場合は値を反転します。 
2. ヒープ内に複数の石がある場合、最大の石 x を削除します。 これは、その時点で入手可能な石の中で最も重いものを表します。 
3. 2 番目に大きい石 y を削除します。 この時点で、2 つの最も強い候補に対して必要なペアワイズ操作をシミュレートしています。 
4. x と y が等しくない場合は、その差 x − y を計算し、それをヒープに戻します。 それらが等しい場合、両方の石は破壊され、何も再挿入されません。 
5. ヒープのサイズが 0 または 1 になるまで続行します。1 つの要素が残っている場合、その値が答えになります。 空の場合、答えは 0 です。

この貪欲な抽出が有効である理由は、問題が非最大要素の相対順序に依存しないためです。 各ステップの結果に影響を与えるのは最大 2 つの値のみであり、それらを削除しても以前の決定を再検討する必要はありません。 ヒープにより、すべてのステップで、現在のグローバル最大値に定義されているとおりに操作が正確に適用されることが保証されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n_and_rest = sys.stdin.read().strip().split()
    if not n_and_rest:
        return
    n = int(n_and_rest[0])
    arr = list(map(int, n_and_rest[1:]))

    # use max heap via negatives
    heap = [-x for x in arr]
    heapq.heapify(heap)

    while len(heap) > 1:
        x = -heapq.heappop(heap)
        y = -heapq.heappop(heap)

        if x != y:
            heapq.heappush(heap, -(x - y))

    if heap:
        print(-heap[0])
    else:
        print(0)

if __name__ == "__main__":
    solve()
```実装は Python に依存します`heapq`これは最小ヒープであるため、最大ヒープをシミュレートするためにすべての値が負の値として格納されます。 ループ条件`len(heap) > 1`ペアが存在する場合にのみ抽出を試行するようにします。 最後のチェックでは、空のヒープの場合を明示的に処理します。これは、すべてのストーンが相殺される入力に必要です。

 ## 特殊なケース

 重要なエッジケースは、すべての石が完全に相殺される場合です。 入力用`[1, 1]`の場合、アルゴリズムは両方の値をヒープにプッシュし、ポップし、それらが等しいことを確認し、何もプッシュしません。 ヒープは空になり、最終出力は正しくゼロになります。 

もう 1 つの微妙なケースは、中間の還元によって繰り返し小さな石が生成され、後で再び相互作用する場合です。 例えば`[5, 4, 3]`最初に生成する`5-4=1`、 それから`[3, 1]`生成する`2`、そして最終的に答えは`2`。 ヒープにより、これらの新しく作成された価値が常に適切なタイミングで再検討されるようになります。なぜなら、これらの価値は同じグローバル構造に再び入り、既存の石と同等に競合するからです。
