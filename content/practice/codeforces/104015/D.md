 ## 解決策
 ## 問題の理解

 辺の長さが不明な長方形を扱っているとします。$a$そして$b$、どちらも厳密に正の実数です。 長方形が直接与えられるわけではありません。 代わりに、その側面に関する 2 つの集約された情報が伝えられます。 

ある記事によると、長方形の異なる 2 つの辺を正確に選択すると、その合計の長さは次のようになります。$x$。 長方形には2辺の長さがあるので、$a$そして長さの2辺$b$、この条件はどちらかを選択することを意味します$a+a$、 または$b+b$、 または$a+b$、どちらの側が選択されたかに応じて。 

2 番目の部分では、異なる 3 つの辺を正確に選択すると、その合計の長さは次のようになります。$y$。 これは、次のいずれかを合計することを意味します$2a+b$または$a+2b$、これもどちらの側が除外されるかに応じて異なります。 

したがって、構造は次のようになります: 値を割り当てる必要があります$a, b > 0$2 つの辺を合計すると、一貫した選択が存在するようになります。$x$、および 3 つの辺の合計を一貫して選択すると、$y$。 このようなすべての有効な長方形の中で、可能な限り最小の周囲長が必要です$P = 2(a+b)$。 前向きな解決策が存在しない場合は、失敗を報告する必要があります。 

制約により許可されるのは、$x, y \le 10^9$したがって、どのような解決策でも問題を定数時間代数の場合に還元する必要があります。 可能性のあるサイド割り当てに対するブルートフォースまたは継続的な検索$a, b$不可能です。 

主な微妙な点は、「2 面」と「3 面」の制約が固定的な表現ではないことです。 どちらの側が選択されるかによって異なるため、複数の構造的なケースが存在し、それらの一部は非自明な形で重複します。 

素朴な間違いは、こう仮定することです$x = a+b$そして$y = 2a+b$、これにより単一の線形システムが得られます。 それは次のようなケースを見逃します$x = 2a$または$x = 2b$、どちらも同様に有効な解釈です。 もう 1 つの失敗モードは、両方の制約が同じ割り当てで満たされる必要があることを無視することです。$a, b$、独立してではありません。 

## アプローチ

 主な問題点は、「2 つの辺の合計」と「3 つの辺の合計」という記述では、どの辺が含まれるかを一意に識別できないことです。 長方形には異なる辺の長さが 2 つしかないため、制約を有効に解釈するには、回数を選択する必要があります。$a$そして$b$それぞれの合計に表示されます。 

両側の和については$x$、可能性は限られています。 長さの両側を選択します$a$、与える$2a = x$、または長さの両側$b$、与える$2b = x$、またはそれぞれの片側を与える$a+b = x$。 

三辺の和については$y$、片側を除外します。 を除く$a$与える$a + 2b = y$。 を除く$b$与える$2a + b = y$。 

したがって、問題全体は、次の 3 つのケースの 1 つを組み合わせて形成された一定サイズの線形システムの小さなセットをチェックすることに帰着します。$x$2つのケースのうちの1つで$y$。 それぞれの組み合わせにより、最大で 2 つの線形方程式が得られます。$a, b$。 それらを解決し、陽性性を確認し、周囲を計算します。 

強引な解釈は継続的に変化させようとするでしょう$a, b$または、割り当てを推測しますが、これは不要です。 構造は個別です。有効な形式は 5 つだけ存在します。 

最適化は、対称性によって探索空間が一定の可能性まで縮小されることを認識することから生まれます。

 ## アルゴリズムのチュートリアル

 私たちは 2 つの方程式のすべての一貫した解釈を体系的にテストします。 

1. 両側和の有効な解釈をすべて列挙します。$x$:

 検討します$2a = x$、$2b = x$、 そして$a + b = x$。 

それぞれは、長方形の 2 つの辺を選択する異なる方法を表します。 
2. 3 辺の合計の有効な解釈をすべて列挙します。$y$:

 検討します$2a + b = y$そして$a + 2b = y$。 

これらは、どちらかのタイプの片側を除外することに相当します。 
3. 解釈のペアごとに、次の線形システムを形成します。$a$そして$b$。 

明示的に解決します。 たとえば、次の場合$2a = x$そして$2a + b = y$、 それから$a = x/2$そして$b = y - x$。 

この構造により、各システムが直接代替ソリューションを持つことが保証されます。 
4. 有効条件を確認します。 

両方$a > 0$そして$b > 0$保持しなければなりません。 いずれかが陽性でない場合は、溶液を廃棄します。 これは、長方形の辺が縮退できないという幾何学的要件を反映しています。 
5.周囲を計算する$P = 2(a + b)$。 

Track the minimum over all valid solutions.
 6. If no valid configuration exists, output$-1$。 

### なぜ効果があるのか

 すべての有効な長方形は、辺が 2 つの合計にどのように寄与するかについての有限の組み合わせ割り当ての 1 つに正確に対応します。 それぞれの合計は数にのみ依存するため、$a$そして$b$条件が含まれている場合、これらの場合を超える隠れた自由度はありません。 すべての可能性を網羅することで完全性が保証され、各候補はその定義上の制約に従って正確にチェックされ、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())
    INF = float('inf')
    ans = INF

    def upd(a, b):
        nonlocal ans
        if a > 0 and b > 0:
            ans = min(ans, 2 * (a + b))

    # Case 1: x = 2a
    a = x / 2
    # y = 2a + b
    b = y - 2 * a
    upd(a, b)

    # Case 2: x = 2b
    b = x / 2
    a = y - 2 * b
    upd(a, b)

    # Case 3: x = a + b
    # y = 2a + b => b = y - 2a => a + (y - 2a) = x => y - a = x => a = y - x
    a = y - x
    b = x - a
    upd(a, b)

    print(-1 if ans == INF else f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```この実装は、2 辺の合計の 3 つの構造的解釈を直接反映し、互換性のある 3 辺の制約に対してそれぞれを解決します。 ヘルパー関数`upd`辺の長さが正でなくなる無効な幾何学的ソリューションをフィルタリングします。 数式には加算、減算、2 による除算のみが含まれ、必要な精度は次のとおりであるため、浮動小数点演算で十分です。$10^{-4}$。 

微妙な点は、それぞれのケースで、どちらの側が使用されるかという一貫した組み合わせが暗黙的に想定されていることです。$x$そしてどの側が除外されるのか$y$。 それぞれのケースがすでに完全な構造構成をエンコードしているため、互換性のない解釈を混合することは不可能です。

 ## 特殊なケース

 単純なソルバーが次のことを仮定した場合、エッジ ケースの 1 つが発生します。$x = a + b$唯一の可能性として。 入力用$x = 6, y = 4$、これは次のことにつながります$a = y - x = -2$、すぐにポジティブに違反します。 アルゴリズムは、次の処理中にそれを正しく拒否します。`upd`チェック。 

もう 1 つのエッジ ケースは、複数の構成によって同一の長方形が生成される場合です。 のために$x = 10, y = 15$、すべてのケースが次のように折りたたまれます$a = b = 5$。 アルゴリズムは最小周囲長のみを追跡するため、これらのケースの重複を排除しようとしません。そのため、候補が繰り返されても正確さに影響しません。 

3 番目のケースは、浮動小数点除算が現れる場合です。$a = x/2$。 すべての計算は線形であり、2 による除算のみを必要とするため、必要な条件下では精度の損失は無視できます。$10^{-4}$許容差があり、特別な合理的な処理は必要ありません。
