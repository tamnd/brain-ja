 ## 解決策
 ## 問題の理解

 英小文字の文字列が与えられます。 目標は、左から右に読んでも文字が減らない文字列、つまり各文字がアルファベット順で前の文字と少なくとも同じ大きさになる文字列に変換することです。 

キャラクターを任意に変更することができます。 それぞれの変更は 1 回の操作としてカウントされ、最終的には減少しない文字列になる一方で、変更する文字数を最小限に抑えたいと考えています。 

出力は 2 つあります。 まず、変更する必要がある位置の最小数を報告します。 次に、この最小値を達成する有効な非減少文字列を構築します。 

n が 200,000 までという制約により、二次戦略から遠ざけられます。 考えられるターゲット文字列をすべて考慮したり、違反を個別に修正する考えられるすべての方法を検討したりするソリューションでは、時間がかかりすぎます。 本質的に線形または線形対数であるものが必要です。 

重要な微妙な点は、ローカルで可能な限り文字を保存するように求められていないことです。 「表示されたとおりにすべての反転を修正する」などの貪欲なローカル修正は、1 つの位置を修正すると後で追加の変更が強制される可能性があるため、グローバルに失敗する可能性があります。 

単純な失敗例は、「cba」のような文字列です。 ローカル修正により、「cb」が「cc」、そして「cca」に変わる可能性がありますが、これは最小限ではありません。 最良の解決策は「bbb」または「ccc」で、どちらも 2 つの変更のみが必要ですが、単純に貪欲な修復を行うと必要以上に修正される可能性があります。 

もう 1 つの微妙なケースは、大きなブロックがすでに順序付けされているものの、いくつかの文字によってわずかに中断されている場合です。 たとえば「アブザブ」。 最適な解決策には、局所的な反転を修正するのではなく、文字列全体を慎重に選択された最終構造に合わせることが含まれる場合があります。 

## アプローチ

 強引な考え方は、最終文字列をアルファベット上の非減少シーケンスと考えることです。 文字は 26 個しかないため、最終的な文字列がソートされるという制約の下で、文字を位置に割り当てられるすべての文字を試してみることができます。 

直接的なブルートフォース解釈は次のようになります。長さ n の減少しない文字列を選択し、元の文字列と異なる位置の数を計算します。 各位置は同じままか増加する可能性があるため、減少しない文字列の数は n で指数関数的になるため、これは完全に実行不可能です。 26 文字を超える長さ n の弱く増加する文字列の数は、組み合わせ的に依然として膨大であるため、選択をアルファベットに制限しても役に立ちません。 

別の視点が必要です。 最終的な文字列を直接構築する代わりに、視点を反転します。アルファベットの各文字について、その時点までの文字に割り当てられる位置の数を決定します。 同様に、文字列を 26 個の連続したブロックに分割することを考えます。各ブロックは固定文字に対応し、ブロックはアルファベットの昇順に表示されます。 

これがキーの構造です。小文字の上にある非減少文字列は 26 個のセグメントのシーケンスとして見なされ、セグメント i は文字 'a' + i で埋められます。 一部のセグメントは空である場合があります。 したがって、タスクは、これらのセグメントの境界がどこにあるのかを選択し、それぞれの選択肢について、割り当てられた文字と一致する元の文字の数を計算することになります。 

各プレフィックスまたは範囲に各文字が何回出現するかを事前に計算できるため、固定パーティションの場合に保持する文字の数をすぐに評価できます。 最適な答えは、保持される文字を最大化するパーティションであり、答えは n からその値を引いたものになります。 

これにより、問題は 26 の州にわたる動的計画法に変わります。 文字を順番に繰り返し、各文字のセグメントがどこまで続くかを決定します。 文字が 26 文字しかないため、寄与を事前計算し、遷移を効率的に評価できます。 この構造は十分に小さいため、プレフィックス カウントを含むアルファベット状態の DP で十分です。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての文字列に対するブルート フォース | 指数 | O(n) | 遅すぎる |
 | アルファベットセグメント上の DP | O(26² + n・26) | O(n・26) または O(n) 最適化 | 承認済み |

 ## アルゴリズムのチュートリアル

 最終的な文字列を 26 個の順序付けられたフェーズによって形成されるものとして再解釈します。 フェーズ k では、文字「a」 + k にいくつかの位置が割り当てられ、後のフェーズに移行すると、より小さな文字に戻ることはありません。 

これを正確にするために、プレフィックス数を計算して、選択した文字に一致するセグメント内の文字の数をすぐに知ることができます。 

次に、各文字に順番に文字列の何文字を割り当てるかを決定する動的プログラミング状態を構築します。 

ステップ 1: プレフィックス頻度テーブルを事前計算します。 各位置 i と各文字 c について、c が s[0..i-1] に出現する回数を保存します。 これにより、任意の間隔でカウントに対する O(1) クエリが可能になります。 

ステップ 2: dp[k][i] を、文字列の長さ i のプレフィックスをカバーするために最初の k 文字 (「a」から「a」+k-1) を使用して正確に一致を維持できる最大文字数として定義します。 これは、最初の i 文字を k 個の非減少文字ブロックに割り当てていることを意味します。 

ステップ 3: k 番目の文字ブロックがどこで終了するかを決定して遷移します。 k 番目の文字が位置 [j, i) に割り当てられている場合、これらの位置はすべて文字 (k 番目の文字) になり、寄与される一致の数は、その間隔内のその文字の出現数になります。 

考えられるすべての j < i を試し、最適な遷移を採用します。 ここで、プレフィックス合計を使用すると評価が高速になります。 

ステップ 4: 答えは dp[25][n] で、文字列全体で 26 文字すべてを使用してできる最善の結果を表します。 最小置換は n からこの値を引いたものです。 

ステップ 5: 結果の文字列を再構築するために、どの分割が最適な値を与えたかを示す親ポインターを保存します。 次に、セグメントごとに文字を割り当てます。 

機能する理由: 有効な減少しない文字列は、文字列を最大 26 個の連続セグメントに分割したものに一意に対応し、各セグメントには一定の文字とセグメント インデックスによって増加する文字が含まれます。 DP はそのようなパーティションをすべて調査し、保持された一致を最大化するパーティションを選択します。 すべての有効なターゲット文字列はこの形式で表現可能であり、すべての遷移は単調性を維持するため、最適なソリューションを見逃すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    # prefix counts: pref[i][c]
    pref = [[0] * 26 for _ in range(n + 1)]
    for i in range(n):
        for c in range(26):
            pref[i + 1][c] = pref[i][c]
        pref[i + 1][ord(s[i]) - 97] += 1

    # dp[k][i] = best matches using first k letters on prefix i
    dp = [[-10**9] * (n + 1) for _ in range(26)]
    parent = [[-1] * (n + 1) for _ in range(26)]

    # base: using 'a' only
    c0 = 0
    for i in range(n + 1):
        dp[0][i] = pref[i][0]

    for k in range(1, 26):
        for i in range(n + 1):
            best = -1
            best_j = -1
            for j in range(i + 1):
                # assign s[j:i] to letter k
                cnt = pref[i][k] - pref[j][k]
                val = dp[k - 1][j] + cnt
                if val > best:
                    best = val
                    best_j = j
            dp[k][i] = best
            parent[k][i] = best_j

    # reconstruct
    res = list(s)
    k = 25
    i = n

    while k >= 0:
        j = parent[k][i] if k > 0 else 0
        if k == 0:
            j = 0
        for x in range(j, i):
            res[x] = chr(97 + k)
        i = j
        k -= 1

    kept = dp[25][n]
    print(n - kept)
    print("".join(res))

if __name__ == "__main__":
    solve()
```このソリューションは、任意のセグメント内の特定の文字に一致する文字の数をカウントすることが定数になるように、プレフィックス頻度テーブルを構築します。 次に、動的プログラミングによって、セグメントが昇順で文字に徐々に割り当てられます。 

実装の微妙な詳細は、dp 状態の初期化です。 大きな負の値を使用すると、初期化されていない遷移を誤って選択することを回避できます。 もう 1 つの詳細は再構成です。文字「z」から「a」まで逆方向に歩き、セグメントを逆の順序で埋めていくことで、DP 決定との一貫性が保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(26² · n) | DP は、各文字と接頭辞のすべての分割ポイントを試行します。 
| スペース | O(26・n) | プレフィックス合計と DP テーブル |

 26 が定数であり、支配的な因子が DP 遷移からの管理可能な定数因子を使用して n 内で線形であるため、制約によりこれが可能になります。

 ## 特殊なケース

 「edcba」のような完全に減少する文字列は、文字列全体をカバーする「a」の単一文字セグメントを選択する DP によって処理されます。 再構築によりすべての位置が「a」に割り当てられ、プレフィックス カウントにより、他のすべての文字に対して最大一致がゼロとして正しく計算されることが保証されます。 

「aaaaa」のような完全に均一な文字列は、有益な分割を引き起こすことはありません。 DP 用語では、上位の文字を導入するすべての遷移により一致が減少するため、アルゴリズムはすべての文字を「a」セグメントに保持し、置換はゼロになります。 

「ababab」のような高度に交互に配置される文字列では、DP は複数のセグメントに分割するか、より少ない文字に折りたたむかを決定する必要があります。 最適なソリューションは少数のセグメントに分割されることが多く、プレフィックスベースの評価により、アルゴリズムはローカル一致を過剰にカウントすることなく、各セグメンテーションの利点を正確にカウントします。
