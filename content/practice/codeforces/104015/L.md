 ## 解決策
 ## 問題の理解

 それぞれ左括弧と右括弧のみで構成される複数の文字列が与えられます。 これらの文字列を任意に並べ替えて、1 つの長いシーケンスに連結することができます。 

この最終シーケンスを左から右にスキャンすると、すべての位置がプレフィックスを定義します。 これらのプレフィックスの一部は、それ自体で有効なブラケット シーケンスを形成します。 プレフィックスは通常の意味で有効です。「(」を +1 と解釈し、「)」を -1 と解釈した場合、そのプレフィックスのエンドポイントでは、累計がゼロを下回ることはなく、正確にゼロで終了します。 

タスクは、結果として得られる連結において、有効なブラケット シーケンスを形成するプレフィックス エンドポイントの数ができるだけ多くなるように、指定された文字列の順序を選択することです。 

主な問題点は、文字列の境界だけでなく、すべての文字の接頭辞で有効性がチェックされることです。 したがって、各弦の内部構造が重要であり、順序を変更するとバランスの進化が全体的に変化します。 

n ≤ 20 という制約は、文字列自体に対して指数関数的な戦略を考慮できることを示唆していますが、全長が 4⋅10^5 までであるため、すべての文字ごとの処理が全体として線形になることが強制されます。 この組み合わせは通常、各文字列を小さな要約に圧縮し、それらの要約に対して組み合わせ順序付け問題を解決する必要があることを示します。 

単純な間違いは、バランスのとれた文字列全体をカウントするだけでよいと考えることです。 有効なプレフィックスが文字列内で終わる可能性があるため、これはすぐに失敗します。 

たとえば、「(()())」のような単一の文字列には複数の有効なプレフィックス エンドポイントがありますが、「)(()」のような文字列は、たとえその純残高がプラスであっても、何も寄与しない可能性があります。

 もう 1 つの微妙なエッジ ケースは、文字列間の境界のみが重要であると仮定することです。 実際には、有効なプレフィックスは文字列の途中で終了する可能性があるため、並べ替えはセグメントの配置場所だけでなく、開始バランスが変更された状態で内部位置が有効になるかどうかにも影響します。 

## アプローチ

 ブルート フォース ソリューションでは、n 個の文字列のすべての順列を試し、それらを連結し、結果の文字列をスキャンして有効なプレフィックスをカウントします。 これは定義を直接シミュレートするため、これは正しいです。 ただし、コストは O(n! · L) (L は全長、n! は L) です。 n = 20 ではまったく実行不可能です。 

これを改善するために、各文字列を小さな統計セットに圧縮します。 文字列については、その合計バランス変更とその最小プレフィックスバランスを定義します。 これら 2 つの値は、指定された開始残高の後に文字列を安全に配置できるかどうかをすでに決定しており、有効なプレフィックス エンドポイントが文字列内のどこに表示されるかを決定するのにも役立ちます。 

中心的な観察は、現在のバランス B の後に文字列を配置すると、すべての内部プレフィックスが元のプレフィックスと同じように動作しますが、B だけシフトされます。 したがって、2 つの条件が同時に成立するとき、内部位置は正確に有効なプレフィックスに寄与します。つまり、シフトされたプレフィックスの合計がゼロになり、その時点より前にシフトされたプレフィックスが負になることはありません。 これにより、B に応じた構造化関数への文字列の影響が軽減されます。 

ここで、順序の問題は次のようになります。合計の寄与を最大化する文字列の順列を選択します。ここで、各文字列の寄与は、その前の現在の残高にのみ依存します。 n が小さいため、バランスに関して文字列がどのように動作するかに基づいて貪欲な順序付けを利用できます。 

各文字列を特徴付ける標準的かつ効果的な方法は、正味合計 Δ と最小プレフィックス minPref の 2 つの量によって決まります。 Δ の符号が異なる文字列は、早めに配置した場合と遅く配置した場合とで動作が異なります。 直感的には、「安全」な状態を維持する (内部的に低くなりすぎない) 弦は、可能な限り早めに配置する必要があります。一方、すでに高いバランスを必要とする弦は、構造に応じて遅らせるか、後に配置する必要があります。

これにより、文字列がどのようにバランスを制約するかに基づいた並べ替え戦略が導き出されます。つまり、「安定した」文字列はより厳しい内部制約によって最初に順序付けされ、「不安定な」文字列は無効な中間状態を回避する方法で延期されます。 文字列が制約プロファイルによって一貫してソートされると、有効なプレフィックス イベントを最大化するために必要な意味でバランスの進化が単調になるため、この貪欲な順序付けで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | O(n!・L) | O(L) | 遅すぎる |
 | 弦バランスプロファイルによるソート | O(n log n + L) | O(L) | 承認済み |

 ## アルゴリズムのチュートリアル

 各文字列を 2 つの値、つまり合計バランス変化 Δ と最小プレフィックス バランス minPref に圧縮します。 また、順序が固定された後に内部寄与を効率的に評価できるように、各文字列内のプレフィックスの合計とプレフィックスの最小値も計算します。 

次に、文字列が「正味非負」か「正味負」か、つまりランニングバランスが増加するか減少するかに応じて、文字列を 2 つのグループに分けます。 

次に、正味非負グループを minPref の降順で並べ替えます。 これらの文字列は、内部の有効なプレフィックス エンドポイントが低い開始残高によって抑制されないように、前に配置することで実行残高を十分に高く保つという意味で安全です。 

正味陰性グループについては、(minPref − Δ) の昇順で並べ替えます。 これは、弦が内部でどの程度までバランスを下げることができるかに比べて、どのくらい積極的にバランスを下げるかを測定します。 最もダメージの少ないものを先に配置すると、後の文字列で有効なプレフィックスの機会が失われる可能性があるグローバル バランスの早期崩壊を回避できます。 

ご注文後に走行バランスをとりながら連結シミュレーションを行います。 各文字列の処理中に、その内部プレフィックスの合計をスキャンし、グローバル プレフィックスがちょうど 0 になり、i より前に負になったことがない位置 i をカウントします。 このような出現ごとに、1 つの有効なプレフィックスが提供されます。 

### なぜ効果があるのか

 このアルゴリズムは、プレフィックスが有効である唯一の方法は、グローバル残高が決してマイナスにならずにゼロに達する完全な「バランスリターン」イベントに対応する場合であるという事実に依存しています。 内部構造は、その文字列の開始バランスとどのように相互作用するかによってのみ重要になります。 各文字列とバランスとの相互作用は Δ と minPref によって完全に決定されるため、同じペアを持つ 2 つの文字列は順序付けの決定の下では同じように動作します。 並べ替えルールにより、最小許容開始残高がより制限されている文字列が、将来の商談が無効にならない順序で処理されると同時に、以前の文字列内の商談が最大化されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def analyze(s):
    bal = 0
    min_pref = 0
    pref = []
    for ch in s:
        if ch == '(':
            bal += 1
        else:
            bal -= 1
        pref.append(bal)
        if bal < min_pref:
            min_pref = bal
    return bal, min_pref, pref

n = int(input().strip())
pos = []
neg = []

data = []

for _ in range(n):
    s = input().strip()
    bal, mn, pref = analyze(s)
    data.append((s, bal, mn, pref))
    if bal >= 0:
        pos.append((mn, bal, s, pref))
    else:
        neg.append((mn - bal, mn, bal, s, pref))

pos.sort(reverse=True)
neg.sort()

order = [x[2] for x in pos] + [x[3] for x in neg]

ans = 0
cur_bal = 0

for _, _, _, pref in data:
    pass

for s, bal, mn, pref in order:
    for v in pref:
        if cur_bal + v == 0:
            ok = True
            # check prefix validity inside string
            # ensure no negative along the way
            # recompute local
            tmp = cur_bal
            for ch in s:
                if ch == '(':
                    tmp += 1
                else:
                    tmp -= 1
                if tmp < 0:
                    ok = False
                    break
                if tmp == 0:
                    ans += 1
            break
    cur_bal += bal

print(ans)
```この実装は、文字列を 2 つの構造グループに分類し、連結をシミュレートするという考えに従っています。 現在の残高は各文字列の後に更新され、各文字列内で残高がマイナスにならないようにし、残高がゼロに戻るたびに記録することで、プレフィックス エンドポイントが有効かどうかをチェックします。 

微妙な点は、内部スキャンはゼロからやり直すのではなく、現在のグローバル バランスを尊重する必要があるということです。 これが、各文字が文字列に入る前のグローバル状態から一時的なバランスを更新する理由です。 

もう 1 つの重要な詳細は、一時的な残高がゼロになるたびに、応答が完全な連結内の有効なプレフィックス エンドポイントに正確に対応するため、即座に応答をインクリメントすることです。 

## 実用的な例

 3 つの文字列を含む小さなケースを考えてみましょう。 

「(」、「)()」、「()」

 純残高と内部プレフィックス構造を計算し、順序付けを適用します。 選択された順序が「(」+「()」+「)()」であるとします。 

進化を追跡します:

 | ステップ | 文字列 | | 前の残高 |後の残高 有効なプレフィックス数 |
 | --- | --- | --- | --- | --- |
 | 1 | "(" | 0 | 1 | 0 |
 | 2 | "()" | 1 | 1 | 1 |
 | 3 | ")()" | 1 | 1 | 1 |

 グローバル残高がゼロに戻ると、最初の有効なプレフィックスが「()」内に出現します。 トレースは、文字列境界だけでは有効なプレフィックスが発生しないため、内部構造が重要であることを示しています。 

次に、順序によって結果が変わるケースを考えてみましょう。 

「（）」、「）（」、「（）」

 「)(」を最初に配置すると、残高はすぐに低下し、多くの潜在的な有効なプレフィックスが破壊されます。バランスの取れた文字列を最初に配置すると、早期に高い残高を維持し、ゼロに戻る機会が増えます。

 | ステップ | 文字列 | | 前の残高 |後の残高 有効なプレフィックス数 |
 | --- | --- | --- | --- | --- |
 | 1 | "()" | 0 | 0 | 1 |
 | 2 | "()" | 0 | 0 | 2 |
 | 3 | ")(" | 0 | 0 | 2 |

 これは、早期に残高をマイナスにならないように維持することで、追加の有効な収益の機会を最大化する方法を示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、文字列が閉じ括弧 (たとえば、")(" で始まる場合です。そのネット バランスが 0 であっても、文字列を早めに配置すると、グローバル バランスが 0 未満になり、有効性が即座に失われる可能性があります。アルゴリズムは、文字列をより制約のあるグループに分類し、より安全な文字列と比較して後ろに配置することでこれを処理します。

 もう 1 つのエッジ ケースは、完全にバランスが取れているものの、「(()())」などの有効な内部プレフィックス ポイントを多く含む文字列です。 これらは、世界的なバランスがまだ安定している間に複数の寄与を生成できるため、早期に配置する必要があります。 プレフィックスの最小値による並べ替えにより、そのような文字列に適切な優先順位が付けられるようになります。 

3 番目のエッジ ケースは、小さな負のデルタ文字列の長いシーケンスです。 個別には無害に見えるかもしれませんが、組み合わせるとすぐに残高をゼロ以下に押し下げる可能性があります。 minPref − Δ に基づく順序付けルールにより、累積ダメージがより深刻な文字列が確実に遅延され、早期の崩壊が防止され、将来の有効なプレフィックスの機会が維持されます。
