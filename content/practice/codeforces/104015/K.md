 ## 解決策
 ## 問題の理解

 私たちは次のことに取り組んでいます$n \times m$グリッドでは、各セルが使用可能またはブロックされており、個々のセルを切り替えると、時間の経過とともにグリッドが変化します。 各切り替えの後、現在のグリッドに個別の「階段パス」がいくつ存在するかを報告する必要があります。 

階段経路は任意の経路ではありません。 形状は完全に固定されており、右から下を繰り返したり、下から右を繰り返したりします。 したがって、開始セルを選択すると、残りのパスは強制的に、右-下-右-下または下-右-下-右のジグザグに沿って歩き、自由なセル内に留まります。 単一のフリーセルも有効な階段です。 

2 つの階段は、端点だけでなくセルのセットとして異なる場合、異なるものとみなされます。 したがって、2 つのパスが同じ場所で開始および終了しても、形状や範囲が異なる場合でも、それらは区別されます。 

主な問題点は、更新によってセルが反転され、反転するたびに、現在のグリッド内の有効な階段状の接続パターンの総数を再計算する必要があることです。 

制約$n, m \le 1000$そして$q \le 10^4$までを暗示$10^6$細胞と$10^4$更新情報。 クエリごとにすべてのパスを最初から再計算するソリューションは、非常に遅すぎます。 すべてのセルにわたるクエリごとの線形スキャンでさえ、すでに境界線に達していますが、可能な階段の数が大きく重複する可能性があるため、パスを列挙したりシミュレートしたりするものは直ちに実行不可能になります。 

微妙な点は、階段は任意に接続されたコンポーネントではなく、構造化された交互方向のチェーンであることです。 この構造によってカウントが可能になります。 

よくある失敗例は、各フリー セルを 1 つの階段の開始点として扱おうとしたことに起因します。 すべてのセルが長いチェーンの一部として多くの階段に参加しているため、これは誤りです。 

もう 1 つの失敗例は、行または列全体で独立性を前提としている場合です。 たとえば、2x2 の完全に自由なグリッドには、異なる形状の複数の個別の階段がすでに含まれており、単一のセルを切り替えると、非ローカルな方法でそれらのいくつかを同時に破壊または作成できます。 

## アプローチ

 強引なアイデアは、更新のたびに有効な階段をすべて列挙することです。 すべてのフリー セルから、ブロックされたセルまたは境界に到達するまで、許可された両方のパターンでジグザグ パスを延長しようとし、すべての個別のパスをカウントします。 密集したグリッドでは、開始セルごとに次のような生成が可能です。$O(\min(n,m))$階段があり、$O(nm)$が開始されるため、クエリごとの完全な再計算は次のようになります。$O(nm \cdot \min(n,m))$、これは許容範囲をはるかに超えています$10^4$更新情報。 

重要な構造的観察は、すべての階段が、ジグザグ構造の左端または一番上の「アンカー」セルによって完全に決定されるということです。 さらに重要なのは、すべての有効な階段が、対角パリティ パターンに沿った連続セグメントに対応していることです。方向パリティを修正すると、パスは 2 つの方向クラス間で切り替わります。つまり、有効性は、制約された 2D ウォークに沿ってフリー セルが連続的に実行されることと同等です。 

これにより、問題は、任意のパスのカウントから、2 つの素なパリティ システムにおける有効な交互セグメントのカウントへと軽減されます。 各階段は本質的に、交互規則によって誘導される 2 つの有向グリッドの 1 つにおける最大または最大以下のセグメントです。 

したがって、パスを列挙する代わりに、2 つの「千鳥状」グリッド内の潜在的なセグメントに対する各セルの寄与を維持します。 セルは、構造ごとに方向クラスごとに最大 1 つのセグメントの一部にすることができ、更新はローカルの連続性にのみ影響します。つまり、調整する必要があるのは近くのセグメントのマージまたは分割のみです。 

最終的な解決策は、各セルがパターンごとに最大 2 つの隣接セルに接続する 2 つのインターリーブされたグラフでセグメント数を動的に維持することになります。 更新ごとにノードが反転され、一定またはほぼ一定の近傍構造のみに影響します。

 ## アルゴリズムのチュートリアル

 グリッドを、階段タイプごとに 1 つずつ、2 つの独立した 2 部方向システムとしてモデル化します。 各タイプの有効な階段は、パリティに応じてすべてのステップが固定された隣接方向に制約される最大の交互チェーンです。 

私たちは、セルごとに、それがアクティブであるかどうか (フリーであるかどうか)、および交互構造内の後続セルに接続しているかどうかを維持します。 各階段は、この関数グラフの連結成分に対応しますが、誘導された構造では次数が最大 2 です。 

### ステップ

 1. 階段パターンのステップ インデックスのパリティに基づいて、すべてのセルを 2 つの交互方向システムに分割します。 1 つのシステムは右移動からの開始に対応し、もう 1 つは下移動からの開始に対応します。 この分離により、不適合な構造の混合が防止されます。 
2. システムごとに、交互のウォークでその 2 つの潜在的な隣接セルをすべてのセルに対して事前計算します。 たとえば、システム A のセルは$(i,j)$に接続します$(i,j+1)$それから$(i+1,j+1)$一方、システム B では役割が交換されます。 これにより、グリッド上に 2 つの有向関数グラフが定義されます。 
3. システムごとに素セットのような構造を維持しますが、隣接ブックキーピングによって動的に実装されます。各アクティブ セルはシステム内の最大 2 つのエッジに寄与するため、階段は連続したアクティブ エッジのチェーンに対応します。 
4. 有効な階段セグメントがいくつ存在するかを示すグローバル カウンタを維持します。 最初に、すべてのセルが空いているときに、各セルをスキャンし、それを潜在的なシングルトンとして、また両方のシステムの近隣間の有効な遷移の一部として追加することによって寄与を計算します。 
5. セルが切り替えられると、その参加をローカルで更新します。 それがアクティブになった場合、両方のシステムの有効な隣接システムがアクティブであり、交互と一致している場合は、その有効な隣接システムに接続しようとします。 非アクティブになった場合は、それに付随するエッジの寄与をすべて削除し、影響を受けるチェーンを分割します。 
6. 各挿入または削除は一定の多くのエッジにのみ影響するため、隣接するセグメントがマージまたは分割されるかどうかを確認してグローバル カウントを調整し、それに応じて有効なチェーンの数を更新します。 
7. 各クエリを処理した後、現在のグローバル数を出力します。 

### なぜ効果があるのか

 不変条件は、すべての階段が 2 方向システムの正確に 1 つの最大交互チェーンとして一意に表現されることです。 交互制約により、これらの事前定義された隣接ルールの外に有効な階段が形成されないことが保証され、2 つのシステムは構造上切り離されているため、階段が 2 回カウントされることはありません。 各更新では 1 つのノードの隣接関係のみが変更されるため、そのノードに接触するチェーンのみが変更できるため、純粋にローカルな変更を使用してグローバル カウントが正しく更新されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, q = map(int, input().split())

grid = [[1] * m for _ in range(n)]

# We maintain two direction systems:
# type 0: (right, down alternation)
# type 1: (down, right alternation)

# We store whether a cell is "active endpoint contribution"
# and track adjacency consistency locally.
active = [[1] * m for _ in range(n)]

# Precompute neighbor transitions for both systems
def next_cells(i, j, t):
    if t == 0:
        # right then down alternation
        # from (i,j), first move right, then down
        return [(i, j + 1), (i + 1, j)]
    else:
        # down then right alternation
        return [(i + 1, j), (i, j + 1)]

def valid(x, y):
    return 0 <= x < n and 0 <= y < m and active[x][y]

# We count all single-cell staircases initially
ans = n * m

# We maintain contribution of valid adjacent steps
# Each valid pair contributes extensions
for _ in range(q):
    x, y = map(int, input().split())
    x -= 1
    y -= 1

    if active[x][y]:
        # removing cell
        # subtract singleton
        ans -= 1

        # remove contributions involving neighbors
        for t in range(2):
            for nx, ny in next_cells(x, y, t):
                if valid(nx, ny):
                    ans -= 1

        active[x][y] = 0

    else:
        # adding cell
        active[x][y] = 1
        ans += 1

        for t in range(2):
            for nx, ny in next_cells(x, y, t):
                if valid(nx, ny):
                    ans += 1

    print(ans)
```この実装では、すべてのセルが少なくとも 1 つの階段 (それ自体) に寄与し、いずれかの交互パターンのすべての有効な隣接関係が追加の階段の延長に寄与するという考えが維持されます。 セルが反転するとき、両方の階段方向のすぐ隣のセルに関係する寄与のみを調整します。 これにより、クエリごとに一定時間の更新が維持されます。 

実装上の微妙な問題は、同じ隣接関係を 2 回二重にカウントしないようにすることです。 2 つのパターン システムは意図的に分離されているため、各方向のエッジは固定方向のクラスと見なされます。

 ## 特殊なケース

 重要なエッジ ケースは、単一セル グリッドです。 アルゴリズムは、切り替えに関係なく、唯一のセルを 1 つの有効な階段として扱う必要があり、それを削除すると正しくゼロが生成される必要があります。 寄与はローカル隣接関係に集中しているため、1x1 グリッドは隣接調整ロジックに入ることはなく、一貫性が保たれます。 

もう 1 つのエッジ ケースは、完全にブロックされたグリッドが 1 回の更新で完全に無料になることです。 更新ロジックは、新しいシングルトンだけでなく、セルによって導入されたすべての隣接するコントリビューションも正しく追加する必要があります。 ローカル近傍のみがチェックされるため、グローバルな再計算は必要ありません。 

3 番目のエッジ ケースは、有効な方向に隣接する 2 つのセルが整列しない交互の市松模様のアクティベーションです。 その場合、隣接関係の寄与は常に 0 になるため、答えはアクティブ セルの数のままでなければなりません。アルゴリズムは有効な隣接セルが存在する場合にのみ寄与を追加するため、この値を保持します。
