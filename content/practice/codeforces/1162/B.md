 ## 解決策
 ## 問題の理解

 同じサイズの 2 つのグリッドが与えられています。 各セル位置には数値のペアが含まれており、1 つは最初の行列に、もう 1 つは 2 番目の行列に含まれます。 許可される唯一の操作は、行列間の同じ座標にある 2 つの数値を交換することです。 したがって、すべての位置について、行列 A の値がそこに留まるか行列 B に移動するか、あるいはその逆かを個別に決定できます。 

これらのローカル スワップ決定を行った後、結果として得られる両方の行列が強い順序付け条件を満たさなければなりません。 すべての行は厳密に左から右に増加する必要があり、すべての列は厳密に上から下に増加する必要があります。 

重要な制約は、スワップはポジション単位でのみ行われるということです。 位置間の移動はありません。つまり、各セルは正確に 2 つの候補値を提供し、そのうちの 1 つを最初の行列に選択し、もう 1 つは自動的に 2 番目の行列に進みます。 

この制約により、合計で最大 2500 個のセルが許可されます。 これにより、代入に対する順列ベースまたは指数関数的な検索が即座に除外されます。 ただし、各セルは二項選択に依存しないため、貪欲な構築またはローカル整合性チェックが可能です。 

素朴な直感による微妙な失敗例は、調整なしで貪欲に行を最初に修正したり、列を最初に修正したりできると仮定することです。 たとえば、各セルの行列 A に常に小さい値を代入すると、後で列の順序が崩れる可能性があります。 同様に、行ごとに個別に最適化すると、列の単調性が破壊される可能性があります。 

主要な問題は、各セルの決定が行制約と列制約の両方に同時に影響することです。 

## アプローチ

 ブルートフォースアプローチでは、各セルを二者決定として扱い、すべてを試します。$2^{nm}$課題。 割り当てごとに、両方の行列が行と列の厳密な増加条件を満たしているかどうかを確認します。 これは正しいですが、構成の数が 2500 ポジションで指数関数的に増加するため、中程度のサイズであっても完全に実行不可能です。 

重要な観察は、どの行列がどの値になるかは実際には気にしておらず、両方の行列が増加することだけが必要であるということです。 各位置には常に 2 つの値があります。 1 つは行列 A に送られ、もう 1 つは行列 B に送られます。そこで問題は、結果として得られる両方のグリッドが両方の次元でソートされるような割り当てを選択できるかということです。 

次に、固定セルを考えてみましょう。 大きい方の値を行列 A に入れると、行列 B は小さい方の値を取得します。 逆を行うと、行列 A の値が小さくなります。 したがって、各セルは、ペアが 2 つの行列にどの方向に寄与するかを選択できます。 

重要な洞察は、貪欲なスキャン順序を使用して両方の行列を同時に構築し、すでに固定された近傍との一貫性を確保できることです。 グリッドを行ごとに、左から右、上から下に処理する場合、セルを決定するときに重要な制約は、両方の行列の左と上に隣接するものだけです。 

各セルで、ペアの両方の方向を試し、すでに割り当てられている近傍に対して両方の行列が有効に保たれているかどうかを確認します。 制約はローカルで単調であるため、この貪欲なパスで十分です。

 ## アルゴリズムのチュートリアル

 同じサイズの 2 つの結果行列 A と B を定義します。 

セルは行優先の順序で処理されます。 

1. 各セルについて$(i, j)$、ペアがあります$(a_{ij}, b_{ij})$。 2 つの代入を考えます: A はどちらかを取得します。$a_{ij}$、Bは取得します$b_{ij}$、または A が取得されます$b_{ij}$、Bは取得します$a_{ij}$。 解決策が存在する場合は、これらのいずれかを選択する必要があります。 
2. 割り当てているかどうかをテストします$a_{ij}$Aと$b_{ij}$to B は、すでに満たされている左隣りに関して厳密な増加条件を保持します。$(i, j-1)$そして上の隣の人$(i-1, j)$。 今後のセルはまだ決定されていないため、チェックはローカルのみです。 
3. 最初の割り当てが制約に違反する場合、交換された割り当てが試行されます。 
4. 両方の割り当てが失敗した場合、ローカル方向性はすでに固定されたプレフィックスで単調性を維持できないため、直ちに不可能であると結論付けます。 
5. すべてのセルが割り当てられるまで続行します。 

グリッドの完成後、構築中にすべてのローカル制約が満たされた場合にのみ、両方の行列が有効になります。 

### なぜ効果があるのか

 スキャンのどの時点でも、以前に割り当てられたすべてのセルは両方の行列で有効な増加プレフィックスを形成します。 将来のセルは、上と左に隣接するセルのみを尊重する必要があります。これは、モノトーン グリッドで行と列の順序に影響を与えることができる位置はこれらの位置だけであるためです。 すべての制約は隣接するセル間にあるため、ローカルな一貫性を確保することで帰納的にグローバルな正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    A = [list(map(int, input().split())) for _ in range(n)]
    B = [list(map(int, input().split())) for _ in range(n)]

    resA = [[0] * m for _ in range(n)]
    resB = [[0] * m for _ in range(n)]

    def ok(i, j, xA, xB):
        if i > 0:
            if resA[i-1][j] >= xA:
                return False
            if resB[i-1][j] >= xB:
                return False
        if j > 0:
            if resA[i][j-1] >= xA:
                return False
            if resB[i][j-1] >= xB:
                return False
        return True

    for i in range(n):
        for j in range(m):
            # try (A[i][j] -> resA, B[i][j] -> resB)
            if ok(i, j, A[i][j], B[i][j]):
                resA[i][j] = A[i][j]
                resB[i][j] = B[i][j]
            elif ok(i, j, B[i][j], A[i][j]):
                resA[i][j] = B[i][j]
                resB[i][j] = A[i][j]
            else:
                print("Impossible")
                return

    print("Possible")

if __name__ == "__main__":
    solve()
```このソリューションでは、2 つの行列の同時充填が維持されます。 ヘルパー関数は、選択したペアの配置が、すでに固定された隣接ペアとの厳密な順序に違反するかどうかをチェックします。 左と上のセルのみを比較するため、行全体または列全体を繰り返しスキャンすることは避けられます。 

よくある実装の落とし穴は、両方の行列が独立して制約を満たさなければならないことを忘れていることです。 B が増加していない場合に A が増加しているだけでは十分ではないため、同じローカル決定で両方をチェックする必要があります。 もう 1 つの微妙な問題は、非厳密な比較を誤って使用していることです。 条件は厳密な増加を必要とするため、等価も無効として扱う必要があります。

 ## 特殊なケース

 重大なエッジ ケースは、以前に固定された隣接セルが原因でセルの両方の選択が単調性に違反する場合です。 たとえば、A の左近傍が 5 で、両方の候補値が ≤ 5 の場合、どちらの割り当ても厳密な増加を満たすことができません。 アルゴリズムはそのセルでこれを即座に検出し、「不可能」を返します。 

別のエッジケースは、隣接するものが 1 つだけ存在する最初の行または最初の列で発生します。 この実装では、存在しないインデックスのチェックが正しく回避され、定義されている制約のみが強制されます。 

最後に、平等は静かな失敗の原因です。 候補値が近傍値と等しい場合、その値は拒否されます。 このアルゴリズムは、厳密でない比較を明示的に使用します (`>=`) 両方の行列にわたってこのルールを均一に適用します。
