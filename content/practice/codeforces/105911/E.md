 ## 問題の理解

 小文字の長い文字列と固定整数が与えられます。$k$。 任意の部分文字列について、部分文字列が正確になるようにその文字を再配置できるかどうかを尋ねられます。$k$同一のブロックが連結されたもの。 言い換えれば、部分文字列内の文字を並べ替えた後、それを次のように分割できるようにしたいのです。$k$文字の等しいマルチセット。 

部分文字列は、その全長が次の値で割り切れる場合に有効です。$k$、各文字が次の倍数で出現する場合、$k$その中で何度か。 この 2 番目の条件は、複数の文字セットを次のように分割できることを保証します。$k$同一のグループ。 

各クエリでは文字列のセグメントが与えられ、そのセグメント内に完全にある部分文字列がこの条件を満たす個数をカウントする必要があります。 

制約は大きく、最大で$3 \times 10^5$文字列の長さとクエリの数。 クエリごとにすべての部分文字列を検査するソリューションは直ちに不可能です。単一のクエリでも$O(n^2)$最悪の場合、クエリ全体で部分文字列が天文学的に大きくなる場合があります。 すべての部分文字列を 1 回スキャンするだけでも限界があるため、ソリューションでは、クエリごとに部分文字列のカウントを線形または対数に近い値に減らす必要があります。 

微妙なエッジケースは、部分文字列の長さが次の値で割り切れない場合です。$k$。 たとえば、次の場合$k = 2$、長さ 3 の部分文字列は、その文字に関係なく、2 つの等しい部分に再配置することはできません。 文字の可分性のみをチェックし、長さの可分性を忘れる単純なアプローチでは、そのようなケースが誤ってカウントされます。 

もう 1 つの罠は、周波数パリティまたは単一文字条件のみをチェックするだけで十分であると想定していることです。 たとえば、$k = 3$、「aabccc」のような部分文字列の合計の長さは 6 ですが、カウントは$a=2, b=1, c=3$。 一部のカウントは 3 で割り切れても、すべてが 3 で割り切れるわけではないため、失敗します。 

中心となる問題は、周波数ベクトルが次のような割り算で定義される制約された格子内にある部分文字列を数えていることです。$k$、任意のクエリ範囲内。 

## アプローチ

 ブルート フォース ソリューションでは、各クエリ範囲内のすべての部分文字列が試行され、文字の頻度が計算され、条件がチェックされます。 各部分文字列について、サイズ 26 の周波数配列を維持します。左の各エンドポイントから拡張するとコストがかかります。$O(26)$、したがって、各クエリは次のようになります$O(n^2 \cdot 26)$最悪の場合。 と$3 \times 10^5$、これはまったく不可能です。 

まず条件を単純化します。 部分文字列は、次のように再配置された後に有効になります。$k$その部分文字列内のすべての文字数が次の値で割り切れる場合に限り、同一のブロックをブロックします。$k$。 合計の長さはカウントの合計であるため、長さの条件は自動的に暗黙的に指定されます。 

したがって、問題は次のようになります。文字周波数ベクトルがゼロモジュロに一致する部分文字列をカウントします。$k$。 

これは、接頭辞合計の剰余を扱うことを示唆しています$k$。 各プレフィックスに対して、カウントを法とする 26 次元ベクトルを定義します。$k$。 部分文字列$l..r$prefix[r] が prefix[l-1] コンポーネント単位のモジュロと等しい場合に有効です$k$。 したがって、問題は範囲クエリ内の等しいベクトルのペアをカウントすることになります。 

これで構造は明確になりました。各プレフィックスは 26 次元空間モジュロの状態にマップされます。$k$そして、クエリ範囲内の等しい状態をカウントする必要があります。 26 次元ベクトルの直接ハッシュは可能ですが、多くのクエリにわたる等しい値の効率的な範囲カウントも必要です。 

これは典型的なオフラインの問題です。 各プレフィックス状態をハッシュに圧縮し、Mo のアルゴリズムまたは周波数マップのセグメント ツリーを使用してクエリを処理できます。 ただし、26 次元では、注意しないとナイーブ ハッシュが衝突に敏感になるため、通常はランダム化された基数または次元ごとに大きな係数を使用してエンコードします。 

より明確に観察すると、これがさらに改善されます。 ベクトルが等しいことのみが必要なため、各プレフィックス状態を 26 個の値のタプルとして扱うことができます。$[0, k-1]$。 ハッシュを使用して、それぞれの一意の状態に整数 ID を割り当てます。 次に、各クエリは次のようになります。プレフィックス ID のサブ配列内の等しい ID のペアをカウントします。これは、Mo のアルゴリズムで解決できる標準的な範囲ペア カウント問題です。$O((n+q)\sqrt{n})$。 

クエリ ポインタを移動しながら、各状態の頻度を維持します。 頻度のある要素を追加する場合$f$、貢献します$f$新しいペア。 削除するときは削除します$f-1$ペアの貢献もそれに応じて変化します。

 ## アルゴリズムのチュートリアル

 1. プレフィックス周波数ベクトルのモジュロを構築する$k$。 ポジションごとに$i$、各エントリがその文字モジュロのカウントを格納する 26 長の配列を維持します。$k$まで$i$。 これにより、部分文字列頻度クエリがプレフィックス状態間の比較に変換されます。 
2. 各プレフィックス ベクトルを単一のハッシュ可能な表現にエンコードします。 それぞれの成分が入っているので、$[0, k-1]$、ベクトルの等価性がハッシュの等価性に対応するように、ローリング混合ベース ハッシュまたはランダム化された重みを使用してそれらを結合します。 このステップにより、26 次元の比較が整数の等価性に縮小されます。 
3. アレイを構築する$a[i]$どこ$a[i]$位置のプレフィックス状態のハッシュです$i$。 また、空のプレフィックスを表すダミーのプレフィックスをインデックス 0 に含めます。 
4. 各クエリを変換する$(x, y)$プレフィックス配列の範囲に入れる: ペアを数えています$i < j$で$[x-1, y]$そのような$a[i] = a[j]$。 
5. Mo の順序付けを使用してクエリを並べ替え、連続するクエリが少しずつエンドポイントを移動するようにします。 
6. 度数表を管理する`cnt[state]`現在の Mo ウィンドウと実行中の応答を確認します。 ポジションを追加するとき$i$、以前に発生したすべての`a[i]`貢献する`cnt[a[i]]`新しいペアが生成されるので、それを答えに追加して頻度を増やします。 取り外すとき$i$、まず頻度を減算し、それが以前に寄与したペアの数を減算します。 
7. すべてのクエリを処理した後、保存されている回答を元の順序で出力します。 

重要な不変条件は、Mo のアルゴリズムの実行中はいつでも、`cnt[v]`ハッシュ値を持つプレフィックス位置の数と正確に等しい$v$現在のウィンドウ内で維持され、維持される答えはそのウィンドウ内の等しいペアの数に等しくなります。 有効な各部分文字列は等しいプレフィックス状態のペアに全単射的に対応するため、アルゴリズムは必要な部分文字列を正確にカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, q = map(int, input().split())
    s = input().strip()

    # prefix modulo-k frequency states
    freq = [0] * 26
    prefix = [(0,) * 26]

    for ch in s:
        freq[ord(ch) - 97] += 1
        freq[ord(ch) - 97] %= k
        prefix.append(tuple(freq))

    # coordinate compress prefix states
    comp = {}
    arr = []
    for p in prefix:
        if p not in comp:
            comp[p] = len(comp)
        arr.append(comp[p])

    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append((l - 1, r, i))

    block = int(len(arr) ** 0.5)

    def mo_cmp(x):
        l, r, _ = x
        return (l // block, r if (l // block) % 2 == 0 else -r)

    queries.sort(key=mo_cmp)

    cnt = [0] * (len(comp) + 5)
    cur_l, cur_r = 0, -1
    cur_ans = 0
    res = [0] * q

    def add(i):
        nonlocal cur_ans
        v = arr[i]
        cur_ans += cnt[v]
        cnt[v] += 1

    def remove(i):
        nonlocal cur_ans
        v = arr[i]
        cnt[v] -= 1
        cur_ans -= cnt[v]

    for l, r, idx in queries:
        while cur_l > l:
            cur_l -= 1
            add(cur_l)
        while cur_r < r:
            cur_r += 1
            add(cur_r)
        while cur_l < l:
            remove(cur_l)
            cur_l += 1
        while cur_r > r:
            remove(cur_r)
            cur_r -= 1
        res[idx] = cur_ans

    print("\n".join(map(str, res)))

if __name__ == "__main__":
    solve()
```この実装は、部分文字列のカウントをプレフィックスの等価性のカウントに変換することに依存しています。 プレフィックス配列にはインデックス 0 が含まれているため、1 から始まる部分文字列は均一に処理されます。 Mo ルーチンは度数表を慎重に維持し、ペア カウント ロジックを使用して答えを段階的に更新します。 

よくある落とし穴は、更新の順序が逆になってしまうことです。`remove`。 減少は寄与分を差し引く前に行われなければなりません。 そうしないと、削除されたペアの数が誤ってカウントされます。 

もう 1 つの微妙な点は、プレフィックスの状態を法で取得する必要があることです。$k$生のカウントとして保存されるだけでなく、すべてのステップで。 モジュロ削減がなければ、ベクトルの等価性は反映されません。$k$-折り畳み構造。

 ## 特殊なケース

 部分文字列の長さが次の値で割り切れない場合、重大なエッジ ケースが発生します。$k$。 たとえば、$k = 3$の場合、長さ 4 の部分文字列は自動的に無効になります。 モジュロ全体でプレフィックス状態が等しいため、アルゴリズムはこれを暗黙的に処理します。$k$合計カウントが一致しない限り、これは発生しないため、そのような部分文字列には等しいプレフィックス状態のペアは存在しません。 

もう 1 つのケースは、文字列全体に均一な文字が含まれている場合です。 その状況では、すべてのプレフィックス状態が少数のベクトル間で循環し、多数の等しいペアが生成されます。 周波数ベースのペアカウントが正しく累積される$f \cdot (f-1)/2$過大な計算をせずに寄付を行うことができます。 

最後の微妙なケースは、クエリが大規模な構造内の小さな範囲である場合です。 Mo のアルゴリズムは現在のウィンドウ内のカウントのみを維持するため、クエリ間隔外のプレフィックス状態は決して寄与せず、グローバルな頻度分布が大きく歪んでいる場合でも正確性が保証されます。
