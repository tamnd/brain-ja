 ## 解決策
 ## 問題の理解

 私たちには、承太郎の最初のポーカー ハンドとして、標準の 52 枚のカード デッキから 5 枚のカードが引かれました。 各カードには 1 から 13 (エースからキング) までのランクがあり、各ランクはデッキ内にちょうど 4 回表示されます。 対戦相手のダービーも、同じ残りのデッキから引いた 5 枚のカードを隠し持っています。 

手を比較する前に、承太郎は数字を選択できます$k$1 から 5 の間で正確に破棄する$k$彼のカードのうち、引きます$k$残りのデッキから新しいカードを交換せずに一律に追加します。 このオプションの交換の後、両プレイヤーは最終ハンドを公開し、スコアは各ハンドのランクの合計となります。 承太郎の合計がダービーの合計より大きい場合、承太郎は利益を得る$k$チップ、小さければ負け$k$、等しい場合、結果はゼロになります。 

タスクは、固定値ごとに計算することです。$k$、承太郎が最適にプレイしたと仮定した場合に予想される最大のチップ結果、つまり承太郎がどちらを選択するかを意味します。$k$ランダムな相手の手札とランダムなドローに対して期待される結果を最大化するために捨てるカード。 

出力は、それぞれ 1 つずつ、5 つの期待値です。$k = 1 \ldots 5$、モジュロの下で$998244353$ここで、除算は逆モジュラーを使用して解釈されます。 

デッキは可能な組み合わせの点では大きいですが、入力されるハンドはわずか 5 枚のカードであり、決定スペースが小さく、構造化されていることがすぐにわかります。 どのような解決策であっても、カードの価値と残りのデッキの確率的構造の対称性を最大限に活用する必要があります。 

素朴な解釈では、すべての捨て札のサブセット、すべての可能なドロー、およびすべての相手のハンドを列挙することを提案します。 デッキの状態の数は組み合わせによるものであるため、これはすぐに不可能になります。承太郎の手札を修正した後、残りのデッキにはまだ 47 枚のカードがあり、相手の手札だけでもすでにカードが 47 枚あります。$\binom{47}{5}$可能性。 

複数のカードが同じランクを持つ場合、微妙なエッジケースが発生します。 スートは無関係でランクのみが重要であるため、同じランクの異なる順列を二重にカウントしてはなりません。 もう1つの問題は、承太郎の最適な捨て札は、除去後の将来のデッキの分布に依存し、何が捨てられるかによってわずかに変化することです。 承太郎のリドローと相手の手札が独立していることを前提とした不用意なアプローチは、誤った期待を生み出すことになります。 

## アプローチ

 直接的な総当たり戦略は、次のすべてのサブセットを列挙することです。$k$承太郎の手札から捨てるカードを計算し、残りの 47 枚のカードデッキからすべての可能な再ドローの組み合わせをシミュレートし、そのような結果ごとに、承太郎の最終的な合計が、同じ残りのデッキ状態からランダムに引いた相手の 5 枚のカードの手札に勝つ確率を計算します。 

対戦相手の列挙を無視しても、再描画スペースだけですでに$\binom{47}{k}$、これをすべての破棄選択肢に対して繰り返す必要があります。 のために$k=5$、これはすでに捨て札の選択肢ごとに何百万もの状態があり、捨て札の選択肢は 5 つしかありませんが、それぞれの場合、同じくらい大きな分布の相手の手札と比較する必要があります。 これにより、実際には指数関数的な状態空間が得られます。 

重要な観察は、対戦相手の手札は、アイデンティティではなく、残りのカード数のマルチセットのみに依存するということです。 承太郎の評価も同様に、最終的なランクの合計のみに依存します。 これにより、問題は組み合わせカード サンプリングから合計に対する確率分布に軽減されます。 

プロセスを次のように再構成します。廃棄セットを選択した後、承太郎は次のように置き換えます。$k$既知の分布からのランダムなサンプルを含むカードと、対戦相手は同じ残りのプールから独立してランダムな 5 枚のカードのサンプルを持ちます。 重要なのは、実際のカードの ID ではなく、金額の配分だけです。 

これは、残りのランク数のマルチセット状態に対する動的プログラミングと合計分布に対する畳み込みを示唆しています。 ランクは 13 個の値にすぎないため、完全な状態空間は、有界のナップザックのような確率分布問題として扱うことで管理可能です。 

最適な解決策は、部分的に枯渇したデッキからカードを引くための確率分布を事前計算し、合計分布を効率的に比較することに依存します。 最後のステップは、期待値を最大化する破棄セットを選択することです。これは、$\binom{5}{k}$ごとの選択肢$k$、小さいです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | デッキサイズの指数関数的増加 | 大 | 遅すぎる |
 | ランク上の DP 分布 | 13 × 5 の小さな多項式 | O(1) 状態 | 承認済み |

 ## アルゴリズムのチュートリアル

 まず問題をランク数に正規化します。 させて$c[i]$ランクの出現数になります$i$承太郎の手の中。 デッキ全体は固定されているため、承太郎のカードを削除すると全体的な枚数は減りますが、確率に影響するのは局所的にのみです。 

グローバルなデッキ数配列を事前計算します$D[i] = 4 - c[i]$、各ランクの残りのカードを表します。 

複数の枚数セットから 5 枚のカードを引くときの合計の分布を計算する関数を定義します。 これは、13 のアイテム タイプにわたる古典的な境界付きナップサック コンボリューションであり、各ランクが値に寄与します。$i$。 

### アルゴリズムのチュートリアル

 1. 入力ハンドをランク 1 ～ 13 の頻度配列に変換します。これにより、無関係なスーツ情報がすべて多重度に圧縮されます。 
2. それぞれについて$k$1 から 5 まで、承太郎のサイズの 5 枚のカードのすべてのサブセットを列挙します。$k$捨てること。 このようなサブセットの数は最大 10 であるため、これは実現可能です。 
3. 破棄することで効果的にそれらのカードがデッキで使用できるようになるため、破棄サブセットごとに、それらのカードを追加し直すことで残りのデッキ数を更新します。 
4. ドロー後の承太郎の最終的なハンドの合計の分布を計算する$k$残りのデッキからのカード。 これは DP を介して行われ、状態はこれまでに引き出されたカードの数と累積合計を表します。 各ランクは、残りのカウントに比例して遷移に貢献します。 
5. 対戦相手の配分も同様に計算しますが、常に同じデッキ状態から 5 枚のカードを引きます。 
6. 計算できるように、両方の分布を累積確率配列に変換します。$P(\text{Jotaro sum} > \text{D’Arby sum})$考えられる合計額を徹底的に調べて効率的に計算します。 
7. 固定廃棄の選択肢の期待値は次のとおりです。$k \cdot (P_{win} - P_{lose})$、これを単純化すると、$k \cdot (2P_{win} + P_{tie} - 1)$。 
8. それぞれのすべての破棄サブセットの最大期待値を取得します。$k$。 

### なぜ効果があるのか

 重要な不変条件は、破棄サブセットを修正した後、ゲームのランダム性は、同じ有限マルチセット分布からの 2 つの独立した描画 (サイズの 1 つ) にのみ依存するということです。$k$すべての順序とスーツレベルの構造が消えます。 合計は独立した抽選に対して加算されるため、結果に対する分布はランク数に対する DP によって完全に捕捉されます。 この DP では、デッキのすべての正当な状態が 1 回だけ表現されるため、確率は正確なままであり、順序や選択によってバイアスが導入されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

# precompute modular inverses for probabilities if needed
inv = [0] * 60
for i in range(1, 60):
    inv[i] = pow(i, MOD - 2, MOD)

def parse(card):
    if card == "A":
        return 1
    if card == "J":
        return 11
    if card == "Q":
        return 12
    if card == "K":
        return 13
    return int(card)

def build_dp(deck, draw):
    # dp[step][sum] compressed to 2D rolling
    max_sum = draw * 13
    dp = [0] * (max_sum + 1)
    dp[0] = 1

    total_cards = sum(deck)

    for _ in range(draw):
        ndp = [0] * (max_sum + 1)
        total = sum(deck)
        for v in range(1, 14):
            if deck[v] == 0:
                continue
            p = deck[v] * pow(total, MOD - 2, MOD) % MOD
            for s in range(max_sum - v + 1):
                if dp[s]:
                    ndp[s + v] = (ndp[s + v] + dp[s] * p) % MOD
        dp = ndp
    return dp

def expected_win(dpA, dpB, k):
    maxA = len(dpA) - 1
    maxB = len(dpB) - 1

    pref = [0] * (maxB + 2)
    for i in range(maxB + 1):
        pref[i + 1] = (pref[i] + dpB[i]) % MOD

    win = 0
    tie = 0
    for i, pa in enumerate(dpA):
        if pa == 0:
            continue
        win = (win + pa * pref[i]) % MOD
        tie = (tie + pa * dpB[i]) % MOD

    lose = (1 - win - tie) % MOD
    return k * (win - lose) % MOD

def main():
    cards = input().split()
    hand = [0] * 14
    for c in cards:
        hand[parse(c)] += 1

    deck = [0] * 14
    for i in range(1, 14):
        deck[i] = 4 - hand[i]

    res = [0] * 6

    from itertools import combinations

    idx = []
    for v in range(1, 14):
        idx += [v] * hand[v]

    for k in range(1, 6):
        best = -10**30
        for comb in set(combinations(range(5), k)):
            new_hand = hand[:]
            for i in comb:
                new_hand[idx[i]] -= 1

            new_deck = [deck[i] + (hand[i] - new_hand[i]) for i in range(14)]

            dpA = build_dp(new_deck, k)
            dpB = build_dp(new_deck, 5)

            val = expected_win(dpA, dpB, k)
            best = max(best, val)

        res[k] = best % MOD

    for k in range(1, 6):
        print(res[k])

if __name__ == "__main__":
    main()
```この実装では、最初にカードをランク​​頻度に変換して、その後のすべての計算が整数分布でのみ機能するようにします。 同一のランクは依然として個別の物理カードとして扱われる必要があるため、破棄列挙ではランクではなくインデックスの組み合わせが使用されます。 

DP 関数は、利用可能なランクに対して繰り返したたみ込みプロセスを使用して、合計に対する確率分布を構築します。 各ステップは 1 枚のカードを引くことを表し、トランジションは残りのデッキ構成によって重み付けされます。 モジュール逆関数は確率の正規化を処理します。 

期待値関数は、累積分布を比較することによって、勝ち、引き分け、負けの確率を計算します。 予想されるチップへの最終的な変換は、ゲームのルールに直接に従います。 

## 実用的な例

 これは、最適な破棄が必ずしも最高のカードである必要はなく、それが分布の分散をどのように変化させるかに依存することを示しています。 

2 番目の例として、価値の高いハンド A、K、K、Q、J を考えてみましょう。K を捨てるのは悪いように思えるかもしれませんが、$k=2$、分散の高いカードを 1 枚削除すると、極端な分散ではなく中間範囲の合計の確率質量が増加するため、期待される結果が向上します。 

| 破棄 | 分散への影響 | 結果の安定性 | 期待値 |

 ## 特殊なケース

 A A A A A のように、5 枚のカードすべてが同じランクである場合、微妙なエッジ ケースが発生します。この場合、サブセットを破棄しても、同じランクが復元されることを除いて、デッキの構成は意味のある形で変わりません。 デッキ数がすべてのランクにわたって対称的なままであり、すべての捨て札の選択が同一の確率分布をもたらすため、DP は依然として正しく動作します。 したがって、すべての k 値は同じ期待結果を生成し、最大化ステップでは任意の破棄が自明に選択されます。 

もう 1 つのケースは、承太郎が K K Q Q J のような高いカードしか持っていない場合です。単純に貪欲なアプローチでは常に知覚価値の低いカードを破棄することになりますが、ここでキングを除去すると、実際には対戦相手に対する相対的なバリアンス アドバンテージが減少する可能性があります。 このアルゴリズムは、個々のカードの寄与ではなく合計分布を評価するため、これを正しく処理します。そのため、同一のランクによって予想される比較に偏りはありません。 

最後に、承太郎のカードを取り除き、デッキがほぼ均一になると、確率はほぼ対称になります。 DP はモジュラーインバースを使用して正しく正規化され、残りのカードの合計が捨て札の選択肢間でわずかに異なる場合でも、除算のバイアスが発生しないようにします。
