 ## 解決策
 ## 問題の理解

 私たちには一列の彫像が与えられ、それぞれの彫像は最初、前、右、後ろ、左というサイクルで配置された 4 つの方向のうちの 1 つを指し、完全に回転した後、再び正面に戻ります。 すべての彫像を時計回りにグローバルに回転させる操作を実行することができますが、各操作は特定の彫像を押すか自分自身を押すことによってトリガーされ、どちらのアクションも最終的には同じグローバル効果を生成します。つまり、すべての彫像が時計回りに 90 度回転するという操作が可能です。 

許可される 2 つの操作の唯一の違いは概念的なものであり、幾何学的なものではありません。 各プレスは常に、サイクル内で正確に 1 ステップずつすべての彫像を回転させます。 この操作はスタチューに個別に影響を与えることはないため、システム全体は、すべての値をモジュロ 4 でグローバルにインクリメントすることを繰り返すことによってのみ進化します。 

目標は、すべての回転後にすべての像が正面を向くように、一連のプレスを選択することです。 各彫像は {0, 1, 2, 3} の値で始まります。0 は前を意味し、1、2、3 は右、後、左に対応します。 

制約 n は 10^6 まで大きくすることができ、彫像ごとに異なる押下シーケンスを試行したり、操作の指数関数的な組み合わせを探索したりするシミュレーションは直ちに除外されます。 有効な解決策は、問題を最悪でも O(n) または O(n log n)、できれば O(n) にまで削減する必要があります。 

ローカルで考えようとすると、微妙な問題が見えてきます。 たとえば、異なる彫像を押すと異なる効果が生じるのではないかと想像するかもしれませんが、実際には両方の操作でアレイ全体に同じ変換が生成されます。 これにより、彫像ごとの制御が削除され、問題は純粋にグローバル オフセット システムに軽減されます。 

エッジケースは、すべての彫像がすでに整列している場合、すべてが同一であるが整列していない場合、および方向の分布によって矛盾する要件が作成される場合に発生します。 たとえば、入力`0 1 2 3`すべてのプレスがすべての値に等しく影響を与えるため、彫像ごとの部分的な推論では明らかに修正できません。 正しい出力は、必要なグローバル回転の数のみに依存し、操作の順序には依存しません。 

## アプローチ

 この強引なアイデアは、一連の押下をシミュレートすることから始まります。 各プレスですべての彫像が 1 ステップずつ回転するため、k 回プレスを適用して、すべての値が 4 を法としてゼロになるかどうかを確認できます。これは簡単です。各 k について、変換された値を計算し、それらがすべてゼロであるかどうかを確認します。 問題は、k には原則として制限がなく、操作では個々の位置が分離されないため、彫像ごとに [0, 3] の k に制限しても役に立たないことです。 

もう少し構造化されたブルート フォース アプローチは、すべての操作が同一であるため、問題となるのは 4 を法とするプレスの合計数だけであることを観察することです。k を 0 から 3 まで試し、毎回配列全体をシミュレートし、妥当性をチェックすることができます。 これは機能しますが、依然として O(4n) のコストがかかります。これは問題ありませんが、より深い構造が隠蔽されます。 

重要な洞察は、システムにはグローバル回転オフセットという 1 つの自由度しかないということです。 k 個の操作を実行すると、すべてのスタチューは k モジュロ 4 ずつ増加します。したがって、ai で始まるスタチューの最終値は (ai + k) mod 4 になります。すべてのスタチューが 0 で終了するには、i ごとに (ai + k) mod 4 = 0 が必要です。 これは、すべての i に対して k ≡ -ai mod 4 であることを意味します。つまり、すべての ai は、k だけシフトした後、同じ値モジュロ 4 に一致する必要があります。 これは、すべての ai が 4 を法として等しい場合にのみ可能であり、k はその値によって一意に決定されます。 

したがって、問題は一貫性のチェックと単一のグローバル オフセットの計算に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | k | のブルート フォース シミュレーション O(4n) | お(1) | 受け入れられるが不要 |
 | グローバルオフセット観測 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 方向の配列を読み取り、各値をモジュロ 4 算術の整数として解釈します。 これは、すべての操作がモジュール構造を維持するために必要です。 
2. k を押すと、すべての要素が (ai + k) mod 4 になるので、すべての値を同時にゼロにする単一の k を検索していることに注目してください。 
3. 条件 (ai + k) mod 4 = 0 を k ≡ -ai mod 4 に変換します。これは、すべての ai が同じ必要な k 値を生成する必要があることを意味します。 
4. 最初の要素から k 候補を k = (4 - a0) mod 4 として計算します。 
5. すべての i について、(ai + k) mod 4 が 0 に等しいことを確認して、一貫性を検証します。これに違反する要素がある場合、均一なグローバル回転の仮定の下では解決策は存在しません。 
6. 一貫性がある場合は、追加の 4 回のプレスの全サイクルは冗長であるため、最小プレス数として k を返します。 

これが機能する理由は、システムに空間的独立性がないためです。 すべての操作はすべてのスタチューに同じ変換を適用するため、状態空間全体がグローバル回転を表す単一の循環変数に折りたたまれます。 このアルゴリズムは、配列全体を 1 つの未知数を持つ単一のモジュラー方程式系に還元することで、この不変式を利用します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    k = (4 - a[0]) % 4
    
    for x in a:
        if (x + k) % 4 != 0:
            print(-1)
            return
    
    print(k)

if __name__ == "__main__":
    solve()
```コードは入力を読み取り、問題をすぐに最初のスタチューから導出された単一のグローバル回転オフセット k を見つけることに落とし込みます。 この選択により、最終的な向きがどのようになるべきかが決まります。最初の像が正面に到達するのに k 回の回転が必要な場合、他のすべての像も同じ k 回転で正面に到達する必要があります。 

ループはこの仮定を検証します。 いずれかの彫像が同じ k の下で整列しない場合、一連の操作によって構成を修正できないことが証明されます。 このチェックは、グローバルな一貫性条件を前提とするのではなく強制するため、不可欠です。 

実装の微妙な詳細は、k のモジュロ計算です。 (4 - a[0]) % 4 を使用すると、k が [0, 3] 内に収まり、正確さを維持しながら負の値が回避されます。 

## 実用的な例

 ### 例 1

 入力:```
4
0 1 2 3
```最初の要素から k を計算します。 

| ステップ | a[i] | (a[i] + k) % 4 | 有効 |
 | --- | --- | --- | --- |
 | i=0 | 0 | (0+0)%4 = 0 | はい |
 | i=1 | 1 | (1+0)%4 = 1 | いいえ |

 k = 0 はすぐに失敗するため、k = 3 を試します ((4 - 0) % 4 = 0 ですが、配列全体で一貫性が失われるため)、すべての制約を満たす単一の k がないことがわかります。 出力は -1 です。 

これは、グローバル回転のみを使用して混合方向を位置合わせできないことを示しています。 

### 例 2

 入力:```
3
2 2 2
```k = (4 - 2) % 4 = 2 を計算します。 

| ステップ | a[i] | (a[i] + k) % 4 | 有効 |
 | --- | --- | --- | --- |
 | i=0 | 2 | 0 | はい |
 | i=1 | 2 | 0 | はい |
 | i=2 | 2 | 0 | はい |

 2 回転後にすべてのスタチューが整列し、計算されたオフセットが正しいことを確認します。 

これにより、一様な配列が常に単一のグローバル回転要件にきれいに削減されることが確認されます。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各像は、計算された単一の回転オフセットの下で一貫性があるかどうか 1 回チェックされます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    data = inp.strip().split()
    n = int(data[0])
    a = list(map(int, data[1:]))

    k = (4 - a[0]) % 4
    for x in a:
        if (x + k) % 4 != 0:
            return "-1"
    return str(k)

# provided sample

# all already front
assert run("3\n0 0 0") == "0"

# uniform rotated
assert run("3\n2 2 2") == "2"

# single element
assert run("1\n3") == "1"

# alternating impossible
assert run("4\n0 2 0 2") == "-1"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、n = 1 の場合です。入力の場合`3`、アルゴリズムは k = (4 - 3) % 4 = 1 を計算し、検証ループは簡単に通過し、出力 1 が生成されます。これは正しいです。なぜなら、単一の彫像は固定回数の回転後に常にそれ自体と一致するからです。 

もう 1 つのケースは、すべての値が同一である場合です。 のために`2 2 2 2`, k は 2 になり、システムは均一なシフトに帰着するため、すべてのチェックに合格します。 

失敗するケースは、次のようなパリティが混在している場合です。`0 2 0 2`。 アルゴリズムは k = 0 を選択しますが、(2 + 0) % 4 = 2 であるため、2 番目の要素はすぐに条件に違反するため、構成は正しく拒否されます。
