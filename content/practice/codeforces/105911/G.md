 ## 解決策
 ## 問題の理解

 各洞窟がノードであり、各一方通行の通路が難易度と呼ばれる重みを持つ有向エッジである有向グラフが与えられます。 アリスは、初期整数のスタミナを持つ指定されたノードから開始します。 彼女が困難を抱えて端を横切るたびに$d$、彼女のスタミナは次のように置き換えられます。$\lfloor x / d \rfloor$。 横断後にスタミナがゼロになると、すぐに停止します。 

重要な点は、アリスはグラフの構造や自分の位置を有益な方法で知らないため、洞窟にいるとき、彼女を助けるか傷つけるかを意図的に選択しないことです。 この問題は、これを最悪の場合の生存の問題に変えます。特定のノードと初期スタミナから開始して、外向きのエッジに沿って移動し続けた場合、スタミナが必然的にゼロになるまでに、何回のトラバースを強制できるでしょうか?

 各クエリは開始ノードと初期スタミナを提供し、生存を延長する最善の選択順序の下で枯渇するまでの最小ステップ数を計算する必要があります。 スタミナの減少ができるだけ遅い方が生存期間が長くなるため、各ノードでの関連する動作は、最も困難度の低い出力エッジを効果的に選択することになります。 

制約は大きく、最大で$2 \cdot 10^5$ノード、$5 \cdot 10^5$エッジ、および$2 \cdot 10^5$クエリ。 これにより、ノード数が線形または対数的なクエリごとのグラフ走査が即座に除外されます。 前処理ステップはほぼ線形またはほぼ線形の時間で行う必要があり、各クエリはほぼ一定または非常に短い対数時間で処理する必要があります。 

任意のエッジを段階的にたどる単純なシミュレーションは、スタミナが一連のフロア分割に依存し、グラフ内の異なるパスによって異なる一連の約数が生成されるという事実によっても複雑になります。 

異なる難易度を持つ複数の発信エッジが存在する場合、微妙なエッジ ケースが発生します。 固定トラバースを誤って仮定したり、より大きな除数を選択するとスタミナがより速く減少することを無視したりすると、一貫性のない答えが得られるでしょう。 

たとえば、ノードに難易度 2 と 100 の発信エッジがある場合、100 を選択するとすぐにスタミナが低下しますが、2 を選択するとスタミナがはるかに長く維持されます。 正しいモデルは、生存を最大化する行動が常に各ステップで利用可能な最小の難易度を選択することであることを反映している必要があります。 

もう 1 つの微妙な点は、グラフ構造自体が、各ノードでどの最小難易度のエッジが利用できるかを決定する場合にのみ重要であることです。 それが修正されると、トラバースは決定的になります。 

## アプローチ

 ブルートフォース解釈では、各クエリを直接シミュレートします。各ステップで、現在のノードを確認し、すべての出力エッジをスキャンして最適な (最小の) 難易度を見つけ、それを横断し、スタミナを更新します。 これは、あらゆる段階で生存を最大化する選択と一致するため、正しいです。 ただし、クエリ間で発信エッジを繰り返しスキャンするのは遅すぎます。さらに重要なことに、同じ決定プロセスを何度も繰り返すことになります。 

重要な観察は、最小の難易度で発信エッジを事前に選択した場合、各ノードの動作が決定的であるということです。 これが完了すると、各ノードには「最良の生存」遷移が 1 つだけ存在します。 グラフは関数有向グラフに折りたたまれ、各ノードが次の 1 つのノードを正確に指します。 

この縮小後、アリスの動きが分岐しなくなりました。 各クエリは 1 つのパスに沿った決定論的な歩行となり、残る唯一の複雑さは、スタミナがそのパスに沿ってどのように進化するかです。 

次にスタミナのダイナミクスを調べます。 すべてのステップが適用されます$x \leftarrow \lfloor x / d \rfloor$どこ$d \ge 2$。 これはスタミナが急速に減少することを意味します。 すべてのエッジの難易度が 2 である最も遅いケースでも、値は毎回半分になるため、ゼロに達するまでのステップ数は約 2 に制限されます。$\log_2 x$、これは最大でも 30 です$x \le 10^9$。 

この境界は 2 番目の重要な単純化です。 グラフに長いサイクルが含まれている場合でも、使い果たされるまでクエリごとに約 30 を超えるエッジをトラバースすることはありません。 これにより、直接シミュレーションが可能になります。

 ## アルゴリズムのチュートリアル

 まずグラフを、各ノードが生存を最大化するために選択された出力遷移を 1 つだけ持つ構造に変換します。 

## アルゴリズムのチュートリアル

 1. すべてのノードについて、最小の難易度で出力エッジを計算します。 これにより、ノードごとに単一の後続ノードが定義されます。 その理由は、より小さい約数を選択すると、常により大きな約数よりも多くのスタミナが維持されるからです。 
2. これらの選択されたエッジを、各ノードが出力エッジを 1 つだけ持つ関数グラフとして扱います。 これからは、移動はこの固定された構造のみに依存します。 
3. 各クエリについて、指定されたスタミナ値を持つ指定されたノードから開始します。 
4. スタミナがゼロになるまで次の処理を繰り返し適用します。後継ノードに移動し、スタミナを更新します。$\lfloor x / d \rfloor$、そして一歩を数えます。 
5.スタミナがゼロになったらすぐに停止し、歩数を出力します。 

終了を可能にする重要な事実は、各ステップが少なくとも 2 で割られるため、スタミナが急速に減少し、意味のあるトランジションが約 30 回を超えることができないということです。 

### なぜ効果があるのか

 各ノードでは、難易度が高い出力エッジは厳密にスタミナをより積極的に減少させ、ゼロに達するまで将来のステップ数を増やすことはできません。 したがって、生存を最大化するための最適な戦略は、すべてのステップで局所的に最適であり、常に最小の出力難易度を選択します。 このローカルルールが固定されると、グローバルパスが一意に決定されます。 フロア分割を適用するプロセスは単調減少でゼロ以下に制限されるため、シミュレーションを終了する必要があります。また、各ステップで値が少なくとも 2 の係数で減少するため、ステップ数は対数的に制限され、効率が確保されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())

    INF = 10**18
    nxt = [0] * (n + 1)
    best_d = [INF] * (n + 1)

    # choose outgoing edge with minimal difficulty
    for _ in range(m):
        u, v, d = map(int, input().split())
        if d < best_d[u]:
            best_d[u] = d
            nxt[u] = v

    # ensure every node has an outgoing edge (guaranteed by statement)
    # but in case of safety, we assume nxt[u] is valid

    out = []

    for _ in range(q):
        u, x = map(int, input().split())
        steps = 0

        # at most ~30 steps since x <= 1e9 and d >= 2
        for _ in range(35):
            d = best_d[u]
            if d == 0:
                break
            x //= d
            steps += 1
            if x == 0:
                break
            u = nxt[u]

        out.append(str(steps))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```前処理ステップでは、各ノードの最小難易度の出力エッジを選択し、決定論的な遷移構造を構築します。 各クエリはプロセスを直接シミュレートします。 考えられるすべての削減パターンを安全にカバーするために、ループ境界は 30 をわずかに上回る値に設定されています。 

微妙な点は、現在のノードが次の遷移に使用されるエッジを決定するため、分割を適用する前ではなく、後にノードを更新することです。 分割後にスタミナがゼロになると、シミュレーションは直ちに停止します。 

## 実用的な例

 各ノードが 1 つの出力エッジを持つ単純なチェーンのようなグラフを考えてみましょう。 

クエリ: スタミナ 10 のノード 1 から開始し、選択したパスに沿ったエッジは常に難易度 2 になります。 

| ステップ | ノード | 前のスタミナ | 難易度 | 後のスタミナ |
 | --- | --- | --- | --- | --- |
 | 1 | 1→2 | 10 | 2 | 5 |
 | 2 | 2→3 | 5 | 2 | 2 |
 | 3 | 3→4 | 2 | 2 | 1 |
 | 4 | 4→5 | 1 | 2 | 0 |

 プロセスは 4 つのステップで停止します。これは、半分に切ることを繰り返すとすぐに消耗してしまうことを示しています。 

次に、難易度が異なる混合例を考えてみましょう。 

スタミナ 9 から開始し、選択した難易度の順序 3、2、2。 

| ステップ | ノード | 前のスタミナ | 難易度 | 後のスタミナ |
 | --- | --- | --- | --- | --- |
 | 1 | A → B | 9 | 3 | 3 |
 | 2 | B → C | 3 | 2 | 1 |
 | 3 | C → D | 1 | 2 | 0 |

 これは、初期の分割における小さな変動であっても、残りの経路長に大きな影響を与えることを示しています。 

これらの痕跡は、プロセスの構造が純粋に乗算的であること、および各ステップが厳密にスタミナを減少させることを裏付けています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import floor

    # embedded solution
    n, m, q = map(int, sys.stdin.readline().split())
    INF = 10**18
    nxt = [0] * (n + 1)
    best_d = [INF] * (n + 1)

    for _ in range(m):
        u, v, d = map(int, sys.stdin.readline().split())
        if d < best_d[u]:
            best_d[u] = d
            nxt[u] = v

    for _ in range(q):
        u, x = map(int, sys.stdin.readline().split())
        steps = 0
        for _ in range(35):
            d = best_d[u]
            x //= d
            steps += 1
            if x == 0:
                break

        out.append(str(steps))

    return "\n".join(out)

 ## 特殊なケース

 厄介なケースは、ノードに非常に異なる困難を持つ複数の発信エッジがある場合です。 アルゴリズムは、最小の難易度エッジを事前に選択することで、これを明示的に解決します。 たとえば、ノードに次のようなエッジがある場合、$d = 2$そして$d = 100$、正しい動作は常に 2 を使用することです。最初のエッジまたは任意のエッジを選択する実装では、生存長が誤って大幅に短縮されてしまいます。 

グラフに自己ループが含まれる場合、別のエッジ ケースが発生します。 最小の難易度の自己ループは、スタミナが減少している間、アリスが同じノードに留まる可能性があることを意味します。 後続ノードが現在のノードと等しい可能性があり、プロセスは引き続き除算を正しく適用するため、シミュレーションはこれを自然に処理します。 

最後に、スタミナが 1 から始まる場合、エッジの難易度に関係なく、最初の部門はゼロを生成します。 この場合、最初の走査でプロセスが直ちに終了するため、シミュレーションでは正確に 1 ステップがカウントされます。
