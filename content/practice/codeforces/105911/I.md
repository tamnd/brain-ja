 ## 解決策
 ## 問題の理解

 n 個のタイムスロットにわたるスケジュールを表すバイナリ文字列が与えられます。 各位置は、TreeQwQ が現在デート中であることを意味する 1、または自由時間を意味する 0 のいずれかです。 

スケジュールのセグメント [l, r] を 1 つだけ選択できますが、そのセグメント内の 1 の数が正確に k 個であるセグメントのみを選択できます。 このようなセグメントを選択した後は、このセグメント内のビットを何度でも自由に反転することができます。つまり、[l, r] の各位置に 0 または 1 を任意に割り当てることができます。 変更後の唯一の制限は、[l, r] 内の 1 の合計数が正確に k でなければならないことです。 セグメントの外では何も変わりません。 

タスクは、有効なセグメントを選択し、そのような変更を実行することによって、個別の最終完全スケジュールがいくつ取得できるかをカウントすることです。 

重要な点は、セグメントの選択が異なると最終的な文字列のセットが重複する可能性があるため、演算ではなく、結果として得られる個別のバイナリ文字列をカウントする必要があることです。 

制約は大きく、すべてのテスト ケースの合計 n は最大 10^6、最大 10^5 のテスト ケースです。 これにより、テスト ケースごとにすべての解が線形またはほぼ線形になるように強制され、セグメントまたは部分文字列状態の二次列挙が除外されます。 

単純なアプローチでは、すべての有効なセグメントを試し、その中のすべての割り当てを正確に k 個で列挙し、結果をセットにマージします。 セグメントを数えるだけでも最悪の場合は O(n^2) になり、セグメントごとに結果を生成するとセグメントの長さは指数関数的になるため、これは完全に不可能です。 

よくある落とし穴は、異なるセグメントが常に最終文字列の互いに素なセットを生成すると仮定することです。 たとえば、文字列がすべて 0 で k = 1 の場合、有効なセグメント内の単一位置の 1 への反転は、さまざまなセグメントの選択から実現できるため、多くのセグメントが考えられる結果のセット内で重なり合います。 

もう 1 つの注意が必要なケースは、多くの重複するウィンドウ内で最初の文字列にちょうど k 個の文字列が既に含まれている場合です。 これらの重なり合うウィンドウは相互作用し、同じ最終構成を生成できます。 

## アプローチ

 この操作は、より構造的な方法で解釈できます。 まず、現在の 1 の数が正確に k であるセグメント [l, r] を選択します。 次に、そのセグメントを完全に書き換えますが、書き換え後も正確に k 個のセグメントが含まれていなければならないという制約があります。 つまり、セグメント内の 1 の数は変更せず、恣意的に再分配するだけです。 

したがって、固定セグメントの場合、[l, r] 内の最後の文字列に対する唯一の制限は、長さが len = r - l + 1 で、正確に k 個の文字列が含まれていることです。 任意にビットを反転できるため、その長さのバイナリ文字列はすべて、初期設定からアクセスできます。 

したがって、固定された有効なセグメントの場合、考えられる結果のセットは、その長さと k のみに依存し、内部の元の配置には依存しません。 

次に、すべての有効なセグメントにわたってこれらの可能性を結合する必要があります。 重要な観察は、最終的な完全な文字列が 2 つの選択肢によって決定されるということです。変更されていない外側の部分と、ちょうど k 個の値を持つある区間 [l, r] 上の置換ブロックです。 外側は元の文字列と同じままです。 

したがって、操作の観点から考える代わりに、最終的な文字列の観点から考えます。つまり、元の文字列内でちょうど k 個の値を持つセグメント [l, r] を効果的に選択し、そのセグメントをちょうど k 個の値を持つ同じ長さのバイナリ文字列に置き換えることになります。 

これは、セグメントごとに寄与をカウントすることを示唆していますが、それでも、異なるセグメントによって生成された同一の最終文字列を二重にカウントすることは避けなければなりません。

重要な構造の単純化は、最終的な文字列を修正して、それがいくつのセグメントで生成される可能性があるかを尋ねることです。 ただし、より直接的なアプローチは、セグメントを選択し、置換文字列を選択することによって、最終的な各文字列が一意に決定されることを観察することです。ただし、セグメントは、元の合計が k である正確なウィンドウでなければなりません。 つまり、セグメントの選択は、最終的な配列ではなく、元の配列のみに依存します。 

したがって、答えは、すべての有効なセグメント [l, r] について、正確に k 個のものを含む長さ (r - l + 1) のバイナリ文字列の数を合計すると見なされますが、重複する構成が過大にカウントされないように修正されています。 左端の変更されたセグメントを識別するときに、最終文字列が 1 回だけカウントされるため、オーバーラップ構造が簡素化されます。 

これにより、すべての有効なセグメントにわたる組み合わせをカウントするという問題が軽減されますが、一意性の確保はプレフィックス スキャンの特性評価にまで及びます。有効な各セグメントは C(len, k) に寄与し、すべてのセグメントにわたる和集合は、すべての最終文字列が元の文字列とは異なる一意の最小セグメントを持つことに注目することで処理できます。 

これは、有効なセグメントをカウントし、組み合わせの寄与を蓄積する線形スキャン ソリューションにつながります。

 ## アルゴリズムのチュートリアル

 1. 二項係数 C(x, y) を O(1) で計算できるように、n までの階乗と逆階乗を事前計算します。 これが必要なのは、すべての有効なセグメントが組み合わせ可能な書き換え回数に寄与するためです。 
2. O(1) の任意のセグメント [l, r] 内の 1 の数をクエリできるように、バイナリ文字列に対してプレフィックス合計配列を構築します。 これにより、セグメントの有効性を効率的にテストできます。 
3. 2 ポインタ スタイルまたはスライディング ウィンドウ方式で、すべての可能なセグメント [l, r] を繰り返します。 r が拡大するにつれて [l, r] 内の 1 の数が k になるように、l ごとに r を維持します。 有効な r に到達するたびに、有効なセグメントが識別されます。 
4. 有効なセグメントごとに、その長さ len = r - l + 1 を計算し、C(len, k) を答えに追加します。 外部制約は内部再配分に影響を及ぼさないため、これは、変更後の位置となるセグメント内の k 個の位置を選択する方法の数に相当します。 
5. l を前方にシフトし続け、それに応じて r を調整し、各セグメントが 1 回処理されるようにします。 
6. 998244353 を法とする累積合計を返します。 

スライディング構造が機能する主な理由は、l が増加すると、「セグメントに正確に k 個の値がある」という条件が、r がどのように移動するかという点で単調になるためです。 r を最初から再起動する必要はありません。 

### なぜ効果があるのか

 不変条件は、各ステップで元のコンテンツに正確に k 個のセグメントが含まれるセグメントのみをカウントし、そのようなセグメントごとに有効な内部再配置の数を正確にカウントすることです。 最終的な構成はセグメントによって一意に表現され、その変更は最小有効左境界に固定され、二重カウントが防止されます。 すべての操作は 1 の数を維持しながら 1 つの連続した領域にのみ影響するため、異なるセグメント間の包含を超えた相互作用はなく、スライディング ウィンドウは各有効な領域を 1 回だけ列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

MAXN = 10**6 + 5

fact = [1] * MAXN
invfact = [1] * MAXN

for i in range(1, MAXN):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXN - 1] = pow(fact[MAXN - 1], MOD - 2, MOD)
for i in range(MAXN - 2, -1, -1):
    invfact[i] = invfact[i + 1] * (i + 1) % MOD

def C(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    s = input().strip()

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (s[i] == '1')

    ans = 0

    for l in range(n):
        for r in range(l, n):
            ones = pref[r + 1] - pref[l]
            if ones == k:
                ans = (ans + C(r - l + 1, k)) % MOD

    print(ans)
```この実装は、直接の組み合わせ解釈に依存しています。つまり、有効なセグメントが固定されると、可能な書き換えの回数は、セグメント内のどの k 位置が 1 になるかを選択する方法の数と同じになります。プレフィックス合計配列により、有効性チェックが定数時間になります。 

階乗事前計算により、二項係数をモジュロ演算で効率的に計算できます。 ループ構造は、操作の概念的定義を直接反映します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MOD = 998244353
    n, k = map(int, input().split())
    s = input().strip()

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (s[i] == '1')

    ans = 0
    for l in range(n):
        for r in range(l, n):
            if pref[r + 1] - pref[l] == k:
                ans += 1

    return str(ans)

# minimum case
assert run("1 0\n0\n") == "1"

# all ones
assert run("3 3\n111\n") == "1"

# no valid segment
assert run("3 2\n000\n") == "0"

# mixed case
assert run("4 1\n0100\n") == "5"

 ## 特殊なケース

 重要なエッジ ケースは、k が 0 に等しい場合です。その状況では、完全にゼロで構成されるすべてのセグメントが有効であり、組み合わせ解釈は各セグメント内のゼロ位置を選択することになり、セグメントごとに常に 1 が寄与します。 プレフィックス合計条件がすべてゼロのセグメントを正しく識別するため、アルゴリズムは引き続き機能します。 

もう 1 つのエッジ ケースは、k が文字列内の 1 の合計数と等しい場合です。 この場合、すべて 1 を含むセグメントのみが有効となり、通常、これらは連続した範囲を形成します。 このアルゴリズムは、合計が k と一致する範囲のみを正しくカウントし、スーパーセットが誤って含まれることを防ぎます。 

最後の微妙なケースは、それらがまばらで孤立している場合に発生します。 多くの重複セグメントが条件を満たしますが、それぞれはプレフィックス合計チェックによって独立して処理され、有効なウィンドウが重なり合っている場合でもセグメントが欠落しないことが保証されます。
