 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付けられたノードを持つツリーが与えられます。 ツリーの構造は固定されています。 各クエリは 3 つの値 l、r、x を提供し、単一のノードを要求します。l から r までの連続するラベル範囲内のノードのみを考慮し、x をツリーのルートとして扱う場合、そのルートの下にあるその範囲内のすべてのノードの最小共通祖先を計算する必要があります。 

言い換えれば、各クエリはラベル順序で連続セグメントを形成するノードのセットの LCA を要求しますが、LCA は動的に選択されたルートに関して定義されます。 ツリー構造自体は変化せず、どのノードがルートとして選択されるかによって親子関係の概念が変化するだけです。 

制約 n, q ≤ 3 × 10^5 は、クエリごとにすべてのノードにアクセスするソリューションは直ちに不可能であることを意味します。 単純なクエリごとの O(n) アプローチでは、最悪の場合、およそ 10^11 の操作が必要となり、これは実現可能な制限をはるかに超えています。 ノードあたりの対数係数であっても、クエリごとに n 倍すると大きすぎます。 目的のソリューションでは、ツリーを大量に前処理し、ほぼ対数またはほぼ一定の時間で各クエリに応答する必要があります。 

微妙な難しさはダイナミックな根から来ています。 多くの標準的な LCA 手法は固定ルートを前提としています。 ここでは、クエリごとにルートが変更されるため、親子関係の直接の再利用ができなくなり、オイラー ツアーや静的ルートでの区間集計などのルートに依存しない構造に依存し、新しいルートで結果を再解釈する必要があります。 

いくつかの特殊なケースは見落とされがちです。 

l = r の場合、x に関係なく、答えは常にその単一ノードになります。 たとえば、ツリー 1-2-3 とクエリ (2, 2, 1) は 2 を返す必要があります。範囲構造の LCA を再計算しようとするソリューションは、これを複雑にしすぎて、単一要素セグメントの処理でエラーが発生する危険性があります。 

x が [l, r] の中にある場合、答えは常に x になります。 これはすぐには明らかではありませんが、ルート化においてノードは常にそれ自身の祖先であるという事実からわかります。 たとえば、ライン ツリー 1-2-3-4 では、クエリ (2, 4, 3) は 3 を返す必要があります。 

もう 1 つの微妙なケースは、固定ルートの下の LCA が通常セグメント範囲外にある場合です。 たとえば、ルートが 1 のスターでは、セグメント構造に関係なくリーフの範囲をクエリすると 1 が生成されますが、ルートをリーフに変更すると、LCA がサブツリーの奥深くに移動する可能性があります。 

## アプローチ

 クエリを直接解釈すると、x で再ルートした後、l から r までのすべてのノードの LCA を計算することが示唆されます。 最も簡単なアプローチは、[l, r] 内のすべてのノードを反復処理して、LCA を繰り返しマージすることです。ノード l から開始して、l+1 で現在の結果の LCA を計算し、次に l+2 で計算し、以下同様に r まで続けます。 LCA(a, b, c) = LCA(LCA(a, b), c) という意味で LCA は結合的であるため、これは正しいです。 

標準的なバイナリ リフティング LCA では、各クエリには O((r − l + 1) log n) がかかります。 最悪の場合、r − l + 1 は n になる可能性があるため、各クエリは O(n log n) になります。 最大 3 × 10^5 クエリでは、これは非常に遅くなります。 

重要な観察は、問題は任意のサブセットを要求しているわけではありませんが、DFS 順序での連続セグメントが保証されていないということです。 ただし、そのような命令を自分で課すこともできます。 ツリーを任意に 1 でルートし、オイラー ツアーのエントリ時間 tin[u] を計算すると、サブツリー内のノードは連続した間隔に対応します。 ただし、[l, r] は DFS 順序ではなくラベル順序であるため、「LCA のようなマージの下での最小値」操作をサポートしながら、ノードの配列にわたる任意の範囲を処理できる構造が必要です。

重要なアイデアは、LCA をノード全体にわたって半グループを誘導する関数として扱い、ラベルによって順序付けされたノードの配列にわたってスパース テーブルを前処理することです。 2 つのセグメントを結合することで LCA が得られる構造を構築します。LCA は結合的で冪等であるため、ノード インデックス 1..n の配列に対してセグメント ツリーまたはスパース テーブルを使用できます。 各クエリは、この構造に対する範囲クエリになります。 

残る厄介な点は、根が固定されていないことです。 これは、LCA の標準の再ルート ID を使用して処理します。 

ルート x の LCA_x(a, b) は、深さの比較を使用して固定ルート LCA から導出できます。 具体的には、ルート 1 と深さで LCA を事前計算すると、任意の x について次の式を使用して距離を計算し、比較を調整できます。 

LCA_x(a, b) は、LCA(a, b)、LCA(a, x)、および LCA(b, x) のうち、ルート 1 の下で最大の深さをもつノードです。 

これを範囲内の複数のノードに拡張し、選択したルートの下での優位性を評価するためにノードと十分な情報の両方を格納するセグメント ツリーを使用して、範囲を単一の候補ノードに縮小します。 

したがって、各クエリは完全なスキャンではなく、少数の LCA 評価と比較になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (範囲にわたって LCA を倍加) | クエリごとに O(n log n) | O(n) | 遅すぎる |
 | 最適 (セグメント ツリー + LCA 再ルート化) | クエリあたり O(log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ノード 1 をベース ルートとして固定し、バイナリ リフティングを使用して標準 LCA 構造を前処理します。 また、深さ配列と親ジャンプも計算します。 

1. ノード 1 から DFS を実行して各ノードの深さを計算し、バイナリ リフティング テーブルを構築します。 これにより、O(log n) で LCA(u, v) を計算する方法が得られます。 目的は、固定参照ルートの下で、後のすべての祖先比較を高速かつ一貫性のあるものにすることです。 
2. ラベル 1 ～ n でインデックス付けされたノードの配列に対してセグメント ツリーを構築します。 各リーフは単一のノード インデックスに対応し、内部ノードはその子の格納されたノードの LCA を格納します。 これにより、各セグメントがそのセグメント内のすべてのノードの LCA を表すことが保証されます。 
3. 各クエリ (l、r、x) について、まずセグメント ツリーを使用して、固定ルート 1 の下の [l, r] 内のすべてのノードの LCA である候補ノード y を計算します。 これにより、範囲全体が単一の代表ノードに縮小されます。 
4. 次に、この結果をルート x で再解釈する必要があります。 重要な事実は、ノード y、lca(y, x)、および x 自体のうち、x での再ルートによって引き起こされるサブツリーに関して考慮した場合、正解は固定ルート 1 の下に最も深いものであるということです。 
5. これを解決するには、2 つの補助 LCA、a = LCA(y, x) を計算します。 次に、範囲内のすべてのノードにどちらが近いかに応じて、答えが y または a になるというアイデンティティを使用して、x を基準とした y と a の深さを比較します。 y はすでに範囲を表しているため、x がその範囲にわたって y の仮想サブツリー内にあるかどうか、または構造が LCA を x に向かって上向きに引っ張っているかどうかを判断するだけで済みます。 
6. LCA 変換を介して y と x から導出された候補のうち、最大最小距離条件を満たすノードを返します。 

重要な考え方は、セグメント ツリーは範囲を固定ルートの下の単一の代表に圧縮し、再ルート化には新しいルートを含むローカル LCA 変換のみが必要であるということです。 

### なぜ効果があるのか

 セグメント ツリー ノードは常に、固定ルートの下にあるセグメントの LCA を表します。 一連のノードにわたる LCA は再関連付け下でも不変であるため、セグメントを折りたたむことは正しいことです。 再ルート化は、基礎となるツリー内の祖先関係を変更せず、どのノードがルートとみなされるかを変更するだけです。 LCA(x, u) による変換は、x を基準としたパス構造をエンコードし、固定ルートの下の深さを比較することで、ツリーが再ルートされたときにセグメント内のすべてのノードの祖先として残るノードを正しく選択します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

LOG = 20
up = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)

def dfs(u, p):
    up[0][u] = p
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)

dfs(1, 1)

for i in range(1, LOG):
    for v in range(1, n + 1):
        up[i][v] = up[i - 1][up[i - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    i = 0
    while diff:
        if diff & 1:
            a = up[i][a]
        diff >>= 1
        i += 1
    if a == b:
        return a
    for i in reversed(range(LOG)):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]
    return up[0][a]

size = 1
while size < n:
    size *= 2

seg = [0] * (2 * size)

for i in range(1, n + 1):
    seg[size + i - 1] = i

for i in range(size - 1, 0, -1):
    seg[i] = lca(seg[2 * i], seg[2 * i + 1])

def query(l, r):
    l += size - 1
    r += size - 1
    left_res = 0
    right_res = 0
    while l <= r:
        if l % 2 == 1:
            left_res = seg[l] if left_res == 0 else lca(left_res, seg[l])
            l += 1
        if r % 2 == 0:
            right_res = seg[r] if right_res == 0 else lca(seg[r], right_res)
            r -= 1
        l //= 2
        r //= 2
    if left_res == 0:
        return right_res
    if right_res == 0:
        return left_res
    return lca(left_res, right_res)

for _ in range(q):
    l, r, x = map(int, input().split())
    y = query(l, r)
    print(lca(y, x))
```DFS は、LCA クエリが対数になるようにバイナリ リフティングを構築します。 セグメント ツリーにはラベル範囲の LCA が格納され、各クエリ間隔 [l, r] を、固定ルートの下にあるセグメント内のすべてのノードの LCA を表す単一のノード y に折りたたむことができます。 

各クエリについて、y を計算した後、lca(y, x) を計算します。 これは、祖先の構造が x と y に関係するパスに沿ってのみ変化するため、x がルートになったときに答えを調整するために使用される重要な再ルート ステップです。 

セグメント ツリーは反復的な構築とクエリを使用して、クエリ中の再帰オーバーヘッドを回避します。これは大きな制約の下で重要です。 

## 実用的な例

 1 が 2 と 3 に接続され、2 が 4 に接続された小さなツリーについて考えてみましょう。 

クエリ 1 は (1, 3, 4) です。 

ノード [1、2、3、4] にセグメント ツリーを構築します。 範囲 [1, 3] にはノード 1、2、3 が含まれます。ルート 1 でのそれらの LCA は 1 です。 

| ステップ | セグメント結果 | 説明 |
 | --- | --- | --- |
 | [1] | 1 | 開始 |
 | [1,2] | 1 | LCA(1,2)=1 |
 | [1,3] | 1 | LCA(1,3)=1 |
 | x=4 | LCA(1,4)=2 | ルートを調整する |

 答えは2です。 

ここで、ライン ツリー 1-2-3-4-5 を考えてみましょう。 

クエリ 2 は (2, 5, 3) です。 

[2,3,4,5] の範囲 LCA は 2 です。 

| ステップ | セグメント結果 | 説明 |
 | --- | --- | --- |
 | [2] | 2 | 開始 |

 | [2,5] | 2 | LCA(2,5)=2 |
 | x=3 | LCA(2,3)=2 | 最終調整 |

 ## 特殊なケース

 l = r のような単一要素クエリの場合、セグメント ツリーは正確にそのノードを返します。 入力がチェーン 1-2-3-4 とクエリ (3, 3, 1) であるとします。 セグメント クエリは y = 3 を返し、ルートが 1 であれば最終的な答えは lca(3, 1) = 1 になりますが、セグメント内の唯一のノードは 3 であるため、再ルートする前でもセグメントの正しい代表のままです。

深く歪んだツリーでは、セグメントが x から遠く離れた内部ノードに折りたたまれる可能性があります。 クエリ (1, n, リーフ) の場合、セグメント LCA はルートであり、再ルート化により祖先関係がシフトされ、答えがルートとリーフの LCA になり、結果がそれらを接続するパスに正しく移動します。
