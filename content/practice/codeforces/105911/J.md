 ## 解決策
 ## 問題の理解

 無限グリッド上にいくつかの点が与えられます。 各点は特定の座標に配置された唐辛子を表し、各唐辛子には固定の種類があります。 1 つのタイプはその列に沿って相互作用します。これは、同じ X 座標を共有する他のピーマンを「気にする」ことを意味します。 もう 1 つのタイプは、その行に沿って相互作用します。これは、同じ y 座標を共有するピーマンを「気にする」ことを意味します。 

要件は、既存のすべてのペッパーが、正しい相互作用タイプの少なくとも 1 つの他のペッパーによって「サポート」されている必要があるということです。 具体的には、垂直タイプのペッパー (列に沿って相互作用するペッパー) は、同じ列の異なる行に少なくとも 1 つの他の垂直タイプのペッパーを必要とします。 水平型ペッパー (行に沿って相互作用するペッパー) には、同じ行の異なる列に少なくとも 1 つの他の水平型ペッパーが必要です。 ペッパーにそのようなパートナーがまだ存在しない場合は、位置と種類の両方を選択して、グリッド上のどこにでも新しいペッパーを追加できます。追加する数を最小限に抑えたいと考えています。 

この制約により、すべてのテスト ケースで最大 2×10^5 のピーマンが許可され、座標は最大 10^9 になります。 これにより、すべてのポイント間のペアごとの相互作用をシミュレートしようとしたり、グリッドを直接検索したりするアプローチは即座に除外されます。 k の二次関数はどれも遅すぎ、単純に実行するとペアごとの対数因子でさえ境界線に達してしまいます。 

構造がほぼ完成しているものの完全には完成していない場合、微妙なエッジケースが発生します。 たとえば、列に垂直ペッパーが 1 つだけある場合、同じ列に少なくとももう 1 つの垂直ペッパーを追加しない限り、要件を満たすことは不可能です。 グローバルカウントのみをチェックするか、行/列が存在するかどうかのみをチェックする単純なアプローチでは、これを見逃してしまいます。 

同様に、2 つの垂直ペッパーがある列を考えてみましょう。 それぞれが同じ列にパートナーを持っているため、両方ともすでに満足しています。 不注意で貪欲な戦略は、相互の満足がすでに成立していることを認識していない場合、不必要に唐辛子を追加しようとする可能性があります。 

## アプローチ

 強引なアイデアは、各唐辛子の満足度を明示的にシミュレートすることです。 すべてのペッパーについて、他のすべてのペッパーをスキャンし、正しいタイプの有効なパートナーが同じ行または列に存在するかどうかを確認します。 これは条件に直接従うものですが、最悪のシナリオではテスト ケースごとに O(k^2) のコストがかかり、k が 2×10^5 に達すると完全に実行不可能になります。 

重要な観察は、コショウの満足度はグローバル構成には依存せず、特定の同値クラスに少なくとも 1 つの他のコショウが存在するかどうかにのみ依存するということです。 垂直ペッパーは x 座標で分割され、水平ペッパーは y 座標で分割されます。 このような各グループ内で重要なのは、その種類のピーマンの数だけです。 

この構造を分離すると、問題は局所的なものになります。 各 x 座標について、そこに存在する垂直ペッパーの数だけを気にします。 各 y 座標について、そこに存在する水平方向のペッパーの数だけを気にします。 相互作用の要件は単純なしきい値条件になります。つまり、グループのサイズが 0 または少なくとも 2 の場合、グループは有効です。 サイズ 1 のグループが唯一の問題となるケースです。これを修正するには、さらに 1 つだけ要素を追加する必要があるからです。 

追加されたピーマンはいつでも必要な行または列に独立して配置できるため、グループ間の相互作用は必要ありません。 これにより、異なる座標間の結合が除去されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k^2) | O(k) | 遅すぎる |
 | 行/列ごとにカウントする | O(k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を 2 つの独立した計数タスクに分割します。1 つは列ごとにグループ化された垂直ピーマンに関するタスク、もう 1 つは行ごとにグループ化された水平ピーマンに関するタスクです。

1. 与えられたすべてのペッパーを走査し、2 つのハッシュ マップを維持します。 1 つのマップは、各列 x に垂直方向のピーマンが何個出現するかを数えます。 もう 1 つは、各行 y に水平方向のピーマンが何個出現するかをカウントします。 このステップでは、すべての幾何学的情報を周波数統計に圧縮します。 
2. すべてのピーマンを処理した後、垂直マップの各列を検査します。 列に垂直ペッパーが 1 つだけ含まれている場合、そのペッパーには現在その列にパートナーがありません。 これを修正するには、同じ列のどこかに少なくとも 1 つの垂直ペッパーを追加する必要があります。 カウントが 2 つ以上の場合、その列のすべてのコショウにはすでに少なくとも 1 つのコンパニオンがあるため、アクションは必要ありません。 
3. 水平マップの行についても同じ推論を繰り返します。 水平方向のペッパーが 1 つだけ含まれる行は、必要な加算を 1 つ行います。 
4. 両方のマップからそのようなシングルトンのケースをすべて合計します。 この合計が、必要な追加ピーマンの最小数です。 

ここでの重要な設計上の選択は、問題のある各グループが独立して修正されることです。 シングルトン列を修正するために新しいペッパーを追加しても、選択した座標に配置され、その特定のグループにのみ影響するため、他の列には干渉しません。 

### なぜ効果があるのか

 不変条件は、すべての有効な構成で、各列内で垂直方向のペッパーが少なくとも 2 つのサイズのコンポーネントにグループ化され、各行内で水平方向のペッパーが同様にグループ化されることを保証する必要があるということです。 サイズ 1 のグループはいずれも孤立しており、内部的には満たされないため、必然的に少なくとも 1 つの外部追加が強制されます。 逆に、各シングルトン グループに新しいペッパーを 1 つだけ追加するだけで常に十分です。これは、他の場所の正確さに影響を与えることなく、そのグループ内に有効なペアが作成されるからです。 グループは座標間で相互作用しないため、独立した補正を合計すると全体的な最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        k = int(input())
        
        col_v = defaultdict(int)
        row_h = defaultdict(int)

        for _ in range(k):
            x, y, w = map(int, input().split())
            if w == 0:
                col_v[x] += 1
            else:
                row_h[y] += 1

        ans = 0

        for x, c in col_v.items():
            if c == 1:
                ans += 1

        for y, c in row_h.items():
            if c == 1:
                ans += 1

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、グリッドを 2 つの周波数マップに圧縮します。1 つは垂直ペッパー用に x でキー設定され、もう 1 つは水平ペッパー用に y でキー設定されます。 各マップ エントリは制約グループを直接表します。 最後のループは、サイズが正確に 1 であるグループがいくつあるかを単純にカウントします。これは、強制加算の数に対応します。 

ここでよくある実装上の間違いは、ピーマンの追加を繰り返しシミュレートしようとすることです。 その場合、構造を繰り返し更新する必要があり、誤って二重カウントや更新のカスケードが発生する可能性があります。 計数アプローチでは、初期分布から最終状態を直接計算するため、このような問題が完全に回避されます。 

## 実用的な例

 ### 例 1

 カウントが含まれる列の垂直ペッパーを考慮してください。`[3, 1, 2]`水平に並んだピーマン`[1, 2, 1]`。 

| ステップ | 列vの状態 | 行_h の状態 | 貢献 |
 | --- | --- | --- | --- |
 | 初期化 | {a:3、b:1、c:2} | {d:1,e:2} | - |
 | スキャン列 | b | のシングルトン - | +1 |
 | スキャン行 | - | d | シングルトン +1 |
 | 結果 | - | - | 2 |

 これは、大きなクラスターではなく、孤立したグループのみが重要であることを示しています。 

### 例 2

 すべての垂直列に少なくとも 2 つのペッパーがすでにあると仮定します。`{x1:2, x2:4}`そして横の列は`{y1:3}`。 

| ステップ | 列vの状態 | 行_h の状態 | 貢献 |
 | --- | --- | --- | --- |
 | 初期化 | {x1:2,x2:4} | {y1:3} | - |
 | スキャン列 | シングルトンなし | - | 0 |
 | スキャン行 | - | シングルトンなし | 0 |
 | 結果 | - | - | 0 |

 This confirms that once every group size is at least two, no additions are required.

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    from collections import defaultdict

    t = int(input())
    out = []

    for _ in range(t):
        k = int(input())
        col_v = defaultdict(int)
        row_h = defaultdict(int)

        for _ in range(k):
            x, y, w = map(int, input().split())
            if w == 0:
                col_v[x] += 1
            else:
                row_h[y] += 1

        ans = 0
        for c in col_v.values():
            if c == 1:
                ans += 1
        for c in row_h.values():
            if c == 1:
                ans += 1

        out.append(str(ans))

    return "\n".join(out)

# single vertical singleton
assert run("1\n1\n10 10 0\n") == "1"

# already satisfied pair
assert run("1\n2\n1 1 0\n1 2 0\n") == "0"

# mixed independent rows and columns
assert run("1\n4\n1 1 0\n1 2 0\n2 1 1\n3 1 1\n") == "0"

# two independent singletons
assert run("1\n2\n1 1 0\n2 2 1\n") == "2"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | single vertical | 1 | シングルトン列は修正が必要です |
 | paired column | 0 | サイズ ≥ 2 には追加の必要はありません |
 | mixed balanced | 0 | 行/列グループの独立性 |
 | two singletons | 2 | 答えの相加的な性質 |

 ## 特殊なケース

 重大なエッジ ケースは、座標グループのサイズがちょうど 1 である場合です。 たとえば:

 入力:```
1
1
5 5 0
```このアルゴリズムは、列 x=5 を垂直ペッパーが 1 つあるものとして分類します。 処理中に、答えが 1 ずつ増加します。 行の寄与は存在しないため、最終出力は 1 になります。正しさは、その列に少なくとも 1 つの追加ノードを導入しない限り、単一のノードが要件を満たすことができないという事実から得られます。 

もう 1 つのケースは、複数のシングルトン グループが異なる列または行に存在する場合です。 

入力:```
1
3
1 1 0
2 2 0
3 3 1
```ここでは各グループが独立しています。 このアルゴリズムは 3 つのシングルトン構造をカウントし、3 を返します。各増分は、切断された要件の修正に対応し、追加は独立して配置できるため、重複や二重カウントはありません。 

3 番目の微妙なケースは、グループにすでに 2 つの要素があるが、複数の位置に分散している場合です。 たとえ座標が異なっていても、同じ x (縦方向) または同じ y (横方向) を共有していれば、それらはすでに満たされています。 アルゴリズムはグループ内の空間分布ではなくカウントのみをチェックするため、これを自然に処理します。
