 ## 解決策
 ## 問題の理解

 Nezha が海で騒乱を引き起こすのにどれくらいの時間を費やしたかを表す 3 つの独立したイベントが与えられています。 各イベントには時間単位で測定される継続時間があり、混乱が発生する時間ごとに一定数の苦情が生成されます。 

具体的には、3 つの別々のインシデントに対応する 3 つの期間があります。 1 つ目は A 時間、2 つ目は B 時間、3 つ目は C 時間続きます。 これらのインシデントのいずれかに費やされるすべての時間は、まさに D の苦情の原因となります。 タスクは、3 つのインシデントすべてで発生した苦情の合計数を計算することです。 

問題の構造は、海を乱すのに費やされる合計時間は、単に 3 つの期間の合計であることを意味します。 各時間は独立して同じ固定コストに寄与するため、最終的な答えは、合計時間に 1 時間あたりの苦情率を掛けたものになります。 

制約は非常に小さく、すべての値は 1 ～ 100 の範囲内に制限されます。これにより、一般的な整数型のオーバーフローに関する懸念が即座に排除され、最も単純な算術アプローチでも制限時間内で十分であることが確認されます。 

順序付け、重複、または部分的な寄与を伴う隠れたエッジのケースはありません。 各インシデントは完全に独立しており、結果に直線的に寄与します。 

よくある間違いは、期間を合計する代わりに誤って乗算してしまうことです。たとえば、A × B × C × D を計算することですが、これは問題の文脈において意味のある解釈がありません。 もう 1 つの間違いは、時間ごとではなくインシデントごとに D を適用することです。これにより、(A + B + C) × D が A × D + B × D + C × D として誤って解釈されますが、より複雑な言語では括弧が欠落していたり​​、グループ化が間違っていたりして誤って実装されます。 Python では、これはリスクが低くなりますが、それでも明示する価値があります。 

## アプローチ

 この問題を考える最も直接的な方法は、各インシデント中に何が起こるかをシミュレートすることです。 概念的には、3 つのイベントのそれぞれを 1 時間ごとに繰り返し、1 時間ごとに D 件の苦情を追加することができます。 これは、A 回、次に B 回、次に C 回ループし、毎回カウンターをインクリメントするように見えます。 これは定義を正確に反映しているため、正しいです。 

ただし、このアプローチは同じ操作を繰り返し実行するため不要です。 反復の合計数は A + B + C となり、最大 300 になります。これはすでに小さいですが、基礎となる構造が明らかになります。すべての反復は、D を加えてまったく同じ作業を実行します。 

各時間が独立して均一に寄与していることを認識すると、シミュレーションを 1 つの算術式に折りたたむことができます。 反復する代わりに、最初に合計時間を計算し、D を 1 回掛けます。これにより、計算全体が定数時間に短縮されます。 

重要な観察点は直線性です。苦情生成プロセスは時間の経過とともに相加的であり、単位時間あたりは均一です。 これにより、レートを適用する前にすべての時間間隔を集計できます。

 ## アルゴリズムのチュートリアル

 すべての障害にわたって発生する苦情の合計を計算したいと考えています。 

1. 入力から 4 つの整数 A、B、C、D を読み取ります。 これらは 3 つの独立した期間と 1 時間あたりの均一な苦情率を表します。 
2. 3 つの期間を合計して、海洋騒乱に費やした合計時間を計算します: total_time = A + B + C。この集計が機能するのは、各事故が苦情の総数に独立して寄与しているためです。 
3. 合計時間に D を掛けて、最終的な苦情数を取得します。answer = total_time × D。このステップでは、合計時間に一律の 1 時間あたりのコストを適用します。 
4. 計算結果を出力します。 

### なぜ効果があるのか

各時間の活動は、苦情への寄与という点で区別がつきません。 割合 D はすべての時間およびすべてのインシデントにわたって一定であるため、苦情の合計数は費やした合計時間数のみに依存します。 加算は乗算に分配されるため、(A × D) + (B × D) + (C × D) は (A + B + C) × D と正確に等しく、最初に集計して 1 回乗算する正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    A, B, C, D = map(int, input().split())
    total_time = A + B + C
    print(total_time * D)

if __name__ == "__main__":
    main()
```実装は派生した式に直接続きます。 入力は 1 行で読み取られ、4 つの整数にアンパックされます。 A、B、C の合計は、計算の構造を明確にするために明示的に保存され、D で乗算されます。 

total_time に中間変数を使用することは正確さを保つために必須ではありませんが、式を読み間違える可能性が減り、導出で使用される論理分解が反映されます。 

すべての算術演算は Python 整数を使用して実行され、可能な最大値 (300 × 100 = 30000) を安全に処理します。

 ## 特殊なケース

 ### 最小値

 入力:

 A = B = C = D = 1

 このアルゴリズムは、total_time = 3 および Output = 3 を計算します。算術式は下限でも有効なままであるため、小さな値に対して特別な処理は必要ありません。 

### 最大値

 入力:

 A = B = C = D = 100

 実行:

 合計時間 = 300

 結果 = 300 × 100 = 30000

 上限であっても、乗算は整数の範囲内に収まり、Python ではオーバーフローや精度の問題は発生しません。 

### 不均一な分布

 入力:

 A = 10、B = 1、C = 1、D = 2

 実行:

 合計時間 = 12

 結果 = 24

 これにより、インシデント間での時間がどのように配分されるかではなく、合計だけが重要であることがわかります。 各時間の貢献度は同じであるため、パーティション分割は無関係です。
