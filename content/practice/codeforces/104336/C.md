 ## 解決策
 ## 問題の理解

 2 人のプレイヤーが与えられ、それぞれ 10 進数で書かれた整数で始まります。 アーサーが所有する`a`、ニキータが所有しています`b`。 その後、アーサーは正確に追加します`n`ニキータは自分の番号の右側に 10 進数を正確に追加します`m`彼の番号の右側の数字。 追加される数字は自由に選択できます。 

両方の拡張が完了すると、結果として得られる 2 つの整数が通常の整数として比較されます。 アーサーの最終的な数字が大きければ勝ち、ニキータの方が大きければ勝ち、それ以外の場合は引き分けです。 

重要な点は、両方のプレイヤーが、自分の勝利のチャンスを最大化するために、付加される数字を最適に選択しようとしているということです。 各プレイヤーは自分のサフィックスのみを制御するため、ゲームはどの程度の影響力があるかを理解することになります。`n`そして`m`～の間の違いを克服することに屈する`a`そして`b`。 

制約は非常に大きく、4 つの値すべてで最大 10^9 です。 これにより、すべてのサフィックスの桁ごとの追加やブルート フォースをシミュレートしようとする構築が即座に排除されます。 10^9 の数字が追加された単一の数値でさえ、明示的に表すことは不可能であるため、解決策は問題を閉じた形式での大きさを比較することに減らす必要があります。 

微妙なエッジケースが現れるのは、`a`そして`b`は近いですが、1 人のプレイヤーが追加する桁が大幅に多くなります。 たとえば、次の場合`a = 9`、`b = 10`、アーサーは多くの数字を追加しますが、ニキータはほとんど数字を追加しないため、先頭の構造は接尾辞の長さに圧倒される可能性があります。 単純な比較`a`そして`b`このような場合、追加できる桁数が無視されるため、完全に失敗します。 

最適性を考慮せずに、プレーヤーが常に 9 だけまたは 0 だけを追加すると仮定すると、別の失敗ケースが発生します。 正しい推論は、各プレーヤーが辞書編集的に最終的な数字を最大にするために接尾辞の数字を選択するという事実に依存します。つまり、追加されるすべての位置で常に 9 を選択します。 

## アプローチ

 強引な解釈では、両方のプレイヤーの選択をシミュレートしようとします。 考えられる長さの数字列ごとに`n`アーサーと`m`ニキータの場合、結果の数値を作成して比較します。 各プレイヤーの最適な選択は考えられるすべてのサフィックスの中から選択されるため、これは理論的には正しいですが、可能性の数は 10^n と 10^m であり、n と m の小さな値であっても天文学的に大きくなります。 ブルートフォースはすぐに失敗します。 

重要な観察は、各プレーヤーの最適な戦略が決定的であるということです。 目標は最終的な数値を最大化することであるため、追加されるすべての数字は 9 である必要があります。より重要な位置が優先されるため、これより小さい数字は、後で補正する利点をもたらさずに値を減らすだけです。 

したがって、アーサーの最終的な数字は次のようになります。`a`に続く`n`9 桁の場合、ニキータは次のようになります`b`に続く`m`9の桁。 

ここで問題は、連結によって形成された 2 つの非常に大きな数値を比較することになります。 それらを明示的に構築する代わりに、構造によって比較します。 拡張後に桁数が異なる場合は、有効長の長い方が優先されます。 有効長が等しい場合は、最初に 10 のべき乗でスケールされた整数部分によって比較し、次に接尾辞の影響によって比較します。 

これにより、問題は次の比較に帰着します。`a * 10^n + (10^n - 1)`対`b * 10^m + (10^m - 1)`。 直接累乗は Python 整数を介した場合にのみ安全であるため、Python の任意精度算術または構造化比較ロジックに依存します。

 ## アルゴリズムのチュートリアル

 1. 両プレーヤーが常にすべてのポジションに数字の 9 を追加することに注意してください。 これは、接尾辞の数字を増やすと最終的な数値が増加し、将来の決定とのトレードオフがないためです。 
2. ゲームの状態を 2 つの決定的な最終数値に置き換えます。 Arthur は次のようにします。`A = a * 10^n + (10^n - 1)`そしてニキータは`B = b * 10^m + (10^m - 1)`。 
3. の大きさを比較する`A`そして`B`。 完全な値を構築する代わりに、Python の多倍長整数演算を使用するか、桁構造を比較することによって値を比較します。 
4. もし`A > B`, アーサーが勝ちます。 もし`A < B`, ニキータが勝ちます。 それ以外の場合、結果は引き分けです。 

重要な推論ステップは、サフィックスの最適化により戦略的な相互作用が完全に除去されるということです。 両方のプレーヤーが最適にプレイすると、ゲームはそれ以上の選択肢のない直接的な数値比較の問題になります。 

### なぜ効果があるのか

 追加されたすべての位置での各プレーヤーの決定は独立して単調です。任意の桁を増加させると、将来の桁に関係なく最終値が厳密に増加します。 これにより、貪欲でない構造が排除されます。 その結果、最適な戦略は固定的かつ固有のものとなり、ゲームは 2 つの構築された数値の決定論的な比較に崩壊します。 どちらの構造も各プレイヤーにとって正確な上限であるため、それらを比較すると正しい勝者が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, b, n, m = map(int, input().split())

A = a * (10 ** n) + ((10 ** n) - 1)
B = b * (10 ** m) + ((10 ** m) - 1)

if A > B:
    print("Arthur")
elif A < B:
    print("Nikita")
else:
    print("Draw")
```このコードは、各プレーヤーの最適な最終数値を導き出す式を直接実装します。 の乗算`10 ** n`元の数値を左にシフトします`n`小数点以下の桁数、および`(10 ** n - 1)`追加されたすべての数字を 9 で埋めます。 

Python の整数型は、次の場合に発生する可能性のある非常に大きな値を安全に処理します。`n`そして`m`大きいため、手動による大きな整数の処理は必要ありません。 

この比較は直接整数比較であり、正確かつ効率的です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    a, b, n, m = map(int, input().split())

    A = a * (10 ** n) + ((10 ** n) - 1)
    B = b * (10 ** m) + ((10 ** m) - 1)

    if A > B:
        return "Arthur"
    elif A < B:
        return "Nikita"
    return "Draw"

# provided samples
assert run("1 2 3 4") == "Nikita"
assert run("54 54 54 54") == "Draw"
assert run("11 10 2 2") == "Arthur"

# custom cases
assert run("1 1 1 2") == "Nikita", "longer suffix wins"
assert run("9 10 1 1") == "Nikita", "base dominance"
assert run("100 1 0 0") == "Arthur", "no extension comparison"
assert run("5 5 10 10") == "Draw", "identical structure"

 ## 特殊なケース

 重要なエッジケースの 1 つは、両方のプレーヤーが同じベースと同じエクステンションの長さを持っている場合です。 入力用`a = 7, b = 7, n = 3, m = 3`、両方とも計算します`7 * 10^3 + 999`、同じ数字が生成されます。 構築された両方の値が同一であり、最終的な等価性チェックで「Draw」が返されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つの微妙なケースは、1 人のプレイヤーのベースがはるかに大きいものの、追加する桁数が少ない場合です。 のために`a = 1000, b = 1, n = 0, m = 5`、アーサーは`1000`、一方、ニキータは`1 * 10^5 + 99999 = 199999`。 アーサーは大きく始まりますが、ニキータの長いサフィックスが完全に支配しています。 このアルゴリズムは、比較の前に 10 の累乗シフトが適用され、大きさが十分に異なる場合に接尾辞の長さが主要な要素となるため、これを捉えます。
