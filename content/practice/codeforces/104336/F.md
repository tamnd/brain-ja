 ## 問題の理解

 サイズのグリッドが与えられています$n \times m$, ここで、各セルは黒または白のいずれかに色付けされます。 グリッドはチェス盤のような地域の地図として想像できます。 「壁を描く」唯一許可されている方法は、異なる色の 2 つの隣接するセル間の境界に沿ったものです。 2 つの隣接するセルが同じ色を共有している場合、そのエッジは使用できず、壁の一部にすることはできません。 

この設定で有効な構造は、そのような許可されたエッジを使用して境界を完全にトレースできる正方形の領域です。 言い換えれば、その周囲に沿ったすべての単位セグメントが異なる色の 2 つのセルの間に位置するように、グリッドに沿って整列された正方形を見つけたいと考えています。 タスクは、そのような正方形の可能な最大辺の長さを計算することです。 少なくとも辺 1 の正方形を形成できない場合は、0 を出力します。 

入力サイズの制約$n \cdot m \le 3 \cdot 10^5$各セルを中心として扱うソリューションはすでに除外されています。$O(nm)$拡大。 3 次またはセルごとの密な 2 次アプローチでも限界を超えます。 これにより、ローカル構造を前処理し、プレフィックス形式の推論または答えよりも二分探索を使用する方向に進みます。 

グリッドが均一である場合、微妙なエッジケースが発生します。 すべてのセルが同じ色の場合、境界エッジはどこにも使用できないため、1×1 の正方形さえ囲むことができません。 これは 1 ではなく 0 を正しく返す必要があります。 

もう 1 つのエッジ ケースは、交互パターンが存在するものの、まばらすぎて完全な正方形の境界を形成できない場合に発生します。 たとえば、サイズ 3×3 のチェッカーボードは、対角線の交互は無関係であるため、有効な 2×2 の正方形を保証しません。 エッジに沿った隣接性のみが重要であり、一部の境界は失敗します。 

## アプローチ

 強引なアイデアは、可能なすべての左上隅と可能なすべての正方形サイズを試してみることです。 各辺の正方形候補について$k$では、すべての境界エッジが「隣接するセルの色が異なる」という条件を満たすかどうかを検証します。 1マスのコストを確認する$O(k)$4 つの側面を検査するため、最悪の場合の複雑さは次のようになります。$O(n m \cdot \min(n,m))$、これはおおよそ次のように縮退します。$O(n^2 m)$。 と$n m \le 3 \cdot 10^5$内部検証が大きなオーバーラップを繰り返し繰り返すため、グリッドが長くなった場合でも、これではまだ遅すぎます。 

重要な観察は、正方形の境界の有効性が、エッジ上のローカル隣接制約のみをチェックすることに帰着できるということです。 全周を繰り返しスキャンする代わりに、水平および垂直の各エッジが「有効」かどうか、つまり 2 つの端点の色が異なるかどうかを前処理します。 その後、問題は次のようになります。その境界に沿ったすべてのエッジが有効になるような最大の正方形を見つけます。 

この縮小が行われると、各行を有効な垂直遷移を記述するバイナリ配列として扱い、各列を有効な水平遷移を記述するものとして扱うことができます。 次に辺の正方形$k$は、その上エッジ、下エッジ、左エッジ、および右エッジについて、すべての対応するセグメントがこれらの事前計算された構造内で有効である場合に有効です。 

修正をテストするには$k$では、グリッド上でウィンドウをスライドさせ、有効性配列のプレフィックス合計を使用して、位置ごとに一定の時間をチェックインできます。 これにより、単一のチェックを行うことができます$k$で$O(nm)$。 次に二分探索を行います$k$、を与える$O(nm \log \min(n,m))$解決。

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 有効なエッジを事前計算する

 グリッドをスキャンし、2 つの補助グリッドを構築します。 1 つは、それぞれの水平方向の隣接性をマークします。$(i, j) \leftrightarrow (i, j+1)$は有効であり、もう 1 つはそれぞれの垂直方向の隣接性をマークします。$(i, j) \leftrightarrow (i+1, j)$有効です。 これにより、色の制約が高速なブール値チェックに変換されます。 

これが重要な理由は、正方形の境界は絶対的な色ではなく、これらの局所的な比較のみに依存するためです。 

### ステップ 2: 有効なエッジにわたるプレフィックス合計を構築する

 完全なセグメントが完全に有効であるかどうかをクエリできるように、水平有効配列と垂直有効配列に対してプレフィックスの合計を構築します。$O(1)$。 これがなければ、各正方形チェックの辺の長さは直線のままになります。 

### ステップ 3: 答えを二分探索する

 最大限を追求します$k$有効な正方形が存在するようにします。 候補者ごとに$k$、左上のすべての位置をテストします。 

二分探索が適用できるのは、サイズが正方形の場合です。$k$存在する場合、境界の制限により、より小さい正方形も有効になります。 

### ステップ 4: 固定正方形サイズを検証する

 与えられた$k$、すべての可能な左上隅を反復処理します。$(i, j)$。 ポジションごとに 4 つの条件をチェックします。 

上端、下端、左端、および右端はすべて、プレフィックス合計を使用して完全に有効です。 

4つの条件をすべて満たすポジションがあれば、$k$実現可能です。 

### ステップ 5: 実現可能な最大値を返す

 二分探索は最大のものに収束します$k$実現可能性が保たれます。 

### なぜ効果があるのか

 このアルゴリズムは、問題をグローバル構造からローカル制約に圧縮します。 正方形の境界はユニット エッジによって完全に決定され、各エッジは独立して有効になります。 プレフィックス合計により定数時間のセグメント検証が可能になるため、すべての候補正方形がオーバーラップを再計算することなくチェックされます。 正方形サイズの単調性により、二分探索の正確性が保証されます。有効な正方形を拡張しても、その境界内に新しい無効なエッジを作成することはできず、制約が追加されるだけであるため、実現可能性はサイズが大きくなるにつれて低下するだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    if n < 2 or m < 2:
        print(0)
        return

    # horizontal valid edges: h[i][j] is edge between (i,j) and (i,j+1)
    h = [[0] * (m - 1) for _ in range(n)]
    # vertical valid edges: v[i][j] is edge between (i,j) and (i+1,j)
    v = [[0] * m for _ in range(n - 1)]

    for i in range(n):
        for j in range(m - 1):
            h[i][j] = 1 if g[i][j] != g[i][j + 1] else 0

    for i in range(n - 1):
        for j in range(m):
            v[i][j] = 1 if g[i][j] != g[i + 1][j] else 0

    ph = [[0] * (m) for _ in range(n)]
    pv = [[0] * (m) for _ in range(n)]

    for i in range(n):
        for j in range(m - 1):
            ph[i][j + 1] = ph[i][j] + h[i][j]

    for j in range(m):
        for i in range(n - 1):
            pv[i + 1][j] = pv[i][j] + v[i][j]

    def ok(k):
        if k == 0:
            return True
        if k == 1:
            return True

        for i in range(n - k + 1):
            for j in range(m - k + 1):
                # top edge
                if ph[i][j + k - 1] - ph[i][j] != k - 1:
                    continue
                # bottom edge
                if ph[i + k - 1][j + k - 1] - ph[i + k - 1][j] != k - 1:
                    continue
                # left edge
                if pv[i + k - 1][j] - pv[i][j] != k - 1:
                    continue
                # right edge
                if pv[i + k - 1][j + k - 1] - pv[i][j + k - 1] != k - 1:
                    continue
                return True
        return False

    lo, hi = 1, min(n, m)
    ans = 0

    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装ではまずグリッドをエッジ有効性配列に変換し、その後のすべてのチェックが比較を繰り返すのではなく接頭辞の合計に基づいて算術演算されるようにします。 The prefix sums are carefully aligned so that each segment query corresponds exactly to a difference of two prefix values.

 の`ok(k)`関数は、有効な正方形の境界の幾何学的条件をエンコードします。 4 つの比較のそれぞれで、片側に沿ったすべてのエッジが有効かどうかがチェックされます。 との平等$k-1$セグメント内のすべてのエッジが使用可能であることを保証します。 

この実現可能性テストに加えて二分探索が適用され、最終的な答えは有効な最大の正方形サイズになります。

 ## 特殊なケース

 すべての「B」セルのような均一なグリッドでは、有効なエッジがまったく生成されません。 前処理ステップでは、すべての水平方向および垂直方向の有効性配列がゼロに設定されるため、すべてのプレフィックス合計チェックは、すべてのプレフィックス合計チェックに失敗します。$k \ge 2$。 k=1 のみが実質的に有効であるため、二分探索は正しく 0 を返しますが、この問題では実際に囲まれた正方形が必要であり、これは使用可能な周囲のエッジに依存します。
