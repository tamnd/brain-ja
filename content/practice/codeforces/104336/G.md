 ## 問題の理解

 壁は一連の独立したセグメントであり、それぞれが初期高さを持っています。 モンスターはパラメータに関連付けられた固定ルールを使用して各セグメントを個別に攻撃します。$k$。 セグメントに対する攻撃は繰り返されるプロセスです。現在の高さが次の値で割り切れる場合はいつでも、$k$、セグメントは即座に破壊され、そのセグメントへの攻撃は追加時間なしで停止します。 それ以外の場合、モンスターは 1 分間かけて高さを次の値に置き換えます。$\lfloor h/k \rfloor$、そして新しい高さから続きます。 

したがって、各セグメントはある程度の分数を占め、合計時間はすべてのセグメントの合計となります。 

攻撃が開始される前に、キングは最大で次の量を使用できます。$m$スクロールします。 各スクロールは 1 つのセグメントにのみ適用され、次から選択した値だけ高さが増加します。$1$に$c$。 同じセグメント上で複数のスクロールを使用することができ、すべての変更は攻撃が開始される前に行われます。 目標は、合計の破壊時間が最大化されるように、これらの増分を分散することです。 

この制約により、単純なシミュレーションは実行不可能になります。 まであります$10^5$セグメントと高さは最大になります$10^9$。 セグメントごとの除算プロセスの直接シミュレーションは、次のように除算を繰り返すため、十分に安価です。$k$値をすぐに減らして、おおよその値を与えます$O(\log_k h)$セグメントごとにステップが異なりますが、スクロールによって複雑さが生じます。 スクロールを配布するあらゆる方法をテストしたり、可能な増分をすべて試したりするソリューションは、実行可能な限界をはるかに超えています。 

セグメントが既に次の値で割り切れる場合には、微妙なエッジ ケースが発生します。$k$。 その場合、寄与時間はゼロとなり、わずかな増加でも動作が劇的に変化する可能性があります。 たとえば、次の場合$k=2$そして$h=4$、セグメントは即座に破壊されます。 増やすことで$1$それを作る$5$、複数の除算ステップが必要になります。 「身長が高いほうが常に悪い」という単純な貪欲さは、ここですぐに壊れます。 

もう 1 つの重要な例外ケースは、繰り返し除算がすぐにゼロに達する場合です。 たとえば、$k=10$、$h=3$の場合、最初のステップがすぐにゼロになるため、セグメントがゼロになるまでにちょうど 1 分かかります。 このような場合は、複数の部門レベルにわたって大きな値が維持される数値とは異なる動作をします。 

## アプローチ

 直接的な力ずくのアプローチでは、セグメントごとにモンスターのプロセスをシミュレートし、可能な限りのスクロールの分配を試みます。 整数の増分に制限したとしても、各スクロールには次のような特徴があります。$O(n)$選択肢、そして$m$スクロールは指数関数的な分岐構造を作成します。 これは明らかに不可能です。 

単一のセグメントを修正し、可能な限りすべての増分を試したとしても、$c$、各候補の破壊時間を再計算しても、最終的には次のようになります。$O(n \cdot c \cdot \log h)$、完全に範囲外です。 

重要な観察は、単一セグメントの破壊プロセスは、$k$。 各セグメントは短いチェーンに従います。$$h \rightarrow \lfloor h/k \rfloor \rightarrow \lfloor h/k^2 \rfloor \rightarrow \dots$$これらの値のいずれかが次の値で割り切れるとすぐにプロセスが停止します。$k$。 これは、時間の寄与がこのチェーンの最初のレベルによって決定されることを意味します。$k$が表示されます。 

この構造により、関数が区分的に安定します。つまり、小さな変化が生じます。$h$常に答えが変わるわけではありませんが、特定のしきい値を超えると、ステップ数が 1 つだけ変わります。 これにより、慎重に選択された増分によってセグメントの破壊時間が 1 ずつ増加する「イベント」の観点から考えることができます。 

スクロールをグローバルに配布する代わりに、スクロールのあらゆる潜在的な有益な使用を候補ゲインとして扱います。 各候補者には 1 つのスクロールのコストがかかり、合計時間がある程度増加します。 次に、利用可能な最良のゲインを繰り返し取得して適用し、そのゲインの元のセグメントを更新します。

 ## アルゴリズムのチュートリアル

 各セグメントの現在の高さを維持し、もう 1 つのスクロールを適用することでどれだけの利益を引き出せるかを繰り返し計算します。 

### 1. 固定高さの破壊時間を計算する

 価値のために$h$、プロセスをシミュレートします。 

繰り返し割ります$k$、現在の値が割り切れない場合は常に歩数をカウントします。$k$。 の倍数に着地した瞬間、$k$、プロセスが停止します。 

これにより、各セグメントのベースライン寄与が得られます。 

### 2. スクロールによって何が変わるのかを理解する

 スクロールすると高さが少し上がります$x \in [1, c]$。 この変更の影響は線形ではありません。 代わりに、商の順序をシフトします。$h, \lfloor h/k \rfloor, \lfloor h/k^2 \rfloor, \dots$、値が次の値で割り切れる最初のレベルを変更する場合があります。$k$。 この最初の変更により、合計時間が 1 単位増加します。 

したがって、各セグメントについては、その破壊時間を改善する最小の増分のみを考慮します。 

### 3. セグメントの次に役立つ増分を計算します。 

現在の値を持つセグメントの場合$h$、そのレベルを調べます。$h_0 = h, h_1 = h//k, h_2 = h//k^2, \dots$各レベルで$t$、値$h_t$まだ割り切れない場合に関連します$k$。 このレベルでさらに 1 分を強制したい場合は、増加させようとします。$h$となることによって$h_t$の次の倍数になります$k$。 

させて$u = k^t$。 それから$h_t = \lfloor h/u \rfloor$。 次の倍数が必要です。$$h_t' = \left(\left\lfloor \frac{h_t}{k} \right\rfloor + 1\right) \cdot k$$これはターゲットの高さに対応します。$$h' = h_t' \cdot u$$したがって、必要な増分は次のようになります。$x = h' - h$。 もし$x \le c$、これは有効なスクロール移動であり、ちょうど 1 分の追加時間が得られます。 

すべてのレベルにわたってそのような最良のゲインを計算します。 

### 4. スクロール用途の貪欲な選択

 単一のスクロールごとに達成可能な最高のゲインをキーとして、すべてのセグメントに対して優先キューを維持します。 各エントリにはセグメント インデックスと最良の増分が保存されます。$x$それは貢献度を高めます。 

各ステップで、最大のゲインを持つセグメントを抽出し、増分を適用し、その高さを更新し、次に最適なゲインを再計算して、それを押し戻します。 

これにより、すべてのスクロールが、合計時間の最大の即時増加をもたらす場所で使用されるようになります。 

### 5. なぜ効果があるのか

 重要な不変条件は、すべてのスクロールが個別の改善イベントに対応し、合計破壊時間がちょうど 1 単位増加することです。 より大きなジャンプは複数のユニット改善に分解でき、それぞれが次の累乗で表される分割しきい値の 1 つを超えることに対応します。$k$。 各スクロールは独立しており、コストは同じであるため、現在利用可能な最大の限界ゲインを常に選択することで最適性が維持されます。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

def base_time(h, k):
    t = 0
    while h % k != 0:
        if h == 0:
            return t
        h //= k
        t += 1
    return t

def best_gain(h, k, c):
    if h == 0:
        return (0, 0)
    best_x = 0
    best_inc = 0

    # try all levels h / k^t
    u = 1
    x = h
    while u <= h:
        x = h // u
        if x == 0:
            break

        if x % k != 0:
            # move x to next multiple of k
            nxt = ((x // k) + 1) * k
            target = nxt * u
            inc = target - h
            if 1 <= inc <= c:
                if inc > best_inc:
                    best_inc = inc
                    best_x = inc

        u *= k

    return (best_inc, best_inc)

def compute_time(h, k):
    t = 0
    while True:
        if h % k == 0:
            return t
        h //= k
        t += 1

n, k = map(int, input().split())
h = list(map(int, input().split()))
m, c = map(int, input().split())

heap = []
cur = h[:]
total = 0

for i in range(n):
    total += compute_time(cur[i], k)
    gain, inc = best_gain(cur[i], k, c)
    heapq.heappush(heap, (-gain, i, inc))

for _ in range(m):
    gain, i, inc = heapq.heappop(heap)
    gain = -gain
    if gain == 0:
        break
    cur[i] += inc
    total += gain
    new_gain, new_inc = best_gain(cur[i], k, c)
    heapq.heappush(heap, (-new_gain, i, new_inc))

print(total)
```実装では 2 つの責任が分離されます。 1 つ目は、分割可能な状態が現れるまで繰り返し分割を使用して、セグメントの破壊時間を計算することです。 2 つ目は、すべての商レベルを調べて、最適な単一スクロール効果を検索することです。$h // k^t$。 各レベルは最大 1 つの候補増分を生成します。これは、商を次の倍数にスナップすることによって導出されます。$k$。 

ヒープにより、最も価値のあるスクロールが常に最初に適用されます。 セグメントが更新されるたびに、将来のゲインが変化するため、再挿入する前に最適な候補を再計算します。 

主な微妙な点は、レベルの検索を制限することです。 各乗算$k$商レベルが 1 つ上がります。$h \le 10^9$、このループは短く、安全に境界が定められています。

 ## 特殊なケース

 エッジ ケースの 1 つは、セグメントが既に次の要素で割り切れる場合です。$k$。 その状況では、すぐに破壊されるため、基本貢献度はゼロになります。 ただし、少しずつ増やすと最上位レベルでの割り算がなくなり、複数の割り算ステップが導入される可能性があります。 最良ゲインの計算ではより高い商レベルを明示的にチェックし、割り切れない状態に入る有効な増分がヒープ内の候補となるため、アルゴリズムはこれを正しく処理します。 

除算を繰り返すとすぐにゼロになってしまう別のケースが発生します。 小さな値の場合、次のような$h < k$、次の場合を除き、プロセスは常に 1 つのステップを実行します。$h = 0$。 商チェーンはほぼ即座に停止し、ゲインを計算する際に考慮すべきレベルがほとんどないため、アルゴリズムはこれを自然に処理します。そのため、特別な処理は必要ありません。
