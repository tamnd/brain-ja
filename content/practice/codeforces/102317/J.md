 ## 問題の理解

 グリッドで表された長方形の洞窟があります。 各セルには、時間 0 における海からの天井の高さが含まれています。 カヌーは北西のセルから出発し、横に隣接するセル間のみを移動して南東のセルに到達する必要があります。 

海面は 1 秒ごとに 1 ミリメートルずつ上昇します。 カヌーが時刻にセルに入った場合`t`、初期の天井高は`a`、残りの天井高は`a - t`。 セルは、この値が厳密に正の場合にのみ有効です。 目標は移動時間を最小限にすることではありません。 代わりに、すべての可能なパスの中で、そのパスに沿って発生する残りの最小天井高の可能な最大値が必要です。 必要な出力は、その最大最小高さ、または`impossible`有効なパスが存在しない場合。 オリジナルのコンテストのアーカイブでは、`1 <= r,c <= 500`までの高さ`10^9`。 

せいぜい`500 * 500 = 250000`セルでは、グリッドを一定の回数だけ検査するアルゴリズムが理想的です。 平`O(rc log 10^9)`対数係数はわずか約 30 であるため、これは合理的です。`O((rc)^2)`このメソッドにはすでに約が必要です`6.25 * 10^10`最大の洞窟での細胞作戦は、数秒の許容範囲をはるかに超えています。 

一見合理的に見える実装が間違った答えを与える、いくつかのエッジケースがあります。 まず、開始セルは時間 0 で入力されるため、1 セルの洞窟では移動する必要がありません。 のために```
1
1 1
7
```答えは`7`。 少なくとも 1 つの手を想定する実装、または答えをゼロから開始する実装では、これが間違っている可能性があります。 

2 番目の問題は、厳密な陽性条件です。 セルに入るとき、ちょうどゼロの上限は許可されません。 のために```
1
1 3
3 1 3
```唯一のルートは時間 1 で中央のセルに入り、残りの高さを与えます。`1 - 1 = 0`。 正しい出力は次のとおりです`impossible`。 を使用した小切手`>= 0`の代わりに`> 0`パスを誤って受け入れてしまいます。 

3 番目の問題は、最適なパスは幾何学的に最短のルートである必要はないということです。 考慮する```
1
2 3
10 2 10
10 10 10
```直接最上行ルートは高さのセルに入ります`2`時刻 1 では無効です。 有効なルートは最初に下に進み、次に一番下の行を横切ります。 残りの高さは`10, 9, 8, 7`、したがって、答えは次のとおりです`7`。 マンハッタンの最短ルートだけを確認する方法では、有効な迂回路を見逃してしまいます。 

サンプル自体は、同じ現象をより微妙に示しています。 最初の洞窟では最低限のクリアランスを保ちながら目的地に到達`3`低いセルを迂回し、より長いルートを受け入れる必要があります。 

## アプローチ

 最も直接的な総当りの解決策は、北西の角から南東の角までの可能な単純なパスをすべて列挙することです。 各パスについて、すべてのセルが入力された正確な時間がわかっているので、計算することができます。`a[cell] - time`すべてのセルに対して最小値を維持します。 すべてのパスの最大値を取ると、必要な答えが正確に得られます。 

問題はパスの数です。 単純なパス検索では、最初の移動の後、すぐに前のセルに戻る必要がないため、後続の各ステップで最大 3 つの選択肢が存在する可能性があります。 と`N = rc`検索ツリーに含めることができるセルの数は次のとおりです。`3^N`候補者が歩く。 大雑把な上限さえも`3^(N-1)`天文学的に大きい`N = 250000`。 ブルートフォースはあらゆる可能性を考慮するため正しいですが、指数関数的な検索スペースにより使用できなくなります。 

より有益な観察は、パスの最適化をやめて、代わりに「はい」か「いいえ」で答える質問をすることです。「少なくとも次の最小クリアランスを達成できるか」`K`?

 目標の最小クリアランスが`K`。 ある時点でセルに入ると`t`、そのセルはまさに次の場合に受け入れられます`a[cell] - t >= K`。 

固定の場合`K`、これは問題を到達可能性の問題に変えます。 最初から BFS を実行できます。 BFS はできるだけ早くすべてのセルに到着します。海面が低いため、早く到着する方が常に良いことになります。 ある時点でセルに到達できる場合`t`、その後同じセルに到達しても、その後の移動が容易になることはありません。 

これにより、簡単な実現可能性テストが行​​われます。`O(rc)`。 述語は単調です: パスが最小クリアランスを維持できる場合`K`の場合、同じパスでより小さなクリアランスを確実に維持できます。 その結果、実行可能な最大の二分探索が可能になります。`K`。 

ブルート フォースはすべてのパスを直接評価するため機能しますが、パスが指数関数的に多いため失敗します。 固定された最小クリアランスが問題を最早到着到達可能性に変換するという観察により、パス列挙を BFS に置き換えることができ、その実現可能性テストの単調性により、最適化は二分探索に削減されます。

 ## アルゴリズムのチュートリアル

 1. 回答候補を扱う`K`必要な最低残り天井高として。 時刻に入力されたセル`t`この候補者に使用できるのは、まさに次の場合です`a[cell] - t >= K`。 
2. 北西セルから BFS を実行します。 BFS レベルは経過時間を表すため、すべてのセルがこのレベルでキューから削除されます。`t`ちょうどその後に到達しました`t`秒。 
3. 時間から隣人を考慮する場合`t`、時間通りに入力したふりをします`t + 1`。 次の場合にのみキューに入れます。`a[neighbor] - (t + 1) >= K`。 これにより、潮の状態と必要な最小クリアランスが同時にチェックされます。 
4. 最初に到達した各セルにマークを付けます。 BFS は、この最初の到着が可能な限り最も早い到着であることを保証します。 同じセルに後から到着することは役に立ちません。将来の天井は後の時点で小さくなるからです。 
5. BFS が南東のセルに到達すると、`K`実現可能です。 BFS が到達可能なセルに到達せずに使い果たす場合、`K`不可能です。 
6. 実現可能性は単調なので二分探索`K`。 から開始`1`有効なパスには厳密に正のクリアランスが必要であるため、次を使用します。`min(a[start], a[target])`安全な上限として。 もし`K = 1`実行不可能です。印刷してください`impossible`。 
7. 二分探索中は、実行可能な最大値を保持します。 中間点が実現可能な場合は、より高い位置を検索します。 それ以外の場合は、下位を検索します。 

なぜ機能するのか: 固定のため`K`、BFS は、訪問されたすべてのセルが開始からの有効なパスを持ち、入力されたすべてのセルが少なくとも残りの高さを持っているという不変条件を維持します。`K`。 BFS は可能な限り早い時間に各セルを検出するため、後でそのセルに到達する代替パスによって状況が緩和されることはありません。 したがって、BFS は、必要なクリアランスを満たすパスが存在するときに正確に宛先に到達します。 実現可能な値は、`K`は正の整数のプレフィックスを形成するため、二分探索では実行可能な最大のクリアランスが返されます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve_case(r, c, grid):
    width = c + 2
    height = r + 2
    total = width * height

    # Pad the grid with zeroes. Since every tested K is at least 1,
    # the padding can never be entered.
    a = [0] * total
    max_height = 0

    for i in range(r):
        base = (i + 1) * width + 1
        row = grid[i]
        for j, x in enumerate(row):
            a[base + j] = x
            if x > max_height:
                max_height = x

    start = width + 1
    target = r * width + c

    def feasible(k):
        if a[start] < k:
            return False

        seen = bytearray(total)
        seen[start] = 1

        q = deque([start])
        time = 0

        while q:
            time += 1
            next_time = time

            for _ in range(len(q)):
                v = q.popleft()

                # Four neighboring cells in the padded grid.
                for nv in (v - 1, v + 1, v - width, v + width):
                    if seen[nv]:
                        continue

                    if a[nv] - next_time < k:
                        continue

                    if nv == target:
                        return True

                    seen[nv] = 1
                    q.append(nv)

        return start == target

    # A valid path must have strictly positive minimum clearance.
    if not feasible(1):
        return "impossible"

    lo = 1
    hi = min(a[start], a[target])
    answer = 1

    while lo <= hi:
        mid = (lo + hi) // 2

        if feasible(mid):
            answer = mid
            lo = mid + 1
        else:
            hi = mid - 1

    return str(answer)

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        r, c = map(int, input().split())
        grid = [list(map(int, input().split())) for _ in range(r)]
        out.append(solve_case(r, c, grid))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```グリッドにはゼロの境界線が埋め込まれます。 すべての二分探索しきい値は少なくとも`1`, したがって、それらの人工細胞は決して条件を満たすことができません。 これにより、BFS 内での個別の行と列の境界チェックが回避され、各拡張が単純に 4 つのインデックス追加になります。 

BFS は、すべてのセルの明示的な距離を保存しません。 代わりに、キューを一度に 1 レベルずつ処理すると、現在時刻が直接得られます。 キューにその後に到達したセルが含まれている場合`time - 1`数秒後に、すべての近隣者が入力されます。`time`秒。 

の`seen`配列は`bytearray`これは、Python のブール値や整数のリストよりもはるかにメモリ効率が高くなります。 各セルは、特定の実現可能性チェックのために最大 1 回 BFS キューに挿入されます。 

条件は以下を使用します`a[nv] - next_time < k`拒否のため。 同等に受け入れます`a[nv] - next_time >= k`。 二分探索は次から始まるので、`1`、これにより、元の厳密な正の高さの要件が自動的に適用されます。 

ターゲットが検出されたときに早期に復帰すると、BFS の残りの部分が節約されます。 開始セルは時間 1 ではなく時間 0 に入力されるため、個別に処理されます。 

浮動小数点演算は使用されません。 到達できる高さ`10^9`ただし、Python の整数には任意の精度があるため、オーバーフローの心配はありません。
