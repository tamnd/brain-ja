 ## 解決策
 ## 問題の理解

 私たちにはいくつかの保護ミッションがあります。 あるミッション中、既知の一連のブラスターショットが指定された時間にジェダイに届きます。 資産を守るジェダイは 1 人または 2 人で、各ジェダイには独自の反応時間があります。 ジェダイは、自分に割り当てられた最初のショットをいつでもブロックできます。 シュートをブロックした後`t`、その同じジェダイは時間まで別のショットをブロックすることはできません`t + reaction_time`。 

ショット時間は任意の順序で指定できるため、最初のステップは時系列に並べ替えることです。 ショットごとに、どちらのジェダイがそれをブロックできるかどうかを決定したいと考えています。 必要な出力は、保護された資産に到達するショットの最小数です。 コンテストの公式声明では、ミッションごとに最大 1000 発のショット、1 人または 2 人のジェダイ、および 1 ～ 100 の反応時間と規定されています。 

ショット数が 1000 回という小さい限界は、二次アルゴリズムでも 1 つのミッションには実用的であることを意味しますが、問題の実際の構造により、より適切な処理が可能になります。 考えられるすべての割り当てを総当りで検索すると、ショットごとに 3 つの選択肢があるため、最悪のケースは次のようになります。`3^b`課題。 と`b = 1000`、それはコンテストの制限時間をはるかに超えています。 有用なソリューションは、ソート後にショットを処理し、ショットごとに一定の作業のみを行う必要があります。 

実装が静かに失敗する可能性があるいくつかのエッジケースがあります。 まず、等しいショット時間は別個のショットであり、異なるジェダイがまったく同時に到着する異なるショットをブロックする可能性があります。 たとえば、```
1
2
5 5
2
1 10
```両方のジェダイがタイム 5 で 2 発のうち 1 発をブロックできるため、答えは次のようになります。`0`。 重複する時間を削除する不注意な実装により、誤ったレポートが発生します。`1`。 

2 番目のエッジ ケースは、両方が利用可能な場合、ジェダイは同じ戦略を使用する必要がないことです。 考慮する```
1
3
1 2 3
2
2 100
```反応時間 2 のジェダイは 3 発すべてをブロックできるため、答えは次のようになります。`0`。 ジェダイも利用可能であるという理由だけで最初のショットを遅いジェダイに割り当てる実装は、この入力でも機能しますが、より慎重に構築されたシーケンスでは選択が重要になります。 正しいルールは、両方が利用可能な場合は常に、反応時間が短いジェダイを優先することです。 

3 番目の境界ケースは、ジェダイが準備ができたときにちょうどショットが到着したときに発生します。 例えば、```
1
3
1 3 5
1
2
```同時にショットを打つため、3 つのショットすべてをブロックできます。`3`時間のショット後に許可されます`1`、そしてその時のショット`5`時間が経っても同様に許可されます`3`。 使用する`>`の代わりに`>=`可用性をチェックすると、誤ってショットがブロックされないままになってしまうことがありました。 

## アプローチ

 直接的な総当たりアプローチは、すべてのショットに対してあらゆる可能な決定を考慮することです。 ショットを並べ替えた後、各ショットをジェダイ 1 に割り当てるか、ジェダイ 2 に割り当てるか、またはスルーを許可することができます。 各ジェダイによってブロックされた最後のショットを維持しながら、反応時間の制約に違反する割り当てを拒否しながら、これらの可能性を再帰的に列挙することができます。 この方法は正しいです。すべての正当なブロッキング戦略が再帰のどこかに現れるため、ミスショットが最も少ない戦略を採用することで最適な結果が得られます。 

問題は、考えられる戦略の数です。 と`b`までのショットがあります`3^b`決定シーケンス。 最大 1000 ショットの場合、これは約`10^477`, そのため、個別の戦略を確認するのは安価ですが、総当たりは使用できません。 

重要な観察は、ショットを時系列に処理するということです。 現在、両方のジェダイが同時にショットをブロックできると仮定します。`t`。 彼らの反応時間を次のようにしましょう`a <= b`。 反応時間のあるジェダイにショットを与えた場合`a`、ジェダイは再び利用可能になります`t + a`、他のジェダイは引き続き利用可能です`t`。 したがって、将来の 2 つの利用可能時間は次のようになります。`{t, t + a}`。 

代わりに、より遅いジェダイにショットを与えると、将来の利用可能時間は次のようになります。`{t, t + b}`。 以来`a <= b`、最初のペアは、今後のショットにとって決して悪くありません。 私たちは 1 人のジェダイをすぐに利用できるように保存し、もう 1 人は代替割り当てが開始されるまでに利用できるようにしました。 

これにより貪欲なルールが得られます。 ショットごとに、ジェダイが 1 人しかいない場合、そのジェダイがショットをブロックしなければなりません。 両方が利用可能な場合は、反応時間が短い Jedi を使用してください。 どちらも利用できない場合、ショットはブロックされず、アセットに到達する必要があります。 

このローカルな選択が安全である理由は、単に速いジェダイが「優れている」と言うよりも強力です。 両方が空いているときに高速な Jedi を使用すると、次に利用可能になる 2 つの時間がコンポーネント的に遅い Jedi を使用して生成される状態よりも遅くない状態が生成されます。 遅いジェダイを選択した後に処理できる将来のシーケンスは、より速いジェダイを選択した後にも処理できます。 したがって、貪欲な決定によって、ブロックできるショットの最大数が減少することはありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(3^b)`|`O(b)`再帰 | 遅すぎる |
 | 最適 |`O(b log b)`|`O(1)`並べ替えとは別に | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ショット時間を読み取り、減少しない順に並べ替えます。 ジェダイが利用できるかどうかは、ジェダイがすでにブロックしたショットのみに依存するため、時間的な処理が必要です。 
2. 各ジェダイがショットをブロックできる次回の時間を保存します。 各ジェダイは最初のショットを即座にブロックできるため、最初は両方の値が負の無限大、またはすべての可能なショット時間よりも小さい値と同等です。 
3. 撮影時間ごとに`t`、次に利用可能な時間が最大かどうかを確認して、どのジェダイが現在利用可能であるかを判断します。`t`。 ジェダイは反応時間が経過したときに正確にショットをブロックする可能性があるため、平等は利用可能であるとみなされます。 
4. どちらのジェダイも利用できない場合は、アセットに到達するショットの数を増やします。 このショットには法的な割り当てはなく、ショットは時系列に処理されるため、これをスキップしても、利用できないジェダイをより早く利用できるようにすることはできません。 
5. 利用可能なジェダイが 1 人だけの場合は、そのジェダイにショットを割り当てます。 利用できないジェダイを使用すると反応時間の制限に違反するため、選択は強制されます。 
6. 両方のジェダイが利用可能な場合は、反応時間の短い方のジェダイにショットを割り当てます。 割り当て後、そのジェダイが次に利用できる時間を次のように設定します。`t + reaction_time`。 
7. すべてのショットが処理された後、必要なミッション形式でブロックできなかったショットの数を出力します。 

不変条件は、ソートされたショット シーケンスのすべてのプレフィックスを処理した後、貪欲戦略がそのプレフィックスからのショットの最大可能数をブロックしており、その最大数を達成する戦略の中で、その 2 つの次回利用可能時間は代替戦略の時間より悪くないということです。 両方のジェダイが利用可能な場合、高速なジェダイを使用すると、低速なジェダイが完全に保存され、低速なジェダイを使用するよりも早く使用済みのジェダイが使用できるようになります。 使用可能なものが 1 つだけの場合、割り当ては強制的に行われます。 どちらも利用できない場合、どの戦略も現在のショットをブロックできません。 これらの事実により、すべてのショットに対して不変条件が維持されるため、最終的なミスショットの数は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    missions = int(input())
    out = []

    for mission in range(1, missions + 1):
        b = int(input())
        shots = list(map(int, input().split()))
        shots.sort()

        j = int(input())
        reaction = list(map(int, input().split()))

        # next_available[k] is the earliest time Jedi k can block again.
        # Negative infinity means that Jedi has not blocked anything yet.
        next_available = [-1] * j

        missed = 0

        for t in shots:
            available = [
                k for k in range(j)
                if next_available[k] <= t
            ]

            if not available:
                missed += 1
                continue

            if len(available) == 1:
                k = available[0]
            else:
                # Both are available. Use the Jedi who recovers sooner.
                if reaction[available[0]] <= reaction[available[1]]:
                    k = available[0]
                else:
                    k = available[1]

            next_available[k] = t + reaction[k]

        out.append(f"Mission #{mission}: {missed}")
        out.append("")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力セクションではミッションの数を読み取り、続いて各ミッションのショットの数と回数を読み取ります。 ショット リストは、アルゴリズムの最初のステップに合わせて、スケジューリングの決定が行われる前に並べ替えられます。`next_available[k]`ジェダイの最も古い時刻を保存します。`k`別のショットをブロックする可能性があります。 初期値`-1`すべてのショット時間が正であるため、これで十分です。 ジェダイが銃撃を阻止した後、`t`、次の法定時刻は正確に`t + reaction[k]`。 

リスト`available`次に利用可能な時間が現在のショット時間以下であるジェダイが含まれます。 の`<=`比較は、ショットが到着したときに反応間隔が正確に終了する境界ケースを処理します。 

両方のジェダイが利用可能な場合、それらの反応時間を比較すると、貪欲な交換の議論が実装されます。 反応時間が等しい場合、どちらの選択も同等であるため、`<=`ブランチは最初のものを安全に選択できます。 

ショット時間が重複しても特別な処理は必要ありません。 それらは一度に 1 つずつ処理されるため、2 人のジェダイが利用できる場合、同時に 2 つのショットは別のジェダイによってブロックされる可能性があります。 ジェダイがそれらの 1 つをブロックした後、反応時間はプラスであるため、次に利用できる時間は厳密に遅くなります。 

Python の整数には任意の精度があるため、`t + reaction[k]`計算がオーバーフローすることはできません。
