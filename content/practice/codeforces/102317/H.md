 ## 問題の理解

 最大 (p) 個の整数のリストがあり、順序付けされた位置のペア ((i,j)) がすべて候補になります。 このペアは、(A_i) が (A_j) の適切な約数である場合、つまり (A_j) が (A_i) の整数倍であるが、2 つの値が等しくない場合にカウントされます。 値が複数回出現する場合でも、同じ値が適切な分割ペアを形成することはありません。 入力値の範囲は (0) から (10^7) ですが、(p) は (10^6) に達することがあります。 公式声明では、ゼロに関する特別な規則も与えられています。ゼロでは何も除算されませんが、ゼロ以外の整数はすべてゼロの適切な約数です。 

出力は、その条件を満たす順序付けされたインデックス ペアの数です。 多重度が重要であるため、値 (2) が 3 回出現し、(6) が 2 回出現した場合、それらの出現は、除数 (2) と被除数 (6) のペア (3\cdot2=6) に寄与します。 正式なフォーマットは`Test case #t: m`、その後に空行が続きます。 

主な制約により、解の形状が変化します。 (p=10^6) の場合、すべての順序ペアをチェックするには、最悪の場合、(10^{12}) 個の割り切りテストが必要になりますが、これは 5 秒の制限をはるかに超えています。 ただし、値は (10^7) によってのみ制限されており、その制限された値の範囲はまさにペアの列挙を倍数ふるいに置き換えることを可能にします。 コンテストでは 5 秒と 256 MB が与えられるため、意図したアプローチではペアの数ではなく値の限界を利用する必要があります。 

合理的な実装を静かに破壊する可能性のあるエッジケースがいくつかあります。

```答えは`0`。 (1) は (1) を除算しますが、適切な約数は除算する数とは異なる必要があります。 チェックのみを行うソリューション`N % D == 0`両方の順序ペアを誤ってカウントしてしまいます。

## アプローチ

 直接的なアプローチは、順序付けされたポジションのペアをすべて検査することです。 各ペア ((i,j)) について、(A_i) がゼロ以外かどうか、(A_i\neq A_j) かどうか、および (A_j) が (A_i) で割り切れるかどうかを確認します。 これは、考えられるすべてのペアに定義を直接適用するため、正しいです。 問題は (O(p^2)) 個のチェック数です。 (p=10^6) では、最悪のケースには (10^{12}) 個の順序ペアが含まれるため、非常に安価な割り算テストであっても、このアプローチを実行可能にすることはできません。 

有益な観察は、条件が位置ではなく値のみに依存するということです。 正の値 (d) が (freq[d]) 回発生すると仮定します。 入力内で発生するすべての正の倍数 (2d、3d、\ldots) がその被除数になる可能性があります。 (m) がそのような倍数である場合、(d) のすべての出現は (m) のすべての出現とペアになり、寄与します。 

[
 周波数[d]\cdot周波数[m]。 
】

 除数値 (d) を固定し、その倍数を調べることで、これらの寄与をカウントできます。 等価性は禁止されているため、値 (d) 自体は意図的にスキップされます。 

ゼロは個別に処理できます。 すべての正の入力値はゼロの適切な約数であるため、次の場合`zero_count`はゼロの数であり、`positive_count`は正の要素の数です。ゼロは正確に寄与します

 [

】

 ゼロ自体は約数として何も寄与しません。 

ブルートフォース手法は、すべてのペアを明示的に考慮するため機能しますが、ペアが多すぎるため失敗します。 固定された正の約数のすべての可能な被除数はその倍数であるという観察により、最初に等しい値を集計し、有界値領域にわたる割り切れる関係を列挙できます。

 ここで (M) は、テスト ケースに実際に現れる最大値です。 (p\le10^6) であるため、実際には最大で (10^6) 個の異なる正の値が発生する可能性があるため、訪問倍数の数は理論上の (M\log M) 限界よりも大幅に小さいことがよくあります。 

## アルゴリズムのチュートリアル

 1. (p) 値を読み取り、最大値 (M) を見つけます。 (M) までの周波数情報だけが必要なので、実際の最大値が小さい場合には、固定上限 (10^7) までのスペースを割り当てる必要はありません。 
2. 周波数配列を構築する`freq`、 どこ`freq[x]`値 (x) の出現数です。 アルゴリズムは正確な倍数で周波数に繰り返しアクセスし、値の範囲が制限されているため、辞書よりも配列の方が適しています。 
3. ゼロを個別に数えます。 有効なペアではゼロが約数になることはありませんが、すべての正の値がすべてのゼロの約数になる可能性があります。 
4. 答えを次のように初期化します。`positive_count * zero_count`。 これは、配当がゼロで除数が正であるすべてのペアを考慮します。 
5. 入力で発生するすべての正の値 (d) について、次の手順を実行します。`2*d, 3*d, ...`一方、倍数は最大 (M) です。 これらはまさに (d) が除算する正の値であり、(d) とは異なります。 
6. 倍数 (m) ごとに、`freq[d] * freq[m]`答えに。 最初の要素は除数の出現を選択し、2 番目の要素は被除数の出現を選択します。 から始まる`2*d`それよりも`d`等しい値は自動的に除外されます。 
7. 蓄積された回答を必要なテストケース形式で出力し、必要な空白行を追加します。 

重要な不変条件は、除数値 (d) を処理した後、除数値が (d) で被除数が正であるすべての有効なペアが 1 回だけカウントされていることです。 外側のループが (d) に達するとカウントされます。これは、すべての正の割り切れる値が倍数ループに出現し、2 つの頻度の積がそれらの出現のすべての組み合わせをカウントするためです。 倍数ループは (2d) から始まるため、等しい値を持つペアはカウントされません。また、外側のループは (1) から始まるため、除数としてゼロを含むペアはカウントされません。 個別のゼロ寄与は、ゼロを含む残りのすべての有効なペアを説明します。 

## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

def solve_case(a):
    n = len(a)
    mx = max(a)

    zero_count = 0
    for x in a:
        if x == 0:
            zero_count += 1

    positive_count = n - zero_count

    # An unsigned 32-bit integer is enough because n <= 10^6.
    freq = array('I', [0]) * (mx + 1)

    for x in a:
        freq[x] += 1

    # Every positive number is a proper divisor of zero.
    ans = positive_count * zero_count

    # For each divisor d, inspect only its proper positive multiples.
    for d in range(1, mx + 1):
        cd = freq[d]
        if cd == 0:
            continue

        for m in range(d + d, mx + 1, d):
            cm = freq[m]
            if cm:
                ans += cd * cm

    return ans

def main():
    t = int(input())
    out = []

    for tc in range(1, t + 1):
        p = int(input())

        a = []
        while len(a) < p:
            a.extend(map(int, input().split()))

        ans = solve_case(a)
        out.append(f"Test case #{tc}: {ans}")
        out.append("")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```の`solve_case`関数は最初に実際の最大値を決定し、周波数配列を可能な限り小さく保ちます。 すべての周波数が最大 (10^6) であるため、最大 (10^7) の符号なし 32 ビット エントリで十分です。 の`array`モジュールを使用すると、数百万の Python 整数オブジェクトを保存するためのはるかに大きなメモリ コストが回避されます。 

ゼロ寄与は倍数ループの前に計算されます。 あれば`positive_count`ポジティブな要素と`zero_count`ゼロの場合、すべての正の要素が除数の位置を占めることができ、すべてのゼロが被除数の位置を占めることができ、デカルト積を生成します。 

メインループは次から始まります`d + d`。 この単一の境界の選択により、別個の等価性チェックを必要とせずに、適切な除数の制限が処理されます。 から開始`d`そして追加`freq[d] * freq[d]`等しい値は適切な分割ペアではないため、これは間違っています。 

乗算には Python の整数が使用されるため、オーバーフローの問題はありません。 固定幅の整数を使用する言語では、有効な順序ペアの数が (p^2) 程度になり、(10^{12}) に達する可能性があるため、64 ビット型が必要です。 

入力リーダーでは、公式形式では 1 行として (p) 値が表示されている場合でも、(p) 値が複数の物理行にまたがることができます。 これにより、アルゴリズムを変更せずにパーサーが堅牢になります。
