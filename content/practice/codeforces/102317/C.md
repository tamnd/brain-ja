 ## 解決策
 ## 問題の理解

 サイズ (n \times n) の正方形のボードがあり、最初は氷のブロックで満たされています。 戦略は、特定の細胞をノックアウトする (m) つの試みから構成されます。 先に直接ノックアウトされたか、カスケードの一部として落ちたために、その位置のブロックがすでに消滅している場合、その試みは無効です。 

ブロックの行全体がまだ無傷であるか、列全体がまだ無傷である場合、ブロックはサポートされたままになります。 行からブロックが削除されると、その行は完全ではなくなります。 同様に、列からブロックを削除すると、その列は不完全になります。 行と列の両方が不完全なブロックは落下し、落下するとさらにブロックが消失する可能性があります。 必要な出力は、各ボードの無効な試行の数です。 元のコンテストには、要求された出力形式の (1 \le n \le 50) と (1 \le m \le 100) が含まれています。`Strategy #b: i`。 

制約の重要な結果は、最大のボードには (2500) 個のセルしかなく、最大でも (100) の手しかないため、単純な (O(mn^2)) シミュレーションでも簡単に十分に小さくなるということです。 ただし、落下プロセスの構造により、さらに優れた作業が可能になります。 すべての (n^2) 個のセルを個別に管理する必要はありません。 

不用意に実装すると見逃される可能性のあるエッジケースがいくつかあります。 1つ目は、まったく同じ動きを繰り返すことです。 例えば、```
1
1 2
1 1
1 1
```出力があります```
Strategy #1: 1
```最初の試行では、唯一のブロックが削除されます。 そのブロックはすでになくなっているため、2 回目の試行は無効です。 直接ノックアウトされたセルのみを記憶する実装はこのケースを処理できますが、間接的に消滅したブロックも正しく処理する必要があります。 

さらに興味深いケースは、行はすでに分割されているが、列はまだ分割されていない場合です。 例えば、```
1
2 3
1 1
1 2
2 1
```出力があります```
Strategy #1: 1
```取り外し後`(1,1)`、行 1 と列 1 が不完全です。 細胞`(1,2)`列 2 はまだ完了しているため、存続します。 削除中`(1,2)`次に列 2 を分割します。最後の試み`(2,1)`行 2 と列 1 の両方が不完全であるため、これは無効です。 よくある間違いは、タッチされた行全体を使用不可として扱うことです。これにより、誤ってマークが付けられてしまいます。`(1,2)`無効。 

境界ケース (n=1) も注目に値します。 のために```
1
1 1
1 1
```出力は```
Strategy #1: 0
```唯一の動きは有効です。 ここでは行と列の区別はなく、行と列の両方が最初から完了しているため、ブロックはサポートされます。 

## アプローチ

 直接シミュレーションではすべてのセルを表現し、移動後にボードを繰り返し検査できます。 ブロックが欠落している場合は、その行が完了しているか、列が完了しているかを確認します。 どちらも完了していない場合、ブロックは落下し、ブロックが消えなくなるまでプロセスを繰り返します。 これは文字通りボードの物理的なルールに従っているので正しいです。 

この実装の問題は、不必要な繰り返し作業です。 すべての移動後にすべての (n^2) 個のセルをスキャンし、ボードの変更が停止するまで完全なスキャンを続ける単純な実装では、1 回の移動に対して (O(n^2)) 回のスキャンが必要となり、スキャンごとに (O(n^2)) 回の作業が必要になります。 (m) 回移動すると、これは (O(mn^4)) になります。 最大の制約では、(100 \cdot 50^4 = 625{,}000{,}000) 個のセル チェックが行われますが、これは 1 秒のコンテスト問題としては不必要に大きくなります。 

すべてのセルの状態は行と列が完了しているかどうかによって決定されるため、総当たりアプローチが機能します。 この観察により、ボードの状態の大部分を破棄できます。 

での移動が成功した直後に何が起こるかを考えてみましょう。`(r,c)`。 行 (r) はもはや完了しておらず、列 (c) も完了していません。 この時点から、ブロックは消滅するだけなので、どちらも再び完全になることはありません。 次に任意のセルを考えてみましょう`(x,y)`。 少なくとも 1 つの次元が完全なままであれば、それは存続します。 行 (x) が一度も分割されていない場合は、行全体がまだ存在します。 列 (y) が一度も壊れていない場合は、列全体がまだ存在します。 すでに両方が壊れている場合は、`(x,y)`落ちたに違いない。 

これは、カスケード全体を 2 つのブール配列のみを使用して表現できることを意味します。`broken_row[r]`その行は言う`r`不完全なものになってしまい、`broken_col[c]`列にも同じことが言えます`c`。 

要求されたセル`(r,c)`正確に言うとまだ存在します`broken_row[r]`または`broken_col[c]`は誤りです。 したがって、両方のフラグがすでに true の場合、試行された移動は無効になります。 移動が有効な場合、その行と列は壊れているとマークされます。 2 つの壊れた次元の交点にあるすべてのセルは消失していることがすでにわかっているため、個別のカスケード シミュレーションはありません。

 | --- | --- | --- | --- |
 | ブルートフォース | (O(mn^4)) | (O(n^2)) | 最悪の場合は遅すぎる |
 | 最適 | (O(m+n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.作成`broken_row`そして`broken_col`、最初はすべての行と列に対して false です。 最初は、すべての行と列にすべての氷ブロックが含まれているため、すべてのセルが存在します。 
2. 試行された各位置を読み取ります`(r,c)`それをゼロベースのインデックスに変換します。 かどうかを確認してください`broken_row[r]`そして`broken_col[c]`どちらも真実です。 
3. 両方のフラグが true の場合、無効移動カウンタをインクリメントします。 細胞は 2 つの不完全な次元の交差点にあるため、すでに落下しているはずです。 
4. それ以外の場合、次のブロック`(r,c)`はまだ存在するため、移動は有効です。 マーク`broken_row[r]`そして`broken_col[c]`本当のように。 ボードはブロックを失うだけなので、これらのディメンションは再び完全になることはありません。 
5. すべての移動後、必要な戦略番号を使用して無効な試行の数を出力します。 

### なぜ効果があるのか

 不変条件は、移動の接頭辞を処理した後、セルが`(r,c)`行の場合にのみ存在します`r`まだ完成しているか、コラムです`c`まだ完成しています。 最初は両方の条件がすべてのセルに当てはまります。 有効な移動が削除されたとき`(r,c)`、その行と列は不完全になります。 行と列の両方が不完全なセルはすべて落ちなければなりませんが、少なくとも 1 つの完全な次元を持つすべてのセルはサポートされたままになります。 ディメンションは再び完全になることはできないため、2 つのブール配列はすべての移動後のボードを正確に表します。 したがって、行と列の両方が壊れているとマークされている場合、移動は無効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        n, m = map(int, input().split())

        broken_row = [False] * n
        broken_col = [False] * n

        invalid = 0

        for _ in range(m):
            r, c = map(int, input().split())
            r -= 1
            c -= 1

            if broken_row[r] and broken_col[c]:
                invalid += 1
            else:
                broken_row[r] = True
                broken_col[c] = True

        out.append(f"Strategy #{case}: {invalid}")
        out.append("")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```入力はボードの数から始まります。 各ボードについて、2 つのブール配列は、どの行と列が少なくとも 1 つのブロックを失ったかを記録します。 

すべての動きに対して、コードは変更する前にまず両方のフラグをチェックします。 この順序が重要です。 行と列の両方がすでに壊れている場合、試みられたブロックはすでに落ちているため、その移動は無効としてカウントされます。 少なくとも 1 つの次元がまだ完了している場合、ブロックはまだサポートされており、移動は有効です。 

有効な移動後の割り当ては意図的に単純になっています。 落ちた他のセルを明示的に削除する必要はありません。 行または列が壊れると、そのフラグは永久に true のままになり、壊れた 2 つの次元の交差部分は次の移動では自動的に存在しないものとみなされます。 

1 を引くと、問題の 1 から始まる行と列の番号付けが、Python の 0 から始まる配列のインデックス付けに変換されます。 Python ではオーバーフローの懸念はなく、答え自体も最大でも (m) です。 

すべてのストラテジの後に空の文字列が追加されると、出力間に必要な空白行が生成されます。 決勝戦`join`への繰り返しの呼び出しも避けることができます。`print`ただし、どちらのアプローチでもこれらの制約に対しては十分高速です。
