 ## 解決策
 ## 問題の理解

 この問題では、CD をトラックの循環シーケンスとしてモデル化し、各トラックの継続時間が固定されています。 ある特定のトラックがアーニャのお気に入りです。 1 日はいくつかの運転区間で構成されます。 奇数番号のセグメントでは、アーニャは車に乗っているため、CD プレーヤーは彼女のお気に入りの曲を再開し、セグメント全体でそれを繰り返すことになります。 偶数番号のセグメントでは彼女が不在であるため、CD は前のセグメントが停止した場所から通常の再生を再開します。 このタスクは、お気に入りのトラックが 1 日のうちに何秒聞こえるかを計算することです。 公式声明では、CD は最大 50 枚、CD 1 枚あたり最大 20 トラック、CD 1 枚あたり最大 100 日、1 日あたり最大 20 の走行セグメントが許可されています。 1 日のセグメントの合計継続時間は最大 86,400 秒です。 

Codeforces バージョンには 1 秒の時間制限と 256 MB のメモリがあります。 入力の合計量は、セグメント単位では少なく、最大でも (50 \times 100 \times 20 = 100{,}000) セグメントですが、これらのセグメントの合計期間は膨大になる可能性があります。 毎秒処理するメソッドは、(50 \times 100 \times 86{,}400 = 432{,}000{,}000) 回もの反復を実行できます。 これは、Python が 1 秒の制限内で試行すべきことをはるかに超えています。 目的のソリューションでは、各セグメントを一定時間で処理する必要があります。 

最初の微妙なケースは、アーニャがお気に入りの曲が終わると同時に退場する場合です。 例えば、```
1
2 1
5 7
1
3 5 1 7
```生成する```
CD #1:
12
```最初の 5 秒は完全にお気に入りの曲なので、Anya が退席すると、通常の再生はトラック 2 から始まります。したがって、1 秒のセグメントは何も寄与せず、最後の 7 秒のセグメントは 7 秒寄与します。 お気に入りの継続時間の正確な倍数をお気に入りの曲の位置 0 として扱う不注意な実装では、1 秒のセグメントがお気に入りの時間として誤ってカウントされてしまいます。 

2 番目の境界ケースは、お気に入りの曲が CD の最後のトラックである場合に発生します。 考慮する```
1
2 2
3 5
1
2 5 6
```出力は```
CD #1:
8
```アーニャはお気に入りの曲を 5 秒間聴きます。 彼女が去ったときにちょうど終了するため、通常の再生はトラック 1 に戻ります。次の 6 秒には、トラック 1 が 3 秒含まれ、次にお気に入りのトラックが 3 秒含まれます。 お気に入りのトラックの終わりを位置として保存する表現`total`循環演算を実行する前に、その位置をゼロに正規化する必要があります。 

3 番目のケースは、トラックが 1 つだけ含まれる CD です。```
1
1 1
5
1
1 100
```答えは```
CD #1:
100
```アーニャがいるときもいないときも、毎秒必ずお気に入りの曲が流れます。 お気に入りのトラックの後に常に別のトラックがあることを想定した実装は、ここで失敗します。 

## アプローチ

 最も直接的な解決策は、一度に 1 秒ずつ CD をシミュレートすることです。 アーニャが車に乗っている間、シミュレートされた 1 秒ごとに答えが 1 つずつ増え、お気に入りの曲内の位置が周期的に進みます。 彼女がいない間、位置は CD 内で通常通り進み、現在の位置がお気に入りのトラックに属している場合は 2 番目の貢献が行われます。 これは正しいです。入力では実際の経過秒数で再生が記述されているため、文字通りプレーヤーをたどることで、何が起こっているかを正確に再現できます。 

問題は秒数です。 1 日には 86,400 秒を含めることができ、50 枚の CD ごとに 100 日を含めることができます。 最悪のケースは、シミュレーションで約 4 億 3,200 万秒です。 一つ一つの作業は単純でも、制限時間に対して作業量が多すぎます。 

重要な点は、通常の再生が周期的であるということです。 Anya が不在になると、CD は円形のタイムラインのように動作し、その長さが CD の合計再生時間になります。 CD を完全に通過するたびに、ちょうど 1 つの固定時間、つまりお気に入りのトラックの長さが、お気に入りの曲に費やされます。 したがって、個々の秒を検査する必要はありません。 

Anya が存在するセグメントに関する 2 番目の有益な観察があります。 すべての秒がお気に入りの曲であるため、答えはセグメント全体の長さだけ増加します。 その後、通常の再生をどこから再開するかを決定するだけで済みます。 お気に入りの曲は繰り返されるため、その新しい位置は、お気に入りの長さを法としたセグメント長によって決まります。 

長さ (L) の欠落セグメントについては、(L) を完全な CD サイクルと残りに分割します。 すべての完全なサイクルは、正確にお気に入りの継続時間に貢献します。 残りは CD 1 枚よりも短く、円形の境界で分割した後、お気に入りの区間を横切ることができるのは最大 1 回です。 その重なりは一定時間で計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(合計経過秒数) | お(1) | 遅すぎる、最大 4 億 3,200 万回の反復 |
 | 最適 | O(セグメント数) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. トラックの長さを読み取り、CD の合計長を計算します。 絶対的な開始位置も計算します`F`お気に入りのトラックの前のすべてのトラックの継続時間を合計することで、そのトラックの時間を短縮できます。 円形のタイムライン上のお気に入りの間隔は次のようになります。`[F, E)`、 どこ`E = F + favorite_duration`。 
2. 関数を定義する`prefix(x)`お気に入りのトラックが最初に何秒現れるかを返します。`x`1 CD サイクルの秒数。 前に`F`値はゼロで、お気に入りの間隔内では直線的に増加し、その後は`E`お気に入りの期間と同じままになります。 これにより、重複カウントがプレフィックス値の減算に変換されます。 
3. 円位置から始まる通常の再生間隔でお気に入りの秒数をカウントする関数を定義します`pos`そして永続的な`length`秒。 最初のテイク`length // total`CD サイクルを完了し、貢献する`full_cycles * favorite_duration`。 残りの場合は、prefix 関数を使用します。 残りが CD の終わりをまたぐ場合、それを現在のサイクルのサフィックスと次のサイクルのプレフィックスに分割します。 
4. 毎日、任意の CD 位置から開始します。最初のセグメントは常に、アーニャが車に乗り込み、すぐにお気に入りの曲の先頭に再生をリセットする奇妙なセグメントであるためです。 その日の答えをゼロに設定します。 
5. その日のセグメントを左から右に処理します。 奇数の長さのセグメントの場合`L`、すべて追加します`L`答えまで数秒。 新しい再生位置は、お気に入りの曲内で、次のオフセットで決定されます。`L % favorite_duration`。 残りがゼロの場合、再生はお気に入りの曲の終わりに達しており、次のトラックに進む必要があるため、位置は次のようになります。`E`、CDの長さを法として正規化したものです。 
6. 偶数の長さのセグメントの場合`L`の場合は、現在位置から通常再生オーバーラップ機能を使用します。 その関数によって返されたお気に入りの秒数を加算し、円の位置を だけ進めます。`L`。 
7. その日の累積回答を印刷します。 CD のすべての日数が処理された後、次の CD に移動する前に必要な空白行を印刷します。 元のコンテストの声明では、すべての CD の後に空白行が必要です。 

### なぜ効果があるのか

 不変条件は、すべての偶数セグメントの直前に、`pos`は、以前のセグメントをすべてたどった場合に CD が自然に再生される正確な位置を表します。 奇数セグメントの間は、お気に入りの曲が強制的に再生されるため、セグメント全体の長さの加算は正確であり、Anya が退出したときにモジュロ演算により正しい位置が得られます。 偶数セグメントの間、CD は通常の循環順序に従い、オーバーラップ機能は、お気に入りのトラックに属する循環間隔の部分を正確にカウントします。 したがって、累積された応答と再生位置の両方が、各セグメントの後でも正しいままになります。 毎日の最初のセグメントでお気に入りの曲がリセットされるため、日を独立して処理できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    output = []

    for case_no in range(1, t + 1):
        n, k = map(int, input().split())
        tracks = list(map(int, input().split()))

        total = sum(tracks)
        favorite = tracks[k - 1]

        favorite_start = sum(tracks[:k - 1])
        favorite_end = favorite_start + favorite

        def prefix(x):
            if x <= favorite_start:
                return 0
            if x >= favorite_end:
                return favorite
            return x - favorite_start

        def favorite_in_normal_playback(pos, length):
            if length == 0:
                return 0

            full_cycles, rem = divmod(length, total)
            result = full_cycles * favorite

            if rem == 0:
                return result

            end = pos + rem

            if end <= total:
                result += prefix(end) - prefix(pos)
            else:
                result += prefix(total) - prefix(pos)
                result += prefix(end - total)

            return result

        d = int(input())

        output.append(f"CD #{case_no}:")

        for _ in range(d):
            s_and_lengths = list(map(int, input().split()))
            s = s_and_lengths[0]
            segments = s_and_lengths[1:]

            answer = 0
            pos = 0

            for i, length in enumerate(segments):
                if i % 2 == 0:
                    # Anya is in the car, so the favorite song
                    # plays for the entire segment.
                    answer += length

                    rem = length % favorite
                    if rem == 0:
                        # The favorite song has just ended.
                        # Continue with the next track.
                        pos = favorite_end % total
                    else:
                        pos = favorite_start + rem
                else:
                    # Normal CD playback.
                    answer += favorite_in_normal_playback(pos, length)
                    pos = (pos + length) % total

            output.append(str(answer))

        output.append("")

    sys.stdout.write("\n".join(output) + "\n")

if __name__ == "__main__":
    main()
```実装の最初の部分では、お気に入りのトラックが CD の絶対タイムライン上の区間として識別されます。 トラックにデュレーションがある場合`[100, 200, 50]`トラック 2 がお気に入りの場合、CD タイムラインは次のようになります。`[0, 350)`、お気に入りの間隔は`[100, 300)`。 この表現により、通常の再生中に個々のトラック番号を追跡する必要がなくなります。`prefix(x)`は主要なカウントプリミティブです。 のために`x <= favorite_start`、 最初`x`秒にはお気に入りの時間が含まれていません。 のために`x >= favorite_end`、お気に入りの曲全体が含まれています。 これらの境界線の間で、お気に入りの投稿はまさに`x - favorite_start`。 

通常の再生機能は、最初に完全な CD サイクルを処理します。 CDが長持ちすれば`total`秒、すべての完全なサイクルが正確に寄与します`favorite`秒。 残りの間隔の長さは次の値より短いです`total`したがって、現在のサイクル内に留まるか、循環境界を一度通過します。 2 つのケースは、prefix 関数によって処理されます。 

奇数セグメントの更新には特別な処理が必要な場合があります。`length % favorite == 0`。 この状況では、お気に入りの曲が終了したばかりであるため、お気に入りの曲を再開するのではなく、再生は次のトラックに移動します。 使用する`favorite_end % total`お気に入りのトラックが最後のトラックで、次の位置が CD の先頭である場合も処理します。 

すべての算術演算は Python の整数に快適に適合します。 1 日の最大期間はわずか 86,400 秒であり、1 日の応答も同じ長さに制限されるため、Python では整数オーバーフローの懸念はありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(T + S) | トラックの前処理には O(T) かかり、すべての運転セグメントは O(1) で処理されます。 |

```最初のセグメントは、お気に入りのトラックの後の境界で CD から離れます。 1 秒の通常セグメントはトラック 2 で始まり、ゼロに寄与します。 最後の 7 秒セグメントは 7 を提供し、`12`。 保存された位置は別のお気に入りの繰り返しの開始ではなく、次のトラックを表すため、不変条件は保存されます。 

お気に入りの曲が最終曲の場合、`favorite_end == total`。 のために```
1
2 2
3 5
1
2 5 6
```最初のセグメントは 5 とセットに寄与します`pos = total % total = 0`。 6 秒間の通常の再生は、トラック 1 の 3 秒間とお気に入りのトラックの 3 秒間をすべて横断します。 結果は`8`。 位置更新のモジュロがそれを防ぐものです`total`無効な円座標にならないようにします。 

CD に 1 曲しか収録されていない場合、お気に入り区間は`[0, total)`。 プレフィックス関数は、通常の再生の残りごとに間隔全体の長さを返しますが、奇数のセグメントもその完全な継続時間に寄与します。 のために```
1
1 1
5
1
1 100
```答えは`100`、すべての秒がお気に入りの曲に属しているためです。 同じ表現は、特別な場合のシミュレーションを行わずに、繰り返される完全な CD サイクルも処理します。 

欠落したセグメントが CD の終端をまたぐ場合、通常の再生機能は残りを現在位置から CD の終端までのサフィックスと、位置 0 までラップした後のプレフィックスに分割します。 これは問題の循環部分であり、単純な`prefix(end) - prefix(start)`式が誤って扱われる可能性があります。 2 つの部分からなる計算により、再生が最後のトラックから最初のトラックに戻った場合でも、お気に入りインターバルのカウントが正確に保たれます。
