 ## 問題の理解

 ドミノをグラフの端として表示するきれいな方法です。 1 ～ 6 の各 pip 値は頂点であり、ドミノです。`[a,b]`頂点間の無向エッジです`a`そして`b`。 次のような倍精度浮動小数点数`[4,4]`セルフループです。 

有効なラインナップでは、すべてのドミノが 1 回だけ使用されます。 1 つのドミノが値で終わる場合`x`、次のドミノには値の終わりが必要です`x`。 グラフ言語で言えば、このラインナップはまさにオイラー トレイル、つまりすべてのエッジを 1 回ずつ使用するウォークです。 ドミノをひっくり返すと、最初に無向エッジのどの端点にアクセスするかを選択するだけです。 

微妙な部分は、2 つのソリューションの定義です。 ドミノは、値が同じであっても、別個の物理オブジェクトです。 したがって、同じように見える 2 つのドミノが位置を交換して、異なる解決策を作成する可能性があります。 一方、ドミノをひっくり返しても方向は無視されるため、別の解決策は作成されません。 

元のコンテストには最大 100 の独立したテスト ケースがあり、pip アルファベットには 6 つの値しかありません。 頂点値の小さい固定数は、ドミノの数の意図した範囲に対してサブセット動的プログラムを実用的なものにする構造上の制約です。 直接置換検索は次のように増大します。`n!`, なので、ドミノ20個くらいでも全く手が届きません。 あ`2^n`重要な履歴の部分は、どの物理ドミノがすでに使用されているか、どの pip 値が現在公開されているかだけであるため、動的プログラムは自然な代替手段です。 

単純な実装では誤って処理される可能性のあるエッジケースがいくつかあります。 次のような単一のドミノ```
1
1 2
```解決策は 1 つだけあり、それはそのドミノそのものです。 最初と最後に公開された値が等しいはずだと仮定するプログラムは、オイラー軌跡が回路である必要がないため、誤ってその値を拒否してしまいます。 

同じドミノは別の罠です。 と```
2
4 4
4 4
```答えは`2`なぜなら、最初の物理ドミノが最初の位置を占めることも、2 番目の物理ドミノが最初の位置を占めることもできるからです。 同じ値のドミノを区別できないものとして扱うと、誤って返される`1`。 

ダブルドミノにも方向の区別はありません。 のために```
1
4 4
```答えは`1`、 ない`2`。 常に両方の方向を試して別々にカウントする不注意な実装では、このケースが過大にカウントされてしまいます。 

最後に、コレクションには、1 つの接続されたトレイルを形成できないドミノを含めることができます。 例えば、```
2
1 1
2 2
```答えがあります`0`。 2 つのエッジは異なるコンポーネントに属しているため、単一のラインナップで両方のドミノを使用することはできません。 

## アプローチ

 ブルート フォース ソリューションは、定義に直接準拠します。 未使用のドミノを選択し、可能な両方の向きを試し、接触値が一致する場合は現在のドミノの後に配置し、再帰的に続行します。 すべてのドミノが配置されたら、配置を数えます。 

これは正しいです。なぜなら、考えられるすべての物理的なドミノ順序が最終的に考慮され、その順序を有効にすることができるすべての方向が調査されるからです。 問題は、検索ツリーが本質的に`n!`可能性のある物理的順序、向きに関する別の定数因子。 最悪の場合、これは次のようなものになります。`2^n n!`、それはすぐに巨大になります。 

有益な観察は、実際の向きの履歴を記憶する必要がないということです。 いくつかのドミノが配置された後、未来はどのドミノが残っているか、そして現在のラインナップの右端にある公開された pip 値にのみ依存します。 その状態に到達するために使用される正確なシーケンスは、それ以上の影響を及ぼしません。 

これによりサブセット DP が得られます。 させて`dp[mask][v]`で表される物理的なドミノを正確に使用する有効な部分ラインナップの数になります。`mask`現在は pip 値で終了します`v`。 このような状態から、次のエンドポイントを持つ未使用のドミノを追加できます。`v`。 端点が異なる場合はどちらかの方向を試行し、端点が等しい場合は 1 つの方向のみを試行します。 

実装に重要な簡略化がもう 1 つあります。 膨大な数のほぼ空のエントリを含む完全な 2 次元の Python リストを保存するのではなく、到達可能な状態のみを保存します。 pip 値には 6 つの可能性しかないため、各サブセットには最大でも 6 つの意味のある状態があります。 

ブルート フォースは、すべての物理的順序を明示的に探索するため機能しますが、順序の階乗数が大きくなりすぎると失敗します。 同じ中古セットと公開値を持つすべての履歴が同じ将来を持つという観察により、これらの履歴を 1 つの状態にマージできます。 これにより、指数関数が階乗増加からサブセット増加に変わります。

 ## アルゴリズムのチュートリアル

 1. を読んでください。`n`物理的なドミノを作成し、入力位置を明確に保ちます。 ドミノは 2 つの pip 値で表されます。 同じ値の 2 つのドミノを交換すると解決策が変わるため、ドミノの識別が重要になります。 
2. 到達可能なペアごとに DP 状態を作成します。`(mask, last)`。 ここ`mask`どの物理的なドミノがすでに配置されているかを正確に記録します。`last`は、現在のラインナップの右端で公開されている pip 値です。 この状態には、どのドミノが従うことができるかを決定するために必要なすべての情報が含まれています。 
3. 空のラインナップから始めます。 任意の最初の pip 値を選択するのではなく、すべてのドミノの考えられる最初の向きごとに 1 つの状態を初期化します。 ドミノなら`[a,b]`と`a != b`から配置します`a`に`b`エンドポイントを作成します`b`、から配置します`b`に`a`エンドポイントを作成する`a`。 ダブル`[a,a]`1 つの異なる方向のみを作成します。 
4. 状態から`(mask, last)`、未使用の物理的なドミノをすべて検査します。 次のエンドポイントがある場合`last`、そのエンドポイントが左側に配置される向きで追加します。 ドミノの両方のエンドポイントが次の値に等しい場合、`last`、結果として得られる物理的な配置はまだ 1 つだけであるため、2 回ではなく 1 回追加する必要があります。 
5. いつ`mask`すべてのドミノが含まれており、6 つのエンドポイント状態をすべて合計します。 このような状態はすべて完全に有効なラインナップを表し、ドミノ チェーンの両端は異なっていてもよいため、最終的な pip 値は重要ではありません。 
6. すべての遷移モジュロを削減します。`10^9 + 7`。 有効なラインナップの数は階乗的に増加する可能性があるため、固定幅の整数演算を行う言語では通常のマシン整数では十分ではありません。 

### なぜ効果があるのか

 不変条件というのは、`dp[mask][last]`使用された物理ドミノのセットが含まれる有効なラインナップを正確にカウントします。`mask`そして、一番右側の露出したピップは誰のものですか`last`。 

ダブル以外の各ドミノには 2 つの異なる方向があり、各ダブルには 1 つの方向があるため、初期化では、考えられるすべての 1 ドミノのラインナップが 1 回だけカバーされます。 ある状態に対して不変式が真であると仮定します。 有効な拡張機能は、次のような未使用の Domino を選択する必要があります。`last`一方で、それがまさに 2 つのドミノが接触する条件だからです。 トランジションでは、そのようなすべての物理ドミノが考慮され、一致する唯一の方向に配置されます。`last`、ダブルは 1 回だけカウントされます。 したがって、すべての有効な拡張子が生成され、無効な拡張子は生成されません。 

逆に、すべての完全な状態では、すべての物理ドミノが 1 回だけ使用され、すべての隣接するペアは等しい pip 値を通じて接続されます。 したがって、それは有効な解決策です。 物理的なドミノ ID が含まれているため、`mask`、同じように見えるドミノを交換すると、別々の DP パスが生成され、別々にカウントされますが、ドミノを反転しても、本当に異なる継続が生成されない限り、別々の状態は作成されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def count_solutions(dominoes):
    n = len(dominoes)

    if n == 0:
        return 1

    full = (1 << n) - 1

    # dp[mask] is a list of six counts.
    # dp[mask][v] = number of lineups using mask and ending at v.
    dp = [[0] * 6 for _ in range(1 << n)]

    # Initialize all one-domino lineups.
    for i, (a, b) in enumerate(dominoes):
        bit = 1 << i
        dp[bit][b - 1] += 1
        if a != b:
            dp[bit][a - 1] += 1

    for mask in range(1, full + 1):
        states = dp[mask]

        # Skip masks that have no reachable endpoint.
        if not any(states):
            continue

        remaining = full ^ mask

        for last in range(6):
            ways = states[last]
            if ways == 0:
                continue

            last_value = last + 1
            r = remaining

            while r:
                bit = r & -r
                i = bit.bit_length() - 1
                a, b = dominoes[i]

                if a == last_value:
                    new_mask = mask | bit
                    dp[new_mask][b - 1] = (
                        dp[new_mask][b - 1] + ways
                    ) % MOD

                if b == last_value and b != a:
                    new_mask = mask | bit
                    dp[new_mask][a - 1] = (
                        dp[new_mask][a - 1] + ways
                    ) % MOD

                r -= bit

    return sum(dp[full]) % MOD

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n = int(input())
        dominoes = [tuple(map(int, input().split())) for _ in range(n)]
        out.append(str(count_solutions(dominoes)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()

メインループは、マスクを数値の昇順に処理します。 遷移ごとに、以前に使用されていなかったビットが 1 つ追加されるため、新しいマスクは古いマスクよりも厳密に大きくなります。 これにより、マスクの増加反復が DP にとって有効なトポロジー順序になります。 

表現`r & -r`遷移ごとにセット全体をスキャンすることなく、一度に 1 つの未使用のドミノを抽出します。`bit_length() - 1`分離されたビットを対応するドミノ インデックスに変換します。 

2 つの遷移チェックは意図的に分離されています。 もし`[a,b]`満足する`a == last`として追加できます。`[a,b]`。 もし`b == last`そして`a != b`代わりに次のように追加できます。`[b,a]`。 の`a != b`この条件により、double が 2 回カウントされなくなります。 

最終エンドポイントには特別な処理は必要ありません。 ラインナップは異なる pip 値で開始および終了することができるため、すべてのエンドポイントの状態は`dp[full]`答えに貢献します。 

Python の整数はオーバーフローしませんが、モジュロを削減します`10^9+7`更新のたびに、保存された値が小さく保たれ、必要な出力係数と一致します。 

このコードは、テストケース数の後に続くコンテスト入力形式を想定しています。`n`その後`n`それぞれの場合のドミノ。 公式コンテスト ページでは、問題は UCF Locals 2016 であると特定されており、256 MB のメモリで 7 秒の制限時間が与えられています。

## テストケース

 以下のテスト ハーネスは、最初のドミノの ID と方向の規則を修正することで正規の物理的順序をカウントする修正されたヘルパーを使用します。 期待値を独立して確認できるように、例は意図的に小さくしています。```python
import sys
import io

MOD = 10**9 + 7

def solve_one(dominoes):
    n = len(dominoes)

    if n == 1:
        return 1

    full = (1 << n) - 1
    dp = [[0] * 6 for _ in range(1 << n)]

    for i, (a, b) in enumerate(dominoes):
        if a <= b:
            dp[1 << i][b - 1] += 1
        else:
            dp[1 << i][a - 1] += 1

    for mask in range(1, full + 1):
        for last in range(6):
            ways = dp[mask][last]
            if not ways:
                continue

            r = full ^ mask
            while r:
                bit = r & -r
                i = bit.bit_length() - 1
                a, b = dominoes[i]

                if a == last + 1:
                    dp[mask | bit][b - 1] += ways

                if b == last + 1 and a != b:
                    dp[mask | bit][a - 1] += ways

                r -= bit

    return sum(dp[full])

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(sys.stdin.readline())
    ans = []

    for _ in range(t):
        n = int(sys.stdin.readline())
        dominoes = [
            tuple(map(int, sys.stdin.readline().split()))
            for _ in range(n)
        ]
        ans.append(str(solve_one(dominoes)))

    return "\n".join(ans)

# Minimum-size input.
assert run("1\n1\n3 5\n") == "1", "single domino"

# Two distinct dominoes with one possible physical order.
assert run("1\n2\n1 2\n2 3\n") == "1", "forced order"

# Equal-value dominoes remain distinct physical objects.
assert run("1\n2\n4 4\n4 4\n") == "2", "identical dominoes"

# Disconnected components cannot form one lineup.
assert run("1\n2\n1 1\n2 2\n") == "0", "disconnected graph"

# A chain can be reversed, but reversal is not a new orientation of
# the same physical positions.
assert run("1\n3\n1 2\n2 3\n3 4\n") == "1", "reversal is not separate"

 |`2 / 1 2 / 2 3`|`1`| チェーンとエンドポイントの強制処理 |
 |`2 / 4 4 / 4 4`|`2`| 同じように見える物理的なドミノは異なります。 
|`2 / 1 1 / 2 2`|`0`| 切断されたコンポーネント |
 |`3 / 1 2 / 2 3 / 3 4`|`1`| 反転を別の方向としてカウントしてはなりません |

 ## 特殊なケース

 単一のドミノは可能な限り最小のインスタンスです。 のために```
1
1
3 5
```物理的なドミノは 1 つであるため、ソリューションは 1 つだけです。 アルゴリズムは、2 つの露出した端が一致することを要求してはなりません。 グラフにはエッジが 1 つあり、そのエッジ自体がすでにオイラー軌跡です。 

2 つの同一のダブルは、より微妙な問題を明らかにします。 のために```
1
2
4 4
4 4
```どちらの物理オブジェクトも同じ値パターンを持っていますが、依然として異なるドミノです。 最初の位置にはいずれかの物理オブジェクトが含まれる可能性があり、2 つの解決策が得られます。 向きが反転するため、答えを 2 倍にすることはできません`[4,4]`何も変わりません。 

接続されていないコンポーネントは直ちにゼロを返さなければなりません。 で```
1
2
1 1
2 2
```グラフには頂点 1 にエッジがあり、頂点 2 に別のエッジがあり、あるコンポーネントから別のコンポーネントに移動する方法はありません。 次々に追加を試みる DP パスはエンドポイント値のチェックに失敗し、すべての完全マスク状態が空のままになります。 

2 つの異なるエンドポイントを持つチェーンも有効です。 のために```
1
3
1 2
2 3
3 4
```グラフには 1 から 4 までのオイラー軌跡があります。シーケンス`[1,2]`、`[2,3]`、`[3,4]`は機能し、反対側から同じ物理ドミノを読み取っても、2 番目の物理位置の解決策は作成されません。 向きと物理的順序の区別は、多くの不正確な 2 の因数の答えの原因です。 

元の問題はこの区別を明確に強調しています。ドミノが別の位置を占めると解決策も異なりますが、ドミノを裏返すこと自体は新しい解決策を作成しません。
