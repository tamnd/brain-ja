 ## 解決策
 ## 問題の理解

 独立した単語検索パズルがいくつかあります。 各パズルは次の要素で構成されます。`r × c`大文字のグリッドと単語のリスト。 単語は、1 つのグリッド セルから開始して、右、左、下、または上の 4 つの基本方向のいずれかに繰り返し移動することによって形成されます。 グリッドは周期的であるため、右端を越えて移動すると左端で継続し、下端を越えて移動すると上端で継続し、同じラッピングが他の 2 方向に適用されます。 したがって、ワードは同じ物理セルを複数回使用することがあります。 

要求されたすべての単語について、その最初の文字の行と列、および単語の残りの方向を報告する必要があります。 入力では、すべての単語が正確に 1 回出現し、どの単語も回文ではないことが保証されるため、同じシーケンスの 2 つの反対方向の間にあいまいさがありません。 

グリッドには 3 ～ 12 行、3 ～ 20 列があり、各単語には 3 ～ 100 文字が含まれます。 これらの寸法は意図的に小さくなっています。 すべてのセル、すべての基本方位、および単語のすべての文字をチェックするとしても、一般的なパズルでは数百万文字の比較にすぎません。 Aho-Corasick やサフィックス構造などの高度な文字列マッチング機構は必要ありません。 実装上の主な懸念事項は、巡回境界付近の正確さです。これは、ワードがエッジを通過して継続する可能性があり、その長さが行または列のサイズを超える場合に複数回折り返される可能性があるためです。 

最初のエッジ ケースは、水平境界を越えてラップしています。 考慮する```
3 3
ABC
DEF
GHI
1
BCA
```単語は行 1、列 2 から始まり、右に進みます。 後`C`、検索は次のように折り返されます`A`したがって、正しい位置は行 1、列 2、方向は右です。 列が 3 に達すると停止する実装は、それを誤って拒否します。 

2 番目のエッジ ケースが複数回ラップされています。 考慮する```
3 3
ABC
DEF
GHI
1
BCABC
```単語は行 1、列 2 から始まり、右に進みます。 その登場人物たちは、`B C A B C`, したがって、検索は右側の境界を 2 回横断します。 1 つのラップのみを処理する不注意な実装は、この場合に失敗します。 

3 番目のエッジ ケースは、同じセルを再度使用する単語です。 と```
3 3
ABC
DEF
GHI
1
BCABCABC
```単語は再び行 1、列 2 から始まり、右に移動します。 セルを再訪問することは禁止されていないため、訪問済みセットに基づく検索は別の問題を解決し、有効な出現を拒否する可能性があります。 

## アプローチ

 直接的なアプローチは、考えられるすべての開始セルと考えられるすべての基本方向を試すことです。 候補を選択したら、その方向に移動しながら単語を 1 文字ずつ比較します。 グリッドは循環しているため、次の行と列はモジュラー演算で取得されます。 すべての文字が一致する場合、候補は入力によって保証された一意の回答になります。 

この強引な方法は、実際の制約にはすでに十分です。 最悪の場合、一言でも検査します`r × c`開始位置、4 方向、最大 100 文字。 最大グリッド サイズでは、`12 × 20`、それはせいぜい`12 × 20 × 4 × 100 = 96,000`単語ごとの文字の比較。 数十語であっても、合計は 1 秒以内に収まります。 

有益な観察は、グリッドが小さく、移動ルールには 4 つの可能性しかないということです。 候補チェック中に分岐はありません。 開始セルと方向が決定されると、セルのシーケンス全体が決定されます。 つまり、単純な決定論的スキャンによって正確性と予測可能なパフォーマンスの両方が得られるということです。 

単語の最初の文字を含むセルのみをチェックし、それらのセルから 4 つの方向をテストすることで、実装をよりクリーンにすることができます。 また、すべての動きをモジュロ演算で正規化します。 たとえば、列から左に移動すると、`0`になる`(0 - 1) % c`、Python では自動的に生成されます。`c - 1`。 これは循環グリッドを直接モデル化します。 

すべての有効なオカレンスには 1 つの開始セルと 1 つの方向があるため、総当たり法が機能します。 パスを検索したり、訪問した状態を維持したりする必要はありません。 同じ観察により、実装が小さくなり、検査される候補文字の数の複雑さが線形に保たれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(s · r · c · L)`|`O(1)`入力とは別に | 承認済み |
 | 最適 |`O(s · r · c · L)`|`O(1)`入力とは別に | 承認済み |

 ここ`s`は単語の数であり、`L`は最大語長です。 2 行目は、同じ漸近アルゴリズムの実用的なバージョンを表しており、不必要な作業を避けるために最初の文字のチェックとモジュール式インデックス付けが使用されています。 

## アルゴリズムのチュートリアル

 1. パズルの数を読み取り、各パズルの寸法と文字グリッドを読み取ります。 グリッドを文字列のリストとして保存して、アクセスできるようにします。`grid[row][column]`は一定時間です。 
2. すべての単語について、すべてをスキャンします。`r × c`細胞。 セルは、その文字が単語の最初の文字と等しい場合にのみ開始点となるため、他のすべてのセルを直ちにスキップします。 
3. 開始セルとして考えられるものごとに、4 つの方向を試します。`(0, 1)`、`(0, -1)`、`(1, 0)`、 そして`(-1, 0)`。 これらはそれぞれ右、左、下、上を表します。 
4. 選択した方向について、一度に 1 文字ずつ単語を検査します。 キャラクターの位置`k`は`row = (start_row + dr * k) % r`そして`column = (start_col + dc * k) % c`。 

モジュール式のインデックス作成が、問題の厄介な部分の鍵となります。 特別なケースなしに、エッジを横切ることと同じエッジを複数回横切ることの両方を処理します。 
5. すべての文字が一致する場合は、開始行、開始列、および方向を記録します。 この問題では一意性が保証されているため、最初に成功した候補が必須の回答になります。 
6. 単語の結果を出力し、次の単語に進みます。 検索は単語ごとに独立しているため、検索間で情報を引き継ぐ必要はありません。 

不変条件は単純です: 候補をチェックするときはいつでも`(start_row, start_col, direction)`、最初の処理後`k`文字の場合、すでにチェックされているすべての文字は、開始セルから対応する数の循環移動でその方向に従うことによって検出される文字とまったく同じです。 もしすべてなら`L`比較が成功すると、完全な単語がそこに出現します。 すべての可能な開始セルとすべての可能な方向が検査されるため、有効な出現を見逃すことはなく、一意性が保証されているため、アルゴリズムが間違った代替を選択することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    directions = [
        (0, 1, "RIGHT"),
        (0, -1, "LEFT"),
        (1, 0, "DOWN"),
        (-1, 0, "UP"),
    ]

    out = []

    for _ in range(t):
        r, c = map(int, input().split())
        grid = [input().strip() for _ in range(r)]

        s = int(input())

        for _ in range(s):
            word = input().strip()
            found = False

            for sr in range(r):
                if found:
                    break

                for sc in range(c):
                    if grid[sr][sc] != word[0]:
                        continue

                    for dr, dc, name in directions:
                        ok = True

                        for k in range(1, len(word)):
                            nr = (sr + dr * k) % r
                            nc = (sc + dc * k) % c

                            if grid[nr][nc] != word[k]:
                                ok = False
                                break

                        if ok:
                            out.append(f"{sr + 1} {sc + 1} {name}")
                            found = True
                            break

                    if found:
                        break

        # Separate consecutive puzzles if required by the judge format.
        # The original input guarantees every requested word has one answer.

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```の`directions`配列には、許可される 4 つの動きとその出力名が含まれます。 行と列のデルタをテキストの方向とともに保持することで、検索順序が出力から切り離されるのを防ぎます。 

検索はすべてのセルで開始されますが、性質が異なるセルはすぐに拒否されます。`word[0]`。 これは小さな最適化ですが、より重要なのは、候補の意味が明確になることです。テストされたすべての候補は、実際には単語の最初の文字で始まります。 

ループは次から始まります`k = 1`なぜなら`k = 0`が一致することがすでに知られています。 表現`(sr + dr * k) % r`行を折り返しますが、`(sc + dc * k) % c`列を包みます。 個別の境界条件はなく、これはグリッドの次元よりも長い単語の場合に特に便利です。 

座標は、印刷時に 0 から始まる Python インデックスから 1 から始まるパズル座標に変換されます。 最大の乗算は次のとおりであるため、特別な整数の処理は必要ありません。`100 × 12`または`100 × 20`。 

固有の出現が見つかるとすぐにコードは停止します。 の`found`flag は、ネストされたループをきれいに中断し、誤って 2 番目の候補を報告することを防ぎます。
