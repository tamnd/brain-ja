 ## 解決策
 ## 問題の理解

 次の形式の行列式を含むセットアップが与えられています。$A^T \times A$、 どこ$A$何らかの行列であり、$A^T$はその転置です。 問題で説明されている主要な操作は、行を交換することです。$A$、この操作では の値は変更されないことがわかります。$A^T \times A$。 

物語を取り除いたこのタスクは、本質的に、ターゲット マトリックスがターゲットであるかどうかを判断することです。$B$の値と一致します$A^T \times A$最初に与えられた行列に対して$A$。 この問題は、行の置換が結果に影響しないこと、つまり行の内部順序が結果に影響しないことを強調しています。$A$最終的な計算結果とは無関係です。 

したがって、入力は行列として解釈できます$A$、おそらく何らかの表現ノイズまたは置換の曖昧さ、および行列を伴う$B$から導出された正規の不変式に対して検証したいこと$A$、つまりグラム行列$A^T A$。 

出力はバイナリです。不変式が指定されたターゲットと一致するかどうかを出力します。 

制約は明示的には述べられていませんが、典型的な Codeforce 構造と行列演算の言及を考慮すると、次のように仮定する必要があります。$n$少なくともここまでは$10^5$または同様のスケール。 これにより、単純な行列乗算が即座に除外されます。$O(n^3)$これを密行列として解釈すると、次のようになります。 ただし、重要な点は、行の交換では操作が不変であるため、変換をシミュレートする必要がないことです。 

単純だが誘惑しやすい間違いは、行の置換を明示的に尊重しながら行列の積を再計算することです。 たとえば、再構築しようとすると、$A$異なる行順序で再計算します$A^T A$、これは行数の階乗になります。 

さらに微妙な失敗例は、転置乗算を誤って解釈した場合に発生します。 たとえば、間違った計算をすると、$A A^T$の代わりに$A^T A$どちらも似ているように見えますが、まったく異なる次元と意味につながります。 

具体的なエッジの例:

 入力:$A = \begin{bmatrix}1 & 2 \\ 3 & 4\end{bmatrix}$計算を間違えた場合$A A^T$、次のようになります。$$\begin{bmatrix}5 & 11 \\ 11 & 25\end{bmatrix}$$しかし$A^T A$与える:$$\begin{bmatrix}10 & 14 \\ 14 & 20\end{bmatrix}$$これらを混同すると、たとえ小さなケースであっても、一貫して間違った答えが得られることになります。 

問題ステートメントのより深く意図された単純化は、すべての行の置換が行ベクトルのマルチセットを保存するため、グラム行列は行にわたって集計された内積のみに依存するということです。 

## アプローチ

 強引な解釈では、問題を文字通りに扱います。考えられるすべての行の置換を考慮します。$A$、計算する$A^T A$それぞれについて、等しいものがあるかどうかを確認します$B$。 の各計算$A^T A$かかります$O(n^2 m)$もし$A$は$n \times m$、そして、あります$n!$順列。 これはたとえ$n = 10$。 

順列の列挙を避け、代わりに行の交換を動的にシミュレートしようとしても、二次構造を繰り返し再計算することになり、不必要な作業が発生します。 

重要な洞察は次のとおりです$A^T A$は基本的に行の合計であるため、行の置換の下では不変です。$$A^T A = \sum_{i} r_i^T r_i$$どこ$r_i$です$i$- 番目の行$A$。 行を交換してもこれらの外積のマルチセットは変更されないため、最終的な行列は同一のままです。 

これにより、問題全体が直接計算に減ります。元の行列からグラム行列を 1 回計算します。$A$、そしてそれを直接比較します$B$。 シミュレーションや順列の組み合わせ論はありません。

 ## アルゴリズムのチュートリアル

 の各行を解釈します。$A$内のベクトルとして$m$-次元空間。 マトリックス$A^T A$は、すべての行にわたるペアごとの座標積を累積することによって構築されます。 

1. マトリックスの読み取り$A$とマトリックス$B$。 想定します$A$もっている$n$行と$m$列、一方$B$は$m \times m$。 ディメンションにより、意味のある比較が 1 つだけ可能であることがすでに強制されています。 
2. を初期化します。$m \times m$マトリックス`res`ゼロ付き。 これにより、計算されたグラム行列が保存されます。 各エントリー$res[j][k]$すべての行にわたる累積ドット積寄与を表します。 
3. 各行について$i$で$A$、すべての列のペアを反復処理します。$(j, k)$。 追加します$A[i][j] \times A[i][k]$に$res[j][k]$。 これは次の定義を直接実装します。$A^T A$明示的に転置を形成せずに。 
4. すべての行を処理した後、`res`完全なものが含まれています$A^T A$。 次に、それをエントリごとに比較します。$B$。 不一致が見つかった場合は、それらが等しくないと即座に結論付けます。 
5. すべてのエントリが一致する場合、等しいことを出力します。 

完全な行列乗算を構築する代わりに行にわたって累積する理由は、行単位の分解がより単純であり、不必要な転置オーバーヘッドを避けるためです。 

### なぜ効果があるのか

 値$A^T A$行の外積の合計に展開されます。$$A^T A = \sum_{i=1}^{n} r_i^T r_i$$各行は、最終的な行列に独立して寄与します。 行の交換は合計内のこれらの項の順序を入れ替えるだけであり、加算は可換であるため、最終結果は変わりません。 これにより、グラム行列は順序に依存するオブジェクトではなく、行の複数集合関数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    A = [list(map(int, input().split())) for _ in range(n)]
    B = [list(map(int, input().split())) for _ in range(m)]
    
    res = [[0] * m for _ in range(m)]
    
    for i in range(n):
        row = A[i]
        for j in range(m):
            for k in range(m):
                res[j][k] += row[j] * row[k]
    
    for i in range(m):
        for j in range(m):
            if res[i][j] != B[i][j]:
                print("No")
                return
    
    print("Yes")

if __name__ == "__main__":
    solve()
```実装はグラム行列の行分解に直接続きます。 各行が完全な外積に寄与するため、一般的なケースでは三重にネストされた構造は避けられません。 比較ステップは、不必要な作業を避けるために、構築直後に行われます。 

よくある落とし穴は、外積を構築するときにインデックスを逆にしてしまうことです。 正しい貢献度は、`row[j] * row[k]`行インデックスを混合したり、明示的に転置しようとしたりしません。

 このアルゴリズムは、グラム行列構築問題によく見られる密な行列の入力サイズに合わせて自然にスケールします。 適度な大きさでも$n, m$すべての入力要素が少なくとも 1 つの乗算に関与するため、これは標準的な最適なアプローチです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    output = io.StringIO()
    sys.stdout = output
    solve()
    return output.getvalue().strip()

def solve():
    n, m = map(int, input().split())
    A = [list(map(int, input().split())) for _ in range(n)]
    B = [list(map(int, input().split())) for _ in range(m)]
    
    res = [[0]*m for _ in range(m)]
    for i in range(n):
        for j in range(m):
            for k in range(m):
                res[j][k] += A[i][j] * A[i][k]
    
    print("Yes" if res == B else "No")

# provided sample-like cases

# minimum size
assert run("1 1\n5\n25\n") == "Yes"

# mismatch case
assert run("1 2\n1 2\n1 3\n1 4\n") == "No"

# identity case
assert run("2 2\n1 0\n0 1\n1 0\n0 1\n") == "Yes"

# negative values
assert run("2 2\n1 -1\n-1 1\n2 -2\n-2 2\n") == "Yes"

 ## 特殊なケース

 微妙なエッジケースが現れるのは、$n = 1$。 この状況では、$A^T A$は、単一の行とそれ自体との単純な外積です。 行に対するループは 1 回だけ実行され、特別な分岐は必要ないため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、すべてのエントリがゼロの場合です。 この場合、すべての寄与はゼロとなり、結果は行数に関係なくゼロ行列になります。 アルゴリズムはゼロを正しく累積し、一致します。$B$それもゼロの場合のみ。 

3 番目のケースは、行が繰り返される場合です。 各行は独立して寄与するため、複製は単純に寄与を線形にスケールします。 たとえば、2 つの同一の行はグラム行列の寄与を 2 倍にします。 このアルゴリズムは、重複排除やハッシュ化を必要とせずに、両方のコピーを自然に蓄積します。
