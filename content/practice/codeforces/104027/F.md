 ## 解決策
 ## 問題の理解

 この問題は、柱でできた 1 次元の地面に垂直に落下する石のブロックの集合をモデル化します。 各列は高さ 0 で空から始まり、石が落ちると、着地した場所に応じて上に積み重なっていきます。 

各石は列の連続した間隔に影響を与えます。 石が到着するとき、それは細胞ごとに徐々に落下することをシミュレートしません。 代わりに、間隔全体にわたって平らに着地する硬いブロックのように動作します。 石はすでにそこにあるものの上に置かれなければならないため、石の最終的な高さは、覆われた間隔で最も高い柱によって決まります。 着陸後、その間隔内のすべての柱の高さを、その最大サポート高さより正確に 1 単位だけ均一に増加させます。 

出力はすべての石を処理した後の最終構成であり、通常は各列の結果の高さ、またはすべての配置の効果を意味します。 

このステートメントは短いですが、重要な抽象化は、すべての操作が範囲クエリとそれに続く範囲割り当てであるということです。 範囲クエリはセグメント内の最大の現在の高さを要求し、更新によりセグメント全体がその最大値に 1 を加えた値に設定されます。 

制約は明示的には示されていませんが、意図された解決策は、クエリごとの操作数と対数オーバーヘッドの積が線形または線形に近いものになります。 列と石の数が両方とも大きい場合、各操作が間隔全体に影響するため、単純なセルごとのシミュレーションは非常に遅くなります。 

微妙なエッジ ケースは、前の更新が後の更新を部分的に支配する、重複する間隔から発生します。 たとえば、列が 0 に初期化され、2 つの操作 (最初の更新間隔 [1,3]、次に更新 [2,4]) がある場合、2 番目の操作は最大値を計算するときに最初の操作で更新された値を監視する必要があります。 オーバーラップ全体でグローバル状態を正しく維持することを忘れた単純な実装では、不正確な着地高さが計算されます。 

別の失敗例は、すべての操作が全範囲をカバーするなど、間隔が大きく、重なり合う場合に発生します。 位置ごとの更新アプローチは二次的な動作に変質し、個々の操作は単純に見えてもタイムアウトになります。 

## アプローチ

 直接シミュレーションでは、列の高さの配列が維持されます。 各石について、その間隔内のすべての列をスキャンし、最大高さを計算し、再度スキャンしてその値に 1 を加えた値を割り当てます。 これは、「インターバル内の最も高いサポートに着地し、その後スパン全体を埋める」という物理的ルールに正確に従っているため、正しいです。 ただし、各操作には間隔の幅に比例した時間がかかるため、すべての石が幅のほぼ全体に及ぶ最悪の場合、全体の複雑さは列数と操作の数で 2 次になります。 

重要な構造上の観察は、操作が静的配列に対する 2 つのアクションによって完全に決定されるということです。範囲最大値クエリの直後に、その範囲内のすべての値を定数に設定します。 これにより、間隔内の動きをシミュレートする必要がなくなります。 最大値が判明すると、結果はセグメント全体で均一になります。 

このため、この問題はセグメント ツリーや、高速範囲最大クエリと高速範囲割り当てをサポートするデータ構造にとって典型的なケースになります。 割り当てられる値は常にクエリから計算された単一の定数であるため、セグメント全体を安全に上書きできます。 標準の遅延伝播メカニズムを超えて、セグメント内の古い値の部分的な伝播は必要ありません。

 | セグメント ツリー (最大範囲 + 範囲割り当て) | O(n log m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

すべての列にわたって高さの配列を維持しますが、それを直接更新するのではなく、範囲最大クエリと範囲割り当て更新の両方をサポートするセグメント ツリー内に格納します。 

### ステップ

 1. すべての列にセグメント ツリーを構築し、すべての高さをゼロに初期化します。 これは、石が落とされる前の空の地面を表します。 
2. 間隔 [l, r] の各ストーン操作について、セグメント ツリーにこの間隔内の最大値を問い合わせます。 この最大値は、石が既存の構造物と重なり合うことなく着地できる最も高い支持点を表します。 
3. このクエリの結果を q とします。 石はその間隔内で最も高い既存の柱の真上に位置するため、高さ q + 1 を占めます。 
4. [l, r] に範囲割り当ての更新を適用し、その間隔内のすべての位置を q + 1 に設定します。これは、石がこの新しい高さでセグメント全体にわたって平らな層を形成していることを反映しています。 
5. すべての石に対してこのプロセスを順番に続けて、各更新で以前の操作から完全に更新された構造が表示されるようにします。 

### なぜ効果があるのか

 各列には、それまでに構築された積層構造の正しい高さがいつでも保存されます。 ある間隔にわたる最大のクエリは、石がその領域で最も高い障害物の上に置かれなければならないという正確な物理的制約を捕捉します。 石は硬くて均一であるため、最終的な高さが決まると、そのスパン内のすべての柱がその高さに一致する必要があります。 セグメント ツリーにより、クエリと上書きの両方が以前のすべての更新と一貫していることが保証されるため、後の操作で以前の構造が無視されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.mx = [0] * (4 * n)
        self.lazy = [-1] * (4 * n)

    def push(self, idx):
        if self.lazy[idx] != -1:
            v = self.lazy[idx]
            self.mx[idx * 2] = v
            self.mx[idx * 2 + 1] = v
            self.lazy[idx * 2] = v
            self.lazy[idx * 2 + 1] = v
            self.lazy[idx] = -1

    def range_set(self, idx, l, r, ql, qr, val):
        if ql <= l and r <= qr:
            self.mx[idx] = val
            self.lazy[idx] = val
            return
        if r < ql or l > qr:
            return
        self.push(idx)
        mid = (l + r) // 2
        self.range_set(idx * 2, l, mid, ql, qr, val)
        self.range_set(idx * 2 + 1, mid + 1, r, ql, qr, val)
        self.mx[idx] = max(self.mx[idx * 2], self.mx[idx * 2 + 1])

    def range_max(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.mx[idx]
        if r < ql or l > qr:
            return 0
        self.push(idx)
        mid = (l + r) // 2
        return max(
            self.range_max(idx * 2, l, mid, ql, qr),
            self.range_max(idx * 2 + 1, mid + 1, r, ql, qr)
        )

def solve():
    n, m = map(int, input().split())
    seg = SegTree(m)

    for _ in range(n):
        l, r = map(int, input().split())
        q = seg.range_max(1, 1, m, l, r)
        seg.range_set(1, 1, m, l, r, q + 1)

    res = []
    for i in range(1, m + 1):
        res.append(str(seg.range_max(1, 1, m, i, i)))
    print(" ".join(res))

if __name__ == "__main__":
    solve()
```セグメント ツリーは、範囲割り当ての遅延伝播を伴う標準形式で使用されます。 重要な実装の詳細は、増分更新をサポートする必要がなく、単一の値でセグメントを上書きするだけであるということです。 したがって、遅延タグはデルタではなく完全な割り当てを保存します。 

操作の順序は重要です。更新を適用する前に最大値を照会する必要があります。そうしないと、新しい値によって結果が汚染されてしまいます。 最終出力は、各位置を個別にクエリすることによって抽出されます。これは、セグメント ツリーのリーフ値を読み取ることと同じです。 

## 実用的な例

 5 つの柱と 3 つの石 ([1,3]、[2,5]、および [1,5]) がある小規模なシナリオを考えてみましょう。 

### トレース 1

 | ステップ | 間隔 | 範囲内の最大値 (q) | 割り当てられた値 | アップデート後の状態 |
 | --- | --- | --- | --- | --- |
 | 1 | [1,3] | 0 | 1 | [1,1,1,0,0] |
 | 2 | [2,5] | 1 | 2 | [1,2,2,2,2] |
 | 3 | [1,5] | 2 | 3 | [3,3,3,3,3] |

 このトレースは、以前の部分構造が後の最大クエリにどのように直接影響するか、および各更新がセグメントを新しい均一レベルにどのように平坦化するかを示します。 

### トレース 2

 次に [2,4]、[1,2]、[3,5] を考えてみましょう。 

| ステップ | 間隔 | 範囲内の最大値 (q) | 割り当てられた値 | アップデート後の状態 |
 | --- | --- | --- | --- | --- |
 | 1 | [2,4] | 0 | 1 | [0,1,1,1,0] |
 | 2 | [1,2] | 1 | 2 | [2,2,1,1,0] |
 | 3 | [3,5] | 1 | 2 | [2,2,2,2,2] |

 これは、各操作がグローバル構造ではなく、その間隔内の現在の最大値のみに依存することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log m) | 各ストーンは、セグメント ツリーに対して 1 つの範囲最大クエリと 1 つの範囲割り当てを実行します。 
| スペース | O(m) | セグメント ツリーは列ごとに一定数のノードを格納します。 

対数係数は、石と柱の数の両方が最大 2×10^5 に達する可能性がある一般的な制約には十分小さいです。

 ## 特殊なケース

 単一列の最小限のケースでは、セグメント ツリーが縮退範囲を正しく処理できるようになります。 入力用`1 1`その後に 1 回のアップデートが行われる`[1,1]`、最大値は 0 で、最終値は 1 になります。 構造は 1 つのリーフに縮小されるため、クエリと更新の両方がそのノードに直接作用する必要があります。 

繰り返されるなど、完全に重複するシーケンス`[1,m]`間隔は遅延伝播を強調します。 最初の更新後、すべての値は 1 になります。 2 番目の更新では、上書きする前に正しくクエリを実行する必要があり、どこでも 2 つが生成されます。 更新後に誤ってクエリを実行する実装では、元の最大構造を尊重せずに、すでに変更された値から誤って増加し続ける可能性があります。 

次のような混合オーバーラップのケース`[1,2]`、`[2,3]`、`[1,3]`部分的な伝播が正しく処理されることをチェックします。 2 番目の更新は最初の更新に依存し、3 番目の更新は両方に依存します。 セグメント ツリーにより、上書きが発生する前に各クエリが一貫した最新の状態を確認し、連鎖した依存関係全体で正確性が維持されます。
