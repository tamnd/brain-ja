 ## アルゴリズムのチュートリアル

 このプロセスを、合計する必要がある一連の時間の寄与として解釈します。 

1. プロセスと制限時間を説明する入力値を読み取ります。$m$。 制限は、計算された合計が比較されるしきい値です。 
2. アキュムレータ変数を初期化する`total_time`ゼロに。 この変数は、これまでに費やされたすべての時間の累計を表します。 
3. プロセスの各コンポーネントについて、その時間の寄与を抽出し、それを`total_time`。 このステップでは、値が大きい場合のオーバーフローを防ぐために 64 ビット演算を使用する必要があります。 
4. すべての投稿を処理した後、比較します。`total_time`と$m$。 もし`total_time`以下である$m$、プロセスは時間内に終了します。 それ以外の場合は、そうではありません。 
5. 対応する決定を出力します。 

### なぜ効果があるのか

 正確さは、プロセスの合計実行時間が正確に独立した時間の寄与の合計であるという事実から得られます。 どのステップも別のステップのコストに影響を及ぼさないため、追加の順序やグループ化が行われても最終的な値は不変です。 加算は結合的かつ可換であるため、増分的に累算すると、単一の式で合計を計算するのとまったく同じ結果が得られます。 との比較$m$したがって、正確かつ決定的です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    data = list(map(int, input().split()))
    if not data:
        return

    # We assume last value is m (time limit)
    m = data[-1]

    total = 0
    for x in data[:-1]:
        total += x  # use Python int (already 64-bit safe)

    if total <= m:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```実装は集約モデルに直接に従います。 入力は一連の整数として読み取られ、最後の値が制限時間として解釈されます。$m$。 それ以前のものはすべて、寄与する時間値として扱われます。 

主な微妙な点は、累算がワイド整数型で確実に行われるようにすることです。 Python ではこれは自動的に処理されますが、C++ のような言語ではまさにこれが行われます。`long long`ステートメントで示唆されているように、必須です。 

最後の比較は単一の条件チェックで行われるため、ソリューションは非常に軽量になります。
