 ## 問題の理解

 都市は次のようにモデル化されています。$n \times n$交差点のグリッド。 各交差点$(x, y)$垂直の通りにある$x$そして水平な通り$y$。 いくつかの交差点に警備員を配置する必要があり、各警備員は正確に 1 つの垂直通りと 1 つの水平通りを「カバー」します。つまり、すべての警備員がその列に 1 回貢献することになります。$x$そして一度コラムへ$y$。 

要件は、すべての行とすべての列が正確に一致している必要があることです。$k$それに属する交差点に配置される警備員。 各交差点には最大でも 1 つの警備員を配置できるため、効率的に警備員のセルを選択しています。$n \times n$すべての行の合計とすべての列の合計が正確に一致する行列$k$。 

出力では、可能な最小数のガードも求められます。 すべてのガードは正確に 1 行 1 列に寄与するため、行の寄与をカウントすると次のようになります。$n \cdot k$合計寄与度、および各ガードは行数に 1 つだけ寄与します。 これですでに答えが決まりました$m = n \cdot k$したがって、タスクは通常の意味での最適化ではなく、選択された多数のセルを使用して有効な構成を構築することです。 

制約$n \le 1000$そして$k \le n$が必要であることを暗示します$O(nk)$または$O(n^2)$最悪の場合は建設。 フローやマッチングを伴うものはやりすぎですが、技術的には実現可能です。 この構造は、直接的な組み合わせパターンを強く示唆しています。 

微妙な失敗例が現れるのは、$k = 0$。 この場合、ガードは配置されず、ゼロを出力した後は出力が空になる必要があります。 もう一つの境界ケースは、$k = n$、すべての行と列に次のすべてが含まれている必要があります。$n$列、グリッド全体を強制します。 

## アプローチ

 この問題を強引に考える方法は、この問題を 2 部構成のグラフ構造として扱うことです。つまり、一方の側に行、もう一方の側に列があり、各ガードがエッジになります。 両側のすべての頂点が正確に次数を持つ 2 部グラフが必要です$k$。 エッジの追加と制約のチェックを繰り返してそのようなグラフを検索したり、各行と列に容量がある最大フロー構築を実行したりすることができます。$k$。 これが機能するのは、有効な各解が完全な次数制約付きの 2 部マルチグラフに対応しているためです。 

しかし、フローベースの構築では、$O(n^2)$少なくとも潜在的なエッジとラン$O(n^3)$実装に応じて、または同様のもの。 構造が対称的で規則的であるため、これは不要です。 

重要な観察は、必要なのは$k$- サイズが等しい 2 つの分割間の通常の 2 部グラフ$n$。 このようなグラフは単純な循環構造を持ち、各行を接続します。$i$に$k$連続した列、モジュロの回り込み$n$。 これにより、すべての行が正確に一致することが自動的に保証されます。$k$エッジの構造により、すべての列も正確に受信します$k$シフトによってエンドポイントが均一に分散されるためです。 

これにより、問題は制約充足問題から決定論的パターン生成タスクに縮小されます。

 ## アルゴリズムのチュートリアル

 二部グラフの行を左の頂点、列を右の頂点として解釈します。 正確に施工いたします$k$列上のスライディング ウィンドウを使用して、行ごとにエッジを表示します。 

1. 行インデックスを修正する$i$。 正確に割り当てます$k$列。 
2. 各行について$i$、列に接続します$i, i+1, \dots, i+k-1$、モジュロを使用して$n$ラッピング。 
3. そのようなすべてのペア$(i, j)$交差点にガードを設置することに相当$(i, j)$。 
4. 構築されたすべてのペアを出力します。 

モジュロ演算がないと、行の終わり近くで列が不足してしまうため、ラッピングは不可欠です。 循環シフトにより、すべての行にわたる均一性が保証されます。 

### なぜ効果があるのか

 各行は正確に結果を生成します$k$構造上個別の列なので、行の制約はすぐに満たされます。 列の制約については、その列を観察してください。$j$行に含まれています$i$まさにいつ$j \in [i, i+k-1]$モジュロ$n$。 すべての行にわたって、この間隔パターンは均一にシフトするため、すべての列が正確にカバーされます。$k$回。 これは、インデックスの巡回シフトの下で構造が不変であると言うのと同じであり、両側に均一な次数分布を強制します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    res = []
    
    for i in range(n):
        for t in range(k):
            j = (i + t) % n
            res.append((i + 1, j + 1))
    
    out = [str(len(res))]
    for x, y in res:
        out.append(f"{x} {y}")
    
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は循環構築の直後に行われます。 行と列は、出力時に 1 から始まるインデックスに変換されます。 ネストされたループオーバー$n$行と$k$オフセットは正確に生成します$n \cdot k$警備員。 

よくある実装上の間違いは、モジュロを忘れることです。$n$、境界付近の行の正確性が損なわれます。 もう 1 つは、0 ベースの内部ロジックと 1 ベースの出力フォーマットを切り替えるときの、off-by-one インデックスです。

 ## 特殊なケース

 のために$k = 0$の場合、ループはペアを生成しません。 出力リストは空のままで、プログラムは正しくゼロを出力します。 この場合、内側のループがスキップされたときに、構築が誤って無効な座標を出力することがなくなります。 

のために$k = n$、各行はすべての列に接続されます。 モジュロ演算は引き続き機能しますが、ラッピングが必要ないため冗長になります。 アルゴリズムは完全なものを生成します$n^2$グリッド、およびすべての行と列が正確に$n$必要に応じて警備員。
