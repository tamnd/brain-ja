 ## 解決策
 ## 問題の理解

 私たちは、標準的なデカルト座標系ではなく、点が整数の 3 倍で表される三角格子埋め込みの 3D 座標系で作業しています。 光線は 2 つの異なる点によって定義されるため、その方向は最初の点から 2 番目の点へのベクトルによって決まります。 

テスト ケースごとに、そのような光線が 1 つ与えられます。 タスクは、同じ初期点から始まり、元の光線に垂直な別の光線を構築することです。 光線全体を記述するように求められるのではなく、光線の方向を定義する 1 つの整数点を出力するだけです。 すべての有効な選択肢の中から、開始点に最も近いものを選択する必要があります。同じ距離に複数の選択肢がある場合は、どれでも受け入れられます。 さらに、構築されたポイントの座標は大きな範囲内に収まらなければならないため、極端に大規模なスケーリング トリックに依存することはできません。 

重要な幾何学的難しさは、座標系自体に起因します。 点は 3 つの座標で指定されますが、有効な方向が事実上 3 次元に埋め込まれた 2 次元オブジェクトであるという制約された構造の中に存在します。 これは、自由な 3D ジオメトリとしての単純な解釈は誤解を招き、解決策は隠れた平面構造を尊重する必要があることを意味します。 

テスト ケースの数という点では制約が大きく、最大 2 万件に達しますが、座標値の大きさは最大 1,000 万件に達します。 これにより、テスト ケースごとに一定時間の構築が強制されます。 候補点の検索や無制限の反復によるシステムの解決を伴うアプローチは遅すぎます。 

1 つの座標軸だけを使用して任意の垂直ベクトルを選択できると仮定すると、素朴な推論による微妙な失敗例が現れます。 たとえば、単純に座標を交換したり否定したりしてベクトルを構築しようとすると、誤って有効な三角形の平面を離れてしまったり、このジオメトリの直交性が崩れてしまったりする可能性があります。 

垂直整数方向のランダム構築または総当たり検索を試みると、別の失敗モードが発生します。 解決策は常に存在しますが、検索空間には原則として制限がなく、直接の公式がなければ、クエリが 20,000 件を下回るとすぐにタイムアウトになります。 

## アプローチ

 強引なアイデアは、境界のある立方体内の現在の点からすべての整数ベクトルを構築し、その結果の方向が元の光線に対して垂直であるかどうかをテストすることです。 各候補点について、方向ベクトルを計算し、適切なドット積の下で直交性を検証します。 座標を妥当な範囲、たとえば開始点付近で ±10^6 に制限したとしても、最悪の場合でも約 10^18 の候補が生成されますが、これは完全に実行不可能です。 

問題の構造は、より強力な何かが起こっていることを示唆しています。 私たちは任意の 3D 空間で作業しているのではなく、制約された三角形座標系で作業しています。 このようなシステムでは、すべての有効な方向が平面内にあります。これは、すべての有効なベクトルで共有される暗黙の法線方向が存在することを意味します。 これを認識すると、問題は 2 つの独立した方向 (指定された光線方向と平面の固定法線) に直交するベクトルを構築することになります。 

この観察により、タスクは探索問題から直接的な線形代数の構築に変わります。 3D に埋め込まれた平面の垂直方向は、平面法線との外積によって取得できます。 法線が固定されており単純であるため、一定の時間で必要な方向を構築できます。

 ## アルゴリズムのチュートリアル

 ### ## アルゴリズムのチュートリアル

1. 指定された光線の方向ベクトルを 2 番目の点と最初の点の差として計算します。 このベクトルは、直交する必要がある幾何学的方向を表します。 
2. 座標系の構造的制約を特定します。有効な移動方向はすべて、3D 空間に埋め込まれた固定平面内にあります。 これは、その平面に対して固定の法線ベクトルが存在し、入力とは独立した一定の方向として扱うことができることを意味します。 
3. 外積を使用して、指定された方向と平面の法線の両方に垂直なベクトルを構築します。 これにより、有効な方向と同じ平面内にあり、元の光線に対して直交するベクトルが生成されます。 
4. この構築されたベクトルを新しい光線の方向として使用し、それを開始点に追加して、必要な 2 番目の点を取得します。 
5. 結果のベクトルがゼロ ベクトルの場合、その構築は無効ですが、有効な光線方向の制約の下では、この縮退は実際には発生しません。 
6. 終点座標を出力します。 ベクトルとその否定の両方が有効な場合は、開始点からの距離が同じであるため、どちらの方向も受け入れられます。 

### なぜ効果があるのか

 三角座標系のすべての有効な光線方向は、ℝ³ の 2 次元部分空間内にあります。 元の方向ベクトルはこの部分空間内にあります。 固定法線ベクトルとの外積により、同じ部分空間内に留まりながら、元の方向に直交するベクトルが生成されます。 これにより、座標系における有効性と、平面に限定されたユークリッド幾何学における垂直性の両方が保証されます。 この構築は決定論的であり、整数演算のみを使用するため、常に境界内に有効な整数点が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    # fixed normal of triangular coordinate plane
    nx, ny, nz = 1, 1, 1

    for _ in range(t):
        x0, y0, z0 = map(int, input().split())
        x1, y1, z1 = map(int, input().split())

        dx, dy, dz = x1 - x0, y1 - y0, z1 - z0

        # cross product d × n
        vx = dy * nz - dz * ny
        vy = dz * nx - dx * nz
        vz = dx * ny - dy * nx

        # move one step in this direction
        print("DA")
        print(x0 + vx, y0 + vy, z0 + vz)

if __name__ == "__main__":
    solve()
```このコードは、最初に元の光線の方向を計算し、次に三角形の埋め込みの法線を表す固定ベクトルとの外積を使用して垂直方向を構築します。 この方向を開始点に追加すると、新しい光線の有効な 2 番目の点が生成されます。 構築はテスト ケースごとに一定の時間で行われます。これは、入力サイズを考慮すると必要です。 

実装の微妙な点は、方向を正規化したりスケールしたりしないことです。 この問題では単位の長さではなく、方向と整数の有効性のみが考慮されるため、これは意図的なものです。 ゼロ以外のスカラー倍数は同等の光線を生成し、生の整数値を保持することで精度の問題を回避できます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    nx, ny, nz = 1, 1, 1
    out = []

    for _ in range(t):
        x0, y0, z0 = map(int, input().split())
        x1, y1, z1 = map(int, input().split())

        dx, dy, dz = x1 - x0, y1 - y0, z1 - z0
        vx = dy * nz - dz * ny

        vz = dx * ny - dy * nx

        out.append("DA")
        out.append(f"{x0+vx} {y0+vy} {z0+vz}")

    return "\n".join(out)

 ## 特殊なケース

 元の光線が座標軸の 1 つと一致する場合、まれなケースが発生します。 このような状況では、座標を回転したりコンポーネントを交換したりする単純なアプローチにより、三角形の平面から外れるベクトルが誤って生成される可能性があります。 外積構造は、常に光線方向と固定平面法線の両方に直交するベクトルを生成し、それが有効な幾何学的構造内に収まることを保証するため、これを完全に回避します。 

もう 1 つの特殊なケースは、座標の大きさが大きい場合です。 すべての演算は入力値の線形結合であるため、追加のスケーリング ロジックを使用しなくても、結果の座標は許容される ±10^18 範囲内に留まります。
