 ## 解決策
 ## 問題の理解

 王国の各都市は目的地の都市を 1 つだけ選択し、それらの間に道路が建設されます。 結果は都市ごとに方向性のある選択になりますが、道路自体は方向性がなく、整数の長さを持ちます。 すべての都市は 1 つの選択を行い、すべての都市には 1 つの外向き道路があるため、王国全体が、各接続コンポーネントに 1 つのサイクルが含まれ、樹木がそのサイクルに接続される構造を形成します。 

今では、それぞれの道は単なる単一の端ではありません。 それは単位セグメントに細分化されます。1 つの終点都市から開始して、他の都市に到達するまで道路に沿って整数距離ごとにポストを配置します。 だから長い道`l`とのパスになります`l-1`新しい中間ポスト。 2 つのエンドポイント都市と合わせて、これはすべてのエッジが一定の長さのノードのチェーンに置き換えられることを意味します。`l`。 

これらすべてのポストは、都市と道路の両方で、最大でも次の色を使用して色付けする必要があります。`K`色。 唯一の制限は、道路セグメントに沿った 2 つの隣接するポストが異なる色でなければならないことです。 有効なカラーリングがいくつ存在するかを法的に数えるよう求められます。`1e9 + 9`。 

重要な問題は、グラフが単純なツリーや単純なサイクルではないことです。 これは関数グラフ (各ノードには出力エッジが 1 つだけあります) ですが、エッジをパスに拡張すると、多くの次数 2 のノードが挿入され、長さがエッジの重みに依存するサイクルを含む、より大きなグラフが効率的に得られます。 

制約から、`N`まで可能です`1.5e5`、エッジの長さは最大です。`1e5`。 拡張後のノードの総数は約 100 に達する可能性があるため、エッジを明示的に拡張することは不可能です`sum l_i`、これは直接ビルドするには大きすぎます。 これにより、元の機能構造に基づいて動作し、パスの長さのみを集計するソリューションが即座に強制されます。 

単純なアプローチでは、グラフを拡張して DP または BFS カラーリングのカウントを実行しようとします。 拡張されたグラフのサイズが潜在的に大きくなるため、これは失敗します。`10^10`最悪の解釈では、少なくとも記憶と時間の限界をはるかに超えています。 

自明ではないエッジケースは、サイクル処理から発生します。 たとえば、全長 3 の単一サイクルはツリーや長いサイクルとは異なる動作をし、サイクル内のパリティの処理を誤ると不正確な答えが得られます。 もう 1 つの落とし穴は自己ループです。都市はそれ自体に接続して、長さ 1 のサイクルを形成する可能性があり、これはサイクルの公式で一貫して処理する必要があります。 

## アプローチ

 強引な解釈では、展開されたグラフを明示的に構築し、各接続コンポーネントで DP を使用して適切なカラーリングをカウントします。 これは原理的には正しいです。グラフはツリーが付加された一連のサイクルにすぎず、ツリーとサイクルを別々に色付けするのが標準であるためです。 ただし、拡張ステップによりそれは実行不可能になります。ノードの数はすべてのエッジの長さの合計に比例し、各 DP 遷移はそのサイズで線形になります。 

重要な観察は、拡張は必要ないということです。 長さのあるパス`l`2 つのノード間のチェーンとまったく同じ制約が与えられます。`l`エッジ。 中間ノードを挿入する代わりに、制約がパスに沿ってどのように伝播するかを知る必要があるだけです。 樹木の場合、寄与率は常に次のとおりです。`(K-1)`エッジがオリジナルか拡張されたかに関係なく、エッジごとに。 サイクルの場合、重要なのは拡張後のサイクルの全長だけです。 

これにより、問題は、各エッジに重みがある関数グラフに縮小され、サイクルに沿った重みの合計とツリー エッジ全体の合計のみが考慮されます。 

各接続コンポーネントには、正確に 1 つの有向サイクルがあります。 サイクルエッジを取り除けば、すべてはサイクルに根ざした森になります。 ツリー部分は単純な乗算係数に寄与し、サイクルは長さのサイクルの色を表現する既知の閉じた形式の表現に寄与します。`L`。 

一定の長さのサイクルの場合`L`、有効な色の数`K`色は:$$(K-1)^L + (-1)^L (K-1)$$これは、サイクルの標準的な色多項式から得られます。 

サイクルの外側にあるものはすべて、サイクル ノードに根付いたツリーのように動作し、`(K-1)`サイクルノード自体を除くノードごと。サイクルノード自体はサイクル式内で処理されます。 

したがって、完全な答えはツリー寄与とサイクル寄与の積となり、エッジを拡張することなく計算されます。

 ## アルゴリズムのチュートリアル

 各ノードが出ていくエッジが 1 つだけある関数グラフを直接操作しますが、各エッジには重みがあります。 

1.各都市から隣接情報を構築`u_i`に`v_i`重さで`l_i`。 これにより、重み付けされたエッジを持つ関数グラフが定義されます。 
2. ノードをトラバースしてサイクルを特定します。 未訪問のノードごとに、現在のトラバーサルで訪問済みのノードに到達するか、以前に処理されたコンポーネントに入るまで、出力エッジをたどります。 現在のパス内で再訪問を検出した瞬間に、サイクルを抽出し、サイクルに沿ったエッジの重みを合計することでその全長を計算します。 
3. サイクルが特定されたら、そのサイクル内のすべてのノードをそのサイクルに属するものとしてマークし、その合計の重み付けされた長さを記録します。`L`。 
4. 各サイクル ノードから、サイクルの一部ではないすべての入力エッジをツリーのルートとして扱います。 これらのツリーのサイズは、DFS を使用するか、訪問したノードを累積することによって計算しますが、エッジを拡張することはありません。 再びサイクルに入らずに、到達可能なノードをカウントするだけです。 
5. サイクルに含まれていないすべてのノードは、サイクルに接続された何らかのツリーに属します。 このような各ノードは次の要因に寄与します。`(K-1)`独立して、サイクル ノードの色が固定されると、すべてのツリー エッジで異なる色の選択が強制されるため、`(K-1)`ノードごとに。 
6. 長さのサイクルごとに`L`、答えにサイクル カラーリング値を掛けます。$$(K-1)^L + (-1)^L (K-1)$$7. すべてのサイクル寄与度を乗算し、次の乗算を行います。`(K-1)`グラフ全体の非サイクル ノードの数に引き上げられます。 

### なぜ効果があるのか

 重要な不変条件は、サイクル エッジを削除した後に残る構造は森林であり、根の固定色が与えられると木の色が独立して考慮されるということです。 すべての非サイクル ノードはその親制約によってのみ強制され、正確に次の乗算係数に寄与します。`(K-1)`グローバル構造とは無関係に。 

サイクルは制約が回り込む唯一の場所です。 サイクルの色多項式は、その全長がどのように構成されるかではなく、その全長にのみ依存します。 拡張された各エッジは単純なパスであるため、その唯一の効果は、サイクルの式が有効であり続けるために必要な構造を維持して、サイクルの合計長を増加させることだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 9

def solve():
    n, k = map(int, input().split())
    to = [0] * n
    w = [0] * n
    for i in range(n):
        u, v, l = map(int, input().split())
        u -= 1
        v -= 1
        to[u] = v
        w[u] = l

    visited = [0] * n
    in_stack = [0] * n

    parent = [-1] * n
    pw = [0] * n

    def dfs(start):
        stack = []
        cur = start
        while True:
            visited[cur] = 1
            in_stack[cur] = 1
            stack.append(cur)

            nxt = to[cur]
            if not visited[nxt]:
                parent[nxt] = cur
                pw[nxt] = w[cur]
                cur = nxt
                continue

            if in_stack[nxt]:
                cycle_nodes = []
                cycle_len = 0

                idx = len(stack) - 1
                while True:
                    node = stack[idx]
                    cycle_nodes.append(node)
                    if node == nxt:
                        break
                    idx -= 1

                cycle_nodes.reverse()

                m = len(cycle_nodes)
                for i in range(m):
                    u = cycle_nodes[i]
                    v = cycle_nodes[(i + 1) % m]
                    cycle_len += w[u]

                return cycle_nodes, cycle_len

            break

        for v in stack:
            in_stack[v] = 0
        return None, 0

    total_nodes = n
    cycle_lengths = []
    in_cycle = [False] * n

    for i in range(n):
        if not visited[i]:
            cycle_nodes, clen = dfs(i)
            if cycle_nodes:
                cycle_lengths.append(clen)
                for x in cycle_nodes:
                    in_cycle[x] = True

    # count non-cycle nodes via reachability pruning is complex;
    # here we rely on functional graph property: nodes not in cycles = n - cycle nodes
    cycle_node_count = sum(in_cycle)
    tree_nodes = total_nodes - cycle_node_count

    def modpow(a, e):
        res = 1
        while e:
            if e & 1:
                res = res * a % MOD
            a = a * a % MOD
            e >>= 1
        return res

    ans = 1

    # tree contribution
    ans = ans * modpow((k - 1) % MOD, tree_nodes) % MOD

    # cycle contributions
    for L in cycle_lengths:
        term = (modpow(k - 1, L) + ( -1 if (L % 2) else 1) * (k - 1)) % MOD
        ans = ans * term % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```実装では、まず各都市の単一の下り道路から機能グラフを構築します。 次に、再帰スタック スタイルのマーキングを使用してサイクルを検出する走査を実行します。 サイクルが見つかると、サイクルのエッジに沿って重みを合計することによってその全長が計算されます。 

すべてのサイクルが識別された後、どのサイクルにも属さないノードはツリー ノードとして扱われ、均一係数に寄与します。`(K-1)`それぞれ。 各サイクルは、重み付けされた全長に基づいて独自の色彩多項式値を提供します。 すべての寄与はモジュロ演算で乗算されます。 

微妙な点は、関数グラフで再帰なしでサイクル検出を正しく処理することです。 スタックベースのアプローチにより、サイクルとその正確な重み付けされた長さを再構築できることが保証されます。

 ## 特殊なケース

 自己ループは可能な限り最小のサイクルであり、都市がそれ自体に接続するときに発生します。 この場合、サイクル長はそのエッジの重みになります。 このアルゴリズムは、トラバーサル中にノードがノード自体を再訪問すると、ただちにそのノードをサイクルの一部として検出し、次のサイクル式を適用します。`L = l_i`。 これにより、単純な実装では特別な構造が忘れられることが多い、長さ 1 のサイクルを正しく処理できるようになります。 

もう 1 つのエッジ ケースは、すべてのノードが 1 つのサイクルを形成する場合です。 走査ではツリー ノードに遭遇することはありません。そのため、全体の答えはサイクル多項式の 1 回の適用に帰着します。 このアルゴリズムは、サイクル全体のすべての重みを正しく累積し、ツリー係数を誤って乗算しません。 

最後のエッジケースは、複数の独立したサイクルです。 各コンポーネントは個別に処理されるため、各サイクルは最終的な結果に独立して寄与し、モジュラー演算により乗算順序が正確さに影響を与えることはありません。
