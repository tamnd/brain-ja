 ## 問題の理解

 完全なグラフが与えられます。$n$頂点。 各頂点には最初に色があり、色は整数として与えられます。 すべての頂点のペアは接続されているため、グラフ構造自体は実際には明示的に操作する必要はありません。 

使用できる唯一の操作は、現在すべての頂点が同じ色を共有している接続されたサブグラフを選択し、それらのすべてを他の色に再色付けすることです。 目標は、そのような操作を最小限に抑えて、すべての頂点が単一の均一な色になるようにすることです。 

グラフが完成しているため、頂点のサブセットは接続されています。 これにより、問題が大きく変わります。接続性によって選択できる頂点が制限されるのではなく、選択されたすべての頂点が現在同じ色でなければならないという条件のみが制限されます。 

入力サイズは最大です$10^6$これにより、すべての色のペアを試したり、サブセットに対する操作を繰り返しシミュレートしたりするなど、二次関数は即座に除外されます。 基本的にカラー配列を線形時間で処理するソリューションが必要です。 

いくつかの微妙な状況が重要になります。 

すべての頂点がすでに同じ色を持っている場合は、たとえば次のようになります。 

入力:```
5
3 3 3 3 3
```操作は必要ないため、答えは 0 でなければなりません。 ここでは、色ごとに少なくとも 1 つの操作を盲目的に想定するアプローチは間違っています。 

すべての色が異なる場合は、たとえば次のようになります。```
4
1 2 3 4
```多くの操作が必要ではないかと思われるかもしれませんが、同じ色の複数の頂点の色を一度に変更できるため、本当の答えは、異なる色がいくつ存在するかによってのみ決まります。$n$自体。 

重要な落とし穴は、接続について考えすぎることです。 グラフは完全なので、接続性によって制限されることはなく、実際の構造は色がどのように分布するかだけです。 

## アプローチ

 ブルートフォース解釈では、プロセスをシミュレートします。 各ステップで、いくつかのカラークラスを選択し、そのサブセットを選択し、色を変更し、グラフを更新し、すべての頂点が 1 つの色を共有するまで繰り返します。 これは原理的には正しいですが、動的なカラー グループを維持し、頂点のセットを繰り返しスキャンまたは更新する必要があります。 最悪の場合、各操作が接触する可能性があります。$O(n)$頂点まで実行できます。$O(n)$オペレーション、それにつながる$O(n^2)$の動作が遅すぎるため、$n = 10^6$。 

重要な観察点は、グラフの構造により、同じ色の頂点のすべてのセットが 1 つの単位として交換可能になっているということです。 同じ色の頂点のサブセットは接続されているため、それぞれの異なる色をブロックとして扱うことができます。 さらに重要なのは、その色のすべての頂点をターゲット カラーに再色付けすることで、1 回の操作で色全体を削除できることです。 

これが明確になると、プロセスは純粋に組み合わせのみになります。 あると仮定します$k$最初ははっきりとした色。 そのうちの 1 つを最終的なターゲット色として選択します。 他のすべてのカラー クラスを少なくとも 1 回はそれにマージする必要があり、それぞれを 1 回の操作でマージできます。 これはすぐに得られます$k - 1$最適な答えとして。 

部分的なサブセットの色を変更したり、中間の変換を実行したりすることにはメリットがありません。各操作で追加コストなしでカラー クラス全体がすでに消費されているためです。

 | 異なる色を数える |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 問題を、初期配列にいくつの異なる色が存在するかを理解することに集約します。 

1. すべての頂点カラーを読み取り、リストに保存します。 グラフの構造は完全であるため無関係であり、接続によって頂点のグループ化に制限が課されません。 
2. 配列内の個別の色の数を計算します。 これは、配列を 1 回スキャンするときにハッシュ セットを使用して実行できます。 これが機能する理由は、各色が 1 回の操作で結合できる独立したグループとして動作するためです。 
3. 異なる色の数を次のようにします。$k$。 もし$k = 1$、グラフはすでに単色であるため、すぐに 0 を返します。 
4.そうでない場合は、戻ります$k - 1$。 これは、最終ターゲットとして 1 つの色を選択し、他のすべての色クラスをその色に 1 つずつマージすることに対応します。 

### なぜ効果があるのか

 重要な不変条件は、プロセスのどの時点でも、残りの各カラー クラスが 1 回の操作で他のカラーに完全に折りたためるということです。 色のサブセットは完全なグラフに接続されているため、削除することを決定した個別の色ごとに複数の操作が必要になることはありません。 カラー クラス全体を別のクラスにマージしない限り、どの操作でも個別のカラーの数を 1 つ以上減らすことはできません。また、そのようなマージは常に可能です。 これにより、$k - 1$必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    colors = list(map(int, input().split()))
    distinct = len(set(colors))
    print(max(0, distinct - 1))

if __name__ == "__main__":
    main()
```このソリューションは、色の配列を読み取り、すべての値をセットに挿入して、存在する固有の色の数を計算し、出力します。$k - 1$。 の`max(0, ...)`ガードは、すべての頂点がすでに同じ色を共有しているという単純なケースを処理します。 

主な微妙な点は、操作をシミュレートしようとしていないことです。 操作構造により、カラー クラス全体を 1 ステップで折りたたむことができるため、シミュレーションは不要になります。

 ## 特殊なケース

 すべての頂点が同じ色を共有する場合、設定されるサイズは 1 となるため、式は次のようになります。$1 - 1 = 0$。 このアルゴリズムは、最後の分岐を超える特別な分岐を必要とせずに、正しく 0 を返します。`max(0, ...)`。 

すべての頂点が異なる色を持つ場合、設定されるサイズは次のようになります。$n$、そして答えは次のようになります$n - 1$。 これは、各カラー クラスを 1 回吸収する必要があり、各吸収が単一の有効な操作であるという事実と一致します。 

交互またはクラスター化された値など、色が任意のパターンで繰り返される場合、セットの抽象化により、一意性を超えたすべての構造が削除されます。 操作は位置ではなく色の識別のみに依存するため、この単純化はすべての構成に有効です。
