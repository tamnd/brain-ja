 ## 問題の理解

 整数の配列が与えられます。 隣接するペアに対して特定のローカル操作を繰り返し適用することができます。 この演算では、2 つの隣接する値を取得し、ペアのビット単位の AND を計算し、その値を両方の要素に XOR します。 この変換後、ペアが変化し、任意の位置に同じルールを繰り返し適用することで配列が進化し続けます。 

目的は、プロセスをシミュレートすることではなく、操作を任意の回数、任意の順序で適用した後に達成できるすべての配列要素の最小合計を決定することです。 出力は、この最小達成可能な合計合計です。 

この制約により、配列の長さは最大 100 万、各値は最大約 2^30 になります。 これにより、操作をシミュレートしたり一連の動きを探索したりするアプローチは即座に除外されます。 状態空間が膨大であり、操作は任意に何度も適用できるため、繰り返しの変換を考慮すると、要素ごとに 1 つの操作を実行するだけでもすでにコストが高すぎます。 

素朴な解釈では、改善が不可能になるまで貪欲に操作を繰り返し適用することを示唆するかもしれませんが、これにはすでに微妙な落とし穴が隠されています。 このプロセスは明らかに単調ではなく、中間ステップではビットの相互作用に応じてローカル値が増減する可能性があります。 どのようなシミュレーション手法でも、操作の順序によっては最適でない固定点に陥る危険性があります。 

2 番目に考えられる誤解は、答えが個々のビットにのみ独立して依存すると仮定することです。 この操作では 2 つの隣接する要素を AND で結合し、その値を XOR で再分配するため、これも危険です。これにより、ビットがキャンセルされたり、異なる位置に導入されたりする可能性があります。 

## アプローチ

 主な困難は、操作によって実際に何が保存され、何が削除できるのかを理解することです。 

まずブルートフォースについて考えてみましょう。 到達可能なすべての配列に到達するまですべての一連の操作を試し、それらの間の最小合計を計算できます。 各操作はペアを変更し、任意のインデックスに繰り返し適用できます。 状態を効率的に表現したとしても、分岐因子は各ステップで n であり、シーケンスは安定化までに任意の長さになる可能性があります。 到達可能な状態の数は爆発的に増加するため、n が 20 のような小さな値を超えるかなり前に、このアプローチは実行不可能になります。 

転換点は、配列全体の単一ビットに何が起こるかを調べることです。 この演算ではビット単位の AND が使用されます。つまり、ビットは両方の要素に存在する場合にのみ転送できます。 次に、XOR により、両方の位置からその共有ビットが削除されます。 これは、キャンセル メカニズムを示唆しています。つまり、2 つの隣接する要素の両方が同じビット位置に 1 を含む場合は常に、そのビットを両方から削除できます。 

この観点から見ると、各ビット位置は他のビット位置とは独立して進化します。 固定ビットでは、この操作により隣接する位置にある 1 のペアを削除できますが、新しい 1 を作成することはできません。 したがって、各ビットについてできることは 1 の数を減らすことだけですが、隣接制約の構造により、恣意的なグローバル キャンセルが防止されます。 

重要な観察は、このビットを共有する連続要素の各接続コンポーネント内で、そのコンポーネントに 1 が 1 つだけ残るまで、1 のペアを繰り返しキャンセルできることです。 これは、1 の各連続セグメントにおいて、カウントのパリティによって 1 つの 1 が残るかどうかが決まると言うのと同じです。

したがって、各ビットについて、合計への最終的な寄与は、2 を法とした連続する 1 のセグメントの数に正確に相当します。これは、接続された各構造内の 1 の合計数が奇数か偶数かに帰着します。 すべてのビットを集計すると、貪欲な線形スキャンが行われます。各ビットを個別に処理し、各最大セグメントにそのビットが含まれる要素の数を追跡します。 

最後に、ビットは相互作用しないので、配列全体のすべてのビットの寄与を合計します。 この実装では、配列をスキャンし、隣接構造全体でビットごとのパリティ情報を維持し、最終的に可能な最小の合計を計算します。

 ## アルゴリズムのチュートリアル

 0 から 29 までの各ビットを独立して処理します。 

1. 固定ビットの場合、配列をスキャンし、隣接関係のキャンセルを通じて相互作用できる少なくとも 1 つの要素にビットが存在する最大セグメントを特定します。 現在のセグメントにアクティブな 1 がいくつ存在するかを概念的に追跡します。 
2. スキャン中、現在接続されているセグメントにこのビットが含まれる要素の数を示すパリティ カウンタを維持します。 ビットが存在しない位置に到達すると、セグメントは終了し、答えにパリティを提供することで問題を解決します。 
3. パリティが 1 の場合、このビットの避けられない 1 つの発生が最適な構成に残り、最終的な合計に 2^ ビットが寄与することを意味します。 
4. カウンタをリセットし、配列の終わりまで次のセグメントのスキャンを続けます。 

この手順がすべてのビットに対して繰り返され、寄与分が蓄積されます。 

### なぜ効果があるのか

 この操作では、隣接するビット間の同一ビットのペアを削除することのみが可能であり、新しいビットが導入されることはありません。 これは、ビットが出現する接続領域内で、ローカル キャンセルを繰り返すことで要素をペアにすることができることを意味します。 各操作ではビットの 2 つの出現が削除されるため、接続された領域内の出現のパリティのみが問題になります。 一連の操作によってこのパリティは変更できないため、不変となります。 したがって、最適な結果は、各ビット コンポーネントでできるだけ多くのペアを個別にキャンセルすることによって達成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    ans = 0

    for b in range(30):
        i = 0
        while i < n:
            if not (a[i] >> b) & 1:
                i += 1
                continue

            cnt = 0
            while i < n and ((a[i] >> b) & 1):
                cnt ^= 1
                i += 1

            if cnt:
                ans += (1 << b)

    print(ans)

if __name__ == "__main__":
    solve()
```コードは各ビットを反復し、ビットごとに 1 回配列をスキャンします。 すべての要素にビットが存在する連続ブロックごとに、XOR 累積を使用してパリティを追跡します。 ブロックが奇数の出現に寄与する場合、ビットはその値を答えに寄与します。 

内部ループ構造により、位置を再検討することがなくなるため、複雑さはビットごとに線形に保たれます。 ビット チェックはシフトによって行われ、これは一定時間です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、単一要素の配列です。 キャンセルは不可能であるため、アルゴリズムは各ビットを独立して処理し、その数値のすべてのビットを直接提供します。 入力用`7`、すべてのビット セグメントは奇数パリティを持つ単一ブロックであるため、出力はそのまま残ります。`7`。 

もう 1 つの特殊なケースは、すべて 0 の配列です。 すべてのビット スキャンはすべての位置を即座にスキップするため、セグメントは何も寄与せず、答えはそのままになります。`0`。 

3 番目のケースは、次のような交互パターンです。`1 2 1`。 ビット 0 の場合、発生は分離され、セグメント全体でパリティでキャンセルされます。ビット 1 の場合も同様で、完全なキャンセルが行われます。 このアルゴリズムは、ゼロ ビットが表示されるたびにセグメントを正しくリセットし、切断された領域全体で誤った蓄積が発生しないようにします。
