 ## 解決策
 ## 問題の理解

 パスグラフが与えられています$n$頂点、すべての頂点$i$に接続されています$i+1$。 この構造の上に、追加の隠れたエッジが追加されます。$(a, b)$が追加されており、厳密にそれらの間に少なくとも 1 つの頂点が存在することが約束されています。$a + 2 \le b$。 これにより、グラフ内にちょうど 1 つのサイクルが作成されます。 

余分なエッジを直接見ることはできません。 代わりに、次の形式でクエリを実行できます。$(l, r)$、システムは、間の最短経路かどうかを答えます。$l$そして$r$変更されたグラフでは、追加されたエッジが使用されます。 つまり、作成したショートカットが$(a, b)$間の距離を厳密に改善します$l$そして$r$ライン上の元のパスと比較します。 

エンドポイントを決定する必要があります$a$そして$b$このようなクエリは最大 50 個使用します。 

重要な構造上の事実は、余分なエッジがなければ、距離は直線であるということです。 余分なエッジを使用すると、その最短パスから恩恵を受けるペアは、非常に特殊な方法でサイクルを「またぐ」必要があります。ライン上の自然なパスは、飛び越えるパスよりも長くなります。$(a, b)$。 

以来$n$と同じ大きさにすることができます$10^6$、明示的に何かをシミュレートしたりスキャンしたりすることはできません。 各クエリは高価であるため、ソリューションではクエリごとに大量の情報を抽出する必要があり、通常は検索スペースが急激に減少します。 

単純な間違いは、隣接するペアをクエリしたり、すべてのペアをスキャンするとエッジ エンドポイントが明らかになる可能性があると考えることです。 たとえば、すべてを試してみると、$(l, r)$必要になるだろう$O(n^2)$クエリですが、これは完全に不可能です。 

微妙に間違ったアプローチは、回答が固定方向に沿って 0 から 1 に切り替わる場所を検出することでエンドポイントを見つけることができると想定することです。 これは、単一のインデックスでは述語が単調ではないため失敗します。ペアがショートカットを使用するかどうかは、1 つの座標だけではなく、両方のエンドポイントに同時に依存します。 

たとえば、隠れたエッジが$(2, 7)$、 それから$(1, 6)$使わないかもしれないけど、$(3, 8)$両方とも「右にシフト」されている場合でも、可能性があります。 単一の線形しきい値動作はありません。 

主な困難は、情報が 2 次元であるにもかかわらず、2 つの未知のエンドポイントを識別する必要があることです。 

## アプローチ

 ブルートフォースの見方は簡単です。 すべての候補ペアをテストできたら$(l, r)$、どちらが 1 を返すかを確認するだけです。正確に 1 つのペアが追加されたエッジに対応するため、これは正しいです。 ただし、これには次のことが必要です$O(n^2)$クエリ、これは中級者でも不可能$n$、ましてや$10^6$。 

重要な観察は、構造がツリーと 1 つのエッジであるため、最短パス クエリが間隔に関する幾何学的条件のように動作することです。 に対する答えは、$(l, r)$間隔があるかどうかのみに依存します。$[l, r]$直接のパスよりも迂回を短くする方法で、隠れたショートカットを「カバー」します。 

これは再構成できます。ショートカットはまさに次のような場合に役立ちます。$l$エッジの片側にあり、$r$が反対側にあり、ゲインは直線距離を超えます。 つまり、一連の肯定的な答えが変換された意味で連続した領域を形成し、二分探索を 2 回利用できます。1 回目は 1 つのエンドポイントを特定し、次にもう 1 つのエンドポイントを特定します。 

これをロック解除する標準的な方法は、一方のエンドポイントを修正し、単調性を使用してもう一方のエンドポイントを検索することです。 直したら$l = 1$、その後、$r$増加すると、クエリは最終的にちょうど次の時点で true になります。$r$隠れたエッジの遠い端点を通過します。 これにより、1 つのエンドポイントに対するクリーンな二分探索が可能になります。 1 つのエンドポイントがわかったら、それを固定し、同じアイデアを繰り返してもう 1 つのエンドポイントを見つけることができます。 

したがって、問題は、巨大な領域で 2 つの未知の値を見つけることから、単調な述語に対する 2 つの二分探索に減少します。$O(\log n)$クエリ。

 ## アルゴリズムのチュートリアル

 クエリ間隔の一方のエンドポイントを修正すると、もう一方のエンドポイントでは応答が単調になるという事実に基づいています。 

1. 左端を 1 に固定し、最小値を二分探索します。$r$クエリが$(1, r)$1 を返します。これは遠方のエンドポイントを識別します$b$。 単調性は、拡張するにつれて、$r$、ショートカットの恩恵を受ける可能性のある頂点のみを含めることができます。 
2. 1回$b$知られているので、見つける必要があります$a$。 今検索します$l$範囲内で$[1, b-2]$制約があるため$a + 2 \le b$。 
3. 候補者にとって$l$、クエリ$(l, b)$。 答えが 1 の場合、それは、$l$は、パスが追加されたエッジを使用する形で、まだショートカットの反対側にあるため、検索を左に移動します。 それ以外の場合は、右に進みます。 
4. 二分探索は有効な最小値または最大値に収束します。$l$述語をどのように定義するかによって異なります。 次に、対称条件を検証して特定します。$a$。 
5. 出力$(a, b)$両方のエンドポイントが識別されたら。 

微妙なのは、1 つのエンドポイントが固定されている場合にのみ述語が単調になることです。 片側を修正しないとクエリの動作に順序が付けられないため、2 段階の検索が不可欠です。 

### なぜ効果があるのか

 グラフは線に 1 つのコードを加えたものであるため、最短経路の改善はそのコードを使用することによってのみ引き起こされます。 固定エンドポイントの場合、もう一方のエンドポイントを拡張しても、コードが最短パス上にある可能性が高まるだけです。これは、間隔を延長するだけであり、ショートカットを使用する可能性を「失う」ことはできないためです。 これにより、二分探索に適した単調な述語が作成されます。 各フェーズでは 1 つのエンドポイントが分離され、一方のエンドポイントが判明すると、もう一方のエンドポイントはライン上の標準的なしきい値検出問題になります。 

## Python ソリューション```python
import sys

input = sys.stdin.readline
print = sys.stdout.write

def ask(l, r):
    sys.stdout.write(f"? {l} {r}\n")
    sys.stdout.flush()
    return int(sys.stdin.readline().strip())

def answer(l, r):
    sys.stdout.write(f"! {l} {r}\n")
    sys.stdout.flush()

def find_b(n):
    lo, hi = 1, n
    while lo < hi:
        mid = (lo + hi) // 2
        if ask(1, mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

def find_a(b):
    lo, hi = 1, b - 1
    while lo < hi:
        mid = (lo + hi) // 2
        if ask(mid, b):
            hi = mid
        else:
            lo = mid + 1
    return lo

def main():
    n = int(input().strip())
    b = find_b(n)
    a = find_a(b)
    answer(a, b)

if __name__ == "__main__":
    main()
```インタラクションは、標準出力の単純なラッパーを通じて処理されます。 インタラクターは同期通信を期待しているため、すべてのクエリはすぐにフラッシュされます。 

機能`find_b`固定左端点 1 の場合、間隔が隠れたコード端点の影響を含めるのに十分な大きさになると述語が true になると仮定して、二分探索を実行します。 答えが 1 となる最小の位置を絞り込んで検索します。 

機能`find_a`次に、検出されたエンドポイントを修正し、同じ単調な動作を使用して反対側を検索しますが、今度は左側の境界を越えます。 

実装における一般的な落とし穴は、インタラクターがクエリのたびにフラッシュする必要があることを忘れることです。 もう 1 つは、次の場合にバイナリ検索の境界を誤って処理することです。$b$1に近いか、$n$制約はあるものの、$a + 2 \le b$有効な検索間隔を保証します$a$。

 ## 特殊なケース

 エッジ ケースの 1 つは、隠れたエッジが境界に非常に近い場合です。$(1, 3)$。 この場合、二分探索は、$b$クエリがあるためまだ機能します$(1, mid)$非常に早い段階で正になり、右側の境界がすぐに 3 まで崩れます。2 回目の検索で$a$その後、非常に短い間隔で動作し、すぐに収束します。 

もう 1 つのケースは、次のようなエッジがほぼ最大の場合です。$(n-2, n)$。 最初の検索では範囲の終わり近くの 1 のみが返されるため、ほとんどのクエリは負になります。 二分探索は正の分布を仮定せず、単調性のみを仮定するため、これは依然として正しく処理されます。 

最後のケースは、次のようにエッジが中央にある場合です。$(n/3, 2n/3)$。 どちらのバイナリ検索も対称的に動作し、偏りなく対数ステップで収束します。
