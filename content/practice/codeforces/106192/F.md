 ## 問題の理解

 目標値が与えられている$n$、そしてそれを選択された構成要素の合計として表したいと考えています。 各構成ブロックには「べき乗」があり、そのべき乗が正確に素数であるブロックが無制限に供給されます。ただし、1 も素数と見なされるという特別なルールがあります。 

したがって、利用可能なコンポーネントは次のとおりです$1, 2, 3, 5, 7, 11, \dots$、これらの数値の任意の複数セットを選択できます。 表現のコストは選択されたコンポーネントの数であり、それらの合計は正確に一致する必要があります。$n$。 タスクは、必要なコンポーネントの数を最小限に抑えることです。 

入力は単一の整数です$n$、 まで$10^9$したがって、以下のすべての素数を列挙しようとするソリューションは、$n$、または最大範囲全体で DP を実行します。$n$、失敗します。 線形または偶数$O(n)$アプローチは直ちに不可能であり、$O(n \log n)$限界をはるかに超えています。 

意味のある演算のみが、数値の範囲ではなく数値の構造に依存する必要があります。 

微妙なエッジケースが現れるのは、$n = 1$。 1 自体が有効なコンポーネントであるため、答えは 1 です。もう 1 つの興味深いケースは次のような場合です。$n$は大きな素数です。 この場合、数値自体を 1 つの要素として捉えることができるため、最適な答えは 1 のままです。 

素朴なアプローチでは、数値を常に小さな素数に分割したいと考えるかもしれませんが、それは常に有益であるとは限りません。$n$それ自体が素数または 1 の場合、常に許可されます。 

## アプローチ

 直接的な強引なアイデアは、これを最短経路またはナップザックのような問題として扱うことです。 素数のすべての組み合わせを試し、それらを繰り返し減算します。$n$、ゼロに達するまでに使用される要素の最小数を追跡します。 これは本質的に、コインの値がすべて素数 (1 を含む) である無制限のコイン変更問題です。 標準的な DP は次のように定義します。$dp[x]$コンポーネントの最小数の合計として$x$、すべての素数にわたる遷移$p \le x$、更新中$dp[x] = \min(dp[x], dp[x-p] + 1)$。 

これは正しいですが、すぐには実行できません。 最大の素数の数$10^9$十分に大きいため、生成するだけでもコストがかかり、状態ごとにそれらを反復処理すると、おおよその結果が得られます。$O(n \pi(n))$、それは限界をはるかに超えています。 

重要な観察は、利用可能な数値の構造が問題を崩壊させるということです。 1 が利用可能なため、任意の整数を常に形成できます。2 は素数であるため、すべての整数はほとんどの 2 とおそらく 1 つの 1 を使用して分解できます。これはすでにパリティが構造を支配していることを示唆しています。考慮する必要があるのは、最小数の大きな成分を使用して合計を作成できるかどうかだけです。 

それをより正確に確認する方法は、実際に何がコンポーネントの数を減らすのかを尋ねることです。 大きな素数を使用する$p$置き換える$p$単一要素のコスト 1 または 2 の単位。 したがって、プライムを使用するたびに、$p$、より小さなユニットを使用する場合と比較して、コンポーネントの数を減らします。 要素あたりの可能な限りの削減は、可能な限り最大の単一チャンクを使用することによって実現されます。$n$それ自体いつ$n$プライムです。 

したがって、最適な戦略は常に最も強い意味で貪欲です。つまり、整数がすでに素数か 1 であるか、そうでない場合は 2 に分割し、必要に応じて 1 つの 1 に分割することになります。 これは単純な特徴付けにつながります。つまり、任意の偶数は次のように形成できます。$n/2$一方、奇数の合成数は、2 の 1 つを 3 に置き換えること (または、1 を 1 つと残りの 2 を同等に使用すること) によって利益が得られます。$(n-3)/2 + 1$。 これを単純化すると、$\lfloor n/2 \rfloor + 1$みんなのために$n > 1$、ただし特殊な場合$n = 2$そして素数は慎重に扱わなければなりません。 

最後の単純化は、答えは次のことによってのみ依存するということです。$n$1かそうでないか。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$n$。 かどうかをすぐに確認します$n = 1$1 は明示的に有効なコンポーネントであり、それ以上分解できないため、答えは 1 に固定されます。 
2. あらゆる場合$n > 1$、それを観察してください$n$それ自体は素数であるか (コンポーネントが 1 つで十分である)、または 2 と 3 を使用して表現できるため、常に素数を使用して表現できます。 
3. 2 つの構造を比較します: 単一コンポーネントを使用$n$素数の場合、そうでない場合は小さな素数のみを使用します。 1 が使用可能なため、いつでも 1 のみを使用するようにフォールバックできますが、これは次の場合を除いて最適とは言えません。$n = 1$。 
4. 合成数は利用可能なセットから最大 2 つの素数に分割できるため (2 と 3 の組み合わせを使用)、この設定では最適な構成に 2 つを超える成分は必要ありません。 
5. したがって、すべての人にとって$n > 1$の場合、コンポーネントの最小数は 1 です。$n$は素数、それ以外の場合は 2。 

### なぜ効果があるのか

 重要な特性は、1 がユニバーサル フィラーであり、2 が最小の非単位ビルディング ブロックであることです。 合成数はそれ自体が素数であるか、または最大 2 つの許可された成分を使用して表現できます。2 を使用すると常にパリティの問題を軽減し、3 または 1 を使用して奇数を調整できるためです。どの構成でも 1 つ未満の成分を使用することはできず、素数以外の成分は使用できません。$n > 1$は単一のコンポーネントで形成できないため、答えは素数に応じて 1 または 2 になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(x: int) -> bool:
    if x <= 1:
        return False
    if x <= 3:
        return True
    if x % 2 == 0:
        return x == 2
    i = 3
    while i * i <= x:
        if x % i == 0:
            return False
        i += 2
    return True

n = int(input())

if n == 1:
    print(1)
elif is_prime(n):
    print(1)
else:
    print(2)
```このソリューションは構造観察を直接エンコードします。 素数チェックが必要なのは、単一の成分 (それ自体) を使用して表現できるのは素数だけですが、すべての合成数には少なくとも 2 つの成分が必要です。これは、それらに等しい単一の許可された要素がないためです。 特別な場合$n = 1$1 は明示的に有効なコンポーネントであるため、個別に処理されます。 

素数性テストは十分に最適化されています。$10^9$トライアル分割を使用して最大$\sqrt{n}$、1秒未満の速さです。

 ## 特殊なケース

 のために$n = 1$の場合、1 はコンポーネントとして明示的に許可されているため、アルゴリズムは直接 1 を返します。 素数ロジックは必要ないため、1 が複合として誤って分類されるのを防ぎます。 

のために$n = 2$の場合、2 は素数であるため、アルゴリズムは 1 を返します。 これも最小の偶数ですが、分解する必要はなく、チェックによって正確に識別されます。 

次のような大きな素数の場合$10^9 + 7$、ループは最大までしか実行されません。$\sqrt{n}$これは約 31623 回の反復であり、十分に制限内であり、正しく 1 を返します。
