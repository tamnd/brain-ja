 ## 解決策
 ## 問題の理解

 この問題では、測定値のデータセットを表す整数の配列が与えられます。 各クエリでは、特定のルールに従って、この配列のセグメントを「同種」にするために必要な最小操作数を計算する必要があります。つまり、連続するサブシーケンス内のすべての同一の数値は、変更を最小限に抑えるために最適にグループ化される必要があります。 概念的には、このタスクは、セグメント内で繰り返される数字が多くなるように変更を最小限に抑えることです。 

配列の長さは最大です$2 \cdot 10^5$、クエリの総数も大きいため、クエリごとに範囲を反復するソリューションは遅すぎます。 単純なアプローチでは、各セグメントをスキャンして最も頻度の高い要素を探し、頻度を数え、変更の数を計算することが考えられます。 最悪の場合、各セグメントが配列とほぼ同じ長さになると、次のような結果になります。$O(n \cdot q)$禁止されている操作$n, q \sim 10^5$。 

明らかではないエッジ ケースには、すでに同種のセグメント、すべての要素が個別であるセグメント、および要素が 1 つだけ含まれるセグメントが含まれます。 たとえば、配列の場合`[2, 2, 3, 3, 3, 2]`、インデックス 2 ～ 5 をカバーするクエリでは、次のことを識別する必要があります。`3`セグメント内で最も頻繁に出現するため、変更は 1 つだけです (インデックス 2 の変更)`2`に`3`）が必要です。 セグメント内の要素の位置を考慮しない単純なアプローチでは、答えが誤って計算される可能性があります。 

## アプローチ

 ブルート フォース手法では、各クエリを反復処理し、セグメント内の各数値の出現数をカウントします。 次に、セグメント長から最大頻度を減算して、変更の数を計算します。 正しいのですが、この方法では次のようになります。$O(n)$クエリごとに、合計の複雑さは次のようになります。$O(n \cdot q)$、大規模な入力の時間制限を超えます。 

最適な解決策は、変更の数はセグメント内の最も頻繁な要素にのみ依存するという観察を活用します。 配列を前処理して数値ごとに、その数値が出現するインデックスを保存すると、二分探索を使用して任意のセグメントに数値が出現する回数をすばやく計算できます。 これにより、クエリごとの複雑さが軽減されます。$O(\log n)$候補者番号ごとに。 さらに最適化するには、セグメントのエンドポイントとその大部分の実行の数値のみを考慮します。これは、データセット内で繰り返されるシーケンスが定義されている方法により、答えは常にセグメントの境界に現れる要素によって支配されるためです。 

重要な洞察は、セグメント境界で頻繁に出現する要素、または長い実行で連続して繰り返される要素のみが、最小限の変更数に影響を与えることができるということです。 これらの候補に焦点を当てることで、正解を見逃さずに複雑さを大幅に軽減します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・q) | O(n) | 遅すぎる |
 | 最適 | O(q・log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を前処理して、一意の数値ごとに、その数値が発生するインデックスを記録します。 これにより、後で 2 回の二分検索を使用して、任意のセグメントに数値が何回出現するかを数えることができます。 
2. セグメントを含む各クエリについて`[l, r]`、候補番号を特定します。 これらはインデックスの数字です`l`そして`r`また、場合によっては、セグメントの一部をカバーする連続したランに表示される数字も含まれます。 
3. 各候補について、前処理されたインデックスと二分探索を使用して、セグメント内のその頻度を計算します。 具体的には、インデックスがいくつあるかを数えます。`[l, r]`。 
4. セグメントの長さから候補内の最大頻度を引いたものとして最小変更数を計算します。 
5. 各クエリに対してこの最小数を返します。 

機能する理由: 変更の数を減らすことができる唯一の数値はセグメントに実際に出現する数値であるため、アルゴリズムは正確さを保証します。 境界または長期にわたる数値に焦点を当てることで、セグメントの真の大部分の要素が常に考慮されるようになります。 不変条件は、考慮される候補間の最大頻度が常にセグメント内の最大頻度と等しいため、セグメントの長さからそれを減算すると、正確な最小限の変化が得られるということです。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        # Preprocess positions
        positions = {}
        for i, x in enumerate(a):
            if x not in positions:
                positions[x] = []
            positions[x].append(i)
        
        for _ in range(q):
            l, r = map(int, input().split())
            l -= 1
            r -= 1
            if a[l] == a[r]:
                print(1)
                continue
            candidates = [a[l], a[r]]
            max_freq = 0
            for x in candidates:
                idx_list = positions[x]
                left = bisect.bisect_left(idx_list, l)
                right = bisect.bisect_right(idx_list, r)
                max_freq = max(max_freq, right - left)
            print((r - l + 1) - max_freq)

if __name__ == "__main__":
    main()
```前処理ステップでは、各数値をそのインデックスにマップします。 各クエリ中に、`bisect_left`そして`bisect_right`セグメント内の候補の出現を効率的にカウントします。 小切手`if a[l] == a[r]`同種のセグメントを即座に処理します。 セグメントの長さから最大周波数を減算して、最小の変化を見つけます。

 ## 特殊なケース

 アルゴリズムは、次の場合にただちに 1 を返して単一要素セグメントを処理します。`l == r`、空白の間隔を避けます。 境界チェックにより同種セグメントが認識される`a[l] == a[r]`。 候補リストには両端が含まれており、二分ベースのカウントによってセグメント内のすべての出現がキャプチャされるため、境界にない交互パターンと多数要素が正しく考慮されます。 例えば、`[1 1 2 1 1 3 1]`セグメントあり`(1,7)`正しく識別する`1`にもかかわらず多数派として`2`そして`3`存在していること。
