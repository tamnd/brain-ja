 ## 解決策
 ## 問題の理解

 私たちは、ビット文字列にちょうど半分の 0 と半分の 1 が含まれている場合に、その文字列を「バランスが取れている」とマークする量子オラクルを実装するように求められています。 入力は、文字列のビットを表す量子ビットのリストと、出力を表す追加の量子ビットです。 概念的には、入力ビット列がバランスされている場合、演算は出力量子ビットを反転し、そうでない場合は変更しないままにする必要があります。 量子ビットは古典的なビットではありません。 それらは重ね合わせて存在する可能性があるため、オラクルはすべての基底状態に対して同時に線形に動作する必要があります。 許可されている操作は、X ゲート (量子 NOT) とその制御されたバージョンのみです。 任意の回転を測定したり適用したりすることはできないため、解は純粋に単一で可逆的である必要があります。 

制約はある意味では非常に厳しいものです。$N \le 10$、小さいです。 これは、制御された操作を設計する目的では、すべての基底状態の総当り列挙が実現可能ですが、実行時に個々の古典的な文字列をチェックするのではなく、依然としてユニタリ演算子として解を表現する必要があることを意味します。 という事実$N$バランスの取れた弦が常に明確に定義されていることも保証します。 主なエッジ ケースは、すべて 0 またはすべて 1 の文字列であり、出力量子ビットは変更されないままにする必要があります。$N/2$ビットは 1 ですが、分散方法が異なります。 合計数をチェックせずに、「1」ごとに出力量子ビットを反転しようとする単純なアプローチは間違っています。 

## アプローチ

 この問題について考える最も素朴な方法は、入力内の 1 の数を数え、その数が等しい場合に出力を反転することです。$N/2$。 古典的な設定では、ビットを合計して比較するということは簡単です。 量子コンピューティングでは量子ビットを測定できないため、量子ビットを直接数えることはできません。 純粋に単一のアプローチでは、制御された X ゲートの組み合わせとして条件をエンコードする必要があります。 小型用$N$理論的には、次のすべての組み合わせに対して複数制御された X ゲートを生成できます。$N/2$出現する可能性のある位置。 これが機能する理由は、$N$は最大でも 10 です。ブルート フォースには、次の構築が含まれます。$C(N, N/2)$このようなゲートは実現可能です。$C(10,5)=252$。 

最適なアプローチは、基底状態の出力量子ビットを正確に反転するだけでよいという事実を活用することです。$N/2$もの。 このような各基本状態は、その文字列に一致するように設定された制御を備えたマルチ制御 X ゲートに対応します。 たとえば、次の場合$N=4$各文字列について、その正確な構成にある入力で制御される出力量子ビットに X を適用します。 これにより、オラクルの正しい動作が生成され、制御される操作の総数は少ないままになります。$N \le 10$。 これにより、補助的な量子ビットや複雑な演算回路が不要になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N * N) | O(N) | N ≤ 10 で許容 |
 | マルチコントロールゲート | O(C(N, N/2) * N) | O(N) | 効率的で受け入れられる |

 ## アルゴリズムのチュートリアル

 1. 長さのすべての基底文字列を決定します。$N$正確に含まれるもの$N/2$もの。 これは、標準的な組み合わせアルゴリズムを使用して組み合わせて行うことができます。 
2. バランスの取れた文字列ごとに、この文字列と一致させるために各入力量子ビットを 0 にするか 1 にするかを決定します。 ゼロにする必要がある位置については、状態 |0> にある量子ビットを制御する必要があります。これは、X ゲートを適用して量子ビットを反転し、それを制御として使用してから反転することによって行われます。 
3. バランスストリングで指定された構成内のすべての入力量子ビットを制御として、出力量子ビットにマルチ制御 X ゲートを適用します。 これは、入力が平衡文字列と正確に一致する場合にのみ、出力量子ビットを反転します。 
4. 可逆性を維持するために、ゼロに設定された制御に対して反転された入力量子ビットを元の状態に復元します。 

機能する理由: 入力量子ビットの各基底状態は、単一の計算パスに対応します。 複数制御された X ゲートは、バランスの取れた文字列に正確に一致する基底状態に対してのみ出力量子ビットを反転します。 量子演算は線形であるため、これらの基底状態の重ね合わせは正しく動作し、すべての入力に対して必要なオラクル変換を同時に生成します。 

## Python ソリューション

 これは Q# の量子問題であるため、古典的な Python の解決策はありません。 代わりに、正しい Q# 実装を次に示します。```
namespace Solution {
    open Microsoft.Quantum.Intrinsic;
    open Microsoft.Quantum.Canon;

    operation Solve(inputs : Qubit[], output : Qubit) : Unit is Adj+Ctl {
        let n = Length(inputs);
        let half = n / 2;

        // Generate all combinations of indices of length `half`
        for idxs in Combinations(0..n-1, half) {
            using (aux = Qubit[0]) {
                mutable controls = new Qubit[0];
                // For each position, decide whether to invert to control on 0
                for i in 0..n-1 {
                    if i in idxs {
                        set controls += [inputs[i]];
                    } else {
                        X(inputs[i]);
                        set controls += [inputs[i]];
                    }
                }
                Controlled X(controls, output);
                // Restore inputs flipped for 0-control
                for i in 0..n-1 {
                    if not (i in idxs) {
                        X(inputs[i]);
                    }
                }
            }
        }
    }
}
```このソリューションは、バランスのとれたビット列ごとに複数制御された X を生成し、入力が一致する場合にのみ出力量子ビットを反転します。 ゼロコントロールに一致するように反転された入力は、単一のプロパティを維持するために直ちに復元されます。 

## 実用的な例

 のために$N=4$、バランスのとれた文字列は 0011、0101、0110、1001、1010、1100 です。入力が |0101> の場合、アルゴリズムは組み合わせ [1,3] を選択し、その構成内の量子ビットに制御を設定し、制御 X を出力に適用します。 入力が 1 つの平衡文字列と正確に一致するため、出力量子ビットは |1> に反転します。 入力が |0001> の場合、どの組み合わせも完全に一致しないため、Controlled X は起動されず、出力は |0> のままになります。 

| ステップ | 入力 | コントロールセット | 出力 |
 | --- | --- | --- | --- |
 | イニシャル | 0101 | - | 0 |
 | 0011を適用 | それに応じて量子ビットが反転されました。 0 | 0 |
 | 0101を適用 | 一致 | 反転出力 | 1 |
 | 0110、1001、...を適用します。 一致しません | - | 1 |

 これにより、アルゴリズムがバランスの取れた弦に対してのみ出力を正しく反転していることが確認できます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(C(N,N/2) * N) | 各組み合わせには、最大 N 個の制御された X 操作が必要です。 
| スペース | O(N) | 制御量子ビットとループ変数の一時ストレージのみ |

from itertools import combinations

def balanced_strings(n):
    half = n // 2
    return [''.join(['1' if i in comb else '0' for i in range(n)]) for comb in combinations(range(n), half)]

assert balanced_strings(4) == ['0011','0101','0110','1001','1010','1100'], "N=4"
assert balanced_strings(2) == ['01','10'], "N=2"
assert balanced_strings(6)[0] == '000111', "N=6 first combo"
assert len(balanced_strings(6)) == 20, "N=6 total combinations"

 ## 特殊なケース

 N=2 の場合、バランスのとれた弦は 01 と 10 だけです。00 や 11 のような入力では、出力は変更されません。 このアルゴリズムは、00 または 11 に対してマルチ制御 X ゲートを正しく適用しません。最大のケース N=10 では、各出力フリップが 1 つの基底状態の一致に正確に対応するため、アルゴリズムは平衡ストリングの数を線形にスケールし、正確さを維持します。 組み合わせはプログラムによって生成されるため、off-by-one エラーは発生しません。
