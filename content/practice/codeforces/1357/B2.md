 ## 問題の理解

 タスクは、3 で割り切れる数値を表すビット文字列をマークする可逆量子オラクルを実装することです。入力は、バイナリ整数をリトルエンディアン順でエンコードする最大 8 量子ビットのレジスタと、ターゲット ビットとして機能する追加の量子ビット 1 つです。 エンコードされた整数が 3 で割り切れる場合に限り、演算ではこのターゲット ビットを反転する必要があります。 

重要な要件は、変換が単一である必要があるということです。つまり、古典的な意味で情報を「計算して上書き」することはできません。 代わりに、すべての基底状態について、入力状態が保存され、入力のブール述語に基づいて出力量子ビットのみが切り替えられるように、システムは一貫して進化する必要があります。 

N ≤ 8 という制約は重要です。 これは、最大 2⁸ = 256 の可能な入力基底状態があることを意味します。 この小さなドメイン サイズにより、3 で割り切れるコンパクトな算術回路を導出する代わりに、考えられるすべての入力を列挙することでオラクルを明示的に構築することが可能になります。 

ここでの単純な間違いは、補助構造を使用せずに量子ビットに対して直接算術論理を使用して 2 進数を解釈し、割り算を計算しようとすることです。 これはすぐに不必要に複雑になり、X ゲートと制御された X ゲートのみが許可されるという制限に違反する危険があります。 

もう 1 つの微妙なエッジ ケースは、オラクルが重ね合わせに対して正しく動作する必要があることを忘れていることです。 測定値を誤って「分岐」したり、古典的な実行を想定したりすると、線形性が崩れてしまいます。 たとえば、|3⟩ と |4⟩ の重ね合わせでは、出力量子ビットはグローバルではなく |3⟩ コンポーネントでのみ反転する必要があります。 

## アプローチ

 強引な古典的なアプローチは、考えられるすべての x に対して関数 f(x) = 1 if x mod 3 = 0 を評価し、それを可逆回路にエンコードすることです。 入力空間のサイズは最大 256 であるため、真理値表を直接構築できます。 

これを量子安全な演算に変換するには、出力量子ビットに対する制御された NOT 演算のシーケンスとして関数を表現する必要があります。 各操作は 1 つの入力割り当てだけを対象とします。 課題は、量子ゲートが本来はビット列の「等価性チェック」ではないことですが、固定パターンに一致する各入力ビットで制御が条件付けされる、複数制御された X ゲートを使用することで等価性をシミュレートできることです。 

重要なアイデアは、3 で割り切れる有効な入力 x ごとに、すべての量子ビットがポジティブ コントロールとして機能するように制御基底を一時的に変換するということです。 パターン内のビットが 0 の場合、制御された操作を適用する前後でその量子ビットを反転します。 これにより、「0 のコントロール」が 1 の標準コントロールに変換されます。 

これにより、算術回路の設計から小さな有限セットの基底状態の列挙と条件付き反転の適用までの問題が軽減されます。

 ## アルゴリズムのチュートリアル

 考えられるすべてのビット文字列を反復処理し、3 で割り切れるビット文字列に対して出力反転を正確にアクティブにすることで、オラクルを構築します。

1. 0 から 2^N − 1 までのすべての整数 x を列挙します。各 x は、リトルエンディアン形式の入力量子ビットの基底状態に対応します。 これにより、考えられるすべての量子基底入力の完全な説明が得られます。 
2. 各 x について、x mod 3 が 0 に等しいかどうかを確認します。割り切れない場合は、この状態に対して何もせず、次に進みます。 これにより、有効な状態に対してのみ Oracle サポートを構築することが保証されます。 
3. 割り算を満たすすべての x について、出力量子ビットをターゲットとする多重制御 X ゲートを構築します。 コントロールは、入力レジスタが x のバイナリ表現と正確に一致することを強制します。 
4. 固定ビット列パターンとの等価性を強制するために、各量子ビットを個別に処理します。 x の i 番目のビットが 1 の場合、その量子ビットに対してポジティブ コントロールを使用します。 それが 0 の場合、X ゲートでその量子ビットを一時的に反転し、制御された操作を適用してから反転します。 これにより、事実上、「ゼロのコントロール」が標準コントロールに変わります。 
5. 制御された X を出力に適用した後、反転した入力量子ビットを復元します。これにより、全体の操作が可逆性を維持し、無関係な基底状態が乱されなくなります。 

### なぜ効果があるのか

 各基底状態 |x⟩ は、それ自体に対応する制御のシーケンスを 1 つだけアクティブにします。 x が 3 で割り切れる場合、制御された X 操作が 1 つだけトリガーされ、出力量子ビットが反転されます。 3 で割り切れない場合は、その構成と一致する構築されたゲートがないため、出力は変更されません。 構築は基底状態にわたって線形であるため、重ね合わせは線形拡張によって正しく展開されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、オール ゼロの状態です。 これは 3 で割り切れる整数 0 に対応するため、重ね合わせのコンテキストに関係なく、入力が |00…0⟩ の場合、出力量子ビットは常に反転する必要があります。 割り切れるセットにはマスク = 0 が含まれるため、この構造はこれを正しく処理します。 

もう 1 つのエッジ ケースは、複数の入力量子ビットが 0 である場合です。ゼロ ビットの制御を反転することを誤って忘れた場合、そのような状態に一致するゲートは存在せず、多くの有効な x 値の正確性が損なわれます。 一時的な X トリックにより、0 と 1 の両方の制約が対称的に処理され、正確なパターン マッチングが維持されます。 

最後のエッジ ケースは、一部の分岐のみが可算性を満たす重ね合わせ状態です。 Controlled-X の線形性により、それらの分岐のみが出力反転をトリガーし、無関係な基底状態間で干渉が発生しないことが保証されます。
