 ## 問題の理解

 アイテムのセットには隠された構造が与えられており、各アイテムは 2 つのクラスのいずれかに属しますが、ラベルを直接観察することはできません。 代わりに、情報を取得する唯一の方法は、データセットに関する慎重に選択されたクエリに応答するオラクルを介することです。 

各クエリは、データの基礎となる「量子」表現と対話し、隠れた分類に間接的に依存する集約された情報を返します。 タスクは、対話型またはクエリが制限された環境の制約の下で、できるだけ少ないクエリを使用して、すべてのアイテムの完全な分類を回復することです。 

アルゴリズムの観点から見ると、これはアクセス制限下での再構成の問題です。個々の要素を検査することはできず、ラベルへのランダム アクセスを想定することもできません。 すべての情報は、隠れた状態の線形または組み合わせのプロパティを明らかにする構造化クエリを通じて抽出する必要があります。 

この制約は、各要素を個別にクエリしたり、すべてのサブセットを徹底的にテストしたりするような単純な戦略が実行不可能であることを意味します。 項目数が 10^5 のオーダーである場合、要素ごとに O(n) の高価な対話型操作を実行するアプローチでも、すでに時間とクエリの両方の予算を超過する危険性があります。 サブセットの数が指数関数的に増加し、オラクルの構造を利用せずに枝刈りを行うことができないため、サブセットを暗黙的に列挙するソリューションは直ちに除外されます。 

素朴な推論でよくある失敗例は、ローカルなクエリによってローカルな情報が明らかになるという仮定です。 たとえば、小さなサブセットをクエリすると単一の要素のラベルが分離されると仮定すると、通常、オラクルの応答はクエリされたすべての要素にわたって複雑になるため、解決策は破綻します。 もう 1 つの微妙な落とし穴は、答えを貪欲に再構築しようとすることです。クエリは単一変数の独立した観測値ではないため、初期の間違った推論が後の推論を汚染します。 

間違ったアプローチの具体例としては、シングルトン セットを繰り返しクエリし、応答がラベルを直接エンコードしていると想定することが挙げられます。 このようなシナリオでは、出力にグローバル パリティまたは集計変換が反映される可能性があり、解釈が無効になり、データセット全体で一貫した誤分類が発生する可能性があります。 

## アプローチ

 ブルート フォース戦略は単純です。要素ごとに、その要素を他のすべての要素から分離するクエリを設計し、応答からそのクラスを推測します。 最悪の場合、これには O(n) クエリが必要となり、各クエリにはシステムとの完全な対話が含まれます。 サブセットの構築または評価により各クエリ自体の処理コストが O(n) の場合、全体の複雑さは O(n^2) になります。これは大規模なデータセットには遅すぎ、一般的な対話型の制約を超えます。 

重要な洞察は、オラクルが隠れた構造に対して線形に動作するということです。 個々の要素を分離しようとするのではなく、各クエリをラベルの未知のベクトルに対する線形方程式として扱います。 問題がこのように解釈されると、再構成は標準的な線形代数タスクになります。つまり、すべての未知数を決定するのに十分な独立した方程式を収集します。 

これにより、問題は「各要素を個別に識別する」という問題から「線形測定から未知のバイナリ ベクトルを回復する」という問題に変換されます。 この角度から見ると、最適な戦略は、空間の基礎を形成するクエリを選択し、すべての未知の要素が少なくとも 1 つの測定に一意に寄与するようにすることです。

データセット 4 では、構造はさらに有利です。クエリ応答は十分に適切に動作するため、慎重に選択したクエリの対数または線形数を使用してフルランク システムを構築し、GF(2) に対するガウス消去法を使用してそれを解くことができます。 これにより、要素ごとの適応的なクエリが完全に回避されます。

 ## アルゴリズムのチュートリアル

 隠れラベルをバイナリ ベクトルとしてモデル化し、各位置が未知の分類に対応します。 各クエリは、モジュロ 2 演算に基づいてこれらの値の線形結合を返し、事実上方程式系を与えます。 

1. 線形独立システムを形成するクエリ ベクトルのセットを構築します。 各クエリは、その応答が未知の変数のさまざまなサブセットを含む個別の方程式を与えるように設計されています。 これを行う理由は、貴重な情報を無駄にする冗長なクエリを確実に排除するためです。 
2. 各クエリ結果を拡張行列の行として保存します。 各行は 1 つの線形方程式に対応し、各列は隠れベクトルの 1 つの変数に対応します。 これにより、インタラクティブなプロセスが静的な線形システムに変換されます。 
3. 構築された行列に対して GF(2) に対してガウス消去法を実行します。 このステップでは、システムを系統的に行階層形式に縮小し、変数を 1 つずつ分離します。 システムのバイナリの性質により、算術演算が XOR 演算に単純化されます。 
4. 行列が縮小されたら、逆置換を実行して各変数を復元します。 解決された各変数は、以前の方程式の依存関係を解決するためにすぐに使用され、システム全体の一貫性が確保されます。 
5. 最後に、すべての要素の再構成された分類を出力します。 

これが機能する理由は、構築されたクエリ セットがシステムのフル ランクを保証しているためです。 すべての隠れ変数は少なくとも 1 つの独立した方程式に寄与し、ガウス消去法により元のシステムと縮小された形式の間の等価性が維持されます。 線形制約を維持せずに情報を破棄することは決してないため、最終的な解決策は元のオラクル応答をすべて満たす必要があり、一貫した一意の分類になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gauss_xor(mat, n, m):
    row = 0
    for col in range(m):
        pivot = -1
        for i in range(row, n):
            if mat[i][col]:
                pivot = i
                break
        if pivot == -1:
            continue
        mat[row], mat[pivot] = mat[pivot], mat[row]

        for i in range(n):
            if i != row and mat[i][col]:
                for j in range(col, m + 1):
                    mat[i][j] ^= mat[row][j]

        row += 1
        if row == n:
            break

def main():
    n = int(input().strip())
    mat = []

    for _ in range(n):
        row = list(map(int, input().split()))
        mat.append(row)

    m = n

    gauss_xor(mat, n, m)

    ans = [0] * n
    for i in range(n):
        for j in range(n):
            if mat[i][j]:
                ans[j] = mat[i][n]
                break

    print(*ans)

if __name__ == "__main__":
    main()
```この実装では、クエリ システムのバイナリ行列表現を構築し、XOR ベースのガウス消去法を使用してそれを削減します。 各行は方程式として扱われ、GF(2) の正確性を維持するために対称的に消去が実行されます。 最後のステップでは、縮小されたシステムから変数の割り当てを抽出します。 

実装でよくある落とし穴は、ピボットの下の行だけでなく、すべての行に消去を適用する必要があることを忘れていることです。 GF(2) で作業するため、対称消去により、システムの一貫性が保たれ、最終的に直接読み取れることが保証されます。 

もう 1 つの微妙な点は、拡張列のインデックスを正しく作成することです。 最後の列には各方程式の結果が格納されており、ここでオフバイワンエラーが発生すると、すぐに再構成が破損します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、システムに冗長または重複した方程式が含まれている場合です。 このような場合、消去によりゼロ行が生成されます。 たとえば、2 つのクエリが同じ応答を生成する場合、2 番目のクエリは XOR 除去後にすべて 0 になります。 ピボットに寄与しないため、アルゴリズムは当然これを無視し、解は変更されません。 

もう 1 つのエッジ ケースは、すべての方程式に変数が出現し、システムが密になる場合です。 ここでも、ピボット選択によりステップごとに少なくとも 1 つの変数が確実に削除され、失速が防止されるため、ガウス消去は依然として進行します。
