 ## 解決策
 ## 問題の理解

 表示される値は 10 進数の文字列 (X) です。 この不具合はちょうど 2 桁の位置に影響を及ぼしました。つまり、(X) の 2 つの異なる位置で桁を交換することで、意図した数値を取得できることになります。 このような 1 回のスワップで取得できるすべての数値の中で、厳密に (X) より小さい最大の数値が必要です。 どのスワップもより小さい有効な 10 進数を生成しない場合、答えは次のようになります。`-1`。 

入力は (10^{100}) まで大きくできるため、数値には最大 101 桁を含めることができます。 これにより、整数型が制限されている言語では値を固定幅の機械整数として扱うことができなくなりますが、桁数が少ないことも意味します。 文字列に対して数百万回の操作を実行するアルゴリズムであっても、1 秒の制限を十分に満たす速度です。 位置のペアに対して直接列挙を安全に使用できます。 

不注意な実装によって誤って処理される可能性があるエッジ ケースが 3 つあります。 のために`100`を交換する`1`どちらのゼロでも、ゼロで始まる数値が生成されるため、有効なこれより小さい正の整数表現は存在せず、答えは次のようになります。`-1`。 先頭の数字をチェックする前に文字列を比較するソリューションでは、誤って受け入れてしまう可能性があります。`010`または`001`。 

のために`999`、すべてのペアには等しい数字が含まれます。 ペアを交換しても数値は変わらないため、厳密に小さい候補は存在せず、答えは次のようになります。`-1`。 スワップによって生成されたという理由だけで候補を受け入れるソリューションは、誤って次の結果を返します。`999`。 

のために`354`、最初の桁と 3 桁目を入れ替えると、`453`、これは大きくなりますが、2 桁目と 3 桁目を入れ替えると次のようになります。`345`、これは小さいです。 正しい答えは、`345`。 これにより、最大の候補ではなく最初の小さな候補を選択する実装が捕捉されます。 

## アプローチ

 直接的なアプローチは、すべての桁位置のペアを試してみることです。 各ペアについて、元の文字列をコピーし、それらの 2 桁を交換し、結果がゼロで始まる場合はその結果を拒否し、それを (X) と比較します。 (X) より小さい場合は、これまでに見つかった最良の候補より大きい場合は常にそれを保持します。 

正確に 2 桁の位置を変更することで考えられるすべての結果が 1 つのペア (i<j) に対応し、アルゴリズムはそのようなすべてのペアを検査するため、この強引な方法は正しいです。 最大の有効な候補を保持すると、必要な答えが正確に得られます。 

この方法のコストは、実際の制約の下では依然として非常に小さいです。 (n) 桁の場合、(\binom n2) 個の交換が可能であり、候補の構築または比較には (O(n)) 個の文字操作が必要になります。 したがって、最悪の場合の複雑さは (O(n^3)) になります。 可能な最大長（n=101）では、スワップは (\binom{101}{2}=5050) のみで、およそ (5050\cdot101)、つまり約 510,000 文字の操作が行われます。 

小さな観察を行うことで、不必要な作業を減らすことができます。 (i<j) と仮定します。 (X[i]\le X[j]) の場合、それらを入れ替えても数値を小さくすることはできません。 最初に変更された位置は (i) で、その桁は同じままか大きくなります。 (X[i]>X[j]) の場合にのみ、より小さい結果が得られます。 他のすべてのペアをスキップできます。 

入力には約 100 桁しか含まれていないため、ブルート フォース手法が機能します。 (X[i]>X[j]) のペアのみが数を減らすことができるという観察により、候補の数はさらに減りますが、単純な列挙が受け入れられる主な理由は、桁数が異常に少ないことです。

 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^3)) | (O(n)) | 承認済み |
 | (X[i]>X[j]) によるペア フィルタリング | (O(n^3)) 最悪の場合 | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (X) を整数に変換するのではなく、文字列として読み取ります。 文字列表現により、すべての桁に直接アクセスできるようになり、整数のサイズへの依存が回避されます。 
2. 最良の回答を存在しないものとして初期化します。 (X) より小さい有効な数値を生成するスワップを見つけた後にのみ、答えを作成します。 
3. 位置のすべてのペアを列挙します (i<j)。 これらのペアは、グリッチの影響を受ける 2 桁の可能なすべての選択肢を表します。 
4. (X[i]\le X[j]) の場合、ペアをスキップします。 交換された数値が (X) と異なる最初の位置は (i) であり、そこにある新しい桁は (X[j]) になります。 (X[j]\ge X[i]) であるため、結果は厳密にはこれより小さくなりません。 
5. (X) をコピーし、位置 (i) と (j) を交換します。 すべての候補は同じ元の番号から生成される必要があるため、元の文字列を変更する代わりにコピーします。 
6. 最初の桁が次の場合、候補者を拒否します。`0`。 先頭のゼロは、意図した数値の有効な 10 進表現を表しなくなりました。 
7. (X[i]>X[j]) であるため、候補は (X) より小さいことがすでに保証されているため、現在の最良の候補と比較します。 新しい候補の方が大きい場合は、最適な候補を置き換えます。 
8. すべてのペアを調べた後、最適な候補が存在する場合はそれを出力します。 それ以外の場合は印刷します`-1`。 

### なぜ効果があるのか

 有効な答え (Y) を検討してください。 交換によって正確に 2 桁が変更されるため、その桁が (Y) を生成する一意の位置のペア (i<j) が存在します。 (Y<X) の場合、最初に変更された位置 (i) はより小さい桁を受け取る必要があるため、必然的に (X[i]>X[j]) になります。 アルゴリズムはこのペアを調べて (Y) を構築し、無効な先行ゼロがない限りそれを受け入れます。 したがって、すべての有効な候補が考慮されます。 アルゴリズムは、受け入れられたすべての候補の最大値を保持するため、最終結果は、1 回のスワップで取得できる (X) より小さい最大の数値になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    best = None

    for i in range(n):
        for j in range(i + 1, n):
            if s[i] <= s[j]:
                continue

            t = list(s)
            t[i], t[j] = t[j], t[i]

            if t[0] == '0':
                continue

            candidate = ''.join(t)

            if best is None or candidate > best:
                best = candidate

    print(best if best is not None else "-1")

if __name__ == "__main__":
    solve()
```入力は次の場所に保存されます`s`文字列として扱われるため、各桁に直接アクセスでき、同じ長さの 10 進数文字列間の比較は、数値間の比較と同じ順序になります。 

ネストされたループはすべてのペア (i<j) を生成します。 条件`s[i] <= s[j]`は有用な剪定ステップです。 数字が等しい場合、スワップによって何も変化しません。 いつ`s[i] < s[j]`、最初に変更される桁が大きくなるため、結果の数値は (X) より大きくなります。 

候補は新しいリストから作成されるため、スワップが後の反復に影響を与えることはありません。 これは、置換スタイルのブルート フォースにおける一般的なバグの原因です。元の配列を復元せずに変更すると、後の候補が以前のスワップに依存することになります。 

候補を受け入れる前に、先行ゼロのチェックが行われます。 たとえば、`1`そして`0`で`100`作成します`001`、これを有効な数値として扱ってはなりません`1`。 

ソリューションのどこにも整数変換はありません。 Python 自体は任意のサイズの整数をサポートしていますが、入力を文字列として扱うことで、意図した表現が明示的になり、すべての演算が桁数に比例した状態に保たれます。

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    try:
        sys.stdin = io.StringIO(inp)
        input = sys.stdin.readline

        old_stdout = sys.stdout
        sys.stdout = output
        try:
            solve()
        finally:

    finally:
        sys.stdin = old_stdin

 ## 特殊なケース

 のために`100`、アルゴリズムは調べます`(0,1)`そして`(0,2)`。 どちらのスワップも数値的には数値を減らしますが、`010`そして`001`したがって、先行ゼロのチェックでは両方が拒否されます。 ペア`(1,2)`同じ数字が含まれているためスキップされます。 最良の答えは存在しないままであるため、アルゴリズムは次のように出力します。`-1`。 

のために`999`、すべてのペアは等しい桁を持ちます。 各ペアは、`s[i] <= s[j]`これは、同じ桁を交換しても、より小さい数値を生成できないためです。 結果は`-1`変更されない値ではなく、`999`。 

のために`2`、数字が 1 つしかないため、ネストされたループにはペアがまったく含まれません。 2 つの異なる数字を交換することはできないため、候補が残らず、`-1`。 

のために`354`、唯一有用なペアは、ゼロベースのインデックスを使用する位置 1 と 2 です。 以来`5 > 4`、それらを交換すると生成されます`345`。 候補は有効で、元の候補より小さく、最良の答えになります。 アルゴリズムは出力します`345`。 

のために`11101`を交換する`1`位置 2 で`0`位置 3 では次のようになります`11011`。 他の有用なスワップは、より小さい候補を生成するか、このスワップを改善しません。 アルゴリズムは維持します`11011`、これは最大の有効な結果です。 

最大長の入力の場合、アルゴリズムは数値をマシン整数に変換しません。 すべての操作はその 10 進数文字に対して直接作用するため、101 桁の境界は短い入力とまったく同じ方法で処理されます。
