 ## 解決策
 ## 問題の理解

 ダリアは固定点 ((x_0,y_0)) に立っており、能力を発射する任意の方向を選択できます。 ターゲットが最大 (R) の距離にある場合は、ターゲットを引くことができますが、追加の制限が 1 つあります。選択した方向に沿って、ダリアはその光線上の最初のターゲットに到達します。 ダリアと選択したターゲットの間に別のターゲットがある場合、遠いターゲットを直接選択することはできません。 

したがって、タスクは、半径 (R) の円内のすべてのターゲットを数えるわけではありません。 同じ光線上にあるターゲットは互いに競合し、その光線上で最も近いターゲットだけを引き出すことができます。 距離 (R) 内に少なくとも 1 つのターゲットが含まれるダリアからの異なる光線が何本あるかを数える必要があります。 

最大 (5\cdot10^5) 個のターゲットを存在できます。 座標と (R) は (10^9) まで大きくなる可能性があるため、ターゲットのすべてのペアを比較するアルゴリズムは、最悪の場合でも約 (2.5\cdot10^{11}) の比較を実行します。 これは、競技プログラミングの制限である 1.5 秒がサポートできる速度をはるかに超えています。 整数 gcd 計算の小さな対数コストとは別に、(O(N\log N))、できれば (O(N)) に近いアプローチが必要です。 

座標は負の値になる可能性があるため、方向はその符号を維持する必要があります。 光線 ((1,2)) と ((-1,-2)) は、同じ無限線上にありますが、方向が異なります。 同時に、((1,2))、((2,4))、および ((-1,-2)) は 3 つではなく 2 つの異なる光線を表します。 

正確な距離 (R) にも境界の問題があります。 距離の 2 乗が正確 (R^2) のターゲットは到達可能であり、カウントする必要があります。 たとえば、```
0 0 5 1
3 4
```答えは`1`、距離はちょうど (5) であるためです。 を使用した実装`< R * R`の代わりに`<= R * R`間違って戻ってきます`0`。 

2 番目のエッジ ケースは、複数のターゲットが同じ光線上にある場合に発生します。 例えば、```
0 0 10 3
1 0
2 0
3 0
```答えがあります`1`、 ない`3`。 3 つのターゲットはすべて射程内にありますが、東に射撃すると必ず命中します`(1,0)`初め。 方向を統合せずに円内のすべてのターゲットを数えるのは間違いです。 

逆方向の場合も扱いを間違えやすいです。 のために```
0 0 10 2
3 0
-3 0
```答えは`2`。 2 つのターゲットは反対の光線上にあるため、Dahlia はどちらかを選択できます。 方向を最大公約数で正規化すると、符号が保存され、これら 2 つの方向が区別されます。 

## アプローチ

 直接的なアプローチは、半径内のすべてのターゲットを調べて、同じ光線上にさらに近いターゲットがあるかどうかを判断することです。 各ターゲットについて、他のすべてのターゲットと比較し、Dahlia からの 2 つのベクトルが互いの正の倍数であるかどうか、および他のターゲットの方が近いかどうかを確認できます。 これは正しいです。ターゲットは、その光線上で他のターゲットがブロックしていない場合に正確に選択可能であるためです。 

問題は比較の二次数です。 (N=5\cdot10^5) の場合、最悪のケースにはおよそ (N(N-1)/2)、つまり約 (1.25\cdot10^{11}) 個のペアが含まれます。 非常に安価な定時間テストであっても、それを実現することはできません。 

重要な観察は、実際にはすべての光線で最も近いターゲットを見つける必要はないということです。 光線に、ダリアからの距離が最大 (R) のターゲットが含まれているとします。 その光線上のすべてのターゲットの中で、最も近いターゲットも最大 (R) であり、その最も近いターゲットはまさにダリアが引っ張ることができるターゲットです。 逆に、レイ (R) 内にターゲットがない場合、そのレイ上の何も引き出す​​ことはできません。 

したがって、答えは単純に、距離が最大 (R) のターゲットによって表される個別の方向の数になります。 

方向は整数演算を使用して正確に表現できます。 ダリアが原点になるようにすべてのターゲットを平行移動し、ベクトルを与えます

 [
 (dx,dy)=(x_i-x_0,y_i-y_0)。 
】

 両方の成分を次の値で割ります。 

[
 g=\gcd(|dx|,|dy|)。 
】

 結果のペア

 [
 \left(\frac{dx}{g},\frac{dy}{g}\right)
 】

 は、その光線の一意のプリミティブ整数表現です。 ((2,6))、((1,3))、((10,30)) などの点はすべて ((1,3)) になりますが、((-1,-3)) は反対方向を向いているため、異なるままです。 

次に、正規化された各方向をセットに挿入できます。 セット内のすべての個別のペアは、正確に 1 つの到達可能な光線に対応します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^2)) | (O(1)) | 遅すぎる |
 | 最適 | (O(N\log C)) | (O(N)) | 承認済み |

 ここで (C) は、最大 (2\cdot10^9) の座標差の大きさです。 対数係数はユークリッド gcd アルゴリズムに由来します。 

## アルゴリズムのチュートリアル

 1. ダリアの位置、最大距離（R）、ターゲットの数を読み取ります。 (R^2) を計算します。距離の 2 乗を比較すると平方根が回避され、正確な整数の比較が行われるためです。 
2. すべてのターゲットについて、その相対ベクトルを計算します。 
[
 dx=x_i-x_0、\qquad dy=y_i-y_0。 
】
 これにより、問題は任意の点の周囲のジオメトリから原点から始まる方向に変わります。 
3. コンピューティング
 [
 d^2=dx^2+dy^2。 
】
 (d^2>R^2) の場合、このターゲットを無視します。 これは引っ張ることができません。また、同じレイ上の他のすべてのターゲットがこのターゲットの背後にある場合はさらに遠くにあるため、このターゲットは到達可能なレイに寄与できません。 
4. 距離チェックを通過したすべてのターゲットについて、次の計算を行います。 
[
 g=\gcd(|dx|,|dy|)
 】
 ベクトルを次のように置き換えます
 [
 (dx/g、dy/g)。 
】
 これにより、ベクトルの正確な方向を維持しながら、ベクトルの大きさが削除されます。 
5. 正規化されたペアをセットに挿入します。 正規化されたペアが等しいということは、ターゲットが同じ光線上にあることを意味します。 異なる符号は異なるままであるため、反対の光線が誤ってマージされることはありません。 
6. すべてのターゲットが処理された後、セットのサイズを出力します。 保存された各方向は、Dahlia が選択してプルできる 1 つのターゲット、つまりその光線上で最も近いターゲットに正確に対応します。 

### なぜ効果があるのか

 距離 (R) 内に少なくとも 1 つのターゲットを含む光線を考慮します。 それらのターゲットの中に、最も近いターゲットがあります。 その距離は最大 (R) であるため、ダリアはその光線を選択し、すぐにこの最も近いターゲットを引き寄せることができます。 したがって、到達可能な光線はすべて 1 つの答えに寄与します。 

次に、距離 (R) 内にターゲットを含まない光線を考えます。 その光線上のすべてのターゲットは遠すぎるため、ダリアはそこから何も引き出す​​ことができません。 したがって、他の光線は答えに寄与しません。

正規化されたベクトルは、一方が他方のプリミティブ ベクトルの正の整数倍である場合、2 つの非ゼロ整数ベクトルが正確に同じ光線に沿って指すため、光線を一意に識別します。 gcd で除算すると、その原始ベクトルが生成されますが、符号を保持したまま反対方向を区別します。 したがって、このセットには、少なくとも 1 つのターゲットが到達可能なレイごとに 1 つのエントリが正確に含まれており、これはまさに必要な答えです。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    x0, y0, R, N = map(int, input().split())

    r2 = R * R
    directions = set()

    for _ in range(N):
        x, y = map(int, input().split())

        dx = x - x0
        dy = y - y0

        if dx * dx + dy * dy > r2:
            continue

        g = gcd(abs(dx), abs(dy))
        directions.add((dx // g, dy // g))

    print(len(directions))

if __name__ == "__main__":
    solve()
```最初の部分は固定位置を読み取り、計算します。`r2`。 平方根を求めると不必要な浮動小数点処理が追加され、精度の問題が発生する可能性があるため、二乗距離が使用されます。 

あらゆるターゲットに対して、`dx`そして`dy`ダリアを基準にして測定されます。 円の外側のターゲットはまったく表す必要がないため、距離の比較は正規化の前に実行されます。 

への呼び出し`gcd(abs(dx), abs(dy))`同じ方向の最小の整数ベクトルを生成します。 絶対値が渡されます。`gcd`ただし、分割時に元の符号は保持されるため、`(1, 2)`そして`(-1, -2)`異なるセットエントリのままになります。 

このステートメントでは、Dahlia の位置を占めるターゲットがないことが保証されているため、ゼロ除算の問題は発生しません。 したがって`(dx, dy)`決してない`(0, 0)`、その gcd は常に正です。 

Python の整数には任意の精度があるため、次のような式が使用できます。`dx * dx + dy * dy`座標の差の 2 乗が (4\cdot10^{18}) に達しても安全です。 

このセットは、重複するすべての方向を自動的に削除します。 最終的なサイズが答えです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(N\log C)) | 各ターゲットには、定数演算に加えて、(2\cdot10^9) で囲まれた整数に対する 1 回の gcd 計算が必要です。 |
 | スペース | (O(N)) | 各ターゲットに対して最大 1 つの正規化された方向が保存されます。 |

## 特殊なケース

 正確な半径の場合は、比較することによって処理されます。`dx * dx + dy * dy`と`R * R`使用して`>`。 のために```
0 0 5 1
3 4
```二乗距離は`25`そして`R * R`もです`25`。 条件`25 > 25`は false なので、方向は`(3,4)`が挿入され、答えは`1`。 を使用した実装`<`包含テストでは誤って破棄されてしまうためです。 

複数のターゲットが 1 つのレイを共有する場合、正規化によりそれらは 1 つのセット エントリに集約されます。 のために```
0 0 10 3
1 0
2 0
3 0
```3 つのベクトルは次のように正規化されます`(1,0)`。 したがって、セットには 1 つの方向のみが含まれており、出力が得られます。`1`。 最も近いターゲット`(1,0)`はダリアが実際に引いているものです。 

反対方向には異なる標識が残ります。 のために```
0 0 10 2
3 0
-3 0
```正規化されたベクトルは`(1,0)`そして`(-1,0)`。 これらは 2 つの別個のセット エントリであるため、答えは次のようになります。`2`。 絶対座標を使用してベクトルを正規化するソリューションでは、2 つの光線が誤ってマージされます。

0 0 5 2
1 0
10 0
```最初のターゲットには二乗距離があります`1`、2 番目の距離は 2 乗です`100`。 のみ`(1,0)`貢献します、そして答えは`1`。 同じ方向の前に到達可能なターゲットがすでにあるため、より遠いターゲットは関連することはできません。 

最後に、比例座標を持つターゲットは、傾きを浮動小数点と比較するのではなく、gcd を使用して正規化する必要があります。 で```
0 0 10 4
1 2
2 4

```最初の 3 つのターゲットはすべて次のように正規化されます`(1,2)`、最後は正規化されます`(-1,-2)`。 このセットには正確に 2 つの方向があるため、出力は次のようになります。`2`。 この整数表現により、浮動小数点の精度の問題と垂直線に必要な特別な処理の両方が回避されます。
