 ## 問題の理解

 ボードには (N+1) 個の位置が円状に配置されています。 声明の最初の位置に対応する位置 (0) は政府に属し、支払いを引き起こすことはできません。 残り (N) の位置は所有できるプロパティです。 

選手はソ選手、B21選手、ローウィー選手の3名です。 プレイヤーが移動するたびに、その変位は固定されます。Seo は常に移動 (V_s)、B21 は常に移動 (V_b)、Lowie は常に移動 (V_l) します。 この順番で繰り返し移動します。 プレイヤーが所有されていない不動産に到達すると、それを奪います。 自分のプロパティに到達しても何も起こりませんが、他のプレイヤーのプロパティに到達すると、探しているイベントがすぐに作成されます。 

このタスクは、最初の支払いが発生したときに発生したサイコロの数を見つけることです。 各プレイヤーの許可された (10^9) 手の移動中に支払いが発生しなかった場合、必要な出力は (3\cdot10^9) です。 

この境界により、プレイヤーごとのすべての (10^9) ターンの直接シミュレーションが不可能になります。 1 ターンあたりの一定の作業量が非常に少ない場合でも、約 30 億回の反復が必要になります。 ただし、ボードのサイズは (N+1\le100001) のみです。これは、(N) に比例したターン数後に関連する動作が繰り返されることを強く示唆しています。 

最初の微妙なケースは、政府の立場に到達することです。 たとえば、`3 1 1 1`、ボードには 4 つのポジションがあります。 Seo は最初のロールで物件 1 に到達し、B21 は 2 番目のロールで同じ物件に到達します。したがって、答えは次のようになります。`2`。 開始位置を通常のプロパティとして扱う不注意な実装では、支払いが誤って報告されてしまいます。 

もう 1 つの境界ケースは、(N) に等しい動きです。 のために`3 3 3 3`、ボードのサイズは 4 なので、各プレイヤーは毎ターン 3 つのポジションを移動します。 Seo はロール 1 でポジション 3 を主張し、B21 はロール 2 でポジション 3 に到達します。答えは次のとおりです。`2`。 モジュロ (N+1) の代わりにモジュロ (N) を使用すると、誤ったボード ジオメトリが表示されます。 

動きの順序も重要です。 のために`3 1 2 3`、Seo はロール 1 でポジション 1 を主張し、B21 はロール 2 でポジション 2 を主張し、Lowie はロール 3 でポジション 3 を主張します。Seo の 2 番目の手で、彼は B21 がすでに所有しているポジション 2 に到達します。したがって、答えは次のようになります。`4`。 所有権を確認する前にラウンド全体を処理するシミュレーションでは、個々のロールの直後に所有権が変更されるという事実を見落としてしまいます。 

最後に、ゲームは支払いなしで永久に繰り返すことができます。 サンプル`29 6 10 15`はそのような場合であり、正解は`3000000000`。 ゲーム状態全体の繰り返しが確立されていない限り、すべてのプレーヤーがいくつかのポジションを再訪したという理由だけで停止するだけでは十分ではありません。 

## アプローチ

 簡単な解決策は、ゲームが起こっているとおりにシミュレーションすることです。 各プレーヤーの現在位置と、どのプレーヤーが各プロパティを所有しているかを格納する配列を保持します。 Seo、B21、Lowie の順に処理し、現在位置をモジュロ (N+1) で更新し、すぐに目的地を検査します。 空の場合は、その所有者を割り当てます。 他の人のものである場合は、現在のロール数を返します。 

このシミュレーションは、ゲームで記述された状態遷移に正確に従っているため、完全に正確です。 問題は停止条件です。 このステートメントでは各プレイヤーに (10^9) 回の動きが許可されているため、最悪の場合は (3\cdot10^9) 回のシミュレートされたロールが必要になりますが、これは 1 秒の制限をはるかに超えています。 

重要な観察は、ボードに正確に (N+1) 個のポジションが含まれていることです。 (N+1) 回の自分の動きの後の 1 人のプレイヤーを考えてみましょう。 それらの総変位は

 ## アルゴリズムのチュートリアル

 1. しましょう`m = N + 1`完全な回覧板には政府の立場に加えて (N) 個のプロパティが含まれているためです。 のインデックスを使用してすべてのポジションを保存します。`0`を通して`m-1`、 どこ`0`が政府の立場です。 
2. 長さの所有権配列を作成します。`m`。 最初はすべてのエントリはゼロであり、所有されていないことを意味します。 位置のエントリ`0`政府のものであるため、請求されることはありません。 
3. 3 つの現在のポジションを保持します。最初はすべてゼロに等しくなります。 また、3 つの固定移動値 (V_s、V_b、V_l) を保持します。 
4. シミュレートするのはせいぜい`m`ラウンドを完了します。 各ラウンドでは、3 人のプレイヤーを Seo、B21、Lowie の順序で処理します。 プレイヤーはモジュロを使用して固定移動値だけ進みます`m`。 
5. 各動作の直後にグローバル ロール カウンタをインクリメントします。 このカウンタは実際に発生したサイコロの出目の数を表すため、現在の目的地が別のプレイヤーに属している場合、それを返すと要求された答えが正確に得られます。 
6. 目的地がゼロの場合は、政府がその立場を所有しているため、無視してください。 所有者がゼロの場合は、現在のプレーヤーを所有者として割り当てます。 所有者がすでに現在のプレイヤーである場合は、何も起こりません。 所有者が別のプレイヤーの場合、これが最初の支払いであるため、現在のロール数を返します。 
7. もしすべてが`3*m`可能なロールは支払いなしで処理され、返品されます`3000000000`。 この後の状態`m`プレイヤーごとの動きは初期状態とまったく同じであるため、将来のすべてのブロックは同じ遷移を繰り返すことになり、支払いを導入することはできません。 

### なぜ効果があるのか

 不変条件は、すべてのシミュレートされたロールの直前に、保存された位置と所有権の配列が、同じ数のロール後の実際のゲームを正確に記述することです。 各移動では正しい固定変位とモジュロ (N+1) が使用され、目的地に到着するとすぐに所有権が更新されます。 したがって、アルゴリズムが初めて他のプレイヤーの所有者を確認したときが、まさに実際のゲームにおける最初の支払いとなります。 

各プレイヤーの (N+1) 回の移動中に支払いが現れなかった場合、各プレイヤーは整数の完全なボード ラップを通過したため、3 つのポジションはすべて 0 に戻ります。 同じ固定移動値と同じターン順序により、同じ目的地のシーケンスが再現されます。 所有権状態も競合することなく同じシーケンスによって生成されているため、今後のゲームは無限に繰り返されます。 したがって戻ります`3000000000`は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, vs, vb, vl = map(int, input().split())

    m = n + 1
    moves = (vs, vb, vl)

    # owner[pos] = 0 if the property is unowned,
    # otherwise 1, 2, or 3 for the corresponding player.
    owner = [0] * m

    # All players start at the government position.
    pos = [0, 0, 0]

    rolls = 0

    # After m moves by each player, the whole game state repeats.
    for _ in range(m):
        for player in range(3):
            pos[player] = (pos[player] + moves[player]) % m
            rolls += 1

            p = pos[player]

            # Position 0 belongs to the government.
            if p == 0:
                continue

            if owner[p] == 0:
                owner[p] = player + 1
            elif owner[p] != player + 1:
                print(rolls)
                return

    print(3000000000)

if __name__ == "__main__":
    solve()

の`owner`配列には、すべてのプロパティの現在の所有者が格納されます。 政府の立場のために特別なものを保存する必要はありません。`p == 0`check は、所有権配列が参照される前にそれをスキップします。 

外側のループは正確に実行されます`m`回。 各反復中、すべてのプレイヤーは 1 ターンを取得するため、シミュレーションは各プレイヤーの正確に (N+1) ターン、つまり合計で (3(N+1)) ロールをカバーします。 

内側のループは使用します`player`価値観`0`、`1`、 そして`2`、Seo、B21、および Lowie に対応します。 配列に格納されている所有者は、`player + 1`これにより、所有されていないプロパティの特別な値がゼロのままになります。 

位置の更新には、`(pos[player] + moves[player]) % m`。 モジュロは次のようにする必要があります`N+1`、 ない`N`, なぜなら、円形ボード上には (N+1) 個の位置があるからです。 

ロールカウンタは、宛先を確認する前にインクリメントされます。 その移動中に支払いが発生した場合、要求された回答には支払いの原因となったロールが含まれるため、現在の値は`rolls`まさに答えです。 

Python の整数には任意の精度があるため、必要なセンチネル値は`3000000000`特別な整数型は必要ありません。 実際のシミュレーションは最大で実行されます`300003`ロールなので、時間とメモリ使用量の両方が制限内に収まります。
