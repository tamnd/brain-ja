 ## 解決策
 ## 問題の理解

 ポリラインは 1 次元の地形プロファイルを表します。 X 座標は厳密に増加しているため、連続するポイントのすべてのペアが 1 つの地形セグメントを形成し、雨水が窪地に留まることができるのは、水の流出を防ぐほど地形の両側が盛り上がっている場合のみです。 

どの窪地でも、水面は水平です。 その左側の境界が点 (i) であり、右側の境界が点 (r) であるとします。 水位は 2 つの境界の高さのうち低い方になります。 

[
 h=\min(y_i,y_r)。 
】

 水域は地形と水平線 (y=h) の間の領域ですが、地形がその線より下にある場所に限ります。 タスクは、地形の各部分が最大でも 1 つのカウントされた領域に属する、このようなトラップされた領域すべての合計を見つけることです。 

制約 (n\le 10^5) により、すべての点のペアの検査が除外されます。 二次アルゴリズムは、最悪の場合、2 秒の制限をはるかに超えて、約 (10^{10}/2) ペア チェックを実行します。 座標は最大 (10^6) であるため、ポリライン全体の水平幅の合計は最大 (10^6) ですが、すべての開始点からのスキャンが実現できるわけではありません。 (O(n)) または (O(n\log n)) の解が必要です。 

誤って対処しやすい特殊なケースがいくつかあります。 たった 2 点なので、囲まれた凹みはまったくありません。 例えば、```
2
0 0
1000000 1000000
```答えがあります`0`。 すべてのペアが盆地を定義すると仮定した解決策では、ここに誤って水を作成することになります。 

高さが同じであることも重要です。 のために```
3
0 2
1 0
2 2
```答えは`1`両側が水位 2 の三角形の盆地を形成しているためです。厳密に大きい点のみを使用する不注意な次の大きい実装では、最大の高さが左側の高さに等しい場合に、右側の境界を認識できない可能性があります。 

右側の境界が左側の境界よりも低くなることもあります。 のために```
3
0 3
1 0
2 2
```水は高さ 2 で右側にこぼれるので、水位は 3 ではなく 2 です。答えは次のとおりです。`2`。 このため、境界の高さは次のようにする必要があります。`min(y_i, y_r)`。 

最後に、右の端点が水位よりも高い場合、最後の地形セグメントは内部のどこかで水面を横切ります。 のために```
4
0 2
1 0
2 1
3 3
```水位は 2 です。最初の 2 つのセグメントは (1) と (1.5) に寄与しますが、高さ 2 より下の部分のみに水が含まれるため、最後のセグメントは (0.25) のみに寄与します。 答えは`2.75`。 最終セグメント全体を水没したものとして扱うと、過剰にカウントされてしまいます。 

## アプローチ

 直接的なアプローチは、考えられるすべての左境界 (i) を試し、すべての考えられる右境界 (j>i) を見つけて、ペアが保持できる水の量を計算することです。 (n(n-1)/2) 個のペアがあり、これは (n=10^5) に対して約 (5\cdot10^9) 個のペアになります。 たとえ各ペアが一定時間で処理されたとしても、これではすでに遅すぎます。 区間もスキャンして面積を計算すると、複雑さは 3 次になります。 

有益な観察は、任意の正しい境界を考慮する必要がないということです。 点 (i) から開始すると、唯一の意味のある右側の境界は、高さが厳密に (y_i) よりも大きい右の最初の点です。 このような点が存在する場合、その前のすべての点は最大 (y_i) であるため、(i) から始まる水は、こぼれる前に正確にその境界に到達します。 これより大きな点が存在しない場合、水は最終的に右側の最も高い点を越えてこぼれます。 その接尾辞の最大値が最初に出現する箇所を境界として選択します。 

これはまさに公式の編集で説明されている構造です。すべての (i) について、(y_{r_i}>y_i) で最小の (r_i>i) を見つけるか、存在しない場合は、右側の位置の中で最大の高さに達する最初の位置を見つけます。 結果の範囲はネストされるか、完全に分離されるため、ある範囲から次の範囲に直接ジャンプして処理できます。 

すべての点の最初に大きい位置は、(O(n)) の単調スタックで見つけることができます。 フォールバック接尾辞の最大値は、1 回の右から左へのスキャンで (O(n)) で計算できます。 

境界 (r_i) がわかったら、(i) から (r_i) までのセグメントをたどって水域を計算します。 ([i,r_i]) を処理した後、(r_i+1) から継続するため、実際に処理される範囲は互いに素です。 したがって、個々の範囲には多くのセグメントが含まれる可能性がありますが、アルゴリズム全体で処理されるセグメントの総数は (O(n)) のみです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^2)) またはそれ以上 | (O(n)) | 遅すぎる |
 | 最適 | (O(n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ポリラインを配列に読み込みます`x`そして`y`。 厳格な増加`x`これは、すべての地形セグメントを独立して統合できることを意味します。 
2. コンピューティング`next_greater[i]`の右側の最初のインデックス`i`と`y[index] > y[i]`。 高さが厳密に減少するスタックを維持しながら、インデックスを右から左に処理します。 スタックにクエリを実行する前に`i`、高さが最大以下のすべての点を削除します。`y[i]`なぜなら、これらのポイントはどれも、最初の厳密に高いポイントにはなりえないからです。`i`。 
3. コンピューティング`suffix_idx[i]`、インデックスの厳密に右側で最大の高さに達する最初の位置`i`。 右から左にスキャンしながら、これまでに確認された最高のポイントを維持します。 現在の高さが厳密に大きい場合は、その点を置き換えます。 高さが等しい場合、既存の点はさらに右にあり、現在の点は によって考慮される接尾辞の一部ではないため、維持します。`suffix_idx[i]`。 
4. から開始します`i=0`。 もし`next_greater[i]`存在するので、それを使用します`r`。 それ以外の場合は使用します`suffix_idx[i]`。 右側に点がない場合、考えられる盆地は存在せず、アルゴリズムは停止します。 
5. 水位を次のように設定します。`h=min(y[i],y[r])`。 この範囲のすべての内部頂点は最大でも`h`の定義により、`r`。 もし`y[r] > h`、最後のセグメントのみが水面を横切ることができます。 もし`y[r] <= h`、すべてのセグメントは完全に水面下または水面上にあります。 
6. ((x_1,y_1)) から ((x_2,y_2)) までの完全に水没したセグメントの場合、地形は直線であるため、その平均高さは ((y_1+y_2)/2) になります。 水位あり`h`、その貢献度は

 [
 (x_2-x_1)\left(h-\frac{y_1+y_2}{2}\right)。 
】

 半分が繰り返されるのを避けるために、実装では 2 倍の領域を格納します。 

[
 (x_2-x_1)(2h-y_1-y_2)。 
】

 1. 最後のセグメントが (y_1\le h) から (y_2>h) に進む場合、水は線の高さに達する前の部分のみを占めます。`h`。 奥行きは高さ(h-y_1)の三角形です。 横断距離は

 [
 (x_2-x_1)\frac{h-y_1}{y_2-y_1},
 】

 したがって面積は2倍になります

 [
 (x_2-x_1)\frac{(h-y_1)^2}{y_2-y_1}。 
】

 実装では、この有理値を次を使用して評価します。`Decimal`大きな座標であっても十分な精度を維持します。 

1. 現在の範囲の面積を答えに加算して設定します。`i=r+1`。 カウントされる部分で範囲が重複することはできないため、すべての地形セグメントは最大 1 回処理されます。 

### なぜ効果があるのか

 各開始点 (i) について、選択された (r_i) は、まさに (i) で発生した水が逃げられる最初の場所です。 より高い点が存在する場合、その点より前のすべての点は (y_i) より高くないため、下限境界の高さは (y_i) になります。 より高い点が存在しない場合、接尾辞の最も高い点が水がこぼれる可能性のある最初の場所となり、その高さが水位を決定します。 したがって、([i,r_i]) は 1 つの最大の閉じ込められた水の構造を記述します。 

このような 2 つの構造は、入れ子になっているか、互いに素になっています。 一番左の構造を処理してからジャンプすると、`r_i+1`、ネストされた構造は処理領域にすでに含まれていますが、素の構造は後から始まります。 したがって、ジャンプは別の盆地に属する水をスキップすることはなく、同じセグメントを 2 回カウントすることはありません。 処理された各セグメントはその幾何学的水域に正確に寄与するため、累積された結果が必要な総面積となります。 

## Python ソリューション```python
import sys
from decimal import Decimal, getcontext

input = sys.stdin.readline

getcontext().prec = 40

def solve(data=None):
    if data is None:
        tokens = iter(sys.stdin.buffer.read().split())
    else:
        tokens = iter(data.split())

    n = int(next(tokens))
    x = [0] * n
    y = [0] * n

    for i in range(n):
        x[i] = int(next(tokens))
        y[i] = int(next(tokens))

    if n <= 2:
        return "0.0000000000\n"

    # next_greater[i] = first j > i with y[j] > y[i].
    next_greater = [-1] * n
    stack = []

    for i in range(n - 1, -1, -1):
        while stack and y[stack[-1]] <= y[i]:
            stack.pop()

        if stack:
            next_greater[i] = stack[-1]

        stack.append(i)

    # suffix_idx[i] = first position attaining the maximum y
    # among positions strictly to the right of i.
    suffix_idx = [-1] * n
    best = -1

    for i in range(n - 1, -1, -1):
        suffix_idx[i] = best

        if best == -1 or y[i] > y[best]:
            best = i

    # Store twice the integer/rational area.
    integer_area2 = 0
    fractional_area2 = Decimal(0)

    i = 0

    while i < n - 1:
        r = next_greater[i]

        if r == -1:
            r = suffix_idx[i]

        if r == -1:
            break

        h = min(y[i], y[r])

        k = i
        while k < r:
            x1, y1 = x[k], y[k]
            x2, y2 = x[k + 1], y[k + 1]
            dx = x2 - x1

            if y2 <= h:
                # Entire segment is below the water surface.
                integer_area2 += dx * (2 * h - y1 - y2)
            else:
                # The segment crosses the water surface.
                # Only the triangular part before the crossing is wet.
                dy = y2 - y1
                numerator = dx * (h - y1) * (h - y1)

                fractional_area2 += (
                    Decimal(numerator) / Decimal(dy)
                )

                # This must be the last segment of this range.
                break

            k += 1

        i = r + 1

    area = (
        Decimal(integer_area2) + fractional_area2
    ) / Decimal(2)

    return f"{area:.10f}\n"

def main():
    sys.stdout.write(solve())

if __name__ == "__main__":
    main()
```最初のスキャンでは、減少する単調スタックを使用して次に大きな配列を構築します。 ポイント処理時`i`、以下のすべてのスタック要素`y[i]`最初の厳密に高いポイントとしては永久に役に立たないため、削除しても安全です。 

サフィックス スキャンは、厳密に高いポイントが存在しない場合を処理します。 への割り当て`suffix_idx[i]`ポイントを考慮する前に起こる`i`これにより、格納されたインデックスが厳密に右側を参照するようになります。 同じ高さは意図的に置き換えません`best`なぜなら、前の点がその接尾辞の最大値の最初の出現だからです。 

メインループは以下を使用します`r`これら 2 つの構造によって選択された境界として。 もし`r=i+1`、内部地形セグメントは存在せず、寄与はゼロです。 へのジャンプ`r+1`この範囲には正の面積の盆地を含めることはできないため、これは依然として正しいです。 

面積は2倍の形で累積されます。 完全なセグメントは整数を生成しますが、最後の交差セグメントは有理数を生成できます。 Python の整数には任意の精度があり、`Decimal`大きな座標の場合にバイナリ浮動小数点値によって生じる可能性がある精度を失うことなく、有理部分を処理します。 

交差点の場合は特に注意が必要です。 いつ`y2 > h`、通常の台形公式を使用すると、水面より上のセグメントの部分がカウントされます。 代わりに、からの三角形のみ`y1`高さまで`h`水没している。 以来`r`上記の最初の点です`y_i`このような点が存在する場合、処理範囲内にそのような交差セグメントが 1 つだけ存在する可能性があります。
