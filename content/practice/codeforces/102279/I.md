 ## 問題の理解

 私たちは持っています`N`空ではないスタック。`i`最初に含まれています`Ai`カード。 2 人のプレーヤーが交互に動き、Lowie が最初に動きます。 移動には 2 つの形式のいずれかが存在します。 プレーヤーは、空ではない単一のスタックから 1 枚のカードを削除することができます。または、すべてのスタックが空でない場合は、すべてのスタックから同時に 1 枚のカードを削除することができます。 最後のカードを取り除いた人が勝ちです。 

目的はゲームをシミュレートすることではありません。 初期位置が最初のプレイヤーの勝ちであるかどうかを判断する必要があります。`lowie`、または最初のプレイヤーが負けること、つまり`imitater`勝利を強制することができる。 

制約は線形スキャンには十分小さいですが、ゲーム状態の列挙には大きすぎます。 スタックは 1000 個あり、各スタックには 1000 枚のカードを含めることができます。 状態はすべてのスタック サイズで記述されるため、直接動的プログラミングのアプローチでは膨大な数の状態が存在する可能性があります。 メモ化した場合でも、可能な構成の数はすべてのスタックの可能な値の積に比例し、1000 スタックでは天文学的な数字になります。 意図したソリューションでは、各スタックを一定の回数だけ検査する必要があります。 

重要な数量は、カードの総数のパリティであり、スタックの数が偶数の場合は、最小のスタックのパリティです。 最小スタックが正である間はすべてのスタックの移動が正確に正当であるため、最小スタックが重要になります。 

カードの総数のみに基づいてソリューションを簡単に破ってしまういくつかのエッジケースがあります。 たとえば、```
2
1 2
```合計は`3`、これは奇妙で、ローウィーが勝ちます。 これが最初のサンプルです。 スタックの数が偶数であるかどうかだけを考慮するソリューションでは、これを見逃してしまいます。 

より微妙なケースは、```
2
2 2
```合計は偶数で最小値も偶数なので、正解は`imitater`。 Lowie がどちらかのスタックからカードを 1 枚取り除くと、合計は奇数になります。 Lowie が両方のスタックから 1 枚のカードを取り除くと、その位置は次のようになります。`(1, 1)`、次のプレイヤーの勝ちです。 合計パリティだけを見ると、合計が偶数のポジションをすべて同様に誤って扱うことになります。 

もう一つの重要な事例は、```
2
1 3
```ここで合計は`4`、しかし最小値は奇数です。 Lowie は両方のスタックから 1 枚のカードを削除してリーチすることができます`(0, 2)`。 2 枚のカードを含む 1 つのスタックだけが残ります。したがって、Lowie はそれら 2 枚のカードを連続ターンで取得できるため、Imitator は負けます。 したがって、合計が均等であっても、この位置は Lowie の勝利となります。 

## アプローチ

 ゲーム理論に基づいた直接的な解決策では、すべての合法的な手を再帰的に検査することになります。 との立場から`N`空ではないスタック、最大数まで存在する可能性があります`N`単一スタックの移動とすべてのスタックの移動。 再帰は正しいです。なぜなら、ポジションは、負けているポジションに少なくとも 1 つの手があった場合に正確に勝っているのに対し、すべての正当な手が勝ちのポジションに移動した場合、ポジションは負けているからです。 

問題は状態空間のサイズです。 スタックの場合`i`以下の任意の値を含めることができます`0`を通して`Ai`まであります。 

[
 \prod_{i=1}^{N}(A_i+1)
 】

 さまざまな構成。 最大値では、次のようになります。`1001^1000`可能な状態。 たとえすべての状態がメモ化で 1 回だけ評価されたとしても、`N+1`状態ごとの移動は`O(N * product(Ai + 1))`仕事。 メモ化がなければ、ゲーム ツリーはさらに大きくなります。 

有益な観察は、すべての動きによってカードの総数が非常に予測可能な量だけ変化するということです。 単一スタックの移動により合計が減少します`1`。 すべてのスタックを移動すると、次のように減少します。`N`。 

いつ`N`が奇数の場合、両方の可能な動きが合計のパリティを変更します。`1`そして`N`奇数です。 端末状態は合計があるため、`0`、つまり偶数である場合、奇数の合計から偶数の合計に移動できるプレーヤーが勝ちのパリティを持ちます。 したがって、奇数については、`N`、合計が奇数の場合は、初期位置が正確に勝利しています。 

いつ`N`が偶数の場合、2 つの動きは異なる動作をします。 単一スタックの移動では合計のパリティが変更されますが、全スタックの移動では偶数が減算され、合計のパリティが維持されます。 これにより、最小値が正の値を維持している間のみ全スタック移動を繰り返し使用できるため、最小値スタックが重要になります。 

偶数の場合`N`、負けているポジションは、合計が偶数で最小スタックが偶数のポジションです。 合計が奇数の場合、Lowie はいつでも合計が偶数の負けの位置に移動できます。 合計が偶数で最小値が奇数の場合、Lowie は全スタック移動を実行して、合計のパリティを維持しながら最小値を偶数にすることができます。 合計と最小値の両方が奇数の場合、Lowie は代わりに最小スタックから 1 枚のカードを削除し、両方の枚数を偶数にします。 

したがって、結果として得られる特性評価は単純です。合計が奇数の場合、または次の場合に Lowie が勝ちます。`N`は偶数で、最小スタックは奇数です。 それ以外の場合は、模倣者が勝ちます。 この特徴は、負けている局面からのすべての手が勝ちの局面につながり、すべての勝ちの局面には負けの局面への動きが含まれることを示すことによって直接証明することもできます。

 ## アルゴリズムのチュートリアル

 1. すべてのスタック サイズを読み取り、計算します。`sum`、カードの総数、および`mn`、最小のスタック サイズ。 最終決定に必要なプロパティはこれらだけです。 
2. もし`sum`奇数です、出力`lowie`。 単一スタックの移動では常に合計パリティが変更され、すべてのスタックの移動でも合計パリティが変更されます。`N`奇数です。 より一般的には、合計が奇数の場合、合計が偶数の負けの位置に到達する正当な手が常に存在します。 
3. もし`sum`は均等であり、`N`奇数です、出力`imitater`。 正当な手ごとに合計が偶数から奇数に変更されるため、Lowie は合計が偶数の負けた別のポジションに直接移動することはできません。 
4. もし`N`は均等であり、`sum`均等である、検査する`mn`。 もし`mn`奇数です、出力`lowie`なぜなら、Lowie はすべてのスタックから 1 枚のカードを取り除くことができるからです。 合計は次の理由から維持されます`N`は偶数ですが、最小値は偶数になります。 
5. もし`N`均等です、`sum`は偶数であり、`mn`偶数、出力`imitater`。 単一スタックの移動ごとに合計オッズが作成され、すべてのスタックの移動により最小オッズが作成されます。 結果として得られる両方のポジションは、次のプレイヤーの勝ちとなります。 

### なぜ効果があるのか

 カードの総数が偶数であり、次のいずれかである一連の位置を考慮します。`N`が奇数であるか、最小スタックが偶数です。 これらはまさに負けポジションであると私たちは主張します。 

このような位置からは、単一スタックの移動により合計が奇数になるため、結果として得られる位置が勝ちとなります。 もし`N`が奇数である場合、すべてのスタックの移動も合計を奇数にします。 もし`N`が偶数の場合、すべてのスタックの移動は偶数の合計を維持しますが、最小値が 1 減って奇数になり、次のプレーヤーに勝ちの位置が与えられます。 

次に、このセットの外側のすべてのポジションを考えてみましょう。 合計が奇数の場合、Lowie は次の場合に単一スタックの動きを選択できます。`N`奇数であるか、最小値に基づいて適切な手を選択します。`N`イーブンで劣勢に立たされている。 合計が偶数であれば、`N`は偶数であり、最小値は奇数である必要があります。 次に、すべてのスタックの移動により偶数の合計が維持され、最小値が均等になり、負けのポジションが生成されます。 したがって、すべての勝ちポジションには負けポジションへの移動があり、証明が完了します。

import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())
    a = list(map(int, input().split()))

    mn = min(a)

    if total % 2 == 1:
        return "lowie"
    elif n % 2 == 1:
        return "imitater"
    elif mn % 2 == 1:
        return "lowie"
    else:
        return "imitater"

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return solve()
    finally:
        sys.stdin = old_stdin
