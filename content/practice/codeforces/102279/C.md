 ## 解決策
 ## 問題の理解

 (n) 個の爆弾が 1 次元の街路上の個別の整数座標に配置されています。 タイプ 1 ツールは、ある長さ (w) の間隔内のすべての爆弾を除去できますが、タイプ 2 ツールは、長さ (2w) の間隔内のすべての爆弾を除去できます。 各ツールは最大 1 回使用できます。 

タスクは、最大 (P) のタイプ 1 ツールと最大 (Q) のタイプ 2 ツールを使用してすべての爆弾を除去できる最小の整数 (w) を見つけることです。 問題となるのは爆弾の座標間の距離だけであるため、まず座標を配列 (x_0<x_1<\dots<x_{n-1}) に並べ替えます。 

制約は (n\le 2000) を中心に意図的に形成されています。 (O(n^2)) チェックは実行可能ですが、爆弾の位置、タイプ 1 ツールの数、タイプ 2 ツールの数の 3 つの独立した次元を持つ DP はすでに大きすぎます。 (10^9) の座標境界は、区間の可能な位置を反復すべきではないことを示唆しています。 その代わり、1 から (10^9) までの反復は約 30 回しかないため、答えの範囲自体は二分探索には十分小さいです。 

正しく見える実装が失敗する可能性がある境界ケースがいくつかあります。 (P+Q\ge n) の場合、すべての爆弾は独自のツールで処理でき、許容される最小値 (w) は 1 であるため、答えはすぐに (1) になります。たとえば、次のようになります。`1 1 0`座標 100 にある単一の爆弾の場合、答えは 1 です。常に DP を実行するソリューションでも答えを得ることができますが、両方のツール タイプが利用可能であると想定する実装は (Q=0) の場合に失敗する可能性があります。 

間隔のエンドポイントは包括的です。 たとえば、`2 0 1`爆弾座標 1 と 3、タイプ 2 ツールは長さ (2w) の間隔をカバーします。 (w=1) では、2 つの爆弾の違いはちょうど 2 であるため、両方とも破壊され、正解は 1 になります。次のような厳密な比較を使用します。`x[j] < x[i] + 2*w`このケースは誤って拒否されてしまいます。 

爆弾は個別の座標を持つことが保証されているため、すべての座標が等しい入力は無効です。 意味のあるストレス ケースに最も近いものは、次のような密集したシーケンスです。`3 3 0`座標は 10、11、12 です。3 つのタイプ 1 ツールでそれぞれ 1 つの爆弾を除去できるため、答えは 1 です。 実装では、すべての有用な間隔に少なくとも 2 つの爆弾が含まれると想定すべきではありません。 

## アプローチ

 直接的な動的計画法により、3 つの量すべてが追跡されます。 州がまだ発見されていない最初の爆弾と、すでに使用されたタイプ 1 およびタイプ 2 の道具の数を説明してみましょう。 最初の露出した爆弾から、タイプ 1 ツールを使用して長さ (w) 間隔の外側にある最初の爆弾にジャンプするか、タイプ 2 ツールを使用して長さ (2w) 間隔の外側にある最初の爆弾にジャンプすることができます。 これは正しいです。すべての爆弾が一直線上にあり、すべての間隔が固定長であるため、左端のカバーされていない爆弾が間隔の開始として選択されたら、その間隔を可能な限り延長しても問題はありません。 

この定式化の問題は、その状態数です。 関連する最悪のケースでは、(n=2000) と (P,Q) はどちらも約 1000 であり、1 回の実現可能性チェックでおおよそ (2000\cdot1000\cdot1000=2\cdot10^9) の状態が得られます。 二分探索中にこのようなチェックを繰り返すことは、まったく現実的ではありません。 

重要な点は、両方の工具数を記憶する必要がないということです。 使用できるタイプ 1 ツールの数を固定するとします。 爆弾配列の接尾辞ごとに、その接尾辞を破壊するために必要な最小限のタイプ 2 ツールを保存できます。 タイプ 1 のカウントは DP 寸法になり、タイプ 2 のカウントは最小化された値になります。 

固定 (w) の場合、次のように定義します。`jump1[i]`タイプ 1 ツールが爆弾 (i) で開始するときにカバーされない最初の爆弾として。 同様に、`jump2[i]`(i) で始まるタイプ 2 ツールによってカバーされない最初の爆弾です。 現在の状態が (i) で始まるサフィックスである場合、次の決定はこれら 2 つの区間のいずれかに強制されます。 したがって、

 [
 f[i][j]=\min\left(f[\text{jump1}[i]][j-1],
 1+f[\text{jump2}[i]][j]\right)。 
】

 ここで (f[i][j]) は、最大 (j) 個のタイプ 1 ツールを使用して (i) 以降の爆弾を破壊するために必要なタイプ 2 ツールの最小数です。 

実装には便利な改良点が 1 つあります。 DP 寸法が小さい方の工具数 (P) または (Q) を選択できます。 (Q<P) の場合、概念的に 2 つのツール タイプの名前を交換します。 対応する間隔の長さも同様に交換されるため、繰り返しは変化しません。 (P+Q<n) が唯一の自明でないケースであるため、小さいカウントはせいぜいおおよそ (n/2) であり、実際の作業もほぼ半分になります。 

最後に、(w) では実現可能性は単調です。 いくつかの (w) が機能する場合、利用可能なすべての間隔が長くなるだけなので、より大きな (w) がすべて機能します。 これにより、(1) から (10^9) までの二分探索が行われます。 これは、コンテストの公式論説で説明されている (O(n^2\log 10^9)) DP 構造と同じです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 立体DP | (O(nPQ)) チェックあたり | (O(nPQ)) | 遅すぎる |
 | 2次元DP+二分探索 | (O(n^2\log 10^9)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての爆弾の座標を並べ替えます。 爆弾が命令されると、一番左のカバーされていない爆弾から始まるすべての間隔で、連続するインデックス範囲がカバーされます。 
2. (P+Q\ge n) の場合は、すぐに 1 を返します。 少なくとも爆弾と同じ数のツールがあれば、座標のギャップに関係なく、爆弾ごとに 1 つのツールで十分です。 
3. (P) と (Q) の小さい方を DP 寸法として選択します。 そのカウントを呼び出します`A`、その間隔の長さ`lenA`、他のツールの数を次のようにします。`B`インターバルの長さあり`lenB`。 type-1 の方が小さいリソースの場合、`lenA=w`そして`lenB=2*w`。 さもないと、`lenA=2*w`そして`lenB=w`。 
4. (w) の現在の値について、次を計算します。`jumpA[i]`そして`jumpB[i]`。 各ジャンプは、座標が次より大きい最初のインデックスです。`x[i] + len`。 座標はソートされているため、2 つのポインターがすべてのジャンプを線形時間で計算します。 
5. A タイプ ツールの許容数を増やして DP を処理します。 固定の場合`j`、計算する`cur[i]`、で始まるサフィックスを破棄するために必要な B タイプ ツールの最小数`i`せいぜい使用`j`Aタイプのツール。 
6. プロセス`i`右から左へ。 爆弾にA型ツールを使用した場合`i`、次の状態は`prev[jumpA[i]]`、 どこ`prev`前の値を表します`j-1`。 B タイプのツールを使用すると、次の状態は次のようになります。`cur[jumpB[i]] + 1`、現在の列ではすでに許可されているため、`j`Aタイプのツール。 
7. 移行は次のとおりです。 
[
 cur[a]=\amin(previous[jumpA[i]],cur[jumpA[i]]+1)。 
】
 最初のタームは次の場合にのみ利用可能です`j>0`。 第 2 項は、代わりに B タイプのツールを 1 つ消費するため、常に利用可能です。 
8. 計算後`cur[0]`、最大かどうかを確認してください`B`。 そうであれば、現在の (w) は実現可能です。 DP では B タイプのツールの数が最小限に抑えられているため、この 1 つの比較で十分です。 
9. 実現可能な最小値 (w) を求める二分探索。 答えを下回るすべての値は実行不可能であり、答え以上のすべての値は実行可能であるという標準の不変条件を使用します。 

### なぜ効果があるのか

 固定 (w) に対して実行可能な解決策を検討します。 一番左の覆われていない爆弾 (i) を見てください。 最初に使用するツールは爆弾 (i) を破壊する必要があり、A タイプのツールでも B タイプのツールでも構いません。 A タイプのツールの場合、次の間隔まで延長します。`x[i] + lenA`爆弾は単なる目標であり、追加の爆弾を破壊してもペナルティがないため、元のソリューションで保存する必要があった爆弾を削除することはできません。 残りの問題は、まさに次で始まる接尾辞です。`jumpA[i]`。 同じ理由が B タイプのツールにも当てはまります。`jumpB[i]`。 

DP は、すべてのサフィックスで両方の可能な選択肢を考慮し、許容される A タイプ ツールの数ごとに必要な B タイプ ツールの最小数を保存します。 したがって、不必要な情報を保存することなく、あらゆる有効なカバー戦略を表します。 最終状態は、その最小 B タイプ数が最大でも利用可能な数である場合に正確に実現可能です。`B`。 

(w) を増やすと間隔が広がるだけなので、二分探索は正しいです。 その結果、実現可能性は最大で 1 回だけ false から true に変化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**9

def feasible(w, x, p, q):
    n = len(x)

    if p + q >= n:
        return True

    # Use the smaller tool count as the DP dimension.
    if p <= q:
        a = p
        b = q
        len_a = w
        len_b = 2 * w
    else:
        a = q
        b = p
        len_a = 2 * w
        len_b = w

    jump_a = [0] * n
    jump_b = [0] * n

    r = 0
    for i in range(n):
        if r < i:
            r = i
        limit = x[i] + len_a
        while r < n and x[r] <= limit:
            r += 1
        jump_a[i] = r

    r = 0
    for i in range(n):
        if r < i:
            r = i
        limit = x[i] + len_b
        while r < n and x[r] <= limit:
            r += 1
        jump_b[i] = r

    # prev[i] = minimum B-type tools needed from i onward
    # using at most j-1 A-type tools.
    prev = [INF] * (n + 1)

    for j in range(a + 1):
        cur = [INF] * (n + 1)
        cur[n] = 0

        if j == 0:
            for i in range(n - 1, -1, -1):
                nxt = jump_b[i]
                cur[i] = cur[nxt] + 1
        else:
            for i in range(n - 1, -1, -1):
                use_b = cur[jump_b[i]] + 1
                use_a = prev[jump_a[i]]
                cur[i] = use_a if use_a < use_b else use_b

        if cur[0] <= b:
            return True

        prev = cur

    return False

def solve():
    n, p, q = map(int, input().split())
    x = [int(input()) for _ in range(n)]
    x.sort()

    if p + q >= n:
        print(1)
        return

    lo = 1
    hi = x[-1] - x[0]

    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(mid, x, p, q):
            hi = mid
        else:
            lo = mid + 1

    print(lo)

if __name__ == "__main__":
    solve()
```すべての遷移は最初のカバーされていない爆弾とその後の連続する爆弾にのみ依存するため、入力が最初にソートされます。 初期の`p + q >= n`check は、正確性の近道であると同時に、(w=1) で明らかに十分な場合に時間の無駄を防ぐための有用な保護手段でもあります。 

2 つのジャンプ配列はモノトーン ポインターを使用します。 爆弾を開始するたびに、ポインターは前方にのみ移動するため、いずれかの配列の構築には (O(n)) 時間がかかります。 比較`x[r] <= limit`は包括的であり、正確な境界の場合を正しく処理します。 

DP は 2 つのアレイのみを使用します。`prev`以前の A ツールの予算が含まれている一方で、`cur`現在のものが含まれています。 再発のニーズ`prev[jumpA[i]]`そして`cur[jumpB[i]]`、両方のインデックスは より大きい`i`ただし、サフィックスがすでに完成している場合を除きます。 だからこそ加工`i`右から左に入力すると、必要なすべての値がすぐに使用可能になります。 

インデックスの値`n`は空の接尾辞を表します。 追加のツールは必要ありません。`cur[n] = 0`が基本ケースです。 いつ`j=0`, Aタイプのツールの使用は禁止されているため、漸化式の最初の項は単純に省略されます。 

DP ディメンションとして小さいリソース数を選択することは、漸近限界には必要ありませんが、Python にとっては重要です。 問題が面白くなるのは、次の場合だけです。`p+q<n`, したがって、小さい方のカウントは (n/2) より下になります。 この実装では、(O(n^2)) テーブルの代わりに 2 つの DP 行のみが保存されます。 

Python の整数には任意の精度があるため、次のような座標演算を実行します。`2*w`オーバーフローすることはできません。 いずれにしても、関係する最大値は (2\cdot10^9) 程度です。

 ## 特殊なケース

 少なくとも爆弾と同じ数のツールがある場合、答えは常に 1 です。たとえば、次のようになります。```
1 1 0
100
```爆弾1つとタイプ1ツール1つを持っています。 座標 100 の周囲に配置された長さ 1 の間隔はそれを破棄するため、バイナリ検索は 1 を返す必要があります。実装は DP を構築する前に終了します。 

リソースがゼロの場合は、`j == 0`支店。 のために```
2 0 1
1
3
```使用できる唯一のツールはタイプ 2 です。 (w=1) では、その長さは正確に 2 であり、座標の差は正確に 2 です。ジャンプ条件は次を使用します。`<=`, したがって、2番目の爆弾が含まれており、答えは1です。 

同じ包含境界がタイプ 1 ツールにも適用されます。 のために```
2 1 0
1
2
```長さ 1 のタイプ 1 インターバルは両方の爆弾をカバーします。 最初のボムからのジャンプは空のサフィックスであるインデックス 2 に到達するため、DP はタイプ 1 ツールを 1 つだけ使用し、1 を返します。 

よくある誤った貪欲な考えは、可能な限り常に長いツールを使用することです。 リソースの制限により、それは安全ではなくなります。 サンプルについて```
3 1 1
2
11
17
```(w=4) では、タイプ 2 ツールは 11 と 17 をカバーできますが、タイプ 1 ツールは 2 を処理します。DP は、固定ツール設定にコミットするのではなく、この割り当てを明示的に考慮します。 

使用可能なすべてのツールが 1 つのタイプである場合でも、スワップされたリソースの定式化は引き続き機能します。 のために```
3 0 1
1
3
5
```小さい方のリソース次元はサイズがゼロのタイプ 1 次元であるため、DP には列が 1 つだけあります。 必要なタイプ 2 間隔の数を効果的に計算します。 (w=1) ではその数は 3 ですが、(w=2) では 1 になります。 

最後に、このステートメントは明確な爆弾座標を保証します。 実装では、等しい座標のための特別なロジックを追加したり、正のギャップを仮定する式を使用したりしないでください。 1、2、3 などの連続した座標は有効であり、2000 個の爆弾と 2000 個のタイプ 1 ツールを使用した最大サイズのテストのように、十分なツールが存在する場合は、すべて (w=1) で個別にカバーできます。
