 ## 解決策
 ## 問題の理解

 次の 1 次元配列があります。`N`ポジション。 B21 は位置から始まります`u`そしてその地位に到達したいと思っています`v`。 位置からの移動`i`に`i + 1`費用`R`から移動中`i`に`i - 1`費用`L`。 これらの移動は、目的の位置が配列内にある場合にのみ可能です。 

追加の操作が 1 つあります。 2 つの位置に同じ配列値が含まれている場合、B21 はコストをかけてそれらの間を直接テレポートできます。`C`、距離に関係なく。 課題は、から得るために必要な最小限のエネルギーを見つけることです。`u`に`v`。 

入力には以下が含まれます`N`、2方向の移動コスト`L`そして`R`、およびテレポートのコスト`C`。 次の行には開始位置と目的地の位置が示され、最後の行には配列値が含まれます。 必要な出力は、通常の移動とテレポートの有効なシーケンスの最小エネルギーです。 

制約`N <= 10^5`すべてのポジションのペアを検査するアルゴリズムを除外します。 特に、多くの位置が同じ値を持つ場合、考えられるすべてのテレポートを明示的に考慮すると、約`N^2`接続。 まで`10^5`の位置では、仕事がほぼ線形である解決策が必要です。`N log N`。 コストは次のように大きくなる可能性があります`10^9`、パスには多くの操作が含まれる可能性があるため、固定幅の整数型を使用する言語では 32 ビット整数では不十分です。 Python の整数はこれを自動的に処理します。 

いくつかのケースでは、誤って対処されやすいものがあります。 まず、開始位置と目的地の位置がすでに等しい可能性があります。 例えば、```
2 5 7 3
2 2
1 2
```必要`0`、B21はすでに目的地に到着しているためです。 常に少なくとも 1 つの動きを考慮する実装では、誤って正のコストが返される可能性があります。 

最も安価なルートは、一致する位置がすぐ隣接していない場合でもテレポートを使用する場合があります。 例えば、```
3 10 10 2
1 3
5 1 5
```答えがあります`2`: 位置`1`そして`3`同じ値が含まれているため、B21 は直接テレポートできます。 隣接する位置のみを考慮する実装では、次の結果が返されます。`20`。 

より安い方向は、ルートの進行方向によっても異なります。 例えば、```
2 7 2 100
2 1
1 2
```答えがあります`7`なぜなら、有用な動きは一歩後退することだけだからです。 移動を 1 つの対称的なコストを持つものとして扱うのは間違いです。 

最後に、テレポートは遠く離れた位置を接続することができ、複数の異なるテレポート グループが 1 つの最適なルートに参加する可能性があります。 開始値から宛先値への 1 つのテレポートだけを考慮するだけでは十分ではありません。 以下のグラフ定式化は、任意のシーケンスを自動的に処理します。 

## アプローチ

 最も直接的な解決策は、配列のすべての位置をグラフの頂点とみなすことです。 連続した位置には有向エッジがあります:`i`に`i + 1`費用がかかる`R`、そしてから`i`に`i - 1`費用がかかる`L`。 同じ値を含む位置のペアごとに、コストのテレポート エッジを追加することもできます。`C`。 

このグラフは元の問題を正確に表しているため、ダイクストラのアルゴリズムを実行すると正しい答えが得られます。 問題はテレポート エッジの数です。 もしすべてなら`N`位置に同じ値が含まれている場合、`N(N - 1)`方向性のあるテレポート エッジ。 のために`N = 100000`、それは約です`10^10`制限時間内に構築または処理できる範囲をはるかに超えています。 

重要な観察は、1 つの値に関連付けられたすべてのテレポート エッジが同じように動作するということです。 値を仮定します`x`位置で発生します`p1, p2, ..., pk`。 これらのポジションのいずれからでも、B21 は正確に費やすことができます`C`価値を得るためにテレポートネットワークに入る`x`そしてそのネットワークから、彼はあらゆる出来事に到達することができます。`x`それ以上何も支払うことなく。 

ペアワイズ テレポート エッジのコレクション全体を、値ハブと呼ばれる 1 つの追加のグラフ頂点で表すことができます。 あらゆる出来事に対して`pi`の`x`、エッジを追加します`pi -> hub_x`費用がかかる`C`、エッジ`hub_x -> pi`費用がかかる`0`。 出発地`pi`に`pj`ハブ経由のコストは正確です`C + 0 = C`、これはまさに元のテレポートのコストです。 

これで、各配列位置は一定数のエッジのみに寄与します。 多くてもあります`N`個別の値なので、最大でも`2N`グラフの頂点と`O(N)`エッジ。 その後、ダイクストラのアルゴリズムが実行されます。`O(N log N)`時間。 

このブルートフォース構築は、考えられるすべてのテレポートが明示的に表現されているため機能しますが、1 つの値が何度も発生すると失敗します。 値を共有するすべてのテレポートが 1 つのハブに圧縮できるという観察により、二次テレポート グラフが疎なグラフに縮小されます。

 | 最適 |`O(N log N)`|`O(N)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、個別の値ごとに 1 つの仮想ハブを作成します。 ハブは、その値を含むすべての位置間をテレポートする機能を表します。 
2. 隣接する位置間に通常の移動エッジを作成します。 あらゆる人にとって`i < N`、 追加`i -> i + 1`費用がかかる`R`、と追加します`i + 1 -> i`費用がかかる`L`。 前方への移動と後方への移動には異なるコストがかかる可能性があるため、これらは有向エッジです。 
3. ポジションごとに`i`に属するハブに接続します。`A[i]`費用がかかる`C`、そのハブを所定の位置に接続し直します`i`費用がかかる`0`。 2 つのエッジのパスは、からの 1 つのテレポートを表します。`i`同じ値が発生する他のすべての値に適用されます。 
4. 位置からダイクストラのアルゴリズムを実行する`u`。 すべてのグラフ エッジには負ではないコストがあるため、現在の最短距離で優先キューから初めて頂点が削除されたときに、その距離が最終的な距離となります。 
5. 位置の距離を返す`v`。 元の問題におけるすべての合法的な移動またはテレポートには、圧縮されたグラフ内に同等のパスがあり、すべての圧縮されたテレポート パスは合法的なテレポートに対応するため、グラフの最短パスはまさに必要な最小エネルギーになります。 

### なぜ効果があるのか

 元の問題における合法的なルートを検討してください。 すべての通常の動きは、1 つの隣接位置エッジに直接対応します。 あらゆる位置からのテレポート`i`位置を決める`j`と`A[i] = A[j]`に対応する`i -> hub[A[i]] -> j`、総コストは`C`。 したがって、すべての元のルートには、同様に高価なグラフ ルートが含まれます。 

逆に、すべてのグラフ ルートは通常の移動エッジ、または位置からハブ、位置へのシーケンスで構成されます。 後者は、両方の位置が同じ値グループに属し、コストが正確であるため、有効なテレポートです。`C`。 したがって、グラフのルートはすべて、同じコストの有効な元のルートを表します。 

したがって、圧縮されたグラフ内の最短経路が最小有効エネルギーになります。 すべてのエッジの重みが負ではないため、ダイクストラはその最短経路を見つけます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, L, R, C = map(int, input().split())
    u, v = map(int, input().split())
    a = list(map(int, input().split()))

    # Compress each distinct array value into one virtual hub.
    value_id = {}
    groups = []

    for i, x in enumerate(a):
        if x not in value_id:
            value_id[x] = n + len(groups)
            groups.append([])
        groups[value_id[x] - n].append(i)

    m = n + len(groups)
    graph = [[] for _ in range(m)]

    # Ordinary moves along the array.
    for i in range(n - 1):
        graph[i].append((i + 1, R))
        graph[i + 1].append((i, L))

    # Teleport hubs.
    for hub_index, positions in enumerate(groups):
        hub = n + hub_index
        for pos in positions:
            graph[pos].append((hub, C))
            graph[hub].append((pos, 0))

    start = u - 1
    target = v - 1

    INF = 10**30
    dist = [INF] * m
    dist[start] = 0

    pq = [(0, start)]

    while pq:
        d, node = heapq.heappop(pq)

        if d != dist[node]:
            continue

        if node == target:
            print(d)
            return

        for nxt, cost in graph[node]:
            nd = d + cost
            if nd < dist[nxt]:
                dist[nxt] = nd
                heapq.heappush(pq, (nd, nxt))

if __name__ == "__main__":
    solve()
```最初の部分では、それぞれの個別の配列値に一意の仮想頂点を割り当てます。 実際の数値は次のように大きくなります。`10^9`したがって、値自体を配列インデックスとして使用するのは無駄です。 ディクショナリは、各値をコンパクトなハブ インデックスにマップします。 

隣接位置のエッジは 2 つの移動方向を別々にエンコードします。 からのエッジ`i`に`i + 1`費用`R`、逆エッジはコストがかかります`L`。 位置はゼロベースのインデックスを使用して内部的に保存されるため、位置を入力します。`u`になる`u - 1`。 

値が出現するたびに、コードはコストを追加します。`C`ポジションからハブまでのエッジと、ハブからポジションに戻るまでのコストがゼロのエッジです。 したがって、ある出現から別の出現へのテレポートは、正確に 2 つのエッジによって表されます。 

優先キューには以下が含まれます`(distance, vertex)`ペア。 小切手`if d != dist[node]`古いエントリを破棄します。`heapq`既存のキーの減少はサポートされていません。 より良い距離が見つかった場合は、新しいペアが単純に挿入されます。 

ターゲットがポップされたときの早期リターンは、ダイクストラのアルゴリズムの下で有効です。 この時点で、ターゲットは残りのすべての頂点の中で最小の暫定距離を持っているため、その後の緩和によってより小さなパスを生成することはできません。 

Python では整数オーバーフローの懸念はありません。 の`10**30`value は、考えられるどの答えよりもはるかに大きい、単なる便利な無限大です。

唯一の有用なルートが配列全体にわたるテレポートである場合、値ハブにより、実装では等しい位置のすべてのペア間に明示的なエッジが要求されなくなります。 のために```
