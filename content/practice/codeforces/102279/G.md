 ## 解決策
 ## 問題の理解

 木が2本あります。 B21 は木の根元を最適に選択し、その高さをできるだけ大きくしようとします。 Lowie は、B21 の観点から敵対的に自分の木のルートを選択するため、B21 は、B21 の結果の高さを厳密に大きくする Lowie の木のルートが存在するかどうかを知るだけで済みます。 

根のある木の高さは、根から頂点までの最長のパス上の頂点で測定されます。 代わりにエッジで測定された距離を使用すると便利です。 ルートから任意の頂点までの最長距離が`h`エッジ、木の高さは`h + 1`頂点。 余分な`1`は両方の木に表示されるので、高さを比較すると消えます。 

B21 の場合、考えられるすべての根の高さを最大化することは、木の直径を見つけることとまったく同じです。 直径があれば`D`エッジ、根元の高さとして直径の終点を選択します。`D + 1`。 

Lowie の場合は、逆の量が必要です。 B21 は、ローウィーの身長をできるだけ小さくする何らかの根があるかどうかを知りたいと考えています。 ルートからすべての頂点までの最小可能な最大距離はツリーの半径であり、これは次のようになります。`ceil(D / 2)`直径が`D`。 したがって、B21 の観点から見た Lowie の可能な最高の高さは次のとおりです。`ceil(D / 2) + 1`。 

入力には、B21 のツリーとそれに続く Lowie のツリーが含まれています。 ある木`N`頂点には`N - 1`アーカイブされた声明のテキストには次のように書かれていたにもかかわらず、エッジ`N`エッジライン。 例では、`N - 1`エッジはツリーの定義と一致する唯一の形式であるため、実装では次のようになります。`N - 1`そして`M - 1`エッジ。 

制限が十分に大きいため、二次走査は不可能です。 まで`10^5`B21 のツリーの頂点と`2 * 10^5`Lowie のツリーの頂点、`O(N^2 + M^2)`メソッドには前後が必要になる場合があります`10^11`近隣訪問。 公式の制限は 256 MB のメモリでわずか 1 秒であるため、目的のソリューションでは各ツリーを線形時間で処理する必要があります。 

最初のエッジ ケースは、単一頂点 B21 ツリーです。```

```B21 の直径はゼロエッジなので、最大高さは次のようになります。`1`。 Lowie の木は一端に直径があるため、最小可能な高さでも`2`。 B21は勝てない、その答えは`FF`。 すべてのツリーに少なくとも 1 つのエッジがあると想定する不注意な実装は、その DFS が存在しない隣接木から開始する場合、または直径を初期化する場合に失敗する可能性があります。`1`。 

2 番目のエッジケースは、まさに境界線での引き分けです。```

```B21の直径は`3`一方、ローウィーの直径は`6`。 ローウィーの最小半径は`ceil(6 / 2) = 3`, したがって、両方のプレイヤーが高さを取得できます`4`。 正しい答えは、`FF`, 引き分けは勝利としてカウントされないためです。 を使用した不用意な実装`>=`の代わりに`>`間違って印刷されてしまう`GGEZ`。

## アプローチ

 直接的な解決策は、考えられるすべてのルートを試すことになります。 各ルートに対して DFS または BFS を実行し、最も遠い頂点を見つけます。 これらの値の最大値を取得すると、B21 の最適な高さが得られ、最小値を取得すると、Lowie が誤って選択した可能性のある最適なルートが得られます。 これは正しいです。木の高さの定義は、選択したルートからの最大距離と正確に一致するからです。 

問題は反復トラバースです。 の横断`N`-頂点ツリーを調べます`2(N - 1)`隣接エントリ。 したがって、ルートごとに 1 回実行すると、`2N(N - 1)`近隣訪問。 Lowie のツリーに対して同じことを行うと、別の結果が得られます`2M(M - 1)`。 で`N = 10^5`そして`M = 2 * 10^5`、これについてです`99,999,400,000`制限時間をはるかに超えた近隣訪問。 

各ルートが 1 つの木の高さを個別に決定するため、総当たりアプローチは機能しますが、実際にはすべてのルートを検査する必要はありません。 ツリーの構造により、必要なものを正確に要約する 2 つのグローバル量が得られます。 

ルートを変更することで得られる最大の高さは直径になります。 直径の端点が`a`そして`b`、で応援しています`a`到達する`b`可能な最大距離での距離なので、結果の高さは直径に 1 を加えたものになります。 

ルートを変更することによって得られる最小の高さは半径です。 すべての頂点は選択したルートの近くにある必要があり、可能な限り最良のルートがツリーの中心になります。 中心は直径の途中にあります。`D`最小可能な最大距離は`ceil(D / 2)`。 

これにより、問題全体が 2 つの直径の計算に集約されます。 ツリーの直径は 2 つのグラフの走査で見つけることができます。 任意の頂点から開始して最も遠い頂点を見つけます`a`。 次に、から始めます`a`そして最も遠い頂点を見つけてください`b`。 からの距離`a`に`b`直径です。 

させて`D_B`B21 のエッジの直径、および`D_L`エッジのローウィーの直径になります。 B21 が勝つのはまさにそのときです`D_B + 1 > ceil(D_L / 2) + 1`これを単純化すると`D_B > ceil(D_L / 2)`。 

結果として得られる比較は、2 つのツリーのサイズにおいて線形です。 これは、コンテストの公式編集者が説明したアプローチでもあり、問題を可能な限り最大および最小の木の高さに落とし込み、1 つの木につき 2 回のトラバースで必要な直径を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(N² + M²)`|`O(N + M)`| 遅すぎる |
 | 最適 |`O(N + M)`|`O(N + M)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. B21 のツリーを読み取り、その隣接リストを作成します。 ある木`N`頂点は正確に持っています`N - 1`エッジなので、これらは B21 のグラフに属するエッジです。 
2. 2 回のトラバースで B21 の直径を計算します。 任意の頂点から開始して、最も遠い頂点を見つけます`a`、から開始します`a`そして最も遠い頂点を見つけてください`b`。 からの距離`a`に`b`は`D_B`、エッジの直径。 
3. Lowie のツリーを読み取り、その隣接リストを作成します。 同じツリー プロパティとは、次のものが含まれていることを意味します。`M - 1`エッジ。 
4. ローウィー直径を計算する`D_L`同じ 2 つのトラバース手法を使用します。 
5. Lowie の直径を根からの最小の最大距離に変換します。 直径の中心にある根元はその最遠距離を最小化し、半径を与えます。`ceil(D_L / 2)`。 整数演算ではこれは`(D_L + 1) // 2`。 
6. B21の最大距離を比較する`D_B`Lowie の最小可能な最大距離で。 B21 が勝つのはまさにそのときです`D_B > (D_L + 1) // 2`。 平等は引き分けを生み出すため、厳密な平等が必要です。 
7. 印刷`GGEZ`不等式が成り立つとき、そして`FF`さもないと。 

### なぜ効果があるのか

 重要な不変条件は、根のある木のすべての高さは、根からのエッジの最大距離に 1 を加えたものとして表現できるということです。 直径の端点は直径の距離で反対側の端点に到達できるため、すべての根の最大の値は直径に 1 を加えたものになります。 そのような最小値は半径に 1 を加えたもので、すべての木の中心には偏心があります。`ceil(D / 2)`、 どこ`D`直径です。 したがって、B21 は、その直径が厳密に Lowie の半径よりも大きい場合に、勝者となるルートの選択を持ちます。 2 回のトラバース手順では各直径が正確に計算されるため、最終的な比較で勝利の可能性のあるルートを見逃したり、引き分けしかできない場合に勝利を宣言したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def diameter(graph):
    n = len(graph)

    def farthest(start):
        dist = [-1] * n
        dist[start] = 0
        stack = [start]
        far = start

        while stack:
            u = stack.pop()
            if dist[u] > dist[far]:
                far = u

            for v in graph[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    stack.append(v)

        return far, dist[far]

    if n == 1:
        return 0

    a, _ = farthest(0)
    _, d = farthest(a)
    return d

def solve():
    n = int(input())
    b21 = [[] for _ in range(n)]

    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        b21[u].append(v)
        b21[v].append(u)

    m = int(input())
    lowie = [[] for _ in range(m)]

    for _ in range(m - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        lowie[u].append(v)
        lowie[v].append(u)

    db = diameter(b21)
    dl = diameter(lowie)

    lowie_radius = (dl + 1) // 2

    if db > lowie_radius:
        print("GGEZ")
    else:
        print("FF")

if __name__ == "__main__":
    solve()
```の`diameter`関数は、チュートリアルで説明した 2 つの走査を正確に実行します。 最初のトラバーサルでは最も遠い頂点を識別するだけで済みますが、2 番目のトラバーサルではその頂点から到達可能なすべての頂点までの距離が記録され、最大の頂点が返されます。 

グラフはツリーなので、単純な反復 DFS で十分です。 すべてのエッジの単位コストが同じであり、重み付けされていないツリーの最遠距離のみが必要なため、BFS は必要ありません。 明示的なスタックを使用すると、次のパスを含むパスでの Python の再帰の深さの問題も回避されます。`10^5`または`2 * 10^5`頂点。 

の`n == 1`頂点が 1 つの木の直径はゼロなので、チェックが必要です。 最初のトラバーサルは引き続き機能しますが、このケースを明示的に処理すると定義が明確になり、空の隣接リストに対する汎用の最遠ノード ロジックの動作に依存することがなくなります。 

直径から半径への変換には、`(dl + 1) // 2`。 均一な直径の場合、`6`、これは与えます`3`。 奇数の直径の場合、`5`、それは与えます`3`、これは床ではなく必要な天井です。 

最終的な比較は厳密です。 もし`db == lowie_radius`、結果の高さは等しいため、出力は次のようになります。`FF`。 

頂点インデックスは、1 ベースの入力から 0 ベースの Python インデックスに変換されます。 Python では整数オーバーフローは不可能であり、すべての距離は最大で`2 * 10^5 - 1`。

```どちらの木もスターです。 それらの直径は`2`したがって、Lowie の半径は次のようになります。`1`。 B21の直径`2`厳密にはより大きいです`1`、そしてアルゴリズムは出力します`GGEZ`。 これは、解が木がパスであるか、多くの枝があるかには依存せず、直径のみに依存する理由を示しています。 

最大サイズの場合、両方のツリーはパスであり、`100000`そして`200000`それぞれの頂点。 それらの直径は`99999`そして`199999`。 ロウイーの半径は`(199999 + 1) // 2 = 100000`、一方、B21 の直径はわずかです`99999`、したがって、答えは次のとおりです`FF`。 この実装では、入力全体を 4 つの線形トラバーサルで処理し、二次距離行列を構築しません。これはまさに制約で必要な動作です。
