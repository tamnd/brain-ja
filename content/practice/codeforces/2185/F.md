 ## 解決策
 ## 問題の理解

 トーナメントは、一連の牛の完全な二分木として見ることができます。 

それぞれの葉は一頭の牛です。 すべての内部ノードは牛の連続したセグメントを表します。 ノードのスキルは、そのセグメント内のすべての値の XOR です。 ノードの 2 つの子が戦う場合、XOR が大きい子が勝ち、XOR が等しい場合は左側の子が勝ちます。 

勝ちスタックは負けスタックの上に置かれます。 

クエリごとに、正確に 1 頭の牛がそのスキル値を一時的に変更します。 私たちはトーナメント全体を運営し、最終スタックでその牛の上に何頭の牛が入るかを決定する必要があります。 

牛の頭数は、$2^n$、 と$n \le 18$。 すべてのテストケースにわたって、牛の総数は最大で$2^{18}$、クエリの合計数は最大でも$2 \cdot 10^5$。 

1 つのトーナメントの完全なシミュレーションには、すべてのトーナメントを処理する必要があります。$2^n-1$一致します。 最大規模のテストでは、これは約$2.6 \cdot 10^5$クエリごとの操作。 乗算$2 \cdot 10^5$クエリは完全に不可能です。 

の小さな値$n$が本当の手がかりです。 1 頭の牛はラウンドごとに 1 つの試合に参加するため、関与するのは 1 つの試合のみです。$n \le 18$一致します。 変更されたリーフからルートまでのパスのみを処理するソリューションは、直ちに適切な複雑さの範囲に入ります。 

単純な実装では問題が発生する可能性がある場所がいくつかあります。 

ネクタイを考えてみましょう。 左側のセグメントに XOR 5 があり、右側のセグメントにも XOR 5 がある場合、左側のセグメントが勝ちます。 を使用した比較`>=`どちらの側も間違っているでしょう。 

例えば：```
2 cows
5 5
```左の牛が勝つので、最終的なスタックは次のようになります。```
right, left
```左の牛の上には 0 頭の牛がいますが、右の牛には 1 頭います。 

もう 1 つの簡単な間違いは、スタック順序が将来の XOR 値に影響を与えると仮定することです。 そうではありません。 XOR は、順序ではなく、どの牛がスタックに属しているかのみに依存します。 これに気づくと、すべてのセグメントのスキルは単にその区間の XOR にすぎません。 

3 番目の間違いは、スタック全体を追跡しようとすることです。 必要なのは 1 頭の牛の位置だけです。 セグメント内の相対的な順序は決して変わりません。 重要なのは、牛を含むセグメントが各祖先の一致に勝つか負けるかだけです。 

## アプローチ

 ブルートフォースの解決策は簡単です。 

クエリごとに、選択した牛の値を変更し、すべてのトーナメント ラウンドをシミュレートし、結果のスタックを構築し、最後に最終スタックで変更された牛を見つけます。 

のトーナメント$N=2^n$牛には含まれています$N-1$一致します。 の最大値$N$は262144です。$2 \cdot 10^5$クエリの場合、これはおおよそ次のようになります$5 \cdot 10^{10}$限界をはるかに超えた操作。 

重要な観察は、変更された牛がトーナメント ツリーの根から葉への 1 つのパスのみに影響を与えるということです。 

リーフ値の変更$a_b$に$c$すべての祖先セグメントの XOR を同じ量だけ変更します。$$\Delta = a_b \oplus c.$$その牛を含まないすべてのセグメントは、以前とまったく同じ XOR を保持します。 

次に、変更された牛の最終的な位置について考えてみましょう。 

ある祖先ノードでは、そのセグメントが兄弟セグメントと競合します。 

そのセグメントが勝った場合、兄弟セグメントはその下に入ります。 私たちの牛の上に新しい牛は現れません。 

そのセグメントが負けた場合は、兄弟セグメントが上に配置されます。 その兄弟セグメント内のすべての牛が私たちの牛の上になります。 

したがって、答えは簡単です。$$\sum \text{(size of sibling segment)}$$牛側が負けたすべての先祖の試合で。 

一頭の牛が持っているのは、$n$先祖たち。 リーフからルートまで歩いて、そのパスに沿って変更された XOR を再計算し、その側が各一致に勝つかどうかを判断できます。 

それは$O(n)$クエリ。 

まずトーナメント ツリーを 1 回構築し、すべてのセグメントの XOR を保存します。 次に、各クエリは、$n \le 18$1 つのパス上のノード。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(qN)$|$O(N)$| 遅すぎる |
 | 最適 |$O(N + q\log N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 前処理

 葉が牛の値である完全なバイナリ ツリーを構築します。 

すべての内部ノードについて、その 2 つの子の XOR を保存します。 

これにより、トーナメントのすべてのセグメントの XOR が得られます。 

### クエリに答える

 牛だとしましょう`b`からの変更`a[b]`に`c`。 

させて$$\Delta = a[b] \oplus c.$$変更されたリーフ値は単純に次のようになります。`c`。 

次に、その葉から根に向かって上向きに歩きます。 

1.セット`cur`現在のノードの変更された XOR に変換されます。 

もともとこれは`c`、現在のノードはリーフそのものであるためです。 
2. 親で兄弟ノードを特定します。 
3. しましょう`sib`は、その兄弟セグメントの保存された XOR になります。 
4. 改造された牛を含む側が勝つかどうかを決定します。 

こちらの側が左の子の場合、次の場合に勝ちます。$$cur \ge sib$$タイが左に行くからです。 

こちらの側が正しい子の場合、次の場合にのみ勝ちます。$$cur > sib$$5. こちらの側が負けた場合は、兄弟セグメントのサイズを答えに追加します。 

そのセグメント内のすべての牛が牛の上に積み重ねられます。 
6. 親セグメントの XOR を計算します。$$cur = cur \oplus sib$$これは、親間隔の変更された XOR です。 
7. 親に移動し、ルートに到達するまで繰り返します。 
8. 蓄積された回答を出力します。 

### なぜ効果があるのか

 すべての内部ノードについて、その子の 1 つが他のノードの上にスタックされます。 

変更された牛は常にそのノードの 1 つの子の中に残ります。 

その子が勝った場合、兄弟セグメントはその下に入り、変更された牛の上の牛の数には何も寄与しません。 

その子が負けた場合、兄弟セグメント全体がその上に配置されます。 その兄弟セグメント内のすべての牛は修正された牛の上にあり、そのセグメントのサイズに正確に寄与します。 

これらの貢献はツリーのレベル全体にわたって独立しています。 変更された牛の上で終了するすべての牛は、変更された牛の側が失われた正確に 1 つの祖先の兄弟セグメントに属します。 

これらの失われた兄弟セグメントのサイズを合計すると、変更された牛より上位のすべての牛が 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, q = map(int, input().split())
        m = 1 << n

        a = list(map(int, input().split()))

        size = m
        seg = [0] * (2 * size)

        for i in range(m):
            seg[size + i] = a[i]

        for i in range(size - 1, 0, -1):
            seg[i] = seg[i << 1] ^ seg[i << 1 | 1]

        for _ in range(q):
            b, c = map(int, input().split())
            pos = b - 1

            node = size + pos
            cur = c
            ans = 0

            seg_size = 1

            while node > 1:
                parent = node >> 1

                if node & 1:
                    sibling = node - 1
                    sib_xor = seg[sibling]

                    if cur <= sib_xor:
                        ans += seg_size
                else:
                    sibling = node + 1
                    sib_xor = seg[sibling]

                    if cur < sib_xor:
                        ans += seg_size

                cur ^= sib_xor
                node = parent
                seg_size <<= 1

            print(ans)

solve()
```ツリーは、標準の反復セグメント ツリー レイアウトで保存されます。 

葉が位置を占めています`size ... 2*size-1`。 すべての内部ノードは、そのセグメントの XOR を保存します。 

クエリの場合、ツリーを変更することはありません。 クエリは独立しているため、再構築または更新は無駄になります。 

変数`cur`現在のパス上の変更されたセグメントの XOR 値を保存します。 葉では等しい`c`。 1 レベル上に移動すると、仮想的な変更の下で親セグメント全体の XOR になります。 

変数`seg_size`現在のレベルでの兄弟セグメントのサイズを格納します。 リーフ レベルでは、兄弟には 1 頭の牛が含まれます。 上昇するたびに、セグメントのサイズは 2 倍になります。 

比較は微妙な部分です。 

セグメントが左側の子の場合、同点は勝ちであるため、負けは次のことを意味します。```
cur < sib_xor
```セグメントが正しい子の場合、同点は損失となるため、損失は次のことを意味します。```
cur <= sib_xor
```これらの不等式を間違えると、同点の場合に不正確な答えが生成されます。

 ## 特殊なケース

 ### 2 つのセグメント間を結び付ける

 入力:```
1
1 1
5 5
2 5
```右側の牛は XOR 5 を持ち、XOR 5 を持つ左側のセグメントに面しています。 

同点が左に行くため、右のセグメントが負けます。 左側のセグメントはその上に積み重ねられるため、1 つの牛が牛 2 の上で終了します。 

アルゴリズムは、正しい子の厳密な比較を使用してこれを処理します。 以来`cur <= sibling`、兄弟サイズが追加されます。 

### 改造牛がすべての試合に勝利

 入力:```
1
2 1
1 2 3 4
4 100
```変更された値は、そのパス上のすべての比較を支配します。 

兄弟セグメントがその上に積み重ねられることはありません。 

このアルゴリズムではセグメント サイズが追加されることはなく、答えが生成されます。`0`。 

### 改良された牛はすべての試合に負けます

 入力:```
1
2 1
8 1 8 1
2 1
```Cow 2 は最初のレベルで負け、その結果のセグメントは次のレベルで再び負けます。 

答えは次のようになります。```
1 + 2 = 3
```これは、トーナメントに出場する他の牛の数とまったく同じです。 

各損失はそのレベルの兄弟セグメントのサイズに寄与し、アルゴリズムは両方の寄与を正しく累積します。
