 ## 解決策
 ## 問題の理解

 個々の試合のことを考えなくなると、大会は驚くほどシンプルな構造になっている。 

牛が試合で生き残るたびに、その新しいスキルは 2 人の参加者の合計になります。 数回連続で勝利した後、生き残った牛のスキルは、単に吸収したすべての牛の合計になります。 

初期スキルを持つ 1 頭の特定の牛に焦点を当てたとします。`v`。 元の位置から取り外して、別の場所に挿入します。 問題は、最大何回の挿入位置でこの牛が最後の生き残りになれるかということです。`k`負けが勝ちに変わる。 

重要な観察は、牛が列内のある位置に到達すると、その左側にあるすべてのものはすでに 1 頭の牛に統合されており、その強さはこれらの値の合計に等しいということです。 重要なのは、現在の牛の体力が少なくともその累計以上であるかどうかです。 そうでない場合は、チートが 1 つ必要です。 

すべてのテストケースにわたる牛の総数は最大で`2 · 10^5`。 すべての牛をすべての位置で明示的にシミュレートするアプローチは、すぐに二次関数になり、あまりにも大きすぎます。 周りに何かが必要です`O(n log n)`テストケースごと、または`O(n log^2 n)`最悪の場合。 

牛を一番前に入れると微妙なエッジケースが現れます。 

例えば：```
n = 3, k = 0
a = [1, 2, 3]
```牛なら`3`位置に移動されます`1`、結合されたプレフィックスと戦う必要はありません`[1,2]`。 すべてのポジションを常に左側のマージがあるかのように扱うと、必要なチートが過剰にカウントされてしまいます。 

もう 1 つの簡単な間違いは、牛が右に移動する間に多くのチートが必要になる可能性があると想定することです。 チートで勝利するたびにその強さは少なくとも 2 倍になるため、個別のチート イベントの数は値の範囲内で対数にすぎません。 この事実が解決策を実現可能にします。 

## アプローチ

 ブルートフォースの解決策は簡単です。 

牛を選びます。 全部試してみる`n`挿入位置。 トーナメント全体をシミュレートし、牛が何回イカサマをする必要があるかを数えてください。 カウントを超えない場合`k`、その位置は良いです。 

1 回のシミュレーションにかかる費用`O(n)`。 がある`n`それぞれのポジション`n`牛、与える`O(n³)`最悪の場合は動作します。 最適化を行ったとしても、それに近いものは`O(n²)`テストケースごとの速度はすでに遅すぎます`n = 2 · 10^5`。 

画期的な進歩は、プレフィックス合計を通じてトーナメントを観察することによってもたらされます。 

させて```
pref[i] = a1 + a2 + ... + ai
```力強い牛のとき`v`先頭に立ち、左から右へ牛を吸収し始めます。チートはまさに次の位置で必要です。```
a[i] > pref[i-1]
```牛に出会うまでに今の体力が溜まっているので`i`等しい`pref[i-1]`。 これらの「危険な」位置は、ほとんどの挿入選択肢とは無関係です。 さらに、そのような位置がチートを強制するたびに、牛の強さは少なくとも2倍になるため、危険な位置の総数はわずかです。`O(log A)`。 

牛ごとに、その牛を除去した後も関連性が残る一連の危険な位置を構築できます。 このセットから次のことを決定できます。 

1. すべてのポジションが自動的に勝利するかどうか。 
2. 挿入位置の接尾辞は最大でどれが必要ですか`k`詐欺師。 
3. 牛が正確に必要とする特別な境界ケース`k`チートを使用すると左側のマージが消える場合があります。 

これにより、問題はプレフィックスの合計と危険な位置の順序付きリストの二分探索に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックスの合計を計算する`pref`。 
2. リストを作成する```
pos = { i | a[i] > pref[i-1] }
```これらはまさに、前からスタートする牛がチートを必要とする場所です。 
3. 牛ごとに加工する`i`独立して。 
4. フィルタリングされたリストを作成する`g`。 

あらゆる危険な位置に対して`x ≠ i`、牛を除去した後も危険が残るかどうかを判断します。`i`。 

もし`x < i`、前の接頭辞`x`は変わっていない。 

もし`x > i`、削除された値`a[i]`プレフィックスから消えるので、条件は次のようになります。```
a[x] > pref[x-1] + a[i]
```受け入れられたソリューションとまったく同じです。 
5. しましょう`m = len(g)`。 

もし`m < k`、最悪の挿入位置であっても使用する量は以下のとおりです。`k`チートなのでどのポジションでも良いです。 
6. もし`k > 0`に対応する位置を見つけます。`k`最後から - 番目の危険なイベント。 

これにより、チート予算内で獲得できる挿入位置の最大サフィックスが決まります。 
7. 特殊なケースが発生するのは次の場合です。`m == k`。 

ここでの答えには、左側のマージが完全に消える位置も含まれます。 

接頭辞の合計と二分探索を使用して、追加のチートを回避しながら牛をどこまで左に挿入できるかを見つけます。 
8. 各牛の累積数を出力します。 

### なぜ効果があるのか

 重要な不変条件は、牛がある種の牛を吸収した後、その強さはそれらの強さの合計に等しいということです。 勝利の正確な順序は重要ではありません。 

チートが必要になるのは、次の相手が今までに蓄積した強さを超えた場合だけです。 これらのイベントは、まさにプレフィックスサム条件によって特定される危険な位置です。 

1 頭の牛を削除すると、その右側のプレフィックスのみが変更されます。そのため、トーナメント全体を再計算するのではなく、危険位置セットを調整することですべての牛を処理できます。 

サフィックスをカウントするステップが機能するのは、遭遇した危険なイベントの数に対して挿入位置が単調になるためです。 ポジションに以上のものが必要になると、`k`チートを使用すると、同じ領域内の以前の位置もすべて失敗します。 この単調性により二分探索が可能になります。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, k = map(int, input().split())
        a = [0] + list(map(int, input().split()))

        pref = [0] * (n + 1)
        for i in range(1, n + 1):
            pref[i] = pref[i - 1] + a[i]

        pos = []
        for i in range(1, n + 1):
            if a[i] > pref[i - 1]:
                pos.append(i)

        ans = [0] * (n + 1)

        for i in range(1, n + 1):
            g = []

            for x in pos:
                if x == i:
                    continue

                if a[x] > pref[x - 1] + (a[i] if x < i else 0):
                    g.append(x)

            if len(g) < k:
                ans[i] = n
                continue

            cur = 0

            if k > 0:
                p = g[-k]
                cur += n - p + 1 - (1 if p < i else 0)

            if len(g) == k:
                if pref[i - 1] >= a[i]:
                    cur += bisect_left(pref, a[i], 1) - 1
                else:
                    cur += bisect_left(pref, 2 * a[i], 1) - 2

            ans[i] = cur

        print(*ans[1:])

solve()
```この実装は、コンテスト分析コミュニティから受け入れられたアイデアに従っています。 すべてのトーナメント状態は以前に吸収された牛の合計で表されるため、プレフィックス合計配列が中心的な構造になります。 

フィルタリングされたリスト`g`最もデリケートな部分です。 牛の撤去`i`は右側のすべての接頭辞を変更するため、危険条件を調整する必要があります。 ここで方向を間違えると、多くの隠れたテストで 1 つずつエラーが発生します。 

表現```
g[-k]
```を選択します`k`最後から数えて 番目の危険な位置。 これは次の場合にのみ有効です。`k > 0`そのため、コードではそのケースを個別に処理します。 

すべての算術演算では Python 整数が使用されるため、プレフィックスの合計が約 100 に達してもオーバーフローのリスクはありません。`2 · 10^14`。 

## 実用的な例

 ### 例 1```
n = 2
k = 0
a = [2, 1]
```| 私 | 危険な位置 | 長さ(g) | 良いポジション |
 | --- | --- | --- | --- |
 | 1 | ∅ | 0 | 2 |
 | 2 | {1} | 1 | 0 |

 牛`1`すでにあらゆる可能な配置を支配しています。 牛`2`不正行為をしないと強い牛に勝つことはできません。 

### 例 2```
n = 3
k = 1
a = [1, 1, 3]
```| 私 | 取り外し後の危険な位置 | 長さ(g) | 答え |
 | --- | --- | --- | --- |
 | 1 | {3} | 1 | 2 |
 | 2 | {3} | 1 | 2 |
 | 3 | ∅ | 0 | 3 |

 大きな牛はどの挿入位置でも勝つことができます。 小さな牛が勝つことができるのは、利用可能な 1 つのチートが最適に使われた場合のみです。 

これらのトレースは、主要な不変条件を示しています。つまり、トーナメント全体のシミュレーションではなく、危険な位置のみが重要です。

 ## 特殊なケース

 検討してください```
n = 2
k = 0
a = [1, 1]
```最初の牛が同点の勝ちとなります。 同点ルールを無視してどこでも厳密な比較を使用すると、どちらの牛も勝つことができないという誤った結論を下してしまいます。 危険なポジションは以下を使用して定義されるため、プレフィックスベースの定式化では元のトーナメント ルールが維持されます。`>`それよりも`>=`。 

考慮する```
n = 3
k = 0
a = [1, 2, 3]
```最後の牛を前に移動すると、左側のマージ全体が削除されます。 アルゴリズムは特別なメソッドを通じてこれを処理します。`len(g) == k`ブランチは、1 つの潜在的なチートが消える位置を明示的にカウントします。 

考慮する```
n = 5
k = 4
a = [1, 1, 1, 1, 100]
```単純なシミュレーションでは、多くのチートが期待されるかもしれません。 実際には、不正行為が成功するたびに牛の実効力が 2 倍になるため、意味のある危険な位置の数はごくわずかです。 このアルゴリズムはこの対数構造を利用しており、一致を 1 つずつシミュレートする必要はありません。
