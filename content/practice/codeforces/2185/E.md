 ## 解決策
 ## 問題の理解

 すべてのロボットはまったく同じ一連の動きを受け取ります。 最初の命令の後、すべてのロボットは同じ変位だけ移動します。 2 番目の命令の後、すべてのロボットは別の共通の変位だけシフトし、以下同様に続きます。 

させて$p_i$最初の後の累積変位になります$i$説明書。 位置からスタートしたロボット$a$位置にあるでしょう$a + p_i$ステップの後$i$。 

ロボットは初めてスパイクに着地したときに死亡します。 命令のすべてのプレフィックスについて、まだ生きているロボットの数を出力する必要があります。 

最初の観察は、ロボットが互いに対話することがないということです。 1 台のロボットが生き残れるかどうかは、そのロボット自身の開始位置とスパイクの位置によってのみ決まります。 これにより、各ロボットの独立した死亡時間を計算できるようになります。 

制約こそが本当の課題なのです。 すべてのテスト ケースにわたる合計は、$n$、$m$、 そして$k$それぞれせいぜい$2 \cdot 10^5$。 あらゆる命令に対してあらゆるロボットをシミュレートするソリューションには、$O(nk)$到達できる仕事$4 \cdot 10^{10}$操作は不可能であり、完全に実行不可能です。 に近いものが必要です$O((n+m+k)\log k)$。 

ロボットがスパイクに到達しない場合、微妙なエッジケースが発生します。 例えば：```
1
1 1 3
10
100
LRL
```スパイクが 100 にある間、ロボットは位置 10 付近のみを移動します。正解は次のとおりです。```
1 1 1
```最終位置のみを調べるソリューションでは、以前に衝突が発生したと誤って結論付けることになります。 

もう 1 つの簡単な間違いは、途中でスパイクに触れるとロボットが即死するということを忘れることです。 考慮する：```
1
1 1 2
1
2
RL
```ロボットが動きます$1 \to 2 \to 1$。 最初の動きの後に死ぬので、答えは次のようになります。```
0 0
```すべての命令の後に位置だけをチェックすると、この衝突を見逃してしまいます。 

最後の明らかではないケースは、どちらかの側のスパイクが原因でロボットが死亡する可能性があるということです。 例えば：```
robot = 10
spikes = {7, 20}
moves = LLL
```ロボットは 3 回目の手で 7 に到達し、死亡します。 右に最も近いスパイクだけを見るのは正しくありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのロボットについて、命令シーケンスを段階的にシミュレートし、その位置を更新し、スパイクの上に立っているかどうかを確認します。 これが起こる最初のステップは、その終了時間です。 

これは、ステートメントで説明されているプロセスに正確に従っているため、正しいです。 残念ながら、それは実行します$O(nk)$更新情報。 両方の値が近い場合$2 \cdot 10^5$、実行時間が非常に長くなります。 

重要な観察は、すべてのロボットが同じ変位シーケンスを共有しているということです。 

させて$$p_i$$後の累積変位になります$i$説明書。 

位置から開始するロボットの場合$a$、ステップ後の位置$i$は$$a+p_i.$$ロボットは、ロボットが訪れたすべての位置にスパイクの位置が含まれる場合に死亡します。 

最初の移動中に到達した最小および最大累積変位がわかっていると仮定します。$i$説明書：$$L_i=\min_{1\le j\le i} p_j, \qquad R_i=\max_{1\le j\le i} p_j.$$すべての移動により位置が 1 単位だけ変更されるため、歩行は最小変位と最大変位の間のすべての整数点を訪問します。 したがって、最初の段階では、$i$命令、から始まるロボット$a$正確な間隔で訪問します$$[a+L_i,\; a+R_i].$$つまり、ロボットはその後も生きています$i$この間隔内にスパイクがない場合に限り、ステップを実行します。 重要なスパイクは、ロボットの開始位置の左側に最も近いスパイクと右側に最も近いスパイクだけです。 

各ロボットについて、間隔が両方の隣接するスパイクを回避できる最大のプレフィックス長をバイナリ検索できます。 これにより、ロボットが生きている最後のステップが得られます。 すべてのロボットについてこの値を計算した後は、各プレフィックス長ごとに何台のロボットが生き残るかを数えるだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nk)$|$O(m)$| 遅すぎる |
 | 最適 |$O((m+k)\log m + n(\log m+\log k))$|$O(m+k+n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 累積変位の極値を計算する

 命令文字列を 1 回処理します。 

現在の変位を維持する$p$。 

すべてのプレフィックスに対して$i$、 店：$$L_i=\min(L_{i-1},p),$$そして$$R_i=\max(R_{i-1},p).$$これらの値は、最初の実行中に到達した左端と右端の変位を表します。$i$説明書。 

### 2. スパイクの位置を並べ替える

 すべてのスパイク座標を並べ替えます。 

ロボットの位置ごとに$a$、次を見つけます:

 - 厳密に左側に最も近いスパイク、
 - 厳密に右側に最も近いスパイク。 

これは、ソートされたスパイク配列の二分探索によって行われます。 

### 3. 各ロボットの生存期間を二分探索する

 位置固定ロボットの場合$a$、 させて：

-$left$最も近い左のスパイクになります。 
-$right$最も近い右のスパイクになります。 

プレフィックス長の場合$mid$、ロボットは正確に生き続けます$$left < a+L_{mid}$$そして$$a+R_{mid} < right.$$最初の不等式は、調査された間隔が左側のスパイクに達していないことを意味します。 2 番目は、適切なスパイクに到達していないことを意味します。 

これらの条件は単調です。 ロボットは一度死んでしまうと二度と生き返ることはありません。 したがって、両方の不等式を満たす最大のプレフィックス長を二分探索します。 

この値を呼び出します$c$。 ロボットはステップを踏んでも生きています$1,2,\dots,c$そしてその後死亡。 

### 4. ステップごとに生存者数を数える

 すべての値を保存する$c$。 

並べ替えてください。 

命令数ごとに$i$、ロボットの数が必要です。$$c \ge i.$$ソートされた配列を 2 ポインターでスイープすると、すべての答えが線形時間で得られます。 

### なぜ効果があるのか

 命令のどの接頭辞についても、すべてのロボットは同じ変位歩行に従います。 その歩行中に訪れた一連の変位は、それまでに到達した最小変位と最大変位の間の正確な間隔です。 

位置から開始するロボット$a$したがって、正確な間隔で訪問します$[a+L_i,a+R_i]$。 ロボットは、その間隔内にスパイクが存在しない場合にのみ存続します。 

最も近い左右のスパイクによって、間隔にスパイクが含まれるかどうかが完全に決まります。 間隔が厳密にそれらの間にある場合、他のすべてのスパイクはさらに遠くなり、到達できなくなります。 隣接するスパイクのいずれかがその間隔に入ると、ロボットは即座に死亡します。 

生存条件はプレフィックス長に関して単調であるため、二分探索は最後に生き残ったプレフィックスを正しく見つけます。 少なくとも生存期間が長いロボットを数える$i$その後生存している数を返します$i$説明書。 

## Python ソリューション```python
import sys
from bisect import bisect_left, bisect_right

input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, m, k = map(int, input().split())
        robots = list(map(int, input().split()))
        spikes = sorted(map(int, input().split()))
        s = input().strip()

        min_disp = [0] * (k + 1)
        max_disp = [0] * (k + 1)

        cur = 0
        for i, ch in enumerate(s, 1):
            if ch == 'L':
                cur -= 1
            else:
                cur += 1

            min_disp[i] = min(min_disp[i - 1], cur)
            max_disp[i] = max(max_disp[i - 1], cur)

        NEG_INF = -10**18
        POS_INF = 10**18

        survive = []

        for a in robots:
            pos = bisect_left(spikes, a)

            left_spike = spikes[pos - 1] if pos > 0 else NEG_INF
            right_spike = spikes[pos] if pos < m else POS_INF

            lo, hi = 1, k
            best = 0

            while lo <= hi:
                mid = (lo + hi) // 2

                alive = (
                    left_spike < a + min_disp[mid]
                    and a + max_disp[mid] < right_spike
                )

                if alive:
                    best = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

            survive.append(best)

        survive.sort()

        ans = []
        ptr = 0

        for step in range(1, k + 1):
            while ptr < n and survive[ptr] < step:
                ptr += 1
            ans.append(str(n - ptr))

        print(*ans)

solve()
```最初のセクションでは、累積変位の極値を計算します。`min_disp[i]`そして`max_disp[i]`ステップまでの動作シーケンスによって探索される範囲全体を説明します`i`。 

各ロボットについて、ソートされたスパイク配列の二分探索を使用して隣接するスパイクを見つけます。 無限センチネルは、片側にスパイクが存在しない場合に使用されます。 これにより、後で特殊な場合のロジックが回避されます。 

命令プレフィックスの二分探索は単調性に依存します。 ロボットが長いプレフィックスを生き残る場合、ロボットはすべての短いプレフィックスも生き残ります。 逆に、スパイクが探索された間隔に入ると、それより大きなプレフィックスはすべて無効のままになります。 

最後のカウント段階は間違いやすいです。`survive[i]`ロボットがまだ生きている最大のステップインデックスを保存します。 ロボットが答えに貢献`step`まさにいつ`survive[i] >= step`。 これらの値を並べ替えると、単一のポインター スイープが可能になります。

## テストケース```python
import sys, io
from bisect import bisect_left

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    out = []

    t = int(input())

    for _ in range(t):
        n, m, k = map(int, input().split())
        robots = list(map(int, input().split()))
        spikes = sorted(map(int, input().split()))
        s = input().strip()

        mn = [0] * (k + 1)
        mx = [0] * (k + 1)

        cur = 0
        for i, ch in enumerate(s, 1):
            cur += -1 if ch == 'L' else 1
            mn[i] = min(mn[i - 1], cur)
            mx[i] = max(mx[i - 1], cur)

        surv = []

        for a in robots:
            p = bisect_left(spikes, a)

            left = spikes[p - 1] if p else -10**18
            right = spikes[p] if p < m else 10**18

            lo, hi = 1, k
            best = 0

            while lo <= hi:
                mid = (lo + hi) // 2

                if left < a + mn[mid] and a + mx[mid] < right:
                    best = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

            surv.append(best)

        surv.sort()

        ptr = 0
        ans = []
        for step in range(1, k + 1):
            while ptr < n and surv[ptr] < step:
                ptr += 1
            ans.append(str(n - ptr))

        out.append(" ".join(ans))

    return "\n".join(out)
