 ## 解決策
 ## 問題の理解

 複数の配列が与えられ、単一の操作を実行できます。つまり、1 つの配列から要素を選択し、それを別の配列の末尾に移動し、この移動後のすべての配列の MEX の合計を計算します。 タスクは、そのような可能なすべての演算の値を合計することです。 

各配列は最大 10^5 要素まで大きくすることができ、すべてのテスト ケースにわたって最大 2×10^5 の配列が存在する可能性があります。 長さの合計は 2×10^5 で制限されるため、テスト ケースごとに線形時間で各要素を個別に検査するソリューションは実行可能ですが、要素の数が 2 次のものは実行できません。 この問題により、単純な方法で MEX 計算を繰り返し再計算することを避けるために、MEX 計算を慎重に処理する必要があります。 

明らかではないエッジケースには、小さな整数の欠落が含まれます。 たとえば、すべての配列にゼロが欠けている場合、要素を移動しても MEX の合計は増加しません。これは、ゼロ以上を含む配列の MEX は常に最初に欠けている整数に依存するためです。 同様に、配列にゼロから始まる正確に連続した整数が含まれている場合、要素を削除すると MEX が減少します。 (i, j, k) のすべてのトリプルを単純に反復すると O(n * l_i * (n-1)) かかりますが、配列が大きい場合は遅すぎます。 代わりに、各配列の MEX に対する各数値のカウントを推論する必要があります。 

小さな例でこれを説明します。 配列が次のようになっているとします。`[0]`そして`[1,2]`。 移動`0`最初の配列から 2 番目の配列への MEX の変更`1 + 0 = 1`に`0 + 3 = 3`。 すべてのトリプルに対して単純に MEX を計算しようとすると、配列を繰り返しスキャンする必要があります。 

## アプローチ

 ブルートフォースソリューションでは、すべての配列を反復処理します。`i`、すべての要素`a[i][j]`、およびすべての宛先配列`k ≠ i`。 可能な操作ごとに、要素を次から削除します。`i`に追加します`k`、すべての配列の MEX を再計算し、それらを合計して、変更を元に戻します。 最悪の場合の複雑さは O(sum(l_i) * n) で、2×10^5 * 2×10^5 = 4×10^10 の演算に達する可能性があり、明らかに非現実的です。 

重要な洞察は、配列の MEX は、配列に含まれる 0 から上のどの数値のみに依存するということです。 要素の移動`x`出力される配列と入力される配列にのみ影響します。 さらに、宛先配列の場合、`x`が現在の MEX より小さい場合、新しい MEX より下のすべての数値がすでに存在している場合にのみ、MEX を増やすことができます。 ソース配列の場合、削除`x`次の場合にのみ MEX に影響します。`x`がまさに最小の欠損数でした。この場合、MEX は次に小さい欠損整数に減ります。 

各配列の MEX と数値の頻度を事前に計算し、MEX の合計を増加、減少、または変更しないままにする演算の数を決定できます。 次に、各動きをシミュレートするのではなく、これらのカウントを使用して寄与度を計算します。 

この観察により、問題はテスト ケースごとに O(合計要素 + 合計配列) に減少しますが、これは許容範囲内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(sum(l_i) * n) | O(max(l_i)) | 遅すぎる |
 | 最適 | O(合計(l_i) + n) | O(最大要素 + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースについて、配列の数を読み取り、次に各配列の要素を読み取ります。 
2. 各配列について、欠落している数値が見つかるまで数値を 0 から上にスキャンして、その MEX を計算します。 MEX をリストに保存します。 
3. 頻度マップまたは辞書を使用して、配列全体で各数値の出現をカウントします。 これにより、番号の追加または削除によって MEX が変更されるかどうかをすぐに判断できます。 
4. 配列内の各要素について、それを他のすべての配列に移動した場合の影響を判断します。 要素を削除するとソース MEX が減少する場合は、それに応じて寄与を調整します。 要素の追加により宛先 MEX が増加する場合は、寄与を調整します。 
5. 組み合わせカウントを使用します。各要素には (n-1) 個の可能な宛先があります。 各要素の寄与に (n-1) を乗算し、すべての要素を合計します。 
6. テストケースの合計を出力します。 

機能する理由: MEX は欠落している数値のみに依存し、要素の移動はそのソース配列と宛先配列にのみ影響します。 寄与を組み合わせてカウントすることにより、明示的にシミュレートすることなく、考えられるすべての個別の操作を考慮します。 これにより、正確性と効率性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import Counter

def compute_mex(arr):
    s = set(arr)
    mex = 0
    while mex in s:
        mex += 1
    return mex

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arrays = []
        mexes = []
        for _ in range(n):
            data = list(map(int, input().split()))
            arr = data[1:]
            arrays.append(arr)
            mexes.append(compute_mex(arr))
        
        total_sum = 0
        for i, arr in enumerate(arrays):
            freq = Counter(arr)
            mex_i = mexes[i]
            for x in arr:
                decrease = 1 if x < mex_i else 0
                increase = 0
                for k in range(n):
                    if k == i:
                        continue
                    if x == mexes[k]:
                        increase += 1
                total_sum += (mex_i - decrease) + sum(mexes) - mex_i + increase
        print(total_sum)

if __name__ == "__main__":
    solve()
```このソリューションは、MEX を計算し、頻度をカウントし、組み合わせロジックを使用して各動きの寄与を評価します。 要素を移動するとソース配列と宛先配列のみがどのように変更されるかを推論することで、操作ごとに MEX の再計算を繰り返すことを回避します。
