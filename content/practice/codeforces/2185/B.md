 ## 解決策
 ## 問題の理解

 配列が与えられます。 すべての位置について、そこで終わる接頭辞を調べ、これまでに確認された最大値を取得します。 配列のスコアは、これらすべてのプレフィックスの最大値の合計です。 

任意の 2 つの要素を最大 1 回交換することも、まったく交換しないことを選択することもできます。 タスクは、結果として得られるスコアを最大化することです。 

スコアを理解するには、次の点を考慮してください。```
[2, 1, 4, 5, 3]

prefix maxima:
2
2
4
5
5

score = 2 + 2 + 4 + 5 + 5 = 18
```制約は非常に小さいです。 テスト ケースは最大 100 個あり、各配列の長さは最大 50 です。可能なすべてのスワップを試行するアルゴリズムでも実用的です。 

と$n=50$、可能なスワップの数は$$\frac{50 \cdot 49}{2} = 1225$$1 つの配列のスコアを計算するには次の時間がかかります$O(n)$。 つまり、完全な総当たり検索にはおよそのコストがかかります$1225 \cdot 50 \approx 6 \times 10^4$テスト ケースごとの操作量は小さいです。 

主な課題は、制約により、より複雑な貪欲な観察を探すのではなく、直接検索が可能になることを認識することです。 

いくつかの特殊なケースは注目に値します。 

最大値がすでに最初にある配列を考えてみましょう。```
5 1
```そのスコアは次のとおりです。```
5 + 5 = 10
```スワップすると以下が生成されます。```
1 5
```そのスコアは次のとおりです。```
1 + 5 = 6
```ゼロスワップを実行できるため、正解は 10 です。 常に 1 回だけのスワップを実行するソリューションは失敗します。 

値が繰り返される配列を考えてみましょう。```
4 4 4
```すべてのスワップでは配列は変更されず、スコアは 12 のままです。ソリューションでは、同等の配列を含むすべての可能性を評価する必要があります。 

最大の要素を前に移動することが最適な場合を考えてみましょう。```
2 1 4 5 3
```2 と 5 を交換すると、次のようになります。```
5 1 4 2 3
```すべてのプレフィックスの最大値は 5 になり、スコアは 25 になります。これは、ローカルで魅力的なスワップが必ずしも最良のものではない理由を示しています。 すべての候補を比較する必要があります。 

## アプローチ

 最も直接的なアプローチは、考えられるすべてのアクションを試すことです。 

インデックスの各ペアについて$(i,j)$、2 つの要素を交換し、結果の配列のスコアを計算し、見つかった最良の値を保持します。 スワップを行わない可能性も考慮する必要があります。 

配列のスコアの計算は簡単です。 現在のプレフィックスの最大値を維持しながら、左から右にスキャンします。 各位置で、その最大値を答えに追加します。 

ブルートフォース手法は、最大 1 回のスワップで取得可能なすべての配列を明示的に評価するため、明らかに正しいです。 最適な答えが存在する場合、それはテストされた構成の中に現れる必要があります。 

Codeforce の問題の多くでは、すべてのスワップを試すことは不可能です。$n$そうかもしれない$10^5$それ以上。 ここ$n\le 50$なので、検索スペースは小さいです。 重要な点は、巧妙な貪欲なトリックではなく、制約によって徹底的な検索が完全に受け入れられるようになったことを認識していることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのスワップに対するブルートフォース |$O(n^3)$|$O(1)$| 承認済み |
 | さらに複雑な最適化 | 不要 | 不要 | 受け入れられるが過剰設計 |

 以来$n\le 50$、$O(n^3)$だけです$125000$テストケースごとの操作は十分に制限内にあります。 

## アルゴリズムのチュートリアル

 1. 元の配列のスコアを計算し、それを現在の最良の回答として保存します。 
2. インデックスのペアごとに$i<j$、2 つの要素を交換します。 
3. 変更された配列を左から右にスキャンします。 

これまでに確認された最大値を維持し、プレフィックスの最大合計を累積します。 
4. 現在のスコアが大きい場合は、最良の回答を更新します。 
5. 次のペアをテストする前に、アレイが元の状態に戻るようにスワップを元に戻します。 
6. すべてのペアを検査した後、見つかった最良のスコアを出力します。 

### なぜ効果があるのか

 最大 1 回のスワップで到達可能な配列のセットは、元の配列と、1 組の位置をスワップすることで得られたすべての配列で構成されます。 アルゴリズムは、このような各配列のスコアを 1 回だけ評価し、検出された最大スコアを記録します。 

すべての正当な結果がチェックされるため、アルゴリズムによって見つかった最大スコアがまさに最適な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def value(a):
    mx = 0
    total = 0
    for x in a:
        mx = max(mx, x)
        total += mx
    return total

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    ans = value(a)

    for i in range(n):
        for j in range(i + 1, n):
            a[i], a[j] = a[j], a[i]

            ans = max(ans, value(a))

            a[i], a[j] = a[j], a[i]

    print(ans)
```ヘルパー関数`value()`配列のスコアを計算します。 現在のプレフィックスの最大値を維持し、それを各位置の現在の合計に追加します。 

メインループは最初に元の配列を評価します。 これにより、「スワップなし」オプションが自動的に処理されます。 

次に、位置の各ペアが一時的に交換されます。 スコアを計算した後、スワップはすぐに元に戻されます。 すべての候補スワップを同じ開始配列でテストする必要があるため、元の順序を復元することが不可欠です。 

スコアは次のように大きくなる可能性があります$50 \times 10000 = 500000$、これは Python の整数に簡単に適合します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    def value(a):
        mx = 0
        total = 0
        for x in a:
            mx = max(mx, x)
            total += mx
        return total

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        ans = value(a)

        for i in range(n):
            for j in range(i + 1, n):
                a[i], a[j] = a[j], a[i]
                ans = max(ans, value(a))
                a[i], a[j] = a[j], a[i]

        out.append(str(ans))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return result

# provided sample

2 1 4 5 3
2

3
3 2 1
2
6 7
"""
) == """25

"""

# minimum size

"""
) == """4
"""

# all equal

"""

"""

"""

"""

"""
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 / 1 2`|`4`| 許容される最小の配列 |

## 特殊なケース

 次のことを考慮してください。```
1
2
5 1
```元のスコアは 10 です。唯一の可能なスワップでは、スコア 6 が生成されます。アルゴリズムは、元のスコアを現在の答えとして開始し、次にスワップをチェックして、より大きい値を保持します。 最終的な答えは 10 です。 

次のことを考慮してください。```
1
3
4 4 4
```元のスコアは次のとおりです。```
4 + 4 + 4 = 12
```スワップのたびに、配列は変更されません。 アルゴリズムはすべての可能性を評価し、常に 12 を取得するため、出力は正しいままになります。 

考慮する：```
1
5
2 1 4 5 3
```最善の策は、2 と 5 を交換して、次のようにすることです。```
5 1 4 2 3
```そのスコアは 25 です。アルゴリズムはインデックスのすべてのペアをチェックするため、このスワップが検査されることが保証され、最大スコアが見つかります。
