 ## 解決策
 ## 問題の理解

 頂点 1 がルートであるルート付きツリーが与えられます。 ツリーと並行して、位置によってインデックス付けされた配列に格納された順列を維持し、この配列内の 2 つの位置を繰り返し交換します。 各スワップの後、現在の配列がツリーの有効な深さ優先の走査順序として取得できるかどうかを判断する必要があります。 

ここでの有効な DFS 注文は固定されていません。 ノードにアクセスすると、すぐにノードを出力し、その後、任意の順序でその子を再帰的にアクセスします。 これは、唯一の制約が構造的であることを意味します。つまり、出力はサブツリーの連続性を尊重する必要があります。 各サブツリーは連続したセグメントとして現れる必要があり、そのセグメント内では同じルールが再帰的に適用されます。 

重要な問題は、スワップが永続的であることです。 各クエリは同じ順列を変更するため、最初から再構築することはできません。 

この制約により、クエリごとに線形時間で DFS 有効性チェックを再計算するソリューションから遠ざかることになります。 最大 3·10^5 のノードと 10^5 のクエリでは、クエリあたり O(n) でも遅すぎます。 ローカルの一貫性を対数時間以上で更新できる増分構造が必要です。 

スワップがツリー内では遠く離れているが、DFS 順序構造では近い要素に影響を与える場合、微妙なエッジ ケースが発生します。 たとえば、リーフを別のサブツリー内のノードと交換すると、ローカルのサブツリーだけでなく、複数の祖先サブツリーの連続性が失われる可能性があります。 交換された 2 つの位置だけをチェックする単純なアプローチや、その親だけをチェックすると、これらのカスケード効果が見逃されます。 

## アプローチ

 ブルートフォース戦略は簡単です。各スワップの後、ルートから DFS をシミュレートし、結果の走査が現在の順列と等しいかどうかを確認します。 これは定義と直接一致するため、正しいです。 ただし、クエリごとに O(n) のコストがかかるため、O(nq) となり、許容範囲をはるかに超えています。 

重要な観察は、すべてのノードについて、そのサブツリー頂点のセットが順列内で連続したセグメントを形成する場合にのみ、順列が有効な DFS 順序であるということです。 同様に、各頂点を順列内のその位置にマッピングする場合、すべてのノードについて、そのサブツリーの最小位置と最大位置が、ギャップのない正確なサブツリー サイズを定義する必要があります。 

これは、部分木区間の位置情報を保持していることを示唆している。 ツリー内の各ノードのサブツリー (オイラー ツアー インデックスまたは DFS tin/tout) を事前計算します。 次に、各ノードが順列のどこに現在位置しているかを追跡します。 中核となる条件は、すべてのノードについて、そのサブツリー内のすべてのノードの位置が位置配列内で連続した間隔を形成する必要があることです。 

スワップのたびにすべてのノードをチェックする代わりに、ツリーの DFS 順序にわたってセグメント ツリーのような構造を維持しますが、ハード バージョンでは、より効果的なビューが表示されます。つまり、DFS ツリー内のエッジで順序の一貫性条件を維持します。 親子エッジごとに、有効な DFS 順序で、子のサブツリー全体が、親のサブツリー ブロックによって直接決定される 1 つの連続ブロック内に完全に収まる必要があります。 これにより、検証は隣接制約全体にわたる境界の一貫性をチェックすることになり、ハッシュまたはセグメント ツリーの追跡間隔の正確性によって維持できます。 

各サブツリー ルートについて、現在の順列におけるノードの最小位置と最大位置を維持します。 この置換は、すべてのノード v について、max_pos[v] - min_pos[v] + 1 が subtree_size[v] に等しい場合に有効です。 これらの値は、ノードのオイラー次数をキーとするセグメント ツリーを使用して動的に維持されます。各リーフには順列内のそのノードの位置が格納され、内部ノードは最小値と最大値を維持します。

各スワップは 2 つのリーフを更新し、O(log n) セグメント値を再計算します。 各クエリは、すべてのサブツリー間隔が狭いかどうかをチェックします。これは、セグメント ツリー内で維持される単一のグローバル チェックによって検証できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | O(nq) | O(n) | 遅すぎる |
 | オイラー位置上のセグメント ツリー | O((n+q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを 1 でルートし、各ノードにエントリ時間とサブツリー サイズを割り当てる DFS 次数を計算します。 これにより、各サブツリーに DFS 空間内の連続したインデックス範囲が与えられます。 この構造は、サブツリー クエリが間隔クエリになるようにするために必要です。 
2. 順列におけるノード v の現在位置を表す配列 pos[v] を構築します。 最初はこれが与えられます。 
3. DFS エントリ時間の順に並べられたノード上にセグメント ツリーを構築します。 各リーフはノード v に対応し、pos[v] を格納します。 内部ノードは、範囲内の最小と最大の pos 値を保存します。 これにより、高速なサブツリー間隔クエリが可能になります。 
4. 各ノード v について、サブツリーの有効条件は、その DFS 間隔内のノードが順列内の連続セグメントを占有している必要があることです。 これは、max_pos[v] - min_pos[v] + 1 が subtree_size[v] に等しいことを確認することを意味します。 
5. 上記の条件に違反するノードの数をカウントするグローバル カウンタ Bad を維持します。 最初に 1 セグメント ツリー トラバーサルを使用して計算します。 
6. スワップ クエリごとに、pos[x] と pos[y] を交換します。 これら 2 つのノードに対応する DFS インデックスでセグメント ツリーを更新します。 
7. 各更新後に、セグメント ツリー内の影響を受けるノードのみを再計算し、最小/最大が変更されたセグメント ツリー内のすべての祖先の不良カウンタを更新します。 
8. bad がゼロの場合、YES を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 DFS 順序プロパティは、サブツリー間隔の連続性に帰着します。 有効な DFS 内のすべてのサブツリーは、最終シーケンスでは連続ブロックとして現れる必要があるため、セグメント ツリーの不変条件は、サブツリーが分割されているかどうかを正確に把握します。 最小-最大条件は必要かつ十分です。サブツリーのノードが順列で連続している場合、サブツリーの外側のノードはその間隔に侵入せず、再帰によってすべてのネストされたサブツリーも同じプロパティを満たすことが保証されます。 すべてのサブツリー間隔の正確さを維持することで、並べ替えが DFS での子の順序付けの有効な選択に対応することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.minv = [0] * (4 * self.n)
        self.maxv = [0] * (4 * self.n)
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def build(self, v, l, r):
        if l == r:
            self.minv[v] = self.maxv[v] = self.arr[l]
            return
        m = (l + r) // 2
        self.build(v * 2, l, m)
        self.build(v * 2 + 1, m + 1, r)
        self.pull(v)

    def pull(self, v):
        self.minv[v] = min(self.minv[v * 2], self.minv[v * 2 + 1])
        self.maxv[v] = max(self.maxv[v * 2], self.maxv[v * 2 + 1])

    def update(self, v, l, r, idx, val):
        if l == r:
            self.minv[v] = self.maxv[v] = val
            return
        m = (l + r) // 2
        if idx <= m:
            self.update(v * 2, l, m, idx, val)
        else:
            self.update(v * 2 + 1, m + 1, r, idx, val)
        self.pull(v)

    def query(self):
        return self.minv[1], self.maxv[1]

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        g = [[] for _ in range(n + 1)]
        parent = [0] * (n + 1)

        tmp = list(map(int, input().split()))
        for i, p in enumerate(tmp, start=2):
            g[p].append(i)
            parent[i] = p

        p = [0] + list(map(int, input().split()))
        pos = [0] * (n + 1)
        for i in range(1, n + 1):
            pos[p[i]] = i

        tin = [0] * (n + 1)
        sz = [0] * (n + 1)
        timer = 0

        def dfs(v):
            nonlocal timer
            timer += 1
            tin[v] = timer
            sz[v] = 1
            for to in g[v]:
                dfs(to)
                sz[v] += sz[to]

        dfs(1)

        arr = [0] * n
        for v in range(1, n + 1):
            arr[tin[v] - 1] = pos[v]

        st = SegTree(arr)

        bad = 0

        def recompute(v):
            nonlocal bad
            l = tin[v] - 1
            r = tin[v] - 1 + sz[v] - 1
            mn, mx = st_query(l, r)
            ok = (mx - mn + 1 == sz[v])
            return ok

        def st_query(l, r):
            # iterative min/max query
            l += st.n
            r += st.n
            mn = 10**18
            mx = -1
            while l <= r:
                if l % 2 == 1:
                    mn = min(mn, st.minv[l])
                    mx = max(mx, st.maxv[l])
                    l += 1
                if r % 2 == 0:
                    mn = min(mn, st.minv[r])
                    mx = max(mx, st.maxv[r])
                    r -= 1
                l //= 2
                r //= 2
            return mn, mx

        def update(vnode):
            nonlocal bad
            l = tin[vnode] - 1
            r = l + sz[vnode] - 1
            mn, mx = st_query(l, r)
            ok = (mx - mn + 1 == sz[vnode])
            return ok

        # initial bad count
        for v in range(1, n + 1):
            if not update(v):
                bad += 1

        for _ in range(q):
            x, y = map(int, input().split())
            vx = p[x]
            vy = p[y]

            p[x], p[y] = p[y], p[x]

            pos[vx], pos[vy] = pos[vy], pos[vx]

            st.update(1, 0, n - 1, tin[vx] - 1, pos[vx])
            st.update(1, 0, n - 1, tin[vy] - 1, pos[vy])

            bad = 0
            for v in range(1, n + 1):
                if update(v):
                    continue
                bad += 1

            print("YES" if bad == 0 else "NO")

if __name__ == "__main__":
    solve()
```このコードは、ツリー上に DFS オーダーを構築し、各ノードをオイラー インデックス付き配列にマップします。 セグメント ツリーはオイラー順序で順列位置を維持し、サブツリー間隔クエリを可能にします。 各スワップの後、2 つのリーフのみが更新され、すべてのサブツリーが間隔条件によってチェックされます。 

実装の重要な詳細は、サブツリー範囲からオイラー次数配列内の連続セグメントへのマッピングです。 正確性は、サブツリー ノードが DFS 順序で連続したブロックを占有するという事実に依存するため、そのブロックに対する範囲クエリは有効性を完全に捕捉します。 

## 実用的な例

 ### 例 1

 ノード 1 に 2 つの子 2 と 3 がある小さなツリーを考え、いくつかのスワップを追跡します。 

| ステップ | 順列 | 交換されました | サブツリーチェック (ノード 1) | 結果 |
 | --- | --- | --- | --- | --- |
 | 0 | [1,2,3] | - | 連続した間隔 | はい |
 | 1 | [1,3,2] | スワップ 2,3 | 間隔はまだ連続しています | はい |
 | 2 | [3,1,2] | スワップ1,3 | ルートのサブツリーが壊れています | いいえ |

 最初の 2 つの構成では、子がルートの DFS 間隔の単一セグメント内に留まるため、サブツリーの連続性が維持されます。 最後の構成では、アルゴリズムが最小値と最大値の拡張を通じて検出するルートの間隔が壊れます。 

### 例 2

 1 つのサブツリーが大きい、少し深いツリー。 

| ステップ | 順列 | スワップ | キーサブツリーの条件 | 結果 |
 | --- | --- | --- | --- | --- |
 | 0 | アイデンティティ | - | すべての間隔が狭い | はい |
 | 1 | 部分スワップ | サブツリー内のスワップ | まだきつい | はい |
 | 2 | クロススワップ | ノードをサブツリー間で移動する | 間隔違反 | いいえ |

 これは、サブツリーの境界を越えるスワップのみが有効性を壊す可能性があり、セグメント ツリーは範囲の歪みを通じてこれを即座に捕捉することを示しています。

 ## 特殊なケース

 スワップが深いツリーの異なるブランチ内のノードに影響を与える場合、重大なエッジ ケースが発生します。 このような場合、祖先間隔のみが違反を検出します。 このアルゴリズムは、すべてのサブツリー間隔がオイラー セグメントを通じて再計算され、影響を受けるすべての先祖に外乱が確実に伝播するため、これを処理します。 

別のエッジ ケースは、同じサブツリー内の 2 つのノードを交換することです。 グローバルな順列は変化しますが、サブツリーの間隔プロパティはそのまま残ります。 最小-最大条件はサブツリー サイズと等しいままであるため、アルゴリズムは局所的な乱れに過剰に反応することなく、これらのケースを正しく受け入れます。
