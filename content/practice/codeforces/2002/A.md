 ## 解決策
 ## 問題の理解

 次のような長方形のグリッドが与えられます。`n`行と`m`列。 各セルには色を割り当てる必要がありますが、色は距離ルールによって制限されます。2 つのセルが同じ色を共有する場合、それらはチェビシェフの意味で十分に離れている必要があります。つまり、行の差と列の差の最大値は少なくとも以下でなければなりません。`k`。 

簡単に言うと、同じ色の 2 つのセルがセル内に存在してはなりません。`(k-1) × (k-1)`互いに正方形の近所。 課題は、この分離ルールを尊重しながら、使用する色をできるだけ少なくすることです。 

各テスト ケースの出力は単一の数値、つまりそのグリッドに必要な最小色の数とその値です。`k`。 

この制約により、最大 10^4 のグリッド次元で最大 1000 のテスト ケースが許可されます。 サイズが 10^4 × 10^4 の単一グリッドですら、明示的に処理するには大きすぎるため、色付けをシミュレートしたり、セルのすべてのペアを比較しようとするものは除外されます。 解決策は以下にのみ依存する必要があります`n`、`m`、 そして`k`、個々の細胞の相互作用ではありません。 

よくある失敗例は、グローバルではなくローカルに考えることから生じます。 たとえば、行ごと、または列ごとに貪欲に色付けを試みるかもしれませんが、制約に方向性がないため、そのようなアプローチはすぐに失敗します。 セルは水平方向と垂直方向の両方で他のセルと競合する可能性があるため、ローカルな決定は 2 次元に同時に伝播します。 

もう一つの微妙なエッジケースは次のような場合に発生します。`k`グリッドの寸法に比べて非常に大きいです。 その場合、すべてのペアが近すぎるため、2 つの異なるセルが同じ色を共有することはできません。 色の定期的な再利用を前提とした単純なアプローチでは、再利用の機会を誤って過大評価してしまいます。 

## アプローチ

 強引なアイデアは、グリッドの色付けを実際にシミュレートすることです。 各セルについて、距離内に矛盾が見られない場合は、以前に使用した色を割り当てようとします。`k`、そうでない場合は、新しい色を導入します。 これには、同じ色の以前に色付けされたすべてのセルに対する距離をチェックする必要があり、最悪の場合の複雑さは次のとおりです。`O(n^2 m^2)`すべてのケースの合計では、制限をはるかに超えています。 

重要な観察は、制約が純粋に幾何学的であり、平行移動に対して不変であるということです。 重要なのは絶対的な位置ではなく、適切な間隔を法とした相対的な位置です。 繰り返しパターンについて考える場合、2 つの同じ色が強制的に遠く離れてしまうように、グリッドを繰り返しブロックに分割するのが自然なアイデアです。 

セルを座標モジュロでグループ化すると`k`、次に同じ残基ペアを持つ任意の 2 つのセル`(i mod k, j mod k)`両方の座標で次の倍数異なります`k`、必要な距離条件を保証します。 これにより、次を使用して有効な構造がすぐに得られます。`k × k`グリッドが両方の次元で十分に大きい場合は常に色が付けられます。 

ただし、グリッドがこれより小さい場合は、`k`一方向では、モジュロ構造は完全に崩壊しなくなりました。 たとえば、次の場合`n < k`の場合、すべての行インデックスは 1 つの剰余クラス サイクル内で異なるため、完全な行インデックスを再利用することはできません。`k`垂直構造。 その場合、個別の行の数が制限要因になります。 

これにより、シンプルで洗練されたビューが得られます。各次元では、次元サイズと`k`。 両方の次元を組み合わせると、最終的な答えが得られます。

 ## アルゴリズムのチュートリアル

 最適な解決策は、各方向に必要な独立した「レイヤー」の数を直接計算することに基づいています。 

1.読む`n`、`m`、 そして`k`。 これらはグリッドと必要な最小分離距離を定義します。 
2. 行に沿って、行パターンを毎回より頻繁に再利用できないことに注目してください。`k`ステップ。 ただし、グリッドの数がこれより少ない場合は、`k`行の場合、すべての行は本質的に一意であり、グリッド サイズ自体を超えてグループ化することはできません。 したがって、有効な行層の数は次のようになります。`min(n, k)`。 
3. 同じ理由を列にも適用します。 有効な列層数は次のとおりです。`min(m, k)`。 
4. 行層と列層の各組み合わせは、最適な構成における固有の色に対応します。 
5. 2 つの独立したカウントを乗算して、必要な色の総数を取得します。`min(n, k) * min(m, k)`。 

この乗算は、各セルをペアに割り当てることと同じ構造であるため機能します。`(i mod k, j mod k)`ただし、グリッドが以下の場合は切り捨てられます。`k`どちらの次元でも。 

### なぜ効果があるのか

 重要な不変条件は、同じ縮小座標のペアを共有する 2 つのセルが、次の値よりも近くに存在できないことです。`k`どちらの方向でも、同一のペアでは両方の座標が次の倍数だけ異なることが強制されるためです。`k`。 同時に、より少ない色を使用しようとすると、そのような 2 つの剰余クラスをマージすることになり、必然的に禁止された距離内にセルのペアが作成されます。 これにより、構築が十分かつ最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m, k = map(int, input().split())
    print(min(n, k) * min(m, k))
```ソリューションは、導出された式を直接適用します。 各テスト ケースは一定時間内に独立して処理されますが、これはケースの数が多いことを考えると重要です。 

唯一の微妙な点は、`min(n, k)`そして`min(m, k)`構造。 よくある間違いは、`k * k`無条件で、グリッドが以下の場合に失敗します。`k`一方または両方の次元で。 

## 実用的な例

 ### 例 1

 入力:```
n = 3, m = 3, k = 2
```次のように計算します。 

-`min(n, k) = 2`-`min(m, k) = 2`したがって、結果 =`2 × 2 = 4`。 

これは、グリッドの 2 周期タイリングでは 4 つの繰り返し剰余クラスのみが必要であるという考えと一致します。 

### 例 2

 入力:```
n = 5, m = 1, k = 10000
```次のように計算します。 

-`min(n, k) = 5`-`min(m, k) = 1`したがって、結果 =`5 × 1 = 5`。 

これは、列が 1 つだけでは、これほど大規模な環境では水平方向の再利用が不可能であることを反映しています。`k`したがって、各行には事実上独自の色が必要です。 

これらの例は、式が次の場合と次の場合の両方に正しく適合することを確認します。`k`が小さい場合と、グリッドよりもはるかに大きい場合です。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, m, k = map(int, input().split())
        out.append(str(min(n, k) * min(m, k)))
    return "\n".join(out)

 ## 特殊なケース

 いつ`k = 1`、セルのすべてのペアは少なくとも 1 の距離にあるため、すべてのセルは単一の色を共有できます。 式は次のようになります`min(n,1) * min(m,1) = 1`、この動作と一致します。 

いつ`k`たとえば、両方の次元よりもはるかに大きいです。`n = m = 5, k = 100`、式は次のようになります`5 × 5 = 25`これは、2 つの異なるセルが同じ色を再利用できないことを正しく反映しています。 

1 つの次元だけが大きい場合、たとえば、`n = 1000, m = 1, k = 10`、結果は次のようになります`10 × 1 = 10`つまり、垂直軸に沿った分離のみが必要であり、水平方向の再利用は無関係です。
