 ## 解決策
 ## 問題の理解

 頂点がヒープ順に番号付けされた完全な二分木が与えられます。 頂点`1`はルートであり、すべての頂点に対して`i > 1`、その親は`i // 2`。 

順列`p`すべての頂点が維持されます。 クエリのたびに、順列内の 2 つの位置が交換されます。 スワップは今後のクエリに対しても有効です。 

各スワップの後、現在の順列がツリーの深さ優先の走査によって生成できるかどうかを判断する必要があります。 DFS は事前注文です。最初にアクセスしたときに頂点が書き込まれます。 唯一の自由は、各ノードがその子を訪問する順序です。 

ツリー構造は固定されており、非常に特殊です。 これは完全な二分木であるため、すべての内部ノードにはちょうど 2 つの子があり、すべての葉が同じレベルにあります。 

一番大きな木には、`65535`すべてのテスト ケースにわたるクエリの合計数は次のとおりです。`50000`。 スワップのたびに有効性を最初から再計算するソリューションでは、すべての頂点を繰り返し調べる必要があります。 最悪の場合、これはおおよそ次のようになります$$65535 \times 50000 \approx 3.2 \cdot 10^9$$まったく実行不可能な操作です。 

完全なバイナリ ツリーにおける DFS 注文の構造は、一般的なツリーよりもはるかに厳格です。 その剛性を活用することが全体の課題です。 

微妙な点は、DFS 注文が一意ではないことです。 たとえば、木の中で```
    1
   / \
  2   3
```両方```
1 2 3
```そして```
1 3 2
```DFS はどちらかの子を最初に選択できるため、これらは有効です。 

もう 1 つの簡単な間違いは、親と子の関係のみをチェックすることです。 

考慮する```
1 2 4 3 5 6 7
```7 つの頂点を持つツリー内。 

すべての親はその子孫の前に表示されますが、これは DFS の順序ではありません。 DFS がサブツリーに入ると`2`、サブツリーに移動する前に、そのサブツリー全体を終了する必要があります。`3`。 頂点`3`登場が早すぎる。 

3 番目の落とし穴は、サブツリーの連続性を忘れることです。 

同じ木に対して、```
1 2 4 5 3 6 7
```サブツリーなので有効です`2`1 つの連続したセグメントを占有します。 

しかし```
1 2 4 3 5 6 7
```サブツリーを分割します`2`DFSでは決してできないことです。 

これらの観察は、正しい特性評価に直接つながります。 

## アプローチ

 最も直接的な解決策は、定義をシミュレートすることです。 

各スワップの後、順列内のすべての頂点の位置を再構築し、順列が有効な DFS オーダーであるかどうかを再帰的に検証します。 ノードの場合`v`、それを確認します`v`はそのサブツリー頂点の中で最初に出現し、各子サブツリーの頂点は直後に出現する連続ブロックを形成します。 

これは、プリオーダー DFS の再帰構造と正確に一致するため、正しいです。 

問題はコストです。 順列全体を検証するには、すべてを調べる必要があります。`n`頂点。 すべてのクエリが結果を返した後にこれを実行すると、`O(nq)`、これは大きすぎます。 

重要な観察は、樹上の DFS の形状から得られます。 

どの事前オーダー DFS オーダーでも、すべてのサブツリーの頂点が 1 つの連続したセグメントを占有します。 私たちのツリーは完璧なので、すべてのサブツリーのサイズは事前にわかっています。 

させて`sz[v]`をルートとするサブツリーのサイズになります`v`。 

頂点を仮定します`v`の位置に表示されます`pos[v]`順列の中で。 

次にセグメント```
[pos[v], pos[v] + sz[v] - 1]
```サブツリーの頂点を正確に含む必要があります`v`。 

リーフの場合、これは自動的に行われます。 

子を持つ内部ノードの場合`l`そして`r`、事前注文 DFS には 2 つの可能性しかありません。```
v, subtree(l), subtree(r)
```または```
v, subtree(r), subtree(l)
```両方の子サブツリーのサイズが既知であるため、これら 2 つの配置のいずれかが発生するかどうかをローカルで確認できます。 

これにより、グローバル DFS 条件が、頂点ごとに 1 つずつのローカル条件のコレクションに変換されます。 

スワップ後は、位置が変更された頂点とその祖先のみが、その有効性に影響を与えることができます。 他のすべてのサブツリーには、以前とまったく同じ配置が表示されます。 

樹高がせいぜいなので$$\log_2 65535 = 16,$$スワップはのみに影響を与えます`O(log n)`頂点。 

無効な頂点の数を維持します。 各スワップの後、影響を受ける頂点を更新し、カウントが 0 かどうかを確認します。

 ## アプローチ

 局所的な条件を定式化してみましょう。 

頂点ごとに`v`、ブール値を定義します`good[v]`。 

もし`v`葉です、`good[v] = True`。 

それ以外の場合は、その子供たちをそのままにしておきます`l`そして`r`。 

をルートとする有効な事前注文 DFS`v`のように見えるはずです```
v
(child subtree A)
(child subtree B)
```どこ`A`そして`B`は`l`そして`r`いずれかの順序で。 

させて```
pv = pos[v]
pl = pos[l]
pr = pos[r]
```最初の子サブツリーは、次の直後に開始する必要があります。`v`。 

だからどちらか```
pl = pv + 1
and
pr = pv + 1 + sz[l]
```または```
pr = pv + 1
and
pl = pv + 1 + sz[r]
```さらに、両方の子自体がすでに DFS プロパティを満たしている必要があります。 

したがって```
good[v]
=
good[l]
and
good[r]
and
(one of the two arrangements above)
```この再帰条件は必要かつ十分です。 

## アルゴリズムのチュートリアル

 1. サブツリーのサイズを事前計算する`sz[v]`頂点ごとに。 

ツリーは固定されており完全であるため、これは事後探索を使用して 1 回行うことができます。 
2. 現在の順列と配列を維持します。`pos`。`pos[x]`頂点の現在位置を保存します`x`順列の中で。 
3. すべての頂点について、計算します。`good[v]`葉から上へ。 

リーフは常に有効です。 内部ノードは、その子の 2 つの可能な DFS 配置をチェックします。 
4. カウンターを維持する`bad`頂点の数に等しい`good[v]`は誤りです。 

順列全体が有効な DFS 注文となるのは、次の場合です。`bad = 0`。 
5. クエリの位置が入れ替わる場合`x`そして`y`、交換された頂点を次のようにします`a`そして`b`。 

順列を更新して更新します`pos[a]`そして`pos[b]`。 
6. 影響を受ける可能性のある頂点をすべて収集します。 

のみ`a`、`b`、そしてその祖先は有効性を変更することができます。 他のサブツリーでは位置の変更は見られません。 
7. 再計算`good[v]`影響を受けるすべての頂点について、浅い頂点よりも先に深い頂点を処理します。 

これにより、親を再計算するときに、子の値がすでに正しいことが保証されます。 
8. グローバルを調整する`bad`頂点が有効から無効に、またはその逆に変化するたびにカウンターします。 
9. 出力`"YES"`もし`bad = 0`、 さもないと`"NO"`。 

### なぜ効果があるのか

 重要な不変条件は次のとおりです`good[v]`サブツリーの頂点が一致する場合に真になります。`v`をルートとする有効な事前注文 DFS シーケンスを形成します。`v`。 

証明はサブツリーの高さに関する帰納法によって行われます。 

葉は自明に有効です。 

クレームが内部ノードの両方の子に当てはまると仮定します。`v`。 予約注文 DFS では、`v`が最初に表示される必要があります。 その後、1 つの子サブツリーが完全に表示され、その後にもう 1 つの子サブツリーが完全に表示されます。 サブツリーのサイズは固定されているため、2 つの子ブロックの開始位置は完全に決定されます。 繰り返しの 2 つのチェックは、考えられる 2 つの子供の面会命令に正確に対応しています。 

いずれかの取り決めが成立し、両方の子サブツリーが有効な場合、次のサブツリー全体が`v`は有効な DFS 注文です。 どちらの取り決めも当てはまらない場合、DFS は観察された順序を生成できません。 

したがって、再発はすべてのノードで正確です。 ルートが有効な場合、順列全体が正確に有効になります。これは、すべてのローカル条件が成立していることと同等です。`bad = 0`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n, q = map(int, input().split())

        parent = [0] * (n + 1)
        arr = list(map(int, input().split()))
        for i in range(2, n + 1):
            parent[i] = arr[i - 2]

        p = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, v in enumerate(p):
            pos[v] = i

        sz = [1] * (n + 1)
        for v in range(n, 0, -1):
            l = v * 2
            r = l + 1
            if l <= n:
                sz[v] += sz[l]
            if r <= n:
                sz[v] += sz[r]

        good = [False] * (n + 1)

        def calc(v):
            l = v * 2
            r = l + 1

            if l > n:
                return True

            pv = pos[v]
            pl = pos[l]
            pr = pos[r]

            option1 = (
                pl == pv + 1 and
                pr == pv + 1 + sz[l]
            )

            option2 = (
                pr == pv + 1 and
                pl == pv + 1 + sz[r]
            )

            return good[l] and good[r] and (option1 or option2)

        bad = 0

        for v in range(n, 0, -1):
            good[v] = calc(v)
            if not good[v]:
                bad += 1

        for _ in range(q):
            x, y = map(int, input().split())
            x -= 1
            y -= 1

            a = p[x]
            b = p[y]

            affected = set()

            cur = a
            while cur:
                affected.add(cur)
                cur = parent[cur]

            cur = b
            while cur:
                affected.add(cur)
                cur = parent[cur]

            for v in affected:
                if not good[v]:
                    bad -= 1

            p[x], p[y] = p[y], p[x]
            pos[a], pos[b] = pos[b], pos[a]

            order = sorted(affected, reverse=True)

            for v in order:
                good[v] = calc(v)

            for v in affected:
                if not good[v]:
                    bad += 1

            print("YES" if bad == 0 else "NO")

if __name__ == "__main__":
    solve()
```ツリーと順列を読み取った後、ソリューションは逆マッピングを構築します。`pos`これにより、任意の頂点の現在位置への定時間アクセスが可能になります。 

サブツリーのサイズはボトムアップで計算されます。 ツリーは完全であり、番号付けされたヒープに格納されているため、ツリーの子は`v`単に`2v`そして`2v+1`。 

機能`calc(v)`証明から漸化式を実装します。 2 つの子サブツリーが、事前注文 DFS が必要とする正確な場所で開始されているかどうかをチェックします。 

配列`good`すべてのサブツリーの有効性を保存します。 カウンター`bad`更新後に一定時間内にクエリに応答できるようになります。 

スワップは、スワップされた頂点とその祖先にのみ影響します。 ツリーの高さは最大でも 16 なので、影響を受けるセットは小さいままです。 

頂点は降順に再計算されます。 ヒープ番号付きツリーでは、すべての子が親よりも大きなインデックスを持っているため、自然に親よりも前に子が処理されます。 

微妙な点の 1 つは、への古い貢献を削除することです。`bad`再計算して後で新しい寄与を追加する前。 このステップを忘れると、計数エラーが蓄積されてしまいます。
