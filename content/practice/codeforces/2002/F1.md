 ## 解決策
 ## 問題の理解

 私たちは、Lelle と Flamm という 2 人のパフォーマーの間で、各ラウンドで勝者が生まれる試合を計画するよう依頼されました。 目標は、次のように計算される合計スコアを最大化することです。`l * W_L + f * W_F`、 どこ`W_L`そして`W_F`は、それぞれ Lelle と Flamm の勝利数です。 ただし、パフォーマンスは厳格な「成功」基準を満たしている必要があります。つまり、各ラウンド後、勝利数の最大公約数は最大 1 でなければなりません。これは、次のことを意味します。`gcd(W_L, W_F) <= 1`。 最終的には、誰もそれぞれの制限を超えて勝利することはできず、簡単なバージョンでは次のことが保証されています。`n = m`。 

入力により複数のテスト ケースが得られ、それぞれのテスト ケースに両プレイヤーの最大許容勝利数 (この簡単なバージョンでは等しい) とスコア係数が含まれます。 出力は、これらの制約の下で達成可能な最大スコアである必要があります。 

制約は重要です。`n`そして`m`まで可能です`2 * 10^7`、つまり、可能なすべてのソリューションを反復するソリューション`(W_L, W_F)`ペアは無理です。 これにより、複雑さ O(n*m) の単純な総当りアプローチが排除されます。 テスト ケースの最大数 1000 は、各ケースの結果を効率的に計算する必要があることも意味します。 

明らかではないエッジケースは、一方のスコア係数が他方のスコア係数を圧倒する場合に発生します。 たとえば、次の場合`l = 1`そして`f = 10^9`、できるだけフラムに勝ってもらいたいのですが、`gcd`制約により、単純に取得できなくなります`W_F = n`。 同様に、次のような小さな値`n = 2`そして`l = f = 1`同点が生じる可能性があり、維持するには慎重な順序が必要です`gcd <= 1`。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 勝利のシーケンスをすべて列挙し、計算することができます。`gcd(W_L, W_F)`各ラウンドの後に、有効な最大スコアを記録します。 これは正しいですが、まったく実用的ではありません。`n = 10^5`、シーケンスの数が指数関数的に増加し、制限時間を超えてしまいます。 

重要な洞察は、互いに素数の構造から得られます。 可能性のあるグリッドを想像すると`(W_L, W_F)`値が互いに素であるペアのみを考慮する必要があります。`gcd`1 を超える値はシーケンスを直ちに無効にします。 以来`n = m`、加重スコア軸に沿って最大となる互いに素のペアは、最適化する線の近くにあります。`l * W_L + f * W_F`。 これは、「支配的な」係数を整数で除算し、連続する互いに素の候補をステップ実行することと同じです。 このアプローチは反復処理に帰着します。`W_L`または`W_F`候補を計算し、線形スコアを最大化するために対応する他の変数を計算し、それらが互いに素であることを確認します。 n×m グリッド全体を調査することなく、単純な数理論を使用して反復を効率的に制限できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n+m)) | お(1) | 遅すぎる |
 | 最適 | O(sqrt(n)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. どのプレーヤーがより高い得点係数を持っているかを特定することから始めます。 一般性を失わずに次のように仮定します。`l <= f`; そうでない場合は、レルとフラムの役割を交換します。 これにより、より高いスコアを優先して反復を効率的に行うことができます。 
2. シーケンスが互いに素のペアで終了する必要があることに注意してください。`(W_L, W_F)`。 どれについても`k`そのような`W_L = floor(n / k) * k`そして`W_F = floor(n / k) * (k-1)`またはその対称的な対応物を使用して、候補を生成できます。 ただし、反復処理することで簡素化できます。`k`1から`sqrt(n)`そして両方を考慮してください`(floor(n/k), n - floor(n/k))`可能な限りの同一候補。 
3. 各候補ペアについて`(W_L, W_F)`、 確認する`gcd(W_L, W_F) == 1`。 互いに素であり、範囲内にある場合にのみスコアを計算します`0 <= W_L <= n, 0 <= W_F <= m`。 
4. すべての有効な候補ペアにわたって観察された最大スコアを追跡します。 最適なペアには、1 人のプレーヤーが`n`勝利から 1 を引いて、もう 1 つが互いに素になるように調整します。 
5. 各テストケースの最大スコアを出力します。 

これが機能する理由は、スコア関数の線形性です。`l*W_L + f*W_F`最適なスコアが実行可能領域の境界で達成されることを意味します。 によって定義される「エッジ」に沿った互いに素のペアに焦点を当てることにより、`W_L + W_F <= n + m`まで繰り返します`sqrt(n)`、冗長な計算を行わずに、関連するすべての候補を効率的に探索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def max_score(n, l, f):
    ans = 0
    for k in range(1, int(n**0.5) + 2):
        W_L = n // k
        W_F = n - W_L
        if W_L <= n and W_F <= n and gcd(W_L, W_F) == 1:
            ans = max(ans, W_L * l + W_F * f)
        W_F_alt = n // k
        W_L_alt = n - W_F_alt
        if W_L_alt <= n and W_F_alt <= n and gcd(W_L_alt, W_F_alt) == 1:
            ans = max(ans, W_L_alt * l + W_F_alt * f)
    return ans

t = int(input())
for _ in range(t):
    n, m, l, f = map(int, input().split())
    # n == m guaranteed
    print(max_score(n, l, f))
```このコードでは、すべてを反復処理します。`k`まで`sqrt(n)`可能な最大の勝利に近い互いに素の候補を生成します。 両方を計算します`(W_L, W_F)`候補者を見逃さないようにするための対称的な対応物です。 の`gcd`チェックでは、一致全体を通じてシーケンスが有効であるとのみみなされることが保証されます。`ans`accumulates the maximum score.

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
