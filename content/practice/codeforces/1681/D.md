 ## 解決策
 ## 問題の理解

 整数が与えられます`x`そして目標の長さ`n`。 任意の数字を繰り返し選択できます`y`現在の番号から`x`そして掛け算する`x`による`y`。 目標は作ることです`x`まさに持っています`n`このような演算の最小数を使用した桁数。 出力はその最小値である必要があります。または、`-1`それが不可能な場合。 

The first thing to notice is that the length of`x`乗算的に成長します。 数字 0 または 1 を乗算しても、単純な場合を超えて長さは増加しないため、これらの数字のみを含む数字はスタックされる可能性があります。 たとえば、次の場合`x = 1`そして`n = 2`、繰り返し 1 を掛けても桁数が増えることはないため、必要な演算数は不可能であるため、出力は次のようになります。`-1`。 

制約は小さいです。`n`最大でも19歳であり、`x < 10^(n-1)`。 これは、考慮する必要がある個別の数値の総数が、BFS スタイルまたはメモ化された検索には十分に小さいことを意味します。 しかし、`x`それ自体が非常に大きくなる可能性があるため、すべての整数値を反復しようとするアルゴリズムは、`10^19`失敗します。 

エッジケースには次のような場合が含まれます。`x`ゼロが含まれている (ゼロを乗算すると進行が停止されるため)、または`x`すでに`1`または他の低い数字。 どの桁が増加に寄与するかを慎重に処理しない単純なアプローチでは、このようなケースは失敗します。 

## アプローチ

 ブルートフォース手法では、すべての一連の操作が試行されます。 各ステップで、次の可能なすべての数値を乗算して生成します。`x`10 進数表現に存在する各桁によって計算されます。 これを BFS でモデル化できます。`x`、キューを格納する`(current_number, operations_so_far)`。 BFS は正しいです。なぜなら、操作の_最小_数が要求され、BFS は操作の昇順で状態を探索するからです。 

純粋な総当たり DFS の問題は、数値が急速に爆発的に増加することです。 繰り返される数値を切り詰めなければ、可能性の数は非常に急速に増加します。 たとえば、から`x = 2`、2 を掛け、次に 4 を掛け、次に 8 を掛けると、すぐに膨大な数に達します。 メモ化や訪問状態の追跡がないと、DFS は同じ番号を無限にまたは繰り返し再訪問し、タイムアウトが発生する可能性があります。 

重要な洞察は、問題の状態が現在の数値によって完全に把握されることを認識することです。`x`これまでに実行された操作の数。 これまでに訪問したことのない番号を探索するだけで済みます。 操作の数を最小限に抑えたいため、BFS が最適に機能します。 数字も無視します`0`そして`1`長さを伸ばすのに役立たないため、掛け算で使用します。 

したがって、最適な解決策は、次から始まる BFS です。`x`、各ステップの乗算`x`重要な数字 (2 ～ 9) によって、訪問された番号を追跡します。 ある数値に達したら`n`桁の場合は、歩数を返します。 到達せずにキューが空になった場合`n`数字、答えは`-1`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DFS | O(9^k) | O(k) | 遅すぎると数値が爆発的に増加します |
 | 訪問枝刈りを使用した BFS | O(到達可能な数値の数) | O(到達可能な数値の数) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力の読み取り`n`そして`x`。 現在の長さかどうかを確認します`x`すでに`n`。 その場合は印刷してください`0`そして戻ります。 これは簡単な境界チェックです。 
2. タプルを使用して BFS キューを初期化します。`(x, 0)`、 どこ`0`これまでの操作の数です。 
3. を初期化します。`visited`含むセット`x`。 これにより、同じ番号を再訪して無限ループに陥ることが防止されます。 
4. キューが空でない間にポップ`(current_number, operations)`正面から。 
5.変換`current_number`文字列に変換し、その数字を反復処理します。 各桁ごとに`d`より大きい`1`、計算します`next_number = current_number * d`。 
6.長さの場合`next_number`等しい`n`、 戻る`operations + 1`。 目標の長さに到達したのはこれが初めてであるため、BFS はその長さが最小限であることを保証します。 
7. もし`next_number`以下より少ない`n`数字が入っていない`visited`に追加します`visited`そしてエンキューする`(next_number, operations + 1)`。 
8. 長さの数値が見つからずにキューが空になった場合`n`、印刷`-1`。 

機能する理由: BFS は、最初に正確な数値に到達することを保証します。`n`桁数を考慮して、最小限の乗算数を使用しました。 訪問セットは、数値を再処理しないことを保証し、数値 1 と 0 による無限ループを防ぎます。1 より大きい数値のみを考慮することで、長さを増やさない操作を回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, x = map(int, input().split())
    if len(str(x)) >= n:
        print(0)
        return
    
    visited = set()
    queue = deque([(x, 0)])
    visited.add(x)
    
    while queue:
        current, ops = queue.popleft()
        for d in str(current):
            digit = int(d)
            if digit <= 1:
                continue
            next_num = current * digit
            if len(str(next_num)) == n:
                print(ops + 1)
                return
            if next_num not in visited and len(str(next_num)) < n:
                visited.add(next_num)
                queue.append((next_num, ops + 1))
    
    print(-1)

solve()
```解決策は次のことを確認することから始まります。`x`すでに希望の長さになっています。 BFS は最小限の操作を保証します。 停滞を避けるために、2 ～ 9 の数字のみを乗算します。 訪問済みセットは、数値の再訪を防ぎます。これは、反復シーケンスが生成される可能性がある 2 や 3 のような小さな桁の場合に重要です。 使用する`deque`BFS が O (到達可能な数) で実行されることを保証します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(R * D) | R は長さ n 未満の到達可能な数値の数で、D ≤ 9 桁で、各乗算と文字列変換のコストは O(D) です。 n ≤ 19 であるため、R は小さくなります。 
| スペース | O(R) | 訪問先セットには到達可能な各番号が格納され、BFS キューには同様の数の状態が保持されます。 |

 n ≤ 19 の場合、到達可能な数値の数は、BFS が 2 秒および 512 MB 以内に適切に完了するのに十分なほど小さいです。
