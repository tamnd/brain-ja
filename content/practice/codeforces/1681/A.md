 ## 解決策
 ## 問題の理解

 2 人のプレーヤーはそれぞれ整数のマルチセットを保持します。 彼らはターンベースのゲームをプレイします。唯一のルールは、新しくプレイされるすべての数字が以前の数字より厳密に大きくなければならないということです。 プレイヤーは交互にターンを行い、各ターンでプレイヤーは最後にプレイした値より大きい残りのカードを選択する必要があります。 そのようなカードが存在しない場合、そのプレイヤーは直ちに負けます。 

各テスト ケースでは、アリスが開始するときとボブが開始するときの 2 つのシナリオの最適なプレイの下で勝者を決定する必要があります。 

制約は非常に小さいです。 各プレイヤーは最大 50 枚のカードを持ち、値は 50 によって制限され、最大 1000 のテスト ケースがあります。 これは、どのソリューションでも、パフォーマンスを心配することなく、並べ替えや単純な計数戦略さえも安全に使用できることを示唆しています。 ゲーム状態の総当りシミュレーションも理論的には可能ですが、その必要はありません。 

微妙な問題は、最初の動きに制約がないことです。 単純なアプローチでは、「最小のカードから始める」または「最大のカードから始める」が常に最適であると想定する可能性があります。 最初の数字の選択によって強制応答の連鎖全体が決定されるため、これは一般的には当てはまりません。 ただし、値の範囲が小さいため、正しい解決策を得るには深いゲーム ツリー検索は必要ありません。 

もう 1 つのよくある落とし穴は、常に最小の有効な次のカードを選択して貪欲にシミュレーションしようとすることです。 この戦略は、早い段階で小さなカードを消費すると、後で対戦相手がより長いチェーンを構築するのを妨げることがあるということを無視しているため、失敗する可能性があります。 

## アプローチ

 直接的なブルート フォース ソリューションでは、ゲームを状態空間として扱います。各状態は、最後にプレイされた値、誰のターン、どのカードが残っているかによって定義されます。 各状態から、すべての有効な手を試します。 これは正しいですが、各プレーヤーがさまざまな方法でプレイの順序を変更できるため、すぐに指数関数的になります。 

重要な観察は、ゲームは同一の値間の順序に依存せず、唯一の制約は単調増加であるということです。 値が小さいため、実際に重要なのは、各プレイヤーが各値のカードを何枚持っているかです。 

両方のプレイヤーの配列をソートしたら、最初の開始値を選択し、可能な限り最長の交互チェーンを貪欲に拡張するという観点から考えることができます。 各プレイヤーは常に、前の動きよりも大きい、利用可能な最小のカードで応答することを望んでいます。より大きなカードを選択すると、将来の選択肢が減るだけだからです。 

これにより、問題は、考えられる開始動作ごとに、シーケンスをどこまで延長できるかを確認するだけになります。 最悪の場合でも開始値は 100 個しかないため、これは非常に効率的になります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に解決します。 

まず、アリスとボブの両方のカードを並べ替えます。 ソートにより、シーケンスを拡張しようとするときに、常にリニア スキャン順序で次の有効なカードを選択できることが保証されます。 

次に、可能な限りの初動を試します。 最初の動きには、アリス開始またはボブ開始の 2 種類があります。 それぞれのケースについて、ゲームをシミュレーションします。 

シミュレーション中、ソートされた各リストへのポインターを維持します。 カードは一度使用されると考慮から外されるため、ポインタは常に前に進み、後戻りすることはありません。 

交互に順番を変えていきます。 各ターンで、現在のプレイヤーは最後にプレイした値より厳密に大きいカードが見つかるまでポインターを進めます。 そのようなカードが存在しない場合、現在のプレイヤーは負けとなり、シミュレーションは終了します。 

両方の開始構成の結果を計算し、勝者を出力します。 

最初の手が決まればゲームは完全に決まるため、辞書編集や構造の複雑さはここでは関係ありません。

### なぜ効果があるのか

 ゲームのどの時点でも、両プレイヤーは将来の柔軟性を最適に維持しようとします。 ソートされた配列では、将来の移動のために可能な限り最大のスペースを残すため、最小の有効なカードを選択することが常に最適です。 より大きな選択をすると、チェーンを継続する能力を向上させることなく、将来利用可能な応答の数が厳密に減少します。 これにより、貪欲なシミュレーションが最適なプレイと同等になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def simulate(a, b, start_a):
    ia = ib = 0
    last = -1
    turn_a = start_a

    while True:
        if turn_a:
            while ia < len(a) and a[ia] <= last:
                ia += 1
            if ia == len(a):
                return "Bob"
            last = a[ia]
            ia += 1
        else:
            while ib < len(b) and b[ib] <= last:
                ib += 1
            if ib == len(b):
                return "Alice"
            last = b[ib]
            ib += 1
        turn_a = not turn_a

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        m = int(input())
        b = list(map(int, input().split()))

        a.sort()
        b.sort()

        res1 = simulate(a, b, True)
        res2 = simulate(a, b, False)

        print(res1)
        print(res2)

if __name__ == "__main__":
    solve()
```このソリューションでは、両方の配列がソートされた状態に保たれるため、次の有効な移動を見つけるには、移動ポインタを使用した線形スキャンが行われます。 各ポインターは前方にのみ進むため、各シミュレーションはカードの総数に対して線形時間で実行されます。 

微妙な点は、比較では以下を使用することです。`<= last`、厳格な増加が正しく実施されるようにします。 もう 1 つの重要な詳細は、カードを選択した直後に最後にプレイされた値が更新され、ターン移行の正確性が維持されることです。
