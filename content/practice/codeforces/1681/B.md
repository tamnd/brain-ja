 ## 解決策
 ## 問題の理解

 私たちに与えられたデッキは、`n`個別の整数値を持つカードを上から下に並べます。 その後、パフォーマンスを行います`m`シャッフル操作。それぞれ数値で定義されます。`b_j`。 操作がトップを取る`b_j`カードを削除し、残りの下に移動します`n - b_j`カードを作成し、各セグメント内の順序を維持します。 すべてのシャッフルの後、デッキの一番上のカードを決定する必要があります。 

入力には複数のテスト ケースが含まれています。 各テスト ケースではカードの数が指定されます`n`、配列`a`デッキを表す、シャッフル数`m`、および配列`b`シャッフル量を表します。 出力は各テスト ケースの単一の整数、つまりすべてのシャッフル後の一番上のカードの値です。 

制約が示すのは、`n`そして`m`それぞれは 2・10^5 に達する可能性があり、すべてのテスト ケースの合計は同じ数値で制限されます。 シャッフルごとに配列のスライスを移動するブルート フォース シミュレーションでは O(n * m) の操作が必要となり、最悪の場合 4·10^10 に達する可能性があります。 これは 2 秒の制限時間としては遅すぎます。 したがって、線形時間アプローチが必要です。`n + m`。 

エッジケースは、同じカードが繰り返し移動する場合、またはシャッフルが重なる場合に発生します。 たとえば、次の場合`n = 2`、`a = [1, 2]`、 そして`b = [1, 1, 1]`単純なシャッフルではカードが 3 回交換されますが、どのインデックスが一番上に到達するかを追跡するだけであれば、デッキ全体をシミュレートしなくても最後のカードを特定できます。 もう 1 つの微妙なケースは、最大の場合です。`b_j`シーケンス内で複数回出現します。 カードを他のすべての上に移動する最初のシャッフルのみが、一番上のカードに影響します。 後でシャッフルして小さいプレフィックスを移動しても、最初のカードを一番上に戻すことはできません。 

## アプローチ

 ブルートフォース手法では、シャッフルごとにデッキをシミュレートします。 シャッフルするたびに一番上を取る`b_j`カードを作成し、残りの下に追加します。 このアプローチは正しいですが、各シャッフルに O(n) 操作が必要になる可能性があり、最大 2 · 10^5 のシャッフルがあり、最悪の場合の実行時間は O(n * m) となるため、非効率的です。 これでは制限時間を超えてしまいます。 

重要な洞察は、最終的なトップカードのみを考慮しているということです。 カードのプレフィックスをデッキの下に移動しても、シャッフルの長さがそのカードの現在の位置よりも厳密に大きい場合を除き、最初の位置より上のカードには影響しません。 したがって、すべてのシャッフル後の一番上のカードは、最大のカードの直後の位置にあるカードになります。`b_j`シャッフル リストの最後から後方に向かって検出されます。 すべてのシャッフルをシミュレートする代わりに、スキャンすることができます。`b`逆に最大値を追跡します`b_j`見た。 その最大値と等しいインデックスにあるカード`b_j`元のデッキのすべてのシャッフル後の一番上のカードになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | O(n) | 遅すぎる |
 | 追跡最大プレフィックス | O(n + m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`そしてデッキ配列`a`。 
2. シャッフル数を読み取る`m`そしてシャッフル配列`b`。 
3. 変数を初期化する`max_b`ゼロに。 これにより、トップに影響を与える最大のシャッフルが追跡されます。 
4. シャッフル配列を反復処理する`b`逆に。 反復ごとに更新します`max_b`現在の値と現在のシャッフル量の最大値まで`b_j`。 どのカードが一番上に到達するかは最大のプレフィックス シャッフルによってのみ決定されるため、これにより、最終的に他のカードの下に移動される最長のプレフィックスがキャプチャされます。 
5. すべてのシャッフルを処理した後、一番上のカードは`a[max_b]`、ゼロベースのインデックスを使用します。 シャッフルがトップに影響を与えない場合、`max_b`はゼロになり、元の一番上のカードが残ります。 
6. 結果を印刷します。 

機能する理由: シャッフルを逆に処理することで、最上位の候補カードを移動する最後のシャッフルの効果をキャプチャします。 最大シャッフル後の小さなプレフィックスは、最終的なトップより下にあったカードのみを移動するため、どのカードがトップになるかには影響しません。 これにより、すべてのカードの動きをシミュレートすることなく正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    m = int(input())
    b = list(map(int, input().split()))
    
    max_b = 0
    for x in reversed(b):
        if x > max_b:
            max_b = x
    print(a[max_b])
```コードは、次を使用してすべての入力を効率的に読み取ります。`sys.stdin.readline`。 シャッフル配列を逆方向に反復して、最終的なトップ カードを決定する最大のプレフィックスを特定します。`max_b`ゼロインデックスで、Python リストのインデックスと一致します。 これにより、単純なシミュレーションから発生する可能性のあるオフバイワンエラーが回避されます。 たった一度の通過だけ`b`が必要なので、複雑さは線形です。`m + n`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースごとに O(n + m) | デックの読み取りには O(n)、シャッフルのスキャンには O(m) かかります。 
| スペース | O(n + m) | 配列`a`そして`b`テストケースごとに保存 |

 の合計`n`そして`m`すべてのテスト ケースにわたって 2 · 10^5 を超えないため、この解は与えられた制約に対して効率的です。 メモリ使用量の大部分は配列によって占められており、256 MB 未満に十分収まります。
