 ## 解決策
 ## 問題の理解

 この問題は、4 つのキーが 2 × 2 のグリッドとして配置された故障したテンキーをモデル化しています。 各キーは 1 ～ 4 の数字の 1 つに対応し、キーを押すと、その行インデックスと列インデックスを含むペアが生成されます。 複数のキーを同時に押すと、コントローラーは行と列の間のペアを失います。 出現した行のセットと出現した列のセットのみを受け取ります。 タスクは、観察された行セットと列セットを生成した可能性のあるキーの異なるサブセットがいくつあるかを数えることです。 元の問題では、キーパッドには 2 つの可能な行値と 2 つの可能な列値しかないため、受信する行セットと列セットのサイズが最大 2 に制限されます。 

入力には複数のテスト ケースが含まれています。 各テスト ケースの最初の行には、受信した個別の行と列の数が示されます。 次の 2 行では、これらの行の値と列の値を説明します。 出力は、行と列の集合が受信信号と正確に一致する 4 つのキーパッド キーのうちのサブセットの数です。 

制約は非常に小さいです。 テスト ケースは最大 10 個あり、受信信号の各次元には 1 つまたは 2 つの値のみが含まれます。 これは、ソリューションに高度な最適化が必要ないことを意味します。 一定時間のアプローチで十分であり、4 つのキーのすべての可能なサブセットをチェックしても、テストごとにわずか 16 ケースで済みます。 大規模なデータ構造や複雑な数学を含むソリューションは、実際の問題よりもはるかに難しい問題を解決することになります。 

主な罠は、異なるキーの組み合わせが同じ信号を生成する可能性があるという事実から生じます。 たとえば、キー 1 と 4 を押すと、キー 2 と 3 を押したときと同じ行セットと列セットが受信されます。信号が元のペアリング情報を保持していないため、一意の押されたセットを再構築しようとするソリューションは失敗します。 

入力用```
1
1 1
0
0
```正しい出力は```
1
```キー 1 のみが行セットを生成します`{0}`と列セット`{0}`。 行と列の選択を個別にカウントする不注意なアプローチでは、行と列が無関係で過剰にカウントされるとして誤って扱われる可能性があります。 

入力用```
1
2 2
0 1
0 1
```正しい出力は```
7
```空のセットを除く 4 つのキーの空でないすべてのサブセットは完全な行セットを生成します`{0,1}`と列セット`{0,1}`。 不注意なアプローチでは、受信信号が 1 つの組み合わせを識別すると想定しているため、1 つだけが返される可能性があります。 

## アプローチ

 キーパッドには 4 つのキーしか含まれていないため、直接的なブルート フォース ソリューションで十分です。 自然な強引なアイデアは、考えられるすべてのキーのサブセットを列挙し、そのサブセットによって作成された信号をシミュレートし、それを指定された信号と比較することです。 選択したキーごとに、その行と列を収集します。 収集された両方のセットが受信した行セットと列セットと等しい場合、答えは増加します。 

このアプローチは、有効なキーストロークの組み合わせの定義を正確にチェックするため、正しいです。 可能なサブセットは (2^4 = 16) のみであるため、最悪のケースではテスト ケースごとに数十の操作しか実行されません。 制約が小さいため、これが意図したソリューションになります。 

重要な点は、キーパッドのレイアウトが固定されていることです。 可能なレイアウトを検索したり、数式を導き出したりする必要はありません。 不明なのは 4 つのキーのどれが押されたかだけであり、完全な検索スペースのサイズは 16 です。ブルート フォース手法により、問題はすでに少数の固定数の候補をチェックするだけで済みます。 

アプローチ間の比較は次のとおりです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(16) | お(1) | 承認済み |
 | 最適 | お(16) | お(1) | 承認済み |

 一定の検索スペースを大幅に削減することはできないため、総当たりソリューションは、ここでも最適な実用的なソリューションです。 

## アルゴリズムのチュートリアル

 1. 4 つのキーを対応する座標とともに保存します。 キー 1 には座標があります`(0,0)`、キー 2 には座標があります`(0,1)`、キー 3 には座標があります`(1,0)`、キー 4 には座標があります`(1,1)`。 
2. 受信した行の値と列の値を読み取り、セットとして保存します。 受信した値の順序は重要ではないため、セットが使用されます。 
3. 0 ～ 15 のすべてのマスクを列挙します。各ビットは、押された組み合わせに 4 つのキーのいずれかが含まれるかどうかを表します。 
4. 現在のマスクについて、選択したキーに属するすべての行と列を収集します。 生成された行セットと列セットは、コントローラーがこの組み合わせから何を受け取るかを正確に記述します。 
5. 生成されたセットを入力セットと比較します。 両方が等しい場合、このマスクをキーストロークの組み合わせとしてカウントします。 
6. 有効なマスクの数を出力します。 

なぜ効果があるのか:

 押されたすべての可能な組み合わせは、4 つのキーの 1 つのサブセットに正確に対応し、すべてのサブセットが列挙によってチェックされます。 サブセットごとに、アルゴリズムはコントローラーが受信した正確な信号を計算します。 サブセットは、その信号が指定された信号と一致する場合にのみカウントされるため、最終的なカウントにはすべての有効な組み合わせのみが含まれます。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    t = int(input())
    keys = [(0, 0), (0, 1), (1, 0), (1, 1)]
    ans = []

    for _ in range(t):
        m, n = map(int, input().split())
        rows = set(map(int, input().split()))
        cols = set(map(int, input().split()))

        cur = 0

        for mask in range(1 << 4):
            r = set()
            c = set()

            for i in range(4):
                if mask & (1 << i):
                    r.add(keys[i][0])
                    c.add(keys[i][1])

            if r == rows and c == cols:
                cur += 1

        ans.append(str(cur))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```配列`keys`は固定キーパッド レイアウトを表します。 要素のインデックスはキー番号から 1 を引いたものであるため、ビット`i`マスク内の 1 つは 1 つのキーパッド キーに直接対応します。 

マスク ループは、考えられるすべてのサブセットをカバーします。 指定された制約では常に少なくとも 1 行と 1 列が提供されますが、より一般的な問題では受信信号が理論的には空になる可能性があるため、空のサブセットが意図的に含まれています。 

セット`r`そして`c`マスクごとに再構築されます。 これにより、列挙問題でよくある実装ミスである、前のサブセットの値を誤って保持することが回避されます。 

キーパッドには正確に 4 つの既知の位置があるため、インデックス境界の問題はありません。 整数オーバーフローも、答えが最大 16 であるため不可能です。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    def solve():
        input = sys.stdin.readline
        t = int(input())
        keys = [(0, 0), (0, 1), (1, 0), (1, 1)]
        out = []

        for _ in range(t):
            m, n = map(int, input().split())
            rows = set(map(int, input().split()))
            cols = set(map(int, input().split()))

            ans = 0
            for mask in range(16):
                r = set()
                c = set()
                for i in range(4):
                    if mask & (1 << i):
                        r.add(keys[i][0])
                        c.add(keys[i][1])
                if r == rows and c == cols:
                    ans += 1

            out.append(str(ans))

        return "\n".join(out)

    result = solve()
    sys.stdin = old_stdin
    return result

 ## 特殊なケース

 次のような 1 つの正確なキーによって生成された信号の場合:```
1
1 1
0
0
```アルゴリズムは 16 個のサブセットすべてをチェックします。 キー 1 を含むサブセットのみが行セットを作成します`{0}`と列セット`{0}`したがって、答えは 1 です。この解決策では、独立した行と列の選択を実際のキーと混同しません。 

すべての行と列を含む信号の場合:```
1
2 2
0 1
0 1
```アルゴリズムは 7 つの一致するサブセットを見つけます。 空のサブセットは行も列も生成しないため拒否されますが、1 つの座標が欠落している単一行または単一列の組み合わせを除く空でないすべてのサブセットは正しく処理されます。 

次のようなあいまいな信号の場合:```
1
2 2
0 1
0 1
```サブセット`{1,4}`そして`{2,3}`どちらも同じコントローラー信号を生成します。 列挙では、不完全な情報から元のキーを再構築するのではなく、組み合わせを直接チェックするため、両方がカウントされます。
