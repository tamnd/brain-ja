 ## 問題の理解

 パズルは円盤状で、`n`セクター。 矢印はセクターから始まります`s`ボタンを押すたびに正確に動きます`k`時計回りにセクターを動かします。 セクターはラップアラウンドするため、セクターの後に`n - 1`次のセクターは`0`。 タスクは、矢印をセクターに着地させるために必要なボタンを押す最小の回数を見つけることです。`x`。 一連の動作が到達できない場合`x`、答えは`-1`。 

入力は、円のサイズ、各クリック後の固定移動、最初のセクター、および目的のセクターを表す 4 つの整数で構成されます。 出力は必要な最小クリック数です。 

制約`n ≤ 20000`多くの場合、すべてのセクターの直接シミュレーションが可能であることを意味しますが、注意が必要です。 シミュレーションには最大で次のものが必要になります。`n`ここでは許容されますが、意図された数学的解決策ではセクター数に依存することを回避し、答えを直接計算します。 さらに重要なことは、ムーブメントの構造がモジュラー演算であるため、同じ推論がより大きな限界まで自然に拡張されることです。 

重要なエッジケースは、追加を繰り返し行うという事実から生じます。`k`必ずしもすべての分野を訪問するわけではありません。 

たとえば、入力が次の場合:```
12 4 1 6
```矢印は次の場所を訪れます。```
1, 5, 9, 1, 5, 9, ...
```対象分野`6`には到達しないため、正しい出力は次のようになります。```
-1
```すべてのセクターが最終的に出現すると仮定した不注意な解決策は、不正確な答えを与えることになります。 

もう 1 つの重要なケースは、開始点がすでにサイクルの一部であるが、ターゲットが最小の正のラップアラウンド カウントを必要とする場合です。 例えば：```
10 6 3 9
```ポジションは次のとおりです。```
3 -> 9
```ワンクリック後、答えは次のようになります。```
1
```フルサイクル後の位置のみをチェックするソリューションや、モジュロ演算を誤って処理するソリューションでは、これが見逃される可能性があります。 

最後のエッジケースは、移動サイズとセクター数が約数を共有する場合です。 例えば：```
8 6 0 5
```矢印は偶数セクターにのみ到達します。```
0, 6, 4, 2, 0, ...
```セクター`5`それは不可能であり、答えは次のとおりです。```
-1
```これらのケースの背後にある分割可能性の条件が解決策の核心です。 

## アプローチ

 簡単なアプローチは、クリックをシミュレートすることです。 から始まる`s`を繰り返し追加します`k`そして結果のモジュロを取得します`n`。 現在のセクターが`x`、その答えが見つかりました。 に戻ると`s`見つからずに`x`、サイクルが完了し、目標に到達できません。 

矢印の動きが決定的であるため、この方法は正しいです。 セクターが繰り返されると、将来のすべてのポジションも繰り返されるため、新しいセクターは出現できません。 問題は、数学的サイクルを個々の動きのシーケンスとして扱うことです。 最悪の場合、ほぼ実行されます`n`繰り返し。 指定された制約の場合、これでも問題ありませんが、基礎となる構造が隠蔽され、スケールできなくなります。 

重要な観察は、その後です。`t`クリックすると、矢印は次の位置にあります。$$(s + t \cdot k) \bmod n$$この値を等しくする必要があります`x`、次のようになります。$$t \cdot k \equiv x - s \pmod n$$これは線形合同です。 この方程式は、次の最大公約数が次の場合にのみ解を持ちます。`k`そして`n`分割する`x - s`。 そうなった場合、方程式をその gcd で除算し、逆モジュラーを使用して有効な最小値を見つけることができます。`t`。 

ブルートフォースソリューションは、反復によって生成された状態を正確に調査するため機能します。 数学的解決策は、モジュラー演算を使用して到達可能な同じ状態を記述し、必要な手数を直接解決するため、より高速に機能します。

 ## アルゴリズムのチュートリアル

 1. 開始セクターからターゲットセクターまでに必要な時計回りの距離を計算します。 

以下を定義します。$$d = (x - s) \bmod n$$後`t`クリックするには、次のものが必要です。$$t \cdot k \equiv d \pmod n$$これにより、運動の問題がモジュラー方程式を解くことに変換されます。 
2. コンピューティング`g = gcd(k, n)`。 

繰り返し加算して到達したすべての値`k`同じ剰余モジュロを持ちます`g`。 これは、ターゲット距離も次の値で割り切れる必要があることを意味します。`g`。 
3. もし`d`で割り切れない`g`、 戻る`-1`。 

いくら掛けてもダメ`k`の倍数以外の剰余を生成できる`g`、そのため、ターゲットセクターに到達できません。 
4. すべての項を次の値で割って式を簡略化します。`g`。 

得られるものは次のとおりです。$$\frac{k}{g}t \equiv \frac{d}{g} \pmod{\frac{n}{g}}$$さて、の係数は`t`は新しい係数と互いに素です。 
5. モジュラー逆関数を求めます。`k / g`モジュロ`n / g`。 

2 つの値は互いに素であるため、逆数が存在します。 Multiplying both sides by this inverse gives:$$t \equiv \frac{d}{g} \cdot (k/g)^{-1} \pmod{n/g}$$6. 負でない最小の値を返します。`t`。 

モジュロ演算により、当然ながら最小の有効なクリック数が得られます。 

機能する理由: 到達可能なセクターは、追加によって生成される循環グループを形成します。`k`モジュロ`n`。 の gcd`k`そして`n`どの残基がそのグループに属するかを正確に決定します。 ターゲット距離がこのグループに属する場合、合同を減らすと可逆係数をもつ方程式が生成され、逆モジュラーによりサイクル内で一意の答えが得られます。 それが属していない場合は、一連のクリックでそれに到達することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def egcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = egcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def mod_inverse(a, mod):
    _, x, _ = egcd(a, mod)
    return x % mod

def solve():
    n, k, s, x = map(int, input().split())

    d = (x - s) % n

    g = egcd(k, n)[0]

    if d % g != 0:
        print(-1)
        return

    k //= g
    d //= g
    mod = n // g

    answer = (d * mod_inverse(k, mod)) % mod
    print(answer)

if __name__ == "__main__":
    solve()
```拡張ユークリッド アルゴリズムが使用されるのは、逆モジュラーの構築に必要な gcd と係数の両方が提供されるからです。 逆行列は、で割った後にのみ存在します。`g`、 なぜなら`k / g`そして`n / g`は共素であることが保証されています。 

最初のモジュロ演算では、次の場合でも時計回りの距離が正しく計算されます。`x`数値的には以下より小さい`s`。 割り算チェックは方程式を簡略化する前に行う必要があります。そうしないと、到達できない場合に無意味な逆計算が生成される可能性があります。 

Python の整数はオーバーフローしないため、乗算は`d * inverse`安全です。 最後のモジュロは、必要なサイクル長内に答えを保持します。

## テストケース```python
import sys
import io

def egcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x1, y1 = egcd(b, a % b)
    return g, y1, x1 - (a // b) * y1

def mod_inverse(a, mod):
    _, x, _ = egcd(a, mod)
    return x % mod

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k, s, x = map(int, sys.stdin.readline().split())

    d = (x - s) % n
    g = egcd(k, n)[0]

    if d % g:
        return "-1\n"

    k //= g
    d //= g
    mod = n // g
    return str((d * mod_inverse(k, mod)) % mod) + "\n"

assert solution("8 6 0 4\n") == "2\n", "reachable case"
assert solution("12 8 1 6\n") == "-1\n", "unreachable gcd case"
assert solution("2 1 0 1\n") == "1\n", "minimum size"
assert solution("20 5 3 18\n") == "-1\n", "same remainder restriction"
assert solution("17 4 10 5\n") == "3\n", "wrap-around movement"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`8 6 0 4`|`2`| 基本到達可能サイクル |
 |`12 8 1 6`|`-1`| GCD 不可能チェック |
 |`2 1 0 1`|`1`| 可能な最小の円 |
 |`20 5 3 18`|`-1`| 移動は 1 つの剰余クラスにのみ到達します。 
|`17 4 10 5`|`3`| 正しいモジュラーラップアラウンド |

 ## 特殊なケース

 対象:```
12 4 1 6
```アルゴリズムは以下を計算します。```

g = gcd(4, 12) = 4
```以来`5`で割り切れない`4`、アルゴリズムはすぐに戻ります`-1`。 これは、到達可能なすべてのセクターの残りが同じであるという事実と一致します。`1`モジュロ`4`。 

のために：```
8 6 0 5
```アルゴリズムは以下を見つけます:```
d = 5
g = gcd(6, 8) = 2
```距離は gcd で割り切れないので、セクター`5`到達できません。 生成されたシーケンスは、次のことを確認します。```
0 -> 6 -> 4 -> 2 -> 0
```のために：```
10 6 3 9
```アルゴリズムは以下を取得します:```
d = 6
g = gcd(6, 10) = 2
```削減後:```
3t ≡ 3 mod 5
```の逆`3`モジュロ`5`は`2`、 それで：```
t = 3 * 2 mod 5 = 1
```答えは`1`、単一の動きに一致します:```
3 -> 9
```考えられるすべての動作シーケンスはモジュラー方程式で表されるため、同じ推論で他のすべてのケースを処理できます。
