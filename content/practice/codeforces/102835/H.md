 ## 解決策
 ## 問題の理解

 ネットワークは、都市が頂点、ケーブルがエッジである無向の重み付きグラフです。 各ケーブルには帯域幅の値があります。 同社は、他のすべての都市からすべての都市に到達できるようにしながら、ケーブルを削除したいと考えているため、最終的なネットワークはスパニング ツリーでなければなりません。 

考えられるすべてのスパニング ツリーの中で、最初の目標は、ツリー内の最小帯域幅エッ​​ジを最大化することです。 この値は、ネットワーク全体の最も弱い接続でもあります。これは、ツリーのすべてのケーブルが、そのケーブルが取り外されたときに作成される 2 つの側間の唯一の接続であるためです。 可能な限り最良の最も弱いエッジを実現した後、同社は、選択したケーブルの合計帯域幅を可能な限り小さくしたいと考えています。 

必要な出力はケーブル帯域幅の合計ではありません。 これは、都市の各ペアにわたって、それらの間で利用可能な帯域幅の合計です。 都市のペアの場合、利用可能な帯域幅は、選択したツリー内の一意のパス上の最小ケーブル帯域幅です。 

グラフが大きくなりすぎて、すべてのスパニング ツリーを試すことが不可能になる場合があります。 可能なツリーの数は指数関数的に増加するため、選択肢を列挙するアプローチはすぐに排除されます。 最適化基準の特別な順序を利用する必要があります。 

よくある間違いは、最大スパニング ツリーを選択してそこで停止してしまうことです。 最大スパニング ツリーは常に最も弱いケーブルを最大化しますが、同じ最も弱い値を持つすべてのツリー間の総ケーブル帯域幅を最小化するとは限りません。 もう 1 つの間違いは、ツリーのエッジを合計して最終的な答えを計算することです。 その答えは、個々のケーブルだけではなく、都市間の経路によって決まります。 

たとえば、次のことを考えてみましょう。```
3 3
1 2 5
2 3 1
1 3 5
```正しく最適化されたツリーは帯域幅 5 と 1 のエッジを使用でき、ペアの帯域幅は 5、1、1 であり、出力は次のようになります。```
7
```選択したケーブル帯域幅を合計するだけの不注意な解決策では 6 が出力されますが、これは問題が求めているものではありません。 

複数のエッジが同じ帯域幅を共有する場合、別のエッジ ケースが発生します。```
4 3
1 2 5
2 3 5
3 4 1
```答えは次のとおりです。```
17
```ペアの帯域幅は 5、5、1、5、1、および 1 であるためです。間違ったステージで等しい重みのエッジを 1 つずつ処理すると、帯域幅レベルで接続されるペアの数を数え間違える可能性があります。 

## アプローチ

 直接的なアプローチでは、考えられるスパニング ツリーを調べ、それらの最も弱いエッジを評価して、必要なペアの寄与を計算します。 これは正しいです。有効な最終ネットワークはすべてスパニング ツリーであり、すべての候補をチェックすると最適なネットワークが見つかるからです。 ただし、エッジが数十本しかないグラフであっても、膨大な数のスパニング ツリーがあるため、このアプローチは使用できません。 

最初の最適化基準は、古典的なボトルネック スパニング ツリー問題です。 可能な最大の最小エッジを持つスパニング ツリーは、最大スパニング ツリーを取得することによって見つけることができます。 そのツリーによって選択された最小のエッジが、考えられる最大のボトルネック値となります。 この値を見つけた後は、それより下のすべてのエッジが最終的な答えに現れることはありません。 

この観察の後、2 番目の基準ははるかに単純になります。 帯域幅が少なくとも最大ボトルネック値であるエッジを含むサブグラフ内の最小スパニング ツリーのみが必要です。 このサブグラフ内のすべてのスパニング ツリーには同じ最適なボトルネックがあるため、選択したケーブルの合計を最小化することは、まさに通常の最小スパニング ツリーの問題となります。 

残りのタスクは、この最終ツリー内のパスの最小値の合計を計算することです。 ツリーのエッジをより大きな帯域幅からより小さな帯域幅に処理すると、重みのエッジが`w`より大きいエッジのみを使用して以前に接続されていたコンポーネントを接続します。`w`。 このステップで初めて接続される都市ペアの数は、まさにパスのボトルネックとなっているペアです。`w`。 素集合和集合構造によりコンポーネントのサイズが得られるため、各エッジ グループの寄与を効率的にカウントできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n + m) | 遅すぎる |
 | 最適 | O(m log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 帯域幅を減らすことによってすべてのケーブルを並べ替え、Kruskal のアルゴリズムを使用して最大スパニング ツリーを構築します。 このツリーに追加された最後のエッジの帯域幅は、選択したエッジの中で最も小さく、これがボトルネックの可能性のある最大値となります。 
2. 帯域幅がこのボトルネック値以上である元のケーブルのみを保持します。 Kruskal のアルゴリズムを再度実行し、今度はケーブルを徐々に分類します。 結果のツリーは、すべての有効な最適ボトルネック ツリーの中で最小のスパニング ツリーになります。 
3. 帯域幅を減らして、この最終ツリーのエッジを並べ替えます。 厳密に大きな帯域幅を持つエッジを使用して接続されている都市を表す、素の集合結合構造を維持します。 
4. 同じ帯域幅のエッジをまとめて処理します。 現在のグループ内のすべてのエッジについて、サイズのコンポーネントを結合します`a`そして`b`作成します`a * b`新しい都市ペアのボトルネックはまさに​​この帯域幅です。 新しく接続されたペアの合計数に帯域幅を掛けて、それを答えに加えます。 
5. 累計を出力します。 

機能する理由: Kruskal の降順プロセスは常に可能な限り最強の接続を維持するため、最大スパニング ツリーは可能な限り最大の最小ケーブル帯域幅を提供します。 このボトルネックが解決されると、すべての有効なソリューションはそのしきい値を超えるエッジのみを使用し、そのサブグラフ内の最小スパニング ツリーによって最も安価な有効なネットワークが得られます。 最終的な DSU プロセスでは、現在の帯域幅がパスをサポートするのに十分なときに正確に都市が接続されるため、各ペアはパスの最小値の正確な値でカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        return True

def solve():
    n, m = map(int, input().split())
    edges = []
    for _ in range(m):
        a, b, w = map(int, input().split())
        edges.append((w, a - 1, b - 1))

    if n == 1:
        print(0)
        return

    desc = sorted(edges, reverse=True)

    dsu = DSU(n)
    bottleneck = 0
    used = 0
    for w, a, b in desc:
        if dsu.union(a, b):
            bottleneck = w
            used += 1
            if used == n - 1:
                break

    valid = [e for e in edges if e[0] >= bottleneck]
    valid.sort()

    dsu = DSU(n)
    tree = []
    for w, a, b in valid:
        if dsu.union(a, b):
            tree.append((w, a, b))
            if len(tree) == n - 1:
                break

    tree.sort(reverse=True)

    dsu = DSU(n)
    ans = 0
    i = 0
    while i < len(tree):
        w = tree[i][0]
        j = i
        add = 0
        while j < len(tree) and tree[j][0] == w:
            _, a, b = tree[j]
            ra = dsu.find(a)
            rb = dsu.find(b)
            if ra != rb:
                add += dsu.sz[ra] * dsu.sz[rb]
                dsu.union(ra, rb)
            j += 1
        ans += add * w
        i = j

    print(ans)

if __name__ == "__main__":
    solve()
```最初の DSU パスでボトルネック値が検出されます。 エッジは最大から最小の順に処理されるため、最終的に受け入れられるエッジは最大スパニング ツリーの最も弱いエッジ、つまり可能な限り最良の最小帯域幅となります。 

2 番目の DSU パスでは、最適化目標が変更されます。 有効なグラフはすでに最適なボトルネックを満たしているため、これらのエッジの中から最小のスパニング ツリーを選択することで、最初の目的を損なうことなくケーブル コストを最小限に抑えることができます。 

最後の DSU パスでは、ツリー構造を使用してパスの最小値をカウントします。 等しい帯域幅のエッジはすべて同じボトルネック値を表すため、1 つのグループで処理されます。 コンポーネント サイズを乗算すると、新しく接続されたすべてのペアが 1 回だけカウントされます。 Python の整数は、オーバーフローを心配することなく、大きな応答サイズを処理します。

 ## 特殊なケース

 グラフに都市が 1 つあり、ケーブルがない場合、評価する都市のペアはありません。 このアルゴリズムはすぐに 0 を返し、スパニング ツリーには常にエッジがあるという想定を回避します。 

複数の最大帯域幅エッ​​ジが存在する場合、ボトルネック値は複数の異なるツリーによって達成される可能性があります。 その中で一番安いものを選ぶのが2番目のクルスカルパスです。 最終的な DSU 計算は、ツリーの構築方法ではなく、結果として得られるツリーのみに依存するため、引き続き機能します。 

同じ帯域幅を持つ複数のエッジを含むツリーの場合、それらのエッジは 1 つのしきい値レベルとして扱われる必要があります。 すべての等しいエッジが追加される前にそれらが個別にカウントされると、一部のペアが間違ったボトルネック値を受け取ることになります。 より小さい帯域幅に移動する前に重みグループ全体を処理すると、現在接続されているすべてのペアが最小エッジが少なくとも現在の帯域幅であるパスを持つという不変条件が維持されます。
