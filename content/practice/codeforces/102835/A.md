 ## 解決策
 ## 問題の理解

 与えられた正の整数を、サイズが十分に近い 2 つの要素に分割できるかどうかを判断する必要があります。 数字`x`2 つの正の整数が存在する場合、右結合とみなされます。`a`そして`b`どこ`a`小さい方の因子、`b`の方が大きい場合、彼らの製品はまさに`x`、小さい係数は大きい係数の少なくとも半分です。 

同様に、約数のペアを選択した後、`(a, b)`と`a <= b`かどうかを確認するだけです。`b <= 2a`。 そのようなペアが存在する場合、答えは次のようになります。`1`; そうでなければ答えは`0`。 

入力には最大 1000 個の独立した数値が含まれており、すべての数値は次の値より小さいです。`2^15`これはわずか 32768 です。この上限は非常に小さいため、数値ごとに数百回のチェックを実行するアルゴリズムは十分に高速です。 検査できる約数はせいぜい数百であるため、考えられるすべての要因のペアを試したソリューションは依然として不必要です。 たとえ`O(x)`この制限ではスキャンは許容されますが、平方根までの除数のみをテストすることで自然に作業を減らすことができます。 

いくつかのケースでは、不注意な実装が失敗する可能性があります。 よくある間違いは、条件に浮動小数点除算を使用することです。`a / b >= 0.5`これにより、回避可能な精度の問題が発生する可能性があります。 等価な整数`2 * a >= b`正確です。 

たとえば、次のように入力します。```
1
66
```要因がある`6 * 11`。 以来`6 / 11`より大きい`0.5`、出力は次のようになります。```
1
```2 つの因子が等しいはずだと誤って仮定して、平方根に近い最も近い因子のペアのみをチェックするソリューションでは、このケースは見逃されます。 

もう 1 つの特殊なケースは素数です。```
1
55
```唯一の因子ペアは`1 * 55`そして`2 * 1 < 55`したがって、出力は次のようになります。```
0
```すべての合成数が右結合されているわけではないため、数値に 1 以外の因数があるかどうかだけをチェックするソリューションでは、間違った結果が得られます。 

可能な最小の入力値も考慮する価値があります。```
1
1
```因子ペアは次のとおりです。`1 * 1`と条件を満たしています。 正しい出力は次のとおりです。```
1
```引数から検索を開始する実装`2`誤って拒否してしまうでしょう。 

## アプローチ

 直接的な総当たりアプローチは、可能なすべての値を試すことです。`a`、どうかを確認してください`a`分割する`x`、そして計算します`b = x / a`。 もし`a <= b`そして`b <= 2a`、有効な分解が見つかりました。 考えられるすべての小さな要素が検査されるため、このアプローチは正しいです。 

1つの数字に対して`x`、これには、からのすべての値をチェックする必要があります。`1`に`x`、与える`O(x)`操作。 最大値が 32768 に近く、テスト ケースが 1000 件である場合、最悪のケースは約 3200 万チェックであり、おそらく多くの言語でまだ合格するでしょうが、因子ペアの数学的構造は無視されます。 

さらに良い観察は、因子がペアで現れるということです。 もし`a`はの約数です`x`、マッチング係数は`b = x / a`。 すべてのペアの少なくとも 1 つのメンバーが次の平方根以下です。`x`なので、次までの約数を検査するだけで済みます。`sqrt(x)`。 約数を見つけるたびに`a`、対応するより大きな因子がすぐにわかり、必要な不等式をテストできます。 

ブルートフォース手法は、考えられるすべての因数分解を探索するため機能しますが、因数のペアの小さい方にはなり得ない値をチェックするのに時間がかかります。 平方根観測では、考えられるすべての候補ペアが考慮されるという保証を維持しながら、これらの不必要なチェックが削除されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | テスト ケースごとに O(x) | お(1) | これらの制限は受け入れられますが、不要です |
 | 最適 | テスト ケースあたり O(sqrt(x)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力番号ごとに`x`、から可能な約数のチェックを開始します`1`まで`sqrt(x)`。 平方根より大きいすべての約数には、対応する小さい約数がすでにチェックされているため、この範囲を検索するだけで済みます。 
2. 値が`a`分割する`x`、ペアの因数を計算します`b = x / a`。 ペア`(a, b)`可能な書き方の 1 つを表します`x`製品として。 
3. 確認する`a`の方が小さい係数です。 ループは平方根までしか到達しないので、`a`は常に以下です`b`。 
4. かどうかを確認します。`b <= 2 * a`。 これは元の比率条件の整数形式であり、浮動小数点計算を回避します。 
5. いずれかの除数のペアが条件を満たす場合、出力します。`1`。 見つからないままループが終了した場合は、次のように出力します。`0`。 

正しさは、考えられるすべての因数分解が行われるという事実から来ます。`x`何らかの約数として現れる`a`とそのペアの値`x / a`。 すべての小さな要素はせいぜい`sqrt(x)`、アルゴリズムはすべての可能な候補ペアをチェックします。 このアルゴリズムは、大きい因子が小さい因子の 2 倍以下であるペアを正確に受け入れます。これはまさに必要な条件です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(x):
    d = 1
    while d * d <= x:
        if x % d == 0:
            a = d
            b = x // d
            if b <= 2 * a:
                return 1
        d += 1
    return 0

def main():
    n = int(input())
    ans = []
    for _ in range(n):
        x = int(input())
        ans.append(str(solve_case(x)))
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```機能`solve_case`一つの数値を独立して扱います。 ループ変数`d`は考えられるより小さい係数を表し、条件は`d * d <= x`検索を必要な範囲に限定します。 

いつ`x % d == 0`、コードは完全な因子ペアを見つけました。 大きい方の係数は整数の除算で計算されるため、四捨五入が答えに影響を与えることはありません。 比較には、`b <= 2 * a`これにより、浮動小数点の精度の問題が回避されます。 

掛け算`d * d`の最大値なので、ここでは安全です`x`は 32768 に過ぎません。より大きな問題では、この境界チェックではよく次のように使用されます。`d <= x // d`固定サイズの整数を使用する言語での整数のオーバーフローを避けるため。

## テストケース```python
import sys
import io

def solve(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    input = sys.stdin.readline

    def solve_case(x):
        d = 1
        while d * d <= x:
            if x % d == 0:
                if x // d <= 2 * d:
                    return 1
            d += 1
        return 0

    n = int(input())
    result = []
    for _ in range(n):
        result.append(str(solve_case(int(input()))))

    print("\n".join(result))
    output = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return output

assert solve("1\n1\n") == "1\n", "minimum value"
assert solve("3\n2\n3\n32767\n") == "1\n0\n0\n", "small and maximum boundary values"
assert solve("4\n4\n9\n16\n25\n") == "1\n1\n1\n1\n", "perfect squares"
assert solve("3\n55\n77\n121\n") == "0\n0\n1\n", "prime factors and near-square cases"
