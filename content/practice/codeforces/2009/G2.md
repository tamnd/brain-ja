 ## 解決策
 ## 問題の理解

 配列が与えられています`a`サイズの`n`。 の各部分配列に対して、`a`, Yunli は、任意の要素に対して操作を実行して、任意の整数に設定できます。 目標は、少なくとも長さが連続して増加するシーケンスを形成することです。`k`そのサブ配列内で。 させて`f(b)`部分配列でこれを達成するために必要な最小操作数になります。`b`。 

各クエリは、複数のサブ配列、特にサブ配列の合計を求めます。`a[l..r]`、の合計を計算します`f([a_l..a_j])`みんなのために`j`から`l+k-1`に`r`。 この問題はそれを保証します`r >= l+k-1`、したがって、考慮されるすべてのサブ配列は少なくとも長さです`k`。 

制約により許可されるのは、`n`そして`q`それぞれの到達点へ`2*10^5`ただし、すべてのテスト ケースの合計は次のように制限されます。`2*10^5`。 これは、各サブ配列を個別に処理する素朴なソリューションを提供できないことを意味します。`O(n^2)`クエリごとの作業は実行不可能です。 線形に近いものが必要です。`O(n log n)`テストケースごとに。 

微妙な点は、連続的に増加する部分配列の定義です。 ターゲット シーケンスは元の値と正確に一致する必要はないため、基本的には最小限の操作で「拡張」できる最長の連続増加シーケンスをカウントします。 文字通り増加する実行を常にカウントするような不注意なアプローチでは、間違った答えが得られます。 

たとえば、`a = [2,3,2,1,2]`そして`k=5`、最良の連続シーケンスは次のように考えられるかもしれません。`[2,3]`しかし、最小操作ソリューションは実際に変換します。`[2,3,2,1,2]`の中へ`[0,1,2,3,4]`別のインデックスから開始します。 正しい推論を行うには、現在のシーケンスと、それを拡張するために必要な変更の数の両方を理解する必要があります。 

## アプローチ

 ブルートフォースアプローチはすべてのサブ配列に対して反復されます。`[a_l..a_j]`クエリと計算の場合`f()`直接。 計算するには`f()`1 つの部分配列に対して、長さの連続するシーケンスに対して可能なすべての開始インデックスを試すことができます。`k`変更する必要がある要素の数を数えます。 長さの部分配列の場合`m`、これは`O(m*k)`。 すべてのクエリ全体で、これは簡単に超える可能性があります`10^{10}`操作。 正しいですが、遅すぎます。 

最適なアプローチでは次のことが観察されます。`f([a_l..a_j])`は、各位置で終わる最長の連続増加サブシーケンスの長さに直接関係します。 具体的に定義すると、`dp[i]`で終わる最大の連続増加シーケンスの長さとして`i`で`a`。 それから`f([a_l..a_j])`等しい`k - length_of_max_consecutive_ending_at_j`。 これにより、各配列のプレフィックス構造を計算する問題が軽減され、各クエリに相対的に線形時間で応答できるようになります。`r-l+1`。 

最大の連続増加シーケンスのスライディング ウィンドウを維持し、次のプレフィックス合計配列を計算できます。`f()`すべてのプレフィックスの値`a`。 次に、各クエリは 2 つのプレフィックスの合計の単純な減算になります。 これは変わります`O(n^2)`クエリごとに`O(n)`前処理と`O(1)`クエリごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * k) | O(n) | 遅すぎる |
 | 最適 | O(n) 前処理 + クエリあたり O(1) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を反復処理する`a`左から右へ。 インデックスごとに`i`、計算する`dp[i]`、で終わる最大の連続増加シーケンスの長さ。`i`。 もし`a[i] == a[i-1]+1`、 セット`dp[i] = dp[i-1]+1`; さもないと`dp[i] = 1`。 これにより、要素を変更せずに構築できる最高の「ストレッチ」が得られます。 
2. 連続した長さのシーケンスを作成するために各プレフィックスに必要な操作の最小数を計算します。`k`。 これは`f_i = max(0, k - dp[i])`。 これらを配列に格納します`ops[i]`。 
3. プレフィックス合計配列を計算する`prefix[i]`のために`ops[i]`、 となることによって`prefix[i] = ops[0] + ops[1] + ... + ops[i]`。 
4. 各クエリについて`[l,r]`の合計が必要です。`f([a_l..a_j])`のために`j`から`l+k-1`に`r`。 これはまさに`prefix[r] - prefix[l+k-2]`、0 から始まるインデックス付けを想定しています。 
5. 各クエリの合計を出力します。 

**機能する理由**:`dp[i]`各位置で終了する最大連続サブシーケンスの長さを保証します。 から引く`k`長さに到達するまでの最小限の変更数を直接与えます。`k`。 プレフィックス合計により、複数のサブ配列を効率的に合計できるようになります。 最適な開始インデックスを暗黙的に考慮するため、各操作カウントは正確です。`dp[i]`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, q = map(int, input().split())
        a = list(map(int, input().split()))
        
        dp = [1]*n
        for i in range(1, n):
            if a[i] == a[i-1]+1:
                dp[i] = dp[i-1]+1
        
        ops = [max(0, k - dp[i]) for i in range(n)]
        prefix = [0]*n
        prefix[0] = ops[0]
        for i in range(1, n):
            prefix[i] = prefix[i-1]+ops[i]
        
        for _ in range(q):
            l, r = map(int, input().split())
            l -= 1
            r -= 1
            start = l + k - 2
            ans = prefix[r] - (prefix[start-1] if start > 0 else 0)
            print(ans)

solve()
```このコードは最初に、連続的に増加するサブシーケンスの長さを計算します (`dp`) を使用し、プレフィックス合計を使用してクエリを迅速に解決します。 境界条件は慎重に処理します。インデックスは 1 ベースの入力から 0 ベースの配列に調整され、開始インデックスが次の場合はプレフィックス合計の減算で処理されます。`0`。
