 ## 解決策
 ## 問題の理解

 各テスト ケースは、4 列の小さな osu!mania ビートマップを記述します。 各行には、 でマークされた 1 つのメモが正確に含まれます。`#`、残りのセルには以下が含まれます`.`。 

行は上から下の順に指定されますが、下に近いノートが最初にヒットするため、ゲームはノートを下から上に処理します。 処理順序内のすべてのノートに対して、列番号を出力する必要があります。`#`が表示されます。 

次のような行:```
..#.
```列 3 にそのメモが含まれています。 

重要な点は、入力順序と必要な出力順序が逆であるということです。 入力の最初の行は最上行ですが、出力する最初の回答は最下行に対応する必要があります。 

制約は非常に小さいです。 すべてのテスト ケースで最大 500 行があり、各行にはちょうど 4 文字が含まれます。 すべての行のすべての文字をスキャンするアルゴリズムでも、合計で約 2000 文字のチェックしか実行されません。 ここでの課題はランタイムではありません。 タスクは純粋に慎重に実装することです。 

簡単な間違いの 1 つは、行を反転するのを忘れることです。 

考慮する：```
1
3
#...
.#..
..#.
```行は上から下まで列を含みます`1, 2, 3`。 

ゲームは下から上に処理されるため、正しい出力は次のようになります。```
3 2 1
```入力順に行を出力する不用意な解決策では、次の出力が出力されます。```
1 2 3
```それは間違っています。 

もう 1 つのよくある間違いは、0 から始まるインデックスの使用です。 

例えば：```
1
1
...#
```注は 4 列目にあります。 

正しい出力は次のとおりです。```
4
```文字列の位置を直接出力するソリューションは次のように出力します。`3`。 

3 番目の微妙なケースは、複数の行の同じ列にメモがある場合です。```
1
2
.#..
.#..
```正しい出力は次のとおりです。```
2 2
```各行は個別に処理する必要があります。 列は個別である必要があるという制限はありません。 

## アプローチ

 最も直接的なアプローチは、すべての行を検査し、行の位置を見つけることです。`#`、その列番号を保存し、最後に保存された回答を逆の行順序で出力します。 

各行には 4 文字しか含まれていないため、この総当たり手法はすでに十分に高速です。 音符の位置を見つけるには、最大 4 つのセルをチェックする必要があります。 合計で最大 500 行の場合、最悪の場合の作業は約 2000 文字の検査だけです。 

制約が小さいため、高度な最適化は必要ありません。 実際の観察とは、単にメモが処理される順序を理解することです。 

入力では行が上から下に示されますが、必要な答えは下から上です。 それを認識すると、問題は各行を簡単にスキャンすることになります。 すべての行について、次の内容が含まれる列を決定します。`#`、それを保存し、後で保存された列を逆の順序で出力します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(n) | 承認済み |
 | 最適 | O(n) | O(n) | 承認済み |

 各行の長さは 4 に固定されているため、行のスキャンは事実上一定時間になります。 この問題に対してはどちらのアプローチも同じです。 

## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、行数。 
3. 空のリストを作成する`cols`これにより、各行にメモの列番号が保存されます。 
4. 各行を読み取ります。 
5. の位置を見つけます。`#`行内でそれを 1 から始まる列番号に変換します。 
6. その列番号を`cols`。 
7. すべての行が処理されたら、以下を反復して順序を逆にします。`cols`最後の要素から最初の要素まで。 
8. 逆の順序をスペースで区切って出力します。 

入力は上から下に与えられ、ノートは下から上に処理されるため、反転が必要です。 

### なぜ効果があるのか

 各行に 1 つだけ存在します`#`, したがって、そのメモの列は一意に決まります。 アルゴリズムは、入力順に行ごとにその列を記録します。 

行に上から下まで番号が付けられている場合、`1...n`の場合、処理順序は次のようになります。`n...1`。 記録されたリストを逆にすると、まさにその順序が生成されます。 すべての出力位置は正しく処理されたノートに対応するため、アルゴリズムは常に必要なシーケンスを返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    cols = []

    for _ in range(n):
        row = input().strip()
        cols.append(row.index('#') + 1)

    print(*reversed(cols))
```ソリューションはアルゴリズムに直接に従います。 

リスト`cols`各行の列番号を格納します。 パイソンの`index('#')`はメモの位置を見つけ、1 を追加すると、結果が 0 から始まるインデックス付けから必要な 1 から始まる列番号付けに変換されます。 

すべての行が読み取られた後、`reversed(cols)`下から上への処理順序が生成されます。 使用する`print(*...)`自動的に数字の間にスペースが入ります。 

最も一般的な実装エラーは、`+ 1`。 もう一つは印刷です`cols`逆にするのではなく、直接的に。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

| スペース | O(n) | 各行の列が格納されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        cols = []

        for _ in range(n):
            row = input().strip()
            cols.append(row.index('#') + 1)

        out.append(" ".join(map(str, reversed(cols))))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result

 ## 特殊なケース

 ### 上から下の順序と下から上の順序

 入力:```
1
3
#...
.#..
..#.
```アルゴリズムは以下を記録します。```
[1, 2, 3]
```次に、リストを逆にします。```
[3, 2, 1]
```そして出力:```
3 2 1
```これは、必要な処理順序と一致します。 

### 最後の列の注記

 入力:```
1
1
...#
```の位置`#`インデックスです`3`。 1 つ追加すると列が得られます`4`。 

出力：```
4
```これにより、アルゴリズムが Python の 0 から始まるインデックスから問題の 1 から始まる列の番号付けに正しく変換されることが確認されます。 

### 同じ列を使用する複数の行

 入力:```
1
2
.#..
.#..
```アルゴリズムは以下を保存します。```
[2, 2]
```逆にしてもシーケンスは変わりません。```
[2, 2]
```出力：```
2 2
```このソリューションでは列が一意であることを前提としないため、繰り返される列は自然に処理されます。
