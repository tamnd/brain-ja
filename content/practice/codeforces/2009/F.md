 ## 問題の理解

 We are given an array`a`長さの`n`そして、はるかに大きな配列に対するクエリを処理するように求められます。`b`。 この配列`b`すべてを取り入れて構築されます`n`循環シフトの`a`そしてそれらを順番に連結していきます。 巡回シフトごとに最初の要素が最後に移動するため、`i`-番目のシフトは に始まります`a[i]`そして配列の先頭に戻ります。 次に、インデックスによって定義されたクエリごとに、`l`そして`r`、部分配列の合計を計算する必要があります`b[l..r]`。 

最初の課題は規模です。 のために`n`最大 2×10^5、配列`b`持っていただろう`n^2`要素、最大 4×10^10。 明らかに建設できない`b`明示的に行うか、単純なプレフィックス合計を実行します。 クエリの数も最大 2×10^5 であるため、ソリューションは各クエリに一定時間または対数時間で応答する必要があります。そうしないと、2 秒の制限を超えてしまいます。 

すべてのシフトを連結するか、反復処理によってクエリをシミュレートする単純なアプローチ`b`実現不可能です。 エッジケースには非常に小さなケースが含まれます`n`、`n = 1`、および複数の完全コピーにまたがるクエリ`a`内部`b`。 もう 1 つの微妙な点は、クエリで次のセグメント内の任意のセグメントを要求できることです。`b`, potentially covering multiple repetitions of elements, so modular arithmetic over indices is required.

 たとえば、次の場合`a = [1,2,3]`、 それから`b`は`[1,2,3,2,3,1,3,1,2]`。 からの問い合わせ`l=3`に`r=5`要素をまたがる`[3,2,3]`。 A naive solution that iterates would compute`3+2+3=8`ですが、これよりもはるかに大きい配列に対してこれを行うメソッドが必要です。`b`記憶に収まります。 

## アプローチ

 The brute-force approach is to actually construct`b`そしてプレフィックスの合計を計算します。 これは小規模な場合に機能します`n`、 しかし`b`もっている`n^2`要素が含まれるため、メモリは O(n^2)、クエリ時間は O(q * n) になります。 最悪の場合に備えて、`n = 2×10^5`、何兆もの演算が必要となるため、これは完全に不可能です。 

重要な洞察は構造を認識することから得られます。 各要素`a[i]`正確に表示されます`n`回`b`、各シフトに 1 回ですが、異なるポジションで行われます。 連結全体の各要素のパターンに注目すると、範囲を 3 つの部分に分けることで、範囲の合計を求めることができます。最初に部分的にカバーされた繰り返しの接頭辞、完全な繰り返し。`a`、および最後の部分的にカバーされた繰り返しの接尾辞。 

プレフィックス合計配列を計算すると`pref`のために`a`それ自体とその合計`a`の任意の位置をマッピングできます。`b`の対応する要素に`a`モジュラー演算を使用します。 各クエリは、端の部分コピーと中央の完全なコピーからの寄与に分割できます。 これにより、事前に計算された合計を使用して、クエリ処理がクエリあたり O(1) に削減されます。

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`q`、次に配列`a`。 
2. プレフィックス合計配列を計算します。`pref`のために`a`、 どこ`pref[i]`最初の合計です`i`の要素`a`。 これにより、任意の連続した部分配列の合計を迅速に計算できます。`a`。 
3. 合計を計算します`total`の`a`として`pref[n]`。 
4. 各クエリについて`(l, r)`、1 から始まる位置を変換します`l`そして`r`で`b`モジュラー演算を容易にするために 0 ベースに変更します。 どの繰り返しを決定するか`a`ポジションは次のとおりです。 

- 開始繰り返しを次のように計算します。`l // n`内でオフセット`a`として`l % n`。 
- 最後の繰り返しを次のように計算します。`r // n`内でオフセット`a`として`r % n`。 
5. クエリが 1 回の繰り返し内に完全に含まれる場合、`a`、単純にプレフィックスの合計の差を取得します。`pref[r_offset + 1] - pref[l_offset]`。 
6. それ以外の場合は、最初の繰り返しで部分的なプレフィックスを合計し、その間の完全な繰り返しを合計します（`total`完全な繰り返しの数を掛けた値)、および最後の繰り返しの部分的な接尾辞。 これらを組み合わせてクエリ結果を取得します。 

不変条件は、配列であることです。`b`のグリッドとして考えることができます`n`の列`a`、任意のセグメントにわたる合計は、行に揃えられた合計とオフセットに分解できます。 モジュラー演算により、常に正しい要素にアクセスできるようになります。`a`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]
    total = pref[n]
    
    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1  # 0-based indexing
        r -= 1
        
        l_block, l_offset = divmod(l, n)
        r_block, r_offset = divmod(r, n)
        
        if l_block == r_block:
            ans = pref[r_offset + 1] - pref[l_offset]
        else:
            ans = (pref[n] - pref[l_offset])  # prefix in first block
            ans += (r_block - l_block - 1) * total  # full blocks in between
            ans += pref[r_offset + 1]  # suffix in last block
        print(ans)
```プレフィックス合計配列`pref`の任意の部分配列に対する O(1) 合計クエリを保証します。`a`。 各クエリの開始と終了で部分ブロックを処理することで、正確性が保証されます。 私たちが使用するのは`divmod`ブロックインデックスとブロック内のオフセットの両方を素早く取得します。 から 1 を引く`l`そして`r`0 から始まるインデックスに変換されます。
