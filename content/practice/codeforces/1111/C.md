 ## 解決策
 ## 問題の理解

 長さの線形基底が与えられています$2^n$, 一部のポジションにはアベンジャーズが含まれています。 サノスは最小限の力で基地全体を破壊したいと考えています。 彼には、ベースのどの部分に対しても 2 つの選択肢があります。それを直接燃やすか、2 つの等しい半分に分割してそれぞれを別々に処理するかのいずれかです。 セグメントを書き込むコストは、アベンジャーが存在するかどうかによって異なります。アベンジャーが存在しない場合は、固定金額がかかります$A$; あれば$n_a$アベンジャーズ、それは費用がかかります$B \cdot n_a \cdot l$、 どこ$l$セグメントの長さです。 

入力は長さの指数を与えます$n$、アベンジャーズの数$k$、定数$A$そして$B$、そしてアベンジャーズの立場。 出力は単一の整数です。サノスが基地を破壊するために必要な最小総パワーです。 

制約$n \le 30$基底長が$2^n$おおよそまで可能です$10^9$。 これにより、すべての位置を反復するアルゴリズムが除外されます。 しかし、$k \le 10^5$つまり、復讐者の位置だけを効率的に処理できるということです。 

明白ではないエッジ ケースとしては、アベンジャーのないセグメント (分割よりも書き込みの方がコストが低い場合) や、単一のアベンジャーを持つセグメント (半分が空になる可能性があるため分割の意味がなくなる可能性がある) などがあります。 すべての位置を反復処理する不注意なソリューションはクラッシュする可能性があります。$n = 30$一方、空のセグメントを無視すると、コストが過大評価される可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、考えられるすべてのセグメント分割が再帰的に考慮され、各ステップでの書き込みと分割のコストが計算されます。 これは概念的には正しいですが、ベース全体を反復処理することで単純に実装すると、長さが長さに達する可能性があるため実用的ではありません。$10^9$。 すべての整数の位置をチェックする再帰的アプローチですら遅すぎます。 

重要な洞察は、アベンジャーを含むセグメントのみを追跡する必要があるということです。 アベンジャーのポジションを並べ替えると、どのセグメントでも$[l, r]$二分探索を使用して、その中にいるアベンジャーの数を計算できます。 これにより、空のポジションを繰り返すことを回避し、書き込みコストを即座に評価できるようになります。 

分割統治戦略を実装できます。セグメントに対して、それを直接書き込むコストを計算し、次にそれを 2 つの半分に分割するコストを再帰的に計算します。 これら 2 つの最小値が、そのセグメントの最適なコストになります。 これにより、複雑さが軽減されます。$O(k \log L)$、 どこ$L = 2^n$、これは効率的です$k \le 10^5$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | お(1) | n > 20 では遅すぎます |
 | 最適 | O(k log L) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力値の読み取り$n, k, A, B$そして復讐者の役職のリスト。 
2. 復讐者の位置を並べ替えます。 これにより、任意のセグメント内のアベンジャーの数に対する高速範囲クエリが可能になります。 
3. 再帰関数を定義する`min_power(l, r)`セグメントを破壊するための最小電力を表します$[l, r]$。 
4. で`min_power(l, r)`、二分探索を使用してアベンジャーの数を数えます$num$で$[l, r]$。 もし$num = 0$、 戻る$A$空のセグメントを書き込む方が、分割するよりもコストがかからないためです。 
5. 直接燃焼コストを次のように計算します。$B \cdot num \cdot (r-l+1)$。 
6. もし$l = r$または$num = 0$、セグメントをそれ以上分割できないため、書き込みコストを返します。 
7. それ以外の場合は、中点を計算します$m = (l + r) // 2$そして、左の最小パワーを再帰的に計算します。$[l, m]$そして正しい$[m+1, r]$。 直接書き込みコストと再帰コストの合計の最小値を返します。 
8. 電話をかける`min_power(1, 2^n)`そして結果を印刷します。 

機能する理由: すべてのセグメントで、アルゴリズムは直接書き込みまたは分割のうち最も安価な方法を選択します。 帰納法により、再帰呼び出しが常にサブセグメントの最適コストを返す場合、その組み合わせによりグローバル最小値が生成されます。 アベンジャーの位置を並べ替えることで、あらゆるセグメントの数を効率的かつ正確に数えることができます。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

n, k, A, B = map(int, input().split())
positions = list(map(int, input().split()))
positions.sort()

def min_power(l, r):
    left_idx = bisect.bisect_left(positions, l)
    right_idx = bisect.bisect_right(positions, r)
    num = right_idx - left_idx
    
    if num == 0:
        return A
    burn_cost = B * num * (r - l + 1)
    if l == r:
        return burn_cost
    m = (l + r) // 2
    split_cost = min_power(l, m) + min_power(m+1, r)
    return min(burn_cost, split_cost)

total_power = min_power(1, 2**n)
print(total_power)
```コードは、効率的にカウントするために、まずアベンジャーの位置を並べ替えます。 の`min_power`関数は、次を使用してセグメント内のアベンジャーの数を計算します。`bisect`。 空のセグメントの場合は、次の値が返されます。$A$。 アベンジャーズの単一のポジションまたはセグメントについては、バーン コストとスプリット コストの両方が計算されます。 再帰により、常に最小値が見つかることが保証されます。

 ## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k log L) | 各再帰呼び出しは、k 要素の二分探索を介してアベンジャーをカウントします。 再帰の深さは log L です。 
| スペース | O(k + log L) | アベンジャーズの並べ替えには O(k) を使用します。 再帰スタックの深さは O(log L) です。 |

 と$k \le 10^5$そして$n \le 30$、合計操作は 1 秒以内に管理できます。 メモリ使用量は最小限です。
