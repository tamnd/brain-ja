 ## 解決策
 ## 問題の理解

 穴の列が与えられ、各穴にはちょうど 1 人の悪役が含まれており、各悪役にはキャラクターによって表されるタイプがあります。 コロニーを表す文字列は均等な長さであるため、自然に 2 つの半分に分割できます。 アイアンマンは、特定のタイプのすべての悪役がコロニーの半分に完全に住んでいる場合にのみ、コロニーを破壊したいと考えています。 ジャービスは2人の悪役を自由に交換できます。 

クエリごとに 2 つのインデックスが与えられます。$x$そして$y$。 ポジションにある悪役のタイプが異なるような、任意の交換によって達成できる個別の配置の数を数えなければなりません。$x$そして$y$(ひいては、これらのタイプの悪役もすべて) 完全にコロニーの半分にいます。 答えはモジュロで報告する必要があります$10^9+7$。 

制約は、最大で次のものを持つことができることを示唆しています$10^5$悪役と$10^5$クエリ。 コロニーの半分のすべての順列を列挙する単純なアプローチは階乗時間であり、不可能です。 これは、次の条件で機能する組み合わせソリューションが必要であることを意味します。$O(n + q)$または$O(n \log n + q)$事前に計算された階乗と頻度カウントを使用します。 

明らかではないエッジケースには、悪役タイプがコロニーの半分よりも多く出現し、それらをすべて半分に配置することが不可能になるシナリオが含まれます。 たとえば、コロニー「aaabbb」と悪役「a」に関するクエリの場合、3 つの「a」はサイズ 3 の半分に収まらず、それを超えないため、有効な配置はありません。 不用意に実装すると、組み合わせ式をやみくもに試行し、ゼロ以外の値が返される可能性があり、これは正しくありません。 

## アプローチ

 ブルートフォース手法では、文字列のすべての個別の順列を列挙し、クエリされた型の半分分割プロパティを満たすものを確認して、それらをカウントします。 これには必要です$O(n!)$クエリごとの操作。これは実行不可能です。$n$まで$10^5$。 

重要な洞察は、問題が組み合わせ計数問題に帰着するということです。つまり、各悪役タイプが完全に半分を占めなければなりません。 Jarvis の無制限のスワップにより、クエリからの型制約を除き、正確な初期位置を無視できます。 各タイプの頻度と半分のサイズだけが必要です$n/2$。 各クエリについて、クエリされた 2 つの型の数を確認し、両方が完全に半分に収まるように、それらを半分に割り当てる方法が何通りあるかを計算します。 

階乗とモジュラー逆関数を事前計算して、組み合わせをすばやく計算します。 半分のサイズの場合$h = n/2$、タイプが発生した場合$k$の場合は左半分に配置できます。$\binom{h}{k}$方法。 複数の種類がある場合は、左半分と右半分を考慮して種類ごとに組み合わせを掛け合わせます。 対称的な配置を二重にカウントしないように注意する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * q) | お(ん!) | 遅すぎる |
 | 事前計算された階乗による組み合わせ | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コロニー全体における各悪役タイプの頻度を計算します。 これにより、半分に各タイプを何個配置する必要があるかがわかります。 
2. 階乗とモジュラー逆関数を最大で事前計算します。$n$高速な組み合わせモジュロ計算用$10^9+7$。 これにより計算が可能になります$\binom{n}{k}$一定時間内に。 
3. クエリごとに、位置にある悪役のタイプを抽出します$x$そして$y$。 それらの周波数を$f_x$そして$f_y$。 
4. どちらかの場合$f_x > n/2$または$f_y > n/2$, そのタイプの悪役をすべて半分に配置することは不可能なので、答えは 0 です。 
5. それ以外の場合は、両方のタイプを半分に割り当てる方法の数を計算します。 両方のタイプが左半分に移動する、両方のタイプが右半分に移動する、またはそれぞれが別々の半分に移動する、の 3 つのケースがあります。 組み合わせを使用して方法の数を計算します。$\text{ways\_left} = \binom{n/2}{f_x} \cdot \binom{n/2 - f_x}{f_y}$

$\text{ways\_right} = \binom{n/2}{f_y} \cdot \binom{n/2 - f_y}{f_x}$6. 有効な取り決めをモジュロで合計します。$10^9+7$。 
7. 各クエリの結果を返します。 

**それが機能する理由**: 不変条件は、各悪役のタイプが半分の範囲内に完全に収まる必要があるということです。 周波数と組み合わせ配置を使用することで、すべての異なる配置を生成せずにキャプチャします。 階乗を事前に計算することで高速な計算が保証され、ケースを左半分と右半分に分けることで正確性が保証され、過剰カウントが回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**9 + 7

# Precompute factorials and inverse factorials
def precompute_factorials(n, MOD):
    fac = [1] * (n + 1)
    ifac = [1] * (n + 1)
    for i in range(1, n + 1):
        fac[i] = fac[i - 1] * i % MOD
    ifac[n] = pow(fac[n], MOD - 2, MOD)
    for i in range(n - 1, 0, -1):
        ifac[i] = ifac[i + 1] * (i + 1) % MOD
    return fac, ifac

def comb(n, k, fac, ifac):
    if k < 0 or k > n:
        return 0
    return fac[n] * ifac[k] % MOD * ifac[n - k] % MOD

def main():
    s = input().strip()
    n = len(s)
    h = n // 2
    q = int(input())
    
    # frequency of each type
    freq = {}
    for c in s:
        freq[c] = freq.get(c, 0) + 1
    
    fac, ifac = precompute_factorials(h, MOD)
    
    for _ in range(q):
        x, y = map(int, input().split())
        tx, ty = s[x - 1], s[y - 1]
        fx, fy = freq[tx], freq[ty]
        
        if fx > h or fy > h:
            print(0)
            continue
        
        if tx == ty:
            print(2 * comb(h, fx, fac, ifac) % MOD)
        else:
            ways = comb(h, fx, fac, ifac) * comb(h - fx, fy, fac, ifac) % MOD
            ways += comb(h, fy, fac, ifac) * comb(h - fy, fx, fac, ifac) % MOD
            print(ways % MOD)

if __name__ == "__main__":
    main()
```**実装メモ**: 階乗を最大半分まで事前計算します。$n$なぜなら、どのタイプもそれを超えることはできないからです。 両方のクエリ インデックスが同じ型を個別に参照する特殊なケースを処理し、組み合わせ数を 2 倍にします。 モジュラー演算により、整数のオーバーフローが防止されます。 クエリではインデックス付けは 1 から始まるため、文字列にアクセスするときに調整されます。
