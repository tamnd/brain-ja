 **タグ:** 実装、文字列

 ## 解決策
 ## 問題の理解

 スーパーヒーロー名を表す 2 つの小文字の文字列が与えられています。 すべての母音を他の母音に変更でき、すべての子音を他の子音に変更できる場合、変換が許可されます。 

実際の文字は関係ありません。 重要なのは、各位置に母音が含まれるか子音が含まれるかということです。 例えば、`'a'`なることができる`'u'`どちらも母音なので、`'b'`なることができる`'z'`どちらも子音なので。 母音が子音になることはありませんし、子音が母音になることはありません。 

タスクは、これらのルールを使用して名前を 2 番目の名前に変換できるかどうかを判断することです。 

文字列の長さは最大でも 1000 であり、非常に小さいです。 文字列を数回スキャンするアルゴリズムでも、十分に高速になります。 重要なのは、変換条件を正しく実装することだけです。 

重要な点は、文字を変更しても文字列の長さは決して変わらないということです。 すべての操作で、ある文字が同じカテゴリの別の文字に置き換えられます。 2 つの名前の長さが異なる場合、答えは即座に「いいえ」になります。 

見落としやすいエッジケースがいくつかあります。 

考慮する：```
a
bb
```正しい答えは次のとおりです。```
No
```母音と子音の数を比較するだけの不注意な解決策は、誤って受け入れられる可能性があります。 長さが等しいことは必須です。 

考慮する：```
ab
cd
```正しい答えは次のとおりです。```
No
```最初の位置は母音と子音です。 どちらの文字列にも全体として 1 つの母音と 1 つの子音が含まれていますが、位置が重要です。 

考慮する：```
ae
io
```正しい答えは次のとおりです。```
Yes
```文字は異なりますが、すべての位置は母音と母音です。 

考慮する：```
code
java
```正しい答えは次のとおりです。```
No
```一部の位置では、一方の文字列には子音が含まれ、もう一方の文字列には母音が含まれます。 

## アプローチ

 この問題を考える強引な方法は、各文字を他の文字列の対応する文字に変更できるかどうかをシミュレートすることです。 すべての位置について、ソース文字とターゲット文字が同じカテゴリに属する​​かどうかを尋ねることができます。 このルールに違反するポジションがある場合、変身することはできません。 

各文字列には最大 1000 文字が含まれるため、すべての位置を直接チェックするには 1000 回の比較のみが必要です。 それはすでに十分に速いです。 

重要な洞察は、手紙の実際の身元は決して重要ではないということです。 変換ルールにより、任意の母音を任意の母音にし、任意の子音を任意の子音にすることができます。 これは、すべての文字を 1 ビットの情報 (母音または子音) に還元できることを意味します。 

この観察の後、問題は非常に単純になります。 まず、長さが等しいことを確認します。 次に、両方の文字列を位置ごとにスキャンします。 各インデックスで、両方の文字が母音であるか、両方とも子音であるかを確認します。 そうでない場合、変換は不可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 この問題では、入力サイズが小さく、すべての文字を少なくとも 1 回検査する必要があるため、自然な総当たりアプローチがすでに最適です。 

## アルゴリズムのチュートリアル

 1. 2 つの文字列を読み取ります。 
2. 長さが異なる場合は出力`"No"`そしてやめてください。 

変換は文字を置き換えるだけです。 文字を挿入したり削除したりすることはありません。 
3. 母音を含むセットを作成する`{a, e, i, o, u}`。 
4. 文字列のすべての位置を反復処理します。 
5. 各位置について、最初の文字列の文字が母音であるかどうか、および 2 番目の文字列の文字が母音であるかどうかを判断します。 
6. 一方の文字が母音で、もう一方の文字が子音の場合、出力`"No"`そしてやめてください。 

このような位置は、許可されている操作では決して変換できません。 
7. 不一致が見つからずにスキャン全体が終了した場合、出力`"Yes"`。 

### なぜ効果があるのか

 変換は、すべての位置を独立して変換できる場合にのみ有効です。 

どの位置でも、母音か子音の 2 つの可能性のみがあります。 母音は任意の母音になることができ、子音は任意の子音になることができます。 したがって、両方の文字が同じカテゴリに属している場合にのみ、位置は変換可能です。 

文字列の長さが異なる場合、一連の置換を行っても文字列を等しくすることはできません。 長さが等しく、すべての位置に一致するカテゴリがある場合、各位置で適切な置換を選択して、ターゲット文字列を取得できます。 これらの条件は必要かつ十分であるため、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
t = input().strip()

if len(s) != len(t):
    print("No")
    sys.exit()

vowels = set("aeiou")

for a, b in zip(s, t):
    if (a in vowels) != (b in vowels):
        print("No")
        break
else:
    print("Yes")
```最初のチェックでは、長さが一致する必要があるという唯一のグローバル制限が処理されます。 

の`vowels`set を使用すると、定数時間のメンバーシップ チェックが可能になります。 文字のペアごとに、式は```
(a in vowels) != (b in vowels)
```は、一方の文字が母音で、もう一方の文字が子音の場合にのみ真となります。 そのような位置が見つかるとすぐに、答えは次のようになります。`"No"`。 

の`for-else`ここではconstructが便利です。 の`else`ブロックは、ループが終了することなく終了した場合にのみ実行されます。`break`、すべてのポジションが必要な条件を満たしたことを意味します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    s = input().strip()
    t = input().strip()

    if len(s) != len(t):
        print("No")
        return

    vowels = set("aeiou")

    for a, b in zip(s, t):
        if (a in vowels) != (b in vowels):
            print("No")
            return

    print("Yes")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("a\nu\n") == "Yes", "sample 1"

# custom cases
assert run("a\nb\n") == "No", "vowel versus consonant"
assert run("ab\ncd\n") == "No", "position mismatch"
assert run("aeiou\nuoiea\n") == "Yes", "all vowels"
assert run("b\nz\n") == "Yes", "single consonants"
assert run(("a" * 1000) + "\n" + ("e" * 1000) + "\n") == "Yes", "maximum length"
assert run("abc\nab\n") == "No", "different lengths"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`a / b`|`No`| 母音は子音になれません |
