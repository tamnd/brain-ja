 ## 解決策
 ## 問題の理解

 私たちにはスーパーヒーローのグループが与えられており、それぞれが初期パワー値を持っています。 このグループは 2 種類の操作を使用して変更できます。グループからスーパーヒーローを 1 つ削除するか (少なくとも 2 つが残っている限り)、選択したスーパーヒーローのパワーを 1 つ増やすことができます。 操作の総数にはグローバル制限があり、単一のスーパーヒーローは限られた回数しか増加できないという追加の制約があります。 

目標は、許可された操作を適用した後、平均パワーが可能な限り大きい、空ではないスーパーヒーローのサブセットで終了することです。 

出力は、達成可能な最大平均を表す単一の実数です。 

制約は、次のことを即座に示唆します。$O(n^2)$あるいは、さらに悪いことに、すべてのサブセットにわたるシミュレーションは不可能です。$n$までです$10^5$。 すべてのサブセットを試行したり、削除後に平均を繰り返し再計算したりするアプローチは、タイムアウトになります。 平$O(n \cdot m)$以来実行不可能です$m$まで可能です$10^7$。 

主な難点は、両方の操作が相互作用することです。要素を削除すると分母が減り、値を増やすと分子が向上しますが、増分は要素ごとに上限があり、グローバルに制限されます。 

いくつかの特殊なケースでは、よくある間違いが明らかになります。 すべての要素が等しい場合、次のようにします。$n=3, a=[5,5,5]$多くの操作がある場合、削除すると比率が改善されずに分母が減るため、最良の戦略はすべての要素を保持し、増分を分散することです。 単純に貪欲な削除を行うと、要素が誤って破棄され、平均が人為的に膨らむ可能性があります。 

もう 1 つの特殊なケースは、1 つの要素が他の要素と比べて極端に大きい場合です。 例えば、$a=[1,1,1000]$。 最適なソリューションでは、おそらく最大の要素のみを保持し、それに増分を投資します。 ほとんどの要素を維持する必要があると想定する戦略は、ここでは失敗します。 

最後の微妙なケースは、操作バジェットが大きいものの、要素ごとの上限が設定されている場合に発生します。$k$制限的です。 たとえ$m$が大きい場合、すべての増分を 1 つの要素にダンプすることはできません。 選択した要素全体にそれらを分散するか、要素を削除すると投資できる額が変わることを受け入れる必要があります。 

## アプローチ

 ブルート フォース ビューでは、スーパーヒーローの可能なすべてのサブセットを試し、最大で$m$要素ごとの上限を考慮して、要素全体で増分します。$k$。 サブセットごとに要素を並べ替え、最大のゲインに貪欲に増分を適用します。 分布の複雑さを無視しても、サブセットだけを列挙するのは困難です。$O(2^n)$、それは不可能です$n=10^5$。 ソート後にプレフィックスのサブセットに制限しても、最大で次のシミュレーションが必要になります。$m$動作が遅すぎます。 

重要な観察は、決定を分離できるということです。まず、サイズのサブセットを固定するとします。$x$。 そのサブセット内では、常に最初に最大の要素に増分を適用します。各増分は合計に等しく寄与しますが、すでに大きな値に適用すると平均が最も向上します。 各要素は最大までしか増加できないため、$k$回、固定サブセット内の使用可能な増分の合計数は次の制限を受けます。$x \cdot k$。 ただし、次のような制限もあります。$m$、したがって、使用可能な増分の合計は次のようになります。$\min(m, xk)$。 

ここで問題は、サブセット サイズの選択です。$x$、最善のものを取る$x$要素を配置し、最大で配布します$\min(m, xk)$その中で増加します。 増分は常にサブセット内の最大の要素に行われるため、固定サイズの最適なサブセット$x$単に$x$最大の初期値。 

これにより、配列をソートし、すべてのサフィックス (または規則によってはプレフィックス) をチェックし、プレフィックスの合計を維持し、適用できる増分数をシミュレートするという問題が軽減されます。 候補サブセット サイズごとに、結果の平均を効率的に計算します。 

最後の最適化では、最大の要素から下方向にサブセットを検討します。これは、小さな要素を削除すると、最適な増分割り当ての後でのみ平均を改善または維持できるためです。

 ## アルゴリズムのチュートリアル

 1. 配列を非降順で並べ替えます。 これにより、サブセットを保持することを検討するとき、最良の候補が常に最大の要素になることが保証されます。 
2. 選択したサブセットを表す接尾辞の合計を迅速に計算できるように、ソートされた配列の接頭辞の合計を事前計算します。 
3. 可能なサブセット サイズを反復処理する$x$1から$n$、サブセットは次のもので構成されます。$x$最大の要素。 
4. サブセットサイズごとに$x$、適用できる合計増分数を計算します。これは次のとおりです。$\min(m, x \cdot k)$。 これは、サブセット レベルで結合されたグローバル制限と要素ごとの制限の両方を表します。 
5. 最も利益を得る要素を常に増やすことによって、これらの増分を最適に分配します。これは、固定ソートされたサブセットでは、最大の要素が最初に増分を受け取ることを意味します。 すべての増分は合計に +1 を加算するため、配分は総和には影響せず、実現可能性のみに影響を与えるため、合計の追加値は正確に増分の数になります。 
6. サブセットサイズの総電力を計算します$x$選択した要素と合計増分の合計として。 
7. 総電力を次の値で割って平均を計算します。$x$、全体にわたって最大値を追跡します$x$。 

### なぜ効果があるのか

 固定サブセット内では、どの要素が増分を受け取るかに関係なく、増分は常に合計に +1 寄与します。 唯一の制限は、要素ごとの上限による実現可能性です。$k$、合計増分が最大で に制限されます。$xk$。 要素の削除は分母を減らすだけであり、要素あたりの利用可能な増分容量を増やすことはないため、最適なソリューションは、あるサブセット サイズに対応する必要があります。$x$、そのサブセット内では、増分のすべての割り当ては、合計の寄与という点で交換可能です。 これにより、ソートされたプレフィックスの選択に対して単純な 1 次元関数を最大化するという問題が解決されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + a[i]
    
    ans = 0.0
    
    for x in range(1, n + 1):
        base_sum = prefix[n] - prefix[n - x]
        increments = min(m, x * k)
        total = base_sum + increments
        avg = total / x
        if avg > ans:
            ans = avg
    
    print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```解決策は、サイズの最適なサブセットが得られるように配列をソートすることから始まります。$x$から構成されていると仮定できます$x$最大の要素。 プレフィックス合計配列を使用すると、そのようなサブセット合計を定数時間で取得できます。 

サブセット サイズごとに、適用できる増分数を計算します。 表現`x * k`要素ごとの上限を強制しますが、`m`グローバル上限を強制します。 これら 2 つの最小値によって、使用可能な増分が決まります。 

増分ごとに合計合計が 1 だけ増加するため、増分の数をサブセットの合計に直接加算します。 平均が計算され、すべてのサブセット サイズにわたって比較されます。 

微妙な点は、要素を動的に削除するシミュレーションを決して行っていないことです。 代わりに、サブセット サイズを選択し、それを直接評価するという問題を再解釈します。 これにより、コストのかかる状態遷移が回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, k, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    a.sort()
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = prefix[i] + a[i]
    
    ans = 0.0
    for x in range(1, n + 1):
        base = prefix[n] - prefix[n - x]
        inc = min(m, x * k)
        ans = max(ans, (base + inc) / x)
    
    return str(ans)

 ## 特殊なケース

 エッジケースの 1 つは、すべての要素が同一である場合です。 このアルゴリズムはすべてのサブセット サイズを評価し、より多くの要素を保持すると、削除が許容する範囲を超えて要素ごとのゲインを増加させることなく、分母が増加することがわかります。 計算された最大値は、増分が十分に活用されている最大の有効なサブセットから正しく取得されます。 

もう 1 つの特殊なケースは、単一要素の配列です。 アルゴリズムは評価のみを行います$x=1$、まで適用されます$\min(m,k)$増分し、サブセットを考慮せずに正しいインフレート値を返します。 

3 番目のエッジケースは次のような場合です。$m$非常に小さいです。 このアルゴリズムは増分をグローバルに正しく制限するため、大きなサブセットであっても増分を過剰に割り当てず、平均の過大評価を防ぎます。
