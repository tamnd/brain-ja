 ## 解決策
 ## 問題の理解

 同じ長さの 3 つの文字列が与えられ、それぞれが 3 人のプレーヤーのうちの 1 人が所有するリボンを表します。 プレイヤーは 1 回の操作で、文字列内の 1 文字だけを別の文字に変更できます。 それらはすべて同じ移動数を取得し、目標は、すべての変更後の文字列の「美しさ」と呼ばれる量を最大化することです。 

文字列の美しさは、その文字列内の連続する部分文字列の最大出現数として定義されます。 たとえば、文字列が完全に同じ文字で構成されている場合、単一文字の部分文字列がすべての位置に出現するため、その出現数は文字列の長さと等しくなります。これがその美しさでもあります。 

重要な観察は、均一な文字列は繰り返される部分文字列を最大化するため、このゲームは各文字列を均一な文字列にどれだけ近づけることができるかということだけを目的としているということです。 

入力は、単一の整数 n、プレーヤーごとに許可される単一文字の変更の数、およびその後に続く 3 つの文字列で構成されます。 正確に n 回ずつ移動した後で、どのプレイヤーが可能な限り最高の最終的な美しさを達成できるかを判断する必要があります。 

制約は重要です。n は 10^9 まで大きくできますが、各文字列の長さは最大 10^5 です。 これは、変換を段階的にシミュレートできないことを直ちに意味します。 いかなる解決策も、文字列の不一致のカウントまたは構造的特性のみに依存する必要があります。 

n が文字列の長さに比べて非常に大きい場合、微妙なエッジ ケースが発生します。 その場合、プレイヤーはすべての文字を自由に上書きできるため、すべての文字列が同一になる可能性があります。 たとえば、文字列の長さが 5 で、n が 10 の場合、プレイヤーはすべての位置を同じ文字に変更して、最終的な美しさを 5 にすることができます。 

もう 1 つの重要なケースは、n が小さい場合です。 その場合、部分的な変更のみが可能となり、最適な戦略は、選択したターゲット文字に変換できる文字の数によって制限されます。 

単純なアプローチでは、変更をシミュレートしたり、変更のたびに部分文字列構造を調査したりする可能性がありますが、時間制限と可能な変換の指数関数的な数の両方により失敗します。 

## アプローチ

 単純化の中心は、達成可能な最高の美しさは常に、弦を可能な限り均一にすることからもたらされるということを認識することです。 

文字列全体が 1 つの文字 (たとえば「a」) で構成される場合、「a」で構成されるすべての部分文字列が最大限に繰り返されます。 実際、すべての位置が同じサブリボンの繰り返しの発生に寄与するため、美しさはまさに文字列の長さになります。 

そこで本当の疑問は、最大 n 個の変更を使用して、何文字を 1 つの繰り返し文字に変換できるかということです。 

固定ターゲット文字の場合、文字列をその文字すべてに変換するコストは、その文字と等しくない位置の数になります。 最適なターゲット キャラクターを選択すると、このコストは最小限に抑えられます。 最小コストがn以下であれば、弦全体が均一になり、全長と同等の美しさが得られます。 

文字列を完全に均質化するのに十分な操作が存在しない場合、最良の戦略は、単一文字の頻度を最大化することです。 それぞれの変更により、1 つの不一致文字が主要な文字に変換される可能性があるため、最終的な最大頻度は、初期の最大頻度に n を加えたものになり、文字列の長さによって制限されます。 

これにより、各プレイヤーにとって非常に明確な公式が得られます。 

元の文字列内の任意の文字の最大頻度を計算し、n を追加しますが、文字列の長さを超えないようにします。 

これは、各操作で選択した 1 つのキャラクターのカウントを 1 つずつ増やすことができ、複数のキャラクターに労力を分割するメリットがないため、最適です。 

最後に、3 つの文字列の結果の値を比較し、勝者を選択します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 編集と部分文字列のブルート フォース シミュレーション | 指数 | 高 | 遅すぎる |
 | 頻度をカウントし、貪欲な最大化を適用する | O(L) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各文字列について、すべての文字の頻度を計算します。 

これにより、潜在的なターゲット文字にすでに一致する位置の数が取得されます。 
2. 文字列内の最大頻度値を特定します。 

最も一般的な文字をターゲットとして選択する場合、これが最適な開始点となります。 
3. n 回の操作後に達成可能な最大周波数を次のように計算します。 

min(文字列の長さ、max_frequency + n)。 

各操作で 1 つの非ターゲット文字をターゲット文字に変換し、カウントを 1 つ増やします。 
4. 3 人のプレーヤー全員に対して同じ計算を繰り返します。 
5. 結果の値を比較し、最も高い値を決定します。 
6. どちらかのプレイヤーが厳密にそれよりも大きな価値を持っている場合、そのプレイヤーが勝ちます。 それ以外の場合、結果は引き分けです。 

n を追加する理由は、文字列全体が均一になるまで、移動するたびに選択した均一ブロックのサイズが 1 つだけ増加する可能性があるということです。 

### なぜ効果があるのか

 不変条件は、各操作で 1 つの不一致位置のみをその文字に反転できるため、k 回の操作の後、選択された文字は最大でもoriginal_count + k 回出現できるということです。 どの操作も同時に 2 つのポジションを増やしたり、一度に複数のキャラクターに利益をもたらしたりすることはできません。 したがって、最適な戦略は常に 1 つのキャラクターにコミットし、その頻度を最大化することです。 最大の周波数を達成する配置は、繰り返される部分文字列を最大化することに対応するため、これは美しさを直接決定します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    t = input().strip()
    u = input().strip()

    def best(s):
        freq = [0] * 128
        for ch in s:
            freq[ord(ch)] += 1
        mx = max(freq)
        return min(len(s), mx + n)

    ks = best(s)
    sh = best(t)
    kt = best(u)

    res = max(ks, sh, kt)

    cnt = 0
    if ks == res:
        cnt += 1
    if sh == res:
        cnt += 1
    if kt == res:
        cnt += 1

    if cnt > 1:
        print("Draw")
    elif ks == res:
        print("Kuro")
    elif sh == res:
        print("Shiro")
    else:
        print("Katie")

if __name__ == "__main__":
    solve()
```このソリューションは、文字列ごとに文字頻度を 1 回計算し、n 回の操作で単一文字の達成可能な最良の優位性を評価します。 長さの最小値により、完全な均質化を超えないことが保証されます。 

比較ロジックは、明示的に同点を追跡して、複数のプレーヤーが同じ最大値を達成したかどうかを判断します。

 ## 特殊なケース

 エッジ ケースの 1 つは、3 つの文字列がすべてすでに同一である場合です。 この状況では、各プレーヤーの最大周波数は全長に等しい同一であり、上限があるため n を追加しても何も起こりません。 アルゴリズムは同等の結果を生成し、正しく引き分けを宣言します。 

もう 1 つのエッジ ケースは、n がゼロの場合です。 結果は初期の最大文字周波数に完全に依存するため、解決策は変換コンポーネントを含まない純粋な周波数比較になります。 

3 番目のケースは、n が選択した文字に対する不一致の数を超える場合に発生します。 たとえば、「abac」のような文字列で「a」を選択した場合、完全に均一にするために必要な操作は 2 つだけです。 追加の操作は全長を超えて改善することはできず、式の上限により過剰カウントが防止されます。
