 ## 問題の理解

 ツリーが与えられます。これは、任意の 2 つの町の間に 1 つの単純なパスを含む接続されたグラフを意味します。 異なる町の順序付けられたペアごとに、その固有の道をたどるウォーキング ルートが定義されます。 

すべての考えられる順序付きの町のペアの中には、無効とみなされるものもあります。 この制限は、と呼ばれる 2 つの特別なノードに依存します。$x$そして$y$。 ペア$(u, v)$からの独特な道を歩くとき、次の場合は禁止されています。$u$に$v$、訪問します$x$最初とその後の訪問$y$。 方向性が重要: 訪問$y$前に$x$両方を訪問するのは問題ありません。また、両方を別の順序で訪問することも問題ありません。 パターンのみ」$x$前に現れます$y$パス上に「」があると、ペアが無効になります。 

タスクは、順序付けられたペアの数をカウントすることです$(u, v)$、 と$u \ne v$、この禁止された順序は避けてください。 

入力サイズは最大です$3 \cdot 10^5$、ノードのすべてのペアに接触するもの、またはパスを繰り返し再計算するものを除外します。 パスを明示的に検査するソリューションは次のように動作します。$O(n^2)$あるいはさらに悪いことに、これは許容範囲をはるかに超えています。 通常、線形または線形に近いものが必要です。$O(n)$または$O(n \log n)$。 

素朴なアプローチでは、すべての順序付きペアを列挙し、からのパスが$u$に$v$含まれています$x$前に$y$。 パスクエリが最適化されていても、ペアの数だけでは$n(n-1)$、すでに約に達しています$10^{10}$最大の制約があるため、これは不可能です。 

微妙なエッジケースが現れるのは、$x$そして$y$隣接している。 その場合、禁止条件は、パスが単一のエッジを横切るかどうかに限定されます。$x \to y$その方向に。 もう 1 つのエッジ ケースは、ツリーが本質的に線である場合です。対称性を前提とすると、順序付けの制約が非常に明確になり、誤解しやすくなります。 

## アプローチ

 ブルートフォースのアイデアは、すべての順序付きペアの定義から始まります。$(u, v)$、パスを計算し、$x$前に現れます$y$。 ツリーは一意のパスを保証するため、正確性は問題ではないため、これは概念的には簡単です。 障害点は純粋に計算上のものです。 がある$n(n-1)$ペアを作成し、各パスを構築するだけでも時間がかかる場合があります$O(n)$最悪の場合、三次的な動作につながります。 

重要な観察は、ほとんどのペアの完全なパス構造を実際には気にしていないということです。 私たちが気にするのは、$x$そして$y$道沿いにあるのは「$x$前に$y$” かどうか。ツリーのルートを次のとおりにすると、そのグローバル条件はサブツリー関係に還元できます。$x$。 

木が根を張ると、$x$、すべてのノードはちょうど 1 つの子サブツリーに属します。$x$または、他のブランチの方向にあるすべてのブランチの外側にあります。 ノード$y$これらのサブツリーの 1 つに正確に存在します。 重要な単純化は、外部のノードからのパスはすべて、$y$-サブツリーへの$y$-サブツリーは通過する必要があります$x$そのサブツリーに入る前に、まさに禁止された順序が作成されます。 

これにより、問題全体が次のサブツリーのサイズの計算に縮小されます。$y$木が根を張るとき$x$そして、そのサブツリーとツリーの残りの部分との間の境界を横切る順序付きペアの数を数えます。

 ## アルゴリズムのチュートリアル

 1. ノードでツリーをルート化します$x$。 これにより、すべてのノードが明確に定義された親子関係を持つ方向構造が修正されます。$x$。 ルート化の理由は、禁止条件が「最初の」という点で非対称であるためです。$x$、 それから$y$”。
 2. ノードの位置を特定する$y$このルート付きツリーのサブツリーのサイズを計算します。$y$。 このサブツリーは、そのパスからのすべてのノードで構成されます。$x$通り抜ける$y$初め。 
3. 以下から始まる DFS を実行します。$y$、ただし、前に戻ってはなりません。$x$。 これにより、完全にサブツリー内に留まることが保証されます。$y$root化で定義されているとおり$x$。 訪問したノードの数がサブツリーのサイズになります$sz$。 
4. このサブツリーの外側にあるすべてのノードを数えます。 その数字は$n - sz$。 
5. 禁止された順序ペアの数を計算します。 最初のノードがサブツリーの外側にある順序ペア。$y$2 番目のノードはその中にあり、パスが生成されます。$x$前に遭遇する$y$。 そのようなペアの数は、$(n - sz) \cdot sz$。 
6. 順序付けされたペアの合計数を計算します。$n(n-1)$、禁止されたカウントを減算します。 

### なぜ効果があるのか

 木を発根させる$x$すべてのノードがコンポーネント内に存在するパーティションを生成します。$y$またはその外側。 サブツリー内のノード$y$まさにそのパスからのパスです$x$入る$y$出発直後$x$。 外部ノードから内部ノードへのパスはすべて通過する必要があります。$x$到達する前に$y$、禁断の命令を強行する。 逆に、他のすべてのペアはこの順序を避けます。$y$その後決して到達しない$x$、 または$x$以前のパス上にありません$y$。 これにより、すべての順序付きペアが、重複や欠落なく有効なセットと無効なセットにきれいに分割されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, x, y = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    # compute subtree size of y when rooted at x,
    # i.e. DFS from y avoiding x
    visited = [False] * (n + 1)

    def dfs(u, parent):
        visited[u] = True
        size = 1
        for v in g[u]:
            if v == parent:
                continue
            if v == x:
                continue
            size += dfs(v, u)
        return size

    sz = dfs(y, -1)

    total = n * (n - 1)
    bad = sz * (n - sz)
    print(total - bad)

if __name__ == "__main__":
    solve()
```実装では隣接リストを構築し、次にルートとなる単一の DFS を実行します。$y$へのトラバースを明示的にブロックします。$x$。 これは効果的に次のサブツリーをシミュレートします。$y$根を張る木の中に$x$明示的にルート構造を構築する必要はありません。 

減算ステップは、アルゴリズムで導出された組み合わせ分割を直接エンコードします。つまり、順序付けられたすべてのペアから外部から交差するペアを差し引いたものです。$y$-サブツリーをそれに追加します。 

よくある実装の落とし穴は、誤って root 化してしまうことです。$y$の代わりに$x$これにより、サブツリーの定義が壊れ、有効な交差が正しくカウントされなくなります。

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。$x$に直接隣接しています$y$。 その状況では、$y$から離れることによって到達可能なノードのみが含まれます$x$、したがって、からの DFS$y$元に戻ろうとするとすぐに終了します$x$。 このアルゴリズムはサブツリー サイズ 1 を正確にカウントし、正しい数の禁止されたペアを生成します。 

次の場合には、別のエッジケースが発生します。$y$から遠く離れた葉ノードです$x$。 DFS は依然としてそのリーフを正確にキャプチャし、それ以上は何もキャプチャせず、外部からそのリーフに入るすべてのペアが禁止されたものとしてカウントされるようにします。 

最後のエッジケースは、チェーンなど、ツリーのバランスが著しく崩れている場合です。 での発根$x$それでもノードを前後にきれいに分離します$y$チェーンに沿って、DFS は以下を含むサフィックス部分を正しく分離します。$y$、分岐に関する構造的な前提を必要とせずに正確さを維持します。
