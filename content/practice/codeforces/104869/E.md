 ## 解決策
 ## 問題の理解

 羊とオオカミの 2 種類の動物と、農夫が操縦するボートで川を渡るシナリオが与えられました。 最初は、羊とオオカミはすべて左岸にいます。 農場主は、最大でも運ぶことができるボートを使って、すべての羊を右岸に移動させたいと考えています。$p$旅行ごとの動物数。 ボートは前後に移動でき、移動中は農民が常にボートに乗っています。 

重要な問題は、どちらかの岸に残された動物が安全に滞在できるのは、農家の監督がある場合、または安全条件を満たしている場合のみであることです。 ある集団が安全でないとみなされるのは、その集団に農夫がいない場合に限られ、その岸辺ではオオカミの数が羊の数を超えている場合に限られます。$q$。 どちらかの岸でこれが発生した場合、その側の羊は食べられたとみなされ、設定は無効になります。 

タスクは、すべての中間構成が安全であることを確認しながら、すべての羊を右岸に移動させるのに必要なボートの最小移動回数を計算するか、それが不可能であると判断することです。 

入力サイズは小さく、両方とも$x$そして$y$最大でも 100 です。これは、貪欲な推論に頼るのではなく、州全体の最短経路探索として問題をモデル化する余裕があることを示唆しています。 ただし、各ボート旅行に動物のサブセットが存在する場合、単純に扱うと大きな分岐要素が導入されるため、主な課題は遷移を制御することです。 

微妙な失敗のケースは、中間の安全性チェックを無視することで発生します。 たとえば、移動した羊の数が多すぎてオオカミを一方の岸に放置すると、移動後の最終構成が有効に見えたとしても、一時的に制約に違反する可能性があります。 正しい解決策は、すべての羊が移動された後だけでなく、単一の遷移後に両方のバンクを検証する必要があります。 

次の場合には、別のエッジケースが発生します。$q = 0$。 この場合、オオカミの数は羊の数をゼロだけ上回ることが許可されています。つまり、監視されていない岸辺にいるオオカミの絶対多数は直ちに危険であることを意味します。 すべての羊を早期に移動させようとする単純な貪欲なアプローチは、安全でない残りの構成で簡単に罠にかかる可能性があります。 

## アプローチ

 自然な出発点は、これを状態遷移の問題として扱うことです。 ブルートフォース戦略では、考えられるあらゆるボートトリップの順序を列挙することになります。 各旅行は、最大でもサイズの動物のサブセットを選択することで構成されます$p$、それらを反対側に移動し、両方の銀行が安全であるかどうかを確認します。 可能なシーケンスの数は旅行の数とともに指数関数的に増加し、各旅行には指数関数的に多くのサブセットがあるため、このアプローチは中程度の場合でも完全に実行不可能になります。$x$そして$y$。 

重要な観察は、システムの状態が 3 つの値 (左岸の羊の数、左岸のオオカミの数、および農夫の位置) によって完全に決定されるということです。 これらが修正されると、他のすべてが暗黙的に反映されます。 これにより、問題は最大で最短パスの検索に軽減されます。$101 \times 101 \times 2$州。 

州間の移行は、収容人数に応じて、1 回の旅行で移動する羊とオオカミの数を選択することによって定義されます。$p$そして農家の現在の側での利用可能性。 このような選択肢の数は多数ありますが、固定されており、状態グラフ構造とは独立しているため、これを重み付けされていないグラフとして扱い、BFS を実行できます。 

ブルートフォースのアイデアは、考えられるすべてのシーケンスを正確にモデル化するため機能しますが、遷移の組み合わせ爆発により失敗します。 状態圧縮の観察により、問題は頂点数の少ないグラフに縮小され、BFS によって最短パスが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 状態を次のように定義します$(s, w, side)$、 どこ$s$そして$w$は左岸の羊とオオカミの数です、そして$side$農民が現在左岸にいるのか右岸にいるのかを示します。 

1. BFS を開始状態で初期化します。$(x, y, 0)$、つまり、すべての動物が左岸にいて、農場主はそこから始まります。 この状態の距離はゼロです。 
2. 州ごとに、ボートに荷物を積み込むためのあらゆる方法を検討します。 整数を選択します$ds$そして$dw$羊とオオカミを動かして表現し、$0 \le ds + dw \le p$、そしてこれらは現在の側で利用可能な動物を超えてはなりません。 
3. 動物を川を渡って移動させた後の状態を計算します。 農家が左側にいる場合は、左側のカウントから減算します。 それ以外の場合は、それらを左側に追加し直します。 
4. 移動するたびに、両岸の安全を確認してください。 銀行が安全でないのは、銀行が現在農家によって監督されておらず、オオカミが羊を上回る場合のみです。$q$。 いずれかのバンクが安全でない場合は、遷移を破棄します。 
5. 結果の状態がまだ訪問されていない場合は、その距離を記録し、BFS キューにプッシュします。 
6. すべての羊が右岸にいる状態に達したら停止します。$s = 0$。 

BFS は、初めて有効な目標状態に到達するときに、最小回数のトリップが使用されたことを保証します。 

### なぜ効果があるのか

 すべてのボートの横断が正確に 1 ステップとしてカウントされるため、問題のグラフは重み付けされていません。 動物と農民の位置の有効な構成はそれぞれノードであり、すべての合法的な移動はノード間のエッジです。 BFS は距離の増加順にノードを探索するため、最初に目標構成に到達した時点では、より短いシーケンスは存在しません。 安全制約により、すべてのエッジが有効な中間構成を表すことが保証されるため、検索空間に無効な状態が含まれることはありません。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def safe(sheep, wolves, is_farmer_left, q):
    # check left bank if unattended
    if not is_farmer_left:
        if wolves > sheep + q:
            return False
    # check right bank if unattended
    rs = total_sheep - sheep
    rw = total_wolves - wolves
    if is_farmer_left:
        if rw > rs + q:
            return False
    return True

x, y, p, q = map(int, input().split())
total_sheep, total_wolves = x, y

# state: (sheep_left, wolves_left, farmer_left)
start = (x, y, 0)
target_sheep_left = 0

dist = [[[-1] * 2 for _ in range(y + 1)] for _ in range(x + 1)]
dist[x][y][0] = 0

q_bfs = deque([start])

while q_bfs:
    s, w, side = q_bfs.popleft()
    d = dist[s][w][side]

    if s == 0:
        print(d)
        sys.exit(0)

    if side == 0:
        max_s, max_w = s, w
    else:
        max_s, max_w = x - s, y - w

    for ds in range(max_s + 1):
        for dw in range(max_w + 1):
            if ds + dw == 0 or ds + dw > p:
                continue

            if side == 0:
                ns, nw, nside = s - ds, w - dw, 1
            else:
                ns, nw, nside = s + ds, w + dw, 0

            if ns < 0 or nw < 0 or ns > x or nw > y:
                continue

            # safety check
            # left bank
            ls, lw = ns, nw
            # right bank
            rs, rw = x - ns, y - nw

            ok = True
            if nside == 0:
                # farmer left
                if rw > rs + q:
                    ok = False
            else:
                # farmer right
                if lw > ls + q:
                    ok = False

            if not ok:
                continue

            if dist[ns][nw][nside] == -1:
                dist[ns][nw][nside] = d + 1
                q_bfs.append((ns, nw, nside))

print(-1)
```この実装では、各構成を 3D 距離テーブルに明示的にエンコードします。 BFS キューは、トリップ数の増加順に状態を展開します。 州ごとに、ボートの容量内に収まり、現在の岸で利用可能な羊とオオカミのすべての組み合わせを試して、実行可能なボートの積載量をすべて列挙します。 

微妙な点は安全性チェックです。農民が現在の側で食事をすることを妨げているため、制約を満たす必要があるのは農民のいない銀行だけです。 これが、コードが次の条件に応じて反対側のバンクのみをチェックする理由です。`side`。 

終了条件は、すべての羊が右岸に移動したときにトリガーされます。これは、`s == 0`。

 ## 特殊なケース

 重要なエッジケースの 1 つは、最初はオオカミがすでに片側を支配しているものの、農夫がそこにいるため、まだ一時的に安全である場合です。 たとえば、すべてのオオカミと羊が一緒に開始した場合、次のような場合でも初期状態は有効です。$y > x + q$監視によりあらゆる攻撃が防止されるためです。 

安全性はファーマーなしで銀行に対してのみチェックされるため、実行中、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、ボートの収容能力が大きく、すべてを一度に移動できる場合です。 この場合、最適な答えは 1 回のトリップであり、BFS は 1 つの拡張ステップですぐに目標状態に到達します。 遷移生成には依然としてすべてのサブセットが含まれていますが、目標状態は早期に検出され、すぐに返されます。 

最後のエッジケースは、永続的な不均衡制約により有効なシーケンスが存在しない場合です。 このような場合、BFS は到達可能な状態をすべて使い果たしますが、到達することはありません。$s = 0$、アルゴリズムは正しく返します$-1$。
