 ## 解決策
 ## 問題の理解

 いくつかのコンテストラウンドからの評価の変化を表す整数の配列が与えられます。 これらのラウンドの順序を任意に変更することができます。 次に、評価 0 から開始して、値を 1 つずつ追加してシミュレーションします。 累計が過去の累計のすべての値を厳密に超えるたびに、それを最大評価の更新としてカウントします。 

タスクは最適な順序を見つけることではなく、よりグローバルなものです。値の固定マルチセットについて、配列のさまざまな順列を選択することで「最大更新数」の異なる値がいくつ達成できるかを知りたいと考えています。 配列の 1 つの要素を変更する更新のたびに、この量を再計算する必要があります。 

重要な制約は、n と q の両方が最大 200,000 になる可能性があるため、順列をシミュレートしようとするソリューションや、更新ごとの対数または定数作業よりも悪いものをクエリごとに推論しようとするソリューションは合格しないということです。 この構造は、答えがマルチセットの詳細な配置ではなく、マルチセットの非常に少数のグローバル プロパティに依存する必要があることを強く示唆しています。 

すべての数値が正でない場合、微妙だが重要なエッジ ケースが発生します。 この状況では、累計はゼロから始まり、厳密に正になることはないため、最大値の更新は行われません。 少なくとも 1 つの更新が常に発生すると仮定する単純なアプローチでは、ここで誤って肯定的な答えが報告されてしまいます。 もう 1 つの脆弱なケースは、ゼロが存在する場合です。ゼロは合計を増やすことはありませんが、不用意に符号を確認するだけだと、ゼロは無害な正の値と誤解される可能性があります。 

## アプローチ

 直接考えようとすると、強引なアイデアは、配列のすべての順列を列挙し、それぞれの順列のプロセスをシミュレートし、プレフィックスの合計が新しいレコードを設定する回数をカウントすることです。 これは定義と正確に一致するため、原則として正しいです。 ただし、n 個の階乗順列があり、1 つの順列をシミュレートするだけでも直線的な時間がかかるため、このアプローチは非常に小さい n を超えるとすぐに爆発的に増加します。 

重要な観察は、このプロセスではプレフィックスの合計が新しい高値を超えたときのみを考慮しており、これは要素が正であるかどうかのみに依存するということです。 負の値とゼロの値は成長を遅らせる可能性がありますが、それ自体で追加の記録破りのイベントを作成することはできません。 一方、正の値は、それぞれ最大 1 つの新しいレコードに寄与することができます。これは、正の数によってプレフィックスの合計が新しいピークに達すると、再配置によって同じ要素が再び寄与することはできないためです。 

これにより、問題全体が、厳密に正の値がいくつ存在するかを追跡するように分解されます。 これが認識されると、達成可能な k 値の数は非常に制限されます。正の数が存在しない場合、プロセスはゼロより大きくなることはありません。そのため、可能な値は k = 0 だけです。少なくとも 1 つの正の数がある場合は、すべての正の値を強制的に早めに出現させて、それぞれに新しいレコードを作成するか、累積された負の値が克服されたときに交差が 1 つだけ発生するように、すべての正の値を最後まで遅らせることができます。 中間の動作も実現可能ですが、重要なのは、1 から正の要素の数までのすべての値が可能であり、連続した範囲を形成することです。 

したがって、配列ごとの答えは単純に正のカウント範囲のサイズになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順列に対するブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | 陽性カウントのみを追跡 | O(n + q) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題全体を、厳密にゼロより大きい配列内の要素の数を維持することに集約します。

1. 配列内の正の要素の初期数を計算します。これを pos と呼びます。 
2. 単一の要素を変更する更新ごとに、まずその要素が更新前にポジティブであるかどうか、および更新後にポジティブであるかどうかを判断します。 
3. 陽性が非陽性になった場合は 1 を減算し、非陽性が陽性になった場合は 1 を加算して、それに応じて位置を調整します。 
4. 各更新後に、pos からの答えを計算します。pos がゼロの場合は 1 を出力し、それ以外の場合は pos を出力します。 

この推論の重要な部分は、なぜ答えが pos だけに依存するのかということです。 プレフィックス最大更新の構造により、厳密に正の増分のみが新しいレコードを作成できるようになりますが、負とゼロはタイミングにのみ影響し、正の値ですでに許可されている数を超えて記録破りのイベントの数を増やすことはできません。 

### なぜ効果があるのか

 累積合計を以前に達成可能なすべての値よりも押し上げる要素を追加すると、プレフィックス合計の実行最大値が増加します。 正でない要素は、プレフィックスの合計に追加しても厳密には合計を増やすことができないため、新しい最大値の増加に寄与することはできません。 したがって、ポジティブな要素のみがそのようなイベントを引き起こすことができます。 

さらに、各正の要素は、独自の新しい最大値を生成するか、単一の最終交差に吸収されるように配置できますが、どの配置でも pos を超える別個の最大更新が発生することはなく、pos がゼロ以外の場合は常に少なくとも 1 つの更新が可能です。 これにより、達成可能な k 値のセットが正確に {1, 2, ..., pos} になるように強制され、pos = 0 の縮退ケースでは、{0} に崩壊します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    pos = 0
    for x in a:
        if x > 0:
            pos += 1
    
    for _ in range(q):
        i, v = map(int, input().split())
        i -= 1
        
        old = a[i]
        if old > 0:
            pos -= 1
        
        a[i] = v
        
        if v > 0:
            pos += 1
        
        if pos == 0:
            print(1)
        else:
            print(pos)

if __name__ == "__main__":
    solve()
```このソリューションは単一のグローバル カウンターを維持します`pos`、常に厳密に正である要素の数を表します。 各更新はこのカウンターにローカルでのみ影響するため、配列自体は以前の値を記憶するためにのみ必要です。 出力ロジックは、導出された特性評価から直接続きます。すべての値が非正であり、単一の可能な結果を​​与えるか、そうでない場合は 1 から pos までのすべてのカウントが達成可能です。 

ここでよくある間違いは、更新のたびにプレフィックスの合計を並べ替えたりシミュレーションしたりして答えを再計算しようとすることですが、これでは時間がかかりすぎます。 重要な単純化は、配列の完全な構造は決して重要ではなく、符号の分布のみが重要であるということです。 

## 実用的な例

 配列を考慮してください`[1, 2, 3]`。 

最初は 3 つの要素がすべて正であるため、pos = 3 となります。 

| ステップ | 配列 | 位置 | 出力 |
 | --- | --- | --- | --- |
 | 初期化 | [1,2,3] | 3 | - |
 | 1 | [1,2,4] | 3 | 3 |
 | 2 | [1、-2、4] | 2 | 2 |
 | 3 | [-3、-2、4] | 1 | 1 |
 | 4 | [-3,-2,1] | 1 | 1 |
 | 5 | [-3,1,1] | 2 | 2 |

 これは、正の要素の数がゼロでない限り、答えは常に正の要素の数に等しいという考えと一致します。 

ここで、次のようなポジティブがないケースを考えてみましょう。`[0, -1, -5]`。 

| ステップ | 配列 | 位置 | 出力 |
 | --- | --- | --- | --- |
 | 初期化 | [0、-1、-5] | 0 | 1 |
 | 更新後 | まだすべて ≤ 0 | 0 | 1 |

 ここでは、順序付けによって実行合計が 0 を超えることはありません。そのため、達成可能な値は k = 0 のみで、有効な k 値の数は 1 です。 

これらのトレースは、不変式が純粋に符号ベースであり、大きさや順序の影響を受けないことを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q) | 各更新では単一のカウンターが O(1) 時間で調整されます。 
| スペース | O(1) おまけ | 配列と 1 つの整数カウンターのみが維持されます。 

この制約により、最大 200,000 回の更新が許可されるため、クエリごとに一定時間の処理が必要になります。 このソリューションは、操作ごとに重い計算を実行しないため、制限内に問題なく収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = list(map(int, input().split()))
    
    pos = sum(1 for x in a if x > 0)
    
    out = []
    for _ in range(q):
        i, v = map(int, input().split())
        i -= 1
        if a[i] > 0:
            pos -= 1
        a[i] = v
        if a[i] > 0:
            pos += 1
        out.append(str(1 if pos == 0 else pos))
    
    return "\n".join(out)

# minimal case
assert run("1 1\n0\n1 5\n") == "1", "single element becomes positive"

# all non-positive
assert run("3 2\n0 -1 -2\n1 -5\n2 -3\n") == "1\n1", "all non-positive stays 1"

# all positive shrinking
assert run("3 3\n1 2 3\n1 -1\n2 -2\n3 -3\n") == "2\n1\n1", "positive count decreases"

# mixed updates
assert run("4 2\n1 -1 2 -3\n2 5\n3 -4\n") == "3\n2", "toggle positives"

# already maximal positives
assert run("2 1\n10 20\n1 -5\n") == "1", "drop to single positive"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一要素の更新 | 1 | 基本ケースの正確性 |
 | すべて非正 | クエリごとに 1 つ | ゼロ陽性の場合の処理​​ |
 | 陽性者の減少 | 縮小する答え | 動的更新 |
 | 混合トグル | 正しい符号遷移 | 両方向 |
 | 単一のポジティブに低下 | 境界遷移 | pos = 1 の動作 |

 ## 特殊なケース

 すべての要素が正でない場合、アルゴリズムは正しく維持します。`pos = 0`全体を通して、すべてのクエリに対して 1 を出力します。 これは、どの順列も正のプレフィックス合計を作成できないため、最大更新は発生しないという事実に対応します。 

値が正から非正に、またはその逆に変化する場合、必要なカウンターの更新は 1 回だけです。 たとえば、変更する`-3`に`4`増加する`pos`1 つずつ増加し、その結果としての回答の増加は、さらに 1 つの要素が独立して潜在的な記録イベントに寄与できるようになったという事実を反映しています。 

正しさは大きさには依存しません。 のような極端な値でも、`-10^9`そして`10^9`～と同じように振る舞う`-1`そして`1`、要素が寄与するかどうかに影響するのは符号のみであるためです。`pos`。
