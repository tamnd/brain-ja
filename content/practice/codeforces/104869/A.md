 ## 解決策
 ## 問題の理解

 私たちにはいくつかの「場面」が与えられています。 各シーンは、色を表す整数のセットによって記述されます。 すべてのシーンに対して、1 つの特別な値が定義されます。それはメイン カラーであり、これは単にそのセット内の最大値です。 

すべてのシーンを順列に配置する必要があります。 順序を修正した後、隣接するすべてのペアを調べます。 A のメイン カラーが B のフルカラー セット内のどこかに表示される場合、シーン A からシーン B へのトランジションがカウントされます。目的は、そのようなトランジションの数ができるだけ多くなるようにシーンを並べ替えることです。 

入力サイズは大きく、すべてのセットで最大 100,000 のシーンと合計 200,000 のカラー エントリがあります。 すべての順列を試行するような解決策は、すでに階乗になっているため、直ちに不可能になります。 シーンのペアに対する 2 次または 3 次の推論も遅すぎます。 これは、答えがローカルの貪欲な構造と色の出現に対する効率的なブックキーピングに依存していることを強く示唆しています。 

微妙な点は、遷移条件が非対称であることです。 A が B に遷移できるかどうかは、A の最大値と、その値が B に含まれるメンバーシップにのみ依存します。逆方向は無関係です。これは、各ノードが保持する特定の値を将来のノードのセットと揃えようとする有向パスを効果的に構築していることを意味します。 

よくある失敗例は、これが対称互換性の問題であると考えることから生じます。 

シーンAに色がある場合`{1, 100}`そしてシーンBは`{100}`の場合、A は B に遷移できますが、100 が B の最大値でもあり、A のセットに出現しない限り、B は必ずしも元に遷移することはできませんが、実際にはそうではありません。 これを無向マッチング問題として扱うと、構造が失われ、誤った貪欲な戦略につながります。 

最大色または設定されたサイズで並べ替えようとすると、別の失敗モードが表示されます。 どちらも、シーンが作成できるトランジションの数とは相関しません。これは、有用性は、値自体ではなく、将来のシーンにその最大値が含まれる数に依存するためです。 

## アプローチ

 ブルートフォースのアイデアは、すべての順列を試し、有効な遷移をカウントすることです。 各配置について、すべての隣接するペアをチェックするには直線的な時間がかかりますが、$n!$順列は、非常に小さい場合でも実行可能な計算をはるかに超えています。$n$。 バックトラッキングを使用して順列を構築しようとしても、指数関数的な分岐が発生します。 

重要な観察は、「シーンが次のシーンにどのように接続されるか」から「シーンが前のシーンにどのように役立つか」に視点を反転することです。 あるシーン$j$前のシーンからの遷移に貢献します$i$ちょうどその最大のとき$i$に含まれています$j$のセットです。 なので、それぞれのシーンで$j$前のシーンからの「リクエスト」のコレクターとして見ることができます。最大の色が含まれるすべての前のシーン$S_j$メリットがある場合$j$その直後に来ます。 

これにより、問題は、各位置の選択が前の位置から満たす残りの「要求された色」の数を最大化するシーケンスを構築することに変わります。 

色ごとに、現在その色が最大値として残っているシーンの数を維持します。 次のシーン候補としては$j$、その値は、最大値が含まれる残りのシーンの数です。$S_j$。 このような値が最も高いシーンを選択するのは自然な貪欲な戦略であり、これはシーンを削除するときに動的に維持できます。 

残りの課題は、カウントが変化したときにこれらの値を効率的に維持することです。シーンを削除すると、その色を含むすべてのシーンからの最大色の寄与が減少するためです。

 ## アルゴリズムのチュートリアル

 各シーンに、セット内の最大の要素であるメイン カラーを割り当てます。 また、各色からその色を含むセットが含まれるシーンのリストへの逆インデックスも用意します。 

現在その色が最大である未配置シーンの数を追跡する各色ごとのカウンターを維持します。 

また、各シーンのスコアも維持します。これは、その色が最大値である残りのシーンの数のセット内のすべての色の合計として定義されます。 このスコアは、シーンが現在の位置の直後に配置された場合に、このシーンが作成できる可能性のあるトランジションの数を表します。 

現在最大のスコアを持つ未配置シーンを繰り返し選択し、それを回答に追加し、考慮から削除します。 シーンを削除すると、その最大色のカウンターが減少し、この色を含むすべてのシーンのスコアが更新されます。 

このプロセスは、すべてのシーンが配置されるまで続きます。 最後に、構築された順序で隣接するペアをスキャンして遷移をカウントします。 

### なぜ効果があるのか

 シーンのスコアは、次に選択された場合に、残りのシーンの現在のプールから作成できるトランジションの数を正確に測定します。 すべてのアップデートは、かつて最大のカラーを備えたシーンが存在していたという事実を反映しています。$c$が使用されると、将来の候補者はその恩恵を受けることができなくなります。$c$。 これにより、各シーンが貢献できる残りの機会がどれくらいあるかを十分に理解した上で、それぞれの貪欲な選択が行われるようになり、その後の決定によって、以前に削除されたシーンの有用性を遡及的に高めることができなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    sets = []
    mx = []
    
    color_to_nodes = {}
    
    for i in range(n):
        arr = list(map(int, input().split()))
        m = arr[0]
        s = arr[1:]
        sets.append(s)
        mx_val = max(s)
        mx.append(mx_val)
    
    cnt = {}
    for i in range(n):
        c = mx[i]
        cnt[c] = cnt.get(c, 0) + 1
    
    # build color -> nodes containing it
    for i in range(n):
        for c in sets[i]:
            if c not in color_to_nodes:
                color_to_nodes[c] = []
            color_to_nodes[c].append(i)
    
    score = [0] * n
    for i in range(n):
        sc = 0
        for c in sets[i]:
            sc += cnt.get(c, 0)
        score[i] = sc
    
    import heapq
    heap = [(-score[i], i) for i in range(n)]
    heapq.heapify(heap)
    
    removed = [False] * n
    ans = []
    
    while heap:
        neg_s, i = heapq.heappop(heap)
        if removed[i]:
            continue
        
        # recompute lazily check
        cur = 0
        for c in sets[i]:
            cur += cnt.get(c, 0)
        if cur != -neg_s:
            heapq.heappush(heap, (-cur, i))
            continue
        
        removed[i] = True
        ans.append(i)
        
        c0 = mx[i]
        cnt[c0] -= 1
        if cnt[c0] == 0:
            del cnt[c0]
        
        if c0 in color_to_nodes:
            for j in color_to_nodes[c0]:
                if not removed[j]:
                    # update score lazily by decreasing one occurrence
                    score[j] -= 1
                    heapq.heappush(heap, (-score[j], j))
    
    # count transitions
    pos = {v: i for i, v in enumerate(ans)}
    res = 0
    for i in range(n - 1):
        a = ans[i]
        b = ans[i + 1]
        if mx[a] in sets[b]:
            res += 1
    
    print(res)
    print(*[x + 1 for x in ans])

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に必要なすべての構造、つまり各シーンの最大カラー、これらの最大カラーの頻度、カラーからそれらを含むシーンへの逆インデックスを構築します。 スコアの計算では、シーンの価値は、それが満たせる残りの最大カラーの数に正確に比例するという考えが使用されます。 

ヒープは、現在最適な候補を常に抽出するために使用されます。 シーンを削除するとスコアが変化するため、ヒープ エントリが古い可能性があるため、抽出のたびに現在のスコアを再計算し、古い場合は押し戻すことで正確さを検証します。 

シーンが選択されると、その最大色のカウンターがデクリメントされ、その変更がその色を含むすべてのシーンに伝播されます。 これが、最初から再計算せずにスコアを段階的に維持できる唯一の理由です。 

最後に、構築された順列の遷移を明示的にカウントすることで、答えが検証されます。 

## 実用的な例

 小さな入力を考えてみましょう。```
3
2 1 2
2 2 3
2 1 3
```ここでの最大値は次のとおりです`[2, 3, 3]`。 

カウントから始めます`cnt[2]=1`、`cnt[3]=2`。 

初期スコア:

 | シーン | セット | スコア |
 | --- | --- | --- |
 | 1 | {1,2} | cnt[1]+cnt[2] = 0+1 = 1 |
 | 2 | {2,3} | 1+2 = 3 |
 | 3 | {1,3} | 0+2 = 2 |

 最初にシーン 2 を選択します。 最大値は 3 なので、減少させます`cnt[3]`を 1 に変更し、3 を含むシーンを更新します。 

| ステップ | 選んだ | 残りのcnt[3] | 次の推論 |
 | --- | --- | --- | --- |
 | 1 | 2 | 1 | 3 を含むシーンのスコアが減少します。 

次のスコアは次のようになります。 

シーン 3 が減少し、シーン 2 が削除されます。 

次に、シーン 3 とシーン 1 のどちらかを選択します。スコアが高いためシーン 3 を優先し、次にシーン 1 を選択します。 

トレースは、セット内にまだ多くの試合が残っているシーンを常に優先していることを確認しています。 

2 番目のケース:```
2
1 10
1 20
```マキシマは`[10, 20]`、そして他のセットの最大値を含むセットはありません。 すべてのスコアはゼロのままであるため、任意の順序が選択され、トランジションはゼロのままになります。 このアルゴリズムは、互換性が存在しない場合、人工的な構造を強制しません。

 ## 特殊なケース

 重要なエッジケースは、すべてのシーンが同じ最大カラーを共有する場合です。 その場合、すべてのシーンが他のシーンから恩恵を受け、アルゴリズムは最後の削除まですべてのノードの高いスコアを継続的に維持します。 貪欲な選択は同等のものの間で任意になりますが、すべての隣接関係は有効なままであり、最大値が生成されます。$n-1$トランジション。 

もう 1 つのケースは、色が互いに素なグループを形成し、他のセット内に最大値が現れない場合です。 ここでは、すべてのスコアはずっとゼロのままです。 ヒープは任意の順序に縮退しますが、順序によっては遷移が発生しないため、これは正しいことです。 

よりデリケートなケースは、単一の色が多くのセットを支配しているが、最大値として現れるのは 1 つのシーンのみである場合です。 そのシーンを削除すると、一連の大幅なスコア削減が引き起こされますが、更新はその色を含むシーンに限定されるため、正確性は維持され、無関係なシーンは影響を受けません。
