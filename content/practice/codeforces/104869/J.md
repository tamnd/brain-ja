 ## 問題の理解

 最大 50 個の頂点を持つ根のないツリーが与えられます。 2 人のプレイヤーが交互にターンを行い、各ターンでエッジを選択します。$u-v$。 この移動はエンドポイントのローカルな交換ではなく、構造的な「再配線」です。$u$を除外する$v$～から切り離される$u$そして再び取り付けられました$v$。 手術後は、$u$エッジのみを維持します$v$、 その間$v$全てを吸収する$u$の他のインシデントのサブツリー。 

このゲームを標準のツリー ゲームとは根本的に異なるものにする追加の制限があります。 移動は、結果のツリーが前のツリーと同型でない場合にのみ許可されます。 言い換えれば、プレーヤーは、ラベルのないツリーの形状を変更しない変換を実行することを禁止されます。 

プレイヤーが有効な手を持っていない場合、ゲームは終了します。 アリスが開始し、両方のプレイヤーが最適にプレイします。 

主な問題は、移動がラベル付きの頂点で定義されるが、合法性は結果として得られるラベルのないツリー構造によってのみ決定されることです。 これは、同型ツリーを生成する 2 つの異なる再配線操作のシーケンスが事実上同一の状態とみなされ、構造的に有効であっても一部の移動が許可されないことを意味します。 

以来$n \le 50$, ラベル付きのすべての状態をブルートフォースすることは不可能です。 ツリー空間は絶対的に小さいにもかかわらず、同型性により多くの構成が崩れ、単純にシミュレートした場合、最悪の場合でも移動ごとの分岐係数は依然として 2 次になります。 

対称性の高いツリーからは、微妙なエッジ ケースが発生します。 特に、スター ツリーは、接木操作によってその構造が維持されるため、他のすべてのツリーとは異なる動作をします。 

ツリーが 4 つの頂点にあるスターの場合:```
1 - 2
|
3
|
4
```中心と葉を摘み取ろうとしても、木を星型に保つ方法で葉を再び取り付けるだけです。 結果のツリーは元のツリーと同形であるため、有効な移動はありません。 同じことがどのスターでも起こります$n$頂点: ゲームはすぐに行き詰まり、アリスは負けます。 

一方、長さ 4 のパスの場合は次のようになります。```
1 - 2 - 3 - 4
```ツリーはスターではないため、少なくとも 1 つの有効な操作が存在します。 この違いがソリューションの中核となることがわかります。 

## アプローチ

 直接シミュレーションでは、ラベル付きの各ツリーを状態として扱い、可能なエッジをすべて試します。$u-v$、隣接リストを再配線し、前の状態に対して同型性をチェックすることによって新しいツリーを生成します。 すべての遷移の同型性テストにはコストがかかり、再配線可能な構成の数はたとえ$n=50$。 

正準ツリー形式のみを格納することによって状態を圧縮したとしても、ツリー同型クラスの大きな暗黙のグラフに直面することになります。 完全なゲーム分析には、このグラフの勝敗状態を計算する必要がありますが、操作の構造を考えると過剰です。 

重要な観察は、移植と移植の動きによって構造がハブに向かって積極的に崩壊するということです。 すべての操作で度数の質量が 1 つの頂点から別の頂点に移動され、繰り返し適用するとツリーが集中する傾向があります。 すべての可能な移動が同型ツリーを生成するという意味で、この操作の下で完全に安定している唯一の構成はスターです。 

ツリーがスターでなくなると、その操作によってツリーの構造的形状が変化するエッジが少なくとも 1 つ常に存在します。 これは、ゲームが同型制約によって中間の非スター状態でブロックされることがないことを意味します。 唯一の終端位置は星です。 

この観点から、ゲームは単純な到達可能性の問題に帰着します。つまり、現在のプレイヤーは少なくとも 1 つの有効な手を行うことができるか、つまり、木はスターではないでしょうか。 

すでにスターの場合、アリスは何も動けず、すぐに負けます。 それ以外の場合、アリスに手があり、ゲームは続行され、最適なプレイによってこの基本的な二分法は変わりません。

 ## アルゴリズムのチュートリアル

 解決策全体は、入力ツリーがスターかどうかを識別することに帰着します。 

1. 入力エッジからすべての頂点の次数を計算します。 
2. 次数を持つ頂点が存在するかどうかを確認する$n-1$。 
3. そのような頂点が存在する場合、ツリーはスターであり、アリスには有効な動きがないため、「ボブ」と出力します。 
4. それ以外の場合、少なくとも 2 つの頂点の次数が 1 より大きいため、ツリーはスターではなく、アリスは移動できるため、「アリス」と出力します。 

これで十分な理由は、スターではない木には少なくとも 1 つのエッジが認められ、そのグラフト操作によって別のラベルのない構造が生成されるため、最初のプレイヤーがすぐに行き詰まることがないからです。 

### なぜ効果があるのか

 同型制約は、ツリーのラベルのない構造全体を保存する移動のみをブロックします。 すべての葉は区別できず、すべての再付着により別の星が生成されるため、移植操作では星内のすべてのエッジの構造が保存されます。 他のすべてのツリーでは、サブツリー間に構造的な非対称性が存在します。これは、少なくとも 1 つのエッジが、グローバル形状の異なる役割を持つ頂点を接続していることを意味します。 このようなエッジ全体にグラフト操作を適用すると、頂点の再ラベル付けでは一致できない形で次数分布が変化するため、結果として得られるツリーは元のツリーと同型ではなくなります。 したがって、非スターツリーには常に少なくとも 1 つの正当な動きがありますが、スターには何もありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())
deg = [0] * (n + 1)

for _ in range(n - 1):
    u, v = map(int, input().split())
    deg[u] += 1
    deg[v] += 1

is_star = any(d == n - 1 for d in deg[1:])

if is_star:
    print("Bob")
else:
    print("Alice")
```全体の決定はツリーに普遍的な中心頂点があるかどうかの検出に依存するため、実装では度数のみが計算されます。 配列`deg`は隣接数を追跡し、一度スキャンするだけでツリーがスターかどうかを判断できます。 

重要な点は、移植手術のシミュレーションが必要ないことです。 シミュレーションを試みると、ラベル付き変換と同型制約が誤って混在してしまいますが、実際の決定は純粋に構造の対称性に依存します。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    n = int(input().strip())
    deg = [0] * (n + 1)
    for _ in range(n - 1):
        u, v = map(int, input().split())
        deg[u] += 1
        deg[v] += 1
    print("Bob" if any(d == n - 1 for d in deg[1:]) else "Alice")

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from io import StringIO
    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out
    solve()
    sys.stdout = old_stdout
    sys.stdin = old_stdin
    return out.getvalue().strip()

 メインのエッジケースは完全に対称なスター構成です。 この場合、可能なすべてのグラフト操作でツリーの同型クラスが保存されるため、正当な移動は存在しません。 アルゴリズムは、次数の頂点をチェックすることでこれを検出します。$n-1$、ラベルに関係なく星を正しく識別します。 

もう一つの微妙なケースは、次のような小さな木です。$n=2$。 どちらかの端点に次数があるため、シングル エッジ ツリー自体はスターです。$1 = n-1$, そのため、アリスはすぐに行動を起こすことができません。 次数チェックでは、特別なケースを使用せずにこれをキャプチャします。 

最後に、スターではない非常に不均衡なツリーでも構造的に非対称性があるため、常に少なくとも 1 つの移動が許可されます。 解決策は、特定の動きを見つけることに依存せず、少なくとも 1 つの動きが存在することを検出することにのみ依存します。これは、ユニバーサル中心頂点が存在しないことによって保証されます。
