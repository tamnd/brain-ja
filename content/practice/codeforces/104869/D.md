 ## 解決策
 ## 問題の理解

 2 つの文字列が与えられ、1 つは「Dark LaTeX」システムのシーケンスを表し、もう 1 つは「Light LaTeX」のシーケンスを表します。 各文字列から、連続した部分文字列を選択できます。 これにより、最初の文字列から 1 つと 2 番目の文字列から 1 つずつ、1 組の部分文字列が得られます。 2 つの部分文字列を連結すると、結果の文字列が正方形の文字列になる、つまり長さが偶数で、前半と後半がまったく同じであるという特性を持つペアがいくつあるかを数えたいとします。 

したがって、S[p..q] と T[u..v] を選択した場合、文字列 X に対して連結 S[p..q] + T[u..v] は XX の形式でなければなりません。これは、2 つの部分文字列の合計の長さが偶数でなければならないことをすでに暗示しており、より構造的には、長さ k の接頭辞は長さ k の接尾辞に等しいことを意味します。ここで、k は全長の半分です。 

どちらの文字列も長さは最大 5000 であるため、それぞれの部分文字列の数は最悪の場合で約 2500 万、ペアの数は約 6.25e14 になります。 すべてのクアドルプルを直接列挙することは完全に不可能です。 どのソリューションでも、すべての部分文字列ペアの反復を避け、代わりに反復構造を再利用する必要があります。 

一般的な障害モードは、連結がペアごとに単純な方法で周期的であるかどうかのみをチェックすることから発生します。 各チェックの部分文字列の長さは線形であっても、n 全体では依然として 3 次であり、非常に遅すぎます。 

もう 1 つの微妙なエッジ ケースは、正方形が S と T の間の境界を非常にアンバランスにまたがる場合です。 たとえば、一方の側が前半部分のほぼすべてに寄与し、もう一方の側が小さなサフィックスに寄与する可能性があるため、各文字列内の対称性を独立して仮定するメソッドでは、これらの構成が失われます。 

## アプローチ

 ブルートフォース手法では、S のすべての部分文字列と T のすべての部分文字列を選択して連結し、前半と後半を比較することで結果が正方形の文字列であるかどうかを確認します。 これは定義に直接従っているので正しいですが、そのコストは部分文字列のペアの数によって支配され、最悪の場合 O(n^4) 個の状態と O(n) 個の状態ごとの検証となり、n = 5000 の場合でも実行不可能になります。 

重要な点は、連結された文字列を実際に実体化する必要がないということです。 スクエア条件は、前半と後半の対応する位置を比較するだけであり、それらの位置は常に S または T のいずれかから構造化された方法で取得されます。 正方形の分割点を修正すると、条件は S と T の接尾辞の接頭辞間の一致制約に減ります。 

条件を書き直すと役に立ちます。 全長が2Lだとします。 次に、すべての i について、位置 i と位置 i+L が等しい必要があります。 これらの位置は、S 内、T 内、または S と T の間の境界を横切る可能性があります。部分文字列を個別に選択する代わりに、連結によって形成された仮想文字列の 2 つのコピーを整列させ、一貫したセグメントのペアを数えるという観点から考えることができます。 

重要な構造の単純化は、視点を逆転させることです。S と T から部分文字列を選択する代わりに、正方形の考えられる中心を列挙し、外側に拡張します。 正方形の文字列はその前半によって完全に決定され、それらの連結が有効な前半と後半の位置合わせを形成するように、S の部分文字列と T の部分文字列を選択する方法を効果的に数えています。 これにより、等しい長さの制約の下で一致するセグメントのペアがカウントされます。

問題を、正方形の 2 つの半分として機能する S と T からの等しい長さの部分文字列のペアを数えることに減らすことができます。 固定長 L の場合、A = B となるような、S からの部分文字列 A と T からの B のペアが必要です。そして、そのような各ペアは、A と B を左/右半分に分割する方法に対応する複数の 4 倍数に寄与します。 組み合わせ係数は、正方形内の分割点を選択する方法の数に応じて線形になります。 

これを効率的に行うために、部分文字列をハッシュごとにグループ化します。 長さ L ごとに、S と T の互いに等しい部分文字列がいくつあるかを数え、寄与を集計します。

 ## アルゴリズムのチュートリアル

 この問題を再定式化して、S と T で一致する部分文字列を数え、正方形内で出現する可能性がある方法の数によって各一致に重みを付けます。 

1. 両方の文字列のローリング ハッシュを事前計算して、部分文字列の比較を O(1) 時間で実行できるようにします。 これにより、文字を明示的に比較することなく、等しい部分文字列を識別できるようになります。 
2. 1 から min(|S|, |T|) までのすべての可能な部分文字列長 L について、長さ L の S のすべての部分文字列を列挙し、それらのハッシュ頻度を保存します。 T に対して概念的に同じことを行います。 

これが長さによって構造化されている理由は、等しい長さの部分文字列のみが正方形の文字列の半分を形成できるためです。 
3. 各長さ L について、周波数のハッシュ マップを使用して、S と T の間の等しい部分文字列を照合します。 部分文字列パターンが S で cS 回、T で cT 回出現する場合、一致する半分を選択するには cS × cT の方法があります。 
4. このような一致した各ペアは、前半がその部分文字列で後半が同じ部分文字列である正方形の文字列に対応します。 ここで、この正方形を S の部分文字列とその後に続く T の部分文字列に分割できる方法が何通りあるかを数える必要があります。 

これは、長さ 2L のウィンドウを左側のセグメントと右側のセグメントに分割するすべての方法を数えることになります。分割は 0 から 2L までの任意の場所で行うことができますが、有効な部分文字列境界に従って、左側の部分が S から取得され、右側の部分が T から取得されるように制約されます。 
5. 有効な一致ペアごとに、寄与は内部分割位置の L 個の選択肢です。 これは、S アライメントと T アライメントの間の正方形の境界が、等価制約を維持しながら連結境界を越えて移動する可能性があるために発生します。 
6. すべての長さおよびすべてのハッシュ グループにわたる寄与を合計します。 

中心的なアイデアは、4 倍を反復する代わりに、繰り返される部分文字列によって定義される正方形の「テンプレート」を反復し、それが S と T にわたって埋め込まれる方法が何通りあるかを数えるということです。 

これが機能する理由は、有効な 4 つ組が結果として得られる正方形の文字列を繰り返し半分に一意に分解するという不変条件に基づいています。 その半分は、選択されたアラインメントの S と T の両方で同一に出現する必要があり、逆に、内部分割は等価性制約に影響を与えないため、そのような共有部分文字列はカウントされた有効な埋め込み数を正確に誘導します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_hash(s, base=91138233, mod=972663749):
    n = len(s)
    h = [0] * (n + 1)
    p = [1] * (n + 1)
    for i, ch in enumerate(s):
        h[i+1] = (h[i] * base + (ord(ch) - 96)) % mod
        p[i+1] = (p[i] * base) % mod
    return h, p

def get_hash(h, p, l, r, mod=972663749):
    return (h[r] - h[l] * p[r-l]) % mod

def solve():
    S = input().strip()
    T = input().strip()
    n, m = len(S), len(T)

    hS, pS = build_hash(S)
    hT, pT = build_hash(T)

    ans = 0

    for L in range(1, min(n, m) + 1):
        freq = {}

        for i in range(n - L + 1):
            hs = get_hash(hS, pS, i, i + L)
            freq[hs] = freq.get(hs, 0) + 1

        for j in range(m - L + 1):
            ht = get_hash(hT, pT, j, j + L)
            if ht in freq:
                ans += freq[ht] * L

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、部分文字列の等価性クエリが定数時間になるように、両方の文字列の多項式ローリング ハッシュを構築します。 次に、考えられるすべての部分文字列長 L に対して反復処理を行います。各 L について、ハッシュをキーとする辞書を使用して、その長さの S のすべての部分文字列をカウントします。 次に、T の部分文字列をスキャンし、一致するハッシュが見つかるたびに寄与分を蓄積します。 

最後のステップでの L による乗算は、長さ 2L の正方形を形成するときに、等しい部分文字列の一致する各ペアを L 通りの異なる方法で中心に配置できるため、有効性を維持する正方形構造内の内部分割位置の数に対応します。 

理論的にはハッシュの衝突に注意する必要がありますが、一般的な競技プログラミング設定では、単一の大きな係数が受け入れられます。 

## 実用的な例

 S = "abab" および T = "ab" について考えてみましょう。 部分文字列の長さを列挙します。 

L = 1 の場合、S の部分文字列は「a」、「b」、「a」、「b」で、a と b の頻度は 2 と 2 です。 T の部分文字列は「a」、「b」です。 一致は、2 × 1 = 2 に寄与する「a」と 2 × 1 = 2 に寄与する「b」の合計 4 です。 

| Ｌ | S 部分文字列 | T 部分文字列 | 一致する | 貢献 |
 | --- | --- | --- | --- | --- |
 | 1 | a、b、a、b | ａ、ｂ | a:2×1、b:2×1 | 4 |

 L = 2 の場合、S 部分文字列は「ab」、「ba」、「ab」となり、カウントは ab:2、ba:1 になります。 T 部分文字列は「ab」です。 「ab」のみが周波数 2 × 1 = 2 と一致し、2 × 2 = 4 に寄与します。 

| Ｌ | S 部分文字列 | T 部分文字列 | 一致する | 貢献 |
 | --- | --- | --- | --- | --- |
 | 2 | アブ、バ、アブ | アブ | ab:2×1 | 4 |

 合計すると 8 となり、サンプルと一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 長さ L ごとに、S の O(n) 個の部分文字列と T の O(n) 個の部分文字列を列挙します。 
| スペース | O(n^2) | 最悪の場合のすべての部分文字列長にわたるハッシュ マップ |

 ## 特殊なケース

 重要なエッジ ケースは、両方の文字列が単一の繰り返し文字で構成されている場合です。 その状況では、長さ L のすべての部分文字列は同一であるため、周波数爆発が発生します。 このアルゴリズムは、長さによって集計し、組み合わせを乗算してカウントするため、これを正しく処理します。そのため、一致する部分文字列が多数ある場合でも、それらは長さごとに 1 つのハッシュ グループに圧縮されます。 

もう 1 つの特殊なケースは、一方の文字列が他方の文字列よりもはるかに短い場合です。 L に対するループは自動的に短い方の長さに上限を設定し、短い文字列から無効な部分文字列の抽出を試みないようにします。 

最後の微妙なケースは、衝突により異なる部分文字列が同一のハッシュを持つ場合です。 理論的には可能ですが、実際には、選択したモジュラスとベースの下では確率は無視できるものであり、競技プログラミング標準ではこのリスクを受け入れています。
