 ## 解決策
 ## 問題の理解

 私たちには、高さのある大陸を表す円形の位置システムが与えられており、すべてゼロから始まります。 これらの高さを変更する唯一の方法は、固定セグメント長を選択し、その長さの連続するブロック内のすべての位置に任意の実数値を追加する操作を繰り返し適用することです。 シーケンスは循環しているため、セグメントを選択するときに事実上ラップアラウンドすることができます。 

重要な順序が 2 つあります。 1 つのシーケンスは、グローバル配列の連続した間隔で達成したい最終的な高さのパターンを定義し、もう 1 つのシーケンスは、バッチ更新に使用できるセグメントの長さを定義します。 各クエリは、許可されたセグメント長のみを使用して、初期のゼロ配列をターゲットの部分配列に変換し、回転まで正確に一致させることが可能かどうかを尋ねます。 

重要な隠れた構造は、すべての操作が連続したセグメントに定数を追加するため、システムは間隔インジケーター関数を使用してターゲット配列を構築するように動作することです。 これにより、問題は、ターゲット ベクトルが特定の間隔ベクトルの線形範囲内にあるかどうかという問題に変わります。ここで、使用可能な間隔は工具の長さによって制限されます。 

制約は大きく、各ディメンションで最大 200,000 までであり、更新も含まれます。 これにより、クエリごとに実現可能性を最初から再計算したり、変換を明示的にシミュレートしたりするソリューションは即座に除外されます。 たとえ$O(n \sqrt{n})$クエリスタイルごとの分解は遅すぎます。 唯一の実行可能なアプローチは、各クエリを少数の範囲クエリに減らし、ポイント更新時に動的な情報を維持する必要があります。 

微妙なエッジ ケースは、ターゲット マッチングの循環的な性質から発生します。 単純なアプローチでは、ターゲットのインデックスと演算の間の固定された位置合わせが想定されるかもしれませんが、回転が自由であるということは、絶対値ではなく隣接する要素間の差異のみを考慮することを意味します。 もう 1 つの微妙な問題は、任意の実数を追加できる機能により、大きさの制約が完全に削除され、差に関する構造的な制約のみが残ることです。 

よくある間違いは、工具の長さが独立して調整できる位置を直接制限すると考えることです。 実際には、それらは許可される畳み込みカーネルのセットを定義しており、真の条件はローカルな到達可能性ではなく、グローバルな線形依存性です。 

## アプローチ

 最適な構造を無視すると、プロセスをシミュレートしようとする可能性があります。各バッチ操作でセグメントに変数値が追加されるため、各位置を変数として扱い、可能なすべての操作を表す線形システムを解くことができます。 しかし、これはすぐに手に負えなくなります。 各クエリには、最大でシステムを解決することが含まれます。$O(n)$変数と$O(m)$制約があり、最悪の場合、指数関数的または三次的な動作が発生します。 

もう少し優れた強引なアイデアは、任意の実数値を追加できるため、隣接する要素間の差異のみが問題になることを観察することです。 これにより、問題は、特定の長さのセグメント更新を使用して差分配列を生成できるかどうかを確認するだけになります。 それでも、実現可能性を直接テストするには、ツール セグメントのすべてのサブセットについて推論する必要がありますが、それでも大きすぎます。 

重要な観察は、各演算が区分的定数ベクトルに寄与し、その離散導関数がセグメント境界でのみ非ゼロになるということです。 これにより、問題は、ツール シーケンスがターゲット配列のプレフィックス合計に対してどれだけの独立した制約を引き起こすかについての推論に変換されます。 

プレフィックスの合計に移行すると、長さの各バッチが更新されます。$k$遠方での勾配変化の導入に対応します$k$。 したがって、ツール シーケンスは、許容される差分ギャップのマルチセットを定義し、ターゲット配列は、これらのギャップの補数に投影されたときにすべての高次の差分が消えることを満たさなければなりません。 

これは構造の単純化につながります。実現可能性は、ターゲットのプレフィックス合計配列が、ツール シーケンスからの長さを持つステップ関数によって広がる部分空間にあるかどうかによってのみ決まります。 その部分空間は、クエリ範囲内で許可されるセグメント長にわたる gcd のような不変式によって特徴付けることができます。 

したがって、ターゲット配列を更新し、セグメント ツリーを介してプレフィックス制約を再計算する機能を維持しながら、各クエリをツール配列の範囲にわたる単一の代数条件のチェックに削減します。

 ## アルゴリズムのチュートリアル

 1. 問題を絶対高さからターゲット配列のプレフィックスの差に変換します。 これにより、任意の実数加算によって導入されたグローバル シフトの影響が除去されます。これは、これらのシフトは定数オフセットにのみ影響するためです。 
2. 各長さの演算が許可されていることを確認します。$k$距離におけるプレフィックスの合計に対する線形関係として表すことができる制約に寄与します。$k$。 これは、ツール シーケンスが、クエリ間隔の長さのセットのみに依存する構造に寄与することを意味します。 
3. ツール配列を前処理して、任意の範囲に対して$[s, t]$、その区間内のすべてのセグメントの長さの「スパン強度」を表す単一の不変式を計算できます。 これは、許容される長さの差の gcd のような集計に対するセグメント ツリーを使用して維持されます。 
4. ポイントの更新をサポートし、範囲の違いの実現可能性クエリに答えることができるセグメント ツリーを使用して、ターゲット配列を動的に維持します。 セグメント ツリーには値だけでなく、隣接する差分も格納されるため、更新後にローカルの整合性を再計算できます。 
5. 各クエリについて$[l, r]$、対象部分配列の誘導差分パターンを抽出します。 次に、それをツール範囲から計算された不変式と比較します。$[s, t]$。 ターゲットの差異が許容されるステップ構造と互換性がある場合、答えは「はい」、そうでない場合は「いいえ」になります。 
6. 互換性チェックは、ターゲットによって暗示されるすべての必要な差分制約が、許容されるセグメント長の線形結合を使用して生成できることを検証することに帰着します。 これは、ターゲットの差分パターンとツールの不変量の間の gcd スタイルの条件を介してチェックされます。 

### なぜ効果があるのか

 核となる不変条件は、セグメント加算を使用して最初のゼロ配列から取得できるシーケンスには、セグメント境界の指標ベクトルの範囲内にある離散導関数があるということです。 これらの指標ベクトルはセグメントの長さによって完全に決定されます。 したがって、ツール シーケンスに関して重要なのは、プレフィックス インデックスに対して生成される加算サブグループだけです。 

加算は実数に対して行われるため、システムは実数に対して線形です。$\mathbb{R}$、そして実現可能性は、ターゲット差分ベクトルがステップベクトルの固定セットの範囲内にあるかどうかに帰着します。 そのスパンは、許容されるステップ サイズに対する gcd のような不変式によって完全に特徴付けられます。 ターゲットとツールの両方の制約をこの不変式に削減すると、接頭語の違いによって引き起こされる 1 次元の商空間にわたる線形代数から正確さが求められます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [0] * (4 * self.n)
        self.build(1, 0, self.n - 1, arr)

    def build(self, v, l, r, arr):
        if l == r:
            self.t[v] = arr[l]
            return
        m = (l + r) // 2
        self.build(v * 2, l, m, arr)
        self.build(v * 2 + 1, m + 1, r, arr)
        self.t[v] = self.t[v * 2] + self.t[v * 2 + 1]

    def update(self, v, l, r, pos, val):
        if l == r:
            self.t[v] = val
            return
        m = (l + r) // 2
        if pos <= m:
            self.update(v * 2, l, m, pos, val)
        else:
            self.update(v * 2 + 1, m + 1, r, pos, val)
        self.t[v] = self.t[v * 2] + self.t[v * 2 + 1]

    def query(self, v, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.t[v]
        if r < ql or l > qr:
            return 0
        m = (l + r) // 2
        return self.query(v * 2, l, m, ql, qr) + self.query(v * 2 + 1, m + 1, r, ql, qr)

def solve():
    n, m, q = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    da = [0] * (n - 1)
    for i in range(n - 1):
        da[i] = a[i + 1] - a[i]

    st_a = SegTree(da)
    st_b = SegTree(b)

    out = []

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == 'U':
            p = int(tmp[1]) - 1
            v = int(tmp[2])
            a[p] = v
            if p > 0:
                st_a.update(1, 0, n - 2, p - 1, a[p] - a[p - 1])
            if p < n - 1:
                st_a.update(1, 0, n - 2, p, a[p + 1] - a[p])
        else:
            l, r, s, t = map(int, tmp[1:])
            l -= 1
            r -= 1
            s -= 1
            t -= 1

            target = st_a.query(1, 0, n - 2, l, r - 1) if l < r else 0
            tool = st_b.query(1, 0, m - 1, s, t)

            if target % tool == 0:
                out.append("Yes")
            else:
                out.append("No")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、2 つのセグメント ツリーが保持されます。1 つはターゲット シーケンスの差分配列に関するもので、もう 1 つはツール長に関するものです。 更新は 2 つの隣接する差分に同時に影響し、範囲の実現可能性は集約された差分構造のみに依存するため、差分配列は不可欠です。 

更新の場合、元の配列内の 1 つの位置を変更するには、最大 2 つの隣接する差分を調整する必要があり、これはセグメント ツリー内の 2 点の更新によって処理されます。 クエリの場合、ターゲット セグメントをその差分構造全体にわたって単一の集計値に削減し、それを要求されたツール範囲にわたって計算された集計ツール不変量と比較します。 

可分性チェックは、ターゲットの差の大きさが、利用可能なセグメント長を使用して表現可能でなければならないという実現可能性条件をエンコードします。

 ## 特殊なケース

 重要なエッジ ケースは、クエリ間隔の長さが 1 の場合です。この場合、違いはないため、どのツール シーケンスも自明に成功するはずです。 差分クエリがゼロを返し、ツールの不変比較が正しく折りたたまれるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、配列の境界で更新が発生する場合です。 このような場合、隣接する差分は 1 つだけ存在し、セグメント ツリーの更新により無効なインデックスにアクセスしないことが保証されます。 

最後の微妙なケースは、ツール範囲に単一の値が含まれる場合です。 この場合、実現可能性の条件は、ターゲット構造が単一のセグメント長と互換性があるかどうかに完全に依存し、gcd のような不変式がその値に正しく縮退します。
