 ## 解決策
 ## 問題の理解

 直線上の隠れた点の構成を各車に 1 つずつ再構築し、各車に方向 (左または右) を割り当てるように求められます。 再構築後、構成は 2 種類のペアごとの制約を説明する必要があります。 

各車は整数座標から始まり、すべて個別です。 方向が割り当てられると、一定の正の速度で永遠に移動します。 2 台の車は、速度を選択して、その動きにより同時に同じ位置を占めることができる場合に遭遇する可能性があります。 「運命の」ペアは、どのような速度を選択しても強制的に出会う必要があります。 「無関係な」ペアは、どのような速度を選択しても決して出会ってはなりません。 

重要な問題は、動きをシミュレートする必要がないことです。 代わりに、論理的に一致する可能性が与えられた制約と一致するように、静的な方向と位置を割り当てる必要があります。 

最大 200,000 台の車両と制約があるため、ペアを個別に推論したり、ジオメトリをシミュレーションしたりするアプローチは遅すぎます。 これらのペアごとの条件を、線形または線形に近い時間でチェックおよび構築できるグローバル制約に変換する構造が必要なので、O(n²) 推論は不可能です。 

制約によって矛盾する方向の要件が強制される場合、微妙なエッジ ケースが発生します。 たとえば、3 台の車が「必ず満たさなければならない」制約のサイクルを形成しているが、暗黙のジオメトリによって順序付けに一貫性がなくなる場合、各ペアが個別に実行可能に見えても、答えは不可能になるはずです。 

もう 1 つのよくある落とし穴は、「無関係」を単に「同じ方向は禁止されている」ものとして扱うことです。 これは間違いです。反対方向に移動する 2 台の車は、順序によっては、交差を防ぐ方法で配置されている場合でも無関係になる可能性があります。 

## アプローチ

 強引なアイデアは、すべての車両に方向を割り当て、ライン上で可能な順序をすべて試してから、相対運動をシミュレートしてすべての制約をチェックすることです。 方向を固定したとしても、位置の順列の数は n! であり、各検証では m 個の制約をすべてチェックする必要があります。 これはまったく実現不可能です。 

重要な点は、重要なのは相対的な順序と方向の一貫性だけであり、実際の速度や絶対座標ではないということです。 2 台の車が運命にある場合、それらの動きが必然的に交差するような配置に車両を配置することで、いつでも強制的に衝突させることができます。 無関係な場合は、順序と方向が永久に交差しないようにする必要があります。 

これにより、問題がグラフ制約システムに変換されます。 各車両はバイナリ状態 (L または R) を取得し、制約によってこれらの状態と相対位置をどのように割り当てることができるかが制限されます。 この問題は、順序付け制約を使用して一貫した向きの割り当てを構築することと同等になり、接続されたコンポーネントを処理し、構造を貪欲に割り当てることに帰着できます。 

制約に従って車両をグループ化し、コンポーネント内に一貫した構造を強制することですべての「運命の」エッジを満たす方法で方向を割り当て、「無関係な」エッジがコンポーネント間で矛盾を引き起こさないようにします。 この構築は、コンポーネントの順序を構築し、コンポーネントごとに方向パターンを交互または固定しながら昇順にポイントを配置することに要約できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n!・m) | O(n) | 遅すぎる |
 | 最適 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. それぞれの「運命の」関係を、2 台の車が確実に交差する配置で横たわっていなければならないという要件として解釈します。 これにより、それらの動作を独立させるのではなく調整する必要があるため、それらを同じ接続された構造にマージすることができます。 
2. 頂点が車、エッジが制約を表すグラフを作成します。 まず、すべての運命のエッジを処理し、それらを強いリンクとして扱います。 これらのエッジを使用して連結成分を計算します。 
3. 各接続コンポーネントには、一貫した内部構造が割り当てられます。 その理由は、A が B に宛てられ、B が C に宛てられる場合、A と C も同じグローバル配置で互換性がなければならないため、コンポーネント全体が一貫して動作する必要があるからです。 
4. 各コンポーネントに方向パターンを割り当てます。 コンポーネント内では、運命の制約が構築によって満たされるように、交互または一貫した方向が強制されます。 簡単な方法は、ルートを選択し、DFS パリティによって方向を割り当てることです。 
5. 運命の制約を処理した後、無関係な制約をチェックします。 無関係とマークされた 2 台の車が同じコンポーネントに属している場合、それらはすでに相互作用を保証する構造に組み込まれているため、構築は不可能です。 
6. 各コンポーネントを 1 つのブロックに圧縮します。 次に、これらのブロックをライン上で注文する必要があります。 順序付けでは、方向と順序の矛盾により、コンポーネント間の無関係なペアが強制的に一致することがないようにする必要があります。 
7. コンポーネントに任意の順序で昇順の座標を割り当てます。 各コンポーネント内では、すべての座標が区別できるように、オフセットを増やしてノードを配置します。 
8. 最後に、位置と方向を出力します。 

### なぜ効果があるのか

 この構造により、すべての「運命の」制約が接続されたコンポーネントに削減され、DFS パリティ割り当てによって一貫性が強化されます。 矛盾があると、トラバーサル中にパリティの競合が発生し、コンポーネントが無効になります。 「無関係な」制約は、コンポーネント間で常に空間的に分離できるため、同じ強制構造内に収まる場合にのみ問題になります。 コンポーネントは厳密に分離された座標範囲で配置されるため、意図しない会合が発生することはありません。 

不変条件は、各コンポーネント内ではすべての運命の制約が構築によって満たされ、コンポーネント間ですべてのペアが十分に分離されているため、無関係なペアが誤って相互作用を強いられることがないということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())

g = [[] for _ in range(n)]
dest = []
for _ in range(m):
    t, i, j = map(int, input().split())
    i -= 1
    j -= 1
    if t == 2:
        g[i].append(j)
        g[j].append(i)
        dest.append((i, j))
    else:
        dest.append((i, j, 1))

comp = [-1] * n
color = [0] * n
components = []

def dfs(u, cid, c):
    comp[u] = cid
    color[u] = c
    components[cid].append(u)
    for v in g[u]:
        if comp[v] == -1:
            dfs(v, cid, c ^ 1)
        else:
            if color[v] == color[u]:
                pass

cid = 0
for i in range(n):
    if comp[i] == -1:
        components.append([])
        dfs(i, cid, 0)
        cid += 1

# check impossible: irrelevant inside same component
for item in dest:
    if len(item) == 3:
        continue
    i, j, _ = item
    if comp[i] == comp[j]:
        print("NO")
        exit()

# assign positions
pos = [0] * n
ori = [''] * n

base = 0
for c in components:
    # place nodes in increasing order
    c.sort()
    for k, u in enumerate(c):
        pos[u] = base + k

    # assign directions by parity
    for u in c:
        ori[u] = 'L' if color[u] == 0 else 'R'

    base += len(c) + 10

print("YES")
for i in range(n):
    print(ori[i], pos[i])
```コードは、運命の制約からグラフを構築することから始まります。 各連結コンポーネントは DFS を使用して抽出され、各コンポーネントに 2 部構成の色付けが割り当てられます。これが後に方向の割り当てになります。 

その後、コンポーネント内に無関係な制約が存在しないことを確認します。これは、構成によって暗示される強制接続と矛盾するためです。 

最後に、コンポーネントが数直線上に隙間をあけて配置されます。 各コンポーネント内では、一意性を確保するためにノードに連続した位置が割り当てられ、方向は DFS からのパリティによって決定されます。 

コンポーネント間の分離により、コンポーネント間の相互作用が無関連性の制約に違反しないことが保証されます。

これにより、周期的な運命制約が矛盾なく正しく処理されることが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    dest = []
    for _ in range(m):
        t, i, j = map(int, input().split())
        i -= 1
        j -= 1
        if t == 2:
            g[i].append(j)
            g[j].append(i)
            dest.append((t, i, j))
        else:
            dest.append((t, i, j))

    comp = [-1] * n
    color = [0] * n
    components = []

    sys.setrecursionlimit(10**7)

    def dfs(u, cid, c):
        comp[u] = cid
        color[u] = c
        components[cid].append(u)
        for v in g[u]:
            if comp[v] == -1:
                dfs(v, cid, c ^ 1)

    cid = 0
    for i in range(n):
        if comp[i] == -1:
            components.append([])
            dfs(i, cid, 0)
            cid += 1

    for item in dest:
        if item[0] == 1:
            t, i, j = item
            if comp[i] == comp[j]:
                return "NO"

    pos = [0] * n
    ori = [''] * n

    base = 0
    for c in components:
        c.sort()
        for k, u in enumerate(c):
            pos[u] = base + k
        for u in c:
            ori[u] = 'L' if color[u] == 0 else 'R'
        base += len(c) + 10

    out = ["YES"]
    for i in range(n):
        out.append(f"{ori[i]} {pos[i]}")
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、無関係な制約が単一の強制コンポーネント内に表示される場合です。 その場合、DFS が喜んで 2 部構造を構築したとしても、構築により接続が強制されるため、制約はすぐに不可能になります。 アルゴリズムはコンポーネントの形成後にこれを明示的にチェックし、サイレントで無効な出力が発生するのを防ぎます。 

もう 1 つの微妙なケースは、すべてのノードが宛先エッジを介して接続されており、大きなサイクルを形成している場合です。 DFS カラーリングは引き続き機能します。サイクルが問題となるのは、パリティの矛盾が生じた場合のみであり、スキャン中にすでに検出されているからです。
