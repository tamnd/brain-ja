 ## 解決策
 ## 問題の理解

 整数配列が与えられ、非常に具体的な変換を実行できます。つまり、3 つのインデックスを昇順に選択し、左端の位置を後の 2 つの値の差分で上書きします。 各操作は配列の右側の構造を消費し、前の位置に値を挿入します。 

目標は、ローカルな意味で配列を最適化することではなく、最大 n 回のそのような変換後にシーケンス全体を非降順でソートすることです。 有効な操作シーケンスを印刷したり、シーケンスが存在しないことをレポートしたりすることができます。 

すべてのテスト ケースにわたって n が 2 · 10^5 に達できるという制約により、テスト ケースごとに解が線形または線形に近いことが強制されます。 操作ごとにグローバルな調整を繰り返し検索またはシミュレーションする戦略は、O(n^2) の動作でも壊滅的な結果となるため、遅すぎます。 

重要な点は、この操作では任意の再割り当てが許可されていないことです。 値を自由に設定することはできず、先頭の位置を後の 2 つの位置の差に置き換えるだけです。つまり、制御された最終形状を生成する構造を慎重に選択する必要があります。 

単純なアイデアは、反転を繰り返し修正することです。a[i] > a[i+1] となるペアを見つけ、何らかの操作を使用してそれを修復しようとします。 これは失敗します。操作は後の値を使用して以前のインデックスに影響を与え、ローカル修正を繰り返すと以前に修正された構造がすぐに破壊されるためです。 たとえば、[3, 1, 2] のような配列では、最初の反転を修復しようとすると、予期せずに新しい反転が左右に導入される可能性があり、単調な進行の保証はありません。 

誤解を招くもう 1 つのシナリオは、配列が [5、4、3、2、1] のように厳密に減少している場合です。 差分を使用して要素を徐々に「持ち上げる」ことができるように見えますが、この操作では後の要素の減算のみが可能であり、慎重に配置されたアンカー値がなければ、各位置を独立して制御することはできません。 

さらに深刻な問題は、この操作では常に任意の配列をソートできるわけではないということです。これは、この操作では強い構造的制限が維持されるためです。生成される値は常に後の要素の差分であるため、システムは自由な書き換えシステムではなく、制約された線形スパンのように動作します。 

## アプローチ

 ブルートフォース解釈では、許可された操作をシミュレートし、反転を貪欲に減らそうとします。 各操作は 1 つのインデックスに影響し、他の 2 つのインデックスに依存するため、単純なシミュレーションでは位置ごとに O(n) 個の調整を試みる可能性があり、O(n^2) 個またはさらに悪い操作が発生する可能性があります。 n は 2・10^5 までであるため、これは実行できません。 

重要な点は、実際には古典的な意味で配列を並べ替える必要がないということです。 必要なのは、許可された操作を使用して非減少シーケンスを構築することだけです。 これは、受け身ではなく建設的に考える必要があることを示唆しています。 

このブレークスルーは、後続の要素の差分を使用して位置を上書きできることに気づいたことから生まれます。これは、最後のいくつかの要素を値を生成するための「ツールキット」として扱うことができることを意味します。 サフィックス内で制御されたモノトーン構造を確保できれば、それを逆方向に伝播して、一貫した方法で以前の要素を上書きできます。 

標準的な建設的な解決策は、最後の 3 つの位置をアンカーとして使用し、操作を右から左に繰り返し適用することに依存しています。 サフィックスで制御されたパターンを強制すると、非減少順序を維持する方法で、以前の各要素を個別に調整できます。 

ブルート フォースは反転を直接修正しようとするため、ローカルでのみ機能します。 操作には方向性があり、接尾辞の構造に依存するため、失敗します。 この建設的なアプローチは、最初に最後に安定したバックボーンを作成し、それを使用してプレフィックスを体系的に上書きするため、成功します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 建設的な接尾語アンカーリング | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず有効な構築が可能かどうかを判断して、ソリューションを構築します。 配列のサイズが 3 の場合、単純な変換を超える意味のある変換は存在しないため、許可された制約の下ですでに並べ替え可能かどうかを直接確認できます。 

大きな配列の場合は、端から始まる単調な構造を構築します。 中心となるアイデアは、最後の 3 つの要素を作業バッファとして使用し、以前の要素を安全に上書きできるパターンを段階的に適用することです。 

### ステップ

 1. 配列がすでに非減少である場合は、ゼロ演算を出力して停止します。 これにより、工事が必要ない場合の無駄な工事を回避できます。 
2. n が小さく、安定したサフィックス構築をサポートできない場合は、実現可能性を直接チェックします。 特に、サイズ 3 の配列は非常に限られた方法でしか調整できないため、まだソートされていない場合は修正できません。 
3. 最後の 3 つの要素を固定アンカー領域として扱います。 必要な中間値を生成できる、制御された非減少構造となることを目指します。 
4. インデックス n-3 から開始して右から左に移動します。 各位置 i について、a[i+1] − a[n] を使用して a[i] を上書きします。これは、i < i+1 < n であるため有効です。 これにより、以前の値が接尾辞構造に徐々に整列されます。 
5. すべてのプレフィックス要素を処理した後、配列は、一貫したアンカーの違いにより減少しないことが保証される、サフィックスによって生成されたパターンと位置合わせされます。 
6. 記録されたすべての操作を出力します。 

重要な直観は、私たちは決して直接「比較を修正」しようとしないということです。 代わりに、すべての位置が安定した接尾辞要素の制御された線形表現になるように強制します。 

### なぜ効果があるのか

 正確さは、生成の基礎として機能する安定したサフィックスを維持することで得られます。 すべての代入では、接頭辞要素が、その後変更されることのない 2 つの後続要素の固定線形結合に置き換えられます。 これにより、一度設定した位置を再度設定する必要がなくなります。 

各 a[i] はサフィックスに関連する同じ構造規則を使用して置換されるため、結果として得られるシーケンスの順序付けは一貫したものになります。 サフィックスは不変アンカーとして機能し、以前のすべての値はモノトーン互換の方法でサフィックスから導出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # already sorted check
        ok = True
        for i in range(n - 1):
            if a[i] > a[i + 1]:
                ok = False
                break

        if ok:
            print(0)
            continue

        # impossible for n == 3 if not already sorted
        if n == 3:
            print(-1)
            continue

        ops = []

        # anchor: use last two positions to stabilize
        # we repeatedly enforce structure from right side
        for i in range(n - 2, 0, -1):
            # ensure i-1 becomes controlled via last two elements
            ops.append((i, i + 1, n))

        print(len(ops))
        for x, y, z in ops:
            print(x, y, z)

if __name__ == "__main__":
    solve()
```このコードでは、配列がすでにソートされているかどうかを最初にチェックします。ソートされている場合は操作が必要ないためです。 次に、最小の非自明なケースを個別に処理します。これは、要素が 3 つだけでは、無秩序を修復できる意味のある変換シーケンスが存在しないためです。 

構築フェーズでは、右から左へオペレーションを構築します。 各操作では、現在の位置と 2 つの固定サフィックス位置が使用され、すべての変換が安定したインデックスに固定されることが保証されます。 最終的な妥当性はシミュレーションではなく構造に依存するため、操作は明示的に適用されるのではなく記録されます。 

微妙な点は、z インデックスとして常に n を使用することです。 これにより、アンカーが決して変更されなくなります。これは正確さのために不可欠です。 移動ターゲットを使用すると、不変条件が無効になり、単調性の保証が破られます。 

## 実用的な例

 ### 例 1

 入力:```
5
5 -4 2 -1 2
```単調でない配列から始めるので構築を進めます。 操作は右から左に生成されます。 

| ステップ | 操作 | 配列効果 (概念) |
 | --- | --- | --- |
 | 1 | 3 4 5 | サフィックス | を使用して位置 3 を更新します。 
| 2 | 2 3 5 | サフィックス | を使用して位置 2 を更新します。 
| 3 | 1 2 5 | サフィックス | を使用して位置 1 を更新します。 

演算を適用すると、各プレフィックス要素はサフィックスから導出された一貫した差分パターンと一致し、非減少シーケンスが生成されます。 

これは、アンカーリングを繰り返すことで、隣接する要素を直接比較することなく、以前の不一致をどのように排除するかを示しています。

```| ステップ | 操作 | 配列効果 (概念) |

これは、小規模なインスタンスには明示的な実現可能性の処理が必要であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各インデックスは最大 1 つの操作を生成し、配列のスキャンは 1 回だけです。 
| スペース | O(1) おまけ | 操作のリストのみが保存されます。 

入力サイズの合計が 2 · 10^5 に達する可能性があるため、線形複雑さが必要になります。 二次方程式のアプローチでは制限時間を超えてしまいます。 この構築ではシミュレーションを完全に回避し、直接操作の生成に依存します。

 ## 特殊なケース

 n = 3 の場合、配列がまだソートされていない場合、アルゴリズムは再構築の試行を明示的に拒否します。 これが必要なのは、完全な配列自体を超えて 3 つの異なるインデックスを選択する柔軟性がないため、変換によって新しい順序関係を作成できないためです。 

すでにソート済みの配列の場合、操作をスキップすると、不必要な自己変更が防止されます。 操作が許可されていても、慎重に制御しないと、操作を適用すると単調性が崩れる可能性があります。 

より大きなサイズの配列を厳密に減少させる場合でも、すべてのプレフィックスが同じ安定したエンドポイントを基準にして書き換えられるため、サフィックス アンカー戦略により一貫した変換シーケンスが生成されます。 これにより、既に変更されたプレフィックス値を使用して位置が書き換えられることがないため、発振や矛盾した更新が防止されます。
