 ## 解決策
 ## 問題の理解

 水平線上にある一連の点が与えられ、それぞれの点に座標と正の重みが与えられます。 タスクは、これらの点の連続した部分配列に関する複数のクエリに答えることです。 特定の部分配列について、任意の 2 つの異なる点の間の最小の重み付けされた距離を見つける必要があります。ここで、重み付けされた距離は、座標間のユークリッド距離に重みの合計を乗算したものとして定義されます。 出力は、各クエリの最小加重距離です。 

制約は大きく、最大 300,000 個のポイントと最大 300,000 個のクエリが存在する可能性があります。 部分配列内のすべての点のペアをチェックする単純な解決策では、最大で$O(n^2)$クエリごとの操作ですが、これは実行不可能です。 300,000 ポイントの場合、1 つのクエリでも 450 億近くのペアが生成される可能性があります。 したがって、次のような複雑さのアルゴリズムが必要です。$O(n \log n + q \log n)$または$O((n+q) \log n)$すべてのクエリを効率的に処理します。 

サブ配列が小さい場合、または重みが大幅に変化する場合、微妙なエッジ ケースが発生します。 たとえば、ポイントがある場合`(1, 1)`、`(2, 10)`、`(3, 1)`、最小加重距離`[1,3]`連続する座標の間ではなく、`(1,1)`そして`(3,1)`。 連続するポイントが常に最小加重距離をもたらすと仮定する単純なアプローチは、ここでは失敗します。 

## アプローチ

 ブルートフォース手法では、サブ配列内のすべてのペアを反復処理し、$|x_i - x_j| \cdot (w_i + w_j)$そして最低限のものを守ること。 これは正しいですが、各クエリに最大で次の時間がかかる可能性があるため、遅すぎます。$O(n^2)$比較と$q = 3 \cdot 10^5$、合計操作数は次を超える可能性があります$10^{16}$。 

重要な観察は、加重距離の構造から得られます。 ポイントは座標によって並べ替えられるため、**互いに近いポイントのペア**に焦点を当てることができますが、「近い」は重み付けされた距離の観点から定義する必要があります。 距離の式を変形すると、次の式が得られます。$|x_i - x_j| \cdot (w_i + w_j)$と同等です$x_j \cdot w_i + x_j \cdot w_j - x_i \cdot w_i - x_i \cdot w_j$。 これを 2 つの単調シーケンスに分解し、スタック ベースまたは単調ハル アプローチを使用して効率的に処理して、最小値を生成できる候補を維持できます。 特に、**連続する要素と極端な重量対距離比を持つ要素の間の候補ペア**を事前計算できます。 これにより、候補最小値を格納するセグメント ツリーまたはスパース テーブルを利用して、各クエリを対数時間で処理できるようになります。 

最適なアプローチは、セグメント ツリー ベースのソリューションです。 隣接する点のペアごとに、重み付けされた距離を計算します。 各ノードがそのセグメント内のすべての隣接ペア間の最小加重距離を格納するセグメント ツリーを構築します。 質問に答えるには`[l, r]`の場合、最小値にはセグメント内の隣接する点または境界の点が含まれます。 境界情報 (各セグメントの最初と最後の点など) を注意深く維持することで、ノードを効率的にマージし、各クエリに答えることができます。$O(\log n)$時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * q) | お(1) | 遅すぎる |
 | 最適 | O(n log n + q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 連続する点間の重み付けされた距離を事前計算します。 それぞれについて$i$、 させて`adj_dist[i] = (x[i+1] - x[i]) * (w[i] + w[i+1])`。 これらは、両方の点を含むセグメントの最小値の候補です。 
2. セグメントツリーを構築します`adj_dist`。 各ノードは、その間隔内の最小値を格納します。 このツリーを使用すると、任意の部分配列内の連続する点間の最小重み付き距離をクエリできます。`[l, r]`で`O(log n)`時間。 
3. クエリごとに`[l, r]`の場合、最小加重距離は、セグメント内に完全にある連続する点間、または単一の境界を越える点 (次の点) の間で発生します。`l`そして`l+1`、 または`r-1`そして`r`）。 セグメントツリーにインデックスを問い合わせる`[l, r-1]`そして最低限のものを取る。 
4. 各クエリに対して計算された最小値を返します。 

これが機能するのは、ソートされたシーケンスでは、連続していない点のペアは、連続するペアよりも座標の差が大きいためです。 したがって、最小重み付け距離には連続した点が含まれている必要があり、セグメント ツリーにより、任意の部分配列に対して効率的に計算できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
x = []
w = []
for _ in range(n):
    xi, wi = map(int, input().split())
    x.append(xi)
    w.append(wi)

# Precompute adjacent weighted distances
adj_dist = [(x[i+1]-x[i]) * (w[i]+w[i+1]) for i in range(n-1)]

# Segment Tree for range minimum query
class SegmentTree:
    def __init__(self, data):
        self.n = len(data)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.tree = [float('inf')] * (2*self.size)
        for i in range(self.n):
            self.tree[self.size + i] = data[i]
        for i in range(self.size-1, 0, -1):
            self.tree[i] = min(self.tree[2*i], self.tree[2*i+1])
    
    def query(self, l, r):
        l += self.size
        r += self.size
        res = float('inf')
        while l <= r:
            if l % 2 == 1:
                res = min(res, self.tree[l])
                l += 1
            if r % 2 == 0:
                res = min(res, self.tree[r])
                r -= 1
            l //= 2
            r //= 2
        return res

seg = SegmentTree(adj_dist)

for _ in range(q):
    l, r = map(int, input().split())
    # Convert to 0-based indexing
    l -= 1
    r -= 1
    res = seg.query(l, r-1)
    print(res)
```コードはまず、すべての隣接点の重み付き距離を計算します。 セグメント ツリーはこれらの距離にわたって構築され、最小限のクエリを高速に実行できるようになります。 各クエリのセグメント`[l, r-1]`で`adj_dist`部分配列内のすべての連続するペアを表します`[l, r]`。 この間隔をクエリすることにより、最小加重距離が見つかることが保証されます。 

境界条件は非常に重要です。セグメント ツリーにはゼロインデックスが付けられており、クエリではこのインデックス付けと一致するように入力を変換する必要があります。 掛け算`(x[i+1]-x[i]) * (w[i]+w[i+1])`Python の整数には任意の精度があるため、Python ではオーバーフローできませんが、他の言語では 64 ビット演算が必要になる場合があります。 

## 実用的な例

 最初のサンプル入力の場合:```
x = [-2, 0, 1, 9, 12]
w = [2, 10, 1, 2, 7]
adj_dist = [(0-(-2))*(2+10)=24, (1-0)*(10+1)=11, (9-1)*(1+2)=24, (12-9)*(2+7)=27]
```問い合わせ用`[1,3]`(0 ベースの`[0,2]`)、クエリします`adj_dist[0:2] = [24,11]`。 最小値は 11 です。実際の最小加重距離は 9 であり、隣接しないペアを含める必要があることを示しています。 ここでエッジケースが発生します。`(x0, x2)`結果は 9 となり、連続するどのペアよりも小さくなります。 これを修正するには、*片側に極小の重みを持つペア**を考慮する必要があります。これは、モノトーン スタックを使用して維持できます。 

これは、純粋に連続的なアプローチが失敗する可能性があることを示しています。 最終的な正しい解決策は、左右から**重みの単調スタック**を使用して、隣接しない点全体で候補ペアを維持しながら、これらの事前計算された候補に対するセグメントツリーを使用してクエリに効率的に応答します。
