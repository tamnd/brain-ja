 ## 解決策
 ## 問題の理解

 配列を変更して、隣接する配列の両方より厳密に大きい位置が存在しないようにする必要があります。 このような位置は極大値と呼ばれます。 最初と最後の要素には近傍が 1 つしかないため、極大値になることはありません。 

各操作で 1 つの要素を 1 から 1 までの任意の値に変更できます。$10^9$。 目標は、変更された位置の数を最小限に抑え、結果として得られる有効な配列を 1 つ出力することです。 

すべてのテスト ケースの要素の合計数は最大で$2 \cdot 10^5$。 2 秒の制限があるため、線形または線形に近いソリューションは完全に安全です。 二次アルゴリズムでは、大まかに次のものが必要になります。$4 \cdot 10^{10}$最悪の場合の操作はあまりにも多すぎます。 

誤って対処しやすい状況がいくつかあります。 

連続するピークを考慮します。```
1 3 1 3 1
```位置 2 と 4 は両方とも極大値です。 各ピークを下げることによってそれらを個別に修正する場合、2 つの操作を使用します。 より良い解決策は、中間の要素を変更することです。```
1 3 3 3 1
```必要な操作は 1 つだけです。 すべてのピークを個別に処理すると、この最適化が失われます。 

もう 1 つの注意が必要なケースは、谷で区切られた 3 つの連続した山です。```
2 1 3 1 3 1 3
```中央の谷を十分に大きな値に変更すると、隣接する 2 つのピークが一度に削除されます。```
2 1 3 3 3 1 3
```後は最後のピークだけが残ります。 貪欲な戦略では、このパターンを認識する必要があります。 

境界位置にも注意が必要です。 で```
5 1 5
```中央の要素のみに 2 つの隣接要素があるため、位置 1 と 3 は、その値に関係なく極大値になることはできません。 誤ってチェックすると、誤った結果が生成されます。 

## アプローチ

 ブルート フォース ビューでは、すべての極大値を検出し、それを個別に修正します。 1 つの可能性は、各ピークが隣接するピークの 1 つより大きくならないまで下げることです。 すべての操作で少なくとも 1 つのピークが破壊されるため、このアプローチは正しいです。 

弱点は山と谷が交互に現れるときに現れます。```
1 3 1 3 1
```中央の要素を一度変更すると両方のピークが削除されますが、両方のピークを個別に修正するには 2 つの修正が必要です。 すべてのピークは独立して処理されるため、近くのピーク間の相互作用は無視されます。 

重要な観察点は、パターンが```
peak - valley - peak
```一回の操作で対応できます。 ポジションの場合$i-1$そして$i+1$ピークであり、位置が増加しています$i$に```
max(a[i-1], a[i+1])
```両方の極大値を同時に削除します。 

これは、左から右にスキャンすることを示唆しています。 2 つのピークが 1 つの要素だけで区切られている場合は、その中間の要素を変更して先に進みます。 それ以外の場合、孤立したピークは個別に修正されます。 

すべての位置は一定の回数だけ検査されるため、アルゴリズム全体が線形時間で実行されます。

 | ブルートフォース | O(n) | お(1) | 常に最適であるとは限りません |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. アレイをスキャンし、どの位置が極大値であるかを記録します。 
2. 配列を左から右に走査します。 
3. いつでもポジション`i`そして`i+2`両方とも極大値である場合は、位置を変更します`i+1`。 
4. Set```
a[i+1] = max(a[i], a[i+2])
```これは、中央の要素が両方のピークと少なくとも同じ大きさになるため、どちらの側も極大値のままにならないからです。 

1. 両方のピークがすでに処理されているため、1 つの操作をカウントし、3 位置分先にスキップします。 
2. 位置の場合`i`は極大値ですが位置`i+2`そうでない場合は、孤立したピークとして扱います。 
3. 交換する```
a[i] = max(a[i-1], a[i+1])
```その極大値は即座に破壊されます。 

1. 1 回の操作をカウントし、スキャンを続けます。 
2. 操作の数と最終的な配列を出力します。 

### なぜ効果があるのか

 1 つの操作で 2 つのピークを削除できる唯一の方法は、それらのピークが 1 つの要素だけで分離されている場合です。 距離が大きいほど、ピークが独立していることを意味します。 

左から右へのスキャン中に、隣接するピークのすべてのペアが 1 回検出されます。 中央の要素を変更すると両方が同時に削除されるため、2 つの操作を費やすよりも常に優れています。 このようなペアの一部ではないピークは、別のピークと操作を共有できないため、それらを個別に修正することが最適です。 したがって、操作の総数は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
ans = []

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    peak = [False] * n
    for i in range(1, n - 1):
        if a[i] > a[i - 1] and a[i] > a[i + 1]:
            peak[i] = True

    cnt = 0
    i = 1

    while i < n - 1:
        if peak[i]:
            if i + 2 < n and peak[i + 2]:
                a[i + 1] = max(a[i], a[i + 2])
                cnt += 1
                i += 3
            else:
                a[i] = max(a[i - 1], a[i + 1])
                cnt += 1
                i += 1
        else:
            i += 1

    ans.append(str(cnt))
    ans.append(" ".join(map(str, a)))

sys.stdout.write("\n".join(ans))
```最初のループは、元の配列内のすべての極大値を特定します。 この情報はスキャン中に固定されたままになります。 変更のたびにピークを再計算すると実装が複雑になるため、その必要はありません。 

メインループはピークを左から右に処理します。 2 つのピークが 2 位置離れている場合、中央の要素を 1 回変更すると両方が削除されます。 これらのピークが終了したため、指数は 3 ポジションジャンプします。 

孤立したピークの場合、ピーク値をより大きな近傍値に置き換えると、新しいピークを作成せずにそのピークが破棄されます。 等価性は極大値としてカウントされないため、最大近傍値を使用するだけで十分です。 

ループはインデックス 1 から開始され、インデックスの前で停止するため、境界位置は検査されません。`n-1`。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        peak = [False] * n
        for i in range(1, n - 1):
            if a[i] > a[i - 1] and a[i] > a[i + 1]:
                peak[i] = True

        cnt = 0
        i = 1

        while i < n - 1:
            if peak[i]:
                if i + 2 < n and peak[i + 2]:
                    a[i + 1] = max(a[i], a[i + 2])
                    cnt += 1
                    i += 3
                else:
                    a[i] = max(a[i - 1], a[i + 1])
                    cnt += 1
                    i += 1
            else:
                i += 1

        out.append(str(cnt))
        out.append(" ".join(map(str, a)))

    sys.stdout.write("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    result = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return result

# minimum size
assert run("1\n2\n5 7\n") == "0\n5 7"

# all equal
assert run("1\n5\n4 4 4 4 4\n") == "0\n4 4 4 4 4"

# alternating peaks
assert run("1\n5\n1 3 1 3 1\n") == "1\n1 3 3 3 1"

# isolated peak
assert run("1\n4\n1 4 2 1\n") == "1\n1 2 2 1"

 | --- | --- | --- |
 | 5 7 | 0 操作 | 最小サイズ |
 | 4 4 4 4 4 | 変更なし | 等しい値 |
 | 1 3 1 3 1 | ワンオペレーション | 2 つのピークの共有修正 |

 ## 特殊なケース

 検討してください```
1 3 1 3 1
```最初のピークは位置 2 と 4 にあります。アルゴリズムは、それらが 1 つの要素によって分離されていることを認識し、中心値を変更します。```
1 3 3 3 1
```使用される操作は 1 つだけです。 各ピークを個別に修正する戦略では、2 つの操作が必要になります。 

考慮する```
2 1 3 1 3 1 3
```位置 3 と 5 にある最初のピークのペアは中央の要素を共有しているため、1 回の操作で両方が削除されます。```
2 1 3 3 3 1 3
```位置 7 の残りのピークは分離され、個別に固定されます。 2 つの操作が最適です。 

考慮する```
5 1 5
```どちらのエンドポイントも極大値になることはありません。 ループは中心位置のみを検査します。中心位置は両方の隣接位置よりも小さいため、操作は実行されず、配列は変更されません。 これにより、境界での 1 つずつのエラーが回避されます。
