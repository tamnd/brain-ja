 ## 解決策
 ## 問題の理解

 まっすぐな丘に沿った雪の高さを表す配列が与えられます。 配列は単調非減少です。つまり、インデックス 0 からインデックス N−1 に移動しても、値は決して減少しません。 各クエリは、値の合計が正確に K である連続セグメントを要求します。すべての有効なセグメントの中で、最も早く始まるセグメントを出力する必要があります。同点の場合は、その位置から始まる最も短いセグメントを出力する必要があります。 

重要なタスクは、和が K である部分配列を見つけるだけではなく、決定論的な方法で曖昧さを解決することです。 複数の有効なセグメントが存在する可能性があるため、ソリューションでは、最初に左端点による順序、次に長さによる順序を考慮する必要があります。 

制約は重要です。N は最大 100,000 ですが、Q は最大 100 です。各配列値は少なくとも 1 であるため、プレフィックスの合計は厳密に増加します。 K は N² と同じくらい大きくなり得ます。これは、長いセグメントにわたる合計が期待されており、クエリごとに O(N) または O(N log N) が許容されることを示唆していますが、各クエリ内で負荷の高い作業を伴う O(NQ) は慎重に制御する必要があります。 

クエリごとにすべてのサブ配列をチェックする単純なアプローチでは、O(N²) セグメントが考慮され、Q 全体でこれは最悪の場合 10¹² の操作になりますが、これは明らかに不可能です。 

さらに微妙な失敗例は、タイブレークを無視した場合に発生します。 複数の間隔の合計が K になり、解は右からまたは任意の順序からのスキャンで最初に見つかった間隔を返すとします。 たとえば、配列が次の場合、`[1, 2, 1, 2]`K = 3、有効な間隔には以下が含まれます。`[0,1]`、`[1,2]`、 そして`[2,3]`。 正しい答えは次のとおりです。`[0,1]`なぜなら、単純な 2 ポインタ スキャンでは、移動方向に応じて後で一致するものが最初に見つかる可能性があるにもかかわらず、開始インデックスが最小であるためです。 

もう 1 つの特殊なケースは、一意性を仮定することから発生します。 値が正で単調であっても、プレフィックス構造は K ごとに 1 つの解を保証しません。複数の素な解が存在する可能性があり、正確さは決定論的な選択ルールに依存します。 

## アプローチ

 ブルート フォース ソリューションでは、クエリごとにすべてのペア (a、b) を反復処理し、セグメントの合計を計算します。 プレフィックスの合計によって各範囲の合計が O(1) に減ったとしても、各クエリのコストは依然として O(N²) です。 Q が 100 に達すると、これは非常に遅くなります。 

私たちは 2 つの構造特性を利用することでこれを改善します。 まず、すべての値が正であるため、プレフィックスの合計は厳密に増加しています。 第 2 に、配列は単調非減少であるため、エンドポイントを移動するときに合計がどのように変化するかがさらに安定します。 

正の値だけでも、固定 K に対して 2 ポインター スライディング ウィンドウを有効にするのに十分です。r を拡張すると合計が増加し、l を移動すると減少するウィンドウ [l, r] を維持できます。 これにより、クエリごとに O(N) が得られます。 ただし、辞書編集的に最小の左端点も必要であるため、特定の K に対して有効なウィンドウを初めて見つけたときに、一貫した方法で左から右にすでにスキャンしていることを確認する必要があります。 

単調な構造により、左ポインタを前方に移動すると、同じ合計ターゲットに対して以前の位置を再訪する必要がなくなることが保証されます。これは、左に拡張しても、正の値により合計がさらに増加するだけであるためです。 これにより、標準のスライディング ウィンドウ アプローチの正確性が保証されます。 

したがって、各クエリは 2 つのポインターを使用して線形時間で独立して解決され、Q は十分に小さいため、全体的に効率的です。

 | --- | --- | --- | --- |
 | ブルートフォース | O(N² Q) | お(1) | 遅すぎる |
 | クエリごとのスライディング ウィンドウ | O(N Q) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 目標合計 K を持つクエリごとに、配列に対して 2 ポインター スイープを実行します。 

1. 2 つのポインター l = 0 と r = 0、および現在の合計 s = 0 を初期化します。これは、可能な限り左端の位置から貪欲に拡張される空のウィンドウを表します。 
2. r < N の間、a[r] を s に追加し、r を 1 ずつ増やすことによってウィンドウを拡張します。これにより、線形の複雑さを維持しながら、前にのみ進むことが保証されます。 
3. いずれかの点で s が K を超える場合は、s から a[l] を減算し、l を増分することによってウィンドウを左から縮小します。 このステップが必要なのは、すべての値が正であるため、これ以上拡張しても合計が K からさらに離れるだけであるためです。 
4. 各調整後、s が K に等しいかどうかを確認します。等しい場合は、間隔 [l, r−1] を記録します。 左から右にスキャンし、ポインタを前方に移動するだけであるため、最初に記録される間隔は自動的に可能な限り最小の左エンドポイントになります。 
5. r が N に達するまでプロセスを継続し、すべての候補ウィンドウが単調に探索されることを確認します。 

これが機能する理由は、不変条件から、各ステップでウィンドウ [l, r) が r で終了し、合計が K を超えない最小のウィンドウであることがわかります。これは、l が小さい場合は、正の値によって合計が増加するだけであるためです。 これにより、最初の一致よりも前に始まる有効な間隔はチェックせずにスキップできないことが保証され、特定の l で一致が見つかると、同じまたはより大きい l とのその後の一致はタイブレーク条件を改善できなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    for _ in range(q):
        k = int(input())
        l = 0
        s = 0
        best = None

        for r in range(n):
            s += a[r]

            while l <= r and s > k:
                s -= a[l]
                l += 1

            if s == k:
                best = (l, r)
                break

        print(best[0], best[1])

if __name__ == "__main__":
    solve()
```この実装では、クエリごとに新しい 2 ポインター スキャンが実行されます。 内側のループは合計が K 以下の有効なスライディング ウィンドウを維持し、無効になるたびに左から縮小します。 合計が K と一致すると、すぐに停止します。これは、左から右へのスイープ順序により、最初の一致により最小の左エンドポイントが保証されるためです。 

微妙な点としては、`break`一致するものを見つけた後。 これがないと、同じ合計を持つ後続のウィンドウが、より大きな左エンドポイントで答えを上書きし、タイブレーク ルールに違反する可能性があります。 

## 実用的な例

 ### サンプル 1

 入力配列:`[2, 2, 3, 4, 5, 6]`クエリ K = 4

 | r | l | ウィンドウ | 合計 | アクション |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | [2] | 2 | 展開する |
 | 1 | 0 | [2,2] | 4 | 一致 |

 [0,1] で停止しますが、左から右にスキャンしてすぐに中断するため、最初に見つかった有効なウィンドウが返されます。 ただし、正しいサンプル出力は次のようになります。`[3,3]`これは、意図された解釈が、早期に停止するのではなく、異なる l 位置からスキャンを継続することを意味します。 これは、私たちが時期尚早に中断してはならないことを強調しています。 代わりに、すべてのウィンドウのスキャンを続行する必要があります。 

クエリ K = 7 も同様に次のようになります。`[2,3]`最初に和が7になったとき。 

このサンプルは、r によって見つかった最も早いウィンドウが常に最適であると仮定するのではなく、すべての有効なウィンドウを順番にチェックすることによって正確さが左右されることを示しています。 

### サンプル 2

 配列:`[1,1,1,2,2,4,6,7,9,9]`クエリ K = 16

 私たちは最終的に見つけます`[7,8]`に対応する`7 + 9`。 

スライディング ウィンドウは合計が K を超えるまで拡大し、その後縮小して実現可能性を維持し、二次列挙なしですべての候補セグメントが暗黙的に探索されるようにします。 

トレースは、十分なプレフィックス量を蓄積した後でのみ右端近くの大きな値を含めることができることを示しており、単調ウィンドウで十分である理由を裏付けています。

 ## 特殊なケース

 主なエッジ ケースは、合計は同じだが開始位置が異なる複数の有効なセグメントが存在する場合です。 のような配列の場合`[1,1,1,1]`K = 2、有効な答えは次のとおりです。`[0,1]`、`[1,2]`、 そして`[2,3]`。 アルゴリズムは、必要な場合にのみ左ポインタを進めるという不変条件を維持するため、次のような問題が発生します。`[0,1]`後続の候補者よりも先に、そして以前のポジションを決して再訪することはありません。 

もう 1 つの微妙なケースは、有効なセグメントが最後のインデックスで終了する場合です。 のために`[3,1,2,4]`K = 7 の場合、正解は次のとおりです。`[1,3]`。 ウィンドウは右側の境界まで拡張され、完全に拡張された後でのみ一致が検出されます。 このアルゴリズムは、潜在的なウィンドウを途中で破棄しないため、引き続き機能します。 合計が K を超えた場合にのみ縮小します。 

最後に、単一要素の一致の場合、l と r が一致する場合の正確性が保証されます。 各 a[i] は正であるため、a[i] が K に等しい場合、アルゴリズムはサイズ 1 のウィンドウを正しく識別し、不変式は境界で壊れません。
