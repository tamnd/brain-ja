 ## 解決策
 ## 問題の理解

 2D 平面内に点在する一連のチェックポイントが与えられます。 各チェックポイントは特定の時間にのみ表示され、その正確な時間にたまたま正確にその座標にいた場合、ある程度の報酬を集めることができます。 

時間ゼロの原点からスタートし、単位時間当たり 1 単位の距離の速度で任意の方向に連続的に移動できます。 これは、地点 A から地点 B への移動には、ちょうど地点間のユークリッド距離が必要であることを意味します。また、待ちたい場合は予定時刻より早く到着しないといけませんが、宝物は正確な時刻にのみ入手できるため、遅れて到着しても役に立ちません。 

目標は、各遷移が物理的に時間内に実現可能であり、収集された値の合計が最大化されるように、原点から開始して訪問する一連のチェックポイントを選択することです。 

入力サイズは最大 5000 チェックポイントです。 考えられるすべての訪問シーケンスをチェックする単純な試みでは、5000 個のノードを含むグラフ内の順列またはパスを探索する必要があります。これは、状態遷移ステップごとに階乗または少なくとも二次関数的に増加し、定数によっては O(N^2 log N) 以上のようなものは潜在的に境界線になる可能性があり、O(N^3) または指数関数は明らかに不可能です。 

重要な点は時間の制約です。点が幾何学的に近い場合でも、タイムスタンプが早すぎるために到達できない場合があります。 逆に、十分な時間が経過していれば、遠くのポイントにも到達できる可能性があります。 これにより、この問題は、時空の到達可能性によって定義される有向グラフにおける制約付き最長経路問題になります。 

いくつかの特殊なケースは、素朴な貪欲な思考を打ち破ります。 よくある失敗は、常に最も近い次の点を優先すると仮定することです。 たとえば、近くの低い値のポイントをスキップするとはるかに大きなゲインが得られる場合でも、時間の制約により、近くの低い値のポイントが早い段階で高い値のポイントに到達するのをブロックする可能性があります。 もう 1 つの微妙なケースは、タイムスタンプが等しい場合です。2 つのポイントが同じ位置にない限り、両方を同時に取得することはできませんが、これは一般に不可能であるため、順序の制約を厳密に尊重する必要があります。 

## アプローチ

 この問題を直接考える方法は、各チェックポイントをノードとして扱い、時間内に i から j に移動できる場合はノード i をノード j に接続することです。 Ti + dist(i, j) ≤ Tj の場合、時刻 Ti のノード i から時刻 Tj にノード j に到達できます。 (0,0,0) に仮想開始ノードも含めると、各チェックポイントで終了する最適な報酬パスを計算できます。 

これは、dp[i] がチェックポイント i で終了する最大報酬である動的プログラミング公式を直ちに示唆します。 各 i について、Tj ≤ Ti である以前のすべての実行可能なチェックポイント j から遷移を試み、j が時間内に i に到達できるかどうかを確認します。 これにより、単純な O(N^2) 解が得られます。 

すべてのチェックポイントは、以前に到達できたチェックポイントにのみ依存するため、ブルート フォース構造が機能します。 しかし、すべての順列または任意のシーケンスを考慮しなければならないという単純な解釈は大きすぎます。 この改善は、時間が実行可能性を厳密に決定するということを理解することで実現しました。遷移は、より短い時間または等しい時間からより大きな時間へのみ有効です。 これにより、問題は、エッジが時間的に前方にのみ進む DAG の最短パスまたは最長パスの問題に変換されます。 

一般的な DAG 最短経路問題とは異なり、エッジは明示的に与えられません。 幾何学的距離を使用して計算する必要があります。 ペアのチェックは定数時間であるため、O(N^2) ではまだ許容されます。 

N = 5000 で二次遷移が範囲内に保たれるため、これ以上洗練されたジオメトリやデータ構造は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 順列に対するブルート フォース パス | お(ん!) | O(N) | 遅すぎる |
 | すべての有効な遷移にわたる DP | O(N^2) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

すべての有効な遷移が前のポイントから後のポイントに進むように、チェックポイントを時間で並べ替えます。 次に、この順序に対して動的プログラミングを実行します。 

### ステップ

 1. すべてのチェックポイントを読み取り、それぞれをその値、座標、および時刻に関連付けます。 仮想開始チェックポイントを (0, 0, 0) に値 0 で追加します。 
2. すべてのポイントを時間の増加順に並べ替えます。 これにより、時間内の有効な移動方向が常に配列順序で前に進むことが保証されます。 この順序付けは、dp を計算するときに将来の状態を再訪するのを防ぐため、非常に重要です。 
3. dp 配列を初期化します。ここで、dp[i] は、正確にチェックポイント i で終わる達成可能な最大合計値を表します。 開始ノード (0) を除くすべての値を負の無限大に設定します。 
4. ソートされた順序で各チェックポイント i について、以前のすべてのチェックポイント j < i を繰り返します。 
5. 各ペア (j, i) について、それらの間のユークリッド距離を計算し、dp 遷移が可能かどうかを確認します。dp[j] が有効であり、Tj + dist(j, i) ≤ Ti です。 
6. 可能であれば、dp[i] = max(dp[i], dp[j] + Vi) を更新します。 これは、チェックポイント i を経由して、j で終わる最もよく知られているルートを延長することを意味します。 
7. すべてのノードを処理した後の答えは、すべてのチェックポイントにわたる最大 dp[i] です。 

### なぜ効果があるのか

 このアルゴリズムは、時間順で i 以降に発生するチェックポイントのみを考慮して、チェックポイント i で正確に終了するすべての有効なパスの中で可能な最高の報酬を dp[i] に保存するという不変条件を維持します。 すべての遷移は時間順序と移動の実現可能性の両方を考慮するため、すべての dp 更新は物理的に有効な移動に対応します。 考えられるすべての有効な先行パスがチェックされるため、i へのより適切なパスが見逃されることはありません。 時間ソートにより遷移グラフの非周期性が保証されるため、将来の状態が過去の状態に影響を与えることがなく、循環や不一致が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def solve():
    n = int(input())
    pts = []
    
    for _ in range(n):
        x, y, t, v = map(int, input().split())
        pts.append((t, x, y, v))
    
    # sort by time
    pts.sort()
    
    # dp[i] = best value ending at i
    dp = [0] * n
    
    ans = 0
    
    for i in range(n):
        t_i, x_i, y_i, v_i = pts[i]
        dp[i] = v_i
        
        for j in range(i):
            t_j, x_j, y_j, v_j = pts[j]
            
            dx = x_i - x_j
            dy = y_i - y_j
            
            if dp[j] == 0 and j != 0:
                # still valid, dp[j] might be unreachable; skip only if desired
                pass
            
            dist = math.hypot(dx, dy)
            
            if t_j + dist <= t_i:
                dp[i] = max(dp[i], dp[j] + v_i)
        
        ans = max(ans, dp[i])
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、dp[i] を計算するときに、すべての潜在的な先行処理がすでに処理されていることを保証するために、時間によるソートに依存しています。 内側のループは、以前のすべてのチェックポイントをチェックし、ユークリッド距離を使用して到達可能性を検証します。 

微妙な点は、距離比較における浮動小数点精度です。 座標と時刻は 1e9 までの整数なので、`math.hypot`は標準ですが、厳密な問題ではイプシロン許容差が必要になる場合があります。 このような競技環境では通常は安全ですが、より堅牢なアプローチは、距離の二乗と時間差の二乗を慎重に比較することです。ただし、ここでは時間差には移動待ち時間が含まれるため、直接比較する方が簡単です。 

## 実用的な例

 ### サンプル 1

 入力:```
3
1 1 100 10
2 2 40 8
20 20 25 1000
```まず時間順に並べ替えます。 

| 私 | (x,y,t,v) | dp[i] 初期化 | 最良の移行 | dp[i] 最終 |
 | --- | --- | --- | --- | --- |
 | 0 | (20,20,25,1000) | 1000 | 開始のみ | 1000 |
 | 1 | (2,2,40,8) | 8 | (20,20,25)からは間に合わない | 8 |
 | 2 | (1,1,100,10) | 10 | (2,2,40) から可能 | 18 |

 最善の方法は、中央のチェックポイントを通過してから最後のチェックポイントを通過し、8 + 10 = 18 を累積することです。 

これは、価値の高い初期ポイントが常に最適であるわけではないことを示しています。 実現可能性の制約がパスを形成します。 

### サンプル 2

 入力:```
2
15 20 25 100
7 24 25 50
```並べ替えられた順序では、時刻 25 で両方が保持されます。移動時間は正ですが、利用可能な時差がゼロであるため、どちらも他方に到達できません。 

| 私 | dp[i] 初期化 | トランジション | dp[i] 最終 |
 | --- | --- | --- | --- |
 | 0 | 100 | なし | 100 |
 | 1 | 50 | なし | 50 |

 答えは100です。 

これは、等時間チェックポイントが実質的に独立したノードであり、それらの間に有効な遷移がないことを示しています。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N^2) | チェックポイントの各ペアは、到達可能性について 1 回チェックされます。 
| スペース | O(N) | DP 配列と格納されたポイント |

 ## 特殊なケース

 エッジケースの 1 つは、複数のチェックポイントが同じタイムスタンプを共有する場合です。 ソート後、それらは連続しますが、距離がゼロでない限り相互に遷移することはできません。 条件が次のとおりであるため、アルゴリズムはこれを自然に処理します。`t_j + dist <= t_i`dist が 0 でない限り失敗するため、dp 状態は独立したままになります。 

もう 1 つのエッジ ケースは、非常に価値の高いチェックポイントが空間内に近いにもかかわらず、タイムスタンプが早い場合です。 値または距離によって選択する単純な貪欲な場合は、最初にそれを取得しようとしますが、dp は、後の蓄積の実行可能性を妨げる場合、それを正しく回避します。 

最後のケースは、中間点の長いチェーンを介してのみ点に到達できる場合です。 DP は、各中間 dp 状態が計算されると、それが前方に伝播できることを保証します。 たとえば、各ホップがかろうじて時間制約を満たしているチェーンでも、すべての中間状態が O(N²) スキャンの有効な先行とみなされているため、正しく累積されます。
