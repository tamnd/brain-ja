 ## 解決策
 ## 問題の理解

 単一の整数が与えられます$n$そして、シーケンスのすべての順列を調べるように求められます。$(1, 2, 3, \dots, n)$。 各順列は、その要素を順番に連結することによって形成される数値として解釈されます。 たとえば、$n = 4$のような順列$[3, 1, 4, 2]$番号 3142 に対応します。 

考えられるすべての順列の中で、このように形成された 2 つの数値の間の可能な最大の差が必要です。 1 つの順列は可能な限り最大の連結数を生成し、別の順列は可能な限り最小の連結数を生成する必要があり、それらの差を取ります。 

入力サイズは最大です$n = 10^5$。 これにより、順列を明示的に列挙したり、すべての数値を構築したりするアプローチは除外されます。$n!$順列は小さいものであっても天文学的に大きい$n$。 有効な解決策はすべて線形か、最悪の場合でも解決策でなければなりません$O(n \log n)$ただし、最適な順列の構造は固定されているため、ここではソートは不要です。 

微妙な点は、数値の算術的並べ替えではなく、連結を扱っていることです。 それで$n = 12$は 2 桁に寄与しますが、$n = 9$1桁貢献します。 これは、位置の重みが桁の長さに依存し、極値順列の構造に影響を与えることを意味します。 

エッジケースは、次の小さな値から発生します。$n$。 のために$n = 1$、順列は 1 つだけであるため、差はゼロでなければなりません。 のために$n = 10$、桁の長さは 1 桁から 2 桁の数値に変化します。これはまさに、幅が均一であると仮定した場合、単純な桁レベルの推論アプローチが失敗する可能性がある場所です。 

## アプローチ

 ブルートフォースソリューションでは、次のすべての順列が生成されます。$1$に$n$、各順列を連結された整数表現に変換し、それらの最小値と最大値を計算します。 これは問題の定義に直接従うため、概念的には単純で正しいものです。 ただし、その複雑さは、$O(n! \cdot n)$すべての順列を生成し、それぞれを連結するため、$n = 10$。 

重要な観察は、実際には順列を探索する必要がないということです。 どの数値の配置が最大の連結値を生成し、どの配置が最小の値を生成するかを判断するだけで済みます。 連結ベースの順序付けの場合、最適な配置は、個々の要素の数値の大きさではなく、結果の文字列の辞書編集的な比較によって決定されます。 

連結された最大の数値は、文字列として書き込むときに数値を降順に並べることによって取得されます。これは、より大きな先行桁を前に置くと常に後の寄与が優先されるためです。 同様に、数値を昇順に並べると、最小の連結数値が得られます。 

順序は次のように固定されているため、$1$に$n$、これは 2 つの文字列を構築することになります: 1 つは次から数値を書くことで形成されます。$n$まで$1$、そしてもう一つから$1$まで$n$、次に両方を整数に変換して減算します。 

この問題は、順列をめぐる組み合わせ最適化から直接構築問題へと崩壊します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n! \cdot n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n \cdot d)$どこ$d$桁コスト |$O(n \cdot d)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 1 から 1 までの数字を追加して、可能な限り最小の連結を構築します。$n$昇順で。 これが機能するのは、結果の文字列の辞書編集順において、前の数字が後の数字よりも優先されるためです。 
2. 以下の数値を追加して、可能な限り最大の連結を構築します。$n$これにより、より大きな数値が早く表示され、最上位桁の位置が最大化されます。 
3. 構築された両方の文字列を整数に変換します。 結果の値が大きくなる可能性があるため、この手順は安全ですが、Python は任意精度の整数を処理します。 
4. 大きい値と小さい値の差を計算して出力します。 

これが機能する理由: 連結された数は文字列ブロックの順序によって完全に決定され、すべてのブロックが固定トークンである場合、2 つの連結を比較することは辞書編集上の順序を比較することと同等です。 この問題では任意の順列が許可されるため、これらのトークンをそれぞれ降順と昇順でグローバルに並べ替えることによって極値が得られます。 これらの順序から逸脱すると、より大きなトークンが後で導入されたり、より小さなトークンが先に導入されたりすることになり、厳密には目的が悪化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())

    # build smallest concatenation: 1 to n
    small_parts = []
    for i in range(1, n + 1):
        small_parts.append(str(i))
    small_val = int("".join(small_parts))

    # build largest concatenation: n to 1
    large_parts = []
    for i in range(n, 0, -1):
        large_parts.append(str(i))
    large_val = int("".join(large_parts))

    print(large_val - small_val)

if __name__ == "__main__":
    solve()
```実装は、前述の構造に直接続きます。 唯一重要な決定は、算術桁シフトではなく文字列連結を使用することです。 これにより、10 の累乗を手動で追跡する必要がなくなり、連続する整数間のさまざまな桁長が正しく処理されます。 

Python の任意精度の整数により、次のような場合でも変換が安全になります。$n = 10^5$、結果として得られる数値は数十万桁になります。

 ## 特殊なケース

 のために$n = 1$、アルゴリズムは両方の文字列を次のように構築します。`"1"`。 差はゼロとなり、順列が 1 つだけ存在するという事実と一致します。 

のために$n = 10$、アルゴリズムは次のように構成します`"12345678910"`そして`"10987654321"`。 重要な微妙な点は、`"10"`2 文字が含まれるため、固定幅トークンを誤って想定すると位置合わせに影響します。 文字列ベースのアプローチでは、連結によってトークンの境界が保持されるため、これは自然に処理されます。 計算された差は、直接の整数解釈と一致します。 

特別な分岐は必要なく、すべてのエッジ ケースが同じ構築ロジックによって均一に処理されます。
