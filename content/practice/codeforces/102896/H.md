 ## 問題の理解

 このシステムは、短期間で進化する確率的プロセスを記述します。 「赤ちゃん」は常に 3 つの状態のいずれかにあり、覚醒、浅い眠り、深い眠りとして解釈されます。 プロセスは覚醒状態で開始され、一定の期間にわたって開始されます。$k$時間ごとに、連続時間の確率則に従ってこれらの状態の間をランダムに遷移します。 

各状態には、次の遷移までの特有の待ち時間があります。 離散的なステップの代わりに、状態を終了するまでの時間は、値によってパラメータ化された指数関数的な分布に従います。$p_i$、状態が少なくとも持続する確率を意味します。$x$時間は$p_i^x$。 これにより、連続時間における遷移がメモリレスになります。これは、システムの重要な構造特性です。 

遷移が発生すると、次の状態は現在の状態に依存します。 覚醒状態または深い睡眠から、システムは常に浅い睡眠に移行します。 浅い眠りから、一定の確率で覚醒または深い眠りに移行する場合があります。 追加のインタラクション層があります。親が起きているとき、親は状態を観察し、特定の遷移が抑制されるように介入できます。具体的には、システムを浅い睡眠状態に保つことで、浅い睡眠から覚醒への移行を防ぎます。 

親はいつ寝るか、いつ起きているかをコントロールし、目標は、固定時間が終了するか、赤ちゃんが起こすまでに予想される総睡眠時間を最大化することです。 

入力はいくつかの独立したテスト ケースを与え、それぞれが水平線の長さを記述します。$k$、3 つの永続パラメータ$p_0, p_1, p_2$、および分岐確率$q_0$。 出力は、最適な戦略の下で予想される最大睡眠時間を表す実数です。 

制約の大きさは小さく、$k \le 10$そしてすべての確率は$[0.1, 0.9]$、しかし、連続時間の確率力学は、まれなイベントの構造と最適な制御の決定が重要であるため、単純なシミュレーションでは不十分であることを示唆しています。 代わりに、ソリューションは、指数関数的生存形式から導出される連続時間遷移率を使用した状態に対する動的プログラミングに依存する必要があります。 

遷移を小さなタイムステップごとに離散的に扱う場合、微妙なエッジ ケースが発生します。 たとえば、次の場合$p_i$が 1 に近い場合、状態は長期間変化しない可能性があり、粒度が粗いタイムステップ シミュレーションでは遷移頻度が過大評価され、睡眠が過小評価されます。 

赤ちゃんが状態 0 でないときは常に親が眠っていると仮定すると、別の失敗例が生じます。これは、起きていれば浅い睡眠からの有害な移行を遅らせたり防止したりして、将来の睡眠の期待値を増加させることができるという事実を無視しています。 

3 番目の問題は、残り時間を組み入れずに離散状態のみでプロセスをマルコフとして扱う場合に発生します。$k$。 ホライズンは有限であるため、値は残り時間に明示的に依存し、貪欲な定常状態推論は失敗します。 

## アプローチ

 直接的なブルートフォース解釈では、遷移時間のランダムなサンプリングを使用して連続時間マルコフ過程をシミュレートし、親が寝ているか起きているかを繰り返し決定しようとします。 各シミュレーションはイベントの軌跡を生成し、終了までのスリープ時間を蓄積し、多くの実行の平均をとって期待値を推定します。 概念的には単純ですが、精度を安定させるために必要なシミュレーションの数が非常に多いため、このアプローチは失敗します。 状態空間は時間的に連続しており、分岐の決定は将来のランダム性に依存するため、数百万のサンプルがあっても分散は高いままです。 

構造的なブレークスルーは、システムが指数関数的な保持時間を備えた制御された連続時間マルコフ過程であることを認識することによってもたらされます。 表現$p_i^x$それぞれの状態を意味します$i$レートに応じて指数関数的な待ち時間が発生する$\lambda_i = -\ln p_i$。 これにより、プロセスが一定の速度で遷移が発生する標準 CTMC に変換されます。 

レート形式で書き込まれると、システムは時間の経過とともに有限状態の最適制御問題になります。 親の決定は基本的に、特定の遷移を許可するかブロックするかであり、それによって効果的な遷移グラフが変更されます。 ホライズンが小さく、状態の数が少ないため、最適値は、微分ベルマン方程式を使用した経時的な動的計画法によって、または同等に、期待値のバランスから導出された連立一次方程式を解くことによって計算できます。 

重要な単純化は、最適な動作は完全な履歴ではなく、現在の状態と残り時間のみに依存するということです。 これにより、問題は値関数の計算に軽減されます。$V_i(t)$、状態から始まる予想される睡眠を表します$i$と$t$残り時間。 遷移構造により、小さな制約により離散化または解析的に解くことができる微分方程式が生成されます。

 ## アルゴリズムのチュートリアル

 1. 各永続化パラメータを変換する$p_i$移行率へ$\lambda_i = -\ln p_i$。 これにより、生存確率が指数関数的な待機時間に変換され、連続時間におけるプロセスがメモリレスになります。 
2. 状態 1 からの特殊な分岐動作を 2 つの出力確率的遷移にエンコードしながら、3 つの状態とこれらのレートによって制御される有向遷移を備えた CTMC としてシステムをモデル化します。 
3. 値関数を定義する$V_i(t)$状態から達成可能な予想睡眠時間として$i$と$t$残り時間。 目標は計算することです$V_0(k)$。 
4. 短い間隔にわたる無限小最適性条件を記述します。$dt$。 その間$dt$、遷移が発生しない、寄与する$dt$親が眠っている場合、または次の確率に比例して遷移が発生する場合$\lambda_i dt$、状態をシフトします。 
5. 状態 1 の場合、制御を組み込みます。親が起きている場合、状態 0 への遷移を抑制できます。これにより、「寝る」または「起きている」という 2 つの競合するアクションが作成され、それぞれが異なる将来の期待値につながります。 
6. 状態と時間ごとに、期待される継続値を比較して最適なアクションを計算します。 これにより、3 つの状態にわたる連成方程式が得られます。 
7. これらの方程式を次から時間を遡って解きます。$t = 0$に$t = k$、時間を離散化するか、直接行列指数公式を使用することによって。 

### なぜ効果があるのか

 このプロセスは連続時間におけるマルコフであり、指数関数的な保持時間により、将来の進化は現在の状態にのみ依存し、その状態がどれだけ長く続いたかには依存しないことが保証されます。 価値関数は、無限小間隔にわたってベルマン最適性条件を満たし、最適な期待報酬を一意に特徴付けます。 すべての遷移はレートが線形であり、決定は 1 つの遷移タイプにのみ影響するため、結果として得られるシステムは線形で明確なままとなり、計算された値が全体的に最適になることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def solve_case(k, p0, p1, p2, q0):
    # rates
    l0 = -math.log(p0)
    l1 = -math.log(p1)
    l2 = -math.log(p2)

    # DP over time with small discretization (sufficient for constraints)
    T = 2000
    dt = k / T

    # V[i] = expected remaining sleep starting from state i at current time
    V = [0.0, 0.0, 0.0]

    # backward in time
    for _ in range(T):
        V0, V1, V2 = V

        # state 0: always forced wake soon; no sleep contribution
        new0 = (1 - l0 * dt) * V1 + (l0 * dt) * V1

        # state 2: similar structure, goes to 1
        new2 = dt + (1 - l2 * dt) * V1 + (l2 * dt) * V1

        # state 1: decision point
        # option A: sleep
        sleep_A = dt + (1 - l1 * dt) * V1 + (l1 * dt) * (q0 * V0 + (1 - q0) * V2)

        # option B: stay awake (block 1->0)
        sleep_B = (1 - l1 * dt) * V1 + (l1 * dt) * V2

        new1 = max(sleep_A, sleep_B)

        V = [new0, new1, new2]

    return V[0]

t = int(input())
for _ in range(t):
    k, p0, p1, p2, q0 = map(float, input().split())
    print(solve_case(k, p0, p1, p2, q0))
```連続時間の定式化には線形遷移強度が必要であるため、この実装では、持続確率を対数を使用してレートに変換します。 動的計画法は、時間間隔の固定離散化にわたって逆方向に実行され、各小さなスライスをほぼ一定として扱います。 

状態遷移は期待形式で直接エンコードされます。 状態 0 と 2 の場合、状態 1 への遷移は決定論的であるため、それらの更新方程式は、タイムステップ内で遷移が発生する確率が低く、値を単純に前方に伝播します。 

状態 1 が唯一の制御点です。 2 つの競合する式が計算されます。1 つは睡眠により両方の遷移が許可され、もう 1 つは起きていると状態 0 への遷移がブロックされます。max 演算子は各ステップで最適なポリシーの選択を実装します。 

実装の微妙な詳細は、睡眠の蓄積と移行の確率の両方が次のようにスケールする必要があることです。$dt$。 このスケーリングが欠けていると、報酬が過大にカウントされたり、無効な確率質量が発生したりすることになります。

 ## 特殊なケース

 いつ$p_i$が 1 に近い場合、遷移率は非常に小さくなり、システムは事実上、期間のほとんどにわたって 1 つの状態に留まります。 対数変換ではゼロに近いレートが生成され、安定性を損なうことなくタイムステップごとの遷移確率が低減されるため、アルゴリズムはこれを正しく処理します。 

いつ$p_i$が 0.1 に近づくと、遷移が頻繁になり、DP は急速に状態を混合します。 この体制では、離散化された更新は迅速に収束し、状態 1 の最大の決定が動作を支配し、頻繁な介入の機会を正確に反映します。 

もし$q_0$が 0 または 1 に近い場合、状態 1 はほぼ決定的に 2 つの状態のいずれかに遷移します。 このアルゴリズムは、意思決定の問題をほぼ決定的な分岐プロセスに正しく還元し、最大演算は単一の有効な遷移パスに適切に折りたたまれます。
