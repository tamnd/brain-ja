 ## 解決策
 ## 問題の理解

 2D 整数グリッド上の点のコレクションが与えられます。 タスクは、正方形の頂点を形成するこれらの点のうち 4 つを選択できるかどうかを判断することです。 正方形は軸に沿って配置されることに限定されないため、4 つの辺がすべて等しく、すべての角が直角である限り、任意に回転できます。 

入力は、各オブジェクトが平面内の点である一連の幾何学オブジェクトとして理解できます。 出力は単純な決定です。つまり、有効な正方形の角として機能するこれらの点の 4 つが存在するかどうかです。 

主な問題は、正方形がローカルな隣接性や入力内の順序によって定義されないことです。 4 つの点のサブセットは正方形を形成する場合も形成しない場合もあり、方向は固定されません。 これにより、密な入力における単純な組み合わせチェックが即座に除外されます。すべての 4 つ組をチェックするには、検査する必要があります。$O(n^4)$候補者にとっても実現可能な範囲をはるかに超えています。$n$数千程度。 

2 番目の微妙な問題は、正方形が座標内で明らかではない方法で重なる可能性があることです。 たとえば、2 つの異なる点のペアが、異なる対角線を介して同じ幾何学的正方形を定義する場合があります。 点の順序が固定されていると仮定したり、軸の位置合わせのみに依存したソリューションは、45 度の正方形を形成する点などの回転構成では失敗します。 

典型的なエッジ ケースは、複数の対角線が一致する円状の構成上に複数の点が存在する場合に発生します。 

たとえば、次の点を考慮してください。```
(0, 0), (1, 1), (1, 0), (0, 1)
```これは明らかに正方形を形成していますが、最小/最大座標を介して軸に沿った長方形のみをチェックする方法であれば、ここでも成功する可能性があります。 ただし、同じ構造を回転すると、そのような単純なロジックが壊れてしまいます。```
(0, 0), (2, 1), (1, 2), (-1, 1)
```これはまだ有効な正方形ですが、軸に合わせたヒューリスティックは完全に失敗します。 

課題は、すべての 4 倍体を明示的に列挙せずに 2 乗を検出することです。 

## アプローチ

 ブルートフォース手法では、4 つの点のすべての組み合わせを反復し、それらが正方形を形成しているかどうかを直接チェックします。 4 つの点が与えられると、すべてのペアごとの距離を計算し、4 つの等しい辺と 2 つの等しい対角線があることを確認できます。 これは、幾何学的定義を直接使用するため、論理的に単純で正しいものです。 

ただし、4倍の数は、$\binom{n}{4}$のオーダーで成長します。$O(n^4)$。 のために$n = 2000$、これはすでに超えています$10^{12}$各チェックには一定時間の距離の計算が含まれます。 高度に最適化されたコードでも、この規模に耐えることはできません。 

重要な観察は、正方形は辺ではなく対角線によって一意に決定されるということです。 正方形の対角となる 2 つの点を選択すると、他の 2 点は幾何学的に決定されます。それらは線分の中点から等距離にあり、方向が直角でなければなりません。 

これにより、より構造化されたビューが得られます。4 つの点を選択する代わりに、対角線の候補として 2 つの点を選択します。 すべての点のペアは潜在的な対角線を定義し、その中点と二乗の長さを計算できます。 2 つの異なるペアが同じ中点と同じ二乗距離を共有する場合、それらは正方形の 2 つの対角線を形成します。 

これにより、問題は 4 倍ではなくペアリング エッジに軽減されます。 すべてのポイント ペアを、次のキーでグループ化して保存します。 

中点 (同じ中心を共有することを保証するため) と二乗距離 (対角線の長さが等しいことを保証するため)。 少なくとも 2 つのペアを含むグループは、有効な正方形を示します。 

これにより、問題は 4 つの要素にわたる組み合わせ爆発からペアにわたるハッシュに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース（4点チェック） |$O(n^4)$|$O(1)$| 遅すぎる |
 | ペア + 対角線によるハッシュ |$O(n^2)$|$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての点を配列に読み取ります。 各点は正方形の潜在的な頂点として扱われますが、それを超える構造は想定しません。 
2. 順序付けされていないすべての点のペアに対して反復処理を行います。 各ペアは、正方形の対角線の候補として扱われます。 これは、4 つのポイントに関する推論から 2 つのポイントに関する推論への重要な移行です。 
3. ペアごとに$(p_i, p_j)$、中点を 2 倍の座標のペアとして計算します$(x_i + x_j, y_i + y_j)$。 同じ正方形の対角線の中点が正確に一致する必要があるため、浮動小数点除算は避けます。 
4. セグメントの二乗距離を計算します。$(x_i - x_j)^2 + (y_i - y_j)^2$。 これにより、整数演算が維持され、平方根なしで対角線の長さが特定されます。 
5. をキーとするハッシュ マップを使用します。$((x_i + x_j, y_i + y_j), dist)$。 ペアごとに、このキーがすでに存在するかどうかを確認します。 そうであれば、同じ正方形のジオメトリに一致する別の対角線が見つかったことになります。つまり、正方形を形成する 4 つの点が存在することになります。 
6. すべてのペアを処理した後に一致するペアが見つからない場合は、正方形は存在しないと結論付けます。 

### なぜ効果があるのか

 すべての正方形には正確に 2 つの対角線があります。 これらの対角線は同じ中点を共有し、同じ長さになります。 逆に、2 つのセグメントが中点と長さを共有し、それらの端点が異なる場合、4 つの端点は等しい対角線を持つ平行四辺形を形成する必要があり、強制的に正方形になります。 このアルゴリズムは、正方形と有効な対角線のペアの間のこの全単射を利用し、有効な構成が見逃されたり、無効な構成が受け入れられたりしないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]
    
    seen = {}
    
    for i in range(n):
        x1, y1 = pts[i]
        for j in range(i + 1, n):
            x2, y2 = pts[j]
            
            mx = x1 + x2
            my = y1 + y2
            dx = x1 - x2
            dy = y1 - y2
            dist = dx * dx + dy * dy
            
            key = (mx, my, dist)
            if key in seen:
                print("YES")
                return
            seen[key] = 1
    
    print("NO")

if __name__ == "__main__":
    solve()
```この解決策は、すべての点ペアを列挙し、各ペアを潜在的な正方形の対角線の正規表現にエンコードすることに依存しています。 辞書により、以前に確認された対角線の定数検索が保証されます。 

実装の微妙な詳細は、実際の中点の代わりに 2 倍の中点座標を使用することです。 これにより、浮動小数点の精度の問題が回避され、整数のみを使用した正確な一致が保証されます。 もう 1 つの重要な詳細は、平方根によって不必要な精度とパフォーマンスのコストが発生するため、ユークリッド距離ではなく平方距離を使用する必要があることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n^2)$| 順序付けされていない点のペアはすべて 1 回処理されます。 
| スペース |$O(n^2)$| 最悪の場合、すべてのペア キーがハッシュ マップに保存されます。 

二次複雑さは、およそまでの一般的な制約では許容可能です。$2 \cdot 10^5$各操作は定数時間のハッシュと比較であるため、ペアになります。 メモリ使用量も二次関数的にスケールされますが、標準の Codeforce 制限内で管理可能なままです。$n$数千です。

 ## 特殊なケース

 微妙なケースの 1 つは、複数の正方形が重なったり、点を共有したりする場合です。 アルゴリズムは一意性を想定していないため、これを自然に処理します。 データセット内の任意の場所にある 2 つの一致する対角線だけが必要です。 

例えば：```
4
0 0
1 1
1 0
0 1
```はすぐに正方形を形成しますが、各ペアは独立して処理されるため、他の場所に別の正方形を形成する点を追加しても干渉しません。 

もう 1 つのケースは、点が繰り返される場合、または縮退したセグメントが表示される場合です。 同一のペアは異なる端点を持つ有効な対角線を形成しないため、重複した点によって誤検知が発生することはありません。 新しい幾何学的構造を導入することなく、既存のキーを強化するだけです。 

最後に、距離が等しくても中点が異なる場合は、中点エンコードによってきれいに分離されるため、衝突しません。
