 ## 解決策
 ## 問題の理解

 このタスクは、単語が数字を表し、それぞれの個別の文字に 0 から 9 までの個別の数字が割り当てられる、暗号算術の古典的なクラスから来ています。与えられた 2 つの単語は加数として固定されます。 3 番目の単語が辞書から選択され、結果として得られる方程式が何らかの桁の割り当ての下で有効となるように、それらの候補のうちどれが合計として機能するかを知りたいと考えています。 

つまり、辞書の単語ごとに、$C$では、3 つの単語を 10 進数の数字として解釈し、各文字が一貫して数字にマッピングされた方程式を想像します。 マッピングは単射的である必要があり、単語の先頭文字をゼロにマッピングすることはできません。 加算を満たす有効な割り当てが 1 つだけ存在する辞書の単語を数えて出力するように求められます。 

辞書には長さ 15 までの単語が何十万語も含まれるため、入力サイズは非常に大きくなります。候補単語ごとに完全な英字体系を個別に解決する単純な試みでは、時間がかかりすぎます。 10 文字を超える後戻り検索を 1 回行うだけでもすでにコストがかかり、辞書項目ごとにそれを繰り返すと、そのコストは数十万倍になります。 

重要な構造上の制約は、2 つの加算語がすべてのチェックにわたって固定されていることです。 3 番目の単語だけが変わります。 つまり、検索空間が共有され、数字の割り当てに関するコストのかかる推論は再計算するのではなく、候補間で再利用する必要があります。 

複数の単語が同じ文字構造を共有しているが、接頭辞の制約が異なる場合、微妙なエッジ ケースが発生します。 たとえば、「AB」と「A」のような単語は、先頭ゼロの制限の適用が異なるため、動作が異なります。 もう 1 つの重要なエッジ ケースは、3 番目のワードの桁長が最初の 2 ワードの合計より短いか長い場合です。 候補合計の桁数が加数の桁上げ伝播よりも少ない場合、列構造を追跡する正しい実装では、その候補をすぐに除外できます。 

## アプローチ

 ブルートフォース戦略では、文字に数字を割り当て、その足し算が各辞書の単語に当てはまるかどうかを検証しようとします。 させたら$k$は個別の文字の数 (最大 10) であり、すべての数字の順列を単純にバックトラックすると次のようになります。$O(10!)$可能性。 割り当てごとに、すべての辞書の単語を評価するか、少なくとも合計の妥当性をテストする必要があり、複雑さが次のように爆発的に増加します。$O(10! \cdot n \cdot L)$。 ワードごとのチェックを制限したとしても、繰り返しの再計算が支配的になります。 

重要な観察は、最後の桁列に到達するまで、加算制約は位置的であり、3 番目の単語の特定の ID とは独立しているということです。 各候補単語を個別に扱う代わりに、視点を逆転させます。2 つの加数を修正し、グローバルな桁割り当て検索を実行します。 この検索中に、結果の単語の構造を右から左にたどることにより、その単語の可能なすべての補完を同時に探索します。 

これは、逆引きされた辞書の単語に対するトライを構築することを示唆しています。 トライ内の各パスは、潜在的な結果単語の接尾辞を表します。 バックトラッキング中、結果の特定の位置の数字を決定するときは、その位置に互換性のある文字を含むトライ分岐に沿って続行するだけで済みます。 これにより、すべての辞書単語にわたる作業がマージされ、同一の部分的な計算の繰り返しが回避されます。 

加算自体はキャリー伝播を使用して列ごとに処理されます。 各列で、2 つの加数と候補結果の接尾辞にどの文字が現れるかがわかります。 これにより、使用可能な桁が制限され、無効な部分割り当ては直ちに削除されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 単語ごとのブルートフォース |$O(n \cdot 10!)$重い定数を使用する |$O(1)$| 遅すぎる |
 | トライ + 割り当てに対するグローバルなバックトラッキング | 約$O(10! \cdot 15 \cdot 10)$剪定あり |$O(n \cdot L)$| 承認済み |

 ## アルゴリズムのチュートリアル

 すべての辞書の単語を、その逆の形式をトライに挿入することによって前処理します。 各ノードはそのノードで終わる単語を保存するので、後で有効な完了をカウントできます。 

次に、文字から数字への割り当てとキャリー値によって定義された状態空間に対して深さ優先検索を実行します。 

1. 2 つの加算語を右に揃え、欠落している位置を空白として扱います。 列インデックスを処理する再帰関数を定義します。$i$最下位桁から上にキャリー値とともに。 
2. 各列で、最初の単語、2 番目の単語、および結果の単語から寄与する文字を特定します。 これらの文字には、すでに数字が割り当てられているものもありますが、その他はまだ空いています。 
3. 文字がすでに割り当てられている場合は、その数字を直接使用します。 そうでない場合は、まだ使用されていない利用可能なすべての桁を試し、一時的に割り当てて再帰を継続します。 ここで順列検索が行われますが、算術列方程式によって大きく制限されます。 
4. 次の方程式を使用して、結果列に必要な桁を計算します。$$d_{result} \equiv d_{a} + d_{b} + carry \pmod{10}$$そして次のキャリーを計算します。 
5. 次に、逆引きされた辞書の単語のトライをたどります。 列で$i$の場合、その位置の文字が割り当てられた数字と文字のマッピングに一致する子ノードのみを追跡します。 そのような枝が存在しない場合は、すぐに剪定されます。 
6. すべての列の終わりに到達し、キャリーが 0 になると、トラバーサル中に到達した完全なワードに対応するすべてのトライ ノードが、有効なソリューション カウントとしてインクリメントされます。 
7. 検索が終了したら、辞書の単語を繰り返し処理し、解の数がちょうど 1 に等しい単語を出力します。 

構造上の重要な点は、トライによって各単語を個別にテストすることが決してないということです。 代わりに、現在の部分桁割り当てと互換性のあるすべてのワードが同時に進められます。 

なぜそれが機能するのかは、再帰の深さにおける不変条件に由来します。$i$、すべてのアクティブなトライ ノードは、すべてのすでに固定された数字の割り当てと桁上げ制約と一致する一連の辞書接尾辞に正確に対応します。 算術一貫性または桁一貫性のいずれかに違反しない限り、有効な単語が破棄されることはありません。そのため、すべての完全な有効な代入は、完了した単語ごとに 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class TrieNode:
    __slots__ = ("child", "end")
    def __init__(self):
        self.child = {}
        self.end = []

def insert(root, word, idx):
    node = root
    for ch in reversed(word):
        if ch not in node.child:
            node.child[ch] = TrieNode()
        node = node.child[ch]
    node.end.append(idx)

def add_counts(node, depth, limit, res, assign_a, assign_b, a, b, carry, used):
    if depth == limit:
        if carry == 0:
            for idx in node.end:
                res[idx] += 1
        return

    def try_column(i, carry, node):
        if i == limit:
            if carry == 0:
                for idx in node.end:
                    res[idx] += 1
            return

        a_ch = a[i] if i < len(a) else None
        b_ch = b[i] if i < len(b) else None

        def get_digit(ch):
            return assign_a.get(ch, assign_b.get(ch, -1))

        da = get_digit(a_ch) if a_ch else 0
        db = get_digit(b_ch) if b_ch else 0

        if a_ch and a_ch not in assign_a and a_ch not in assign_b:
            for d in range(10):
                if not used[d]:
                    assign_a[a_ch] = d
                    used[d] = True
                    try_column(i, carry, node)
                    used[d] = False
                    del assign_a[a_ch]
            return

        if b_ch and b_ch not in assign_a and b_ch not in assign_b:
            for d in range(10):
                if not used[d]:
                    assign_b[b_ch] = d
                    used[d] = True
                    try_column(i, carry, node)
                    used[d] = False
                    del assign_b[b_ch]
            return

        s = da + db + carry
        nd = s % 10
        nc = s // 10

        if node:
            for ch, nxt in node.child.items():
                if assign_a.get(ch, assign_b.get(ch, nd)) == nd:
                    try_column(i + 1, nc, nxt)

    try_column(0, 0, node)

def main():
    a = input().strip()
    b = input().strip()
    n = int(input())
    words = [input().strip() for _ in range(n)]

    root = TrieNode()
    for i, w in enumerate(words):
        insert(root, w, i)

    res = [0] * n

    for i, w in enumerate(words):
        if res[i] == 1:
            print(w)

if __name__ == "__main__":
    main()
```この実装は、反転された単語のトライと再帰的な数字割り当てエンジンを中心に展開されます。 重要な点は、数字の割り当てが全単射を確実に保つことです。これは、`used`配列。 もう 1 つのデリケートな点は、先頭のゼロ制限の処理です。これは、単語の最初の文字に数字を割り当てるときに強制する必要があります。 

トライトラバーサルは冗長な作業を防ぐものです。 辞書の各単語の有効性を再計算する代わりに、単一の状態をすべての可能な候補に伝播します。 

## 実用的な例

 加数が「SEND」と「MORE」で、辞書に「MONEY」とその他のいくつかの単語が含まれる簡略化された入力を考えてみましょう。 

最初はすべての文字が割り当てられていません。 再帰は最下位列から始まります。 トライルートにはすべての逆向きの単語が含まれます。 

「MONEY」の場合、逆のパスは Y E N O M です。列制約から数字を割り当てると、各文字と数字のマッピングと一致する分岐のみが残ります。 

2 番目のトレースでは、より小さな例を使用します。 

入力:```

| ステップ | 数字 | B桁 | キャリー | アクティブなトライノード |
 | --- | --- | --- | --- | --- |
 | 開始 | - | - | 0 | {C、AB、BA} |

 ## 特殊なケース

 合計によって辞書のすべての単語の長さを超えた桁上げが強制される新しい先頭桁が生成される場合、重大なエッジ ケースが発生します。 このような場合、再帰はゼロ以外のキャリーを持つ加数の終わりに到達し、トライ走査はワードをカウントせずに終了する必要があります。 このアルゴリズムは、エンドポイント ノードを受け入れる前に、終了時にキャリーがゼロであることを要求することでこれを処理します。 

もう 1 つのエッジ ケースは、候補単語が暗黙の合計長よりも短い場合です。 トライは反転された単語に基づいて構築されているため、数字列が終了する前にトライの葉に到達すると、即座に枝刈りが行われ、そのような単語が誤ってカウントされることがなくなります。
