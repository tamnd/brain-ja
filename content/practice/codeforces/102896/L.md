 ## 解決策
 ## 問題の理解

 ノードが整数キーを格納する固定二分探索ツリーが与えられます。 各ノードは、そのサブツリーのサイズだけでなく、そのサブツリー内の最小キーと最大キーも認識しています。 この構造を使用して、再帰的プロシージャは範囲クエリを実行します。$[L, R]$、その間隔内にツリー内のキーがいくつあるかをカウントします。 

この手順は、単にすべてのノードを走査するわけではありません。 代わりに、サブツリー全体がクエリ範囲から完全に外れる場合はサブツリー全体をスキップしようとします。また、サブツリーが範囲内に完全に含まれる場合は下降を停止し、サブツリー全体を一度にカウントします。 それ以外の場合は、ノードを訪問し、場合によってはそれをカウントし、両方の子に再帰的に続行します。 

各クエリについて計算する必要がある量は、範囲内の値の数ではなく、ツリー上で実行されるときにこの再帰プロシージャが実行する関数呼び出しの数です。 これには、枝刈りによってすぐに終了する呼び出し、完全にカバーされたサブツリーで停止する呼び出し、およびルートでの最初の呼び出しが含まれます。 

制約は大きく、最大 20 万ノードと 20 万クエリです。 すべてのクエリの再帰を直接シミュレーションすると、ツリーの大部分を繰り返し再利用することになります。 最悪の場合、単一のクエリでほぼ構造全体の走査が強制され、すべてのクエリにわたって二次的な動作が発生する可能性があります。 これは 2 秒の制限で処理できる範囲をはるかに超えています。 

主な課題は、値を集計するのではなく、サブツリーの間隔とクエリ範囲との重なり具合に応じて、再帰によって構造がどのように探索されるかをカウントしていることです。 

クエリ範囲がサブツリー間隔と正確に一致する場合、微妙なエッジ ケースが発生します。 たとえば、サブツリーにキーが含まれている場合、$[1, 10]$そしてクエリは$[1, 10]$の場合、関数はそのノードで停止し、その子にはアクセスしません。 常に下降する単純なトラバーサルでは、呼び出しが誤って過大にカウントされてしまいます。 

もう 1 つのエッジ ケースは、クエリ範囲がサブツリーを完全に除外する場合です。 サブツリーに間隔がある場合$[20, 30]$そしてクエリは$[1, 10]$の場合、再帰は子を訪問せずにすぐにゼロを返します。 単純な DFS は依然としてサブツリーを探索し、呼び出しを過剰にカウントします。 

## アプローチ

 ブルート フォース ソリューションは、文字通りすべてのクエリに対して説明された再帰を実行します。 ノードの間隔をチェックし、プルーニングするかどうかを決定し、必要に応じて子に再帰的にアクセスします。 これは定義を正確に反映しているため、正しいです。 

ただし、このアプローチは各クエリが多くのノードに影響する可能性があるため、コストがかかります。 ツリーが歪んでいたり、クエリ範囲が広い場合、1 つのクエリがすべてのクエリを訪問する可能性があります。$n$ノード。 と$q$クエリ、これは次のことにつながります$O(nq)$最悪の場合の動作。これは完全に実行不可能です。$2 \cdot 10^5$。 

重要な点は、再帰がセグメント ツリー範囲クエリと構造的に同一であるということです。 各ノードはキーの間隔を表し、その間隔が部分的にクエリと重複する場合にのみ再帰が分割されます。 ノードが完全にクエリ範囲内にある場合、再帰はそのノードで直ちに停止します。 完全に外側にある場合は完全にスキップされます。 

これは、再帰が常に、切り離されたカバーされたセグメントへのツリーの「標準分解」のノードと、それらに向かって下降中に遭遇する中間ノードを正確に訪問することを意味します。 したがって、訪問された呼び出しの数は、どのサブツリー間隔がクエリの完全に内側にあるか、部分的に重複しているか、または完全に外側にあるかによってのみ決まります。 

再帰をシミュレートする代わりに、ツリーをキーのソート順にわたるセグメント ツリーとして扱うことができます。 各ノードの最小-最大間隔によって連続セグメントが形成され、子がそのセグメントに分割されます。 クエリ$[L, R]$これは、間隔が完全に覆われているか、部分的に交差しているセグメントツリー状のノードの小さなセットを生成します。 再帰呼び出しをカウントすることは、このセグメント ツリーの走査で訪問したノードをカウントすることと同じになります。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(n)$| 遅すぎる |
 | セグメントツリースタイルのトラバーサル |$O(\text{visited nodes per query})$、償却済み$O(\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードを前処理して、そのサブツリー間隔を把握します。$[min[v], max[v]]$。 

クエリごとに$[L, R]$では、再帰的走査の構造をシミュレートしますが、間隔チェックを使用して不必要な降下を回避します。 

1. 根元から始めます。 概念的には、ルート ノードで最初の関数呼び出しを行うため、それをすぐにカウントします。 
2. 現在のノードの間隔が完全に外れている場合$[L, R]$、展開せずに戻ります。 これは剪定に相当します。 
3. 現在のノードの間隔が完全に含まれている場合$[L, R]$、元の関数が返すことになるため、このノードを 1 回の呼び出しとしてカウントし、その下で再帰を停止します。`v.count`子供たちを訪問せずに。 
4. それ以外の場合、間隔は部分的にクエリと重複します。 現在のノードを数えてから、左と右の子を再帰的に調べます。 
5. この制御された走査全体で訪問したすべてのノードを合計します。 

重要な考え方は、元の再帰を文字通りに実行しているわけではないということです。 間隔比較のみを使用して、その_制御フローの決定_を再現しています。 

### なぜ効果があるのか

 元の関数のすべての再帰呼び出しは、サブツリー間隔が完全に無関係であることがわかっていないノードに入ることに対応します。 ノードの間隔が完全にクエリ内にある場合、再帰は直ちに停止するため、子孫呼び出しは存在しません。 完全に屋外にある場合、通話は存在しますが、すぐに終了します。 部分的に重複する場合は、子まで再帰を続行する必要があります。 

これにより、間隔の関係によって完全に決定される固有の訪問パターンが作成されます。 サブツリー間隔は階層を形成するため (各子間隔は親間隔に厳密に含まれます)、再帰は常に同じ決定論的な間隔分割のセットに従います。 私たちの走査はそれらの分割を正確に再現するため、関数呼び出しの数と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
left = [0] * (n + 1)
right = [0] * (n + 1)
key = [0] * (n + 1)

for i in range(1, n + 1):
    l, r, k = map(int, input().split())
    left[i] = l
    right[i] = r
    key[i] = k

minv = [0] * (n + 1)
maxv = [0] * (n + 1)

def dfs(v):
    minv[v] = key[v]
    maxv[v] = key[v]
    if left[v]:
        dfs(left[v])
        minv[v] = min(minv[v], minv[left[v]])
        maxv[v] = max(maxv[v], maxv[left[v]])
    if right[v]:
        dfs(right[v])
        minv[v] = min(minv[v], minv[right[v]])
        maxv[v] = max(maxv[v], maxv[right[v]])

dfs(1)

q = int(input())

def solve(v, L, R):
    if v == 0:
        return 0
    if maxv[v] < L or minv[v] > R:
        return 1
    if L <= minv[v] and maxv[v] <= R:
        return 1
    return 1 + solve(left[v], L, R) + solve(right[v], L, R)

out = []
for _ in range(q):
    L, R = map(int, input().split())
    out.append(str(solve(1, L, R)))

print("\n".join(out))
```最初の部分では、事後 DFS を使用してサブツリー間隔を構築します。 各ノードの最小値と最大値はその子から計算されます。すべての枝刈りの決定はこれらの範囲に依存するため、これは不可欠です。 

クエリ関数は、問題で説明されている再帰プロセスを直接反映しています。 すべての通話が貢献します`1`なぜなら、`lookup`カウントされます。 現在のサブツリーがクエリの外側にある場合、呼び出しは引き続きカウントされますが、停止します。 完全に内側に入った場合もコールをカウントしますが、早めに終了します。 それ以外の場合は、両方の子に分岐します。 

重要な点は、ルート呼び出しをスキップしたり、ケースをマージしたりして最適化を試みないことです。これは、問題は明らかに関数呼び出し数に関するものであり、作業を伴う訪問ノードに関するものではないためです。 

## 実用的な例

 ノード 1 に子 2 と 3 があり、2 が左、3 が右になるようにキーが配置されている小さなツリーを考えてみましょう。 

すべてのキーを完全にカバーするクエリの場合、走査はルートで直ちに停止します。 

| ステップ | ノード | 間隔 | 決定 | 電話 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 完全なツリー | 完全に内側 | 1 |

 これは、root 呼び出しのみが行われることを示しています。 

次に、すべてを除外するクエリを考えてみましょう。 

| ステップ | ノード | 間隔 | 決定 | 電話 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 完全なツリー | 子をチェックするための部分的/外部リード | 1 |
 | 2 | 2 | 左のサブツリー | 外側 | 2 |
 | 3 | 3 | 右のサブツリー | 外側 | 3 |

 ここでもすべてのノードが 1 回呼び出されますが、再帰は各ノードですぐに停止します。 

これは、関数呼び出し数が訪問したサブツリー サイズと同じではなく、試行されたすべての降下ステップをカウントしていることを示しています。

 ## 特殊なケース

 完全にカバーされたサブツリーは、早期停止動作を示しています。 サブツリーの場合$[1, 100]$そしてクエリ$[1, 100]$の場合、関数はルートのみを呼び出し、降下しないため、出力は正確に 1 になります。 

完全に独立したサブツリーは枝刈りを示しています。 サブツリーの場合$[50, 60]$そしてクエリ$[1, 10]$の場合でも、関数はノードを 1 回呼び出し、除外を検出し、すぐに停止します。 

歪んだツリーは最悪の場合の深さをテストします。 ツリーがチェーンに縮退すると、すべてのノードが部分重複クエリのために順番にアクセスされ、アルゴリズムはそのパスに沿ったノードごとに 1 つの呼び出しを正しくカウントします。
