 ## 解決策
 ## 問題の理解

 小文字のラテン文字で構成される文字列が与えられます。 この文字列から、文字を繰り返し選択し、それを書き留め、残りの文字列を厳密に左側の部分と厳密に右側の部分に分割することで、新しい文字列を構築できます。 次に、同じプロセスを両方の部分に個別に順番に適用します。 選択の完全なシーケンスごとに、元の文字列のすべての文字を何らかの順序で並べた最終的な 1 つの文字列が生成されますが、任意の順列ではありません。順序は、選択したピボットを中心とした再帰的な分割によって制限されます。 

タスクは、この再帰的な「ピボットを選択して両側で再帰する」プロセスによって生成できる辞書編集上の最小の文字列を決定することです。 

この制約により、文字列の長さは最大 200,000 まで許可され、考えられるすべての選択肢、さらにはセグメントのすべての順列をシミュレートしようとするソリューションは即座に除外されます。 選択肢に基づいて分岐したり、ステップごとに複数の候補文字列を構築したりするアプローチは、指数関数的に爆発的に増加します。 線形または線形に近い動作、通常は O(n log n) または O(n) が必要です。 

微妙なエッジ ケースとして、文字が繰り返されると有効なピボットが複数選択され、異なる構造分解が生じる可能性があります。 たとえば、「bbaacc」のような文字列では、同じ最小文字の異なる出現を選択すると分割パターンが変化します。また、構造について慎重に推論しない限り、左端の出現を単純に貪欲に選択することは明らかに安全ではありません。 

もう 1 つの明白ではない落とし穴は、これが文字列の並べ替えと同等であると想定していることです。 そうではない。 再帰により、どの文字を他の文字と入れ替えることができるかが制限されるため、場合によっては一致する場合でも、出力はソートされた文字の複数セットだけであるとは限りません。 

## アプローチ

 ブルートフォース解釈では、プロセスを正確にシミュレートします。 文字列セグメントの場合、考えられるすべてのピボット位置を選択し、左右のセグメントの結果を再帰的に計算し、ピボットと両方の結果を連結します。 次に、すべての選択肢の中から辞書編集的に最小のものを選択します。 

これは定義に直接従うため機能しますが、壊滅的に遅いです。 長さ n の文字列の場合、各状態は最大 n 個の選択肢に分岐し、各選択肢は 2 つの部分問題に分割されます。 結果として生じる再帰ツリーの数は、超指数関数的に増加します。 異なるピボットシーケンスは異なる構造状態を生成し、一般に個別の部分構造の数は依然として指数関数的であるため、メモ化でもそれは保存されません。 

重要な観察点は、プロセスでは常に 1 つの文字がルートとして選択され、他の文字はすべてその文字に関連して分割されるということです。 辞書編集的に最小の結果が必要な場合は、より小さい文字が最終出力のできるだけ早い段階で表示されるようにする必要があります。 これは、構造上の貪欲な選択を示唆しています。各段階で、現在のセグメント内の最小の文字を選択する必要があります。最初の文字が大きいと、結果の文字列がすぐに辞書編集上、小さい文字で始まる文字列よりも悪くなるからです。

最小の文字を修正すると、セグメント内で出現するすべての文字は、パーティション化の点でのみ交換可能になりますが、それらはすべて有効な分解を生成します。 重要な単純化は、元の位置によって引き起こされる順序を維持しながら、常に利用可能な最小の文字を取得し、同じロジックを残りの部分に再帰的に適用することによって、最終的な答えを構築できることです。 これにより、最小の文字を繰り返し抽出し、それに応じて残りの構造を分割するという問題が軽減されます。これは、スタックのような再構築によるセグメントを意識した貪欲なトラバーサル、または次の出現ポインタを使用した分割統治を使用して効率的に実装できます。 

実際の標準的な解決策は、文字列を間隔として扱い、現在の間隔内の最小文字を繰り返し選択し、その左右のサブ間隔で再帰的に順序を常に維持することです。 これは、セグメント ツリーまたは RMQ 構造を使用して O(n log n) で実行できます。

 ## アルゴリズムのチュートリアル

 現在の問題を、構造的制約の下で常に可能な限り最良の次の文字を抽出しながら、部分文字列間隔から答えを構築するものとして表します。 

1. 任意の間隔内の最小文字の位置を返すことができる文字列にわたる範囲最小クエリ構造を事前計算します。 これは、辞書編集順で次にどの文字を配置できるかを迅速に決定するために必要です。 
2. 部分文字列 s[l:r+1] から取得可能な最良の文字列を返す再帰関数solve(l, r) を定義します。 この関数の目的は、分割ルールに従って最適なシーケンスを構築することです。 
3.solve(l, r) で、RMQ 構造体を使用して s[l:r+1] 内の最小文字の位置 m を見つけます。 この文字は、このセグメントのすべての有効な構造の中で強制的に最初に配置されます。これは、より大きな文字を前に配置する有効な構造は辞書編集的に悪くなるからです。 
4. 答えに s[m] を追加します。 
5. 左側のセグメントを再帰的に解決します(l, m-1)。 これにより、選択したピボットの左側にもともと存在する文字が可能な限り最良の順序で配置されます。 
6. 右側のセグメントで再帰的にソルブ(m+1, r)を実行します。 これにより、右側にある文字が可能な限り最適な順序で配置されます。 
7. 元の分割プロセスでの再帰による構築順序の定義方法を考慮して、結果を左、ピボット、右の順序で連結します。 

### なぜ効果があるのか

 再帰の不変条件は、どのセグメントでも、常にそのセグメント内の使用可能な最小の文字を結果の文字列のできるだけ早い段階に配置することです。 最初に最小の文字を選択することから逸脱すると、より小さい文字を選択する有効な構造と比較して、辞書編集的に大きな接頭辞が即座に導入されてしまいます。 ピボットを修正した後、再帰呼び出しを除いて、構築プロセスでは選択したピボット境界を越えて文字が混在することはないため、左側と右側の部分は独立したサブ問題になります。 これにより、最適な部分構造が保証されます。つまり、区間の最適解は、その部分区間の最適解で構成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, s):
        self.n = len(s)
        self.s = s
        self.seg = [(chr(127), -1)] * (4 * self.n)
        self._build(1, 0, self.n - 1)

    def _better(self, a, b):
        return a if a[0] < b[0] or (a[0] == b[0] and a[1] < b[1]) else b

    def _build(self, v, l, r):
        if l == r:
            self.seg[v] = (self.s[l], l)
            return
        m = (l + r) // 2
        self._build(v * 2, l, m)
        self._build(v * 2 + 1, m + 1, r)
        self.seg[v] = self._better(self.seg[v * 2], self.seg[v * 2 + 1])

    def query(self, v, l, r, ql, qr):
        if ql > r or qr < l:
            return (chr(127), -1)
        if ql <= l and r <= qr:
            return self.seg[v]
        m = (l + r) // 2
        return self._better(
            self.query(v * 2, l, m, ql, qr),
            self.query(v * 2 + 1, m + 1, r, ql, qr)
        )

def solve():
    s = input().strip()
    n = len(s)
    st = SegTree(s)

    sys.setrecursionlimit(10**7)

    def dfs(l, r):
        if l > r:
            return ""
        ch, idx = st.query(1, 0, n - 1, l, r)
        return ch + dfs(l, idx - 1) + dfs(idx + 1, r)

    print(dfs(0, n - 1))

if __name__ == "__main__":
    solve()
```セグメント ツリーには、ノードごとに、そのセグメント内の最小文字とそのインデックスが格納されます。これは、正しい分割を再構築するために必要です。 各再帰呼び出しはクエリを使用して対数時間でピボット位置を見つけ、その後、左右の間隔に分割します。 

実装の微妙な詳細は、文字とインデックスの両方を返すことです。これは、等しい文字を一貫して並べる必要があるためです。そうしないと、再帰によって一貫性のないピボットが選択され、決定性が損なわれる可能性があります。 

再帰では、最初に左側の結果、次にピボット、次に右側の結果が連結され、選択した文字を中心とした分割の構造定義と一致します。

 ## 特殊なケース

 主なエッジケースは、文字列が同じ文字の繰り返しで構成されている場合です。 この場合、すべての文字は有効なピボットであり、再帰では正確さに影響を与えることなく、一貫して 1 つのインデックスを選択する必要があります。 インデックスによるセグメント ツリーのタイブレークにより、決定的な選択が保証されるため、入力に対して`aaaa`、再帰呼び出しごとに左端が選択されます。`a`再帰は単に文字列を線形に剥がし、次の結果を生成します。`aaaa`。 

もう 1 つのエッジ ケースは、次のような厳密に減少する文字列です。`dcba`。 アルゴリズムは常に選択します`a`最初に最上位レベルで、次に残りのセグメントを再帰的に分解します。 各再帰では、残っている最小の文字が選択され続け、次の結果が生成されます。`abcd`。 セグメント分割により、反転が残らないことが保証されます。 

3 番目のケースは、次のような交互パターンです。`ababab`。 ここでは、複数の同一の極小値が異なる位置に存在します。 インデックス タイブレークにより安定した分割が確保され、不一致な分割が防止され、再帰によりバランスの取れた分解が構築され、辞書編集上最小の有効な再構成が得られます。
