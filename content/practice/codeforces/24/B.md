 ## 解決策
 ## 問題の理解

 私たちはF1シーズン全体の結果を与えられています。 各レースには、1 位から最下位までのドライバーがリストされています。 チャンピオンシップの勝者は 2 つのランキング システムのいずれかによって決まります。 

オリジナルのシステムでは、ドライバーは主に合計ポイントによってランク付けされます。 各レースの上位 10 位には固定ポイントが与えられます: 25、18、15、12、10、8、6、4、2、1。2 人のドライバーが同じポイント数を持っている場合、1 位フィニッシュの回数を比較します。 それでも同点の場合は、2 位、次に 3 位というように比較します。 

代替システムでは、最初の 2 つの優先順位が逆転します。 ドライバーは勝利数で1位にランクされます。 勝利数が等しい場合は、合計ポイントを比較します。 それでも同点の場合は、再度 2 位、3 位などのカウントを比較します。 

入力により、すべてのレースが順番に表示されます。 レースごとに、フィニッシュ順位ごとに分類された参加ドライバーのリストを受け取ります。 ドライバーはいくつかのレースをスキップする可能性がありますが、少なくとも 1 回出場した場合でも最終順位に考慮する必要があります。 

制約は非常に小さいです。 最大で 20 のレースがあり、全体で最大 50 人のドライバーが参加します。 各レースに 50 人のドライバー全員が参加したとしても、レース結果の総数はわずか 1000 件です。つまり、高度な最適化技術や複雑なデータ構造は必要ありません。 ランキング ルールを直接実装しても十分高速です。 

本当に難しいのは、タイブレークを正しく実装することです。 比較ルールはポイントや勝ちだけではなく辞書順に行われるため、不注意な実装は失敗することがよくあります。

## アプローチ

 最も直接的なアプローチは、シーズン全体を書かれたとおりに正確にシミュレーションすることです。 すべてのドライバーについて、合計ポイントと各ポジションでの完走回数を保存します。 すべてのレースを処理した後、必要なランキング ルールに従ってすべてのドライバーのペアを比較します。 

ブルート フォース バージョンでは、2 つのドライバーを比較するたびに、すべての統計を最初から再計算できます。 ドライバー A と B を比較するとします。すべてのレースをスキャンし、両方のポイントと順位を数えて、どちらが上位にランクされるかを決定できます。 最大 50 人のドライバーの場合、およそ 2500 件の比較を実行する可能性があり、各比較で最大 1000 件のレース結果をスキャンできます。 これでも、数百万回程度の操作の制限内に収まります。 

それでも、同じ情報を繰り返し再計算する必要はありません。 すべての比較は、蓄積されたシーズン統計のみに依存します。 これに気づくと、問題ははるかにすっきりします。 

重要な観察は、各ドライバーのシーズンがコンパクトな記録で表現できるということです。 

1. 合計ポイント。 
2. 1位の数。 
3. 2位の数。 
4. 3位の数。 
5. など。 

その後、ドライバーのランキングはこれらの記録間の純粋な辞書編集的な比較となり、2 つのスコアリング システムの優先順位はわずかに異なります。 

元のシステムの比較キーは次のとおりです。```
(points, first_places, second_places, ...)
```代替システムの場合、比較キーは次のとおりです。```
(first_places, points, second_places, ...)
```ドライバーとレースの数が少ないため、すべてのドライバーを反復処理し、選択したコンパレータに従って最良のドライバーを維持することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(D² × R × N) | お(1) | 承認済み |
 | 最適 | O(R × N + D² × N) | O(D × N) | 承認済み |

 ここ、`D`はドライバーの数、`R`はレースの数であり、`N`レースで分類されたドライバーの最大数です。 

## アルゴリズムのチュートリアル

 1. すべてのドライバーの辞書を作成します。 

ドライバーごとに、以下を保存します。 

- 合計ポイント。 
- 配列`places[i]`ドライバーがそのポジションでフィニッシュした回数をカウントします`i`。 

タイブレークは勝利後も続く可能性があるため、完全な配置数が必要です。 
2. すべてのレースを上から下まで処理します。 

最初のドライバーが勝者、2 番目のドライバーが 2 位というように続きます。 更新:

 - そのポジションの配置カウンター。 
- 順位がトップ 10 以内の場合、ドライバーのポイント。 
3. 元のシステムの比較関数を定義します。 

2 つのドライバーを次の順序で比較します。 

- 合計ポイント。 
- 1位の数。 
- 2位の数。 
- 3位の数。 
- 違いが現れるまで続けます。 

これはチャンピオンシップのルールに正確に一致します。 
4. 代替システム用に別の比較関数を定義します。 

この順序で比較します。 

- 勝利数。 
- 合計ポイント。 
- 2位の数。 
- 3位の数。 
- 必要に応じてさらに続行します。 

代替ルールでは一貫性よりも勝利が優先されるため、勝利が最初にチェックされます。 
5. すべてのドライバーを反復処理して、各システムで最適なドライバーを見つけます。 

現在のチャンピオンとして任意のドライバーから始めます。 他のドライバーごとに、比較関数を適用します。 新しいドライバーのランクが高い場合は、チャンピオンを置き換えます。 
6. 両方のチャンピオンを出力します。 

### なぜ効果があるのか

 すべてのレースは、各ドライバーのシーズン統計に独立して寄与します。 合計ポイントと順位数によって、公式のランキング ルールが完全に決まります。 レースの順序やレースのアイデンティティからの追加情報は重要ではありません。 

比較関数は問題のステートメントを正確に反映します。 1 人のドライバーがより多くのポイントを獲得した場合、元のシステムではそのドライバーがすぐに勝ちます。 ポイントが等しい場合は、最初の異なる配置数によってランキングが決まります。 代替システムは同じロジックに従い、勝利が最初にチェックされます。 

すべてのドライバーの統計が正しく蓄積され、比較は公式のタイブレーク順序に従って行われるため、選択されたチャンピオンは正しい必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

POINTS = [25, 18, 15, 12, 10, 8, 6, 4, 2, 1]

def solve():
    t = int(input())

    drivers = {}

    for _ in range(t):
        n = int(input())

        for pos in range(n):
            name = input().strip()

            if name not in drivers:
                drivers[name] = {
                    "points": 0,
                    "places": [0] * 55
                }

            drivers[name]["places"][pos + 1] += 1

            if pos < 10:
                drivers[name]["points"] += POINTS[pos]

    names = list(drivers.keys())

    def better_original(a, b):
        da = drivers[a]
        db = drivers[b]

        if da["points"] != db["points"]:
            return da["points"] > db["points"]

        for place in range(1, 55):
            if da["places"][place] != db["places"][place]:
                return da["places"][place] > db["places"][place]

        return False

    def better_alternative(a, b):
        da = drivers[a]
        db = drivers[b]

        if da["places"][1] != db["places"][1]:
            return da["places"][1] > db["places"][1]

        if da["points"] != db["points"]:
            return da["points"] > db["points"]

        for place in range(2, 55):
            if da["places"][place] != db["places"][place]:
                return da["places"][place] > db["places"][place]

        return False

    champion_original = names[0]
    champion_alternative = names[0]

    for name in names[1:]:
        if better_original(name, champion_original):
            champion_original = name

        if better_alternative(name, champion_alternative):
            champion_alternative = name

    print(champion_original)
    print(champion_alternative)

solve()
```このソリューションはまず、すべてのドライバーのシーズン統計を構築します。 の`places`配列には、ドライバーが各ポジションでフィニッシュした回数が格納されます。 索引`1`勝利を表す、インデックス`2`は 2 位などを表します。 

固定サイズの配列を使用する方が、比較中に構造体のサイズを動的に変更するよりも簡単で安全です。 レースには最大でも 50 人のドライバーが参加するため、サイズ 55 のアレイはあらゆる可能な配置を快適にカバーします。 

2 つの比較関数はランキング システムを直接エンコードします。 元のシステムでは最初にポイントを比較しますが、代替システムでは最初に勝利を比較します。 これらの主な基準の後、どちらも辞書順に配置カウントを続行します。 

微妙な詳細の 1 つは、タイブレーカーのループ範囲です。 元のシステムはその場からチェックを開始します`1`なぜなら勝利はポイント後の最初のタイブレークだからです。 すでに処理されている代替システムが個別に勝利するため、そのループはその場所から開始されます`2`。 

もう 1 つの重要な実装上の選択肢は、トップ 10 フィニッシュだけでなく、すべての順位を保存することです。 ポイント外のドライバーはその後のタイブレークに影響を及ぼします。
