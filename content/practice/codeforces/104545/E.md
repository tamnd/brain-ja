 ## 問題の理解

 私たちには、進化する「統計」のコレクションが与えられており、それぞれが真か偽のいずれかになります。 最初に存在するのは、`v`本当の統計と`f`虚偽の統計。 重要な重要な量は、すべての統計のうちの誤った統計の割合です。 

複数回適用できる特別な操作があります。 これを適用するたびに、「統計の 75% 以上が誤りである」というステートメントが考慮されます。 このステートメント自体が新しい統計となり、その真理値は現在の比率に依存します`f / (v + f)`。 

現在の偽統計の割合が厳密に 3/4 より大きい場合、そのステートメントは真とみなされ、値が増加します。`v`1 ずつ増加します。それ以外の場合は増加します`f`各操作の後、統計の合計数は 1 ずつ増加し、しきい値を超えたかどうかに応じて true と false の間の分布が変化します。 

偽の統計の割合が正確に 75% になるまで、この操作を何回適用する必要があるかを決定する必要があります。`f / (v + f) = 3/4`。 

制約により、最大で次のことが許可されます。`10^5`値が最大のテスト ケース`10^8`。 これにより、プロセスにはテストごとに直線的な時間がかかり、累積すると実行不可能な合計に達する可能性があるため、最悪の場合、操作ごとに分数を段階的に再計算するシミュレーションは除外されます。 

単純なシミュレーションには、構造的な落とし穴も隠されています。比率が 3/4 より上か下かによって決定が反転します。これは、明らかな変数において更新のシーケンスが単調ではないことを意味します。 収束するまで反復しようとすると、不等式によって動作が切り替わる境界を簡単に誤って処理してしまう可能性があります。 

エッジケースの小さな例としては、`v = 1, f = 2`。 比率は`2/3`、これは 3/4 を下回っているため、操作が増加します。`f`。 やみくもに繰り返すと、明らかな収束が得られずにシステムが急速に変化していきます。 不注意なシミュレーションでは、収束が目標比率に向かって即時または単調であると想定する可能性がありますが、これは構造的に保証されていません。 

本当の課題は、プロセスをシミュレートすることを求められるのではなく、正確な代数条件に到達するために必要な正確なステップ数を決定することを求められることです。 

## アプローチ

 直接的なアプローチでは、プロセスを段階的にシミュレートします。 各ステップでは、次のことを確認する必要があります。`f / (v + f) > 3/4`、いずれかを更新します`v`または`f`、等価条件が満たされるまで継続します。 各ステップは O(1) ですが、ステップ数が大きくなる可能性があります。`v`そして`f`フラクションが正確に 3/4 で安定する点まで成長する可能性があります。 最悪の場合、システムの最終的なサイズに比例した数の操作が必要になる可能性があり、小さな定数によって厳密に制限されることはありません。 

重要な観察は、各操作が恣意的ではなく、常に状態を 2 つの決定的な線形方向のいずれかに沿って移動させるということです。`(v, f)`飛行機。 条件`f / (v + f) > 3/4`と同等です`4f > 3(v + f)`、これを単純化すると、`f > 3v`。 したがって、決定ルールは次のいずれかによってのみ決まります。`f`より大きい`3v`。 

これにより、プロセスが 2 つの体制に分割されます。 もし`f > 3v`、増やします`v`。 それ以外の場合は増加します`f`。 それぞれの操作で次のいずれかが変化します`v`または`f`正確に 1 ずつ増加するため、システムは区分的線形パスに沿って進化します。 

すべてのステップをシミュレートする代わりに、正確な平衡状態に到達するために必要な操作の数を推論できます。`f = 3(v + f)/4`、これを単純化すると、`4f = 3(v + f)`そしてさらに`f = 3v`。 したがって、目標は、次の状態に到達することです。`f = 3v`。 

調整を繰り返すプロセスと解釈できます`(v, f)`この線形制約が満たされるまで。 それぞれの操作が増加します`v`または増加します`f`そして、ライン上に正確に着地するために必要な増分数を数えたいとします。`f = 3v`。 

これは決定論的な算術問題になります。現在の状態が満足のいく状態からどれだけ離れているかを追跡します。`f = 3v`、そして各操作が制御された方法でそれを近づけます。

 ## アルゴリズムのチュートリアル

 条件を再公式化し、必要なステップ数を直接表現します。 

1. 対象となる条件が何であるかを把握することから始める`f = 3v`。 これは書き換えから来ています`f / (v + f) = 3/4`、これは次のようになります。`4f = 3v + 3f`したがって、`f = 3v`。 
2. 間の不等式に応じて操作がどのように動作するかを観察します。`f`そして`3v`。 もし`f > 3v`の場合、現在の小数は 3/4 より大きいため、増分します。`v`。 もし`f ≤ 3v`、増分します`f`。 これは、すべてのステップがシステムを差異のバランスに向けて動かすことを意味します。`f - 3v`。 
3. ポテンシャル関数を定義する`d = f - 3v`。 ターゲットは`d = 0`。 ここでその方法を書き直します`d`操作のたびに変化します。 もし`d > 0`、増分します`v`、変換します`d`の中へ`(f) - 3(v+1) = d - 3`。 もし`d ≤ 0`、増分します`f`、変換します`d`の中へ`(f+1) - 3v = d + 1`。 
4. ここで、次の進化をシミュレーションします。`d`単純なループで 1 つずつステップを踏むのではなく、ブロックごとにジャンプすることによって実行されます。 いつ`d`が正である場合、繰り返し適用すると、正でなくなるまでステップごとに 3 ずつ減少します。 非正の場合、正になるまで繰り返し適用するとステップごとに 1 ずつ増加します。 
5. このプロセスは、減少フェーズと増加フェーズの間で交互に行われます。 各フェーズは、段階的に繰り返すのではなく、除算を使用して直接算術ジャンプに折りたたむことができます。 
6. この交互ジャンプを次のレベルまで続けます。`d`はちょうど 0 になります。蓄積されたジャンプの数が答えになります。 

これが機能する理由は、プロセスが単一の整数状態によって完全に制御されるためです。`d = f - 3v`。 あらゆる操作が変化する`d`その符号のみに依存する固定定数によって計算されます。 それを超える隠れた状態はありません`d`したがって、進化は 2 つの線形遷移規則を伴う整数上の決定論的なウォークです。 繰り返される同一の遷移を折りたたむと、決定ルールが単調なセグメント内で変化しないため、正確さが保たれます。`d`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(v, f):
    d = f - 3 * v
    steps = 0

    while d != 0:
        if d > 0:
            # apply v increments: each reduces d by 3
            # we need to know how many such steps until d <= 0
            k = (d + 2) // 3
            d -= 3 * k
            v += k
            steps += k
        else:
            # apply f increments: each increases d by 1
            k = (-d)
            d += k
            f += k
            steps += k

    return steps

t = int(input())
out = []
for _ in range(t):
    v, f = map(int, input().split())
    out.append(str(solve_one(v, f)))

print("\n".join(out))
```この実装により、同一の操作の長時間実行が圧縮されます。 いつ`d > 0`まで「v を増やす」操作を繰り返し適用します。`d`ゼロと交差するか、-3 ステップの完全なブロックよりも少なくて済むほど十分に小さくなります。 式`(d + 2) // 3`を実現するには 3 を何減分する必要があるかを正確に計算します。`d`ゼロ以下にします。 

いつ`d ≤ 0`、ステップごとに増加します`d`1 なので直接ジャンプします`-d`ゼロに到達するまでのステップ。 これにより、線形成長による 1 つずつの反復が回避されます。 

変数`steps`実行された操作の合計数が累積されます。これが問題で求められるものです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、システムがまさに境界上で開始される場合です。`f = 3v`。 この場合、条件はすでに満たされているため、必要な答えはゼロになります。 たとえば、入力`v = 10, f = 30`与える`d = 0`したがって、アルゴリズムはループに入らずにすぐにゼロを返します。 

別の微妙なケースが発生する場合`f`よりもはるかに小さいです`3v`。 例えば`v = 10, f = 1`与える`d = -29`。 アルゴリズムは単一ブロックを適用して増加します。`f`29時までに直接届く`d = 0`。 単純なシミュレーションでは 29 回の反復が必要ですが、圧縮されたアプローチでは 1 回のジャンプで処理され、この領域のすべてのステップが同一の動作をするため、正確さが保たれます。
