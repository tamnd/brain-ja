 ## 解決策
 ## 問題の理解

 平面内に、それぞれが木を表す一連の点が与えられます。 すべての木をきつめの輪ゴムで包むと、セットの凸包が得られます。 この船体の上に横たわっている木はすでに森林の境界上にありますが、内側の木はそうではありません。 

各ツリーについて、このツリーが残りのセットの境界の一部になるためには、他の何本のツリーを削除する必要があるかを知りたいと考えています。 ポイントを削除しても、ツリーが他のポイントに対して外側に移動するのに役立つだけであるため、質問は幾何学的なものになります。つまり、凸レイヤーの点で各ポイントがポイント セット内にどのくらい深くネストされているかということになります。 

ポイントの答えは、本質的に、凸包を繰り返し除去する剥離プロセスにおける「層の深さ」です。 最も外側のハル上の点には答え 0 があり、外側の層を削除した後の次のハル上のポイントには答え 1 があり、以下同様です。 

この制約により、テスト ケースごとに最大 3000 ポイントが許可され、ポイントごとの 3 次または繰り返しの完全な再計算が即座に除外されます。 削除のたびに凸包を再計算する単純なアプローチでは、O(N² log N) 以上の結果となり、TLE が発生します。 船体を N 回再計算しても遅すぎます。 

微妙なエッジ ケースは、複数の点が同じ凸包境界上にある場合です。 これらはすべて同じ深さ 0 を同時に受信する必要があります。 もう 1 つは同一線上の境界チェーンです。この場合、点は船体のエッジ上にあり、内部の点ではなく境界点として扱われる必要があります。 

## アプローチ

 強引な解釈は次のようになります。各点について、他の点のサブセットを削除し、その点が凸包の一部になるかどうかを確認します。 各サブセットにはハルの計算が必要になるため、これはすぐに指数関数的になります。 

より構造化された大胆なアイデアは、ピーリングをシミュレートすることです。凸包を計算し、それを除去し、次の包を計算する、などです。 これは、各「レイヤー」が除去ステップに対応しているため機能します。 ただし、削除するたびにハルを最初から再計算するとコストがかかります。 素朴に実行すると、各ハル計算のコストは O(N log N) となり、最悪の場合は層が O(N) になり、O(N² log N) になる可能性があります。 

重要な点は、ハルを最初から繰り返し再計算する必要がないということです。 代わりに、ハルを徐々に剥離しながら、各ポイントに「レイヤー番号」を割り当てることができます。 ハルを計算するたびに、そのすべての頂点に現在の深度でラベルを付け、アクティブ セットから削除します。 すべての点にラベルが付けられるまでこれを繰り返すと、正解が得られます。 各ポイントは正確に 1 回削除され、レイヤーごとに最大 1 つのハル計算に参加するため、慎重に実装すれば最大数千の N に対して十分な効率を維持します。 

これは一般にオニオン分解または凸層と呼ばれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ポイントごとにハルを再計算する | O(N3 log N) | O(N) | 遅すぎる |
 | 繰り返される船体剥離 | O(N² log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のアクティブ ポイントのセットから凸包を繰り返し抽出します。 

1. 未処理としてマークされたすべてのポイントから開始します。 配列を維持します`ans`各ポイントの -1 に初期化され、そのレイヤーの深さを表します。 
2. 未割り当ての点がまだある間に、単調連鎖アルゴリズムを使用して現在のアクティブ セットの凸包を計算します。 これにより、残りの構造の外側の境界が得られます。 
3. このハル上にあるすべてのポイントには、現在のレイヤー番号が割り当てられます。 これらの点は、ちょうどこの数のレイヤーを削除した後に境界となる可能性のある木に対応します。 
4. これらのハル ポイントをアクティブ セットから削除します。 
5. レイヤーカウンターをインクリメントし、ポイントがなくなるまで繰り返します。 

重要な考え方は、各反復で点の凸状「シェル」が 1 つだけ剥がされ、すべての点が 1 つのシェルに属するということです。 

## なぜ機能するのか

 各凸包は、現在の点セットの最も外側の境界を表します。 この境界上の点には、すべての方向において厳密にその外側に他の点が残っていないため、その段階では凸面の深さは最小になります。 それらのポイントは残りのレイヤーに囲まれたままであるため、これを削除しても内部のポイントの相対的な深さには影響しません。 したがって、各反復では、凸面の深さの昇順で点の 1 つの完全な層を正確に識別します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(o, a, b):
    return (a[0]-o[0])*(b[1]-o[1]) - (a[1]-o[1])*(b[0]-o[0])

def convex_hull(points):
    points.sort()
    if len(points) <= 1:
        return points

    lower = []
    for p in points:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)

    upper = []
    for p in reversed(points):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)

    return lower[:-1] + upper[:-1]

def solve():
    n = int(input())
    pts = []
    for i in range(n):
        x, y = map(int, input().split())
        pts.append([x, y, i])

    alive = pts[:]
    ans = [-1] * n
    layer = 0

    while alive:
        hull = convex_hull(alive)
        hull_set = set((p[0], p[1], p[2]) for p in hull)

        new_alive = []
        for p in alive:
            if (p[0], p[1], p[2]) in hull_set:
                ans[p[2]] = layer
            else:
                new_alive.append(p)

        alive = new_alive
        layer += 1

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```この実装では、アクティブなポイントのリストが維持され、そのセットの凸包が繰り返し計算されます。 ハル ポイントには現在のレイヤー インデックスが割り当てられ、削除されます。 

実装の微妙な詳細は、船体のメンバーシップを確実に識別することです。 比較に座標が使用される場合のあいまいさを避けるために、インデックスを含む完全なトリプルを保存します。 もう 1 つの詳細は、同一直線上にある境界点が船体に含まれていることを確認することです。これは、`<= 0`向きのチェック。 

## 実用的な例

 中心点を持つ単純な正方形を考えてみましょう。 

入力:```
5
0 0
10 0
10 10
0 10
5 5
```レイヤー 0 では、凸包に 4 つの角が含まれています。 それらにはすべて 0 が割り当てられます。中心は残ります。 

レイヤー 1 では、中心のみが残り、残りのセットのハルを形成するため、1 が割り当てられます。 

| ステップ | アライブセットサイズ | 船体ポイント | 割り当て済み |
 | --- | --- | --- | --- |
 | 0 | 5 | コーナー | 0 |
 | 1 | 1 | 中央 | 1 |

 これにより、外側の境界点が 0 になり、内部の深さが内側に向かって増加することが確認されます。 

ここで、ネストされた内部点を持つ三角形を考えてみましょう。 各ピーリングでは最外層のみが除去され、残りのポイントが新しいハル頂点となり、正しいレイヤリング動作が確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N² log N) | 各層は縮小セットの凸包を再計算します。 
| スペース | O(N) | ポイントと中間ハルを保存する |

 N が最大 3000 の場合、総再計算はポイント数によって制限され、各ハル計算は実際には効率的であるため、このアプローチで十分です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    def cross(o,a,b):
        return (a[0]-o[0])*(b[1]-o[1]) - (a[1]-o[1])*(b[0]-o[0])

    def hull(points):
        points.sort()
        lower=[]
        for p in points:
            while len(lower)>=2 and cross(lower[-2],lower[-1],p)<=0:
                lower.pop()
            lower.append(p)
        upper=[]
        for p in reversed(points):
            while len(upper)>=2 and cross(upper[-2],upper[-1],p)<=0:
                upper.pop()
            upper.append(p)
        return lower[:-1]+upper[:-1]

    alive = pts[:]
    ans = [-1]*n
    layer = 0

    while alive:
        h = set(hull(alive))
        nxt = []
        for p in alive:
            if p in h:
                ans[pts.index(p)] = layer
            else:
                nxt.append(p)
        alive = nxt
        layer += 1

    return "\n".join(map(str, ans))

 | 三角形 | 0 0 0 | すべての境界 |

 ## 特殊なケース

 すべての点が船体の境界上にあるため、完全に同一線上にあるセットは重要なケースです。 この場合、最初のハルは完全なセットに等しいため、すべてのポイントはレイヤー 0 に割り当てられ、すぐに削除されます。凸面で他のポイントよりも深いポイントはないため、これは正しいことです。 

もう 1 つのエッジ ケースは、多くのポイントが同じ凸包エッジ上にある場合です。 これらはすべて同時に同じレイヤーに割り当てる必要があります。 船体の構造には、方向ルールにより同一線上にあるエッジ ポイントが含まれており、それらがすべて一緒に削除され、同じ深さが割り当てられることが保証されます。
