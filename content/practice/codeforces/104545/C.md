 ## 解決策
 ## 問題の理解

 スナックのテーブルを表す小さなバイナリ グリッドが与えられます。各セルは 1 (チーズ ボール) または 0 (コシーニャ) です。 タスクは、軸に沿って整列した長方形のサブグリッドを 1 つだけ選択し、その長方形内にすべてのスナックを収集することです。ただし、長方形にはコシーニャがまったく含まれてはいけないという制限があります。 言い換えれば、四角形内の選択されたすべてのセルは 1 でなければなりません。 

目的は、収集されるチーズ ボールの数を最大化することです。これは、完全に 1 で構成される部分長方形の面積を最大化することと同じです。 

n × m ≤ 400 という制約が重要な構造上の手がかりとなります。 最悪の場合でも、これは非常に小さなグリッドであるため、時間制限を超えるリスクなしに、二次関数またはセルごとにわずかに悪い解を得ることができます。 ただし、これは、意図した解決策がすべての四角形に対するブルートフォースではないことも示唆しています。これは、それでも多くの部分行列を繰り返しチェックする必要があり、不必要なオーバーヘッドと厄介な実装につながるためです。 

考えられるすべての四角形を列挙し、すべてが 1 であるかどうかを検証する素朴なアプローチは、パフォーマンスや実装の複雑さの点で静かに失敗する可能性があります。 たとえば、20 × 20 グリッド上でも約 10^8 個の長方形があり、それぞれをチェックするには追加の作業がかかります。 

素朴な実装のさらに微妙な失敗例は、四角形の誤った検証に起因します。 長方形を選択し、その角または部分的なスキャンのみをチェックするとします。 

入力:```
3 3
1 1 1
1 0 1
1 1 1
```不注意なチェッカーは、境界線のみをチェックしてグリッド全体にまたがる長方形を検証し、それが有効であると結論付け、誤って 9 を返す可能性があります。正しい答えは 4 で、中心のゼロを避ける 2×2 の 1 の部分正方形から得られます。 

これは、正確さが境界値だけではなく、四角形内のグローバル構造に依存することを示しています。 

## アプローチ

 ブルートフォースのアイデアは簡単です。上の行、下の行、左の列、右の列で定義されるすべての可能な部分四角形を列挙し、それぞれについてすべてのセルをスキャンしてゼロが含まれているかどうかを確認します。 そうでない場合は、その面積を計算し、答えを更新します。 

これが機能するのは、問題の定義を直接強制するためです。 ただし、そのコストは急速に増加します。 O(n^2 m^2) 個の長方形があり、各検証のコストは最悪の場合 O(nm) となり、理論上の限界は O(n^3 m^3) になります。 n × m ≤ 400 であっても、これは実際には遅すぎます。 

重要な点は、実際にはすべての四角形の妥当性を最初から再計算する必要がないということです。 代わりに、行全体で構造を再利用できます。 一番下の行を固定すると、グリッドをヒストグラムに圧縮できます。各列には、その行で終わる連続 1 の数が格納されます。 その行で終わるすべて 1 の四角形は、このヒストグラムの連続セグメントになります。 次に、問題はヒストグラム内の古典的な最大の長方形となり、単調スタックで効率的に解決されます。 

これにより、2D 長方形の検索が一連の 1D 問題に変換され、各問題は行ごとに線形時間で解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((nm)^2・nm) | お(1) | 遅すぎる |
 | ヒストグラム DP + スタック | O(nm) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 連続するヒストグラムの高さを表す配列を維持しながら、グリッドを行ごとに処理します。 

1. 配列を初期化する`height`サイズ m でゼロが付きます。 この配列は、各列について、現在の行で終わる連続した列の数を表します。 
2. 各行について、列をスキャンしてヒストグラムを更新します。 現在のセルが 1 の場合、インクリメントします`height[j]`このステップでは、2D 制約を垂直方向のランの 1D 表現に変換します。 
3. 更新されたものについて`height`配列を使用して、ヒストグラム内の最大の長方形を計算します。 これは、単調増加するインデックスのスタックを使用して行われます。 スタックの最上部よりも低い高さに遭遇した場合、ポップされた高さを制限高として使用し、現在のインデックスを正しい境界として使用して、繰り返しポップして面積を計算します。 
4. すべての行にわたって表示される最大面積を記録します。 
5. すべての行を処理した後、最大記録領域を出力します。 

重要な推論ステップは、すべての有効なすべて 1 の四角形には一意の最下行があるということです。 各行を潜在的な下限境界として扱うことで、ヒストグラム段階ですべての四角形が正確に 1 回考慮されるようになります。 

### なぜ効果があるのか

 任意の行 r で、`height[c]`r で終了し、途切れることなく列 c で上向きに伸びる長方形の最大可能高さをエンコードします。 最下行 r を持つすべて 1 の長方形は、すべての高さが少なくとも長方形の高さである列の連続セグメントに対応します。 ヒストグラムの定式化はこれらの制約を正確に捉えているため、ヒストグラム内の最大の長方形が行 r で終わる最適な長方形となります。 すべての長方形には下位行があるため、すべての行をスキャンすることですべての可能性がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def largest_histogram(heights):
    stack = []
    best = 0
    heights.append(0)
    
    for i, h in enumerate(heights):
        while stack and heights[stack[-1]] > h:
            height = heights[stack.pop()]
            left = stack[-1] if stack else -1
            width = i - left - 1
            best = max(best, height * width)
        stack.append(i)
    
    heights.pop()
    return best

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]
    
    height = [0] * m
    answer = 0
    
    for i in range(n):
        for j in range(m):
            if grid[i][j] == 1:
                height[j] += 1
            else:
                height[j] = 0
        
        answer = max(answer, largest_histogram(height))
    
    print(answer)

if __name__ == "__main__":
    solve()
```実装ではローリング ヒストグラムが維持されます。`height`連続したものを垂直に蓄積します。 ヘルパー関数は、高さを強制的に増加させるスタックを使用して、行ごとに線形時間で最適な長方形を計算します。 ヒストグラムに追加されたセンチネル ゼロにより、残りのすべてのスタック要素が計算の最後に確実にフラッシュされます。 

唯一の微妙な実装の詳細は、ゼロのセルに遭遇するとすぐに列の高さをゼロにリセットすることです。これは、そのセルを含む四角形が無効になるためです。 

## 実用的な例

 ### 例 1

```ヒストグラムの展開と計算:

 | 行 | 高さの配列 | 最適なヒストグラム領域 |

 | 1 | [1, 1] | 2 |
 | 2 | [2, 2] | 4 |

 2 行目では、両方の列が高さ 2 に達し、2×2 の長方形を形成するヒストグラムが作成されます。 

これにより、垂直方向の累積が複数の行にまたがる四角形を正しくキャプチャしていることが確認されます。

これは、この方法がどのように自然に垂直方向の連続性を蓄積し、それを水平方向の幅の拡張に変換するかを示しています。

 ## 特殊なケース

 完全にゼロのグリッドは、アルゴリズムが古い値を蓄積するのではなく、ヒストグラムの高さを適切にリセットするかどうかをテストします。 すべての行が 0 の場合、高さの配列は 0 のままで、ヒストグラムは常に 0 を返し、正しい答えが得られます。 

単一行グリッドでは、問題が純粋なヒストグラムに縮小されます。 すべての高さは 0 または 1 であるため、アルゴリズムは 1 の最も長い連続セグメントを正しく計算します。 

完全に 1 つが埋め込まれたグリッドは、最大の蓄積をテストします。 各行ではすべてのヒストグラム値が増加し、最後の行では幅全体が最大の高さで使用できるヒストグラムが生成され、予想どおり n × m が得られます。
