 ## 解決策
 ## 問題の理解

 この物語では、カフェテリアの口座に 1 回だけお金を追加し、そのお金から繰り返し食事に使う登場人物が描かれています。 各食事には 2 通貨単位の固定費がかかります。 未知の回数の食事の後、私たちは 2 つの値を観察します。1 回のチャージで追加された金額と、確認した時点の残高です。 

課題は、充電後に支払われた食事の数を再構築することです。 重要な隠された構造は、リチャージ後に残高が変化する唯一の方法は、食事ごとの一定のコストを繰り返し減算することであるため、問題全体は、アカウントから消えた金額を見つけて、それを 1 回の食事の価格で割ることに帰着します。 

入力により、再充電量と現在の残高という 2 つの整数が得られます。 出力は、充電後に消費された食事の数です。 

制約は非常に小さく、両方の値が 200 で制限され、同じパリティを持つことが保証されます。 これにより、シミュレーションや検索の必要性が即座に排除されます。 値の範囲にわたって定数時間または線形時間で実行されるソリューションは、すでに十分以上です。 

素朴ですがよくある間違いは、リチャージの前に未知の初期残高を再構築しようとすることです。 たとえば、アカウントがゼロから始まったと仮定したり、リチャージ前の履歴を推測しようとしたりする場合があります。 この問題では、再充電が 1 回だけであり、関連するすべての処理がその後に行われることが明示されているため、これは不要です。 

もう 1 つの潜在的な混乱はパリティ制約から生じます。 それぞれの食事の値段がちょうど 2 つであることに気づかずに、パリティなどというものは危険なものだと考える人もいるかもしれません。 実際には、リチャージ残高と最終残高の差が 2 で割り切れることが保証されているため、答えは常に整数になります。 

## アプローチ

 強引な解釈では、食事を 1 つずつシミュレーションすることになります。 チャージ金額から最終残高に達するまで2を繰り返し減算します。 これが機能するのは、各操作が 1 回の食事に直接対応し、観察されたバランスに達したときに正確に停止するためです。 ただし、ここでは境界が小さいとはいえ、このアプローチは食事ごとに 1 回の反復を実行するため、概念的に無駄です。 

重要な観察点は、すべての食事の費用が同じであるということです。 繰り返しの減算をシミュレートする代わりに、追加された額と残った額の差として総使用額を直接計算できます。 その合計支出金額は、食事の数に 2 を乗じたものに等しくなければなりません。 したがって、答えは 1 回の除算で得られます。 

これにより、問題が段階的なプロセスから直接的な算術抽出に削減されます。

 ## アルゴリズムのチュートリアル

 チャージ後の使用金額を計算し、食事回数に換算します。 

1. 2 つの整数、リチャージ値と現在の残高を読み取ります。 これらは、補充後の開始量と観察された残量を表します。 
2. リチャージ金額から最終残高を差し引いて、合計使用金額を計算します。 バランスに影響を与える他の操作がないため、この差はすべての食事を組み合わせたものに正確に対応します。 
3. 各食事には正確に 2 単位の費用がかかるため、使用金額を 2 で割って食事数を求めます。 
4. 結果を出力します。 

### なぜ効果があるのか

1 回のリチャージの後、残高に影響を与える唯一の操作は食事の支払いであり、それぞれの操作で残高がちょうど 2 ずつ減ります。 したがって、残高の合計減少量は食事数のちょうど 2 倍になります。 他のトランザクションは発生しないため、リチャージ後の最初の残高と最終残高の差によって食事回数が一意に決まります。 パリティ条件により、この差が常に偶数であることが保証されるため、整数の除算は剰余なしで有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())
    spent = x - y
    print(spent // 2)

if __name__ == "__main__":
    solve()
```実装は派生した式に直接続きます。 引き算`x - y`リチャージ後の総支出を把握します。 使用金額の各単位が固定の食事数に対応するため、ループやシミュレーションは必要ありません。 

唯一の微妙な点は、整数除算が使用されていることを確認することです。 この問題は同一パリティを保証するため、`x - y`は常に偶数であるため、フロア除算は安全に正しい整数の結果を生成します。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:

    return str(spent // 2)

 ## 特殊なケース

 リチャージが現在の残高と等しい場合、その差はゼロになるため、アルゴリズムはゼロの食事を出力します。 これは、リチャージ後に支出が発生しなかった状況に相当し、減算ステップでは直ちにゼロが生成されます。 

残高がゼロになると、リチャージで得たお金はすべて消費されます。 アルゴリズムは計算します`x - 0`、これはフル充電量に等しく、2で割ると総食事数が得られます。 パリティ制約により次のことが保証されるため、`x`この場合でも、除算は常に正確であり、有効な整数カウントが生成されます。
