 ## 解決策
 ## 問題の理解

 次のサイズの長方形グリッドが与えられます。$N \times M$, ここで、各セルは部屋を表します。 左上のセルから始めます$(1,1)$右下のセルに到達したい$(N,M)$。 移動は通常のグリッドの単調な移動に制限されます。つまり、各ステップは 1 セル下または 1 セル右に移動するため、有効なルートはすべて、訪問セルの数という点で最短パスになります。 

このグリッドの内側には禁止されたセルがあります$(X,Y)$そこは訪れてはいけないもの。 そのセルを通過するパスは無効であるため、カウントから除外する必要があります。 タスクは、その 1 つのブロックされたセルを回避しながら、開始から終了までに存在する最短パスがいくつあるかを計算することです。 

制約は小さいです。$1 \le N, M \le 30$。 これにより、グリッドが動的計画法や組み合わせ論にとって十分に小さいことがすぐにわかります。 ナイーブでも$O(N \cdot M \cdot 2)$または$O(N^2 M^2)$アプローチは許容されますが、パス上の指数関数的なものは不要です。 

禁止されたセルが開始点または目的地のいずれかに一致する場合、微妙なエッジ ケースが発生します。 もし$(X,Y) = (1,1)$の場合、すぐにブロックされるため、パスはまったく存在しません。 もし$(X,Y) = (N,M)$、同じ理由で宛先に到達できません。 もう 1 つの重要なケースは、ブロックされたセルがすべての最短パス構造の外側にあり、グリッド境界により到達不能または無関係である場合です。ただし、単調グリッドではすべてのセルが到達可能であるため、些細な方法でエッジにない限り、常に問題になります。 

## アプローチ

 この問題を考える最も直接的な方法は、有効なパスをすべて列挙することです。$(1,1)$に$(N,M)$、右または下のみにステップし、通過したものは破棄します。$(X,Y)$。 すべてのパスが明示的にチェックされるため、これは概念的には単純で正しいですが、組み合わせ的に爆発的です。 1 つの中にある単調なパスの数$N \times M$グリッドは$\binom{N+M-2}{N-1}$、中程度のサイズであっても非常に急速に増大し、それらを明示的に列挙することは、$30 \times 30$。 

重要な観察は、セルを通過することを条件とする場合、すべての有効なパスが 2 つの独立したセグメントで構成されていることです。$(1,1)$あるセルに、そしてそのセルから$(N,M)$。 この構造は、動的計画法または組み合わせ論を示唆しています。 すべてのセルはその上部または左隣のセルからのみ到達できるため、完全なパスについて考える代わりに、各セルに到達する方法が何通りあるかを数えます。 

禁止セルは、ウェイの数を強制的にゼロにするバリアとして機能するだけで、これに依存するすべてのパスは DP 伝播で自然に消えます。 これにより、問題は 1 つのブロック状態での標準的なグリッド パスのカウントに変わります。

 ## アルゴリズムのチュートリアル

 DP テーブルを定義します。`dp[i][j]`セルに到達する方法の数を表します$(i,j)$から$(1,1)$禁断の独房を踏まずに。 

1. 2D 配列を初期化する`dp`サイズの$N \times M$ゼロ付き。 これにより、明示的に到達しなかったセルはデフォルトで無効のままになります。 
2.セット`dp[1][1] = 1`開始セルが禁止されていない場合、そうでない場合、答えはすぐにゼロになります。 すべてのパスがここから始まるため、これにより DP 全体が固定されます。 
3. すべてのセルを行優先の順序で繰り返します。 細胞ごとに$(i,j)$、禁止された位置と一致する場合$(X,Y)$、私たちは強制します`dp[i][j] = 0`そしてそこからのトランジションをスキップします。 これにより、それを通過するすべてのパスが効果的に削除されます。 
4. セルがブロックされていない場合は、その有効な先行セルからの寄与を伝播します。$i > 1$、 追加`dp[i-1][j]`、そしてもし$j > 1$、 追加`dp[i][j-1]`。 これらは上または左からの到着に対応しており、許可される唯一の動きです。 
5. 表に記入すると、答えは次のようになります。`dp[N][M]`、禁止されたセルに触れることのないすべての有効な最短パスを集約します。 

これが機能する主な理由は、セルへのすべての有効なパスが、上または左からの最後の 1 つの移動で終了する必要があることです。 これにより、すべてのパスの完全で重複のない分解が作成され、各パスが最初に各状態に到達したときに正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M, X, Y = map(int, input().split())
    
    if (X, Y) == (1, 1):
        print(0)
        return
    
    dp = [[0] * (M + 1) for _ in range(N + 1)]
    dp[1][1] = 1
    
    for i in range(1, N + 1):
        for j in range(1, M + 1):
            if i == 1 and j == 1:
                continue
            if i == X and j == Y:
                dp[i][j] = 0
                continue
            
            ways = 0
            if i > 1:
                ways += dp[i - 1][j]
            if j > 1:
                ways += dp[i][j - 1]
            dp[i][j] = ways
    
    print(dp[N][M])

if __name__ == "__main__":
    solve()
```DP テーブルは、問題ステートメントと一致し、インデックス シフト エラーの繰り返しを避けるために、意図的に 1 インデックスが付けられています。 禁止セルは、遷移ロジックが適用される前に明示的にゼロに設定され、下流の状態に寄与できないようにします。 

微妙な点の 1 つは、開始セルを個別に処理することです。 そのガードがないとループは上書きしてしまいます`dp[1][1]`特に基本ケースを統合する実装では、遷移を通じて誤って二重にカウントされます。

            if j > 1:
                ways += dp[i][j - 1]
            dp[i][j] = ways

 ## 特殊なケース

 禁止セルが開始位置の場合$(1,1)$の場合、パスを開始することさえできないため、DP はすぐにゼロに解決されます。 アルゴリズムは早期リターンを通じてこれを処理し、不必要な計算を防ぎます。 

禁止セルが目的地の場合$(N,M)$、そのセルは強制的にゼロに設定され、決して寄与しないため、DP は当然最後にはゼロになります。 たとえば、$2 \times 2$ブロックのあるグリッド$(2,2)$、すべてのパスが禁止状態で終了するため、`dp[2][2] = 0`。 

禁止セルが境界線上にある場合など$(1,k)$または$(k,1)$、パスの 1 つのクラスを早期に削除するだけです。 DP は引き続き残りの方向からの有効な代替を蓄積し、再帰によりブロックされたセルを越えて無効な寄与が漏れないことが保証されます。
