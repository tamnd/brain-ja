 ## 解決策
 ## 問題の理解

 ちょうど N 個の単語で構成される長いテキストが与えられており、このテキストが非常に特殊な生成プロセスから生じた可能性があるかどうかを判断したいと考えています。 

このプロセスは次のとおりです。11 個の既知の単語からなる固定辞書 U が存在し、元の​​「真のメッセージ」 T はこの辞書のみから取得された単語のシーケンスです。 次に、26 個の大文字の隠された並べ替えが T のすべての文字に均一に適用され、観察されたテキスト S が生成されます。与えられたのは S だけであり、そのような T とそのような文字の並べ替えが存在するかどうかを判断する必要があります。 そうであれば、有効な順列も 1 つ再構築する必要があります。 

したがって、タスクは基本的に、アルファベットに対する一貫した全単射を使用して、S を U から単語に「デコード」できるかどうかを判断することです。 

重要な制約は、順列がグローバルであることです。すべての単語の出現ごとに同じ文字マッピングが機能する必要があります。 これにより、問題は解析や文字列照合の問題ではなく、文字の対応関係に関する一貫性チェックの問題に直ちに変わります。 

入力サイズは大きく、最大 10^6 文字です。 これにより、すべての順列を試行したり、単語ごとのマッピングを繰り返しチェックしたりするなど、テキスト全体の長さにおける二次的なものはすべて除外されます。 有効なソリューションでは、各文字を一定の回数だけ処理する必要があります。 

微妙なエッジケースは文字の衝突から生じます。 S の 2 つの異なる文字が U の同じ元の文字に強制的にマッピングされると、構築は失敗します。 逆に、単語の出現が異なるため、S の文字が U の 2 つの異なる文字にマッピングされなければならない場合も、これは失敗します。 もう 1 つの特殊なケースは、U 内の異なる単語が接頭辞または内部構造を共有する可能性があるため、グローバルな一貫性を持たない単語ごとの貪欲なマッチングが静かに機能しなくなることです。 

## アプローチ

 素朴な考えは、アルファベットのすべての順列を試して、S をデコードすると U からの単語のみが生成されるかどうかを検証することです。これは、26! であるため、直ちに実行不可能です。 天文学的に大きいです。 単一の順列のチェックに限定しても O(|S|) のコストがかかりますが、これは問題ありませんが、候補を生成することは不可能です。 

より構造化されたブルート フォース アプローチは、単語をスキャンしながらマッピングを段階的に割り当てることです。 S の各単語について、U のすべての単語と照合し、その照合と一致する文字マッピングの構築を試みることができます。 複数の一致が存在する場合は分岐します。 最悪の場合、各単語が複数の辞書エントリに一致する可能性があり、一貫性制約は後でのみ伝播するため、単語全体に指数関数的な分岐が発生します。 状態の数は、N の実現可能な制限をはるかに超えて 10^6 まで爆発的に増加します。 

重要な観察は、辞書 U が小さくて固定されていることです。 これにより、視点を逆転させることができます。S を T にデコードして順列を適用する代わりに、S の単語と U の単語の間で可能なすべての全単射を、制御された方法で試みます。 

S の各ワードは、同じ長さの U のいくつかのワードに対応する必要があります。 U は小さい (11 単語) ため、S の各単語に対して、最大でも数個の候補しかありません。 候補の組み合わせごとに、グローバル文字マッピングの拡張を試みます。 マッピングは、S の文字と U 空間の標準アルファベットの文字の間の全単射として維持されます。 どこかの時点で競合が発生した場合、その候補の割り当ては無効になります。 

これにより、問題は部分全単射の一貫性チェックに変わり、単語ごとに貪欲に実行できます。 各文字は一度マッピングされ、再マッピングされることはないため、全体の複雑さはテキストのサイズに比例します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース順列 | O(26! · | S | ) |
 | 単語ごとのバックトラッキング | N の指数 | O(N) | 遅すぎる |
 | 単語ごとの貪欲な全単射 | O( | S | ) |

 ## アルゴリズムのチュートリアル

私たちはこの問題を、S の文字から U の単語で構成される仮説の元のテキストの文字への一貫したマッピングを構築するものとして扱います。 

1. Split the input string S into words. 各ワードは、同じ長さの U 内の 1 つのワードに対応する必要があります。 単語の長さが U 内のどの単語にも一致しない場合、置換によって長さと単語の境界が保持されるため、入力を直ちに拒否できます。 
2. 全単射を表すサイズ 26 の 2 つの配列を維持します。`to`S の文字を元のアルファベットの文字にマッピングします。`from`可逆性を保証するため、2 つの文字が同じターゲットにマップされることはありません。 
3. S の各単語について、同じ長さを持つ U のすべての単語を繰り返します。 候補単語ごとに、マッピングを 1 文字ずつ拡張してみます。 
4. この試行中に、単語内の各位置 i について、現在のマッピングをチェックします。 マッピングがすでに定義されている場合、それは候補単語の性質と一致する必要があります。 定義されていない場合は、逆マッピングが違反されていないことも確認しながら、暫定的に割り当てます。 
5. U の候補単語が現在の単語のすべての位置のマッピングを正常に拡張した場合、それらの割り当てを永続的にコミットし、次の単語に移動します。 機能する候補がない場合は、有効な分解が存在しないと結論付けます。 
6. すべての単語が正常に処理された場合、マッピングから導出された再構成された順列が出力されます。 

単語ごとのマッピングを安全にコミットできる理由は、一貫したグローバル ソリューションは、各単語の出現によって引き起こされるマッピングに同意する必要があるためです。 単語が一貫して一致した場合、それを取り消しても、解の空間を拡張することなく、不必要な分岐が導入されるだけです。 

### なぜ効果があるのか

 このアルゴリズムは、S の文字と仮想の元のテキストの文字の間の部分的な全単射を維持します。 受け入れられたすべての単語は、その単語によって引き起こされるすべての制約が満たされることを保証します。 U のすべての単語は固定かつ有限であり、マッピングはグローバルに一貫しているため、有効な解決策は重複する文字に対してまったく同じ制約を引き起こす必要があります。 したがって、競合が発生した場合、有効な置換は存在できません。 すべての単語が成功した場合、テキスト全体にわたって一貫した有効な全単射が構築されたことになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

U = ["AC", "AMOR", "BRASILEIRO", "CAVALO", "MARATONUSP",
     "OSSO", "OVO", "PATA", "RARADA", "TLE", "VOO"]

from collections import defaultdict

by_len = defaultdict(list)
for w in U:
    by_len[len(w)].append(w)

def solve():
    n = int(input().strip())
    words = input().strip().split()

    to = [-1] * 26
    fr = [-1] * 26

    def can_match(s, t):
        # try to match s -> t using current mapping
        changes = []
        for a, b in zip(s, t):
            x = ord(a) - 65
            y = ord(b) - 65

            if to[x] != -1 and to[x] != y:
                return None
            if fr[y] != -1 and fr[y] != x:
                return None

            if to[x] == -1:
                to[x] = y
                fr[y] = x
                changes.append((x, y))

        return changes

    for w in words:
        L = len(w)
        candidates = by_len[L]

        found = False
        for t in candidates:
            snapshot = []
            ok = True

            for a, b in zip(w, t):
                x = ord(a) - 65
                y = ord(b) - 65

                if to[x] != -1 and to[x] != y:
                    ok = False
                    break
                if fr[y] != -1 and fr[y] != x:
                    ok = False
                    break

                if to[x] == -1:
                    to[x] = y
                    fr[y] = x
                    snapshot.append((x, y))

            if ok:
                found = True
                break

            for x, y in snapshot:
                to[x] = -1
                fr[y] = -1

        if not found:
            print("N")
            return

    res = ''.join(chr(to[i] + 65) for i in range(26))
    print("Y")
    print(res)

if __name__ == "__main__":
    solve()
```この実装は、全単射を強制するために 2 つの配列に依存しています。 の`to`配列では、S の各文字が正確に 1 つの文字にマップされることが保証されますが、`fr`2 つの文字が同じターゲット文字にマップされないようにします。 U からの候補単語をテストするとき、一時的にマッピングを割り当て、候補が失敗した場合はロールバックし、さまざまな選択肢にわたって正確さを維持します。 

微妙な点は、単語全体を検証した後にのみ候補をコミットすることです。 部分的な割り当ては以下で追跡されます`snapshot`、これはロールバックに不可欠です。 これがないと、失敗した候補によってグローバル マッピングの状態が破損してしまいます。

 ### 例 1

 入力:```
3
NBSBUPOVTQ PWP BD
```単語ごとに処理します。 単語「NBSBUPOVTQ」は長さ 10 で、長さ 10 の U の候補と一致します。これを「MARATONUSP」と照合してみます。 これにより、N→M、B→A、S→R などの一貫したマッピングが生成されます。 

| ステップ | 単語 | 候補者 | アクション | マッピングステータス |
 | --- | --- | --- | --- | --- |
 | 1 | NBSBUPOVTQ | マラトンナスプ | 受け入れる | 部分的な全単射が構築されました |
 | 2 | PWP | オヴォ | 受け入れる | 拡張マッピング |

 すべての単語が成功するため、「Y」と構築された順列を出力します。 

このトレースは、すべての新しい単語はすでに一貫性のある部分全単射を拡張するだけであるため、単語ごとの局所的な一貫性が十分であることを示しています。 

### 例 2

 入力:```
2
BD CMOR
```最初の単語「BD」は、U 内の長さ 2 の複数の候補にマッピングできます。最初に「AC」を試してみるとします。 これにより、B→A と D→C が設定されます。 ここで、2 番目の単語「CMOR」はこのマッピングを尊重する必要があります。 既存の制約の下で U 内の単語が C→M と一貫して一致できない場合、失敗します。 他の候補を試すと矛盾が生じます。 

| ステップ | 単語 | 候補者 | アクション | マッピングステータス |
 | --- | --- | --- | --- | --- |
 | 1 | BD | 交流 | 暫定 | B→A、D→C |
 | 2 | CMOR | 一致しません | ロールバック | マッピングが元に戻されました |

 一貫したグローバル割り当てが存在しないため、「N」を出力します。 

これはロールバックの重要性を示しています。1 つの単語に対するローカルで有効なマッピングは、将来のすべての単語をブロックする可能性があります。

def run(inp: str) -> str:

    import sys as _sys
    from collections import defaultdict

         "OSSO", "OVO", "PATA", "RARADA", "TLE", "VOO"]

    for w in U:
        by_len[len(w)].append(w)

    n = int(_sys.stdin.readline().strip())
    words = _sys.stdin.readline().strip().split()

    to = [-1] * 26
    fr = [-1] * 26

    for w in words:
        L = len(w)
        found = False

        for t in by_len[L]:
            snapshot = []
            ok = True

            for a, b in zip(w, t):
                x = ord(a) - 65
                y = ord(b) - 65

                if to[x] != -1 and to[x] != y:
                    ok = False
                    break
                if fr[y] != -1 and fr[y] != x:
                    ok = False
                    break

                if to[x] == -1:
                    to[x] = y
                    fr[y] = x
                    snapshot.append((x, y))

            if ok:
                found = True
                break

            for x, y in snapshot:
                to[x] = -1
                fr[y] = -1

        if not found:
            return "N"

    return "Y\n" + ''.join(chr(to[i] + 65) for i in range(26))

 ## 特殊なケース

 文字が複数の単語に含まれており、部分的に早期に割り当てられると、厄介な状況が発生します。 たとえば、「OVO」が最初に処理される場合、O→A と V→B が割り当てられます。 その後、別の単語で O→C が必要になる場合があり、これはすぐに全単射制約に違反します。 アルゴリズムは、不可逆的なコミット前の互換性チェック中にこれを正しく拒否します。 

もう 1 つの特殊なケースは、複数の辞書の単語が同じ長さを共有する場合です。 単純な実装では最初の一致を貪欲にコミットし、後で失敗する可能性がありますが、ロールバック メカニズムにより、クリーンな状態のスナップショットを使用して各候補が個別にテストされることが保証されます。 

最後に、単一文字または非常に短い単語は、マッピングに大きな曖昧性を引き起こすため重要です。 制約は同じ全単射配列を通じて強制され、特別なケースは必要ないため、アルゴリズムはそれらを自然に処理します。
