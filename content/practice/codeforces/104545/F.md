 ## 解決策
 ## 問題の理解

 複数の神との競争が与えられ、各神は最初に既知の投票数を持っています。 リストの最初の神はゼオスで、残りは競合者です。 ゼオスとは別の神を選び、その神から一票を奪い、ゼオスに与えるという操作を何度でも行うことができます。 したがって、操作ごとにゼオスの票が 1 つ増加し、他の神の票が 1 つ減少します。 

目標は、ゼオスが他のすべての神よりも厳密に先に進むために必要なそのような操作の最小数を決定することです。 

状況を再構成する有効な方法は、再分配の観点から考えることです。 各操作は投票の合計を変更せず、競合他社からの投票塊の 1 単位を Zeos に移動するだけです。 t 回の操作の後、ゼオスは t 増加し、他の神は集合的に t 減少し、選ばれた神に分配されました。 

制約 m は 200000 まで大きくすることができ、個々の投票数は最大 10^9 になります。 これにより、操作を 1 つずつシミュレートしようとするアプローチは即座に排除されます。 t 自体が非常に大きくなる可能性があり、投票の総和程度になる可能性があるため、操作ごとの線形シミュレーションでさえ遅すぎます。 

重要な微妙な点は、唯一の要件は厳密な優位性であるということです。ゼオスは他のすべての神よりも厳密に多くの票を獲得して終了する必要があります。 そのしきい値を超えて Zeos を最大化する必要はありません。 

いくつかの特殊なケースについては、知っておく価値があります。 

ゼオスがすでに他のどの神よりも多くの票を持っている場合、答えはゼロになります。 たとえば、入力が 10 1 2 3 の場合、操作は必要ありません。 

1 1000000000 1 1 など、非常に大きな競合他社が 1 つある場合、戦略はその最大値を減らすと同時に Zeos を増やすことに完全に焦点を当てる必要があります。 

現在の最大の競合他社から常に乗り換えるといった素朴な貪欲な考えは「正しいように感じます」が、論理を組み立てないと、どれだけの操作が必要か、いつ停止するかが不明確になります。 最適解はまさにそれを明らかにします。 

## アプローチ

 最も直接的なアプローチは、プロセスをシミュレートすることです。 各ステップで最大の競合他社を特定し、そこから 1 票を差し引いて Zeos に転送します。 これは、最大の脅威をできるだけ早く軽減するため、直感的に最適です。 

これは最大ヒープで実装できます。 各操作は O(log m) で、Zeo が他のすべての操作より厳密に大きくなるまで繰り返します。 ただし、操作数 t は膨大になる可能性があります。 最悪の場合、大きな値をゼロ近くまで下げると同時に Zeos を増やす必要があり、t は 10^9 以上になります。 そのため、段階的なシミュレーションが不可能になります。 

重要な点は、プロセスを段階的にシミュレートする必要がないということです。 代わりに、指定された操作数 t が十分であるかどうかのみを考慮します。 固定 t の実現可能性を確認できたら、答えを二分探索できます。 

したがって、問題は決定の問題に帰着します。つまり、t 個の操作が与えられた場合、ゼオスが厳密に全員より先に終わるように他の神々にそれらを分配できるでしょうか?

 固定 t の場合、Zeos は a1 + t で終了します。 残りの神々はそれぞれ ai から負でない量を引いた値を持ち、それらすべてから減算された合計量は正確に t になります。 最終的な最大の競合他社を最小化するには、常に現在の最大値から最初に減算します。 これからの逸脱は、より大きな最大値を残すだけです。 

したがって、実現可能性は貪欲にチェックできます。他の神を降順に並べ替え、t 操作を費やしてその順序でそれらをできるだけ減らすことができます。 

このチェックが線形時間で可能になると、t にわたる二分探索により最終的な答えが得られます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 段階的なヒープ シミュレーション | O(t log m) | O(m) | 遅すぎる |
 | 二分探索 + 貪欲な実現可能性チェック | O(m log m log S) | O(m) | 承認済み |

 ここで、S は投票の総数、または回答の上限です。 

## アルゴリズムのチュートリアル

 ### 最適な戦略

 ゼオスを個別に扱い、残りの神に焦点を当てます。 

## アルゴリズムのチュートリアル

 1. Zeos の投票 a1 を配列の残りの部分から分離します。 
2. 残りの値を降順に並べ替えます。 これにより、削減を配布する際に常に最も危険な競合他社に最初に対処することが保証されます。 
3. t 回の操作が十分かどうかを判断する関数 check(t) を定義します。 
4. check(t) 内で、ソートされた配列全体に t のリダクションをどのように分配するかをシミュレートします。 各競合他社について、降順で、現在の値と残りの予算 t まで、可能な限り多くを差し引きます。 
5. すべての競合他社を処理した後、それらの競合他社の最大の残りの値を計算します。 Zeos の最終的な値は a1 + t です。 
6. Zeos の最終値が残りのすべての競合他社よりも厳密に大きい場合は true を返します。 
7. check(t) が true となる最小の t を二分探索します。 

check(t) 内のこの貪欲な分布が有効である理由は、最適な戦略では、最初に大きな値を減らすことを優先する必要があるためです。 大きい値をそのまま残して小さい値を減らすと、最大競合相手が不必要に大きくなり、満たそうとしている条件が悪化するだけです。 

### なぜ効果があるのか

 いかなる瞬間においても、競争相手の複数の価値観のみが重要であり、それらがどの特定の神に属しているかは問題ではありません。 演算ごとに 1 つの要素が 1 つずつ減ります。 t 回の操作後の最終最大値を最小限に抑えるには、常に現在利用可能な最大値を減らす必要があります。 これにより、大きな要素での「見逃した」縮小は、中間の最大値を改善せずに追加コストをかけて後でのみ補償できるため、他の一連の縮小はより小さい最大値を生成できないという不変条件が維持されます。 

この単調な構造が確立されると、問題は t にわたる単調な実現可能条件となり、二分探索の正確さが保証されます。

もう 1 つの微妙な点は、すべての操作で 1 票を Zeos に転送する必要があるため、リダクションをどのように配分するかに関係なく、Zeos の最終値は常に正確に a1 + t になることです。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    a1 = a[0]
    arr = sorted(a[1:], reverse=True)

    def check(t):
        rem = t
        mx = 0
        for v in arr:
            use = min(v, rem)
            rem -= use
            mx = max(mx, v - use)
        return a1 + t > mx

    lo, hi = 0, sum(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if check(mid):
            hi = mid
        else:
            lo = mid + 1
    return str(lo)

# minimum case
assert solve("3\n1 1 1\n") == "1"

# already winning
assert solve("3\n10 1 2\n") == "0"

# single big opponent
assert solve("2\n1 1000000000\n") == "1000000000"

# balanced case
assert solve("4\n2 4 2 5\n") == "4"

# all equal
assert solve("5\n5 5 5 5 5\n") == "4"

 ## 特殊なケース

 Zeos がすでに最大である場合、実現可能性チェックは t = 0 ですぐに合格するため、アルゴリズムは正しく 0 を返します。 

[1, 100] のような場合、貪欲な分布により、すべての操作が最初に 100 に行き、Zeo を増加させながら着実に縮小します。 チェック関数は、小さい要素に触れる前に最大の要素のバジェットをすべて消費することで、これを正確にモデル化します。 

[5, 5, 5, 5] のように、すべての値が等しい場合、アルゴリズムは、Zeo が他の値と一致するだけでなく、厳密に超えなければならないことを正確に捕捉します。 これにより、縮小後に Zeos が一定の最大値を超えるのに十分な転送が強制されます。そのため、答えは合計の半分ではなく、対称性を破るために必要な正確な値になります。
