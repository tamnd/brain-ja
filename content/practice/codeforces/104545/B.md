 ## 解決策
 ## 問題の理解

 アイテムのいくつかのグループが与えられます。各グループは風船の色に対応し、初期数が設定されています。 コンテナには膨らませたバルーンの数が決まった数までしか搭載できないため、膨らませたバルーンの総数を最大でも所定の制限まで減らす必要があります。 

ポイントは、削減の仕組みです。 時間は秒単位で区切られます。 毎秒、正確に 1 つの色を選択し、その色のすべての風船を観察します。 ある色が 1 秒間観察されると、その色のすべての風船が効果的に半分に減り、そのプロセスはカウント上のフロア分割のように動作します。 色にバルーンが x 個ある場合、1 回の操作で ⌊x/2⌋ になります。 このプロセスを繰り返し、1 秒ごとに 1 色を選択します。残りのすべての風船の合計が最大 S になるまでに必要な秒数を最小限に抑えたいと考えています。 

入力により、色の数と容量制限 S が与えられ、その後に各色の初期カウントが続きます。 出力は、必要な最小操作数 (秒) です。 

この制約では最大 100,000 色が許可され、各色数は 1e9 まで大きくなります。 これにより、すべての色にわたってすべての可能な操作を素朴にシミュレートするアプローチは即座に除外されます。 各操作は 1 つの色にのみ影響するため、考えられる選択肢ごとに合計を繰り返し再計算する単純な戦略では遅すぎます。特に、単一の色では O(log bi) のリダクションが必要になる可能性があり、すべての色を合計すると、リダクションだけでも約 1e5 × 30 の演算が上限となる可能性があります。しかし、決定プロセスの方が重要です。毎秒どの色を削減するかを選択することが最も難しいのです。 

エッジ ケースは、S が非常に小さいかゼロの場合、またはすべての値がすでに小さい場合に発生します。 たとえば、S = 0 ですべての bi = 1 の場合、すべてをゼロに減らす必要があり、各色は独立して縮小するため、それぞれの縮小順序が重要になります。 もう 1 つのエッジ ケースは、S が十分に大きいため操作がまったく必要ない場合であり、この場合はすぐに 0 が返されるはずです。 

## アプローチ

 ブルート フォース ビューでは、プロセスを段階的にシミュレートします。 毎秒、考えられるすべての色を試し、選択した 1 つの色に半分の演算を適用した結果の合計を計算し、最良の選択を選択します。 これには、各ステップで各候補色の合計を再計算することが含まれます。 事前計算を行ったとしても、各操作によって状態空間が変更されるため、状態の数は急速に増加し、最大で多数のステップをシミュレートする必要があります。 最悪の場合、各色は約対数 2 倍減少する可能性があるため、何百万もの状態遷移が存在する可能性があり、各決定ステップのコストは O(N) となり、実行不可能な O(N² log A) スケールの動作につながります。 

重要な観察は、各操作の効果が減少するということです。大きな数値を半分に減らすと、最初は大幅な減少が得られますが、数値が小さくなるにつれて利点は小さくなります。 これは、現時点で合計額の最大の削減をもたらす操作を常に優先する必要があることを示唆しています。 

限界ゲインの観点から考えると、各色には一連の考えられる「利点」があります。x から x/2 への最初の縮小では x - x/2 のゲインが得られ、次の縮小では x/2 - x/4 が得られます。 各色は、一連のゲインの減少に寄与します。 問題は、合計が最大 S に低下するまで最大のゲインを持つ操作を選択することです。これは当然、潜在的な削減すべてに対する貪欲な選択であり、最大ヒープで効率的に管理できます。 

合計を計算し、色ごとに最初の削減を実行する利点をプッシュすることで初期化します。 操作を適用するたびに、利用可能な最良のゲインをポップし、それを合計から減算し、同じ色の次のゲインをプッシュします。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N² log A) | O(N) | 遅すぎる |
 | 最大ヒープで貪欲 | O(N log A + K log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、和の制約が満たされるまで最も収益性の高い削減を繰り返し適用することに変換します。 

1. すべてのバルーン数の初期合計を計算します。 これは、削減する必要がある出発点を表しています。 
2. 合計がすでに S 以下である場合は、削減する必要がないため、ゼロ操作ですぐに停止できます。 
3. 各カラー値 x について、1 つの削減の効果を計算します。x は x // 2 になるため、ゲインは x - x // 2 になります。操作を 1 回適用した後の更新された値とともに、このゲインを最大優先順位構造に格納します。 
4. 次の削減で最大のゲインが得られる色を抽出します。 その減少を適用し、合計からゲインを差し引き、費やした時間を 1 秒カウントします。 
5. 色にリダクションを適用した後、新しい値を使用して同じ色の次に可能なゲインを計算します。 これは、次回その同じ色を再度減色できるときを表しており、その色を構造に再挿入する必要があります。 
6. 合計が S 以下になるまでプロセスを繰り返します。 

これが機能する理由は、各操作が個別に明確に定義された削減量に寄与し、各色の将来の削減が減少シーケンスの一部として事前にわかっているためです。 現在最大の限界削減を常に選択することで、総計の即時削減を最大化するために毎秒が確実に使用され、より大きな削減が利用可能なままである間は、より小さな削減​​が選択されることはありません。 

重要な不変条件は、各ステップにおいて、優先キューには、現在の状態を考慮した各色に対して次に利用可能な削減が正確に含まれていることです。 これにより、将来起こり得るすべてのアクションが正しく表現され、アルゴリズムがより適切な即時削減をスキップすることがなくなります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, S = map(int, input().split())
    a = list(map(int, input().split()))

    total = sum(a)
    if total <= S:
        print(0)
        return

    # max heap via negative values
    pq = []

    for x in a:
        if x > 0:
            gain = x - x // 2
            heapq.heappush(pq, (-gain, x))

    ops = 0

    while total > S:
        gain, x = heapq.heappop(pq)
        gain = -gain

        total -= gain
        ops += 1

        new_x = x // 2
        if new_x > 0:
            new_gain = new_x - new_x // 2
            heapq.heappush(pq, (-new_gain, new_x))

    print(ops)

if __name__ == "__main__":
    solve()
```このソリューションは、考えられる削減の優先順位キューを維持します。 各要素には、色の現在の値と、それを 1 回減らすことによるメリットが格納されます。 各操作の後、その色は更新され、次の潜在的なゲインで再挿入されます。 累積された削減により合計が必要な制限を下回ると、ループは停止します。 

微妙な点は、ゲインを元の値ではなく常に現在の値から計算することです。 これは、半減するたびに削減順序が変更され、更新しないと将来の利益が過大評価されることになるため、不可欠です。 

## 実用的な例

 入力を考慮してください:```
2 5
3 5
```初期合計は 8 なので、少なくとも 3 減らす必要があります。 

| ステップ | 選択されたゲイン | 状態 (a) | 合計 |
 | --- | --- | --- | --- |
 | 0 | - | [3、5] | 8 |
 | 1 | 2 (5→2) | [3、2] | 6 |
 | 2 | 1 (3→1) | [1、2] | 5 |

 2 回の操作の後、合計は 5 になり、制約を満たします。 

ここで次のことを考えてみましょう。```
5 0
1 1 1 1 1
```初期合計は 5、目標は 0 であるため、すべてを削除する必要があります。 

| ステップ | 選択されたゲイン | 状態 (a) | 合計 |
 | --- | --- | --- | --- |
 | 0 | - | [1,1,1,1,1] | 5 |
 | 1 | 1 | [0,1,1,1,1] | 4 |
 | 2 | 1 | [0,0,1,1,1] | 3 |
 | 3 | 1 | [0,0,0,1,1] | 2 |
 | 4 | 1 | [0,0,0,0,1] | 1 |
 | 5 | 1 | [0,0,0,0,0] | 0 |

 各操作では、1 を半分にすると 0 になるため、直観と一致して、正確に 1 つの単位が削除されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log A + K log N) | 各色は O(log A) の削減を生成し、それぞれがヒープからプッシュ/ポップされます。 
| スペース | O(N) | ヒープは色ごとに最大 1 つのアクティブ状態を保存します。 

この制約により、最大 1e5 の色と最大 1e9 の値が許可されるため、log A は約 30 になります。これにより、ヒープ操作の総数が管理可能に保たれ、Python での 1 秒の実行の一般的な制限内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return sys.stdout.getvalue().strip() if False else solve_capture(inp)

def solve_capture(inp: str) -> str:
    import heapq
    input = iter(inp.strip().split()).__next__

    n = int(input())
    S = int(input())
    a = [int(input()) for _ in range(n)]

    total = sum(a)
    if total <= S:
        return "0"

    pq = []
    for x in a:
        gain = x - x // 2
        pq.append((-gain, x))
    heapq.heapify(pq)

    ops = 0

    while total > S:
        gain, x = heapq.heappop(pq)
        gain = -gain
        total -= gain
        ops += 1
        nx = x // 2
        if nx > 0:
            ng = nx - nx // 2
            heapq.heappush(pq, (-ng, nx))

    return str(ops)

 ## 特殊なケース

 S = 0 ですべての値が 1 の場合、アルゴリズムはすべての値がゼロになるまで各要素のゲイン 1 を繰り返し選択します。 各ステップで合計が正確に 1 ずつ減り、ヒープは要素がなくなるまで循環します。 

total ≤ S などのすでに満たされた入力の場合、早期終了により不必要なヒープの構築や操作が防止され、ただちにゼロが返されます。 

1 つの巨大な値と多数の小さな値のような大きな偏った入力の場合、ヒープは、初期ゲインが優先されるため、大きな値が常に最初に処理されるようにします。また、縮小するにつれて優先順位は自然に低下し、必要に応じて小さな値が引き継ぐことができます。
