 ## 問題の理解

 我が家には水を入れたタンクがいくつかあります。 単一の操作は異例です。水源タンクを選択するときに、取水量を決定しません。 スコップは自動的に取られます`min(current_amount, K)`そのタンクからすべてをすぐに別のタンクに注ぎます。 

目標は、水の総量を等しくすることではありません。`V`。 合計金額は変わりません。 代わりに、少なくとも 1 つのタンクに正確な内容を含める必要があります。`V`一連の操作後のミリリットル。 

出力形式は圧縮されています。 同じタンクからの移送の場合`x`タンクへ`y`連続して何度も繰り返される場合は、1 行として出力することもできます`cnt x y`。 

制約が主な手がかりです。 タンクは最大 5000 個あり、各初期量は最大で`10^5`、しかしターゲットは`V`と同じ大きさにすることができます`10^9`。 ソリューションには数十億回の転送が必要になる可能性があるため、個々のスクープ操作を総当りでシミュレーションすることは不可能です。 出力制限は最大でも`N + 5`圧縮された操作は、建設的な数学的解決策が存在することを強く示唆しています。 

最も重要な観察は、操作によってタンクが次のいずれかによって変更されるということです。`K`または、現在保有している残高が以下の場合は残高によって決まります。`K`。 これは剰余を意味します`K`中心的な役割を果たします。 

いくつかの特殊なケースは見落とされがちです。 

考慮する：```
2 3 0
5 7
```正解は「はい」です。 1 つのタンクから水を空になるまで繰り返し取り出すことができます。 正の目標金額のみを検索するソリューションでは、このケースは誤って拒否されます。 

考慮する：```
2 5 8
3 5
```水の合計は 8 なので、答えは明らかです。「YES」です。 すべての水を 1 つのタンクに移すだけです。 モジュロのみを推論するアプローチ`K`合計額を考慮しないと、この些細な可能性を見逃してしまいます。 

考慮する：```
3 4 7
4 8 12
```すべてのタンクの量は 4 の倍数です。出現するすべての量は 4 の倍数のままです。7 は 4 の倍数ではないため、答えは NO です。 不用意に構築すると、たとえモジュロ不変式が禁止しているにもかかわらず、任意の値を構築しようとする可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、操作を適用することで到達可能な状態を探索します。 すべての有効なシーケンスが状態グラフ内のパスに対応するため、このような検索は正しいです。 

残念ながら、国家空間は膨大です。 タンクは任意に大量の量を保持でき、たとえ少量の投入でも、到達可能な構成の数は爆発的に増加します。 状態空間検索はまったく実行不可能です。 

重要な観察は、モジュロで何が起こるかを調べることから得られます。`K`。 

タンクに少なくとも次のものがあると仮定します。`K`単位。 1 回の転送で正確に削除`K`、したがってその剰余モジュロ`K`変わりません。 

タンクに以下のものが入っていると仮定します。`K`。 1 回の転送で完全に空になり、残りは 0 になります。 

したがって、すべてのタンクは元の剰余モジュロのみを提供できます。`K`。 繰り返し減算することができます`K`タンクから取り出した後、オプションで最後の操作を 1 つ実行してゼロにします。 

これは、各タンクをコインとして扱うことを示唆しています。```
ri = ai mod K
```ただし、残りの 0 は何も寄与しません。 

タンクを特別なコレクタータンクに排出することで、どれが生き残り、どれがゼロになるかを自由に決定できます。 達成可能なタンク量は、これらの剰余の部分集合の和に等しい剰余をモジュロで持ちます。`K`。 すべての剰余は厳密に以下より小さいため、`K`、サブセットから取得できる実際の値は、単に剰余の通常のサブセットの合計です。 

問題は次のようになります。 

合計が以下に等しい余りをいくつか選択できますか?`V mod K`、コレクターに蓄積された合計金額が少なくとも`V`?

 これにより、モジュロ値に関する部分集合和動的計画法の問題が発生します。`K`。 以来`K ≤ 5000`、`O(NK)`DP は完全に実用的です。

 ## アルゴリズムのチュートリアル

 ### 1. 簡単なケースに対処する

 しましょう`S`総水量となります。 

もし`V > S`、水は節約されるので、答えはすぐには不可能です。 

もし`V == S`、すべての水を1つのタンクに移して完了できます。 

### 2. 有用な剰余を計算する

 すべての戦車について次を計算します。```
ri = ai mod K
```これらの残基のみが、ターゲットの残基を構築するために重要です。 

### 3. K を法とする部分集合和 DP を実行します。 

しましょう:```
target = V mod K
```残りに対してナップサックスタイルの DP を実行します。`dp[x]`残差合計かどうかを記録します`x`再構築を可能にする親情報とともに形成することができます。 

すべての余りは以下であるため、`K`、達成可能なすべての金額は次のとおりです。`[0, K-1]`。 

### 4. Reconstruct a subset

 もし`target`到達できない場合は、「いいえ」と答えてください。 

それ以外の場合は、タンクの 1 つのサブセットを再構築し、その剰余の合計は次のようになります。`target`。 

これらの戦車は残りの貢献を維持します。 他のすべてのタンクは最終的に完全に空になります。 

### 5. コレクタータンクの選択

 選択したサブセットの中から、最終ターゲットとなる戦車を 1 台選択します。 

選択されていないすべてのタンクは完全にその中に排出されます。 

コレクター以外の選択されたタンクは、残りの部分まで正確に減らされます。 

コレクターは移送された水をすべて受け取ります。 

### 6. コレクターの金額を計算する

 すべての削減の後、コレクターには以下が含まれます```
collector_value = S - sum(other_selected_remainders)
```選択されたサブセットの保証```
collector_value ≡ V (mod K)
```そして```
collector_value ≥ V
```### 7. コレクタを V に削減します。 

違いがあるので、```
collector_value - V
```は負でない倍数です`K`、コレクターから任意の補助タンクに繰り返し移送します。 

各転送は正確に削除します`K`。 

コレクターは最終的には正確になります`V`。 

### なぜ効果があるのか

 不変条件は、タンクの剰余モジュロです。`K`ゼロ以外の別の剰余に変更することはできません。 タンクは元の残量を保持するか、ゼロに減らすことしかできません。 

したがって、達成可能なすべての構成は、どの元の残りが生き残るかを選択することによって決定されます。 サブセット合計 DP は、考えられるすべての生存者残余合計を正確に列挙します。 

このようなサブセットを修正した後は、残りのすべての操作が有益になります。 選択されなかったタンクはゼロになり、選択されたタンクは残りが減り、除去された水はすべて 1 つのコレクターに蓄積されます。 コレクターの金額が希望の値と何倍も異なります。`K`、そのため、フルスクープ転送を繰り返すと、正確に減少します。`V`。 

達成可能なすべての残留パターンが DP で表現され、すべての DP ソリューションが実際のタンク操作によって実現できるため、アルゴリズムは完全かつ正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, v = map(int, input().split())
    a = list(map(int, input().split()))

    total = sum(a)

    if v > total:
        print("NO")
        return

    target = v % k

    dp = [-1] * k
    parent = [(-1, -1)] * k
    dp[0] = -2

    rem = [x % k for x in a]

    for i in range(n):
        r = rem[i]
        if r == 0:
            continue

        ndp = dp[:]

        for s in range(k):
            if dp[s] == -1:
                continue

            ns = (s + r) % k

            if ndp[ns] == -1:
                ndp[ns] = i
                parent[ns] = (s, i)

        dp = ndp

    if dp[target] == -1:
        print("NO")
        return

    chosen = [False] * n

    cur = target
    while cur != 0:
        prev, idx = parent[cur]
        chosen[idx] = True
        cur = prev

    chosen_indices = [i for i in range(n) if chosen[i]]

    if not chosen_indices:
        chosen_indices = [0]
        chosen[0] = True

    collector = chosen_indices[0]

    ops = []

    def add_op(cnt, x, y):
        if cnt > 0 and x != y:
            ops.append((cnt, x + 1, y + 1))

    for i in range(n):
        if i == collector:
            continue

        if chosen[i]:
            need = rem[i]
            cnt = (a[i] - need) // k
            add_op(cnt, i, collector)

            a[collector] += cnt * k
            a[i] -= cnt * k
        else:
            cnt = a[i] // k
            add_op(cnt, i, collector)

            a[collector] += cnt * k
            a[i] -= cnt * k

            if a[i] > 0:
                add_op(1, i, collector)
                a[collector] += a[i]
                a[i] = 0

    diff = a[collector] - v

    aux = 0 if collector != 0 else 1

    add_op(diff // k, collector, aux)

    print("YES")
    for cnt, x, y in ops:
        print(cnt, x, y)

if __name__ == "__main__":
    solve()
```DPストアのみ`K`状態、これが重要な最適化です。 親ポインターを使用すると、完全な DP テーブルを保存せずに、選択したサブセットを再構築できます。 

建設段階はその証拠を反映しています。 選択したサブセットの外側のタンクは完全に空になります。 サブセット内のタンクは残りを正確に保持します。 取り外されたすべてのユニットはコレクターに送られます。 

微妙な点の 1 つは、コレクターの最終的な縮小です。 現在の値との差`V`で割り切れることが保証されています`K`。 まさにこれが、フルスクープ転送を繰り返すことでモジュロ クラスを乱すことなく過剰量を除去できる理由です。 

もう 1 つの微妙な詳細は、剰余ゼロ戦車の処理です。 これらは DP 内で新しい残基を達成するのに決して役立つものではないため、スキップできます。 建設中に、それらはコレクターに完全に排出されるだけです。

 ## 特殊なケース

 ### 総水量よりも大きな目標

 入力:```
2 5 20
3 4
```水の総量はわずか 7 です。操作で水が生成されることはないため、20 に達することは不可能です。 アルゴリズムは DP を実行する前にこれを検出し、NO を出力します。 

### すべての剰余はゼロに等しい

 入力:```
3 4 7
4 8 12
```すべてのタンクは 4 の倍数です。どの操作でも 4 の倍数を削除または追加するため、すべてのタンク量は常に 4 の倍数のままです。7 は 4 の倍数ではないため、解は存在しません。 DP は残基 0 にのみ到達し、ターゲットの残基 3 を正しく拒否します。 

### ターゲットはゼロに等しい

 入力:```
2 3 0
5 7
```目標残余もゼロです。 DP は空のサブセットを使用して直ちに成功します。 この構造では、任意のコレクターを選択し、すべての水をそこに集め、コレクターがちょうど 0 になるまで 3 の倍数を除去します。 

### 既存のタンクにはすでに V が含まれています

 入力:```
3 5 10
10 7 8
```アルゴリズムはまだ機能します。 DP は有効な剰余パターンを見つけ、その構築により演算がゼロになるか、短い等価シーケンスが生成される可能性があります。 アルゴリズムは変更を必要とするのではなく、到達可能性を考慮するため、すでに正しいタンクが存在しても障害が発生することはありません。
