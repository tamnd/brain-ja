 **タグ:** dfs および同様の、貪欲、数学、ソート、2 つのポインタ

 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 サイズ n の順列が与えられています。これは、1 から n までのすべての整数が 1 回だけ現れることを意味します。 この配列の横には、許可されたスワップによってどの隣接する位置が「接続」されているかを説明する文字列が含まれます。 i 番目の文字が 1 の場合、位置 i と i+1 の要素を何度でも交換できます。 0 の場合、その境界は永久にブロックされます。 

スワップは許可されたエッジ上で任意に繰り返すことができるため、実際の自由は個々のスワップに関するものではなく、許可された隣接するスワップのチェーンを通じて相互にどのインデックスに到達できるかによって決まります。 このような到達可能な領域内では、要素を任意に並べ替えることができます。 異なる領域間では、要素が交差することはできません。 

タスクは、これらの制約付きスワップ操作を使用して、配列をソートされた順列 1、2、3、...、n に変換できるかどうかを判断することです。 

n が 200000 までの制約により、スワップのシミュレーションは直ちに除外されます。 単一の要素が O(n) 回移動する可能性があるため、線形時間でスワッピングを繰り返す場合でも遅すぎます。 どのようなアプローチでも、問題をシングルパスまたはソートを伴うほぼ線形の処理に減らす必要があります。 

接続が間接的である場合、微妙な障害が発生することがあります。 たとえば、(1,2) と (2,3) の間のスワップが許可され、(3,4) は許可されない場合、位置 1 から 3 が 1 つのグループを形成します。 隣接する正しい配置をチェックするか、ローカルな修正を試みるだけの単純なアプローチでは、セグメント全体がグローバルに拘束されていることを見落としてしまいます。 

もう 1 つの注意が必要なケースは、コンポーネントが長いが内部的に乱れている場合です。 

入力:

 n = 5

 a = [5、4、3、2、1]

 s = 1111

 完全な自由により完全に並べ替えが可能になるため、出力は YES である必要があります。 貪欲な隣接チェックでは、たとえグローバルな並べ替えが可能であっても、中間の不規則性が誤って拒否される可能性があります。 

最後に、切断されたスワップについて考えてみましょう。 

入力:

 n = 4

 a = [2, 1, 4, 3]

 s = 00 0

 他の問題では各ペアを個別にローカルに修正できる場合でも、スワップは許可されないため、出力は NO になります。 

## アプローチ

 プロセスを直接シミュレートしようとすると、配列を繰り返しスキャンし、可能な限りスワップを適用することになります。 最良の実装であっても、単一の要素を正しい位置に移動するには O(n) 回のスワップが必要になる可能性があり、これをすべての要素に対して行うと O(n²) 回の動作が発生します。 n が 200000 までの場合、これは完全に不可能です。 

重要な観察は、スワップがインデックスに対する等価関係を定義するということです。 許可された隣接スワップのチェーンを通じて位置 i が位置 j に到達できる場合、この連結コンポーネント全体の要素を任意に並べ替えることができます。 これにより、問題は「操作のシーケンス」から「グループ化の制約」に変わります。 

インデックスの接続された各セグメントが独立していることを受け入れると、問題は、各セグメントに、ソートされた配列に最終的に配置される必要がある値のセットが正確に既に含まれているかどうかを確認することになります。 最終的なターゲットは恒等順列であるため、位置 i には値 i が含まれている必要があります。 したがって、セグメント [l, r] の場合、現在の内部の値は、ある順序で l から r までの正確な整数でなければなりません。 

これにより、隣接する許可されたスワップによって形成されるグラフの接続コンポーネントをスキャンし、各コンポーネントの値を収集し、それらが予想される間隔と一致することを確認するタスクが軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース スワッピング シミュレーション | O(n²) | お(1) | 遅すぎる |
 | コンポーネントのグループ化 + 検証 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 スワップが完全に接続されている最大のセグメントに配列を分割することで、配列を処理します。

1. スワップ文字列を反復処理し、連続するエッジがすべて 1 であるインデックスのセグメントを特定します。そのような各セグメントは、任意の置換が可能なコンポーネントを表します。 これは重要な構造の簡素化です。 
2. 各セグメント [l, r] について、すべての値 a[l]、a[l+1]、...、a[r] を収集します。 どの要素も 0 境界を越えることができないため、このセグメントに出現できる値はこれらのみです。 
3. 収集した値を並べ替えて、予想されるシーケンス l、l+1、...、r と比較します。 それらが正確に一致する場合、セグメントは有効です。 
4. いずれかのセグメントがこの条件を満たさない場合、すぐに並べ替えは不可能であると判断します。 
5. すべてのセグメントが条件を満たしている場合、配列全体をソートできると結論付けられます。 

並べ替えがチェックとして機能する理由は、期待されるセットと現在の値の両方が、同じサイズの整数の連続した間隔を形成する必要があるためです。 ソート後の等価性は、同一のマルチセットを検証する直接的な方法です。 

### なぜ効果があるのか

 スワップ グラフは配列を連結コンポーネントに分解し、スワップによってコンポーネント間で要素が移動されることはありません。 これにより、不変条件が作成されます。つまり、コンポーネント内の値の複数セットは永久に固定されます。 ソートされたターゲットでは、各位置 i に値 i が含まれる必要があるため、各コンポーネントにはインデックス範囲に対応する整数が正確に含まれている必要があります。 この条件が当てはまる場合、各コンポーネント内の内部再配置によりソートされた配列を構築できます。 失敗した場合、許可された一連のスワップでは欠落値または余分な値を修復できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    s = input().strip()
    
    i = 0
    while i < n:
        j = i
        while j < n - 1 and s[j] == '1':
            j += 1
        
        segment = a[i:j+1]
        segment.sort()
        
        expected = list(range(i + 1, j + 2))
        if segment != expected:
            print("NO")
            return
        
        i = j + 1
    
    print("YES")

if __name__ == "__main__":
    solve()
```この実装では、配列を 1 回スキャンして、スワップが許可される各最大領域を拡張します。 領域ごとに値を抽出し、並べ替えて、必要な ID 間隔と一致するかどうかを確認します。 インデックス付けは慎重に調整されます。0 ベースのインデックス付けのセグメント [i, j] は、正確に [i+1, j+1] でなければならない値に対応します。 

よくある間違いは、予想される範囲を構築するときにインデックスがずれていることです。 もう 1 つの微妙な問題は、スワップ文字列の長さが n-1 で要素間の境界を定義するため、j が n-1 で停止することを忘れていることです。

 ## 特殊なケース

 境界ケースは、許可されたスワップがまったくない場合に発生します。 この状況では、すべてのインデックスがサイズ 1 のコンポーネントを形成するため、配列がすでにソートされている場合にのみ、各セグメントが期待値と自明に一致します。 各セグメント [i, i] が単一要素の予想範囲に対してチェックされるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、完全に接続されたスワップ文字列です。 ここでは、配列全体が 1 つのコンポーネントになるため、チェックは値の複数セットが正確に 1 から n であるかどうかを検証することになります。 入力は順列であることが保証されているため、そのセグメントを並べ替えると常に予想される範囲と一致し、結果は YES になります。 

より微妙なケースは、コンポーネントが非常に小さい 101010... のような交互制約です。 最大の連続ブロックがそれぞれ独立して処理され、グローバル接続についての仮定が行われないため、アルゴリズムは引き続き正しく動作します。
