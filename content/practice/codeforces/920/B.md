 ## 解決策
 ## 問題の理解

 時間の経過とともに進化する単一サーバーのキューをシミュレートしています。 各生徒は既知の時刻に現れ、列の最後に加わります。 サーバーは 1 秒あたり 1 人の生徒にサービスを提供できるティーポットで、サービスは常に現在キューの先頭にいる生徒に行われます。 学生は最終的に前に到着してちょうど 1 秒間サービスを受けるか、まだ他の人の後ろで待っている場合はサービスを受けずに締め切り時間にシステムを離れるかのどちらかです。 

入力により、各生徒が列に到着する時刻と、その後待たなくなる時間がわかります。 学生が列に加わると、個人の締め切りまでに強制的に退出しない限り、順番に並び続けます。 各生徒の重要な出力は、生徒が配膳された正確な秒数、または生徒が忍耐力が切れるまでに先頭に到達できなかった場合はゼロです。 

制約は十分に小さいため、約 1,000 万回までの単純な操作までのソリューションは安全です。 すべてのテスト ケースの合計生徒数が最大 1000 人で、到着時間が 5000 に制限されている場合、O(n * max_time) のシミュレーションでも実行可能です。 これは、高度なデータ構造を心配することなく、時間を段階的に安全にシミュレートしたり、キューを貪欲に維持したりできることをすでに示唆しています。 

微妙な点は、到着順とインデックス順の相互関係です。 複数の学生が同じ秒に到着すると、問題により、インデックスの低い学生が先にキューに入ることが強制されます。 これは、キューの順序が決定的であり、慎重に構築する必要があることを意味します。 そうしないと、単純な「到着順のみで並べ替える」アプローチでは、タイが誤って交換される可能性があります。 

もう 1 つの注意が必要な状況は、キューがすでに何人かの人々を処理した後に学生が到着し、即座にキューの先頭になる場合に発生します。 その場合、前の生徒が入力順にまだ存在していてもまだ到着していない場合でも、生徒はすぐに提供されます。 このため、静的な順序を仮定するのではなく、時間の経過をシミュレートすることが不可欠になります。 

最後に、素朴な推論の失敗例は、各生徒がインデックスが小さい以前のすべての生徒を単に待つと仮定することです。 これは、学生がサービスを受ける前に姿を消す可能性がある締め切りの影響を無視しており、後続の学生が予想よりも早く先に進むことを可能にする可能性があります。 

## アプローチ

 簡単なアイデアは、秒ごとにシミュレーションすることです。 各時間単位で、到着する学生をキューに入れ、キューを維持し、キューが空でない場合は、先頭の学生にサービスを提供します。 また、最前列の生徒が期限を過ぎていないか確認し、排除します。 このアプローチは、問題のルールを正確に反映しているため、正しいです。 

ただし、この単純なシミュレーションは、不注意に実装すると、繰り返しスキャンまたはキューの削除を非効率的に管理する可能性があります。 最悪の場合、最大 5000 秒にわたって 1 秒あたり O(n) の操作を実行することになり、約 500 万の操作が発生する可能性があります。これはまだ許容範囲内ですが、不必要に冗長になります。 

重要な点は、複雑なクリーンアップを伴う完全なイベント駆動型シミュレーションは必要ないということです。 制約が小さいため、時間の増加順にイベントを安全に処理し、到着をキューに押し込み、常に先頭の有効性をチェックできます。 各生徒は 1 回挿入され、1 回削除されるため、合計の操作はテスト ケースごとに n で線形に保たれます。 

本当の単純化は、私たちは最前にいる次に空いている生徒のことだけを気にしており、時間は到着したとき、またはサービス時間を割り当てるときにのみ問題になるということです。 アイドル秒数を明示的にシミュレートしません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 単純な秒ごとのシミュレーション | O(T · 最大時間) | O(n) | 受け入れられるが不格好 |
 | イベント駆動型キューのシミュレーション | テストあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

到着したがまだサービスを受けていない、または有効期限が切れている学生の列を維持しながら、学生の処理に時間を費やしています。 

1. 同点の場合の元のインデックスを保持しながら、学生を到着時間ごとに並べ替えるか反復処理します。 これにより、複数の到着が同時に発生した場合でも、正しいキュー挿入順序が保証されます。 
2. 最も早い到着から始まる現在の時刻ポインタを維持します。 
3. 活発な学生の列を維持します。 各エントリには、インデックス、到着時刻、期限が保存されます。 
4. 必要に応じて時間を次のイベントに進め、到着時刻に達した生徒全員をキューに入れます。 これにより、キューが常に現在の状態を反映するようになります。 
5. キューが空でない場合は、前の生徒を連れて行きます。 現在の時間が許可された間隔内にある場合は、この時間をサービス時間として割り当て、それらを削除します。 
6. 先頭の生徒がすでに締め切りを過ぎている場合は、その生徒を破棄し、次の生徒のチェックを続けます。 
7. キューが空の場合は、空の秒数をステップ実行するのではなく、時間を次の到着イベントにジャンプします。 

重要な考え方は、すべての生徒が列に出入りするのは多くても 1 回だけであり、過去の決定を決して再考しないということです。 

### なぜ効果があるのか

 いつでも、キューは到着し、まだサービスを受ける資格のある一連の学生を正確に表します。 すべての到着者が正しい順序を保持し、後の生徒はまだキューに残っている前の生徒を迂回できないため、時間が進んだ場合、常に先頭の生徒が次にサービスを受けることになります。 各生徒は FIFO 順序で処理され、提供されるか期限切れになるのは 1 回だけであるため、毎秒明示的にシミュレーションする必要がなく、シミュレーションではシステムの実際の状態が保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        students = []
        for i in range(n):
            l, r = map(int, input().split())
            students.append((l, r, i))

        students.sort(key=lambda x: (x[0], x[2]))

        ans = [0] * n
        from collections import deque
        q = deque()

        i = 0
        time = students[0][0]

        while i < n or q:
            while i < n and students[i][0] <= time:
                q.append(students[i])
                i += 1

            if not q:
                time = students[i][0]
                continue

            l, r, idx = q.popleft()

            if time > r:
                continue

            ans[idx] = time
            time += 1

        print(*ans)

if __name__ == "__main__":
    solve()
```このコードは、最初に学生を並べ替えて、インデックスのタイブレークによってキューの順序を維持しながら、到着が正しい時間順で処理されるようにします。 Deque には、アクティブなすべての学生が保存されます。 生徒にサービスを提供したり、列が空の場合は次の到着者にジャンプしたりすることで、継続的に時間を進めます。 サービスを提供するとき、私たちは生徒がまだ許可された間隔内にいることを確認します。 それ以外の場合は、それらを破棄して続行します。 

微妙な詳細は、キューが空の場合のタイムジャンプです。 これがないと、シミュレーションはサービスが発生しないところでタイム ステップを誤って無駄にしてしまい、不必要で遅くなる可能性があります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    def solve():
        t = int(input())
        for _ in range(t):
            n = int(input())
            students = []
            for i in range(n):
                l, r = map(int, input().split())
                students.append((l, r, i))

            students.sort(key=lambda x: (x[0], x[2]))

            ans = [0] * n
            q = deque()
            i = 0
            time = students[0][0]

            while i < n or q:
                while i < n and students[i][0] <= time:
                    q.append(students[i])
                    i += 1

                if not q:
                    time = students[i][0]
                    continue

                l, r, idx = q.popleft()

                if time > r:
                    continue

                ans[idx] = time
                time += 1

            return " ".join(map(str, ans))

        return ""

    return solve()

 ## 特殊なケース

 主なエッジケースは、学生が到着したものの、締め切りが非常に厳しく、すぐに期限切れになる場合です。 たとえば、次のような学生がいます。`l = r = 1`時刻 1 に正確に提供されるか、まったく提供されない必要があります。 アルゴリズムは、現在の時間が期限を超えていない場合にのみ時間を割り当て、それ以外の場合は他の時間をブロックする前に破棄するため、これを処理します。 

もう一つのケースは、多くの学生が同時に到着する場合です。 到着時間で並べ替えてからインデックスを作成するため、キューの挿入によって必要な順序が維持され、サービスの順序が変更される誤った優先順位の入れ替えが防止されます。 

3 番目のケースは、処理の途中でキューが空になった場合です。 次の到着者に直接時間を移動することで、人為的な遅延を回避し、正確性を失うことなく新しく到着した生徒に即座に対応できるようにします。
