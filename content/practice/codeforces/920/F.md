 ## 解決策
 ## 問題の理解

 私たちは、2 つの演算が範囲にわたって繰り返し適用される整数の配列を操作しています。 1 つの操作では、セグメント内のすべての値を正の除数の数に置き換えます。もう 1 つの操作では、以前のすべての更新後のセグメント内の値の合計を求めます。 

重要なオブジェクトは divisor-count 関数です。 置換を適用するたびに、選択した間隔内のすべての要素が縮小または安定します。これは、約数の数を取得すると、任意の整数がはるかに小さい数にマップされるためです。 たとえば、10^6 付近の値は最大約 240 の約数まで下がり、適用を繰り返すとすぐにすべてが 1 または 2 に近づき、そこでプロセスが安定します。 

制約は大きく、最大 300,000 個の要素と 300,000 個のクエリです。 更新ごとにすべての要素の除数の数を再計算する単純なソリューションでは、遅すぎます。 除数の計算を最適化したとしても、広い範囲のすべての要素に繰り返し触れると、最悪の場合、二次関数の動作が発生します。 

微妙な点は、要素ごとに少数のアプリケーションを実行した後では、更新が冪等であることです。 値が 1 または 2 になると、D(1) = 1 および D(2) = 2 であるため、除数関数をさらに適用しても役に立ちません。この特性が、問題が効率的に解決できる理由のすべてです。 

範囲が繰り返し更新される場合、エッジ ケースが発生します。 

一例として、10^6 のような大きな数値で満たされたセグメントがあります。 クエリごとに除数を繰り返し再計算する単純なアプローチでは、各 REPLACE がすべての要素に影響するため、すぐに制限時間を超えてしまいます。 

別のエッジ ケースでは、1 でいっぱいの配列など、すでに安定したセグメントに対して REPLACE が繰り返されます。 正しいソリューションでは、作業の無駄を避ける必要があります。 そうしないと、300,000 件の更新が依然として不必要な走査につながります。 

## アプローチ

 直接シミュレーションでは、範囲内のすべてのインデックスを反復処理し、除数の数を再計算することで、各 REPLACE を処理します。 各 SUM は間隔の合計を再計算します。 これは正しいですが、高価です。 最悪の場合、1 回の REPLACE が O(n) 個の要素に影響し、そのような操作が最大 O(n) 個になると、複雑さは O(nm) になり、これは実行不可能です。 

重要な観察は、値が非常に早く安定するということです。 D(x) を数回適用すると、すべての要素が 1 または 2 になり、それ以降の更新によって変更されなくなります。 これは、各インデックスが不活性になる前に、意味のある「更新」ができるのは少数回だけであることを意味します。 

これを利用して、合計のセグメント ツリーと、値がすでに 1 または 2 である位置をスキップできる構造を維持します。範囲内のすべての要素に盲目的に REPLACE を適用するのではなく、2 より大きい値がまだ含まれているセグメントにのみ降下します。セグメントが完全に安定すると、マークが付けられ、再アクセスされることはありません。 

これを効率的にサポートするために、各セグメント ツリー ノードにそのセグメントの最大値を格納します。 最大値が 2 未満の場合は、REPLACE 中にすぐにスキップできます。 

REPLACE 操作はガイド付きのトラバーサルになります。値がまだ変更される可能性があるノードのみを訪問します。 葉で、D(a[i]) を再計算し、ツリーを更新します。 SUM は、標準のセグメント ツリー範囲合計クエリによって処理されます。 

これにより、問題は古典的な「値が急速に減少し、早期に停止する」セグメント ツリーの最適化に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | O(n) | 遅すぎる |
 | 枝刈りを伴うセグメントツリー | 写真 枝刈りを伴うセグメントツリー O((n + m) log n) 償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードが 2 つの値 (セグメントの合計とセグメント内の最大値) を格納するセグメント ツリーを維持します。

1. 初期配列からセグメント ツリーを構築し、各ノードに合計と最大値の両方を保存します。 これにより、クエリとプルーニングの決定の両方が可能になります。 
2. 範囲 [l, r] の SUM クエリの場合、セグメント ツリーを通常どおり走査し、クエリ範囲全体にあるノードからの合計を累積します。 これは標準的な範囲合計クエリ ロジックです。 
3. [l, r] に対する REPLACE クエリの場合は、ルートから再帰的走査を開始します。 セグメントが完全に範囲外にある場合は、何も行いません。 
4. セグメントが完全に範囲内にあり、その最大値が ≤ 2 の場合は、直ちに停止します。 D(1)=1 および D(2)=2 であるため、内部の要素はこれ以上変更できません。 この枝刈りが主な効率向上になります。 
5. リーフ ノードに到達したら、D(a[i]) を直接計算し、値とセグメント ツリー集合体の両方を更新します。 
6. セグメントが部分的に範囲内にある場合、またはまだ max > 2 である場合は、その子を再帰し、処理後に値を更新します。 
7. 再帰の後、正確さを維持するために内部ノードの合計と最大値を再計算します。 

### なぜ効果があるのか

 正しさは、除数の数が 2 より大きい整数を厳密に減らすという事実に依存します。つまり、要素が 2 より大きい間に更新されるたびに、要素は安定に近づきます。 一度1か2になると二度と変わりません。 したがって、各インデックスは意味のある作業にわずかな回数しか貢献できず、セグメント内のすべての値が 2 以下になると、そのセグメントは永続的に安定し、永久にスキップできます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 10**6

div = [0] * (MAXV + 1)
for i in range(1, MAXV + 1):
    for j in range(i, MAXV + 1, i):
        div[j] += 1

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.sum = [0] * (4 * self.n)
        self.mx = [0] * (4 * self.n)
        self.arr = arr
        self.build(1, 0, self.n - 1)

    def build(self, v, tl, tr):
        if tl == tr:
            self.sum[v] = self.arr[tl]
            self.mx[v] = self.arr[tl]
        else:
            tm = (tl + tr) // 2
            self.build(v * 2, tl, tm)
            self.build(v * 2 + 1, tm + 1, tr)
            self.pull(v)

    def pull(self, v):
        self.sum[v] = self.sum[v * 2] + self.sum[v * 2 + 1]
        self.mx[v] = max(self.mx[v * 2], self.mx[v * 2 + 1])

    def update_range(self, v, tl, tr, l, r):
        if tl > r or tr < l or self.mx[v] <= 2:
            return
        if tl == tr:
            self.sum[v] = div[self.sum[v]]
            self.mx[v] = self.sum[v]
            return

        tm = (tl + tr) // 2
        self.update_range(v * 2, tl, tm, l, r)
        self.update_range(v * 2 + 1, tm + 1, tr, l, r)
        self.pull(v)

    def query_sum(self, v, tl, tr, l, r):
        if tl > r or tr < l:
            return 0
        if l <= tl and tr <= r:
            return self.sum[v]
        tm = (tl + tr) // 2
        return self.query_sum(v * 2, tl, tm, l, r) + self.query_sum(v * 2 + 1, tm + 1, tr, l, r)

n, m = map(int, input().split())
arr = list(map(int, input().split()))

st = SegTree(arr)

for _ in range(m):
    t, l, r = map(int, input().split())
    l -= 1
    r -= 1
    if t == 1:
        st.update_range(1, 0, n - 1, l, r)
    else:
        print(st.query_sum(1, 0, n - 1, l, r))
```解決策は、更新前にすべての配列値がその範囲内に留まるため、最大 10^6 までの除数カウントを事前計算することから始まります。 これにより、クエリ中に除数を繰り返し再計算することがなくなります。 

セグメント ツリーには合計と最大値の両方が保存されます。 最大値がクリティカル プルーニング シグナルです。これが 2 未満になると、そのセグメントではそれ以上更新できないことがわかります。 

update_range 関数は、明示的な遅延伝播を行わずに遅延スタイルのトラバーサルを実行します。 更新をプッシュする代わりに、最大値を使用して再帰が必要かどうかを決定します。 リーフ更新では、事前計算されたテーブルを使用して除数関数が直接適用されます。 

クエリは、標準的なセグメント ツリー範囲合計クエリです。 

## 実用的な例

 ### 例: サンプル入力

 初期配列は [6, 4, 1, 10, 3, 2, 4] です。 

最初の SUM [1,7] は、セグメント ツリーから直接合計 30 を計算します。 

次の SUM [4,5] は 10 + 3 = 13 を返します。 

次に、REPLACE [3,5] は次のように変換します。 

1 → 1、10 → 4、3 → 2 により、更新された配列 [6,4,1,4,2,2,4] が得られます。 

2 番目の SUM [4,4] は 4 を返します。 

次に、REPLACE [5,7] で [2,2,4] → [2,2,3] を変換します。 

最終的な合計 [1,7] は 6+4+1+4+2+2+3 = 22 になります。 

このトレースは、除数の適用を繰り返すと値がどのように急速に圧縮されるか、また安定した値がどのように変化しないかを示します。

 ## 特殊なケース

 1 と 2 だけで構成される完全に安定した配列は、REPLACE クエリが直ちに終了する必要があることを示しています。 セグメント ツリーの最大チェックにより、リーフにアクセスすることなく再帰がルートで停止することが保証されます。
