 ## 解決策
 ## 問題の理解

 順列を構築するように求められるわけではありません。 2 つの長さの順列が存在するかどうかを判断するだけで済みます。`n`正確に共有するように存在できる`a`先頭と正確な位置`b`最後に位置。 

2 つの順列について考えてみましょう`p`そして`q`。 最長の共通プレフィックスに長さがある場合`a`、次に位置`0...a-1`等しい必要がありますと位置`a`異なる限り、`a = n`。 同様に、それらの最長の共通接尾辞が length である場合、`b`、そして最後`b`ただし、位置は等しくなければならず、そのサフィックスの直前の位置は異なっていなければなりません。`b = n`。 

制約はわずかです。 順列の長さは最大で`100`、最大で`10^4`テストケース。 たとえ`O(n)`または`O(n^2)`テストケースごとのチェックは簡単です。 課題はパフォーマンスではなく、有効なペアが存在するかどうかを決定する正しい条件を発見することです。 

いくつかの特殊なケースは見落とされがちです。 

考慮する：```
n = 1, a = 1, b = 1
```答えは`Yes`。 順列は 1 つだけあり、`[1]`したがって、両方の順列が同一である必要があります。 以下のようなケースを盲目的に拒否するソリューション`a + b >= n`間違って出力されてしまう`No`。 

考慮する：```
n = 2, a = 1, b = 1
```答えは`No`。 最初の位置が一致し、2 番目の位置も一致する場合、順列は完全に同一です。 それらの共通のプレフィックスとサフィックスの長さは両方とも次のようになります。`2`、 ない`1`。 

考慮する：```
n = 4, a = 1, b = 1
```答えは`Yes`。 有効なペアの 1 つは次のとおりです。```
p = [1,2,3,4]
q = [1,3,2,4]
```一般的なプレフィックス長は次のとおりです。`1`共通の接尾辞の長さは次のとおりです。`1`。 

よくある間違いは、`a + b <= n`。 例えば：```
n = 3, a = 1, b = 1
```ここ`a + b = 2 <= 3`、しかし答えはまだです`No`。 前部と後部に 1 つの共通の位置を固定すると、中央の 1 つの位置だけが残ります。 変更は少なくとも 2 つの値を移動する必要があるため、2 つの順列は 1 つの位置だけで異なることはできません。 

## アプローチ

 強引なアイデアは、長さのすべての順列を生成することです。`n`、すべてのペアを調べ、それらの最長の共通プレフィックスとサフィックスを計算します。 これは、定義を直接テストするため、正しいです。 残念ながら、順列の数は`n!`。 たとえ`n = 10`、すでにあります`3,628,800`順列が異なるため、完全な検索は不可能になります。 

重要な観察は、位置を数えることから得られます。 

最初`a`位置は強制的に等しくなります。 最後`b`位置も強制的に平等になります。 つまり、`a + b`一部の位置は重複する可能性がありますが、位置は一致するものとしてすでに固定されています。 

残りの位置は、順列が異なる可能性がある唯一の領域を形成します。 

させて```
free = n - a - b
```もし`free < 0`の場合、必要な共通のプレフィックスとサフィックスが重複しすぎます。 これが起こる唯一の方法は、順列が完全に同一になる場合です。 それは特別な場合にのみ可能です`n = a = b`。 

もし`free = 0`、すべての位置が強制的に一致するため、ここでも順列は同一になります。 ない限り`n = a = b`、必要な最長のプレフィックスとサフィックスの長さを達成できません。 

もし`free = 1`、固定されていない位置が 1 つだけあります。 1 つの値を移動すると必ず別の位置にも影響を与えるため、2 つの順列が 1 つの位置だけで異なることはできません。 

異なる順列を作成するには、少なくとも 2 つの自由な位置が必要です。 次に、その空き領域内の 2 つの値を交換して、必要な不一致を取得できます。 

したがって、条件は次のようになります。```
n - a - b >= 2
```または特殊な場合:```
a = n and b = n
```Codeforces の社説では通常、次のような同じ考えが表現されています。```
a + b <= n - 2
```または```
a = n and b = n
```これらの条件は同等です。

 ## アルゴリズムのチュートリアル

 1.読む`n`、`a`、 そして`b`。 
2. かどうかを確認します。`a == n`そして`b == n`。 

この状況では、両方の順列が単に同一である可能性があります。 答えは`Yes`。 
3. それ以外の場合は、`a + b <= n - 2`。 

これは、強制された共通プレフィックスと共通サフィックスの外側に少なくとも 2 つの位置が残ることを意味します。 
4. 条件が成立した場合に出力`Yes`。 

少なくとも 2 つの空き位置があれば、その領域内でスワップを調整し、必要なプレフィックスとサフィックスを維持しながらさまざまな順列を作成できます。 
5. それ以外の場合は出力`No`。 

空き位置が 2 つ未満であるということは、順列が同一であるか、ちょうど 1 つの位置が異なる必要があることを意味しますが、これは順列では不可能です。 

### なぜ効果があるのか

 最初の`a`順位と最後`b`位置は 2 つの順列間で等しくなるように固定されます。 差異がある場合は、残りの位置でも発生する必要があります。 

ある順列は、1 つの位置だけで別の順列と異なることはできません。 値を移動すると、少なくとも 1 つの追加位置が強制的に変更されます。 したがって、同一でないペアには、変更が許可される少なくとも 2 つの位置が必要です。 

いつ`a + b <= n - 2`、そのような位置が少なくとも 2 つあり、その領域内の単純な交換により有効なペアが作成されます。 いつ`a + b > n - 2`、残っている空きポジションは 2 つ未満です。 唯一実現可能なケースは、すべてのポジションが共有される場合です。`a = b = n`、ここで、同一の順列が要件を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n, a, b = map(int, input().split())

    if (a == n and b == n) or (a + b <= n - 2):
        print("Yes")
    else:
        print("No")
```実装は数学的条件に直接に従います。 

最初の分岐は、両方の最長共通長が順列全体の長さに等しいという独特の状況を処理します。 その場合、2 つの順列は同一になる可能性があります。 

2 番目のブランチは、強制一致するプレフィックスとサフィックスの外側に少なくとも 2 つの位置が残っているかどうかをチェックします。 使用する`a + b <= n - 2`まったく同じ条件ではありますが、空きポジションの数を明示的に計算することを回避します。 

すべての値が最大値であるため、オーバーフローの懸念はありません。`100`。 唯一微妙な部分は特殊なケースを思い出すことです`a = b = n`。 それがなければ、次のような入力`1 1 1`誤って生成してしまう`No`。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n, a, b = map(int, input().split())

        if (a == n and b == n) or (a + b <= n - 2):
            ans.append("Yes")
        else:
            ans.append("No")

    return "\n".join(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# provided sample
assert run(
"""4
1 1 1
2 1 2
3 1 1
4 1 1
"""
) == "Yes\nNo\nNo\nYes", "sample 1"

# minimum size
assert run(
"""1
1 1 1
"""
) == "Yes", "single element permutation"

# exactly one free position
assert run(
"""1
5 2 2
"""
) == "No", "cannot differ in exactly one position"

# exactly two free positions
assert run(
"""1
6 2 2
"""
) == "Yes", "minimum accepted free region"

# maximum size style case
assert run(
"""1
100 49 49
"""
) == "Yes", "large valid case"

# all positions forced equal but not full length
assert run(
"""1
2 1 1
"""
) == "No", "identical permutations would violate longest lengths"

## 特殊なケース

 次のことを考慮してください。```
n = 1
a = 1
b = 1
```アルゴリズムはまず次のことをチェックします。`a == n`そして`b == n`。 両方の条件が true であるため、出力されます。`Yes`。 

トレース：```
a == n -> true
b == n -> true
answer -> Yes
```これは唯一の置換を正しく処理します`[1]`。 

考慮する：```
n = 2
a = 1
b = 1
```特殊なケースは次の理由で失敗します。`a`そして`b`両方とも等しくありません`n`。 

それから：```
a + b = 2
n - 2 = 0
```条件`2 <= 0`false であるため、アルゴリズムは次のように出力します。`No`。 

すべての位置が強制的に等しくなり、順列が同一になります。 それらの最長の共通プレフィックスとサフィックスは次のようになります。`2`、 ない`1`。 

考慮する：```
n = 3
a = 1
b = 1
```アルゴリズムは以下を評価します。```
a + b = 2
n - 2 = 1
```以来`2 <= 1`は誤りです、答えは`No`。 

使用可能な中間ポジションは 1 つだけです。 順列を変更しようとすると、少なくとも 2 つの位置を変更する必要がありますが、空きスロットが 1 つしかない場合は不可能です。 

考慮する：```
n = 4
a = 1
b = 1
```アルゴリズムは以下を評価します。```
a + b = 2
n - 2 = 2
```以来`2 <= 2`それは本当です、答えは`Yes`。 

ちょうど 2 つのポジションが未確定のままです。 これらの位置の値を交換すると、必要な共通のプレフィックスとサフィックスの長さを持つ有効な置換が生成されます。
