 ## 解決策
 ## 問題の理解

 循環シーケンスが与えられています。これは、最初と最後の位置も隣接していることを意味します。 最初は、隣接する 2 つの要素が等しくありません。 

Muxii はいつでも 1 つの要素を選択して消去できます。 その消去後、リングは同じ値が隣接したかどうかをチェックします。 もしそうなら、それらの同等の隣人のうちの 1 つが即座に消滅します。 この自動削除により、別の等隣接ペアが作成され、再び削除される場合があります。 

このプロセスは、リングが空になるまで続行されます。 Muxii が要素の選択と消去という明示的な操作を実行する回数を最大化したいと考えています。 自動削除はカウントされません。 

入力により、いくつかのテスト ケースが得られます。 循環シーケンスごとに、可能な最大数の手動削除を計算する必要があります。 

制約は非常に小さいです。 シーケンスの長さは最大 100 で、テスト ケースの数は最大 100 です。 高価なシミュレーションでも快適にフィットします。 課題はパフォーマンスではなく、プロセスの構造を理解することです。 

間違いの主な原因は、すべての要素がいつでも手動で削除できると想定していることです。 考慮する：```text
4
1 2 1 2
```一つ削除したら`1`、リングは次のようになります。```text
2 1 2
```残りの要素は 3 つだけなので、最大 3 つの手動操作が可能です。 正解は 4 ではなく 3 です。 

もう 1 つの微妙なケースは、1 回だけ出現する値を含むシーケンスです。```text
4
1 2 3 2
```固有の値を削除する`3`最初に次のように与えられます:```text
1 2 2
```隣接する 2 つのうちの 1 つ`2`s は自動的に消えます。```text
1 2
```その後、残りの両方の要素を手動で削除できます。 答えは4です。 

最後のエッジ ケースはサイズ 1 のリングです。```text
1
1
```唯一の要素がそれ自体に隣接していません。 手動で削除できるので、答えは 1 です。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての削除命令を試し、すべての自動削除をシミュレートします。 これは、あらゆる有効な戦略を検討しているため、正しいです。 残念ながら、削除命令の数は要素の数にほぼ比例します。 中程度のサイズであっても、これは完全に不可能になります。 

重要な観察結果は、自動削除が避けられない場合を調べることで得られます。 

ある値がリング内に 1 回だけ出現すると仮定します。 その位置に値を含めます`x`。 最初にその要素を削除すると、その 2 つの隣接要素が隣接するようになります。 以来`x`は一意でした。これらの隣接するものは両方とも同じであることはできません`x`。 さらに重要なのは、手動で移動を続ける機能を維持しながら、自動削除によってリングを縮小するのに役立つように、そのような位置を選択できることです。 

実際、一度だけ出現する値が存在する場合、すべての元の要素が 1 回の手動操作に寄与するように、いつでも削除を調整できます。 答えは次のようになります`n`。 

唯一の問題となるのは、すべての値が少なくとも 2 回出現する場合です。 

隣接する等しい値は最初は禁止されているため、値が出現するたびに他の値で区切る必要があります。 すべての値が少なくとも 2 回出現する場合、個別の値の最小数は 2 となり、リングの動作は異なります。 この場合、手動で 1 回削除すると、必然的にリングが十分に崩壊し、可能な操作が 1 つだけ失われます。 

注目すべき結果は、答えが 2 つだけしか存在しないということです。 

ある値が 1 回だけ出現する場合、答えは次のようになります。`n`。 

すべての値が少なくとも 2 回出現する場合、答えは次のようになります。`n / 2 + 1`。 

すべての値が少なくとも 2 回出現し、合計の長さは次のようになります。`n`、2 番目のケースは、まさに存在する場合にのみ発生します。`n / 2`明確な価値観。

 ## アルゴリズムのチュートリアル

 1. リング内のすべての値の頻度を数えます。 

2. 値が 1 回だけ出現するかどうかを確認します。 

3. そのような値が存在する場合は、出力`n`。 

一意の値を開始点として使用すると、手動による削除の最大数を維持できます。 

4. それ以外の場合、すべての値が少なくとも 2 回表示されます。 

5. 出力`n // 2 + 1`。 

この状況では、リングの構造により、手動操作による 1 つの有効損失が強制され、最大値は正確に`n/2 + 1`。 

### なぜ効果があるのか

 問題全体は、一意の値が存在するかどうかにかかっています。 

値が 1 回だけ出現すると、削除を開始する安全な場所となります。 削除を適切に選択すれば、自動削除によって利用可能な手動操作の総数が減ることはありません。`n`要素は手動で選択することで考慮できます。 

すべての値が少なくとも 2 回出現する場合、リングは完全に繰り返された値で構成されます。 等しい隣接値は禁止されているため、同じ値の出現は他の値と交互に発生する必要があります。 削除すると、最終的には 2 つの等しい値がマージされ、避けられない自動削除がトリガーされます。 最適な戦略では、潜在的な手動操作が 1 つだけ失われ、閉じられた形式の答えが得られます。`n/2 + 1`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1
        
        has_single = any(v == 1 for v in freq.values())
        
        if has_single:
            print(n)
        else:
            print(n // 2 + 1)

if __name__ == "__main__":
    solve()
```実装は数学的特徴付けに直接従います。 

頻度表は、ある値が 1 回だけ出現するかどうかを決定します。 そのような値が存在する場合は、次のように出力します。`n`。 それ以外の場合は印刷します`n // 2 + 1`。 

難しい境界条件はありません。 ケース`n = 1`単一の値が 1 回出現するため、自然に最初の分岐に分類されます。 すべての計算には最大でも 100 の値が含まれるため、整数オーバーフローは不可能です。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    out = []

    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = {}
        for x in a:
            freq[x] = freq.get(x, 0) + 1

        if any(v == 1 for v in freq.values()):
            out.append(str(n))
        else:
            out.append(str(n // 2 + 1))

    return "\n".join(out)

1
1
""") == """4
3
1"""

""") == "1"

# all values unique
assert run("""1
5
1 2 3 4 5
""") == "5"

# every value repeated
assert run("""1
6
1 2 3 1 2 3
""") == "4"

# smallest repeated structure
assert run("""1
2
1 2
""") == "2"

 ## 特殊なケース

 次のことを考慮してください。```text
1
1
1
```価値の頻度`1`まさに一つです。 アルゴリズムは戻ります`n = 1`。 これは、唯一の要素を手動で削除できるという事実と一致します。 

考慮する：```text
1
4
1 2 3 2
```価値観`1`そして`3`一度登場する。 アルゴリズムはすぐに戻ります`4`。 一意の値が存在するため、4 つの手動操作をすべて実行できます。 

考慮する：```text
1
4
1 2 1 2
```すべての値は 2 回表示されます。 アルゴリズムは 2 番目の分岐に入り、次を返します。```text
4 // 2 + 1 = 3
```これは最適な戦略と公式サンプルと一致します。 

考慮する：```text
1
6
1 2 3 1 2 3
```すべての値は 2 回出現するため、答えは次のようになります。```text
6 // 2 + 1 = 4
```これにより、2 番目の式が最小の例を超えて適用され、一意の値が存在しないことのみに依存することが検証されます。
