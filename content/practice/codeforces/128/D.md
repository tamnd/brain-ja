 ## 解決策
 ## 問題の理解

 複数の数字のセットが与えられ、隣接する数字のすべてのペアが 1 つだけ異なるようにそれらを円形に配置することが可能かどうかを尋ねられます。 概念的には、これは各数値がサイクル上の頂点であり、隣接する数値間の絶対差が 1 でなければならないことを意味します。入力は要素の数と、その後に続く要素自体で構成されます。 出力は、そのような循環配置が存在する場合は単純に「YES」、存在しない場合は「NO」になります。 

制約は重要です: 要素の数$n$まで可能です$10^5$、値自体は次の値に達する可能性があります。$10^9$。 これにより、階乗時間となるすべての順列を明示的に構築しようとするソリューションが除外されます。 線形または線形に近いアプローチが必要です。 

いくつかの特殊なケースでは、単純な解決策では簡単につまずいてしまう可能性があります。 たとえば、すべての数値が同一の場合、隣接する数値の差は 1 ではなく 0 になるため、出力は「NO」になる必要があります。 数値が単純な増加または減少のシーケンスを形成している場合、次のようになります。`1 2 3 4 3 2`、円形の条件を満たすために対称に配置することは可能かもしれません。 もう 1 つの注意が必要なケースは、数値が 2 回以上出現するが、シーケンスの終点ではない場合です。 例えば、`1 2 2 3 3 3`有効な円を形成できないため、`3`2 つに隣接する必要があります`3`s が少なくとも 1 回あり、差異条件に違反しています。 

## アプローチ

 ブルート フォース アプローチは簡単に説明できます。数値のすべての順列を生成し、それぞれの循環差分条件をチェックします。 これは文字通りあらゆる可能な配置をテストするため、原理的には正しいですが、複雑さは次のとおりです。$O(n!)$、これはまったく実用的ではありません$n$まで$10^5$。 

重要な洞察は、隣接する差異が正確に 1 であるシーケンスの特性を観察することで得られます。 有効な配列は、実際には、「山」または「谷」のパターンを形成する連続する整数 (繰り返しの可能性がある) のシーケンスです。これは、各数値が隣接する数値と正確に 1 だけ異なっている必要があるためです。 これは、マルチセットを厳密に増加するセグメントと厳密に減少するセグメントに分割でき、各数値は 1 回しか出現しない最小値と最大値を除き、最大 2 回出現することを意味します。 中央に 2 回以上出現する数値は、隣接する 2 つの同一の数値を強制することになり、差の要件に違反します。 

この観察から、それぞれの異なる数値の出現を数えるという最適なアプローチが浮かび上がります。 数値が 2 回以上出現する場合、または円が閉じない構成で最大値または最小値が 2 回出現する場合、答えは「いいえ」です。 それ以外の場合は、最初に厳密に増加する一意の数値を最大値まで配置し、次に残りの数値を降順で最小値まで追加することによって数値を配置することができます。 これにより、隣接するすべてのペアが 1 つずつ異なることが保証されます。

 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 辞書を使用して、マルチセット内の各個別の数値の頻度を数えます。 これにより、数値が 2 回以上出現するかどうかをすぐに識別できます。 そうなった場合は、「NO」を出力して停止します。 
2. 最小値と最大値を見つけます。 これらは、潜在的な連続シーケンスの境界を定義します。 
3. シーケンスの途中に 2 回以上出現する数値がないことを確認します。 数値が 2 回出現する場合、1 つのコピーは増加するセグメントに配置され、もう 1 つは減少するセグメントに配置されます。 最小値と最大値は、円の閉じた部分で隣接するものが繰り返されるのを避けるために、それぞれ 1 回だけ表示されます。 
4. すべてのチェックに合格した場合は、「YES」を出力します。これは、最初に数値を昇順 (それぞれ 1 回出現) に並べ、次に重複するものを降順に並べることによって、有効な循環シーケンスを構築できるためです。 

機能する理由: このアルゴリズムは、隣接する数値は 1 ずつ異なっていなければならないという特性に依存しています。 数値を昇順、次に降順に並べると、シーケンス内の隣接するペアのそれぞれが 1 ずつ異なります。これに違反する唯一の方法は、数値が 2 回以上出現するか、境界で誤って出現する場合です。 頻度をカウントし、最小値と最大値を調べることにより、不法な近隣が発生しないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import Counter

n = int(input())
a = list(map(int, input().split()))
freq = Counter(a)

# if any number appears more than twice, impossible
if any(v > 2 for v in freq.values()):
    print("NO")
    sys.exit(0)

nums = sorted(freq.keys())

# if min or max appears twice, impossible
if freq[nums[0]] == 2 or freq[nums[-1]] == 2:
    print("NO")
    sys.exit(0)

print("YES")
```このソリューションは配列を読み取り、頻度をカウントし、数値が 2 回以上出現する、または最小値/最大値が 2 回出現するというあり得ないケースを即座に排除します。 キーを並べ替えることは、「山」構造を概念化するのに役立ちますが、条件によって実現可能性が保証されるため、シーケンスを明示的に構築する必要はありません。

## テストケース```python
import sys, io
from collections import Counter

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    freq = Counter(a)
    if any(v > 2 for v in freq.values()):
        return "NO"
    nums = sorted(freq.keys())
    if freq[nums[0]] == 2 or freq[nums[-1]] == 2:
        return "NO"
    return "YES"

# Provided sample
assert run("4\n1 2 3 2\n") == "YES", "sample 1"

# Custom cases
assert run("3\n5 5 5\n") == "NO", "triple identical"
assert run("3\n1 2 3\n") == "YES", "simple consecutive"
assert run("5\n1 2 3 4 5\n") == "YES", "all consecutive unique"
assert run("6\n1 2 2 3 3 4\n") == "YES", "duplicates in middle"
assert run("4\n1 1 2 2\n") == "NO", "min duplicated"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3\n5 5 5 | いいえ | 数字が 2 回以上出現します |
 | 3\n1 2 3 | はい | 単純な増加シーケンス |
 | 5\n1 2 3 4 5 | はい | 連続した番号、重複なし |
 | 6\n1 2 2 3 3 4 | はい | 中央の重複は許可されます |
 | 4\n1 1 2 2 | いいえ | 最小重複エッジケース |

 ## 特殊なケース

 すべての数字が同じ場合、たとえば、`5 5 5`の場合、アルゴリズムは数値が 2 回以上出現することを正しく識別し、「NO」を返します。 次のような単純な増加シーケンスの場合`1 2 3`の場合、アルゴリズムはすべての周波数が 1 つであること、最小値と最大値が 1 回だけ現れることを確認し、「YES」を出力します。 最小値または最大値が 2 回出現するような特殊なケースの場合。`1 1 2 2`の場合、アルゴリズムは不可能であることにフラグを立てて、無効な循環隣接を回避します。 各ケースは頻度チェックとソートされたキー検査によって直接処理され、正確性が保証されます。
