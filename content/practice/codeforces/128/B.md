 ## 解決策
 ## 問題の理解

 小文字の文字列と整数 _k_ が与えられます。 このタスクは、文字列の考えられるすべての部分文字列を生成し、それらを辞書順に並べ替えて、その順序で _k_ 番目の部分文字列を返すことです。 部分文字列は繰り返すことができるため、複数の同一の部分文字列は個別に考慮する必要があります。 部分文字列が _k_ 個よりも少ない場合は、次の値を返します。`"No such line."`。 

制約としては、文字列の長さ _n_ は最大 100,000、_k_ は最大 100,000 に達することができます。 長さ _n_ の文字列にはおよそ _n(n+1)/2_ 個の部分文字列があり、これは _n_ = 100,000 の場合に最大 50 億個になるため、すべての部分文字列を単純に列挙することは不可能です。 これほど大量のコレクションを制限時間内に整理するのは不可能です。 これにより、O(n²) または O(n² log n) のアプローチが除外されます。 

エッジ ケースには、文字が繰り返される文字列、長さ 1 の文字列、部分文字列の合計数を超える _k_ が含まれます。 たとえば、`"aa"`および _k_ = 3 の場合、辞書編集順の部分文字列は次のとおりです。`"a"`、`"a"`、`"aa"`。 単純なアプローチでは、誤って重複を削除して間違った結果が生成されたり、インデックスの数え間違いが発生したりする可能性があります。 

## アプローチ

 ブルートフォースソリューションの説明は簡単です。 すべての部分文字列を生成し、リストに格納し、リストを辞書順に並べ替えて、インデックス _k-1_ の要素を返します。 部分文字列の生成と並べ替えは原理的に正しいため、このアプローチは小さな文字列に対して機能します。 ただし、O(n²) 個の部分文字列があり、それらを並べ替えるのに O(n² log n²) かかるため、時間計算量は O(n² log n) です。 n = 10⁵ では、これは遅すぎます。 

効率的なソリューションを実現するための重要な洞察は、すべての部分文字列を明示的に生成しないようにすることです。 辞書順にソートされた部分文字列は、文字列の接尾辞の接頭辞として表すことができます。 すべての接尾辞を生成して並べ替えると、部分文字列の辞書編集順序は、これらの並べ替えられた接尾辞に沿って進み、接頭辞を段階的に取得することに対応します。 プレフィックスの長さを _k_ に制限することで、必要な最小限の文字のみが考慮され、O(n²) 個の作業が回避されます。 

これは、優先キューを使用するか、単にすべてのサフィックスを並べ替えてからプレフィックスを順番にカウントすることによって効率的に実装できます。 _k_ 番目の部分文字列に到達したら停止します。 これにより、メモリのオーバーヘッドが軽減され、完全な部分文字列の列挙が回避されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log n²) | O(n²) | 遅すぎる |
 | サフィックス + プレフィックスの列挙 | O(n log n + k²) | O(n + k²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 次のようにして、文字列のすべてのサフィックスを生成します。`s[i:]`それぞれに`i`0からn-1まで。 各サフィックスは異なる位置で始まり、その位置から始まるすべての部分文字列が含まれます。 
2. 接尾辞のリストを辞書順に並べ替えます。 これにより、接頭辞を考慮する限り、接尾辞を順番に調べると、部分文字列が辞書編集順に得られることが保証されます。 
3. 列挙した部分文字列の数を追跡するためにカウンターを初期化します。 ソートされた順序で各サフィックスについて、長さ _k_ までのすべてのプレフィックスを列挙します。 _k_ 番目の部分文字列は _k_ より長くならないため、必要以上の文字が生成されないようにプレフィックスの長さを制限します。 
4. プレフィックスごとに、カウンターをインクリメントします。 カウンタが _k_ に等しい場合、このプレフィックスを出力して終了します。 _k_ に達することなく、すべての接尾辞からすべての接頭辞を列挙し終えた場合は、次のように出力します。`"No such line."`。 
5. この方法では、ソートされた接尾辞に考えられるすべての部分文字列が順番に含まれており、この方法で接頭辞をカウントすることで繰り返しの部分文字列が正しく処理されるため、正確さが保証されます。 

機能する理由: 接尾辞を並べ替えることにより、グローバルな辞書編集順序が作成されます。 元の文字列のすべての部分文字列は、何らかの接尾辞の接頭辞です。 プレフィックスを長さを増やして列挙すると、重複が正しくカウントされ、サブストリングが正しい順序で表示されます。 プレフィックスの長さを _k_ に制限すると、不必要な作業が制限され、時間とメモリの爆発が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    s = input().strip()
    k = int(input())
    n = len(s)
    
    # Generate all suffixes
    suffixes = [s[i:] for i in range(n)]
    suffixes.sort()
    
    count = 0
    for suff in suffixes:
        # Limit the prefix length to k to avoid extra work
        for l in range(1, min(len(suff), k) + 1):
            count += 1
            if count == k:
                print(suff[:l])
                return
    print("No such line.")

if __name__ == "__main__":
    main()
```最初の部分では、文字列と整数の入力を効率的に読み取ります。 サフィックスの生成は空間的に O(n) です。 サフィックスのソートは O(n log n) です。 プレフィックスをカウントするときは、_k_ 番目の部分文字列が見つかるとすぐに停止します。 私たちが使用するのは`min(len(suff), k)`_k_ より長い部分文字列は、先頭から数えて _k_ 番目の部分文字列になることはできないためです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + k²) | n 個のサフィックスを並べ替えるのは O(n log n)、ソートされたサフィックス全体で長さ k までのプレフィックスを列挙するのは O(k²) |
 | スペース | O(n + k²) | サフィックスには O(n)、小さなプレフィックスを一時的に保存するには O(k²) |

 n ≤ 10⁵、k ≤ 10⁵ という制約がある場合、O(n log n + k²) が許容されます。 100,000 個のサフィックスのソートは十分に高速であり、プレフィックスの列挙を制限することでメモリを超過することはありません。
