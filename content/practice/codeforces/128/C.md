 ## 解決策
 ## 問題の理解

 まずは方眼紙に描かれた長方形から始めます。 重要なのは国境だけであり、内部は重要ではありません。 プレイヤーは、前の長方形の内側に厳密に小さい長方形を繰り返し描きます。 新しい境界線はどの時点でも前の境界線に触れることはできないため、すべての新しい四角形は、4 方向すべてに少なくとも 1 つのグリッド セルによって古い四角形から分離されている必要があります。 

まさにその後`k`移動したら、最終的に何種類の異なる描画が可能かを数えたいと思います。 プロセス中に描画される四角形のセットが異なる場合、2 つのゲームは異なるものとみなされます。 

重要な観察は、移動するたびに、上から少なくとも 1 行、下から 1 行、左から 1 行、右から 1 行が削除されて長方形が縮小するということです。 現在の長方形に高さがある場合`h`と幅`w`、次の長方形は少なくとも 1 層の間隔で内側に厳密に収まる必要があるため、その高さは最大でも`h - 2`その幅は最大で`w - 2`。 

制約は次のとおりです`1000`3 つのパラメータすべてに対して。 これにより、長方形のシーケンスを明示的に生成するアプローチは即座に除外されます。 すべての遷移にコストがかかる場合、Python では三次動的プログラムであっても危険になり始めます。 周りに何かが必要です`O(n + m + k)`または`O(nk + mk)`。 

見落としやすいエッジケースがいくつかあります。 

もし`k = 1`、厳密には元の長方形の内側にある 1 つの長方形だけを選択しています。 例えば：```
3 3 1
```答えは`1`、中央だけなので、`1 × 1`正方形の作品。 

実装を不注意にすると、外枠に接する四角形を誤ってカウントする可能性があります。 

もう 1 つの微妙なケースは、すべての移動が完了する前に長方形が小さすぎる場合に発生します。```
2 2 2
```正しい答えは、`0`。 

1 回移動した後、可能な長方形は次のとおりです。`0 × 0`、これは無効です。 幾何学的実現可能性をチェックせずに縮小操作の数だけを追跡するソリューションでは、過剰にカウントされてしまいます。 

さらに興味深い例は次のとおりです。```
4 5 1
```答えは`9`。 

有効な内側の長方形は次のとおりです。```
1×1: 6 positions
1×2: 2 positions
2×1: 1 position
```素朴な四角形の数式では、配置数が寸法に依存することが見落とされることがよくあります。 

## アプローチ

 ブルートフォース解釈は簡単です。 移動するたびに、境界に触れずに前の長方形の内側に厳密に収まるすべての長方形を列挙します。 再帰的に継続します`k`動きます。 

これが機能するのは、すべての有効なゲームが文字通りネストされた一連の四角形であるためです。 再帰はゲームのルールと正確に一致します。 

問題は分岐要素です。 サイズの長方形`h × w`おおよそ含まれています`O(h²w²)`サブ長方形。 最悪の場合、再帰ツリーは指数関数的に爆発します。 中程度の次元であっても、状態の数は膨大になります。 

ゲームの構造により、より明確な視点が得られます。 

元の四角形が複数の行にまたがっていると仮定します。`[1, n]`とコラム`[1, m]`。 すべての動きは、上、下、左、右からどれだけ縮小するかを個別に選択します。 長方形は接触できないため、移動するたびに 4 つのマージンすべてを少なくとも増加させる必要があります。`1`。 

後`k`移動する場合、以下を選択しました:```
k rows removed from the top,
k rows removed from the bottom,
k columns removed from the left,
k columns removed from the right.
```順序は、これらの除去がどのように移動に分散されるかという点においてのみ重要です。 

まず垂直方向の寸法に注目してください。 

すべての動きの後に削除した場合`a`上からの列と、`b`下から行を並べて、次のようにします。```
a ≥ k
b ≥ k
a + b < n
```移動間の削除のシーケンスは分割に対応します`a`の中へ`k`ポジティブな部分と分割`b`の中へ`k`ポジティブな部分。 

整数を分割する方法の数`x`の中へ`k`肯定的な部分は次のとおりです。$\binom{x-1}{k-1}$中間の長方形をすべて追跡するのではなく、総収縮がどのように分布するかをカウントするだけです。 

同じ理由が水平方向にも当てはまります。 

標準の組み合わせ恒等式を使用して合計を単純化すると、有効な垂直縮小パターンの総数は次のようになります。$\binom{n-1}{2k}$同様に、水平パターンの数は次のようになります。$\binom{m-1}{2k}$2 つの次元は独立しているため、最終的な答えはその積になります。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`m`、 そして`k`。 
2. かどうかを確認します。`2k > n - 1`または`2k > m - 1`。 

すべての動きは、両側から少なくとも 1 つのレイヤーを消費します。 後`k`移動するには少なくとも必要です`2k`削除された行と`2k`削除された列の合計。 どちらかの次元が小さすぎる場合、有効なシーケンスは存在しません。 
3. 階乗および逆階乗を最大で事前計算します。`1000`。 

高速な二項係数モジュロクエリが必要です`10^9 + 7`。 
4. 以下を計算します。$\binom{n-1}{2k}$5. 以下を計算します。$\binom{m-1}{2k}$6. 2 つの値を剰余で乗算します。`10^9 + 7`。 
7. 結果を印刷します。 

### なぜ効果があるのか

 それぞれの移動により、上、下、左、右の 4 つのマージンが独立して増加します。 結局`k`移動すると、反対側からの合計除去によって全体の入れ子構造が決まります。 

有効なゲームを選択することは、ゲームの場所を選択することと同じです。`2k`必須の収縮層が間に発生します。`n - 1`利用可能な垂直方向のギャップ、および同様に、`m - 1`水平方向の隙間。 

組み合わせ同一性は、これらの選択肢を正確にカウントし、一連の長方形が欠落したり重複したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def build_factorials(limit):
    fact = [1] * (limit + 1)
    for i in range(1, limit + 1):
        fact[i] = fact[i - 1] * i % MOD

    inv_fact = [1] * (limit + 1)
    inv_fact[limit] = pow(fact[limit], MOD - 2, MOD)

    for i in range(limit, 0, -1):
        inv_fact[i - 1] = inv_fact[i] * i % MOD

    return fact, inv_fact

def comb(n, r, fact, inv_fact):
    if r < 0 or r > n:
        return 0
    return fact[n] * inv_fact[r] % MOD * inv_fact[n - r] % MOD

def solve():
    n, m, k = map(int, input().split())

    limit = max(n, m)
    fact, inv_fact = build_factorials(limit)

    ans = comb(n - 1, 2 * k, fact, inv_fact)
    ans *= comb(m - 1, 2 * k, fact, inv_fact)
    ans %= MOD

    print(ans)

solve()
```階乗事前計算は、定数時間の二項係数クエリをサポートします。 最大値だけなので、`1000`、これはとても安いです。 

ヘルパーさん`comb`を返すことで無効なケースを安全に処理します`0`いつ`r > n`。 次のような不可能な構成を自動的に処理します。`2k > n - 1`。 

式では、`n - 1`そして`m - 1`縮小はグリッド線の間で発生するためです。 よくある間違いは、次のように使用することです。`n`直接的には、不可能な境界線の配置が過大評価されます。 

逆モジュロではフェルマーの小定理が使用されます。`10^9 + 7`プライムです。

import sys
import io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def build_factorials(limit):
        fact = [1] * (limit + 1)

        for i in range(1, limit + 1):
            fact[i] = fact[i - 1] * i % MOD

        inv_fact = [1] * (limit + 1)
        inv_fact[limit] = pow(fact[limit], MOD - 2, MOD)

        for i in range(limit, 0, -1):
            inv_fact[i - 1] = inv_fact[i] * i % MOD

        return fact, inv_fact

    def comb(n, r, fact, inv_fact):
        if r < 0 or r > n:
            return 0
        return fact[n] * inv_fact[r] % MOD * inv_fact[n - r] % MOD

    n, m, k = map(int, input().split())

    fact, inv_fact = build_factorials(max(n, m))

    ans = comb(n - 1, 2 * k, fact, inv_fact)
    ans *= comb(m - 1, 2 * k, fact, inv_fact)
    ans %= MOD

    return str(ans)

# provided sample
assert run("3 3 1\n") == "1", "sample 1"

# minimum possible input
assert run("1 1 1\n") == "0", "cannot place any inner rectangle"

# exactly enough space for one move
assert run("3 4 1\n") == "3", "single shrinking layer"

# impossible because too many moves
assert run("5 5 3\n") == "0", "not enough layers"

# symmetric medium case
assert run("5 5 1\n") == "36", "basic combinatorial count"

 ## 特殊なケース

 次のことを考慮してください。```
2 2 2
```必要なものは次のとおりです。```
2k = 4
n - 1 = 1
m - 1 = 1
```アルゴリズムは以下を計算します。```
C(1, 4) = 0
```両方の次元について、答えは次のようになります。`0`。 

これはジオメトリを正確に反映します。 1 回移動すると、もう 1 つの長方形が入る余地はなくなります。 

ここで次のことを考えてみましょう。```
3 3 1
```計算は次のようになります。```
C(2, 2) × C(2, 2) = 1
```合法的な配置は 1 つだけ、つまり中央セルです。 これにより、外側の境界線に接する長方形が組み合わせ解釈によって自動的に除外されることが確認されます。 

最後に、次のことを考慮してください。```
1000 1000 1
```答えは次のとおりです。```
C(999, 2)^2
```すべての二項係数は線形前処理後に一定時間で計算されるため、実装ではこれを効率的に処理します。
