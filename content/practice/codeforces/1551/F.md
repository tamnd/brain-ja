 ## 解決策
 ## 問題の理解

 このタスクは、選択された頂点のすべてのペアが等しく離れているように、ツリー内の頂点のサブセットを選択することです。 単に任意のノードを選択するのではなく、非常に厳密な幾何学的構成が必要です。サブセットを選択すると、すべてのペアごとの距離が単一の固定値に集約される必要があります。 

入力により複数のツリーが得られます。 各ツリーについて、この「すべてのペア間の等しい距離」特性を満たす正確に k 個の頂点を選択し、大きな素数を法とする結果を返す方法が何通りあるかを数えるよう求められます。 

制約は小さく、n は最大 100、テスト ケースは最大 10 個です。 これにより、すべてのテストにわたる対数因数トリックや高度なグローバル前処理などの高度な最適化の必要性が即座に排除されます。 数千万回の操作以内に収まる限り、テスト ケースごとの 3 次またはわずかに悪い組み合わせ DP であっても許容されます。 

重要な構造的制約が条件自体の中に隠されています。 k 個の頂点を選択し、すべてのペアごとの距離が等しい場合、セットはツリー メトリック内で非常に制限されます。 k が 2 より大きい場合、これにより、非常に特殊な「距離空間における星のような」構造が強制されます。 多くの素朴なアプローチは、任意のサブセットが機能すると仮定したり、等距離条件が隣接するペアだけでなくすべてのペアにわたってグローバルであることを忘れたりすることで失敗します。 

よくある誤った仮定は、ルートから同じ深さのノードを選択すれば十分であるというものです。 これだけでは十分ではありません。同じ深さにある 2 つのノードでも、最も低い共通の祖先がどこにあるかに応じて、ペアごとの距離が異なる可能性があるためです。 

たとえば、ライン ツリー 1-2-3-4 では、距離が 1,2,1 であるため、ノード {1,2,3} の選択は失敗します。 「構造化されている」ように見えても、ペアごとの距離は均一ではありません。 これは、深さが等しいことや対称性だけでは妥当性が保証されないことを示しています。 

もう 1 つの微妙なエッジ ケースは、k = 2 です。チェックする距離が 1 つだけであるため、ノードの任意のペアは自動的に条件を満たします。 多くのソリューションはこのケースを複雑にしすぎて、誤って有効なペアを除外してしまいます。 

## アプローチ

 直接的な総当たりアプローチでは、サイズ k のすべてのサブセットを試し、すべてのペアごとの距離が等しいかどうかを確認します。 O(n^k) 個のサブセットがあり、各チェックのコストは O(k^2) ですが、k が中程度の場合、n = 100 の場合でも完全に実行不可能になります。 k を約 10 に制限するだけでも、すでに膨大な検索スペースが生成されます。 

より構造化された観察は、条件を書き直すことで得られます。 選択したノード間のすべてのペアごとの距離が等しい場合、k ≥ 3 の場合、選択したすべてのノードが c から同じ距離 d にあり、ツリーのルートが c であるときに異なる枝に存在するような「中心」頂点 c が存在する必要があります。 選択された 2 つのノードが c の同じブランチ内にある場合、それらの距離は厳密に 2d より小さくなり、等価性が崩れます。 

これにより、問題は、考えられる各中心の周りの計数問題に変換されます。 固定中心 c と固定距離 d の場合、すべてのノードが c のどの隣接サブツリーに属するか、およびそのサブツリー内のノードが c から正確に距離 d の位置にいくつあるかによって分類します。 各サブツリーから 1 つのノードを選択するか、何も選択しませんが、正確に k 個の異なるサブツリーを選択し、寄与を乗算する必要があります。 

これは、ノードの子に対する古典的なサブセット DP になります。各「項目」は、深さ d のサブツリーに存在する有効なノードの数に等しい重みを与えます。 

k = 2 の場合、構造は縮退します。 一定の距離 c = d(u,v) が常に存在するため、ノードのすべてのペアは有効です。 したがって、答えは単純に n から 2 を選択します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(n^k · k^2) | O(k) | 遅すぎる |
 | サブツリー上の中心 + 深度 DP | O(n^3) | O(n) | 承認済み |

## アルゴリズムのチュートリアル

 解を特殊なケース k = 2 と一般的なケース k ≥ 3 に分割します。 

### 1. k = 2 を個別に処理します。 

k が 2 に等しい場合、順序のない頂点のペアはすべて有効であるため、答えは n(n−1)/2 になります。 これは不必要な計算を回避し、1 つの距離のみが関係する場合には構造的制約が現れないという事実を反映しています。 

### 2. 候補センターを修正する

 ツリー内の各頂点 c について、それを「メトリック スター」構成の潜在的な中心として扱います。 正しさは、k ≥ 3 の有効な構成には、選択されたすべてのノードを異なるブランチに分割する共通の祖先として機能する一意の頂点が必要であるという考えに依存しています。 

### 3. c からサブツリー距離構造を計算します。 

c の各近傍について、そのコンポーネント (c を除く) を探索し、c からの距離 d ごとにノードの数を計算します。 これは、各近隣から開始する DFS または BFS で行われ、c に対する相対的な距離を累積します。 

この時点で、各隣接サブツリー S および各深さ d に対して、c から距離 d にある S 内のノードを正確にカウントする値 a[S][d] を定義できます。 

### 4. 隣接サブツリー上にサブセット DP を構築する

 固定 c と固定深さ d の場合、正確に k 個の異なる隣接サブツリーを選択し、選択された各サブツリーから距離 d にあるノードを 1 つ選択したいとします。 

これは、多項式の x^k の係数を計算することと同じです。 

(1 + a[S1][d] x)(1 + a[S2][d] x) ... (1 + a[Sm][d] x)

 dp[j] がこれまでに j 個のサブツリーを選択する方法の数である DP 配列を維持します。 各サブツリー値 a について、dp を逆に更新します。 

dp[j] += dp[j−1] * a

 これにより、サブツリーのすべてのサブセットをカウントし、それらの寄与を正しく乗算することが保証されます。 

### 5. すべての中心と深度にわたって集約する

 中心 c と深さ d のすべての選択肢にわたる寄与を合計します。 それぞれの有効な構成は、その一意の中心 c が枝への分解を決定し、その距離 d が層を決定するため、正確に 1 回だけカウントされます。 

### なぜ効果があるのか

 k ≥ 3 の場合、有効な頂点セットは、選択したノード間のすべてのペアごとの最短パス上にある一意の頂点 c を持たなければなりません。 これにより、選択されたすべてのノードが c の異なる子サブツリーに配置され、そこから等距離に配置されます。 c と d が固定されると、サブツリー間の独立性によりカウントの乗算が可能になり、DP は重複することなくすべての有効なサブツリー選択を列挙します。 この構造に従わなければ、無効な構成は等しいペアごとの距離を満たすことができません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        line = input().strip()
        while line == "":
            line = input().strip()
        n, k = map(int, line.split())

        adj = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)

        if k == 2:
            print(n * (n - 1) // 2)
            continue

        # precompute distances from every node using BFS
        from collections import deque

        dist = [[-1] * n for _ in range(n)]
        for i in range(n):
            q = deque([i])
            dist[i][i] = 0
            while q:
                x = q.popleft()
                for y in adj[x]:
                    if dist[i][y] == -1:
                        dist[i][y] = dist[i][x] + 1
                        q.append(y)

        ans = 0

        # for each center
        for c in range(n):
            # build root-subtree id via first step from c
            comp_id = [-1] * n

            def dfs(u, p, cid):
                comp_id[u] = cid
                for v in adj[u]:
                    if v != p and v != c:
                        dfs(v, u, cid)

            cid = 0
            for v in adj[c]:
                dfs(v, c, cid)
                cid += 1

            # for each depth
            for d in range(1, n + 1):
                a = [0] * cid

                for v in range(n):
                    if dist[c][v] == d:
                        if c == v:
                            continue
                        if len(adj[c]) == 0:
                            continue
                        # find subtree id
                        # move one step from v toward c's neighbor subtree
                        u = v
                        prev = -1
                        while True:
                            if dist[c][u] == 1:
                                break
                            for w in adj[u]:
                                if dist[c][w] < dist[c][u]:
                                    prev = u
                                    u = w
                                    break
                        # u is neighbor of c
                        for i, nb in enumerate(adj[c]):
                            if nb == u:
                                a[i] += 1
                                break

                dp = [0] * (k + 1)
                dp[0] = 1
                for val in a:
                    for j in range(k, 0, -1):
                        dp[j] = (dp[j] + dp[j - 1] * val) % MOD

                ans = (ans + dp[k]) % MOD

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```コードは、ペアの組み合わせ単位を使用して、k = 2 の場合を直接処理することから始まります。 ロジックの残りの部分は、定数時間の距離クエリを可能にするためにすべてのペアの最短パスを構築し、可能な中心ごとに反復処理します。 

中心ごとに、ツリーは隣接ルートのコンポーネントに分解されます。 各距離レイヤー d について、その距離にある各コンポーネントに出現するノードの数をカウントし、ナップザック スタイルの DP を実行して、k 個のコンポーネントを選択する方法をカウントします。 DP は、独立したサブツリーからの寄与を正しく乗算することを保証します。 

実装上の微妙なリスクは、ノードのサブツリー ID を見つける際の非効率性です。 最適化されたソリューションでは、これはより明確に事前計算されますが、ここでは制約により、より単純な再構築が可能になります。

 ## 特殊なケース

 重要なエッジ ケースは k = 2 で、構造に関係なくすべてのペアをカウントする必要があります。 サブツリーベースの制約を強制しようとすると、有効なペアが誤って拒否されます。 

もう 1 つのエッジ ケースは、すべてのノードが中心に対して対称であるが、2 つのブランチのみに属している場合です。 その場合、たとえ深さが完全に一致していても、十分な個別のサブツリーを選択できないため、k ≥ 3 は不可能になります。 サブツリー上の DP カウントは k に達しないため、アルゴリズムはこれを自然に処理します。 

最後のエッジ ケースは線形チェーンです。この場合、多くのノードが異なる中心からの同様の深さを共有しているにもかかわらず、LCA 構造により、k ≥ 3 のペアごとの距離が等しくならず、DP は正確にゼロになります。
