 ## 解決策
 ## 問題の理解

 次の長方形グリッドが与えられます。$n$行と$m$ドミノを使用して完全にタイル化し、各ドミノが 2 つの隣接するセルを正確にカバーするようにする必要があります。 すべてのセルは正確に 1 つのドミノに属している必要があるため、グリッドは隣接するセルのペアに完全に分割されます。 

タイリング内のすべてのドミノの中で、まさに$k$は水平に配置する必要があります。つまり、左と右のセルを接続しますが、残りのドミノはすべて垂直で、上下のセルを接続します。 各ドミノは 2 つのセルをカバーするため、ドミノの総数は次のように固定されます。$\frac{nm}{2}$, したがって、垂直ドミノの数は強制的に次のようになります。$\frac{nm}{2} - k$。 

出力は単なる妥当性の決定ではありません。 また、同じドミノの両方のセルが文字を共有し、異なるドミノの隣接するセルが文字を共有しないように、各ドミノに文字を割り当てることによって表される明示的なタイリングを構築する必要もあります。 文字は Domino コンポーネントの単なる識別子であり、意味のある値ではありません。 

制約は小さく、両方の次元が最大 100、テスト ケースが最大 10 です。 これにより、サイズ 100 × 100 の単一グリッドでも天文学的な数のドミノ分解が発生するため、タイリングに対する指数関数的な検索やバックトラックが排除されます。 ソリューションはセル数が線形である必要があり、通常はグリッド上を数回通過するだけです。 

重要な構造上の制約はパリティです。ドミノ タイリングは常にセルをペアにしますが、水平配置と垂直配置ではグリッド ジオメトリとの相互作用が異なります。 これにより、タイルが存在するにもかかわらず、要求された数の水平ドミノを配置できない状況が発生します。 

微妙な失敗例は、行ごとまたは列ごとのパリティをチェックせずに行ごとに貪欲な水平配置を試みた場合に発生します。 たとえば、$2 \times 3$グリッド付き$k = 0$、すべてを垂直方向に埋めようとするかもしれませんが、各列の高さが奇数であるため、垂直方向のみのタイリングは不可能です。 グリッドの構造により純粋な垂直方向の分解が妨げられるため、正解は依然として「いいえ」です。 

奇数の寸法のグリッドでは、別の特殊なケースが発生します。 で$3 \times 3$グリッドでは、タイリングは制約された方法で方向を混合する必要があり、方向を盲目的に交互にすると、一致しないセルが強制的に残される可能性があります。 

## アプローチ

 素朴な試みは、これをグリッド グラフのマッチング問題として扱うことです。各セルが頂点であり、エッジが隣接するセルを接続します。 正確に完璧にマッチングしたい$k$水平エッジ。 ブルートフォース手法では、すべての完全な一致を列挙して水平エッジをカウントするか、隣接する空きセルのペアを再帰的に試行するバックトラッキングを実行することもあります。 一致する数は指数関数的に増加します$nm$、だからさえ$4 \times 4$グリッドはすでに探索するには多すぎる構成を生成しています。 

重要な点は、実際には一致を検索する必要がないということです。 必要な構造化タイルは 1 つだけであり、それを決定論的に自由に構築できます。 グリッドは 2 部構成であるため、次の固定パターンで並べて表示できます。$2 \times 2$ブロックまたは行ごとのペアを作成し、ブロック内の方向をローカルに調整して、作成する水平ドミノの数を制御します。 

特に役立つ視点は、グリッドを行の垂直ペアにグループ化することです。 行の各ペア内では、行間または行内でセルをどのようにペアにするかに応じて、各列が垂直ドミノまたは水平ドミノのいずれかになります。 これにより、グローバル制約が行ペアごとの水平エッジのバジェットに変換されます。 

この構造は、隣接する行のペアごとに、そのストリップ内に水平のドミノを何個配置するかを決定し、すべてのストリップの合計が等しくなるようにすることになります。$k$。 各ストリップは、最大で偶数個の水平ドミノを独立して実現できます。$m$、これらのストリップを縫い合わせます。 

これにより、問題は配布に変わります$k$独立したブロック全体に渡って、その後各ブロックが決定的な交互パターンで埋められます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. まず、グリッドを行ペアに縮小することで構築が可能かどうかを確認します。 もし$n$が奇数である場合、最後の行は慎重に処理する必要があり、その場合、列内の垂直ドミノのみが可能です。 これにより、水平ドミノはその行に収まらないため、その行に存在できる水平ドミノの数が即座に制限されます。 
2. グリッドを一度に 2 行ずつ作成します。 連続する行の各ペアは、高さ 2、幅 2 の水平ストリップとして扱われます。$m$。 このようなストリップ内では、配置を自由に決めることができます。 
3. ストリップごとに、水平方向のドミノをいくつ配置するかを決定します。 まで貪欲に割り当てます$m$ストリップごとに水平ドミノを配置しますが、残りを超えないようにします。$k$。 
4. 選択したストリップ内に、互いに素な列のペアに水平ドミノを配置します。 たとえば、列$0-1$、$2-3$このような各ペアは 1 つの水平ドミノを消費し、一意の文字が割り当てられます。 
5. 水平方向の配置に使用されないストリップ内の残りの列は、ストリップ内で垂直方向に埋められ、上部と下部のセルがペアになります。 
6. 列の数が奇数の場合、ストリップの最後の列は水平のドミノを形成できないため、垂直でなければなりません。 
7. すべてのストリップが処理されるまで繰り返します。 最後に、正確に使用していない場合は、$k$水平ドミノの場合、その構築は無効です。 

### なぜ効果があるのか

 それぞれ$2 \times m$ストリップはタイリング構造の点で独立しています。1 つのストリップ内の水平ドミノが他のストリップに干渉することはありません。 ストリップ内で列を水平または垂直にペアにすると、常に有効な完全一致が生成されます。 すべてのセルは正確に 1 つのストリップに属し、各ストリップは完全にタイル化されているため、グローバル タイリングは有効です。 この構造により、水平方向のドミノ カウントがストリップごとに正確に制御されるため、合計制約が競合することなく満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())

        grid = [[''] * m for _ in range(n)]
        used = 0
        cur = ord('a')

        ok = True

        for i in range(0, n, 2):
            if i + 1 >= n:
                # last single row: only vertical dominos possible
                if k != 0:
                    ok = False
                    break
                for j in range(0, m, 2):
                    if j + 1 >= m:
                        ok = False
                        break
                    c = chr(cur)
                    grid[i][j] = c
                    grid[i][j + 1] = c
                    cur += 1
                continue

            # we have a 2-row strip: i and i+1
            for j in range(m):
                if k == 0:
                    break

                if j + 1 < m and k > 0:
                    # try horizontal domino inside strip
                    c = chr(cur)
                    grid[i][j] = c
                    grid[i][j + 1] = c
                    used += 1
                    k -= 1
                    cur += 1
                else:
                    break

            # fill remaining cells in this strip vertically
            for j in range(m):
                if grid[i][j] == '':
                    if i + 1 >= n:
                        ok = False
                        break
                    c = chr(cur)
                    grid[i][j] = c
                    grid[i + 1][j] = c
                    cur += 1

        if not ok or k != 0:
            print("NO")
        else:
            print("YES")
            for row in grid:
                print(''.join(row))

if __name__ == "__main__":
    solve()
```このコードは、増加する文字を使用してドミノ ID を割り当てます。 各配置は、行ペア内に水平ペアを割り当てるか、列を垂直に埋めます。 変数`k`水平ドミノを明示的に配置した場合にのみ消費され、必要な数を正確に制御できます。 

微妙な点は、奇数の高さのグリッドの最後の行では水平方向の配置を決して許可しないことです。その行は水平方向のドミノをサポートできないためです。 この制約は、行ペアのループ構造によって暗黙的に強制されます。

 ## 特殊なケース

 主なエッジケースは次のような場合です$n$奇数です。 この状況では、最後の行にはパートナーがいないため、その行のすべてのセルが垂直ドミノの一部である必要があります。 アルゴリズムは、最後の行に水平方向に配置することを決して試行せず、可能であれば下方向にのみペアにすることでこれを処理します。 それ以外の場合、構造が完全なカバレッジを許可しない場合、構成は拒否されます。 

もう 1 つのエッジケースは次のような場合です$m$の中は奇数です$2 \times m$ストリップ。 最後の列は水平ドミノの一部にはできないため、垂直方向にペアにする必要があります。 この構造では、垂直方向の割り当てのために自然に残しておき、無効なハーフ ドミノが残らないようにします。 

さらにエッジケースが現れるのは、$k = 0$。 このアルゴリズムは、水平方向の配置をすべてスキップし、すべての列を垂直方向に直接埋めて、きれいな列方向のタイリングを生成します。 これにより、スキップ条件を超える特別なケースを必要とせずに、構築が純粋な垂直マッチングに正しく縮退していることが確認されます。
