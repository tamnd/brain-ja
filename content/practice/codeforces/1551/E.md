 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、そこから要素を繰り返し削除できます。 削除するたびに配列が圧縮されるため、インデックスは常に連続した状態になります。 すべての削除の後、値がインデックスと一致する位置を調べます。これは、最終的な配列にできるだけ多くの「固定点」が必要であることを意味します。 

目標は固定点を最大化することではなく、少なくとも達成することです`k`削除する要素の数を最小限に抑えながら。 

重要な点は、要素を削除するとすべてのインデックスが右に変更されることです。 したがって、要素が固定点になるかどうかは、その値だけでなく、その前に発生する削除の数にも依存します。 

制約は、テスト ケースごとの 2 次または 2 次に近い解を得るのに十分な小ささです。 それぞれのテストには、`n ≤ 2000`、合計`n`テスト全体でも ≤ 2000 です。これは、`O(n^2)`または`O(n^2 log n)`ソリューションは許容されますが、テストごとに 3 次のものは不要です。 

インデックスのシフトを考慮せずに削除を貪欲にシミュレートしようとすると、すぐに単純な落とし穴が現れます。 たとえば、要素を削除すると、その後の位置がすべて変更されるため、元のインデックスに対して固定点をチェックすることは無効になります。 

もう 1 つの微妙なエッジケースは、答えが不可能な場合です。 たとえば、すべての値がインデックスに比べて非常に大きい場合、削除後でも十分な値を位置に揃えることができない可能性があります。 小さな例としては、`a = [5, 5, 5]`、`k = 2`。 どのように削除しても、値とインデックスが等しい十分な位置を作成できません。 

## アプローチ

 強引な解釈では、保持する要素のすべてのサブセットを試し、結果の配列をシミュレートし、固定小数点をカウントします。 これは明らかに指数関数的です。`2^n`サブセットであり、枝刈りしても大きすぎるため、`n = 2000`。 

欠失シーケンスが実際に何を行うのかについて、より構造化されたビューが必要です。 

削除について考える代わりに、視点を反転してください。残っている部分列を選択しているのです。 要素を位置に保持するとします`i1 < i2 < ... < im`。 最終的な配列では、これらは位置になります。`1..m`。 元のインデックスに保持された要素`i`その値が保持された要素内の新しい位置と等しい場合、 は固定小数点になります。 

したがって、位置に保持された要素の場合`i_j`、次の場合に固定小数点に寄与します。`a[i_j] = j`。 

これにより、問題は、インデックスの数を最大化するサブシーケンスを選択することになります。`j`満足する`a[i_j] = j`。 しかしインデックスは`j`その前に保持していた要素の数によって異なります。 

より有用な変換は、各候補固定点の前の削除の観点から考えることです。 何らかの地位が欲しいと仮定します`i`最終的な配列の固定点になります。 維持すれば`a[i]`、その場合、その最終的な位置は次のようになります。`i - deletions_before_i`。 これを修正するには、次のものが必要です。`a[i] = i - deletions_before_i`、 それで`deletions_before_i = i - a[i]`。 

これは各インデックスを意味します`i`要件を課します: 正確に削除する必要があります`i - a[i]`要素を固定点として選択する前に。 また、この値は負ではない必要があります。そうでない場合、それを固定点にすることは不可能です。 

ここで問題は少なくとも選択することになります`k`それぞれのインデックスには、これらの要件が順番に一貫しているように、必要な「その前の削除バジェット」が含まれています。 インデックスの昇順で固定点を選択する場合、必要な削除は互換性のある方法で非減少でなければなりません。 

これをインデックス上の DP としてモデル化できます。各ポジションについて、既に形成した固定点の数と効果的に使用した削除の数を追跡しながら、それを固定点として選択するかスキップするかを検討します。 

よりクリーンな最適化が実現します。要素ごとに、修正するためにその前に何回削除が必要かという観点から「コスト」を計算します。 次に、少なくとも選択しようとします`k`これらのコストを順番に満たせるように、要素をインデックスの昇順で並べます。 この問題は、実現可能性の制約を伴うサブシーケンスの選択に帰着しますが、これは当然 DP で処理されます。 

私たちは定義します`dp[i][j]`プレフィックスで使用される最小削除数として`i`入手する`j`固定点。 からの移行`i-1`に`i`、スキップするか、`i`(削除する場合は削除数を 1 つ増やします)、または現在の削除を考慮して実現可能であれば、固定点として保持します。 

重要な洞察は、実現可能性は現在の削除数が以下に等しいかどうかによってのみ決まるということです。`i - a[i]`私たちがそれを取ることを決めたとき。 

このDPは`O(n^2)`テストごとに。

 | 最適なDP | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. インデックスごとに`i`、要件を計算します`need[i] = i - a[i]`。 もし`need[i] < 0`, この位置は決して固定点になり得ないので、候補として無視します。 
2. 動的プログラミング テーブルを構築します。`dp[j]`正確に達成するために必要な最小の削除数を表します。`j`これまでの固定点。 
3.初期化`dp[0] = 0`他のすべての状態は無限大です。 固定点がない場合、削除は必要ありません。 
4. インデックスを左から右に繰り返します。 各インデックスで 2 つの選択肢を検討します。 
5. 最初の選択肢は要素をスキップすることです。 これは削除に相当し、すべての状態で削除カウントが 1 ずつ増加します。 これは、要素の削除が将来のインデックスに影響することをモデル化します。 
6. 2 番目の選択肢は、要素を固定点として取得することです。 これは、現在の削除数が必要な数と一致する場合にのみ有効です。`need[i]`。 一致する場合は更新します`dp[j+1]`を使用して`dp[j]`必要な削除がすでに考慮されているため、余分な削除を追加する必要はありません。 
7. すべての要素を処理した後、`j ≥ k`そのような`dp[j]`有限です。 答えは、これらのうちの最小の削除です。 

### なぜ効果があるのか

 各固定点は、元のインデックス、最終位置、およびその前の削除の数の間に厳密な位置合わせ条件を課します。 DP では、要素を固定点として選択するときは常に、プレフィックスの削除がその要素に必要なものと正確に一致する必要があります。 先に進むにつれて削除は単調に増加し、インデックスのみを前方に遷移するため、DP は選択されたすべての固定点間の一貫性を維持します。 不一致の削除はブロック遷移をカウントするため、無効な順序は除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**9

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    # dp[j] = minimum deletions to get j fixed points so far
    dp = [INF] * (n + 1)
    dp[0] = 0

    for i in range(n):
        ndp = [INF] * (n + 1)

        need = i + 1 - a[i]  # 1-based index logic

        for j in range(n):
            if dp[j] == INF:
                continue

            # option 1: skip i (delete it)
            ndp[j] = min(ndp[j], dp[j] + 1)

            # option 2: take as fixed point if feasible
            if need >= 0 and dp[j] == need:
                ndp[j + 1] = min(ndp[j + 1], dp[j])

        dp = ndp

    ans = min(dp[k:])
    print(-1 if ans == INF else ans)

t = int(input())
for _ in range(t):
    solve()
```DP 配列は、異なる選択による状態の混合を避けるために、インデックスごとに再構築されます。 条件`dp[j] == need`以前の削除を考慮した後、固定小数点が有効になるために必要な正確な位置合わせ制約をエンコードします。 

微妙な実装ポイントは、`i + 1 - a[i]`の代わりに`i - a[i]`Python では 0 から始まるインデックスが使用されますが、条件は当然 1 から始まります。 

2 番目の微妙な点は、要素をスキップすると削除数が常に増加するため、後の要素がその位置に移動できることです。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`a[i]`その位置に対して大きすぎます。 例えば`i=2, a[i]=5`与える`need < 0`したがって、その要素が固定されることはあり得ません。 条件が次のとおりであるため、アルゴリズムは当然これを無視します。`need >= 0`失敗します。 

もう 1 つのエッジ ケースは、すべての要素がすでに満たされている場合です。`a[i] = i`。 その場合`need = 0`どこにでも存在するため、すべての要素は削除を必要とせずに有効な固定点になります。 DP はあらゆるものを取得することを許可します`k`コストゼロで答えを生み出す`0`。 

最後のエッジケースは次のような場合です`k = 1`。 このアルゴリズムは、制約を満たす単一のインデックスを正確に見つけ出し、1 つの要素を整列させるために必要な最小限の削除を返します。これは、構造に応じてゼロまたは小さなシフト コストのいずれかです。
