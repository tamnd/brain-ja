 ## 解決策
 ## 問題の理解

 ラテン文字の小文字で構成される文字列が与えられます。 位置のいくつかを選択し、選択した各位置に 2 つの色 (赤または緑) のいずれかを 3 つのルールで割り当てたいと考えています。 

まず、選択したすべての位置に 1 つの色が適用されますが、一部の位置はペイントされないままになる場合があります。 第 2 に、各色内で、選択されたすべての文字はペアごとに区別できる必要があるため、赤で 2 回表示される文字や、緑で 2 回表示される文字は存在できません。 第三に、赤色の位置の数は緑色の位置の数と等しくなければなりません。 最後に、これを行うためのすべての有効な方法の中で、ペイントされる位置の数を最大化する必要があります。タスクは、その最適な配置で赤色の位置の数を出力することです。 

赤と緑のサイズは等しいため、ペイントされた文字を最大化することは、その値を 2 倍最大化することと同等であるため、実質的に、異なる文字の 2 つの素なセット間で可能な最大のバランスのとれた組み合わせを探すことになります。 

文字列の長さは最大 50 で、テスト ケースは最大 1000 個あります。そのため、文字列構造に対するすべてのサブセットまたは代入を直接試行するソリューションは、組み合わせ推論を超えている場合、すでに危険です。 ただし、アルファベットのサイズは 26 文字のみであり、これが重要な構造上の制限です。 

素朴な解釈では、出現する文字をそれぞれ独立して割り当てようとするかもしれませんが、それはすぐに「色ごとに区別する」ルールを破ることになります。 別の素朴なアプローチでは、位置と色のすべてのサブセットを試す可能性がありますが、それは大まかに爆発的に増加します。$3^n$、たとえ$n = 50$。 

微妙な特殊なケースは、文字が何度も出現する場合です。 たとえば、`"xxxxxx"`、複数使用することはできません`'x'`1 つは赤、もう 1 つは緑なので、全体の多重度は役に立ちません。 もう 1 つのエッジ ケースは、次のような異なる文字の文字列です。`"abcdef"`、すべてのキャラクターが使用可能ですが、バランスにより均等に分割する必要があるため、最大でも半分しか使用できません。 

本当の制約は位置ではなく、個別の文字です。 

## アプローチ

 この問題を考える強引な方法は、各位置に 3 つの状態 (赤、緑、未使用) のいずれかを割り当ててから、妥当性をチェックすることです。 割り当てごとに、各カラー クラスに重複する文字が含まれていないこと、およびサイズが一致していることを確認します。 これは探索します$3^n$州、そしてさらには$n = 50$、それは実現可能性をはるかに超えています。$10^{23}$構成。 

解決策を解く構造は、立場の観点から考えるのをやめ、代わりに個別のキャラクターの観点から考えることです。 各文字は、何度出現しても、使用可能な赤色スロットと使用可能な緑色スロットを最大 1 つずつ提供します。 したがって、すべての文字を、色ごとに 1 つずつ、0、1、または 2 つの使用可能な割り当ての容量に圧縮できます。 

文字が少なくとも 2 回出現する場合、両方の色をサポートできます。 一度出現すると、1 つの色のみをサポートできます。 赤の文字のセットを選択する場合、緑の同じサイズの素のセットを選択する必要があります。 したがって、私たちができる最善の方法は、できるだけ多くの異なる文字を選択し、それらを 2 つの等しい半分に分割することです。 制限要因は、少なくとも 1 回出現する文字の数、つまり個別の文字のセットのサイズになります。 

させて$d$文字列内の個別の文字の数になります。 文字ごと、色ごとに最大 1 つのオカレンスを割り当てることができるため、最大でも使用できます。$d$各色の文字を全体的に組み合わせたもの。 色は同じサイズでなければならないため、できる限りのことはそれらをペアにして、最大値を与えることです。$\lfloor d/2 \rfloor$赤い文字。 

これは直感とも一致します。私たちは基本的に異なる文字のペアを形成しており、各ペアは赤と緑に 1 つずつ寄与します。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースの文字列を読み取り、その中に出現する個別の文字のセットを計算します。 このステップでは、使用可能なすべての「リソース」がキャプチャされます。これは、各色の固有性の制約により、文字を繰り返しても柔軟性が向上しないためです。 
2. しましょう$d$個別の文字の数になります。 ここで、これらの文字から形成できる色のペアが何組あるかを推論します。 
3. コンピューティング$k = d // 2$。 これは、利用可能な個別の文字から可能な限り多くの素の赤と緑のペアを形成することを表します。 
4. 出力$k$テストケースの答えとして。 

重要な推論手順は、すべての赤色の文字は異なる緑色の文字と一致する必要があり、同じ色内で文字を再利用できないということです。 したがって、有効な貢献単位ごとに 2 つの異なる文字が消費されます。 

### なぜ効果があるのか

 このアルゴリズムは、ペイントされたすべての文字が一意の文字と色のペアに対応し、各文字が色ごとに最大 1 つのそのようなペアに寄与できるという不変条件に依存しています。 しかないので、$d$明確な文字しか作成できません$d$両方の色にわたる使用可能な割り当ての合計。 色のバランスが取れている必要があるため、有効な各ソリューションでは、単位寄与ごとに 2 つの異なる文字 (赤と緑) が消費されます。 それを超えようとするあらゆる試み$d//2$色の文字を再利用するか、使用可能な個別のアルファベットを超える必要があり、どちらも制約に違反します。 したがって、計算された値は達成可能であり、最大値でもあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    d = len(set(s))
    print(d // 2)
```このソリューションは、各テスト ケースを文字セットの計算に削減します。 の`set(s)`この操作は重複を自動的に削除し、文字の繰り返しによって追加の使用可能な容量が提供されないという制約を直接モデル化します。 

2 による除算は、赤と緑のカウントが等しくなければならないという要件を反映しているため、使用可能なすべての単位は 2 つの異なる文字を消費します。 

微妙な点は、周波数を追跡する必要がないということです。 たとえキャラクターが 10 回出現したとしても、それは依然として 1 つの可能な赤スロットと 1 つの緑スロットのみを提供します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = []
    t = int(input())
    for _ in range(t):
        s = input().strip()
        out.append(str(len(set(s)) // 2))
    return "\n".join(out)

 ## 特殊なケース

 次のような単一文字列の場合`"a"`、個別のセットのサイズは 1 であるため、アルゴリズムは次のように計算します。$1 // 2 = 0$。 これは、赤と緑を区別したまま、両方に 1 つの文字を割り当てることはできないという事実と一致します。 

次のような完全に繰り返される文字列の場合`"xxxxxx"`、個別のセットは`{x}`、再び与えます$k = 0$。 多くの位置が存在する場合でも、各色の内部の一意性制約により、すべての位置が単一の使用可能な要素に折りたたまれ、バランスにより割り当てができなくなります。 

次のようなすべての異なる文字の文字列の場合、`"abcdef"`、セットのサイズは 6 で、次の結果が得られます。$k = 3$。 文字を 3 つずつ 2 つのグループに明示的に分割し、各グループが異なる文字を持ち、すべての制約を正確に満たすことができます。
