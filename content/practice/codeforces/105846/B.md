 ## 解決策
 ## 問題の理解

 左から右に開かなければならないドアが並んでいます。 ドア`i`コストと報酬があります。 通常ドアを開けるには、少なくともそのコストをコインで持っている必要があり、その後コストを支払い、報酬を受け取ります。 ドアは、前のすべてのドアが開いた後にのみ開くことができます。 

開始する前に、いくつかのドアを選択し、そのロックを解除することがあります。 ロックを削除するとドアは自由に開くことができますが、削除されたロックは 1 回の操作としてカウントされます。 目標は、できるだけ少ない操作ですべてのドアに到達できるようにすることです。 

入力により、いくつかのテスト ケースが得られます。 各テスト ケースには、ドアの数、コインの初期数、各ドアのコスト、および各ドアから受け取った報酬が含まれています。 出力は、ロックを取り外す必要があるドアの最小数です。 

制約は動的プログラミングを可能にするのに十分小さいものです。 ドアの数は最大 100 で、すべてのコインの値も最大 100 です。ドアを開けるたびにコインの数が最大 100 増加するため、すべてのドアを開いた後のコインの最大数は約 100 です。`100 + 100 * 100 = 10100`。 これは、現在のコイン数に基づいた状態空間が実現可能であることを意味します。 取り外されたドアの可能なすべてのサブセットを試すソリューションには、次のものが必要です。`2^n`選択肢は多すぎます`n = 100`。 

厄介なケースは、ロックの解除がドアが開かない場合にだけ役立つわけではないという事実から生じます。 現在手頃な価格のドアでも、コストを節約することで後で利用できるコインの数が増えるため、無料にする価値がある可能性があります。 

例えば：```
Input
3 10
5 9 9
1 2 9
```正しい出力は次のとおりです。```
2
```コインは10枚あれば十分なので、欲張れば最初の扉が普通に開くかもしれません。 それを開いた後、`10 - 5 + 1 = 6`コインが入ってしまい、2番目のドアを開けることができません。 2 番目のドアを取り外す必要がありますが、その後でも 3 番目のドアを取り付ける余裕はありません。 最初のドアも外す必要があります。 間違いは、手頃な価格のドアが常に通常どおりに開かれるべきであると想定していることです。 

もう 1 つの境界ケースは、操作が必要ない場合です。```
Input
1 1
1
1
```答えは次のとおりです。```
0
```唯一のドアはすぐに開くことができるため、少なくとも 1 つのロックを強制的に解除するア​​プローチは間違っています。 

## アプローチ

 直接的な力ずくのアプローチは、可能なすべてのドアのセットを削除しようとすることです。 サブセットごとに、最初のドアから最後のドアまでのプロセスをシミュレートします。 ドアがロックされている場合は、コインが十分にあるかどうかを確認します。 そうでない場合、選択したサブセットは失敗します。 それ以外の場合は、継続してコイン数を更新します。 成功したすべてのサブセットの中で、最小のサイズを採用します。 

取り外されたドアのあらゆる選択肢が検討されるため、これは正しいです。 問題はサブセットの数です。 と`n = 100`、 がある`2^100`可能な選択肢は、処理できる範囲をはるかに超えています。 

有益な観察は、どのドアが取り外されたかを正確に記憶する必要がないということです。 未来は 2 つのことだけで決まります。どのドアを開けようとしているのか、そして現在持っているコインの数です。 2 つの異なる方法で同じ枚数のコインを使って同じドアに到達した場合、より少ない操作でより良い状態が常に得られます。 これにより、多くの可能性を単一の動的プログラミング状態にマージできます。 

各ドアには 2 つのトランジションがあります。 ロックを解除し、コインを支払わずに報酬を獲得し、操作を 1 つ追加することができます。 または、現在のコインが十分な場合に限り、ロックを維持することもできます。 私たちはコストを支払い、報酬を獲得し、同じ回数の操作を維持します。 

コインの範囲はおよそ 10100 で制限されており、テスト ケースごとに約 100 万の状態が与えられるため、状態数は管理可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | お(1) | 遅すぎる |
 | 最適 | O(n * n * 最大コイン) | O(最大コイン) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 動的プログラミング配列を作成します。`dp[c]`処理されたドアのプレフィックスを開いて正確に終了した後に必要な、削除されるロックの最小数を表します。`c`コイン。 

値`c`過去について必要なすべてを説明します。 現在のコイン数が判明すると、以前の選択の順序は重要ではなくなります。 

1. ドアを開ける前に状態を初期化します。 コインの開始量があり、ロックがゼロであるため、初期状態は次のようになります。`dp[starting_coins] = 0`。 
2. ドアを左から右に加工します。 考えられる現在のコインの量ごとに、現在のドアのロックを外してみてください。 

コインは使用されないため、新しいコインの量は、現在のコインにこのドアの報酬を加えたものになります。 操作回数が 1 回増加します。 

1. 同じドアについて、現在のコインがドアのコスト以上であれば、ロックを維持してみます。 

移行によりコストが減算され、報酬が追加されます。 操作回数は変わりません。 

1. すべてのドアを処理した後、答えは到達可能なすべてのコイン状態の最小値になります。 

最終的なコインの量は多数考えられます。 それらの中で最も少ない数の操作のみを考慮します。 

なぜ効果があるのか:

 不変条件は、ドアのプレフィックスを処理した後、到達可能なすべてのコイン金額が、その金額に到達するために必要な削除されたロックの最小数とともに保存されるということです。 2 つの遷移は、隣のドアのロックを解除するか、ロックを保持したまま通常どおり支払うかの、考えられるすべての決定をカバーします。 すべての有効な一連の決定が表現され、同一の状態のより悪いバージョンは破棄されるため、最終的な最小値がまさに最適な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    INF = 10**9
    MAX_C = 10100

    for _ in range(t):
        n, x = map(int, input().split())
        c = list(map(int, input().split()))
        a = list(map(int, input().split()))

        dp = [INF] * (MAX_C + 1)
        dp[x] = 0

        for i in range(n):
            ndp = [INF] * (MAX_C + 1)

            for coins in range(MAX_C + 1):
                if dp[coins] == INF:
                    continue

                free_coins = coins + a[i]
                if free_coins <= MAX_C:
                    if dp[coins] + 1 < ndp[free_coins]:
                        ndp[free_coins] = dp[coins] + 1

                if coins >= c[i]:
                    normal_coins = coins - c[i] + a[i]
                    if normal_coins <= MAX_C:
                        if dp[coins] < ndp[normal_coins]:
                            ndp[normal_coins] = dp[coins]

            dp = ndp

        out.append(str(min(dp)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```配列`dp`可能なすべてのコイン量に対する現在の最良の回答を保存します。 初期状態では、開始量にゼロの操作が配置されます。 

すべての遷移では現在のドアを開く前の状態を使用する必要があるため、ドアごとに新しい配列が作成されます。 同じ配列を再利用すると、1 回の反復で同じドアを複数回開くことができます。 

最初の遷移はロックの解除に対応します。 削除されたロックにはコインが必要ないため、常に存在します。 2 番目の遷移は通常のオープンに対応し、十分なコインが利用可能な場合にのみ許可されます。 

可能な最大の開始値は 100 であり、100 のドアごとに最大 100 枚のコインを追加できるため、コインの最大値は固定されています。 この固定境界を使用すると、不必要なメモリ オーバーヘッドが回避され、実装が単純になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * 最大コイン) | 各ドアは、可能なすべてのコイン量を 1 回処理します。 
| スペース | O(最大コイン) | 現在と次の DP 配列のみが保存されます。 

最大コイン値は約 10,100 であるため、テスト ケースあたりの遷移の総数は約 100 万回になります。 これは制限内に簡単に収まります。 

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline

    t = int(data())
    ans = []
    INF = 10**9
    MAX_C = 10100

    for _ in range(t):
        n, x = map(int, data().split())
        c = list(map(int, data().split()))
        a = list(map(int, data().split()))

        dp = [INF] * (MAX_C + 1)
        dp[x] = 0

        for i in range(n):
            ndp = [INF] * (MAX_C + 1)
            for coins in range(MAX_C + 1):
                if dp[coins] == INF:
                    continue

                if coins + a[i] <= MAX_C:
                    ndp[coins + a[i]] = min(ndp[coins + a[i]], dp[coins] + 1)

                if coins >= c[i]:
                    ndp[coins - c[i] + a[i]] = min(ndp[coins - c[i] + a[i]], dp[coins])

            dp = ndp

        ans.append(str(min(dp)))

    sys.stdin = old
    return "\n".join(ans)
