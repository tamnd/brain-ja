 ## 解決策
 ## 問題の理解

 私たちは、$n \times n$グリッド。各セルには 1、2、または 3 のいずれかの数値が含まれている必要があります。グリッドは、すべての行のビットごとの XOR が 0 に等しく、すべての列の XOR が 0 に等しい場合にのみ有効とみなされます。 このようなすべての有効なグリッドの中で、すべてのエントリの合計ができるだけ大きい構成だけをカウントするように求められます。 

重要な点は、制約がセルごとに独立していないということです。 1 つの位置の選択は、行と列の両方の XOR 条件に影響を与えるため、グリッドは、厳密に結合されたシステムのように動作します。$n^2$独立した選択。 

制約$n \le 10^6$まで$10^4$テスト ケースは、少量の前処理または直接の数式評価の後、テスト ケースごとの解は基本的に一定時間でなければならないことを意味します。 グリッドを構築またはシミュレートしようとするアプローチは直ちに実行不可能です。$O(n^2)$限界をはるかに超えています。 

微妙な問題が現れるのは、$n$小さいです。 たとえば、次のようなとき$n = 1$、グリッドには単一のセルがあります。 そのセルは、行と列の両方で XOR ゼロを同時に満たしながら、グローバル制約構造の下で意味のある方法で合計を最大化することができず、このエッジ ケースは、より大きなセルとは異なる動作をします。$n$。 

のために$n = 2$有効な構成は 1 つだけです。つまり、すべてを 3 つで満たすことで、XOR 制約を維持しながら合計が増加する他の構成はありません。 これは、小さなケースは独自の構造に崩壊する可能性がある一方、より大きな奇数サイズでは追加の自由度が導入されることを示しています。 

よりデリケートな失敗例は、すべてを 3 で貪欲に埋めて、XOR の不一致をローカルで修正しようとした場合に発生します。 たとえば、$3 \times 3$グリッドでは、変更が行列全体に伝播するため、単一の行を修正しようとすると、ローカル修復戦略を使用しないと列の制約が破られる可能性があります。 

## アプローチ

 ブルートフォース手法では、すべての値の割り当てが試行されます。$\{1,2,3\}$すべてのセルに入力し、行と列の XOR 制約をチェックして合計を計算します。 これは探索します$3^{n^2}$可能性は爆発的に広がります$n=3$、すでに完全に非現実的になっています。 

もう少し素朴なアプローチでは、行ごとに制約を適用しようとします。 各行について、有効な XOR ゼロ シーケンスを列挙し、列の一貫性をチェックしながらそれらを結合することができます。 これにより、冗長性がいくらか軽減されますが、列の制約は複数の行が選択された後にのみ明確になるため、部分状態の指数関数的な数が依然として発生します。 

重要な単純化は、行列を行と列を同時に対象とした XOR 制約のシステムとして見ることで実現します。 任意の値で考えるよりも、すべてを 3 で満たされた均一な行列と比較する方が便利です。 

すべてのセルが 3 の場合、各行の XOR はパリティのみに依存します。$n$。 いつ$n$が偶数である場合、各行の XOR はすでに 0 であり、同じことが列にも当てはまります。 これは、3 が最大許容値であるため、すべて 3 の行列が有効であり、合計が自動的に最大化されることを意味します。 この場合、柔軟性は残されていません。 

いつ$n$が奇数である場合、すべて 3 の行列は構造化された方法で XOR 制約に違反します。つまり、すべての行と列の XOR が 0 ではなく 3 になります。この欠陥は一様であり、これを修正するには、両方の次元で XOR 値を同時に反転する制御された変更を導入する必要があります。 

問題を最小の偏差を使用して均一な XOR 欠陥を修正するものとして再構成すると、その構造は、個々のセル値を個別に選択するのではなく、行と列に修正パターンを割り当てることと同等になります。 これにより、問題は、小さな結合制約を持つ独立した XOR 割り当ての有効な構成をカウントすることに軽減されます。

 ## アルゴリズムのチュートリアル

 1. かどうかを確認します。$n = 1$。 この場合、合計を最大化しながら制約を満たす有効な方法がないため、答えはゼロになります。 
2. もし$n$が偶数の場合、すべてのセルを 3 で埋めると、すべての行と列の XOR がすでに 0 になることがわかります。 3 を超える値はないため、この構成が最適です。 有効な最適行列の数は単一の構成に集約されます。 
3. もし$n$が奇数の場合は、すべて 3 の行列から開始します。 すべての行と列の XOR が 0 ではなく 3 になり、均一な不一致が生じます。 
4. セルを任意に変更するのではなく、各変更を行と列の両方で XOR 寄与を反転する修正として解釈します。 各セルの選択は、2 つの独立した XOR システム (行用と列用) にどのように寄与するかを選択するものとみなすことができます。 
5. 構造を独立した行および列の補正構造に分解します。 それらの間の相互作用は自由を生み出します$(n-1) \times (n-1)$自由度グリッドは、残りの構造が XOR 一貫性条件によって決定されます。 
6. この空きサブグリッド全体に独立したバイナリのような補正パターンを割り当てる方法の数を数えます。 それぞれの有効な割り当ては、正確に 1 つの最大和行列に対応します。 
7. 構造的自由度を一定数のグローバル補正選択肢と組み合わせて、奇数の閉じた形式のカウントを生成します。$n$。 

### なぜ効果があるのか

 重要な不変条件は、XOR 制約がフィールド全体にわたって線形であることです。$\mathbb{F}_2$, そのため、行と列の条件はビットに関する一次方程式系として扱うことができます。 マトリックス制約により、次の自由度が減少します。$n^2$セルを、独立した行と列の制約のみに依存する次元を持つ部分空間に変換します。 合計を最大化すると、ほぼすべてのエントリが 3 のままになるため、すべての有効なソリューションは、基本構成の XOR を保持する摂動を最小限に抑えることによってのみ異なります。 これにより、計数問題が行列の列挙ではなく、線形システムの計数解に変わります。

import sys
input = sys.stdin.readline

MOD = 998244353

def modpow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

t = int(input())
for _ in range(t):
    n = int(input())
    
    if n == 1:
        print(0)
        continue

    exp = (n - 1) * (n - 2)
    base = modpow(2, exp)

    if n % 2 == 0:
        print(base % MOD)
    else:
        print((3 * base) % MOD)

## テストケース```python
import sys, io

MOD = 998244353

def modpow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        if n == 1:
            out.append("0")
        else:
            exp = (n - 1) * (n - 2)
            base = modpow(2, exp)
            if n % 2 == 0:
                out.append(str(base % MOD))
            else:
                out.append(str((3 * base) % MOD))
    return "\n".join(out)
