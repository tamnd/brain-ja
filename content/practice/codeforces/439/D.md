 ## 解決策
 ## 問題の理解

 2 つの整数配列が与えられ、1 つは Devu に属し、もう 1 つは彼の兄弟に属します。 1 回の操作で、いずれかの配列の単一要素を繰り返し 1 ずつ増減させることができます。 目標は、そのような単位調整の最小数を使用して、Devu の配列の最小値が弟の配列の最大値と少なくとも同じ大きさになるように配列を変換することです。 

条件を解釈する便利な方法は、最初の配列のすべての要素がそのしきい値以上であり、2 番目の配列のすべての要素がそのしきい値以下であるようなしきい値が必要であるということです。 最終的なしきい値は事前に固定されているわけではなく、両方の配列をどのように変更するかを選択することによって暗黙的に決定されます。 

この制約により、配列ごとに最大 1e9 の値を持つ最大 100,000 個の要素が許可されます。 最悪の場合、単一の調整シーケンスでも数十億のステップが必要になる可能性があるため、段階的に操作をシミュレートしようとするソリューションは直ちに不可能になります。 これにより、ほぼ線形または線形演算時間で機能する解決策が求められます。これには、ソートと、候補のしきい値に対するある種の貪欲な構造または二分探索が含まれる可能性があります。 

両方の配列を調整せずに個別に修正しようとすると、単純な間違いが発生します。 たとえば、次のすべての要素をプッシュしようとするかもしれません。`a`実現可能な最小値まで、すべての要素をプッシュします。`b`調整が行われるにつれて最適なミーティングポイントが変化する可能性を考慮せずに、実現可能な最大値まで引き下げます。 移動するだけでよいと想定すると、別の微妙な失敗が発生します。`a`上向きまたは移動のみ`b`場合によっては、片側のみを大幅に変更するよりも、両側をわずかに調整する方がコストが安くなる場合があるためです。 

簡単なシナリオを考えてみましょう。`a = [1, 100]`、`b = [50]`。 上げるだけなら`a`、上げる必要があります`1`少なくとも`50`、コストは 49 です。代わりに、さらに削減する場合`b`または、しきい値を慎重に変更すると、総コストが削減される可能性があります。 これは、最適な解決策が独立した修正ではなくグローバルしきい値に依存することを示しています。 

## アプローチ

 ブルート フォース アプローチでは、最終しきい値のすべての可能な値が試行されます。 固定閾値の場合`x`、すべてを作るのにかかるコストを計算します。`a[i] >= x`そしてすべての`b[j] <= x`。 各要素のコストは、単純に制約からどれだけ離れているかということになります。`a[i] < x`、私たちが支払います`x - a[i]`、それ以外の場合は 0。 もし`b[j] > x`、私たちが支払います`b[j] - x`これらを合計すると、そのしきい値のコストが得られます。 

これは正しいです。ターゲットのしきい値が固定されると、各要素は相互作用することなく個別に調整できるためです。 ただし、1 から 1e9 までの可能な整数をすべて試すことは不可能です。 

重要な観察は、コスト関数が閾値に関して凸であるということです。 しきい値を増やすと、次のようなコストがかかります。`a`コストが増加する一方で、`b`構造的に減少します。 これは、最適な値が既存の配列値によって形成される「臨界点」の近くに発生することを意味します。 実際、次の値の中から候補となるしきい値のみを考慮するだけで十分です。`a`そして`b`、連続する並べ替えられた値の間では、コスト関数の傾きは変化しないためです。 

両方の配列を並べ替えると、プレフィックス情報を使用してすべての候補しきい値を効率的に評価できます。あるいは、問題を古典的な中央値スタイルの位置合わせ問題に変換することで問題をさらに軽減できます。 最も明確な解釈は、ピボットを中心に両方の配列を概念的にマージし、共有境界に向かう合計の絶対移動を最小限に抑えるバランスの取れた分割を見つけることです。 

より直接的な最適な洞察は、値を選択することです。`x`以下を最小限に抑えるようにします。 

以下の要素に必要な増加の合計`x`で`a`、さらに上記の要素に必要な減少`x`で`b`。 並べ替えにより、候補ごとに線形時間で、または 2 つのポインターを使用して償却された一定時間で、これらの寄与を段階的に評価することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての x に対するブルート フォース | O(N * 最大値) | お(1) | 遅すぎる |
 | ソート + スイープ / 2 つのポインター | O((n + m) log(n + m)) | O(1) 追加 (ソート以外) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、両方の配列を並べ替えて、構造化された方法でしきい値を推論できるようにします。 並べ替えると、潜在的な回答を既存の要素または既存の要素の間にある値として扱います。 

次に、満たされた要素と満たされていない要素の間の「アクティブな境界」が変化する可能性のある位置をスイープすることによって、候補しきい値を評価します。 

1. 配列のソート`a`と配列`b`。 要素が順番にしきい値を超えるようにソートする必要があり、増分コストの追跡が可能になります。 
2. 現在のしきい値の位置と両側の要素を調整するコストを表すポインタとアキュムレータを初期化します。 
3. 両方の配列から導出された位置を考慮して、しきい値を上方にスイープします。 各ステップで、要素の数を維持します。`a`しきい値を下回っているか、またその中に要素がいくつあるか`b`その上にあります。 
4. しきい値をある候補値から次の候補値に移動するときは、最初から再計算するのではなく、コストを段階的に更新します。 変更は、間隔内で影響を受ける要素の数にのみ依存します。 
5. 評価されたすべてのしきい値にわたる最小コストを追跡します。 

重要な考え方は、2 つの連続する候補値の間で、コストに寄与する要素の構造は変わらないため、コストは線形に進化し、一定時間で更新できるということです。 

### なぜ効果があるのか

 固定しきい値では、すべての要素がしきい値との関係に基づいて独立して寄与します。 これにより、総コストは区分的線形関数の合計になります。 ソートにより、これらの関数のすべてのブレークポイントが事前にわかっていることが保証されます。 コストの導関数は配列値でのみ変化するため、最小値はこれらのブレークポイントのいずれかで発生する必要があります。 これらの点のみを評価することで、最適なソリューションがスキップされないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    a.sort()
    b.sort()
    
    # prefix sums for fast range cost computation
    pa = [0]
    for x in a:
        pa.append(pa[-1] + x)
    
    pb = [0]
    for x in b:
        pb.append(pb[-1] + x)
    
    def cost(x):
        # cost to make all a[i] >= x
        import bisect
        i = bisect.bisect_left(a, x)
        cost_a = x * i - pa[i]
        
        # cost to make all b[j] <= x
        j = bisect.bisect_right(b, x)
        cost_b = (pb[m] - pb[j]) - x * (m - j)
        
        return cost_a + cost_b
    
    # candidate points are values in a and b
    candidates = set(a + b)
    
    ans = float('inf')
    for x in candidates:
        ans = min(ans, cost(x))
    
    print(ans)

if __name__ == "__main__":
    solve()
```このコードでは、まず両方の配列を並べ替えて、プレフィックスの合計を計算してコストを迅速に評価できるようにします。 の`cost(x)`関数は、二分探索を使用して各配列を 2 つの部分 (しきい値以下またはしきい値を超える要素) に分割します。 のために`a`、より小さな要素を増やすのにどれだけ必要かを計算します。 のために`b`、より大きな要素を下げるためにどのくらい必要かを計算します。 

次に、既存の値から抽出された候補しきい値のみを評価します。 これが機能するのは、並べ替えられた 2 つの隣接する値の間では、寄与タイプを変更する要素がないため、コスト関数が線形であり、区間内で新しい最小値を持つことができないためです。

 ## 特殊なケース

 主要なエッジケースは、次のすべての要素が存在する場合に発生します。`a`はすでにすべての要素よりも大きくなっています`b`。 この状況では、条件はすでに満たされており、答えはゼロになるはずです。 範囲内のどの候補しきい値でも条件に違反する要素がなく、コストがゼロになるため、アルゴリズムはこれを自然に処理します。 

配列が高度にインターリーブされている場合、次のような別のエッジ ケースが発生します。`a = [1, 100, 200]`そして`b = [50, 60, 70]`。 最適なしきい値は、両方のアレイが部分コストに寄与する重複領域内にあります。 候補値をスイープすると、この領域内の最小値が確実に捕捉されます。 

最後の微妙なケースは、最適なしきい値が正確な値ではなく、値の間にある場合です。 離散的な候補のみをテストする場合でも、コスト関数は連続する並べ替えられた値の間で線形であるため、内部最小値はエンドポイントが同じコストを共有することを意味し、エンドポイントを評価するだけで十分であることを意味します。
