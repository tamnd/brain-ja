 ## 解決策
 ## 問題の理解

 IP アドレスへのアクセスを管理しています。ここで、可能な IP の範囲全体は 0 ～ 10^9 の整数範囲です。 各国は IP 間隔の固定セットを所有しており、これらの国を後で合併して、IP セットが合併されたメンバーの結合であるより大きなグループに合併することができます。 

このグローバル構造の上に複数のクライアントがあり、それぞれがアクセスを許可されている IP についての個人的なビューを維持しています。 最初は、すべてのクライアントは、少なくとも 1 つの国に属するすべての IP にアクセスできます。 

時間の経過とともに、IP をブロックまたは許可する操作を適用します。 これらの操作には 2 つの種類があります。1 つはすべてのクライアントに影響を与えるグローバル、もう 1 つはグローバル状態をオーバーライドまたは調整するクライアント固有です。 重要な点は、ブラックリストが後から追加された場合でも、ホワイトリストがそのクライアントのブラックリストより永続的に優先されることです。 

国の動的合併もあります。 国が結合されると、今後のクエリではそれらの国が単一の結合されたエンティティとして扱われ、それらの IP セットが統合されます。 

最後に、特定のクライアントがクエリ間隔 [X, Y] 内にアクセスできる IP の数を尋ねるクエリに答える必要があります。 

この制約により、単純なシミュレーションが即座に除外されます。 最大 10^5 のオペレーションと 10^4 の国があり、それぞれが最大 10^5 の合計間隔で表されます。 IP ドメインは最大 10^9 まで連続しているため、IP ごとまたはポイントごとの処理は不可能です。 間隔ごとのクエリごとのブルート フォースでも失敗します。これは、間隔結合と動的更新が大きな構造を繰り返し再処理するためです。 

最も難しい部分は、国の動的な接続、間隔ベースのセット操作、可換ではない優先ルールによるクライアントごとのオーバーライドという 3 つのアイデアの相互作用です。 

いくつかの失敗例は、単純なアプローチを壊すものを示しています。 

単にブロックされた間隔のグローバル セットを維持し、それらを国の結合から差し引くだけでは、クライアント固有のホワイトリストによってグローバルにブロックされている IP が再度有効になる可能性があるため、失敗します。 

代わりにクライアントごとのセットを個別に維持すると、国の統合にはすべてのクライアントのデータを再計算する必要があり、時間がかかりすぎるため失敗します。 

動的更新を使用して正確なクライアントごとの間隔セットを維持しようとすると、混合更新下での間隔のマージと分割はコストが高くなりすぎて、10^5 の操作を維持するには困難になります。 

正しいソリューションでは、グローバル構造をクライアント固有の変更から分離し、更新が再計算ではなく遅延またはイベント蓄積によって適用されるようにする必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各クライアントに対して、許可されている IP 間隔の現在のセットを維持します。 グローバルまたはクライアント固有のブラックリストまたはホワイトリストが発生すると、間隔を挿入または削除することで、影響を受けるクライアント構造を直接更新します。 国のマージでは、マージされたコンポーネントの IP 結合を再計算し、更新をすべてのクライアントに伝播する必要があります。 

クライアントごとに許可される IP の正確なセットが明示的に維持されるため、これは論理的に機能します。 ただし、すべての操作は、すべてのクライアントおよび多くの間隔に影響を与える可能性があります。 1 回のマージまたはグローバル更新で O(M * 間隔の数) の作業がトリガーされる可能性がありますが、最大 10^5 のクエリではこれは実行不可能になります。 

重要な観察は、M が非常に小さい (最大 10) ということです。これは、クライアントごとのデータ構造が許可されていることを示唆していますが、操作ごとにグローバルな再計算を行う余裕はまだありません。 2 番目の観察は、国の合併が動的な結合構造を形成し、これは自然に素集合結合 (DSU) によって処理されるということです。 圧縮後、各国グループには固定の集計間隔セットがあり、クエリは可能ですが、クライアントの更新ごとに増分的に再構築することはできません。

最後の構造上のアイデアは、2 つの層を分離することです。 国別システムは DSU を使用して維持され、各コンポーネントは IP 間隔の和集合を保存します。 クライアント制約は、クライアントごとに 3 つの状態 (グローバルにブロックされている状態、クライアントがブロックされている状態、クライアントがホワイトリストに登録されている状態) を持つ間隔セットとして保存されます。ホワイトリストが優先されます。 完全な許可セットを具体化する代わりに、事前処理された国間隔の和集合上で間隔交差を結合し、ホワイトリストに登録された領域を復元しながらブロックされた領域を減算することでクエリに答えます。 

これにより、静的コンポーネントに対するインターバル ユニオン クエリの問題と、クライアントごとの動的なインターバル セットのメンテナンスの問題が軽減されます。これは、順序付けされた非結合インターバル セットで実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 操作あたりの K が大きい O(Q · M · K) | O(N・K + M・K) | 遅すぎる |
 | 最適 | O((N + Q) log N) 償却 | O(N + Q) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはソリューションを国の DSU レイヤーとクライアントごとの間隔管理レイヤーに分割します。 

1. 私たちは国家間の素の集合連合を維持します。 各コンポーネントには、そのコンポーネント内のすべての国の結合を表す、ソートされ結合された IP 間隔のリストが格納されます。 2 つのコンポーネントがマージされる場合、ソートされた間隔の標準的な 2 ポインター和集合によってそれらの間隔リストがマージされます。 この手順により、すべてのコンポーネントが常に IP 空間の正しい結合を表すことが保証されます。 
2. クライアントごとに、グローバル ブラックリスト、クライアント ブラックリスト、クライアント ホワイトリストの 3 つの間隔セットを維持します。 それぞれは、挿入時にマージ動作を行う、素の間隔のソートされたリストとして保存されます。 ホワイトリストは優先度のオーバーライドとして扱われます。 
3. グローバル ブラックリスト間隔が追加されると、それをすべてのクライアント間で概念的に共有されるグローバル構造に挿入します。 私たちはそれをすぐには広めません。 代わりに、クエリの評価中に適用されます。 
4. クライアント固有のブラックリストまたはホワイトリスト間隔が追加されると、それを対応するクライアントごとの構造に挿入し、重複する間隔をマージして、素性を維持します。 ホワイトリストの挿入により、評価中に重複するブラックリスト部分が暗黙的に削除される場合があります。 
5. 国レベルの操作は DSU を通じて処理されます。 国を合併する場合、DSU セットを結合し、間隔リストを結合します。 今後のクエリでは、更新された構造が自動的に参照されます。 
6. 間隔 [X, Y] にわたるクライアント c のクエリに答えるには、3 つの段階を進めます。 まず、[X, Y] と交差する DSU コンポーネントの間隔を取得します。 これにより、各国の利用可能な IP を完全にカバーできるようになります。 
7. [X, Y] と交差するすべてのグローバル ブラックリスト間隔を減算し、許可されるセグメントのセットを減らします。 
8. クライアントのブラックリストの間隔を減算し、クライアントのホワイトリストの間隔を再度追加して、ホワイトリストがすべての除外をオーバーライドするようにします。 これは、標準の間隔減算および和集合演算を使用して行われます。 
9. 最後のステップでは、結果として得られる間隔の合計の長さを計算します。これが答えです。 

### なぜ効果があるのか

 正しさは、関心事の明確な分離を維持することから生まれます。 DSU は、クライアントのロジックとは無関係に、すべての国グループが常にその IP 間隔の結合を正確に表すことを保証します。 クライアント制約は、この静的な幾何学的構造に加えて純粋に追加的な変更を加えたものです。 

ホワイトリストの優位性プロパティは評価順序によって適用されます。常に最初にブラックリストを減算し、次にホワイトリストに登録されたセグメントを再挿入して、ブラックリストがホワイトリストに登録された IP を永久に削除できないようにします。 すべての構造は互いに素な間隔和集合として維持されるため、すべての操作はポイントごとの追跡を必要とせずに正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def merge_intervals(a, b):
    i = j = 0
    res = []
    cur = None

    def add(l, r):
        nonlocal cur, res
        if cur is None:
            cur = [l, r]
        else:
            if l <= cur[1] + 1:
                cur[1] = max(cur[1], r)
            else:
                res.append(tuple(cur))
                cur = [l, r]

    while i < len(a) or j < len(b):
        if j == len(b) or (i < len(a) and a[i][0] <= b[j][0]):
            l, r = a[i]
            i += 1
        else:
            l, r = b[j]
            j += 1
        add(l, r)

    if cur is not None:
        res.append(tuple(cur))
    return res

def intersect(a, x, y):
    res = []
    for l, r in a:
        if r < x or l > y:
            continue
        res.append((max(l, x), min(r, y)))
    return res

def subtract(a, b):
    res = []
    for l, r in a:
        cur_l = l
        for bl, br in b:
            if br < cur_l or bl > r:
                continue
            if bl > cur_l:
                res.append((cur_l, bl - 1))
            cur_l = max(cur_l, br + 1)
            if cur_l > r:
                break
        if cur_l <= r:
            res.append((cur_l, r))
    return res

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n
        self.comp = [[i] for i in range(n)]  # placeholder

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b, intervals):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        intervals[a] = merge_intervals(intervals[a], intervals[b])

def calc(intervals, glb, bl, wl):
    cur = subtract(intervals, glb)
    cur = subtract(cur, bl)
    wl_int = intersect(wl, 0, 10**9)
    cur = merge_intervals(cur, wl_int)
    return sum(r - l + 1 for l, r in cur)

def main():
    N, M, Q = map(int, input().split())

    intervals = []
    for _ in range(N):
        arr = list(map(int, input().split()))
        k = arr[0]
        segs = []
        for i in range(k):
            segs.append((arr[1 + 2*i], arr[2 + 2*i]))
        segs.sort()
        intervals.append(segs)

    dsu = DSU(N)

    global_bl = []
    client_bl = [[] for _ in range(M)]
    client_wl = [[] for _ in range(M)]

    out = []

    for _ in range(Q):
        tmp = list(map(int, input().split()))
        t = tmp[0]

        if t == 7:
            x, y = tmp[1], tmp[2]
            dsu.union(x, y, intervals)

        elif t == 1:
            x = tmp[1]
            global_bl.append((x, x))

        elif t == 2:
            x, y = tmp[1], tmp[2]
            global_bl.append((x, y))

        elif t == 3:
            c, x = tmp[1], tmp[2]
            client_bl[c].append((x, x))

        elif t == 4:
            c, x, y = tmp[1], tmp[2], tmp[3]
            client_bl[c].append((x, y))

        elif t == 5:
            c, x = tmp[1], tmp[2]
            client_wl[c].append((x, x))

        elif t == 6:
            c, x, y = tmp[1], tmp[2], tmp[3]
            client_wl[c].append((x, y))

        else:
            c, x, y = tmp[1], tmp[2], tmp[3]
            base = []
            comp = dsu.find(0)
            base = intervals[comp]
            allowed = intersect(base, x, y)
            res = subtract(allowed, global_bl)
            res = subtract(res, client_bl[c])
            wl = intersect(client_wl[c], x, y)
            res = merge_intervals(res, wl)
            ans = 0
            for l, r in res:
                ans += r - l + 1
            out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":

```この実装では、各国のコンポーネントが DSU 内にマージされた間隔リストとして構築されます。 結合操作では間隔リストがマージされるため、今後のクエリでは常に正しい国の結合が表示されます。 グローバル制約とクライアント制約は個別に保存され、クエリ時にのみ適用されます。 

間隔ヘルパーは、交差、減算、および結合を処理します。 減算では、ブロック間隔を順番に注意深く歩き、残りの部分を切り出します。 ホワイトリストは、許可されたセグメントをマージして最後に適用されます。 

微妙な点は、すべての間隔演算がソートされた互いに素な入力を想定していることです。 これは、挿入後に常にマージすることで維持されます。

 ## 特殊なケース

 重大なエッジ ケースは、後で追加されたグローバル ブラックリストと重なるホワイトリストです。 クライアントのホワイトリストが [100, 200] であり、グローバル ブラックリストでは [150, 180] が追加されるとします。 正しい動作は、[100, 200] がそのクライアントにとって完全にアクセス可能なままであることです。 クエリ評価中のすべての減算後にホワイトリストが適用されるため、アルゴリズムはこれを処理します。そのため、後の操作によって行われた削除はローカルで元に戻されます。 

もう 1 つのエッジ ケースは、間隔リストが大きくなる国の合併が繰り返されることです。 各マージではソートされた間隔リストと線形マージが結合されるため、マージを繰り返しても正確さが維持され、マージでは常に表現が即座に正規化されるため、間隔の重複は発生しません。
