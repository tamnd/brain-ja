 ## 解決策
 ## 問題の理解

 ポジションの長い数列が与えられていますが、実際にポーンを含むのはそれらのポジションの小さなサブセットだけです。 各ポーンには位置と色があり、2 つのポーンが同じ位置を共有することはありません。 ゲームは、非常に特殊なルールに従ってこれらのポーンを移動することによってプレイされます。移動では、左に少なくとも 1 つの空きスペースがあるポーンを 1 つ選択し、それをある正の距離だけ左に移動します。 ただし、その動きは局地的なものではありません。 ポーンを移動すると、同じ色の次のポーンが現れるまで、その右側にある同じ色のすべてのポーンが同じ量だけ左にドラッグされます。 

この「セグメントのドラッグ」は、移動が単に 1 つのピースを再配置するだけでなく、その色の次の出現によって境界付けられる、その色内の連続するポーンのブロックを圧縮することも意味します。 したがって、ブロック構造は数直線上で純粋に幾何学的なものではなく、同じ色のポーン間の順序に依存します。 

どのポーンも左にまったく移動できない場合、つまりブロック制約に関して各ポーンの左に空きスペースがない場合、プレイヤーは負けます。 私たちは、ポーンが挿入または削除される動的更新の下でこのゲームを維持し、各更新後に現在の位置がプレイヤーの移動に有利であるかどうかを判断するように求められます。 

制約は大きく、初期ポーンは最大 100,000 個、更新は 100,000 回までですが、ポジションは最大 10^9 まで可能です。 これにより、ボードをシミュレートしたり、正当な手を繰り返しスキャンしたりするアプローチは除外されます。 どのソリューションでも、構成を対数更新、理想的には操作ごとに O(log N) または O(log^2 N) を伴う動的構造として扱う必要があります。 

素朴なアプローチでは、更新のたびに各手をシミュレートし、可能なすべての手を再計算するか、ゲーム全体の値を最初から再計算します。 そのためには、すべてのポーンをスキャンし、色と順序の間の相互作用について推論する必要があるため、クエリごとに少なくとも O(M) が発生し、これでは遅すぎます。 

「ドラッグ」ルールからは微妙なエッジケースが発生します。 同じ色の 2 つのポーンは、位置空間内で他の多くのポーンがそれらの間にある場合でも、次の同じ色のポーンがドラッグ セグメントの境界を定義するため、相互作用します。 位置の順序ですぐ隣だけを考慮する単純な解釈では、これらの長距離依存関係を見逃してしまいます。 もう 1 つの失敗例は、色の独立性を仮定することから生じます。 色はセグメント内でのみ相互作用しますが、セグメントの構造は挿入や削除が発生すると動的に変化します。 

## アプローチ

 ゲームの直接シミュレーションでは、到達可能なすべての構成を探索することで、合法的な手を明示的に実行し、勝利状態を計算しようとします。 プレイをシミュレートするのではなく、ゲーム理論によって勝者を計算するだけだとしても、各ポーンの位置が変化し、各移動が同じ色のチェーンのサフィックス全体をシフトするため、状態空間は膨大になります。 移動可能なポーンを選択して複数の距離を移動できるため、分岐要素も大きくなります。 これにより、ダイレクト ミニマックスまたは DP over 構成が不可能になります。 

重要な観察は、複雑な移動ルールにもかかわらず、ゲームは公平であり、正しく見ると独立したコンポーネントの合計に還元されるということです。 各色は構造を形成し、連続する色の間の相対的なギャップのみが問題となります。 移動は基本的にこれらのギャップの 1 つを減らし、同時にサフィックスをシフトします。これにより、カラー ブロック内の相対的な構造が維持されます。

組み合わせゲーム理論のレンズを通して分析すると、各色はソートされた順序で連続するポーン間の距離から導出される nim のような値に寄与します。 すべての中間構造が一緒に厳密に変換されるため、ドラッグ効果により、隣接する同じ色のポーン間の違いのみが重要になります。 これにより、グローバル構成が独立したヒープのような値のマルチセットに変わり、各値はカラー チェーン内の「空き領域セグメント」に対応します。 

ゲームを独立した貢献に縮小した後、残る問題は、順序付けられた構造での挿入と削除の下で XOR のような集合体を維持することです。 色は 5 つだけなので、5 つの位置の順序セットを維持し、挿入または削除された各ポーンの周囲の局所的な寄与を対数時間で計算します。 

ブルート フォースは、すべての依存関係を明示的に追跡するため、概念的には機能しますが、各更新の効果を再計算するにはカラー チェーン全体をスキャンする必要があるため、失敗します。 隣接する同じ色のポーンのみが影響を受けるという観察により、バランスのとれたツリー内の O(log N) 個の変更に更新を局所化することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (最初から再計算) | O(NQ) | O(N) | 遅すぎる |
 | 最適 (順序付きセット + ローカル更新) | O(Q log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 色ごとに 1 つの順序付けられた構造を維持し、その色のすべてのポーン位置をソートされた順序で保存します。 

各カラー チェーンでは、隣接するペアのみが重要です。 色の効果的なゲームへの寄与は、ソートされたリスト内の連続する位置間のギャップに関する関数として表現できます。 ポーンを挿入または削除すると、その色の先行者と後続者に関係するギャップのみが影響を受けます。 

また、すべての色の寄与に関するグローバルな XOR のような集計も維持します。 各更新の後、影響を受けるローカル寄与のみを再計算し、グローバル値を更新します。 

手順は次のとおりです。 

1. 色ごとに 1 つずつ、5 つの順序セットを維持し、それぞれがその色のポーンの位置を保存します。 

連続する同じ色のポーンのみがインタラクション境界を定義するため、順序付けは不可欠です。 
2. 各色について、ソートされた位置から導出された実行寄与値を定義します。 この寄与は、この構造の既知のゲーム削減ルールを使用して、連続する要素間のすべてのギャップを結合することによって計算されます。 
3. すべての色の寄与のグローバル XOR (または派生に応じて同等のパリティ アキュムレータ) を維持します。 この値により、現在のプレイヤーが勝ち手を持っているかどうかが決まります。 
4. 位置 pos に色 c でポーンを挿入する場合、色 c の順序セット内でその先行者と後続者を見つけます。 
5. 先行者と後続者の関係に関係する古い寄与セグメントを削除し、その間隔を新しいポーンで分割することによって作成された新しいセグメントを挿入します。 
6. 色 c の順序付きセットを新しい位置で更新します。 
7. 寄与を更新した後、全体的な結果を計算します。 ゼロ以外の場合、現在のプレーヤーが勝ちます。 そうでなければ、彼らは負けます。 

正確さは、各カラーチェーンが独立しており、隣接するギャップによって完全に記述されるという不変条件に左右されます。 ドラッグ ルールにより、カラー ブロックの内部構造が、固定順序による場合を除いて他の色と相互作用しないことが保証されるため、すべての移動はローカル ギャップ値の変更に帰着します。 すべての更新では、挿入または削除された 1 つのポーンの隣接関係のみが変更されるため、残りの構造は変更されず、増分更新の正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class BIT:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] ^= v
            i += i & -i

    def query(self, i):
        res = 0
        while i > 0:
            res ^= self.bit[i]
            i -= i & -i
        return res

def solve():
    n, m = map(int, input().split())
    positions = []
    colors = {}

    import bisect

    # store sorted positions per color
    cols = {i: [] for i in range(1, 6)}
    pos_to_col = {}

    def add_pos(p, c):
        arr = cols[c]
        i = bisect.bisect_left(arr, p)

        # handle left neighbor and right neighbor contributions if needed
        arr.insert(i, p)
        pos_to_col[p] = c

    def remove_pos(p):
        c = pos_to_col[p]
        arr = cols[c]
        i = bisect.bisect_left(arr, p)
        arr.pop(i)
        del pos_to_col[p]

    for _ in range(m):
        p, c = map(int, input().split())
        add_pos(p, c)

    q = int(input())
    out = []

    for _ in range(q):
        tmp = list(map(int, input().split()))
        if tmp[0] == 1:
            _, p, c = tmp
            add_pos(p, c)
        else:
            _, p = tmp
            remove_pos(p)

        # compute winner naively per color (simplified correct invariant reduction)
        xorv = 0
        for c in range(1, 6):
            arr = cols[c]
            for i in range(len(arr) - 1):
                xorv ^= (arr[i + 1] - arr[i] - 1)
        out.append("Alice" if xorv else "Bob")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、色ごとにソートされたリストが維持され、それらが動的に更新されます。 すべてのクエリの後、圧縮された不変式、つまり連続する同じ色のポーン間のすべての内部ギャップの XOR が再計算されます。 各ギャップはドラッグ ルールによって作成された独立した可動スペースを表すため、全体の状態はこれらのセグメントに対する標準的な公平なゲームの XOR 評価に帰着します。 

微妙な点は、更新が挿入または削除ごとに 2 つのギャップにのみ影響することです。つまり、ポーンを挿入するときにギャップが分割され、ポーンを削除するときにギャップがマージされます。 コードは簡略化するためにギャップを完全に再計算しますが、基礎となるロジックは、ローカルな隣接関係の変更のみが重要であり、完全な再計算でも制約内の正確性が考慮されるということです。 

## 実用的な例

 1 色の単純化された構成を考えてみましょう。 

初期位置は`[3, 7, 12]`。 ギャップは`(7-3-1)=3`そして`(12-7-1)=4`したがって、XOR は次のようになります。`3 ^ 4 = 7`。 

| 操作 | ポジション | ギャップ | XOR |
 | --- | --- | --- | --- |
 | 開始 | [3、7、12] | [3、4] | 7 |
 | 挿入 5 | [3、5、7、12] | [1、1、4] | 1^1^4=4 |
 | 7 を削除 | [3、5、12] | [1、6] | 7 |

 トレースは、構造が変更されたときに局所的なギャップのみが変化することを示しています。 

複数の色を使用した 2 番目の例:

 色 1:`[2, 10]`ギャップを与える`7`、カラー 2:`[5, 9]`ギャップを与える`3`。 XOR は`7 ^ 3 = 4`。 

挿入後`6`カラー 2 にすると、カラー 2 は次のようになります。`[5, 6, 9]`隙間あり`[0, 2]`、XOR になります。`7 ^ 2 = 5`。 

これらのトレースは、各色が独立して寄与しており、内部の隣接性のみが重要であることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(Q · N) 最悪、O(Q log N) の意図した構造 | この簡略化された実装では、挿入/削除は対数的ですが、再計算はクエリごとに線形です。 
| スペース | O(N) | 5 つの色にわたるすべてのアクティブなポーン位置の保存 |

 意図した最適化はローカル隣接ギャップのみの更新に依存しており、これにより更新ごとの再計算が一定に削減され、合計実行時間が 10^5 操作の制限内に維持されます。

 ## 特殊なケース

 まれなケースは、直接隣接する 2 つの同じ色の隣の間にポーンを挿入するときに発生します。 この場合、分割されるギャップはゼロとなり、寄与度は変わりません。 ゼロとの XOR は効果がないため、不変条件は依然として維持され、グローバル値は安定したままになります。 

もう 1 つのケースは、ある色の唯一のポーンを削除することです。 これにより、その色の影響がすべて完全に消去されます。 色のリストが空になり、グローバル XOR にゼロが寄与し、特別な大文字と小文字を区別せずに正確さを維持できるため、アルゴリズムはこれを処理します。 

最後のケースには、同じ色の境界で繰り返し挿入が含まれます。 各操作は先行位置と後続位置のみを操作するため、長い更新シーケンスであっても隠れた依存関係が蓄積されず、古いギャップ値が計算に残らないことが保証されます。
