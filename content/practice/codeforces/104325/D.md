 ## 解決策
 ## 問題の理解

 整数のコレクションが与えられ、それぞれが正確に使用してバイナリで保存されます。$K$ビット。 正確に実行することが許可されています$P$各操作は、1 つの数値を選択し、そのビットの 1 つを反転することで構成されます。 

ビットを反転するとは、ビットを 0 から 1、または 1 から 0 に切り替えることを意味します。すべての操作を実行した後、グローバル スコア (順序付けされていない要素のすべてのペアに対する XOR の合計) を使用して、最終的な配列の品質を評価します。 正式には、すべてのペアに対して$i < j$、計算します$a_i \oplus a_j$そしてこれらの値を合計します。 

タスクは、この最終的な合計を最大化するだけでなく、具体的なシーケンスを出力することでもあります。$P$その最大値を達成するビット反転。 異なるシーケンスでも同じ最適値が生成される可能性があり、有効な値であればどれでも出力できます。 

主な難点は、数値の 1 ビットを変更すると他のすべての数値に対する寄与に影響を与えるため、反転するたびに複数のペアごとの XOR 値が間接的に影響を受けることです。 これにより、グローバルな依存関係が作成されます。つまり、ローカルの反転は非ローカルな効果を持ちます。 

この制約により、総当たりの探索は不可能になります。 と$N \le 10^5$、$K \le 30$、そして最大$P \le 3 \cdot 10^6$、考えられるそれぞれの反転を素朴な方法で個別にシミュレートしたり評価したりすることはできません。 各フリップ後に完全な XOR 合計を再計算するだけでもコストがかかります$O(N)$、につながる$O(NP)$、これは大きすぎます。 

すべての数値が同一である場合、微妙なエッジケースが発生します。 たとえば、すべてが$a_i = 0$、その後、すべての反転が最初に多様性を増加させるため、XOR 合計が増加します。 ただし、フリップの分散が不十分な場合、後のフリップによって前のゲインがキャンセルされる可能性があります。 グローバル ゲインを追跡せずに任意のビットを貪欲に反転する単純な戦略では、簡単に発振したり、すでに飽和したビットの反転を無駄にしたりする可能性があります。 

もう 1 つのエッジケースは次のような場合です$P$に比べて非常に大きいです$N \cdot K$。 同じビットを 2 回反転するとその効果が打ち消されるため、計画なしにすべての演算を盲目的に使用すると、目的を改善しないにもかかわらず出力が必要な冗長な動きが発生します。 

## アプローチ

 ブルートフォースのアイデアは単純です。各演算を独立して検討し、すべての数値の可能なすべてのビットを反転してみて、結果の配列をシミュレートし、完全なペアごとの XOR 和を計算し、即時に最適な改善を選択します。 これは目的関数を直接評価するため概念的には機能しますが、目的関数の各評価にはコストがかかります。$O(NK)$慎重に行われた場合、または$O(N^2)$ペアに対して単純に実行した場合。 これを繰り返すと、$P$操作は少なくとも$O(PN)$、これは大きすぎます$N = 10^5$。 
重要な洞察は、目標を書き直すことから得られます。 ペアごとの XOR の合計はビットごとに分解できます。 ビット位置ごとに$b$、そのビットが設定されている要素の数のみが重要です。 もし$c_b$要素にはビットがあります$b$が 1 に等しい場合、合計に対するこのビットの寄与は次のようになります。$$c_b \cdot (N - c_b) \cdot 2^b$$これにより、問題はビットごとの独立した寄与の制御に変換されます。 

これで、各フリップは 1 つの数値の 1 ビットに影響し、カウントのみが変わります。$c_b$そのビットのために。 したがって、すべての操作には、完全な配列構造ではなくローカル ビット数のみに依存するグローバル スコアにおける明確に定義された限界ゲインがあります。 

これにより、問題は、ビットごとの寄与の合計が最大になるフリップを繰り返し選択することになります。 以来$K \le 30$を使用すると、現在のカウントを維持し、ゲインを効率的に再計算できます。 

私たちは常にすべてのフリップの中から利用可能な最良のものを選択します$N \cdot K$可能性がある場合は、それを適用し、影響を受けるビット数を更新して続行します。 ヒープまたは全ビットの再計算は制約内で機能します。$NK \approx 3 \cdot 10^6$。

 ## アルゴリズムのチュートリアル

 グローバル スコアはこれらの数にのみ依存するため、現在各ビットが設定されている要素の数を追跡します。 

1. すべての初期ビット数を計算します。$K$配列全体のビット位置。 これにより、XOR 合計に対する各ビットのベースライン寄与が確立されます。 
2. 各ビットについて$b$、特定の要素のビットを反転した場合に合計スコアがどれだけ変化するかを計算します。 反転するとカウントが変化するため、効果は要素のその位置に現在 0 があるか 1 があるかによって異なります。$c_b$+1 または -1 のいずれかで指定します。 
3. 最大限のプラスの貢献をもたらすフリップを繰り返し選択できる構造を維持します。 正の反転がない場合でも、操作を実行する必要があるため、引き続き最も害の少ない反転または中立的な反転を選択します。 
4. フリップを選択するとき$(i, b)$、それを適用します: ビットを切り替えます$a_i$、カウントを更新します$c_b$それに応じて。 このステップにより、ビットを含むすべてのフリップの将来のゲインが変更されます。$b$, そのため、その効果を更新する必要があります。 
5.正確になるまで繰り返します$P$操作が実行され、常に現在利用可能な最良のフリップが選択されます。 

中心的な考え方は、各演算がビットごとの XOR 寄与の合計のわずかな増加を貪欲に最適化し、寄与構造によって局所的な最適性が全体的な改善と確実に一致するようにするということです。 

### なぜ効果があるのか

 XOR 合計は独立したビットの寄与にきれいに分解され、各ビットの寄与はそのビットが含まれる数値の数にのみ依存します。 すべてのフリップではそのようなカウントが 1 つだけ変更され、フリップの効果はその変化によって完全にキャプチャされます。$c_b (N - c_b)$。 目標にはクロスビット相互作用がないため、各ステップでの最良の限界ゲインを最適化することで全体的な最適性が維持されます。 このプロセスは、整数状態にわたる分離可能な凹関数に最も急な上昇ステップを繰り返し適用することと同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K, P = map(int, input().split())
    a = list(map(int, input().split()))

    # count ones per bit
    cnt = [0] * K
    for x in a:
        for b in range(K):
            if (x >> b) & 1:
                cnt[b] += 1

    # precompute current value contribution
    def gain(i, b):
        bit = (a[i] >> b) & 1
        c = cnt[b]
        if bit == 1:
            # flipping 1 -> 0
            new_c = c - 1
        else:
            # flipping 0 -> 1
            new_c = c + 1

        before = c * (N - c)
        after = new_c * (N - new_c)
        return (after - before) << b

    import heapq
    heap = []

    # initialize all possible flips
    for i in range(N):
        for b in range(K):
            g = gain(i, b)
            heapq.heappush(heap, (-g, i, b))

    res = []

    for _ in range(P):
        while True:
            neg_g, i, b = heapq.heappop(heap)
            g = -neg_g
            # recompute to avoid stale values
            if g != gain(i, b):
                continue
            break

        # apply flip
        res.append((i + 1, b))
        bit = (a[i] >> b) & 1
        if bit:
            cnt[b] -= 1
        else:
            cnt[b] += 1
        a[i] ^= (1 << b)

        # push updated affected entries for this bit
        for j in range(N):
            heapq.heappush(heap, (-gain(j, b), j, b))

    print("\n".join(f"{i} {b}" for i, b in res))

if __name__ == "__main__":
    solve()
```コードはビット数をグローバルに維持し、ヘルパー関数を通じて限界ゲインを再計算します。 ヒープには、推定された改善順に並べられた候補フリップが保存されます。 ゲインは反転するたびに変化する可能性があるため、古いエントリは受け入れられる前に再計算によってフィルタリングされます。 

唯一の微妙な点は、ビットを反転した後、そのビットに関係するすべての反転で値が変更されるため、すべてのインデックスにわたってそのビットの更新された候補を再挿入する必要があることです。 これにより、ヒープが現在の状態と一貫性を保ちます。

 ## 特殊なケース

 エッジ ケースの 1 つは、単一要素の配列です。 ペアがないため、XOR 合計は常に 0 であり、反転のシーケンスはすべて有効です。 このアルゴリズムは、すべてのゲインがゼロの場合でも、定義された最適な反転を常に選択するため、有効な操作を生成します。 

すべての要素が同一である場合、別の特殊なケースが発生します。 最初は、すべての XOR 寄与はゼロです。 反転すると多様性が高まりますが、同じビットを繰り返し反転するとゲインが元に戻される可能性があります。 このアルゴリズムは、各操作の後にゲインを再計算することでこれを回避し、古い改善が永続的に優先されることがないようにします。 

最後のエッジケースは次のような場合です$P$とても大きいです。 アルゴリズムは常に正確に出力するため、$P$操作では、システムが局所最適に達した後も継続されますが、ゲイン計算により、出力形式の正確さを損なうことなく有効な変換が循環されることが保証されます。
