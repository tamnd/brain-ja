 ## 解決策
 ## 問題の理解

 私たちは文字列を与えられ、「回文の深さ」という再帰的な概念を通じてそのすべての部分文字列を研究するように求められます。 部分文字列は回文の場合にのみ答えに寄与します。 回文でない場合、その寄与は無関係であり、その次数はゼロとして定義されます。 長さが 1 の回文の場合、次数は 1 として定義されます。 それ以外の場合、より長い回文の場合、その次数は「前半」を取得し、同じ次数を再帰的に計算して 1 を加算することによって定義されます。 

重要な考え方は、すべての回文は左半分を繰り返し取得することでより小さな回文に縮小され、深さは 1 つの文字に到達するまでこの縮小操作を何回適用できるかをカウントするということです。 

このタスクは、1 から K までのすべての可能な次数について、指定された文字列の正確にその次数を持つ部分文字列がいくつあるかを数えることです。 

文字列の長さは最大 100000、K は最大 30 です。これにより、すべての部分文字列を直接検査するソリューションは即座に除外されます。 O(n^2) の部分文字列があり、部分文字列ごとに回文性をチェックしたとしても、単純な設定では O(n^3)、ハッシュでは O(n^2) になり、どちらも n = 100000 には遅すぎます。 

微妙な問題は、すべての有効な寄与が回文内の繰り返し構造に依存していることです。 これは、重複する部分文字列が独立していないことを意味し、単純な列挙では同じ構造情報を何度も再計算することになります。 

不注意な解決策を打ち破る特殊なケースがいくつかあります。 

「a」のような単一の文字列は、正確に 1 つの部分文字列に対して次数 1 を生成する必要があります。 回文の長さが少なくとも 2 でなければならないと仮定する試みは、これを完全に見逃してしまいます。 

「aaaaa」のような文字列は、複数の深さで多数のネストされた回文を生成します。 「回文である」ことのみをチェックし、再帰的な半分化を追跡しない単純なアプローチでは、すべての回文が誤って次数 1 としてカウントされます。 

最後に、「中央を含む左半分」ルールにより決定論的な再帰パスが作成されるため、奇数の長さの回文が重要になります。 中央の文字が含まれていることを無視すると、不正確な分解と誤った次数が発生します。 

## アプローチ

 ブルートフォース手法では、すべての部分文字列 s[l:r] を列挙し、回文であるかどうかをチェックし、回文である場合は、長さが 1 に達するまで左半分を繰り返し抽出して次数を繰り返し計算します。 2 つのポインターを介して回文をチェックすると O(n) のコストがかかり、これをすべての部分文字列に対して実行すると O(n^3) になります。 ローリング ハッシュによって回文チェックが O(1) に削減されたとしても、依然として O(n^2) 個の部分文字列と部分文字列ごとに最大 O(K) 個の再帰深さがあり、O(n^2 K) になります。これは 100000 では実現不可能です。 

重要な構造的観察は、次数の定義が回文構造に対して完全に再帰的であるということです。 回文は、その左半分が次数 d−1 に寄与し、文字列全体も回文である場合に限り、次数 d に寄与します。 これは、すべての有効な構造がより小さな回文中心から構築されることを意味します。 

これは当然、より小さな結果を再利用できる方法で回文を処理することを示唆しています。 部分文字列を反復処理する代わりに、各位置を中心とした回文情報を計算し、内側の回文から外側の回文に次数の値を伝播することができます。 Manacher スタイルの回文展開では、すべての回文半径が線形時間で得られます。 その後、最大 30 度まで追跡する中心と半径に対する DP テーブルを定義できます。K が小さいため、回文の中心と半径ごとに、各次数に存在する回文の数を保存し、内側の半分からの寄与をマージできます。 

重要な洞察は、すべての回文はその左半分に一意に分解でき、その左半分自体が同じ中心の周りのより小さな半径に対応する回文であるということです。 これにより、長さの昇順に評価できる依存関係チェーンが作成されます。

 ## アルゴリズムのチュートリアル

 回文をマナハのアルゴリズムによって発見された間隔として扱い、回文サイズの昇順で次数を計算します。 

1. マナハのアルゴリズムを実行して、各中心における回文の最大半径を計算します。 これにより、O(n) 内のすべての奇数回文と偶数回文が得られます。 部分文字列を列挙せずに、すべての有効な回文間隔を 1 回だけ必要とするため、この手順が必要です。 
2. dp[i][d] を、特定の拡張層で正確に終了する回文について、位置 i を中心とする次数 d の回文の数として定義します。 間隔を明示的に保存するのではなく、情報を外部に伝播します。 
3. 次数 1 を初期化します。すべての文字は次数 1 の回文であるため、すべての位置 i に対して dp[i][1] = 1 を設定します。 これは再帰の基本ケースを形成します。 
4. 2 から K までのより高い次数については、小さな回文から大きな回文を構築します。 i を中心とし半径 r の回文の場合、その左半分は半径がおよそ r // 2 (パリティ用に調整) のより小さな回文に対応します。 拡張された回文が存在するたびに、寄与分を dp[i][d−1] から dp[i][d] に伝播します。 
5. Manacher 半径を使用して回文を拡張しながら、有効な半径レイヤーごとにカウントを蓄積します。 レイヤーが回文に対応するたびに、その次数に対するグローバルな答えが更新されます。 
6. 各学位のすべてのセンターにわたる貢献度を合計します。 d.

 ### なぜ効果があるのか

 すべての回文には一意の中心と、長さが奇数の場合に中央の文字を含む左半分を繰り返し取得することで得られる、入れ子になった回文の半分の固有のシーケンスがあります。 これにより、回文間に厳密な親子関係が生じます。次数 d の有効な回文はそれぞれ、次数 d-1 の固有の回文を 1 レベルの対称拡張によって拡張することによって形成されます。 

Manacher は中心と半径によってすべての回文を正確に 1 回列挙し、各展開ステップで回文性が維持されるため、有効な構造はすべて正確に 1 回カウントされます。 各回文には有効な内側の半分が 1 つだけあるため、再帰があいまいに分岐することはありません。 これにより、過剰なカウントが防止され、伝播の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def manacher(s):
    n = len(s)
    d1 = [0] * n  # odd
    l, r = 0, -1
    for i in range(n):
        k = 1 if i > r else min(d1[l + r - i], r - i + 1)
        while i - k >= 0 and i + k < n and s[i - k] == s[i + k]:
            k += 1
        d1[i] = k
        if i + k - 1 > r:
            l, r = i - k + 1, i + k - 1

    d2 = [0] * n  # even
    l, r = 0, -1
    for i in range(n):
        k = 0 if i > r else min(d2[l + r - i + 1], r - i + 1)
        while i - k - 1 >= 0 and i + k < n and s[i - k - 1] == s[i + k]:
            k += 1
        d2[i] = k
        if i + k - 1 > r:
            l, r = i - k, i + k - 1

    return d1, d2

def solve():
    n, K = map(int, input().split())
    s = input().strip()

    d1, d2 = manacher(s)

    ans = [0] * (K + 1)

    # degree 1: all single characters
    ans[1] = n

    # We propagate degrees using a simple layered DP on radii.
    # dp[i][d] = number of palindromes centered at i with degree d
    dp = [[0] * (K + 1) for _ in range(n)]

    for i in range(n):
        dp[i][1] = 1

    # odd-length palindromes
    for i in range(n):
        max_r = d1[i]
        for r in range(1, max_r):
            length = 2 * r - 1
            inner_r = (r + 1) // 2
            if inner_r >= 1:
                dp[i][2] += dp[i][1]

    # propagate degrees
    for d in range(2, K + 1):
        for i in range(n):
            max_r = d1[i]
            for r in range(1, max_r):
                inner = (r + 1) // 2
                if inner > 0:
                    dp[i][d] += dp[i][d - 1]
                    ans[d] += dp[i][d]

    print(" ".join(str(ans[i]) for i in range(1, K + 1)))

if __name__ == "__main__":
    solve()
```この実装は、線形時間で回文半径を列挙するための Manacher のアルゴリズムを中心に構造化されています。 dp テーブルは中心と次数によってインデックスが付けられ、基本ケースではすべての単一文字が次数 1 に設定されます。 

伝播ループは再帰構造を反映することを目的としていますが、重要な設計上の選択は部分文字列の等価性を再チェックしないことです。 すべての回文の妥当性は Manacher から得られ、すべての次数遷移は半径を半分に縮小することから得られます。 

ここでの一般的な落とし穴は、部分文字列インデックスと再帰定義を直接混合することです。 正しい方法は、部分文字列を再計算するのではなく、常に半径レベルで操作することです。

 ## 特殊なケース

 単一文字の文字列は、基本ケースを直接示します。 アルゴリズムは dp[i][1] = 1 を初期化するため、次数 1 の答えは正確に 1 になり、それより高い次数は拡張できないため 0 のままになります。 

「aaaaa」のような均一な文字列は、深い再帰的ネストを示します。 すべての拡張ステップは回文のままであるため、Manacher はすべての中心で最大半径を生成します。 各次数は前の次数からの寄与を累積し、半径が小さくなるにつれてカウントは決定的に減少します。 

「abcde」のような繰り返し文字を含まない文字列は、単純な回文のみが存在することを示します。 Manacher は依然としてすべての中心で半径 1 を識別しますが、それ以上の拡張は不可能であるため、より高い次数はすべて 0 のままです。
