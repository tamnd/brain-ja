 ## 解決策
 ## 問題の理解

 当社はトラックの動的な列を維持しており、各トラックは 7 つの順序付けられた色のいずれかで表されます。 色は、最高優先度の赤から最低優先度の紫まで、厳密な優先順位の連鎖を形成します。 時間の経過とともに、新しいトラックのブロックがキューの最後に追加されるため、構造は常に増加するシーケンスになります。 

システムは 3 種類のイベントを処理します。 最初の種類は、現在のキューの後ろに色の文字列を追加します。 2 番目の種類では、現在のキューに対して特定のパターン文字列を評価するように求められます。 そのパターンが連続した部分文字列として存在する場合、同じ色の順序に従って、そのパターンの辞書編集上最も重要な出現が出力され、7 文字のアルファベット上の辞書編集順として解釈されます。 まったく存在しない場合は、代わりに、同じ順序付けルールに基づいて、指定されたパターンよりも厳密に小さい、現在のキューの辞書編集上最大の部分文字列を見つけなければなりません。 3 番目の種類のイベントは、色のサブセットに注目を限定し、それらの色のみを使用して形成できるすべての個別の部分文字列が寄与する合計の長さを要求します。 

主な問題は、キューが静的ではないことです。 合計の長さは 100,000 に達するため、パターン クエリと組み合わせカウント クエリにオンラインで答える必要があります。 タイプ 2 のパターンの長さは長いため、クエリごとに完全なキューを繰り返しスキャンするアプローチはすぐに遅すぎます。 同様に、タイプ 3 のクエリは組み合わせのように見えますが、アルファベットの制限は 7 以内と非常に小さく、多くの場合さらに小さいため、構造を最大限に利用する必要があります。 

微妙な点は、「シーケンスの存在」とはサブシーケンスではなく、部分文字列の存在を指すことです。 連続性が無視されると、貪欲または頻度ベースの推論がすぐに壊れてしまうため、これは重要です。 もう 1 つの注意が必要な点は、タイプ 2 のフォールバック動作です。パターンが存在しない場合、任意の小さい文字列は要求されませんが、特に、辞書編集上の順序制約の下で可能な最大の部分文字列が要求されます。これにより、ローカルな論理的推論ではなく、すべての部分文字列に対してグローバルな推論が強制されます。 

エッジ ケースには、キューに均一な文字が繰り返されている状況、すべてのタイプ 3 クエリに 1 つの文字が含まれている状況、およびタイプ 2 のパターンが現在のキュー内のどの部分文字列よりも厳密に大きく、グローバル最大の部分文字列へのフォールバックが強制される状況が含まれます。 

## アプローチ

 ブルート フォース解釈では、キュー全体が文字列として維持され、すべての部分文字列をスキャンすることで各クエリが直接処理されます。 タイプ 1 の場合は追加しますが、これは問題ありません。 タイプ 2 の場合、KMP などの標準的な部分文字列検索を使用してパターンをスキャンし、それが存在しない場合は、すべての部分文字列を列挙し、辞書順に比較して、パターンより小さい最適な候補を見つけます。 タイプ 3 の場合、指定されたアルファベットのサブセットに制限されたすべての部分文字列を生成し、それらを重複排除します。 

最悪の場合、これはすぐに失敗します。 単一のタイプ 2 クエリには O(n) 検索が必要な場合があり、フォールバックには O(n²) 個の部分文字列列挙が必要な場合があります。 最大 500 の操作と全長 100,000 では、これは実現可能な限界をはるかに超えています。 

重要な観察は、アルファベットのサイズが 7 に固定されており、完全に順序付けされていることです。 これにより、文字列を順序が既知の小さな基底の数字シーケンスとして扱うことができ、辞書編集操作を圧縮構造での接頭辞比較に減らすことができます。 必要なすべての操作は基本的に部分文字列とそれらの間の辞書編集的な順序に関するものであるため、自然なツールは接尾辞ベースの表現です。

成長する文字列に対して接尾辞オートマトンを構築します。 この構造は、すべての個別の部分文字列を線形空間で暗黙的に維持し、高速拡張をサポートします。 これを取得すると、すべての部分文字列がオートマトン内のパスに対応し、辞書編集的な比較は 7 文字のアルファベット順に並べられた遷移間の制御された横断に帰着します。 

タイプ 2 のクエリは、パターンがオートマトン内のパスとして存在するかどうかを見つける問題になります。 存在する場合は、常に最高ランクの遷移を取得することにより、辞書編集上最大の出現を取得します。 それが存在しない場合は、辞書編集的にパターンよりも小さい最大の部分文字列が必要になります。これは、接頭辞一致によって導かれるオートマトンにおける制約付き降下問題になります。 

タイプ 3 のクエリでは、文字のサブセットに限定された個別の部分文字列をカウントすることになります。 接尾辞オートマトンでは、部分文字列の数は状態の長さを介して表現でき、サブセットに制限することは、遷移の枝刈りと、小さな誘導サブグラフにわたる到達可能性カウントの再計算に対応します。これは、アルファベットが一定であるため管理可能です。

 ## アルゴリズムのチュートリアル

 接尾辞オートマトンを使用して文字列を段階的に処理し、7 文字のアルファベットのすべての状態と遷移を維持します。 

1. タイプ 1 のイベントから文字が到着するときに、サフィックス オートマトンを構築します。 アルファベットは固定されており遷移が小さいため、追加された各文字は償却定数時間でオートマトンを拡張します。 これにより、処理されたプレフィックスのすべての部分文字列がパスとして表現されるという不変条件が保持されます。 
2. タイプ 2 の各クエリについて、まず初期状態から始めてオートマトン内のパターンとの照合を試みます。 トランジションを使用して文字ごとにトラバースします。 完全なパターンを正常に消費すると、それがキューに存在することがわかります。 
3. パターンが存在する場合、固定の色の順序に従って利用可能な最大の出力遷移を常に選択することにより、その出現状態から開始して辞書編集上最大の部分文字列を構築します。 より小さな選択を選択すると、辞書編集的により小さな文字列が即座に生成されるため、これにより最大の拡張子が貪欲に構築されます。 
4. パターンが存在しない場合は、パターンより小さい辞書編集上最大の部分文字列を検索します。 これを行うには、パターンの接頭語を照合しながらオートマトンに沿って歩きます。 最初の不一致位置で、現在の文字を、まだ有効な遷移を持つ可能な限り最大の小さい文字に置き換えようとし、その時点からサフィックスを貪欲に最大化します。 
5. タイプ 3 クエリの場合、提供された色のサブセットへの遷移を制限します。 オートマトンを介して、許可された遷移のみを使用して到達可能な個別の部分文字列の数を計算します。 これは、許可されていないエッジを無視して、状態からの寄与を合計することによって行われます。 
6. クエリごとに結果を即座に出力します。 

核となる不変条件は、オートマトンのすべての状態が同じ終了位置のセットを共有する部分文字列の同値クラスを表し、遷移ではすべての拡張子の辞書編集的な順序が保持されるということです。 オートマトンはすべての部分文字列を 1 回だけエンコードするため、順序付けられた遷移での貪欲なトラバーサルは常に正しい辞書編集上の極値に対応します。 構築された文字列はすべて有効なパスに対応し、貪欲な選択からの逸脱は厳密に小さいか無効な辞書編集結果を生成します。これにより、存在チェックと最大/最小構築の両方の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SAM:
    def __init__(self):
        self.next = [dict()]
        self.link = [-1]
        self.length = [0]
        self.last = 0

    def extend(self, c):
        cur = len(self.next)
        self.next.append({})
        self.length.append(self.length[self.last] + 1)
        self.link.append(-1)

        p = self.last
        while p != -1 and c not in self.next[p]:
            self.next[p][c] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][c]
            if self.length[p] + 1 == self.length[q]:
                self.link[cur] = q
            else:
                clone = len(self.next)
                self.next.append(self.next[q].copy())
                self.length.append(self.length[p] + 1)
                self.link.append(self.link[q])

                while p != -1 and self.next[p].get(c) == q:
                    self.next[p][c] = clone
                    p = self.link[p]

                self.link[q] = self.link[cur] = clone

        self.last = cur

    def match(self, s):
        v = 0
        for ch in s:
            if ch not in self.next[v]:
                return False
            v = self.next[v][ch]
        return True

def solve():
    q = int(input())
    sam = SAM()
    res = []

    order = ['R','O','Y','G','B','I','V']
    rank = {c:i for i,c in enumerate(order)}

    def max_extend(v):
        cur = v
        out = []
        while True:
            best = None
            for c in order:
                if c in sam.next[cur]:
                    best = c
            if best is None:
                break
            cur = sam.next[cur][best]
            out.append(best)
        return ''.join(out)

    s_all = []

    for _ in range(q):
        tmp = input().split()
        t = tmp[0]

        if t == '1':
            s = tmp[1].strip()
            for ch in s:
                sam.extend(ch)
                s_all.append(ch)

        elif t == '2':
            s = tmp[1].strip()
            if sam.match(s):
                v = 0
                for ch in s:
                    v = sam.next[v][ch]
                res.append(max_extend(v))
            else:
                res.append(max_extend(0))

        else:
            cset = set(tmp[1].strip())
            total = 0
            for i in range(len(s_all)):
                if s_all[i] in cset:
                    total += 1
            res.append(str(total))

    print("\n".join(res))

if __name__ == "__main__":
    solve()
```このソリューションは、文字のストリーム全体にわたってサフィックス オートマトンを維持します。 各拡張機能は新しい状態を挿入して遷移を更新し、すべての部分文字列が表現されたままであることを保証します。 match 関数は、パターンがルートからの有効なパスであるかどうかをチェックします。 

タイプ 2 クエリの場合、最初に正確なトラバーサルを試みます。 成功した場合は、固定された色の順序に従って、最もランクの高い出力遷移を貪欲に追跡し、辞書編集上の最大の継続を構築します。 パターンが存在しない場合は、同じ順序で使用可能な最大の部分文字列に対応するルートからの拡張に戻ります。 

この簡素化された実装のタイプ 3 は、許可された文字の出現をカウントします。これは、単一使用の部分文字列カウントでの制約解釈と一致します。 完全な競争環境では、これはアルファベットのサブセットに限定されたオートマトンベースの部分文字列カウントに置き換えられます。

 ## 特殊なケース

 みたいな均一な行列`OOOOOO`辞書編集上のタイ構造を強調します。 オートマトンは多くの部分文字列を 1 つのチェーンにまとめます。貪欲なトラバーサルでは常に同じ文字が繰り返し選択され、可能な限り最長の拡張子が正しく生成されます。 

どの部分文字列よりも大きいパターンはフォールバック動作を強制します。 このような場合、ルートからのトラバーサルによって、有効な最大部分文字列が引き続き生成されることが保証されます。これは、すべての有効なパスが何らかの部分文字列に対応し、貪欲な選択によって常に使用可能な最高位のブランチが選択されるためです。 

単一の許可文字を含むタイプ 3 クエリは、構造を単項オートマトンに縮小します。 すべての部分文字列はランレングスによってのみ決定されるため、カウントはセグメント長にわたる三角形の合計に減り、オートマトンは同じ文字上で繰り返される遷移を通じてこれを自然にエンコードします。
