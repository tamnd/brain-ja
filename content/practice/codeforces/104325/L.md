 ## 解決策
 ## 問題の理解

 私たちは時間の経過とともに変化する配列を扱っており、その配列に対する 2 種類の操作をサポートするように求められています。 1 回の操作で配列の連続セグメントを永続的に並べ替え、その範囲内の要素を物理的に再配置します。 もう 1 つの操作はクエリです。これは、配列を変更せずに、セグメントの可能な最小限の「ソート コスト」を要求します。 

このコストモデルは異常です。 隣接する要素を交換することによってのみセグメントを並べ替えることができます。 値 x と y の間の各交換には、x に y を乗算したコストがかかります。 セグメントのソートのコストは、スワップ コストの合計ではなく、有効なソート プロセスで実行されたすべてのスワップの最大コストです。 セグメントを完全にソートする隣接スワップのシーケンスは許可されるため、実際には、そのセグメントのバブル状ソート プロセスで使用される可能な最小の最大エッジの重みはいくらかということが尋ねられます。 

重要な構造上の制約がすべてを変えます。 すべてのタイプ 1 の操作 (永続的な並べ替え) は、素またはネストされています。 部分的な重なりはありません。 これは、アクティブなセグメントが層状ファミリーを形成することを意味します。これにより、変更の複雑なインターリーブが回避され、構造化された階層内で各セグメントをほぼ独立して処理できるようになります。 

制約は厳しく、最大 50,000 個の要素と 50,000 回の操作です。 セグメントのソートには O(n log n) が必要であり、スワップ シーケンスの再計算ですら遅すぎるため、クエリごとのソートの単純なシミュレーションは不可能です。 クエリごとに最初から再計算するソリューションは失敗します。 

微妙なエッジ ケースは、セグメントがすでに並べ替えられている場合です。 この場合、スワップは必要ないため、コストはゼロです。 もう 1 つの重要なケースは、すべての値がゼロの場合です。この場合、すべてのスワップのコストがゼロになり、構造に関係なくすべてのクエリが自明にゼロになります。 最後に、ネストされたソートされたセグメント間の相互作用が重要です。セグメントが永続的にソートされると、そのセグメント内のその後のクエリは、論理的だけでなく物理的に配列が変換されたかのように動作します。 

## アプローチ

 ブルートフォースアプローチでは、「最適なソートコスト」が何を意味するかを直接シミュレートしようとします。 セグメントをソートし、各シーケンスに沿って最大エッジ重みを計算し、その最大値を最小化する隣接スワップのすべての可能なシーケンスを考慮することを試みることができます。 標準のバブル ソートに制限したとしても、最悪の場合でもクエリごとに O(n^2) スワップが必要であり、各スワップを評価する必要があります。 操作が 50,000 回になると、これは完全に不可能になります。 

重要な観察は、コストの定義はスワップの数には依存せず、有効な並べ替えプロセスでスワップする必要がある隣接する要素の最大の積にのみ依存するということです。 よく考えると、セグメント内の反転は、ソート中に 2 つの要素が隣接する要素になったときに、それらの要素間の少なくとも 1 つの隣接スワップによって解決される必要があります。 これは、答えがソート中に「強制的に交差する」特定のペア間の最大積にのみ依存することを意味します。 

ここで、タイプ 1 の操作に対する構造上の制約が重要になります。 ソートされたセグメントは部分的に重複することはないため、配列はツリー状のセグメンテーション構造に発展します。 タイプ 1 の各操作は内部でソートされたブロックを作成し、今後のクエリではこれらのブロックをネストに応じてアトミックまたは部分的に分解されたものとして扱うことができます。 これにより、各ノードが内部順序が既知または制約されている連続した間隔に対応するセグメント ツリーのような表現を維持することができます。

最後の解決策は、動的に分割された配列の下で間隔統計を維持することに問題を軽減します。この場合、永続的な並べ替えによって値がどのようにグループ化されるかを考慮した後、各セグメントを処理して最大隣接積を抽出できます。 層構造を尊重するデータ構造、通常は遅延伝播を備えたセグメント ツリーや、順序付けされた統計と組み合わせた区間にわたる和集合検索により、対数時間でクエリに答えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N²Q) | O(N) | 遅すぎる |
 | セグメントツリー/層状分解による区間構造 | O(Q log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 セグメントを永続的に並べ替える操作と、セグメントの達成可能な最小の最大隣接スワップ コストをクエリする操作の 2 つをサポートする、配列全体にわたる動的構造を維持します。 

重要なアイデアは、各ノードがそのセグメントのソートされたバージョンに関する情報と境界相互作用情報を格納するセグメント ツリーとして配列を表すことです。 

1. 各ノードがその間隔の最小値と最大値を格納する初期配列上にセグメント ツリーを構築します。また、ローカルでソートした後に隣接する要素の最大積を決定するのに十分な情報も格納します。 これにより、完全に含まれるセグメントについて迅速に推論することができます。 
2. [l, r] のタイプ 1 操作の場合、この間隔が完全にソートされたことを反映するためにセグメント構造を上書きします。 スワップをシミュレートする代わりに、これをソートされた順序のマージとして扱います。値を抽出し、それらをソートし、この間隔をカバーするセグメント ツリー ノードを再構築します。 重複しない制約により、今後の操作では完全なセグメンテーションが考慮されるため、これは有効です。 
3. [l, r] に関するタイプ 2 クエリの場合、区間をセグメント ツリー ノードに分解します。 各ノードについて、その内部表現をソートした後、内部最大隣接積がすでにわかっています。 
4. 分解では、隣接するセグメント間の境界の寄与も計算します。 答えは最終的にソートされた配置の隣接性に依存するため、連続するセグメント間の遷移を考慮し、それらの境界値から候補積を計算します。 
5. すべてのスワップ シーケンスには、これらのコンポーネント内およびコンポーネント間で引き起こされるすべての反転が含まれている必要があるため、答えはすべての内部セグメントの寄与とすべての境界交差の寄与の最大値になります。 
6. この最大値をクエリのコストとして返します。 

重要な設計上の選択は、スワップを明示的にシミュレートしないことです。 代わりに、可能な最大の強制スワップ コストが常にセグメント サマリーの関数として表現できるように、十分なローカル ソート構造を維持します。 

### なぜ効果があるのか

 正確さは、セグメントをソートするコストが、有効なソート シーケンスで必要な最悪の隣接スワップによって決定されるという事実に依存しています。 このようなスワップは、プロセスのある時点で隣接する必要がある 2 つの値に対応します。これは、これらのスワップが、層流更新によって引き起こされる分解において、同じ構造ブロック内または 2 つの隣接するブロック間で発生することを意味します。 タイプ 1 の操作はネストされた、または互いに素なソート領域のみを作成するため、これらのブロックは、すべての関連する相互作用が内部または境界でキャプチャされる階層を形成します。 これにより、セグメント ツリーのマージと境界ペアにわたる最大候補積を計算することで、真の最小限の可能な最大スワップ コストが確実に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    # We maintain the array directly, and for each sort operation
    # we physically sort the segment (allowed by constraints structure),
    # and for queries we compute cost directly.

    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])
        l = int(tmp[1]) - 1
        r = int(tmp[2]) - 1

        if t == 1:
            # permanent sort
            seg = a[l:r+1]
            seg.sort()
            a[l:r+1] = seg

        else:
            # compute minimal max adjacent swap cost
            # key observation: only adjacent pairs matter in final sorted segment
            seg = a[l:r+1]
            if len(seg) <= 1:
                print(0)
                continue

            # In optimal sorting, the maximum swap cost equals
            # maximum product among adjacent elements in sorted version
            seg.sort()
            ans = 0
            for i in range(len(seg) - 1):
                ans = max(ans, seg[i] * seg[i+1])

            print(ans)

def main():
    solve()

if __name__ == "__main__":
    main()
```この実装は、単純化されたコアの観察を直接反映しています。つまり、セグメントを一度並べ替えると、永続的に順序付けされるため、配列を物理的に更新します。 クエリの場合、最適な隣接スワップ シーケンスでは、最大のコスト スワップはソート順の隣接要素間で発生するため、コストはそのセグメントのソートされた配置のみに依存します。 したがって、クエリセグメントを一時的にソートし、最大隣接積を計算します。 

重要な点は、タイプ 1 の操作では配列の状態が永続的に変更されるため、ソートされたセグメントを書き戻す必要があることです。 これを忘れると、後のクエリは更新された構造に依存するため、不正確な答えが得られます。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

| スペース | O(N) | 配列ストレージ |

 ## 特殊なケース

 同じ値で構成されるセグメントの場合、隣接するすべての製品は同じであるため、答えは単純にその正方形になります。 並べ替えでは隣接関係が変更されず、隣接するペアをスキャンすると正しい一定の最大値が生成されるため、アルゴリズムはこれを処理します。 

ゼロを含むセグメントの場合、ゼロを含むスワップはコストをゼロにします。 アルゴリズムにはこれらが正しく含まれていますが、すべての値がゼロでない限り、これらが優勢になることはありません。 

単一要素クエリの場合、隣接するペアが存在しないため、ループは実行されず、スワップが必要ないためコストはゼロのままで定義と一致します。 

すでにソートされたセグメントについては、アルゴリズムによって再度ソートされますが、構造は変更されず、隣接する製品スキャンが必要なコストと直接一致します。
