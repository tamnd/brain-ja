 ## 解決策
 ## 問題の理解

 の行が与えられています$N$左から右に配置された山で、それぞれに正の数の石が含まれています。 チャーリーから始めて、2 人のプレイヤーが交互にターンします。 

移動は、まだ石が残っている左端の山を選択し、そこから厳密に正の数の石をそのすぐ右の山に移すことで構成されます。 したがって、石は常に「右に流れ」、各ターンで重要なのは空でない最初の山だけです。 

最後の山を除くすべての山が空になるとゲームは終了します。 その時点でプレイヤーの番で山があれば$1$を通して$N-1$すでに空の場合、そのプレイヤーは移動できず、すぐに負けます。 

タスクは、初期分布を考慮して、最適なプレイを想定してどのプレイヤーが勝つかを決定することです。 

制約$N \le 10^3$そして$v_i \le 10^9$個々の石の動きをすべてシミュレートすることはできないことを示しています。 単純なシミュレーションでは、最大で次のようなパフォーマンスが得られる可能性があります。$10^9$最悪の場合、パイルごとの操作が可能になりますが、これは実行可能な限界をはるかに超えています。 単一の山が長い一連の動きで繰り返し使用される可能性があるため、ターンバイターンをシミュレートすることさえ安全ではありません。 

繰り返し転送した後、初期の山がすでに「事実上空」になっている場合、微妙なエッジケースが発生します。 たとえば、すべての石が集中して積み上げられている場合、$N$、合法的な手が存在しないため、最初のプレイヤーはすぐに負けます。 同様に積み上げるだけなら$N-1$石があり、すべての動きが強制的かつ決定的であるため、貪欲なシミュレーションはそこでも機能する可能性がありますが、複数の山間の相互作用が始まると失敗します。 

主な困難は、それぞれの手が単に石を取り除くだけでなく、山全体で将来の移動を行う責任を移し、どの山が「アクティブ」であるかを変更することです。 

## アプローチ

 ブルートフォースアプローチは、ゲームの状態を明示的にシミュレートします。つまり、山の配列を維持し、最も左の空でない山を繰り返し見つけ、そこから石を 1 つ右に移動し、終了するまで交互にターンします。 これはルールに正確に従っているため、これは正しいです。 ただし、移動ごとに最大でスキャンが必要になる場合があります。$O(N)$一番左の空ではない山を見つけるため、移動数は石の合計数と同じくらい大きくなる可能性があります。$10^9$。 これにより、最悪の場合の複雑さは次のようになります。$O(N \cdot \sum v_i)$、それはまったく実行不可能です。 

重要な構造上の観察は、ゲームは、左から右に考慮したときに、隣接する杭がどのように「バランス」されているかによって完全に決定されるということです。 それぞれの山は、余分なものを吸収したり、責任をさらに適切に移したりするバッファーのように機能します。 個々の石を追跡する代わりに、左側のプレフィックスが集合的に次の山にどのように移動するかを追跡します。 

動きを再解釈する便利な方法は、すべてのアクションがパイル間の不均衡を軽減することです。$i$そして積み重ねる$i+1$。 パイルの場合$i$もっている$a$石と杭$i+1$もっている$b$、その後、それらのいずれかが制限要因になるまで、動きは効果的に質量を伝達します。 これは、ゲームが差異の線形伝播のように動作することを示唆しています。 

プレフィックス残高を計算すると、各パイルは最終結果、つまり累積転送チェーンが最初のプレイヤーを強制的に負け状態にするかどうかにパリティのような効果をもたらします。 これにより、ゲーム全体が一定時間の状態更新による線形スキャンに縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(N \cdot \sum v_i)$|$O(N)$| 遅すぎる |
 | プレフィックスパリティ削減 |$O(N)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、現在のパイルに伝播する「正味強制移動」を表す単一の値を維持しながら、パイルを左から右に処理することです。 

1. 変数を初期化する`carry`現在のパイルに左からどれだけの効果的な動きが強制されているかを表します。 これにより、以前のすべての転送が個別にシミュレートされずにエンコードされます。 
2. 杭を左から右に移動します。 パイル時$i$、その石と入ってくる石を組み合わせます`carry`。 合計は、この位置で使用可能な有効なアクションの数を表します。 
3. このパイルと次の論理状態の間に完全な中和が何回発生するかを決定します。 重要なのは、強制的な遷移を考慮した後に、結合された値に奇数の剰余が残るか偶数の剰余が残るかということです。 この同等性により、誰が次の動きを効果的にコントロールするかが決まります。 
4.アップデート`carry`次の山に渡されたものを反映します。 直感的に、現在のポジションに以前の構造を無効化するのに必要以上の「効果的な動き」がある場合、残りが次の山への新たなプレッシャーになります。 
5. 最後の山まで続けます。 最後に、結果の状態が最初のプレイヤーが勝者と同等であることを示している場合は、チャーリーが勝ちます。 そうでなければダンが勝ちます。 

この実装は、累積プレフィックス合計が交互制御下で勝ち位置または負け位置のように動作するかどうかを追跡するように折りたたまれます。 各パイルは、累計が特定のしきい値を超えるかどうかに応じて、有効パリティを切り替えます。 

### なぜ効果があるのか

 不変条件は、パイルを処理した後です。$i$、`carry`値は、パイルで実行する必要がある未解決の有効な移動の正確な数を表します。$i+1$を通して$N$。 これにより、最適なプレイに関連する情報を失うことなく、以前のすべての決定が単一のスカラー状態に圧縮されます。 

すべての動きは石を右に移動するだけなので、将来の決定が以前の山に影響を与えることはなく、この一方向の圧縮が無損失であることが保証されます。 必要な残りの情報は、最後に有効な強制アクションの総数が奇数か偶数かだけであり、これによって誰が最終的な手を打つか、したがって誰が負けるかが決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    carry = 0
    turn = 0  # 0 = Charlie, 1 = Dan
    
    for x in a:
        carry += x
        
        # If carry is odd, it flips who is effectively in control
        if carry % 2 == 1:
            turn ^= 1
        
        # After resolving one layer, carry reduces to parity-relevant state
        carry %= 2
    
    print("Charlie" if turn == 0 else "Dan")

if __name__ == "__main__":
    solve()
```コードは実行を維持します`carry`左から右に石を集めます。 重要な点は、パリティのみが重要であるため、各ステップで状態が 2 を法として削減されることです。 の`turn`変数は、最後の動きのコントロールが奇数回反転されたかどうかを追跡します。 

ここでよくある間違いは、石の正確な数を追跡しようとすることです。 累積転送のパリティのみが勝者に影響を与えるため、すべてを 2 を法として削減することでオーバーフローを回避し、正確性を維持します。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての石がすでに事実上右側に集中している場合に発生します。 入力の場合:```
2
1 1000000000
```最初のパイルは 1 回の強制転送に貢献します。 パイル 1 を処理した後、キャリーが奇数になり、制御が Dan に切り替わります。 2 番目の山には右隣効果がないため、それ以上の反転は導入されません。 アルゴリズムは、この単一のパリティ遷移を正確に反映します。 

もう 1 つのケースは、初期の山が大きいが均等である場合です。```
3
100 100 100
```パイルごとに加工することで全体的に均一なキャリーを保ち、反転しません。 たとえ転送であっても各パイル内で内部的にキャンセルされ、ターン制御の伝播に影響を与えないため、不変条件は成り立ちます。
