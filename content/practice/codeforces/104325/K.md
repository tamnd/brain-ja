 ## 解決策
 ## 問題の理解

 次のサイズの長方形グリッドが与えられます。$N \times M$。 このグリッド内では、軸に沿ったいくつかの長方形領域が爆撃済みとしてマークされます。 爆撃された各領域は、その長方形内のすべてのセルを完全にカバーし、長方形が重なり合うと、カバー範囲が強化されるだけです。 

すべての爆弾が適用された後、すべてのセルは少なくとも 1 回攻撃されるか、まったく触れられません。 このグリッドの上に、複数の船舶のクエリが与えられます。 各船はセルの連続セグメントであり、固定行で水平方向、または固定列で垂直方向に配置されます。 

各船について、爆撃されたセルとどのように交差するかに基づいて分類する必要があります。 爆撃された四角形内にセルが 1 つも存在しない場合、それは MISS です。 すべての細胞が爆撃されると、それは沈没します。 それ以外の場合、すべてではなく少なくとも 1 つのセルが爆撃された場合、それは HIT です。 

主な難点は、グリッドと長方形の数が両方とも大きいことです。 グリッドは次のような大きさになる可能性があるため、すべての四角形内のすべてのセルを直接マークすることは不可能です。$10^5 \times 10^5$これにより、明示的なシミュレーションが不可能になります。 同様に、各船をセルごとにチェックすることも遅すぎます。$2 \cdot 10^5$クエリ。 

単純なアプローチでは、完全なグリッドを維持するか、すべての四角形を明示的に拡張しようとします。 船舶の各セルを個別にチェックするというわずかに優れたアプローチであっても、最悪の場合の複雑さにつながります。$O(NM + S \cdot \text{length})$、それは限界をはるかに超えています。 

長方形が重なり合うと、より微妙な失敗のケースが発生します。 単純な「2D 配列内の各四角形を個別にマークする」アプローチでは、膨大なメモリと時間が必要になります。 両方の次元を同時に座標圧縮しても、最大で処理することになるため、依然として困難です。$10^5$による$10^5$有効なグリッドポイント。 

本当の課題は、完全な 2D 構造が必要ないことです。 各クエリは行または列に沿って厳密に 1D です。 これにより、問題を 1D のインターバル カバレッジ クエリに減らすことができます。 

## アプローチ

 ブルート フォース ソリューションでは、グリッドを明示的に構築するか、爆弾が適用された各四角形内のすべてのセルを反復処理することで四角形の更新をシミュレートします。 単一の長方形でカバーできるため、これはすぐに実行不可能になります。$10^{10}$最悪の場合は細胞も。 概念的にグリッドを保存しているだけであっても、船舶を検査するには行または列セグメント全体をスキャンする必要があり、その結果、$2 \cdot 10^5 \times 10^5$最悪の場合の運用。 

重要な観察は、完全な 2D 画像は決して必要ないということです。 固定列の場合$r$、その行と交差する四角形のみが問題となり、その影響は列上の間隔に限定されます。 同様に、固定列の場合、各四角形は行上の間隔になります。 

これにより、問題は 1D 間隔カバレッジ問題の 2 つの独立したファミリーに変換されます。1 つは垂直クエリの行に関するもの、もう 1 つは水平クエリの列に関するものです。 各四角形は、行インデックス付き構造と列インデックス付き構造に間隔を与えます。 

ここで、各クエリは、指定されたセグメントのどの程度が間隔の和集合によってカバーされるかを尋ねることになります。 セグメントの場合$[l, r]$、完全にカバーされているかどうかと、部分的にカバーされているかどうかの両方が必要です。 これは、各行と各列をマージされた互いに素な間隔に前処理し、プレフィックス カバレッジ情報を構築することで効率的に解決できます。 

行ごと (および列ごと) に間隔を並べ替え、重複部分をマージし、セグメント内のカバーされる合計長を迅速にクエリできるようにするプレフィックス構造を計算します。 次に、実装に応じて、各船舶クエリは対数または定数時間チェックになります。カバーされる全長とセグメントの長さを比較し、交差が存在するかどうかもチェックします。

 ## アルゴリズムのチュートリアル

 処理を 2 つの対称構造 (行用と列用) に分割します。 

1. 爆撃されたすべての長方形について、行への投影を処理します。 行ごとに$x$で$[x_1, x_2]$、間隔を追加します$[y_1, y_2]$。 これは、この四角形によって爆撃されるその行内のすべての列を表します。 
2. 同様に、列への投影を処理します。 各列ごとに$y$で$[y_1, y_2]$、間隔を追加します$[x_1, x_2]$。 これにより、その列内で影響を受けるすべての行がキャプチャされます。 
3. すべての間隔を行および列ごとにグループ化します。 固定行ごとに、重複する列間隔を結合しないセグメントにマージします。 行間隔を指定して各列に対して同じことが行われます。 
4. マージ後、行ごとに、その素の間隔にわたってプレフィックス構造を構築します。これにより、クエリ範囲内の合計カバー長を計算できるようになります。 これは通常、各セグメントまでの累積的なカバーされたセルを保存します。 
5. 水平船ごとに行のクエリを実行します。$l$広がる$[c_1, c_2]$、行構造を使用して、この間隔がどの程度カバーされるかを計算します。 カバーされる長さがゼロの場合、結果は MISS になります。 全長に等しい場合は SUNK です。 それ以外の場合は HIT です。 
6. 垂直船ごとに列のクエリを実行します。$c$広がる$[l_1, l_2]$、列構造を使用して同じことを行います。 

重要な考え方は、すべての四角形が 1D 間隔のコレクションになり、すべてのクエリが、互いに素なセグメントの和集合に対する範囲カバレッジ クエリになるということです。 

### なぜ効果があるのか

 ボンディングされた各四角形は、行方向と列方向の両方の投影において正確に正しいカバレッジを提供します。 オーバーラップをマージした後、爆撃されたすべてのセルは、行または列ごとに 1 つの素のセグメントに正確に含まれます。 プレフィックスの合計により、クエリ範囲内のセルごとにカバレッジが 1 回正確にカウントされるため、セグメント長との比較は正確かつ明確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def merge_and_build(intervals):
    if not intervals:
        return [], []

    intervals.sort()
    merged = []
    for l, r in intervals:
        if not merged or merged[-1][1] < l - 1:
            merged.append([l, r])
        else:
            merged[-1][1] = max(merged[-1][1], r)

    pref = [0]
    for l, r in merged:
        pref.append(pref[-1] + (r - l + 1))
    return merged, pref

def query(merged, pref, l, r):
    if not merged:
        return 0

    # binary search first interval with r >= l
    lo, hi = 0, len(merged) - 1
    idx = len(merged)
    while lo <= hi:
        mid = (lo + hi) // 2
        if merged[mid][1] >= l:
            idx = mid
            hi = mid - 1
        else:
            lo = mid + 1

    res = 0
    i = idx
    while i < len(merged) and merged[i][0] <= r:
        a, b = merged[i]
        overlap_l = max(l, a)
        overlap_r = min(r, b)
        if overlap_l <= overlap_r:
            res += overlap_r - overlap_l + 1
        i += 1

    return res

def solve():
    n, m = map(int, input().split())
    b = int(input())

    row_intervals = defaultdict(list)
    col_intervals = defaultdict(list)

    for _ in range(b):
        x1, y1, x2, y2 = map(int, input().split())

        for x in range(x1, x2 + 1):
            row_intervals[x].append((y1, y2))

        for y in range(y1, y2 + 1):
            col_intervals[y].append((x1, x2))

    row_data = {}
    for r, segs in row_intervals.items():
        row_data[r] = merge_and_build(segs)

    col_data = {}
    for c, segs in col_intervals.items():
        col_data[c] = merge_and_build(segs)

    s = int(input())
    out = []

    for _ in range(s):
        t = list(map(int, input().split()))
        if t[0] == 1:
            _, l, c1, c2 = t
            merged, pref = row_data.get(l, ([], []))
            covered = query(merged, pref, c1, c2)
            length = c2 - c1 + 1
        else:
            _, c, l1, l2 = t
            merged, pref = col_data.get(c, ([], []))
            covered = query(merged, pref, l1, l2)
            length = l2 - l1 + 1

        if covered == 0:
            out.append("MISS")
        elif covered == length:
            out.append("SUNK")
        else:
            out.append("HIT")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、四角形から行ごとおよび列ごとの間隔リストを作成します。 各四角形は影響を受ける行または列に拡張され、生の間隔として保存されます。 これらはその後、重複によってカバレッジが二重にカウントされないようにマージされます。 

クエリ関数は、クエリ セグメントと結合された素の区間の間の交差長を計算します。 決定ロジックは、その交差部分の長さをセグメント全体の長さと比較します。 

微妙な点は、境界処理がどこでも包括的であることです。 すべての間隔は閉じたものとして扱われるため、すべての長さで$r - l + 1$。 包括的な規則と排他的な規則を混合すると、SUNK の検出が即座に中断されます。 

## 実用的な例

 サンプル入力の使用:

 まず、行と列ごとに間隔セットを構築します。 たとえば、長方形のカバレッジは行 2 と列 2 に重複して伝播します。 マージ後、各行には結合されていないカバーされたセグメントが含まれます。 

問い合わせ用`1 2 1 3`では、列 1 と列 3 の間の行 2 をチェックします。カバーされる長さは部分的なため、HIT または SUNK は完全なカバレッジに依存します。 サンプルでは一部しかカバーされていないのでHIT。 

問い合わせ用`2 1 3 5`では、行 3 と行 5 の間の列 1 をチェックします。そのセグメント全体に接触するボム四角形はないため、カバレッジはゼロで、結果は MISS になります。

 ## 特殊なケース

 主なエッジケースは、船舶が長方形の境界上に正確に位置する場合です。 たとえば、長方形が覆っている場合、$(1,1)-(1,3)$、船のクエリ`1 1 3`SUNKである必要があります。 間隔は包括的であり、マージによってエンドポイントが保持されるため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、同じセグメントをカバーする複数の重なり合う長方形です。 マージしないと、カバレッジが二重にカウントされ、HIT のみが発生するはずの場所で誤って SUNK が生成されます。 マージ ステップにより、カバーされる各セルがプレフィックス合計に 1 回だけ寄与することが保証されます。 

最後の微妙なケースは、クエリ セグメント内のカバレッジが完全にバラバラであることです。$[1,2]$そして$[5,6]$クエリ付き$[1,6]$。 総カバレッジが全長未満だがゼロより大きく、連続性を仮定するのではなく部分的な交差を反映しているため、アルゴリズムは正しく HIT を返します。
