 ## 解決策
 ## 問題の理解

 グリッドの各セルには 2 つの状態のいずれかを割り当てる必要があります。これは、小麦を植えるか、ヒマワリを植えているかと考えることができます。 セル内で小麦を選択すると行列 A から一定の利益が得られ、ヒマワリを選択すると行列 B から一定の利益が得られます。これまでのところ、これはセルごとの独立した決定にすぎません。 

この結合は隣接関係から生じます。隣接する 2 つのセル (水平または垂直) に異なるクロップが割り当てられるたびに、対応する C 値によって与えられるペナルティを支払います。 これにより、問題は、すべてのローカルな決定が近くのセルに影響を与えるグローバルな最適化タスクに変わります。 

出力は、各セルの作物を選択し、個々のセルのゲインとエッジの不一致ペナルティのバランスをとった後に達成可能な最大利益です。 

この制約によりグリッド サイズは最大 70 x 70 に設定されるため、セルの数は最大 4900 個になります。 すべてのセルに対するブルート フォース割り当てには 2^4900 の構成が必要になりますが、これは完全に不可能です。 相互作用グラフは両方向のサイクルを持つ一般的なグリッドであるため、サブセットにわたる動的プログラミングさえも不可能です。 

さらに微妙な問題は、ペナルティが絶対値ではなく、隣接するものが異なるかどうかに依存することです。 これは、目的を行や列で区切ることができず、貪欲な選択は失敗することを意味します。 たとえば、高 A セルで局所的に小麦を選択すると、たとえすべての近隣者が個別に小麦を好んでいたとしても、ヒマワリの近隣住民を強制し、ローカルの利益を上回る複数のペナルティが引き起こされる可能性があります。 

A[i][j] と B[i][j] を比較して各セルを独立して割り当てる素朴な貪欲なアプローチは、局所的な利益よりも中央の一貫性が重要な 2x2 グリッドではすぐに機能しません。 

## アプローチ

 強引な解決策では、小麦またはヒマワリの各セルへの可能な割り当てをすべて試し、総利益を計算し、最良のものを採用します。 これはすべての構成を評価するため正しいですが、2^(N・M) 個の状態を評価する必要があり、ペナルティの計算にはそれぞれのコストが O(NM) かかり、これは実現可能な制限をはるかに超えています。 

重要な観察は、目的が 2 つの部分で構成されているということです。独立したセルの報酬と、隣接するエンドポイントが一致するか否かのみに依存するペアごとのペナルティです。 この構造は、グラフ内の最小 s-t カットに変換できる、古典的なバイナリ ラベリング エネルギー最小化問題と一致します。 

このアイデアは、各セルがノードとなるフロー ネットワークを構築することです。 セルを小麦またはヒマワリに割り当てることは、セルを切り口の片側に配置することに相当します。 単項利益はソースとシンクへのエッジ コストとしてエンコードされ、隣接ペナルティは隣接ノード間のエッジとしてエンコードされます。 カットはラベル付けを表し、そのコストは慎重に選択されたベースラインと比較した損失に等しくなります。 

最大化を最小化に変換し、最小カットを使用することにより、指数関数的な探索空間を多項式時間グラフ アルゴリズムに縮小します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(N・M)・NM) | O(NM) | 遅すぎる |
 | 最適 (最小カット / 最大流量) | O(F・V・E) | O(V + E) | 承認済み |

 ## アルゴリズムのチュートリアル

 グリッドをフローネットワークに変換し、最小カット問題を解決します。

1. 各セルについて、max(A[i][j], B[i][j]) に等しいベースライン値を計算します。 これは、相互作用を無視した場合の最大の利益を表します。 後で、このベースラインに対して損失を差し引きます。 
2. 各セルに対して、小麦を選択するコストとヒマワリを選択するコストの 2 つのコストを定義します。 これらはベースラインから実際のゲインを引いたものとして定義されるため、どちらも負ではありません。 
3. すべてのセルにグラフ ノードを作成し、さらにソース ノードとシンク ノードを作成します。 
4. 各セルについて、ヒマワリの割り当てコストに等しい容量でソースをセルに接続し、小麦の割り当てコストに等しい容量でセルをシンクに接続します。 このエンコードにより、これらのエッジを切断することは、そのラベルを選択するペナルティを支払うことに相当することが保証されます。 
5. すべての水平または垂直の隣接に対して、ペナルティ C[i][j] に等しい容量を持つ無向エッジ (2 つの有向エッジとして実装) を追加します。 このエッジにより、隣接するセルに異なるラベルが割り当てられている場合、カットではまさにこのペナルティを支払う必要があります。 
6. ソースとシンクの間で最大フロー アルゴリズムを実行します。 最小カットの値は、ベースライン構成からの避けられない損失の合計です。 
7. すべてのセルのベースライン合計から最小カット値を引いて、達成可能な最大利益を回収します。 

正確さは、各 s-t カットを小麦とヒマワリのセットへのセルの分割として解釈することで得られます。 単項エッジは各セルに特定のラベルを割り当てるコストをエンコードし、ペアワイズ エッジはエンドポイントが反対側にあるときに不一致コストが正確に支払われることを保証します。 

不変条件は、すべての有効なラベルが正確に 1 つのカットに対応し、カット容量がそのラベルのベースライン損失に等しいということです。 最小カットでは可能な限り最小の損失が見つかるため、結果として得られるラベル付けにより利益が最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

class Dinic:
    def __init__(self, n):
        self.n = n
        self.adj = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.adj[u].append([v, c, len(self.adj[v])])
        self.adj[v].append([u, 0, len(self.adj[u]) - 1])

    def bfs(self, s, t, level):
        q = deque([s])
        level[s] = 0
        while q:
            u = q.popleft()
            for v, c, _ in self.adj[u]:
                if c > 0 and level[v] < 0:
                    level[v] = level[u] + 1
                    q.append(v)
        return level[t] != -1

    def dfs(self, u, t, f, level, it):
        if u == t:
            return f
        for i in range(it[u], len(self.adj[u])):
            it[u] = i
            v, c, rev = self.adj[u][i]
            if c > 0 and level[v] == level[u] + 1:
                pushed = self.dfs(v, t, min(f, c), level, it)
                if pushed:
                    self.adj[u][i][1] -= pushed
                    self.adj[v][rev][1] += pushed
                    return pushed
        return 0

    def max_flow(self, s, t):
        flow = 0
        INF = 10**18
        level = [-1] * self.n

        while True:
            level = [-1] * self.n
            if not self.bfs(s, t, level):
                break
            it = [0] * self.n
            while True:
                pushed = self.dfs(s, t, INF, level, it)
                if not pushed:
                    break
                flow += pushed
        return flow

def solve():
    n, m = map(int, input().split())
    A = [list(map(int, input().split())) for _ in range(n)]
    B = [list(map(int, input().split())) for _ in range(n)]

    Cx = [list(map(int, input().split())) for _ in range(n)]
    Cy = [list(map(int, input().split())) for _ in range(n - 1)]

    def id(i, j):
        return i * m + j

    N = n * m
    S = N
    T = N + 1
    dinic = Dinic(N + 2)

    base = 0

    for i in range(n):
        for j in range(m):
            a = A[i][j]
            b = B[i][j]
            base += max(a, b)

            u = id(i, j)

            dinic.add_edge(S, u, max(a, b) - b)
            dinic.add_edge(u, T, max(a, b) - a)

    for i in range(n):
        for j in range(m - 1):
            u = id(i, j)
            v = id(i, j + 1)
            dinic.add_edge(u, v, Cx[i][j])
            dinic.add_edge(v, u, Cx[i][j])

    for i in range(n - 1):
        for j in range(m):
            u = id(i, j)
            v = id(i + 1, j)
            dinic.add_edge(u, v, Cy[i][j])
            dinic.add_edge(v, u, Cy[i][j])

    mincut = dinic.max_flow(S, T)
    print(base - mincut)

if __name__ == "__main__":
    solve()
```この実装では、各セルをノードにマップし、ソースとシンクが 2 つのクロップの選択肢をエンコードするフロー ネットワークを構築します。 基本値は、セルごとの楽観的な最大値を累積します。 ソースおよびシンクへのエッジは、ローカルでの最適な選択から逸脱した場合のペナルティをエンコードし、双方向エッジは隣接関係の不一致コストをエンコードします。 

よくある実装の落とし穴は、単項エッジの方向を逆にしてしまうことです。 正しい解釈は、ノードにヒマワリが割り当てられている場合はソースからノードへのエッジがコストを表し、小麦が割り当てられている場合はノードからシンクへのエッジがコストを表すということです。 カットではソース側からシンク側に交差するエッジに対してのみ支払いが行われるため、この方向が重要です。

 最終的な答えは、16 から計算されたカット コスト調整を引いたもので、サンプル出力と同様に 16 になります。

 ## 特殊なケース

 サイズ 1x1 の最小グリッドには隣接関係ペナルティがないため、アルゴリズムは A と B の最大値を選択することになります。最小カットは単項エッジのみを評価し、カットでは安価な側が正しく選択されるため、フロー ネットワークは引き続き機能します。 

すべてのエッジでペナルティがゼロのグリッドは、セルごとに独立した決定に折りたたまれます。 この場合、すべてのペアワイズ エッジの容量はゼロであるため、カットに影響を与えることはなく、各ノードはその単項エッジによってのみ決定され、セルごとの最大値の予想される合計と一致します。 

非常に多額の罰金が科せられる訴訟では、世界的な一貫性が求められます。 一部のセルが個別にもう一方のクロップを優先する場合でも、コストのかかるカットを回避できる場合、最小カットではすべてのノードを片側に揃えることが優先されます。 多くの大容量エッジを切断すると、単一のコストを支払うよりもコストが高くなるため、フローの定式化ではこのトレードオフを自然に把握できます。
