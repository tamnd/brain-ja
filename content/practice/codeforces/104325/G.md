 ## 解決策
 ## 問題の理解

 私たちは円形の配置の前に立っています。$N$ドア。 どのドアからも$x$、単一タイプのアクションを実行できます: ステップ サイズを選択します$i$そして正確に動く$i$前方に位置し、ドアを通過するときに回り込みます$N$。 このような各ステップ サイズには固定コストがかかります$C_i$、すべてのコストはステップ サイズが増加しても単調に増加しないため、長いジャンプが短いジャンプよりも高価になることはありません。 

ドア 1 から始めますが、移動だけではすべてが自動的に「ロック解除」されるわけではありません。 ドアは、移動後に着地した瞬間に開いたものとみなされます。 目標は、すべてのドアが少なくとも 1 回は訪問されるようにジャンプのシーケンスを選択し、総コストを最小限に抑えることです。 

重要な構造上の制約は、ドア間の任意の遷移を選択していないことです。 すべての動きは、小さなメニューから選択された固定長のジャンプです。$N$オプションがあり、ジャンプの使用頻度に関係なく、ジャンプを使用するたびにそのコストが全額支払われます。 

入力サイズが到達しました$10^5$これにより、一連の訪問を明示的にシミュレートしたり、ジャンプ選択肢のすべてのサブセットを試行したりするソリューションは除外されます。 二次関数の何か$N$すでに遅すぎますし、$O(N \log N)$構造はローカルではなくグローバルであるため、ソリューションは慎重に正当化される必要があります。 

単純な考え方による微妙な失敗例は、最適なジャンプ サイズを 1 つ選択してそれを繰り返すだけでよいと想定した場合に現れます。 たとえば、コストに関しては、$[5, 4, 3, 2]$ステップ 4 だけを繰り返し選択するのは魅力的に見えますが、サイクル内で 1 つの位置のみを訪問し、ステップ サイズが互いに素でない場合はすべてのノードをカバーすることはありません。$N$。 誤解を招きやすいもう 1 つのケースは、貪欲に利用可能な最も安価なステップを常に選択することが最適であるように見えますが、小さなステップを繰り返すと、合計使用回数が増加する冗長なサイクルに陥る可能性がある場合です。 

本当の難しさは、適用範囲がコストの順序だけではなく、モジュール構造に依存することです。 

## アプローチ

 強引なアイデアでは、可能なジャンプのシーケンスをすべてシミュレートし、訪問した位置を追跡しようとします。 各状態 (現在の位置と訪問したマスク) から、すべてのステップ サイズを試すことができます。 訪問されたセットにはサイズがあるため、これはすぐに指数関数的になります$2^N$、ビットマスクを無視しても、パスの数はサイクルによって爆発的に増加します。 

もう少し素朴な試みは、ステップ サイズのサブセットを選択し、それを使用してすべての剰余モジュロをカバーする方法を決定するという観点から考えることです。$N$。 しかし、それでも、選択したセットがサイクル全体を生成するかどうかを確認するには、gcd 構造とステップの組み合わせについての推論が必要です。これは、問題が組み合わせ検索ではなく、基本的に数論に基づいていることを示唆しています。 

重要な洞察は、視点を逆転させることで得られます。つまり、円上のパスについて考える代わりに、選択したステップ サイズによって作成される個別の「コンポーネント」の数について考えます。 ステップサイズ$i$円を分割します$\gcd(N, i)$ばらばらのサイクル。 ステップを使う場合$i$、それらのサイクル内でのみ探索します。 最終的にすべてを訪問するには、複合効果によってこれらすべてのサイクルが時間の経過とともに単一の接続された走査にマージされるように、十分なステップが必要です。 

コストはステップ サイズに応じて単調に減少するため、コストの点では、ステップが大きいほど常に小さいステップと少なくとも同じくらい優れています。 これは、可能な限り大きなステップに依存する必要があることを示唆していますが、大きなステップでは接続性が低下する可能性があります (gcd が大きい)。 ステップを小さくすると接続性が向上しますが、コストがかかります。 

問題は、総コストを最小限に抑えながら完全な接続を確保するために、最終的に gcd 効果が 1 になるステップ サイズのマルチセットを選択することです。 

これはまさに古典的な「gcd を 1 まで構築する」構造であり、各ステップ サイズが現在の状態の除数の削減に寄与します。 最適な戦略は、gcd 状態に対する DP として定式化できます。これまでに使用されたステップ セットの特定の gcd を達成するための最適なコストを追跡します。 

ステップ サイズを含めるコスト$i$は$C_i$、現在の gcd 状態から移行します$g$に$\gcd(g, i)$。 最小限のコストで gcd 1 で終了したいと考えています。 

なぜなら$N$までです$10^5$、gcd 状態を最大の値として扱うことができます。$N$、標準の除数グループ化を使用して遷移を最適化できます。

 ## アルゴリズムのチュートリアル

 1. 各ステップサイズを解釈します$i$現在の「接続状態」を$g$に$\gcd(g, i)$。 ステップを選択する前の最初の状態は次のとおりです。$N$、すべての位置を法的に考慮しているためです。$N$。 
2. DP 配列を定義します。`dp[g]`選択したステップ サイズの現在の gcd が次の値に等しい状態に到達するために必要な最小コストです。$g$。 初期化する`dp[N] = 0`まだ操作が選択されていないためです。 
3. ステップ サイズを 1 から 2 まで繰り返します。$N$。 ステップサイズごとに$i$、そのコストを考慮します$C_i$、そしてそれをすべての既存の gcd 状態に適用しようとします。 
4. 現在の各 gcd 状態について$g$、次の状態を計算します$ng = \gcd(g, i)$。 私たちはリラックスしようとします`dp[ng]`と`dp[g] + C_i`。 これはステップの追加を表します$i$私たちが選んだセットに。 
5. ステップ サイズの昇順で状態を処理するか、同じ反復内で遷移が再利用されないように DP の一時コピーを維持し、各ステップが 1 回だけカウントされるようにします。 
6. すべてのステップ サイズを処理すると、答えは次のようになります。`dp[1]`、gcd 1 はすべての残基が到達可能な完全に接続された構造に対応するためです。 

これが機能する理由は、gcd 進化がモジュラー サイクルのステップ サイズによって引き起こされる接続性を完全に捕捉しているためです。 一連のステップによって、次のサブグループが定義されます。$\mathbb{Z}_N$、そのサブグループのサイズは、選択したステップ サイズと gcd によって正確に決定されます。$N$。 gcd 1 を達成することは、完全な循環グループを生成することと同等であり、これはすべてのドアに到達可能であることを意味します。 DP 状態では各ステップが最大 1 回選択されるため、完全なグループを生成する最小の総コストを持つステップ サイズのサブセットを効果的に選択することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = list(map(int, input().split()))
    
    # dp[g] = min cost to achieve gcd-state g
    INF = 10**18
    dp = [INF] * (n + 1)
    dp[n] = 0

    for i in range(1, n + 1):
        cost = c[i - 1]
        new_dp = dp[:]  # do not reuse updated states in same iteration
        
        for g in range(1, n + 1):
            if dp[g] == INF:
                continue
            ng = gcd(g, i)
            if dp[g] + cost < new_dp[ng]:
                new_dp[ng] = dp[g] + cost
        
        dp = new_dp

    print(dp[1])

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

if __name__ == "__main__":
    solve()
```この実装は、可能な gcd 状態にわたって完全な DP を維持し、各ステップ サイズを使用してそれらを 1 回だけ更新します。 一時配列により、1 回の反復で同じステップを複数回連鎖適用することがなくなり、無制限の再利用が誤ってシミュレートされます。 

gcd 関数は、オーバーヘッドを回避し、ソリューションを厳密な制限内に保つために手動で実装されます。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$N = 1$。 唯一の行動はステップ 1 であり、答えは自明です$C_1$単一のノードを超えた移動の概念がないためです。 

もう 1 つのエッジケースは次のような場合です$C_N$他と比べて非常に小さいです。 そのような場合、ステップを選択すると、$N$すべての遷移をただちに 1 つのサイクルにまとめて、gcd を次と等しくします。$N$、その後、それ以上の削減は不可能になります。 dp は次から移行するため、アルゴリズムはこれを正しく処理します。$N$直接に$\gcd(N, N) = N$状態が変化しないため、誤った過剰カウントが防止されます。 

3 番目のケースは、すべてのコストが等しい場合です。 次に、ソリューションは、gcd を急速に削減する最小限のステップのセットを選択する傾向があり、DP は、状態を改善せずにコストが増加するだけであるため、冗長なステップが答えを改善しないことを保証します。
