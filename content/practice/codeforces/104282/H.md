 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$各セルにケーキが含まれているか空であるグリッド。 課題は、総合的な満足度を最大化しながら、すべてのケーキを食べることです。 可能なアクションは 2 つあります。 1 回のアクションでケーキを 1 個食べ、一定の報酬が得られます$p$。 もう 1 つのアクションは、縦または横に隣接する 2 つのケーキを食べて報酬を与えます。$q$、これは 2 つのシングルケーキ操作を置き換えます。 

問題は基本的に、隣接するペアのサブセットを選択して二人食い操作に「マージ」し、残りのケーキはすべて個別に取り出すことにあります。 各ケーキは、単独で、またはペアの一部として、正確に 1 回消費される必要があるため、すべての 1 セルをシングルトンと、グリッドによって引き起こされる隣接グラフのエッジに効果的に分割しています。 

グリッドのサイズは最大です$300 \times 300$、つまり最大 90,000 セルです。 これにより、ペアリングのサブセットを列挙しようとしたり、指数関数的なマッチングを実行したりするアプローチは即座に除外されます。 おおよその解決策は、$O(nm \cdot \text{something linear})$または$O(V + E)$テストごとは許容されますが、マッチングの組み合わせ探索を伴うものは許容されません。 

微妙な点は、隣接するケーキをできるだけ多くペアにする必要はないということです。 ペアリングが有益かどうかは、完全に以下の比較に依存します。$q$そして$2p$。 もし$q < 2p$、ペアリングはシングルを2つ取るよりも悪いです。 もし$q > 2p$、ペアリングは常に優れていますが、隣接構造による制約があり、各セルは最大 1 回しか使用できないため、すべてのセルを任意にペアリングすることはできません。 

ケーキが小さな接続コンポーネントを形成し、ペアリングの機会が限られている場合、エッジケースが発生します。 たとえば、隣接する 2 つのケーキのみを考えてみましょう。 もし$q < 2p$、答えは$2p$、しかし、常にペアにする単純な貪欲な人は、誤って取る可能性があります$q$。 もう 1 つのエッジケースは、3 つのケーキが並んだものです。 ペアリングが有益な場合は、1 つのペアのみを選択し、1 つはシングルのままにします。 どのペアを選択するかは無関係ですが、誤った貪欲マッチングが過大評価を試みる可能性があります。 

## アプローチ

 ブルートフォースパースペクティブは、各ケーキがノードでありエッジが隣接するケーキを接続するグラフとしてグリッドを扱います。 エンドポイントを共有するエッジが 2 つ存在しないようにエッジのセットを選択し、合計の重みを最大化する必要があります。エッジの選択により、$q$ノードを一致しないままにしておくと、貢献します$p$。 

これはまさに一般的なグラフにおける最大重み合わせ問題です。 単純なブルート フォースでは、すべてのマッチングを試行します。各ノードについて、一致しないままにするか、隣接するノードの 1 つと一致させ、残りのグラフを再帰的に実行して、最良の結果を計算します。 グリッドが完全に埋め尽くされた最悪のケースでは、各ノードには最大 4 つの選択肢があり、再帰が大幅に分岐するため、次のような指数関数的な複雑さが生じます。$O(2^{nm})$精神的に。 これは 90,000 ノードではまったく不可能です。 

重要な観察は、すべてのノードの重みが同一であり、エッジが均一であることです。 この決定は、エッジを使用することで 2 つのシングルと比較して合計値が向上するかどうか以外は、構造に局所的に依存しません。 これにより、真のマッチング問題を解決する必要がなくなります。 代わりに、唯一の意味のある選択は、有益な場合に有効なマッチングでできるだけ多くのエッジを使用するかどうかです。 

コストを比較すると、シングルを 2 つとると次のようになります。$2p$、ペアリングすると$q$。 もし$q \le 2p$、ペアリングは決して有益ではないので、私たちは単にすべてのケーキを個別に受け取ります。 もし$q > 2p$、ケーキによって引き起こされるグリッドサブグラフ内の互いに素な隣接ペアの数を最大化したいと考えています。 これは、グリッド セルの市松模様の色付けによって形成される 2 部グラフの最大一致の問題になります。 

グリッド グラフは 2 部構成であるため、標準フローまたは DFS ベースの 2 部マッチングを使用して最大マッチングを計算できます。 各ケーキ セルは 4 方向に隣接するセルに接続し、できるだけ多くのエッジを一致させます。

 ## アルゴリズムのチュートリアル

 私たちは、次のような比較に基づいて問題を 2 つの領域に分割しました。$q$そして$2p$。 

1. グリッド内にケーキが何個存在するかを数えます。 これは、すべてを個別に考える場合のベースラインを示します。 
2. もし$q \le 2p$、ケーキの合計に次の値を掛けたものをすぐに返します。$p$。 これは、どのペアリングでも総報酬が減少するか改善されないため、どのペアリングも決して役に立たないためです。 
3. もし$q > 2p$では、ケーキの各セルが頂点となるグラフとしてグリッドをモデル化します。 グリッドをチェス盤パターンで色付けして、2 つのパーティションを取得します。 
4. 隣接するケーキセル間のエッジを反対色の反対側で接続します。 これにより、グラフが 2 部構成になることが保証されます。これは、標準のマッチング アルゴリズムをきれいに適用するために必要です。 
5. このグラフで最大の 2 部マッチングを計算します。 一致した各エッジは、2 つのシングルを 1 つのペア操作で置き換えることを表し、追加の$q - 2p$個別に扱いすぎます。 
6. 最終的な答えはケーキの合計時間として計算されます。$p$、一致するサイズの倍を加えたもの$(q - 2p)$。 

この分解の背後にある理由は、すべてのケーキが個別に取得されるベースラインから開始し、その後、一致する各エッジが 2 つの単一寄与を 1 つのペア寄与にアップグレードするということです。 

### なぜ効果があるのか

 すべての有効な戦略は、ケーキ セルのセットをシングルトンと互いに素な隣接するペアに分割します。 これは、隣接グラフのマッチングに正確に対応します。 あらゆるソリューションの価値は、$p \cdot (\text{number of nodes}) + (q - 2p) \cdot (\text{number of matched edges})$。 以来$p$がすべてのノードにわたって一定であるため、合計値の最大化は、マッチングのエッジ数の最大化につながります。$q > 2p$、それ以外の場合はエッジを選択しません。 マッチング制約により、セルが再利用されないことが保証されるため、すべての実行可能なソリューションは有効なマッチングに対応し、その逆も同様です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m, p, q = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    ones = []
    idx = [[-1] * m for _ in range(n)]

    for i in range(n):
        for j in range(m):
            if grid[i][j] == 1:
                idx[i][j] = len(ones)
                ones.append((i, j))

    k = len(ones)

    if q <= 2 * p:
        print(k * p)
        return

    # build bipartite graph
    adj = [[] for _ in range(k)]

    dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

    for v, (i, j) in enumerate(ones):
        for di, dj in dirs:
            ni, nj = i + di, j + dj
            if 0 <= ni < n and 0 <= nj < m and idx[ni][nj] != -1:
                adj[v].append(idx[ni][nj])

    color = [(i + j) % 2 for i, j in ones]

    match_to = [-1] * k

    def dfs(v, vis):
        for u in adj[v]:
            if vis[u]:
                continue
            vis[u] = True
            if match_to[u] == -1 or dfs(match_to[u], vis):
                match_to[u] = v
                return True
        return False

    matching = 0
    for v in range(k):
        if color[v] == 0:
            vis = [False] * k
            if dfs(v, vis):
                matching += 1

    ans = k * p + matching * (q - 2 * p)
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まずグリッドをケーキ セルのリストに圧縮し、それぞれにインデックスを割り当てます。 これにより、空のセルの処理が完全に回避され、隣接性チェックが高速に行われます。 

二部マッチングは、標準の DFS 拡張パス アプローチを使用して実装されます。 重複した作業を避けるために、DFS は 1 つのカラー クラスからのみ開始します。 の`match_to`配列は、どの左側の頂点が現在各右側の頂点に一致しているかを格納します。 DFS が成功するたびに、一致するサイズを 1 つ増やす拡張パスが見つかります。 

最終的な式は、ベースラインと改善の構造を直接反映しています。 よくある実装の落とし穴は、マッチ サイズを合計スコアに変換するときに、ベースラインの二重カウントを差し引くのを忘れることです。 ここの式では、ベースラインから明示的に構築することでそれを回避しています。

 ## 特殊なケース

 特殊なケースの 1 つは、ケーキがまったくない場合です。 アルゴリズムはこれを次のようにマッピングします$k = 0$、ベースラインと一致する寄与の両方が消えるため、すぐにゼロが生成されます。 

別のケースは、すべてのケーキが分離されている場合です。 たとえ$q > 2p$、隣接グラフにはエッジがないため、一致するサイズはゼロとなり、結果は残ります。$k \cdot p$。 隣接リストが空であるため、DFS マッチングでは拡張パスが正しく検出されません。 

最後のケースは、完全に塗りつぶされたグリッドです。$q \le 2p$。 グラフが密であっても、アルゴリズムはマッチングの構築を完全に回避し、直接返します。$k \cdot p$、不必要な計算を防ぎ、大きな入力に対する時間制限を回避します。
