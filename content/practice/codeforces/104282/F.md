 ## 解決策
 ## 問題の理解

 最大 8 つの人々のグループが与えられ、各グループには固有の名前が付けられた個人の小さなセットが含まれます。 複数のグループに分かれて出現する個体もいます。 これらのグループから正確に k 個を選択し、それらのグループにメッセージを送信する順序を決定する必要があります。 

グループがメッセージを受信すると、そのメンバーは名前の辞書編集順にお金を寄付します。 各個人には、すべてのグループにわたって 50 というグローバルな上限があります。つまり、ある人が以前に処理されたグループですでにある程度の金額を寄付した後は、50 制限の残りの部分までしか寄付することができません。 1 つのグループ内では、収集される合計の上限も 114 であるため、多くの人がまだキャパシティに余裕がある場合でも、そのグループについては 114 で停止します。 

重要な相互作用は、限られた予算をより早く寄付できる発注グループが変わることです。 ある人が複数の選択されたグループに参加している場合、グループを早めに送信すると、そのグループの 50 人のキャパシティの一部が「消費」され、他の場所への将来の貢献が削減される可能性があります。 

タスクは、k 個のグループを選択し、集められたお金の合計が最大になるようにそれらに命令することです。 

制約は非常に小さく、n ≤ 8、各グループの人数は最大 10 人です。 これは、サブセットと順列の列挙を含むあらゆる解決策が実行可能であることを直ちに示唆しています。 8でも！ はわずか 40320 であり、小さなリストのグループごとの処理と組み合わせると、順序付けに対するブルート フォースが許容されます。 

主な微妙なエッジケースは共有メンバーです。 同じ名前が複数のグループに出現する場合、貢献度は以前の消費に依存します。 各グループを個別に計算するか、固定グループ値を想定する単純な解決策ではオーバーカウントされます。 

もう 1 つの微妙なケースは、グループ内の辞書編集的な順序から発生します。 名前は事前にソートされていないため、貢献をシミュレートする前に名前をソートする必要があります。ソートしないと、部分消費の順序が変更され、間違った上限が適用されることになります。 

## アプローチ

 直接的な総当たりの解決策は、k 個のグループを選択するすべての方法を試してから、それらの選択されたグループのすべての順列を試みることです。 注文ごとにプロセスをシミュレートします。各人がすでに世界中でどれだけ貢献したかを追跡する辞書を維持します。 各グループについて、そのメンバーを辞書順に処理し、各メンバーが min (残りの容量、50 から既に指定されている値を引いた値) を提供し、同時に 114 に達するとグループを停止します。 

これはルールを正確にモデル化しているため、正しく機能します。 ただし、グループと順列の組み合わせによってコストが増加します。 順列の数は最大 8 です。 選択すると係数 C(8, k) が追加されるため、扱いやすくなります。 

さらに、n が非常に小さいため、問題をサブセットと順列にわたる状態 DP に分割することさえ不要であることがわかります。 選択されたセットに対する単純なビットマスク DP と順列列挙で十分です。 k ≤ 8 であるため、最悪の場合の複雑さは小さいままです。 

重要な考え方は、重要な世界状態は各個人がどれだけ貢献したかだけであるということです。 すべてのグループにわたって合計で最大 80 個の個別の名前 (8 × 10 で区切られる) が存在するため、シミュレーション中に辞書またはマップを維持できます。 各順列評価は独立しています。 

列挙を超えた枝刈りやメモ化を必要とするには制約が小さすぎるため、より深い組み合わせ最適化は必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 + シミュレーション | O(n! · n · m log m) | O(名前の合計) | 承認済み |
 | サブセット全体にわたる最適化された DP (オプション) | O(2^n · n! · m log m) | O(名前の合計) | 承認済み |

 ## アルゴリズムのチュートリアル

 k 個のグループのサブセットを修正し、可能な順序をすべて試します。

1. n 個のグループからサイズ k のすべてのサブセットを生成します。 各サブセットは、グループの可能な選択を表します。 
2. サブセットごとに、そのグループのすべての順列を生成します。 各順列は処理順序の候補です。 
3. 固定順列の場合、マップを初期化します。`paid[name] = 0`各人がすでに世界中でどれだけ貢献したかを追跡するため。 
4. グループを順列順に 1 つずつ処理します。 
5. グループを処理する前に、そのメンバー名を辞書順に並べ替えます。 貢献はこの順序に依存するため、これが必要です。 
6. カウンタの初期化`group_sum = 0`現在のグループの場合。 
7. ソート順に各人ごとに次のようにします。 

彼らがまだどれだけ与えることができるかを計算します。`give = min(50 - paid[name], 114 - group_sum)`。 

もし`give > 0`、両方に追加します`paid[name]`そして`group_sum`。 

場合は早めに中止してください`group_sum == 114`、グループの上限に達したため。 
8. すべての順列にわたる最大合計を追跡します。 

これが機能する理由は、すべての有効な戦略が選択したサブセットの 1 つの順列に正確に対応し、シミュレーションがローカル (114 キャップ) とグローバル (1 人あたり 50 キャップ) の両方の制約を尊重するためです。 順序が固定されると寄与は決定的になるため、徹底的な検索により最適性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from itertools import combinations, permutations

def calc(order, groups):
    paid = {}
    total = 0

    for idx in order:
        members = sorted(groups[idx])
        group_sum = 0

        for name in members:
            prev = paid.get(name, 0)
            if prev >= 50 or group_sum >= 114:
                continue

            give = min(50 - prev, 114 - group_sum)
            if give > 0:
                paid[name] = prev + give
                group_sum += give
                total += give

                if group_sum == 114:
                    break

    return total

def solve():
    n, k = map(int, input().split())
    groups = []
    for _ in range(n):
        arr = input().split()
        m = int(arr[0])
        groups.append(arr[1:])

    ans = 0

    for comb in combinations(range(n), k):
        for perm in permutations(comb):
            ans = max(ans, calc(perm, groups))

    print(ans)

if __name__ == "__main__":
    solve()
```ソリューションの中核となるのは、`calc`グループの 1 つの固定順序を忠実にシミュレートする関数。 辞書`paid`一人当たりの累積貢献度を保存します。 各グループ内で並べ替えることにより、グループが処理されるたびに辞書編集上の順序が正しく適用されるようになります。 早めの休憩のとき、`group_sum`ヒット 114 により、不必要な反復が防止されます。 

外側のループは、すべての有効な選択肢と順序を列挙します。 n は最大 8 であるため、これは計算上安全です。

 ## 特殊なケース

 主なエッジケースは、すべてのグループに同じ人物が含まれている場合です。 その場合、どの順列でも最初のグループのみが最大 50 個を抽出でき、残りのグループは何も寄与しません。 アルゴリズムはこれを処理します。`paid[name]`最初の露光後すぐに飽和します。 

もう 1 つのエッジ ケースは、グループに多数の小規模な貢献が含まれており、メンバーが使い果たされる前に合計が正確に 114 になる場合です。 早期の中断により、上限を超えて誤って寄付を追加し続けることがなくなります。 

最後のエッジケースは、ある人が複数のグループに所属しているが、辞書順に 1 つのグループでは遅く、別のグループでは早い場合です。 グループごとに並べ替えることで、順序の一貫性が確保され、グローバルな`paid`状態により、グループ間の依存関係が正しく適用されることが保証されます。
