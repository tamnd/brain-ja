 ## 解決策
 ## 問題の理解

 飛行機上の一連の敵の位置が与えられ、すべてキャラクターが立っている原点を基準にして測定されます。 キャラクターは武器を回転させて方向を選択することができ、攻撃するたびに、その方向から始まる 45 度の固定角度セクター内にあるすべての敵を排除します。 セクターは原点に固定されているため、自由なのはこのウェッジをどのように回転させるかだけです。 

課題は、この 45 度のくさびの方向を選択して、その中にいる敵の数が最大になるようにすることです。 

キー入力は、-10⁴ ～ 10⁴ の範囲の座標で最大 100,000 点です。 これにより、点のペアまたは 3 つによって定義されるすべての可能なウェッジ方向をテストしようとするソリューションは即座に除外されます。これは、候補方向ごとの単純な角度比較が 2 次またはさらに悪い動作につながるためです。 

境界動作に微妙な問題が発生します。 45 度のくさびを形成する 2 本の光線上に正確に位置する点を数えなければなりません。 これは、角度の定式化では等価性を慎重に処理する必要があるため、重要です。そうしないと、浮動小数点の比較に応じて、境界上の点が失われたり二重にカウントされたりする可能性があります。 もう 1 つのエッジ ケースは垂直方向と水平方向で、ゼロによる除算や精度の不安定性により単純な傾き計算が失敗します。 

小さな例で境界感度を示します。 点 (1, 2)、(2, 1)、および (1, 1) がある場合、y = x の線に沿って適切に配向されていれば、45 度の最適なくさびには 3 つすべてが含まれます。 浮動小数点の角度に依存する単純なアプローチでは、精度誤差により境界に位置合わせされたポイントが除外される可能性があります。 

## アプローチ

 強引なアイデアは、すべての敵のポイントをウェッジの 1 つの境界光線の候補方向として扱うことです。 このような方向ごとに、別の境界光線を 45 度離れてスイープし、その間にある点の数を数えることができます。 それぞれの固定方向について、すべての点をチェックするには O(n) かかり、すべての n 方向を試すには O(n²) がかかります。これは最悪でも約 10¹⁰ の操作に相当し、制限時間内に実行されません。 

重要な観察は、座標を変更するとジオメトリが単純になるということです。 平面内に配置された 45 度のくさびは、座標の違いを伴う条件に対応します。 平面を 45 度回転すると、ウェッジは、変換された座標系で軸に沿った間隔制約に変わります。 

具体的には、変換された座標を定義します。 

u = x + y および v = x − y。 

元の平面の 45 度の角度セクターは、v の順序を尊重するか、単調な配置を同等に処理しながら、u 値がウェッジ方向に比例する長さの範囲内にある点を選択することに対応します。 変換後、問題は、ソートされた角度表現、または同様にソートされた方向角のスライディング ウィンドウでカバーできる点の最大数を見つけることに帰着します。 

より堅牢な解釈では、三角法を完全に回避します。各点は角度 θ = atan2(y, x) を定義します。 くさびの問題は次のようになります。長さ π/4 の範囲内に角度がある点の最大数を見つけます。 すべての角度を並べ替え、円形配列上で 2 ポインター スイープを使用します (2π を追加して角度を複製します)。 これにより、問題は固定角度ウィンドウ内の古典的な最大点に変わります。 

角度がソートされると、π/4 を超えるまでウィンドウを拡大し、その後ウィンドウを縮小すると、すべてのエンドポイントにわたって線形スキャンが維持されるため、スイープが機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 角度ソート + 2 つのポインター | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 幾何学的な方向を 1 次元の角度順序に変換することで、この問題を解決します。

1. atan2(y, x) を使用してすべての点の角度を計算します。 これにより、範囲 (−π, π] の値が得られます。このステップでは、幾何学的方向をソート可能なスカラーに変換します。これは、角度の包含が間隔の包含になるため重要です。
 2. 角度を一貫した範囲 (通常 [0, 2π)] に正規化して、円形のラップアラウンドをきれいに処理できるようにします。 
3. すべての角度を昇順に並べ替えます。 このリスト内の任意の連続セグメントが角度空間内の連続スイープに対応するように、ソートが必要です。 
4. 各角度に 2π を加えて配列を拡張します。 この重複により、複雑なモジュラー演算を行わずにラップアラウンド間隔を処理できるようになります。 
5. 2 ポインターのスライディング ウィンドウを使用します。 angle[r] と angle[l] の間の角度差が最大でも π/4 である間、展開する右ポインタを維持します。 これにより、ウィンドウ内のすべての点がウェッジ制約の下で有効になることが保証されます。 
6. 左ポインタの位置ごとに、有効な右拡張子の最大値を計算し、r − l + 1 で答えを更新します。次に、左ポインタを前方に移動して続行します。 
7. 見つかった最大ウィンドウ サイズを返します。 

スライディング ウィンドウを安全に使用できる理由は、並べ替え後に右ポインタを展開しても角度スパンが増加するだけだからです。 スパンが π/4 を超えると、左ポインタを移動しない限り、その固定された左端点に対して再び有効になることはありません。 

### なぜ効果があるのか

 正確さは、有効なウェッジが最大 π/4 の長さの角度の間隔に正確に対応するという事実に依存します。 このようなすべての間隔は、その中の最小角度に等しい開始角度によって表すことができます。 その開始角度の場合、最適解は前方の π/4 以内にある点の最大の連続ブロックです。 ソートでは角度順序が保持されるため、すべての有効なサブセットはソートされた double 配列内の連続したセグメントとして表示され、2 ポインター スキャンはそのようなセグメントをすべて暗黙的に列挙します。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    n = int(input())
    angles = []
    
    for _ in range(n):
        x, y = map(int, input().split())
        ang = math.atan2(y, x)
        if ang < 0:
            ang += 2 * math.pi
        angles.append(ang)
    
    angles.sort()
    
    # duplicate for circular wrap
    extended = angles + [a + 2 * math.pi for a in angles]
    
    ans = 0
    r = 0
    window = math.pi / 4
    
    for l in range(n):
        while r < len(extended) and extended[r] - extended[l] <= window + 1e-12:
            r += 1
        ans = max(ans, r - l)
    
    print(ans)

if __name__ == "__main__":
    solve()
```実装の中核は、atan2 を使用した角度への変換であり、これにより、すべての傾斜ベースの不安定性が回避されます。 正規化ステップにより、すべての角度が単一の円形スケール上で比較可能であることが保証されます。 配列の複製により、350 度に近い角度と 10 度に近い角度を組み合わせたようなラップアラウンド ウィンドウを、特別な場合を除いて処理できるようになります。 

2 ポインター ロジックは単調な右ポインターを慎重に維持するため、各要素は最大 2 回 (左境界として 1 回、右境界として 1 回) 処理されます。 

比較における小さなイプシロンにより、点が 45 度セクターの境界上に正確に位置する場合の浮動小数点精度の問題が回避されます。 

## 実用的な例

 点 (1, 2)、(2, 1)、および (1, 1) を考えてみましょう。 

角度に変換した後:

 | ポイント | 角度 (おおよそ) |
 | --- | --- |
 | (1,2) | 1.107 |
 | (2,1) | 0.464 |
 | (1,1) | 0.785 |

 ソートされた角度は [0.464, 0.785, 1.107] になります。 それらを [0.464, 0.785, 1.107, 6.747, 7.068, 7.389] として複製します。 

サイズ π/4 ≈ 0.785 のウィンドウをスライドさせます。 

| l | r | 角度[l] | 角度[r-1] | スパン | ウィンドウサイズ |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 3 | 0.464 | 1.107 | 0.643 | 3 |
 | 1 | 3 | 0.785 | 1.107 | 0.322 | 2 |
 | 2 | 3 | 1.107 | 1.107 | 0 | 1 |

 最大値は 3 で、すべてのポイントを 45 度のウェッジでカバーできることを意味します。 

このトレースは、角度空間で点がソートされると、最適なウェッジが連続セグメントに対応し、スライディング ウィンドウがそれを正しくキャプチャすることを示しています。 

(1,0)、(0,1)、(-1,0)、(0,-1) など、大きく離れた点を含む 2 番目の例では、どの π/4 区間にも 3 つの点が含まれず、ウィンドウのピークが 1 に正しく設定されていることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 並べ替え角度が優先され、スライディング ウィンドウは直線的です |
 | スペース | O(n) | 角度リストと複製された配列を格納 |

 n が最大 100,000 であれば、ソートは容易に十分に高速になり、線形スイープは無視できます。 少数の浮動小数点配列のみを保存するため、メモリ使用量は十分に制限内にあります。

 ## 特殊なケース

 45 度セクターの境界に非常に近い点は、浮動小数点の堅牢性をテストします。 たとえば、(1, 100) や (100, 1) のような点は、π/4 境界に非常に近い角度を生成します。 アルゴリズムは、比較において小さなイプシロンを介してこれを処理し、境界の包含が一貫していることを保証します。 

0 に近い角度や 2π に近い角度などのラップアラウンドの場合は、配列を複製することで処理されます。 複製がないと、角度 0 にまたがるウェッジが、誤って 2 つの切断されたセグメントに分割されて表示されます。 拡張配列はこれらのケースを単一の連続ウィンドウにマージし、スライディング ポインターは有効な間隔の一部としてそれらを自然に取得します。
