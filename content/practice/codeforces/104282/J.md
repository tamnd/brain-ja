 ## 問題の理解

 次の配列から始めます$n$数字。 最初は、各要素は個別のセグメントとして独立しています。 このプロセスでは、隣接する 2 つのセグメントを繰り返し選択し、それらを 1 つにマージし、その新しいセグメントに、その中のすべての要素の合計に等しい値を割り当てます。 各マージの後、このセグメント値が累計に追加されます。 まさにその後$n-1$マージすると、すべてが 1 つのセグメントになります。 

重要な問題は、マージの順序が固定されていないことです。 隣接するマージの有効なシーケンスはどれでも許可され、シーケンスが異なると異なる中間セグメント履歴が生成され、累積合計が変わります。 タスクは、考えられるすべてのマージ シーケンスにわたる最終的な答えの合計を計算することです。 

制約$n \le 500$すぐに、二次または三次動的計画法は許容されるが、マージの順列にわたる指数関数的なものは許容されないことを示唆しています。 すべてのマージ順序を列挙する単純な試みは、カタルーニャ語のような多くのセグメント構造とマージ タイミングの追加のインターリーブがあり、直接シミュレーションが不可能になるため、非常に急速に成長します。 

微妙なエッジケースが現れるのは、$n = 1$。 マージはまったく行われないため、アキュムレータには何も追加されないため、答えはゼロになるはずです。 少なくとも 1 つのマージを前提としたソリューションは、ここで中断されます。 

もう 1 つの重要な例外ケースは、値が最大で大きくなる可能性があることです。$10^9$、セグメントの合計が次の値に達する可能性があります$10^{12}$、マージシーケンスの数も多くなります。 これにより、すべての中間計算が強制的にモジュロで実行されます。$998244353$そして全体を通してモジュラー演算を使用します。 

## アプローチ

 直接的な強引なアプローチでは、隣接するセグメントをマージするあらゆる可能なシーケンスをシミュレートしようとします。 各状態は配列のパーティションであり、各ステップで、マージするセグメントの隣接するペアの 1 つを選択します。 これにより、州の数がすぐに爆発的に増加します。 状態を効率的に表現したとしても、マージ シーケンスの数は膨大であり、バイナリ ツリーを構築するすべての方法を数えることに匹敵します。$n$内部操作を指示しながら退社します。 これは指数関数的よりも速く増加し、列挙が不可能になります。$n = 20$。 

重要な構造上の観察は、すべての有効なマージ プロセスが配列上のバイナリ ツリーとして表現できることです。 各リーフは要素であり、各内部ノードは連続した間隔にわたるマージを表します。 ルートは最後の完全な間隔に対応します。 これが分かると、問題はそのようなバイナリ ツリーすべての合計になりますが、さらに複雑になります。各ツリーは、左右のサブツリーの独立したマージの相対的な順序に応じて複数の有効なマージ シーケンスに対応するため、異なるツリーが均等に寄与するわけではありません。 

これにより、2 レベルの動的プログラミング構造が生まれます。 まず、各間隔構造に対応するマージ シーケンスの数を数えます。 次に、それらのカウントによって重み付けされたセグメント合計の寄与を計算します。 

しばらくの間$[l, r]$、その内部の最後のマージを考慮します。これは、ある位置で間隔を分割します。$k$。 左の間隔$[l, k]$そして正しい間隔$[k+1, r]$最後のマージを除いて独立して進化します。 重要な組み合わせ要素は、有効性を維持しながら、左右の部分問題からのマージ操作を時間内にどのようにインターリーブできるかです。 これにより、内部マージ ステップのインターリーブに基づいて二項係数が生成されます。 

2 つの DP テーブルを維持します。 1 つは、各間隔の有効なマージ シーケンスの数を保存します。 もう 1 つは、合計寄与率 (すべてのシーケンスにわたって累積されたセグメントの合計の合計) を保存します。 両方を分割構造を使用して結合します。

 ## アルゴリズムのチュートリアル

 私たちは定義します$f[l][r]$間隔を完全に構築する有効なマージ シーケンスの数として$[l, r]$、 そして$g[l][r]$そのようなすべてのシーケンスにわたって累積された合計の答えとして。 

また、プレフィックスの合計を事前計算して、任意の間隔の合計を取得できるようにします。$O(1)$、二項係数を計算する階乗および逆階乗。 

### 1. 区間の合計と組み合わせを事前計算する

 次のようにプレフィックスの合計を計算します。$\text{sum}(l, r)$一定時間で利用可能です。 階乗および逆階乗モジュロも事前計算します。$998244353$二項係数を迅速に評価します。 

これが必要なのは、すべての遷移が左右のサブツリーからのマージがどのようにインターリーブするかをカウントすることに依存しているためです。 

### 2. 単一要素の基本ケース

 どれについても$l = r$、マージは必要ないため、間隔とゼロ寄与を構築する方法は 1 つだけです。 

それで$f[l][l] = 1$そして$g[l][l] = 0$。 

より長い間隔は最終的に単一の要素に分解されるため、これにより DP が固定されます。 

### 3. 最後のマージポイントによって間隔を分割する

 インターバルごとに$[l, r]$、分割ポイントを選択します$k$最後のマージが結合する場所$[l, k]$そして$[k+1, r]$。 

以下を定義します。$$m = r - l + 1$$この間隔内の内部マージの合計数は次のとおりです。$m - 1$。 最後のマージが修正されたため、残りを配布します。$m - 2$左と右の部分問題をマージします。 

左翼が貢献$lenL - 1$内部マージ、右貢献$lenR - 1$、これらの操作は任意にインターリーブできます。 有効なインターリーブの数は次のとおりです。$$\binom{m-2}{lenL-1}$$### 4. マージシーケンスの数を計算します。$f[l][r]$分割ごとに$k$、左右を独立して組み合わせます。$$f[l][r] += f[l][k] \cdot f[k+1][r] \cdot \binom{m-2}{lenL-1}$$これは、この分割と一致するすべての有効なマージ シーケンスをカウントします。 

### 5. 貢献度 DP を計算する$g[l][r]$各マージ シーケンスは次の 2 つの方法で貢献します。 

左側と右側のパーツは内部コストに寄与するため、次のように追加します。$$g[l][k] + g[k+1][r]$$次に、最後のマージを考慮します。$[l, r]$、追加します$\text{sum}(l, r)$シーケンス全体に 1 回。 この分割のシーケンスの数は次のとおりです。$$f[l][k] \cdot f[k+1][r] \cdot \binom{m-2}{lenL-1}$$したがって、移行は次のようになります。$$g[l][r] += \binom{m-2}{lenL-1} \cdot \left(g[l][k] \cdot f[k+1][r] + f[l][k] \cdot g[k+1][r] + \text{sum}(l,r)\cdot f[l][k]\cdot f[k+1][r]\right)$$この構造は寄与をきれいに分離します。内部コストが伝播し、ルート マージによってシーケンスごとに一定間隔の合計が追加されます。 

### なぜ効果があるのか

 正確さは、すべての完全なマージ プロセスを配列上のバイナリ ツリーとして扱うことで得られ、内部ノードは連続した間隔でのマージに対応します。 固定間隔の場合、ルート分割を選択すると、ルート分割が左右のサブ問題に一意に分割されます。 残る唯一のあいまいさは、左右のサブツリーでの独立したマージの順序であり、これらは二項インターリーブ係数によって完全に特徴付けられます。 

すべてのマージ シーケンスは、バイナリ ツリーの選択とインターリーブ順序に一意に対応するため、DP は各可能性を 1 回だけ列挙し、有効なマージ スケジュールの数によって正しく重み付けされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    if n == 1:
        print(0)
        return
    
    prefix = [0] * (n + 1)
    for i in range(n):
        prefix[i + 1] = (prefix[i] + a[i]) % MOD
    
    def seg_sum(l, r):
        return (prefix[r + 1] - prefix[l]) % MOD
    
    N = n + 5
    fact = [1] * N
    invfact = [1] * N
    
    for i in range(1, N):
        fact[i] = fact[i - 1] * i % MOD
    
    invfact[N - 1] = pow(fact[N - 1], MOD - 2, MOD)
    for i in range(N - 2, -1, -1):
        invfact[i] = invfact[i + 1] * (i + 1) % MOD
    
    def C(n, k):
        if k < 0 or k > n:
            return 0
        return fact[n] * invfact[k] % MOD * invfact[n - k] % MOD
    
    f = [[0] * n for _ in range(n)]
    g = [[0] * n for _ in range(n)]
    
    for i in range(n):
        f[i][i] = 1
        g[i][i] = 0
    
    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1
            total = 0
            
            for k in range(l, r):
                lenL = k - l + 1
                lenR = r - k
                ways = C(lenL + lenR - 2, lenL - 1)
                
                left_f = f[l][k]
                right_f = f[k + 1][r]
                
                left_g = g[l][k]
                right_g = g[k + 1][r]
                
                sum_lr = seg_sum(l, r)
                
                total = (total + ways * (
                    left_g * right_f +
                    left_f * right_g +
                    sum_lr * left_f % MOD * right_f
                )) % MOD
            
            f[l][r] = 0
            for k in range(l, r):
                lenL = k - l + 1
                lenR = r - k
                ways = C(lenL + lenR - 2, lenL - 1)
                f[l][r] = (f[l][r] + ways * f[l][k] % MOD * f[k + 1][r]) % MOD
            
            g[l][r] = total
    
    print(g[0][n - 1] % MOD)

def main():
    solve()

if __name__ == "__main__":
    main()
```コードは間隔 DP を中心に構成されており、外側のループで間隔の長さが増加するため、すべての部分間隔がすでに計算されています。 機能`C`は、左部分問題と右部分問題の間のマージ操作のインターリーブを考慮するために頻繁に使用されます。 

DP アレイ`f`そして`g`数学的定義と直接一致します。 最もデリケートな部分は、最終的なマージの寄与に、構造的な分解だけでなく完全なシーケンスの正しい数を確実に乗算することです。これは結合によって処理されます。`left_f`そして`right_f`の中で`g`遷移。

 ## 特殊なケース

 のために$n = 1$の場合、アルゴリズムは DP を入力せずにすぐにゼロを返します。 マージが発生しないため、セグメント合計は加算されないため、これは定義と一致します。
