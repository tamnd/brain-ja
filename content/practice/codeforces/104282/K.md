 ## 解決策
 ## 問題の理解

 1 から n までの範囲から取得された 4 つの素数の特別なグループを数えるように求められます。 各グループは、4 つの数値がすべて素数であり、正確に 3 つの等しいギャップを持つ等差数列を形成するように、インデックス a、b、c、d で構成されます。 つまり、最初の素数 a とステップ サイズ ギャップを選択すると、残りの 3 つの値は、a + ギャップ、a + 2・ギャップ、および a + 3・ギャップとして完全に決定され、それらもすべて素数であり、n を超えてはなりません。 

入力は単一の整数 n で、使用できる値の範囲を定義します。 出力は有効な 4 倍の数です。 

n ≤ 10^6 という制約は、すべての 4 倍数を直接列挙しようとする解法は遅すぎることを強く示唆しています。 10^6 までの素数の数は約 78,000 で、その中のすべての 4 タプルをチェックすると、O(P^4) のオーダーになるため、すでに許容範囲をはるかに超えています。 最初にすべてのペアを試してみても、O(P^2) が得られます。これは境界線ですが、慎重に最適化すれば許容できる可能性があります。 ただし、ペアごとの単純なギャップ探索では、依然として TLE の危険性があります。 

重要な構造上の制約は、任意の 4 倍素素数を選択していないことです。 等差条件は、構造を長さ 4 の等差数列に崩壊させます。 つまり、すべての有効な解は、最初の要素とステップ サイズを選択することによって一意に決定されます。 

a < b < c < d は正のギャップによって暗黙的に示されるため、順序付けに関する難しい特殊なケースはありません。 唯一の微妙なエッジ ケースは境界オーバーフローから発生します。+ 3 · ギャップが n を超える場合、シーケンスは無効であり、カウントしてはなりません。 

単純な間違いは、一定の間隔を強制せずに、すべての素数を反復処理し、その後にあるすべての可能なトリプルを試行することです。 たとえば、単一の一貫したギャップを強制するのではなく、ペアごとの相対的な差異のみをチェックする場合、素数 (5、11、17、29) の選択が誤って考慮される可能性があります。 

## アプローチ

 直接的な強引なアプローチは、n までのすべての素数を生成し、その後、それらの 4 倍数ごとに昇順に試し、それらが等差数列を形成しているかどうかを確認することです。 これには、素数リストに対する 4 つのネストされたループが含まれます。 P 素数がある場合、このアプローチは P^4 / 24 チェックのオーダーで実行されますが、P が約 78,000 である場合、これは完全に実行不可能です。 

等差数列をその場でチェックすることに限定したとしても、a と b を固定し、c と d を強制しようとすると、依然として 3 次構造に直面します。 これは O(P^3) になりますが、それでも大きすぎます。 

重要な観察は、4 つの素数の等差数列が 2 つのパラメーター (最初の要素と差) によって完全に決定されるということです。 a と b を固定すると、差は b − a として強制され、残りの 2 つの値は一意に決定されます。 これにより、問題は a + 2d と a + 3d が素数であるかどうかを確認することに集約されます。 

これにより、問題は組み合わせ列挙から定数時間の素数チェックによる素数の構造化検索に移行します。 n までのふるいでは、各チェックは O(1) になり、候補ペア (a, b) の合計数は約 P^2 / 2 になります。これは、慎重に実装すれば最適化された Python で P ≈ 78,000 に対応できますが、それでも限界に近いです。 ただし、インデックスとして素数のみを反復処理し、数列が n を超えたときに早期に中断することで、不必要な作業を減らすことができます。 

この改善は、素数チェックを高速化するだけでなく、条件を完全な 4 倍体ではなくペアからの決定論的な構造に折りたたむことにも当てはまります。

 ## アルゴリズムのチュートリアル

 ## ステップ 1: n までのプライム ルックアップを構築する

まず、n までのエラトステネスのふるいを計算し、すべての数値を素数かどうかマークします。 これにより、後で定数時間の素数チェックが可能になります。これは、等差数列から導出された多くの候補値を検証することになるため、不可欠です。 

## ステップ 2: 素数のリストを抽出する

 素数とマークされた 2 から n までのすべての整数を配列に収集します。 これにより、等差数列の有効な開始点をコンパクトに表現できます。 

## ステップ 3: 進行の最初の要素を反復処理する

 リスト内の各素数 a について、それを長さ 4 の等差数列の開始候補として扱います。 目標は、ステップ サイズを定義する 2 番目の素数 b > a を選択することです。 

最初の要素を修正する理由は、すべての進行には昇順で一意の開始点があるため、これにより順列の過剰なカウントが回避されるためです。 

## ステップ 4: 2 番目の要素を選択し、ステップを計算します

 a の後の各素数 b について、d = b − a を定義します。 2 つの点が固定されると算術シーケンスは固定されるため、このステップで進行が完全に決まります。 

後で c を独立して選択しようとすると、等間隔の保証が失われるため、この削減は不可欠です。 

## ステップ 5: 残りの 2 つの要素を検証する

 c = b + d および d4 = c + d = a + 3·d を計算します。 ふるいを使用して、両方が ≤ n であり、両方が素数であるかどうかを確認します。 両方の条件が当てはまる場合、この 4 倍をカウントします。 

このステップは、無効な候補が除外される唯一の場所です。 ふるいは各チェックが O(1) であることを保証し、ソリューション全体の効率を維持します。 

## ステップ 6: カウントを蓄積する

 (a, b, c, d) は厳密に増加しており、(a, b) から一意に生成されるため、すべての有効な数列は 1 つのカウントに寄与します。 すべての有効なケースを合計し、結果を出力します。 

## なぜ機能するのか

 すべての有効な 4 倍数は、a < b である順序付きの素数のペア (a, b) の 1 つに正確に対応します。 このペアは差 d = b − a を一意に定義するため、残りの 2 つの要素を一意に定義します。 逆に、位置 a + 2d および a + 3d で有効な素数を生成するペアは、有効な解に対応します。 これにより、有効なクアドルプルと有効な生成ペアとの間に 1 対 1 のマッピングが確立され、過剰カウントや省略が発生しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    if n < 2:
        print(0)
        return

    is_prime = [True] * (n + 1)
    is_prime[0] = is_prime[1] = False

    i = 2
    while i * i <= n:
        if is_prime[i]:
            step = i
            start = i * i
            while start <= n:
                is_prime[start] = False
                start += step
        i += 1

    primes = [i for i in range(2, n + 1) if is_prime[i]]

    idx = {p: True for p in primes}

    m = len(primes)
    ans = 0

    for i in range(m):
        a = primes[i]
        for j in range(i + 1, m):
            b = primes[j]
            d = b - a
            c = b + d
            d4 = c + d

            if d4 > n:
                break

            if is_prime[c] and is_prime[d4]:
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```sieve セクションは、各インデックスが後で一定時間内に使用される素数クエリに直接応答するブール配列を構築します。 ネストされたループはすべての順序付き素数ペア (a、b) を反復処理しますが、4 番目の要素が n を超えると内側のループが早期に中断されるため、大きなギャップでの不必要なチェックが防止されます。 

c と d4 の計算では等差数列制約が直接エンコードされるため、3 番目と 4 番目の要素を明示的に反復する必要がありません。

 ## 特殊なケース

 n = 2 または n = 3 の場合、ふるいは素数を生成しますが、4 つの異なる素数が必要であるため、4 倍は可能ではありません。 素数リストが短すぎてペア (a, b) が存在できないため、アルゴリズムはすぐに 0 を返します。 

n = 10 のような小さな範囲の場合、ふるいは素数を正しく識別しますが、最小のギャップでもすぐに範囲外の値または素数以外の値が生成されるため、内側のループは有効な数列を形成しません。 d4 > n の早期ブレーク条件により、無効なアクセスが試行されなくなります。 

多くの素数が存在する大きな n の場合、すべての候補数列がふるいを使用して最後の 2 つの位置で明示的に検証され、不完全な算術構造チェックによる誤検知を防ぐため、アルゴリズムは依然として安全です。
