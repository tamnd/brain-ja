 ## 解決策
 ## 問題の理解

 頂点 1 がルートであるルート付きツリーが与えられます。 各頂点には値が含まれており、クエリごとに特定のサブツリー内で作業するように求められます。 クエリでは 2 つの頂点 u と v が与えられ、タスクは v のサブツリー内のすべての頂点を調べて、XOR 式 a[u] XOR a[i] の値を最大化する 1 つの頂点 i を選択することです。 出力は最大値のみであり、頂点自体ではありません。 

構造は静的です。 ツリーも値も変化せず、クエリのみが到着します。 各クエリは独立しているため、課題は純粋に、サブツリー制約の下で多くの範囲のような最大 XOR クエリを前処理して答えることだけです。 

制約は私たちを二次関数から遠ざけます。 最大 2×10^5 のノードと 2×10^5 のクエリを使用すると、クエリごとにサブツリーをスキャンするソリューションは最悪の場合 O(nq) まで低下します。これは約 4×10^10 の操作に相当し、完全に実行不可能です。 非常に慎重に最適化しない限り、クエリ スタイルごとの分解が O(n√n) であっても遅すぎます。 

さらに微妙な問題は、「v のサブツリー」が元の番号付けでは連続した範囲ではないことです。 追加の構造がなければ、単純なセグメント クエリの問題として扱うことはできません。 

v = 1 など、サブツリーが非常に大きい場合に重要なエッジ ケースが発生します。その場合、すべてのクエリは「ツリー全体の任意のノードとの a[u] の最大 XOR」に縮退します。 単純な解決策では、そのようなクエリごとにトライの再計算やグローバルなスキャンを試行する可能性があり、これにより直ちに TLE が実行されます。 

もう 1 つの特殊なケースは、サブツリー、特に葉が非常に小さい場合です。 サブツリーごとに構造を再構築する単純なアプローチでは、たとえ答えが自明であっても、サイズ 1 のクエリに対して繰り返し作業が無駄になります。 

## アプローチ

 ブルートフォースの解決策は簡単です。 各クエリ (u、v) について、DFS または BFS を使用して v のサブツリーを走査し、そのサブツリー内のすべてのノード i について a[u] XOR a[i] を計算し、最大値を追跡します。 すべての候補者を直接チェックするため、これは正しいです。 

コストはサブツリーの走査を繰り返すことで発生します。 1 回の走査は O (サブツリーのサイズ) であり、すべてのクエリ全体で最悪のケースは、多くのクエリが大きなサブツリー (特にルート付近) を要求する場合です。 各クエリがほぼすべてのノードをスキャンする可能性があるため、最悪の場合、これは O(nq) にまで縮退します。 

重要な観察は、ツリーを線形化するとサブツリー クエリが管理可能になるということです。 オイラー ツアーまたは DFS オーダーを実行すると、各サブツリーが配列内の連続した区間になります。 開始時刻 tin[v] と終了時刻 tout[v] を記録すると、v のサブツリーはセグメント [tin[v], tout[v]] に対応します。 

ここで、問題は次のようになります。各クエリ (u, v) について、固定数 a[u] との XOR を最大化する a[i] (静的間隔の i の場合) を見つける必要があります。 これは、各要素が値を持つ配列に対する古典的なオフライン範囲クエリの問題であり、クエリはサブ配列内の固定キーとの最大の XOR を要求します。 

範囲内の最大の XOR を解決するには、バイナリ トライを使用します。 静的セットがある場合は、すべての要素を挿入し、クエリごとに O(30) で最大の XOR をクエリできます。 範囲制約の場合は、範囲制限と高速 XOR クエリの両方をサポートする構造が必要です。 標準的なアプローチは、オイラー次数のオフライン スイープと永続トライまたはトライのセグメント ツリーを組み合わせたものです。 

ここでの最も直接的な競技プログラミング ソリューションは、各ノードがセグメント値から構築されたバイナリ トライを格納するセグメント ツリーです。 各クエリは、トライ トラバーサルを通じて関連するセグメント ツリー ノードを論理的にマージすることによって回答されます。 ただし、ノードごとに完全な試行を構築するとメモリが重すぎます。

より実用的で標準的な解決策は、オイラー順序でのオフライン永続トライです。オイラー配列でプレフィックストライを構築するため、各バージョン i にはオイラー順序で 1 から i までの値が含まれます。 次に、範囲クエリ [l, r] は、トライの意味でバージョン r からバージョン l−1 を引いた 2 つのバージョンを組み合わせることによって回答されます。トライ ノードのカウントを使用して、範囲内に存在する分岐のみをたどることを保証します。 

DFS オーダーにより、サイズ n の配列が得られます。 この配列に対して永続的なバイナリ トライを構築します。 各ノードは、ビットパスが出現した回数を記憶します。 挿入ごとに O(30) 個のノードがコピーされるため、合計メモリは O(n・30) になります。 各クエリはトライを下っていくものとなり、選択されたブランチが範囲差内に存在することを確認しながら、XOR を最大化するビットを貪欲に選択します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(1) おまけ | 遅すぎる |
 | オイラー次数の永続的なバイナリ トライ | O((n + q) · 30) | O(n · 30) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、サブツリー クエリが間隔クエリになるように、ツリーを線形構造に変換します。 ノード 1 から始まる DFS は、各ノードに最初にアクセスしたときに開始時刻 tin[v] を割り当て、その子孫の探索が終了したときに終了時刻 tout[v] を割り当てます。 また、euler[tin[v]] = a[v] となる配列 euler も構築します。 

この変換後、v のすべてのサブツリーはオイラー配列の区間 [tin[v], tout[v]] に正確に対応します。 このステップが必要なのは、不規則なツリー構造を範囲クエリが意味のある構造に変換するためです。 

次に、オイラー配列に対して永続的なバイナリ トライを構築します。 オイラー配列を左から右に処理し、最初の i 要素を挿入した後、バージョン root[i] を取得します。 各バージョンは、euler[1..i] のすべての値を表します。 各トライ ノードには、ビット 0 とビット 1 の 2 つの子ポインタと、そのノードを通過する数値の数を示すカウントが格納されます。 

新しい数値 x を以前のバージョンに挿入するときは、そのビットによって定義されたパスに沿ったノードのみをコピーし、途中でカウントをインクリメントします。 他のすべてのノードはバージョン間で共有されます。 これにより、すべてのバージョンのビルドが効率的に維持されます。 

各クエリ (u, v) について、オイラー インデックス [l, r] = [tin[v], tout[v]] にわたる範囲クエリに還元します。 a[u] XOR x を最大化したいと考えています。ここで、x はその範囲内の任意の値です。 これは、トライ バージョン r とトライ バージョン l−1 を同時に比較することによって計算されます。 最上位から最下位までの各ビットで、XOR で 1 を与えるブランチを選択しようとします。これは、a[u] と x の間に反対のビットが必要であることを意味しますが、そのブランチが範囲内に存在する場合に限り、2 つのバージョン間のカウントを使用してチェックされます。 

優先ブランチのバージョン差のカウントがゼロの場合は、他のブランチにフォールバックします。 少しずつ結果を積み上げていきます。 

最後に、計算された最大 XOR 値を出力します。 

それが機能する理由は 2 つの不変条件に基づいています。 まず、オイラー ツアーでは、サブツリーのメンバーシップが連続セグメントのメンバーシップと同等であることが保証されるため、サブツリーの外側にあるノードは答えに影響を与えることができません。 第 2 に、永続的なトライ差分クエリにより、すべての分岐の決定がバージョン r とバージョン l−1 の間のカウントを比較することによって検証されるため、すべてのステップで選択された範囲内に存在する数値のみが考慮されることが保証されます。 これにより、各ビットを独立して貪欲に最大化しながら、サブツリーの外側の値を決して選択しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXB = 30

class Node:
    __slots__ = ("ch0", "ch1", "cnt")
    def __init__(self):
        self.ch0 = -1
        self.ch1 = -1
        self.cnt = 0

nodes = [Node()]

def new_node():
    nodes.append(Node())
    return len(nodes) - 1

def insert(prev, x):
    cur = new_node()
    root = cur
    nodes[cur].cnt = nodes[prev].cnt + 1

    for b in reversed(range(MAXB)):
        bit = (x >> b) & 1
        nodes.append(Node())
        nxt = len(nodes) - 1

        nodes[nxt].cnt = 0

        if bit == 0:
            nodes[nxt].ch0 = 0
            nodes[nxt].ch1 = 0
        else:
            nodes[nxt].ch0 = 0
            nodes[nxt].ch1 = 0

        prev = prev
        cur = cur

    return root

sys.setrecursionlimit(10**7)

n = int(input())
a = list(map(int, input().split()))
g = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

tin = [0] * n
tout = [0] * n
euler = []
timer = 0

def dfs(v, p):
    global timer
    tin[v] = timer
    euler.append(a[v])
    timer += 1
    for to in g[v]:
        if to == p:
            continue
        dfs(to, v)
    tout[v] = timer - 1

dfs(0, -1)

# persistent trie (correct compact version)
MAXB = 30

trie_ch0 = [[0]]
trie_ch1 = [[0]]
trie_cnt = [[0]]

def new_trie_node():
    trie_ch0.append(0)
    trie_ch1.append(0)
    trie_cnt.append(0)
    return len(trie_cnt) - 1

def insert_version(prev_root, x):
    new_root = new_trie_node()
    cur = new_root
    trie_cnt[cur] = trie_cnt[prev_root] + 1

    for b in reversed(range(MAXB)):
        bit = (x >> b) & 1

        nxt = new_trie_node()
        if bit == 0:
            trie_ch0[cur] = nxt
            trie_ch1[cur] = trie_ch1[prev_root]
        else:
            trie_ch1[cur] = nxt
            trie_ch0[cur] = trie_ch0[prev_root]

        cur = nxt
        prev_root = trie_ch0[prev_root] if bit == 0 else trie_ch1[prev_root]

    return new_root

roots = [0]
for i in range(n):
    roots.append(insert_version(roots[-1], euler[i]))

def query(l_root, r_root, x):
    cur_l = l_root
    cur_r = r_root
    ans = 0
    for b in reversed(range(MAXB)):
        bit = (x >> b) & 1
        want = bit ^ 1

        if want == 0:
            cnt = trie_cnt[trie_ch0[cur_r]] - trie_cnt[trie_ch0[cur_l]]
            if cnt > 0:
                ans |= (1 << b)
                cur_l = trie_ch0[cur_l]
                cur_r = trie_ch0[cur_r]
            else:
                cur_l = trie_ch1[cur_l]
                cur_r = trie_ch1[cur_r]
        else:
            cnt = trie_cnt[trie_ch1[cur_r]] - trie_cnt[trie_ch1[cur_l]]
            if cnt > 0:
                ans |= (1 << b)
                cur_l = trie_ch1[cur_l]
                cur_r = trie_ch1[cur_r]
            else:
                cur_l = trie_ch0[cur_l]
                cur_r = trie_ch0[cur_r]

    return ans

q = int(input())
out = []
for _ in range(q):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    l = tin[v]
    r = tout[v]
    l_root = roots[l]
    r_root = roots[r + 1]
    out.append(str(query(l_root, r_root, a[u])))

print("\n".join(out))
```DFS セクションは、サブツリーのメンバーシップが区間となるオイラー表現を構築します。 永続的なトライ構造はバージョン管理された構造を構築するため、オイラー配列の各プレフィックスが効率的に表現されます。 クエリ関数は両方のバージョンを同時に調べ、カウントの差を使用して、XOR を最大化するビットを貪欲に選択しながら、サブツリー間隔内の値のみが考慮されるようにします。 

微妙な点は、トライ内のすべての動作がポインタ l と r の両方を同時に更新し、「バージョンの違い」が不変に保たれることです。 片側のみが更新されると、範囲制約が壊れ、無効な要素が回答に漏れる可能性があります。 

## 実用的な例

 値 [3, 1, 4, 2] を持つ小さなツリーと、オイラー次数が [1, 2, 3, 4] になる単純な構造について考えてみましょう。 

クエリ u = 2、v = 2 の場合、サブツリーにはノード 2 のみが含まれるため、範囲は単一の要素になります。 

| ステップ | ビット | ビット | 優先 | 利用可能 | アクション | XOR が構築されました |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 1 | いいえ | 0 | 行く 0 |
 | 2 | 0 | 1 | 1 | いいえ | 行く1 | 0 |
 | 3 | 0 | 0 | 1 | いいえ | 0 | 行く 0 |

 要素が 1 つだけ存在するため、結果は 0 になります。そのため、要素自体との XOR は 0 になります。 

ここで、サブツリーに値 [1, 2, 4] が含まれており、u が値 3 (バイナリ 011) に対応するクエリを考えてみましょう。 3 で XOR を最大化しようとします。 

| ステップ | ビット | ビット | 優先 | 利用可能 | アクション | XOR が構築されました |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 0 | 1 | はい | テイク1 | 1 |
 | 2 | 1 | 1 | 0 | はい | テイク0 | 3 |
 | 3 | 0 | 1 | 0 | はい | テイク0 | 3 |

 貪欲なビットごとの選択により、許可されたサブツリー間隔内で達成可能な最大の XOR が構築されます。 

これらのトレースは、アルゴリズムが制約付きバイナリ トライ ウォークのように動作し、ビット決定をコミットする前にサブツリー範囲に対して実行可能性が常に検証されることを示しています。

 ## 特殊なケース

 リーフである v などのリーフ サブツリーは、クエリ範囲を単一のオイラー位置に縮小します。 トライ範囲の差には有効な要素が 1 つだけ含まれるため、すべてのビット チェックで代替分岐が検出されず、アルゴリズムは、u がそのノードと等しい場合は 0 の XOR を返し、それ以外の場合は正しい単一の比較を返します。 

ルート クエリ v = 1 はオイラー配列全体をカバーします。 この場合、root[n] と root[0] の差により完全なトライがアクティブになり、あらゆるビットの決定により利用可能な最適な分岐を自由に選択できます。 このアルゴリズムは、セット全体に対する標準の最大 XOR のように動作します。 

オイラー順序では連続したセグメントが生成されるため、ツリーの歪みが大きくても正確さには影響しません。 サブツリーが配列のほぼ全体にまたがる場合でも、同じバージョン違いロジックが保持され、範囲外の選択が防止されます。
