 ## 解決策
 ## 問題の理解

 私たちにはドミノカードのコレクションが与えられました。 各カードには、表の値と裏の値という 2 つの値が含まれています。 カードの完全なセットから、最初に正確に K 枚のカードを選択します。 この最初の選択のスコアは、選択された K 枚のカードのフロントの値の合計です。 

これらの K 枚のカードを修正した後、その中から L 枚のカードを選択し、それらのバック値の合計である追加スコアを計算することができます。 最終的なスコアは、K 個のフロント値と L 個のバック値の合計であり、この合計を最大化したいと考えています。 

重要な制約は、2 番目の選択が既に選択されている K 枚のカードに制限されることです。そのため、実際に決定するのは、どの K 枚のカードを含めるか、そしてそれらの K 枚のうちのどの L 枚がバック値に寄与するかということです。 

入力サイズは n = 100000 に達します。これにより、すべてのサブセット、あるいはサイズ K のすべての組み合わせを試行するソリューションは即座に除外されます。およそ O(n log n) または O(n √n) より悪いアプローチは遅すぎます。 ソートベースの戦略またはデータ構造を使用した貪欲な選択が唯一の現実的な方法です。 

単純な戦略が 2 つの選択肢を独立して扱う場合、微妙な失敗例が発生します。 たとえば、上位 K 個のフロント値を選択し、次にそれらから上位 L 個のバック値を個別に選択しようとすると、最良のバック値がフロント選択で最適ではなかったカードに属している可能性があるため、これは失敗する可能性があります。 

具体的な例:

 n = 3

 A = [100, 1, 1]

 B = [1, 100, 100]

 K = 2、L = 1

 A で上位 2 枚を選択すると、カード (100,1) と (1,100) が取られ、表の合計は 101 になります。その中で最も良い裏は 100 なので、合計は 201 になります。 

ただし、最適な解決策はカード (1,100) と (1,100) を選択することですが、K=2 でそのようなペアは 1 つしか存在しないため、それは不可能です。そのため、選択のバランスを慎重にとる必要があります。 

これは、フロント値とバック値が包含をめぐって競合し、構造が両方の決定を結合していることを示しています。 

## アプローチ

 強引なアイデアは、サイズ K のすべてのサブセットを選択し、各サブセットに対してバックサムに最適な L 個の要素を選択することです。 これは問題の定義を直接評価するため、正しいです。 ただし、サブセットの数は$\binom{n}{K}$、これは中程度の n であっても天文学的に大きいため、これは完全に不可能になります。 

重要な観察は、2 番目のステップは常に「選択された K セット内から L 人のベストバックを選択する」ということです。 これは、固定 K セットの寄与が、セット内のすべての A 値の合計と、そのセット内の最大の L B 値の合計の 2 つのコンポーネントとして考えられることを示唆しています。 難しいのは、K セットの最適な選択が A と B の両方に同時に依存することです。 

第 2 段階でどのカードが使用されるかを推測することで、問題を再解釈できます。 バック値に寄与する L カードのセット S をどういうわけか知っていたとします。 これらの L カードは最終的な K セレクションの一部である必要があり、それらについては、貢献が B に固定されているため、ある意味 A の代わりに B を使用することをすでに約束しています。 

次に、残りの K − L スロットについて考えます。 これらの場合、選択された各カードはその A 値のみを提供します。 L スペシャル カードの場合、実質的に A ではなく A に加えて B の追加ボーナスが得られますが、貢献を慎重に分離すると、この観点が容易になります。 

よりクリーンな変換は、A に寄与するすべてのカードから開始し、次に選択したいくつかのカードを A から B にアップグレードすることを考えることです。K 枚のカードのセットを選択した場合、基本寄与はそれらの K カードに対する A の合計になります。 その中で、A ではなく B を貢献する L 枚のカードを選択すると、それらの L 枚のカードに (B − A) の追加ゲインが与えられます。 したがって、問題は K 枚のカードを選択し、その中から最大 (B − A) のゲインを持つ L 個のアイテムを選択することになります。 

これは古典的な構造につながります。ベース A と L の追加ボーナスを最大化する K 個の要素が必要です。 

これは、候補をソートし、ヒープを使用して K プールの最適な選択肢を維持しながら、L の最適な改善を追跡することで処理できます。 

標準的な解決策は、カードを A の降順に並べ替え、徐々に候補セットを構築することです。 反復中に、選択された K 個のうちどの L 個の項目が最良の (B − A) ゲインを与えるかを追跡する構造を維持します。 これらの向上のための最小ヒープを維持して、常に上位 L 個の改善を維持します。 

新しいアイテムを含めた瞬間に、それはすぐに A に貢献します。 この場合、潜在的なアップグレード値は (B − A) となり、上位 L 個の改善点に入る可能性があります。 改善されている場合は、現在の最小の改善が置き換えられ、それに応じて基本合計が調整されます。 

少なくとも K 個の項目が考慮されたすべてのプレフィックスの中で可能な限り最適な構成を追跡します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^K) | O(K) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各カードをゲイン[i] = B[i] − A[i] のペア (A[i]、gain[i]) に変換します。 

私たちは A の降順でカードを処理し、常に強力なフロントの貢献を最初に考慮するようにします。 

1. すべてのカードを A の降順に並べ替えます。 これにより、プレフィックスを検討するときに、常に利用可能な最良のベース コントリビューションを使用して作業することが保証されます。 
2. 現在候補プールにあるすべてのカードの A 値の累計を維持します。 これは、すべてを選択した場合の基本スコアを表します。 
3. A から B に切り替えるために現在選択されている L 枚のカードを表す、選択したカードのゲイン値を保存する最小ヒープを維持します。ヒープ サイズは最大 L です。 
4. ソートされた順序でカードを繰り返し、各カードを候補プールに追加します。 その A を現在の合計に加算し、それがこれまでに確認された最高の L ゲインの 1 つである場合、そのゲインをヒープにプッシュします。 
5. ヒープ サイズが L を超える場合は、最小のゲインを削除します。 これにより、常に最高の L アップグレードを維持できるようになります。 
6. 少なくとも K 枚のカードを検討したら、現在のスコアを次のように計算します。 

total ヒープ内のゲインの合計 + 合計。 
7. すべてのプレフィックスの最大値を追跡します。

これが機能する理由は、K 枚のカードの最適な選択は、その中で L 個の最良のゲイン アップグレードを選択することと組み合わせて、A 順にソートされたプレフィックスとして表すことができるためです。 より大きな A が除外され、より小さな A を持つカードが選択された場合、それらを交換しても基本合計が減少することはなく、結果を改善する方法で利用可能なゲインの選択肢が減ることはありません。 この交換引数により、最適性を失うことなく、プレフィックス構造への注意を制限することができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))
    K, L = map(int, input().split())

    cards = []
    for i in range(n):
        cards.append((A[i], B[i]))

    cards.sort(reverse=True)

    base_sum = 0
    gain_sum = 0
    heap = []

    ans = 0

    for i, (a, b) in enumerate(cards):
        base_sum += a
        gain = b - a

        heapq.heappush(heap, gain)
        gain_sum += gain

        if len(heap) > L:
            gain_sum -= heapq.heappop(heap)

        if i + 1 >= K:
            ans = max(ans, base_sum + gain_sum)

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、カードを A の降順に並べ替えることから始まります。これは、接頭辞推論を可能にする構造的な決定です。 変数base_sumは、処理されたすべてのカードをKセットの一部として取得した場合の合計寄与度を追跡します。 ヒープは、ゲイン (B − A) として実装された最良の L アップグレードを維持します。 新しいカードが追加されるたびに、楽観的にそのカードをゲイン構造に組み込み、L を超えた場合は最悪のカードを削除し、最良の改善点のみを保持します。 

小切手`i + 1 >= K`K 枚のカードを選択する必要があるため、プレフィックスに少なくとも K 枚のカードが存在する構成のみを評価します。

 ## 特殊なケース

 1 つのエッジ ケースは、L がゼロに等しい場合に発生します。 この場合、問題は単純に K 個の最大 A 値を選択することになります。 ヒープは常に空のままであるため、アルゴリズムはこれを自然に処理します。そのため、gain_sum はゼロになり、答えは最大の K A 値の合計になります。 

K が N に等しい場合、別のエッジ ケースが発生します。その場合、すべてのカードを選択する必要があり、唯一の自由は L 個の最良のゲインを選択することです。 アルゴリズムは配列全体を処理し、ヒープは上位 L (B − A) 値を正しく収集し、特別なケースを必要とせずに最適な結果を生成します。 

3 番目の状況は、すべてのゲインが負の場合です。つまり、B が常に A より小さいことを意味します。ヒープには有害性が最も低いゲインが格納されますが、アルゴリズムは効果的により大きな A 値を優先し、最適なトレードオフに合わせて最もマイナスの少ないアップグレードを選択することで損失を最小限に抑えます。
