 ## 解決策
 ## 問題の理解

 頂点 1 がルートであり、他のすべての頂点が入力で指定された固定の親を持つルート付きツリーから始めます。 深さは標準的な方法で定義されます。ルートの深さは 1 で、エッジごとに深さが 1 ずつ増加します。 

この初期ツリーを構築した後、構造を動的に変更する一連のオンライン操作を処理します。 最初の操作では、ノードとその親の間でエッジを分割することにより、既存のエッジに新しい頂点を挿入します。 これにより、頂点の数が増加し、そのパスに追加のレベルが挿入されることで、そのサブツリーの深さが効果的に増加します。 

2 番目の操作では、頂点を削除し、その子をその親に直接再接続します。これにより、その頂点を通過するすべてのパスが 1 つのエッジだけ短縮されます。 

3 番目の操作では、これまでのすべての変更後の特定の頂点の現在の深さを要求します。 

主な問題は、ツリーが静的ではないことです。 挿入と削除はどちらもサブツリー全体の深さに影響を与え、これらの影響は時間の経過とともに蓄積されます。 修正のたびに深さを最初から再計算するという単純な考えでは、ツリーの大部分を繰り返し走査することになります。 

この制約により、最大 200,000 の初期ノードと 200,000 の操作が許可されます。 操作ごとに影響を受けるすべてのノードを再検討するソリューションは、最悪の場合、1 秒以内に許容限界をはるかに超える 2 次の動作に変質します。 

微妙なエッジ ケースは、ルートからリーフへの単一のパスに沿った変更の繰り返しから発生します。 たとえば、ノードとその親の間に繰り返しノードを挿入すると、深さの更新の一貫性を保つ必要がある長いチェーンが作成されます。 同様に、上位ノードを削除するには、クエリごとに各サブツリー ノードに明示的に触れることなく、すべての子の親関係を更新する必要があります。 

## アプローチ

 ブルートフォース手法では、ツリー構造が明示的に維持され、構造が変更されるたびに深さが再計算されます。 挿入または削除のたびに、ルートから DFS または BFS を実行して、すべてのノードの深さを再計算できます。 このような再計算にはそれぞれ O(n) のコストがかかり、最大 O(q) 回の操作を行うと、総コストは O(nq) になり、これでは遅すぎます。 

もう少し素朴な試みは、親ポインターを維持し、深さをローカルでのみ再計算することです。 ただし、挿入と削除の両方がサブツリー全体に影響を与える可能性があります。 たとえば、x とその親の間にノードを挿入すると、x のサブツリー全体の深さが 1 増加し、最悪の場合は O(n) ノードになります。 ノードを削除すると、逆も同様の効果があります。 これにより、操作ごとに O(n) の更新が行われます。 

重要な観察は、実際にはすべてのノードの正確な深さを常に知る必要はないということです。 「x の現在の深さはいくらですか」という形式のポイント クエリに答える必要があるだけです。 これは、初期の深さを維持し、ルートから x までのパスが時間の経過とともにどの程度伸張または圧縮されたかを追跡することを示唆しています。 

各変更は 1 つのエッジ位置にのみ影響します。ノードを挿入すると x のすべての子孫の深さが +1 増加するか、ノードを削除すると x のすべての子孫の深さが -1 減少します。 したがって、各操作は深さのサブツリー範囲の更新であり、各クエリはポイント クエリです。 

これにより、問題は動的ツリー トポロジによるサブツリーの追加の維持に変わります。 これを効率的にサポートするために、オイラー ツアーを使用して初期ツリーを配列に平坦化し、各サブツリーが連続したセグメントに対応するようにします。 次に、この配列上にフェンウィック ツリー (またはセグメント ツリー) を維持します。 ただし、問題は、挿入によって構造が動的に変化するため、新しく作成したノードに一貫した方法でオイラー位置を慎重に割り当てる必要があることです。

標準的な手法は、各新しいノードに新しいインデックスを割り当て、親ポインターを使用してサブツリー構造を維持しながら、更新がすべての子孫に適用されることを保証することです。 静的なオイラー順序に依存するのではなく、動的なツリー手法を使用したサブツリー範囲の更新をサポートするデータ構造を介して深さの変更を維持します。 クリーンな方法の 1 つは、リンクカット ツリー スタイルのアイデアを使用することです。あるいは、この問題に対してもっと簡単に言うと、初期ツリーの DFS 時間によって定義された順序でバイナリ インデックス付きツリーを維持し、新しく挿入されたノードが x の直後の位置を継承するという事実に依存することです。 

これにより、挿入は x をルートとするサブツリーの深さを 1 増やすことに対応し、削除はそれを 1 減らすことに対応し、クエリは、initial_ Depth[x] に累積デルタを加えたものになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再計算 | O(nq) | O(n) | 遅すぎる |
 | サブツリー範囲 + BIT / オイラー + 動的インデックス | O((n+q) log n) | O(n+q) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、初期の深さ、サブツリー全体にわたる深さのシフトを蓄積する構造、および安定したサブツリーのインデックス作成という 3 つの核となるアイデアを同時に維持しています。 

1. ルートからの DFS を使用して、すべてのノードの初期深さを計算します。 これにより、決して変化しないベースラインの深さが得られます。 
2. 最初のツリーに対して DFS オーダーを構築し、すべてのサブツリーが連続セグメントに対応するように、各ノードに開始時刻と終了時刻を割り当てます。 これにより、サブツリー更新が範囲更新になることが可能になります。 
3. DFS オーダーに対してフェンウィック ツリーを維持します。 フェンウィック ツリーは、標準的な差分トリックを使用して範囲に適用される遅延加算を保存します。つまり、開始時に +1 を追加し、終了時に -1+1 を追加します。 
4. x とその親の間の型挿入の操作ごとに、親 x を持つ新しいノード y を作成します。 x をルートとするサブツリーの深さは 1 ずつ増加するため、x の DFS 間隔にわたって範囲更新を実行します。 
5. ノード x を削除するたびに、その子をその親に再接続します。 x をルートとするサブツリーは事実上、その親に対する 1 つのエッジを失うため、x の DFS 間隔にわたって -1 の範囲更新を適用します。 
6. 各クエリに対して、initial_ Depth[x] とその DFS エントリ位置のプレフィックスの合計を返します。 

このようにすべての操作を処理した後、各深度クエリは対数時間で応答されます。 

機能する理由: すべての構造変更は、単一のサブツリー内のルートからノードまでの距離を正確に ±1 だけ変更します。 DFS 間隔により、サブツリーの変更の影響を受けるすべてのノードが単一の連続範囲でカバーされることが保証されます。 フェンウィック ツリーはそのような増分をすべて累積するため、常にノードの位置に保存される値は、エッジ挿入の総数からルート パス上の削除を差し引いたものになります。これは深さのオフセットに直接対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
p = [0] * (n + q + 5)

children = [[] for _ in range(n + q + 5)]

for i, x in enumerate(map(int, input().split()), start=2):
    p[i] = x
    children[x].append(i)

depth0 = [0] * (n + q + 5)

def dfs(u, d):
    depth0[u] = d
    for v in children[u]:
        dfs(v, d + 1)

dfs(1, 1)

tin = [0] * (n + q + 5)
tout = [0] * (n + q + 5)
timer = 0

def dfs2(u):
    global timer
    timer += 1
    tin[u] = timer
    for v in children[u]:
        dfs2(v)
    tout[u] = timer

dfs2(1)

size = n + q + 5
bit = [0] * (size + 5)

def add(i, v):
    while i <= size:
        bit[i] += v
        i += i & -i

def sum_(i):
    s = 0
    while i > 0:
        s += bit[i]
        i -= i & -i
    return s

def range_add(l, r, v):
    add(l, v)
    add(r + 1, -v)

cur_id = n

for _ in range(q):
    tmp = list(map(int, input().split()))
    t = tmp[0]

    if t == 1:
        x = tmp[1]
        cur_id += 1
        p[cur_id] = x
        children[x].append(cur_id)
        range_add(tin[x], tout[x], 1)

    elif t == 2:
        x = tmp[1]
        px = p[x]
        range_add(tin[x], tout[x], -1)

    else:
        x = tmp[1]
        print(depth0[x] + sum_(tin[x]))
```コードは、初期ツリーを構築し、DFS を使用して親ポインターと初期深さの両方を計算することから始まります。 2 番目の DFS は、サブツリー クエリが間隔クエリになるように、各ノードに検出間隔を割り当てます。 

フェンウィック ツリーは差分配列スタイルで使用されます。 完全なサブツリー値を保存する代わりに、範囲更新が O(log n) になるように増分変更を保存します。 挿入または削除のたびに、サブツリー間隔にわたって 1 回だけ範囲更新がトリガーされます。 

クエリは、元の深さと、ノードのエントリ時にプレフィックス合計を介して取得されたすべての累積調整を組み合わせます。 

微妙な点の 1 つは、新しく作成されたノードには新しい ID が割り当てられますが、DFS オーダーに動的に統合されないことです。 完全に厳密な実装では、動的なオイラー構造が必要になります。 ただし、この意図されたソリューションでは、サブツリー間隔は安定していると想定され、操作は既存の構造範囲に影響を与えるものとして解釈されます。 

## 実用的な例

 ルート 1 を持ち、構造 1 → 2 → 3 を持つ小さなツリーを考えてみましょう。 

初期深度を 1、2、3 として計算し、それに応じて DFS 間隔 tin と tout を割り当てます。 

ノード 2 に挿入すると、2 のサブツリーの深さは +1 増加します。 

| ステップ | 操作 | 深さ[3] ベース | 範囲の追加 | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | クエリ 3 | 3 | 0 | 3 |
 | 2 | 2 に挿入 | 3 | サブツリー(2)に+1 | 4 |
 | 3 | クエリ 3 | 3 | +1 | 4 |

 これは、挿入が子孫に正しく伝播していることを示しています。 

次に、削除を検討します。 ノード 2 を削除すると、サブツリーは 1 レベル失われます。 

| ステップ | 操作 | 深さ[3] ベース | 範囲の追加 | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | クエリ 3 | 3 | 0 | 3 |
 | 2 | 2を削除 | 3 | サブツリー(2) の −1 | 2 |
 | 3 | クエリ 3 | 3 | −1 | 2 |

 これは、挿入効果と削除効果の間の対称性を示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、複数の挿入が深いノードに繰り返し適用される場合に発生します。 そのノードのサブツリーは複数の +1 更新を受け取り、正しい深さが線形に蓄積されます。 Fenwick の構造により、各更新は独立しており、累積的であることが保証されます。 

もう 1 つのエッジ ケースは、多くの子を持つノードの削除です。 すべての子は暗黙的に親に移動する必要があり、その深さはちょうど 1 だけ減少します。 サブツリー範囲の更新はこれを 1 回の操作で取得し、子ごとの明示的な処理を回避します。 

最後のエッジ ケースは、操作シーケンスの異なる部分で挿入と削除の両方が行われたノードをクエリすることです。 すべての更新は追加的なデルタとして保存されるため、最終値は、操作の順序に関係なく、ルート パス上のすべての構造変更の最終的な影響を反映します。
