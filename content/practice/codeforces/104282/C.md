 ## 解決策
 ## 問題の理解

 6 つの独立したトラックがあり、各トラックにはブロックが表示されるいくつかの互いに素な時間セグメントが含まれています。 各セグメント`[l, r]`からの整数秒ごとに意味します`l`に`r`包括的に、そのトラックをその秒で押すことを選択した場合、そのトラックはちょうど 1 ポイントに貢献します。 

毎秒、宵宮は 6 トラック中最大 5 トラックのボタンを押すことができます。 その時点でトラックにブロックがあり、それを押した場合、その秒でそのトラックに対して 1 ポイントを獲得します。 押すトラックの数が 5 を超えない限り、各秒ごとにどのトラックを押すかを自由に選択できます。 

タスクは、すべての秒数とすべてのトラックにわたって収集されるポイントの合計数を最大化することです。 

重要な問題点は、時間が次までに及ぶことです。`10^8`、トラック間の合計間隔は約`2 * 10^5`。 これにより、すべてのソリューションは秒ごとの反復を回避し、代わりにイベント境界で動作するようになります。 

素朴な解釈では、毎秒シミュレートし、最大 5 つのアクティブなトラックを貪欲に押すことになります。 タイムラインが大きすぎるため、これはすぐに失敗します。 時間を圧縮することも必要ですが、それでも主な課題は、各瞬間にどの単一トラックをスキップするかを決定することです。 

微妙だが重要なエッジ ケースは、複数のトラックがアクティブで、「5 つのトラックの最適な選択」が間隔の境界により頻繁に変化する場合に発生します。 

たとえば、ある瞬間に 6 つのトラックすべてがアクティブになっているとします。 正確に 1 つのトラックを無視することを選択し、少なくとも 1 つの潜在的なポイントを失うことを選択する必要があります。 後で 5 つだけがアクティブなままになった場合は、不必要にトラックをスキップしていないことを確認する必要があります。 単純に貪欲な秒あたりのシミュレーションでは、誤って以前の選択に「固執」する可能性があります。 

## アプローチ

 整数秒ごとに時間を修正すると、問題は単純になります。各秒ごとに、アクティブなトラックの数を数えます。 6 の場合、5 つのトラックしか押すことができないため、ちょうど 1 ポイントを失います。 そうでなければ何も失うものはありません。 

したがって、答えは次と同等です: すべての秒間の合計`min(5, active_tracks_at_time)`。 

強引な方法は、すべての間隔を個々の秒に拡張し、アクティブなトラックの頻度カウントを維持し、1 秒ごとにアクティブなトラックの数を計算することです。 ただし、合計スパンは次のとおりです。`10^8`、これを不可能にします。 

重要な観察は、アクティブな間隔のセットが固定されている時間セグメント内では何も変化しないということです。 アクティブなトラックの数が変更されるのは、間隔のエンドポイントのみです。 したがって、各間隔を変換できます`[l, r]`2 つのイベントに分割: 1 つは`l`カバレッジを拡大し、`r + 1`カバレッジが減少します。 次に、時間を順番にスイープして、現時点でアクティブなトラックの数を維持します。 

連続する 2 つのイベント位置の間`x`そして`y`、アクティブなトラックの数は一定であるため、寄与は単純に次のようになります。`(y - x) * min(5, active_count)`。 

これにより、問題は従来のスイープ ラインにまで縮小されます。`2 * 2e5`イベント。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(最大時間 × 6) | お(1) | 遅すぎる |
 | スイープライン | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての間隔のエンドポイントを、アクティブなトラックのグローバル タイムラインの変化として扱います。 

1. 各区間を変換する`[s, t]`6 つのトラックのそれぞれを 2 つのイベントに追加します。`+1`時に`s`そして追加します`-1`時に`t + 1`。 これにより、カバレッジが経時的な差分配列として表現されることが保証されます。 
2. すべてのトラックからすべてのイベントを 1 つのリストに収集し、時間順に並べ替えます。 アクティブ数の正確さを維持するには時間を時系列で処理する必要があるため、並べ替えが必要です。 
3.初期化`active = 0`そして`answer = 0`、ポインタを設定します`i = 0`並べ替えられたイベントについて。 
4. イベントポイントを一掃します。 それぞれの異なる時間ごとに`x`、最初に前回からの寄与度を計算します`prev`に`x`として`(x - prev) * min(5, active)`。 これが機能する理由は、`active`この間隔内では変化しません。 
5. 次に、すべてのイベントを一度に適用します`x`、更新中`active += delta`イベントごとに。 これにより、この時点で現在アクティブなトラックの数が更新されます。 
6. 移動`prev`に`x`そして続けます。 
7. すべてのイベントを処理した後は、最後のイベント以降はすべてアクティブな間隔がゼロであるため、それ以上の貢献は必要ありません。 

微妙な点は、現在の座標で更新を適用する前に寄与を計算していることです。 これにより、時間ごとのイベントの意味が保持されます。`x`～からのみ影響を与える`x`前ではなく、これからです。 

### なぜ効果があるのか

 2 つの連続するイベント ポイント間の固定時間セグメントでは、アクティブな間隔のセットは変化しません。 したがって、アクティブなトラックの数はそのセグメント全体で一定です。 スコアリング関数は、アイデンティティや履歴ではなく、特定の秒間にアクティブなトラックの数のみに依存するため、最適な決定もセグメント全体にわたって一定です。`min(5, active)`。 すべての最大定数セグメントにわたるこれらの寄与を合計すると、すべての秒が 1 回だけカバーされ、重複や欠落がなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

events = []

# 6 tracks
for _ in range(6):
    data = list(map(int, input().split()))
    n = data[0]
    arr = data[1:]
    for i in range(n):
        l = arr[2 * i]
        r = arr[2 * i + 1]
        events.append((l, 1))
        events.append((r + 1, -1))

events.sort()

active = 0
ans = 0

prev = events[0][0]
i = 0
m = len(events)

while i < m:
    x = events[i][0]

    ans += (x - prev) * min(5, active)

    while i < m and events[i][0] == x:
        active += events[i][1]
        i += 1

    prev = x

print(ans)
```この実装では、すべてのトラックにわたるすべての間隔境界のフラットなイベント リストが作成されます。 各間隔は開始時に +1、終了直後に -1 を与えるため、正確なカバレッジが保証されます。 

スイープ ループは、「間隔の寄与」を「状態の更新」から慎重に分離します。 掛け算`(x - prev) * min(5, active)`ここでは、問題全体が時間次元からセグメント集約にまで縮小されます。 

よくある落とし穴はアップデートです`active`セグメント寄与度を追加する前に、`x`。 これにより、イベントが誤って 1 単位ずつシフトされ、境界秒数が過大または過少にカウントされます。 

## 実用的な例

 わかりやすくするために、トラックが 2 つある小さなシナリオを考えてみましょう (問題には 6 つのトラックがありますが)。 トラック 1 に`[1, 3]`そしてトラック2には`[2, 4]`。 

私たちはイベントを構築します:

 | 時間 | 変更 |
 | --- | --- |
 | 1 | +1 |
 | 2 | +1 |
 | 4 | -1 |
 | 5 | -1 |

 今度はスイープします:

 | セグメント | アクティブ | 貢献 |
 | --- | --- | --- |
 | 1-2 | 1 | 1 × 1 = 1 |
 | 2-4 | 2 | 2 × 2 = 4 |
 | 4-5 | 1 | 1 × 1 = 1 |

 合計 = 6。 

これにより、重複する間隔が正しくスタックされ、セグメントベースの計算が秒ごとの推論と一致することが確認されます。 

次に、6 つのトラックすべてが 1 秒間オーバーラップする場合を考えてみましょう。`[10, 10]`すべてのトラックで。 

時間 10 では、アクティブ = 6 ですが、取得できるのは 5 つだけです。 

| セグメント | アクティブ | 貢献 |
 | --- | --- | --- |
 | 10-11 | 6 | 1 × 5 = 5 |

 これにより、キャップが正しく適用されていることを確認できます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    events = []
    for _ in range(6):
        data = list(map(int, input().split()))
        n = data[0]
        arr = data[1:]
        for i in range(n):
            l = arr[2 * i]
            r = arr[2 * i + 1]
            events.append((l, 1))
            events.append((r + 1, -1))

    events.sort()

    active = 0
    ans = 0
    prev = events[0][0]
    i = 0
    m = len(events)

    while i < m:
        x = events[i][0]
        ans += (x - prev) * min(5, active)
        while i < m and events[i][0] == x:
            active += events[i][1]
            i += 1
        prev = x

    return str(ans)

 ## 特殊なケース

 重要なエッジ ケースは、複数のイベントが同じタイムスタンプで発生し、混合間隔が開始および終了する場合です。 このアルゴリズムは、特定の時点ですべてのイベントをまとめて処理しますが、それは前のセグメントからの寄与を考慮した後でのみ処理されます。 これにより、境界での数え間違いを防ぎます。 

たとえば、1 つの間隔が次の時点で終了する場合、`x`そしてもう一つはから始まります`x`、両方とも同じイベント グループで処理されます。 への貢献`[prev, x)`古いアクティブ カウントを使用します。これにより、次から始まる間隔が正しく除外されます。`x`。 

もう 1 つのエッジ ケースは、すべての間隔がトラック間で互いに素であり、アクティブが 1 を超えることがない場合です。アルゴリズムは依然として機能します。`min(5, active)`に減少します`active`、特別な処理を行わずに正確さを維持します。
