 ## 解決策
 ## 問題の理解

 私たちには、単語の置換に関する固定の辞書が与えられています。 各ルールでは、特定の単語を常に別の固定単語に置き換える必要があると規定されています。 すべてのルールを読んだ後、BSQ が話す文を形成する一連の単語が与えられます。 その文内のすべての単語は、厳密に 1 つの置換ルールの左側として出現することが保証されているため、各単語は厳密に 1 つの出力単語にマップされます。 

タスクは、指定されたルールを使用して各単語を個別に置き換え、結果のシーケンスを出力することによって文を変換することです。 

制約は小さく、ルールの数と文内の単語数は両方とも最大 100、各単語の長さは最大 10 です。これにより、入力サイズが少なくとも 1 次または 2 次の解であれば十分に高速であることがすぐにわかります。 すべての単語のすべてのルールを直接スキャンしたとしても、実行される文字列比較は最大 10,000 件のみであり、これは簡単なことではありません。 

変換の連鎖や複数ステップの書き換えなど、隠れた構造的な複雑さはありません。 各単語は、提供されたマッピングを使用して 1 回だけ置換されます。 

いくつかの特殊なケースについては、依然として明示する価値があります。 

単純な実装では、置換が反復的であると誤って想定される可能性があります。 たとえば、あるルールが「a → b」で、別のルールが「b → c」である場合、間違った解決策によりルールが繰り返し適用され、「a」が「c」に変わってしまう可能性があります。 ただし、この問題は決して推移閉包を要求しません。 直接置換のみが必要です。 

もう 1 つの潜在的な落とし穴は、単語がスペースで区切られたトークンであることを忘れることです。 入力を生の文字列として処理し、部分文字列を置き換えようとすると、偶発的な部分一致によって結果が破損する可能性があります。 たとえば、「wow」内の「wo」を置き換えることは部分文字列ベースのアプローチでは正しくありませんが、トークンベースの処理ではこれを完全に回避します。 

## アプローチ

 問題を解決する簡単な方法は、ルールを検索プロセスとして解釈することです。 文内の単語ごとに、左側が単語と一致するルールが見つかるまですべてのルールを調べ、対応する右側を出力します。 

ルールは単純な関連リストを形成するため、この強引な方法は正しいです。 ただし、そのコストは文の単語の数とルールの数を掛けたものに比例します。 最悪の場合、これにより 100 × 100 = 10,000 回の文字列比較が行われます。これはここではまだ許容可能ですが、制約が拡大すると無駄になります。 

重要な観察は、静的データセット内で同じキーを繰り返し検索していることです。 まさにこれがハッシュ マップの設計目的です。 各ソース単語からその置換までの辞書を事前計算することで、各クエリの平均検索時間を O(1) に短縮します。 これにより、問題は繰り返しの線形スキャンから直接マッピングの問題に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース スキャン | O(nm) | O(n) | 受け入れられるが不要 |
 | ハッシュマップ検索 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべてのルールを格納するマッピング構造を構築します。 各キーはソース単語であり、各値はその置換単語です。 

1. 整数 n と m を読み取ります。これらは、文中に出現するマッピング ルールの数と単語の数を定義します。 
2. 空の辞書を初期化します。 
3. n 個のルールのそれぞれについて、ペア (si, ti) を読み取り、si → ti として辞書に保存します。 この手順により、後で一定時間のルックアップが保証されます。 
4. 文の m 語を読みます。 
5. 文内の単語ごとに、マッピングされた値を辞書から取得し、出力シーケンスに追加します。 
6. 変換されたすべての単語をスペースで区切って順番に出力します。 

直接検索を安全に信頼できる理由は、この問題により、すべての入力単語がマッピング内のキーとして表示されることが保証されるため、欠落キーの処理が必要ないためです。 

### なぜ効果があるのか

このアルゴリズムは、入力単語のセットに対して定義された関数 f を構築します。各単語には 1 つの画像が含まれます。 この問題では完全なカバレッジと左辺の一意性が保証されているため、 f は明確に定義されたマッピングです。 出力文は、単に入力シーケンス内の各トークンに f を点単位で適用したものです。 以前の置換に依存するルールがないため、各変換は独立しており、順序が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m = map(int, input().split())
    mp = {}

    for _ in range(n):
        s, t = input().split()
        mp[s] = t

    words = input().split()
    res = []

    for w in words:
        res.append(mp[w])

    print(" ".join(res))

if __name__ == "__main__":
    main()
```解決策は辞書を構築することから始まります`mp`すべての置換ルールを保存します。 各入力ペアは直接挿入され、問題はすべての入力ペアを保証するため、上書きは心配ありません。`si`は区別されます。 

次に、文は次を使用してトークンのリストとして読み取られます。`split()`これにより、単語を部分文字列ではなく原子単位として扱うことが保証されます。 各単語は辞書検索によって翻訳され、結果リストに追加されます。 最後に、出力をスペースで結合して、変換された文を再構築します。 

微妙ですが重要な点は、出力の構築中に文字列の連結を繰り返さないようにすることです。 リストを使用して、`" ".join()`繰り返しの文字列の追加による二次的な増加ではなく、線形な時間動作を保証します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    mp = {}

    for _ in range(n):
        s, t = input().split()
        mp[s] = t

    words = input().split()
    res = [mp[w] for w in words]
    return " ".join(res)

 ## 特殊なケース

 微妙なケースの 1 つは、文中に同じ単語が繰り返し出現することです。 例えば：```
2 3
a x
b y
a a b
```アルゴリズムは各トークンを個別に処理します。 最初の「a」は「x」になり、2番目の「a」は再び「x」になり、「b」は「y」になります。 辞書引きは位置や履歴に依存しないため、繰り返しても問題ありません。 

もう 1 つのケースは、部分的な置き換えを決して試みないようにすることです。 空白を使用して文を分割するため、各トークンはアトミックに処理されます。 「ab」や「a」など、単語に接頭辞が共通している場合でも、それらは辞書内では別個のキーとなるため、混同されません。 

最後に、すべての入力単語がマッピング内に存在することが保証されているため、フォールバック処理は必要ありません。 辞書への直接アクセスは常に有効であり、問​​題の制約の下で KeyError ケースを考慮する必要はありません。
