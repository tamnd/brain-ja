 ## 解決策
 ## 問題の理解

 個別の整数のリストが与えられており、その中からできるだけ多くの整数を選択してサブセットを形成したいと考えていますが、1 つの制限があります。一方が他方よりちょうど 9 大きい 2 つの数値を選択することは許可されていません。 言い換えれば、値 x を選択する場合、同時に x + 9 を選択することは避けなければなりません。 

タスクは、そのようなサブセットの可能な最大サイズを計算することです。 

入力サイズは最大 200,000 個の数値にすることができ、値は最大 1e9 までです。 これにより、すべてのサブセットを試行したり、密なグラフを明示的に構築したりするソリューションは即座に除外されます。 ブルートフォース サブセット チェックは n が増えると指数関数的に増大し、2 × 10⁵ の 2 乗が大きすぎるため、単純な O(n²) ペア チェック アプローチでもタイムアウトになってしまいます。 

制約の構造が鍵となります。制約は、正確に 9 だけ異なる数値のみを関連付けます。これは非常に局所的な相互作用であるため、疎できれいに分解されるグラフのような構造が期待されるはずです。 

数値が長い等差数列を形成する場合、微妙な特殊なケースが発生します。 たとえば、配列に 1、10、19、28 が含まれる場合、隣接する各ペアは 9 で区切られており、すべてを選択することはできません。 「常に利用可能な最小の数値を取得し、+9 の近傍を破棄する」などの不注意で貪欲なアプローチは、構造を意識せずにグローバルに適用すると失敗する可能性があります。これは、決定が配列全体ではなく、接続されたコンポーネント内でのみ独立しているためです。 

もう 1 つのエッジ ケースは、1、11、20、30 など、数値が分散している場合です。ここでは、9 だけ異なる 2 つの値はないため、正解は単純に 4 になります。グループ化を過度に複雑にしたり、連続した範囲を想定したりするアルゴリズムは、このような疎な構成を誤って処理することになります。 

## アプローチ

 直接的な総当たりのアイデアは、すべてのサブセットを考慮し、禁止されたペアが存在するかどうかを確認することです。 各サブセットについて、すべてのペアをスキャンし、9 に等しい差がないことを確認します。これは正しいですが、実行不可能です。2ⁿ サブセットがあり、各チェックのコストが最大 O(n) になる可能性があり、指数関数的な時間が発生する可能性があります。 

わずかに改良された総当り攻撃は、配列をソートし、要素ごとに、以前に選択された要素の競合をチェックして、それを含めるかどうかを決定しようとするものです。 各要素を他の多くの要素と比較する必要がある可能性があるため、これでも最悪の場合は O(n²) の動作に劣化します。 

重要な点は、この制限は x と x + 9 の両方が存在するかどうかのみに依存するということです。 これは、各数値がノードとなるグラフを構築し、両方が存在する場合は x を x + 9 に接続することを示唆しています。 各ノードには最大で 2 つの隣接ノードがあります: x − 9 と x + 9。これは、すべての接続されたコンポーネントが単純なチェーンであることを意味します。 

その構造を認識すると、問題は、隣接する 2 つの頂点が選択されないように、パス グラフ内の頂点の最大数を選択することになります。 これは、パス上の古典的な最大独立集合であり、接続された各セグメント内の他のすべての要素を取得することによって解決されます。 

エッジを明示的に構築する必要さえありません。 同じ剰余を持つ数値のみが繰り返し 9 ずつ異なる可能性があるため、数値を 9 を法とする値でグループ化するだけで十分です。 各剰余クラス内で、変換された値 k = a / 9 (より正確には、+9 のステップを暗黙的に追跡する k = a) を並べ替え、値が正確に 9 だけ異なる連続する実行に分割します。各実行はパスのように動作します。 

長さ L のラン内では、最適な答えは単純に ceil(L / 2) になります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2ⁿ・n) | O(n) | 遅すぎる |
 | 最適 (グループ + パス DP) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての数値を 9 を法とする剰余でグループ化します。これが機能するのは、同じ剰余を持つ数値のみが繰り返し正確に 9 だけ異なるため、グループ間の相互作用は不可能であるためです。 
2. グループごとに、番号を並べ替えます。 競合グラフ内の隣接性は値による順序付けに対応するため、並べ替えが必要です。 
3. ソートされたリストをスキャンし、その差が正確に 9 である場合に限り、2 つの連続する値を接続するシーケンスとして解釈します。これにより、連続する算術ステップのチェーンが形成されます。 
4. 連続する要素間の差が 9 でない場合は常に、シーケンスをセグメントに分割します。各セグメントは独立したパス コンポーネントです。 
5. 長さ L の各セグメントについて、答えに ceil(L / 2) を追加します。 これは、隣接するノードが両方とも選択されないように、パス内の要素を交互に選択することに対応します。 
6. すべてのセグメントにわたる寄与を合計し、結果を出力します。 

### なぜ効果があるのか

 各値は、9 を法とする 1 つの剰余クラスに正確に属し、そのクラス内では、エッジは +9 の 1 ステップだけ異なる数値のみを接続します。 これにより、接続されているすべてのコンポーネントが単純なパスであることが保証されます。 パス上では、有効な選択はすべて独立セットに対応し、パスに沿って交互に選択することで最大の独立セットが得られます。 コンポーネントは互いに素であるため、それぞれを個別に解決して合計することで、全体的な最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    groups = {}
    for x in a:
        r = x % 9
        if r not in groups:
            groups[r] = []
        groups[r].append(x)

    ans = 0

    for r in groups:
        arr = sorted(groups[r])

        i = 0
        m = len(arr)

        while i < m:
            j = i
            while j + 1 < m and arr[j + 1] - arr[j] == 9:
                j += 1

            length = j - i + 1
            ans += (length + 1) // 2
            i = j + 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まずモジュロ 9 で数値をバケット化し、潜在的な競合をすべて分離します。 各バケットをソートすると、競合する可能性のあるペアが同じ算術チェーンの一部である場合、それらのペアが隣接するペアとして表示されるようになります。 

内側のループは、連続する差分がちょうど 9 である最大のセグメントを構築します。そのような各セグメントは独立して処理され、その長さの半分を切り上げて加算します。 表現`(length + 1) // 2`は、セル除算の直接整数形式です。 

よくある実装の落とし穴は、差が正確に 9 ではないときにセグメントを再開し忘れることです。この区切りがないと、関連のない数値が誤って 1 つのパスとして扱われてしまいます。 

## 実用的な例

 ### 例 1

 入力:```
n = 5
a = [1, 10, 19, 2, 11]
```モジュロ 9 でグループ化します。 

| 残り | 値 |
 | --- | --- |
 | 1 | 1、10、19 |
 | 2 | 2、11 |

 次に各グループを処理します。 

残り 1 の場合: ソートされた結果は [1, 10, 19] になります。 すべての差は 9 なので、長さ 3 の 1 つのセグメントになります。寄与は ceil(3/2) = 2 です。 

残り 2 については、[2, 11] がソートされます。 長さ 2 の 1 つのセグメント、寄与率は 1。 

| グループ | セグメント | 長さ | 貢献 |
 | --- | --- | --- | --- |
 | 1 | [1,10,19] | 3 | 2 |
 | 2 | [2,11] | 2 | 1 |

 最終的な答えは 3 です。 

これは、アルゴリズムが独立した算術チェーンを正しく分離し、チェーンごとに最適な選択を適用していることを確認します。 

### 例 2

 入力:```

```グループ化:

合計の答えは 3 です。 

これは、孤立した単一要素が自明なセグメントとして正しく動作することを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    groups = {}
    for x in a:
        r = x % 9
        groups.setdefault(r, []).append(x)

    ans = 0
    for r in groups:
        arr = sorted(groups[r])
        i = 0
        m = len(arr)
        while i < m:
            j = i
            while j + 1 < m and arr[j + 1] - arr[j] == 9:
                j += 1
            ans += (j - i + 2) // 2
            i = j + 1

    return str(ans)

 ## 特殊なケース

 エッジ ケースの 1 つは、3、12、21、30 など、すべての数値がステップ 9 で完全な等差数列を形成する場合です。この場合、グループ全体が 1 つのセグメントになります。 アルゴリズムは長さ 4 の単一ランを正しく計算し、最適な交互選択に一致する 2 を返します。 

もう 1 つのエッジ ケースは、1、100、1000、10000 など、同じモジュロ クラス内で値が非常にまばらな場合です。9 に等しい隣接する差がないため、各要素は長さ 1 の独自のセグメントを形成します。アルゴリズムはそれぞれを別個の実行として扱い、要素ごとに 1 を提供し、完全なカウントを生成します。 

最後のエッジ ケースは、同じ剰余グループ内に複数の独立したチェーンが存在する場合に発生します。 たとえば、1、10、19 と 28、37 は 2 つの互いに素なセグメントを形成します。 スキャンは 9 を超えるギャップで正しく中断され、これらのセグメントが誤ってマージされず、それぞれが独立して解決されます。
