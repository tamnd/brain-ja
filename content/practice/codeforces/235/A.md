 ## 解決策
 ## 問題の理解

 最小公倍数が最大になるように、_n_ 以下の 3 つの正の整数を選択するように求められます。 整数は個別である必要はないため、より大きな LCM を達成するのに役立つ場合は、数値を繰り返すことができます。 入力は単一の整数 _n_ で、最大 100 万まで可能です。 出力は 1 つの整数、つまり [1,_n_] の範囲内の 3 つの整数の最大許容最小公倍数です。 

ここで重要なのは、数値が大きく、可能な限り互いに素である場合に最小公倍数が最も速く成長することを理解することです。 最大 3 つの数値を単純に乗算することは、それらが共通の因数を共有する場合には失敗する可能性があります。 たとえば、_n_ が偶数の場合、_n、n-1、n-2_ を取得すると、それらはほとんど互いに素であるため通常は機能しますが、_n_ 自体が偶数の場合、_n、n-1、n-2_ を取得すると、_n_ と _n-2_ が因数 2 を共有するため、_n、n-1、n-2_ よりも大きな LCM が生成される可能性があります。 

この制約は、すべてのトリプルを試すよりも早く解決策が必要であることを意味します。 _n_ が最大 10^6 の場合、すべての O(n³) トリプルをブルート フォース チェックすると、およそ 10^18 回の操作が必要となり、これは実行不可能です。 O(n²) でさえ約 10^12 ですが、それでも大きすぎます。 これにより、単純な列挙が排除されます。 エッジ ケースには、選択できる最大の数値が制限されている非常に小さい _n_ (1、2、3 など) が含まれており、繰り返される数値を適切に処理する必要があります。 

## アプローチ

 ブルートフォースアプローチは、1 ≤ a, b, c ≤ n のすべてのトリプル (a、b、c) を考慮し、それらの最小公倍数を計算し、最大値を追跡することです。 これが機能するのは、考えられるすべての組み合わせを考慮することが保証されるからです。 ただし、n = 10^6 の場合、およそ 10^18 個の LCM を計算することになりますが、これは実際の計算をはるかに超えています。 

最適なアプローチは 2 つの観察を活用します。 まず、最小最小公倍数はほぼ常に範囲内の最大の数値を含みます。これは、最小公倍数は互いに素な数に対して乗算され、数値の大きさとともに増加するためです。 第 2 に、チェックする必要があるのは n の周囲のいくつかのトリプルのみです。数値 n、n-1、n-2、n-3、および n-4 を考慮して、この小さなセットからすべてのトリプルを取得できます。 これにより、組み合わせの数が最大 10 個に減り、評価が簡単になります。 

小さな _n_ も慎重に扱う必要があります。 n ≤ 2 の場合、3 つの異なる数値を選択することはできないため、数値を繰り返し選択します。 n = 1 の場合、唯一の選択肢は (1, 1, 1) です。 n = 2 の場合、最適なトリプルは (2, 1, 1) です。 n ≥ 3 の場合、上記の戦略は確実に機能します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. n が 1 の場合、唯一のトリプルは (1, 1, 1) であるため、1 を返します。 n が 2 の場合、トリプル (2, 1, 1) に対応する 2 を返します。 これらは明示的な基本ケースです。 
2. n ≥ 3 の場合、n、n-1、n-2、n-3、および n-4 の 5 つの最大の整数から構成される候補セットを構築します。 このセットは小さいですが、可能な限り最大の LCM を生成するには十分です。 
3. この候補セットから 3 つの数字のすべての組み合わせを列挙します。 トリプルごとに LCM を計算します。 最大値を追跡してください。 
4. 見つかった最大 LCM を返します。 

これが機能する理由は、n-4 より小さい数値を含めると、n から n-4 までの数値を使用するよりも大きな LCM を生成できないためです。 数値が小さいほど、全体の大きさが減少し、共有因子が増加して、LCM が減少します。 

## Python ソリューション```python
import sys
import math
from itertools import combinations
input = sys.stdin.readline

def lcm(a, b):
    return a * b // math.gcd(a, b)

def lcm3(a, b, c):
    return lcm(a, lcm(b, c))

def solve():
    n = int(input())
    if n == 1:
        print(1)
        return
    if n == 2:
        print(2)
        return
    candidates = [n, n-1, n-2, n-3, n-4]
    max_lcm = 0
    for a, b, c in combinations(candidates, 3):
        max_lcm = max(max_lcm, lcm3(a, b, c))
    print(max_lcm)

solve()
```コードはヘルパーを定義します`lcm`2 つの数字の場合、`lcm3`3 つの数値の連鎖`lcm`呼び出します。 n = 1 と n = 2 を明示的に処理し、より大きな n の候補セットを構築します。 使用する`itertools.combinations`、すべてのトリプルを効率的にチェックし、最大値を維持します。 n-4 を選択すると、n が偶数で 1 つの数をスキップすると共素性が高まるシナリオを含め、潜在的な高 LCM トリプルをすべてカバーできるようになります。

## 特殊なケース

 n = 1 の場合、可能なトリプルは (1,1,1) のみであるため、アルゴリズムはすぐに 1 を返します。 n = 2 の場合、候補セット [2,1,-1,...] は正の数 2,1 のみを使用し、必要に応じて繰り返します。 負の数値は無視されます。 n ≥ 3 の場合、候補選択では、共素性を低下させる可能性がある 2 または 3 の倍数を回避しながら、LCM を最大化する数値が常に含まれるようにします。 たとえば、n = 8 の場合、候補 [8,7,6,5,4] が得られ、アルゴリズムは (8,7,6) から最大 LCM 336 を正確に見つけます。
