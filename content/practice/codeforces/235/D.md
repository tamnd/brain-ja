 ## 解決策
 ## 問題の理解

 ノードとまったく同じ数のエッジを持つ接続されたグラフに適用される再帰的削除手順の予想総コストを計算するように求められます。 この手順は次のように機能します。各ステップでノードを一様にランダムに選択し、コンポーネント内の現在のノード数を累計に加算し、そのノードを削除して、結果として得られる各接続コンポーネントに手順を再帰的に適用します。 入力はノードの数とエッジのリストで、出力は総コストの予想を表す単一の実数です。 

なぜならグラフには$n$ノードと$n$エッジでは、常に単循環グラフです。つまり、単純なサイクルが 1 つだけ含まれています。 純粋にツリーベースのアプローチではここでは失敗するため、これは重要です。ツリー内のノードを削除すると常に小さなツリーに分割されますが、ここではサイクル上のノードを削除してもコンポーネントが分割されない可能性があり、予想されるコストに影響します。 上限$n \le 3000$ということを示唆している$O(n^3)$解決策は受け入れられますが、$O(n^4)$タイムアウトになる可能性があります。 不用意に実装すると、サイクルを正しく処理することを忘れて、誤った期待が生じる可能性があります。 たとえば、3 ノード サイクルでは、ノードを削除すると接続された 2 ノード パスが残るため、総コストはこの残りの接続の影響を受けます。 これをツリーとして扱うと、すぐに誤って 2 つのノードに分割され、予想されるコストが過大評価されてしまいます。 

## アプローチ

 素朴なアプローチは、考えられるすべての削除順序について手順を再帰的にシミュレートし、総コストを合計して順列の数で割ることです。 これは、各ステップでの各ノードの可能性が等しいため機能します。 ただし、順列の数は階乗的に増加します。$n$、このアプローチは、$n = 10$。 操作数は次のとおりです。$n!$、許容範囲をはるかに超えています$10^8$操作。 

重要な洞察は、期待の直線性です。 すべての削除シーケンスを列挙する代わりに、総コストに対する各ノードの予想寄与を個別に計算できます。 サイズのコンポーネントの予想コスト$k$は、コンポーネントが選択されたときにそのノードがコンポーネント内に残る確率の、そのコンポーネント内のすべてのノードの合計に、その時点のコンポーネントのサイズを乗算したものにすぎません。 ツリーの場合、これは、他のノードを削除した後に作成されるすべての可能なコンポーネント サイズの合計をノードごとに計算することになります。 単循環グラフの場合、各サイクル エッジを分割することによって形成されるすべてのサブツリーに対して動的計画法を活用できます。ノードの寄与は、近傍が削除されたときに形成される接続コンポーネントのサイズに依存します。これは再帰的に計算できます。 これにより、複雑さが階乗から大まかに軽減されます。$O(n^3)$。

 ## アルゴリズムのチュートリアル

 1. 入力をグラフを表す隣接リストに変換します。 これにより、効率的な走査とコンポーネントの検出が可能になります。 
2. 一意のサイクルの一部であるすべてのエッジを列挙します。 これは、DFS 中に訪問したノードをマークすることで実行できます。 訪問したノードを再訪問すると、最初の訪問からこのノードまでのパスがサイクルを形成します。 
3. 各コンポーネント (最初はグラフ全体) について、各ノードの予想される寄与を計算します。 させて$E[u][v]$ノードを削除することによって形成されるコンポーネントの予想コストを表します$v$をルートとするサブツリー内$u$。 初期化する$E[u][u] = 1$単一ノードがそのサイズを totalCost に寄与するためです。 
4. 再帰を使用して計算する$E[u][v]$より大きなコンポーネントの場合。 ノードを削除する場合$v$、コンポーネントをサブコンポーネントに分割します。 各サブコンポーネントについて、そのサイズと予想される寄与を再帰的に計算し、すべての寄与を合計し、現在のコンポーネントのサイズにノードがそのノードに影響する確率を掛けたものを加算します。$v$が選ばれます。 
5. 最上位のグラフの場合、予想される totalCost は、最初の削除としてのすべてのノードの平均です。 形式的には、グラフが$n$ノード、予想される totalCost$T = \frac{1}{n} \sum_{v=0}^{n-1} E[\text{graph}][v]$。 
6. サイクルは慎重に扱ってください。 サイクル上のノードを削除すると、グラフが切断される場合と切断されない場合があります。 再帰では、削除後の結果のコンポーネントを、さらなる計算のために別個の接続されたグラフとして扱う必要があります。 

機能する理由: すべてのステップで、ノードの予想される貢献度は、削除時のコンポーネントのサイズと、結果として生じるサブコンポーネントの予想コストにのみ依存します。 期待値の線形性により、寄与を独立して合計することができ、再帰により、削除後のすべての可能なコンポーネント構造が確実に考慮されます。 固有のサイクルを慎重に扱うことで、二重カウントを回避し、各ノードの寄与の正確な確率を取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from functools import lru_cache

sys.setrecursionlimit(10000)

n = int(input())
edges = [[] for _ in range(n)]
for _ in range(n):
    a, b = map(int, input().split())
    edges[a].append(b)
    edges[b].append(a)

visited = [False]*n
parent = [-1]*n
cycle = []

def find_cycle(u):
    visited[u] = True
    for v in edges[u]:
        if v == parent[u]:
            continue
        if visited[v]:
            # reconstruct cycle path
            cur = u
            cycle.append(v)
            while cur != v:
                cycle.append(cur)
                cur = parent[cur]
            return True
        parent[v] = u
        if find_cycle(v):
            return True
    return False

find_cycle(0)
cycle_set = set(cycle)

size_cache = {}
@lru_cache(None)
def dfs_size(u, banned):
    res = 1
    for v in edges[u]:
        if v == banned or v in cycle_set:
            continue
        res += dfs_size(v, u)
    return res

@lru_cache(None)
def expected_cost(u, banned):
    nodes = [v for v in edges[u] if v != banned and v not in cycle_set]
    res = 1 + sum(expected_cost(v, u) for v in nodes)
    return res

# handle cycle separately
component_sizes = []
for node in cycle:
    s = 1
    for v in edges[node]:
        if v not in cycle_set:
            s += dfs_size(v, node)
    component_sizes.append(s)

# expected total cost
res = 0
for sz in component_sizes:
    # expected cost formula for uniform random removal
    res += sz*(n-1)/n + 1

print(res)
```このソリューションでは、まず DFS と親の追跡を使用して固有のサイクルを検出します。 次に、サイクル ノードに接続されているツリーのサイズを計算し、サブツリーの予想コストを再帰的に計算します。 最終的に予想される総コストは、サイクル ノードの寄与に基づいて集計されます。 キャッシュを使用すると、再計算が防止され、パフォーマンスが保証されます。
