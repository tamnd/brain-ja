 ## 解決策
 ## 問題の理解

 ゲーム内の各クリックは独立してヒット成功 (`O`) またはミス (`X`）。 

完成したシーケンスについては、最大の連続ブロックに分割します。`O`。 ブロックに長さがある場合`L`、貢献します`L²`スコアに。 合計スコアは、これらの二乗ブロック長の合計です。 

具体的な順序は与えられていません。 その代わり、どのポジションでも`i`、確率はわかっています`p[i]`クリックが成功したことを示します。 すべてのクリックは独立しています。 最終スコアの期待値を計算する必要があります。 

最初の本能は、考えられるすべての結果について考えることです。 長さのシーケンス`n`もっている`2^n`可能な実現があり、各実現には独自のスコアがあります。 それらを列挙して期待値を計算することは不可能です。 と`n`まで`100000`、すべての結果を保存することすらばかげています。 

制約`n ≤ 100000`線形時間に近いものが必要であることをすぐに示唆しています。 二次動的計画法はすでに高価すぎるため、`10^10`作戦は制限時間をはるかに超えている。 受け入れられている解決策では、各確率を一定の回数だけ処理する必要があります。 

難しいのは、スコアが連続成功の実行全体に依存することです。 ポジションで終了するラン`i`かなり以前に恣意的に開始された可能性があるため、局所的な移行は明らかではありません。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
1
1.0
```唯一可能な順序は次のとおりです`"O"`のスコアは`1`。 繰り返しが行われる場合は、最初の位置を正しく初期化する必要があります。 

考慮する：```
2
1.0 1.0
```唯一可能な順序は次のとおりです`"OO"`のスコアは`4`、 ない`2`。 個々のポジションの期待される寄与を単純に合計する方法では、連続する成功の間の相互作用を見逃してしまいます。 

考慮する：```
3
0 1 0
```中央のクリックは常に一定の長さを形成します`1`、つまり、答えは正確に`1`。 確率で位置を通じて偶然に状態を伝達するあらゆる再発`0`間違った結果が生成されます。 

別の微妙なケースは次のとおりです。```
3
0.5 0.5 0.5
```ランは複数のポジションにまたがる可能性があるため、ポジションの貢献度は`i`で終了する予想される実行の長さによって異なります。`i-1`。 この依存関係は、まさにソリューションが捉える必要があるものです。 

## アプローチ

 ブルートフォースを試してみるとします。 

それぞれについて、`2^n`考えられるシーケンスがあれば、その確率とスコアを計算して、追加することができます。`probability × score`答えに。 期待はそのように定義されているため、これは数学的に正しいです。 

問題は結果の数です。 たとえ`n = 50`、すでに 1,000 兆を超えるシーケンスが存在します。 のために`n = 100000`、このアプローチは完全に実行不可能です。 

重要な観察は、実際には実行を完全に分散する必要はないということです。 もう 1 つのポジションを処理するときに、予想されるスコアを更新するのに十分な情報だけが必要です。 

一連の成功が現在の位置で終わると想像してください。 その長さを`L`。 

現在のクリックが成功すると、長さからランが延長されます`L-1`長さまで`L`、そのランのスコア貢献度は から変化します。`(L-1)²`に`L²`。 

増加分は、`L² - (L-1)² = 2L - 1`。 

この漸進的な形式は重要な簡素化です。 

完全な実行を追跡する代わりに、連続成功の現在のサフィックスの予想される長さを追跡します。 新しく成功したクリックが到着すると、スコアが増加します。`2L-1`。 期待値は線形であるため、次の期待値のみが必要です。`L`。 

これにより、次のような単純な線形 DP が維持されます。`len`、現在の位置で終わる連続成功サフィックスの予想される長さ。`ans`, これまでに蓄積された期待スコア。 

各確率は 1 回処理され、`O(n)`解決。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 状態の定義

 しましょう:`f`= 予想される連続長さ`O`現在の位置で終わるサフィックス。`ans`= 現在の位置を処理した後の予想スコア。 

### 遷移導出

 確率を処理していると仮定します`p`。 

クリックが失敗した場合、サフィックスの長さは次のようになります。`0`。 

クリックが成功すると、接尾辞の長さは前の接尾辞の長さにプラスしたものになります。`1`。 

したがって、次のようになります。$$f' = p(f+1)$$なぜなら確率的には`p`私たちは得る`f+1`、そして確率的に`1-p`私たちは得る`0`。 

次に、スコアの増加について考えてみましょう。 

クリックが成功すると、新しい長さのランが延長されます。`L`、ランスコアは次のように増加します。$$L^2-(L-1)^2 = 2L-1$$新しい長さは次のとおりです`f+1`期待条件付きの形式で。 

したがって、このポジションによって寄与される期待される増加額は次のようになります。$$p \cdot (2(f+1)-1) = p(2f+1)$$それで：$$ans' = ans + p(2f+1)$$の古い値に注意してください。`f`更新する前に、ここで使用する必要があります。 

### 番号付きのステップ

 1.初期化`f = 0`そして`ans = 0`。 
2. 確率を左から右に処理します。 
3. 現在の確率について`p`、 追加$$p(2f+1)$$に`ans`。 

これは、クリックが成功した場合に現在の実行を延長することによって生じる予想されるスコアの増加です。 
4. 予想されるサフィックスの長さを更新します。$$f = p(f+1)$$クリックが失敗すると、サフィックスはゼロになります。 成功すると、サフィックスの長さが 1 つ増加します。 
5. すべての確率が処理された後、出力`ans`。 

### なぜ効果があるのか

 しましょう`L_i`位置で終わる連続成功サフィックスのランダムな長さを示します`i`。 

維持される変数`f`まさに`E[L_i]`。 

位置決め時`i`成功すると、そこで終了する実行の長さが変わります`L_i-1`に`L_i`。 スコアの増分は常に次のようになります。$$L_i^2-(L_i-1)^2 = 2L_i-1$$期待値を取得し、期待値の線形性を使用すると、次のようになります。$$E[\Delta] = p_i(2E[L_{i-1}]+1)$$これはまさにに追加されたアップデートです`ans`。 

すべてのスコアの増加は 1 回だけ考慮されるため、`f`現在の位置を処理した後の予想されるサフィックスの長さ、累積された値と常に等しくなります。`ans`予想される合計スコアに等しい。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(float, input().split()))

    f = 0.0
    ans = 0.0

    for prob in p:
        ans += prob * (2.0 * f + 1.0)
        f = prob * (f + 1.0)

    print("{:.15f}".format(ans))

solve()
```変数`f`現在の連続成功サフィックスの予想される長さを格納します。 更新する前に、古い値を使用して、現在のクリックによる予想されるスコアの増加を計算します。 

順序は重要です。 式$$ans += p(2f+1)$$前の位置で終わるサフィックスの長さを使用します。 更新中`f`1 つ目は、新しいサフィックスの長さを誤って使用し、貢献度の部分を二重にカウントします。 

すべての計算では浮動小数点数が使用されます。 再帰では加算と乗算のみが実行されるため、必要な処理には標準の倍精度で十分です。`10^{-6}`正確さ。 

浮動小数点変数が 2 つだけ維持されるため、メモリ使用量は一定に保たれます。`n`。

 | 測定 | 複雑さ | 説明 |

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    p = list(map(float, input().split()))

    f = 0.0
    ans = 0.0

    for prob in p:
        ans += prob * (2.0 * f + 1.0)
        f = prob * (f + 1.0)

    return "{:.15f}".format(ans)

# provided sample
assert abs(float(run("3\n0.5 0.5 0.5\n")) - 2.75) < 1e-9

# minimum size, always miss
assert abs(float(run("1\n0\n")) - 0.0) < 1e-9

# minimum size, always hit
assert abs(float(run("1\n1\n")) - 1.0) < 1e-9

# all hits, score = 3^2
assert abs(float(run("3\n1 1 1\n")) - 9.0) < 1e-9

# isolated guaranteed hit
assert abs(float(run("3\n0 1 0\n")) - 1.0) < 1e-9

# two guaranteed hits form one block of length 2
assert abs(float(run("2\n1 1\n")) - 4.0) < 1e-9
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 0`|`0`| 最小のインスタンス、成功したクリックなし |
 |`1 / 1`|`1`| 正しい初期化 |
 |`3 / 1 1 1`|`9`| アレイ全体にわたる単一の実行 |
 |`3 / 0 1 0`|`1`| ミス後の適切なリセット |

## 特殊なケース

 次のことを考慮してください。```
1
0
```最初は`f = 0`。 アップデートにより追加されるのは、`0 * (2*0 + 1) = 0`答えに、そして`f`残る`0`。 最終結果は`0`、すべてのクリックが失敗するという事実と一致します。 

考慮する：```
2
1 1
```最初のクリック後、`ans = 1`そして`f = 1`。 2 回目のクリック後、追加された貢献度は次のようになります。`1 * (2*1 + 1) = 3`、最終的な答えは次のとおりです。`4`。 これは、単一の長さのランを正確に表します`2`のスコアは`2²`。 

考慮する：```
3
0 1 0
```最初のクリックでは何も貢献せず、終了します`f = 0`。 2回目のクリックが貢献`1`、生産`f = 1`。 3 回目のクリックでは何も反映されず、サフィックスがリセットされます。 答えはまさに`1`、1 回の成功したクリックに相当します。 

考慮する：```
4
1 0 1 1
```順序は決定的です。 ランは、`"O"`そして`"OO"`、スコアを与える`1² + 2² = 5`。 

アルゴリズムにより次のものが生成されます。 

| ポジション | p | 前の | その後 |
 | --- | --- | --- | --- |
 | 1 | 1 | 0 | 1 |
 | 2 | 0 | 1 | 1 |
 | 3 | 1 | 0 | 2 |
 | 4 | 1 | 1 | 5 |

 位置 2 でリセットすると、後の実行が最初の実行と誤ってマージされるのを防ぎます。
