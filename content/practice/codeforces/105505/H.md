 ## 解決策
 ## 問題の理解

 このプログラムは、関数呼び出しの有向非巡回グラフです。 各関数には基本コストがあり、関数が別の関数を呼び出すたびに、その呼び出し先の実行コスト全体が即座に追加され、この効果はその後のすべての呼び出しに再帰的に伝播します。 

グラフの観点から考えると、すべての関数はノードであり、すべての呼び出しは有向エッジです。 関数の総コストは、関数自体の重みだけではなく、発信エッジを介して到達可能なすべてのノードの重みの合計であり、複数の呼び出し命令が存在する場合は多重度もカウントされます。 

グラフは DAG であることが保証されているため、すべての評価が明確に定義されており、再帰ループはありません。 

課題は、基本コストが時間の経過とともに変化することです。 各更新では単一ノードの重みが変更され、クエリでは以前のすべての更新を考慮したノードの現在の合計「クロージャ合計」が求められます。 最後に、各クエリ結果を個別に返すのではなく、回答の加重合計を順番に累積します。 

制約があるため、この構造は非常に困難になります。 最大 8000 個のノードとエッジがあるため、グラフは十分小さいため、二次前処理が妥当です。 ただし、最大 1e6 イベントが存在する可能性があるため、クエリごとに完全な DP を再計算することはできません。 操作ごとに線形時間でイベントごとにエッジまたはノードを再検討するアプローチは生き残れません。 

バグを引き起こす単純な誤解は、更新のたびに DP 全体を再計算することです。 たとえば、チェーン 1 → 2 → 3 → 4 では、ノード 4 の基本コストを変更すると、直接実行するとすべての先祖の再計算が強制されます。これは小規模な例では問題ありませんが、大規模になると致命的に遅くなります。 

もう 1 つの微妙なケースは、同じ関数ペア間での複数の呼び出しです。 これは、グラフがエッジの複数セットであるため、到達可能性だけではなく多重度を考慮して寄与をカウントする必要があるため重要です。 

## アプローチ

 ブルートフォースの観点は単純明快です。 現在の基本値を維持し、クエリごとに DAG 上で DP を実行できます。 逆のトポロジー順序でノードを処理すると、各ノードはその発信近隣ノードの寄与を集約します。 これにより、単一のクエリのクロージャ合計が正しく計算されます。 

これが機能するのは、グラフがトポロジー的にソートされると、各ノードが後続の順序のノードにのみ依存するため、単一のパスで十分だからです。 

イベント数を考慮すると問題が発生します。 各クエリには O(N + M) のコストがかかり、最大 1e6 イベントの場合、これは非常に遅くなります。 問題は正確さではなく、同じ構造計算の繰り返しです。 

重要な観察は、伝播の構造は決して変わらないということです。 基底ベクトルのみが変更されます。 これによりシステムが線形になります。 すべての機能の総コストは、基本コストの固定線形結合として表すことができます。 

T(i) = 係数 (i, j) の j にわたる合計 * B[j]

 係数は DAG のみに依存し、多重度を考慮して、すべてのコール パスを通じて i から j に到達する回数を表します。 

これらの係数が判明すると、各クエリは単なるドット積になります。 更新は基本ベクトルに対する単純な点の変更となり、クエリは固定線形形式を評価します。 

トレードオフは、この係数行列の保存と使用になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに DP を再計算する | O(E · (N + M)) | O(N) | 遅すぎる |
 | すべてのパス係数を事前計算し、ドット積を介してクエリを実行します。 O(N² + N・M + Q・N) | O(N²) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、DAG のトポロジー的な順序を修正します。 これにより、ノードを再度訪問することなく、依存関係構造をクリーンに計算できるようになります。 

1. すべての関数の位相順序を計算します。 これにより、すべての関数が、それが依存するすべての関数の前に出現することが保証されます。 
2. 各関数 i について、i から開始して各関数 j が呼び出される回数を計算します。 DPテーブルを構築します`dp[i][j]`、次のように初期化されます`dp[i][i] = 1`。 
3. 逆のトポロジー順序でノードを移動します。 各エッジ i → k に対して、k のすべての出現がその呼び出し先のすべての寄与を継承するように寄与を伝播します。 正式には、すべての j に対して次を追加します。`dp[k][j]`の中へ`dp[i][j]`、i から k への呼び出しの数を乗算します。 

このステップが機能するのは、逆トポロジー順序では、ノードの処理時にノードのすべての子孫がすでに完全に計算されているためです。 

1. 前処理後、現在の基本値配列 B を維持します。 
2. ノード i に対するクエリの場合、T(i) を dp[i] と B の内積として計算します。 
3. 更新設定 B[i] = v の場合は、値を単純に上書きします。 
4. クエリの回答が到着したときに、その回答の必要な加重合計を維持します。 

### なぜ効果があるのか

 各 dp[i][j] は、すべての個別のコール パスをカウントし、エッジの多重度を考慮して、i の実行が最終的に j の実行をトリガーした合計回数を表します。 グラフは非巡回であるため、すべてのパスは DP 伝播に 1 回だけ寄与し、サイクルを二重にカウントするリスクはありません。 実行の線形性により、すべての j にわたる寄与を合計すると、完全な実行コストが正確に再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def topo_sort(n, adj):
    indeg = [0] * n
    for u in range(n):
        for v in adj[u]:
            indeg[v] += 1

    stack = [i for i in range(n) if indeg[i] == 0]
    topo = []

    while stack:
        u = stack.pop()
        topo.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                stack.append(v)

    return topo

def main():
    n = int(input())
    B = list(map(int, input().split()))
    m = int(input())

    adj = [[] for _ in range(n)]
    radj = [[] for _ in range(n)]

    for _ in range(m):
        f, g = map(int, input().split())
        f -= 1
        g -= 1
        adj[f].append(g)
        radj[g].append(f)

    topo = topo_sort(n, adj)
    pos = [0] * n
    for i, v in enumerate(topo):
        pos[v] = i

    dp = [ [0] * n for _ in range(n) ]

    for v in reversed(topo):
        dp[v][v] = 1
        for to in adj[v]:
            for j in range(n):
                if dp[to][j]:
                    dp[v][j] += dp[to][j]

    e = int(input())
    ans = 0

    for _ in range(e):
        tmp = input().split()
        if tmp[0] == 'U':
            i = int(tmp[1]) - 1
            v = int(tmp[2])
            B[i] = v
        else:
            j = int(tmp[1]) - 1
            s = 0
            row = dp[j]
            for k in range(n):
                s += row[k] * B[k]
            ans = (ans + (_ + 1) * s) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    main()
```前処理では、DAG 構造を使用して完全な推移的寄与行列を構築します。 各行 dp[i] は、i からの実行が到達可能なすべてのノードにどのように拡張されるかをエンコードします。 クエリ フェーズでは、現在の基本配列に対するその行の直接評価が行われます。 

更新操作は将来の評価にのみ影響し、行列はすでにすべての構造伝播をキャプチャしているため、簡単です。 

実装上の微妙な点は、dp 伝播ではエッジの多重度を考慮する必要があることです。 このため、エッジをブール値の到達可能性として扱うのではなく、隣接リストが直接反復処理されます。 

## 実用的な例

 関数が 1 → 2 → 3 を形成し、基本値が [10, 20, 100] である小さなチェーンを考えてみましょう。 

| ステップ | イベント | B 状態 | クエリノード | 計算された T(i) |
 | --- | --- | --- | --- | --- |
 | 1 | Q1 | [10,20,100] | 1 | 230 |
 | 2 | Q2 | [10,20,100] | 2 | 120 |
 | 3 | Q3 | [10,20,100] | 3 | 100 |

 各クエリはダウンストリームの貢献を集計します。 ノード 1 にはすべてが含まれ、ノード 2 にはそれ自体と 3 が含まれ、ノード 3 は分離されています。 

ここで、分岐グラフ内のクエリとインターリーブされた更新を考えてみましょう。 

| ステップ | イベント | B 状態 | クエリノード | 計算された T(i) |
 | --- | --- | --- | --- | --- |
 | 1 | Q2 | [?、?] | 2 | 初期値 |
 | 2 | Q1 | [?、?] | 1 | 構造に依存します |
 | 3 | U20 | [?,0] | - | ベースが変更されました |
 | 4 | Q1 | [?,0] | 1 | 削減 |
 | 5 | Q2 | [?,0] | 2 | 更新されました |

 これは、基本値のみが変化し、構造伝播は固定されたままであることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N² + N・M + E・N) | DP は完全な寄与行列を構築し、各クエリは 1 つの行を評価します。 
| スペース | O(N²) | すべてのペア間の推移的な寄与数を格納します。 

N が 8000 で制限されており、最適化された定数係数の下で二次構造が前処理とクエリごとの評価の両方で受け入れられるため、この解決策は指定された制約の下で実行可能です。

 ## 特殊なケース

 エッジのない単一ノードにより、dp[i][i] が正しく 1 に初期化されており、偶発的な伝播が発生していないことが確認されます。 実行時間は常に基本値とまったく同じであり、更新によって単純に上書きされます。 

長いチェーンは、推移的な累積が複数の層に正しく伝播するかどうかをテストします。 DP の順序付けが省略されていると、中間ノードがより深いノードからの寄与を見逃すことになります。 

同じターゲットへの複数の発信エッジを持つノードは、多重度の処理をテストします。 関数が別の関数を 2 回呼び出す場合、その寄与を 2 回カウントする必要があります。これは、DP の蓄積中にエッジの多重度が考慮される場合にのみ保持されます。 

同じノードへの更新が繰り返される場合、基本ベクトルのみが変更され、構造の再計算は必要ありません。
