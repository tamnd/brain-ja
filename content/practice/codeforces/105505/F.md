 ## 解決策
 ## 問題の理解

 の行が与えられています$N$同じトイレがあり、最初はすべて空でした。 次々と人が到着し、各人は現在空いていて、両側に人が住んでいないトイレを選択しなければなりません。 言い換えれば、誰かがその位置に座ると、$i$、その後両方$i-1$そして$i+1$その時点では空である必要があります (または範囲外である必要があります)。 

まさにその後$K$人々が選択した場合、占有トイレの最終構成には、同じルールの下で他の人がどの位置も選択できない特性が必要です。 私たちはそのような最終的な取り決めを構築するか、それが不可能であると判断する必要があります。 

出力は長さの文字列です$N$ここで、「X」は使用中のトイレを示し、「-」は空いているトイレを示します。 まさにその状態に到達することができれば、$K$有効な配置によってシステムが完全にブロックされる場合は、有効な最終構成を出力します。 それ以外の場合は、単一の「*」を出力します。 

制約$N \le 10^6$そして$K \le N$どのような解決策も線形または線形に近いものでなければならないことを強くお勧めします。 配列を繰り返しスキャンして人を配置する二次シミュレーションは、それぞれの配置にコストがかかる可能性があるため、遅すぎます。$O(N)$、につながる$O(NK)$最悪の場合。 

微妙な問題は、ローカルの貪欲な配置戦略が失敗する可能性があることです。 たとえば、境界付近に人を配置するのが早すぎると、今後の配置オプションが誤って減少し、有効な構成が存在するにもかかわらず、すべての移動をブロックするために完了できない構成が生成される可能性があります。 

次の場合には、別のエッジケースが発生します。$K = 0$。 その場合、有効な移動のない、すでに完全にブロックされた構成が必要になりますが、少なくとも 1 の長さの空のセグメントは常に移動を許可します。$N \ge 1$, したがって、これが可能なのは次の場合だけです。$N = 0$、決して起こりません。 したがって、$K=0$些細な解釈以外は暗黙的に不可能につながります。 

反対の極端な場合、$K = N$、すべてのポジションを占有することを強制されますが、これは最初の配置後の隣接ルールに明らかに違反しているため、完全な占有は決して有効ではありません。$N > 1$。 

本当に難しいのは、有効な移動が残っていない構成を理解することです。 この条件は非常に強力です。すべての空セルには少なくとも 1 つの占有隣接セルがなければなりません。これは、空セルが占有セルに囲まれた孤立した単一のギャップにのみ出現できることを意味します。 

## アプローチ

 ブルートフォースの観点からプロセスをシミュレートします。 現在の配列を維持し、有効な位置を繰り返しスキャンします。$i$両方の隣接が空になるように、1 つを選択し、占有済みとしてマークし、移動が存在しなくなるか配置が完了するまで続行します。$K$人々。 これはプロセス定義と直接一致しており、正しいです。 

ただし、配置ごとにアレイ全体をスキャンするにはコストがかかります$O(N)$、そしてこれをやると$K$回が与えます$O(NK)$となり、$10^{12}$最悪の場合の運用。 それは限界をはるかに超えています。 

重要なのは、配置順序ではなく、最終状態が重要であるということです。 「これ以上の移動は存在しない」という制約は、構造的な条件を表します。つまり、インデックスがあってはなりません。$i$そのような$i$は空であり、隣り合うものは両方とも空です。 これは、すべての空のセグメントの長さは最大 2 であり、長さが 3 以上のセグメントには、将来の挿入をブロックする占有セルが含まれている必要がある、ということと同じです。 

ここから、逆の推論ができます。 人々の到着をシミュレートする代わりに、最終的なパターンを直接構築します。 占有された各セルは、隣接する 2 つの空のスロットを将来使用できなくなるように「強制終了」します。 したがって、各「X」は、それ自体を中心とする最大 3 サイズのウィンドウを効果的にブロックします。 

ということで梱包中です$K$「ブロッキングセンター」を長さ方向に変える$N$選択した中心から距離 1 以内のすべての位置を削除した後、使用可能なスロットが残らないようなライン。 これはカバー問題になります: 区間の結合$[i-1, i+1]$選択されたインデックスは、センターを許可しない孤立したブロックセーフな残り物を除くすべてのポジションをカバーする必要があります。 

実現可能性を確認するきれいな方法は、左から右へ貪欲に作業することです。 「X」を配置してから、次の位置をスキップして（隣接するため）、これを繰り返します。 これにより、距離 2 の制約の下で最大の独立セットが生成されます。 達成可能な配置の最大数は、$\lceil N/2 \rceil$。 もし$K$これを超えると、タスクは不可能になります。 

ただし、正確に達成すると、$K$また、移動が残らないようにするには、少し異なる視点が必要です。有効な配置の最大構成が必要であり、それが飽和していることを確認します。 3 つの連続する「-」のセグメントがない場合、構成は正確に飽和します。 この条件は、すべての空のランの長さが最大 2 であることを意味します。 

そこで、「---」を避け、正確に含むパターンを構築します。$K$×。 残りの予算に応じて、「X-X」または「XX-」スタイルのブロックを貪欲に構築することができ、フリーのトリプルギャップが決して作成されないようにします。 

これは、線形時間で解決できる、線分の建設的なパッキング問題に帰着します。

 ## アルゴリズムのチュートリアル

 まだ必要な配置数を維持しながら、最終的な文字列を左から右に構築します。 

1. 答えをすべて「-」として初期化し、カウンターを保持します`K_left = K`。 隣接性の制約を尊重しながらポジションを埋め、将来的に有効なポジションが意図せずに作成されることがないようにします。 
2. 位置を左から右に繰り返します。 各インデックスで$i$、「X」を配置できるかどうかを確認してください。 立場であれば許される$i$は現在空であり、両方の近隣は以前の配置によって強制されていません。 これにより、選択した 2 つの位置が隣接できないというルールが維持されます。 
3. 「X」を配置する場合は、$i$、設定しました`ans[i] = 'X'`、 減少`K_left`1 ずつ増加し、インデックスをスキップします$i+1$。 に配置するためスキップが必要です$i$無効にする$i+1$隣接制限により有効な候補として認められません。 
4. ポジションがなくなるか、必要な配置がなくなるまで、この貪欲な配置を続けます。 任意の時点で、これ以上「X」を配置できない場合でも、`K_left > 0`、建設は不可能です。 
5. 最大限の有効な配置を構築した後、連続する 3 つの位置のセグメントがすべて空になっていないことを確認します。 そのようなセグメントが存在する場合でも、新しい人物が配置される可能性があるため、構成は無効です。 有効であれば出力します。 

### なぜ効果があるのか

 重要な不変条件は、2 つの隣接する「X」位置を決して許可しないこと、さらに配置が必要な場合は常にできるだけ早く「X」を配置することです。 これにより、有効な設定が有効であるかどうかが保証されます。$K$配置が存在する場合、貪欲なプロセスは必要なポジションを早期にスキップしません。これは、スキップすると柔軟性が向上せず、将来の可用性が低下するだけであるためです。 結果として得られる構成は、距離 2 の制約の下で最大であり、最大であることは飽和を意味します。残りの空の位置には少なくとも 1 つの占有された隣接位置が必要であるため、それ以上の配置は不可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    K, N = map(int, input().split())
    
    ans = ['-'] * N
    K_left = K
    
    i = 0
    while i < N and K_left > 0:
        # try place at i if possible
        # must ensure no adjacency violation
        if ans[i] == '-':
            ans[i] = 'X'
            K_left -= 1
            i += 2
        else:
            i += 1
    
    if K_left > 0:
        print("*")
        return
    
    # check no "free move" remains: no "---"
    for i in range(N - 2):
        if ans[i] == ans[i+1] == ans[i+2] == '-':
            print("*")
            return
    
    print("".join(ans))

if __name__ == "__main__":
    solve()
```この実装では、単純な貪欲ポインタが維持されます。 「X」が配置されると、すぐに次の位置をスキップします。これは、この構造と一致するさらなる配置戦略の隣接条件に違反するためです。 残りのチェックでは、別の有効な挿入を可能にする長い空のセグメントを誤って残していないことを確認します。 

微妙な点は、貪欲なステップでは「X」を配置するときに近隣を明示的にチェックしないことです。 これは安全です。なぜなら、前に進むだけであり、隣接するインデックスに配置することは決してないからです。`i += 2`ジャンプ。 最後の検証ステップでは、グローバル構造の正確性を保証します。

 ## 特殊なケース

 主なエッジケースは次のような場合です$N = 1$。 唯一の有効な出力は、次の場合に単一のトイレを配置することです。$K = 1$。 インデックス 0 に配置され、すぐに次の条件が満たされるため、アルゴリズムはこれを処理します。`K_left = 0`、「X」を生成します。 

もう一つのケースは次のような場合です。$N = 2$。 何があっても、1 人を配置した後、他のポジションには常に隣接する占有された隣人が存在するため、$K = 1$実現可能です。 貪欲ループは位置 0 に配置され、1 をスキップして、すでに飽和している「X-」を生成します。 

長い空のセグメントも重要です。 たとえば、$N = 6, K = 2$、貪欲な人は「---」を含む「X-X---」を生成し、将来の手が存在することを誤って示唆する可能性があります。 最終チェックでは、トリプルフリーのセグメントをスキャンすることでこれを検出し、無効な受け入れを防ぎます。 

これらのケースは、微妙な無効な構造を避けるために、ローカル配置ルールとグローバル飽和チェックの両方が必要であることを確認しています。
