 ## 問題の理解

 長さのシーケンスが与えられます$N$これは、から番号が付けられたすべてのステーションの完全な訪問順序を表すことになっています。$1$に$N$。 一部のエントリは欠落しており、ゼロとして表示されますが、他のエントリは修正されており、すでに区別されています。 

最終シーケンスの意図された構造は非常に制約されています。つまり、基部から開始し、最高点に到達するまでいくつかのステーションを通過して厳密に上向きに登り、その後厳密に下降して、すべてのステーションを 1 回だけ訪問する必要があります。 言い換えれば、最終的な順列は 1 つのピークまで増加し、その後減少する必要があります。ただし、ピークが終了した場合には完全に増加するか完全に減少する可能性も考慮されます。 

すべてのステーションは他のすべてのステーションから到達可能であるため、グラフの説明は順序付けには事実上無関係です。 唯一の実際の制約は、順列の形状です。 

複雑さの観点から見ると、$N \le 10^5$私たちをほぼ直線状にするか、$O(N \log N)$ソリューション。 選択ごとに完全な検証を行ってピークのすべての配置を試すことを伴うものは、遅すぎます。 構築またはシングルパスの実現可能性チェックが必要です。 

微妙な点は、ゼロは独立して任意の値のプレースホルダーではないということです。 彼らは集合的に以下の順列を完了しなければなりません$1$に$N$, そのため、不足している数字はすべてどこかに強制的に配置されます。 

素朴な推論では 2 つの失敗パターンが頻繁に現れます。 

1 つの問題は、最終的な置換が有効である限り、欠損値の補完が機能すると仮定していることです。 たとえば、固定値がどちらかの側ですでに単調性に違反している場合、いくら埋めてもそれを修正することはできません。 次のような入力を検討してください$[3, 1, 2, 0, 0]$。 固定部分はすでに左側で減少を強制し、その後増加させますが、これは厳密に増加するプレフィックスの一部になることはできないため、解決策は存在しません。 

もう 1 つの問題は、ピークの配置を考えすぎていることです。 考えられる各位置で最大値をテストしようとする人もいるかもしれませんが、制約の構造により、単調制約が尊重される限り、実現可能性はピークがどこに配置されるかに関係なく行われます。 

## アプローチ

 強引なアイデアでは、ゼロを欠落している数値で置き換え、その結果の順列がビットニックであるかどうかを確認するあらゆる方法を試します。 まであります$N!$最悪の場合は完了し、残りの値の順列に制限しても階乗爆発が残ります。 「ピークを選択して残りの値を分配する」という構造を修正したとしても、ピークごとにすべての割り当てを試してみると、$O(N^2)$あるいはさらに悪いことに。 

重要な観察は、最終シーケンスには構造要件が 1 つだけあるということです。ピークの左側はすべて厳密に増加するシーケンスを形成し、右側はすべて厳密に減少するシーケンスを形成する必要があります。 すべての数値は個別であるため、各辺にどの値が属するかを決定すると、各辺内で値をどのように順序付けする必要があるかが完全に決まります。 

これにより、問題は一貫性チェックに集約されます。つまり、ピークの有効な分割に関して、すでに固定された数値が左側の昇順または右側の降順に違反しているかどうかです。 そうでない場合は、順序を尊重する限り、未使用の数値をどこに配置するかを自由に選択できるため、いつでも欠損値を貪欲に割り当てることができます。 

次に、ピーク値は次のとおりである必要があるという事実を利用します。$N$、すべての値は$1$に$N$が現れる必要があり、単峰順列のピークが最大要素である必要があります。 

一度$N$はピークとして扱われ、その位置は任意のゼロ位置にすることができます。 その後、問題は 2 つの独立した単調サブシーケンスにきれいに分割され、充填は簡単になります。

 ## アルゴリズムのチュートリアル

 まず、ゼロがどのように埋められるかに関係なく保持する必要がある構造上の制約を分離します。 

1. ピーク値の位置を特定する$N$。 もし$N$はすでに存在しているため、その位置は固定されています。 それ以外の場合、後で任意のゼロ位置に配置されますが、その正確な位置は固定値に対する単調制約の有効性に影響しません。 
2. 概念的に、ピーク位置の周囲で配列を左側の部分と右側の部分に分割します。 
3. 左側のすべての固定値を確認します。 順番に読むと、厳密に増加しているはずです。 隣接する固定値がこれに違反している場合、ゼロは固定要素の順序を変更できないため、補完では修復できません。 
4. 右側のすべての固定値を確認します。 順番に読むと、厳密に減少しているはずです。 繰り返しますが、違反があるとタスクは不可能になります。 
5. 未使用の番号をすべて収集します。$1$に$N$。 これらは、まさにゼロの位置を埋める必要がある値です。 
6. 欠損値を左右のパートに独立して割り当てます。 左側は残りの数値の一部を受け取り、左から右へ昇順に埋められます。 右側は残りを受け取り、左から右へ降順に埋められます。 
7. ピーク値を配置します$N$配列を選択した左右のサイズに分割する、使用可能な任意のゼロ位置で。 

重要な設計上の選択は、ゼロの正確な値を局所的に「推測」しないことです。 各側が残りの数値の一部の単調な順序付けをサポートできることだけを保証します。 

### なぜ効果があるのか

 最終的な順列は、ピークを伴う単峰性の場合に正確に有効です。$N$。 このような順列では、後方に移動したときに、左側のすべての位置が次の位置より小さく、右側のすべての位置が次の位置より大きくなければなりません。 これは、各辺がその値の並べ替え順序によって完全に決定され、唯一の実際の制約は、固定値がその順序と矛盾しないことであることを意味します。 未使用の番号を任意に割り当てることができるため、各辺内でソートすることで一貫した割り当てを完了できます。 値の分割を超えると、左と右の間の相互作用は存在しません。

import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    posN = -1
    for i in range(n):
        if a[i] == n:
            posN = i
            break
    
    if posN == -1:
        posN = next(i for i in range(n) if a[i] == 0)
    
    left_fixed = []
    right_fixed = []
    
    for i in range(n):
        if a[i] == 0:
            continue
        if i < posN:
            left_fixed.append(a[i])
        elif i > posN:
            right_fixed.append(a[i])
    
    for i in range(len(left_fixed) - 1):
        if left_fixed[i] >= left_fixed[i + 1]:
            print("*")
            return
    
    for i in range(len(right_fixed) - 1):
        if right_fixed[i] <= right_fixed[i + 1]:
            print("*")
            return
    
    used = set(x for x in a if x != 0)
    remaining = [x for x in range(1, n + 1) if x not in used and x != n]
    
    left_vals = []
    right_vals = []
    
    for i in range(n):
        if i == posN:
            continue
        if i < posN:
            left_vals.append(i)
        else:
            right_vals.append(i)
    
    # assign by simple sorted filling
    left_nums = sorted([x for x in remaining if len(left_vals) > 0])
    right_nums = sorted([x for x in remaining if len(left_vals) == 0])
    
    # build result
    res = a[:]
    l = sorted([x for x in remaining])
    # split counts
    lc = sum(1 for i in range(n) if i < posN and a[i] == 0)
    rc = sum(1 for i in range(n) if i > posN and a[i] == 0)
    
    left_fill = sorted(l[:lc])
    right_fill = sorted(l[lc:])
    
    li = 0
    ri = 0
    
    for i in range(posN - 1, -1, -1):
        if res[i] == 0:
            res[i] = left_fill.pop()
    
    for i in range(posN + 1, n):
        if res[i] == 0:
            res[i] = right_fill.pop()
    
    res[posN] = n
    
    print(*res)

if __name__ == "__main__":
    solve()
```コードは最初にピーク値がどこにあるかを決定します。$N$行かなければなりません。 まだ固定されていない場合は、任意のゼロ位置に一時的に配置され、残りの構築はその分割を中心に進行します。 

次に、各側の固定値がすでに単調順序に従っていることを検証します。 固定値は再配置できないため、このステップが実際に必要な唯一の実現可能性チェックです。 

その後、未使用の番号がすべて収集され、左側と右側に空きスロットがいくつあるかに応じて分割されます。 並べ替えにより、厳密な単調性を維持した方法で各辺を埋めることができます。 

最後に、ピークを配置し、両側に独立してゼロを埋めることによって配列が再構築されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ピークの両側に固定値がすでに表示されているものの、局所的には一貫している場合です。 たとえば、次のような左側のセグメント$[1, 3]$は有効ですが、後でゼロがそれらの間に小さい数値を強制的に配置する場合、アルゴリズムは固定順序を決して破らないことでこれを回避します。 

別のケースは、ピーク値が$N$は存在しません。 このような場合、これを任意に配置するのは危険に思えるかもしれませんが、これはグローバル最大値であるため、区切り文字として使用する場合を除いて、順序付けの制約と相互作用することはありません。 両側が単調である限り、任意のゼロ位置が機能します。 

3 番目のケースは、中央付近の 1 つの固定値を除くすべての値がゼロの場合です。 この構造は依然として機能します。固定値はローカルな順序を制限するだけであり、残りの数値は常に単調性を満たすためにその値を中心に分割できるからです。
