 ## 解決策
 ## 問題の理解

 バイナリ文字列としきい値が与えられます。$K$。 次の文字列が含まれている場合、その文字列は「不良」とみなされます。$K$または複数の同一の連続文字。これは、次のようなブロックを意味します。$0000$いつ$K = 4$、 または$111$いつ$K = 3$。 「kool」文字列は、等しい文字のすべての最大ブロックの長さが厳密に以下のバイナリ文字列です。$K$。 

個々の文字を反転して、0 を 1 に、または 1 を 0 に変えることができます。また、最小限の反転回数で元の文字列を有効なクール文字列に変換したいと考えています。 また、そのような結果の文字列を 1 つ出力する必要があります。 

重要な問題は、キャラクターの反転がローカルで単独で機能しないことです。 ビットを変更すると、長いランを小さなランに分割したり、将来のフリップ後に隣接するランをマージしたりする可能性があるため、問題は、最小限のコストを支払いながら、長いセグメントを許容される部分にグローバルに分割することです。 

入力サイズは以下に達します$10^5$これにより、考えられるすべての変更された文字列を考慮しようとしたり、決定ごとにすべてのサブセグメントを実行したりするソリューションは直ちに除外されます。 仮説を反転するたびに妥当性を再計算するなど、二次関数は遅すぎます。 線形または線形に近い貪欲な構造が必要です。 

微妙なエッジケースは、長いランがちょうど境界に現れるか、決定を反転した後に重なって現れる場合に現れます。 たとえば、次の場合$K = 3$そして文字列は$00000$、3 文字ごとに個別に反転するだけの単純なアプローチでは、次のような結果が得られる可能性があります。$01010$これは有効ですが、グループ化戦略によっては必ずしも最適であるとは限りません。 正しい解決策では、ポジションごとに個別に決定するのではなく、フリップが各最大ラン内で調整されるようにする必要があります。 

もう 1 つのエッジケースは次のような場合です$K = 2$。 この場合、2 つの等しい文字が隣接することはできないため、ターゲット文字列は厳密に交互する必要があります。 この特殊なケースは、等しい隣接ペアのすべてが直ちに無効になるため、単純な実行ベースの思考を誤解させる可能性があります。 

## アプローチ

 ブルートフォース手法では、結果として得られる可能性のあるすべての文字列を試し、最適なものを選択します。 各位置は 0 または 1 になるため、次のようになります。$2^n$候補を確認し、各テイクの妥当性をチェックする$O(n)$、指数関数的増加につながる$O(n2^n)$小規模でも実現不可能な解決策$n$。 

より構造化されたブルートフォースでは、元の文字列を最大長のブロックに分割する方法を選択することによって最終的な文字列が完全に決定されることを観察することで、これを改善します。$K-1$、そして各ブロックの性格を決めます。 ただし、それでも、すべての境界の選択が次の境界の選択と相互作用するため、すべてのセグメンテーションを列挙することは依然として指数関数的に増加します。 

重要な洞察は、恣意的な反転という観点から考えるのをやめ、代わりに、元の文字列内の同一文字の最大実行ごとに違反を局所的に修正するという観点から考えることです。 次のようなセグメントを見てみるとします。$000000$。 有効な最終文字列は、これを最大でもサイズの塊に分割する必要があります$K-1$。 最小限の反転でこれを行う唯一の方法は、どの位置が同じキャラクターのままで、どの位置を反転してブレークを作成するかを決定することです。 重要なのは、フリップでは、他の場所での違反を減らすのに役立たない追加のコストを支払わなければ、異なる元の値の実行をマージできないため、単一の実行内では最適な戦略が他の実行から独立しているということです。 

これにより、各最大実行を個別に処理するという問題が軽減されます。 長さのランごとに$L$、同じ文字のセグメントが 2 文字を超えないように、2 文字にわたる文字列に変換したいと考えています。$K-1$、コストは元の実行キャラクターから変更されたポジションの数です。 ランは均一であるため、決定は、どのセグメントも超過しないようにラン内のどこで反転するかを選択することになります。$K-1$、フリップを最小限に抑えながら。 

これは古典的な貪欲なグループ化の問題になります。各実行をトラバースし、次の値を超えるものは決して許可しないように強制します。$K-1$連続した同一の最終文字。必要な場合にのみ反転を選択します。

 ## アルゴリズムのチュートリアル

 文字列は左から右に処理されますが、重要な構造は、等しい文字の最大の実行を処理することです。 

1. すべての文字が同一である最大のセグメントに文字列を分割します。 各セグメントは独立して処理できます。その理由は、その特性を変更する反転はローカル隣接制約にのみ影響し、他のランの内部構造には影響しないからです。 
2. セグメントごとに、次の内容が含まれない有効な出力に変換する方法を決定します。$K$連続する等しい文字。 元のセグメントは均一であるため、このタスクは、長いランを最大でもサイズの塊に分割するフリップのパターンを決定するものであると解釈します。$K-1$。 
3. セグメントを走査し、現在の出力実行内で元のセグメント文字と一致する文字の数のカウンタを維持します。 カウンターが到達した場合$K$、そうしないと制約に違反してしまうため、現在の位置を反対のビットに反転する必要があります。 このリセットにより、構築された文字列内に無効な実行が構築されることがなくなります。 
4. キャラクタを反転すると、反対のキャラクタのランを構築しているため、現在の出力ランのカウンタもリセットします。 有効性は元のセグメントごとではなく文字値ごとに定義されるため、これは不可欠です。 
5. 作成した各文字を答えに追加して進めます。 フリップの総数は、単純に、構築された文字が元の文字列と異なる位置の数です。 

この貪欲な強制により、厳密に必要な場合にのみ反転することが保証され、不必要な変更が導入されることがなくなります。 

### なぜ効果があるのか

 すべての位置で、アルゴリズムは、構築された文字列の現在のサフィックスに決して含まれないという不変式を維持します。$K$連続する同一文字。 もし私たちが到達できたら$K$ラン内の元のキャラクターとの連続した一致は、反転せずに継続すると直ちに制約に違反するため、反転が強制されます。 制約に違反しない場合は、コストが増加しないため、元のキャラクターを維持することが常に最適です。 したがって、すべてのフリップは強制補正に正確に対応し、最小性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    K, S = input().split()
    K = int(K)
    n = len(S)
    
    res = []
    flips = 0
    
    i = 0
    while i < n:
        j = i
        while j < n and S[j] == S[i]:
            j += 1
        
        seg_len = j - i
        
        cnt_same = 0
        current_char = S[i]
        
        for idx in range(i, j):
            if cnt_same == K - 1:
                # we cannot extend run, must flip
                new_char = '1' if current_char == '0' else '0'
                res.append(new_char)
                flips += (new_char != S[idx])
                cnt_same = 1
                current_char = new_char
            else:
                res.append(current_char)
                flips += (current_char != S[idx])
                cnt_same += 1
        
        i = j
    
    print(flips, ''.join(res))

if __name__ == "__main__":
    solve()
```実装は最初に解析します$K$と文字列を検索し、等しい文字の最大セグメントを反復処理します。 各セグメント内で、同一の出力文字が長さに達しないようにしながら出力を貪欲に構築します。$K$。 カウンター`cnt_same`現在の出力実行の長さを追跡します。 届いたら$K-1$、違反を防ぐために、次の位置を反対のビットに反転する必要があります。 

実装の微妙な詳細は、選択された出力文字とその位置にある元の文字列を比較することによってフリップがカウントされることです。 これにより、強制変更により構築された文字が異なる場合でも、正確性が保証されます。 もう一つ重要なポイントはリセットです`cnt_same`反転後、実行 ID が変更されるため。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$K=2$等しい文字のペアはすべて無効であるためです。 入力用`2 0000`、アルゴリズムは 2 文字ごとに即座に反転し、次のようなものを生成します。`0101`。 2 つの同一の隣接する出力は決して許可されないため、不変条件は依然として維持されます。
