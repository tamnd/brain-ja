 ## 解決策
 ## 問題の理解

 線が与えられており、これを X 軸と考えることができます。 この線上には、明確な X 座標に垂直に立っている数人の人がいます。 各人には身長があるため、各人は直線上に固定された垂直線分と考えることができます。 

光は、線の上の左端から、地面に対して一定の角度 θ で来ます。 光の方向は決まっているので、各人は右にまっすぐな影を落とします。 影は任意ではなく、再び地面と交差するまで光の方向に沿って投影される光線です。 

必要なのは、これらの影の少なくとも 1 つによってカバーされる X 軸の全長です。 シャドウ間の重なりは 1 回だけカウントする必要があるため、ライン上の一連の間隔の結合長を効果的に計算することになります。 

重要な難易度は幾何学的なものです。 各人は、他の人から独立して固定長の影を生成するわけではありません。 影の長さは高さと角度の両方に依存し、後ろの背の高い人が特定の方法で光を遮ると、その人の位置よりも早く影が始まる可能性があります。 これにより、要素間に相互作用が生じ、各シャドウを独立して処理することができなくなります。 

この制約により、最大 100,000 人が許可され、ポジションは最大 3 × 10^5 になります。 これにより、人々のすべてのペアを明示的に比較したり、影の伝播を段階的にシミュレートしようとする二次アプローチは即座に除外されます。 O(N log N) または O(N) に近い値が必要です。 

単純な間違いは、各シャドウを個別に計算してから間隔をマージすることです。 シャドウ エンドポイントは個人自体によって純粋に決定されないため、これは失敗します。 もう 1 つの微妙な失敗モードは、影が常に無限に伸びると想定していることです。 実際には、それぞれの影は光線と地面の交差点の幾何学形状によって切り取られ、光を遮る他の点とも効果的に相互作用します。 

2 番目の微妙なエッジケースは、複数の背の高い人と低い人が交互に配置されるときに現れます。 幾何学的投影を正しく処理せずに左から右へ貪欲に累積すると、シャドウの境界は高さの違いだけでなく傾斜の比較に依存するため、セグメントを過大にカウントしたり、過少カウントしたりする可能性があります。 

## アプローチ

 この強引なアイデアは、文字通りジオメトリをシミュレートすることです。 各人について、その人の頭頂部を通過する光の方向からの線を計算し、それが地面と交差する場所を見つけることができます。 これにより影のエンドポイントが得られ、人の位置からそのエンドポイントまでの間隔が計算されます。 最後に、すべての間隔をマージし、和集合の長さを計算します。 

問題は、これはシャドウが独立していることを前提としているということです。 実際には、近くにいる人が後ろの背の高い人によって完全に隠れてしまう可能性があり、単純な一人当たりの投影が無効になります。 これを修正するには、すべての影を投影する線によって形成されるエンベロープを考慮する必要があります。 

正しい観察は、すべての影は単一の単調な構造によって支配されているということです。つまり、照明の境界は、各人の身長と位置によって決定される線の上部包絡線です。 変換された座標系で線を定義するものとして各人物を再解釈すると、影の結合は、線スイープにおける古典的な包絡線または凸包タイプの問題になります。 

幾何学的変換は、各影の境界を、tan(θ) によって決定される傾きを持つ x の一次関数として表現することから得られます。 これにより、問題は x 上の線形関数の最大値を維持することに変わります。 照らされた障害物の結合は、ある線が別の線を支配する追跡に変換されます。 

問題を x 座標でソートされた線の上部エンベロープを維持することに縮小すると、人々を順番に処理し、単調な構造を使用してアクティブなフロンティアを維持できます。 これにより、ペアごとの比較が回避され、線形時間が得られます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース インターバル + マージ | O(N^2) | O(N) | 遅すぎる |
 | エンベロープ/スイープの最適化 | O(N log N) または O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. X 座標を増やしてすべての人物を並べ替えます。 これにより、地面に沿った動きと同じ順序でジオメトリが処理され、シャドウの境界が空間的にどのように変化するかに合わせて処理できるようになります。 
2. 各人物を、線形の境界を定義する幾何学的オブジェクトに変換します。 光の角度 θ を使用して、影の制約を Tan(θ) から導出される傾きを持つ線として表現します。 これにより、高さが線形関数のオフセットに変換されます。 
3. これらのラインの現在の上部エンベロープを表す構造を維持します。 新しい人物はそれぞれ、新しい境界セグメントに貢献するか、以前の境界セグメントによって完全に支配されます。 
4. 新しい人物を処理するときは、その人物の行とエンベロープ内の最後のアクティブな行を比較します。 新しい行が常に以下である場合は、何も寄与しないため、破棄できます。 
5. 新しいラインが現在のエンベロープと交差する場合は、交点を計算します。 この点は優勢が切り替わる境界となり、それに応じて前のラインの寄与を切り捨てます。 
6. 各ラインが影の範囲を担当する x 軸上の有効な間隔を追跡することによって、寄与の長さを累積します。 これらの間隔を結合すると、影で覆われた領域全体が形成されます。 
7. すべての点を処理した後、すべてのエンベロープ セグメントの長さを合計します。 

重要な考え方は、各人は上部のエンベロープの一部を定義する場合にのみ重要であるということです。 他のものはすべて完全に影になってしまいます。 

### なぜ効果があるのか

 各人は、影の影響が線形である変換された座標系の線に対応します。 すべての位置 x で支配的な影はすべての人々の間で最大の幾何学的制約によって決定されるため、目に見える影の境界は正確にこれらの線の上の包絡線です。 エンベロープを定義する線のみを維持することにより、地面が少なくとも 1 つの影で覆われている点のセットが正確に保存され、エンベロープ セグメントが軸を互いに素な支配区間に分割するため、領域が 2 回カウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def solve():
    theta, n = map(int, input().split())
    pts = []
    for _ in range(n):
        x, h = map(int, input().split())
        pts.append((x, h))

    pts.sort()

    # direction of light
    t = math.tan(math.radians(theta))

    # We model shadow as envelope of lines in transformed space.
    # Each point contributes a line: y = a*x + b in dual space.
    # slope depends on tan(theta), height contributes intercept shift.

    def intersect(a1, b1, a2, b2):
        return (b2 - b1) / (a1 - a2)

    hull = []  # (a, b, start_x)

    def add_line(a, b):
        if hull:
            while True:
                a1, b1, x1 = hull[-1]
                if abs(a1 - a) < 1e-12:
                    if b <= b1:
                        return
                    else:
                        hull.pop()
                        if not hull:
                            break
                        continue
                x = (b1 - b) / (a - a1)
                if len(hull) >= 2 and x <= hull[-1][2]:
                    hull.pop()
                else:
                    break
        x_start = -1e30 if not hull else (b - hull[-1][1]) / (hull[-1][0] - a)
        hull.append((a, b, x_start))

    for x, h in pts:
        a = t
        b = h - t * x
        add_line(a, b)

    # integrate envelope
    ans = 0.0
    for i in range(len(hull)):
        a, b, x_start = hull[i]
        x_end = hull[i + 1][2] if i + 1 < len(hull) else 1e30
        # value is linear contribution projected back
        ans += max(0.0, x_end - x_start)

    print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```コードはまず、幾何学的構造が軸に沿って一貫性を持つように人物を分類します。 角度の正接は、シャドウの伝播における水平方向の変位が垂直方向の高さにどのように関係するかを定義します。 変換された表現では各人物が線になり、モノトーン スタックには実際に目に見える影の境界に寄与する線だけが維持されます。 

の`add_line`関数は、完全に支配されているラインを削除することにより、エンベロープの凸性を強制します。 交差点は、取材に対する責任が、ある人から別の人に切り替わる場所を定義します。 最後に、蓄積されたセグメントが合計されて、カバーされる全長が算出されます。 

三角関数のスケーリングにより交点が実数値になるため、浮動小数点演算が必要になります。

 ## 特殊なケース

 主要なエッジケースは、光の角度に対して、すべての人が同じ高さと位置の構造を持っている場合に発生します。 この状況では、生成されたすべての線は変換された空間内で平行になります。 アルゴリズムは、等しい傾斜を個別に処理し、より高い切片を優先することでこれを処理し、支配的な構造のみが船体に残るようにします。 

もう 1 つのケースは、非常に背の高い人が小柄な人の右端に見える場合です。 人物ごとのシャドウの単純な計算では、誤って以前のシャドウが過度に拡張される可能性がありますが、エンベロープの構築により、交差点で正確に以前の寄与が切り捨てられ、過剰カウントが防止されます。 

最後の微妙なケースは、交差点付近の浮動精度です。 2 つの線が非常に近くで交差する場合、単純な比較では優先順位が誤って入れ替わる可能性があります。 このアルゴリズムは、一貫した挿入順序と船体メンテナンス ステップでの厳密な不等号処理によってこれを回避します。
