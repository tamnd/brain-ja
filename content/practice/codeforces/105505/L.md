 ## 解決策
 ## 問題の理解

 未知のラテン方陣に適用される一連の演算が与えられます。 ラテン広場というのは、$N \times N$～の数字で埋められたグリッド$1$に$N$, ここで、各数値は各行および各列に 1 回だけ表示されます。 重要な特性は、行と列が行内で繰り返されることなく、同じシンボル セットの順列であることです。 

最終的なグリッドは表示されず、変換のリストのみが表示されます。 各変換では、2 つの行または 2 つの列が交換されます。 これらのスワップは、最初の隠れたラテン方陣に次々に適用され、最終的な行列が生成されます。 

ただし、実際には最終的な行列が与えられていないのが問題です。 私たちは別の逆質問をされます: すべてのスワップを適用した後、変換と一致する有効な最終構成を取得できるような初期ラテン方陣は存在しますか? 「はい」の場合、そのような初期正方形を少なくとも 1 つ構築する必要があります。 そうでない場合は、不可能であると出力します。 

重要な認識は、行と列を交換してもラテン方陣の特性が破壊されないということです。 行と列を並べ替えるだけで、構造は維持されます。 したがって、変換は行インデックスと列インデックスに対する独立した置換として機能します。 

制約により、最大で$N \le 500$そして$T \le 10^5$。 これは、完全な行列でスワップをシミュレートしたり、操作ごとに行の内容を明示的に再計算したりできないことを直ちに示唆しています。 どのようなソリューションでも、スワップのシーケンスを線形または線形に近い時間でインデックスの最終的な順列に圧縮する必要があります。 

複数のスワップが互いに打ち消し合ったり、サイクルを形成したりする場合、微妙なエッジケースが発生します。 たとえば、2 つの同一の行スワップは行の恒等変換を復元しますが、中間推論ではカウント スワップだけでなくパリティと構成を正しく考慮する必要があります。 もう 1 つのエッジ ケースは、2 つの次元を分離せずに直接マッピングを再構築しようとした場合に、行と列の置換が矛盾を示唆する方法で相互作用する場合です。 

## アプローチ

 単純な試みでは、プロセスを直接シミュレートすることになります。 行列を明示的に維持し、各行または列の交換を順番に適用することもできます。 各スワップのコスト$O(N)$したがって、全体の複雑さは次のようになります。$O(TN)$、最悪の場合は$10^5 \cdot 500 = 5 \cdot 10^7$操作。 境界線にありますが、本当の問題は、最終的な行列がまだ分からないことです。したがって、シミュレーションだけでは有効な逆行列を構築するのには役立ちません。 さらに悪いことに、問題は最終状態を計算することではなく、それにマッピングできる一貫した元の構成を見つけることです。 

重要な洞察は、マトリックス内の値について考えるのをやめ、代わりにポジションがどのように移動するかを考えることです。 各行のスワップにより、行インデックスの順列が構成されます。 各列のスワップは、列インデックスの順列を構成します。 すべての操作を処理した後、2 つの順列が得られます。1 つは元の各行がどこで終わるかを記述し、もう 1 つは元の各列がどこで終わるかを記述します。 

次に、最後の行列を考えてみましょう。 細胞$(i, j)$最後のグリッドは元のセルに対応します$(r, c)$、 どこ$r$のプリ画像です$i$行の置換の下で、$c$のプリ画像です$j$列の置換の下にあります。 これは、有効なラテン方陣を最終構成として選択した場合、それを逆マッピングして有効な初期四角形を構築できることを意味します。 

したがって、問題は、ラテン方陣を作成し、行と列の逆順列を適用して元の状態に「戻す」ことに帰着します。 任意のラテン方格が受け入れられるため、標準的な循環構造を使用できます。$A[i][j] = (i + j) \bmod N + 1$。 残る唯一の問題は、合成された行と列の順列が明確に定義されているかどうかです。スワップは順列であるため、常に明確に定義されています。 

最後のステップは一貫性をチェックすることです。行と列のすべての置換がラテン方格の妥当性を維持するため、構造を無効にする追加の制約はありません。 したがって、答えは常に構成可能であり、実際の唯一のタスクは逆順列を正しく適用することです。

 ## アルゴリズムのチュートリアル

 変換の効果を 2 つの独立した順列に分割し、1 つは行に作用し、もう 1 つは列に作用します。 

1. 2 つの配列を初期化する$row[i] = i$そして$col[i] = i$。 これらは、元のインデックスから現在のインデックスへの ID マッピングを表します。 
2. 各操作を順番に処理します。 間の行交換の場合$i$そして$j$、交換$row[i]$そして$row[j]$。 列の交換の場合は、交換します$col[i]$そして$col[j]$。 これは、順列構成を直接シミュレートします。 
3. すべての操作が完了すると、元のインデックスから最終インデックスへのマッピングが得られます。 逆マッピングも必要なので、配列を構築します$invRow$そして$invCol$そのような$invRow[row[i]] = i$列についても同様です。 
4. 正統なラテン方陣を構築する$base[i][j] = (i + j) \bmod N + 1$。 これにより、すべての行と列にすべての値が 1 回だけ含まれるようになります。 
5. 変換を逆にして、最初の正方形を構築します。 最終順位ごとに$(i, j)$から値を配置します。$base[invRow[i]][invCol[j]]$の回答行列に$(i, j)$。 

この方向性が機能する理由は、値について直接推論しようとするのではなく、インデックスの順列を効果的に元に戻しているためです。 

### なぜ効果があるのか

 行の交換は順列を定義します$P$行インデックスと列スワップで順列を定義します$Q$列インデックスについて。 各行と列は次の順列のままであるため、独立した行と列の順列の下では、ラテン方陣はラテン方陣のままになります。$1 \ldots N$。 有効なラテン方格を構築し、逆順列を適用することで、指定された変換を適用すると同じ最終配置が再構築されることが保証されます。 これは、未知のオリジナルを明示的に再構築する必要なく、存在と正しさを示します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    N, T = map(int, input().split())
    
    row = list(range(N))
    col = list(range(N))
    
    for _ in range(T):
        parts = input().split()
        typ = parts[0]
        i = int(parts[1]) - 1
        j = int(parts[2]) - 1
        
        if typ == 'R':
            row[i], row[j] = row[j], row[i]
        else:
            col[i], col[j] = col[j], col[i]
    
    inv_row = [0] * N
    inv_col = [0] * N
    
    for i in range(N):
        inv_row[row[i]] = i
        inv_col[col[i]] = i
    
    base = [[0] * N for _ in range(N)]
    for i in range(N):
        for j in range(N):
            base[i][j] = (i + j) % N + 1
    
    ans = [[0] * N for _ in range(N)]
    for i in range(N):
        for j in range(N):
            ans[i][j] = base[inv_row[i]][inv_col[j]]
    
    for row_ in ans:
        print(*row_)

if __name__ == "__main__":
    main()
```このソリューションでは、まず、直接スワップを使用して、すべての変換を 2 つの順列に圧縮します。 値を元の座標系に配置する必要がある一方で、順列は元のインデックスから最終インデックスへの前方への移動を記述するため、反転ステップは非常に重要です。 標準的なラテン方陣は、すべての行と列の置換の下で有効な中立構造として使用されます。 

よくある間違いは、演算のみに基づいて値を再構築しようとすることですが、変換によって値が制約されることはなく、位置のみが制約されます。 その分離こそが構築を有効なものにするのです。

 ## 特殊なケース

 エッジケースの 1 つは、スワップが時間の経過とともに相殺される場合です。 たとえば、行 1 と行 2 を 2 回交換すると、同一性が戻ります。 アルゴリズムはスワップを置換配列に直接適用するため、これを自然に処理します。 2 回目の交換の後、順列は元の状態に戻り、反転により一貫したマッピングが生成されます。 

もう 1 つの特殊なケースは、行と列が大量に混在していることです。 すべての行が完全に並べ替えられ、すべての列が完全に並べ替えられた場合でも、アルゴリズムは中間行列構造に依存しません。 最終的な順列のみに依存するため、矛盾が生じることはありません。 

最後のエッジケースは次のような場合です$N = 2$, ここで、ラテン方陣には有効な形式が 2 つだけあります。 この構築でも有効な巡回行列が生成され、順列は有効性を損なうことなく行と列の順序を変更するだけであり、最小スケールでも正確さを確認します。
