 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースでは、正の整数の配列から開始します。 2 つの異なる位置を繰り返し選択し、乗算係数を 1 つの値から別の値に移動することができますが、その係数は最初に選択した値の約数でなければなりません。 具体的には、1 つの数値を何らかの約数で割り、その約数を乗算によって別の要素に押し込むことで、1 つの数値を 2 つの部分に分割します。 

目標は、最終的にすべての要素が同一になるように素因数を配列全体に再配分できるかどうかを判断することです。 

この演算を解釈する便利な方法は、すべての数値の合計積が決して変更されないということです。 1 つの要素を x で除算し、別の要素を x で乗算すると、全体積は不変になります。 したがって、私たちができる唯一の自由は、素因数を要素間でどのように配分するかを再配置することです。 

各要素は素因数に分解でき、この操作により、任意のグループ化されたチャンク内の要素間で素因数を移動できます (個々の素数だけでなく、任意の約数が許可されるため)。 

制約は十分に小さいので、各テスト ケースについて、ほぼ線形または線形因数分解を行うことができます。 すべての n の合計は最大 10^4 で、値は最大 10^6 になるため、ふるいまたは事前計算された SPF による素因数分解が適切です。 n の二次関数はテスト ケースごとにすでに安全ですが、値に直接依存するものは遅すぎます。 

平均または gcd のような不変量の観点から考えると、微妙な問題が発生します。 イコライゼーションは sum または gcd のみに依存するのではないかと素朴に考えますが、どちらも最終状態を直接特徴付ける方法では保存されません。 不変式は加算ではなく乗算です。 

エッジ ケースは、すべての数値がすでに等しい場合に発生し、即座に YES を返す必要があります。 もう 1 つの問題は、数値が互いに素であり、すべての要素にわたって素指数を均等に再分配できない場合です。 たとえば、[2, 3, 5] がある場合、素数を移動することはできますが、素数の指数の合計は n で割り切れなければならないため、すべての要素が同じで終わる一致する分布を作成することはできません。 

## アプローチ

 強引なアイデアは、操作をシミュレートすることです。 すべてのインデックスのペア、選択した要素のすべての約数を試し、再帰的または BFS を使用して遷移を適用します。 各状態はアレイ構成です。 これはすぐに爆発します。各数値には多くの約数が含まれる可能性があり、素因数はさまざまな方法で再分配できるため、構成の数は指数関数的に増加します。 n = 10 の場合でも、これは実行不可能になります。 

重要な観察は、この演算によって配列全体の素数指数の複数セットが変更されないことです。 すべての素因数は、すべての要素にわたる固定合計指数に寄与し、それらの指数を n 個のビン間で再分配するだけです。 最終状態では、各数値が同一である必要があります。つまり、すべての要素に各素数のまったく同じ指数が含まれている必要があります。 

したがって、各素数 p について、配列全体の指数の合計が S の場合、最終構成では各要素に p の S / n 個のコピーが含まれている必要があります。 つまり、S はすべての素数に対して独立して n で割り切れる必要があります。 許可された操作を使用して要素間で素数べき乗を常に移動できるため、この条件は必要かつ十分です。 

したがって、問題は、すべての数値を因数分解し、素数ごとの指数を合計し、n で割り切れるかどうかを確認することに帰着します。

 | ブルートフォースシミュレーション | 指数 | 指数 | 遅すぎる |
 | 素数指数のカウント | O(n log A) | O(A) または O(素数の数) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 10^6 までのすべての整数の最小素因数を事前計算します。 これにより、各数値を高速に因数分解できます。 その理由は、すべてのテスト ケースにわたって効率的に値を素数に繰り返し分解する必要があるためです。 
2. テスト ケースごとに、配列全体の素数指数の合計を追跡する辞書または配列を初期化します。 これは、主要因子の世界的な在庫を表します。 
3. 各要素 a[i] について、SPF テーブルを使用して要素を因数分解し、その素数指数をグローバル カウントに追加します。 因数分解は乗法構造を一意に表すため、この手順は有効です。 
4. すべての要素を処理した後、記録されたすべての素数を反復処理し、各合計指数が n で割り切れるかどうかを確認します。 最終状態では、すべての要素が各素数の正確に等しいシェアを持たなければならないため、これが必要です。 
5. すべての素数が割り切れる場合は、YES を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 この演算により、配列内のすべての素数の合計指数が保存されます。 要素間で任意の約数を移動できるため、素数累乗を任意のチャンク内で移動できます。これは事実上、各素数を位置間で独立して再分配できることを意味します。 すべての要素を等しくするための唯一の障害は、各素数の合計指数を n 個の要素に均等に分割できるかどうかです。 これが当てはまる場合、建設的な再分配が存在します。 そうでない場合は、少なくとも 1 つの要素に小数指数が必要になりますが、これは不可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXA = 10**6

spf = list(range(MAXA + 1))
for i in range(2, int(MAXA ** 0.5) + 1):
    if spf[i] == i:
        step = i
        start = i * i
        for j in range(start, MAXA + 1, step):
            if spf[j] == j:
                spf[j] = i

def factorize(x, acc):
    while x > 1:
        p = spf[x]
        cnt = 0
        while x % p == 0:
            x //= p
            cnt += 1
        acc[p] = acc.get(p, 0) + cnt

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    total = {}
    for v in a:
        factorize(v, total)
    
    ok = True
    for p, cnt in total.items():
        if cnt % n != 0:
            ok = False
            break
    
    print("YES" if ok else "NO")
```SPF ふるいは、10^6 までの各数値をその値に対して対数時間で因数分解できるように、最小の素因数配列を構築します。 各因数分解により素数が共有辞書に蓄積されます。 

正確性チェックでは、指数の合計が n で割り切れるかどうかのみが検証されます。 最終構成の各要素は各素数の cnt / n 個のコピーを正確に受け取る必要があるため、これで十分です。 

よくある間違いは、gcd または積の可分性のみをチェックすることですが、制約は素数ごとであり、素数間で独立しています。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
a = [8, 2, 4]
```因数分解:

 8 = 2^3

 2 = 2^1

 4 = 2^2

 2 の合計指数は 6 です。 

| ステップ | アクション | 2 の合計指数 | n | チェック |
 | --- | --- | --- | --- | --- |
 | 1 | プロセス8 | 3 | 3 | - |
 | 2 | プロセス2 | 4 | 3 | - |
 | 3 | プロセス4 | 6 | 3 | 6 % 3 == 0 |

 6 は 3 で割り切れるので、各要素の指数は 2 になり、[4, 4, 4] が生成されます。 これにより、指数合計が均等に分割される場合に再分配が機能することが確認されます。 

### 例 2

 入力:```
n = 3
a = [2, 3, 5]
```各素数は 1 回出現するため、合計は次のようになります。 

2:1、3:1、5:1

 | プライム | 合計指数 | n | 割り切れる |
 | --- | --- | --- | --- |
 | 2 | 1 | 3 | いいえ |
 | 3 | 1 | 3 | いいえ |
 | 5 | 1 | 3 | いいえ |

 3 で割り切れるものはないため、均等な分布は存在しません。 各最終要素には小数部の素指数が必要ですが、これは不可能です。

 この制約では合計 10^4 までの合計要素と最大 10^6 までの値が許可されるため、線形ふるいと高速因数分解は制限内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MAXA = 10**6
    spf = list(range(MAXA + 1))
    for i in range(2, int(MAXA ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, MAXA + 1, i):
                if spf[j] == j:
                    spf[j] = i

    def factorize(x, acc):
        while x > 1:
            p = spf[x]
            cnt = 0
            while x % p == 0:
                x //= p
                cnt += 1
            acc[p] = acc.get(p, 0) + cnt

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = {}
        for v in a:
            factorize(v, total)

        ok = True
        for c in total.values():
            if c % n != 0:
                ok = False
                break

        out.append("YES" if ok else "NO")

    return "\n".join(out)

 ## 特殊なケース

 [100] のような単一要素の配列の場合、アルゴリズムは 100 を因数分解し、すべての素数指数が 1 で割り切れることを検出します。チェックは常にパスして YES を返し、演算が必要ないという事実と一致します。 

[7,7,7,7] などの既に均一な配列の場合、すべての素数指数の合計は n の倍数になります。 各素数カウントは 1 つの要素の指数の 4 倍であるため、割り算が成り立ち、アルゴリズムは再配分の推論なしで YES を確認します。 

[2,3,5] など、合計指数が割り切れない配列の場合、各素数の合計指数は 1 ですが、n は 3 です。チェック中に、それぞれが割り切れず、アルゴリズムは変換を試行せずに正しく NO を返します。
