 ## 解決策
 ## 問題の理解

 整数のシーケンスが与えられており、私たちの目標は、最小限の削除を使用してそれを「美しい」シーケンスに変換することです。 美しいシーケンスは連続したブロックで構成されており、各ブロックは長さを示す数字で始まり、その直後にちょうどその数の要素が続きます。 たとえば、シーケンス`[3, 3, 4, 5, 2, 6, 1]`に分けられるのですでに美しいです`[3, 3, 4, 5]`そして`[2, 6, 1]`、それぞれブロック長ルールを尊重します。 

入力は複数のテスト ケースで構成されます。 テストケースごとに、シーケンスの長さが与えられます。`n`そしてシーケンスそのもの。 出力はテスト ケースごとに 1 つの整数、つまりシーケンスを美しくするために必要な最小削除数です。 

この制約は、考えられるすべてのサブシーケンスに対する総当りアプローチが実行不可能であることを意味します。`n`まで可能です`2 * 10^5`、との合計`n`すべてのテスト ケースの上限も次のとおりです。`2 * 10^5`、これは、`O(n log n)`または`O(n)`テストケースごとのソリューションは許容されますが、`O(n^2)`が遅すぎるでしょう。 

ほとんどすべての要素を削除する以外にシーケンスが有効なブロックを形成できない場合、微妙なエッジ ケースが発生します。 例えば、`[5, 6, 3, 2]`有効な開始ブロックを形成できないため、最小限の解決策としてはすべてを削除する必要があります。 潜在的なブロック長に等しい数値を前方検索でスキャンするだけの単純なアプローチは、このような場合には失敗する可能性があります。 

## アプローチ

 ブルートフォース手法では、考えられるすべてのサブシーケンスを試し、有効なブロックに分割できるかどうかを確認します。 開始インデックスごとに、次の長さのブロックの読み取りを試みることができます。`a[i]`そして残りを再帰的に検証します。 これは概念的には機能しますが、`O(2^n)`複雑さは完全に非現実的です`n = 2 * 10^5`。 

効率的なソリューションを実現するための重要な点は、関連する削除は、ブロックを壊すかブロックを完了できない削除だけであるということです。 各予想ブロックの最初の要素を潜在的なブロック長として扱う場合、問題は、ブロック長構造に一致する**連続ブロックの最長シーケンス**を見つけることになります。 この配列の長さがわかれば、最小限の欠失は次のようになります。`n - total_length_of_blocks`。 

動的プログラミングテーブルを維持できる`dp[x]`これは、これまでに確認された最長の「値 x で終わる美しいプレフィックス」を表します。 次に、シーケンスを反復処理します。`a[i]`長さのブロックが続くと予想されます`dp[a[i]]`、それを拡張します。 それ以外の場合は、新しいブロックを開始します。 このように DP を更新することで、美しいサブシーケンスの最大合計長を効率的に追跡できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 動的プログラミング | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の辞書を初期化する`dp`整数をマップします`x`ある長さのブロックで終わる最も長い美しいサブシーケンスの長さまで`x`。 
2. 各数値を反復処理します。`a[i]`シーケンスで。 各数値について、現在の値を確認します。`dp`予想される前のブロック長に対応する`a[i] - 1`。 そのようなブロックが存在する場合は、以下を含めることで拡張できます。`a[i]`。 それ以外の場合は、長さ 1 の新しいブロックを開始します。 
3.アップデート`dp[a[i]]`現在の値と、ここで終了するブロックの新しく計算された長さの間の最大値。 これにより、考えられるすべてのブロック長に対して常に最長のサブシーケンスが保持されるようになります。 
4. シーケンス全体を処理した後、次の最大値が得られます。`dp`最も長い美しいサブシーケンスの長さを表します。 
5. 必要な削除の最小数は次のとおりです。`n - max(dp.values())`。 

**機能する理由**: このアルゴリズムは、次の不変条件を維持します。`dp[x]`は常に、ある長さのブロックで終わる最長のシーケンスの長さです`x`。 各要素は既存のブロックを継続するか、新しいブロックを開始して、有効なサブシーケンスが失われないようにします。 削除は次のようにカウントされるため、`n - total_length_of_blocks`、解決策は最小限です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    dp = dict()
    for num in a:
        prev_len = dp.get(num - 1, 0)
        dp[num] = max(dp.get(num, 0), prev_len + 1)
    
    max_beautiful = max(dp.values(), default=0)
    print(n - max_beautiful)
```**説明**: シーケンス内の各要素を反復処理し、その要素で終わる有効なブロックの最長チェーンを計算します。`dp.get(num - 1, 0)`前のブロックが存在する場合はその長さを取得し、存在しない場合は 0 を取得します。`max(dp.get(num, 0), prev_len + 1)`サブシーケンスの長さが増加する場合にのみ拡張するようにします。 処理後、最も長く美しいサブシーケンスがシーケンスの長さから減算されて、答えが得られます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        dp = dict()
        for num in a:
            prev_len = dp.get(num - 1, 0)
            dp[num] = max(dp.get(num, 0), prev_len + 1)
        print(n - max(dp.values(), default=0))
    return out.getvalue().strip()
