 ## 解決策
 ## 問題の理解

 文字列から始めます`x`。 ワンオペレーションで置き換え可能`x`と`x + x`、現在の文字列がそれ自体に追加され、その長さが 2 倍になることを意味します。 

ターゲット文字列も与えられます`s`。 タスクは、次のようにするために必要な 2 倍演算の最小数を見つけることです。`s`の現在の値内のどこかに表示されます`x`連続した部分文字列として。 どれだけの操作を行ってもこれを実現できない場合は、出力する必要があります。`-1`。 

最も重要な制約は、`n · m ≤ 25`。 どちらの文字列も非常に小さいです。 何度か 2 倍にした後でも、開始時の長さが小さいため、文字列の長さは絶対的に非常にゆっくりと増加します。 これは、KMP やサフィックス構造などの高度な文字列アルゴリズムが必要ないことをすぐに示唆しています。 直接シミュレーションが可能です。 

難しいのは、失敗を宣言する前に何倍にする必要があるかを決定することです。 不用意に実装すると、実際には答えが不可能なときに、永遠に 2 倍になり続ける可能性があります。 

考慮する`x = "ab"`そして`s = "aaa"`。 2 倍になった文字列はすべて次の繰り返しになります。`"ab"`:```
ab
abab
abababab
...
```キャラクター`'a'`と出ますが3回連続`'a'`キャラクターは決してそうではありません。 ずっと続けても何も変わらないから正解は`-1`。 

もう 1 つの微妙なケースは、ターゲットが最初からすでに存在している場合です。 

入力：```
2 2
aa
aa
```出力：```
0
```チェックの前に少なくとも 1 回の 2 倍化を実行するソリューションは、誤って次の値を返します。`1`。 

3 番目のエッジ ケースは、ターゲットがコピー間の境界を越えるときに発生します。 

入力：```
5 5
eforc
force
```最初は`"force"`は表示されません。 1 回 2 倍にした後:```
eforceforc
```部分文字列は最初のコピーの終わり近くで始まり、2 番目のコピーまで続きます。 の単一コピー内のみをチェックするソリューション`x`見逃してしまうだろう。 

## アプローチ

 最も直接的なアイデアはシミュレーションです。 かどうかを確認してください`s`はすでにの部分文字列です`x`。 そうでない場合は2倍`x`、もう一度確認して続行します。 

すべての操作で 1 つの新しい文字列状態が生成され、操作数の増加順にそれらの状態を検査するため、このアプローチは正しいです。 初めて見つけたのは`s`、最小限の操作数が自動的に見つかりました。 

残る問題は、いつ止めるかだ。 

単純な実装は、文字列が巨大になるまで無期限に継続される可能性があります。 それは不必要です。 以来`s`長さがある`m`、現在の文字列の長さが少なくとも次の値に達すると、`m`、将来のあらゆる出来事`s`すでに存在しているか、追加の 2 倍化によって境界が作成されたために出現している必要があります。 

なぜ 1 回余分に 2 倍にするだけで十分なのでしょうか? 現在の文字列の長さが少なくとも`m`、任意の長さの部分文字列`m`おそらく 2 つの隣接するコピー間の交差点を除いて、現在の文字列の 1 つのコピー内に完全に収まります。 もう 1 回ダブリングを実行すると、そのようなすべてのクロス ポジションが作成されます。 もし`s`がまだ現れない場合、その後の倍加では根本的に新しいパターンを作成できません。 

なぜなら`n · m ≤ 25`、長さは小さいままです。 一般的に受け入れられている解決策は、長さが`m`、各操作の後にチェックし、さらに 1 回倍加した後に追加のチェックを 1 回実行します。

 正確な複雑さは非常に小さいため、`m ≤ 25`。 

## アルゴリズムのチュートリアル

 1.読む`x`そして`s`。 
2. もし`s`はすでにの部分文字列です`x`、 戻る`0`。 
3. カウンタの初期化`ops = 0`。 
4.長さは`x`の長さよりも小さいです`s`:

 1. 交換する`x`と`x + x`。 
2. インクリメント`ops`。 
3. もし`s`は現在、次の部分文字列です`x`、 戻る`ops`。 

最終的には長さに達するかそれを超える必要があります`m`, したがって、このループは数回しか実行されません。 
5. さらに 2 倍化を 1 回実行します。 

1. 交換する`x`と`x + x`。 
2. インクリメント`ops`。 
3. もし`s`の部分文字列です`x`、 戻る`ops`。 

この最終チェックでは、2 つのコピー間の境界を越える部分文字列が処理されます。 
6. 部分文字列がまだ表示されない場合は、戻ります。`-1`。 

### なぜ効果があるのか

 このアルゴリズムは、考えられるすべての操作回数の後に生成された文字列を昇順に検査するため、返される答えは自動的に最小になります。 

残る唯一の懸念は、さらに 2 倍になった後で停止するのが安全かどうかです。 現在の長さが少なくとも`m`、長さのすべての部分文字列`m`将来、二重化された文字列は、現在の文字列の 1 つのコピー内に完全に収まるか、隣接するコピー間の境界を 1 つだけ越えます。 次の倍加により、そのような境界位置がすべて作成されます。 もし`s`そのときは現れず、その後の倍加では同じ構造がより大きなスケールで繰り返されるだけで、新しい長さを導入することはできません。`m`部分文字列。 こうして戻ってくる`-1`は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n, m = map(int, input().split())
        x = input().strip()
        s = input().strip()

        if s in x:
            answers.append("0")
            continue

        ops = 0

        while len(x) < len(s):
            x += x
            ops += 1

            if s in x:
                answers.append(str(ops))
                break
        else:
            x += x
            ops += 1

            if s in x:
                answers.append(str(ops))
            else:
                answers.append("-1")

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```最初のチェックは、操作が必要ない場合を処理します。 

現在の文字列が少なくともターゲットと同じ長さになるまで、ループは 2 倍になり続けます。 最初に成功した状態が最小の答えを与えるため、2 倍になるたびにすぐに部分文字列をテストします。 

の`while ... else`ここの構造は便利です。 の`else`ブロックは、ループが正常に終了した場合にのみ実行されます。つまり、文字列を少なくとも長さまで拡張するときに応答が見つからなかった場合にのみ実行されます。`m`。 

最後の追加の倍増が重要な詳細です。 多くの誤送信は長さに達するとすぐに停止されます`m`、新しく作成された境界を越えてのみ現れる部分文字列が失われます。 

すべての文字列が非常に小さいため、オーバーフローの懸念はありません。 何度か倍増させた後でも、その長さは小さいままです。
