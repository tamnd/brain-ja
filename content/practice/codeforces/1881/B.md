 ## 解決策
 ## 問題の理解

 3 つの正の整数が与えられ、それぞれがスレッドの長さを表します。 1 回の操作で、単一のスレッドを選択し、それを整数の長さ (両方とも厳密に正) で、それらの合計が元の長さに等しい 2 つの小さなスレッドに分割します。 このような分割は、すべてのスレッドにわたって合計で最大 3 回まで許可されます。 一連の分割を実行した後、結果として得られるすべてのスレッドがまったく同じ長さになるようにします。 

主要な出力は実現可能性のチェックです。テスト ケースごとに、3 つ以下の分割を使用して最終的に同じ長さの部分のコレクションを作成できるかどうかを判断する必要があります。 

制約はテスト数の点で大きく、最大 10^4 ケースですが、各テスト ケースのサイズは一定です。 これにより、任意の分割構成をシミュレートしたり、状態を検索したりするアプローチは即座に排除されます。これは、パーティション全体で中程度に分岐する BFS でも爆発するためです。 各テストは一定時間またはほぼ一定時間内に回答する必要があります。 

微妙な点は個数が決まっていないこと。 操作ごとにスレッドレットの合計数が 1 つずつ増加するため、最大 3 回の操作の後では、合計で最大 6 個のスレッドレットが得られます。 最終状態のサイズに対するこの厳しい制限により、直接的な組み合わせ推論が可能になります。 

単純な思考を打ち破る傾向があるエッジ ケースには、(1, 1, 1000000000) など、1 つの値が他の値よりはるかに大きい状況や、(5, 5, 6) など、2 つの値がすでに等しいが 3 番目の値がわずかにずれている状況が含まれます。 これらは多くの場合、貪欲な「最大値を分割して均等化する」戦略を誘惑しますが、これらは厳密な操作制限とセグメント サイズの整数制約を無視します。 

## アプローチ

 強引なアイデアとしては、最大 3 つのカットを実行するすべての可能な方法をシミュレートすることです。 各カットでは現在のセグメントが選択され、それが 2 つの正の整数に分割されます。 長さ L のセグメントには L-1 個の可能な分割があるため、分岐係数はセグメントの長さに応じて増加します。 たった 3 つの操作であっても、これにより可能性の大きなツリーが作成され、多くの状態がさまざまなカット順序で繰り返されます。 構成の合計数は、10^4 のテスト ケースにわたって列挙できる数をはるかに超えています。 

重要な観察は、実際には中間の構成は気にしておらず、均一な最終長さが存在するかどうかだけを気にしているということです。 最終的な長さが x の場合、元のすべてのセグメントを長さ x の部分に分解する必要があります。 これにより、問題は各数値が等しい部分の合計として表現できるかどうかを確認することに変わりますが、合計で最大 3 つのカットしか導入できないという追加の制限があります。 

この制限は非常に厳しく、カットごとにピースの数が 1 つずつ増加するため、3 つのセグメントから開始して、最大 6 つのセグメントで終了できます。 したがって、最終的な構成のサイズは 3、4、5、または 6 になります。すべてのピースの長さが等しい必要があるため、合計 S は、{3,4,5,6} の k について S mod k = 0 を満たす必要があります。ここで、k は最終的なピースの数です。 有効な k ごとに、元の各セグメントをサイズ S/k の整数に分割できるかどうか、および必要なカットの総数が 3 を超えないかどうかを確認します。 

固定ターゲット長 x の場合、長さ a のセグメントは、a が x で割り切れる場合は (a/x − 1) に等しいカットに寄与しますが、それ以外の場合は不可能です。 3 つのセグメントすべてのこれを合計すると、必要な操作の合計数が得られます。 [3,6] に有効な x を生成し、最大 3 つのカットを必要とする実行可能な k が存在する場合、答えは YES です。

 ## アルゴリズムのチュートリアル

 可能な限りの最終的な数のピースをテストしていきます。

1. 3 つのねじの長さの合計 S を計算します。 これは、最終的なすべての等しいピース間で均等に分割する必要がある全長です。 
2. 3 から 6 までの最終ピース k の候補数ごとに、S が k で割り切れるかどうかを確認します。 そうでない場合、この k は等しいセグメントを生成できず、破棄されます。 
3. 有効な k ごとに、ターゲット ピースの長さ x = S / k を計算します。 これは、各最終ねじ山の可能な唯一の長さです。 
4. 元の各セグメント a について、a が x で割り切れるかどうかを確認します。 そうでなければ、小数部分に切断することができないため、この構成は不可能です。 
5. 割り切れる場合は、そのセグメント内で必要なカットの数を a / x − 1 として計算します。これは、a を m 個の等しいチャンクに分割するには正確に m − 1 個のカットが必要であるという事実から来ています。 
6. 3 つのセグメントすべてにわたるこれらのカット数を合計します。 合計が最大 3 であれば、この構成は実現可能であるため、すぐに YES を返すことができます。 
7. [3,6] の k が機能しない場合は、NO を返します。 

### なぜ効果があるのか

 すべての操作でセグメントの数が 1 つずつ増加するため、3 つのセグメントから開始すると、最大 6 つのセグメントを含む構成にのみ到達できます。 これにより、等しい部分の最終的な数が小さな一定範囲に制限されます。 最終的なセグメンテーション サイズが固定されている場合、元の各セグメント内のカットの構造が強制されます。等しい部分は一意のターゲット長を意味し、各セグメントが寄与するカットの数を個別に決定します。 セグメントは、共有される最終的な長さの制約を介する場合を除いて相互作用しないため、実現可能性のチェックは、独立したコストを合計し、グローバルな削減予算を検証することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(a, b, c):
    total = a + b + c

    for k in range(3, 7):
        if total % k != 0:
            continue
        x = total // k

        cuts = 0
        ok = True

        for v in (a, b, c):
            if v % x != 0:
                ok = False
                break
            cuts += v // x - 1

        if ok and cuts <= 3:
            return True

    return False

t = int(input())
for _ in range(t):
    a, b, c = map(int, input().split())
    print("YES" if possible(a, b, c) else "NO")
```この実装は、最終パーティション サイズ 3 から 6 のみが関連するという観察に直接従っています。 k にわたるループでは、考えられるすべての終了状態を列挙し、それぞれについて、最大 3 つのカットで構築できるかどうかを検証します。 

カットの計算では、セグメントを m 個の等しい部分に分割するには正確に m-1 回の操作が必要であるという恒等式が使用されます。 これにより、分割プロセスを明示的にシミュレートすることが回避されます。 ブール値フラグにより​​、割り切れない場合に無効な分解を早期に破棄できるようになります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        a, b, c = map(int, input().split())
        total = a + b + c
        for k in range(3, 7):
            if total % k != 0:
                continue
            x = total // k
            cuts = 0
            ok = True
            for v in (a, b, c):
                if v % x != 0:
                    ok = False
                    break
                cuts += v // x - 1
            if ok and cuts <= 3:
                return "YES"
        return "NO"

    t = int(input())
    return "\n".join(solve() for _ in range(t))

assert run("1\n6 3 3\n") == "YES"  # classic split case

 ## 特殊なケース

 (1, 1, 100) のようなケースでは、カットがグローバルに制限されているという制限が強調されます。 アルゴリズムは [3,6] 内のすべての k を試行しますが、これらの k の値から導出される有効な x については、大きなセグメントにより分割が多すぎるか、割り切れないため、すべての候補が失敗し、出力は NO になります。 

(6, 3, 3) の場合、正しい解決策には、分割する必要があるセグメントは 1 つだけであること、および分割により操作制限を超えることなく正確に正しい数の部分が生成されることを認識する必要があります。 このアルゴリズムは、シーケンスをシミュレートするのではなく、正確なセグメントごとのカット数を計算することでこれを捕捉します。 

(5, 5, 5) のようなすでに等しい入力の場合、x = 5 の k = 3 の場合はゼロ カットが生成され、制約が直ちに満たされ、演算を実行せずに YES が生成されます。
