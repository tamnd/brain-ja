 ## 解決策
 ## 問題の理解

 この問題により、古代のアルゴリズムによって生成された謎のシーケンスが得られます。 短い長さのシーケンスから開始する`m`、アルゴリズムは新しい数値を繰り返し挿入します`x_i + 1`選択した要素の後に`x_i`シーケンスの長さに達するまで`m+k`。 課題は、あらゆるシーケンスに対して逆方向に作業することです。`b`、 決定する`f(b)`、生成された可能性のある最小の開始シーケンスの長さ`b`この挿入プロセスを通じて。 計算できるようになると`f(b)`どのシーケンスでも、目標は合計することです`f`特定のシーケンスのすべてのサブセグメントにわたって`a`。 

入力は一連の整数です`a`複数のテスト ケースにわたる最大 300,000 の要素。 これにより、すべてのサブセグメントを明示的に反復する素朴なアプローチができなくなります。これは、O(n^2) 個のサブセグメントがあり、10^10 の演算に達する可能性があるためです。 合計を効率的に計算するには、シーケンスの構造を利用する必要があります。 

厳密に増加するシーケンスでは、微妙なエッジ ケースが発生します。 のために`[1,2,3,4]`、長さ 1 の開始シーケンスから任意のサブセグメントを生成できますが、次のようなシーケンス`[1,3,5,7]`できず、各サブセグメントの最小開始長はそれ自体の長さになります。 単純なアプローチでは、単調シーケンスが常に 1 に減少すると想定する可能性がありますが、ここでは当てはまりません。 同様に、プラトーまたは減少のあるシーケンスを正しく計算するには、慎重な処理が必要です。`f`。 

## アプローチ

 ブルートフォースアプローチは単純ですが、実行不可能です。 サブセグメントごとに`[a_l,...,a_r]`では、逆のプロセスをシミュレートできます。つまり、前の要素よりちょうど 1 大きい要素を、削除できなくなるまで繰り返し削除し、残りの長さを数えます。 これは正しく計算されます`f(b)`しかし、すべてのサブセグメントに対して O(n^2) 回の反復が必要であり、サブセグメントごとに O(n) 回の作業が必要になる可能性があるため、複雑さは O(n^3) となり、これでは遅すぎます。 

重要な洞察は次のとおりです`f(b)`増加する連続チェーンを分断する要素の位置にのみ依存します。 具体的には、元のシーケンスをシードと考えると、任意の要素が`b_i`前の値よりも 1 大きくない値は、開始シーケンスにその前の値を強制的に含めます。 このように、各要素について`a_i`で終わるサブセグメントの最小の長さ。`i`かどうかをチェックすることで、動的プログラミング方式で更新できます。`a_i - 1`直前に現れた。 各値の最後の位置のマップを維持することにより、新しい開始要素の数を効率的に計算できます。`a_i`で終わるすべてのサブセグメント`i`。 これにより、テスト ケースあたりの複雑さが O(n) に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最後の位置マップを使用した最適な DP | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 辞書を初期化する`last_position`各値が発生した最新のインデックスを追跡します。 これにより、値があるかどうかをすぐに確認できます`v-1`現在の要素の直前に存在します。 
2. 配列を初期化する`dp`どこ`dp[i]`の合計を保存します`f`インデックスで終わるすべてのサブセグメント`i`。 初期化する`dp[0]`単一要素のサブセグメントの最小長は常に 1 であるため、1 に設定されます。 
3. シーケンスを反復処理する`a`左から右へ。 要素ごとに`a[i]`、どうかを確認してください`a[i]-1`直前に現れた（を使用して）`last_position`）。 存在する場合、現在の要素は前のチェーンを拡張することができ、最後に出現した時点で終了する前のサブセグメントに基づいて、ここで終了するサブセグメントの最小開始長を増分します。`a[i]-1`。 さもないと、`a[i]`新しいチェーンを開始し、合計に 1 を加えます。 
4.アップデート`last_position[a[i]]`現在のインデックスに。 
5. シーケンスを処理した後、次のすべてのエントリを合計します。`dp`の合計を取得するには`f`すべてのサブセグメントにわたって。 

なぜ効果があるのか​​:`last_position`マップは値がどこにあるかを常に知っているという不変条件を維持します`v-1`が最後に発生するため、連続する番号のチェーンを効率的に拡張できます。 で終わるすべてのサブセグメント`i`チェーンを拡張するか (以前のサブセグメントを再利用)、新しい最小シードを開始して、次の定義を正確にキャプチャします。`f(b)`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        last_pos = dict()
        dp = [0] * n
        total = 0
        
        for i in range(n):
            if a[i]-1 in last_pos:
                dp[i] = i - last_pos[a[i]-1]
            else:
                dp[i] = i + 1
            last_pos[a[i]] = i
            total += dp[i]
        
        print(total)

solve()
```コードは辞書を使用します`last_pos`各数値の最新の出現を追跡します。 それぞれの要素について、`dp[i]`の合計に対する寄与度を計算します`f`で終わるサブセグメントから`i`。 以前の連続した値が存在する場合は、拡張できるサブセグメントのみをカウントします。 それ以外の場合は、で終わるすべてのサブセグメントをカウントします。`i`。 寄付金は次のように蓄積されます。`total`そしてテストケースごとに出力します。
