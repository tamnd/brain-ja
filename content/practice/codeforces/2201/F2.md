 ## 解決策
 ## 問題の理解

 まずは、$n \times n$完全に空のグリッドを作成し、いくつかのセルを徐々に黒く塗ります。 各ペイント操作の後で、現在の白黒パターンが 2 行 2 列を含む非常に特殊な禁止構成を回避しているかどうかを判断する必要があります。 

禁止されたパターンは、より構造的な方法で言い換えることができます。 2 つの異なる行を選択します$i < j$と 2 つの異なる列$k < l$。 見てください$2 \times 2$それらの交差によって形成される部分行列。 この条件は、値が「相互不一致」である、つまり左上が右下に等しく、右上が左下に等しく、最初の列の 2 つの値が異なるような部分行列を見つけてはいけないことを示しています。 言い換えれば、これら 4 つのセルの間で、対角線は一致するが行が一致せず、両方の色が各行と列で入れ替わって表示される有効な「X 字型」パターンを色が形成してはなりません。 

グリッドには黒と白しか含まれていないため、最初はすべて白が有効であることは自明です。 各クエリは単一のセルを白から黒に永久的に反転します。更新のたびに、禁止されたセルがないかどうかを判断する必要があります。$2 \times 2$構造がグリッドのどこにでも現れています。 

制約は極端で、全体で最大 200 万の操作が可能で、グリッド側でも最大 200 万の操作が可能です。 これにより、クエリごとに行や列を検査するものは即座に排除され、操作ごとに一定以上の処理またはほぼ一定の処理を実行するデータ構造であっても、慎重に制御する必要があります。 行または列のペアをチェックしようとしたり、近傍をスキャンしようとするソリューションは、桁違いに失敗します。 

微妙な問題は、この状態がグローバルであるにもかかわらず、見た目はローカルであるということです。 単純な実装では、新しく描画されたセルの影響を受ける行のすべてのペア、または列のすべてのペアをチェックしようとする可能性がありますが、単一のセルであっても、$O(n)$このようなペアは、時間の経過とともにそのアプローチを二次関数的にします。 

行方向または列方向のビットセットを維持し、オーバーラップを直接チェックしようとすると、別の障害モードが発生します。 禁止された構造は、セットの交差だけではなく、2 つの列にわたる 2 つの行間の相関に依存するため、単純なセットの交差数では不十分です。 

小さな失敗例を次に示します。 両方の対角線が存在する長方形を形成する黒いセルがあるとします。$$(i,k), (j,l), (i,l), (j,k)$$行の交差部分のみを追跡する単純なアプローチでは、行が$i$そして$j$2 つの列を共有し、集計に応じて何かを結論付けるのが遅すぎたり早すぎたりするため、このパターンが位置の共有だけでなく相互調整に関するものであるという事実が見落とされます。 

重要な難しさは、この条件が基本的に、行と列の間に誘発された二部構造が組み合わせの意味で「非単調」になるかどうかに関することです。 

## アプローチ

 ブルート フォース ソリューションでは、行のすべてのペアをスキャンし、列のすべてのペアで禁止されたパターンをチェックすることで、各クエリの後に妥当性を再計算します。 これは概念的には簡単です。$2 \times 2$サブマトリックスがルールに違反しているかどうかを確認します。 ただし、各クエリでチェックが必要になる可能性があるため、黒いセルのリストを維持しても役に立ちません。$O(n^2)$考えられる行と列の組み合わせ。 以上$2 \cdot 10^6$操作を行うと、これは完全に不可能になります。 

別の試みは、行のペアを修正することです$i, j$両方に黒いセルがある列を追跡します。 このような列が 2 つ存在する場合は、違反が疑われる可能性があります。 しかし、この条件は共有列の存在だけに関するものではないため、これではまだ不十分です。 それは、列を通じて同時に相互作用する行の「異なるペア」間の相互相関に依存します。 

重要な構造的洞察は、行間のペアパターンの一貫性の観点から条件を再解釈することです。 セルの観点から考えるのではなく、共有の黒い列を介して行が互いにどのように関係しているのかという観点から考えます。 

列を修正する$c$。 それぞれの黒マス$(r, c)$行間の関係を誘発します$r$および黒の列を持つ他のすべての行$c$。 2 つの行が 1 つの列を共有している場合、それらは「その列を介して接続されている」ことになります。 禁止された構成は、2 つの異なる列が同じ行ペア間で互換性のないペア関係を引き起こし、列による行ペアのサポート方法に競合サイクルが事実上発生する場合に現れます。 

これは、行のペアごとに、それらの行に現在接続されている列の数を追跡することを示唆しています。 違反は、誘導された構造に矛盾を強制するような方法で、行のペアが少なくとも 2 つの異なる列によって接続されている場合に発生します。 ただし、すべての行ペアを保存することは不可能です。 

したがって、視点を再度逆転させます。行ペアの代わりに、列ごとに相互作用を追跡します。 各列には、黒いセルが含まれる行のセットが維持されます。 重要な観察は、行のペアが少なくとも 2 つの異なる列に一緒に出現したときに違反が作成されるということです。 つまり、アクティブな列のセット上の交差部分のサイズが少なくとも 2 である 2 つの行が存在するかどうかを検出する必要があります。 

これにより、行のペアごとに、現在両方を含む列の数を示すカウンターを維持するという問題が軽減されます。 直接的なメンテナンスはまだ大きすぎますが、スパース性を利用しています。各列は時間の経過とともにその行セットのみが増加し、各更新は 1 つの列のみに影響します。 

黒マスを挿入する場合$(r, c)$、列内の以前にアクティブ化されたすべての行を反復処理します。$c$、各ペアのグローバルカウンターをインクリメントします$(r, x)$。 いずれかのペアがカウント 2 に達すると、行列が無効であることがすぐにわかります。 

これを効率的に保つために、すべての更新にわたる増分の合計数は、列内で形成されるペアの合計数によって制限されることが観察されます。$\sum \binom{s_c}{2}$、 どこ$s_c$列内の黒セルの数です$c$。 すべての操作を通じて、新しい黒セルは最大でも追加されるだけです$s_c$各セルは 1 回挿入されるため、全体の複雑さは管理可能です。 

カウントを保存するために、順序付けられた行ペアをキーとするハッシュ マップまたは辞書と、カウントが 2 に達したかどうかを示すグローバル ブール フラグを維持します。

 ## アルゴリズムのチュートリアル

 1. 各列から、その列に現在黒のセルが含まれている行のリストへのマッピングを維持します。 これにより、各更新をその列内でローカルに処理できるようになります。 
2. ハッシュマップを維持する`cnt[(r1, r2)]`現在両方の行に黒セルが含まれている列の数を保存する$r1$そして$r2$、 と$r1 < r2$。 これは、行の各ペアが蓄積した「共有サポート」の数をエンコードします。 
3. グローバルフラグを維持する`bad = False`。 黒いセルを追加しても禁止された構成を削除できないため、一度設定すると永続的に設定されたままになります。 
4. 各クエリについて$(r, c)$、列にすでに存在するすべての行を反復処理します。$c$。 そのような行ごとに$x$、ペアを形成します$(\min(r,x), \max(r,x))$そしてそのカウンターをインクリメントします`cnt`。 
5. いずれかのカウンタが 2 になったら、セットします。`bad = True`。 これは、2 つの異なる列が同じ行のペアをサポートするようになり、禁止された行の存在が保証されることを意味します。$2 \times 2$構造。 
6. 現在の答えを追加します。次の場合は「YES」`bad`は依然として False、それ以外の場合は「NO」です。 

これが機能する理由は、禁止された構造を作成する唯一の方法が、2 つの異なる列に同時に接続された 2 つの行を作成することであるためです。 黒のセルを挿入するたびに、その列に形成されたすべての新しい行ペアを明示的に登録します。 初めて任意のペアが異なる列に 2 回出現すると、交差を生成する構造が正確に得られます。$2 \times 2$矛盾しており、その瞬間からその状態は元に戻ることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, q = map(int, input().split())

        col_rows = {}
        pair_cnt = {}
        bad = False

        for _ in range(q):
            r, c = map(int, input().split())

            if c not in col_rows:
                col_rows[c] = []

            lst = col_rows[c]

            # if already bad, just consume input
            if not bad:
                for x in lst:
                    a, b = (r, x) if r < x else (x, r)
                    key = (a, b)
                    pair_cnt[key] = pair_cnt.get(key, 0) + 1
                    if pair_cnt[key] == 2:
                        bad = True

            lst.append(r)

            out.append("NO" if bad else "YES")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```### コードの説明

 このソリューションは、列ごとに、黒く塗られた行のリストを保持します。 新しい黒いセルはそれぞれ、その列内で以前に確認されたセルとのみ相互作用します。これは、新しい行ペアの相互作用が形成される唯一の場所です。 

辞書`pair_cnt`行の各ペア間に接続を作成した個別の列の数を格納します。 いずれかのペアがカウント 2 に達した瞬間に、禁止された構造が検出され、状態が無効として永久にマークされます。 

行ペアには方向性がないため、重複を避けるためにペアをソートされた順序で保存します。 一度`bad`true の場合、入力は引き続き処理されますが、ランタイムの安定性を維持するために不要な更新はスキップされます。

 ## 特殊なケース

 重大なエッジ ケースは、単一の列で多数の更新が発生する場合です。 この場合、新しい挿入はすべてその列の前のすべての行と相互作用するため、アルゴリズムはカウントを誤ってリセットしたり複製したりしないようにする必要があります。 すべてのインタラクションはその列のリストに限定され、各ペアの増分は順序に依存しないため、この構造はこれを自然に処理します。 

もう 1 つの微妙なケースは、2 つの特定の列間の相互作用により違反が遅れて現れる場合です。 このアルゴリズムは、隣接関係ではなくグローバル ペアのカウントに依存するため、これを捉えます。ペアが 2 つの異なる列に出現すると、入力シーケンス内の間隔に関係なく、条件が検出されます。 

最後に、多くの列にわたって行が繰り返されると、密なペアの相互作用が作成される可能性があります。 辞書ベースのカウントにより、実際のペアの出現のみが問題となることが保証され、ペアがしきい値 2 に達すると、計算は正確さに影響を与えなくなり、効率が維持されます。
