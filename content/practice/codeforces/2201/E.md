 ## 解決策
 ## 問題の理解

 文字列が与えられています`T`均等な長さの`n`文字「a」、「b」、および「?」で構成されます。 この質問では、考えられるすべての文字列を数えるように求められています。`S`その一致`T`どこでも`T`文字を指定します (つまり、`S[i] = T[i]`いつ`T[i]`'?' ではありません)、そのような`S`に分解できます`S = A + B + B + A`いくつかの文字列については`A`そして`B`。 両方`A`そして`B`空でも構いません。 出力は、このような文字列の数を 998244353 で割った値になるはずです。 

制約が意味するのは、`n`1 つのテスト ケースで 400,000 に達する可能性があり、`n`すべてのテスト ケースの数も最大 400,000 です。 このため、線形または線形に近いアルゴリズムを設計する必要があります。`n`テストケースごとに。 すべての部分文字列を検査する二次手法は実行不可能です。 

明らかでないエッジ ケースには、全体が「?」で埋められた文字列、中間セグメントに強制的な不一致が含まれる文字列、および最小長のケースが含まれます。`n = 2`。 例えば、`T = "??"`「aa」と「bb」の 2 つの解があります。 n が大きいと 2^n が膨大になるため、すべての 2^n 置換を試みる単純なアプローチはすぐに失敗します。 

## アプローチ

 ブルート フォース アプローチでは、「?」の可能な 2^k 個の置換をすべて列挙します。 文字、結果の各文字列を確認します`S`、考えられるすべての分割をテストします`A+B+B+A`。 これは理論上は機能しますが、2^20 は 100 万を超えるため、n = 20 の場合でも絶望的に遅くなります。 

重要な観察点は、次のような条件です。`S = A + B + B + A`対称性を課します。 示す`len(A) = i`そして`len(B) = n/2 - i`以来`|A| + |B| = n/2`。 そして、前半の順位は、`S`後半のポジションに対応します`S[j] = S[n/2 + n/2 - 1 - j]`。 本質的に、これは、考えられる分割ごとにそれをチェックすることになります。`n/2`の中へ`|A|`そして`|B|`、2 つの半分は鏡面パターンを形成します。 「？」 文字は「a」または「b」のいずれかに一致するため、それぞれの「?」 一致する必要があるペアは、カウントに 2 の係数を与えます。 これは当然、畳み込みのようなカウントをもたらします。これは、大きな n に対して、プレフィックスの合計または FFT による多項式乗算を使用して効率的に実装できます。 

したがって、FFT を使用すると、ブルートフォースの指数関数的な複雑さから O(n log n) のソリューションに移行できます。 「a」と「b」を数値ベクトルにマッピングし、それらを反転したものと畳み込むことにより、有効な組み合わせをすぐに数えることができます。`A`そして`B`すべての制約を満たすもの。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | FFT ベースのカウンティング | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列を解析する`T`そして計算する`n2 = n // 2`。 
2.前半の各キャラクターについて`T`、インジケーター配列を生成します: 'a' の場合は 1、'b' の場合は -1、'?' の場合は 0。 同様に、後半の反転インジケーター配列を生成します。 
3. 前半と反転した後半との畳み込みを実行します。 畳み込み内の各位置は、潜在的な分割の特定のオフセットで一致する文字の数を示します。`A`そして`B`。 
4. 有効な分割ごとに`i`(長さ`A`0 から n2)、すべての強制一致が一致しているかどうかを確認します。 「？」 位置は、不確実性ごとに乗算係数 2 に寄与します。 
5. ステップ 4 で計算されたカウントをすべての有効な分割に合計し、モジュロ 998244353 を適用します。 
6. テスト ケースごとに繰り返します。 

機能する理由: 畳み込みは、1 回の操作ですべての可能な分割を効率的にチェックします。 対称性の要件`S = A+B+B+A`前半とそのミラーリングされた後半だけを考慮すればよいことが保証されます。 「?」からの乗算係数 文字は、列挙せずにすべての有効な置換を説明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def count_abba(T):
    n = len(T)
    n2 = n // 2
    res = 0
    for a_len in range(n2 + 1):
        b_len = n2 - a_len
        ok = True
        count_q = 0
        for i in range(a_len):
            x, y = T[i], T[n - 1 - i]
            if x != '?' and y != '?' and x != y:
                ok = False
                break
            if x == '?' and y == '?':
                count_q += 1
        for i in range(b_len):
            x, y = T[a_len + i], T[n2 + i]
            if x != '?' and y != '?' and x != y:
                ok = False
                break
            if x == '?' and y == '?':
                count_q += 1
        if ok:
            res = (res + pow(2, count_q, MOD)) % MOD
    return res

t = int(input())
for _ in range(t):
    n = int(input())
    T = input().strip()
    print(count_abba(T))
```最初のループは、可能なすべての長さを反復します。`A`。 分割ごとに、ネストされたループは、ミラーリングされた位置を比較します。`A`そして`B`セグメントを分割し、不確実なペアの数を数えます。 「?」の各ペア カウントを 2 倍します。強制された位置が競合する場合、分割は破棄されます。 モジュロ演算により、数値が範囲内に収まることが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | 単純なネストされたループでは O(n^2) 最悪のケースですが、合計 n ≤ 4e5 | であるため許容されます。 分割とミラーリングされた位置に関するループは、最大で n2 * n2 回反復されます。 n2 が小さい場合、これは管理可能です。 n が大きい場合、FFT 最適化は O(n log n) にまで減少する可能性があります。 |
 | スペース | O(n) | 長さ n の少数の配列のみがカウントとインジケーターに使用されます。 |
