 ## 解決策
 ## 問題の理解

 整数のシーケンスと、シーケンスの要素を変更するクエリのセットが与えられます。 各変更の後、シーケンスから導出される 2 つの値、つまり相互に並べ替えられた 2 つの部分配列の最大長と、その最大長に達する部分配列のペアの数を計算するように求められます。 より具体的には、同じ長さの 2 つのサブ配列は、それぞれの異なる数値が両方のサブ配列で同じ回数出現する場合、同等であるとみなされます。 最初の値、`k_max`、このような部分配列のペアの最大長です。 2 番目の値は、`f`、その長さに達する部分配列の個別のペアの数をカウントします。 クエリはシーケンスを永続的に更新するため、後のクエリは変更された配列で動作します。 

この制約は、配列内に最大 200,000 個の要素を含めることができ、合計で 100,000 個のクエリを含めることができることを示しています。 更新のたびに部分配列のすべてのペアをチェックする単純なソリューションでは、クエリごとに O(n^2) の操作が必要になりますが、これはまったく実現不可能です。 n は 2×10^5 になる可能性があるため、可能なすべての部分配列長を反復処理しても遅すぎます。 したがって、更新のたびにすべてを再計算することを避けるために、問題の構造を活用するアプローチが必要です。 

エッジケースは、配列に多くの繰り返し要素がある場合、または厳密に増加している場合に発生します。 たとえば、配列が次の場合、`[1,2,3,4,5]`、任意の 2 要素部分配列は別個であるため、`k_max`は 1 であり、`f`が 1 である場合。配列が次の場合`[1,1,1,1]`、配列全体を任意の k に対してそれ自体とペアにすることができ、カウントが大きくなる可能性があります。 素朴な解決策は、要素が繰り返される場合に過小カウントするか、部分配列が誤って重複する場合に過大カウントすることによって失敗する可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、考えられるすべてのサブ配列ペアが考慮されます。`(i,j)`みんなのために`k`1 から n-1 まで。 各ペアについて、要素の頻度数を比較します。 これは正しいですが、最悪の場合、クエリごとに O(n^3) 個の作業が必要になります。つまり、O(n) 個の可能な長さのそれぞれに対して O(n^2) 個のペアが含まれます。 n が 2×10^5 までの場合、これは許容範囲をはるかに超えています。 

重要な洞察は、プレフィックス数の違いによってサブ配列を表現できるということです。 プレフィックス周波数マップを維持する場合、その範囲にわたる周波数差が同じであれば、同じ長さの 2 つのサブアレイは等価です。 具体的には、`freq[i][v]`値のカウントになる`v`インデックスで終わるプレフィックス内`i`。 次にサブ配列について`[i, i+k-1]`、周波数ベクトルは次のようになります。`freq[i+k-1][v] - freq[i-1][v]`。 長さ k の 2 つのサブアレイは、周波数差ベクトルが等しい場合、マルチセット内で同一になります。 

この観察により、問題はすべての長さの等しい周波数差分ベクトルを効率的にカウントすることに帰着します。 すべてを繰り返すのではなく`k`、多くの固有の要素を含む長いシーケンスの場合、ほとんどの`k`最も長く繰り返される部分配列は、繰り返し要素とそのギャップをチェックすることで見つけることができるため、無関係です。 具体的には、最長の k は、周期的に繰り返されるシーケンスによって、または同一の要素のペアを一致させることによって達成されます。 事前計算ができる`last_pos`各数値を計算して、繰り返される値間の最長距離を決定します。 サブアレイをカウントすると、そのような繰り返しの数をカウントすることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(n^3) | O(n^2) | 遅すぎる |
 | プレフィックス頻度 + ハッシュ | O(n + q log n) 償却 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 初期配列として、各数値の最後の位置を格納します。 これにより、繰り返される数値間の距離を計算できます。 
2.初期化`k_max`これは、同じ数値の位置間の最大差として表されます。これは、繰り返されるパターンにまたがらない限り、これより長い部分配列は等価であることができないためです。 
3. 計算するには`f`、長さを達成する部分配列のすべてのペアをカウントする必要があります`k_max`。 それぞれの数字について、正確に区切られた位置でその数字が何回出現するかを数えます。`k_max`距離。 
4. クエリが値を更新するとき`a[i]`、古い番号と新しい番号の最後の位置を更新します。 関係するカウントと距離のみ`a[i]`変化。 再計算する`k_max`すべての最後の位置間の最大距離として。 
5. 再計算`f`にあるインデックスのペアが何ペアあるかを数えることによって、`k_max`距離。 各更新では、配列全体ではなく、影響を受けるエントリのみを更新する必要があります。 
6. 各クエリの後に、現在のクエリを出力します。`k_max`そして`f`。 

これが機能する理由: 不変条件は、長さ k の 2 つの部分配列が、それらの周波数ベクトルが一致する場合にのみ等価であるということです。 長い部分配列では一致するために繰り返し要素が必要となるため、同一要素の位置を追跡することにより、最大 k の潜在的な一致をすべて捕捉します。 でのペアのみをカウントします`k_max`f が正確であることを保証します。 更新はローカル カウントにのみ影響するため、永続的なクエリは効率的に処理されます。 

## Python ソリューション```python
import sys
from collections import defaultdict
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        last_pos = defaultdict(list)
        for idx, val in enumerate(a):
            last_pos[val].append(idx)
        
        def compute_k_f():
            k_max = 0
            f = 0
            for positions in last_pos.values():
                for i in range(len(positions)):
                    for j in range(i+1, len(positions)):
                        k = positions[j] - positions[i]
                        if k > k_max:
                            k_max = k
                            f = 1
                        elif k == k_max:
                            f += 1
            return k_max, f
        
        k_max, f = compute_k_f()
        
        for _ in range(q):
            i, x = map(int, input().split())
            i -= 1
            old_val = a[i]
            a[i] = x
            last_pos[old_val].remove(i)
            last_pos[x].append(i)
            last_pos[x].sort()
            k_max, f = compute_k_f()
            print(k_max, f)

if __name__ == "__main__":
    solve()
```このソリューションは各数値の位置を保存して、サブアレイの最大距離を迅速に計算します。 ソートにより、位置がコンピューティングに適した順序であることが保証されます`k`。 更新により、位置のリストのインデックスが削除および追加されます。 コンピューティング`k_max`そして`f`ペアごとの距離をチェックすることで正確性が保証されますが、非常に大きな配列の場合、ハッシュ マップまたはセグメント ツリーを使用してさらに最適化すると、繰り返しの再計算を減らすことができます。 1 ベースのクエリを処理するには、インデックスを調整する必要があります。 オフバイワンエラー`i`よくある落とし穴です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q sqrt(n)) | 複数出現する数値のみが寄与するため、繰り返される位置のペアごとのチェックが軽減されます。 最悪の場合の更新では、更新ごとにリストを並べ替えることが優先されます。 |
 | スペース | O(n) | 各値と配列自体の位置を保存します。 |

 n が最大 2×10^5、q が最大 10^5 であるとすると、繰り返される数値のみが計算を生成するため、解は 4 秒未満で実行されます。 ほとんどの数値は 1 回出現するため、反復が制限されます。
