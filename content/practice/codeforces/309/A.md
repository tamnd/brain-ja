 ## 解決策
 ## 問題の理解

 円形トラック上のランナー間の予想される衝突数を計算するように求められました。 各ランナーは、長さのトラックに沿った異なる位置からスタートします。`l`そして、同じ確率で時計回りまたは反時計回りのいずれかを選択します。 すべてのランナーは、単位時間あたり 1 メートルという同じ速度で正確に走ります。`t`時間単位。 2 人のランナーが同じ地点で出会った場合、それは衝突としてカウントされます。 2 人のランナーが複数の瞬間に出会った場合、複数回衝突する可能性があります。 

入力により得られるものは、`n`、ランナーの数、`l`トラックの長さ、`t`実行時間と配列`n`トラックに沿って開始位置を並べ替えます。 出力は 1 つの実数、つまり、実行後のすべてのランナー間で予想される衝突の合計数です。`t`最大 10^-6 の精度の時間単位。 

と`n`最大 10^6 および`t`そして`l`10^9 までは、時間単位ごとの位置の総当りシミュレーションは実行不可能です。 時間単位ごとにすべてのペアをシミュレートすると、最大 10^15 の操作が必要になり、これは 2 秒の時間制限をはるかに超えます。 したがって、時間ステップごとにシミュレーションすることなく、均一な速度と対称性を利用して、予想される衝突を導き出す必要があります。 

エッジ ケースには、ランナーが 1 つしかない (衝突がない)、ランナーが互いに密集して同じペアで複数の衝突が発生する可能性がある、およびトラックの長さが他のものと比べて非常に長いなどが含まれます。`t`、これにより、ランナーが複数いるにもかかわらず衝突が起こらない可能性があります。 

## アプローチ

 単純なアプローチでは、すべてのランナーのペアを反復処理し、時間単位ごとに位置をシミュレートし、衝突をカウントします。 これが機能するのは、2 人のランナーが同じ位置を占めているときと、小さな距離で衝突が発生するためです。`n`そして`t`、カウントが正しく蓄積されます。 ただし、`n`最大 10^6 および`t`最大 10^9、繰り返し`t`ステップ数は不可能であり、最悪の場合の演算回数は O(n^2 * t) となり、これは受け入れられません。 

重要な洞察は、対称性と均一な速度を考慮することです。 各ペアのランナーが反対方向に走る確率は 50% です。 衝突は、それらが互いに向かって移動する場合にのみ発生します。 時間単位ごとにシミュレーションする代わりに、2 人のランナー間の距離を計算し、逆方向に走った場合に何回遭遇するかを判断できます。 円形のトラックでは、これは、反対方向に移動した距離の合計がトラックの長さに達する回数に相当します。 各方向の選択は独立しているため、各ペアの予想衝突数に 0.5 を掛けて、すべてのペアを合計します。 

これにより、ランナーの位置を分類し、その範囲内にスタート地点がいくつあるかを数えるという問題が軽減されます。`2 * t`各ランナーの数メートル先の円を囲みます。 これは、ソートされた配列に対する 2 ポインター手法を使用して効率的に実行でき、循環の性質を処理できるように概念的に拡張されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * t) | O(n) | 遅すぎる |
 | ツーポイントの予想 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ランナーの開始位置を並べ替えます。入力により、ランナーの開始位置がすでに並べ替えられていることが保証されます。 ソートにより、2 ポインター スイープが正しく動作することが保証されます。 
2. 追加してトラック位置を概念的に複製します。`l`それぞれの元の位置に移動し、「ラップアラウンド」配列を形成します。 これにより、ループ内でモジュラー演算を行わずに円周距離を簡単に処理できるようになります。 
3. 2 つのポインターを初期化します。`i`オリジナルを反復処理します`n`ランナーと、`j`範囲内で到達可能な最も遠いランナーを追跡します`2 * t`ランナーから時計回りの距離`i`。 
4. 各ランナーについて`i`、 前進`j`ランナーが定位置に着くまで`j`以上です`2 * t`先に。 間のランナーの数`i+1`そして`j-1`衝突する可能性のあるすべてのランナーを表します`i`時間内に`t`それらが反対方向に動いた場合。 
5. これらのカウントをすべて合計し、0.25 を掛けます。 係数 0.25 は、2 つの独立した 50% 確率から得られます。`i`1 つは時計回りに動き、もう 1 つは反時計回りに動きます。 
6. 結果の合計を十分な浮動小数点精度で出力します。 

機能する理由: 不変条件は、各ランナーについて、ツーポインター ウィンドウが有効衝突距離内にあるすべてのランナーを正確にカウントすることです。 0.25 を掛けると、カウントが独立した方向の選択で予想される衝突数に変換されます。 各ペアはランナーごとに 1 回カウントされるため、この方法では、予想される衝突の合計が欠落したり二重にカウントされたりすることなく正確に計算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, l, t = map(int, input().split())
a = list(map(int, input().split()))

# Duplicate array to handle circular wrap
b = a + [x + l for x in a]

ans = 0
j = 0
for i in range(n):
    while j < len(b) and b[j] - a[i] <= 2 * t:
        j += 1
    ans += j - i - 1  # runners in range after i

# Each collision has probability 1/4
print("{0:.10f}".format(ans * 0.25))
```まず入力を効率的に読み取り、解析します。 円周距離を考慮して配列を拡張し、2 ポインタ アプローチを使用してその範囲内のすべてのペアを見つけます。`2 * t`距離。 引き算`i + 1`二重カウントを避けるために、現在のランナーより前のランナーのみをカウントします。 0.25 を掛けると、各ランナーが反対方向に移動する確率が 50% になります。 結果は、精度要件を満たすために小数点以下 10 桁にフォーマットされます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, l, t = map(int, input().split())
    a = list(map(int, input().split()))
    b = a + [x + l for x in a]
    ans = 0
    j = 0
    for i in range(n):
        while j < len(b) and b[j] - a[i] <= 2 * t:
            j += 1
        ans += j - i - 1
    return "{0:.10f}".format(ans * 0.25)

# Provided samples
assert run("2 5 1\n0 2\n") == "0.2500000000", "sample 1"
