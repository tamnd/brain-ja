 ## 解決策
 ## 問題の理解

 メモリ レイアウトは、いくつかの連続する空きセグメントに分割されており、独立した空間ブロックと考えることができます。 各ブロックは固定長であり、このメモリに配置したい配列のコレクションもあります。 各配列は、指定された長さのメモリの連続セグメントを消費し、単一のブロック内に完全に収まる必要があります。 

タスクは、正常に保存される配列の数を最大化するために、どの配列を配置するか、およびそれらをどこに配置するかを選択することです。 各ブロックは、重複せず、その容量内に収まる限り、複数の配列をホストできますが、配列をブロック間で分割することはできず、ブロックはマージできないという意味で独立しています。 

入力の構造が重要です。2 つのマルチセット、ブロック容量、配列サイズを一致させています。目標は、各ブロック内の間隔パッキング制約の下で成功した代入の数を最大化することです。 

制約は大きく、最大 10^6 ブロックと 10^6 配列があります。 配置をシミュレートしたり、ブロックごとまたは配列ごとに組み合わせを試行したりするソリューションは、非常に遅すぎます。 実行可能な唯一の解決策は、ソートと貪欲な処理を使用した場合、およそ O(n log n) または O(n) です。 これにより、すべてのサブセットに対する動的プログラミングやブロックごとの組み合わせパッキングが即座に排除されます。 

貪欲なマッチングが間違った順序で行われると、微妙なエッジケースが発生します。 たとえば、残ったスペースを調整せずに大きな配列を最初に大きなブロックに配置しようとすると、断片化の機会が無駄になる可能性があります。 配列の全体的な最適な順序を考慮せずに、ブロックを独立して処理し、各ブロックを貪欲にパックすると、別の失敗ケースが発生します。 

## アプローチ

 ブルートフォース解釈では、ブロックへの配列のすべての割り当てを試し、実現可能性をチェックします。 「各配列について、あるブロックに当てはめてみよう」と単純化したとしても、これは O(nm) となり、両方とも 10^6 に達すると制限をはるかに超えます。 

ブロックと配列をソートし、配列ごとにブロックをスキャンして適合するものを見つけることで、より構造化されたブルート フォースが向上します。 これにより定数因子は減少しますが、それでも二次的な動作に退化します。 

重要な点は、各配列にはブロック内の連続したセグメントのみが必要であるため、ブロック内で使用される配列タイプを固定すれば、サイズ A のブロックはサイズ 2b の最大で Floor(A / (2b)) の配列を収容できるということです。 ただし、ブロック内に異なるサイズが混在していると、直接カウントすることが困難になります。 

重要な洞察は、小さな配列をその場所に割り当てることができる場合、大きな配列をブロックに代入してもメリットが得られないということです。これは、小さな配列の方が柔軟性が高く、大きな配列用に大きなブロックが保持されるためです。 これは、グローバルな貪欲な戦略につながります。つまり、配列とブロックの両方をソートし、常に最小の配列を最初にそれらを収容できる最小のブロックに一致させようとするか、実現可能性を維持しながら最も制約された側から同等の処理を試みます。 

これを強制する標準的な方法は、ブロック サイズと配列サイズをソートし、ポインターによる貪欲なマッチングを使用し、残りの最小の配列を、それを保持できる最小の利用可能なブロックに常に適合させようとすることです。 ブロックが小さすぎる場合はスキップされます。 十分に大きい場合は、それを 1 回使用して次に進みます。 

これにより、問題はソートされた配列とブロックに対する線形スキャンに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 最適な貪欲なマッチング | O(n log n + m log m) | O(1)-O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各配列要件を実際のメモリ需要 (2*b[i]) に変換します。 これにより、両方の入力が同等のセグメント長に正規化されます。 
2. ブロック サイズを非降順で並べ替えます。 ソートにより、常に最小の利用可能な容量が最初に考慮されるため、小さなブロックで十分な場合に小さな要件で大きなブロックを無駄にすることがなくなります。 
3. 配列サイズを降順でない順に並べ替えます。 これは、最も制限の厳しい (最小の) 配列を最初に割り当てるという考えと一致しており、後でより大きな配列に対する柔軟性を最大化します。 
4. 2 つのポインターを初期化します。1 つはブロック用、もう 1 つは配列用で、どちらもソートされたリストの先頭から開始します。 
5. 両方のポインタが有効である間、繰り返します。 各ステップで、現在の最小の未割り当て配列と現在の最小の利用可能なブロックを比較します。 
6. 現在のブロックが小さすぎて配列に収まらない場合は、このブロックを破棄して、次に大きいブロックに移動します。 このブロックはソートにより残りの配列に使用できないため、これは安全です。 
7. ブロックが配列に適合する場合は、配列をこのブロックに割り当て、配置された配列の数をインクリメントし、両方のポインターを前方に移動します。 これにより、この単純化されたマッチング モデルで各ブロックが最大 1 回使用されることが保証されます。これは、最適性を損なうことなく、現在の最小配列に適合できるブロックを使用できるため、有効です。 

### なぜ効果があるのか

 正確さは、ソートによって引き起こされる単調な実現可能性構造に依存します。 配列とブロックが順序付けされると、実現可能性がしきい値条件になります。ブロックが特定の配列に適合しない場合、それより大きな配列にも適合することはできません。 これにより、ブロックをスキップしても常に安全になります。 同様に、利用可能な最小の配列を実行可能な最小のブロックに割り当てると、大きなブロックが不必要に消費されることがなくなり、将来のより大きな配列の容量が確保されます。 この貪欲な構造により、行われるすべての割り当てが局所的に最適であることが保証され、合計数を増やす可能性のある将来の実行可能な割り当てがブロックされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

a.sort()
b = sorted(x * 2 for x in b)

i = j = 0
ans = 0

while i < n and j < m:
    if b[j] >= a[i]:
        ans += 1
        i += 1
        j += 1
    else:
        j += 1

print(ans)
```この解決策は、両方のシーケンスを読み取り、配列要件を実際のメモリ長に変換することから始まります。 両方のリストをソートすることは、2 ポインター スイープに必要な単調な構造を作成するため不可欠です。 

ポインタ`i`次に配置したい配列を追跡し、`j`次に使用するブロックを追跡します。 現在のブロックが小さすぎる場合、現在のサイズ以上の残りの配列を提供できないため、そのブロックは破棄されます。 適合する場合、割り当てをコミットし、両方のポインターを進めて、ブロックも配列も再利用されないようにします。 

よくある間違いは、不等式を逆転させたり、間違った方向に繰り返したりすることです。 正しい比較は常に、ブロックが配列を収容できるかどうかであり、その逆ではありません。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
5 3
8 4 3 2 2
3 2 2
```変換後も配列サイズはそのまま残ります`[8, 4, 4]`ブロックサイズは`[2, 4, 8, 2, 3]`、並べ替える`[2, 2, 3, 4, 8]`。 

| 私 | j | 配列 | ブロック | アクション | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 8 | 2 | ブロックが小さすぎます | 0 |
 | 0 | 1 | 8 | 2 | ブロックが小さすぎます | 0 |
 | 0 | 2 | 8 | 3 | ブロックが小さすぎます | 0 |
 | 0 | 3 | 8 | 4 | ブロックが小さすぎます | 0 |
 | 0 | 4 | 8 | 8 | 割り当てる | 1 |
 | 1 | 5 | 4 | - | 停止 | 1 |

 次に 2 番目の例を考えてみましょう。```
4 5
10 5 4 2
1 2 2 2 6
```並べ替えられた配列:`[2, 4, 5, 10]`、ブロックは並べ替えられます:`[2, 2, 2, 6, 20]`。 

| 私 | j | 配列 | ブロック | アクション | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 2 | 2 | 割り当てる | 1 |
 | 1 | 1 | 4 | 2 | ブロックをスキップ | 1 |
 | 1 | 2 | 4 | 2 | ブロックをスキップ | 1 |
 | 1 | 3 | 4 | 6 | 割り当てる | 2 |
 | 2 | 4 | 5 | 20 | 割り当てる | 3 |
 | 3 | 5 | - | - | 停止 | 3 |

 これらのトレースは、最適性を損なうことなく、使用できない小さなブロックがスキップされながら、小さな配列がどのように早期にマッチングされるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + m log m) | ソートが優先され、その後に 1 回のリニア スキャンが続きます。 
| スペース | O(1) おまけ | 入力ストレージを超えるのはポインターとカウンターのみ |

 Python では効率的な入力とその後の線形スキャンを使用して 10^6 整数のソートが可能であるため、複雑さは 10^6 要素の制限内に十分収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    a.sort()
    b = sorted(x * 2 for x in b)

    i = j = 0
    ans = 0

    while i < n and j < m:
        if b[j] >= a[i]:
            ans += 1
            i += 1
            j += 1
        else:
            j += 1

    return str(ans)

# provided sample
assert run("5 3\n8 4 3 2 2\n3 2 2\n") == "2"

# minimum case
assert run("1 1\n2\n1\n") == "1"

# no fit case
assert run("2 2\n10 10\n1 1\n") == "0"

# exact matching case
assert run("3 3\n2 4 6\n1 2 3\n") == "3"

# large skewed case
assert run("4 2\n100 50 25 10\n1 20\n") == "2"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 小さいフィット | 1 | 最小限の割り当ての正確さ |
 | フィットしないケース | 0 | 正しい拒否処理 |
 | 完全一致 | 3 | 1 対 1 の貪欲なマッチング |
 | 歪んだサイズ | 2 | 大小のアンバランスへの対応 |

 ## 特殊なケース

 主なエッジ ケースは、大きな配列に必要な大きなブロックの前に、小さなブロックが多数出現する場合です。 次のような入力の場合:```
3 2
100 1 1
50 50
```並べ替えるとブロックが生成される`[1, 1, 100]`と配列`[50, 50]`。 再利用を許可していた場合、アルゴリズムは 2 つの小さなブロックをスキップし、両方の配列を大きなブロックに誤って割り当てますが、各ブロックは使い捨てであるため、50 が 1 つだけ適合するため、答えは 1 になります。貪欲ポインタにより、容量を誤って再利用することがなくなります。 

もう 1 つのエッジ ケースは、配列が最小の少数を除いてすべてのブロックよりも小さい場合です。 のために：```
4 3
8 7 6 5
1 1 1
```このアルゴリズムは、3 つの最小の配列を 3 つの最小の実行可能なブロックに即座に割り当てます。これにより、小さな配列の早期消費が常に安全であり、より大きな配列が存在しないため、より大きな割り当てがブロックされないことが確認されます。
