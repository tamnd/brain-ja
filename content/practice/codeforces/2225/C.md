 ## 解決策
 ## 問題の理解

 2 行のグリッドが与えられ、$n$列があるため、$2n$セルの合計。 各セルは赤または黒に色付けされます。 目標は、できるだけ少ないセルを再ペイントして、再ペイント後にすべてのセルをペアにすることができるようにすることです。$2n$細胞を正確に$n$隣接するペア。ここで、隣接とは辺を共有することを意味し、各ペアは同じ色の 2 つのセルで構成されなければなりません。 

ペアリングは事前に固定されていません。 すべてのペアに 2 つの同じ色のセルが含まれている限り、水平方向または垂直方向の近傍のみを使用して、有効な完全一致を選択することができます。 タスクは、そのような有効な一致が少なくとも 1 つ存在するようにするには、いくつのセルを再描画する必要があるかを決定することです。 

の構造$2 \times n$グリッドは非常に特殊な隣接グラフを強制します。各セルには最大 3 つの隣接セルがあり、有効なペアはすべての頂点をカバーする互いに素なエッジの選択に対応します。 各頂点は正確に 1 つのペアに属している必要があるため、一致するすべてのエッジが同じ色を接続し、再描画操作を最小限に抑える完全な一致を許容するグリッドにグリッドを変換できるかどうかを実質的に問うことになります。 

制約$n \le 2 \cdot 10^5$テスト ケース全体にわたるということは、テスト ケースごとに線形または線形に近いソリューションが必要であることを意味します。 列のサブセットに対する一致の列挙や動的プログラミングを伴うものは、遅すぎます。 平$O(n \log n)$テストごとは許容されますが、不要です。 

重要なエッジケースは、すべてのセルが最初は同じ色である場合です。 その後、再描画する必要がなく、隣接するすべてのペアを任意にペアにすることができます。 反対に、有効なペア構造をブロックする形で色が完全に交互になっている場合、一致する構造を作成するためにほぼすべてのセルを再描画する必要が生じる可能性があります。 

ローカルの貪欲ペアリングが失敗した場合、別の微妙なケースが発生します。 たとえば、列方向の貪欲なペアリングは、局所的には最適に見えますが、より優れたグローバル マッチングを妨げます。これは、垂直方向と水平方向のペアリングにより、隣接する列の隣接構造の可用性が変化するためです。 

## アプローチ

 ブルートフォースアプローチでは、パーティションを分割する可能なすべての方法を列挙しようとします。$2n$セルを隣接するペアに分割し、各ペアを有効にするために必要な再描画の回数を計算します。 再描画を無視しても、グリッド グラフ内の完全一致をカウントすることはすでに指数関数的です。$n$。 各列には分岐が導入されています。複数の構成では、列内で垂直方向にペアにしたり、列全体で水平方向にペアにしたりできます。 これにより、ほぼフィボナッチのような可能性の増大が起こり、非常に小さい値を超えると総当たり攻撃が不可能になります。$n$。 

重要な観察結果は次のとおりです。$2 \times n$グリッドでは、すべての有効な一致構造を、列内の垂直ドミノまたは隣接する列を接続する水平ドミノのいずれかを含むローカル パターンに分解できます。 これにより、問題は列ごとに、内部で解決するか隣接列とペアにするかを決定することになります。 

再描画はコスト関数として行われます。各潜在的なドミノ (垂直または水平) は、両方のエンドポイントを同一にするために修正する必要がある不一致の色の数に等しいコストを持ちます。 ドミノを配置する重み付けされた選択肢としてグリッドを再解釈すると、問題は、小さな状態空間を持つ列に対する線形動的プログラミングになります。つまり、列が前の列からの水平ペアによってすでに「消費」されているかどうかです。 

最終的なソリューションは、列ごとに 2 つの状態を持つ DP に削減され、一致しないセルを次の列に持ち込むかどうかを追跡し、各遷移の最小再描画コストを計算します。

 ## アルゴリズムのチュートリアル

 列を左から右に処理します。 各列について、2 つのセルを比較し、それらがすでに一致しているか、または垂直方向にペアになっている場合は再描画が必要かどうかを評価します。 

前の列が保留中の水平接続を残したかどうかを表す動的状態を定義します。 これが必要なのは、水平ペアリングが現在の列の 1 つのセルと次の列の 1 つのセルを消費するためです。 

### ステップ

 1. 各列について、その中に垂直ペアを作成するコストを計算します。 両方のセルがすでに一致している場合、これは 0 です。それ以外の場合、それらを統合するには 1 回の再描画が必要です。 これは、列内のペアリングのオプションを表します。 
2. 隣接する列にわたって 2 つの水平ペアを形成するコストを計算します。 これには、列間で上から上と下から下を一致させる必要があります。$i$そして$i+1$。 再ペイントのコストは、これら 2 つの位置の不一致の数です。 
3. 列の DP 状態を維持する$i$: 柱に到着した場合の最小再塗装コスト$i$からの保留中の水平接続の有無にかかわらず$i-1$。 
4. カラムからの遷移$i$に$i+1$次のいずれかによって:

 垂直ペアリングの選択$i$、または

 ペアリング$i$水平に$i+1$、両方の列を同時に消費します。 
5. 保留状態のない列 0 で DP を初期化し、すべての有効な遷移にわたる最小コストを累積します。 
6. 最終的な答えは、列の最小コストです。$n$保留中の一致しないセルはありません。 

### なぜ効果があるのか

 内のすべての有効な完全なペアリング$2 \times n$グリッドは、列内の垂直方向、または 2 つの隣接する列にまたがる水平方向の、互いに素なドミノ配置に分解されます。 これらは、高さ 2 のグリッドで隣接関係の制約を満たす唯一の方法です。DP は、水平方向の遷移では常に一度に 2 つの列を消費し、垂直方向の遷移では 1 つの列を個別に消費することを保証することで、各セルが 1 回だけ使用されるように強制します。 状態変数は、部分的なペアリングが未解決のまま残らないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        top = input().strip()
        bot = input().strip()

        # dp[i][0] = min cost up to i with no pending horizontal connection
        # dp[i][1] = min cost up to i with a pending connection state
        INF = 10**18

        dp0, dp1 = 0, INF

        i = 0
        while i < n:
            # vertical cost at column i
            vcost = 0 if top[i] == bot[i] else 1

            # if we end column i vertically
            ndp0 = min(ndp0 := INF, dp0 + vcost, dp1 + vcost)

            # horizontal pairing i with i+1 if possible
            if i + 1 < n:
                hcost = (top[i] != top[i+1]) + (bot[i] != bot[i+1])

                # transition from no pending
                ndp1 = min(dp0 + hcost, dp1 + hcost)
            else:
                ndp1 = INF

            dp0, dp1 = ndp0, ndp1
            i += 1

        print(dp0)

if __name__ == "__main__":
    solve()
```このコードは、完全な DP 配列ではなく、2 つのローリング状態を維持します。`dp0`は、水平ドミノの完了を待っている列がない場合の最良のコストを表します。`dp1`水平ペアリングが進行中の状態を追跡します。 

各列について、垂直ペアリングのコストを評価し、それを次の状態に伝播します。 可能な場合は、次の列との水平ペアリングも試みます。 ローリング アップデートにより、一定のメモリ使用量が保証されます。 

微妙な点は、水平ペアリングは両方の列を一貫して消費するものとして扱う必要があることです。 DP 移行により、コストはペアごとに 1 回追加され、再描画操作が二重にカウントされることはありません。
