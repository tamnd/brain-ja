 ## 解決策
 ## 問題の理解

 2D 整数グリッド上の一連の点が与えられます。 これらの点は敵対的な構造ではありません。 代わりに、それらは軸に沿った大きな正方形内のランダムなプロセスから生じます。 私たちのタスクは、固定半径の円を配置することです$r$、ほとんどの点がカバーされるように中心が整数になります。 

点が円の内側にある場合、または正確に境界上にある場合、円は点を覆います。 複数の円を配置することができますが、領域が重なってはいけません。 タッチは許可されていますが、ポジティブエリアの交差は禁止されており、実際にはセンターは少なくとも$2r$ユークリッド距離で離れています。 

目標はすべてのポイントを網羅することではなく、少なくとも少なくとも$89\%$。 この許容差は、正確な幾何学的パッキングではなく、密度ベースまたは確率的な戦略を示唆するため、重要です。 

入力サイズは最大です$n = 10^4$。 どれでも$O(n^2)$幾何学的比較戦略は境界線にありますが、定数係数が小さい場合は合格する可能性があります。 ただし、目的のソリューションでは、ペアごとのサークル相互作用やグローバル最適化を回避する必要があります。 

微妙な制約は、円の領域よりもはるかに大きい正方形の内部でランダムに均一に生成されることです。 これは、ポイントが領域内で自然にクラスター化されているだけでなく、孤立したポイントが存在することも意味します。 有効な解決策が存在するという保証により、徹底的な検索の必要がなくなりますが、それを決定的に見つける方法はわかりません。 

単純な間違いは、たとえば K 平均法スタイルのグループ化や貪欲な最大ディスクを使用して、ポイントを最適にクラスタリングする必要があると想定することです。 最適なクラスタリングはローカルな決定では不安定であり、コストが高くなるため、これらのアプローチは失敗する可能性があります。 

もう 1 つのよくある失敗は、貪欲にすべてのポイントに円を配置し、重複を解決しようとすることです。 これは、オーバーラップの解決がグローバルになり、カスケードして正確性が損なわれる可能性があるため、失敗します。 

もっと単純な間違いは、円ごとのカバレッジを最大化する必要があると想定することです。 この問題には最適なパッキングは必要なく、しきい値カバレッジのみが必要であるため、粗いグリッドベースの戦略で十分です。 

## アプローチ

 ブルートフォース解釈では、境界ボックス内のすべての可能な整数の中心を考慮し、距離内にある点の数を評価します。$r$。 次に、貪欲に最適な中心を選択し、覆われた点を削除し、繰り返します。 

これは、各ステップが局所的に最適な円を選択するため概念的には機能しますが、計算的には実行不可能です。 候補センターの数は$O(X^2)$どこ$X$まで可能です$10^5$、あきらめる$10^{10}$候補者たち。 候補を点座標に制限しても、結果は得られます$O(n^2)$最悪の場合、反復ごとにチェックが行われるため、$10^8$に$10^9$距離の計算。 

重要な構造観察は、ランダムな均一分布と弱いカバレッジ要件から得られます。 少なくとも$89\%$をカバーする必要がある場合、全体的に最適なクラスターではなく、密な領域を見つけるだけで済みます。 一様にランダムな正方形では、点は自然に局所的な変動を形成し、一部の領域には平均よりも大幅に多くの点が含まれます。 十分に密な領域は円で捉えることができます。 

継続的に検索する代わりに、セル サイズが次の値に比例するグリッドを使用して平面を離散化します。$r$。 任意の半径の円$r$境界のあるグリッド セルのセットに関連付けることができ、密集したクラスターはその内部の点の 1 つの近くに代表的な中心を持ちます。 

したがって、問題を既存の点位置でのみ候補中心をスキャンすることに縮小します。 カバーされていないポイントごとに、距離内にまだカバーされていないポイントがいくつあるかを数えます。$r$。 この数がしきい値を超えた場合、そこに円を配置し、それらの点を削除します。 

オーバーラップ制限は、ポイントを削除することによって暗黙的に処理されます。円を配置すると、その領域内のポイントが消え、将来の候補が自然に移動するため、別の円を近づきすぎることはありません。

 ## アルゴリズムのチュートリアル

 私たちは、空間枝刈りによる点中心に対する貪欲なクラスタリング戦略に依存しています。 

1. すべてのポイントを最初に発見されたものとして扱い、それらを動的構造 (通常はリストまたはセット) に保存します。 
2. カバーされていないポイントの数が$11\%$の$n$、適切な円の中心を見つけてみてください。 

候補点ごとに$p_i$、距離内にある未カバーのポイントの数を数えます$r$。 これは、浮動小数点エラーを回避するために、二乗ユークリッド距離を使用して行われます。 

これが機能する理由は、有効な解には、残りのカバーされていない点の密なサブセットをカバーする少なくとも 1 つの円が必要であり、それらの点の 1 つがその中心近似として機能できるためです。 
3. カバレッジ数が最大のポイントを選択します。 この最大値が小さい場合は、残りのカバーされていないポイントがすでにまばらであり、許容範囲内にあることを意味します。$11\%$しきい値。 
4. この選択した点を中心とする円を配置し、半径内のすべての点にマークを付けます$r$カバーされているように。 
5. 停止条件が満たされるまで繰り返します。 

重要な最適化は、相互に作用する幾何学的オブジェクトとして円を明示的に維持しないことです。 代わりに、カバレッジは純粋にポイントの削除によって管理されます。これは、オーバーラップする円にはオーバーラップするカバーされていないポイントが必要となるため、実際には自動的に非オーバーラップが強制されますが、そのポイントはもう存在しません。 

### なぜ効果があるのか

 このアルゴリズムは、カバーされていないポイントの縮小セットを維持します。 配置された各円は、代表的な位置を中心とする点の密集した近傍を削除します。 入力は円のサイズに比べて大きな領域では一様にランダムであるため、ほとんどの点が削除されるまで密集したクラスターが常に存在します。 

不変条件は、各反復の後、残りのすべての覆われていない点が、以前に選択された密集領域の外側にあるということです。 各反復では局所密度の大部分が削除されるため、カバーされていないセットは急速に縮小します。 以下に陥る前にプロセスが停止します$11\%$の要件を確保します。$89\%$カバレッジは満たされています。 

ランダム分布の保証により、進行を妨げるほど大きな病的まばらな構成が高確率で存在しないことが保証され、有効な解決策の存在は、そのような密な選択が常に存在することを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, r = map(int, input().split())
    pts = [tuple(map(int, input().split())) for _ in range(n)]
    
    r2 = r * r
    alive = [True] * n
    remaining = n
    centers = []

    def count_covered(i):
        x1, y1 = pts[i]
        cnt = 0
        for j in range(n):
            if alive[j]:
                x2, y2 = pts[j]
                dx = x1 - x2
                dy = y1 - y2
                if dx * dx + dy * dy <= r2:
                    cnt += 1
        return cnt

    while remaining > (11 * n) // 100:
        best_i = -1
        best_cnt = 0

        for i in range(n):
            if not alive[i]:
                continue
            cnt = count_covered(i)
            if cnt > best_cnt:
                best_cnt = cnt
                best_i = i

        if best_i == -1 or best_cnt == 0:
            break

        centers.append(pts[best_i])

        x0, y0 = pts[best_i]
        for i in range(n):
            if alive[i]:
                x, y = pts[i]
                dx = x - x0
                dy = y - y0
                if dx * dx + dy * dy <= r2:
                    alive[i] = False
                    remaining -= 1

    print(len(centers))
    for x, y in centers:
        print(x, y)

if __name__ == "__main__":
    solve()
```このソリューションは、まだカバーされていないポイントの最大数をカバーするポイントを繰り返し選択します。 機能`count_covered`すべてのポイントをスキャンしてカバレッジを計算し、メイン ループが最良の候補を貪欲に選択します。 

削除ステップは、領域が一度カバーされるとその後の決定に影響を与えず、同じ領域に重複する円が発生するのを防ぐため、非常に重要です。 

終了条件は、少なくともカバーするという要件を直接エンコードします。$89\%$ポイントの。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての点がすでに 1 つの半径内にある場合です。 この状況では、最初に選択されたセンターがすべてをカバーし、残りの比率がしきい値を下回るためにループがすぐに停止します。 貪欲な選択では、すべてのポイントが同じ範囲にあるため、自然に任意のポイントが中心として選択されます。 

もう 1 つのケースは、ポイントが均等に分散されており、単一のポイントが大きくカバーされない場合です。 その後、各反復で少数のポイントのみが削除されますが、89% のしきい値が満たされるとループは停止します。 アルゴリズムは完全なカバレッジを強制しようとすることはありません。これにより、不必要な円が回避されます。 

3 番目のケースは、クラスターから遠く離れた孤立した外れ値です。 これらの点はカバーされていないままですが、許容される 11% のスラック内にあるため、アルゴリズムはそれらをカバーしようとせずに終了し、問題の要件に一致します。
