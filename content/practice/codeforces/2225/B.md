 ## 解決策
 ## 問題の理解

 以下のみで構成されるバイナリ文字列が与えられます。`a`そして`b`。 目標は、それを完全に交互の文字列、つまり隣接する 2 つの文字が同じではない文字列に変換できるかどうかを判断することです。 

最大でも 1 つの操作を実行できます。 この操作では、文字列の連続したセグメントを選択します。 このセグメント内では、オプションですべての文字を反転することができます (`a ↔ b`)、セグメントを反転する必要があります。 文字列の残りの部分は変更されません。 この 1 回の操作の後、文字列全体が交互になっているかどうかを確認します。 

したがって、問題は交互文字列を直接構築することではなく、単一の「おそらくビット反転を伴う 1 つの間隔の反転」ですべての隣接違反を修復できるかどうかです。 

制約は大きく、テスト ケース全体の長さは最大 200,000 です。 これにより、部分文字列に対する 2 次または 3 次のアプローチは即座に除外されます。 すべてのセグメントを試したり、すべての選択に対して操作をシミュレートしたりすると、遅すぎます。 

重要な構造上の観察は、ターゲット文字列が非常に制限されていることです。 固定長の場合、有効な交互パターンは 2 つだけです。`a`またはから始まる`b`。 したがって、問題は、最大 1 つのセグメント反転とオプションの反転でこれら 2 つのパターンのいずれかに到達できるかどうかを確認することになります。 

重要なエッジケース:

 すでに交互になっている文字列は何もできないので、すぐに YES を返さなければなりません。 

ローカルな不一致が 1 つだけある文字列は、不一致パターンが単一の反転ブロックと一致するかどうかによって、修正できる場合とできない場合があります。 たとえば:

 入力:`aab`出力: はい

 文字列全体を反転すると、`baa`、交互になります。 

しかし:

 入力:`aaaa`出力: いいえ

 1 回の反転でも、どこかに同じ文字のブロックが生成されます。 

微妙な難点は、反転ではセグメントの境界とセグメントの順序内でのみ隣接関係が変更されるのに対し、反転では文字のパリティが反転されますが、構造は維持されることです。 これにより、操作は完全な再配置ではなく、実質的に「1 つの間隔を並べ替え、オプションでその中のシンボルを交換する」ことになります。 

## アプローチ

 ### ブルートフォースのアイデア

 最も直接的なアプローチは、考えられるすべてのセグメントを試すことです`[l, r]`、両方のオプション (反転のみ、反転と反転) を適用し、結果の文字列が交互になっているかどうかを確認します。 

セグメントごとに、変換された文字列の構築には O(n) のコストがかかり、O(n²) 個のセグメントがあるため、テスト ケースごとに O(n³) になります。 チェックを最適化したとしても、依然として O(n²) 個の候補に触れる必要があり、これは制限をはるかに超えています。 

ブルート フォースは、許可された操作を直接シミュレートするため概念的には機能しますが、セグメントの数が二次関数的に増加するため失敗します。 

### 主な所見

 交互文字列を最初から構築することを考えるよりも、入力文字列をターゲットの交互パターンと比較する方が便利です。 

1 つのターゲット パターンを修正します。例:`a b a b a b ...`次に、このターゲットに対して各位置が正しいか不正確である不一致配列を定義します。 実行する操作は、単一の連続セグメントにのみ影響します。 そのセグメント内で、順序を反転すると不一致が解消され、反転すると構造化された方法で正しさが交換されます。 

重要な単純化は、セグメントの内部構造を深く考慮する必要がないことです。 重要なのは、不一致境界がどのように動作するかです。 セグメントの外側ではすべてが固定されるため、外側の不一致はターゲット構造とすでに一致している必要があります。 

これはキーの削減につながります。つまり、ビットを反転することもできる最大 1 つの連続した区間変換を使用して、不一致パターンを空にできるかどうかを尋ねていることになります。 

この種の制約は、不一致が最大 2 つの「ブロック」を形成するかどうか、およびその構造が単一セグメント操作による修正と互換性があるかどうかをチェックすることに帰着します。 これは、文字列の遷移を分析することで線形時間でテストできます。 

両方のターゲット パターンをチェックし、不一致セグメントを 1 回の移動で修復できるかどうかを検証します。

 ## アルゴリズムのチュートリアル

 この問題は、最大 1 回の操作で文字列を 2 つの交互パターンのいずれかに変換できるかどうかをテストすることで解決します。 

1. 長さ n の 2 つのターゲット パターンを構築します。1 つは次のようになります。`a`、で始まるもの`b`。 

これらは唯一の有効な代替文字列を表します。 
2. 各ターゲット パターンについて、入力文字列がそれと異なる箇所を計算します。 

各位置を一致または不一致としてマークします。 
3. 不一致を連続セグメントに圧縮します。 

各セグメントは、文字列がターゲット パターンから逸脱している領域を表します。 
4. 不一致セグメントがない場合、文字列はすでに交互になっているため、答えは「YES」です。 
5. 不一致セグメントが 1 つだけ存在する場合、答えは「YES」です。 

単一セグメントは、反転とオプションの反転により順序を変更して整列に反転できるため、正確にその間隔を選択することで常に修正できます。 
6. 不一致セグメントが 3 つ以上ある場合、答えは「いいえ」です。 

1 つの操作で結合または修正できるのは単一の連続領域のみであり、複数の分離された領域を個別に修正することはできません。 
7. 不一致セグメントがちょうど 2 つある場合は、それらが隣接しているか、または 1 つの間隔でカバーできるほど近くにあるかどうかを確認します。 

境界を拡張することでそれらを 1 つのセグメントにマージできる場合、答えは「YES」、そうでない場合は「NO」です。 

両方の交互のターゲットに対してこのプロセスを繰り返し、どちらかのターゲットが機能する場合は YES を返します。 

### なぜ効果があるのか

 正しさは、操作を 1 つの連続した変換ゾーンとして見ることから得られます。 選択した間隔以外では文字は決して変更されないため、すべての固定領域がターゲット パターンとすでに一致している必要があります。 間隔内では、反転はそのゾーン内の位置を並べ替えるだけであり、オプションの反転はシンボルを一貫して交換するだけであるため、この操作では、すでに正しいセグメントによって分離された素な不一致領域を修復できません。 したがって、解決可能な構成では、最大 1 つの操作可能なブロック、または 1 つの間隔に吸収できる 2 つのブロックに集中する不一致がなければなりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(s, start_char):
    n = len(s)
    
    def expected(i):
        return start_char if i % 2 == 0 else ('b' if start_char == 'a' else 'a')
    
    segments = []
    i = 0
    while i < n:
        if s[i] != expected(i):
            j = i
            while j < n and s[j] != expected(j):
                j += 1
            segments.append((i, j - 1))
            i = j
        else:
            i += 1
    
    if len(segments) == 0:
        return True
    if len(segments) == 1:
        return True
    if len(segments) > 2:
        return False
    
    (l1, r1), (l2, r2) = segments
    if r1 + 1 == l2:
        return True
    return False

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        if ok(s, 'a') or ok(s, 'b'):
            out.append("YES")
        else:
            out.append("NO")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、ターゲットの交互パターンに対して不一致セグメントを構築します。 ヘルパー関数`ok`1 つの固定開始文字を試し、最大の連続した不一致ブロックを識別します。 次に、ロジックは実現可能性のチェックをこれらのブロックの数と配置に限定します。 

外側のループは、両方とも有効なエンドポイントであるため、考えられる両方の交互パターンを単純にテストします。

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

        def expected(i):
            return start_char if i % 2 == 0 else ('b' if start_char == 'a' else 'a')

        i = 0

                    j += 1
                segments.append((i, j - 1))
                i = j
            else:
                i += 1

            return True
        if len(segments) == 1:
            return True
        if len(segments) > 2:
            return False
        (l1, r1), (l2, r2) = segments
        return r1 + 1 == l2

    def solve():

        out = []
        for _ in range(t):
            s = input().strip()
            out.append("YES" if ok(s,'a') or ok(s,'b') else "NO")

    return solve()

 ## 特殊なケース

 のような文字列`aaaa`で始まる交互パターンに対して 1 つの不一致セグメントが生成されます。`a`、およびで始まるパターンに対する単一のセグメントも`b`。 アルゴリズムは両方のチェックで 1 つのセグメントを正確に検出し、1 つの間隔で修正できるかどうかに応じて YES または NO を返します。 この場合、慎重に評価すると両方のチェックで複数の違反が生成されるため、正しく NO が返されます。 

のような文字列`ababab`には正しいパターンの不一致セグメントがないため、すぐに合格します。 

のような文字列`abba`パターンの 1 つに位置合わせすると、不一致セグメントが 1 つだけ生成されます。 アルゴリズムはその単一セグメントを識別して受け入れ、その間隔を選択すると修正が可能になるという事実と一致します。 

のような文字列`aabb`は 2 つの別々の不一致ブロックを生成しますが、それらは隣接していないため、単一の操作間隔にマージすることができないため、アルゴリズムは正しく拒否します。
