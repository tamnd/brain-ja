 ## 解決策
 ## 問題の理解

 2 つの整数が与えられます`x`そして`y`そのような`y`より大きい`x`そしてそれは次で割り切れます`x`。 タスクは、3 番目の整数が存在するかどうかを判断することです。`z`それは厳密に次の間にあります`x`そして`y`、は次で割り切れます`x`、しかし分割しません`y`。 簡単に言えば、次の倍数を探しています。`x`それはより大きいです`x`それ自体はあるが均等に分割されていない`y`。 

制約により許可されるのは、`x`そして`y`と同じくらい大きくなる`10^18`まであります`10^4`テストケース。 これは、すべての候補に対して反復されるソリューションを意味します。`z`間の倍数が異なるため、実行不可能です。`x`そして`y`巨大なものになる可能性があります。 テストケースごとに一定時間のチェックが必要か、最悪の場合、比率が対数的なものが必要です。`y/x`。 

エッジケースが発生するのは次の場合です`y`ちょうど2倍です`x`。 そのシナリオでは、次の唯一の倍数は、`x`厳密に間`x`そして`y`は`2x = y`、条件を満たさない`y % z != 0`。 たとえば、次の場合`x = 5`そして`y = 10`、ありません`z`条件を満たしているので、答えは次のようになります。`NO`。 不注意なアプローチは危険をもたらす可能性があります`2x`除算制約をチェックしないと、誤った結果が生成されます。`YES`。 

別の微妙なケースが発生する場合`y`の大きな倍数です`x`ただし、2 より大きい素因数によってのみ指定されます。次に、最も単純な選択は次のとおりです。`z = 2x`うまくいきますので`y`で割り切れない`2x`。 の素因数分解の仕組みを理解する`y/x`の小さな倍数と相互作用します`x`が鍵です。 

## アプローチ

 ブルート フォースのアプローチは簡単です。次の倍数ごとに生成します。`x`から`2x`まで`y-x`、分割されるかどうかを確認します`y`。 そのような倍数が割り切れない場合`y`、 戻る`YES`。 それ以外の場合は戻ります`NO`。 この方法は原理的には正しいですが、最悪のシナリオでは次のようなことが起こります。`y/x`に近いです`10^18/x`、すべての倍数を反復処理することは計算上不可能です。 

より高速なソリューションを実現する重要な観察は、次の最小倍数であるということです。`x`より大きい`x`は`2x`。 もし`y`に等しくありません`2x`、 それから`2x`最初の 2 つの条件は自動的に満たされます (`2x > x`で割り切れる`x`）。 残っている唯一のチェックは、`y`で割り切れます`2x`。 そうでない場合は、`2x`が私たちの解決策です。 もし`y`で割り切れます`2x`、次の倍数を確認できます`3x`、しかし、なぜなら`y % x == 0`、の分割`y`による`x`整数を返します`k`。 どうかを確認する必要があります`k > 2`; はいの場合は、`2x`分けない`y/k > 1`、 それで`2x`動作します。 もし`k == 2`、`y = 2x`そして有効なものはありません`z`。 これにより、問題はテスト ケースごとの一定時間のチェックに軽減されます。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. テスト ケースごとに、整数を読み取ります。`x`そして`y`。 
3. 比率を計算する`k = y // x`。 この回数です`x`に適合する`y`。 
4. もし`k == 2`、整数はありません`z`厳密に間`x`そして`y`条件を満たすものです。 出力`NO`。 
5. もし`k > 2`、整数`z = 2 * x`すべての条件を満たします。 出力`YES`。 

なぜうまくいくのか: 分割することによって`y`による`x`、問題を小さな整数チェックに縮小します。`z = 2x`は常により大きいです`x`未満`y`いつ`k > 2`。 以来`2x`分割する`y`そのときだけ`k`均等です、私たちの小切手`k > 2`いずれかを保証します`2x`分けない`y`、または有効な倍数が存在します。 このアプローチでは、すべての有効な入力の正確性が保証されます。これは、次の 3 つの基準に違反する可能性のある他の構造的条件がないためです。`z`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    x, y = map(int, input().split())
    k = y // x
    if k == 2:
        print("NO")
    else:
        print("YES")
```コードは高速 I/O で複数のテスト ケースを効率的に読み取ります。 各ペアごとに`x, y`、比率を計算します`k = y // x`そして即座に出力を決定します。 の倍数を生成することを避けます。`x`明示的に行うことで、タイムアウトのリスクを排除します。 境界線`k == 2`エッジケースを処理します。`y`ちょうど2倍です`x`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    t = int(input())
    for _ in range(t):
        x, y = map(int, input().split())
        k = y // x
        if k == 2:
            print("NO")
        else:
            print("YES")
    return output.getvalue().replace("\n","")

# Provided samples
assert run("3\n5 10\n21 31234567890\n87 84\n") == "NOYESYES", "sample 1"

# Custom cases

assert run("1\n1 3\n") == "YES", "smallest valid YES case"
assert run("1\n100000000000000000 300000000000000000\n") == "YES", "large numbers, k > 2"
assert run("1\n10 20\n") == "NO", "y = 2*x edge case"
assert run("1\n7 28\n") == "YES", "k = 4 multiple works"

## 特殊なケース

 重要なエッジケースは、`y = 2x`。 入力用`x = 5, y = 10`、比率`k = 2`。 アルゴリズムは正しく出力します`NO`なぜなら`2x`等しい`y`そして厳密な不平等に違反します。 もう 1 つの特殊なケースは、次のような非常に大きな数値です。`x = 10^17, y = 3*10^17`。 ここ`k = 3`、 それで`2x = 2*10^17`厳密にその間にあります`x`そして`y`、 そして`y % (2x) != 0`。 アルゴリズムの出力`YES`正しく。 どちらのエッジ ケースでも、アルゴリズムが小さい入力と大きい入力を一貫して処理していることが確認されています。
