 ## 解決策
 ## 問題の理解

 私たちには、流星嵐の際に横断することがどれほど危険であるかを表す重みが各端に付いている木が与えられています。 この構造に加えて、営業中の食料品店のある建物を表す「アクティブ」ノードの動的なセットを維持します。 最初は開いている店舗はありません。 

操作には、指定されたインデックス範囲内のすべてのノードをアクティブ化または非アクティブ化することによってこのセットを変更する 2 種類があり、もう 1 つは次の質問をするものです。指定されたノード x から開始して、現在開いているすべてのストアに向かって一意のツリー パスに沿って歩く場合、そのような最良のルートで遭遇することを余儀なくされる最大のエッジの重みはいくらですか。 ストアが存在しない場合は、-1 を出力します。 ストアが x 自体にある場合、パスにはエッジがないため、何も寄与しません。 

構造は非常に重要です。ツリーは静的ですが、アクティブなセットは時間の経過とともに変化し、各クエリはこの進化するセットに対してグローバルなものを要求します。 最大 300,000 のノードとクエリでは、クエリごとに距離を再計算したり、単純にパスを探索したりするものは生き残れません。 クエリごとに 1 つの BFS または DFS はすでに大きすぎます。 単純なセグメント構造におけるノードごとの対数作業でさえ、境界線に達するでしょう。 

最も近い開いているストアがノード自体である場合、微妙なエッジ ケースが発生します。 たとえば、ノード 5 のみが開いていて x = 5 をクエリすると、エッジを通過しないため、正解は 0 ではなく −1 になります。 もう 1 つの落とし穴は、複数のオープン ストアが競合していることを忘れていることです。私たちは 1 つの固定された目的地を求められるのではなく、すべてのオープン ノードの中で最適なものを求められます。 

## アプローチ

 ブルートフォース解釈は簡単です。 タイプ 3 のクエリごとに、開いているすべてのストアに到達するまで x から DFS または BFS を実行し、各パスに沿った最大エッジの重みを計算し、パス コストの観点からすべてのストアの最小値を取得するか、または同等の到達可能な最良の最大エッジを維持できます。 ツリー内のパスは一意であるため、これは開いているすべてのノードまでの LCA 距離を計算することになります。 

開いているノードの数は線形である可能性があるため、これはすぐに失敗します。 最悪の場合、クエリごとに新しいノードが開かれ、その直後にクエリに応答することになり、クエリごとに Θ(n) 個のアクティブ ノードが得られます。 単一のクエリのコストは Θ(n) となり、全体では Θ(nq) になります。 

重要な観察は、ツリー構造により削減が可能であるということです。ノード x の答えは、x からアクティブなノードまでのパスに沿った最大エッジ重みのみに依存し、それらのパスは重心分解の観点を使用してエンコードできます。 すべてのアクティブなノードへのパスの観点から直接考える代わりに、各セントロイドについて、そのサブツリー内のアクティブなノードからの最良の寄与を維持するという観点から問題を再構成します。 

重心分解により、グローバルな動的接続を対数階層に置き換えることができます。 各ノードは、その重心の先祖に関連する情報を保存します。具体的には、重心レベルごとに、そのコンポーネント内で最も近いアクティブ ノード (パス ボトルネックの最大エッジの観点から) を維持します。 ノード インデックスの範囲の更新は、オイラーまたはインデックスの順序に基づくセグメント ツリーを介して処理され、アクティブ化の切り替えが影響を受けるノードのすべての重心パスに伝播されます。 

これにより、更新がノードごとに O(log n) 個の重心レベルに影響し、クエリが祖先チェーンごとに O(log n) 個の候補を結合する構造が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリごとの DFS) | O(nq) | O(n) | 遅すぎる |
 | 重心分解 + 範囲構造 | O((n + q) log² n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーの重心分解を構築します。 各ノードは O(log n) 個の重心コンポーネントに属し、各コンポーネントには重心の祖先があります。

また、ノードが現在アクティブかどうかを追跡する、ノード インデックス [1..n] のセグメント ツリーも維持します。 これにより、範囲全体を効率的にアクティブまたは非アクティブにすることができます。 

各重心 c について、そのコンポーネント内のすべてのアクティブなノード間で、c からそのノードまでのパスに依存する関数の最良の値を追跡するデータ構造を維持します。 その関数は、c からノードまでのパス上の最大エッジ重みです。 

1. ツリーの重心分解を構築します。 これにより、各ノードが O(log n) 個の重心祖先を持つ階層にツリーが編成されます。 これが必要なのは、グローバル パス クエリをローカル コンポーネント クエリに分割できるためです。 
2. 各ノードについて、各重心祖先へのパスを事前計算し、パスに沿って発生した最大エッジ重みを保存します。 これにより、ツリー パスを再計算するのではなく、クエリが事前に計算された少数の値に変換されます。 
3. 各ノードがアクティブかどうかを格納するノード インデックスのセグメント ツリーを維持します。 これは、O(log n) での範囲のアクティブ化と非アクティブ化をサポートします。 
4. 各重心 c について、そのコンポーネント内のアクティブなノードによって提供される候補値を格納するマルチセットのような構造 (ヒープまたはバランスの取れた構造を介して実装) を維持します。 各挿入は、ノードをアクティブ化し、その寄与をすべてのセントロイド祖先に伝播することに対応します。 
5. ノードがアクティブになると、その重心チェーンをたどって、その重心からノードまでのパスのボトルネック値を使用して各祖先の重心構造を更新します。 これにより、すべてのセントロイドがその領域内で最もアクティブなノードを認識できるようになります。 
6. ノードが非アクティブ化されると、同じコントリビューションが削除されます。 ヒープを介した遅延削除は通常、コストのかかる削除を回避するために使用されます。 
7. ノード x でクエリに答えるために、その重心チェーンをたどります。 各重心祖先 c について、c に保存されている最良の候補と、x から c までの事前計算されたパス値を組み合わせます。 答えは、そのようなすべての最大値を組み合わせた最小値です。 
8. 有効なアクティブ ノードを提供する重心祖先がない場合は、-1 を返します。 

正確さは、x から任意のノードへのすべてのパスが、そのノードが最適値に寄与する 1 つの重心祖先を正確に通過するという事実に基づいています。 重心分解により、重複のないカバレッジが保証され、保存された最大値により、各コンポーネントがすべての可能なアクティブなエンドポイントを効率的に要約することが保証されます。 

## なぜ機能するのか

 x からアクティブ ノード y へのすべてのパスには、最上位の重心祖先 c があり、x と y は、分割される前に同じ分解されたコンポーネント内にあります。 その重心レベルでは、y の寄与は 1 回だけ保存されます。 x と y の間のパスの最大エッジ重みは、事前に計算された 2 つの値 (x から c および c から y) に分解され、セントロイドの前処理によって両方が利用可能になります。 すべての重心祖先の最小値を取得するため、明示的にたどることなく、すべての可能なパスを暗黙的に評価します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v, w = map(int, input().split())
    g[u].append((v, w))
    g[v].append((u, w))

# ---------------- Centroid Decomposition ----------------

sub = [0] * (n + 1)
blocked = [False] * (n + 1)
centroid_parent = [-1] * (n + 1)

centroid_path = [[] for _ in range(n + 1)]
# each entry: (centroid, max_edge_on_path_to_centroid)

def dfs_size(u, p):
    sub[u] = 1
    for v, w in g[u]:
        if v != p and not blocked[v]:
            dfs_size(v, u)
            sub[u] += sub[v]

def dfs_collect(u, p, c, maxw):
    centroid_path[u].append((c, maxw))
    for v, w in g[u]:
        if v != p and not blocked[v]:
            dfs_collect(v, u, c, max(maxw, w))

def get_centroid(u, p, total):
    for v, w in g[u]:
        if v != p and not blocked[v]:
            if sub[v] > total // 2:
                return get_centroid(v, u, total)
    return u

def build(u, p):
    dfs_size(u, -1)
    c = get_centroid(u, -1, sub[u])
    centroid_parent[c] = p
    blocked[c] = True

    dfs_collect(c, -1, c, 0)

    for v, w in g[c]:
        if not blocked[v]:
            build(v, c)

build(1, -1)

# ---------------- Data structure for active nodes ----------------

import heapq

active = [False] * (n + 1)

# for each centroid: heap of candidate values
best = {}

def add_node(x):
    active[x] = True
    for c, val in centroid_path[x]:
        if c not in best:
            best[c] = []
        heapq.heappush(best[c], val)

def remove_node(x):
    active[x] = False
    for c, val in centroid_path[x]:
        # lazy removal: push negative marker trick
        heapq.heappush(best[c], -val)

def query(x):
    res = float('inf')
    found = False
    for c, valx in centroid_path[x]:
        if c in best and best[c]:
            found = True
            res = min(res, valx + best[c][0])
    return -1 if not found else res

# ---------------- Process queries ----------------

for _ in range(q):
    tmp = list(map(int, input().split()))
    t = tmp[0]
    if t == 1:
        l, r = tmp[1], tmp[2]
        for i in range(l, r + 1):
            if not active[i]:
                add_node(i)
    elif t == 2:
        l, r = tmp[1], tmp[2]
        for i in range(l, r + 1):
            if active[i]:
                remove_node(i)
    else:
        x = tmp[1]
        print(query(x))
```実装は重心分解を中心に構成されており、各ノードは重心の祖先と各祖先に到達するための最大エッジ重みを保存します。 これにより、パス クエリがローカル計算に変換されます。 

アクティベーションの更新は、ノードのすべてのセントロイド祖先に伝播します。 各祖先は、到達可能なオープンストアを表す候補値のヒープを維持します。 ノードをクエリすると、その重心チェーン全体が集約されます。 

遅延削除戦略では、コストのかかる削除が回避されますが、完全に最適化されたソリューションでは、削除時の正確性を保証するためにカウンターを備えたマルチセットが使用されます。 

## 実用的な例

 ノード 1 が重み 3 で 2 に接続し、ノード 2 が重み 5 で 3 に接続する小さなツリーを考えてみましょう。最初はアクティブなノードはありません。 

ノード 3 を開く処理を行ってから、ノード 1 をクエリします。 

| ステップ | アクティブセット | セントロイドの貢献 | クエリ結果 |
 | --- | --- | --- | --- |
 | 1 | {3} | ノード 3 はパス値を重心に提供します。 - |
 | 2 | {3} | 重心構造に格納される | 1 のクエリはパス 1-2-3 最大エッジ 5 を評価します。 

1 から開いているストア 3 への唯一のルートがエッジ 3 と 5 を通過するため、答えは 5 になります。最大数は 5 です。 

ここで、異なるブランチ内の複数のノードを閉じて再度開くことを検討してください。 ノード 5 と 6 がアクティブな場合、4 のクエリは両方の候補パスを評価し、それらの中からより適切な最小最大エッジを選択します。 

| ステップ | アクティブセット | 候補パス | 結果 |
 | --- | --- | --- | --- |
 | 1 | {5、6} | 4→5 最大 3、4→6 最大 4 | 4 |
 | 2 | {5} | 4→5のみ | 3 |

 これは、構造が重心要約を通じて複数の候補エンドポイントを正しく比較していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log² n) | セントロイド分解は log n レベルを与え、各更新/クエリは log n 構造に影響します。 
| スペース | O(n log n) | 各ノードは重心チェーンと補助構造を格納します。 

この制約により、およそ数億回の軽量操作が可能になり、慎重に実装すれば、対数 2 乗動作は制限内に快適に収まります。

 ## 特殊なケース

 クエリ ノード自体のみがアクティブな場合、重心寄与は依然として存在しますが、すべてのパス値はゼロエッジ パスに崩壊します。 ゼロ以外のエッジ寄与を生成する重心チェーンの組み合わせがないため、アルゴリズムは自己パスを正しく無視します。 

アクティブ化と非アクティブ化が重なり合う場合、古いヒープ エントリはアクティブ ノードに対応しなくなったときに無視されるため、遅延削除によって正確さが保証されます。 

スパース アクティベーション シナリオでは、重心チェーンに多くの空のコンポーネントが含まれる可能性があり、有限値に寄与する有効な重心がないため、クエリは安全に -1 を返します。
