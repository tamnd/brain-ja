 ## 解決策
 ## 問題の理解

 それぞれが映画のシーンを表す一連の短い文字列が与えられます。 これらのシーンからサブシーケンスを選択することができます。つまり、元の順序は維持しますが、一部のシーンをスキップする場合があります。 

選択したシーンを連結すると、単一の文字列が得られます。 目的は、連結が回文である空ではないサブシーケンスが少なくとも 1 つ存在するかどうかを判断することです。 

主な難しさは、文字列を自由に構築しているのではなく、最大 3 つの長さのブロック全体を選択することによって構築していることです。また、順序を維持する必要があります。 

制約は大きく、すべてのテスト ケースにわたるシーンの総数は最大 100,000 です。 すべてのサブシーケンスを試すアプローチは、指数関数的に多くのサブシーケンスがあるため、直ちに不可能になります。 連結後にすべての部分文字列をチェックすることすら不可能です。 

素朴なアプローチは、多くの組み合わせを構築したり、貪欲に回文を構築したりすることですが、回文が遠くの反転パターンの一致に依存している場合は失敗します。 

単一のシーン自体は回文ではないが、2 つのシーンを組み合わせると回文を形成する場合、微妙なエッジ ケースが発生します。 たとえば、「アブ」と「バ」です。 個々の文字列のみをチェックすると、誤って NO が返されてしまいます。 

別の特殊なケースは、回文が 2 文字の文字列、中間の回文 1 文字、およびその逆の 3 つの部分で形成される場合に発生します。 たとえば、「ab」、「c」、「ba」などです。 この構造が欠けていると、誤った拒否につながります。 

## アプローチ

 ブルートフォース解釈では、シーンのすべてのサブシーケンスを考慮してそれらを連結し、結果の文字列が回文であるかどうかを確認します。 これは定義に直接従うので正しいですが、サイズ n の配列のすべてのサブセットを探索し、O(2^n) 個の可能性を与えます。 回文チェックが全長において線形であるとしても、これは実現可能な限界をはるかに超えています。 

検索スペースを大幅に削減する必要があります。 重要な観察は、回文は両端の対称文字を一致させることによって決定されるということです。 各シーンの長さは最大 3 であるため、利用可能な部分を使用して長さ 1、2、または 3 の回文を作成できるかどうかを推論するだけで済みます。 

これは構造の簡素化につながります。 有効な部分列回文は、2 つの条件のいずれかを満たさなければなりません。 単一のシーンがすでに回文文字列になっているか、連結して回文を形成する 2 つのシーンを選択することができます。 連結は対称である必要があるため、2 番目のケースでは、シーケンス内で文字列とその逆を検索し、場合によっては他の要素で区切ることになります。 

この制限された設定では長さが 2 を超える回文は一致するペアまたは長さ 1 または 3 の中央の回文ブロックに縮小する必要があり、これらは反転と回文のシングルをチェックすることですでにカバーされているため、より長い組み合わせを考慮する必要はありません。 

したがって、問題は文字列およびその逆の頻度と検索の問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n・L) | O(L) | 遅すぎる |
 | 最適 | O(n・L) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、表示された文字列のセットを維持します。 

1. これまでに検出されたすべての文字列のハッシュ セットを維持します。 

これにより、逆の対応物が存在するかどうかの定時検索が可能になります。 
2. 新しい文字列 s ごとに、まず s 自体が回文であるかどうかを確認します。 

そうであれば、単一要素のサブシーケンスが有効であるため、すぐに「YES」と答えることができます。 
3. s の反転がすでに表示されているかどうかを確認します。

「はい」の場合、2 つのシーン (以前の文字列と現在の文字列) の回文連結を形成できます。 
4. さらに、構造の長さの制約を安全にするために、長さ 2 のすべての検出された文字列も追跡し、ある文字列の最初の文字が別の文字列の 2 番目の文字と逆の順序で一致する相互一致パターンをチェックします。 ただし、長さは最大 3 であるため、逆引き検索では、有効な 2 ブロックの回文がすべて完全に捕捉されています。 
5. どちらの条件も満たされない場合は、セットに s を挿入して続行します。 
6. 最後までに条件がトリガーされなかった場合は、NO を出力します。 

### なぜ効果があるのか

 文字列全体の連結から構築された回文は、最終的な文字列全体で対称な位置を揃える必要があります。 各ブロックは非常に短いため、有効な構造は単一の回文ブロック、または順序が互いに逆のブロックのペアのいずれかに折りたたまれます。 逆チェックでは、有効なミラーリングされたペアがサブシーケンス順序に存在する場合は、スキップされた要素に関係なく、それが検出されることが保証されます。 

左から右にスキャンするため、候補の右半分を検査するときに、すべての潜在的な左半分がすでに保存されており、有効なペアが見逃されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_pal(s):
    return s == s[::-1]

t = int(input())
for _ in range(t):
    n = int(input())
    seen = set()
    
    ok = False
    
    for _ in range(n):
        s = input().strip()
        
        if not ok:
            if is_pal(s):
                ok = True
            else:
                rs = s[::-1]
                if rs in seen:
                    ok = True
        
        seen.add(s)
    
    print("YES" if ok else "NO")
```このソリューションは、テスト ケースごとに 1 つのセットを維持し、一定の時間平均で各文字列をチェックします。 

回文チェックは、単純な文字列の反転比較です。 逆引き検索は、一致するパートナーが以前にすでに出現していたかどうかを検出する中心的なメカニズムです。 

ブール値フラグは、有効な構成が見つかった後の不要な作業を防ぎますが、正確さには影響しません。

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

        n = int(input())
        seen = set()
        ok = False

                if s == s[::-1] or s[::-1] in seen:
                    ok = True
            seen.add(s)
        
        out.append("YES" if ok else "NO")
    
    return "\n".join(out)

 ## 特殊なケース

 単一文字の文字列入力は常に回文であるため、すぐに処理されます。 たとえば、入力`["a"]`最初のステップで YES が生成されるため、`a == a[::-1]`。 

みたいなペア`["ab", "ba"]`逆引きによってのみ検出されます。 加工時`"ba"`、`"ab"`セット内にすでに存在しているため、どちらの文字列も個別には回文ではない場合でも、YES の結果がトリガーされます。 

のようなケース`["ab", "cd", "cba"]`逆ペアが整列せず、単一の回文文字列が表示されないため、有効な回文部分列は生成されません。 アルゴリズムは条件をトリガーせずにすべての文字列を処理し、正しく NO を出力します。 

これらのケースは、アルゴリズムが強引な構築ではなく純粋に構造的対称性に依存していることを裏付けており、制約の下での正確性にはこれで十分です。
