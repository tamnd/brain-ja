 ## 解決策
 ## 問題の理解

 アリスとボブの 2 人用ゲームを分析するように頼まれました。 ゲームは次の期間続きます`n`順番に、アリスは次のいずれかの数字を選択します。`0`そして`k`。 次に、ボブは、少なくとも追加する必要があるという制限付きで、その数値を現在の合計スコアに加算するか減算するかを決定します。`m`の`n`数字。 両方のプレイヤーが最適にプレイします。アリスは最終スコアをできるだけ高くすることを望み、ボブは最終スコアをできるだけ低くすることを望みます。 タスクは最終スコアのモジュロを決定することです`10^9 + 7`。 

重要な課題は、ボブの決定が最小限の追加数によって制約されることです。`m`、アリスは任意の数字を選択できます`[0, k]`ボブの選択に影響を与えるためです。 これにより、潜在的な利益を最大化することと、ボブを不利な立場に追い込むこととの間に微妙な相互作用が生じます。 入力制約 (`n ≤ 2000`、すべての合計`n`≤ 2000) の場合、テスト ケースごとに O(n²) の複雑さのアルゴリズムを検討できますが、これより大幅に遅いものは遅すぎます。 出力にはモジュラー演算が必要であり、有理数をモジュラー逆数として処理する必要があるため、オーバーフローを避けるために慎重に行う必要があります。 

エッジケースには、次のような状況が含まれます。`m = n`つまり、ボブは常に追加する必要があるため、アリスは単純に毎ターン最大化します。 もう一つのエッジケースは、`k = 0`、これはアリスの選択を矮小化します。 小さい`n`または`m = 1`最適なスコアが整数ではない場合、小数点以下の結果が得られる可能性があるため、これらは重要です。 

## アプローチ

 ブルートフォースアプローチでは、アリスの数字とボブの応答のすべてのシーケンスをシミュレートし、考えられるすべての戦略ペアのスコアを計算しようとします。 これには探索が必要になります`O((k+1)^n)`可能性があり、中程度の人でも明らかに実行不可能です`n`。 ブルート フォースはすべてのオプションを評価するため、概念的には正しいですが、組み合わせ爆発により機能しません。 

重要な洞察は、ゲームの構造を観察することで得られます。どの時点でも、ボブはスコアを最小化する操作を選択します。 ボブは少なくとも追加する必要があるため、`m`アリスが大きな数字を選択すると、ボブの柔軟性が制限されることがあります。 慎重に推論すると、ゲームは組み合わせ和の問題に帰着することがわかります。アリスは選択する必要があります。`k`すべてのターンでスコアが決まり、ボブが減算できるターンの割合と加算しなければならないターンの割合によって決まります。 より正式には、期待される最適スコアは次のように表すことができます。```
score = k * (2^(n-1) - 2^(n-m-1)) / 2^(n-1)
```これは、ボブが追加を強制されるシーケンスの数を数えることと、組み合わせの重みを使用することから生じます。 この式には分数が含まれており、出力要件を満たすために逆モジュラーに変換します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((k+1)^n) | O(n) | 遅すぎる |
 | 組み合わせ公式 | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`各テストケースの読み取りを繰り返します`n`、`m`、 そして`k`。 
2. 最初に単純なケースを処理します。 もし`m = n`, ボブはすべての数字を加算する必要があります。 アリスが選ぶ`k`各ターンのスコアは`n * k % MOD`。 
3. もし`m < n`、最適なスコアを表す分数の分子と分母を計算します。 分子は`2^(n-1) - 2^(n-m-1)`、分母は`2^(n-1)`。 これらは、シーケンスの加重和を表す 2 の累乗です。 
4. 分数を掛ける`k`そしてモジュロに変換します`MOD`モジュラーインバースを使用します。 パイソンの`pow(a, b, MOD)`負の指数またはフェルマーの小定理を使用して計算できます`denominator^-1 % MOD`。 
5. 最終スコアのモジュロを出力します。`10^9 + 7`。 

機能する理由: ゲームの組み合わせ構造により、アリスの最適な戦略は常に最大の数を選択することになります。 ボブの制約により、減算オプションは残りのターンに制限され、分数式はスコアにプラスに寄与するシーケンスをカウントします。 モジュラー演算により、モジュロでの正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        if m == n:
            print(k * n % MOD)
            continue
        pow2 = [1] * (n + 1)
        for i in range(1, n + 1):
            pow2[i] = pow2[i-1] * 2 % MOD
        numerator = (pow2[n-1] - pow2[n-m-1]) % MOD
        denominator_inv = pow(pow2[n-1], MOD-2, MOD)
        ans = numerator * denominator_inv % MOD * k % MOD
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは 2 のべき乗を法的に計算します。`MOD`シーケンスを効率的に処理します。 分子は好ましい結果を数え、分母はその分数を正規化します。 モジュラー逆関数は浮動小数点演算を回避し、結果が正しいモジュロであることを保証します。`10^9 + 7`。 コードはこのケースを明示的に処理します`m = n`組み合わせ分数でのゼロによる除算を避けるため。

 ## 特殊なケース

 いつ`m = n`, ボブはすべての数字を足さなければなりません。 入力用`3 3 2`、アリスが選ぶ`2`各ターン。 ボブがすべてを追加すると、スコアは次のようになります。`3*2 = 6`。 アルゴリズムが検出するのは、`m = n`そして戻ってきます`n*k`直接。 

いつ`k = 0`, アリスはゼロしか選べません。 入力用`5 1 0`、スコアは関係なくゼロです。`m`。 アルゴリズムは分子と分母をゼロとして正しく計算し、ゼロを出力します。 

スコアが分数の場合、モジュラー反転によって除算が処理されます。 入力用`6 3 10`、分数は`24/32*10 = 7.5`。 コンピューティング`(24 * pow(32, MOD-2, MOD) * 10) % MOD`与える`375000012`これにより、アルゴリズムがモジュロ演算の下で非整数スコアを正しく処理することが確認されます。
