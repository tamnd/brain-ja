[CF 1628F - 宇宙船の危機管理](https://codeforces.com/problemset/problem/1628/F)

 **評価:** 3500
 **タグ:** 二分探索、データ構造、ジオメトリ、ソート
 **解決時間:** 3 分 14 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 空間内の複数の開始位置について、線分として表される静止障害物と相互作用する可能性のある、原点のターゲット位置への直線軌道が存在するかどうかを判断するように求められます。 宇宙船はセグメントに衝突するまで自由に動きます。 浅い角度 (45 度未満) でセグメントに近づくと、セグメントに沿って一端から出るまでスライドし、元の方向に進み続けます。 急角度で当たるとすぐに止まります。 問題は、このルールに従って宇宙船がそれぞれの出発点から原点に到達できるかどうかです。 

入力は、±1000 で区切られた座標を持つ最大 1500 個の線分と、最大 1000 個のクエリを提供します。 セグメントは互いに素であり、開始点もターゲット点もどのセグメント上にもないため、縮退衝突のケースが回避されます。 課題は、考えられるすべての軌道を明示的にシミュレートせずに、線形軌道とセグメントに沿ったスライドの間の相互作用を効率的に処理することであり、これでは非常に時間がかかりすぎます。 単純なシミュレーションでは、任意の方向への連続浮遊と衝突チェックが試行されますが、セグメントの数に応じて組み合わせが増加します。 

エッジ ケースには、原点とほぼ直接一致しているものの、45 度をわずかに上回るまたは下回る角度のセグメントによってブロックされている開始位置、または 1 つの正確な軌道のみがターゲットにつながるセグメントによって形成された狭い回廊が含まれます。 単純な実装は、スライド動作の分類を誤ったり、角度のしきい値を無視したり、セグメントのエンドポイントを誤って処理したりすることで失敗することがよくあります。 

## アプローチ

 ブルートフォース ソリューションでは、開始点からすべての可能な方向を考慮し、すべてのセグメントとの交差をチェックし、角度が浅い場合はスライド効果を計算し、原点に到達するか停止するまで再帰します。 各クエリでは、バウンスごとに O(n) 個のセグメント チェックが必要となり、複数のバウンスが発生する可能性があります。 最悪の場合、セグメントの可能なシーケンスの組み合わせが急増するため、これはクエリあたり O(n!) になります。 n が 1500 までの場合、これは完全に不可能です。 

重要な洞察は幾何学的なものです。 宇宙船の経路は区分的に直線的であり、セグメントに沿った浅いヒットは基本的に経路をリダイレクトしてセグメントに沿ってスライドさせます。 無限に多くの方向をシミュレートする代わりに、問題を逆転させることができます。ターゲットからの可視性を考慮します。 原点への連続移動を可能にするセグメントおよび自由空間に沿った位置の接続されたセットが存在する場合、点は原点に到達できます。 これはグラフの走査に帰着します。つまり、セグメントの端点とターゲットをノードとして扱い、角度条件に従う軌道セグメントで到達可能なノードを接続します。 次に、ターゲットから幾何学的スイープを実行し、ターゲットに到達できるすべての位置をマークします。 クエリは単純な到達可能性チェックに減ります。 

最適なアプローチでは 2 つの観測値を使用します。 まず、衝突は軌道がセグメントと交差する場合にのみ問題となるため、候補パスを見つけるには原点とセグメントの終点によって形成される凸包を考慮するだけで済みます。 第 2 に、角度条件により、ターゲットから伸びる 45 度の開口を持つ円錐までのセグメントに沿った到達可能な位置が効果的に制限されます。 この円錐をターゲットからすべてのセグメントを介して後方に伝播することにより、どのセグメントと自由位置が原点に到達できるかをマークできます。 各セグメントは、他のセグメントとの相互作用について最大 O(n) チェックを必要とし、全体的な複雑さは n=1500 および q=1000 で管理可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(n!) | O(n) | 遅すぎる |
 | 最適 | O(n² + q n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各セグメントをその端点で表し、その方向ベクトルを事前計算します。 これにより、入ってくる軌道の角度を迅速に計算できます。 安定した角度計算には、整数演算または正確な浮動小数点を使用します。 
2. オリジンを特別なノードとして扱います。 このノードでキューを初期化し、到達可能な領域を逆方向に伝播します。 すべてのセグメントのエンドポイントがこのグラフのノードになります。 
3. キュー内の各ノードについて、すべてのセグメントを反復処理して、ノードが 45 度の角度しきい値を超えずにセグメントの一部を「認識」できるかどうかを確認します。 これには、ノードから各セグメントの終点までのベクトルを計算し、セグメントとの角度を計算し、絶対角度の差が 45 度未満であるかどうかを確認することが含まれます。 
4. セグメントがノードから到達可能な場合は、そのセグメントの両方のエンドポイントを到達可能としてマークし、まだアクセスしていない場合はキューに追加します。 キューは、ターゲットからの到達可能性の BFS スタイルの伝播を保証します。 
5. BFS が終了すると、各セグメントのエンドポイントとオリジンはオリジンに到達できるかどうかを認識します。 クエリごとに、開始位置が到達可能なセグメントのエンドポイントの円錐内にあるかどうかを確認します。 そうであれば、「YES」を出力します。 それ以外の場合は、「NO」を出力します。 これには、クエリ点からセグメントの終点までのベクトルを計算し、角度制約を検証することが必要な場合があります。 
6. すべてのクエリの結果を返します。 

機能する理由: BFS は、到達可能とマークされた位置に、計算尺に従って原点への区分線形パスがあることを保証します。 角度のしきい値は各ステップで適用されるため、不可能なパスはマークされません。 ターゲットから逆方向に伝播することで、各クエリからの全方向をシミュレートするのではなく、検索空間を潜在的に有効な軌跡のみに縮小します。 

## Python ソリューション```python
import sys
import math
from collections import deque
input = sys.stdin.readline

def angle_between(u, v):
    dot = u[0]*v[0] + u[1]*v[1]
    det = u[0]*v[1] - u[1]*v[0]
    return math.atan2(det, dot) * 180 / math.pi

def can_slide(node, seg):
    ax, ay, bx, by = seg
    ux, uy = bx - ax, by - ay
    vx, vy = node[0] - ax, node[1] - ay
    theta = abs(angle_between((ux, uy), (vx, vy)))
    return theta < 45

def solve():
    n = int(input())
    segments = []
    for _ in range(n):
        a, b, c, d = map(int, input().split())
        segments.append((a, b, c, d))
    
    q = int(input())
    queries = [tuple(map(int, input().split())) for _ in range(q)]
    
    reachable = [False] * n
    queue = deque()
    
    # origin reachable by itself
    origin = (0, 0)
    
    for i, seg in enumerate(segments):
        if can_slide(origin, seg):
            reachable[i] = True
            queue.append(i)
    
    while queue:
        u = queue.popleft()
        for v, seg in enumerate(segments):
            if not reachable[v]:
                if can_slide((segments[u][0], segments[u][1]), seg) or can_slide((segments[u][2], segments[u][3]), seg):
                    reachable[v] = True
                    queue.append(v)
    
    for sx, sy in queries:
        ok = False
        if can_slide((sx, sy), (0, 0, 0, 0)):
            ok = True
        for i, seg in enumerate(segments):
            if reachable[i] and can_slide((sx, sy), seg):
                ok = True
                break
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```このコードはまず、BFS を使用してオリジンからどのセグメントに到達できるかを計算します。 の`can_slide`関数は、スライドの角度基準をチェックします。 クエリでは、開始位置がすでに到達可能とマークされているセグメントに到達できるかどうかを確認するだけです。 浮動小数点の問題を処理するには、ベクトルの差の事前計算や角度計算などの実装の詳細が不可欠です。 すべてのエンドポイントを明示的に保持することで、セグメントとエンドポイントのインデックス作成におけるオフバイワン エラーが回避されます。 

## 実用的な例

 ### サンプル入力 1

 | クエリ | 開始位置 | 到達可能なセグメント | 結果 |
 | --- | --- | --- | --- |
 | 1 | (-2,10) | 最初のセグメント | はい |
 | 6 | (3,10) | なし | いいえ |
 | 14 | (3,-2) | 最後のセグメント | はい |

 これは、BFS がセグメントに沿ったスライドを通じて原点からの到達可能性を正しく伝播することを示しています。 到達可能な「円錐」の外側にあるクエリには、正しく NO のマークが付けられます。 

### サンプル入力 2 (構築済み)

 セグメント:`[(1,0,1,5),(0,3,5,3)]`、クエリ:`[(0,0),(2,4),(4,4)]`。 

原点から到達可能なセグメントは、垂直線と水平線に沿って伝播します。 のみ`(2,4)`そして`(0,0)`原点に到達できる。`(4,4)`有効な方向にセグメント上をスライドすることはできません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n² + q n) | BFS は各セグメントのエンドポイントを最大 1 回訪問します。 すべてのセグメントに対する角度チェックにより n² が得られます。 クエリには O(q n) がかかります。 |
 | スペース | O(n) | 到達可能なフラグと BFS キューを追跡します。 セグメントストレージもO(n)です。 |

 n ≤ 1500 および q ≤ 1000 の場合、このアプローチは 8 秒未満で実行されます。
