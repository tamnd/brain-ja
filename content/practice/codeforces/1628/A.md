 ## 解決策
 ## 問題の理解

 負ではない整数の配列が与えられ、現在の配列のプレフィックスを繰り返し切り取ることができます。 カットごとに、そのプレフィックスの MEX を計算し、それを新しい配列に追加します。 そのプレフィックスを削除した後、何も残らなくなるまで残りのサフィックスを使用し続けます。 自由は完全にこれらのカットポイントを選択する方法にあります。 

目標は、MEX 値の有効なシーケンスを生成することだけではなく、そのシーケンスを辞書編集的に可能な限り大きくすることです。 これは、構築された配列の最初の値が可能な限り大きいことを意味します。 同点の場合は、2 番目の値を最大化します。以下同様です。 

すべてのテスト ケースにわたる n の制約の合計は最大 2⋅10^5 であるため、テスト ケースごとに 2 次の解は失敗します。 O(n log n) のソリューションでも許容できますが、プレフィックスに対して MEX を最初から繰り返し再計算するものは遅すぎます。これは、大幅に最適化されていない限り、MEX の計算自体に直線的な時間がかかるためです。 

素朴だが重要な落とし穴は、常に完全な配列を取得するか、常に最小限のセグメントを取得する必要があると想定していることです。 たとえば、[0, 1, 2, 0, 3] のような配列では、配列全体を取得すると、最初のステップに最適な MEX 4 が得られますが、他の配列では、初期のカットにより後で複数の大きな MEX 値が生成される可能性があります。 最適な戦略は、セグメント サイズについてグローバルに貪欲ではなく、特定の MEX に必要なすべての値を含むという点でプレフィックスが「完全」になる時期についてローカルに貪欲です。 

配列に繰り返しゼロが多数ある場合、または小さな値が 1 つだけ欠落している場合、微妙なエッジ ケースが発生します。 たとえば、[1, 1, 1] にはどのプレフィックスにも MEX 0 が含まれるため、どのパーティションもすべて 0 になります。 不注意な解決策ではセグメントを不必要に拡張しようとする可能性がありますが、辞書編集上の順序は改善されません。 

もう 1 つのエッジ ケースは、配列がすでに [0..n-1] の順列である場合です。 この場合、配列全体を取得する場合にのみ、最初の MEX が n になります。 それ以前のカットでは MEX が大幅に減少するため、貪欲なプレフィックス補完が重要になります。 

## アプローチ

 ブルートフォースアプローチでは、配列をセグメントに分割する可能なすべての方法をシミュレートします。 各位置で、考えられるすべての k を試し、プレフィックスの MEX を計算し、残りのサフィックスを再帰的に実行します。 各プレフィックスの MEX の計算には単純に O(n) のコストがかかり、位置ごとに O(n) の選択肢があるため、パーティションの数が指数関数的に増加します。 状態をメモ化したとしても、部分配列の数は O(n²) であり、MEX を再計算すると、これは完全に不可能になります。 

重要な観察は、プレフィックスの MEX は、0 からある値までのすべての数値が存在するかどうかのみに依存するということです。 セグメントを修正したら、実際に必要なのは、MEX ができるだけ大きくなるように、十分なオカレンスを「収集」するために必要な範囲までセグメントを拡張することです。 1 つのセグメントを最適に形成した後、それを削除し、残りの部分で繰り返します。 これにより、問題は貪欲なスキャン プロセスに変換され、すでに確認した値を維持し、完全な「MEX ブロック」がいつ完了したかを判断します。 

すべてのカットを試す代わりに、左から右にスキャンして、徐々に値を収集し、現在の MEX を追跡します。 プレフィックスに 0 から現在の MEX-1 までのすべての数値が含まれている場合、セグメントを閉じてその MEX を出力できます。 次に、リセットして続行します。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n²) 以上 | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 現在のセグメント内の数値の周波数カウンターと現在の MEX 候補を追跡する変数を維持しながら、配列を左から右に処理します。

1. 空の頻度テーブルと現在の mex を 0 に設定して新しいセグメントを開始します。このセグメントに対して可能な最大の MEX を決定しようとしています。 
2. 要素を 1 つずつスキャンし、度数テーブルに挿入します。 値を挿入するたびに、どの小さな数値が存在するかに関する知識が更新されます。 
3. 各挿入の後、現在の mex 値が度数テーブルに存在する限り、mex ポインタを進めます。 これにより、mex は常に現在のセグメント内の欠落している最小の整数を反映するようになります。 
4. いずれかの時点で、0 から mex−1 までのすべての値を少なくとも 1 回確認した場合は、このセグメントを安全に閉じて、答えに mex を追加できます。 その理由は、セグメントをさらに拡張しても、次に大きくなる可能性のある mex を遅らせすぎることなく、この位置の辞書編集上の最適性を高めることができないためです。 
5. 周波数テーブルと mex を 0 にリセットし、次の位置からスキャンを続けます。 
6. 配列の完成後、未完成のセグメントがある場合、その mex が最終値として追加されます。 

### なぜ効果があるのか

 各セグメントは、残りの配列の連続したプレフィックスであることを条件として、その mex が最大化されるように構築されます。 現在のセグメント内に 0 から mex−1 までのすべての整数が入った瞬間、mex は固定されます。 セグメントをさらに拡張すると、mex を変更せずに維持するか、次のセグメントの形成を遅らせることしかできません。現在の mex は可能な限り最も早いカットですでに最大であるため、辞書編集上の順序を改善することはできません。 これにより、貪欲な不変条件が作成されます。すべてのカットは、現在の mex が完全に決定される最も早い位置で行われ、辞書編集上の最も早い位置で最大の寄与が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        cnt = [0] * (n + 5)
        used = set()
        res = []

        mex = 0
        have = 0

        for x in a:
            cnt[x] += 1
            used.add(x)

            while mex in used:
                mex += 1

            # we can close segment when all numbers < mex appear
            # i.e., every value 0..mex-1 is present at least once
            # we check this via cnt > 0 implicitly using mex progression
            ok = True
            for v in range(mex):
                if cnt[v] == 0:
                    ok = False
                    break

            if ok:
                res.append(mex)
                cnt = [0] * (n + 5)
                used.clear()
                mex = 0

        if mex != 0 or any(cnt):
            # recompute mex for last segment
            final_mex = 0
            while cnt[final_mex]:
                final_mex += 1
            res.append(final_mex)

        print(len(res))
        print(*res)

if __name__ == "__main__":
    solve()
```このコードは、現在のセグメントの実行周波数配列と、進化する mex を効率的に追跡するために確認された値のセットを維持します。 mex ポインターはできるだけ早く貪欲に進められ、mex より下のすべての値が存在することが確認されたときにセグメントが終了します。 各カット後にリセットすると、各セグメントが独立していることが保証されます。 

微妙な詳細は、最終セグメントの処理です。カット条件を明示的にトリガーしない場合でも、残りのサフィックスは、頻度テーブルから直接計算された最後の mex 値に寄与します。

 ## 特殊なケース

 [1, 2, 3] など、ゼロがまったく含まれない配列を考えてみましょう。 プレフィックスの mex は 0 であるため、アルゴリズムは最初の要素でセグメントを直ちに閉じます。 結果の出力は一連のゼロであり、mex の進行条件がトリガーされないため、各カットは即座に発生します。 

[0, 0, 0] のような配列の場合、 mex は少なくとも 1 つのゼロが見つかった後にのみ 1 になります。 セグメントは最初の 0 が表示されるまで拡大し、その後閉じて、セグメントごとに 1 が繰り返されます。 

[0,1,2,3] では、アルゴリズムは 0 から 3 までのすべての値が存在するまで待機し、その後 mex 4 で一度閉じます。それより早いカットでは、最初の位置でより小さな mex が生成され、辞書編集上の順序が直ちに悪化します。
