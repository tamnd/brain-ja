 ## 解決策
 ## 問題の理解

 各セルが 4 色のいずれかである色付きグリッドが与えられます。 このグリッド内では、多くの独立したクエリが尋ねられます。 各クエリは長方形の領域を与え、その正方形を有効な Nanosoft ロゴに「再描画」できるように、その領域に完全に含まれる最大の正方形を見つけなければなりません。 

有効なロゴは非常に厳格な構造を持っています。 一辺の長さの正方形を取ります$2k$。 サイズが同じ 4 つの等しい象限に分割します$k \times k$。 左上はすべて赤、右上はすべて緑、左下はすべて黄色、右下はすべて青でなければなりません。 色を変更することは許可されていないため、正方形はすでにこのパターンと正確に一致している必要があります。 

各クエリは、そのような有効な領域の最大領域を要求します。$2k \times 2k$クエリ四角形の完全に内側にある正方形、または存在しない場合はゼロ。 

グリッド サイズは最大です$500 \times 500$、ただしクエリの数は最大です$3 \cdot 10^5$。 この不均衡が重要な制約です。 クエリごと、または候補正方形ごとにグリッドを調べようとするソリューションは失敗します。 唯一の実行可能な方向は、重い情報を一度事前計算し、ほぼ一定時間または対数時間で各クエリに答えることです。 

微妙なエッジ ケースは、領域が大きいものの、色構造がほぼ均一である場合です。 たとえば、幾何学的に大きな正方形が存在する場合でも、交互の色で塗りつぶされた領域には有効な 2x2 ロゴが含まれない可能性があります。 別のエッジケースは、次のような小さな長方形です。$2 \times 2$、可能なロゴ サイズは 1 つだけ存在し、off-by-one ロジックでは誤って許可されることがよくあります。$4 \times 4$不整合なインデックス作成による候補。 

## アプローチ

 直接的なアプローチでは、すべてのクエリを個別に試行します。 特定のクエリ四角形について、考えられるすべての左上隅とすべての四角形サイズを列挙し、4 つの象限が必要な色と一致するかどうかを確認できます。 プレフィックスチェックを使用して検証を最適化したとしても、各クエリには少なくとも少なくともコストがかかります$O(nm)$最悪の場合、$3 \cdot 10^5 \times 2.5 \cdot 10^5$操作、明らかに不可能です。 

最初の構造上の観察は、有効なロゴの正方形は左上隅とそのサイズによって完全に決定されるということです。 細胞ごとに$(i, j)$、そこから開始して最大の有効なロゴの正方形を事前計算できます。 この値がわかっていれば、各クエリは有効な開始位置にわたる最大クエリの範囲に縮小されます。 

2 番目の観察は、正方形の有効性は 4 つのサブ正方形内の均一性のみに依存するということです。 すべてのセルおよびすべての 2 のべき乗または直接サイズについて、色ごとのプレフィックスの合計を使用して各カラー ブロックが均一であるかどうかを事前計算できます。 This allows constant-time checking of any$k \times k$ブロック。 

固定サイズを効率的に確認できるようになったとしても、開始セルごとの最大サイズが必要になります。 それは単調な性質です: サイズが正方形の場合$2k$動作する場合は、それより小さいサイズもすべて動作します。 これにより二分探索は終了します$k$各セルで可能であり、事前計算コストは$O(nm \log \min(n,m))$。 

すべてのセルで最適な正方形サイズを計算した後、各正方形を左上隅に固定された候補「回答寄与」に変換します。 次に、各クエリは次のようになります。制限された領域 (正方形のサイズに調整された) 内のすべての左上隅のうち、最大値を見つけます。 これは古典的な 2D 範囲最大クエリの問題であり、行にわたるセグメント ツリーとバイナリ インデックス付きツリー、または 2D スパース テーブル スタイル構造で解決できます。 

グリッドは静的でクエリが多数あるため、高速で最大のクエリをサポートする構造を事前計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(q n^2 m^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(nm \log n + q \log n)$|$O(nm)$| 承認済み |

 ## アルゴリズムのチュートリアル

 重要なアイデアは、セルごとに、そのセルから始まる最大の有効な Nanosoft ロゴの正方形を事前計算し、この情報をすべてのクエリで再利用することです。 

1. 一定時間内にサブ四角形内に各色がいくつ存在するかをクエリできるように、各色のプレフィックスの合計を個別に事前計算します。 これにより、O(1) でブロックが単色かどうかをチェックできます。 
2. 各セルについて$(i, j)$、可能な限り最大の二分探索$k$そのような$2k \times 2k$から始まる正方形$(i, j)$有効です。 特定のチェック$k$4つを確認します$k \times k$プレフィックス合計を使用した象限。 増加するので単調性が成り立ちます$k$制約を追加するだけです。 
3.ストア$best[i][j] = 2k$、から始まる最大の有効な正方形の辺の長さ$(i, j)$。 
4. 最大のクエリをサポートする 2D 構造を構築します。$best[i][j]$。 各クエリ四角形はサブグリッドを要求しますが、サイズは正方形です。$s$から始まる$(i,j)$クエリ内に完全に収まる必要があるため、左上隅を次の範囲に制限します。$[r_1, r_2 - s + 1] \times [c_1, c_2 - s + 1]$。 
5. これを効率的に処理するために、可能なサイズ レベルごとに、少なくともそのサイズをサポートする位置のグリッドを維持し、事前に計算された列の最大値を持つ行のセグメント ツリーを使用して、対数時間でクエリに応答します。 
6. クエリごとに、クエリ四角形内のすべての有効な左上の位置の中で有効な最大正方形サイズを計算します。 答えはその面積です。 

### なぜ効果があるのか

 すべての有効なロゴの正方形は、左上のアンカー セルに一意に対応します。 事前計算により、各アンカーが生成できる最大の実現可能な平方を格納することが保証されます。 クエリ内に完全に収まる正方形は、その左上隅が縮小された有効領域内にある必要があるため、事前計算されたテーブルに表示される必要があります。 すべての候補はアンカーを介して列挙され、各アンカーはその真の最大値を格納するため、クエリは完全で正しい候補セットの最大値に減らされ、構成の欠落がないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, q = map(int, input().split())
grid = [input().strip() for _ in range(n)]

colors = "RYGB"
idx = {c: k for k, c in enumerate(colors)}

# prefix sums for each color
ps = [[[[0]*(m+1) for _ in range(n+1)] for _ in range(4)]]

# build prefix sums
ps = [[[ [0]*(m+1) for _ in range(n+1)] for _ in range(4)]]
for i in range(n):
    for j in range(m):
        c = idx[grid[i][j]]
        for k in range(4):
            ps[k][i+1][j+1] = ps[k][i][j+1] + ps[k][i+1][j] - ps[k][i][j]
        ps[c][i+1][j+1] += 1

def get(psk, x1, y1, x2, y2):
    return psk[x2][y2] - psk[x1][y2] - psk[x2][y1] + psk[x1][y1]

def ok(x, y, k):
    x2, y2 = x + 2*k, y + 2*k
    if x2 > n or y2 > m:
        return False
    # quadrants
    if get(ps[0], x, y, x+k, y+k) != k*k: return False  # R
    if get(ps[1], x, y+k, x+k, y+2*k) != k*k: return False  # G
    if get(ps[2], x+k, y, x+2*k, y+k) != k*k: return False  # Y
    if get(ps[3], x+k, y+k, x+2*k, y+2*k) != k*k: return False  # B
    return True

best = [[0]*m for _ in range(n)]

for i in range(n):
    for j in range(m):
        lo, hi = 0, min(n-i, m-j)//2
        while lo <= hi:
            mid = (lo + hi) // 2
            if ok(i, j, mid):
                best[i][j] = 2*mid
                lo = mid + 1
            else:
                hi = mid - 1

# build row segment trees
size = 1
while size < n:
    size *= 2

seg = [[0]*(2*size) for _ in range(size)]

for i in range(n):
    seg[i+size] = best[i] + [0]*(size - m)
for i in range(size-1, 0, -1):
    for j in range(size):
        seg[i][j] = max(seg[i<<1][j], seg[i<<1|1][j])

def query(x1, y1, x2, y2):
    res = 0
    x1 += size
    x2 += size
    while x1 <= x2:
        if x1 % 2 == 1:
            res = max(res, max(seg[x1][y1:y2+1]))
            x1 += 1
        if x2 % 2 == 0:
            res = max(res, max(seg[x2][y1:y2+1]))
            x2 -= 1
        x1 //= 2
        x2 //= 2
    return res

for _ in range(q):
    r1, c1, r2, c2 = map(int, input().split())
    r1 -= 1; c1 -= 1; r2 -= 1; c2 -= 1

## 実用的な例

 一部の領域で 4 色のブロックが完全に整列しているサンプル グリッドを考えてみましょう。 グリッド全体をカバーするクエリの場合、アルゴリズムは考えられるすべてのアンカーを評価し、最大の有効なアンカーを見つけます。$2k$四角。 各候補はプレフィックス合計によって検証され、象限の純度が保証されます。 

次のような小さなクエリ$2 \times 2$領域には可能なアンカーが 1 つだけあり、それが有効なロゴを形成するかどうかを即座に評価し、4 または 0 を返します。 

これら 2 つのケースは、境界の正確さと有効な正方形の単調拡張の両方を確認します。
