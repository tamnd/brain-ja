 ## 解決策
 ## 問題の理解

 同じ長さの 3 つの文字列が与えられています。 これらは、3 行の文字が列に並んでいると考えてください。 各列位置で実行できる操作は 1 つだけです。3 番目の文字列の文字を選択して最初の文字列の文字と交換するか、2 番目の文字列の文字と交換します。 他の操作は許可されず、すべての列が独立して処理されます。 

位置ごとに 1 回の交換を実行した後の目標は、1 番目の文字列と 2 番目の文字列が同一になることが可能かどうかを判断することです。 

重要なポイントは、各ポジションが分離されていることです。 インデックス i では、トリプルのみを並べ替えます。`(a[i], b[i], c[i])`交換することで`c[i]`他の2つのうちの1つと。 直接交換することは決して許可されていません`a[i]`と`b[i]`。 

制約は小さく、各文字列の長さは最大 100 で、テスト ケースの数は最大 100 です。 これにより、テスト ケースごとに線形または二次を超えるものは直ちに除外されますが、実際には、構造はテスト ケースごとに O(n) の解が期待されることを示唆しています。 

ローカルな選択がグローバルに競合する場合、微妙なエッジケースが発生します。 単純なアプローチでは、貪欲に文字を一致させようとする可能性があります。`a`そして`b`スワップがどのような影響を与えるかを考慮せずに`c`ただし、操作はインデックスごとに独立しているため、このグローバルな推論は不要です。 もう 1 つのよくある間違いは、インデックス間で文字を自由に再配置できると想定していることです。これは、スワップによって位置間で文字が移動されることがないため、誤りです。 

## アプローチ

 強引な解釈では、インデックスごとに、次のいずれかを選択するあらゆる方法が試行されます。`c[i]`と交換します`a[i]`または一緒に`b[i]`。 つまり、ポジションごとに 2 つの選択肢が与えられます。`2^n`合計構成。 構成ごとに、すべてのスワップをシミュレートし、結果が次のとおりであるかどうかを確認します。`a`等しい`b`。 これは正しいですが、指数関数的に増加します。 n = 100 の場合でも、これはまったく実行不可能です。 

重要な点は、実際には最終的な文字列をシミュレートする必要がないということです。 交換後の各位置では、3 つの文字のセットは変更されただけで同じままになります。 したがって、本当の質問はローカルです。最終的な結果が得られるように、各位置に値を割り当てることができるでしょうか。`a[i]`最終値に等しい`b[i]`?

 インデックス i ではトリプルから始まります`(a[i], b[i], c[i])`。 許可されたスワップの後、`c[i]`結局どちらかの立場になる`a[i]`または`b[i]`。 これは、各インデックスで、どの 2 文字が最終となるかを選択していることを意味します。`(a[i], b[i])`ペアになり、残りのキャラクターが新しいキャラクターになります`c[i]`。 

したがって、問題は次のようになります。インデックスごとに、次のような割り当てを選択できるでしょうか。`a[i] == b[i]`配置転換後は？ 

これは、すべてのインデックスについて、両方の共有値として機能する文字をトリプルから選択できることを保証する必要があることを意味します。`a[i]`そして`b[i]`。 ただし、キャラクターをコピーすることはできないので、入れ替えるしか方法はありません。`a[i] == b[i]`両方の位置がそのインデックスで利用可能なマルチセットから同じ文字を取得できるかどうかです。 

したがって、各位置について、次の値が存在するかどうかを確認します。`{a[i], b[i], c[i]}`両方に入れることができる`a[i]`そして`b[i]`有効なスワップを通じて。 これは、構造が矛盾を強制しない限り可能ですが、矛盾は次の場合にのみ発生します。`a[i]`そして`b[i]`調和できない方法で修正されている`c[i]`ヘルパーとして。 

各インデックスは独立しているため、明示的なグローバル取り決めを構築する必要はなく、スワップ ルールに基づいてポジションごとの実現可能性を検証するだけで済みます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 各インデックス i について、トリプルを検査します。`(a[i], b[i], c[i])`。 

目的は、位置 a[i] と b[i] の最終文字を等しくできるかどうかを判断することです。 
2. もし`a[i] == b[i]`の場合、この位置はすでに一貫しており、このインデックスでの平等を強制するためにスワップは必要ありません。 続けます。 
3. もし`a[i] != b[i]`、それなら頼らなければなりません`c[i]`ミスマッチを解消するために。 1 回のスワップ後に両方のポジションを等しくする唯一の方法は、次のとおりです。`c[i]`対立するキャラクターを一方の側に押し込みながら、一方の側に入れ替えることができます`c[i]`、次の場合にのみ効果的に位置合わせを許可します。`c[i]`2 つのターゲットの 1 つを使用可能な方法で照合します。 どちらでもない場合`a[i]`または`b[i]`と交換することで共通の解決された値として機能できます。`c[i]`の場合、このインデックスは構築を完全にブロックします。 
4. すべてのインデックスが実行可能であれば、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

この実装では、位置ごとにローカルな一貫性チェックを行うリニア スキャンが行われます。 

### なぜ効果があるのか

 各操作は単一のインデックスに対して厳密にローカルであり、スワップがインデックス間で相互作用することはありません。 これにより、問題が位置ごとの独立した制約に分解されます。 最終的な文字列を同一にする唯一の方法は、すべての位置でスワップ ルールに準拠した有効なローカル値の割り当てを許可することです。 インデックス間で情報を伝播する操作はないため、すべてのローカル制約を満たすことが必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a = input().strip()
        b = input().strip()
        c = input().strip()
        
        ok = True
        
        for i in range(len(a)):
            if a[i] == b[i]:
                continue
            
            # We need to use c[i] to reconcile mismatch
            # If c[i] matches neither, we cannot fix this position
            if c[i] != a[i] and c[i] != b[i]:
                ok = False
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは各テスト ケースを反復し、各位置を個別にチェックします。 重要な実装の詳細は、不一致条件です。`a[i] != b[i]`、可能な唯一の救助キャラクターは`c[i]`、スワップでは移動のみが許可されるため、`c[i]`他の 2 つの位置のいずれかに移動します。 もし`c[i]`は両方に無関係であるため、スワップ シーケンスは両方の側を等しくすることはできません。 

早期ブレークにより、不可能な位置が見つかるとすぐにテスト ケースの処理が停止されます。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。`a == b`最初から。 The algorithm correctly outputs YES immediately, since every index passes the equality check without needing any help from`c`。 

もう 1 つのケースは、一部のインデックスのみが一致しない場合です。 例えば：```
a = "ab"
b = "ac"
c = "xx"
```インデックス 1 では、`a == b`, なので安心です。 インデックス 2 で不一致が発生し、`c[2]`どちらとも無関係です`a[2]`そして`b[2]`、そのため、アルゴリズムはテスト ケースを拒否します。 単一の不可能な位置が構造全体を無効にすることを反映して、スキャンは早期に停止します。 

3 番目のケースは次の場合です。`c[i]`のいずれかに一致します`a[i]`または`b[i]`。 例えば：```
a = "ab"
b = "ba"
c = "aa"
```インデックス 1 では、不一致が解決されます。`c[1]`マッチ`a[1]`。 At index 2, mismatch is resolved because`c[2]`マッチ`b[2]`。 アルゴリズムは受け入れ、次のことを示します`c`文字をローカルに吸収して再配布できる柔軟な仲介者として機能します。
