 ## 解決策
 ## 問題の理解

 すべてのセルが都市を表す長方形のグリッドが与えられ、各都市には少数の色のいずれかが割り当てられます。 どの都市からでも、ジェイバーは 4 つの隣接するセルの 1 つ、またはグリッド内の現在のセルと同じ色の他のセルに 1 秒以内に移動できます。 

各クエリについて、これらの移動ルールに基づいて、あるセルから別のセルに移動するのに必要な最小時間を計算するように求められます。 

グリッドは 1000 x 1000 までの大きさになる可能性があるため、最大 100 万個のノードが存在します。 色数は最大 40 色ですが、これが重要な構造上の制限です。 クエリの数は 100,000 に達する可能性があり、完全なグリッドでの BFS やダイクストラなどのクエリごとのグラフ検索は直ちに除外されます。 

クエリごとの直接最短パス検索は、最悪の場合、クエリあたり O(nm) 程度のコストがかかりますが、10^5 クエリではまったく実行不可能です。 

単純な推論が失敗する、自明ではない状況が 2 つあります。 

まず、テレポーテーションを「すべての同じ色のノード間の自由なグローバル エッジ」として扱うことは、巨大な接続性を持つグラフを構築することを示唆しています。 クエリごとの BFS は、同じ大きな領域を繰り返し再訪問し、タイムアウトになります。 

次に、テレポートを無視してグリッド隣接のみを使用すると、誤った結果が生成されます。 たとえば、色 5 のすべてのセルがグリッド全体に分散されている場合、色 5 の離れた領域間の移動は事実上瞬時に行われますが、グリッドのみの BFS では長いマンハッタン距離が誤って測定されてしまいます。 

## アプローチ

 ブルートフォース手法では、グリッドを、隣接するセル間のエッジと、同じ色を共有する 2 つのセル間のエッジを持つグラフとして扱います。 ソース セルから、ターゲットに到達するまで BFS を実行できます。 すべての動きには単位コストがあるため、これは正しいです。 問題はエッジの数です。単一のカラー クラスには最大 10^6 のノードが含まれる可能性があり、暗黙的な隣接関係が非常に密になります。 すべてのエッジを明示的に構築しなくても、BFS はクエリごとに大規模な接続コンポーネントを繰り返し走査します。 最大 10^5 のクエリでは、これは実現可能な制限をはるかに超えます。 

重要な点は、色は最大でも 40 色しかないということです。 個々のセルについて繰り返し推論する代わりに、各色がポータル システムとして扱われる構造に問題を圧縮します。 グリッドのエッジは局所的には依然として重要ですが、長距離の移動は色の遷移を通じて発生します。 これは、クエリごとにすべてを再計算するのではなく、グリッドの重要な「インターフェイス」間の最短距離を事前に計算することを示唆しています。 

問題を確認する便利な方法は、各色に対してマルチソース BFS を実行し、すべてのセルから各色の最も近いセルまでの距離を計算することを検討することです。 k が小さいため、色 c ごとに色 c のすべてのセルから開始して BFS を同時に実行する距離テーブルを事前計算する余裕があります。 これにより、任意の位置から色 c のセルに到達するための最小グリッド距離が得られます。 

これらの距離がわかると、u から v までのパスは 3 つの部分に分解できます。u から選択した色 c のセルへの移動、色 c 内でテレポート (コスト 0)、そして色 c のセルから v への移動です。したがって、答えは、dist(u, c) + dist(v, c) のすべての色 c にわたる最小化になります。 また、c が u または v の色と等しい場合に暗黙的に取得される直接グリッド距離も含まれます。 

これにより、各クエリが最大 40 色をスキャンするようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース BFS | O(q・nm) | O(nm) | 遅すぎる |
 | カラーごとのマルチソース BFS + クエリ スキャン | O(k・nm + q・k) | O(k・nm) | 承認済み |

 ## アルゴリズムのチュートリアル

1. グリッドを読み取り、すべてのセルを色別にグループ化します。 各色が BFS ソース セットとして機能するため、このグループ化が必要です。 
2. 1 から k までの色 c ごとに、色 c のすべてのセルが最初は距離 0 のキューにあるマルチソース BFS を実行します。BFS は 4 方向の隣接によって拡張されます。 結果は距離配列 dist_c[x][y] で、色 c のセルに到達するために必要な最小グリッド ステップが格納されます。 
3. これらの k 個の距離グリッドを保存します。 各 BFS は独立していますが、すべてが同じグリッド構造と移動ルールを共有します。 
4. エンドポイント u および v を持つ各クエリについて、テレポーテーションを無視する場合、答えをマンハッタンの最短パスとして初期化します。テレポーテーションは、同じ色のソースを介して BFS レイヤーによって暗黙的にすでにカバーされています。 
5. 次に、すべての色について繰り返します。 色ごとに dist_c[u] + dist_c[v] を計算し、最小値で答えを更新します。 
6. 各クエリの最終最小値を出力します。 

カラー反復が機能する理由は、テレポーテーションによりどこにでもカラーを「入力」し、そのカラー クラス内に瞬時にジャンプできるため、すべての最適なパスが最大 1 つのカラー遷移点を通過すると想定できるためです。 

### なぜ効果があるのか

 有効なパスはすべて、カラー クラス内でグリッドの移動と瞬間的なジャンプを交互に繰り返すものとして見ることができます。 u から v への最適なパスを検討します。テレポーテーションを使用する場合、ある時点でカラー クラス c に入り、おそらく後で終了します。 テレポートによって色内横断のコストがなくなるため、色 c 内のすべての動きを 1 つのイベントに圧縮できます。 したがって、最適な戦略は、色 c を選択し、u からその色の任意のセルに到達し、さらにその色から v に到達するコストを最小限に抑えることと同じです。BFS の前処理により、これらのエントリ コストがグリッド グラフ内の正確な最短パス距離であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, k = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    pos = [[] for _ in range(k + 1)]
    for i in range(n):
        for j in range(m):
            pos[grid[i][j]].append((i, j))

    INF = 10**18
    dist = [[[INF] * m for _ in range(n)] for _ in range(k + 1)]

    for c in range(1, k + 1):
        q = deque()
        seen = [[False] * m for _ in range(n)]

        for (i, j) in pos[c]:
            dist[c][i][j] = 0
            q.append((i, j))
            seen[i][j] = True

        while q:
            x, y = q.popleft()
            for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nx, ny = x + dx, y + dy
                if 0 <= nx < n and 0 <= ny < m and not seen[nx][ny]:
                    seen[nx][ny] = True
                    dist[c][nx][ny] = dist[c][x][y] + 1
                    q.append((nx, ny))

    for _ in range(int(input())):
        r1, c1, r2, c2 = map(int, input().split())
        r1 -= 1; c1 -= 1; r2 -= 1; c2 -= 1

        ans = abs(r1 - r2) + abs(c1 - c2)

        for c in range(1, k + 1):
            d = dist[c][r1][c1] + dist[c][r2][c2]
            if d < ans:
                ans = d

        print(ans)

if __name__ == "__main__":
    solve()
```前処理ステップでは、色ごとに 1 つずつ、k 個の BFS レイヤーを構築します。 各 BFS は、その色の出現までの最短グリッド距離を計算します。 クエリ フェーズでは、単に最良の中間色を評価します。 初期のマンハッタン距離は、フォールバックの上限として機能します。 

唯一の微妙な点は、BFS が同じ色のすべてのセルからマルチソースであることを確認することです。 これがないと、距離は可能な限り最も近いエントリ ポイントではなく、任意の 1 つの代表からの距離を反映することになります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k · n · m + q · k) | k 個の BFS がグリッド上で実行され、さらにクエリごとに k 個のチェックが実行されます。 
| スペース | O(k・n・m) | 色ごとの距離グリッド |

 k ≤ 40 および n·m ≤ 10^6 の場合、前処理は約 4,000 万回の緩和であり、これは快適に適合します。 クエリ作業は k において線形であり、10^5 クエリを効率的に処理します。

        grid = [list(map(int, input().split())) for _ in range(n)]

        pos = [[] for _ in range(k + 1)]
        for i in range(n):
            for j in range(m):

            for (i, j) in pos[c]:

                    nx, ny = x+dx, y+dy
