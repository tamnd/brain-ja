 ## 解決策
 ## 問題の理解

 私たちには、パンのオプションのコレクションが与えられていますが、それらはすべて、限られた共有リソースである生地を消費し、その一部は追加の限られた材料である詰め物も消費します。 各オプションは、固定利益を生み出す 1 単位の製品を生成します。 特別なオプションの 1 つは、生地のみを消費するプレーン製品を表します。 

タスクは、生地の総使用量が所定の予算を超えないよう、また各充填タイプが利用可能な在庫を超えて過剰に使用されないように、各オプションの生産ユニット数を決定することです。 生産されたすべてのユニットはすぐに利益に変換され、残ったリソースは無関係です。 目標は、総利益を最大化することです。 

この構造は基本的に複数のアイテム タイプを備えた境界付きナップザックですが、追加のグローバル リソース制約とタイプごとの複数の独立した容量制限があります。 

制約は小さいため、指数関数的な検索ではなく、動的プログラミングまたは慎重な貪欲な削減アプローチを強く示唆しています。 生地の総数は最大1000個程度、餡の種類は最大10種類です。 この組み合わせは通常、生地の容量に対して DP を余裕があることを意味しますが、タイプごとに可能なすべてのカウントを単純に拡張すると、簡単に数十万の状態に膨れ上がる可能性があるため、各充填タイプをモデル化する方法には注意する必要があります。 

いくつかの特殊なケースは見落とされがちです。 

1 つは、生地あたりの利益の点でフィリング タイプがプレーン オプションよりも厳密に劣っており、フィリングの制約を無視している場合です。 たとえば、プレーンなパンの方が、具材が豊富なパンよりも生地 1 グラムあたりの利益が大きい場合、たとえ具材が豊富であっても、すべての具材のオプションは無関係です。 

もう 1 つは、充填が非常に限られているため、1 個あたりの収益性は高くても、数回しか使用できず、無制限の供給を想定した単純な DP がそれを過剰にカウントしてしまう場合です。 

3 番目の微妙なケースは、生地ごとに最も高い利益を貪欲に優先することで、充填の制約によって将来の高価値の組み合わせが妨げられる可能性があることを無視している場合です。 たとえば、ボリュームたっぷりだが利益の高い商品は、少ないがより効率的な用途のために確保しておいたほうがよい希少な食材を消費する可能性があり、単純に欲張りな注文は失敗する可能性があります。 

## アプローチ

 強引なアイデアは、考えられる各パンをアイテムとして扱い、カウントのすべての組み合わせを試すことです。 各フィリングのタイプ i について、生地と利用可能なフィリングの両方を考慮して、0 から実行可能な最大値までの任意の数を選択できます。 m 種類のすべての組み合わせを試してみると、最大 10 個の変数 (それぞれが最大 100 以上になる可能性があります) にわたるネストされた列挙になります。 枝刈りを行ったとしても、最悪のケースは 100^10 構成程度の組み合わせ爆発に似ており、これはまったく実行不可能です。 

2 番目の単純な改善は、各充填タイプを複数の同一のアイテムに変換し、標準の 0/1 ナップザックを生地の上で実行することです。 これは正確性に関しては機能しますが、各タイプを最大 100 コピーに拡張するとアイテムが約 1000 個になり、1000 容量× 1000 アイテムを超える DP はまだボーダーラインですが許容できるため、制約に違反します。 ここでの本当の問題はパフォーマンスではなく、明確さです。このアプローチでは構造が隠蔽され、最適化について推論するのが難しくなります。 

重要な観察は、m が非常に小さく、最大でも 10 であることです。これは、フィリングの種類を 1 つずつ処理し、生地の容量を超える DP を維持する必要があることを示唆しています。 各タイプについて、可能なすべてのカウントを明示的に拡張する必要はありません。 代わりに、アイテムの数が利用可能な詰め物と生地の消費量の両方によって制限される、境界のあるナップザック遷移として扱います。

各フィリングの種類ごとに、製造できるバンズの最大数は min(ai / bi, n / ci) です。 これにより、タイプごとに自然な境界が与えられるため、各タイプは境界のある項目セットになります。 m が小さいため、境界付きナップザックの標準的な最適化 (通常はカウントのバイナリ分割) を適用できます。これにより、各境界付き項目が O(対数制限) 0/1 項目に変換されます。 これにより、生地の容量を超える標準的なナップザックの問題が軽減されます。 

プレーンなパンは、無制限に供給される単なるアイテム タイプの 1 つであるため、DP での繰り返し遷移として許可するか、または別個の無制限のナップザック ディメンションとして扱うことで処理できます。 n が小さいため、プレーン バンを使用して DP を緩和する 2 番目のループを安全に実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのカウントのブルートフォース列挙 | m 単位の指数関数と限界値 | お(1) | 遅すぎる |
 | すべての項目を展開し、ナップザックを実行します。 O(n × アイテムの合計) | O(n) | 受け入れられたが重い |
 | バイナリ分割 + DP を備えた境界付きナップザック | O(n log 100 × m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. dp[x] が正確に x グラムの生地を使用して達成可能な最大利益を表す DP 配列を構築します。 ゼロである dp[0] を除き、すべての状態を負の無限大に初期化します。 この構造により、正確なリソース使用量を尊重しながら利益を蓄積することができます。 
2. 各充填タイプを個別に処理します。 特定の種類について、充填材の在庫と生地の入手可能性の両方によって制限される、その種類から製造できるバンズの最大数を計算します。 この制限により、不可能な生産数は決して考慮されなくなります。 
3. バイナリ分割を使用して、この有界量を 2 の累乗に分解します。 たとえば、最大 13 個のパンを作ることができる場合、これを 1、2、4、6 と表します。各チャンクは、コストと利益が比例する個別の仮想アイテムになります。 
4. これらの仮想アイテムのそれぞれについて、生地容量の逆順で dp 配列に対して標準の 0/1 ナップサック遷移を実行します。 値が改善される場合は利益を追加することで、dp[j] から dp[j +cost] を更新します。 逆反復により、各項目が最大 1 回使用されるようになります。 
5. 全ての餡を加工した後、プレーンバンズを組み込みます。 在庫制限がないため、無制限のアイテムとして扱い、dp を繰り返し前方に緩和して、生地が許す限り複数回使用できるようにします。 
6. 未使用の生地は許可され、すべてのリソースを正確に消費する必要はないため、最終的な答えはすべての dp 状態の最大値です。 

重要な正確性の特性は、各充填タイプを処理した後、有効なすべての制限された組み合わせの下で、以前に考慮されたタイプのみを使用して、達成可能なすべての利益構成を dp エンコードすることです。 バイナリ分割により、各充填タイプの実行可能なすべてのカウントが、選択された仮想アイテムの合計として表現可能であることが保証され、1 つのタイプの決定が共有生地容量を超えて他のタイプの実現可能性を妨げないため、ナップザック遷移により最適な下部構造が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, c0, d0 = map(int, input().split())
    
    dp = [-10**18] * (n + 1)
    dp[0] = 0

    for _ in range(m):
        a, b, c, d = map(int, input().split())

        max_cnt = min(a // b, n // c)

        k = 1
        items = []
        while max_cnt > 0:
            take = min(k, max_cnt)
            items.append((take * c, take * d))
            max_cnt -= take
            k <<= 1

        for cost, val in items:
            for j in range(n - cost, -1, -1):
                if dp[j] != -10**18:
                    dp[j + cost] = max(dp[j + cost], dp[j] + val)

    # unbounded plain buns
    for j in range(n + 1):
        if dp[j] != -10**18:
            cnt = (n - j) // c0
            dp[j + cnt * c0] = max(dp[j + cnt * c0], dp[j] + cnt * d0)

    print(max(dp))

if __name__ == "__main__":
    solve()
```最初の DP ループは、生地の使用量にわたって実行可能な状態を構築します。 各充填タイプは、境界のある項目のセットに変換されるため、どの状態も成分制限に違反することはありません。 逆反復は、1 回の反復で同じバイナリ チャンクを複数回再利用することを防ぎ、0/1 ナップザック セマンティクスの正確さを維持するため、不可欠です。 

第 2 段階では、コントロールされた方法でプレーンのバンズを貪欲に塗布します。 残りの容量はすべて同一のチャンクでのみ使用できるため、できるだけ多くのプレーン バンズを使用して、各状態を最適な拡張に変換します。 

よくある落とし穴は、プレーンのバンズを分離せずに同じ境界付き DP ループに直接混ぜようとすることです。 これは、完全に境界のないナップザック構造に慎重に変換しない限り、誤った再利用動作につながることがよくあります。

 ## 特殊なケース

 エッジ ケースの 1 つは、フィリング タイプが大量に入手可能であるにもかかわらず、単位当たりの生地の使用量が多すぎる場合です。 その状況でも、バイナリ分割によって項目は生成されますが、DP 遷移が非効率であれば、それらの項目は決して選択されません。 アルゴリズムは、最大化を通じてそれらを自然に除外します。 

もう 1 つの特殊なケースは、すべてのフィリングの種類がプレーンのパンよりも劣っている場合です。 DP は最初にそれらを調査しますが、プレーンパンの最終的な無制限の緩和がすべての州を支配し、正しい答えが保証されます。 

3 番目のエッジケースは、生地が小さく、1 つまたは 2 つのフィリングの種類しか収まらない場合です。 DP は、すべてのタイプを使用する必要があるとは想定していないため、引き続き機能します。 状態は、サイズが大きすぎる組み合わせに対しては到達不可能なコストのままであり、正確性が保たれます。
