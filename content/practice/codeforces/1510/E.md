 ## 解決策
 ## 問題の理解

 重みの行を表す整数のシーケンスが与えられており、特定のルールに従ってシーケンスのバランスをとるこの行に沿った位置を見つけたいと考えています。 具体的には、左側の重みの合計が右側の重みの合計と等しい場合、そのポジションは **均衡点** と呼ばれます。 私たちの仕事は、そのようなポジションをすべて見つけて、存在する場合は報告することです。 

入力はシーケンスの長さで構成されます`n`に続く`n`重みを表す整数。 出力は、平衡点のインデックス (1 から始まる) または`-1`何も存在しない場合。 

制約は中程度です。`n`まで行くことができます`10^5`重みは次のように大きくすることができます`10^9`。 これは、ネストされたループ内のすべてのインデックスのペアを反復するソリューションは、時間がかかりすぎるため、遅すぎることを意味します。`O(n^2)`操作。 必要なのは`O(n)`一般的な 2 秒の制限を下回るアプローチ。 

すべての重みがゼロの場合、明らかではないエッジ ケースが発生します。 この場合のすべての位置は、左右の合計がゼロであるため、技術的には均衡点です。 もう 1 つのエッジ ケースは、シーケンスの長さが 1 で、唯一の位置が自明の平衡点である場合です。 これらの小さな例は、境界を正しく処理しない単純な実装ではつまずく可能性があります。 

## アプローチ

 素朴なアプローチは簡単です。 ポジションごとに`i`、左側のすべての要素と右側のすべての要素の合計を計算し、2 つの合計を比較します。 これは定義に直接従うため機能しますが、すべてのインデックスの合計を計算するとコストがかかります。 それぞれの合計は`O(n)`操作が複雑になるため、`O(n^2)`これは明らかに遅すぎます。`n = 10^5`。 

重要な点は、各ステップで合計を最初から再計算する必要がないことです。 配列の合計を事前に計算すると、任意のインデックスに対して`i`、左側の合計は前の要素の合計です。`i`、右側の合計は、合計から左側の合計から現在の要素を引いたものです。 これにより、配列を 1 回反復して左側の合計を維持し、インデックスごとに一定時間で右側の合計を計算することができます。 これにより、複雑さが軽減されます。`O(n)`。 

ブルートフォースは平衡の定義を直接実装しているため機能しますが、次の場合には失敗します。`n`大きいです。 プレフィックスの合計の維持に関する観察により、左と右の合計を効率的に計算しながら、問題を配列の 1 回のパスに減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | プレフィックス合計 / シングルパス | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列の合計を計算します。 これはすべての重みの合計であり、右側の合計をすばやく計算できるようになります。 
2. 変数を初期化する`left_sum = 0`現在のインデックスの左側にある要素の累積合計を追跡します。 
3. インデックスを使用して配列を反復処理します。`i`:

 - コンピューティング`right_sum`として`total_sum - left_sum - a[i]`。 これは、現在位置の右側にあるすべての要素の合計を表します。 
- もし`left_sum == right_sum`、 報告`i+1`(1 ベースのインデックス) を均衡点として終了します。 
- それ以外の場合は更新します`left_sum += a[i]`次のインデックスに移動する前に現在の要素を含めます。 
4. ループ後に平衡点が見つからない場合は、リターンします。`-1`。 

機能する理由: アルゴリズムは、次の不変条件を維持します。`left_sum`常に、現在のインデックスより前の要素の合計と厳密に等しくなります。 それぞれのステップで、`right_sum`現在のインデックス以降の要素の合計を正確に表します。 もし`left_sum == right_sum`が成立すると、平衡点の定義が満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def find_equilibrium():
    n = int(input())
    a = list(map(int, input().split()))
    total_sum = sum(a)
    left_sum = 0

    for i in range(n):
        right_sum = total_sum - left_sum - a[i]
        if left_sum == right_sum:
            print(i + 1)
            return
        left_sum += a[i]
    print(-1)

find_equilibrium()
```解決策は読むことから始まります`n`そして配列。 合計は 1 回計算されます。 ループは実行を維持します`left_sum`そして計算します`right_sum`総和を使って一定時間で計算します。 印刷には注意が必要です`i+1`この問題では 1 から始まるインデックスが使用されているためです。 更新中`left_sum`条件をチェックした後、合計が常に配列の正しい部分を反映していることを確認します。

 ## 特殊なケース

 単一要素配列の場合`[10]`、アルゴリズムは次のように計算します。`left_sum = 0`そして`right_sum = 0`、を満たす`left_sum == right_sum`、および出力`1`。 すべてゼロの配列の場合`[0, 0, 0, 0]`、最初のインデックスも条件を満たし、出力が得られます。`1`。 どちらのシナリオでも、アルゴリズムが境界を正しく処理し、off-by-one エラーを回避していることが確認されています。 

この社説では、境界条件、不変式、効率的な計算を注意深く管理しながら、プレフィックス合計を使用して解を再導出する方法を読者にガイドしています。
