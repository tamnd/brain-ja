 ## 解決策
 ## 問題の理解

 この問題により、各ノードにラベルがあり、各ラベルが「ガイド」値を表す有向グラフが得られます。 各ノードは、その出力隣接ノードの 1 つに私たちを導くことができます。タスクは、各ノードについて、一連のガイドに従うことで最終的にサイクルまたは終端ノードに到達するかどうか、およびそのパスに沿っていくつの異なるノードが訪問されるかを決定することです。 

正式には、入力は整数です`n`ノード数の場合は整数`m`エッジの数を指定してから、グラフを説明するエッジのリストを取得します。 各ノードには、実質的に発信エッジの選択肢となる「ガイド」があります。 各ノードの出力は、サイクルまたは終了に達するまでのパスの長さです。 ノードがサイクル内にある場合は、サイクルの長さと到達可能なノードが必要です。 

制約は、最大で次のものを持つことができることを意味します。`n = 10^5`ノードと`m = 2*10^5`エッジ、2 秒の制限付き。 これにより、すべてのノードからのすべてのパスを単純にシミュレートするようなアプローチが即座に排除され、最悪の場合 O(n^2) 操作が発生する可能性があります。 

明らかではないエッジ ケースには、自己ループ、切断されたコンポーネント、または複数のサイクルを含むグラフが含まれます。 たとえば、それ自体を指す単一のノードは長さ 1 のサイクルを形成します。再帰を終了するときにノードのみを訪問済みとしてマークする単純な深さ優先検索では、ノードを過剰にカウントしたり、サイクル長を誤って計算したりする可能性があります。 

例:

 入力:```
3 3
1 2
2 3
3 1
```すべてのノードがサイクルを形成します。 出力は、各ノードの長さ 3 のサイクルを示す必要があります。 不用意に実装すると、サイクルを認識せずにパスが 3 で終了すると考える可能性があります。 

## アプローチ

 ブルート フォース ソリューションは、すべてのノードから DFS または BFS を開始し、サイクルまたは行き止まりに到達するまで、パスに沿って訪問したすべてのノードを記録します。 グラフは有限であり、最終的にパスはループするか終了するため、これは正しく機能します。 ただし、大きい場合は失敗します`n`各 DFS は最悪の場合 O(n) に達する可能性があり、これをすべてのノードに実行すると O(n^2) になり、遅すぎます。 

重要な洞察は、**メモ化** と **サイクル検出** を組み合わせて使用​​すると、問題を効率的に解決できるということです。 各ノードの結果は、そこから到達可能なノードにのみ依存します。 結果を遅延計算してキャッシュすることで、すでに処理したノードのパスの再計算を回避します。 さらに、DFS 中にノードを「進行中」および「完了」としてマークすることでサイクルを検出できるため、サイクル長を正確に計算してサイクル内のすべてのノードに伝播することができます。 

サイクル外のノードが最終的にサイクルまたはターミナル ノードにつながるという観察により、各強接続コンポーネント (SCC) を独立して扱うことができます。 メモ化を使用して DFS を実行すると、すべてのノードとエッジが最大でも一定の回数だけ処理されるため、時間計算量は O(n + m) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各ノードからのブルート フォース DFS | O(n^2) | O(n) | 遅すぎる |
 | メモ化とサイクル検出を備えた DFS | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ノードの状態を追跡するために配列を初期化します。`state[node]`未訪問 (0)、訪問中 (1)、訪問済み (2) のいずれかになります。 別の配列`res[node]`各ノードから到達可能なノードの数を格納します。 
2. 各ノードが訪問されていない場合は、DFS を開始します。 ノードを訪問中としてマークします。 
3. DFS 中に、(ガイドで示されているように) ネイバーごとに、未訪問の場合は再帰します。 隣人が訪問している場合、サイクルが検出されます。 サイクルの長さを記録し、サイクル内のすべてのノードにマークを付けます。 
4. 再帰が戻ったら、計算します`res[node]`1 に隣接ノードから到達可能なノードの数を加えたものです。 サイクルが発生した場合は、サイクルの長さをパスに沿ってサイクル内のすべてのノードに伝播します。 
5. ノードを訪問済みとしてマークします。 
6. すべてのノードを処理した後、結果を順番に出力します。 

**機能する理由**: DFS ではすべてのノードが 1 回だけ処理されます。 訪問状態により、サイクルが正しく検出されることが保証されます。 メモ化により、ノードの到達可能数が計算されると、DFS 内のすべての祖先によって再利用されることが保証されます。 各パスは既知の結果を持つノードに到達するかサイクルを検出することによって終了するため、アルゴリズムはノードを過剰にカウントすることはなく、正確性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**6)

def solve():
    n, m = map(int, input().split())
    edges = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        edges[u-1].append(v-1)
    
    state = [0] * n  # 0 = unvisited, 1 = visiting, 2 = visited
    res = [0] * n

    def dfs(u):
        if state[u] == 1:  # cycle detected
            res[u] = 0
            return u, 0  # start of cycle, length
        if state[u] == 2:
            return -1, res[u]

        state[u] = 1
        cycle_start = -1
        cycle_len = 0
        for v in edges[u]:
            start, length = dfs(v)
            if start != -1:
                cycle_len += 1
                if start == u:
                    start = -1
            else:
                cycle_len = max(cycle_len, length)
            cycle_start = start if cycle_start == -1 else cycle_start

        state[u] = 2
        res[u] = cycle_len + 1
        return cycle_start, res[u]

    for i in range(n):
        if state[i] == 0:
            dfs(i)

    print('\n'.join(map(str, res)))

if __name__ == "__main__":
    solve()
```DFS 関数は 3 つのケースを処理します。未訪問ノードは通常どおり再帰し、訪問ノードはサイクルを示し、訪問ノードはキャッシュされた結果を返します。`res[u]`から到達可能な個別のノードの数を累積します。`u`、サイクルまたは終端パスを介して。 深いパスを処理するために、再帰制限が増加しました。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | DFS では各ノードが 1 回訪問され、各エッジが 1 回横断されます。 
| スペース | O(n + m) | グラフの隣接リストと状態/解像度配列 |

 n ≤ 10^5 および m ≤ 2×10^5 の場合、アルゴリズムは 2 秒以内に快適に完了します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    solve()
    return out.getvalue().strip()

# Provided sample: cycle
assert run("3 3\n1 2\n2 3\n3 1\n") == "3\n3\n3", "sample 1"

# Linear path, no cycles
