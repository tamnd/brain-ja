 ## 解決策
 ## 問題の理解

 タイルの列を含むゲームが与えられ、各タイルには正の整数のラベルが付いています。 高橋選手と青木選手の2人が交互にプレーします。 自分の番では、プレーヤーは、セグメント内のすべての数字が 1 より大きい公約数を共有するようにタイルの連続セグメントを選択します。その後、プレーヤーはそのセグメントをボードから削除し、そのセグメント内の数字の合計に等しいポイントを獲得します。 有効なセグメントがなくなるとゲームは終了し、合計が高いプレイヤーが勝ちとなります。 

入力はタイル値のシーケンスで構成されます。 私たちのタスクは、高橋から始めて、両方のプレーヤーが最適にプレーした場合に高橋が達成できる最大スコアを計算することです。 

最初の観察は、入力サイズが最大 50 タイルになる可能性があるということです。 制限時間は数秒なので、これは十分に短いものです。$O(n^3)$アルゴリズムは実現可能かもしれないが、何でも$O(n^4)$それ以上になると危険になります。 

すべてのタイルが素数である場合、エッジ ケースが発生します。 この場合、有効な手は存在せず、最初のプレイヤーのスコアは 0 になります。 もう 1 つの微妙なケースは、すべてのタイルが等しく複合である場合、たとえばすべて 4 である場合です。 その後、最初のプレーヤーはすべてのタイルを一度に削除し、すぐに合計を獲得できます。 隣接するペアのみを調べる単純なアルゴリズムでは、マルチタイル セグメントを見逃す可能性があり、最適なスコアが過小評価される可能性があります。 

## アプローチ

 ブルートフォース手法では、考えられるあらゆる移動シーケンスを再帰的にシミュレートします。 各プレイヤーについて、公約数が 1 より大きいすべてのセグメントを試し、それを削除し、相手のターンに戻ります。 この方法は、考えられるすべてのプレイを探索するので正しいですが、分岐要素は大まかに次のとおりです。$O(n^2)$セグメントの数に応じて、再帰の深さも指定できます。$O(n)$。 と$n = 50$、それは周りにつながります$O(50^{3})$実際にはそれ以上の操作が行われますが、これは限界ギリギリの速度です。 

重要な洞察は、どのセグメントが共通の約数を共有するかを事前に計算することです。 タイル値は最大で$10^6$を使用すると、それらを因数分解したり、gcd を効率的に計算したりできます。 どのセグメントが有効であるかがわかれば、問題は取り外し可能なセグメントを含む配列上でのターンベースの最大合計ゲームに帰着します。 これを動的プログラミングでモデル化できます。 させて`dp[l][r]`現在のプレーヤーがサブ配列に適用できる最大スコア差を保存します。`l`に`r`。 有効なセグメントごとに`[i, j]`内部`[l, r]`、現在のプレーヤーはその合計を取得して減算することができます`dp[l][i-1] + dp[j+1][r]`（相手の反応）差を最大化する。 

これにより、指数再帰は次のように変換されます。$O(n^3)$DPがあるので$O(n^2)$サブ配列と各サブ配列は試行できます$O(n)$セグメント。 gcd を事前計算すると、各セグメントのチェックが実行されます。$O(1)$の代わりに$O(n)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^2) | O(n) | 遅すぎる |
 | 最適なDP | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのセグメントの gcd を事前計算します。`[i, j]`。 のために`gcd[i][j]`、タイルの gcd を格納します`i`を通して`j`。 これにより、セグメントが O(1) で有効かどうかをチェックできます。 
2. 2D DP 配列を初期化する`dp[l][r]`どこ`l <= r`現在の部分配列を表します。`dp[l][r]`高橋が青木に対して達成できる最大得点差を記録する`[l, r]`。 
3. 反復する`length`1から`n`。 各サブ配列について`[l, r]`その長さの場合は初期化します`dp[l][r] = 0`。 
4. 考えられるすべてのセグメントを検討する`[i, j]`内部`[l, r]`。 もし`gcd[i][j] > 1`、そのセグメントの合計を計算します。 プレイヤーはこのセグメントを選択し、対戦相手は残りの左側で最適にプレイします。`[l, i-1]`そして正しい`[j+1, r]`。 アップデート`dp[l][r]`と`max(dp[l][r], sum_segment - dp[l][i-1] - dp[j+1][r])`。 
5. 戻る`dp[0][n-1]`高橋選手の最高得点です。 

アルゴリズムが機能する理由は、`dp[l][r]`プレーヤーが強制できる最大のネットアドバンテージを再帰的に取得します`[l, r]`。 各ステップではすべての有効なセグメントが最適に考慮され、対戦相手の最適な応答を差し引くことでターンベースの戦略が正しく考慮されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))
    
    # Precompute gcd for all segments
    gcd = [[0]*n for _ in range(n)]
    for i in range(n):
        gcd[i][i] = a[i]
        for j in range(i+1, n):
            gcd[i][j] = math.gcd(gcd[i][j-1], a[j])
    
    # DP table
    dp = [[0]*n for _ in range(n)]
    for length in range(1, n+1):
        for l in range(n-length+1):
            r = l+length-1
            for i in range(l, r+1):
                for j in range(i, r+1):
                    if gcd[i][j] > 1:
                        left = dp[l][i-1] if i > l else 0
                        right = dp[j+1][r] if j < r else 0
                        dp[l][r] = max(dp[l][r], sum(a[i:j+1]) - left - right)
    
    print(dp[0][n-1])

if __name__ == "__main__":
    main()
```の事前計算`gcd[i][j]`各セグメントを素早く確認できるようになります。 ネストされたループ`i`そして`j`内部の取り外し可能なすべてのセグメントをスキャンします`[l, r]`。 慎重に境界を処理することで、範囲外のインデックスが作成されないようにします。 の引き算`dp[l][i-1] + dp[j+1][r]`相手の最適な反応をモデル化します。 

## 実用的な例

 入力例:```
4
2 3 4 6
```| l | r | dp[l][r] の計算 |
 | --- | --- | --- |
 | 0 | 0 | セグメント [0,0]、gcd=2>1、sum=2、dp[0][0]=2 |
 | 1 | 1 | [1,1]、gcd=3>1、sum=3、dp[1][1]=3 |
 | 0 | 1 | [0,0]、[1,1] 有効、dp[0][1]=max(2,3)=3 |
 | 2 | 3 | [2,2]=4、[2,3]=4+6 gcd=2>1、dp[2][3]=10 |
 | 0 | 3 | すべての有効なセグメント、[2,3] sum=10 - dp[0][1]=3、dp[0][3]=7 を選択します。 

このトレースは、すべての取り外し可能なセグメントを考慮し、対戦相手の応答を差し引くことによって、DP が最適なスコア差をどのように取得するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^3) | n^2 部分配列 × 部分配列ごとに可能な n 個のセグメント |
 | スペース | O(n^2) | すべてのセグメントの DP テーブル + gcd テーブル |

 n ≤ 50 の場合、50^3 = 125,000 回の演算は容易に制限内に収まり、O(n^2) メモリは無視できます。
