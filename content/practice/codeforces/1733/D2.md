 ## 解決策
 ## 問題の理解

 同じ長さの 2 つのバイナリ文字列が与えられています。 最初の文字列の位置のペアを反転することで、それらの間の不一致を修正できます。 各操作は 2 つの異なるインデックスを選択し、それらの位置で両方のビットを切り替えます。 コストは、選択したインデックスが隣接しているかどうかによってのみ異なります。 隣接するフリップは、隣接しないフリップよりも安価です。 

タスクは、総コストを最小限に抑えながら、これらのペアの反転を使用して最初の文字列を 2 番目の文字列に変換するか、それが不可能であると判断することです。 

実現可能性に関する重要な観察は、パリティから得られます。 すべての演算は正確に 2 ビットを反転するため、次の位置の数は`a[i] != b[i]`常に偶数だけ変化する必要があります。 各操作はペアの不一致を修正または導入するため、最初は不一致位置の合計数が偶数でなければなりません。そうしないと、一連の操作で不一致を完全に除去できません。 これは直ちに必要条件を与えます。 

制約`n ≤ 5000`総和も制限されているということは、テスト ケースごとに O(n²) 個の解は許容されますが、3 次のものは遅すぎることを意味します。 位置の不一致に対する動的プログラミングまたは貪欲なペアリング戦略を期待する必要があります。 

素朴な推論による微妙な失敗例は、不一致の 2 つのインデックスを任意にペアにすることで常に貪欲に不一致を修正できると想定していることです。 コスト構造によって隣接関係が重要になると、この問題は解決されません。 もう 1 つの失敗例は、最も近い不一致を一致させることが常に最適であると仮定していることです。これは、遠く離れた不一致を一緒にペアにすることで、他の場所でより良い構造を可能にすることでコストを削減できる場合があるということを無視しています。 

たとえば、位置に不一致がある場合`[1, 2, 100, 101]`、貪欲な隣接ペアリングでは 2 つのコスト x 操作が行われますが、ペアリング`(1, 100)`そして`(2, 101)`ものによってはもっと安くなるかもしれません`y`、したがって、地域性だけでは十分ではありません。 

## アプローチ

 ブルートフォースアプローチは、不一致のインデックスをペアにして総コストを計算するためのあらゆる方法を検討することです。 あれば`k`不一致がある場合、基本的にそれらをペアで照合し、各ペアに対して隣接するか隣接しないかを選択します。 ペアリングの数は階乗的に増加するため、これは中程度のレベルの人でもすぐに実行できなくなります。`k`。 

不一致の位置のみが重要であることが分かると、構造は単純化されます。 すべてのインデックスを抽出しましょう`p`そのような`a[p] != b[p]`。 各操作で正確に 2 つの不一致が修正されるため、これらすべてのインデックスをペアにする必要があります。 もし`k`奇妙です、答えはすぐには不可能です。 

ここで問題は、コストを最小限に抑えるためにこれらの不一致インデックスのペアを選択することになります。`(i, j)`費用`x`もし`j = i+1`元の配列内、そうでない場合`y`。 

重要な洞察は、直線上の点を照合しており、隣接するインデックスのみが特別に安価なコストを持つということです。 これは、順序付けされた不一致リストに対する DP を示唆しています。 各ステップで、元の文字列内で隣接している場合は現在の不一致を次の不一致と照合するか、コストをかけて後の不一致とペアにします。`y`、中間のものは個別に処理される可能性があります。 

重要な単純化は、非隣接ペアリングのコストは距離には依存せず、隣接ステータスのみに依存することです。 したがって、不一致リスト内で連続していない、または元の配列内で隣接していない 2 つの不一致をペアにすることを選択すると、コストは常に次のようになります。`y`、そして構造は、形成できる隣接する不一致ペアの数を数えることに要約されます。 

したがって、素の隣接不一致ペアの数を最大化したいと考えます。`(i, i+1)`両方の位置が一致しない場合。 このような各ペアは、コストを考慮して最適に解決できます。`min(x, 2y)`それらを個別に処理する場合と比較して、各操作はすでに 2 ビットを反転しているため、実際の比較は、それらを一緒にペアにするか、それぞれを他の位置とペアにするかです。 

より明確なビューは次のとおりです。配列をスキャンし、不一致が見つかるたびに、元の文字列内で隣接している場合は次の不一致と一致させるかどうかを決定します。 それ以外の場合は、他の不一致と組み合わせる必要があり、コストがかかります`y`。 

これは、不一致コンポーネントをカウントし、各実行内で最適なペアリングを決定する貪欲な DP につながります。

 ## アルゴリズムのチュートリアル

 1. 不一致位置のリストを計算します。`a[i] != b[i]`。 このカウントが奇数の場合は戻ります`-1`なぜなら、すべての操作は正確に 2 つの位置を固定し、パリティは変更できないからです。 
2. 不一致の位置を昇順にたどりますが、圧縮されたリスト構造ではなく、元のインデックスの観点から推論します。 現在ローカル隣接不一致ペアを解決しようとしているかどうかを維持します。 
3. インデックスに 2 つの連続した不一致が発生した場合`i`そして`i+1`、ペアリングを検討します。 このペアリングには費用がかかります`x`ただし、外部ペアリングを介して個別に解決する場合と比較します。これには実質的にコストがかかります。`2y`。 それで、私たちは取る`min(x, 2y)`。 
4. 不一致が孤立している（別の不一致に隣接していない）場合は、コストをかけて他の不一致と組み合わせる必要があります。`y`。 このような不一致を蓄積し、後でペアリングすることで貢献します。`y`操作ごとに。 
5. 合計の答えは、すべての隣接する不一致ペアからの寄与を合計し、残りの不一致不一致の半分に次の値を乗じることによって得られます。`y`。 

これが機能する理由は、各プレフィックスを処理した後、解決されたすべての不一致がそのプレフィックス内で最適に完全にペアリングされ、残りの未解決の不一致は外部または将来の不一致とペアリングされなければならず、そのようなペアリングのコストは常に均一であるという不変条件に基づいています。`y`。 コストに影響を与える唯一の構造上の選択は、隣接性を利用するかどうかであり、その決定はローカルであり、互いに素なセグメント間で独立しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x, y = map(int, input().split())
        a = input().strip()
        b = input().strip()

        mismatch = []
        for i in range(n):
            if a[i] != b[i]:
                mismatch.append(i)

        k = len(mismatch)
        if k % 2 == 1:
            print(-1)
            continue

        if k == 0:
            print(0)
            continue

        # try to form adjacent pairs in original array
        i = 0
        used = [False] * n
        cost = 0

        while i < k:
            if i + 1 < k and mismatch[i] + 1 == mismatch[i + 1]:
                cost += min(x, 2 * y)
                i += 2
            else:
                i += 1

        # remaining mismatches handled by y-cost pairing
        # count remaining unmatched mismatches
        # reconstruct which were used in adjacent pairs
        used = [False] * n
        i = 0
        while i < k:
            if i + 1 < k and mismatch[i] + 1 == mismatch[i + 1]:
                used[mismatch[i]] = True
                used[mismatch[i + 1]] = True
                i += 2
            else:
                i += 1

        rem = 0
        for idx in mismatch:
            if not used[idx]:
                rem += 1

        cost += (rem // 2) * y
        print(cost)

if __name__ == "__main__":
    solve()
```コードの最初の部分では、不一致の位置を抽出し、パリティをチェックします。 これにより、コストを推論する前に実現可能性が強制されます。 

貪欲スキャンは、元の文字列内の隣接する不一致を特定します。 このような各ペアは潜在的に安価な操作として扱われますが、コードは直接隣接する操作のコストを正しく比較します。`x`コストがかかる2つの長距離作戦を使用する代替手段`2y`。 

最後に、隣接構造が使い果たされると、残りのすべてのペアリングのコストが均一になるため、残りの不一致は任意にペアリングされます。`y`。 パリティ チェックでは偶数カウントが保証されるため、2 による除算は有効です。

 ## 特殊なケース

 主なエッジケースは、不一致が孤立しているものの、大量に存在する場合です。 たとえば、すべての位置が異なる場合、不一致数は次のようになります。`n`したがって、パリティは問題ありませんが、隣接関係は存在しません。 アルゴリズムはこれを次のように簡素化します。`(n/2) * y`、安価な構造が存在しないため、任意のペアリングに対応します。 

もう 1 つの特殊なケースは、不一致によって連続したブロックが形成される場合です。 のようなブロックで`[i, i+1, i+2, i+3]`、アルゴリズムは隣接関係を貪欲に利用し、ペアリングします`(i, i+1)`そして`(i+2, i+3)`もし`x < 2y`それ以外の場合は、それらを独立したものとして効果的に扱い、使用します`y`ペアリング。 これは、隣接関係を使用する価値があるかどうかという、問題における唯一の意味のある構造的決定を捉えています。
