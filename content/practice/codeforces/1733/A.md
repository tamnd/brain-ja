 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、制限付きのスワップ操作を使用して要素を再配置することができます。 制限は、固定数で割ったときに同じ余りを共有するインデックスの位置のみを交換できることです。$k$。 これにより、配列が次のように分割されます。$k$独立したインデックスクラス:位置$i, i+k, i+2k,\dots$すべてが同じクラスに属しており、スワップを繰り返すことで値を自由に交換できます。 

まで演奏した後、$k$このようなスワップの場合は、任意のブロックを選択します$k$最終配列内の連続する要素を抽出し、それらの合計を計算します。 タスクは、この選択された連続ブロックが最大の合計値を持つように、許可されたスワップを使用して配列を配置することです。 

この操作の構造上の重要な意味は、要素がグローバルに変更可能ではないということです。 各位置クラスは独立して進化するため、大きな値を任意に移動することはできません。 代わりに、各剰余クラスのモジュロ$k$内部で再配置できる小さなマルチセットのように動作します。 

制約は小さいです。$n \le 100$そして$t \le 600$。 これはすぐに次のことを示します。$O(n^2)$または$O(n^3)$テストケースごとのソリューションは安全です。 本当の課題はパフォーマンスではなく、スワップで何が可能になるかを正しくモデル化することです。 

完全な置換自由を仮定すると、微妙な失敗例が現れます。 たとえば、配列全体をソートして最適なウィンドウを選択できると誤って信じている場合、大きな値が存在するにもかかわらず互換性のない残基クラスにロックされている場合に、間違った答えが得られることになります。 いつでも「最大のものをもたらすことができる」と仮定すると、別の間違いが発生します。$k$モジュロ制約を無視して要素を一緒に使用すると、次のような場合に壊れます。$k=2$ここで、偶数インデックスと奇数インデックスは独立したプールです。 

正しいアプローチでは、最終的に選択されたセグメントの各位置は、特定の残基クラスからの要素のみで埋められることを考慮する必要があります。 

## アプローチ

 ブルートフォースビューでは、長さを選択するあらゆる方法が試行されます。$k$許可されたすべてのスワップをシミュレートした後、セグメントを作成します。 スワップでは各剰余クラス内での任意の置換が許可されるため、次のようになります。各クラス内で値を分散するすべての方法を列挙し、すべてのウィンドウを試します。 これは、各クラスが小さいにもかかわらず、最終ウィンドウにわたるクラス間の結合により直接列挙が不可能になるため、組み合わせ的に爆発的に発生します。 

重要な観察は、各モジュロ クラス内のスワップにより、そのクラスが完全に並べ替え可能になるということです。 したがって、各剰余クラスに対して$r$、その値を位置に任意に割り当てることができるマルチセットとして扱うことができます。$r, r+k, r+2k,\dots$。 最終的な配列は任意ではありませんが、各クラスはそれ自体を並べ替える方法を個別に選択できます。 

次に、次の長さの候補ウィンドウを検討します。$k$、位置から開始$s$。 連続するインデックスをステップ実行すると剰余を法的に循環するため、このウィンドウは各剰余クラスから 1 つの要素を正確に選択します。$k$。 だから位置$s+i$常に剰余クラスに対応します$(s+i) \bmod k$。 

したがって、各ウィンドウは各クラスから 1 つの要素を選択しており、これらの選択された代表の合計を最大化したいと考えています。 各クラスは独立して並べ替え可能であるため、残差クラスごとに、最適なウィンドウに参加する位置に可能な限り最良の要素が配置されるようにしたいと考えています。 

完全な配置を構築しようとする代わりに、視点を反転します。残差クラスごとに、その値を降順で並べ替えます。これは、可能な限りより大きな要素を常に早い段階で使用したいためです。 次に、考えられるそれぞれの開始インデックスを検討します。$s$、そのウィンドウ構造に合わせて各クラスから利用可能な最大の未使用要素を選択することにより、達成可能な最良の合計を計算します。 

なぜなら$k \le n \le 100$、残差ごとにソートされたバケットを維持し、各ウィンドウの開始を貪欲にテストすることで、この割り当てを直接シミュレートできます。

 ## アルゴリズムのチュートリアル

 1. 配列を次のように分割します。$k$インデックスモジュロに基づくグループ$k$。 各グループには、自由に値を交換できるすべてのポジションが含まれています。 
2. 各グループを降順に並べ替えて、そのクラス内でどの要素が最も価値があるかを常に把握できるようにします。 
3. 可能な開始インデックスごとに$s$長さの-$k$ウィンドウで、達成可能な最良の合計を計算します。 
4. から始まるウィンドウを計算するには$s$を繰り返します。$k$ウィンドウ内の位置。 
5. ポジションごとに$s+i$、その残基クラスを決定します$r = (s+i) \bmod k$、グループから次に大きい未使用の要素を取得します$r$。 
6. これらの選択した要素を合計して、そのウィンドウのスコアを取得します。 
7. すべての開始位置の最大値を追跡します。 

各クラス内で貪欲な選択が機能する理由は、クラス内ですべての置換が達成可能であるためです。 したがって、ウィンドウ全体で最も「有用な」出現に高い値を割り当てることができます。 

### なぜ効果があるのか

 各剰余クラスは独立した置換空間を形成します。 最終的な配置は、各クラスの順列を選択することと同じです。 あらゆる長さ-$k$window は、固定された循環パターンで各クラスから要素を 1 つだけ選択します。 したがって、ウィンドウを最大化するとは、一貫した割り当て戦略に基づいて各クラスから利用可能な最適な要素を選択することになります。 ソートにより、候補ウィンドウに影響を与える可能性のある大きな要素が、あまり有用でない位置に無駄に配置されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        groups = [[] for _ in range(k)]
        for i, val in enumerate(a):
            groups[i % k].append(val)

        for g in groups:
            g.sort(reverse=True)

        # we will simulate assignment greedily for each possible window
        ans = 0

        for start in range(n - k + 1):
            used = [0] * k
            score = 0

            for i in range(k):
                r = (start + i) % k
                score += groups[r][used[r]]
                used[r] += 1

            ans = max(ans, score)

        print(ans)

if __name__ == "__main__":
    solve()
```これらが自由の真の単位であるため、実装では最初に剰余クラスを構築します。 各グループを降順に並べ替えることで、そのクラスに残っている最適な要素に常にアクセスできるようになります。 

各候補ウィンドウについて、各クラスから 1 つの要素を順番に取得することをシミュレートします。 の`used`array は、各残余クラスからすでに消費された要素の数を追跡するため、異なるウィンドウ位置で同じクラスが繰り返し発生することで値が誤って再利用されなくなります。 

すべての開始位置にわたる外側のループにより、すべての有効なウィンドウが確実に考慮されます。 以来$n \le 100$、この 2 次スキャンで十分です。

 ## 特殊なケース

 最小限のケースが発生するのは、$n = 1, k = 1$。 このアルゴリズムは、単一の値を含む 1 つの剰余クラスを作成します。 並べ替えは何も行わず、唯一のウィンドウがその要素を自明に選択し、正しい出力を生成します。 

すべての要素が同一の場合、すべての剰余クラスには繰り返し値が含まれます。 並べ替えと貪欲な選択では、すべてのウィンドウで同じ合計が得られるため、最大値はすべての開始点で安定しています。 各クラス インデックスは個別にインクリメントされるため、アルゴリズムはオーバーカウントしません。 

いつ$k = n$、各ウィンドウは配列全体です。 各残差クラスには要素が 1 つだけ含まれているため、交換によって意味のある変更は行われません。 このアルゴリズムは 1 つのウィンドウのみを正しく評価し、合計を返します。
