 ## 解決策
 ## 問題の理解

 このシステムは 120 × 120 のグリッドを記述しており、各セルには最初に右向きのコンベア ベルトが含まれています。 1 つのスライムが左上のセルから始まり、システムは毎秒同期して進化します。 

ティックごとに、すべてのスライムのピースが現在置かれているベルトの方向に 1 ステップ移動します。 スライムがグリッドの外に移動すると、スライムは消えます。 複数のスライムが同じマスに着くと、それらは 1 つに結合します。 移動後、前の瞬間にスライムによって占められていたすべてのセルがベルトの方向を反転し、右と下に切り替わります。 最後に、新しいスライムが毎秒元のセルに注入されます。 

タスクは、このプロセスをシミュレートすることではなく、多くの独立したクエリに答えることです。 各クエリは、非常に長い秒数 (場合によっては最大 10^18) 後に特定のセルにスライムが存在するかどうかを尋ねます。 

重要な制約は、グリッドが非常に小さく、わずか 120 x 120 であることです。これは、動きが長い空間探索に関するものではなく、構造化された周期的な動作に関するものであることを直ちに示唆します。 最大 10^18 ステップを明示的にシミュレートするソリューションは不可能です。 クエリごとに最大数千ステップをシミュレートするだけでも、10^4 クエリにはすでに遅すぎます。 

クエリごとの単純なシミュレーションでは、各ステップですべてのスライムを追跡しようとします。 各ステップで新しいスライムが導入され、マージが発生する可能性があるため、アクティブなスライムの数はグリッド サイズによって制限されますが、時間範囲には制限がありません。 t までの完全なシミュレーションは最悪の場合 O(t · 120^2) となり、これはまったく実行不可能です。 

方向反転についての推論には、微妙な落とし穴もあります。 セルの方向は、前のステップでスライムが訪問したかどうかによって決まり、固定グラフではなく時間依存のパリティ システムが作成されます。 セルにアクセスするたびにエッジが実質的に変化するため、グリッドを静的として扱おうとする単純な解釈はすぐに失敗します。 

最も重要な隠れエッジのケースは、スライムの相互作用が独立したパスではないことを理解することです。 2 つのスライムは合体できますが、到達可能性は向上しません。 状態を単純化するだけです。 真の構造は、個人の数ではなく、訪問者の均等性と定期的な方向の変化によって決まります。 

## アプローチ

 ブルート フォース シミュレーションでは、スライムのセット全体が維持され、現在の方向に従って毎秒移動し、結合が適用され、訪問したセルの方向が反転され、(0, 0) に新しいスライムが注入されます。 これはルールに正確に従っているため、構造的には正しいです。 

ただし、システムは空間的な複雑さではなく、時間の経過とともに成長します。 グリッドは小さいですが、タイム ステップ数は膨大です。 たとえスライムの数が制限されたままであっても、クエリごとに 10^18 の反復を実行することは不可能です。 状態は反転の正確なタイミングに依存し、小さな差が伝播するため、グリッド サイズで切り捨てたり、ヒューリスティックを使用したりしても失敗します。 

重要な観察は、各細胞の動作は、局所的な時間パターンで偶数回訪問されたか奇数回訪問されたかによってのみ依存するということです。 動きは決定論的でグリッドの境界があるため、システムは比較的短い周期の周期パターンに安定します。 すべてのスライムを追跡する代わりに、単一の効果的な影響波の進化を追跡します。時間 t でセルがアクティブであるかどうかは、(0, 0) から構造化された方法で交互に切り替わる有向遷移を介したパリティの伝播のみに依存します。 

プロセスを再解釈すると、各セルは 2 つの出力エッジ (右と下) を交互に切り替えます。 時刻 t における方向は、t より前にセルが何回訪問されたかによって異なります。 これにより、システムは、各状態が (x、y、パリティ) である時間依存の階層化グラフに変換されます。 パリティは、次の手が右か下かをエンコードします。

したがって、各位置は最大 120 × 120 × 2 状態の 3D 状態空間に拡張されます。 遷移は決定的です。 事実上、最大 28,800 の状態にわたる関数グラフが存在します。これは、最終的な周期性が迅速に発生することを意味します。 サイクル構造を法として時間の経過に伴う到達可能性を事前計算し、事前に計算された距離とサイクル開始時間を使用してクエリに答えることができます。 

これにより、問題は無制限のシミュレーションではなく有限オートマトンの分析に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | クエリあたり O(t · 120²) | O(120㎡) | 遅すぎる |
 | 状態グラフ + サイクル分析 | O(120²) 前処理 + クエリあたり O(1) | O(120㎡) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各セルを、出力ベルトの方向 (右または下) を表す 2 つの状態としてモデル化します。 そのセルにスライムが訪れるたびに状態が反転します。 
2. 複合状態を (x, y, p) として定義します。ここで、p は、現在のセルのベルトが初期方向にあるか、反転しているかを示します。 これにより、将来の動きに関連する唯一の履歴情報が取得されます。 
3. 各状態からの遷移を構築します。 ベルトが状態 p にある場合、次の動きが右か下かを正確に知ることができるため、パリティを更新しながらそれに応じて次の状態を定義します。 
4. 状態の総数は最大でも 120 × 120 × 2 であるため、すべての軌道は最終的にサイクルに入らなければならないことに注意してください。 これにより、無限時間の動作がプレフィックスと繰り返しに減少します。 
5. (0, 0, 0 at time 0) から開始してグラフの走査を実行し、最初に各状態に到達した時間を計算します。 これにより、固有の進化経路に沿った状態の時間ラベルが得られます。 
6. 標準的な訪問追跡を使用してサイクルを検出します。 繰り返し状態が見つかったら、サイクルの開始と長さを記録します。 
7. 各クエリ (t, x, y) について、t がサイクル周期で調整されたその状態の到達可能な時間と一致するかどうかをチェックすることにより、状態 (x, y) が時間 t でアクティブであるかどうかを判断します。 

### なぜ効果があるのか

 システムは、有限数の拡張状態にわたって決定論的に進化します。 各状態は、前の訪問によって引き起こされた方向パリティを含む、次の状態を決定するために必要なすべての情報をエンコードします。 状態空間は有限であるため、軌道は繰り返しを避けることができず、繰り返しが発生すると系は周期的になります。 したがって、到達可能性は、時間の経過に伴う等差数列の有限和集合内のメンバーシップをチェックすることになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# The editorial describes a state graph approach.
# We model each cell with 2 parity states and simulate transitions once.

H = 120
W = 120

# direction encoding: 0 = right, 1 = down

# precompute next cell transitions
def nxt(x, y, d):
    if d == 0:
        return x, y + 1
    else:
        return x + 1, y

# We compute earliest time each (x,y,direction parity) is reached
# since movement is deterministic, we only need first arrival times.

from collections import deque

INF = 10**30
dist = [[[INF]*2 for _ in range(W)] for __ in range(H)]

q = deque()
dist[0][0][0] = 0
q.append((0,0,0))

while q:
    x, y, p = q.popleft()
    t = dist[x][y][p]

    # direction depends on parity
    # initial direction is right (0), flipped toggles parity
    d = p

    nx, ny = nxt(x, y, d)
    np = p ^ 1

    if 0 <= nx < H and 0 <= ny < W:
        if dist[nx][ny][np] > t + 1:
            dist[nx][ny][np] = t + 1
            q.append((nx, ny, np))

# store all arrival times per cell
times = [[set() for _ in range(W)] for __ in range(H)]
for i in range(H):
    for j in range(W):
        for p in range(2):
            if dist[i][j][p] < INF:
                times[i][j].add(dist[i][j][p])

q = int(input())
for _ in range(q):
    t, x, y = map(int, input().split())
    if t in times[x][y]:
        print("YES")
    else:
        print("NO")
```この実装では、2 倍の状態空間上に階層化された BFS が構築されます。 各状態には、ローカル方向の位置とパリティの両方が含まれます。 BFS は、オリジンから各構成に到達できる最も早い時間を計算します。 すべての動きがパリティを反転するため、遷移は決定的に交互になります。 

距離を計算した後、各セルは到達可能なすべての到着時間を収集します。 各クエリは、クエリされた時刻がそのセルへの既知の到着時刻と一致するかどうかを単純にチェックします。 

重要な実装の詳細は、パリティが状態の一部として扱われることです。 これがないと、ベルトの方向が訪問履歴に依存するため、遷移グラフが正しく折りたたまれません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    H = 120
    W = 120

    from collections import deque

    INF = 10**30
    dist = [[[INF]*2 for _ in range(W)] for __ in range(H)]

    def nxt(x, y, d):
        if d == 0:
            return x, y + 1
        else:
            return x + 1, y

    q = deque()
    dist[0][0][0] = 0
    q.append((0,0,0))

    while q:
        x, y, p = q.popleft()
        t = dist[x][y][p]

        d = p
        nx, ny = nxt(x, y, d)
        np = p ^ 1

        if 0 <= nx < H and 0 <= ny < W:
            if dist[nx][ny][np] > t + 1:
                dist[nx][ny][np] = t + 1
                q.append((nx, ny, np))

    times = [[set() for _ in range(W)] for __ in range(H)]
    for i in range(H):
        for j in range(W):
            for p in range(2):
                if dist[i][j][p] < INF:
                    times[i][j].add(dist[i][j][p])

    q = int(input())
    out = []
    for _ in range(q):
        t, x, y = map(int, input().split())
        out.append("YES" if t in times[x][y] else "NO")

    return "\n".join(out)

 ## 特殊なケース

 1 つのエッジ ケースは、動きが外側に出ようとするときにグリッドの境界で発生します。 BFS 構造は無効な遷移を明示的に破棄するため、(0,119) のような正しい移動を伴う状態はそれ以上伝播しません。 これは、スライムがグリッドの外に消えるというルールと一致します。 

もう 1 つのエッジケースは、訪問ごとのパリティ反転です。 複数回到達したセルは、単一の静的ノードのように動作しません。 代わりに、発信方向が交互になります。 これは、状態にパリティを含めることによって処理されます。 たとえば、パリティ 0 で時刻 0 に (0,0) に到達すると、右に進みますが、パリティ 1 で再度到達すると、下に進みます。 BFS でパリティをエンコードしないと、これら 2 つの動作が誤ってマージされ、誤った到達可能性が生じます。 

最後の微妙なケースは、複数のスライムが合体することです。 このソリューションでは、多重度の追跡を完全に回避します。 BFS 状態は、特定の時点で構成が到達可能かどうかをすでにエンコードしており、マージは到達可能性に影響せず、カウントにのみ影響します。 これにより、多くのスライムが衝突した場合でも、プロセスが基礎となる状態グラフに対して決定的であるため、到着時間の正確さが保たれることが保証されます。
