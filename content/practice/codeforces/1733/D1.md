 ## 解決策
 ## 問題の理解

 同じ長さの 2 つのバイナリ文字列が与えられています。 一度に 2 つの位置を反転する操作を繰り返し適用することができます。つまり、l < r でインデックス l と r を選択し、両方のビットを反転します。 コストは、選択した位置が隣接しているかどうかによってのみ異なります。 隣接するペアはコスト x で高価ですが、隣接しないペアはコスト y で安くなり、x ≥ y が保証されます。 

目標は、総コストを最小限に抑えながら、これらのペアの反転を使用して初期文字列をターゲット文字列に変換するか、それが不可能であると判断することです。 

各操作では 2 ビットが反転されるため、文字列内の 1 の数のパリティは、制御された方法で一度に 0 または 2 ずつ変化します。 より便利なビューは、a と b の間の不一致位置のみに焦点を当てることです。 a[i] が b[i] と異なるすべてのインデックスは、奇数回反転する必要がある位置であり、すべての操作で正確に 2 つの位置が反転されます。 これは、不一致の数が偶数である必要があり、そうでない場合、一連の操作で不一致を修正できないことを直ちに意味します。 

すべてのテストの合計 n が最大 3000 であるため、制約は十分に小さく、テスト ケースごとに O(n^2) または O(n log n) の貪欲または DP アプローチが受け入れられます。これは、ペアの不一致を明示的に安全に考慮できることを示唆しています。 

微妙な失敗のケースは、貪欲なペアリングが誤解を招くような形で不一致がまばらまたは集中している場合に発生します。 たとえば、遠く離れた 1 つを除いてすべての不一致が隣接している場合、貪欲なローカル ペアリングは、より安価な長距離 y ペアを使用する代わりに、x コスト エッジを使用して過大なコストを支払う可能性があります。 

もう 1 つの重要なエッジ ケースは、2 つの別々の長距離ペアを使用する場合と比較して、x が実際には有益ではない場合です。 x ≥ y であるため、隣接するペアリングが単独で優れていることは決してありませんが、将来のペアリングにどのインデックスが利用可能なままになるかに影響するため、構造的に重要になる可能性があります。 

## アプローチ

 まず、a と b 間のすべての不一致インデックスを特定します。 これらがソートされたリスト p に格納されているとします。 各操作はちょうど 2 つのインデックスを反転するため、p 内のすべての要素をペアにする必要があります。 不一致の数が奇数の場合、答えは直ちに不可能になります。 

コストを無視した場合、各インデックスを含める必要があるのは 1 回だけであるため、不一致インデックスの組み合わせは機能します。 したがって、問題は直線上の 2k 点のペアリングに帰着し、元のインデックス順序で j = i + 1 でない限り、i と j のペアリングに y のコストがかかり、その場合は x のコストがかかります。 

ブルートフォースソリューションでは、位置が一致しないすべての組み合わせが試行されます。 これは、サイズ k の完全なグラフ上の完全なマッチング問題ですが、複雑さの要因であり、n = 3000 の場合でも完全に実行不可能です。 

重要な観察は、最適な構造には恣意的なマッチングが必要ないということです。 すべての非隣接ペアのコストは同じであるため、意味のある唯一の違いは、元の配列で隣接する不一致をペアにするかどうかです。 これにより、問題は不一致リスト上の 1 次元の DP に帰着します。 

不一致はソートされた順序で処理されます。 各ステップで、現在の不一致と次の不一致をペアにするか、それを後の不一致と間接的に一致させます。 ただし、すべての非隣接ペアリングは同じコスト y を持つため、最適な戦略は不一致リスト内のローカル隣接構造に対して貪欲になります。 

事実上、不一致リスト内の隣接するペアをコスト x で取得するか、それらを独立した要素として扱い、コスト y で任意の他のペアとペアにするかを決定します。 

これにより、連続する不一致インデックスをペアリングするか、ローカルでペアリングをスキップしてグローバル ペアリングを使用するかを検討する DP が生成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのペアリング) | O((n/2)!) | O(n) | 遅すぎる |
 | 最適な DP / 貪欲なペアリング | O(n) | O(n) | 承認済み |

## アルゴリズムのチュートリアル

 まず、a と b の間の不一致位置のリストを作成します。 このリストを p とする。 

1. a[i] ≠ b[i] であるすべてのインデックス i を計算します。 カウントが奇数の場合は、すぐに -1 を返します。 これは、すべての操作が正確に 2 ビットを反転するため、不一致パリティが偶数でなければならないという事実から導かれます。 
2. コスト アキュムレータをゼロに初期化します。 
3. 不一致リストを左から右にたどります。 位置 i にいるとき、不一致リスト内で p[i] と p[i + 1] が連続している場合は、それらをペアにすることを検討します。 
4. 元の文字列で p[i] と p[i + 1] が隣接している場合、コスト x を使用してそれらをペアにすることを検討します。 ただし、これを、それぞれコスト y を使用して両方を他のインデックスとペアにする代替戦略と比較します。 
5. 決定は、隣接する不一致ペアごとに x と 2y の安い方を選択することに帰着します。 x ≤ 2y の場合、隣接する不一致を貪欲にペアリングします。 それ以外の場合は、隣接するペアの使用を避け、代わりにそれらをグローバルに照合される個別の要素として扱います。 
6. 隣接しない不一致の場合、グローバル マッチングでのペアリングを通じて、それぞれが効果的にコストに寄与します。 
7. それに応じて拠出金を合計し、総コストを返します。 

なぜそれが機能するかは、不一致セットの構造に関係しています。 各不一致は 1 回だけペアリングする必要があります。 すべての非隣接ペアリングは同等であるため、唯一意味のある最適化は、隣接エッジを「消費」するか (コスト x)、2 つの独立したペアリングをシミュレートするか (コスト 2y) です。 コストは隣接を超えた距離に依存しないため、より複雑な再ルーティングには利点がありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x, y = map(int, input().split())
        a = input().strip()
        b = input().strip()

        mismatches = []
        for i in range(n):
            if a[i] != b[i]:
                mismatches.append(i)

        m = len(mismatches)

        if m % 2 == 1:
            print(-1)
            continue

        if m == 0:
            print(0)
            continue

        # We will pair greedily
        cost = 0
        i = 0

        while i < m:
            if i + 1 < m:
                # consider pairing consecutive mismatches
                if mismatches[i] + 1 == mismatches[i + 1]:
                    cost += min(x, 2 * y)
                    i += 2
                    continue

            # otherwise, this mismatch is paired "globally"
            cost += y
            i += 1

        print(cost)

if __name__ == "__main__":
    solve()
```このソリューションでは、不一致の位置のみが重要であるため、最初に不一致の位置を抽出します。 パリティチェックにより実現可能性が保証されます。 

貪欲ループは、不一致のインデックスを順番に処理します。 元の文字列で 2 つの連続した不一致が隣接している場合、それらを直接ペアリングするために x を支払うか、コスト 2y で個別にペアリングをシミュレートするかを決定します。 それ以外の場合、不一致を独立したものとして扱い、それらが他の遠く離れた不一致とペアになることを反映して、それぞれコスト y を割り当てます。 

微妙な部分は、コストを改善できる唯一の構造がローカル隣接であるという前提です。 これは、すべての非隣接ペアリングが均一コストに崩壊するため、利用できる追加の組み合わせ構造がないため当てはまります。 

## 実用的な例

 ### 例 1

 入力:```
5 8 7
01001
00101
```不一致の位置はインデックス 1 と 2、および 4 と 5 にあります (0 ベース: 0,1,3? インデックスによって異なります。内部的には 0 ベースに従います)。 

次のように進めます。 

| ステップ | 考慮される不一致ペア | 状態 | アクション | コスト |
 | --- | --- | --- | --- | --- |
 | 1 | (1,2) | 隣接 | min(8, 14) = 8 | 8 |
 | 2 | (4,5) | 隣接 | min(8, 14) = 8 | 16 |

 ただし、最適なマッチング構造により、必要なペアリングは 1 つだけです。 正しく選択するとコスト 8 が得られます。 

これは、x < 2y の場合、隣接する不一致が最適にペアリングされることを示しています。 

### 例 2

 入力:```
5 7 2
01000
11011
```検査後の構造で不一致の数が奇数であり、1 つの不一致の位置が残っています。 すべての操作で 2 つの位置が固定されるため、それは不可能です。 

| ステップ | 不一致数 | パリティチェック | 結果 |
 | --- | --- | --- | --- |
 | 1 | 奇数 | 失敗 | -1 |

 これは、パリティ不変式が実現可能性のために必要であることを裏付けています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テストあたり O(n) | 文字列を一度スキャンして不一致を収集し、もう一度スキャンしてそれらを処理します。 
| スペース | O(n) | 不一致の位置を保存します |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return sys.stdout.getvalue().strip()

def solve():
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, x, y = map(int, input().split())
        a = input().strip()
        b = input().strip()

        mismatches = [i for i in range(n) if a[i] != b[i]]
        m = len(mismatches)

        if m % 2 == 1:
            out.append("-1")
            continue

        if m == 0:
            out.append("0")
            continue

        cost = 0
        i = 0
        while i < m:
            if i + 1 < m and mismatches[i] + 1 == mismatches[i + 1]:
                cost += min(x, 2 * y)
                i += 2
            else:
                cost += y
                i += 1
        out.append(str(cost))

    return "\n".join(out)

 ## 特殊なケース

 単一の不一致がある入力の場合、奇数のカウントではペアリングが不可能であるため、アルゴリズムはすぐに -1 を返します。 不一致が連続ブロックを形成する入力の場合、決定は、ブロック内の隣接する不一致を x を使用してペアにするか、y コストのペアに分割するかに限定されます。 完全に交互する不一致パターンの場合、隣接関係は存在しないため、解は純粋な y コストの累積になり、グローバル ペアの解釈と一致します。
