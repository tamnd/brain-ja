 ## 解決策
 ## 問題の理解

 頂点 1 がルートであり、各頂点が数値を持つルート付きツリーが与えられます。 頂点ごとに$v$から上に向かうパスを考えます。$v$根元まで。 そのパスに沿って、いくつかの交互合計式を形成します。任意の祖先で停止することができ、値がプラスから始まる符号で交互に合計を計算します。$v$、次に親でマイナス、次に祖父母でプラス、というように続きます。 

タスクは、すべての頂点について、そのようなすべての上向きセグメント間で取得可能な最大値を計算することです。 

これを言い換えると、各頂点がその祖先チェーンに沿ったシーケンスを定義し、そのチェーンの最良のプレフィックスが交互の符号の下に必要になるということです。 

この制約により、どのソリューションもテスト ケースごとに本質的に線形でなければならないことが明確になります。 すべてのテスト ケースにわたる頂点の合計数は次のとおりです。$2 \cdot 10^5$そのため、上向きトラバーサルを使用して頂点ごとに独立して答えを再計算するソリューションは、パスの共有プレフィックスに対して作業を繰り返し、すぐに制限を超えることになります。 ナイーブ$O(n^2)$テストケースごとのアプローチはすでに不可能です。 

各頂点の答えはそのすべての祖先に依存するが、祖先はサブツリー間で共有されるという事実から、微妙な問題が生じます。 各ノードで上向きの合計を最初から再計算する単純な DFS では、同じエッジを繰り返し再利用し、計算が大幅に重複します。 

もう 1 つの落とし穴は、完全なルート パスのみが重要であると想定していることです。 最良の交互合計は、必ずしもルートではなく、任意の祖先で早期に停止する可能性があるため、ルートからノードへの完全な計算に制限すると、有効な候補が失われます。 

## アプローチ

 直接的なアプローチは、各頂点を個別に処理することです。 頂点の場合$v$、親ポインターをたどって、交互の合計を維持し、最大値を追跡します。 これは、許可されているすべてのセグメントを明示的に評価するため、正しいです。 ただし、各ノードに子が 1 つだけある偏ったツリーでは、各クエリは次のようになります。$O(n)$、すべての頂点にわたってこれは次のようになります$O(n^2)$が遅すぎます。 

重要な観察は、交互構造を正規化できるため、問題がルートからノードへのパスに沿った変換されたシーケンスに対する最大サフィックス クエリになるということです。 すべてを最初から再計算するのではなく、ルートから DFS を実行しながら動的な情報を維持します。 

させて$dp[v]$～からの交互の合計を表します$v$固定の符号パターンでルートまで。 これを再帰的に定義して、各ノードが親から一定時間内に構築されるようにすることができます。 これらの値が利用可能になると、次からの交互の合計が得られます。$v$先祖に$u$は、符号調整を行った 2 つのプレフィックスのような値の差になります。 

主な困難は、ノードごとの単一のプレフィックスの合計だけではなく、そのプレフィックス構造のすべてのサフィックスの最大値にも興味があることです。 これは、DFS 中に 2 番目の状態 (トラバース方向の現在のノードで終わる最適な代替サフィックス) を使用して維持できます。 親から子に移動すると、交互の合計と、そのパスでこれまでに確認された最良の値の両方を更新できます。 

これにより、問題がツリー DP に変換され、各ノードがその親から 2 つの値を継承します。1 つは現在の交互の合計を表し、もう 1 つはその上で達成可能な最良の答えを表します。 それぞれの遷移は、$O(1)$なので、ツリー全体が線形時間で処理されます。

 ## アルゴリズムのチュートリアル

 ツリーを 1 にルートし、現在のパスに沿って 2 つの値 (交互のプレフィックス値と現在のノードの最良の回答) を伝えながら DFS を実行します。 

1. ルートに次のような初期代替値を割り当てます。$a_1$、長さ 1 のパスには交互がないためです。 
2. また、ルートの最適値を次のように初期化します。$a_1$、それがルートから始まる唯一の可能なセグメントであるためです。 
3. DFS中、親から移動する場合$v$子供に$u$で交互の値を計算します。$u$親の寄与の符号を反転して追加することにより、$a_u$。 これにより、パスに沿った正しい交互構造が維持されます。 
4. 各ノードについて$u$、親からの最もよく知られているプレフィックス情報を拡張し、それを新たに開始する場合と比較することを考慮して、候補の答えも計算します。$u$。 
5. の答え$u$はこれらの可能性の最大値であり、さらに深く進む前に保存されます。 
6. すべてのサブツリーが正しい履歴に基づいて構築されるように、代替プレフィックス値と最良の回答の両方を子に伝播します。 

重要な設計上の選択は、何も上向きに再計算しないことです。 ノードに必要なすべての値は、親から渡された状態ですでにエンコードされています。 

### なぜ効果があるのか

 ルートからノードへのパスに沿って、ノードで終わるすべての有効な交互セグメントは、その祖先の中からカット位置を選択することに正確に対応します。 DFS 状態は、これらすべてのプレフィックス計算を 2 つの実行値に圧縮します。1 つは現在のノードで終了する交互の合計を追跡し、もう 1 つはそのパス上でこれまでに確認された最良のセグメントを追跡します。 すべてのノードは 1 回訪問され、その状態は親の状態のみに依存するため、候補セグメントが見逃されることはなく、セグメントが二重にカウントされることもありません。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = [0] + list(map(int, input().split()))
        
        g = [[] for _ in range(n + 1)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)
        
        ans = [0] * (n + 1)
        
        def dfs(v, p, cur_alt, best_up):
            ans[v] = best_up
            
            for u in g[v]:
                if u == p:
                    continue
                # child alternation: flip sign relative to parent path
                next_alt = a[u] - cur_alt
                
                # best value either starts new at u or extends path
                next_best = max(a[u], a[u] - cur_alt, best_up)
                
                dfs(u, v, next_alt, next_best)
        
        dfs(1, -1, a[1], a[1])
        print(*ans[1:])

if __name__ == "__main__":
    solve()
```DFS には 2 つの状態が含まれます。 最初、`cur_alt`は、現在のノードで終わる完全なパスの交互の合計を表します。 2番目、`best_up`は、ルートから現在のノードまでのパス上のどこかで終了する最適な交互セグメントを表します。 

子供に移るとき、計算によって記号構造を反転します。`a[u] - cur_alt`。 これが機能するのは、交互の合計定義が深さごとにパリティを変更するためです。 この遷移では、深さのパリティを明示的に追跡することなく、符号の一貫性が維持されます。 

の表現`next_best`では、子で新しいセグメントを開始する、親のコントリビューションを含むセグメントを拡張する、または上ですでに確認した最良の回答を継承するという 3 つの可能性が考慮されています。

 ### 例 1

```| ノード | cur_alt | ベストアップ | 答え |

 | 1 | 4 | 4 | 4 |

 ノード 3 では、最良のセグメントは、3 から始まる新しい計算ではなく、上位の祖先から得られます。これは、継承された最良の値がローカルな変更と同じくらい重要であることを確認します。

 ## 特殊なケース

 線形チェーンは、すべてのノードが交互の反転の長いシーケンスに依存するため、最も敏感なケースです。 DFS 状態は、各ノードが親から 1 つの更新を正確に受信し、再計算せずに完全な履歴を保存するため、正確性を保証します。 

根元が 1 の星は子供たちを完全に孤立させます。 それぞれの子の答えは、ルートの状態とその伝播にのみ依存します。`best_up`ブランチ間の相互汚染を防ぎます。 

均一な配列は、同じ値でも深さのパリティに応じて自明ではない交互の合計が生成されるため、アルゴリズムが大きさの違いではなく交互の構造に依存していることを強調しています。
