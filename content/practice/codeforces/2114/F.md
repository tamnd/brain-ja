 ## 問題の理解

 2 つの整数が与えられます。`x`そして`y`、および上限`k`。 私たちの目標は変革することです`x`の中へ`y`可能な限り最小限の操作を使用します。 それぞれの演算で乗算が可能になります`x`任意の整数で`a`1との間`k`、または割る`x`任意の整数で`a`1との間`k`除算で整数が得られる限り。 各テスト ケースについて、最小限の操作数を見つけるか、レポートする必要があります。`-1`それが不可能な場合。 

制約は重要です。`x`、`y`、 そして`k`最大 10^6 までの大きさが可能で、最大 10^4 のテスト ケースが存在する可能性があります。 すべての合計`x`そして`y`テスト ケース全体の数は 10^8 を超えません。これは、すべてのテスト ケースについて、考えられるすべての操作シーケンスに対して網羅的な検索を実行することはできないことを意味します。 これは、最大 100 万までの数値を効率的に処理しながら、指数関数的な数の演算シーケンスの探索を回避する方法が必要であることを示唆しています。 

エッジケースは次の場合に発生します。`x`すでに等しい`y`、 いつ`x`または`y`が 1 の場合、または`k`は 1 です。たとえば、次の場合`x = 4`、`y = 5`、 そして`k = 3`、3 までの数値を使用した一連の乗算や除算は 5 に到達することはできません。もう 1 つの微妙なシナリオは、次のような場合です。`x`分割する`y`より大きい素因数を介した場合のみ`k`; このような場合、変換は不可能です。 考えられるすべてのシーケンスを単純にシミュレートしようとすると、何も表示されずに失敗するか、遅すぎる可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、すべての操作シーケンスを再帰的に、または BFS を使用して試行します。 各ステップでは、次のことを検討します。`2*k`選択肢 (1 で乗算または除算して、`k`)、現在の値を追跡します。 このアプローチは正しいのですが、シーケンスの数は操作の数とともに指数関数的に増加するため、すぐに実行不可能になります。 最大の入力の場合、簡単に 10^20 以上のステップが必要になります。 

重要な洞察は、演算が乗算的であり、最大の整数のみが関与するということです。`k`。 したがって、一連の演算ではなく、素因数の数について推論することができます。 各演算は数値を何か ≤ で乗算または除算します。`k`、素因数 ≤ の指数のみを増減できます。`k`。 したがって、問題は、(多重度を伴う) 素因数の総数を数えるということになります。`x`そして`y`異なるものを比較し、以下に制限された操作を使用してそれらを「転送」できるかどうかを確認します。`k`。 

具体的には、演算の数を次のように定義できます。 を達成するために乗算するために必要な素因数の数を数えます。`y`から`x`、素数のみを考慮します ≤`k`、これらの係数で割ることができる回数を数えます。 合成数を掛ける`a`は、その素因数分解を乗算することと同じです。 除算では、因子が存在することが必要です。`x`。 これにより、問題は組み合わせ検索から素因数分解の算術に変換されます。

 ## アルゴリズムのチュートリアル

 1. もし`x`等しい`y`、0 のオペレーションを出力し、次のテスト ケースに移動します。 
2.因数分解`x`そして`y`プライムパワーに。 このために、2 から 2 までのすべての整数を考慮します。`k`、それぞれを除算します`x`そして`y`繰り返して指数を数えます。 より大きい因子を無視する`k`導入も削除もできないからです。 
3. 各素因数について`p`、あと何回出現するかを計算します。`y`よりも`x`。 このような単位の違いごとに、因数分解がちょうど 1 に寄与する数値による 1 回の乗算または除算が必要です。`p`。 
4. 必要なすべての乗算演算とすべての必要な除算演算のカウントを合計します。 どこかの時点で要因となった場合、`y`を超える`k`しかし、に欠けています`x`、出力`-1`生成できないからです。 
5. 操作の合計数を最小シーケンス長として返します。 

このアルゴリズムが機能するのは、乗算と除算が素因数の指数において線形であり、すべての演算がこれらの因数のカウントにのみ影響するためです。 一連の数値ではなく指数に焦点を当てることで、指数関数的な爆発を回避します。 不変条件は、任意の演算シーケンスの後、素数の指数 ≤`k`それらの操作の累積効果を反映しており、差異のバランスをとるために必要な数の操作のみを適用します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def prime_factors_count(n, k):
    counts = {}
    i = 2
    while i*i <= n and i <= k:
        while n % i == 0:
            counts[i] = counts.get(i, 0) + 1
            n //= i
        i += 1
    if n > 1 and n <= k:
        counts[n] = counts.get(n, 0) + 1
    return counts

def min_operations(x, y, k):
    if x == y:
        return 0
    xf = prime_factors_count(x, k)
    yf = prime_factors_count(y, k)
    
    ops = 0
    for p in set(xf.keys()) | set(yf.keys()):
        xi = xf.get(p, 0)
        yi = yf.get(p, 0)
        if yi > xi:
            ops += yi - xi
        elif xi > yi:
            ops += xi - yi
    # Check if y contains factors larger than k that are missing in x
    remainder = y
    for p, c in yf.items():
        remainder //= p**c
    if remainder > 1 and remainder > k:
        return -1
    return ops

t = int(input())
for _ in range(t):
    x, y, k = map(int, input().split())
    print(min_operations(x, y, k))
```この解決策は、最初に自明な等価の場合をチェックします。 次に、以下の素数のみを使用して両方の数値を因数分解します。`k`。 それぞれの因子の差が 1 つの演算に寄与します。 小切手`remainder > k`不可能な変換が実現可能であると誤って主張しないようにします。
