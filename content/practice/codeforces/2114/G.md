 ## 解決策
 ## 問題の理解

 空の配列から開始して、その左端または右端に整数を繰り返し追加します。 各挿入の後、配列自体が単純化される可能性があります。つまり、2 つの同一の近傍が出現するたびに、それらはそれらの合計に等しい 1 つの要素にマージされます。 新しい値が隣接する値と再度一致し、再度マージされる可能性があるため、このマージはカスケードすることができます。 挿入の順序が固定されると、プロセスは決定的になります。 

まさにその後$k$挿入すると、最終的な配列が観察されます$a$長さの$n$、そしてタスクは、いくつかのシーケンスがあるかどうかを判断することです。$k$挿入によって生成された可能性があります。 

このプロセスを考えるのに役立つ方法は、時間を逆に考えることです。 最後の各要素は、隣接する等しい値を繰り返しマージすることによって形成されたブロックを表します。 マージが発生するたびに、2 つの等しい数値が生成されます$x, x$なる$2x$。 したがって、各最終値は、より小さい挿入値の 2 のべき乗のスケーリング履歴ですが、マージは、挿入直後に等しい隣接値が存在する場合にのみ発生します。 

制約が十分に大きいため、明示的に挿入をシミュレートしたり、考えられるすべての履歴を維持しようとするアプローチは失敗します。 と$n$まで$10^5$テスト全体にわたって、$k$まで$10^6$、テストごとに線形または線形に近いものより悪い解は除外されます。 平$O(k)$テストごとには不可能です。 

重要な微妙な点は、隣接する等しい値が入力で禁止されていることです。これは、最終的な配列がすでに完全に安定した状態を反映していることを意味します。 これにより、最終構成での保留中のマージに関する曖昧さは解消されますが、それがどのように構築されたかについての曖昧さは解消されません。 

単純な間違いは、各操作が最終配列に 1 つの要素だけを提供すると考えることです。マージによって 1 つの出力要素への複数の挿入が削減されるため、これは誤りです。 もう 1 つの罠は、要素の合計が次のようなものと等しいと仮定することです。$k$、これも false です。マージするとカウントが保持されずに値が変更されるためです。 

## アプローチ

 ブルート フォース アプローチでは、どちらかの端に値を挿入し、考えられるすべてのマージ カスケードを追跡するためのすべての可能な方法をシミュレートしようとします。 挿入される値を最終的な配列に見られる値に制限したとしても、分岐係数は依然として指数関数的です。$k$、各挿入は左または右に移動でき、再帰的マージがトリガーされるためです。 これは小さなものを超えてすぐに爆発します$k$。 

重要な構造的洞察は、マージは完全にローカルであり、隣接する等しい値の間でのみ発生するということです。 これは、各最終値を、ペアごとのマージを繰り返すことで作成される一連の「2 倍化」に分解できることを意味します。 逆に、それぞれの値は、$x$の複数の挿入から来ていると見なすことができます$x/2, x/2$、または最終的には、同じ基本値のコピーを多数挿入することによって行われます。 

このプロセスは、各最終値をマージのバイナリ ツリーに分割することと同等になります。葉は元の挿入に対応します。 このツリーの葉の数によって、その値を生成するために必要な操作の数が決まります。 

数字の場合$x$、偶数のままで 2 で割ることができる回数によって、その「マージ レベル」の数が決まります。 もし$x = 2^p \cdot odd$、その後、生産します$x$少なくとも必要です$2^p$挿入は、制約された方法でそのブロック構造に寄与します。 ただし、重要な単純化は、各配列要素が、特定の貪欲な分割解釈の下でのバイナリ分解における 1 の数に等しい、必要な挿入数に寄与することです。 

左から右に処理される場合、各要素を構築することによって「消費」される操作の数を維持します。 実現可能性の条件は、必要な最小限の挿入の合計が最大でも以下であるかどうかをチェックすることになります。$k$、および隣接関係の制約を破ることなく境界を分割または拡張することによってパリティと余分な挿入を吸収できるかどうか。 

より正確な視点は、各要素が$a_i$少なくとも必要です$\text{popcount}(a_i)$バイナリ結合モデルへの概念的な挿入、および追加の$k - n$演算は、禁止された隣接等式を強制しない限り、最終的な配列を変更せずに吸収できる冗長な挿入に対応します。 隣接する等しい値が最終的な配列に現れることはないため、これらの追加の演算は常に境界拡張として配置できます。 

したがって、問題は最終要素ごとに少なくとも 1 つの挿入を割り当て、残りを分散できるかどうかを確認することに帰着します。$k-n$無効な中間マージ構造を強制しない方法で挿入します。 これは、2 つのチェーンのべき乗によって暗示される構造的制約が矛盾しない限り、常に可能です。矛盾は特定のパリティおよび可分性構成でのみ発生します。 

最終的な解決策は、各要素のバイナリ構造に対する貪欲な実行可能性チェックに集約されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. それぞれを構築するために必要な最小挿入数を計算します。$a_i$それを 2 の累乗に分解することによって。 これは、マージによって値を後方に何回分割できるかをカウントしていると解釈します。 これにより、要素ごとの基本要件が決まります。 
2. すべての要素にわたるこれらの最小要件を合計して、下限を取得します。$need$。 これは、配列構造を生成する可能性のある演算の最小数を表します。 
3. もし$need > k$、最も効率的な構築でも目標を達成できないため、すぐに「NO」を出力します。 
4. 残りのスラックを計算します$k - need$。 このたるみは、新しい構造に寄与する必要のない余分な挿入を表します。 
5. 要素の境界を越えてマージするような方法で隣接する等しい要素を強制することなく、スラック操作を挿入できるかどうかを確認します。 最終的な配列には等しい隣接要素がないため、構造を変更するマージをトリガーすることなく、スラック挿入を常に端またはギャップ内に配置できます。そのため、実現可能性はスラックが非負かどうかによってのみ決まります。 
6. 実行可能な場合は「YES」を出力し、実行可能な場合は「NO」を出力します。 

重要な部分は、制約のため、マージは最終的な表現で要素の境界を越えないことです。$a_{i-1} \ne a_i$、セグメント構造の独立性が保証されます。 

### なぜ効果があるのか

 重要な不変条件は、各最終要素が独立したマージ ツリーに対応し、その葉が挿入操作に対応することです。隣接する最終値が異なるため、これらのツリーは決して相互作用しません。 マージは等しい値の間でのみ発生するため、1 つのツリー内の操作によって別のツリーでのマージがトリガーされることはありません。 これにより、配列が独立したコンポーネントに分離されるため、必要な演算の総数は追加的で最小限になります。 追加の操作は、新しい等隣接ペアを作成せずに境界に挿入でき、最終的な構造は維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        # Each element contributes a minimal "construction cost"
        # equal to number of set bits in its binary representation
        need = 0
        for x in a:
            need += x.bit_count()
        
        if need > k:
            print("NO")
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```最終的な配列が固定されると、マージでは異なる大きさの値が混在することがないため、各要素は独立して処理されます。 の使用`bit_count()`バイナリ マージ解釈の下での最小分解コストを取得します。 

唯一の微妙な実装の詳細は、中間配列の状態空間が無制限であるため、線形スキャンを使用し、プロセスのシミュレーションを避けることを保証することです。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$n = 1$。 この場合、配列は単一の値であり、答えは純粋に次のとおりであるかどうかによって決まります。$k$少なくともその数値の最小建設コストです。 1 つの要素の合計のみを計算するため、アルゴリズムはこれを自然に処理します。 

もう 1 つの特殊なケースは、すべての値が 2 の累乗である場合です。 この場合、各ビット数は 1 なので、$need = n$。 もし$k = n$、構造はしっかりしています。 もし$k > n$、余分な操作は境界で吸収される必要がありますが、不要なマージを引き起こす隣接する等しい値がないため、常に安全です。
