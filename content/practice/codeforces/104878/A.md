 ## 解決策
 ## 問題の理解

 交差点がノード、道路がエッジである無向グラフとしてモデル化された都市が与えられています。 パウダーは実験室であるノード 1 から出発し、ゾウンへの隠された入り口であるノード N に到達したいと考えています。 一部の交差点には最初は警察官がいます。 

パウダーがあまりにも多くの警察が占拠する交差点を通過する場合、その道は危険であると見なされます。 最初のタスクはこの制約を無視し、訪問する交差点の数に関して 1 から N までの最短パスを単純に求めます。 すべてのエッジは重み付けされていないため、これは重み付けされていないグラフで最短経路を見つけることと同じです。 

2 番目のタスクは状況を変更します。 すべての警察官が単一の交差点 V に誘い込まれます。つまり、V が唯一の警察管理ノードとなり、他のすべての警察ノードは安全になります。 パウダーはVを一切踏めません。 V が禁止されているグラフで、1 から N への最短パスを再度計算する必要があります。 

この制約では、最大 100,000 個のノードとエッジが許可され、クエリごとに二次関数や三次関数さえも即座に除外されます。 BFS は O(N + M) で実行されるため、クエリごとに 1 つの BFS が可能です。 ノードごとにパスを再計算したり、すべてのパスをシミュレートしようとするアプローチは遅すぎます。 

1 または N のいずれかがすでに警察の規則によってブロックされている場合、微妙なエッジ ケースが発生します。 2 番目のサブタスクでノード 1 が V に等しい場合、または N が V に等しい場合、パスは存在しません。 同様に、元のグラフで N に到達できない場合、両方の答えは -1 になります。 

もう 1 つの注意が必要な状況は、グラフが切断されている場合です。 たとえば、ノード N がノード 1 とは異なるコンポーネントにある場合、ポリシング制約がない場合でも、答えはすぐに -1 になります。 接続を前提とした単純な最短パスの実装は、到達可能性を明示的にチェックしない限り、ここで暗黙的に失敗します。 

## アプローチ

 両方のサブタスクの構造は、重み付けされていないグラフ上の最短経路問題を強く示唆しています。 強引な解釈では、1 から N までのすべての単純なパスを列挙し、最短の有効なパスを選択します。 すべての有効なパスが考慮されるため、これは理論的には正しいですが、グラフ内の単純なパスの数は N とともに指数関数的に増加する可能性があります。密なグラフでは、分岐係数が各ステップで複合するため、たとえ小さな入力であってもすぐに不可能になります。 

より現実的ではありますが、まだ素朴なアイデアは、優先キューを使用してダイクストラのようなプロセスを実行することです。これはまだ正しいですが、すべてのエッジの重みが等しいため、やりすぎです。 O(M log N) で動作しますが、これは許容範囲内ですが、必要以上に遅くなります。 重要な観察は、すべてのエッジのコストが等しいため、BFS はすでにエッジの数、つまり訪問するノードの数に関して最短パスを保証しているということです。 

2 番目のサブタスクの唯一の変更は、1 つのノードが禁止されていることです。 それ以外の場合、グラフの構造は変わりません。 これは、そのノードを完全に無視して BFS を再度実行できることを意味します。 

したがって、問題は、BFS を 2 回実行することになります (1 回はグラフ全体で 1 回、もう 1 回はノード V が削除されたグラフで) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスを列挙する | 指数 | O(N) | 遅すぎる |
 | ディクストラ | O(M log N) | O(N + M) | 受け入れられるが不要 |
 | 2 回の BFS 実行 | O(N + M) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 両方のサブタスクを独立した BFS 計算として扱います。 

### 最初の最短パス

1. M 個のエッジからグラフの隣接リストを作成します。 これにより、近隣の高速なトラバースが可能になります。 
2. ノード 1 から開始して標準 BFS を実行します。-1 に初期化されたキューと距離配列を維持します。 
3. エッジではなく交差点をカウントするため、 distance[1] を 1 に設定します。 
4. キューからノードをポップし、各近隣ノードにアクセスされていない場合は、 distance[current] + 1 を割り当ててプッシュします。 
5. 到達可能なすべてのノードが処理されたら停止します。 
6. サブタスク 1 の答えは、距離 [N]、または距離に到達しなかった場合は -1 です。 

ここでの重要な考え方は、BFS がソースからのステップ数の昇順でノードを探索するため、初めてノードに到達した時点で、そのノードへの可能な最短パスがすでに見つかっているということです。 

### 禁止ノードを含む 2 番目に短いパス

 1. BFS を繰り返しますが、ノード V をブロックされたものとして扱います。 
2. 開始ノード 1 が V に等しい場合、または宛先ノード N が V に等しい場合は、すぐに -1 を返します。 
3. BFS 中に近隣を考慮するときは常に、V につながる遷移をスキップします。 
4. それ以外の場合は、前と同じように BFS を実行し、距離 [N] を計算します。 

### なぜ効果があるのか

 正確さは、BFS がソースからの距離が小さくならない順にノードを処理するという不変式に依存します。 すべてのエッジのコストは等しいため、最初にノードに距離を割り当てるとき、その値はすべての可能なパスの中で最小になります。 ノード V を削除すると、単に状態空間からノード V が削除されますが、この単調特性は変更されません。 したがって、BFS は、制限されたグラフ内の有効な最短パスを引き続き正確に計算します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(n, adj, blocked):
    if blocked[1] or blocked[n]:
        return -1

    dist = [-1] * (n + 1)
    q = deque()

    dist[1] = 1
    q.append(1)

    while q:
        u = q.popleft()
        for v in adj[u]:
            if blocked[v]:
                continue
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)

    return dist[n]

def solve():
    n, m, k, V = map(int, input().split())

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    police_nodes = list(map(int, input().split()))
    blocked1 = [False] * (n + 1)
    for x in police_nodes:
        blocked1[x] = True

    ans1 = bfs(n, adj, blocked1)

    blocked2 = blocked1[:]
    blocked2[V] = True

    ans2 = bfs(n, adj, blocked2)

    print(ans1, ans2)

if __name__ == "__main__":
    solve()
```このソリューションでは、グラフの構築と走査が分離され、両方の BFS 実行で同じ隣接リストが再利用されるようになります。 の`blocked`array は、元の警察の位置と 2 番目のクエリの変更された制約の両方をエンコードするキーの抽象化です。 

BFS 関数は交差の数で距離を返します。これが、ソース距離を 0 ではなく 1 として初期化する理由です。これにより、結果を解釈する際の off-by-one エラーが回避されます。 

また、BFS を実行する前に、ノード 1 またはノード N がブロックされているかどうかを明示的にチェックします。その場合、トラバーサルは成功しません。

 ### 例 1

 入力:```
9 10 4 6
1 2
1 3
2 4
3 5
5 6
5 7

```すべてのポリシング ノード 3、5、6、7 を無視して、1 から BFS を実行します。 

| ステップ | 現在のノード | 距離の割り当て |
 | --- | --- | --- |
 | 1 | 1 | 距離[1]=1 |
 | 2 | 2 | 距離[2]=2 |
 | 3 | 4 | 距離[4]=3 |
 | 4 | 5 | ブロック、スキップ |
 | 5 | 3 | ブロック、スキップ |
 | 6 | 6 | ブロック、スキップ |

 探索を続けると、距離 6 でノード 9 に到達するまで、許可されたノードを通過できます。したがって、答えは 6 です。 

2 番目の BFS では、ノード 6 もブロックされます。 すべての最短ルートが既に V を回避しているため、この特定のグラフでは最短パスの構造は変化せず、結果は 6 のままです。 

これにより、ブロックされたノードを追加しても、それが最適なルートの一部でなかった場合、最短パスの長さが必ずしも変更されるわけではないことが確認されています。 

### 例 2

 より単純なグラフを考えてみましょう。```
5 4 1 3
1 2
2 3
3 4
4 5
2
```まず、BFS はノード 2 を警察として無視します。 

| ステップ | ノード | 距離 |
 | --- | --- | --- |
 | 1 | 1 | 1 |
 | 2 | 2 | ブロックされました |
 | 3 | 3 | 1 ～ 3 のパス経由で到達可能ですか? いいえ |

 ノード 3 は到達できないため、答えは -1 です。 

2 番目の BFS はさらにノード 3 をブロックします。 

パスがまったく存在しないため、結果も -1 になります。 

これは、グラフが最初は接続されていたとしても、ブロッキングによってグラフが完全に切断される可能性があることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + M) | 隣接リストを介した 2 つの BFS トラバーサル |
 | スペース | O(N + M) | グラフ ストレージと距離および訪問された配列 |

 この制約では最大 100,000 のノードとエッジが許可されるため、線形時間 BFS は問題なく制限内に収まります。 BFS を 2 回実行しても、合計操作数は 2 秒の制限のしきい値を大幅に下回ります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    def bfs(n, adj, blocked):
        if blocked[1] or blocked[n]:
            return -1
        dist = [-1] * (n + 1)
        q = deque([1])
        dist[1] = 1
        while q:
            u = q.popleft()
            for v in adj[u]:
                if blocked[v]:
                    continue
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    q.append(v)
        return dist[n]

    n, m, k, V = map(int, sys.stdin.readline().split())
    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        a, b = map(int, sys.stdin.readline().split())
        adj[a].append(b)
        adj[b].append(a)

    police = list(map(int, sys.stdin.readline().split()))
    blocked1 = [False] * (n + 1)
    for x in police:
        blocked1[x] = True

    ans1 = bfs(n, adj, blocked1)
    blocked2 = blocked1[:]
    blocked2[V] = True
    ans2 = bfs(n, adj, blocked2)

    return f"{ans1} {ans2}"

 ## 特殊なケース

 2 番目のシナリオでノード 1 またはノード N がブロックされると、BFS は意味のある形で開始されません。 早期の復帰により、誤った部分走査が防止され、出力は正しく -1 になります。 

グラフが切断されると、BFS の完了後、ノード N の距離配列は -1 のままになります。 これは、初期化以外の特別なケースを必要とせずに、不可能であることを直接通知します。 

最適なパスが V を通過する必要がある場合、2 番目の BFS はそのノードを完全にスキップすることで自然にそれを回避します。 次に、検索では代替ルートが探索され、代替ルートが存在しない場合、結果は予想どおり -1 になります。
