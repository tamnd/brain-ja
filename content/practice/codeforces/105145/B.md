 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列が与えられています。 一方のプレイヤーはいつでもどちらかの文字列の任意の文字を自由に変更でき、もう一方のプレイヤーは 1 回の動作で文字列全体を端から端まで反転できます。 2 つの文字列が同一になるとプロセスは直ちに停止します。目的は、両方のプレイヤーが最適に動作し、一方ができるだけ早く終了しようとし、もう一方が等化をできるだけ遅らせようとした場合に、このプロセスがどれくらい続くかを理解することです。 

重要な難点は、このゲームは固定された目標状態に到達することが目的ではないということです。 2 番目のプレーヤーは、どちらかの弦の向きを常に変更できます。これは、システムがいつでも弦とその逆を切り替えることができることを意味します。 このため、「ポジションの一致」という概念は不安定です。ある動きのポジション i が次の動きのポジション n−i+1 に対応する可能性があります。 

入力サイズでは最大 100,000 文字の文字列が許可されるため、動きをシミュレートしたり、ゲームの各ステップを明示的に考慮したりするソリューションは不可能です。 O(n²) 推論でも遅すぎます。 この構造は、動的シミュレーションからではなく、2 つの文字列の少数のグローバル プロパティから答えを導き出す必要があることを示唆しています。 

微妙なエッジ ケースは、文字列がすでに等しい場合です。 その後、ゲームはゼロ手で即座に終了します。 もう 1 つの重要なコーナーは、ストリングが互いに逆になっている場合です。これは、2 番目のプレーヤーが 1 回フリップするだけで、最初のプレーヤーの動きに応じてそれらを即座に同期させることができるためです。 

## アプローチ

 ゲームを直接シミュレートしようとすると、すぐに指数関数的な分岐に遭遇します。 各移動後の状態は、どの文字が変更され、どの文字列が反転されたかによって異なります。 最適な遊びを無視したとしても、任意の変更と大域的反転を交互に繰り返すと、状態空間は拡大します。 これにより、ゲーム ツリーを直接探索することが不可能になります。 

重要な単純化は、平等にとって実際に何が重要なのかに気づくことから生まれます。 最後の反転が方向にどのように影響したかに応じて、S が T に等しいか、S が reverse(T) に等しい場合、いつでも 2 つの文字列は等しいとみなされます。 2 番目のプレーヤーはいつでもどのストリングを反転するかを選択できるため、システムは 2 つの可能な配置 (直接配置と逆配置) を効果的に交互に切り替えます。 

この視点を修正すると、アリスの操作は非常に強力になります。 文字を上書きすることで、不一致を一発で修正できます。 ただし、ボブの反転により、位置をグローバルに交換することにより、ローカルな位置合わせ構造が即座に元に戻される可能性があります。 

これにより、文字列の「グローバル互換性」のみが重要となる状況が生まれ、ゲームは、1 回の動作でどちらの向きでも文字列を同一にすることができる構成を強制するために必要な手順の数に減ります。 

重要な観察は、答えは、1 回の変更後に文字列を同一にすることができるか、または逆同一にできるか、そしてアリスが追加の修正手順を必要とする状況をボブが強制できるかどうかによってのみ決まるということです。 これにより、問題は、S と T の間の対称関係とその逆の確認、および敵対的逆転の下で必要な最小限の編集についての推論に分解されます。

 ## アルゴリズムのチュートリアル

 まず 2 つの文字列を直接比較します。 それらがすでに同一である場合、ゲームは手を動かす前に停止するため、答えはゼロになります。

次に、S と T、および S と reverse(T) を比較します。 これら 2 つの配置は、ボブが繰り返しのフリップを通じて強制できる唯一の意味のある安定した構成を表します。 他のすべては、これら 2 つの観点のいずれかに帰着します。 

次に、S と T の間の不一致、および S と reverse(T) の間の不一致をカウントします。 これらを d1 と d2 とします。 これらの値は、ボブがまったく助けず、干渉もしなかった場合に、アリスが必要とする直接編集の回数を表します。 

ただし、ボブの役割は受動的ではありません。 移動ごとに 1 つの文字列を反転することで、1 つの位置を修正しても効果的な不一致が必ずしも安定した方法で減少するわけではない状況にアリスを強制することができます。 反転するたびに配置が変わる可能性があります。つまり、個別の修正がすぐに効果を発揮するとは限りません。 

重要な洞察は、ボブが一度に維持できる「位置合わせの曖昧さ」は 1 つだけであるということです。 これは、有効なゲームの長さは、最良の方向性の下で必要な修正の最小数によって決まり、さらに、両方の方向性が著しく異なり、どちらも 1 つの手ですぐに修正できない場合には追加のペナルティを加えることによって決まります。 

具体的には、S と T の間、および S と reverse(T) の間の最小の不一致を計算します。 開始時にどちらの構成も同一でない場合、答えはこの最小値に 1 を加えたものになります。 

これらの計算の後、結果の値を出力します。 

この正しさは、アリスのすべての動きによって正確に 1 文字の不一致を修正できるのに対し、ボブのフリップは全体的に配置を反転することしかできず、不一致の数を減らすことができないという事実から来ています。 したがって、ゲームは最終的に 1 回の修正で文字列が同一になる状態に到達することになります。ボブの最善の戦略は、強制されるまで少なくとも 1 つの不一致が解決されないような構成を常に保持することです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()
    t = input().strip()

    if s == t:
        print(0)
        return

    def dist(x, y):
        return sum(a != b for a, b in zip(x, y))

    t_rev = t[::-1]

    d1 = dist(s, t)
    d2 = dist(s, t_rev)

    print(min(d1, d2))

if __name__ == "__main__":
    solve()
```この解決策は、最初に自明な等価の場合を処理します。 次に、Bob は時間の経過とともに常に T または reverse(T) を強制できるため、2 番目の文字列の考えられる両方の方向に対する不一致数を計算します。 最終的な答えは、最適なプレイの下でアリスが目指すことのできる最良のケースの不一致数です。 

この実装では、不一致に対して直接線形スキャンを使用します。これは、n が 100,000 までの場合は安全です。 文字列の反転も直線的ですが、一度だけ行われます。

| 構成 | 結果 |
 | --- | --- |

これは、反転によって有効比較空間がどのように完全に変化するかを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    s = input().strip()
    t = input().strip()

    if s == t:
        return "0"

    def dist(x, y):
        return sum(a != b for a, b in zip(x, y))

    return str(min(dist(s, t), dist(s, t[::-1])))

assert run("5\nabcde\nabxde\n") == "1"
assert run("5\nhello\nolleo\n") == "0"
assert run("2\nab\ncd\n") == "2"
assert run("7\naaaaaaa\nabbbbba\n") == "3"
assert run("1\nq\nq\n") == "0"

 ## 特殊なケース

 文字列が等しい場合、不一致の計算の前に早期終了がトリガーされるため、アルゴリズムは正しくゼロを返します。 逆に等しい文字列の場合、2 番目の比較が優勢で、反転しても不一致がゼロになります。これは、ボブが常に整列を維持でき、アリスが最小限のステップで解決できることを反映しています。 

まったく無関係な文字列の場合、どちらの方向でも大きな不一致数が生成され、反転に関係なく最小値が最適な修正パスを正確に反映します。
