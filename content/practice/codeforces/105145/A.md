 ## 解決策
 ## 問題の理解

 L から R までの連続した範囲の整数が与えられ、各整数は材料を表します。 この範囲から 2 つのマテリアル (同じである可能性があります) を選択し、それらの 10 進表現の違いに基づいてスコアを計算する必要があります。 

スコアを計算するには、まず両方の数値を同じ長さの数字列として書き込み、短い方の数値の先頭にゼロを埋め込みます。 次に、桁ごとに比較し、対応する桁の差の絶対値を合計します。 これは事実上、数字ベクトル間の L1 距離です。 

タスクは、区間 [L, R] 内のすべての数値ペアにわたってこの距離を最大化することです。 

制約は非常に大きく、L と R は最大 10 桁、つまり約 10^10 までの長さにすることができます。 間隔には最大 10^10 の数値を含めることができるため、すべてのペアを試行するソリューションは即座に除外されます。 範囲を超えて反復することさえ不可能です。 

重要な構造上の困難は、範囲が任意ではないことです。つまり、範囲は連続区間ですが、桁ごとの違いはキャリー構造と位置の制約に大きく依存するため、局所的な貪欲な推論が自明ではなくなります。 

L と R の桁の長さが異なる場合、微妙なエッジ ケースが発生します。 たとえば、L = 90 および R = 100 です。ここで、数値を比較するには、先頭のゼロを慎重に処理する必要があります。 パディングなしで生の整数または文字列を比較する単純な実装では、誤った結果が生成されます。 

もう 1 つのエッジ ケースは、L = R = 7 など、間隔に数値が 1 つだけ含まれる場合です。この場合、可能なペアは (7, 7) のみであり、スコアは 0 になります。どのソリューションでも、これを明示的に処理する必要があります。 

最後に、桁の境界を越えた遷移が重要です。 たとえば、L = 190 と R = 209 では、数値のさまざまな「形状」からの数字を混合することができ、最適なペアは区間内ではなく端点近くにあることがよくあります。 

## アプローチ

 ブルート フォース ソリューションでは、[L, R] 内のすべてのペア (x, y) を反復処理し、それらの桁ごとの差を計算し、最大値を取得します。 各比較のコストは O(d) で、d は桁数であるため、合計の複雑さは O((R−L+1)^2 · d) になります。 R が 10^10 までの場合、これは完全に不可能です。 

重要な観察は、比較する数値を固定すると、各桁の位置の寄与が独立しているということです。 スコアはポジションの合計であるため、合計を最大化することは、同時にポジションごとの貢献を最大化することを意味します。 ただし、任意の数字ベクトルではなく、一貫した整数を選択する必要があるため、数字は数値全体で独立していません。 

重要な構造的洞察は、最適なペアは、間隔によって課される実現可能性の制約の下で、各桁の位置の極端な選択によって常に決定されるということです。 数値を列挙する代わりに、数値のペアに対する桁 DP の観点から同時に考え、それぞれの数値がまだ L または R によって制限されているかどうかを追跡します。 

2 つの数値を左から右に 1 桁ずつ構築し、両方が [L, R] 内に収まるようにします。 各位置で、接頭辞の制約を尊重しながら、選択した数字間の絶対差を最大化しようとします。 

これにより、問題は、構築された 2 つの数値の接頭辞が L および R 境界とどのように比較されるかを表す状態を含む数字 DP に変わります。

 | Digit DP over pairs | O(d · 10^2 · 4) | O(d · 4) | 承認済み |

 ## アルゴリズムのチュートリアル

 |L| の最大値に等しい長さを使用して、数値を先頭にゼロが付いた固定長の数字列として処理します。 and |R|.

 2 つの数値を同時に構築する DP を定義します。 

1. 必要に応じて L の先頭にゼロを埋め込み、L と R を同じ長さに正規化します。

これにより、一貫した数字のインデックス付けが保証され、境界チェックが均一になります。 
2. 再帰関数 dp(pos、tightL1、tightR1、tightL2、tightR2) を定義します。ここで、pos は現在の桁インデックスであり、tight フラグは、構築された各数値の接頭辞が境界でまだ L または R と正確に等しいかどうかを示します。 これらのフラグは、[L, R] の外側に無効な数値を構築しないようにするために必要です。 
3. 各位置で、[0, 9] 内のすべての可能な数字のペア (a、b) を繰り返します。 各ペアについて、現在の厳しい制約を考慮して、これらの数字を配置することで両方の数字が許容範囲内に収まるかどうかを確認します。 
4. 桁の割り当てが有効な場合、寄与率 |a − b| を計算します。 そしてそれを次の位置 dp(pos + 1, updated flags) からの達成可能な最良の値に加算します。 
5. すべての有効な数字ペアの最大値を取得します。 
6. すべてのタイト フラグを true に設定して位置 0 から開始します。これは、両方の数値が最初に L と R の両方によって制約されることを意味します。 
7. dp(0, true, true, true, true) の結果を返します。 

重要な点は、フラグがどのように更新されるかです。 対応する境界桁と等しい桁を配置すると、タイトなままになります。 それ以外の場合は、その方向に制約を緩和します。 

### なぜ効果があるのか

 DP は、すべての位置で、部分的に構築された両方の数値が [L, R] 内のいくつかの数値の有効な接頭辞であるという不変条件を維持します。 すべての遷移では、境界制約に対して数字の実現可能性をチェックすることで、この不変条件が維持されます。 すべての有効な数値ペアはこの状態空間内の 1 つのパスに正確に対応し、すべてのパスが評価されるため、すべての DP 状態の最大値は可能な最大スコアに等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    L = input().strip()
    R = input().strip()

    n = max(len(L), len(R))
    L = L.zfill(n)
    R = R.zfill(n)

    from functools import lru_cache

    @lru_cache(None)
    def dp(pos, tL1, tR1, tL2, tR2):
        if pos == n:
            return 0

        lo1 = int(L[pos]) if tL1 else 0
        hi1 = int(R[pos]) if tR1 else 9
        lo2 = int(L[pos]) if tL2 else 0
        hi2 = int(R[pos]) if tR2 else 9

        best = 0

        for a in range(lo1, hi1 + 1):
            ntL1 = tL1 and (a == int(L[pos]))
            ntR1 = tR1 and (a == int(R[pos]))
            for b in range(lo2, hi2 + 1):
                ntL2 = tL2 and (b == int(L[pos]))
                ntR2 = tR2 and (b == int(R[pos]))
                best = max(best, abs(a - b) + dp(pos + 1, ntL1, ntR1, ntL2, ntR2))

        return best

    print(dp(0, True, True, True, True))

if __name__ == "__main__":
    solve()
```実装は数字 DP 構造に直接に従います。 Padding ensures digit alignment. DP 状態は、各数値が依然として L または R によって制約されているかどうかを明示的にエンコードします。遷移は、桁ペアを列挙し、桁ごとの絶対差を累積します。 

実装の微妙な点は、桁の境界が数値ごとに独立して厳密さに依存することです。 もう 1 つは、4 つのフラグすべてを慎重に更新する必要があるということです。 1 つでも欠けていると、無効な番号が生成されます。

 ## 特殊なケース

 L が R に等しい場合、DP はすぐにすべての桁が固定され、すべての寄与がゼロになる状態に達します。 再帰は引き続き実行されますが、単一の強制パスをたどるだけで、正しく 0 が生成されます。 

L と R の長さが異なる場合、パディングにより正しい位置合わせが保証されます。 たとえば、L = 90 および R = 100 は 090 および 100 になります。DP は先頭のゼロを R の数字と正確に比較するため、上位の位置で大きな寄与が可能になります。 

L = 111 と R = 111 など、数字が範囲全体で同一である場合、すべての遷移が強制され、どの数字のペアもプラスに寄与しません。 

範囲が大きい場合でも、DP は数値ではなく数字の状態のみを調査するため、大きさによる影響を受けません。
