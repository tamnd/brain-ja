 ## 解決策
 ## 問題の理解

 頂点 1 にルートを持つルート付きツリーが与えられています。すべての非ルート ノードには親があり、ノードからその親までの各エッジには負ではない重みがあります。 

すべての頂点に 1 から n までの個別の整数を割り当て、頂点の順列を形成する必要があります。 割り当ては任意ではありません。すべての頂点 v について、v のサブツリー内の頂点に割り当てられたすべての値を見ると、それらの値は整数の連続セグメントを形成する必要があります。 この条件により、最終的な順序付けではすべてのサブツリーが連続ブロックを占有することになるため、ラベル付けは本質的に、サブツリーが決してインターリーブしないツリーの線形配置になります。 

ラベリングのコストはエッジにわたって定義されます。 ルートとは異なるすべてのノード v について、親に対するエッジの重みに、順列における v とその親の位置間の絶対差を乗算して支払います。 

タスクは、この総コストを最小限に抑える有効なラベルを選択することです。 

n が 5000 までという制約は、O(n^2) または O(n log n) の解が許容されることを意味します。 有効な順列の数は、サブツリーの連続性制約の下でも指数関数的であるため、順列を列挙しようとする解決策は不可能です。 

素朴だが重要な失敗例は、サブツリーの連続性制約を無視したことに起因します。 たとえば、ノードに 2 つの子がある場合、それらのサブツリーを順列にインターリーブすると、距離に関して局所的に有利であると思われる場合でも、有効性が損なわれます。 

もう 1 つの微妙な問題は、子の相対的な順序が重要ではないと想定していることです。 実際、子の順序を変更すると、サブツリーの開始位置が変更されるため、そのサブツリー内のすべてのエッジの寄与が変更されます。 

感度を示す典型的な小さなツリーは、サイズ 100 と 1 の 2 つの子 a と b を持つルートです。それらの順序を入れ替えると、重いエッジの距離への寄与が大幅に変化するため、グローバル構造を持たない貪欲なローカル選択は失敗します。 

## アプローチ

 サブツリーの連続性条件により、最終的な並べ替えが DFS 順序とまったく同じように動作するように強制されます。各ノードのサブツリーは連続セグメントになり、子のサブツリーは親のセグメント内の連続したブロックとして表示されます。 唯一の自由は、各ノードでの子の順序付けです。 

これが認識されると、問題は、すべてのノードについて、誘発されるコストを最小限に抑える子の順序を選択することになります。 

ブルートフォースアプローチでは、すべてのノードで子のすべての順列を試行し、その結果の DFS 順序を構築し、位置を計算し、コストを評価します。 これは正しいですが、分岐因子で階乗的に爆発します。 星型のツリーであっても、ルートには n 個の子が存在するため、これは実行不可能です。 

重要な点は、子サブツリーの位置は、以前に配置された兄弟サブツリーの合計サイズのみに依存するということです。 これにより、ノードでのコストがシーケンス スケジューリング問題に分解可能になります。つまり、各子はサブツリー サイズに等しい処理時間とエッジ コストに等しい重みを持つタスクになります。 

各ノードにおける問題は、前の子がサブツリーのサイズに比例して後の子の距離の寄与を増加させる合計を最小化する子の順序を見つけることになります。 これはまさに古典的な重み付け順序の最適化であり、ペアごとのスワップ引数によって最適な並べ替えルールが決定されます。 

2 つの子 i と j を比較すると、サブツリーのサイズとエッジの重みの比が単調条件を満たす場合には、i を j の前に配置する方が適切であることがわかります。 これにより、単純な貪欲な順序付けルールが得られます。

## アルゴリズムのチュートリアル

 1. サブツリーのサイズをボトムアップで計算します。 

各ノード v について、s[v] を 1 にその子のサイズの合計を加えたものとして定義します。 これが必要なのは、エッジの距離の寄与が以前の兄弟サブツリーの大きさに依存するためです。 
2. 各ノードについて、各子 u を処理時間 s[u] と重み c[u] を持つ項目として扱います。 

ノード内のコスト構造は、s[u] が判明した後のより深い構造ではなく、子の順序付けにのみ依存します。 
3. ペアワイズスワップ分析を使用して、子の最適な順序を決定します。 

2 つの子 i と j の場合、i を j の前に置くと追加コスト w_j * s_i が寄与し、逆の場合は w_i * s_j が寄与します。 したがって、より良い順序付けは、s_i / w_i と s_j / w_j を比較することによって決定されます。 
4. 浮動小数点演算を回避するために交差乗算を使用して、比率 s[u] / c[u] を増加させることによってすべてのノードの子を並べ替えます。 

これにより、スワップ条件下での順序の局所的な最適性が保証されます。 
5. サブツリー v の最適コスト寄与である dp[v] を計算します。 

dp[v] を、子の dp[u] に直接のエッジ寄与を加えた合計として初期化します。 ソートされた順序で子を反復処理する間、prefix_s を以前に配置されたサブツリーの合計サイズとして維持します。 各子 u について、c[u] * (1 + prefix_s) を dp[v] に加算し、s[u] によって prefix_s を更新します。 
6. ツリー全体の答えとして dp[1] を返します。 

正確性は、各サブツリーがすでに内部的に最適に配置されており、各ノードでの順序付けによってすべての子間の相互作用項が最小化されるという不変条件に依存します。 サブツリーの相互作用はノードの境界を越えないため、すべてのノードでの局所的な最適性が全体的な最適性を構成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n + 1)]

for i in range(2, n + 1):
    p, c = map(int, input().split())
    g[p].append((i, c))

s = [0] * (n + 1)
dp = [0] * (n + 1)

def dfs(v):
    s[v] = 1
    for u, _ in g[v]:
        dfs(u)
        s[v] += s[u]

    children = []
    for u, c in g[v]:
        children.append((u, c, s[u]))

    children.sort(key=lambda x: (x[2] / x[1]) if x[1] != 0 else float('inf'))

    total = 0
    prefix_s = 0

    for u, c, sz in children:
        dp[v] += dp[u]
        dp[v] += c * (1 + prefix_s)
        prefix_s += sz

    s[v] = max(1, s[v])
    return

dfs(1)
print(dp[1])
```DFS は最初にサブツリーのサイズを計算し、それを再利用して順序を決定します。 実装の重要な詳細は、並べ替えが相互比較可能な比率を使用して行われることですが、実際にはここでは除算が許容されます。 より安全なバージョンでは使用されます`sz * other_c < other_sz * c`。 

DP の累積により、各子サブツリーの内部最適コストと、以前の兄弟によって引き起こされる位置シフトという 2 つの効果が分離されます。 プレフィックスの合計は、最終的なプレオーダー レイアウトで各サブツリー ルートがその親からどれだけ離れているかを正確に追跡します。 

## 実用的な例

 ノード 1 に 2 つの子 2 と 3 (両方とも葉) があり、エッジの重みが c2 = 5 および c3 = 2 である小さなツリーを考えてみましょう。 

サブツリーのサイズは s2 = s3 = 1 です。 

| ステップ | ノード順序の決定 | プレフィックス | 貢献 |
 | --- | --- | --- | --- |
 | 3 を最初に配置します | 小さい比率を選択する | 0 | 2 * (1 + 0) = 2 |
 | 2 位 | 3以降 | 1 | 5 * (1 + 1) = 10 |

 ルートでの合計コストは 12 です。 

順序を入れ替えると、次のようになります。 

| ステップ | ノード順序の決定 | プレフィックス | 貢献 |
 | --- | --- | --- | --- |
 | 2 を最初に配置します | 悪い順序 | 0 | 5 * (1 + 0) = 5 |
 | 3秒位 | 2以降 | 1 | 2 * (1 + 1) = 4 |

 総コストは 9 になり、比率に基づいた正しい順序付けの重要性がわかります。 

これは、貪欲な順序付けが恣意的ではなく、サブツリー サイズがコストをどのように伝播するかによって構造的に決定されることを示しています。

 ## 特殊なケース

 リーフ ノードは、サイズ 1 を提供し、子を持たないため、自然に処理されます。そのため、その dp 値はゼロのままで、他の場所の順序付けには影響しません。 

子が 1 つあるノードでは順序のあいまいさが発生せず、プレフィックスの累積はゼロのままであるため、コストはエッジの重みの 1 倍の単純な重み付き距離に減少します。 

誤った順序付けが蓄積されたプレフィックス サイズ効果の二次爆発につながるため、高次ノードは最も敏感なケースです。 アルゴリズムは、派生した比率ルールを使用して子を一度並べ替えることによってこれを処理し、すべてのペアごとの相互作用が一貫して最適化されるようにします。 

重みがゼロのエッジは、目的への寄与がゼロであるため、順序付けには影響しません。 事実上、その子がコストの考慮事項から除外されるため、比率の比較では正しく無関係になります。
