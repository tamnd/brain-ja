 ## 問題の理解

 私たちは、すべてのノードが常に正確に$k$子への発信エッジ。 それらのそれぞれ$k$エッジには固定の重みがあります。最初の重みは 1、2 番目の重みは 2 など、最大で$k$。 ルートから、子を段階的に通過する下向きのパスを検討し、そのたびに次のいずれかを選択します。$k$エッジ。 

パスは単純にルートから始まる一連のエッジ選択であり、その総コストはそのルートに沿って使用されるエッジの重みの合計です。 合計の重みが正確に一致するパスのみに関心があります。$n$。 それらの中で、重みが少なくとも 1 つ以上のエッジを含むパスのみをカウントします。$d$、少なくとも 1 つのステップがラベル付きのエッジを使用することを意味します。$d, d+1, \dots, k$。 

したがって、タスクは、以下の制約された構成をカウントすることです。$n$: 各ステップは値に寄与します。$[1, k]$、順序は重要であり、シーケンスには少なくとも 1 つの「大きな」ステップ (少なくとも$d$）。 各選択肢は個別の子にも対応するため、たとえ同じ重みを持っていても、異なるシーケンスは個別に区別されます。 

制約$n, k \le 100$「これまでの合計」や「制約が満たされるかどうか」などの状態に対する二次または三次動的計画法ソリューションで十分であることが明確になります。 シーケンスの数が次のように増加するため、シーケンスに対して指数関数的なものは実行不可能です。$k^n$、これは中程度の場合でも天文学的に大きくなります。$n$。 

単純な試みでは、総重量のすべてのシーケンスを列挙しようとする可能性があります。$n$。 現在の合計によって枝刈りしたとしても、シーケンスの数は一般化されたフィボナッチ爆発のように動作します。 たとえば、$k=3$そして$n=20$、部分パスの数はすでに数百万を超えています。 これにより、ブルートフォースは即座に不可能になります。 

微妙なエッジケースが現れるのは、$d = 1$。 この場合、すべてのエッジは「大きい」ので、すべての有効な分解は$n$部品に分割$[1,k]$許容されます。 もう一つのエッジケースは、$d = k$、ここでは体重のステップのみ$k$大きいとみなされるため、シーケンスには少なくとも 1 つが含まれている必要があります。$k$。 「少なくとも 1 つの大きなエッジ」という条件を忘れた不用意な解決策は、どちらの状況でもオーバーカウントになります。 

## アプローチ

ただし、合計のあるどの状態からでも$s$まであります。$k$トランジションと深さが到達可能$n$。 これにより、おおよその結果が得られます$O(k^n)$最悪の場合のシーケンスですが、これは完全に不可能です。 

重要な観察は、シーケンス全体を記憶する必要はなく、現在の合計と少なくとも 1 つの「大きな」エッジを既に使用したかどうかという 2 つの情報だけを記憶する必要があるということです。 これは、合計の接頭辞に対する動的プログラミングを直ちに示唆します。 

残りの合計または現在の合計に対する DP と、条件が満たされているかどうかを示すバイナリ状態を定義します。 遷移は単純です: 合計から$i$、それぞれの重みを加算してみます$w \in [1,k]$、次のいずれかに応じて合計とフラグの両方を更新します。$w \ge d$。 

これにより、選択肢の指数関数的なツリーが階層化されたグラフに変わります。$n$州、各州は最大でも$k$発信トランジション、与える$O(nk)$複雑。

 ## アルゴリズムのチュートリアル

 次元がこれまでに達成された合計である動的プログラミング テーブルを構築し、「大きなエッジ」が使用されたかどうかを追跡します。 

1. DP テーブルを定義する$dp[i][0/1]$、 どこ$i$は現在の合計であり、2 番目の次元は重み付きのエッジを少なくとも 1 つ使用したかどうかを示します$\ge d$。 この構造により、履歴全体が最終条件に関連する唯一の情報に圧縮されます。 
2.初期化$dp[0][0] = 1$。 これは、エッジを取得する前のルートの空のパスを表します。 エッジが取られていないため、大きなエッジはまだ使用されていません。 
3. 以下のすべての合計を反復処理します。$0$に$n-1$。 各状態は、すでに特定の合計重みを持つ部分パスを表します。 
4. 各州から$(i, flag)$、すべてのエッジの重みを試してください$w$1から$k$。 もし$i + w \le n$、パスを 1 ステップ延長できます。 これは、ツリー内の 1 つの子エッジを選択することに正確に対応します。 
5. 移行時に、新しいフラグを次のように計算します。$flag \lor (w \ge d)$。 これにより、一度大きなエッジを使用すると、そのプロパティが状態に永続的に記憶されることが保証されます。 
6. 現在の状態から次の状態に至るまでの経路の数を加算します。$dp[i + w][new\_flag] += dp[i][flag]$、モジュロを取る$10^9 + 7$。 
7. 表に記入すると、答えは次のようになります。$dp[n][1]$、合計が正確に欲しいので$n$少なくとも 1 つの大きなエッジが使用されます。 

### なぜ効果があるのか

 すべての有効なルートからノードへのパスは、重みの合計が次のようなエッジ選択のシーケンスに一意に対応します。$n$。 各遷移は単一の有効なエッジ選択肢を追加するため、DP はそのようなシーケンスをすべて 1 回だけ列挙します。 将来の遷移は、以前の小さなエッジの順序ではなく、残りの合計と制約がすでに満たされているかどうかのみに依存するため、状態圧縮は安全です。 したがって、2 つの異なる有効なシーケンスが誤ってマージされることはなく、無効なシーケンスが到達することはありません。$dp[n][1]$フラグが制約を正しく強制するためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n, k, d = map(int, input().split())

dp = [[0, 0] for _ in range(n + 1)]
dp[0][0] = 1

for i in range(n + 1):
    for used in range(2):
        if dp[i][used] == 0:
            continue
        cur = dp[i][used]
        for w in range(1, k + 1):
            if i + w > n:
                break
            nxt_used = used or (w >= d)
            dp[i + w][nxt_used] = (dp[i + w][nxt_used] + cur) % MOD

print(dp[n][1])
```DP テーブルには、大きなエッジの使用の有無にかかわらず、各合計に到達する方法の数が保存されます。 外側のループは合計を昇順に処理するため、すべての遷移は常に前に進み、以前の状態に戻ることはありません。 

1 から 2 までの重みにわたる遷移ループ$k$各ノードには次の要素があるため、ツリー構造を正確に反映します。$k$それらのエッジウェイトを持つ子供たち。 早めの休憩のとき、$i + w > n$重量が増加しているため、それ以降の重量もすべて超過するため、これは安全です$n$。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def solve():
    n, k, d = map(int, sys.stdin.readline().split())
    dp = [[0, 0] for _ in range(n + 1)]
    dp[0][0] = 1

    for i in range(n + 1):
        for used in range(2):
            cur = dp[i][used]
            if not cur:
                continue
            for w in range(1, k + 1):
                if i + w > n:
                    break
                nd = used or (w >= d)
                dp[i + w][nd] = (dp[i + w][nd] + cur) % MOD

    print(dp[n][1])

def run(inp: str) -> str:
    global input
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    old = sys.stdout
    sys.stdout = out
    solve()
    sys.stdout = old
    return out.getvalue().strip()

# provided sample
assert run("3 3 2\n") == "3"

# minimum case
assert run("1 1 1\n") == "1"

# no valid large edge possible
assert run("3 2 3\n") == "0"

# all edges are large
assert run("3 3 1\n") == "4"

# boundary k=n
assert run("4 4 3\n") >= "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3 3 2 | 3 | サンプルの正確性 |
 | 1 1 1 | 1 | 最小の非自明なパス |
 | 3 2 3 | 0 | 大きなエッジ条件を満たすことが不可能 |
 | 3 3 1 | 4 | すべてのエッジが大きいため、すべてのシーケンスが有効です。 

## 特殊なケース

 いつ$d = 1$、すべてのエッジは大きいとみなされるため、答えは、次のすべての構成を数えることになります。$n$パーツを使って$1..k$。 エッジが取られるたびに、すべての遷移がすぐにフラグを 1 に設定するため、DP は引き続き機能します。$dp[i][1]$最初のステップの後に関連します。 

いつ$d = k$、最大のエッジのみが制約に影響します。 DP は、決して使用しないシーケンスを正しく追跡します。$k$で$dp[*][0]$、に移動するだけです$dp[*][1]$いつ$k$が選ばれます。 これにより、合計に達した場合でも無効なシーケンスがきれいに分離されます。$n$、次の場合を除いてカウントされないことを保証します。$k$少なくとも 1 回は表示されます。
