 ## 解決策
 ## 問題の理解

 「ブラックスクエア」では、陪審員は黒い正方形が現れるたびに 4 つの垂直ストリップの 1 つを押す必要があります。 各ストリップには、それを押すためのカロリーで測定される固定のエネルギーコストがあります。 1 番目から 4 番目のストリップを押したときに消費されるカロリーを表す 4 つの整数が与えられます。 ゲームの進行は文字列によって記述されます。各文字は「1」から「4」までの数字であり、その秒時点でどのストリップに正方形があるかを示します。 タスクは、このシーケンスに従い、対応するストリップを押して、陪審員が消費する総カロリーを計算することです。 

入力は最大 105 ゲーム秒を保証するため、私たちのソリューションは各キャラクターを効率的に、理想的には線形時間で処理する必要があります。 各カロリーコストはゼロになる可能性があります。つまり、ストリップを押してもエネルギーを消費しない可能性があります。 エッジ ケースには、完全に 1 種類のストリップである文字列、交互のストリップ、または最大長が 105 である文字列が含まれます。文字ごとに繰り返し検索または複雑な操作を実行する単純なソリューションでは、制限時間を超える可能性があります。 

すべてのカロリーコストがゼロの場合、微妙なエッジケースが発生します。 たとえば、入力が次の場合`0 0 0 0`そして`s = "12341"`、正しい出力は次のとおりです。`0`しかし、たとえば、すべての印刷機が少なくとも 1 カロリーを提供すると仮定するような不用意なアプローチは、間違った結果をもたらすでしょう。 

## アプローチ

 ブルートフォースアプローチは、文字列を反復処理し、文字ごとに対応するカロリーコストにマッピングし、それを累計に加算することです。 これが機能するのは、各秒が独立しているためです。 特定のストリップのコストを知る必要があるだけです。 すべての文字を検査する必要があり、最悪の場合の複雑さが文字列の長さに比例するため、総当り攻撃は技術的にはすでに最適化されています。 

このアプローチが十分であることを確認する重要な観察は、ストリップ間に相互作用がないことです。 カロリーは加算されるものです。 各ルックアップは定数時間の操作であるため、最適化や複雑なデータ構造は必要ありません。 文字「1」から「4」をカロリー配列内の対応するインデックスに直接マッピングすることにより、総カロリーを効率的に蓄積できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 1 番目から 4 番目のストリップのカロリーを表す 4 つの整数を読み取ります。 リストに保存する`calories`直接インデックス作成用。 
2. 文字列を読み取ります`s`黒い四角の連続を表します。 
3. 変数を初期化する`total`カロリーカウントを蓄積するにはゼロにします。 
4. 各文字を反復処理します。`c`文字列の中で`s`。 変換する`c`を整数に変換し、0 から始まるインデックスと一致するように 1 を引いてから、アクセスします。`calories`そのインデックスに値を追加します`total`。 
5. すべての文字を処理した後、次の値を出力します。`total`。 

機能する理由: アルゴリズムは、次の不変条件を維持します。`total`処理されたすべてのストリップのカロリーの合計は常に等しくなります。 すべてのキャラクターは正確に 1 回処理され、そのコストに直接マッピングされるため、カロリーが見逃されたり二重にカウントされたりすることはありません。 決勝戦`total`したがって、 はすべての秒間の合計となり、問題の要件を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# read calorie costs for each strip
calories = list(map(int, input().split()))
s = input().strip()

total = 0
for c in s:
    total += calories[int(c) - 1]

print(total)
```最初の行は 4 つのカロリー値を読み取り、リストに保存します。 から 1 を引くと、`int(c)`「1」～「4」からゼロから始まるリストのインデックスへのマッピングが正しいことを保証します。 ループは適切なカロリー値を直接追加します。`total`条件チェックや分岐はありません。 これにより、off-by-one エラーが回避されます。 誤って改行文字が処理されないように、文字列から空白が削除されます。

## 複雑さの分析

 | --- | --- | --- |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    calories = list(map(int, input().split()))
    s = input().strip()
    total = 0
    for c in s:
        total += calories[int(c) - 1]
    return str(total)

# provided sample
assert run("1 2 3 4\n123214\n") == "13", "sample 1"

# custom cases
assert run("0 0 0 0\n12341\n") == "0", "all zero calories"
assert run("1 1 1 1\n11111\n") == "5", "all same strip"
assert run("1 2 3 4\n4321\n") == "10", "descending order"
assert run("10 20 30 40\n444444\n") == "240", "repeated max strip"
assert run("5 5 5 5\n1\n") == "5", "single element"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 0 0 0 0 / 12341 | 0 | ゼロカロリーストリップの取り扱い |
 | 1 1 1 1 / 11111 | 5 | 同じストリップを繰り返し押す |
 | 1 2 3 4 / 4321 | 10 | 降順シーケンスの正しいインデックス マッピング |
 | 10 20 30 40 / 444444 | 240 | 最後のストリップを複数回押す |
 | 5 5 5 5 / 1 | 5 | 最小入力サイズ |

 ## 特殊なケース

 すべてのカロリー値がゼロになると、`total`順序に関係なくゼロのままです。 たとえば、入力`0 0 0 0\n12341`生成する`0`。 アルゴリズムは、次のように長さ 1 の文字列を正しく処理します。`5 5 5 5\n1`、最初のストリップのコストを 1 回追加するだけです。 単一のストリップを繰り返し押す場合、たとえば`11111`すべてのカロリーが 1 の場合、アルゴリズムは合計を正しく累積し、複数の同一文字にわたって不変条件が保持されることを確認します。
