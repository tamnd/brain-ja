 ## 解決策
 ## 問題の理解

 数直線上にいくつかの閉区間が与えられます。 各間隔は、その端点間の一連の整数または実数点を表し、端点自体も含まれます。 タスクは、この新しい間隔が指定された間隔ごとに少なくとも 1 つの共通点を持つように、追加の間隔を 1 つ構築することです。 このようなすべての有効な間隔の中で、可能な限り短い長さの間隔が必要です。長さは、右端点から左端点を引いたものとして定義されます。 

より構造的な用語で言い換えると、指定されたすべてのセグメントに同時に「接触」するセグメントを探しています。 タッチするとは、各入力セグメントに対して、新しいセグメントが少なくとも 1 点で重なる必要があることを意味します。 目標は、オーバーラップを最大化することではなく、普遍的な交差特性を維持しながら、構築されるセグメントのサイズを最小化することです。 

この制約により、すべてのテスト ケースにわたって最大 100,000 個のセグメントが許可されます。 これにより、すべての候補区間を試したり、すべてのペアや組み合わせを明示的にチェックしたりするアプローチは即座に除外されます。 二次関数または偶数関数$O(n \log n)$テスト ケースごとのソリューションは、不用意に繰り返すと境界線に達してしまうため、目的のソリューションでは各テスト ケースを数回の線形スキャンに減らす必要があります。 

よくある失敗モードは、要件をすべての間隔に共通の点を見つけるものと誤解することから発生します。 これは、すべての間隔の交差部分が空でないかどうかを確認することと同じになります。 たとえば、間隔が次の場合、$[1,2]$そして$[3,4]$、共通点がないため、単純なアプローチでは解決策がないと結論付けられる可能性があります。 しかし、正しい答えは依然として有効です。次のように、両方に重なるセグメントを選択できます。$[2,3]$これは、タスクが 1 つのセグメントで区間をカバーすることであり、すべての区間を 1 点で交差させることではないことを示しています。 

もう 1 つの微妙な問題は、指定されたセグメントのエンドポイントのみを考慮する必要があると仮定していることです。 この直感はほぼ正しいですが、最適な構築の議論を通じて慎重に正当化する必要があります。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての候補セグメントを列挙し、それぞれのセグメントがすべての入力セグメントと交差するかどうかをテストしようとします。 セグメントエンドポイントの範囲は最大であるため、$10^9$、これは離散化しても実現不可能です。 候補を入力セグメントのエンドポイントに制限したとしても、$O(n^2)$可能な間隔を調べ、すべてのセグメントに対してそれぞれをチェックすると、次のようになります。$O(n^3)$、それは限界をはるかに超えています。 

重要な観察は、「新しいセグメントはすべてのセグメントと交差しなければならない」という制約を、各セグメント内の 1 つの点を選択し、選択したすべての点を可能な限り最短の間隔でカバーするという観点から書き換えることができるということです。 ポイントを選ぶなら$x_i$各インターバル内で$[l_i, r_i]$の場合、有効なセグメントはすべてをカバーする必要があります。$x_i$。 一連の点をカバーする最短のセグメントは次のようになります。$[\min x_i, \max x_i]$、したがって、その長さは$\max x_i - \min x_i$。 

残りの問題は、この範囲が最小になるように、間隔ごとに 1 つの代表点を選択することです。 最適な構造は、極端な位置のみが重要であるという事実から生まれます。 選択したポイントが間隔内にある場合、その間隔の実現可能性を損なうことなく、いつでもどちらかの端点に向かって移動できます。この移動は、全体の範囲を縮小または維持するのにのみ役立ちます。 

これにより、問題は 2 つの候補による最適化に縮小されます。各間隔について、その左端点または右端点のみが考慮されます。 最適なソリューションは、それぞれの条件を満たす選択から導き出される必要があります。$x_i$どちらかです$l_i$または$r_i$。 次に、そのような選択によってもたらされる最適な範囲を計算します。 構造はさらに単純化されます。最適な答えは、「ピボット間隔」を選択し、それに対して他のものを整列させるというすべての選択肢の最小値に対応します。これは、エンドポイントの並べ替えから得られる極値制約をチェックすることになります。 

より直接的で標準的な単純化はさらにすっきりします。 すべての間隔と交差する最小セグメントは、点を選択することによって決定されます。$x$すべての間隔に周囲のセグメント内に少なくとも 1 つの点が含まれるようにする$x$。 最適なセグメントのエンドポイントは、右側のエンドポイントのグローバル最小値と左側のエンドポイントのグローバル最大値の間に存在する必要があります。 最小限必要な長さは、正しいペア構造を考慮した上で、これら 2 つの値を適切に順序付けした場合の、これら 2 つの値の間のギャップです。 これにより、エンドポイントがソートされ、隣接する構造が暗黙的に検査され、ソート後に単純な線形計算が行われます。 

実際には、既知の解決策は、構造化された方法ですべてのエンドポイントをソートし、各間隔から少なくとも 1 つのエンドポイントをカバーする達成可能な最小のスパンを計算することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースのすべての間隔を読み取り、それらをペアとして保存します$(l_i, r_i)$。 この表現では、重複を推論するために必要なすべての情報が保存されます。 
2. 間隔を左側の端点で並べ替えます。 ソートにより安定した順序が得られるので、どの程度の間隔でカバー セグメントを強制的に引き伸ばすことができるかを推論することができます。 
3. ソートされた順序で間隔をスイープするときに、これまでに確認された最大の右端点を追跡します。 これは、以前の間隔との重複を確保するために必要な最悪の場合の拡張を表します。 
4. 現在の間隔制約によってカバーセグメントがどの程度拡張されるかを比較することにより、可能な限り最小の候補回答を維持します。 各ステップで、現在の間隔の左側の境界を、これまでに確認された最大の右側の境界と比較します。 
5. キー量は、逆視点での左端点の現在の最大値と右端点の現在の最小値との差のすべての指標にわたる最小値として現れ、これはスイープ中に効率的に計算できます。 
6. 各テスト ケースの最小計算長を出力します。 

### なぜ効果があるのか

 有効なセグメントはすべての間隔で交差する必要があります。つまり、各間隔の少なくとも 1 つのポイントが含まれている必要があります。 間隔が 1 つのエンドポイントによってソートされる場合、セグメントが強制的に拡大される唯一の方法は、新しい間隔が以前の間隔によって暗示された現在の実行可能領域の外側に完全に存在する場合です。 スイープはこれらの制約違反を正確に捕捉します。 すべての間隔はそのエンドポイントを通じてのみ寄与し、実行可能性を弱めることなく内部の選択をエンドポイントにプッシュできるため、最適なソリューションはスキャン中にキャプチャされた境界イベントで実現される必要があります。 これにより、計算された最小スパンが実行可能なカバー セグメントに正確に対応し、より小さなセグメントがすべての間隔制約を同時に満たすことができないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        seg = [tuple(map(int, input().split())) for _ in range(n)]

        # sort by left endpoint
        seg.sort()

        # we track constraints
        max_left = seg[0][0]
        min_right = seg[0][1]
        ans = float('inf')

        for l, r in seg[1:]:
            # update feasible region overlap structure
            max_left = max(max_left, l)
            min_right = min(min_right, r)

            # candidate gap between extremes
            ans = min(ans, max(0, max_left - min_right))

        print(ans)

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを個別に処理します。 並べ替えにより、左側のエンドポイントの昇順で間隔が検査されるようになり、意味のある実行制約を維持できるようになります。 変数`max_left`そして`min_right`より多くの間隔が考慮されるにつれて、実現可能なオーバーラップのウィンドウが狭まっていることを表します。 現在の最大の左端点が現在の最小の右端点を超えると、強制的な分離が発生し、そのギャップが候補の答えに寄与します。 

微妙なディテールは、`max(0, max_left - min_right)`。 現在の交差が空でない場合、値はゼロです。これは、すべての処理された間隔に共通の点が存在することを意味します。 それ以外の場合、ギャップは制約がどれだけ離れているかを表し、制約をブリッジするために必要な最小セグメント長に直接変換されます。

 ## 特殊なケース

 次のような素な間隔の場合$[1,2]$そして$[10,11]$、スイープは次の場合にすぐに大きなギャップを生成します。`max_left`その間は10になります`min_right`は 2 のままです。計算された値`max_left - min_right`は 8 になります。これは、まさに分離を埋めるために必要な最小限のセグメントです。 

完全に重複する間隔の場合$[1,5], [2,6], [3,7]$、走行中の交差点が空になることはありません。`max_left`決して超えない`min_right`、したがって、ギャップは全体を通してゼロのままであり、正しい答えが生成されます。 

チェーンを通じて間隔が間接的にオーバーラップする混合オーバーラップ パターンの場合、実行中の min-max 構造により、明示的なペアごとの比較を必要とせずにオーバーラップの伝播が正しくキャプチャされることが保証されます。
