 ## 解決策
 ## 問題の理解

 整数の固定配列と多くのクエリが与えられます。 各クエリでは、正確に選択することを想像する必要があります。$k$元の順序を維持したまま配列から要素を取得します。 このような長さの部分列すべての中で$k$, まず、可能な最大の合計値を持つものが必要です。 この最大合計に達するすべての部分列の中で、辞書編集的に最小のものを選択します。 

この特別なサブシーケンスが特定のオブジェクトに対して修正されると、$k$、各クエリはその中の単一の位置を要求します。 

重要な難点は、$k$クエリごとに変更があり、最大で$2 \cdot 10^5$したがって、クエリごとにソリューションを最初から再計算することは不可能です。 

この制約により、前処理でのソリューションがほぼ線形またはほぼ線形になるようにし、クエリごとに対数または定数が適用されます。 クエリごとにサブシーケンスを貪欲に繰り返し構築すると、約$O(nm)$、これは大きすぎます。 

複数のサブシーケンスの最大合計が同じである場合、微妙な失敗のケースが発生します。 たとえば、配列に繰り返し値が含まれている場合、「利用可能な次に大きいものを常に選択する」という貪欲なアプローチでは、位置構造が無視されます。 辞書編集的な最小化では、サブシーケンス内の以前の位置ができるだけ小さくなるように強制されます。これには、等しい値が以前に出現することを優先する必要がある場合があります。 

もう 1 つの注意が必要な状況は、値が等しいかほぼ等しい場合に発生します。2 つの部分列の合計が同じである可能性がありますが、順序の選択が異なると、辞書編集上の結果も異なります。 合計を追跡するだけの単純なアプローチでは、間違ったサブシーケンスが返されます。 

たとえば、次のことを考えてみましょう。```
a = [5, 1, 5]
k = 2
```両方のサブシーケンス`[5,5]`そして`[5,5]`の合計は同じですが、辞書編集上のタイブレークにより、最初に前の 5 が選択されるため、値だけでなく位置に依存する決定的な構造が生じます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各クエリについて、次の長さのすべてのサブシーケンスを試します。$k$、それらの合計を計算し、合計が最大のものだけを保持し、その中から辞書順に最小のものを選択します。 これはすぐに指数関数的になります$n$、あるので$\binom{n}{k}$後続。 

クエリごとに動的プログラミングを使用して改善したとしても、クエリごとに最適なサブシーケンスを計算します。$k$独立してコストがかかる$O(nk)$または$O(n \log n)$クエリごとに、依然として下位に達します$2 \cdot 10^5$クエリ。 

重要な観察点は、この問題は実際にはすべての項目について再計算する必要がないということです。$k$。 要素を値で並べ替えると、サイズの最適な部分列が$k$は常に、$k$配列内の最大の要素ですが、制約があります。元の順序を保持する必要があるため、実際にはサイズを選択しています。$k$最大値を持つインデックスのサブセット。 これはトップを選択するのと同じです$k$要素を値で並べ替えて、元の順序に戻します。 

このように表示すると、構造は静的になります。インデックスを値の降順で、プレフィックスごとに並べ替えることができます。$k$、どのインデックスが選択されているかを正確に知っています。 残りの課題は、$pos$その順序付けられたサブシーケンス内の - 番目の要素。 

要素が「アクティブ化」される順序を次のように前処理できます。$k$1から$n$。 新しい要素を (値の降順で) 含めるたびに、ソートされた位置を維持する構造にその位置を挿入します。 次に、各プレフィックス$k$は選択されたインデックスのソートされたリストに対応しており、バイナリ リフティングまたはセグメント ツリー順序統計構造を使用して位置クエリに答えることができます。 

クリーンな実装では、フェンウィック ツリーを使用してどのインデックスが選択されているかを維持し、k 次の統計をサポートします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | 指数関数的 /$O(n^2 m)$|$O(n)$| 遅すぎる |
 | 最適 (ソート + BIT) |$O(n \log n + m \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列のすべてのインデックスを値の降順に並べ替えます。 

これにより、要素を徐々に「アクティブ化」するときに、合計を最大化するために必要な次に最適な値が常に追加されるようになります。 
2. アレイを構築する`order`、 どこ`order[t]`サブシーケンス サイズから移動するときに使用可能になる要素のインデックスです$t-1$に$t$。 
3. ポジションに対するフェンウィック ツリー (または任意の注文統計構造) を維持する$1 \ldots n$、最初は空です。 
4. それぞれについて$k = 1 \ldots n$、 入れる`order[k]`フェンウィックの木の中へ。 

このステップの後、ツリーはサイズに最適なサブシーケンスのインデックスを正確に表します。$k$、インデックスの昇順で格納されます。 
5. それぞれからマッピングを事前計算します。$k$フェンウィック ツリーを介して、選択された位置のソートされたリストに暗黙的に送信されます。 
6. 質問に答えるには$(k, pos)$を見つけてください。$pos$-最初のアクティブなインデックスの中で 2 番目に小さいアクティブなインデックス$k$挿入された要素。 

これは標準的なフェンウィック ツリーの「k 番目」クエリです。 
7. 元の配列のそのインデックスの値を返します。 

### なぜ効果があるのか

 いつでも固定$k$、最適なサブシーケンスには、正確に$k$配列内の最大値。 より大きな未使用の値が存在するときに、より小さな値が含まれている場合、それを置き換えると合計が増加し、最適性に矛盾します。 等和の選択肢の中で、インデックスを昇順に選択すると、可能な場合は常に前の位置が優先されるため、辞書編集的に最小のサブシーケンスが得られます。 フェンウィック ツリー構造では、まさにこの不変条件が適用されます。$k$が含まれています。$k$最も高い値の要素を検索し、それらをソートされたインデックス順に読み取ると、必要な辞書編集上最小限の有効なシーケンスが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def kth(self, k):
        idx = 0
        bitmask = 1 << (self.n.bit_length())
        while bitmask:
            nxt = idx + bitmask
            if nxt <= self.n and self.bit[nxt] < k:
                k -= self.bit[nxt]
                idx = nxt
            bitmask >>= 1
        return idx + 1

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    order = sorted(range(n), key=lambda i: a[i], reverse=True)

    bit = Fenwick(n)
    ptr = 0

    queries = []
    for _ in range(int(input())):
        k, pos = map(int, input().split())
        queries.append((k, pos, _))

    ans = [0] * len(queries)

    # sort queries by k
    queries.sort()

    for k, pos, qi in queries:
        while ptr < k:
            bit.add(order[ptr] + 1, 1)
            ptr += 1
        idx = bit.kth(pos)
        ans[qi] = a[idx - 1]

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```解決策は、値の降順でインデックスを並べ替えることから始まり、これによって要素が候補セットに入る順序が決まります。 フェンウィック ツリーは、現在選択されているインデックスを維持します。 

各クエリは正確に保証された後に処理されます$k$要素が挿入されました。 その後、フェンウィック ツリーにより、$pos$-番目に選択された対数時間のインデックス。 戻り値は、単にそのインデックスの配列値です。 

よくある間違いは、サブシーケンスを形成するときに元のインデックスの順序を保持する必要があることを忘れることです。 フェンウィック ツリーは、インデックスを保存し、常にインデックスの昇順で取得することで、この問題を暗黙的に解決します。 

もう 1 つの微妙な点は、Fenwick ツリーにおける 1 から始まるインデックス付けです。 0 から始まる配列インデックスと 1 から始まるツリー位置を混合すると、off-by-one エラーが頻繁に発生します。

 ## 特殊なケース

 完全に等しい配列は、値が同点になると、選択順序が純粋にインデックス駆動であることを示します。 このアルゴリズムは値の昇順にインデックスをアクティブにしますが、すべての値は同一であるため、フェンウィック ツリーはインデックスのプレフィックスを選択することになります。 クエリは、pos 番目に小さいインデックスを正しく返します。 

配列を厳密に増加させると、逆の極端な結果が得られます。つまり、最大値が最後にあるため、アクティブ化は右から左に行われます。 任意のサブシーケンス$k$になります$k$フェンウィック ツリーは、それらが辞書編集要件に一致するインデックスの昇順で返されることを保証します。 

単一要素の配列は、フェンウィック ツリーが最小入力サイズで壊れないこと、および k=1 の k 番目のクエリが常に唯一のインデックスを返すことを検証します。
