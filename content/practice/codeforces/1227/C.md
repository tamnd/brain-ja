 ## 問題の理解

 一連のかっこが与えられ、隣接するセグメントを反転する操作を適用できます。 このような反転のシーケンスを適用した後、有効なバランスの取れた括弧シーケンスを取得する必要がありますが、非常に特殊な構造を持っています。左から右にスキャンすると、正確に`k`プレフィックス自体が完全なバランスの取れた括弧シーケンスである位置。 

要件を解釈する別の方法は、正しい括弧シーケンスがどのように分解されるかを調べることです。 すべてのバランスの取れたシーケンスは、「プリミティブ ブロック」に一意に分割できます。各ブロックはバランスのとれた最小のプレフィックスであり、その中に以前のバランスのとれたプレフィックスは含まれません。 それ自体が有効な完全なシーケンスであるプレフィックスの数は、まさにそのようなプリミティブ ブロックの数です。 したがって、タスクは、指定された文字列を有効な括弧シーケンスに正確に変換することです。`k`原始的なコンポーネント。 

入力が`n/2`オープニングと`n/2`右括弧なので、解決策は常に存在します。 

この操作は強力です。部分文字列を反転すると、文字の位置を任意に効果的に再配置できますが、これはセグメントの反転によってのみ可能です。 まで許されているので、`n`操作と`n ≤ 2000`、複雑な最適化に依存するのではなく、文字列を段階的に修正する建設的な戦略を講じることができます。 

プレフィックスのバランスを貪欲に考えると、微妙なエッジケースが発生します。 単純な試みでは、プレフィックスを有効にすることでローカルで「バランスを修正」しようとする可能性があります。 局所的な修正によって後で構造が破壊される可能性があるため、これは失敗します。 もう 1 つの失敗モードは、明示的なターゲット シーケンスを構築せずにプレフィックス バランスを直接制御しようとすることです。これにより、反転操作との調整が困難になります。 

正しい見方は、構築中にプレフィックスのバランスの観点から考えるのをやめ、代わりに、最初に最終的なターゲットの形状を決定し、その後、最初の文字列をそれに変換することです。 

## アプローチ

 強引なアイデアは、各状態をノードとして扱い、すべての部分文字列の反転を試み、BFS を使用して有効な最終構成を検索することです。 各州には大まかに`O(n^2)`遷移し、状態空間は指数関数的になります。`n`。 たとえ`n = 200`、これは完全に不可能になります。 

重要な洞察は、検索する必要がまったくないということです。 正確に有効な最終シーケンスを明示的に構築できます。`k`プリミティブ ブロックを作成し、初期文字列を決定論的にプリミティブ ブロックに変換します。 

正確な値を持つ有効なシーケンスの構造`k`通常のプレフィックスの位置は単純です。 私たちはまさにそれを望んでいます`k`プレフィックスが完全にバランスが取れたとき。 最もクリーンな構造は、`k-1`最小限のブロック`"()"`、その後に残りのかっこを含む 1 つの大きなバランスのとれたブロックが続きます。```
"()" * (k - 1) + "(" * a + ")" * a
```どこ`a = n/2 - (k - 1)`。 

これは正確に保証します`k`プリミティブコンポーネント: それぞれ`"()"`は 1 つ貢献し、最後の大きなブロックはさらに 1 つ貢献します。 

このターゲット文字列を修正すると、残りの問題は、部分文字列の反転を使用して、ある文字の並べ替えを別の並べ替えに変換することになります。 これは、左から右に貪欲に行うことができます。文字列の後半で文字を見つけ、セグメントを反転して前に出すことで、各文字を正しい位置に配置します。

 ## アルゴリズムのチュートリアル

 まずターゲット文字列を構築し、次に入力をそれに変換します。 

### 1. ターゲット構成を構築する

 次からなる文字列を形成します`k-1`のコピー`"()"`、その後に残りのブロックが続きます`'('`その後`')'`。 

これにより正確に保証されます`k`原始的なバランスのとれたコンポーネントは、それぞれ`"()"`はスタンドアロン プリミティブであり、最後のブロックは 1 つの大きなプリミティブです。 

### 2. 入力を貪欲にターゲットに変換する

 位置を左から右に処理します。 

ポジションごとに`i`現在のキャラクターがすでにターゲットと一致している場合は、何も行いません。 それ以外の場合は、位置を前方に検索します`j`そのような`s[j]`で必要な文字と等しい`i`。 

次に部分文字列を反転します`[i, j]`。 これにより、必要な文字が所定の位置に配置されます`i`そのセグメント内のすべての文字を保持しながら、順序を変更するだけです。 

このステップは、文字列全体がターゲットと一致するまで繰り返されます。 

### 3. 出力操作

 それぞれの逆転が記録されます。 操作数は最大で`n`各操作で少なくとも 1 つの位置が永続的に固定されるためです。 

### なぜ効果があるのか

 それぞれのステップで`i`、位置を固定したら`i`、二度と触れることはありません。 これは、後の反転は厳密に より大きいポジションでのみ機能するためです。`i`。 したがって、正しさは、ステップで次のことを保証することに帰着します。`i`、同じ括弧の複数セットを並べ替えているだけなので、接尾辞で必要な文字を常に見つけることができます。 

最終的な文字列はターゲットと正確に一致し、ターゲットは正確に一致するように構築されています。`k`通常のプレフィックス。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = list(input().strip())

    # build target
    half = n // 2
    left_blocks = k - 1

    target = []
    target.extend("()" * left_blocks)
    remaining = half - left_blocks
    target.extend("(" * remaining)
    target.extend(")" * remaining)

    target = list(target)

    ops = []

    for i in range(n):
        if s[i] == target[i]:
            continue

        j = i
        while j < n and s[j] != target[i]:
            j += 1

        # reverse [i, j]
        s[i:j+1] = s[i:j+1][::-1]
        ops.append((i + 1, j + 1))

    print(len(ops))
    for l, r in ops:
        print(l, r)

if __name__ == "__main__":
    solve()
```ターゲットの構築は、設計上の選択の中核となります。 その構造が修正されると、残りのアルゴリズムは制御された並べ替えプロセスにすぎなくなります。 反転操作は、実装を単純にし、許可された操作数の範囲内でスワップをシミュレートするためのツールとしてのみ使用されます。 

実装の微妙な点は、文字列の構築中にバランスを明示的に追跡する必要がないことです。 すべてのバランス制約は最終ターゲットにエンコードされるため、正確性は純粋な文字列変換に限定されます。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。`k = 1`。 この場合、ターゲットは次のように配置されたすべての括弧で構成される単一の大きなプリミティブ ブロックになります。`"(" * (n/2) + ")" * (n/2)`。 アルゴリズムはまだ機能します。`"()"`プレフィックス ブロックが挿入され、貪欲な配置により完全にネストされた構造が構築されます。 

もう一つのケースは次のような場合です。`k = n/2`、ターゲットとなるのは`"()"`繰り返された`n/2`回。 ここではすべてのブロックがプリミティブであるため、2 文字ごとにペアを形成する必要があります。 以前の固定ペアに影響を与えることなく、必要な各文字を独立して所定の位置に引き込むことができるため、貪欲な逆転プロセスは引き続き成功します。 

失敗が発生しやすいシナリオは、構築中にプレフィックスの有効性を維持しようとすることです。 たとえば、スワップ中にプレフィックスのバランスを貪欲に確保しようとすると、誤って初期の有効なプレフィックスが導入されてしまう可能性があります。`k`。 ターゲットベースの構築では、有効なプレフィックスの正確な数を動的ではなく構造的にエンコードすることで、これを完全に回避します。
