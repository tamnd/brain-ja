 ## 解決策
 ## 問題の理解

 一連の数値が与えられているので、クエリごとに正確に選択することを想像する必要があります。`k`元の順序を維持しながら、このシーケンスから要素を抽出します。 このようなすべてのサブシーケンスの中で、最初に選択した値の合計を最大化することに注意します。 どの部分列が可能な最大合計を達成するかがわかったら、次に 2 番目のルールを課します。それらの最適合計部分列の中から、辞書編集的に最小のものを選択する必要があります。 

各クエリは完全なサブシーケンスを要求するのではなく、その特定に対して一意に決定された最適なサブシーケンス内の特定の位置の値のみを要求します。`k`。 

重要な問題は、多くのインデックスを選択すると同じ合計が得られるため、「固定長の最大合計部分列」が一意ではないことです。 辞書編集上のタイブレークでは、前の位置に関する一貫したルールが強制されます。つまり、2 つの選択肢の合計が同等に優れている場合は常に、前の要素をできるだけ小さくする方を優先します。 

制約は小さいです。`n ≤ 100`そして`m ≤ 100`。 これにより、セグメント ツリーやバイナリ インデックス付きツリーのような漸近的に最適な構造の必要性が即座に排除されます。 注意深く管理すれば、3 次または 4 次の推論でも受け入れられます。 クエリごとに何かを再計算するソリューションは依然として実行可能です。 

最大のものを選択することだけを考えると、素朴だが微妙な間違いが発生します。`k`要素をグローバルに。 順序を維持する必要があるため、これは失敗します。 もう 1 つのよくある落とし穴は、タイの処理です。左から右に貪欲に最大値を選択しても、すべての最大和サブシーケンス間で辞書編集上の最小構造が自動的に保証されるわけではありません。 

具体的な障害シナリオは次のとおりです。```
a = [5, 1, 5, 1], k = 2
```最大合計は 10 で、インデックス (1、3) を選択することで達成できます。 他の候補は (1,3) のみなので、これは自明です。 しかし、次のように変更すると、```
a = [5, 4, 5, 4], k = 2
```(1,3) と (1,4) の合計は 10 と 9 になりますか? 実際には、(1,3) と (1,4) の両方の合計が 10 と 9 だけが間違っています。 正しいのは (1,3)=10、(1,4)=9 なので同点ではありません。 より良い例:```
a = [4, 5, 4, 5], k = 2
```(2,4) と (1,4) は両方とも合計 10 を与えますが、辞書編集的に小さいのは (1,4) で [4,5] を生成しますが、貪欲な「遅い時間で最大値を取る」と、他の欠陥のある構造で誤って [5,5] 構造が選択される可能性があります。 これは、タイブレークが価値のみによるものではなく、構造的なものであることを示しています。 

## アプローチ

 ブルートフォース解釈では、長さのすべてのサブシーケンスが試行されます。`k`。 各サブシーケンスについて、その合計を計算し、最大値を追跡し、その中で辞書編集上最小のシーケンスを保持します。 あるので`C(n,k)`選択肢と各サブシーケンスの比較コスト`O(k)`、これはすぐに指数関数的になります。 でさえ`n = 100`、これは不可能です。 

重要な観察は、実際には明示的にサブシーケンスを列挙するように求められていないということです。 最終的なサブシーケンスの各位置について、どの元の要素がその位置を安全に占有しつつ、最適なソリューションを完成させることができるかを決定するだけで済みます。 

これは、貪欲な選択戦略を示唆しています。 サブシーケンスを左から右に構築しているとします。 各ステップで、残りのスロットを使用して最大の合計を達成できる、可能な限り早い位置を選択したいと考えています。 すべての値が正であるため、長さの最適な合計部分列は`k`は常に選択することによって形成されます`k`寄与度の点で最大の値を選択しますが、順序制限により、それらをシーケンス順に選択する必要があります。 

したがって、問題を次のように再解釈します。答えの各位置について、候補を左から右にスキャンし、要素を取得しても可能な限り最良の結果を完成できるかどうかを判断します。 実現可能性をテストするために、サフィックスの選択から達成可能な最大の合計と比較します。 

なぜなら`n ≤ 100`、すべての位置とすべての残りの長さについて、単純な DP を使用してそのサフィックスから取得できる最大合計を事前計算できます。 

実現可能性がわかったら、貪欲な構築が機能します。つまり、最適な合計を達成できる最小のインデックスを選択します。 このようなすべての有効な選択肢の中で、最も古いインデックスを選択すると、辞書編集的に最小限の順序が保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(n,k) · k · m) | O(k) | 遅すぎる |
 | DP + 貪欲 | O(n² + n·k·m) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 DP テーブルを事前計算します。`dp[i][len]`を選択することで得られる最大額です`len`インデックスで始まるサフィックスの要素`i`。 

1. ビルドする`dp`配列の最後から。 ポジションごとに`i`から`n`まで`1`、それぞれの長さ`len`、スキップするか、`a[i]`または、それをサブシーケンスの最初の要素として取得し、更新します`dp[i][len] = max(dp[i+1][len], a[i] + dp[i+1][len-1])`。 これは、任意のサフィックスからの達成可能な最良の合計をエンコードします。 
2. クエリごとに`(k, pos)`、最適なサブシーケンスを段階的に構築します。 位置から開始します`i = 1`そして選択する必要があります`k`要素。 
3. 各ステップで候補者を試します`i, i+1, ...`昇順で。 候補インデックスの場合`j`、摂取しているかどうかを確認します`a[j]`次に選択された要素でも最適な合計を達成できるためです。 選択した場合、達成可能な最高の合計を計算します。`a[j]`今プラス`dp[j+1][remaining-1]`。 
4. 最初のものを選択します`j`これが全体的な最適値と等しくなるように`dp[1][k]`。 そのインデックスはサブシーケンスの次の要素になります。 
5.選択後`j`、更新します`i = j + 1`そして減少します`k`1 つずつ繰り返し、サブシーケンスが完了するまで繰り返します。 

この貪欲な選択が機能する決定的な理由は、DP がすでに全体的な最適性をエンコードしているためです。 どのステップでも、選択によって最適な合計が得られる場合、それを後のインデックスに延期しても、合計は改善されずに辞書編集上の順序が増加するだけです。 したがって、最も早い有効な選択が常に安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
m = int(input())

# 1-indexed for convenience
a = [0] + a

# dp[i][len] = max sum using len elements from i..n
dp = [[0] * (n + 1) for _ in range(n + 2)]

for i in range(n, 0, -1):
    for length in range(1, n + 1):
        # skip i
        best = dp[i + 1][length]
        # take i
        if length > 0:
            best = max(best, a[i] + dp[i + 1][length - 1])
        dp[i][length] = best

def build(k, pos):
    res = []
    i = 1
    remaining = k
    target = dp[1][k]

    while remaining > 0:
        for j in range(i, n + 1):
            if remaining == 0:
                break
            if n - j + 1 < remaining:
                break

            val = a[j] + dp[j + 1][remaining - 1]
            if val == target - sum(res):
                res.append(a[j])
                i = j + 1
                remaining -= 1
                break
    return res[pos - 1]

for _ in range(m):
    k, pos = map(int, input().split())
    print(build(k, pos))
```DP テーブルはボトムアップで構築されるため、すべてのサフィックスの状態は使用前に既知になります。 貪欲な再構成では、グローバルな最適合計に到達できるインデックスのみを選択するように慎重に行われます。 

微妙な点の 1 つは、部分和の誤った再計算を避けることです。 現在の合計を維持するのではなく、DP の一貫性に依存します。 表現`target - sum(res)`概念的には、残りの必要な寄与を追跡しますが、最適化された実装では、サフィックス DP の状態を直接比較することでこれを回避できます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n² + m·n²) | DP は n×n テーブルを埋め、各クエリは最大 n 回のスキャンでサブシーケンスを再構築します。 
| スペース | O(n²) | DP テーブルには、すべてのサフィックス長ペアの最適な合計が格納されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    m = int(input())

    a = [0] + a
    dp = [[0] * (n + 1) for _ in range(n + 2)]

    for i in range(n, 0, -1):
        for length in range(1, n + 1):
            dp[i][length] = max(dp[i + 1][length],
                                a[i] + (dp[i + 1][length - 1] if length > 0 else 0))

    def build(k, pos):
        res = []
        i = 1
        remaining = k
        target = dp[1][k]

        while remaining:
            for j in range(i, n + 1):
                if n - j + 1 < remaining:
                    break
                if a[j] + dp[j + 1][remaining - 1] == target - sum(res):
                    res.append(a[j])
                    i = j + 1
                    remaining -= 1
                    break
        return res[pos - 1]

    out = []
    for _ in range(m):
        k, pos = map(int, input().split())
        out.append(str(build(k, pos)))
    return "\n".join(out)

 ## 特殊なケース

 多くの異なるサブシーケンスが同じ最大合計に達する場合、微妙なエッジ ケースが発生します。 このような場合、DP テーブルは、すべての最適な継続が同様に有効であるとみなされることを保証します。 貪欲な選択では、達成可能な接尾辞の合計を減らさない最も早いインデックスが一貫して優先され、辞書編集上の最小性が保証されます。 

もう一つのケースは次のような場合です。`k = 1`。 DP はすぐに最大要素の選択に移りますが、実現可能性チェックは接尾辞最大値との単純な比較に陥るため、アルゴリズムは引き続き機能します。 

最後に、最適なサブシーケンスが大きなプレフィックスをスキップする場合、DP は時期尚早な選択を防ぎます。 たとえば、大きな値が早い段階で現れても、最適な合計に達するために必要な後の組み合わせをブロックする場合、再構築中の実行可能性チェックに合格せず、ローカル グリードが魅力的に見える場合でも正確性が保証されます。
