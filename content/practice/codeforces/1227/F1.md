 ## 解決策
 ## 問題の理解

 長さの多肢選択テストに対して固定の解答キーが与えられます。`n`、各質問には既知の正しい選択肢があります。 また、各ポジションが次から任意の値を取得できる、テストの回答を記入するあらゆる可能な方法も検討しています。`1`に`k`。 

選択された回答配列により、正解と一致する位置の数に等しいスコアが生成されます。 その後、配列が 1 位置ずつ循環的にシフトされ、同じ固定応答キーを使用してスコアが再計算されます。 このタスクは、このローテーション後にスコアが厳密に増加するという特性を持つ最初の回答配列がいくつあるかを数えるというものです。 

難しいのは、1 つの構成を評価することではなく、すべての有効な構成を数えることです。`k^n`可能性。 以来`n`2000年までです`k`最大 10^9 までの大きさになる可能性があるため、すべての配列をブルート フォースすることは不可能です。 二次関数であっても`k`状態空間は指数関数的であるため、無関係です。`n`。 

私たちが利用できる唯一の構造は、元の配列と回転された配列の間のスコアの差が、隣接する位置間の局所的な関係と固定配列との比較にのみ依存するということです。`h`。 

すべてのポジションが次の場合、微妙なエッジケースが発生します。`h`は同一です。 その場合、マッチング構造は高度に対称になり、回転がインデックスを結合するため、位置を独立して扱うという単純な推論は崩れます。 もう一つのエッジケースは、`n = 1`、回転は何もしないので、答えはゼロでなければなりません。`k`。 意味のあるシフトを前提としたソリューションはここでは失敗します。 

## アプローチ

 直接的なアプローチは、可能なすべての配列を反復処理することです。`a`、そのスコアを計算します`h`、回転後のスコアを計算して比較します。 これは正しいですが、すぐには実行不可能です。`k^n`配列、さらには配列を評価する場合でも`O(n)`、指数関数的な時間につながります。 

重要な観察は、完全な配列について考えるのをやめ、代わりに回転前後の各位置の寄与を比較することです。 各ポジション`i`貢献する`1`もし`a[i] == h[i]`。 回転後の値`i`に移動します`i+1`、したがって、貢献度は次のいずれかによって異なります。`a[i] == h[i+1]`。 これにより、問題は隣接するインデックス間の 2 つの循環一致パターンの比較に変換されます。 

各ポジションについて、私たちが気にするのは、`a[i]`マッチ`h[i]`、`h[i+1]`、両方、またはどちらでもない。 これにより、各位置が小さなローカル状態に縮小されますが、これらの状態はサイクル全体にわたって一貫している必要があります。 問題は、実際の値の割り当てによって引き起こされる制約を持つ 4 状態のアルファベットにわたる循環シーケンスをカウントすることになります。 

実際の値を直接追跡する代わりに、選択した値が以下に等しいかどうかに応じてポジション間の遷移を分類します。`h[i]`、`h[i+1]`、またはそのどちらでもない。 各カテゴリで使用可能な値の数は、`h[i] == h[i+1]`またはそうでない場合、組み合わせの重みが導入されます。 

次に、各位置がタイプに寄与し、遷移が実際の値を選択することと一致している必要があるサイクルにわたる DP として問題を再解釈します。`[1, k]`。 これは、1 つの位置でサイクルを中断し、最後に一貫性を強制する標準的な循環 DP になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | O(k^n · n) | O(n) | 遅すぎる |
 | ステート間で DP を循環する | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ポジションごとに定義します`i`どのような価値観`a[i]`2 つの隣接する比較に影響します:`h[i]`そして`h[i+1]`(剰余インデックス`n`）。 これにより、次の 4 つの論理カテゴリが得られます。 

値はどちらにも一致せず、のみ一致する`h[i]`、一致のみ`h[i+1]`、または両方に一致する場合`h[i] == h[i+1]`。 

各エッジについて`(i, i+1)`、各動作を生成する値の数を計算します。 これにより、連続するポジションの「一致状態」間の遷移の重みが与えられます。 

次に、状態が次のいずれかをエンコードする位置に DP を構築します。`a[i]`等しい`h[i]`。 元のスコアと回転されたスコアの間の寄与の差はローカル遷移に依存するため、正味のゲインを追跡します。 

周期条件を強制するために、最初の位置を固定し、円周上で DP を実行し、合計ゲインが正かどうかを累積します。 

最終的な答えは、合計ゲインが厳密にゼロより大きいすべての DP パスの合計です。 

### なぜ効果があるのか

 元の配列と回転された配列の間のスコア差は、隣接するインデックス間の独立したローカル寄与の合計に分解されます。 各値は 2 つの位置のみに影響するため、スコア項は 2 つだけになります。 このローカルな依存関係により、情報を失うことなくサイクル DP を通じてグローバル制約を強制できることが保証されます。 すべての有効な割り当ては 1 つの DP パスに正確に対応し、すべての DP パスは有効な割り当てに対応し、全単射と正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    h = list(map(int, input().split()))
    
    if n == 1:
        print(0)
        return

    # Precompute for each i the categories of values:
    # we only need counts:
    # equal to h[i], equal to h[i+1], equal to both, or neither
    
    cnt = []
    for i in range(n):
        j = (i + 1) % n
        if h[i] == h[j]:
            eq = 1
            neq = k - 1
            cnt.append((eq, 0, 0, neq))
        else:
            # values:
            # 1 value equal h[i]
            # 1 value equal h[i+1]
            # remaining k-2 are neither
            cnt.append((1, 1, 0, k - 2))

    # dp[pos][gain offset] is impossible directly due to large k range
    # Instead we compute expected gain difference contribution-wise.
    # We only need total difference > 0, so we use DP over cumulative gain range.

    # Each position contributes:
    # match at i contributes +1 if a[i]==h[i]
    # after shift contributes +1 if a[i]==h[i+1]

    # net contribution per value at i:
    # if value == h[i] -> +1 old
    # if value == h[i-1] -> affects previous edge etc.

    # We convert to edge contribution:
    # diff = sum_i [a[i]==h[i+1]] - [a[i]==h[i]]

    # each position independent => DP over cyclic sum constraint.

    max_shift = 2 * n
    offset = n

    dp = [[0] * (2 * n + 1) for _ in range(n + 1)]
    dp[0][offset] = 1

    for i in range(n):
        new = [[0] * (2 * n + 1) for _ in range(n + 1)]
        for g in range(2 * n + 1):
            cur = dp[i][g]
            if not cur:
                continue

            j = (i + 1) % n
            if h[i] == h[j]:
                same = 1
                diff = k - 1

                # value equal h[i] gives 0 net change
                new[i + 1][g] = (new[i + 1][g] + cur * same) % MOD
                new[i + 1][g] = (new[i + 1][g] + cur * diff) % MOD
            else:
                # value = h[i]
                new[i + 1][g - 1] = (new[i + 1][g - 1] + cur) % MOD
                # value = h[i+1]
                new[i + 1][g + 1] = (new[i + 1][g + 1] + cur) % MOD
                # other values
                new[i + 1][g] = (new[i + 1][g] + cur * (k - 2)) % MOD

        dp = new

    ans = 0
    for g in range(offset + 1, 2 * n + 1):
        ans = (ans + dp[n][g]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、位置をスキャンしながらスコア差をランニングバランスとしてエンコードしようとします。 重要な考え方は、サイクル内の後続または先行に一致するかどうかに応じて、各位置が +1、-1、または 0 のいずれかを与えるということです。 

DP は、負の値を安全に保存できるように、シフトされたバランス インデックスを維持します。 各ステップでは、選択した値が以下に等しいかどうかに応じて、可能な残高の分布が更新されます。`h[i]`、`h[i+1]`、またはそのどちらでもない。 最終的な合計では、正味ゲインが正となるすべての構成が抽出されます。 

微妙な点は、ラップアラウンドを正しく処理することです: 位置`n`位置と比較する`1`、DP は一貫性を損なうことなくインデックスを周期的に処理する必要があります。 これが、すべてのトランジションで明示的に使用される理由です。`(i+1) % n`。

 ## 特殊なケース

 のために`n = 1`、回転によって配列は変更されないため、回転後に厳密に高いスコアを生成できる構成はありません。 正味ゲインは常にゼロであり、しきい値を超える状態はないため、アルゴリズムは正しくゼロを返します。
