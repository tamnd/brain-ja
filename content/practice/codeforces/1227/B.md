 ## 解決策
 ## 問題の理解

 非減少配列が与えられています`q`、これは何らかの隠れた順列から生成されると主張されています。`p`接頭辞最大値を取ることによって。 あらゆるポジションで`i`、`q[i]`最初の値の中で最大の値に等しい`i`の要素`p`。 

タスクは、有効な順列を再構築することです。`p`サイズの`n`プレフィックスの最大配列が一致するもの`q`、またはそのような順列が存在しないと判断します。 

重要な解釈は、`q`順列に新たな記録的最高値がいつ現れるかを教えてくれます。 いつでも`q[i] > q[i-1]`、 位置`i`これまでに出現したことのない新しい最大値を導入する必要があります。 いつでも`q[i] == q[i-1]`、 位置`i`現在の最大値を超えるものは導入できません。 未使用の小さい値を入れる必要があります。 

この制約により、テスト ケース全体で合計最大 100,000 個の要素が許可されます。 これにより、ブルート フォースやバックトラッキングによって並べ替えを試みるソリューションは即座に排除されます。 テストケースごとに線形構造が必要です。 

値が増加すると、微妙な失敗のケースが表示されます。`q`ただし、この増加により、以前にすでに表示されているはずの番号がスキップされます。 たとえば、次の場合`q = [1, 3]`、値`2`プレフィックスの最大条件を破らずに配置する場所はありません。 これが中心的な実現可能性制約です。 

もう 1 つの重要なエッジ ケースは、同じ最大値の繰り返しです。 もし`q[i]`繰り返しになりますが、最大増加に対する新たな制約は導入されませんが、プレフィックスの最大値を誤って増加させるような番号を誤って割り当てないように、未使用の番号を注意深く追跡する必要があります。 

## アプローチ

 強引なアイデアは、順列を構築し、その接頭辞の最大値が一致するかどうかを確認してみることです。`q`。 位置ごとに、未使用の番号をすべて試して、結果として得られるプレフィックスの最大配列を検証できます。 これには大まかに調査する必要があります`n!`最悪の場合の順列。これを超えると完全に実行不可能になります。`n = 10`。 

問題の構造は、より直接的な構造を示唆しています。 配列`q`新しい最大値が表示された場合にのみ変更されます。 そこで私たちは次のように考えることができます`q`最大値が固定される「セグメント」を定義し、新しい最大値が導入される場合にはジャンプすることもあります。 

いつでも`q[i]`増加する場合、その値は正確な位置に配置する必要があります`i`。 そうしないと、そのサイズの最大の新しいプレフィックスを作成できなくなります。 これにより、配列が厳密に増加するすべての位置が即座に修正されます。 

残りのポジションは次のとおりです。`q[i] == q[i-1]`。 これらの位置には、現在のプレフィックスの最大値よりも小さい値を入力する必要があります。重要な点として、現在の最大値よりも小さい未使用の番号はすべて、その最大値が最初に確立される前に最終的にどこかに出現する必要があります。 これは、未使用の番号のプールを維持し、プレフィックスの最大制約を尊重しながら、それらをできるだけ遅く割り当てるという貪欲な戦略につながります。 

私たちが確認しなければならない唯一の実現可能性条件は、すべてのステップで次のことが行われることです。`q`から増加します`q[i-1]`に`q[i]`、前の最大値 + 1 から次の値までのすべての数値`q[i] - 1`未使用のプールですでに使用可能である必要があります。 そうでなければ建設は不可能です。

 ## アルゴリズムのチュートリアル

 どの番号がすでに使用されているかを追跡し、使用可能な番号のプールを維持しながら、順列を構築します。 

1. ブール配列を初期化するか、使用された数値を追跡するように設定し、すべての数値のリストまたはスタックを準備します。`1`に`n`まだ配置されていないもの。 このプールは、新しい最大値が必要ない位置に引き続き割り当てることができる値を表します。 
2. 変数を維持します`current_max = 0`、これまでに順列に配置された最大値を表します。 これが必要なのは、「フラット」セグメントに配置される数値がそれを超えてはいけないためです。 
3. ポジションを繰り返します`i`から`1`に`n`。 もし`q[i] > q[i-1]`、次に位置を決めます`i`の強制配置です`q[i]`。 プレフィックスの最大値がその値まで増加するのは初めてであるため、この値をここに配置する必要があります。 
4. 新しい最大値を設定する前に`q[i]`、すべての値が範囲内であることを確認します。`(current_max + 1 ... q[i] - 1)`はまだ未使用です。 これらの数値のいずれかがすでに以前に配置されている場合、最大値が増加する前にそれらの数値を表示する必要があるため、この構築は無効になります。 未使用の場合は、初期のフラット セグメントで自然に消費されます。 
5. いつ`q[i] == q[i-1]`、厳密に以下の残りの未使用の最大の数値を割り当てます。`current_max`。 これにより、プレフィックスの最大値を誤って増やすことがなくなります。 
6. 値を設定した後、それを使用済みとしてマークし、続行します。 
7. いずれかの時点で有効な番号を割り当てることができない場合 (たとえば、未使用の番号が current_max 以下でない場合)、戻り値が返されます。`-1`。 

### なぜ効果があるのか

 アルゴリズムは、増加するたびに、`q`に新しく導入された最大要素に正確に対応します。`p`。 2 回の増加の間では、プレフィックスの最大値に影響を与えない数値のみを使用するため、安定性が維持されます。`q`。 不変条件は、どの位置でも`i`、構築されたプレフィックスの最大値は以下に等しい`q[i]`また、後の増加をサポートするために必要となるはずの数値を消費することがないため、すべての未使用の数値は常に将来の制約と互換性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        q = list(map(int, input().split()))
        
        used = [False] * (n + 1)
        res = [0] * n
        
        available = set(range(1, n + 1))
        
        ok = True
        current_max = 0
        
        for i in range(n):
            if i == 0:
                res[i] = q[i]
                used[q[i]] = True
                available.remove(q[i])
                current_max = q[i]
                continue
            
            if q[i] > q[i - 1]:
                if q[i] in used:
                    ok = False
                    break
                res[i] = q[i]
                used[q[i]] = True
                available.remove(q[i])
                current_max = q[i]
            else:
                # pick largest unused ≤ current_max
                found = False
                for v in range(current_max, 0, -1):
                    if not used[v]:
                        res[i] = v
                        used[v] = True
                        available.remove(v)
                        found = True
                        break
                if not found:
                    ok = False
                    break
        
        if not ok:
            print(-1)
        else:
            print(*res)

if __name__ == "__main__":
    solve()
```コードは、どの値がすでに使用されているかを追跡し、いつでも強制最大値を直接割り当てます。`q`が増加します。 フラット セグメントの場合、現在の最大値を超えない最大の残りの値が貪欲に選択されるため、時期尚早に新しい最大値が導入されることが回避されます。 の`used`配列により一意性が保証され、逆方向スキャンにより将来の配置に対する柔軟性が確保されます。 

実装の微妙な詳細は、`available`正確さを保つために設定されていますが、未使用の番号との一貫性を維持するのに役立ちます。 実際の意思決定ロジックは完全に次のものに依存します。`used`そして`current_max`。 

## 実用的な例

 ### 例 1

 入力:`q = [1, 3, 4, 5, 5]`建設を段階的に追跡します。 

| 私 | q[i] | 現在の最大値 | アクション | 解像度 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | 1位 | [1, _, _, _, _] |
 | 1 | 3 | 3 | 3 位 (新しい最大値) | [1、3、_、_、_] |
 | 2 | 4 | 4 | 4 位 (新しい最大値) | [1、3、4、_、_] |

 これにより、すべての増加が固定されると、現在の最大値を超えない限り、残りの値を自由に配置できることが確認されます。 

### 例 2

 入力:`q = [1, 1, 3, 4]`| 私 | q[i] | 現在の最大値 | アクション | 解像度 |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 1 | 1位 | [1, _, _, _] |

 1 はすでに使用されており、他に有効な値が存在しないため、位置 1 には未使用の値 ≤ 1 はありません。 アルゴリズムはそのケースを正しく拒否します。 

これは、プレフィックス最大値が繰り返されると、十分な小さい値が十分早い段階で存在するように強制され、そうでない場合は構造が壊れることを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、配列が 1 より大きい値で始まる場合です。たとえば、`q = [3, 3, 3]`。 アルゴリズムはすぐに配置を試みます`3`ただし、プレフィックス最大値の制約に違反せずに以前の位置を埋めるために使用できるこれより小さい値はありません。 不変式にはすべての値が必要であるため、これは正しく失敗します。`1`に`q[0]-1`最初の最大値が確立される前に出現することは不可能ですが、`q[0] > 1`。 

もう 1 つのエッジケースは次のような場合です`q`大きなジャンプの増加など`q = [1, 10]`。 ここでの値は、`2`を通して`9`最大値になる前に最初の位置に配置する必要があります`10`、これは不可能であるため、アルゴリズムはそれを正しく拒否します。 

最後のエッジケースは、次のような完全にフラットな配列です。`q = [1, 1, 1, 1]`。 アルゴリズムの配置`1`最初の位置では、後続の位置に有効な値が残されていないため、次の場合を除いて即座に拒否されます。`n = 1`。
