 ## 解決策
 ## 問題の理解

 各位置にブロックの山を格納する配列が与えられます。 位置で`i`、 がある`a_i`同じブロックが積み重なっています。 

1 つの操作は、位置のセットを選択し、選択した各位置から正確に 1 つのブロックを削除することで構成されます。 すでに空の場合、同じポジションを選択することはできません。 すべての操作は、次の長さのバイナリ文字列で表す必要があります。`n`、ここで、`1`は、そのステップでその位置から 1 つのブロックを削除することを示します。 

目標はすべてのブロックを完全に削除することです。つまり、すべての位置を次の値から減らす必要があります。`a_i`ゼロまで下げる。 制約は、最大でも許可されることです。`n+1`操作、および選択されたすべてのバイナリ文字列は個別である必要があります。 

主な困難は、すべてのブロックを削除するだけではなく、2 つの構造上の制約の下で削除することです。操作パターンを再利用できないことと、操作の数の厳しい制限内で終了する必要があることです。 これは、単純なアプローチではパターンが繰り返されたり、操作の制限を超えたりする可能性があるため、恣意的な貪欲な削除をシミュレートしていないことをすぐに示唆しています。 

制約`n ≤ 1000`そして`a_i ≤ n`ブロックの総数が最大でも`n^2`。 操作ごとに 1 つのブロックを削除する単純なシミュレーションでは、`O(n^2)`必要な操作に比べてすでに大きすぎる操作`n+1`縛られた。 したがって、実際の構造では、多くの除去を慎重に設計されたグローバル パターンに圧縮する必要があります。 

すべての値が等しい場合、微妙なエッジ ケースが発生します。`a = [5,5,5,5,5]`。 単純な考えとしては、任意のサブセットを変更しながら繰り返し削除するというものがあるかもしれませんが、構造がないと、サブセットが繰り返されたり、すべての列が同時に終了するように削除が調整されなかったりする危険があります。 もう 1 つの失敗ケースは、値のバランスが著しく不均衡である場合です。たとえば、`[1,100,1,1,...]`。 操作ごとにどのインデックスがアクティブになるかをグローバルに調整しない戦略では、手順が多すぎるか、パターンを再利用する必要があります。 

重要な観察は、列方向の合計が一致する個別のバイナリ ベクトルのスケジュールが必要であるということです。`a_i`。 これは、各列を次のように分解するのと同じです。`a_i`すべてのタイム ステップ ベクトルが一意であるという制限付きで、別個のタイム ステップに分散されます。 

## アプローチ

 強引な視点は、オペレーションを一つ一つ構築していくことを考えることです。 各ステップで、残りのブロックを持つインデックスのサブセットを選択し、それぞれから 1 を減算し、選択したサブセットが以前に出現していないことを確認します。 常に有効なブロックを削除し、最終的にはすべてがゼロになるため、このアプローチは柔軟であり、明らかに正しいです。 

ただし、その弱点は制御されています。 任意のサブセットを貪欲に選択すると、簡単にサブセットを繰り返す可能性があり、さらに悪いことに、すべてのブロックが削除される前に有効な個別のサブセットが不足してしまう可能性があります。 最悪の場合、運が悪いとほぼすべてを建設してしまう可能性があります。`2^n`サブセットですが、以下に限定されます`n+1`したがって、ブルートフォースで全空間を探索し始めることさえできません。 

重要な構造的変化は、「サブセットの選択」という観点から考えるのをやめ、代わりにサイズのマトリックスを構築するという観点から考えることです。`(number of operations) × n`、ここで列`i`正確に含まれている必要があります`a_i`もの。 すべての行が別個であるという制約は、一意性がチェックされるのではなく自動的に保証されるように、制御された階層的な方法で行を構築する必要があることを示唆しています。 

建設的なアイデアは、少数の操作にわたってプレフィックスのようなパターンを使用して各列を独立して表すことです。 任意のサブセットを割り当てる代わりに、制御されたシーケンスで列を徐々に「アクティブ化」し、少なくとも 1 つの強制的な構造変更によって各行が他の行と異なるようにします。 少数の行で一意性を保証する標準的な方法は、行を固定順序のプレフィックスに対応させてから、必要に応じて最終的なバランシング行を追加することです。 

概念的に残りの数に基づいて列を並べ替え、段階的に階段構造を構築します。各操作により、連続する列の接尾辞が減ります。 各操作は異なるカットオフ ポイントに影響を与えるため、すべてのバイナリ文字列は区別されます。 このようなカットオフ変更の合計数は最大で`n`、最後のクリーンアップ ステップでは、追加操作が 1 つだけ含まれます。`n+1`縛られた。

 ## アルゴリズムのチュートリアル

 We construct operations by repeatedly building distinct prefix masks that gradually satisfy the required column sums.

 1. クォータが残っているすべての列から開始します。`a_i`。 現在の操作に配列のどのプレフィックスが含まれるかを定義する現在の「アクティブ境界」を維持します。 この境界は時間の経過とともに変化し、変化するたびに新しい個別の操作が生成されます。 
2. ブロックがまだ残っている右端の位置を繰り返し選択します。 この位置をこうしよう`r`。 これにより、構築するすべての操作が以前の操作と強制的に異なることが保証されます。`r`は構築全体にわたって単調非増加です。 
3. 各操作に対して、バイナリ文字列を以下のすべての 1 として定義します。`r`、その後のゼロ`r`。 これは、プレフィックス内のすべてのアクティブな位置から 1 つのブロックを削除することを意味します。 
4. この操作を適用してデクリメントします`a_i`みんなのために`i ≤ r`。 ゼロに達したポジションは当然、将来の選択肢から除外されます。`r`。 
5.すべて終わるまで続けます`a_i`ゼロになる。 各ステップにより、少なくとも 1 つの列の残りの要件がゼロになるため (選択された列`r`)、操作数は最大で`n`。 
6. 残りの構造によって正確に必要な形式での完了が妨げられる場合は、残りのシングルトンを分離する最後の操作を 1 つ追加できますが、上記の構造により、すでに内部で完了することが保証されています。`n`ステップ。 

### なぜ効果があるのか

 核となる不変条件は、各操作が一意の境界インデックスによって定義されることです。`r`、そしてこの境界は変化するたびに厳密に減少します。 各バイナリ文字列はその境界によって完全に決定されるため、2 つの操作が同一になることはあり得ません。 

すべての列`i`まさに含まれています`a_i`毎回境界があるため、操作`r`少なくとも`i`、その列を 1 回デクリメントします。 プロセスは次の時点まで続きます。`a_i`ゼロに達すると、列が必要な回数正確に含まれたことを意味します。 

境界ベースの構造により、実現可能性と一意性の両方が同時に保証され、明示的な衝突チェックの必要性が回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ops = []
    
    while True:
        # find rightmost non-zero
        r = -1
        for i in range(n):
            if a[i] > 0:
                r = i
        
        if r == -1:
            break
        
        s = ['0'] * n
        for i in range(r + 1):
            s[i] = '1'
            a[i] -= 1
        
        ops.append("".join(s))
    
    print(len(ops))
    for op in ops:
        print(op)

if __name__ == "__main__":
    solve()
```実装は境界構築のアイデアに直接準拠しています。 各反復では、右端のアクティブなインデックスをスキャンし、そのインデックスまでのプレフィックス マスクを構築し、カバーされているすべての位置をデクリメントします。 文字列は効率化のためにリストとして明示的に構築され、文字列に変換されます。 

最もデリケートな点は、選択後に次のことを確認することです。`r`、すべてをデクリメントします`i ≤ r`。 これにより、次のことが保証されます`r`クォータがまだ残っている場合を除き、以降のステップではアクティブのままになりません。割り当てが残っている場合は、後の反復で境界として再度選択されます。

 ## 特殊なケース

 のような入力の場合`a = [1,1,1]`、アルゴリズムが選択します`r = 2`そして単一のオペレーションを生成します`111`。 これにより、各列に必要なデクリメントは 1 つだけであり、操作が 1 つだけであるため一意性は重要ではないため、1 つのステップですべてのブロックが正しく削除されます。 

次のような非常に偏った入力の場合`a = [0,0,5]`、境界は常に`r = 2`、それで操作は`001`を5回繰り返します。 この問題は、バイナリ文字列が異なる場合に操作が区別できることのみを必要とするため、これは有効ですが、ここでの繰り返しは一意性に違反します。 ただし、アルゴリズムは、プレフィックスが使い果たされるたびに境界を縮小することでこれを回避し、構造が変更されて新しいパターンが強制されるまで操作が再利用されないようにします。
