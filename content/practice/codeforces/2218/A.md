 ## 解決策
 ## 問題の理解

 この問題では整数を選択するように求められます$y$与えられた整数に対して$x$最小限の$x$そして$y$できるだけ大きいです。 それぞれが 1 つの整数で構成される複数のテスト ケースが与えられています。$x$-67 から 67 まで。出力は整数でなければなりません$y$各テストケースの同じ範囲内で。 

簡単に言い換えると、視覚化すると、$x$そして$y$数直線上では、$\min(x, y)$は常に 2 つのうちの小さい方です。 この最小値を最大化するには、次のことが必要です$y$厳密に次より大きくなる$x$。 それから$\min(x, y)$等しくなります$x$、これは最大値です。 もし$y \le x$、最小値は次のようになります$y$、厳密には以下よりも小さいです$x$, そのため、最小値は最大化されません。 

制約は非常に小さいです。$x$は -67 ～ 67 の範囲にあり、テスト ケースは最大 6767 個あります。 各テスト ケースは独立しており、ケースごとの解を計算するのは簡単です。 たとえ$O(t)$単純な算術によるアプローチは、1 秒の制限時間内に簡単に収まります。 

明らかではないエッジケースには、最大値と最小値が含まれます。 のために$x = 67$、選ぶことはできません$y > 67$境界が私たちを制限するからです。 したがって、$y = 67$それ自体は有効です。 同様に、$x = -67$、 どれでも$y \ge -67$譲ります$\min(x, y) = -67$、だから選ぶことができます$y = -66$または範囲内のそれ以上の数値。 重要なのは、常にすぐ上の数字を選択することです$x$可能であれば、-67 から 67 の範囲を尊重します。 

## アプローチ

 ブルートフォースアプローチは簡単です。 与えられた$x$、すべてを試すことができます$y$-67 から 67 まで、計算します$\min(x, y)$それぞれについて、最大の結果を選択します。 可能なのは 135 個だけであるため、これは機能します$y$値を使用しますが、パターンは予測可能であるため不要です。 ブルートフォースの複雑さは次のようになります。$O(t \cdot 135)$これは許容できますが、扱いにくく、洗練されていません。 

重要な洞察は次のとおりです$\min(x, y)$いつでも最大化されます$y > x$、その場合、最小値は以下に等しいため、$x$。 したがって、最適な選択は、$y$単純に$x+1$上限の 67 を超えない限り。その場合、$y = 67$が唯一の有効な選択肢です。 この観察により、問題はテスト ケースごとの定数時間の計算に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(t * 135) | お(1) | 受け入れられるが不要 |
 | 最適 | O(t) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 これにより、計算を繰り返す回数が決まります。 
2. 各テスト ケースについて、次の内容を読んでください。$x$。 私たちが決定します$y$このために$x$。 
3. コンピューティング$y = x + 1$。 これにより、次のことが保証されます$\min(x, y) = x$、これは最大です。 
4. もし$y > 67$、 調整する$y$範囲内に留まるには67歳まで。 
5. 出力$y$。 すべてのテスト ケースに対して繰り返します。 

これが機能する理由は、$y$その上$x$最小値は減らないため、最小値をこれより大きくすることはできません$x$。 選択する$y = x + 1$シンプルさを保ち、平等性の問題を回避し、問題の制約を尊重します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    x = int(input())
    y = min(x + 1, 67)
    print(y)
```コードは最初に読み取られます$t$、テストケースの数。 次に、各テスト ケースについて、次のようになります。$x$、計算します$y$上で説明したロジックを使用して、それを出力します。 使用する`min(x + 1, 67)`上限を超えないようにします。 高速I/O`sys.stdin.readline`これは競技プログラミングの標準的な手法ですが、ここでは`input()`入力サイズが小さいため、これでも十分です。

 ## 特殊なケース

 のために$x = 67$、$x + 1 = 68$許容範囲を超えています。 アルゴリズムクランプ$y$67まで、$\min(x, y) = 67$。 のために$x = -67$、1 を追加すると -66 が得られ、これは範囲内であり、最小値が -67 で最大化されることが保証されます。 これにより、許容範囲の両端が正しく処理されることが確認されます。 あらゆる中間者にとって$x$、$y = x + 1$保証する$\min(x, y) = x$、これは可能な最小値の最大値です。
