 ## 解決策
 ## 問題の理解

 サラダの種類には 1 ～ 10^8 の番号が付けられています。 各タイプの価格は、最も近い吉数に切り上げて決定されます。 幸運の数字は、10 進表現に数字 3 と 8 のみを含む正の整数です。たとえば、3、8、38、および 883 は幸運ですが、13 と 380 は幸運ではありません。 

入力により、サラダ タイプ [l, r] の間隔が与えられます。 この期間内にあらゆる種類のサラダを 1 つだけ購入した場合の合計価格を見つける必要があります。 課題は、間隔が非常に長くなる可能性があるため、すべてのサラダの種類を直接チェックするのは現実的ではないことです。 元の問題の制約では、最大 10^8 の値が許可されます。これは、O(r-l+1) 解では 1 つのテスト ケースに対して最大 1 億回の操作が必要になる可能性があることを意味します。 これは Python の制限に近すぎるため、オーバーヘッドの余地がありません。 すべてのタイプを反復するのではなく、ラッキーナンバーの構造を活用する必要があります。 

有益な観察は、幸運な数字はほとんどないということです。 k 桁のラッキーナンバーの数は 2^k だけです。 私たちが関心のある範囲内にあるすべての幸運な数字を考慮しても、合計数は小さいままです。 これは、ラッキー ナンバー自体を構築し、連続するラッキー ナンバー間の間隔を使用して、一度に大きな範囲を計算できることを意味します。 

いくつかの境界ケースでは、幸運な数字自体のみを考慮する実装が壊れる可能性があります。 たとえば、入力が次の場合:```
1 2
```答えは次のとおりです。```
6
```どちらのタイプも幸運な数字ではありませんが、価格は 3 です。 

別のケースは次のとおりです。```
8 8
```答えは次のとおりです。```
8
```値 8 は、幸運な数字 8 で終わる間隔に属します。次の幸運な数字より厳密に小さい数字のみを処理する不注意な実装では、幸運な数字自体を見逃してしまう可能性があります。 

3 番目の重要なケースは、間隔が幸運な境界を越える場合です。```
3 9
```価格は次のとおりです。```
3 8 8 8 8 8 33
```したがって、答えは次のとおりです。```
76
```値 9 は、次の幸運な数字 33 にジャンプします。範囲を 8 付近で連続しているものとして扱うと、誤って価格 8 から 9 が割り当てられてしまいます。 

## アプローチ

 簡単な解決策は、l と r の間のすべてのサラダ タイプを生成し、それ以上の最初の幸運な数字を見つけて、その価格を加算することです。 これは定義に直接従うため、検証が簡単です。 ただし、間隔に 10^8 の可能なタイプがすべて含まれている場合、アルゴリズムは約 1 億回の検索を実行します。 たとえ各ラッキー検索が高速であっても、反復回数が多すぎます。 

重要な洞察は、価格がどこで変化するかを観察することで得られます。 サラダタイプの価格はどのポジションでも変わりません。 これは、ある幸運な数字の境界から次の幸運な数字まで一定のままです。 たとえば、最初の方にあるラッキーナンバーは次のとおりです。```
3, 8, 33, 38, 83, 88
```タイプ 1、2、および 3 はすべてコスト 3。タイプ 4 ～ 8 はすべてコスト 8。タイプ 9 ～ 33 はすべてコスト 33。 

個々のタイプを合計する代わりに、これらの定数セグメントを合計することができます。 必要な情報は、幸運な数字の順序付きリストだけです。 

ラッキーナンバーの数は少ないので、すべてを生成できます。 ソートが完了すると、幸運な間隔をたどることによって、任意の位置 x までのプレフィックス コストを計算できます。 要求された回答については、r までのプレフィックスの合計を計算し、l-1 までのプレフィックスの合計を減算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(r-l+1) | お(1) | 遅すぎる |
 | 最適 | O(2^10 log(2^10)) | O(2^10) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 答えに影響を与える可能性のあるすべてのラッキーナンバーを生成します。 k 桁の幸運な数字には正確に 2^k 通りの可能性があるため、最大 10 までの長さを生成しても数千の値しか得られず、管理が容易です。 
2. 生成されたラッキーナンバーを並べ替えます。 すべてのサラダの種類には、それより小さくない最初の幸運な数字が使用されるため、これらを昇順で必要とします。 
3. 1 から x までのすべてのサラダ タイプの合計コストを返す関数を作成します。 この関数は、幸運な数字を順番に調べ、可能な限り完全な間隔を消費します。 
4. 各ラッキーナンバー cur ごとに、前のラッキーナンバーを記録します。 区間 (prev, cur] 内のすべてのタイプには価格 cur があります。x がこの区間を超えた場合、寄与分をすべて加算します。```
(cur - prev) * cur
```次に、次のラッキーナンバーに移動します。 

1. x 以上の最初の幸運な数字に達したとき、その間隔の一部だけが必要になる場合があります。 追加：```
(x - prev) * cur
```そしてやめてください。 

1. 必要な答えを次のように計算します。```
prefix(r) - prefix(l - 1)
```これにより、元の範囲クエリが 2 つのプレフィックス計算に変換されます。 

なぜ効果があるのか:

 不変条件は、ラッキーナンバー cur を処理する前に、prev までのすべてのサラダの種類に正確な価格がすでに正確に割り当てられていることです。 prev の後で cur で終わる間隔は、最初のラッキーナンバーが cur 以上である数字のみで構成されます。 価格関数は幸運な数字でのみ変化するため、これらの間隔を処理すると、すべてのタイプが 1 回だけカバーされ、すべての位置に正しい値が割り当てられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def generate_lucky():
    lucky = []

    def dfs(x):
        if x > 10**10:
            return
        if x:
            lucky.append(x)
        dfs(x * 10 + 3)
        dfs(x * 10 + 8)

    dfs(0)
    lucky.sort()
    return lucky

lucky = generate_lucky()

def prefix_cost(x):
    if x <= 0:
        return 0

    ans = 0
    prev = 0

    for cur in lucky:
        if x <= prev:
            break

        if x <= cur:
            ans += (x - prev) * cur
            return ans

        ans += (cur - prev) * cur
        prev = cur

    return ans

def solve():
    l, r = map(int, input().split())
    print(prefix_cost(r) - prefix_cost(l - 1))

solve()
