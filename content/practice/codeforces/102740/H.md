 ## 解決策
 ## 問題の理解

 長い一次元の廊下があります。 一部の位置にはザッパー装置が含まれており、一部の位置にはゴーストが含まれています。 ザッパーはあらゆるゴーストを除去できますが、エネルギーコストはそれらの間の距離の二乗に依存します。 すべてのザッパーは独立して使用できるため、すべてのゴーストはそれに最も近いザッパーによって処理される必要があります。 必要な出力は、モジュロ (10^9+7) をとった、すべてのゴーストの最小二乗距離の合計です。 

入力により、ザッパーとゴーストの数と、それに続く廊下に沿った位置がわかります。 位置は整数であり、(10^7) まで大きくすることができますが、ザッパーとゴーストの数は両方とも (10^5) に達する可能性があります。 (10^5) 個のゴーストと (10^5) 個のザッパーを使用すると、考えられるすべてのペアをチェックするには (10^{10}) 個の距離計算が必要になりますが、これは 2 秒の制限をはるかに超えています。 (O((n+m)\log n)) に近いかそれ以上の解が必要です。 

主なエッジケースは、最も近いザッパーが最初に遭遇するものではない可能性があり、距離がゼロになる可能性があるという事実から生じます。 たとえば、入力が次の場合:```
1 1
5
5
```答えは`0`幽霊はすでにザッパーに乗っているからです。 厳密に短い距離のみをチェックするソリューションでは、このケースを誤って見逃す可能性があります。 

別のケースは、ゴーストが最初のザッパーの前または最後のザッパーの後にある場合です。```
2 2
10
20
0
30
```正しい答えは、`200`、位置にゴーストがあるため`0`距離です`10`最初のザッパーと位置のゴーストから`30`距離です`10`2つ目のザッパーから。 2 つのザッパー間でのみ検索するソリューションは、これらのゴーストの両側にザッパーがないため、失敗します。 

3 番目のケースは、2 つのザッパーが同等に近い場合です。```
2 1
4
10
7
```答えは`9`、両方のザッパーが距離があるため`3`距離が離れている場合、コストは (3^2) です。 最小距離を使用する限り、タイブレークの選択は問題ありません。 

## アプローチ

 直接的なアプローチは、すべてのゴーストとすべてのザッパーを比較することです。 各ゴースト位置 (x) について、すべてのザッパー位置の ((x-z_i)^2) を計算し、最小値を保持します。 これは正しいです。ザッパーの選択は独立しているため、各ゴーストを個別に最適化できるからです。 ただし、(10^5) 個のゴーストと (10^5) 個のザッパーを使用すると、最悪の場合は (10^{10}) 個の比較と距離の計算が実行され、遅すぎます。 

この問題を容易にする構造は、すべてのオブジェクトが一直線上にあることです。 ザッパーの位置を並べ替えた後、ゴーストに最も近いザッパーは、そのゴーストを囲む 2 つのザッパーのうちの 1 つである必要があります。 左に最も近いザッパーよりも左にあるザッパーはさらに遠くにあり、同じ議論が右側にも当てはまります。 

これにより、問題は二分探索に帰着します。 各ゴーストについて、少なくともゴースト位置にある最初のザッパーを見つけます。 そのザッパーが右側の最も近い候補です。 ソートされた配列内の前のザッパーは、左側の最も近い候補です。 両方の候補が存在する場合は、それらの距離を計算し、小さい方の二乗距離を加算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 最適 | O((n+m) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのザッパーの位置を並べ替えます。 ソートされた順序により、二分探索を使用して任意のゴーストに最も近い近傍を見つけることができます。 
2. 各ゴースト位置について、ソートされたザッパー配列内でそのゴーストの挿入位置を見つけます。 このインデックスは、ゴーストよりも小さい位置にある最初のザッパーを指します。 
3. そのインデックスにザッパーが存在する場合は、それを確認します。 これは右側の最も近いザッパーです。 
4. そのインデックスの直前にザッパーが存在するかどうかを確認します。 これは左側で最も近いザッパーです。 
5. 利用可能な二乗距離のうち小さい方を答えに加えます。 すべてのゴーストに対してこれを繰り返し、結果のモジュロ (10^9+7) を取得します。 

2 つのザッパーだけをチェックする必要がある理由は、行の順序にあります。 幽霊が 2 人のザッパーの間にいると仮定します。 最も近い左のザッパーからさらに左に移動すると、距離が増加するだけであり、最も近い右のザッパーからさらに右に移動すると、距離は増加します。 同じ推論が、すべてのザッパーの範囲外のゴーストにも適用されます。 

機能する理由: ソート後、二分探索位置により、すべてのザッパーがゴーストの左側と右側に分割されます。 各グループから最も近い要素が唯一考えられる最適な選択です。 同じグループ内の他のザッパーはすべて遠くにあるため、その二乗距離を小さくすることはできません。 アルゴリズムは可能な最近傍の両方を評価するため、常に各ゴーストの最小エネルギー コストを選択します。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m = map(int, input().split())

    zappers = []
    for _ in range(n):
        zappers.append(int(input()))

    ghosts = []
    for _ in range(m):
        ghosts.append(int(input()))

    zappers.sort()

    ans = 0

    for x in ghosts:
        idx = bisect_left(zappers, x)

        best = None

        if idx < n:
            d = x - zappers[idx]
            best = d * d

        if idx > 0:
            d = x - zappers[idx - 1]
            cost = d * d
            if best is None or cost < best:
                best = cost

        ans = (ans + best) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```ゴーストは独立して処理できるため、ソートされたザッパー リストは保存する必要がある唯一の構造です。 の`bisect_left`この呼び出しは、ソートを中断せずにゴーストを挿入できる最初の位置を返します。これにより、右側の最初のザッパーが正確に得られます。 

コードは、左の候補の前に右の候補をチェックしますが、順序は正確さに影響しません。 境界チェックが必要なのは、挿入位置がゼロになる可能性があり、これは左ザッパーが存在しないことを意味するか、または左ザッパーが存在しないことを意味するためです。`n`、つまり、適切なザッパーが存在しないことを意味します。 

二乗距離は整数を使用して計算されます。 Python は大きな整数を自動的に処理しますが、加算のたびにモジュロを取得すると、累積された答えが制限され、必要な出力形式に従います。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n+m) log n) | ソートには O(n log n) がかかり、すべてのゴーストが 1 回の二分探索を実行します。 
| スペース | O(n) | ソートされたザッパー位置のみが保存されます。 

この制約により、約数百万の操作が可能になりますが、数十億の操作は許可されません。 ザッパーを並べ替えてバイナリ検索を実行すると、作業が (10^5) 位置の必要な範囲内に収まります。

 ## 特殊なケース

 ゴーストが正確にザッパー上にある場合、二分探索によりそのザッパーが正しい候補として検出されます。 計算された距離はゼロであるため、アルゴリズムはエネルギーを追加しません。 のために：```
1 1
5
5
```ソートされたザッパーリストは`[5]`、検索インデックスは`0`、適切な候補のコストは次のとおりです。`0`。 

ゴーストがすべてのザッパーの前にある場合、検索インデックスは次のようになります。`0`, したがって、左の候補はありません。 このアルゴリズムでは最初のザッパーが使用されます。 のために：```
2 2
10
20
0
30
```の幽霊`0`ザッパーのみをチェックします`10`、(10^2=100)を与えます。 

ゴーストがすべてザッパーの場合、検索インデックスは配列の長さになります。 このアルゴリズムは、存在しない正しい候補をスキップし、最終ザッパーを使用します。 の幽霊`30`同じ例では位置を使用します`20`、コストもかかります (10^2=100)。 

ゴーストが 2 つのザッパーの間に正確に存在する場合、両方の候補がテストされます。 のために：```
2 1
4
10
7
```コストは (3^2) と (3^2) であるため、どちらを選択しても正しい最小値が得られます。`9`。
