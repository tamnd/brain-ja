 ## 解決策
 ## 問題の理解

 このプロセスは、5 人の指名された兵士が列に並ぶことから始まります。 線量は常に前線の兵士に与えられます。 その兵士は同一のクローンを 1 つ作成し、両方のコピーがキューの最後尾に移動します。 任務は、それを受け取る兵士の名前を決定することです。`n`3回目の投与量。 入力は、この無限の投与量シーケンス内の 1 つの位置であり、出力は、元の 5 人の兵士の対応する名前です。 

制約`n <= 10^6`解決策についてどのように考えるべきかが変わります。 2 秒の制限に対して 100 万回の操作は小さいため、各線量を 1 つずつ処理するシミュレーションは完全に許容されます。 大規模な数学的構造を構築したり、キュー全体を繰り返し再構築しようとするソリューションでは、作業が無駄になります。 キューの現在の順序を維持し、投与ごとに 1 つの操作を実行するだけで済みます。 

主なエッジケースは、兵士が再び現れたときの誤解から発生します。 よくある間違いは、シーケンスが単に 5 つの位置ごとに繰り返されていると想定することです。 例えば：```
Input:
6
```正しい出力は次のとおりです。```
Ace
```最初の 5 回の投与後、元の兵士はすべて 1 回クローン化されるため、キューは次のようになります。```
Ace, Ace, Bolt, Bolt, Cameron, Cameron, Doom, Doom, Echo, Echo
```6回目の投与は再びエースに与えられます。 繰り返しサイクルを使用すると、ボルトが誤って出力されます。 

別の境界ケースは、最初に考えられる入力です。```
Input:
1
```正しい出力は次のとおりです。```
Ace
```以前のキューの状態を考慮する必要がないため、最初の人物はインデックス付けのミスをゼロにすることなく正しく処理される必要があります。 

## アプローチ

 直接的なアプローチは、キューをシミュレートすることです。 私たちは現在の兵士の順序を維持します。 線量ごとに、最初の兵士を削除し、これが要求された位置であるかどうかを確認し、その兵士のコピーを 2 つ後ろに追加します。 これはプロセスに正確に従うため、答えが正しいことが保証されます。 

これが効率的に機能する理由は、入力制限が 100 万操作のみであるためです。 すべての操作後のキュー サイズは、最大でも最初の 5 人の兵士と 100 万の新しいクローンであるため、メモリ使用量は小さいままです。 

より複雑なアプローチでは、シーケンス内のパターンを見つけようとする場合があります。 誰かが処理されるたびにコピーの数が増加するため、キューには興味深い増加特性がありますが、ここではそれらのパターンを発見して維持する必要はありません。 ブルート フォースは最大操作数が少ないため機能しますが、パターン検索では必要なパフォーマンスが向上することなく複雑さが増します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(n) | 承認済み |
 | パターンの導出 | メソッドに応じて O(log n) または O(1) | お(1) | 不要 |

 ## アルゴリズムのチュートリアル

 1. 開始兵士 5 人をキューに保管します。 キューは、将来の線量が割り当てられる正確な順序を表します。 
2. 完了するまでクローン作成操作を繰り返します。`n`回目の投与量に達します。 各反復中に、先頭の兵士を削除します。その兵士が次の投与を受けるためです。 
3. 現在の反復番号が`n`、その兵士の名前をすぐに出力します。 すでに決定されている答えに影響を与えることができないため、将来のクローンをシミュレートする必要はありません。 
4. それ以外の場合は、削除された兵士のコピーを 2 つキューの最後に追加します。 元の兵士と新しいクローンは両方ともプロセスのルールに従って最後に待機します。 

機能する理由: 反復が完了するたびに、アルゴリズムによって保存されたキューは、同じ回数の投与後の実際のキューとまったく同じになります。 最初は両方のキューは同一です。 各ステップでは同じ先頭の兵士が削除され、最後に同じ 2 つのコピーが挿入されるため、不変式は true のままです。 とき`n`回目の削除が発生すると、アルゴリズムは実際の兵士を受け取ったのと同じ兵士を返します。`n`3回目の投与量。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n = int(input())

    q = deque(["Ace", "Bolt", "Cameron", "Doom", "Echo"])

    for i in range(1, n + 1):
        person = q.popleft()

        if i == n:
            print(person)
            return

        q.append(person)
        q.append(person)

if __name__ == "__main__":
    solve()
```最初の要素の削除と後ろへの要素の追加という、必要な操作の両方が効率的であるため、両端キューが使用されます。 通常の Python リストでは、残りの要素をすべて移動する必要があるため、先頭から削除するのにコストがかかります。 

ループは次から始まります`1`の代わりに`0`問題は位置として最初の線量を要求するためです`1`。 これにより、現在の兵士が答えであるかどうかを確認する際に 1 つずれるエラーが回避されます。 

クローン作成操作は、回答を確認した後にのみ実行されます。 チェックする前にクローンを追加した場合、キューの状態は現在の兵士が線量を受け取った瞬間ではなく、次の瞬間を表すことになります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各用量には、デキューへの 1 回の取り外しと最大 2 回の挿入が必要です。 |
 | スペース | O(n) | キューは、シミュレートされた線量ごとに 1 要素ずつ増加します。 |

## テストケース```python
import sys
import io
from collections import deque

def solve(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    n = int(sys.stdin.readline())
    q = deque(["Ace", "Bolt", "Cameron", "Doom", "Echo"])

    ans = ""
    for i in range(1, n + 1):
        person = q.popleft()
        if i == n:
            ans = person
            break
        q.append(person)
        q.append(person)

    sys.stdin = old_stdin
    return ans + "\n"

assert solve("1\n") == "Ace\n", "sample 1"
assert solve("6\n") == "Ace\n", "sample 2"
assert solve("943\n") == "Cameron\n", "sample 3"

assert solve("2\n") == "Bolt\n", "second soldier receives the second dose"
assert solve("5\n") == "Echo\n", "last original soldier"
assert solve("10\n") == "Echo\n", "after the first doubling cycle"
assert solve("1000000\n") != "", "large input handling"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`|`Ace`| 最小入力とインデックス作成境界 |
 |`2`|`Bolt`| 2 番目のキュー要素への即時遷移 |
 |`5`|`Echo`| 完全な初期キューを処理中 |
 |`10`|`Echo`| 最初のクローン作成後の正しい取り扱い |
 |`1000000`| 任意の有効な名前 | 最大の制約パフォーマンス |

 ## 特殊なケース

 のために`n = 1`、キューには元の 5 人の兵士のみが含まれます。 このアルゴリズムは、最初の反復で Ace を削除し、現在の反復が要求された位置と等しいことを確認し、キューを変更する前に Ace を返します。 

のために`n = 6`重要な点は、最初の 5 つの操作はキューを変更しないままにするということです。 各兵士が処理された後、後ろに 2 つのコピーが追加されます。 Echo が 5 回目の投与を受けると、キューは次のようになります。```
Ace, Ace, Bolt, Bolt, Cameron, Cameron, Doom, Doom, Echo, Echo
```6番目の除去はエースです。 アルゴリズムは 5 回の反復後に同じ状態に到達し、正しい結果を返します。 

次のような大きな値の場合、`n = 1000000`、アルゴリズムは一連の回答全体を保存しようとはしません。 現在のキューの状態を保存し、必要な操作を一度に 1 つずつ実行するだけなので、実行時間は入力サイズに比例して増加し、実用的なレベルを維持します。
