 ## 解決策
 ## 問題の理解

 の配列が与えられます$n$正の整数。各値は、通りに沿って配置された植物の「成長レベル」を表します。 あらゆるポジションについて$i$に像を置くことを想像します。$i$-番目の植物を選択し、その位置にある植物を除く他のすべての植物の成長レベルの積に等しいスコアを計算します。$i$。 

タスクは、すべてのインデックスに対してこの値を個別に計算し、結果を剰余として出力することです。$998244353$。 

ということで、それぞれのポジションごとに$i$、私たちが望むのは：$$x_i = \prod_{j \ne i} a_j \pmod{998244353}$$制約により、最大で$n = 10^5$、そしてそれぞれ$a_i$と同じ大きさにすることができます$10^9$。 すべてのインデックスのすべての要素を直接乗算すると、次の処理が必要となるため、非常に遅すぎます。$O(n^2)$掛け算。 

値自体が大きいため、モジュラー演算で慎重に処理しないと、中間積は簡単に 64 ビットの制限を超えます。 

値が大きく繰り返される場合には、微妙なケースが発生します。 たとえば、すべての値が等しい場合、すべての答えは同一であり、次と等しいはずです。$a^{n-1} \mod 998244353$。 モジュラー除算や事前計算を誤って処理すると、対称性が崩れます。 

もう 1 つの重要なエッジケースは次のような場合です。$n = 2$。 それぞれの答えは単に他の要素であり、正しく理解するのは簡単ですが、総当たり実装では逆モジュラーを適切に処理せずに、誤って両方の値を乗算したり、誤って除算したりすることがあります。 

## アプローチ

 単純な解決策はそれぞれを計算します$x_i$他のすべての要素を反復して乗算します。 これは問題の定義に直接従うため、正しいです。 ただし、インデックスごとに次のことを実行します。$n-1$乗算すると、合計は約$n(n-1)$操作。 と$n = 10^5$、これは次のようになります$10^{10}$これは妥当な制限時間をはるかに超えています。 

重要な観察は、すべての答えが同じグローバル構造を共有しているということです。$x_i$1 つの要素を除いた配列全体の積です。 すべての要素の合計積を事前に計算する場合、各答えは次の式で得られます。$a_i$この商品から。 モジュラー演算では不用意に直接除算を行うことはできないため、逆モジュラーを使用します。 

次のように計算します。$$\text{total} = \prod_{i=1}^{n} a_i \mod 998244353$$それから：$$x_i = \text{total} \cdot a_i^{-1} \mod 998244353$$以来$998244353$が素数であり、ゼロ以外のすべての要素には逆数があり、高速累乗を使用して計算できます。$$a_i^{-1} = a_i^{MOD-2} \mod MOD$$これにより、問題は 1 つのグローバル製品の計算に縮小され、$n$べき乗モジュラー。

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、係数を定義します。$MOD = 998244353$。 すべての計算は、オーバーフローを防止し、逆モジュラーによる除算を可能にするために、この値を法として削減されます。 
2. すべての要素のモジュロの合計積を計算します。$MOD$。 これは、配列を 1 回反復し、段階的に乗算することによって行われます。 このステップでは、すべてのグローバル情報を 1 つの値に圧縮します。 
3. インデックスごとに$i$、モジュラー逆関数を計算します。$a_i$指数による高速累乗の使用$MOD - 2$。 これが機能するのは、係数が素数であるためであり、フェルマーの小さな定理によってこの反転の正しさが保証されます。 
4. 総積に次の逆数を掛けます。$a_i$、結果のモジュロを取得します$MOD$。 これにより、効果的に寄与が相殺されます。$a_i$、他のすべての要素の積が残ります。 
5. すべての計算値を順番に出力します。 

### なぜ効果があるのか

 核となる不変条件は、いつでも変数が`total`常に配列モジュロ内のすべての要素の積を表します$MOD$。 それを掛けると$a_i^{-1}$、ちょうど 1 つの出現を代数的に分割しています。$a_i$モジュラー演算の下で。 逆モジュラーは素体では正確であるため、この演算は正確さを維持し、選択された要素を除くすべての要素の正確な積を生成します。 すべての計算は同じ共有グローバル積から開始されるため、インデックス間の依存関係は崩れません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modpow(a, e):
    res = 1
    a %= MOD
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

n = int(input())
a = list(map(int, input().split()))

total = 1
for x in a:
    total = total * x % MOD

ans = []
for x in a:
    inv = modpow(x, MOD - 2)
    ans.append(total * inv % MOD)

print(*ans)
```実装はアルゴリズムの正確な構造に従います。 の`modpow`関数は、逆モジュラーを効率的に計算するために必要な 2 進累乗を実行します。 総積は線形時間に 1 回計算されます。 次に、各要素はその逆を介して分割することによって独立して処理されます。 

微妙な点は、すべての演算がモジュロで実行されることです。$MOD$、べき乗内の乗算を含みます。 これにより、オーバーフローが防止され、モジュラー演算の正確さが保証されます。

## テストケース```python
import sys, io

MOD = 998244353

def modpow(a, e):
    res = 1
    a %= MOD
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    total = 1
    for x in a:
        total = total * x % MOD
    out = []
    for x in a:
        out.append(total * modpow(x, MOD - 2) % MOD)
    return " ".join(map(str, out))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# sample-like test
assert run("4\n114 514 1919 810\n") == "798956460 177200460 47462760 112445724"

# minimum n
assert run("2\n3 5\n") == "5 3"

# all equal
assert run("5\n7 7 7 7 7\n") == "2401 2401 2401 2401 2401"

# includes large values
assert run("3\n1000000000 999999937 123456789\n") is not None

 ## 特殊なケース

 重要なエッジケースは、すべての値が同一である場合です。 入力の場合:```
5
7 7 7 7 7
```合計製品は$7^5 \mod MOD$。 各答えは 1 つの 7 を割り、結果は次のようになります。$7^4$。 7 の各逆モジュラは同一であるため、アルゴリズムはこれを自然に処理し、すべての出力が等しいままになります。 計算はインデックスの順序に依存しないため、対称性は維持されます。 

もう一つのエッジケースは、$n = 2$。 のために：```
2
a b
```総製品は$ab$。 最初の答えは次のようになります$ab \cdot a^{-1} = b$、2番目は次のようになります$a$。 これは、特別な場合のロジックを必要とせずに、直接の解釈と一致します。 

最後に、大きな値は次のようになります。$10^9$すべての乗算は剰余換算されるため、安全に処理されます。$998244353$すべてのステップで、Python と中間モジュラー演算の両方でオーバーフローを防止します。
