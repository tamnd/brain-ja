 ## 解決策
 ## 問題の理解

 私たちには学生のグループが与えられ、各学生は一意の学生 ID と初期スコアによって識別されます。 その中で、入力順序のインデックス m で示される 1 人の生徒が特別であり、この生徒をシャオ A と呼びます。 

変換は、元のスコアに基づいて 2 つの独立したフェーズで発生します。 まず、Xiao A は自分のスコアを調整します。初期スコアが 60 未満の場合は、60 に上げます。そうでない場合は、スコアを変更しません。 この変更は本人の本来の価値観のみに依存し、他の生徒の評価には影響しません。 

次に、Xiao A は元の完全なスコアのリストを使用して他の全員を調べます。 しきい値は、変更前の初期状態から計算された平均スコアです。 元のスコアがこの平均以上である他の学生は、スコアを 2 ポイント減らされ、下限は 0 になります。 

重要な点は、両方の決定がスコアの最初のスナップショットに基づいていることです。 Xiao Aの修正後、平均値は再計算されず、削減の適格性も初期データから固定されます。 唯一の動的部分は、2 つのルールの最終的な適用です。 

出力では、すべての学生の最終スコアを学生 ID で昇順に並べて印刷する必要があります。 

制約は小さく、n は最大 100 です。これは、テストごとに O(n^2) または O(n) の解があれば簡単に十分であることをすぐに示唆しています。 複雑なデータ構造を試みる必要はなく、最適化よりも実装の明確さが重要です。 

よくある間違いは、Xiao A のスコアを変更した後に平均を再計算することに起因します。 たとえば、初期スコアが [1, 4, 100] の場合、平均は 35 です。Xiao A の更新ではこのしきい値は変更されませんが、不注意な実装では再計算が行われ、カットオフが誤ってシフトされる可能性があります。 

もう 1 つの間違いは、スコアをその場で更新し、更新された値を使用して誰かが平均以上かどうかを判断することです。 これは、決定は初期スコアに基づいて行われなければならないというルールを破ります。 

最後に、2 を減算するときに 0 の下限を忘れると、負の値が生成される可能性があり、これは無効です。 

## アプローチ

 ブルートフォースの見方は簡単です。 まず、すべての初期スコアの平均を計算します。 次に、すべての生徒に対して反復処理を行います。 生徒が Xiao A の場合、彼のスコアを少なくとも 60 点に制限するルールを適用します。そうでない場合は、元のスコアが少なくとも平均値であるかどうかを確認し、平均値である場合は 2 を減算します。 

このアプローチはすでに線形時間で実行されます。 計算を明示的に複数のパスに分割したとしても、総コストは O(n) です。 最適化について考える唯一の理由は、平均値を誤って再計算したり、更新された値と元の値を混合したりすることを避けるためです。 

重要な洞察は、これがフィードバック付きのシミュレーションではないということです。 決定境界が定義された後は、何も変更しません。 元の配列を保存して平均を 1 回計算すると、他のすべての操作は各要素に対する単純な決定論的変換になります。 これにより、問題は初期スコアから最終スコアまでの単一パス マッピングに縮小されます。 

動的構造を維持したり、変換前に並べ替えたりすることに利点はありません。 並べ替えは、スコアではなく ID による最終出力ステップでのみ関係します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n) | O(n) | 承認済み |
 | 直接計算 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての生徒の記録を読み取り、(student_id、score) のペアとして保存します。 出力は入力順ではなく ID でソートする必要があるため、完全なストレージが必要です。 
2. すべての元のスコアの合計を計算し、n で割って平均値を取得します。 この値は計算全体を通じて固定しておく必要があります。 
3. 入力シーケンス内の位置 m によって Xiao A を識別し、彼の元のスコアを別に保存します。 意思決定のために変更しないでおきます。 
4. 学生 ID から最終スコアまでのマッピングを作成します。 元の値に適用されるルールに基づいてこれを入力します。 
5. 各生徒に対して繰り返します。 生徒が Xiao A の場合、スコアを max(60,original_score) に設定します。 これにより、他のものに影響を与えることなく、最小限の通過調整が確実に適用されます。 
6. 他のすべての生徒については、元のスコアと計算された平均値を比較します。 Original_score ≥ Average の場合は、0 を下回らないように 2 減らします。それ以外の場合は、変更しないでください。 
7. すべての学生を処理した後、学生 ID で並べ替え、最終スコアを出力します。 

### なぜ効果があるのか

 正確さは、すべての決定が固定の参照状態、つまり元のスコア配列を使用して行われるという事実から得られます。 平均により、生徒を 2 つのグループに静的に分割することが定義され、Xiao A の調整はその分割とは独立しています。 中間結果に依存するルールがないため、変換は要素ごとに適用される純粋な関数です。 並べ替えは出力順序にのみ影響し、計算には影響しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

students = []
id_list = []
scores = []
a_idx = m - 1  # m is given in input order position

for _ in range(n):
    sid, sc = map(int, input().split())
    students.append((sid, sc))
    id_list.append(sid)
    scores.append(sc)

total = sum(scores)
avg = total / n

a_id, a_score = students[a_idx]

result = {}

for sid, sc in students:
    if sid == a_id:
        result[sid] = max(60, sc)
    else:
        if sc >= avg:
            sc = max(0, sc - 2)
        result[sid] = sc

students.sort(key=lambda x: x[0])

print(" ".join(str(result[sid]) for sid, _ in students))
```この実装では、学生の生のリストと最終結果の辞書という 2 つの並列表現が保持されます。 辞書を使用する理由は、出力順序がソートされた ID に依存し、入力順序とは異なる場合があるためです。 平均は変更前に 1 回計算され、しきい値ロジックの正確性が保証されます。 

微妙な点は、Xiao A を正しく識別することです。 入力により、m が学生 ID ではなく入力位置を参照することが保証されます。 そのため、m - 1 を使用して保存されたリストに直接インデックスを付けます。

```これにより、平均が元のデータから固定されており、Xiao A の調整が他のデータに影響を与えないことが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    data = inp.strip().split()
    n = int(data[0])
    m = int(data[1])

    students = []
    idx = 2
    for _ in range(n):
        sid = int(data[idx]); sc = int(data[idx+1])
        idx += 2
        students.append((sid, sc))

    total = sum(sc for _, sc in students)
    avg = total / n

    a_id, a_score = students[m-1]

    res = {}
    for sid, sc in students:
        if sid == a_id:
            res[sid] = max(60, sc)
        else:
            if sc >= avg:
                sc = max(0, sc - 2)
            res[sid] = sc

    students_sorted = sorted(students)
    return " ".join(str(res[sid]) for sid, _ in students_sorted)

# provided samples
assert run("3 2\n1 1\n2 4\n3 100") == "1 60 98"
assert run("4 2\n4 49\n2 98\n3 1\n1 22") == "22 98 1 47"

# all equal
assert run("3 1\n2 50\n1 50\n3 50") == "48 60 48"

# minimum n
assert run("1 1\n1 59") == "60"

# boundary average
assert run("2 1\n1 60\n2 60") == "58 60"

# high skew
assert run("3 3\n1 0\n2 0\n3 100") == "0 0 98"

 | 独身学生 | 60 | 最小の場合 |

 ## 特殊なケース

 エッジケースの 1 つは、すべてのスコアが同一である場合です。 この状況では、平均が各スコアに等しいため、Xiao A 以外のすべての生徒が減点の対象となります。 入力の場合:```
3 1
2 50
1 50
3 50
```平均は 50 です。Xiao A (学生 2) は 60 になります。他のすべては 2 減らされ、それぞれ 48 になります。 アルゴリズムは ≥ 条件を正しく適用します。 

もう 1 つのエッジケースは、1 人の生徒です。 入力の場合:```
1 1
1 59
```平均は 59 です。Xiao A は唯一の生徒で、60 に固定されています。他に更新がないため、出力は 60 です。他の生徒に対するループは空であるため、アルゴリズムはこれを自然に処理します。 

最後のエッジケースは、Xiao A がすでに 60 をはるかに超え、平均を超えている場合です。 入力の場合:```
2 2
1 100
2 90
```平均は 95 です。生徒 1 は平均を下回っているため、変化はありません。 max(60, 90) が 90 であるため、Xiao A は 90 のままです。最終的な出力は、順序を除いて変更されません。 これにより、Xiao A のルールが他のルールに適用されるしきい値条件と相互作用しないことが確認されます。
