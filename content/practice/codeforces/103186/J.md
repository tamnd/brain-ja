 ## 解決策
 ## 問題の理解

 行に配置されたカードの値を表す一連の整数が与えられます。 アリスとボブの 2 人のプレイヤーは、すべてのカードが取られるまで、ターンごとに交互に 1 枚のカードを選びます。 アリスはいつも最初に動きます。 どちらのプレイヤーも完全に最適です。アリスはボブに対する最終的な利点を最大化しようとしますが、ボブは同じ利点を最小限に抑えようとします。 

プレイヤーのスコアは、プレイヤーが選んだカードの値の合計として定義されます。 最終的な関心数量は、すべてのカードが取られた後のアリスの合計とボブの合計の差です。 

アリスがセットを集めたら$A$そしてボブはセットを集めます$B$、次を計算したいとします。$$\sum A - \sum B$$面白いのは、これが完全な情報交互ゲームであるということです。 それぞれの動きは、当面の利益だけでなく、将来のカードの利用可能性も変化させるため、貪欲な「常に最良のカードを取得する」戦略が明らかに正しいとは言えません。 

制約$n \le 5000$ということを示唆している$O(n^2)$または$O(n^2 \log n)$解決策は許容されますが、サブセットや順列にわたる指数関数的なものは実行不可能です。 すべてのゲーム状態にわたる単純なミニマックスでは、あらゆる可能なピック順序が考慮されます。$n!$、明らかに不可能です。 

重要なエッジケースは負の値から発生します。 すべての数値が負の場合、「大きな正の数を取る」という直感は完全に壊れます。 たとえば、$[-1, -10, -20]$、「大きい」ということは利益が増えるのではなくマイナスが少ないことを意味するため、最良の手が明らかではありません。 もう 1 つのエッジ ケースは、早期に大きなプラスを取ると、後で対戦相手をさらにマイナスの値に追い込む可能性がある混合サインです。これは戦略的に重要です。 

もう 1 つの微妙なケースは、値が同一または対称である場合です。 例えば、$[5, 5, 5, 5]$、最適な戦略は問題ではなく、最終的な差はゼロになるはずです。 順序付けアーティファクトに依存するソリューションは、タイでも正確さを維持する必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、考えられるすべてのゲーム状態をシミュレートします。 各ステップで、プレイヤーは残りのカードの 1 つを選択し、プレイヤーを切り替えながら次の状態に戻ります。 これは、サブセットに対する標準のミニマックス再帰です。 

これは最適なプレーを完全にモデル化するため概念的には機能しますが、指数関数的です。 メモ化しても状態数は$2^n$、残りのカードの各サブセットは個別の状態であり、遷移には最大まで試す必要があるためです。$O(n)$選択肢。 それは大まかに与えます$O(n \cdot 2^n)$、これは実現可能性をはるかに超えています。$n = 5000$。 

重要な観察は、ゲームが実際には手の同等性を超えた順序制約に依存していないということです。 各カードは正確に 1 回取られ、各プレイヤーは正確に取ります$\lfloor n/2 \rfloor$または$\lceil n/2 \rceil$カード。 最適な戦略は、ボブが同様に彼女のアドバンテージを破壊しようとしている場合に、アリスがどのカードを確保できるかを決定することになります。 

目標を書き直すと効果的です。 合計を$S$。 アリスが合計を取る場合$A$、ボブは得ます$S - A$、 それで：$$A - (S - A) = 2A - S$$したがって、アリスの利点を最大化することは、$A$、彼女が集めた価値の合計。 

ここで、ゲームは次のようになります。アリスは集めた金額を最大化したいと考えており、ボブはそれを最小化したいと考えていますが、両方が交互に選択します。 各移動は単純に 1 つの要素を削除するため、この構造は、位置制約のないマルチセット上の古典的な交互選択問題に帰着します。 

最適な戦略は、ソートされた値に貪欲です。両方のプレーヤーは、値の順序で残りの極値から効果的に選択しますが、隣接性や構造の制約がないため、最適な結果は、すべての値をソートし、最大値から最小値へ交互に割り当てることによって単純に決定されます。 

最初に動くアリスは、この最適なプレイ モデルで利用可能な最大の値を確保します。 

したがって、解決策は、配列を降順でソートし、インデックス 0 から始まる 2 番目の要素ごとに合計することになります。

 ## アルゴリズムのチュートリアル

 1. カード値のリストを降順に並べ替えます。 

これにより、価値の低いカードよりも価値の高いカードを常に考慮することが保証されます。これは、両方のプレイヤーの強さが対称的であり、価値の相対的な順序のみが重要であるため、これが必要です。 
2. インデックスを割り当てることで、最適な交互ピックをシミュレートします。アリスは 0、2、4 などの位置を取り、ボブは暗黙的に 1、3、5 などの位置を取ります。 

これが機能するのは、ソート後、各プレイヤーが常に最も高い残りの値を優先し、交互のターンによって正確にこの分割が強制されるためです。 
3. ソートされた配列の偶数インデックスの値を加算して、アリスの合計を計算します。 
4. 合計合計からアリスの合計を減算して、ボブの合計を暗黙的または直接的に計算します。 
5. 差分を出力する$A - B$、これは以下と同等です$2A - S$。 

これにより、必要に応じて別の Bob アキュムレータを維持する必要がなくなります。 

### なぜ効果があるのか

 重要な不変条件は、並べ替え後のプレイの相対的な順序が常にグローバル ランキングと一致することです。 どちらのプレイヤーも常に高い値を好み、残りのカードへのアクセスを妨げる構造的な制約がないため、ゲームは決定論的なランクの割り当てに陥ります。アリスはソートされた順序で偶数ランクの要素をすべて受け取り、ボブは奇数ランクのすべての要素を受け取ります。 局所的な偏差によってどちらのプレイヤーの結果も改善されることはありません。残りの最大値を取ることから逸脱すると、同じプレイヤーにとってより厳密に優れた選択肢が即座に失われるか、次の動きで対戦相手にその選択肢が与えられてしまうからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort(reverse=True)
    
    alice = 0
    for i in range(0, n, 2):
        alice += a[i]
    
    total = sum(a)
    bob = total - alice
    
    print(alice - bob)

if __name__ == "__main__":
    solve()
```実装はまず配列を読み取り、降順に並べ替えます。 このループは、インデックス 0 から始まる 2 つおきの要素を取得することによってアリスのシェアを累積し、交互シーケンスにおける彼女の先手有利を反映します。 最終的な差はアイデンティティを使用して計算されます。$A - B = 2A - S$、ボブへの余分なパスを回避します。 

ここでよくある落とし穴は、アリスが最初に移動することを忘れることです。これにより、割り当てられたインデックスのパリティが変化します。 もう 1 つは、ソートを行わずに 2 ポインタ シミュレーションを試みていますが、最適な再生はローカルの隣接関係ではなくグローバル ランキングに依存するため、失敗します。

 ## 特殊なケース

 次のような単一要素配列の場合`[x]`, アリスはすぐにそれを受け取るので、答えは簡単です。`x`。 このアルゴリズムはソートしてインデックス 0 を取得します。これは、この動作と直接一致します。 

次のようなすべてが等しい配列の場合、`[k, k, k, k]`、ソートによって順序は変更されず、アリスは合計のちょうど半分を受け取ります。 ボブは残りの半分を受け取り、差はゼロになります。 偶数インデックスの累積により合計のちょうど半分が得られ、同点でも正確さが維持されます。 

次のようなすべて負の配列の場合`[-1, -2, -3, -4]`、ソートにより生成される`[-1, -2, -3, -4]`。 アリスは取る`-1`そして`-3`、ボブは取る`-2`そして`-4`。 このアルゴリズムは、負の値が少ないことを正しく優先します。これは、すべての寄与が有害である場合でも、アリスの合計を最大化することと一致します。
