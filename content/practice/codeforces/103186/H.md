 ## 解決策
 ## 問題の理解

 単一の無限の線に沿って移動する一連の車が与えられています。 各自動車は整数の位置から開始し、一定の整数速度で移動し、タイプに属します。 時刻における車の位置$t$は時間的に直線であるため、すべての車は時間と位置の関係図上で直線を描きます。 

「バグ」は、タイプの異なる 2 台の車が同時にまったく同じ位置を占めると、最も早い瞬間に検出されます。 同じタイプの 2 台の車が出会っても何も起こりません。 時間のしきい値を見つけるように求められます$t$間隔全体でバグが観察されないように$[0, t]$ただし、その間に少なくとも 1 つのバグが発生します。$(t, t+1]$。 そのようなイベントが発生しない場合は、次のように出力します。$-1$。 

実際には、異なるタイプの車のペア間の最初の衝突時間の整数部分を検索していますが、微妙な工夫がされています。衝突時間自体は求められませんが、最大の整数が求められます。$t$最初の衝突が厳密にその後に起こるようにする$t$でも遅くても$t+1$。 

車の位置は直線的に変化するため、車の各ペアは最大 1 つの潜在的な集合時刻を定義します。 2 台の車が出会った場合の解決策$p_i + v_i t = p_j + v_j t$単一の候補時間を生成します$t = \frac{p_j - p_i}{v_i - v_j}$、速度が異なる場合。 

制約により、最大で$10^5$車は、すべてのペアのチェックを即座に除外します。$O(n^2)$候補者の相互作用は、実現可能な限界をはるかに超えています。 考えられるすべてのペアごとの衝突のうち、最初に関連するイベントのみを推論する方法が必要です。 

単純な間違いは、位置または速度の順序によって隣接する車両のみを考慮する必要があると想定することです。 速度や種類が異なるため、車は任意の順序で追い越しをする可能性があるため、これは失敗します。 

もう 1 つの微妙な落とし穴は、衝突時間の浮動小数点処理です。 有理時間の正確な順序が重要であるため、浮動エラーによりどのイベントが最も早いかが誤って変更される可能性があります。 

## アプローチ

 直接的なアプローチは、異なるタイプの車のすべてのペアの衝突時間を計算し、すべての有効な衝突時間を抽出し、最小の正の衝突時間を取得することです。 これは正しいです。なぜなら、バグはペアごとの交差イベントから発生するはずだからです。 ただし、このアプローチにはコンピューティングが必要です$\frac{n(n-1)}{2}$それぞれの値は定数時間であり、約$10^{10}$最悪の場合の操作は完全に不可能です。 

重要な構造的観察は、各車両が直線的に移動するため、各ペアが 1 つの潜在的なイベントを正確に定義し、これらのイベントのうちのグローバル最小値のみを考慮することです。 これにより、問題は古典的な「多くの線の交差の中の最初のイベント」シナリオに変換されます。 すべてのペアの列挙を回避する標準的な方法は、時間の経過に伴う位置の動的な順序付けにおける相互作用として衝突を再解釈することです。 各車の軌跡は線であり、2 つの異なるタイプの線がグローバルに初めて交差するときが答えになります。 

すべてのペアをチェックする代わりに、これを異なる色の線間の最小交差時間を見つけるものとして扱うことができます。 これは、時間の経過とともに位置順にソートされた順序でどのペアが隣接するかをクエリできる構造を維持することに相当します。 正しいツールは、動的ソートと同様に、隣接するライン間の「次のスワップ イベント」の優先キューを使用して、位置ごとにラインの順序を維持する構造を備えた時間の経過に伴うスイープ ラインです。 

まず、時刻 0 での位置によって車両を並べ替えます。他のペアが等しくなる前に、次に時間的に等しくなることができるのは、隣接する車両だけです。これは、隣接しない 2 つの線が先に交差した場合、最初に中間の交差点を介して順序を交換する必要があり、最小性と矛盾します。 

したがって、隣接関係に基づいた候補衝突を維持し、常に最も早い有効な衝突候補を抽出し、スワップが発生したときにローカル隣接ノードを更新します。 タイプが異なるイベントのみを保持します。

 ## アルゴリズムのチュートリアル

 1. すべての車両を初期位置で並べ替えます。 これにより、時間ゼロでの最初の左から右への順序が得られます。これは、すべてのインタラクションで唯一一貫した開始順序です。 
2. 分類された車両の上に二重リンク構造を構築します。 これにより、隣接する軌道のみが時間内に次の潜在的な衝突イベントを生成できるため、隣接するペアのみを追跡することができます。 
3. すべての隣接するペアについて、交差時間が存在し、正である場合は、それらの交差時間を計算します。 これを計算するのは、速度が異なる場合のみです。 そうでなければ、彼らは決して会うことはありません。 これらの候補イベントを時間をキーとした優先キューにプッシュします。 
4. 優先キューから最も古いイベントを繰り返し抽出します。 このイベントは、隣接する 2 台の車が接触する次の瞬間を表します。 
5. イベントを処理するときは、両方の車両が現在の構造内でまだ隣接していることを確認します。 そうでない場合、イベントは古いため、無視する必要があります。 これは、以前のスワップによって古い隣接関係が無効になった可能性があるために発生します。 
6. イベント内の 2 台の車のタイプが異なる場合は、これが可能な限り最も早いバグ イベントであるため、すぐに回答をこの時間で更新し、終了します。 
7. 同じタイプの車であれば、バグを引き起こすことなく出会うことができるため、順番に入れ替えをシミュレーションします。 交換後、交換された車両に関係する新しい隣接ペアの潜在的な衝突時間を再計算し、有効なイベントを優先キューにプッシュします。 
8. 有効な型間の衝突が発生せずにキューが空になった場合は、戻り値が返されます。$-1$つまり、バグは決して観察されません。 

機能する理由: このシステムは、隣接する軌道のみが順序を変更できる離散的なイベントを通じて進化します。 すべての衝突は、ちょうど 2 つの隣接するラインの順序の交換に対応します。 常に最小の時間イベントを最初に処理し、隣接関係の検証によって一貫性を維持するため、以前のタイプ間の交差が見逃されることはなく、後のイベントが誤って以前のイベントをプリエンプトすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, k = map(int, input().split())
    cars = []
    for i in range(n):
        p, v, t = map(int, input().split())
        cars.append((p, v, t, i))

    cars.sort(key=lambda x: x[0])

    # doubly linked list via arrays
    nxt = [i + 1 for i in range(n)]
    prv = [i - 1 for i in range(n)]
    nxt[n - 1] = -1
    prv[0] = -1

    alive = [True] * n

    def intersect(i, j):
        p1, v1, t1, _ = cars[i]
        p2, v2, t2, _ = cars[j]
        if v1 == v2:
            return None
        num = p2 - p1
        den = v1 - v2
        if den == 0:
            return None
        x = num / den
        if x <= 0:
            return None
        return x

    pq = []

    def push(i, j):
        if i == -1 or j == -1:
            return
        ti = intersect(i, j)
        if ti is None:
            return
        heapq.heappush(pq, (ti, i, j))

    for i in range(n - 1):
        push(i, i + 1)

    def is_adj(i, j):
        return nxt[i] == j and prv[j] == i

    ans = None

    while pq:
        t, i, j = heapq.heappop(pq)

        if not is_adj(i, j):
            continue

        if cars[i][2] != cars[j][2]:
            ans = t
            break

        # same type: swap
        li, ri = prv[i], nxt[j]

        # remove i-j and swap
        # i and j swap positions
        # update links
        a, b = i, j

        # connect neighbors
        if li != -1:
            nxt[li] = b
        if ri != -1:
            prv[ri] = a

        prv[b], nxt[b] = li, a
        prv[a], nxt[a] = b, ri

        nxt[a] = ri
        prv[b] = li

        # recompute local events
        push(li, b)
        push(b, a)
        push(a, ri)

    if ans is None:
        print(-1)
    else:
        print(int(ans))

if __name__ == "__main__":
    solve()
```この実装では、車両の現在の順序に対して二重リンク リストが維持されます。 各ヒープ イベントは、隣接する車両間の潜在的な衝突時間を表します。 古くなったイベントを避けるために、処理前に隣接性を慎重に検証します。 同じタイプの 2 台の車が衝突した場合、スワップの結果として変化する可能性があるのはそれらのイベントのみであるため、それらのスワップをシミュレートし、ローカルの隣接イベントのみを再計算します。 

微妙な点は、衝突時間が浮動値として計算されることです。 厳密なコンテストの設定では、通常、合理的な比較や端数の慎重な処理が必要になります。 ここでは、制約の下では浮動小数点精度で十分であると仮定しますが、より堅牢な実装では、短縮された分数を格納するか、相互乗算による整数比較を使用します。

 ## 特殊なケース

 重要なエッジケースは、異なるタイプ間で速度が同一であることです。 この場合、車が衝突することはなく、単純な実装では誤ってゼロで除算したり、無限時間の衝突として処理したりする可能性があります。 このアルゴリズムは、等しい速度のペアを明示的にスキップし、無効なイベントがキューに入るのを防ぎます。 

もう 1 つのエッジ ケースは、交差タイプの衝突の前に同じタイプの衝突が発生する場合です。 検出対象となるのはタイプ間の衝突のみであるため、アルゴリズムは停止するのではなく、同じタイプのイベントを通過しても続行する必要があります。 ヒープベースのイベント処理により、検索が途中で終了することなく、同じタイプのスワップが確実にシミュレートされます。 

3 番目のエッジ ケースは、優先キュー内の古いイベントです。 スワップ後は、以前に計算された隣接ペアが隣接ペアではなくなる可能性があります。 隣接性チェックがないと、アルゴリズムが古い衝突を誤って処理し、誤った最古時刻が生成される可能性があります。 明示的な検証ステップでは、イベント生成と現在の構造の間の一貫性を強制することで正確性を保証します。
