 ## 解決策
 ## 問題の理解

 複数の生徒のセットが与えられ、各生徒には整数の「身長ランク」が与えられます。同じ値は同じ身長を意味します。 タスクは、すべての生徒を同じ長さの 2 つの列に配置することです。 あれば$n$学生、両方の行に含まれる$n/2$位置は左から右にインデックス付けされます。 

各行の高さは左から右に向かって減少しない必要があります。 さらに、2 つの行を列ごとに見ると、2 行目の生徒の身長は、1 行目のすぐ上の生徒と少なくとも同じでなければなりません。 したがって、すべての列は垂直方向に弱く増加するペアを形成し、各行自体は水平方向に弱く増加します。 

私たちは、生徒が別の立場になった場合、2 つの取り決めを異なるものとして扱い、そのような有効な取り決めがいくつ存在するかを数えるよう求められます。 答えは 998244353 を法として計算する必要があります。 

入力は高さを直接与えるのではなく、重複を含む並べ替えられた順序でランクを与えます。 これは、等しい要素の相対的な順序は重要ではありませんが、多重度は重要であるマルチセットを効果的に操作していることを意味します。 

制約$n \le 5000$は、おおよそ以下の解決策が得られることを意味します。$O(n^2)$または$O(n^2 \log n)$は許容されますが、階乗列挙や指数関数的状態爆発などは不可能です。 プレフィックス状態に対する動的プログラミングまたは組み合わせ構築を期待する必要があります。 

重要な点は、重複を正しく処理することです。 複数の生徒が同じ身長を共有している場合、行間または行内で生徒を交換すると、位置の同一性に応じて異なる構成が生成される場合と生成されない場合があります。 等しい値を区別できないものとして扱う単純なアプローチでは、注意を払わないと過小評価または過大評価される可能性があります。 

小さなエッジケースは、すべての高さが等しい場合です。 その場合、有効な配置は純粋に行の構造的制約に依存し、カウントは単調な 2 行の塗りつぶしをカウントすることになりますが、これはまだ組み合わせ論的に自明ではありません。 もう 1 つのエッジ ケースは、高さが厳密に増加する場合です。この場合、制約が大幅に厳しくなり、基本的に単一の順序構造が強制されます。 

## アプローチ

 直接的な総当たり解釈では、それぞれの$n$学生を 2 つの行のいずれかに配置し、各行を並べ替えて妥当性をチェックします。 順列を無視して代入だけを試したとしても、$\binom{n}{n/2}$一番上の行を選択する方法と、それぞれの選択肢について、行内に配置することで階乗因数が追加されます。 これは、たとえ$n=20$。 中心的な問題は、有効性がパーティション化だけでなく、各行内で発生するソートされた構造にも依存するため、単純な列挙では同等の順列を探索する労力が無駄になることです。 

構造上の観察としては、各行にどの要素を入れるかを決定したら、両方の行を独立して非降順で並べ替える必要があるということです。 これにより、内部の置換が完全に削除されます。 したがって、問題はサイズのサブセットを選択することになります。$n/2$両方のサブセットをソートした後、列方向の条件が成立するような最初の行: 各位置について$i$、$top[i] \le bottom[i]$。 

ここでの重要なアイデアは、値を昇順に処理し、2 つの行を段階的に構築することです。 要素はその値を除いて区別できないため、意味のある唯一の状態は、各値の要素の数が値の接頭辞で最初の行と 2 行目に割り当てられているかどうかです。 これにより、周波数に対する動的計画法が定式化されます。 

させて$cnt[v]$value の出現数になります$v$。 値を昇順に処理し、各ステップで発生する値を分散します。$v$2 つのグループに分けます。一部は上の行に移動し、残りは下の行に移動します。 両方の行がソートされ、列方向に有効であるという制約は、値を入力するときという単純な実現可能性条件に変換されます。$v$、すべてのプレフィックスで、最上行に割り当てられる要素の数が決して超えないことを確認する必要があります。$n/2$、下の行も同様です。 以前の値はすべてそれより小さいか等しいため、順序制約は自動的に保持され、値ブロック内の割り当ては単調性を保持します。 

残りの問題は、両方の行が正確に終わることを確認しながら、すべての値の分布をカウントすることです。$n/2$要素。 これはナップザックのような DP となり、これまでに最上行に割り当てられた要素の数を追跡します。 

dp[i][j] を、最初の i 個の個別の値を処理した後の方法の数として定義し、j 個の要素を最上行に配置します。 周波数 f の値 v ごとに、0 から f までのすべての分割 k を試行します。k 要素は上に、f-k は下に移動します。 次に、j から j+k に遷移します。 

複雑さは$O(m \cdot n \cdot f)$最悪の形ではありますが、周波数の合計は n であるため、合計の遷移は次のように最適化できます。$O(n^2)$、快適にフィットします。 

ブルート フォースは代入を明示的に探索するため機能しますが、階乗冗長性により失敗します。 DP が機能するのは、値ごとに意味のある唯一の決定は各行にコピーが何個入るかということであり、すべての置換が組み合わせ二項選択に崩壊するためです。

 ## アルゴリズムのチュートリアル

 1. 入力を昇順でそれぞれの個別の高さの値の周波数に圧縮します。 これが必要なのは、等しい値内の同一性ではなく、多重度のみが重要であるためです。 
2. DP 配列を初期化します。ここで、dp[j] は、正確に j 個の要素が最上行に配置されるように処理された値を割り当てる方法の数を表します。 要素が割り当てられていないため、最初は dp[0] = 1 となり、単一の有効な空の構成になります。 
3. 周波数 f でそれぞれの個別の値を処理します。 この値に対して、次に新しい DP 配列を計算します。最初はすべてゼロです。 この配列は、2 つの行間で f 個の同一の要素を分散する方法を蓄積します。 
4. dp の各現在の状態 j について、0 から f までのすべての k について、現在の値の k 個の要素を上の行に配置し、f-k を下の行に配置することを検討します。 このような各選択は、dp[j] に次の値を乗じたものに寄与します。$\binom{f}{k}$次へ[j+k]。 
5. すべての値を処理した後、最上行のちょうど半分の要素が必要なため、最終的な答えを dp[n/2] とします。 

二項係数が必要なのは、各値グループ内で、値が同一であっても、どの特定の出現を最上行に置くかを選択することが組み合わせ的に重要であるためです。 

### なぜ効果があるのか

 v までの値を処理する任意の時点で、dp[j] は、処理された値からの正確に j 個の要素が最上行にあるすべての有効な部分割り当てを表します。 値を昇順に処理するため、値グループ内の割り当てでは両方の行の並べ替え順序が維持されます。 両方の行がグローバルに非減少する値のシーケンスから構成されているため、列の制約が自動的に満たされ、各行内の順序がグローバルに保持されます。 DP 遷移では、各値グループを個別に分散するためのあらゆる方法が尽くしられます。各値のコピーが最上位の行に移動する数の選択にそれぞれ一意に対応するため、2 つの異なる DP パスが同じ最終割り当てを生成することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    # compress frequencies
    freq = []
    i = 0
    while i < n:
        j = i
        while j < n and a[j] == a[i]:
            j += 1
        freq.append(j - i)
        i = j

    dp = [0] * (n + 1)
    dp[0] = 1

    used = 0

    for f in freq:
        ndp = [0] * (n + 1)
        # precompute binomial coefficients for this block
        # since f is small relative and total sum n <= 5000, direct computation is fine
        C = [[0] * (f + 1) for _ in range(f + 1)]
        for i in range(f + 1):
            C[i][0] = 1
            for j in range(1, i + 1):
                C[i][j] = (C[i-1][j-1] + C[i-1][j]) % MOD

        for j in range(used + 1):
            if dp[j] == 0:
                continue
            for k in range(f + 1):
                ndp[j + k] = (ndp[j + k] + dp[j] * C[f][k]) % MOD

        used += f
        dp = ndp

    print(dp[n // 2] % MOD)

if __name__ == "__main__":
    solve()
```個別の高さごとのカウントのみが重要であるため、実装ではまず入力を並べ替えて周波数ブロックに圧縮します。 動的プログラミング配列は、各ブロックの処理後に最上行に割り当てられた要素の数を追跡します。 トランジションは、現在のブロックからの要素の数が最上行に配置されることを繰り返し、同一要素間の内部選択を表す二項係数によって重み付けされます。 

重要な実装の詳細は、慎重なインデックス付けです。dp 範囲は、処理される要素の数まで拡張する必要があるだけなので、次を使用します。`used`遷移を制限し、不必要な計算を回避します。 

簡単にするために、二項テーブルはブロックごとに再計算されます。 合計以来$n \le 5000$、全体のコストは制限内にとどまります。

 ## 特殊なケース

 エッジケースの 1 つは、すべての値が同一である場合です。 この場合、順序の制約は無関係であり、答えは純粋にどちらの半分を一番上の行に置くかを選択することになります。 f = n の単一周波数ブロックは dp[n/2] = を生成するため、DP はこれを正しく処理します。$\binom{n}{n/2}$。 

もう 1 つの特殊なケースは、すべての値が異なる場合です。 ここで、すべての値は f = 1 の独自のブロックであり、DP はパスカルの三角形を構築する標準の二項畳み込みとなり、次の結果が得られます。$\binom{n}{n/2}$。 これは、並べ替えによって有効性が自動的に強制されるため、どのサブセットでも機能するという直観と一致します。 

のような混合ケース`1 1 2 2`ブロック間の相互作用をテストします。 最初のブロックを処理した後、dp は 1 のすべての分割を反映します。 2 番目のブロックを処理すると、これらのカウントが正しく乗算およびシフトされ、最上位行の合計サイズ制約を維持しながら値グループ間の独立性が維持されます。
