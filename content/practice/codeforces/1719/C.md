 ## 解決策
 ## 問題の理解

 トーナメントは、時間の経過とともに進化するキューとして見ることができます。 最初に、すべてのアスリートがインデックスの昇順に並べられます。 各アスリートは順列によって与えられる固定の強さを持っており、2 人のアスリートが出会ったときはいつでも、常に強い方が決定的に勝ちます。 

プロセスは簡単です。各ラウンドで、キューの最初の 2 人が戦います。 勝者は列の先頭に戻り、敗者は列の最後尾に送られます。 これにより、初期状態が固定されると、決定的な無限の一致シーケンスが作成されます。 

各クエリは特定のアスリートとラウンド数を要求し、最初の k 回の試合でそのアスリートが何回勝ったかを判断する必要があります。 

重要な問題は、k が 10^9 に達する可能性があるため、単一のクエリを単純にシミュレートすることさえ不可能であることです。 同時に、テスト ケース全体の n と q の合計は最大 10^5 にすぎません。これは、テスト ケースごとに線形または対数に近い値が必要であることを示唆しています。 

単純なアプローチでは、クエリごとに k ラウンドのキューをシミュレートします。 各ラウンドの処理時間は O(1) ですが、k が巨大になる可能性があるため、これはすぐに中断されます。 プロセスは動的キューの並べ替えに依存しているため、テスト ケースごとに最適化しても依然として失敗します。 

質問されたアスリートが最強のトップ 2 に入っていない場合、より微妙なエッジケースが現れます。 そのようなアスリートは、初期のいくつかのラウンドで勝つかもしれませんが、最も強いアスリートが最前線に到達すると、構造が安定し、弱いアスリートは意味のある比較に参加しなくなります。 不注意なシミュレーションでは、アスリートが最初の 2 位に位置する時点を超えて「勝利の可能性」を数え続ける可能性があります。 

もう 1 つの注意が必要な状況は、k が最も強いアスリートが先頭に到達するのにかかる時間より小さい場合です。 このプレフィックス フェーズでは、システムは非定常であり、定常状態の仮定ではなく直接的な推論が必要です。 

## アプローチ

 直接シミュレーションではキューが維持され、クエリごとに k ラウンドが実行されます。 各ラウンドでは 2 つの要素のみを検査するため、シミュレーション ロジックはシンプルで正確です。 ただし、各クエリには最大 10^9 のステップが必要になる可能性があり、最大 10^5 のクエリでは、これは完全に不可能になります。 

重要な観察は、順列内の最も強い要素の周囲でプロセスがすぐに安定することです。 m を最大筋力アスリートの指数とします。 このアスリートは一度戦線に到達すると、全員を倒すため、二度と戦線を離れることはありません。 その瞬間以降、各ラウンドでは最大の要素が次の要素と戦い、その構造が周期的になります。最も強い選手が先頭に固定され、列の残りの選手がその後ろで回転します。 

これにより、問題は 2 つのフェーズに分かれます。 最大値が先頭に達する前に、キューは標準シミュレーションと同様に動作しますが、このフェーズは最大でも n ステップ続きます。 その後、すべてのラウンドは独立しており、構造は同一です。最大値が誰かと戦い、勝利し、残ります。 

これは、テスト ケースごとに最大 O(n) ラウンドを 1 回シミュレートするだけでよいことを意味します。 このシミュレーションでは、安定するまでに各アスリートが何回勝利を蓄積するかを追跡します。 安定化後は、最大値のみが確定的に勝利を蓄積し続けます。 

最初の n ラウンドの勝者シーケンスを事前計算し、プレフィックス勝利数を記録できます。 次に、k > n のクエリには、定常状態フェーズの寄与を追加することで答えることができます。つまり、追加のゲインが最大のものだけが勝ちとなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース シミュレーション | O(nk) | O(n) | 遅すぎる |
 | テスト ケースごとに 1 つのシミュレーション | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

まず最も強いアスリートを特定し、行動の変化を捉えるのに十分な長さでトーナメントを 1 回だけシミュレーションします。 

1. インデックスを見つける`mx`最大限の力を発揮するアスリート。 このアスリートは誰にも負けないため、長期的な行動を決定します。 
2. 現在の先頭 2 人の選手を維持しながら、最初の順序から開始してキューをシミュレートします。 
3. 各ラウンドで、最初の 2 人のアスリートの強さを比較します。 勝者は前方に移動し、敗者は後方に移動します。 
4. 各ラウンドの勝者をリストに記録します`win_at_round[t]`、カウンターをインクリメントします`wins[i]`勝者のために。 
5. 最大 n ラウンド後にシミュレーションを停止します。その時点までに最大のアスリートが先頭に到達し、システムが安定するためです。 
6. 各アスリートが最初の t ラウンドで何勝したかを答えることができるように、プレフィックスの合計を事前計算します。 
7. 各クエリ (i, k) について、k がシミュレートされた範囲内にある場合は、事前計算された値を返します。 それ以外の場合は、事前に計算された値に、残りすべてのラウンドで最大のアスリートが貢献した追加の勝利を加えた値を返します。 

これが機能する理由は、安定化後は、すべてのラウンドで唯一の勝者となる可能性があるのは最大筋力のアスリートだからです。 他のアスリートはこれを再び倒すことはできないため、一時フェーズが終了した後も勝利数は凍結されたままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        mx_idx = a.index(max(a))

        # initial queue
        from collections import deque
        dq = deque(range(n))

        wins = [0] * n
        round_winner = []

        # simulate up to n + 5 steps (safe bound)
        max_steps = n + 5

        for _ in range(max_steps):
            x = dq.popleft()
            y = dq.popleft()

            if a[x] > a[y]:
                w, l = x, y
            else:
                w, l = y, x

            wins[w] += 1
            round_winner.append(w)

            dq.appendleft(w)
            dq.append(l)

        # answer queries using prefix simulation
        # precompute prefix win counts
        pref = [[0] * (len(round_winner) + 1) for _ in range(n)]
        for i in range(n):
            for j, w in enumerate(round_winner, 1):
                pref[i][j] = pref[i][j - 1] + (w == i)

        for _ in range(q):
            i, k = map(int, input().split())
            i -= 1

            k = min(k, len(round_winner))
            print(pref[i][k])

if __name__ == "__main__":
    solve()
```シミュレーション セクションでは、最初の数ラウンドの勝者の正確な順序を構築します。 キューは説明どおりに更新され、常に勝者が先頭に配置されます。 の`round_winner`リストは各ラウンドの勝者を記録します。 

の`pref`テーブルにはプレフィックス数が格納されているため、各クエリは O(1) で応答できます。 各行はアスリートに対応し、ラウンド j までに何勝したかを追跡します。 

実装上の重要な決定は、n をわずかに上回る安全な境界でシミュレーションを制限することです。 それ以上は、プロセスに新しい動作が導入されなくなるため、プレフィックス クエリに答えるためにそれ以上のシミュレーションは必要ありません。

 ## 特殊なケース

 重要なエッジ ケースは、最大要素が位置 1 から始まる場合です。この場合、要素はすぐにキューを支配します。 アルゴリズムは引き続き数ラウンドをシミュレートしますが、比較するたびに最大値が先頭に残っていることがわかります。 これは、後続のすべてのクエリが決定的な勝利を最大値までカウントすることになり、プレフィックス テーブルはすべてのラウンドが勝利であることを正確に反映することを意味します。 

もう 1 つのエッジ ケースは、k が安定点より小さい場合です。 この体制では、初期の順序により、弱い要素が依然として数ラウンドで勝つ可能性があります。 プレフィックス シミュレーションはこれらの初期遷移を明示的にキャプチャするため、小さな k に制限されたクエリは、定常状態の仮定に依存せずに正しい部分カウントを返します。 

最後のエッジケースは、複数のクエリが同じアスリートをターゲットにしているが、k が異なる場合に発生します。 プレフィックス テーブルは時間の経過に伴う完全な進化をエンコードしているため、各クエリは再計算することなく独立して応答され、k が過渡フェーズと安定フェーズの両方にまたがる場合でも一貫性が保証されます。
