 ## 解決策
 ## 問題の理解

 長さの順列を数えるように求められます$n$ここで、シーケンスの最大公約数は$1 \cdot p_1, 2 \cdot p_2, \dots, n \cdot p_n$は厳密に 1 より大きくなります。ここで$p$1 から 1 までの整数の順列です。$n$。 簡単に言うと、各要素にその位置を乗算し、それらの積すべてが 1 より大きい共通因数を共有するようにします。 

入力は複数のテスト ケースで構成され、それぞれが単一のテスト ケースを指定します。$n$。 出力は「美しい」順列のモジュロ数です。$998244353$。 

制約により許可されるのは、$n$最大 1000 および最大 1000 のテスト ケース。 すべての順列を生成する単純なソリューションは複雑になります。$O(n!)$、でもそれは不可能です$n = 10$。 大まかに機能するアプローチが必要です$O(n^2)$または$O(n \log n)$テストケースごとに。 

見落としやすいエッジケースには、非常に小さなケースが含まれます$n$。 のために$n=1$、唯一の順列は$[1]$、それは$\gcd(1) = 1$したがって美しくありません。 のために$n=2$、順列$[2,1]$機能するので$\gcd(2,2) = 2 > 1$。 これらは、何も仮定できないことを示しています$n > 1$自動的に解決策が見つかります。 

もう 1 つの微妙な点は、すべての積が均等になるように順序を並べ替えることができる場合に、美しい順列がしばしば生じることです。 これは、すべての順列を個別にチェックするのではなく、組み合わせパターンを示唆しています。 

## アプローチ

 ブルートフォースアプローチでは、すべてが列挙されます。$n!$順列と計算$\gcd(1\cdot p_1, \dots, n \cdot p_n)$それぞれに。 これは問題ステートメントを直接実装しているため、原理的には正しいですが、絶望的に遅いです。 たとえ$n=10$、これには 360 万の順列をチェックする必要があり、これを乗算します。$n$あたりの操作$\gcd$計算は、許容される 1 秒の実行時間をはるかに超えています。 

重要な洞察は、$\gcd$1 を超えるには、すべての数値が共通の因数を共有する必要があります。 考慮すべき最小の素数は 2 です。すべての積が偶数であることを保証できる場合、$\gcd$これにより、積が均等になる位置に偶数を割り当てるという単純な構造が得られます。 分析により、数値の前半が偶数のインデックスを占め、後半が奇数のインデックスを占める順列をカウントする漸化式を導き出すことができます。$n$偶数か奇数か。 いくつかの組み合わせ作業の後、これは次のように単純化されます。$(n//2)!^2$モジュロ$998244353$均等に$n$、奇数の場合は 0$n$。 

この観察は、奇数の位置に奇数を掛けると奇数の積が得られるという事実に基づいています。 したがって、$n$奇数、少なくとも 1 つの製品は奇数のままであり、$\gcd$1 の 1. 偶数のみ$n$すべての製品が係数 2 を共有する完全な配置が可能になります。

 | ブルートフォース | O(n!・n) | O(n) | 遅すぎる |
 | 最適 | O(n + t) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗を最大値まで事前計算する$n$モジュロ$998244353$。 これにより、$O(1)$階乗検索を実行し、各テスト ケースの再計算を回避します。 
2. テストケースの数を読み取る$t$それぞれを反復処理します$n$。 
3. それぞれについて$n$、奇数かどうかを確認します。 そうであれば、少なくとも 1 つの積が奇数になるため、0 を出力します。$\gcd$1になります。 
4. もし$n$が偶数の場合、美しい順列の数を次のように計算します。$(n//2)!^2 \mod 998244353$。 これは、数値の下半分を奇数の位置に、上半分を偶数の位置に割り当てる方法をカウントします。 
5. 各テスト ケースの結果を出力します。 

なぜ機能するのか: 不変条件は、すべての製品が次の場合にのみ偶数であるという特性を維持することです。$n$は偶数であり、各積に少なくとも 1 つの偶数因数が含まれるように数値が分散されます。 の階乗を二乗することにより、$n/2$、すべての有効な並べ替えを数値の 2 つの半分について個別に考慮します。 他のどんなアレンジメントもこれ以上の効果を生み出すことはできません$\gcd$奇妙な製品を導入すると、$\gcd$1まで下げます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAX_N = 1000

# Precompute factorials modulo MOD
fact = [1] * (MAX_N + 1)
for i in range(1, MAX_N + 1):
    fact[i] = fact[i-1] * i % MOD

t = int(input())
for _ in range(t):
    n = int(input())
    if n % 2 != 0:
        print(0)
    else:
        half = n // 2
        res = fact[half] * fact[half] % MOD
        print(res)
```コードは、計算の繰り返しを避けるために、最初に階乗を事前計算します。 テストケースごとに奇数を処理します$n$すぐに 0 を出力します。偶数の場合$n$、2 つの半分の配置が独立しているため、順列の各半分の階乗の積を計算し、階乗を 2 乗します。 モジュロ$998244353$オーバーフローが発生せず、問題の要件を満たしていることを保証します。 

## 実用的な例

 サンプル入力`4`:

 | n | n%2 | 半分 | 事実[半分] | 結果 |
 | --- | --- | --- | --- | --- |
 | 4 | 0 | 2 | 2 | 4 |

 説明：`n=4`は均等です。 半分は2です。`2! = 2`。 二乗すると 4 になります。 4 つの美しい順列があります: [2,1,4,3]、[2,3,4,1]、[4,1,2,3]、[4,3,2,1] (それぞれの半分を並べ替えるまで)。 

サンプル入力`3`:

 | n | n%2 | 結果 |
 | --- | --- | --- |
 | 3 | 1 | 0 |

 説明：`n=3`奇数です。 どの順列でもどこかに奇数の積があり、gcd=1 となります。 したがって、美しい順列は0です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    MOD = 998244353
    MAX_N = 1000
    fact = [1] * (MAX_N + 1)
    for i in range(1, MAX_N + 1):
        fact[i] = fact[i-1] * i % MOD
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        if n % 2 != 0:
            out.append("0")
        else:
            half = n // 2
            res = fact[half] * fact[half] % MOD
            out.append(str(res))
    return "\n".join(out)

assert run("1\n1\n") == "0", "smallest odd n"

 ## 特殊なケース

 のために`n=1`、アルゴリズムはすぐに識別します`n%2==1`これにより、最小の入力が正しく処理されます。 のために`n=2`、`n%2==0`、半分=1、`1!*1! = 1`単一の美しい順列に一致する出力 1`[2,1]`。 のために`n=1000`、事前に計算された階乗により、次のことが可能になります。`500!^2 % MOD`効率的に。 このアルゴリズムは奇数入力と偶数入力を区別して処理するため、奇数 `n の順列はありません。
