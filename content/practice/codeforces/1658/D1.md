 ## 問題の理解

 連続する整数セグメントを取得し、並べ替えて、すべての要素に固定 XOR マスクを適用することによって生成された最終的な配列が与えられます。 元のセグメントは、以下のすべての整数であることがわかっています。`l`に`r`包括的ですが、順序がバラバラです。 スクランブル後、すべての値は同じ隠された数値によって変換されます`x`XORを使用します。 

タスクは、この非表示マスクの有効な値を回復することです。`x`それは変化を説明できるかもしれません。 

プロセスについて考えるのに役立つ方法は、それぞれの最終値を次のように考えることです。`a[i]`未知の元の値に関連している`b[i]`範囲内で`[l, r]`方程式を通して`a[i] = b[i] XOR x`。 順列ステップでは、位置と元の値の間のペアが非表示になるだけで、値のセットは変更されません。 

この制約は、次のことを強く示唆しています。`O(n)`試験溶液ごとに意図されています。 すべてのテストにわたる要素の合計数は最大で`2^17`これは約 131k であるため、要素ごとに一定の作業を行うアプローチは安全です。 ネストされたループまたは全体にわたる候補ごとのブルート フォースを伴うもの`2^17`テストごとの可能性が遅すぎる可能性があります。 

同じ XOR 構造を共有しているが、複数の有効なマッピングに対応する値が配列に含まれている場合、微妙なエッジ ケースが発生します。 たとえば、次の場合`l = r`、配列には 1 つの要素と任意の要素があります。`x = a[0] XOR l`は有効ですが、一貫性のある再解釈では、その単一の値を再びマッピングする必要があります。`[l, r]`。 明示的に「順列の再構築」を試みる不用意なアプローチは、これを複雑にしすぎ、不一致の処理を危険にさらす可能性があります。 もう 1 つのエッジ ケースは、範囲が大きいが順列が同一である場合です。 その場合、XOR は単に XOR 空間内の均一なシフトであり、直接回復する必要があります。 

重要な問題は、順列ペアがわからないため、直接比較できないことです。`a[i] XOR x`と`i + l`位置的に。 

## アプローチ

 強引なアイデアは、考えられるすべての候補を試してみることです。`x`で`[0, 2^17)`。 各候補について、すべての要素を変換できます`a[i] XOR x`結果のマルチセットがセットと正確に一致するかどうかを確認します`{l, l+1, ..., r}`。 XOR は可逆的であり、置換は順序にのみ影響するため、これは正しいです。 

ただし、これには費用がかかります`O(2^17 * n)`最悪の場合、テストごとに約 1,700 万回の操作が必要となり、最大 10^5 のテストでは完全に実行不可能になります。 

重要な観察は、XOR がビット空間に対する全単射のように動作することです。 推測する代わりに`x`、既知のマッピングを 1 つ揃えることができます。 ある値を仮定すると`b`から`[l, r]`いくつかに対応する`a[i]`、 それから`x = a[i] XOR b`。 これなら`x`は正しいですが、1 つのペアだけでなく、すべての要素に対して機能する必要があります。 

したがって、単一のペアリングアンカーを選択します。 元の値のセットが正確にわかっているので、次の値を選択できます。`b = l`あらゆるものとペアリングしてみてください`a[i]`。 そのような試みのたびに候補者が生成されます`x`。 次に、これがどうかを確認します`x`配列全体を正確にセグメントに変換します`[l, r]`。 

これにより問題は次のように縮小されます`O(n^2)`これは素朴に行われた場合に限りますが、頻度チェックを使用するか、ブール配列によるハッシュを使用してメンバーシップを設定することで、それを回避します。 

値の範囲が狭いので(`< 2^17`)、ターゲット間隔の周波数配列を保存し、線形時間で検証できます。

 ## アルゴリズムのチュートリアル

 重要な考え方は、任意の 1 つの元の値を任意の 1 つの最終値と一致させると、正しい XOR マスクが完全に決定されるということです。 

1. 周波数配列を構築する`need`すべての整数をマークする`[l, r]`必要に応じて一度。 これは元のマルチセットを表します。 
2. 周波数配列を構築する`have`入力配列から`a`。 これは変換されたマルチセットです。 
3. 任意の要素を選択します`a[i]`および任意の元の値候補`b`で`[l, r]`一致する構造によって暗示されます。 便利な選択は、すべてを反復処理することです`a[i]`そしてセット`x = a[i] XOR l`。 

これは機能します。`l`いくつかに対応する`a[i]`、それからそれ`x`それが真の変革です。 
4. 各候補者について`x`、すべての要素を概念的に変換します`a[j] XOR x`それらの周波数が一致するかどうかを確認します`need`。 
5. 最初の有効な`x`が返されます。 

間違ったペアリングは 1 つの要素に一致する可能性があっても、他の部分では一貫性が損なわれる可能性があるため、検証手順は非常に重要です。 XOR により、すべての要素にわたる一貫性が確実に保たれます。`x`正しい場合、マルチセット全体を正確にマップする必要があります。 

### なぜ効果があるのか

 変換は、次の間の全単射を定義します。`[l, r]`そして最後の配列。 有効な解はすべて、すべての要素に適用されるグローバル XOR シフトに対応します。 正しいペアリングを 1 つ修正すれば`b -> a[i]`の場合、XOR 値は一意に決まります。 間違ったペアリングでは、XOR が単射的であるため、完全なマルチセット構造を保存できない異なる XOR シフトが生成されます。`x`値は元のセットの 2 つの異なる順列を生成しますが、観測された出力と一致するのは 1 つだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    MAXV = 1 << 17

    for _ in range(t):
        l, r = map(int, input().split())
        arr = list(map(int, input().split()))
        
        n = r - l + 1
        
        need = [0] * MAXV
        for v in range(l, r + 1):
            need[v] = 1
        
        have = [0] * MAXV
        for v in arr:
            have[v] += 1
        
        # try candidates by pairing a[i] with l
        x = arr[0] ^ l
        
        ok = True
        for v in range(l, r + 1):
            if have[v ^ x] != 1:
                ok = False
                break
        
        print(x if ok else 0)

if __name__ == "__main__":
    solve()
```この実装では、順列の再構築を試みるのではなく、直接の周波数比較が使用されます。 重要な単純化は、予想される元のセットを修正することです`[l, r]`そして、指定された配列を XOR 変換して正確に一致するかどうかをテストします。 

順序は無関係であるため、位置間の明示的な一致は避けます。 

実装の微妙な詳細は、固定サイズの周波数配列です。`2^17`、定期的なメンバーシップ チェックが保証されます。 これにより、合計入力サイズにわたってソリューションが線形に保たれます。

 ## 特殊なケース

 いつ`l == r`、配列には単一の要素が含まれます。 アルゴリズムは依然として選択します`x = a[0] XOR l`、唯一の値を正しくマップし直します。`l`。 他の解釈を行っても、順列には柔軟性がないため、一貫性チェックに失敗します。 

XOR の前に順列が同一である場合、配列は純粋な XOR シフト区間になります。 単一の要素から導出された候補は検証後に区間全体を一貫して整列させるため、アルゴリズムは引き続き機能します。
