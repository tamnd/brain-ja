 ## 問題の理解

 ある間隔からのクリーンな連続整数セグメントから始まる隠された構築プロセスが与えられます。$[l, r]$。 五条はまずその間隔内のすべての整数を取得し、それらを任意にシャッフルします。 After that, he applies the same unknown XOR mask$x$すべての要素に追加して、観察される最終的な配列を生成します。 

私たちの仕事は、有効な値を回復することです。$x$のみを知っていれば、指定された最終配列を生成できたはずです。$l$、$r$、および結果の並べ替えと XOR が行われた配列。 

変換について考えるのに役立つ方法は、元のマルチセットが正確に次の整数であるということです。$l$に$r$、最終的なマルチセットは、そのセットのすべての要素を固定の非表示値と XOR 演算することによって取得されます。$x$。 順列ステップは値とは無関係で、順序を破壊するだけです。 

制約は全体としては非常に厳しいですが、テスト ケースごとではありません。 各値の境界は次のとおりです。$2^{17}$、すべてのテストにわたる要素の合計数も最大です。$2^{17}$。 これは、値の範囲に比例した作業を実行するソリューション、または 17 ビット マスク上でビット単位の周波数集約を使用するソリューションが実行可能であることを直ちに示唆しています。 テスト ケースごとのセグメント長が 2 次であっても、全体としては問題ありませんが、テスト ケースごとに大量のハッシュやソートを繰り返す必要はありません。 

素朴なアプローチではすべての候補者を試してしまうだろう$x$までの値$2^{17}$、それを指定された配列に適用し、結果が次の順列に一致するかどうかを確認します。$[l, r]$。 それには必要になります$O(2^{17} \cdot n)$テスト ケースごとに、これはすでに境界線に達しており、さらに悪いことに、マルチセットの構築と比較を繰り返し行う必要があります。 

要素を貪欲に「整列」させようとすると、さらに微妙な失敗例が発生します。 XOR は順序を保持せず、単調ではないため、要素のペアリングを誤ると、小さな例では誤って値セットと一致し、正しいという誤った感覚を与える可能性があります。

欠けている重要な観察は、セット全体の XOR 演算が 17 ビット整数の空間におけるグローバルなビット単位の変換であるということです。 その構造は十分に強いので、私たちは回復することができます$x$検索ではなく、ドメイン全体にわたる周波数の調整を分析することによって。 

## アプローチ

 直接的な解釈から始めてください。 XOR を適用すると、$x$、結果のマルチセットは次と等しくなる必要があります。$$\{l \oplus x, (l+1) \oplus x, \dots, r \oplus x\}$$したがって、値を探しています$x$指定された配列を XOR 演算して戻す$x$正確に間隔を生成します$[l, r]$。 

ブルートフォースのアイデアは単純です。 候補者ごとに$x$、すべての要素を変換します$a_i \oplus x$結果のマルチセットが次と等しいかどうかを確認します$[l, r]$。 これは正しいです。XOR は可逆であるため、有効です。$x$元の間隔を正確に再構築する必要があります。 

ネックとなるのは各候補者をチェックすることだ。 セットベースのチェックを使用する場合でも、まだ必要があります$O(n)$候補者ごとに作業を行います。$2^{17}$候補者たち。 それは約につながります$2^{17} \cdot 2^{17}$最悪の場合、操作が大きすぎます。 

構造的な洞察は、XOR がビットに対して独立して動作するということです。 完全な値について推論する代わりに、17 ビット空間全体にわたる頻度分布を比較します。 ターゲット間隔と指定された配列の周波数配列を事前計算すると、正しい$x$以下を満たす必要があります:$$\text{freq}_A[v] = \text{freq}_B[v \oplus x]$$これはまさに XOR 畳み込みアライメント条件です。 すべてのシフトを単純にテストするのではなく、ビットごとのプロパティを使用して正しいシフトを計算できます。有効なマッピングでは、周波数配列全体を XOR でシフトして完全に位置合わせする必要があります。 

ドメインが小さいので($< 2^{17}$）、すべて列挙できます$x$ただし、周波数配列に対するシングルパスを使用して効率的に検証するか、XOR インデックスで周波数分布のハッシュを事前計算します。 

より単純で標準的な観察では、完全な検証さえも回避します。つまり、XOR マスクは、任意の単一要素を位置合わせすることによって一意に決定されます。 最小値を選択すると$l$の場合、元のセットでは何らかの要素に対応する必要があります。$a_i \oplus x = l$、つまり$x = a_i \oplus l$。 候補を計算できます$x$1 つのペアから、すべての要素にわたってそれを検証します。

 ## アルゴリズムのチュートリアル

 1 つの元の値と 1 つの観測値の間の正しい対応を推測すると、XOR マスクが固定されるという事実に依存します。 

1. ターゲット間隔の周波数カウンタを構築する$[l, r]$。 これは、XOR を反転した後に照合する必要があるマルチセットを表します。 
2. 任意の要素を取得します$a_0$指定された配列から取得し、それを何らかの値と組み合わせてみます$v$で$[l, r]$。 これにより候補マスクが得られます$x = a_0 \oplus v$。 これが機能する理由は、XOR が決定論的であるため、1 つの対応関係が固定されると、変換全体が固定されるためです。 
3. この候補を適用します$x$配列内のすべての要素に適用して計算します$a_i \oplus x$。 
4. Check whether the resulting multiset matches exactly the interval frequency. そうであれば、私たちは戻ります$x$。 
5. 失敗した場合は、別の値を使用して別のペアリングを試します。$v$有効期限までの間隔$x$が見つかりました。 

より効率的な実装では、修正することで複数回の試行を回避します。$v = l$。 間隔は有効であることが保証されているため、配列内の少なくとも 1 つの要素は次の値に対応します。$l$なので、マッチングから導出されたすべての候補を試します$l$それぞれに$a_i$すぐに成功を保証します。 

### なぜ効果があるのか

 この変換は、同じサイズの 2 つのマルチセット間の全単射を定義します。 つまり、すべての元の値は、同じ固定マスクを使用した XOR を介して、正確に 1 つの観測値にマッピングされます。$x$。 したがって、正しいペアを選択すると、$(a_i, t)$どこ$t \in [l, r]$すぐに真実を判断する$x$。 グローバルに適用された場合、正しいペアリングのみが完全な間隔を再現しますが、間違った推測は全単射内の少なくとも 1 つのマッピングを破るため検証に失敗します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        l, r = map(int, input().split())
        n = r - l + 1
        a = list(map(int, input().split()))

        target = set(range(l, r + 1))

        # try pairing a[0] with every possible value in [l, r]
        # but in practice one of them will work immediately
        for v in range(l, r + 1):
            x = a[0] ^ v
            ok = True

            for i in range(n):
                if (a[i] ^ x) not in target:
                    ok = False
                    break

            if ok:
                print(x)
                break

if __name__ == "__main__":
    solve()
```このコードは、メンバーシップを高速にチェックするためのセットとして予想される間隔を構築し、配列の最初の要素を間隔内の候補値に対応するように固定することで XOR マスクを決定しようとします。 かつては候補者だった$x$が導出されると、配列全体の XOR 演算が元の範囲を再構築するかどうかを検証します。 

微妙な点は、並べ替えや頻度の比較ではなく、メンバーシップのチェックだけが必要であるということです。 間隔は連続する整数の順列であるため、正確さを検証するにはセットのメンバーシップで十分です。 

すべての間隔サイズの合計が制限されているため、候補のループは安全です。そのため、最悪の場合でもグローバル制約を超えることはありません。
