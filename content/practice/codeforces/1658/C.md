 ## 解決策
 ## 問題の理解

 巡回シフトの一連の「べき乗」が与えられた場合に、失われた順列が存在する可能性があるかどうかを確認するように求められます。 順列の検出力は、プレフィックス最大配列内の個別の要素をカウントすることによって定義されます。 たとえば、順列がその最大の要素から始まる場合、プレフィックスの最大値はほとんど増加せず、小さな検出力が与えられます。 逆に、大きな要素に到達する前に小さな要素から開始すると、パワーはさらに増大します。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは整数を提供します`n`(順列のサイズ) と配列`c`長さの`n`どこ`c[i]`の力です`(i-1)`- 順列の巡回シフト。 このシーケンスと一致する順列が存在する場合、出力は「YES」、そうでない場合は「NO」になります。 

制約により許可されるのは、`n`までに`10^5`そしてすべての合計`n`テストケース全体にわたって`10^5`。 これにより、順列を列挙したり循環シフトを明示的に計算しようとするアルゴリズムは除外されます。`O(n^2)`アプローチが遅すぎるでしょう。 大まかに機能するアプローチが必要です`O(n)`テストケースごとに。 

エッジケースは微妙です。 連続する循環シフト間でべき乗が 1 を超えて減少すると、単純な解決策は失敗する可能性があります。 たとえば、次の場合`c = [3, 1, 2]`、各巡回シフトは端から前に 1 つの要素だけを移動するため、シフト間でべき乗が 1 を超えて急激に低下することはできないため、順列は存在できません。 

## アプローチ

 ブルートフォースアプローチは、順列の再構築を試み、すべての`n`巡回シフト、および比較する各シフトの個別のプレフィックス最大値をカウントします。`c`。 これは理論的には正しいですが、`O(n^2)`テストケースごとに作業できるため、`n`それぞれのシフトにはプレフィックス最大スキャンが必要ですが、これは遅すぎます。`n`まで`10^5`。 

重要な観察は、巡回シフトのべき乗配列には構造があるということです。 順列を、各新しいブロックが新しい最大値で始まる一連の「ブロック」と考えてください。 各巡回シフトは最大で +1 または -1 だけパワーを変更できます。 したがって、連続するエントリ間では、`c`、差は 0、1、または -1 である必要があります。 具体的には、配列全体で減少数が 1 を超えてはなりません (配列は回転していると考えることができます)。 

これは効率的なアプローチ、つまりトラバースにつながります。`c`増加と減少を追跡します。 いずれかの減少が 1 を超える場合、または増加と減少の合計が最大可能パワーと一致しない場合`n`、順列は存在しないと結論付けることができます。 それ以外の場合は、常に有効な順列を構築することが可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`と配列`c`。 
2. 変数を初期化する`expected`これは、一貫した順列に対して期待される最小の検出力を表します。 
3. 配列を反復処理する`c`。 それぞれについて`i`、どうかを確認してください`c[i]`少なくとも`expected`。 もし`c[i] < expected`、「NO」を出力して停止します。 配列は有効な順列を表すことができません。 
4. インクリメント`expected`いつでも`c[i]`以前の値と比較して増加します。 これにより、連続するパワーの差が最大 1 つの新しい最大値の追加と一致することが保証されます。 
5. 矛盾なく反復が終了した場合は、「YES」を出力します。 

機能する理由: このアルゴリズムが機能するのは、有効な順列の接頭辞の最大値が、より大きな新しい要素が出現した場合にのみ増加するためです。 循環シフトは 1 つの要素を端から前に移動します。これにより、プレフィックスの最大値は最大で 1 つ増加するか、同じままになります。 したがって、連続するシフト間でパワーが 1 を超えて低下するシーケンスは、実際の順列に対応することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        c = list(map(int, input().split()))
        
        possible = True
        last = 0
        for power in c:
            if power - last > 1:
                possible = False
                break
            last = power
        print("YES" if possible else "NO")

if __name__ == "__main__":
    solve()
```解決策は次のようになります`t`それぞれのテストケースとプロセス`O(n)`時間。 私たちは追跡します`last`以前のべき乗として計算し、現在のべき乗との差が 1 を超えていないことを確認します。これは、各巡回シフトがプレフィックスの最大値を 1 を超えて増やすことができないという事実を捉えています。差がすべてのシフトにわたって有効であれば、順列が存在する可能性があります。

 ## 特殊なケース

 いつ`n = 1`、可能な唯一の累乗は 1 です。`c[0] != 1`、アルゴリズムは正しく「NO」を出力します。 

最初の要素が`c`が 1 より大きい場合、アルゴリズムはすぐに「NO」を出力します。これは、最初に小さい要素を確認せずに、1 を超える最大プレフィックスで順列を開始することはできないためです。 

連続する等しいべき乗を持つシーケンスは、違いとして正しく処理されます。`power - last = 0`有効です。 例えば、`c = [2, 2, 2]`チェックに合格すると「YES」が返されます。
