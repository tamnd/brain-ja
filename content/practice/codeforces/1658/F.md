 ## 問題の理解

 バイナリ文字列が与えられ、その中で全長が指定された数値である重複しないセグメントを選択したいとします。$m$、これらのセグメントの連結が元の文字列と同じ比率の 1 を持つようにします。 つまり、元の文字列が$x$のうちのもの$n$キャラクターを組み合わせた場合、選択したセグメントの組み合わせにも、$x/m$。 課題はセグメントの数を最小限に抑えることです。$k$、これを満たすために必要です。 

入力制約により、次のことが可能になります。$n$までに$2 \cdot 10^5$、まであるかもしれません$10^4$テスト ケース、すべての合計の合計$n$テストケース全体にわたって$2 \cdot 10^5$。 これは、余裕がないことを意味します$O(n^2)$テストケースごとの操作。 線形または線形に近い解は許容されます。 

エッジケースが発生するのは次の場合です$m$に等しい$n$、 いつ$m$すべての文字が 0 または 1 の場合、または元の文字列内の 1 の割合が整数の 1 を許可しない場合、は 1 になります。$m$文字。 たとえば、次のように考えてみましょう$s = 0101$そして$m = 3$。 可愛らしさは、$0.5$, ただし、3 文字を選択すると 1 つまたは 2 つしか得られません。 長さ 3 で正確に 3/6 = 0.5 を生み出す組み合わせはないため、答えは -1 になります。 任意の部分文字列長が機能することを前提とした単純な実装は、ここでは失敗します。 

## アプローチ

 ブルート フォース アプローチでは、全長が$m$それらの連結が同じ可愛さを持つかどうかを確認してください。 これは明らかに実行不可能です。 すべての長さの部分配列を試しても$m$そして可愛さのチェックは$O(n \cdot m)$テストケースごとに、到達可能$4 \cdot 10^{10}$最悪の場合の運用。 

重要な洞察は、連結されたセグメントで必要な 1 の合計数に焦点を当てることです。 させて$ones$文字列内の 1 の合計数であり、$total$長さになります。 連結されたセグメントには正確に含まれている必要があります$required_ones = ones \cdot m / n$もの。 これが整数でない場合、解は存在しません。 1 の目標数がわかったら、達成するために連続する 1 と 0 のセグメントを貪欲に選択できます。$required_ones$全長あり$m$。 文字列を左から右にスキャンし、目標の比率を維持しながら 1 と 0 を蓄積することで、セグメントを段階的に構築できます。 

このアプローチが機能するのは、問題が全長にわたる 1 の個別の割り当てに帰着するためです。$m$。 セグメントの数を最小限に抑えることは、可能な限り連続した要素を結合することに相当します。

 ## アルゴリズムのチュートリアル

 1. 1 の合計数を計算します。$total_ones$、文字列内$s$。 コンピューティング$required_ones = total_ones * m / n$。 これが整数でない場合は、同じかわいらしさを実現できる選択がないため、すぐに -1 を出力します。 
2. 結果のセグメントの空のリストを初期化します。 2 つのポインターを保持します。1 つは現在のセグメントの開始用で、もう 1 つは文字列のスキャン用です。 また、まだ必要な文字の数と、選択する文字が何文字残っているかを示すカウンターも維持します。 
3. 文字列を左から右にスキャンします。 必要な残りの文字数が残りの文字数と等しい場合、残りのセグメントはすべての文字を取得する必要があります。 それ以外の場合は、現在のセグメントを次のいずれかの長さになるまで貪欲に拡張します。$m$に達するか、要件が満たされます。 
4. セグメントが、さらに多くの文字を使用すると要件または長さを超えるポイントに達したとき$m$、開始と終了を記録してセグメントを閉じ、残りのセグメントと長さを更新して、新しいセグメントを開始します。 
5. スキャンが終了したら、すべてのセグメントの長さの合計が次と等しいことを確認します。$m$そして 1 の合計は等しい$required_ones$。 セグメント数を出力$k$そしてのリスト$(l_i, r_i)$ペア。 

機能する理由: 各ステップでは、選択したセグメントの連結が必要なセグメントと長さをまだ超えていないという不変条件が維持されます。 これらの制限を尊重しながらセグメントを貪欲に拡張することで、最小限の数の連続セグメントを構築します。 別のキャラクターを追加すると、かわいらしさの要件に違反する場合、閉じることができる最初のセグメントが正確に閉じられます。 これにより最小限のことが保証されます$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        s = input().strip()
        total_ones = s.count('1')
        
        if total_ones * m % n != 0:
            print(-1)
            continue
        target_ones = total_ones * m // n
        
        if target_ones == 0:
            print(1)
            print(1, m)
            continue
        if target_ones == m:
            print(1)
            for i, c in enumerate(s):
                if c == '1':
                    print(i + 1, i + 1)
                    break
            continue
        
        segments = []
        start = 0
        ones_needed = target_ones
        length_needed = m
        
        for i, c in enumerate(s):
            if length_needed == 0:
                break
            if ones_needed == 0:
                take = min(length_needed, i - start + 1)
                segments.append((start + 1, start + take))
                length_needed -= take
                start += take
                continue
            if c == '1' and ones_needed > 0:
                segments.append((i + 1, i + 1))
                ones_needed -= 1
                length_needed -= 1
                start = i + 1
            elif c == '0':
                segments.append((i + 1, i + 1))
                length_needed -= 1
                start = i + 1
        
        if length_needed != 0 or ones_needed != 0:
            print(-1)
        else:
            print(len(segments))
            for l, r in segments:
                print(l, r)

if __name__ == "__main__":
    solve()
