 ## 解決策
 ## 問題の理解

 私たちは数種類のケーキを製造できるパン屋を与えられました。 各ケーキのレシピはある程度の材料を消費し、再利用可能なツールのセットが必要です。 すべての材料とすべての道具にはコストがあり、ケーキにも販売価格があります。 

重要な決定は、各レシピを最大 1 回使用できるという制限の下で、ケーキのどのサブセットを焼くかです。 ケーキを選択した場合、必要なすべての材料と必要な道具の代金を支払わなければならず、それから販売価格を得ることができます。 ツールは消費されませんが、選択したケーキに必要な場合は購入する必要があるため、ツールの費用は最大でも世界で 1 回支払われますが、材料はケーキごとに支払われます。 

目標は、選択したケーキからの総収益から、使用したすべての材料と購入したすべてのツールのコストを差し引いた総利益を最大化することです。 

入力には、材料のコスト、ツールのコスト、ケーキごとに、必要な各材料のユニット数と必要なツールが記述されます。 出力は単一の数値、つまり達成可能な最高の利益です。 

制約は、最大数百のケーキ、材料、ツールを示します。 ケーキのすべてのサブセットに対する単純な列挙は、すでに最大 2^200 の可能性を暗示していますが、これは完全に実行不可能です。 どのような解決策でも、ケーキの数への指数関数的な依存を回避する必要があります。 

モデリングの微妙な点は、ツールのコストがケーキ間で共有されるため、意思決定間の結合が生じることです。 少なくとも 1 つの選択されたケーキでツールが使用された場合、そのコストは 1 回だけ支払われます。 これにより、ケーキ間の独立性が失われ、問題が自明ではなくなります。 

エッジケースは、ケーキが個別に利益を上げているが、共有ツールのコストにより利益がなくなった場合、またはツールが高価であるが必要なのは 1 回だけであり、その償却コストが重要になる場合に発生します。 たとえば、2 つのケーキにはそれぞれ非常に高価なツールが必要になる場合があります。 ケーキを 1 つだけ使用すると、ツールのコストを全額支払うことになりますが、両方を使用してもツールのコストはさらに増加し​​ないため、ケーキごとの評価と比較して最適な選択が逆転する可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、ケーキのすべてのサブセットが考慮されます。 各サブセットについて、ケーキごとの寄与を合計することで材料の合計コストを計算し、必要なツールの和集合をとることでツールのコストを計算します。 これは利益の定義を直接評価するものであるため、これは正しいです。 

ただし、これには 2^C のサブセットを反復する必要があります。 各サブセットのコストの計算が O(G + T) に最適化されたとしても、全体の複雑さは O(2^C (G + T)) となり、C が約 200 の場合、これは実現可能な限界をはるかに超えます。 

より迅速な解決を可能にする構造は、材料とツールを分離することで生まれます。 材料コストはケーキごとに加算されるため、直線的かつ独立して寄与します。 ツールのコストは、選択された少なくとも 1 つのケーキがそれらを使用するかどうかによってのみ決まります。つまり、ツールはセット カバレッジのように動作します。各ツールは、少なくとも 1 回選択されると固定ペナルティを与えます。 

これにより、問題は、各ケーキが線形利益に貢献するケーキの選択に変わりますが、ツールをアクティブ化すると追加のペナルティが発生します。 重要なアイデアは視点を変えることです。ケーキごとに考えるのではなく、ツールのサブセットごとに考えます。 T も最大 200 であるため、ツールの使用状況を状態として扱い、ツール マスク上の DP またはツール サブセット上のナップザックのような集計を使用してケーキの寄与を組み合わせることができます。 材料はケーキごとに事前に計算でき、難しい部分はツールの相互作用のみになります。 

ツールを無視してケーキごとにその本質的価値を計算し、ツールのサブセット DP を介してツールのコストを処理します。ツールのサブセットごとに、ツール要件がそのサブセットに含まれるケーキによって達成可能な最高の利益を集計します。 これにより結合が軽減され、2^C ではなく 2^T 状態にわたる動的プログラミングが可能になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ケーキのサブセットに対するブルートフォース | O(2^C (G + T)) | O(1) または O(C) | 遅すぎる |
 | ツールサブセット上の DP | O(2^T * C) | O(2^T) | 承認済み |

 ## アルゴリズムのチュートリアル

 ## 最適なアルゴリズム

 1. 各ケーキについて、必要な数量と材料価格を掛け合わせて材料コストを計算します。 これを販売価格から差し引くと、ツールを無視した基本利益が得られます。 これにより追加的な寄与が分離されるため、ツールが唯一の結合要素になります。 
2. 各ケーキについて、そのツール要件を T ツール上のビットマスクとして表します。 これによりツール セットがコンパクトな整数に変換され、サブセット操作をビット単位のロジックで実行できるようになります。 
3. すべてのツール マスクに対して配列 dp を構築します。dp[0] = 0 を除き、負の無限大に初期化されます。各状態は、必要なツールがそのマスクで正確にカバーされている選択されたケーキのコレクションを使用して達成可能な最高の利益を表します。 
4. ケーキごとに、すべてのマスクに対して降順でナップザックのような更新を実行します。 このケーキを取り上げると、現在のマスク m から m OR マスク[ケーキ] に移行し、基本利益を追加します。 これは、これまでに必要なすべてのツールに加えて、このケーキのツールをアクティブ化するモデルです。 
5. すべてのケーキを処理した後、ツールコストを適用します。 各マスクについて、マスクに含まれるツールの合計コストを差し引きます。 これは、標準サブセット DP を使用してサブセットにわたるツール コストの合計を事前計算することによって行われます。 
6. 答えは、ツールコストを適用した後のすべてのマスクの最大値です。 

各ケーキが最大 1 回使用されるように、降順の更新が必要です。 昇順に更新すると、同じケーキが中間状態まで複数回カウントされる可能性があります。 

### なぜ効果があるのか

 DP の不変条件は、最初の k 個のケーキを処理した後、dp[m] が、ツールの結合が正確に m である k 個のケーキのサブセットを使用して、達成可能な最大の基本利益を格納することです。 すべての遷移は現在のケーキを除外または含めます。これを含めると、ビットごとの OR を介してツール要件が正しくマージされます。 各ケーキは 1 回だけ考慮されるため、どの州にもそれを複数回含めることはできません。 ツール コストの最終的な減算により、各ツールはマスクごとに 1 回正確に課金され、元のコスト定義と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    G, C, T = map(int, input().split())
    c = list(map(int, input().split()))
    g = list(map(int, input().split()))
    t = list(map(int, input().split()))

    # ingredient matrix
    A = [list(map(int, input().split())) for _ in range(C)]

    tool_mask = [0] * C
    tool_list = []
    for i in range(C):
        parts = list(map(int, input().split()))
        k = parts[0]
        mask = 0
        for x in parts[1:]:
            mask |= 1 << (x - 1)
        tool_mask[i] = mask

    # base profit per cake (ignore tools for now)
    base = [0] * C
    for i in range(C):
        cost = 0
        for j in range(G):
            cost += A[i][j] * g[j]
        base[i] = c[i] - cost

    # dp over tool masks
    N = 1 << T
    dp = [-10**30] * N
    dp[0] = 0

    for i in range(C):
        m = tool_mask[i]
        val = base[i]
        if val <= 0 and m == 0:
            continue
        for mask in range(N - 1, -1, -1):
            if dp[mask] < -10**20:
                continue
            nm = mask | m
            dp[nm] = max(dp[nm], dp[mask] + val)

    # compute tool cost per mask
    cost_mask = [0] * N
    for i in range(T):
        bit = 1 << i
        for mask in range(N):
            if mask & bit:
                cost_mask[mask] += t[i]

    ans = 0
    for mask in range(N):
        ans = max(ans, dp[mask] - cost_mask[mask])

    print(ans)

if __name__ == "__main__":
    main()
```材料コストの計算はケーキごとに 1 回行われるため、線形な前処理が保証されます。 DP ループはマスクに対して慎重に逆方向に反復されるため、各ケーキは最大 1 回だけ寄与します。 ビットマスク構造はツール セットをエンコードするため、和集合演算は OR 演算になります。 

微妙な点は、dp[0] を除き、dp をゼロではなく大きな負の値で初期化することです。これは、到達不能な状態が遷移に寄与してはならないためです。 もう 1 つの重要な詳細は、マイナスの基本利益を正しく処理することです。マイナスの寄与を持つケーキでも、複数の収益性の高いケーキ間で高価なツールを共有できる場合には役立ちます。 

## 実用的な例

 ### 例 1

 2 つのケーキと 2 つのツールを使用した単純化されたケースを考えてみましょう。 

Cake 1 の基本利益は 10 で、ツール A を使用します。 

Cake 2 の基本利益は 8 で、ツール A と B を使用します。 

工具のコストは各5です。 

dp の状態を追跡します。 

| ステップ | ケーキ | マスク前 | 移行 | 後のマスク | dp値 |
 | --- | --- | --- | --- | --- | --- |
 | 初期化 | - | 00 | - | 00 | 0 |
 | 1 | ケーキ1 | 00 | 00 → 01 (+10) | 01 | 10 |
 | 1 | ケーキ1 | 01 | 01 → 01 (+10) スキップ | 01 | 10 |
 | 2 | ケーキ2 | 00 | 00 → 11 (+8) | 11 | 8 |
 | 2 | ケーキ2 | 01 | 01 → 11 (+18) | 11 | 18 |

 DP の後、マスクあたりのツール コストを差し引きます。 

マスク 01 コスト = 5、値 = 10 − 5 = 5

 マスク 11 コスト = 10、値 = 18 − 10 = 8

 ベストは8です。 

このトレースは、共有ツール A が最適な選択をどのように変更するかを示しています。ケーキを組み合わせることで、ツールのコストを集計した後の利益が向上します。

ケーキ1は利益3、ケーキ2は利益4。 

| ステップ | ケーキ | マスク | DP |

## 複雑さの分析

 ## 特殊なケース

 重要なエッジケースは、ケーキの収益はプラスだが、ツールが非常に高価である場合です。 DP は、同じツール セット内で複数のケーキを組み合わせるのに役立つ場合を除き、その選択を正しく回避します。 たとえば、ケーキ A だけでコスト 100 の工具が必要で、利益が 10 である場合、dp[mask] は減算前は正ですが、工具コストの減算後は負になり、選択されないことが保証されます。 

もう 1 つのエッジ ケースは、複数のケーキが同じツール セットを共有する場合です。 DP は基本利益を同じマスクに集計し、ツールのコストを 1 回差し引いた後、ケーキが使用するケーキの数に関係なく、ツールが 1 回だけ支払われることを正しく反映します。 

3 番目のケースは、ケーキに道具がない場合です。 そのマスクはゼロであるため、常に dp[0] に直接寄与し、ツールのコストには影響せず、問題の定義と正確に一致します。
