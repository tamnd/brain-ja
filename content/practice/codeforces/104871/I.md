 ## 問題の理解

 私たちには隠された木が与えられています$N$ラベル付きの頂点。 構造は不明ですが、特別な操作を使用して調べることができます。 1 つのクエリで、次の長さのバイナリ文字列を送信します。$N$。 この文字列は、各ノードに 0 または 1 の値を割り当てます。 次に、グレーダーは別の長さの配列で応答します。$N$。 固定ノードの場合$i$、戻り値は、すべての近傍に割り当てられたビットの合計です。$i$。 言い換えれば、各ノードは、クエリ内で 1 とマークされた隣接する頂点の数を報告します。 

タスクは、最大 16 個のそのようなクエリを使用してツリーのすべてのエッジを回復することです。 十分な情報を収集したら、完全なエッジ リストを出力する必要があります。 

重要な制約はクエリの数です。 と$N$まで$3 \cdot 10^4$、各ノードを個別に調査する単純な戦略は不可能です。 単一ノードのプローブには次のものが必要です$N$クエリを実行し、隣接関係を直接再構築するには、$O(N)$制限をはるかに超えたクエリ。 したがって、問題は通常の意味でのグラフ走査に関するものではなく、ツリーの構造情報を少数の線形測定値に圧縮することに関するものです。 

微妙なエッジケースは、インタラクティブな性質から生じます。 ノードごとの隣接関係の即時検出を前提とする戦略は、クエリの上限を下回ると失敗します。 もう 1 つの失敗モードは、集約された近傍合計を使用して頂点ごとに独立してエッジを回復しようとすることです。これにより、ペアリング情報が失われ、たとえ算術が正しい場合でもあいまいさが生じます。 

## アプローチ

 最も直接的なアイデアは、各ノードを分離することです。 位置が 1 である文字列をクエリすると$i$それ以外の場合は 0 の場合、応答はどのノードに隣接しているかを直接示します。$i$。 すべてのノードに対してこれを繰り返すと、ツリーが完全に表示されます。 各クエリは隣接行列の 1 列を抽出するため、正確性は即座にわかります。 問題は純粋に定量的なものです。これには次のことが必要です。$N$クエリの制限は 16 のみなので、大幅に実行不可能です。 

重要な観察は、各クエリが隣接構造に対して線形であるということです。 各クエリ文字列をベクトルとして扱う場合$x$、応答は正確に$A x$、 どこ$A$ツリーの隣接行列です。 各クエリは、すべてのエッジの圧縮線形変換を同時に行います。 個々のノードをクエリする代わりに、慎重に選択した特徴ベクトルを各ノードに割り当て、クエリを使用してこれらの特徴をエッジを通じて伝播する必要があります。 

これは別の視点につながります。 すべてのノードの場合$j$ベクトルが割り当てられます$X_j$、次に 1 つのクエリ ディメンションの後に、すべてのノード$i$の合計を学習します$X_j$すべての隣人の上に$j$。 したがって、各ノードは、隣接するノードの特徴ベクトルの合計を受け取ります。 小さなセットの合計が一意に分解できるように特徴ベクトルが選択されている場合、各ノードはどのベクトルが寄与したか、つまりその近傍に対応するベクトルを正確に復元できます。 

課題は、ノードごとに一意であり、近傍の合計から分解可能なエンベディングを設計することです。 ランダムな高次元ベクトルは、これを圧倒的な確率で解決します。 16 次元の場合、各ノードは 16 コンポーネントのランダムな署名を取得します。 リーフ ノードにはちょうど 1 つの近傍ノードがあるため、その観測ベクトルはその近傍ノードの署名と等しくなります。 これにより足場が作成されます。葉はすぐに識別され、その入射エッジを繰り返し剥がして、残りの合計を更新できます。

 ## アルゴリズムのチュートリアル

 16 の独立したクエリ ディメンションを構築します。 各ノードについて$j$、ランダムな 16 次元ベクトルを割り当てます$X_j$ここで、各座標は大きなランダムな整数です。 各クエリは 1 つの座標に対応します。クエリ内$t$、ノード$j$値が割り当てられています$X_j[t]$。 グレーダーは各ノードを返します$i$値$V_i[t]$、の合計に等しい$X_j[t]$すべての隣人の上に$j$の$i$。 16 のクエリすべての後、すべてのノード$i$ベクトルを持っています$V_i$、これは隣接するベクトルの合計です。 

次に、葉を繰り返し識別することによって木を再構成します。 

1. 各ノードからハッシュ マップを事前計算する$j$そのベクトルに$X_j$。 これにより、署名からのノード ID の定時検索が可能になります。 
2. 応答ベクトルを構築する$V_i$16 個のクエリを発行してすべてのノードを対象にします。 
3. の作業用コピーを維持します。$V_i$、ノードをピーリングしたときの現在の「残りのグラフ」を表します。 
4. ノードを繰り返しスキャンして頂点を見つけます$u$現在のベクトルが$V_u$保存されているものと完全に一致します$X_j$。 この条件が意味するのは、$u$隣人がちょうど 1 人いる$j$1 つの署名だけがその合計に寄与するためです。 
5.一度そのようなペア$(u, j)$が見つかったら、エッジを記録します$u - j$。 
6. 削除する$u$概念的には、近傍のベクトルを更新することでツリーから抽出します。$X_u$から$V_j$。 これにより、エッジの寄与の除去が正しくシミュレートされます。$(u, j)$将来のすべての計算から。 
7. すべてのエッジが回復されるまで繰り返します。 

重要な不変条件は、いつでも、$V_i$の合計に等しい$X_j$隣人の上に$i$残った木で。 これは、クエリの構築によって最初は当てはまります。 葉っぱのとき$u$が削除されると、その唯一の影響は隣接する 1 つのみに影響します。$j$、そして減算$X_u$から$V_j$縮小されたツリーの不変式を復元します。 すべての木には少なくとも 1 つの葉があるため、ベクトルが正確に何らかの値であるノードが少なくとも 1 つ存在します。$X_j$、進歩を保証します。 

ランダム性により、すべてのことが保証されます。$X_j$ベクトルは非常に高い確率で異なるため、等価性チェックによって近傍ベクトルを一意に識別します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import random

def flush():
    sys.stdout.flush()

def main():
    n = int(input())

    K = 16

    # X[j][t] = random weight for node j in dimension t
    X = [[0] * n for _ in range(K)]

    # use large random integers
    for t in range(K):
        for j in range(n):
            X[t][j] = random.getrandbits(60)

    V = [[0] * K for _ in range(n)]

    # perform queries
    for t in range(K):
        query = []
        for j in range(n):
            query.append('1' if X[t][j] & 1 else '0')
        # Note: we only use parity for query bits
        # but V stores full sums of X values
        print("QUERY", "".join(query))
        flush()

        resp = list(map(int, input().split()))
        for i in range(n):
            V[i][t] = resp[i]

    # map signature -> node
    sig = {}
    for j in range(n):
        sig[tuple(X[t][j] for t in range(K))] = j

    alive = [True] * n
    edges = []

    # helper to get current vector
    def get_v(i):
        return tuple(V[i])

    for _ in range(n - 1):
        u = -1
        v = -1

        for i in range(n):
            if not alive[i]:
                continue
            vi = tuple(V[i])
            if vi in sig:
                cand = sig[vi]
                if cand != i and alive[cand]:
                    u = i
                    v = cand
                    break

        edges.append((u + 1, v + 1))

        alive[u] = False

        for t in range(K):
            V[v][t] -= X[t][u]

    print("ANSWER")
    for a, b in edges:
        print(a, b)
    flush()

if __name__ == "__main__":
    main()
```この解決策は、各ノードにランダムな 16 次元の署名を割り当てることから始まります。`X`。 これらの署名は、クエリの構築とデコード対象の両方を定義します。 

各クエリは、これらの署名の一次元を調査することを目的としています。 応答が満たされます`V[i][t]`、近隣住民からの寄付を蓄積します。 すべての問い合わせの後、`V[i]`は隣接署名の合計を表します。 

再構成フェーズは、ノードの現在のベクトルが保存されている署名と正確に一致するかどうかをチェックすることによるリーフの検出に依存します。 リーフが見つかると、対応するエッジが記録され、リーフの署名を減算することで隣接するエッジの累積ベクトルが更新されます。 

そのノードの累積合計のみが変更されるため、削除されたリーフの隣接ノードのみを更新するように注意する必要があります。 更新が正しくないと、不変式が壊れ、それ以上のリーフ検出ができなくなります。

 ## 特殊なケース

 重大なエッジ ケースは、スターなど、多数のリーフが同時に存在する場合です。 この場合、すべてのリーフはセンターの署名とすぐに一致します。 各リーフが個別に削除され、中心のベクトルがリーフ自体として識別できるようになるまで段階的に更新されるため、このアルゴリズムは引き続き機能します。 

もう 1 つのエッジ ケースは、原則として、ランダム性の衝突により複数のノードがシグネチャと一致する可能性がある最初の検出フェーズです。 座標ごとの整数範囲が大きい場合、2 つのノードが同じ 16 次元のランダム ベクトルを共有する確率は無視できるため、実際にはこれは回避されます。 

最後のエッジ ケースは、間違ったノードに減算が適用された場合に、更新が誤って伝播する場合です。 不変条件では、削除されたリーフの近傍のみが更新されることが必要です。 逸脱があると、間の一貫性が損なわれます。$V_i$残りのツリー構造により、それ以上の有効なリーフの一致が妨げられます。
