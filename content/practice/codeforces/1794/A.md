 ## 解決策
 ## 問題の理解

 隠し文字列が与えられます$s$長さの$n$。 見る代わりに$s$直接、空ではないすべてのプレフィックスで構成される文字列のマルチセットが表示されます。$s$および空でないすべての接尾辞$s$を除く$s$自体。 これら$2n-2$文字列はシャッフルされるため、その順序には情報が含まれません。 

このコレクションだけから、元の文字列が$s$回文です。 

重要な観察は、データがすべての長さ-1 から長さ-までを完全に決定するということです。$n-1$プレフィックスとサフィックスですが、どの文字列がプレフィックスでどれがサフィックスであるかは明示的には示されません。 特に、マルチセット内の最長の文字列は常に次の長さになります。$n-1$、それらが再構築できる唯一の候補です$s$。 

制約は小さいです。$n \le 20$最大 120 のテスト ケース。 これは偶数を意味します$O(n^2)$あるいは、候補に対する乱暴な列挙は、パフォーマンスの観点からは些細なことです。 本当の難しさは効率ではなく、正しい構造を再構築することです。$s$順序付けされていないフラグメントから。 

プレフィックスとサフィックスのセットが重なり合う場合、特に次の場合に、微妙なエッジ ケースが発生します。$s$「aaa」や「abab」のような繰り返し構造があります。 このような場合、複数の再構成候補が$s$マルチセットと一致しているように見えますが、有効なのは 1 つだけです。 最初の 2 つの最も長い文字列が一意に決定されると想定する不用意なアプローチ$s$両方が異なる方向の有効なプレフィックスである場合、一貫性をチェックしないと失敗する可能性があります。 

たとえば、2 つの最長の文字列が同一である場合、その文字列がどちらの方向のプレフィックスであるかサフィックスであるかという、考えられる両方の解釈を慎重にテストする必要があります。 両方の方向を考慮しないと、回文性について誤った結論が得られる可能性があります。 

## アプローチ

 ブルートフォース解釈では、元の文字列を再構築しようとします。$s$どの文字列が長さのプレフィックスであるかについて可能なすべての割り当てを試みることにより、$n-1$。 候補プレフィックスを選択したら、それを可能な長さのそれぞれのサフィックスと組み合わせることにより、候補の完全な文字列を再構築できます。$n-1$、マルチセットに対して一貫性をチェックします。 次に、再構成候補ごとに、それが回文であるかどうかをテストします。 

せいぜいあるので$2n-2 \le 38$文字列と長さの明確な候補が少数のみ$n-1$、この強引なアプローチは実際にはすでに小規模です。 ただし、重要な非効率性は概念的なものです。プレフィックスとサフィックスの構造によってすでに文字列のほぼすべてが強制されている場合、再構成は組み合わせ代入問題として扱われます。 

重要な洞察は、その答えは実際には完全な再構築を必要としないということです。$s$。 マルチセットには常に 2 つの長さの文字列が含まれます。$n-1$。 そのうちの 1 つはプレフィックスです$s[0:n-1]$、もう一方は接尾辞です$s[1:n]$。 これら 2 つの文字列は正確に重なる必要があります$n-2$文字が有効な文字列からのものである場合。 この重複条件により、正確に 2 つの候補となる完全な文字列が決定され、有効な再構成が回文であるかどうかを確認するだけで済みます。 

可能な両方の方法で 2 つの候補を整列させ、一方をプレフィックスとして、もう一方をサフィックスとして処理して、完全な文字列を構築します。 いずれかの再構成がマルチセット構造と一致する場合、次のように導き出されます。$s$前方と後方で同じように読み取れるかどうかを確認します。 

これにより、問題は一定数の文字列構築と回文チェックに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース再構築 |$O(n^2 \cdot n!)$(概念的に) |$O(n)$| 遅すぎる/不必要 |
 | 最適なオーバーラップチェック |$O(n^2)$テストケースごと |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 一定の長さの文字列をすべて区切る$n-1$。 このような文字列は常に 2 つだけ存在します。 これらは、元の文字列の末尾を形成できる唯一の候補です。 
2. 2 人の候補者を呼び出し、電話します。$A$そして$B$。 それぞれは、次の接頭辞または接尾辞のいずれかを表します。$s$, しかし、どれがどれなのかは分かりません。 
3. 再構築の試み$s$仮定することで$A$はプレフィックスであり、$B$は接尾辞です。 これが有効な場合、最初の$n-1$文字は一致する必要があります$A$、そして最後$n-1$文字は一致する必要があります$B$。 これにより、候補全文字列が一意に決定されます。 
4. 交換された役割で同じ再構築を実行します。$B$プレフィックスとして、そして$A$接尾語として。 これにより、2 番目の候補文字列が生成されます。 
5. 一貫性のある各候補文字列について、それが回文であるかどうかを確認します。 少なくとも 1 つの有効な再構成が回文である場合、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

なぜそれが機能するのかは、プレフィックスとサフィックスの構造の厳格さからわかります。 2つの長さになったら$n-1$文字列は固定されているため、文字列間の重複部分は中央に 1 文字だけ定義する必要があります (または、すべての位置にわたる一貫性を確認する必要があります)。 有効な元の文字列はこれら 2 つのフラグメントを正確に誘導する必要があり、他の自由度は残されていません。 したがって、すべての有効な再構成は、2 つの最も長い文字列の役割を交換することによって形成された 2 つの候補の中にあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_pal(s):
    return s == s[::-1]

t = int(input())
for _ in range(t):
    n = int(input())
    arr = input().split()
    
    # collect candidates of length n-1
    cand = [x for x in arr if len(x) == n - 1]
    a, b = cand[0], cand[1]
    
    candidates = []
    
    # try a as prefix, b as suffix
    s1 = a + b[-1]
    candidates.append(s1)
    
    # try b as prefix, a as suffix
    s2 = b + a[-1]
    candidates.append(s2)
    
    ok = False
    for s in candidates:
        if is_pal(s):
            ok = True
            break
    
    print("YES" if ok else "NO")
```この解決策では、まず構造的に重要な文字列 (長さの文字列) だけを分離します。$n-1$。 短いプレフィックスとサフィックスはこれらの最長のものによって完全に暗示されるため、他のすべては再構築には冗長です。 次に、どの候補が最後の文字に含まれるかを交換することによって、2 つだけのもっともらしい完全な文字列を構築します。 

The palindrome check is straightforward since$n \le 20$、逆比較が簡単になります。 

実装の微妙な点は、マルチセットの完全な一貫性を明示的に検証しようとしていないことです。 この問題では、入力が常に何らかの有効な文字列に対応することが保証されるため、唯一の曖昧さは向きにあり、再構築の有効性には影響しません。 

## 実用的な例

 ### 例 1

 入力:```
n = 4
bcd cd a d abc ab
```長さ 3 の文字列を抽出します。`abc`、`bcd`。 

| ステップ | あ | B | 候補文字列 | 回文 |
 | --- | --- | --- | --- | --- |
 | プレフィックスとしての A | ABC | BCD | ABCD | いいえ |
 | プレフィックスとして B | BCD | ABC | BCDA | いいえ |

 可能な再構成は 2 つだけです。 どちらも回文ではないため、出力は NO になります。 

これにより、決定は中間構造ではなく、エンドポイントのアライメントのみに依存することが確認されます。 

### 例 2

 入力:```
n = 3
i io i oi
```長さ 2 の文字列は、`io`そして`oi`。 

| ステップ | あ | B | 候補文字列 | 回文 |
 | --- | --- | --- | --- | --- |
 | 接頭辞 | イオ | オイ | いいおい | はい |
 | B 接頭語 | オイ | イオ | オイオ | はい |

 少なくとも 1 つの再構成は回文であるため、出力は YES になります。 

これは、両方の再構成が有効な文字列である場合でも、答えは有効な再構成が対称性を満たすかどうかのみに依存することを示しています。

 ## 特殊なケース

 同じ文字の複数のコピーなど、すべての文字列が同一である場合、両方の再構成候補は同じ文字列に折りたたまれます。 たとえば、次の場合$n=3$すべての文字列が「a」である場合、長さ 2 の 2 つの候補は両方とも「aa」です。 このアルゴリズムは、有効な再構成「aaa」を 1 つだけ形成し、それを回文として正確に識別します。 

「ab」と「ba」のように、2 つの最長の文字列が互いに逆の場合、どちらの方向でも有効な完全な文字列が生成されますが、回文と一致するのは 1 つだけです。 このアルゴリズムは両方の再構成を明示的にチェックし、入力マルチセット内の順序に関係なく正確さを保証します。
