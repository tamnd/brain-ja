 ## 解決策
 ## 問題の理解

 ネットワークはルーティング ステーションのツリーであるため、任意の 2 つのステーション間には単純なパスが 1 つだけ存在します。 荷物は、出発地から目的地に移動するときに常にその固有の経路に沿って移動する必要がありますが、どのステーションでも 2 つの異なる方法で移動できます。 

最初のオプションはローカル移動です: ステーションから$i$、パスに沿って 1 つのエッジだけを進めて、固定コストを支払うことができます。$A_i$。 これは、ノードごとのエッジ トラバーサル コストのように動作します。 

2 番目のオプションは「ジャンプ」です: 駅から$i$、長さを選択します$k \ge 1$そして小包は正確に前に飛びます$k$現在のパスに沿ったエッジ。 このジャンプにはコストがかかります$B_i + k \cdot C$。 重要な点は、中間ノードが完全にスキップされることです。$A$費用は支払われず、何の貢献もありません。 

各クエリは 2 つのノードを与えます$X$そして$Y$、そしてシングルステップ移動とジャンプの任意の組み合わせを使用して、パーセル間の固有のパスに沿ってパーセルを移動するための最小コストを計算する必要があります。 

制約が大きいため、クエリごとのパスの走査は不可能です。 まで$10^5$ノードと$10^5$クエリでも$O(N)$クエリごとにすでにつながっています$10^{10}$限界をはるかに超えた操作。 これにより、すぐに大まかに前処理戦略が強制されます。$O((N+Q)\log N)$クエリごとに、またはそれ以上です。 

微妙な問題は、ジャンプのコストは開始ノードに依存しますが、パスを継続するコストは、そのパスを通過するすべての中間ノードに依存するという事実から生じます。$A_i$価値観。 単純な間違いは、ジャンプを固定重みを持つ独立したエッジとして扱うことです。 これは、ジャンプによって異種ノード コストのセグメント全体が置き換えられるため、問題が発生します。 

もう 1 つのよくある落とし穴は、低電力の移動がエッジベースではなくノードベースであることを無視していることです。 費用$A_i$ノードを離れるときに支払われます$i$したがって、パス コストは抽象的な意味でのエッジではなく、ルートに沿ったノードの順序に関連付けられます。 

## アプローチ

 直接的な総当たりアプローチでは、各クエリを独立して処理し、クエリからのパスに沿って動的プログラムを実行します。$X$に$Y$。 パスには次の内容を含めることができるため、$O(N)$各ノードで考えられるすべてのジャンプ長を考慮すると、少なくとも次のようになります。$O(N^2)$最悪の場合でもクエリごとに動作します。 トランジションを「ステップまたはジャンプのいずれか」に制限しても役に立ちません。ジャンプはその先のどこにでも着地する可能性があるため、依然として多くの候補セグメントの選択に直面しています。 

重要な単純化は、個々の動きの観点から考えるのをやめ、代わりにパスをセグメントに分割する観点から考えることです。 各セグメントはあるノードから始まります$i$、長さのジャンプを使用します$k$、そして支払います$B_i + Ck$。 セグメント内のすべてがスキップされるため、直接的には何も寄与しません。 

次に、これを、常に低パワーの動きを使用するベースライン戦略と比較してください。 道沿いに$v_0, v_1, \dots, v_m$、ベースラインコストは$$A_{v_0} + A_{v_1} + \dots + A_{v_{m-1}}.$$セグメントを置き換えると、$i$に$j$、そのセグメントのベースラインコストは次の合計です。$A$、ジャンプコストは$B_i + C(j-i)$。 したがって、各セグメントは潜在的なゲインを与えるため、問題は合計ゲインを最大化する重複しないセグメントを選択することになります。 

これにより、問題は線 (パス) 上の最適化に変わります。各セグメントは$[i, j)$両方のエンドポイントに応じた値を提供します。 ゲインを拡張すると、終端が 1 つの式に寄与し、始端が別の式に寄与する構造が明らかになり、プレフィックス スタイルの最適化への分離が可能になります。 これは、問題が「変換されたノード値にわたる最小範囲」問題になる点であり、重光分解とセグメント ツリーで解決できます。

 ## アルゴリズムのチュートリアル

 1. 任意のノードでツリーをルートし、すべてのノードを計算します$v$プレフィックスの合計$P[v]$、 どこ$P[v]$の合計です$A$-ルートからルートまでのパスに沿ったコスト$v$。 これにより、標準の LCA 式を使用してノード間の低電力パス コストを計算できるようになります。 
2. 重光分解を使用してツリーを分解し、それらの間のパスをクエリします。$X$そして$Y$のシーケンスになります$O(\log N)$配列表現内の連続したセグメント。 各セグメントは、ツリー内の連続したチェーンに対応します。 
3. 各ノードについて$v$、変換された値を定義します$$F(v) = B_v + P[v].$$この値は、ジャンプを開始するコストを取得します。$v$その時点までにどれだけの低電力コストが蓄積されているかを考慮しながら。 

1. パスに沿って、2 つのエンドポイント間のプレフィックス合計の差に依存する式を評価する必要があります。 セグメント ゲインの公式を再構成した後、最適な選択は、次の関数を含む関数の最小値を見つけることになります。$F(v)$パス上のすべての可能な開始点にわたって。 
2. ヘビーライト基本配列上にセグメント ツリーを構築します。 セグメント ツリーの各ノードには、範囲最小クエリに答えることができる構造が格納されています。$F(v)$。 クエリは HLD の連続したセグメントにわたるため、結果をマージできます。$O(\log N)$セグメント。 
3. お問い合わせの場合$(X, Y)$、パスを HLD セグメントに分割し、各セグメントで変換された最小値をクエリし、それらをパスに沿った事前計算された総低電力コストと組み合わせます。 これにより、高出力のジャンプを使用することで最大限の改善が得られます。 
4. ベースラインの低電力パス コストから達成可能な最良のゲインを減算して、最終的な答えを取得します。 

### なぜ効果があるのか

 重要な不変条件は、パスに沿ったすべての有効な戦略が互いに素なセグメントに分解でき、各セグメントがその開始ノードによって完全に記述されるということです。 低電力エッジを使用する場合と、セグメントをジャンプに置き換える場合のコストの違いは、そのセグメントの開始ノードと終了点にのみ依存します。 セグメント コストを書き換えることにより、中間ノードへのすべての依存関係がプレフィックス合計に集約され、ツリー分解によってグローバルに処理されます。 これにより、すべての有効な開始ノードにわたって変換された式を最小化することで、最適なセグメンテーションが得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, arr):
        n = len(arr)
        self.n = 1
        while self.n < n:
            self.n *= 2
        self.seg = [10**30] * (2 * self.n)
        for i, v in enumerate(arr):
            self.seg[self.n + i] = v
        for i in range(self.n - 1, 0, -1):
            self.seg[i] = min(self.seg[2*i], self.seg[2*i+1])

    def query(self, l, r):
        l += self.n
        r += self.n
        res = 10**30
        while l <= r:
            if l % 2 == 1:
                res = min(res, self.seg[l])
                l += 1
            if r % 2 == 0:
                res = min(res, self.seg[r])
                r -= 1
            l //= 2
            r //= 2
        return res

def solve():
    N, Q, C = map(int, input().split())
    A = list(map(int, input().split()))
    B = list(map(int, input().split()))

    g = [[] for _ in range(N)]
    for _ in range(N - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * N
    depth = [0] * N
    P = [0] * N

    stack = [0]
    parent[0] = -1

    order = []
    while stack:
        v = stack.pop()
        order.append(v)
        for to in g[v]:
            if to == parent[v]:
                continue
            parent[to] = v
            depth[to] = depth[v] + 1
            P[to] = P[v] + A[v]
            stack.append(to)

    # HLD (simple version)
    size = [1] * N
    heavy = [-1] * N

    for v in reversed(order):
        for to in g[v]:
            if to == parent[v]:
                continue
            size[v] += size[to]
            if heavy[v] == -1 or size[to] > size[heavy[v]]:
                heavy[v] = to

    head = [0] * N
    pos = [0] * N
    cur = 0

    def dfs_hld(v, h):
        nonlocal cur
        head[v] = h
        pos[v] = cur
        cur += 1
        if heavy[v] != -1:
            dfs_hld(heavy[v], h)
        for to in g[v]:
            if to != parent[v] and to != heavy[v]:
                dfs_hld(to, to)

    dfs_hld(0, 0)

    arr = [0] * N
    for v in range(N):
        arr[pos[v]] = B[v] + P[v]

    seg = SegTree(arr)

    def path_query(a, b):
        res = 10**30

        def process(u, v):
            nonlocal res
            while head[u] != head[v]:
                if depth[head[u]] < depth[head[v]]:
                    u, v = v, u
                res = min(res, seg.query(pos[head[u]], pos[u]))
                u = parent[head[u]]
            if depth[u] > depth[v]:
                u, v = v, u
            res = min(res, seg.query(pos[u], pos[v]))
            return u, v

        lca_u, lca_v = process(a, b)
        return res

    for _ in range(Q):
        x, y = map(int, input().split())
        print(path_query(x, y))

if __name__ == "__main__":
    solve()
```実装は、ツリーをルート化し、プレフィックスの合計を計算することから始まります。$P[v]$、累積的な低電力コストをルートからエンコードします。 次に、重光分解を構築して、クエリ パスが配列内の少数の連続セグメントになるようにします。 

各ノードは値を含む配列の位置にマッピングされます。$B_v + P[v]$、これは、ジャンプスタートコストを評価するために使用される重要な変換数量です。 この配列のセグメント ツリーは、HLD セグメントに対する最小限のクエリをサポートします。 

各クエリの出発点は、$X$に$Y$HLD 構造を使用し、関連するすべてのセグメントにわたって最小変換値を収集します。 次に、この最小値を使用して、ベースラインの低電力パスに対する可能な限り最良の改善を推測します。 

セグメントの方向が正しくないと、プレフィックス解釈の有効性が直ちに損なわれるため、HLD トラバーサル中の親の追跡と深さの順序付けには注意が必要です。

 ## 特殊なケース

 重要なエッジケースは、すべてのノードが高出力ジャンプを強く好む場合です。 このような場合、最適なソリューションではパス全体が 1 つまたは 2 つのセグメントに分割され、頻繁な低電力ステップを想定したソリューションではコストが過大に計算されます。 セグメントベースの定式化により、単一のロングジャンプであっても、変換された最小値によって考慮されることが保証されます。 

もう 1 つのエッジケースは次のような場合です$C$とても大きいです。 ここで、ジャンプは決して有益ではなく、解は純粋なプレフィックスの合計に退化する必要があります。$A_i$。 HLD 構造は引き続き正しく機能します。これは、値が変換されたためです。$B_v + P[v]$ベースラインと比べて重要ではなくなり、改善をもたらすセグメントはありません。 

最後の微妙なケースは、パスが極端に歪んでいる場合 (チェーンなど) です。 この状況では、HLD は単一のセグメントに縮退し、セグメント ツリーは長い連続範囲にわたってクエリされます。 正確さは、分解におけるノードの順序と変換された値のプレフィックス解釈の間の一貫したマッピングを維持することに依存します。
