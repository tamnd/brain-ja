 ## 解決策
 ## 問題の理解

 次の隠された構成が与えられています。$N$一列に並べられた石の山、$N$は 2 の累乗です。 各杭には高さがあり、これらの高さは最初は降順でない順序で並べ替えられます。 インタラクティブ バージョンでは値を直接見ることはできませんが、概念的には、システムは整数の配列を維持し、変更のたびに常にソートされた状態を維持します。 

2 種類の操作が許可されています。 最初の操作では、インデックスのサブセットを選択し、選択した非負の値を追加します。$X$選択したすべてのパイルを一度に並べ替えた後、配列全体が再並べ替えられます。 2 番目の操作では、現在 2 つの位置に同じ高さの山が保持されているかどうかをクエリしますが、ソート順のインデックスによってのみクエリが実行されます。 

タスクは、限られた数の加算および比較操作のみを使用して、すべての杭の高さが等しくなる状態に到達することです。 課題は、実際の値が分からず、相対的な同等性の情報しか分からないこと、および再ソートによりすべての変更が位置の同一性を即座に破壊することです。 

ソリューションを形作る重要な制約は次のとおりです。$N \le 2048$、 それで$N$は、構造化されたグループ演算には十分小さいですが、頻繁に比較する単純なペアごとの推論ではすぐに制限を超えるほど十分に大きいです。 2 の累乗構造は、問題が再帰的なペアリングまたは倍増戦略を中心に設計されていることを示す強力なヒントでもあります。 

単純な試みでは、すべてのペアを比較して等価クラスを特定しようとしますが、ソートされた並べ替えにより位置の一貫性が損なわれるため、安定したマッピングを維持することさえ不可能になります。 もう 1 つの素朴なアイデアは、より大きな要素に向かって小さな要素を繰り返しインクリメントすることですが、どの山が等しいかがわからないと、これは制御不能な推測と過剰な操作に堕落します。 

各追加操作後の再ソートにより、微妙なエッジ ケースが発生します。 たとえば、インデックスが安定していると仮定してサブセットを「修正」しようとすると、ソート順序が変わり、対応関係が失われます。 操作全体にわたる固定インデックスの意味に依存するソリューションは、何も通知せずに失敗します。 

## アプローチ

 ブルートフォース的な観点は、比較を使用して値の正確なマルチセット構造を特定し、すべてを繰り返し最大値に揃えることです。 ただし、各比較ではインデックスのペアが等しいことが分かるだけであり、加算操作のたびにインデックスは並べ替えによって並べ替えられます。 構造全体を再構築するには、本質的に次のことが必要になります。$\Theta(N^2)$あるいはさらに悪い比較を行ったり、調整を繰り返したりすると、このコストが許容限度を超えて増大する可能性があります。 

重要な点は、実際には値を知る必要がないということです。 すべての要素が等しくなることを確認するだけでよく、任意のサブセットに一括増分を適用できます。 これは、要素の絶対値ではなく、要素間の差異に基づいて作業することを示唆しています。 

すべての操作では順序は維持されますが、同一性は維持されないため、特定の要素の追跡に依存することは避けるべきです。 代わりに、同じサイズの隣接するブロックをマージすることで、個別の値の数を繰り返し減らします。 という事実$N$は 2 の累乗であることが重要です。これにより、配列を再帰的に構造化された半分として扱う、クリーンな分割統治ペアリング戦略が可能になります。 

中心的なアイデアは、各ペアが等しくなるように隣接するペアを繰り返し「平準化」し、各ペアを単一のユニットとして扱い、上に向かって継続することです。 各平準化ステップでは、各ペアの片側でターゲットを絞った加算操作を使用し、正確な値を知る必要がなく、そのペア内で均等化します。 

比較演算は、必要な場合にペア内の等しいことを確認するためにのみ必要ですが、一方の側が常に他方の側と一致するように増分を制御することで、構築をほぼ決定的に行うことができます。

 ## アルゴリズムのチュートリアル

 配列を、同じサイズの隣接するセグメントを繰り返しマージするものとして扱います。 どの段階でも、各セグメントのサイズ内でそれを維持します$2^k$、対称的に適用される追加操作の制御されたシーケンスを使用して、すべての要素を等しくすることができます。 

1. サイズ 1 のセグメントから始めます。各要素は自明の点で均一です。 
2. サイズ1からサイズまでの各レベルについて$N/2$、サイズの隣接するセグメントをペアにする$s$。 We focus on two consecutive blocks$A$そして$B$、各サイズ$s$。 
3. ポジションの各ペアについて$i$で$A$そして対応する$i$で$B$、高さが同じになるようにする必要があります。 直接減算することはできないため、代わりに比較を使用して、一方が小さいかどうかを検出します。 
4. 代表的な比較で、次の最初の要素が示される場合$A$はの最初の要素と等しくありません$B$、どのブロックを増やすかを決定します。 それらが等しい場合、そのペアには何も必要ありません。 
5. 小さい方のブロックに属するすべてのインデックス (概念的には、どちらかのすべての要素) から構成されるサブセットを構築します。$A$または$B$比較結果に応じて)、2 つのブロックを揃える慎重に選択した値を使用して加算操作を適用します。 
6. このレベルのすべてのペアを処理した後、マージされた各セグメントのサイズは$2s$均一になります。 
7. アレイ全体が単一の均一なセグメントになるまで繰り返します。 

これが機能する理由は、各マージ ステップ内で値を増やすだけで、値を減らすことがないため、サブセグメント内で以前に確立された平等性が維持されるためです。 2 つの等しいセグメントが整列されると、それらは常に同一の更新をグループとして受け取るため、その後の操作後も等しいままになります。 

不変条件は、処理後のレベルです。$k$、サイズのすべてのセグメント$2^k$同一の値で構成されます。 各マージ ステップでは、セグメント内の正確さを維持しながらセグメント間の一貫性を高めるため、最終的には配列全体が 1 つの値にまとめられます。

def make_all_equal(N, Q_add, Q_compare):
    # We do not have access to real interactor in this template.
    # The structure below represents the intended strategy.

    def apply_add(indices, x):
        if not indices:
            return
        add(indices, x)

    # Work in levels of doubling segment sizes
    size = 1
    while size < N:
        for start in range(0, N, 2 * size):
            left = list(range(start, start + size))
            right = list(range(start + size, start + 2 * size))

            # decide which side to lift
            # compare representatives
            if compare(left[0], right[0]):
                continue  # already equal

            # We don't know ordering direction; conceptually pick one side
            # In a deterministic strategy, we can safely raise right onto left
            # (or vice versa depending on implementation constraints)
            apply_add(right, 1)

        size *= 2
```このコードは、階層結合の考え方に従っています。 セグメント サイズを繰り返し 2 倍にし、隣接するブロックを単位として扱います。 各ペアについて、代表的な要素を比較します。 異なる場合は、片側に均等な増分を適用して位置を揃えます。 コードの簡素化は概念的な戦略を反映しています。 完全な対話型ソリューションでは、観察された差異に基づいて増分が慎重に計算されますが、構造的な考え方は同じであり、局所的に均等化してから上方にマージします。 

実装の微妙な点は、追加操作のたびに配列が再ソートされることです。これは、インデックスの連続性が失われることを意味します。 正しい完全なソリューションは、固定インデックスへの依存を回避し、代わりに構築を通じて維持される論理グループ ID に基づいて動作します。そのため、社説では位置追跡ではなくブロック レベルの推論を強調しています。

 ## 特殊なケース

 厄介なケースは、すべての値がすでに等しい場合です。 アルゴリズムは不必要な追加操作を回避する必要があります。これは、変更を行っても等価性は維持されますが、操作バジェットが無駄になるためです。 比較ステップにより、不必要な作業が行われないことが保証されます。 

もう 1 つのエッジ ケースは、次のように値が厳密に交互する場合です。`[1,2,1,2,...]`。 各ローカル比較で不一致が特定され、可能な限り最小のスケールで即座に解決され、不一致の伝播が防止されるため、ペアごとのマージは引き続き成功します。 

最後に、値が大きな繰り返しブロックを形成する場合、各マージ ステップが均一ブロック全体を原子単位として扱うため、同種領域内で冗長な比較が発生しないため、アルゴリズムは最適に動作します。
