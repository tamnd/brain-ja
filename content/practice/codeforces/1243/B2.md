 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列が与えられ、非常に特殊な操作を使用してそれらを繰り返し修正できます。つまり、最初の文字列から 1 文字を選択し、2 番目の文字列から 1 文字を選択し、それらを交換します。 目標は、最大でも演奏後に 2 つの弦を同一にすることです。$2n$このようなスワップを実行すると同時に、スワップ シーケンスを明示的に出力します。 

重要な点は、すべての操作で 1 つの文字列内ではなく、2 つの文字列間で文字が移動されるということです。 したがって、基本的には文字の「結合されたマルチセットを再配置」することができますが、それは 2 つの配列間の位置を交換することによってのみ可能です。 

制約は小さいです。$n \le 50$、$k \le 1000$。 これはすぐに次のことを示唆しています。$O(n^2)$あるいは$O(n^3)$試験溶液ごとに問題ありません。 ただし、実際の操作を出力し、厳密な制限内に収める必要があるため、$2n$移動する場合、正確さは最適化よりも構築によって左右されます。 

微妙だが重要な制約は、常に成功するとは限らないということです。 この操作では両方の文字列にわたる文字のマルチセット全体が保持されますが、それらを強制的に 2 つの同一の半分に分割します。 つまり、結合された文字列内にすべての文字が偶数回出現する必要があります。 文字が奇数回出現する場合、その文字を 2 つの同一の文字列に均等に分割することは不可能になります。 

単純なアプローチでは、不一致を別の場所の一致する文字と交換することで、左から右へ貪欲に不一致を修正しようとする可能性があります。 これには 2 つの点で失敗する可能性があります。 まず、それを超える可能性があります$2n$スワップが慎重に構成されていない場合、操作の制限が発生します。 第 2 に、必要な文字が到達可能な構成に存在しない場合、新たな不一致が生じることなくスタックする可能性があります。 

たとえば、次のように考えてみましょう$s = "aa"$、$t = "ab"$。 文字数は、$a:3, b:1$, したがって、運用を考える以前に、それらを同等にすることは不可能です。 貪欲なアルゴリズムは、実行不可能性を早期に認識せずに、スワップや無駄な操作を試みる可能性があります。 

別の失敗例は、同じ不一致が繰り返し「修正」され、その後、以前のスワップによって再び壊れた場合に発生します。これは、スワップが不一致の位置を単調に減らすように設計されていない場合に発生します。 

## アプローチ

 強引なアイデアでは、考えられるすべてのスワップ シーケンスを深度までシミュレートします。$2n$。 各状態は文字列のペアであり、各移動は選択するものを選択します。$i, j$。 これにより、次のような分岐要因が生じます。$n^2$、深さ$2n$、これはたとえ$n = 50$なぜなら、状態空間は実際の限界を超えて爆発するからです。 

重要な点は、検索する必要がまったくないということです。 すべての位置で次のことを確認するだけで済みます$i$のキャラクター$s[i]$そして$t[i]$平等になる。 これは、後の位置を一時的に乱す自由を維持しながら、位置を左から右に 1 つずつ固定することを示唆しています。 

操作の構造は強力です: スワッピング$s[i]$と$t[j]$必要なキャラクターを所定の位置に「引っ張る」ことができます$s[i]$どこからでも$t$、ただし、キャラクターを移動させることもできます。$s[i]$の中へ$t[j]$後で修復できます。 これにより、制御された交換を使用して 2 つの配列を構築するのと同様になります。 

標準的な戦略は貪欲ですが、慎重に制御されます。 位置で$i$、 もし$s[i]$すでに等しい$t[i]$、私たちは何もしません。 それ以外の場合は、ポジションを検索します$j > i$ここで、必要な文字をスワップの回数を制限して導入できます。 重要なのは、1 つの位置につき最大 2 回のスワップが必要になる可能性があるということです。1 回目は有用なキャラクターを所定の位置に配置し、もう 1 回目は移動したキャラクターを修正します。 

なぜなら$n \le 50$、試合をスキャンし、制御されたスワップを実行する余裕があり、決して超えないことを保証します$2n$トータルオペレーション。

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、インデックスの作成が完了した後、$i$、ポジション$0 \dots i$は正しいです。 

1. 各ポジションごと$i$、どうかを確認してください$s[i] == t[i]$。 「はい」の場合、この位置はすでに最終目標と一致しているため、次に進みます。 
2. 異なる場合は修正を試みます$s[i]$。 何かの位置を探します$j > i$どちらかの$s[j] == s[i]$または$t[j] == s[i]$。 これにより、必要な文字を確実に取り込むことができます。$s[i]$最大 2 つのスワップを使用します。 
3. 位置が見つかったら、$s[j] == s[i]$の間でスワップを実行します。$s[j]$そして$t[i]$。 これにより、正しい文字が に移動します$t[i]$、そして交換します$s[i]$と$t[i]$両方の位置を揃えます。 2 回目の交換により、$s[i]$以前のポジションを崩さずに修正します。 
4. それ以外の場合は、$t[j] == s[i]$。 この場合、まず交換します$s[j]$と$t[j]$、目的の文字を に移動します。$s[j]$。 次に、前のケースと同様に、所定の位置に移動します。$i$。 
5. 各修正では最大 2 つのスワップが使用されるため、$n$私たちが決して超えることのないポジション$2n$。 

### なぜ効果があるのか

 アルゴリズムは、すべてが前に配置されるという不変式を維持します。$i$両方の文字列ですでに等しいため、再度変更されることはありません。 各操作は位置を固定します$i$または、すでに固定されている位置を乱すことなく、必要なキャラクターを近づけます。 なぜなら、位置の不一致はすべて$i$一致する文字をインポートすることで解決されます。$j \ge i$、プレフィックスから文字を再度移動することはありません。プロセスにより以前の位置にエラーが再導入されることはありません。 有界 2 スワップ修復により、グローバルなバックトラックなしですべての位置がローカルに解決されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    k = int(input())
    for _ in range(k):
        n = int(input())
        s = list(input().strip())
        t = list(input().strip())
        
        ops = []
        
        def swap(i, j):
            s[i], t[j] = t[j], s[i]
            ops.append((i + 1, j + 1))
        
        ok = True
        
        for i in range(n):
            if s[i] == t[i]:
                continue
            
            found = False
            
            for j in range(i + 1, n):
                if s[j] == s[i]:
                    swap(j, i)
                    swap(i, i)
                    found = True
                    break
            
            if found:
                continue
            
            for j in range(i + 1, n):
                if t[j] == s[i]:
                    swap(j, j)
                    swap(j, i)
                    swap(i, i)
                    found = True
                    break
            
            if not found:
                ok = False
                break
        
        if not ok:
            print("No")
        else:
            print("Yes")
            print(len(ops))
            for x, y in ops:
                print(x, y)

for _ in range(1):
    solve()
```この実装は、欲張りな左から右への戦略に従います。 ヘルパーさん`swap(i, j)`許可された文字列間スワップを実行し、操作を記録します。 最初のループでは、いずれかの文字列に必要な文字が直接出現することを使用して、各不一致の解決を試みます。 

微妙な点は、スワップには同じインデックスが含まれる可能性があることです。$i$2 回。操作では許可されているため、これは有効です。$i = j$。 これは、追加の簿記を必要とせずに、文字を簡単に正しい位置に配置するために使用されます。 

正確さは常に右にスキャンすることに依存しているため、修正後に以前の位置が乱されることはありません。

 ## 特殊なケース

 重要なケースの 1 つは、必要な文字が反対側の文字列の同じ位置にのみ存在する場合です。 アルゴリズムは、自己対象のスワップを許可することでこれを処理します。$i = j$これにより、操作ルールに違反することなくキャラクターをインポートできるようになります。 

もう 1 つのケースは、複数の不一致が先頭に集まっている場合です。 常に右に検索し、以前のインデックスを再度参照することはないため、後の交換によって文字列の後の部分が一時的に乱れたとしても、初期の位置の修正は元に戻されません。 処理後にプレフィックスが固定されたままであるという不変条件により、密な不一致構成であっても正確さが保証されます。
