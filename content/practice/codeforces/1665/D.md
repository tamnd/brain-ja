 ## 解決策
 ## 問題の理解

 隠れた正の整数を見つけるように求められます$x$1との間$10^9$。 観察する代わりに$x$直接、シフトされた 2 つの数値の最大公約数をクエリできます。$x$。 具体的には、任意の 2 つの正の整数に対して、$a$そして$b$、インタラクターが戻ります$\gcd(x + a, x + b)$。 タスクは決定することです$x$このようなクエリは最大 30 個使用します。 

課題は推測にあります$x$選択したペアとの算術相互作用を通じて間接的に。 この限界は、すべてを総当たりで検索する余裕がないことを示しています。$10^9$可能性。 最大限の情報を抽出するには、各クエリを選択する必要があります。 複数の可能性を 1 つの約数にまとめる GCD のみが得られるため、慎重に選択する必要があります。$a$そして$b$重要です。 

ナイーブなエッジケースは次の場合に発生します。$x$非常に小さいか非常に大きいです。 たとえば、次の場合$x = 1$、次のような小さな値をクエリします。$a = 1$そして$b = 2$収量$\gcd(2, 3) = 1$、最小限の情報を提供します。 もし$x = 10^9$、大きな値をクエリすると、同様に多くの可能性が 1 つに集約される可能性があるため、戦略は適応的である必要があります。 

別の微妙なケースが発生するのは、$x + a$そして$x + b$ある約数の連続した倍数です。 このような場合、次のような場合でも GCD 1 が表示されます。$x$それ自体が大きいです。 したがって、可算構造を理解すると、$x$重要です。 

## アプローチ

 ブルートフォースアプローチでは、可能な限りすべての攻撃が繰り返されます。$x$値、シミュレーション$\gcd(x + a, x + b)$一部のクエリについては、一貫性を確認してください。 各テスト ケースには最大で$10^9$チェックがあり、最大 1000 のテスト ケースがあります。 操作数は妥当な制限をはるかに超えています。 

重要な洞察はプロパティから得られます$\gcd(x + a, x + b) = \gcd(a - b, x + b)$。 これにより問題が理解に変わります$x$モジュロのさまざまな違い。 相違点が存在する一連のクエリを慎重に選択することで、$b - a$既知であり、比較的素な、または構造化されているものであれば、決定することができます。$x$モジュロの数はますます大きくなります。 本質的に、これは中国剰余定理の対話型応用です。各 GCD は次の条件に合同制約を与えます。$x$を組み合わせて特定します。$x$。 

したがって、最適なアプローチは建設的です。 差が 2 の累乗になるようにクエリを選択します。 これにより、次のバイナリ表現を抽出できます。$x$少しずつ。 各 GCD は特定のビットが設定されているかどうかを明らかにし、30 回のクエリ後に再構築できます。$x$全体的に。 2 のべき乗の使用は、各クエリが 1 ビットを分離することを保証し、重複や曖昧さを回避することが保証されるため、非常に重要です。

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`x_guess`ゼロに。 これには、再構築された値が保持されます。$x$そのビットを推測すると。 
2. 0 から 29 までの各ビット位置に対して、次のクエリを構築します。`a = 2^bit`そして`b = 0`。 これにより、違いが確実に得られます$a - b = 2^bit$、現在のビットを分離します。 
3. クエリ`? a b`そして応答を読んでください`g`。 コンピューティング`g % 2^(bit+1)`。 もし`g`で割り切れます$2^{bit+1}$、現在のビット$x$それ以外の場合は 1。更新`x_guess`それに応じて。 
4. 30 ビットすべてが処理されるまで繰り返します。 最終版を印刷する`x_guess`隠し番号として。 

機能する理由: 差が 2 の累乗である GCD は下位ビットのみを認識するため、各クエリは単一ビットを分離します。 摂取することで`g % 2^(bit+1)`かどうかを検出します。$x$その位置に 1 があります。 2 のべき乗はバイナリ表現においてペアごとに独立しており、ビットが干渉しないことが保証されます。 30 回のクエリの後、次のすべてのビットが$2^{29}$が決定され、全​​範囲をカバーします$1 \le x \le 10^9$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def solve():
    t = int(input())
    for _ in range(t):
        x_guess = 0
        for bit in range(30):
            a = 1 << bit
            b = 0
            print(f"? {a} {b}")
            sys.stdout.flush()
            g = int(input())
            if g % (1 << (bit + 1)) != 0:
                x_guess |= (1 << bit)
        print(f"! {x_guess}")
        sys.stdout.flush()

solve()
```このソリューションでは、まずテスト ケースの数を読み取ります。 各テスト ケースでは、30 ビット位置を反復します。 クエリはビットを分離し、応答は再構築に使用されます。`x_guess`。 これは対話型であるため、フラッシュが必要です。 使用する`1 << bit`ビット選択の正確な制御を保証します。

 ## 特殊なケース

 のために`x = 1`、クエリする`a = 1`そして`b = 0`GCD 1 を生成し、ビット 0 が設定されていることを示し、再構築します`x_guess = 1`。 のために`x = 10^9`、2 の大きな累乗をクエリすると、各ビットが正しく分離されます。 アルゴリズムは、許可範囲の両端を正しく処理し、各クエリで`1 << bit`モジュロ演算は分離されたビットの大きさと正確に一致します。
