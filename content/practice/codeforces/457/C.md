 ## 解決策
 ## 問題の理解

 私たちは既知の有権者がいる都市での選挙に勝とうとしています。 現在、各有権者は 0 から上の番号が付けられた候補者を支持しており、それぞれがあなたに投票してもらうために賄賂を支払うコストを持っています。 候補0は私たちです。 私たちの目標は、他の候補者よりも厳密に多くの票を確保するために最小限の資金を費やすことです。 

入力では有権者の数が提供され、その後に各エントリに有権者が現在支持している候補者とその候補者に賄賂を提供するコストが含まれるリストが表示されます。 有権者がすでに私たちを支持している場合、その費用はゼロです。 出力は、勝つために必要な最小の総コストです。 

制約は重要です。 有権者が最大 100,000 人である場合、有権者のすべてのサブセットを検査するソリューションは遅すぎます。 賄賂のあらゆる組み合わせを検討しようとする強引なアプローチは爆発的であり、直ちに排除されます。 二次アプローチはタイムアウトする可能性が高いため、おおよそ O(n log n) または O(n * m) のアプローチが必要です。ここで、m は個別の候補の数です。 

誤って対処しやすいエッジケースは、すでに他の誰よりも多くの票を持っているときに発生します。 たとえば、入力が次の場合:```
3
0 0
1 5
2 7
```私たちはすでに 1 票を持っていますが、これはすでに他の候補者よりも多いかもしれません。 アルゴリズムは賄賂が必要ないことを検出し、0 を出力する必要があります。別の厄介なケースは、複数の候補者が同じ票数を持っており、辛うじてそれらを上回るためには、各対立候補者から最も安価な投票者を賄賂で賄う必要がある場合に発生します。 この微妙な点を見逃すと、浪費につながります。 

## アプローチ

 素朴なアプローチは、目標とする可能なすべての投票数を試し、その数に達するためにどの有権者に賄賂を渡す必要があるかを確認することです。 具体的には、現在私たちに投票していない有権者のすべてのサブセットを考慮し、各サブセットの総コストを計算し、彼らに賄賂を渡すことで勝利票数が得られるかどうかを確認できます。 このアプローチは、考えられるすべての賄賂シナリオを調査するため正しいものですが、指数関数的です。100,000 人の有権者がいる場合、2^100,000 の可能性は完全に手に負えません。 

より迅速な解決策を可能にする重要な洞察は、勝つためには次に高い支持を得ている候補者よりも 1 票多く得ればよいということを認識することです。 したがって、「目標投票数」という観点から考えることができます。つまり、自分自身に何票を獲得したいのか、その数に到達するための最小コストはいくらなのか、ということです。 希望する潜在的な投票数ごとに、最も低い賄賂コストで最も有力な対立候補を支持する有権者に賄賂を優先させることができます。 対立候補ごとに有権者を費用で並べ替えることで、最小費用を段階的に計算できます。 

問題は、実現可能な投票目標ごとに、目標を超える票を獲得した候補者からの賄賂の最も安価な組み合わせを評価することに帰着します。 私たちは、達成を目指す可能性のある総投票数をすべて反復し、その数に到達するために安価に賄賂を賄うことができる追加の有権者の優先列を維持します。 これにより、各候補者の投票者が分類され、潜在的な賄賂の山が維持されるため、問題は指数関数的なものからおよそ O(n log n) に減少します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての有権者を読み取り、現在支持している候補者ごとにグループ化し、各候補者の贈収賄コストをリストに保存します。 これにより、候補者に対するあらゆる潜在的な賄賂に迅速にアクセスできるようになります。 
2. 各候補者の贈収賄費用リストを昇順に並べ替えます。 目標の投票数に関係なく、最も低コストの有権者に賄賂を贈るのが常に最適であるため、より安価な賄賂を最初に検討する必要があります。 
3. それぞれの可能な目標投票数について`t`(現在の投票数から、任意の候補者が保持している最大投票数に 1 を足したものまで) を保持し、その数に達するための最小コストを計算します。 これは、まずどの候補者がより多くの票を持っているかを特定することによって行われます。`t-1`(勝つためには厳密にそれぞれ以上のものが必要なので)。 このような候補者ごとに、投票数を以下に減らすために何人の有権者を買収する必要があるかを決定します。`t`。 
4. 過半数を占めた各候補者から必要な最安投票者の数を取り出し、その数を減らします。 すべての候補者の残りの有権者の優先キュー (またはソートされたリスト) を維持し、初期数とこれらの賄賂がまだ下回っている場合に必要な追加票を記入します。`t`。 
5. このターゲットに対して選択されたすべての賄賂のコストを合計します。 すべてのターゲット投票数にわたる最小合計コストを追跡します。 
6. 取得した最小コストを返します。 

なぜ機能するのか: どのターゲットに対しても不変条件が維持されます。`t`、アルゴリズムにより、すべての候補者が最大でも`t-1`最小コストの賄賂を選択した後に投票します。 考えられるすべての目標投票数を反復し、利用可能な最も安価な賄賂を常に受け​​取ることにより、厳格な過半数を確保するために必要な最小限の支出を保証します。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

n = int(input())
votes = {}
our_votes = 0

for _ in range(n):
    a, b = map(int, input().split())
    if a == 0:
        our_votes += 1
    else:
        if a not in votes:
            votes[a] = []
        votes[a].append(b)

for v in votes:
    votes[v].sort()

all_candidates = list(votes.keys())
min_cost = float('inf')
max_votes = max(len(lst) for lst in votes.values()) if votes else 0

for target in range(our_votes, n+1):
    extra_needed = max(0, target - our_votes)
    costs_heap = []
    total_cost = 0
    extra_collected = 0
    
    for cand in all_candidates:
        cand_votes = len(votes[cand])
        if cand_votes >= target:
            num_to_bribe = cand_votes - (target - 1)
            total_cost += sum(votes[cand][:num_to_bribe])
            for c in votes[cand][num_to_bribe:]:
                heapq.heappush(costs_heap, c)
        else:
            for c in votes[cand]:
                heapq.heappush(costs_heap, c)
    
    while extra_collected < extra_needed and costs_heap:
        total_cost += heapq.heappop(costs_heap)
        extra_collected += 1
    
    if extra_collected == extra_needed:
        min_cost = min(min_cost, total_cost)

print(min_cost)
```このコードは、まず候補者ごとにすべての有権者を収集し、その賄賂コストを分類します。 潜在的な投票目標ごとに、他の候補者の投票を目標以下に減らすために必要な賄賂の数を計算し、残りの必要な投票を埋めるための追加の投票者を最小ヒープに保存します。 これにより、最も安価な追加賄賂が常に最初に選択されるようになります。 すべてのターゲットにわたる最小の合計コストが出力されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各候補者の投票者をソートし、最小ヒープを維持することが実行時間を支配します。 |
 | スペース | O(n) | すべての投票者のコストとヒープを保存するには、線形スペースが必要です。 |

 n ≤ 100,000 の場合、O(n log n) 操作は 2 秒以内に実行可能で、100,000 個の整数の格納は 256 MB メモリ内に十分収まります。
