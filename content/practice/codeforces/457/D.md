 ## 解決策
 ## 問題の理解

 私たちは、$n \times n$ビンゴボード。 すべてのセルには、次から選択された個別の数字が含まれています。$1$に$m$、そしてすべての有効なボードは同様に可能性が高くなります。 

ボードが生成された後、正確に$k$個別の番号が呼び出されます。 すべてのセット$k$数字の可能性も同様です。 セルの番号が着信番号の中に出現すると、そのセルがマークされます。 

すべてのセルがマークされている場合、行は完了したとみなされます。 同じ条件でカラムが完成します。 ボードが次で終了した場合$r$完全な行と$c$列を完成させた場合のスコアは$$2^{r+c}.$$タスクは、予想されるスコアを計算することです。 

この制約により、シミュレーションや状態ベースのアプローチは完全に排除されます。 ボードには以下が含まれます$300^2 = 90000$細胞、そして$m$と同じ大きさにすることができます$100000$。 行や列のサブセットを反復処理することさえ不可能です。 期待値を少数の組み合わせ状態に減らす公式が必要です。 

最初のトラップは、行と列が独立していることを前提としています。 そうではありません。 1 つの行が完了すると、呼び出された番号を共有するため、別の行または列が完了する確率が変わります。 

例えば：```
n = 2
m = 4
k = 3
```一番上の行が完了している場合は、その行の両方の番号が呼び出されたセットに属している必要があります。 これは、行と交差する列が完成する確率に影響します。 

もう 1 つの簡単な間違いは、特定の基板レイアウトを条件にしようとすることです。 ボード自体はランダムです。 解は両方のランダム プロセスを同時に平均化する必要があります。 

2 番目の微妙なケースは、必要なマークされたセルが着信番号の数を超える場合に発生します。```
n = 3
m = 20
k = 4
```5 つ以上の個別のセルをマークする必要があるイベントは、呼び出される数値が 4 つだけであるため、確率は 0 です。 正しく実装すると、これらの項に対して自動的にゼロが生成される必要があります。 

3 番目のエッジ ケースは最小のボードです。```
1 2 1
```セルが 1 つあります。 確率で$1/2$その番号が呼び出され、スコアが与えられます$2$。 それ以外の場合のスコアは$1$。 

期待は$$\frac12 \cdot 2 + \frac12 \cdot 1 = 1.5.$$ただし、ボード番号自体はランダムです。 ボードの世代と着信番号の両方を平均することで正式な答えが得られます$2.5$。 ランダム性の 1 つのソースを忘れた導出は間違っています。 

## アプローチ

 ブルート フォース アプローチでは、考えられるすべてのボードとすべての考えられる着信番号セットを列挙し、各結果のスコアを計算し、結果を平均します。 

ボードの数は、$$\frac{m!}{(m-n^2)!},$$呼び出されるセットの数は$$\binom{m}{k}.$$たとえ小さな入力であっても、これは天文学的な数字です。 

ブルート フォースが概念的に正しい理由は、スコアはどの行と列が完成するかによってのみ決まるからです。 課題は、ボードを列挙せずにこれらのイベントをカウントする方法を見つけることです。 

重要な観察は、スコアを書き直すことから得られます。 

させて$R_i$その行のインジケーターになります$i$完了しており、$C_j$その列の指標となる$j$完了です。 

それから$$2^{R_i} = 1 + R_i$$なぜなら$R_i$どちらかです$0$または$1$。 

したがって$$2^{\sum R_i + \sum C_j} = \prod_{i=1}^{n}(1+R_i) \prod_{j=1}^{n}(1+C_j).$$次に製品を展開します。$$\prod_{i}(1+R_i)\prod_{j}(1+C_j) = \sum_{A,B} \left( \prod_{i\in A} R_i \right) \left( \prod_{j\in B} C_j \right),$$どこ$A$行のサブセットであり、$B$列のサブセットです。 

期待値を考慮し、直線性を利用して、

 E[\text{スコア}] = \sum_{A,B} P(\text{}A\text{ のすべての行が完了し、}B\text{ のすべての列が完了)。 

これは問題を確率の計算に変換します。 

仮定する$|A|=a$そして$|B|=b$。 

選択した行ごとにすべてが必要です$n$マークされたセル。 選択した列ごとに、すべての列も必要です。$n$マークされたセル。 結合には以下が含まれます$$t = an + bn - ab$$細胞、なぜなら$ab$行と列の交差は 2 回カウントされました。 

それらすべて$t$セルには個別の数字が含まれています。 イベントは、これらの番号がすべて呼び出されたセットに属するときに発生します。 

もし$t$特定の数字がその中に現れる必要があります$k$数字と呼ばれる、確率は$$\frac{\binom{m-t}{k-t}}{\binom{m}{k}} = \frac{(k)_t}{(m)_t}.$$重要なのは、これは以下にのみ依存します。$t$、実際に選択された行と列ではありません。 

だからどのペアも$(a,b)$貢献する$$\binom{n}{a} \binom{n}{b} \cdot \frac{\binom{m-t}{k-t}}{\binom{m}{k}}.$$あるのは$(n+1)^2$可能な値$(a,b)$、最大でも$301^2$。

 ## アルゴリズムのチュートリアル

 1. すべての二項係数を事前計算する$\binom{n}{i}$のために$0 \le i \le n$。 

以来$n \le 300$を使用して反復的に構築できます。$$\binom{n}{i} = \binom{n}{i-1} \cdot \frac{n-i+1}{i}.$$2. 事前計算$$p[t] = \frac{\binom{m-t}{k-t}}{\binom{m}{k}}$$あらゆる人にとって$0 \le t \le n^2$。 

から始める$p[0]=1$。 のために$t \ge 1$、$$p[t] = p[t-1] \cdot \frac{k-t+1}{m-t+1}.$$一度$t>k$、確率はゼロになります。 
3. 可能な数の選択された行をすべて反復します。$a$と選択された列$b$。 
4. コンピューティング$$t = an + bn - ab.$$これは、まさにこれらの行と列を結合したセルの数です。 
5.追加$$\binom{n}{a} \binom{n}{b} p[t]$$答えに。 
6. 累計回答数を超えた場合$10^{99}$、印刷$10^{99}$。 

### なぜ効果があるのか

 拡張後$$\prod_i(1+R_i)\prod_j(1+C_j),$$すべての用語は、行のサブセットと列のサブセットの選択に対応します。 指標の積は以下に等しい$1$選択したすべての行が完了したときと次の値が等しいとき$0$さもないと。 

そのイベントの確率は、それらのラインに属するセルのセットにのみ依存します。 彼らの結合には以下が含まれます$$an+bn-ab$$異なる細胞。 すべてのボード番号は個別であるため、このイベントは、それらの個別の番号がボード内に表示されることを要求することと同じです。$k$いわゆる数字。 

したがって、すべてのサブセット ペアがその発生確率に正確に寄与し、すべてのサブセット ペアを合計すると、期待されるスコアが得られます。 どの用語も省略されず、どの用語も 2 回カウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    max_t = n * n

    choose = [0.0] * (n + 1)
    choose[0] = 1.0
    for i in range(1, n + 1):
        choose[i] = choose[i - 1] * (n - i + 1) / i

    p = [0.0] * (max_t + 1)
    p[0] = 1.0

    limit = min(k, max_t)
    for t in range(1, limit + 1):
        p[t] = p[t - 1] * (k - t + 1) / (m - t + 1)

    ans = 0.0

    for a in range(n + 1):
        ca = choose[a]
        for b in range(n + 1):
            t = a * n + b * n - a * b
            if t > k:
                continue

            ans += ca * choose[b] * p[t]

    if ans > 1e99:
        print("1e99")
    else:
        print("{:.10f}".format(ans))

solve()
```配列`choose`すべての値を保存する$\binom{n}{i}$。 乗法漸化式を使用すると階乗が回避され、数値的に安定した状態が維持されます。$n=300$。 

配列`p`の固定セットが成立する確率を格納します。`t`個別の数値が呼び出されたセットに完全に含まれています。 再帰的に計算すると、二項係数を繰り返し評価するよりもはるかに高速になります。 

表現```
t = a * n + b * n - a * b
```は、ソリューションにおける最も重要な計算式です。 減算により、2 回カウントされた行と列の交差が削除されます。 

小切手```
if t > k:
    continue
```すべての不可能な出来事に即座に対処します。 以上の場合`k`個別の数値が必要な場合、確率は正確にゼロです。 

すべての計算には浮動小数点が使用されます。 公式の答えでは相対的な誤差が許容されます$10^{-9}$、ここではダブルで十分です。

 ## 特殊なケース

 次のことを考慮してください。```
3 20 4
```完全な行には、すでに 3 つのマークされたセルが必要です。 2 つの完全な行には 6 つの異なるセルが必要です。 

アルゴリズムは計算します$$t = an + bn - ab.$$のために$a=2, b=0$、$$t = 6.$$以来$6 > k = 4$、その投稿はすぐにスキップされます。 これは実際の確率、つまり正確にゼロと一致します。 

ここで次のことを考えてみましょう。```
2 4 4
```4 つの番号すべてが呼び出されます。 すべてのセルにマークが付けられます。 すべての行とすべての列が完了しました。 

スコアはいつも$$2^{2+2}=16.$$アルゴリズムでは、$$p(t)=1$$あらゆる人にとって$t \le 4$。 サブセット展開は次のようになります。$$\sum_{a=0}^{2}\binom{2}{a} \sum_{b=0}^{2}\binom{2}{b} = 2^2 \cdot 2^2 = 16.$$最後に、次のことを考慮してください。```
1 2 1
```行と列は実際には同じセルです。 不用意な解決策は、これらを 2 つの独立した要件としてカウントする可能性があります。 私たちの和集合式は次のようになります。$$t = 1 + 1 - 1 = 1,$$そのため、オーバーラップは正しく処理されます。 確率は、2 つではなく 1 つの必要なセルを使用して計算されます。
