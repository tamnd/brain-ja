 ## 解決策
 ## 問題の理解

 アパートのリストが与えられ、それぞれに販売価格と地区ラベルが付けられています。 時間は次のように分けられます`t`ボリスは毎日、せいぜい 1 つのアパートを売るか、何もしないことができます。 目標は、総収益を最大化するために、アパートのサブセットを選択し、選択した各アパートを個別の日に割り当てることです。 

スケジューリングを難しくする追加の制約があります。 地区ごとに、ボリスがその地区のアパートを売却する場合、同じ地区の別のアパートをすぐに売却しないようにする必要があります。 より正確には、任意の連続したブロック内で、`K`日に、どの固定地区からも最大で 1 件のセールが発生する可能性があります。 これは、同じ地区の 2 つのアパートが日に売れた場合と同じです。`d1 < d2`、 それから`d2 - d1 >= K`。 

したがって、問題は、最も価値のあるアパートを選択するだけでなく、地区のクールダウン規則が満たされるようにそれらをタイムライン上に配置することです。 

制約は以下に達します`n, t ≤ 10^5`これにより、すべての配置を試行する二次的なスケジューリングやシミュレーションが除外されます。 どのソリューションも線形に近いか、`O(n log n)`。 

素朴な貪欲なアプローチがスケジュール構造を無視すると、微妙な障害モードが発生します。 たとえば、常に最も高価な残りのアパートを選択し、将来の空室状況を考慮せずにそれを恣意的に割り当てると、より良い構成を簡単にブロックできます。 

次の状況を考えてみましょう。`t = 3, K = 2`、同じ地区の高価値のアパートメントが 2 つ、別の地区から中価値のアパートメントが 1 つあります。 最初に選択したアパートメントの割り当てが遅すぎると、別の順序で両方が許可される場合でも、2 番目のアパートメントに有効なスロットが残らない可能性があります。 これは、慎重に配置しないと値の並べ替えだけでは不十分であることを示しています。 

もう一つの微妙なケースは、ある地区での密集した紛争から生じたものです。 多くのアパートが同じ地区を共有している場合、間隔の制約により密にスケジュールを設定することができないため、単純な「すべてを選択」戦略は失敗します。 たとえば、`K = 3`、同じ地区に 10 のアパートがあり、空き日数が多いとしても、選択できるのは約`t / 3`彼らのうち。 

## アプローチ

 強引なアイデアは、アパートのすべてのサブセットを考慮し、時間をかけてバックトラッキングまたは動的プログラミングを使用して、それらを日付と最後に使用された地区の位置に割り当てようとすることです。 これには、使用された日を追跡し、各地区が規則を遵守するようにする必要があります。`K`ギャップ制約。 固定のサブセットのみを割り当てようとしても、選択した各アパートメントは可能な限り多くの日数で配置される可能性があるため、最悪の場合、スケジュール自体が指数関数的に増加します。 と`n = 10^5`、これは実現不可能です。 

重要な点は、曜日の正確な割り当てが柔軟であるということです。 重要なのは、有効な配置が存在するかどうかだけであり、どの特定の有効なスケジュールを選択するかではありません。 これは、値の降順にアパートメントを処理し、各アパートメントを有効なスロットにできるだけ早く配置するという貪欲な戦略を示唆しています。 すべての制約は値の順序とは独立しているため、高価値のアパートをスケジュールできる場合、それを拒否して低価値のアパートを選択することは決して望ましくありません。 

これにより、問題はスケジュール中に 2 つの制約を維持することに変わります。1 日あたり最大 1 つのアパートメントを収容できることと、各地区には次の利用可能な日を次の時間まで早めるクールダウンがあります。`K`。 

迅速な割り当てをサポートするために、当社では常に、必要な開始点以降に最も早い空き日を与える構造を維持しています。 これは、何日にもわたって素のセットユニオン構造を使用して実装でき、毎日が次に利用可能なものを指します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数 | O(t) | 遅すぎる |
 | 貪欲 + DSU スケジューリング | O(n α(t)) | O(t) | 承認済み |

 ## アルゴリズムのチュートリアル

 実現可能性の制約を尊重しながら、より価値の高い決定を優先する必要があるため、アパートメントを価格の降順に処理します。 

## アルゴリズムのチュートリアル

 1. すべてのアパートメントを価格の降順に並べ替えます。 これにより、アパートを決めるときはいつでも、残りのすべての選択肢の中で、その時点で利用可能な最良の選択肢となることが保証されます。 
2. 配列を維持する`last[d]`地区からアパートを売却した最終日を保存する`d`。 最初は、すべての地区が日中から利用できるように、すべての値が設定されています。`1`。 
3. 素のセットユニオン構造を何日も維持する`1..t`、各日は、次に利用可能な未使用の日を指します。 これにより、特定の日以降に最も早い空きスロットをすばやく見つけることができます。 
4. 並べ替えられた順序で各アパートメントについて、最も早い有効な販売日を次のように計算します。`start = last[b_i] + K`。 これにより、工事による地区クールダウンルールが施行されます。 
5. 最初の無料日について DSU 構造をクエリします。`d >= start`。 そんな日がこの中にあるなら`1..t`、このアパートを 1 日に割り当てます`d`。 それ以外の場合は、アパートを完全にスキップしてください。 
6. アパートの日割りが決まった場合`d`、マークデー`d`とマージすることで DSU 構造内で占有されるようになります。`d + 1`、更新します`last[b_i] = d`。 
7. で初期化された出力配列に割り当てを保存します。`-1`指定された日に、選択したアパートメントのインデックスを記入します。 

### なぜ効果があるのか

 このアルゴリズムは、実行を通じて 2 つの不変条件を維持します。 まず、DSU は常に未使用の日を返し、その日を今後の検討対象から直ちに削除するため、割り当てられた日はすべてグローバルに一意です。 第二に、地区の割り当てはすべて間隔を尊重します。これは、これまでに新しい割り当てを許可したことがないためです。`last[b_i] + K`。 

アパートメントを価値の降順に処理することで、価値の高いアパートメントを配置できる場合、価値の低い代替品が同じ有用なタイムスロットを消費する前に常に試行されるようになります。 DSU は、実行可能な最も早い日を常に選択することを保証します。これにより、割り当てを不必要に前倒しすることがなくなり、後の柔軟性が維持されます。 有効なスケジュールは、合計値を減らすことなく、この貪欲な配置によって生成されるスケジュールに変換できます。

import sys
input = sys.stdin.readline

def find(parent, x):
    if parent[x] != x:
        parent[x] = find(parent, parent[x])
    return parent[x]

def union(parent, x, y):
    x = find(parent, x)
    parent[x] = find(parent, y)

n, K, t = map(int, input().split())

apts = []
for i in range(n):
    a, b = map(int, input().split())
    apts.append((a, b, i + 1))

apts.sort(reverse=True)

        last[b] = d
        union(parent, d, d + 1)

res_sum = 0

実装の微妙な詳細は、常に次から検索することです。`last[b] + K`、最後に使用した日プラス 1 日からではありません。 これにより、割り当て後に検証するのではなく、スケジュール段階で地区のクールダウンが直接強制されます。 

出力配列`ans`日付をアパートのインデックスにマッピングし、完全なスケジュールを直線的な時間で印刷できるようにします。

 ## 特殊なケース

 エッジケースの 1 つは、多くの高額なアパートが同じ地区に属しており、`K`大きいです。 アルゴリズムは、間隔ルールに適合するもののみを割り当てます。DSU は、以前の配置を誤って上書きするのではなく、後のものは正しく失敗することを保証します。 たとえば、`K = 3`そして日々`1..5`、スケジュールできるのは 1 つの地区から最大 2 件の販売だけであり、アルゴリズムにより当然これが強制されます。`start`利用可能な日数は固定されたままですが、増加し続けます。 

値で並べ替えないと、初期の低価値の配置が高価値の配置をブロックする可能性があるという別のエッジ ケースが発生します。 より価値の高いアパートメントが常に最初に考慮され、最も早い実行可能なスロットを占有するため、並べ替えによりこのようなことが起こらないことが保証されます。 

最後のケースは次のような場合です。`t`よりもはるかに大きいです`n`。 このシナリオでは、DSU は単に初期の空き日を返し、後のほとんどの日は使用されないままであるため、引き続き正しく動作します。 特別な対応をしなくても自然とスケジュールはまばらになります。
