 ## 解決策
 ## 問題の理解

 番号が与えられ、非常に特殊な操作を使用して繰り返し変更することができます。 1 回の操作で、3、33、333 など、10 進形式が数字 3 のみで構成される正の整数を選択し、それを現在の値に加算します。 

このような加算をいくつか実行した後、目標は、10 進表現で 0 から 3 までの数字のみを含む数値に到達することです。つまり、最終的な数値のすべての桁は最大でも 3 でなければなりません。必要な加算の数を最小限に抑えることが求められます。 

主な難点は、各演算が単純な +1 や +k ではなく、3 が繰り返される桁の接頭辞に影響を与え、10 進数の桁上げを通じて大きく相互作用する構造化された数値であることです。これは、各演算の効果が複数の桁にわたってグローバルであり、異なる演算が自明ではない形で重複することを意味します。 

入力サイズでは、最大 10 桁の数値と最大 1000 個のテスト ケースが許可され、桁の長さの合計は最大 10^7 になります。 これにより、操作のすべてのシーケンスをシミュレートしたり、実際の数値を検索しようとするアプローチは即座に除外されます。 唯一の実行可能な方向は、桁ごとに推論し、これらの「すべて 3」の数値が追加されたときにどのように動作するかの構造を利用することです。 

単純だが魅力的なアイデアは、可能な限り小さい「3…3」を追加して、右から左へ貪欲に数字を修正してみることです。しかし、後の桁上げによって以前の修正が破壊される可能性があるため、これは失敗します。 たとえば、2 に修正された数字が、より高い位置を処理すると 5 になり、最終的な数字が再び無効になる可能性があります。 操作はローカルではないため、貪欲な安定化は成り立ちません。 

もう 1 つの一般的な障害モードは、各桁を個別に扱うことです。 たとえば、各桁を独立して 3 以下に修正できると仮定すると、すべての演算が下位のすべての位置に同時に影響を及ぼし、上向きのキャリーが導入されることが無視されます。 

## アプローチ

 ブルートフォース手法では、一連の操作をシミュレートします。 各ステップで長さ L を選択し、L 桁の 3 からなる数値を追加します。小さい L に制限したとしても、分岐係数は依然として大きく、可能なシーケンスの数は演算の数とともに指数関数的に増加します。 最悪の場合、答えを得るには数ステップ以上かかる可能性があるため、これはすぐに実行不可能になります。 

構造的な洞察は、すべての操作はその長さによってのみ決定されるということです。 長さ L の演算では、最下位桁から位置 L-1 までのすべての桁位置に 3 が加算されます。 これは、個々の数値について考える代わりに、各桁の位置をカバーする演算の数を考えることができることを意味します。 

演算の数 k を固定すると、すべての演算の全体的な効果は非増加シーケンス c[i] で表すことができます。ここで、c[i] は数字 i に影響を与える演算の数です。 このシーケンスは c[0] = k で始まり、より長い演算の数が少ないか等しいため、より有効な桁に移動するにつれて減少します。 

このような構造を修正すると、問題は桁上げを伴う桁 DP になります。桁ごとに加算をシミュレートし、n と演算による寄与を加算した後、結果として得られるすべての桁と桁上げが有効な状態 (最後の桁 ≤ 3) に留まり、桁上げが正しく伝播することを確認します。 

次に、k を小さい値から上に増やしていき、DP によって実現可能性を確認します。 問題の制約と構造により、必要な k が実際には非常に小さく、制限されていることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシーケンス | 指数 | 指数 | 遅すぎる |
 | 固定 k 上の桁 DP | k あたり O(k² · L · C) | O(k・L・C) | 承認済み |

 ここで、L は桁数、C は有界キャリー範囲です。 

## アルゴリズムのチュートリアル

小さい k から始めて最大 k 回の操作を使用して有効な数値に到達できるかどうかを確認することで、各テスト ケースを個別に解決します。 

1. 演算の候補数 k を決定します。 各操作は「3 で埋められたプレフィックス」に寄与するため、すべての k 個の操作を個別にモデル化するのではなく、一緒にモデル化します。 
2. 最下位桁から最上位桁までの位置にわたる桁 DP を定義します。 各位置 i で、現在のキャリーとこの桁に影響を与える操作の数を追跡します。 
3. 値 c[i] を使用して演算の効果を表します。これは、k 個の演算のうちのいくつが数字 i に及ぶかを意味します。 長いプレフィックスは短いプレフィックスよりも頻繁に現れることができないため、この値は c[0] = k および c[i] ≤ c[i−1] を満たす必要があります。 
4. 各桁位置で、0 から c[i−1] までの c[i] の有効な選択肢をすべて試します。 それぞれの選択によって、その桁にどれだけ加算するかが決まります: 3 · c[i]。 
5. 結果の桁値を n[i] + 3・c[i] + キャリーとして計算します。 10 を法とする新しい数字を抽出し、繰り上げを伝播します。 
6. モジュロおよびキャリー処理の後で結果の桁が 3 を超える遷移は拒否され、不一致が生じます。 要件は、最後の数字が 3 以内であることです。 
7. すべての桁を処理した後、残りのキャリーがすべて解決され、一連の c 値が一貫して 0 に減衰できることを確認するために、追加のステップを 1 つ続けます。 
8. 指定された k に対して有効な DP パスが存在する場合、答えとして k を返します。 

実現可能性が見つかるまで、k を増やすためにこのチェックを繰り返します。 

正しさは、有効な演算のシーケンスがまさに 1 つの非増加シーケンス c[i] を誘導するという事実から来ており、逆に、そのような有効なシーケンスは実際の演算のセットに対応します (c が減少する場所に応じて演算の長さを選択します)。 DP は、桁上げによる桁ごとの加算を正確にシミュレートしながら、そのような有効な表現をすべて探索するため、有効な構成を見逃したり、無効な構成を許容したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(n, k):
    digits = list(map(int, str(n)[::-1]))
    L = len(digits)

    # we allow one extra position to flush carry
    max_pos = L + 1

    # dp[pos][prev_c][carry]
    # compressed using sets per layer
    from collections import defaultdict

    dp = defaultdict(set)
    dp[(0, k, 0)] = True

    for i in range(max_pos):
        ndp = defaultdict(set)
        ni = digits[i] if i < L else 0

        for (pos, prev_c, carry) in dp:
            if pos != i:
                continue

            for ci in range(prev_c + 1):
                add = ni + 3 * ci + carry
                ndig = add % 10
                ncarry = add // 10

                if ndig > 3:
                    continue

                # enforce eventual decay: after last digit we must be able to go down to 0
                ndp[(i + 1, ci, ncarry)] = True

        dp = ndp

        if not dp:
            return False

    for (pos, prev_c, carry) in dp:
        if carry == 0 and prev_c == 0:
            return True

    return False

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        for k in range(0, 6):
            if possible(n, k):
                print(k)
                break

solve()
```この実装では、最下位側から 1 桁ずつ数値が構築されます。 状態は、現在の桁 (prev_c) にまだ「到達」している操作の数と、これまでに生成されたキャリーを追跡します。 各状態について、c[i] の考えられるすべての次の値を試します。これは前の値を超えてはならず、重複するプレフィックス操作から生じる単調構造を強制します。 

数字の制約`ndig > 3`すべての桁が {0,1,2,3} に留まらなければならないという要件にすでに違反している状態を除外します。 問題の構造により小さな答えの限界が保証されているため、k にわたるループには上限が設けられています。 

## 実用的な例

 ### 例 1

 n = 9 とします。 

k = 0 を試みますが、9 は有効ではないため、明らかに失敗します。 k = 1 の場合、単一の操作を使用してシミュレーションします。 数字 0 に 3 を加えて 12 を生成できます。その数字は 1 と 2 で、どちらも有効です。 DP は有効なパスをすぐに見つけるため、答えは 1 です。 

### 例 2

 n = 97 とします。 

k = 2 の場合、実現可能な構造の 1 つは、異なる長さの演算を使用して、高い桁ほど寄与が少なくなるようにすることです。 DP は、単位の桁からのキャリーが 10 の位を調整する構成を探索し、最終的に伝播後に両方の桁が 3 以下になる表現を生成します。 

| 数字 | n[i] | c[i] | +3c[i] | 持ち込み | 合計 | 数字 | 実行する |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 7 | 2 | 6 | 0 | 13 | 3 | 1 |
 | 1 | 9 | 1 | 3 | 1 | 13 | 3 | 1 |
 | 2 | 0 | 0 | 0 | 1 | 1 | 1 | 0 |

 このトレースは、減少する c[i] 値を選択すると、最終桁を範囲内に保ちながらキャリーを吸収できる方法を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(K・L・C・K) | 桁上の DP、状態のキャリー、および c[i] 値上の遷移 |
 | スペース | O(K・C) | 現在と次の DP レイヤーのみが保存されます。 

ここで、K は答えの小さな定数の上限 (固定限界までチェックされる)、L は桁数、C は最大 K 個の演算によって引き起こされるキャリー範囲です。 K は一定で小さいため、合計入力サイズが大きい場合でも、ソリューションは制限内で快適に実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def possible(n, k):
        digits = list(map(int, str(n)[::-1]))
        L = len(digits)
        max_pos = L + 1

        from collections import defaultdict
        dp = defaultdict(bool)
        dp[(0, k, 0)] = True

        for i in range(max_pos):
            ndp = defaultdict(bool)
            ni = digits[i] if i < L else 0

            for (pos, prev_c, carry) in dp:
                if pos != i:
                    continue
                for ci in range(prev_c + 1):
                    add = ni + 3 * ci + carry
                    ndig = add % 10
                    ncarry = add // 10
                    if ndig > 3:
                        continue
                    ndp[(i + 1, ci, ncarry)] = True
            dp = ndp

        return any(carry == 0 and prev_c == 0 for (_, prev_c, carry) in dp)

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n = int(input())
            for k in range(6):
                if possible(n, k):
                    out.append(str(k))
                    break
        return "\n".join(out)

    return solve()

assert run("1\n9\n") == "1"
assert run("1\n0\n") == "0"
assert run("1\n12\n") in {"0", "1"}
assert run("1\n999\n") >= "0"

 ## 特殊なケース

 主なエッジケースは、番号がすでに有効である場合です。 その状況では、c[i] はどこでもゼロでなければならないため、k = 0 の DP はすぐに成功し、追加値もキャリー伝播も生成されません。 アルゴリズムは、上位 k 層に入ることなく、これを正しく受け入れます。 

もう 1 つのエッジ ケースは、999 のような数字で、すべての桁がキャリー チェーンをトリガーします。 k = 1 または 2 の場合、DP は、3 で埋められたプレフィックスの単一または二重構造の加算がキャリーをどのように吸収できるかを調査します。 c[i] に対する単調制約は、上位の桁が下位の桁よりも多くの寄与を受けるという矛盾した状態を防ぐため、ここでは重要です。 

最後のエッジケースは、完全に 3 で構成される長い数字です。 これらはすでに有効であり、不必要な操作を行うと桁上げによって 3 より上の桁に押し上げられる危険があります。 DP は、k = 0 の場合にのみゼロオペレーション構成を許可し、人為的な追加が決して導入されないようにすることでこれを回避します。
