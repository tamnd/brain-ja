 ## 解決策
 ## 問題の理解

 私たちに与えられた直線的な道路は、`n`それぞれの地点は、スタートから特定のマイルマーカーにあります。 各光景には、関連付けられた美しさのスコアがあります。 ランナーは、マイル マーカーで定義された、ジョギングする道路の連続した部分を選択したいと考えています。`l`そして`r`、セグメントに少なくとも 3 つの観光スポットが含まれるようにします。 ランナーの満足度は、そのセグメント内の最も美しい 3 つの光景の合計から、セグメントの長さ (走行距離) を引いたものによって測定されます。 

タスクは、各テスト ケースについて、最適な値を選択することによって、可能な最大の満足度の値を決定することです。`[l, r]`セグメント。 入力は複数のテスト ケースで構成され、各テスト ケースには最大で`10^5`ただし、すべてのテスト ケースの合計の上限は次のとおりです。`10^5`。 

これらの制約を考慮すると、テスト ケースごとに O(n) より悪い解は遅すぎます。 すべての O(n^2) セグメントを評価する単純なアプローチは、最大 10^10 の演算が発生する可能性があるため、明らかに実行不可能です。 

エッジ ケースには、等しい美しさの値を持つ配列、最大値と最小値が交互になる配列、および 3 つの最大の美しさが端近くに位置する配列が含まれます。 たとえば、`b = [100, 1, 100, 1, 100]`、最適なセグメントには、間隔を置いて配置された 3 つの最大の美しさすべてが含まれている必要があります。 不注意なアプローチでは、ギャップを考慮せずに連続した要素のみを誤って選択してしまう可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 考えられる各セグメントについて`[l, r]`少なくとも 3 つの要素を使用して、上位 3 つの美しさの合計を計算し、減算します。`(r - l)`。 これが機能するのは、すべての有効なセグメントの満足度を直接計算するためです。 ただし、その複雑さは単純に実行した場合は O(n^3)、ソートされたセグメントを維持した場合は O(n^2 log n) であり、指定された制約に対して遅すぎます。 

重要な洞察は、この用語が`(r - l)`長いセグメントにペナルティを与えます。 重要なのは上位 3 人の美人だけなので、セグメント全体は必要ありません。 私たちは上位 3 人の美女の位置だけを気にします。 したがって、特にエッジにおいて、1 番目、2 番目、および 3 番目に大きい美しさをさまざまな組み合わせで含むセグメントを考慮できます。 実際、距離を短くするとペナルティが軽減されるため、最適なセグメントにはほとんどの場合、配列の最初または最後の要素の 1 つが含まれます。 したがって、最初近くで始まり、上位 3 人の美女で終わり近くで終わるセグメントだけを調べる必要があります。 

最初または最後の要素と最大の美しさを含む組み合わせに注意を絞ることにより、問題を配列ごとの少数の一定数の候補セグメントのチェックに減らすことができ、O(n) の解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 log n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 各テスト ケースについて、照準器の数を読み取ります。`n`そして美しさの配列`b`。 
2. もし`n`ちょうど 3 です、戻ります`sum(b) - 2`唯一の有効なセグメントは配列全体であるため、直接的に。 
3. それ以外の場合は、最初の 2 つの要素、最後の 2 つの要素、または最大の 3 つの要素を含むセグメントのみを考慮します。 これが機能するのは、距離を最小化するために最適なセグメントには少なくとも 1 つの境界が含まれている必要があるためです。 
4. 配列内の 3 つの最大の美しさの値とそのインデックスを特定します。 それらを次のように表しましょう`a1, a2, a3`ポジション付き`p1, p2, p3`。 
5. これらの最大の美しさの位置を使用して候補セグメントを生成します。 セグメントのみをチェックする`[min(p1, p2, p3), max(p1, p2, p3)]`最初または最後の光景に加えて、トップの美しさのいずれか 2 人を含むセグメント。 
6. 候補セグメントごとに、次の計算を行います。`sum(top3 in segment) - (r - l)`そして最大値を維持します。 
7. テスト ケースの最大満足度を出力します。 

重要な観察は、少なくとも 1 つの境界を含まないセグメントでは、距離のペナルティが美しさの向上を上回るため、結果がほとんど改善されないということです。 これにより、チェックするセグメントの数がテスト ケースごとに一定の数に減ります。 

機能する理由: このアルゴリズムでは、最大の 3 つの美しさと最短距離を含むすべての組み合わせが考慮されるようになります。 これらの主要な美しさの 1 つが欠けているセグメントは、3 つすべてを含むセグメントの値を超えることはできません。また、境界を含むセグメントをチェックすることで、最小距離のシナリオを確実に把握できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))
        if n == 3:
            print(sum(b) - 2)
            continue

        # Get indices of the top three beauties
        top = sorted([(val, i) for i, val in enumerate(b)], reverse=True)[:3]
        positions = [i for val, i in top]
        positions.sort()
        # The segment from min to max of top three beauties
        l, r = positions[0], positions[2]
        top_sum = sum([b[i] for i in positions])
        result = top_sum - (r - l)

        # Consider segments that include first or last element
        for start in [0, 1]:
            for end in [n-2, n-1]:
                if end - start + 1 >= 3:
                    seg = b[start:end+1]
                    seg_sum = sum(sorted(seg, reverse=True)[:3])
                    result = max(result, seg_sum - (end - start))
        print(result)

solve()
```コードはまず、次のような簡単なケースを処理します。`n = 3`。 次に、3 つの最大の美しさを特定し、それらすべてをカバーするセグメントを形成します。 次に、配列の境界にある小さなセグメントを考慮して、短い距離が見逃されないようにします。 長さ 2 ～ n のセグメントを並べ替えて上位 3 つを取得することで、正確性が保証されます。 境界チェックはオフバイワンエラーを回避し、`enumerate`正しいインデックス作成を保証します。
