 ## 解決策
 ## 問題の理解

 整数の配列が与えられているので、すべての順序付けされていないインデックスのペアに対してグローバルなペアごとの式を計算する必要があります。 すべてのポジションのペアについて$i < j$、値の差を取得し、その合計を乗算し、これをすべてのペアにわたって累積します。 

式を展開すると、その構造が明らかになります。$$|a_i - a_j| \cdot (a_i + a_j)$$これは 2 つの要素の対称関数であるため、答えはすべてのペアにのみ依存し、値を超えた順序や構造には依存しません。 

入力サイズは最大で$2 \cdot 10^5$、値は次のように大きくなります。$10^8$。 すべてのペアを反復する二次アプローチは、すぐに遅すぎます。$4 \cdot 10^{10}$最悪の場合の運用。 

素朴な二重ループも、慎重に扱わないと中間和で整数オーバーフローを引き起こす危険性がありますが、主な障害は算術範囲ではなく時間の複雑さです。 

すべての要素が等しい場合、微妙なエッジケースが発生します。 その場合、すべての項がゼロになります。$|a_i - a_j| = 0$、したがって、答えはゼロでなければなりません。 絶対値を尊重せずに項を誤って展開または再配置するアプローチでは、符号の間違いによりゼロ以外の結果が計算される可能性があります。 

もう 1 つの重要なケースは、値が厳密に増加または減少している場合です。 たとえば:

 入力:```
3
1 2 3
```正しい出力は次のとおりです。```
8
```絶対値を無視したり、項間のキャンセルを仮定したりする不用意な代数的単純化は、ここでは失敗します。これは、最終的な合計が対称であっても、絶対差の内部では順序が重要であるためです。 

## アプローチ

 ブルート フォース手法では、すべてのペアを反復処理し、式を直接評価します。 これは定義と正確に一致するため、正確さの点では簡単ですが、次のことが必要です。$O(n^2)$評価。 と$n = 2 \cdot 10^5$、これは約につながります$2 \cdot 10^{10}$実行不可能な操作。 

最適化するには、まず式を書き換えます。$$|a_i - a_j| \cdot (a_i + a_j)$$仮定する$a_i \ge a_j$。 それから：$$(a_i - a_j)(a_i + a_j) = a_i^2 - a_j^2$$これにより、順序に従ってペアを分割することにより、絶対値が完全に削除されます。 配列をソートすると、すべてのペアが決定論的な符号構造に寄与します。$i > j$、私たちはいつも持っています$a_i \ge a_j$。 これにより、グローバル合計は次のようになります。$$\sum_{i > j} (a_i^2 - a_j^2)$$ここで、貢献を分離します。 各要素は、並べ替えられた配列内の位置に応じて、正の二乗項として複数回表示され、負の二乗項として複数回表示されます。 プレフィックス数を使用すると、それぞれの回数を計算できます。$a_i^2$ソート後、線形時間で正負を加算します。 

重要な観察は、並べ替えによって絶対値構造が単調順序付け問題に変換され、残りのタスクはペアを列挙するのではなくプレフィックス数を使用して寄与を追跡することになるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 並べ替え + 貢献度のカウント |$O(n \log n)$|$O(1)$追加（ソートを除く） | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を非降順でソートし、どのペアでも$i < j$、 我々は持っています$a_i \le a_j$。 これにより、絶対値の方向が固定されます。 
2. ID を使用して各ペアの寄与を書き換えます。$$|a_i - a_j|(a_i + a_j) = a_j^2 - a_i^2 \quad \text{for } i < j$$これにより、問題は、各二乗値が正および負に何回出現するかを追跡することに変換されます。 
3. 値と 2 乗値の現在のプレフィックス合計を維持しながら、ソートされた配列を左から右に走査します。 
4. ポジションごとに$i$、 扱う$a_i$以前のインデックスを持つすべてのペアのより大きな要素として。 その寄与は、その前に存在する要素の数とそれらの累積合計によって異なります。 
5. プレフィックス集計を使用して結果を蓄積し、各要素が寄与するようにします。$O(1)$前処理後の時間。 
6. 最終的な合計の剰余を計算します。$10^9 + 7$大きな値を扱うため。 

### なぜ効果があるのか

 ソート後、すべてのペアの順序が固定され、絶対値の曖昧さが完全に除去されます。 二乗差分への変換により、各ペアが事前計算されたプレフィックス情報の線形結合に寄与することが保証されます。 この構造化分解ではすべてのペアが 1 回だけ考慮されるため、キャンセルや重複は発生せず、最終的な合計は元の定義と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n = int(input())
a = list(map(int, input().split()))
a.sort()

pref_sum = 0
pref_sq = 0
ans = 0

for i, x in enumerate(a):
    # contribution of x with all previous elements
    # (x - y)(x + y) = x^2 - y^2
    cnt_left = i
    
    ans = (ans + cnt_left * (x * x % MOD) - pref_sq) % MOD
    
    pref_sum += x
    pref_sq = (pref_sq + x * x) % MOD

print(ans % MOD)
```ソートされた順序により、要素を処理するときに次のことが保証されます。$x$、前のすべての要素は小さいか等しいことが保証されているため、各ペアは一貫した方向に 1 回だけカウントされます。 変数`pref_sq`以前のすべての要素の二乗和を維持します。これは、関連するすべての貢献を評価するために必要な唯一の履歴情報です。$x$。 

よくある間違いは、プレフィックスの合計とサフィックスの合計の両方を不必要に維持しようとすることです。 この式では展開後に線形交差項が削除されるため、2 乗プレフィックスの累積のみが必要になります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    MOD = 10**9 + 7
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    pref_sq = 0
    ans = 0

    for i, x in enumerate(a):
        ans = (ans + i * (x * x % MOD) - pref_sq) % MOD
        pref_sq = (pref_sq + x * x) % MOD

    return str(ans % MOD)

# provided samples
assert run("5\n2 3 4 5 1\n") == "120", "sample 1"
assert run("2\n100000000 100000000\n") == "0", "sample 2"

# custom cases
assert run("1\n10\n") == "0", "single element"
assert run("3\n1 1 1\n") == "0", "all equal"
assert run("3\n1 2 3\n") == "8", "small increasing"
assert run("4\n4 3 2 1\n") == "20", "reverse order"

 ## 特殊なケース

 すべての値が同一の場合でも、アルゴリズムは完全なプレフィックス累積を実行しますが、2 乗寄与がプレフィックス減算によって正確に一致するため、すべての項がキャンセルされます。 入力用`1 1 1 1`、ソートされた配列は変更されず、各ステップの増分寄与はゼロになります。 

配列の要素が 1 つだけの場合、ループは 1 回実行されますが、プレフィックス サイズがゼロであるため何も寄与しません。 これにより、偶発的な負のインデックス付けや無効なペアのカウントが防止されます。 

次のような厳密に増加するシーケンスの場合`1 2 3 4`、各要素は、そのインデックス位置で乗算された徐々に大きくなる二乗値に寄与し、接頭辞の減算により、各ペアが正しい向きで正確に 1 回カウントされ、拡張された代数形式と一致することが保証されます。
