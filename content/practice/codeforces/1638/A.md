 ## 解決策
 ## 問題の理解

 長さの順列が与えられています$n$、これは次のすべての整数を含む配列です。$1$に$n$まさに一度。 順列の連続するサブセグメントを 1 つだけ選択し、それを逆にすることができます。 目標は、この 1 回の反転を使用して、辞書編集上可能な最小の順列を生成することです。 辞書順とは、配列を左から右に要素ごとに比較し、最初に異なる場所によってどの配列が小さいかを決定することを意味します。 

たとえば、置換が与えられたとすると、`[2,1,3]`、反転`[2,1]`生成する`[1,2,3]`、オリジナルよりも小さいです。 順列がすでにソートされている場合、単一要素以外のセグメントを反転すると状態が悪化するため、最適なアクションは、長さ 1 のセグメントを反転して、実質的に配列を変更しないことです。 

制約が示すのは、$n$最大 500 個まで可能で、テスト ケースも最大 500 個まで存在できます。 これは、考えられるすべてのセグメントを試す単純な総当りアプローチを意味します。$O(n^3)$各反転の効果を要素ごとにチェックすると、最悪の場合、時間がかかりすぎます。 代わりに、効率的に逆転するのに最適なセグメントを特定する戦略が必要です。 

明らかではないエッジケースには、すでにソートされている配列、最初の要素がすでに 1 であるが残りがソートされていない配列、複数の最小要素が後で出現する可能性がある配列が含まれます。 例えば、`[1,4,2,3]`逆転しなければなりません`[4,2]`1 の直後に 2 を配置して、`[1,2,4,3]`。 不注意なアプローチでは、常に最初の要素から逆に始めようとし、小さな可能性を見逃してしまう可能性があります。 

## アプローチ

 ブルートフォース手法では、インデックスのすべてのペアを試します。$(l, r)$、そのセグメントを反転し、結果の順列を現在の最良のものと比較します。 これには、$O(n^2)$反転、それぞれのコスト$O(n)$新しい配列を構築して、$O(n^3)$。 これは小さなものでも機能します$n$しかし、それは遅すぎます$n = 500$そして500のテストケース。 

重要な点は、順列を辞書編集的に小さくするには、可能な限り小さい数値をできるだけ早く配置するように努めるべきであるということです。 順列が同一性と異なる最初の位置 (ソートされた順列) が、私たちが行動すべき場所です。 位置が最小ではない最初の要素を見つけたら、その後の最小の数値を見つけて、最初の間違った要素からその最小の数値の位置までセグメントを反転します。 これにより、辞書編集上の順序ができるだけ早く改善されることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 左から右へ順列を繰り返して最初のインデックスを見つけます。`i`どこ`p[i]`に等しくありません`i+1`。 これは、現在の順列がソート順と異なり始める位置です。 
2. そうでない場合`i`存在する場合、順列はすでにソートされています。 単一要素セグメントを反転する`[1,1]`「ちょうど 1 回の反転」要件を満たすためです。 
3. それ以外の場合は、位置を見つけます`j`で始まるサフィックス内の最小要素の`i`。 これは私たちが前に進めたい要素です`i`。 
4. サブセグメントを反転します`[i, j]`。 これにより、最小の要素が可能な限り早い位置に移動し、その後に大きな要素が押し出されます。 
5. Output the resulting permutation.

 機能する理由: 現在位置がずれている最小の要素を、並べ替えがソート順から外れる最も早いインデックスに配置することで、結果の並べ替えが辞書編集的に最小限になることが保証されます。 その他の反転では、最初の異なる位置に大きな要素を残すか、最小の要素を後で移動することになり、より悪い順列が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        
        # find first index where permutation differs from sorted
        for i in range(n):
            if p[i] != i + 1:
                break
        else:
            # already sorted, reverse a single element
            print(*p)
            continue
        
        # find the smallest element in the suffix starting at i
        j = i + p[i:].index(min(p[i:]))
        
        # reverse the segment [i,j]
        p[i:j+1] = reversed(p[i:j+1])
        
        print(*p)

if __name__ == "__main__":
    solve()
```このソリューションは、まずテスト ケースの数を読み取ります。 各テスト ケースについて、次のようになります。`n`そして順列`p`。 次に、場違いな最初の要素を特定し、その後の最小要素を見つけ、セグメントを反転してその最小要素を前方に移動し、結果の順列を出力します。 すでにソートされた配列などのエッジケースは、`else`に関する条項`for`ループ。 

## 実用的な例

 **入力:**`[3, 2, 1, 4]`| ステップ | 私 | j | 反転後の p |
 | --- | --- | --- | --- |
 | 最初の不一致を見つける | 0 | - | - |
 | サフィックスの最小値 | 2 | 2 | - |
 | 逆行する`[0,2]`| 0 | 2 |`[1,2,3,4]`|

 これは、最小セグメントを反転すると、辞書編集上の可能な限り最も早い改善が得られることを示しています。 

**入力：**`[1, 4, 2, 3]`| ステップ | 私 | j | 反転後の p |
 | --- | --- | --- | --- |
 | 最初の不一致 | 1 | - | - |
 | サフィックスの最小値 | 2 | 2 | - |
 | 逆行する`[1,2]`| 1 | 2 |`[1,2,4,3]`|

 このアルゴリズムは、最も初期の場違い要素 (4) を特定し、その後の最小要素 (2) を反転によって前方に移動します。

 ## 特殊なケース

 長さ 1 のような順列の場合`[1]`、アルゴリズムは、場違いな要素がないことを特定し、単に出力します。`[1]`。 すでにソートされている順列の場合、次のようになります。`[1,2,3,4,5]`、`for`ループは中断されることなく終了し、`else`句により、長さ 1 のセグメントが反転され、順列は変更されません。 最小の数値が中央にある順列の場合、次のようになります。`[1,3,4,2]`、アルゴリズムは最初の不一致を正確に識別します (`3`インデックス 1) で、サフィックス (`2`インデックス 3) で、反転します`[1,3]`、生産`[1,2,4,3]`。 これにより、アルゴリズムがすべての重要なエッジケースを正しく処理していることが確認されます。
