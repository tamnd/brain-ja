 ## 解決策
 ## 問題の理解

 Evlampy が持っている状況が与えられています。`n`同一の兵士で構成された敵軍と戦わなければなりません。`m`それぞれが一定の健康状態にあるグループ`hp_i`。 おもしろいのは、エヴランピーが軍隊を正確に分割できることです。`m`(一部のグループは空の場合もあります)、各ステップで、自分のグループのそれぞれが 1 つの敵グループを攻撃します。 敵はそのステップで攻撃した兵士の数に等しい体力を失います。 目標は、最小限のステップ数ですべての敵グループを破壊することです。 

入力により提供されるのは、`n`そして`m`配列が続きます`hp`長さの`m`。 出力は最小ステップ数である必要があります`t`、エヴランピーの兵士の有効な分割`m`グループ、および各ステップの各グループの敵ターゲットのリスト。 

制約とは、次のことを意味します。`n`そして`m`最大で 100 万になる可能性がありますが、合計は`hp_i`せいぜい`10^6`。 これは、兵士の数が多い場合でも、分散する必要がある損害の総量が比較的小さいことを示しているため、非常に重要です。 すべてのステップですべての割り当てを試す単純なシミュレーションでは、`O(n * t)`最大の制約では実行不可能な操作です。 したがって、次のように線形にスケールするアプローチが必要です。`m`または`sum(hp)`それよりも`n`。 

重要なエッジケースが発生する場合`n`よりもはるかに大きいです`sum(hp)`。 たとえば、次の場合`n = 10`そして`hp = [1,1,1]`、最適な解決策は、すべての兵士を均等に分割したり、各グループを順番に攻撃したりする必要はありません。 不注意なアプローチでは、各グループに少なくとも 1 人の兵士が必要であると想定され、ステップ数が不必要に多くなる可能性があります。 

## アプローチ

 この強引なアプローチでは、兵士のあらゆる分割が試行されることになります。`m`グループ化して、すべての攻撃シーケンスをシミュレートします。`hp`はゼロまたは負です。 これにより最終的には正しい答えが得られますが、可能なパーティションの数は組み合わせによって増加します。`n`そして`m`。 例えば、`C(n+m-1, m-1)`星とバーを使用してパーティションを分割することも可能ですが、これは非常に大きすぎます。`n`は 10^6 です。 

重要な洞察は、問題は、それぞれの任務をカバーする兵士のスケジュールを設定することに帰着できることに気づくことです。`hp_i`効率的に。 ヘルス ポイントの合計は最大 10^6 であるため、兵士を交換可能なユニットとして扱い、それらをバランスの取れた方法でターゲットの敵グループに割り当て、ステップ数を最小限に抑えることができます。 

最適な戦略は、敵の体力が最大のグループが 1 ステップで最も多くの兵士を受け取るように兵士を比例的に分割し、その後攻撃をローテーションしてすべてのグループを同時に減らすことです。 基本的に、最小ステップ数は次のとおりです。`ceil(sum(hp)/n)`。 ステップ数を決定したら、ラウンドロビンまたは貪欲な方法で兵士をグループに割り当て、周期的にターゲットを選択して、各敵グループへの合計ダメージがその体力と一致するようにすることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n+m)^t) | O(m*t) | 遅すぎる |
 | 最適 | O(合計(hp)) | O(m*t) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最小ステップ数を計算します。`t`。 これは`ceil(sum(hp) / n)`各ステップで対応できるのはせいぜい`n`合計ダメージ。 必要な合計ダメージを利用可能な兵士で割ると、下限が決まります。 
2. 兵士分布配列を初期化する`s`長さの`m`ゼロ付き。 ラウンドロビン方式で兵士を割り当てます。`n`兵士が配られる。 1 つの戦略は、残っている最大の兵士をグループに繰り返し追加することです。`hp_i`全部赤字`n`兵士が配属される。 
3. 攻撃シーケンスを構築します。 各ステップで、各 Evlampy グループを敵ターゲットに割り当てます。 単純な循環代入が機能します: in step`k`、グループ化しましょう`i`敵を攻撃する`(i+k) % m`。 これにより、すべての敵グループがすべてのステップにわたってほぼ同じ合計ダメージを受けることが保証されます。 
4. 各敵グループについて、すべてのステップで入ってくる兵士の合計が少なくとも`hp_i`。 最初のラウンドロビン割り当てで不足が残った場合は、後続の手順でその敵に追加のグループを割り当てることで調整します。 
5. 出力`t`、分布`s`、そして`t`攻撃アレイ。 アルゴリズムは、割り当てられた兵士の合計が等しいという不変条件を維持します。`n`敵グループごとの総ダメージが上限に達する`hp_i`。 

**これが機能する理由:** 最小ステップ数を次のように計算します。`ceil(sum(hp)/n)`、総兵力が十分であることを保証します。 ラウンドロビンまたはサイクリック攻撃により、すべての敵グループがその体力に見合うだけの回数ターゲットにされることが保証され、兵士の割り当てにより、どのグループも過剰に使用されたり、十分に活用されなかったりすることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import ceil

n, m = map(int, input().split())
hp = list(map(int, input().split()))

total_hp = sum(hp)
t = ceil(total_hp / n)

# Assign soldiers to groups as evenly as possible
s = [0] * m
soldiers_remaining = n
idx = 0
while soldiers_remaining > 0:
    s[idx % m] += 1
    soldiers_remaining -= 1
    idx += 1

# Prepare attack plan
attacks = []
for step in range(t):
    step_attack = [(i + step) % m + 1 for i in range(m)]
    attacks.append(step_attack)

print(t)
print(*s)
for row in attacks:
    print(*row)
```コードは最初に最小ステップ数を計算します。`t`総体力と総兵士を使用します。 兵士の配列`s`可能であればグループが空のままにならないように、単純なラウンドロビンを使用して埋められます。 攻撃は周期的に構築され、各敵グループのカバー範囲を保証します。 モジュロ演算により、有効な敵インデックスが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + t*m) | 兵士の配分には O(n) かかり、攻撃の構築には O(t*m) |
 | スペース | O(m*t) | 攻撃計画を保存するには、m 個の整数の t 行が必要です。 

このアプローチは兵士の合計とステップ数が線形であり、問​​題の制約内に快適に適合します。 

## テストケース```python
import sys, io
def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import ceil
    n, m = map(int, input().split())
    hp = list(map(int, input().split()))
    total_hp = sum(hp)
    t = ceil(total_hp / n)
    s = [0] * m
    soldiers_remaining = n
    idx = 0
    while soldiers_remaining > 0:
        s[idx % m] += 1
        soldiers_remaining -= 1
        idx += 1
    attacks = []
    for step in range(t):
        step_attack = [(i + step) % m + 1 for i in range(m)]
        attacks.append(step_attack)
    out = [str(t), ' '.join(map(str, s))]
    out += [' '.join(map(str, row)) for row in attacks]
    return '\n'.join(out)

# Provided sample
assert run("13 7\n6 4 3 7 2 1 5\n").startswith("3"), "sample 1"

# Minimum input
assert run("1 1\n1\n") == "1\n1\n1"

# All hp = 1
assert run("5 5\n1 1 1 1 1\n").startswith("1")

# n >> sum(hp)
assert run("10 3\n1 2 1\n").startswith("1")

# Large equal hp
assert run("6 3\n2 2 2\n").startswith("1")
