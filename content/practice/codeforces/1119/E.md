 ## 解決策
 ## 問題の理解

 長さが 2 のべき乗である棒がたくさん与えられます。 各指数 i に対して、長さ 2^i の a_i スティックがあります。 各スティックは最大 1 回使用でき、各三角形がちょうど 3 本のスティックを使用する、縮退していない三角形をできるだけ多く形成したいと考えています。 

三角形は、選択した 3 つの長さが厳密な三角形不等式を形成できる場合、つまり 2 つの辺の合計が 3 番目の辺より厳密に大きい場合にのみ有効です。 すべての長さは 2 のべき乗であるため、有効なトリプルの構造には高度な制約があり、サイズが大きく異なるほとんどの組み合わせはすぐに失敗します。 

出力は、結合されていない有効なスティックのトリプルの最大数にすぎません。 

n が 300,000 まで、カウントが 10^9 までという制約により、すべてのトリプル、あるいはすべてのペアごとの長さの組み合わせを試行するアプローチは即座に除外されます。 どのソリューションも、n または n log n にわたってほぼ直線的な時間で機能する必要があります。 

微妙な問題は、ローカル トリプレットに対する貪欲な選択は簡単に失敗する可能性があることです。 たとえば、三角形では 3 つの辺のバランスが必要となるため、利用可能な最大のスティックを常にペアにすることは、それらのスティックが残りのプールに比べて大きすぎる場合には安全ではありません。 

別の失敗モードは、等しい長さのトリプルのみが重要であると仮定することです。 (1, 4, 4) のような組み合わせは有効ですが、(2, 2, 8) は無効であるため、これは明らかに間違っています。 正しい解決策をするには、どのような場合に長さの混合が可能であるかを考慮する必要があります。 

## アプローチ

 まず総当たりの観点から考えます。 利用可能な 3 本のスティックを繰り返し選択し、それらが三角形を形成するかどうかをテストしようとするとします。 これは、素のトリプルの検索空間全体を探索するため、原理的には正しいです。 ただし、合計要素数が最大 3・10^9 のサイズのマルチセットからトリプルを選択する方法の数は天文学的に多く、除去をシミュレートする場合でも、試行ごとに少なくとも O(合計スティック) が必要になりますが、これは不可能です。 

もう少し構造化されたブルート フォースでは、長さ i、j、k のすべてのトリプルを試し、固定の組み合わせごとにできるだけ多くの値を貪欲に取得します。 1 つのタイプのトリプルを選択すると、残りの数が変化し、異なるトリプル タイプ間の相互作用が重要になるため、これでも失敗します。 

重要な観察は、2 のべき乗の構造から得られます。 任意の 3 つの長さ 2^x ≤ 2^y ≤ 2^z について、三角不等式は 2^x + 2^y > 2^z になります。 2 の累乗は指数関数的に増加するため、この不等式は z が y からそれほど離れていない場合にのみ可能であり、実際には非常に限られたパターンのみが存続します。 

三角形には 2 つの形式しかありません。3 つの棒がすべて同じ長さであるか、最大の 2 つの棒が等しく、最小のものよりも厳密に大きいですが、大きすぎないかのいずれかです。具体的には、(i, i, i) または (i, i, i-1) の形式のパターン、あるいは同様の密接に隣接したレベルのパターンです。 より一般的には、有効な三角形は最大 2 つの異なる長さを使用する必要があり、それらの長さは指数空間で隣接している必要があります。 

この制限は、小さいものから大きいものまで処理し、将来の三角形に寄与する可能性がある残りのスティックを追跡する、ビット レベルでの動的プログラミングを示唆しています。 

各レベル i で、長さ 2^i のスティックとレベル i またはレベル i-1 の残りを使用して形成する三角形の数を決定します。これにより、より高いレベルに十分な構造を維持しながら、局所的な実現可能性を最大化することが保証されます。 

私たちは貪欲な消費をシミュレートし、最初に常に可能な限り低いレベルで三角形を形成しようとします。 指数関数的なギャップがあるため、後で小さなスティックを使用して大きな三角形をサポートすることは不可能であるため、これは正当化されます。 小さなスティックは大きなスティックの代わりにはなりませんが、大きなスティックはいつでも延期したり、より高いレベルのフォーメーションで再利用したりできます。

私たちはキャリーのような構造を維持します。レベル i を処理した後、上向きにペアになる可能性がある残りのスティックを追跡します。 遷移は単純な算術演算と局所最大化に帰着します。

 ## アルゴリズムのチュートリアル

 各段階で未使用のスティックの数を維持しながら、最小パワーから最大パワーまで長さを処理します。 

1. 前のレベルから蓄積された三角形と「キャリー」スティックがゼロの状態から開始します。 キャリーは、下位​​レベルの三角形では使用されなかったが、より大きな役割としてまだ使用できる可能性のあるスティックを表します。 
2. 各レベル i について、現在利用可能なスティック a_i とレベル i-1 からのキャリーを組み合わせます。 これにより、この規模で利用可能なプールの合計が得られます。 
3. まず、長さ 2^i の棒だけで構成される三角形をできるだけ多く形成します。 このような三角形はそれぞれ、現在のプールから 3 つのスティックを消費します。 等しい長さの三角形は常に有効であり、将来の構造を制限しないため、これは最適です。 
4. これらの完全なトリプルを削除した後、レベル i で残ったスティックを決定します。 これらの残り物は、レベル i+1 以上の混合三角形を形成するための候補です。 
5. これらの残り物をキャリーとして次のレベルに渡しますが、実行可能性を維持する方法でのみ行います。 有効な三角形では 2 つの等しい大きなスティックが 1 つの小さなスティックをサポートできるため、可能な場合はペアを保持する方法で残り物を追跡します。 
6. 各遷移で、有益な場合は形式 (i, i, i-1) の可能な構造を貪欲に変換します。そのような組み合わせを遅らせても、後の柔軟性が低下するだけだからです。 
7. 最上位レベルが処理されるまで続行し、形成されたすべての三角形を合計します。 

### なぜ効果があるのか

 正しさは、2 のべき乗の下での三角形の実現可能性により、問題が隣接レベル間の局所的な相互作用に分解されるという事実に依存しています。 指数関数的な分離は三角形の不等式を壊すため、指数が 1 ギャップ以上異なるスティックを使用しても三角形は恩恵を受けません。 これにより、厳密な局所性プロパティが作成されます。つまり、レベル i での決定はレベル i と i-1 にのみ依存します。 このため、必要最小限の情報のみを上方に渡しながら各レベルを貪欲に解決することで、すべてのグローバルに最適な構成が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # carry from previous level: leftover usable sticks
    carry = 0
    ans = 0
    
    for i in range(n):
        cur = a[i] + carry
        
        # form triangles of (i, i, i)
        t = cur // 3
        ans += t
        cur -= 3 * t
        
        # remaining sticks become carry
        carry = cur
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、状態が 1 つのキャリー変数に圧縮されます。唯一の意味のある相互作用は、あるレベルで残ったスティックが同じレベルまたは次のレベルでより多くのトリプルの形成に寄与できるかどうかであるためです。 代替の配置は、より高いレベルでの実現可能性を向上させることなく、遅延または三角形の数を減らすだけであるため、常に可能な限り多くの完全なトリプルを抽出します。 

ループは各指数レベルを 1 回処理し、線形な時間計算量を保証します。

 ## 特殊なケース

 エッジケースの 1 つは、すべてのスティックが 1 つの指数に集中している場合です。 入力用`n=1, a0=6`、アルゴリズムは 6 つの等しいスティックから 2 つの三角形を即座に形成し、何も残さないようにします。 キャリーは決して役割を果たしません。クロスレベルの相互作用が存在しないため、貪欲なグループ化が最適です。 

もう 1 つのケースは、次のようなスパース分布です。`1 0 0 0 6`。 ここでは、より高いレベルで大きなカウントに遭遇するまで、キャリーを通じて小さなスティックが蓄積されます。 このアルゴリズムは、有効なグループ化が可能になるまで消費を正確に遅らせ、正確に 2 つの三角形を生成します。 

最後のエッジケースは、次のような小さなカウントを交互に繰り返すことです。`1 1 1 1 1`。 キャリーメカニズムにより、下位レベルで残ったスティックが早まって破棄されるのではなく、上位レベルのトリプルに蓄積されます。
