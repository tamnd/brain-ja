 ## 解決策
 ## 問題の理解

 2 つの整数が与えられます。`s`そして`k`。 課題は表現すること`s`から取得した個別の数値の合計として`k`-ボナッチシーケンス。 

この数列はフィボナッチのように動作しますが、前の 2 つの値を合計するのではなく、各項は前の値の合計になります。`k`条項。 始まりは特別です。 最初`k - 1`条件は`0`、`k`-番目の用語は`1`、以降のすべての値は前の値から構築されます。`k`価値観。 

たとえば、次のようなとき`k = 2`、シーケンスは次のようになります。```
0, 1, 1, 2, 3, 5, 8, ...
```いつ`k = 3`、次のようになります。```
0, 0, 1, 1, 2, 4, 7, 13, ...
```合計が等しい少なくとも 2 つの異なるシーケンス値を出力する必要があります。`s`。 

制約は一見すると大きいです。 両方`s`そして`k`到達できる`10^9`。 これにより、以下に直接依存するアプローチは除外されます。`k`サイズ調整された配列または動的プログラミング`s`。 重要な観察は、最初の数項の後に数列が指数関数的に増加することです。 小さいものでも`k`、以下の生成された値の数`10^9`これは、生成されたシーケンスに対して貪欲な処理を行う余裕があることを意味します。 

微妙な点は、シーケンスの先頭に多くのゼロが存在することです。 この問題では、個別の位置ではなく、個別の数値が必要です。 つまり、シーケンスにゼロがたくさん含まれている場合でも、複数のゼロを使用することはできません。 不用意に実装すると 2 つのゼロが出力される可能性があり、これは区別性に違反します。 

次の入力を考えてみましょう。```
1 3
```シーケンスは次のように始まります。```
0, 0, 1, 1, 2, ...
```間違った解決策では、次のことが試行される可能性があります。```
0 0 1
```しかし、数字は区別できません。 有効な答えは次のとおりです。```
0 1
```貪欲な選択を使用する場合、もう 1 つの簡単な間違いが発生します。 使用可能な最大値を貪欲に取得し、残りの合計がゼロになったときに停止すると、選択される数値は 1 つだけになる可能性があります。 この問題には少なくとも 2 つの数値が明示的に必要です。 

例えば：```
5 2
```以来`5`それ自体はフィボナッチ数であり、単純な貪欲は次のように与えます。```
5
```それは無効です。 次のようなものが必要です。```
0 2 3
```余分なゼロは、少なくとも 2 つの異なる数値を保証するためにこの問題で使用される標準的なトリックです。 

## アプローチ

 強引なアイデアは、すべてを生成することです。`k`-ボナッチ数まで`s`次に、すべてのサブセットを試して、一部のサブセットの合計が以下になるかどうかを確認します。`s`。 

これは、生成される用語の数がかなり少ないため機能します。 フィボナッチ数さえも超える`10^9`約45期を経て。 しかし、サブセットの列挙は依然として実行不可能になります。 使用可能な番号は約 45 個で、サブセットの数は約 45 個になります。`2^45`、2秒以内では全く不可能です。 

シーケンス構造により、より強力なプロパティが得られます。 すべての項は、フィボナッチ表現やゼッケンドルフ表現と同様に、十分に小さい使用可能なすべての項の合計よりも大きくなります。 これは、最大のものを繰り返し取るという貪欲な戦略が機能することを意味します。`k`-ボナッチ数が残りの値を超えないこと。 

なぜここで貪欲が可能になるのでしょうか？ 

反復により、シーケンスは初期フェーズの後に単調に増加します。 さらに重要なのは、すべての数値は前の数値の合計です。`k`したがって、利用可能な最大値を採用すると、将来の構築を妨げることなく、残りのターゲットをできるだけ多く削除できます。 貪欲なフィボナッチ分解の背後にある同じロジックは、自然に次のように拡張されます。`k`-ボナッチ数。 

残りの問題は、少なくとも 2 つの異なる番号が必要であることです。 貪欲に数値が 1 つだけ生成される場合、それは正確に一致する必要があります。`s`自体。 その場合は単に追加するだけです`0`、これは常に利用可能であり、あらゆる正の数とは区別されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m) | O(m) | 遅すぎる |
 | 最適 | O(㎡) | O(m) | 承認済み |

 ここ`m`生成された数です`k`-ボナッチ数まで`s`、実際には非常に小さいです。 

## アルゴリズムのチュートリアル

 1. すべての明確なポジティブを生成する`k`-ボナッチ数まで`s`。 

シーケンスは次から始まります`k - 1`ゼロと1`1`。 次の値はすべて、前の値の合計と等しくなります。`k`価値観。 私たちが気にするのは以下の値までです`s`なぜなら、それより大きな数は決して分解に参加できないからです。 
2. 生成された値を昇順に保存します。 

シーケンスは最初の重複の後に厳密に増加するため、最大から最小への貪欲な処理は簡単です。 
3. から始める`remaining = s`。 

可能な最大の未使用値を繰り返し減算します。 
4. 生成された数値を逆順に調べます。 

数値が最大でも`remaining`、それを答えに含めてから差し引きます`remaining`。 

これは標準的な貪欲なサブセット構築です。 シーケンスは急速に増大するため、可能な最大値を選択しても完了が妨げられることはありません。 
5. まで続けます`remaining`ゼロになります。 

この時点で、選択した数値の合計は正確に次のようになります。`s`。 
6. 答えに数字が 1 つだけ含まれている場合は、`0`。 

これは、次のような場合に対処します。`s`それ自体は`k`-ボナッチ番号。 この問題には少なくとも 2 つの異なる数値が必要です。`0`は常に、選択された正の値とは異なります。 
7. 回答のサイズと数値を印刷します。 

### なぜ効果があるのか

 重要な特性は、すべての`k`-bonacci 数値は前の値の合計に等しい`k`数字。 この成長構造により、選択した項よりも小さい残りの値は、より小さい項を使用して表すことができます。 貪欲な人は決して不可能な剰余を生み出すことはありません。 

すべてのステップで、アルゴリズムは、現在の剰余がより小さい未使用のシーケンス値を使用して表現できるという不変条件を維持します。 最大の有効な項を選択すると、表現可能性を維持しながら、可能な限り積極的に剰余が削減されます。 

最終調整は`0`ゼロを追加しても合計は変化せず、ゼロはすべての正の数とは異なるため、正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s, k = map(int, input().split())

    # Build sequence:
    # [0, 0, ..., 0, 1]
    seq = [0] * (k - 1) + [1]

    window_sum = 1

    while True:
        nxt = window_sum

        if nxt > s:
            break

        seq.append(nxt)

        window_sum += nxt
        window_sum -= seq[-k - 1]

    # Keep only distinct positive values
    vals = sorted(set(x for x in seq if x > 0))

    ans = []
    rem = s

    for x in reversed(vals):
        if x <= rem:
            ans.append(x)
            rem -= x

    # Need at least two distinct numbers
    if len(ans) == 1:
        ans.append(0)

    print(len(ans))
    print(*sorted(ans))

if __name__ == "__main__":
    solve()
```シーケンスの生成にはスライディング ウィンドウの合計が使用されます。 新しい各項を前の項から直接計算する`k`要素にはコストがかかります`O(k)`ステップごとに、次の場合に危険になります。`k`大きいです。 代わりに、現在のウィンドウ合計を増分的に維持します。 

現在のウィンドウに最後のウィンドウが含まれているとします。`k`シーケンス値。 次のシーケンス要素はまさにその合計です。 新しい値を追加した後、新しい用語を追加し、最も古い用語を削除することによってウィンドウを更新します。 

表現:```
window_sum -= seq[-k - 1]
```間違いやすいです。 新しい値を追加した後、ウィンドウから出る要素は正確に`k + 1`端からの位置。 

初期シーケンスには多くの重複、特にゼロ、場合によっては重複が含まれます。 この問題では個別の数値が要求されるため、貪欲な選択の前に正の値を明示的に重複排除します。 

貪欲フェーズでは、最大値から最小値の順に数値が処理されます。 シーケンスのサイズが小さいため、単純な逆走査で十分です。 

決勝戦`0`挿入は、無効な 1 要素の回答を避けるための小さいですが重要な詳細です。

import sys
import io

def solve():
    input = sys.stdin.readline

    s, k = map(int, input().split())

    seq = [0] * (k - 1) + [1]
    window_sum = 1

    while True:
        nxt = window_sum

        if nxt > s:
            break

        seq.append(nxt)

        window_sum += nxt
        window_sum -= seq[-k - 1]

    vals = sorted(set(x for x in seq if x > 0))

    ans = []
    rem = s

    for x in reversed(vals):
        if x <= rem:
            ans.append(x)
            rem -= x

    if len(ans) == 1:
        ans.append(0)

    ans.sort()

    print(len(ans))
    print(*ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# large k, slow sequence growth
assert run("2 100\n") == "2\n0 2\n"

# exact k-bonacci number
