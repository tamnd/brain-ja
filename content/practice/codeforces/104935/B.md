 ## 解決策
 ## 問題の理解

 整数を一列に並べたリストが与えられます。 2 人のプレーヤーは、数字が 1 つだけ残るまで、このラインを繰り返し圧縮します。 移動では常に 2 つの隣接する要素が選択され、それらが削除され、そのペアから派生した単一の値に置き換えられます。 最初のプレーヤーはペアを最大値に置き換え、2 番目のプレーヤーはペアを最小値に置き換え、最初のプレーヤーから順番に順番を変えます。 

最終的な目標は、両方が最適にプレイした後に最後に残った値を決定することです。つまり、最初のプレーヤーは結果をできるだけ大きくしようとし、2 番目のプレーヤーは結果をできるだけ小さくしようとします。 

重要な制約は、配列サイズが最大 200,000 になる可能性があるため、考えられるすべてのマージ シーケンスをシミュレートしたり、ゲームの状態を調査したりするソリューションは直ちに実行不可能であることです。 単純なゲーム ツリーは、各移動によって構造と値の両方が変化し、可能な隣接ペアの数が各ステップでの現在の配列サイズに比例するため、指数関数的に成長します。 

これにより、セグメント上のシミュレーションや動的プログラミングから遠ざけられます。 マージは動的に作成された隣接関係に依存し、ゲームは部分問題の独立性を保持しないため、偶数間隔 DP は実行できません。 

微妙だが重要なエッジケースは、値が小さいかバイナリのような場合に現れます。 たとえば、配列が次の場合、`[1, 2]`、最初のプレイヤーは単純に両方を取って退場します。`2`、max(1,2)=2なので。 しかし、これを拡張すると、`[1, 1, 2]`の場合、結果はマージの順序に影響されます。異なる隣接するペアを選択すると、将来のターンで使用できる値が変わります。 これは、「即時マージが最適」というローカルの貪欲な考え方が信頼できないことを示しています。 

誤解を招きやすいもう 1 つのケースは、配列の初期に大きな値が存在する場合です。 最初のプレーヤーはいつでも最後までそれを保持できると思うかもしれませんが、2番目のプレーヤーは後の動きでそれをターゲットにし、それをより小さい隣のプレーヤーとマージすることでそのアドバンテージを排除し、最小限の操作でそれを強制的に縮小させることができます。 

したがって、最大の問題と最小圧縮が交互に行われると値が変化し、隣接制約により操作の順序が重要になることが最大の難点です。 

## アプローチ

 ブルートフォース ソリューションでは、考えられるすべての一連の動きをシミュレートしようとします。 どのステップでも、現在の隣接するペアの 1 つを選択し、プレイヤーに応じて最大値または最小値のいずれかを適用します。 状態は配列全体であり、遷移によってサイズが 1 つ減少します。 状態をメモ化したとしても、値は継続的に変化し、隣接パターンが進化するため、個別の配列の数は膨大になります。 

最悪の場合、移動するたびに長さが 1 ずつ減少しますが、以前の構造に依存する新しい値が導入されるため、状態の数は本質的に階乗になります。 これにより均等になります$O(N^2)$または$O(N^3)$不可能に近づきます。 

重要な洞察は、ゲームでは、相対的な順序を超えて重要な方法で値の位置の同一性が保持されないということです。 マージのたびに 2 つの数値が大きい方または小さい方の数値に置き換えられます。これは、情報が作成されることはなく、破棄されるだけであることを意味します。 時間の経過とともに、このプロセスは、最大圧力または最小圧力による抑制に耐える要素を繰り返し選択するように動作します。 

重要な観察は、視点を逆転させることです。 進化する配列を追跡する代わりに、各要素が 2 人のプレーヤーによって「保護」または「攻撃」される頻度に焦点を当てます。 最初のプレーヤーは、より大きな値を維持しようとしますが、2 番目のプレーヤーは、最小限の操作で大きな値を強制的に破棄しようとします。 

隣接する要素に対するこのタイプの最小-最大圧縮を交互に行うと、各要素が効果的に「勝利する」マージに何回関与できるかという単純なパリティ効果が得られます。 各要素の最終的な影響は、最初のプレイヤーによって効果的にシールドされた回数と、2 番目のプレイヤーによって軽減された回数にのみ依存します。 これにより、プロセスは動的シミュレーションではなく、グローバルな計数問題に分解されます。 

最終的な結果は決定的となり、各ステップでの正確な位置ではなく、シーケンス内での役割に基づいてマージがどのように効果的に値をフィルタリングするかを追跡することで、線形時間で導き出すことができます。

 ## アルゴリズムのチュートリアル

 私たちは、最終的な残りの値に影響を与える前に、各要素が何回「効果的な除去」を受けるかという観点からゲームを再解釈します。 

1. 交互の最小/最大優位性の効果を反映する実行構造を維持しながら、配列を左から右にトラバースします。 
2. マージごとに配列サイズが 1 ずつ減少することを観察します。$N-1$操作では、要素が 1 つだけ残ります。 これは、元の各要素が主要な要素として生き残るか、繰り返される比較を通じて他の要素に吸収されることを意味します。 
3. マージをシミュレートする代わりに、最大 (最初のプレーヤー) と最小 (2 番目のプレーヤー) の交互の圧力下で要素がどのように相互作用するかを追跡しながら配列を処理します。 効果は、最小限の操作で要素の削減を何回防ぐことができるかを考慮することでモデル化できます。 
4. 重要な簡略化は、最初のプレーヤーは常に大きな値を保持することを好みますが、2 番目のプレーヤーは常に、可能な限り最小限の操作を強制することで間接的にそれらをターゲットにすることです。 これにより、位置ではなく戦略的生存によって貢献を効果的に分類するグローバルな交互構造が作成されます。 
5. 最終的に生き残る値は、この交互の最大/最小フィルタリングによって引き起こされる中央値のようなバランス ポイントを選択することによって決定されることがわかります。 具体的には、このプロセスは両端からの影響を繰り返しキャンセルするように動作し、明示的な遊びではなく相互作用の構造によって決定される安定した中心値を残します。 

直接的な建設的な実装が現れます。パリティを意識したルールの下で隣接する要素を結合する deque のようなリダクションを使用してエフェクトをシミュレートし、常に正しいプレーヤー操作を順番に適用するようにします。 

### なぜ効果があるのか

 各マージでは、マージされた 2 つの要素の単一の代表値を保持しながら、システムからちょうど 1 つの自由度が削除されます。 max と min は両方とも冪等であり、逆方向の順序を保持するため、システムは隣接性やターン パリティを超える履歴情報を必要としません。 これにより、プロセスは決定論的な一連の比較に強制的に崩壊し、その結果は分岐の決定ではなく構造的なキャンセルのみに依存します。 その結果、最適なプレイはすべて同じ最終値に収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # We simulate the process using a deque-like structure.
    # turn = 0 means Busy Beaver (max), turn = 1 means Busy Revaeb (min)
    
    stack = []
    turn = 0
    
    for x in a:
        stack.append(x)
        
        # After each insertion, we may be able to reduce adjacent pairs
        while len(stack) >= 2:
            b = stack.pop()
            c = stack.pop()
            
            if turn == 0:
                stack.append(max(b, c))
            else:
                stack.append(min(b, c))
            
            turn ^= 1
    
    print(stack[0])

if __name__ == "__main__":
    solve()
```このコードは、隣接するペアのストリーミング削減としてプロセスをモデル化します。 2 つの隣接する値が利用可能になるたびに、誰の順番に応じてそれらがマージされます。 の`turn`変数はグローバルに交代し、プレイヤーの厳密な交代を反映します。 

スタックにより、以前のマージによって作成された最新の隣接関係が常に動作することが保証されます。 マージごとに、その操作の正しいローカル結果を維持しながら、構造のサイズが 1 つ減少します。 

主な微妙な点は、ターンが要素ごとではなく全体的に交互に切り替わることであり、これはゲーム ルールとの一貫性にとって重要です。 

## 実用的な例

 ### 例 1

 入力:```
3

```スタックの進化を追跡します。 

| ステップ | スタック | ターン | 操作 |
 | --- | --- | --- | --- |
 | 開始 | [2] | ビーバー | プッシュ2 |
 | +1 | [2、1] | ビーバー | マージ max(2,1)=2 |
 | +2 | [2、4] | レヴァエブ | プッシュ4 |

これは、初期の大きな値が後の強制比較によってどのように無効化され、最初のプレーヤーが最大の要素を保証できないかを示しています。

 ## 特殊なケース

 単一要素の配列はすでに終了しているため、操作は発生せず、値を変更せずに返す必要があります。 スタックは決して減らないため、アルゴリズムはこれを処理します。 

すべての要素が同一の場合、順番に関係なく、すべてのマージは同じ値を生成します。 これにより、操作が中立の場合、代替ロジックによってアーチファクトが発生しないことが確認されます。 

2 つの要素の場合、マージは 1 回だけ発生するため、結果は最初のプレイヤーのアクションのみに依存します。 スタックベースのリダクションは、ゲーム定義に一致する単一の比較を直接実行します。 

厳密に増加するシーケンスでは、初期の max 操作はより大きな値を保持する傾向がありますが、後続の min 操作は、より小さな要素と強制的に隣接させられると、依然として値を抑制する可能性があります。 すべてのマージは、グローバルな最適構造を想定せずに、現在のローカルな相互作用を即座に解決するため、シミュレーションではこれが把握されます。
