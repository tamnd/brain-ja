 ## 問題の理解

 各テスト ケースにはバイナリ文字列が与えられます。各位置は、Busy Beaver (1) または Lazy Lemur (0) をサポートする都市を表します。 この配列を正確に分割することができます。$K$連続する空でないセグメントであり、各セグメントは地区とみなされます。 地区内の 1 の数が 0 の数より厳密に大きい場合、その地区は「勝利」したとみなされます。 

あらゆる人にとって$K$1から$N$、パーティションを選択する必要があります$K$セグメントのうち、厳密に大部分が 1 であるセグメントの数を最大化し、その最大値を出力します。 

重要な問題は、パーティション分割がそれぞれ異なることです。$K$そして、固定パーティション化を評価しているのではなく、配列をカットするすべての可能な方法を最適化しています。 

制約が意味するのは、$N$まで可能です$10^5$テストケースごと、合計$N$テスト全体でも$10^5$。 これにより、すべてのパーティションを明示的に試行するソリューションは除外されます。これは、分割する方法が多数あるためです。$K$セグメントは指数関数的です$N$そして、すべてのカット位置にわたる動的計画法でさえ、少なくとも二次的な動作につながるでしょう。 

テスト ケースごとに線形またはほぼ線形のソリューションが必要になる可能性があります。$O(N \log N)$または$O(N)$。 

いくつかの微妙な特殊なケースがすぐに現れます。 配列にゼロのみが含まれている場合、セグメントの厳密な過半数が 1 になることはありえないため、すべての答えはゼロになります。 配列がすべて 1 の場合、分割方法に関係なく、すべてのセグメントが自動的に優先されます。$K$、答えはまさにそのとおりです$K$。 グローバル構造を考慮せずにローカル セグメントを最大化しようとする素朴な貪欲なアプローチは、次のような小さな混合パターンでも失敗します。`11010`、時期尚早にカットすると、後のセグメントを改善する可能性のあるマージが破壊される可能性があります。 

## アプローチ

 まず総当たり戦略を考えます。 固定の場合$K$、あらゆる配置方法を試すことができます$K-1$間のカットポイント$N-1$ギャップを調べ、各セグメントのバランスを計算し、勝っているセグメントの数を数えます。 これは問題を正しくモデル化していますが、パーティションの数は$\binom{N-1}{K-1}$、中程度の場合でも巨大になります$N$。 すべてを合計しても$K$これは完全に不可能になります。

重要な観察は、1 を$+1$そして0から$-1$。 セグメントは、その合計が正の場合にのみ勝ちます。 これにより、問題はパーティション内の正和セグメントの数を最大化するという問題に変換されます。$K$部品。 

これで構造がより明確になりました。 パーティションを選択するたびに、できるだけ多くのセグメントの合計が正になるように、どこをカットするかを効果的に決定します。 重要な洞察は、セグメントが現在プラスではない場合、答えを改善する唯一の方法はセグメントをさらに分割することであり、分割によって柔軟性が高まるということです。非勝利セグメントは、十分な局所的なポジティブ変動が含まれていれば、複数の勝利セグメントに分解できる可能性があります。 

これは、配列を処理し、増加するにつれて良好なセグメントとして「抽出」できるセグメントの数を維持することを示唆しています。$K$。 の最適値$K$は、プレフィックス構造の貪欲な分解で正の和の部分配列を何回分離できるかによって決まります。 これにより、単調な構造が得られます。$K$増加しても、答えが減少することはなく、カットが追加されるたびに、勝ちセグメントの数は最大で 1 つずつ増加します。 

この単調性により、セグメントを段階的に洗練させるという観点から考えることができます。 現在勝っているセグメントの数を最大化するパーティションを維持し、あと 1 つのカットを許可したときにこの値がどのように増加するかを研究します。 これは、ローカル プレフィックス合計の寄与を追跡し、セグメント ゲインに対する優先順位構造を使用して可能な限り最良のセグメンテーションを貪欲に維持することに帰着できます。 

最終的な解決策は、基本的に、セグメントの「利益」に基づいた貪欲なセグメンテーションです。利益とは、地域を勝者に分割することがどれだけ有益であるかということです。 各カットは、達成可能なポジティブ セグメントの数を最大限に増やす場所で選択されます。

 ## アルゴリズムのチュートリアル

 文字列を配列に変換します$a$、 どこ$a[i] = +1$「1」の場合と$-1$「0」の場合。 

プレフィックス合計を構築します$p[i]$、 どこ$p[i]$の合計です$a[1..i]$。 セグメント$[l, r]$まさにいつ勝てるのか$p[r] - p[l-1] > 0$。 

1. 簡単なパーティションから開始します$K=1$、ここで唯一のセグメントは配列全体です。 勝っているかどうかを計算し、それに応じて現在の最適な構造を初期化します。 
2. 配列をスキャンし、これまでに形成されたセグメントを表す構造を維持します。 各セグメントには現在の合計があり、それをさらに分割することがどれほど有益であるかの尺度も維持します。 直感的には、合計が小さいか負のセグメントが分割の候補となります。 
3. 分割により勝利セグメントの数が増加するセグメントを繰り返し特定します。 これは、プレフィックスの合計が新しい正のサブ配列を分離できることを示す潜在的な分割点を追跡することによって行われます。 
4. セグメント分割の「利得」をキーとした優先キューを維持します。 ゲインは、もう一度最適にカットすることによって追加で獲得できる勝ちセグメントの数を表します。 増えるたびに$K$、利用可能な最高のゲインをポップし、分割を適用します。 
5. それぞれの操作の後、$N-1$可能な分割の場合、現在の勝ちセグメントの数を記録します。 これですべての答えが得られます$K$。 

機能する理由: 最適なパーティションはすべて、完全な配列から開始され、徐々にカットが挿入されていると見なされます。 カットごとにセグメントの数が 1 つずつ増加しますが、対物レンズへの影響は分割されるセグメントに限定されます。 セグメントのスコアは合計にのみ依存するため、セグメントの分割による改善は関連のないセグメントとは無関係です。 この独立性により、各ステップで常に最高の限界ゲインを選択することで、すべてのステップに対してグローバルに最適な結果が得られます。$K$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(s):
    n = len(s)
    a = [1 if c == '1' else -1 for c in s]

    # prefix sums
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + a[i]

    # We use a greedy multiset of segment gains.
    # Each segment is represented by its best possible improvement.
    import heapq

    # start with one segment [0, n)
    segments = [(0, n)]
    base_score = 1 if pref[n] > 0 else 0

    # priority queue of gains (negative for max heap)
    pq = []

    def calc_gain(l, r):
        # best split point maximizing improvement
        best = -10**18
        best_pos = -1
        for i in range(l + 1, r):
            left = pref[i] - pref[l]
            right = pref[r] - pref[i]
            gain = (left > 0) + (right > 0) - (pref[r] - pref[l] > 0)
            if gain > best:
                best = gain
                best_pos = i
        return best, best_pos

    # initialize
    g, pos = calc_gain(0, n)
    heapq.heappush(pq, (-g, 0, n, pos))

    ans = [0] * (n + 1)
    ans[1] = base_score

    for k in range(2, n + 1):
        if not pq:
            ans[k:] = [base_score] * (n - k + 1)
            break
        neg_g, l, r, pos = heapq.heappop(pq)
        if pos == -1:
            ans[k:] = [base_score] * (n - k + 1)
            break

        ans[k] = ans[k - 1] + (-neg_g)

        left_seg = (l, pos)
        right_seg = (pos, r)

        g1, p1 = calc_gain(*left_seg)
        g2, p2 = calc_gain(*right_seg)

        if p1 != -1:
            heapq.heappush(pq, (-g1, l, pos, p1))
        if p2 != -1:
            heapq.heappush(pq, (-g2, pos, r, p2))

    return ans[1:]

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()
        out.append(" ".join(map(str, solve_case(s))))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、1 つのセグメントから開始して、勝ちセグメントの数を最も増やす最適な分割を繰り返し適用するという考えに従っています。 プレフィックス合計配列は、サブセグメントが勝っているかどうかを評価するために使用されます。 

ヒープには、候補セグメントとその最適な分割位置が格納されます。 各抽出は増加をシミュレートします$K$1 つずつ増やし、それに応じて回答を更新します。 

主な微妙な点は、最適な内部構造が変化するため、セグメントを分割した後、その子の最適な分割を再計算することです。 これが、分割ごとに 2 つの新しい候補セグメントがトリガーされる理由です。

 ## 特殊なケース

 完全にゼロで構成される入力の場合、すべてのセグメントの合計は負またはゼロになるため、どのパーティションも勝利セグメントを生成することはできません。 アルゴリズムは基本スコア 0 から開始され、どの分割でも正のゲインが見つからないため、ヒープは空のままで、すべての答えはゼロのままです。 

all-one 配列の場合、分割に関係なく、すべてのセグメントは正の合計になります。 スプリットごとにセグメント数が増加し、勝利セグメントの数も 1 つずつ増加します。 ヒープは常に分割ごとに 1 に等しい正のゲインをもたらし、答えを生成します。$1, 2, \dots, N$、すべてのセグメントが勝っているという事実と一致します。
