 ## 解決策
 ## 問題の理解

 主催者は何人かいますが、会議が進むにつれてそれぞれの主催者が徐々に遅くなっていきます。 各主催者の遅れは一定ではありません。特定の人については、最初の会議での遅れがわかっており、その後の会議ごとに一定の増分でさらに遅くなります。 

各会議には固定時間が設定されています。 目標は、すべての主催者が会議に完全に参加できないほど遅れて到着する最初の会議インデックスを決定することです。つまり、会議の到着時間が少なくとも会議の全期間であることを意味します。 

状況を捉えるもう 1 つの方法は、各人が時間の経過とともに遅刻を表す線形関数を持っているということです。 会議番号について$k$、彼らの遅刻は$t_i + (k-1)a_i$、そして私たちは最も早いものを望んでいます$k$これらすべての値が少なくとも$M$。 

制約により、最大で$2 \cdot 10^5$主催者、遅刻の値は最大まで増加する可能性があります$10^9$。 これにより、会議に関するシミュレーションは即座に排除されます。 たとえ各会議のチェックが直線的だったとしても$N$、答え自体が大きくなる可能性があるため（最大約$10^9$最悪の場合）。 

強引なアイデアは、会議ごとに会議をシミュレートし、毎回全員の遅刻を再計算することです。 会議の数と会議ごとの計算の両方が大きすぎるため、これは失敗します。 

数式を使用して各会議を最初から再計算しようとしながらも会議をループする場合、より微妙な問題が発生します。各チェックが正しくても、反復回数が爆発的に増加する可能性があります。 

小さな例:

 入力:```
2 10
9 1
0 1
```この入力の場合、次の理由から正解は 2 です。 

- 会議 1: 遅刻は 9 と 0 ですが、すべてが 10 を超えるわけではありません
 - 会議 2: 遅刻は 10 と 1 ですが、まだ両方とも 10 以上ではないため、実際には会議 2 も失敗し、答えは 10 になります (最終的には両方ともしきい値を超えます)。 

シミュレーション手法では、両方がしきい値を超えるまで反復を続けるため、最終的な答えを直接計算できる場合でも、多くのステップが必要となる場合があります。 

## アプローチ

 会議を通じて直接シミュレーションすると、増加する可能性があります$k$、それぞれについて$k$すべてを計算する$t_i + (k-1)a_i$、すべてが少なくとも$M$。 これは定義と正確に一致するため、正しいです。 ただし、最悪の場合はすぐに壊れます。答えが大きい場合は、次のようにします。$10^9$、各小切手にかかる費用$O(N)$、それでは大まかに見ていきます$2 \cdot 10^5 \cdot 10^9$まったく実行不可能な操作です。 

重要な観察は、各主催者が独自に会議数のしきい値を定義し、それを超えると必ず会議に欠席するということです。 遅刻は単調に増加するため、一度会議に欠席すると、その後のすべての会議に欠席することになります。 したがって、各人は 1 つのカットオフ ポイント、つまり最初の会議で「常に欠席」することになります。 

固定の人にとっては$i$、私たちは最小のものを望んでいます$k$次のような:$$t_i + (k-1)a_i \ge M$$この不等式は直接解くことができます。 すべての主催者についてこのしきい値を計算すると、すべての条件を同時に保持する必要があるため、全員が欠席した最初の会議がすべての個々のしきい値の最大値になります。 

したがって、問題は、時間の経過に伴う動的なプロセスのシミュレーションからコンピューティングに移ります。$N$独立した算術しきい値と最大値の取得。

 | ブルートフォースシミュレーション |$O(N \cdot K)$|$O(1)$| 遅すぎる |
 | 一人当たりのしきい値の計算 |$O(N)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各主催者について、遅刻を会議インデックスの関数として解釈します。$k$:$t_i + (k-1)a_i$。 これにより、動的プロセスが静的な不等式問題に変換されます。 
2. 会議に欠席するための条件を再調整します。$$t_i + (k-1)a_i \ge M$$になる$$(k-1)a_i \ge M - t_i$$3. 最小の整数を計算する$k$この不等式を満たすものです。 分割は正確ではない可能性があるため、天井分割を使用します。$$k_i = \left\lceil \frac{M - t_i}{a_i} \right\rceil + 1$$これにより、主催者が最初の会議を開催します。$i$いつも遅いです。 
4. すべての最大値を追跡する$k_i$。 すべての主催者は独自のしきい値を満たす必要があるため、答えは少なくともこれくらい大きくなければなりません。 
5. すべての主催者を処理した後の最大値を出力します。 

### なぜ効果があるのか

 各主催者は「出席」から「常欠」に 1 回だけ遷移し、この遷移点は会議数において単調です。 しきい値に達すると、二度と時間厳守になることはありません。 したがって、「全員が遅刻する」というシステム全体の条件は、最も遅刻する主催者がしきい値を超えたときにまさに満たされます。 最大値を取得すると、すべての独立した制約が最初の会議に正しく同期され、すべての制約が同時に真になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ceil_div(a, b):
    return (a + b - 1) // b

def solve():
    n, m = map(int, input().split())
    ans = 1

    for _ in range(n):
        t, a = map(int, input().split())
        need = m - t
        k = ceil_div(need, a) + 1
        if k > ans:
            ans = k

    print(ans)

if __name__ == "__main__":
    solve()
```実装は、導出されたしきい値の式に直接従います。 ヘルパーさん`ceil_div`は、浮動小数点演算を行わずに整数の上限除算を安全に処理します。これにより、精度の問題が回避され、大きな値の正確性が保証されます。 

変数`ans`すべての主催者の最大しきい値を保存します。 最初の会議はベースライン インデックスとして常に有効であるため、1 から始まります。 各主催者について、個人のカットオフ会議を計算し、グローバル最大値を更新します。

```各主催者の閾値を計算します。 

| 主催者 | t | | 必要性 = M - t | k の計算 | k_i |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 9 | 1 | 1 | ceil(1/1)+1 = 2 | 2 |

このトレースは、答えがしきい値を超えるのが最も遅い主催者によって完全に支配されていることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    ans = 1

    for _ in range(n):
        t, a = map(int, input().split())
        need = m - t
        k = (need + a - 1) // a + 1
        ans = max(ans, k)

    return str(ans)

# sample
assert run("4 60\n0 30\n10 30\n20 30\n25 30\n") == "9"

# minimum case
assert run("1 10\n0 1\n") == "11", "single beaver"

# already close to threshold
assert run("2 5\n4 1\n1 10\n") == "2", "one dominates"

# equal growth
assert run("3 100\n0 10\n0 10\n0 10\n") == "10", "uniform case"

# large increments
assert run("2 100\n0 100\n99 1\n") == "2", "boundary crossing"
```| テスト入力 | 期待される出力 | 検証内容 |

 | 単一のビーバー | 写真 11 | 基本的な公式の正しさ |
 | 混合しきい値 | 2 | 最大選択ロジック |

 ## 特殊なケース

 微妙なケースの 1 つは、主催者が最初の会議ですでに敷居に非常に近づいている場合です。 例えば：```
1 10
9 1
```ここで、必要な追加遅延は 1 です。計算により次のようになります。$$k = \lceil 1/1 \rceil + 1 = 2$$会議 1 ではまだ完全に遅刻していませんが、会議 2 ではちょうどしきい値を超えています。 アルゴリズムは正しく 2 を返します。これは、オフバイ 1 シフトが$(k-1)$最終的に処理されます`+1`式では。 

もう 1 つのケースは、複数の主催者が成長率が大きく異なる場合です。 最大値を設定すると、たとえほとんどの人が早めに遅刻したとしても、成長の遅い 1 人の主催者が最終的な答えを決定することが保証されます。 例えば：```
2 100
0 1
0 100
```2 番目の主催者は会議 2 で遅れますが、最初の主催者は 100 回の会議が必要です。 結果は 100 で、アルゴリズムは中間値の影響を受けることなく、その最大値を正しく選択します。
