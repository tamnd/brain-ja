 ## 解決策
 ## 問題の理解

 文字のみで構成される可変文字列を使用しています。`a`、`b`、 そして`c`。 更新のたびに、文字列に関する構造的な質問に答える必要があります。つまり、文字列に`abc`続編として。 

重要な詳細は、文字を削除するのではなく、文字を任意に置き換えることのみが許可されるということです。 置き換えると、キャラクターを次のいずれかに変更できます。`a`、`b`、 または`c`、そして、その後に発生する可能性のあるものをすべて破棄するために必要な、そのような編集の最小限の数が必要です。`abc`。 

部分シーケンス条件により、これが部分文字列の問題とは根本的に異なります。 連続したパターンを探しているのではなく、順序付けられたトリプルを探しています。`a`それから`b`それから`c`、おそらく遠く離れています。 これは、まばらな出現であっても重要であり、単純なローカル修正は機能しないことを意味します。 

入力サイズは最大です`n, q ≤ 100000`したがって、更新のたびに答えを最初から再計算するには、大まかに次の処理が必要になります。`O(nq)`これは許容範囲をはるかに超えています。 たとえ`O(n log n)`クエリごとのアプローチではタイムアウトになる危険性があります。 これにより、前処理後に各更新が対数時間または定数時間で処理されるソリューションが強制されます。 

微妙なエッジケースは、すでに含まれていない文字列から発生します。`abc`続編として。 例えば、`"aaacccbbb"`順序付けが妨げられるため、ローカル パターンに関係なく安全です。`a < b < c`。 もう 1 つの注意が必要なケースは、複数の互いに素なサブシーケンスが重なり合う場合で、貪欲なローカル修正によって必要な変更の数が過小評価される場合です。 

## アプローチ

 ブルートフォース手法では、更新のたびに文字列をスキャンし、`abc`部分系列として存在します。 これは次の方法で実行できます`O(n)`単純なポインタ スキャンを使用する: 最初にすべてを一致させる`a`、 それから`b`、 それから`c`。 ただし、最小限の変更数も計算する必要があるため、ブルート フォースでは、削除や置換によってそのようなすべてのサブシーケンスがどのように破壊されるかを考慮する必要があります。 プレフィックスを使用した単純な動的プログラミングには依然としてコストがかかります`O(n)`クエリごとに、`O(nq)`全体的に複雑なので、合計 200,000 の操作には遅すぎます。 

重要な洞察は、文字列に長さ 3 のパターンに等しいサブシーケンスが含まれているかどうかのみを考慮しているということです。 これは、有限オートマトンの観点を示唆しています。マッチングを通じてどれだけ多くの方法で進歩できるかを追跡します。`a → b → c`順番に。 ポジションについて考えるのではなく、キャラクターが状態間の遷移にどのように貢献するかを考えます。 

文字列のプレフィックスごとに、現在状態 0 (何も一致しなかった)、状態 1 (少なくとも 1 つ一致した) にある方法が何通りあるかを示す 3 状態 DP を維持できます。`a`)、状態 2 (一致`ab`)、状態 3 (完了`abc`）。 問題は、状態 3 に決して到達しないようにすることです。ただし、文字の変更が許可されているため、各位置は 3 つの文字のいずれかを選択するものとして解釈でき、禁止された状態への遷移を強制する位置の数を最小限に抑えたいと考えています。 

これは、3×3 遷移行列上の古典的なセグメント ツリーになります。 各文字は、状態カウントを変換する方法を説明する行列に対応します。 セグメントの結合は、遷移の半リングにおける行列の乗算に対応します。 文字列全体の答えは、状態 3 に到達できるかどうかから得られます。 より正確には、到達するすべてのパスをブロックするために必要な最小限の編集を計算します。`abc`。 

コスト構造は次のようにエンコードできます。キャラクターを現状維持する場合はコスト 0、変更する場合はコスト 1、それぞれの選択により異なる遷移行列が生成されます。 行列を事前計算します。`a`、`b`、`c`そして、それらをセグメント ツリーに結合します。セグメント ツリーには、各ノードが最小限の変更コストで可能な限り最良の遷移動作が保存されます。 

各更新の後、1 つのリーフを更新し、上向きに再計算します。`O(log n)`、ルートはグローバルな答えをエンコードします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | セグメントツリー + DP トランジション | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. サブシーケンスのマッチングがどこまで進んだかを示す DP として各プレフィックスをモデル化します。`abc`。 何も一致しなかった、一致した、に対応する状態を追跡します`a`、一致しました`ab`、またはすでに形成されている`abc`。 目標は、最終状態に到達しないようにすることです。 
2. キャラクターごとに、DP 状態を変更しない場合にどのように遷移するかを定義します。 たとえば、私たちが見た状態にあるとします。`a`、遭遇`b`他の文字は状態を変更しないままにすることができます。 
3. 必要に応じて各位置を変更できるようにします。 これは、各文字の位置が 3 つの可能な遷移動作に関連付けられていることを意味します (次のように扱います)。`a`、`b`、 または`c`)、各選択肢のコストは、元のものと一致する場合は 0、一致しない場合は 1 になります。 
4. 各位置をサイズ 4×4 の小さな遷移行列としてエンコードします。`(i, j)`状態から移動できるかどうかを表します`i`述べます`j`ある程度のコストがかかります。 マトリックスには、最小コストの推移が保存されます。 
5. 各ノードがそのセグメントの最適に結合された遷移行列を格納するセグメント ツリーを構築します。 2 つのセグメントを結合することは、左側のセグメント、次に右側のセグメントを通過する最適な方法、つまり最小限のコストでの行列乗算を行うことに相当します。 
6. 各更新後に、その位置のリーフ行列を再構築し、ルートまでの祖先を再計算します。 ルート行列は、文字列全体で禁止状態に達することを回避するための最小コストを示します。 
7. 各クエリの後の答えは、DP が絶対に到達しないようにするために必要な最小限のコストです。`abc`これは、すべてのサブシーケンスを防止することに相当します。 

### なぜ効果があるのか

 アルゴリズムが機能するのは、すべてのサブシーケンスが`abc`DP 状態を通る単調なパスに対応します`0 → 1 → 2 → 3`インデックス全体にわたって。 このようなパスは、文字の有効な割り当てとして解釈できる一連の位置を通過する必要があります。 関連するコストを伴う 3 つの決定論的な遷移の間の選択肢として各位置をエンコードすることにより、グローバルなサブシーケンス制約をローカルな合成問題に変換します。 セグメント ツリーは、すべての間隔で考えられるすべての部分状態の最適コストを保存するため、ルートは、禁止された部分シーケンスを形成または回避するためのすべての可能な方法を集約します。 すべての有効なサブシーケンスはこれらの状態を通る 1 つのパスに正確に対応するため、すべてのパスをブロックすることで正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

# states:
# 0 = nothing matched
# 1 = matched 'a'
# 2 = matched 'ab'
# 3 = matched 'abc' (forbidden, we try to avoid it)

def merge(A, B):
    # A and B are 4x4 matrices
    res = [[INF]*4 for _ in range(4)]
    for i in range(4):
        for k in range(4):
            if A[i][k] == INF:
                continue
            for j in range(4):
                res[i][j] = min(res[i][j], A[i][k] + B[k][j])
    return res

def make_matrix(ch, orig):
    # dp transition matrix for one position
    # cost is 0 if we keep original char, else 1
    chars = ['a','b','c']
    res = [[INF]*4 for _ in range(4)]

    for c in chars:
        cost = 0 if c == orig else 1

        for st in range(4):
            nst = st
            if st == 0:
                if c == 'a':
                    nst = 1
                elif c == 'b':
                    nst = 0
                elif c == 'c':
                    nst = 0
            elif st == 1:
                if c == 'b':
                    nst = 2
                elif c == 'a':
                    nst = 1
                elif c == 'c':
                    nst = 1
            elif st == 2:
                if c == 'c':
                    nst = 3
                elif c == 'a':
                    nst = 1
                elif c == 'b':
                    nst = 2
            else:
                nst = 3

            res[st][nst] = min(res[st][nst], cost)

    return res

class SegTree:
    def __init__(self, s):
        self.n = len(s)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.seg = [[[INF]*4 for _ in range(4)] for _ in range(2*self.size)]

        for i in range(self.n):
            self.seg[self.size+i] = make_matrix(s[i], s[i])

        for i in range(self.size-1, 0, -1):
            self.seg[i] = merge(self.seg[2*i], self.seg[2*i+1])

    def update(self, idx, ch):
        self.seg[self.size+idx] = make_matrix(ch, ch)
        i = self.size + idx
        while i > 1:
            i //= 2
            self.seg[i] = merge(self.seg[2*i], self.seg[2*i+1])

    def answer(self):
        # best cost to avoid reaching state 3
        res = self.seg[1][0][0]
        return res

def main():
    n, q = map(int, input().split())
    s = list(input().strip())

    st = SegTree(s)

    for _ in range(q):
        i, c = input().split()
        i = int(i) - 1
        s[i] = c
        st.update(i, c)
        print(st.answer())

if __name__ == "__main__":
    main()
```この実装では、各位置を DP 遷移デバイスとして扱い、それらをセグメント ツリーと結合します。 マージ操作は重要な部分です。これにより、連続する 2 つのセグメントを通るあらゆるパスが確実に考慮され、編集が導入されるにつれてコストが蓄積されます。 

更新ステップでは、ツリー内の影響を受けるパスのみを再構築し、各クエリの対数を維持します。 最終的な答えはルートから読み取られ、文字列全体にわたるすべての可能な状態遷移が集約されます。 

## 実用的な例

 ### 例 1

 入力文字列:`aaabccccc`、サンプルのように位置 4 を繰り返し変更します。 

ルート DP コストのみを追跡します。 

| ステップ | 文字列 | 主な効果 | 最小編集数 |
 | --- | --- | --- | --- |
 | イニシャル | ああああ すでにサブシーケンスがあります`abc`| 1 |
 | 4→a以降 | ああああああああ すべてを壊す`abc`パス | 0 |
 | 4→b以降 | ああああ 1 つの有効なサブシーケンス パスを復元します。 1 |

 このトレースは、単一の位置で複数のサブシーケンスの形成を制御できることを示しています。そのため、局所的な貪欲な修正では不十分です。 

### 例 2

 検討してください`ababcc`。 

| ステップ | 文字列 | 観察 | 答え |
 | --- | --- | --- | --- |
 | イニシャル | アバブク | a、b、c の複数のインターリーブが存在します。 2 |
 | 中央のb→aを変更 | ああああ | 残っている有効なサブシーケンスが少なくなります。 1 |

 これは、重複するサブシーケンスが少数の編集でどのように崩れるか、そしてなぜ DP がローカル パターンではなくグローバル構造を追跡する必要があるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n) | 各更新はセグメント ツリー内の 1 つのパスに影響します。 
| スペース | O(n) | 各ノードは一定サイズの DP 行列を格納します。 

この制約により、およそ 10^5 の更新が可能になり、更新ごとの対数再計算は時間制限内に問題なく収まります。

import sys, io

def run(inp: str) -> str:

            for k in range(4):
                for j in range(4):

    class Seg:

 ## 特殊なケース

 重大なエッジケースは、すでに何も含まれていない文字列です。`abc`続いて。 例えば、`"ccccbbbbaaaa"`決して形成しない`abc`順序が逆になるからです。 このアルゴリズムにより、DP 状態が状態 3 に到達することがなくなり、ルート コストはゼロのままになります。 

別のエッジケースは次のような文字列です`"abcabcabc"`、すべての位置が複数の重複するサブシーケンスに参加します。 ここで、慎重に選択した 1 つの文字を削除すると、多くのサブシーケンスが一度に壊れる可能性があります。 すべてのセグメントが完全な状態遷移情報を保持しているため、セグメント ツリー表現はこれらの重複を正しく集約し、共有構造が二重にカウントされたり欠落したりしないようにします。 

3 番目のケースは、同じ位置への更新が繰り返される場合です。 各更新ではリーフ行列が完全に置き換えられ、祖先が再計算されるため、累積エラーは発生しません。 各クエリは文字列の正確な現在の状態を反映します。
