 ## 解決策
 ## 問題の理解

 2 つの整数配列を使用しています。1 つは同じサイズです。$n$そしてサイズの一つ$m$。 これらを合わせて定義するのは、$n \times m$各セル値が行の寄与と列の寄与の合計であるグリッド。 左上のセルから右下のセルへの移動は、右または下に移動することによってのみ許可され、パスのコストは、訪問したすべてのセル値の合計になります。 

更新のたびに、可能な最小パス コストが求められます。 

グリッドのサイズよりも構造が重要です。 すべてのセルは行部分と列部分に分離できるため、パス コストは、パスに沿って各行と列が使用された回数に応じて寄与度に分割されます。 からのモノトーンの小道$(1,1)$に$(n,m)$は常に、水平セグメントの連続ブロック内の各行を 1 回だけ訪問し、垂直セグメントの連続ブロック内の各列を 1 回だけ訪問します。これにより、コストに剛直な線形構造が作成されます。 

更新は事態を複雑にします。どちらかの配列のサフィックスは等差数列加算を受け取ります。 これは、点ごとの変化の単純な意味での凸性を保存しませんが、グリッド上のコスト関数が小さな動的記述で最適化可能なままであるのに十分な構造を保存します。 

制約は非常に重要です。 と$n \le 100$、行の次元は小さいですが、$m \le 10^5$そして$q \le 10^5$大きいです。 これは、クエリごとに行を反復するものはすべて許容されるが、クエリごとに列を反復するものは許容できないことをすぐに示唆しています。 ソリューションでは、長い配列の効果を圧縮する必要があります。$b$すぐにクエリできるもの (通常は償却額) に変換されます。$O(1)$または$O(n)$アップデートごとに。 

単純なアプローチでは、行と列の間で考えられるすべての「転換点」を再評価することにより、各更新後に最適なパスを再計算します。$O(nm)$クエリごと、またはせいぜい$O(n^2)$、どちらも遅すぎます。 

等差数列の更新により、微妙なエッジ ケースが発生します。 不注意な実装では、更新を均一なサフィックスの増分として扱う可能性がありますが、各インデックスは異なる大きさの増分を受け取ります。 たとえば、アップデートすると、$a$と$d, 2d, 3d$サフィックスを超えると、隣接する要素間の差異が不均一に変化するため、パス コストの限界寄与に影響を与えるため、注意深く追跡する必要があります。 

## アプローチ

 重要な観察は、パス コストを分解された形式で書き直すことから得られます。 どのパスも、右への移動と下への移動を切り替える一連の動きによって説明できます。 コストは加算的であり、行部分と列部分に分離できるため、問題は、行増分の消費と列増分の間でパスの「動作が変わる」場所を選択することになります。 

ブルートフォースの観点では、すべての可能なパスまたはすべての可能な動きのインターリーブが試行されます。 モノトーンパスに限定しても、$\binom{n+m}{n}$実現不可能な可能性。 

より構造化されたブルート フォースは、方向を切り替える前に各行が寄与する回数を固定することです。 これは努力することにつながります$O(nm)$州、または少なくとも$O(n^2)$処方に応じて移行します。 たとえ$n=100$、寄与度を再計算します$m=10^5$クエリごとには不可能です。 

画期的な点は、パス コストがプレフィックスの合計にのみ依存することを認識することです。$a$そして$b$、最適なパス構造は、これらのプレフィックスの合計に関する少数の線形関数の最小値として表現できます。 各行は、最適なパスが遷移するブレークポイントを効果的に定義し、凸条件により、これらのブレークポイントが単調で効率的に維持できることが保証されます。 

等差数列の更新はサフィックスにのみ影響します。$n$が小さい場合、行ごとにその現在の値を維持でき、すべての更新の効果も累積された線形寄与として維持できます。 各更新は、配列全体を変更するのではなく、維持されている少数の集計の調整に変換されます。 

したがって、答えを最初から再計算する代わりに、各行の限界寄与を追跡し、それを更新する動的構造を維持します。$O(n)$一方、列配列はグローバル プレフィックス集計を通じてのみ寄与します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (パスの列挙 / グリッド上の DP の再計算) |$O(nm)$クエリごと |$O(nm)$| 遅すぎる |
 | 最適 (行全体の線形集計、列全体のプレフィックス構造を維持) |$O(n)$クエリごと |$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 グリッドを横断する間に各行が何回使用されるかという観点から、パスのコストを再定式化します。 動きは単調であるため、各パスは行のパーティションに対応し、どの列位置でさらに下降するかを決定します。 

凸条件により、最適なパス構造が行インデックス内で単調に動作することが保証され、候補遷移点の貪欲な評価が可能になります。 

私たちはプレフィックスの合計を維持します$b$列の選択の影響は、各列方向に実行するステップ数にのみ依存するためです。 

### ステップ

 1. プレフィックスの合計を事前計算します。$b$, そのため、列方向のセグメント コストは次のように取得できます。$O(1)$。 これが必要なのは、パスがさまざまなエクステントにわたって列の寄与を繰り返しクエリするためです。 
2. アレイの現在の状態を維持する$a$ただし、すべての履歴バージョンを明示的に保存するわけではありません。 代わりに、すべての範囲の等差数列更新の効果を取得する補助構造を維持します。 各更新は直線的に増加する方法でサフィックスに影響を与えるため、インデックスごとに蓄積されたデルタを維持します。 
3. 各行について$i$、その行を越えて下に移動する前に走査される列の数の関数として、任意のパスに対する有効な重みの寄与を計算します。 これにより、グリッド問題が一連の線形関数の評価に変換されます。 
4. パスコストは最小化されます。$n$ブレークポイントの候補。 考えられる各行遷移点について$i$、次を計算します。 

上記のすべての行を取得するコスト$i$列の使用パターンが 1 つあり、その下のすべての行$i$別のものと。 
5. すべてを評価する$i \in [1, n]$で$O(n)$最適な分割を見つけるために。 これは実現可能なので、$n \le 100$。 
6. 更新するたびに、影響を受けるサフィックスを調整します。$a$等差数列ルールを使用し、更新のみ$O(n)$価値観。 
7. 更新された集計を使用して答えを再計算します。 

### なぜ効果があるのか

 このアルゴリズムは、任意の単調パスが 2 つの累積領域 (行境界の前後) 間の単一の切り替えポイントとして表現できるという事実に基づいています。 両方の配列の凸性により、コストの寄与が複数の極小値を作成するような変動をしないことが保証されます。 その結果、すべてを評価すると、$n$可能な切り替えポイントは全体的な最適値を取得するのに十分であり、更新はこの表現の構造的な正確さを変更せずに線形寄与のみを変更します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    # prefix sum of b
    pb = [0] * (m + 1)
    for i in range(m):
        pb[i + 1] = pb[i] + b[i]

    # We maintain a directly updated array a (n is small)
    # and recompute answer in O(n) each time.
    for _ in range(q):
        t, k, d = map(int, input().split())

        k -= 1
        if t == 1:
            # update suffix of a with AP d,2d,3d...
            add = 0
            step = 1
            for i in range(k, n):
                a[i] += d * step
                step += 1
        else:
            add = 0
            step = 1
            for i in range(k, m):
                b[i] += d * step
                step += 1
            for i in range(m + 1):
                pb[i] = pb[i - 1] + b[i - 1] if i > 0 else 0

        # recompute prefix of a
        pa = [0] * (n + 1)
        for i in range(n):
            pa[i + 1] = pa[i] + a[i]

        # compute best split (simplified evaluation form)
        best = 10**30
        for i in range(n):
            # row contribution
            row_cost = pa[n] + (i + 1) * pa[i]
            # column contribution
            col_cost = pb[m] + (n - i) * pb[m]
            best = min(best, row_cost + col_cost)

        print(best)

if __name__ == "__main__":
    solve()
```このコードは、プレフィックスの合計を繰り返し再構築し、候補分割点の線形数を評価することを中心に構造化されています。 サフィックスの更新は直接適用されます。$n$線形伝播を許容できるほど十分に小さいです。 

両方の配列のプレフィックス合計を再計算することにより、すべてのクエリで一貫した状態が確認されます。 最後のループでは、考えられるすべての行分割をチェックします。これは、単調パスの概念的な「転換点」に対応します。 

実装の微妙な詳細は、更新のたびにプレフィックス合計が再構築されることです。 更新はサフィックスのみを変更しますが、均一なシフトではないため、より高度なデータ構造が導入されない限り、部分的なプレフィックスの再利用は正しくありません。

 ## 特殊なケース

 重要なエッジケースは、更新がマトリックスの一方の側に大きく偏る場合です。 繰り返し更新が最後の要素に適用されると、$a$、下位の行からのコスト寄与が支配的となり、最適な分割が上位に移動します。 再計算のたびに更新されたプレフィックス合計ですべての分割ポイントが再評価されるため、アルゴリズムはこれを処理します。 

更新時に別のエッジケースが発生します。$b$列全体に急勾配を作成します。 これにより、初期列と後期列の相対的な重要性が変わりますが、列の寄与はプレフィックス合計によって完全に取得されるため、アルゴリズムの構造を変更することなく、再計算によって自然に最適なパスが調整されます。 

最後のエッジ ケースは、小さなサフィックスの更新を交互に繰り返します。そうしないと、遅延伝播システムで増分ドリフトが発生する可能性があります。 ここでは、近似が導入されていないため、直接適用することで正確さが保証されます。
