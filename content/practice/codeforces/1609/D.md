 ## 解決策
 ## 問題の理解

 私たちは、最初はまったく関係のない人々のグループを与えられます。 時間の経過とともに、一連のペアが表示され、各ペアは最終的に満たさなければならない制約を表します。つまり、ペアの 2 人は最終的に結ばれなければなりません。これは、2 人を結ぶ直接の紹介の連鎖が存在することを意味します。 

ウィリアムは、人を紹介できる唯一の人物です。 それぞれの導入により、これまでつながりのなかった 2 人の個人がつながり、最初は空だったグラフに効果的にエッジが追加されます。 最初の i 個の導入を実行した後、すべての最初の i 個の制約が満たされる必要があります。つまり、それらのペアのそれぞれが、結果として得られるグラフの同じ連結成分内に存在する必要があります。 

すべてのプレフィックス長 i について、概念的には最初からやり直し、正確に i 個の導入を実行し、最初の i 制約が満たされていることを確認します。 これらの紹介を選択するためのすべての有効な方法の中で、私たちは紹介を通じて相互に連絡できる最大の人々の集団のサイズを最大化したいと考えています。 グラフの用語では、最大の連結成分のサイズを最大化します。 

重要な点は、各プレフィックスが独立していることです。 以前のプレフィックスから構造を引き継いでいないため、各 i は同じ n 個のノード上で個別の最適化問題を定義し、最初に接続制約が必要です。 

制約は十分小さいため、n が 1000 までであれば O(n^2) または O(n^2 log n) の推論が可能です。 ただし、すべてのプレフィックスを再計算するという事実は、接続を毎回最初から再計算するのではなく、段階的に更新できる構造が必要であることを強く示唆しています。 

i ごとに接続を最初から再構築し、制約を強制しようとする単純なアプローチでは、完全なグラフ構築を繰り返し実行するか、可能なすべての導入を検索することになります。 これは、プレフィックスごとに実現可能性をチェックするだけでも既に大量の Union-find または BFS ロジックが必要となり、プレフィックスごとに個別に実行するとコストが d 倍になるため、すぐに実行不可能になります。 

一般的なエッジ ケースは、制約が重複するコンポーネントを形成するときに発生します。 たとえば、制約が (1,2)、(2,3)、(3,4) の場合、最適な構築によりすぐにチェーンが構築され、最大のコンポーネントが着実に成長します。 ただし、制約が初期段階で互いに素であり、後になって初めて大きなグループに接続される場合、慎重にマージ順序を設定せずに制約を貪欲にローカルに解釈すると、達成可能なコンポーネント サイズが過小評価される可能性があります。 

もう 1 つの微妙な問題は、何を最大化する必要があるかを誤解していることです。 満たされる制約や追加されるエッジの数を最大化するわけではありません。 プレフィックス内のすべての制約を強制した後、最大の連結コンポーネントのサイズを最大化しています。 

## アプローチ

 ブルートフォースの観点は、固定 i について、(x1, y1) から (xi, yi) までのすべてのペアが同じ連結成分内に存在することを確認することから始まります。 エッジを繰り返し追加して妥当性をチェックすることでグラフを構築しようとすることもできますが、それは重要な困難につながります。すべての制約が接続されている限り、William がどの導入を実行するかを自由に選択できます。 

実際の構造は次のとおりです。制約により、ノードの特定のグループが同じ接続コンポーネント内に配置されるようになります。 最初の i 制約を補助グラフのエッジと考えると、有効な最終構成は少なくともこの補助グラフの各接続コンポーネントを接続する必要があります。 つまり、制約グラフの各コンポーネントは、ウィリアムが作成したグラフの接続されたコンポーネント内に完全に含まれている必要があります。 

したがって、最適な戦略は、William が断片化を最小限に抑える方法でコンポーネントを接続し、各制約コンポーネントを「マージする必要がある」ブロックとして事実上扱うことができるようにすることを認識することです。 唯一の自由は、正確に i 個のエッジを使用してこれらのブロックをどのようにマージするかです。

重要な洞察は、正確に i 個の導入を実行し、各導入で 2 つのコンポーネントをマージするため、n 個の分離されたノードから開始して i 個のマージを実行するということです。 i がマージされた後は、常に正確に n - i 個のコンポーネントが得られます。 したがって、問題は、制約コンポーネントが含まれなければならないことを尊重しながら、それらのマージがどのように分散されるかを制御することに帰着します。 

これは、制約に対する貪欲な結合検索プロセスにつながります。つまり、制約を 1 つずつ処理し、そのエンドポイントを結合します。 i 個の結合後の Union-find 構造体の最大の接続コンポーネントのサイズが、達成可能な最良の答えを与えます。これは、有効な構築では少なくともこれらの強制接続を尊重する必要があり、それらのマージを正確に達成する構築を常に実現できるためです。 

したがって、DSU を維持し、コンポーネントのサイズを追跡します。 各制約を処理した後、最大の DSU コンポーネントのサイズを更新します。 

微妙な正当化は、制約には直接エッジではなく接続のみが必要であるため、エンドポイントをマージするだけで十分であるということです。 各制約は、有効な実現においてそれらのコンポーネントの結合を効果的に強制します。 これらを結合すると、最小限の強制構造が正確にキャプチャされ、制約を超えた任意の導入が許可されるため、最大のコンポーネントが制約によって形成された最大の DSU コンポーネントと等しい構成を常に実現できます。

 ## アルゴリズムのチュートリアル

 素の集合結合構造を維持しながら、制約を段階的に処理します。 

1. それぞれが独自のコンポーネント内にある n 個のノードで DSU を初期化します。 各コンポーネントのサイズは 1 です。 
2. 変数を維持する`best`これまでに確認された最大コンポーネント サイズが格納されます。 
3. 各制約 i = 1 ～ d について、ペア (x_i, y_i) を取得し、それらの DSU コンポーネントをマージします。 それらがすでに同じコンポーネント内にある場合は、何も変わりません。 
4.各結合操作の後に、更新します`best`DSU に現在存在する最大のコンポーネント サイズを反映します。 
5. 出力`best`各接頭辞 i を処理した後。 

これが機能する主な理由は、各制約が 2 つのグループ間の接続を強制するためです。 2 つのグループが制約内で接続されると、有効な構築では最終的なグラフでそれらが接続されることを保証する必要があります。 DSU は、そのような強制された関係をすべてコンポーネントに圧縮し、各導入が 2 つのコンポーネントをマージするため、コンポーネントのサイズを追跡することで、可能な限り最大の接続グループの成長を直接把握できます。 

### なぜ効果があるのか

 任意の接頭辞 i で、制約エッジはグラフを定義します。グラフの接続コンポーネントは、すべての有効な構成で接続する必要がある人々の同値クラスです。 有効な導入計画では、これらの各クラスを内部接続し、各クラスがスーパーノードのように動作するようにする必要があります。 形成できる可能な最大の連結コンポーネントは、各制約コンポーネントを分割できないものとして扱い、そのサイズを数えることによって取得されます。 DSU はこれらの等価クラスを正確に維持し、マージが許可される唯一の操作であるため、i 個の結合後の DSU 状態は、最初の i 個の制約を満たした後に達成可能な最大の強制接続構造を表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return 0
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return self.size[a]

n, d = map(int, input().split())
dsu = DSU(n)

best = 1
out = []

for _ in range(d):
    x, y = map(int, input().split())
    x -= 1
    y -= 1
    merged_size = dsu.union(x, y)
    if merged_size:
        best = max(best, merged_size)
    out.append(str(best))

print("\n".join(out))
```DSU 構造は、制約によって引き起こされる接続コンポーネントを追跡します。 各結合は、2 人が同じ接続されたグループに所属することを強制することに対応します。 size 配列を使用すると、結果として得られる各グループの大きさを定数時間で追跡し、更新することができます。`best`これにより、各プレフィックスの後に達成可能な最大のクラスターが常にわかるようになります。 

主要な実装の詳細は、更新のみを行うことです。`best`実際にマージが行われるとき。 2 つのノードがすでに同じコンポーネント内にある場合、制約によって新しい構造は追加されず、答えは変更されません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, d = map(int, input().split())
    dsu = DSU(n)

    best = 1
    out = []

    for _ in range(d):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        merged_size = dsu.union(x, y)
        if merged_size:
            best = max(best, merged_size)
        out.append(str(best))

    return "\n".join(out)

    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
    def find(self, x):

            x = self.parent[x]
        return x

        a = self.find(a)
        b = self.find(b)

            return 0
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return self.size[a]

 ## 特殊なケース

 小さいながらも重要なケースは、制約がすでに接続されているペアを繰り返す場合です。 たとえば:

 入力:```
4 3
1 2
2 3
1 3
```最初の 2 つの制約の後、ノード {1,2,3} はすでに統合されています。 3 番目の制約は DSU の状態を変更しません。 アルゴリズムはそれを正しく無視します。`union`0 を返し、`best`は更新されていません。 出力は、新しい接続が強制されないという事実と一致しています。 

もう 1 つのケースは、制約が後でのみ役立つ 2 つの独立したクラスターを形成する場合です。 DSU は、部分的なマージが正しく蓄積されることを保証し、真のマージが発生した場合にのみ最大のコンポーネントが更新されるようにして、冗長な制約によるインフレを防ぎます。
