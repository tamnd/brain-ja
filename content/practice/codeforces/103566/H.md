 ## 問題の理解

 次のシーケンスとして考えることができるパスが与えられています。`n`家と学校の間に一列に配置された道路セグメント。 この線に沿ったどこかに家から学校までの有効な最短ルートがあり、その長さは整数です`x`。 このルートがどこにあるのか、内部でどのように動作するのかはわかりませんが、ブラック ボックスと対話することはできます。 

セグメントインデックスを選択するたびに`i`、質問します`? i`そして番号を受け取ります。 この数値は、セグメントが`i`隠れた最短ルートにあります。 そのルート上にない場合、応答は正確に次のようになります。`x`。 ルート上にある場合、応答は次のようになります。`n - x`。 

目標は、次の値を決定することです。`x`できるだけ少ないクエリを使用します。 

構造的に重要な制約は、最短ルートにはすべてのセグメントの半分以上を含めることはできないということです。 この非対称性により、サンプリングされたほとんどの位置が同じように動作することが保証されるため、非常に少ないクエリで問題を解決できるようになります。 

複雑さの観点から見ると、相互作用がすべてを支配します。 各クエリはプロトコルの観点から高価であるため、ソリューションでは時間の複雑さではなくクエリの数を最小限に抑える必要があります。 すべてのポジションをスキャンしようとする戦略は、次の場合には直ちに不可能になります。`n`大きいです。 

すべてのクエリが同じように動作する、または複数のクエリ位置が独立していると仮定すると、微妙な失敗のケースが発生します。 実際には、すべての答えはグローバルに同じ隠された値に関連付けられています。`x`したがって、クエリの冗長性によって、慎重に選択された少数のサンプル以外の新しい情報は提供されません。 

## アプローチ

 この問題についての素朴な考え方は、あらゆる立場を試してみることだ`i`、クエリを尋ね、次のことを推測しようとします。`i`最短ルート上にあります。 明らかにされる情報は位置がパス上にあるかどうかだけであり、各クエリは依然として 2 つのグローバル値のうちの 1 つだけを生成するため、これはすぐに不要になります。 すべての位置をマークしてパス構造を再構築しようとしても、まだ学習できません。`x`回答間のグローバルな関係を利用することなく直接的に。 

重要な観察は、システムが隠れてバイナリであるということです。 すべてのクエリは次のいずれかを返します`x`または`n - x`。 これは、インタラクション空間全体が崩れて、2 つの値のどちらが見られているかを区別できないことを意味します。 少なくとも 1 つのクエリ結果が得られたら、答えは返された値かその補数でなければならないことがすでにわかっています。`n`。 

残る唯一の問題はあいまいさです。サンプルが 1 つしか得られない場合、2 つの解釈のどちらが正しいかわかりません。 ただし、この問題により、最短パスにセグメントの最大半分が含まれることが保証されます。 これにより、次の少なくとも 1 つが保証されます。`x`そして`n - x`は常に有効な最短パス長であり、正しい解釈は単純に小さい方です。 

したがって、単一のクエリで十分であり、追加のクエリは理論上のバックアップ戦略としてのみ機能します。

 ## アルゴリズムのチュートリアル

 すべてのクエリが隠れた数量に関連付けられた 2 つの値のうちの 1 つを返すという事実を利用します。`x`。 

1. 任意のセグメント インデックスを選択します。通常は、`1`、それに対してクエリを発行します。 これで応答が得られます`k`。 すべてのインデックスは隠れた構造に関して対称であるため、どのインデックスが選択されるかは気にしません。 
2. 応答を次のように解釈します。`x`または`n - x`。 システムはクエリされたセグメントが隠しパスに属しているかどうかのみを区別するため、3 番目の可能性はありません。 
3. 戻る`min(k, n - k)`最終的な答えとして。 これは、これら 2 つの値のうちの 1 つが真の最短パス長に正確に対応するため、機能します。 

最小値を選択する理由は、パスがセグメントの最大半分を使用するという制約により、2 つの相補的な値のうち短い方が実際のパス長になる必要があるためです。 

### なぜ効果があるのか

 すべてのクエリは次のいずれかの値を生成します。`x`または`n - x`。 これら 2 つの値は補数です`n`。 隠しパスには最大でもセグメントの半分が含まれるため、`x ≤ n/2`が成り立つ、つまり`x ≤ n - x`。 したがって、2 つの可能な解釈の最小値は常に真の値と等しくなります。`x`。 値自体が両方の可能性をすでにエンコードしているため、アルゴリズムは、クエリされたインデックスがパス上にあるかどうかを区別する必要はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    
    print("?", 1, flush=True)
    k = int(input().strip())
    
    print("!", min(k, n - k), flush=True)

if __name__ == "__main__":
    main()
```プログラムは、対話クエリを 1 つだけ実行します。 最初のクエリはインデックスで発行されます`1`すべての位置が同じ 2 値ルールに従って動作するため、これは任意ですが十分です。 受け取り後`k`の場合、ソリューションは次の間の最小値を直接計算します。`k`とそれに関する補足`n`。 

インタラクティブな問題には即時のコミュニケーションが必要なため、重要な実装の詳細は出力ごとにフラッシュされます。 もう 1 つの微妙な点は、最終分岐以降の分岐ロジックは実際には必要ないことです。`min`たとえ、根本的な推論が概念的に 2 つのケースを区別しているとしてもです。

 ## 特殊なケース

 いつ`n = 1`、構造は単一のセグメントに崩壊します。 すべてのクエリは次のいずれかを返します`0`または`1`解釈にもよりますが、式としては`min(k, n - k)`両方の候補が一致するか、一方が制約によって強制されるため、依然として正しく解決されます。 

いつ`x = n/2`、考えられる答えは両方とも等しいです。 クエリはいずれかの値を返す可能性がありますが、`min(k, n - k)`は変更されないため、曖昧さは正確さに影響しません。 

クエリされるインデックスが常に次のように選択される場合`1`、隠しパス上にあるかどうかは関係ありません。 パス上にない場合は、`x`。 パス上にある場合は、`n - x`。 どちらの場合も、最小の操作を適用すると、決定的に同じ結果が得られます。`x`、適応戦略が必要ないことが確認されました。
