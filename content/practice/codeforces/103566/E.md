 ## 解決策
 ## 問題の理解

 N 人の参加者の集合が与えられ、各参加者は、潜在的な「友人参照」Fi、準備状況フラグ Pi、およびタイムスタンプ Ti の 3 つの情報によって記述されます。 このプロセスでは、最初はすべて 0 の派生配列 cnt を定義します。これは、各参加者を適格な友人として「検証」した他の参加者の数をカウントします。 

各参加者 i について、i が他の人の友人 Fi の有効な推薦者として機能できるかどうかを判断しようとします。 Fi がゼロ以外の場合、参加者 i は Fi の数の増加に貢献する可能性がある人物とみなされます。 ただし、これは 2 つの独立した条件を満たす場合にのみ許可されます。Pi は正である必要があり、特定の資格チェックに合格していることを意味します。Ti は厳密に TFi より大きくなければなりません。つまり、友達が参照している友達よりも後に登録したことを意味します。 

すべての条件が満たされる場合、cnt[Fi] を 1 ずつインクリメントします。 すべての参加者を処理した後、各参加者 i を再度調べて、cnt[i] が少なくとも 2 であるインデックスを出力します。出力はインデックスの昇順である必要があります。 

入力サイズ N は、ソリューションを形成する重要な要素です。 直接スキャンでは参加者ごとに一定量の作業のみを実行するため、O(N) または O(N log N) のアプローチが必要です。 参加者のペアに対するネストされたチェックを伴うものはすべて O(N²) になりますが、N が 2⋅10⁵ などの典型的な Codeforce 制約に達すると、これは実行不可能になります。 

Fi がゼロの場合、微妙なエッジ ケースが発生します。 その場合、参加者はカウントに寄与せず、cnt[0] にインデックスを付けようとしても、慎重に扱わないと無効になります。 タイムスタンプが等しい場合、別のエッジ ケースが発生します。条件は厳密に Ti > TFi であるため、等価性は失敗するはずであり、非厳密な比較を使用する単純な実装ではカウントが誤って増加します。 

最後の落とし穴は、複数の参加者が同じ Fi に独立して貢献できることを忘れていることです。 これは、cnt がブール配列ではなく周波数アキュムレータであり、重複した寄与が期待されることを意味します。 

## アプローチ

 ブルートフォース解釈は定義を直接シミュレートします。すべての参加者 i について、他のすべての参加者 j をスキャンし、j が cnt[i] に貢献できるかどうかを確認します。 これにより、各ペアの Fi、Pi、Ti に関係する条件をチェックすることになり、プロセスが効果的に 2 次になります。 論理的には正しいですが、最悪の場合、約 N² の比較が行われることになり、N が大きい場合には速度が遅すぎます。 

重要な観察は、各参加者が単一のターゲット指標 Fi に最大 1 単位の情報を寄与し、この寄与は他のすべての参加者とは独立して決定されるということです。 cnt へのさまざまな更新間に依存関係はありません。これは、単一の線形パスですべての寄与を計算できることを意味します。 

各参加者に対して有効な寄稿者を検索する代わりに、すべての参加者を 1 回直接反復し、i ごとに寄稿者としての資格があるかどうかを確認します。 そうであれば、cnt[Fi]をインクリメントします。 これにより、問題は「入力される有効な関係のクエリ」から「出力される有効なエッジの処理」に変換され、ネストされた反復が不要になります。 

cnt を構築した後、2 回目の線形スキャンで cnt[i] ≥ 2 のすべてのインデックスが抽出されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | O(N) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべての配列 F、P、および T を読み取ります。これらは、各参加者から別の参加者への有向の潜在的な寄与を定義します。 構造は静的であるため、動的更新は必要ありません。 
2. cnt をサイズ N のすべて 0 の配列として初期化します。 これにより、各参加者が受け取る有効な投稿者の数が累積されます。 
3. 各参加者 i を 1 から N まで繰り返します。各 i について、それが他の人のカウントに寄与するかどうかを決定します。 
4. Fi がゼロに等しい場合は、i を直ちにスキップします。 これにより、無効なインデックス作成が回避され、コントリビューション ターゲットが存在しないことが反映されます。 
5. Pi が正かどうかを確認します。 Pi が 0 の場合は貢献できないのでスキップします。 この条件は、認定ステップに失敗した参加者を除外します。 
6. Ti が厳密に TFi より大きいかどうかを確認します。 そうでない場合は、i をスキップしてください。 これにより、後の参加者のみが以前の参加者を検証できるという順序制約が強制されます。 
7. すべてのチェックに合格した場合、cnt[Fi] を 1 つ増やします。 これは、Fi が 1 人の有効なサポート参加者を獲得したことを記録します。 
8. すべての参加者を処理した後、i を 1 から N まで繰り返し、cnt[i] が少なくとも 2 であるすべてのインデックスを収集します。これらは、十分な有効な確認を受け取った参加者です。 
9. 収集されたインデックスを昇順で出力します。i を昇順で探索するため、これは自動的に保証されます。 

正確さは、ステップ 7 の後、i がすべての制約の下で x に 1 回だけ寄与するように、cnt[x] が参加者の数 i と等しくなるという不変条件に基づいています。 各参加者は独立して処理され、最大でも 1 つの増分に寄与するため、二重カウントや省略は発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    F = [0] + list(map(int, input().split()))
    P = [0] + list(map(int, input().split()))
    T = [0] + list(map(int, input().split()))

    cnt = [0] * (n + 1)

    for i in range(1, n + 1):
        f = F[i]
        if f == 0:
            continue
        if P[i] <= 0:
            continue
        if T[i] <= T[f]:
            continue
        cnt[f] += 1

    res = []
    for i in range(1, n + 1):
        if cnt[i] >= 2:
            res.append(i)

    print(*res)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムを正確に反映しています。最初のパスで頻度カウントが構築され、2 番目のパスで有効なインデックスが抽出されます。 重要な点は厳密な不平等チェックです`T[i] <= T[f]`これは、等しいタイムスタンプと小さいタイムスタンプの両方を正しく拒否する方法で記述されています。 

インデックス付けは、配列を 1 ベースの形式にシフトすることで処理されます。これにより、有効な参加インデックスと Fi に使用されるゼロ センチネルとの間の混乱が回避されます。 

## 実用的な例

 ### 例 1

 参加者が有効な貢献の単純なチェーンを形成する小さな例を考えてみましょう。 

入力：```
n = 4
F = [0, 1, 1, 2]
P = [0, 1, 1, 1]
T = [0, 1, 2, 3]
```加工中にcntを追跡する。 

| 私 | フィ | 円周率 | ティ | 条件が成立します | CNTアップデート | CNTの状態 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1 | いいえ | なし | [0,0,0,0] |
 | 2 | 1 | 1 | 2 | はい | cnt[1]++ | [0,1,0,0] |
 | 3 | 1 | 1 | 3 | はい | cnt[1]++ | [0,2,0,0] |
 | 4 | 2 | 1 | 3 | はい | cnt[2]++ | [0,2,1,0] |

 最終的な cnt は [0,2,1,0] です。 cnt ≥ 2 の参加者を出力します。これは参加者 1 のみです。 

このトレースは、複数の独立した寄与が干渉することなくcntに正確に蓄積していることを示している。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての参加者に対して Fi がゼロに等しい場合です。 このシナリオでは、ループによって cnt の増加がトリガーされることはなく、最終出力は空になります。 最初の条件が次のとおりであるため、アルゴリズムはこれを自然に処理します。`if f == 0`無効なインデックス作成を防ぎ、すべての更新をスキップします。 

もう 1 つのエッジ ケースは、有効と思われるペアのタイムスタンプが等しい場合に発生します。 たとえば、Fi = j および Ti = Tj の場合、厳密な不等式により条件は失敗します。 コードでは明示的に使用します`T[i] <= T[f]`平等を拒否し、偶発的な増分が発生しないようにします。
