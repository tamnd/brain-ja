 ## 解決策
 ## 問題の理解

 複数のマッチ棒のセットが与えられ、各マッチ棒は整数の長さを持ちます。 同じ長さが何度も現れる可能性がありますが、重要なのは各長さが何回現れるかだけです。 これらのマッチ棒から 2 つの可能なタイプのタワーを構築したいと考えており、各タイプについて、建設ルールに基づいて達成可能な最適なタワーの高さを計算したいと考えています。 

最初のタイプでは、タワーは正方形のみで構成されます。 辺の長さ i の正方形は、同じ長さ i のマッチ棒から作られ、正方形を垂直に積み重ねると、固定パターンで追加のマッチ棒が消費されます。 長さ i を固定する場合、その長さのマッチ棒のみを使用し、完全な正方形のレベルがいくつ構築できるかを知りたいとします。 各レベルは最初のレベル以降、長さ i のマッチ棒を 3 本消費するため、Fi レベルが構築される場合、必要なマッチ棒の総数は 1 + 3Fi になります。 利用可能な電源は cnt[i] であるため、Fi は 1 + 3Fi ≤ cnt[i] となる最大の整数です。 各レベルは高さ i に寄与するため、答えへの寄与は Fi · i になります。 

2 番目のタイプでは、タワーは長方形のレベルで構成されます。 各レベルには、長さ h の 2 つの垂直側面と、長さ w の水平上部が 1 つ必要です。 重要なのは、垂直コンポーネントと水平コンポーネントで異なる長さが使用されることです。 垂直の長さ h を固定すると、垂直スティックの数は cnt[h] となるため、最大で Floor(cnt[h] / 2) レベルをサポートできます。 長さ w の水平トップの場合、最初のレベル以降の各レベルにはトップが 1 つ必要なので、最大で cnt[w] − 1 レベルを構築できます。 したがって、完全なレベルの数はこれら 2 つの量の最小値であり、高さの寄与は h と w に依存します。 

入力サイズでは最大 2 · 10^5 の異なる長さが許可されるため、長さのすべてのペアを直接試行するソリューションは遅すぎます。 すべての (h, w) ペアに対する二次チェックは 4 · 10^10 回の演算のオーダーになりますが、これは一般的な制限の下では不可能です。 固定された h に対して w がどのように最適に動作するかという構造を利用する必要があります。 

縦横に同じ長さを使用すると、微妙なエッジケースが現れます。 その場合、2 つの制約が相互作用するため、二重にカウントしたり、独立した供給を誤って想定したりすることを避ける必要があります。 もう 1 つの問題は、cnt[i] が非常に小さい場合、特に 1 または 2 の場合です。この場合、除算と減算を含む式は、慎重に扱わないとゼロまたは負の値を生成する可能性があります。 

## アプローチ

 正方形の場合の直接的なアプローチは簡単です。 すべての決定は i に対してローカルであるため、長さ i ごとに cnt[i] から Fi を計算します。 正方形には長さが混在しないため、これは最適です。 

長方形の場合、単純なアプローチは、すべてのペア (h, w) を試し、min(cnt[h] / 2, cnt[w] − 1) を計算し、高さによって重み付けされた最良のものを取得することです。 これはすべての構造を正しくモデル化しますが、O(A^2) ペアのため速度が遅すぎます。 

重要な観察は、h が固定されている場合、制限要因は通常、垂直方向の容量 cnt[h] / 2 であるということです。w が重要になるのは、cnt[w] − 1 がこの値より小さい場合、つまり水平方向のスティックがボトルネックになる場合だけです。 この領域では、cnt[w] を増加させると最小値を改善または維持することしかできないため、cnt[w] を最大化する w が必要になります。 

これにより、w の検索が大幅に減少します。 すべての w を考慮する代わりに、最も頻度の高い長さを主に考慮します。これは、それが cnt[w] を最大化し、ボトルネックになる可能性が最も低いためです。 また、2 番目に頻度の高い長さも考慮する必要があります。最も頻度の高い長さを h として使用すると、独立性を損なわずにそれを w として再利用できないため、代替候補が必要になります。 

したがって、各 h について、一定数の候補 w 値、つまり全体的に最も頻度の高い長さ、および h がそれに等しい特殊な場合には 2 番目に頻度の高い長さのみを評価します。 これにより、問題は A にわたる線形時間に短縮されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 周波数ベースの最適化 | O(A) | O(A) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、周波数配列 cnt を構築します。ここで、 cnt[x] には、長さ x のスティックが何本存在するかが格納されます。 これにより、タワー内のあらゆる役割に使用できるスティックの数に常にアクセスできるようになります。 

次に、すべての長さ i にわたって反復して、最良の四角形タワーの寄与を計算します。 最初のスティックの後は追加レベルごとに 3 つのスティックが必要となるため、各 i について Fi を cnt[i] // 3 として計算します。 高さを Fi * i として計算し、最大値を追跡します。 

次に、cnt で最も頻繁に使用される 2 つの長さを特定します。 最も頻度の高い長さは、cnt[w] を最大化し、cnt[w] − 1 を最大化するため、水平方向のトップの最適な候補です。同じプールを最適に再利用できないため、最も頻度の高い長さが垂直方向として使用される場合のフォールバックとして 2 番目に頻度の高い長さが必要になります。 

その後、考えられるすべての垂直方向の長さ h について繰り返します。 各 h について、垂直方向の容量を cnt[h] // 2 として計算します。水平方向の候補 w については、最良の周波数の選択のみを考慮します。 各候補 w について、水平方向の容量を cnt[w] − 1 として計算します。レベルの数はこれら 2 つの値の最小値であり、結果の高さの寄与を計算します。 

すべての有効な (h, w) 選択肢に対して答えを更新します。 

### なぜ効果があるのか

 垂直方向の長さ h が固定されている場合、タワーの高さは垂直方向と水平方向の供給量の両方によって制限されるレベルの数によって決まります。 垂直方向の項は cnt[h] のみに依存し、水平方向の項は cnt[w] のみに依存します。 目標はレベルの数とともに増加するため、これら 2 つの値の最小値を最大化する必要があります。 

cnt[h] / 2 が小さい場合、cnt[w] − 1 ≥ cnt[h] / 2 の w はいずれも同等に優れているため、正確な選択ではなく、実現可能性のみが重要になります。 cnt[h] / 2 が大きい場合、cnt[w] がボトルネックとなり、cnt[w] を最大化することが最適です。 したがって、h と競合するかどうかに応じて、最大の周波数と 2 番目に大きい周波数のみが重要になります。 

これにより、最適な構成を失うことなく、w の有効な検索スペースが削減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    MAXA = 200000
    cnt = [0] * (MAXA + 1)

    for x in arr:
        cnt[x] += 1

    ans = 0

    for i in range(MAXA + 1):
        f = cnt[i] // 3
        ans = max(ans, f * i)

    first = 0
    second = 0

    for i in range(MAXA + 1):
        if cnt[i] > cnt[first]:
            second = first
            first = i
        elif cnt[i] > cnt[second]:
            second = i

    best_ws = {first, second}

    for h in range(MAXA + 1):
        if cnt[h] == 0:
            continue
        vert = cnt[h] // 2

        for w in best_ws:
            if cnt[w] == 0:
                continue
            horiz = cnt[w] - 1
            levels = min(vert, horiz)
            if levels > 0:
                ans = max(ans, levels * h)

    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、周波数配列を構築することから始まります。どちらの構築も長さごとのカウントのみに依存するため、これは不可欠です。 平方計算は直接的です。3 つの追加スティックの各グループが 1 つのレベルに寄与するため、整数を 3 で割ると完全なレベルの数が得られます。 

最も頻繁に使用される 2 つの長さの選択は、可能なすべての幅にわたる二次探索を置き換える最適化です。 cnt[h] が大きい場合には次善の w は最小値を改善できないため、cnt[w] を最大化する候補だけが必要になります。 

最後のループでは、各 h を垂直構造として評価し、それを 2 つの可能な w 候補のみと組み合わせます。 垂直方向と水平方向の容量の最小値によってレベルの数が決まり、h を掛けると高さが求められます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、cnt[h] が 1 の場合です。その場合、cnt[h] // 2 は 0 なので、w に関係なく、垂直方向の容量によって長方形の構築が妨げられます。 レベルがゼロになり何も寄与しないため、アルゴリズムはこれを自然に処理します。 

もう 1 つは、最も頻繁に使用される長さを h としても使用する場合です。 その場合、制約のない方法で水平頂点について cnt[w] = cnt[h] に依存することはできません。 2 番目に多い候補により、引き続き有効な代替案を検討できるようになります。 たとえば、すべてのスティックの長さが同じである場合、2 番目の候補は実質的に使用されず、長方形は両方の役割が同じプールを共有する制約された形式に正しく縮小されます。 

最後のエッジ ケースは、cnt[w] = 1 の場合です。その場合、cnt[w] − 1 = 0 となり、w は単一レベルさえもサポートできないことを意味します。 レベルはゼロになり、最大値には影響しないため、これらの候補は無視しても問題ありません。
