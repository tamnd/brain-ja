 ## 解決策
 ## 問題の理解

 私たちには、シャフトによって接続された歯車の有向ネットワークが与えられています。 各シャフトはトルクをあるギアから別のギアに伝達しますが、そのシャフトの効率パーセンテージによって決定される、入ってくるトルクの一部のみが残ります。 ギアからシャフトの場合`u`ギアに`v`効率がある`e`、その後任意のトルク`x`に到着`u`貢献する`x * (e / 100)`で`v`。 

各クエリについて、ソース ギアに固定トルクを適用することから始めます。`s`。 そのトルクは有向エッジに沿って伝播し、途中で効率が倍増します。 ターゲットギアまでの可能なパスが複数ある場合`t`、可能な最大の伝達トルクを考慮しない限り、トルクの寄与はさまざまなパスにわたって直線的に加算されません。 私たちは達成可能な最高の結果を望んでいますので、事実上、`s`に`t`これはエッジ効率の積を最大化し、その最大積を初期トルクに掛けます。 

したがって、各クエリは、有向重み付きグラフで乗算パスの最大値を見つけることになります。ここで、エッジの重みは、次の確率です。`[0, 1]`。 

制約は十分に小さいため、クエリごとに最短パス スタイルの計算を行うことができます。 と`n ≤ 1000`そして`m ≤ 5000`、クエリごとにダイクストラのようなアルゴリズムを実行することは実現可能です。`q ≤ 100`。 Floyd-Warshall のような単純な全ペアの前処理アプローチでは、約`n^3 ≈ 10^9`操作は境界線に達していますが、Python では遅すぎます。 クエリごとのヒープベースのベストパス検索の再実行は、制限内で問題なく実行できます。 

複数のパスを考えると、微妙な問題が発生します。 貪欲な緩和では、常に最良の既知の積を確実に伝播する必要があります。これは、次善の中間値が高効率エッジを介して拡張された場合に後で最適になる可能性があるためです。 これにより、BFS スタイルの「先着順」アプローチが排除されます。 

重要なエッジケース:

 まず、到達不可能な目標。 からのパスがない場合`s`に`t`、答えは次のようになります。`0`、小さな浮動小数点値ではありません。 たとえば、次の場合`s = 1`、`t = 2`、パスが存在しない場合、正しい出力は次のようになります。`0`たとえ内部距離が に留まるとしても、`0`または`-inf`表現にもよりますが。 

第二に、効率が 100% を超えるサイクルは不可能です。`e ≤ 100`なので、増幅は存在しません。 これにより、パス積がループによって増加しないことが保証されるため、ダイクストラ式の単調性が維持されます。 

3 番目に、多くのパーセンテージを乗算するため、浮動小数点の精度が重要になります。 必要な誤差許容度は次のとおりであるため、倍精度を使用するだけで十分です。`1e-6`。 

## アプローチ

 ブルートフォースのアイデアは、考えられるすべてのパスを列挙することです。`s`に`t`、各パスに沿った効率の積を計算し、最大値を取得します。 これは問題の定義と直接一致するため、正しいです。 ただし、サイクルを含むグラフ内のパスの数は指数関数的に増加する可能性があります。 適度に接続されたグラフであっても、個別の単純なパスの数が実現可能な限界を超えて爆発的に増加する可能性があり、このアプローチは小さなインスタンスを超えると使用できなくなります。 

より構造化されたビューは、各パスが乗算スコアに寄与することに注目することです。 対数を取得してエッジの重みを変換すると、積の最大化は対数値の合計の最大化と同じになります。 これにより、問題は対数空間で正のエッジの重みをもつグラフの最長経路問題に変換されます。 ただし、値のログは`(0,1]`が正ではない場合、実際には負の重みの合計を最大化しています。これは、否定後の非負のエッジ コストを持つグラフ内の最短パスを見つけることと同じです。 符号を明示的に変換する代わりに、緩和を最大化として扱い、乗算の重みに対してダイクストラ スタイルのアルゴリズムを直接実行する方が簡単です。 

重要な観察は、ノードに対する最適な値は緩和下では単調であるということです。ノードの積が大きくなると、それを拡張すると、近傍のより良い、または同等の候補しか生成できなくなります。 これにより、現在最もよく知られている状態を常に展開する優先キューのアプローチが可能になります。 

クエリは最大 100 個あるため、クエリごとにこの単一ソースの最大製品検索を実行すると効率的です。

 | 最適 (クエリごとのダイクストラ) | O(q · m log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 各クエリを独立して処理します。 

### 1. 効率を乗算の重みに変換する

 各エッジ`u → v`効率よく`e`要素として扱われる`e / 100`。 これはパスに沿って乗算する値です。 

### 2. 最適トルク配列を初期化する

 配列を維持します`dist[]`どこ`dist[i]`ノードに到達できる初期トルクの最大部分を保存します`i`。 すべての値を次のように設定します`0`、 を除外する`dist[s] = 1`。 

これは、伝達損失が発生する前に、ソースでフルトルクが維持されていることを表します。 

### 3. 最大優先度のキューを使用する

 状態を保存します`(current_best_factor, node)`プライオリティ キュー内で、最も高い係数から順に並べられます。 まずは`(1, s)`。 

最大ヒープ動作 (負の値または逆比較によって実装) を使用して、常に最も有望な部分パスを最初に展開します。 

### 4. 発信エッジをリラックスする

 ノード処理時`u`電流係数あり`f`、私たちはすべての隣人を改善しようとします`v`経由`f * (e / 100)`。 この値がより大きい場合`dist[v]`、更新します`dist[v]`そしてそれをヒープにプッシュします。 

このステップにより、ダイクストラの緩和と同様に、ノードに対する改善が即座に前方に伝播されることが保証されます。 

### 5. 早期停止はオプションです

 ターゲットノードをポップしたら停止できます`t`その時点で最適な値が見つかったため、プライオリティ キューから削除されます。 

### 6. 結果の出力

 もし`dist[t]`残る`0`、ノードに到達できないため、次のように出力します。`0`。 それ以外の場合は乗算します`dist[t]`イニシャルトルクにより`T`。 

### なぜ効果があるのか

 核となる不変条件は、ノードが優先キューからポップされるたびに、関連付けられた値がそのノードで達成可能な最大乗算係数になるということです。 すべてのエッジの重みが含まれているため、これは当てはまります。`[0, 1]`したがって、パスを拡張してもその値が増加することはありません。 したがって、すでに処理されたノードへの後で検出されたパスは、すでに最終化された最適な値を超えることはできません。 これにより、最小化ではなく最大化することを除いて、プロセスの正確さはダイクストラのアルゴリズムと同じになります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v, e = map(int, input().split())
        w = e / 100.0
        g[u].append((v, w))

    for _ in range(q):
        s, t, T = map(int, input().split())

        dist = [0.0] * (n + 1)
        dist[s] = 1.0

        pq = [(-1.0, s)]

        while pq:
            neg_f, u = heapq.heappop(pq)
            f = -neg_f

            if f < dist[u]:
                continue

            if u == t:
                break

            for v, w in g[u]:
                nf = f * w
                if nf > dist[v]:
                    dist[v] = nf
                    heapq.heappush(pq, (-nf, v))

        print(dist[t] * T if dist[t] > 0 else 0.0)

if __name__ == "__main__":
    solve()
```グラフは、事前に計算された確率を含む隣接リストとして保存されます。 クエリごとに、`dist`各クエリには独立したソースがあるため、配列になります。 

プライオリティ キューは負の値を使用して最大ヒープをシミュレートします。`heapq`最小ヒープです。 古い状態のチェックも含まれています`if f < dist[u]`古いエントリをスキップします。 

到着したら早めの退場`t`実際には実行時間を短縮しますが、正確性のためには必要ありません。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ターゲットに到達できない場合です。 次のものがあるとします。```
3 1 1
1 2 50
1 3 100
```からの道はありません`3`に`1`、アルゴリズムが初期化されます`dist[3]=1`しかし決して届かない`1`。 プライオリティ キューはターゲットにアクセスせずに空になり、そのまま残ります。`dist[1]=0`。 出力は正しく次のようになります`0`。 

もう 1 つのケースは、長さと効率が異なる複数のパスが存在する場合です。```
1 → 2 → 3 (0.5 * 0.5 = 0.25)
1 → 3 (0.2)
```アルゴリズムが最初に発見するのは`3`と`0.2`、その後、それを次のように改善します`0.25`。 緩和ステップでは、ヒープから最良の値が抽出された場合にのみノードを最終決定するため、改善が無視されないことが保証されます。 

3 番目のケースは自己完結型サイクルです。 すべての重みが最大であるため、`1`、サイクルを繰り返し実行しても、製品を増やすことはできません。 たとえサイクルがあったとしても、無限の改善ループを生み出すことはできません。 優先キューは当然、より悪い値を持つ再訪問ノードを無視し、無限処理を防ぎます。
