 ## 解決策
 ## 問題の理解

 非常に大きな整数の配列を維持し、それに対する 2 種類の演算をサポートしています。 最初の操作では、連続セグメント内のすべての要素、つまり各値にアフィン変換を適用します。`a[i]`に置き換えられます`a[i] * c + d`。 2 番目の演算では、セグメント内で、固定素数を法とした後、指定された剰余と等しくなる要素の数を尋ねます。$P = 10^5 + 3$。 

主な問題点は、更新が単純な加算や代入ではなく、線形変換であり、クエリが素数を法とする値にのみ依存することです。 したがって、システムはモジュロ構造を維持する方法で進化します。$P$ただし、変換が繰り返される場合でも、範囲全体の頻度をカウントする必要があります。 

この制約により、クエリごとの要素ごとの処理が不可能であることが明確になります。 と$n \le 10^6$そして最大まで$q \le 10^4$、クエリごとに対数の要素に触れることさえ許容されますが、クエリごとに線形セグメントに触れることは許容されません。 メモリ制限が大きいため、ノードごとの状態による重いセグメント ツリーまたはブロック分解が可能です。 

微妙なエッジケースは、残基を効果的に「混合」するアフィン更新の繰り返しから発生します。 たとえば、私たちが適用すると、`(a[i] = a[i] * c + d)`繰り返し、値をモジュロでラップすることができます$P$重要な方法で更新され、更新順序が異なると異なる分布が生成されます。 もう 1 つの落とし穴は、複数のレイヤーにわたるアフィン マップの構成を考慮せずに、ローカルでモジュラー値のみを追跡できると仮定していることです。 

単純な間違いは、モジュロを更新中にではなくクエリ中にのみ適用することです。これにより、オーバーフローや不正な変換が発生します。 もう 1 つは、線形更新が単純な遅延追加を可能にする方法で相互に行われると仮定することです。 実際、それらは合成の下で非可換半群を形成します。 

## アプローチ

 ブルートフォース手法は簡単です。 更新クエリごとに、セグメントを反復処理します。`[l, r]`そして申請してください`a[i] = a[i] * c + d`。 クエリごとに、再度範囲を反復処理し、モジュロで一致する数をカウントします。$P$。 これは、定義に正確に従い、常に値の一貫性を保つため、正しいです。 

ただし、このアプローチのパフォーマンスは次のとおりです。$O(n)$クエリごとに作業します。 と$n = 10^6$そして$q = 10^4$、最悪の場合のコストは次のとおりです。$10^{10}$実行可能な限界をはるかに超えた操作。 

重要な観察は、各要素の値が、構成可能なアフィン変換の繰り返しによって進化するということです。 更新をすぐにプッシュダウンする代わりに、遅延変換としてセグメント ツリーに保存できます。 各ノードはモジュロ値の頻度表を維持します。$P$、遅延伝播は保留中のアフィン関数を保存します`(c, d)`古い値を新しい値にマッピングします。 

重要な構造は、頻度表にアフィン変換を適用することは、格納されているすべての剰余を再マッピングすることと同じであるということです。 以来$P$は固定されており、に比べて比較的小さい$n$、各ノードで残基の分布を維持し、インデックスの再作成によってそれらを更新できます。 

これにより、問題は、サイズの周波数配列を格納するセグメント ツリー ノードの維持に変わります。$P$一方、遅延タグは、これらの周波数を並べ替えるアフィン マップを表します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 周波数 + 遅延アフィン マップを使用したセグメント ツリー | O((n + q) log n * P) 償却 | O(n log n * P) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ノードが周波数配列を格納するセグメント ツリーを構築します。`cnt[v]`すべての残基に対して`v`モジュロ$P$。 各リーフが初期化されます`cnt[a[i] % P] = 1`。 これにより、任意のセグメントの値の分布を直接表現できます。 
2. 各ノードに対して、遅延アフィン タグも維持します`(c, d)`保留中の変換を表す`x -> x * c + d mod P`。 識別タグは、`(1, 0)`。 
3. 遅延タグをノードに適用する場合、子はすぐには更新されません。 代わりに、インデックスを再マッピングすることでノードの周波数配列を変換します。古い剰余はそれぞれ`x`に貢献する`(x * c + d) % P`。 アフィン変換は剰余に対して決定論的に作用するため、これにより正確さが保たれます。 
4. 遅延タグを結合するには、関数を作成します。 ノードがすでに変換されている場合`(c1, d1)`そして受け取ります`(c2, d2)`、複合効果は`(c2 * c1 mod P, (c2 * d1 + d2) mod P)`。 これは、関数の置換から得られます。`(c1, d1)`それから`(c2, d2)`。 
5. 更新クエリの場合`[l, r, c, d]`では、セグメント ツリーを走査し、完全にカバーされたすべてのノードにアフィン タグを適用します。 部分的なオーバーラップは再帰的にプッシュダウンされます。 
6. お問い合わせの場合`[l, r, x]`、完全に範囲内のセグメント ツリー ノードから寄与を収集し、合計します。`cnt[x]`。 保留中の遅延変換は、ノードの周波数配列にアクセスする前にプッシュする必要があります。 
7. 遅延伝播により、各セグメント ノードが生の形式でも変換された形式でも常に一貫していることが保証され、完全な再計算の繰り返しが回避されます。 

### なぜ効果があるのか

 各セグメント ツリー ノードは剰余モジュロのマルチセットを表します$P$。 アフィン変換はこの剰余空間上の順列として機能し、変換の構成は同じ代数構造内に残ります。 不変条件は、すべてのノードの周波数配列が、正しい順序で適用されるすべての保留中の変換の下で、そのセグメントの値に常に正確に対応するということです。 アフィンマップの合成は結合的かつ閉モジュロであるため$P$、遅延更新では情報が失われることはなく、すべてのクエリは正しく変換されたヒストグラムを読み取ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 100000 + 3

class Node:
    __slots__ = ("cnt", "c", "d")
    def __init__(self):
        self.cnt = None
        self.c = 1
        self.d = 0

def compose(c1, d1, c2, d2):
    return (c2 * c1) % MOD, (c2 * d1 + d2) % MOD

def apply(node, c, d):
    if node.cnt is None:
        return
    new_cnt = [0] * MOD
    for v, f in enumerate(node.cnt):
        if f:
            nv = (v * c + d) % MOD
            new_cnt[nv] += f
    node.cnt = new_cnt

def build(a, seg, idx, l, r):
    if l == r:
        seg[idx] = Node()
        seg[idx].cnt = [0] * MOD
        seg[idx].cnt[a[l] % MOD] = 1
        return
    m = (l + r) // 2
    seg[idx] = Node()
    build(a, seg, idx * 2, l, m)
    build(a, seg, idx * 2 + 1, m + 1, r)
    seg[idx].cnt = [seg[idx*2].cnt[i] + seg[idx*2+1].cnt[i] for i in range(MOD)]

def push(seg, idx):
    node = seg[idx]
    if node.c == 1 and node.d == 0:
        return
    apply(node, node.c, node.d)
    if idx * 2 < len(seg):
        lc, ld = seg[idx*2].c, seg[idx*2].d
        rc, rd = seg[idx*2+1].c, seg[idx*2+1].d
        seg[idx*2].c, seg[idx*2].d = compose(lc, ld, node.c, node.d)
        seg[idx*2+1].c, seg[idx*2+1].d = compose(rc, rd, node.c, node.d)
    node.c, node.d = 1, 0

def update(seg, idx, l, r, ql, qr, c, d):
    if qr < l or r < ql:
        return
    if ql <= l and r <= qr:
        node = seg[idx]
        node.c, node.d = compose(node.c, node.d, c, d)
        return
    push(seg, idx)
    m = (l + r) // 2
    update(seg, idx*2, l, m, ql, qr, c, d)
    update(seg, idx*2+1, m+1, r, ql, qr, c, d)
    seg[idx].cnt = [seg[idx*2].cnt[i] + seg[idx*2+1].cnt[i] for i in range(MOD)]

def query(seg, idx, l, r, ql, qr):
    if qr < l or r < ql:
        return 0
    if ql <= l and r <= qr:
        return seg[idx].cnt[target]
    push(seg, idx)
    m = (l + r) // 2
    return query(seg, idx*2, l, m, ql, qr) + query(seg, idx*2+1, m+1, r, ql, qr)

n, q = map(int, input().split())
a = list(map(int, input().split()))
seg = [None] * (4 * n)
build(a, seg, 1, 0, n-1)

for _ in range(q):
    parts = list(map(int, input().split()))
    if parts[0] == 1:
        _, l, r, c, d = parts
        update(seg, 1, 0, n-1, l-1, r-1, c % MOD, d % MOD)
    else:
        _, l, r, x = parts
        target = x % MOD
        print(query(seg, 1, 0, n-1, l-1, r-1))
```セグメント ツリーは、ノードごとの完全な残差ヒストグラムを使用して構築されます。 各更新では子がすぐに書き換えられるわけではありません。 代わりに、アフィン変換を蓄積します。`(c, d)`形状。 プッシュするときに、ヒストグラムを再マップすることで変換を具体化し、構成された変換を子に伝播します。 

微妙な点は構成順です。 アップデート`(c, d)`既存の遅延変換の後に適用する必要があるため、合成は次のように行われます。`compose(existing, new)`正しい順序で。 これを逆にすると、関数の連鎖が正しく行われなくなります。 

クエリはグローバルに依存します`target`各クエリは単一の残基カウントを要求するため、簡単にするために変数を使用します。

 ## 特殊なケース

 重要なエッジ ケースは、きれいに構成されるはずのアフィン更新が繰り返されることです。 応募を検討してください`(x -> 2x + 1)`単一の要素に対して 0 から始まる 2 回の更新。最初の更新では 1 が生成され、2 回目の更新では 3 が生成されます。合成された変換`(2,1) ∘ (2,1)`生成する`(4,3)`、そしてそれを一度適用すると、`0*4 + 3 = 3`、段階的な進化に合わせて。 セグメント ツリーはまさにこのプロパティに依存しており、合成関数はそれを強制します。 

もう 1 つのケースは、セグメントが更新によって完全にカバーされ、その後に部分的なクエリが実行される場合です。 更新は遅延するため、変換をプッシュする前にノードをクエリしてはなりません。 プッシュ ステップにより、保存されたヒストグラムが実際の値と一致することが保証されます。 これがないと、クエリで古い周波数が読み取られる可能性があります。 

最後のケースは次のような場合です。`c = 0`。 アフィン マップはセグメント内のすべての値を折りたたんで、`d`。 再マッピングのステップ`apply`すべてのカウントを単一の残基に正しく集中させ、組成が維持されるため、繰り返し適用しても安定した状態が維持されます。`(0, d)`チェーン下の動作。
