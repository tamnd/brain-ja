 ## 解決策
 ## 問題の理解

 私たちは、各頂点をプリオーダー DFS トラバーサルの開始点として選択できるツリーを操作しています。 このような走査では、あるノードにアクセスし、その近傍を任意の順序で再帰的に走査し、すべての頂点の線形シーケンスを生成します。 隣接順序は自由であるため、各開始頂点は単一の固定トラバーサル シーケンスではなく、有効な事前順序順列のファミリー全体に対応します。唯一の構造上の制約は、各サブツリーが一度入力されると連続ブロックとして表示されることです。 

頂点ごとに$u$で表します$S_u$から始まるこのような DFS を実行することによって取得できるすべてのシーケンスのセット$u$、各ステップで子の順序を変更します。 2 つの頂点が与えられた場合$u$そして$v$、考えられるすべてのシーケンスのペアを比較します。$a_1 \in S_u$そして$a_2 \in S_v$、定義します$f(u,v)$このようなペア間の最小可能な LCS 長として。 

ここでの LCS は、同じ頂点セットの 2 つの順列に対して計算されますが、主な問題点は、サブシーケンス構造の点で 2 つのシーケンスを可能な限り類似しないようにすることを目的として、両方の走査で独立して DFS の子を敵対的に並べ替えることができることです。 

制約により、最大で$2 \cdot 10^5$頂点とクエリを使用するため、前処理後のソリューションは基本的にクエリごとに線形または対数である必要があります。 二次関数または偶数$O(n \log n)$クエリごとのアプローチは、次のような問題につながるため、直ちに実行不可能です。$10^{10}$スケール操作。 

両方のクエリ頂点が同じである場合、微妙なエッジ ケースが発生します。 基礎となるツリーが同一であっても、子を自由に並べ替えられるということは、同じルートからの 2 つの DFS トラバーサルが同一のシーケンスではないことを意味し、LCS が常に$n$それは不正確でしょう。 

もう 1 つの重要なエッジ ケースは、2 つの頂点がツリー内で遠く離れている場合です。 このような場合、多くのノードは独立して並べ替えることができるサブツリーに属しており、DFS 順序の単純な貪欲な調整は、一貫したサブツリー順序を暗黙的に仮定するため、LCS を過大評価します。 

## アプローチ

 定義から直接推論しようとすると、総当り的なアプローチにより、すべての DFS 事前順序順列が列挙されます。$u$、すべてから$v$、すべてのペアの LCS を計算します。 単一のルートの場合でも、すべてのノードがその子の順序を任意に変更できるため、有効な DFS 順序の数は分岐に応じて階乗的に増加します。 これにより、最悪の場合、シーケンスの数が指数関数的になり、すべてのペアを比較することは完全に不可能になります。 

重要な観察は、DFS の順序は異なりますが、すべて同じ分解を考慮しているということです。各ノードは、そのサブツリーに対応する連続したブロック構造に寄与しています。 唯一の柔軟性は、兄弟サブツリーの置換です。 これは、部分列マッチングの観点から、任意の順列を扱っているのではなく、ルート付きツリー構造によって制約された順列を扱っていることを意味します。 

重要な構造の単純化は、2 つの DFS 順序を比較するときに、サブツリーの異なる順序を選択することで、ツリーの大部分を各シーケンス内で独立して「移動」できることです。 結果として、すべての敵対的な構築において一貫して不可避のマッチングに寄与する頂点は、2 つの開始頂点間の一意のパス上にある頂点だけになります。 そのパスから外れたすべてのものを 1 つのトラバースで配置して、他のトラバースでの整列を避ける順序で表示することができます。 

これにより、問題は、後続の位置合わせでどれだけの構造が強制的に残されるかについての推論に帰着しますが、これはツリー内の 2 つの頂点間の距離のみに依存することがわかります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | DFS 命令に対するブルート フォース | 指数 | 指数 | 遅すぎる |
 | 木道減少観察 |$O(n + q)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーを前処理して、最小共通祖先クエリと任意の 2 つのノード間の距離計算をサポートします。 距離をすばやく計算できるようになると、各クエリは単一の式評価に減ります。 

1. ツリーを任意に (たとえばノード 1 で) ルートし、DFS を実行して親ポインターと深さを計算します。 これにより、LCA を効率的に計算できる構造が確立されます。 
2. LCA クエリ用のバイナリ リフティング テーブルを構築します。 これにより、任意の 2 つのノードの最小共通祖先を対数時間で計算できます。これはクエリの数が多いために必要です。 
3. クエリごとに$(u, v)$、標準恒等式を使用してそれらの間の距離を計算します。$$\text{dist}(u,v) = \text{depth}(u) + \text{depth}(v) - 2 \cdot \text{depth}(\text{LCA}(u,v)).$$4. の値を出力します。$f(u,v)$、間のパス上のエッジの数に対応します。$u$そして$v$、つまり$\text{dist}(u,v)$。 

これが機能する理由は、DFS プレオーダー シーケンスのどのペアでも、兄弟サブツリーを自由に並べ替えて、サブツリー間の一意の単純なパスの外側にあるすべてのアライメントを破壊できるためです。$u$そして$v$。 ただし、そのパスに沿って、祖先構造により、DFS トラバーサルにおいて一貫して順序を尊重した頂点の最小チェーンが維持されます。 その強制チェーンの長さは 2 つの頂点間のエッジの数と正確に同じであり、敵対的な順序付けによって LCS をこの固有の接続制約よりも小さくすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, q = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

LOG = (n).bit_length()
up = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)

def dfs(u, p):
    up[0][u] = p
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)

dfs(1, 0)

for k in range(1, LOG):
    for v in range(1, n + 1):
        up[k][v] = up[k - 1][up[k - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    bit = 0
    while diff:
        if diff & 1:
            a = up[bit][a]
        diff >>= 1
        bit += 1

    if a == b:
        return a

    for k in range(LOG - 1, -1, -1):
        if up[k][a] != up[k][b]:
            a = up[k][a]
            b = up[k][b]

    return up[0][a]

def dist(a, b):
    c = lca(a, b)
    return depth[a] + depth[b] - 2 * depth[c]

for _ in range(q):
    u, v = map(int, input().split())
    print(dist(u, v))
```実装はバイナリ リフティングを中心に行われます。 DFS は深さと直接の親を固定し、リフティング テーブルは祖先ジャンプを 2 の累乗に圧縮します。 その後、各クエリは LCA 計算に帰着し、その後に距離の定数時間算術式が続きます。 唯一の微妙な部分は、両方のノードを一緒に上にジャンプする前に、深さの調整ステップが正しいことを確認することです。 

## 実用的な例

 1 が 2 と 3 に接続され、3 が 4 と 5 に接続されているツリーを考えてみましょう。$(1,4)$の場合、LCA は 1 であるため、距離は 2 として計算されます。これは、パスが次のとおりであるという考えと一致します。$1 \rightarrow 3 \rightarrow 4$、これには 2 つのエッジが含まれます。 

| ステップ | あなた | v | LCA | 深さ(u) | 深さ(v) | 距離 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | 1 | 4 | - | 0 | 2 | - |
 | LCA後 | 1 | 4 | 1 | 0 | 2 | - |
 | 最終 | 1 | 4 | 1 | 0 | 2 | 2 |

 このトレースは、構造的距離のみが重要であり、サブツリーの順列は最終的な最小化された LCS に影響を与えないことを確認します。 

2 番目の例として、ライン ツリーを取り上げます。$1 - 2 - 3 - 4 - 5$。 問い合わせ用$(2,5)$、LCA は 2、距離は 3 です。強制パスは次のとおりです。$2 \rightarrow 3 \rightarrow 4 \rightarrow 5$、エッジが 3 つ与えられるため、答えは 3 になります。 

| ステップ | あなた | v | LCA | 深さ(u) | 深さ(v) | 距離 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | 2 | 5 | - | 1 | 4 | - |
 | LCA後 | 2 | 5 | 2 | 1 | 4 | - |
 | 最終 | 2 | 5 | 2 | 1 | 4 | 3 |

 これは、完全に縮退したツリーであっても、結果がパスの長さに応じて一貫して動作することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n + q \log n)$| DFS とバイナリ リフティングの前処理、その後クエリごとの LCA |
 | スペース |$O(n \log n)$| 祖先テーブルと隣接関係の表現 |

 前処理は、次の制限内に快適に適合します。$n \le 2 \cdot 10^5$、各クエリは対数時間で応答されるため、最大入力サイズに対してソリューションが効率的になります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    LOG = (n).bit_length()
    up = [[0] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)

    sys.setrecursionlimit(10**7)

    def dfs(u, p):
        up[0][u] = p
        for v in g[u]:
            if v != p:
                depth[v] = depth[u] + 1
                dfs(v, u)

    dfs(1, 0)

    for k in range(1, LOG):
        for v in range(1, n + 1):
            up[k][v] = up[k - 1][up[k - 1][v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        diff = depth[a] - depth[b]
        bit = 0
        while diff:
            if diff & 1:
                a = up[bit][a]
            diff >>= 1
            bit += 1
        if a == b:
            return a
        for k in range(LOG - 1, -1, -1):
            if up[k][a] != up[k][b]:
                a = up[k][a]
                b = up[k][b]
        return up[0][a]

    def dist(a, b):
        c = lca(a, b)
        return depth[a] + depth[b] - 2 * depth[c]

    out = []
    for _ in range(q):
        u, v = map(int, input().split())
        out.append(str(dist(u, v)))
    return "\n".join(out)

 ## 特殊なケース

 両方の端点が同じ頂点である場合、次のようになります。$u=v=3$の場合、LCA は自明のことながらノード自体であり、計算された距離はゼロです。 これは、ノードからノード自体への一意のパスにはエッジが含まれていないため、別個のコンポーネント間のトラバースによって強制されるシーケンス長が存在しないという事実と一致します。 

単一のエッジで接続されているノードの場合、次のようになります。$u=2, v=3$それらが直接リンクされているツリーでは、LCA は 1 つのエンドポイントで、距離は 1 です。DFS 事前注文の柔軟性では、この隣接制約を削除できません。これは、あるノードから別のノードへのトラバーサルはそのエッジを 1 回だけ通過する必要があり、この場合、最小 LCS は 1 に等しくなります。
