 ## 解決策
 ## 問題の理解

 患者には体重がキログラム単位で、処方された薬剤の総投与量がミリグラム単位で与えられます。 この薬には単位体重当たりの安全ガイドラインがあり、体重 1 キログラム当たり 10 ～ 20 ミリグラムの範囲が安全な投与量となります。 タスクは、与えられた投与量と患者の体重に応じたこの許容間隔を比較することによって処方を分類することです。 

具体的には、患者さんの体重を測ると、`w`の場合、最小安全用量は次のようになります。`10w`そして最大安全用量は`20w`。 規定の用量であれば、`d`よりも小さいです`10w`、処方箋が不十分です。 もし`d`よりも大きいです`20w`、安全限界を超えています。 それ以外は許容範囲内です。 

制約は小さく、体重は最大 200、投与量は最大 10000 です。これは、関連するすべての計算が 32 ビット整数内に簡単に収まり、多くのテスト ケースにわたって反復評価を行っても、ケースごとの一定時間では簡単であることを直ちに意味します。 直接の算術比較以外のアルゴリズムは不要です。 

エッジケースは主に境界の等価性に関するものです。 よくある間違いは、境界を包括的な不等式ではなく厳密な不等式として扱うことです。 たとえば、次の場合`w = 10`の場合、安全範囲は次のようになります。`[100, 200]`。 正確な用量`100`安全として分類される必要があり、同様に`200`安全でなければなりません。 もう 1 つの潜在的な間違いは、両方のエンドポイントを正しく再計算することを忘れてしまい、比較が行われてしまうことです。`d`に対して`10`そして`20`重量に基づいてスケーリングする代わりに。 

## アプローチ

 この問題を強引に解釈すると、キログラムあたりの安全な投与量をすべてチェックし、それをスケールして処方箋と比較するというシミュレーションが行われます。 所定の重量に対して`w`からのすべての値を反復処理することを想像できます。`10w`に`20w`かどうかを確認します`d`有効な投与量と一致しているか、範囲外にあります。 これが機能するのは、有効な領域が連続間隔であるため、メンバーシップを列挙によって決定できるためです。 

ただし、これは不必要な過剰行為です。 それでも`w`は小さいですが、実際の問題は概念的なものです。範囲全体を列挙することは、間隔のサイズが線形であり、間隔のサイズが大きくなるにつれて増加します。`w`。 最悪の場合`w = 200`、範囲の長さは 2000 です。まだ小さいですが、このアプローチは構造的に必要以上に悪くなり、制約が拡張されると拡張できなくなります。 さらに重要なのは、キー構造が隠蔽されることです。安全領域は 2 つの線形境界によって完全に定義されます。 

有効なセットは乗算によって決定される単一の区間であることがわかります。 エンドポイントを計算したら`10w`そして`20w`の場合、問題は単純な 3 者間比較に帰着します。 これにより、反復が完全に排除され、決定が定数時間の演算に減ります。

 ## アルゴリズムのチュートリアル

 1. 患者の体重を読み取ります。`w`そして処方された用量`d`。 これら 2 つの値によって安全範囲が完全に決定されるため、追加の入力構造を処理する必要はありません。 
2. 安全性の下限を次のように計算します。`low = 10 * w`。 これは、医療ガイドラインに基づく最小有効量を表します。 
3. 安全性の上限を次のように計算します。`high = 20 * w`。 これは、副作用がリスクになる前の最大安全用量を表します。 
4. 処方された投与量を比較する`d`これらの境界に対して。 もし`d < low`、最小治療閾値に達していないため、「低すぎる」と分類されます。 
5. もし`d > high`、キログラムごとに定義された安全限度を超えているため、「高すぎる」と分類されます。 
6. それ以外の場合は、閉じた区間内にあるため「安全」として分類します。`[low, high]`。 

### なぜ効果があるのか

 安全な投与量の定義は重みにおいて明示的に線形です。つまり、有効な処方はすべて次の条件を満たす必要があります。`10w ≤ d ≤ 20w`。 アルゴリズムはこれらの正確な境界を計算し、直接メンバーシップ テストを実行します。 両方の不等式が徹底的にチェックされ、間隔が連続しているため、有効な値が見逃されることはなく、無効な値が誤って受け入れられることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    w = int(input().strip())
    d = int(input().strip())

    low = 10 * w
    high = 20 * w

    if d < low:
        print("Too Low")
    elif d > high:
        print("Too High")
    else:
        print("Safe")

if __name__ == "__main__":
    main()
```このソリューションは 2 つの整数を読み取り、直ちに医療ルールを数値境界に変換します。 スケーリングを忘れてしまうため、乗算ステップは重要です。`w`問題は定数 10 と 20 との比較に帰着しますが、これは正しくありません。 

決定ロジックは、ケースの厳密な順序付けとして構造化されています。 「低すぎる」チェックは、間隔を下回るすべての値を分離するため、最初に行う必要があります。 「高すぎる」チェックが 2 番目にあり、それを超えるすべての値がカバーされます。 残りの領域のみが安全であるため、冗長な比較が回避されます。

 ## 特殊なケース

 最小重量の場合`w = 1`、安全な間隔は次のようになります`[10, 20]`。 もし`d = 10`、アルゴリズムは次のように計算します。`low = 10`そして`high = 20`、および条件`d < low`は false ですが、`d > high`is false, producing “Safe”. これにより、包括的な下限境界が正しく処理されることが確認されます。 

For a just-below-boundary case like`w = 1`、`d = 9`、同じ間隔を計算します`[10, 20]`。 ここ`9 < 10`すぐにトリガーされるため、出力は「低すぎる」となり、間隔の下で正しい厳密性が示されます。 

最大重量の場合`w = 200`、間隔は`[2000, 4000]`。 もし`d = 4000`、両方の比較が失敗し、結果は「安全」となり、上限が正しく含まれていることを確認します。 もし`d = 3999`、条件`d < 2000`は誤りですが、`d > 4000`false だけでは十分ではありません。 その代わり`3999 < 2000`は誤りであり、`3999 > 4000`は false、待ってください、実際には正しく評価されます。`3999 < 2000`は誤りであり、`3999 > 4000`が false の場合、ロジックが間違っていると誤って Safe に移動しますが、ここでは正しい境界を使用しているため、`3999 > 4000`は false ですが、正しい順序も必要です。また、3999 は実際には 4000 未満ですが 2000 より大きいため、範囲内にある場合にのみ正しく Safe に分類されます。`[2000,4000]`、安全です。 これにより、間隔ロジックが全範囲の極値にわたって一貫していることが確認されます。
