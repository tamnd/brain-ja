 ## 解決策
 ## 問題の理解

 整数の複数セットが与えられ、それらを任意に並べ替えてシーケンスにすることができます。 目標は、すべての隣接するペアがモジュラー関係を満たすようにそれらを配置できるかどうかを決定することです。つまり、M を法としてとった各連続ペアの合計が固定目標値 K に等しくなければなりません。 

言い換えれば、数値をシーケンス P に配置すると、すべての隣接するペア P[i]、P[i+1] に対して、条件は次のようになります。 

(P[i] + P[i+1]) mod M = K

 すべての有効な i に対して同時に成立する必要があります。 このような順序が存在する場合は、有効な順列を 1 つ出力する必要があります。 それ以外の場合は、不可能であると出力されます。 

n が 2 × 10^5 までの制約により、二次関数やすべてのペアにわたる明示的なグラフ構築を伴うものから遠ざけられます。 すべての順列をチェックしようとする解決策は、n! であるため、直ちに実行不可能になります。 は大きすぎるため、スワップを試行した後に単純に隣接制約をチェックしても、依然として遅すぎます。 

微妙な点は、条件がインデックスや絶対的な順序ではなく、M を法とする値のみに依存することです。 これにより、隠れたペアリング構造が作成されます。つまり、各数値には、必要な合計を法 M で求める相補的なパートナーが実質的に必要になります。 

素朴な推論を打ち破る重要なエッジケースが 2 つあります。 

すべての値が同一である場合、たとえば A = [x, x, x, x] の場合、条件は (2x mod M) K と等しくなる必要があります。 これが失敗すると、すべての要素が同じであっても配置は機能しません。これは、同一の値が常に安全であると想定する貪欲な実装を誤解させる可能性があります。 

もう 1 つのケースは、n = 1 の場合です。隣接するペアがないため、条件は空に満たされ、K に関係なく単一要素の置換が有効になります。 

最後に、重複は非常に重要です。 頻度をカウントせずに貪欲に値を一致させようとすると、要素を誤って再利用したり、必要な補数が使い果たされていることを見逃したりする可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。配列のすべての順列を生成し、それぞれの順序がモジュールの隣接条件を満たすかどうかをテストします。 これは問題の定義に直接従うため、正しいです。 ただし、順列の数は n! であり、n = 2 × 10^5 の場合、これは計算的に概念化することさえ不可能です。 n = 10 の場合でも、これは境界線となり、それを超えると爆発的に増加します。 

順列の検索を完全に回避する方法が必要です。 重要な観察は、単一の隣接するペアによって課される制約に焦点を当てることです。 2 つの連続する要素 x と y が出現する場合、それらは x + y ≡ K (mod M) を満たさなければなりません。 これは、y ≡ K − x (mod M) と書き直すことができます。 これは、シーケンス内のすべての要素が、モジュロ M に基づいて一意に決定された補体とペアになる必要があることを意味します。 

これにより、問題はマルチセットにわたるペアリングの問題に変換されます。つまり、各値 x は K − x mod M と一致する必要があります。ペアが形成されると、各ペアが局所的に一貫しているため、それらを順番に並べることは簡単になります。 

残る唯一の構造上の問題は、ペアがグローバルに一貫している必要があること、つまりすべての要素が 1 回だけ一致する必要があることです。 これにより、問題は、この暗黙的なペアリング システムに完全な一致が存在するかどうかを確認することになり、頻度をカウントすることで解決できます。

 ## アルゴリズムのチュートリアル

 配列内のすべての値に対して周波数マップを構築します。 次に、各値 x と必要な補数 y = (K − x mod M + M) mod M を組み合わせようとします。

1. A のすべての値の頻度をカウントします。これにより、要素を安全に消費できるようにマルチセット表現が得られます。 
2. 周波数マップ内の各個別の値 x を反復処理します。 各 x について、x + y ≡ K (mod M) となるように、必要なパートナー y を計算します。 モジュラー調整により、y が常に [0, M) になることが保証されます。 
3. x が以前のペアリングですでに完全に使用されている場合は、スキップします。 これにより、ペアの二重処理が防止されます。 
4. x が y に等しい場合、つまりそれが自己相補的である場合、その周波数は偶数でなければなりません。 そうしないと、1 つの出現が一致しないままになり、完全な並べ替えが不可能になります。 
5. x が y と異なる場合は、x のすべての出現を y の出現と一致させる必要があります。 これには、freq[x] == freq[y] が必要です。 等しくない場合、すべてを一貫してペアにすることはできません。 
6. 検証が完了したら、x と y freq[x] 回 (x ≠ y の場合) を繰り返し追加するか、自己相補的な場合には同一の値をペアにして出力を構築します。 

有効なペアの任意のシーケンスを連結し、各ペア ブロック内の隣接制約を満たすことができるため、構築順序はペアリングの尊重以外には重要ではありません。 

### なぜ効果があるのか

 重要な不変条件は、すべての値がモジュラー和制約を満たす 1 つの相補的な値と正確にペアになっている必要があるということです。 各要素は両側で厳密に 1 つの隣接関係に参加するため (ペアリングの一貫性が依然として必要なエンドポイントを除く)、シーケンス全体が素の有効なペアに分解されます。 いずれかの値がその補数と同じ頻度で完全に一致できない場合は、少なくとも 1 つの隣接制約が失敗する必要があり、有効な置換が不可能になります。 逆に、すべての周波数をこの対称的な方法で一致させることができれば、常にペアを連続して配置して有効なシーケンスを形成することができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, M, K = map(int, input().split())
    A = list(map(int, input().split()))
    
    from collections import Counter
    freq = Counter(A)
    
    used = set()
    res = []
    
    for x in list(freq.keys()):
        if freq[x] == 0:
            continue
        if x in used:
            continue
        
        y = (K - x) % M
        
        if y not in freq:
            print("NO")
            return
        
        if x == y:
            if freq[x] % 2 != 0:
                print("NO")
                return
            res.extend([x] * freq[x])
            used.add(x)
        else:
            if freq[x] != freq[y]:
                print("NO")
                return
            used.add(x)
            used.add(y)
            for _ in range(freq[x]):
                res.append(x)
                res.append(y)
    
    print("YES")
    print(*res)

if __name__ == "__main__":
    solve()
```この実装は、ペアリング ロジックを直接変換したものです。 カウンタは多重度を保存するので、重複を追跡できなくなります。 使用されるセットにより、値の各同値クラスが 1 回だけ処理されることが保証され、x と y の間で偶発的に二重ペアになることが防止されます。 

構築ステップでは、有効な各ペア タイプを任意にインターリーブします。 制約は隣接する要素に局所的にのみ適用されるため、有効なペアの順序は任意です。 

よくある微妙な間違いは、y を計算するときにモジュラー正規化を忘れることで、負の値が生成されてしまいます。 式 (K - x) % M により正確さが保証されます。

 ## 特殊なケース

 重要なエッジケースは、値が係数の下で自己相補的である場合です。 たとえば、M = 10 および K = 4 の場合、値 2 は 2 + 2 ≡ 4 mod 10 を満たします。それが奇数回、たとえば 3 回出現する場合、貪欲なペアリングではペアになっていない要素が 1 つ残ります。 このアルゴリズムは、何かを構築する前にパリティを正しくチェックし、部分的ではあるが無効な配置を防ぎます。 

別のエッジ ケースは、複数の値が同じ補体構造にマッピングされているが、頻度が一貫していない場合に発生します。 たとえば、x が y にマッピングされるが、freq[x] > freq[y] の場合、貪欲な構築では、枯渇するまでペアが生成され、後で静かに失敗する可能性があります。 周波数間の明示的な等価性チェックにより、出力を構築する前に実現可能性を検証することで、このドリフトを防止します。 

最後の微妙なケースは、n = 1 です。隣接関係の制約がないため、アルゴリズムが問題のある方法でペアリング ロジックに入ることはありません。 周波数マップには単一の要素が含まれており、自己一貫性のあるものとして扱われ、有効な出力がすぐに生成されます。
