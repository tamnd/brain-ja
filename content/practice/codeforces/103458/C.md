 ## 解決策
 ## 問題の理解

 モデル化されているプロセスは、固定数の薬室を備えた円形の銃シリンダーでプレイされるターンベースのエリミネーション ゲームです。 弾丸が入っている薬室もあれば、空の薬室もあります。 開始位置が一様にランダムになるようにシリンダーを回転させ、その後 2 人のプレーヤーが交互にトリガーを引きます。 トリガーが空のチャンバーを指すと、シリンダーが 1 位置前方に回転し、ターンが他のプレイヤーに移る以外は何も起こりません。 引き金が弾丸を指すとすぐにゲームは終了し、引き金を引いたプレイヤーが負けます。 

この問題で与えられる重要な制御は、最初のプレイヤーがゲーム開始前にどの部屋に弾丸が入っているかを選択できることです。n 個の位置に正確に k 個の弾丸が配置されます。 このようなすべての構成の中で、最初のプレイヤーが負ける可能性を最小限に抑えるものが必要です。 複数の構成が同じ最適確率を達成する場合、空のスロットが埋められたスロットよりも小さい、辞書編集上最小のバイナリ文字列を選択する必要があります。 

入力は、構成全体を明示的に尋ねるのではなく、この最適な構成内の特定の位置に黒丸が含まれているかどうかを尋ねる一連のクエリです。 各クエリの出力は、そのチャンバーが安全であるか装填されているかを表す文字です。 

制約 n は 10^18 まで大きくすることができ、位置の反復やプロセスの明示的なシミュレーションに依存する構築は即座に除外されます。 線形または対数の位置ごとの推論であっても、インデックスの算術に帰着しない限り避けなければなりません。 クエリの数は最大 1000 であるため、クエリごとに O(1) または O(log n) の推論が必要です。 

単純なアプローチでは、ゲームをシミュレートするか、さまざまな配置での損失確率を評価しようとします。 組み合わせ推論に限定しても、構成の数は二項(n, k)であり、中程度のnであっても天文学的に大きいため、n個の位置間でk個の弾丸のすべての配置を試すことは不可能です。 

最適な戦略が局所的な間隔や貪欲な配置に依存すると仮定すると、より微妙な障害モードが現れます。 たとえば、弾丸を等間隔に配置することは合理的であるように思えるかもしれませんが、ランダムな回転により循環シフト下で効果的なゲームが対称になるという事実が無視されているため、絶対的な位置ではなく循環構造のみが重要になります。 

もう 1 つのよくある誤った仮定は、辞書編集上の最小化により、最初の位置または最後の位置が特別な役割を果たすというものです。 ただし、辞書編集順は確率が最小化された後にのみ同順位を破るので、最適な循環構造を考慮せずに位置 1 を直接優先する推論は失敗します。 

## アプローチ

 ブルートフォースの観点では、弾丸の k 個の位置を選択し、最適なプレイで最初のプレーヤーが負ける確率を計算します。 これには、空の各チャンバーが状態をシフトし、ターンの交互がサイクルの長さと相互作用するサイクル上の確率的ゲームを分析する必要があります。 各構成について、正確な確率を計算するには、考えられるすべての開始ローテーションとプレー結果をシミュレートする必要があり、これは n と k の両方で指数関数的です。 状態には現在の回転オフセットとサイクルの残りの構造の両方が含まれるため、シリンダーと回転パリティの状態に対して動的計画法を定式化しようとしても、すぐに爆発してしまいます。

重要な観察は、シリンダーが回転によってランダム化されると、弾丸の周期的なパターンのみが重要となり、ゲームは事実上、円に沿った連続する弾丸間の距離に依存するということです。 このプロセスは、最初の弾丸がヒットするまで常に決定的に前進します。つまり、各開始位置は、次の弾丸につながる空のセルのセグメントに対応します。 これにより、問題は個々の位置ではなく、連続する弾丸の間のギャップについての推論に帰着します。 

最適な構成は、これらのギャップができるだけ等しいときに達成されます。これは、ギャップが不均一であると、ランダムな開始位置が大きな空のセグメントに入る可能性が増加し、予想される生存時間が増加し、ターン パリティに影響を与えるためです。 ギャップのバランスを取ると、セグメントの長さの分散が最小限に抑えられ、すべてのバランスの取れた分布の中で、辞書編集上の最小性により、ギャップ構造を維持しながら可能な限り前の位置が空になります。 

これにより、n − k 個の空スロットを k セグメント全体にできるだけ均等に円形に配置する構造に変換されます。 ギャップ サイズが決定されると、指定されたインデックスが箇条書きであるかどうかを再構築することは、そのインデックスがどのセグメントに該当するか、および箇条書きの境界または空のストレッチに対応するかどうかを計算することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての配置のゲーム結果のブルート フォース シミュレーション | 指数 | O(n) | 遅すぎる |
 | バランスの取れた循環ギャップ構築 + インデックス マッピング | O(k + q) | O(n) 暗黙的 / O(1) 追加 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. k 個の箇条書きを、円を空のセルの k 個のギャップに分割するものとして扱います。 空のセルの総数は n − k であり、これらは k 個のギャップに分散されなければなりません。 
2. 基本ギャップ サイズを (n − k) // k として計算し、より大きなギャップの数を (n − k) % k として計算します。 これにより、ギャップの差が最大 1 になることが保証されます。これは最適なバランスに必要です。 
3. 辞書編集上の最小性を維持する方法で、位置 1 から開始して黒丸と空のセグメントを交互に配置することにより、概念的な循環構造を構築します。 これは、一貫した循環順序付けにおいて、できるだけ早く小さなギャップを配置することを意味します。 
4. 各位置について、繰り返されるギャップ パターン内でそのオフセットをマッピングすることにより、その位置が空のセグメント内にあるのか、箇条書きの境界にあるのかを判断します。 
5. サイクル内の位置のインデックスを計算し、セグメント境界の算術演算を使用してそれが箇条書きまたは空のスロットに対応するかどうかを確認することで、クエリに答えます。 

この手順が有効である理由は、ギャップ サイズが最適に固定されると、残された唯一の自由は円形パターンの回転だけだからです。 辞書編集的な最小性は、バランスのとれた構造によって許容される限り遅く、可能な限り早い弾丸を配置するローテーションを強制します。これは、決定論的な順序でギャップを埋めることに対応します。 維持される不変条件は、任意の 2 つの連続する弾丸の間で、空のスロットの数が最大 1 つ異なること、および他の場所でギャップを増やさずに弾丸をより早く移動するためにプレフィックスを変更することはできないということであり、これにより損失の可能性が悪化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, q = map(int, input().split())
    
    if k == 0:
        for _ in range(q):
            input()
            print(".")
        return
    
    if k == n:
        for _ in range(q):
            input()
            print("X")
        return

    total_empty = n - k
    base = total_empty // k
    extra = total_empty % k

    # Build segment sizes: k gaps, some are base+1, others base
    gaps = [base + 1] * extra + [base] * (k - extra)

    # Precompute prefix sums of segment lengths in circular order
    # We interleave: gap, bullet, gap, bullet...
    # We'll simulate linearized structure starting from a bullet
    seg = []
    for i in range(k):
        seg.append(gaps[i])
        seg.append(1)  # bullet

    pref = [0]
    for x in seg:
        pref.append(pref[-1] + x)

    cycle_len = pref[-1]

    # We map queries in 1..n onto this constructed cycle
    # repeated pattern if needed
    # We assume construction starts with gap then bullet structure repeated

    for _ in range(q):
        x = int(input())
        pos = (x - 1) % cycle_len

        # find segment via linear scan (q small, k up to 1000 assumption)
        i = 0
        while i < len(seg) and pref[i+1] <= pos:
            i += 1

        # seg[i] determines whether it's bullet or empty
        # odd index in seg => bullet, even => gap
        if i % 2 == 1:
            print("X")
        else:
            print(".")

if __name__ == "__main__":
    solve()
```この実装では、最初に、箇条書きがない、またはすべての位置が箇条書きである縮退ケースが処理されます。 一般的なケースでは、空のスロットを k 個のセグメントにできるだけ均等に分散します。 この構造は概念的に、空のセグメントと箇条書きの位置が交互に並ぶように構築されています。 クエリは、インデックスをこの繰り返しサイクルにマッピングし、どのセグメントに該当するかを特定することによって解決されます。 

微妙な部分は、サイクルがすべての n 位置を明示的に具体化するのではなく、暗黙的に構築されることです。これは、大きな n では不可能です。 代わりに、1 つの期間の構造のみが構築され、サイクル長の算術法によってメンバーシップが決定されます。 

## 実用的な例

 n = 5、k = 2 とします。3 つの空のスロットが 2 つのギャップに分散されており、base = 1 および extra = 1 となるため、ギャップ サイズは [2, 1] になります。 

| セグメントインデックス | タイプ | サイズ | 累計 |
 | --- | --- | --- | --- |
 | 0 | ギャップ | 2 | 2 |
 | 1 | 弾丸 | 1 | 3 |
 | 2 | ギャップ | 1 | 4 |
 | 3 | 弾丸 | 1 | 5 |

 x = 1 ～ 5 の場合、この構造にマッピングすると次のようになります。 

1→ギャップ→「。」

 2→ギャップ→「。」

 3→箇条書き→「×」

 4→ギャップ→「。」

 5→箇条書き→「×」

 これは、この構造がバランスのとれた分布をもたらすことを裏付けています。 

ここで、n = 6、k = 3 とします。空の合計 = 3 なので、base = 1、extra = 0 となり、ギャップは [1,1,1] になります。 

| セグメントインデックス | タイプ | サイズ |
 | --- | --- | --- |
 | 0 | ギャップ | 1 |
 | 1 | 弾丸 | 1 |
 | 2 | ギャップ | 1 |
 | 3 | 弾丸 | 1 |
 | 4 | ギャップ | 1 |
 | 5 | 弾丸 | 1 |

 出力は完全に交互のパターン「.X.X.X」となり、最大限の対称性を示します。

 ## 特殊なケース

 k が 0 に等しい場合、構造は長さ n の単一のギャップに縮退し、すべてのクエリは空を返す必要があります。 アルゴリズムは、モジュール推論の前にこれを明示的に処理します。 

k が n と等しい場合、すべてのギャップのサイズは 0 になるため、すべてのセグメントは箇条書きになります。 各ギャップの長さはゼロであり、箇条書きマーカーのみが残るため、交互構造は正しく折りたたまれます。 

n が大きく k が小さい場合、ベース ギャップ サイズは大きくなり、最も複雑になるのは空のセグメントです。 モジュロベースのマッピングにより、これらのセグメントを明示的に拡張しようとしないことが保証されるため、メモリ使用量は一定に保たれます。 

n − k が k で割り切れない場合、サイズ 1 の余分なギャップが最初のセグメントに分配されます。 これにより、バランスを維持しながら辞書編集上の最小限度が維持され、プレフィックスベースの割り当てにより、曖昧さのない決定的な配置が保証されます。
