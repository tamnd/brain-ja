 ## 解決策
 ## 問題の理解

 バスケットボール選手候補のリストからチームを編成するよう求められます。それぞれのチームは整数のパワーを持ちます。 相手には力のあるチームがいる$D$を構成し、メンバーの合計パワーが を超えた場合にチームが勝利します。$D$。 面白いのは、各試合の前に、コーチがチーム内のすべてのプレーヤーをそのチームの最も強いプレーヤーと一致するように強化できることです。 各プレイヤーは最大 1 チームに参加できますが、勝利できるチームの数を最大化したいと考えています。 

入力は次のもので構成されます$N$プレイヤーのパワーを表す整数、および$D$、敵の勢力。 出力は単一の整数です。最大値が優先されます。 

制約により許可されるのは、$N$まで$10^5$そしてパワーアップします$10^9$。 これは、$O(N^2)$アプローチは機能しません。 近くに何かが必要です$O(N \log N)$at worst. 操作は、大規模な配列に対して効率的に拡張する必要があります。 可能なすべてのサブセットを試して、増幅された合計が上回るかどうかを確認する素朴なアプローチ$D$実現不可能です。 

エッジケースには次のものが含まれます: すべてのプレイヤーのパワーが以下の場合$D$、非常に強力なプレイヤーが 1 人だけ、またはすべてのパワーが互いに等しい。 たとえば、次の場合$N = 3$、$D = 100$、そして力は$[30, 30, 30]$、最強のメンバーに増幅しても与えることができるため、どのチームも勝つことはできません。$30 * 3 = 90 \le D$。 不注意なアプローチは、各プレーヤーだけで勝利チームを形成できると誤って想定する可能性がありますが、増幅された合計は次の値を超える必要があります。$D$。 

## アプローチ

 ブルートフォース手法では、チームを形成するプレーヤーのすべての可能なサブセットを考慮し、そのサブセットの増幅された合計を計算し、それが次の値を超えているかどうかを確認します。$D$。 最悪の場合、これを繰り返す必要があります。$2^N$サブセット。 のために$N = 10^5$、これは不可能です。 ソート後にすべての連続するセグメントを試すというヒューリスティックでも、単純に実装すると遅すぎます。 

重要な洞察は、プレーヤーをパワー別に分類した後、最良の戦略は貪欲であるということです。 勝利を最大化するには、利用可能な最強のプレーヤーで可能な限り最小のチームを形成する必要があります。 規模のある候補チームの場合$k$、最強のメンバーが力を持っていれば$p$、増幅されたチームの合計は次のようになります。$k * p$。 必要です$k * p > D$。 大きいので$k$価値観を超えやすくなる$D$小規模なプレーヤーの場合は、最も強いチームから順にチームを編成します。 新しいチームで最も強い選手を選ぶたびに、勝つために必要な最小チーム規模を計算します。$D$そして残っている最も弱いプレイヤーの多くを奪います。 これにより、各チームが勝利し、プレイヤーが 2 回使用されることはなくなります。 

この貪欲な観察により、問題は単純なソートと 2 ポインタのアプローチまたはインデックス追跡に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N) | O(N) | 遅すぎる |
 | 最適 (貪欲 + ソート) | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレイヤーのパワーを昇順に並べ替えます。 並べ替えにより、各チームの最も強いプレーヤーと利用可能な最も弱いチームメイトを効率的に選択できるようになります。 
2. 2 つのポインターまたはインデックスを初期化します。1 つは先頭にあります (`i`) と最後に 1 つ (`j`) ソートされた配列。`i`利用可能な最も弱いプレーヤーを指します。`j`最強へ。 
3. カウンタの初期化`wins`ゼロに。 これにより、形成された優勝チームの数が追跡されます。 
4. ながら`i <= j`で残っている最強のプレイヤーを考えてみましょう。`j`。 勝つために必要な最小チームサイズを計算する`D`:`k = ceil(D / P[j])`。 これは最小のコピー数です`P[j]`必要です。 
5. 十分なプレイヤーが残っているかどうかを確認します。`j - i + 1 >= k`、プレイヤーとチームを結成します`j`そして`k-1`から始まる利用可能な最も弱いプレーヤーの中で`i`。 インクリメント`wins`、増分`i`による`k-1`使用済みの選手を前線から外し、デクリメントする`j`使用した最強のプレイヤーを削除します。 
6. 勝利チームを形成するのに十分なプレーヤーが残っていない場合`P[j]`、 停止。 これ以上のチームは勝てません。 
7. 戻る`wins`。 

機能する理由: 不変条件は、各ステップで常に最小数のプレイヤーを使用して勝利が保証されるチームを形成し、常に利用可能な最強のプレイヤーを使用することです。 どの選手も二度使用されることはなく、勝利の機会がスキップされることもありません。 並べ替えられた配列により、残りの潜在的な勝利を最大化する組み合わせを常に選択できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import math

def max_wins():
    n, D = map(int, input().split())
    P = list(map(int, input().split()))
    P.sort()
    
    i, j = 0, n - 1
    wins = 0
    
    while i <= j:
        strongest = P[j]
        team_size = (D + strongest) // strongest  # ceil(D / strongest)
        if team_size <= (j - i + 1):
            wins += 1
            i += team_size - 1
            j -= 1
        else:
            break
    
    print(wins)

if __name__ == "__main__":
    max_wins()
```コードはまず累乗を並べ替えます。 ツーポインタのアプローチにより、プレーヤーを常に最適に消費することが保証されます。 の`(D + strongest) // strongest`インポートせずに上限を計算するトリック`math.ceil`スピードのために。 境界条件`i <= j`そして`team_size <= j - i + 1`小さな配列を処理し、インデックスエラーを防ぎます。

 ## 特殊なケース

 すべてのプレイヤーが同じパワーを持っている場合、アルゴリズムは必要なチーム サイズを正確に計算し、できるだけ多くのチームを形成します。 入力用`[3,3,3,3]`と`D=10`、必要なチームサイズは 4 であるため、チームは 1 つだけ形成されます。 べき乗が非常に大きい場合でも、整数の除算によってオーバーフローが回避されるため、アルゴリズムは引き続き機能します。 チーム サイズの計算には天井分割が考慮されているため、シングル プレイヤー シナリオは正しく処理されます。
