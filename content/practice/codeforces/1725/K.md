 ## 解決策
 ## 問題の理解

 私たちは整数の高さを持つ建物が並ぶ王国を管理しています。 住民は時折、特定の区間 [l, r] (r-l は常に奇数) 内の高さを持つすべての建物を対象として批判を発します。 次に、王国の建設チームは、その間隔に建物が存在しないように建物の高さを調整する必要があります。 調整するたびに高さが 1 ずつ増減しますが、高さは正の値のままです。 

操作には3種類あります。 1 つ目は建物を特定の高さに設定し、2 つ目は建物の高さをクエリし、3 つ目は批判間隔を課します。この間隔は、最小限の時間で建物の外側の高さを移動することで直ちに解決する必要があります。 重要な観察は、各批判の後、調整された高さは以前の批判を満たす必要がないということです。 これは、批判が建物の高さの現在のスナップショットにのみ影響することを意味します。 

入力サイズは大きくてもよく、最大 4×10^5 の建物と 4×10^5 のクエリ、高さは 10^9 までです。 これにより、批判ごとにすべての建物を反復するアプローチが不要になります。これは、最悪の場合、4×10^5 × 4×10^5 = 1.6×10^11 の演算を実行できるためですが、これは実行不可能です。 したがって、対数または償却定数時間でクエリを処理できる構造が必要です。 

単純な実装を壊す可能性のあるエッジケースは、建物の高さがちょうど批判区間の中間点にある場合です。 たとえば、建物の高さが 5 で批判間隔が [4, 6] の場合、不注意なアルゴリズムにより建物を上に移動するか下に移動するかを正しく決定できない可能性があります。 最小時間ルールは、一意の最適な方向が存在することを保証します。つまり、区間内のすべての建物を区間外の最も近い境界に移動します。 もう 1 つのエッジケースは、複数の批判が重複する範囲に影響を与える場合です。 それぞれが独立しているため、現在の高さを基準にして処理する必要があります。 

## アプローチ

 ブルートフォース ソリューションでは、批判が発生するたびにすべての建物を直接反復処理します。 区間内の各建物について、l-1 と r+1 の両方までの距離を計算し、建物をより近い境界に移動します。 これは正しく機能しますが、批判ごとに O(N) 操作が必要です。 Q の批判を考慮すると、総コストは O(NQ) ですが、これは N、Q が 4×10^5 までの場合には遅すぎます。 

最適なアプローチは、各建物の調整が間隔の中間点のみに依存するという観察を活用します。 r-l が奇数であるため、中点は分数になりますが、中点の下限または整数の除算を考慮できます。 厳密に中点以下のすべての高さは l より下に移動し、厳密に中点よりも大きいすべての高さは r より上に移動します。 これは、批判を範囲の結合として扱うことができ、各建物が中間点との関係のみを考慮できることを意味します。 これをグローバル オフセットまたは遅延適用される変換としてモデル化し、この変換に対する各建物の個々の高さを保存することでクエリを効率的に解決できます。 重要な洞察は、各批判ですべての建物を物理的に移動するのではなく、クエリ時に建物への影響を計算するために、最後の批判の中点を知るだけでよいということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NQ) | O(N) | 遅すぎる |
 | 最適 | O(Q) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を維持する`heights`すべての建物の現在の高さ。 変数も維持します`crit_l`そして`crit_r`最新の批判間隔を保存します。 
2. タイプ 1 のクエリの場合、建物の高さを直接設定します。`heights[k] = w`。 
3. タイプ 3 のクエリの場合、批判間隔を保存します。`[l, r]`。 中点を次のように計算します。`mid = (l + r) // 2`。 
4. タイプ 2 のクエリの場合、有効な高さが必要です。 現在の高さが以内の場合`[l, r]`、l-1 と r+1 の両方までの距離を計算し、近い方に移動します。 高さが中点と正確に等しい場合、独自の最小限の調整は、高さを l-1 まで下げることです。 
5. タイプ 2 クエリに対して計算された有効高さを返します。 

それが機能する理由: 不変条件は、批判の後、各建物がその場所に留まるか (区間外の場合)、区間外の最も近い境界に最小限移動するということです。 最後の批判のみを保存し、最小限の調整を遅延計算することにより、すべての建物に対して反復処理を行うことなく、タイプ 2 クエリの正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
heights = list(map(int, input().split()))
q = int(input())

crit_l, crit_r = None, None

for _ in range(q):
    query = input().split()
    t = int(query[0])
    if t == 1:
        k = int(query[1]) - 1
        w = int(query[2])
        heights[k] = w
    elif t == 2:
        k = int(query[1]) - 1
        h = heights[k]
        if crit_l is not None:
            l, r = crit_l, crit_r
            if l <= h <= r:
                mid = (l + r) // 2
                if h <= mid:
                    h = l - 1
                else:
                    h = r + 1
        print(h)
    else:
        crit_l, crit_r = int(query[1]), int(query[2])
```このコードは、タイプ 1 を直接代入して処理し、タイプ 3 を最後の批判を保存することによって処理します。 タイプ 2 は有効高さを遅延計算します。 中点を計算し、建物をどちら側に移動するかを決定するときは、特に高さが中点と等しい場合には注意が必要です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(Q) | 各クエリは、批判に対する遅延計算を使用して O(1) で処理されます。 
| スペース | O(N) | すべての建物の高さを保存する |

 このアルゴリズムは、3 秒の制限時間内で最大 4×10^5 までの N と Q を快適に処理します。
