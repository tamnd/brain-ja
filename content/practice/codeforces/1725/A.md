 ## 解決策
 ## 問題の理解

 この問題のグリッドは任意ではなく、その寸法によって完全に決定されます。 すべてのセルには一意の整数が含まれており、数値は左から右に行ごとに増加します。 最初の行には最初の M 個の整数が入力され、2 番目の行はその直後に続きます。 したがって、グリッドは行優先の順序で書かれたフラット化された配列のように動作します。 

非常に特殊な条件を満たす隣接するセルのペアを数えるように求められます。 ペアは、辺を共有する 2 つのセルによって形成されます。これは、水平および垂直に隣接するセルのみを考慮することを意味します。 これら 2 つのセル内の数値間の絶対差が正確に 1 である場合、そのようなペアは有効であると呼ばれます。順序のない各セルのペアは 1 回カウントされます。 

重要な構造上の制約は、数字が非常に厳密なパターンで連続していることです。 これにより、グリッドをシミュレートする必要がなく、行と列の位置によって引き起こされる算術関係のみを推論するだけで、隣接関係の比較が決定的になります。 

この制約により、N と M は 10^9 まで許可され、グリッドの構築が即座に除外されます。 サイズ 10^9 の単一行であっても、制限時間内に明示的に保存したり反復したりすることはできません。 セルまたはエッジを個別に反復するソリューションは、線形または二次爆発により失敗します。 唯一の実行可能なアプローチは、O(1) または O(log N) の算術用語で推論することです。 

N または M のいずれかが 1 の場合、微妙なエッジ ケースが発生します。M = 1 の場合、水平方向の隣接関係は存在せず、垂直方向の隣接関係のみが存在します。 N = 1 の場合、垂直方向の隣接関係は存在せず、水平方向の隣接関係のみが存在します。 両方向が存在することを前提とした単純な実装では、カウントが過剰になったり、無効なインデックス付けが試行されたりします。 もう 1 つの特殊なケースは行間の遷移です。値は行 i から行 i+1 にラップし、この境界は行内の隣接とは異なる動作をします。 

## アプローチ

 ブルートフォース ソリューションでは、グリッドを明示的に構築し、隣接するセルのすべてのペアをチェックします。 各セルには最大 2 つの前方隣接セルがあるため、すべての N × M セルをスキャンし、セルごとに定期的なチェックを実行する必要があります。 これは O(NM) 操作につながりますが、NM は 10^18 に達する可能性があるため、これは不可能です。 

重要な観察は、隣接関係がローカルであり、値の割り当てが線形であることです。 行内では、連続する列の値が 1 だけ異なります。 つまり、すべての水平エッジが自動的に有効なタイト ドミノを形成します。 このようなエッジは行ごとに正確に M - 1 個あり、N 行あるため、水平方向の寄与は簡単です。 

垂直エッジはより微妙です。 同じ列の行 i から行 i+1 に移動すると、値は正確に M だけ増加します。そのため、垂直方向の隣接値は 1 ではなく M だけ異なります。つまり、M = 1 でない限り垂直エッジは認定されません。この特殊な場合、各列は連続する整数のチェーンであり、すべての垂直方向の隣接関係が有効になります。 

したがって、問題全体は、水平方向の有効なエッジを数えることと、M = 1 の場合に垂直方向のエッジを条件付きで追加することに帰着します。

 ## アルゴリズムのチュートリアル

 カウントを水平方向の寄与と垂直方向の寄与に分けます。 

1. 各行を個別に考慮して、水平方向のタイトなドミノを計算します。 

長さ M の行では、隣接する列のペアはすべて値 x および x+1 を形成するため、M - 1 個の水平エッジはすべて有効です。 N 行があるため、これは N × (M - 1) に寄与します。 
2. 列方向の構造を調べて、垂直方向の隣接性を個別に処理します。 

セル (i, j) と (i+1, j) の値の差は常に M です。これが 1 になるのは、M = 1 の場合のみです。これは、番号付けが単一のチェーンに折りたたまれるためです。 
3. M が 1 の場合、すべての列は連続する整数の垂直シーケンスになります。

その場合、各列は N - 1 個の有効な垂直エッジに寄与し、そのような列が M 個あるため、垂直寄与は M × (N - 1) になります。 
4. 両方の寄与を合計し、結果を出力します。 

なぜ効果があるのか

 グリッドは、線形公式を通じて座標と整数の間の全単射を定義します。 水平隣接関係では、行に沿って 1 ずつ増加する構造のため、連続した整数が保持されます。 垂直隣接関係は、行ストライド M が 1 に等しい場合にのみ連続する整数を保持します。隣接関係構造は、重複のない独立した水平コンポーネントと垂直コンポーネントに完全に分解されるため、各方向を個別にカウントすると、考えられるすべてのエッジの正確な分割が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

N, M = map(int, input().split())

horizontal = N * (M - 1)
vertical = M * (N - 1) if M == 1 else 0

print(horizontal + vertical)
```この実装は、以前に導出された分解を直接エンコードします。 水平エッジは、すべての行が M - 1 個の有効なペアに寄与するという事実を使用して計算されます。 垂直エッジは、M = 1 の縮退の場合にのみ追加されます。それ以外の場合、垂直方向の差は常に 1 より大きくなります。 

よくある間違いは、水平方向の式を反映して、N × (M - 1) を使用して垂直エッジを対称的に追加しようとすることです。 これは失敗します。垂直方向の隣接性は、グリッド形状の対称性ではなく、番号付けのストライドに依存するためです。 もう 1 つの落とし穴は、M > 1 の場合、垂直エッジが完全に消えることを忘れていることです。

 入力:```

```水平方向の寄与は行ごとに計算されます。 各行には有効な水平エッジが 3 つあり、行数は 3 つあります。 

M ≠ 1 であるため、垂直方向の寄与はゼロです。 

| ステップ | 水平 | 垂直 | 合計 |

 | イニシャル | 0 | 0 | 0 |

 これにより、複数列グリッドでは行内の隣接関係のみが重要であることがわかります。 

### 例 2

 入力:```
4 1
```現在、グリッドは 1 列であるため、水平エッジは存在しません。 

| ステップ | 水平 | 垂直 | 合計 |
 | --- | --- | --- | --- |
 | イニシャル | 0 | 0 | 0 |
 | 水平後 | 0 | 0 | 0 |
 | 垂直後 | 3 | 3 | 3 |

 各列は純粋な連続シーケンスを形成するため、すべての垂直ステップが有効です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | お(1) | N と M の算術演算のみ |
 | スペース | お(1) | 補助構造は使用していません |

 このソリューションは、入力サイズに関係なく、一定数の算術演算を実行します。 これは、グリッドに対する反復が必要ないため、N、M から 10^9 までの制約内に簡単に適合します。 

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    N, M = map(int, input().split())
    horizontal = N * (M - 1)
    vertical = M * (N - 1) if M == 1 else 0
    return str(horizontal + vertical)

# provided sample
assert solve("3 4\n") == "9"

# minimum case
assert solve("1 1\n") == "0"

# single row
assert solve("1 5\n") == "4"

# single column
assert solve("5 1\n") == "4"

# rectangular grid
assert solve("2 3\n") == "4"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 | 0 | 最小のグリッド |
 | 1 5 | 4 | 水平エッジのみ |
 | 5 1 | 4 | 垂直エッジのみ |
 | 2 3 | 4 | 混合構造の一貫性 |

 ## 特殊なケース

 N = 1 および M = 1 の場合、グリッドには単一のセルが含まれるため、隣接するペアは存在しません。 アルゴリズムは水平 = 1 × 0 = 0 を返し、M ≠ 1 条件が失敗するため垂直方向はスキップし、正しく 0 を返します。 

N = 1 および M > 1 の場合、グリッドは単一行になります。 水平方向の計算では M - 1 が得られ、これはライン内の隣接するペアの数と一致します。 垂直方向はゼロのままで、無効な行間推論を正しく回避します。 

M = 1 および N > 1 の場合、グリッドは連続する整数の単一列になります。 水平方向は 0、垂直方向は 1 × (N - 1) となり、各ステップが正確に 1 だけ異なるチェーン構造を正確に捉えます。
