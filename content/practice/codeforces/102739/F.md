 # 問題の理解

 タスクは、すべてのフィットネス トラッカーの値を Sasha が受け入れられるようにすることです。 値は、素数または 2 の累乗のいずれかであれば受け入れられます。 記録された数値ごとに、記録以上の最小許容数値を見つける必要があります。 出力には毎日 1 つの回答が含まれます。 

入力には最大で次のものが含まれます$10^5$記録された値。各値は次のように大きくなります。$10^7$。 クエリごとにすべての候補番号を個別にチェックするソリューションでは、コストが高くなりすぎる可能性があります。 最悪の場合、多くの数値を前方にスキャンしてそれぞれの素数をテストすると、次の結果をはるかに上回るパフォーマンスが得られる可能性があります。$10^8$これは、1 秒間の競争プログラミング環境では安全ではありません。 最大値のサイズは、関連するすべての回答を一度前処理することが意図された方向であることを示唆しています。 

特殊なケースは、ほとんどの場合、答えが必ずしも素数であるとは限らないという事実によって引き起こされます。 値がすでに 2 の累乗になっている場合があり、その累乗が次の素数よりも小さい場合があります。 たとえば、入力```
1
1023
```出力があります```
1024
```1024 は 2 のべき乗であり、1023 の次の素数よりも小さいためです。素数のみを検索するソリューションでは、誤って 1031 が返されます。 

もう 1 つのよくある間違いは、0 と 1 は素数ではないが、この問題の解釈では 1 は有効な 2 の累乗であることを忘れていることです。$2^0$。 例えば：```
1
0
```出力があります```
1
```素数のみのソリューションは、2 より小さい素数の答えがなく、次から始まる 2 のべき乗の実装が存在しないため、失敗します。$2^1$正しい値が失われます。 

繰り返される値も重要です。 例えば：```
3
16 16 17
```出力があります```
16 16 17
```アルゴリズムは、同じ情報を再計算するのではなく、一度前処理してすべてのクエリに一貫して答える必要があります。 

## アプローチ

 簡単なアプローチは、すべてのクエリを個別に処理することです。 指定された値から始めて、素数または 2 のべき乗のいずれかが見つかるまで、後続の各整数をテストできます。 これは正しいです。候補を昇順に検査するため、最初の有効な候補がまさに必要な最小値になります。 問題は繰り返し作業の量です。 多くのクエリが大きな値に近い場合、すべてのクエリでほぼ同じ素数チェックが繰り返されます。 と$10^5$クエリとその周りの値$10^7$、このアプローチでは簡単に何十億もの小さな操作が必要になる可能性があります。 

問題の構造から、より良い選択肢が得られます。 考えられる答えは、素数と 2 のべき乗の 2 種類のみです。 2 の累乗は非常にまれであるため、直接保存できます。 エラトステネスのふるいを使用すると、可能な限り最大の答えまでの素数を 1 回生成できます。 その後、すべてのクエリは検索問題になります。つまり、その値以上の最初の素数を見つけて、それをその値以上の最初の 2 のべき乗と比較します。 

残りの問題は、次の素数を素早く見つける方法です。 最大値はほんのわずか程度なので$10^7$、各位置がその位置またはその後に最も近い素数を格納する配列を構築できます。 1 回の逆スキャンでこの配列が埋められます。 その後、すべてのクエリは一定時間内に応答されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * ギャップ * sqrt(A)) | お(1) | 遅すぎる |
 | 最適 | O(M log log M + M + n) | お(お) | 承認済み |

 ここ$M$ふるいにかけた最大値です。 ふるいは主要な前処理ステップですが、クエリへの回答は日数に比例します。 

## アルゴリズムのチュートリアル

 1. 最初にすべての値を読み取り、表示される最大値を決定します。 ふるいは答えに影響を与える可能性のある範囲のみをカバーする必要があるため、これが必要です。 
2. 範囲を少し広げてエラトステネスのふるいを実行します。 ふるいはすべての合成数にマークを付け、クエリに使用できる素数を正確に残します。 
3. 素数のサフィックス配列を構築します。 範囲の終わりから始まりに向かってスキャンし、最後に確認された素数を覚えておきます。 このスキャンの後、位置の値は$i$以上の最小の素数です$i$。 
4. 必要な範囲まで 2 のすべてのべき乗を生成します。 並べ替えて保存します。 各クエリについて、このリストを二分検索して、少なくともクエリ値である 2 の最初の累乗を見つけます。 
5. 元の数値ごとに、次の素数と次の 2 のべき乗を比較します。 両方の候補が有効であり、両方ともそれぞれのカテゴリの可能な限り最も早い候補であるため、小さい方が答えになります。 

機能する理由: 前処理後、すべての素数候補は次素数配列で表され、すべての 2 のべき乗候補は生成されたリストに対する二分探索で表されます。 任意の入力値に対して$x$、有効な回答はすべて、これら 2 つのカテゴリのいずれかに属している必要があります。 アルゴリズムは各カテゴリから最小の候補を選択し、2 つのうちの小さい方を返すため、これより小さい有効な数値は存在できません。 

## Python ソリューション```python
import sys
import bisect

input = sys.stdin.readline

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return

    n = data[0]
    a = data[1:]

    mx = max(a)

    limit = mx + 100000

    prime = bytearray(b'\x01') * (limit + 1)
    prime[0] = 0
    if limit >= 1:
        prime[1] = 0

    i = 2
    while i * i <= limit:
        if prime[i]:
            start = i * i
            prime[start:limit + 1:i] = b'\x00' * (((limit - start) // i) + 1)
        i += 1

    next_prime = [0] * (limit + 2)
    nxt = 0
    for i in range(limit, -1, -1):
        if prime[i]:
            nxt = i
        next_prime[i] = nxt

    powers = []
    x = 1
    while x <= limit:
        powers.append(x)
        x *= 2

    ans = []
    for value in a:
        p = next_prime[value]
        idx = bisect.bisect_left(powers, value)
        pw = powers[idx]
        if p < pw:
            ans.append(str(p))
        else:
            ans.append(str(pw))

    print(" ".join(ans))

if __name__ == "__main__":
    solve()
```前処理のサイズは最大入力値に依存するため、コードは最初にすべてのクエリを読み取ります。 ふるいは`bytearray`これはブール情報のみを保存し、Python の整数リストよりもはるかにメモリ効率が高いためです。 

ふるい内のスライスの割り当てでは、すべての素数の倍数が一度にマークされます。 生成された`next_prime`配列は逆方向に埋められるため、すべての位置でその右側に最も近い素数がすぐにわかります。 これにより、すべてのクエリに対して素数に対する二分検索を行う必要がなくなります。 

力のリストは 1 から始まります。$2^0$ゼロのような場合に必要です。 二分探索では、現在の値以上の最初のべき乗が返されます。 最後の比較では、最も近い許容可能な数値が素数であるか 2 の累乗であるかという、残りの唯一の決定が処理されます。 

最大クエリ値の後の追加の 100000 桁により、次の素数に到達するのに十分な余地が得られます。 これにより、ふるいのサイズを小さく保ちながら、可能な最大の入力値の複雑な処理も回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(M log log M + M + n log log M) | ふるいは前処理を支配し、各クエリは 2 のべき乗の間で二分検索を実行します。 
| スペース | お(お) | sieve と next-prime 配列には、限界値までのすべての位置の情報が格納されます。 

最大値は$10^7$したがって、Python では線形サイズの前処理構造が実用的です。 前処理の後、ソリューションは次の処理を行います。$10^5$2 のべき乗に対する小さな二分検索を除き、一定サイズの作業のみを行うクエリ。 

## テストケース```python
import sys
import io
import bisect

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return ""

    n = data[0]
    a = data[1:]

    mx = max(a)
    limit = mx + 100000

    prime = bytearray(b'\x01') * (limit + 1)
    prime[0] = 0
    if limit >= 1:
        prime[1] = 0

    i = 2
    while i * i <= limit:
        if prime[i]:
            prime[i * i:limit + 1:i] = b'\x00' * (((limit - i * i) // i) + 1)
        i += 1

    nxt = 0
    next_prime = [0] * (limit + 2)
    for i in range(limit, -1, -1):
        if prime[i]:
            nxt = i
        next_prime[i] = nxt

    powers = []
    x = 1
    while x <= limit:
        powers.append(x)
        x *= 2

    res = []
    for v in a:
        p = next_prime[v]
        pw = powers[bisect.bisect_left(powers, v)]
        res.append(str(min(p, pw)))

    return " ".join(res)
