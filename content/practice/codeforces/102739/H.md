 ## 解決策
 # 問題の理解

 この問題では、一連の配送会社に関する多くの範囲クエリに答えるように求められます。 日中、到着した宅配業者の会社が配列として記録されます`a`。 各同僚に対して、その同僚が食べ物を注文した可能性のある期間を表すこの配列の間隔が与えられます。 その範囲内で最も多く出現する会社番号を見つけなければなりません。 複数の会社が同じ最大周波数を持っている場合は、どの会社でも受け入れられます。 

配列の長さとクエリの数は両方とも次の範囲に達する可能性があります。`100000`、一方、企業識別子は次のように大きくなる可能性があります。`10^9`。 識別子の範囲が広いということは、会社番号を配列インデックスとして直接使用できないことを意味するため、圧縮が必要になります。 のサイズ`n`そして`q`すべての間隔のすべての要素をチェックすることを除外します。 各クエリを個別にスキャンするソリューションは、次のようなパフォーマンスを実現できます。`10^10`最悪の場合、1 秒の制限をはるかに超えた操作が行われます。 配列内の総移動量が次の値に近いメソッドが必要です。`n * sqrt(n)`。 

よくある間違いは、ネクタイを間違って扱うことです。 答えは一意である必要はありません。 例えば：```
5
1 2 1 2 3
1
1 4
```正しい出力は次のいずれかです。`1`または`2`, どちらも 2 回出現するためです。 最初に見つかった最大値が常に安定していると仮定するソリューションは、データ構造から要素を削除した後に失敗する可能性があります。 

もう 1 つのエッジ ケースは、単一の要素を含むクエリです。```
3
7 8 9
1
2 2
```答えは次のとおりです。`8`。 現在の最大周波数をゼロに初期化し、最初の要素を正しく追加することを忘れた実装では、無効な値が返される可能性があります。 

3 番目のケースは、多くのアップデートを経て 1 つの企業が優勢になった場合です。```
6
5 1 5 2 5 3
1
1 6
```答えは次のとおりです。`5`。 現在の最大値を増やすだけで、削除後に修復しない遅延更新戦略では、古い頻度が維持され、間違った答えが生成される可能性があります。 

## アプローチ

 直接的なアプローチは、各クエリを個別に処理することです。 しばらくの間`[l, r]`、間のすべての位置をスキャンします。`l`そして`r`、すべての企業の出現数をカウントし、最大数を選択します。 これは、クエリに属する​​要素を正確に検査するため、正しいです。 問題は繰り返し作業です。 すべてのクエリが配列全体をカバーする場合、各クエリにコストがかかります`O(n)`、与える`O(nq)`となり、`10^10`最大入力サイズの操作。 

問題の構造は、クエリが範囲内の頻度についてのみ質問し、隣接するクエリが重なり合うことが多いということです。 頻度情報を毎回ゼロから再構築する代わりに、クエリの順序を変更して 1 つの移動ウィンドウを維持できます。 これが Mo のアルゴリズムの背後にある考え方です。 

Mo のアルゴリズムは、配列をおおよそのサイズのブロックに分割します。`sqrt(n)`。 クエリは左側のブロックによって並べ替えられ、次に右側のエンドポイントによって並べ替えられます。 あるクエリから次のクエリに移動するときは、変更された位置のみを追加または削除します。 維持されるウィンドウには常に現在のクエリ間隔が正確に含まれるため、頻度テーブルは常に準備ができています。 

残りの課題は、要素がウィンドウに出入りする間、最も頻繁に発生する会社を維持することです。 圧縮された企業識別子の周波数配列と、各周波数を現在保有している企業の数を示す別の配列を保持します。 要素を削除するときに、現在の最大頻度がなくなった場合は、その頻度を持つ企業が存在するまでその頻度を減らします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最適 | O((n + q)√n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての会社 ID を連続した整数に圧縮します。 最終的な答えを逆変換できるように、元の値は個別に保存されます。 
2. ブロックサイズを選択します`sqrt(n)`Mo の順序に従ってクエリを並べ替えます。 小さい左側のブロックを持つクエリが最初に来て、1 つのブロック内で右側のエンドポイントの順序が増えます。 これにより、現在の間隔が全体的にどれだけ移動する必要があるかが最小限に抑えられます。 
3. 2 つのポインターを使用して現在の間隔を維持します。 最初は間隔は空です。 左または右の境界が変更された場合は、対応する配列位置を追加または削除します。 
4. 会社を追加する場合は、その頻度を増やします。 その頻度を持つ企業の数を更新し、必要に応じて現在の最大値を引き上げます。 
5. 会社を削除する場合は、その頻度を減らします。 周波数カウンターを更新します。 以前の最大周波数が存在しなくなった場合は、有効な周波数が残るまで最大値を下げます。 
6. 処理されたクエリごとに、頻度が現在の最大頻度と等しい会社を選択し、その元の識別子を保存します。 

不変条件は、ポインタが移動するたびに、頻度テーブルが現在の間隔内の要素を正確に記述することです。 2 番目の構造は、保存された最大周波数が常にウィンドウに実際に表示される周波数であることを保証します。 回答はその頻度を持つ企業からのみ選択されるため、生成されたすべての回答は要求された範囲の有効なモードになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    values = sorted(set(arr))
    comp = {v: i for i, v in enumerate(values)}
    a = [comp[x] for x in arr]

    q = int(input())
    queries = []
    for i in range(q):
        l, r = map(int, input().split())
        queries.append((l - 1, r - 1, i))

    block = int(n ** 0.5) + 1

    queries.sort(
        key=lambda x: (
            x[0] // block,
            x[1] if (x[0] // block) % 2 == 0 else -x[1]
        )
    )

    freq = [0] * len(values)
    freq_count = [0] * (n + 1)

    answers = [0] * q
    current_max = 0
    best = -1

    def add(x):
        nonlocal current_max, best
        old = freq[x]
        if old:
            freq_count[old] -= 1
        new = old + 1
        freq[x] = new
        freq_count[new] += 1
        if new > current_max:
            current_max = new
            best = x

    def remove(x):
        nonlocal current_max, best
        old = freq[x]
        freq_count[old] -= 1
        new = old - 1
        freq[x] = new
        if new:
            freq_count[new] += 1
        if old == current_max and freq_count[old] == 0:
            current_max -= 1
            while current_max and freq_count[current_max] == 0:
                current_max -= 1
            if current_max:
                for i, f in enumerate(freq):
                    if f == current_max:
                        best = i
                        break

    left = 0
    right = -1

    for l, r, idx in queries:
        while left > l:
            left -= 1
            add(a[left])
        while right < r:
            right += 1
            add(a[right])
        while left < l:
            remove(a[left])
            left += 1
        while right > r:
            remove(a[right])
            right -= 1

        answers[idx] = values[best]

    print("\n".join(map(str, answers)))

if __name__ == "__main__":
    solve()
```圧縮ステップにより、大きな企業番号が小さなインデックスに置き換えられ、周波数配列への一定時間のアクセスが可能になります。 元の番号はそのまま残ります`values`したがって、出力では引き続き入力の識別子が使用されます。 

の`queries`ソート順序は Mo のアルゴリズムの主要部分です。 右端点の交互の方向により、隣接するブロック間の不必要なポインターの移動が減少します。 

の`freq`配列には、圧縮されたすべての会社の現在の出現数が格納されます。 の`freq_count`array は、特定の周波数が現在存在するかどうかという別の質問に答えます。 これにより、削除するたびにすべての周波数を再構築する必要がなくなります。 

Python の整数はオーバーフローしないため、頻度値は安全です。 重要な境界の詳細は、維持される間隔には両側が含まれるため、ポインタを移動する際には追加操作と削除操作が正しい順序で行われる必要があるということです。

 ## 特殊なケース

 アルゴリズムは現在の最大頻度を持つ企業のみを検索するため、同点のケースが処理されます。 特定の企業が勝たなければならないということは決して想定しておりません。 のために：```
5
1 2 1 2 3
1
1 4
```維持される周波数は`1:2`そして`2:2`, なので、どちらの会社でも返品可能です。 

単一要素クエリの場合:```
3
7 8 9
1
2 2
```Mo のアルゴリズムは位置のみを追加することで空のウィンドウを拡張します`2`。 の頻度`8`は 1 になり、最大周波数も 1 になるため、返される答えは正確に次のようになります。`8`。 

多くの更新後の主要な値の場合:```
6
5 1 5 2 5 3
1
1 6
```最終的な頻度テーブルには以下が含まれます`5:3`、他のすべての会社は周波数 1 を持っています。 維持される最大値は 3 になり、アルゴリズムは戻ります。`5`。 削除によって勝者の頻度が一時的に減少した場合でも、同じロジックが機能します。これは、頻度カウンターが次のクエリに答える前に最大値を修復するためです。
