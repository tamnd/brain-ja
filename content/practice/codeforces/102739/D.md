 ## 解決策
 # 問題の理解

 タスクは、正方形の都市地図を 2 つの国に分割することです。 各セルには都市が含まれているか、空です。 マップ全体の都市の数は偶数であり、両国はまったく同じ数の都市を受け取る必要があります。 国境はセルの端に沿っている必要があり、各国の内部では、その国のセルのみを使用して、すべてのセルが他のすべてのセルから到達可能でなければなりません。 

入力は、`N x N`グリッドどこ`C`都市をマークし、`D`空のセルにマークを付けます。 出力は同じサイズの別のグリッドで、すべてのセルが 2 つの国のいずれかに割り当てられます。 

主な困難は都市を数えることではなく、双方のつながりを維持する分割を作成することです。 と`N`50 までは、グリッドのセル数は最大 2500 です。 これは、線形または二次アルゴリズムにとっては十分小さいですが、可能な分割の数が指数関数的に増加するため、多くの可能な境界を試したり、すべてのパーティションにわたって高価な検索を実行したりするアプローチは不可能です。 

いくつかの特殊なケースには注意が必要です。 2 つの都市だけを含むグリッドも引き続き有効です。 例えば：```
2
CD
DC
```正しい出力は次のようになります。```
11
22
```完全な行または列を 1 つの国に配置しようとする方法は、都市のバランスが直線に沿って取れていない可能性があるため、失敗する可能性があります。 

もう 1 つのケースは、都市がマップの一端に集中している場合です。```
3
CCC
DDD
DDD
```正しい出力は次のとおりです。```
111
222
222
```都市の数ではなくセルの数が均衡しているかどうかのみをチェックする不用意なソリューションでは、無効な答えが生成されます。 

最後のトリッキーなケースは、列内のカットです。 例えば：```
3
DDD
CDC
DDD
```有効な出力は次のとおりです。```
111
122
222
```2 つの国に同じ数のセルが含まれている必要はありません。 重要なのは都市の数のみであるため、均等な面積を強制すると不必要な制限が生じます。 

## アプローチ

 直接的な強引なアイデアは、接続されている可能性のあるすべてのリージョンを試し、その補完領域も接続されており、都市の半分が含まれているかどうかを確認することです。 考えられるすべての答えを調べるため、正しさを簡単に確認できます。 ただし、10 × 10 のグリッドであっても、可能なサブセットの数はすでに膨大です。 50 x 50 グリッドの場合は次のようになります。`2^2500`したがって、徹底的な検索はオプションではありません。 

有益な観察は、任意の形状を検索する必要がないということです。 境界線を移動する間、両側が接続されたままであることが保証される形状が 1 つだけ必要です。 グリッドのスネークトラバースには、まさにこの特性があります。 

セルを 1 行ずつ訪問することを想像してください。 最初の行では左から右に、2 行目では右から左に移動し、方向を変えます。 この順序のすべてのプレフィックスは、複数の完全な行と現在の行のセグメントで構成されているため、接続されています。 すべての接尾辞は同じ理由で接続されています。 これにより、可能なすべてのカットが有効な分割を作成する 1 次元の順序付けが得られます。 

次に、この蛇の順序に沿って歩き、すべての都市の半分を収集したらすぐに停止します。 訪問したセルが 1 番目の国となり、残りのセルが 2 番目の国になります。 経由地は都市数によって選択されるため、両国は必要な数の都市を受け取ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(N*N)) | O(N*N) | 遅すぎる |
 | 最適 | O(N*N) | O(N*N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッド上の都市の総数を数え、各国が受け取る必要がある都市の数を計算します。 声明では都市の総数が均等であることが保証されているため、目標は全体の半分となる。 
2. ヘビの順序でセルを生成します。 偶数行の場合は、左から右の列に移動します。 奇数の行の場合は、右から左の列にアクセスします。 すべてのプレフィックスとサフィックスが接続されたままであるため、この順序が選択されます。 
3. 蛇の秩序を横断し、最初の国に割り当てられた都市の数を数え続けます。 カウントが目標の都市数に達するまで、セルを最初の国に属するものとしてマークします。 
4. 残りのすべてのセルを 2 番目の国に割り当てます。 カット位置はすでに有効であるため、追加の接続チェックは必要ありません。 

これが機能する理由: 不変条件は、スネーク オーダーのプレフィックスを処理した後、処理されたセルが 1 つの連結コンポーネントを形成するということです。 未処理のサフィックスについても同様です。 トラバースが停止すると、最初の国はまさにそのような接頭辞となり、2 番目の国はま​​さにそのような接尾辞になります。 最初の国が全都市の半分を受信すると停止が発生するため、2 番目の国は自動的に残りの半分を受信します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    grid = [input().strip() for _ in range(n)]

    total = sum(row.count('C') for row in grid)
    need = total // 2

    ans = [['2'] * n for _ in range(n)]

    got = 0
    done = False

    for i in range(n):
        cols = range(n) if i % 2 == 0 else range(n - 1, -1, -1)
        for j in cols:
            if done:
                break
            ans[i][j] = '1'
            if grid[i][j] == 'C':
                got += 1
                if got == need:
                    done = True
        if done:
            break

    print('\n'.join(''.join(row) for row in ans))

if __name__ == "__main__":
    solve()
```コードはまず都市を数えて、最初の国に必要な数を決定します。 回答グリッドは 2 番目の国に割り当てられたすべてのセルから始まります。つまり、トラバーサルではプレフィックス セルを次のようにマークするだけで済みます。`1`。 

ネストされたループはスネーク パスを実装します。 方向は、接続を維持するための重要な詳細である行パリティに基づいて変わります。 目標の都市数に達すると、残りのセルにはすでに正しい割り当てが割り当てられているため、ループは直ちに停止します。 

グリッドは内部でゼロベースの座標を使用するため、インデックス調整は必要ありません。 グリッドには最大 2500 個のセルが含まれるため、Python の整数はすべての可能なカウンターに対して十分な大きさになります。 

## 実用的な例

 次のことを考慮してください。```

DDD
DDC
DDC
```蛇の順番は、`(0,0) ... (0,2), (1,2) ... (1,0), (2,0) ... (2,2)`。 都市が 2 つあるため、最初の国には 1 つの都市が必要です。 

| ステップ | セル | 国の都市数 1 | 割り当て |
 | --- | --- | --- | --- |
 | 1 | (0,0) | 0 | 1 |
 | 2 | (0,1) | 0 | 1 |
 | 3 | (0,2) | 0 | 1 |
 | 4 | (1,2) | 1 | 1 |
 | 5 | 残りのセル | 1 | 2 |

 結果として生じる分割により、各国に 1 つの都市が与えられます。 最初の国は一番上の行に最初の都市セルを加えたもので、残りのセルは接続されたままになります。 

別の例:```
3
CCC
DDD
DDD
```ここでも、ヘビの順序は左上から始まります。 都市が 3 つあるため、最初の国にはそのうち 2 つが必要です。 

| ステップ | セル | 国の都市数 1 | 割り当て |
 | --- | --- | --- | --- |
 | 1 | (0,0) | 1 | 1 |
 | 2 | (0,1) | 2 | 1 |
 | 3 | 残りのセル | 2 | 2 |

 カットは最初の行の内側で行われます。 これは、スネーク順序がなぜ有用であるかを示しています。最初の国は、両方の部分が接続されたままでも行の途中で終了する可能性があります。

 ## 特殊なケース

 都市が 2 つしかない場合、アルゴリズムは、蛇の順序で最初の都市に遭遇した後で停止します。 プレフィックスには 1 つの都市が含まれ、サフィックスにはもう 1 つの都市が含まれます。 接続プロパティはスネーク順序から得られるため、特別な処理は必要ありません。 

すべての都市が横断の開始点近くに表示される場合、国境は非常に早い段階で表示されることがあります。 最初の国には少数のセルしか含まれていない可能性があるため、アルゴリズムは引き続き機能します。 都市の数が等しいためには、領土のサイズが等しい必要はありません。 

必要な分割が行の途中で発生した場合、アルゴリズムはその行の一部のみを最初の国に割り当てます。 その前の完全な行はこのセグメントに接続され、残りのセグメントはその後の行に接続されます。 これはまさに、単純な行または列ベースのカットが失敗する一方、スネーク順序付けは成功する状況です。
