 ## 解決策
 ## 問題の理解

 私たちは持っています`n`期間中に完了する必要がある独立したサブタスク`m`連続した日々。 各サブタスクには許可される時間間隔があり、次の日からいつでも実行できます。`s_i`に`f_i`。 サブタスクにはちょうど 1 日単位が必要です。つまり、複数のサブタスクを同じ日に実行することもできますが、1 日の数はできるだけ少なくしたいと考えています。 

目標は、すべてのサブタスクが 1 つの有効な日に割り当てられ、1 日に割り当てられるサブタスクの最大数が最小限に抑えられるスケジュールを見つけることです。 出力は、この最小限の可能な最大負荷に、日ごとのサブタスクの 1 つの有効な分布が続きます。 

制限により、最大で許可されます`300000`サブタスクと`300000`日々。 検索空間が指数関数的に増大するため、多くの可能な割り当てをチェックするアプローチは不可能です。 すべてのサブタスクを可能な限り毎日試すシミュレーションでも、約`n * m`、それは約です`9 * 10^10`最大の場合の操作。 に近い解決策が必要です`O((n + m) log n)`または`O((n + m) log^2 n)`。 

主な困難は、特定の 1 日あたりの最大負荷が可能かどうかを判断するだけでなく、実際のスケジュールを構築することです。 正しいソリューションでは、重なり合う間隔、利用可能なタスクがない日、実行可能なタスクが 1 日しかないタスクを処理する必要があります。 

単一のタスクを考えてみましょう。```
1 1
```1日利用可能です。 答えは`1`、唯一のタスクを初日に実行する必要があるためです。 平均負荷から答えを初期化するソリューション`ceil(n / m)`しかし、そのような場合には不可能な集中間隔が失敗する可能性があることを忘れています。 

別の例は次のとおりです。```
3 3
1 1
1 1
1 3
```正しい答えは、`2`。 最初の 2 つのタスクは両方とも 1 日目に実行する必要があるため、最大負荷を 1 つにすることは不可能です。 期限を考慮せずに 1 日あたりのタスクの総数だけを見る不注意な貪欲な方法では、1 日あたり 1 つのタスクで十分であると誤って主張する可能性があります。 

最後のエッジケースは次のとおりです。```
2 5
2 2
5 5
```答えは`1`。 3日目と4日目は仕事がありませんが、それは問題ではありません。 すべてのタスクに必要な有効日は 1 日だけです。 誤って毎日タスクを受信する必要がある実装では、有効なスケジュールが拒否されます。 

## アプローチ

 最も直接的なアプローチは、1 日に許可されるサブタスクの最大数を推測しながらスケジュールを作成してみることです。 

答えが最大で次であることがわかっているとします。`x`。 これが可能かどうかは、左から右に日をスイープすることでテストできます。 開始日が到来したすべてのサブタスクが利用可能になります。 利用可能なすべてのサブタスクの中で、終了日が最も早いものを常に選択する必要があります。 これは、標準的な最も早い期限の貪欲ルールです。 タスクの有効期限がすぐに切れる場合、後のタスクにはまだ柔軟性がある可能性があるため、タスクを延期することは危険です。 

固定の場合`x`、スケジュールが存在する場合は常に、最も短い期限を持つ選択したタスクを当日に移動しても、将来の日が困難になることはないため、この貪欲なチェックは正しいです。 最も緊急性の高いタスクを最初に使用するため、タスクが不必要に失われることはありません。 

ただし、次の 1 つの値をテストすると、`x`十分ではありません。 有効な最小値が必要です。 答えは単調です。`x`動作する場合は、さらに大きな容量も動作します。 これにより、答えに対する二分探索が可能になります。 

ブルート フォース バージョンでは、可能な限りすべての容量を試し、スケジュールを繰り返し再構築します。 すべての容量を試してみます`n`実行可能性チェックにはそれぞれコストがかかるため、遅すぎるでしょう`O((n + m) log n)`、について与える`O(n(n + m) log n)`操作。 

重要な観察は、実現可能性述語が単調であるということです。 二分探索により、チェックの数が約`log n`、グリーディ スイープは、成功した最終チェック中にスケジュールを構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n(n + m) log n) | O(n + m) | 遅すぎる |
 | 最適 | O((n + m) log n log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのサブタスクを開始日までに保存します。 これにより、スイープ中に、その日にどのサブタスクが利用可能になるかをすぐに見つけることができます。 
2. 一日あたりの容量を可能な限り最小にする二分探索`x`。 下限は`1`、上限は`n`というのは、間隔が許せば、1 日にすべてのサブタスクを実行するのが常に上限となるためです。 
3. 候補者の能力ごとに`x`、一日中左から右へのスイープを実行します。 すべてのサブタスクを追加します`s_i`現在の日付と同じ値を、次の順序で最小ヒープに格納します。`f_i`。 
4. 現在の日にまだ未使用の容量がある間に、終了日が最も小さいタスクをヒープから繰り返し削除し、それを当日に割り当てます。 
5. ヒープに終了日が現在日よりも小さいタスクが含まれている場合、候補容量は不可能です。 そのタスクはすでに可能な限り毎日実行されていません。 
6. すべての日が処理された後、すべてのタスクが割り当てられたかどうかを確認します。 「はい」の場合、候補容量は機能し、より小さい答えの検索を続けます。 それ以外の場合は、容量を増やします。 
7. 二分探索で最小容量が見つかったら、その容量で貪欲な構築を最後にもう一度実行し、結果の割り当てを出力します。 

なぜ効果があるのか:

 グリーディ スイープ中に不変なのは、現在ヒープ内にあるすべてのタスクが現在または将来の日のいずれかを待機していることです。 最初に最小の期限を選択すると、最も制限の厳しいタスクが遅れないようになります。 この貪欲なプロセスが失敗した場合は、一部のタスクに有効な位置が残っていないことを意味するため、テストされた容量を持つスケジュールは存在できません。 成功すると、すべてのタスクは間隔と 1 日の制限の両方を尊重して割り当てられます。 次に、二分探索により、この不変条件を維持できる最小容量が見つかります。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

n, m = map(int, input().split())
by_start = [[] for _ in range(m + 2)]

for i in range(1, n + 1):
    s, f = map(int, input().split())
    by_start[s].append((f, i))

def check(cap, need_plan=False):
    heap = []
    ans = [[] for _ in range(m + 1)]
    done = 0

    for day in range(1, m + 1):
        for item in by_start[day]:
            heapq.heappush(heap, item)

        if heap and heap[0][0] < day:
            return None

        take = min(cap, len(heap))
        for _ in range(take):
            f, idx = heapq.heappop(heap)
            if need_plan:
                ans[day].append(idx)
            done += 1

        if heap and heap[0][0] < day:
            return None

    if done != n:
        return None

    if need_plan:
        return ans
    return True

lo, hi = 1, n
while lo < hi:
    mid = (lo + hi) // 2
    if check(mid):
        hi = mid
    else:
        lo = mid + 1

plan = check(lo, True)

out = [str(lo)]
for day in range(1, m + 1):
    out.append(str(len(plan[day])) + (" " + " ".join(map(str, plan[day])) if plan[day] else ""))

print("\n".join(out))
```配列`by_start`タスクが表示される初日ごとにタスクをグループ化します。 これにより、毎日すべてのタスクをスキャンする必要がなくなります。 

ヒープには、終了日順に注文された利用可能なタスクが保存されます。 Python はタプルを辞書編集的に比較します。`(finish, index)`出力に使用できるタスク番号を維持しながら、最も早い期限が自動的に最初に与えられます。 

機能`check`二分探索と最終的な答えの生成の両方に使用されます。 二分探索中は、容量が機能するかどうかだけを知る必要があり、最後の呼び出しでは選択されたタスク番号が記録されます。 

タスクを引き受ける前後に期限をチェックすることで、忘れたタスクが後日まで残ることを防ぎます。 2 番目のチェックは、当日のタスクを割り当てた後、次に小さい期限がすでに無効になっている可能性があるため、便利です。 

すべてのカウンタは最大値であるため、大きな整数の演算は必要ありません。`300000`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n log n) | 各二分探索反復では 1 回のヒープ スイープが実行され、反復回数は O(log n) です。 |
 | スペース | O(n + m) | タスク バケット、ヒープ、および最終スケジュールはすべて、最大でも線形の情報を保存します。 |

def solve(data):

    by_start = [[] for _ in range(m + 2)]

    for i in range(1, n + 1):
        s, f = map(int, input().split())
        by_start[s].append((f, i))

    import heapq

    def check(cap, plan=False):

        cnt = 0

            for x in by_start[day]:
                heapq.heappush(heap, x)

            if heap and heap[0][0] < day:
                return None

            for _ in range(min(cap, len(heap))):
                f, idx = heapq.heappop(heap)
                if plan:

                cnt += 1

            return None

    return "\n".join(out)

 ## 特殊なケース

 対象:```
1 1
1 1
```ヒープは初日に唯一のタスクを受け取り、それをすぐに割り当てます。 二分探索では容量を 1 より小さくすることはできないため、答えは正解です。 

のために：```
3 3
1 1
1 1
1 3
```容量 1 のチェックは失敗します。 1 日目に、貪欲アルゴリズムは 2 つのタスクのうち 1 つを 1 日目に終了するように配置する必要がありますが、同じ期限の別のタスクは残ります。 2 日目が始まると、残りのタスクの有効期限はすでに切れています。 キャパシティ 2 は、両方の緊急タスクが即座に処理されるため、成功します。 

のために：```
2 5
2 2
5 5
```このアルゴリズムでは、1 日目、3 日目、4 日目が空のままになります。 ヒープには許可された日のタスクのみが含まれるため、無効な割り当ては試行されません。

5 5

1 5
1 5
1 5
