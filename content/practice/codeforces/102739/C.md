 ## 問題の理解

 ポリーナには決まった帰宅ルートがあります。 ルートの最初の部分は屋根のない通りで、`t1`2 番目の部分は木々の下の路地で、`t2`分。 彼女は学校をいつ下校するかを選択できますが、遅くともその時間までに到着しなければなりません`d`。 

毎分における雨の強さがわかります。 木々の下を歩いていると、雨の強さが弱まります。`s`, ただしマイナスにはなりません。 タスクは、総雨量が最小となる出発時刻を見つけることです。複数の出発時刻の最小値が同じ場合は、最も早い出発時刻を選択します。 

入力には、ルートの長さ、最終の許容到着時刻、樹木の保護値、および分ごとの雨の強さの配列が含まれます。 出力は、開始分と発生した最小総降雨強度です。 

制約は、意図したソリューションの鍵となります。 値`d`到達できる`10^6`したがって、考えられるすべての開始時刻をチェックし、ルート全体をスキャンするアルゴリズムは、次のように実行されます。`10^12`最悪の場合の運用。 制限時間内で 100 万分を快適に処理できるため、直線的なソリューションが必要です。 

主なエッジ ケースは、ルートの覆われていない部分と覆われている部分の間の移行から発生します。 不注意な解決策は、ツリーの削減が分ごとに個別に適用されること、および結果がマイナスになることはないことを忘れることがよくあります。 

たとえば、次のようになります。```
1 1 2 10
5 20
```正しい出力は次のとおりです。```
0 5
```時間に開始`0`激しさを秘めた1分間を提供します`5`木々に覆われた強烈な1分間`max(20 - 10, 0) = 10`、合計で`15`。 時間に開始`1`旅行全体に余裕がないため、同じ到着制限の問題が発生します。 引き算する解決策`s`1 分ごとではなく、カバーされるセグメントの合計から計算すると、間違った値が計算される可能性があります。 

別のケースは次のとおりです。```
2 2 5 10
8 1 3 4 100
```答えは次のとおりです。```
1 8
```時間に開始`1`覆われていない雨を降らせる`1 + 3 = 4`そして雨が降り注いだ`max(4 - 10, 0) + max(100 - 10, 0) = 90`、これは最適ではありません。 正しい開始は、すべての有効なウィンドウを考慮することによって見つけられます。 よくある間違いは、ルートの分割がどのように変化するかを確認せずに、雨が降っている最初の数分間が常に最適であると想定することです。 

## アプローチ

 直接的なアプローチは、可能な限り出発時刻を試してみることです。 選択した開始について、最初の開始の寄与を計算します。`t1`通常は数分、そして次の分`t2`木の削減で数分。 このアプローチは、問題で最小化する必要がある数量を正確に評価するため、正しいです。 

問題は繰り返し作業です。 まであります`d - t1 - t2 + 1`可能性のある開始の瞬間。 それぞれについて、最大でスキャン`t1 + t2`最悪の場合は数分で約`10^12`操作時の操作`d`は`10^6`が遅すぎます。 

有益な観察は、2 つの隣接する出発時刻がほぼすべての時間を共有していることです。 開始時間を 1 分進めると、ルート計算から 1 分が終了し、新しい 1 分が計算に入ります。 現在の値を再計算するのではなく、更新するだけで済みます。 

ルートは 2 つのスライディング ウィンドウとして表すことができます。 覆われていない部分には常に次のものが含まれます`t1`連続した分であり、カバーされた部分には常に次の内容が含まれます。`t2`分。 ウィンドウがシフトすると、カバーされていないセグメントの最初の 1 分は無関係になり、カバーされたセグメントの最初の 1 分間のステータスが変更され、カバーされたセグメントに新しい 1 分が入ります。 これらの変更を維持すると、考えられるすべての開始時刻を一定時間でチェックできるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(d(t1 + t2)) | O(d) | 遅すぎる |
 | 最適 | O(d) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初に考えられる出発時間、つまり時間における雨への曝露量を計算します。`0`。 最初`t1`分は元の値に寄与し、次の分は元の値に寄与します`t2`分は値の減少に寄与します。 これにより、スライディング ウィンドウの初期値が得られます。 
2. この値を現在の最小値として保存し、最も早い最適な答えが現在の開始時刻であることを覚えておいてください。 
3. 出発時刻を左から右に移動します。 時間をずらす場合`i`時間まで`i + 1`、以前は最初にカバーされていなかった分は旅行の一部ではなくなったため、削除します。 
4. 新しいルートの最初の未カバーの分となる分を追加します。 以前は木の下にあったため、保護された寄与から完全な雨の寄与に変更する必要があります。 
5. ルートの終点の保護セクションに入る新しい分を追加します。 木の削減に貢献します。 
6. 各シフトの後、新しい合計をこれまでに見つかった最良の答えと比較します。 古い回答を保持すると、最も早い開始時間が自動的に保持されるため、値が小さい場合にのみ回答を置き換えます。 

なぜ効果があるのか:

 スライド プロセスのあらゆる瞬間において、維持される値は、正確に現在の出発時間の総降雨量となります。 2 つの隣接する出発間の移行では、境界分の保護ステータスの変更を含め、ルートから消える分が正確に削除され、ルートに入る分が正確に追加されます。 すべての有効な出発時刻が 1 回訪問され、最小値が記録されるため、アルゴリズムは最適な出発時刻を見つけます。 最初に出現した最小値を維持することで、タイブレーク ルールが処理されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t1, t2, d, s = map(int, input().split())
    r = list(map(int, input().split()))

    def wet(x, protected):
        if protected:
            return max(0, x - s)
        return x

    cur = 0

    for i in range(t1):
        cur += r[i]

    for i in range(t1, t1 + t2):
        cur += wet(r[i], True)

    best = cur
    best_start = 0

    for start in range(1, d - t1 - t2 + 1):
        cur -= r[start - 1]
        cur -= wet(r[start + t1 - 1], True)
        cur += r[start + t1 - 1]
        cur += wet(r[start + t1 + t2 - 1], True)

        if cur < best:
            best = cur
            best_start = start

    print(best_start, best)

if __name__ == "__main__":
    solve()
```機能`wet`は、問題の中で唯一の特別な演算である木に覆われた雨の強度を分離します。 これを 1 か所に保管しておくと、カバーされていない分に誤って削減が適用されることを避けられます。 

初期計算では出発時刻の状態を構築します`0`。 最初のループは通常の道路を処理し、2 番目のループは路地を処理します。 その後、スライディング ループによって現在の値が更新されます。 

更新順序は重要です。 位置の分`start + t1 - 1`は保護されたセグメントからカバーされていないセグメントに移動するため、最初にその保護された部分を削除してから、その値をすべて追加する必要があります。 新しい最後の分は保護されたセグメントにのみ入るため、その削減された値が直接追加されます。 

実装ではすべてのインデックスはゼロベースです。 ループは次で停止します`d - t1 - t2`それは、締め切り前に旅行を完了できる最後の出発時刻であるためです。

import sys
import io

def solve(inp):
    old_stdin = sys.stdin
    old_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    import builtins

    def solution():
        input = sys.stdin.readline
        t1, t2, d, s = map(int, input().split())
        r = list(map(int, input().split()))

        def wet(x):
            return max(0, x - s)

        cur = sum(r[:t1]) + sum(wet(x) for x in r[t1:t1+t2])
        best = cur
        ans = 0

            cur -= r[start - 1]
            cur -= wet(r[start + t1 - 1])
            cur += r[start + t1 - 1]
            cur += wet(r[start + t1 + t2 - 1])

            if cur < best:
                best = cur
                ans = start

        print(ans, best)

    solution()

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out.getvalue()

 ## 特殊なケース

 木の減少が降雨強度よりも大きい場合、保護された寄与は負の値ではなくゼロになる必要があります。 のために：```
1 1 2 10
5 20
```アルゴリズムは最初の 1 分を次のように計算します。`5`そして2分目は`max(20 - 10, 0) = 10`。 負でない保護された値を保持し、次を返します。```
0 15
```複数の出発時刻の最小エクスポージャが同じ場合は、最も早い出発時刻が残らなければなりません。 更新では、厳密に小さい値が表示された場合にのみ、保存された回答が変更されます。 例えば：```
1 1 3 5
7 7 7
```どの出発時刻でも合計は同じになるため、答えは次のようになります。```
0 7
```木の下から通常の道路に一瞬変化するケースは、オフバイワンバグが発生しやすい場所です。 のために：```
2 2 5 10
8 1 3 4 100
```この更新により、送信境界分の古い保護された寄与分が削除され、検出された後にその完全な値が追加されます。 これはまさにスライディング式で表される遷移であるため、アルゴリズムは正しい結果を生成します。```
1 8
```
