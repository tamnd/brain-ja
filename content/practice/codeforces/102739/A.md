 ## 解決策
 # 問題の理解

 ギャラリーには以下が含まれます`n`絵画は左から右へ決まった順序で配置されています。 アリーナはギャラリーの最初の側からスタートし、最後の絵に向かって歩きます。 散歩中、彼女は現在の方向の前方にある絵画にのみ立ち寄ることができます。 ギャラリーの端に到達すると、彼女は向きを変え、反対方向に進みます。 音声ガイドには、彼女が実際にすべての絵画を鑑賞した順序が記録されています。 

課題は、この閲覧順序を生成する可能性があるギャラリー内の完全な歩行の最小数を再構築することです。 左から右へのウォークには記録された順序で増加するペイント番号が含まれている必要があり、右から左へのウォークには減少するペイント番号が含まれている必要があります。 

入力により、ペイント番号の順列が得られます。 すべての絵画は一度だけ出現するため、シーケンス自体が各絵画が閲覧された正確な瞬間を教えてくれます。 出力は、このシーケンスを分割するために必要な、交互に増加および減少するセグメントの最小数です。 

主な制約は、`n ≤ 100000`。 これにより、シーケンスの可能なすべての分割を試したり、すべてのパスですべてのペイントを繰り返しシミュレートしたりするソリューションが除外されます。 ソリューションでは、各絵画を一定回数処理する必要があります。これは、`O(n)`アプローチ。 

微妙な点は、その方向に見える最後の絵に到達しても散歩は終了しないということです。 ギャラリーの物理的な端に到達した場合にのみ終了します。 このため、たとえより長い数学的サブシーケンスがまだ増加または減少している可能性がある場合でも、オーディオ シーケンス内の次のペイントによって新しいウォークが強制される可能性があります。 

次の入力を考えてみましょう。```
4
1 2 4 3
```正しい出力は次のとおりです。```
2
```最初に左から右に歩くと見えます`1 2 4`。 絵画`3`は現在位置より後ろにあるため、アリーナは引き返さなければなりません。 長く増加するサブシーケンスだけを探す不注意な解決策では、より少ないウォークが可能であると誤って判断する可能性があります。 

もう 1 つのエッジ ケースは、次のペイントのたびに方向を変更する必要がある場合です。```
5
1 5 2 4 3
```正しい出力は次のとおりです。```
5
```このシーケンスは、ペイントするたびに増加と減少を繰り返します。 等しい要素または単一要素のウォークを誤って処理すると、すべてのペイントで完了したウォークが必要となるため、ここでオフバイ 1 エラーが発生する可能性があります。 

## アプローチ

 直接的なアプローチは、ギャラリーの散歩をシミュレートすることです。 既に閲覧した一連の絵画を維持し、一方の端から開始して、ギャラリー内を繰り返し移動して、現在の方向にある次に利用可能な絵画を探すことができます。 このアプローチはストーリーに正確に従っているため、正しいです。 ただし、これを直接実装するには、パスごとに多くの絵画をスキャンする必要がある場合があります。 最悪の場合、こんなことも考えられます`n`パスと各パスで検査できる`n`絵画、につながる`O(n²)`操作が遅すぎるため、`n = 100000`。 

重要な観察は、オーディオ シーケンスには必要な情報だけがすでに含まれているということです。 1 回の歩行中に、表示される絵画の番号は単調なシーケンスを形成する必要があります。 最初の歩行は増加し、2 番目の歩行は減少し、3 番目の歩行は増加する必要があります。 したがって、この問題は、順列を左から右に読み取るときに、増加と減少の実行を何回切り替える必要があるかを見つけることと同じです。 

すべての歩行が 1 つの単調セグメントに対応するため、総当たりシミュレーションが機能します。 シーケンス内にすでに存在する情報を発見するのに繰り返し時間がかかるため、失敗します。 現在の歩行の方向が以前に表示された絵画によって決定されるという観察により、シミュレーション全体を 1 回のスキャンに減らすことができます。

 ## アルゴリズムのチュートリアル

 1. 1回の散歩から始めます。 その方向は左から右であるため、現在のセグメントは増加しているはずです。 
2. 音声ガイドに保存されている順序で絵画をスキャンします。 以前の絵画番号と現在の歩行に必要な方向を保持します。 
3. 現在の方向が増加していて、次の絵の番号が前の絵の番号より大きい場合、同じ歩行を続けることができます。 
4. 現在の方向が減少していて、次の絵の番号が前の絵の番号より小さい場合、同じ歩行を続けることができます。 
5. そうしないと、現在の散歩にこの絵を含めることはできません。 ウォークの数を増やし、方向を逆にします。これは、Arina がギャラリーの端に到達して、ギャラリーを見る前に向きを変えたはずであるためです。 
6. 以前のペイント番号を現在の番号に置き換え、シーケンス全体が処理されるまで続行します。 

貪欲な切り替えで十分である理由は、すべての歩行の方向が固定されているためです。 2 つの連続した絵画がその方向に違反すると、以前の選択では状況を修復することはできません。 2 番目の絵は物理的にアリーナの間違った側にあるため、新たな歩行は避けられません。 

なぜ効果があるのか:

 不変条件は、オーディオ シーケンスのプレフィックスを処理した後、アルゴリズムがそのプレフィックスに必要な最小ウォーク数を正確にカウントしており、現在の方向が次のウォークで可能な唯一の方向であるということです。 次の絵が現在の方向に適合する場合は、答えが増加しないため、現在の歩行を延長することが常に最適です。 適合しない場合は、前のウォークにその絵を含めることができないため、もう 1 つのウォークを追加することが必須です。 すべての決定が強制されるため、貪欲なプロセスにより可能な限り最小限の四球が生成されます。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    ans = 1
    direction = 1
    prev = a[0]

    for x in a[1:]:
        if direction == 1:
            if x < prev:
                ans += 1
                direction = -1
        else:
            if x > prev:
                ans += 1
                direction = 1
        prev = x

    print(ans)

if __name__ == "__main__":
    solve()
```変数`direction`現在のギャラリーの歩行方向を保存します。 の値`1`現在の歩みは、小さな絵画番号からより大きな絵画番号へと進むことを意味します。`-1`逆方向に進むことを意味します。 

スキャンでは、オーディオ シーケンス内の隣接する絵画のみが比較されます。 比較が現在の方向と矛盾する場合、コードは直ちに新しいウォークを開始し、方向を反転します。 

による初期化`ans = 1`最初のペイントには常に少なくとも 1 回の歩行が必要なため、安全です。 制約は次のことを保証します`n`少なくとも 1 つあるため、アクセス`a[0]`有効です。 

アルゴリズムは前の描画、現在の方向、現在の答えのみを必要とするため、追加の配列は必要ありません。

import sys
import io

    old_stdin = sys.stdin

                ans += 1
                direction = 1
        prev = x

    sys.stdin = old_stdin

 ## 特殊なケース

 単一塗装の場合:```
1
1
```アルゴリズムは 1 回のウォークから始まり、ループには入りません。 答えは残っている`1`これは、アリーナに入ってその絵を見るだけでよいという事実と一致します。 

すでに増加しているシーケンスの場合:```

```すべての比較は現在の左から右の方向と一致します。 アルゴリズムは決して方向を変えずに戻ります`1`。 最後の絵に到達した後に常に交互に実行されるソリューションでは、ここでオーバーカウントされます。 

最初のステップが後戻りする場合:```

```Arina は小さいインデックスから大きいインデックスに向かって移動しているため、最初のウォークには 2 番目の絵画を含めることはできません。 アルゴリズムは、以下を含む最初の増加する歩行をカウントします。`4`、その後、残りを含む減少歩行に切り替えます。 答えは、`2`。 

頻繁に変更が行われるシーケンスの場合:```

```隣接するすべてのペアが現在の方向を壊します。 アルゴリズムは比較のたびに方向を変えて戻ります。`6`これは、最初の後の各ペイントが個別のトラバースを必要とするという事実と一致します。
