 ## 問題の理解

 という表現から始めます`n × n`。 1 回の反復中に、この正確なパターンが出現するたびに次のパターンに置き換えられます。`n`番号のコピー`n`。 これらのコピーは左から右にペアになっており、`×`すべてのペアの内側に挿入されます。 連続するペア間、および最後のペアとペアになっていない決勝戦の間`n`いつ`n`奇数、通常の乗算​​記号`·`が挿入されます。 

操作が繰り返される`k`回。 最後に残ったすべての`×`にも変わります`·`, したがって、2 つの乗算記号の区別はなくなります。 タスクは、最終式モジュロ内のすべての乗算記号をカウントすることです。`998244353`。 

値は次のとおりです。`n <= 10^9`そして`k <= 10^6`。 線形アルゴリズムであっても`k`反復は約 100 万回のみ実行されますが、これはまったく合理的です。 不可能なのは、式自体を構築することです。式のサイズは反復回数に応じて指数関数的に増大するためです。 以来`n`すでに 10 億に達する可能性があり、単一の拡張でも巨大な表現を作成できます。`k`そのサイズは、実際のメモリや時間制限をはるかに超えています。 

直接的な再発が起こりやすい小さなケースがいくつかあります。 のために`n = 1, k = 1`、イニシャル`1 × 1`正義になる`1`、したがって、答えは次のとおりです`0`。 すべての反復で新しい乗算記号が作成されると盲目的に仮定する繰り返しでは、誤って最初の乗算記号が保持されてしまいます。 のために`n = 2`、式`2 × 2`に変身します`(2 × 2)`、したがって、乗算記号の数は次のとおりになります。`1`永遠に。 これは幾何比が次のようになる特殊なケースです。`1`。 最後に、いつ`k = 0`、変換はまったく起こらないので、すべての`n`答えはまさにそのとおりです`1`。 例えば、`1 0`答えがあります`1`たとえ最初の変換で乗算が完全に削除されてもです。 

## アプローチ

 簡単なアプローチは、反復ごとに式を構築することです。 これは定義に文字通り従っており、現在のそれぞれを置き換えるので、これは正しいです。`n × n`必要な括弧と乗算記号を挿入します。 問題は、関係するデータの量です。 させて`q = floor(n / 2)`。 あらゆる出来事が起こる`×`正確に生成します`q`新たな出来事`×`次の反復では、`n`新しい数字の形式`q`完全なペア。 1から始める`×`、 後`t`反復があります`q^t`そのようなシンボル。 したがって、建設ベースのソリューションには少なくとも次のものが必要です。`Theta(q^k)`関連するシンボルを表すためだけに機能します。 次のような値の場合、`n = 10^9`そして`k = 10^6`、これはまったく不可能です。 

重要な観察は、実際の式は決して必要ないということです。 含まれている乗算記号の数だけを知る必要があります。 あると仮定します`x_t`の発生`×`後`t`繰り返し。 それらのそれぞれは独立して、以下を含む構造になります。`floor(n / 2)`新しい`×`シンボル。 したがって、`x_t = floor(n / 2)^t`。 

次に合計数を考えてみましょう`a_t`乗算記号の両方を数える`×`そして`·`、 後`t`繰り返し。 1 つの古い`×`を含む式に置き換えられます。`n - 1`乗算記号。 置換前には、その場所には 1 つのシンボルが含まれていたため、合計は正確に増加します`n - 2`。 

反復時`t`、 がある`x_t`交換可能なオカレンス。 その結果、`a_{t+1} = a_t + (n - 2) x_t`と`a_0 = 1`。 

置き換える`x_t = q^t`与える`a_k = 1 + (n - 2)(1 + q + q^2 + ... + q^(k-1))`。 

最終的な交換は、`×`による`·`シンボルの数は変わらないので、`a_k`まさに要求された答えです。 

したがって、必要なのは等比数列だけです。 以来`q <= 5 * 10^8`、係数より小さい`998244353`。 もし`q != 1`、使用できます`1 + q + ... + q^(k-1) = (q^k - 1) / (q - 1)`、

 モジュラーインバースを使用します。 分母がモジュラスを法としてゼロである唯一のケースは次のとおりです。`q = 1`、つまり`n = 2`。 その場合の合計は単純に`k`。

 ## アルゴリズムのチュートリアル

 1. コンピューティング`q = n // 2`。 これが新規の数です`×`ある老人によって生み出されたシンボル`×`次の反復中に、`n`数値に正確に含まれる`floor(n / 2)`完全なペア。 
2. 反復後に観察します。`t`、の数`×`記号は`q^t`。 初期式にはそのような記号が 1 つ含まれており、次のようになります。`x_0 = 1`、各反復でこのカウントを乗算します。`q`。 
3. 式自体ではなく、乗算記号の合計数を追跡します。 1 つを交換する`×`と`n`数字が生み出す`n - 1`結果の式内の乗算記号。 古い発生が 1 つのシンボルに寄与したため、純増加は次のようになります。`n - 2`。 
4. この増加を全体で合計します`k`繰り返し。 答えは`1 + (n - 2) * S`、

どこ`S = 1 + q + q^2 + ... + q^(k-1)`。 
5. もし`k = 0`、 それから`S = 0`、したがって、答えは次のとおりです`1`。 The geometric formula also handles this naturally.
 6. もし`q = 1`、 使用`S = k`なぜなら、進行の各項は`1`。 これはまさに次の場合に発生します`n = 2`。 
7. それ以外の場合は計算します`S = (q^k - 1) * inverse(q - 1) mod MOD`。 パイソンの`pow(q, k, MOD)`はモジュラー電力を効率的に計算し、フェルマーの定理は逆数を次のように与えます。`pow(q - 1, MOD - 2, MOD)`。 

### なぜ効果があるのか

 中心的な不変条件は次のとおりです。`t`正確に反復`q^t`の発生`×`存在する。 このような発生はそれぞれ独立して変換され、それぞれが正確に生成します。`q`新しい`×`シンボル。 合計シンボル数については、変換されたすべての出現が 1 つの乗算シンボルから`n - 1`乗算記号なので、純増加に貢献します。`n - 2`。 この貢献をまとめると`1, q, ..., q^(k-1)`出現により、乗算記号の最終的な数が正確に得られます。 最後の変換`×`に`·`文字のみが変更され、カウントは変更されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())

    q = n // 2

    if q == 1:
        geometric_sum = k % MOD
    else:
        geometric_sum = (pow(q, k, MOD) - 1) % MOD
        geometric_sum = geometric_sum * pow(q - 1, MOD - 2, MOD) % MOD

    answer = (1 + (n - 2) * geometric_sum) % MOD
    print(answer)

if __name__ == "__main__":
    solve()
```プログラムは最初に計算します`q`、から形成された完全なペアの数。`n`1 回の置換によってコピーが作成されます。 変数`geometric_sum`変換された数を表します`×`すべての反復にわたって累積された発生数。 

の`q == 1`ブランチが必要なため、`q - 1`はゼロになるため、逆モジュールは存在しません。 のために`n = 2`、進行は単純です`1 + 1 + ... + 1`。 

お互いのために`n`、等比数列の公式は有効です。 Python の 3 つの引数`pow`巨大な整数を構築せずにべき乗剰余演算を実行します`q^k`。 

表現`(n - 2) * geometric_sum`は通常の整数と同様に非常に大きくなる可能性がありますが、Python は任意のサイズの整数を処理し、最後のモジュロ演算により必要な結果が得られます。 固定幅の整数を使用する言語では、十分な幅の型または縮小剰余を使用して乗算を実行する必要があります。`MOD`初め。 

数式でも処理されます`k = 0`。 その場合`pow(q, 0, MOD)`は`1`、幾何和がゼロになるので、答えは次のようになります。`1`、変更されていない初期式と正確に一致します。

import sys
import io

MOD = 998244353

def solve():
    n, k = map(int, input().split())

    q = n // 2

    if q == 1:
        geometric_sum = k % MOD
    else:
        geometric_sum = (pow(q, k, MOD) - 1) % MOD
        geometric_sum = geometric_sum * pow(q - 1, MOD - 2, MOD) % MOD

    answer = (1 + (n - 2) * geometric_sum) % MOD
    print(answer)

def run(inp: str) -> str:
    global input
    old_stdin = sys.stdin
    old_input = input

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    try:
        from contextlib import redirect_stdout
        output = io.StringIO()
        with redirect_stdout(output):
            solve()
        return output.getvalue().strip()
    finally:
        sys.stdin = old_stdin
        input = old_input

# Provided samples
assert run("5 0\n") == "1", "sample 1"
assert run("5 1\n") == "4", "sample 2"
assert run("5 2\n") == "10", "sample 3"

# Minimum n, no iterations
assert run("1 0\n") == "1", "initial 1 × 1"

# Minimum n, one iteration removes the only multiplication
assert run("1 1\n") == "0", "n = 1"

# n = 2 is the geometric-ratio boundary case
assert run("2 1000000\n") == "1", "q = 1"

# Even n, checking the pairing behavior
assert run("4 1\n") == "3", "n = 4, k = 1"

# Maximum-size input, verifies that no expression is constructed
def reference(n, k):
    q = n // 2
    if q == 1:
        s = k % MOD
    else:
        s = (pow(q, k, MOD) - 1) % MOD
        s = s * pow(q - 1, MOD - 2, MOD) % MOD
    return (1 + (n - 2) * s) % MOD

assert run("1000000000 1000000\n") == str(
    reference(1000000000, 1000000)
), "maximum constraints"

 ## 特殊なケース

 のために`n = 1, k = 1`、 我々は持っています`q = 0`。 幾何和は`1`、最初の反復のみが存在するためです。 答えは`1 + (1 - 2) * 1 = 0`。 これは次の事実と一致します`1 × 1`シングルになる`1`、乗算記号は残りません。 

のために`n = 2`、 我々は持っています`q = 1`。 それぞれの発生`2 × 2`別の括弧に置き換えられます`2 × 2`, したがって、乗算記号の合計数は変わりません。 式では、`S = k`、しかし係数`n - 2`ゼロです、与えます`1`あらゆる人にとって`k`、 含む`k = 10^6`。 

のために`k = 0`の場合、幾何和には項が含まれず、ゼロになります。 結果的に答えは`1`あらゆる可能性のために`n`。 これは正しい結果です。`n × n`乗算記号が 1 つだけあり、反復によって変更されていません。 

奇数の場合`n`、の最終コピー`n`ペアの外に残されます。 これでは新規の数は変わりません`×`残るシンボル`floor(n / 2)`。 たとえば、`n = 5`、1 つの出現が 2 になります。`×`シンボルとペアになっていないシンボル`5`。 普通の`·`結果のグループ間のシンボルは、1 つの乗算シンボルを 5 つのオペランドの式に置き換えると、合計 4 つの乗算シンボルが作成されるという事実によってすでに説明されています。 

非常に大きい場合`n`そして`k`、実際の式は天文学的に大きくなりますが、漸化式は次だけに依存します。`q`、等比数列、および純増加`n - 2`。 この実装では、式やそのサイズに比例する量は決して保存されないため、同じ一定量のメモリが最小入力と最大入力の両方を処理します。
