 ## 問題の理解

 У каждого эксперимента есть одно число (t_i)。 Если эксперимент (i) проводится сразу перед экспериментом (j), лаборатория должна перейти от одного оборудования к другому за

 [
 \max(t_i,t_j)
 】

 分かった。 Подготовка оборудования для первого эксперимента и уборка после последнего в суммарное время не входят.

 Значит, если эксперименты идут в порядке (p_1,p_2,\ldots,p_n), нужно минимизировать

 [
 \sum_{k=1}^{n-1}\max(t_{p_k},t_{p_{k+1}})。 
】

 Нужно вывести не само минимальное время, а перестановку номеров экспериментов, которая его достигает.

 При (n\le 3\cdot10^5) перебор перестановок невозможен. Даже алгоритмы (O(n^2)) уже слизком медленные для ограничения в одну секунду, поскольку они потребуют порядка (9\cdot10^{10}) そうです。 Нам нужен алгоритм порядка (O(n\log n)) или лучзе.

 Значения (t_i) могут достигать (10^9), поэтому резение не должно зависеть от величины самих чисел. В Python обычные целые числа переполнения не вызывают, хотя само значение суммарного времени могло бы быть порядка (3\cdot10^{14})、これを実行します。 

Первый крайний случай возникает при (n=1)。 Например, для входа```
1
1000000000
```ответом должно быть```
1
```Здесь вообще нет пары соседних экспериментов, поэтому нельзя пытаться обращаться к элементам после первого.

 Другой важный случай связан с одинаковыми значениями. 年```
4
7 7 7 7
```(7) を参照してください。 Канонический ответ назего алгоритма будет```
1 2 3 4
```Нельзя требовать единственную конкретную перестановку, когда несколько вариантов имеют одинаковую стоимость.

 Наконец、нельзя сортировать только сами значения и забывать исходные номера. Например、```
3
5 1 5
```порядок значений (1,5,5) действительно оптимален, но выводить нужно номера экспериментов. Корректный канонический ответ здесь```
2 1 3
```Если вывести`1 5 5`、это вообще не перестановка номеров экспериментов。 

## アプローチ

 Самый прямой способ состоит в переборе всех (n!) перестановок. Для каждой перестановки можно пройти по ее (n-1) соседним парам и вычислить сумму максимумов. Такой перебор корректен、потому что среди всех рассмотренных перестановок обязательно находится оптимальная。 Но его трудоемкость равна (O(n!,n)), то есть уже при (n=10) требуется порядка (10!\cdot9=32,659,200) проверок соседних ぱっと。 При (n=3\cdot10^5) такой подход не имеет практического смысла.

 Можно попробовать строить порядок жадно, но сначала нужно понять, за что именно мы платим. Рассмотрим любую границу между двумя соседними экспериментами. Ее стоимость равна больгему из двух (t), поэтому каждую границу можно мысленно "приписать" тому эксперименту, あなたの которого это бользее значение。 

Возьмем все эксперименты и расположим их по возрастанию:

 [
 t_{p_1}\le t_{p_2}\le\ldots\let_{p_n}。 
】

 В таком порядке стоимость границы между (p_k) и (p_{k+1}) равна просто (t_{p_{k+1}})。 Поэтому общая стоимость равна

 [
 t_{p_2}+t_{p_3}+\ldots+t_{p_n}。 
】

 Теперь появляется нижняя граница для любого возможного порядка. Рассмотрим эксперимент с самым маленьким (t). Он может быть единственным экспериментом, который не является бользим концом ни одной границы. Каждый другой эксперимент должен хотя бы один раз быть бользим концом некоторой соседней пары. Иначе обе его соседние границы, если они существуют, были бы определены значениями других экспериментов, а сам этот эксперимент оказался бы полностью "неоплаченным"。 

Значит, стоимость любой перестановки не меньзе суммы всех (t_i), кроме одного минимального значения. То есть

 [
 \text{コスト}\ge \sum t_i-\min t_i。 
】

 Именно такую стоимость дает сортировка по возрастанию. Следовательно、она оптимальна。 

Получается особенно простой результат: нужно только отсортировать эксперименты по (t_i) и вывести их исходные ね。 Если значения равны, порядок между ними не имеет значения.

 | アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n!,n)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. Сохраняем для каждого эксперимента пару`(t_i, i)`、、`t_i`является временем оборудования, а`i`является его исходным номером. Номер нужен、потому что в ответе требуется вывести именно перестановку экспериментов.
 2. Сортируем эти пары по`t_i`Снеубывающем порядке. Если несколько значений одинаковы, их взаимный порядок не влияет на стоимость, поэтому любой порядок среди них допустим。 
3. После сортировки берем номера экспериментов в получивлемся порядке. Это и есть требуемая перестановка.
 4. Если (n=1)、сортировка содержит один элемент、поэтому алгоритм автоматически выводит единственный номер и не требует отдельной обработки。 

### なぜ効果があるのか

 Пусть эксперименты после сортировки имеют значения

 [
 a_1\le a_2\le\ldots\le a_n。 
】

 В отсортированном порядке стоимость всех границ равна

 [
 a_2+a_3+\ldots+a_n、
 】

 Лоскольку на каждой границе справа стоит больгее или равное значение.

 Теперь рассмотрим произвольную перестановку。 Для каждой границы ((u,v)) ее стоимость (\max(t_u,t_v)) можно приписать верзине с бользим значением. В линейной цепочке каждый эксперимент, кроме максимум одного, обязан быть бользим концом хотя бы одной ゴー。 Следовательно, в сумму обязательно попадут все значения, кроме одного. Чтобы сумма была минимальной、неучтенным нужно оставить самое маленькое значение. Получаем нижнюю границу

 [
 a_2+a_3+\ldots+a_n。 
】

 Отсортированный порядок достигает этой границы, значит он оптимален.

def solution(inp: str) -> str:
    data = list(map(int, inp.split()))
    n = data[0]
    t = data[1:1 + n]

    order = sorted(range(n), key=lambda i: t[i])
    return " ".join(str(i + 1) for i in order)

def cost(t, order):
    if len(order) <= 1:
        return 0

    return sum(
        max(t[order[i]], t[order[i + 1]])
