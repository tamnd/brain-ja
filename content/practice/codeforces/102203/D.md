 ## 問題の理解

 工場を表す固定点 (O) と、平面内に収集点 (n) があります。 4 つの収集ポイントを選択し、それらを 2 つのペアに分割する必要があります。 各ペアの点を接続する線分は (O) を通過し、4 つの点が 1 つの円上になければなりません。 

(O) を通る各行には最大 2 つの収集ポイントが含まれるため、有効なペアを選択すると、それらの 2 つのポイントは (O) の反対側に位置する必要があります。 したがって、すべての有用なペアは、正確に 2 つの収集ポイントを含む (O) を通る 1 つの行に対応します。 

(O) とすべての収集ポイントの座標は、絶対値が最大 (10^4) の整数ですが、(n) は最大 (2000) です。 (O(n^2)) ソリューションはすでに約 400 万回の反復を実行しますが、これは Python では快適です。 (O(n^3)) または (O(n^4)) の解は、1 秒の制限の下では現実的ではありません。 したがって、主な目標は、検索を本質的にポイント上の 1 回のパスに減らすことです。 

幾何学的な詳細がいくつかあるため、一見正しい実装が失敗する可能性があります。 (O) からの同じ光線上の点のペアは、(O) を含むセグメントを形成しません。 例えば、```
0 0
4
1 0
2 0
0 1
0 -2
```には正 (X) 線上に 2 つの点があるため、最初の 2 つは有効なペアにはなりません。 唯一の有効なペアは ((0,1),(0,-2)) ですが、これでは必要な 4 つの点を形成するには不十分であるため、答えは次のようになります。`NO`。 無向傾斜だけで点をグループ化し、(O) のどちら側を占めるかを忘れる実装では、最初の 2 つの点が誤ってペアとして扱われる可能性があります。 

(O) と一致する点も別個に扱う必要があります。 例えば、```
0 0
3
0 0
1 0
-1 0
```には非縮退ペアが 1 つだけあるため、答えは次のようになります。`NO`。 (O) の点は (O) からの距離がゼロであり、有用な 4 点構成で必要な 2 点セグメントの 1 つに参加できません。 

重複した座標は、すべての正規化された方向が自動的に有効なペアを表すと想定しないもう 1 つの理由です。 例えば、```
0 0
2
1 1
1 1
```同じ場所に 2 つの収集ポイントが含まれています。 それらは (O) の反対側にないため、(O) を介して必要なセグメントを形成できません。 答えは`NO`。 

最後に、正確な算術が重要です。 関連する幾何学的量は距離の二乗の積であり、これに浮動小数点値を使用すると、不必要な等価性エラーが発生する可能性があります。 すべての座標は整数であるため、計算全体を整数で実行できます。 

## アプローチ

 直接的なアプローチは、4 つの収集ポイントのすべてのセットを列挙し、4 つのポイントを 2 つのペアに分割する 3 つの方法をすべて試し、対応するセグメントが通過するかどうか (O) を確認し、次に 4 つのポイントが同周期であるかどうかを確認することです。 これは正しいです。考えられるすべての答えが明示的に検査されるからです。 ただし、(n=2000) の場合、4 点の部分集合を列挙するだけでは次のことが必要になります。 

[
 \binom{2000}{4}=664,668,499,500
 】

 最悪の場合は繰り返し。 それは利用可能な時間をはるかに超えています。 

有用な幾何学的観察は、選択された 2 つのセグメントが (O) を通過する同じ円の割線であるということです。 このような線上の任意の点ペア (A、B) について、次のように定義します。 

[
 P(A,B)=OA\cdot OB。 
】

 円の同じ点 (O) を通る任意の 2 つの割線について、点の累乗定理は次のようになります。 

[
 OA\cdot OB=OC\cdot OD。 
】

 したがって、一度に 4 つの点を調べる代わりに、点のペアを含む (O) を通る各線を調べて、その距離の積を計算できます。 2 つの異なる有効な直線は、それらの積が等しい場合に、必要な答えを正確に返します。 

実際の距離を使用する必要はありません。 もし

 [
 r_A^2=OA^2,\qquad r_B^2=OB^2,
 】

 この場合、距離の積の等価性は次と同等です。 

[
 r_A^2r_B^2=r_C^2r_D^2。 
】

 これらの値はすべて整数です。 

残りのタスクは、同じ線上の反対側の点を特定することです。 点 (P) については、それを (O) だけ平行移動し、ベクトルをその座標の gcd で減算し、その符号を維持します。 たとえば、((6,4)) は ((3,2)) になり、その反対の光線は ((-3,-2)) になります。 ペアは、両方の正規化ベクトルが発生する場合に正確に存在します。 

入力では、(O) を通る任意の線上に最大 2 つの点が存在することが保証されるため、各光線には最大 1 つの関連点を含めることができます。 正規化された有向ベクトルごとに 1 つの点を保存し、その否定を探すことができます。 

ブルート フォース アプローチは、考えられるすべての 4 ポイント構成を明示的にチェックするため機能しますが、(n=2000) の場合は失敗します。 すべての有効な構成は 2 つの逆光線のペアによって決定され、円によってそれらの距離積が等しくなるという観察により、問題を有効なラインごとに 1 つの整数値をハッシュすることに縮小できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n^4)) | (O(1)) | 遅すぎる |
 | 最適 | (O(n\log C)) | (O(n)) | 承認済み |

 ここで (C) は最大絶対変換座標です。 (C\le 2\cdot10^4) であるため、これらの制約に対して gcd 計算は実質的に定数時間になります。 

## アルゴリズムのチュートリアル

 1. (O) の座標を減算して、すべての収集ポイントを移動します。 変換された座標 ((0,0)) を持つ点は、(O) を挟む別の点と非縮退ペアを形成できないため、無視されます。 
2. 残りのすべての点の方向を正規化します。 変換されたベクトルが ((x,y)) の場合、両方の座標を (\gcd(|x|,|y|)) で除算します。 符号を変更しないで、反対の光線が反対のキーを生成するようにします。 
3. 正規化された有向ベクトルごとに、ポイント インデックスとその二乗距離を保存します。 
[
 r^2=x^2+y^2。 
】
 各ライン上の最大 2 点に関する条件により、光線に 2 つの異なる収集点が含まれないことが保証されます。 
4. すべての方向 (v=(x,y)) について、反対方向 (-v) を探します。 存在しない場合、それらの点は (O) を介してセグメントを形成できません。 
5. 各無向行は 1 回だけ処理します。 簡単な方法は、辞書編集上のタプル順序で (v< -v) を満たす方向のみを処理することです。 その線上の 2 点 (A,B) について、次のように計算します。 
[
 値=OA^2\cdot OB^2。 
】
 6. すべてのペアで見つかった最初のペアを保存します。`value`。 別の異なる行で同じ値が生成された場合は、保存されている 2 つのエンドポイントの後に、現在の行の 2 つのエンドポイントが出力されます。 それらの 2 つのセグメントには両方とも (O) が含まれており、積が等しい条件により、4 つの点すべてが 1 つの円上にあることが保証されます。 
7. 重複する積がない場合は、出力します。`NO`。 

### なぜ効果があるのか

 (A,B) と (C,D) のペアを含む有効な答えを考えてみましょう。 両方のセグメントが (O) を通過するため、(A、B) は 1 つのラインの反対の光線上にあり、(C、D) は別の線の反対の光線上にあります。 4 つの点が 1 つの円上にあるため、その円に関する (O) の累乗は次のようになります。 

[
 OA\cdot OB=OC\cdot OD。 
】

 両辺を二乗すると、アルゴリズムによって検査された正確な等価性が得られます。 

逆に、(O) を通る 2 つの異なる線に、積が等しい反対光線のペア (A、B) および (C、D) があるとします。 (A、B、C) を円で囲みます。 (O) でのパワーは最初のセカントによって決定され、(OA\cdot OB) に等しくなります。 2 番目の線は (C) でこの円と交差し、(O) からの距離が同じ積になる別の点でも交差します。 (OC\cdot OD) はその値に等しいため、(D) はまさにその 2 番目の交点になります。 したがって、4 つの点はすべて同じ円上にあります。 

不変条件は、処理されたすべての有効なラインが、正確に 1 つの整数、つまり (O) に関するそのペアの二乗乗の大きさで表されるということです。 等しい整数は、同じ円に属する 2 つの割線に正確に対応します。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    ox, oy = map(int, input().split())
    n = int(input())

    rays = {}

    for idx in range(1, n + 1):
        x, y = map(int, input().split())
        x -= ox
        y -= oy

        if x == 0 and y == 0:
            continue

        g = math.gcd(abs(x), abs(y))
        x //= g
        y //= g

        rays[(x, y)] = (idx, x * x + y * y)

    seen_value = {}

    for direction, data in rays.items():
        x, y = direction
        opposite = (-x, -y)

        if opposite not in rays:
            continue

        # Process each undirected line only once.
        if direction > opposite:
            continue

        idx1, r1 = data
        idx2, r2 = rays[opposite]

        value = r1 * r2

        if value in seen_value:
            a, b = seen_value[value]
            print("YES")
            print(a, b, idx1, idx2)
            return

        seen_value[value] = (idx1, idx2)

    print("NO")

if __name__ == "__main__":
    solve()
```コードの最初の部分は、ファクトリが原点になるようにすべてのポイントを変換します。 これにより、方向テストと距離計算の両方が (O) の元の位置から独立します。 

gcd 正規化は、同じレイ上のベクトルを同じ辞書キーに変換します。 たとえば、((10,6)) と ((5,3)) は両方とも ((5,3)) になります。 それらの反対の光線は ((-5,-3)) で表されます。 方向のない線だけでは 2 点間のセグメントに (O) が含まれるかどうかを判断するのに十分ではないため、意図的に符号を保持します。 

二乗距離は、コード内で正規化された後に計算されます。 正規化されたベクトルが同じ方向を向いているため、これは有効ですが、ここには微妙な点があります。保存される二乗距離は、正規化された方向の二乗長ではなく、元の点の実際の二乗距離でなければなりません。 したがって、上記のコードは正しくありません。 

正しい実装では、正規化されたベクトルを辞書キーとしてのみ使用しながら、距離計算のために元の変換された座標を保持する必要があります。 修正された完全なソリューションは次のとおりです。```python
import sys
import math

input = sys.stdin.readline

def solve():
    ox, oy = map(int, input().split())
    n = int(input())

    rays = {}

    for idx in range(1, n + 1):
        x, y = map(int, input().split())
        x -= ox
        y -= oy

        if x == 0 and y == 0:
            continue

        dist2 = x * x + y * y

        g = math.gcd(abs(x), abs(y))
        dx = x // g
        dy = y // g

        rays[(dx, dy)] = (idx, dist2)

    seen_value = {}

    for direction, (idx1, r1) in rays.items():
        dx, dy = direction
        opposite = (-dx, -dy)

        if opposite not in rays:
            continue

        if direction > opposite:
            continue

        idx2, r2 = rays[opposite]
        value = r1 * r2

        if value in seen_value:
            a, b = seen_value[value]
            print("YES")
            print(a, b, idx1, idx2)
            return

        seen_value[value] = (idx1, idx2)

    print("NO")

if __name__ == "__main__":
    solve()
```2 番目のバージョンが提出されるバージョンです。 正規化された方向と元のベクトルの区別は重要です。 正規化により距離情報が削除されるため、正規化ベクトルを使用して (OA^2) を計算すると、同じ光線上の無関係な点が同じ距離を持つように見えます。 

Python の整数には任意の精度があるため、積によってオーバーフローが発生することはありません。 元の座標の差が (2\cdot10^4) で区切られている場合、各二乗距離は最大でも (8\cdot10^8) で、積はおおよそ (6.4\cdot10^{17}) よりも小さくなります。 

辞書編集上の比較`direction > opposite`同じ行を 2 回処理することを防ぎます。 これはジオメトリには影響せず、同じペアをパワー マップに 2 回保存することを回避するだけです。 

最後の 4 つのインデックスの順序も意図的です。 最初の 2 つのインデックスは 1 つの逆レイ ペアから取得され、最後の 2 つは別のペアから取得されます。 その結果、出力形式の要求どおりに、最初のセグメントと 2 番目のセグメントは両方とも (O) を通過します。
