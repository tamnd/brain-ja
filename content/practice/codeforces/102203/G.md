 ## 問題の理解

 地区は 8 つしかないため、すべてのエージェントは 8 × 8 のバイナリ遷移行列で表すことができます。 エージェント (k) の場合、エージェントがリックとバローナを地区 (u) から地区 (v) に連れて行くことができるとき、エントリ (A_k[u][v]) は 1 になります。 

クエリ ([l,r,s,t]) の場合、エージェントは固定順序 (l,l+1,\ldots,r) で使用する必要があります。 それらの行列を (A_l,A_{l+1},\ldots,A_r) と書くと、可能なルートの数は正確に次の ((s,t)) エントリになります。 

[
 A_lA_{l+1}\cdots A_r
 】

 ここで、乗算は、998244353 を法とする通常の行列乗算です。乗算は、すべての可能な中間地区にわたって合計されるため、単一の行列積は、すべての個別のルートを 1 回だけカウントします。 公式の制約とサンプルは、Codeforces の問題ページにあります。 

入力には、最大 (10^5) 個のエージェントと (2\cdot10^5) 個のクエリが含まれます。 1 つのクエリを直接スキャンすると (10^5) 個の行列に触れる可能性がありますが、(2\cdot10^5) 回繰り返すとすでに多すぎます。 8 要素ベクトルを維持し、64 のスカラー演算で 1 つのバイナリ行列を適用する自然な動的プログラミング バージョンでも、

 [
 2\cdot10^5\cdot10^5\cdot64=1.28\cdot10^{12}
 】

 スカラー演算。 従来のセグメント ツリーでは、クエリあたりの行列積の数は (O(\log n)) に減りますが、各積は完全な 8 × 8 行列の乗算であるため、Python は依然として膨大な量の作業を実行します。 

クエリの異常な状態が鍵となります。 クエリ間隔が別のクエリ間隔内に適切に含まれていません。 2 つの区間が左端点で並べ替えられ、最初の区間の右端点が 2 番目の区間よりも大きい場合、2 番目の区間は最初の区間に含まれます。 したがって、(l) で並べ替えた後、右端点も減少しません。 等しい左端点は、右端点を増やすことによって単純に並べ替えることができます。 

これは、クエリされた範囲をスライディング ウィンドウとして表示できることを意味します。 左端点は右へのみ移動し、右端点は右へのみ移動します。 右への追加と左からの削除をサポートしながら、シーケンスの積を維持するデータ構造が必要です。 標準の 2 スタックのスライディング ウィンドウ集計構造は、非可換行列乗算を含むあらゆる結合演算に対して正確にそれを実行します。

## アプローチ

 最も直接的な正しい方法は、すべてのクエリを個別に処理することです。 開始地区に 1 を含み、それ以外の場所に 0 を含む 8 要素ベクトルから始めます。 (l) から (r) までのすべてのエージェントについて、このベクトルにそのエージェントのバイナリ遷移行列を乗算します。 最後のエージェントの後の (t) に対応するコンポーネントが答えです。 これは正しいです。最初の (k) エージェントを処理した後、ベクトルにはそれらのエージェントの後にすべての地区に到達する方法の数が格納されているからです。 

問題は繰り返しスキャンすることです。 1 つのクエリには (10^5) 個のエージェントを含めることができ、また (2\cdot10^5) 個のクエリを含めることもできます。 最悪のケースは、(1.28\cdot10^{12}) 程度のスカラー ベクトル行列演算であり、制限をはるかに超えています。 

標準の範囲積データ構造では、セグメントの積をセグメント ツリーに格納します。 クエリでは、(O(\log n)) 個の事前計算された行列を組み合わせることができます。 行列の乗算は結合的であるため、代数は完全に有効ですが、特別なクエリ条件は利用されません。 (2\cdot10^5) クエリと約 17 ツリー レベルでは、何百万もの 8 × 8 行列の乗算が行われます。 

決定的な観察は、並べ替え後にクエリが単調なシーケンスを形成することです。 左側の境界が後方に移動することはなく、右側の境界も後方に移動しません。 その結果、エージェント行列の FIFO シーケンスとして現在のクエリ間隔を正確に維持できます。 

問題は、行列の乗算が一般に可逆ではないことです。 現在の積が (A_lA_{l+1}\cdots A_r) である場合、(A_l) は単数である可能性があるため、逆数を乗算することによって (A_l) を削除することはできません。 2 スタックの集約キューはこれを完全に回避します。 各スタックには部分積が格納されるため、最も古い要素を削除するには、反対側のスタックが空になったときに再構築するだけで済みます。 すべての行列はスタック間で最大 1 回移動され、ウィンドウの更新ごとに償却定数の多くのモノイド演算が行われます。 これは、一般に SWAG と呼ばれるスライディング ウィンドウ集約のアイデアと同じです。 

この問題に特有の便利な最適化がもう 1 つあります。 元のエージェント マトリックスはすべてバイナリです。 スタック集合体にエージェントを追加する場合、1 つのオペランドは常にバイナリであるため、通常の 64 個のモジュラー乗算の代わりに、選択した行または列の合計として乗算を実行できます。 以下のコードはこの最適化を使用しています。 クエリに答えるとき、2 つのスタック集合体の積全体は必要ありません。 必要なエントリは 1 つだけなので、2 つの集計を結合するのにかかるコストは、乗算と加算の項が 8 つだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(mn\cdot8^2)) | (O(8^2)) | 遅すぎる |
 | セグメントツリー | (O(m\log n\cdot8^3)) | (O(n\cdot8^2)) | 正しいですが、不必要に高価です |
 | 最適なスワッグ | (O(n\cdot8^3+m\cdot8)) | (O(n\cdot8^2+m)) | 承認済み |

 8 は固定定数であるため、最適な複雑さは実質的に (O(n+m)) 個の行列演算になります。 

## アルゴリズムのチュートリアル

 1. すべての 64 ビット入力数値を 8 × 8 バイナリ行列に変換します。 8 つの行マスクと 8 つの列マスクを、フラット化された 64 エントリとともに保存します。 マスクを使用すると、不必要なスカラー乗算を実行せずに、任意の集合体にバイナリ エージェント行列を乗算できます。 
2. すべてのクエリを読み取り、次の基準で並べ替えます。`(l, r)`。 元の順序はすべてのクエリとともに保存されるため、後で回答を復元できます。 クエリ ファミリには適切なネストが含まれていないため、(l) による並べ替えは (r) を非減少にするのに十分です。 
3. 処理中のクエリに現在属しているエージェントを正確に含むスライディング ウィンドウを維持します。 その 2 つのエンドポイントは次のとおりです`left`そして`right`。 最初はウィンドウは空です。 
4. ウィンドウを右に拡張するには、新しいエージェントをすべて追加します。`right`現在のクエリの (r) と等しくなります。 バックスタックには、新しく追加された行列が格納されます。 その集計は、そのスタック内のすべての行列の時系列順の積です。 
5. 左側のエンドポイントを前方に移動するには、ウィンドウの前面からマトリックスを削除し、`left`現在のクエリの (l) と等しくなります。 フロントスタックが空でない場合は、最も古い行列を単純にポップできます。 空の場合は、すべての行列をバック スタックからフロント スタックに移動します。 順序を逆にすると、最も古い行列がフロント スタックの最上位要素になります。 
6. フロントスタックを再構築する際、その集計を最も古い行列から最新の行列に向かって再計算します。 新しい行列が (A) で、以前の集計が (P) である場合、新しい集計は (P A) ではなく (A P) になります。 行列の乗算は可換ではないため、順序は重要です。 
7. ウィンドウが ([l,r]) を表すと、その積は最大 2 つの集合体に分割されます。 両方のスタックが存在する場合、完全な製品は次のようになります。`front_product * back_product`。 1 つのスタックが空の場合、その集合体はすでに製品全体になります。 
8. 要求されたエントリ ((s,t)) のみが必要です。 2 つの集計が (F) と (B) の場合、次のように計算します。 

[
 (FB)[s][t]=\sum_{k=0}^{7}F[s][k]B[k][t].
 】

 これには 8 回のスカラー乗算のみが必要です。 

1. クエリの元のインデックスの下に回答を保存します。 並べ替えられたクエリがすべて処理されたら、回答を元の順序で印刷します。 

### なぜ効果があるのか

 不変条件は、クエリ ([l,r]) に答える直前に、2 つのスタックが一緒になって行列 (A_l,A_{l+1},\ldots,A_r) をその順序で正確に表すことです。 バック スタックは行列を時系列順に集合体に格納しますが、フロント スタックは行列を集合体に古いものから最新のものまで格納します。 バックスタックがフロントスタックに転送されると、物理的な反転によってスタックの順序が時系列に変更され、新しいフロント集合体がそれぞれ (A P) として形成され、製品の順序が維持されます。 したがって、2 つの集合によって表される積は常に正確に (A_lA_{l+1}\cdots A_r) になります。 したがって、要求された行列エントリは、(s) から (t) までのルートを正確にカウントします。 

各エージェントが 1 回追加され、フロント スタックが再構築されるたびに、移動されたすべてのエージェントがポップされる前に 1 回転送されるため、償却限界が続きます。 単調なスライディング ウィンドウの下では、エージェントを繰り返し前後に転送することはできません。 Thus the total number of stack aggregate updates is linear in (n).

 ## Python ソリューション```python
import sys
from array import array

input = sys.stdin.readline

MOD = 998244353

# Positions of set bits for every 8-bit mask.
BIT_POS = [()]
for mask in range(1, 256):
    cur = []
    x = mask
    while x:
        b = x & -x
        cur.append(b.bit_length() - 1)
        x -= b
    BIT_POS.append(tuple(cur))

def parse_agent(x):
    rows = [0] * 8
    cols = [0] * 8
    flat = [0] * 64

    # Bit 63 is matrix position (0, 0), bit 0 is (7, 7).
    for p in range(64):
        bit = (x >> (63 - p)) & 1
        if bit:
            i = p >> 3
            j = p & 7
            rows[i] |= 1 << j
            cols[j] |= 1 << i
            flat[p] = 1

    return (tuple(rows), tuple(cols), tuple(flat))

def mul_right_binary(a, cols):
    """
    Compute A * B, where A is a general 8x8 matrix and B is binary.
    """
    out = array('I', [0]) * 64

    for i in range(8):
        base = i << 3
        for j in range(8):
            pos = BIT_POS[cols[j]]

            if not pos:
                continue

            if len(pos) == 1:
                value = a[base + pos[0]]
            else:
                value = 0
                for k in pos:
                    value += a[base + k]
                value %= MOD

            out[base + j] = value

    return out

def mul_left_binary(rows, b):
    """
    Compute A * B, where A is binary and B is a general 8x8 matrix.
    """
    out = array('I', [0]) * 64

    for i in range(8):
        pos = BIT_POS[rows[i]]
        base = i << 3

        if not pos:
            continue

        if len(pos) == 1:
            src = pos[0] << 3
            for j in range(8):
                out[base + j] = b[src + j]
        else:
            for j in range(8):
                value = 0
                for k in pos:
                    value += b[(k << 3) + j]
                out[base + j] = value % MOD

    return out

def entry_product(a, b, s, t):
    """
    Return (A * B)[s][t], without constructing A * B.
    """
    base_a = s << 3
    value = 0

    for k in range(8):
        value += a[base_a + k] * b[(k << 3) + t]

    return value % MOD

def solve():
    n, m = map(int, input().split())

    agents = []
    for _ in range(n):
        agents.append(parse_agent(int(input())))

    queries = []
    for idx in range(m):
        l, r, s, t = map(int, input().split())
        queries.append((l - 1, r - 1, s - 1, t - 1, idx))

    # For non-nested intervals, sorting by l makes r nondecreasing.
    queries.sort(key=lambda q: (q[0], q[1]))

    # Each entry is (raw_agent, aggregate_of_stack).
    #
    # Back stack:
    #   top is the newest element.
    #   aggregate is product from oldest to newest.
    #
    # Front stack:
    #   top is the oldest element.
    #   aggregate is product from oldest to newest.
    back = []
    front = []

    left = 0
    right = -1

    answers = [0] * m

    for ql, qr, s, t, idx in queries:
        while right < qr:
            right += 1
            raw = agents[right]

            if back:
                old_agg = back[-1][1]
                agg = mul_right_binary(old_agg, raw[1])
            else:
                agg = raw[2]

            back.append((raw, agg))

        while left < ql:
            if not front:
                # Transfer back -> front.
                while back:
                    raw, _ = back.pop()

                    if front:
                        old_agg = front[-1][1]
                        agg = mul_left_binary(raw[0], old_agg)
                    else:
                        agg = raw[2]

                    front.append((raw, agg))

            front.pop()
            left += 1

        if front:
            f = front[-1][1]

            if back:
                b = back[-1][1]
                answers[idx] = entry_product(f, b, s, t)
            else:
                answers[idx] = f[(s << 3) + t]
        else:
            b = back[-1][1]
            answers[idx] = b[(s << 3) + t]

    sys.stdout.write('\n'.join(map(str, answers)))

if __name__ == "__main__":
    solve()
```の`parse_agent`関数はステートメントのビット順序に正確に従います。 最上位ビットは行列の位置 ((0,0)) を表すため、位置`p`ビットを使用します`63 - p`。 最下位ビットを最初の行列要素として扱うとエンコード全体が逆になるため、これは誤った答えの一般的な原因となります。 

の`rows`そして`cols`マスクには、最適化された乗算ルーチンに必要なバイナリ構造が含まれています。 のために`A * B`バイナリ付き`B`、各出力エントリは、`A`、ここで、選択されたインデックスは列マスクによって決定されます。`B`。 対称的なアイデアは次の目的で使用されます。`A * B`いつ`A`バイナリです。 

2 つのスタックには、生のエージェントと、そのスタック プレフィックスに属するアグリゲートの両方が含まれています。 逆集計は次のように更新されます。`old_aggregate * new_agent`。 フロントアグリゲートは次のように再構築されます。`new_agent * old_aggregate`転送されたエージェントは、フロント スタックに既に存在するすべてのものよりも古いためです。 

このコードは、クエリに応答するときに、フロント集計とバック集計の積を構築することを意図的に避けています。 必要な行列エントリは 1 つだけなので、`entry_product`対応する 8 項のドット積を直接計算します。 

の`array('I')`type は、Python 整数オブジェクトではなく、32 ビット符号なし整数として集計エントリを格納します。 すべての値は 998244353 を法として削減されるため、4 バイトで十分です。 これにより、ウィンドウに (10^5) に近い行列が含まれる場合のメモリ消費が大幅に削減されます。 

Python の整数には任意の精度があるため、通常の算術演算ではオーバーフローの問題は発生しません。 最大 8 つの項を合計した後の明示的なモジュロにより、集計エントリがモジュラス未満に保たれますが、最終的なクエリのドット積も必要な値を法として削減されます。

 |`[1,2]`、`1 -> 3`|`[1,2]`| (A_1) | (A_2) | 1 |
 |`[2,2]`、`2 -> 3`|`[2]`| (A_2) | 空 | 1 |

 最初のクエリの後、ウィンドウにはエージェント 1 のみが含まれます。2 番目のクエリは右側の境界を拡張するため、エージェント 2 がバックスタックにプッシュされます。 (A_1A_2) の要求されたエントリは 1 つです。 3 番目のクエリは左側の境界を 1 から 2 に移動するため、エージェント 1 が前面から削除され、残りの集計は正確に (A_2) になります。 

2 番目の例は、繰り返しの訪問と重複したクエリ範囲を示しています。```
2 3
9223372036854775808
9223372036854775808
1 2 1 1
1 2 1 1
2 2 1 1
```どちらのエージェントも遷移 (1\to1) のみを持っています。 

| クエリ | 左 | 右 | 現在のルート | 答え |
 | --- | --- | --- | --- | --- |
 | 最初 | 1 | 2 | (1\to1\to1) | 1 |
 | 2番目 | 1 | 2 | (1\to1\to1) | 1 |
 | 3番目 | 2 | 2 | (1\to1) | 1 |

 ソート処理では同じウィンドウに連続して応答できるため、重複したクエリは特別な問題を引き起こしません。 ある地区からそれ自体への行列遷移は完全に有効なエッジであるため、繰り返された地区も保存されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n\cdot8^3+m\cdot8)) | すべてのエージェントは 1 回プッシュされ、最大 1 回転送されますが、各クエリには 8 項の内積だけが必要です。 
| スペース | (O(n\cdot8^2+m)) | スタック集計には一定サイズの 8 × 8 行列が含まれており、すべてのクエリは並べ替えのために保存されます。 

係数 (8^3=512) は問題によって修正されるため、漸近的な動作はエージェントとクエリの数において線形になります。 両方のエンドポイントの単調性により、エージェントが繰り返し挿入および削除されることが防止されます。 256 MB のメモリ制限は、Python 実装では集約行列をコンパクトな 32 ビット配列に格納することで処理されます。

 長さ 1 の間隔の場合、スライディング ウィンドウには 1 つの行列が含まれます。 入力が```
