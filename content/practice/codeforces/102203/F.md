 ## 問題の理解

 文字列があります`s`長さの`n`。 すべての部分文字列はその位置と長さによって識別されるため、同じ文字が含まれる 2 つの文字列は個別に考慮されます。 考えられるすべての長さについて、その長さの部分文字列の出現のすべてのペアを考慮します。 2 つの文字列が異なる場合は、そのうちの 1 つが辞書編集的に小さいため、このペアは答えに 1 つ寄与します。 等しい文字列は何も寄与しません。 

タスクは、すべての長さにわたってそのようなペアをすべてカウントすることです。 たとえば、`abac`、次の 2 つの出現`a`は別個の部分文字列ですが、同等であり、互いにペアを形成しません。 それぞれの発生`a`の出現とペアを形成します`b`または`c`。 

長さは最大でも`2500`これは 2 次アルゴリズムには十分小さいですが、2 秒の制限では 3 次アルゴリズムには十分ではありません。 すでに約`n² / 2`開始位置のペア。 ポジションのペアごとに大幅な追加作業を実行するソリューションは、すぐに遅くなりすぎます。 ターゲットは近くにいるはずです`O(n²)`時間。 答えは次のように大きくなります。`n(n-1)(n+1) / 6`、

 それは約です`2.6 * 10^9`のために`n = 2500`したがって、32 ビットの符号付き整数では十分ではありません。 Python の整数はこれを自動的に処理します。 

直接実装では誤って処理される可能性のあるエッジケースがいくつかあります。 のために`s = "a"`、同じ長さの部分文字列は 2 つ存在しないため、答えは次のようになります。`0`。 2 つの位置が実際に存在することを確認する前にカウントを開始する実装では、偽のペアが生成される可能性があります。 

のために`s = "aaa"`、答えも`0`。 同じ長さの部分文字列のすべてのペアは、出現位置が異なっていても、同じ文字列で構成されます。 異なる文字列の代わりに異なる出現をカウントする不注意な解決策は、それらを誤ってカウントすることになります。 

のために`s = "aaaa"`、同じ問題があらゆる長さで表示されます。 特に、 位置から始まる 2 つのオカレンス`0`そして`1`2 番目の出現で使用できる全長に等しいプレフィックスを持ちます。 答えは残っている`0`。 

のために`s = "aab"`、答えは`2`。 の 2 つの発生`a`それぞれが平等で何も寄与しない一方で、`a`発生は、と 1 つのペアを形成します。`b`発生。 解決策では、平等と単に開始位置が異なることを区別する必要があります。 

## アプローチ

 最も直接的なアプローチは、すべての部分文字列の長さを列挙し、その長さのすべての部分文字列の出現を収集し、すべてのペアを辞書編集的に比較することです。 これは正しいです。なぜなら、必要なすべてのペアが正確に 1 つの長さに属し、その長さの出現するすべてのペアがチェックされるからです。 

問題は比較の回数です。 長さについて`L`、 がある`n-L+1`出現するため、ペアの数は`C(n-L+1, 2)`。 

すべての長さを合計すると、部分文字列比較の数は次のようになります。`C(n,2) + C(n-1,2) + ... + C(2,2)`等しい`n(n-1)(n+1) / 6`。 

で`n = 2500`、まさにこれです`2,604,166,250`比較。 たとえすべての辞書編集上の比較が一定時間だったとしても、これはすでに限界をはるかに超えています。 文字列を 1 文字ずつ比較すると、実際のコストがさらに悪化する可能性があります。 

有益な観察は、2 つの等しくない部分文字列のどちらが小さいかを実際に知る必要がないということです。 同じ長さの 2 つの異なる文字列の場合、正確に 1 つが小さくなります。 2 つの部分文字列が等しいかどうかを判断するだけで済みます。 

2 つの開始位置を考慮する`i < j`。 で始まるサフィックスの中で最も長い共通プレフィックス`i`そして`j`は`LCP(i,j)`。 2 番目のサフィックスには、`n-j`文字なので、共通プレフィックスの長さは最大でも`n-j`。 

部分文字列の長さごとに`L <= n-j`、で始まる 2 つの部分文字列`i`そして`j`が正確に等しいとき`L <= LCP(i,j)`。 したがって、すべての長さ`LCP(i,j) + 1, ..., n-j`1 つの有効なペアが生成されますが、短い長さでは等しい部分文字列が生成され、何も寄与しません。 

したがって、位置のペアの寄与は`i,j`単純に`n-j-LCP(i,j)`。 

これにより、部分文字列の長さにわたるループ全体が削除されます。 開始位置の各ペアの LCP のみが必要です。 

LCP 値自体には、単純な動的プログラミングの反復があります。`LCP(i,j) = 0`もし`s[i] != s[j]`、

そして`LCP(i,j) = 1 + LCP(i+1,j+1)`もし`s[i] == s[j]`。 

がある`O(n²)`そのような状態。 のみを使用しながらそれらを計算できます`O(n)`各状態は次の対角線のみに依存するため、メモリが必要になります。`LCP(i+1,j+1)`。

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取って、`n`その長さになります。 配列を作成する`dp`長さの`n+1`。 開始位置固定処理中`i`、`dp[j]`代表します`LCP(i,j)`その状態が計算された後。 
2. プロセスの開始位置`i`から`n-2`まで`0`。 それらを逆方向に処理するのは、`LCP(i,j)`に依存します`LCP(i+1,j+1)`、すでに処理された行に属します。 
3. 固定ごとに`i`、 プロセス`j`から`i+1`まで`n-1`。 昇順は必須です。 前に`dp[j+1]`上書きされても、まだ含まれています`LCP(i+1,j+1)`, したがって、現在の状態を計算するために使用できます。 
4. もし`s[i]`そして`s[j]`異なる、設定する`lcp = 0`。 それらの共通プレフィックスはすぐに終了します。 
5. もし`s[i] == s[j]`、 セット`lcp = 1 + dp[j+1]`。 最初の文字が一致し、それらの文字を削除した後、次で始まるサフィックスを比較します。`i+1`そして`j+1`。 
6. 2 番目の部分文字列の長さは次のとおりです。`1`を通して`n-j`、あります。`n-j`これら 2 つの開始位置を含む等長比較が可能です。 まさに最初の`lcp`それらの長さは等しい。 追加`n-j-lcp`答えに。 
7. 計算された値を保存します`lcp`で`dp[j]`、次に進みます`j`。 すべての開始位置のペアが処理された後、累積された答えを出力します。 

### なぜ効果があるのか

 任意の 2 つの開始位置を修正する`i < j`。 これらの位置から形成される共通の長さの部分文字列ペアはすべて、最大でも長さがあります。`n-j`で始まるオカレンスがあるため、`j`文字列の最後で終了します。 

定義によれば、`LCP(i,j)`、2 つの部分文字列は、以下のすべての長さで等しいです。`LCP(i,j)`、そしてそれらは、以下に至るまでのより長い長さごとに異なります。`n-j`。 それらが異なっていて同じ長さである場合は常に、辞書編集的には 1 つの方が小さいため、そのような長さはそれぞれ 1 つの有効なペアに寄与します。 

したがって、位置のペアは正確に寄与します`n-j-LCP(i,j)`。 DP は、必要なすべての LCP を繰り返しから正確に計算し、開始位置のすべてのペアが 1 回だけ処理されます。 これらの寄与を合計すると、必要な数のペアが正確に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(s):
    n = len(s)
    if n < 2:
        return 0

    # dp[j] is LCP(i, j) for the current i after it is computed.
    # Before dp[j] is overwritten, dp[j + 1] is still LCP(i + 1, j + 1).
    dp = [0] * (n + 1)
    ans = 0

    for i in range(n - 2, -1, -1):
        for j in range(i + 1, n):
            if s[i] == s[j]:
                lcp = dp[j + 1] + 1
            else:
                lcp = 0

            ans += n - j - lcp
            dp[j] = lcp

    return ans

def main():
    s = input().strip()
    print(solve(s))

if __name__ == "__main__":
    main()
```外側のループの処理`i`LCP 再帰に必要な行がすでに計算されているように、逆方向に計算されます。 内側のループは前方に進みます。`j`。 この順序付けは実装の微妙な部分です。`j`逆に処理された、`dp[j+1]`前の行ではなく現在の行に既に属しているため、繰り返しが破棄されます。 

配列には余分な位置が 1 つあります。`dp[n] = 0`。 これは、2 番目のインデックスが文字列の末尾を超えた 2 つのサフィックスの LCP として機能します。 次の場合に特殊なケースを削除します。`j = n-1`。 

表現`n-j`は、2 つの開始位置に使用できる最大共通長です。 LCP を減算すると、部分文字列が等しい長さが正確に削除されます。 LCP がわかった後は、文字比較は必要ありません。同じ長さの 2 つの等しくない文字列は、常に辞書順に並べられた 1 つのペアを生成するからです。 

答えは Python の整数を使用して累積されるため、最大の答えが より大きくてもオーバーフローの問題は発生しません。`2^31-1`。

## テストケース```python
import sys
import io

def solve(s):
    n = len(s)
    if n < 2:
        return 0

    dp = [0] * (n + 1)
    ans = 0

    for i in range(n - 2, -1, -1):
        for j in range(i + 1, n):
            if s[i] == s[j]:
                lcp = dp[j + 1] + 1
            else:
                lcp = 0

            ans += n - j - lcp
            dp[j] = lcp

    return ans

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = sys.stdin.readline().strip()
    return str(solve(s))

# Provided sample
assert run("abac\n") == "9", "sample 1"

# Minimum-size input
assert run("a\n") == "0", "single character"

# All occurrences are equal
assert run("aaa\n") == "0", "all equal"

# Repeated prefix and equality boundary
assert run("aaaa\n") == "0", "all substrings of the same length are equal"

# Every a paired with the final b
assert run("aab\n") == "2", "two a occurrences versus one b occurrence"

# Maximum-size input
assert run("a" * 2500 + "\n") == "0", "maximum length, all equal"

# Maximum-size input with a single different final character
assert run("a" * 2499 + "b\n") == "2499", "maximum length, final character differs"

 ## 特殊なケース
