 ## 解決策
 ## 問題の理解

 それぞれが正の整数の重みを持つボクサーのセットが与えられています。 各ボクサーは体重を最大 1 まで増減できますが、体重は厳密にプラスのままでなければなりません。 私たちの目標は、調整後に同じ体重を共有するボクサーが 2 人もいない、可能な限り最大のチームを編成することです。 入力はボクサーの数を提供します。`n`、およびその重みのリスト。 出力は、固有の重みを持つ最大チームのサイズを表す単一の整数です。 

制約が示すのは、`n`最大 150,000、重みは 150,000 に達する可能性があります。 考えられるすべての調整の組み合わせを試す単純なアプローチでは、指数関数的な時間がかかり、現実的ではありません。 O(n log n) 以上のほぼ線形または線形演算時間で実行されるソリューションが必要です。O(n^2) では、最悪の場合 220 億回を超える操作が発生し、2 秒の制限をはるかに超えるためです。 

いくつかの特殊なケースを検討する価値があります。 すべてのボクサーの体重が同じ場合、チームを最大化するために体重を慎重に上下に調整する必要があります。 たとえば、重みを使用すると、`[1,1,1]`、最適な結果は次のとおりです。`[1,2,3]`もう 1 つのケースは、重みに 1 が含まれる場合です。これは、1 をさらに減らすことができないため、調整ではそのような重みを増やすだけでなければなりません。 最大ウェイトが上限付近で複数回発生する場合は、ウェイトを増やすときに 150,001 を超えないようにする必要があります。 

## アプローチ

 ブルート フォース ソリューションの説明は簡単です。各ボクサーに対して、3 つの可能な重み (現在、現在 -1、現在 +1) をすべて試し、その重みがチーム内ですでに割り当てられているかどうかを確認します。 そうでない場合は、チームに追加してください。 すべてのボクサーが処理されるまで続行します。 これは、実行可能なすべての重みの割り当てを明示的にチェックするため、正しいです。 問題は、最悪の場合、各ボクサーが 3 つの可能性を試し、一意性をチェックするにはセットの検索または更新を繰り返し行う必要があり、慎重に管理しないと O(n^2) の複雑さになる可能性があることです。 と`n = 150,000`、このアプローチはタイムアウトになります。 

重要な洞察は、ボクサーを処理する順序が重要であるということです。 ボクサーを体重順に並べ替えることで、体重の小さいものから順に検討することができます。 各ボクサーについて、体重がプラスのままで利用可能な場合は 1 だけ減らそうとし、次に元の体重を試し、最後に 1 だけ増やしてみます。この貪欲な戦略により、より小さな体重が最初に埋められ、競合することなくより高い体重のための余地が残されます。 これが機能する理由は、ウェイトは一度使用すると再利用できないためです。 常に最小の利用可能なオプションを選択することで、後の衝突を最小限に抑えます。 これにより、使用される重みのセットまたはブール配列を維持しながら、ソートされたリストを通過する 1 回のパスで問題が軽減され、ソートと O(n) スペースにより O(n log n) 時間が達成されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(max(a_i)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ボクサーの数を読み取る`n`そして重みのリスト`a`。 
2. 重みのリストを昇順に並べ替えます。 並べ替えにより、より小さい重みが最初に処理されるため、利用可能な最小の一意の重みを貪欲に割り当てることができます。 
3. ブール配列を初期化するか、すでに割り当てられている重みを追跡するように設定します。 ウェイトをボクサーに割り当てるときに、そのウェイトを使用済みとしてマークします。 
4. カウンタの初期化`team_size`正常に割り当てられたボクサーをカウントするには、ゼロにします。 
5. 各重みを反復処理します。`w`ソートされたリスト内。 重量ごとに、次の順序で試してください。 

ａ．`w-1`、それがポジティブで使用されていない場合にのみ。 割り当てられている場合は、使用中としてマークを付けて増分します`team_size`。 

b. もし`w-1`利用できませんでした。試してください`w`自体。 利用可能な場合は、使用済みとしてマークを付けて増分します`team_size`。 

c. どちらでもない場合`w-1`または`w`利用可能でした、試してください`w+1`。 利用可能な場合は、使用済みとしてマークを付けて増分します`team_size`。 
6. すべてのボクサーを処理した後、`team_size`可能な限り最大規模のチームが含まれます。 この値を出力します。 

機能する理由: このアルゴリズムは、割り当てられたすべての重みが一意であるという不変条件を維持します。 ソートにより、より小さいウェイトが優先されるようになり、ウェイト 2 以上のボクサーを減らすことによってのみ割り当てられる小さい番号の無駄が回避されます。 3 段階の貪欲チェックにより、少なくとも 1 つの近くの体重が利用可能な場合、各ボクサーがチームに貢献することが保証されます。 すべてのオプションは昇順にテストされるため、潜在的な割り当てが見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
weights = list(map(int, input().split()))
weights.sort()

MAX_W = 150001
used = [False] * (MAX_W + 2)
team_size = 0

for w in weights:
    if w > 1 and not used[w-1]:
        used[w-1] = True
        team_size += 1
    elif not used[w]:
        used[w] = True
        team_size += 1
    elif w + 1 <= MAX_W + 1 and not used[w+1]:
        used[w+1] = True
        team_size += 1

print(team_size)
```この解決策は、入力を読み取り、ボクサーの体重を並べ替えることから始まります。 ブール配列を使用して、定数時間アクセスで使用される重みを追跡します。 ソートされた重みを反復することで、より小さい重みが最初に処理され、不要な競合が回避されます。 各条件は、可能であれば削減し、その後維持し、その後増加するという貪欲な選択を処理します。 境界チェックにより、負の重みや過度に大きな重みが使用されていないことが保証されます。 インクリメント`team_size`重みが正常に割り当てられた場合にのみ、正確さが維持されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    weights = list(map(int, input().split()))
    weights.sort()
    MAX_W = 150001
    used = [False] * (MAX_W + 2)
    team_size = 0
    for w in weights:
        if w > 1 and not used[w-1]:
            used[w-1] = True
            team_size += 1
        elif not used[w]:
            used[w] = True
            team_size += 1
        elif w + 1 <= MAX_W + 1 and not used[w+1]:
            used[w+1] = True
            team_size += 1
    return str(team_size)

# Provided samples
assert run("4\n3 2 4 1\n") == "4", "sample 1"
assert run("5\n1 1 2 2 3\n") == "5", "custom sample"

# Custom cases
assert run("3\n1 1 1\n") == "3", "all equal weights"
assert run("2\n1 2\n") == "2", "minimum n"
assert run("5\n1 2 2 2 3\n") == "5", "multiple duplicates with lower bound 1"
assert run("6\n5 5 5 5 5 5\n") == "6", "all equal larger weights"
assert run("4\n150000 150000 150000 150000\n") == "4", "upper bound weights"
