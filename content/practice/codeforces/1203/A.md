 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 各シナリオでは、学生のグループが固定された循環順序で配置され、その順序が円の周りを時計回りに移動することを表す線形リストとして表示されます。 

各生徒は 1 から n までの一意のラベルを持ち、与えられた配列は、円の周りを時計回りに歩いたときに各位置にどのラベルが表示されるかを記述します。 

課題は、この円形の配置がどちらの方向でも「完全な連続ダンス」として解釈できるかどうかを判断することです。 有効なケースでは、ある生徒から始めて時計回りに移動すると、途切れることなく順番に 1、2、3、...、n というシーケンスが生成されます。 もう 1 つの有効なケースでは、時計回りに移動すると、反転したシーケンス n、n−1、...、1 が生成されます。円には固定の開始点がないため、シーケンスを回転することはできますが、順序を変更することはできません。 

したがって、問題は、指定された循環順列が増加シーケンスまたは減少シーケンスのいずれかの回転であるかどうかを確認することに帰着します。 

制約は小さく、n は最大 200、q は最大 200 です。これは、各回転を検査したり、各位置を直接チェックしたりするソリューションでも、十分に高速であることを意味します。 テスト ケースごとにリニア スキャンを行うだけで十分です。 

n が 1 または 2 に等しい場合、微妙なエッジ ケースが発生します。n = 1 の場合、どのような配置も自明に有効です。 n = 2 の場合、[1, 2] と [2, 1] は両方とも有効ですが、入力が順列であることが保証されているため、[1, 1] のような繰り返しは不可能です。そのため、有効性は隣接関係の一貫性にのみ依存します。 

よくある間違いは、ラップアラウンドの一貫性を考慮せずに、隣接する差分が +1 であるか -1 であるかだけをチェックすることです。 たとえば、[2, 3, 4, 5, 1] は、インデックス順で 1 が 2 に隣接していなくても有効です。 円形のラップにより有効になります。 

## アプローチ

 これについて考える強引な方法は、円内の可能なすべての開始点を試してみることです。 開始インデックス i ごとに、時計回りに歩くことをシミュレートし、1 から n を順番に読み取れるか、または n から 1 を順番に読み取れるかどうかを確認します。 これには開始点ごとに O(n) の作業が必要で、テスト ケースごとに O(n^2) になります。 

これは n ≤ 200 ではすでに許容可能ですが、重要な観察を使用してさらに単純化できます。有効な配置では、円に沿って時計回りに移動すると、連続する要素間の差は常に一貫して +1 (値空間の mod n) または一貫して -1 (値空間の mod n) でなければなりません。 構造は厳格です。方向を決定すると、全体の順列が決まります。 

したがって、すべての回転を試す代わりに、循環的に解釈した場合に、すべての隣接する差分が 1 ずつ増加するか、1 ずつ減少するかのいずれかに一致するかどうかだけをチェックします。 

これを実装するには、p[i+1] が p[i]+1 (または n から 1 にラップ) であるか、p[i+1] が p[i]−1 (または 1 から n にラップ) であるかを位置ごとにチェックします。 いずれかの条件が最後から最初のエッジを含むすべてのエッジに当てはまる場合、答えは「YES」です。

 | ブルートフォース回転チェック | O(n^2) | お(1) | 承認済み |
 | 方向の一貫性チェック | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 現在のクエリの順列を読み取り、円の周りの時計回りの順序を表します。 この順序は固定されており、変更できません。 
2. 時計回りに増加するシーケンスを検証しようとすると仮定します。 n が 1 に戻る特殊なケースを使用して、連続する各ペアが値がちょうど 1 ずつ増加するというルールに従っているかどうかを検証します。 
3. 増加チェックが失敗した場合は、減少バージョンを試行します。この場合、各ステップは 1 だけ正確に減少する必要があります。ただし、1 が n に戻るという特別な場合があります。 
4. どちらのチェックでも、シーケンスを循環として扱う必要があります。これは、最後の要素が最初の要素に戻ることを意味します。 これにより、破断線ではなく完全なループをテストしていることが保証されます。 
5. すべての隣接ペアに対していずれかの方向が有効な場合は、YES を出力します。 それ以外の場合は NO を出力します。 

### なぜ効果があるのか

 有効なラウンド ダンスでは、円の周りを歩くことで常に 1 つの一貫した方向に連続したラベルが生成される必要があります。 これにより、グローバル制約が強制されます。すべてのノードには、トラバーサル方向に有効なサクセサが 1 つだけ存在します。 ラベルは順列であるため、隣接する 1 つでも +1 または -1 ルールに違反すると、円を回転して完全なシーケンスにすることは不可能になります。 逆に、すべての隣接関係が 2 つの一貫したステップ ルールのいずれかを満たしている場合、サイクル全体は、すべての整数を順番にカバーする単一の有向サイクルを形成する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok_inc(p):
    n = len(p)
    for i in range(n):
        cur = p[i]
        nxt = p[(i + 1) % n]
        if cur == n:
            if nxt != 1:
                return False
        else:
            if nxt != cur + 1:
                return False
    return True

def ok_dec(p):
    n = len(p)
    for i in range(n):
        cur = p[i]
        nxt = p[(i + 1) % n]
        if cur == 1:
            if nxt != n:
                return False
        else:
            if nxt != cur - 1:
                return False
    return True

q = int(input())
for _ in range(q):
    n = int(input())
    p = list(map(int, input().split()))
    if ok_inc(p) or ok_dec(p):
        print("YES")
    else:
        print("NO")
```このコードは、考えられる 2 つの有効な構造を 2 つの明示的なチェックに分割します。 各関数は、円形配置のすべてのエッジを通過し、後続関係が厳密な等差数列モジュロ n に一致するかどうかを検証します。 

モジュロインデックスの使用`(i + 1) % n`最後の要素が最初の要素に接続し直さなければならないため、これは重要です。そうしないと、サイクルではなくパスのみを検証することになります。 

## 実用的な例

 ### 例 1: p = [1, 2, 3, 5, 4]

 まず増加方向をテストします。 

| 私 | カー | 次へ | 予想される | これまでのところ有効です |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 2 | 2 = 1+1 | はい |
 | 1 | 2 | 3 | 3 = 2+1 | はい |
 | 2 | 3 | 5 | 4 が予想されます | いいえ |

 増加チェックは 3 から 5 への移行で失敗します。次に、降順をテストします。 

| 私 | カー | 次へ | 予想される | これまでのところ有効です |
 | --- | --- | --- | --- | --- |
 | 0 | 1 | 2 | 0 予想されるラップ | すぐにいいえ |

 どちらの方向も機能しないため、出力は NO になります。 

これは、隣接関係が 1 つ壊れるだけでサイクル全体を無効にするのに十分であることを示しています。 

### 例 2: p = [3, 2, 1, 4]

 増加チェック:

 | 私 | カー | 次へ | 予想される | 有効 |
 | --- | --- | --- | --- | --- |
 | 0 | 3 | 2 | 4 が予想されます | いいえ |

 減少チェック:

 | 私 | カー | 次へ | 予想される | 有効 |
 | --- | --- | --- | --- | --- |
 | 0 | 3 | 2 | 2 = 3−1 | はい |
 | 1 | 2 | 1 | 1 = 2−1 | はい |
 | 2 | 1 | 4 | 4 = 1−1 ラップ | はい |
 | 3 | 4 | 3 | 3 = 4−1 | はい |

 これは、有効なシーケンスが 1 から始まる必要がないことを確認します。 完全な減少サイクルの回転は許容されます。

def run(inp: str) -> str:

        for i in range(n):

            nxt = p[(i + 1) % n]
            if cur == n:

                if nxt != n:
                    return False
            else:

 ## 特殊なケース

 n = 1 の場合、一貫性に違反する遷移がないため、両方のチェックは自明に成功します。そのため、定義により 1 人のスチューデントが有効なサイクルを形成します。 

n = 2 のような小さなサイクルの場合、両方向は同じ隣接性チェックにまとめられ、アルゴリズムは [1, 2] と [2, 1] の両方を正しく受け入れます。これは、それぞれが厳密な後続規則の 1 つを満たしているためです。 

[3, 4, 5, 1, 2] などの回転の場合、シーケンスが 1 から始まらない場合でも、増加チェックは成功します。配列の最後にあるモジュロ条件によりラップアラウンドの正確性が保証され、構造が線形ではなく真に循環していることが確認されます。
