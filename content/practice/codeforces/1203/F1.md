 ## 解決策
 ## 問題の理解

 Polycarp は初期評価を持つフリーランサーです`r`。 彼はプロジェクトのリストを持っており、各プロジェクトは 2 つの数字で定義されています。プロジェクトを開始するために必要な最低評価と、完了後の評価の変化 (プラスまたはマイナスになる可能性があります) です。 この質問は、評価がゼロを下回らずにすべてのプロジェクトを完了できる順序が存在するかどうかを尋ねます。 

重要な課題は、一部のプロジェクトでは評価が低下するため、完了が早すぎると後続のプロジェクトが不可能になる可能性があることです。 ポジティブなプロジェクトは、評価のしきい値を満たしていればいつでも実行できますが、ネガティブなプロジェクトは、Polycarp の評価が決してゼロを下回らないように慎重に注文する必要があります。 

制約は中程度で、プロジェクト数は最大 100、評価数は最大 30,000 です。 これは、およそ O(n² log n) 回の操作で解決策が実現可能であることを意味します。 プロジェクトのブルートフォース並べ替えは O(n!) であり、明らかに遅すぎます。 エッジケースには、初期評価が低すぎるために個別に完了できないプロジェクトや、ネガティブでない評価を維持するために肯定的なプロジェクトと注意深く交互に配置する必要がある一連のネガティブなプロジェクトが含まれます。 

たとえば、Polycarp の評価が 5 で、プロジェクトが`(4, -3), (2, 1)`の場合、最初のプロジェクトをすぐに試行する単純なアプローチでは、評価が 2 に下がり、それ以上の進歩が困難になるため失敗します。 正しい戦略は、プラスまたはマイナスの影響が小さいプロジェクトを最初に完了することです。 

## アプローチ

 ブルートフォースアプローチでは、プロジェクトのすべての順列を試し、評価の制約が満たされているかどうかを確認します。 これは正確性を保証しますが、n! であるため実行不可能です。 非常に早く成長します。 n = 100 の場合、すべての順列を計算することさえ不可能です。 

重要な観察は、マイナスではない評価の変更があるプロジェクトは、必要な評価の昇順で貪欲に実行できるということです。 評価がマイナスに変更されるプロジェクトの場合は、完了後に評価がゼロを下回らないようにする必要があります。 マイナスのプロジェクトを「負債」として扱う場合、各プロジェクトは下落に耐えられる十分な評価を持って開始する必要があります。 ネガティブなプロジェクトを最も高い安全しきい値で並べ替える、具体的には`a_i + |b_i|`、最も要求の厳しいネガティブ プロジェクトを最後に完了することが保証され、最大限の柔軟性が可能になります。 

最適なソリューションでは、プロジェクトを肯定的な評価変更グループと否定的な評価変更グループに分けます。 肯定的なプロジェクトは、必要な評価に従って貪欲に処理されます。 ネガティブ プロジェクトは次の基準で並べ替えられます。`a_i + |b_i|`そしてその順番で実行されます。 私たちは両方のグループを繰り返し、プロジェクトを開始する前に現在の評価が十分であるかどうかを常に確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 評価と安全しきい値による欲張り | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プロジェクトのリストを 2 つのグループに分割します: ネガティブでないプロジェクト`b_i`ネガティブなプロジェクト`b_i`。 ポジティブなプロジェクトは評価のしきい値を満たせば安全に完了できるのに対し、ネガティブなプロジェクトは評価が下がり、慎重な注文が必要となるため、この区別は非常に重要です。 
2. ポジティブなプロジェクトを昇順に並べ替えます。`a_i`。 まず最も簡単なポジティブ プロジェクトを完了すると、早期に評価が最大化され、後でより困難なポジティブ プロジェクトのしきい値を満たすのに役立ちます。 
3. ネガティブ プロジェクトを昇順に並べ替えます。`a_i + |b_i|`。 これにより、格付けへの影響を考慮して安全に実行できるネガティブなプロジェクトを確実に開始し、十分な格付けバッファーが蓄積された時点で最も危険なネガティブな下落を最後まで延期することができます。 
4. すべてのポジティブなプロジェクトを繰り返します。 それぞれについて、Polycarp の現在の定格が必要な条件を満たしているかどうかを確認します。`a_i`。 「はい」の場合は追加します`b_i`現在の評価に。 評価が不十分なためにプロジェクトを開始できない場合は、終了して「NO」を返します。 
5. すべてのネガティブ プロジェクトを並べ替えられた順序で繰り返します。 現在の定格が満たされているかどうかを確認してください`a_i`。 「はい」の場合は差し引きます`|b_i|`現在の評価からすると。 完了後の評価がマイナスになる場合や、`a_i`現在の定格より大きい場合は、終了して「NO」を返します。 
6. すべてのプロジェクトが正常に完了した場合は、「YES」を返します。 

機能する理由: このアルゴリズムは、Polycarp の評価がゼロを下回らないという不変条件を維持します。 肯定的なプロジェクトは常に安全であり、否定的なプロジェクトは、低下を吸収するのに十分な評価バッファーが存在する場合にのみ試行されます。 ネガティブなプロジェクトを並べ替える`a_i + |b_i|`「最も大きな影響を与える」プロジェクトが最後に処理されるようにすることで、早期の評価の枯渇を防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, r = map(int, input().split())
pos_projects = []
neg_projects = []

for _ in range(n):
    a, b = map(int, input().split())
    if b >= 0:
        pos_projects.append((a, b))
    else:
        neg_projects.append((a, b))

# Process positive projects first
pos_projects.sort(key=lambda x: x[0])
for a, b in pos_projects:
    if r < a:
        print("NO")
        sys.exit()
    r += b

# Process negative projects carefully
neg_projects.sort(key=lambda x: x[0] + abs(x[1]), reverse=False)
for a, b in neg_projects:
    if r < a or r + b < 0:
        print("NO")
        sys.exit()
    r += b

print("YES")
```このコードは、ポジティブなプロジェクトとネガティブなプロジェクトを分離します。 前向きなプロジェクトは選別され、貪欲に実行されます。 ネガティブ プロジェクトは次の基準で並べ替えられます。`a_i + |b_i|`、これにより、定格低下を適用する際の安全性が保証されます。 私たちは各プロジェクトの前後に評価をチェックし、アルゴリズムのステップと正確に一致させてマイナスでないことを確認します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, r = map(int, input().split())
    pos_projects = []
    neg_projects = []

    for _ in range(n):
        a, b = map(int, input().split())
        if b >= 0:
            pos_projects.append((a, b))
        else:
            neg_projects.append((a, b))

    pos_projects.sort(key=lambda x: x[0])
    for a, b in pos_projects:
        if r < a:
            return "NO"
        r += b

    neg_projects.sort(key=lambda x: x[0] + abs(x[1]))
    for a, b in neg_projects:
        if r < a or r + b < 0:
            return "NO"
        r += b

    return "YES"

# Provided samples
assert run("3 4\n4 6\n10 -2\n8 -1\n") == "YES", "sample 1"
# Custom cases
assert run("2 5\n2 -3\n5 -2\n") == "NO", "rating drops too low"
assert run("1 1\n1 0\n") == "YES", "minimum input, neutral change"
assert run("3 10\n5 -5\n6 -4\n4 3\n") == "YES", "mixed positive/negative, ordering matters"
assert run("2 3\n5 2\n2 -1\n") == "NO", "cannot start high requirement project first"
assert run("4 7\n1 3\n3 -2\n2 1\n5 -3\n") == "YES", "complex interleaving of positive and negative"
