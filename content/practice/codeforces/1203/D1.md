 ## 問題の理解

 ソース文字列が与えられます`s`そしてターゲット文字列`t`、 どこ`t`の部分列であることがすでに保証されています`s`。 つまり、次から文字を選択できます。`s`順番に入手して`t`何も並べ替えることなく。 

実行できる操作は、連続した文字ブロックを 1 つ削除することです。`s`。 そのブロックを削除した後、次のことを行います。`t`結果の文字列のサブシーケンスが残ります。 削除されるブロックのすべての有効な選択肢の中で、可能な限り長いセグメントを削除するものが必要です。 

タスクの構造は構築することではありません`t`繰り返しますが、それは達成可能であることがすでに知られているからです。 実際の制約は、どの連続間隔がどの範囲にあるかを特定することです。`s`少なくとも 1 つの有効な埋め込みを保持しながら「消去しても安全」です`t`。 

入力サイズは小さく、文字列あたり最大 200 文字です。 これにより、サフィックス オートマトンやセグメント ツリーのような高度な最適化の必要性が即座に排除されます。 3 次またはわずかに 2 次の解も許容されますが、次の部分文字列にわたる指数関数はすべて許容されます。`s`慎重に境界を定めた場合にのみ安全です。 

単純な失敗モードは、不一致の周囲を貪欲に削除することを想定した場合、または最長のプレフィックスまたはサフィックスを個別に削除しようとした場合に発生します。 たとえば、次の場合`s = "abacaba"`そして`t = "aba"`、真ん中を削除`"c"`は最適ですが、貪欲なプレフィックスまたはサフィックス推論では、両端にさまざまな出現に対する必須の一致が含まれるため、これを見逃します。`t`。 

重要な問題は、以下のことが発生することです。`t`内部にさまざまな方法で埋め込むことができます`s`、中間セグメントを削除しても、別の埋め込みが保持される可能性があります。 

## アプローチ

 ブルートフォース手法では、考えられるすべての部分文字列が試行されます。`[l, r]`削除します。 選択肢ごとに、結果の文字列を構築し、`t`まだ続編です。 サブシーケンスのチェックには直線的な時間がかかります`|s|`、これはおおよそ次のようになります`O(n^3)`最悪の場合:`O(n^2)`部分文字列の回数`O(n)`その後のチェック。 と`n ≤ 200`、これは境界線ですが、Python ではまだ安全です。 ただし、それは不要です。 

重要な点は、削除後に文字列を実際に再構築する必要がないということです。 代わりに、埋め込みを分割できるかどうかだけを知る必要があります。`t`で`s`削除されたセグメントの周囲。 

削除されたセグメントの修正を検討する`[l, r]`。 もし`t`その後もまだサブシーケンスである場合は、次のプレフィックスと一致させることができます。`t`で`s[0:l-1]`そして残りの接尾辞は`t`で`s[r+1:]`。 したがって、問題は最適な分割を見つけることになります。`t`プレフィックスとサフィックスとして照合できる 2 つの部分に分割`s`、順序を尊重したポジション。 

これにより、次の 2 つのことが事前計算されることになります。`s`、どれくらい`t`のすべての接尾辞を照合できます。`s`、サフィックスはどれくらいですか`t`私たちはマッチングできます。 次に、すべての分割ポイントを試します。`s`、それらを削除されたセグメントの境界として解釈します。

 ## アルゴリズムのチュートリアル

 2 つの配列を構築します。 最初の配列`pref[i]`何文字を保存するか`t`のみを使用してマッチングできます`s[0..i]`貪欲に左から右へ。 2 番目の配列`suf[i]`何文字を保存するか`t`のみを使用してマッチングできます`s[i..n-1]`、ただし右から左に一致します。 

次に、削除されたセグメントを解釈します`[l, r]`。 削除した場合はそのままにします`s[0..l-1]`そして`s[r+1..n-1]`。 一致するとします`k`の登場人物`t`プレフィックス部分と残りの部分`|t|-k`サフィックス部分に。 両方の部分が一貫した位置で共存できることを確認する必要があります。 

すべてのプレフィックス一致の長さについて、`k`で最も古いインデックスがわかります。`s`どこで終わるのか、そして接尾辞の一致の場合は、どこから始まるのか最新のインデックスがわかります。 前方一致位置と後方一致位置を事前計算します。 

よりクリーンな実装では、次の 2 つのポインターを使用します。 

1. コンピューティング`pre[i]`の最大プレフィックスとして`t`マッチした`s[0..i]`。 
2. コンピューティング`suf[i]`最大の接尾辞として`t`マッチした`s[i..n-1]`。 
3. あらゆる人にとって`l`で`s`、それを削除の開始として扱います。 
4. あらゆる人にとって`r >= l`、分割が存在するかどうかを計算します。`t`プレフィックスが前に収まるように`l`サフィックスは後に適合します`r`。 
5. 最大値を追跡する`r - l + 1`。 

これが機能するのは、有効なソリューションは、有効なプレフィックス一致とサフィックス一致の間の中間セグメントを切り出すことに対応するためです。`t`。 

### なぜ効果があるのか

 の有効な埋め込み`t`最後の文字列では、次の各文字を割り当てる必要があります。`t`削除されたセグメントの左側の部分または右側の部分のいずれかに。 残りの文字列は順序を維持するため、左側の部分は次の接頭辞と一致する必要があります。`t`で`s[0..l-1]`そして右側の部分は接尾辞と一致する必要があります`t`で`s[r+1..n-1]`。 このアルゴリズムは、プレフィックスとサフィックスの一致配列を介して、このプレフィックスとサフィックスの分割で考えられるすべての分割ポイントを暗黙的に列挙し、有効な分割が見逃されないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()
    n, m = len(s), len(t)

    # pref[i]: max prefix length of t matched in s[0:i]
    pref = [0] * n
    j = 0
    for i in range(n):
        if j < m and s[i] == t[j]:
            j += 1
        pref[i] = j

    # suf[i]: max suffix length of t matched in s[i:]
    suf = [0] * n
    j = m - 1
    for i in range(n - 1, -1, -1):
        if j >= 0 and s[i] == t[j]:
            j -= 1
        suf[i] = m - 1 - j

    # We also need boundary convenience
    pref_pos = [0] * n
    j = 0
    for i in range(n):
        if j < m and s[i] == t[j]:
            j += 1
        pref_pos[i] = j

    ans = 0

    # try all deletion intervals
    for l in range(n):
        for r in range(l, n):
            # check if we can split t into prefix+suffix
            # prefix from [0..l-1], suffix from [r+1..]
            # compute prefix match in prefix region
            k = 0
            for i in range(l):
                if k < m and s[i] == t[k]:
                    k += 1

            # compute suffix match in suffix region
            p = m - 1
            for i in range(n - 1, r, -1):
                if p >= 0 and s[i] == t[p]:
                    p -= 1

            if k > m - 1 - p:
                ans = max(ans, r - l + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、考えられるすべての削除間隔を直接テストします。 間隔ごとに、次の文字数が再計算されます。`t`左右で合わせることができます。 この条件は、分割が次のすべての文字をカバーするかどうかを比較します。`t`重複せずに。 これは最も最適化された形式ではありませんが、指定された制約に対しては正しく、十分です。 

重要な点は、プレフィックスとサフィックスのマッチングを間隔ごとに再計算する必要があることですが、これは許容できる理由です。`n ≤ 200`。 より最適化されたバージョンでは事前計算された配列が再利用されますが、このバージョンでは正確性の明確さを優先しています。

 ## 特殊なケース

 微妙なケースの 1 つが次のような場合です。`t`内部で多くの重複する方法で一致させることができます`s`。 例えば、`s = "aaaaa"`そして`t = "aa"`。 アルゴリズムは、任意の 2 つの発生の間の分割を効果的に許可することでこれを処理します。`a`プレフィックスとサフィックスの一致は削除間隔ごとに再計算できるためです。 これにより、中間ブロックを削除しても代替埋め込みが誤って削除されないようになります。
