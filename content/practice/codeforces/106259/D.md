 ## 解決策
 ## 問題の理解

 整数の配列が与えられているので、少なくとも 2 の長さの部分列を選択する必要があります。 選択したサブシーケンスに対して、選択したすべての数値のビットごとの AND と、選択したすべての数値のビットごとの OR という 2 つのビットごとの集計を計算します。 サブシーケンスのスコアは、これら 2 つの結果間の XOR です。 タスクは、すべての有効なサブシーケンスにわたってこのスコアを最小化することです。 

重要な観察は、AND はビットを下に折りたたむのに対し、OR はビットを上に拡張するということです。 それらの間の XOR は、同じセットのこれら 2 つの極端な圧縮によって生成された最終ビット パターンの不一致を測定します。 少なくとも 2 のサイズのすべてのサブセットを検索しているため、検索スペースは指数関数的であり、直接列挙することは不可能です。 

制約は大きく、すべてのテスト ケースにわたる要素の総数は最大 30 万に達します。 これにより、すべてのサブセット、さらにはペアごとの追加の処理を伴うすべてのペアを検査するアプローチが即座に排除されます。 許容可能なソリューションは、テスト ケースごとに線形またはほぼ線形である必要があります。 

単純なアプローチでは、最初にすべてのペアを試し、より大きなサブシーケンスでは答えを改善できないと想定する可能性があります。 要素を追加すると AND と OR の両方が非自明な方法で変更されるため、これはすでに疑わしいです。 たとえば、3 番目の数値を追加すると、OR を変更せずに AND を大幅に減らすことができ、XOR の結果が低下する可能性があります。 これは、正当化がなければ、ペアごとの推論だけでは不十分であることを意味します。 

2 番目の微妙な問題は、サブ配列ではなくサブシーケンスが許可されることです。 これにより、局所性の制約がなくなり、順序ではなく値の分布のみが重要であることが強化されます。 

## アプローチ

 ブルート フォース手法では、サイズが少なくとも 2 のすべてのサブシーケンスを列挙し、それらの AND と OR を計算し、XOR を評価します。 各サブセットの AND と OR の計算には、サブセット サイズに比例した時間がかかるため、全体の複雑さはすべてのサブセットのオーダーであり、n では指数関数的になります。 ペアに制限しても O(n²) が得られますが、これは 3・10⁵ までの n についてはすでに失敗します。 

重要な洞察は、複数の要素にわたって AND と OR がどのように動作するかを調べることで得られます。 固定ビット位置の場合、選択されたすべての要素にそのビットが設定されている場合にのみ AND は 1 になり、少なくとも 1 つの要素にそのビットが設定されている場合は OR は 1 になります。 どのビットでも、ペア (AND ビット、OR ビット) は (0,0)、(0,1)、または (1,1) のみです。 XOR は、これらが異なる場合にのみ影響します。これは、まさに OR にはビットが設定されているが、AND にはビットが設定されていない場合に発生します。 この条件は、選択された要素のうち、すべての値がそのビットを共有するわけではないことを意味します。 

次に、ペアに注目すると何が起こるかを考えてみましょう。 任意のペア (x, y) について、AND は x & y であり、OR は x | です。 y なので、スコアは (x & y) XOR (x | y) になります。 古典的な恒等式は、これが x XOR y に等しいことを示します。 これは、ビットが x と y の間で異なる場合、AND と OR はすべてのビットで正確に異なり、XOR の動作と一致するためです。 

これにより問題が大幅に単純化されます。 サイズが少なくとも 2 のサブシーケンスのスコアは、その中に小さな XOR のような寄与を達成するペアが少なくとも 1 つ存在するかどうかによってのみ決まります。 さらに要素を追加しても、選択したセット内の最小のペアごとの XOR を減らすことはできないため、最良のサブシーケンスは常に何らかのペアによって達成されます。 より大きなセットでは追加のペアが導入されるだけであり、スコアは最良のペアを下回ることはできません。 

したがって、問題は、すべてのペアにわたる (a[i] & a[j]) XOR (a[i] | a[j]) の最小値を見つけることに帰着します。これは、配列のすべてのペアにわたる最小 XOR を見つけることと同じです。 

これにより、タスクは古典的な「最小 XOR ペア」問題に縮小され、ビット単位のトライを使用して挿入あたりの線形時間で解決できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | お(1) | 遅すぎる |
 | 最小ペアの XOR | をビットごとに試行します。 O(n log A) | O(n log A) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最適なアプローチ

1. 各数値を 31 ビットの整数として扱い、数値を 1 つずつ処理してバイナリ トライに挿入します。 各トライ ノードには、ビット 0 とビット 1 に対応する 2 つの子が格納されます。この構造により、以前に挿入された最も近い数値を XOR 感覚で効率的に見つけることができます。 
2. 入力される各数値について、挿入する前にトライをクエリして、その数値との XOR を最小にする数値を見つけます。 これは、一致するビットは XOR で 0 の寄与を生成するため、可能であれば貪欲に同じビットをたどることによって行われます。そうでない場合は、反対の分岐を取ることを強制されます。 
3. クエリ中に、パスに沿って XOR 値を累積します。 発散を余儀なくされるたびに、そのビット位置にコストが追加されます。 これにより、以前に挿入された数値の間で可能な限り最良の一致が構築されます。 
4. 各要素で見つかった最小の XOR を使用してグローバル応答を更新します。 これにより、すべての要素が以前のすべての要素に対して一度だけペアになるため、すべてのペアが確実に考慮されます。 
5. 現在の数値をトライに挿入すると、今後のクエリで使用できるようになります。 

### なぜ効果があるのか

 トライにより、各数値について、最上位ビットから下方向のビット単位の不一致を最小限に抑える別の数値が効果的に選択されることが保証されます。 上位ビットの改善がすべての下位ビットを支配するため、この貪欲な構築は最適です。 この非対称な方法ではすべてのペアが 1 回考慮されるため、すべてのペアにわたる最小 XOR が 1 回だけ取得され、見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("child",)
    def __init__(self):
        self.child = [None, None]

def insert(root, x):
    node = root
    for b in range(30, -1, -1):
        bit = (x >> b) & 1
        if node.child[bit] is None:
            node.child[bit] = Node()
        node = node.child[bit]

def query(root, x):
    node = root
    res = 0
    for b in range(30, -1, -1):
        bit = (x >> b) & 1
        if node.child[bit] is not None:
            node = node.child[bit]
        else:
            node = node.child[bit ^ 1]
            res |= (1 << b)
    return res

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        root = Node()
        insert(root, arr[0])

        ans = float('inf')

        for i in range(1, n):
            x = arr[i]
            ans = min(ans, query(root, x))
            insert(root, x)

        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、テスト ケースごとにバイナリ トライを構築します。 各数値は最上位ビットから下に向かって 1 ビットずつ挿入されます。 クエリ関数は、一致するビットを優先してトライを探索し、必要な場合にのみ分岐し、結果の XOR コストを累積します。 最初の要素は処理の前に挿入され、後続のすべての要素に少なくとも 1 つの候補パートナーが含まれるようになります。 

31 ビットの選択は、値が最大 10⁹ であるという制約と一致します。 固定深さを使用すると、動的なビット長チェックによるオーバーヘッドが回避されます。

 ## 特殊なケース

 すべての値が同一である配列の場合、すべてのペアの XOR はゼロになり、トライでは即座に同一の一致が見つかり、ゼロが生成されます。 アルゴリズムによって最初の値が挿入され、後続のすべてのクエリですべてのレベルで同じビット パスが検索されます。 

厳密に増加する 2 の累乗の場合、各数値は正確に 1 つのビット位置で異なり、トライにより最大の異なるビットで発散が強制され、予測可能な XOR 値が生成されます。 貪欲なトラバーサルは、ビット空間内の最近傍を正確に識別します。 

ゼロが含まれる場合、最初にゼロを挿入すると、今後のすべてのクエリが即座にゼロ ビットと一致することが保証され、多くの場合、非常に小さな XOR 値が生成されます。 このトライは、特別なケースを使用せずにすべてゼロの分岐を正しく処理します。
