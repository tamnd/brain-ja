 ## 解決策
 ## 問題の理解

 原点を中心とする円の内側に点が与えられます。 各ポイントはトッピングを表し、正または負の数値を持ちます。 原点から始まる 2 つの光線によって定義されるピザのスライスを選択することができます。これは、角度間隔を選択し、原点からの方向がその間隔内にあるすべてのトッピングを取得することを意味します。 境界上のすべてが含まれます。 

スライスには幾何学的制約があり、その面積は指定された制限を超えることはできません。 スライスは扇形であるため、その面積は角度に正比例します。 これにより、制約が、選択できる角度間隔の上限に変わります。 

有効なスライスについては、その内部のすべてのポイントの値を合計します。 スライスのスコアは、この合計の絶対値です。 タスクは、面積制約を満たす可能な限り最良の角度間隔を選択し、この絶対和を最大化することです。 

入力サイズは大きく、すべてのテスト ケースにわたって最大 3x10^5 ポイントがあります。 これにより、角度境界としての点のペアの二次列挙が即座に除外されます。 すべての光線のペアをテストしたり、候補区間ごとに合計を最初から再計算したりしようとするソリューションは、遅すぎます。 

主な微妙な点は、固定端点を持つ線分上ではなく、円形領域上で単純な合計を最大化していることです。 間隔は角度 0 の方向を囲む可能性があるため、円形の性質を慎重に扱わない限り、単純な線形スライディング ウィンドウ推論が不完全になります。 

典型的な失敗例は、ラップアラウンドを無視したことに起因します。 2 つの高い値のクラスターが角度 0.01 ラジアンと 6.27 ラジアンの近くにあると仮定します。 2π 境界を横切る小さなスライスには両方が含まれる可能性がありますが、並べ替えられた角度に対する単純な線形スイープでは、角度が遠く離れているものとして扱われます。 円形の連続性を複製したりモデル化したりしないソリューションでは、そのような最適なスライスが失われます。 

もう 1 つのよくある間違いは、絶対値を無視することです。 最大合計部分配列のみを追跡する場合、強い負のスライスが正のスライスよりも大きな絶対値を生成する可能性があるにもかかわらず、負の重い領域は無視されます。 

## アプローチ

 ブルートフォースアプローチでは、トッピングのすべてのペアを潜在的な境界光線として選択し、それらが定義する角度間隔を計算して、内側にあるすべての点を合計します。 角度を事前に計算してプレフィックスの合計を使用したとしても、O(n^2) 間隔をテストする必要があり、円形構造全体にわたる各間隔の妥当性をチェックするには、最悪の場合でも線形時間がかかります。 これにより、直接実行した場合はおよそ O(n^3) の動作が発生し、最適化された範囲クエリを使用した場合は O(n^2) の動作が発生し、どちらも制限をはるかに超えています。 

重要な観察は、角度の順序のみが重要であるということです。 ポイントが角度によって並べ替えられると、有効なスライスはこの円形順序の連続セグメントに対応しますが、角度幅が領域制限から導出される固定しきい値を超えないという追加の制約があります。 

これにより、サブ配列の長さがインデックス距離ではなく角距離で定義されるという追加の制約を伴い、問題は円形配列全体にわたる最大絶対和サブ配列を見つけることになります。 角度がソートされると、角距離は配列に沿って単調になり、2 ポインターのスライディング ウィンドウが可能になります。 

次に、円形配列を複製して線形配列に変換します。 これにより、ラップアラウンド間隔を 2 倍の配列の標準間隔にすることができます。 この構造内では、角度幅の制約を常に満たすスライディング ウィンドウを維持します。 右のエンドポイントごとに、必要に応じて左のエンドポイントを進め、現在の合計を維持します。 答えは有効なウィンドウ合計の最大絶対値であるため、最大合計と最小合計の両方を追跡します。

 | 最適な引き違い窓 | テストあたり O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 面積制約を角度制限に変換する

 半径 r、角度 θ の扇形の面積は (1/2) r^2 θ です。 これから、θmax = 2A / r^2 を計算します。 有効なスライスの角度幅は最大でも θmax でなければなりません。 

### ステップ 2: すべての点の極角を計算します。 

各トッピングについて、atan2(y, x) を使用して角度を計算します。 これにより、すべての点が区間 [0, 2π) 上に配置されます。 

スライス制約は距離ではなく原点からの方向のみに依存するため、この手順は不可欠です。 

### ステップ 3: 角度ごとにポイントを並べ替える

 すべての点を極角で並べ替えます。 ソート後、ラップアラウンドのない有効なスライスは、この順序での連続セグメントに対応します。 

ソートは、ジオメトリを 1D 構造に変換し、ウィンドウ処理が可能になります。 

### ステップ 4: 循環ラップを処理するために配列を複製する

 角度を 2π 増やして各点を再度追加します。 これにより、円形の間隔が線形の間隔に変換されます。ラップアラウンド スライスは、この拡張された配列内の通常のセグメントになります。 

このステップにより、角度 0 の境界を横切るスライスを見逃すことがなくなります。 

### ステップ 5: 2 ポインター ウィンドウを使用して角度幅を強制する

 左ポインタと現在の合計を維持します。 各右ポインタについて、左右の角度差が最大 θmax になるまで左ポインタを移動します。 ウィンドウはスライス領域に関して常に有効です。 

これが機能するのは、ソートされた角度によって単調性が保証されるためです。そのため、ウィンドウが無効になった場合は、左ポインタを増やすことで有効性を回復できます。 

### ステップ 6: 最大ウィンドウ合計と最小ウィンドウ合計の両方を追跡する

 ウィンドウ内の値の合計を維持します。 有効なウィンドウごとに、最大合計と最小合計の両方を更新します。 

最終的な答えは、これら 2 つの極値の絶対値の最大値です。 

最適なスライスにはほとんど負の値が含まれている可能性があり、その絶対値が正のスライスよりも優勢であるため、両方が必要です。 

### なぜ効果があるのか

 すべての有効なスライスは、連続した角度間隔に対応します。 並べ替えると、これらの間隔が連続したセグメントになります。 複製により、ラップアラウンド間隔も連続するようになります。 2 ポインター プロセスでは、各右端点に対して最小の有効な左端点が維持されるため、すべての最大有効セグメントが 1 回だけ列挙されます。 これにより、実現可能なすべてのスライス合計がウィンドウ合計として考慮され、最大値と最小値の両方を取得することで絶対的な目的がカバーされることが保証されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, r, A = map(int, input().split())
        
        pts = []
        for _ in range(n):
            x, y, v = map(int, input().split())
            ang = math.atan2(y, x)
            if ang < 0:
                ang += 2 * math.pi
            pts.append((ang, v))
        
        if n == 0:
            print(0)
            continue
        
        theta = (2.0 * A) / (r * r)
        if theta >= 2 * math.pi:
            total = sum(v for _, v in pts)
            print(abs(total))
            continue
        
        pts.sort()
        
        ext = pts + [(a + 2 * math.pi, v) for a, v in pts]
        
        left = 0
        cur_sum = 0
        ans = 0
        
        for right in range(len(ext)):
            cur_sum += ext[right][1]
            
            while ext[right][0] - ext[left][0] > theta:
                cur_sum -= ext[left][1]
                left += 1
            
            ans = max(ans, abs(cur_sum))
        
        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、atan2 を使用してジオメトリを角度に変換し、すべての方向が単一の円形スケールに正規化されるようにすることから始まります。 面積制約は、セクター面積公式を使用して最大角幅に変換されます。 

角度によってポイントを並べ替えると、有効なスライスが連続したセグメントに対応する構造が作成されます。 複製ステップにより、ラップアラウンド スライスを通常の間隔と同様に処理できるようになります。 

スライディング ウィンドウは累計を維持し、角度幅が許容制限を超えるたびに左側の境界を調整します。 正と負の両方の極値を正しく追跡するには、内部合計が符号付きのままである必要があるため、絶対値は答えを更新する場合にのみ適用されます。 

## 実用的な例

 値 10、-20、30、-5 を持つ 4 つの点が 4 分の 1 回転で配置された単純なケースを考えてみましょう。 角度制限では最大でも半円が許容されると仮定します。 

角度に変換した後、点は循環順に並べ替えられます。 スライディング ウィンドウは、まず角度制限に達するまで拡張され、値が累積されます。 移動すると、合計が 20 の [10, -20, 30]、合計が 25 の [30, -5] などのセグメントがキャプチャされる可能性があります。 

| 右インデックス | 左のインデックス | ウィンドウ値 | 合計 |
 | --- | --- | --- | --- |
 | 0 | 0 | 10 | 10 |
 | 1 | 0 | 10、-20 | -10 |
 | 2 | 0 | 10、-20、30 | 20 |
 | 3 | 1 | -20、30、-5 | 5 |

 このトレースは、有効なウィンドウを維持しながらマイナスの寄与がどのように自然に処理されるかを示しています。 

次に、2 つの高い値の点が角度 0 と 2π の近くにあるラップアラウンドの例を考えてみましょう。 複製後、それらは拡張配列内で隣接するようになり、連続性を損なうことなくウィンドウに両方を含めることができます。 

| 右インデックス | 左のインデックス | ウィンドウ値 | 合計 |
 | --- | --- | --- | --- |
 | 0 | 0 | 100 | 100 |
 | 1 | 0 | 100、90 | 190 |

 これは、複製が必要な理由を裏付けています。複製がないと、これらの点は遠く離れて表示され、結合されることはありません。

 ## 特殊なケース

 重要なエッジケースは、許容される角度幅が全円を超える場合です。 この状況では、制約は意味を持たなくなり、すべての点が 1 つのスライスに含まれる可能性があります。 唯一の有効なスライスは完全なセットであるため、アルゴリズムはすべての値の絶対和を直接返すことによってこれを処理します。 

もう 1 つのエッジ ケースは、最適値が非常に負のクラスターから得られる場合です。 このアルゴリズムは最小ウィンドウ合計を明示的に追跡し、大きな負の合計が失われないようにします。 たとえば、スライスに値 [-50, -40] が含まれている場合、合計は -90 で、答えは 90 になります。これは、最大合計のみのアプローチでは見逃してしまいます。 

3 番目のエッジ ケースは、ラップアラウンド ドミナンスです。 2 つの高い値の点が角度 0 と 2π の近くにある場合、それらは生の順序では分離されますが、複製後に隣接します。 スライディング ウィンドウはそれらを単一の有効なスライスに正しくマージし、どの線形セグメントよりも高いスコアを生成します。
