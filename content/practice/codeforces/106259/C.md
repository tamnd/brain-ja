 ## 解決策
 ## 問題の理解

 小文字で構成される文字列が与えられ、削除された各部分が回文であり、長さが均一である限り、部分文字列を繰り返し削除できます。 部分文字列を削除した後、文字列の残りの部分が結合され、すべて削除するか、行き詰まるまで作業が続行されます。 

問題は、文字列全体を完全に削除するような一連の削除が存在するかどうかです。 

この制約により、すべてのテスト ケースの全長が 3 · 10^5 に達することが許可されるため、解は線形に近いか、テスト ケースあたり最大でも O(n log n) でなければなりません。 すべての部分文字列を試行したり、明示的に削除をシミュレートしたりする 2 次アプローチは、長さ 10^5 の単一文字列でさえ O(n^2) 演算にはすでに大きすぎるため、すぐに失敗します。 

いくつかの特殊なケースには、早めに気づく価値があります。 のような文字列`uwu`は回文であっても削除できません。長さが奇数であるため、有効な操作がまったく適用されません。 のような文字列`abab`また、すべての文字数が偶数であっても、どこにも偶数長の回文部分文字列が存在しないため、削除できません。 最後に、次のような文字列`abba`文字列全体が偶数長の回文であるため、完全に削除できます。 

これらの例は、局所的な対称性だけでは不十分であることを示唆しています。 重要なのは、文字列をネストされた対称的な削除の構造に分解できるかどうかです。 

## アプローチ

 直接的な試みは、プロセスをシミュレートすることです。 各ステップで、すべての部分文字列をスキャンし、それらが偶数長の回文であるかどうかを確認し、可能であれば 1 つを削除して、繰り返します。 ハッシュや 2 つのポインターを使用した場合でも、削除できる数は多く、削除のたびに文字列が再形成されるため、最悪の場合、全体の複雑さは 3 次になります。 これは限界をはるかに超えています。 

重要な点は、削除の順序について考えるのをやめ、代わりに文字列が完全に削除可能である場合に最終的な構造がどのようになるかを考えることです。 削除するたびに、連続する偶数長の回文が削除されます。 偶数長の回文は、そのセグメント内の対称位置のペアとして見られます。 すべての削除を順次ではなく一度に追跡すると、文字列内の各位置は最終的に同じ文字の別の 1 つの位置と正確に一致します。また、削除は連続したブロックに対して行われるため、これらのペアが競合する形で交差することはありません。 

これは構造の再定式化につながります。各ペアが等しい文字を接続し、これらのペアが無効な方法で交差しないように、すべてのインデックスをペアにできるかどうかを決定しようとしています。 このようなペアが存在すると、いつでも内側から外側へ削除を実行できます。 

このようなペアを強制する自然な方法は、各文字の出現を逆の順序でペアにすることです。 文字が k 回出現する場合、最初の出現は最後の出現とペアになり、2 番目の出現は最後から 2 番目の出現とペアになる必要があります。 これにより、候補区間のセットが生成されます。 残りの疑問は純粋に構造的なものになります。これらの間隔は正しくネストされているのでしょうか、それとも分解が不可能になるような形で一部の間隔が交差しているのでしょうか?

 | インターバルペアリング + 構造チェック | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、すべての文字の出現数をカウントします。 任意の文字が奇数回出現した場合は、文字列全体を削除することは不可能であると直ちに判断してください。 これが必要なのは、すべての削除でカウントのパリティがグローバルに保持され、完全な削除にはすべてのカウントが偶数である必要があるためです。 
2. 文字ごとに、それが出現するすべてのインデックスを個別にリストします。 最初の出現と最後の出現をペアにし、2 番目の出現と最後から 2 番目の出現をペアにします。 各ペアは、元の文字列の間隔を定義します。 

このステップは、単一の文字クラス内で交差を作成せずに同一の文字を照合する唯一の可能な方法をエンコードします。 
3. すべての文字にわたるこれらすべての間隔を 1 つのリストに収集します。 
4. 間隔を左側のエンドポイントで並べ替えます。 次に、それらが適切な入れ子構造を形成しているかどうかを確認します。 
5. 開始位置の昇順で間隔をスイープし、右端点の順に並べられたアクティブな間隔のスタックを維持します。 新しい間隔に入ると、それを押します。 間隔の終わりに到達すると、それは最後に開かれた間隔に対応する必要があります。 そうでない場合は、交差が発生し、建設は無効になります。 
6. 違反を検出せずにすべての間隔の処理を終了すると、文字列を完全に削除できます。 

### なぜ効果があるのか

 各削除は、連続する偶数長の回文を削除することに対応し、そのセグメント内に一連の対称ペアリングが誘導されます。 プロセス全体を通じて、すべての位置が 1 回だけ一致し、一致は常に等しい文字間で行われます。

各文字の出現を外側から内側にペアにすることにより、対称的な削除が繰り返されることで生じる可能性のある唯一の構造を強制します。 結果として生じる 2 つの間隔が交差する場合、それは、必要な 2 つの対称構造が、連続する回文のネストされた削除では生成できない方法でインターリーブする必要があることを意味します。 逆に、すべての間隔がネストされている、または互いに素である場合は、いつでも最初に最も内側の間隔を削除し、有効性を損なうことなく徐々に外側に折りたたむことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(s: str) -> bool:
    n = len(s)
    pos = {}
    
    for i, c in enumerate(s):
        pos.setdefault(c, []).append(i)
    
    intervals = []
    
    for c, arr in pos.items():
        if len(arr) % 2 == 1:
            return False
        for i in range(len(arr) // 2):
            l = arr[i]
            r = arr[-1 - i]
            intervals.append((l, r))
    
    intervals.sort()
    
    stack = []
    
    for l, r in intervals:
        while stack and stack[-1][1] < l:
            stack.pop()
        
        if stack and stack[-1][1] > r:
            return False
        
        stack.append((l, r))
    
    return True

def main():
    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        out.append("YES" if solve_one(s) else "NO")
    print("\n".join(out))

if __name__ == "__main__":
    main()
```コードはまず各文字の位置をグループ化し、次に対称的な出現を一致させることによって強制ペアリング間隔を構築します。 パリティ チェックにより、不可能なケースが早期に除外されます。 

重要な部分は間隔の検証です。 左のエンドポイントでソートした後、スタックはアクティブな間隔の入れ子構造を維持します。 前の間隔内で終了するが、そのネスト位置と一致しない間隔が見つかった場合、交差が検出され、完全な削除が不可能になります。 

微妙な点は、削除のシミュレーションをまったく行っていないことです。 プロセス全体は、一貫したグローバル ペアリングが存在するかどうかを確認することになります。

| イベント | 前にスタック | アクション | | の後にスタック

### 例 2:`abcd`各文字は 1 回出現するため、パリティはすぐに失敗します。 

| キャラクター | カウント | 決定 |
 | --- | --- | --- |
 | | 1 | 不可能 |
 | b | 1 | 不可能 |
 | c | 1 | 不可能 |
 | d | 1 | 不可能 |

 奇数の数が存在するため、ペアリングは不可能であり、答えは「NO」です。 

これら 2 つのケースは、構造上の不可能性とパリティの障害という両方の故障モードを示しています。

 ## 特殊なケース

 次のような単一文字の場合`a`パリティ ルールを直接示します。 アルゴリズムは文字数が奇数であることを即座に検出し、構造的な構築を試行せずに NO を返します。 

のために`abab`の場合、ペアリング ステップでは間隔 (0,2) と (1,3) が生成されます。 一方が他方の内側で始まり外側で終わるため、これらの間隔は交差します。 スタック検証中に、2 番目の間隔が最初の間隔内に適切にネストされていないため、この交差が検出され、拒否につながります。 

のために`aabbccdd`、間隔は (0,1)、(2,3)、(4,5)、(6,7) です。 すべての間隔が互いに素であるため、スタックでは不一致が発生することはなく、その構造は有効であり、アルゴリズムはそれを受け入れます。
