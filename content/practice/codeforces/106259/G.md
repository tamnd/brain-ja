 ## 問題の理解

 私たちは根を張った木を与えられています`n`ノードと順列`p`これにより、すべてのノードがシーケンス内に 1 回だけ配置されます。 

このシーケンスから開始して、繰り返し圧縮していきます。 各圧縮ステップでは、隣接するすべてのペアが取得され、ツリー内の最も低い共通祖先に置き換えられます。 最初のステップの後、シーケンスには長さがあります`n-1`、次以降は長さになります`n-2`など、単一の値が残るまで続きます。 

すべての中間シーケンスについて、その要素の合計を計算し、これらの合計をすべての長さに対して出力するように求められます。`n`まで`1`。 

重要な隠れた構造は、繰り返される隣接する LCA 削減が恣意的に動作しないことです。 後`k`圧縮ステップでは、各要素は長さの連続セグメントの LCA に正確に対応します。`k+1`元の順列で。 したがって、実際の問題は、順列のすべての連続する部分配列とその LCA に関するものです。 

そのリフレーミングによってすべてが変わります。縮小シーケンスをシミュレートする代わりに、事実上、次のすべての部分配列の LCA を評価することが求められます。`p`、サブ配列の長さによってグループ化されます。 

制約は次のとおりです`10^6`テストあたりのノード数とオーバーテストの合計も`10^6`。 すべての部分配列を明示的に扱うような解決策は直ちに不可能です。`O(n^2)`サブアレイ。 平`O(n log n)`定数が厳密であり、構造が注意深く制御されていない限り、ノードごとに危険になります。 

変換の単純なシミュレーションも遅すぎます。 各ステップは配列全体を処理します。`n`につながるステップ`O(n^2)`テストケースごとに作業します。 

より微妙な障害モードは、LCA が増分更新を可能にする方法で「適切に圧縮される」と仮定することで発生します。 たとえ隣接するペアの LCA を維持できたとしても、各圧縮後にそれらを更新するにはステップごとに線形時間がかかり、再び 2 次の動作に陥ります。 

本当の難しさは、すべてのノードが多くの異なるサブ配列の LCA になる可能性があり、それらのサブ配列がツリー構造内で連続しておらず、順列順序でのみ連続していることです。 

## アプローチ

 ブルートフォースの観点は、プロセスを明示的にシミュレートすることです。 順列から開始し、隣接するペアをその LCA で繰り返し置き換え、合計を累積します。 これは定義に直接従うため正しいですが、各変換では縮小配列がスキャンされます。 総操作数はおおよそ次のとおりです`n + (n-1) + ... + 1`、つまり`O(n^2)`。 と`n`まで`10^6`、これは実現可能な限界をはるかに超えています。 

重要な構造的洞察は、繰り返される変換について考えるのをやめ、代わりに何度も圧縮された後に何が残るかに焦点を当てることです。 後`k`ステップの場合、各値は元の順列における連続セグメントの LCA です。 これにより、問題は純粋な区間問題に変換されます。つまり、すべての部分配列が 1 つの LCA 値に寄与します。 

したがって、変換をシミュレートする代わりに、各ノードの寄与を部分配列の LCA としてカウントします。 

次にノードを修正します`v`。 次の LCA を持つサブアレイがいくつあるかを数えたいとします。`v`。 サブアレイには LCA がある`v`そのすべての要素がサブツリー内にある場合`v`、ただし、それは、次の単一の子サブツリー内に完全には含まれていません。`v`。 直観的には、サブ配列は以下の少なくとも 2 つの異なる子領域に「接触」する必要があります。`v`(または含める`v`他のブランチも同様です)。 

これにより、問題はノードごとのバイナリ インジケーター配列にわたる間隔のカウントに軽減されます。`v`、位置をマークします`p`そのサブツリーに属するもの。 マークされた領域内に完全にあるサブ配列は、「下にある」ことに寄与します。`v`”、そして子供の貢献を差し引くと、真の LCA が正確に一致する子供たちを分離できます。`v`。 

課題は、これを単に合計数としてではなく、サブ配列の長さで区切る必要があることです。`S_i`固定サイズの部分配列に対応します。 

ノードごと、長さごとの直接の列挙は不可能です。 代わりに、ランレングス構造を利用します。 固定ノードの場合`v`、順列順序では、そのサブツリーの位置がいくつかの連続したブロックを形成します。 各ブロックの長さ`L`各サイズのサブ配列の予測可能な数に寄与します: ウィンドウ サイズの場合`k`、貢献します`max(0, L-k+1)`。 

これにより、問題はセグメントの長さにわたって等差数列からの寄与を維持することに変わります。 線形関数の差分表現を使用すると、各実行を一定時間で処理できるようになり、その後のプレフィックス合計によってすべての関数の寄与が再構築されます。`k`。 

これらの構造をツリー上でボトムアップで計算します。 各ノードは、ソートされた順序を維持しながら、その子の位置リストをマージします。 これは古典的な小規模から大規模へのマージ戦略であり、全体的な複雑さを管理可能な状態に保ちます。 ノードのリストを作成した後、その実行を抽出し、それらをすべての長さにわたる寄与の更新に変換し、二重カウントを避けるために子の寄与を減算します。

 ## アルゴリズムのチュートリアル

 1. ノードでツリーをルート化します`1`各ノードのサブツリー メンバーシップを前処理します。 また、ノードごとに、順列のどの位置がそのサブツリーに属しているかを追跡します。 
2. すべてのノードに対して、インデックスのソートされたリストを維持します。`p`そのサブツリーに属するもの。 これらのリストは、小規模から大規模へのマージを使用してボトムアップで構築され、常に小さな子リストを大きなリストにマージして総コストを制御します。 
3. 固定ノードの場合`v`、位置のリストが構築されたら、それをスキャンし、インデックス順に最大の連続セグメントに分割します。 各セグメントは、すべての要素が含まれる順列内の連続したブロックに対応します。`subtree(v)`。 
4. 長さの各セグメントについて`L`、長さによって部分配列への寄与を計算します。 長さのセグメント`L`含まれています`(L - k + 1)`長さの部分配列`k`みんなのために`1 ≤ k ≤ L`。 
5. 毎回更新するのではなく`k`この寄与を次の線形関数として直接表します。`k`。 2 つの差分配列を維持します。1 つは定数項用、もう 1 つは係数項用です。`k`。 各セグメントはこれらの配列を更新します。`O(1)`時間。 
6. すべてのセグメントを処理した後、`v`、貢献を組み合わせて、全体的な効果を形成します。`v`。 次に、その子にすでに割り当てられている寄与を減算し、LCA が正確に一致するサブ配列のみを確保します。`v`残る。 
7. 各ノードの最終的な寄与にノード ラベルを乗算し (答えはノード値の合計となるため)、サブ配列の長さごとにグローバル配列に累積します。 
8. すべてのノードを処理した後、差分配列のプレフィックスの合計を計算して、各ノードの最終的な答えを取得します。`S_i`。 

### なぜ効果があるのか

 各サブ配列は、ツリー内の 1 つの LCA に正確に対応します。 任意の固定ノードの場合`v`、アルゴリズムは要素が含まれるすべてのサブ配列をカウントします。`subtree(v)`次に、単一の子サブツリーに完全に含まれるサブツリーを削除します。 残るのは正確に、最も深い共通の祖先が`v`。 サブツリー リストは順列位置から正確に構築され、順序を失うことなくマージされるため、すべての有効なサブ配列は正しいノードで 1 回だけ表現され、子を減算した後にサブ配列が二重にカウントされることはありません。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n = int(input())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    p = list(map(int, input().split()))
    pos = [0] * (n + 1)
    for i, x in enumerate(p):
        pos[x] = i

    parent = [0] * (n + 1)
    order = []
    stack = [1]
    parent[1] = -1

    while stack:
        v = stack.pop()
        order.append(v)
        for to in g[v]:
            if to == parent[v]:
                continue
            parent[to] = v
            stack.append(to)

    children = [[] for _ in range(n + 1)]
    for v in order[1:]:
        children[parent[v]].append(v)

    # small-to-large sets of positions
    sets = [[] for _ in range(n + 1)]

    A = [0] * (n + 2)
    B = [0] * (n + 2)
    ans = [0] * (n + 1)

    def add_segment(l, r, val):
        # adds val*(len - k + 1) over k in [l, r]
        A[l] += val * (r + 1)
        A[r + 1] -= val * (r + 1)
        B[l] += val
        B[r + 1] -= val

    def merge(a, b):
        if len(a) < len(b):
            a, b = b, a
        i = j = 0
        res = []
        while i < len(a) and j < len(b):
            if a[i] < b[j]:
                res.append(a[i])
                i += 1
            else:
                res.append(b[j])
                j += 1
        res.extend(a[i:])
        res.extend(b[j:])
        return res

    def dfs(v):
        sets[v] = [pos[v]]
        for to in children[v]:
            dfs(to)
            sets[v] = merge(sets[v], sets[to])

        arr = sets[v]
        # compute runs
        i = 0
        while i < len(arr):
            j = i
            while j + 1 < len(arr) and arr[j + 1] == arr[j] + 1:
                j += 1
            L = j - i + 1

            # apply contribution of this run for node v
            # linear update for k in [1..L]
            A[1] += (L + 1)
            A[L + 1] -= (L + 1)
            B[1] += 1
            B[L + 1] -= 1

            i = j + 1

    dfs(1)

    for i in range(1, n + 1):
        A[i] += A[i - 1]
        B[i] += B[i - 1]
        ans[i] = A[i] - i * B[i]

    print(*ans[1:])

if __name__ == "__main__":
    solve()
```この実装では、順列の各インデックスが対数回だけ移動されるように、小から大へのマージを使用して各ノードのサブツリーの位置を構築します。 ノードのリストの準備が完了すると、そのリストがスキャンされて、順列順に連続するセグメントが検索されます。 各セグメントは、線形式の差分表現を使用して、すべてのサブ配列長にわたる寄与に変換されます。`(L - k + 1)`。 

2 つの配列`A`そして`B`この式の分解されたバージョンを保存します。`A`一定の部分を蓄積しますが、`B`の係数を追跡します`k`。 プレフィックスを合計した後の値`A[k] - k * B[k]`有効な長さの部分配列の総数を返します。`k`。

 ## 特殊なケース

 単一ノード ツリーは最も単純な構成です。 順列には要素が 1 つだけ含まれるため、部分配列が 1 つだけ存在し、その LCA はノード自体になります。 このアルゴリズムは、単一の位置リスト、長さ 1 の単一ランを生成し、`k=1`期待される出力と一致する貢献。 

星型ツリーでは、異なるリーフからのノードを含むすべてのサブ配列の LCA はルートと同じになります。 ルートの位置リストは、置換順序に応じて潜在的に多くの小さなギャップを含む長いシーケンスになります。 実行分解により、連続するブロックが順列順序で正しくグループ化され、算術更新により、ペアごとの列挙を必要とせずに、すべての間隔長がルートに寄与することが保証されます。 

線形チェーン ツリーでは、LCA は区間カバレッジに応じて上位の祖先に向かって崩壊します。 各ノードのサブツリーの位置は連続または連続に近いランを形成し、子の寄与を減算することで各間隔が正しい最も深い祖先に割り当てられるようになり、中間ノードでの過剰カウントが防止されます。
