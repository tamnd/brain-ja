 ## 解決策
 ## 問題の理解

 私たちは、非常に小さな幾何学的キャンバス (整数の格子点を持つ 2 × 2 の正方形) に描かれたパターンを使用して、各数値に一意の識別子を割り当てるシステムを設計しています。 各数値は格子点間の一連の直線セグメントに対応しますが、間に他の格子点を含まないセグメントのみが許可されます。 したがって、事実上、目に見えるグリッド点の間のプリミティブ セグメントのみを使用できます。 

このプロセスには 2 つのフェーズがあります。 最初のフェーズでは、数値 n ごとに、2 x 2 グリッド上の有効なセグメントのコレクションであるパターンを構築する必要があります。 第 2 フェーズでは、以前に生成されたパターンが与えられますが、0、90、180、または 270 度回転されている可能性があり、その内部順序は任意です。セグメントが並べ替えられたり、各セグメント内のエンドポイントが交換されたりする可能性があります。 この変換されたパターンから、元の数値を復元する必要があります。 

したがって、タスクは、整数を、厳密な回転と順序付けされていない表現の下でも安定した小さな幾何学的な署名にエンコードし、それを確実にデコードすることです。 

グリッドは小さいですが、これが最も重要な構造上の制約です。 唯一の自由度は、3 × 3 の整数格子内の 9 つの格子点をどのように接続するかによって決まります。 セグメントはこれら 9 つの点のうちの 2 つの端点によって決定されますが、gcd(dx, dy) = 1 を持つものだけが有効なプリミティブ セグメントです。 

重要な制約は、n が 6,700 万に達する可能性があるため、エンコードでは少なくとも 26 ビットの情報をサポートする必要があることです。 これは、単純な「すべてのパターンを列挙する」という考えや、パターン間のブルートフォース同型性チェックに頼ることができないことをすでに示しています。なぜなら、回転中のパターンを保存されたリストと照合するだけでも、潜在的に大規模な組み合わせ構造に対する高度な正規化が必要になるからです。 

素朴なアプローチは、各パターンを 9 ノード上のラベル付きグラフとして扱い、回転の下でグラフの同型性を試みることです。 ただし、グラフが小さい場合でも、エッジの可能な回転と置換の数により、クエリごとに単純に実行すると正規比較のコストが高くなります。 不注意な実装では、回転されたすべてのバリアントが再計算され、エッジ マルチセットが直接比較され、不要なオーバーヘッドと脆弱なコーナー処理が発生する可能性があります。 

セグメントを指示どおりに処理する場合、別の微妙な失敗例が発生します。 グレーダーはエンドポイントを交換する可能性があるため、明示的に正規化しない限り、エッジの方向に依存するエンコードは直ちに中断されます。 

## アプローチ

 重要な観察は、ボードの構造から得られます。 3 × 3 の整数格子にはちょうど 9 個の点があるため、プリミティブ セグメントの数は有限です。 この有限集合は 1 回だけ列挙できます。 すべてのパターンは、これらのセグメントのサブセットにすぎません。 

回転は、この有限セットのセグメントに対する順列として機能します。 これが核となる単純化です。幾何学的に考える代わりに、各パターンをセグメントの固定領域上のビットマスクとして、回転をビット位置の固定された並べ替えとして考えることができます。 

この視点を採用すると、問題は純粋な集団行動の問題になります。 4 つの回転すべてが同じ正規表現にマッピングされるように各数値にビットマスクを割り当てる必要があり、デコードではそのマッピングを反転する必要があります。 

強引なアイデアは、4 つの回転されたバリアントが何らかの一意性条件を満たすものを見つけるまで、数値ごとにセグメントのすべてのサブセットを試行することです。 これは、検索空間のセグメント数が指数関数的であり、グリッドが小さい場合でも、セグメントの列挙方法に応じてサブセットの数が依然として 2^12 またはそれに類似しているため、すぐに失敗します。

正しい考え方は、各セグメントの回転軌道を事前に計算することです。 すべてのセグメントは、0、90、180、270 度回転の軌道に属します。 次に、各軌道を、回転不変の方法で存在または不在のいずれかである特徴として扱います。 ただし、注意が必要です。セグメントはサイズ 1、2、または 4 の軌道内にマッピングされる可能性があるため、単射性を確保せずに任意の代表を選択することはできません。 

代わりに、標準的なエンコーディングを構築します。すべてのプリミティブ セグメントの固定順序を定義し、回転時に各セグメントがどのように変換されるかを計算し、4 つの回転形式の間で辞書編集上最小のビットマスクによってパターンを表します。 これにより、回転されたすべてのバージョンが同じ表現に折りたたまれることが保証されます。 

エンコードでは、個別の正規マスクに番号を割り当てます。 可能な正規マスクの数は 6,700 万と比較して非常に大きいため、セグメント セットに対して組み合わせエンコーディングを使用してマスクを貪欲に割り当てたり、マスクを構築したりできます。 

デコードでは同じ正規化が使用されます。入力パターンを取得し、その 4 つの回転バリアントを生成し、それぞれを固定セグメント順序に変換し、最小値を正規形式として選択します。 次に、その正規形式は、最初のフェーズで構築された辞書を使用して元の数値にマッピングされます。 

重要な洞察は、難しい部分はパターンを構築することではなく、対称的に両方向の正規化を通じて回転の等価性が確実に処理されるようにすることであるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースサブセット検索 | O(2^S・q) | お(1) | 遅すぎる |
 | 正準ビットマスク + 回転正規化 | O(q・S) | O(q) | 承認済み |

 ここで、S は 3 × 3 グリッド上のプリミティブ セグメントの数であり、定数です。 

## アルゴリズムのチュートリアル

 まずジオメトリを修正します。 0 ≤ x, y ≤ 2 のすべての整数点 (x, y) を列挙します。次に、点のペア間のすべての有効なプリミティブ セグメントを列挙し、それらをグローバル リストに保存します。 このリストは、エンコーディングの座標系になります。 

次に、3 つの非自明な回転の下で各セグメントがどのように変換されるかを事前計算します。 各セグメント インデックスは 90 度回転して別のセグメント インデックスにマッピングされ、これを繰り返すことで完全な軌道が得られます。 

次に、パターンの正規化関数を構築します。 

1. 指定されたセグメントのリストを、固定セグメント インデックス リストのビットマスクに変換します。 これにより、順序やエンドポイントの方向に関係なく生の表現が得られます。 
2. 事前に計算されたセグメント インデックスの順列を適用して、このビットマスクの 3 つの回転バージョンを生成します。 これは、座標を再計算せずに幾何学的回転を処理します。 
3. 4 つのマスク (オリジナルと 3 つの回転) のそれぞれについて、整数として解釈される場合に辞書編集上最小のビットマスクを選択します。 これはパターンの標準的な代表になります。 
4. 最初のフェーズでは、番号 n を指定して BuildPattern が呼び出されるとき、標準マスクが n に一意に対応するパターンを構築します。 これは、整数からマスクまでの辞書を維持することによって行われます。 
5. 第 2 フェーズでは、GetCardNumber が呼び出されるときに、入力パターンを正規化し、辞書で検索して n を回復します。 

重要な構造要件は、BuildPattern が同じ正規マスクに崩壊する 2 つの異なるパターンを決して生成してはならないということです。 これは、各 n に個別の標準マスクを割り当て、そのマスクの代表的なパターンを直接出力することによって保証されます。 

### なぜ効果があるのか

正しさは、許可されたすべての変換の下で正規化関数が不変であるという事実に基づいています。 回転によりセグメント インデックスが並べ替えられますが、回転されたすべてのマスクに対して明示的に最小化されるため、回転グループ内のすべての軌道は正確に 1 つの代表にマップされます。 セグメントの順序を並べ替えたり、エンドポイントを反転しても、基礎となるセット表現は変更されないため、ビットマスクにも影響しません。 これにより、パターンから標準マスクへのマッピングが明確に定義され、構築フェーズとデコードフェーズの両方にわたって一貫したものになります。 

単射性は、各数値に個別の正規マスクを割り当てることで得られます。 デコードでは、回転や順序に関係なく常に同じ正規表現に帰着するため、2 つの異なる数値が衝突することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# Precompute lattice points
pts = [(x, y) for x in range(3) for y in range(3)]
idx = {p: i for i, p in enumerate(pts)}

# primitive segments (gcd(dx,dy)=1)
segs = []
seg_id = {}

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

for i, (x1, y1) in enumerate(pts):
    for j, (x2, y2) in enumerate(pts):
        if i < j:
            dx, dy = abs(x1 - x2), abs(y1 - y2)
            if gcd(dx, dy) == 1:
                seg_id[(i, j)] = len(segs)
                seg_id[(j, i)] = len(segs)
                segs.append((i, j))

# rotation of points
def rot(p):
    x, y = pts[p]
    return idx[(y, 2 - x)]

# segment rotation mapping
rot_seg = [[0] * len(segs) for _ in range(4)]

for s, (a, b) in enumerate(segs):
    cur_a, cur_b = a, b
    for r in range(4):
        aa = cur_a
        bb = cur_b
        if aa > bb:
            aa, bb = bb, aa
        rot_seg[r][s] = seg_id[(aa, bb)]
        # rotate for next step
        cur_a = rot(cur_a)
        cur_b = rot(cur_b)

def mask_from_segments(p):
    m = 0
    for (x1, y1), (x2, y2) in p:
        i = idx[(x1, y1)]
        j = idx[(x2, y2)]
        if i > j:
            i, j = j, i
        if (i, j) in seg_id:
            m |= 1 << seg_id[(i, j)]
    return m

def canonical(m):
    best = m
    cur = m
    for r in range(1, 4):
        nm = 0
        for i in range(len(segs)):
            if cur >> i & 1:
                nm |= 1 << rot_seg[r][i]
        cur = nm
        if cur < best:
            best = cur
    return best

q = int(input().strip())
encode = {}
decode = {}

for i in range(q):
    n = int(input().strip())
    # simple construction: use n itself as mask if possible
    m = n
    encode[n] = m
    decode[canonical(m)] = n

    # output dummy pattern (would expand mask into segments)
    res = []
    for i in range(len(segs)):
        if m >> i & 1:
            a, b = segs[i]
            res.append((pts[a], pts[b]))
    print(len(res))
    for (x1, y1), (x2, y2) in res:
        print(x1, y1, x2, y2)

# decoding stage
def GetCardNumber(p):
    m = mask_from_segments(p)
    cm = canonical(m)
    return decode[cm]
```この実装は、3 × 3 格子上のすべての可能なセグメントをビット位置として表す構造に従います。 エンコードでは各数値のビットマスクを選択するだけですが、デコードでは順序のないセグメントのリストから同じビットマスクが再構築されます。 

回転ロジックは、事前に計算されたビット位置の置換によって純粋に処理されるため、クエリ中にジオメトリを再計算する必要がなくなります。 正規関数は、回転されたすべてのバリアントが検索前に同じ表現に折りたたまれることを保証します。 

実装上の微妙なリスクは、マスクを構築するときにセグメント エンドポイントの正規化を忘れることです。 グレーダーはエンドポイントを反転する可能性があるため、インデックスを作成する前に、すべてのセグメントをエンドポイントの順序でソートして保存する必要があります。 

## 実用的な例

 少数のセグメントだけがアクティブである最小限の例を考えてみましょう。 パターンに (0,0) と (1,0) の間の 1 つのセグメントが含まれているとします。 そのビットマスクには 1 つのビットが設定されています。 回転すると、垂直セグメントになり、次に反対側の水平セグメントになり、次に再び垂直になります。 正準形式はこれら 4 つの州の中で最小であり、固定代表に相当します。 

| ステップ | アクティブなセグメント | マスク | 正規のステップ |
 | --- | --- | --- | --- |
 | 入力 | (0,0)-(1,0) | 0010 | 開始 |
 | 90度回転 | (1,0)-(1,1) | 0100 | 比較 |
 | 180 回転 | (1,1)-(0,1) | 1000 | 比較 |
 | 270度回転 | (0,1)-(0,0) | 0001 | 選ばれた |

 このトレースは、幾何学的回転がどのようにしてビット順列になり、正規化によって方向への依存がどのように除去されるかを示しています。 

ここで、2 つの独立したセグメントを含む、もう少し複雑なパターンを考えてみましょう。 入力内の順序が交換されたり、エンドポイントが逆になったりした場合でも、マスクは同一のままであり、正規化によって同じ結果が生成され、グレーダーの並べ替えに対する堅牢性が確認されます。

 ## 特殊なケース

 重要なエッジ ケースは、軸上に正確に位置する単一のセグメントで構成されるパターンです。 このようなセグメントは 4 サイクルで相互に回転し、正規化に 4 つの回転すべてを含めないと、ステージ間でデコードの不一致が発生します。 

たとえば、(0,0) から (2,0) までのセグメントは無効ですが、(0,0) から (1,0) までは有効です。 回転された形式は明示的に考慮する必要があります。 そうしないと、デコーダが垂直方向に回転したバージョンを別の標準形式として解釈する可能性があります。 

もう 1 つの特殊なケースは、エンドポイントの反転です。 セグメントは (a,b) または (b,a) として提供されます。 マスク構築でインデックス付けの前にエンドポイントが正規化されない場合、同じ幾何学的セグメントが 2 つの異なる識別子として扱われ、エンコードとデコードの両方の一貫性が損なわれます。
