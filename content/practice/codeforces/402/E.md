 ## 解決策
 ## 問題の理解

 正方行列が与えられます$a$サイズの$n \times n$その要素はすべて非負の整数です。 この行列は、次のグラフの重み付けされた隣接行列として考えることができます。$n$ノード、ここで$a_{ij} > 0$ノードからの直接のエッジを示します$i$ノードへ$j$。 

タスクは、正の整数が存在するかどうかを判断することです。$k$行列のべき乗$k$で示される$a^k$、すべてのエントリが厳密に正である行列が得られます。 これは、グラフの用語で言うと、すべてのノードが他のすべてのノードに正確に到達できるかどうかを尋ねることに相当します。$k$元のエッジによって形成されたパスに沿ったステップ。 

制約は重要です。$n$最大 2000 になる可能性があるため、明示的に計算しようとするソリューションはすべて$a^k$単純に行列を乗算することは直ちに実行不可能になります。 単一の行列の乗算は次のようになります。$O(n^3)$、これは最悪の場合でもすでに 80 億回の操作に達しており、遅すぎます。 

微妙なエッジ ケースは、切断されたノードまたはブロックから発生します。 たとえば、単位行列を考えてみましょう。```
2
1 0
0 1
```ここで、行列のべき乗は非対角要素を接続できないため、答えは「NO」です。 単純に以下のことをチェックする素朴なアプローチ$a$非ゼロ要素がある場合、行列の到達可能性構造を無視すると、誤って「YES」と表示される可能性があります。 

もう 1 つの自明ではないケースは、巡回置換です。```
3
0 1 0
0 0 1
1 0 0
```この行列は最終的に次の条件で厳密に正になります。$a^3$なぜなら、各ノードは 3 つのステップで他のすべてのノードに到達できるからです。 チェックだけをするいい加減な実装$a$または$a^2$失敗するだろう。 

この問題をグラフの到達可能性の問題として理解することが効率の鍵となります。 

## アプローチ

 ブルートフォース手法は簡単です。行列を繰り返し乗算し、各乗算の後にすべての要素が正であるかどうかを確認します。 から始める$a$、 それから$a^2$、 それから$a^3$、 等々。 すべての要素が正になるか、行列が安定した時点で停止します。 これは正しいです。行列の乗算は、長さが増加するパスの組み合わせを正確にモデル化するからです。 ただし、最悪の場合の複雑さは次のとおりです。$O(n^4)$まで乗算すると$n$各乗算は$O(n^3)$。 のために$n = 2000$、これは完全に非現実的です。 

最適なアプローチはグラフ理論を活用します。 行列を有向グラフの隣接行列として解釈します。 ゼロ以外の各エントリはエッジを示します。 グラフが **強く接続されている**場合、つまりすべてのノードから他のすべてのノードへのパスが存在する場合に限り、行列はあるべき乗で厳密に正になります。 強い接続性のチェックは、深さ優先検索 (DFS) または幅優先検索 (BFS) を 2 回 (元のグラフで 1 回、転置グラフで 1 回) 使用することで効率的に行うことができます。 これにより、複雑さが軽減されます。$O(n^2)$、すべてのエッジを走査するだけでよく、隣接行列の各走査にはコストがかかるためです。$O(n^2)$最悪の場合。 

ブルート フォースは文字通り到達可能性行列を構築するため機能しますが、乗算あたりの 3 乗コストと必要な乗算の数が不明なため失敗します。 グラフのアプローチが機能するのは、行列内の実際の数値に関係なく、強い接続性によって正のべき乗の存在が保証されるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^4) | O(n^2) | 遅すぎる |
 | グラフの接続性 | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. マトリックスから隣接グラフを構築する$a$。 あらゆる人にとって$a_{ij} > 0$、ノードから有向エッジを追加します$i$ノードへ$j$。 これにより、数値が抽象化され、到達可能性のみに焦点が当てられます。 
2. 任意のノード (たとえばノード 1) を選択し、DFS を実行して、元のグラフ内でそこから到達可能なすべてのノードをマークします。 未訪問のノードがある場合、グラフは強く接続されていないため、すぐに「NO」を返すことができます。 
3. すべてのエッジを反転してグラフの転置を作成します。 これにより、到達可能性の方向が反転します。 
4. 転置グラフ内の同じノードから DFS を実行します。 未訪問のノードがある場合、元のグラフは強く接続されていないため、「NO」を返します。 
5. 両方の DFS トラバーサルがすべてのノードを訪問した場合、グラフは強く接続されています。 これにより、何らかの正の整数が存在することが保証されます。$k$そのような$a^k$は厳密に正であるため、「YES」を返します。 

**機能する理由**: DFS チェックでは、すべてのノードが他のすべてのノードに到達できること (元のグラフ)、および他のすべてのノードからすべてのノードに到達できること (転置グラフ) が保証されます。 これら 2 つの条件を組み合わせると、まさに強力な接続が定義されます。 線形代数のペロン-フロベニウスの定理は、強く接続された非負の行列が厳密に正の累乗を持つことを保証します。これはまさに私たちが必要とするものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(5000)

def main():
    n = int(input())
    adj = [[] for _ in range(n)]
    for i in range(n):
        row = list(map(int, input().split()))
        for j in range(n):
            if row[j] > 0:
                adj[i].append(j)

    visited = [False] * n

    def dfs(v, graph):
        visited[v] = True
        for u in graph[v]:
            if not visited[u]:
                dfs(u, graph)

    # Check reachability from node 0
    dfs(0, adj)
    if not all(visited):
        print("NO")
        return

    # Check reachability in the transposed graph
    adj_t = [[] for _ in range(n)]
    for i in range(n):
        for j in adj[i]:
            adj_t[j].append(i)

    visited = [False] * n
    dfs(0, adj_t)
    if not all(visited):
        print("NO")
    else:
        print("YES")

if __name__ == "__main__":
    main()
```コードはまず行列を隣接リストに変換します。 DFS は、元のグラフと転置されたグラフの両方で、開始ノードからすべてのノードに到達できることを保証します。 時間制限内に収めるためには、行列を繰り返し乗算する代わりに隣接リストを使用することが重要です。 再帰制限を増やすと、最悪の場合のグラフで DFS の最大深さが処理されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 各 DFS はすべてのエッジを横断します。 最大 n^2 個のエッジが存在する可能性があります。 |
 | スペース | O(n^2) | 最悪の場合、隣接リストにはすべてのエッジが格納される可能性があります。 訪問された配列は O(n) を使用します。 |

 のために$n \le 2000$、アルゴリズムは最大 400 万回の操作を快適に 1 秒未満で実行します。
