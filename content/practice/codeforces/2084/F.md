 ## 問題の理解

セグメントが`[x1, x2, ..., xk, mn]`どこ`mn`がセグメント全体の最小値である場合、演算により次のように変換されます。`[mn, x1, x2, ..., xk]`。 

部分的に指定された別の置換が与えられます`c`。 一部の位置にはすでに固定値が含まれていますが、位置には固定値が含まれています。`0`まだ無料です。 完了しなければなりません`c`完全な順列に`b`次のような:

 1. ゼロ以外の位置はすべて変更されません。 
2.`b`から到達可能です`a`せいぜい使用`n`許可された操作。 

タスクは操作のシーケンスを見つけることではありません。 必要なのは、有効なターゲットの順列を構築することだけです。 

の合計`n`すべてのテストケース全体で最大でも`5 · 10^5`。 二次的な動作を伴う解決策は直ちに不可能になります。 平`O(n log^2 n)`この規模ではやや不快になるでしょう。 ターゲットの複雑さは次のとおりです。`O(n log n)`テストファイルごとに。 

難しいのは、順列を完成させることではありません。 難しいのは、どの順列がどこから到達できるかを理解することです。`a`。 

いくつかの特殊なケースは見落とされがちです。

```操作が移動する可能性があります`1`左に進むが、決して動くことはできない`2`の前に`1`。 到達可能性は非常に制限されています。 失われたすべての位置を個別に処理すると、不可能なターゲットが生成されてしまいます。

## アプローチ

 最初に理解することは、次から到達可能な順列のセットです。`a`。 

値を仮定する`x`位置にあります`pos[x]`元の順列で。 操作では、セグメントの最小要素のみを移動できます。 すべての値は個別であるため、移動された要素は常にそのセグメント内の最小値になります。 

特定の値に注目する`x`。 

いつでも`x`移動する場合、選択したセグメントの最小値でなければなりません。 つまり、交差するすべての要素が`x`よりも大きいです`x`。 したがって`x`より大きな値を横切ることはできますが、より小さな値を横切ることはできません。 

この観察はこのプロセスを完全に特徴づけています。 

させて```
p[x] = position of x in a.
```到達可能なすべての順列における、任意のペアの相対順序`(u,v)`と`u < v`そして`p[u] < p[v]`永久に固定されます。 以来`v`小さい値を越えることはできません`u`、それらの順序は決して変わりません。 

これらのペアごとの制約は、半順序を定義します。 

ブルートフォースの観点では、操作によって生成された順列の到達可能性グラフ全体が構築されます。 中程度の場合でも`n`、到達可能な状態の数は膨大になります。 単一の順列により生成される可能性があるのは、`Θ(n²)`が移動し、状態空間が階乗的に増加します。 これはまったく実現不可能です。 

重要な洞察は、到達可能な順列はまさに非常に特殊な半順序の線形拡張であるということです。 

それぞれの値について`v`、元の順列の左側にある最も近い小さい値を見つけます。 この値を親にします`v`。 

例えば：```
a = [3,5,6,2,1,4]

value: 1 2 3 4 5 6
pos  : 5 4 1 6 2 3
```親子関係は次のようになります。```
1 root
2 -> 1
3 root
4 -> 1
5 -> 3
6 -> 5
```これはまさに順列のデカルト ツリーであり、値の順序を優先して構築されています。 

基本的な事実は、到達可能なすべての順列はまさにこのフォレストのトポロジカルな順序であり、すべての親がその子の前に現れる必要があるということです。 

ここで問題は次のようになります。 

値の順列を構築する`1..n`それ

 1. すべての固定位置を尊重します。 
2. デカルト フォレストの位相的順序付けです。 

これは推論がはるかに簡単です。 

フォレストのトポロジカルな順序付けは貪欲に生成できます。 親がすでに配置されているすべてのノードはいつでも利用可能です。 

固定位置制約は、どの値が特定の位置を占める必要があるかを示します。 位置を左から右に処理します。 

位置の場合`i`値に固定されます`x`、 それから`x`現在利用可能である必要があります。 それ以外の場合は、有効な順序が存在しません。 

位置の場合`i`無料なので、現在利用可能な値を設定できます。 将来の柔軟性を最大化するには、利用可能な最大の値を選択する必要があります。 

なぜ最大なのか？ 値が小さいほど子孫のロックが解除されるためです。 小さな値を遅らせても問題はありませんが、あまりにも早く消費すると、将来の固定ポジションに衝突が生じる可能性があります。 これは、このフォレストにおける制約付きトポロジカル順序付けのための標準的な貪欲戦略です。 

結果として得られるアルゴリズムは、現在利用可能なすべてのノードを最大ヒープ内に維持します。

### なぜ効果があるのか

 デカルト フォレストは、許可された操作によって決して違反されない優先順位制約を正確にエンコードします。 

到達可能な順列はすべて、各親をそのすべての子の前に配置する必要があります。 逆に、このフォレストのすべてのトポロジー的順序付けは、許可された移動を通じて実現できます。 したがって、到達可能な順列は、まさにフォレストのトポロジカルな順序になります。 

構築中、利用可能なセットには、親がすでに出現しているノードが正確に含まれます。 利用可能なノードを選択すると、トポロジカルな順序付けを完了できる可能性が維持されます。 

固定位置の場合、必要な値がすでに使用可能である必要があります。 それが利用できない場合は、祖先の一部がまだ出現していないため、あらゆるトポロジカルな順序付けにおいてこの要件は不可能になります。 

自由なポジションの中で、利用可能な最大の値を選択することは、より小さな値を延期する貪欲な選択です。 値が小さいほど、子孫のロックが解除されるため、価値が高くなります。 それらを遅らせることは、将来の柔軟性を高めるだけです。 標準の交換引数は、解が存在する場合、選択された自由位置の値を利用可能な最大値で置き換えることで存在が維持されることを示します。 

したがって、アルゴリズムは、存在する場合は常に有効な完了を出力し、それ以外の場合は不可能であることを正しく報告します。 

## Python ソリューション```python
import sys
from bisect import bisect_left
from heapq import heappush, heappop

input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, idx, val):
        n = self.n
        bit = self.bit
        while idx <= n:
            bit[idx] = max(bit[idx], val)
            idx += idx & -idx

    def query(self, idx):
        res = 0
        bit = self.bit
        while idx > 0:
            res = max(res, bit[idx])
            idx -= idx & -idx
        return res

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        c = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for i, x in enumerate(a, 1):
            pos[x] = i

        parent = [0] * (n + 1)
        children = [[] for _ in range(n + 1)]

        fw = Fenwick(n)

        for x in range(1, n + 1):
            ppos = fw.query(pos[x])
            if ppos:
                par = a[ppos - 1]
                parent[x] = par
                children[par].append(x)
            fw.add(pos[x], pos[x])

        fixed_pos = [0] * (n + 1)
        ok = True

        for i, x in enumerate(c, 1):
            if x:
                fixed_pos[x] = i

        available = []
        active = [False] * (n + 1)

        for x in range(1, n + 1):
            if parent[x] == 0:
                active[x] = True
                heappush(available, -x)

        ans = [0] * n

        for i in range(1, n + 1):
            need = c[i - 1]

            if need:
                if not active[need]:
                    ok = False
                    break

                active[need] = False
                ans[i - 1] = need

                for y in children[need]:
                    active[y] = True
                    heappush(available, -y)

            else:
                while available and not active[-available[0]]:
                    heappop(available)

                if not available:
                    ok = False
                    break

                x = -heappop(available)
                active[x] = False
                ans[i - 1] = x

                for y in children[x]:
                    active[y] = True
                    heappush(available, -y)

        if not ok:
            out.append("-1")
        else:
            out.append(" ".join(map(str, ans)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```すべての値の位置を計算した後、コードはデカルト フォレストを構築します。 フェンウィック ツリーには、すでに処理された小さい値に属する最大の位置が格納されます。 までのプレフィックスをクエリします`pos[x]`左側の最も近い小さい値を返します。 

トポロジー構築では最大ヒープを使用します。 Python は最小ヒープのみを提供するため、値は否定されて挿入されます。 

の`active`配列は注目に値します。 ノードが使用できなくなっても、ヒープ エントリがすぐに削除されることはありません。 代わりに、古いエントリは抽出中に遅延して破棄されます。 これにより、高価な削除が回避されます。 

もう 1 つの微妙な点は、固定位置の処理です。 値は、現在アクティブな場合にのみ有効です。 未使用かどうかを確認するだけでは不十分です。 その親はすでに出現しているはずです。

 ## 特殊なケース

 検討してください```
a = [3,2,1]
c = [0,3,0]
```森は```
1 -> 2 -> 3
```位置 2 では、値 3 が要求されます。 値 3 は、1 と 2 の両方が配置されるまで使用可能になりません。 アルゴリズムは 3 が非アクティブであることを確認し、すぐに戻ります。`-1`。 

考慮する```
a = [3,2,1,5,4]
c = [3,2,1,5,4]
```どの位置も固定されています。 必要な各値は、必要なときに正確に使用できるようになります。 アルゴリズムは同じ順列を単純に再現します。 

考慮する```

c = [0,0,0,0]
```複数のトポロジカルな順序が存在します。 max-heap は、すべての空き位置で現在利用可能な最大値を選択します。 この貪欲な選択でも、選択されたすべての値が利用可能であり、より小さな値を遅らせても将来の完了が妨げられることがないため、実現可能性は維持されます。 

これらのケースは、祖先より前のノードのリクエスト、完全に固定された有効なターゲット、および多くの可能なトポロジー順序による制約のない位置などの主な障害モードをカバーしています。
