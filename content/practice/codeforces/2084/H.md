 ## 解決策
 ## 問題の理解

 バイナリ文字列から始めて、長さ 3 のウィンドウに基づいて削除ルールを繰り返し適用します。 

バイナリ トリプルの場合、中央値は単に過半数の値です。 ウィンドウを選択した後、ウィンドウの左端から始まるサフィックス内で最初に出現した多数決値を削除します。 

最終的な長さが少なくとも 2 である限り、プロセスはいつでも停止できます。 有効な一連の操作の結果として、_異なるバイナリ文字列_がいくつ出現するかを数えるよう求められます。 

最初の観察は、等しいビットの正確な位置は重要ではないということです。 重要なのは、等しい値の最大ランへの分解です。 例えば```
0011100011
```になる```
[2,3,3,2]
```ここで、各数値は最大ブロックの長さです。 

すべてのテスト ケースの合計の長さは最大でも`2 · 10^6`, したがって、二次アルゴリズムは直ちに不可能になります。 たとえ`O(n log n)`ソリューションはすでに利用可能な予算のかなりの部分を使用しています。 意図したソリューションは実行回数が線形です。 

危険なケースは、実行数が非常に少ないケースです。 

1 つの実行のみで構成される文字列の場合、次のようになります。```
11111
```すべての操作は単純に`1`。 取得できる文字列は正確な長さです`2,3,4,5`、答えを与える`4`。 少なくとも 1 つの代替が存在することを前提とした解決策は、ここでは失敗します。 

ちょうど 2 回の実行の場合、次のように```
000111
```唯一の自由は、各実行でどれだけのシンボルが生き残るかです。 答えは 2 つのランレングスの積になります。 特別な取り扱いが必要です。 

## アプローチ

 ブルート フォース検索では、到達可能なすべての文字列が状態として扱われます。 各状態からすべての有効なウィンドウを試し、考えられるすべての子孫を再帰的に生成します。 

これは文字通り到達可能性グラフを調査するものであるため、これは正しいです。 残念なことに、州の数は指数関数的に増加しています。 数十の長さの文字列であっても、検索は絶望的になります。 

重要な構造上の観察は、操作によって新しい値が決して作成されないということです。 既存の実行を短縮するだけです。 文字列をランレングスに圧縮した後```
a1, a2, ..., am
```問題全体がランレングスのカウント問題になります。 

削除ルールを注意深く分析すると、実行は圧縮表現内の同じパリティの実行とのみ対話できることがわかります。 これにより、到達可能性関係が実行インデックス間の単調なマッチング プロセスに変わります。 結果として得られる動的プログラミングの状態は、元の文字列の位置ではなく、実行分解のみに依存します。 

この DP の直接実装は次のとおりです。`O(m²)`。 クリティカルな移行では、フォームの量を支配する次の実行が繰り返し要求されます。```
a[i] - floor(i/2)
```これは単調な構造を示唆しています。 ランを右から左に処理し、単調なスタックを維持することにより、高価なすべてのトランジションをインターバル加算に圧縮できます。 DP は線形になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース到達可能性 | 指数 | 指数 | 遅すぎる |
 | ランレングス DP + モノトーン スタック | O(m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 圧縮を実行する

 バイナリ文字列を最大の等しいセグメントの長さに変換します。 

例えば、```
001000111
```になる```
[2,1,3,3]
```実行回数を次のようにします`m`。 

### 特殊なケース

 1. もし`m = 1`、答えは`n - 1`。 
2. もし`m = 2`、答えは`a[1] · a[2]`。 

これらのケースは、上で説明した縮退構造に対応します。 

### 次に有力なランを構築する

 1. パリティごとに、インデックスを右から左に個別に処理します。 
2. 次の順序で単調なスタックを維持します。```
a[i] - floor(i/2)
```1. しましょう`nxt[i]`現在の値よりも優先される値を持つ同じパリティで後で最初に実行されるもの。 

これはまさに正式な実装で使用される構造です。 

### 動的プログラミング

 1. しましょう`f[i]`アクティブ フロンティアが実行される到達可能な圧縮状態の数を示します`i`。 
2. 差分配列の値`d[i]`多くの同一の遷移によって生成される間隔加算を実行するために使用されます。 
3. 処理実行時`i`、その後の到達可能なすべての実行にその寄与を伝播します。 モノトーン スタック リンクは、2 次数の遷移を圧縮します。 
4. 残りのサフィックスが正しいパリティを持つすべての州が答えに貢献します。 
5. 最終実行は、圧縮状態によって表される具体的な文字列の数に独立して寄与するため、累積カウントに最後の実行のサイズを掛けます。 

### 2 つの方向

 1. 元の実行アレイで DP を 1 回実行します。 
2. 最初のランを削除し、新しい最初のランの長さを次のように置き換えた後、再度実行します。`1`。 
3. 2 つの結果を剰余として加算します。`10^9 + 7`。 

これは、削除プロセスで左側の境界が動作する可能性がある 2 つの方法を説明しています。 公式ソリューションは、これら 2 つの DP 評価を正確に計算し、それらを合計します。 

### なぜ効果があるのか

 実行圧縮後、到達可能なすべての文字列は、各実行がどれだけ短縮されるかによってのみ決定されます。 削除ルールはランの交互パターンを保存し、その長さのみを変更します。 DP は、実行可能なすべての短縮パターンを列挙します。 

数量```
a[i] - floor(i/2)
```等しいパリティの実行間に優勢順序を誘導します。 支配的なランを横切るトランジションは、最初の支配的なランへのトランジションとマージできます。 モノトーン スタックはこの情報を正確に記録するため、到達可能な状態を失うことなく間隔の集計が可能になります。 すべての有効な短縮パターンは 1 回だけカウントされるため、DP カウントは取得可能な個別のバイナリ文字列の数と等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def solve_case(s):
    n = len(s)

    a = []
    i = 0
    while i < n:
        j = i
        while j + 1 < n and s[j + 1] == s[i]:
            j += 1
        a.append(j - i + 1)
        i = j + 1

    m0 = len(a)

    if m0 == 1:
        return n - 1

    if m0 == 2:
        return a[0] * a[1] % MOD

    def calc(arr):
        m = len(arr) - 1  # 1-indexed

        nxt = [0] * (m + 1)
        stk = []

        for start in (m if m & 1 else m - 1,
                      m - 1 if m & 1 else m):

            stk.clear()
            for i in range(start, 0, -2):
                cur = arr[i] - i // 2
                while stk and arr[stk[-1]] - stk[-1] // 2 < cur:
                    stk.pop()
                nxt[i] = stk[-1] if stk else 0
                stk.append(i)

        f = [0] * (m + 3)
        d = [0] * (m + 3)

        f[1] = arr[1]
        for i in range(3, m, 2):
            f[i] = 1

        ans = 0

        for i in range(1, m):
            if i >= 3:
                d[i] = (d[i] + d[i - 2]) % MOD

            f[i] = (f[i] + d[i]) % MOD

            j = i + 1
            x = 0

            while j < m:
                k = nxt[j] if nxt[j] else m

                f[j] = (f[j] + f[i] * (arr[j] - x)) % MOD

                x = arr[j] + (k - j) // 2 - 1

                d[j + 2] = (d[j + 2] + f[i]) % MOD
                d[k] = (d[k] - f[i]) % MOD

                j = k

            if ((m - i) & 1):
                ans = (ans + f[i]) % MOD

        return ans * arr[m] % MOD

    arr = [0] + a

    ans = calc(arr)

    b = [0] + a[1:]
    b[1] = 1

    ans = (ans + calc(b)) % MOD
    return ans

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        s = input().strip()
        out.append(str(solve_case(s)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```実装は公式の線形ソリューション構造に従います。 圧縮実行フェーズでは、バイナリ文字列を最大セグメントに変換します。 1 回および 2 回の実行の特殊なケースは、カウント式が閉じた形式であるため、すぐに処理されます。 

モノトーンスタック構造は次のように計算します。`nxt[i]`パリティごとに個別に。 これは非常に重要です。 奇数インデックスと偶数インデックスを混合すると、優勢特性が破壊され、不正確な遷移が発生します。 

DP は差分配列を使用します。 アップデート```
d[l] += value
d[r] -= value
```パリティ サブシーケンス全体に適用される寄与を表します。 一致するパリティ位置に沿ってのみプレフィックスの蓄積を伝播することを忘れることは、バグの一般的な原因です。 

すべての算術はモジュロで実行されます`10^9 + 7`。

 検討してください```

```実行分解は次のとおりです。`[3]`。 すべての操作で 1 つ削除されます`1`、取得可能な唯一の最終文字列の長さは 2 です。 アルゴリズムはすぐに戻ります`n - 1 = 2`、取得可能な 2 つの長さに一致します`{2,3}`。 

考慮する```
6
000111
```分解は`[3,3]`。 到達可能な文字列は、残りの 0 と 1 の数によってのみ決まります。 がある`3 · 3 = 9`可能性があり、正確に 2 回の実行式によって返される値です。 

考慮する```
5

```すべての実行の長さは 1 です。 単純な推論では、実行を大幅に短縮することはできないため、結果がほとんど存在しないと想定することがよくあります。 DP は、パリティ ベースの遷移を通じてこの構成を正しく処理し、到達可能なすべての圧縮状態を 1 回だけカウントします。
