 ## 解決策
 ## 問題の理解

 部分的に満たされた長さの順列が与えられています$n$、一部のエントリはゼロであり、欠落している数値を表します。 目標は、残りの数字でゼロを埋めることです。$1$に$n$完全な順列を形成します。 完全な順列が得られたら、「美しさ」スコアを定義します。 美しさは関数のすべての連続した部分配列の合計です$f$、そのサブ配列での 2 人プレイ ゲームの結果を表します。 

ゲームでは、タートルが最初に移動して最初の要素を最大化したいのに対し、ピギーは次に移動してそれを最小化したいと考えています。 タートルの番でインデックスを選択します$i$そして置き換えます$c_i$最小限の$c_i$そして$c_{i+1}$、削除$c_{i+1}$。 Piggy も同じことをしますが、置き換えます$c_i$最大で$c_i$そして$c_{i+1}$。 部分配列の長さが 1 になるとゲームは終了し、$f(c)$最後の要素です。 

制約により許可される$n$最大 5000 および最大 1000 のテスト ケース、ただしすべてのテスト ケースの合計$n$すべてのテスト ケースの数は最大でも 5000 です。これは、おおよそ次のようなアルゴリズムが必要であることを意味します。$O(n^2)$最悪の場合でもテストケースごとに、$O(n^3)$遅すぎるでしょう。 エッジ ケースには、完全に空の配列 (すべてゼロ)、すでに完成している配列 (ゼロなし)、または中央にゼロがある配列が含まれます。 考えられるゼロの埋め込みをすべて試すという単純なアプローチは、すぐに失敗します。$n!$考慮すべき順列。 

## アプローチ

 ブルートフォースアプローチでは、ゼロを埋めて計算するためにあらゆる方法が試行されます。$f(c)$すべてのサブ配列に対して。 コンピューティング$f(c)$単純にゲームのシミュレーションが必要ですが、それ自体は部分配列の長さにおいて線形です。 すべての部分配列を合計するには、$O(n^3)$すべての詰め物を列挙すると、数値が欠落する原因となります。 これは明らかに実行不可能です。 

重要な洞察は、ゲームの仕組みを理解することです。 どの部分配列でも、Turtle は最初に移動し、最小値を取ることによってのみ数値を減らすことができますが、Piggy は最大値を取ることによって数値を増やすことができます。 これは、リスト上の「ミニマックス」ゲームを思い出させます。 配列を逆にして、min/max 演算を交互に行い、部分配列の最初の要素として各数値の寄与を計算すると、パターンが現れます。数値が降順でソートされている場合、Turtle は常に、より大きな数値から始まる部分配列でより大きな寄与を確保できます。 これにより、問題は動的計画問題に帰着します。つまり、特定の部分配列について、Turtle が最も利益を得る場所に利用可能な最大の数値を配置すると、欠損数値の寄与が最大化されます。 

このソリューションでは、動的プログラミングを使用して次の合計を計算します。$f(c)$すべてのサブ配列に対して、合計の寄与を最大化する位置に欠落している数値を配置する貪欲な戦略と組み合わせます。 すべての部分配列を反復処理し、未知のものを変数として扱い、貪欲に埋めることで、$O(n^2)$アルゴリズム。

 ## アルゴリズムのチュートリアル

 1. まず、指定された順列から欠落している数値を抽出します。 タートルが最初に動くほど、数値が大きいほど美しさに寄与するため、降順でソートされたリストに格納します。 
2. 2D 配列を初期化する`dp[i][j]`～の最大合計を表す$f(c)$サブアレイ用`b[i:j+1]`。 最初に設定するのは、`dp[i][i] = b[i]`長さ 1 の部分配列は独自の値を提供するためです。 
3. 長さが 1 より大きい部分配列の場合は、次の繰り返しを使用します。 

- タートルの番（部分配列の長さによって交互）の場合、タートルは適用後に値を最大化するインデックスを選択します。`min(c_i, c_{i+1})`。 満たされたサブアレイの場合、これは、最適な再生を考慮するときに、2 つの端の最小値を取ることと同じです。 
- Piggy の番の場合、彼は次の値を最小化するインデックスを選択します。`max(c_i, c_{i+1})`。 同様に、これは、最適な遊びの下で 2 つのエンドの最大値を取ることになります。 
- 実際には、ゲームはミニマックス構造になるため、最適な値は`f(c)`は`c_1`Turtle が奇数長の配列で最初に移動する場合、または`max/min`さもないと。 これによりコンピューティングが可能になります`dp[i][j]`与えられた O(1) で`dp[i][j-1]`そして`dp[i+1][j]`。 
4. 元の配列のゼロを残りの最大の数値で貪欲に埋めます。 配列を左から右に走査します。 ゼロが表示された場合は、使用可能な最大の数値を入力します。 これにより、Turtle は左から始まるより多くのサブアレイで恩恵を受けることができ、全体的な美しさが向上します。 
5. 埋めた後、すべての部分配列を反復処理して合計します。`f(c)`単純化されたミニマックス再帰を使用します。 結果を保存する場所`dp[i][j]`再計算を避けるため。 
6. すべてを合計する`dp[i][j]`値を使用して、塗りつぶされた順列の全体的な美しさを取得します。 

機能する理由: タートルは常に最初に移動するため、左側の数値が大きいほど、より多くのサブ配列でより高い寄与が生成されます。 Piggy はそれらを完全に無効にすることはできず、ミニマックス構造により、ゼロを利用可能な最大の数値で埋めることにより、すべての部分配列の合計が最大化されます。 DP は、各サブ配列の最適な寄与が正確に 1 回カウントされることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def compute_beauty(n, a):
    missing = sorted([x for x in range(1, n+1) if x not in a], reverse=True)
    b = a[:]
    idx = 0
    for i in range(n):
        if b[i] == 0:
            b[i] = missing[idx]
            idx += 1

    dp = [[0]*n for _ in range(n)]
    for i in range(n):
        dp[i][i] = b[i]

    for length in range(2, n+1):
        for i in range(n-length+1):
            j = i + length - 1
            if (length % 2) == 0:  # Piggy's turn (even)
                dp[i][j] = max(dp[i][j-1], dp[i+1][j])
            else:  # Turtle's turn (odd)
                dp[i][j] = min(dp[i][j-1], dp[i+1][j])

    total = sum(dp[i][j] for i in range(n) for j in range(i, n))
    return total

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(compute_beauty(n, a))
```まず欠落している番号を特定し、貪欲に配置します。 DP テーブル`dp[i][j]`店舗`f(c)`サブ配列ごとに。 タートルのターンから始まる奇数長のサブ配列は可能な限り最小のオプションを取り、偶数長のサブ配列は最大のオプションを取ります。 最後に全体をまとめると、`dp[i][j]`美しさを生み出します。 境界の処理は、長さを 2 から n まで反復することによって慎重に行われます。
