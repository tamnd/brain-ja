 ## 解決策
 ## 問題の理解

 単一の整数が与えられます$n$、冥王星の推定半径をマイル単位で表します。 問題は、この値が冥王星が特定の幾何学的要件の下で惑星として認定されるのに十分な大きさであるかどうかです。 

この要件は、固定参照オブジェクト、つまり半径 1000 マイルの「星」との比較に基づいています。 冥王星は円としてモデル化され、星は五芒星として扱われます。 冥王星の資格を得るための条件は、半径が円であることです。$n$星を完全に含むのに十分な大きさでなければなりません。 簡単に言うと、冥王星の半径は、星が完全にその中に収まることを保証するしきい値以上でなければなりません。 

したがって、タスクは次のことを決定することになります。$n$星を囲むために必要な最小半径を満たすか、それを超えています。 

唯一の入力はこの整数です$n$、出力は二者決定です。冥王星が惑星として認められる場合は「YES」を出力し、そうでない場合は「NO」を出力します。 

制約$1 \leq n \leq 10^9$これは、ソリューションが一定時間で実行される必要があることを意味します。 幾何学的シミュレーションや星型の反復構築を試みるソリューションは、たとえ入力サイズ自体が十分に小さいため、正確さが唯一の本当の課題であるとしても、不必要であり、遅すぎるでしょう。 

エッジケースは限られていますが、それでも注目に値します。 いつ$n = 1000$, 冥王星はまさにその基準点にあるので、受け入れられるはずです。 いつ$n < 1000$など1個単位でも$n = 999$、答えは拒否でなければなりません。 ここで最もよくある間違いは、厳密な不等式を間違った方向に使用すること、または平等が許可されることを忘れることです。 

## アプローチ

 素朴な解釈では、五芒星の実際の幾何学形状を推論し、その境界円を正確に計算しようとします。 それには、頂点座標の導出、中心からの距離の計算、そして冥王星の半径との比較が含まれます。 数学的には実現可能ですが、この問題はすでに重要な洞察を提供しているため、この問題は不要です。つまり、星の有効収容半径は 1000 マイルに固定されています。 

ブルートフォース手法では、星の形状をシミュレートまたは再構築し、すべての極値点を計算して、最小の包囲円半径を決定します。 これには、定数要素を多く使用するジオメトリ操作と浮動小数点比較が含まれます。 入力サイズは無関係ですが、実装の複雑さは高く、数値安定性のリスクが生じます。 

重要な単純化は、星の大きさがすでに 1 つのスカラーしきい値 (1000 マイル) に要約されていることを認識することです。 それが受け入れられると、幾何学的な問題全体が、次のような直接比較に崩壊します。$n$そして1000。 

したがって、ジオメトリを計算する代わりに、指定された半径をしきい値と比較するだけです。 もし$n \geq 1000$、冥王星が該当します。 それ以外の場合はそうではありません。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$n$入力から。 これは冥王星の推定半径です。 
2. 比較する$n$1000 は、星を完全に含むために必要な最小半径です。 
3. もし$n \geq 1000$の場合、冥王星の円は包含条件を満たすのに十分な大きさであるため、「YES」が出力されます。 
4. それ以外の場合は、円が小さすぎて星を完全に含めることができないため、「NO」を出力します。 

### なぜ効果があるのか

 この問題は、すべての幾何学的複雑さを 1 つのしきい値条件に落とし込みます。 この星に必要な包囲は完全に半径 1000 によって特徴付けられます。つまり、半径 1000 未満の円は星を完全に囲むことができませんが、半径 1000 以上の円は完全に囲むことができます。 このアルゴリズムは、近似や変換を行わずにこの定義条件を直接評価するため、正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

if n >= 1000:
    print("YES")
else:
    print("NO")
```このソリューションは 1 つの整数を読み取り、1 つの比較を実行します。 重要な実装の詳細は、「少なくとも 1000 と同じくらい大きい」という条件によって等価性が明示的に許可されているため、比較が包括的であることを保証することです。 

ループや追加の解析は必要ありません。 この単純さは意図的なものです。追加のロジックは、1 つずつずれたり、書式設定の間違いが発生する可能性をもたらすだけです。

 ## 特殊なケース

 唯一意味のあるエッジ動作は、しきい値 1000 付近です。 

入力用$n = 999$、アルゴリズムは値を読み取り、評価します。$999 \geq 1000$これは false であるため、「NO」が出力されます。 これは円が不十分であることを正しく反映しています。 

入力用$n = 1000$、比較は次のようになります$1000 \geq 1000$これは true と評価され、「YES」が生成されます。 これにより、平等性が有効な包含として扱われることが確認されます。 

次のような大きな値の場合$n = 10^9$の場合、比較は Python でのオーバーフローや精度の問題のない単純な整数チェックのままであり、入力範囲全体にわたって一貫した正確性が保証されます。
