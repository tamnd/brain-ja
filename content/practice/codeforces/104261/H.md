 ## 解決策
 ## 問題の理解

 空から始まり時間の経過とともに拡張される成長文字列を維持しています。 各更新操作では新しい部分文字列が末尾に追加され、場合によっては現在の完全な文字列についてのクエリが求められることがあります。 クエリごとに、これまでに構築された文字列全体の最小期間を決定する必要があります。 

ここでのピリオドは長さを意味します$p$長さの接頭辞を取ると$p$それを十分な回数繰り返すと、文字列全体を正確に再構築できます。 最後の繰り返しは部分的である可能性があるため、最後の文字列内のすべての文字が、繰り返されるプレフィックス パターン内の対応する文字と一致することのみを必要とします。 

入力の構造により、文字列が段階的に増加します。 これにより、すべての操作で追加される合計長は次の制限を受けるため、完全な文字列に依存する場合、各追加後に高価な事前計算を最初から再構築することが除外されます。$2 \cdot 10^5$、クエリの数は最大です。$10^3$。 クエリごとに線形または線形に近い構造を再計算するソリューションでも、十分に効率的であれば全体としては許容されますが、クエリごとに 2 次の構造はすぐに失敗します。 

単純な解釈では、クエリが表示されるたびに、考えられるすべてのプレフィックス長をスキャンして最小期間を最初から再計算することになります。 このアプローチは論理的には安全ですが、文字列が長さに達すると遅くなりすぎます。$10^5$、各クエリにコストがかかるため、$O(n)$、につながる$O(Nn)$全体として、到達できる$10^8$最悪の場合は操作が可能であり、1 秒の制約の下では Python では境界線に達するか安全ではありません。 

単純なプレフィックス チェックの微妙な失敗例は、文字列の反復性が高いものの、初期段階では完全に周期的ではない場合に発生します。 たとえば、次のような文字列を考えてみましょう。`abababx`。 単純なアルゴリズムでは、すべての位置を適切にチェックせずに 2 作品のような短い期間を誤って結論付ける可能性があり、完全な一貫性ではなく可分性のみをチェックすると、誤って再計算される可能性があります。 

重要な問題は、文字列が動的であることです。 すべてを最初から再計算せずに、追加操作で周期性情報を維持する方法が必要です。 

## アプローチ

 ブルートフォース手法は簡単です。 追加するたびに、現在の文字列を取得し、1 から 2 までのすべての可能な期間の長さを試します。$n$。 候補者ごとに$p$、すべての位置かどうかを確認します$i$満足する$s[i] = s[i \bmod p]$。 それが成立する場合、そのような最小のものを返します$p$。 

これは、期間の定義を直接テストするため、正しいです。 ただし、それぞれの検証には費用がかかります$O(n)$、そして私たちはそれを最大で行います$n$候補者、与える$O(n^2)$クエリごとに。 と$n$潜在的に到達する$2 \cdot 10^5$累積的に、これは実行不可能になります。 

重要な観察は、周期性がプレフィックス関数構造、特に KMP で使用される故障関数によって支配されるということです。 文字列の最小ピリオドは、その最長の境界線から導き出すことができます。ここで、境界線は接頭辞であり、接尾辞でもあります。 プレフィックス関数の値がわかっている場合$\pi[n-1]$の場合、最小の期間は次のようになります。$n - \pi[n-1]$、それが分割することを条件に$n$それ以外の場合、ピリオドは$n$。 

重要な構造的洞察は、これを最初から再計算する必要がないということです。 prefix-function は、文字を追加するときに段階的に更新できます。 新しいキャラクターはそれぞれ、償却方式で KMP オートマトンを拡張します。$O(1)$、クエリごとに即座に答えを計算するために必要な情報をすべて維持します。 

したがって、周期構造を再計算する代わりに、成長する文字列に対して KMP 失敗関数を維持します。 追加するたびに最後のプレフィックス関数の値が更新され、各クエリは現在の最小期間を直接読み取ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$クエリごと |$O(n)$| 遅すぎる |
 | インクリメンタル KMP |$O(1)$追加/クエリごとに償却 |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 文字列とそのプレフィックス関数配列は、文字列が大きくなるにつれて維持されます。 

1. 空の文字列と空のプレフィックス関数リストを初期化します。 プレフィックス関数は、位置ごとに、その位置までのサフィックスでもある最長の適切なプレフィックスの長さを追跡します。 
2. すべての追加操作では、KMP オートマトンに追加されているかのように、各文字を 1 つずつ処理します。 各文字について、前の値とフ​​ォールバック リンクを使用してそのプレフィックス関数の値を計算します。 これにより、文字列を再度スキャンするのではなく、すでに計算された境界情報を再利用できるようになります。 
3. 新しい文字のプレフィックス関数を計算するとき、一致するものが見つかるかゼロに達するまで、以前に計算されたプレフィックス値を使用して繰り返しフォールバックします。 各フォールバックにより候補境界の長さが減少するため、このステップはコア効率の向上となります。 
4. 新しい位置の正しいプレフィックス関数値が計算されたら、それを配列に追加して続行します。 これにより、現在の文字列長までのすべての境界情報の正確さが維持されます。 
5. クエリが到着すると、現在の文字列長を使用して最小期間を計算します。$n$および最後のプレフィックス関数の値$\pi[n-1]$。 候補期間は、$p = n - \pi[n-1]$。 
6. もし$n \bmod p = 0$、 それから$p$は最小の期間です。 それ以外の場合、文字列全体がそれ以上の繰り返し構造を持ち、答えは次のようになります。$n$。 

これが機能する主な理由は、$\pi[n-1]$文字列全体の最長の境界線をキャプチャします。 有効なピリオドはすべてボーダー構造と一致する必要があり、最小の繰り返し単位は正確に文字列の長さから最長のボーダーを引いたものになります。 

### なぜ効果があるのか

 プレフィックス関数は、すべての位置で、現在のプレフィックスのサフィックスでもある最長の適切なプレフィックスを保存します。 これは、文字列に繰り返し構造がある場合、それが境界チェーンとして現れることを意味します。 最小の繰り返しブロックは、文字列全体から可能な限り最大の境界線を削除することに対応します。 残りの長さが全長を割った場合、このブロックを繰り返すことで文字列が正確に再構築されます。 それ以外の場合、より小さい繰り返しはプレフィックスとサフィックスの両方の制約に一貫して一致することができないため、全長が唯一の有効な期間になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = []
pi = []

def add_char(c):
    i = len(s)
    s.append(c)
    j = pi[i - 1] if i > 0 else 0

    while j > 0 and s[j] != c:
        j = pi[j - 1]

    if i > 0 and s[j] == c:
        j += 1

    pi.append(j)

def solve_period():
    n = len(s)
    if n == 0:
        return 0
    p = n - pi[-1]
    if n % p == 0:
        return p
    return n

def main():
    n = int(input())
    for _ in range(n):
        parts = input().strip().split()
        if parts[0] == '0':
            for ch in parts[1]:
                add_char(ch)
        else:
            print(solve_period())

if __name__ == "__main__":
    main()
```この実装では、文字列自体とそのプレフィックス関数という 2 つの配列が維持されます。 の`add_char`ルーチンは直接増分 KMP 移行です。 変数`j`は現在の最良の境界候補を表し、一致が見つかるまで、以前に計算されたプレフィックス値を使用して繰り返しフォールバックします。 これにより、プレフィックス全体の再スキャンが回避されます。 

クエリ関数は、prefix-function と最小期間の間の標準的な同一性を使用します。 引き算`n - pi[-1]`候補ブロック サイズが生成され、割り算チェックにより繰り返しが正確であることが保証されます。 

よくある落とし穴は、接頭辞関数を追加されたセグメントごとではなく、連結された文字列全体にわたって計算する必要があることを忘れていることです。 もう 1 つの微妙な点は、追加された部分文字列全体を単一の KMP トランジションとして扱うのではなく、各文字を個別に処理する必要があることです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s = []
    pi = []

    def add_char(c):
        i = len(s)
        s.append(c)
        j = pi[i - 1] if i > 0 else 0
        while j > 0 and s[j] != c:
            j = pi[j - 1]
        if i > 0 and s[j] == c:
            j += 1
        pi.append(j)

    def solve():
        n = len(s)
        p = n - pi[-1] if n else 0
        return p if n % p == 0 else n

    out = []
    q = int(input())
    for _ in range(q):
        parts = input().split()
        if parts[0] == '0':
            for ch in parts[1].strip():
                add_char(ch)
        else:
            out.append(str(solve()))
    return "\n".join(out)

assert run("3\n0 abab\n1\n0 ab\n1\n") == "2\n2"

 ## 特殊なケース

 単一文字の文字列は、接頭辞関数の基本動作を示します。 入力が`0 a`クエリが後に続くと、prefix-function はゼロのままであるため、計算された期間は次のようになります。$1 - 0 = 1$、長さを割ると答え1が得られます。 

次のような非反復文字列`abcdef`は、prefix-function がゼロで終わることを示しています。 計算された期間は次のようになります。$6$、より小さい約数が一致しないため、出力は全長になります。 

次のような完全に周期的な文字列`abcabcabc`各繰り返しの終わりに大きな境界線が生成され、プレフィックス関数は 6 で終了します。計算された周期は 3 になり、割り切れないため、繰り返し構造が正しく検出されたことが確認されます。
