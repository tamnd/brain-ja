 ## 解決策
 ## 問題の理解

 それぞれに必要なしきい値が設定された人々の列が与えられます。 マイクは限られた数の割引チケットを所有しており、各チケットを列の最大 1 人に割り当てることができます。 チケットの効果はローカルではありません: チケットがポジションに与えられた場合`i`、後の人が開始者の要件以下の要件を持っている限り、連続するポジションを通じて自動的に前方に伝播します。 厳密に大きな要件を持つ人に遭遇するとすぐに伝播は停止します。 

目標は、最大でも`D`直接または伝播を通じて割引を受ける個別の人の総数が最大化されるようにチケットを作成します。 

入力サイズは最大で`N = 100000`これにより、開始位置のすべてのサブセットを試行したり、選択ごとに繰り返し伝播をシミュレートしたりするソリューションは直ちに除外されます。 考えられるすべてのチケット配置に対する 2 次スキャンでさえ遅すぎます。`D`最大でも 100 ですが、`N`は大きいため、構造を慎重に利用する必要があります。 

微妙なエッジケースは、伝播の重なりから発生します。 2 つのチケットが交差またはネストされたセグメントに展開される場合、重複を誤ってカウントすると、答えが膨らんだり小さくなったりする可能性があります。 たとえば、2 つのチケットが両方とも、減少するサフィックスの同じプレフィックス上で展開される場合、単純なカウントでは、すでに 1 回割引されているにもかかわらず、対象となるポジションが 2 重にカウントされてしまいます。 

もう 1 つの特殊なケースは、単調配列です。 配列が厳密に増加している場合、開始点を超える伝播は存在しないため、各チケットは 1 人のみをカバーします。 厳密に減少する配列では、1 つのチケットでサフィックス全体をカバーできますが、最初の完全なカバーの後は追加のチケットによるメリットはありません。 

## アプローチ

 強引なアイデアは、選択することです`D`開始位置を確認し、各選択の伝播をシミュレートします。 選択した位置ごとに、伝播条件が崩れるまで前方にスキャンし、カバーされるすべてのインデックスをマークします。 選択したすべての開始を処理した後、マークされたインデックスの数を数えます。 

これは伝播ルールを直接実装しているため、これは正しいです。 ただし、その複雑さは法外です。 選択する`D`ポジションコスト`O(N^D)`可能性があり、たとえ小さなものであっても、`D`これは爆発します。 開始点を修正してカバレッジを効率的にシミュレートしたとしても、各シミュレーションは最大で次の範囲までスキャンする可能性があります。`O(N)`、につながる`O(DN)`構成ごとに異なりますが、すべての組み合わせを列挙することはまだ不可能です。 

重要な観察点は、各チケットがその開始位置によって一意に決定されるセグメントを作成するということです。セグメントは、シーケンスが厳密に開始値より大きくなる次の位置まで拡張されます。 このように問題を捉えると、それぞれの立場が`i`決定的な間隔を定義します`[i, r[i]]`。 問題は最大でも選択になります`D`組合の適用範囲を最大化する間隔。 ただし、標準の間隔スケジューリングとは異なり、間隔は選択した開始点に依存しますが、事前に計算されると複雑な方法で構造的に相互作用することはありません。 

これにより、動的プログラミング ソリューションが可能になります。左から右に処理し、各位置でチケットを開始するかスキップするかを決定します。 以来`D ≤ 100`、使用したチケットの数とラインをどれだけカバーしたかを追跡する DP を定義できます。 カバレッジは単調で前進するため、状態を圧縮できます。 

インデックスごとに事前計算します`i`到達可能な最も遠いエンドポイント`r[i]`単純な順方向スキャンを使用するか、単調構造をより効率的に使用します。 次に、DP トランジションは、到達可能な最良のカバレッジを維持しながら、開始の選択またはスキップをシミュレートします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | O(N^D) | O(N) | 遅すぎる |
 | 最適 | O(ND) | O(ND) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのポジションの事前計算`i`最も遠いインデックス`r[i]`すべての要素が`i`に`r[i]`以下である`M[i]`。 これは、チケットを配置した場合の完全な効果を定義します。`i`。 このステップでは、動的伝播ルールを静的間隔に変換します。 
2. 動的プログラミングテーブルを定義する`dp[k][i]`プレフィックス内の対象となる人の最大数を表します`0..i`正確に使用して`k`チケット。 このように構成しているのは、各チケットが 1 つの間隔に寄与しており、重複を考慮する必要があるためです。 
3.初期化`dp[0][i] = 0`みんなのために`i`, チケットには何もカバーされていないためです。 
4. 位置を左から右に繰り返します。 それぞれのポジションで`i`では、チケットを置かないという 2 つの選択肢を検討します。`i`、または配置します。 
5. チケットを発券しなかった場合`i`、 それから`dp[k][i]`～から引き継ぐ`dp[k][i-1]`。 これにより、以前の適用範囲の決定が保存されます。 
6. チケットを発券した場合`i`、次の範囲までのすべてのインデックスがカバーされます。`r[i]`。 更新します`dp[k+1][r[i]]`使用して`dp[k][i-1] + (r[i] - i + 1)`。 これにより、新しいセグメントの寄与が追加されます。 直接ジャンプする理由`r[i]`間のすべてがそれですか`i`そして`r[i]`は完全にカバーされ、間隔内でさらなる意思決定を行う必要はありません。 
7. すべての位置を処理した後、答えはすべての位置の最大値になります。`dp[k][i]`どこ`k ≤ D`。 

### なぜ効果があるのか

 The key invariant is that every state`dp[k][i]`正確に使用して可能な限り最高のカバレッジを表します`k`重複しないチケットはプレフィックス内で始まり、`i`。 Because each ticket expands into a fixed maximal interval starting at its chosen index, any optimal solution can be seen as a set of disjoint or overlapping intervals whose contributions are counted exactly once when the interval is first created. The DP enforces that each interval is accounted for at its starting point and never revisited, preventing double counting while preserving all valid combinations of starts.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    a = list(map(int, input().split()))

    r = [0] * n

    # compute farthest reach for each i
    for i in range(n):
        mx = a[i]
        j = i
        while j + 1 < n and a[j + 1] <= mx:
            j += 1
        r[i] = j

    # dp[k][i] = best coverage using k tickets up to i
    dp = [[0] * n for _ in range(d + 1)]

    for k in range(d + 1):
        for i in range(n):
            if i > 0:
                dp[k][i] = max(dp[k][i], dp[k][i - 1])

            if k < d:
                start_prev = dp[k][i - 1] if i > 0 else 0
                reach = r[i]
                gain = reach - i + 1
                if i > 0:
                    dp[k + 1][reach] = max(dp[k + 1][reach], start_prev + gain)
                else:
                    dp[k + 1][reach] = max(dp[k + 1][reach], gain)

    ans = 0
    for k in range(d + 1):
        ans = max(ans, max(dp[k]))

    print(ans)

if __name__ == "__main__":
    solve()
```コードは最初に伝播境界を計算します。`r[i]`条件が満たされている間、貪欲に右に拡張することで、`a[j] ≤ a[i]`が成立する。 これは、チケットがどこまで配置されるかのルールを直接エンコードします。`i`ラインに影響を与える可能性があります。 

次に、DP テーブルは、チケットの数ごとに達成可能な最良のカバレッジを追跡します。 位置をスキップする遷移では以前の結果が引き継がれ、最適な部分解が失われないことが保証されます。 チケットを配置するトランジションはエンドポイントに直接ジャンプします`r[i]`これは、すべての中間位置が同じ操作で消費されることを反映しています。 

微妙な詳細は、次のように更新されることです。`dp[k+1][r[i]]`の値を使用する必要があります`dp[k][i-1]`、 ない`dp[k][i]`そうでないと、同じリージョンから始まる複数のチケットが連鎖し、過剰にカウントされる危険があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, d = map(int, input().split())
    a = list(map(int, input().split()))

    r = [0] * n
    for i in range(n):
        mx = a[i]
        j = i
        while j + 1 < n and a[j + 1] <= mx:
            j += 1
        r[i] = j

    dp = [[0] * n for _ in range(d + 1)]

    for k in range(d + 1):
        for i in range(n):
            if i > 0:
                dp[k][i] = max(dp[k][i], dp[k][i - 1])
            if k < d:
                prev = dp[k][i - 1] if i > 0 else 0
                reach = r[i]
                gain = reach - i + 1
                dp[k + 1][reach] = max(dp[k + 1][reach], prev + gain)

    return str(max(max(row) for row in dp))

 ## 特殊なケース

 次のような厳密に減少するシーケンス`10 9 8 7 6`任意の開始点から最大の伝播をトリガーします。 インデックス 0 から開始すると、`r[0]`したがって、DP は追加のチケットによってすでに完全にカバーされている範囲を超えてカバー範囲を人為的に拡大しないようにする必要があります。 間隔はすぐに消費され、それ以降の配置ではすでにカウントされたインデックスを再導入できないため、遷移ロジックがこれを処理します。 

次のような厳密に増加するシーケンス`1 2 3 4 5`生成する`r[i] = i`みんなのために`i`。 すべてのチケットは正確に 1 ユニットに貢献します。 したがって、DP は次のように動作します。`D`独立した要素であり、最大値は単純に`D`または`N`、どちらか小さい方。 これにより、条件が満たされない場合でも、伝播ロジックが誤って間隔を拡張しないことが確認されます。 

次のような定数配列`5 5 5 5 5`これは、任意の位置にあるすべてのチケットがサフィックス全体をカバーするという退化したケースを作成します。 任意の場所に配置された最初のチケットは、その右側のすべてを効果的に支配し、追加のチケットは、すでにカバーされているインデックス以外に新しいものを提供しません。
