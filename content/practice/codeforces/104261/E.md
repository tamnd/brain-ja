 ## 解決策
 ## 問題の理解

 最大 12 個の頂点を持つ完全な重み付きグラフが与えられます。 各頂点は岩石の破片を表しており、コスト マトリックスから、2 つの破片を直接接着するのにどれだけのコストがかかるかがわかります。 タスクは、サイクル内で選択されたすべてのエッジの合計コストが最小化されるように、各フラグメントを 1 回だけ使用して、すべてのフラグメントを 1 つのサイクルに配置することです。 

グラフの用語では、対称エッジの重みを持つ完全な無向グラフで最小重みのハミルトニアン サイクルを探します。 出力は、すべての頂点を 1 回訪問して開始頂点に戻る 1 つのサイクルを形成する、ちょうど N 個のエッジの重みの合計です。 

ここで重要な信号は、制約 N ≤ 12 です。 すべての頂点の順列を列挙しようとするアルゴリズムは、O(N!) で直接実行され、12! になります。 ≈ 4 億 7,900 万の順列、各順列には N 個のエッジの合計が必要です。 定数要素が含まれると、Python では 4 秒の制限の下ではすでに遅すぎます。 これは、サブセットに対するビットマスク動的プログラミング アプローチを直ちに示唆します。 

単純な定式化では、いくつかの特殊なケースが見落とされがちです。 1 つは、サイクルをパスとして扱い、それを閉じるのを忘れることです。これにより、最初に戻る最後のエッジを逃すことになります。 たとえば、N = 3 でコストがすべて 1 の場合、パスベースのソリューションでは、正しいサイクル コスト 3 の代わりにコスト 2 が計算される可能性があります。もう 1 つの問題は、すべてのサイクルが 2N 回の回転と反転で現れるため、総当たり置換でサイクルを二重にカウントすることです。これは、慎重に正規化しない限り単純な最小化を複雑にします。 

## アプローチ

 ブルーフォースのアイデアは単純明快です。 開始ノードを固定し、残りのノードのすべての順列を生成します。 各順列について、連続するノード間のエッジと最初に戻るエッジを合計することによってサイクル コストを計算します。 これは、可能なすべてのハミルトニアン サイクルを明示的にチェックするため、正しいです。 

問題は繰り返しの規模です。 (N−1) 個あります! 開始を修正した後の順列と各評価のコストは O(N) であるため、合計の複雑さは O(N! · N) になります。 N = 12 の場合、これは実現可能な限界をはるかに超えています。 

重要な観察点は、部分的な構築の状態は、どのノードがすでに使用されているか、および現在どのノードにいるかによってのみ依存するということです。 そのサブセットに到達した順序は、将来の決定には重要ではありません。 これはまさにビットマスク動的プログラミングがキャプチャする構造です。 

DP[mask][i] を、固定ノード 0 から開始し、マスク内のノードを正確に訪問し、ノード i で終了する最小コストとして定義します。 各状態から、cost[i][j]を追加して、未訪問のノード j まで拡張しようとします。 最後に、各エンドポイントから 0 に戻ってサイクルを閉じます。 

これにより、次数 N の順列による指数関数的な爆発が減少します。 それぞれが N 個の遷移を持つサイズ 2^N のサブセットに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (順列) | O(N!・N) | O(N) | 遅すぎる |
 | ビットマスク DP (TSP) | O(N^2・2^N) | O(N · 2^N) | 承認済み |

 ## アルゴリズムのチュートリアル

 開始点として 1 つのノード (通常はノード 0) を固定します。これにより、コストを変更せずに任意のサイクルを回転して 0 から開始できるため、サイクルの回転対称性がなくなります。 

サブセットと最後に訪問したノードによってインデックス付けされた DP テーブルを定義します。 サブセットは、どのノードが部分パスに既に含まれているかを追跡します。

1. コストを最小限に抑えるため、すべての DP 値を大きな数値に初期化します。 ノード 0 のみを訪問してノード 0 から開始する場合はコストがかからないため、DP[1 << 0][0] = 0 と設定します。 
2. 0 から (1 << N) − 1 までのビットマスクを使用して、ノードのすべてのサブセットを反復します。各サブセットは、訪問されたフラグメントの部分セットを表します。 
3. サブセットごとに、そのサブセットに含まれる可能性のあるすべての最後のノードを反復処理します。 DP[mask][i] が無効な場合は、到達不可能な状態を表すためスキップします。 
4. 状態 (マスク、i) から、マスクにない任意のノード j に移動してサイクルを延長してみます。 遷移により DP[mask | (1 << j)][j] (DP[マスク][i] + コスト[i][j])。 これにより、各州に到達するための最も安価な方法が常に蓄積されます。 
5. DP テーブルを埋めた後、マスクが (1 << N) − 1 に等しい状態ですべてのノードが訪問されました。考えられる最後のノード i ごとに、cost[i][0] を追加して、開始ノードに戻るサイクルを閉じて最小値を取得します。 

重要なアイデアは、DP が同じ訪問セットと終了点を共有するすべての順列を 1 つの状態に圧縮するということです。 これが、同一の部分問題の再計算を妨げる原因で​​す。 

### なぜ効果があるのか

 任意の時点で、DP[mask][i] は、マスク内のノードを正確に訪問して i で終了するすべての可能な順序の中での最小コストを表します。 新しいノード j への拡張は、i とマスクのみに依存し、どのようにしてこの構成に到達したかには依存しません。 これにより、最適な部分構造が確立されます。より大きなセットに対する最適なソリューションは、そのサブセットの最適なソリューションから構築できます。 すべてのハミルトニアン サイクルは、この DP 内の状態の 1 つのシーケンスに正確に対応し、すべての状態遷移はすべての可能性を考慮して正確さを維持するため、すべてのエンドポイントにわたる最終的な最小値から最適なサイクルが正しく得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    cost = [list(map(int, input().split())) for _ in range(n)]
    
    INF = 10**18
    size = 1 << n
    dp = [[INF] * n for _ in range(size)]
    
    dp[1][0] = 0  # start from node 0, mask = 000...001
    
    for mask in range(size):
        if not (mask & 1):
            continue
        for i in range(n):
            if dp[mask][i] == INF:
                continue
            if not (mask & (1 << i)):
                continue
            for j in range(n):
                if mask & (1 << j):
                    continue
                new_mask = mask | (1 << j)
                new_cost = dp[mask][i] + cost[i][j]
                if new_cost < dp[new_mask][j]:
                    dp[new_mask][j] = new_cost
    
    full = size - 1
    ans = INF
    for i in range(n):
        ans = min(ans, dp[full][i] + cost[i][0])
    
    print(ans)

if __name__ == "__main__":
    solve()
```DP テーブルは、到達不能な状態を表すために大きなセンチネル値で初期化されます。 開始状態では、ノード 0 がそのノードのみを含むビットマスクで固定されます。 

三重ループ構造が必要です。マスクはサブセットを列挙し、i はそれらのサブセットのエンドポイントを列挙し、j は拡張を試みます。 条件チェックにより、有効な状態のみを拡張し、サブセットに既に含まれているノードを再利用しないことが保証されます。 

最後のループは、ノード 0 に戻ってサイクルを明示的に閉じます。これは、誤った実装で最も見逃されることが多いステップであり、DP は直接サイクルではなくハミルトニアン パスのみを構築するため、これは不可欠です。 

## 実用的な例

 サンプル入力をトレースします。 

入力：```
4
0 1 2 3
1 0 4 5
2 4 0 6
3 5 6 0
```意味のある DP 遷移のみを追跡します。 

| ステップ | マスク | 最後のノード | DP値 | アクション |
 | --- | --- | --- | --- | --- |
 | 初期化 | 0001 | 0 | 0 | 開始 |
 | 拡張する | 0011 | 1 | 1 | 0→1 |
 | 拡張する | 0101 | 2 | 2 | 0→2 |
 | 拡張する | 1001 | 3 | 3 | 0→3 |
 | フルパス | 1111 | 1、2、3 | 計算された | 複数の順列 |

 次に、1 つの最適なパスを考えます。0 → 1 → 2 → 3 → 0 のコストは 1 + 4 + 6 + 3 = 14 になります。 

このトレースは、DP が各状態の最小コストを維持しながら、ノード 0 からすべての部分パスを構築していることを示しています。 最後の閉鎖ステップにより、サイクルが正しく完了することが保証されます。 

2 番目の小さなケースは、正しさを確認するのに役立ちます。 

入力:```
3
0 1 1
1 0 1
1 1 0
```すべてのサイクルは等しいコスト 3 を持ちます。DP は 2 (パス コスト 0→1→2) を生成し、次に 2→0 を加算して 3 を生成します。すべての順列は同じ最適値に崩壊し、対称性の処理が確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N^2・2^N) | サブセットとエンドポイントごとに、最大 N 個のノードへの遷移を試みます。 
| スペース | O(N · 2^N) | DP テーブルには、各 (マスク、最後のノード) ペアの値が格納されます。 

N ≤ 12 の場合、2^N = 4096、N^2 · 2^N は約 589k の演算となり、これは Python の制限内に簡単に収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    input = sys.stdin.readline
    n = int(input())
    cost = [list(map(int, input().split())) for _ in range(n)]
    
    INF = 10**18
    size = 1 << n
    dp = [[INF] * n for _ in range(size)]
    dp[1][0] = 0
    
    for mask in range(size):
        if not (mask & 1):
            continue
        for i in range(n):
            if dp[mask][i] == INF:
                continue
            if not (mask & (1 << i)):
                continue
            for j in range(n):
                if mask & (1 << j):
                    continue
                dp[mask | (1 << j)][j] = min(dp[mask | (1 << j)][j], dp[mask][i] + cost[i][j])
    
    full = size - 1
    ans = min(dp[full][i] + cost[i][0] for i in range(n))
    return str(ans)

 ## 特殊なケース

 一般的なエッジケースは、すべてのコストがゼロの場合です。 DP はすべての状態にゼロを伝播し、最後のクロージャでもゼロが追加され、正しい結果 0 が生成されます。これにより、アルゴリズムが正の重みに依存していないことが確認されます。 

もう 1 つの微妙なケースは、最適なサイクルが単純な貪欲なパスに似ていない場合です。 たとえば、非対称に見えるコスト マトリックスの場合、最適パスは、後のコストを削減するために、局所的に安価なエッジを回避する可能性があります。 DP はこれを処理します。これは、すべての状態が局所的な貪欲な選択ではなく、すべての部分順列にわたる真の最小値を保存しているためです。 

最後に、最小のケース N = 2 でサイクル終了の正確さをテストします。 DP は単一のパス 0 → 1 を構築し、最後のステップで明示的にコスト [1][0] を追加することで、サイクルが完了し、誤ってパスとして扱われないことが保証されます。
