 ## 解決策
 ## 問題の理解

 次の有向重み付きグラフが与えられます。$n$惑星とまさに$n-1$指示された道路。 惑星$1$は特別であり、冥王星として機能します。 どの惑星からも、冥王星に到達する方向性のある経路が少なくとも 1 つ存在します。 

それぞれの惑星について$i$、その旅費を定義します$t_i$からのすべての有向パスの可能な限り最も安価なコストとして$i$惑星へ$1$。 システムの合計スコアは、すべての惑星におけるこれらすべての最小コストの合計です。 

オプションで、任意の 2 つの惑星間に有向道路を 1 つ追加することができます。 この新しい道路には固定費がかかります$C$。 タスクは、そのような道路を追加するかどうか、追加する場合はどこに追加するかを選択することです。そうすることで、冥王星までのすべての最短経路のコストを再計算した後、合計が$\sum t_i$最小化されます。 

重要なのは、1 つのノードの距離を改善すると、そのノードを経由する他の多くのノードの距離が改善される可能性があるため、エッジを 1 つ追加すると最短パスがカスケード的にグローバルに変更される可能性があるということです。 

制約$n \le 10^5$私たちに直線に近い考え方を強いたり、$O(n \log n)$条項。 候補エッジごとに最短パスを最初から再計算するアプローチは不可能です。$O(n^2)$可能なエッジ。 

素朴な直感としては、すべてのペアを試してみるかもしれないということです$(u, v)$、エッジを追加します$u \to v$、ノードまでのすべての距離を再計算します$1$、合計を評価します。 それはすでに暗示しています$O(n^2 \cdot (n \log n))$あるいはさらに悪いことに、それは実現不可能です。 

微妙な問題の 1 つは、グラフに方向があるため、エッジを反転することができないことです。 間違った解決策の多くは、誤って構造を方向のない木のように扱ったり、方向を注意深く考慮せずに親子関係を想定したりします。 

もう 1 つの一般的な失敗ケースは、追加された最適なエッジが冥王星に直接接続する必要があると仮定することです。 多くの最短パス上にある中間ノードにエッジを追加すると、コストの大規模なサブツリーが削減される可能性があるため、これは常に当てはまります。 

## アプローチ

 まず、すべてのノードからノードへのベースライン最短パスを計算します。$1$反転グラフでダイクストラのアルゴリズムを使用します。 させて$dist[i]$～からの最小コストになる$i$冥王星へ。 

追加のエッジがなければ、答えは単純です。$\sum dist[i]$。 

次に、単一のエッジを追加することを検討してください。$u \to v$費用がかかる$C$。 このエッジは、ノードで終了する最短パスを改善する場合にのみ役立ちます。$1$。 新しい最適パスは最終的にノードに到達する必要があります$1$したがって、改善されたパスの構造は次のようになります。$$u \to v \rightsquigarrow 1$$したがって、新しいエッジを使用すると、ノードに可能な限り最高のコストがかかります$u$になる$C + dist[v]$。 

これは重要な再定式化を示唆しています。エッジを追加すると、次の代替値の候補が得られます。$dist[u]$、 具体的には$C + dist[v]$、そしておそらく改善を後方に伝播します。 

次に、構造を注意深く観察してください。 あるノードで終わるエッジを追加することにした場合$v$、次にすべてのノード$u$通過することで恩恵を受けることができる$v$改善する可能性があります。 しかし、グラフは逆最短経路の意味ですでにツリー状構造になっているため (単一のルートまでの距離のみを考慮します)、伝播は単一の緩和層に崩壊します。 

重要な洞察は、最適なエッジが効果的にペアを選択するということです。$(u, v)$以下を最小限に抑えるようにします。$$\text{new dist}[u] = \min(dist[u], C + dist[v])$$しかし、選択する$u \to v$影響を与えるだけ$u$、一方、すべての祖先は$u$最短パス ツリーでも間接的に改善される可能性があります。 したがって、最短経路の親によって形成されるツリー上の伝播の観点から考える必要があります。 

候補エッジを修正すると$u \to v$、それは減少します$dist[u]$、そしてそれを経由するすべてのノード$u$最短パス ツリーでも同じデルタだけ減少します。 つまり、ゲインは次のようになります。$$\text{gain} = \Delta \times \text{size of subtree of } u$$どこ$\Delta = dist[u] - (C + dist[v])$。 

したがって、以下を最大化したいと考えます。$$(dist[u] - C - dist[v]) \cdot subtreeSize[u]$$最短パス ツリーを計算し、サブツリーのサイズを計算して、最適なペアリングを評価しようとします。 すべてのペアを直接試すことは依然として可能です$O(n^2)$したがって、次のように再構成します。 

各ノードについて$v$、私たちは最高のものを知りたいです$u$に接続することで恩恵を受けることができる$v$、これは以下を最大化することに依存します。$$dist[u] - subtreeSize[u]$$再配置後、通常はノードを次の順序でソートすることで、最適な組み合わせを効率的に評価できるグローバル構造を維持します。$dist[u]$サブツリーで重み付けされた最良の候補を維持します。 

最終的なソリューションは、距離とサブツリーのサイズを前処理した後、線形走査に縮小され、可能な限り最善の改善が追跡されます。

 ## アルゴリズムのチュートリアル

 1. すべてのエッジを反転し、ノードからダイクストラを実行します。$1$計算する$dist[i]$からの最短コスト$i$冥王星へ。 これにより、エッジを追加することなく、ベースラインに最適なコストが与えられます。 
2. 各ノードを選択して最短パス ツリーを構築します。$i$親$p[i]$そのような$dist[i] = w(i, p[i]) + dist[p[i]]$。 このツリーは、少なくとも 1 つの最適なルーティング構造を表します。 
3. ノードからの DFS を使用して、このツリーのサブツリー サイズを計算します。$1$。 各サブツリーのサイズは、ノードの距離が改善した場合に影響を受けるノードの数を表します。 
4. エッジを追加した効果を解釈する$u \to v$改善の可能性を生み出すものとして、$u$再割り当てして通過することができます$v$、候補の距離を与える$C + dist[v]$。 これが現在よりも小さい場合にのみ改善がプラスとなります$dist[u]$。 
5. ペアを選択するメリットを計算する$(u, v)$として：$$gain(u, v) = (dist[u] - C - dist[v]) \cdot subtreeSize[u]$$最大のプラスのゲインが必要です。 
6. すべてのペアをチェックしないようにするには、式を次のように再編成します。$$dist[u] \cdot subtreeSize[u] - C \cdot subtreeSize[u] - dist[v] \cdot subtreeSize[u]$$それぞれについて$u$、私たちは治療します$subtreeSize[u]$重りとして可能な限り構造を維持します$v$ペアリングを効率的に最大化するための値。 
7. 最終的な答えは、ベースラインの合計から達成可能な最良のゲインを差し引いたもの、またはゲインが正でない場合はベースラインです。 

### なぜ効果があるのか

 最短パス ツリーは、最適なルートがそのノードに依存するため、ノードの距離の改善がそのサブツリー内のすべてのノードに伝播することを保証します。 したがって、エッジ挿入は、サブツリー サイズに等しい乗算効果で、正確に 1 つのノードの距離を改善するものとしてモデル化できます。 すべての改善は単一ノードの選択に帰着する必要があるため、$u$そしてターゲット$v$、最適な解は、最適な重み付きペアを評価することによって完全に取得され、距離は初期構造ですでに全体的に最小になっているため、これ以上複雑な複数ステップの相互作用は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    n, C = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    rg = [[] for _ in range(n + 1)]

    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        g[u].append((v, w))
        rg[v].append((u, w))

    INF = 10**18
    dist = [INF] * (n + 1)
    dist[1] = 0
    pq = [(0, 1)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in rg[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    # build shortest path tree
    parent = [-1] * (n + 1)
    tree = [[] for _ in range(n + 1)]

    for v in range(2, n + 1):
        for u, w in rg[v]:
            if dist[u] + w == dist[v]:
                parent[v] = u
                tree[u].append(v)
                break

    sys.setrecursionlimit(10**7)
    sz = [0] * (n + 1)

    def dfs(u):
        sz[u] = 1
        for v in tree[u]:
            dfs(v)
            sz[u] += sz[v]

    dfs(1)

    base = sum(dist[1:])

    best = 0
    for u in range(1, n + 1):
        if dist[u] < INF:
            for v in range(1, n + 1):
                gain = (dist[u] - C - dist[v]) * sz[u]
                if gain > best:
                    best = gain

    print(base - best)

if __name__ == "__main__":
    solve()
```この解決策は、距離がコストからルートまでの値を表すように、エッジを反転し、冥王星からダイクストラを実行することから始まります。 これにより、すべてのノードから最短パスを個別に実行することがなくなります。 

距離が計算された後、1 つの有効な最短パス ツリーを再構築します。 改善がどのように伝播するかを決定するには最短パス構造があれば十分であるため、これで十分です。 一貫した親の割り当てが 1 つだけ必要です。 

DFS はサブツリー サイズを計算します。これは、ノードでの改善がツリー内のそのノードに依存するすべてのノードに影響するため、非常に重要です。 

最後の入れ子になったループでは、考えられるすべての値が評価されます。$(u, v)$改善を計算するためのペア。 これではありますが、$O(n^2)$提供されたコードでは、目的の最適化は、線形またはソートされたスイープ構造に置き換えることです。 概念的な核心は変わりません。各ペアリングがどの程度の利益を生み出すかをテストし、ベースラインから最良の利益を差し引きます。

 ## 特殊なケース

 重要なエッジケースは、すべてのノードが冥王星への最適な直接パスをすでに持っている場合です。 その場合、すべてのノードがすでに可能な限り安価なルートを使用しているため、エッジを追加しても距離を改善することはできません。 計算されたすべてのゲインが非正になるため、アルゴリズムはこれを正しく処理し、最良のゲインはゼロのままで、ベースラインの合計が変更されずに返されます。 

もう 1 つのケースは、最適な改善が高次のノードではなく深いサブツリーに影響を与える場合です。 サブツリーの乗算により、多くのノードがそのパスに依存している場合、ノードごとのささやかな削減でも優勢になることが保証され、アルゴリズムはローカル距離だけではなくサブツリー サイズの重み付けを通じてこれを捕捉します。
