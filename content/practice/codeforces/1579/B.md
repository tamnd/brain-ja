 ## 解決策
 ## 問題の理解

 配列と特殊な演算が与えられています。 個々の要素を交換する代わりに、任意の連続セグメントを選択し、そのセグメントを任意の量だけ左に回転させることができます。 回転後、要素は同じ間隔内に残り、順序のみが周期的に変化します。 

タスクは、配列を非減少順序に変換することです。 操作の数を最小限に抑える必要はありません。 最大でも使用する任意のシーケンス$n$回転は受け入れられます。 

各テスト ケースには 1 つの配列が含まれます。 すべてのテスト ケースについて、実行する回転数を出力し、すべての回転を左端点、右端点、およびシフト量で記述する必要があります。 

制約は非常に小さいです。 配列の長さは最大 50 で、テスト ケースの数は最大 1000 です。 たとえ$O(n^3)$ソリューションは約のみ実行します$50^3=125000$テスト ケースごとの操作なので、十分に高速です。 高度なデータ構造は必要ありません。 

微妙な点の 1 つは、重複した値が存在することです。 配列が次のようになっているとします。```
3
2 1 1
```並べ替えたバージョンは、```
1 1 2
```位置 0 を固定するときは、任意の値ではなく、最初に出現した未使用の値 1 を移動する必要があります。 そうしないと、等しい値の相対的な配置が妨げられ、後の位置の一致が難しくなる可能性があります。 

もう 1 つのまれなケースは、正しい要素がすでに配置されている場合に発生します。 例えば```
4
1 2 3 4
```答えには演算が含まれていない必要があります。 不注意な実装では、シフト 0 で無駄な回転が出力される可能性がありますが、この問題ではシフト量が正である必要があります。 

等しい要素を含む配列にも注意が必要です。 のために```
4
5 5 5 5
```配列はすでにソートされているため、正解はやはり操作がゼロです。 最初に一致する値を検索して不必要に回転すると、事態が複雑になるだけです。 

## アプローチ

 ブルートフォースのアイデアは、ソートされた配列が表示されるまで、考えられるすべての回転シーケンスを検索することです。 あらゆる間隔とあらゆるシフト量が利用できるため、可能性の数は爆発的に増加します。 たとえ$n=50$、このアプローチは絶望的です。 

有益な観察は、操作の数を最適化する必要がないということです。 必要なのは、最大でもいくつかのシーケンスを使用することだけです$n$回転。 

挿入ソートについて考えてみましょう。 位置で$i$、一度位置決めします$0\ldots i-1$すでに正しいので、必要な位置に配置する要素を持ってくるだけです$i$あの場所へ。 その要素が現在その位置にある場合$j$、セグメントを選択できます$[i,j]$そしてそれを左に回転させます$j-i$。 

セグメントが```
[x1, x2, ..., xk, target]
```左回転$k$生成する```
[target, x1, x2, ..., xk]
```まさに目的の要素がその位置に移動します$i$、以前に固定されたすべての位置はそのまま残ります。 各ポジションに必要な回転は最大でも 1 回転であるため、実行するのは最大でも 1 回転です。$n-1$操作。 

回転にはあらゆる順列に到達するのに十分な表現力があるため、総当たりアプローチは機能しますが、検索空間が膨大であるため失敗します。 慎重に選択したローテーションで 1 つの位置を永続的に配置できるという観察により、問題は単純な挿入ソートのようなプロセスに帰着します。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 並べ替えられた配列のコピーを作成します。 
2. 位置を左から右に処理します。 
3. 現在の位置について$i$、最初の位置を見つけます$j\ge i$その値は、位置に表示されるべき値と等しい$i$ソートされた配列内。 
4. もし$j=i$、正しい要素はすでにそこにあるので、次に進みます。 
5. それ以外の場合はセグメントを検討する$[i,j]$。 このセグメントを左に回転します$j-i$。 
6. 回転後、要素は元の位置に配置されます$j$位置に移動します$i$、その間のすべての要素$i$そして$j-1$位置を 1 つ右に移動します。 
7. この操作を記録し、次の位置に進みます。 

### なぜ効果があるのか

 不変条件は、位置を処理する前の条件です。$i$、接頭辞$0\ldots i-1$すでにソートされた配列と一致しています。 

必要な値を位置に配置するとき$j$セグメントを回転させます$[i,j]$、からのポジションのみ$i$に$j$変化。 前の位置$i$変更されないため、不変式は保持されます。 希望の値が正確な位置に移動します$i$、プレフィックスを作成します$0\ldots i$正しい。 

帰納法により、すべての位置を終了した後、すべてのインデックスにソートされた配列と同じ値が含まれるため、配列全体がソートされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        target = sorted(a)
        ops = []

        for i in range(n):
            j = i
            while j < n and a[j] != target[i]:
                j += 1

            if j == i:
                continue

            ops.append((i + 1, j + 1, j - i))

            val = a[j]
            for k in range(j, i, -1):
                a[k] = a[k - 1]
            a[i] = val

        out.append(str(len(ops)))
        for l, r, d in ops:
            out.append(f"{l} {r} {d}")

    sys.stdout.write("\n".join(out))

solve()
```このアルゴリズムは、まずソートされたターゲット配列を構築します。 これにより、どの値が各位置を占めるべきかがわかります。 

すべてのインデックスについて、必要な値が最初に見つかるまで右に検索します。 重複が存在する場合は、最初に出現したものを使用することが重要です。 多くの場合、後のコピーを選択しても機能しますが、最も古いコピーを選択すると、自然に挿入ソートが模倣され、操作の数が少なくなります。 

ステートメントではそれが必要であるため、操作パラメータでは 1 から始まるインデックスが使用されます。 

実際の配列の更新には注意が必要です。 回転セグメント$[i,j]$が残した$j-i$要素を取得するのと同じです`a[j]`、所定の位置に配置します`i`、それらの間の要素を 1 ステップ右に移動します。 これを直接実装すると、一時スライスの作成が回避され、ロジックが透過的に保たれます。 

各位置で最大 1 つの操作がトリガーされるため、操作の数が超過することはありません$n-1$。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        target = sorted(a)
        ops = []

        for i in range(n):
            j = i
            while j < n and a[j] != target[i]:
                j += 1

            if j == i:
                continue

            ops.append((i + 1, j + 1, j - i))

            val = a[j]
            for k in range(j, i, -1):
                a[k] = a[k - 1]
            a[i] = val

        ans.append(str(len(ops)))
        for x in ops:
            ans.append("{} {} {}".format(*x))

    return "\n".join(ans)

 ## 特殊なケース

 重複する値を考慮します。```
1
3
2 1 1
```ソートされた配列は`[1,1,2]`。 

位置 0 には 1 が必要です。最初の出現はインデックス 1 に表示されます。回転セ​​グメント`[0,1]`与える```
[1,2,1]
```位置 0 が正しくなりました。 位置 1 には、インデックス 2 ですでに使用可能な 1 が再度必要になります。もう一度回転すると配列がソートされますが、現在インデックス 1 には 2 が含まれているため、アルゴリズムは必要に応じてその操作を自動的に実行します。 常に現在のインデックスから検索するため、重複によってあいまいさが生じることはありません。 

ここで、すでにソート済みの配列を考えてみましょう。```
1
4
1 2 3 4
```すべての位置について、検索によりすぐに見つかります。`j=i`。 操作は記録されません。 出力には操作が含まれておらず、問題の要件を満たしています。 

最後に、すべての値が等しいとみなします。```
1
4
7 7 7 7
```ソートされたコピーは元の配列と同一です。 すべての検索は即座に停止し、回転は実行されず、アルゴリズムは正しくゼロ操作を出力します。 セグメントをやみくもに回転させる不注意な実装は、シフト量が正でなければならないという要件に違反することになります。
