 ## 解決策
 ## 問題の理解

 0 と 1 だけからなる配列と正の整数が与えられます。`d`循環右シフトを指定します。 各ステップで、配列は右にシフトして変換されます。`d`位置を調べ、同じ位置にあるシフトされた配列内の要素と各要素のビット単位の AND をとります。 このプロセスは、配列の変更が停止するまで繰り返されます。 タスクは、配列が完全にゼロになるまでに必要なステップ数を決定するか、レポートすることです。`-1`すべてゼロにならない場合。 

入力には複数のテスト ケースが含まれています。 各テスト ケースは配列の長さを示します`n`、シフト量`d`、および配列要素。 制約により許可されるのは、`n`最大 100 万、すべてのテスト ケースにわたる合計最大 100 万の要素。 これにより、各ステップの各要素のプロセスを素朴にシミュレートするアルゴリズムは除外されます。これは、ステップ数が多い場合、100 万個の要素に対して AND 演算を繰り返すと簡単に制限時間を超える可能性があるためです。 あらゆる変換をシミュレートすることを避けるアプローチが必要です。 

明らかではないエッジ ケースには、すべての要素が 0 である配列、シフトが含まれる配列が含まれます。`d`はの約数です`n`および 1 はゼロに触れずにサイクルし、単一の 1 またはゼロで区切られた 1 のシーケンスを含む配列です。 たとえば、`n=4`、`d=2`、 そして`a=[1,0,1,0]`、単純なアプローチでは、配列が最終的にゼロになると想定する可能性がありますが、循環 AND パターンにより、シフト後に各要素がそれ自体と AND 演算されるため、配列は決して変化しません。`-1`。 

## アプローチ

 ブルートフォース手法では、アレイを段階的にシミュレートします。 各ステップで、シフトされた配列を計算し、すべての要素に対して AND 演算を実行し、配列が変更されたかどうかを確認します。 これは正しいです。変換は決定論的であり、配列の長さは有限であるため、最終的にはすべて 0 か 0 以外のパターンで安定します。 ただし、このアプローチは非常に時間がかかる可能性があります。 のために`n = 10^6`そして`d`1 秒のサイクルを維持するため、安定するまでのステップ数も次のようになります。`O(n)`以上の結果、`O(n^2)`合計操作数は 2 秒の制限には多すぎます。 

最適化のための重要な洞察は、配列が自然に、繰り返しシフトすることによって形成されるサイクルに分解されるということです。`d`。 各サイクルは独立しており、サイクル内の AND 演算はサイクル全体でゼロを伝播することと同じです。 いずれかのサイクルに、サイクル長よりも長い 1 の連続ブロックが含まれている場合、サイクルの他の部分からのゼロによって完全に上書きされることはありません。 サイクル内の 1 の最長連続セグメントの長さによって、そのサイクルをゼロにするのに必要なステップ数が決まります。 すべてのステップをシミュレートするのではなく、各サイクルで連続する 1 の長さを追跡し、最大値を計算するだけで済みます。 

この観察により、問題は、潜在的に数百万のステップをシミュレートすることから、各サイクルを 1 回反復してその 1 で単純なメトリクスを計算することに軽減されます。 あるので`gcd(n, d)`サイクル、それぞれの長さ`n / gcd(n, d)`の場合、複雑さは配列サイズに比例します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * ステップ) | O(n) | n が大きいと遅すぎます |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンピューティング`g = gcd(n, d)`。 これにより、配列内の独立したサイクルの数が得られます。 各要素は正確に 1 つのサイクルに属し、AND 演算は同じサイクル内の要素にのみ影響します。 
2. サイクルごとに、サイクル パターンに従って要素を抽出します。インデックスで始まるサイクルの場合`i`、要素は`a[i], a[(i+d)%n], a[(i+2d)%n], ...`ループバックするまで`i`。 
3. 連続する 1 を数えるときの周期的な性質を処理するために、サイクルをそれ自体に連結します。 たとえば、サイクルが次のような場合`[1,0,1]`として扱います`[1,0,1,1,0,1]`ラップアラウンドするシーケンスを検出します。 
4. 各サイクルについて、最長の連続する 1 シーケンスの長さを計算します。 サイクルが完全に 1 で構成されている場合、それをゼロにすることは不可能なので、次を返します。`-1`。 
5. それ以外の場合、すべてのサイクルにわたる連続する 1 の最大長は、配列がすべて 0 になるために必要なステップ数になります。 これは、各ステップで、各 1 がそのサイクルの 0 と AND 演算された場合に 0 になる可能性があるためです。 
6. 各テスト ケースの全サイクルにわたる最大値を出力します。 

機能する理由: 各サイクルは独立しています。`d`サイクル内の各要素を同じサイクル内の別の要素に繰り返しマッピングします。 AND 演算は、反復ごとに 1 ステップずつサイクル全体にゼロを広げます。 したがって、任意のサイクル内で最も長く連続する 1 のシーケンスによって、そのサイクルをゼロに減らすために必要な反復回数が決まります。 サイクルにゼロがない場合、その 1 は減ることはありません。`-1`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def solve():
    t = int(input())
    for _ in range(t):
        n, d = map(int, input().split())
        a = list(map(int, input().split()))
        g = gcd(n, d)
        max_len = 0
        impossible = False
        for start in range(g):
            cycle = []
            i = start
            while True:
                cycle.append(a[i])
                i = (i + d) % n
                if i == start:
                    break
            doubled = cycle + cycle
            longest = 0
            cur = 0
            for val in doubled:
                if val == 1:
                    cur += 1
                    longest = max(longest, cur)
                else:
                    cur = 0
            if longest >= len(cycle):
                impossible = True
                break
            max_len = max(max_len, longest)
        print(-1 if impossible else max_len)

if __name__ == "__main__":
    solve()
```コードはアルゴリズムに正確に従います。 gcd を使用してサイクルを計算し、サイクル連結でラップアラウンドを処理し、各サイクルで最も長く連続する 1 をチェックします。 小切手`longest >= len(cycle)`決してゼロにならないサイクルを確実に検出します。 これにより、ラッピングや使用に関する off-by-one エラーが回避されます。`cur`for counting は、配列を繰り返しスライスすることを回避します。
