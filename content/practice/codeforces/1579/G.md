 ## 解決策
 ## 問題の理解

 セグメントの長さのシーケンスが与えられているので、これらのセグメントを無限数直線上に次々に配置する必要があります。 最初のセグメントは座標 0 で始まり、1 つの端点は 0 に固定されます。次の各セグメントは、その開始端点を前のセグメントの終了点と共有することによって前のセグメントに接続する必要がありますが、各ステップでセグメントの方向を反転することができます。 したがって、各セグメントは、その長さだけ現在の位置を左または右に拡張します。 

すべてのセグメントを配置した後、ライン上のすべてのカバーされた間隔の結合を調べます。 構築は常にライン上で接続されたウォークを形成するため、この結合は単一の区間であり、その長さは単にウォーク中に到達した最小座標と最大座標の間の距離になります。 

タスクは、この最終的にカバーされる間隔ができるだけ短くなるように、すべてのセグメントの方向を選択することです。 

この制約により、テストごとに最大 10^4 のセグメントと最大 1000 のテスト ケースが許可されるため、どのソリューションもテスト ケースごとに基本的に直線的な時間で実行する必要があります。 多くのテストにわたるテスト ケースごとの 10^4 の 2 乗は大きすぎるため、テスト ケースごとの n の 2 次関数は最悪の場合すでに遅すぎます。 

すべてのセグメントが同じ方向に押すと、微妙なエッジケースが発生します。 たとえば、すべての長さが正で、常に右に拡張する場合、カバレッジはすべての長さの合計になります。 ただし、方向を反転すると、この範囲が大幅に縮小される可能性があります。 もう 1 つのエッジ ケースは、交互の選択が初期には局所的に最適であるように見えても、後で大きな広がりを引き起こす場合です。 たとえば、現在のエンドポイントを最小化する方向を常に選択するなどの貪欲な選択は、必ずしもグローバル最大スパンを最小化するとは限りません。 

欲張りが失敗する簡単な例は次のとおりです。 

入力:```
3
1 100 1
```現在の位置をゼロ付近に維持しようと貪欲に試みると、最終的には 100 近くに及ぶような形で変動する可能性がありますが、より適切な戦略により動きのバランスが取れ、極端な値がより効果的に相殺されます。 

最大の問題は、各セグメントが符号付きの値に寄与することであり、プレフィックスの合計の最大値と最小値の差を最小限に抑えようとしている点です。 

## アプローチ

 すべての可能性をシミュレーションすると、各セグメントには 2 つの選択肢があります。左に進むか右に進むかです。 これにより、2^n 個の可能な構成を持つバイナリ決定木が形成されます。 構成ごとに、結果のパスを計算し、その最小座標と最大座標を追跡します。 これは正しい答えを与えますが、n は 10^4 になる可能性があり、2^n は天文学的に大きくなる可能性があるため、完全に実行不可能です。 

重要な観察は、エンドポイントの正確な位置だけを決して気にしないということです。 重要なのは、各ステップの後に到達できるエンドポイントの位置の範囲です。 セグメントの一部のプレフィックスを処理した後、到達可能なエンドポイント位置のセットは常に連続した間隔になります。 これは、各ステップがすべての位置を +a[i] または -a[i] だけシフトし、到達可能なセットの凸性を維持するためです。 

したがって、すべてのパスを追跡するのではなく、各プレフィックスの後の到達可能なエンドポイントの最小値と最大値の 2 つの値のみを追跡します。 ステップ i で、現在の範囲が [L, R] の場合、セグメント a[i] を追加すると、新しい範囲は次のようになります。 

L - a[i] から R + a[i]。 

これは、[L, R] のどの点からでも左右に拡張できるため、極値は外側に向かって対称的に拡張されます。 しかし、この素朴な解釈は不完全です。各ステップで独立してではなく、最終的なスパンを最小化するために全体的に方向を選択しているということを捉えていません。 

本当に重要な洞察は、プロセスを署名された貢献のバランスを取るものとして再解釈することです。 各セグメントに、方向を表す +a[i] または -a[i] を割り当てます。 最終的な位置は符号付き値のプレフィックス合計であり、カバーされる長さは最大プレフィックス合計と最小プレフィックス合計の差です。 

これは古典的な問題になります。つまり、プレフィックスの合計の範囲を最小化するように符号を割り当てます。 最適な構造は、i 要素の処理後に達成可能なプレフィックス合計のセットが常に一定の間隔であり、間隔にわたって単純な DP を使用して境界を拡張および縮小することで貪欲に更新できることです。 

現在のエンドポイントと潜在的な最小値の間の一連の考えられる差を維持します (または、同等の合計の到達可能な間隔を追跡します)。 この変換により標準的な間隔 DP が得られ、各ステップで間隔が対称性に基づいて拡大し、その後「折りたたまれます」。 これにより、2 つの境界状態圧縮を使用した線形解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての符号の割り当て) | O(2^n · n) | O(n) | 遅すぎる |
 | 間隔 DP (2 つの境界) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 各セグメントの処理後のプレフィックス合計の可能な限り最良の広がりを表す 2 つの値を使用してプロセスをモデル化します。 

1. 0 の単一点から開始します。これは、プレフィックスの最小値と最大値の合計が両方とも 0 であることを意味します。 
2. 各セグメント長 a[i] について、到達可能なプレフィックス合計の現在の範囲にどのような影響を与えるかを検討します。 
3. a[i] を追加すると、既存のプレフィックス合計 x は x + a[i] または x - a[i] のいずれかになる可能性があるため、到達可能なセットは両方向に外側に拡張されます。 
4. 拡張後も、新しい到達可能な値は連続した間隔を形成するため、そのエンドポイントを更新するだけで済みます。 
5. 到達可能なプレフィックスの合計の最小値と最大値を表す、low と high の 2 つの値を維持します。 
6. 各ステップで、次のように最低値と最高値を更新します。 

low = min(low - a[i], low + a[i])

 高 = 最大(高 - a[i], 高 + a[i])
 7. すべてのセグメントを処理した後の答えは、高 - 低です。 

微妙な点は、各ステップで可能性が 2 倍になりますが、到達可能なセットは凸型のままであるため、エンドポイントはそれを完全に記述します。 

### なぜ効果があるのか

重要な不変条件は、i 個のセグメントを処理した後、すべての可能なプレフィックス合計のセットが連続した間隔 [低、高] を形成することです。 新しいセグメントはそれぞれ、既存のすべての値 x を 2 つの値 x ± a[i] にマッピングし、2 つのシフトされた間隔を生成します。 これら 2 つの区間の和集合は、両方とも同じ連続セットの変換であるため、依然として 1 つの区間です。 したがって、ギャップは発生せず、状態は常に最小値と最大値に圧縮されます。 最終的なカバレッジは極値プレフィックスの合計にのみ依存するため、間隔の長さの高値から低値は、最適な符号を選択​​した後の可能な最小カバレッジとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        low = 0
        high = 0
        
        for x in a:
            # expanding both directions
            new_low = min(low - x, low + x)
            new_high = max(high - x, high + x)
            low, high = new_low, new_high
        
        out.append(str(high - low))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、間隔圧縮のアイデアを直接実装しています。 変数`low`そして`high`各プレフィックスの後のエンドポイント座標の現在到達可能な範囲を表します。 各ステップで、可能な拡張の両方を検討し、それに応じて極端な拡張を更新します。 最後の違いは、達成可能な最小スパンです。 

よくある落とし穴は、両方のエンドポイントを個別に更新する必要があることを忘れていることです。 いずれか 1 つだけを使用する`low + a[i]`または`low - a[i]`対称性がないと正しさが損なわれます。

 ## 特殊なケース

 単一セグメントのような最小のケースでは、間隔が 0 から a[0] までに強制されるため、答えはその長さだけであることがわかります。 このアルゴリズムは、low と high を 0 に初期化し、すぐに [-a[0], a[0]] に展開して、正しいスパンを生成します。 

[1, 1000, 1] などの大きな値が交互に現れる場合は、中間展開が広い範囲で誤ってロックする可能性があるかどうかをテストします。 間隔の更新により各ステップでの対称性が確保されるため、2 番目のステップは [-1, 1] から [-1001, 1001] に拡張され、最後のステップでは可能なキャンセルを失うことなく正しく調整されます。 

[5、4、3、2、1] のような単調減少シーケンスは、一方向への貪欲なバイアスが誤って蓄積していないことをチェックします。 各ステップが対称的に拡張されるため、アルゴリズムは極端な値のみを正確に追跡し、最終的な範囲は単純な予想に比べて狭いままになります。
