 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$、1 から 1 までのすべての整数を含む配列を意味します。$n$まさに一度。 私たちのタスクは、この順列を処理して両端キュー (deque) にし、新しい要素をそれぞれ前または後ろに配置することです。 目標は、すべての要素が処理された後に、辞書編集上可能な最小のシーケンスを両端キュー内に生成することです。 

辞書編集順はよく知られた「辞書順」です。要素を左から右に比較し、シーケンスが異なる最初の位置によってどのシーケンスが小さいかを決定します。 例えば、`[1,3,2]`よりも小さいです`[1,3,4]`最初の 2 つの要素が一致し、2 < 4 であるためです。 

制約により、最大で次のことが許可されます。$2 \cdot 10^5$すべてのテスト ケースに合計要素数が含まれるため、ソリューションは要素の合計数に対してほぼ直線的な時間で実行される必要があります。 これにより、考えられるすべての前後の配置を試すような単純なアプローチは除外されます。$2^n$テストケースごとの操作。 

エッジケースは、最小の要素が順列の後半で発生する場合に現れます。 たとえば、次のように考えてみましょう`[5,4,3,2,1]`。 常に後ろに追加する場合、最初の要素は 5 になり、非常に大きな接頭辞が生成されますが、最適な辞書編集順序は次のとおりです。`[1,2,3,4,5]`。 極小値では別の微妙な問題が発生します。`[3,1,2]`。 次に小さい要素を常に先頭に追加するという素朴で貪欲なアプローチでは、次のような結果が生じる可能性があります。`[1,3,2]`または`[1,2,3]`。 すべてのステップでシーケンスが最小であることを保証するには、慎重に推論する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、前後の挿入のすべてのシーケンスが試行されます。 のために$n=10^5$、これには必要です$2^n$これは完全に不可能です。 もう少し賢いアイデアは、現在の両端キューの終了に基づいてメモ化を使用して再帰的にバックトラッキングすることですが、それでも$O(n^2)$状態空間では遅すぎる可能性があります。 

重要な洞察は、残りのサフィックス内の最小の要素が常に両端キューのできるだけ早くに配置される必要があるということです。 小さな要素が表示されたら、すでに追加されている大きな要素の前にそれを配置する位置 (前または後ろ) に挿入することが常に有利です。 順列の場合、配置されていない最小の要素は次の場所にあります。$O(1)$ポジションを前処理する場合の時間。 

これを形式化できます。順列を反復するときに、ウィンドウを維持します。`[l, r]`辞書編集上の最小限の順序を維持しながら、前または後ろに追加できる連続した要素を表します。 残りの範囲内の最小要素を特定するたびに、それを適切な順序で結果に追加し、すべての要素が配置されるまでウィンドウを拡張します。 

これは、単純な線形時間の貪欲な解決策につながります。常に、残っている最小のプレフィックス (左から) を取得し、それを両端キューに追加し、順列がなくなるまで繰り返します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適な貪欲さ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのポインタを初期化します。`l = 0`そして`r = n-1`、順列内の未処理の要素の現在の範囲を表します。 
2. 現在のウィンドウ内の最小限の要素を特定します。`[l, r]`。 
3. 極小要素が左端にあるか右端にあるかを確認します。 左側にある場合は、すべての連続する最小要素を左から両端キューに追加します。 右側にある場合は、すべての連続する最小要素を右から追加します。 
4.アップデート`l`そして`r`追加したばかりの要素を超えてウィンドウを縮小します。 
5. すべての要素が両端キューに配置されるまで、手順 2 ～ 4 を繰り返します。 

これが機能する理由: 各ステップで、次に小さな未配置要素ができるだけ早く配置されることが保証されます。 それ以外の選択をすると、小さい要素の配置が遅れるか、大きい要素が小さい要素の前に配置され、辞書編集的により大きなシーケンスが生成されます。 連続展開により、順序を崩さずに等しいまたは連続した最小要素を確実に配置できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        l, r = 0, n - 1
        result = deque()
        while l <= r:
            # find smallest element in current range
            mn = min(p[l:r+1])
            # place minimal contiguous elements from left
            if p[l] == mn:
                while l <= r and p[l] == mn:
                    result.append(p[l])
                    l += 1
                    if l <= r:
                        mn = min(p[l:r+1])
            else:
                # minimal is at right
                while l <= r and p[r] == mn:
                    result.appendleft(p[r])
                    r -= 1
                    if l <= r:
                        mn = min(p[l:r+1])
        print(' '.join(map(str, result)))

if __name__ == "__main__":
    solve()
```コードでは、残りのスライスで最小限の要素を繰り返し見つけ、現在の位置に基づいてそれを左側に配置するか右側に配置するかを決定します。 の`deque`操作により、両端で O(1) 挿入が可能になります。 の選択`append`対`appendleft`辞書編集上の最小性を保証します。 

微妙なところがアップデート中`mn`要素を配置した後、残りの範囲内の新しい最小値は異なる可能性があるためです。 

## 実用的な例

 ### 例 1

 入力:`[3,1,2,4]`| ステップ | l | r | ん | デック状態 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 3 | 1 | 空 |
 | 1 | 0 | 3 | 1 | 追加左 1 → [1] |
 | 2 | 1 | 3 | 2 | 追加 2 → [1,3,2] |
 | 3 | 2 | 3 | 3 | 3 を追加 → [1,3,2,4] |

 デク`[1,3,2,4]`辞書編集的には最小限です。 

### 例 2

 入力:`[3,2,1]`| ステップ | l | r | ん | デック状態 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 2 | 1 | 追加左 1 → [1] |
 | 1 | 0 | 1 | 2 | 追加左 2 → [2,1] |
 | 2 | 0 | 0 | 3 | 追加左 3 → [3,2,1] |

 最小限の位置に基づいて配置を反転すると、`[1,2,3]`最終出力で。
