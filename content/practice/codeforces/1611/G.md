 ## 解決策
 ## 問題の理解

 次のサイズの長方形グリッドが与えられます。$n \times m$, ここで、各セルにはキャンディー (「1」) が含まれるか、空 (「0」) のいずれかが含まれます。 ロボットは、一番上の行の任意のセルから開始し、グリッドから離れるまで左下または右下に斜めに移動できます。 途中で出会ったあらゆるキャンディーを集めます。 Polycarp は、最上列に最小限の数のロボットを配置して、すべてのキャンディーを収集したいと考えています。 

入力は複数のテスト ケースを提供し、それぞれがグリッドを指定します。 出力はテスト ケースごとに 1 つの整数である必要があり、すべてのキャンディーを消去するために必要な最上段のロボット配置の最小数を示します。 

制約は重要です。 すべてのテスト ケースにわたるセルの合計数が次を超えないこと$10^6$、各次元は少なくとも 2 です。これにより、セルの数に関して線形または線形に近いアルゴリズムが制限されます。 一番上の行のセルごとに考えられるすべてのロボット パスを単純にシミュレーションすると、各パスに次の処理が含まれる可能性があるため、時間がかかりすぎます。$O(n)$移動し、最大で$m$プレースメントごとの開始位置。 エッジ ケースには、キャンディーのないグリッド (出力 0)、1 つの隅にのみキャンディーがあるグリッド、またはすべてのキャンディーが対角線に沿って並んでいる場合が含まれます。 不注意なアルゴリズムは、列ごとに 1 つのパスを想定するか、左右の対角線を適切に処理できない可能性があります。 

## アプローチ

 ブルートフォースアプローチは、可能な限り最上行の開始セルをすべて試し、ロボットの経路をシミュレートし、収集したキャンディーを削除することを、グリッドが空になるまで繰り返すことです。 正しいのですが、必要な場合もあります$O(n \cdot m \cdot k)$どこでの操作$k$ロボットの配置数です。 100 万個のセルを使用すると、これは$10^9$最悪の場合、動作が非常に遅くなります。 

重要な洞察は、ロボットの動きが対角線に沿って制限されているということです。キャンディーが位置にあります。$(x, y)$最上行列から開始するロボットのみが収集できます$y - (x-1)$または$y + (x-1)$(範囲内であると仮定して)。 上の行の列ごとに、対角線を介して到達できる下のセルの範囲を計算できます。 次に、問題は貪欲な間隔のカバーに帰着します。つまり、各ロボットの配置がキャンディーのサブセットを「カバー」します。 一番左の覆われていないキャンディーからスイープし、1 回のパスでできるだけ多くのキャンディーをカバーできるようにロボットを最適に配置し、それを繰り返すことができます。 

問題を一番上の行の間隔に変換すると、複雑さはパスの総数ではなく、キャンディーの数で線形になり、次の結果が得られます。$O(n \cdot m)$各テストケースの合計操作。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m * k) | O(n * m) | 遅すぎる |
 | 最適 | O(n * m) | O(n * m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`top_range`長さの`m`、各上の行の列について、対角線上に到達できる最も遠い左と右の下の行の列を表します。 
2. グリッド内のすべてのキャンディーを繰り返します。 キャンディーごとに、`(i, j)`、ロボットが到達できる最上行の列のセットを計算します。 これは、行オフセットによって列インデックスを左または右にシフトすることで得られます。有効な開始列は次のとおりです。`j - (i-1)`に`j + (i-1)`に固定されている`[0, m-1]`。 
3.アップデート`top_range`ロボットが最上行の各位置から到達できる最大列と最小列を記録します。 
4. すべての間隔を開始列で並べ替えます。 
5. 貪欲なカバー戦略を使用します。カバーされていない左端の列から開始し、カバレッジを右端に拡張する最上行の列にロボットを配置し、次のカバーされていないキャンディーに移動します。 
6. すべてのキャンディーが覆われるまで、ロボットの配置ごとにカウンターをインクリメントします。 
7. テストケースのカウンターを出力します。 

機能する理由: すべてのキャンディーは、最上行の配置に対応する一定の間隔でカバーされる必要があります。 現在の覆われていないキャンディーから最も右側にカバレッジを拡張する配置を貪欲に選択することで、配置の数を最小限に抑えます。これは、カバレッジをそこまで拡張しない配置では、後で追加のロボットの配置が必要になるためです。 この不変条件により、最適な解決策が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        input()  # skip blank line
        n, m = map(int, input().split())
        grid = [input().strip() for _ in range(n)]
        
        if all(cell == '0' for row in grid for cell in row):
            print(0)
            continue
        
        intervals = []
        for i in range(n):
            for j in range(m):
                if grid[i][j] == '1':
                    l = max(0, j - i)
                    r = min(m - 1, j + i)
                    intervals.append((l, r))
        
        intervals.sort()
        ans = 0
        farthest = -1
        i = 0
        while i < len(intervals):
            curr_end = farthest
            while i < len(intervals) and intervals[i][0] <= farthest + 1:
                curr_end = max(curr_end, intervals[i][1])
                i += 1
            ans += 1
            farthest = curr_end
        print(ans)

solve()
```コードは最初に空のグリッドを個別に処理します。 キャンディーごとに、それに到達できる最上行の間隔を計算します。 左側の境界で並べ替えると、最小限のロボット配置ですべてのキャンディーを網羅する貪欲なスイープが可能になります。`farthest`現在のカバレッジ境界を追跡します。 内側のループは、ロボットの配置をコミットする前にカバレッジを最適に拡張し、最小限のパスを保証します。 境界クランプにより、エッジ キャンディのインデックス エラーが防止されます。

## 特殊なケース

 左上から右下への斜めのキャンディー 1 つ`(i,i)`同じ最上行のセルでカバーされます。 アルゴリズムは間隔を計算します`[0,2]`一番下のキャンディーについては、列 0 に貪欲に配置することですべてをカバーします。 出力は 1 です。コーナー キャンディーが遠く離れている場合、間隔は重なり合わず、複数の配置が強制されます。 クランプにより、ロボットを最上列の外で起動しようとすることがなくなります。 完全に空のグリッドの場合、アルゴリズムは直ちに 0 を出力し、不必要な計算を回避します。
