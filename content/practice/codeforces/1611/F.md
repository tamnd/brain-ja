 ## 解決策
 ## 問題の理解

 この問題には、固定金額で開始し、学生の列に対応する必要がある ATM のシミュレーションが含まれます。 各生徒は、ATM からプラスの金額を入金するか、マイナスの金額を引き出します。 ATM を運営する Polycarp は、列のどの時点からでも学生へのサービスを開始することができ、ATM が引出しに応じられなくなると永久に停止します。 このタスクは、完全にサービスを受けることができる最も長く連続する生徒のサブシーケンスを見つけて、このサブシーケンス内の最初と最後の生徒のインデックスを出力することです。サービスを提供できる生徒がいない場合は -1 を出力します。 

入力は複数のテスト ケースで構成され、それぞれが生徒の数、ATM の初期残高、トランザクション リクエストのシーケンスを指定します。 この制約により、テスト ケースあたり最大 200,000 人の学生と最大 10,000 のテスト ケースが許可されますが、合計は`n`すべてのテスト ケース全体で 200,000 を超えません。 これにより、テスト ケースあたりの複雑さが O(n²) のアプローチは即座に除外されます。最悪の場合、制限時間を大幅に超える約 4×10¹⁰ の操作を実行することになるからです。 O(n) または O(n log n) のアプローチが実現可能です。 主なエッジ ケースは、ATM 残高が最初に早期引き出しに不十分な場合、引き出しの前に入金が発生した場合、またはシーケンスに引き出しとして扱われてはならないゼロが含まれている場合に発生します。 

たとえば、次のシーケンスを考えてみましょう`[-5, 10, -3]`の初期残高で`4`。 最初の生徒から開始する単純な実装は、最初の引き出しが残高を超えるため失敗します。 正しいアプローチは、最初の生徒をスキップし、次の 2 生徒を処理し、後続のインデックスを返すことです。`2 3`。 

## アプローチ

 ブルートフォース手法では、考えられるすべての開始生徒を考慮し、連続するサブシーケンスごとに ATM をシミュレートし、最も長い有効なサブシーケンスの長さを追跡します。 このアプローチはあらゆる可能性を明示的にチェックするため、正しいことが保証されます。 ただし、n=200,000 の最悪の場合、すべてのサブシーケンスの長さを合計すると、約 2×10¹⁰ の演算が実行されることになり、2 秒以内には実行できません。 

重要な洞察は、ATM の残高と引き出しを注意深く追跡することで、問題が 1 パスのスライディング ウィンドウにまで軽減されるということです。 ATM が引出しを処理できなくなると、その引出しを含むその後の手続きは無効になります。 プラスの入金は ATM 残高を増やすだけで、その後の利用は制限されませんが、マイナスの引き出しはウィンドウを強制的にシフトさせる可能性があります。 これは当然、2 ポインター アプローチを使用するか、効率を高めるためにプレフィックス合計と組み合わせてウィンドウ内の最大のマイナス トランザクションを追跡することを示唆しています。 このソリューションは、実行残高を維持し、残高がマイナスになる場合に候補開始点を動的に更新します。 連続するセグメントに焦点を当て、累積合計の特性を活用することで、テスト ケースあたりの直線的な時間を達成できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | スライディング ウィンドウ / プレフィックス合計 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのポインターを初期化します。`start`0 は、提供されるサブシーケンスの潜在的な開始を表し、`max_len`最長の有効なサブシーケンスの長さを格納する場合は 0 として格納します。 追跡`max_start`そして`max_end`for the final output.
 2. インデックスを使用して生徒を反復処理します。`i`を維持し、`balance`ATM 開始金額に初期化された変数`s`。 
3. 各生徒に取引額を加算します。`a[i]`に`balance`。 もし`a[i]`が正の場合、ATM 残高が増加します。 マイナスの場合は、次のことを確認してください。`balance`撤退後はマイナスになる。 
4. もし`balance`ゼロを下回ると、この学生は現在の授業から始めることができません`start`。 動く`start`に`i + 1`そしてリセット`balance`に`s`、事実上、次の生徒を新しい候補者のスタートとして考慮します。 
5. 有効なトランザクションが発生するたびに、現在のウィンドウが`i - start + 1`を超える`max_len`。 そうなった場合はアップデートしてください`max_len`、`max_start`、 そして`max_end`現在のウィンドウに移動します。 
6. すべての生徒を処理した後、次の場合は`max_len`0のまま、印刷`-1`。 それ以外の場合は、印刷します`max_start + 1`そして`max_end + 1`0 ベースのインデックス付けから 1 ベースのインデックス付けに変換します。 

機能する理由: このアルゴリズムは、候補ウィンドウ内で ATM 残高が決してマイナスにならないことを保証し、引き出しができない場合にのみ開始をシフトすることで、最大の連続セグメントを効率的に識別します。 ポジティブ トランザクションはウィンドウを無制限に拡張し、実行可能な最長のサブシーケンスが見つかることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, s = map(int, input().split())
        a = list(map(int, input().split()))
        max_len = 0
        max_start = max_end = -1
        start = 0
        balance = s
        for i in range(n):
            balance += a[i]
            if balance < 0:
                start = i + 1
                balance = s
            else:
                if i - start + 1 > max_len:
                    max_len = i - start + 1
                    max_start = start
                    max_end = i
        if max_len == 0:
            print(-1)
        else:
            print(max_start + 1, max_end + 1)

if __name__ == "__main__":
    solve()
```コードは、説明どおりにポインターとバランスを初期化します。 残高がマイナスになると、`start`そしてバランスをリセットして無効なシーケンスを回避します。 長さチェックにより、最も長い有効なサブシーケンスのみが記録されることが保証されます。 1 から始まるインデックスへの変換は、出力形式を一致させるために重要です。 リセットする`balance`引っ越した後`start`新しい候補セグメントがそれぞれ ATM の初期合計で始まることを保証します`s`。
