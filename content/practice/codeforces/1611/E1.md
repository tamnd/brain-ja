 ## 解決策
 ## 問題の理解

 迷路は、部屋 1 をルートとする方向のないツリーです。ヴラドは部屋 1 から開始し、部屋 1 ではない任意のリーフ ノードに到達したいと考えています。リーフとは、隣接する廊下が 1 つだけある任意のノードです。 

同時に、複数の友人がすでに別のノードに配置されています。 毎秒、ヴラドと友人全員が滞在するか、隣接するノードに移動することができ、全員が同時に移動します。 ヴラドがノードに着地するか、同時にまたはそれより早く友人がいるエッジを通過すると、ヴラドは即座に負けます。 

問題は、友人たちがどのように動いても、ヴラドが安全に葉に到達できるような戦略を選択できるかどうかです。 

重要な側面は敵対的な動きです。ヴラドを止めるために友人たちは完全に協力しますが、ヴラドは自分の道を選択します。 これにより、問題は、ヴラドに、友人が傍受するよりも厳密に速く到達できる「逃げ葉」が少なくとも 1 枚あるかどうかを確認することに変わります。 

制約は十分に大きいため、テスト ケースごとにどのような解も線形または線形に近いものでなければなりません。 すべてのテストにわたるノードの合計は最大 2 × 10^5 であるため、合計 O(n) または O(n log n) のアプローチが必要です。 移動のシミュレーションやパスごとのチェックは、ツリー全体の距離を計算する必要があるため、時間がかかりすぎます。 

友達が同時に移動することを無視すると、微妙な失敗のケースが発生します。 

たとえば、ヴラドが距離 5 離れた葉を見て、友人が距離 6 離れている場合、移動は並行して発生し、傍受は端点だけでなくパスに沿って発生する可能性があるため、ヴラドが勝つと言うだけでは十分ではありません。 素朴で貪欲な「葉までの距離を比較する」ことは、友人からの複数のソースの最短経路を慎重にモデル化しない限り失敗する可能性があります。 

もう 1 つの特殊なケースは、ルートがリーフに隣接している場合です。 ヴラドはすぐに逃げようとするかもしれませんが、友人が十分近くから始めれば、たとえ最初は葉の上にいなかったとしても、最初のステップで迎撃する可能性があります。 

## アプローチ

 強引なアイデアは、すべてのステップでヴラドとすべての友人の両方をシミュレートすることです。 私たちは、ヴラドに対して可能なすべての動きを試し、友人に対して可能なすべての反応を試し、ゲーム ツリーを効果的に探索します。 枝刈りを行ったとしても、各ノードは段階的に分岐し、木の高さは O(n) になる可能性があるため、これは爆発的になります。 これはすぐに指数関数的に増加します。 

重要な観察は、友達が個別に最適な戦略を独自に選択しているわけではないということです。 代わりに、集合的に各ノードにどれだけ速く到達できるかのみを考慮します。 すべての友人が同時に移動するため、すべての友人がノードに到達できる最小時間を計算できます。 これは、重み付けされていないツリー上の古典的なマルチソース最短経路問題であり、すべてのフレンドから開始する BFS によって解決されます。 

各ノードでの敵の最も早い到着時間が分かると、ヴラドの問題はノード 1 からの単一ソース BFS に減ります。ヴラドは、自分の到着時間が友人の到着時間よりも厳密に短いノードを安全に移動することができます。 この制約の下で Vlad がいずれかのリーフ ノード (ノード 1 を除く) に到達すると、Vlad が勝ちます。 

問題は、グラフ上の時間制約フィールドの下での到達可能性をチェックすることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースゲームシミュレーション | 指数 | 高 | 遅すぎる |
 | マルチソース BFS + 制約付き BFS | テストあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべての友人の位置で初期化された BFS を使用して、友人がすべてのノードに到達できる最も早い時間を計算します。 これにより距離配列が得られます`distF`。 

このステップが機能するのは、すべてのエッジの重みが等しいためです。そのため、BFS は複数のソースからの最短パスを同時に正しく計算します。 
2. Vlad に対してノード 1 から BFS を実行し、彼の到着時間を追跡します。`distV[u]`。 
3. Vlad の BFS 中は、ネイバーへの遷移のみを許可します`v`もし`distV[v] < distF[v]`。 

この条件により、友人がそのノードを占領または傍受できる前に、ヴラドが厳密に到着することが保証されます。 
4. Vlad がノード 1 ではないリーフ ノード (次数 1) に到達した場合、すぐに彼が勝てると結論付けます。 
5. このようなリーフに到達せずに BFS が終了した場合、Vlad は脱出を保証できません。 

### なぜ効果があるのか

 重要な不変条件は、Vlad が訪問するすべてのノードに、どの友人よりも厳密に早く到達するということです。 友人は彼をブロックするために最適に移動するため、遅くともヴラドまでに友人がノードに到達できる場合、そのノードは安全ではありません。 BFS 制限は、考えられるすべての敵対戦略に対してグローバルな安全条件を強制し、ゲームを到着時間の静的な比較に崩壊させます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        line = input().strip()
        while line == "":
            line = input().strip()
        n, k = map(int, line.split())

        friends = list(map(int, input().split()))
        g = [[] for _ in range(n + 1)]

        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        INF = 10**18
        distF = [INF] * (n + 1)
        q = deque()

        for f in friends:
            distF[f] = 0
            q.append(f)

        while q:
            u = q.popleft()
            for v in g[u]:
                if distF[v] == INF:
                    distF[v] = distF[u] + 1
                    q.append(v)

        distV = [-1] * (n + 1)
        q = deque([1])
        distV[1] = 0

        ans = False

        while q:
            u = q.popleft()

            if u != 1 and len(g[u]) == 1:
                ans = True
                break

            for v in g[u]:
                if distV[v] == -1:
                    nd = distV[u] + 1
                    if nd < distF[v]:
                        distV[v] = nd
                        q.append(v)

        print("YES" if ans else "NO")

if __name__ == "__main__":
    solve()
```この解決策では、問題を 2 つの BFS パスに分割します。 1 つ目は、敵が各ノードをどれだけ早く支配できるかを計算し、2 つ目は、Vlad が厳密に早くリーフに入ることができるかどうかをチェックします。 

微妙な実装の詳細は、厳密な不等式です。`nd < distF[v]`。 友人と同時に到着しても傍受されるため、平等は安全ではありません。 

もう 1 つの重要な点は、葉を正しく検出することです。 Vlad が勝つためには別のリーフに到達する必要があるため、たとえ小さなツリーで次数 1 を持っていたとしてもノード 1 を明示的に除外します。 

## 実用的な例

 ### 例 1

 入力:```
3 1
2
1 2
2 3
```ノード 2 の友人からの最初の BFS は次のようになります。```
distF[2]=0, distF[1]=1, distF[3]=1
```ヴラド BFS が開始します:```
distV[1]=0 → can go to 2 (but 1 < 0 is false, so blocked)
```そのため、ヴラドはどこへでも安全に移動することができません。 

| ステップ | ノード | 距離 | 状態 |
 | --- | --- | --- | --- |
 | 開始 | 1 | 0 | ルート |
 | 試して2 | 2 | ブロックされました | 1 < 0 偽 |

 Vlad がすぐに中央で制御されるため、出力は NO になります。 

### 例 2

 入力:```
5 1
5
1 2
2 3
3 4
4 5
```友達は 5 から始まるため、距離は次のようになります。```
distF = [INF, 4, 3, 2, 1, 0]
```ヴラド BFS:```
1 -> 2 -> 3 -> 4
```彼は時刻 3 にノード 4 に到着しますが、distF[4] = 1 であるため、そこでブロックされます。 

彼はそれ以上先に進むことができません。 

これは、友人が出口に近い場合、たとえ長い道でも安全ではないことを示しています。

 ## 特殊なケース

 エッジ ケースの 1 つは、友人がノード 1 に隣接して開始する場合です。この状況では、`distF[1] = 1`, そのため、ヴラドは友人からの距離が 1 以下の隣人に安全に移動することはできません。 厳密な不等式は最初の層で失敗するため、BFS はすべての即時移動を正しくブロックします。 

もう 1 つのケースは、複数の葉が異なる深さに存在する場合です。 アルゴリズムは浅い葉や深い葉を好みません。 代わりに、到達可能な安全なリーフを自然に見つけます。 「最も近いリーフ」は安全ではないが、わずかに遠いリーフは安全である可能性があり、ノードごとの安全性の比較のみがこの区別を捉えるため、単純なリーフへの最短パスのアプローチはここでは失敗します。 

最後の微妙なケースは、ヴラドと友人が異なる経路を通って同時にノードに到着する可能性がある場合に発生します。 厳密な不等式により平等を受け入れることができなくなり、ノードでのみではなく移動中の傍受が正しくモデル化されます。
