 ## 解決策
 ## 問題の理解

 自分自身を指すルートを除き、各頂点がその親へのポインターを持つツリーが与えられます。 この親配列`b`ツリーを明確にエンコードします。 それに加えて、順列もあります`p`私たちの目標は、頂点がルートからの距離でソートされたときに順列と正確に一致するように、各エッジに正の整数の重みを割り当てることです。`p`。 頂点の距離は、ルートからの一意のパスに沿った重みの合計です。 

制約は重要です。 頂点の数はテスト ケースごとに最大 200,000、テスト ケースは最大 10,000 まで可能ですが、合計は`n`すべてのテストの上限は 200,000 です。 これは、各頂点を O(1) または O(log n) 時間で処理する必要があることを意味します。 すべての順列またはパスを明示的に試行するアルゴリズムは機能しません。 

厄介なエッジケースは、順列が次の場合に発生します。`p`ツリー階層を尊重しません。 たとえば、子が親の前に表示される場合、`p`の場合、距離は常にルートから下に向かって増加するため、子の距離を親の距離よりも小さくする正の重みを割り当てる方法はありません。 複数のノードが同じ親を共有する場合、つまりノード内の相対的な順序が異なる場合、別の微妙な問題が発生します。`p`エッジの重みは一意に決定されるため、違反があると割り当てが不可能になります。 たとえば、`b = [1,1,1]`そして`p = [2,3,1]`、ノード 1 はルートですが、最後に来ます。`p`。 ルートの距離は常に 0 でなければならないため、これは不可能です。 

## アプローチ

 ブルートフォースアプローチでは、重みの割り当てを繰り返し試行し、おそらく各エッジのすべての整数を試し、次に距離を計算して順列と照合することを試みます。`p`。 これは、指数関数的な数の割り当てを調べる必要があるため、明らかに実行不可能です。n=10 の単一のテスト ケースですら、この方法では処理できません。 

重要な観察は、距離は次の順序に従って厳密に増加する必要があるということです。`p`。 任意のノードに対して`u`、その距離は親の距離より大きくなければなりません`b[u]`。 各ノードの距離を次のように維持すると、`dist[u]`、エッジの重みを割り当てることができます`w[u] = dist[u] - dist[b[u]]`。 この重みは正の値でなければなりません。 したがって、有効な割り当ての場合、次の各ノードは`p`親の後に来る必要があります`p`。 親がその子よりも後に出現する場合、`p`、割り当ては不可能です。 親が先に来ることがわかったら、割り当てることができます`dist[u] = dist[b[u]] + increment`、 どこ`increment`は少なくとも 1 であり、次の位置の差になる可能性があります。`p`順列に従って厳密に距離が増加するようにします。 この洞察により、問題は線形スキャンに帰着します。`p`そして重みを決定するための簡単な算術。

 ## アルゴリズムのチュートリアル

 1. ルートを特定します。 反復処理`b`そしてインデックスを見つけてください`r`どこ`b[r] == r`。 セット`dist[r] = 0`そして`w[r] = 0`。 
2. マッピングを構築する`pos`頂点からその位置まで`p`。 これにより、O(1) での順序を確認できます。 
3.初期化`dist`ゼロの配列として、および`w`ゼロの配列として。 
4. 各頂点を反復処理します。`v`順列の中で`p`2番目の要素から始めます。 させて`par = b[v]`。 もし`pos[par] >= pos[v]`、親は子の後に来るか、子の同じ位置に来ます。`p`、それは不可能です。 この場合、出力`-1`。 
5. それ以外の場合は、割り当てます`dist[v] = pos[v] - pos[par] + dist[par]`。 エッジの重みを設定する`w[v] = dist[v] - dist[par]`。 これにより保証されます`w[v] > 0`そして距離は正しく増加します。 
6. すべての頂点を処理した後、`w`配列を解決策として使用します。 

なぜ機能するのか: 維持される不変条件は次のとおりです。`dist[par] < dist[child]`すべての親子ペアに対して、これはまさに順列に必要なものです。 常に位置の違いに基づいて重みを割り当てるため、厳密な不等式が成り立ちます。 親は常に子の前に現れるため、エッジの重みはゼロまたは負になりません。`p`。 これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))
        p = list(map(int, input().split()))

        pos = [0] * (n + 1)
        for idx, v in enumerate(p):
            pos[v] = idx

        w = [0] * n
        dist = [0] * n
        possible = True
        root = -1
        for i in range(n):
            if b[i] == i + 1:
                root = i + 1
                break
        dist[root - 1] = 0
        w[root - 1] = 0

        for v in p:
            if v == root:
                continue
            par = b[v - 1]
            if pos[par] >= pos[v]:
                possible = False
                break
            dist[v - 1] = dist[par - 1] + pos[v] - pos[par]
            w[v - 1] = dist[v - 1] - dist[par - 1]

        if not possible:
            print(-1)
        else:
            print(' '.join(map(str, w)))

if __name__ == "__main__":
    solve()
```この解法では、まずルートを決定し、その距離をゼロに初期化します。 の`pos`配列は頂点を順列内の位置にマップして、親子の順序をすばやく確認します。 距離は、次から導出される正の差を加算することによって計算されます。`pos`これにより、エッジの重みが正の値を維持し、置換順序が尊重されるようになります。 子が親より前にある場合は、次のように出力します。`-1`。
