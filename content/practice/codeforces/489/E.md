 ## 解決策
 ## 問題の理解

 川沿いに休憩ポイントがいくつかあります。 ポイント`i`の位置にあります`x[i]`絵画的価値がある`b[i]`。 旅行者は座標から始まります`0`そして、最も遠い最後の休憩ポイントで終了しなければなりません。 

旅行者がその位置から移動した場合`p`位置を決める`q`1 日で、その日に移動した距離は`q - p`。 彼の理想的な一日の距離は`l`、つまり、その日までに寄与したフラストレーションは次のとおりです。$$(q-p-l)^2.$$ルートとは、ある点で終わる一連の休憩ポイントの増加です。`n`。 選択したルートについては、$$F = \sum ( \text{daily distance} - l )^2$$は完全なフラストレーションであり、$$B = \sum b_i$$それは、訪れた休憩ポイントの完全な絵のような美しさです。 

最小化する量は$$\frac{F}{B}.$$出力はこの比率の値ではありません。 最適なルート自体を 1 つ出力する必要があります。 

最初の課題は、目標が比率であることです。 動的プログラミングでは通常、追加コストが処理されますが、ここでは分子と分母がパス全体に依存します。 

制約は二次動的計画法を可能にするのに十分小さいものです。 私たちはせいぜい`1000`休憩ポイント。 頂点が静止点であり、エッジが可能なジャンプを表すグラフには、約 100 万の有向エッジが含まれます。 アン`O(n²)`DP は完全に許容されますが、ルートの指数関数的な列挙は不可能です。 

微妙な点は、ルートが任意の休憩ポイントをスキップする可能性があることです。 もう 1 つの微妙な点は、絵のような美しさは訪問したポイントに対してのみ蓄積されますが、フラストレーションはジャンプごとに依存します。 地元で良いジャンプを貪欲に選択するアプローチは、簡単に失敗する可能性があります。なぜなら、絵のように美しいポイントがあれば、多少悪い旅行スケジュールが正当化される可能性があるからです。 

考慮する：```
n = 2, l = 10

(10, 1)
(20, 1000)
```両方のポイントを使用するとフラストレーションが発生します`0 + 0 = 0`、 比率`0`。 

ポイント 2 に直接進むとフラストレーションが発生します`(20-10)^2 = 100`、 比率`100/1000 = 0.1`。 

最適なルートは、両方のルートが同じ目的地で終了する場合でも、より多くのポイントを使用します。 

もう 1 つの簡単な間違いは、旅は座標から始まることを忘れることです`0`。 のために```
1 10
20 5
```距離をカバーできるのはその日だけ`20`、 ない`0`。 フラストレーションは、`(20-10)^2 = 100`。 

## アプローチ

 ブルートフォースソリューションでは、中間休憩ポイントのすべてのサブセットを列挙し、そのポイントで終了するすべての可能なルートをチェックします。`n`。 各ポイントは使用またはスキップされるため、大まかに次のとおりです。`2^(n-1)`ルート。 と`n = 1000`、これはまったく不可能です。 

比率目標は、古典的な最適化トリックを示唆しています。 最適な比率が何らかの方法でわかっているとします。`R`。 ルートが最適になるのは、次の場合です。$$\frac{F}{B} \le R.$$乗算`B > 0`与える$$F - R B \le 0.$$これにより、比率が加法式に変換されます。 

次に、候補値を固定することを想像してください。`C`。 ルートのコストを次のように定義します。$$F - C B.$$この式の最小値が負の場合、一部のルートは次の条件を満たします。$$\frac{F}{B} < C.$$最小値が正の場合、すべてのルートの比率が次の値よりも大きくなります。`C`。 

これにより、元の問題が二分探索に適した決定問題に変わります。 

固定の場合`C`、ルートコストは$$\sum \Big((x_i-x_j-l)^2\Big) - C \sum b_i.$$式はルートに沿って加算されます。 つまり、動的計画法を使用して最小値を計算できるということです。 

させて`dp[i]`点で終了するルートの最小変換コストになります。`i`。 

それから$$dp[i] = -C b_i + \min_j \left( dp[j] + (x_i-x_j-l)^2 \right),$$どこ`j < i`。 

開始位置`0`座標を持つ仮想ノードのように動作します`0`そしてコスト`0`。 

すべての遷移が検査されるため、複雑さは次のようになります。`O(n²)`DP 実行ごとに。 

最適な比率は二分探索によって見つかります`C`。 十分な精度でパスを取得した後、最後の DP 実行でパスが再構築されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n² log M) | O(n) | 承認済み |

 ここ`M`は答えの検索範囲です。 

## アルゴリズムのチュートリアル

 1. すべての座標と絵の美しさの値を保存します。 
2. 答えの二分探索`C`。 
3.固定の場合`C`、動的プログラミングを実行します。 
4. しましょう`dp[i]`の最小値を示します$$F - C B$$点で終わるすべてのルートの中で`i`。 
5. 開始座標の処理`0`仮想頂点として。 

スタートからポイントへの直接の移行`i`費用がかかる$$(x_i-l)^2 - C b_i.$$6. ペアごとに`j < i`、 リラックス$$dp[j] + (x_i-x_j-l)^2 - C b_i.$$訪問ポイントに相当します`i`ポイントの直後`j`。 
7. DP テーブルに記入した後、検査します。`dp[n]`。 

もし`dp[n] < 0`の場合、一部のルートは以下の比率を達成します。`C`, そのため、二分探索間隔を下方に移動します。 

それ以外の場合は上に移動します。 
8. 二分探索を約 60 回繰り返します。 倍精度はこれを簡単にサポートします。 
9. 結果の値を使用して、最後に DP を実行します。`C`。 
10. 遷移を計算する際に、最良の値を生成した前の遷移を保存します。 
11. 先行ポインタをポイントから逆方向にたどってルートを再構築します。`n`。 
12. 再構築されたシーケンスを反転して印刷します。 

### なぜ効果があるのか

 任意の固定値の場合`C`、DP は次のように計算します。$$\min_{\text{route}} (F - C B).$$この最小値が負の場合、一部のルートは次の条件を満たします。$$F - C B < 0,$$これは以下と同等です$$\frac{F}{B} < C.$$最小値が負でない場合、すべてのルートには少なくとも比率があります。`C`。 

したがって、最小変換コストの符号は、次のことを正確に答えます。`C`最適な比率を上回っているか下回っています。 二分探索は実行可能な最小の比率に収束します。 

最終的な DP は、最適な比率に任意に近い値で変換された問題を解決します。 標準的な分数計画法理論では、この値で変換された目的を最小化するルートはすべて、元の比率目的にとって最適なルートであることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, l = map(int, input().split())

    x = [0] * (n + 1)
    b = [0] * (n + 1)

    for i in range(1, n + 1):
        x[i], b[i] = map(int, input().split())

    def dp_run(C, restore=False):
        INF = 1e100

        dp = [INF] * (n + 1)
        parent = [-1] * (n + 1)

        for i in range(1, n + 1):
            best = (x[i] - l) ** 2 - C * b[i]
            par = 0

            for j in range(1, i):
                cand = dp[j] + (x[i] - x[j] - l) ** 2 - C * b[i]
                if cand < best:
                    best = cand
                    par = j

            dp[i] = best
            parent[i] = par

        if not restore:
            return dp[n]

        path = []
        cur = n

        while cur:
            path.append(cur)
            cur = parent[cur]

        path.reverse()
        return path

    lo = 0.0
    hi = 1e12

    for _ in range(70):
        mid = (lo + hi) / 2.0

        if dp_run(mid) < 0:
            hi = mid
        else:
            lo = mid

    path = dp_run(hi, True)
    print(*path)

if __name__ == "__main__":
    solve()
```重要なルーチンは、`dp_run(C)`。 候補者比率を固定する場合`C`、最小変換コストを計算します。 仮想開始位置はダイレクトトランジションで処理されます。$$(x_i-l)^2 - C b_i.$$明示的な頂点がありません`0`DP テーブルでは必須です。 

トランジションでは、以前のすべての休止点が考慮されます。 以来`n`だけです`1000`、二次ループは十分に小さいです。 

二分探索では、真の最適な比率が内部に存在するという不変条件が維持されます。`[lo, hi]`。 変換された最適値が負になるたびに、次のことがわかります。`mid`は答えより大きいため、上限は下に移動します。 

再構築の実行ではまったく同じ DP が使用されますが、最良の遷移を担当する先行者が保存されます。 前任者に続いて`n`逆の順序で最適なルートが得られます。 

よくある実装上の間違いは、最後の二分探索反復からの中点を使用して再構築することです。 最終的な上限の使用`hi`は検索全体を通して実行可能な側に留まるため、より安全です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 次のことを考慮してください。```
1 10
20 5
```ルートは1つだけです。 DP は計算します$$(20-10)^2 - C \cdot 5.$$開始位置が座標として正しく扱われる`0`、したがって、1 日あたりの距離は次のようになります。`20`。 復興の成果`1`。 

考慮する：```
2 10
10 1
20 1000
```両方の点を使用すると比率が得られます`0`。 直接ポイントに行く`2`収量比`100/1000 = 0.1`。 

DP は、その移行を通じて両方の可能性を比較します。 ルート`1 -> 2`変換されたコストを生み出す`-1001C`、直接ルートでは生成されます。`100 - 1000C`。 最適な比率に近い場合、最初の式は小さくなるため、再構成は次の値を返します。`1 2`。 

考慮する：```
3 10
10 1
11 1000
20 1
```貪欲な戦略はポイントを訪れる可能性があります`2`その巨大な絵の美しさのため。 民進党は地方の決定を下さない。 訪問ポイントによって生じる不十分なジャンプ距離を含む、完全なルート コストを評価します。`2`。 グローバルに最適な先行者のみが各状態で生き残るため、最終的なルートは正しいままになります。
