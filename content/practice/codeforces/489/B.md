 ## 解決策
 ## 問題の理解

 ダンサーのグループが 2 つあります。 男の子にはそれぞれスキル レベルがあり、女の子にはそれぞれスキル レベルがあります。 男の子と女の子は、スキル レベルの差が最大 1 である場合にのみペアにできます。各ダンサーは最大 1 つのペアに所属できます。 

課題は、できるだけ多くの有効な男の子と女の子のペアを形成することです。 

入力は 2 つの配列で構成されます。 最初の配列には男子のスキル レベルが含まれ、2 番目の配列には女子のスキル レベルが含まれます。 出力は、スキルの差が最大 1 である素のペアの最大数です。 

制約は非常に小さいです。 どちらのグループにも最大 100 人のダンサーが含まれるため、二次アルゴリズムでも十分に高速です。 これは、Hopcroft-Karp のような高度なマッチング アルゴリズムが必要ないことを意味します。 課題は、単純な貪欲な解決策を可能にする構造を認識することです。 

よくある間違いは、元の入力順序で貪欲にダンサーをペアにしてしまうことです。 入力内のダンサーの順序には意味がありません。 例えば：```
boys  = [4, 1]
girls = [2, 3]
```正解は2、ペアリングによる`(1,2)`そして`(4,3)`。 ソートされていない配列に対する左から右への貪欲スキャンでは、1 つのペアしか見つからない可能性があります。 

複数のダンサーが同じスキルを持っている場合、別の微妙なケースが発生します。```
boys  = [2, 2, 2]
girls = [1, 2, 3]
```正解は 3 です。順序を考慮せずに最初に利用可能な互換性のあるパートナーを常に選択するアルゴリズムでは、今後の一致が誤ってブロックされる可能性があります。 

3 番目のエッジ ケースは、より適切な一致が後で存在するため、一見有効な一致をスキップする必要がある場合です。```
boys  = [1, 2]
girls = [2, 3]
```最適な答えは 2. ペアリングボーイ`2`女の子と`2`初葉少年`1`比類のない。 ペアリング`(1,2)`そして`(2,3)`2つのペアを与えます。 ソリューションでは、このような競合を体系的に回避する必要があります。 

## アプローチ

 この問題を最も直接的に見る方法は、2 部マッチング問題として見ることです。 すべての男の子が、スキルの差が最大 1 であるすべての女の子に関係するグラフを作成します。次に、最大の一致を見つけます。 

すべての有効なペアがグラフ内の一致に対応するため、このアプローチは正しいです。 最大でも 100 人の男子と 100 人の女子であれば、標準的な拡張パス アルゴリズムは制限内で快適に実行できます。 

ただし、グラフの視点では重要なプロパティが隠されています。 相性はスキルの数値のみで決まります。 両方のスキル配列がソートされている場合、同様のスキルを持つダンサーがソートされた順序で隣接します。 

残った最小の少年がスキルを持っていると仮定します`b`、そして残った最小の女の子はスキルを持っています`g`。 

もし`|b - g| ≤ 1`、ペアリングは常に安全です。 どちらのダンサーも、より小さなスキルを持った人を待っていては、より大きな答えを生み出すことはできません。誰も存在しないからです。 

もし`b < g - 1`、それから男の子`b`今の女の子にも、その後の女の子にもマッチしません。 後の女の子は全員少なくともスキルを持っています`g`、したがって、それらとの違いは`b`はさらに大きいです。 その少年には決して匹敵するものはないので、私たちは彼を捨てるべきです。 

同様に、`g < b - 1`、今の彼女は絶対にマッチングできないので、捨てるべきです。 

この観察は、両方の配列をソートした後の 2 ポインター貪欲アルゴリズムに直接つながります。

 ## アルゴリズムのチュートリアル

 1. 男子のスキル配列と女子のスキル配列を読みます。 
2. 両方の配列を非降順で並べ替えます。 

並べ替えると、同様のスキル レベルを持つダンサーが互いに近くに表示されるため、ローカルな決定が全体的に正しいことが可能になります。 
3. 2 つのポインタを初期化します。`i`男の子用と`j`女の子の場合はどちらも0から始まります。 
4.初期化`answer = 0`。 
5. 両方のポインターが配列内にあるときに、現在のスキルを比較します。 
6. もし`abs(boys[i] - girls[j]) <= 1`、ペアを形成し、増加します`answer`、両方のポインタを進めます。 

このペアは有効であり、どちらかのダンサーを後のパートナーに残しても結果は改善されません。 
7. それ以外の場合、`boys[i] < girls[j]`、 前進`i`。 

今の男の子は今の女の子に匹敵するには弱すぎます。 後の女の子は全員少なくとも同じくらい強いので、この男の子は将来のペアに参加することはできません。 
8. それ以外の場合は次へ進みます`j`。 

対称的に、現在の女の子は現在の男の子に匹敵するには弱すぎるため、将来のペアには決して参加できません。 
9. 1 つのポインターが配列の最後に到達したら、停止して出力します。`answer`。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは最も小さい比類のない男の子と最も小さい比類のない女の子を検査します。 

スキルの差が最大 1 の場合、ペアリングしても最適な答えを減らすことはできません。 どちらのダンサーの将来のパートナーも、少なくとも現在の候補者と同じくらいのスキルを持っているため、試合を延期しても追加の機会を生み出すことはできません。 

1 人のダンサーが弱すぎて他のダンサーと一致しない場合、そのダンサーは反対にソートされた配列内の後のダンサーと一致することはできません。 すでにペアリングが不可能なため、破棄しても何も失われません。 

このアルゴリズムは、最適な解決策にまだ貢献できるダンサーを削除することはありません。 各決定により、将来のペアの達成可能な最大数が保存されます。 ポインターの位置を誘導することにより、最終的なカウントが最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    boys = list(map(int, input().split()))

    m = int(input())
    girls = list(map(int, input().split()))

    boys.sort()
    girls.sort()

    i = 0
    j = 0
    ans = 0

    while i < n and j < m:
        if abs(boys[i] - girls[j]) <= 1:
            ans += 1
            i += 1
            j += 1
        elif boys[i] < girls[j]:
            i += 1
        else:
            j += 1

    print(ans)

if __name__ == "__main__":
    solve()
```最初の部分は入力を読み取り、両方のスキル配列をソートします。 並べ替えは、貪欲な推論を有効にするための重要な前処理ステップです。 

変数`i`そして`j`常に最も小さな比類のない男の子と女の子を指します。 両方のグループに未処理のダンサーが含まれている間、ループは継続します。 

現在のダンサーに互換性がある場合、ペアが形成され、両方のポインターが前方に移動します。 各ダンサーは 1 つのペアのみに所属できるため、どちらも再度考慮する必要はありません。 

現在の男の子のスキルが現在の女の子のスキルより 1 以上小さい場合、男の子のポインタだけを進めるのが正しいです。 将来の女の子はさらに優れたスキルを持っているため、現在の男の子に匹敵するチャンスは残されていません。 

対称の場合は、女の子のポインターが進みます。 

すべての値が小さいため、オーバーフローの心配はありません。 一般的に間違いを引き起こす唯一の実装詳細は、2 ポインター スキャンを実行する前に並べ替えを忘れることです。

 ## 特殊なケース

 次のことを考慮してください。```
1
1
1
2
```スキルの差はちょうど 1 です。アルゴリズムは次のように比較します。`1`そして`2`、それがわかります`abs(1 - 2) = 1`、ペアを形成し、出力します`1`。 を使用した実装`< 1`の代わりに`<= 1`間違って出力されてしまう`0`。 

考慮する：```
2
4 1
2
2 3
```並べ替え後:```
boys  = [1, 4]
girls = [2, 3]
```アルゴリズムが最初に一致する`(1,2)`、その後一致します`(4,3)`、答えを生み出す`2`。 並べ替えを行わないと、貪欲なスキャンが次から開始される可能性があります。`4`そして1試合負ける。 

考慮する：```
3
2 2 2
3
1 2 3
```このアルゴリズムは、3 つのペアすべてを連続的に照合します。 ポインタは一致後に常に前に移動し、ダンサーが 2 回使用されることを防ぐため、値を繰り返しても特別な問題は発生しません。 

考慮する：```
2
1 1
2
5 5
```最初の比較は、`1`対`5`。 少年は弱すぎるため、アルゴリズムは少年ポインタを進めます。 2人目の男の子にも同じことが起こります。 ペアは形成されず、出力は次のようになります。`0`。 これは、スキルがはるかに劣っているダンサーを破棄することが安全である理由を示しています。
