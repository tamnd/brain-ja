 ## 解決策
 ## 問題の理解

 整数の配列が与えられているので、配列の位置を交換して、それを非減少順序に変換する必要があります。 興味深いのは、最小スワップ数が必要ないことです。 最大でも以下を含む有効なシーケンス`n`交換は受け付けております。 

出力はスワップ操作自体で構成されます。 印刷された順序でそれらを適用した後、配列はソートされる必要があります。 

配列の長さは最大 3000 です。これは十分に小さいため、`O(n²)`解決策は完全に受け入れられます。`3000² = 9,000,000`制限内に簡単に収まる操作。 高度なデータ構造や、`O(n log n)`テクニック。 

主な課題は値の重複にあります。 すべての値が個別である場合は、ソートされた配列内のターゲット位置に各値を単純にマップできます。 重複の場合、複数の位置に同じ値が含まれる可能性があるため、不注意なマッピングにより 1 つのオカレンスが複数のターゲット位置に割り当てられる可能性があります。 

考慮する：```
3
2 1 2
```ソートされた配列は次のとおりです。```
1 2 2
```値をマッピングするだけの場合`2`「ソートされた配列内の位置」には、2 つの有効な位置があります。 個々の発生を追跡せずにそれらを交換可能として扱うと、誤った交換が発生する可能性があります。 

もう 1 つのエッジケースは、すでにソートされた配列です。```
4
1 2 3 4
```正しい答えは次のとおりです。```
0
```一部の実装では、スワップが必要ない場合でも、不必要にスワップが実行されます。 

3 番目のケースは、すべての要素が等しい場合です。```
5
7 7 7 7 7
```繰り返しますが、答えにはスワップが含まれていない必要があります。 値の比較のみに基づくロジックでは、同一の要素の動きを発明することを避けなければなりません。 

## アプローチ

 強引なアイデアは、各位置に表示される最小の要素を繰り返し見つけて、それを所定の位置に置き換えることです。 ポジションについて`i`、サフィックスをスキャンします`i...n-1`、正しい要素を見つけて、必要に応じて 1 回の交換を実行します。 

このアプローチは正しいです。なぜなら、位置を固定した後だからです。`i`、その立場は二度と変わりません。 残念ながら、それには`O(n)`それぞれをスキャンします`n`ポジション、結果として`O(n²)`時間。 

興味深いことに、`O(n²)`ここではすでに十分に高速です。 本当の観察とは、漸近的な複雑性を改善することではなく、最大でも次のような結果を生み出すことです。`n`重複した値をきれいに処理しながら交換します。 

重要なアイデアは、配列のコピーをソートし、すべての要素の現在位置を維持することです。 位置決め時`i`にはまだ最終値が含まれていないため、ここにあるべき値を保持する位置を見つけて、2 つの位置を交換します。 

各スワップにより 1 つのポジションが永久に固定されます。 しかないので、`n`ポジションの場合、スワップの合計数は最大でも`n-1`。 

要素を見つけやすくするために、ペアを並べ替えます。`(value, original_index)`。 これにより、重複する値が出現するたびに一意の ID が与えられます。 そうすれば、各要素はそれがどの最終位置に属するかを正確に知ることができます。

 ## アルゴリズムのチュートリアル

 1. すべての要素を元のインデックスとともに次のように保存します。`(value, index)`。 
2. これらのペアを値で並べ替えます。 並べ替え後、位置を決めます`i`この配列の は、最終的に位置を占める要素を表します`i`ソートされた順序で。 
3. 配列を作成する`pos`どこ`pos[original_index]`作業配列内のその要素の現在位置を保存します。 
4. 別の配列を作成する`cur`どこ`cur[position]`現在その位置を占めている元の要素を格納します。 
5. 位置を左から右に処理します。 
6. 位置で`i`、正しい要素がすでに存在するかどうかを確認してください。 正しい要素は、元のインデックスがソートされたペア リストの 位置に表示される要素です。`i`。 
7. 正しい要素がすでにその位置にある場合`i`、 続く。 
8. それ以外の場合は、次を使用して現在の位置を見つけます。`pos`。 
9. の 2 つの位置を交換します。`cur`のエントリを更新します。`pos`、スワップを記録します。 
10. すべての位置に指定された要素が含まれるまで続行します。 

交換するたびに、正しい要素が最終位置に配置されます。 その立場は二度と変わりません。 

### なぜ効果があるのか

 ソートされたリスト`(value, original_index)`ペアは、すべての値の出現ごとに一意の宛先を割り当てます。 重複したものであっても、元のインデックスが異なるため区別可能になります。 

ステップで`i`、正しい要素がまだ存在しない場合は、その要素を正確に位置に移動します。`i`。 交換後のポジション`i`ソートされた順序によって指定された要素が含まれます。 

後の操作は以上の位置にのみ影響するため、`i+1`、 位置`i`永遠に正しいままです。 この引数をすべての位置に対して繰り返すと、最終的には完全にソートされた配列が生成されます。 

各スワップで少なくとも 1 つの新しいポジションが固定されるため、スワップの数が超過することはありません。`n-1`、問題の要件を満たしています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    sorted_pairs = sorted((a[i], i) for i in range(n))

    cur = list(range(n))
    pos = list(range(n))

    swaps = []

    for i in range(n):
        target_id = sorted_pairs[i][1]

        if cur[i] == target_id:
            continue

        j = pos[target_id]

        swaps.append((i, j))

        x = cur[i]
        y = cur[j]

        cur[i], cur[j] = cur[j], cur[i]
        pos[x], pos[y] = pos[y], pos[x]

    print(len(swaps))
    for i, j in swaps:
        print(i, j)

solve()
```このソリューションでは値が直接再配置されることはありません。 代わりに、要素の元の位置を表す識別子を再配置します。 

配列`sorted_pairs`は、各元の要素が最終的な並べ替え順序でどこに属するかを決定します。 配列`cur`どの元の要素が現在各位置を占めているかを示します。`pos`逆マッピングを提供します。 

スワップが発生した場合、両方の構造を一貫して更新する必要があります。 どっちか更新忘れてる`cur`または`pos`これは最も一般的な実装ミスであり、今後の検索が即座に中断されます。 

アルゴリズムは位置を左から右に固定します。 一度位置を固定すると、再度その位置に触れることがなくなります。

 ## 特殊なケース

 値が重複する場合を考えてみましょう。```
3
2 1 2
```ソートされたペアのリストは次のようになります。```
(1,1) (2,0) (2,2)
```値の 2 つの出現`2`元のインデックスが異なるため、引き続き区別できます。 アルゴリズムは、1 つのコピーを位置 1 に割り当て、もう 1 つのコピーを位置 2 に割り当てます。あいまいさは存在しないため、結果の配列は正しく並べ替えられます。 

すでにソート済みの配列を考えてみましょう。```
4
1 2 3 4
```ソートされたペアのリストは現在の配置と一致します。 あらゆるポジションについて`i`、`cur[i]`は、すでに必要な元のインデックスと等しくなります。 スワップは記録されず、出力は次のようになります。```
0
```すべての要素を等しいとみなします。```
5
7 7 7 7 7
```を並べ替える`(value, index)`インデックスが異なるため、ペアの順序は維持されます。 すべての位置には指定された要素がすでに含まれているため、ここでも交換は発生しません。 アルゴリズムは当然のことながら演算を出力しません。 

これらのケースは、元のインデックスを通じて各オカレンスに一意の ID を割り当てることが、ソリューションを正しくするための重要な詳細である理由を示しています。
