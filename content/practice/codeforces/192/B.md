 ## 解決策
 ## 問題の理解

 私たちは、タイルが雨によって破壊されて歩行できなくなるまでに、反対派がタイルの大通りに沿って歩くことができる日数を決定するように求められています。 各タイルには、日数で測定される耐久性があります。 _aᵢ_ 日にはタイルはまだ無傷ですが、_aᵢ + 1_ 日には破壊されます。 移動は制限されています。タイル _i_ から、対戦相手はタイル _i+1_ または _i+2_ に移動できます。 最初または最後のタイルが破壊された場合、または最初のタイルから最後のタイルに到達できる一連のジャンプがない場合、ウォークは阻止されます。 

入力はタイルの数 _n_ の後に、各タイルが破棄された日を表すサイズ _n_ の配列 _a_ が続きます。 出力は単一の整数で、歩行がまだ実行可能な最後の日です。 

制約は小さく、_n_ ≤ 1000 および _aᵢ_ ≤ 1000 です。これにより、タイムアウトを気にすることなく、時間計算量がおよそ O(n²) までの解を得ることができます。 移動によって 1 つのタイルを飛び越えることができるため、主な課題は、考えられるすべてのパスをブロックする、破壊されたタイルの最大の連続ギャップを特定することです。 エッジ ケースには、最初と最後のタイルが同じである _n_ = 1 の場合や、単一のタイルの破壊により有効なパスが即座に妨げられるシナリオが含まれます。 

## アプローチ

 ブルート フォース アプローチでは、1 日目から毎日をシミュレートし、破壊されたタイルにマークを付け、貪欲または BFS メソッドを使用して最初のタイルから最後のタイルまでの走査を試みます。 正しいとはいえ、このアプローチでは各走査で最大 1000 日のチェックが必要となり、最悪の場合の複雑さは O(n²) になりますが、制約を考慮すると許容範囲ですが、不要です。 

重要な観察は、すべてが破壊された 3 つの連続したタイルのセグメントがある場合、歩行が不可能になるということです。 相手は 1 つのタイルを飛び越えることができるため、2 タイルのギャップは回避できますが、3 タイルのギャップではパスが完全にブロックされます。 したがって、歩行可能な最大日は、連続するタイルのすべての 3 つの要素の最小値になります。 また、最初と最後のタイルが破壊されるとすぐに開始または終了が妨げられるため、最初と最後のタイルを個別にチェックする必要があります。 

連続するトリプレットに焦点を当てることで、問題を毎日のシミュレーションからタイル配列の単純なスキャンに減らし、O(n) の解を生成します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (毎日シミュレーション) | O(n * max(aᵢ)) ≈ 10^6 | O(n) | 許容できるが非効率的 |
 | 最適 (連続するトリプレットをスキャン) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 変数を初期化する`max_day`無限に。 この変数は、有効なパスが存在する最後の日を保持します。 
2. タイルの耐久性の配列を繰り返し処理します。 連続するタイルの 3 つの要素 (タイル i、i+1、i+2) ごとに、それらの中で最小の破壊日を計算します。 アップデート`max_day`現在の値の最小値と、このトリプレットの最小値から 1 を引いたものです。マイナス 1 は、タイルが _aᵢ_ 日にはまだ無傷であるが、_aᵢ + 1_ 日に破壊されたという事実を説明します。 
3. 最初のタイルと最後のタイルを個別に確認します。 どちらかが _d_ 日に破壊された場合は、更新します`max_day`それぞれ min(max_day, a₁ - 1) または min(max_day, aₙ - 1) に設定します。 
4. 関連するタイルをすべてスキャンした後、印刷します。`max_day`。 

維持される不変条件は次のとおりです`max_day`は常に、重大な障害が発生する前の最後の日を表します。 これにより、タイルまたは連続するタイルの 3 つのタイルが使用できなくなった場合にのみ反対が失敗するため、正しさが保証されます。これはまさに私たちがチェックしていることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

# Handle trivial case of single tile
if n == 1:
    print(a[0] - 1)
    sys.exit()

max_day = float('inf')

# Check triplets
for i in range(n - 2):
    max_day = min(max_day, min(a[i], a[i + 1], a[i + 2]) - 1)

# Check first and last tiles
max_day = min(max_day, a[0] - 1)
max_day = min(max_day, a[-1] - 1)

print(max_day)
```このソリューションでは、まず単一タイルのエッジ ケースを処理します。 次に、連続するすべてのトリプレットをスキャンして、詰まりが発生した最も早い日を見つけます。 最後に、最初と最後のタイルが損なわれていないことを確認します。 1 を引くと、タイルが破壊しきい値に達した日でもまだ使用可能であることがわかります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | トリプレットとエッジのタイル配列上のシングル パス |
 | スペース | お(1) | max_day を追跡するための変数のみ。追加の構造はありません。 

n ≤ 1000 の場合、この線形スキャンは 2 秒の制限内で適切に実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    if n == 1:
        return str(a[0] - 1)
    max_day = float('inf')
    for i in range(n - 2):
        max_day = min(max_day, min(a[i], a[i + 1], a[i + 2]) - 1)
    max_day = min(max_day, a[0] - 1)
    max_day = min(max_day, a[-1] - 1)
    return str(max_day)

# Provided samples
assert run("4\n10 3 5 10\n") == "2", "sample 1"
assert run("5\n6 4 5 7 5\n") == "3", "sample 2"

# Custom cases
assert run("1\n10\n") == "9", "single tile"
assert run("3\n2 2 2\n") == "1", "all equal, triplet blocks on day 2"
assert run("4\n1 2 3 4\n") == "0", "first tile destroyed immediately"
assert run("5\n10 10 10 10 10\n") == "9", "all survive long, path ok"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1\n10 | 9 | シングルタイルケース |
 | 3\n2 2 2 | 1 | トリプレット破壊は早期にブロックします。 
| 4\n1 2 3 4 | 0 | 最初のタイルはすぐに破壊されます |
 | 5\n10 10 10 10 10 | 9 | 均一な長期耐久性、早期ブロックなし |

 ## 特殊なケース

 n = 1 の場合、最初と最後のタイルは同じです。 アルゴリズムは、使用可能な最後の日を正確に表す a[0] - 1 を返すことでこれを処理します。 

タイルのトリプレットの耐久性が他のタイルよりも低い場合、ループはすべてのトリプレットの中から最小値を見つけて、その点を超えてウォークを続行できないようにします。 たとえば、`[10,3,5,10]`、三つ子`[10,3,5]`パスを制限し、過大評価を正しく防ぎます。 

トリプレットがクリティカルになる前に最初または最後のタイルが破壊された場合、個別のチェックによって確実に`max_day`それに応じて更新されます。 これでシナリオが処理されます`[1,10,10]`、生産`0`最初のタイルはすぐに失敗するためです。
