 ## 解決策
 ## 問題の理解

 2 つの配列があります。`A`そして`B`。 内部の元の順序を維持しながら、2 つの配列の要素をインターリーブして、最終的な 1 つの配列を作成する必要があります。`A`そして内側`B`。 マージ後、すべての要素は、最終的な配列内の 1 から始まる位置を乗算した値を提供します。 目標は、総コストが可能な限り最小になるマージ順序を選択することです。 必要な出力には、ステートメントで示される形式のテスト ケース番号も含まれます。 

入力サイズにより、考えられるすべてのマージが試行されなくなります。 2 つの配列に長さがある場合`n`そして`m`、各マージは配列の 1 つが占める位置の選択に対応するため、有効なインターリーブは指数関数的に多く存在します。 届く長さで`100000`すべてのテストで到達する全長`10^6`、可能なマージオーダーの数によっては、いかなる解決策も不可能です。 要素ごとに 1 つの決定を行う線形時間手法が必要です。 

難しいのは、配列自体を並べ替える必要がないことです。 よくある間違いは、通常のマージ操作に似ているため、常に小さい方の現在の要素を取得することです。 右に移動すると位置乗数が増加するため、これは間違っています。 通常は、大きな値を先に配置する必要があります。 

たとえば、次のことを考えてみましょう。```
1
2 2
5 3
4 5
```最適なマージされた配列は次のとおりです。```
5 4 5 3
```費用は次のとおりです。```
1*5 + 2*4 + 3*5 + 4*3 = 40
```Small-First マージでは次の結果が得られます。```
4 5 5 3
```費用込み:```
1*4 + 2*5 + 3*5 + 4*3 = 41
```この違いは、より大きな番号 1 の位置を左に移動する方が、より小さい番号を同じ量だけ左に移動するよりも節約できるという事実から生じます。 

もう 1 つの特殊なケースは、値が等しい場合です。 例えば：```
1
1 1
7
7
```可能な両方のマージは同一です。```
7 7
```答えは次のとおりです。```
21
```厳密な比較を誤って使用するソリューションは、値が等しい場合に配列の 1 つを適切に使用しないため失敗する可能性があります。 

最後の境界ケースは、1 つの配列が早期に終了する場合です。 例えば：```
1
1 3
8
1 2 3
```選択した後`8`まず、残りの要素が元の順序で表示される必要があります。```
8 1 2 3
```答えは次のとおりです。```
8 + 4 + 6 + 9 = 27
```両方の配列に要素があり、残りのサフィックスを無視して要素を比較するだけの実装では、誤った結果が生成されます。 

## アプローチ

 直接的なブルート フォース ソリューションでは、すべての有効なマージが列挙されます。 マージごとに、結果のコストが計算され、最小値が維持されます。 考えられるすべての最終的な取り決めがチェックされるため、これは正しいです。 ただし、マージ回数は二項係数となります。`C(n+m,n)`、指数関数的に増加します。 小さな配列でもすでに多くの可能性が生まれているため、このアプローチでは指定された制限に対処できません。 

重要な観察は、異なる配列に由来する 2 つの隣接する要素を観察することで得られます。 最終的な配列内の 2 つの隣接する要素が次のようになると仮定します。`x`に続く`y`。 ポジションのコストへの貢献度`p`そして`p+1`は：```
p*x + (p+1)*y
```それらを交換すると、貢献度は次のようになります。```
p*y + (p+1)*x
```2 番目の配置は、まさに次のような場合に適しています。`x < y`。 言い換えれば、異なる配列の 2 つの使用可能な要素を交換できる場合は常に、大きい方が早く表示される必要があります。 

マージのどの時点でも、位置をすぐに決定できる要素は、2 つの配列の先頭にある現在未使用の要素だけです。 小さい方のフロント要素を選択すると、大きい方のフロント要素が 1 つ後の位置に強制的に配置されます。 これら 2 つの選択肢を交換すると、コストが改善されます。 したがって、最適な選択は常に、現在の 2 つのフロント要素のうち大きい方を取ることです。 

これは、最終的な貪欲アルゴリズムで使用されるのと同じ推論です。 ブルートフォース手法ではすべての可能な順序が探索されますが、交換引数は、すべての最適解が、各選択が利用可能なより大きな前要素を取るものに変換できることを示しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(n+m,n) * (n+m)) | O(n+m) | 遅すぎる |
 | 最適 | O(n+m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 両方の配列の最初の未使用要素のポインターから開始し、マージされた配列内の現在位置を次のように設定します。`1`。 
2. 両方の配列にまだ未使用の要素が含まれている間に、現在の前部の 2 つの値を比較します。 大きい方を選択し、その寄与を追加します`position * value`答えに移動し、対応するポインタを前に移動します。 

この選択が安全である理由は、前にある 2 つの値が、次に配置できる異なる配列の唯一の要素であるためです。 大きい値を後で配置した場合、2 つを交換するとコストが削減されます。 
3. 一方の配列が空になったら、もう一方の配列の残りの要素を元の順序で追加します。 それらの相対的な順序はすでに固定されており、それ以上の選択肢はありません。 
4. 完全にマージされた配列が完成するまで、要素を配置するたびに位置を増やし続けます。 

なぜ効果があるのか:

 不変条件は、貪欲な決定が行われるたびに、まったく同じプレフィックスを持つ最適なマージが存在するということです。 利用可能な 2 つのフロント要素を検討してください`x`そして`y`。 最適なマージによって小さい方が大きい方の前に配置される場合、どちらの要素も独自の配列の要素と交差できないため、これら 2 つの要素は最終的にこの順序で表示されます。 隣接する 2 つの選択肢を交換すると、大きい値が 1 つ左に移動することによってコストが変更されますが、これによって答えが増加することはありません。 この交換を繰り返すと、そのような悪い選択がすべて削除されるため、より大きな現在の要素を選択することで常に最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(a, b):
    i = 0
    j = 0
    pos = 1
    ans = 0
    n = len(a)
    m = len(b)

    while i < n and j < m:
        if a[i] >= b[j]:
            ans += pos * a[i]
            i += 1
        else:
            ans += pos * b[j]
            j += 1
        pos += 1

    while i < n:
        ans += pos * a[i]
        i += 1
        pos += 1

    while j < m:
        ans += pos * b[j]
        j += 1
        pos += 1

    return ans

def main():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        out.append(f"Case {case}: {solve_case(a, b)}")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```2つの指針`i`そして`j`2 つの元の配列で次に使用可能な要素を表します。 メイン ループは、ウォークスルーで説明されている貪欲な決定を正確に実行します。 比較には、`>=`の代わりに`>`答えに影響を与えることなく、同じ値が一貫して消費されるようにします。 

1 つの配列が使い果たされた後は、残りのループはオプションではありません。 残りの要素は依然としてコストに寄与しており、最初のループが停止した時点からその位置は増加し続けます。 

Python 整数は任意の精度で自動的に使用されます。これは、考えられる最大コストが 32 ビット整数の制限を超える可能性があるため便利です。

 ## 特殊なケース

 等しい値の場合、次のようになります。```
1
1 1
7
7
```アルゴリズムが比較する`7`そして`7`、次の理由により最初の配列を選択します。`>=`条件を取得し、残りの要素を取得します。 両方の貢献は同一であるため、順序は重要ではありません。 

1 つの配列が早く終了する場合:```
1
1 3
8
1 2 3
```アルゴリズムは最初に比較します`8`そして`1`、かかります`8`、最初の配列は空になります。 残りの値`1,2,3`次のような順序で出現する必要があります。```
8 1 2 3
```費用がかかる`27`。 

すべての値が等しい場合:```
1
3 3
0 0 0
0 0 0
```可能なすべてのマージのコストはゼロです。 貪欲な決定でも、すべての要素が 1 回だけ消費され、正しい結果が返されます。 

小さい要素を選択するほうが魅力的と思われる値の場合:```
1
2 2
5 3
4 5
```アルゴリズムが最初に選択する`5`以上`4`。 この選択により、最適なプレフィックスが作成されます。これは、より大きな値を後に配置すると乗数が増加し、より小さな値の乗数が減少するためです。 最終結果は`40`。
