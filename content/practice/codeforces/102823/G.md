 ## 解決策
 ## 問題の理解

 正の整数の配列があります。 1 回の操作で、配列のすべての要素が 1 だけ増加します。 タスクは、配列全体の最大公約数が 1 より大きくなるように必要な最小の演算数を見つけることです。 どれだけの操作を行ってもこれを達成できない場合は、報告する必要があります`-1`。 元の問題は、2018 年の中国大学プログラミング コンテスト、桂林会場からのものです。 

重要な部分は、すべての要素が同じ量だけシフトされるということです。 私たちが演奏したら`x`演算すると、配列は次のようになります。$$a_1+x,\ a_2+x,\ ...,\ a_n+x$$ある整数があるとします`d > 1`シフト後のすべての数値を除算します。 それから`d`また、任意の 2 つの要素の差を分割します。$$(a_i+x)-(a_j+x)=a_i-a_j$$付加価値がなくなってしまいます。 これは、最終的な gcd の可能な約数が要素間の元の差異によって完全に決定されることを意味します。 

制約により、最大で`n = 100000`要素と値は次のように大きくできます。`10^9`。 これにより、考えられる多くのシフトを試したり、すべての要素の考えられる多くの約数をチェックしたりすることが排除されます。 ソリューションでは、少量の追加の数理論作業のみを使用して、線形時間またはそれに近い時間で配列を処理する必要があります。 

主なエッジケースは、差異の構造から生じます。 すべての要素が同一の場合、差の gcd はゼロであり、ゼロを通常の値のように扱うと誤った答えが生じる可能性があります。 例えば：```
1
1
1
```正しい答えは次のとおりです。```
Case 1: 1
```1 回の操作の後、配列は次のようになります。`[2]`、その gcd は`2`。 差の約数のみを検索する不注意な解決策では、ゼロ以外の差が存在しないため、何も見つからない可能性があります。 

もう 1 つの重要なケースは、差の gcd が 1 である場合です。 例えば：```
1
3
2 5 9
```違いは次のとおりです。`3`そして`7`、その gcd は`1`。 正しい出力は次のとおりです。```
Case 1: -1
```シフトされた配列の公約数もこれらの差を除算する必要がありますが、1 より大きい数で両方を除算することはできません。 

最後のエッジケースは、gcd がすでに 1 より大きい場合です。 例えば：```
1
3
6 12 18
```答えは次のとおりです。```
Case 1: 0
```操作は必要なく、常に正のシフトを検索するソリューションでは最小の答えを見逃してしまいます。 

## アプローチ

 直接的なアプローチは、プロセスをシミュレートすることです。 試してみてもいいでしょう`x = 0, 1, 2, ...`、 追加`x`すべての要素に適用し、結果の配列の gcd を計算します。 考えられるすべての操作を昇順にチェックしているため、これは正しいことです。 

問題は、必要なシフト数について有用な上限がないことです。 1シフトのコストを確認するだけでも`O(n)`時間がかかり、多くのシフトを試すのはすぐに不可能になります。 最悪の場合、テストされる操作の数が非常に多くなり、許容範囲をはるかに超える複雑さが生じる可能性があります。 

重要な観察は、シフトによって差異が変化しないことです。 最終的な gcd が何らかの値の場合`d > 1`、その後、すべての違い`a_i - a_j`で割り切れる必要があります`d`。 させて：$$g = gcd(|a_2-a_1|, |a_3-a_1|, ..., |a_n-a_1|)$$考えられるすべての最終 gcd は、次の約数でなければなりません。`g`。 

今では問題ははるかに小さくなりました。 最小のものを見つけるだけで済みます`x`次のような:$$gcd(a_1+x, g) > 1$$すべてのシフトを検索する代わりに、因数分解します。`g`。 すべての素約数について`p`の`g`、シフトされた最初の要素は次の数で割り切れる必要があります。`p`。 これを達成する最小の変更は次のとおりです。$$x = (p - (a_1 \bmod p)) \bmod p$$これらの値の最小値を取ると答えが得られます。 

ブルート フォースはすべての可能なシフトをチェックするため機能しますが、検索スペースが大きすぎるために失敗します。 差 gcd は、無限の検索空間を 1 つの数値の素約数の有限セットに縮小します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * 答え) | お(1) | 遅すぎる |
 | 最適 | O(n + sqrt(g)) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初の要素とのすべての差の gcd を計算します。 から始める`g = 0`、そしてすべての要素に対して`a[i]`、 アップデート：$$g = gcd(g, |a_i-a_1|)$$値`g`シフト後の最終 gcd となる可能性のある約数が正確に含まれています。 

1. もし`g`がゼロの場合、すべての要素は等しい。 この状況では、配列にはその共通値と等しい gcd がすでにあります。 その値が 1 より大きい場合、答えは 0 です。 それ以外の場合、すべての要素は 1 であり、1 回の操作ですべてを 2 にするのに十分です。 
2. もし`g`は 1 なので、1 より大きい約数はすべての差異を分割できません。 考えられる最終的な gcd はすべて除算する必要があるため、`g`、操作は決して成功しません。 戻る`-1`。 
3. 要因`g`それぞれの異なる素約数を検査します`p`。 

プライムの場合`p`最終的な gcd の約数になるには、次のものが必要です。$$a_1+x \equiv 0 \pmod p$$最小の非負の値`x`この式を満たすかどうかは直接計算されます。 すべての素約数の最小値を維持します。 

1. 見つかった最小シフトを出力します。 

それが機能する理由: 有効な答えは何らかの gcd を作成する必要があります`d > 1`。 以来`d`シフトされたすべての要素を分割すると、シフトされた要素間のすべての差分が分割されます。これは元の差分とまったく同じです。 したがって`d`分けなければなりません`g`。 1 より大きいすべての約数には、次の素約数が含まれます。`g`したがって、すべての素約数をチェックするだけで十分です。 このような各素数について、アルゴリズムは、その素数がシフトされた配列を分割する最も早い瞬間を見つけます。これらの瞬間の最小値が、可能な限り最も早い成功した操作の数となります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def solve_case(a):
    n = len(a)

    g = 0
    first = a[0]
    for x in a[1:]:
        g = math.gcd(g, abs(x - first))

    if g == 0:
        return 0 if first > 1 else 1

    if g == 1:
        return -1

    ans = 10**18
    temp = g

    p = 2
    while p * p <= temp:
        if temp % p == 0:
            ans = min(ans, (-first) % p)
            while temp % p == 0:
                temp //= p
        p += 1

    if temp > 1:
        ans = min(ans, (-first) % temp)

    return ans

def main():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(f"Case {case}: {solve_case(a)}")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```コードは最初にすべての差異の gcd を構築します。 すべてのペアごとの差は 1 つの固定値からの差によって表現できるため、最初の要素が基準として使用されます。 

の`g == 0`ブランチは、すべての数値が等しい場合を処理します。 ゼロはすべての整数を除数として持ち、通常の除数ロジックが無意味になるため、これを分離する必要があります。 

因数分解ループは、次のそれぞれの異なる素因数を抽出します。`g`。 素因数が見つかると、実行に必要な正確な演算数が求められます。`a[0]`それで割り切れるのは`(-first) % p`。 Python のモジュロ演算は必要な非負の剰余をすでに返しているため、手動による境界処理が不要になります。 

ループは、の平方根までの約数をテストするだけで済みます。`g`。 ループの後、1 より大きい残りの値はそれ自体が素因数であるため、チェックする必要があります。

 ## 特殊なケース

 すべての数値が等しい場合、差 gcd はゼロになります。 入力の場合:```
1
3
1 1 1
```アルゴリズムは特殊なケースに入り、戻ります。`1`。 1 回の操作の後、配列は次のようになります。`[2,2,2]`、その gcd は 2 です。 

差 gcd が 1 の場合、正の除数はシフト操作に耐えることができません。 のために：```
1
3
2 5 9
```違いは`3`そして`7`、与える`g = 1`。 最終的な gcd は両方の値を除算する必要があるため、可能な除数は 1 だけであるため、アルゴリズムは正しく返します。`-1`。 

配列に有効な gcd がすでにある場合、答えはゼロでなければなりません。 のために：```
1
3
12 18 30
```違いのgcdは`6`。 素因数`2`は最初の値をすでに除算しているため、計算されたシフトはゼロになり、アルゴリズムは不要な演算を実行しません。
