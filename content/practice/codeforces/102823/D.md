 # 問題の理解

 この操作は、数値のバイナリ表現に対して機能します。 任意の 3 つの連続するビット位置を選択し、それらの 3 ビットを反転することができます。 3 つのビットのうち、最初と 3 番目の位置だけが場所を変更するため、1 回の操作は正確に 2 位置離れた 2 つのビット間の交換になります。 

タスクは数値を変換することです`x`の中へ`y`このようなスワップの最小数を使用します。 先行ゼロを考慮することができます。これは、演算を適用するときに、設定された最上位ビットを超える位置を使用できることを意味します。 

重要な構造は、ビットがそのパリティ位置を決して変更できないということです。 位置 0 のビットは、位置 2、4、6 などにのみ移動できます。 位置 1 のビットは、位置 3、5、7 などにのみ移動できます。 この演算により、バイナリ表現が 2 つの独立したシーケンスに分割され、1 つは偶数の位置を含み、もう 1 つは奇数の位置を含みます。 

の値`x`そして`y`と同じ大きさにすることができます`10^18`したがって、関連するビットは約 61 個だけです。 最大 10,000 のテスト ケースでは、ソリューションはケースごとにほぼ一定の時間に達する必要があります。 可能なスワップの数が大きくなる可能性があるため、操作のシミュレーションは実行できませんが、固定ビット数の処理は容易に十分に高速です。 

よくある間違いは、1 の合計数だけを比較することです。 たとえば、変形する`1`の中へ`2`両方の数値に 1 つの設定ビットが含まれている場合でも、これは不可能です。 唯一のビット`1`は位置 0 にありますが、唯一のビットは`2`は位置 1 にあり、パリティを変更する操作はありません。 

もう 1 つの特殊なケースは、先頭のゼロが重要な場合です。 たとえば、変形する`3`の中へ`6`答えがあります`1`。 バイナリではこれは`011`に`110`、演算により 3 ビットが反転されます。 位置を考慮せずに数値を文字列として扱うと、左端のゼロが有効なビット位置であることを誤って見逃す可能性があります。 

最後のエッジケースは、操作が必要ない場合です。 入力用```
5
5
```意味`x = 5`、`y = 5`、答えは`0`。 必要なスワップのみをカウントし、すでに一致している状態を忘れるソリューションでは、不要な肯定的な応答が生成される可能性があります。 

# アプローチ

 ブルート フォース アプローチでは、ビットのトリプルを繰り返し選択し、反転を適用して、条件に達する最短の一連の操作を検索します。`y`。 これは正しいです。すべての有効な操作シーケンスが、可能な 2 進数の状態グラフ内のパスに対応するからです。 ただし、状態の数はビット数に応じて指数関数的に増加します。 関連する 61 ビットに限定しても可能性が多すぎるため、最短パスの検索は不可能です。 

重要な観察は、3 ビットの反転では位置が交換されるだけであるということです。`i`そして`i + 2`。 これは、この演算がビットの任意の並べ替えではないことを意味します。 これは、同じパリティを持つ一連のポジション内の隣接スワップです。 偶数の位置は 1 つの独立した配列を形成し、奇数の位置は別の独立した配列を形成します。 

この変換の後、問題は古典的な最小隣接スワップ問題になります。 1 つのパリティ グループについて、すべての 1 の位置がわかります。`x`そして、中のすべてのものの位置`y`。 の最初のもの`x`の最初の位置に移動する必要があります`y`、2 番目のものは 2 番目のものに移動する必要があります。 隣接するスワップの最小数は、圧縮パリティ配列内のこれらの距離の合計です。 

ブルート フォースが機能するのは、ビットのあらゆる動きを調査するためですが、パリティ グループ間でビットが決して交差しないという事実は無視されます。 パリティ観察により、問題は 2 つの独立した 1 次元の再配置に帰着します。

 # アルゴリズムのチュートリアル

 1. のビットを抽出します。`x`そして`y`最下位ビットから上に向かって。 どちらの値も最大で 61 個程度の位置しか必要ありません。`10^18`。 この範囲を超える位置は常にゼロになります。 
2. 設定されたビット位置をパリティに基づいて 2 つのグループに分けます。 パリティごとに、圧縮シーケンス内の 1 のインデックスを保存します。 たとえば、ポジション`0, 2, 4, 6`圧縮されたインデックスになる`0, 1, 2, 3`。 
3. 対応するパリティ グループ内の 1 の数を比較します。`x`そして`y`。 それらが異なる場合、演算は偶数位置と奇数位置の間で少しも移動しないため、変換は不可能です。 
4. パリティグループごとに、順番に一致させます。 すべてのソース圧縮インデックスとターゲット圧縮インデックス間の絶対差を加算します。 これは、そのパリティ シーケンス内で必要な隣接スワップの数です。 
5. 2 つのパリティ グループのコストを加算し、結果を出力します。 

機能する理由: 許可される操作は、まさに 2 つのパリティ サブシーケンスの 1 つにおける隣接スワップです。 隣接するスワップでは、他のパリティの順序が保持され、任意のビットを同じパリティ グループ内の任意の位置に移動できます。 バイナリ シーケンスの場合、隣接するスワップの最小数は、最初のスワップと最初のスワップ、2 番目のスワップと 2 番目のスワップなどを照合することによって達成されます。 1 の数が異なる場合、一連のスワップで 1 を作成または削除することはできないため、答えは不可能です。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(x, y):
    src = [[], []]
    dst = [[], []]

    for i in range(61):
        if (x >> i) & 1:
            src[i & 1].append(i // 2)
        if (y >> i) & 1:
            dst[i & 1].append(i // 2)

    ans = 0

    for p in range(2):
        if len(src[p]) != len(dst[p]):
            return -1
        for a, b in zip(src[p], dst[p]):
            ans += abs(a - b)

    return ans

def main():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        x, y = map(int, input().split())
        out.append(f"Case {case}: {solve_case(x, y)}")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```ゼロ ビットは明示的に移動する必要がないため、このソリューションでは設定されたビットの位置のみが保存されます。 所定の位置にセットされたビット`i`パリティグループに属している`i % 2`、その圧縮位置は`i // 2`。 これにより、元の位置が、隣接する要素が交換の可能性を表すインデックスに変換されます。 

不可能チェックは距離を計算する前に行われます。 2 つのパリティ グループはビットを交換できないため、1 の合計数だけを比較すると不正確になります。 

最後のループでは、ソートされた 1 の位置が同じ順序で一致する必要があるという事実を利用します。 すべてのスワップは自身のパリティ シーケンス内で 1 ビットずつ移動するだけであるため、動的プログラミングやシミュレーションは必要ありません。

# テストケース```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    main()

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return result

    src = [[], []]
    dst = [[], []]

    for i in range(61):
        if (x >> i) & 1:
            src[i & 1].append(i // 2)
        if (y >> i) & 1:
            dst[i & 1].append(i // 2)

    ans = 0
    for p in range(2):
        if len(src[p]) != len(dst[p]):
            return -1
        for a, b in zip(src[p], dst[p]):
            ans += abs(a - b)
    return ans

def main():
    t = int(input())
    out = []
    for case in range(1, t + 1):
        x, y = map(int, input().split())
        out.append(f"Case {case}: {solve_case(x, y)}")
    print("\n".join(out))

# エッジケース

 パリティが不可能な場合については、次のように考えます。`x = 1`そして`y = 2`。 バイナリ形式は次のとおりです。`...0001`そして`...0010`。 唯一のセットされたビットは、位置 0 で始まり、位置 1 で終了します。すべての操作は距離 2 で位置を交換するため、ビットが奇数の位置に到達することはありません。 このアルゴリズムは、ソース ビットを偶数グループに、ターゲット ビットを奇数グループに配置し、異なるカウントを検出して、次の値を返します。`-1`。 

先行ゼロの処理については、次の点を考慮してください。`x = 3`そして`y = 6`。 関連するビットは次のとおりです。`011`そして`110`。 位置 0 に設定されたビットは、偶数圧縮シーケンスの 1 ステップである位置 2 に移動します。 奇数の位置は変更されません。 アルゴリズムは 1 つの動きを計算して返します。`1`。 

すでに解決済みのケースについては、次のように考えます。`x = 12`そして`y = 12`。 両方のパリティ グループには、まったく同じ 1 つの位置が含まれています。 すべての距離はゼロなので、答えはゼロです。 このアルゴリズムは不必要なスワップを実行しません。 

値が大きい場合は、次のことを考慮してください。`x = 10^18`そして`y = 10^18`。 このアルゴリズムは 61 個の位置のみを検査するため、数値の大きさ自体に依存せずに上限を処理します。 ビットを移動する必要がないため、答えはゼロのままです。
