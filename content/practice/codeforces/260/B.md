 ## 解決策
 ## 問題の理解

 入力は数字と文字のみで構成される長い文字列です。`-`。 この文字列内のどこかに、正確に次のように書かれた日付のように見える部分文字列が多数存在する可能性があります。`dd-mm-yyyy`。 

私たちの仕事は、そのような部分文字列として最も頻繁に現れる有効な日付を見つけることです。 有効な日付は次の 3 つの条件を満たしている必要があります。 

まず、形式は、日を 2 桁、月を 2 桁、年を 4 桁のハイフンで区切ったものにする必要があります。 

次に、年は次のいずれかである必要があります。`2013`、`2014`、 または`2015`。 

第三に、その日は指定された月に有効である必要があります。 これらの年は閏年ではないため、2 月は 28 日になります。 

答えは存在し、一意であることが保証されています。 

文字列の長さは最大でも`10^5`。 日付を表す部分文字列には常に長さがあります`10`, したがって、最大でも約`10^5`検討すべき候補ポジション。 これは、考えられる長さ 10 の部分文字列をすべてスキャンすることが可能であることを直ちに示唆しています。 すべての候補を他のすべての候補と比較しようとするソリューションは、二次関数の動作に偏り、遅くなりすぎます。 

微妙な点は、部分文字列は無効であるにもかかわらず、構文的には日付のように見える可能性があることです。 例えば：```
31-02-2013
```これはパターンに一致します`dd-mm-yyyy`, ただし、2 月には 31 日がないので、カウントしないでください。 

もう 1 つの簡単な間違いは、日と月に正確に 2 桁が使用されていない日付を受け入れることです。 考慮する：```
1-01-2013
```必要な形式の長さはちょうど 10 文字であるため、これは有効な現象ではありません。 のみ：```
01-01-2013
```カウントします。 

3 番目の落とし穴は、月固有の日数制限です。 例えば：```
31-04-2014
```4月は30日しかありません。 確認するだけの解決策`1 <= day <= 31`間違って数えてしまうでしょう。 

最後に、重複した出現が許可されます。 文字列の中で```
0012-10-2012-10-2012
```開始位置が異なると、有効な日付部分文字列が生成される場合があります。 すべての長さ 10 のウィンドウを個別に検査する必要があります。 

## アプローチ

 強引なアイデアは、2013 年から 2015 年までのすべての有効な日付を生成し、それぞれの予言全体を検索することです。 

その範囲には有効な日付が約 1,000 件しかないため、正確であるかどうかは簡単です。 各日付について、その文字列表現が予言に何回出現するかを数え、その最大値を保持します。 

問題は走行時間です。 予言には次の内容が含まれる可能性があります`10^5`文字。 約 1,000 の日付を個別に検索すると、次の結果が得られます。`10^8`最悪の場合、文字操作が必要になり、不必要にコストがかかります。 

問題の構造は、プロセスを方向転換することを示唆しています。 

「それぞれの有効な日付は何回発生しますか?」と尋ねる代わりに、「長さ 10 の各部分文字列が表す日付は何ですか?」と尋ねることができます。 

有効な出現箇所はすべて、ちょうど 10 文字を占める必要があります。```
dd-mm-yyyy
```あるのは`n - 9`文字列全体にそのようなウィンドウが含まれます。 ウィンドウごとに、それが有効な日付を形成しているかどうかを確認できます。 存在する場合、その日付の頻度を増やします。 

これにより、問題は予言の単一の線形スキャンに変換されます。 各位置は 1 回処理され、有効性チェックには一定の時間がかかり、ハッシュ マップには頻度が保存されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(1000・n) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(k) | 承認済み |

 ここ`k`検出された個別の有効な日付の数です。最大でも 2013 から 2015 までの有効な日付の数です。 

## アルゴリズムのチュートリアル

 1. 予言文字列を読みます。 
2. 各月の日数を含む配列を準備します。```
[31,28,31,30,31,30,31,31,30,31,30,31]
```2013 年から 2015 年はうるう年ではないため、2 月は常に 28 日になります。 
3. すべての開始位置を反復します。`i`長さ 10 の部分文字列が存在するようにします。 
4. 部分文字列を抽出する`s[i:i+10]`。 
5. 2 番目と 5 番目の位置にハイフンが含まれているかどうかを確認します。 

そうでない場合、部分文字列は必要な形式と一致できません。 
6. 解析:

 - キャラクターからの日`[0:2]`- 文字から月`[3:5]`- 文字からの年`[6:10]`解析が失敗した場合は、部分文字列を破棄します。 
7. 日付を確認します。 

- 年は 2013 年から 2015 年の間です
 - 月は 1 ～ 12 です
 - 日は少なくとも 1 です
 - 日はその月の日数を超えない
 8. 日付が有効な場合は、元の部分文字列をキーとして使用して、ハッシュ マップ内の日付のカウントを増分します。 
9. これまでに確認された最も頻度の高い日付を追跡します。 
10. すべてのウィンドウを処理した後、最大カウントで日付を出力します。 

### なぜ効果があるのか

 予言内のすべての有効な出現は、ちょうど 10 個の連続する文字を占め、長さ 10 のウィンドウで表現されなければなりません。 アルゴリズムは、そのようなウィンドウをすべて 1 回だけ検査します。 

部分文字列は、すべての有効性チェックに合格した場合にのみ頻度マップに寄与するため、カウントされたすべての出現は正しい日付に対応します。 逆に、正しい日付の出現はすべて、検査されたウィンドウの 1 つとして表示され、カウントされます。 

したがって、頻度マップには、すべての有効な日付の正確な出現数が保存されます。 黙示録の日付は、最大の頻度を持つ一意の有効な日付として定義されているため、最大のカウントを持つキーを選択すると正しい答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    days_in_month = [31, 28, 31, 30, 31, 30,
                     31, 31, 30, 31, 30, 31]

    freq = {}
    best_date = ""
    best_count = 0

    for i in range(len(s) - 9):
        cur = s[i:i + 10]

        if cur[2] != '-' or cur[5] != '-':
            continue

        try:
            day = int(cur[0:2])
            month = int(cur[3:5])
            year = int(cur[6:10])
        except ValueError:
            continue

        if not (2013 <= year <= 2015):
            continue

        if not (1 <= month <= 12):
            continue

        if not (1 <= day <= days_in_month[month - 1]):
            continue

        freq[cur] = freq.get(cur, 0) + 1

        if freq[cur] > best_count:
            best_count = freq[cur]
            best_date = cur

    print(best_date)

if __name__ == "__main__":
    solve()
```有効な日付は正確に 10 文字を占める必要があるため、スキャンでは長さ 10 のすべての可能なウィンドウが検査されます。 

ハイフンのチェックは、整数を解析する前に実行されます。 これにより、ほとんどの無効なウィンドウがすぐに拒否され、不必要な変換が回避されます。 

月の有効性チェックはインデックス作成の前に行われます`days_in_month[month - 1]`。 この順序を逆にすると、月が範囲外の場合に無効なインデックスにアクセスする危険があります。`1..12`。 

元の部分文字列が辞書キーとして使用されます。 日付は常に正規表現で保存されるため、`dd-mm-yyyy`形式では、同一の日付は常に同一のキーを生成します。 

実行最大値はスキャン中に更新され、周波​​数マップの 2 回目のパスが回避されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    def solve():
        input = sys.stdin.readline
        s = input().strip()

        days = [31, 28, 31, 30, 31, 30,
                31, 31, 30, 31, 30, 31]

        freq = {}
        best_date = ""
        best_count = 0

        for i in range(len(s) - 9):
            cur = s[i:i + 10]

            if cur[2] != '-' or cur[5] != '-':
                continue

            try:
                d = int(cur[:2])
                m = int(cur[3:5])
                y = int(cur[6:])
            except ValueError:
                continue

            if not (2013 <= y <= 2015):
                continue
            if not (1 <= m <= 12):
                continue
            if not (1 <= d <= days[m - 1]):
                continue

            freq[cur] = freq.get(cur, 0) + 1

            if freq[cur] > best_count:
                best_count = freq[cur]
                best_date = cur

        print(best_date)

    solve()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return out.getvalue().strip()

 ## 特殊なケース

 次のことを考慮してください。```
31-02-2013
```部分文字列には正しい値が含まれています`dd-mm-yyyy`構造。 アルゴリズムは日を解析します`31`、 月`2`、および年`2013`。 月は有効ですが、2 月のみ許可されます`28`日々。 条件```
day <= days_in_month[month - 1]
```失敗するため、部分文字列は破棄され、カウントされません。 

考慮する：```
31-04-2014
```4月は`30`日々。 アルゴリズムは計算します`days_in_month[3] = 30`、それを検出します`31 > 30`、そして日付を拒否します。 これにより、構文的には正しいが、不可能な暦日を数えることができなくなります。 

考慮する：```
1-01-2013
```この文字列の長さはわずか 9 文字です。 このアルゴリズムは長さ 10 のウィンドウのみを検査するため、これを候補日付として扱うことはありません。 必要な形式では、日と月の両方に正確に 2 桁が必要です。 

考慮する：```
13-12-2013-12-2013
```部分文字列`13-12-2013`が最初に表示され、重複により後で別の発生が始まります。 アルゴリズムはすべての開始位置を個別にチェックするため、両方の出現位置が正しくカウントされます。 重複する一致には特別な処理は必要ありません。
