 ## 解決策
 ## 問題の理解

 数字から始めましょう`a`。 正確に延長したい`n`回。 

単一の拡張とは、現在の番号の右側に 10 進数 1 桁を追加することを意味します。 数字は次のいずれかになります`0`に`9`ただし、追加後の数値は次の値で割り切れる必要があります。`b`。 

この操作を正確に実行した後、`n`場合によっては、最終的な数値を出力する必要があります。 いずれかのステップで、割り算を維持しながら追加できる数字がない場合は、`b`、その後プロセスは停止し、答えは次のようになります。`-1`。 

制約は小さい`a`そして`b`、 しかし`n`と同じ大きさにすることができます`100000`。 このことから、増加する数値全体に対して高コストの演算を実行するアルゴリズムは危険であることがすぐにわかります。数値自体に 100,000 桁を超える可能性があるからです。 追加される数字ごとの仕事が一定またはほぼ一定であるメソッドが必要です。 

微妙な点は、最後だけでなく、すべての拡張後にも割り算条件が成立する必要があることです。 例えば：```
a = 1, b = 11, n = 2
```任意に数字を追加し、最終的な数値のみをチェックすると、無効な中間状態が作成される可能性があります。 操作自体は各ステップで割り算が必要です。 

もう 1 つの簡単な間違いは、1 つの拡張が可能であれば、将来のすべての拡張が可能であると想定することです。 考慮する：```
a = 1, b = 2, n = 1
```追加中`0`与える`10`、これは機能します。 

しかし、のために```
a = 1, b = 11, n = 1
```数字がありません`d`そのような`1d`で割り切れます`11`したがって、正しい答えは次のとおりです。```
-1
```とにかく続行しようとする不用意な実装は間違っています。 

後のステップについても重要な観察があります。 で割り切れる数が見つかったら、`b`を追加して、`0`以下の場合にのみ可算性を維持します。`10`と互換性があります`b`。 一般的には、追加する`0`可分性は保たれません。 例えば：```
12 % 3 = 0
120 % 3 = 0
```しかし```
14 % 7 = 0
140 % 7 = 0
```特定の約数がある場合にのみ機能します。 最初の拡張が成功した後に何が起こるかについては、慎重に推論する必要があります。 

## アプローチ

 最も直接的なアプローチは、説明どおりにプロセスを正確にシミュレートすることです。 各ステップで、可能な 10 桁すべてを試してください。 各桁について、新しい数値を作成し、それが次の数で割り切れるかどうかを確認します。`b`。 何らかの数字が機能する場合は、それを追加して続行します。 

ロジックは文字通り操作の定義に従っているため、正しいです。 問題は、その数がすぐに膨大になってしまうことです。 後`100000`拡張子が含まれている場合があります。`100000`数字。 このような数値の構築と除算を繰り返すのはコストがかかりすぎます。 

重要な観察は、割り算は剰余モジュロのみに依存するということです。`b`。 

現在の番号が`x`。 数字の追加`d`作成します```
x' = 10x + d
```必要です```
(10x + d) % b = 0
```現在の値`x`それ自体は重要ではありません。 のみ`x % b`重要です。 

最初に、残りの部分がわかっています。`a`モジュロ`b`。 数字を試してみます`0`を通して`9`そしてそれを実現するものを探してください```
(10 * remainder + d) % b == 0
```そのような数字が存在する場合、新しく形成された数は次の数で割り切れます。`b`。 

ここからは重要な単純化です。 最初の拡張が成功した後、現在の数値は次の数で割り切れます。`b`、その余りは次のようになります`0`。 

その時点から、将来のすべてのステップは残りから始まります`0`。 必要なのは数字だけです`d`満足のいく```
d % b = 0
```以来`0`は常にそのような数字であり、追加されます`0`すでに割り切れる数を取得すると、永久に機能します。 

したがって、問題全体は、最初の内線を次の数で割り切れる単一の数字を見つけることに帰着します。`b`。 そのような数字が存在しない場合、答えは次のようになります。`-1`。 それ以外の場合は、その数字を 1 回追加してから、`n - 1`ゼロ。

 ## アルゴリズムのチュートリアル

 1. コンピューティング`r = a % b`。 
2. すべての数字を試してください`d`から`0`に`9`。 
3. かどうかを確認します。`(r * 10 + d) % b == 0`。 
4. 条件を満たす桁がない場合は出力`-1`。 
5. それ以外の場合、最初の有効な数字を次のようにします。`d`。 
6. 答えを次の 10 進表現として作成します。`a`、その後に数字が続く`d`。 
7. 正確に追加`n - 1`ゼロ。 
8. 結果の文字列を出力します。 

The reason step 7 works is that after appending the first valid digit, the current number is divisible by`b`。 その剰余モジュロ`b`今はゼロです。 ゼロを追加すると、```
10 * current
```その余りは依然としてゼロであるため、```
(10 * 0) % b = 0
```現在の剰余表現を操作する場合。 

### なぜ効果があるのか

 しましょう`r = a % b`。 

最初に追加される数字は次の条件を満たす必要があります```
(10r + d) % b = 0
```追加するので`d`数値を次のように変換します`10a + d`、および剰余モジュロ`b`この式で保存されます。 

数字がない場合は、`0`に`9`が方程式を満たす場合、最初の演算は不可能であるため、答えは次のようになります。`-1`。 

数字の場合`d`それを満たしている場合、新しい数値は次で割り切れます。`b`。 Its remainder becomes zero. Every later extension appends digit`0`。 剰余ゼロから始まり、次の剰余は次のようになります。```
(10 * 0 + 0) % b = 0.
```残りは二度と変更されません。 すべての中間数は次で割り切れます。`b`, したがって、必要な操作はすべて有効です。 構築された数値は正確に次の結果になります。`n`拡張子。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, n = map(int, input().split())

    r = a % b

    for d in range(10):
        if (r * 10 + d) % b == 0:
            ans = str(a) + str(d) + "0" * (n - 1)
            print(ans)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```最初の部分では、次の剰余を計算します。`a`モジュロ`b`。 これは、数字を正常に追加できるかどうかを判断するために必要な唯一の情報です。 

数字のループ`0`を通して`9`有効な最初の内線番号を検索します。 可能性は 10 個しかないため、この検索は定数時間になります。 

有効な数字が見つかると、答えが文字列として構築されます。 最終的な数値には 100,000 桁を超える可能性があるため、文字列を使用することが重要です。 整数として保存するのは不必要で非効率的です。 

表現`"0" * (n - 1)`残りの拡張子を正確に追加します。 いつ`n = 1`、これは空の文字列になり、追加される数字は 1 つだけ正しく生成されます。 

有効な数字が見つからないままループが終了した場合、最初の操作は実行できず、正しい答えは次のようになります。`-1`。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def solve():
        input = sys.stdin.readline
        a, b, n = map(int, input().split())

        r = a % b

        for d in range(10):
            if (r * 10 + d) % b == 0:
                return str(a) + str(d) + "0" * (n - 1)

        return "-1"

    return solve()

# sample from statement
assert run("5 4 5\n") == "520000", "sample"

# minimum values
assert run("1 1 1\n") == "10", "minimum case"

# impossible first extension
assert run("1 11 1\n") == "-1", "no valid digit"

# n = 1, exactly one append
assert run("12 3 1\n") == "120", "single extension"

# divisor requiring nonzero first digit
assert run("5 7 2\n") == "560", "first digit 6 gives divisibility"

# large n shape check
out = run("1 1 100000\n")
assert len(out) == 100001, "large output length"
assert out[0] == "1", "starts correctly"

 ## 特殊なケース

 ### 有効な最初の桁がありません

 入力:```
1 11 1
```残りは次のとおりです。```
1 % 11 = 1
```アルゴリズムはすべての桁をチェックします。```
(10 + d) % 11
```のために`d = 0..9`。 

どれもゼロを生成します。 最初の操作は実行できないため、アルゴリズムはすぐに次の出力を行います。```
-1
```これはプロセスの定義と一致します。 

### 必要な拡張子は 1 つだけです

 入力:```
12 3 1
```残りはゼロです。 

桁`0`すぐに次の条件を満たします。```
(0 * 10 + 0) % 3 = 0
```答えは次のようになります。```
120
```余分なゼロは追加されません。`n - 1 = 0`。 

### 非常に大きい n

 入力:```
1 1 100000
```最初の有効な数字は次のとおりです`0`。 

アルゴリズムは以下を構築します。```
10 + 99999 zeros
```膨大な数に対して高価な演算を実行する必要はありません。 実行時間は出力サイズに比例して増加しますが、出力自体には 100001 桁が含まれるため、これが最適です。 

### 有効な最初の桁はゼロではありません

 入力:```
5 7 2
```残りは次のとおりです。```
5
```アルゴリズムは次の状態になるまで数字をテストします。```
(5 * 10 + 6) % 7 = 56 % 7 = 0
```桁を選択します`6`、生産`56`。 さらにゼロが 1 つ追加され、次のようになります。```
560
```すべての中間数は割り算の要件を満たしているため、この構成は有効です。
