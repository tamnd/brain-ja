 ## 解決策
 ## 問題の理解

 複数のクエリが与えられます。 各クエリは、以下の整数の範囲を記述します。$l$に$r$、各整数は候補「スターシップ番号」を表します。 任意の番号に対して$x$、そのスコアを 10 進表現の最大桁と最小桁の差として定義します。 タスクは、範囲内のスコアができるだけ大きい数字を選択することです。 

したがって、クエリごとに、新しい数値を作成したり、何かを変更したりすることはありません。 整数の閉じた間隔をスキャンし、数字パターンが最も「広がっている」要素、つまり少なくとも 1 つの大きな数字と少なくとも 1 つの小さな数字が含まれる要素を探しています。 

制約は特定の点で厳しいです。$10^4$クエリ、各範囲は最大で$10^6$。 クエリごとに直接フル スキャンを行うと、最悪の場合、検査が行われます。$10^{10}$これは実行可能な実行時間をはるかに超えています。 単一の範囲を繰り返しスキャンすることさえ現実的ではないため、ソリューションでは各間隔のすべての数値を反復することを回避する必要があります。 

範囲が小さいか縮退している場合、次のような微妙なエッジ ケースが表示されます。$l = r$。 この場合、候補は 1 つしかないため、回答は強制されます。 もう 1 つの興味深いケースは、桁の構造が数値の順序と一致していないため、最適な数値が範囲の境界近くにある場合です。 たとえば、次のような範囲で$[59, 63]$の場合、最良の答えはエンドポイントではなく、中央に 0 桁の数字です。エンドポイントだけを検査する場合、これは明らかではありません。 

## アプローチ

 ブルートフォースの解決策は簡単です。 クエリごとに、以下を繰り返します。$l$に$r$、各数値の最大桁と最小桁を計算し、それらの差を計算して、最適な値を追跡します。 数字の抽出には時間がかかります$O(\log_{10} x)$, そのため、実際には各数値に一定の時間がかかります。 全体の複雑さは次のようになります。$O((r-l+1)\cdot t)$、最悪の場合は約$10^6 \cdot 10^4 = 10^{10}$操作。 これはすぐに制限を超えます。 

重要な観察は、数字の範囲が 0 ～ 9 で区切られているため、考えられる最大の幸運は 9 であるということです。これは、数字に数字 9 と数字 0 の両方が含まれる場合にのみ達成されます。範囲内でそのような数字が見つからない場合は、できるだけ近づけようとします。つまり、数字に存在する 2 つの数字の間のギャップを最大化したいと考えます。 これは、極端な数字、特に 0 と 9、または 8 と 0、9 と 1 などの離れた数字のペアを含む数字を探す必要があることを示唆しています。 

すべての数字をスキャンするのではなく、優れた候補者は構造的に「数字が豊富」でなければならないという事実を利用します。 実際には、範囲内の最良の答えは、10 進数表現に 9 または 0 を含む数値に近いものになります。これは、これらの数値の広がりが最大になるためです。 範囲の絶対値が小さいため ($\le 10^6$) を使用すると、クエリごとに慎重に選択された一定数の候補 (境界桁を強制するか内部桁を極値に置き換えることによって形成される数値) を安全にチェックできます。 

これにより、すべての整数をスキャンするという問題が、クエリごとに有望な候補の少数のセットを評価することに軽減されます。

 ## アルゴリズムのチュートリアル

 私たちは、クエリごとに少数の候補セットをテストし、数字の広がりを直接計算することを中心にソリューションを構築します。 

1. クエリごとに$[l, r]$、最適な数値には 0 や 9 などの極端な数値が含まれる可能性が高いと考えてください。これにより、範囲の境界付近の数値や境界数値から構成される数値をチェックするようになります。 
2. エンドポイントから始まる候補セットを収集します$l$そして$r$制約付き桁問題の最適値は境界付近にあることが多いためです。 
3. エンドポイントごとに、制御された方法で桁を置き換えて追加の候補を生成し、極端な桁の導入を試みます。 実際的な戦略は、数値を範囲内に保ちながら、1 桁の位置を 0 または 9 に置き換えて得られる数値をテストすることです。 範囲が狭いので($\le 10^6$)、これにより得られる候補は最大でも数十個です。 
4. 各候補について、次の範囲内にあることを確認します。$[l, r]$。 存在する場合は、桁をスキャンし、最小桁値と最大桁値を追跡することによって、その桁の幸運度を計算します。 
5. 最も幸運な候補者を追跡します。 複数の候補が同点の場合は、いずれか 1 つを返すことができます。 
6. クエリごとに最適な候補を出力します。 

これが機能する主な理由は、最適性が数値の近さだけではなく、数字のみに依存するためです。 極端な数字を導入することによって数字の多様性が最大化されるため、範囲境界の周りの小さな構造化された近傍だけで、すべての意味のある候補を明らかにするのに十分です。 

### なぜ効果があるのか

 あらゆる数字の幸運は、その数字のセットによって完全に決まります。 0 または 9 は数字空間のグローバルな極値であるため、最大の改善は 0 または 9 を導入することによってもたらされます。 したがって、最適な解には、これらの数字がすでに含まれているか、含まれる数字に近い値が含まれている必要があります。 桁を大幅に変更すると、数値が小さな近傍の外に移動する傾向があるため、数値を変更した境界候補の制限されたセットをチェックすることで、桁の広がりを最大化できる構成に遭遇することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def luckiness(x: int) -> int:
    mx = 0
    mn = 9
    while x > 0:
        d = x % 10
        mx = max(mx, d)
        mn = min(mn, d)
        x //= 10
    return mx - mn

def solve():
    t = int(input())
    for _ in range(t):
        l, r = map(int, input().split())

        best_x = l
        best_val = -1

        # small candidate set around endpoints
        candidates = set()
        candidates.add(l)
        candidates.add(r)

        for x in (l, r):
            s = str(x)
            n = len(s)
            for i in range(n):
                for d in "09":
                    y = int(s[:i] + d + s[i+1:])
                    if l <= y <= r:
                        candidates.add(y)

        for x in candidates:
            val = luckiness(x)
            if val > best_val:
                best_val = val
                best_x = x

        print(best_x)

if __name__ == "__main__":
    solve()
```機能`luckiness`10 進数を反復処理して桁の極値を計算します。数値は最大でも次の値であるため、これが最適です。$10^6$。 これにより、ほとんどの計算で文字列のオーバーヘッドが回避されます。 

クエリごとに、境界とそのわずかな桁の摂動から構成される小さな候補セットを構築します。 この考え方は、全範囲を調べなくても、任意の位置に 0 または 9 を挿入するだけで、最も影響力のある数字の変更を十分にシミュレートできるということです。 

私たちは常に候補者を範囲に照らして検証します$[l, r]$数値を変更すると、値が簡単に区間外に押し出される可能性があるためです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def luckiness(x: int) -> int:
        mx = 0
        mn = 9
        while x > 0:
            d = x % 10
            mx = max(mx, d)
            mn = min(mn, d)
            x //= 10
        return mx - mn

    t = int(input())
    out = []
    for _ in range(t):
        l, r = map(int, input().split())
        best_x = l
        best_val = -1
        candidates = {l, r}

        for x in (l, r):
            s = str(x)
            n = len(s)
            for i in range(n):
                for d in "09":
                    y = int(s[:i] + d + s[i+1:])
                    if l <= y <= r:
                        candidates.add(y)

        for x in candidates:
            val = luckiness(x)
            if val > best_val:
                best_val = val
                best_x = x

        out.append(str(best_x))

    return "\n".join(out)

 ## 特殊なケース

 いつ$l = r$の場合、候補セットにはエンドポイントのみが含まれており、変更は必要ないため、アルゴリズムはその数値を正しく返します。 幸運は直接計算されるため、曖昧さはありません。 

次のような 1 桁の範囲の場合$[1, 9]$, 最大桁が最小桁と等しいため、すべての数字の幸運度は 0 になります。 すべての候補が均一に評価され、任意の値が受け入れられるため、アルゴリズムは引き続き機能します。 

数値の中に 0 または 9 を導入することで最適な数値が作成される範囲の場合、次のようになります。$[59, 63]$、数字の突然変異ステップは 60 のような候補を生成し、エンドポイントと比較してそれらのより高い広がりを正確に識別します。 

10 のべき乗境界に近い範囲の場合、次のようになります。$[90, 100]$、候補の生成により、両方の表現が考慮されることが保証され、99 または 90 のような構造の存在がエンドポイントの摂動を通じて捕捉されます。
