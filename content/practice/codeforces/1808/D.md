 ## 解決策
 ## 問題の理解

 奇数長のすべての部分配列に対して`k`、その部分配列を回文に変えるために必要な要素の置換の数を知りたいと考えています。 答えは、すべての長さにわたるこれらの値の合計です。`k`サブアレイ。 

固定の奇数長サブアレイの場合、左側の各位置は右側の対称位置とペアになります。 2 つの値がすでに等しい場合、そのペアを置換する必要はありません。 異なる場合は、1 つだけ置き換えれば十分です。 異なる対称ペアは独立しているため、部分配列の回文性は単に不一致の対称ペアの数になります。 

配列の長さは最大です`2 * 10^5`したがって、その中のすべてのサブ配列とすべてのペアを調べることは不可能です。 まであります`2 * 10^5`各ウィンドウには最大で 6 つのウィンドウを含めることができます。`10^5`対称的なペア。 二次または三次の解は限界をはるかに超えています。 

微妙なケースが現れるのは、`k = 1`。 長さ 1 のすべての部分配列はすでに回文であるため、答えは常に次のようになります。`0`。 

例えば：```
3 1
5 7 9
```正しい出力は次のとおりです。```
0
```すべてのウィンドウが少なくとも 1 つのペアに寄与すると仮定する解決策は、ここでは失敗します。 

間違いを犯しやすいもう 1 つの場所は、配列の境界付近です。```
5 3
1 2 1 2 1
```等しいペア`(0, 2)`有効な長さ 3 のウィンドウに属しており、`(2, 4)`。 ペア`(0, 4)`は、中心に関して対称であっても、長さ 3 のウィンドウには属しません。 中心が有効なウィンドウの中心になり得るかどうかを確認せずに、距離制約内のすべての等しいペアをカウントすると、間違った結果が得られます。 

3 番目の落とし穴はパリティです。 整数の中心の周りの対称位置は常に同じパリティを持ちます。 ポジション`1`そして`2`それらの中点は配列インデックスではないため、奇数長ウィンドウ内で対称ペアを形成することはできません。 

## アプローチ

 ブルート フォース ソリューションは、定義に直接準拠します。 For every window of length`k`、すべての対称ペアを比較し、不一致をカウントします。 これは正しいです。各不一致には 1 つの置換が必要ですが、各一致ペアには置換が必要ありません。 

問題はコストです。 がある`n - k + 1`窓と`(k - 1) / 2`ウィンドウごとにペア。 最悪の場合、これはおおよそ次のようになります`2 * 10^10`比較すると大きすぎます。 

重要な観察は、ウィンドウについて考えるのをやめて、対称ペアについて考え始めることです。 

させて```
m = (k - 1) / 2
```すべての有効なウィンドウが正確に寄与します`m`対称的なペア。 あるので`n - k + 1`ウィンドウの場合、対称ペアの出現の総数は次のとおりです。```
(n - k + 1) * m
```このようなペアをすべて不一致として数えれば、それが答えになります。 唯一の修正は、等しい対称ペアが寄与することです。`0`の代わりに`1`。 

したがって、問題は次のようになります。```
How many valid symmetric pair appearances have equal values?
```各対称ペアは 2 つの位置によって識別されます`(i, j)`。 

ペアはある程度の長さで使用されます-`k`次の場合に限り、ウィンドウが表示されます。```
1. i and j have the same parity.
2. j - i <= 2m.
3. Their midpoint lies inside the range of valid window centers.
```ここで必要なのは、これらの条件を満たす等しい値の位置ペアをカウントすることだけです。 

異なる値を持つ位置は無関係であるため、インデックスを値ごとにグループ化します。 各値グループ内で、インデックスが並べ替えられます。 あらゆるインデックスに対して`i`、位置の間隔を計算します`j`すべての妥当性制約を満たしているものを見つけてから、二分探索を使用してその範囲内に含まれる同じ値のインデックスがいくつあるかを数えます。 

これにより問題は次のように縮小されます`O(n log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nk) | お(1) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. しましょう`m = (k - 1) // 2`。 
2. コンピューティング```
total_pairs = (n - k + 1) * m
```これは、すべてのウィンドウにわたる対称ペアの出現数です。 
3. 配列の位置を値とパリティでグループ化します。 

異なるパリティを持つ位置は、整数の中心の周りに対称的なペアを形成することはできないため、値ごとに 2 つのリストを保存します。 
4. ポジションごとに`p`1 つのパリティ リスト内で、どの等しい値の位置を決定するか`q > p`有効な対称ペアを形成できます。 
5. 中点条件は次のようになります。```
m <= (p + q) / 2 <= n - m - 1
```になる```
2m - p <= q <= 2(n - m - 1) - p
```6. 距離条件は次のようになります。```
q <= p + 2m
```7. すべての制約を組み合わせると、```
low = max(p + 1, 2m - p)
up  = min(p + 2m, 2(n - m - 1) - p)
```8. 並べ替えられたパリティ リストで二分探索を使用して、次の位置にある位置の数を数えます。`[low, up]`。 
9. このようなカウントをすべて合計すると、`equal_pairs`。 
10. すべての有効な対称ペアの出現は、次のいずれかに寄与します。`1`値が異なる場合、または`0`値が等しい場合、つまり```
answer = total_pairs - equal_pairs
```### なぜ効果があるのか

 すべてのウィンドウ内のすべての対称ペアの出現は、配列位置の 1 つのペアに正確に対応します。`(i, j)`その中点はウィンドウの中心です。 派生した 3 つの条件は、まさにそのようなウィンドウが存在する条件です。`total_pairs`すべての対称ペアの出現をカウントします。`equal_pairs`エンドポイントがすでに一致している出現を正確にカウントします。 一致する各ペアが貢献します`0`代わりに回文にする`1`したがって、それらを差し引くと、不一致の対称ペアの出現の数が正確に残ります。これは、必要な回文の合計です。 

## Python ソリューション```python
import sys
from bisect import bisect_left, bisect_right
from collections import defaultdict

input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

m = (k - 1) // 2

total_pairs = (n - k + 1) * m

pos = defaultdict(lambda: [[], []])

for i, x in enumerate(a):
    pos[x][i & 1].append(i)

equal_pairs = 0

for parity_lists in pos.values():
    for arr in parity_lists:
        for idx, p in enumerate(arr):
            low = max(p + 1, 2 * m - p)
            up = min(p + 2 * m, 2 * (n - m - 1) - p)

            if low > up:
                continue

            l = bisect_left(arr, low, idx + 1)
            r = bisect_right(arr, up)

            equal_pairs += r - l

print(total_pairs - equal_pairs)
```最初の部分では、すべてのウィンドウにわたる対称ペアの出現の合計数を計算します。 

ディクショナリは、値とパリティによってインデックスをグループ化します。 整数の中心の周りの対称位置は常に等しいパリティを持つため、パリティによる分割は非常に重要です。 この分離がないと、非整数の中点を持つペアが誤ってカウントされます。 

固定位置の場合`p`、間隔`[low, up]`すべての妥当性制約の交差部分です。 その間隔内のすべての等しい値の位置が、1 つの一致する対称ペアの出現を形成します。 

二分探索では、それらの位置が対数時間でカウントされます。 すべてのインデックスは 1 つのリストにのみ属するため、合計作業量は次のようになります。`O(n log n)`。 

すべての算術演算は Python 整数内に快適に収まります。 答えは大まかに到達できます`10^10`したがって、他の言語で 32 ビット整数を使用するのは安全ではありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 各インデックスは、その値パリティ グループ内でバイナリ検索に参加します。 
| スペース | O(n) | グループ化された位置の保存 |

 と`n ≤ 2 · 10^5`、`O(n log n)`このソリューションは数百万回の操作のみを実行し、制限時間内に簡単に収まります。 補助メモリはインデックスの数が線形です。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from bisect import bisect_left, bisect_right
from collections import defaultdict

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    m = (k - 1) // 2
    total_pairs = (n - k + 1) * m

    pos = defaultdict(lambda: [[], []])

    for i, x in enumerate(a):
        pos[x][i & 1].append(i)

    equal_pairs = 0

    for parity_lists in pos.values():
        for arr in parity_lists:
            for idx, p in enumerate(arr):
                low = max(p + 1, 2 * m - p)
                up = min(p + 2 * m, 2 * (len(a) - m - 1) - p)

                if low > up:
                    continue

                l = bisect_left(arr, low, idx + 1)
                r = bisect_right(arr, up)

                equal_pairs += r - l

    return str(total_pairs - equal_pairs)

# provided sample
assert run("8 5\n1 2 8 2 5 2 8 6\n") == "4"

# minimum size
assert run("1 1\n7\n") == "0"

# all equal
assert run("5 3\n4 4 4 4 4\n") == "0"

# k = 1
assert run("4 1\n1 2 3 4\n") == "0"

# off-by-one around borders
assert run("5 3\n1 2 1 2 1\n") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1 / 7`|`0`| 最小入力サイズ |
 |`5 3 / 4 4 4 4 4`|`0`| すべてのウィンドウはすでに回文です。 
|`4 1 / 1 2 3 4`|`0`| 特殊な場合`k = 1`|
 |`5 3 / 1 2 1 2 1`|`0`| 境界中心制約とパリティ処理 |

 ## 特殊なケース

 次のことを考慮してください。```
3 1
5 7 9
```我々は持っています`m = 0`、 それで```
total_pairs = 0
```どのウィンドウにも対称ペアは存在しません。 アルゴリズムはすぐに戻ります`0`。 

考慮する：```
5 3
1 2 1 2 1
```有効な中心は位置です`1`、`2`、 そして`3`。 

ペア`(0, 4)`は等しい値と整数の中点を持ちますが、その距離は`4`、より大きい`2m = 2`。 長さ 3 のウィンドウでは対称ペアとして表示されることはありません。 間隔の計算では自動的に除外されます。 

考慮する：```
5 5
1 1 2 1 1
```ペア`(0, 1)`値は等しいがパリティが異なります。 その中点は整数配列の位置ではないため、奇数長のウィンドウの中心に関して対称にすることはできません。 インデックスはカウントする前にパリティによって分離されるため、このペアは決して考慮されません。 

これらのケースはまさに、多くの誤った実装が一致するペアを過大評価しているケースです。 インターバル条件とパリティ条件により、無効なペアがすべて削除されます。
