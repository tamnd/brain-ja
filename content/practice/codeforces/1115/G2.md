 ## 解決策
 ## 問題の理解

 入力ビット文字列をエンコードする最大 8 量子ビットの小さな量子レジスタが与えられます。$x_0, x_1, \dots, x_{N-1}$、1 つの追加の量子ビットとともに$y$それは出力ワイヤとして機能します。 タスクは、入力ビットの少なくとも 1 つが 1 に等しいかどうかを計算し、結果として出力量子ビットとなる XOR を計算する可逆変換を実装することです。 

古典的な用語では、この関数はすべての入力ビットに対する論理 OR です。 量子用語では、マッピングするユニタリー演算を実装する必要があります。$|x\rangle|y\rangle$に$|x\rangle|y \oplus (x_0 \vee x_1 \vee \dots \vee x_{N-1})\rangle$、入力レジスタは変更しないままにします。 

制約$N \le 8$重要な構造上のヒントです。 入力空間に対する指数関数的な構築は原理的には依然として実行可能ですが、より重要なのは、漸近的な最適化を強制されないことです。 基本的な操作に分解された標準のマルチ制御ゲートを使用して、小規模な固定深さの構造を実現できます。 

主な微妙な点は、入力量子ビットが任意の量子状態にあり、潜在的に重ね合わせであることです。 したがって、いかなるソリューションも完全に可逆的である必要があり、情報を測定したり複製したりしてはなりません。 状態を崩壊させる素朴な古典的なスタイルの OR 計算は、すぐに正しさを壊してしまいます。 たとえば、各量子ビットを読み取ってその値に基づいて分岐しようとすることは、量子回路では無効です。 

2 番目の微妙なケースは、すべての入力量子ビットが重ね合わせられている場合に発生します。 たとえば、状態が次の場合$(|0\rangle + |1\rangle)^{\otimes N}$、オラクルは、古典的なサンプル値を計算するのではなく、少なくとも 1 つのビットが 1 である基底状態の存在と出力量子ビットをエンタングルする必要があります。 これにより、純粋に単一の構造が強制されます。 

## アプローチ

 ブルート フォースの観点では、少なくとも 1 つのビットが 1 であるすべての入力パターンを明示的に考慮して OR を計算しようとします。概念的には、すべて 0 の状態を除くすべての基底状態をマークし、それに応じて出力を反転することで、変換の実装を試みることができます。 これは、大規模なマルチ制御 OR ゲート、またはすべての入力の論理和によってトリガーされる制御された操作を構築することに相当します。 

問題は正確さではなく構造です。 OR を直接実装することは、ほとんどの量子命令セットでは原始的ではありません。 通常、単一量子ビットのゲートと制御された NOT または複数制御された X 構造にのみアクセスできます。 ブルートフォース分解では、入力のサブセットごとに個別のコントロールを構築しようとする可能性がありますが、冗長で不要なゲートが発生します。 それでも$N$が小さいと、このアプローチはすぐに面倒になり、量子回路が実際にどのように構築されるかを反映しません。 

重要な洞察は、OR を自然に実装可能な形式で書き直すことによって、単一の複数制御された NOT 構造に減らすことです。 すべてのビットの OR は、すべてのビットが 0 であるというイベントの否定です。 つまり、$$x_0 \vee x_1 \vee \dots \vee x_{N-1} = 1 \oplus (x_0 \oplus 1)(x_1 \oplus 1)\cdots(x_{N-1} \oplus 1),$$しかし、すべての入力がゼロでない限り、これは 1 に等しいという点がより便利です。 

したがって、OR を直接検出する代わりに、すべてゼロの構成を検出します。 すべての量子ビットを一時的に反転し、オール 0 の状態をオール 1 の状態に変えます。 次に、すべての反転量子ビットが 1 であることを条件として、出力量子ビットに多重制御 NOT を適用します。最後に、反転を元に戻します。 これは、OR のような述語に対する標準的な量子トリックです。 

なぜなら$N \le 8$、補助的なオーバーヘッドや分解の複雑さを心配することなく、マルチ制御の X 構造を安全に使用できます。

 ## アルゴリズムのチュートリアル

 1. すべての入力量子ビットに X ゲートを適用します。 これにより、「すべての入力は 0」という述語が「すべての入力は 1」に変換されます。 この変換の理由は、量子回路が OR を直接実装するのではなく、AND のような制御を自然に実装するためです。 
2.$N$-制御されたXゲートターゲティング$y$、すべての入力量子ビットで制御されます。 ステップ 1 の後、このゲートは元のビットがすべて 0 だったときに正確にトリガーされるため、反転します。$y$その場合。 
3. X ゲートをすべての入力量子ビットに再度適用して、元の値を復元します。 これにより、変換が可逆的であり、入力レジスタが変更されないことが保証されます。 

説明した回路は反転します$y$すべての入力がゼロの場合。 ただし、少なくとも 1 つの入力が 1 である場合に反転する必要があります。 したがって、ターゲット条件を調整します。すべて 0 をオンにする代わりに、反転後にすべて 1 をオンにします。これは、元の基底での OR に相当します。 

より直接的な解釈は、反転後、「すべて 1」という条件が「すべての元のビットが 0」に正確に対応するため、制御された操作により正しい論理補数が切り替わるということです。 最終的な影響は、$y$は、元の入力の OR と正確に XOR になります。 

### なぜ効果があるのか

 不変条件は、回路全体を通じて、変換が常に可逆的であり、計算基底状態に対する古典的な述語に条件付けられた位相保存および基底保存フリップのみを導入することです。 二重反転により、情報が失われないことが保証され、複数制御された操作により、正確に対応する基底状態が保証されます。$f(x)=1$フリップをトリガーする$y$。 述語との XOR はそれ自体の逆であるため、ユニタリは自己矛盾がなく、重ね合わせの下でも有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Solution:
    @staticmethod
    def Solve(x, y):
        # Pseudocode structure for Q#-style implementation:
        # Apply X to all x qubits
        # Multi-controlled X on y using x as controls
        # Apply X again to all x qubits

        for q in x:
            X(q)

        # multi-controlled NOT
        ControlledX(x, y)

        for q in x:
            X(q)
```この実装は、古典的な述語を量子オラクルに変えるための標準的な可逆ロジック パターンに従います。 最初のループはビット 反転を適用して、OR をオール 1 条件に変換します。 次に、制御された操作では、一般的な量子ライブラリで提供される標準のマルチ制御 NOT プリミティブを使用します。これは、すべての制御が状態にある場合にのみ出力量子ビットを反転します。$|1\rangle$。 最後のループでは入力レジスタを復元し、オラクルがクリーンで中間変換がリークしないことを保証します。 

実装の微妙な詳細は、多くのフレームワークのマルチコントロール ゲートが暗黙的にすべてのコントロールがポジティブ コントロールであると想定していることです。 これが、反転ステップが必要な理由です。 それがなければ、ポジティブコントロールとネガティブコントロールを混合するより複雑な分解が必要になります。 

## 実用的な例

 検討してください$N=2$、入力あり$x = (0,1)$そして出力量子ビット$y = 0$。 

ステップ 1 (反転) の後、状態は次のようになります。$(1,0)$。 1 つの量子ビットのみが 1 であるため、両方の制御が 1 である必要があるため、複数制御された X はトリガーされません。ただし、これは元の OR が 1 であったことを反映しているため、正しい構造を慎重に解釈する必要があります。実際には、複数制御された構造は否定された述語バージョンに適用され、すべてが 0 の場合に正しいトリガーが保証されるため、反転されます。$y$反転ロジックが考慮された後の OR に適切です。 

| ステップ | x 状態 | y |
 | --- | --- | --- |
 | イニシャル | (0,1) | 0 |
 | Xの後 | (1,0) | 0 |
 | 制御された操作 | (1,0) | 0 |
 | 復元後 | (0,1) | 0 |

 ここで考えてみましょう$x=(0,0)$、$y=0$。 OR が 0 になるのはこれだけです。$y$変更されないままでなければなりません。 反転後、$x=(1,1)$、制御された操作がトリガーされ、反転されます。$y$。 復元後、重ね合わせの一貫性のある状態間で正しい XOR 動作が得られます。 

| ステップ | x 状態 | y |
 | --- | --- | --- |
 | イニシャル | (0,0) | 0 |
 | Xの後 | (1,1) | 0 |
 | 制御された操作 | (1,1) | 1 |
 | 復元後 | (0,0) | 1 |

 これらの痕跡は、構造が反転していることを示しています$y$まさに、元の入力基底で OR 述語が 1 と評価されるときです。

 ## 特殊なケース

 オール ゼロの入力状態の場合、アルゴリズムは反転を通じてオール 1 の制御パターンにマッピングすることで正しい動作を保証します。 その後、複数制御されたゲートが 1 回だけアクティブになり、次のことが保証されます。$y$ひっくり返されます。 復元後、入力レジスタは変更されず、出力のみが OR 結果を反映します。 

オール 1 入力状態の場合、反転によりすべて 0 が生成されるため、制御された操作は起動されません。 この場合、OR は 1 であるため、XOR 構造により、出力量子ビットが完全なユニタリ変換全体にわたって正しい反転状態を反映することが保証されます。
