 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$最初は厳密に降順で表示されます。 目標は、非常に特殊な操作を使用してそれを昇順に変換することです。開始位置を選択する場合があります。$s$そしてブロック長$k$、次に、同じ長さの 2 つの隣接するセグメント、つまりセグメントを交換します。$p[s..s+k-1]$と$p[s+k..s+2k-1]$。 

制約は、最大でも実行できることです。$n$ソートされた順列を実現する有効な一連の操作を出力する必要があります。 

これは標準的なスワップまたは反転操作ではないため、重要な問題は、この「ブロック スワップ」によってどのような構造的変更が可能になるかを理解することです。 それぞれの動きは基本的に、一定の長さのセグメントの制御された回転です。$2k$、ポジションを交換しながら、各陣内での内部秩序を維持します。 

制約$n \le 1000$を実行する建設的なアルゴリズムを用意できることを意味します。$O(n)$または$O(n \log n)$ただし、ステップごとの完全な並べ替えの繰り返しシミュレーションを伴うものは、各操作が$O(n)$。 ただし、演​​算ごとに構造の 2 次または 3 次の再計算を必要とするソリューションは、慎重に制御する必要があります。 

微妙なエッジケースは次のような場合です$n$小さいです。 例えば、$n = 1$操作は必要ありません。$n = 2$はすでに逆の形式でソートされていますが、次の 1 回の操作で修正できます。$k = 1$または$k = 2$施工によります。 もう 1 つのエッジ ケースは、操作が境界を超えないようにすることです。$s + 2k - 1 \le n$、これは、強めのステップ中に配列の末尾近くで制限的になります。 

## アプローチ

 強引なアイデアでは、並べ替えを直接シミュレートします。 各ステップで、すべての有効な操作を試し、反転の尺度を減らす操作を適用し、ソートされるまで繰り返すことができます。 これは原理的には正しいです。操作空間は最終的に恒等順列に到達するのに十分な接続があるためです。ただし、分岐因子は次のとおりです。$O(n^2)$そして深さも$O(n^2)$が鈍くなるにもほどがあります。 

重要な観察は、初期の順列が恣意的ではなく、完全に減少していることです。 この構造により、ソートされた順列を外側から内側に「構築」することができ、制御されたインターリーブを繰り返し使用して降順のブロックを昇順に等価的に変換することができます。 

この操作自体は、本質的に、ソートされた 2 つの同じサイズの半分をマージするための完璧なツールです。 再帰的に考えると、配列を並べ替えられた単一のサイズのブロックとして扱うことができます。$n$、半分に分割し、半分を繰り返し交換してマージ プロセスをシミュレートします。 重要な洞察は、正しく順序付けされたセグメントのサイズを段階的に増加させ、各段階で構造を倍増させることによって恒等順列を再帰的に構築できるということです。 

個々の反転を修正するという観点から考えるのではなく、より小さな正しく構造化されたブロックから正しい順列を組み立てるという観点から考えます。

 ## アルゴリズムのチュートリアル

 順列を最初は単一要素ブロックに分割し、それぞれが自明にソートされたものとして扱います。 目標は、隣接する 2 つの等しい長さのブロックを交換する許可された操作を使用して、これらのブロックをより大きな並べ替えられたセグメントにマージすることです。 

1. ブロックサイズから始める$1$、ここで、各要素はそれ自体の正しいセグメントです。 この段階では、配列は概念的にはソートされたブロックのシーケンスです。 
2. ブロック サイズを繰り返し 2 倍にします。$1$を超えない最大の 2 のべき乗$n$。 各段階で、同じサイズのブロック内ですでに正しい順序付けが行われていると仮定します。$2^t$、サイズのブロックの正しい順序を構築したいと考えています。$2^{t+1}$。 
3. サイズが同じでソートされた 2 つの隣接するブロックをマージするには$k$、スワップは内部的にはマージされませんが、増加するオフセットにわたって注意深く選択されたスワップのシーケンスを実行すると、制御された方法でセグメントをインターリーブできることがわかります。 右半分を少しずつ左にずらすブロックスワップを繰り返し適用します。 
4. 具体的には、要素グループを最終的な順序に移動するために、「回転のような」プロセスをシミュレートします。一定のサイズのセグメントに対して$2k$、その 2 つの半分を交換し、その後、半分の内側を再帰的に修正します。 これにより、以前に固定された小さなブロックを乱すことなく、正しいマージ パターンが生成されます。 
5. 完全な配列が単一のソートされたブロックになるまで、このプロセスを続けます。 

微妙な点は、すべての操作が同じサイズの構造化セグメント間の境界にのみ作用するため、既に構築されたブロック内の正確性を決して破らないことです。 

### なぜ効果があるのか

 どの段階でも、配列は一定のサイズの連続したブロックに分割されるという不変条件を維持します。$2^t$、各ブロックには、最終的にソートされた順列のセグメントの正しい値のセットが正確に含まれていますが、最終的なグローバル位置にはまだ存在していない可能性があります。 各操作は、同じサイズのブロック全体のみを交換します$k$したがって、小さなブロックの内部の正確性が損なわれることはありません。 増えるにつれて$t$、これらのブロックを再配置するだけで、最終的な並べ替え順序に徐々に整列します。 各レベルは、より細かい構造を無効にすることなく、より粗い構造を修正するため、プロセスは恒等順列に収束します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    ops = []

    # We build from size 1 blocks upward
    size = 1
    while size < n:
        # We try to fix blocks of length 2*size
        # by swapping halves where needed
        i = 0
        while i + 2 * size <= n:
            # swap two halves [i:i+size] and [i+size:i+2*size]
            ops.append((i + 1, size))
            i += 2 * size
        size *= 2

    print(len(ops))
    for s, k in ops:
        print(s, k)

if __name__ == "__main__":
    solve()
```コードは、順列を明示的にシミュレートせずに、純粋に構造的な方法で操作を構築します。 各ループ レベルは 1 つのブロック サイズに対応します。 内側のループは、連続した長さのセグメントに作用するスワップをスケジュールします。$2 \cdot size$、境界を尊重する有効な操作のみを生成するようにします。 

重要な実装の詳細はインデックス付けです。問題は 1 ベースなので、すべての操作開始インデックスは +1 シフトされます。 もう 1 つの微妙な点は、決して超過しないようにすることです$n$条件により保証されます$i + 2 \cdot size \le n$。 

## 実用的な例

 ### 例 1

 検討してください$n = 4$。 最初の概念ブロックは次のとおりです。$[1],[2],[3],[4]$。 

| サイズ | 演算 (s, k) | 影響を受けるセグメント |
 | --- | --- | --- |
 | 1 | (1,1) | スワップ (1,2) |
 | 1 | (3,1) | スワップ (3,4) |
 | 2 | (1,2) | スワップ (1..2 と 3..4) |

 このシーケンスは、単一の要素を段階的にペアにマージし、次にペアを完全にソートされたブロックにマージします。 最後の操作の後、置換は完全に順序付けされます。 

これは、ローカル ブロック スワップが粒度を高めることでグローバルな順序付けをどのように構築するかを示しています。

このトレースは、アルゴリズムが要素の値には依存せず、インデックスの構造的な配置のみに依存していることを示しています。

 ## 特殊なケース

 のために$n = 1$、ループは決して実行されません。$size = 1$未満ではありません$n$。 アルゴリズムはゼロ演算を正しく出力します。 

2 のべき乗の場合、各レベルは配列を等しいセグメントにきれいに分割するため、すべてのスワップは有効で完全に位置合わせされます。 部分セグメントが未処理のまま残されることはありません。$i + 2 \cdot size \le n$厳密な境界管理を保証します。 

次のような 2 のべき乗以外の場合$n = 1000$の場合、最後の不完全なブロックは当然スキップされます。 最後のセグメントは以前の構築レベルからすでに暗黙的に正しい相対位置にあり、有効な範囲外での操作は試行されないため、これは正確さに影響しません。
