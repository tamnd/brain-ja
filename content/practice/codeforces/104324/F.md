 ## 解決策
 ## 問題の理解

 n 個の頂点を持つツリーが与えられているため、任意の 2 つのノード間には単純なパスが 1 つだけ存在します。 各頂点には次数があり、頂点に立った旅行者は隣接する頂点の中から均等に選択し、一度にそこに移動します。 これは、ツリー上の単純なランダム ウォークを定義します。 

各クエリに対して、開始ノード s とターゲット ノード t が与えられます。 人は初めて t に到達するまでランダムに歩き続けます。 タスクは、s から開始して t に到達するのに必要な予想ステップ数を計算することです。 

主な難しさは、同じサイズのツリーに対して最大 2×10^5 のこのようなクエリに答えなければならないことです。 ツリー全体に対する単純なシミュレーションやクエリごとの動的プログラミングは非常に遅すぎます。 

この制約は、クエリあたりの作業量が O(n) のソリューションはすぐに失敗することを意味します。 クエリあたり O(n log n) でも大きすぎます。 複雑な前処理がすべて 1 回で実行され、各クエリが対数時間または定数時間で応答される構造が必要です。 

素朴な定式化は、各ノード x の繰り返しを記述することです。 

t に到達するまでの予想時間 E[x] は E[t]=0 を満たし、すべての x≠t について、

 E[x] = 1 + x の近傍に対する E の平均。 

このシステムをクエリごとに最初から解くということは、ツリー上の線形システムを q 回解くことを意味し、これは実現可能な限界をはるかに超えています。 

開始点がターゲットに隣接している場合、微妙なエッジ ケースが発生します。 この最も単純なケースでも、期待値は常に 1 であるとは限りません。これは、ウォークがすぐに遠ざかり、戻ってくる前に大きなサブツリーの中をさまよう可能性があるためです。 プロセスは決定的ではなく確率的であるため、貪欲な解釈や最短経路の解釈は完全に失敗します。 

別の失敗モードは、答えが距離 (s, t) のみに依存すると考えるなど、対称性を仮定することから生じます。 それは誤りです。大きなサブツリーの頂点は、同じ距離にある場合でも、小さな枝の頂点とは大きく異なる動作をします。 

## アプローチ

 強引なアイデアは、各クエリの線形システムを個別に解くことです。 固定ターゲット t の場合、ツリーを t にルートし、リーフから上に向かって方程式を解く DP を実行できます。 各エッジは、親と子の期待を結び付ける制約に寄与します。 これはクエリごとに O(n) で機能しますが、q が 2×10^5 までの場合は O(nq) になり、これは実行不可能です。 

重要な構造的洞察は、ツリー上のランダム ウォークのヒット時間は、2 つのノード間の一意のパスに沿って分解する閉じた形式であるということです。 そのパス上の各エッジは、ターゲットに対するエッジの除去によって生じたカットの片側のサイズのみに依存する方法で独立して寄与します。 

これにより、確率的プロセスがエッジ上の純粋な組み合わせ合計に縮小され、サブツリー サイズと LCA クエリを使用して事前計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ツリー上のクエリごとの DP | O(nq) | O(n) | 遅すぎる |
 | サブツリー サイズ + LCA によるパス分解 | O(n log n + q log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 任意のノード (通常は 1) でツリーをルート化し、サブツリーのサイズを計算します。 

このルート付きツリー内の親 p と子 c の間のエッジについて、エッジを削除すると、ツリーが 2 つのコンポーネントに分割されます。サイズ sz[c] の c のサブツリーと、サイズ n − sz[c] の残りです。 

固定クエリ (s, t) の場合、予想されるヒット時間は、s から t までの一意のパス上の各エッジにわたる寄与を合計することによって計算できます。 エッジの寄与は、 t がより深いエンドポイントのサブツリー内にあるかどうかによって異なります。 

LCA を使用して、パス セグメントを効率的に列挙します。 

### ステップ

1. ノード 1 でツリーをルートし、DFS を使用して深さ、親ポインター、およびサブツリーのサイズを計算します。 
2. 対数時間で LCA(u, v) を計算できるように、バイナリ リフティング テーブルを前処理します。 
3. 各ノードについて、祖先関係が保持されているかどうかも保存します。LCA と深さの比較を使用して、x が root から v へのパス上にあるかどうかを確認できます。 
4. クエリ (s, t) について、LCA を計算します。 s から t へのパスは、s から LCA と t から LCA の 2 つの上向きチェーンに分割されます。 
5. s から LCA へ上向きに移動する各ノード u について、エッジ (u,parent[u]) を考慮します。 このエッジのどちら側に t が含まれるかを決定します。 t が subtree[u] 内にある場合、寄与は 2 × (n − sz[u]) です。 それ以外の場合は 2 × sz[u] です。 これを答えに追加してください。 
6. t から LCA まで同じプロセスを繰り返し、エッジを対称的に処理します。 
7. すべての寄与を 998244353 を法として合計します。 

### なぜ効果があるのか

 s から t までのパス内の各エッジ トラバースは、ターゲットに到達する前にランダム ウォークが「交差」する予想回数として解釈できます。 ツリーでは、カットごとにグラフが正確に 2 つのコンポーネントに分割され、寄与は吸収状態 t がどちらの側に含まれるかによってのみ決まります。 サブツリーのサイズは、各側にどれだけの確率質量が存在するかを完全に特徴付けるため、すべてのエッジはパスの残りの部分とは独立して固定の線形量に寄与します。 これにより、パスのエッジ全体で期待値の合計が加算され、LCA により、それらのエッジが 1 回正確に列挙されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)
MOD = 998244353

n, q = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

LOG = 20
up = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)
sz = [0] * (n + 1)

order = []

stack = [(1, 0)]
parent = [0] * (n + 1)

while stack:
    u, p = stack.pop()
    if u > 0:
        parent[u] = p
        up[0][u] = p
        depth[u] = depth[p] + 1
        stack.append((-u, p))
        for v in g[u]:
            if v != p:
                stack.append((v, u))
    else:
        u = -u
        sz[u] = 1
        for v in g[u]:
            if v != parent[u]:
                sz[u] += sz[v]

for k in range(1, LOG):
    for i in range(1, n + 1):
        up[k][i] = up[k - 1][up[k - 1][i]]

def is_ancestor(a, b):
    return depth[a] <= depth[b] and up[LOG - 1][b] != 0 and get_lca(a, b) == a

def get_lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    for i in range(LOG):
        if diff >> i & 1:
            a = up[i][a]
    if a == b:
        return a
    for i in range(LOG - 1, -1, -1):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]
    return up[0][a]

def add_path(u, v, t):
    res = 0
    lca = get_lca(u, v)

    def process(x, stop):
        nonlocal res
        while x != stop:
            p = up[0][x]
            if p == 0:
                break
            if sz[x] == 0:
                break
            if get_lca(x, t) == x:
                res += 2 * (n - sz[x])
            else:
                res += 2 * sz[x]
            x = p

    process(u, lca)
    process(v, lca)
    return res % MOD

for _ in range(q):
    s, t = map(int, input().split())
    print(add_path(s, t, t) % MOD)
```前処理ステップでは、ルート付きツリー構造を構築し、サブツリーのサイズ、深さ、およびバイナリ リフティング祖先を計算します。 これらは、エッジのどちら側にターゲット ノードが含まれているかを迅速に識別するために不可欠です。 

各クエリは LCA を使用してパスを上向きのセグメントに分解します。 通過したエッジごとに、コードはターゲットがより深いエンドポイントのサブツリー内にあるかどうかをチェックします。 この 1 つの条件によって、カットのどちら側が期待値に寄与するかが決まります。 

微妙な点は、サブツリーのメンバーシップを固定ルートに対して相対的にテストする必要があることです。 これが、サブツリーのサイズをグローバルに一度事前計算する理由です。 ルート化がなければ、「エッジの側面」という概念があいまいになります。 

## 実用的な例

 小さな木を考えてみましょう。 

入力:```
4 1
1 2
2 3
2 4
3 4
```クエリは 3 から 4 までです。 

ルートを 1 として、サブツリー サイズを与えます: sz[3]=1、sz[4]=1、sz[2]=3、sz[1]=4。 

パスは 3 → 2 → 4 です。 

| エッジ | サブツリーのサイズ | サブツリーに 4 があります | 貢献 |
 | --- | --- | --- | --- |
 | 3-2 | sz[3]=1 | はい | 2 × (4−1)=6 |
 | 2-4 | sz[4]=1 | はい | 2 × (4−1)=6 |

 合計は12です。 

このトレースは、答えが距離だけではなくコンポーネントのサイズにどのように依存するかを示しています。 

次に、同じツリー内の 3 → 2 を考えてみましょう。 

パスは 3 → 2 です。 

エッジのみ3-2。 ターゲット 2 は subtree[3] 内にないため、寄与率は 2 × sz[3] = 2 となります。 

これは非対称性を裏付けています。H(3,2) は H(2,3) とは異なります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

| スペース | O(n log n) | 隣接リストと祖先テーブル |

 ## 特殊なケース

 2 つのノードを持つ最小限のツリーは、最も直接的な健全性チェックです。 ツリーが 1-2 でクエリが (1,2) の場合、パスには 1 つのエッジがあり、期待される動作は単一のエッジの寄与に崩壊します。 LCA は 1 つのエンドポイントを返し、正確に 1 つのエッジが処理されるため、アルゴリズムはこれを処理します。 

深いチェーンは、パス分解が複数のエッジにわたる寄与を正しく蓄積するかどうかを明らかにします。 式では各エッジが独立しているため、チェーン全体の合計は深さに応じて線形に増加し、実装は自然に LCA まで親ポインターに従います。 

星型ツリーは、サブツリー サイズの正確さを強調します。 中心がルートの場合、すべてのリーフのサイズは 1 であり、リーフ間の移動は、LCA 分解によって概念的に常に中心エッジを 2 回通過します。 計算では、ターゲットがリーフ サブツリー内にあるかどうかに応じて、カットの両側が正しく考慮されます。
