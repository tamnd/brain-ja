 ## 解決策
 ## 問題の理解

 ユーザーは、軸に沿った直線の道路セグメントで構成されるルートに沿って都市を歩いています。 各セグメントは完全に水平または完全に垂直であるため、いつでもユーザーの位置は 1 つの座標で直線的に移動しますが、もう 1 つの座標は固定されたままになります。 

飛行機にはいくつかの携帯電話の塔が固定されています。 散歩中のあらゆる瞬間に、電話は最も近い塔に接続されます。 これを最小ユークリッド距離と呼ぶとすると、$t$として$f(t)$の場合、オペレーターは歩行全体の二乗距離の積分に基づいて料金を請求します。 言い換えれば、あらゆる瞬間は、ユーザーが最も近いタワーからどれだけ離れているかの二乗に等しい量を寄与し、それを時間の経過とともに継続的に蓄積します。 

出力は単一の実数、つまり累積コストの合計です。 

制約は十分に小さいため、数百万回程度の算術演算の解は許容されます。 最大 2000 のタワーと最大 500 のルート ポイントがあるため、セグメントの数は最大 499 です。座標は次のように制限されているため、各セグメントの長さは最大 2000 です。$[-1000, 1000]$。 これにより、細かい離散化を使用して各時間ステップですべての塔までの距離を評価しようとするものは直ちに排除されます。 

各時間単位をサンプリングする単純な連続シミュレーションでは、最悪の場合でも依然として遅すぎます。$500 \cdot 2000 = 10^6$ステップ、および各ステップで 2000 個のタワーをチェックすると、$2 \cdot 10^9$距離の計算。 

ジオメトリでは、より微妙な問題が発生します。最も近いタワーがセグメント内で連続的に変化する可能性があります。 セグメントの終点でのみ最も近いタワーを選択した場合でも、別のタワーが中央に近づくという事実を見逃す可能性があります。 たとえば、パスの反対側にある 2 つの塔は、途中でどちらが最も近いかを「交換」できます。 

したがって、重要な困難は、距離を評価するだけではなく、多くの二次関数の下限エンベロープを継続的に追跡することです。 

## アプローチ

 単一の直線セグメント上で、ユーザーの位置は 1 つのパラメータに依存します$t$、そのセグメントの開始からの時間。 セグメントが水平の場合、一方の座標は一定で、もう一方の座標は線形です。$t$。 固定タワーまでの二乗距離は、次の二次関数になります。$t$。 注意深く拡大すると、すべての塔が放物線を描きます。$t$、そして必要な関数はこれらすべての放物線の最小値です。 

したがって、各セグメントは、「最小の」形式の関数を統合することになります。$n$区間にわたる二次関数」。 

ブルートフォース手法では、時間を非常に細かい解像度で離散化し、各時点で最も近いタワーを再計算します。 これは関数の定義に直接従うため概念的には機能しますが、各評価ではすべてのタワーをスキャンする必要があるため、計算的には実行不可能です。 

重要な構造的観察は、すべての二次関数が同じ主要係数を共有していることです。$t^2$。 距離表現を拡張した後、各タワーは形状の機能に貢献します$$t^2 + (linear\ in\ t) + constant.$$これは、すべてのタワーの最小値を普遍的な凸項に分割できることを意味します。$t^2$一連の行にわたる最小値を加えたもの。 問題が「ある区間にわたる最小ライン数」になると、下部エンベロープを明示的に構築できる古典的な凸包問題になります。 

最小値を点ごとに動的に追跡する代わりに、各セグメントの線の下側包絡線全体を計算し、それを単一の線が最適な区間に分割し、各区間で分析的に統合します。 

素朴な考えのボトルネックは、再計算の繰り返しです。 最適化は、各セグメントが独立しており、完全な凸包を最初から構築するのが安価であるほど十分に小さいことを利用することです。

 ## アルゴリズムのチュートリアル

 マルコのパスの各セグメントを個別に処理します。 

1. セグメントの場合、時間の経過に伴う動きをパラメータ化します。$t \in [0, L]$、 どこ$L$セグメントのマンハッタンの長さです。 位置が直線的になります$t$、どちらかが変化する$x$または$y$一方、他の座標は固定されたままになります。 これにより、距離の二乗が多項式になります。$t$。 
2. すべての塔について、二乗ユークリッド距離をマルコの位置まで展開します。 結果は常に次の形式になります。$$f_i(t) = t^2 + a_i t + b_i.$$の$t^2$この用語はすべてのタワーで同一です。 
3. 共通の 2 次項を因数分解します。 実際に最小化する必要がある関数は次のようになります。$$\min_i f_i(t) = t^2 + \min_i (a_i t + b_i).$$これにより、幾何学的な問題が線のより低いエンベロープを維持することに軽減されます。 
4.すべての行を集める$a_i t + b_i$現在のセグメントの場合。 各タワーは 1 つの回線に寄与するため、セグメントごとに最大 2000 回線があります。 
5. これらの線を傾きで並べ替えます$a_i$。 この順序により、下部エンベロープを形成する線の凸包を構築できます。 建造中には、最後の船体のラインとの交差位置を確認し、決して最適ではないラインを破棄します。 
6. 船体を構築した後、船体上の連続する線間の交点を計算します。 これらの交点は、$t$-axis では単一行が最小限になります。 
7. すべての間隔をセグメント領域にクリップします$[0, L]$。 クリップされた間隔ごとに、以下を統合します。$$\int (t^2 + a t + b)\, dt$$閉じた形式の逆導関数を使用する:$$\frac{t^3}{3} + \frac{a t^2}{2} + b t.$$8. すべての船体間隔にわたる寄与を合計し、グローバルな答えに追加します。 

### なぜ効果があるのか

 いつでも$t$、最も近い塔はまさに二次関数が最小値に達する塔です。 すべての二次関数は同じ曲率を共有するため、それらを比較すると、共通項を削除した後は一次関数の比較になります。 凸包構造により、すべての間隔が保証されます。$t$には正しい最小化ラインがあり、最も近いタワーのあらゆる変化は 2 つの船体ライン間の交差に正確に対応します。 積分は正確な正確な区間ごとに個別に実行されるため、近似は導入されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def integrate_quad(a, b, l, r):
    # integral of t^2 + a t + b from l to r
    def F(x):
        return x**3 / 3 + a * x**2 / 2 + b * x
    return F(r) - F(l)

def cross(a1, b1, a2, b2):
    # intersection of a1 x + b1 and a2 x + b2
    # solve a1 x + b1 = a2 x + b2
    return (b2 - b1) / (a1 - a2)

def solve_segment(lines, L):
    # lines: (a, b)
    lines.sort()  # sort by slope

    hull = []
    for a, b in lines:
        while len(hull) >= 2:
            a1, b1 = hull[-2]
            a2, b2 = hull[-1]
            a3, b3 = a, b
            # check if middle line is useless
            if (b2 - b1) * (a2 - a3) >= (b3 - b2) * (a1 - a2):
                hull.pop()
            else:
                break
        hull.append((a, b))

    # build segments
    pts = [0.0]
    segs = []

    for i in range(len(hull) - 1):
        a1, b1 = hull[i]
        a2, b2 = hull[i + 1]
        x = cross(a1, b1, a2, b2)
        pts.append(x)

    pts.append(L)

    for i in range(len(hull)):
        l = max(0.0, pts[i])
        r = min(L, pts[i + 1])
        if r > l:
            a, b = hull[i]
            segs.append((a, b, l, r))

    res = 0.0
    for a, b, l, r in segs:
        res += integrate_quad(a, b, l, r)

    return res

def main():
    n = int(input())
    towers = [tuple(map(int, input().split())) for _ in range(n)]

    m = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(m)]

    ans = 0.0

    for i in range(m - 1):
        x1, y1 = pts[i]
        x2, y2 = pts[i + 1]

        dx = x2 - x1
        dy = y2 - y1
        L = abs(dx + dy)  # one coordinate changes

        lines = []

        if x1 == x2:
            # vertical: y changes
            step = 1 if y2 > y1 else -1
            for xi, yi in towers:
                a = 2 * (y1 - yi) * step
                b = (y1 - yi) ** 2 + (x1 - xi) ** 2
                lines.append((a, b))
        else:
            # horizontal: x changes
            step = 1 if x2 > x1 else -1
            for xi, yi in towers:
                a = 2 * (x1 - xi) * step
                b = (x1 - xi) ** 2 + (y1 - yi) ** 2
                lines.append((a, b))

        ans += solve_segment(lines, L)

    print(f"{ans:.10f}")

if __name__ == "__main__":
    main()
```コードは各セグメントを分離し、共有の 2 次項を取り除いた後、各タワーを時間の一次関数に変換します。 凸包は、斜面のソートと最適でないラインの剪定によって構築されます。 連続する船体のライン間の交点は、優勢な正確な領域を定義し、統合は各領域に対して分析的に実行されます。 

唯一の微妙な部分は、を使用して方向を正しく処理することです。`step`、トラバーサルを反転すると線形係数の符号が反転しますが、二次項または定数項は変更されないためです。

 ## 特殊なケース

 特殊なケースは、複数のタワーが変換後に同一の線形係数を生成する場合に発生します。 その場合、凸包構造はそれらを冗長なものとして扱うことができます。 同一のラインが同一の寄与を最小限に定義するため、アルゴリズムは引き続き機能し、重複を削除してもエンベロープは変更されません。 

もう 1 つの微妙なケースは、最も近いタワーがセグメント エンドポイントの境界で正確に切り替わる場合です。 交差の計算により、0 または 0 に等しい端点が生成されます。$L$、クリッピングステップにより、重複または欠落した間隔が 2 回寄与することがなくなります。 

3 番目のケースでは、交差を計算する際の浮動小数点精度が関係します。 すべての座標は整数であり、セグメントの長さが短いため、倍精度で十分ですが、ほぼ等しい交点の順序が間違っていないように注意する必要があります。
