 ## 解決策
 ## 問題の理解

 私たちは 2 つの学生グループから「チーム」を編成しようとしています。 学部生の中から正確に 3 人の異なる学生を選択する必要があり、このチームの質は彼らの強さの値の合計です。 大学院生の中から、コーチとして活動する学生を 1 人だけ選びます。 

コーチはチームの強さを厳密に上回っていなければなりません。すべての有効な選択肢の中で、私たちはコーチがチームの強さにできるだけ近いことを望んでいます。 言い換えれば、卒業生の強みを厳密に大きく保ちながら、選択した卒業生の強みと 3 つの学部の強みの合計との間のプラスのギャップを最小限に抑えたいと考えています。 

入力は 2 つの配列で構成されます。 最初の配列には学部の強みが含まれており、増加するインデックス トリプルを選択する必要があります。 2 番目の配列には卒業生の強みが含まれており、そのいずれかを選択します。 出力は、制約を満たす 1 つの有効なインデックスの 4 倍になるか、学部生の可能なすべての 3 倍に勝てるほど強い卒業生がいない場合は -1 になります。 

制約は十分に小さいため、学部生に対する三次列挙は実現可能です。 n が最大 300 の場合、トリプルの数は約 450 万であり、これは境界線ですが、慎重に実行すれば Python では許容可能です。 m も 300 なので、前処理後でも各合計とすべてのコーチのペアリングは妥当です。 

微妙な失敗例は、複数のトリプルの合計が同じでインデックスが異なる場合、または複数のコーチが同じチーム合計を異なるギャップでカバーできる場合に発生します。 「最強のコーチと最強のチームを採用する」といった素朴な貪欲な考えは失敗します。なぜなら、最強のコーチは不必要に大規模になる可能性があるためです。最適な解決策は、中規模のコーチと少し大きなチームを組み合わせることがよくあります。 

もう 1 つのよくある落とし穴は、厳密な不等式 bk > sum を忘れることです。 誤って等価性が許可された場合、アルゴリズムは無効なペアを受け入れ、不正確な最小ギャップを生成します。 

## アプローチ

 ブルートフォースアプローチは簡単です。 私たちは学部生の 3 人全員を列挙し、その合計を計算し、すべての大学院生に有効なコーチを見つけようと試みます。 各トリプルについて、すべての m 個のコーチをスキャンして、トリプルの和よりも大きい最小の bk を見つけます。 これはすべての可能性を直接チェックするので正しいですが、コストが O(n^3 m) (およそ 300^3 × 300) と大きすぎます。 

重要な観察は、問題を 2 つの部分に分離できるということです。 まず、すべての学部トリプルは合計のマルチセットを生成します。 第 2 に、各合計について、それより厳密に大きい最小の卒業値のみを考慮します。 これは、卒業生の強みを分類し、二分探索を使用することを提案しています。 固定和に対する最適なコーチがわかったら、問題は卒業配列の上限との差を最小にする三重和を見つけることになります。 

そこで、すべての O(n^3) 三重和を事前に計算し、各和について、ソートされた卒業生リストを二分探索して、それより大きい最小値を見つけます。 それによって答えの候補が得られます。 最適解とは、単にこれらすべての候補の中で最も優れたものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3 m) | お(1) | 遅すぎる |
 | 最適 | O(n^3 log m) | O(n^3) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはすべての学部生のトリプルを列挙し、それぞれを可能な限り最高の大学院生コーチとペアにすることを中心にソリューションを構築します。

1. 元のインデックスとともに卒業配列を並べ替えます。 並べ替えにより、二分探索を使用してチームの合計より厳密に大きい最小値を効率的に見つけることができます。 これは、すべてのコーチにわたる線形スキャンを置き換えます。 
2. 学部配列内のすべてのトリプル i < j < q を反復し、それらの合計 s = ai + aj + aq を計算します。 各トリプルは候補チームを表します。 
3. 各合計 s に対して、ソートされた大学院配列で二分検索を実行し、bk > s となる最初のインデックス k を見つけます。 そのようなインデックスが存在しない場合、このトリプルは有効なチームを形成できないため、スキップされます。 
4. 有効なコーチが見つかったら、差 bk - s を計算します。 グローバルなベストアンサーを維持し、より小さな違いが見つかるたびにそれを更新します。 
5. 改善が発生するたびに、i、j、q、および選択したコーチの対応するインデックスを保存します。 トリプルのインデックスは列挙から直接保存され、コーチ インデックスはソートされた配列に格納された元のインデックスから取得されます。 

なぜそれが機能するのかは、直接最小化構造からわかります。 固定された学部の三重和 s ごとに、可能な限り最良のコーチは、厳密に s より大きい最小の卒業生の値です。 どんなに大きなコーチでも差は広がるばかりです。 したがって、考えられるすべての を列挙すると、各候補チームに最適な組み合わせが検討されたことが保証され、これらの組み合わせの全体的な最小値を選択することで正しい答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

b_sorted = sorted([(val, idx + 1) for idx, val in enumerate(b)])

best_diff = float('inf')
ans = None

# pre-extract values and indices separately for faster access
b_vals = [x[0] for x in b_sorted]
b_idx = [x[1] for x in b_sorted]

def lower_bound(x):
    lo, hi = 0, m
    while lo < hi:
        mid = (lo + hi) // 2
        if b_vals[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo

for i in range(n):
    for j in range(i + 1, n):
        for q in range(j + 1, n):
            s = a[i] + a[j] + a[q]
            pos = lower_bound(s)
            if pos == m:
                continue
            diff = b_vals[pos] - s
            if diff < best_diff:
                best_diff = diff
                ans = (i + 1, j + 1, q + 1, b_idx[pos])

if ans is None:
    print(-1)
else:
    print(*ans)
```出力には元のラベルが必要であるため、コードは最初に元のインデックスを維持しながら卒業生の強度を並べ替えます。 二分探索関数は、最初の卒業生が指定されたチームの合計よりも厳密に大きいことを検出します。これは、平等が許されないため重要です。 

トリプル ループは、すべての学部の組み合わせをインデックスの昇順で列挙します。これにより、追加のチェックを行わずに、必要な制約 i < j < q が保証されます。 

唯一の微妙な実装の詳細は、バイナリ検索で以上の値ではなく、厳密に大きい値が返されるようにすることです。 これは、b_vals[mid] <= x の場合に境界をプッシュすることで処理されます。 

## 実用的な例

 次の入力を考えてみましょう。```
3 2
1 2 3
10 8
```トリプルを 1 つだけ列挙します。 

| 私 | j | q | 合計 | ベストコーチインデックス | コーチの価値 | 差分 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 3 | 6 | 2 | 8 | 2 |

 有効なコーチは 8 のみです。これは、6 より大きい最小値であるためです。したがって、結果は (1, 2, 3, 2) になります。 

ここで次のことを考えてみましょう。```
3 2
1 2 3
6 4
```| 私 | j | q | 合計 | ベストコーチインデックス | コーチの価値 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 3 | 6 | なし | なし |

 厳密に 6 より大きい卒業値はないため、有効なペアは存在せず、答えは -1 になります。 

これらの例は、選択ロジックと厳密な不等式要件の両方を確認します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    b_sorted = sorted([(val, idx + 1) for idx, val in enumerate(b)])
    b_vals = [x[0] for x in b_sorted]
    b_idx = [x[1] for x in b_sorted]

    def lower_bound(x):
        lo, hi = 0, m
        while lo < hi:
            mid = (lo + hi) // 2
            if b_vals[mid] <= x:
                lo = mid + 1
            else:
                hi = mid
        return lo

    best_diff = float('inf')
    ans = None

    for i in range(n):
        for j in range(i + 1, n):
            for q in range(j + 1, n):
                s = a[i] + a[j] + a[q]
                pos = lower_bound(s)
                if pos == m:
                    continue
                diff = b_vals[pos] - s
                if diff < best_diff:
                    best_diff = diff
                    ans = (i + 1, j + 1, q + 1, b_idx[pos])

    return "-1\n" if ans is None else " ".join(map(str, ans)) + "\n"

 ## 特殊なケース

 エッジケースの 1 つは、すべての学部生の合計がすべての大学院生の強度を超える場合に発生します。 例えば：```
3 2
10 20 30
5 6
```このアルゴリズムはすべての 3 つの合計を計算し、常にバイナリ検索で m が返されることがわかります。これは、有効なコーチが存在しないことを意味します。 bk > s を満たすペアがないため、正解は -1 になります。 

もう 1 つのケースは、複数のトリプルが同じ最大の差を生み出す場合です。 例えば：```
4 3
1 2 3 4
10 10 10
```すべてのトリプルの合計は異なりますが、最良のコーチ値は同じです。 アルゴリズムは、厳密に小さい差が現れた場合にのみ更新されるため、有効な最適なトリプル コーチ ペアが返されます。これは、あらゆる最適な答えが受け入れられるという問題の要件と一致します。
