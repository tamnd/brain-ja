 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、$n$それぞれが 5 桁の文字列として記述される個別の郵便番号 (先頭のゼロが許可されるため、すべてのコードは長さ 5 桁の固定長文字列として扱うことができます)$0$に$9$）。 各郵便番号をグラフ内のノードとして考えてください。 

2 つのノードのコードが正確に異なる場合、接続されています。$k$位置、つまり正確に$k$5 桁の位置のうちの桁が異なり、残りの桁は異なります。$5-k$桁が同じ位置にあります。 

すべての開始ノードに対して$s$Tommaso はそのノードから開始し、直接接続されているすべてのノードを繰り返し検出し、それらのノードから続行して、グラフの接続されたコンポーネント全体を効果的に取得します。 タスクは、各ノードの接続コンポーネントのサイズを計算することです。 

重要な制約は、$n$と同じ大きさにすることができます$10^5$、各コードは固定長 5 を持ちます。 この組み合わせは重要です。グラフのノード数は多くなりますが、ノードごとの構造は非常に小さいです。 すべてのペアを明示的に構築またはチェックしようとするソリューションは、次の理由によりすぐに失敗します。$O(n^2)$比較はすでに行われています$10^{10}$操作。 

本当の難しさは、隣接関係が単純なプレフィックスや等価条件ではなく、正確なハミング距離条件によって定義されるため、単純なハッシュやソートのトリックでは直接解決できないことです。 

多くの郵便番号が桁の大きな重複を共有する場合、微妙なエッジケースが発生します。 たとえば、すべてのコードが 1 つの位置のみで異なる場合、$k=1$グラフは非常に密になり、単純なペア列挙では、多くのほぼ同一の文字列を繰り返し比較することになります。 もう 1 つのエッジケースは次のような場合です$k=5$、エッジはすべての位置で異なるコードを接続しますが、これは非ローカルであり、単純なプレフィックス グループ化ではキャプチャできません。 

## アプローチ

 直接的なアプローチは、郵便番号のすべてのペアを比較し、5 桁の位置でハミング距離を計算することです。 これはエッジの定義に直接従うため正しいですが、それには次のことが必要です。$O(n^2 \cdot 5)$操作。 と$n = 10^5$、これは完全に不可能になり、次のオーダーに達します。$10^{10}$比較。 

改善するために、文字列の長さが 5 に固定されているという事実を利用しようとします。 完全なペアごとの比較という観点から考えるのではなく、視点を変えます。2 つのコード間の違いは、どの位置が一致するか、どの位置が一致しないかによってのみ決まります。 これは、固定位置のパターンによってノードをグループ化することを示唆しています。 

重要な観察点は、正確な距離にあるノードを直接検索するのではなく、$k$、各ノードについて、位置のサブセット上でそのノードと一致する他のノードの数を数えることができます。 位置のサブセットごとに、そのサブセット上の正確な数字を共有するノードの数がわかっている場合は、位置のサブセットに対する包含/除外を使用して、指定された位置のセットに正確に一致するノードの数を再構築できます。 

これにより、問題は、明示的なグラフの構築から、非常に小さな宇宙、つまり 5 つの位置のべき乗集合、つまり、$2^5 = 32$サブセット。 その制限された構造により、必要なすべての相互作用を効率的に計算できます。$10^5$ノード。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアワイズ比較 |$O(n^2 \cdot 5)$|$O(1)$| 遅すぎる |
 | 包含/除外を使用したサブセットのカウント |$O(n \cdot 2^5 \cdot 2^5)$|$O(n \cdot 2^5)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各郵便番号を 5 桁の配列として扱います。 位置のサブセットについては、それらの位置の数字のみを抽出することで署名を定義します。 

1. ポジションのサブセットごとに$S$、すべての郵便番号を署名に基づいてグループ化します。$S$。 各ノードについて$i$、すぐに計算できます$A_S(i)$、これは一致するノードの数です$i$すべてのポジションで$S$。 これは、同じ署名があるため機能します。$S$それらの立場の平等を保証します。 
2. 「一致」よりも正確なものが必要です。$S$”。どの位置が一致するかを正確に知る必要があります。このために、スーパーセットに対する包含/除外を使用します。定義$E_S(i)$一致する位置のセットを持つノードの数として$i$まさに$S$。 これらの値は、正確な等価パターンを分離します。 
3. 計算します$E_S(i)$すでにわかっている値から$A_T(i)$、 どこ$T \supseteq S$。 この関係は、ノードが一致する場合に次のようになります。$i$少なくともすべてのポジションで$S$、それはすべてでカウントされます$A_T(i)$スーパーセット用$T$。 交互の合計を使用して、これをサブセット格子上で反転します。 
4. すべての完全一致パターンがカウントされたら$E_S(i)$がわかっている場合は、正確にすべての構成を特定します。$5-k$ポジションは一致します。 そのような各サブセット$S$ハミング距離を正確に求める有効な方法に対応します$k$。 合計します$E_S(i)$すべてのサブセットにわたって$S$サイズの$5-k$ノードの最終的な答えを取得するには$i$。 

### なぜ効果があるのか

 正確さは、ノードのすべてのペアが、それらが一致する位置の一意のサブセットに対応するという事実に基づいています。 このサブセットによってハミング距離が完全に決まります。 包含-除外ステップにより、より大きなスーパーセットからの寄与が正確に相殺され、一致の正確な構造のみが残るため、各ペアが真の一致パターンに基づいて正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

n, k = map(int, input().split())
codes = [input().strip() for _ in range(n)]

# precompute all subsets of positions
masks = []
for m in range(1 << 5):
    masks.append(m)

# for each mask, build mapping signature -> list size per node
# A[mask][i] = number of nodes matching i on mask
A = [[0] * n for _ in range(32)]

# build hash maps per mask
for mask in range(32):
    mp = defaultdict(list)
    for i, code in enumerate(codes):
        sig = []
        for pos in range(5):
            if mask & (1 << pos):
                sig.append(code[pos])
        mp[tuple(sig)].append(i)
    for sig, idxs in mp.items():
        for i in idxs:
            A[mask][i] = len(idxs)

# exact match pattern counts E[mask][i]
E = [[0] * n for _ in range(32)]

# inclusion-exclusion over supersets
for mask in range(32):
    for i in range(n):
        val = 0
        sub = mask
        while True:
            comp = ((1 << 5) - 1) ^ sub
            T = comp | mask
            sign = (-1) ** (bin(T).count("1") - bin(mask).count("1"))
            val += sign * A[T][i]
            if sub == 0:
                break
            sub = (sub - 1) & mask
        E[mask][i] = val

# answer: sum over masks with exactly 5-k matches
ans = [0] * n
for mask in range(32):
    if bin(mask).count("1") == 5 - k:
        for i in range(n):
            ans[i] += E[mask][i]

print(*ans)
```この解決策は、すべてのコードを固定長文字列として読み取ることから始まります。 次に、位置のサブセットごとに度数表を作成します。 各テーブルでは、それらの位置で特定のノードに一致するコードの数を定数時間で取得できます。 

包含と除外のループは、重要な点です。 各サブセットについて、そのすべてのサブマスクを列挙し、事前に計算されたカウントを交互の符号と組み合わせます。 これにより、スーパーセットが複数回寄与することによって引き起こされる過剰カウントが除去されます。 

最後に、サイズが正確に一致するサブセットのみを集約します。$5-k$必要なハミング距離条件を直接エンコードする位置の一致。

このトレースは、明示的なペアのチェックではなく、純粋に位置一致構造を通じて隣接関係が正しく捕捉されていることを示しています。

 ## 特殊なケース

 郵便番号が一桁を除いてすべて同一である場合、および$k = 1$、すべてのノードは、正確にその位置で異なる他のすべてのノードに接続されます。 サブセット構築では、固定位置の署名によってノードがグループ化されるため、同じ 4 つの固定数字を共有するノードは自然に同じバケットに分類され、包含/排他によって正確な単一位置の差の要件が分離されます。 

いつ$k = 5$、一致する数字がないペアのみがカウントされます。 多くの中間サブセット バケットが大きい場合でも、最終的な集計ではサイズ 0 のサブセットのみが考慮されます。これは完全な不一致パターンに相当します。 逆変換ステップにより、最終的な合計に達する前に、偶発的な部分一致が確実にキャンセルされます。
