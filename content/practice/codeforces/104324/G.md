 ## 解決策
 ## 問題の理解

 元々は未知の順序で配置された整数のマルチセットが与えられています。 元の順序に関する唯一の構造上の手がかりは、隣接性や並べ替えに関するものではなく、インデックスに関連付けられたグローバルな算術プロパティに関するものです。各要素を取得し、配列 (1 から始まるインデックス) 内のその位置を追加すると、結果の数値は 1 より大きい公約数を共有します。 

同様に、いくつかの整数が存在します。$d > 1$すべての値が$a_i + i$で割り切れます$d$元の正しい順序で。 受け取る入力はシャッフルされた配列値のみであるため、タスクはそれらを位置に並べ替えることができるかどうかを決定することです。$1 \ldots n$この割り算条件が成立するようにし、成立する場合は、有効な順列を 1 つ出力します。 

主な問題は、制約がすべての位置にわたってグローバルであることです。 ペアをローカルで照合するのではなく、単一の隠れた約数が得られるように値を調整しようとしています。$d$シフトされたすべての値を同時に除算します。 

制約$n \le 10^5$順列に対する階乗検索または指数検索は除外されます。 平$O(n^2)$解決策は境界線にあるため、構造は問題を線形または線形演算に近いものに削減する必要があります。 値が上がるので、$10^9$また、密な周波数配列や、値から導出されるすべての候補約数に対する総当りの列挙に依存することもできません。 

すべての値が等しい場合、または配列がすでに「ほぼ有効」であるにもかかわらず、単一の配置が原因で失敗する場合、微妙なエッジ ケースが発生します。 たとえば、次の場合$a = [2, 2, 3]$、有効な順序が存在するかどうかに関係なく、貪欲に配置しようとすると簡単に失敗する可能性があります。 正しさは、大域除数の存在を実際に強制するものを理解することにかかっています。 

## アプローチ

 ブルートフォース解釈では、配列のすべての順列を試し、すべての値を計算します。$a_i + i$を指定し、GCD が 1 より大きいかどうかを確認します。これは定義上は正しいですが、すぐには不可能です。$n!$順列と各チェックのコスト$O(n)$、全体の複雑さは天文学的に大きくなります。$n = 10$。 

重要な洞察は、視点を反転することです。 値の順列について考える代わりに、隠れた約数によって引き起こされる構造を修正します。$d$。 そのような場合$d$存在する場合、すべての位置に対して$i$、私たちは持っている必要があります$a_i \equiv -i \pmod d$。 これは、各位置が、そこに配置できる値に対してモジュール式の制約を課すことを意味します。 

したがって、固定候補者については、$d$の場合、問題は合同条件下での位置と値の間の 2 部マッチングになります。 ただし、考えられるものをすべて列挙すると、$d$まだ高すぎる。 重要な観察は、$d$2 つの有効なシフト値間のすべての差を除算する必要があります。$$(a_i + i) - (a_j + j)$$有効な取り決めのために。 それは示唆します$d$構造化された一連の差異の約数です。 

より単純で強力な再定式化が現れます。順列を修正すると、その条件はすべてを述べたのと同じになります。$a_i + i$同じ剰余クラスのモジュロ内にあります$d$、 それで$d$すべてのペアごとの差を除算します。 したがって、任意の候補配置について、次の値は$d$は、選択したシフト値間のすべての差を除算する必要があり、その可能な大きさが強く制限されます。 

これは建設的な戦略につながります。つまり、有効な構成が存在する場合、インデックスを差し引いた後に単調構造に正規化できるという仮説を立てて、最小の要素を最小のインデックスに揃えようとします。 これにより、問題は、シーケンスが$a_i + i$は自明ではない gcd を持ちます。これは、すべての値が一貫した残基構造に一致することを保証することと同じです。 

最終的な解決策は、配列をソートして正規の割り当てをテストすることになります。これは、シフトされた値の公約数の存在を壊すことなく、有効な構成を値でソートした構成に変換できるためです。

 ## アルゴリズムのチュートリアル

 1. 配列を非降順でソートし、順列の候補を生成します。 

この選択は、シフトされた値の公約数の実現可能性を維持しながら、有効な構成を値の増加を考慮した順序に再配置できるという考えに基づいています。 
2. すべての値を計算する$b_i = a_i + i$このソートされた配置について。 

インデックス構造が修正されたため、この標準的なアライメントが必要な gcd 条件をすでに満たしているかどうかをテストしています。 
3. すべての gcd を計算します。$b_i$。 

gcd が 1 より大きい場合、この順列は有効であり、出力できます。 
4. gcd が 1 に等しい場合は、有効な順列が存在しないと結論付けます。 

その理由は、より大きな gcd を作成するような並べ替えは、ソートによってすでに構造変化が最小限に抑えられているという事実と矛盾するということです。$a_i + i$、したがって、隠れた約数が出現することはできません。 

### なぜ効果があるのか

 重要な不変条件は、有効な配置にはすべてのシフトされた値が必要であるということです。$a_i + i$あるものを法とする単一の算術剰余クラスに収まる$d > 1$。 いかなる置換も、これらのシフトされた値のマルチセットを置換するだけであり、公約数を生成する可能性がある差分のマルチセット構造は変更しません。 

ソートにより、このマルチセットのアライメントの標準的な代表が生成されます。 この最も構造化されたアライメントであっても、gcd が 1 に崩壊する場合、並べ替えによって自明でない公約数が生じることはありません。これは、置換によって、考えられるシフト和のセットにまだ暗黙的に含まれていなかった新しい公約数を作成できないためです。 したがって、ソートされた構成は実現可能性の証人として機能します。有効な gcd 構造を明らかにするか、不可能であることを証明します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    
    g = 0
    for i in range(n):
        g = gcd(g, a[i] + (i + 1))
    
    if g == 1:
        print("NO")
    else:
        print("YES")
        print(*a)

if __name__ == "__main__":
    solve()
```解決策は、配列をソートし、変換されたシーケンスの gcd を評価することに重点を置いています。$a_i + i$。 gcd の累積は 0 から始まり、最初の値で正しく初期化されます。 

実装の重要な詳細は、形成時に 1 から始まるインデックスの位置を使用することです。$a[i] + (i+1)$。 よくある間違いは、インデックス ベースを混合することです。これにより、直ちに正確さが失われます。 もう 1 つの微妙な点は、gcd をゼロで初期化することです。$\gcd(0, x) = x$これにより、最初の要素の特殊なケースが回避されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての要素が同一である場合です。 入力用`[k, k, k]`、並べ替えは何も変更せず、シフトされた値は次のようになります。`k+1, k+2, k+3`。 gcd は完全に次のものに依存します`k`そしてインデックスの算術パターン。 アルゴリズムは、特別なケースを使用せずにこれを正しく評価します。 

もう 1 つのケースは、配列が最小の場合です。`n = 2`。 値が 1 異なる場合、次のようになります。`[1, 2]`、シフトされた値は`[2, 4]`ソートされた順序で、gcd 2 と有効な答えが生成されます。 アルゴリズムはこれを分岐せずに自然に捉えます。 

3 番目のエッジ ケースは、配列が構造的には有望に見えても、単一の互換性のない値が原因で失敗する場合です。`[1, 2, 3]`。 ソート後、シフトされた値は次のようになります。`[2, 4, 6]`gcd は 2 なので、有効です。 これは、一見「タイトな」シーケンスでも条件を満たす可能性があり、その正しさは視覚的な直感ではなく gcd 計算に完全に依存していることを示しています。
