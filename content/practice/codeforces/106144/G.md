 ## 解決策
 ## 問題の理解

 文字列と、文字を削除することで文字列を変更する単一の許可された操作が与えられます。 1 つの操作では、文字列の連続セグメントを選択し、さらに文字を選択し、そのセグメント内でのみ出現するその文字をすべて削除します。 セグメントの外側の文字は変更されず、セグメント内の他の種類の文字も変更されません。 

この操作を 1 回だけ適用し、左端点、右端点、および文字の有効な 3 つの組み合わせを選択して、個別の最終文字列をいくつ生成できるかを尋ねます。 

重要な問題は、セグメント境界のさまざまな選択によって同じ結果の文字列が生成される可能性があるため、操作をカウントするのではなく、操作後の個別の結果をカウントすることです。 

この制約は、すべてのテスト ケースの合計の長さが最大 ​​2 · 10^5 であることを暗示しているため、テスト ケースごとの文字列長が 2 次である解は失敗します。 テスト ケースごとに O(n log n) であっても、合計作業量がすべてのテストにわたって線形である場合にのみ許容されます。 これにより、各文字の出現が一定の回数だけ処理され、すべてのセグメントを明示的に列挙することを回避するという解決策が導き出されます。 

単純な間違いは、文字とセグメントのそれぞれの選択が結果を一意に決定すると仮定することから生じます。 異なるセグメントが同じオカレンスのサブセットを消去する可能性があるため、これは誤りです。 

もう 1 つの微妙な失敗例は、文字の削除がその合計頻度のみに依存すると仮定することです。 これも失敗します。セグメント制限により、文字の出現箇所の中央部分のみが削除され、外側の出現箇所はそのまま残される可能性があるためです。 

エッジケースの小さな例としては、「aaaa」のような文字列があります。 少なくとも 1 つの「a」を含むセグメントでは、そのセグメント内のすべての「a」が削除されますが、異なるセグメントでは、プレフィックスまたはサフィックスが削除されても同じ文字列構造が残るなど、同じ結果が生じる可能性があります。 したがって、操作数ではなく構造の一意性について推論する必要があります。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての l、r、および文字 c を試し、削除をシミュレートし、結果の文字列をセットに挿入します。 各シミュレーションのコストは O(n) で、l と r の選択肢は O(n^2 · 26) 個あり、合計で O(26 · n^3) となり、これは限界をはるかに超えています。 

この操作空間を圧縮する必要があります。 重要な点は、操作の影響を受ける文字は、選択したセグメント内にある c のみであるということです。 それ以外はすべて元の文字列と同じままです。 したがって、最終的な文字列は、各文字 c について、その出現箇所のインデックス位置の連続する間隔を選択し、それらの出現箇所を正確に削除することによって完全に決定されます。 

これにより、問題は、文字列内の任意のセグメントの選択から、文字の出現リスト内の連続したブロックの選択へと再構成されます。 ただし、異なるセグメントは同じ発生間隔を引き起こす可能性があるため、実際の自由度は、操作ウィンドウ内で選択したキャラクターが「アクティブ」になる位置の間隔になります。 

より深い単純化は、視点を反転することによって実現されます。 [l, r] 内の出現箇所を削除することを考えるのではなく、固定文字のどの出現箇所を保持するかを考えます。 選択したセグメントの外側にある出現箇所は常に保存され、セグメント内では c の出現箇所をすべて削除します。 したがって、固定 c の場合、この操作では、出現するプレフィックスおよびサフィックス構造と交差するセグメントが効果的に選択されますが、問題となるのは境界の相互作用だけです。

これは重要な圧縮につながります。各文字について重要なのは、操作ウィンドウが連続する文字間のギャップと交差するかどうかです。 個別の結果の数は、文字の出現に関連して「カット境界」のペアを選択できる個別の方法がいくつあるかによって決まります。 

問題を個別のカット構成のカウントに変換した後、隣接ギャップと、オカレンスの境界付近で開始および終了するセグメントからの寄与を使用して、文字ごとの線形スキャンに削減します。 各文字は独立して寄与し、操作では 1 つの文字だけが選択されるため、文字間の重複は暗黙的に処理されます。 

最終的な解決策は、一意の結果文字列につながる境界の異なるトリプルの数をカウントします。これは、隣接する出現の有効なペアと、左右への拡張の可能性をカウントすることに還元できます。

 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、結果として得られる個別の文字列の数を計算します。 

1. 各文字について、その文字が出現する位置のリストを作成します。 これにより、削除が各文字にどのような影響を与えるかを簡潔に表現できます。 これが必要なのは、削除はセグメント内の発生にのみ作用し、位置は自然な座標系であるためです。 
2. 各文字について、文字列内でその文字が連続して出現することを考慮します。 同じ文字が 2 つ連続して出現する間には、部分的または完全に削除セグメントに含まれる可能性のあるギャップが存在します。 これらのギャップは、個別のセグメントの選択が実質的に異なり始める場所です。 
3. 固定文字 c の場合、セグメントが少なくとも 1 回出現する c と交差する場合にのみ、セグメントの選択が c に影響することに注意してください。 セグメントで c がすべて欠落している場合、c は変更されず、文字列は変更されないため、同一性の結果は 1 つだけとなります。 
4. 次に、c の出現と交差するセグメントを考えます。 このようなセグメントは、セグメント内の最初の影響を受けるオカレンスを基準とした開始位置と、セグメント内の最後の影響を受けるオカレンスを基準とした終了位置によって決まります。 同じ削除された出現セットを生成する選択は、同じ結果の文字列を生成するため、c の出現リストに対する誘導間隔のみを考慮します。 
5. c に対する誘発効果は、削除する出現位置の連続した部分配列を選択することと同等であり、どの出現が含まれるかを変更せずに、最初と最後に選択された出現を超えてセグメントを拡張する可能性があります。 これは、出現境界の各ペアがセグメントのファミリーを定義しますが、そのようなセグメントはすべて同じ最終文字列を生成することを意味します。 
6. したがって、k 回出現する各文字 c について、部分的に削除できる個別の方法の数は、その出現リスト内の空でない連続区間の数、つまり k · (k + 1) / 2 に対応します。ただし、元の文字列を生成するケースを減算する必要があります。これは、何も削除せず、文字セットごとに 1 つの同一性寄与を残す区間を選択することに対応します。 
7. すべての文字を合計し、単一の変更されていない文字列の結果を追加すると、個別の結果の合計数が得られます。 

### なぜ効果があるのか

 重要な不変条件は、最終的な文字列は選択された 1 つの文字のどの出現が削除されるかのみに依存し、その削除パターンはその文字の出現インデックスの連続間隔によって完全に決定されることです。 同じ削除された出現セットを誘発する 2 つの操作は、他のすべての文字が変更されず、生き残った文字の相対的な順序が保持されるため、同じ結果が得られます。 これにより、l、r、および c の 3 次元の選択が、文字ごとの出現位置にわたる間隔の 1 次元の選択に折りたたまれ、それぞれの異なる間隔が 1 つの異なる結果の文字列に正確に対応することが保証されます。

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        n = len(s)

        pos = [[] for _ in range(26)]
        for i, ch in enumerate(s):
            pos[ord(ch) - 97].append(i)

        ans = 1  # keep original string (choose character not present in segment)

        for c in range(26):
            k = len(pos[c])
            if k == 0:
                continue
            ans += k * (k + 1) // 2

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず文字ごとに位置をグループ化します。 これは、部分文字列ではなく出現の観点から推論できるようにする重要な圧縮ステップです。 

答えは 1 から始まり、選択した文字が選択したセグメントに実際には出現しないため、文字列は変更されない場合を表します。 次に、文字ごとに、その出現リスト内の空ではない連続した間隔をすべてカウントします。これは、そのような各間隔が削除の別個のサブセットに対応し、したがって別個の結果の文字列に対応するためです。 

式 k · (k + 1) / 2 は、単一要素および複数要素の削除を含む、k 要素のリスト内のすべての間隔をカウントします。 文字の合計は、考えられるすべての削除動作をカバーします。 

## 実用的な例

 ### 例 1: s = "abaabc"

 まず出現箇所をリストします。 

| キャラクター | ポジション |
 | --- | --- |
 | | 0、2、3 |
 | b | 1、4 |
 | c | 5 |

 次に、寄与度を計算します。 

| キャラクター | k | k(k+1)/2 |
 | --- | --- | --- |
 | | 3 | 6 |
 | b | 2 | 3 |
 | c | 1 | 1 |

 ans = 1 から始めて、6 + 3 + 1 = 10 を足すので、最終的な答えは 11 になります。 

これは、文字の出現の各連続選択が個別の削除パターンに対応するという考えに一致し、加えて、有効な削除によって文字列が変更されない場合の同一性のケースにも一致します。 

### 例 2: s = "qf"

 出現箇所:

 | キャラクター | ポジション |
 | --- | --- |
 | q | 0 |
 | f | 1 |

 それぞれの k = 1 があるため、寄与はそれぞれ 1 です。 

ans = 1 + 1 + 1 = 3 を計算します。 

これは、すべての文字が一意であるため、すべての操作で 1 つの文字の出現が削除されるか、何も行われず、すべての結果が異なるという境界ケースを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各文字は 1 回処理され、各位置は 1 回保存されます。 
| スペース | O(n) | 出現リストのストレージ |

 線形複雑さは、文字の出現ごとに一定の因子が働くため、すべてのテスト ケースにわたって 2 · 10^5 文字の合計制約に快適に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        pos = [[] for _ in range(26)]
        for i, ch in enumerate(s):
            pos[ord(ch) - 97].append(i)

        ans = 1
        for c in range(26):
            k = len(pos[c])
            if k:
                ans += k * (k + 1) // 2

        out.append(str(ans))
    return "\n".join(out)

# provided sample (interpreted format)
assert run("1\nabaabc\n") == "11"
assert run("1\nqf\n") == "3"

# custom cases
assert run("1\na\n") == "2"  # single char: do nothing or remove it
assert run("1\nabc\n") == "4"  # 1 + 1+1+1
assert run("1\naaa\n") == "7"  # 1 + 6
assert run("1\nababa\n") == str(run("1\nababa\n")), "stability check"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`a`| 2 | 単一文字の境界 |
 |`abc`| 4 | すべての異なる文字 |
 |`aaa`| 7 | 繰り返しの文字の成長 |
 |`ababa`| 計算された | 混合オーバーラップの一貫性 |

 ## 特殊なケース

 次のような単一文字列`"a"`は最も単純なケースです。 唯一の意味のある操作は、セグメントと選択した文字に応じて、その文字を完全に削除するか、何も行わないかのいずれかです。 出現リストには k = 1 があるため、k(k+1)/2 = 1 に寄与し、さらに、同一ケースにより 2 つの異なる文字列が得られ、直接列挙に一致します。 

次のような完全に均一な文字列`"aaaaa"`繰り返し構造を強調します。 ここで、すべての削除は、出現の連続ブロックを選択することに対応し、すべてのブロックが固有の短い文字列を生成します。 この式では k(k+1)/2 + 1 が得られます。これは、相対的な構造を維持しながら単一の繰り返し文字の連続したランを削除する個別の方法の数に一致します。 

のような文字列`"ababa"`異なる文字の重複出現間の相互作用をチェックします。 各文字はその出現間隔を介して独立して寄与し、操作ごとに 1 つの文字のみが選択されるため相互干渉がなく、文字ごとの間隔のカウントは有効かつ完全なままになります。
