 ## 解決策
 ## 問題の理解

 括弧の文字列が与えられます。 2 人のプレイヤーが交互にこの文字列の端から文字を削除します。 移動するたびに、プレイヤーは現在の文字列の左端または右端の文字を選択して削除します。 違いは、Monocarp は移動中に、削除された文字を 2 番目の文字列に追加するのに対し、Polycarp は単純にそれを破棄することです。 

2 番目の文字列は Monocarp によってのみ構築され、空で始まります。 この文字列が空ではない通常の括弧シーケンスになった場合は、Monocarp が即座に勝ちます。 これが起こる前に元の文字列からすべての文字が削除された場合、Polycarp が勝ちます。 

重要な問題は、Monocarp がすべてのブラケットの完全な解析を完了しようとしているわけではなく、正しいブラケット シーケンスをすでに形成するために収集したシーケンスの一部のプレフィックスが必要なだけであり、これはすべての手が終了する前に発生する可能性があることです。 Polycarp の役割は純粋に破壊的であり、Monocarp がそのような接頭語を形成するのを阻止しようとします。 

制約の合計サイズは小さく、テスト ケース全体の文字列長の合計は最大 6000 です。これにより、すべてのゲーム状態またはすべての可能な移動シーケンスにわたる指数関数的なシミュレーションが即座に除外されます。 テスト ケースごとの 3 次または 2 次の解は許容されますが、完全なゲーム ツリーの探索を伴うものは許容されません。 

微妙な点は、Monocarp は、収集した文字列のいずれかの接頭辞が正しい括弧シーケンスであるとすぐに勝ちますが、必ずしも収集した文字列全体が勝者である必要はないということです。 これにより、「バランスの取れたプレフィックス」を早期に形成することが本当の目的になります。 

## アプローチ

 ブルートフォースのアイデアでは、ゲームを完全なミニマックス プロセスとしてシミュレートします。 各状態は、s の現在の部分文字列、現在の文字列 t、および誰の順番によって決定されます。 各状態から、左を取るか右を取るかに分岐します。 Monocarp はさらに t を更新し、移動のたびに t の接頭辞が通常の括弧シーケンスを形成しているかどうかをチェックします。 

これはすぐに爆発します。 エンドポイントの選択だけを考慮した場合でも、ゲーム パスの数は n (およそ 2^n) で指数関数的に増加し、すべてのノードでブラケットの有効性をチェックすると事態はさらに悪化します。 最適なプレイの構造はこのツリーに隠されているため、総当たりは使用できません。 

重要な観察は、Polycarp の動きは t の構造にまったく依存していないということです。 彼は、Monocarp が後で選択できるものに影響を与えるためにキャラクターを削除するだけです。 Monocarp の唯一の望みは、Polycarp の削除に関係なく、正しい括弧シーケンスとなる t の接頭辞を取得できる状況を迅速に強制することです。 

これにより、問題は初期文字列の構造特性に帰着します。つまり、Polycarp がすべての機会を破壊する前に、Monocarp が 2 つの一致する括弧を正しい順序で取得できることを保証できるかどうかです。 重要な簡略化は、両端から分離できる括弧の「安全なペア」の存在のみが重要であり、ゲームは開始時に文字列がすでに「拘束されすぎているか」を確認することになるということです。 

既知の最後の特徴付けは非常に単純です。Monocarp が負けるのは、考えられるすべての最初の動きが強制的に収集された文字列が右括弧で始まる場合のみです。その場合、接頭辞は有効な RBS になり得ないからです。 それ以外の場合、Monocarp は十分に早い段階で開始ブラケットを選択することで、勝利の構成を強制できます。 

これにより、文字列の構造の線形チェックが行われます。つまり、Polycarp がすぐに防ぐことができない方法で、開始括弧を t の最初の文字として固定できる動きが存在するかどうかです。

 ## アルゴリズムのチュートリアル

ゲームは基本的に Monocarp が t の最初のキャラクターを選択することから始まります。 この最初の動きの後、ポリカルプは反応しますが、モノカルプがすでに取ったものを遡って変更することはできません。 したがって、決定的な問題は、Monocarp が最初に選んだキャラクターが開始ブラケットであることを保証できるかどうかです。 

Monocarp が最初の動きの結果を開始括弧内にできた場合、彼はすでに、後で完全な RBS に拡張できるという意味で有効な 1 文字の接頭辞 t を持っています。 その時点から、最適なプレイにより、完全な有効なシーケンスが表示されるまで延長を続けることができます。 

Monocarp が左か右の選択に関係なく、最初の動きで閉じ括弧を取ることを強制される場合、t は ')' で始まります。 ')' で始まる文字列には、通常のブラケット シーケンスである空でないプレフィックスを含めることはできません。これは、有効な RBS では、すべてのプレフィックス境界で、開始部分が終了部分より少なくとも 1 つ多い必要があるためです。 

したがって、最初の文字列のどちらかの端点に左括弧が含まれているかどうかを確認するだけで済みます。 少なくとも 1 つの端が '(' の場合、Monocarp はそれを選択し、t の開始開始を確保します。両方の端が ')' の場合、最初の動きは閉じ括弧を生成し、Monocarp は運命づけられます。 

Polycarp は内部構造のみを削除できますが、最初の動きの選択を防ぐことはできないため、ゲーム全体がこのエンドポイント チェックに帰着します。 

### なぜ効果があるのか

 不変条件は、Monocarp の勝利条件は、括弧シーケンスとして直ちに無効ではない接頭辞で t を開始できるかどうかのみに依存するということです。 有効なブラケット シーケンスは ')' で始めることはできないため、Monocarp の成功は、最初に収集された文字が '(' であることを確認することと同じです。

 Polycarp のその後の動きはこの最初の事実を変えることはできず、Monocarp は RBS である t の接頭語の存在のみを必要とするため、最初の文字 '(' があることは、最適なプレイの下で有効な完了戦略が存在することを保証します。両端が ')' の場合、考えられるすべての最初の動きが強制的に失敗し、後の戦略はそれを修復できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        if s[0] == '(' or s[-1] == '(':
            out.append("Monocarp")
        else:
            out.append("Polycarp")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、ゲーム全体をテスト ケースごとの定数チェックに削減することを反映しています。 各文字列が読み取られ、そのエンドポイントのみが検査されます。 Polycarp の削除は、どちらの端から最初の文字を選択する Monocarp の機能にも影響を与えないため、文字列の残りの構造は無関係です。 

決定は効率化のために出力リストに追加され、最後に一度出力されるため、繰り返しの I/O オーバーヘッドが回避されます。 

## 実用的な例

 インプットを考慮する`s = "(()())"`。 エンドポイントは両方とも '(' であるため、Monocarp はすぐに左括弧を選択できます。

 | ターン | s (現在) | モノカープピック | t | 結果チェック |
 | --- | --- | --- | --- | --- |
 | 1 | (()()) | '(' | ( | 有効なプレフィックスが存在します |

 これは、t の最初の文字が '(' になると、Monocarp は完全な有効なシーケンスを構築できることを示しています。

 ここで考えてみましょう`s = "))))"`。 

| ターン | s (現在) | モノカープピック | t | 結果チェック |
 | --- | --- | --- | --- | --- |
 | 1 | )))) | ')' | ) | 無効なプレフィックスはすぐに無効になります。 

ここで、考えられるすべての最初の動きは ')' を生成するため、Monocarp は t の有効な接頭辞を形成できません。 

これら 2 つのケースは、核となる二分法を示しています。エンドポイントにアクセス可能な '(' が存在するかどうかで、ゲーム全体が決まります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    res = []
    for _ in range(t):
        n = int(input())
        s = input().strip()
        if s[0] == '(' or s[-1] == '(':
            res.append("Monocarp")
        else:
            res.append("Polycarp")
    return "\n".join(res)

# provided samples (conceptually reconstructed format)
assert run("1\n4\n()\n") == "Monocarp"
assert run("1\n5\n)((()\n") == "Polycarp"

# custom cases
assert run("1\n3\n))(\n") == "Monocarp", "has opening at end"
assert run("1\n3\n)))\n") == "Polycarp", "all closing"
assert run("1\n6\n()()()\n") == "Monocarp", "mixed but ends '('"
assert run("1\n6\n))()))\n") == "Polycarp", "no usable start"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`))(`| 単果皮 | エンドポイント '(' は勝利の手を許可します |
 |`)))`| ポリカルプ | 端に開きブラケットはありません。 
|`()()()`| 単果皮 | 一般的なケースでは、エンドポイントのチェックは十分です。 
|`))()))`| ポリカルプ | 内部構造は無関係 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、唯一の開始ブラケットが中央にある場合です。 例えば、`s = "))()("`。 Monocarp は右端の文字 '(' を選択し、t の有効な開始を即座に確保します。アルゴリズムは最後の文字のみをチェックするため、これを正しく処理します。

 もう 1 つのエッジ ケースは、両端が ')' であるが、内部に多数の '(' がある場合です。`s = ")()()()"`。 文字列には左括弧が豊富にありますが、Polycarp は常に端点の削除のみを許可するため、Monocarp は最初にそれらを選択できません。 両方のエンドポイントが ')' であり、最初の移動で閉じ括弧からの開始が回避されるため、アルゴリズムは Polycarp を正しく出力します。 

最後のエッジケースは、次のような最小限の長さのシナリオです。`s = "()()"`。 ここでは両端は '(' と ')' ですが、少なくとも 1 つの端が '(' であるため、Monocarp が即座に勝ち、意図したロジックと一致します。
