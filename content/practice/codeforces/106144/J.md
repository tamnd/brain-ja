 ## 問題の理解

 正の整数が与えられます`n`10 進表現にはゼロが含まれません。 この数値から、一連の変換、つまり各演算で数値の最後の桁を前に移動する「循環シフト」を定義します。 この操作を繰り返すと`x`回は新しい数値を生成します。これを次のように表します。`n → x`。 数字は周期的に回転するため、`len(n)`操作すると元の数値に戻ります。 

各テスト ケースのタスクは、すべての正の整数を見つけることです。`x`この循環シフトを適用すると、`x`回は加算とまったく同じ値を生成します`x`元の数値に戻す、つまり`n → x = n + x`。 そのようなものをいくつ出力する必要があります`x`存在し、昇順にリストします。 

重要な制約は次のとおりです。`n < 10^9`, したがって、最大 9 桁で、最大 1000 個のテスト ケースがあります。 これは、どのソリューションでも合計数百万回程度の操作を安全に費やすことができることをすでに暗示していますが、すべての反復処理を伴うものはすべて、`x`まで`n`それは不可能ですので`n`それ自体は大きくなる可能性があります。 演算の構造は桁数において完全に周期的です。これは、解が桁の大きさではなく桁サイクルに依存する必要があることを示唆しています。`x`。 

微妙な点は、操作はゼロのない数値に対してのみ定義されていますが、入力によってそれが保証されているため、無効な回転を処理する必要がないということです。 もう一つの微妙な点は、`x`それ自体は桁数よりも大きくなる可能性がありますが、回転は毎回繰り返されます。`m`ステップ、それで`n → x`のみに依存する`x mod m`。 

注目に値するエッジケースは、桁数が少ないことです。 もし`n`は 1 桁なので、回転しても何も起こりません。`n → x = n`みんなのために`x`。 すると条件はこうなります`n = n + x`、これはどんなポジティブなことでも不可能です`x`したがって、答えは空でなければなりません。 この縮退を忘れた素朴なアプローチでは、誤ってカウントされてしまいます。`x = m`または同様の偶然の一致。 

もう 1 つのエッジケースは次のような場合です`n`のようなものです`111...1`。 回転しても数値はまったく変化しないため、再び等価性は次の時点でチェックされることになります。`n + x`定数に等しいため、正の値には当てはまりません`x`。 

## アプローチ

 ブルートフォースアプローチでは、それぞれの`x`、回転された数値と比較します。`n + x`。 主な難点は、`x`は原則として制限がないため、カットオフが必要になります。 以来`n → x`桁数に等しい周期を持つ周期的です`m`、任意の有効な`x`このサイクルに沿って一貫して行動する必要があります。 制限しても`x`のようなある範囲まで`1`に`10^6`の場合、加算側は際限なく増大し、対称性の期待はすぐに打ち破られるため、強引な方法では意味のある検索スペースの削減にはつながりません。 

重要な観察は、考えるのをやめるということです`x → n → x`の関数として`x`、代わりに等価性を桁ごとに解釈します。 させて`n`持っている`m`数字。 書き込み`n → x`数字を回転することと同じです`k = x mod m`。 したがって、左辺は次のもののみに依存します。`k`、フルではありません`x`。 右側には、`n + x`数値自体が変化します。つまり、等価性が維持できる唯一の方法は、次の構造が存在する場合です。`n + x`の固定回転に一致します`n`。 

これにより、数値という非常に強力な制約が強制されます。`n + x`とまったく同じ桁マルチセットを持たなければなりません`n`、回転しただけです。 追加以来`x`大きさが変化する場合、桁桁上げの混乱を避ける唯一の方法は、`x`これは、回転の境界を越えて数字がどのようにシフトするかに密接に関係しています。 実際、有効な各解は、追加するときの一貫したキャリー パターンに対応します。`x`に`n`回転をシミュレートします。 

重要な洞察は、等号を回転位置合わせ上の数字 DP として扱うことです。 それぞれの回転量を試してみる`k`（から`1`に`m`) が存在するかどうかを確認します。`x`回転するように`n`による`k`等しい`n + x`。 すべてを試すのではなく`x`、私たちは再構築します`x`回転したフォームとフォーム間の減算という制約を使用して、桁ごとに計算します。`n`無効な借用の不一致のない有効な正の整数を生成する必要があります。 

これにより、問題は各回転を 1 回チェックし、暗黙的な差が数値として一貫しているかどうかを検証するだけになります。

 ## アルゴリズムのチュートリアル

 私たちは書きます`n`文字列として`s`長さの`m`。 

1.回転量を固定する`k`から`1`に`m`。 構築する`t`、循環回転して得られる文字列`s`最後を移動することで`k`数字を前にします。 これは次の値を表します。`n → k`。 
2. 次に、整数が存在するかどうかを判断したいとします。`x`そのような`n + x = value(t)`。 これは以下と同等です`x = value(t) - n`, したがって、この差を 10 進数の算術で計算します。 引き算します`s`から`t`適切な借用処理を使用します。 
3. 右から左への減算の実行中に、無効な借用構成が発生していないことを確認します。`x`否定的または矛盾しています。 いずれかの桁で正しく減算できない場合、この回転は無効となり、破棄されます。 
4. 減算が成功したら候補番号を取得します`x`。 私たちもそれをチェックしています`x`は正であり、ゼロになる、または予期しない長さの制約があるなどの主要な問題はありません。 
5. 有効なものをすべて保存する`x`値を並べ替えてから出力します。 

これが機能する理由は、すべての有効な解が 1 つの回転に正確に対応する必要があるためです。`k`、 以来`n → x`のみに依存する`x mod m`。 回転が固定されると、方程式は純粋な算術恒等式になります。`t = n + x`、一意に決定されます`x`。 減算ステップは、この恒等式が 10 進数で矛盾なく成立するかどうかを単純に検証するだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def subtract(a: str, b: str):
    # returns a - b as string if valid and positive, else None
    n = len(a)
    i = n - 1
    j = n - 1
    carry = 0
    res = []

    while i >= 0:
        da = ord(a[i]) - 48
        db = ord(b[j]) - 48 if j >= 0 else 0

        da -= carry
        if da < db:
            da += 10
            carry = 1
        else:
            carry = 0

        val = da - db
        if val < 0:
            return None
        res.append(str(val))
        i -= 1
        j -= 1

    while j >= 0:
        db = ord(b[j]) - 48
        if db != 0:
            return None
        j -= 1

    # remove leading zeros
    res = ''.join(reversed(res)).lstrip('0')
    if res == "":
        return None
    return res

def rotate(s, k):
    return s[-k:] + s[:-k]

def solve():
    s = input().strip()
    m = len(s)
    ans = []

    for k in range(1, m + 1):
        t = rotate(s, k)
        x = subtract(t, s)
        if x is not None:
            ans.append(int(x))

    ans.sort()
    print(len(ans))
    if ans:
        print(*ans)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```実装の中核は減算ルーチンで、回転された数値から元の数値を引いた値が有効な正の整数になるように強制します。 回転はシフトごとに O(m) で実行され、減算も O(m) であるため、各候補回転のコストは O(m) です。 m は最大 9 であるため、これはテスト ケースごとに実質的に一定の時間になります。 

実装でよくある落とし穴は、減算は正しい方向で実行する必要があることを忘れていることです。つまり、計算する必要があります。`t - n`、 ない`n - t`前者のみが有効な正の値に対応するため、`x`。 もう 1 つの微妙な問題は、結果の先頭にゼロがあることです。 減算の結果がすべて 0 の場合、それは有効な正の整数ではありません。

 ## 特殊なケース

 次のような 1 桁の入力の場合`n = 7`、回転しても数値が変わることはありません。 アルゴリズムが試行する`k = 1`、取得します`t = "7"`、減算結果は`0`、正の値が必要なため破棄されます。`x`。 最終的な答えは空で、7 に正の数を加えてもそれを変更しないという制約と一致します。 

次のような繰り返しの数字の場合`n = 2222`、すべての回転で同じ文字列が生成されます。 各減算の試行ではゼロが得られるため、すべての候補が除外されます。 アルゴリズムは、これらのケースを誤って受け入れることを正しく回避します。 

次のような繰り返しのない数値の場合、`n = 1234`、異なる回転により異なる結果が得られます。`t`、減算では、桁の位置合わせによってきれいなボロー伝播が可能になる場合にのみ、有効な正の値が生成されます。 アルゴリズムは、減算中に一貫性のないボロー チェーンを拒否することでこれを直接捕捉し、真の算術一致のみが確実に生き残るようにします。
