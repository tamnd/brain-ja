 ## 解決策
 ## 問題の理解

 空から始まり、一連のエッジ挿入を通じて進化するグラフを維持しています。 挿入された各エッジには、赤または青の 2 つの色のいずれかが割り当てられますが、グラフの基礎となる接続性は色を無視します。 挿入のたびに、2 つの条件を同時に満たしながら削除できるエッジの数を計算する必要があります。 

まず、残りのグラフは接続性を正確に保持する必要があります。つまり、削除前に接続されていた頂点のペアは、削除後も接続されたままでなければなりません。 グラフの用語では、現在の接続コンポーネントを保持するために必要のないエッジのみを削除できます。 これは、接続に厳密に必要なのはスパニング フォレスト内のツリー エッジだけであるため、削除がサイクルに関連していることを直ちに示唆しています。 

次に、グローバル バランス制約があります。削除される赤いエッジの数は、削除される青いエッジの数と等しくなければなりません。 これにより 2 つのカラー クラスが結合され、ブリッジ以外のエッジを色ごとに個別にすべて削除することができなくなります。 

各クエリ後の出力は、両方の制約の下で削除できるエッジの最大数です。 

制約は最大 3·10^5 頂点と 3·10^5 クエリであるため、更新のたびに接続を再計算したり、スパニング フォレストを最初から再計算したりするアプローチは、直ちに遅すぎます。 クエリごとに DFS または DSU を使用してコンポーネントを再計算しても、O(nq) が発生しますが、これは実現不可能です。 接続性とサイクル構造を対数またはほぼ一定の償却時間で更新する増分構造が必要です。 

セルフループとマルチエッジから微妙なエッジケースが生まれます。 自己ループは接続性を向上させることは決してできないため、いつでも削除可能ですが、それでも色の不均衡の原因となります。 同様に、すでに接続されているコンポーネント間の複数のエッジは冗長ですが、赤と青の差の制約に影響します。 冗長なエッジをカウントせずにコンポーネントのみを追跡する単純なアプローチは失敗します。 

## アプローチ

 重要な問題は、グローバル接続を尊重しながら、単に冗長エッジをカウントするのではなく、色ごとに分割された冗長エッジをカウントしていることです。 

強引なアイデアは、各クエリの後に完全なグラフを維持し、色を無視して最大範囲フォレストを再計算することです。 固定グラフの場合、DSU または DFS を実行してスパニング フォレストを選択し、その外側にあるエッジの数を数えることができます。 これらのエッジは、接続性に関してはまさに削除可能なエッジです。 ただし、これは、削除で赤と青のカウントのバランスを取る必要があるという要件を無視しています。 

色を組み込むには、すべての冗長エッジを考慮し、赤色の削除の数が青色の削除の数と等しくなるように、削除するエッジのサブセットを選択する必要があります。 R を冗長な赤のエッジ、B を冗長な青のエッジとすれば、2・min(R, B) に寄与する最大 min(R, B) ペアと、それらのペアを超えて構造的に強制的に削除されたすべてのエッジを削除できます。 重要なのは、冗長性は純粋に接続性によって定義されるということです。エッジが到着したときにエンドポイントがすでに接続されている場合、エッジは冗長です。 

これは中心的な観察につながります。 DSU を使用してエッジを挿入順序で処理すると、エッジが表示されるたびに、それが 2 つの異なるコンポーネントを接続しているかどうかを確認できます。 「はい」の場合、それはスパニング フォレストの一部であるため、削除できません。 「いいえ」の場合、それは冗長であり、その色に応じて R または B のいずれかに寄与します。 接続構造自体は色に依存しません。 

したがって、問題を、DSU の下で時間の経過とともに 2 つの冗長エッジを維持し、各クエリの後に単純な算術式を使用して応答することに帰着します。

クエリごとの接続性の再計算はステップごとに O(n + q) であるため、ブルート フォースは失敗します。 DSU ベースの増分手法では、各エッジを償却逆アッカーマン時間で処理し、プロセス全体を線形にします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに接続を再計算する | O(q・n) | O(n) | 遅すぎる |
 | DSU の増分カウント | O((n+q) α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 頂点と 2 つのカウンター (冗長な赤いエッジ用と冗長な青いエッジ用に 1 つ) にわたって素の集合結合構造を維持します。 また、これまでに確認されたエッジの総数も維持します。 

1. 各頂点がそれ自身の親である DSU を初期化し、両方の冗長カウンターをゼロに設定します。 わかりやすくするために必要に応じて、グローバル エッジ カウンターも保持します。 
2. クエリごとに、エッジ (u、v) とその色を読み取ります。 
3. u と v が同じ DSU コンポーネントに属しているかどうかを確認します。 これは検索操作を使用して行われます。 DSU は、接続の現在のスパニング フォレストを表します。 
4. u と v が異なるコンポーネントにある場合、DSU 内でそれらをマージします。 このエッジは接続に必要であるため、接続を変更せずに削除することはできません。 
5. u と v がすでに同じコンポーネント内にある場合、このエッジは接続性に関して冗長です。 赤または青の色に対応する冗長カウンタをインクリメントします。 これは、このエッジが周期上にあるためです。 
6. エッジを処理した後、答えを計算します。 冗長なエッジはすべて削除の候補ですが、同じ数の赤と青のエッジを削除する必要があります。 R が冗長な赤色のエッジの数、B が冗長な青色のエッジの数である場合、各色の min(R, B) エッジをペアにして削除できます。 各ペアは 2 つの欠失に寄与するため、バランスのとれた欠失は 2・min(R, B) に寄与します。 残りのペアになっていない冗長エッジは、等価制約に違反するため使用できません。 
7. 値 2・min(R, B) を出力します。 

これが機能する理由は、接続制約の構造にあります。 DSU は現在のグラフのスパニング フォレストを維持するため、フォレスト内にないすべてのエッジは必然的にサイクルの一部になります。 サイクル エッジのサブセットを削除しても接続性は変わりません。すべての冗長エッジは、以前のフォレスト エッジによって拡張された現在のグラフ内の少なくとも 1 つのサイクル上にあります。 森林の端が削除されることはないため、接続構造は維持されます。 したがって、唯一の自由は冗長エッジの選択にあり、唯一のグローバルな制限は色間でカウントを一致させることです。 DSU により、エッジが常に必須と冗長に正しく分類されるため、カウントが安定し、順序に依存しなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            return False
        if self.r[ra] < self.r[rb]:
            ra, rb = rb, ra
        self.p[rb] = ra
        if self.r[ra] == self.r[rb]:
            self.r[ra] += 1
        return True

def solve():
    n, q = map(int, input().split())
    dsu = DSU(n + 1)

    red_redundant = 0
    blue_redundant = 0

    for _ in range(q):
        t, u, v = map(int, input().split())

        if not dsu.union(u, v):
            if t == 1:
                red_redundant += 1
            else:
                blue_redundant += 1

        ans = 2 * min(red_redundant, blue_redundant)
        print(ans)

if __name__ == "__main__":
    solve()
```DSU は、エッジが接続に寄与するかどうかを決定するためにのみ使用されます。 ユニオン操作は、エンドポイントがすでに接続されている場合に正確に False を返し、これにより冗長エッジが識別されます。 次に、それらを色ごとに分割します。 

よくある微妙な点は、サイクルを形成する正確なエッジを追跡する必要はなく、その数だけを追跡する必要があることです。 もう 1 つの微妙な点は、何もデクリメントしないことです。グラフが概念的に進化しても、エッジは決して削除されないため、DSU は時間が経っても有効なままです。

 3 つの頂点を持つ小さなランを考えてみましょう。 

入力：```

```コンポーネントと冗長数を追跡します。 

| ステップ | エッジ | タイプ | DSU マージ | 冗長な赤 | 冗長な青 | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1-2 | 赤 | マージ | 0 | 0 | 0 |
 | 2 | 1-2 | 青 | 同じコンプ | 0 | 1 | 0 |
 | 3 | 2-3 | 赤 | マージ | 0 | 1 | 0 |

 最後のステップの後、冗長な赤のエッジが 1 つと冗長な青のエッジが 1 つあるため、接続を維持しながら両方を削除して、2 つの削除を行うことができます。 

これは、サイクル エッジのみが寄与し、それらが色間でペアになっていることを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) α(n)) | 各クエリは、最大 1 つの DSU 結合/検索操作を実行します。 
| スペース | O(n) | DSU の親配列とランク配列 |

 ## 特殊なケース

 重要なエッジケースは自己ループです。 自己ループは接続を変更しないため、常に直ちに冗長として分類されます。 たとえば、入力`1 1 1`赤の冗長カウンタが 1 ずつ増加しますが、一致する青の冗長エッジが現れるまで、答えは 0 のままです。 find(1) が find(1) と等しいため、DSU はこれを正しく処理し、冗長ブランチをトリガーします。 

もう 1 つのケースは、既に接続されている頂点間でエッジが繰り返される場合です。 頂点 1 と 2 がチェーンを介して接続されている場合、追加のエッジ 1 ～ 2 は色に関係なく冗長です。 DSU は、union(1,2) が false を返すことを保証するため、そのようなエッジはすべて正しいカウンターに蓄積されます。 

最後の微妙なケースは、青のエッジの前に多くの赤の冗長エッジが現れるなど、初期の不均衡です。 式 2・min(R, B) により、両側が利用可能になるまで一致しないエッジはバランスの取れた削除セットに寄与できないため、削除が時期尚早にカウントされることがなくなります。
