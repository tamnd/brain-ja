 ## 解決策
 ## 問題の理解

 整数配列と対応するコスト配列が与えられます。 配列内の各位置について、一定のコストでその値を置き換えることができ、変更しない位置は元の値を保持します。 変更を実行した後、値が次の値より厳密に大きい位置として「ドロップ」を定義します。 目標は、最小限のコストですべてのドロップを排除することです。 

配列は最大 8000 要素まで大きくでき、最大 5000 個のテスト ケースを含めることができます。 すべてのテスト ケースの配列長の合計は 8000 に制限されているため、処理する要素の総数は控えめであり、配列長の 2 次複雑さのアルゴリズムを使用できます。 Each element and each cost can be up to$10^9$したがって、大きな数値を慎重に扱い、固定幅の整数を使用する言語での整数のオーバーフローを回避する必要があります。 

エッジケースは、配列がすでに減少していない場合に発生します。 その場合、費用はかかりません。 もう 1 つの微妙なケースは、1 つを除いてすべての要素を置き換えるのが最適な場合です。たとえば、配列が厳密に減少している場合です。 不注意で貪欲なアプローチで局所的なドロップだけを調べると、支払いが過剰になったり、グローバルな最小値を見つけられなかったりする可能性があります。 値が繰り返される配列も慎重に扱う必要があります。重複を保持する方が、値の削除を避けるために一部の値を置き換えるよりもコストがかからない可能性があるためです。 

## アプローチ

 ブルートフォースアプローチでは、置換する位置のすべての可能なサブセットを考慮し、コストを計算し、結果の配列が減少していないかどうかを確認します。 サブセットの数は$2^n$でさえ天文学的な大きさです。$n=20$, so brute force is entirely infeasible.

 より構造化されたアプローチでは、潜在的な値をソートまたは「圧縮」した後、問題を動的計画問題として再構成できることが認識されます。 各位置で重要なプロパティは、選択した最終値と、その時点までに有効な配列を実現するための最小コストだけです。 位置を左から右に繰り返す場合、現在の位置の各候補値について、現在の値以下である前の位置の候補値を考慮するだけで済みます。 This forms a standard DP pattern where$dp[i][v]$最初のものを作成するための最小コストを表します$i$要素は減少せず、値で終わる$v$。 

これを効率的に行うために、配列値を離散化します。 すべてを考慮するのではなく、$10^9$考えられる整数の場合、コストを増加させることなく、最適な置換を元の配列の値に減らすことができるため、元の配列に現れる値のみを考慮する必要があります。 これを使用して、DP を実装できます。$O(n^2)$以前のすべての状態の再スキャンを避けるために、プレフィックスを最小値に維持することで、テスト ケースごとにテストを実行します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | 離散化を使用した動的計画法 | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、配列を読み取ります。`a`そしてコスト配列`c`。 長さを記録する`n`。 
2. すべての一意の値を収集します。`a`そしてそれらを並べ替えます。 このソートされた値のリストは、`vals`は、任意の位置に割り当てることができるすべての最終値を表します。 
3. DP テーブルの初期化`dp`寸法付き`n x len(vals)`、 どこ`dp[i][j]`最初のものを作成するための最小コストを表します`i+1`要素は減少せず、`i`-番目の要素に等しい`vals[j]`。 
4. 最初の行を入力します。 ポジションについて`0`に設定するコスト`vals[j]`は`0`もし`vals[j]`等しい`a[0]`(変更なし)、それ以外の場合`c[0]`(交換させていただきます)。 
5. 残りの位置を繰り返します。`i = 1`に`n-1`。 各候補値について`vals[j]`位置で`i`、以前のすべての候補値の中から最小コストを見つけます。`vals[k]`どこ`vals[k] <= vals[j]`。 追加`c[i]`もし`vals[j] != a[i]`交換費用を考慮するため。 
6. プレフィックス最小配列を使用して、最小値を効率的に見つけます。`k`満足のいく価値観`vals[k] <= vals[j]`。 これにより、各候補について以前のすべての状態をスキャンする必要がなくなり、`O(n^2)`時間。 
7. すべての位置を処理した後、答えは DP テーブルの最後の行の最小値となり、配列全体を非減少にするための最小コストを表します。 

機能する理由: 各ステップで、DP は次の不変条件を維持します。`dp[i][j]`最初のものを作成するための最小コストです`i+1`で終わる非減少要素`vals[j]`。 すべての有効な以前の値を考慮し、置換コストを追加することで、最適な組み合わせを見逃すことなく、実行可能なすべての変換を探索します。 離散化により、管理可能な数の候補値のみを処理できるようになり、接頭辞の最小化により非減少制約を効率的に維持できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        c = list(map(int, input().split()))
        
        vals = sorted(set(a))
        m = len(vals)
        
        dp = [0] * m
        for j in range(m):
            dp[j] = 0 if vals[j] == a[0] else c[0]
        
        for i in range(1, n):
            new_dp = [0] * m
            prefix_min = [0] * m
            prefix_min[0] = dp[0]
            for j in range(1, m):
                prefix_min[j] = min(prefix_min[j-1], dp[j])
            
            for j in range(m):
                cost = 0 if vals[j] == a[i] else c[i]
                new_dp[j] = prefix_min[j] + cost
            dp = new_dp
        
        print(min(dp))

if __name__ == "__main__":
    solve()
```コードはまず配列値を離散化し、`vals`。 最初の行は、置換が必要かどうかに応じて初期化されます。 後続の位置ごとに、プレフィックス最小配列を構築して、置換コストを追加しながら非減少制約を効率的に強制します。 最終的な答えは、単に最後の位置で達成可能な最小コストです。
