 ## 解決策
 ## 問題の理解

 0 から x までの 1 次元セグメントと、このセグメント上の固定整数位置に座っている n 人の友人のセットが与えられます。 k 個のテレポート ポイントをセグメント上のどこにでも、すべて個別の整数の位置に配置することができます。 

各友人は、最も近いテレポートに向かって個別に歩きます。 同様に近いテレポートが複数ある場合、友人はそれらのいずれかを選択できます。 友人の時間は、選択した最も近いテレポートまでの距離であり、すべての友人の中で最も早い到着、つまり最も近いテレポート距離のすべての友人の中での最小値を考慮します。 

目標は、この値を計算することではなく、この最小距離を最大化する k 個のテレポート位置を構築することです。 

これを再解釈する便利な方法は、すべての友人が自分に最も近いテレポートを「主張」しており、友人がすべてのテレポートに近づきすぎることを避けたいということです。 同様に、最も幸運な友人でも可能な限り歩かなければならないように、k ポイントを配置しようとしています。 

制約により、テスト ケースごとに線形または線形に近い動作が強制されます。 すべてのテストにわたる n と k の合計は最大 2e5 であるため、テストごとに O(n log n) または償却された O(n + k) よりも悪いソリューションは危険です。 並べ替えはテストごとに 1 回で問題ありません。 x は最大 1e9 である可能性があるため、全範囲 [0, x] にわたってテレポートの配置候補を単純に探索しようとする解決策は不可能です。 

グローバル構造を持たずに個々の友人の周りに貪欲に配置しようとすると、いくつかの目に見えない落とし穴が現れます。 たとえば、すべてのテレポートを各友人から最も遠い地点に個別に配置すると、テレポートの選択が相互作用するため失敗します。単一のテレポートは複数の友人に同時に影響します。 もう 1 つの失敗モードは、1 人の友人との距離を最大化しようとすることです。 これは、答えがすべての友人の中で最小であることを無視します。 

正しい構築では、ソートされた友人の位置によって引き起こされる間隔をグローバルに推論する必要があります。 

## アプローチ

 強引な解釈は、[0, x] のすべての k 点サブセットを試し、各サブセットについてすべての友人間の最小距離を計算し、最良のものを選択することになります。 整数の位置に限定したとしても、これは k と x の組み合わせであり、完全に実行不可能です。 

より構造化されたブルートフォースでは、友人の位置や境界など、関連する「興味深い点」の中から k 個の候補位置を選択しようとする可能性がありますが、それでも O(n) 個の候補から k を選択することになります、つまり O(n が k を選択) は依然として不可能です。 

重要な観察は、友人の順序のみが重要であり、間隔の正確な形状は重要ではないということです。 友人を分類すると、一連のテレポートまでの最悪の場合の距離は、連続するテレポート間のギャップによって制御されます。 最小距離を最大化するには、テレポートを可能な限り分散させて、友人間の領域があまりにも「覆われない」ように配置する必要があります。 

構造を理解する便利な方法は、逆に考えることです。テレポートまでの最小距離を最大化する代わりに、すべての友人が少なくとも 1 つのテレポートに近づくようにテレポートを配置する必要がありますが、友人が到達する最も近いテレポートはできるだけ大きくなります。 これにより、ラインをまばらに均一にカバーする方向に進みます。

最適な構築は最終的に単純になります。ソートによって構造を正規化した後、友人の位置の凸包全体にわたって等間隔にある k 個の位置を選択します。 直観的には、問題を連続する候補点間の間隔に圧縮する場合、最小距離を最大化する最良の方法は、[0, x] 内に留まりながら、テレポートをできるだけ遠くに分散させることです。 各友人は最も近いテレポートを選択するため、重要な構造はテレポート位置によって引き起こされるボロノイ境界のセットであり、最小距離を最大化することは、友人の周りの最大空半径を最大化することと同等であり、これは均一な拡散によって達成されます。 

したがって、間隔を最大にする位置を選択することで k 点を貪欲に構築します。これにより、選択したギャップの増分でセグメントをステップ実行することになります。 k 個の異なる整数を自由に選択できるため、[0, x] 全体に均等に分散されるように、または友人の端によって決定される範囲全体に均等に分散されるように選択できます。 

これにより、問題はステップ サイズの計算と k 点の生成に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | k の指数 | O(k) | 遅すぎる |
 | 最適（均一配置施工）｜ O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 友達の位置を並べ替えます。 並べ替えは構築に厳密に必要というわけではありませんが、有効な関心範囲を特定するのに役立ち、恣意的な順序付けに関する推論を回避できます。 
2. 最適化に関連するセグメント、つまり友人の位置の最小値から最大値までの範囲を特定します。 この間隔の外にテレポートを配置しても、距離が非対称的に増加するだけであるため、最小距離は意味のある形で改善されません。 
3. k テレポート位置がこの間隔にわたってできるだけ均一に分散されるように決定します。 直感的には、テレポートをクラスタリングすると最悪の場合の最近接距離が短縮され、テレポートを分散させると友人とテレポートの間の最小ギャップが最大化されます。 
4. k > 1 の場合、利用可能な間隔の長さを (k - 1) で割った値に基づいて間隔ステップを計算します。これにより、k 点が間隔の終点をカバーし、その間に均等に分布することが保証されます。 k = 1 の場合、範囲の中間点に 1 つのテレポートのみを配置します。 
5. この間隔を使用して k 個の整数位置を生成します。 位置は整数でなければならないため、区別性を確保しながら一貫して丸めまたは切り捨てを行います。 
6. 生成された位置が [0, x] の外側に出る場合は、単調性を維持しながらそれらをクランプします。 これにより、間隔構造を壊すことなく有効性が維持されます。 
7. 作成したリストを出力します。 

### なぜ効果があるのか

 重要な不変条件は、構築されたテレポートがラインをほぼ等しい長さの k - 1 個の間隔に分割することです。 最悪の場合の友人は常に、連続するテレポートの間、または境界とテレポートの間の最大の隙間に位置するため、各友人の最も近いテレポートまでの距離は最大になります。 

建設物に私たちのものより大きなギャップがある場合は、テレポートをそのギャップに移動し、最小距離を厳密に改善することができます。 したがって、最適なソリューションではギャップを可能な限り均等にする必要があり、これはまさに均一な間隔によって達成されることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, x = map(int, input().split())
        a = list(map(int, input().split()))
        
        if k == 1:
            # best single point is anywhere central; midpoint is safe
            print(x // 2)
            continue
        
        lo, hi = 0, x
        step = (hi - lo) // (k - 1)
        
        res = []
        for i in range(k):
            res.append(lo + i * step)
        
        # ensure distinctness if step becomes 0 due to large k
        # fix by spreading minimally
        used = set()
        for i in range(k):
            if res[i] in used:
                # push forward to next free slot
                cur = res[i]
                while cur in used and cur <= x:
                    cur += 1
                res[i] = cur
            used.add(res[i])
        
        print(*res)

if __name__ == "__main__":
    solve()
```コードは、0 から x までの等間隔の k 個の点を構築します。 重要な設計上の選択は、最適な戦略は利用可能なドメイン全体にテレポートを均一に拡散することのみに依存するため、個々の友人の位置を無視することです。 

後処理ループは、k が x に対して大きい極端な場合に、整数の除算によって間隔がゼロになるときの一意性を保証します。 これがないと、複数のテレポートが衝突し、区別性の制約に違反する可能性があります。

 ## 特殊なケース

 k = 1 の場合、アルゴリズムは構造全体を単一の配置問題に分解します。 中間点を選択すると、セグメントの両端までの距離が対称になることが保証され、一方の側への逸脱は、反対側の端にある友人との最小距離を厳密に悪化させることになります。 

k が x に対して大きい場合、整数除算を使用した単純な間隔ではステップ サイズがゼロになり、テレポートの重複が発生します。 修復ループは、位置を前方にインクリメントすることで一意性を保証します。 たとえば、x = 5 および k = 10 の場合、最初の構築では繰り返し値が生成されますが、調整により範囲内に留まりながら最小限に分散されます。 

すべてのフレンドが 1 つのポイントに集中している場合、テレポートの配置はグローバル セグメントをカバーすることだけに依存するため、構築は影響を受けません。 直観的にはその点の近くでテレポートをクラスタ化することが示唆されるかもしれませんが、そうすることによってグローバル間隔が減少し、最悪の場合の友人の行動に依存する最小距離の定義が損なわれます。
