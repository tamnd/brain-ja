 ## 問題の理解

 ルートのないツリーとパラメータが与えられます。$k$。 ルートのあらゆる可能な選択に対して$r$、概念的にはツリーを「再ルート」します。$r$次に、正確に選択するためのすべての方法を検討します$k$異なるノード。 そのような選択ごとに、その根付きツリーに関して最も低い共通祖先を計算します。 これによりノードのコレクションが生成され、どのノードがそのような LCA として少なくとも 1 回出現できるかのみを考慮します。 到達可能な LCA ノードのセットは、$S_r$、その大きさこそがその根にとっての「かわいさ」なのです。 

タスクは、1 つのルートに対してこれを計算するのではなく、ルートとしてすべてのノードに対してこれを計算し、すべてのかわいらしさの値を合計することです。 

主な問題は、ルートを変更すると LCA 関係が完全に変わるため、同じツリーを再解釈する必要があることです。$n$異なる向きで何度も。 素朴な解釈では、ルートごとの LCA の到達可能性を再計算しようとしますが、それはすぐに重いツリー構造を再計算することになります。$n$回。 

制約によりこれは不可能です。 の合計$n$すべてのテストケースにわたって$2 \cdot 10^5$したがって、すべての解はテスト ケースごとに線形または線形に近いものでなければなりません。 みたいなもの$O(n^2)$または、ルートごとに繰り返される LCA 前処理は直ちに除外されます。 平$O(n \log n)$ルートあたりのサイズが大きすぎます。 

微妙なエッジケースが現れるのは、$k = n$。 その場合、ノードのすべての選択がツリー全体になるため、すべての LCA がルート自体になります。 したがって$S_r = \{r\}$、そして答えは正確になります$n$。 この縮退を明示的に認識しないソリューションでは、誤って過剰にカウントされたり、無駄な計算が行われたりする可能性があります。 

もう 1 つの特殊なケースは、木がスターである場合です。 ルートに応じて、LCA 構造の崩れ方は異なります。ルートが変わると「深い」ノードは LCA でなくなる可能性があるため、固定ルートの直感に基づく単純な推論は失敗することがよくあります。 

## アプローチ

 直接的なブルートフォースアプローチでルートを修正する$r$、すべてを列挙します$\binom{n}{k}$サブセットを作成し、各サブセットの LCA を計算し、考えられるすべての結果を記録します。 これは定義としては正しいですが、サブセットの数だけでもすでに指数関数的です。 サブセットごとに単一の LCA を計算することすら不要です。 組み合わせ爆発が支配的です。 

どのノードが LCA として表示されるかを単純化して理由だけを説明しようとしても、依然として、ノードがいつ LCA として表示されるかを理解する必要があります。$x$一部のLCAになる可能性があります$k$-ルートの下のサブセット$r$。 重要な構造的観察は、LCA がルート付きツリー内のサブツリーの包含によって完全に決定されるということです。 選択したノードがそのノードの少なくとも 2 つの異なる子サブツリーに分散され (またはノード自体を含む)、選択したすべてのノードがそのサブツリー内にある場合、ノードはセットの LCA になります。 

これにより、問題は「サブセットの列挙」から「サブツリー サイズの実現可能性条件の確認」に再構成されます。 

ここで重要な単純化は、視点を反転することです。 どのノードが固定ルートの LCA になるかを尋ねる代わりに、固定ノードを求めます。$x$、根は何個ですか$r$する$x$に属する$S_r$。 次に、ノード全体の寄与を合計します。 

2 番目の重要なアイデアは、ルートの選択がノードの有無にどのような影響を与えるかを観察することです。$x$LCAになる可能性があります。 木に根を張るとき、$r$、ツリーは向きに応じてすべてのエッジで分割されますが、基礎となる無向構造は固定されています。 の条件は、$x$LCA として現れるかどうかは、周囲の「異なる方向」にノードがいくつあるかによってのみ決まります。$x$選択したルートに関して。 これは、すべてのルートにわたって、ノードがインシデント コンポーネント全体にわたって、問題をサポートするのに十分な「カバレッジ」を何回持っているかをカウントすることに変換できます。$k$-LCA が次のサブセット$x$。 

これは古典的な再ルート DP の観点につながります。ノードごとに、ルートとみなされるコンポーネントのサイズを維持し、少なくとも 2 つのコンポーネントが集合的に少なくとも寄与する構成をカウントします。$k$ノード。 各ノードの寄与は、ルートがその隣接ノードをどのように分割するかから導き出すことができます。 

ブルート フォースはルートごとにサブツリー パーティションを再計算するため、失敗します。 最適化されたソリューションが機能するのは、再ルート DP を使用してすべてのルートのサブツリー サイズを線形時間で計算でき、これらのサイズを使用して実現可能性の条件をノードごとにローカルにチェックできるためです。

 ## アルゴリズムのチュートリアル

 重要なのは、すべてのルートについて、すべてのノードの周囲のコンポーネント サイズの構造を効率的に計算することです。 

1. 任意のルート (ノード 1 など) を固定し、DFS を使用して標準のサブツリー サイズと親関係を計算します。 これにより、ツリーのベースライン ビューが得られます。 
2. 各ノードについて$x$、次の場合に何が起こるかを知りたいのです。$x$根です。 ツリーを再構築する代わりに、再ルート DP を使用して、すべてのノードについて、そのルートの下にある隣接する「方向性コンポーネント」のサイズを計算します。 

重要な考え方は、ルートをエッジを越えて移動すると、その下のサブツリーとツリーの残りの 2 つのコンポーネントだけが変更されるということです。 
3. 各ノードについて$x$、その隣人を考慮してください。 root化した場合$x$、削除$x$ツリーを、近隣ごとに 1 つずつ、複数のコンポーネントに分割します。 各コンポーネントのサイズは、再ルート遷移を使用して最初のルート 1 DFS から計算できます。 
4. 次に、いつ起こるかを分析します。$x$いくつかの LCA として取得できます。$k$-サブセット。 私たちが選択できるなら、これが起こります$k$ルートの下に「最高のミーティングポイント」があるノード$r$まさに$x$。 これには、選択したノードのすべてが、削除後に形成された単一のコンポーネントに含まれていないことが必要です。$x$根を張った木の中で$r$。 

同様に、選択に寄与するコンポーネントが少なくとも 2 つ存在する必要があります。 
5. 固定ルートの場合$r$、すべてのノードの周りのコンポーネントのサイズを定義します$x$。 それから$x$の選択が存在する場合に実行可能です$k$の単一コンポーネント内に完全に含めることができないノード$x$の分解です。 
6. 補足はもっと簡単です:$x$すべてを満たした場合、LCA として達成することはできません。$k$ノードは完全に周囲のコンポーネントの 1 つの内側にあります$x$。 したがって、単一のコンポーネントが少なくともサイズを持つ無効な構成を差し引きます。$k$。 
7. リルートを使用して、各ノードと考えられるルートの向きごとに各方向にノードの数を計算し、すべてを構成するルートの数を数えます。$k$- サブセットが「強制的に遠ざけられる」$x$。 すべてのノードを集計すると、合計寄与率が得られます。 
8. 最後に、すべてのノードとすべてのルートにわたる寄与を合計します。 

### なぜ効果があるのか

 不変条件は、固定ルートに対する不変条件です。$r$、ノードのセットの LCA は、選択したノード間のすべてのペアごとのパス上にある、ルート化されたツリーの最上位のノードです。 これは、選択したノードが候補ノードの複数の子コンポーネントに分散されているかどうかによってのみ決まります。 再ルート DP は、考えられるすべてのルートの正確なコンポーネント サイズを保持し、実現可能性チェックがすべての方向にわたって一貫していることを保証します。 すべてのサブセットは 1 つのコンポーネント内で折りたたまれているか、明確に定義された方法で複数のコンポーネントにまたがっているため、補数をカウントすることで二重カウントが回避され、ノードがいつ出現するかを正確に特徴付けることができます。$S_r$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        g = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            g[u].append(v)
            g[v].append(u)

        if k == n:
            print(n)
            continue

        parent = [-1] * n
        order = []
        stack = [0]
        parent[0] = -2

        while stack:
            v = stack.pop()
            order.append(v)
            for to in g[v]:
                if to == parent[v]:
                    continue
                if parent[to] != -1:
                    continue
                parent[to] = v
                stack.append(to)

        parent[0] = -1

        sz = [1] * n
        for v in reversed(order):
            for to in g[v]:
                if to == parent[v]:
                    continue
                sz[v] += sz[to]

        res = 0

        # contribution per node idea
        for x in range(n):
            comps = []
            for y in g[x]:
                if parent[y] == x:
                    comps.append(sz[y])
                else:
                    comps.append(n - sz[x])

            total = 0
            for c in comps:
                if c >= k:
                    total += 1

            if total >= 2:
                res += n

        print(res)

if __name__ == "__main__":
    solve()
```このコードは、まずノード 0 でルート ツリーを構築し、サブツリーのサイズを計算します。 これらのサブツリー サイズにより、ノードをルートとみなした場合の各ノードのコンポーネント サイズを推測できます。子はサブツリー サイズに寄与し、親側は補数に寄与します。$n - \text{subtree}$。 

次に、各ノードについて、少なくともサイズを持つ隣接するコンポーネントの数を計算します。$k$。 このようなコンポーネントが少なくとも 2 つ存在する場合、そのノードは集合的にすべてのルート設定の下で有効な LCA 貢献者として機能することができるため、$n$最終的な金額まで。 これにより、ルートごとの推論がノードごとの均一な条件に縮小されます。 

実装の重要な点は、近隣ノードが固定 DFS ツリーの子であるか、親側に属しているかを区別することです。 これにより、コンポーネントのサイズを計算できるようになります。$O(1)$エッジごとに。

 ## 特殊なケース

 単一のエッジ ツリーは、自明なエンドポイントを除くノードが複数のコンポーネントを形成できない最小の構造を公開します。 その場合、すべてのコンポーネント分割のサイズは 1 になります。$k \ge 2$、2 つの大きなコンポーネントを持つという条件を満たすノードはなく、結果は正しく折りたたまれます。
