 ## 解決策
 ## 問題の理解

 整数の配列で 2 人用のゲームをシミュレートするように求められますが、各整数の頻度のみがわかる圧縮表現を使用します。 アリスとボブは交代で、アリスは常に 1 つの要素を選択して個人配列に追加し、ボブは最大で 1 つの要素を削除します。`k`残りの配列からの要素。 目標は、両方が最適に再生されるという仮定の下で、収集された配列の MEX であるアリスの最終スコアを計算することです。アリスは MEX を最大化しようとし、ボブは MEX を最小化しようとします。 

入力により得られるのは、`m`、存在する最大の要素、および`f_0`を通して`f_m`、各数値のカウントを表します。 テスト ケースごとに、アリスが達成できる最適な MEX である単一の整数を出力する必要があります。 

制約により、いくつかの単純化が明らかになります。 最大`m`は 50 で非常に小さく、すべての合計は`m`テスト ケース全体の数は 1000 で制限されます。`O(m)`または`O(m log m)`テストケースごとのアルゴリズムは許容可能です。 カウント`f_i`は 10^9 まで大きくなる可能性があるため、個々の要素をシミュレートすることはできません。 代わりに、周波数と「ターン」を総合的に判断する必要があります。 

考慮すべきエッジケースには、ボブが小さな数値のコピーをすべてすぐに削除できる状況や、アリスが要素を選択することさえできない状況が含まれます。`0`。 たとえば、配列に次のものが含まれている場合、`[0:1, 1:0, 2:10]`そして`k=1`、ボブがただちに唯一の を削除するため、アリスは MEX 1 を通過できません。`0`アリスが最初にそれを選ばなかったら。 同様に、`k`が非常に大きいため、ボブはほとんどすべての要素を削除でき、アリスの MEX が大幅に制限される可能性があります。 

## アプローチ

 素朴なアプローチは、すべてのターンを正確にシミュレートすることです。アリスが要素を選択し、ボブが最大で要素を削除します。`k`要素を追加し、配列が空になるまで繰り返します。 これには、各要素を個別にシミュレートする必要があります。 カウントは最大 10^9 になる可能性があるため、このアプローチには最大 10 億回の操作が必要となり、完全に実行不可能です。 

最適なアプローチを実現するための重要な洞察は、「アリスが整数ごとに何回フルターンできるか」という観点からゲームを検討することです。 アリスは常に 1 つの要素を取り、ボブは最大で 1 つの要素を削除できるため、`k`、ボブの削除を集計できます。 特定の値について`x`、要素の合計数 ≤ の場合`x`アリスが確保できるものには、以下を含めるだけで十分です`x`ボブがそれらをすべて削除する前に、彼女の配列で MEX を過去に増やすことができます`x`。 そうでない場合、ボブは彼女を含めることをブロックします。`x`、MEXはそこで止まります。 

形式化するには、カウントのプレフィックス合計を考慮します。 させて`prefix[i]`の要素の総数になります。`0`に`i`。 アリスが確保できるのは`ceil(prefix[i]/(k+1))`Bob が最適に削除した場合、これらの要素のコピーが作成されます。 から反復します`0`上向きに、アリスが何枚のコピーを保証できるかをシミュレートします。 少なくとも 1 部のコピーを保証できない場合`i`、MEX はまさに`i`。 これにより、要素ごとのシミュレーションが回避され、完全にカウントで動作します。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`m`、`k`、およびカウントの配列`f_0`を通して`f_m`。 これらのカウントは、圧縮された配列を表します。 
2. 変数を初期化する`mex`0に、そして`remaining`0にします。`remaining`は、ボブの除去を考慮して、アリスが現在の整数のうち何個のピックを保証できるかを追跡します。 
3. 整数を反復処理する`i`から`0`に`m`。 追加`f_i`に`remaining`。 これは、アリスが要求できるプールに利用可能なコピーを追加することをシミュレートします。 
4. ボブの除去後にアリスが確保できるコピーの数を計算します。 各ラウンドで、ボブは最大で削除できます`k`要素を選択し、アリスは 1 を選択します。つまり、各グループに対して、`k+1`要素を使用すると、アリスは 1 を確保できます。数学的には、`taken = remaining // (k+1)`。 
5. もし`taken == 0`, アリスはこの整数を確保できないため、ループを停止します。 現在`mex`値は最終的な MEX です。 
6. それ以外の場合はインクリメントします`mex`そして更新します`remaining = remaining - taken*(k+1)`。 これは、要求された要素を削除し、次の整数に進むことを表します。 
7. ループの後、計算された結果を出力します。`mex`。 

これが機能するのは、アリスが各整数の少なくとも 1 つのコピーを昇順で確実に確保しているためです。これはまさに MEX を前進させるためにアリスが必要とするものです。 ボブは、より高い要素で除去能力を無駄にせずに、より早い要素をブロックすることはできません。`k+1`最適なプレーを正確にシミュレートします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    m, k = map(int, input().split())
    f = list(map(int, input().split()))
    
    mex = 0
    remaining = 0
    
    for count in f:
        remaining += count
        taken = remaining // (k + 1)
        if taken == 0:
            break
        mex += 1
        remaining -= taken * (k + 1)
    
    print(mex)
```コードはアルゴリズムを反映しています。`remaining`以前の反復からの残りを含むカウントを累積します。 で割る`k+1`アリスが 1 つを選択し、ボブが最大で削除することをシミュレートします。`k`最適に。 アリスが現在の整数のコピーを確保できない場合は、停止します。 更新します`remaining`確保された各整数の後に、剰余を繰り越すことができます。 エッジケースなど`k`非常に大きいか、カウントが最小であるかは自然に処理されます。`taken`アリスが何も主張できない場合は、すぐに 0 になります。
