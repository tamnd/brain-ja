 ## 解決策
 ## 問題の理解

 組み合わせプロパティを満たす、制限された要素を持つ特定の配列を数えるように求められます。 具体的には、次の長さのすべての配列を考慮します。`n`各要素が間にある場所`0`そして`k`。 配列から開始して、長さが 2 以上の連続する部分配列を繰り返し選択して減算できる場合、その配列は良好であると呼ばれます。`1`その部分配列の各要素から配列がすべて 0 になるまで。 私たちの目標は、与えられた素数を法として、いくつの配列が適切であるかを計算することです。`p`。 

アレイが優れている理由を理解することは非常に重要です。 小さな例でルールを明確にします。 のために`n=3`そして`k=1`、配列`[0,1,1]`インデックスも選べるので良いですね`2..3`そして引きます`1`、到達`[0,0,0]`。 配列`[1,0,1]`両方の非ゼロ要素を一緒に削減するために少なくとも 2 つの長さの連続セグメントを選択できないため、これは適切ではありません。 

制約はアルゴリズムの選択に関する指針を与えます。 最大`n`は 3000 と次の合計です`n^2`すべてのテスト ケースにわたって 10^7 を超えません。 これにより、すべての単純な列挙が除外されます。`(k+1)^n`簡単にアクセスできる配列`3000^3000`。 代わりに、大まかに実行する動的プログラミングのアプローチが必要です。`O(n*k)`または`O(n^2)`テストケースごとに。 弾性率`p`素数であることにより、組み合わせ論が機能する場合にモジュラー逆行列を使用できるようになります。 

不注意な実装でつまずく可能性のあるエッジケースとしては、次のようなものがあります。`k`に等しい`1`または`n`、多くのシーケンスの良し悪しは自明であり、配列ではすべての要素が最大値になります。 たとえば、`n=3`そして`k=3`、`[3,3,3]`それは良いですが、`[3,0,3]`これは、中央のゼロに影響を与えることなく外側の 3 つの両方を削減できる少なくとも 2 つの長さの連続したセグメントが存在しないためではありません。 

## アプローチ

 ブルート フォースのアプローチは簡単です。長さのすべての配列を生成します。`n`要素を含む`[0, k]`そしてリダクション操作をシミュレートします。 配列ごとに、減算を繰り返します。`1`すべての要素がゼロになるか、移動が不可能になるまで、ある部分配列から移動します。 それは正しいのですが、操作数は天文学的な数字になります。 のために`n=3000`そして`k=3000`、 がある`(k+1)^n ≈ 3001^3000`配列の場合、各チェックに 1 マイクロ秒しかかからないとしても、これは実行不可能です。 

重要な洞察は、組み合わせ論を使用して問題を再定式化することです。 リダクション操作では基本的に、少なくとも 2 つの長さの連続するセグメントを減らすことができます。 配列は、連続する要素間の差が 1 を超えず、長さが 2 以上のセグメントに含まれないように分離された要素がない場合に適しています。 これは、各要素が最大で存在する配列をカウントすることになります。`1`これは、隣接する差異によって制約される構成またはシーケンスをカウントすることに相当します。 

正式には、`dp[i][j]`長さの配列の数になります`i`で終わる`j`それは良いことです。 再発は次のとおりです。```
dp[i][j] = sum(dp[i-1][0..j])
```どこ`0 ≤ j ≤ k`。 これは、以前の配列が次で終わるため機能します。`x ≤ j`まで拡張できます`j`シーケンスが最終的にゼロになるという特性を維持しながら。 プレフィックス合計を使用して合計を効率的に計算し、単純な計算を減らすことができます。`O(k)`あたり`dp`への移行`O(1)`、を与える`O(n*k)`テストケースごとのソリューション。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 テスト ケースごとに、次の内容を読んでください。`n`、`k`、 そして`p`。 
2. DP 配列を初期化する`dp`サイズの`k+1`、 どこ`dp[j]`value で終わる現在の長さの良好なシーケンスの数を表します`j`。 
3. 基本ケース: 長さ 1 のシーケンスの場合、任意の値`0..k`それは些細なことですので、`dp[j] = 1`みんなのために`j`。 
4. ポジションごとに`i`2から`n`、新しいを計算します`dp_new`配列。 計算するには`dp_new[j]`、以前のすべてを合計します`dp[x]`どこ`0 ≤ x ≤ j`実行中のプレフィックス合計を使用して、すべてのプレフィックス合計の再計算を回避します。`j`。 
5.加工後長さ`i`、割り当てます`dp_new`に`dp`そして続けます。 
6.長さに達したら`n`、答えはすべての合計です`dp[j]`のために`0 ≤ j ≤ k`モジュロ`p`。 

なぜ機能するのか: DP の不変条件は次のとおりです。`dp[i][j]`適切な長さのシーケンスをすべてカウントします`i`で終わる`j`。 重要な観察は、各ステップがそれ以下の値で終わるシーケンスを拡張し、連続したデクリメント操作が機能する場合に限り、シーケンスをゼロに減らすことができるということです。 プレフィックス合計により、すべての有効な拡張子が効率的に蓄積されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k, p = map(int, input().split())
        dp = [1] * (k + 1)
        for _ in range(1, n):
            prefix = [0] * (k + 2)
            for j in range(k + 1):
                prefix[j + 1] = (prefix[j] + dp[j]) % p
            dp = [prefix[j + 1] for j in range(k + 1)]
        print(sum(dp) % p)

if __name__ == "__main__":
    solve()
```コードは高速 I/O を使用します。`sys.stdin.readline`複数のテストケースの場合。 長さの DP 配列を維持します`k+1`長さのプレフィックス合計配列を使用します`k+2`遷移を計算します。 モジュラー演算により、数値が指定された素数を超えないことが保証されます。`p`。 微妙な点は、off-by-one バグの一般的な原因である負のインデックスを避けるために、プレフィックス インデックスが 1 オフセットされていることです。
