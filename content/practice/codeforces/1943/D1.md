 ## 問題の理解

 長さの配列を見ています`n`、ここで、各位置は次の間の整数を保持できます。`0`そして`k`。 このような配列はすべて候補とみなされ、全体のユニバースは次のようになります。`(k+1)^n`。 

「良い」という概念は、引き算の演算によって定義されます。`1`連続したセグメントから。 任意のセグメントを選択できます`[l, r]`と`l < r`、そのセグメント内のすべての値を 1 ずつ減らし、これを何度でも繰り返します。 配列は、そこから始めて、これらのセグメントの減算のみを使用して、負になることなく最終的にすべての要素をゼロに減らすことができれば、良いものになります。 

これを再解釈する有効な方法は、逆に考えることです。 配列から開始してセグメントを減算する代わりに、セグメントを追加してゼロから配列を構築することを想像してください。 各操作で追加されるのは、`1`完全な間隔まで。 したがって、適切な配列とは、まさに間隔の増分を積み重ねることによって形成できる配列です。 

したがって、質問は次のようになります。`[0, k]`、間隔インジケーター関数の合計としていくつ表現できるか、各演算で追加される値`1`少なくとも 2 つの長さの間隔で。 

制約`n ≤ 400`複数のテストケースの合計`n^2`まで`2e5`すぐに示唆する`O(n^2)`または`O(n^2 log n)`テスト ケースごとのソリューションが意図されていますが、すべてのテストにわたる三次的なものは遅すぎます。 法は大きな素数であるため、逆数を使用したモジュラー組み合わせ論または DP が期待されます。 

微妙なエッジケースが要件です`l < r`、シングルポイント更新を禁止します。 これにより、標準的な差分配列問題と比較して構造が大幅に変わります。 単位セグメントを想定したり、これを無制限のプレフィックス増分として扱う単純なアプローチでは、特に次の場合に構成を誤ってカウントします。`n = 3`または`k = 1`、縮退が最も顕著に見られる箇所です。 

## アプローチ

 直接的な総当たりアプローチは、すべてを反復することになります。`(k+1)^n`配列を作成し、それぞれが許可された間隔演算に分解できるかどうかをテストします。 固定配列の場合、実現可能性をチェックするということは、それが区間加算の合計として表現できるかどうかを判断することを意味します。 これは、導出された差分構造が負でない間隔のカウントに分解できるかどうかをチェックするのと同等であり、それ自体は貪欲またはフローのような推論によって約 1 時間で解決できます。`O(n^2)`配列ごとに。 

これはすぐに爆発します。`(k+1)^n`指数関数的に成長し、`n = 20`、それはすでに不可能です。 ボトルネックは実現可能性のチェックではなく、すべての配列の列挙です。 

重要な構造的洞察は、この演算が配列に対して非常に具体的な線形基底、つまり間隔ごとに定義しているということです。`[l, r]`と`l < r`その範囲内のベクトルを提供します。 したがって、次の範囲で囲まれたこれらのベクトルの整数の組み合わせを数えています。`k`。 これにより、問題は、間隔基底ベクトルによって定義された制約された多面体内の整数点を数えることに変わります。 

より使いやすい視点は、配列から「差分構造」への移行です。 違いを定義しましょう`d[i] = a[i] - a[i-1]`。 各間隔の更新では、正確に 2 つの違いが変化します。`d[l]`そして減少します`d[r+1]`(範囲内の場合)。 これは、到達可能な配列の空間が、その差分シーケンスがエッジを通る値の流れとして表現できるすべての配列に対応することを意味します。`l → r+1`。 

これにより、問題は折れ線グラフ上で境界のあるフローをカウントすることに変わります。 各配列は、各位置で開始および終了する「フロー」の量と制約の構成に対応します。`0 ≤ a[i] ≤ k`は、これらのフローのプレフィックス合計制約になります。 

これは古典的な DP につながります。つまり、現在位置をカバーしているアクティブな間隔の数を維持しながら、左から右にスキャンします。 位置で`i`、値`a[i]`は、正確にカバーするアクティブな間隔の数です。`i`。 各間隔はある時点から始まります`l`そしていつか終わる`r ≥ l+1`。 それで、私たちが到着したとき、`i`、開始間隔の数を選択します。`i`、で終わるのはいくつありますか`i`。 

これにより、アクティブなカウントが決して超過しないように、開始と終了の有効なシーケンスをカウントするという問題が軽減されます。`k`。 

重要な簡素化は、正確な間隔のエンドポイントを追跡する必要はなく、開いている間隔の数だけを追跡する必要があることです。 新しいインターバルが発生するたびにアクティブなカウントが増加し、終了するたびにアクティブなカウントが減少します。 間隔の長さは少なくとも 2 でなければならないため、間隔は次から始まります。`i`で終了することはできません`i`, したがって、少なくとも 1 ステップの間アクティブになります。 

最終的には、位置と現在のアクティブ数に対する DP が決まり、トランジションは各ステップで開始および終了する間隔の数によって決まり、アクティブ数が常に選択した値と一致するように制約されます。`a[i]`。 

これにより、組み合わせの DP が得られます。`O(nk)`プレフィックス合計を使用して最適化できる遷移のある状態。

 ## アルゴリズムのチュートリアル

 この配列を一連の「アクティブな間隔」として解釈します。 それぞれのポジションで`i`、値`a[i]`カバーする間隔の数に等しい`i`。 

1. DP 状態を定義します`dp[i][x]`、位置を処理する方法の数を表します`1`を通して`i`まさにそのようなこと`x`インターバルは現在位置でアクティブです`i`。 

この状態が機能するのは、構築を延長するために必要な情報が現在進行中の間隔の数だけであるためです。 
2. 位置で`i`、状態にあるとします。`dp[i][x]`。 最終的には次のようになります。`a[i]`ポジションをカバーするアクティブなインターバル`i`。 そこで私たちは強制します`x = a[i]`ターゲット値と一致する遷移のみを許可することで間接的に行われます。 

重要な制約は、アクティブな間隔が次のとおりであることです。`i`の値と一致する必要があります`i`そうでない場合、構築された構造は配列に対応しません。 
3. 位置から`i`に`i+1`の数を決定します。`x`アクティブな間隔は継続します。 仮定する`t`インターバルは続く。 それから`x - t`間隔は次で終了します`i`。 

これは、位置でどの間隔が閉じるかを選択することに対応します`i`。 これらはアクティブなものの中から任意であるため、組み合わせを数えます。 
4. また、開始する新しい間隔の数も選択します。`i+1`。 その数字を`s`。 これらの間隔は次の時間でアクティブになります。`i+1`。 

新しいアクティブ数は次のようになります。`t + s`、これは次と等しくなければなりません`a[i+1]`。 
5. したがって、遷移は可能な限り反復することになります。`t`そのような`0 ≤ t ≤ x`、および設定`s = a[i+1] - t`。 必要です`s ≥ 0`そして、どの間隔が続き、どの間隔が始まるかの組み合わせの選択を考慮する必要があります。 
6. どれを選択するかは無数にあります`t`から間隔が続きます`x`アクティブなものは`C(x, t)`。 残りは決定的に決定されます。 
7. We precompute factorials and inverse factorials modulo`p`二項係数を迅速に計算します。 

からDPを充填した後、`i = 1`に`n-1`、答えは`dp[n][a[n]]`。 

### なぜ効果があるのか

 不変条件は、処理後の位置です。`i`、すべての構成は次のようにカウントされます`dp[i][x]`プレフィックスを正確に生成する有効な部分区間分解に対応します。`a[1..i]`、開いた間隔の数は次となります。`x`。 すべてのインターバルはカバレッジの連続ブロックに寄与するため、アクティブなインターバルごとにカウントすると、インターバル構築のすべての構造的制約が維持されます。 二項遷移は、どのアクティブな間隔が持続するかを選択するすべての方法を説明し、新しい開始は、次の値と一致する新しい間隔を導入するすべての方法を説明します。 に違反するため、無効な構造は表示されません。`a[i]`不一致のアクティブ カウントが必要になりますが、これは各遷移境界で除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = None

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    n, k, p = map(int, input().split())
    global MOD
    MOD = p

    a = [0] + list(map(int, input().split()))

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    invfact = [1] * (n + 1)
    invfact[n] = modinv(fact[n])
    for i in range(n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def C(n_, r_):
        if r_ < 0 or r_ > n_:
            return 0
        return fact[n_] * invfact[r_] % MOD * invfact[n_ - r_] % MOD

    dp = [0] * (n + 1)
    dp[a[1]] = 1

    for i in range(1, n):
        ndp = [0] * (n + 1)
        for x in range(n + 1):
            if dp[x] == 0:
                continue
            if x != a[i]:
                continue
            for t in range(x + 1):
                s = a[i + 1] - t
                if 0 <= s <= k:
                    ndp[s + t] = (ndp[s + t] + dp[x] * C(x, t)) % MOD
        dp = ndp

    print(dp[a[n]] % MOD)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()

階乗と逆階乗はテスト ケースごとに事前計算されます。`n`十分に小さいので`O(n^2)`前処理は全体的な制約の下では安全です。 二項係数は、どのアクティブな間隔が持続するかを選択する方法が何通りあるかを計算します。 

ネストされたループオーバー`x`そして`t`両方とも次によって制限されているため安全です`n`、すべてのテスト ケースの合計の複雑さは、グローバル`n^2`限界。

 ## 特殊なケース

 重大なエッジケースは、配列の中央にゼロが含まれる場合です。 例えば`a = [1, 0, 1]`。 素朴な解釈では、インターバルは位置を「スキップ」できないと想定するかもしれませんが、実際にはインターバルは連続したままでなければならないため、ゼロを指定すると、対象となるすべてのインターバルがその時点の直前で終了し、その時点の後に再開されます。 DP がこれを強制するのは、アクティブ カウントが位置 2 でゼロに低下し、すべてのインターバルを終了する以外に選択肢がないためです。 

もう一つのエッジケースは、`k = 1`。 ここでは、すべての位置が 1 つの間隔でカバーされるか、まったくカバーされないかのどちらかです。 これにより、システムは、位置を少なくとも 2 つの互いに素な長さの間隔に分割する方法を数えることになります。 DP は自然に、マッチングのような構造をカウントするものと、`l < r`制約によりシングルトンが誤って許可されてしまいます。 

最後に、いつ`n = 3`、システムは最小限であるため、無効な構造上の仮定がすべて可視化されます。 連続性を強制せずに開始と終了を独立して処理することによる過大なカウントは、この体制ではすぐに誤った結果を生成します。
