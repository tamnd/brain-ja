 ## 解決策
 ## 問題の理解

 2 つの整数で定義される数直線上の線分が与えられます。$\ell$そして$r$そして Peter はこのセグメントを 2 つの特定の方法で折りたたむことができます: 左から右へ (`LTR`) そして右から左へ (`RTL`）。 各折り畳みは、セグメントの端点と選択された点の合計が素数である場合にのみ可能です。 折りたたむと、セグメントは縮小します。ピーターは常に、自分に有利な折りたたみを最大化する極端な値、つまり最大値を選択します。$x$のために`LTR`そして最小の$x$のために`RTL`。 私たちのタスクは、セグメントを可能な限り最小の長さに短縮する個別の折り畳みシーケンスの数を決定することです。 

入力では複数のテスト ケースが提供され、それぞれに$\ell$そして$r$。 出力はフォールディングシーケンスのモジュロ数です。$998244353$各セグメントごとに。 

制約はアルゴリズムに微妙なヒントを提供します。 その間$\ell$そして$r$まで行くことができます$10^{12}$、 違い$r - \ell$せいぜい$10^5$。 これは、折り畳むことができる数値の実際のセグメントが狭い範囲にあることを意味するため、非常に重要です。 までのすべての数値を反復しようとする単純なアプローチ$10^{12}$実現不可能ですが、相対的なセグメントの長さに焦点を当てた戦略は管理可能です。 

エッジケースには非常に短いセグメントが含まれます。たとえば、$r - \ell = 1$。 このシナリオでは、一部の折り畳み操作がまったく不可能になる可能性があり、セグメントをこれ以上縮小できないため、答えは自明のことですが 1 になります。 もう 1 つの微妙なケースは、素数がセグメント内にまばらであり、フォールディングの機会が制限され、フォールディング シーケンスの数が減少する場合に発生します。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべてのシーケンスをシミュレートしようとします。`LTR`そして`RTL`操作。 折り畳みごとに、セグメント内のすべての候補点をチェックして、端点との合計が素数であるかどうかを確認します。 概念的には正しいですが、この方法は法外に遅いです。$r - \ell \le 10^5$、すべてのシーケンスをシミュレートすると、操作が指数関数的に増加します。 

重要な洞察は、実際の位置は相対的にのみ重要であるということです。$\ell$そして$r$。 以来$r - \ell$が小さい場合、ふるいを使用して最大の素数を事前計算できます。$2r$、またはより効率的に、間隔内で$[\ell, r]$との合計を考える$\ell$または$r$。 次に、セグメントを位置としてモデル化します。$0$に$n = r - \ell$そして、動的プログラミングまたは幅優先探索 (BFS) を実行して、可能な折り畳みを探索します。 各セグメントの状態はペアに対応します$(L, R)$現在のエンドポイントを表します。 メモ化または辞書を使用してシーケンスをカウントすると、折り畳みルールを適用しながら、各状態に到達する方法の数を伝播できます。 極端な選択肢は、`LTR`そして`RTL`決定論的な折りたたみを保証するため、異なる折りたたみ順序によって同じ最終的な最小長のセグメントが生成される場合にのみ、複数のシーケンスが発生します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(r-l)) | O(2^(r-l)) | 遅すぎる |
 | 相対位置における最適な DP/BFS | O((r-l)^2) | O((r-l)^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンピューティング$n = r - \ell$。 セグメントをマッピングする$[\ell, r]$に$[0, n]$。 これにより、距離を正確に保ちながら計算が簡素化されます。 
2. 以下のすべての素数を事前計算します。$2r$（または$2n$シフト後に十分）エラトステネスのふるいを使用します。 これにより、折り目候補点の定数時間素数チェックが可能になります。 
3. キューまたは DP テーブルを初期化して、現在のセグメントとそれらに到達する方法の数を保存します。 セグメントから開始$(0, n)$そしてカウント1。 
4. 処理するセグメントがある一方で、次のことを考慮してください。`LTR`そして`RTL`折り目:

 - のために`LTR`、最大のものを検索します$x$で$[1, n]$そのような$\ell + x$プライムです。 セグメントを折ります$[\frac{0+x}{2}, R]$。 
- のために`RTL`、最小のものを検索します$x$で$[0, n-1]$そのような$R + x$プライムです。 セグメントを折ります$[L, \frac{R+x}{2}]$。 
5. 生成された新しいセグメントごとに、そのセグメントに到達する方法の数を増やします。 新しいセグメントが訪問されている場合は、カウントの剰余を合計します。$998244353$。 
6. 新しい折り目でセグメントを縮小できなくなるまで続けます。 最小長のセグメントをすべて収集し、その数を合計します。 
7. 和の剰余を返します$998244353$最小間隔を生成する折り畳みシーケンスの数として。 

正確さは 2 つの不変式に依存します。 まず、常に最も有効な折り畳み点を選択することにより、他の折り畳みはそれより短くできないセグメントにつながるため、可能な限り最短の長さのセグメントを見逃すことはありません。 第 2 に、DP/BFS は、同じセグメントを生成するすべてのシーケンスがカウントされることを保証し、状態による二重カウントを回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def sieve(n):
    is_prime = [True]*(n+1)
    is_prime[0] = is_prime[1] = False
    for i in range(2,int(n**0.5)+1):
        if is_prime[i]:
            for j in range(i*i,n+1,i):
                is_prime[j] = False
    return is_prime

def solve_case(l, r):
    n = r - l
    primes = sieve(2*r + 1)
    
    dp = {}
    from collections import deque
    queue = deque()
    dp[(0, n)] = 1
    queue.append((0, n))
    min_len = n
    
    while queue:
        L, R = queue.popleft()
        ways = dp[(L,R)]
        # LTR
        for x in range(R, L, -1):
            if primes[l + x]:
                new_L = (L + x) // 2
                new_seg = (new_L, R)
                if new_seg not in dp:
                    queue.append(new_seg)
                dp[new_seg] = (dp.get(new_seg, 0) + ways) % MOD
                min_len = min(min_len, new_seg[1] - new_seg[0])
                break
        # RTL
        for x in range(L, R):
            if primes[r - (R - x)]:
                new_R = (R + x) // 2
                new_seg = (L, new_R)
                if new_seg not in dp:
                    queue.append(new_seg)
                dp[new_seg] = (dp.get(new_seg,0)+ways) % MOD
                min_len = min(min_len, new_seg[1]-new_seg[0])
                break
    
    result = 0
    for (L,R), cnt in dp.items():
        if R-L == min_len:
            result = (result + cnt) % MOD
    return result

t = int(input())
for _ in range(t):
    l,r = map(int,input().split())
    print(solve_case(l,r))
```sieve 関数は、以下の素数を事前計算します。$2r$素数チェックを高速化します。 BFS はセグメントの状態を調査し、問題の仕様に従って常に極端な折り畳み点を選択します。 の`dp`辞書は各セグメントに到達する方法の数を蓄積し、最小長のセグメントが最後に収集されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((r-l)^2) | O(r-l) 個のセグメント位置のそれぞれは、O(r-l) 個の新しいセグメントに折りたたまれます。 BFS explores all reachable states. |
 | スペース | O((r-l)^2) | ディクショナリには、到達可能な各セグメントと、そこに到達するための方法の数が保存されます。 |

 とすれば$r-l \le 10^5$、状態の数は管理可能であり、アルゴリズムは 1 秒の制限時間内に快適に収まります。
