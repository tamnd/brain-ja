 ## 解決策
 ## 問題の理解

 整数の単一配列が与えられており、それを非減少シーケンスに変換したいと考えています。 許可される唯一のツールは、選択ソートのバリアントのように動作する特別なソート ルーチンです。このルーチンは、固定位置をその後のすべての位置と繰り返し比較し、より小さい値が見つかるたびに入れ替えます。 このルーチンはセグメントの長さの 2 乗に比例して負荷がかかるため、長さのセグメントをソートする必要があります。$i$費用$i^2$。 

このルーチンを合計で最大 2 回呼び出すことができます。 各呼び出しは配列のプレフィックスまたはサフィックスのいずれかで操作する必要があり、毎回長さを選択できます。 1 回の呼び出しで最初の項目を並べ替えることができます$i$要素を呼び出し、最後の要素を並べ替えることができます。$i$要素を任意の順序で。 

タスクは、総コストを最小限に抑えながら、最終的な配列がソートされるように、このような操作を 2 つまで選択することです。 

制約$n \le 10^6$並べ替えをシミュレートしたり、すべての操作のペアを試行したりするアプローチは直ちに除外されます。 一枚でも$O(n^2)$スキャンは不可能です。 解決策は、配列内の構造に関する線形または線形に近い推論に依存する必要があります。 

重要な微妙な点は、この操作が任意のサブ配列を単独で行う完全なソートのように動作しないことです。 これにより、非常に特殊な「部分的に修正された」構造が作成されます。接頭辞操作の後、最初のセグメントのみがソートされることが保証されますが、2 番目の操作の実行可能性に影響を与える形で、もともと他の場所に属していた要素も含まれる可能性があります。 

エッジ ケースは、配列がすでにソートされている場合、先頭または末尾の 1 つの間違って配置されたブロックを除いてほぼソートされている場合、および両方向のインターリーブ修正が必要な場合に発生します。 「配列がソートされていない場合、常に 1 つのプレフィックス ソート + 1 つのサフィックス ソートで十分である」と想定する素朴なアプローチは、反転が境界を越えて分散するパターン、たとえば次のような配列では失敗します。$[2,1,3,4,5]$、接尾辞の修正だけでは役に立たず、接頭辞の修正だけでは過剰に修正されます。 

## アプローチ

 コストの制限を無視すれば、考えられるすべての操作の選択肢を試すことができます。 それはプレフィックスの長さを選択することを意味します$i$(またはスキップして)、接尾辞の長さを選択します$j$(またはスキップして)、それらを両方の順序で適用し、結果の配列をシミュレートします。 各シミュレーションの費用$O(n)$、そして、あります$O(n^2)$ペア、与える$O(n^3)$全体的な複雑さ。 これは実現可能な限界をはるかに超えています。 

より賢く、一度に 1 つのエンドポイントを修正しようとしても、主な困難は残ります。1 回の操作の後、配列はグローバルにソートされず、2 回目の操作の効果は、最初の操作で値がどのように再配分されたかによって決まります。 

重要な観察は、ソートされたプレフィックスとサフィックスに関して操作が単調に動作することです。 ある程度の長さのプレフィックスの後$i$、 最初$i$要素はまさに$i$プレフィックスの最小要素をソート順に並べたもの。 同様に、ある長さの接尾辞の後$i$、最後$i$要素は内部的にソートされますが、要素にすでに正しいマルチセットが含まれていない限り、必ずしもグローバルに正しいサフィックスであるとは限りません。 

これは単純化につながります。最終的にソートされた配列は、プレフィックスとサフィックスを正しくすることで実現でき、それらの間の相互作用は、配列が「すでに正しい」から「修正が必要」に移行する単一の境界点にのみ依存します。 

問題は、配列がソートされたバージョンとすでに一致している場所を特定し、ソートされていない残りの領域を修正するために 1 つの操作が必要か 2 つの操作が必要かを判断することになります。 各手術コストは選択された長さによってのみ決まるため、すべての障害をカバーする最小のセグメントが必要です。 

配列のソートされたバージョンを計算し、元の配列と比較します。 させて$l$それらが異なる最初のインデックスであり、$r$それらが異なる最後のインデックス。 外のすべて$[l, r]$はすでに正しいです。 

ここからは、意味のある戦略がいくつかあるだけです。 

サイズの 1 つのプレフィックス操作で配列全体をソートできます。$n$。 これは常に機能します。 

不規則性が片側に揃っている場合は、1 つのプレフィックスまたは 1 つのサフィックスで配列を修正することを試みることができます。 

それ以外の場合は、2 つの操作を使用します。1 つは間隔の一部をカバーするプレフィックス、もう 1 つは残りをカバーするサフィックスです。 最適な分割は常に境界と一致します。$l$または$r$なぜなら、厳密に不一致間隔の外側に演算を適用しても正確性は変わらないが、コストが増加するからである。 

これにより、問題は、$l$そして$r$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(n^3)$|$O(n)$| 遅すぎる |
 | 境界分析 |$O(n \log n)$または$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列のソートされたコピーを作成します。 これにより、到達する必要があるターゲット構成が得られます。 シミュレーションではなく比較のみに使用します。 
2. 一番左のインデックスを見つけます$l$ここで、元の配列はソートされた配列とは異なります。 これは、正しさが最初に壊れる場所を示しています。 
3. 右端のインデックスを見つけます$r$ここで、元の配列はソートされた配列とは異なります。 これは、正しさの終わりを示します。 
4. そのようなインデックスが存在しない場合、配列はすでにソートされているため、答えはゼロになります。 
5. 長さの単一のプレフィックス演算を使用して配列全体をソートするコストを考慮する$n$、つまり$n^2$。 
6. 長さの単一プレフィックス操作かどうかを確認します$r+1$十分です。 アイデアは、その後すべてが$r$はすでに正しく、プレフィックスは次のように修正されています$r$グローバルな順序を復元すると、残りのサフィックスは変更されずに有効になります。 
7. 同様に、長さの単一の接尾辞演算が行われるかどうかを確認します。$n-l$十分です。 
8. 最後に、2 つの操作の分割を検討します。1 つのプレフィックスがカバーします。$[0, l + k]$および 1 つのサフィックスをカバーする$[l + k, n-1]$境界線の選択のために。 最適な分割は、プレフィックスとサフィックスの操作が、プレフィックスとサフィックスの境界候補に正確に一致する場合に発生します。$l$そして$r$なぜなら、これを超える操作は正確性を向上させることなくコストを増加させるだけだからです。 
9. 境界によって引き起こされるいくつかの候補の組み合わせを評価し、最小コストを取得します。 

### なぜ効果があるのか

 不一致間隔$[l, r]$順序がターゲットと異なる唯一の領域です。 この間隔をまったく外れた操作を行っても、障害を軽減することはできません。 部分的にカバーしているがさらに拡張する操作は、正確性を向上させることなくコストを増加させるだけです。 許可される操作は単調であるため (プレフィックスとサフィックスのソートはセグメント内でソートされた状態に並べ替えるだけです)、最適なソリューションでは操作の境界を次のように揃える必要があります。$l$そして$r$。 これにより、セグメント選択に対する指数関数的な検索が、一定数の意味のある構成に集約されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    b = sorted(a)
    
    if a == b:
        print(0)
        return
    
    l = 0
    while l < n and a[l] == b[l]:
        l += 1
    
    r = n - 1
    while r >= 0 and a[r] == b[r]:
        r -= 1
    
    ans = n * n
    
    # full prefix sort
    ans = min(ans, n * n)
    
    # prefix up to r
    # cost: (r+1)^2, but only valid if prefix fix makes whole array sorted
    def check_prefix(k):
        arr = a[:]
        i = k
        for x in range(i):
            for y in range(x + 1, i):
                if arr[x] > arr[y]:
                    arr[x], arr[y] = arr[y], arr[x]
        return arr == b
    
    def check_suffix(k):
        arr = a[:]
        start = n - k
        for x in range(start, n):
            for y in range(x + 1, n):
                if arr[x] > arr[y]:
                    arr[x], arr[x] = arr[y], arr[x]
        return arr == b
    
    for i in range(1, n + 1):
        # prefix only
        if check_prefix(i):
            ans = min(ans, i * i)
        # suffix only
        if check_suffix(i):
            ans = min(ans, i * i)
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、候補のプレフィックスとサフィックスの長さを直接テストします。 ヘルパー ルーチンは、セグメントに対するアリスの操作を正確にシミュレートし、ソートされたターゲットに対して正確さを検証します。 これは最も最適化された形式ではありませんが、問題の構造を反映しています。つまり、セグメントがローカルで正しいマルチセットにソートされるかどうか、そしてグローバルにそれで十分であるかどうかだけを考慮します。 

重要な実装の詳細は、選択されたセグメントに対する選択ソートのような動作を忠実に再現することです。 単純な sort() 呼び出しを想定するなど、何らかの逸脱があると、中間状態が誤って表現され、不正確な実行可能性チェックが行われる可能性があります。

 ## 特殊なケース

 サイズ 1 の最小配列は、すでにソートされており、操作が必要ないため、常にコストがゼロになります。 

すでにソートされた配列は、アルゴリズムがゼロ不一致間隔を正しく検出する必要があることを示しています。 不必要な操作はコストを誤って増加させます。 

完全に反転した配列は、たとえ配列が最大限に無秩序であっても、単一のプレフィックス操作がグローバルに十分であることを認識することの重要性を示しています。 

境界での 1 つの反転、たとえば$[2,1,3,4,5]$は、局所的な乱れは非常に小さなプレフィックスで修正できることが多く、大規模な操作を試みてもコストが増加するだけであることを示しています。 

みたいな中間反転$[1,3,2,4,5]$最適なセグメントは、不必要に完全なプレフィックスまたはサフィックスに拡張するのではなく、不規則な間隔と正確に一致する必要があることを強調しています。
