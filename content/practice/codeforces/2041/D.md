 ## 解決策
 ## 問題の理解

 文字のグリッドとして表された長方形の迷路があります。 空のセルは歩くことができ、壁は動きをブロックし、2 つの特別なセルは開始位置とターゲット位置をマークします。 目標は、4 つの基本的な方向に移動しながら、最小限のステップ数で最初からターゲットに到達することです。 重要な点は、同じ方向に 3 つ以上の連続ステップを実行できないことです。 実行すると「落ちてしまう」ため、同じ方向に 3 つを超えるシーケンスは許可されません。 

入力により、グリッド サイズと各セルの説明が提供されます。 出力は、ターゲットに到達するために必要な最小ステップ数、またはパスが存在しない場合は -1 です。 

境界は重要です。 セルの総数は 200,000 に達する可能性があり、およそ O(n*m) よりも複雑なアルゴリズムは遅すぎることになります。 グリッドの完全な走査を繰り返したり、枝刈りをせずに考えられるすべてのパスを探索する単純な DFS を行う余裕はありません。 これにより、すべての一連の動きを明示的に試行するアルゴリズムが除外されます。 

明らかではないエッジ ケースには、最短の幾何学的パスが「3 ステップ ルール」によってブロックされる状況が含まれます。 たとえば、直線の長さ 5 の廊下は、5 つの直線ステップでは通過できません。 1 つの方向で最大 3 つのシーケンスに分割し、次に方向を変える必要があります。 連続ステップ制約を無視する単純な BFS は、少なくとも 6 回の移動が必要な場合に、ターゲットに 5 回の移動で到達可能であると誤って報告します。 もう 1 つの注意が必要なケースは、開始点が一方向を除くすべての面で壁にすぐ隣接している場合です。 BFS は、無効なパスを回避するために、連続する移動を注意深く追跡する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、DFS を使用して再帰的に、またはキューを使用して反復的にすべてのパスを最初から探索し、動きの正確なシーケンスを追跡しようとします。 すべてのセルで各方向への連続移動の回数を保存する必要があります。 このアプローチはすべての有効なシーケンスを考慮するため概念的には正しいですが、すぐに遅くなりすぎます。 最悪の場合、各セルは 4 つの可能な方向とそれぞれ最大 3 つの連続ステップで訪問される可能性があり、追跡する必要がある状態は O(4_3_n*m) になります。 これは理論的には実現可能ですが、再帰と状態チェックの繰り返しを伴う単純な実装では、200,000 セルの制限に近づくと困難になります。 

最適なアプローチでは、BFS を使用し、各状態を位置、最後の移動方向、およびその方向への連続ステップの組み合わせとして扱います。 状態を (x、y、方向、Continuous_count) として定義することで、各動作が 3 ステップのルールに従うようになります。 BFS は、初めて目標に到達するときに、最小限のステップ数が使用されたことを保証します。 重要な洞察は、連続ステップ ルールではパス全体を記憶する必要はなく、最後の方向とその数だけを記憶する必要があるため、追跡する状態の数が大幅に減少するということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DFS | O(4_3_n_m_paths) | O(n_m_paths) | 遅すぎる |
 | 状態追跡を備えた BFS | O(n_m_4*3) | O(n_m_4*3) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 入力グリッドを解析し、開始点とターゲットの座標を特定します。 これにより、BFS の開始点と目的地が決まります。 
2. 4 次元の訪問済み配列またはディクショナリ: Visited[x][y][direction][count] を初期化して、セルが特定の最後の方向と連続ステップ数で訪問されたかどうかを追跡します。 これにより、BFS が状態を再訪せず、サイクルが防止されます。 
3. BFS キューを開始位置で初期化します。 初期状態では、方向は「なし」、連続数はゼロと考えることができます。 
4. キューが空でない間に、現在の状態 (x、y、last_direction、Continuous_count、steps_taken) をキューから取り出します。 4 つの可能な移動方向のそれぞれについて、新しい位置 (nx、ny) を計算します。 
5. グリッドの外や壁に入った場合は、移動をスキップします。 
6. 新しい連続カウントを決定します。 移動が last_direction と同じ方向の場合は、Continuous_count を 1 ずつ増分します。 それ以外の場合は、1 にリセットします。Continuous_count が 3 を超える場合は、この移動をスキップします。 
7. 新しい状態 (nx、ny、方向、Continuous_count) がまだ訪問されていない場合は、訪問済みとしてマークし、steps_taken + 1 でキューに入れます。 
8. いずれかの時点で BFS がターゲット座標に到達すると、steps_taken を返します。 BFS はステップの増加順に状態を探索するため、これにより最小限のステップが保証されます。 
9. BFS キューがターゲットに到達せずに空になった場合は、-1 を返します。 

機能する理由: BFS は、ステートが初めてターゲットに到達するときに、可能な限り最小限の移動で済むようにします。 状態には方向と連続するステップが含まれており、すべての動きが 3 ステップのルールに従うことが保証されます。 ステップ制限に違反するパスはキューに追加されないため、より短いパスは存在できません。 

## Python ソリューション```python
import sys
from collections import deque
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    dirs = [(0,1), (1,0), (0,-1), (-1,0)]  # R, D, L, U
    
    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'S':
                sx, sy = i, j
            if grid[i][j] == 'T':
                tx, ty = i, j

    visited = [[[[False]*4 for _ in range(4)] for _ in range(m)] for _ in range(n)]
    queue = deque()
    
    # direction: 0=R,1=D,2=L,3=U, last=-1 for start
    for d in range(4):
        visited[sx][sy][d][0] = True
        queue.append((sx, sy, d, 0, 0))
    
    while queue:
        x, y, last_dir, count, steps = queue.popleft()
        if (x, y) == (tx, ty):
            print(steps)
            return
        for d, (dx, dy) in enumerate(dirs):
            nx, ny = x + dx, y + dy
            if not (0 <= nx < n and 0 <= ny < m):
                continue
            if grid[nx][ny] == '#':
                continue
            new_count = count + 1 if d == last_dir else 1
            if new_count > 3:
                continue
            if not visited[nx][ny][d][new_count-1]:
                visited[nx][ny][d][new_count-1] = True
                queue.append((nx, ny, d, new_count, steps+1))
    print(-1)

if __name__ == "__main__":
    solve()
```BFS は、4 つの可能な開始方向でキューを初期化します。 各移動は、移動が同じ方向に継続した場合にのみ連続カウントを更新します。 訪問された配列は 4 つの方向すべてを追跡し、無効なシーケンスの再訪問を防止します。 小切手`(new_count > 3)`3 段階ルールを直接適用します。 

## 実用的な例

 サンプル 1:

 | ステップ | 位置 (x,y) | 方向 | 連続 | ステップ |
 | --- | --- | --- | --- | --- |
 | 0 | (1,1) | R | 0 | 0 |
 | 1 | (1,2) | R | 1 | 1 |
 | 2 | (1,3) | R | 2 | 2 |
 | 3 | (1,4) | R | 3 | 3 |
 | 4 | (2,4) | D | 1 | 4 |
 | 5 | (3,4) | D | 2 | 5 |
 | 6 | (3,5) | R | 1 | 6 |
 | 7 | (3,6) | R | 2 | 7 |
 | ... | ... | ... | ... | ... |
 | 15 | (1,10) | R | 2 | 15 |

 これは、BFS が最短パスを探索しながら連続ステップ ルールを正しく適用していることを示しています。 

カスタム ケース: 廊下 1x5:```
5 5
#####
#S...#
#####
```BFS は、直線の 5 ステップのシーケンスを右の 3 ステップに分割し、次に 1 ステップの下/上 (可能な場合)、次に残りのステップに分割し、無効なシーケンスが発生しないようにします。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n_m_4*3) | 各セルは最大 4 方向×連続 3 回まで訪問できます。 |
 | スペース | O(n_m_4*3) | 訪問された配列は、BFS のすべての状態を追跡します。 |

 n*m ≤ 200,000 の場合、状態の最大数は 240 万で、これは 2 秒以内に実現可能です。 メモリ使用量は 1 GB をはるかに下回っています。
