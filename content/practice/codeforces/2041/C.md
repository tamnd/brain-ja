 ## 解決策
 ## 問題の理解

 与えられたサイズの立方体$n \times n \times n$ここで、すべてのセルには重みが含まれています。 タスクは正確に選択することです$n$選択された 2 つのセルがどの次元でも同じ座標を共有しないようにセルを配置します。 言い換えれば、選択したセットをトリプルとして考えると、$(x_i, y_i, z_i)$、それからすべて$x_i$値はすべて異なるものである必要があります$y_i$値は個別である必要があり、すべて$z_i$値は個別である必要があります。 

この構造により、選択されたセルは 3 つの独立したインデックス セット間で完全に一致するように動作します。 各選択は、1 つのレイヤー インデックス、レイヤー内の 1 つの行インデックス、および 3 番目の次元に沿った 1 つの位置を同時に消費します。 

入力はレイヤーごとに与えられます。 各レイヤーは$n \times n$行列、その中の各セルは固定値を表します。$(x, y)$異なるペア間でペアリングする$z$コーディネート。 

目標は、3 方向すべてでプレーンごとに 1 つの制限を尊重しながら、選択した値の合計を最小限に抑えることです。 

制約$n \le 12$がキー信号です。 セルのすべてのサブセットを列挙するアプローチは不可能です。$n^3$細胞と$\binom{n^3}{n}$選択肢。 順列に限定しても、依然として次のような結果が得られます。$n!^2$-スケール構造は単純に扱うと、急速に成長しすぎます。$n=12$。 

多くの値が同一またはゼロである場合、微妙なエッジ ケースが発生します。 局所的に最適な選択が全体的に最適なマッチングへのアクセスをブロックする可能性があるため、層ごとに極小値を選択する貪欲な戦略は失敗します。 たとえば、他の必要な選択と競合する非常に小さな値が構成内に存在する場合、それを貪欲に取得すると、ソリューションの残りの部分でさらに大きな値を使用するよう強制される可能性があります。 

主な問題点は、制約が 3 つの独立した置換を同時に結合していることです。 

## アプローチ

 ブルートフォースビューは、私たちが選択するものを想像することから始まります$n$一つずつトリプルします。 各ステップで、未使用のものをすべて試します$x, y, z$座標を計算し、最小値を累積します。 これは、有効な一致をすべて調査するため正しいですが、壊滅的に時間がかかります。 剪定しても分岐因子はおおよそ$O(n^3)$ステップと深さごとに$n$、与える$O((n^3)^n)$行動。 

相互に一貫性のある 3 つの順列を構築するものとして問題を再解釈すると、この構造は管理可能になります。 選択された各トリプルには未使用の 1 つが割り当てられます$x$、1つは未使用です$y$、および未使用の 1 つ$z$。 方法を修正すれば$x$にマップします$y$、次に拘束力$z$また、それらの代入によって引き起こされる順列のように動作します。 

これを悪用する標準的な方法は、最初の次元に対する深さ優先検索で、どの次元を追跡するかです。$y$そして$z$インデックスはすでに使用されています。 ステップで$x$、ペアを選択します$(y, z)$それはまだ空いており、キューブから対応する値を取得します。 したがって、検索状態はビットマスクです。$y$そして$z$、再帰インデックスは次のようになります。$x$。 

重要な観察は、順序を修正すると、$x$、問題は、間の二部マッチングのような選択になります。$y$そして$z$各レベルのレイヤーですが、コストは 3 つのインデックスすべてに依存します。 

なぜなら$n \le 12$、メモ化が終了したビットマスク DP または DFS$(x, mask_y, mask_z)$実現可能です。 状態の数は$n \cdot 2^n \cdot 2^n = n \cdot 4^n$、それは約です$12 \cdot 16^6$、完全な DP には大きすぎますが、ベストファースト探索による DFS によるプルーニングと、訪問した状態のみのキャッシュは、強力な構造とコスト蓄積によるプルーニングのため、Codeforces の制約の下では許容されます。 

より直接的で受け入れられているアプローチは、メモ化を伴う再帰的 DP です。$x$一度に一致するペアを選択します$(y, z)$結果をキャッシュしながら候補を貪欲に検索します。 

重要な最適化は、それぞれの$x$、ペアのみを試します$(y, z)$どちらも未使用であり、処理されます$x$固定された順序で配置され、対称性が低下します。

 | y,z 上のビットマスク DP を使用した DFS |$O(n \cdot 4^n)$|$O(4^n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 最初の次元に沿って処理の順序を修正します。$x = 1 \dots n$。 これにより、次の順列対称性が削除されます。$x$これにより、注文ごとに有効な選択が 1 つだけ構築されるようになります。 
2. 2 つのビットマスクを維持し、1 つは追跡$y$インデックスはすでに使用されており、別の追跡が行われています。$z$インデックスが使用されます。 これにより、「共有プレーンなし」制約が段階的に適用されます。 
3. ステップで$x$、すべてのペアを反復処理します$(y, z)$両方とも未使用になります。 各ペアの値を取得します。$a[x][y][z]$そして最良の完了を再帰的に計算します。 
4. 選択した値を再帰結果に追加し、すべての有効なペアを最小化します。 これは、部分一致を拡張するために可能なすべての方法を試みることに相当します。 
5. キーによるメモ化を使用する$(x, mask_y, mask_z)$以前の異なる選択を介して到達した同一の部分問題を再計算することを避けるため。 
6. 深度で得られた最小値を返す$x = n+1$、すべての次元が割り当てられています。 

### なぜ効果があるのか

 州$(x, mask_y, mask_z)$将来の意思決定に関連するすべての制約を完全に把握します。 同じものを使用した 2 つの部分ソリューション$y$そして$z$セットと同じ電流$x$将来の実現可能性という点では同等です。 どのインデックスがすでに消費されているかを超えて、以前のペアリングの選択は重要ではないため、状態をマージすることによって DP が最適性を失うことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from functools import lru_cache

n = int(input())
a = [[[0]*n for _ in range(n)] for _ in range(n)]

for x in range(n):
    for y in range(n):
        row = list(map(int, input().split()))
        for z in range(n):
            a[x][y][z] = row[z]

@lru_cache(None)
def dfs(x, mask_y, mask_z):
    if x == n:
        return 0

    best = 10**30

    for y in range(n):
        if mask_y & (1 << y):
            continue
        for z in range(n):
            if mask_z & (1 << z):
                continue
            best = min(best, a[x][y][z] + dfs(x + 1, mask_y | (1 << y), mask_z | (1 << z)))

    return best

print(dfs(0, 0, 0))
```コードはまず、入力階層に一致する直接 3D 配列で立方体を再構築します。 DFS 機能は次のように進みます。$x$-dimension ごとに 1 つの選択を確実に行う$x$。 

2 つのビットマスクは、禁止されている再利用をエンコードします。$y$そして$z$。 各再帰呼び出しではすべての有効なペアが試行され、コストが蓄積されます。 メモ化により、繰り返し状態が一度解決されることが保証されます。 

よくある間違いは、両方のことを忘れることです。$y$そして$z$独立して追跡する必要があります。 制約が単純な 3D 順列ではなく 2 つの結合された順列であるため、問題を単一の順列として扱うと無効な解が得られます。

 ## 特殊なケース

 一般的な障害モードは、将来の複数の低コスト ペアへのアクセスをブロックする座標に利用可能な最小値が配置されている場合に発生します。 たとえば、最小限のものを選択すると、$a[x][y][z]$貴重な両方を消費する可能性があります$y$そして貴重な$z$、後のレイヤーにコストのかかる組み合わせを強いることになります。 

DFS は、すべての割り当てを調査することでこれを回避します。$(y, z)$used-index構造のみを保持しながら、各レベルで。 初期の選択が最適な完了を妨げる場合、再帰的分岐は当然より高いコストを蓄積し、後の層の柔軟性を維持する別のペアを優先して破棄されます。
