 ## 問題の理解

 課題はチェス盤上のビショップの動きに関するものです。 標準グリッド上に 2 つの正方形が与えられ、それぞれが座標によって識別されます。 ピースは対角線に沿ってのみ移動できます。つまり、移動するたびに行と列が同じ大きさで反対方向に変化します。 

目標は、開始マスからターゲットマスに移動するために必要なビショップの最小移動回数を決定するか、それが不可能であると報告することです。 

入力は、開始正方形と宛先正方形の座標で構成されます。 出力は、必要な対角移動の最小数を表す単一の整数、または問題の定式化に応じて不可能を示す特別な値です。 

明示的な制約がない場合でも、このタイプの問題は、テスト ケースごとに定数時間推論を行うように設計されています。 重要な意味は、どのソリューションでも基板の形状を数回の算術チェックに削減する必要があるということです。 パスのシミュレーション、ボード上の BFS、またはステップバイステップの移動を伴うものはすべて、座標範囲が大きい場合、グリッドのサイズに少なくとも線形または二次の動作が導入されるため、非常に遅くなります。 

両方の正方形が同一である場合、微妙なエッジケースが現れます。 この状況では、移動する必要がないため、答えはゼロでなければなりません。 別の特殊なケースは、チェス用語で 2 つの正方形が同じ色ではない場合に発生します。 ビショップは常に同じ色のマス目に留まるため、座標間でパリティが異なる場合、ターゲットに到達することは不可能です。 例えば、(1,1)から(1,2)までは色が違うので答えられません。 対角線距離のみをチェックする単純なアプローチでは、このパリティ制約を考慮しない場合、到達可能性を誤って仮定することになります。 

## アプローチ

 この問題を考える強引な方法は、最初の正方形から始まるすべての可能なビショップ パスをシミュレートすることです。 ビショップはどの位置からでも、4 つの対角方向に沿って移動でき、場合によっては多くのステップを実行できます。 グリッド上の BFS は、移動数の観点から最短パスを正しく見つけます。 

これが機能するのは、BFS が移動回数を増やしながら到達可能なすべてのマス目を探索し、初めて目的地に到着するときに使用した移動回数が最小限であることが保証されるためです。 ただし、基板のサイズによってコストが発生します。 座標の範囲が大きな値に達する場合、グリッドを明示的なグラフとして扱うことは不可能になります。 各ノードは対角線に沿って最大 O(n) 位置に拡張でき、大規模な状態空間になります。 

重要な観察は、司教の運動が強力な幾何学的構造を持っているということです。 ビショップは、両方の正方形が同じ対角線上にある場合に限り、1 回の移動で正方形に到達します。これは、座標の差の絶対値が等しいという条件と同等です。 そうでない場合、問題は 2 つの移動パスが存在するかどうかを確認することになります。 チェスの幾何学では、同じ色の 2 つの正方形は、両方の対角の交差点にある中間の正方形を通過することによって、最大 2 回のビショップの動きで接続できます。 

これにより、問題全体が座標のパリティと対角の等価性の算術チェックに集約されます。

 ## アルゴリズムのチュートリアル

1. 開始正方形座標と目標正方形座標を読み取ります。 これらは 2D 整数格子内の 2 つの点を定義し、チェス盤の位置として解釈します。 
2. 開始マスがターゲットマスと同一の場合は、直ちに 0 を返します。 移動は必要なく、移動ルールを適用しようとしても不必要な計算が発生するだけです。 
3. 座標の絶対差を比較することにより、2 つの正方形が同じ対角線上にあるかどうかを確認します。 もし`|x1 - x2| == |y1 - y2|`, 単一のビショップの動きでそれらを直接接続できるため、1 を返します。 
4. 2 つの正方形が同じ色であるかどうかを確認します。 これは座標のパリティによって決まります。正方形は、黒であるか白であるかに応じて判断できます。`x + y`偶数または奇数です。 2 つの正方形の間でパリティが異なる場合は、出力形式に応じて -1 または「不可能」を返します。 
5. 正方形が 1 回の移動では到達できないが、同じ色を共有している場合は、2 を返します。そのようなペアは、両方の端点からの対角線の交点にある中間正方形を選択することによって、正確に 2 回のビショップ移動で接続できます。 

正確さは、考えられるすべての構成を、同一の位置、単一の対角線の到達可能性、および同じ色だが非対角線の到達可能性という 3 つの独立した幾何学的ケースに分類することで得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x1, y1, x2, y2 = map(int, input().split())

    if x1 == x2 and y1 == y2:
        print(0)
        return

    if abs(x1 - x2) == abs(y1 - y2):
        print(1)
        return

    if (x1 + y1) % 2 != (x2 + y2) % 2:
        print(-1)
        return

    print(2)

if __name__ == "__main__":
    solve()
```この実装では、論理分類が直接反映されます。 最初の条件は、移動が必要ない縮退ケースを処理します。 2 番目の条件は、行と列のオフセットの大きさが一致する必要がある、ビショップの動きの正確な幾何学的定義を取得します。 3 番目の条件は、ビショップが正方形の色を保持するという不変条件をエンコードし、反対のパリティ間の遷移を防ぎます。 

最終的な 2 の戻り値は、前のケースを除外した後にのみ正当化されます。つまり、正方形は同じ色であるが、斜めに並んでいないことが保証されます。 これにより、明示的に構築しなくても 2 つの移動パスが常に存在することが保証されます。

 ## 特殊なケース

 重要なエッジケースは、開始マスと終了マスが一致する場合です。 入力用`1 1 1 1`の場合、アルゴリズムは幾何学的チェックの前にすぐに 0 を返します。 これにより、位置が斜めまたは 2 つの移動で到達可能であると誤って分類されるのを防ぎます。 

もう 1 つのケースは、次のような直接斜め方向の到達可能性です。`3 5 6 8`。 絶対的な差は等しいため、対角方向の移動はすでに十分であり、色分類よりも具体的であるため、アルゴリズムはパリティをチェックせずに 1 を返します。 

3 番目のケースには、次のような反対色の正方形が含まれます。`1 1 2 3`。 ここでパリティチェック`(x + y) % 2`が異なるため、アルゴリズムは不可能な場合に正しく停止します。 対角線の距離のみをチェックする単純なアプローチでは、ビショップ パスが存在しないにもかかわらず、誤って 2 移動の解決策を割り当てようとします。 

最後に、以下のような一般的な同色非対角の場合`2 3 5 6`対角フィルタとパリティ フィルタの両方を通過し、2 つの移動の結論が保証されます。 これにより、分類によってすべての可能な入力が重複や曖昧さなしにきれいに分割されていることが確認されます。
