 ## 解決策
 ## 問題の理解

 整数でラベル付けされた頂点のコレクションが与えられ、各頂点のペアには、それらの値のビットごとの XOR によって定義される暗黙的な接続コストがあります。 タスクは、選択した接続の総コストが最小になるように、すべての頂点を 1 つのツリー構造に接続することです。2 つの頂点間の各接続は、ラベルの XOR に寄与します。 

基礎となるグラフは完成していますが、エッジの数は二次関数的に増加するため、自明でない入力サイズではすべてのエッジを明示的に構築することは不可能です。 この問題は、代わりに、ほとんどのエッジが実体化することを回避するために、XOR 演算の構造を悪用することに依存しています。 

入力は整数の配列として解釈でき、各整数は完全に接続された重み付きグラフ内のノードを表します。 出力は、このグラフ上のスパニング ツリー内のエッジの重みの最小可能合計です。 

素朴な解釈では、Kruskal や Prim のような MST アルゴリズムがすぐに示唆されます。 ただし、どちらもエッジを列挙するか、最小出力エッジを効率的にクエリする必要があります。 すべてのペアがエッジを定義するため、列挙だけでもすでに O(n²) のコストがかかりますが、n が 2⋅10⁵ などの一般的な競技プログラミングの制限に近づくと、これは実行不可能になります。 

値が同一の場合、重要なエッジケースが発生します。 すべての数値が同じ場合、すべての XOR エッジの重みは 0 になるため、どのスパニング ツリーの総コストも 0 になります。 エッジの構築や並べ替えを試みる単純な実装では、たとえ答えが些細なものであっても、かなりの時間を無駄にする可能性があります。 もう 1 つの微妙なケースは、数値が上位ビットによってクラスター化されている場合に発生します。 たとえば、値の半分が約 2¹⁵ で、残りの半分が約 2¹⁵ + 小さい値の場合、MST 構造は、ソートされた順序でのローカル隣接ではなく、グループ間の XOR 最小化に大きく依存し、順序に基づく貪欲な仮定が無効になります。 

## アプローチ

 ブルートフォースソリューションでは、問題を完全なグラフ MST として扱います。 すべてのペアごとの XOR 距離を計算し、エッジを保存し、Kruskal を実行します。 XOR は有効な非負の重みを定義し、MST アルゴリズムが直接適用されるため、これは概念的には簡単です。 MST プロパティは重みの生成方法に依存しないため、正確性は即座にわかります。 

失敗点はスケールです。 n(n−1)/2 エッジの計算にはすでに 2 次時間とメモリが必要であり、それらを並べ替えると別の対数係数が追加されます。 n が約 10⁵ の場合でも、これはまったく実行不可能です。 

XOR の構造により状況が変わります。 2 つのノード間の重みはビット パターンのみに依存します。 すべてのペアを比較する代わりに、バイナリ表現によって数値をグループ化し、問題をビットごとに再帰的に分離できます。 重要な観察は、XOR 距離を介したあらゆる MST では、上位ビットで最初に異なる数値間で接続が形成される傾向があり、この構造はバイナリ トライを使用して利用できるということです。 

このアイデアは再帰的になります。数値を最上位ビットで分割し、部分問題を個別に解決し、次に 2 つの半分を可能な限り最小限の交差エッジで慎重に接続します。 そのクロス エッジは、完全なペアごとの比較を避け、2 つのセット間の最小 XOR ペアをクエリするトライを使用して効率的に見つけることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | Brute Force (完全なグラフ上の Kruskal) | O(n² log n) | O(n²) | 遅すぎる |
 | MST のディバイド＆コンカーに挑戦 | O(n log A) | O(n log A) | 承認済み |

 ここで、A は最大値の範囲であり、通常は制約に応じて 23¹ または 2⁶⁰ によって制限されます。 

## アルゴリズムのチュートリアル

 入力数値をバイナリ空間内の点として扱います。 目標は、各ビット レベルでグループ間の接続を最小限に抑えながら MST を再帰的に構築することです。

1. 1 つのセット内のすべての数値から始めて、それらの中で出現する最上位ビットを検討します。 このビットは、数値が異なる可能性がある最も重要な場所であるため、最初の意味のある分割を定義します。 
2. ビットが 0 か 1 かに基づいて、セットを 2 つのサブセットに分割します。この分割により、サブセット間のすべてのエッジが XOR 寄与にこのビットを含める必要があり、クロス エッジの下限が保証されます。 
3. 各サブセット内の MST コストを再帰的に計算します。 この段階では、各サブセットが内部で最適に解決されていると仮定します。 
4. 2 つのサブセットを接続するには、それらの間に最小の XOR ペアが必要です。 すべてのペアをチェックする代わりに、1 つのサブセットをバイナリ トライに挿入し、他のサブセットの各要素をクエリして最適な一致を探します。 
5. 最小のクエリ結果により、2 つのコンポーネントを接続する最も安価なエッジが得られます。 この値を合計コストに加算します。 
6. 概念的に 2 つのサブセットをマージし、再帰で上向きに戻り、各レベルがコンポーネント間の接続を 1 つだけ提供するようにします。 

重要な考え方は、各再帰レベルでグループ間エッジが 1 つだけ導入され、そのエッジがトライを使用して最適に選択されるということです。 

### なぜ効果があるのか

 各再帰レベルで、ビットによる分割により 2 つのコンポーネントが作成されます。クロスエッジにはそのビットが XOR 値に含まれている必要があります。つまり、このレベルで見つかった最良のペアよりも安価なクロスエッジは存在しません。 各コンポーネント内では、数値が上位ビットで定義されたグループに属するかどうかに下位ビットが影響を与えることができないため、すべての決定は相手側とは独立しています。 

これにより、構造的不変条件が強制されます。各再帰呼び出しは、ビット制限されたユニバース内で MST を完全に解決し、残された唯一の自由は、2 つの部分の間の 1 つの接続だけになります。 最小の XOR ペアを選択すると、この必要な接続に寄与するコストが可能な限り最小限に抑えられ、最適性が全体的に維持されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Trie:
    def __init__(self):
        self.next = [[-1, -1]]
        self.count = [0]

    def add(self, x):
        node = 0
        self.count[node] += 1
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            if self.next[node][bit] == -1:
                self.next[node][bit] = len(self.next)
                self.next.append([-1, -1])
                self.count.append(0)
            node = self.next[node][bit]
            self.count[node] += 1

    def query(self, x):
        node = 0
        res = 0
        for b in range(30, -1, -1):
            bit = (x >> b) & 1
            if self.next[node][bit] != -1 and self.count[self.next[node][bit]] > 0:
                node = self.next[node][bit]
            else:
                res |= (1 << b)
                node = self.next[node][bit ^ 1]
        return res

def solve(arr):
    if len(arr) <= 1:
        return 0
    if len(arr) == 2:
        return arr[0] ^ arr[1]

    mx = max(arr)
    bit = mx.bit_length() - 1

    if bit < 0:
        return 0

    left = []
    right = []
    for x in arr:
        if (x >> bit) & 1:
            right.append(x)
        else:
            left.append(x)

    if not left:
        return solve(right)
    if not right:
        return solve(left)

    cost = solve(left) + solve(right)

    trie = Trie()
    for x in left:
        trie.add(x)

    best = float('inf')
    for x in right:
        best = min(best, trie.query(x))

    return cost + best

def main():
    n = int(input())
    arr = list(map(int, input().split()))
    print(solve(arr))

if __name__ == "__main__":
    main()
```実装の中核は再帰的です。`solve`ビットごとのパーティショニングを強制する関数。 トライは、2 つの独立したサブツリーを接続する必要がある時点でのみ使用され、二次関数の動作が妨げられます。 

実装の微妙な詳細は、固定ビット範囲です。 標準の 32 ビット制約では、30 から 0 までを使用するのが安全です。 トライ クエリは常に、可能な限りビットを一致させることによって、XOR を最小化するブランチを貪欲に選択します。 

再帰構造は不可欠です。 最上位ビットによってきれいに分割せずにすべてのレベルでマージが行われた場合、クロス エッジが 1 つの主要なビットの差に対応することが保証されないため、正確性の議論は破綻します。 

## 実用的な例

 ### 例 1

 入力:```
4
1 2 3 4
```まず、存在する最上位ビット (ビット 2) で分割します。 

| ステップ | 現在のセット | 左 | 右 | クロスベスト | 追加コスト |
 | --- | --- | --- | --- | --- | --- |
 | 1 | [1,2,3,4] | [1,2,3,4] ビットごとに分割 | [] | - | - |
 | 2 | 再帰的分割 | [1,2] | [3,4] | trie | によって計算されます。 最小クロス |
 | 3 | 葉の結合 | (1,2) と (3,4) | - | XOR エッジ | 蓄積された |

 このアルゴリズムは、各半分の内部に MST を構築し、グループ間の最も安価な XOR ペアを使用してそれらを接続します。 これは、グループ間ペアリングが恣意的ではなく、ビット構造から派生することを裏付けています。 

### 例 2

 入力:```
3
0 8 10
```ここで、最上位ビットは 3 (値 8) です。 

| ステップ | セット | 左 (ビット 3 = 0) | 右 (ビット 3 = 1) | ベストクロスエッジ |
 | --- | --- | --- | --- | --- |
 | 1 | [0,8,10] | [0,10] | [8] | trie | によって計算されます。 
| 2 | 左を解決 | [0,10] | - | 0^10 = 10 |
 | 3 | 接続 | - | - | 最小(8^0, 8^10) = 最小(8,2)=2 |

 このトレースは、最上位ビットによるグループ化が重要である理由を示しています。数値的には 8 が 10 から遠く離れているにもかかわらず、XOR 構造により 10 を通る小さな接続エッジが可能になります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log A) | 各数値は、ビット長によって制限される再帰深さ全体でトライ レベルごとに 1 回処理されます。 
| スペース | O(n log A) | trie ノードは、挿入されたプレフィックスに比例して蓄積されます。 

再帰の深さは、最大値のビット数によって制限されます。 各レベルは要素を重複させることなく配列を分割するため、すべてのレベルにわたる合計作業量は対数因数まで線形を維持します。 これは、最大 2⋅10⁵ までの n の一般的な制限内に問題なく収まります。

 ## 特殊なケース

 すべての値が同一の場合、すべての再帰的分割により最終的に空の相互接続が生成され、すべてのサブツリーのコストがゼロになります。 トライは意味のある形で使用されることはありませんが、交差エッジがすでにゼロコストの構造を改善できないため、再帰は引き続き正しくゼロを返します。 

連続する整数など、値が下位ビットのみで異なる場合、最上位ビットの分割により小さなグループがすぐに分離されます。 各マージ ステップでは非常に小さな XOR エッジが検出され、トライにより不必要な比較を列挙することなくそれらのエッジが確実に選択されます。
