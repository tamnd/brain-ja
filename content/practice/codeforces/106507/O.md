 ## 解決策
 ## 問題の理解

 私たちは、`n x n`セルのボード。 各セルはアクティブ (`1`) またはブロックされた (`0`）。 隣り合うセル間での移動は許可されており、アクティブなセルのみを訪問できます。 更新のたびに 1 つのセルの状態が変化するため、左上のセルが右下のセルにまだ到達できるかどうかを判断する必要があります。 

問題は動的更新だけではありません。 入力クエリは以前の回答を使用して暗号化されます。 入力で指定された座標は、最後の座標に応じてシフトされます。`num`そのため、クエリを並べ替えたり、オフラインで処理したりすることはできません。 正確な次の更新を知る前に、それぞれの状態に答える必要があります。 

ボード サイズが十分に大きいため、400 万頂点のグラフを保存するにはすでにコストがかかりますが、更新数はわずか 2000 です。これは、慎重に最適化されたトラバーサルが機能する一方で、すべての更新後の完全なグラフ アルゴリズムでは遅すぎることを意味します。 素朴なBFSはすべてに影響を与えます`n^2`すべてのクエリの後のセル、`O(qn^2)`これは、最大制限で約 80 億のセル訪問になります。 

重要なエッジ ケースは、唯一可能なコリドーを切断するセルと、開始セルまたは終了セルがブロックされているケースです。 例えば：```
1
0
1 1
0 0
```反転後、唯一のセルがアクティブになるため、答えは次のようになります。`YES`。 単一セル グリッドのケースを処理せずに隣接セルのみをチェックする実装は失敗します。 

別のケースは次のとおりです。```
2
11
10
1 1
0 0
```右下のセルは最初はブロックされているため、無関係な反転の後でも答えは残る必要があります`NO`そのセルがアクティブになるまで。 開始領域が拡張されたかどうかのみを追跡するコードでは、宛先を確認せずに誤って成功を報告する可能性があります。 

## アプローチ

 簡単な解決策は、BFS を実行することです。`(1,1)`フリップするたびに。 BFS は開始セルの連結成分を正確に計算するため、正しいことを証明するのは簡単です。 問題は繰り返し作業の量です。 と`q = 2000`そして`n = 2000`、最悪の場合は約`2000 * 2000 * 2000 = 8 * 10^9`セルチェック。 

問題を変える観察は、グリッドのサイズが固定されており、行数がわずか 2000 であることです。BFS キューに個々のセルを保存する代わりに、現在到達可能な領域のすべての行をビットセットとして保存します。 Python の整数はすでにコンパクトなビット配列のように動作するため、水平方向の拡張は数ビットの操作になります。 各 BFS レイヤーは、整数シフトを使用してすべての行を一度に処理します。 

最適化されたアプローチでもグラフの走査は実行されますが、定数係数ははるかに小さくなります。 2000 個のセルの行は 1 つの整数で表され、フラッド フィル全体は約`n`レイヤーごとの整数演算。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースBFS |`O(q * n^2)`|`O(n^2)`| 遅すぎる |
 | ビットセット BFS |`O(q * n * d)`どこ`d`は拡張ラウンドの数です |`O(n)`| 指定された制限内で受け入れられます |

 ## アルゴリズムのチュートリアル

 1. すべてのグリッド行を整数ビットマスクとして保存します。 少し`j`行の`i`セルかどうかを示します`(i, j)`活動中です。 
2. 以前の回答を使用して現在のクエリをデコードします。 最後`num`答えはバイナリ値として保持されます。`YES`に代表される`1`。 
3. 対応する行整数のビットを切り替えて、デコードされたセルを反転します。 
4. ビットセットを使用してフラッドフィルを実行します。 配列を保持する`reach`、 どこ`reach[i]`行内で到達可能なすべての列が含まれます`i`。 
5. だけで始める`(0, 0)`そのセルがアクティブであれば到達可能です。 
6. すべての行を繰り返し展開します。 新しいセルは、前の行、次の行、および左右にシフトされた同じ行から取得される可能性があります。 結果をその行のアクティブなセルと交差させます。 
7. 反復により新しい到達可能なセルが生成されなくなったら停止します。 最終行に最後のビットが含まれている場合、宛先には到達可能になります。 

なぜ効果があるのか:

 不変条件は、各拡張ラウンドの後に、`reach`最大でも現在のラウンド数の長さのパスを使用して最初から到達可能なセルのみが含まれます。 4 つの可能な方向で拡張すると、有効な次のステップがすべて追加され、グリッドと交差するとブロックされたセルが削除されます。 新しいセルが表示されない場合、到達可能なコンポーネントは完了しているため、宛先ビットをチェックすると正しい答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    grid = []
    for _ in range(n):
        s = input().strip()
        mask = 0
        for i, c in enumerate(s):
            if c == '1':
                mask |= 1 << i
        grid.append(mask)

    q, num = map(int, input().split())

    decode = []
    for _ in range(1 << num):
        u, v = map(int, input().split())
        decode.append((u, v))

    ans_bits = 0
    answers = []
    last_mask = (1 << num) - 1

    def reachable():
        if (grid[0] & 1) == 0:
            return False

        reach = [0] * n
        reach[0] = 1

        while True:
            changed = False
            nxt = [0] * n

            for i in range(n):
                cur = reach[i]

                if i:
                    cur |= reach[i - 1]
                if i + 1 < n:
                    cur |= reach[i + 1]

                cur |= (reach[i] << 1)
                cur |= (reach[i] >> 1)

                cur &= grid[i]

                nxt[i] = cur
                if cur != reach[i]:
                    changed = True

            reach = nxt

            if not changed:
                return (reach[n - 1] >> (n - 1)) & 1 == 1

    out = []

    for _ in range(q):
        x, y = map(int, input().split())

        val = ans_bits
        ux, vy = decode[val]

        x += ux
        y += vy

        if x > n:
            x -= n
        if y > n:
            y -= n

        x -= 1
        y -= 1

        grid[x] ^= 1 << y

        ok = reachable()

        if ok:
            out.append("YES")
            bit = 1
        else:
            out.append("NO")
            bit = 0

        ans_bits = ((ans_bits << 1) | bit) & last_mask

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```グリッド表現は、実装の最初の重要な詳細です。 文字列を使用すると、すべての更新とすべての走査にコストがかかりますが、整数ビットマスクを使用すると、Python はネイティブの整数演算で多くのセル操作を実行できます。 

デコードステップでは最後のデータのみが保持されます。`num`と答える。 マスク操作は、ステートメントのローリング バイナリ表現に一致する古いビットを削除します。 

塗りつぶしは意図的に新しいものを作成します。`n`ラウンドごとの要素配列。 これにより、現在のラウンド中に発見されたセルとその前に存在していたセルが混合することを回避できます。これにより、BFS スタイルの不変条件が崩れます。 

宛先チェックでは 0 から始まる座標が使用されるため、最終セルはビットになります。`n-1`並んでいる`n-1`。 これはオフバイワンミスの一般的な原因です。

 ## 特殊なケース

 いつ`n = 1`、アルゴリズムは、唯一のセルを使用して到達可能なマスクを初期化します。 最終的な宛先チェックでは同じビットが読み取られるため、当然のことながら、そのセルがアクティブであるかどうかが答えになります。 

宛先がブロックされている場合、最終位置のビットは決して挿入されません。`reach`これは、すべての拡張ステップがアクティブ セルによってマスクされるためです。 したがって、最終チェックは返されます。`NO`。 

フリップによって 2 つの大きな領域間の唯一の接続が削除されると、次のフラッド フィルで到達可能なコンポーネントが最初から再計算されます。 以前の接続情報に依存しないため、削除後に古いパスを保持することができません。
