 ## 解決策
 ## 問題の理解

 タワーの高さの配列が与えられます。 それを左からスキャンし、以前のすべての値よりも厳密に大きい新しい最大値に遭遇するたびに記録することを想像してください。 これらの記録された値はシーケンスを形成します`L(h)`。 同じスキャンを右から実行すると、別のシーケンスが得られます`R(h)`右から左に移動するときに新しい最大値となる値で構成されます。 

たとえば、シーケンスでは、`L(h)`「左側のスカイライン」をキャプチャし、`R(h)`「正しいスカイライン」を捉えます。 

タスクはこれらのスカイラインを計算することではありません。 代わりに、元の配列のサブシーケンスが完全な配列とまったく同じ 2 つのスカイライン セットを生成する個数を数えなければなりません。 

サブシーケンスは、順序を維持しながら要素を削除することによって形成されます。 2 つのサブシーケンスは、異なるインデックスを使用している場合、結果の値が同じであっても異なります。 

したがって、制約は構造的なものです。要素を削除した後、サブシーケンスは元のシーケンスとまったく同じように左右の両方の極度の可視性パターンを保持する必要があります。 

この制約は、テスト ケース全体で最大 3×10^5 の合計要素にわたって答えを計算する必要があることを意味しているため、サブシーケンスを列挙したり、要素ごとに選択肢のペアを処理したりするソリューションは不可能です。 単一のテスト ケース内の二次関数はすべて、すでにすぐに失敗します。 

隠れた難しさは、条件が局所的ではないことです。 要素を削除すると、将来の「最高値」が双方向から変更される可能性があるため、単純な貪欲な削除は何も通知せずに失敗します。 

いくつかの具体的な失敗パターンは、これを説明するのに役立ちます。 

私たちが取るなら`[1, 3, 2]`、左側のスカイラインは`{1, 3}`。 削除中`2`スカイラインを変えずに保ちます。 しかし、`[1, 2, 3]`、削除`2`何も変わりません。 しかし、`[3, 1, 2]`、削除`1`どの要素が右から最大に表示されるかを変更します。 「最大値以外の要素は削除できる」などの単純なルールは、「最大値以外」は方向に依存するため失敗します。 

もう 1 つの微妙なケースは、値が繰り返されることです。 で`[2, 2, 2]`、最初だけ`2`に貢献する`L`ただし、重複を削除または保持するサブシーケンスは、厳密な最大値の比較で同点がどのように解釈されるかに応じて、等価条件を保持する場合と保持しない場合があります。 等しい値を交換可能なものとして扱う不注意な解決策は、正当性を損ないます。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべてのサブシーケンスを列挙し、その左右の可視最大値セットを計算し、それらを元の配列と比較し、一致する数をカウントします。 

長さの配列の場合`n`、 がある`2^n`後続。 サブシーケンスごとに、`L`そして`R`費用`O(n)`最悪の場合。 それは次のことにつながります`O(n·2^n)`たとえそれが不可能な操作`n = 30`。 

重要な観察は次のとおりです`L(h)`そして`R(h)`中間値ではなく、記録破りの最大値の位置のみに依存します。 元の配列のグローバル最大値構造を修正したら、有効なサブシーケンスは両端からスキャンしたときに新しい最大値が現れる正確な位置を保存する必要があります。 

これにより、問題は組み合わせカウントのタスクに変わります。元の配列内の連続する「臨界最大値」の間では、順序制約を除いて要素は無関係であり、そのような各要素は、いずれかの方向に新しい最大値が導入されない限り、可視性に影響を与えることなく含めることも除外することもできます。 

この構造は、各非クリティカル要素が二項選択に寄与する分解につながりますが、それは周囲の最大間隔によって定義された制約の下でのみです。 この解決策は、連続する左/右の最大値境界の間で要素をグループ化し、要素が両方向によって制約される場合の重複を慎重に処理しながら、各セグメントの独立した寄与を乗算することに帰着します。 

最終結果は、グローバル最大スケルトンに基づくセグメントごとのカウントの積になります。そのため、テスト ケースごとに線形時間でソリューションを評価できます。

 ## アルゴリズムのチュートリアル

 元の配列の構造を、左右のレコードの最大値に基づいて再構築します。 

1. コンピューティング`Lmax`左から右にスキャンするときに新しい最大値として表示される値のシーケンスとして。 これらは、配列の「左側に表示されるアンカー」です。 

これらの要素を削除するとすぐに変更されるため、これらの要素は有効なサブシーケンスに強制的に表示されます。`L`。 
2. コンピューティング`Rmax`同様に右から左にスキャンします。 これらは「右側に表示されるアンカー」です。 
3. いずれかに属する配列内のすべてのインデックスをマークします。`Lmax`または`Rmax`重要な立場として。 これらの要素は、保存する必要がある正確なスカイライン構造を定義するため、有効なサブシーケンスのバックボーンを形成します。 
4. 配列を連続する重要な位置の間のセグメントに分割します。 各セグメント内では、すべての要素は両側の隣接する最大値によって厳密に制限されます。つまり、禁止されている新しいレコードにならない限り、どちらのスカイラインにも影響を与えることはできません。 
5. セグメントごとに、スカイラインの制約に違反せずに独立して選択できる要素の数を数えます。 このような各要素は事実上オプションであり、要素を含めたり除外したりしてもプレフィックスやサフィックスの最大値は変わらないため、係数 2 に寄与します。 
6. すべてのセグメントからの寄与を 998244353 を法として乗算します。 

### なぜ効果があるのか

 不変条件は、有効なサブシーケンスのプレフィックス最大値とサフィックス最大値のセットが元の配列のものと正確に一致する必要があるということです。 これにより、記録破りの要素のいずれかを削除すると、導入時に見られた最大値が変更されるため、すべての記録破りの要素が強制的に存在することになります。 

これらのアンカーが修正されると、他のすべての要素は少なくとも 1 つの隣接する境界最大値よりも厳密に下に位置します。これは、包含に関係なく、どちらの方向にも新しいレコードを導入できないことを意味します。 したがって、これを含めることは多重度にのみ影響し、可視性構造には影響しません。 

セグメントは固定最大値によって区切られているため、異なるセグメント内の選択は相互作用せず、最終的なカウントはセグメント間で乗算されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # compute left maxima
        left_max = [False] * n
        cur = -1
        for i in range(n):
            if a[i] > cur:
                left_max[i] = True
                cur = a[i]

        # compute right maxima
        right_max = [False] * n
        cur = -1
        for i in range(n - 1, -1, -1):
            if a[i] > cur:
                right_max[i] = True
                cur = a[i]

        critical = [left_max[i] or right_max[i] for i in range(n)]

        ans = 1
        i = 0
        while i < n:
            if critical[i]:
                i += 1
                continue

            j = i
            while j < n and not critical[j]:
                j += 1

            length = j - i
            ans = (ans * pow(2, length, MOD)) % MOD
            i = j

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、アレイがクリティカル領域と非クリティカル領域に分離されます。 最初のパスでは、左右のスカイライン制約によってどの位置が必要であるかを計算します。 2 番目のパスでは、重要ではない要素を連続したブロックにグループ化し、ブロックごとに 2 の累乗を乗算します。 

唯一の微妙な点は、最大値を構築するときに厳密な比較を使用することです。 等しい場合は、新たに表示されるタワーは作成されないため、厳密に大きい値のみがスカイラインを更新します。

それぞれ係数 2 が寄与するため、答えは 4 になります。

 ## 特殊なケース

 単一要素の配列は、その要素が左と右の両方で最大であるため、常に完全にクリティカルです。 アルゴリズムは両方のスキャンでこれをクリティカルとして正しくマークし、答え 1 を生成します。 

厳密に増加する配列では、すべての要素が左最大値になるため、すべての位置が重要であり、選択肢に寄与するセグメントはありません。 アルゴリズムは正しく 1 を生成し、要素を削除すると変更されるという事実と一致します。`L(h)`。 

重複のある配列では、最初に出現した最大値のみがスカイライン構造に寄与します。 アルゴリズムが厳密な値を使用しているため、`>`比較では、重複によって最大値がリセットされず、繰り返される値の下でも正確さが保証されます。
