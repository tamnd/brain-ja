 ## 解決策
 ## 問題の理解

 このタスクは、整数に対する単純な数値変換を定義します。 任意の整数の場合$y$で示されるその桁の合計を考慮します。$d(y)$。 数字$y$指定された整数と互換性があると見なされます$x$桁の合計を引く場合$y$正確に収穫します$x$、 意味$y - d(y) = x$。 

各クエリ値について$x$、整数をいくつ数えるように求められます$y$この関係を満たします。 

重要な観察は次のとおりです$y$ステートメント内では明示的に狭い範囲に制限されません。 ただし、桁の合計は、数値自体に比べて非常にゆっくりと増加します。 もし$y$もっている$k$数字、その後$d(y) \le 9k$、 それで$y - d(y)$に非常に近いです$y$。 これは、固定の$x$、 有効$y$値は上の狭いウィンドウ内になければなりません$x$、おおよそ以内$x + 1$に$x + 9 \cdot \text{digits}(x)$。 

この構造は非常に重要です。すべての整数を検索するのではなく、候補はテスト ケースごとに最大でも数十個の値に分類されます。 

単純なアプローチでは、上向きに反復されます。$x$値が大きくなりすぎるまで状態を確認します。 これはすでに効率性を示唆していますが、さらに重要なのは、検索を厳密に制限できることです。 

正しさを理解するには、いくつかの特殊なケースが重要です。 

1つのケースは次のような場合です$x = 1$。 方程式は次のようになります$y - d(y) = 1$。 小さな値を試してみると、可能な最小の桁補正がすでにオフセットに対して大きすぎるため、解決策が存在しないことがわかります。 例えば、$y = 2$与える$2 - 2 = 0$、 そして$y = 10$与える$10 - 1 = 9$、1を完全にスキップします。 

もう一つの微妙なケースは次のような場合です。$x$大きく、多くのゼロで終わります。$998244360$。 ここで、有効です$y$値は依然として緊密にクラスター化されており、解決策は最後の桁に 1 桁を追加することのみに依存します。そのため、答えがちょうど 10 になることがよくあります。 

## アプローチ

 強引な解釈は次のようになります。$x$の値を増やしてみてください。$y$、桁の合計を計算し、一致をカウントします。 すべての候補が直接テストされるため、これは正しいですが、探索空間は概念的には無限です。 

ただし、関数の構造は、$f(y) = y - d(y)$局所的な偏差が小さいため、ほぼ単調になります。 増加中$y$増加する$f(y)$ただし、桁桁上げによって桁の合計が減少することがあり、解が広範囲に広がるのではなく、小さなクラスターが作成されます。 

重要な洞察は、条件を局所的に逆転させることです。 すべてをスキャンするのではなく、$y$、私たちは表現します$y$として$x + k$そして方程式を書き換えます:$$x + k - d(x + k) = x \Rightarrow k = d(x + k)$$それでオフセットは$k$の桁の合計と等しくなければなりません$x + k$。 桁の和は最大でも$9$桁数を掛けて、$k$に関連する小さな定数によって制限されます$x$。 つまり、上記の小さな範囲のみをテストする必要があるということです$x$、実際には通常は最大 100 個の値です。 

ブルート フォースは、テスト ケースごとの定数チェックに退化します。これは、大きな入力サイズには十分です。

 ## アルゴリズムのチュートリアル

 すべてを検索するのではなく、次のように方程式を再定式化します。$y$、上記の小さなオフセットを検索します$x$。 

1.読む$x$。 回答候補をフォームの数値として扱います$y = x + k$。 
2. すべての値を試します$k$たとえば 0 から 100 までの小さな固定範囲です。 

上限は、9 桁の数値の場合、桁の合計が数十を超えることはないという事実に基づいています。 
3. それぞれについて$k$、計算する$y = x + k$。 
4. 桁の合計を計算します。$d(y)$。 
5. かどうかを確認します。$y - d(y) = x$。 当てはまる場合は、これを数えてください$y$。 
6. この合計数を出力します。$x$。 

有界な範囲のみが必要な理由は、次のような場合です。$k$大きくなり、その後$d(x + k) \le 9 \cdot \text{digits}(x + k)$は対数的に増加しますが、$k$直線的に成長します。 最終的には平等$k = d(x+k)$不可能になります。 

### なぜ効果があるのか

 正しさは、有効な解決策が次の条件を満たす必要があるという事実に基づいています。$k = d(x+k)$。 数値と次の桁の合計$m$最大でも桁数は$9m$、 それで$k$桁数に関連付けられた小さな定数を超えることはできません$x$。 これにより、すべての解が上記のコンパクトな間隔内に収まることが保証されます。$x$、検索を制限することで有効な候補が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digit_sum(n: int) -> int:
    s = 0
    while n:
        s += n % 10
        n //= 10
    return s

t = int(input())
for _ in range(t):
    x = int(input())
    ans = 0

    for k in range(0, 200):
        y = x + k
        if y - digit_sum(y) == x:
            ans += 1

    print(ans)
```桁合計関数は、文字列変換によるオーバーヘッドを回避するために反復的に行われます。 メイン ループは 200 という控えめな境界を使用します。これは、最大入力サイズに対して考えられるすべての桁上げと桁の合計の相互作用を安全にカバーします。 

重要な実装の詳細は、上限を数学的に厳しくしようとしていないことです。 10 桁の数値の最大桁数の合計は 90 であるため、90 を十分に超える定数は機能します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def digit_sum(n):

            s += n % 10
            n //= 10

## 特殊なケース

 のために$x = 1$、アルゴリズムがチェックします$y$1から上へ。 どの候補者も失敗する$y - d(y) = 1$、ループは正しくゼロを生成します。 重要な点は、たとえ$y = 10$桁上げが導入されていますが、桁合計の調整は依然として等価性を満たすには大きすぎます。 

のような値の場合$x = 998244360$、有効な解決策は次の場合にのみ発生します。$y$は、桁の合計を揃えながら最後の桁のブロックを増やすことによって形成されます。 ループが小さい$k$は、最後の桁のみが制御された量だけ桁の合計を変更するため、これら 10 個の値を正確に取得します。
