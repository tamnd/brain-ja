 ## 解決策
 ## 問題の理解

 2 行の長方形グリッドが与えられ、$n$列、および複数のセット$2n$セルの値を表す数値。 これらの値をグリッド全体で任意に並べ替えることができます。 

「カメ」は左上のセルから開始し、右下のセルに到達するまで右または下にのみ移動します。 パスに沿って、訪問したセルの値の合計を収集します。 ただし、すべての単調なパスの中でこの合計が最大になるパスを常に選択するという意味で、タートルは敵対的です。 

私たちの仕事は、タートルが選択した最善のパスの合計ができるだけ小さくなるように、グリッド内の数値を再配置することです。 

したがって、相互作用は次のようになります。最初に配置を選択し、次にタートルが収集した合計を最大化するパスを選択し、その結果の値を最小化したいと考えます。 

制約は十分に小さいため、解決策は次のとおりです。$O(n \log n)$が予想されます。 すべての順列、さらにはすべてのグリッド構成を調査しようとする試みは、配置の数が膨大であるため、直ちに実行不可能になります。$(2n)!$、これは、たとえ控えめな値であっても、計算可能な限界をはるかに超えて増加します。$n$。 配置ごとにすべてのパスをシミュレートする場合でも、別の要素が追加されます。$O(n)$、ブルートフォースは完全に不可能になります。 

微妙な点は、タートルの最適なパス構造は、上の行から下の行に切り替わる場所に大きく依存することです。 有効なパスは、ある列まで完全に上の行に留まってから一度ドロップするか、対称的に最初に下の行に留まってから切り替わります。 この構造が問題に組み合わせの圧力を生み出すのです。 

一般的な失敗例は、値が「局所的には最適化」されているものの、全体的には悪い場合に発生します。 たとえば、大きな値を 1 行に配置するのは安全であるように見えますが、タートルはパスのほとんどでその行を経由することができます。 もう 1 つの失敗例は、プレフィックスの合計を考慮せずに大きな値と小さな値を交互に使用することです。これにより、タートルは最も大きな値を取得するスイッチ ポイントを選択することができます。 

## アプローチ

 強引なアイデアは単純です。つまり、次のすべての順列を生成します。$2n$値を取得してグリッドに配置し、タートルが達成できる最大パス合計を計算します。 固定グリッドの場合、最適なパスを計算できます。$O(n)$すべての列を行間の切り替えポイントとして試してみます。 これにより、全体的な複雑さは次のようになります。$O((2n)! \cdot n)$であってもすぐに難治になってしまいます。$n = 10$階乗増加がすべてを支配するためです。 

重要な観察は、パス構造が非常に制限されていることです。 最適なパスは、行を切り替える 1 つの列によって決まります。 グリッドを固定する場合、最適なパス値はすべての分割点の最大値になります。$k$2 つの式のうち、行 1 を右に進み、次まで$k$次に 2 列を最後まで、または逆方向に並べます。 これにより、パスの問題がプレフィックスとサフィックスの合計の評価に軽減されます。 

これが明確になったら、残りの問題は、分割点によって過度に大きな合計が生成されないように値を配置する方法です。 タートルは常に、私たちの配置に対して考えられる最悪の分割を選択するため、潜在的なプレフィックスとサフィックスの組み合わせをすべて「平滑化」したいと考えています。 

重要な構造的洞察は、重要なのはローカルな隣接性ではなく、値のグローバルな順序付けであるということです。 値を並べ替えることで、プレフィックスに蓄積される大きな要素を制御できるようになります。 最適な構築は、最終的には単調な分離になります。小さな値は、タートルが 1 つの行に強制できるすべてのプレフィックスを支配する必要がありますが、大きな値は、単一のパスが収集しすぎることを防ぐ方法で行全体に分割されるように配置する必要があります。 

これは、すべてを分類する構造につながります。$2n$値を設定し、「バランスの取れた反対の順序」で配分します。つまり、上の行は昇順で埋められ、下の行は降順で埋められます。 これにより、上の行のプレフィックスは下の行の比較的大きなサフィックス値とペアになり、その逆も行われるため、パスが両方のセグメントで大きな値を一貫して収集することがなくなります。

 ## アルゴリズムのチュートリアル

 1.すべて集める$2n$2 つの入力行の値を 1 つの配列に変換します。 これにより、グリッドの順序を完全に変更できるため、初期レイアウトへの依存がなくなりました。 
2. 配列を降順でない順に並べ替えます。 その目的は、どの値が「危険」 (大きい) でどの値が安全 (小さい) かを推論できるように、グローバル ランキングを課すことです。 
3. 最初の行を左から右に最小値を使用して埋めます。$n$値を昇順に並べます。 これにより、一番上の行のプレフィックスが徐々に増加し、タートルが行を切り替える前に悪用する可能性のある大きなスパイクが含まれないことが保証されます。 
4. 最大の行を左から右に入力します。$n$値は降順で表示されます。 この逆転は、最下行の 1 つのプレフィックスが連続セグメントに多数の大きな値を集中させてしまうのを防ぐため重要です。そうしないと、ドミナント パスが作成されます。 
5. 結果のグリッドを出力します。 

この配置の背後にある理由は、すべての有効なパスがグリッドを一方の行のプレフィックス セグメントともう一方の行のサフィックス セグメントに分割するためです。 小さい値と大きい値を逆の単調方向に分離することで、パスに大きな連続ブロックが蓄積されるのではなく、そのような分割で低い値と高い値が混在するようになります。 

### なぜ効果があるのか

 キーの不変条件は、どの列でも同じです。$k$、パスがスイッチングによって収集できる値の合計$k$は、ソートされた 1 つのシーケンスのプレフィックスと、別の逆の順序のシーケンスのサフィックスの組み合わせによって制限されます。 一方の行は増加し、もう一方の行は減少しているため、プレフィックスとサフィックスのペアは本質的に、大きな値と小さな値のバランスが取れています。 これにより、パスの両方の部分に多くの大きな要素が同時に含まれる分割点の存在が防止されます。 

タートルは常にそのようなすべての分割の最大値を選択するため、私たちの構築ではすべての候補分割値が可能な限り均一に保たれることが保証され、その結果、達成可能な最大パス合計が最小化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    vals = a + b
    vals.sort()
    
    top = vals[:n]
    bottom = vals[n:]
    
    # top increasing
    row1 = top
    
    # bottom decreasing
    row2 = bottom[::-1]
    
    print(*row1)
    print(*row2)

if __name__ == "__main__":
    solve()
```実装は建設的なアイデアに直接従います。 唯一の微妙な点は、並べ替え後に正しい分割を確実に行うことです。$n$要素は一番上の行に移動し、最大の要素が$n$逆の順序で下の行に移動します。 逆転は不可欠だ。 これがないと、大きな値がクラスター化して 2 行目に強力なプレフィックス合計が作成され、タートルが遅延スイッチを介してこれを悪用する可能性があります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が等しい場合です。 その状況では、すべての配置は同等であり、カメの進路の選択は無関係になります。 並べ替えによってマルチセット構造が変更されず、両方の行の分散が同一のままであるため、アルゴリズムはこのプロパティを保持します。 

もう 1 つの特殊なケースは、多数の小さな値の中に 1 つの非常に大きな値がある場合です。 単純に配置すると、行の先頭に大きな値が配置され、タートルがすべてのパスにその値を取り込む可能性があります。 構築されたソリューションでは、反転により最大値が下の行の最後に配置され、タートルが他の利益を犠牲にする特定の分割にコミットした場合にのみその値がキャプチャされることが保証されます。 

最後の微妙なケースは、値が高度にクラスター化されている場合です。たとえば、多数の等しい中間値といくつかの極端な値です。 ソートされた分割では、行全体で極端な値が分離されることが保証され、単一のプレフィックスとサフィックスの組み合わせが分布の両端に同時に蓄積されるのを防ぎます。
