 ## 解決策
 ## 問題の理解

 Vanya は、三角形の数字で表されるパターンを正確に使用してピラミッドを構築したいと考えています。 最初のレベルには 1 つの立方体が含まれます。 2 番目のレベルには 1 + 2 = 3 個の立方体が含まれます。 3 番目のレベルには 1 + 2 + 3 = 6 個の立方体が含まれています。 一般的にはレベル`i`最初の合計が必要です`i`正の整数。 

利用可能なキューブの総数が与えられています。`n`。 私たちの仕事は、キューブがなくなる前に構築できる完全なレベルの最大数を決定することです。 

制約は非常に小さいです。 キューブの数は最大で`10^4`これは、単純なシミュレーションでも十分に高速であることを意味します。 構築できるレベルの数は、`10^4`新しいレベルごとに、前のレベルよりも多くのキューブが必要になるためです。 単純な反復ソリューションは、制限内に簡単に収まります。 

よくある間違いは、各レベル自体が三角数であることを忘れていることです。 

考慮する：```
Input:
4
```最初のレベルは 1 つのキューブを使用し、2 番目のレベルは 3 つのキューブを使用します。 これらを合わせると 4 つの立方体が必要になるため、答えは次のようになります。```
2
```不注意な実装により、レベルが誤って想定される可能性があります`i`まさに必要です`i`立方体にして 3 を返します。 

もう 1 つの微妙なケースは、レベルを終了した直後にキューブがなくなった場合に発生します。```
Input:
10
```レベルには 1、3、6 個のキューブが必要です。 

合計は次のとおりです。```
1 + 3 + 6 = 10
```正しい答えは次のとおりです。```
3
```完了したレベルをカウントする前に、残りのキューブがゼロになるとすぐに停止する実装は、誤って 2 を返します。 

## アプローチ

 最も直接的なアイデアは、レベルごとにピラミッドを構築することです。 レベルごとに、そのレベルに必要なキューブの数を計算し、残りの供給量からそれを差し引き、十分なキューブが残っている間続行します。 

この総当たりシミュレーションはすでに十分に高速です。 以来`n ≤ 10000`、レベルの数は少ないです。 三角数の計算を繰り返しても、その作業量は無視できます。 

重要な観察は、レベルに必要なキューブの数です。`i`自体は三角数です。$$1 + 2 + \cdots + i = \frac{i(i+1)}{2}$$したがって、ピラミッドを構築している間、現在のレベルとそれに必要なキューブを追跡するだけで済みます。 次のレベルに余裕がある場合は、そのコストを差し引いて高さを上げます。 

レベルは順番に構築する必要があり、各レベルには固定コストがあるため、有効な構築は可能な限り上から順に貪欲にレベルを取得することだけです。 次のレベルに上がる余裕がなくなった瞬間、これより高いピラミッドは存在できなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(h²) | お(1) | 承認済み |
 | 最適なシミュレーション | O(h) | お(1) | 承認済み |

 ここ`h`は最終的なピラミッドの高さで、最大でも約 30 です。`n ≤ 10000`。 

## アルゴリズムのチュートリアル

 1. 利用可能なキューブの数を読み取ります。`n`。 
2.初期化`height = 0`。 
3.初期化`level = 1`。 
4. 以下を使用して、現在のレベルに必要なキューブの数を計算します。$$\frac{\text{level}(\text{level}+1)}{2}$$5. 十分なキューブが残っている場合は、その量を減算します。`n`、 増加`height`、次のレベルに移動します。 

これは、ピラミッドのもう 1 つの層を正常に完了することに相当します。 
6. 次のレベルで使用可能なキューブの数を超えるまで繰り返します。 
7. 出力`height`。 

### なぜ効果があるのか

 すべての反復で、アルゴリズムは 1 から 1 までのすべてのレベルの不変条件を維持します。`height`完全に構築されており、残りの価値は`n`構築後に残ったキューブに等しい。 

次に可能なアクションは一意に決定されます。つまり、次のレベルを完了できるか、完了できないかのどちらかです。 可能であれば、それを建設すると高さが 1 つ増加します。 それができない場合、より高いピラミッドも同じ未完成のレベルを必要とすることになりますが、それは不可能です。 したがって、アルゴリズムは達成可能な最大の高さで正確に停止します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

height = 0
level = 1

while True:
    need = level * (level + 1) // 2

    if n < need:
        break

    n -= need
    height += 1
    level += 1

print(height)
```変数`level`は、構築しようとしている次の層を表します。 表現```
level * (level + 1) // 2
```そのレベルの三角数を計算します。 

十分なキューブが残っている場合は常に、それらのキューブを消費して、完了したレベルをもう 1 つ記録します。 ループは、次に必要な層が完了できない時点で終了します。 

最も一般的な 1 つ違いの間違いは、インクリメントです。`level`コストを計算する前に。 そうすると、サイズ 1 の最初のレイヤーがスキップされます。もう 1 つのよくある間違いは、次のレベルが手頃かどうかを確認する代わりに、残りのキューブがゼロであるかどうかを確認することです。 などの正確なフィット感`n = 10`最終的に完了したレベルもカウントする必要があります。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    n = int(input())

    height = 0
    level = 1

    while True:
        need = level * (level + 1) // 2

        if n < need:
            break

        n -= need
        height += 1
        level += 1

    print(height)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("1\n") == "1\n", "sample 1"

# custom cases
assert run("4\n") == "2\n", "exactly two levels"
assert run("10\n") == "3\n", "exactly three levels"
assert run("19\n") == "3\n", "just short of fourth level"
assert run("10000\n") == "21\n", "maximum input range"
```| テスト入力 | 期待される出力 | 検証内容 |
