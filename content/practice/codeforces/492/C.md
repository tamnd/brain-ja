[CF 492C - ヴァーニャと試験](https://codeforces.com/problemset/problem/492/C)

 **評価:** 1400
 **タグ:** 貪欲、並べ替え
 **解決時間:** 57 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 Vanya には多数の試験があり、それぞれの試験は 1 点から最高点 _r_ の間で採点されます。 彼は、奨学金の資格を得るために、全体の平均が少なくとも _avg_ に達することを望んでいます。 各試験では、エッセイを書くことでスコアを向上させることができますが、1 ポイントずつ成績を上げるための費用は試験ごとに異なります。 目標は、必要な平均値に達するために書かなければならないエッセイの総数を最小限に抑えることです。 

入力により、試験の数 _n_、最高成績 _r_、および必要な平均 _avg_ が得られます。 各試験には、現在の成績と、増加点ごとに必要なエッセイの数という 2 つの数値が表示されます。 出力は単一の整数、つまり必要な最小合計エッセイである必要があります。 

制約は重要です。 _n_ が 10^5 まで、_r_ が 10^9 まである場合、O(n log n) よりも複雑なアルゴリズムはタイムアウトになる危険性があります。 たとえば、可能なすべてのグレードの増加を明示的に繰り返すと、時間がかかりすぎます。 また、_b_i_ は 10^6 まで大きくなる可能性があるため、単純な合計を使用する場合は整数のオーバーフローを避けるためにエッセイのコストを慎重に考慮する必要があります。 

エッジケースは微妙な場合があります。 1 つは、現在の平均がすでに _avg_ を満たすか超えている場合です。この場合、エッセイは必要ありません。 もう 1 つは、一部の試験がすでに最大評点 _r_ に達しており、アルゴリズムがそれ以上の評点を上げようとすることを回避する必要がある場合です。 不用意に実装すると、エッセイのコストを無視して常にインデックス順に成績を上げようとし、最適ではない解決策が得られる可能性があります。 たとえば、次のような場合です。```
2 5 5
5 10
3 1
```Vanya はすでに合計 8 ポイントを持っており、10 ポイントが必要なので、最初の試験も最大点であるにもかかわらず、2 番目の試験だけを 2 ポイント増やす必要があります。 試験を入力順に盲目的に処理する単純なアプローチは失敗する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、必要な合計スコアに達するまで、すべての試験で可能なあらゆる増分が考慮されます。 増分ごとに、対応するエッセイのコストを追加し、合計平均が十分になった時点で停止します。 原理的には正しいですが、最悪の場合の演算数は O(n*r) に達する可能性があり、この問題では最大 10^14 に達します。これは明らかに実行不可能です。 

重要な点は、1 点あたりのエッセイの費用は試験ごとに異なるため、エッセイの費用はできるだけ少なくしたいということです。 したがって、1 点あたりのエッセイの数が少ない試験で成績を上げることを優先する必要があります。 試験をエッセイの費用で並べ替えることで、最初に最も安価な増分を貪欲に選択することができます。 並べ替えた後、必要なだけ、または最高評点に達するまで、試験を繰り返します。 成績の合計が _n × avg_ を満たすかそれを超えるまで続けます。 これにより、ソートにより複雑さが O(n log n) に軽減され、入力制限に対して十分に効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*r) | O(n) | 遅すぎる |
 | 貪欲にコストで並べ替え | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. Vanya が現在持っている成績の合計を計算します。 これをそのままにしておきます`current_sum`。 
2. 希望の平均に達するために必要な合計ポイントを計算します。`required_sum = n * avg`。 
3. もし`current_sum >= required_sum`、エッセイは必要ないので、0を出力して終了します。 
4. 各試験の現在の成績とエッセイの費用を組み合わせます。 これらのペアをエッセイコストで昇順に並べ替えます。 これにより、常に最も安価な増分が最初に選択されるようになります。 
5.初期化`essays = 0`そして`needed = required_sum - current_sum`。 
6. 並べ替えられた試験を繰り返します。 試験ごとに、可能な最大増加量を計算します。`increase = min(r - grade, needed)`。 
7.追加`increase * essay_cost`に`essays`。 減算`increase`から`needed`。 
8. もし`needed`ゼロに達するとループが終了します。 合計を出力する`essays`。 

**なぜ効果があるのか**

 1 点あたりの小論文コストは試験ごとに固定されているため、この貪欲な方法は正しいです。 エッセイの合計を最小限に抑えるには、最適なソリューションでは常に、ポイント増加ごとに費やすエッセイをできるだけ少なくする必要があります。 コスト順に並べ替えると、追加したすべてのポイントが利用可能な中で最も安いことが保証されます。 アルゴリズムは各ステップで不変条件を維持します。`needed`は必要な残りのポイント数であり、費やされる合計エッセイは、これまでに実行された増分に対して最小限です。 一度`needed`がゼロの場合、平均要件は満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, r, avg = map(int, input().split())
exams = [tuple(map(int, input().split())) for _ in range(n)]

current_sum = sum(grade for grade, _ in exams)
required_sum = n * avg

if current_sum >= required_sum:
    print(0)
    sys.exit()

# sort exams by essay cost
exams.sort(key=lambda x: x[1])

needed = required_sum - current_sum
essays = 0

for grade, cost in exams:
    increase = min(r - grade, needed)
    essays += increase * cost
    needed -= increase
    if needed == 0:
        break

print(essays)
```コードはまず、必要な平均に達するために不足している合計ポイント数を計算します。 試験をコスト別に分類することで、各エッセイの支出が可能な限り効率的に行われるようになります。 の`min(r - grade, needed)`このラインは、最大勾配を超えたり、必要なポイントをオーバーシュートしたりすることがないことを保証します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 並べ替え試験が実行時間の大半を占めます。 
| スペース | O(n) | 試験のリストを保存する |

 n が最大 10^5 の場合、O(n log n) 操作は 1 秒の制限内に問題なく収まります。 メモリ使用量も 256 MB を大幅に下回っています。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, r, avg = map(int, input().split())
    exams = [tuple(map(int, input().split())) for _ in range(n)]

    current_sum = sum(grade for grade, _ in exams)
    required_sum = n * avg

    if current_sum >= required_sum:
        return "0"

    exams.sort(key=lambda x: x[1])
    needed = required_sum - current_sum
    essays = 0

    for grade, cost in exams:
        increase = min(r - grade, needed)
        essays += increase * cost
        needed -= increase
        if needed == 0:
            break

    return str(essays)

# provided samples
assert run("5 5 4\n5 2\n4 7\n3 1\n3 2\n2 5\n") == "4"
assert run("2 5 2\n5 10\n3 1\n") == "0"

# custom cases
assert run("1 5 5\n5 1\n") == "0", "single exam already enough"
assert run("3 10 10\n10 3\n9 2\n8 1\n") == "3", "needs minimal increases on cheapest exam"
assert run("2 1000000000 1000000000\n1 1\n1 1\n") == str(1999999998), "max r and avg"
assert run("4 10 7\n7 5\n6 1\n5 1\n4 2\n") == "4", "mixed costs, must choose cheapest first"

 | 2 10^9 10^9\n1 1\n1 1 | 1999999998 | オーバーフローせずに大きな数値を処理します。
