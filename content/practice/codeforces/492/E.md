 ## 解決策
 ## 問題の理解

 フィールドを表す _n_ × _n_ グリッドが与えられ、特定のセルに _m_ 個のリンゴの木が配置されます。 Vanya はあるセルから開始し、固定ベクトル (_dx_, _dy_) に沿って離散時間ステップで移動し、トロイダル状にグリッドの周囲を包み込みます (つまり、位置は _n_ を法として取得されます)。 彼はすでに訪れた独房に戻ると動きを止めた。 

タスクは、Vanya がこの軌道に沿ってリンゴの木の最大数を確認できる開始セルを決定することです。 複数のツリーが同じセルを占有することができ、複数の開始セルが最大値に達する可能性があるため、それらのいずれも出力として受け入れられます。 

制約は厳密です。_n_ は最大 10^6、_m_ は最大 10^5 であり、O(n^2) 個の解を避ける必要があります。 軌道あたりのステップ数は _n_ に比例する可能性があり、_n^2_ 通りの開始が可能であるため、考えられるすべての開始セルからの直接シミュレーションは実行できません。 これには、考慮すべき個別のパスの数を減らすアルゴリズムが必要です。 

動きベクトルが _n_ と互いに素でない場合、微妙なエッジ ケースが発生します。 この場合、Vanya の軌跡はすべてのセルのサブセットのみを訪問することになり、すべてのパスを個別にシミュレートしようとする単純な試みはこれを見逃したり、冗長な作業を実行したりすることになります。 

たとえば、_n_ = 4、_dx_ = 2、_dy_ = 2、および (0,0) にある 1 つのリンゴについて考えてみましょう。 不用意なシミュレーションはすべてのセルを反復する可能性がありますが、同じ剰余モジュロ gcd(dx,n) または gcd(dy,n) 上にない開始は (0,0) に到達しません。 正しい出力は、剰余クラス (0,0) モジュロ 2 内の任意のセルになります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのセルから開始する Vanya をシミュレートし、それが繰り返されるまで軌跡を追跡します。 それぞれの軌跡について、遭遇したリンゴの数を合計します。 すべての開始セルが有限で決定的なパスを生成するため、これは原理的には正しいです。 ただし、最大軌道長は n / gcd(dx, n) * n / gcd(dy, n) であり、最悪の場合は n^2 に近づく可能性があります。 n が 10^6 までになると、演算の数が管理できなくなり、このアプローチは O(n^2) となり、非常に遅くなります。 

重要な観察は、軌道構造が非常に規則的であるということです。 Vanya は _n_ を法とするベクトル (_dx_, _dy_) で移動するため、パスは最大公約数 _g_ = gcd(dx, dy, n) によって決定される周期で繰り返されます。 各セルをサイズ g × g の小さな「残差グリッド」にマッピングできます。ここで、各残差クラスは、軌道に沿った両次元で _n/g_ を法とする等価なすべてのセルを表します。 各剰余クラス内で、軌道はすべてのセルを正確に 1 回訪問します。 したがって、これらの短縮された軌道に沿ってリンゴの合計を計算し、最大値を選択するだけで済みます。 

この削減により、問題は O(n^2) パスのシミュレーションから、それぞれが n^2 / g^2 セルを訪問する O(g^2) 軌道の計算へと変わります。 実際には、g は最大でも n であるため、合計の操作はおよそ O(m + g^2) になります (m はツリーの数)。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n^2) | 遅すぎる |
 | 最適 | O(m + n) | O(m + n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 移動ベクトルとフィールド サイズの最大公約数を計算します。`g = gcd(dx, dy, n)`。 これにより、グリッドが軌跡が含まれる g × g 残差クラスに分割されます。 
2. 各リンゴの木をその残基クラスにマッピングします。`(xi % g, yi % g)`。 クラスごとに、そのクラスに該当するすべてのリンゴ座標のリストを維持します。 このマッピングの理由は、同じ剰余クラスで始まる軌跡は同じパターンに従い、他のクラスと相互作用しないためです。 
3. 残基クラスごとに、軌道の長さを決定します。 これは`l = n / g`、パスが両方の軸に沿って法 n を繰り返すまでのステップ数。 各軌道は長さ l の周期的です。 
4. 残基クラス内のセルの循環シーケンスに沿って「ウィンドウ」をスライドさせます。 l を法とする各可能な開始位置にあるリンゴの数を合計します。 この合計が最大になる開始位置を追跡してください。 
5. 元のグリッドに沿って最初に出現する残基を選択することにより、最適な残基位置を実際の座標に戻します。 同じ剰余クラス内のすべての位置が軌道法 n の下で等価であるため、有効な変換はどれでも受け入れられます。 
6. 検出された最大のリンゴの座標を返します。 

これが機能する理由: 不変条件は、同じ剰余クラス内のすべての軌跡が n を法として同一であり、軌跡内のすべてのセルが反復前に 1 回だけ訪問されることです。 フィールドを剰余クラスに削減することで、すべての個別の軌跡を正確に 1 回考慮し、すべてのリンゴを考慮することが保証されます。 

## Python ソリューション```python
import sys
from math import gcd
input = sys.stdin.readline

n, m, dx, dy = map(int, input().split())
apples = [tuple(map(int, input().split())) for _ in range(m)]

g = gcd(dx, dy)
residue = {}

for x, y in apples:
    key = (x % g, y % g)
    if key not in residue:
        residue[key] = []
    residue[key].append((x, y))

best_count = -1
best_pos = (0, 0)

for (rx, ry), cells in residue.items():
    l = n // g
    # build counts along the trajectory
    counts = [0] * l
    for x, y in cells:
        # map to trajectory index
        ix = (x - rx) // g
        iy = (y - ry) // g
        idx = (ix * dy // g - iy * dx // g) % l
        counts[idx] += 1
    # find maximum
    max_idx = counts.index(max(counts))
    count = counts[max_idx]
    if count > best_count:
        best_count = count
        best_pos = (rx + max_idx * dx // g, ry + max_idx * dy // g)

print(best_pos[0], best_pos[1])
```説明: まずリンゴを残基クラスごとに分割します。`(x % g, y % g)`同じクラス内のすべてのセルは、軌道の下では同等であるためです。 counts 配列は、軌道ステップを観察されたリンゴの数にマッピングします。 各リンゴの軌道に沿ってインデックスを計算し、効率的に個数を構築します。 最も多くのリンゴが表示されるステップを選択し、次のようにスケーリングすることで実際の開始座標を再構築します。`dx/g`そして`dy/g`。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m + n) | 各リンゴは 1 回処理され、残差が割り当てられます。 各残差軌跡は長さ ≤ n で、リンゴごとに O(1) で処理されます。 |
