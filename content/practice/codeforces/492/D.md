 ## 解決策
 ## 問題の理解

 2 人のプレイヤーが一連のモンスターを攻撃しています。 各モンスターにはヒット時の体力値があり、死ぬまでに多くの個別の攻撃が必要であることを意味します。 攻撃は恣意的にインターリーブされるわけではありません。 代わりに、2 人のプレーヤーは完全に一定の間隔で打撃を行いました。 毎回 1 人のプレイヤーがヒットを生み出す$1/x$秒、もう一方は毎$1/y$秒。 どちらも時間 0 で開始するため、それらのヒット時間は実際のタイムライン上で 2 つの無限の等差数列を形成します。 

各モンスターについて、それがいつ死ぬかを尋ねるのではなく、その健康要件を完了する最後の攻撃を誰が実行するかを尋ねます。 両方のプレイヤーがまったく同じ瞬間に攻撃を当て、その攻撃でモンスターを仕留めた場合、答えは共有されます。 

重要な隠された構造は、プロセス全体が 2 つのソートされたイベント時間シーケンスを結合することに相当しますが、実際の時間値ではなく、結合されたシーケンスの順序のみが重要であるということです。 各ヒットは、2 つの定期スケジュールから抽出された、グローバルにソートされた時刻リスト内の次のイベントにすぎません。 

制約により、最大で$10^5$したがって、すべてのモンスターにわたるすべてのヒットをシミュレートするソリューションは不可能です。 中程度の場合でも$x$そして$y$、すべてのモンスターの合計ヒット数が到達可能$10^9$したがって、ヒットごとのシミュレーションは直ちに除外されます。 の身元を特定する方法が必要です$a_i$シーケンスを生成せずにマージされたシーケンス内の - 番目のイベント。 

微妙なエッジケースは、等しいタイミングの衝突から発生します。 もし$x = y$、すべてのヒットは同時に発生するため、すべてのモンスターは「両方」を出力する必要があります。 もう 1 つのエッジ ケースは、一方の周波数が他方よりもはるかに大きい場合に発生します。この場合、周期の最小公倍数の共有倍数を除いて、ほとんどすべてのヒットが 1 人のプレーヤーに属します。 

単純な間違いは、$a_i$- 時間を前方にスキャンすることにより、モンスターごとに個別にヒットします。 モンスターごとに最適化したとしても、各スキャンは線形であるため、これは失敗します。$a_i$、それは可能です$10^9$。 

## アプローチ

 直接シミュレーションのアプローチでは、2 つのポインターを維持し、それぞれが Vanya と Vova の次のヒット時間を生成し、早い方を繰り返し選択します。 これにより、マージされたシーケンスが正しく構築されます。 ただし、これを最大限までやると、$a_i$、複雑さはすべてのモンスターの体力の合計に比例し、限界をはるかに超えています。 

重要な観察は、実際にはリアルタイム値が必要ないということです。 必要なのはヒットの相対的な順序だけです。 いつでも、次のヒットは、次の予定時間が短いプレイヤーから生まれます。 これにより、問題は次の倍数を比較することになります。$1/x$そして$1/y$、これは、次の倍数をマージしたシーケンス内の整数を比較することと同等です。$x$そして$y$彼らの製品によって時間を計るとします。 

シーケンスを明示的に生成する代わりに、時間を二分探索することができます。$t$。 一定時間内に発生したヒット数をカウントできます。$\lfloor t \cdot x \rfloor + \lfloor t \cdot y \rfloor$を使用して公倍数の二重カウントを修正します。$\lfloor t \cdot \text{lcm}(x, y) \rfloor$。 これにより単調関数が得られ、少なくとも次の条件を満たす最小時間を見つけることができます。$a_i$ヒットが発生しました。 

その時間を見つけたら、可分性条件をチェックして、それが Vanya のスケジュールに属するか、Vova のスケジュールに属するか、あるいはその両方に属するかを判断します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | シミュレーション |$O(\sum a_i)$|$O(1)$| 遅すぎる |
 | モンスターごとの二分探索 |$O(n \log A)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 次の最小公倍数を事前計算します。$x$そして$y$。 これは、両方のプレーヤーが同時にヒットした瞬間を表しており、二重カウントを避けるために必要です。 
2. 各モンスターの健康を治療します。$a_i$クエリとして次のように尋ねます。$a_i$- 番目のヒットはマージされたシーケンスで発生しますか?
 3. 時間をかけて二分探索を使用する$t$。 評価する関数は、これまでに発生したヒット数です。$t$。 次のように計算します。$$f(t) = \left\lfloor t \cdot x \right\rfloor + \left\lfloor t \cdot y \right\rfloor - \left\lfloor t \cdot \text{lcm}(x,y) \right\rfloor$$これにより、同時ヒットを二重にカウントすることなく、両方のプレーヤーからのすべてのヒットが正しくカウントされます。 
4. 最小の二分探索$t$そのような$f(t) \ge a_i$。 これにより、$a_i$- 番目のヒットはこの時点またはそれより前に発生します。 
5. 見つけたら$t$、最後のヒットの所有権を決定します。 

- もし$t$両方で割り切れます$1/x$そして$1/y$(同様に、$t$は両方の期間の倍数です)、「両方」と出力します。 
- それ以外の場合$t$Vanya のヒット時間に対応し、「Vanya」と出力されます。 
- それ以外の場合は「Vova」を出力します。 
6. すべてのモンスターに対して個別に繰り返します。 

### なぜ効果があるのか

 ヒットのプロセスはイベント時間の厳密に増加するシーケンスを形成し、すべてのイベントは Vanya、Vova、またはその両方によって同時に一意に決定されます。 カウント機能$f(t)$時間の経過とともにヒットが蓄積されるだけであるため、時間の経過とともに単調になります。 したがって、二分探索では、正確な時間インデックスが分離されます。$a_i$- 番目のイベントが発生します。 同時イベントは二重カウントから削除されますが、その後の同一性チェックでは保持されるため、分類は元のマージされたシーケンスと一貫したままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def lcm(a, b):
    return a // gcd(a, b) * b

def count(t, x, y, l):
    return t // x + t // y - t // l

def solve_one(k, x, y, l):
    lo, hi = 1, 10**18

    while lo < hi:
        mid = (lo + hi) // 2
        if count(mid, x, y, l) >= k:
            hi = mid
        else:
            lo = mid + 1

    t = lo

    # classify the hit at time t
    is_x = (t % x == 0)
    is_y = (t % y == 0)

    if is_x and is_y:
        return "Both"
    if is_x:
        return "Vanya"
    return "Vova"

def main():
    n, x, y = map(int, input().split())
    l = lcm(x, y)

    for _ in range(n):
        k = int(input())
        print(solve_one(k, x, y, l))

if __name__ == "__main__":
    main()
```コードはまず、2 つの周期シーケンス間の相互作用を 1 つのカウント関数に縮小します。 ヘルパーさん`count`これまでに発生したヒット数を計算します`t`、LCM の倍数で重複部分を慎重に減算します。 二分探索では、累積カウントが必要なヒット数に初めて到達する箇所が特定されます。 

分類ステップでは、見つかった時間に直接モジュラー演算を使用します。 もし`t`両方の期間で割り切れる場合、ヒットは共有されます。 それ以外の場合、除数はどのスケジュールがイベントを生成したかを識別します。 

よくある実装上の間違いは、次を使用して浮動小数点時間推論を試みることです。$t/x$スタイルの比較。 これは精度の問題で失敗しますが、すべての比較は整数演算で実行できるため不要です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def gcd(a, b):
        while b:
            a, b = b, a % b
        return a

    def lcm(a, b):
        return a // gcd(a, b) * b

    def count(t, x, y, l):
        return t // x + t // y - t // l

    def solve_one(k, x, y, l):
        lo, hi = 1, 10**18
        while lo < hi:
            mid = (lo + hi) // 2
            if count(mid, x, y, l) >= k:
                hi = mid
            else:
                lo = mid + 1
        t = lo
        if t % x == 0 and t % y == 0:
            return "Both"
        if t % x == 0:
            return "Vanya"
        return "Vova"

    n, x, y = map(int, input().split())

    out = []
    for _ in range(n):
        k = int(input())
        out.append(solve_one(k, x, y, l))
    return "\n".join(out)

 ## 特殊なケース

 いつ$x = y$、すべてのヒットは同じタイムスタンプで発生します。 二分検索では依然として有効な時間が返されます$t = k \cdot x$、すべてのクエリに対して両方の割り算チェックが成功し、一貫して「両方」が生成されます。 

いずれかのとき$x$または$y$1 に等しい場合、そのプレーヤーは毎秒ヒットし、マージされたシーケンスを支配します。 カウント関数は次のように単純化されるため、アルゴリズムは依然として正しく動作します。$t + \lfloor t/y \rfloor - t/y$、減算により共有イベントが正しく削除されます。 

いつ$a_i$とても大きいです、近いです$10^9$、バイナリ検索の深さは増加しますが、次の制限が残ります。$60$による反復$10^{18}$探索範囲。 カウント関数の単調性はすべての範囲に当てはまるため、正確さは影響を受けません。
