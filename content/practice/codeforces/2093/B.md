 ## 問題の理解

 10 進数が文字列として与えられます。 残りの桁の相対的な順序を維持しながら、その桁のサブセットを削除する場合があります。 結果として得られる一連の数字は正の数を表す必要がありますが、先行ゼロは許可されます。 

結果として得られるすべての数値について、そのコストは次のように定義されます。$$\text{cost}=\frac{\text{number value}}{\text{sum of its digits}}$$すべての有効なサブシーケンスの中で、可能な限り最小のコストが必要です。 最小コストが達成されたら、出力では最小限の削除数が要求されるため、できるだけ多くの桁を保持する必要があります。 

入力数値には最大 100 桁を含めることができるため、標準の整数型よりもはるかに大きくなります。 これは、部分列を実際の整数に変換することに基づく解決策には危険が伴うことを直ちに示唆しています。 テスト ケースの数は最大 1000 です。これは、テスト ケースごとに線形に近い時間が必要であることを意味します。 各文字列の長さは最大でも 100 なので、$O(n^2)$ソリューションは簡単に十分に高速です。 

難しいのは、実際に可能な最小コストがいくらなのかを理解することです。 

簡単な間違いの 1 つは、ゼロ以外の数字を多く保持すると効果があると考えることです。 考慮する：```
n = 12
```考えられる有効なサブシーケンスは次のとおりです。`1`、`2`、 そして`12`。 

費用は次のとおりです。$$1/1=1,\quad 2/2=1,\quad 12/(1+2)=4$$最小コストは 1 で、ゼロ以外の単一の数字によって達成されます。 正解は1削除です。 

もう 1 つの微妙なケースは、先行ゼロが役立つ場合です。```
n = 1005
```保管`0005`秩序は保たなければならないので不可能ですが、`005`有効です。 その費用は$$5/(0+0+5)=1$$結果は 1 桁ではなく 3 桁になります。 1 桁のみを検索するソリューションでは、最適な削除数を逃してしまいます。 

3 番目のよくある落とし穴は、最終的な数値が正でなければならないことを忘れていることです。```
n = 1000
```ゼロのみを保持すると、結果の数値がゼロになるため無効です。 最も有効なサブシーケンスは次のとおりです。`0001`? その秩序は存在しません。 最良の選択は`1000`、`100`、`10`、 または`1`。 最小コストは次のように達成されます。`1`、保持できるのは 1 桁だけです。 答えは3つの削除です。 

## アプローチ

 ブルート フォース ソリューションでは、指定された文字列のすべてのサブシーケンスが列挙されます。 長さ 100 の数値の場合、次のようになります。$$2^{100}$$可能性のあるサブシーケンスですが、これは完全に実行不可能です。 長さ60でも、これはすでに加工できる限界をはるかに超えています。 

すべての有効なサブシーケンスのコストを計算し、最適なものを選択できるため、ブルート フォースは概念的に機能します。 問題は、検索スペースが指数関数的に増大することです。 

より良いアプローチを見つけるには、コスト関数の構造を理解する必要があります。 

部分列に数字の合計があると仮定します。$S$と数値$V$。 数値が正なので、$V \ge S$。 

なぜこれは常に真実なのでしょうか? 10 進数$$d_k10^k+d_{k-1}10^{k-1}+\cdots+d_0$$少なくとも$$d_k+d_{k-1}+\cdots+d_0$$なぜなら、10 のべき乗はすべて少なくとも 1 であるからです。 

これにより、$$\frac{V}{S}\ge 1$$有効なサブシーケンスごとに。 

したがって、可能な最小コストは 1 を下回ることはできません。 

いつ平等が成り立つのか？ 

必要です$V=S$。 10 進数がその桁の合計と等しくなる唯一の方法は、ゼロ以外の桁が 1 つだけ存在し、残りのすべての桁が先行ゼロである場合です。 例:```
5
05
005
0007
```これらはすべてコスト1です。 

達成可能な最小コストが常に 1 であることがわかると、タスクは完全に変わります。 部分的な最適化はもう行われません。 コストが 1 に等しい最長のサブシーケンスのみが必要です。 

このようなサブシーケンスには、ゼロ以外の数字が 1 つだけ含まれている必要があり、その前に保持されている他のすべての数字はゼロでなければなりません。 ゼロ以外の数字の後のゼロは小数点に寄与し、桁の合計を増やさずに数値を増やすため、コストが 1 より大きくなります。 

したがって、ゼロ以外の数字の位置ごとに、以下から構成されるコスト 1 の部分列を形成できます。 

1. その位置の前にゼロがある。 
2. ゼロ以外の数字そのもの。 

その長さは次のとおりです。$$(\text{number of zeros before it}) + 1$$このような最大の長さが必要です。 

元の文字列の長さが$n$保持可能な最大長は$L$、その場合、答えは次のようになります。$$n-L$$| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列の長さを次のようにします。$n$。 
2. これまでに確認されたゼロの数を維持しながら、文字列を左から右にスキャンします。 
3. 現在の桁が`'0'`、ゼロカウンターをインクリメントします。 
4. 現在の桁がゼロ以外の場合は常に、この桁で終わる最長のコスト 1 部分列の長さを計算します。 

その長さは次のとおりです。$$\text{zeros\_before}+1$$なぜなら、以前のすべてのゼロとこのゼロ以外の数字を保持できるからです。 
5. ゼロ以外のすべての位置にわたってそのような最大長を追跡します。 
6. スキャン後、この最大長を$L$。 
7. 出力:$$n-L$$私たちが保管しているので$L$数字を入力し、残りを削除します。 

### なぜ効果があるのか

 すべての正の数は次の条件を満たします$V \ge S$したがって、すべての有効なコストは少なくとも 1 です。サブシーケンスは、その数値がその桁の合計と等しいときに正確にコスト 1 に達します。 

10 進数表現の場合、これはゼロ以外の数字が 1 つあり、その前に保持されている他のすべての数字がゼロである場合にのみ発生します。 ゼロ以外の数字を追加すると、数字の合計よりも値が増加します。 ゼロ以外の数字の後にゼロがあると、余分な小数点以下の桁が作成され、値も増加します。 

固定の非ゼロ桁の場合、初期のゼロをすべて維持すると、コスト 1 を維持しながらサブシーケンスの長さが最大になります。ゼロ以外の位置をすべてチェックすると、可能な限り最長のコスト 1 のサブシーケンスが見つかります。 コスト 1 はグローバル最小コストであるため、そのようなサブシーケンスの長さを最大化すると、削除の数が最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    s = input().strip()

    zeros = 0
    best = 0

    for ch in s:
        if ch == '0':
            zeros += 1
        else:
            best = max(best, zeros + 1)

    print(len(s) - best)
```変数`zeros`現在の位置の前にゼロが何個出現したかを格納します。 

ゼロ以外の数字に遭遇するたびに、以前のすべてのゼロをこの数字と一緒に保持してコスト 1 の部分列を形成できることがわかります。 結果として得られる長さは、`zeros + 1`。 

変数`best`文字列全体の最大の長さを格納します。 

最後に、もし`best`最小限のコストを達成しながら桁を維持できる場合は、残りの桁をすべて削除する必要があります。 答えは`len(s) - best`。 

微妙な点は、選択したゼロ以外の数字の後に現れるゼロは決してカウントされないことです。 これらは、桁の合計を変更しないまま数値を増加させることになるため、コスト 1 のサブシーケンスに属することはできません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        s = input().strip()

        zeros = 0
        best = 0

        for ch in s:
            if ch == '0':
                zeros += 1
            else:
                best = max(best, zeros + 1)

        out.append(str(len(s) - best))

    return "\n".join(out)

# provided samples

# minimum size

# many leading zeros before final non-zero after deletions
assert run("1\n1005\n") == "1"

# all digits non-zero
assert run("1\n99999\n") == "4"

# off-by-one around final position
assert run("1\n0001\n") == "0"

# length 100 boundary
assert run("1\n" + "1" + "0" * 99 + "\n") == "99"
