 ## 解決策
 ## 問題の理解

 指定された配列の最短の部分配列を見つけるように求められます`a`「美しさ」が閾値に達するかそれを超える人の`k`。 配列の美しさは、その要素の任意のペア間の最大 XOR 値です。 したがって、効果的には、次の部分配列ごとに、`a`、ペアごとの XOR を計算し、それらのいずれかが少なくとも`k`。 そうである場合、その部分配列の長さが候補となり、そのような長さの最小値が必要になります。 

入力は複数のテスト ケースで構成され、各テスト ケースには最大 200,000 個の要素の配列が含まれます。 テスト ケース全体のすべての配列の長さの合計も 200,000 によって制限されます。 各要素の大きさは次のとおりです。$10^9$, したがって、最大 30 ビットの整数を扱います。 単純なペアごとの比較では時間がかかるため、各配列をほぼ線形時間かそれよりわずかに上回る時間で処理できるアルゴリズムが必要です。$O(n^2)$、これは完全に不可能です$n \sim 10^5$。 

エッジケースには、すべての要素が等しい配列、以下の配列が含まれます。`k`が 0 (数値とそれ自体の XOR が 0 であるため、すべての部分配列は美しい)、および 2 つの要素が XOR ≥ を生成しない配列`k`。 不注意なアプローチでは、最大 XOR が常に最大値と最小値の間にあると想定する可能性がありますが、XOR は単調ではないため、それは保証されません。 

## アプローチ

 ブルート フォース ソリューションでは、すべてのサブ配列を考慮し、そのサブ配列の最大 XOR を計算し、それが少なくとも以下であるかどうかを確認します。`k`。 長さの配列の場合`n`、 がある$O(n^2)$サブ配列内で最大の XOR を単純に計算するには、最大で 2 時間かかります。$O(n)$、 その結果$O(n^3)$時間。 これは明らかに制約に対して遅すぎます。 

重要な点は、**連続する要素のペア**を調べることでサブ配列内の最大 XOR を検出できるということです。特に、サブ配列に 3 つ以上の要素がある場合は、隣接するすべてのペアまたはトリプルをチェックすることで、いつでも最大 XOR を含むより小さなサブ配列に縮小できるからです。 これは、XOR の微妙ですが強力な特性です。最大の XOR は、値や位置がそれほど離れていない要素によって実現されることが多く、すべての 2 要素および 3 要素ウィンドウをテストするだけで十分です。 

したがって、すべての部分配列をチェックする代わりに、長さ 1、2、または 3 の部分配列のみを考慮する必要があります。長さ 1 の場合、数値とそれ自体の XOR は 0 です。長さ 2 の場合、2 つの数値の XOR がチェックされます。 長さ 3 の場合、3 つのペアすべてをチェックします。 これにより、複雑さが大幅に軽減され、$O(n)$テストケースごとに。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | 最適 (長さ ≤ 3 のウィンドウ) |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テストケースを繰り返して読み取ります。`n`、`k`、および配列`a`。 
2. 変数を初期化する`ans`に`n + 1`、これまでに見つかった最短の長さを表します。 私たちが使用するのは`n + 1`有効なサブ配列はこれを超えることができないため、センチネルとして使用されます。`n`。 
3. インデックスを使用して配列を反復処理します。`i`。 各要素について、以下を確認してください。 

- もし`a[i] >= k`、この要素から構成される長さ 1 の部分配列はすでに美しいです。 アップデート`ans`に`min(ans, 1)`。 
4. 連続したペアの場合`(a[i], a[i+1])`、計算する`a[i] ^ a[i+1]`。 If it is ≥`k`、 アップデート`ans`に`min(ans, 2)`。 
5. For consecutive triples`(a[i], a[i+1], a[i+2])`、3 つのペアごとの XOR をすべて計算します。`a[i] ^ a[i+1]`、`a[i+1] ^ a[i+2]`、`a[i] ^ a[i+2]`。 どれかが ≥`k`、 アップデート`ans`に`min(ans, 3)`。 
6. 繰り返した後、次の場合は`ans`まだです`n + 1`、出力`-1`美しい部分配列が存在しないためです。 それ以外の場合は出力`ans`。 

**機能する理由**: XOR ≥ を達成する 3 つ以上の要素を含むサブ配列`k`XOR ≥ を持つ連続するペアまたはトリプルが含まれている必要があります`k`。 これは整数における XOR の特性です。最大の XOR は小さなウィンドウ内のいくつかのペアに保存されます。 したがって、1 要素、2 要素、および 3 要素ウィンドウのみをチェックするだけで十分であり、考えられる最小長の部分配列をすべてカバーできます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def shortest_beautiful_subarray():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        ans = n + 1

        for i in range(n):
            if a[i] >= k:
                ans = min(ans, 1)
            if i + 1 < n:
                if a[i] ^ a[i+1] >= k:
                    ans = min(ans, 2)
            if i + 2 < n:
                xors = [a[i] ^ a[i+1], a[i+1] ^ a[i+2], a[i] ^ a[i+2]]
                if any(val >= k for val in xors):
                    ans = min(ans, 3)
        
        print(ans if ans != n + 1 else -1)

if __name__ == "__main__":
    shortest_beautiful_subarray()
```コードは、説明されている手順に従います。 インデックスエラーを避けるために、ペアとトリプルの境界を注意深くチェックします。 センチネル値`n + 1`美しい部分配列が存在するかどうかの判断が簡単になります。 XOR の計算は簡単で、追加のデータ構造は必要ありません。
