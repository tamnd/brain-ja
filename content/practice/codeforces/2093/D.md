 ## 解決策
 ## 問題の理解

 私たちは満たしています$2^n \times 2^n$からの整数を含むグリッド$1$に$2^{2n}$ですが、順序は行優先でも列優先でもありません。 代わりに、グリッドは再帰的に構築されます。 

最小スケールでは、$2 \times 2$ブロックは固定パターンで埋められます。 

左上は 1、右下は 2、左下は 3、右上は 4 を取得します。 

より大きなグリッドの場合、同じ考え方が再帰的に適用されます。 正方形は 4 つの等しい象限に分割され、それらの象限は最初に左上の象限、次に右下の象限、次に左下、次に右上という固定の順序で埋められます。 各象限は、到達するまで同じルールを使用して埋められます。$2 \times 2$ブロック。 

これは座標間の全単射を定義します$(x, y)$と価値観$d$。 各クエリは、座標を値にマップするか、値を座標に戻すかを要求します。 

サイズ$2^n$まで行くことができます$2^{30}$、つまりグリッドには次のものがあります。$2^{60}$細胞。 明示的な構築は不可能です。 1 回の完全な横断でも天文学的な規模になります。 唯一の実行可能なアプローチは、グリッドを象限に繰り返し分解して、クエリごとに対数時間で答えを計算することです。 

素朴な考えを打ち破る重要なエッジ ケースは、象限内で行優先の順序を仮定すること、または象限の走査が辞書編集的であると仮定することです。 たとえば、$2 \times 2$ブロックでは、順序は座標によってソートされないため、基本パターンを調整せずに標準のバイナリ空間充填 (モートン順序など) を前提とした座標からインデックスへの変換では、誤った結果が得られます。 

クエリの両方向が同じ再帰的順序付けと一致している必要があることを忘れると、別の微妙な失敗が発生します。 1 つの方向のみを直接計算し、象限構造を考慮せずにそれを「反転」しようとするソリューションは、大規模な場合には失敗します。$n$マッピングが線形ではないためです。 

## アプローチ

 ブルートフォースアプローチでは、グリッドを明示的に構築します。 レベルごとに、サイズに達するまで象限を再帰的に埋めていきます。$2 \times 2$、値を割り当てます。 これにはすべてを訪問する必要があります$2^{2n}$中程度の細胞であっても不可能です$n$。 で$n = 20$、これはもう$2^{40}$実行可能な計算をはるかに超えています。 

重要な観察は、再帰が各レベルの象限にわたって基数 4 システムを使用して数値をエンコードしていることです。 各セルの位置は、最上位レベルから下位レベルまでの一連の象限選択によって説明できます。$2 \times 2$ベースケース。 同様に、各数値は一連の象限インデックスに対応しますが、ひねりが加えられています。$2 \times 2$パターンは標準的な順序ではないため、4 つの葉のカスタム順列として扱う必要があります。 

したがって、グリッドを構築する代わりに、座標を長さのパスに変換します。$n$四分木で同様に数値をそのようなパスに変換します。 各ステップは、2 ビットの座標情報と 2 ビットの値オフセットに寄与します。 これにより、各クエリが次のように削減されます。$O(n)$、最大でも 30 ステップです。 

象限インデックスと座標オフセットおよび値オフセットの両方の間の一貫したマッピングを維持します。 唯一重要でない部分は、リーフ レベルでの基本マッピングです。これは、最後の 2 ビットを数値に変換する方法、およびその逆の方法を定義します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^{2n})$|$O(2^{2n})$| 遅すぎる |
 | 最適 |$O(n)$クエリごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ビット レベルの再帰を使用して、各クエリを個別に処理します。 

### 座標 → 値のクエリ

 1. フルレンジから始めます$[1, 2^n] \times [1, 2^n]$と値のオフセット$0$。 

最終的な答えを次のように解釈します$1 + \text{offset}$。 
2. 各レベルで、現在の正方形をサイズの 4 つの象限に分割します。$2^{k-1} \times 2^{k-1}$。 どの象限を決定するか$(x, y)$かどうかを確認することで嘘をつきます$x$上半分か下半分か、$y$左半分または右半分にあります。 
3. この象限を充填順序のランクに変換します。 順序は次のとおりです。 

左上→0、右下→1、左下→2、右上→3。 

このマッピングは、空間位置が 4 進数の数値の数字になる方法を定義するため、問題の核心です。 
4.追加`quadrant_index * (4^(remaining_levels-1))`オフセットに。 これにより、現在のレベルの最終的な数値への寄与が累積されます。 
5. 更新して選択した象限に移動します。$(x, y)$原点を基準にしてベースに到達するまで継続します$2 \times 2$場合。 
6. 基本ケースでは、同じパターンを使用して、残りの座標を 4 つの値のいずれかに直接マッピングします。 

(1,1) → 1、(2,2) → 2、(2,1) → 3、(1,2) → 4 を加算し、累積オフセットに加算します。 

### 値 → 座標クエリ

 1.変換$d-1$正確に基数 4 表現に変換します$n$各桁は、最上位から最下位までの象限の選択を表します。 
2. フルグリッドから開始します$(1,1)$に$(2^n,2^n)$。 
3. 各レベルで、次の 4 進数の数字を取得し、同じ順序を使用して象限にマッピングします。 

0→左上、1→右下、2→左下、3→右上。 
4. 現在の座標をその象限の原点に移動し、下に行くか右に行くかに応じてオフセットを蓄積します。 
5. 最後にベースを塗ります。$2 \times 2$デコード:

 1→(1,1)、2→(2,2)、3→(2,1)、4→(1,2)。 

### なぜ効果があるのか

 このアルゴリズムは、各セルを四分木を通るパスとしてエンコードし、各レベルは 4 進数の 1 桁を正確に提供します。 再帰的な構築により、すべての象限が同じ相対順序で連続的に埋められることが保証されるため、空間分解と数値間隔の間のマッピングが保持されます。 基本ケースでは、2 ビットの座標と値の間の固定全単射を定義し、リーフ レベルでの一貫性を確保します。 すべてのステップで領域と連続する値の範囲間の 1 対 1 のマッピングが維持されるため、衝突やギャップは発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# quadrant order:
# 0 -> TL
# 1 -> BR
# 2 -> BL
# 3 -> TR

def coord_to_val(n, x, y):
    res = 0
    size = 1 << n

    for k in range(n, 1, -1):
        half = 1 << (k - 1)
        block = 1 << (2 * (k - 1))

        if x <= half and y <= half:
            q = 0
        elif x > half and y > half:
            q = 1
            x -= half
            y -= half
        elif x > half and y <= half:
            q = 2
            x -= half
        else:
            q = 3
            y -= half

        res += q * block

    # base 2x2
    if x == 1 and y == 1:
        res += 1
    elif x == 2 and y == 2:
        res += 2
    elif x == 2 and y == 1:
        res += 3
    else:
        res += 4

    return res

def val_to_coord(n, d):
    d -= 1
    x = y = 1
    size = 1 << n

    for k in range(n, 1, -1):
        block = 1 << (2 * (k - 1))
        q = d // block
        d %= block

        half = 1 << (k - 1)

        if q == 0:
            pass
        elif q == 1:
            x += half
            y += half
        elif q == 2:
            x += half
        else:
            y += half

    # last level
    if d == 0:
        return x, y
    elif d == 1:
        return x + 1, y + 1
    elif d == 2:
        return x + 1, y
    else:
        return x, y + 1

t = int(input())
out = []

for _ in range(t):
    n = int(input())
    q = int(input())

    for _ in range(q):
        parts = input().split()
        if parts[0] == "->":
            x = int(parts[1])
            y = int(parts[2])
            out.append(str(coord_to_val(n, x, y)))
        else:
            d = int(parts[1])
            cx, cy = val_to_coord(n, d)
            out.append(f"{cx} {cy}")

sys.stdout.write("\n".join(out))
```座標から値への関数は四分木を下っていき、最終的なインデックスから各四分円の寄与分を減算します。 値から座標への関数は、ブロック サイズによる除算を使用して基数 4 桁を抽出することで、このプロセスを逆にします。 

微妙な実装の詳細は、均一な再帰を継続するのではなく、基本ケースが明示的に処理されることです。 これにより、実行時の高価な電力計算が回避され、最終的な結果の正確さが保証されます。$2 \times 2$辞書順に並べられていないマッピング。 

べき乗の代わりにビット シフトを使用すると、すべての計算が高速に行われ、整数の範囲内に収まるようになります。

 ## 特殊なケース

 エッジケースの 1 つは、$n = 1$、ロジック全体が次のように折りたたまれます。$2 \times 2$基本の順列。 このアルゴリズムは引き続き同じループを 0 回実行し、ベース マッピングを直接適用します。これにより、他の場所で特別な分岐を行うことなく正確さが保証されます。 

別のケースは最大深さです$n = 30$。 ここで、再帰ベースまたは浮動小数点の電力計算はオーバーフローするか速度が低下します。 ビット シフト ベースのブロック計算により、大きなべき乗を明示的に計算することがなくなり、すべての演算が 32 ビットまたは 64 ビットの整数演算の範囲内で安全に行われるようになります。 

3 番目のケースは、方向を交互に切り替えるクエリです。 どちらの関数も純粋でステートレスであるため、クエリ間で中間状態が保持されないため、インターリーブは正確さに影響しません。
