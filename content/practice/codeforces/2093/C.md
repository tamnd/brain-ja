 ## 解決策
 ## 問題の理解

 基本整数が与えられます`x`そして繰り返し回数`k`。 から`x`、新しい数値を構築します`y`の 10 進表現を書くことによって`x`連続して`k`区切り文字を挿入せずに繰り返します。 たとえば、次の場合`x = 52`そして`k = 3`、 それから`y = 525252`。 もし`x = 6`そして`k = 7`、 それから`y = 6666666`。 

タスクは、この数値を明示的に構築して、通常の意味での素数性をテストすることではなく、この構築された数値が正しいかどうかを判断することです。`y`プライムです。 

制約は、構築することを即座に通知します。`y`一般的には不可能です。 いつ`x`最大9桁で、`k`が 7 までの場合、結果の数値は最大 63 桁になる可能性があり、これはすでに標準の整数型を超えています。 文字列として保存することも問題ありませんが、最大 100 個のテスト ケースに対する 63 桁の整数の素数性テストには、高度な大きな整数の素数性テクニックが必要であり、定格 1000 の問題には依然として過剰です。 

より微妙な問題は、次のようなエッジケースに現れます。`k = 1`そして`x = 1`。 もし`x = 1`そして`k = 1`、 それから`y = 1`、これは素数ではありません。 もし`k > 1`、たとえいつでも`x = 1`、結果は次のような再計算になります`111...1`、特別に見えるかもしれませんが、常に複合です`k > 1`この構造では因数分解できるためです。 

単純な間違いは、文字通り文字列を構築し、試行除算を使用して素数チェックを試みることです。 sqrt(n) まで最適化しても、`y`そしてテストケースを繰り返しました。 

## アプローチ

 直接的なブルートフォースソリューションは以下を構築します。`y`までの除算を使用して素数かどうかを確認します`sqrt(y)`。 これは概念的には正しいですが、すぐに実行不可能になります。 番号`y`は最大 63 桁まで含めることができるため、単一の素数チェックですら、合理的な決定論的試行分割アプローチをはるかに超えています。 

重要な観察は構造的です。連結を繰り返すと、いつでも強力な代数因数分解特性を持つ数値が作成されます。`k > 1`。 長さを`x`なれ`d`。 次に、構築された数値は次のように書くことができます。$$y = x \cdot 10^{d(k-1)} + x \cdot 10^{d(k-2)} + \cdots + x$$ファクタリング`x`、次のようになります。$$y = x \cdot (10^{d(k-1)} + 10^{d(k-2)} + \cdots + 1)$$これは、いつでも`k > 1`、`y`の製品です`x`そして 1 より大きい別の整数。`y`複合物を除く`x = 1`そして 2 番目の要素が特別であることに依存します。 ただし、その場合でも、次の場合、2 番目の因数は 1 より大きくなります。`k > 1`、 それで`y`複合です。 

したがって、プライムを取得できるのは次の場合のみです。`k = 1`、そのときだから`y = x`。 問題は、次のことを確認することに帰着します。`x`それ自体がプライムです。 

したがって、ソリューション全体は次のように折りたたまれます。 

- もし`k > 1`、答えは常に「NO」です。 
- もし`k = 1`、の素数性をチェックします`x`。 

今必要なのは素数性テストだけです`x ≤ 10^9`までの試行分割が簡単です。`sqrt(x)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース構築 + 大きな素数テスト | O(k· | x | + sqrt(y)) |
 | 因数分解の洞察 + チェック x | テストあたり O(√x) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`x`そして`k`テストケースごとに。 計算が引き継がれないため、各ケースを独立して処理します。 
2. もし`k`が 1 より大きい場合は、ただちに「NO」を出力します。 これは、複合性を保証する繰り返しの連結の代数的因数分解から得られます。 
3. もし`k`が 1 に等しい場合、問題は次のことを確認することに集約されます。`x`は素数です。 
4. 素数性をテストするには`x`、最初に小さなケースを処理します: 2 未満の数値は素数ではありません。 
5. のために`x ≥ 2`、2 から までのすべての整数で割ってみてください。`sqrt(x)`。 約数が見つかった場合は、`x`複合です。 それ以外の場合は素数です。 

### なぜ効果があるのか

 正確かどうかは、繰り返しが発生するたびに連結により自明ではない乗算構造が導入されるという事実にかかっています。 のために`k > 1`、構築された数値は常に次の積に分解されます。`x`および 10 のべき乗の幾何学和。どちらも厳密に大きさが 1 より大きくなります。 これにより、次のいずれかに関係なく複合性が保証されます。`x`それ自体がプライムです。 いつ`k = 1`、構造は導入されておらず、数値は正確に`x`したがって、素数性は正確に保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(n: int) -> bool:
    if n < 2:
        return False
    if n % 2 == 0:
        return n == 2
    i = 3
    while i * i <= n:
        if n % i == 0:
            return False
        i += 2
    return True

t = int(input())
for _ in range(t):
    x, k = map(int, input().split())
    if k > 1:
        print("NO")
    else:
        print("YES" if is_prime(x) else "NO")
```コードはまず構造的なショートカットを分離します。`k > 1`これにより、繰り返される大きな数を構築したり推論したりする必要がなくなります。 素数チェックは必要な場合にのみ適用されるため安全です。`x`によって制限されています`10^9`。 

素数関数は、2 を処理した後に偶数をスキップすることによって最適化された標準の平方根試行除算を使用します。制約を考慮すると、これで十分です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t √x) | 各テストでは、√x | までの試行除算を使用して、k = 1 の場合にのみ素数性をチェックします。 
| スペース | お(1) | いくつかの変数を超える補助構造はありません。 

この制約により、最大 100 個のテスト ケースが許可されます。`x ≤ 10^9`。 √10^9 は約 31623 であるため、√x アプローチは十分に高速であり、最悪のケースではその操作を 100 回実行しますが、これは十分に制限内です。

 ## 特殊なケース

 最も敏感なエッジケースは次のとおりです。`x = 1`。 もし`k = 1`、番号は`1`、これは素数ではないため、出力は「NO」でなければなりません。 もし`k > 1`、数値は次のような 1 の文字列になります。`111...1`、これは現在も処理されています。`k > 1`ルールが適用され、構築なしで即座に「NO」と分類されます。 

もう 1 つの特殊なケースは、次のような繰り返しのある小さな素数です。`x = 2, k = 2`。 構築された数値は、`22`これは明らかに合成であり、素数性チェックの前に反復規則によりアルゴリズムは正しく「NO」を返します。 

最後に、大きな素数は、`k = 1`、 のような`x = 999999937`、純粋に素数チェックループによって処理されます。 このアルゴリズムは平方根の境界のみに依存し、オーバーフローや変換の問題のない正確性を保証します。
