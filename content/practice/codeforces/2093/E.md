 ## 解決策
 ## 問題の理解

 配列が与えられ、配列全体をカバーする正確に k 個の連続する部分に切り出すように求められます。 配列が分割されると、各部分は MEX 値を持ち、最悪の部分、つまり k 個のセグメントすべての中で最小の MEX が考慮されます。 目標は、この最悪の MEX ができるだけ大きくなるように分割を選択することです。 

問題を再構成すると役立ちます。MEX は、0、1、2 などの存在をどれだけ早く保証できるかのみに依存するため、すべてのセグメントが少数でも「十分に豊富」であることを強制しようとしています。 セグメントに整数 x が欠落している場合、その MEX は最大でも x です。 

この制約は、ソリューションがテスト ケースごとに線形に近い必要があることを意味します。 テスト全体の合計 n は 2e5 であるため、テスト ケースごとに O(n log n) または O(n) よりも悪いアプローチは失敗します。 候補値ごとの単純な貪欲シミュレーションは、それが線形であれば許容されますが、テスト ケースごとの n の二次関数は不可能です。 

k が大きい場合、微妙なエッジケースが現れます。 k が n と等しい場合、すべてのセグメントの長さは 1 になるため、各 MEX は要素が 0 かどうかに応じて 0 または 1 になります。もう 1 つの注意が必要なケースは、配列にゼロがまったくない場合です。 この場合、すべてのセグメントは MEX 0 を持つため、k に関係なく答えは強制的に 0 になります。 セグメント内の値を常に「収集」できると想定する単純なアプローチは、ここで破綻します。 

貪欲にセグメントを早く切り取ろうとすると、別の失敗モードが発生します。 たとえば、x-1 までのすべての数値が含まれるとすぐにセグメントを終了して MEX を貪欲に最大化しようとすると、セグメントが多すぎて k に到達できない可能性があります。 

## アプローチ

 重要な考え方は、答えをテストできるものとして扱うことです。 値 x を推測し、すべてのセグメントが少なくとも x の MEX を持つように、配列を少なくとも k 個のセグメントに分割することが可能かどうかを尋ねるとします。 この条件を確認できれば、最大xを二分探索することができます。 

セグメントが少なくとも x の MEX を持つには、0 から x-1 までのすべての数値が少なくとも 1 回含まれている必要があります。 これにより、問題はスライディング ウィンドウにわたるカバレッジ要件に変換されます。各有効なセグメントは、閉じる前に必要な値をすべて「収集」する必要があります。 

ブルートフォースの方法は、配列を k 個のセグメントに分割し、各セグメントの MEX を計算するあらゆる方法を試みることです。 n-1 個のギャップはそれぞれカットされるかカットされないため、パーティションの数は指数関数的になります。 セグメントごとの MEX を計算しても O(n) になるため、このアプローチはまったく実行不可能です。 

視点を逆転させることで改善がもたらされます。 カットを選択して MEX をチェックする代わりに、x を固定して左から右に貪欲にセグメントを構築し、必要な値 0 から x-1 をすべて満たしたらすぐにセグメントを常に終了します。 この貪欲な構築により、特定の x に対して可能な最大数の有効なセグメントが生成されます。 この最大数でも k 未満の場合、x は不可能です。 

これが機能するのは、有効になるポイントを超えてセグメントを拡張すると、後で形成できるセグメントの数が減るだけで、増加することはないからです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティショニング | O(2^n · n) | O(n) | 遅すぎる |
 | 二分探索 + 貪欲チェック | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 値 x が実現可能であれば、それより小さい値も可能であるため、最初に答え x を二分探索します。

1. 固定 x の場合、少なくとも k 個の有効なセグメントを形成できるかどうかを判断するチェッカーを定義します。各セグメントには 0 から x-1 までのすべての整数が含まれます。 これは、MEX ≥ x の正確な条件です。 
2. 現在のセグメントの周波数構造を維持しながら、配列を左から右にスキャンします。 また、これまでに 0 から x-1 までの個別の値がいくつ見つかったかも追跡します。 
3. [0, x-1] の範囲に値 v が表示されると、その頻度を更新し、それが現在のセグメントで最初に出現した場合は、満たされた値のカウンターを増やします。 
4. カウンタが x に達すると、現在のセグメントが有効になります。 ここですぐにカットして周波数構造とカウンターをリセットし、スキャンを続けます。 
5. この方法で形成できるセグメントの数を数えてください。 この数が少なくとも k であれば、x は実行可能です。 それ以外の場合はそうではありません。 

意味のあるパーティショニング コンテキストでは MEX が n+1 を超えることはできないため、バイナリ検索範囲は 0 から n+1 までです。 

### なぜ効果があるのか

 固定 x の場合、貪欲戦略は常に、セグメントが有効になる最も早い位置でセグメントを終了します。 それ以降のカットでは、有効なセグメントの数を増やすことなく、より多くの要素が消費されるだけです。 したがって、この貪欲により、その x に対して達成可能な有効なセグメントの最大数が生成されます。 この最大値でも k を下回る場合、代替パーティションは成功しません。 これにより、実現可能性チェックの正確性が確立され、二分探索により最大の x が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(a, k, x):
    if x == 0:
        return True

    freq = [0] * (x + 1)
    have = 0
    segments = 0

    for v in a:
        if v < x:
            if freq[v] == 0:
                have += 1
            freq[v] += 1

        if have == x:
            segments += 1
            if segments >= k:
                return True
            freq = [0] * (x + 1)
            have = 0

    return segments >= k

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    lo, hi = 0, n + 1
    while lo < hi:
        mid = (lo + hi + 1) // 2
        if can(a, k, mid):
            lo = mid
        else:
            hi = mid - 1

    print(lo)
```チェッカー機能はソリューションの中核です。 より大きな値は MEX が x に達するかどうかに影響しないため、x よりも厳密に小さい値に関する情報のみが維持されます。 セグメント内に必要な値がすべて表示されると、セグメントはすぐに閉じられます。 

二分探索は、無限ループを回避し、実現可能な最大の x への収束を保証するために、標準の上位中間形式で実装されます。 

## 実用的な例

 ### 例 1

 入力:```
5 2
2 1 0 0 1
```さまざまな x についての実現可能性をテストします。 

x = 2 の場合、各セグメントには {0,1} が含まれている必要があります。 スキャンします:

 | インデックス | 値 | 0 | 持っています 1 つ持っています | セグメント |
 | --- | --- | --- | --- | --- |
 | 0 | 2 | 0 | 0 | 0 |
 | 1 | 1 | 0 | 1 | 0 |
 | 2 | 0 | 1 | 1 | 0 → カット |
 | 3 | 0 | 1 | 1 | 1 |
 | 4 | 1 | 1 | 1 | 1 → カット |

 2 つのセグメントが得られるので、x = 2 が可能です。 

x = 3 の場合、セグメントごとに {0,1,2} が必要です。 形成できるセグメントは 1 つだけなので、x = 3 は失敗します。 

これにより、回答 2 が確認されます。 

### 例 2

 入力:```
4 4
1 0 0 0
```x = 1 の場合、各セグメントには 0 が含まれている必要があります。 

スキャン中:

 | インデックス | 値 | 0 | 持っています セグメント |
 | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 |
 | 1 | 0 | 1 | 0 → カット |
 | 2 | 0 | 1 | 1 → カット |
 | 3 | 0 | 1 | 2 → カット |

 各カットがゼロを分離する場合にのみ、少なくとも 4 つのセグメントを形成できますが、最初のカットの後はすでに構造が消費されているため、4 つの有効なセグメントを生成できません。 したがって結果は0です。 

これは、多くのセグメントを強制すると、達成可能な MEX がどのように崩れるかを示しています。

 ## 特殊なケース

 配列にゼロがまったく含まれていない場合、すべてのセグメントは即座に MEX 0 になります。どのセグメントも値 0 を収集できないため、x = 1 のチェッカーは失敗します。そのため、二分探索は正しく 0 に折りたたまれます。 

k が n と等しい場合、各要素は独自のセグメントを形成する必要があります。 このアルゴリズムは、単一の要素がすでに要件を満たしているセグメントのみをカウントします。 x ≥ 2 の場合、単一の要素に 0 と 1 の両方を含めることはできないため、これは不可能です。実現可能性チェックは早期に停止し、ゼロが存在するかどうかに応じて 0 または 1 を適切に返します。 

k = 1 の場合、配列全体が 1 つのセグメントになります。 貪欲チェックはグローバル MEX 条件のチェックに減り、バイナリ検索は問題の定義と一致する配列全体の MEX を効果的に見つけます。
