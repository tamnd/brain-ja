 ## 解決策
 ## 問題の理解

 私たちには有向関数グラフが与えられています。つまり、すべての子供がまさに 1 人の「永遠の親友」を指します。 子供のサブセットを選択し、円の中に配置して、その円の各子供が少なくとも片側で親友の隣に座るようにしたいと考えています。 隣接関係は円内で対称であるため、選択された子ごとに、その BFF も選択され、最終的な順序でそれらの子に隣接して表示される必要があることを意味します。 

タスクは、そのような有効なサークルに含まれる子の数を最大化することです。 

制約$N \le 1000$余裕があるという意味$O(N^2)$あるいは$O(N^3)$近づいてきます。 ただし、サブセットの指数関数的な列挙は不可能です。$2^{1000}$は大きすぎます。 

重要な構造観察は、各ノードの出次数 1 があるため、グラフが有向サイクルに分解され、ツリーがそれらのサイクルにフィードされることです。 これは、隣接性要件によって許可される置換が大幅に制限されるため、有効な構造がサイクル構造と一致する必要があることを直ちに示唆します。 

相互ペアがある場合、微妙なエッジケースが発生します$a \leftrightarrow b$。 これらは 2 サイクルで、長いサイクルとは異なり、両側につながるチェーンを取り付けることで「延長」できます。 単純なサイクルのみを考慮する単純なアプローチでは、これらの拡張機能を見逃してしまいます。 

もう 1 つのエッジ ケースは、最適な構成が単一の大きなサイクルではなく、多くの構造の組み合わせである場合です。つまり、1 つの長いサイクルと複数の相互ペアとチェーンの組み合わせです。 たとえば、最初に最大のサイクルを貪欲に選択すると、失敗する可能性があります。 

## アプローチ

 強引なアイデアとしては、子のすべての順列を試し、それが有効な円を形成しているかどうかを確認し、最大サイズを追跡するというものです。 これは正しいですが、実行不可能です。順列を生成することさえ困難です。$O(N!)$、隣接性制約のチェックには次の時間がかかります。$O(N)$、極小を超えると使用できなくなります$N$。 

重要な洞察は、グラフ構造を解釈することです。 各ノードには出力エッジが 1 つだけあるため、すべての接続コンポーネントには 1 つの有向サイクルが含まれます。 他のものはすべて、そのサイクルに流入する有向ツリーです。 

ここで、答えに対する 2 つの根本的に異なる貢献を分離します。 

まず、サイクル外のノードは BFF 隣接条件を破らずに有効な循環隣接に配置できないため、少なくとも 3 の長さのサイクルはそのサイクル サイズにのみ寄与できます。 

次に、長さ 2 のサイクルは異なる動作をします。 お互いのペア$a \leftrightarrow b$は「コア」として機能し、で終わる最長の受信チェーンを接続できます。$a$で終わる最長の受信チェーン$b$。 これらのチェーンを線形化し、ペアの両側に追加して、より大きな有効な構造を形成することができます。 

したがって、最適な答えは、最良の単純なサイクル (長さは少なくとも 3) と、最良の入力チェーンによって拡張されたすべての 2 サイクルの合計の間の最大値になります。 

これにより、問題はサイクル検出とサイクル ノードへの最長の逆パス計算に軽減されます。

 | ブルートフォース |$O(N!)$|$O(N)$| 遅すぎる |
 | 木のサイクル + DP |$O(N)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 BFF 関係を、各ノードが出ていくエッジを 1 つだけ持つ有向グラフとして扱います。 

1. まず、標準の DFS または反復訪問マーキングを使用してすべてのサイクルを検出します。 現在再帰スタック内にあるノードに再度アクセスすると、サイクルが抽出されます。 
2. すべてのノードについて、逆エッジを使用してサイクル構造への深さを計算します。 逆隣接リストを構築して、サイクル ノードから外側に最長のチェーンを伝播できるようにします。 
3. 各ノードについて、同じサイクル内でノードを再訪問しない、そのノードで終わる最長のパスを計算します。 これは、逆グラフの葉から上に向かって DP によって行われます。 
4. 少なくとも 3 の長さのすべてのサイクルについて、それをスタンドアロンの有効な円候補とみなし、そのサイズで答えを更新します。 
5. 相互ペアサイクルごとに$a \leftrightarrow b$、特別に扱います。 で終わる最長のチェーンを計算します。$a$サイクルエッジを除き、同様に$b$。 貢献度は、$2 + bestChain[a] + bestChain[b]$。 
6. すべての相互ペアの寄与を合計し、それらは独立しているため、最良の長期サイクルの答えと比較します。 
7. これら 2 つの値の最大値を出力します。 

自明ではないステップが、チェーンを 2 サイクルにしか追加できない理由です。 その理由は、より長いサイクルでは、すべてのノードで両方の隣接ノードがすでに固定されているため、追加のノードを挿入すると、最後のサークルで隣接関係の一貫性が損なわれるためです。 対照的に、2 サイクルには、直鎖を吸収できる「開いた接続点」が 2 つあります。 

### なぜ効果があるのか

 すべての有効な構成は、単一の有向サイクルであるか、ツリーがフィードされる互いに素な双方向ペアで構成されている必要があります。 関数グラフ構造は、他のグローバルな配置が隣接性制約を満たすことができないことを保証します。 DP は、すべての有効なアタッチメントが正確に 1 回カウントされることを保証し、サイクルとペアのケースに分割することで、重複する構造の過剰カウントを回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    f = [0] + list(map(int, input().split()))

    rev = [[] for _ in range(n + 1)]
    for i in range(1, n + 1):
        rev[f[i]].append(i)

    visited = [0] * (n + 1)
    in_stack = [0] * (n + 1)
    best_cycle = 0
    pairs = []

    def dfs(u):
        nonlocal best_cycle
        visited[u] = 1
        in_stack[u] = 1
        v = f[u]

        if not visited[v]:
            dfs(v)
        elif in_stack[v]:
            # found cycle
            cycle = []
            cur = v
            while True:
                cycle.append(cur)
                if cur == u:
                    break
                cur = f[cur]
            if len(cycle) == 2:
                pairs.append((cycle[0], cycle[1]))
            else:
                best_cycle = max(best_cycle, len(cycle))

        in_stack[u] = 0

    for i in range(1, n + 1):
        if not visited[i]:
            dfs(i)

    dp = [0] * (n + 1)

    def dfs2(u):
        for v in rev[u]:
            dfs2(v)
            dp[u] = max(dp[u], dp[v] + 1)

    for i in range(1, n + 1):
        dfs2(i)

    pair_sum = 0
    used = set()
    for a, b in pairs:
        if (b, a) in used:
            continue
        used.add((a, b))
        pair_sum += 2 + dp[a] + dp[b]

    print(max(best_cycle, pair_sum))

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```このソリューションでは、まずリバース エッジを構築して、サイクル ノードへのチェーン長の計算を可能にします。 サイクル検出ステップでは、すべての有向サイクルを識別し、それらを長さ 2 の相互ペアまたはより長いサイクルのいずれかに分類します。 リバースエッジ上の DP は、各ノードの最長の入力チェーンを計算し、相互ペア構造でのみ使用されます。 

実装上の微妙な問題は、サイクル抽出によって異なる DFS パス間でノードが誤って再利用されないようにすることです。 もう 1 つは、チェーンはどこからでも開始できますが、サイクル ノードで終了する必要があるため、リバース エッジ上の DP をグローバルに計算する必要があることです。 

## 実用的な例

 ### 例 1

 入力:```
4
2 3 1 4
```サイクル 1 → 2 → 3 → 1 があり、ノード 4 は構造を通じて間接的にそれ自体を指します (解釈によっては、孤立しているか自明です)。 サイクルの長さは 3 なので、3 が直接寄与します。 相互のペアは存在しないため、答えは 3 です。 

| ステップ | アクション | 結果 |
 | --- | --- | --- |
 | 1 | サイクルを検出 | {1,2,3} |
 | 2 | サイクルを分類する | 長さ 3 |
 | 3 | dp を計算する | 非ペアには無関係 |
 | 4 | 完了する | 答え = 3 |

 これにより、長いサイクルがそのまま適用されることが確認されます。 

### 例 2

 入力:```
4
1 2 1 2
```(1,2) と (3,4) の 2 つの相互ペアがあります。 それぞれが独立して貢献します。 

| ペア | DP への貢献 | 合計 |
 | --- | --- | --- |
 | (1,2) | 0 + 0 | 2 |
 | (3,4) | 0 + 0 | 2 |

 ペアの合計は 4 です。 

これは、長いサイクルとは異なり、相互のペアを組み合わせることができる理由を示しています。

 ## 特殊なケース

 重要なエッジ ケースは、グラフに相互ペアのみが含まれる場合です。 この状況では、最適な答えは常に各ペアの拡張チェーンの合計であり、サイクルは存在しません。 このアルゴリズムは各ペアを独立して正確に蓄積し、干渉がないことを保証します。 

もう 1 つのエッジ ケースは、ノードに入力ツリーがある長いサイクルです。 ツリーが存在する場合でも、隣接制約を破らずにそれらを接続することはできないため、最終サイクルの回答では正しく無視されます。
