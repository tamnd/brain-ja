 ## 解決策
 ## 問題の理解

 私たちは 2 つのパラメータによって定義される非標準の時計システムを使用しています: 1 日の時間数`h`そして1時間の分数`m`。 一瞬の時間をペアで与えられる`(x, y)`どこ`x`は現在の時間であり、`y`は現在の分です。`0 ≤ x < h`そして`0 ≤ y < m`。 

この開始の瞬間から、時間は通常、分ごとに進み、次の時点で折り返します。`m`分、その後`h`何時間も。 言い換えれば、クロックは長さのサイクルのように動作します。`h · m`分。 

このタスクは、時刻に関する単純な関数を定義します。時と分の 10 進表現を個別に取得し、すべての桁を合計し、この値を時刻の「桁合計」と呼びます。 たとえば、時間`07:05`桁の合計があります`0 + 7 + 0 + 5 = 12`。 

指定された開始時刻から、桁の合計が開始瞬間の桁の合計と等しい瞬間に最初に到達するまで、何分進める必要があるかを決定するように求められます。 

重要な点は、時間が循環しているということです。 後`h · m`分が経過すると同じ状態に戻るため、検索は当然この期間を法とします。 

単純に解釈すると、一致するものが見つかるまで順方向にシミュレーションする必要があるかもしれませんが、サイクルの長さは次のように長くなる可能性があります。`10^4`またはそれ以上であり、複数のテスト ケースが存在する場合があります。 これでもシミュレーションするには十分小さいように見えますが、より緊密なソリューションが望ましいです。 

答えが次のような場合、微妙なエッジケースが現れます。`0`、開始時刻がすでに条件を満たしていることを意味します。 もう 1 つは、サイクルが終了するときです。そのため、リニア スキャンでは「早い」場合でも、最初の有効な時間が翌日に発生する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。開始時刻の桁の合計を計算し、元の値と再び一致するまで時計を 1 分ずつ繰り返し進め、毎回桁の合計を再計算します。 システムはその後も繰り返すので、`h · m`これにより、終了が保証されます。 

各ステップには一定の時間がかかるため、テストごとの最悪の場合の複雑さは次のようになります。`O(h · m)`。 複数のテスト ケースにわたって、これはまだ許容できる可能性があります。`h, m ≤ 100`ただし、クエリごとにほぼサイクル全体をスキャンする必要がある場合は無駄になります。 

重要な観察は、選択肢の最小化や最適化のような構造的なことは求められていないということです。 決定的なサイクルに沿って固定状態に戻る最初の時間だけが必要です。 これにより、問題はすぐに、長さの円形配列をスキャンすることになります。`h · m`。 各状態はそれ自体の桁の合計にのみ依存するため、高度なデータ構造やプレフィックスのトリックは必要ありません。 

毎回単一の整数インデックスにマッピングすることで、実装の明確性を向上させることができます。`[0, h·m - 1]`。 州から`t`、次の状態は`(t + 1) mod (h·m)`、除算と剰余を介して時と分を計算できます。 これにより、遷移が単純になり、キャリー ロジックを手動で処理する必要がなくなります。

## アルゴリズムのチュートリアル

 1. 開始時刻の桁の合計を計算します。`(x, y)`そしてそれを次のように保存します`target`。 この値は決して変更されず、再度ヒットする条件として機能します。 
2. 現在時刻を単一の整数に変換します。`cur = x * m + y`。 この線形化により、時間の進行が簡単になります。 
3. 任意の桁の合計を事前計算します。`(hour, minute)`オンデマンドでペアリングします。 各評価では、整数を数字に変換するだけで済みます。これは、制限された制約が与えられた定数時間です。 
4. 最大で実行されるループを開始します`h * m`ステップ。 各ステップで、現在の値を計算します。`(hour, minute)`から`cur`除算と剰余を使用して、その桁の合計を計算します。 
5. 桁の合計が一致する場合`target`、開始から経過した歩数を返します。 
6. それ以外の場合はインクリメントします`cur`1 ずつ (モジュロ`h * m`) 続けてください。 
7. 開始状態に戻る前に一致するものが見つからなかった場合、答えは次のようになります。`0`, 初期状態ですでにサイクル保証を満たしているためです。 

### なぜ効果があるのか

 時間のシステムは、長さの単一の有向サイクルを形成します。`h · m`ここで、各ノードは次の瞬間までに 1 つの発信エッジを持ちます。 サイクルを順番に移動するため、可能なすべての構成は、反復の前に 1 回だけアクセスされます。 桁合計条件は各ノードで個別に評価されるため、最初に一致する値が見つかったときは、必然的に順方向の進行における最も早い有効時刻となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def digit_sum(x, y):
    return sum(map(int, str(x))) + sum(map(int, str(y)))

def solve():
    h, m, x, y = map(int, input().split())

    start_sum = digit_sum(x, y)
    start = x * m + y
    total = h * m

    cur = start
    for step in range(total):
        hour = cur // m
        minute = cur % m

        if digit_sum(hour, minute) == start_sum:
            print(step)
            return

        cur = (cur + 1) % total

    print(0)

if __name__ == "__main__":
    solve()
```この解決策は、クロック構成を読み取り、初期時間の桁の合計を計算することから始まります。 その後、時間は 1 つの整数に平坦化されるため、モジュラー ラップアラウンドでは 1 分進むだけで増分されるようになります。 

ループ内で、線形インデックスから時と分を再構築します。 これにより、個別の状態変数を維持することが回避され、遷移の正確さが保証されます。 桁の合計チェックはステップごとに繰り返され、元の値と一致するとすぐに、実行されたステップ数を返します。 

微妙な点は、答えがゼロの場合の処理​​です。 ループ構造はすでに初期状態をチェックしています。`step = 0`したがって、すぐに返すと、このケースが正しくカバーされます。

 ## 特殊なケース

 エッジ ケースの 1 つは、開始時間が既に桁合計条件を満たしている場合です。 たとえば、小さな時計の場合`h = 2, m = 3`、から始まります`0:00`、桁の合計は`0`、およびステップの最初のチェック`0`すぐに戻ります`0`。 

もう 1 つのケースは、正解を得るためにサイクルを繰り返す必要がある場合です。 仮定する`h = 2, m = 3`、から始まります`1:02`。 桁の合計は、次のステップを通過するまで一致しない可能性があります。`1:00`、`1:01`、`1:02`ラップアラウンド後にもう一度。 アルゴリズムは完全に反復されるため、これを正しく処理します。`h · m`サイクル。 

最後の微妙なケースは、1 つのサイクル内に複数の有効な瞬間が存在する場合です。 このアルゴリズムは、状態をスキップせずに厳密な時間順序でスキャンするため、常に最初に見つかったものを返し、追加の簿記を必要とせずに正確性を保証します。
