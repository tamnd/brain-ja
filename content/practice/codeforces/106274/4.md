 ## 問題の理解

 文字だけで構成される文字列があります`1`そして`2`。 の量`1`文字数は の量とまったく同じです`2`文字。 ゲートは、等しい文字が決して隣り合わない場合にのみ安定します。つまり、最後の文字列は次のように交互になる必要があります。`121212...`または`212121...`。 

許可される唯一の操作は、隣接する 2 つの文字を交換することです。 隣接するスワップごとに、1 文字を左または右に 1 つ移動することで文字列の順序が変更されます。 タスクは、元の文字列を有効な代替文字列に変換するために必要なスワップの最小数を見つけることです。 

入力サイズは 100000 文字に達する可能性があります。 これにより、入れ子になったループ内で、置き忘れたキャラクターを繰り返し検索し、個別にスワップして移動するシミュレーションは即座に除外されます。そのような方法は二次時間に達する可能性があるためです。 100,000 ポジションの場合、`O(n^2)`このアルゴリズムでは、最悪の場合でも約 10^10 の操作が必要になりますが、これは 1 秒の制限をはるかに超えています。 

主なエッジ ケースは、文字列がすでに条件を満たしている場合、2 つの交互パターンのうち 1 つだけが可能である場合、および等しい文字の長いブロックが存在する場合に発生します。 たとえば、次のような場合です。```

12
```答えは`0`。 常にビルドしようとする不注意な実装`1212...`ここでは他のパターンをチェックしなくても機能しますが、他のパターンの方が安価な場合は失敗する可能性があります。

## アプローチ

 簡単なアイデアは、文字列が交互になるまで実際に交換を実行することです。 文字列をスキャンし、現在の文字が必要な文字と異なる最初の位置を見つけ、必要な文字を含む後の位置を見つけて、隣接する文字を入れ替えて左に移動します。 これは正しいです。隣接する各移動は、許可される操作の 1 つであるためです。 ただし、次のような文字列では、`222...111...`、大きなブロック全体ですべてのキャラクターを移動するには、大量のスワップが必要となり、シミュレーション自体がそれらすべてを実行します。 演算数は 2 次になる可能性があります。 

重要な点は、スワップをシミュレートする必要がないということです。 移動する必要があるすべてのキャラクターの移動距離が答えに影響します。 最終的な交互パターンを決定すると、どの位置に含めるべきかが正確にわかります。`1`文字。 現在の位置を比較できます`1`それらのターゲット位置の文字。 

現在の`1`ポジションは`a[0], a[1], ...`そしてターゲット`1`ポジションは`b[0], b[1], ...`。 両方の配列がソートされているため、最初の現在の配列と一致します。`1`最初のターゲットと`1`、2 番目と 2 番目、というように合計の最小の動きを与えます。 の合計`abs(a[i] - b[i])`位置の数を数えます`1`キャラクターは移動する必要がありますが、交換するたびに 1 つずつ移動します`1`そして1つ`2`同時に行われるため、スワップ数はこの値の半分になります。 

最終的に考えられるパターンは 2 つだけです。 コストを計算します`1212...`そして`2121...`そして小さい方を取ります。

 ## アルゴリズムのチュートリアル

 1. キャラクターが配置される位置を収集します。`1`元の文字列に表示されます。 すべてのターゲット文字列にはまったく同じ数があるため、`1`このリスト サイズは、考えられるすべてのターゲットを記述するのに十分です。 
2. 対象となるパターンを確認します。`1`ゼロベースのインデックスを使用して、偶数のインデックスごとに配置する必要があります。 現在と比較してください`1`positions with these desired positions and add their movement distances. Divide the result by two to get the number of swaps.
 3. 逆のパターンを確認します。`1`奇数のインデックスごとに配置する必要があります。 同じ計算により、2 番目に考えられる最終的な配置のコストが得られます。 
4. 2 つのコストのうち小さい方を出力します。 有効な最終文字列はすべて、これら 2 つの交互パターンのいずれかでなければならないため、他の配置を考慮する必要はありません。 

機能する理由: 隣接する入れ替え中に、等しい文字の順序が変わることはありません。 最初`1`元の文字列の左から 1 番目になる必要があります`1`ターゲット文字列内で、それを他の場所に割り当てると、より遠くまで移動し、合計の移動量が増加するためです。 同じ議論が以下のすべてに当てはまります`1`。 全員の動きの合計が`1`スワップごとに文字が交換されるため、文字数はスワップ数の 2 倍に等しくなります。`1`と`2`正確に 1 つ移動します`1`一つのポジションごとに。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    ones = [i for i, c in enumerate(s) if c == '1']

    def cost(start):
        total = 0
        for idx, pos in enumerate(ones):
            target = start + 2 * idx
            total += abs(pos - target)
        return total // 2

    print(min(cost(0), cost(1)))

if __name__ == "__main__":
    solve()
```リスト`ones`すべての現在の位置を保存します`1`文字。 これで十分な情報です。`2`文字は残りの位置によって自動的に決定されます。 

ヘルパー関数は、`1`が表示されるはずです。 の値`0`を表します`121212...`、値は`1`を表します`212121...`。 ターゲット位置は次のように生成されます。`start + 2 * idx`。 

2で割るのは微妙な部分です。 合計は、すべての合計ステップ数を測定します。`1`キャラクターが旅をする。 単一の隣接スワップで 1 つ移動します`1`1 つの位置と 1 つの位置を移動します`2`反対方向の 1 つの位置なので、その動きはカウントされます`1`文字数はスワップ数のちょうど 2 倍です。 

二分検索やシミュレーションがないため、アルゴリズムは文字列を一定の回数だけスキャンします。

## テストケース```python
import sys
import io

def solution(data: str) -> str:
    sys.stdin = io.StringIO(data)
    input = sys.stdin.readline

    n = int(input())
    s = input().strip()

    ones = [i for i, c in enumerate(s) if c == '1']

    def cost(start):
        total = 0
        for i, pos in enumerate(ones):
            total += abs(pos - (start + 2 * i))
        return total // 2

    return str(min(cost(0), cost(1))) + "\n"

 ## 特殊なケース

 すでに交互になっている場合:```
2

```の位置`1`は`[0]`。 最初のパターンは、`1`位置にある`0`、動きはゼロです。 2番目のパターンは、その位置に配置したい`1`、1つの動きを与えます。 最小値は`0`したがって、アルゴリズムは文字列を変更しないままにします。 

長いブロックの場合:```
8
22221111
```の`1`ポジションは`[4,5,6,7]`。 ターゲットに向けて`12121212`、希望の位置は次のとおりです。`[0,2,4,6]`。 動きは、`4 + 3 + 2 + 1 = 10`、与える`5`交換します。 ターゲットに向けて`21212121`、希望の位置は次のとおりです。`[1,3,5,7]`、動きを与える`3 + 2 + 1 + 0 = 6`、つまり`3`交換します。 アルゴリズムは小さい方の値を返します。 

隣接する競合が重なる場合:```

```ある`11`真ん中に。 最適な変更は、不良ペアを個別に修正しないことです。 ターゲット`2121`は 1 文字を 1 位置ずつ移動する必要があるため、計算される移動は合計 2 位置となり、答えは 1 回の交換になります。 このアルゴリズムは、局所的なパターンをカウントするのではなく、最終的な変位を測定するため、これを捕捉します。
