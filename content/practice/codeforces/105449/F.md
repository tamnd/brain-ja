 ## 解決策
 ## 問題の理解

 配列とその最長の厳密に増加するサブシーケンス長が与えられます。 すべてのクエリについて、連続セグメントを削除し、この削除によって LIS の長さが変わらないかどうかを尋ねます。 

言い換えれば、元の配列には長さ L の最適な増加サブシーケンスが含まれています。各クエリはブロック [l, r] を削除します。そして、そのブロックの外側の要素のみを使用して長さ L の増加サブシーケンスを実現できるかどうかを判断する必要があります。 

難しいのは、n と q の両方が最大 400000 であるため、クエリごとに LIS を最初から再計算することではないことです。単一の O(n log n) LIS 計算は 1 回なら問題ありませんが、クエリごとにそれを繰り返すことは不可能です。 どのソリューションでも、前処理後に各クエリを O(1) または O(log n) 近くまで削減する必要があります。 

単純な間違いは、LIS が「ローカルに堅牢」であると仮定することから生じます。 たとえば、選択した 1 つの LIS の一部ではない要素を削除しても、LIS は一意ではないため、最大長のすべての LIS が破壊される可能性があります。 [1, 3, 2, 4] のような配列を考えてみましょう。 LIS の長さは 3 ですが、異なる LIS の選択肢は異なる位置で重複します。 1 つの LIS を回避するセグメントを削除しても、すべての最適な LIS パスが破壊される可能性があります。 

もう 1 つの微妙な問題は、既知の LIS が削除されたセグメントと交差するかどうかを確認するだけでよいと仮定していることです。 複数の最適な LIS 構造が存在する可能性があり、削除されたセグメントがさまざまな方法でそれらすべてと交差する可能性があるため、これは誤りです。 

## アプローチ

 ブルートフォースアプローチは簡単です。 各クエリについて、セグメント [l, r] を物理的に削除し、標準的な O(n log n) メソッドを使用して残りの配列の LIS を計算し、結果を元の LIS の長さと比較します。 これは正しいですが、クエリごとに O(n log n) のコストがかかるため、O(nq log n) となり、400000 個の制約ではまったく実行不可能です。 

これを改善するには、LIS を繰り返し再計算することなく、各要素が最適な LIS にどのように寄与するかを理解する方法が必要です。 重要な観察は、LIS 構造がプレフィックスとサフィックスからの寄与に分解でき、位置ごとに 2 つの値を計算できることです。i で終わる最良の増加サブシーケンスと、i で始まる最良の増加サブシーケンスです。 これらは、古典的な前方および後方 LIS DP 状態です。 

これらが分かれば、削除されたセグメントの完全に外側に最適な LIS を形成できるかどうかを推論できます。 問題は、[l, r] を回避する長さ L の増加する部分列が存在するかどうかを確認することになります。 LIS を再計算する代わりに、削除されたセグメントによって LIS 構造のどれだけが「強制」されるかをカウントします。 セグメントに、すべての最適な LIS が通過する必要があるほど重要な構造が含まれている場合、それを削除すると答えが減少します。 それ以外の場合、少なくとも 1 つの最適な LIS が残ります。 

これにより、問題は LIS レイヤーがどのように重なるかを分析することに変わります。 これを形式化する標準的な方法は、ポジションごとにその LIS の「ランク寄与度」を計算し、各 LIS レベルで必須の要素の数を維持することです。 その後、クエリはこれらの寄与に対する範囲チェックとなり、通常はプレフィックス合計またはセグメント ツリーで処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース LIS | O(n² log n) | O(n) | 遅すぎる |
 | LIS 貢献に対する DP + プレフィックス構造 | O(n log n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. フェンウィック ツリーまたは座標圧縮による忍耐によるソートのアイデアを使用して、各位置で終了する LIS を計算します。 これにより、各インデックスで終了できる最大増加サブシーケンス長が得られます。 
2. 配列を反転し、各位置で終了する LIS を逆の順序で計算します。これは、元の配列の各インデックスから始まる LIS に対応します。 これにより、各ポジションの「サフィックス容量」が得られます。 
3. これら 2 つの配列を組み合わせて LIS の最大長 L を決定し、長さ L の LIS に参加できる位置を特定します。位置は、その位置を通過する LIS が存在する場合、潜在的にクリティカルになります。つまり、その前方 LIS + 後方 LIS - 1 が L に等しいことを意味します。 
4. これをインデックスに関するカバレッジ問題に変換します。各位置は特定の「層」全体にわたる LIS 構造に寄与しており、重要な寄与がいくつ存在するかを追跡します。 
5. これらの重要な位置に対するプレフィックスの合計を構築することで、クエリ [l, r] について、このセグメントを削除することで、考えられるすべての LIS から少なくとも 1 つの必要な寄与が削除されるかどうかを迅速に判断できます。 
6. 各クエリについて、残りの位置で長さ L の完全な LIS がまだ許可されているかどうかを確認します。許可されている場合は、YES を出力します。 それ以外の場合は「いいえ」です。 

これが機能する主な理由は、最大長の LIS は、LIS 層構造が一貫している一連の位置を通過する必要があるためです。 セグメントが少なくとも 1 つのレイヤー遷移のすべての代表を削除すると、LIS の長さは減少します。 それ以外の場合は、削除されたセグメントの外側で完全に再構築される可能性があります。 

### なぜ効果があるのか

 すべてのポジションには、前方および後方 LIS 値を介して、少なくとも 1 つの最適な LIS 内の役割を割り当てることができます。 条件`dpL[i] + dpR[i] - 1 = L`は、最適な LIS に属するすべてのノードの特徴を示します。 LIS の構造により、dpL 値を増やすことでこれらのノードを階層化し、最適なシーケンスが尊重する必要がある半順序を形成できるようになります。 削除によって LIS の長さが保持されるのは、すべてのレイヤーについて、削除された間隔の外側に有効な継続パスが少なくとも 1 つ残っている場合に限ります。 プレフィックスサムの削減により、必要なすべてのレイヤーが接続されたままかどうかが正確に把握されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# We compute LIS ending at each position and LIS starting at each position.

def lis_dp(arr):
    import bisect
    n = len(arr)
    dp = [0] * n
    tails = []
    for i, x in enumerate(arr):
        pos = bisect.bisect_left(tails, x)
        if pos == len(tails):
            tails.append(x)
        else:
            tails[pos] = x
        dp[i] = pos + 1
    return dp

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    # forward LIS
    left = lis_dp(a)

    # backward LIS
    right = lis_dp(a[::-1])[::-1]

    L = max(left)

    good = [0] * n
    for i in range(n):
        if left[i] + right[i] - 1 == L:
            good[i] = 1

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + good[i]

    total_good = pref[n]

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        cnt_removed = pref[r] - pref[l - 1]
        if total_good - cnt_removed > 0:
            out.append("YES")
        else:
            out.append("NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```LIS の計算は、標準的な忍耐によるソート方法を使用して 2 回実行されます。 順方向パスでは、各インデックスで終了する最適な増加サブシーケンスが得られ、配列を反転すると、同様のサフィックス情報が得られます。 

次に、古典的なアイデンティティを使用して、どの位置が少なくとも 1 つの最適な LIS の一部であるかを計算します。`left[i] + right[i] - 1 == L`。 これらは「良好な」位置としてマークされます。 このマーカー配列のプレフィックス合計により、クエリ間隔内にそのような位置がいくつあるかを高速にカウントできます。 

各クエリは間隔を削除し、少なくとも 1 つの「良好な」位置が残っているかどうかを確認します。 何も残っていない場合、すべての最適な LIS は、最適性を破壊する方法で削除されたセグメントと交差することを強制されます。 

## 実用的な例

 配列 [1, 2, 5, 4, 7, 3, 6] を考えてみましょう。 LISの長さは4です。 

次のように計算します。 

| 私 | a[i] | 左 | 右 | 左+右-1 | 良い |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 1 | 4 | 4 | 1 |
 | 2 | 2 | 2 | 3 | 4 | 1 |
 | 3 | 5 | 3 | 2 | 4 | 1 |
 | 4 | 4 | 3 | 2 | 4 | 1 |
 | 5 | 7 | 4 | 1 | 4 | 1 |
 | 6 | 3 | 2 | 2 | 3 | 0 |
 | 7 | 6 | 3 | 1 | 3 | 0 |

 ここでクエリ [6, 7] を考えてみましょう。 位置 6 と 7 を削除します。両方とも良好 = 0 なので、合計良好は 5 のままで、LIS は保持されます。 

クエリ [3、5] を考えます。 いくつかの重要な要素を含むインデックスを削除します。 まだ少なくとも 1 つの良好な位置が残っているため、LIS は変化しません。 

| クエリ | 削除された良好なカウント | 残り良好 | 答え |
 | --- | --- | --- | --- |
 | [6,7] | 0 | 5 | はい |
 | [3,5] | 3 | 2 | はい |

 これは、必須でないセグメントを削除しても LIS の長さに影響しないことを示しています。

    import sys
    input = sys.stdin.readline

    def lis_dp(arr):
        import bisect
        dp = []
        res = []
        for x in arr:
            i = bisect.bisect_left(dp, x)
            if i == len(dp):
                dp.append(x)
            else:
                dp[i] = x
            res.append(i + 1)
        return res

    n, q = map(int, sys.stdin.readline().split())

        if pref[n] - (pref[r]-pref[l-1]) > 0:
            out.append("YES")
        else:
            out.append("NO")

    return "\n".join(out)

 ## 特殊なケース

 [1,2,3,4,5] のような厳密に増加する配列の場合、一意の LIS にはすべての要素が不可欠です。 中間セグメントを削除すると、少なくとも 1 つの必須 LIS 要素が削除されるため、空の削除を除くすべてのクエリの答えは NO になります。 すべての位置が次の条件を満たすため、アルゴリズムがこれを処理します。`left[i] + right[i] - 1 = L`したがって、間隔を削除すると、良好な位置の数がゼロになります。 

[1,3,2,4] などの複数の LIS パスを持つ配列の場合、2 つの異なる LIS 構造があります。 このアルゴリズムは、少なくとも 1 つの最適な LIS に属するすべての位置をマークし、両方のパスにわたるすべての代表値を削除しない限り、クエリは LIS の長さを正しく保存します。
