 ## 解決策
 ## 問題の理解

 グリッドを次の整数で埋める必要があります。$0$に$2^c - 1$, ここで、各整数は次の部分集合を表します。$c$バイナリ表現による色。 もし$k$セル値の - 番目のビットは$1$、そのセルは色に属します$k$。 

3 つの制約が構築を支配します。 まず、ゼロ以外のすべての値$x$少なくとも 1 回、最大 20 回出現する必要があります。 2番目に、色ごとに$k$、値がビットを持つセルのセット$k$に等しい$1$4 方向の隣接下で単一の接続コンポーネントを形成する必要があります。 第三に、グリッドの寸法は以下を超えてはなりません。$1500 \times 1500$。 

重要な問題は、接続性は個々の価値観に関するものではなく、少し共有する価値観の結合に関するものであるということです。 単一の値が複数回出現する可能性がありますが、その出現はすべて、そのビットマスクに応じて複数の色成分に同時に寄与します。 これにより、共有配置を通じてすべての色が結合されます。 

制約$c \le 17$指数構造を許容できるほど十分小さい$c$しかし、十分な大きさがあるため、厳密なグリッドでは単純な色ごとの幾何学的分離は不可能です。 The bound “each value appears at most 20 times” is crucial because it allows us to replicate values to fix connectivity without worrying about excessive grid size.

 単純な考えは、各マスクを個別に割り当て、その出現箇所を任意に配置することです。 カラー クラスがグリッド全体に分散し、接続性が保証されないため、これはすぐに失敗します。 Another naive attempt is to arrange cells in a 1D snake and hope each color’s ones appear in a contiguous segment, but this forces a global ordering that cannot simultaneously satisfy all$c$independent bit constraints.

 本当の障害は、接続性が値ごとに強制されるのではなく、ジオメトリから自動的に「継承」される構造が必要なことです。 

## アプローチ

 ブルートフォースの考え方では、各マスクを独立して扱います。最初にすべての値を配置し、次にビットごとに BFS チェックを実行し、セルを移動して接続を修正しようとします。 1 つのセルを移動すると最大で影響を受けるため、これは失敗します。$c$接続構造を一度に作成でき、プレースメントの検索スペースは$(1500^2)^{2^c}$in the worst case, completely infeasible.

 重要な点は、実際には任意の配置が必要ないということです。 各ビットについて、そのビットを含むすべてのセルが単一の接続された「領域」内に存在することを確認するだけで済みます。 各色を接続された幾何学的足場に対応させ、そのビットを持つすべてのセルがその足場上に配置されるようにすることができれば、条件は自動的になります。 

これは、視点を逆転することを示唆しています。つまり、接続を引き起こす値について考える代わりに、最初にビットの明示的な接続構造を構築し、次にその中に値を埋め込みます。 

The construction that achieves this is to create$c$薄いグリッド レイアウト内の独立したモノトーンの「レール」。すべてのセルが、それに含まれるビットに対応するすべてのレール上に配置されるように配置されます。 各レールは接続されたパスであるため、選択したセル間の遷移が同じレール ジオメトリ内にある限り、レール上で選択されたセルのサブセットは接続されたままになります。 重要なトリックは、値が 2 つ存在する場合は常に、各ビットのそれらを接続するために必要なすべてのパスが同じビットレール システム内に留まるようにすることです。 

これを具体的かつ単純にするために、高さのグリッドを使用します。$c$そして十分な広さの幅。 各行はビットに対応します。 We construct in row$k$グリッドのセグメントをカバーする連続パス。 その行のすべてのセルは色に属します$k$。 次に、値を列に配置し、各列に慎重にマスクを割り当て、そのビットに対応する行にのみ配置します。 各行は 1 つの接続された線であるため、すべてのカラー クラスは線のサブセグメントになり、接続されます。 

「値ごとに最大 20 回の出現」という制約を尊重するため、行ごとに 20 回を超えてマスクを再利用することはありません。また、値が過度に多くのコピーを蓄積しないように、出現を列ごとに分散します。 

これにより、問題が 2D のグローバル接続制約から単調な 1D 構造に沿った独立した接続に軽減されます。

 ## アルゴリズムのチュートリアル

 グリッドを行ごとに明示的に構築します。 

1. 高さを次のように設定します。$h = c$そして幅を選択してください$w = 20 \cdot (2^c - 1)$。 これにより、ゼロ以外のマスクごとに最大 20 個のコピーを配置するのに十分なスペースが保証されます。 
2. 各ビットについて$k$、列を予約します$k$色の「運び手」として$k$。 行全体がその色の接続されたバックボーンとして機能します。 
3. すべてのマスクを反復処理します$x$から$1$に$2^c - 1$。 各マスクについて、それを 20 個の連続する列に割り当て、各マスクが発生するたびに、$x$別個の列ブロックに配置されます。 
4. 列内$j$マスクに割り当てられる$x$、私たちは価値を置きます$x$すべての行に$k$どこで$k$-番目のビット$x$は$1$、そして私たちは置きます$0$他の場所で。 これにより、サブセット構造が垂直方向の配置に直接エンコードされます。 
5. 各行が連続しているため、すべての色が$k$ビットを含むすべてのマスクの投影を正確に表示します$k$、列全体に配置されます。 このような各射影はマスク ブロックごとに割り当てられた各行セグメント内で連続しており、ブロック間の遷移は列全体を通じてのみ発生するため、結合は接続されたままになります。 
6. 結果のグリッドを出力します。 

重要な設計上の選択は、列でオカレンスを分離し、行で各ビットの接続を確保することです。 

### なぜ効果があるのか

 少し修正してください$k$。 ビットのあるすべてのセル$k = 1$並んで横たわる$k$以下を含むマスクに対応する列間隔のコレクション全体にわたって$k$。 行内$k$の場合、各マスクは列の連続したブロックを占有するため、これらの間隔は連続して表示されます。 異なるマスクが値空間内で互いに素であっても、行内のそれらの幾何学的表現は$k$隣接するセグメントのシーケンスを形成します。 行に沿った隣接性は連続しているため、これらすべてのセグメントの結合は接続されます。 

各値は 1 つの列ブロックに正確に表示され、垂直方向に最大 20 列を占めるため、頻度の制約は満たされます。 各ビットが独自の専用行に適用されるため、接続性は各ビットに対して独立して保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    c = int(input())
    
    max_mask = (1 << c) - 1
    
    h = c
    w = 20 * max_mask
    
    grid = [[0] * w for _ in range(h)]
    
    col = 0
    
    for mask in range(1, max_mask + 1):
        for rep in range(20):
            if col >= w:
                break
            for k in range(c):
                if (mask >> k) & 1:
                    grid[k][col] = mask
            col += 1
    
    print(h, w)
    for row in grid:
        print(*row)

if __name__ == "__main__":
    main()
```このコードは、ビットごとに 1 行のグリッドを構築します。 各マスクは最大 20 個の連続した列で繰り返されます。 各列内に、マスクのビットに対応する行を正確に設定します。 

重要な点は、各列が独立しているため、マスクが切断された領域に広がらず、各行が接続性が維持された連続構造を形成することです。
