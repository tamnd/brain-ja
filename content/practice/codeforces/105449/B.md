 ## 解決策
 ## 問題の理解

 長さの隠し文字列が与えられます$n$、最初から構築されました$k$ラテン文字の小文字。 文字列は直接与えられません。 代わりに、それを一意に決定する 2 つの情報が与えられます。 

まず、文字の正確な複数セット、つまりそれぞれの文字が何回表示されるかを知らされます。$k$文字が表示されます。 これにより、頻度分布は修正されますが、位置は修正されません。 

次に、すべての開始位置の順列が与えられます。$1 \dots n$、辞書順に並べ替えたときの、不明な文字列のすべての接尾辞の順序を表します。 したがって、位置が$i$位置の前に表示されます$j$、次にサフィックス$s[i..]$辞書編集的には接尾辞より小さい$s[j..]$。 

タスクは、サフィックスの順序と文字数の両方が一致する元の文字列を再構築することです。 このステートメントは一意性を保証します。 

この制約は、考えられるすべての文字列を試す単純な試みは完全に不可能であることを意味します。 固定頻度で文字列を生成する場合でも、指数関数的になります。$n$、各候補のサフィックスの順序を検証するにはコストがかかります$O(n^2)$、天文学的に長い実行時間につながります。$n$まで$2 \cdot 10^5$。 

2 番目の単純なアイデアは、文字列を再構築し、サフィックスを繰り返し比較して正確さを検証することです。 また、接尾辞の比較は最悪の場合線形であり、多くの接尾辞が必要になる可能性があるため、これは二次関数またはさらに悪い動作に変質します。 

本当の難しさは、サフィックスの順序付けによってグローバルな制約が作成されることです。つまり、位置での決定です。$i$affects comparisons between suffixes starting at different positions and shifted indices.

 A common pitfall is treating the suffix array as if it only constrains adjacent pairs locally. That is not sufficient because equality of prefixes between suffixes propagates constraints further down the string. Another subtle issue is assuming that once a character is placed, comparisons become independent. In reality, a decision can change the first mismatch position between multiple suffix pairs.

 ## アプローチ

 ブルートフォース再構築では、指定された文字数に一致するすべての文字列が生成され、そのサフィックス配列が指定された順列と一致するかどうかがチェックされます。 これは正しいですが、実行不可能です。 枝刈りを行っても、検索スペースは$\frac{n!}{c_1!c_2!\dots c_k!}$、各検証にはサフィックスの構築または比較が必要であり、少なくとも$O(n^2)$候補者ごとに。 これはすぐに爆発します$n = 2 \cdot 10^5$。 

重要な点は、実際には完全な接尾辞を比較する必要がないということです。 サフィックス配列は、順序内のすべての隣接するペアについて、最初の違いが厳密な不等式を作成する必要がある場所を示すだけです。 つまり、隣接するすべてのペアが$(i, j)$制約が生じます。サフィックスが異なる最初の位置で、$i$の文字より厳密に小さくする必要があります$j$。 

これにより、問題は文字列全体の比較から、未知の位置で生じる一連の局所的な不等式制約の強制へと移行します。 課題は、すべての制約と頻度制限に従って一貫して文字を割り当てながら、各隣接する接尾辞のペアで最初の違いがどこで発生するかを発見することになります。 

最初に文字列を決定してサフィックスの順序を検証する代わりに、2 つのサフィックスが「強制的に」異なる場合は常に、最終的に不等式が成立する位置を確実に割り当てながら文字列を構築します。 これは、制御された順序で位置を処理し、どの位置に文字を割り当てることができるかを維持することで管理できます。

 ## アルゴリズムのチュートリアル

 サフィックス配列の順序を処理し、それを位置間の制約に変換します。 接尾辞の順序で隣接するすべてのペアについて、接尾辞の先頭からそれらが異なる必要がある最初の位置が見つかるまで、それらの比較がどのように展開されるかをシミュレートします。 

文字列がまだわかっていないため、すでに解決されているインデックスをスキップできる位置にわたる動的な構造を維持します。 これは通常、サフィックス内の次の未解決の位置に効率的にジャンプできるように、DSU の「ネクスト ポインター」を使用して実装されます。 

### ステップ

 1. すべてのポジションを未割り当てとして初期化します。 各文字の残りの文字数も維持します。 
2. 隣接するサフィックスのペアごとに開始します$(i, j)$指定されたサフィックス配列順序で、すでに固定された位置をスキップする DSU を使用して 2 つのサフィックスに対する同期スキャンをシミュレートします。 目標は、2 つの接尾辞が異なる必要がある最初のインデックスを見つけることです。 
3. このスキャン中、文字を固定していない限り、両方のサフィックスは未割り当ての位置で一致するかのように動作します。これは、区別する文字がまだ導入されていないためです。 DSU を使用して両方のポインターを進め続けます。 
4. 2 つの接尾辞間の最初の未解決の比較位置に到達すると、方向制約を記録します。位置にある文字$i + t$位置の文字より厳密に小さくなければなりません$j + t$。 この制約を位置間の依存関係として保存します。 
5. すべての制約が収集されたら、最小文字から最大文字まで文字を割り当てます。 各ステップで、現在使用可能な最小の文字を安全に割り当てる位置を選択します。 位置の割り当てが制約からすでに適用されている不等式の要件に違反しない場合、その位置は安全です。 
6. 選択した文字の利用可能な数を減らし、位置を割り当て済みとしてマークし、DSU 構造を更新して、今後のスキャンでその位置をスキップします。 

### なぜ効果があるのか

 サフィックス配列は、すべての隣接するペアについて、最初の不一致が 2 つの対応する文字間の厳密な順序を定義することを保証します。 この不一致の正確な位置を構築時まで延期することで、制約が避けられない場合にのみ制約が適用されます。 DSU 構造により、必要以上に早く不一致を誤って想定することがなくなります。 すべての制約は最初に考えられる分岐点から派生するため、すべての制約を満たすことで、すべての接尾辞の比較が指定された順序と一致することが保証されます。 

最小文字から上への貪欲な割り当てでは、辞書編集的な順序がグローバルに尊重されます。つまり、位置に小さい文字が割り当てられると、その位置が別の位置よりも小さいことを要求する後の制約に違反することはありません。これらの制約は、構築中にすでに構造的に強制されている最初の不一致点でのみアクティブになるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n + 2))

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def remove(self, x):
        self.p[x] = self.find(x + 1)

def solve():
    n, k = map(int, input().split())
    sa = list(map(int, input().split()))
    cnt = list(map(int, input().split()))

    dsu = DSU(n + 2)
    s = [-1] * (n + 1)

    # constraints: for simplicity store adjacency lists
    less = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)

    def first_diff(i, j):
        # find first differing position between suffixes i and j
        x, y = i, j
        while x <= n and y <= n:
            x = dsu.find(x)
            y = dsu.find(y)
            if x > n or y > n:
                return None
            if x == y:
                # same position, move both
                dsu.remove(x)
                x += 1
                y += 1
                continue
            return (x, y)
        return None

    # build constraints
    for idx in range(len(sa) - 1):
        i, j = sa[idx], sa[idx + 1]
        res = first_diff(i, j)
        if res:
            u, v = res
            less[u].append(v)
            indeg[v] += 1

    # nodes with no incoming constraints are candidates
    from collections import deque
    q = deque([i for i in range(1, n + 1) if indeg[i] == 0])

    # assign greedily by letters
    cur = 0
    for ch in range(k):
        for _ in range(cnt[ch]):
            # pick any available node (simplified greedy)
            while q and s[q[0]] != -1:
                q.popleft()
            if not q:
                break
            u = q.popleft()
            s[u] = ch
            for v in less[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    q.append(v)

    print("".join(chr(ord('a') + x) for x in s[1:]))

if __name__ == "__main__":
    solve()
```この実装では、サフィックス比較のシミュレーション中に、すでに検討されている位置をスキップするように DSU が維持されます。 の`first_diff`ルーチンは、2 つの接尾辞が強制的に分岐する最初の位置を見つけ、それによってこれら 2 つの位置の間に有向制約が作成されます。 すべての制約が構築されると、貪欲な割り当てにより、接尾辞の比較によって引き起こされる依存関係の順序を尊重しながら、可用性に応じて文字が分散されます。 

微妙な点は、DSU の更新は、一致する位置に沿って進むときと、割り当てられた位置を削除するときの両方で行われることです。 これにより、比較では常に無関係なインデックスがスキップされ、時間の経過とともに線形性が維持されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、複数のサフィックス ペアによって重なり合う制約が生成され、最終的には同じ位置が含まれる場合です。 DSU ベースのスキップにより、位置が解決されると、サフィックス比較の一部として再検討されることがなくなるため、制約が重複したり誤って適用されたりすることがなくなります。 

もう 1 つのケースは、文字が繰り返されているため、長いプレフィックスに対してサフィックスが同一である場合です。 そのような状況では、比較は制約が生成される前にはるかに進んでしまいます。 DSU は、すでに固定された位置をスキップすることを保証するため、大きなブロックが一致する場合でもウォークは直線的なままになります。 

最後のエッジケースは、サフィックス配列がすでにほぼソートされているか、完全に反転されている場合です。 その場合、制約グラフはチェーンになり、貪欲な割り当ては、構造的な順序のみではなく可用性によって駆動されるため、文字数を考慮しながら、あいまいさなしに単純にそのチェーンに従います。
