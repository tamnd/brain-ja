 ## 問題の理解

 私たちに与えられた自動販売機には、いくつかの隠しコンパートメントがあり、それぞれにいくつかの缶が入っています。 同じ数のボタンもありますが、ラベルが失われているため、各ボタンは固定の未知の順列を介して正確に 1 つのコンパートメントに密かに配線されています。 

ボタンを押すと、割り当てられたコンパートメントと効果的に対話します。そのコンパートメントに缶がまだ残っている場合は 1 缶を受け取りますが、そうでない場合は何も受け取りません。 この機械は、缶が分配されたかどうかだけを教えてくれますが、缶がどの区画から来たのかは決して教えてくれませんし、残りの在庫レベルを観察することもありません。 

目標は、少なくとも次のことを保証するボタン押下の適応戦略を設計することです。`k`最悪の場合、コンパートメントへのボタンの隠蔽割り当てが行われる可能性があります。 非表示の順列がどのように選択されるかに関係なく、常に十分な最小の押下回数が必要です。 

重要な問題は、私たちが部分的な情報の下で活動していることです。 コンパートメントを直接識別することはできませんが、ボタンを繰り返し操作することで間接的にコンパートメントを使い果たすことができます。 

この制約は、どの解も線形または線形に近い必要があることを示唆しています。`O(n log n)`テストケースごとに合計なので、`n`すべてのテストケースにわたって、`2 · 10^5`。 これにより、多くの適応戦略を繰り返し試行したり、割り当てを分岐したりするシミュレーションは除外されます。 

1 つまたは 2 つの小さなコンパートメントを除いてすべてのコンパートメントが大きい場合、微妙なエッジ ケースが発生します。 たとえば、次の場合`a = [1, 1, 100]`そして`k = 2`、素朴なアプローチでは、小さなコンパートメントを空にするために無駄なプレスを避けることができると仮定するかもしれませんが、実際には、コンパートメントに完全に触れる戦略は、最終的にコンパートメントが枯渇したときに避けられない余分なコストを支払うことになります。 この「最後の失敗したプレス」は見落とされやすく、貪欲な推論における誤った答えの中心的な原因となります。

 ## アルゴリズムのチュートリアル

 この問題を、コンパートメント サイズの配列にわたる決定論的な累積プロセスに変換します。 

### ステップ

 1. 配列をソートする`a`降順ではない順に。 

これは、最小のコンパートメントが最初に効果的に枯渇し、到達するまでの枯渇イベントの数を最大化する最悪のシナリオをモデル化します。`k`。 
2. 2 つの変数を初期化します。`sum = 0`回収した缶や`used = 0`完全に使い果たされたコンパートメントの数。 
3. ソートされた配列を最小から最大まで繰り返します。 それぞれの値について`x`：

もし`sum + x < k`、コンパートメント全体を取り上げます。 増やします`sum`による`x`そして増加します`used`による`1`というのは、このコンパートメントは目標に到達する前に完全に使い果たされてしまうからです。 

もし`sum + x >= k`、正確に到達するために、このコンパートメントの一部のみを取り上げます`k`すぐに中止してください。 障害イベントは決して観察されないため、このコンパートメントは使い果たされたものとしてカウントされません。 
4. 答えは次のとおりです。`k + used`。 の`k`期間は成功した印刷回数をカウントし、`used`コンパートメントの消耗によって引き起こされる避けられないプレスの失敗をカウントします。 

### なぜ効果があるのか

 すべての成功缶は、結果を生み出す 1 回のプレスに対応します。 以下のプレスの成功数を減らす戦略はありません。`k`。 唯一のあいまいさは、プレスして缶が出るかどうかであり、「缶なし」という結果を得る唯一の方法は、割り当てられたコンパートメントがすでに空になっているボタンを押すことです。 

このような空のプレスは、コンパートメントが完全に消費された瞬間にのみ発生します。 完全に消費された各コンパートメントは、そのような空の印刷機を 1 台だけ提供し、コンパートメントの容量が使い果たされると、いかなる戦略もそのコストの支払いを避けることはできません。 敵は小さなコンパートメントを最初に消費することを強制できるため、到達する前に使い果たされたコンパートメントの数を最大化することができます。`k`、昇順に並べ替えると、最悪の場合の構造がキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        a.sort()
        
        s = 0
        used = 0
        
        for x in a:
            if s + x < k:
                s += x
                used += 1
            else:
                break
        
        print(k + used)

if __name__ == "__main__":
    solve()
```このソリューションはコンパートメントのサイズをソートするので、到達するまでに完全なコンパートメントが何個消費されるかを評価できます。`k`。 ループは、途中で使用された完全なセグメントの数をカウントしながら、しきい値に達するまで寄与を蓄積します。 最終的な答えは追加します`k`成功したすべての描画を対象として、避けられない失敗プレスに対応する消耗したコンパートメントの数を追加します。 

重要な実装の詳細はすぐに停止します`s + x >= k`最後のコンパートメントが必ずしも使い果たされるとは限らず、それをカウントすると誤って追加の失敗が追加されるためです。
