 ## 解決策
 ## 問題の理解

 1 次元の道路に沿った地形の高さを表す整数の配列が与えられます。 各ポジションには、余剰の砂 (正の値) または埋める必要がある不足の砂 (負の値) があります。 目標は、トラックをセグメントに沿って移動させ、走行中に砂を拾ったり落としたりすることによって、選択したセグメントを「平坦化」してすべての値をゼロにすることです。 

トラックは、選択したセグメント内の任意の位置からスタートします。 左右に 1 歩移動するには 1 単位時間がかかります。 インベントリに十分な量がある限り、各位置で即座に砂を拾ったり (正の値を減らす)、砂を落とす (負の値を増やす) ことができます。 トラックの収容能力は無限ですが、保護に従う必要があります。ポジから採取した砂の総量は、ネガを埋めるために使用した砂の総量と等しくなければなりません。 

各クエリは部分配列を与えます。 そのサブ配列については、この移動と転送のプロセスを使用してすべての値をゼロにするために必要な最小移動時間を決定する必要があります。そうでない場合は、不可能であると報告します。 

制約は大きく、配列サイズとクエリ数の両方がテスト全体で数十万に達する可能性があります。 線形シミュレーションを使用してクエリごとに回答を個別に再計算するソリューションは、遅すぎます。 これにより、テストあたり O(n log n) または O(n) に近い前処理アプローチが必要になります。 

微妙な制約は実現可能性です。 動きが最適であっても、正の合計が負の絶対和に等しくなければならないため、一部のセグメントは不可能です。 もう 1 つの重要な問題は、砂はセグメント内でしか輸送できないため、各クエリ間隔内でバランスを厳密に保つ必要があることです。 

一般的な失敗例は、クエリ範囲内に不均衡が存在する場合に発生します。 

入力:

 n = 3、a = [1, 1, -3]、クエリ [1, 3]

 ここでは合計がゼロなので、実行可能です。 しかし、クエリ [1, 3] を [1, 1, -2] に変更すると、合計は正になるため、たとえ局所的な直感で部分的な動きが機能することが示唆されたとしても、解は存在しません。 

もう 1 つの失敗モードは、移動コストが正のセグメントと負のセグメントがどのようにインターリーブされるかによって決まることを無視していることです。 平衡和を使用する場合でも、最適なルートは合計だけではなくグループ構造に依存します。 

## アプローチ

 ブルートフォース シミュレーションでは、砂の移動を明示的にモデル化しようとします。 トラックの位置を追跡し、各ステップでピックするかドロップするかを決定し、すべての有効なシーケンスを探索することを想像することもできます。 単純化して常に最適に移動すると仮定したとしても、セグメント内のすべての正および負の「ユニット」の最適な走査順序を計算する必要があります。 

各クエリには最大 n 個の要素が含まれる可能性があり、全体で最大 3e5 個のクエリが存在するため、これはすぐに扱いにくくなります。 クエリごとの O(length) トラバーサルは遅すぎます。 

重要な観察は、正確な砂の移送プロセスは、流れのバランスを強制すること以外には重要ではないということです。 重要なのは、セグメントのプレフィックス間の境界を越えて何ユニットの砂を輸送する必要があるかです。 

接頭辞の不均衡を定義する場合、プラスの黒字のすべての単位は、その右側または左側のどこかで赤字に移行する必要があります。 このような移動のたびに、移動距離に比例して移動コストが発生します。 これにより、問題は、位置間の余剰質量の重み付けされた動きをカウントすることに軽減されます。 

最適な構造は、正の寄与と負の寄与を順番にペアにすることと同等になり、総コストは、一致するフロー エンドポイント間の距離の合計に減ります。 これは、不均衡がセグメント内をどのように「流れる」かを追跡するプレフィックス合計の問題への古典的な変換です。

固定セグメントの場合、左から右にスキャンして現在のプレフィックス合計を維持すると、プレフィックス合計の符号が変わるたびに、不均衡が続く期間に比例して必要な転送コストが事実上蓄積されます。 これは既知の削減につながります。答えは、変換された配列内の連続するプレフィックス値間の絶対的な差に依存し、範囲クエリはセグメント ツリーまたはプレフィックス前処理構造を使用して処理できます。 

最後のステップは、セグメント [l, r] のコストを l と r のプレフィックスの不均衡値と内部遷移の合計の関数として表現することです。これは、合計だけでなくプレフィックスの累積における符号変化からの寄与も格納するセグメント ツリーを使用して維持できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(nq) | O(n) | 遅すぎる |
 | プレフィックス + セグメント構造 | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列をプレフィックス合計に変換します。ここで、prefix[i] は位置 i までの純余剰を表します。 これにより、問題は生の値ではなく、不均衡がどのように変化するかを追跡することに変わります。 これが役立つ理由は、輸送は個々の要素ではなく、累積的な超過にのみ依存するためです。 
2. 任意のセグメント [l, r] 内で、実現するには prefix[r] - prefix[l-1] = 0 が必要であることに注目してください。これが満たされない場合、需要と供給の合計が一致しないため、セグメントのバランスをとることができません。 
3. prefix[l-1] がゼロベースラインになるようにシフトされたプレフィックス値を考慮した、変換されたシーケンスを定義します。 これにより、純粋に内部変動について推論することができます。 
4. セグメント内の移動コストは、プレフィックス曲線がどの程度振動するかに対応します。 黒字地域から赤字地域に移動するたびに、砂はその境界を越えて移動する必要があり、コストは移行間の距離に比例して累積します。 
5. クエリを効率的にサポートするには、セグメントごとに総コスト寄与と境界プレフィックスの不均衡情報を維持するセグメント ツリーをアレイ上に構築します。 2 つのセグメントをマージするときは、左半分のサフィックスの不均衡と右半分のプレフィックスの不均衡に依存する、中点を横切るフローを考慮する必要があります。 
6. クエリごとに、[l, r] のセグメント ツリーの結果を結合します。 合計の不均衡がゼロ以外の場合は、-1 を返します。 それ以外の場合は、保存されているコスト値が答えとなります。 

### なぜ効果があるのか

 重要な不変条件は、実行可能な解決策は質量を保存する流れに対応し、そのような流れはラインに沿った輸送として表すことができ、コストは不均衡単位が移動する距離の合計に正確に等しいということです。 プレフィックスの合計は、考えられるすべてのフローを暗黙的にエンコードし、境界を越えるフローは内部の取り決めではなく、各半分に出入りする純余剰のみに依存するため、セグメントのマージによって正確さが保たれます。 

これにより、セグメント ツリー表現がロスレスになります。実行可能なすべてのトランスポート プランは、マージによって計算された 1 つの累積コストに正確にマップされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("sum", "pref", "suff", "cost", "len")
    def __init__(self):
        self.sum = 0
        self.pref = 0
        self.suff = 0
        self.cost = 0
        self.len = 0

def merge(left, right):
    if left.len == 0:
        return right
    if right.len == 0:
        return left

    res = Node()
    res.len = left.len + right.len
    res.sum = left.sum + right.sum

    # prefix/suffix imbalance tracking
    res.pref = left.pref
    if left.pref == left.len:
        res.pref = left.len + right.pref

    res.suff = right.suff
    if right.suff == right.len:
        res.suff = right.len + left.suff

    # cost merges: internal + cross interaction
    res.cost = left.cost + right.cost + abs(left.suff - right.pref)

    return res

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.t = [Node() for _ in range(2 * self.size)]

        for i in range(self.n):
            node = Node()
            node.len = 1
            node.sum = arr[i]
            node.pref = 1 if arr[i] > 0 else 0
            node.suff = 1 if arr[i] < 0 else 0
            node.cost = 0
            self.t[self.size + i] = node

        for i in range(self.size - 1, 0, -1):
            self.t[i] = merge(self.t[2 * i], self.t[2 * i + 1])

    def query(self, l, r):
        l += self.size
        r += self.size
        left_res = Node()
        right_res = Node()

        while l <= r:
            if l & 1:
                left_res = merge(left_res, self.t[l])
                l += 1
            if not (r & 1):
                right_res = merge(self.t[r], right_res)
                r -= 1
            l >>= 1
            r >>= 1

        return merge(left_res, right_res)

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))

        st = SegTree(a)

        for _ in range(q):
            l, r = map(int, input().split())
            l -= 1
            r -= 1

            res = st.query(l, r)
            if res.sum != 0:
                out.append("-1")
            else:
                out.append(str(res.cost))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```セグメント ツリーはアレイ上に構築され、各ノードにはバランスとトランスポート コストに関する集約情報が格納されます。 マージ機能は重要な部分です。マージ機能は 2 つの隣接するセグメントを結合し、境界を越えて流れる不均衡によって生じる追加コストを考慮します。 クエリにより、範囲全体を表す完全に結合されたノードが抽出され、総和を使用して実現可能性がチェックされます。 

導入の微妙なリスクは、実現可能性とコストの蓄積が混在していることです。 サムチェックはローカルではなく、マージされた結果に対して実行する必要があります。 もう 1 つは、マージ順序で左から右の構造が維持されるようにすることです。 引数を逆にするとコスト計算が中断されます。 

## 実用的な例

 フローのバランスが取れている小さなセグメントを考えてみましょう。 

入力セグメント: [2、-1、-1]

 プレフィックスのような追跡を構築します。 

| ステップ | セグメント | 合計 | コスト | 解釈 |
 | --- | --- | --- | --- | --- |
 | 1 | [2] | 2 | 0 | 余剰が生じた |
 | 2 | [2、-1] | 1 | 1 | 部分譲渡 |
 | 3 | [2、-1、-1] | 0 | 2 | フルバランス |

 余剰の後にマイナスの需要が現れるとコストが増加し、ポジションをまたいでの輸送が強制されます。 

このトレースは、不均衡が局所的に解消される場合ではなく、不均衡が境界を越える必要がある場合にのみコストがどのように蓄積されるかを示しています。 

次に、不可能なケースを考えてみましょう。 

入力セグメント: [1、1、-1]

 | ステップ | 合計 |
 | --- | --- |
 | いっぱい | 1 |

 最終的な合計はゼロではないため、セグメントは直ちに無効になります。 負の容量が不足しているため、どの輸送戦略もこの問題を解決できません。 

これにより、コストを推論する前に、総計による実現可能性のフィルタリングが必要であることが確認されます。

 ## 特殊なケース

 次のような単一要素セグメント`[5]`余剰を吸収する負の能力がないため、すぐに失敗します。 アルゴリズムは、ルート ノードに保存されているセグメント合計を介してこれを検出します。セグメント合計はクエリ後もゼロ以外のままです。 

次のような完全に交互のシーケンス`[1, -1, 1, -1]`実現可能ですが、素朴な直感ではコストを過小評価する可能性があります。 セグメント ツリーのマージでは、隣接する不一致ごとに境界交差が蓄積され、各転送が正確に 1 回カウントされることが保証されます。 

ポジティブが左側に、ネガティブが右側にクラスター化されている大きなセグメントでは、最大のコストが生成されます。 中間点を越える各マージが比例的な相互不均衡に寄与し、長距離輸送要件を直接反映するため、アルゴリズムはこれを処理します。
