 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テストケースには、$n$小さなブロックであり、各ブロックにはちょうど 2 つの数字が含まれます。 これらのブロックの順序を任意に変更することはできますが、ブロック内の順序を変更することはできません。 ブロックの順序を選択した後、それらを 1 つの長さの配列に連結します。$2n$。 目標は、結果として得られる配列内の反転の数を最小限に抑えることです。反転は位置のペアです。$i < j$の値が$i$の値より大きいです$j$。 

したがって、唯一の自由は長さ 2 のセグメントの順列です。 各セグメント内では、その 2 つの値の相対的な順序は固定されています。 

重要な問題は、反転がグローバルであることです。 A bad placement of one pair can interact with many others, since both elements of each block can contribute inversions with both elements of other blocks.

 制約により、最大で$10^5$すべてのテスト ケースにわたる合計ペア。 それは二次関数を除外します$n$、さえ$O(n^2)$テストケースごとの比較は非常に遅すぎます。 解決策は本質的に次のようにする必要があります$O(n \log n)$または$O(n)$テストごとに。 

いくつかの危険な状況が重要になります。 

単純なアプローチでは、最初の要素、または最小値または最大値でブロックを並べ替えることが試行される可能性があります。 これは、最適な順序付けが単一の代表だけではなく、異なるブロックの両方の要素間の相互作用に依存するため、失敗する可能性があります。 

たとえば、ブロックについて考えてみましょう。$[1, 100]$そして$[50, 51]$。 最初の要素で並べ替えると、$[1,100],[50,51]$これにより、100 対 50 および 51 から多くの反転が生成されます。これらを反転すると、反転が大幅に減少します。 

もう 1 つの微妙な失敗ケースは、ブロックが内部的に増加または減少しているが、その寄与は他のブロックと相対的にその役割を交換するかどうかに依存する場合です。 

したがって、順序決定において各ブロックがどのように動作するかを捕捉するルールが必要です。 

## アプローチ

 ブルートフォース戦略では、すべての順列を試みます。$n$ブロック。 順列ごとに、連結された配列を構築し、フェンウィック ツリーまたはマージソートを使用して反転をカウントし、コストを計算します。$O(n \log n)$順列ごとに。 あるので$n!$順列、これは次のようになります$O(n! \cdot n \log n)$、でもそれは不可能です$n = 10$。 

2 つのブロックを隣り合わせに配置するときに実際に何が重要なのかを理解する必要があります。 2 つのブロックがあるとします。$(a,b)$そして$(c,d)$。 最初のブロックが 2 番目のブロックの前にある場合、寄与するクロスインバージョンは、次のブロックの数によって異なります。$a,b$より大きい$c,d$。 これは、各ブロックを、その要素が他のブロックと比較してどの程度「高い」か「低い」かによって要約する必要があることを示唆しています。 

重要な観察は、各ブロックがその最初の要素と 2 番目の要素の間の「遷移動作」を定義すると考えることができるということです。 各ブロック内で小さい要素を大きい要素の前に常に配置すると、不必要な内部反転が回避され、ブロック間の反転のみが問題になります。 

ここで重要な単純化: 各ブロックを次のようにソートした後、$(x_i \le y_i)$, ブロックを数直線上の区間として考えます。 最適な戦略は、ブロックを 2 番目の要素でソートすることです。$y_i$、つまり最大値です。 直観的には、最大値が小さいブロックは、将来のブロックで反転が発生する可能性が低いため、より早く出現するはずです。 

大きな最大値を持つブロックが早期に配置された場合、その大きな値により、後のブロックでより小さな値を持つ多くの反転が作成される可能性があります。 これが後に配置された場合、限定された形で以前のブロックにのみ影響し、この順序により貢献がグローバルに一貫した方向に整列されます。 

これにより、問題は次の基準で並べ替えられるようになります。$y_i$、各ブロックを次のように連結します。$[x_i, y_i]$。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. すべてのブロックについて、小さい値が最初になるように 2 つの値を並べ替えます。 これにより、ブロック内の反転は常に回避できるため、不要な内部反転が削除されます。 
2. すべてのブロックを 2 番目の値で降順でない順に並べ替えます。 2 番目の値は、このブロックが将来何回の反転を作成できるかの「リスク境界」として機能します。 
3. ソートされたブロックをその順序で走査し、各ブロックの両方の要素を回答配列に追加します。 
4. 連結された配列を出力します。 

2 番目の要素による並べ替えが正しい理由は、2 番目の要素がこのブロックが配列の最初に導入する最大値を表すためです。 より小さな最大値を持つブロックを最初に配置すると、大きな値が可能な限り遅延され、将来の多くの小さな要素で反転が形成される可能性が減ります。 

### なぜ効果があるのか

 各ブロックを並べ替えた後、$x_i \le y_i$、ブロックの唯一の潜在的に有害な影響は、そのより大きな要素です。$y_i$。 より大きなブロックの場合$y_i$より小さいブロックの前に配置されます$y_j$、 それから$y_i > y_j$内部構造に関係なく、少なくとも 1 つの反転を保証します。 

ブロックを並べ替えることで、$y_i$、私たちはいつでもそれを保証します$i < j$、 我々は持っています$y_i \le y_j$したがって、2 番目の要素が逆の順序で導入されることはありません。 最初の要素から$x_i$いつもいる$\le y_i$、同じ順序によっても制約されます。 この位置合わせにより、すべてのブロック間の反転がグローバルに最小化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        arr = []
        for _ in range(n):
            a, b = map(int, input().split())
            if a > b:
                a, b = b, a
            arr.append((a, b))
        
        arr.sort(key=lambda x: x[1])
        
        res = []
        for a, b in arr:
            res.append(a)
            res.append(b)
        
        out.append(" ".join(map(str, res)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装ではまず、小さい値が最初になるように各ペアを正規化します。これにより、構築によって内部反転が発生することがなくなります。 次に、各ペアの 2 番目の要素によって並べ替えられ、最終シーケンスの早い段階でブロックが寄与する最大値がエンコードされます。 

最後のループは、ソートされたペアを単純にフラット化します。 順序付けにより相互作用が最小限に抑えられているため、追加の反転追跡は必要ありません。 

微妙な点は、並べ替えでは 2 番目の要素のみを使用する必要があることです。 最初の要素または要素の合計を使用すると、順序が正しくなくなる可能性があります。これは、反転構造が各ブロック内のより大きな公開値に依存するためです。 

## 実用的な例

 ### 例 1

 入力ブロック:$$(3,3), (2,4), (3,2), (1,3)$$正規化後:$$(3,3), (2,4), (2,3), (1,3)$$2 番目の要素でソート:$$(3,3), (1,3), (2,3), (2,4)$$| ステップ | ブロック | これまでの出力 |
 | --- | --- | --- |
 | 1 | (3,3) | 3 3 |
 | 2 | (1,3) | 3 3 1 3 |
 | 3 | (2,3) | 3 3 1 3 2 3 |
 | 4 | (2,4) | 3 3 1 3 2 3 2 4 |

 これは、最大値が大きいブロックを遅延させると、大から小への反転の数が減少することを示しています。 

### 例 2

 入力ブロック:$$(5,5), (10,2), (3,9), (6,1)$$正規化後:$$(5,5), (2,10), (3,9), (1,6)$$並べ替え:$$(5,5), (1,6), (3,9), (2,10)$$| ステップ | ブロック | これまでの出力 |
 | --- | --- | --- |
 | 1 | (5,5) | 5 5 |
 | 2 | (1,6) | 5 5 1 6 |
 | 3 | (3,9) | 5 5 1 6 3 9 |
 | 4 | (2,10) | 5 5 1 6 3 9 2 10 |

 この構造により、ますます大きくなる 2 番目の要素が後で出現し、広範囲にわたる反転が引き起こされるのを防ぎます。

 ## 特殊なケース

 次のような単一ブロックの場合$(b, a)$どこ$b > a$、アルゴリズムは最初にそれを$(a, b)$内部反転が存在しないことを保証します。 他にブロックがないため、最終的な出力は自明に正しいものになります。 

同一のペアが繰り返される場合、ソートは効果がなく、どのような置換でも反転は生じません。 アルゴリズムはすべての値を任意の順序で保存し、結果は最適なままになります。 

極大値を厳密に減少させるシーケンスの場合、次のようになります。$(10,1), (9,2), (8,3)$、正規化の結果$(1,10), (2,9), (3,8)$。 2 番目の要素で並べ替えると順序が逆になり、$(3,8), (2,9), (1,10)$、大きな 2 番目の要素を配列の後半にプッシュすることで、相互反転を最小限に抑えます。
