 ## 解決策
 ## 問題の理解

 私たちには、独立したギャンブル ゲームのコレクションが与えられました。 各ゲームには成功確率があり、成功した場合には配当が支払われます。 面白いのは、選択したゲームのいずれかが失敗すると、選択したゲーム全体の報酬がゼロになるということです。 選択したすべてのゲームが成功した場合、支払いは個々の報酬の合計となります。 

したがって、選択したサブセットの期待値は、成功確率とそのサブセット内の報酬の合計の積になります。 課題は、この期待を最大化するサブセットを選択することです。 

入力サイズは最大 200,000 ゲームに達し、指数関数的なサブセット列挙は即座に除外されます。 2e5 の 2 乗アプローチでは 4e10 の演算が必要になるため、二次解でも大きすぎます。 

主要な構造上の制約は、確率が 100 までの小さな整数であるのに対し、報酬は積制約のある正の整数であることです。$p_i \cdot w_i \le 200000$。 これにより、単一のゲームが確率と報酬の両方で恣意的に優勢になることがなくなり、並べ替えや貪欲な選択が効果的である可能性があることが示唆されます。 

すべての確率が 100 未満の場合、微妙なエッジ ケースが発生します。単純な直感では、すべてのゲームを取得する方が報酬の合計が増加するため常に良いと思われるかもしれませんが、乗算確率ペナルティが利益を圧倒する可能性があります。 たとえば、報酬は高いが確率が低いゲームを追加すると、期待が低下する可能性があります。 

もう 1 つの失敗モードは、報酬または確率のみによる貪欲な選択です。 報酬のみによる並べ替えは確率の縮小を無視しますが、確率のみによる並べ替えは報酬の加算構造を無視します。 正しい解決策は両方のバランスを同時にとらなければなりません。 

## アプローチ

 ブルートフォースアプローチでは、ゲームのすべてのサブセットを試し、確率の積と報酬の合計を計算し、最大の期待値を追跡します。 これは目的関数を直接評価するため、概念的に機能します。 ただし、サブセットの数は$2^n$、たとえそれが不可能になる$n=40$、ましてや$200,000$。 計算量の爆発は、サブセット選択の組み合わせの性質から生じます。 

重要な観察は、漸進的な推論を可能にする方法で目的を再定式化することです。 サブセットを維持し、新しいゲームを追加することを検討するとします。 期待は確率では乗算的に変化し、報酬では加算的に変化します。これは、正規化された方法で限界寄与を比較する必要があることを示唆しています。 

現在のサブセットに確率積を持たせる$P$そして報酬額$S$。 確率で新しいゲームを追加したら$p$そしてご褒美$w$、新たな期待は$$(P \cdot \frac{p}{100}) \cdot (S + w).$$ゲームの追加が役立つかどうかの比較は、ゲームの追加のみに依存する比率の比較に帰着します。$(p, w)$そして現状。 

A standard transformation is to sort games by decreasing ratio$\frac{w_i}{100 - p_i}$代数的再配置後、これは限界改善の比較から得られます。 直感的には、期待される合計への寄与が確率減衰の影響を上回る場合、ゲームは有益です。 

並べ替えた後、各ゲームを順番に含めるかどうかを貪欲に決定します。 達成可能な最良の期待値を動的に維持します。プレフィックスごとに、拡張によって値が向上するかどうかを計算します。 

これにより、問題は指数関数的な検索からソートされたリストに対する線形スキャンに軽減されます。

 ## アルゴリズムのチュートリアル

 1. すべてのゲームをペアとして読み取ります$(p_i, w_i)$確率を分数に変換します$p_i / 100$。 この標準化により、均一な乗算処理が可能になります。 
2. 式の値を降順にしてゲームを並べ替えます$\frac{w_i}{100 - p_i}$。 この順序は、ゲームがサブセットの早い段階に含まれている場合に、確率の損失をどれだけの報酬が補うかを反映しています。 
3. 2 つの変数: 実行確率積を初期化します。$P = 1.0$そして継続的な報酬額$S = 0.0$。 
4. 答えを 0.0 として初期化し、これまでに見つかった最良の期待値を表します。 
5. ソートされた順序でゲームを繰り返します。 ゲームごとに、包含を考慮して候補状態を更新します。$P' = P \cdot (p_i / 100)$そして$S' = S + w_i$。 
6. 期待値を計算する$E' = P' \cdot S'$場合は回答を更新します$E'$現在のベストより大きいです。 
7. 設定によって、実際に含めることを決定します。$P = P'$そして$S = S'$。 このステップは有効です。ソートされた順序によって、以前の決定が将来の拡張に対して最適なままであることが保証されるからです。 

### なぜ効果があるのか

 このアルゴリズムは、目的関数が減少する乗算係数と増加する加算係数の積に分解できるという事実に基づいています。 ソート基準により、各ステップで、報酬の獲得と確率の減衰の間の最良のトレードオフの順序でゲームが考慮されることが保証されます。 これにより、目的の値を減少させることなく、最適なサブセットをソートされた順序のプレフィックスに変換できる構造が誘導されます。 この交換引数により、貪欲な構築でより適切なサブセットを見逃さないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    games = []
    for _ in range(n):
        p, w = map(int, input().split())
        games.append((p, w))
    
    # sort by w / (100 - p)
    # avoid division by sorting cross-multiplied
    games.sort(key=lambda x: (x[1] * 1.0 / (100 - x[0]) if x[0] != 100 else float('inf')), reverse=True)

    P = 1.0
    S = 0.0
    ans = 0.0

    for p, w in games:
        P *= p / 100.0
        S += w
        ans = max(ans, P * S)

    print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、導出された支配比率に従ってゲームを並べ替え、より良い報酬とリスクのトレードオフを持つゲームがより早く表示されるようにします。 ループは累積確率と報酬合計を維持します。 この順序付けでは最適なサブセットがプレフィックスで閉じられているため、各ステップで完全なプレフィックスが候補サブセットとして評価されます。 

一般的な実装の落とし穴は、多くの確率を乗算するときに浮動小数点の安定性を忘れることです。 ここでは Python float を使用するだけで十分です。$n$大きいが、確率には限界があり、精度要件は$10^{-6}$。 

もう一つの微妙な点はハンドリングです$p_i = 100$、これによりヒューリスティックの分母が無限になります。 これらのゲームは確率を低下させないため、常に最初に行う必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    n = int(inp.split()[0])
    games = []
    idx = 1
    for _ in range(n):
        p = int(inp.split()[idx]); w = int(inp.split()[idx+1])
        idx += 2
        games.append((p, w))

    games.sort(key=lambda x: (x[1] / (100 - x[0]) if x[0] != 100 else float('inf')), reverse=True)

    P = 1.0
    S = 0.0
    ans = 0.0

    for p, w in games:
        P *= p / 100
        S += w
        ans = max(ans, P * S)

    return f"{ans:.6f}"

# sample
assert run("3\n80 80\n70 100\n50 200\n") == "112.000000", "sample 1"

# all probability 100
assert run("2\n100 10\n100 20\n") == "30.000000", "all certain wins"

# single game
assert run("1\n80 50\n") == "40.000000", "single game"

# low probability high reward
assert run("2\n10 1000\n90 1\n") == run("2\n90 1\n10 1000\n"), "order invariance"

# large equal cases
assert run("3\n90 10\n90 10\n90 10\n") > "0.000000", "uniform case"

 ## 特殊なケース

 重要なエッジケースは、1 つ以上のゲームが$p_i = 100$。 これらのゲームは確率積を減少させないため、最適なソリューションには常に含める必要があります。 アルゴリズムでは、ソートの重みが無限であるため、それらは自然に最前面に浮かび上がり、それらを含めると合計が増加するだけです$S$影響を与えずに$P$。 

もう 1 つの特殊なケースは、確率が非常に小さい場合です。 このような場合、ゲームを 1 つ追加するだけでも、以前は有益だったサブセットが最適ではなくなるほど製品が減少する可能性があります。 接頭辞の評価により、アルゴリズムはすべての包含を強制するのではなく、最適な停止点を確実に捕捉します。 

最後のエッジケースは、すべてのゲームの比率が同様の場合に発生します。 このアルゴリズムは引き続き機能します。順序のわずかな違いによっても、どのプレフィックスが積和トレードオフを最大化するかが決まり、最大追跡ステップによって最適なプレフィックスが常に選択されることが保証されます。
