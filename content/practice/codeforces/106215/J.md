 ## 解決策
 ## 問題の理解

 A と B という 2 つの平行な歩道があり、それぞれに 1 から n までの位置が含まれています。 歩道 A の位置 1 から開始し、歩道 B の位置 n に到達したいとします。 

歩道に沿って 1 つ前に進むには 1 秒かかります。 特定の位置には 2 つの歩道を接続する横断歩道があります。 横断歩道で道路を渡るのも1秒かかりますが、それが許されるのは信号が青の時だけです。 

すべての信号機は同じスケジュールを共有します。 時間 0 から緑色で始まります。k 秒ごとに色が切り替わります。 つまり、ある時間帯は信号が緑色になります`[0, k-1]`、中は赤`[k, 2k-1]`、緑色の間`[2k, 3k-1]`、 等々。 毎秒、前に歩くか、許可されている場合は渡るか、待つかのいずれかを行うことができます。 

c. ある位置で横断歩道を 1 つだけ使用する必要があります。 渡ったら、位置 n に到達するまで歩道 B を歩き続けます。 

入力により、歩道の長さ n、横断歩道の数 m、切り替え間隔 k、およびすべての横断歩道の位置が与えられます。 テスト ケースごとに、最小到着時間を出力する必要があります。 

制約は重要な観察事項です。 まであります$10^5$テスト ケースごとの横断歩道と最大 10 のテスト ケース。 横断歩道ごとに一定以上の作業を実行するソリューションは、速度が非常に遅くなる危険性があります。 アン$O(m)$解は容易に十分に高速ですが、二次関数は不可能です。 

唯一の決定は、どの横断歩道を使用するかです。 横断歩道が決まると、道は完全に決まります。 

微妙な点は、赤の段階で横断歩道に到着すると、次の青の段階まで待つ必要がある場合があることです。 

考慮する：```
n = 6, k = 1
crosswalk = 2
```時間 1 で位置 2 に到達します。k = 1 なので、時間 1、3、5、... は赤になります。 すぐに渡ることはできず、時間 2 まで待つ必要があります。到着時に信号が青かどうかだけを確認し、待つことを無視する解決策では、間違った答えが得られます。 

もう 1 つのエッジ ケースは、グリーン フェーズが始まるまさにその瞬間に到着した場合に発生します。```
n = 10
k = 5
crosswalk = 6
```時刻 5 に到着します。時刻 5 は区間に属します`[5, 9]`、これは緑ではなく赤です。 よくある 1 つ違いの間違いは、間隔のエンドポイントを間違って扱い、すぐに交差してしまうことです。 

3 番目のケースは、横断歩道が終点近くに唯一ある場合です。```
n = 100
crosswalk = 99
```実際には、横断する前にほぼ全距離を歩くのが最適かもしれません。 常に最初に利用できる横断歩道を選択​​するような欲張りな戦略は失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての横断歩道の位置 c について、その横断歩道を選択​​した場合の合計移動時間を計算します。 

位置 1 から c まで歩くには、`c - 1`秒。 その到着時刻を`t`。 

時刻 t で信号が青であれば、すぐに渡ってもよいでしょう。 それ以外の場合は、次の緑色のフェーズまで待機します。 渡った後は、1秒間横断歩道を渡ってから歩きます。`n - c`歩道Bをさらに数秒進みます。 

横断歩道の選択肢は m 個しかないため、それらすべてを個別に評価すると、すでに次の結果が得られます。$O(m)$アルゴリズム。 

興味深いのは、待ち時間を効率的に決定することです。 

ライトは k 秒ごとに切り替わります。 計算してみると```
block = t // k
```ブロック 0 は緑、ブロック 1 は赤、ブロック 2 は緑というようになります。 

いつ`block`が均等であれば、すぐに横断を開始できます。 

いつ`block`奇妙です、私たちは赤い区間内にいます。 次の緑の間隔は に始まります```
(block + 1) * k
```したがって、必要な待ち時間は```
(block + 1) * k - t
```この観察が行われると、各横断歩道を一定時間で評価できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 待機の直接シミュレーションによるすべての横断歩道のブルート フォース | O(m) | お(1) | 承認済み |
 | 最適 | O(m) | お(1) | 承認済み |

 この問題では、どの横断歩道を使用するかだけが決定されるため、総当り選択列挙はすでに最適です。 

## アルゴリズムのチュートリアル

 1. 答えを非常に大きな数値として初期化します。 
2.横断歩道の位置ごとに`c`、その横断歩道に到着する時間を計算します。```
arrive = c - 1
```1 秒ごとに 1 つの位置を歩くということは、正確に後に位置 c に到達することを意味します`c - 1`秒。 
3. 時間の経過とともにライトが緑か赤かを判断します`arrive`:```
block = arrive // k
```偶数番号のブロックは緑色、奇数番号のブロックは赤色です。 
4. もし`block`が偶数の場合は、待ち時間をゼロに設定します。 
5. もし`block`が奇数の場合、次の緑フェーズまでの待ち時間を計算します。```
wait = (block + 1) * k - arrive
```6. この横断歩道の合計移動時間を計算します。```
total = arrive + wait + 1 + (n - c)
```これらの用語は、横断歩道まで歩くこと、待つこと、横断すること、歩道 B を歩くことを表します。 
7. 最小の回答を更新します。 
8. すべての横断歩道を処理した後、見つかった最小値を出力します。 

### なぜ効果があるのか

 横断歩道の位置 c が固定されている場合、考えられるルートは 1 つだけです。 横断歩道の到着時間はいつも`c - 1`、将来の決定とは無関係に。 徒歩以外にかかる唯一の追加コストは、信号のスケジュールによって生じる待ち時間です。 

時刻 t における信号機の状態は、次のパリティのみに依存します。`t // k`。 対応するブロックが緑色の場合は、すぐに横断するのが最適です。 赤の場合は、次の緑のブロックが始まるまで横断することはできません。さらに待っても到着が遅れるだけなので、その瞬間まで正確に待つのが最適です。 

すべての実行可能な戦略は、指定された横断歩道の 1 つを選択する必要があるため、すべての横断歩道を評価して最小値を取得し、可能なすべての解決策を検討します。 計算された最小の移動時間がまさに最適な答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        input()  # consume possible blank line

        line = input().strip()
        while not line:
            line = input().strip()

        n, m, k = map(int, line.split())
        crosswalks = list(map(int, input().split()))

        ans = 10**30

        for c in crosswalks:
            arrive = c - 1
            block = arrive // k

            if block % 2 == 0:
                wait = 0
            else:
                wait = (block + 1) * k - arrive

            total = arrive + wait + 1 + (n - c)
            ans = min(ans, total)

        print(ans)

solve()
```実装は数式に直接に従います。 

最も重要な詳細は、照明スケジュールの解釈です。 当時の状態`arrive`によって決定されます`arrive // k`。 偶数ブロックは緑に対応し、奇数ブロックは赤に対応します。 

もう 1 つの簡単な間違いは、横断には 1 秒かかることを忘れることです。 信号がすぐに青になっても、横断動作自体には時間がかかります。 

Gym ステートメントの入力には、セクション間に空白行が含まれています。 このコードは、各テスト ケースを読み取る前に空行を安全にスキップするため、書式設定された入力とコンパクトな入力の両方に対して堅牢になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m) | 各横断歩道の継続的な作業 |

 このソリューションは、横断歩道の数に応じて線形にスケールします。 以来$m \le 10^5$、すべての横断歩道を 1 回処理するのは簡単に制限内に収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    out = []

    t = int(input())

    for _ in range(t):
        line = input().strip()
        while not line:
            line = input().strip()

        n, m, k = map(int, line.split())
        crosswalks = list(map(int, input().split()))

        ans = 10**30

        for c in crosswalks:
            arrive = c - 1
            block = arrive // k

            if block % 2 == 0:
                wait = 0
            else:
                wait = (block + 1) * k - arrive

            ans = min(ans, arrive + wait + 1 + (n - c))

        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 次のことを考慮してください。```
1
6 1 1
2
```到着時間は`1`。 以来`1 // 1 = 1`、ライトは赤です。 アルゴリズムは以下を計算します。```
wait = (1 + 1) * 1 - 1 = 1
```合計時間は次のようになります。```
1 + 1 + 1 + 4 = 7
```時間 1 での交差は不可能であるため、出力は正しいです。 

ここで、正確な位相境界を考えてみましょう。```
1
10 1 5
6
```到着時間は`5`。```
block = 5 // 5 = 1
```ブロック 1 は赤なので、次のようになります。```
wait = 10 - 5 = 5
```アルゴリズムは、時刻 5 がすでに赤色の間隔内にあることを正しく認識します。 結果は15です。 

最後に、遅い横断歩道について考えてみましょう。```
1
100 2 10
2 99
```横断歩道 2 の場合、到着時間は 1 で、合計は 100 です。 

横断歩道 99 の場合、到着時刻は 98 です。`98 // 10 = 9`、ライトは赤で待機は2秒です。 合計は次のとおりです。```
98 + 2 + 1 + 1 = 102
```アルゴリズムは両方の可能性を比較し、100 を選択します。これにより、すべての横断歩道が独立して評価され、最適な横断歩道が選択されることが確認されます。
