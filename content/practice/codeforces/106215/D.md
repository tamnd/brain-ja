 ## 解決策
 ## 問題の理解

 配列が与えられています`a`ここで、各位置は単語とそれに割り当てられたスコアを表します。 

インデックスのペアごとに`(i, j)`と`i < j`、問題は次のように定義します$$\text{dist}(i,j)=a_i+a_j$$距離が位置の差と正確に一致する場合、ペアは美しいとみなされます。$$j-i=a_i+a_j$$テスト ケースごとに、この等式を満たすペアの数を数えなければなりません。 

配列の長さは次のように大きくできます。`2 · 10^5`、およびすべての合計`n`テストケース全体でも最大で`2 · 10^5`。 すべてのペアをチェックするソリューションでは、大まかに次のことが必要になります。$$\frac{n(n-1)}2$$比較。 のために`n = 2 · 10^5`、それは約です`2 · 10^{10}`まったく実行不可能な操作です。 

合計入力サイズは、テスト ケースごとに線形時間に近い時間、または最悪の場合でも時間が必要であることを強く示唆しています。`O(n log n)`。 

微妙な観察が境界から生まれます`a_i`。 すべてのスコアがプラスであるため、次の場合`a_i >= n`、その後、関係するペアはありません`i`いつまでも美しくなれるから$$a_i+a_j \ge a_i+1 > n-1$$一方、可能な最大値は`j-i`だけです`n-1`。

## アプローチ

 最も直接的な解決策は、すべてのペアを調べることです`(i, j)`、計算する`a_i + a_j`と比較してください`j - i`、一致をカウントします。 

このメソッドは定義から正確な条件をチェックするため、明らかに正しいです。 問題はその複雑さです。 のために`n = 2 · 10^5`、ペアの数はおよそ 200 億であり、制限をはるかに超えています。 

何かをより速く見つけるには、条件を書き換えます。$$j-i=a_i+a_j$$同じインデックスを含む用語を同じ側に移動します。$$j-a_j=i+a_i$$今、ペアはまさにその値が美しいとき$$i+a_i$$左の端点が等しい場合$$j-a_j$$適切なエンドポイントの場合。 

これにより、問題はペアのチェックから等しい値のカウントに変換されます。 

インデックスを左から右に処理するとします。 ポジションに到着したら`j`、以前のポジションの数を知る必要があります。`i`満足する$$i+a_i=j-a_j$$以前に確認されたすべての値の頻度マップを維持すると、`i+a_i`、次に有効なパートナーの数`j`は単に次の周波数です`j-a_j`。 

各インデックスは 1 回だけ寄与し、線形時間のソリューションを提供します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適なハッシュ マップ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空の周波数マップを作成します。 
2. 1 から始まるインデックスを使用して、配列を左から右に処理します。 
3. 現在のポジションについて`j`、次を計算します。$$key = j - a_j$$以前のすべてのインデックス`i`満足のいく`i + a_i = key`～と美しいペアを形成する`j`。 

1. の周波数を加算します。`key`答えに。 

変換された方程式は元の条件とまったく同じであるため、これはすべての有効な以前のパートナーをカウントし、無効なパートナーはカウントしません。 

1. コンピューティング$$store = j + a_j$$それを周波数マップに挿入します。 

将来のポジションは、このインデックスを左のエンドポイントとして使用する可能性があります。 

1. すべての位置が処理されるまで続行します。 

### なぜ効果があるのか

 周波数マップには常に値が含まれます`i + a_i`現在の位置より厳密に小さいインデックスの場合。 

インデックス処理時`j`、すべての美しいペアは満足する必要があります$$i+a_i=j-a_j$$マップ内のすべてのインデックスにはすでに`i < j`。 したがって、次の頻度は`j-a_j`は、正確に以前の有効なインデックスの数です。 すべての美しいペアは、その右のエンドポイントが処理されるときに 1 回カウントされ、無効なペアは変換された等価性を満たすことができません。 これにより正しさが確立されます。 

## Python ソリューション```python
import sys
from collections import defaultdict

input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = defaultdict(int)
        ans = 0

        for i in range(1, n + 1):
            x = a[i - 1]

            ans += freq[i - x]
            freq[i + x] += 1

        print(ans)

solve()
```解は代数変換に直接続きます。 

変数`freq`値のカウントを保存します`i + a_i`以前に処理されたインデックスから。 各位置について、最初にクエリを実行します。`freq[i - a_i]`有効なペアを形成できるのは以前のインデックスのみであるためです。 貢献度を数えた後、次のように挿入します。`i + a_i`地図に。 

順序は重要です。 挿入が最初に行われた場合、現在のインデックスがそれ自体と誤って一致する可能性があります。`a_i = 0`。 この問題では正の値が保証されますが、正しい順序を維持することでロジックの数学的正確さが保たれます。 

ループ内で 1 から始まるインデックスを使用すると、元の方程式が正確に一致し、導出中の余分な調整が回避されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from collections import defaultdict

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def input():
        return sys.stdin.readline()

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        freq = defaultdict(int)
        ans = 0

        for i in range(1, n + 1):
            ans += freq[i - a[i - 1]]
            freq[i + a[i - 1]] += 1

        out.append(str(ans))

    return "\n".join(out)

# custom cases

assert run("1\n4\n3 1 1 1\n") == "1", "boundary example"

assert run("1\n6\n1 2 3 1 2 3\n") == "1", "general case"

 ## 特殊なケース

 次のことを考慮してください。```
1
3
2025 2025 2025
```処理によりキーが生成される`-2024`、`-2023`、 そして`-2022`。 これらの値はいずれも保存された値として表示されません。`i + a_i`したがって、すべての検索ではゼロが返されます。 アルゴリズムは次を出力します。```
0
```インデックスの差が数千に達することはないため、これは正しいことです。 

考慮する：```
1
5
1 1 1 1 1
```保存された値は次のようになります。`2, 3, 4, 5, 6`。 ポジションで`3`、`4`、 そして`5`、クエリされた値は次のとおりです。`2`、`3`、 そして`4`、それぞれがすでに正確に 1 回存在します。 答えは次のようになります`3`、二重にカウントすることなく、すべての有効なペアを正しくカウントします。 

考慮する：```
1
4
3 1 1 1
```マップは次のように進化します。```
after i=1: {4:1}
after i=2: {4:1,3:1}
after i=3: {4:2,3:1}
```で`i=4`、クエリ値は`3`、一度存在します。 答えは 1 つ増えて次のようになります。```
1
```唯一の美しいペアと一致します`(2,4)`。
