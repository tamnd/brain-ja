 ## 解決策
 ## 問題の理解

 セルの 1 次元グリッドが与えられ、各セルは正または負の整数値を保持します。 プレーヤーは指定された位置から開始し、一定の長さの一連の動きを実行します。$|s|$。 それぞれの動きは左、右、または不明です。 未知の動きはどちらの方向にも割り当てることができます。 

プレーヤーがセルに入るたびに、再訪問も含めてその値が収集されます。 開始セルはスコアに影響しません。 左または右の境界を越えて移動してもプロセスは停止しません。プレーヤーは境界セル上に留まり、さらに外側に移動しようとすると効果的にその値を再び収集します。 

タスクは、訪問したセル全体で収集された合計が最大になるように、すべての未知の動きに方向を割り当てることです。 

主な問題点は、動きの選択が将来の位置に影響を及ぼし、それがどのセル値が複数回収集されるかに影響を与えることです。 境界では再訪問が許可され、さらには強制されるため、問題は単純な経路を見つけることではなく、繰り返しの利益を最大化する軌道を形成する方向を選択することです。 

この制約により、合計の合計を含む複数のテスト ケースが許可されます。$n$すべての動きの文字列の合計の長さは約 2000 で制限されます。これにより、すべてをシミュレートするソリューションは即座に除外されます。$2^{\text{number of question marks}}$割り当ては指数関数的に増加し、中程度の文字列であっても実行不可能になるためです。 

位置とインデックスの完全な状態に対する単純な動的プログラミングは妥当ですが、位置と時間に対する直接の DP は次のようなものになるため、依然として注意深い最適化が必要です。$O(n \cdot |s|)$これは、遷移が単純で効率的に再利用される場合にのみ許容されます。 

単純な推論を打ち破るエッジケースは、境界バウンスと繰り返しの訪問から発生します。 

1 つの例として、1 つの境界セルを除くすべての値が負の場合があります。たとえば、次のようになります。 

入力:

 n = 3、k = 2

 a = [ -5, 100, -5 ]

 s = "LLLL"

 単純な貪欲な人は、中心から遠ざけたり、再訪問を避けたりしようとするかもしれませんが、正しい戦略は、繰り返しの +100 ゲインを最大化するために、意図的に境界セルで繰り返しバウンスすることです。 

もう 1 つの注意が必要な状況は、最適な戦略に、最初に高価値領域から離れて、繰り返しのリターンを設定することが含まれる場合です。 たとえば:

 入力:

 n = 5、k = 3

 a = [10、-100、50、-100、10]

 s=「？？？」

 単純なアプローチでは 50 付近に留まる可能性がありますが、最適なプレイには、強制的な動きが境界とどのように相互作用するかに応じて、10 から 50 の間でバウンスすることが含まれる場合があります。 

これらのケースは、問題が移動ごとに純粋に局所的なものではないことを示しています。 最適な決定は長期的な再訪パターンに依存します。 

## アプローチ

 ブルート フォース ソリューションでは、疑問符のすべての割り当てを試し、結果のパスをシミュレートして、スコアを計算します。 各シミュレーションの費用$O(|s|)$、そして$q$クエスチョンマークが複雑になる$O(2^q \cdot |s|)$。 以来$|s|$最大 2000 まで可能ですが、これは$q \approx 25$。 

重要な点は、システムの状態が文字列内の現在位置とインデックスによって完全に決定されるということです。 将来のスコアは、これら 2 つの値にのみ依存し、どのようにそれらに到達したかには依存しません。 これは、時間と位置に応じた動的プログラミングを示唆しています。 

ただし、方向を割り当てるすべての可能性に対する単純な DP は、依然として「?」ごとに分岐します。 重要な構造の単純化は、各ステップで位置が 1 だけ増加または減少し、境界での無効な移動が自己ループに崩壊することです。 これにより、方向が選択されると、遷移が決定的になります。 

したがって、最初の i 番目の動きを処理して位置 j で終了した後、可能な限り最高のスコアを追跡する DP を定義できます。 固定ステップでは、位置 j にいる場合、左または右に移動すると、常に 1 つの結果位置が生成されます。 手が「?」の場合、両方の方向を試して、より良い結果を採用します。 

遷移はステップごとに n 単位で線形であり、次のようになります。$O(n \cdot |s|)$、制約の下では許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てに対するブルートフォース | (O(2^q \cdot | s | )) |
 | DP オーバーポジションとステップ | (O(n \cdot | s | )) |

 ## アルゴリズムのチュートリアル

 各ステップについて、各位置で終了するときに達成可能な最高のスコアを保存する動的プログラミング テーブルを構築します。 

1. DP 配列を初期化します。`dp[x]`現在の動きのプレフィックスを処理し、その位置にある後の最高のスコアを表します`x`。 初期位置を除くすべての値を負の無限大に設定して開始します。開始セルはカウントされないため、初期位置はスコア 0 から始まります。 
2. 一連の動きを左から右に繰り返します。 各ステップで、新しい DP 配列を構築します。`ndp`現在の動きを適用した後の結果を表します。 
3. ポジションごとに`x`、現在のDPで到達可能であれば、移行を検討します。 文字が「L」の場合、次のように遷移します。`x-1`、しかし、もし`x`はすでに左側の境界にあるので、ここに留まります`x`。 結果のセルの値をスコアに追加します。 
4. 同様に、文字が「R」の場合は、次のように進みます。`x+1`、またはに滞在`x`右境界にある場合は、対応するセル値を追加します。 
5. 文字が「?」の場合、両方の可能性を評価し、「L」として扱うか「R」として扱い、両方の遷移を伝播して、各宛先セルの最大スコアを維持します。 
6. 現在のステップのすべての位置を処理した後、次のように置き換えます。`dp`と`ndp`そして続けます。 

答えは、最終的な DP 配列の最大値です。 

### なぜ効果があるのか

 DP 状態は、将来の決定にとって重要なもの、つまり現在の位置と累積スコアを正確にキャプチャします。 同じ手数を経て同じ局面で終了する 2 つの履歴は、今後交換可能です。これは、将来の遷移は、その局面にどのように到達したかではなく、局面と次の一手だけに依存するためです。 これにより、最適な部分構造が確立されます。プレフィックスの最良の結果は最適に拡張するのに十分であり、位置ごとの最大スコアのみを維持することで正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    s = input().strip()

    INF = -10**30

    # dp[position]
    dp = [INF] * n
    dp[k - 1] = 0

    for ch in s:
        ndp = [INF] * n

        for i in range(n):
            if dp[i] == INF:
                continue

            def relax(nxt):
                ndp[nxt] = max(ndp[nxt], dp[i] + a[nxt])

            if ch == 'L' or ch == '?':
                if i == 0:
                    relax(0)
                else:
                    relax(i - 1)

            if ch == 'R' or ch == '?':
                if i == n - 1:
                    relax(n - 1)
                else:
                    relax(i + 1)

        dp = ndp

    print(max(dp))

if __name__ == "__main__":
    solve()
```コードは DP 定義に直接準拠しています。 唯一の微妙な点は、境界の移動を正しく処理することです。遷移をスキップする代わりに、それらを同じインデックスにマップし直し、境界セルを繰り返し踏むことを正しくモデル化します。 

の`relax`関数は、複数のパスが同じ位置に到達した場合に、最良のスコアのみが保持されることを保証します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        s = input().strip()

        INF = -10**30
        dp = [INF] * n
        dp[k - 1] = 0

        for ch in s:
            ndp = [INF] * n
            for i in range(n):
                if dp[i] == INF:
                    continue

                def relax(nxt):
                    ndp[nxt] = max(ndp[nxt], dp[i] + a[nxt])

                if ch == 'L' or ch == '?':
                    relax(i - 1 if i > 0 else 0)
                if ch == 'R' or ch == '?':
                    relax(i + 1 if i < n - 1 else n - 1)

            dp = ndp

        return str(max(dp))

    return solve()

 ## 特殊なケース

 重要なエッジケースは、開始位置が境界にある場合です。 その状況では、外部への強制的な移動は崩壊してその場に留まるため、DP はこれを境界値を収集する有効な自己遷移として扱う必要があります。 遷移は境界外の移動を同じインデックスに明示的にマップするため、アルゴリズムはこれを処理します。 

もう 1 つの特殊なケースは、すべての手が「?」である場合です。 DP は各ステップで両方向を探索する必要がありますが、それでもすべての可能性を位置ごとの単一の最適値に圧縮する必要があります。 位置を超えて別の状態に分岐することはないため、指数関数的な爆発が回避されます。 

3 番目のケースは、内部セルに負の値が存在するが、境界が正である場合です。 最適な戦略はエッジで振動するようになりますが、DP は値の高い境界状態に留まるか、または値の高い境界状態に戻る遷移を繰り返し好むため、これは自然に発見されます。
