 ## 解決策
 ## 問題の理解

 私たちは、すべてのノードが通常または特殊であるツリーを操作しています。 ウォークはエッジに沿って自由に移動できますが、ウォーク中のノードの動作には非対称性が 1 つあります。通常のノードは何度でも再訪問できますが、各特殊ノードは訪問ノードのシーケンス全体で最大 1 回しか出現できません。 

すべての開始ノードについて、そのノードから開始する単一の有効なウォークに含めることができる個別のノードの最大数が必要です。 通常のノードへの再訪問には制限がないため、実際の制限は完全に、特別なノードがツリー内で「ループ」または迂回する機能をどのように制限するかによって決まります。 

出力は、特別なノードに関する単純なパスの最適なサイズを表すノードごとの値であり、通常のグラフの意味での単純なパスである必要はありません。 ウォークは通常のノードを繰り返すことができますが、特別なノードを繰り返すことは禁止されています。 

この制約は、すべてのテスト ケースにわたるノードの総数が最大 200,000 であり、ツリー構造により O(n) エッジが保証されることを意味します。 テスト ケースごとに 2 次的な解法は直ちに不可能です。 入力全体で慎重に償却しない限り、ノードあたり O(n log n) であっても遅すぎます。 

重要な微妙な点は、通常のノードを再検討することで、通常の領域をコストなしで特別なノードを接続する自由なコリドーとして扱うことが効果的に可能になることです。 これを標準的な最長パス問題として扱う単純なアプローチは、再訪問が特別なノードではなく通常のノードでのみ許可されるという事実を無視するため、失敗します。 

小さな失敗例がこれを示しています。 ノードが特別で、通常のノードを介して離れた 2 つの特別なノードに接続されているとします。 特別な制約を覚えておらずにパスを拡張しようとする単純な DFS は、戻るときに最初の特別なノードを再訪問し、答えを誤って膨らませる可能性があります。 たとえば、すべてが特別で 2 から始まる行 1-2-3 では、2→1→2→3 に行こうとすると、ノード 2 が誤って再利用され、これは無効です。 

最大の問題は、ウォークが特別なノードを通過すると、そのノードを分岐点として再度使用できないことです。 これにより、問題は、通常のノードがコネクタとしてのみ機能する一方で、再利用せずにパスに沿って収集できる特別なノードの数についての推論に変わります。 

## アプローチ

 ブルート フォース ソリューションでは、開始ノードごとに、可能なすべてのウォークを探索し、状態セットを使用して訪問した特別なノードを追跡しようとします。 これは本質的に、(現在のノード、訪問先の特別なサブセット) によって定義される状態にわたる DFS になり、M では指数関数的になります。ウォークはノードに関して単純である必要はなく、特別なノードに関してのみ単純である必要があるため、列挙がさらに複雑になるため、すべての単純なパスを試行する単純化されたブルート フォースでさえ失敗します。 ツリー内の可能なパスの数は O(n^2) で、パスごとに妥当性をチェックして個別のノードをカウントする必要があり、全体として 3 次的な動作が行われます。 

重要な構造上の観察は、通常のノードには再訪問が制限されていないということです。これは、通常のノードに接続されているコンポーネントは、特別なノードを接続する自由に再利用可能な「接着剤」のように動作することを意味します。 通常のノードのすべての最大接続コンポーネントを単一のスーパーノードに縮小すると、ツリーは特殊なノードがこれらの通常のコンポーネントを介して接続された構造になります。 

この縮小されたツリーでは、すべてのエッジが通常の領域を通過する通路を表します。 「特別なノードは最大 1 回アクセスできる」という制約は、頂点を繰り返さずにこの圧縮ツリー内のウォークに沿って含めることができる特別なノードの数に関する制約になります。 構造は依然としてツリーであるため、有効な最大ウォークは、この縮小されたツリー内の単純なパスに対応します。

したがって、開始ノードごとに、特別なノードが 1 回だけカウントされることを考慮しながら、そのノードを含むコンポーネントから始まる短縮ツリー内の最長の単純なパスを見つけることが答えになります。 

これは、古典的なツリー DP/リルート スタイルの問題になります。つまり、収縮されたツリー内の各ノードについて、そこから始まるパスで到達可能な特別なノードの最大数を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パス上のブルート フォース | O(2^M・N) | O(N) | 遅すぎる |
 | コンポーネントの縮小 + ツリー DP | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、通常のノードのみで形成される連結成分を特定します。 このような各コンポーネントは 1 つのスーパーノードにマージされます。 通常のみの領域内では、特別なノードの制約に影響を与えることなく、任意に何度でもトラバースできるため、これは有効です。 
2. 各ノードが特別なノードまたは通常のコンポーネントのスーパーノードを表す新しいツリーを構築します。 コンポーネントを接続する元のエッジが少なくとも 1 つある場合は、コンポーネント間にエッジを追加します。 
3. 各特別ノードに 1 の重みを割り当て、訪問ノードをカウントするか特別ノードのみをカウントするかに応じて、各通常コンポーネントに 0 または 1 の重みを割り当てます。 ここでは個別のノードを最大化しているため、短縮されたツリー内のすべてのノードが 1 に寄与しますが、通常のコンポーネントは構造的に再利用できますが、特別なノードは繰り返すことができません。 
4. 収縮ツリーを任意にルートし、標準ツリー DP を計算します。ここで、dp[u] は、u から始まる有効な下向きウォークにおける個別のノードの最大数です。 
5. DFS 中に、子を通じて最適な拡張を伝播します。 再訪問は動きを妨げない通常のコンポーネントを介してのみ許可されるため、縮小ツリー内の各エッジをパス構造内で一度使用できるものとして扱います。 
6. 各ノードが開始点となるように再ルート パスを実行し、親側と子側からの最適な貢献を組み合わせます。 
7. 結果を元のノードにマッピングします。同じ通常コンポーネント内のすべてのノードは同じ答えを共有しますが、特別なノードは個々の計算値を保持します。 

重要な推論ステップは、収縮後、ウォーク制約は、収縮されたツリー内のノードの再訪問を禁止するのと同等になるということです。これは、再訪問には、特別なノードを再訪問するか、個別性を侵害する方法で収縮された構造を再利用する必要があるためです。 したがって、問題は、ツリー内の最適な単純パス展開を計算することに帰着します。 

### なぜ効果があるのか

 通常のコンポーネントを圧縮した後、特別なノード間を移動するたびに、コンポーネントの一意のシーケンスを通過する必要があります。 特別なノードは再利用できないため、有効な最大ウォークは、縮小されたツリー内の単純なパスに対応します。 通常のノードを再訪問する機能では、コンポーネントの短縮によって既にエンコードされているものを超える追加の個別のパスは作成されません。これは、再訪問では単一の短縮されたノード内の内部トラバースのみが許可されるためです。 したがって、各開始ノードの答えは、この縮約ツリー内のそのコンポーネントから始まる最長の単純なパスのみに依存します。これはまさに再ルート DP が計算するものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    special = set(map(int, input().split()))

    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    # Step 1: build components of normal nodes
    comp = [-1] * (n + 1)
    comp_id = 0

    def dfs(u, cid):
        stack = [u]
        comp[u] = cid
        while stack:
            x = stack.pop()
            for y in g[x]:
                if comp[y] == -1 and y not in special:
                    comp[y] = cid
                    stack.append(y)

    for i in range(1, n + 1):
        if i not in special and comp[i] == -1:
            dfs(i, comp_id)
            comp_id += 1

    # each special node is its own component
    for i in range(1, n + 1):
        if i in special:
            comp[i] = comp_id
            comp_id += 1

    # Step 2: build contracted tree
    cg = [[] for _ in range(comp_id)]
    for u in range(1, n + 1):
        for v in g[u]:
            if comp[u] != comp[v]:
                cg[comp[u]].append(comp[v])

    # remove duplicates
    for i in range(comp_id):
        cg[i] = list(set(cg[i]))

    # Step 3: tree DP (two-pass reroot)
    sys.setrecursionlimit(10**7)
    parent = [-1] * comp_id
    order = []

    root = 0
    stack = [root]
    parent[root] = -2

    while stack:
        u = stack.pop()
        order.append(u)
        for v in cg[u]:
            if v == parent[u]:
                continue
            if parent[v] == -1:
                parent[v] = u
                stack.append(v)

    # subtree dp: best downward contribution
    dp = [1] * comp_id  # each node counts as 1

    for u in reversed(order):
        for v in cg[u]:
            if v == parent[u]:
                continue
            dp[u] = max(dp[u], 1 + dp[v])

    # reroot DP
    ans_comp = [0] * comp_id

    def reroot(u, acc_from_parent):
        # collect top two children contributions
        best1 = best2 = acc_from_parent
        for v in cg[u]:
            if v == parent[u]:
                continue
            val = dp[v] + 1
            if val > best1:
                best2 = best1
                best1 = val
            elif val > best2:
                best2 = val

        ans_comp[u] = best1

        for v in cg[u]:
            if v == parent[u]:
                continue
            use = best1 if best1 != dp[v] + 1 else best2
            reroot(v, use)

    reroot(root, 1)

    # map back
    res = [0] * (n + 1)
    for i in range(1, n + 1):
        res[i] = ans_comp[comp[i]]

    print(*res[1:])

t = int(input())
for _ in range(t):
    solve()
```実装は、反復 DFS を使用して、すべての通常のノードを接続されたコンポーネントにグループ化することから始まります。 これにより、再帰の深さの問題が回避され、各通常領域が単一のユニットになることが保証されます。 各特別なノードには独自のコンポーネントが割り当てられるため、他のノードとマージすることはできません。 

圧縮後、コンポーネント間の新しい隣接リストを構築します。 複数の元のエッジが同じ 2 つのコンポーネントを接続できますが、パス構造は変更されないため、重複したエッジは削除されます。 

コア DP は、最適な下向きパスを計算するサブツリー パスと、最適な上向き寄与を伝播する再ルート パスで構成されます。 再ルート手順では、上位 2 つの最良の子寄与を維持することで、除外される子が二重にカウントされることを慎重に回避します。 

最後に、元のすべてのノードはそのコンポーネントの値を継承します。 

## 実用的な例

 中央のノードが特殊である 3 つのノードの単純なチェーン (1-2-3、うち 2 つは特殊) を考えてみましょう。 

コンポーネントを構築します。ノード 1 と 3 は通常のコンポーネント構造を形成し、ノード 2 は独自のコンポーネントになります。 縮約ツリーは 1component-2-3component です。 

| ステップ | ノード | DP | 最高の子 | 答え |
 | --- | --- | --- | --- | --- |
 | 初期化 | 1c | 1 | - | - |
 | 初期化 | 2 | 1 | - | - |
 | 初期化 | 3c | 1 | - | - |

 DP の伝播後、各エンドポイントはそれ自体から開始して 3 つのノードすべてに到達できます。 リルートステップにより対称性が確認されます。 

ここで、中心が通常で葉が特別である星を考えてみましょう。 任意の葉から開始して、中心を通って他のすべての葉に移動できますが、葉は特別であるため、再度訪問することはできません。 

| ステップ | ノード | DP | acc | 答え |
 | --- | --- | --- | --- | --- |
 | 初期化 | 中央 | 2 | - | - |
 | 初期化 | 葉 | 1 | - | - |

 再根付は、任意の葉から開始すると中心を通ってすべての葉まで完全に横断し、中心から開始すると最大の広がりが得られることを示しています。 

これらのトレースは、特別なノードにシングルビジット制約を適用しながら、縮小された構造が到達可能性を正しく維持していることを示しています。

 ## 特殊なケース

 すべてのノードが正常な場合には特殊なケースが発生します。 この場合、ツリー全体が 1 つのコンポーネントになり、すべての開始ノードは N を返す必要があります。縮小ステップではすべてがマージされ、構造が 1 つのスーパーノードに縮退するため、DP はすべてのノードにフル サイズを正しく割り当てます。 

もう 1 つのケースは、すべてのノードが特別な場合です。 その後、各ノードは縮小ツリー内で分離されます。 特別なノードを再度訪問しない限り移動は不可能であるため、DP は答え 1 を持つ各ノードに帰着します。 

通常のツリーの奥深くに 1 つの特別なノードがある混合ケースでは、短縮によって接続が正しく維持されるかどうかがテストされます。 たとえば、1 つのノードだけが特別な長いチェーンでも、任意の点から開始してチェーン全体を横断することができ、縮小されたツリーは、特別なノードが通過を妨げず、再訪問を制限するだけであることを正しく反映します。
