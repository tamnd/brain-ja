 ## 解決策
 ## 問題の理解

 私たちには無限の塔が与えられています。 各フロアには正確に$n$部屋があり、各部屋に 1 名が宿泊できます。 人を床に置く$x$費用$2x$予算の単位を超えない限り、同じフロアに複数人を配置することができます。$n$そこにいる人々。 

各テスト ケースには、フロアごとの収容人数が与えられます。$n$そして総予算$m$。 私たちは予算を正確に使用しなければなりません。それより少なくても多くてもいけません。 正確に支出しながら人々をフロアに割り当てる有効な方法の中でも、$m$、配置する人数を最大化したいと考えています。 予算を正確に達成することが不可能な場合は、出力します。$-1$。 

重要な構造は、コストが人ではなくフロアのインデックスのみに依存し、すべてのフロアが同一の「コスト項目」の制限された供給のように動作するということです。$x$まで提供します$n$アイテム、それぞれのコスト$2x$、それぞれ1人が貢献します。 

制約は次のとおりです$10^{18}$これにより、単純な方法でフロアごとまたは人ごとに反復されるソリューションは即座に除外されます。 いずれかの直線的なアプローチ$n$、$m$、または階数が不可能です。 解決策では、問題をテスト ケースごとの対数または平方根の動作のようなものに減らす必要があります。 

微妙な問題は、コストの実現可能性だけを最適化しているのではなく、正確な合計の制約の下で人数を最大化していることです。 このため、貪欲な「最も安いものを最初に埋める」アプローチは自明ではなくなります。オーバーシュートしたり、埋められない剰余が残ったりすると、構築が無効になるからです。 

素朴な推論を打ち破るエッジケースには、予算の同等性が満たされない状況が含まれます。 あらゆるコストがかかるため、$2x$、合計予算は均等である必要があります。 たとえば、次の場合$m = 5$に関係なく、割り当ては存在できません。$n$, すべての合計は 2 の倍数であるためです。 

容量が不足すると別の失敗例が現れます。$n$とても小さいです。 たとえば、次の場合$n = 1$そして$m = 30$、同じフロアに複数の人を重ねることはできないため、解決策は個別のフロアコストを選択することになります。$2,4,6,\dots$、単純なプレフィックスフィルではなく、制約されたコインシステムのように動作します。 

## アプローチ

 総当たりの観点は各フロアを処理することです$x$までのものとして$n$同一の原価項目$2x$、合計コストが正確になるように、各フロアに何人配置するかを選択してください。$m$選択したアイテムの総数を最大化します。 これは直接、最大で有界ナップザック問題になります。$10^{18}$可能な項目タイプがあるため、明示的な動的プログラミングや反復は絶望的です。 コストが超過するまでフロアを繰り返しても$m$あきらめる$10^{18}$最悪の場合は状態。 

重要な観察は、コスト構造が階数に応じて厳密に増加しており、すべての項目が同じ値を持っていることです (各人が回答に 1 つだけ貢献しています)。 これは、単価あたりの人数を最も効率的に増やすことができるため、可能な限り安いフロアを常に好むことを意味します。 

ただし、完全合計要件があるため、残りの実現可能性を確認せずに、貪欲にできるだけ安価なアイテムを取得することはできません。 

問題を 2 つの層に分けることでこれを解決します。 まず、すべてのコストを 2 で割って半分の単位で作業します。$x$費用$x$、合計予算は次のようになります$m' = m/2$。 もし$m$奇妙です、答えはすぐには不可能です。 

次に、決定事項を個人ではなくフロアごとにグループ化します。 フロアをフルに使ったら$x$、私たちは取る$n$犠牲を払う人々$x$それぞれ、サイズのブロックに貢献します$n$。 これにより、問題は、完全なフロアをいくつ使用するか、さらに次のフロアの一部を選択するかという問題に変わります。 

余裕があるうちに貪欲に1階から順に全フロアを取得していきます。 フロアを完全に占領したら$1$を通して$k$、消費されるコストは$$n(1 + 2 + \dots + k) = n \cdot \frac{k(k+1)}{2}.$$私たちはそのような最大のものを選択します$k$を超えないもの$m'$。 その後、残りの予算をフロアに分配します$k+1$、追加人数ごとに料金がかかります$k+1$。 

これにより、問題はテスト ケースごとの少数の算術演算に軽減されます。

 | フロアブロックの貪欲な構造 |$O(\sqrt{m})$テストケースごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ここでは、最適な割り当てを直接構築する方法で構築を段階的に説明します。 

## アルゴリズムのチュートリアル

 1.設定により予算を半単位に換算$m' = m / 2$。 もし$m$奇数です、戻ります$-1$すべての有効なコストは均等であるため、すぐに実行されます。 
2. 完成したフロアの最大数を見つける$k$床を完全に埋めるように$1$を通して$k$と$n$各人が予算を超えることはありません。 これらのフロアを完全に埋めるコストは次のとおりです。$n \cdot k(k+1)/2$。 増やします$k$このまま貪欲に$m'$。 
3. これらのフロア全体のコストを以下から差し引きます。$m'$。 残りの予算は次のフロアにのみ関連するようになりました$k+1$。 
4. 床の上で$k+1$、各人にかかる費用$k+1$、最大でも配置できます$n$人々。 残りの予算を超えない範囲でできるだけ多くの予算を追加します。$\min(n, \lfloor m' / (k+1) \rfloor)$人々。 
5. これらの手順の後、残りの予算が正確にゼロにならない場合、構築は無効となり、リターンされます。$-1$。 それ以外の場合、人数の合計は、フロア全体の負担金とフロアの一部負担金の合計となります。 

### なぜ効果があるのか

 どの段階においても、各人が平等に目的に貢献し、低層階では消費する予算が厳密に少なくなるため、高価なフロアよりも安価なフロアを完全に優先します。 より高価なフロアを使用しながら、より少ない人数をより安価なフロアに配置するような逸脱は、総数を減らすか維持するだけであり、改善することはありません。 

全フロア安心の構造です。$1$を通して$k$フロアを考慮する前に飽和状態になっている$k+1$。 コストは線形であり、フロアごとのキャパシティーは均一であるため、実行可能性や総コストを変えることなく、人数を減らすことなく、最適なソリューションをこの貪欲な形式に変換できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())

        if m % 2 == 1:
            print(-1)
            continue

        m //= 2

        # find maximum k such that n * k(k+1)/2 <= m
        k = 0
        while True:
            cost = n * (k + 1) * (k + 2) // 2
            if cost <= m:
                k += 1
            else:
                break

        used = n * k * (k + 1) // 2
        rem = m - used

        ans = n * k
        ans += min(n, rem // (k + 1))

        # check exact spend
        if used + min(n, rem // (k + 1)) * (k + 1) != m:
            print(-1)
        else:
            print(ans)

if __name__ == "__main__":
    solve()
```ソリューションは、フロアにいる全員がコストを正常化できるようにすることから始まります。$x$費用$x$。 これにより、推論全体で係数 2 を運ぶことが回避されます。 

のループ$k$総コストを実現可能なままにしながら、完全に埋まっているフロアの数を増やすことができます。 各反復は、次に安いフロアを飽和状態にすることを約束することを表します。$n$人々。 

フロア全体を修正した後、残りは次のフロアで処理され、追加の各人に一律のコストがかかるため、整数除算を使用して可能な限り最良のフィルを計算できます。 

最終的な実現可能性チェックでは、現在のフロアコストを使用して表現できない予算が残ることになる部分的な可算性に依存していないことを確認します。

 ## 特殊なケース

 いつ$m$が奇数である場合、有効な構築はすべて偶数の総コストのみを使用するため、アルゴリズムはそのケースを即座に拒否します。 これはフロア推論が始まる前に処理されます。 

いつ$n = 1$、各フロアは最大でも 1 人しか貢献できないため、ソリューションは厳密な合計の制約の下で個別のフロア インデックスを選択することに退化します。 貪欲なフルフロア構造は、単位多重度を備えた連続する整数の選択を反映しているため、依然として機能します。 

いつ$n$が非常に大きい場合、正規化後の単位コスト ステップでフロア 1 だけですべてのバジェットを吸収できるため、ソリューションは事実上、バジェットが使い果たされるまでフロア 1 のみを取得するように崩壊し、より高いフロアはカウントの最大化に決して有益ではありません。 

予算が満床の三角数をわずかに上回る場合、残りは床を踏みます$k+1$が重要になり、その正しさは、利用可能な予算やフロア容量を超えないようにするために整数の除算を使用するかどうかに依存します。
