 ## 解決策
 ## 問題の理解

 負ではない整数のシーケンスから始めます。 各移動では、隣接する 2 つの要素を選択し、それらの合計を実行中のスコアに加算し、その同じ合計をそれら 2 つの要素間の配列に挿入し直します。 この挿入により配列の構造が変更されるため、今後の操作は新しく作成された値にも作用できるようになります。 

このような操作を一定回数正確に実行した後、可能な限り最大のスコアが必要になります。 各操作はスコアに寄与し、配列を永続的に変更するため、マージの順序と選択が重要になります。 多くのクエリに答えるように求められます。各クエリでは、実行する必要がある操作の数が指定され、その正確な数に対して達成可能な最高のスコアが返されます。 

この制約は、操作ごとに繰り返される配列の更新に依存するシミュレーションを即座に除外するような厳しいものです。 すべてのテスト ケースにわたる要素とクエリの合計数は最大 200,000 で、各操作は概念的に配列サイズを変更するため、n が約 200,000 の単一のテスト ケースであっても、クエリごとに対数または線形以上の作業を行うことができません。 最適な選択をステップごとまたはクエリごとに個別に動的に再計算するソリューションは、制限を超えることになります。 

素朴な推論による微妙な失敗例は、貪欲なローカル決定で十分であると仮定した場合に現れます。 たとえば、常に最大の隣接合計をマージすることは最初は合理的であるように見えますが、大きな値を早期に挿入すると将来の隣接構造が変更され、より適切な累積パターンがブロックされるため、失敗します。 

別の失敗モードは、元の隣接ペアのみが重要であると仮定することです。 たとえば、`[1, 2, 3]`、合併後`2+3=5`、新しい値は将来のマージに参加し、最適なシーケンスは元の構造ではなく新しく作成された合計に依存する可能性があります。 この進化する構造を無視するアプローチは、有効な高スコア構造を見逃します。 

最後に、各クエリを個別に処理すると、同じ動的構造を繰り返し再計算することになりますが、テスト ケースあたり最大 200,000 のクエリを考慮すると、これでは遅すぎます。 

## アプローチ

 ブルートフォース解釈は簡単です。 各ステップで、すべての隣接するペアを試し、その結果のスコア寄与を計算し、挿入をシミュレートし、必要な操作数に達するまで再帰的または反復的に続行します。 これは、考えられるすべてのマージ シーケンスを調査するため、正しいです。 ただし、操作ごとに配列サイズが 1 ずつ増加し、各ステップで配列をスキャンして最善の手を見つけるか、すべての可能性を試す必要があります。 最悪の場合、k 個の操作を実行すると、配列が大きくなり隣接関係の更新にコストがかかるため、実装に応じて O(k n + k^2) かそれ以上のコストがかかります。 n と k が最大 200,000 であるため、これは完全に不可能です。 

重要な観察点は、運用構造が非常に規則的であるということです。 すべての操作は 2 つの隣接する値を取得し、その境界をそれらの合計で置き換え、同じ値がスコアに追加されます。 これは、各操作が動的に展開する隣接グラフ内のエッジを効果的に選択することを意味しますが、どの操作の寄与も常に、以前のマージの何らかの構造によってもともと分離されていた 2 つの数値の正確な合計になります。 

重要な単純化は、マージがどのように実行されたとしても、挿入された要素の値は常に元の配列の連続セグメントの合計であることです。 これは、すべての操作が、何らかの連続したセグメントを選択し、それを 1 回「カット」して、その合計に寄与するとみなせることを意味します。 繰り返し挿入のプロセスは、繰り返しセグメントを分割することに対応し、蓄積されるスコアは、すべての分割で作成されたセグメントの値の合計です。 

これにより、問題は初期配列から導出されたセグメントの重みの管理に再構成されます。 最善の戦略は、分割するために現在利用可能な最良のセグメントを繰り返し選択することです。セグメントを分割すると、その合計が利益として正確に得られ、その後、将来の貢献がさらなる分割に依存する 2 つの小さなセグメントが生成されるためです。 

これは現在、古典的な「最大の重量増加を繰り返し取得する」構造になっており、常に候補セグメントの合計を維持し、利用可能な最大のセグメントを常に選択します。 各分割では 2 人の新しい候補者が導入されます。 必要なのは次の最適な操作だけであるため、優先キューで十分です。プレフィックス合計を介してすべてのセグメント合計を事前計算して、任意の間隔合計の O(1) クエリを許可できます。 

残りの洞察は、すべてのクエリを個別にシミュレートする必要はないということです。 代わりに、すべてのクエリの最大 xi までの操作数ごとに、達成可能な最良のスコアを事前計算できます。 これは、各ステップが現在のセグメント合計の最大値を選択するシーケンス生成問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 / O(k² n) | O(n + k) | 遅すぎる |
 | セグメント合計より優先キューを使用する貪欲な | O((n + 最大 x) log n) | O(n + 最大 x) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、考えられるすべての操作を、セグメントを 2 つの小さなセグメントに分割するものと解釈します。ここで、ゲインは分割されるセグメントの合計です。 これを効率的に実行するために、当社は現在利用可能なセグメントの構造を維持しています。

1. 初期配列のプレフィックスの合計を計算して、セグメントの合計を定数時間で計算できるようにします。 これが必要なのは、動的に形成されたセグメントの合計を最初から再計算せずに頻繁に評価するためです。 
2. 配列全体を表す 1 つのセグメントで最大ヒープを初期化し、その合計とインデックス範囲を保存します。 これは、最初は配列全体が分割可能な 1 つの利用可能なセグメントであるという事実を表します。 
3. 1 から最大クエリ値までの各操作について、最大の合計を持つセグメントをヒープから抽出します。 この選択は正しいです。すべての演算が常に、選択したセグメントの合計に正確に寄与するため、分割によって独立した部分問題のみが作成される構造では、即時ゲインを最大化することが最適です。 
4. 抽出されたセグメントの合計を、この歩数の全体的な答えに加算します。 
5. 選択したセグメントを中間点で分割し、2 つのサブセグメントを作成します。 サイズが少なくとも 1 のセグメントのみをさらに分割できるため、結果として得られる両方のセグメントの長さが少なくとも 1 の場合はヒープにプッシュします。 
6. すべてのクエリに答えるのに十分な操作を処理するまで繰り返します。 

最大のクエリまでのすべての k の答えを計算した後、各クエリは O(1) で答えられます。 

これが機能する理由は、セグメント分解の不変式に由来します。 どの時点でも、ヒープ内のセグメントのセットは、元の配列の分割を、互いに素な連続した間隔に形成します。 各操作では、分割するセグメントを 1 つだけ選択し、ゲインは正確にその合計になります。 有効な操作シーケンスはすべて、このパーティション構造に対する分割選択肢のシーケンスに対応します。 各セグメントは、将来の分割を除いて他のセグメントから独立しているため、各ステップで利用可能な最大のセグメント合計を選択すると、パーティションの細分化を超えた将来の分割の実現可能性に影響を与えることなく、現在の寄与が最大化されます。 この貪欲な選択は、システムで利用可能な限界ゲインを常に最大限に引き出すことと一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        q = int(input())
        queries = list(map(int, input().split()))
        maxk = max(queries)

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        def seg_sum(l, r):
            return pref[r] - pref[l]

        # max-heap: (-sum, l, r)
        heap = []
        heapq.heappush(heap, (-(seg_sum(0, n)), 0, n))

        # answers for k operations
        ans = [0] * (maxk + 1)

        for k in range(1, maxk + 1):
            neg_s, l, r = heapq.heappop(heap)
            s = -neg_s
            ans[k] = ans[k - 1] + s

            if r - l > 1:
                mid = (l + r) // 2
                heapq.heappush(heap, (-(seg_sum(l, mid)), l, mid))
                heapq.heappush(heap, (-(seg_sum(mid, r)), mid, r))

        print(*[ans[x] for x in queries])

if __name__ == "__main__":
    solve()
```この実装では、定数時間の範囲合計クエリをサポートするためにプレフィックス合計を構築します。 最大ヒープは負の値を使用してシミュレートされ、各アクティブ セグメントをインデックスのペアとして保存します。 各反復では、分割するのに最適なセグメントが抽出され、その寄与分が実行中の応答に追加され、中間点での分割後に 2 つの子がプッシュされます。 

主要な特性は、分割によってセグメントが独立したサブセグメントに縮小されることであるため、中間点の選択は構造の正確さの観点からは任意です。 重要なのは、ヒープが使用可能なセグメントとその合計を常に正確に追跡することです。 

各ステップは以前の最良の状態のみに依存するため、回答を段階的に蓄積するように注意する必要があります。

 ## 特殊なケース

 重大なエッジケースは、最大のセグメントが、将来の利益のために直ちに分割されるべきセグメントではない場合です。 たとえば、`[10, 1, 1]`、セグメント全体の合計は 12 ですが、構造を保持することに比べて、分割することは長期的には最適ではない可能性があります。 このアルゴリズムは、現在のステップを超えて取り消し不能な決定をコミットすることはないため、引き続き正しく処理されます。 将来のステップのために結果として得られるすべてのセグメントを維持しながら、即時貢献のための貪欲な選択のみを使用します。 

もう 1 つのエッジ ケースは、複数のセグメントの合計が等しい場合です。 ヒープの順序付けは合計によってのみ安定するため、タイブレークは問題ではありません。すべてのタイ セグメントが同様に寄与し、それらのいずれかを分割すると、将来のセグメント合計のマルチセットが保存されるからです。 

3 番目のケースは最小限の入力です`[a1, a2]`。 可能な操作パスは 1 つだけです。 ヒープは 1 つのセグメントから始まり、ポップされて、それ以上分割できない 2 つのシングルトンに分割されます。 このアルゴリズムは、次の値に等しい寄与を 1 つだけ生成します。`a1 + a2`、唯一の有効な操作シーケンスと一致します。
