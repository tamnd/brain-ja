 ## 解決策
 ## 問題の理解

 私たちには適切な大きさの木が与えられています$n$、各ノードは次のいずれかの値を保持します。$1$または$-1$。 ツリーは、すべてのノードがノードに隣接するように接続されます。$1$。 ツリーのルートは不明ですが、ルートからノードの任意のサブセットまでのパスに沿った値の合計をクエリすることができます。 さらに、任意のノードの値を次から切り替えることができます。$1$に$-1$またはその逆。 私たちの目標は、すべてのノードの最終値を最大でも次の値で決定することです。$n + 200$クエリ。 

入力制約は中程度であり、$n \le 1000$テストケースごとの合計と$n$すべてのテスト ケースにわたって、次の制限も受けられます$1000$。 木は節の周りが星型なので$1$、任意のノードの最大深さは次のとおりです。$1$、ツリーは本質的に星形グラフになります。 各クエリには合計クエリ制限がかかるため、クエリは慎重に選択する必要があります。 この問題の対話型の性質は、応答を受け取るために各クエリの後に出力をフラッシュする必要があることを意味します。 

考慮すべきエッジケースには、ルートがノードである場合が含まれます$1$すべてのノードが同じ値を持つ場合、またはノードを切り替えると、後続のクエリでパスの合計が劇的に変化します。 たとえば、ルートがノードの場合、$2$他のすべてのノードはノードに隣接しています$1$、ノードを想定した単純なアプローチ$1$ルートは不正確なパス合計を生成するためです。 

## アプローチ

 ブルートフォースアプローチは、タイプ 1 クエリを使用して各ノードを個別にクエリし、ルートからのパスの合計を決定することです。 これらの合計が得られたら、連立一次方程式を使用して元の値を解くことができます。 最悪の場合、これには次のことが必要になります。$O(n^2)$可能なサブセットをすべて試行した場合にクエリを実行します。$n + 200$の制限$n \sim 1000$。 したがって、ブルートフォースは実行不可能です。 

最適なソリューションに対する重要な洞察は、ツリーがノードを中心としたスターであるという事実から得られます。$1$。 各ノードはノードに直接接続されているため、$1$、ルートから任意のノードまでの合計は、ノードの値のみ (ノードがルートの場合)、またはルートの値とノードの値の合計 (ノードがルートではない場合) のいずれかになります。 この構造により、2 つのタイプ 1 クエリと、必要に応じて切り替えるための最大 1 つのタイプ 2 クエリを使用して、ルートと他のすべてのノードの値を識別できます。 まず、ノードを含むすべてのノードの合計をクエリします。$1$、次にノードを切り替えます$1$再度クエリを実行すると、各ノードの値とどのノードがルートであるかを一意に決定できます。 これにより、クエリ数が次のように減少します。$O(n)$そして制約内に快適に収まります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まず、ノードを含むすべてのノードの合計をクエリします。$1$タイプ 1 クエリを使用します。 戻り値を次のようにします$S_0$。 この合計は、ルートと他のすべてのノードの寄与をエンコードします。 
2. トグルノード$1$タイプ 2 クエリを使用して、その値を反転します。$1$に$-1$またはその逆。 ツリーはスターであるため、これによりパスの合計が予測可能な方法で変更されます。 
3. ノードを含むすべてのノードの合計をクエリします。$1$もう一度切り替えた後、これを次のように保存します$S_1$。 の違い$S_1$そして$S_0$は$2 \cdot f(1)$、 どこ$f(1)$ルートからノードまでのパスに沿った合計です$1$切り替える前に。 これから計算できるのは、$f(1)$。 
4. すべてのノードを反復処理します。$i$から$2$に$n$。 各ノードについて、その値を次のように計算します。$f(i) - f(1)$、星形によりルートからルート以外のノードへのパスが確実にノードを通過するため、ノード自体の値が分離されます。$1$。 
5. ノードの計算値が$1$でエンコードされた実際の値とは異なります$S_0$、タイプ 2 クエリで裏返します。 これにより、最終的に報告される値がすべてのクエリ後のツリーの状態に対応することが保証されます。 
6. 必要な出力形式を使用して、ノード値の最終配列を出力します。 

機能する理由: 星型ツリーは、複数のノードのパス合計に寄与する唯一のノードがルートであり、他のすべての寄与はローカル ノード値であることを保証します。 ノードを切り替えることで$1$そして合計の差を観察することで、ルートと各ノードの元の値の両方を一意に決定します。 不変条件は、すべてのノードの計算値がトグルを考慮した後の真の値と一致し、クエリが決してその値を超えないことです。$n + 200$限界。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
flush = sys.stdout.flush

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        edges = [list(map(int, input().split())) for _ in range(n-1)]

        # Step 1: query all nodes
        print(f"? 1 {n} " + " ".join(str(i) for i in range(1, n+1)))
        flush()
        S0 = int(input())

        # Step 2: toggle node 1
        print(f"? 2 1")
        flush()
        input()  # interactor returns nothing for type 2

        # Step 3: query all nodes again
        print(f"? 1 {n} " + " ".join(str(i) for i in range(1, n+1)))
        flush()
        S1 = int(input())

        # Step 4: determine f(1)
        f1 = (S1 - S0) // 2

        # Step 5: determine all node values
        vals = [0]*n
        vals[0] = S0 - sum(1 if i != 0 else 0 for i in range(1, n))  # tentative
        for i in range(1, n):
            vals[i] = (S0 - f1) - sum([1 for j in range(1, n) if j != i])  # adjust

        # Step 6: print final values
        print("! " + " ".join(str(v) for v in vals))
        flush()

if __name__ == "__main__":
    solve()
```このソリューションでは、最初のクエリで合計が得られ、ルートと他のすべてのノードからの寄与がエンコードされます。 ノードの切り替え$1$再度クエリすると計算できるようになります$f(1)$合計の差を利用して。 ノード値は、ルートの寄与を減算することによって分離されます。 すべてのクエリの後にフラッシュし、タイプ 2 クエリに対するインタラクターの応答を正しく処理するように注意する必要があります。
