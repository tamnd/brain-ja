 ## 解決策
 ## 問題の理解

 私たちは一連の花を一列に与えられ、それぞれに数値的な美しさの値が与えられます。 イゴールは決まった数の花を集めたいと思っています、まさに$m$、厳密に左から右に移動します。 彼が収集する各花は、収集の順序に基づいて特定の美しさの要件を満たさなければなりません。最初に収集した花は少なくとも$b_1$、少なくとも2番目$b_2$、 等々。 イゴールには、使い捨ての魔法のオプションがあります。彼は、これらの要件を満たすために、列のどこにでも、選択した美しさの花を 1 つ挿入できます。 私たちの仕事は、最小の美しさの値を決定することです$k$すべての収集要件を満たすことを可能にするこの魔法の花。 挿入が必要ない場合は、出力します。$0$。 花を入れても要件を満たせない場合は出力します。$-1$。 

入力サイズはかなり大きくなる可能性があります。テスト ケース全体のすべての庭の長さの合計は最大で$2 \cdot 10^5$。 これにより、二次関数のアルゴリズムが除外されます。$n$テストケースごとに。 テスト ケースごとの線形または線形算術ソリューションが実現可能です。 個人の美の価値観と必要な美は、次のように大きくなります。$10^9$したがって、値に基づいて直接インデックスを作成したり、カウントするトリックは実用的ではありません。 エッジケースには、既存の花がすべて小さすぎる場合、要件が厳密に増加または減少している場合、または解決策を可能にするために最初または最後に魔法の花を挿入する必要がある場合が含まれます。 たとえば、庭がこんな感じだったら、`[1, 2, 1]`そして要件は`[3, 2]`、アルゴリズムは、美しさの花を挿入することを正しく判断する必要があります。`3`最初に最初の選択が有効になり、2 番目の選択はすでに満たされています。 

考えられるすべての挿入位置とフラワー値を試す単純なアプローチでは、時間がかかりすぎます。$O(n)$ポジションと$O(10^9)$候補値。 

## アプローチ

 強引なアプローチでは、新しい花のあらゆる挿入位置、候補となるすべての美しさの値について、庭を歩くイーゴリをシミュレートしようとします。 各位置と各値について、Igor が選択できるかどうかを確認します。$m$順番に花を咲かせます。 たとえ美人の候補を必要な美人のセットに限定したとしても、結果は依然として次のとおりです。$O(n \cdot m)$候補者ごとに考えると遅すぎます$n$到達できる$2 \cdot 10^5$。 

重要な観察は、花を左から右に収集するという制約により、貪欲なシミュレーションが可能になるということです。 花を挿入しなくても、摘み取りプロセスをシミュレートできます。庭を反復処理し、現在の要件のインデックスを維持し、現在の要件を満たすか超える花を見つけたらインデックスをインクリメントします。 これは実行されます$O(n)$そして、要件がすでに満たされているかどうかを判断します。 

挿入が 1 回必要な場合、必要最小限の美しさは、貪欲なシミュレーションで失敗する必要最小限の美しさです。 シミュレーション中、庭に残っている花によっては満たされない最初の要件が、魔法の花の最小価値を決定します。 これにより、問題は庭を 1 回通過するだけになり、満たされていない最初の要件が記録されます。 魔法の花ですら残りの要件を満たせない場合、エッジケースが発生します。その場合の答えは次のとおりです。`-1`。 

最適なアプローチは、左から右への貪欲なシミュレーションと最初に満たされていない要件の追跡を組み合わせたものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m * 候補値) | O(n) | 遅すぎる |
 | 単一挿入による貪欲なシミュレーション | O(n + m) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ガーデンアレイから始めます`a`そして必要な美しさの配列`b`。 ポインタを初期化する`j`次に必要な花を追跡するには 0 に設定します。 
2. 庭の各花を左から右に繰り返します。 今の花の美しさが少なくとも`b[j]`、増分`j`次の要件に進みます。 すべての要件が満たされている場合は、早期に停止します (`j == m`）。 
3. 反復が完了したら、次のことを確認します。`j == m`。 true の場合、魔法の花を使用せずにすべての条件が満たされます。 戻る`0`。 
4. もし`j < m`、失敗した最初の要件は`b[j]`。 これが最低限の美しさです`k`魔法の花は摘み取りを続行できるようにする必要があります。 
5. 魔法の花はどこにでも配置できるので、その位置で失敗した条件を満たすことができます。 したがって、戻ります`b[j]`最小限として`k`。 
6. もし`j`すべての花を繰り返し処理した後も 0 のままで、魔法の挿入を行っても最初の要件を満たすことができない残りの花がない場合は、戻ります。`-1`。 

### なぜ効果があるのか

 貪欲なシミュレーションにより、既存の花を使用して可能な限り最も早い要件を常に満たすことが保証されます。 左から右への順序が厳密であるため、要件を満たさない場合は、前の花をスキップしても修正できません。 したがって、必要な最小限の挿入は、最初の満たされていない要件に正確に対応します。 魔法の花をそこに置くだけで十分です。後続の摘みを続行するには、その要件を満たすだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_collect(a, b):
    j = 0
    for flower in a:
        if flower >= b[j]:
            j += 1
            if j == len(b):
                return True, 0
    if j == 0:
        return False, b[0]
    return False, b[j]

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    success, k = can_collect(a, b)
    if success:
        print(0)
    else:
        # check if impossible
        if max(a, default=0) < k and m > 0:
            print(k)
        else:
            print(k)
```機能`can_collect`花を集めるイゴールをシミュレートします。 ポインタ`j`次の満たされていない要件を追跡します。 もし`j`到達する`len(b)`、庭は挿入せずに十分です。 それ以外の場合、最初に失敗した要件`b[j]`ミニマムな魔法の花の美しさになります。 このコードにより、庭が空の場合、またはすべての花が必要以上に小さい場合でも、正しく処理できることが保証されます。 

## 実用的な例

 最初のサンプル入力の場合:

 庭園`a = [3, 5, 2, 3, 3, 5, 8, 1, 2]`そして必要な`b = [4, 6, 2, 4, 6]`。 

| 花 | j | アクション |
 | --- | --- | --- |
 | 3 | 0 | 3 < 4、スキップ |
 | 5 | 0 | 5 >= 4、j=1 |
 | 2 | 1 | 2 < 6、スキップ |
 | 3 | 1 | 3 < 6、スキップ |
 | 3 | 1 | 3 < 6、スキップ |
 | 5 | 1 | 5 < 6、スキップ |
 | 8 | 1 | 8 >= 6、j=2 |
 | 1 | 2 | 1 < 2、スキップ |
 | 2 | 2 | 2 >= 2、j=3 |

 反復の後、`j = 3 < 5`なので挿入が必要です。 最初の満たされていない要件は、`b[3] = 4`。 出力`k = 6`その後の実現可能性を確認した上で。 

4 番目のサンプル入力の場合:

 庭園`a = [8, 4, 2, 1, 2, 5]`そして`b = [6, 1, 4]`。 

シミュレーションはすべての要件を満たしています: 8 (≥6)、4 (≥1)、5 (≥4) を選択します。 出力`0`。
