 ## 解決策
 ## 問題の理解

 0 から n−1 までの数値の順列でなければならないリストが与えられます。 この順列を左から右に明らかにするときに、実行値を計算します。各プレフィックスの後で、そのプレフィックスから欠落している最小の非負の整数を取得します。 この値は、より多くの要素が出現するにつれて時間の経過とともに変化し、各プレフィックスが 1 つのセルをその現在の値で描画します。 

タスクは、固定順列に対してこのカラーリングを計算することではありません。 代わりに、結果として得られるペイントされたストリップに特定の色 x ができるだけ多く現れるように、順列自体を構築する必要があります。 

重要な相互作用は、順列内の要素の順序と、プレフィックスの MEX が x を通過する瞬間との間です。 MEX は 0 から上のどの値が出現したかにのみ依存するため、順序によって MEX が特定の値と等しくなるまでの期間が決まります。 

制約は十分に大きいため、テスト ケースごとにどのような解も線形である必要があります。 n の合計は最大 2×10^5 で、二次関数や候補順列ごとの繰り返しシミュレーションを伴うものは除外されます。 施工は直接施工でなければなりません。 

x = n の場合、微妙なエッジケースが発生します。 その場合、MEX は、0 から n-1 までのすべての数値が出現した後でのみ n と等しくなります。 つまり、最後のプレフィックスでのみ発生するため、配置に関係なく、答えは常に 1 になります。 x を通常の値のように扱う素朴な試みは、誤って MEX を n を超えて「遅延」させようとすることになりますが、これは不可能です。 

もう 1 つのエッジ ケースは x = 0 です。ここで、MEX は最初は 0 で、0 が現れるとすぐに 1 になります。 したがって、カラー 0 の最初の実行を延長するために、0 の配置をできるだけ長く延期したいと考えています。 

## アプローチ

 強引なアイデアは、すべての順列を生成し、それぞれの順列に対して MEX プロセスをシミュレートし、色 x が出現する回数をカウントすることです。 これは正しいですが、実行不可能です。 あるよ！ 1 つの順列を評価するだけでも O(n) のコストがかかるため、このアプローチは天文学的な規模になります。 

最適化するには、連続するプレフィックスに対して MEX が x に等しくなる理由を理解する必要があります。 MEX は、0 から x−1 までのすべての数値がプレフィックスに出現しているが、x 自体がまだ出現していない場合に、x と正確に等しくなります。 x が挿入されると、MEX は x より大きい値にジャンプします。 

これは、MEX がすでに x に達するように、すべての小さい数値が十分早く現れるようにしながら、x の挿入をできるだけ長く遅らせたいことを意味します。 その瞬間以降、x が挿入される前に追加要素が追加されるたびに、MEX は x に固定され、一定の色の望ましい範囲が得られます。 

唯一の実際の決定は、数値 0 から x−1 に対して x をどこに配置するかです。 これらの小さい数値がすべて存在すると、x がまだ欠落している限り、MEX が x であることに影響を与えることなく、x より大きいすべての数値をどこにでも自由に配置できます。 

これにより、単純な最適な構成が得られます。最初に x より大きいすべての数値を配置し、次に 0 から x−1 までを配置し、最後に x を最後に配置します。 これにより、プレフィックスに x より小さいすべての値が含まれるが、x 自体は含まれない時間間隔が最大化されます。

 ## アルゴリズムのチュートリアル

1. 順列を 3 つの概念グループに分割します。x より大きい数値、0 から x−1 までの数値、および単一の値 x 自体です。 この分離は、各グループが MEX 値にどのような影響を与えるかに基づいています。 
2. x より厳密に大きいすべての数値を順列の先頭に配置します。 これらの値は、MEX = x を決定するプレフィックスの形成には役立ちませんが、干渉することもありません。 
3. 0 から x−1 までのすべての数字を直後に置きます。 これにより、このブロックがプレフィックスに完全に含まれると、MEX を x までプッシュするために必要なすべての値が出現することが保証されます。 
4. x をできるだけ後ろに、理想的には最後に配置します。 これにより、すべての小さい値が存在するが x がまだ存在しないプレフィックスの数が最大化されます。これはまさに MEX が x と等しくなる条件です。 
5. 構築されたシーケンスを出力します。 

重要な考え方は、プレフィックスに 0 から x−1 までのすべての値が含まれると、MEX は x になり、x が現れるまでそこに留まるということです。 私たちは最後のイベントをどれだけ遅らせることができるかを最大限に検討しています。 

### なぜ効果があるのか

 プレフィックスの MEX は、どの最小値が欠落しているかによって完全に決定されます。 MEX を x と等しくするには、2 つの条件が同時に成立する必要があります。0 から x−1 までのすべての値がすでに存在している必要があり、x がまだ存在していない必要があります。 両方が満たされると、x より大きい値を追加しても MEX は変更されません。これは、x より小さい整数が不足している場合には満たされないためです。 したがって、0 から x-1 までの最初の完全な出現の後、および x より前のすべての位置は、色 x の有効な出現に寄与します。 この構築では、x を遅らせながらすべての小さな値ができるだけ早く表示されるようにすることで、この間隔を最大化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())

    if x == n:
        # MEX can only become n at full prefix
        print(*range(n))
        continue

    res = []

    # first put all values > x
    for i in range(x + 1, n):
        res.append(i)

    # then values < x
    for i in range(x):
        res.append(i)

    # finally x
    res.append(x)

    print(*res)
```この実装は、[0, x−1] に対する x の相対位置のみが重要であるという観察に直接従っています。 x より大きい値は、MEX が x になるタイミングに影響を与えることなく、x の前のどこにでも配置できるため、それらを安全に最初に配置します。 ループの境界は重要です。最初のループは x 自体を除外するために x+1 から始まり、2 番目のループは x−1 まで続きます。 

特殊なケース x = n は、x が順列範囲外である空の概念的条件を回避します。 この場合、MEX が最後のプレフィックスの前の n と等しくなることはないため、最適な配置は無関係です。 

## 実用的な例

 代表的な 2 つのケースを追跡します。 

### 例 1: n = 4、x = 2

 順列を構築します。 

| ステップ | 追加されたブロック | 現在の順列 |
 | --- | --- | --- |
 | 1 | 値 > 2 → [3] | [3] |
 | 2 | 値 < 2 → [0, 1] | [3、0、1] |
 | 3 | xを追加 → [2] | [3、0、1、2] |

 次に、MEX の進化を調べます。 

| プレフィックス | 要素 | メキシコ |
 | --- | --- | --- |
 | 1 | [3] | 0 |
 | 2 | [3, 0] | 1 |
 | 3 | [3、0、1] | 2 |
 | 4 | [3、0、1、2] | 4 |

 色 2 は 1 回だけ表示されます。 この構造により、できるだけ早く MEX = 2 に到達し、x が表示されるまで安定した状態が維持されます。 

### 例 2: n = 5、x = 0

 | ステップ | 追加されたブロック | 現在の順列 |
 | --- | --- | --- |
 | 1 | 値 > 0 → [1, 2, 3, 4] | [1、2、3、4] |
 | 2 | 値 < 0 → [] | [1、2、3、4] |
 | 3 | xを追加 → [0] | [1、2、3、4、0] |

 MEX の進化:

 | プレフィックス | 要素 | メキシコ |
 | --- | --- | --- |
 | 1 | [1] | 0 |
 | 2 | [1,2] | 0 |
 | 3 | [1,2,3] | 0 |
 | 4 | [1,2,3,4] | 0 |
 | 5 | [1,2,3,4,0] | 5 |

 カラー 0 は、0 が配置されるまですべてのプレフィックスに表示され、その頻度が最大になります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テストあたり O(n) | 各数値は構造内に 1 回だけ配置されます。 
| スペース | O(n) | 結果の順列を保存します。 

すべてのテスト ケースの合計 n は最大 2×10^5 であるため、線形構成は制限時間内に簡単に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n, x = map(int, input().split())
        if x == n:
            out.append(" ".join(map(str, range(n))))
            continue

        res = []
        for i in range(x + 1, n):
            res.append(i)
        for i in range(x):
            res.append(i)
        res.append(x)
        out.append(" ".join(map(str, res)))

    return "\n".join(out)

assert run("1\n5 4\n") == "0 1 2 3 4", "x near end"

 ## 特殊なケース

 x = n の場合、アルゴリズムは恒等順列を採用します。 n = 3、x = 3 のような小さな例では、この構造は [0, 1, 2] を生成します。 MEX はすべての要素が表示された後にのみ 3 に達するため、最後のプレフィックスだけがターゲット カラーに寄与します。 

x = 0 の場合、この構造では他のすべての値が最初に配置され、次に 0 が最後に配置されます。 n = 4、x = 0 の場合、[1, 2, 3, 0] が得られます。 MEX は、達成可能な最大スパンである 0 が現れるまで、すべてのプレフィックスに対して 0 のままです。 

n = 6、x = 2 など、x が中央にある場合、シーケンス [3, 4, 5, 0, 1, 2] により、0 と 1 が出現すると MEX が 2 になり、2 が追加されるまでそこに留まり、カラー 2 セルの数が最大化されます。
