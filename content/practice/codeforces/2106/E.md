 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列が与えられ、多くの独立したクエリに答える必要があります。 各クエリはサブ配列範囲を選択します$[l, r]$そして目標値$k$。 配列がソートされていない場合でも、その固定範囲に対して標準の二分探索プロセスを実行することを想像します。 

このシミュレートされた二分探索の各ステップで、現在の間隔の中点を調べます。 中間点にすでに次の値が含まれている場合$k$、検索は成功します。 それ以外の場合、中点値が以下の場合$k$、右半分に進みます。 それが大きい場合は、左半分に進みます。 このプロセスは、配列値を考慮すると完全に決定的です。 

検索を開始する前に、内部でいくつかのインデックスを選択できます。$[l, r]$、ただし、の位置を選択することは禁止されています。$k$。 選択したインデックスの値を自由に並べ替えることができます。 目標は、二分探索で次の位置に正常に到達することです。$k$選択したインデックスをできるだけ少なくします。 

したがって、タスクは次のとおりです。二分検索が正しく動作し、最終的に検索が完了するように、クエリごとに「ローカルに再配置」する必要がある要素の最小数を決定します。$k$、またはそれは不可能であると報告します。 

制約は厳しいです: 合計$n$そして合計$q$すべてのテストケースにわたって、$2 \cdot 10^5$。 これにより、範囲にわたる再計算と組み合わせたバイナリ検索のクエリごとのシミュレーションが即座に排除されます。$O(n)$最悪の場合、クエリごとの速度がすでに遅すぎる可能性があります。 

主な難点は、二分探索がグローバルな順序付けではなく、一連の中間点の比較に依存していることです。 単純な間違いは、「小さいものはすべて左に移動し、大きいものはすべて右に移動」するだけでよいのに、セグメントを並べ替えていない、と仮定することです。 限られた数の位置のみを固定しているため、二分探索パスの構造が重要です。 

微妙なエッジケースが現れるのは、$k$は最初の検索間隔には存在しません。 要素を並べ替えることはできても、移動することはできません$k$それ自体または範囲外から導入します。 もし$k \notin [l, r]$、すぐに成功するのは不可能です。 

## アプローチ

 ブルートフォース手法では、バイナリ検索パスをシミュレートし、訪問した各中間点で、検索を正しい方向に導くためにその位置を「修正」する必要があるかどうかを判断します。 固定クエリの場合、次のバイナリ検索パスをシミュレートできます。$[l, r]$中間値が最終的に到達するために必要な値と矛盾する場合は常に$k$、修正が必要なものとしてカウントされます。 次に、すべての矛盾を同時に解決するためにどのインデックスを選択するかをグローバルに決定しようとします。 

これは、バイナリ検索パス上にある場合、選択された 1 つのインデックスで複数のステップを解決でき、クエリ間で異なるパスが自明ではない方法で重複するため、すぐに複雑になります。 クエリごとの単純な再計算では、潜在的にバイナリ検索ロジックも再実行されます。$O(n)$病理学的症例におけるステップ、$O(nq)$、大きすぎます。 

重要な観察は、固定セグメントに対する二分探索は恣意的ではないということです。二分探索は常に決定論的なインデックスのセットを参照し、二分分解ツリーを形成します。$[l, r]$。 各中間点は決定制約を定義します。左に進むか右に進むかは比較に依存します。$p[m]$と$k$。 検索を成功させるには、その過程でのあらゆる決断が必要です。$[l, r]$まで$k$の真の相対順序と一致していなければなりません$k$。 

インデックスを 3 つのカテゴリに分類します。$k$: より小さい値$k$、に等しい$k$、およびそれ以上$k$。 の位置$k$は固定されており、からのバイナリ検索パスは$[l, r]$に$pos(k)$常にそれに向かって進まなければなりません。 つまり、パス上のすべての中間点には方向要件が課されます。中間点が左側にある場合は、$pos(k)$、左右に誤ってルーティングされないことを確認する必要があります。 右側も同様に。 

決定的な削減点は、二分探索で訪れるすべての中間点がすでに正しく動作しているか、選択したセットにそのインデックスを含めることによって修正する必要があるということです。 選択したインデックスを任意に並べ替えることができるため、パスに沿ったすべての「誤った決定」を満たすのに十分なインデックスを選択すれば、常に正しい値を割り当てることができます。 

これにより、問題は、バイナリ検索パスに沿った必要な方向と矛盾する中間点の位置がいくつあるかを数えるという問題に軽減されます。$k$、実現可能性の制約の下で、相対的に利用可能な小さい値と大きい値の数によって決定されます。$k$。 

## アルゴリズムのチュートリアル

 1. 置換内の各値の位置を事前に計算して、位置を特定できるようにします。$pos(k)$で$O(1)$。 バイナリ検索パスは場所に依存するため、これが必要です。$k$物理的に座ります。 
2. もし$pos(k)$中にはいない$[l, r]$、すぐに戻ります$-1$。 移動を許可する操作がないため、バイナリ検索は検索間隔外ではターゲットに到達できません。$k$範囲内に。 
3. 次から始まる二分探索間隔プロセスをシミュレートします。$[l, r]$ただし、値を検索する代わりに、現在の中点が左側にあるか右側にあるかを追跡します。$pos(k)$。 
4. 各中間点について$m$、 比較する$m$と$pos(k)$。 もし$m = pos(k)$, このステップでは変更は必要ありません。 
5. もし$m < pos(k)$、二分探索は右に進む必要があります。 つまり、$p[m]$未満である必要があります$k$。 現在であれば$p[m] > k$、この位置は「間違っている」ため、選択したセットに含める必要があります。 
6. もし$m > pos(k)$、二分探索は左に進む必要があります。 つまり、$p[m]$より大きくなければなりません$k$。 現在であれば$p[m] < k$、これも選択が必要な「間違った」位置です。 
7. 二分探索パスに沿ったこのような不一致の中点位置をすべて数えます。 選択された各インデックスは正しいサイド制約を満たすように再配置できるため、答えは必要な修正の数です。 

### なぜ効果があるのか

 バイナリ検索パスは決定点の固定シーケンスを形成し、各決定は中間点の値が以下より小さいか大きいかのみに依存します。$k$。 誤った決定があった場合は、その位置を変更する必要があります。それを変更しないままにしておくと、検索が永久に遠ざかってしまうためです。$pos(k)$。 各オーバーライドはそのインデックスの選択に対応しており、選択したインデックスを任意に並べ替えることができるため、常に一貫した値を割り当てることができ、すべての修正された位置が同時に正しく動作するようになります。 修正された各インデックスは制約に関して独立しているため、このプロセスでは新たな競合が発生することはありません。必要なのは、以下の 1 つの不等式を満たすだけです。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        p = list(map(int, input().split()))
        
        pos = [0] * (n + 1)
        for i, v in enumerate(p, 1):
            pos[v] = i
        
        for _ in range(q):
            l, r, k = map(int, input().split())
            pk = pos[k]
            
            if pk < l or pk > r:
                print(-1, end=" ")
                continue
            
            d = 0
            L, R = l, r
            
            while L <= R:
                m = (L + R) // 2
                if m == pk:
                    break
                
                if m < pk:
                    if p[m - 1] > k:
                        d += 1
                    L = m + 1
                else:
                    if p[m - 1] < k:
                        d += 1
                    R = m - 1
            
            print(d, end=" ")
        print()

if __name__ == "__main__":
    solve()
```このソリューションでは、まず位置マップを構築します。$k$クエリごとの定数時間です。 次に、各クエリはバイナリ検索間隔の更新プロセスをシミュレートし、必要な方向と矛盾する中間点位置のカウンターを維持します。$k$。 

重要な実装の詳細は、中間点インデックスと位置の厳密な比較です。$k$、値そのものではありません。 ロジックは、検索がインデックス空間内で左に移動するか右に移動するかによって決まりますが、正確さの条件は、その中間点の値が次の点に関連する不等式を尊重するかどうかによって決まります。$k$。 

選択されたセットにそのインデックスを含めることによってそのような各違反を修正する必要があるため、答えは違反したすべての中間点の決定を累積します。

 ## 特殊なケース

 重要なエッジ ケースは、二分探索の中点が次の位置の周囲で繰り返し振動する場合です。$k$、特に逆順または敵対的な順列で。 このような場合、すべての中間点の決定は必要な方向と矛盾する傾向があり、答えはセグメント サイズではなく二分探索木の深さに比例します。 

もう 1 つの重要なケースは次のような場合です。$k$区間の 1 つの境界付近にあります。 二分探索パスは大きく偏り、少数の中間点のみが訪問されます。 ターゲット インデックスに達するとシミュレーションが停止するため、アルゴリズムは、間隔全体ではなく、訪問した中間点のみを正しくカウントします。 

最後に、セグメント サイズが 1 の場合、その 1 つの位置に含まれるかどうかに応じて、アルゴリズムはすぐに成功するか失敗します。$k$であり、変更はできません。これは、二分探索終了の定義と一致します。
