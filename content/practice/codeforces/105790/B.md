 ## 解決策
 ## 問題の理解

 いくつかの山で持ち帰りゲームを行っています。 

移動は、山を 1 つ選択し、2 の累乗に等しい数の石を取り除くことで構成されます。 選択した山に十分な石が含まれている限り、許可される除去は 1、2、4、8 などです。 ジュリアが最初に動き、動けなかったプレイヤーが負けます。 

ゲームが始まる前に、ジョバナは正確に演技しなければなりません`X`操作。 1 回の操作で、彼女は山を選択し、そのサイズを 2 倍にします。 これらの必須のダブルスの後、両プレーヤーは完璧にプレーし、どちらが勝つかを決定する必要があります。 

入力には、パイルの数、必要な 2 倍化の数、および初期のパイル サイズが含まれます。 出力は勝者の名前です。 

制約は大きく、最大で`10^5`パイルとパイルの最大サイズ`10^9`、 その間`X`と同じ大きさにすることができます`10^9`。 移動や倍増を個別にシミュレートするソリューションは不可能です。 必要なのは`O(N)`または`O(N log N)`解決。 

やっかいな部分は、`X`巨大なものになる可能性があります。 倍増がゲームのグランディ値にどのような影響を与えるかを理解できれば、すべての倍増後の山の実際のサイズは無関係です。 問題全体がゲーム理論の問題になります。 

よくある間違いは、倍増後の正確なパイル サイズを分析することです。 例えば：```
N = 1
X = 1000000000
a = [1]
```10 億回倍増した後の山の値を追跡しようとしても無意味です。 ゲームの結果はグランディの数値のみに依存し、それらは非常に単純なパターンに従います。 

もう 1 つの簡単な間違いは、2 倍になるたびに位置が常に変わると仮定することです。 パイル サイズが 3 で割り切れる場合、2 倍にしても同じグランディ値が維持されます。 例えば：```
N = 1
X = 1
a = [3]
```パイルのグランディ数は 2 倍になった後も変化しないため、Giovana はゲームの状態に影響を与えることなく効率的に移動を行うことができます。 

最後の微妙なケースは、初期 Nim xor がすでにゼロである場合に現れます。 ジョバナはゼロに抑えたいと思っていますが、正確に実行する必要があります。`X`倍増。 それらの倍増を「無駄にする」ことができるかどうかが答えを決定します。 

## アプローチ

 ブルートフォースビューは、すべての杭サイズのグランディ数を明示的に計算することです。 サイズの山の場合`v`、到達可能なすべての状態を考慮します`v - 2^k`、グランディ数を計算し、mex を取得します。 

これは小さな値に対して機能し、最初のいくつかの状態を計算すると次のようになります。 

| パイルサイズ | グランディ |
 | --- | --- |
 | 0 | 0 |
 | 1 | 1 |
 | 2 | 2 |
 | 3 | 0 |
 | 4 | 1 |
 | 5 | 2 |
 | 6 | 0 |

 パターンがすぐに現れます。グランディ数は次のようです。`v mod 3`。 

杭のサイズが上限に達するため、計算による総当りの証明では実際の制約には十分ではありません。`10^9`。 数学的な特徴付けが必要です。 

重要な観察は、2 の累乗はすべて 1 または 2 のモジュロ 3 のいずれかに合同であるということです。```
2^0 ≡ 1 (mod 3)
2^1 ≡ 2 (mod 3)
2^2 ≡ 1 (mod 3)
2^3 ≡ 2 (mod 3)
...
```したがって、残留物の山からの移動`k`モジュロ 3 は常に他の 2 つの残基のいずれかに到達しますが、同じ残基には到達しません。 

山に残留物があると仮定します`k`。 

すべての動きは残留物に到達します`{0,1,2} \ {k}`。 

より小さい位置のグランディ値が正確に 3 を法とした剰余であると仮定すると、到達可能なグランディ数のセットも次のようになります。`{0,1,2} \ {k}`。 そのセットのメキシコは`k`。 

これは次のことを証明します。```
Grundy(v) = v mod 3
```さて、ゲームはニムになります。 すべての剰余の xor によって勝者が決まります。 

残りの課題は、2 倍演算の効果を理解することです。 

パイル残渣の場合:```
0 -> 0
1 -> 2
2 -> 1
```2 倍にすると 1 と 2 が入れ替わりますが、0 は変更されません。 

これにより、問題全体が残基 1 と 2 のカウントに関するパリティ引数に還元されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースグランディ計算 | O(max(ai) log max(ai)) またはそれ以上 | O(最大(ai)) | 遅すぎる |
 | 剰余モジュロ 3 ゲーム分析 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 剰余を計算する`ai mod 3`すべての山ごとに。 
2. Nim xor を計算する`S`すべての残留物の。 
3. 各残基クラスに属する山の数を数えます。`freq[0]`、`freq[1]`、 そして`freq[2]`。 
4. もし`X = 0`、前処理は行われません。 この位置は標準的な Nim 位置です。 

ジュリアがスタートするので、そうすれば彼女が勝ちます`S != 0`。 そうでなければジョバナが勝ちます。 
5. もし`X > 0`そして`S = 0`, 先手プレイヤーが負けているため、ジョバナはすでにポジションを気に入っています。 

彼女は、すべての必須の 2 倍化で xor を変更しないことを望んでいます。 
6. 剰余 0 を持つパイルは、任意の数のダブリングを吸収できます。`0 -> 0`。 

そのような山が存在する場合、Giovana は必要なすべての操作をそこに費やすことができます。 
7. 剰余 0 パイルが存在しない場合、倍加するたびに剰余 1 と剰余 2、またはその逆が交換されます。 

同じパイルに 2 つのダブリングを適用すると、元の残留物が復元されます。 

したがって、xor は次の場合にのみ変更されないままになります。`X`は均等です。 
8. もし`X > 0`そして`S != 0`, ジョバナはポジションをxor zeroに変換したいと考えています。 
9. 1 つの剰余 1 パイルを剰余 2 と交換すると、両方の剰余カウントのパリティが変更されます。 

xor は、両方の場合に正確にゼロになります。`freq[1]`そして`freq[2]`奇数です。 
10. xor ゼロに達したら、それ以上の 2 倍化は破棄する必要があります。 

これは可能です`X`が奇数であるか、余分な演算を 1 つ吸収するために剰余 0 のパイルが存在する場合。 
11. 出力`"Giovana"`ゲーム開始前にジュリアに負けポジションを強制できる場合、そうでない場合は出力`"Julia"`。 

### なぜ効果があるのか

 基本的な不変条件は、すべてのパイルがサイズが次の Nim パイルとまったく同じように動作するということです。`ai mod 3`。 その証明はグランディの反復から得られます。すべての移動で剰余が 3 を法とする 1 または 2 だけ変更され、他のすべての剰余クラスが到達可能になり、現在の剰余クラスは到達不能になります。 したがって、mex は現在の残留物です。 

倍増も実際のパイルサイズには依存しません。 これは剰余 3 にのみ影響し、剰余 0 は固定されたままとなり、残基 1 と 2 が交換されます。ゲームがこれら 3 つの剰余クラスに縮小されると、残基 1 と 2 のカウントのパリティのみが問題になります。 編集条件はまさに、ジョヴァナが必須の倍加を使用してニム xor をゼロにし、それを維持できる状況です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, x = map(int, input().split())
a = list(map(int, input().split()))

freq = [0, 0, 0]
s = 0

for v in a:
    r = v % 3
    freq[r] += 1
    s ^= r

if x == 0:
    win = (s == 0)
else:
    if s == 0:
        win = (freq[0] > 0 or x % 2 == 0)
    else:
        win = (
            freq[1] % 2 == 1 and
            freq[2] % 2 == 1 and
            (x % 2 == 1 or freq[0] > 0)
        )

print("Giovana" if win else "Julia")
```最初のループは、ゲームに必要なすべてのもの、つまり Nim xor と 3 を法とする剰余の頻度を計算します。 

の`x == 0`ブランチは普通のニムです。 xor が 0 の場合は、開始プレイヤーが負けることを意味します。つまり、ジュリアが先に動いたのでジョバナが勝ちます。 

のために`x > 0`、ロジックは剰余変換規則から直接に従います。 条件`freq[0] > 0`剰余 0 パイルは位置を変更せずに奇数の追加ダブリングを費やす唯一の方法であるため、これは特に重要です。 

すべての算術演算は 32 ビット整数に快適に収まりますが、いずれにしても Python は自然にそれより大きな値を処理します。 パイルが明示的に 2 倍になることはありません。これにより、大きな制限に関する問題が回避されます。`X`。

import sys, io

def solve():
    input = sys.stdin.readline

    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    freq = [0, 0, 0]
    s = 0

    for v in a:
        r = v % 3
        freq[r] += 1
        s ^= r

    if x == 0:
        win = (s == 0)
    else:
        if s == 0:
            win = (freq[0] > 0 or x % 2 == 0)
        else:
            win = (
                freq[1] % 2 == 1 and
                freq[2] % 2 == 1 and
                (x % 2 == 1 or freq[0] > 0)
            )

    print("Giovana" if win else "Julia")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return out.getvalue().strip()

# custom cases

assert run("1 0\n3\n") == "Giovana"
assert run("1 0\n1\n") == "Julia"
assert run("2 2\n1 2\n") == "Giovana"
assert run("2 1\n1 2\n") == "Julia"
assert run("3 1000000000\n3 6 9\n") == "Giovana"

 ## 特殊なケース

 次のことを考慮してください。```
1 1
3
```パイル残差は 0 です。初期の xor も 0 です。Giovana はすでにその位置に満足しており、このパイルに必要な倍増を費やすことができます。`0 -> 0`。 xor はゼロのままで、ジュリアは負けている Nim の位置からスタートします。 アルゴリズムが検出するのは、`freq[0] > 0`そして出力`Giovana`。 

次に、次のことを考えてみましょう。```
2 1
1 2
```残留物は、`[1,2]`。 xor はすでにゼロです。 残留0パイルはありません。 必須のダブリング スワップ 1 つ`1 -> 2`または`2 -> 1`、xor をゼロから変更します。 以来`X`が奇妙であるため、ジョバナは効果をキャンセルできません。 アルゴリズムが条件に達しました`freq[0] == 0`そして`X % 2 == 1`、生産`Julia`。 

ついに：```
3 2
1 2 3
```残留物は、`[1,2,0]`。 xor は非ゼロであり、非ゼロの剰余カウントは両方とも奇数です。 Giovana は 1 つの倍加を使用して xor をゼロにし、剰余 0 パイルを使用して残りの必要な演算を吸収できます。 アルゴリズムは次のすべての条件を満たします。`S != 0`分岐と出力`Giovana`。
