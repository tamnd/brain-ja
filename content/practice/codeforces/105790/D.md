 ## 解決策
 ## 問題の理解

 宇宙船が着陸帯に近づいています。 船と滑走路の間には、$N$山。 船は毎秒 1 キロメートルの一定速度で前進し、同時に毎秒 1 キロメートルの一定速度で下降します。 

船が高度から降下を開始した場合$H$、1秒後に最初の山を通過します。$H-1$、2秒後、高度で2番目の山を通過します$H-2$、そして一般に、それは$i$- 番目の標高の山$H-(i+1)$ゼロベースのインデックスを使用する場合。 

それぞれの山には高さがある$h_i$。 船は通過するすべての山の上に厳密に留まらなければなりません。 タスクは最小の初期高度を見つけることです$H$それは衝突がないことを保証します。 

入力は山の数とその高さで構成されます。 出力は単一の整数、つまり最低安全開始高度です。 

山の高さは次のように大きくなります。$10^9$。 これにより、高度値に関するシミュレーションや、考えられるすべての開始高さを試すアプローチが即座に除外されます。 山の数が多すぎると、ソリューションで各山を 1 回だけ処理する必要がある場合があります。$O(N)$スキャン。 

間違いの主な原因は、厳密な不平等です。 船は単に山の頂上に到達するだけではなく、その上に留まらなければなりません。 

考慮する：```
1
10
```初期高度が 11 の場合、山を通過すると船は高度 10 に達します。 厳密には標高が山の高さよりも高いわけではないので、これは衝突です。 正しい答えは次のとおりです。```
12
```もう 1 つの簡単な間違いは、最初の山に到達する前に船が高度を下げることを忘れていることです。 

例：```
3
2 2 1
```高度 4 で、船は高度 3 で最初の山に到達し、高度 2 で 2 番目の山に到達し、2 番目の山に衝突します。 正しい答えは次のとおりです。```
5
```3 番目の落とし穴は、1 から始まるインデックスと 0 から始まるインデックスを矛盾して使用することです。 

例：```
2
1 100
```2 番目の山では、船は高度にあります$H-2$、 ない$H-1$。 正しい状態は、$H > 102$、答えは次のとおりです。```
103
```間違ったインデックス作成スキームでは 102 が生成されます。 

## アプローチ

 最も直接的なアプローチは、候補となる開始高度を 1 つずつ試していくことです。 標高ごとに$H$、飛行をシミュレーションし、すべての山がクリアされているかどうかを確認します。 このシミュレーションは、問題で説明されている条件を正確にチェックしているため、正確です。 

問題は、必要な高度が超過する可能性があることです。$10^9$。 答えが見つかるまでのあらゆる高度をテストするには、何十億ものチェックが必要ですが、これは完全に不可能です。 

もう少し賢いバージョンでは、答えに対して二分探索を実行します。 固定高度の場合$H$で安全性を確認できます。$O(N)$時間。 答えはおおよその範囲内にあるので、$10^9$、二分探索には約 31 回の反復が必要です。$O(N \log 10^9)$。 

重要な観察により、二分探索さえも削除されます。 

山を越えるとき$i$、船の高度は次のようになります。$$H - (i+1)$$衝突を避けるには:$$H - (i+1) > h_i$$並べ替え:$$H > h_i + i + 1$$これはどの山にも当てはまるはずなので、$H$の最大値より厳密に大きくなければなりません$h_i + i + 1$。 

この要件を満たす最小の整数は次のとおりです。$$H = \max(h_i + i + 1) + 1$$これは次のように書くこともできます。$$H = \max(h_i + i + 2)$$アレイを 1 回スキャンするだけで答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(N \cdot A)$|$O(1)$| 遅すぎる |
 | 二分探索 |$O(N \log A)$|$O(1)$| 承認済み |
 | 最適 |$O(N)$|$O(1)$| 承認済み |

 ここ$A$は答えの大きさを表します。 

## アルゴリズムのチュートリアル

 1.読む$N$そして山の高さ。 
2.初期化`answer = 0`。 
3. インデックスのすべての山について`i`:

 コンピューティング`h[i] + i + 2`。 

この値は、まさにその特定の山を安全にクリアするために必要な最低開始高度です。 
4.アップデート`answer`これまでに確認された最大値です。 

すべての山には開始高度の下限が課されます。 最も強い下限が最終的な答えを決定します。 
5. 出力`answer`。 

### なぜ効果があるのか

 山用$i$、船は高度に達します$H-(i+1)$。 安全には次のことが必要です。$$H-(i+1) > h_i$$これは次と同等です。$$H \ge h_i+i+2$$なぜなら$H$は整数です。 

すべての山はそのような下限を 1 つ生成します。 少なくとも 1 つの山では、最大境界よりも低い高度は失敗します。 最大限界自体は、すべての不等式を同時に満たします。 それは十分であり、必要であるため、最小限の有効な答えです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
h = list(map(int, input().split()))

ans = 0

for i in range(n):
    ans = max(ans, h[i] + i + 2)

print(ans)
```この実装は数学的導出を直接反映しています。 

表現`h[i] + i + 2`は、厳密な不等式を整数の下限に変換することで得られます。 使用する`+1`の代わりに`+2`船は厳密に山の上に留まらなければならないため、これは不正確です。 

ループは各山によって課される要件を計算し、最大のものだけを保持します。 入力配列と実行最大値を超える追加のストレージは必要ありません。 

Python の整数は、次の値よりも大きい値を自動的に処理します。$10^9$なので、オーバーフローは心配ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(N)$| 山の中を 1 回スキャン |
 | スペース |$O(1)$| 現在の最大値のみが保存されます。 

このアルゴリズムは、山ごとに一定量の作業を実行し、要素を再検討することはありません。 これは、次の場合でも、典型的な競技プログラミングの制限に快適に適合します。$N$とても大きいです。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(input())
    h = list(map(int, input().split()))

    ans = 0
    for i in range(n):
        ans = max(ans, h[i] + i + 2)

    return str(ans)

# provided samples

 ## 特殊なケース

 次のことを考慮してください。```
1
10
```アルゴリズムは以下を計算します。$$10 + 0 + 2 = 12$$そして出力12。 

手動で確認すると、高度 11 は高度 10 の山に到達しますが、厳密にはそれより上ではありません。 厳密な不等式は正しく処理されます。 

考慮する：```
3
2 2 1
```計算された値は次のとおりです。$$4,\ 5,\ 5$$したがって、答えは 5 です。 

船は高度 4 で高度 2 の 2 番目の山を通過し、衝突します。 最大要件により、最低安全高度が正確に特定されます。 

考慮する：```
2
1 100
```アルゴリズムは以下を計算します。$$1+0+2=3$$そして$$100+1+2=103$$答えは103です。 

2 つ目の山には 1 秒ではなく 2 秒後に到達します。 式には、インデックス項を通じて正しい高度損失が自動的に組み込まれます。`i + 1`、オフバイワンの間違いを避けます。
