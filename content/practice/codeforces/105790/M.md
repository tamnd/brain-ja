 ## 解決策
 ## 問題の理解

 マルチバースはルートユニバースとルートのある有向ツリーを形成します`1`。 すべてのエッジは、星が多い宇宙から星が少ない宇宙へと向いています。 スターの数はルートからリーフのすべてのパスに沿って厳密に減少するため、特定のノードのセットに到達できるすべてのユニバースの中で、スターの数が最も少ないユニバースは、単純にそれらのノードの最も深い共通の祖先になります。 ツリーの用語では、それは最下位共通祖先 (LCA) です。 

クエリごとに、個別のユニバースの順序付きリストが与えられます。$$a_1,a_2,\dots,a_K$$そして計算しなければなりません$$\sum_{1 \le i \le j \le K} f(i,j)$$どこ$f(i,j)$は、連続セグメント内のすべてのユニバースに到達できる最も深いノードのユニバース識別子です。$a_i,\dots,a_j$。 そのノードはセグメント内のすべてのノードの LCA であるため、タスクは次のようになります。$$\sum_{1 \le i \le j \le K}
\text{LCA}(a_i,a_{i+1},\dots,a_j)$$追加される値としてユニバース番号自体を使用します。 

ツリーには以下が含まれます$10^5$ノードは最大で$10^5$すべてのクエリの長​​さの合計は最大で$3 \cdot 10^5$。 すべてのサブ配列を個別に検査するソリューションには、$O(K^2)$クエリごとの作業量は、制限内に収まる範囲をはるかに超えています。 

微妙な点は、ノード ラベルが深さや星の数ではないことです。 答えは、LCA 操作によって返されたユニバース識別子を追加します。 

次のクエリを考えてみましょう。```
2 4 5
```サンプル ツリーでは、4 と 5 は両方とも 3 の子です。 

間隔は次のとおりです。```
[4] -> 4
[5] -> 5
[4,5] -> 3
```答えは次のとおりです。```
4 + 5 + 3 = 12
```識別子を合計する代わりに LCA をカウントする不注意な実装では、誤った結果が生成されます。 

もう 1 つの特殊なケースは、長さが 1 のクエリです。```
1 7
```唯一の間隔は、`[7]`、単一ノードの LCA はノード自体です。 答えは次のとおりです。`7`、その親やルートではありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 間隔ごとに$[i,j]$、その内部のすべてのノードの LCA を計算し、結果を答えに追加します。 

これを行う 1 つの方法は、各開始位置からの間隔を延長することです。 現在の LCA を維持しながら正しいエンドポイントを移動すると、すべての間隔を次のように処理できます。$O(\log N)$バイナリリフティングを使用します。 全体の複雑さは次のようになります。$O(K^2 \log N)$。 と$K$と同じくらい大きい$10^5$、これはまったく不可能です。 

重要な観察は、LCA が非常に急速に崩壊するということです。 

位置を固定する$r$。 で終わるすべてのサブ配列を見てください。$r$:```
[a_r]
[a_{r-1}, a_r]
[a_{r-2}, a_r]
...
```間隔を左に拡張すると、LCA はツリー内で上方向にしか移動できなくなります。 LCA が変更されると、それは前の LCA の厳密な祖先になります。 

根から葉までの道に沿って存在するのは、$O(\log N)$LCA マージを繰り返した後に現れる可能性のある個別の祖先。 これは、古典的な「部分配列の個別の gcd」問題で使用されるのと同じプロパティです。 固定位置で終わるサブアレイの個別の LCA のセットは小さいままです。 

位置で終わるサブ配列のすべての個別の LCA がすでにわかっていると仮定します。$r-1$。 新しいノードの場合$a_r$、すべての古い LCA 値$v$は次のようになります:$$\text{LCA}(v,a_r)$$拡張サブ配列の場合。 また、LCA が次のような新しい 1 要素の部分配列も追加します。$a_r$。 

結果として得られる値の多くは等しいため、等しい LCA をマージし、そのカウントのみを保持します。 個別の LCA の数は少ないままなので、効率的なソリューションが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(K^2 \log N)$|$O(1)$| 遅すぎる |
 | 最適 |$O(K \log^2 N)$クエリごと |$O(\log N)$クエリごと | 承認済み |

 すべてのクエリの合計複雑さは次のとおりです。$O((\sum K)\log^2 N)$、これは簡単に適合します。$\sum K \le 3 \cdot 10^5$。 

## アルゴリズムのチュートリアル

 ### 前処理

 1. ノードでツリーをルート化します`1`。 
2. DFS を実行して深さとバイナリリフティングテーブルを計算します。`up[v][j]`、 どこ`up[v][j]`です$2^j$- 番目の祖先`v`。 
3. を実装します。`lca(u,v)`バイナリリフティングを使用した関数。 

### 1 つのクエリを処理しています

 1. リストを管理する`cur`ペアを含む`(lca_value, count)`。 

意味は、前の位置で終わるすべてのサブ配列の中で、正確に`count`そのうちの LCA は次のとおりです`lca_value`。 
2. 次のノードの場合`x`、新しいリストを開始します`nxt`。 
3.挿入`(x,1)`の中へ`nxt`。 

これは 1 要素の部分配列を表します`[x]`。 
4. ペアごとに`(v,c)`で`cur`、計算する`w = lca(v,x)`。 

で表されるすべての部分配列`(v,c)`で終わる長い部分配列になります`x`、その新しい LCA は`w`。 
5. 最後のペアがすでに保存されている場合は、`nxt`LCAあり`w`、 追加`c`その数に。 それ以外の場合は追加`(w,c)`。 

連続する等しい LCA はマージされ、個別の値のみが残ります。 
6. 交換する`cur`と`nxt`。 
7.追加$$\sum (\text{lca\_value} \times \text{count})$$すべてのペアにわたって`cur`クエリの回答に。 
8. クエリ シーケンスのすべてのノードに対してこの手順を繰り返します。 

### なぜ効果があるのか

 加工後の位置`r`、リスト`cur`で終わるすべてのサブ配列を表します`r`、LCAごとにグループ化されています。 で終わるすべてのサブ配列`r`は 1 要素間隔のいずれかです`[a_r]`またはで終わるサブ配列の拡張子`r-1`。 

長期間の場合、新しい LCA は正確に次のようになります。$$\text{LCA}(\text{old LCA}, a_r)$$ノードのセットの LCA は、ペアごとの LCA 操作を繰り返すことで段階的に蓄積できるためです。 

したがって、次で終わるすべてのサブ配列は、`r`ちょうど 1 つのグループに貢献します`cur`であり、すべてのグループは実際の部分配列に対応します。 合計する`lca_value × count`で終了するすべての間隔の合計寄与度を示します。`r`。 すべての位置を合計すると、すべての間隔が 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, q = map(int, input().split())

    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    LOG = (n + 1).bit_length()

    depth = [0] * (n + 1)
    up = [[0] * (n + 1) for _ in range(LOG)]

    stack = [1]
    parent = [0] * (n + 1)
    parent[1] = 1

    order = [1]
    while stack:
        v = stack.pop()
        for to in g[v]:
            if to == parent[v]:
                continue
            parent[to] = v
            depth[to] = depth[v] + 1
            stack.append(to)
            order.append(to)

    for v in range(1, n + 1):
        up[0][v] = parent[v]

    for j in range(1, LOG):
        prev = up[j - 1]
        cur = up[j]
        for v in range(1, n + 1):
            cur[v] = prev[prev[v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a

        diff = depth[a] - depth[b]
        bit = 0
        while diff:
            if diff & 1:
                a = up[bit][a]
            diff >>= 1
            bit += 1

        if a == b:
            return a

        for j in range(LOG - 1, -1, -1):
            if up[j][a] != up[j][b]:
                a = up[j][a]
                b = up[j][b]

        return up[0][a]

    answers = []

    for _ in range(q):
        arr = list(map(int, input().split()))
        k = arr[0]
        nodes = arr[1:]

        cur = []
        ans = 0

        for x in nodes:
            nxt = [(x, 1)]

            for v, cnt in cur:
                w = lca(v, x)

                if nxt[-1][0] == w:
                    nxt[-1] = (w, nxt[-1][1] + cnt)
                else:
                    nxt.append((w, cnt))

            cur = nxt

            for v, cnt in cur:
                ans += v * cnt

        answers.append(str(ans))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    main()
```前処理では、ツリー全体に対してバイナリ リフティング テーブルを 1 回構築します。 すべての LCA クエリが実行されます。$O(\log N)$。 

クエリ処理では、現在の位置で終わるサブ配列の個別の LCA のみが保持されます。 新しいノードによって以前のすべてのサブ配列を拡張すると、多くの場合、いくつかの LCA が同じ祖先に集約されます。 隣接する等しい結果をマージすることが重要です。そうしないと、リストが線形サイズに増大する可能性があります。 

答えには、LCA 操作によって返されたユニバース識別子が使用されます。 あり得るので、$O(K^2)$間隔の場合、最終合計は 64 ビット整数で保存する必要があります。 Python の整数はこれを自動的に処理します。

 ## 特殊なケース

 ユニバースを 1 つだけ含むクエリ:```
2 1
1 2
1 2
```唯一の間隔は、`[2]`。 アルゴリズムが作成する`cur = [(2,1)]`、追加します`2 * 1`、そして戻ります`2`。 別のノードによる LCA 計算は必要ありません。 

チェーン:```
1 - 2 - 3 - 4
query: 2 3 4
```間隔 LCA は次のとおりです。```
[2] = 2
[3] = 3
[4] = 4
[2,3] = 2
[3,4] = 3
[2,3,4] = 2
```答えは次のとおりです。```
2 + 3 + 4 + 2 + 3 + 2 = 16
```LCA は必要な場合にのみ上方に移動するため、グループ化された LCA 表現はこれを自然に処理します。 

に根ざしたスター`1`:```
1 connected to 2,3,4,5
query: 2 3 4 5
```少なくとも 2 つの長さのすべての間隔に LCA があります`1`。 処理中に、多くの拡張子が同じ値に折りたたまれ、マージ ステップでそれらが 1 つの値に結合されます。`(1,count)`ペア。 これはまさに、保存される状態の数を少なく保つ状況です。
