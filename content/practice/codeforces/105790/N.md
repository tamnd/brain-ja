 ## 解決策
 ## 問題の理解

 私たちは、$N \times M$グリッド。 シールドがその位置に構築されるたびに$(x,y)$、列内のすべてのセルを保護します$x$列内のすべてのセル$y$。 少なくとも 1 つのシールドで保護されている場合、セルは使用可能です。 

操作には 2 種類あります。 

タイプ 1 の操作では、新しいシールドが構築されます。 

タイプ 2 の操作は、アルメイディングが次から始まるかどうかを尋ねます。$(x_i,y_i)$到達できる$(x_f,y_f)$保護されたセルのみを使用し、4 つの基本的な方向に一度に 1 ステップずつ移動します。 

グリッド自体には最大で次のものを含めることができます$10^6$セルの数は同じですが、クエリの数は$2 \cdot 10^5$。 すべての保護されたセルの状態を維持しようとしたり、クエリごとにグラフ検索を実行しようとしたりするソリューションは、すぐに遅すぎます。 一定のサイズのグリッド上の単一の BFS であっても$10^6$すでにコストがかかるため、それを繰り返し行うことは不可能です。 必要なのは$O(1)$または$O(\log N)$クエリごとに回答します。 

主な危険は、シールドによって作成される接続構造を誤解することです。 

次の入力を考えてみましょう。```
3 3 2
1 2 2
2 2 1 2 3
```シールドは行 2 と列 2 をアクティブにします。両方のセル$(2,1)$そして$(2,3)$は保護された行にあるため、答えは次のようになります。```
SIM
```エンドポイントが同じ保護された行または列にあるかどうかをチェックするだけの単純な実装は、より一般的なケースでは失敗します。 

もう 1 つの興味深いケースは次のとおりです。```
3 3 2
1 2 2
2 1 2 3 2
```開始セルと終了セルは両方とも列 2 に属しているため、保護されています。正解は次のとおりです。```
SIM
```セルが異なる行にある場合でも、列全体が保護されます。 

ついに：```
3 3 2
1 2 2
2 1 1 3 3
```どちらのエンドポイントも保護されていません。 正しい答えは次のとおりです。```
NAO
```パスは、保護されていないセルで開始または終了することさえできません。 

## アプローチ

 ブルート フォース ソリューションでは、すべての保護されたセルを明示的にマークし、タイプ 2 クエリごとに 2 つのエンドポイント間で BFS または DFS を実行します。 これは保護領域内の動きを直接シミュレートするため、これは正しいです。 

問題は規模だ。 1 つのシールドが行全体と列全体に影響を与える可能性があります。 まで$10^6$細胞と$2 \cdot 10^5$クエリを実行し、グリッドを繰り返し探索することは制限をはるかに超えています。 

重要な観察は、シールドが実際に何を作成するかを理解することから得られます。 

シールドが構築されると、$(x,y)$、 行$x$完全に保護され、カラム$y$完全に保護されるようになります。 彼らの交差セル$(x,y)$行と列を接続します。 

すべてのシールドは常に 1 つの行と 1 つの列の両方をアクティブにするため、すべての保護された構造には少なくとも 1 つの行と列の交差が含まれます。 保護されたセルは、アクティブ化された行またはアクティブ化された列のいずれかに属します。 このようなセルから交差点に移動し、そこからシールドによってアクティブ化された他の保護された行または列に移動できます。 その結果、すべての保護されたセルは単一の接続コンポーネントに属します。 

それは問題を完全に変えます。 

タイプ 2 クエリでは、接続性を確認する必要はまったくありません。 両方のエンドポイントが保護されていることを確認するだけで済みます。 両方が保護されている場合、それらは自動的に一意の保護されたコンポーネントに属し、相互にアクセス可能になります。 どちらかのエンドポイントが保護されていない場合、答えは不可能です。 

2 つのブール配列を維持できます。 

1 つのアレイは、どの行がシールドの中心としてこれまでに出現したかを記録します。 

他の記録には、どの柱がシールドセンターとして出現したかが記録されています。 

細胞$(r,c)$行が正確に保護される$r$アクティブまたは列です$c$活動中です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース BFS | O(Q・N・M) 最悪の場合 | O(N・M) | 遅すぎる |
 | 最適な行/列追跡 | O(Q) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ブール配列を作成する`row`サイズの`N`そしてブール配列`col`サイズの`M`。 
2. タイプ 1 クエリの場合`(x, y)`、 マーク`row[x] = True`そして`col[y] = True`。 
3. タイプ 2 クエリの場合、開始セルが保護されているかどうかを判断します。 

細胞`(r, c)`の場合は保護されます`row[r]`アクティブであるか、`col[c]`活動中です。 
4. 宛先セルが同じルールを使用して保護されているかどうかを確認します。 
5. 両方のセルが保護されている場合は、印刷します。`"SIM"`。 

すべての保護セルは、同じ接続された保護領域に属します。 
6. それ以外の場合は印刷します`"NAO"`。 

### なぜ効果があるのか

 すべてのシールドは行全体と列全体をアクティブにします。 これら 2 つの構造はシールドの中心で交差し、それらの間に接続が作成されます。 

保護されたセルは、アクティブな行またはアクティブな列のいずれかにあります。 そのセルから、その行または列に沿ってシールドの交差点まで移動できます。 交差を通じて、すべての保護された行と保護された列は、1 つの接続された構造の一部になります。 したがって、すべての保護されたセルは相互に到達可能です。 

クエリが失敗する唯一の理由は、開始セルまたは宛先セルが保護されていないことです。 それはまさにアルゴリズムがチェックするものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, q = map(int, input().split())

rows = [False] * n
cols = [False] * m

ans = []

for _ in range(q):
    data = list(map(int, input().split()))

    if data[0] == 1:
        _, x, y = data
        rows[x - 1] = True
        cols[y - 1] = True
    else:
        _, xi, yi, xf, yf = data

        start_ok = rows[xi - 1] or cols[yi - 1]
        finish_ok = rows[xf - 1] or cols[yf - 1]

        ans.append("SIM" if start_ok and finish_ok else "NAO")

sys.stdout.write("\n".join(ans))
```2 つの配列は問題の全体的な状態です。 

シールドが作成されるとき、その行または列内のすべてのセルにマークが付けられるわけではありません。 それを行うと費用がかかりすぎます。 代わりに、行と列がアクティブであることだけを覚えておきます。 

クエリセルの場合`(r,c)`、保護条件は正確に次のとおりです。```
rows[r] or cols[c]
```これは保護の定義と直接一致します。 

この実装では内部で 0 から始まるインデックスが使用されるため、入力から読み取られたすべての座標は配列にアクセスする前に 1 ずつ減らされます。 

接続性はシールドの形状によってすでに暗示されているため、グラフ構築、BFS、DFS、または共用体検索構造は必要ありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(Q) | 各クエリは少数の配列アクセスのみを実行します。 
| スペース | O(N + M) | 行に 1 つと列に 1 つのブール配列 |

 以来$Q \le 2 \cdot 10^5$そして$N \cdot M \le 10^6$、クエリの線形処理は簡単に十分に高速です。 2 つの配列を超えるグリッド自体のサイズに依存する操作はありません。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, m, q = map(int, input().split())
    rows = [False] * n
    cols = [False] * m

    out = []

    for _ in range(q):
        a = list(map(int, input().split()))

        if a[0] == 1:
            rows[a[1] - 1] = True
            cols[a[2] - 1] = True
        else:
            s = rows[a[1] - 1] or cols[a[2] - 1]
            t = rows[a[3] - 1] or cols[a[4] - 1]
            out.append("SIM" if s and t else "NAO")

    return "\n".join(out)

# sample 1
assert run(
"""3 3 3
1 2 2
2 2 1 2 3
2 1 1 3 3
"""
) == "SIM\nNAO"

# sample 2
assert run(
"""3 3 4
2 1 1 3 3
1 1 1
2 1 1 3 3
2 3 1 1 3
"""
) == "NAO\nNAO\nSIM"

# minimum grid, no shield
assert run(
"""1 1 1
2 1 1 1 1
"""
) == "NAO"

# single shield, same cell

"""
) == "SIM"

# protected through row
assert run(

"""

# one endpoint protected, one not

 ## 特殊なケース

 次のことを考慮してください。```
1 1 1
2 1 1 1 1
```シールドは構築されていません。 行は非アクティブで、列も非アクティブです。 アルゴリズムは以下を評価します。```
rows[1] OR cols[1] = false
```両方のエンドポイントに対して、以下が生成されます。```
NAO
```唯一のセルが保護されていないため、これは正しいです。 

次に、次のことを考えてみましょう。```
3 3 2
1 2 2
2 1 2 3 2
```シールドを構築した後、行 2 と列 2 がアクティブになります。 どちらのエンドポイントも列 2 にあるため、両方が保護されます。 アルゴリズムは次を返します。```
SIM
```行が異なっていても、アクティブな列に沿った移動は可能です。 

ついに：```
4 4 2
1 2 2
2 2 1 4 4
```開始セル`(2,1)`行 2 がアクティブであるため、保護されています。 目的地`(4,4)`行 4 も列 4 もアクティブではないため、保護されません。 アルゴリズムはこれを即座に検出し、次のように出力します。```
NAO
```保護されていないセルでパスが終了することはできないため、答えは正しいです。
