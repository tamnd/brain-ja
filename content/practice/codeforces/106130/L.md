 ## 解決策
 ## 問題の理解

 コインの列を表すバイナリ文字列が与えられます。 各位置は 0 または 1 で、目標は文字列全体をすべて 1 に変換することです。 

唯一許可される操作は、2 つの隣接する位置を選択し、両方のコインを同時に投げることです。 反転とは、0 を 1 に、1 を 0 に変えることを意味します。したがって、各移動は、正確に 2 つの連続するビットを切り替えます。 

質問は純粋に到達可能性に関するものです。初期構成から始めて、このような隣接するダブルフリップ操作を任意の数だけ使用して、すべて 1 の構成に到達できるでしょうか?

 投入サイズは非常に小さく、最大でも 20 コインです。 これは、必要に応じて指数関数的な状態探索が実行可能であることを即座に示唆していますが、同時に力任せに頼るのではなく、きれいな構造的不変量を導出できるはずであることも示唆しています。 

微妙な点は、操作の効果が重複していることです。 位置 i での反転は i と i+1 に影響を与えるため、移動はローカルで相互作用しますが、変更は配列全体に伝播する可能性があります。 これにより、多くの場合、パリティベースの制約が発生します。 

呼び出す価値のあるエッジケースは、非常に小さな文字列やすでに解決された構成から発生します。 

たとえば、入力のように文字列がすでにすべて 1 である場合、`1111`、正解は自明です`Yes`。 正しいメソッドは、不必要な変換を試みることなく、これを明示的に受け入れる必要があります。 

別の例は`10`。 位置 1 と 2 に対する 1 回の操作で両方のビットが反転され、反転します。`10`の中へ`01`、その後、それ以上の操作を行っても修正できません。 したがって、答えは次のとおりです`No`。 単純に貪欲なアプローチでは、ローカル修正が常に可能であると誤って想定される可能性があります。 

もう少し長い例は次のとおりです`001`、ローカルな推論が誤解を招く可能性のある方法で操作が相互作用する可能性があります。 正しいソリューションは、ローカルな改善に依存するのではなく、グローバルな不変条件を捉える必要があります。 

## アプローチ

 この問題を強引に考える方法は、各バイナリ文字列をグラフ内の状態として扱うことです。 各状態は、任意のインデックス i に有効な操作を適用し、位置 i と i+1 を反転することによって他の状態に接続されます。 n ビットがあるため、各状態からの可能な手は n-1 通りあります。 

状態の総数は最大でも 2^20、つまり約 100 万です。 この状態空間上の BFS または DFS は、すべてが 1 の状態に到達可能かどうかを常に検出します。 各遷移では文字列の構築またはコピーに O(n) 時間がかかるため、最悪の場合の複雑さの合計は O(n · 2^n) 程度になります。これは境界線ですが、厳しい制限の下ではまだ許容できる可能性があります。 

ただし、これは構造を無視します。 各操作は正確に 2 ビットを反転します。これは、ゼロの数のパリティを維持することを意味します。 さらに注意深く見てみると、ローカル構成に応じて、すべての移動でゼロの合計数が 0、2、または -2 ずつ変化しますが、さらに重要なのは、GF(2) 上の線形システムとして適切に見た場合に、2 を法とするビットの合計のパリティが保持されることです。 

この問題は当然ながら GF(2) 上で線形です。 各演算は、位置 i および i+1 にあるベクトルを加算することに対応します。 これらの基底演算を使用して、初期ベクトルからターゲット ベクトル (すべて 1) を取得できるかどうかを尋ねます。 これは、チェーン構造上の線形方程式系になります。 

重要な簡素化は、変数を左から右に貪欲に削除することで実現します。 各操作は隣接する位置にのみ影響するため、問題を配列に沿った一貫性の強制として扱うことができます。位置 i を固定する方法を決定すると、位置 i+1 が制約されます。 

これは単純な決定論的シミュレーションにつながります。つまり、最初のビットが 1 になるように貪欲に強制し、必要な反転を順方向に伝播します。 各移動は隣接するペアにのみ影響するため、以前の決定を考慮して各位置を修正する方法は 1 つだけです。 

ブルートフォースはすべての状態を探索しますが、その構造によりシステムは単一パス チェックに崩壊します。

 | 貪欲な伝播 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、強制的な決定をシミュレートします。 

1. 最初の位置から開始します。 すでに 1 の場合は何もしません。 0 の場合、それを修正する唯一の方法は、位置 0 と 1 に両方を反転する操作を適用することです。 
2. 位置 i で反転を適用すると、s[i] と s[i+1] の両方が切り替わります。 このアクションは、文字列をその場で変更するか、操作のパリティを追跡することによって暗黙的に記録されます。 
3. 位置 i+1 に移動し、同じロジックを繰り返します。 各ステップで、場合によっては右隣の位置と合わせて反転することにより、現在の位置が 1 になるようにします。 
4. このプロセスを位置 n-2 まで続けます。 その時点で、それ以前のすべての位置は 1 であることが保証されます。 
5. 最後に最後の位置を確認します。 1 の場合、変換は可能です。 そうでなければ不可能です。 

重要な設計上の選択は、以前の位置を決して再考しないことです。 (i, i+1) を伴う演算を使用して位置 i が固定されると、それ以降の演算では再び i に触れることはなくなるため、その値は安定します。 

### なぜ効果があるのか

 このアルゴリズムでは、左から右への不変条件が適用されます。つまり、インデックス i の処理後、すべての位置 ≤ i は 1 に等しくなります。位置 i を固定する各操作は、i と i+1 にのみ影響し、以降のすべての操作で i を再度変更することはありません。これは、後のすべての操作には厳密に i より大きいインデックスが含まれるためです。

これにより、制約の強制的な伝播が作成されます。 どのステップでも、位置 i で 0 を修正する操作を使用できない場合 (たとえば、パートナーが存在しない最後の位置)、構成は不可能です。 それ以外の場合、各操作の効果はサイズ 2 のスライディング ウィンドウに限定されるため、すべてのローカル修正はグローバルに一貫しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = list(input().strip())
    n = len(s)

    for i in range(n - 1):
        if s[i] == '0':
            # flip i and i+1
            s[i] = '1'
            s[i + 1] = '1' if s[i + 1] == '0' else '0'

    print("Yes" if s[-1] == '1' else "No")

if __name__ == "__main__":
    solve()
```この実装は、貪欲な伝播のアイデアを直接エンコードします。 文字列は可変リストに変換されるため、一定時間内に反転を適用できます。 右隣の位置のみを直接固定できるため、ループは n−2 までしか実行されません。 

重要な点は、最後の位置を直接修正しようとしないことです。 代わりに、以前の強制操作によって暗黙的に決定されます。

これらのトレースは、初期の強制決定がどのように伝播するか、および最終的な位置が一貫性チェックとしてどのように機能するかを示しています。

 ## 特殊なケース

 単一文字の場合`1`操作は必要ないため、自明に動作します。 アルゴリズムはループを完全にスキップし、直接出力します。`Yes`。 

ケース`0`隣接性が重要である理由を示します。 有効な操作がないため、最後の文字のチェックはすぐに失敗します。`0`。 

のために`10`、最初の位置は`1`したがって、インデックス 0 では反転はトリガーされません。2 番目の位置は残ります。`0`、パートナーなしでは修正できないため、アルゴリズムは正しく出力します。`No`。 

のために`001`、最初のインデックスは反転を引き起こし、`110`。 この後、それ以上の修正は不可能となり、最終状態は最後の位置チェックに失敗します。 これは、早期に貪欲な修正を行っても、最終的には避けられない不整合を引き起こす可能性があることを示しており、まさにそれがアルゴリズムによって検出されます。
