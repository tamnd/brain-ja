 ## 解決策
 ## 問題の理解

 単一の確率値が与えられます`p`、必要な結果を得るための 1 回の独立した試行の成功率を表します。 学生はちょうど 3 回の独立した試行を行います。 各試行は確率的に成功するか、`p`または確率で失敗する`1 - p`。 少なくとも 1 回成功すると、全体的な成功がすでに保証されているため、プロセスは関連性を失います。 

タスクは、3 つの試行のうち少なくとも 1 つが成功する確率を計算することです。 

入力は次の範囲の浮動小数点数です。`0`そして`1`。 出力は、3 回の試行以内の成功確率を表す単一の浮動小数点数です。許容誤差は次のとおりです。`1e-4`相対誤差または絶対誤差のいずれかで。 

この記述は短いですが、重要なモデリングの選択は、これが古典的な「独立したベルヌーイ試行を繰り返して少なくとも 1 回成功する」問題であることを認識することです。 

大きな制約はないため、パフォーマンスは関係ありませんが、浮動小数点演算を扱っているため、数値の安定性が多少重要になります。 微妙なエッジケースのみが境界に表示されます`p = 0`そして`p = 1`。 

もし`p = 0`、すべての試行は失敗するため、答えは次のようになります。`0`。 次のような単純な計算`1 - (1 - p)^3`ここでも動作しますが、浮動小数点精度によって負のゼロや小さなノイズが発生しない場合に限ります。 

もし`p = 1`、すべての試行は成功するため、答えは正確に`1`。 

よくある間違いは、シーケンスを手動で列挙しようとして、複数の成功が発生した場合に誤って結果を二重にカウントしてしまうことです。 これは、慎重に構造化されていない限り、誤った組み合わせ推論につながります。 

## アプローチ

 強引な解釈では、3 つの独立した試験の考えられるすべての結果を明示的に列挙することになります。 各トライアルには成功または失敗の 2 つの状態があるため、`2^3 = 8`合計の結果パターン。 各パターンの確率を計算し、少なくとも 1 つの成功を含むパターンを合計することができます。 

このアプローチは、独立した事象に対する確率の定義に直接従うため、正しいです。 ただし、これは不必要に冗長であり、試行回数が増えると拡張性が低くなります。`n`試験には必要になるだろう`2^n`組み合わせ。 

重要な観察は、「少なくとも 1 つの成功」を数えるのは、補数を使用することで簡単になるということです。 すべての有利なケースを合計する代わりに、すべての試行が失敗する確率を計算し、`1`。 

1 回の試行が失敗する確率は、`(1 - p)`。 試行は独立しているため、3 つすべてが失敗する確率は次のようになります。`(1 - p)^3`。 したがって、望ましい確率は次のようになります。`1 - (1 - p)^3`これにより、結果の列挙の問題が 1 つの算術式に軽減されます。

 ## アルゴリズムのチュートリアル

 1.確率を読む`p`入力から。 この値は、試行ごとの成功確率を表します。 
2. 故障確率を計算する`q = 1 - p`。 これにより、問題は「良い出来事」ではなく、単一の「悪い出来事」についての推論に変換されます。 
3. 3 回の試行がすべて失敗する確率を次のように計算します。`q^3`。 独立性により、試行間での乗算が可能になります。 
4. この値をから引きます。`1`少なくとも 1 回の試行が成功する確率を取得します。 
5. 結果を浮動小数点数として出力します。 

実際の計算は一定数の算術演算のみであるため、実装は簡単です。 

### なぜ効果があるのか

 「少なくとも 1 つの成功」と「すべての失敗」というイベントは相補的かつ相互に排他的であり、確率空間全体をカバーします。 独立性により、同一の確率の積として「全失敗」イベントを正確に計算できるため、補数により浮動小数点演算を超える近似を行わずに正確なターゲットが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

p = float(input().strip())

q = 1.0 - p
ans = 1.0 - q * q * q

print(ans)
```コードは確率を浮動小数点として読み取り、補数の失敗確率を計算し、乗算を繰り返すことでその確率を 3 乗します。 これにより、呼び出しによる潜在的なオーバーヘッドが回避されます。`pow`そして計算を明示的に保ちます。 

からの引き算`1.0`浮動小数点誤差の蓄積を最小限に抑えるために最後に実行されます。 この式には少数の演算しか含まれていないため、精度は必要な許容範囲内に十分収まります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    p = float(input().strip())
    q = 1.0 - p
    ans = 1.0 - q**3
    return str(ans)

# provided sample
assert abs(float(run("0.5")) - 0.875) < 1e-9

# edge: always fail
assert abs(float(run("0")) - 0.0) < 1e-9

# edge: always succeed
assert abs(float(run("1")) - 1.0) < 1e-9

# small probability
assert abs(float(run("0.1")) - (1 - 0.9**3)) < 1e-9

# high probability
assert abs(float(run("0.9")) - (1 - 0.1**3)) < 1e-9
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 0.5 | 0.875 | 標準ケース |
 | 0 | 0 | すべての失敗 |
 | 1 | 1 | 保証された成功 |
 | 0.1 | 0.271 | 低確率体制 |

 ## 特殊なケース

 のために`p = 0`、私たちは得ます`q = 1`、 それで`q^3 = 1`そして結果は`0`。 アルゴリズムは、すべての試行が失敗することを正確に捕捉するため、成功する可能性はありません。 

のために`p = 1`、私たちは得ます`q = 0`、 それで`q^3 = 0`そして結果は`1`。 これは、最初の試行で保証された成功を反映しており、その後の試行は無関係です。 

に近い極端な浮動小数点入力の場合`0`または`1`の場合、式には 1 つの減算と 2 つの乗算のみが含まれ、必要な誤差許容範囲内に収まるため、減算は安定したままになります。
