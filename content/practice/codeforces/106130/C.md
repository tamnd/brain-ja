 ## 解決策
 ## 問題の理解

 サイズの隠れた順列と対話しています$n$。 順列はクエリの前に固定され、各クエリでは任意の長さを送信できます。$n$配列。 システムは、送信された配列と非表示の順列の間で正確に一致する位置の数を返します。 

タスクは、最大でも次の値を使用して順列全体を再構築することです。$n^2$このようなクエリはテスト ケースごとに作成されます。 

重要な制限は、$n \le 100$、との合計$n^2$すべてのテスト ケースの制限は 10000 です。これにより、二次クエリ戦略が受け入れられることがすぐにわかりますが、各クエリ自体は 1 つのクエリ自体だけであるため、3 次クエリやクエリごとの大量の計算を必要とするものでも問題ありません。$O(n)$。 実際の制約はクエリごとのコストではなく、クエリの数です。 

各クエリを位置に関する情報を与えるものとして扱うことから、素朴な誤解が生じることがよくあります。 実際には、各応答はグローバル スコアにすぎないため、情報を分離するクエリを設計しない限り、直接再構築することはできません。 

単一のランダムまたは貪欲な再構築戦略が機能すると仮定すると、微妙な失敗例が現れます。 たとえば、ローカル クエリに基づいて位置ごとに独立して値を割り当てようとすると、すぐにあいまいさに遭遇します。 

もし$n = 3$そして隠れた順列は$[2,3,1]$、ポジションごとに候補者を個別にテストするような単純な試みでは、フィードバックによってエラーが特定されないため、矛盾する割り当てが簡単に生成される可能性があります。 

中心的な課題は、制御された方法で「代替案を比較」できるクエリを設計して、それぞれの立場を決定論的に解決できるようにすることです。 

## アプローチ

 強引なアイデアは、各位置のすべての可能性を試して順列を完全に再構成することです。 ポジションについて$i$、設定してみるかもしれません$a_i = x$残りを任意に埋めて、一致数が増加するかどうかを観察します。 ただし、応答の集計はすべてのポジションにわたって一致するため、これは基本的に信頼できません。 1 つの座標の変更は、配列の残りの部分が注意深く制御されない限り、分離できない形でグローバル スコアに影響を与えます。 

代わりに、置換全体をブルートフォースで実行しようとすると、すべてをテストする必要があります。$n!$候補者であっても、それは完全に不可能です$n = 100$。 

重要な点は、一度に 1 つの位置を分離する必要がないということです。 代わりに、順列の「現在の推測」を維持し、それを徐々に修正することができます。 各クエリは私たちの推測を隠れた順列と比較し、その応答は現在正しい位置の数を正確に示します。 

これにより、自然な最適化の方向が生まれます。現在の推測で 2 つの位置を交換し、正しい一致の数が増加すると、交換は有益になります。 減少した場合は元に戻します。 これは本質的に、グローバル スコアに基づいた順列のローカル検索です。 

問題の構造により、スコア関数が一貫性があり決定的であるため、これが実行可能になります。 各スワップは、予測可能な方法でスコアを最大 2 だけ変更するため、これを安全に使用して、正しい順列に向かって収束させることができます。$O(n^2)$交換します。

 | --- | --- | --- | --- |
 | ブルートフォース列挙 |$O(n!)$|$O(n)$| 遅すぎる |
 | ローカル スワップの最適化 |$O(n^2)$クエリ |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 現在の配列を維持します$p$、最初は任意の順列に設定されます。通常は$[1, 2, \dots, n]$。 

1. 現在の順列を使用してインタラクターをクエリし、一致の数を保存します。$k$。 この値は、現在の推測のもとですでに正しい位置の数を表します。 
2. インデックスのすべてのペアを反復処理します。$(i, j)$と$i < j$、交換を検討してください$p[i]$そして$p[j]$。 
3. スワップ後にクエリを実行し、新しい一致数を取得します。$k'$。 これは、スワップによって隠れた順列との位置合わせが改善されたかどうかを示します。 
4. もし$k' > k$、正しいポジションの数が増えるため、スワップを維持します。 更新も行っております$k \leftarrow k'$。 
5. もし$k' \le k$、正確性が向上しないため、スワップを元に戻します。 これにより、進捗状況が失われることがなくなります。 
6. スワップによってスコアが改善されなくなるまでペアのスキャンを続けます。その時点で、置換は非表示の置換と一致する必要があります。 

このプロセスが正しく終了する理由は、スコアが 0 から 0 までの範囲にあるためです。$n$、受け入れられたすべてのスワップは厳密に少なくとも 1 ずつ増加します。改善のみを受け入れるため、循環することはできません。 

## なぜ機能するのか

 スコア関数は、固定順列での完全一致をカウントします。 交換は 2 つのポジションにのみ影響し、スコアの変化はそれら 2 つのポジションが以前に正しかったか不正確だったかによってのみ決まります。 スワップによってスコアが増加した場合、それは、複数の正しいポジションを破ることなく、少なくとも 1 つの以前は間違っていたポジションが正しくなったことを意味します。 厳密に改善された手のみを受け入れるため、到達するまで固定点の数が単調に増加します。$n$、これは隠れた順列に正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(a):
    print("?", *a)
    sys.stdout.flush()
    return int(input())

def solve():
    n = int(input())
    p = list(range(1, n + 1))

    cur = ask(p)

    for i in range(n):
        for j in range(i + 1, n):
            p[i], p[j] = p[j], p[i]
            nxt = ask(p)

            if nxt >= cur:
                cur = nxt
            else:
                p[i], p[j] = p[j], p[i]

    print("!", *p)
    sys.stdout.flush()

t = int(input())
for _ in range(t):
    solve()
```コードは、順列のサイズを読み取り、単純な ID 推測を初期化することから始まります。 これは有効な置換構造を保証するため、自然なベースラインです。 

各クエリは、現在の推測が隠れた順列にどの程度近いかを評価します。 ネストされたループは、すべてのペアごとのスワップを体系的に試みます。 各交換の後、変更によって位置合わせが改善されたかどうかをすぐにテストします。 そうでない場合は、単調性を維持するために元に戻します。 

対話型プロトコルでは、各出力後のフラッシュが必要です。 これがないと、インタラクターは時間内にクエリを受信できず、同期が壊れてしまいます。 

## 実用的な例

 隠れた順列を考える$p = [2, 1, 3]$、最初の推測付き$[1, 2, 3]$。 

### トレース

 | ステップ | 現在の配列 | クエリ結果 |
 | --- | --- | --- |
 | 初期化 | [1,2,3] | 1 |
 | スワップ(0,1) | [2,1,3] | 3 |
 | 受け入れる | [2,1,3] | 3 |

 最初のクエリは 1 つの正しい位置を示しています。 位置 0 と 1 を交換した後、スコアは 3 にジャンプします。これは、交換によって順列全体が整列するため、交換が受け入れられることを意味します。 

これは、恒等順列がターゲットに近い場合、有益なスワップによって正しい構造が即座に公開されることを示しています。 

ここで考えてみましょう$p = [3,2,1]$。 

| ステップ | 現在の配列 | クエリ結果 |

 | スワップ(0,2) | [3,2,1] | 3 |
 | 受け入れる | [3,2,1] | 3 |

 ここでは、単一の長距離スワップによって 2 つの不一致位置が同時に修正され、最小限のフィードバックでもスコア関数がどのように全体的な正確性を目指して導かれるかを示しています。

 ## 特殊なケース

 のために$n = 1$の場合、アルゴリズムは単一のクエリを実行し、唯一の可能な順列を即座に返します。 考慮すべきスワップがないため、ID の初期化はすでに正しく行われています。 

のために$n = 2$、可能なスワップは 1 つだけです。 最初の推測が間違っている場合、交換により必然的に一致カウントが 2 に増加するため、常に受け入れられます。 これは、自明ではない最小のケースでも単調改善特性が維持されることを示しています。 

大型の場合$n$、アルゴリズムは、不正な順列には少なくとも 1 つの位置のペアが含まれている必要があり、その交換によって位置合わせが改善されるという事実に基づいています。 スワップの改善を貪欲に受け入れることで、スコアが減少することがなく、以下の制限を受けるため、収束が保証されます。$n$。
