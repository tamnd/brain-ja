 ## 問題の理解

 小文字の文字列が与えられます。 ゲームを開始する前に、キャラクターを好きな順序に並べ替えることができます。 

1 回の消去操作で、同じ文字で構成される連続ブロックが選択され、そのブロックの長さは少なくとも 3 でなければなりません。ブロック全体が消え、文字列の残りの部分が連結されます。 せいぜいパフォーマンスするかもしれません`k`そのような操作。 

タスクは、文字列の最終的な最小長を見つけることです。 

重要な点は、消去が行われる前に文字列を自由に再配置できることです。 順序が固定されなくなると、問題は元の文字列内の位置に関するものではなくなります。 重要なのは、各キャラクターが何回登場するかです。 

文字列の長さは次のとおりです。`10^5`したがって、文字列自体の再配置や削除シーケンスをシミュレートしようとするアルゴリズムは不要です。 このアルファベットには小文字が 26 文字しか含まれていないため、解決策は文字列構造ではなく文字の頻度に基づいて行う必要があることが強く示唆されています。 

いくつかの特殊なケースは判断を誤りやすいものです。 

考慮する：```
n = 2, k = 100
s = aa
```の数`'a'`はわずか 2 です。少なくとも 3 の長さのブロックは決して形成されないので、答えは次のようになります。`2`、 ない`0`。 

考慮する：```
n = 6, k = 1
s = aaabbb
```不注意なアプローチでは、再配置後に 2 つのグループのうち 1 つだけを削除できると考えるかもしれませんが、これは正しいことです。 どちらかを削除します`"aaa"`または`"bbb"`、長さを残す`3`。 

考慮する：```
n = 7, k = 5
s = aaaaabc
```それでも`k`大きい、キャラクター`'a'`5 つのコピーすべてを 1 つのブロックに配置できるため、1 回の操作で完全に削除できます。`"aaaaa"`。 答えは`2`、複数の操作を必要とするものではありません。 

## アプローチ

 強引な考え方では、考えられるすべての再配置と、考えられるすべての削除命令について考えることになります。 文字列の長さが中程度の場合でも、順列の数は天文学的な数に達し、削除されるたびに文字列は再び変更されます。 これはまったく実現不可能です。 

重要な観察は、再配置によりすべての位置制約が取り除かれるということです。 

キャラクターが登場するとします`c`回。 

もし`c < 3`、そのキャラクターは削除可能なブロックを形成することはできません。 文字列をどのように並べ替えても、少なくともそれらは`c`文字は残らなければなりません。 

もし`c ≥ 3`、すべてのコピーを 1 つの連続したブロックにまとめて配置し、1 回の操作でブロック全体を削除できます。 1 つの操作でそのキャラクターのすべての出現がすでに削除されているため、同じキャラクターに対して複数の操作を費やすことには何のメリットもありません。 

これにより、問題は単純なリソース割り当て問題に変換されます。 

頻度が 3 以上の各文字がアイテムになります。 

- コスト: 1 回の操作。 
- ゲイン: その周波数。 

予算は最大でも`k`操作を行っているため、削除される文字数を最大化したいと考えています。 最適な戦略は、最も頻度の高い文字を最初に削除することです。 

小文字は 26 個しかないため、頻度を数え、少なくとも 3 つのすべての頻度を収集し、降順に並べ替えて、最大のものを取得するだけで済みます。`k`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(n + 26 log 26) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての小文字の頻度を数えます。 
2. あらゆる周波数について`c`、どうかを確認してください`c ≥ 3`。 

3 より小さい頻度は削除できないため、リムーバブル プールには何も寄与しません。 
3. すべての取り外し可能な周波数をリストに保存します。 

このような各頻度は、1 回の操作で完全に削除できる文字を表します。 
4. リストを降順に並べ替えます。 

すべての削除可能な文字には同じ数の操作、つまり 1 回の操作が必要となるため、最初に最大の頻度で操作を行う必要があります。 
5. 最初のものを取る`min(k, len(list))`周波数を計算し、それらを合計します。 

これは削除できる最大文字数です。 
6. 出力:```
n - removed_characters
```### なぜ効果があるのか

 再配置後、同じ文字の出現はいつでもグループ化できます。 

登場キャラクターに関しては`c ≥ 3`すべてのコピーを連続して配置すると、一定の長さの取り外し可能なブロックが作成されます。`c`, そのため、文字クラス全体を 1 回の操作で削除できます。 登場回数が 3 回未満のキャラクターの場合は、除去可能なブロックをまったく形成できません。 

したがって、すべてのキャラクターは独立して 2 つのカテゴリのいずれかに分類されます: コスト 1 で完全に削除できるか、削除できないかです。 問題は最大でも選択になります`k`合計頻度ができるだけ大きい削除可能な文字。 すべてのコストは等しいため、最大の周波数を選択することが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    freq = [0] * 26
    for ch in s:
        freq[ord(ch) - ord('a')] += 1

    removable = [c for c in freq if c >= 3]
    removable.sort(reverse=True)

    removed = sum(removable[:k])
    print(n - removed)

solve()
```最初の部分では、文字の頻度をカウントします。 

リスト`removable`1 回の操作で出現セット全体を削除できる文字が正確に含まれています。 3 未満の頻度は有効な排除に参加できないため無視されます。 

降順に並べ替えると、最初の`k`エントリは最も収益性の高い操作に対応します。 それらを合計すると、削除された文字の最大数が得られます。 

最終的な答えは、元の長さから削除された文字数を引いたものになります。 

微妙な点としては、`k`削除可能な文字数よりもはるかに大きい場合があります。 Python のスライスはこれを自然に処理します。`removable[:k]`場合でも安全です`k`リストの長さを超えています。

# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:

    input = sys.stdin.readline

    n, k = map(int, input().split())
    s = input().strip()

    freq = [0] * 26
    for ch in s:
        freq[ord(ch) - ord('a')] += 1

    removable = [c for c in freq if c >= 3]
