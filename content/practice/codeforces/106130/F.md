 ## 解決策
 ## 問題の理解

 私たちは、動的な複数の投票セットを維持しています。`m`参加者。各参加者はインデックスによって識別されます。`0`に`m - 1`。 投票ごとに 1 人の参加者のカウントが増加し、その参加者が現在少なくとも 1 票を持っている場合、削除操作によってカウントが減少します。 システムは、次の初期シーケンスを通じて進化します。`n`投票数に続いて`q`更新。各更新は挿入または削除のいずれかであり、どちらも擬似ランダム プロセスによって生成されます。 

更新のたびに、概念的にはすべての参加者を現在の投票数で降順に並べ替えます。 させて`a[k]`は、このソートされたカウントのマルチセット内の k 番目に大きい投票カウント値を示します。 次に、投票数がこのしきい値と正確に等しいすべての参加者を調べます。`a[k]`、そしてそれらのインデックスの合計を計算します。 その合計は次のように記録されます`S_i`i 番目の操作の場合。 最終的な答えは、これらすべての XOR です。`S_i`。 

重要な問題点は、両方とも`n`そして`q`最大 2 × 10^7 までの大きさになる可能性があり、`m`も 2 × 10^7 までです。 これにより、操作ごとのすべての参加者の完全なスキャンや周波数配列の完全な並べ替えが除外されます。 サイズの明示的な配列を維持する場合でも`m`実行可能であるだけですが、すべてに関わる操作はすべて`m`クエリごとに要素を指定することは不可能です。 

明らかではないエッジケースは、多くの参加者が同じ周波数を共有する場合、特にほとんどがゼロである場合です。 たとえば、ほぼすべてのカウントが 0 の場合、k 番目に大きい値は多くの場合 0 になります。これは、現在カウントが 0 の参加者がすべて答えに含まれていることを意味します。 ゼロ以外のエントリのみを追跡する単純なソリューションでは、これらの参加者を完全に見逃してしまいます。 

もう 1 つの微妙なエッジ ケースは、参加者の投票がゼロであるために削除が無視されるが、それでも答えを計算する必要がある場合です。 周波数の構造は有効な更新が行われた場合にのみ変更されますが、更新によって実際に状態が変更されたかどうかに関係なく出力を計算する必要があるため、これが重要になります。 

## アプローチ

 直接シミュレーションは配列を維持します`cnt[i]`参加者ごとに計算し、各操作後にすべての周波数を再計算します。 単一のカウントを更新した後、カウントの頻度ヒストグラムを作成し、頻度を並べ替えて、k 番目に大きいカウント値を見つけます。 最後に、すべての参加者をスキャンして、その値に一致する参加者を合計します。 

このアプローチは正しいですが、非常に高価です。 各更新には、ディストリビューションを再構築するための O(m) 作業と、さらに O(m log m) または O(m) のスキャンが必要となり、結果としておよそ O(qm) となり、これは実現可能な限界をはるかに超えています。 

重要な観察は、参加者の完全な順序付けや完全な頻度分布自体を実際には気にしていないということです。 カウントの中で k 番目に大きい頻度値のみを考慮します。 これは複数の周波数セットにおける値であり、参加者に関する構造的な順序付けの問題ではありません。 

そのため、参加者ごとの構造のみを維持するのではなく、頻度の分布、つまり現在カウント 0、カウント 1、カウント 2 を持つ参加者の数などを維持します。 させて`freq[c]`参加者の正確な人数`c`投票。 各更新では 1 人の参加者のみが移動されます。`c`に`c+1`または`c-1`なので、エントリは 2 つだけです`freq`変化。 

次に、マルチセットの中で k 番目に大きい値は何か、ここでの値は何か、と答える必要があります。`c`表示されます`freq[c]`回。 これは、周波数バケットを高いカウントから下方向にスキャンし、k に達するまで累積することで解決できます。 カウントは時間の経過とともに増加するだけなので、最大でも`n+q`、アクティブな範囲は制限されています。 

2 番目の部分の答えとしては、カウントが次と等しいインデックスの合計です。`a[k]`、各カウント値に対して追加の構造を維持します。`c`、現在そのカウントを持つインデックスの合計を維持します。 この場合、クエリごとの答えは直接的に次のようになります。`sum[c*]`、 どこ`c* = a[k]`。 

したがって、各演算は、k 番目の周波数レベルを見つけるための実装戦略に応じて、予想される O(1) または O(log N) になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q · m + q · m log m) | O(m) | 遅すぎる |
 | 最適 | 構造に応じて O(q · √n) または O(q log n) | O(m + 最大カウント) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは 3 つの主要な構造を維持しています: 配列`cnt[x]`参加者の現在の投票を保存する`x`、辞書または配列`freq[c]`現在投票数を持っている参加者の数を保存する`c`、および別の配列`sum[c]`カウントが次と等しい参加者のインデックスの合計を保存する`c`。 

最初は参加者全員がゼロ票からスタートするため、`freq[0] = m`そして`sum[0] = 0 + 1 + ... + (m - 1)`。 

各操作で 1 人の参加者が更新されます`v`。 

1. 読み取り操作の種類と参加者インデックス`v`。 削除の場合は、`cnt[v] == 0`、何もしない`cnt`、`freq`、 または`sum`。 状態は変更されないままですが、出力が依然として必要であるため、その後もクエリ計算を続行します。 
2. 操作が有効なデクリメントの場合、参加者を移動します`v`現在のカウントから`c`に`c - 1`。 デクリメントします`freq[c]`そして引きます`v`から`sum[c]`、次に増加します`freq[c - 1]`そして追加します`v`に`sum[c - 1]`。 同じパターンがインクリメント操作にも適用されます。 
3. 更新後、すべてのカウントの中で k 番目に大きい頻度値が必要です`c`そのような`freq[c] > 0`。 可能な最大値から下方向にカウントをスキャンし、累積します。`freq[c]`累積合計がそれ以上になるまで`k`。 現在`c`は目標値です`t`。 
4. 1回`t`が見つかった場合、このステップの寄与は単純に`sum[t]`。 
5. この値を最終応答アキュムレータに XOR します。 

スキャンが効率的に機能する理由は、カウントの変化が遅いためです。各参加者のカウントは操作ごとに最大 ±1 ずつ変化するため、カウントの分布は滑らかで、最大カウントは挿入の合計数によって制限されたままになります。 

### なぜ効果があるのか

 いつでも、`freq[c]`値の多重度を正確に表します`c`すべての参加者数のマルチセット内。 k 番目に大きい値は純粋にこのマルチセットに対して定義されるため、参加者を明示的に並べ替えることなく、周波数を高から低までスキャンすることで正しい順序の統計が再構築されます。 sum 配列は更新のたびに一貫して維持されるため、正しい値が得られると`t`が決定されると、答えはその同値クラス内のすべてのインデックスの正確な合計になります。 

単一ユニット遷移以外のカウントに影響を与える操作はありません。`freq`そして`sum`各更新後も、システム状態の一貫した不変状態が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    seed, k, n, m, q, b = map(int, input().split())

    MOD = 1000000007

    def read():
        nonlocal seed
        seed = (seed * 13331 + 23333) % MOD
        return seed

    maxv = n + q + 5

    cnt = [0] * m
    freq = [0] * (maxv + 1)
    sm = [0] * (maxv + 1)

    # initial state: all zeros
    freq[0] = m
    sm[0] = m * (m - 1) // 2

    def add(x, v):
        c = cnt[x]
        freq[c] -= 1
        sm[c] -= x
        cnt[x] = c + v
        c2 = c + v
        freq[c2] += 1
        sm[c2] += x

    for _ in range(n):
        v = read() % m
        add(v, 1)

    ans = 0

    for _ in range(q):
        op = read()
        v = read() % m

        if op < b:
            if cnt[v] > 0:
                add(v, -1)
        else:
            add(v, 1)

        # find k-th largest frequency value
        rem = k
        t = 0
        for c in range(maxv, -1, -1):
            if freq[c]:
                rem -= freq[c]
                if rem <= 0:
                    t = c
                    break

        ans ^= sm[t]

    print(ans)

if __name__ == "__main__":
    solve()
```実装ではカウントが保持されます`cnt`、そして使用します`freq`そして`sm`カウント値の同期された集計として。 の`add`関数は状態遷移が発生する唯一の場所であり、参加者ごとの状態と集約されたバケットの間の一貫性を確保します。 

k 番目に大きい周波数値の検索は、可能なカウントに対する線形スキャンです。 合計数が超えることはありませんので、`n + q`、この範囲は制限されており、制約の下では安全です。 

微妙な点の 1 つは初期化です。すべての参加者はゼロから開始するため、`sm[0]`はインデックスの算術和として計算され、操作の前に正確性が保証されます。 

## 実用的な例

 ### 例 1

 次のような小さなシステムを考えます。`m = 5`、`k = 2`。 初期化といくつかの更新の後、カウントが得られたとします。`[0, 2, 0, 2, 1]`。 

頻度バケットを構築します。 

| カウント | 周波数 | 合計 |
 | --- | --- | --- |
 | 2 | 2 | 1 + 3 = 4 |
 | 1 | 1 | 4 |
 | 0 | 2 | 0 + 2 = 2 |

 高から低までスキャンします。 

まずカウント 2、累積 = 2 を取得します。k = 2 なので、すぐに停止します。 したがって、しきい値は 2 で、答えは sum[2] = 4 となります。 

これにより、k がそのバケット内に到達したときに、最大の頻度を持つ参加者のみが貢献することが確認されます。 

### 例 2

 カウントを次のようにします`[1, 1, 1, 0]`、k = 3とします。 

| カウント | 周波数 | 合計 |
 | --- | --- | --- |
 | 1 | 3 | 0 + 1 + 2 = 3 |
 | 0 | 1 | 3 |

 スキャン:

 カウント 1、累積 = 3 を取得し、k に達します。 したがって、しきい値は 1、答えは 3 です。 

これは、頻度の関係が自然に処理されることを示しています。すべての等しい頻度の参加者がグループ化され、選択は累積多重度のみに依存します。
