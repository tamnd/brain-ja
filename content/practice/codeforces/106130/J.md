 ## 解決策
 ## 問題の理解

 グリッドが与えられています$n+2$行と$m$列。 上の列と下の列は安全ですが、$n$中央の列にはそれぞれ 1 つの石像が含まれています。 各彫像はその列の特定の列に座り、左または右を向いています。 その位置から、その列に沿って向いている方向に水平レーザーを放射し、そのレーザーで覆われたすべてのセルが禁止されます。 彫像の独房自体も禁止されています。 

セルが彫像によって占有されているか、レーザー光線上にある場合、セルはブロックされます。 スタート位置はグリッドの右上隅、ゴールは左下隅です。 各ステップで、プレイヤーは 1 つのセルを上下左右に移動できますが、グリッドから離れたり、ブロックされたセルに入ることができません。 

このタスクは、ブロックされていないセルを通る有効な移動のみを使用して、スタートからゴールまでのパスが存在するかどうかを判断することです。 

グリッド サイズは最大でも約 100 万セルです。 これは、各セルを一定の回数訪問するアルゴリズムは実行可能であることを直ちに示唆していますが、連続した 2 次関数やクエリごとに繰り返し再計算を伴うものは遅すぎるでしょう。 

微妙な失敗例は、レーザー効果の誤解から生じます。 レーザーは単一のセルではなく光線全体であるため、像の位置のみをブロックされたものとして扱うのは正しくありません。 

たとえば、行の 3 列目に右向きの彫像がある場合、その行の 3 列目から 3 列目までのすべてのセルが$m$安全ではありません。 列 3 のみをブロックする単純なアプローチでは、レーザー ゾーンの通過が誤って許可され、誤った「YES」が生成されます。 

もう 1 つのエッジ ケースは、レーザーが連続して安全なセルをまったく残さない場合です。 列 1 の彫像が左を向いている場合、列全体が安全でなくなり、実質的に完全なバリアとして機能します。 

## アプローチ

 問題について考える最も直接的な方法は、問題をグラフとしてモデル化することです。 グリッド内のすべてのセルはノードであり、両方の端点が安全な場合、エッジは直交する隣接するセルを接続します。 このグラフが構築されたら、開始セルから標準の到達可能性検索を実行できます。 

グリッドが明示的であるため、グラフの構築は簡単です。 中央の各行について、レーザーが当たったすべてのセルをブロック済みとしてマークします。 次に、残りのセルに対して BFS または DFS を実行します。 

この強引なアイデアはすでに最適に近づいています。 主なコストは、各セルを最大 1 回訪問し、最大 4 つの隣接セルをチェックすることです。$O(nm)$時間。 制約は純粋に幾何学的で静的なものであるため、隠れた組み合わせの爆発はありません。 

重要な観察は、レーザー制約はグラフ内に存在するセルを変更するだけであるということです。 ステップ間に時間のダイナミクスや依存関係が導入されることはありません。 ブロックされたセルが事前計算されると、問題は単純なグリッド接続に縮小されます。 

したがって、タスクは次のように折りたたまれます: ブロックされたグリッドを構築してから、BFS を実行します。

 ## アルゴリズムのチュートリアル

 まず問題を空きセルとブロックされたセルの静的グリッドに変換してから、BFS を実行します。 

1. 2D ブール配列を作成する`blocked`サイズの$(n+2) \times m$、最初はすべて false です。 セルに入力できるかどうかを表します。 
2. それぞれについて$n$中段、像の位置を読む$c_i$そして方向$d_i$。 彫像セル自体をブロック済みとしてマークします。 
3. 彫像が右を向いている場合、次のすべてのセルが$c_i$に$m$その行はブロックされます。 左向きの場合、次のすべてのセルが$1$に$c_i$ブロックされてしまう。 これにより、レーザー光線が連続したセグメントとして直接エンコードされます。 
4. 以下からBFSを実行します。$(1, m)$ブロックされていない場合。 キューと訪問済みの配列を維持します。 
5. 各セルから 4 方向に移動してみます。 ネイバーがグリッド内にあり、ブロックされておらず、以前に訪問したことがない場合にのみ、ネイバーをキューに入れます。 
6. 到着したら早めに停止する$(n+2, 1)$。 

ここでの BFS の背後にある重要な考え方は、すべての移動には等しいコストがかかるため、重み付けされていないグリッドでの到達可能性がまさに BFS の計算内容であるということです。 

### なぜ効果があるのか

 ブロックされたセルが修正されると、グリッドは標準の 4 近傍グラフになります。 BFS は、開始セルを含む接続コンポーネントを正確に探索します。 ターゲットが同じコンポーネント内にある場合、BFS は最終的にターゲットに到達します。 そうしないと、このコンポーネントの外部に代替パスが存在しないため、到達できなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    
    # grid has n+2 rows
    blocked = [[False] * m for _ in range(n + 2)]
    
    # read statues
    for i in range(n):
        c, d = input().split()
        c = int(c) - 1
        r = i + 1
        
        blocked[r][c] = True
        
        if d == 'R':
            for j in range(c, m):
                blocked[r][j] = True
        else:
            for j in range(0, c + 1):
                blocked[r][j] = True
    
    sr, sc = 0, m - 1
    tr, tc = n + 1, 0
    
    if blocked[sr][sc] or blocked[tr][tc]:
        print("NO")
        return
    
    q = deque()
    q.append((sr, sc))
    visited = [[False] * m for _ in range(n + 2)]
    visited[sr][sc] = True
    
    dirs = [(1,0), (-1,0), (0,1), (0,-1)]
    
    while q:
        r, c = q.popleft()
        if (r, c) == (tr, tc):
            print("YES")
            return
        
        for dr, dc in dirs:
            nr, nc = r + dr, c + dc
            if 0 <= nr < n + 2 and 0 <= nc < m:
                if not blocked[nr][nc] and not visited[nr][nc]:
                    visited[nr][nc] = True
                    q.append((nr, nc))
    
    print("NO")

if __name__ == "__main__":
    solve()
```この実装では、まずブロック マップを行ごとに構築し、各レーザーを塗りつぶされた間隔として直接エンコードします。 次に、グリッド上で標準の BFS を実行します。 Visited 配列により、各セルが 1 回処理されることが保証され、方向配列により 4 つの可能な移動がエンコードされます。 

インデックス付けには注意が必要です。追加の境界行により、入力では 1 ベースの列と 1 オフセットされた行が使用されるため、すべてを内部的に 0 ベースのインデックス付けに変換します。 

## 実用的な例

 ### 例 1

 レーザーが中央の行の大部分をブロックする小さなグリッドを考えてみましょう。 

入力:```
1 3
2 R
```開始は次のとおりです$(1,3)$、ゴール$(3,1)$。 中央の行の列 2 には右を向いた彫像があるため、セル$(2,2)$そして$(2,3)$ブロックされ、残るのは$(2,1)$使える。 

| ステップ | セル | キューの状態 | アクション |
 | --- | --- | --- | --- |
 | 1 | (1,3) | (1,3) | 開始 |
 | 2 | (2,3 ブロック) | (1,3) | スキップ |
 | 3 | (1,2) | (1,2) | 左に移動 |
 | 4 | (2,1) | (2,1) | 下に移動 |
 | 5 | (3,1) | 到達しました | 成功 |

 このトレースは、BFS がレーザー境界によって作成された狭い通路をどのように自然に検出するかを示しています。 

### 例 2

 入力:```
2 2
1 L
2 R
```ここでは、中央の列が両方とも大きく制限されています。 

| ステップ | セル | キューの状態 | アクション |
 | --- | --- | --- | --- |
 | 1 | (1,2) | (1,2) | 開始 |
 | 2 | (1,1) | (1,1) | 左に移動 |
 | 3 | ブロックされた行セル | - | 降りることができません |
 | 4 | - | 空 | BFS 終了 |

 各列が少なくとも 1 方向の交差の可能性をすべて排除し、連続的な垂直方向の横断を防ぐため、どのパスも中央の列を通過することはできません。 

これらの例は、アルゴリズムが使用可能なレーザー構成と完全に遮断するレーザー構成をどのように区別するかを示しています。

 ## 特殊なケース

 開始セルまたは終了セルがレーザー ゾーン内にある場合、重大なエッジ ケースが発生します。 たとえば、構成により右上のセルがブロック済みとしてマークされる場合、BFS はただちにパスを拒否する必要があります。 アルゴリズムは、検索を開始する前に両方のエンドポイントをチェックすることでこれを処理し、無駄な走査が発生しないようにします。 

もう 1 つのケースは、レーザーが列全体をカバーする列です。 このような状況では、その列がグリッド内のハードセパレーターになります。 その行を横切る遷移が存在しないため、BFS は当然これを尊重し、検索スペースは切断されたコンポーネントに分割されます。 

最後に、両方のエンドポイントが、交互のレーザー方向によって作成された異なる切断領域にある場合、BFS はターゲットに到達することなく到達可能な領域を使い果たし、正しく「NO」を返します。
