 ## 解決策
 ## 問題の理解

 私たちにはツリーが与えられ、非常に具体的な再構築操作を繰り返し実行することが許可されています。 各操作では、まず一時的なルートとしてノードが選択され、そのステップの親子関係が定義されます。 次に、非ルートノードを選択します$u$。 その根付いたビューの場合、その直系の子はすべて、$u$から切り離されています$u$に直接再接続します$u$の親。 この後、$u$はすべての子を失い、実質的にリーフになります (親との接続を除く)。 

目標は、単純なパスの長さが 3 エッジを超える構造にツリーを変換することです。 言い換えれば、最終的なツリーの直径は最大 3 でなければなりません。最小限の操作数を使用してこれを達成したいと考えています。少なくとも 1 つの操作が必要な場合は、有効な最初の操作も出力する必要があります。これは、選択したルートを指定することを意味します。$r$そして選択したノード$u$最適なシーケンスの最初のステップとして。 

制約は以下を意味します$10^5$テスト ファイルごとにノードがあり、多くのテスト ケースがあるため、ソリューションはテスト ケースごとに線形である必要があります。 操作ごとにグローバルな再計算を繰り返したり、変換をシミュレーションしたりするものは、すぐに遅すぎます。 

重要な点は、操作が選択したルートに依存することです。 同じノード$u$親子構造が変化するため、ルートとして選択されたノードに応じて動作が異なる場合があります。 このため、操作が実際に達成する内容の構造的不変条件を特定しない限り、単純な貪欲シミュレーションの信頼性が低くなります。 

よくある落とし穴は、操作が元のツリー内で純粋にローカルであると想定することです。 そうではない。 これはルート付きツリー内でローカルです。つまり、効果はエッジの動的な方向に依存します。 

素朴な推論を打ち破る傾向があるエッジケースには、次のようなものがあります。 

ツリーがすでに長さ 3 以下のパスである場合、操作は必要ありません。 たとえば、4 つのノードのチェーンにはすでに直径 3 があるため、出力は 0 になります。不注意な解決策では、依然として変換が試行される可能性があります。 

ツリーが星の場合、すでに直径 2 があるため、やはり操作は必要ありません。 

ツリーに異なるノードに接続された複数の長い枝がある場合、最初の正しい操作では、単一のサブツリーをローカルに修正するのではなく、グローバルな高さを迅速に削減する必要があります。 直径構造を考慮せずに任意の高次ノードをターゲットとするグリーディでは、最長パスを削減できない可能性があります。 

## アプローチ

 ブルートフォースアプローチは、root の考えられるすべての選択をシミュレートします。$r$とノード$u$、操作を適用し、直径が最大 3 に達する最小ステップ数を再帰的に検索します。操作ごとにツリー構造が変更されるため、親子関係と直径の再計算にはコストがかかります。$O(n)$。 浅い検索でも全体に分岐$r$そして$u$につながる$O(n^3)$または、それよりも悪い行動は不可能です。$10^5$ノード。 

重要な観察は、ターゲット構造が非常に限定的であるということです。 直径が最大 3 のツリーは、1 つのノードを中心とする星、または中心がエッジで接続された 2 つの星のいずれかにしか見えません。 これは、最終構成には最大 2 つの「中心」頂点があり、他のすべてのノードがこのコアから 1 または 2 の距離内にあることを意味します。 

操作自体は「平坦化」の動きとして最もよく理解されています。つまり、選択したルートの下で、$u$以下の分岐層を 1 つ削除します$u$その子を上に押し上げることによって。 これによりサブツリー内のノードのセットは変更されませんが、深さが減り、中間の分岐点がなくなります。 

重要な簡素化は、複数の操作を慎重にシミュレートする必要がないことです。 木の直径がすでに最大 3 であれば、作業は完了です。 それ以外の場合は、直径の端点を公開するルートを親構造として常に選択し、中央領域のノードを選択して 1 回の操作で過剰な分岐を排除できるため、構造を有効な構成に折りたたむには、慎重に選択した 1 つの操作で十分です。 

したがって、答えは 0 または 1 の演算のいずれかです。 主なタスクは、木がすでに直径制約を満たしているかどうかを検出し、満たしていない場合は 1 つの有効なペアを生成することになります。$(r, u)$それが最適な変換を開始します。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(n^3)$|$O(n)$| 遅すぎる |
 | 直径チェック + 建設的な動き |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず木の直径を計算します。 これは、BFS を 2 回実行することで実行できます。 任意のノードを選択し、そこから最も遠いノードを見つけて、そのノードから再度 BFS を実行して直径の長さを取得します。 

直径が最大 3 の場合、演算は必要なく、0 を出力します。 

直径が 3 より大きい場合は、圧縮プロセスを開始する単一の操作を構築する必要があります。 直径の 1 つの端点を一時的なルートとして選択します$r$なぜなら、これにより、ルートのある形で長い鎖構造が最大限に露出されるからです。 それから私たちは選択します$u$直径パスの中心近くのノード、具体的には直径パス上の中間ノードとして。 このノードは、次のルート構造でその下に分岐があることが保証されています。$r$有効な圧縮ポイントになります。 

1 を出力し、続いて$r, u$。 

### なぜ効果があるのか

 直径が 3 を超えるツリーには、少なくとも 4 の長さのパスが含まれている必要があります。そのようなパスには、1 つの終点ルートに対して分岐構造が集中している、明確に定義された中間点領域があります。 エンドポイントをルートとして選択すると、中間点ノードがルート表現の内部分岐ボトルネックになります。 そのノードでの操作により、子孫の 1 つの層が削除され、それらが上にプッシュされ、最長パスの複雑さが厳密に軽減されます。 最終的な目標は直径が最大 3 であるため、この中央のボトルネックを解消すれば、1 ステップで有効な構成に到達するのに十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, adj):
    n = len(adj) - 1
    dist = [-1] * (n + 1)
    parent = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0
    far = start

    while q:
        v = q.popleft()
        for to in adj[v]:
            if dist[to] == -1:
                dist[to] = dist[v] + 1
                parent[to] = v
                q.append(to)
                if dist[to] > dist[far]:
                    far = to

    return far, dist, parent

t = int(input())
for _ in range(t):
    n = int(input())
    adj = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        adj[u].append(v)
        adj[v].append(u)

    if n == 1:
        print(0)
        continue

    a, _, _ = bfs(1, adj)
    b, dist, parent = bfs(a, adj)

    diameter = dist[b]

    if diameter <= 3:
        print(0)
        continue

    path = []
    cur = b
    while cur != -1:
        path.append(cur)
        cur = parent[cur]
    path.reverse()

    r = a
    u = path[len(path) // 2]

    print(1)
    print(r, u)
```実装は、直径エンドポイントを計算し、直径パスを再構築するためのダブル BFS から始まります。 パスが判明すると、その長さによって操作が必要かどうかが直接決まります。 

ルートの選択は、直径の 1 つの端点として固定されます。 これは、ルート ビューで直径パスが直線になることを保証するため、意図的なものです。 選択したノード$u$はそのチェーンの中間点であり、構造の最も密度の高い部分に存在することが保証されます。 

直径パスを再構築するときは注意が必要です。2 番目の BFS からの親ポインターに依存します。 1 つのエンドポイントからの BFS は、一意のツリー パス構造に正確に対応する最短パス ツリーを生成するため、これは有効です。 

## 実用的な例

 ### 例 1

 5 つのノードの単純なチェーンを考えてみましょう。$1 - 2 - 3 - 4 - 5$。 

1 から BFS を実行すると、最も遠いノードとして 5 に到達します。 直径が4なので手術が必要です。 

| ステップ | | b | パス | 直径 | アクション |
 | --- | --- | --- | --- | --- | --- |
 | BFS1 | 1 | 5 | 1-2-3-4-5 | 4 | 長いチェーンを検出する |
 | r | を選択してください 1 | 5 | 1-2-3-4-5 | 4 | エンドポイントのルート |
 | あなたを選んでください | 1 | 5 | 1-2-3-4-5 | 4 | 中間点 = 3 |

 出力します$r=1, u=3$。 これにより、根の形の中央の分岐点が削除され、1 回の操作でチェーン構造が崩壊します。 

これは、長い線状構造が、終点ルート化の下の中間点をターゲットにすることによって解決されることを確認します。 

### 例 2

 ノード 1 を中心とし、葉 2、3、4、5 を持つ星があるとします。 

直径は2なので、操作は必要ありません。 

| ステップ | 直径 | アクション |
 | --- | --- | --- |
 | BFS | 2 | 星が検出されました |

 これは、たとえ「枝分かれしている」ように見えても、高次だが浅いツリーがすでに有効であることを裏付けています。

 ## 特殊なケース

 単一ノードの場合、直径の計算ではゼロが得られ、変換は必要ないため、アルゴリズムはすぐに 0 を返します。 

星型ツリーの場合、BFS は直径 2 を検出するため、直径 ≤ 3 という条件が成立し、操作は実行されません。 これにより、すでに最適な構造における不必要な変更が回避されます。 

長いチェーンの場合、アルゴリズムはエンドポイントを正確に識別し、操作ターゲットとして中間点を選択します。 これにより、チェーンを段階的に修正しようとするのではなく、中央のボトルネックを 1 つのステップで確実に取り除くことができます。 

複数の分岐を持つバランスのとれたツリーの場合、直径は 3 より大きく正しく計算され、選択された中間点は依然として最長のパス上にあるため、操作のターゲットが任意の分岐ではなく構造的に関連するノードであることが保証されます。
