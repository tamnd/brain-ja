 ## 解決策
 ## 問題の理解

 1 から n までの数値の順列を作成するように求められます。 この順列から、2 つの古典的な部分列の尺度、つまり厳密に増加する最も長い部分列の長さと、厳密に減少する最も長い部分列の長さを調べます。 これら 2 つの長さの合計を最小にする順列を出力したいと考えています。 

重要な問題は、これら 2 つの量が順列を反対の構造方向に引っ張ることです。 非常にソートされた配列では増加するサブシーケンスが長くなり、非常に反転された配列では減少するサブシーケンスが長くなります。 課題は、どちらの単調な構造も大きくならないバランスの取れた構造を見つけることです。 

入力は 2000 までの単一の整数 n であるため、O(n^2) または O(n log n) の構造は完全に受け入れられます。 n! 以来、指数関数的または列挙順列に基づくものは不可能です。 成長が早すぎる。 O(n^3) でさえ境界線に達しますが、おそらく許容可能です。 ただし、直接的に建設的な O(n) を目指す必要があります。 

微妙な点は、LIS と LDS の両方が同じ順列で計算されることです。 LIS を削減するために配置を変更すると、誤って LDS が増加する可能性があり、その逆も同様であるため、構造を持たない貪欲なローカル スワップは簡単に失敗する可能性があります。 

たとえば、n = 5 について考えてみましょう。 

順列 1 2 3 4 5 では、LIS = 5 および LDS = 1、合計 = 6 となります。 

順列 5 4 3 2 1 では、LIS = 1 および LDS = 5、合計 = 6 となります。 

素朴なアイデアは、1 5 2 4 3 のように小さい値と大きい値を交互に配置することかもしれませんが、そのようなインターリーブでは両方のサブシーケンスの長さが体系的に制御されず、配置によっては長い単調なサブシーケンスが発生する可能性があります。 

本当の課題は、ローカルな決定ではなくグローバル構造を使用して、増加および減少するサブシーケンスの幅を同時に制御することです。 

## アプローチ

 ブルート フォース ソリューションでは、1 から n までのすべての順列を列挙し、動的プログラミングを使用して、順列ごとに O(n^2) 時間で各順列の LIS と LDS を計算します。 そうすると O(n! · n^2) となり、n が 10 程度の場合でも不可能になります。 

重要な観察は、この問題は基本的に順列を単調部分列に分解することに関するものであるということです。 LIS、LDS、および半順序の間の古典的な関係は、サブシーケンスを直接最適化しようとするのではなく、グリッド状またはブロック構造を使用することを示唆しています。 

正しい構成は、順列を 2 次元レイアウトに配置して表示することで得られます。 数値をブロックに分割し、ブロックの順序を増加させながらブロック内で反転することを考えると、同時に単調サブシーケンスがどこまで拡張できるかを制限することができます。 そのアイデアは、増加または減少するサブシーケンスが頻繁に「ブロックを切り替える」ことを強制され、その成長を制限する構造を作成することです。 

自然な最適な構築は、配列をおおよそのサイズ sqrt(n) のセグメントに分割し、値の昇順にセグメントを配置しながら、降順で各セグメントを埋めることです。 これにより、LIS がセグメント数によって制限され、LDS がセグメント サイズによって制限され、両方のバランスがとれるパターンが作成されます。 

より正確には、ブロック サイズ B を約 sqrt(n) とすると、サイズ B のブロックに数値を入力し、各ブロックを降順で配置し、ブロックを昇順に配置します。 次に、ブロック内では、増加するサブシーケンスでは B 個を超える要素を取ることはできませんが、ブロック全体にわたって、減少するサブシーケンスでは最大約 n/B 個のブロックを取ることができ、平衡和は 2 sqrt(n) 付近で最小化されます。 

これは、順列に対する LIS + LDS の最小化が二乗分解によって最適化されるという既知の直観と一致します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n^2) | O(n) | 遅すぎる |
 | ブロック平方施工 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

正方形ブロッキング戦略を使用して置換を構築します。 

1. ブロック サイズ B = ⌈sqrt(n)⌉ を選択します。 これにより、増加するサブシーケンスと減少するサブシーケンスの制御の間のトレードオフのバランスがとれます。 
2. 1 から n までの数値をサイズ B の連続するグループに分割します。ただし、最後のグループは除く。 
3. グループごとに、数値を昇順に保存するのではなく、降順に保存します。 これにより、ブロック内で長く増加するサブシーケンスを形成することが困難になります。 
4. ブロックを値の昇順に配置します。 つまり、最初のブロックには最小の数値が含まれ、2 番目のブロックには次に小さい数値が含まれます。 
5. すべてのブロックの連結を出力します。 

各ブロック内で反転する理由は、局所的な増加構造を破壊するためです。 一方、ブロックの順序を増加させ続けることで、ブロック間の大きなジャンプによって、長く減少するサブシーケンスが多くのブロックにまたがるのを防ぐことができます。 

### なぜ効果があるのか

 増加するサブシーケンスは、ブロック間を移動しようとする場合、ブロックごとに最大 1 つの要素を取ることができます。これは、後のブロックの要素は厳密に大きくなりますが、内部順序が逆になり、一貫した選択が制限されるためです。 同様に、ブロックの順序が増加しているため、減少するサブシーケンスはブロック内に閉じ込められ、減少したままあるブロックから別のブロックに移動することはできません。 したがって、LIS はブロック数によって制限され、LDS はブロック サイズによって制限され、それらの合計はおよそ B + n/B となり、B が約 sqrt(n) のときに最小化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    import math
    B = int(math.sqrt(n))
    if B * B < n:
        B += 1

    res = []
    for start in range(1, n + 1, B):
        end = min(n, start + B - 1)
        block = list(range(start, end + 1))
        block.reverse()
        res.extend(block)

    print(*res)

if __name__ == "__main__":
    solve()
```実装はブロック構築の直後に行われます。 平方根を使用してブロック サイズを計算し、連続する整数の範囲にわたって反復処理を行います。 各ブロックは追加される前に反転されます。 重要な点は、ブロックがインデックスではなく値の範囲に基づいて形成されるため、順列プロパティが確実に保持されることです。 

各ブロックを反転することは、ブロック全体でグローバルな順序を維持しながら、ブロック内を移動するときに増加するサブシーケンスを頻繁に再起動するため、必須です。 

## 実用的な例

 ### 例 1: n = 6

 B = 2 とします。ブロック [1,2]、[3,4]、[5,6] を形成します。 それぞれを反転すると、[2,1]、[4,3]、[6,5]になります。 

| ステップ | ブロック範囲 | リバース後のブロック | 結果 |
 | --- | --- | --- | --- |
 | 1 | 1 2 | 2 1 | 2 1 |
 | 2 | 3 4 | 4 3 | 2 1 4 3 |
 | 3 | 5 6 | 6 5 | 2 1 4 3 6 5 |

 最終的な順列: 2 1 4 3 6 5。 

これは、値が局所的に減少しているものの、ブロック全体ではグローバルに増加していることを示しています。 

### 例 2: n = 7

 B = 3 とします。ブロックは [1,2,3]、[4,5,6]、[7] です。 逆転後：[3,2,1]、[6,5,4]、[7]。 

| ステップ | ブロック範囲 | リバース後のブロック | 結果 |
 | --- | --- | --- | --- |
 | 1 | 1 2 3 | 3 2 1 | 3 2 1 |
 | 2 | 4 5 6 | 6 5 4 | 3 2 1 6 5 4 |
 | 3 | 7 | 7 | 3 2 1 6 5 4 7 |

 これは、最後の小さなブロックがどのように正確さを破らないかを示しています。 バランスをわずかに調整するだけです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import sqrt
    n = int(inp.strip())
    B = int(sqrt(n))
    if B * B < n:
        B += 1
    res = []
    for start in range(1, n + 1, B):
        end = min(n, start + B - 1)
        block = list(range(start, end + 1))
        block.reverse()
        res.extend(block)
    return " ".join(map(str, res))

# minimal
assert run("1") == "1"

# small case
assert run("2") in ["1 2", "2 1"]

# sample-like
assert len(run("6").split()) == 6

# larger case structure
assert len(run("10").split()) == 10
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 1 | 最小境界 |
 | 2 | 1 2 または 2 1 | 最小の自明でない順列 |
 | 6 | 6 つの数字 | ブロックの正確性と完全性 |
 | 10 | 10 個の数字 | 一般的な構造の妥当性 |

 ## 特殊なケース

 n = 1 の場合、アルゴリズムは B = 1 を設定します。唯一のブロックは [1] ですが、それを反転しても [1] になります。 LIS と LDS は両方とも 1 であり、代替の置換は存在しません。 

n = 2、B = 2 の場合、単一のブロック [1,2] が [2,1] に反転されます。 これにより、LIS = 1 および LDS = 2 が生成されます。これは、どの順列でも少なくとも 1 つが 2 に等しい必要があるため、最適です。 

n = 3 の場合、B = 2。ブロックは [1,2] → [2,1] および [3] → [3] となり、[2,1,3] になります。 LIS は 2、LDS は 2 であり、小規模でもすでにバランス効果が現れ始めていることがわかります。 

これらの各ケースでは、ブロック サイズの計算を超える特別な処理を必要とせずに、小さな n で構築がスムーズに劣化することが確認されています。
