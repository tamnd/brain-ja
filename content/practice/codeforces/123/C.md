 ## 問題の理解

 私たちは満たしています`n × m`ブラケット付きのグリッド。 すべてのセルには次のいずれかが含まれます`"("`または`")"`。 

左上隅から右下隅までのすべての単調パスが正しいブラケット シーケンスを形成している場合、グリッドは有効であると呼ばれます。 単調なパスは右または下にのみ移動します。 

問題の 2 番目の部分では、グリッド間の順序を定義します。 各セルには固有の優先順位があります。`1`に`nm`。 2 つのグリッドを比較するには、優先順位の昇順にセルを検査し、グリッドが異なる最初の位置を見つけます。 グリッドには、`"("`その位置では小さいと見なされます。 

を出力する必要があります。`k`この順序で - 番目の有効なグリッド。 

最初に理解しなければならないのは、有効性条件が実際に何を意味するのかということです。 からのパス`(1,1)`に`(n,m)`常に長さがある`n + m - 1`。 このようなパスはすべて、それ自体が通常のブラケット シーケンスである必要があります。 

通常の括弧シーケンスには 2 つのプロパティがあります。 

1. すべてのプレフィックスには少なくとも同じ数が含まれます`"("`として`")"`。 
2. 総数`"("`の合計数に等しい`")"`。 

すべてのパスの長さは同じであるため、合計の長さは偶数である必要があります。 つまり、`n + m - 1`均等でなければなりません。 奇数の場合は、有効なグリッドが存在しません。 このステートメントは、指定された問題に対する十分な解決策を保証します。`k`したがって、不可能な入力を明示的に処理する必要はありません。 

制約は、強引な列挙を排除するのに十分な大きさです。 グリッドには最大`100 × 100 = 10000`細胞。 全部チェックしても`2^(nm)`グリッドはばかげて不可能です。 の値`k`と同じ大きさにすることができます`10^18`これは、正確な天文学的なカウントではなく、ある上限の値までカウントする必要があるだけであることを強く示唆しています。 

隠された構造特性は、すべての有効なグリッドが対角インデックスによって完全に決定されることです。`i + j`。 

任意のパスを検討してください。 ステップで`t`、パスは常に満たされるセル上にあります。`i + j = t + 2`。 すべてのパスは、各対角線から 1 つのセルに正確にアクセスします。 同じ対角線上の異なるセルに異なる括弧がある場合、2 つのパスがシーケンス内の同じ位置にある異なる括弧を選択する可能性があり、すべてのパスが同時に正しいという要件が破られてしまいます。 

この観察により、問題は 2D グリッドから 1D ブラケット シーケンスに分解されます。 

素朴な推論を打ち破るようなエッジケースがいくつかあります。 

仮定する：```
1 3
```唯一のパスの長さは`3`、これは奇妙です。 奇数の長さの正しい括弧シーケンスは存在しません。 不注意な実装では、依然として次のようなものを生成しようとする可能性があります。`"()("`。 

別の微妙なケースは次のとおりです。```
2 2
```どの道にも長さがある`3`、また無理。 一部の単純な DP 定式化ではパリティ条件を忘れ、誤って無効な状態をカウントします。 

さらに興味深い例は次のとおりです。```
2 3

```2 番目の対角括弧が混合されている場合、2 つのパスにより異なる 2 番目の文字が生成されます。 一方が他方より早く無効になる可能性があります。 対角線全体の均一性はオプションではなく、条件によって強制されます。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 すべて列挙する`2^(nm)`グリッド、すべてのモノトーン パスが規則的なブラケット シーケンスを形成しているかどうかを確認し、有効なグリッドをすべて収集し、カスタムの優先順位を使用して並べ替えて、`k`- 番目のもの。 

1 つのグリッドをチェックするには、すべての単調パスを調べる必要があります。 そのようなパスの数は次のとおりです。$$\binom{n+m-2}{n-1}$$のために`100 × 100`この数字は天文学的な数字です。 グリッドの数を考慮する前に、検証自体が不可能です。 

重要な観察は、すべてのパスがそれぞれの対角線から 1 つのセルに正確にアクセスすることです。 させて：$$d = i + j$$すべてのセルが同じ`d`すべてのパスで同じ位置に表示されます。 

次に、同じ対角線上の 2 つのセルに異なる括弧が含まれているとします。 この場合、2 つの異なるパスにより、同じシーケンス位置に異なる文字が生成される可能性があります。 あるシーケンスはブラケットバランスに違反する可能性がありますが、別のシーケンスは違反しない可能性があります。 すべてのパスが常に正しくなる唯一の方法は、同じ対角線上のすべてのセルに同じ括弧が含まれることです。 

これにより問題は完全に変わります。 

ブラケットを個別に選択するのではなく、`nm`セルでは、対角線ごとにブラケットを 1 つだけ選択します。 正確には次のとおりです。$$n + m - 1$$反対角なので、グリッド全体がその長さの単一の括弧シーケンスに対応します。 

条件ははるかに単純になりました。 すべてのパスはまったく同じシーケンスを読み取ります。 グリッドは、そのシーケンスが通常の括弧シーケンスである場合にのみ有効です。 

カスタムオーダーも管理しやすくなります。 各対角線には、異なる優先順位を持つ複数のセルが含まれています。 対角線の最も古い比較ポイントは、単にその対角線内の最小優先度です。 したがって、これらの最小優先順位に従って反対角を並べ替え、その順序で括弧シーケンスを比較できます。 

この時点で、問題は次のようになります。 

1. 対角線の順序を構築します。 
2. を見つけます。`k`-そのカスタム位置順序の下での 番目の通常の括弧シーケンス。 
3. すべての対角線を均一に塗りつぶします。 

貪欲に答えを組み立てることができます。 比較順序の各ステップで、`"("`。 有効な補完がいくつ存在するかを数えます。 その数が少なくとも`k`、 保つ`"("`。 それ以外の場合は、からカウントを減算します。`k`そして場所`")"`。 

カウンティング DP は、バランス状態を備えた標準ブラケット シーケンス DP です。

 ## アルゴリズムのチュートリアル

 1. 対角線の数を計算します。 

対角線には次のインデックスが付けられます。$$s = i + j$$からの範囲`2`に`n + m`。 
2. それぞれの対角線について、その最小優先度を計算します。 

同じ対角線上のすべてのセルは同じ括弧を共有する必要があるため、対角間の比較順序は、各対角の内側に表示される最小の優先順位によって決まります。 
3. これらの最小優先順位に従って対角線を並べ替えます。 

これにより、問題で使用される正確な辞書編集順序が得られます。 
4. しましょう`L = n + m - 1`。 

これは、すべてのパス シーケンスの長さです。 通常のブラケットシーケンスは偶数の長さでなければならないため、`L`均等でなければなりません。 
5. DP テーブルを構築します。 

させて：$$dp[pos][bal]$$からのポジションを終了する有効な方法の数になります。`pos`現在の残高が`bal`。 

バランスとは次のことを意味します。$$\#("(") - \#(")")$$すでに使用されています。 
6. DP を逆方向に充填します。 

最後に：$$dp[L][0] = 1$$他のすべての期末残高は無効です。 

位置ごとに追加してみます`"("`または`")"`マイナス残高は決して許さない。 
7. 優先順位に従って貪欲に答えを組み立てます。 

ソートされた順序での各対角線について:

 1.仮置き`"("`。 
2. 有効な完了がいくつ残っているかを数えます。 
3. カウントが少なくとも`k`、 保つ`"("`。 
4. それ以外の場合は、カウントをから減算します。`k`そして場所`")"`。 

これは、カウントを使用した標準的な辞書編集方式の生成です。 
8. 各対角のブラケットを決定したら、グリッドを埋めます。 

あらゆる細胞`(i,j)`対角線に割り当てられた括弧を受け取ります`i+j`。 

### なぜ効果があるのか

 すべての単調パスは、各対角線から対角線の昇順で 1 つのセルに正確にアクセスします。 対角線に括弧が混在している場合、2 つのパスにより同じシーケンス位置に異なるシンボルが生成される可能性があります。 その場合、正しさはパスの選択に依存することになり、すべてのパスが正しくなければならないという要件に矛盾します。 

したがって、すべての有効なグリッドは、対角線上の 1 つのブラケット シーケンスに一意に対応します。 

最初の異なるセルは最小優先度が最も早く現れる対角線に属している必要があるため、グリッド間の順序も正しく減少します。 

DP は、特定のプレフィックスを拡張する通常のブラケット シーケンスの数を正確にカウントします。 貪欲な構造では、十分な補完が残っている場合は常に、辞書編集上可能な限り最小の文字が選択されるため、生成されるシーケンスは正確に`k`- 番目のもの。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    n, m, k = map(int, input().split())

    p = [list(map(int, input().split())) for _ in range(n)]

    L = n + m - 1

    # minimum priority for each anti-diagonal
    diag_min = [10**18] * (L + 2)

    for i in range(n):
        for j in range(m):
            s = i + j
            diag_min[s] = min(diag_min[s], p[i][j])

    # order of diagonals in comparison
    order = sorted(range(L), key=lambda x: diag_min[x])

    # dp[pos][bal]
    dp = [[0] * (L + 2) for _ in range(L + 1)]
    dp[L][0] = 1

    for pos in range(L - 1, -1, -1):
        rem = L - pos

        for bal in range(L + 1):
            val = 0

            # place '('
            if bal + 1 <= L:
                val += dp[pos + 1][bal + 1]

            # place ')'
            if bal > 0:
                val += dp[pos + 1][bal - 1]

            dp[pos][bal] = min(val, INF)

    ans_diag = ['?'] * L

    assigned = [None] * L

    # map diagonal -> sequence position
    pos_of_diag = [0] * L
    for idx, d in enumerate(order):
        pos_of_diag[d] = idx

    seq = ['?'] * L

    balance = 0

    for pos in range(L):
        # try '('
        remain_count = 0

        if balance + 1 <= L:
            remain_count = dp[pos + 1][balance + 1]

        if remain_count >= k:
            seq[pos] = '('
            balance += 1
        else:
            k -= remain_count
            seq[pos] = ')'
            balance -= 1

    # assign brackets to diagonals
    for d in range(L):
        ans_diag[d] = seq[pos_of_diag[d]]

    out = []

    for i in range(n):
        row = []
        for j in range(m):
            row.append(ans_diag[i + j])
        out.append(''.join(row))

    print('\n'.join(out))

solve()
```最初の部分では、各対角線内の最小優先度を計算します。 この値によって、対角線が 2 つのグリッド間の比較にいつ参加するかが決まります。 

微妙な点は、比較順序が自然な対角順序ではないことです。 最初の異なるセルによって順序が決定されるため、対角線を最小の含まれる優先度で並べ替える必要があります。 

DP は、古典的なバランス ブラケット シーケンス DP です。`dp[pos][bal]`処理後に可能なサフィックスの数を保存します`pos`現在の残高のあるキャラクター`bal`。 

カウントの上限は次のとおりです`10^18`なぜなら、この問題では大きな値が区別されないからです。 キャップがないと、固定幅の整数を使用する言語はオーバーフローしてしまいます。 Python の整数は任意の精度ですが、キャップによって値が管理しやすくなり、意図したロジックが反映されます。 

貪欲な構築は辞書編集的な生成です。 まず置くかどうかをテストします`"("`少なくともまだ残っています`k`有効な補完。 「はい」の場合は、そのまま保管します。 それ以外の場合は、これらのシーケンスがすべて前に来るため、それらを差し引いて選択します。`")"`。 

簡単な間違いの 1 つは、シーケンスの位置が幾何学的対角インデックスではなく、対角優先度によって順序付けされていることを忘れることです。 配列`pos_of_diag`この変換を処理します。 

もう 1 つの簡単なバグは、建設中にマイナスの残高が許可されてしまうことです。 このようなプレフィックスは有効なブラケット シーケンスになることはありません。
