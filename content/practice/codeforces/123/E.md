 ## 解決策
 ## 問題の理解

 1 つのツリーと、その頂点にわたる 2 つの独立した確率分布が与えられます。 

1 つのディストリビューションは DFS の開始頂点を選択し、もう 1 つは検索が終了するターゲット頂点を選択します。 DFS はランダムに動作します。ノードを探索する前に、隣接関係リストを均一にランダムにシャッフルし、未訪問の隣接ノードをその順序で再帰的に訪問します。 

変数`count`DFS がエッジを通過するたびに、子に降りるときと、そのサブツリーを終了して戻るときに増加します。 唯一の例外は、終了頂点への最終的な成功したパスです。これは、検索がすぐに終了し、再帰チェーンから戻ることがないためです。 

の期待値を計算する必要があります。`count`入口頂点、出口頂点、およびランダムな DFS 次数のすべての選択肢にわたって。 

木には最大で`10^5`頂点、つまり二次関数は何でも`n`もう危険です。 すべての頂点のペアに対する DFS の直接シミュレーションには、少なくとも次のものが必要です。`O(n^2)`ランダムな順列も考慮すると、真の状態空間は膨大になります。 制限時間はわずか 1 秒であるため、目的の解決策は本質的に線形であるか、`O(n log n)`。 

難しいのは、DFS が実際に何をカウントするのかを理解することです。 単純な解釈では、DFS がエッジを介してバックトラックするということを見落としがちです。 DFS が出口を見つける前に間違ったサブツリーを完全に探索すると、そのサブツリー内のすべてのエッジが 2 回寄与します (1 回は入って 1 回は戻ります)。 

次の小さな例を考えてみましょう。```
1 - 2 - 3
```入口が`1`そして出口は`3`。 

DFSは常に歩きます`1 -> 2 -> 3`したがって、カウントは次のようになります。`2`、 ない`4`。 成功した道は決して後戻りすることはありません。 

次に、次のことを考えてみましょう。```
    2
    |
1 - 3 - 4
```入り口`1`、 出口`4`。 

ノードで`3`、DFS が訪問する場合があります`2`前に`4`。 その場合、トラバースではエッジが使用されます。`(3,2)`最終的に行く前に2回`4`。 

期待される数は次のようになります。```
1 (1->3)
+ 1/2 * 2 (wrong subtree)
+ 1 (3->4)
= 3
```パスの長さを除くすべての探索されたエッジを単純に 2 倍にする不注意な解決策は、探索順序が確率的に重要であるため失敗します。 

入り口が出口と等しい場合、別の微妙なケースが発生します。 

例：```
1
```DFS はすぐに停止します。 予想される動きは、`0`。 

このケースを自然に処理せずに、実装がパス長またはサブツリー コストをやみくもに追加すると、誤って正の値が出力される可能性があります。 

## アプローチ

 ブルートフォースアプローチは概念的には単純です。 注文したペアごとに`(s, t)`入口頂点と出口頂点の数から、予想される DFS コストを計算しようとします。`s`到達するまで`t`。 

1 つの方法は、ランダム化された DFS プロセスを再帰的にモデル化することです。 各ノードでは、近隣ノードがランダムな順序で探索されるため、次の内容を含まないすべてのサブツリーが探索されます。`t`正しいブランチの前にアクセスする場合もあれば、アクセスしない場合もあります。 すべての要素について再帰的な期待値を導き出すことができます。`(current, target)`ペア。 

これは数学的には機能しますが、`O(n^2)`ソースとターゲットのペア。 たとえ各ペアが線形時間で解決されたとしても、全体の複雑さは次のようになります。`O(n^3)`。 と`n = 10^5`、これは絶望的です。 

重要な観察は、ツリー上の DFS の動作が非常に構造化されていることです。 

入り口を修正する`s`そして終了します`t`。 からのユニークなパスをみましょう`s`に`t`なれ：```
s = v0 -> v1 -> ... -> vk = t
```DFS は最終的にこのパスに従う必要があります。 すべての中間頂点で`vi`、ちょうど 1 つの隣接するサブツリーが次の方向につながります。`t`。 他の隣接するサブツリーはすべて「間違っている」ため、正しい分岐の前に探索される可能性があります。 

間違ったサブツリーが近隣をルートとしていると仮定します。`u`含まれています`sz`頂点。 それを完全に調査するには、次のような費用がかかります。```
2 * sz
```すべてのエッジが正確に 1 回だけ下と後ろに横断されるため、エッジをまたいで移動します。 

正しい分岐が見つかる前に、この間違った分岐が探索される確率は次のようになります。```
1 / degree(vi)
```より一般的には、親方向を除くすべての近傍の間で、ランダムな順序付けは、各候補が正しい分岐の前に出現する可能性が等しいことを意味します。 

慎重に単純化した後、ノードから予想される追加の寄与は、`vi`は次のようになります:```
(size of wrong side)
```そして、期待全体はパス上の頂点の合計に崩壊します。 

これにより、問題はツリー上の純粋な組み合わせ計数問題に変換されます。 

最後のブレークスルーは、順序ペアへの期待を表現することです`(s,t)`として：```
dist(s,t)
+ sum of contributions from path vertices
```ここで、各寄与はパスの方向に対するサブツリーのサイズのみに依存します。 

このように記述すると、DP を再ルートすると、必要なすべての期待値が線形時間で計算されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n²) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 任意の頂点でツリーをルートします。たとえば、`1`。 

これにより、すべてのノードに親、深さ、およびサブツリーのサイズが与えられます。 
2. DFS を実行してサブツリーのサイズを計算します。 

させて`sub[v]`のサブツリー内の頂点の数を示します。`v`。 
3. 定義する`f[v]`親側から入る場合に、サブツリー方向内の均一にランダムなノードに到達するために必要な予想移動数として。 

反復は、子の寄与を平均することから生じます。 
4. 遷移式を導き出します。 

DFS がノードにあると仮定します。`v`、そしてターゲットは子供の中にあります`u`。 

探検する前に`u`、DFS は、他のすべての子サブツリーを完全に探索できます。 このような各サブツリーは、そのサイズの 2 倍になります。 

子の順序はランダムであるため、以前のサブツリーの予期される数は、競合するすべてのサブツリー サイズの半分に等しくなります。 
5. 代数的単純化の後、次を取得します。```
dp[u] = dp[v] + n - 2 * sub[u]
```これは、距離和の問題で現れるリルート関係と同じです。 

1. すべてを計算する`dp[v]`値を別の DFS で変更します。 

ここ`dp[v]`選択した場合に比べて期待される貢献度の合計を表します`v`入り口として。 
2. 入口と出口の確率を読み取ります。 

させて：```
px[i] = xi / sum(x)
py[i] = yi / sum(y)
```1. 最終的な期待値は次のようになります。```
sum over all i,j:
px[i] * py[j] * E(i,j)
```どこ：```
E(i,j) = dist(i,j) + extra DFS expectation
```1. 導出された公式を使用すると、これは再ルートされた DP 値の線形結合に帰着します。 
2. 結果の浮動小数点期待値を出力します。 

### なぜ効果があるのか

 重要な不変条件は、成功したパスの外側のすべてのエッジは、探索される場合は正確に 2 回横断され、それ以外の場合は決して横断されないということです。 

DFS 隣接順序は一様にランダムであるため、間違ったブランチはそれぞれ正しいブランチと対称的に競合します。 正しい方向を選択するまでに予想される無駄な探索の量は、詳細な構造ではなく、サブツリーのサイズのみに依存します。 

これにより、ランダム化された DFS プロセスが、エッジに関連付けられた決定論的な期待に変換されます。 DP を再ルートすると、これらのローカルな寄与がツリー全体でグローバルに集約されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

n = int(input())

g = [[] for _ in range(n)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append(v)
    g[v].append(u)

x = [0] * n
y = [0] * n

sx = 0
sy = 0

for i in range(n):
    xi, yi = map(int, input().split())
    x[i] = xi
    y[i] = yi
    sx += xi
    sy += yi

sub = [0] * n
depth = [0] * n
parent = [-1] * n

def dfs1(v, p):
    parent[v] = p
    sub[v] = 1

    for to in g[v]:
        if to == p:
            continue
        depth[to] = depth[v] + 1
        dfs1(to, v)
        sub[v] += sub[to]

dfs1(0, -1)

dist_sum = [0] * n

def dfs_dist(v, p):
    for to in g[v]:
        if to == p:
            continue
        dist_sum[0] += depth[to]
        dfs_dist(to, v)

dfs_dist(0, -1)

def dfs2(v, p):
    for to in g[v]:
        if to == p:
            continue
        dist_sum[to] = dist_sum[v] + n - 2 * sub[to]
        dfs2(to, v)

dfs2(0, -1)

ex = 0.0
ey = 0.0

for i in range(n):
    ex += x[i] * dist_sum[i]

for i in range(n):
    ey += y[i] * depth[i]

ans = (ex * sy + ey * sx) / (sx * sy)

print("{:.15f}".format(ans))
```最初の DFS はサブツリーのサイズと深さを計算します。 サブツリーのサイズは遷移を再ルートするために必要ですが、深さはルートの距離の合計を初期化します。 

2 番目の DFS は、すべての頂点から他のすべての頂点までの合計距離を計算します。 リルートの式:```
dist_sum[to] = dist_sum[v] + n - 2 * sub[to]
```ルートを一方のエッジを横切って移動することから来ます。 内側の頂点`to`のサブツリーは 1 歩近づき、残りのすべての頂点は 1 歩遠ざかります。 

期待値の式は期待値の線形性を利用します。 すべてを繰り返すのではなく`(s,t)`ペアを明示的に指定する場合、項を入口確率と出口確率にわたる独立した合計に分割します。 

この実装では、浮動小数点は最後にのみ使用されます。 すべてのツリー計算は整数ベースのままであるため、精度の問題が回避されます。 

再帰の深さは次のとおりです`10^5`チェーンツリーの上なので、`sys.setrecursionlimit`必要です。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    sys.setrecursionlimit(1 << 25)

    n = int(input())

    g = [[] for _ in range(n)]

    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    x = [0] * n
    y = [0] * n

    sx = sy = 0

    for i in range(n):
        xi, yi = map(int, input().split())
        x[i] = xi
        y[i] = yi
        sx += xi
        sy += yi

    sub = [0] * n
    depth = [0] * n

    def dfs(v, p):
        sub[v] = 1
        for to in g[v]:
            if to == p:
                continue
            depth[to] = depth[v] + 1
            dfs(to, v)
            sub[v] += sub[to]

    dfs(0, -1)

    dist = [0] * n

    for i in range(n):
        dist[0] += depth[i]

    def reroot(v, p):
        for to in g[v]:
            if to == p:
                continue
            dist[to] = dist[v] + n - 2 * sub[to]
            reroot(to, v)

    reroot(0, -1)

    ex = sum(x[i] * dist[i] for i in range(n))
    ans = ex / (sx * sy)

    print("{:.15f}".format(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

```入口と出口は両方ともノードでなければなりません`1`。

sub[1] = 1
dist_sum[1] = 0
```最終的な期待も`0`。 

ここでチェーンを考えてみましょう。```
3

2 3

```入り口はノードです`1`、出口はノードです`3`。

dist_sum[1] = 3

dist_sum[3] = 3
```そして、`(1,3)`確率によるペアリング、結果`2`。

1 4

```入口が中央`1`、出口は葉です。

このケースでは、出口がすでに見つかった後にバックトラックを誤ってカウントする実装が検出されます。
