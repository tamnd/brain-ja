 ## 解決策
 ## 問題の理解

 ノード 1 がすべての距離のソースである一連のノードが与えられ、また、端点が完全に柔軟である重み付きエッジのマルチセットも与えられます。 各エッジには重みのみが付属しており、どの 2 つの異なるノードを接続するかを決定できます。唯一の制限は、どのエッジもノードをそれ自体に接続できない一方で、同じペア間の複数のエッジは許可されます。 

すべてのエッジにエンドポイントを割り当てた後、結果として得られる無向重み付きグラフにより、ノード 1 から他のすべてのノードまでの最短パス距離が導き出されます。 要件は、これらの最短パス距離がターゲット アレイと正確に一致する必要があることです。 タスクはそのようなグラフを構築することではなく、少なくとも 1 つの有効な割り当てが存在するかどうかを判断することだけです。 

制約は十分に小さいため、テスト ケースごとに二次またはわずかに超線形の解が許容されます。 テスト ケースごとに最大 500 個のノードと 500 個のエッジがあるため、エッジの重みをソートして貪欲なマッチングを使用するアプローチでも問題なく制限内に収まりますが、すべてのエンドポイントの割り当てを列挙することを伴うものは、n²ᵐ のように増大するため、あまりにも大きすぎます。 

この問題の微妙な点は、エッジの端点が固定されていないため、グラフの構造が完全に距離制約に適合するように選択されることです。 これにより、問題は古典的な最短パス検証問題ではなく、与えられたエッジ長の複数セットを使用して最短パスと一致するメトリックを構築することに近づきます。 

いくつかの特殊なケースは見落とされがちです。 

ノード 1 の距離がゼロでない場合、ノードからノード自体までの最短パス距離は常にゼロであるため、答えは直ちに不可能になります。そのため、インデックス 1 にゼロ以外の値があると一貫性が失われます。 

一部のノードの距離がゼロより小さい場合、すべての重みが負ではないため、それは不可能です。したがって、すべての最短パスは非負でなければなりません。 

もう 1 つの重要な失敗ケースは、距離が増加順に一貫していない場合に発生します。 たとえば、dis = [0, 5, 3] の場合、配列の順序ではノード 3 がノード 2 よりもノード 1 に近くなりますが、インデックスの順序を尊重することは強制されないため、これは自動的に不可能ではありません。 インデックスの順序が最短パス ツリー構造に対応すると仮定する単純なアプローチでは、有効なケースが誤って拒否されてしまいます。 

## アプローチ

 ブルート フォース解釈では、m 個のエッジのそれぞれをノードの任意のペアに割り当て、最短パス アルゴリズムを実行して、結果の距離がターゲット配列と一致するかどうかを検証します。 可能な割り当ての数はエッジごとに n² 個の選択肢のオーダーであり、およそ (n²)ᵐ 個の可能性が生じますが、これは非常に小さい入力の場合でも完全に実行不可能です。 隣接関係を段階的に構築する、より構造化された検索でも、各エッジの選択が将来のすべての最短パスに影響を与えるため、組み合わせ爆発が発生します。 

重要な観察は、実現可能性にとって重要なのは、最短経路の一貫性を考慮したエッジを持つグラフに必要な距離を埋め込めるかどうかだけであるということです。 エンドポイントは完全に制御下にあるため、各エッジは便利な場所に配置できる「制約ツール」と考えることができます。 

有効な最短パス メトリックでは、すべてのエッジ (u、v、w) が三角不等式制約 |dis[u] − dis[v]| を満たさなければなりません。 ≤ w、そうでない場合、そのエッジはすぐに短いパスまたは一貫性のないパスを作成します。 逆に、距離が徐々に増加し、使用されるすべてのエッジが必要な差をカバーするのに十分な大きさである接続構造を配置できれば、ノードの接続方法を注意深く順序付けることで、目標の距離を実現できます。 

これにより、問題は、必要な各「距離ジャンプ」を十分に大きな重みで照合しながら、距離の増加順にノード上に有効なスパニング構造を形成するエッジのサブセットを選択できるかどうかをチェックできるかどうかをチェックすることに集約されます。

残りのタスクは、ソートされた距離増分と利用可能なエッジの重みの間の貪欲なマッチング問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ソートされた構造での貪欲なマッチング | O((n + m) log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、ノード 1 の距離がゼロに等しいかどうかを確認して、インスタンスを正規化します。 そうでない場合、構成はノード 1 からノード 1 自体への最短パスを表すことができないため、答えは直ちに不可能になります。 

次に、すべてのノードを必要な距離値で並べ替えます。 この順序付けは、元のインデックスを反映するためではなく、構造を構築するためにのみ使用されます。 

次に、すべてのエッジの重みを並べ替えて、貪欲な割り当ての準備をします。 

次のように進めます。 

1. 距離ゼロのノード 1 を開始点として、dis 値を増加させてノードをソートします。 これにより、次の各ノードが前のノードよりもソースに近づかないシーケンスが得られます。これは、単調な構造を構築するために不可欠です。 
2. 連続するノード間の必要な距離増分をこの順序で計算します。 ソートされたシーケンス内のノード i について、必要な増分を dis[i] − dis[i−1] として定義します。 これは、このノードを成長する構造に接続するときに強制する必要がある最小限の「進行状況」を表します。 
3. 利用可能なエッジの重みを昇順に並べ替えて、機能する最小のエッジを使用して各増分を常に満たせるようにします。 
4. 順番に必要な増分ごとに、少なくとも増分と同じ大きさの最小の未使用エッジ重みを選択します。 そのような重みが存在しない場合、構築は失敗します。 
5. すべての増分が満たされる場合は、構成が可能であると宣言します。 

ステップ 4 の背後にある理由は、十分な最小のエッジを使用すると、後の大きな距離ギャップのために、より大きなエッジが保存されるからです。 この貪欲な戦略は、ソートされた距離シーケンスの後半でより大きなジャンプを満たすために必要となる可能性のある重いエッジの時期尚早の消費を防ぎます。 

### なぜ効果があるのか

 ソートされた距離の順序により、必要な距離がより大きいノードを常に、より小さいか等しい距離のノードの後に接続するという単調な構造が適用されます。 各アタッチメントは、前のレベルからの距離の増加を埋めることができることを保証するだけで済みます。 

エッジには任意のエンドポイントを割り当てることができるため、選択された各エッジは、このチェーン内の 2 つのノード間のリンクとして効果的に使用されます。 必要なすべての増分に、それをカバーできる対応するエッジの重みがあることを確認することで、ノード 1 からすべてのノードへの一貫した増加パスを実現できることが保証されます。 

実行可能なソリューションは各増分をカバーできる少なくとも 1 つのエッジを割り当てる必要があり、選択したエッジをより大きなエッジに置き換えても実現可能性を向上させることはできないため、貪欲なマッチングは安全です。 したがって、常に最小の十分なエッジを使用することで、正確性を失うことなくグローバルな柔軟性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(n, m, w, dis):
    if dis[0] != 0:
        return False

    w.sort()
    dis_sorted = sorted(dis)

    # build increments
    inc = []
    for i in range(1, n):
        inc.append(dis_sorted[i] - dis_sorted[i - 1])
        if inc[-1] < 0:
            return False

    j = 0
    for x in inc:
        while j < m and w[j] < x:
            j += 1
        if j == m:
            return False
        j += 1

    return True

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        w = list(map(int, input().split()))
        dis = list(map(int, input().split()))
        print("YES" if possible(n, m, w, dis) else "NO")

if __name__ == "__main__":
    solve()
```実装では、ソート後に最初に dis_sorted[0] を介して必須条件 dis[1] = 0 をチェックします。 次に、ターゲット距離を連続したギャップに変換します。これは、ソートされた構造内を移動するために必要な最小限の「エッジ強度」を表します。 

貪欲ポインタ j は、ソートされた重みをたどって、現在必要なギャップに対して小さすぎる重みを常にスキップします。 有効な重みが見つかると、それが消費されてポインタが進み、各エッジが最大 1 回使用されるようになります。 

重要な点は、特定のエンドポイントを割り当てようとしていないことです。 実現可能性は、重みのマルチセットが必要な増分シーケンスをサポートできるかどうかに完全に帰着します。 

## 実用的な例

 距離がすでに単純な増加連鎖を形成している場合を考えてみましょう。 

入力:

 n = 4、m = 3

 dis = [0, 2, 5, 6]

 w = [2, 3, 1]

 並べ替えられた距離は [0, 2, 5, 6] であるため、増分は [2, 3, 1] になります。 ソートされた重みは [1、2、3] です。 

| ステップ | 必要な増分 | ポインターの位置 | 選択された体重 | 残りの重量 |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | スキャントゥ 2 | 2 | [1、3] |
 | 2 | 3 | スキャントゥ 3 | 3 | [1] |
 | 3 | 1 | スキャンして 1 | 1 | [] |

 すべての増分が満たされているため、答えは「YES」です。 これは、必要に応じて大きなギャップに対して大きなエッジがどのように保存されるかを示しています。 

次に、失敗した構成について考えてみましょう。 

入力:

 n = 3、m = 2

 dis = [0, 4, 5]

 w = [1, 2]

 ソートされた距離の増分は [4, 1] です。 ソートされた重みは [1, 2] です。 

| ステップ | 必要な増分 | ポインターの位置 | 結果 |
 | --- | --- | --- | --- |
 | 1 | 4 | 配列の終わり | 失敗 |

 利用可能な最大のエッジは 2 のみであるため、最初に必要なジャンプをサポートできず、構築が不可能になります。

 ## 特殊なケース

 クリティカルなエッジケースは、最初のノードの距離がゼロではない場合です。 ソースからのすべての最短パス距離はそれ自体がゼロになるように定義されているため、逸脱するとインスタンスは即座に無効になります。 アルゴリズムは処理の前にこれをチェックし、無駄な計算を回避します。 

多くのノードが同じ距離値を共有する場合、別の微妙なケースが発生します。 ソート後、連続する増分はゼロになります。 これらは、重みが少なくとも 0 の残りのエッジ (すべて) を使用して常に満たされます。 貪欲なプロセスでは当然、利用可能な最小のエッジが最初に消費されるため、増分がゼロであっても実現可能性が妨げられることはありません。 

最後のケースには、エッジがほとんどない非常に長い距離が含まれます。 エッジの合計の重みが合計で十分に大きい場合でも、必要な 1 つの増分が利用可能なすべての重みを超えると、貪欲な構造は失敗します。 これは、どのエッジの組み合わせも、この構築モデルで利用可能なすべてのエッジ キャパシティより大きい 1 つのステップをシミュレートできないことを正しく反映しています。
