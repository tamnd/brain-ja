 ## 解決策
 ## 問題の理解

 私たちは、「状態」が 0 から n までの整数値である単一のクリーチャーを制御しています。 状態 0 から開始して、最終的に状態 n に到達したいと考えています。 

助っ人生き物を販売する店がある。 価値 i のヘルパーを購入するには ai がかかり、i ごとに無制限に供給されます。 ヘルパーを購入したら、すぐにそれを現在のクリーチャーとマージします。 

現在の値が x で、それを値 y の購入したヘルパーとマージした場合、結果は決定的ではありません。 新しい値は、x と y の間の完全な整数間隔から選択された一様にランダムな整数になります。 したがって、遷移範囲は [min(x, y), max(x, y)] で、内部のすべての整数の可能性は同等です。 

各操作は、ヘルパー値の選択、そのコストの支払い、およびこのランダム化されたマージの実行で構成されます。 現在の値が n になるまでこれを繰り返すことができます。 タスクは、0 から開始して値 n に到達するまでの予想総コストを最小化することです。 

重要な点は、すべてのアクションによって状態が多くの状態にわたる分布に変化するため、コストは意思決定を伴う確率的プロセスに対する予想コストになるということです。 

n ≤ 5000 という制約は、O(n²) または O(n² log n) 動的プログラミング アプローチが意図されていることを示しています。 状態と遷移に対する 3 つのネストされたループを含むものはどれも遅すぎますが、O(1) 遷移評価による 2 次遷移は許容されます。 

微妙なエッジ ケースは、選択したヘルパー値が現在の値と等しい場合です。 その場合、間隔は単一点に崩壊するため、状態は変化しません。 このアクションは、進歩がなくコストが追加されるだけであるため、常に厳密には最適ではありませんが、依然として意思決定スペースに表示され、反復ロジックを壊してはなりません。 

もう 1 つの重要な点は、すべての遷移が DP 値の間隔にわたる平均に依存することです。 これらの間隔の合計が毎回素朴に再計算されると、解は三次になり、合格しなくなります。 

## アプローチ

 このプロセスを直接考える方法は、各値 x から予想される残りのコストを定義することです。 状態 x から開始して n に到達するまでの最小予想コストを表す関数 E[x] がわかっているとします。 状態 x から、考えられるすべてのヘルパー値 y を試します。 すぐに ay を支払い、その後 x と y の間で均一にランダムな状態に移行します。 予想される将来のコストは、その間隔にわたる E の平均です。 

これにより、各選択肢 y が y の期待コストに、一定期間にわたる E の平均を加えたものとなる反復が得られます。 ブルート フォース法では、すべての x とすべての y についてこれを評価し、各ペアについてすべての要素をスキャンして間隔平均を計算します。 これにより、O(n³) 時間がかかります。つまり、n 個の状態、n 個の選択肢、および各平均の計算に O(n) が必要になります。 n が最大 5000 であるため、これは実現可能な限界をはるかに超えています。 

重要な観察は、コストがかかる部分は E に対して繰り返される範囲合計クエリだけであるということです。より大きな状態について E が判明すると、プレフィックス合計を使用してすべての間隔平均を O(1) で答えることができます。 これにより、各遷移の評価が定数時間に短縮され、解が二次動的プログラムに変わります。 E[x] は、すでに計算された値を含むより大きな状態と混合区間の E に依存するため、このプロセスは自然に大きな値から小さな値まで機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n) | 遅すぎる |
 | プレフィックス合計を使用した最適な DP | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 E[x] を、x から開始して状態 n に到達するために必要な最小予想コストとして定義します。 また、プレフィックス合計配列 S も維持します。S[i] には E[0] から E[i] までの合計が格納されます。これにより、間隔平均を一定時間で計算できます。 

n から 0 まで x の降順で値を計算するので、E[x] を評価するときに、必要なより大きな状態がすべてすでにわかっていることがわかります。

1. 目標に到達すると、それ以上のコストは必要ないため、E[n] = 0 に設定します。 
2. プレフィックス合計配列 S を維持します。ここで、E[i] を計算した後、S[i] = S[i-1] + E[i] を更新します。 この構造により、任意の間隔にわたって合計を高速に計算できます。 
3. n-1 から 0 までの各状態 x について、0 から n までのすべての可能なヘルパー選択肢 y を評価します。 各選択肢は区間 [l, r] を定義します。ここで、l = min(x, y) および r = max(x, y) です。 
4. 各 y について、[l, r] にわたる E の平均として予想される次の状態コストを計算します。 接頭辞の合計を使用すると、これは (S[r] - S[l-1]) / (r - l + 1) となります。 y を選択するための総コストは、y にこの期待値を加えたものです。 
5. すべての y の最小値を取得し、それを E[x] に割り当てます。 
6. E[x] が終了したら、x-1 に移動する前にプレフィックス合計配列を更新します。 

これが機能する理由は、選択 y を修正すると、マージ後のプロセスが結果の値を除く以前の状態のメモリをすべて失うためです。 これにより、問題は純粋なマルコフ決定プロセスとなり、最適性は現在の値のみに依存します。 DP が有効なのは、すべての移行コストが即時支払いと次の状態に対する線形期待にきれいに分解され、それらの期待が以前に計算された E 値によって完全に決定されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n_and_rest = list(map(int, sys.stdin.read().split()))
    n = n_and_rest[0]
    a = n_and_rest[1:]
    
    if n == 0:
        print("0.000000")
        return

    E = [0.0] * (n + 1)
    S = [0.0] * (n + 1)

    E[n] = 0.0
    S[n] = 0.0

    for x in range(n - 1, -1, -1):
        best = float('inf')

        for y in range(0, n + 1):
            l = x if x < y else y
            r = y if x < y else x

            length = r - l + 1
            interval_sum = S[r] - (S[l - 1] if l > 0 else 0.0)
            expected_next = interval_sum / length

            cost = a[y] + expected_next
            if cost < best:
                best = cost

        E[x] = best
        S[x] = S[x + 1] + E[x] if x < n else E[x]

    print(f"{E[0]:.10f}")

if __name__ == "__main__":
    solve()
```コードは DP 定義に直接準拠しています。 配列 E は各状態からの最適な予想コストを格納しますが、S は高速な間隔合計をサポートすることを目的としています。 各状態 x は、より大きなインデックスがすべて完了した後に計算され、期待値で使用されるすべての間隔がすでに計算された値または安定した値のみを参照することが保証されます。 

よくある落とし穴は、プレフィックス合計配列を誤って更新することです。 E を n から 0 まで埋めるため、プレフィックスの合計は、選択した順序で一貫して再構築する必要があります。 もう 1 つの微妙な点は、二次関数の複雑さを破壊するループ内での区間和の再計算を回避することです。 

## 実用的な例

 ### 例 1

 n = 3、コスト a = [1, 10, 1, 100] の小さなインスタンスを考えてみましょう。 その考えは、たとえランダム性によって価値が分散されたとしても、安価なエンドポイントはそこに飛びつくことを促すということです。 

E を 3 → 0 の順序で計算します。 

| × | y | を考えてみましょう。 間隔 | 平均E | コスト a[y] + 平均 | E[x] |
 | --- | --- | --- | --- | --- | --- |
 | 3 | - | - | - | 0 | 0 |
 | 2 | 3 | [2,3] | (E[2]+0)/2 | 100+小 | すべての中で最高 |
 | 2 | 0 | [0,2] | avg(E[0..2]) | 1 + 平均 | 分 |
 | 1 | 3 | [1,3] | avg(E[1..3]) | 100 + 平均 | |
 | 1 | 0 | [0,1] | avg(E[0..1]) | 1 + 平均 | |
 | 0 | すべてy | [0,y] | avg(E[0..y]) | a[y] + 平均 | E[0] |

 これは、決定が当面のコストと、結果として生じる間隔の「広がり」のバランスによって決定されることを示しています。 安価なエンドポイントは、たとえランダム性が生じてもコストが削減されるため、価値があります。 

### 例 2

 n = 2、a = [5, 1, 5] を考えます。 

状態 1 から y = 1 を選択しても、何の進歩も生じないため、役に立ちません。 y = 0 または y = 2 を選択すると、間隔 [0,1] または [1,2] が作成され、どちらもランダム性が生じますが、動きは可能になります。 

これは、自己遷移が存在するにもかかわらず最適値に影響を与えない理由を示しています。

 ## 特殊なケース

 n = 0 の場合、操作は必要ないため、DP はすぐに 0 を返す必要があります。 アルゴリズムは、配列にアクセスする前にこれを明示的に処理します。 

y が x と等しい場合、間隔は崩壊し、期待される次の状態は E[x] と等しくなります。 計算されたコストは a[x] + E[x] になりますが、これは常に改善する遷移よりも悪いため、最小値に影響を与えることはありません。 

コストが極端に偏っている場合、たとえば非常に安価で高価値のヘルパーの場合、DP は広い間隔を作成する大きなジャンプを好む場合があります。 間隔が広いと平均 E の分散が増加し、これが遷移コストに直接反映されるため、アルゴリズムはこれを自然に捉えます。
