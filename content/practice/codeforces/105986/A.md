 ## 問題の理解

 私たちは限られたスロット数で小規模なチームを構築しており、総攻撃力を最大化したいと考えています。 ユニットには2種類あります。 

1 つのタイプは基本ユニットであり、常に固定の攻撃値に貢献します。$a$。 もう 1 つのタイプは増幅ユニットで、それ自体が 1 攻撃に貢献しますが、すべての基本ユニットの攻撃も増加します。$b$。 アンプ効果はスタックするため、各アンプはすべての基本ユニットを再び増加させます。 

ユニットの総数を超えないように、各ユニットを何個配置するかを選択する必要があります。$n$。 目標は、攻撃値の合計を最大化することです。 

入力により、複数の独立したシナリオが得られます。 各シナリオが提供するのは、$n$、$a$、 そして$b$。 それぞれに対して達成可能な最良の合計攻撃を計算する必要があります。 

制約により、最大で次のことが許可されます。$10^5$テストケースと$n$まで$10^5$。 これにより、テスト ケースごとのユニット数のすべての分布を試行するソリューションは除外されます。 すべての分割に対する 2 次スキャンはすでに遅すぎます。$O(n)$テストケースごとのアプローチは最悪の場合失敗します。 

重要な問題は、アンプがすべての基本ユニットにグローバルに影響を与えるため、アンプの値は選択する基本ユニットの数に依存し、その逆も同様であることです。 各アンプの限界利得は現在の構成に依存するため、「できるだけ多くのアンプを使用する」または「すべての基本機能を使用する」などの単純で貪欲な選択は失敗する可能性があります。 

微妙なエッジケースが現れるのは、$b = 0$。 その場合、アンプは独自の攻撃にのみ貢献し、基本を改善することはありません。そのため、アンプは、状況に応じて、より弱い、または同等の基本ユニットと同等になります。$a$。 もう 1 つのエッジケースは次のような場合です$a = 0$、ここでは値全体がアンプから得られ、それらの相互作用は消えます。 

## アプローチ

 ブルートフォース戦略は、アンプの可能な数をすべて試すことです。 修正するとします$k$アンプを使用したら、残りを使用します$n-k$基本ユニット用のスロット。 この構成では、合計攻撃力を計算するのが簡単です。各基本単位が寄与します。$a + k \cdot b$、各アンプは 1 に寄与します。すべてを評価します。$k$0から$n$。 

このアプローチは、有効な構成をすべて列挙するため、正しいです。 ただし、実行されるテストケースごとに、$O(n)$評価、それぞれの評価は$O(1)$、そうです。$O(n)$テストケースごとに。 まで$10^5$テストケース、これは次のことにつながります$10^{10}$最悪の場合の操作は実行不可能です。 

重要な観察は、目的関数が次の関数であるということです。$k$非常に構造化された方法で直線的です。 固定の合計値を書くと$k$、次のようになります。$$(n-k)(a + kb) + k$$これを展開すると、次の二次式が表示されます。$k$しかし、より重要なのは、増加するときの段階的な変化です。$k$直接分析することができます。 すべてをテストする必要はありません$k$; 代わりに、アンプの数を増やすと結果が改善されるかどうかを確認し、最適値は境界にあります。 

これにより、増分ゲインの符号動作から導出される一定数の候補構成のみを評価するという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 アンプの数を次のように固定します。$k$を計算して合計値式を導出します。 

1. 次の構成を検討します。$k$アンプと$n-k$基本単位。 総攻撃力を次のように計算します。$f(k) = (n-k)(a + kb) + k$。 これは、直接的な貢献と相乗効果の両方を直接エンコードします。 
2. 式を頭の中で拡張して、次の場合にどのように変化するかを理解します。$k$が増加します。 目標は完全な代数的単純化ではなく、アンプをもう 1 つ追加することで合計値が改善されるか減少するかを特定することです。 
3. 構成を比較する$k$そして$k+1$。 違い$f(k+1) - f(k)$アンプの数を増やす必要があるかどうかを決定します。 この差は次の一次関数になります。$k$, したがって、関数は単峰性です。 
4. この関数は整数に対して単峰性であるため、$[0, n]$の場合、最適値は境界の 1 つ、または傾きの符号が変わる点にある必要があります。 これは、一定数の候補をチェックするだけでよいことを意味します$k$限界ゲインが非正になる場所を解くことで得られる値。 
5. これらの候補の中から最良のものを計算し、それを返します。 

機能する理由: アンプの数の関数としての合計値は、整数に対して凹型の二次関数であり、単一のピークを持つことを意味します。 アンプを追加することによる限界利益がプラスでなくなると、再びプラスになることはありません。 これにより、局所最適が大域的になることが保証され、解決策は境界または臨界遷移点の評価に留まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, a, b):
    def value(k):
        return (n - k) * (a + k * b) + k

    # marginal gain threshold derived from concavity:
    # we test candidate region around where adding an amplifier stops being useful
    best = 0

    # check boundaries explicitly
    for k in (0, n):
        best = max(best, value(k))

    # check potential interior optimum near derivative zero
    # derivative approximation leads to k ≈ (a - 1) / (2b) when b > 0
    if b > 0:
        k = (a - 1) // (2 * b)
        for dk in range(-2, 3):
            kk = k + dk
            if 0 <= kk <= n:
                best = max(best, value(kk))

    return best

def main():
    T = int(input())
    out = []
    for _ in range(T):
        n, a, b = map(int, input().split())
        out.append(str(solve_case(n, a, b)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装では、式を直接エンコードすることで構成の値を計算します。 すべての可能性をスキャンするのではなく、境界ケースと二次形式の転換点から導出された推定最適値の周囲の小さな近傍のみを評価します。 

微妙な部分は候補者の選択です。 表情が凹んでいる$k$, したがって、最大値は頂点の周囲に集中します。 整数頂点は離散導関数条件を使用して近似され、その周囲の小さなウィンドウによって正確さが保証されます。

 ## 特殊なケース

 いつ$n = 1$、決定は単一のユニットを選択することに帰着します。 アルゴリズムは引き続き両方を評価します$k = 0$そして$k = 1$したがって、単独の基本ユニットと単独のアンプを正しく比較できます。 

いつ$b = 0$、アンプは基本ユニットを改善することはありません。 この式は、次の間の線形トレードオフに単純化されます。$a$および 1、および境界のチェック$k = 0$そして$k = n$すべてのスロットをベーシックにするかアンプにするかを正しく選択します。 

いつ$a = 0$、すべての価値はアンプから生まれ、それらの相互作用は消滅します。 式は、カウントを最大化する構成を選択することによって支配され、再び境界チェックによって正しい動作が捕捉されます。 

大型用$b$、関数は鋭いピークになります。 離散頂点近似は依然として最適値に近く、小さな近傍スキャンにより真の最大値が含まれることが保証されます。
