 ## 解決策
 ## 問題の理解

 16 チーム間の完全に指定された決定論的なトーナメントが与えられます。 チームの各ペアには、入力にエンコードされた固定の結果があります。初期シード位置 i と j については、対戦した場合はどちらか一方が勝ち、この結果は決して変わりません。 

実際の競争は単純な総当りではありません。 代わりに、これは厳格な構造を持つスイス式のシステムです。つまり、チームは同一の勝敗記録を持つグループ内で繰り返しペアリングされ、3勝または3敗に達するとプレーを停止し、ペアリングのルールはシード順と再戦禁止の制約に依存します。 各ラウンドの後、シードは階層を使用して再計算されます。最初に勝利数、次に対戦相手の結果から得られる二次スコア、そして最後にタイブレーカーとしての初期シードが計算されます。 

最終的に出力するように求められるのは、プロセスが示すよりも単純なものだけです。 1 から 16 までの各初期シードについて、スイスのシステムが完成した後の最終的な勝敗数が必要です。 

隠れた重要な難しさは、トーナメントのルールが適応的で動的に見えるにもかかわらず、すべての試合結果が事前に決定されており、チームの数が固定されており非常に少ないため、システム全体が決定的であることです。 課題は、単純な意味での組み合わせ爆発ではなく、進化するランキングと過去の一致制約に依存する構造化されたペアリング プロセスを忠実にシミュレートすることです。 

入力サイズは構造上一定です。16 チーム間のすべてのペアごとの結果を説明する 15 行です。 これは、三次シミュレーションまたは中程度の重状態シミュレーションを含むあらゆるソリューションが実現可能であることを直ちに示唆していますが、単純な方法でグローバル マッチングを繰り返し再計算するものは、不必要なオーバーヘッドと実装の複雑さのリスクを伴います。 

「再戦禁止」ルールとグループ内のシードベースの選択を組み合わせることで、微妙なエッジケースが発生します。 勝敗バケットのみを追跡し、過去の対戦相手を無視する不注意なシミュレーションでは、無効な組み合わせが割り当てられ、意図されたスイスの構造から静かに逸脱する可能性があります。 もう 1 つのよくある落とし穴は、シード順を誤って再計算することです。特に、対戦相手の合計結果に依存する 2 番目のタイブレークです。 

## アプローチ

 直接的な強引な解釈では、スイスのトーナメントをラウンドごとにシミュレートすることになります。 各ラウンドでは、現在の戦績に基づいてチームをグループ化し、各グループ内でシード順位の最も高いチームを繰り返し選択し、再戦禁止の制約に違反しない最適な対戦相手と対戦させます。 結果を更新し、すべてのグループが処理されるまで続行し、その後シードを再計算して繰り返します。 

このアプローチは問題の記述を正確に反映しているため、概念的には正しいです。 しかし、その複雑さは、有効な対戦相手の繰り返しの選択に隠されています。 最悪の場合、有効な対戦相手を見つけるために各試合について最大 O(n) の候補をスキャンする可能性があり、すべてのラウンドで O(n log n) または O(n²) の試合決定が行われます。 シード順序と対戦相手の履歴チェックが頻繁に再計算されるため、実際にはこれは簡単に O(n³) になります。n = 16 の場合はまだ問題ありませんが、実装に負担がかかり、エラーが発生しやすくなります。 

重要な観察は、n が固定であり、非常に小さいということです。 これにより、漸近的な最適化から、忠実なステート マシンの構築へと視点を変えることができます。 ペアリングについて賢くしようとする代わりに、明示的なデータ構造を使用して正確なルールを直接シミュレートすることができます。勝ち、負け、対戦相手のセットを追跡し、定義どおりに正確にランキングを再計算します。 

最も重要な単純化は、最初の結果が決まればトーナメントは決定的であると認識することです。 分岐や最適化の問題はありません。 すべてのペアリングはルールによって強制され、プロセス全体は慎重に記録することで段階的にシミュレートできます。 二次ランキングは段階的に維持できるため、最初から再計算する必要がなくなります。

ブルートフォースは、トーナメントルールに明示的に従うため機能しますが、再戦禁止の制約と二次ランキングの定義を完全にエンコードせずに「ペアリングを最適化」しようとすると概念的に失敗します。 正しい解決策は、状態を注意深く更新して完全なシミュレーションを採用することです。

 | 単純なペアリング検索による完全なルール シミュレーション | O(n3 log n) | O(n²) | n = 16 の場合は受け入れられます |
 | 増分ランキング更新を備えた明示的なステート マシン | O(n3) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 各チームの現在の勝敗、およびすでに対戦した対戦相手のセットを維持しながら、トーナメントをラウンドごとにシミュレーションします。 

まず、すべてのチームを勝敗ゼロ、対戦相手セットが空の状態で初期化します。 また、入力から完全な結果行列を事前計算して、任意の一致結果を O(1) でクエリできるようにします。 

次に、全チームが 3 勝または 3 敗になるまでラウンドを繰り返し実行します。 各ラウンドは、すべてのアクティブなチームを現在の (勝ち、負け) 記録に基づいてグループ化することから始まります。 このグループ化はスイス バケットを定義します。 

3 番目に、各バケット内で一致を生成する必要があります。 現在のシード順序付けルールに従ってバケット内のチームを並べ替えます。つまり、勝ち数の高いチームが最初に、次にすべての対戦相手に対する (勝利から負けを差し引いた) の合計として定義された二次スコア、最後にタイブレーカーとしての初期シード インデックスが並べ替えられます。 この順序によって選択の優先順位が決まります。 

4 番目に、バケット内のペアになっていない最高ランクのチームを繰り返し選択します。 このチームの場合、同じバケット内で下方向にスキャンして、まだ対戦していない最高ランクの対戦相手を見つけます。 最初の有効な対戦相手が選択されます。 両方をペアとしてマークし、その試合を記録します。 再一致禁止ルールは以前に検出されたペアのみを禁止するため、このスキャンは安全です。 

5 番目に、事前に計算された結果マトリックスを使用して試合を解決し、それに応じて勝敗を更新し、両チームの対戦相手の関係を記録します。 

6 番目に、すべてのバケットが処理された後、更新された統計を通じて暗黙的にグローバル シード順序を再計算します。 これは次のラウンドのグループ化に影響しますが、グループ化は常に (勝ち、負け) に基づいているため、バケットの構築を超えた別の並べ替え手順は必要ありません。 

すべてのチームが 3 勝または 3 敗の最終状態に達するまで繰り返します。 

これが機能する理由は、システム全体が決定論的で局所的にペアリングに貪欲であるためです。各ステップで、利用可能な最高シードのチームが常に最適な対戦相手を選択します。 n が小さく、すべての制約が明示的であるため、バックトラッキングや全体的な最適化は必要ありません。 対戦相手のセット不変により、違法な再戦が決して作成されないことが保証され、すべての試合が少なくとも 1 つのチームを停止条件に厳密に進めるため、勝敗カウンターにより最終的な終了が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = 16

    # read upper-triangular outcome matrix
    win = [[0]*n for _ in range(n)]
    for i in range(n-1):
        row = list(map(int, input().split()))
        for j, v in enumerate(row, start=i+1):
            win[i][j] = v
            win[j][i] = 1 - v

    W = [0]*n
    L = [0]*n
    played = [set() for _ in range(n)]

    active = set(range(n))

    def secondary(i):
        # sum over (opponent wins - losses)
        return sum(W[x] - L[x] for x in played[i])

    while True:
        active = [i for i in range(n) if W[i] < 3 and L[i] < 3]
        if not active:
            break

        # group by (W, L)
        from collections import defaultdict
        groups = defaultdict(list)
        for i in active:
            groups[(W[i], L[i])].append(i)

        # process each group independently
        for key in groups:
            group = groups[key]

            # sort by seed rule
            group.sort(key=lambda i: (-W[i], -secondary(i), i))

            used = set()
            m = len(group)

            for idx in range(m):
                i = group[idx]
                if i in used:
                    continue

                # find opponent
                j = None
                for k in range(idx+1, m):
                    cand = group[k]
                    if cand in used:
                        continue
                    if cand not in played[i]:
                        j = cand
                        break

                if j is None:
                    continue

                used.add(i)
                used.add(j)

                # play match
                if win[i][j]:
                    wi, wj = i, j
                else:
                    wi, wj = j, i

                W[wi] += 1
                L[wj] += 1
                played[i].add(j)
                played[j].add(i)

    for i in range(n):
        print(W[i], L[i])

if __name__ == "__main__":
    main()
```ソリューションは完全な結果行列を保存するため、各一致を一定時間内に解決できます。 中核となる状態は、勝敗カウンターに加えて、再戦禁止の制約を強制する、すでにプレイした対戦相手のチームごとのセットで構成されます。 

(W, L) によるグループ化は、スイスの構造を直接反映しています。 ソート関数は、ランキング ルールをエンコードします。つまり、勝利による 1 番目、対戦相手の強さによる 2 番目、そして最初のインデックスです。 n が小さいため、二次スコアはオンデマンドで計算されます。 ここではキャッシュは不要です。 

ペアリングはソートされた順序で貪欲に行われ、前方にスキャンして、まだプレイされていない最初の有効な対戦相手を見つけます。 これにより、シードの優先順位と再戦の制限の両方が考慮されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、チームがそのバケット内で繰り返し上位になるにもかかわらず、潜在的な対戦相手がすべてすでにプレイ済みとしてマークされている場合です。 その状況では、完全な対戦相手の履歴をチェックしない単純な実装では、スイスの制約に違反して、以前の対戦相手を再割り当てしようとする可能性があります。 正しい実装では、その反復でそのチームのペアリングを単純にスキップし、同じまたは後の処理順序で別の有効な試合のために残します。 

もう 1 つの微妙なケースは、2 番目のランキングの同点が同一の対戦相手セットを持つ複数のチームに連鎖する場合です。 タイブレークは最終的に最初のシードに戻るため、この最終比較を含めないと、ソートが不安定になり、ペアの順序が一貫性を失う可能性があります。 実装されたコンパレータには、最後のキーとしてシード インデックスが明示的に含まれており、完全な対称性の下でも決定性が保証されます。
