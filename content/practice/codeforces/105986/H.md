 ## 問題の理解

 高さの完全な完全な二分木が与えられています。$n$。 これは、木が持っていることを意味します$n$レベル、根元はレベルにあります$n$、各内部ノードにはちょうど 2 つの子があり、すべてのリーフが同じレベルにあります。$1$。 すべてのリーフには次のいずれかが割り当てられます。$0$または$1$。 すべての内部ノードは、その 2 つの子の XOR をとります。 

葉で値が固定されると、ツリー内のすべてのノードは決定論的に次のいずれかになります。$0$または$1$。 タスクは、ツリー内のすべてのノードの値の合計ができるだけ大きくなるようにリーフ値を選択することです。 

入力は多くの独立したクエリで構成され、それぞれに高さが与えられます。$n$。 クエリごとに、すべてのノードの最大可能総和をモジュロで出力する必要があります。$998244353$。 

重要な構造的制約は次のとおりです。$n$と同じ大きさにすることができます$10^{18}$したがって、ツリーを明示的にシミュレートしたり、レベル間で反復したりするソリューションは不可能です。 答えは、閉じた形式で表現できるか、クエリごとに対数時間で計算できる必要があります。 

微妙な点は、指数関数的に多くのノードがあるにもかかわらず、その構造は非常に規則的であるということです。すべての内部ノードは、サイズが 2 のべき乗である連続した葉のブロックの XOR を表します。 これは、各ノードの値がそのサブツリー内の 1 の数のパリティのみに依存することを意味します。 

よく見られる素朴な誤解は、内部ノードは独立して最適化できると考えることです。 たとえば、各サブツリーのルートを次のように設定しようとするかもしれません。$1$貪欲ですが、これは重複する制約間の一貫性を無視します。つまり、リーフの選択は多くのノードに同時に影響します。 

エッジケースは小さな高さから発生します。 のために$n=1$、ノードは 1 つだけであり、答えは明らかです。$1$。 のために$n=2$、ノードが 3 つあり、達成可能な最良の合計は次のとおりです。$2$。 のために$n=3$、構造は自明ではなくなり、すでに複数のレベルにわたってリーフ割り当てを調整する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてが列挙されます。$2^{2^{n-1}}$リーフ値の割り当てを行って、各割り当ての結果として得られる XOR ツリーを計算し、最大合計を取得します。 単一の構成を計算するだけでもコストがかかります$O(2^n)$、したがって、これは、たとえ$n=5$。 

より現実的な素朴なアイデアは、サブツリーに対する動的プログラミングであり、サブツリーの高さごとにどのような構成が可能かを追跡しようとします。 ただし、サブツリーは単一ビットだけでなくリーフ割り当て全体によって決定されるため、状態空間は依然として爆発的に増加します。 

重要な洞察は、個々のノードの観点から考えるのをやめ、代わりにツリーのレベルの観点から考えることです。 各レベルはリーフの互いに素なセグメントで構成され、そのレベルの各ノードは単にそのセグメントの XOR です。 したがって、問題は次のようになります: 長さのバイナリ配列を選択する$2^{n-1}$、そして XOR が次のような二進区間 (ツリー ノードに対応する区間) の合計数を最大化します。$1$。 

これにより、問題はすべての 2 のべき乗セグメントにわたる構造化された組み合わせ最適化に変わります。 重要な観察は、最適解には再帰的なパターンがあるということです。つまり、高さの木の寄与です。$n$木の高さで表すことができる$n-2$というのは、2 番目のレイヤーごとに独立した最適化を可能にする方法でレベルが交互に切り替わるためです。 

これは単純な反復につながり、最終的には閉じた形式になります。

 ## アルゴリズムのチュートリアル

 ### 最適なアイデア

 各ノードが長さのセグメントに対応していることがわかります。$2^k$、その値はそのセグメントの XOR です。 したがって、各ノードはどちらかに貢献します$0$または$1$セグメントに奇数の 1 が含まれているかどうかに応じて異なります。 

目標は、XOR が (すべてのレベルにわたって) セグメントの数を最大化するリーフ配列を選択することです。$1$。 

### 主要な構造観察

 1. 最下位レベル (葉) は、配列内の 1 の数に直接寄与します。 
2. 次のレベルのグループはペアで退場します。 各ペアが貢献します$1$2 つのビットが異なる場合。 
3. より高いレベルでは、より大きなブロックにわたってこのパターンが繰り返されます。 

重要な制約は、リーフ レベルでの選択がその上のすべてのレベルに同時に影響するということです。 

### 再帰構造

 私たちは定義します$f(n)$身長の最大可能合計として$n$。 

ツリーを一定のサイズのブロックに分割します$2^{n-2}$レベルの相互作用を比較する場合。 最適な構築は 2 レベルごとに交互に影響を及ぼし、再発につながります。$$f(n) = f(n-2) + 2^{n-1}$$直感的には、レベルからの最大の達成可能な貢献は、$n-1$が優勢で、残りの構造は独立した高さの小さな木のように動作します。$n-2$。 

### 基本ケース

 直接計算します。$f(1) = 1$

$f(2) = 2$これらから、再発によってすべての値が完全に決定されます。 

### クローズドフォーム

 繰り返しを展開する:$$f(n) = 2^{n-1} + 2^{n-3} + 2^{n-5} + \cdots$$したがって、ステップ 2 で 2 のべき乗を合計します。 

もし$n = 2m$:$$f(n) = 2^{2m-1} + 2^{2m-3} + \cdots + 2^1 = \frac{2^{n+1} - 2}{3}$$もし$n = 2m+1$:$$f(n) = 2^{2m} + 2^{2m-2} + \cdots + 2^0 = \frac{2^{n+1} - 1}{3}$$### なぜ効果があるのか

 前の層が最適に修正されると、2 番目ごとのレベルからの寄与を互いに独立して最適化できるため、反復が成り立ちます。 ツリーは 2 レベルごとに同一の部分構造に分割され、最適な構成が一貫したパターンで繰り返されます。 これにより、2 レベルの境界を越えるクロスレベル干渉が防止されます。これが、解が等比級数に崩れる理由です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modpow(a, e):
    res = 1
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())

        p = modpow(2, n + 1)

        if n % 2 == 0:
            ans = (p - 2) * pow(3, MOD - 2, MOD)
        else:
            ans = (p - 1) * pow(3, MOD - 2, MOD)

        print(ans % MOD)

if __name__ == "__main__":
    solve()

べき乗を計算します$2^{n+1}$たとえ効率的に$n$まで$10^{18}$。 のパリティ$n$2 つの閉じた形式から選択します。 

ここでよくある間違いは、減算はモジュロで実行する必要があることを忘れていることです。$MOD$、特に偶数の場合、$2^{n+1} - 2$正規化する前にマイナスになる可能性があります。

import sys, io

MOD = 998244353

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def modpow(a, e):
        res = 1
        while e:
            if e & 1:
                res = res * a % MOD
            a = a * a % MOD
            e >>= 1
        return res

    T = int(input())
    out = []
    for _ in range(T):
        n = int(input())
        p = modpow(2, n + 1)
        if n % 2 == 0:
            ans = (p - 2) * pow(3, MOD - 2, MOD)
        else:
            ans = (p - 1) * pow(3, MOD - 2, MOD)
        out.append(str(ans % MOD))
    return "\n".join(out)
