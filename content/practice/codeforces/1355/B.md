 ## 問題の理解

 探索者のリストが与えられ、それぞれに番号が関連付けられています。$e_i$これは、参加するグループに何人いなければならないかを表します。 探索者に価値がある場合$e$の場合、彼らは少なくとも次のサイズのグループにのみ参加するつもりです。$e$。 タスクは、各グループ内のすべてのメンバーの制約を尊重しながら、一部またはすべてのエクスプローラーをできるだけ多くの有効なグループに分割することです。 

各テスト ケースは独立しています。 それぞれについて、グループ化自体ではなく、形成できるグループの最大数を出力するだけで済みます。 

制約が十分に大きいため、どの解も線形または線形に近い必要があります。$n \log n$テストケースごとに。 すべてのテスト ケースにわたる要素の総数は次のように制限されるため、$3 \cdot 10^5$、各テスト ケースを並べ替えて 1 回処理するソリューションで十分ですが、単純な方法で貪欲にグループの構築を繰り返し試行するアプローチは、最悪の場合、二次的な動作に劣化します。 

探索者を分類せずに 1 人ずつグループに割り当てようとすると、微妙な失敗モードが発生します。 たとえば、大きな要件を早い段階で見つけて単独で配置した場合、後でそれを他の要件とグループ化して複数の有効なグループを形成できた可能性があることが判明する可能性があります。 もう 1 つの失敗モードは、小さなグループを考慮せずに、到着順に貪欲にグループを形成しようとすることです。$e_i$値はグループを効率的に「埋める」ために使用する必要があります。そうでない場合は、値が大きくなります。$e_i$値を設定できなくなる可能性があります。 

## アプローチ

 ブルートフォース戦略では、グループを段階的に構築しようとします。 残りのエクスプローラーのサブセットを繰り返し選択し、有効なグループを形成できるかどうかをテストし、有効なグループを形成できる場合は削除します。 これは、制約定義を直接尊重するため、正しいです。 問題は、実行可能性を検証するために各試行が残りのアレイの大部分をスキャンする可能性があり、最悪の場合、これにより$O(n^2)$探索者が繰り返し再検討された場合のテスト ケースごとの動作。 

重要な構造的観察は、グループの条件はそのサイズのみに依存し、アイデンティティには依存しないということです。 探索者をその順に並べ替えると、$e_i$、蓄積した候補数を維持しながら、貪欲にグループを構築できます。 利用可能なエクスプローラーの累積数が現在の要素の要件に達するか超えると、グループを終了してカウンターをリセットできます。 これが機能するのは、グループを遅延しても利用可能なメンバーのプールが増えるだけであり、実現可能性が低下することはないからです。 

これにより、問題はソートされた配列を 1 回通過するだけになり、潜在的なグループとして現在検討している要素の数が追跡されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 まず、配列をソートします。$e_i$減少しない順序で。 並べ替えにより、常に最小の要件を最初に満たそうとすることが保証されます。これは、配置が最も簡単で、有効なグループを形成するためのフィラーとして機能するため、不可欠です。 

次に、現在のグループに対して蓄積した探索者の数を表すカウンターを維持しながら、ソートされた配列をスキャンします。 探索者を含めるたびに、このカウンターは 1 つずつ増加します。 

カウンタが現在の探索者の要件と等しくなったら、グループを閉じます。 この時点で、これらのエクスプローラーは割り当てられており再利用できないため、カウンターをゼロにリセットします。 

このチェックが (より大きいではなく) 同等で行われる理由は、現在のプールの最も弱い要件を満たすのに十分なメンバーが揃ったら、その時点を超えた追加の蓄積は、次のグループの形成をすぐに開始するために使用する方が適切であるためです。 

### なぜ効果があるのか

 並べ替え後、配列の任意のプレフィックスには、残りの要素の中で可能な最小の要件が含まれます。 最も早い有効な時点でグループを形成すると、より大きな要件を持つ要素が早期に無駄になることがなくなり、後のステップでの柔軟性が確保されます。 各グループは、累積カウントが最後に含まれる要素のしきい値と正確に一致する最大セグメントに対応し、どのグループもサイズ制約に違反せず、有効なグループ化がスキップされないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        e = list(map(int, input().split()))
        e.sort()

        cnt = 0
        groups = 0

        for x in e:
            cnt += 1
            if cnt >= x:
                groups += 1
                cnt = 0

        print(groups)

if __name__ == "__main__":
    solve()
```この解決策は、要件を並べ替えて、より簡単な制約を最初に処理することから始まります。 変数`cnt`現在形成されているグループのサイズを追跡します。 エクスプローラーを追加するたびに、現在のグループが有効かどうかを比較して確認します。`cnt`現在の要件では`x`。 有効になると、すぐにグループを確定してリセットします。 

よくある間違いは、次まで待つことです`cnt == x`の代わりに`cnt >= x`。 グループが予想よりも早く有効になる可能性があり、チェックを遅らせると不必要に大きなグループが形成され、形成される総数が減少するため、複数の小さな値が出現すると等価性だけでは失敗します。

def solve(inp: str) -> str:

 ## 特殊なケース

 最小の単一要素のケースでは、カウンターが即座に条件を満たすため、要件 1 を持つエクスプローラーが常に単独でグループを形成することが保証されます。 

すべての値が等しい場合$n$プレフィックスがサイズに達しないため、形成できるグループは 1 つだけになります。$n$すべての要素が消費される前に、要件が高い場合にアルゴリズムがオーバーカウントしないことを確認します。 

厳密に増加するシーケンスにより、初期の小さな値がフィラーとして正しく機能し、大きな値が誤って時期尚早のグループ化を強制しないことが保証されます。 ソートされた貪欲パスは、正確性を維持しながら、十分な蓄積が存在するまでクロージャを自然に遅らせます。
