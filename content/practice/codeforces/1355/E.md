 ## 解決策

 ## 問題の理解

 それぞれに初期高さが設定された柱の列が与えられます。 目標は、すべての柱が最終的に同じ高さになるようにこれらの高さを変換することです。 レンガを追加したり、レンガを削除したり、柱の間でレンガを移動したりすることができますが、それぞれに異なるコストがかかります。 

重要な決定は、固定された目標の高さに合わせる必要はないということです。 代わりに、最終的な共通の高さを自分で選択する必要があり、その選択によって必要な各タイプの操作の数が決まります。 選択した高さの場合、その上の柱は過剰なレンガを提供し、その下の柱は不足するレンガを必要とします。 過剰分は移動または削除することで安価に処理でき、不足分は移動または追加で満たすことができます。 

N は 100000 に達し、高さは 10^9 に達する可能性があるため、入力サイズにより、テスト ケースごとに最大でも O(N log V) または O(N) のアルゴリズムが求められます。 各評価が線形で範囲が大きい場合、考えられるすべてのターゲットの高さを個別に試行する単純な戦略では時間がかかりすぎます。 

操作を決定する際に微妙な点が現れます。レンガを移動する方が、削除して追加するよりもコストがかからない場合がありますが、常にそうとは限りません。 これにより、M と A + R の比較に依存するコスト構造が作成されます。この比較が無視されると、ソリューションで移動が過剰に使用されたり、まったく使用されなかったりする可能性があり、どちらも不正確な結果につながります。 

典型的な失敗例は、移動が個別の操作よりも厳密に安価な場合に発生します。 たとえば、A = 5、R = 5、M = 1 の場合、移動は追加と削除の両方を支配するはずですが、黒字と赤字を常に独立して処理する単純な分割戦略では支払いが過剰になります。 

削除と追加を組み合わせた場合よりも移動の方がコストがかかる場合、別の特殊なケースが発生します。 A = 1、R = 1、M = 100 の場合、手はまったく使用されるべきではなく、一致する黒字と赤字のペアを貪欲に動かすアルゴリズムは最適とは言えない結果を生成します。 

## アプローチ

 ブルートフォースのアイデアは簡単です。目標の高さ H を固定し、H を超える総超過量と H を下回る総不足量を計算し、利用可能な操作を使用してそれらのバランスを取るコストを計算します。 最適な解はある整数の高さに対応する必要があるため、0 から最大高さまでのすべての可能な H を試行すると正確さが得られます。 

ただし、高さの範囲は 10^9 までなので、直接反復することは不可能です。 一意の高さに制限したとしても、最大 10^5 の値が存在し、各候補の再計算コストは​​ O(N) となり、最悪の場合は O(N^2) になります。 

重要な観察は、H 上のコスト関数が凸状の構造であるということです。 H が増加すると、黒字は減少し、赤字は単調に増加します。 これにより、任意の固定 H のコストを線形時間で評価し、整数領域での三分探索を使用して最小値を探索することができます。 さらに重要なのは、高さをソートした後、プレフィックスの合計を使用して各評価を効率的に計算できることです。 

並べ替え後、二分探索を使用して、候補の高さの上または下にレンガが何個あるかをすばやく計算できます。 これにより、各コスト評価が O(log N) に減り、完全な検索は O(N log N + log V log N) になります。 実際には、より標準的で最適なソリューションでは、三項検索を完全に回避し、ソートされた高さ全体を 1 回スイープしてプレフィックス合計を使用して直接コストを計算し、ブレークポイントから最適な高さの候補を導​​き出します。 

最も重要な構造的洞察は、目標高さが固定されている場合、問題は過剰供給と不足需要の 2 つの部分に分解されるということです。 唯一の複雑な問題は、超過を移動によって不足に変換するのと、削除と追加のペアによって変換するのとどちらが安いのかということです。

 ## アルゴリズムのチュートリアル

 最初に柱の高さを並べ替えて、ターゲット候補の上と下に何本あるかを効率的に推論できるようにします。 

1. 高さの配列を降順でない順に並べ替えます。 これにより、任意の高さの候補を配列内の分割点として扱うことができ、左側がすべて下に、右側がすべて上になります。 
2. 高さのプレフィックスの合計を計算します。 これにより、合計を繰り返し再計算することなく、赤字と黒字を計算するために必要なセグメントの合計の高さをすばやく計算できます。 
3. 最終的な高さ H の候補を検討します。固定 H の場合、高さが少なくとも H になる最初のインデックスを見つけます。左側はすべて赤字で、右側はすべて黒字です。 
4. H 未満のすべての要素を H まで引き上げるのに必要な合計量として不足額を計算します。これは、H に下位要素の数からその合計を引いた値を掛けたものです。 これは入手しなければならないレンガを表しています。 
5. H より上の要素から削除できる総量として余剰を計算します。これは、H より上の要素の合計から H を引いたものに、それらの要素の数を乗算したものです。 これは利用可能なレンガを表します。 
6. 黒字と赤字をどのように解決するかを決定します。 レンガを移動する方が、個別に削除して追加するよりも安価な場合は、最初に剰余と赤字が最小になるまで移動を使用します。 それ以外の場合は、削除操作と追加操作を使用して、黒字と赤字を個別に処理します。 
7. 高さ H の総コストは、一致する黒字と赤字のペアを移動するコストに、個別に処理される一致しない残りの黒字と赤字を加えたコストになります。 
8. 関連するすべての候補高さ、具体的にはすべての個別の入力高さに加えて潜在的な境界の極値についてこのコストを評価し、最小値を取得します。 

それが機能する理由: 目標の高さが固定されている場合、最適な戦略は常に黒字と赤字を貪欲に組み合わせます。これは、各移動が両方の数量を同時に直接的に減少させるためです。 残った余剰は削除し、残った赤字は追加する必要があります。 各操作のコストはブリックごとに線形で独立しているため、一致するペアと残差への分解は、その固定 H に対してグローバルに最適です。最終的な答えは、余剰と不足の構成が変化するすべての可能な構造ブレークポイントを最適化することによって得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, A, R, M = map(int, input().split())
    h = list(map(int, input().split()))
    
    h.sort()
    
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + h[i]
    
    # helper to compute cost for target height H
    def cost(H):
        import bisect
        k = bisect.bisect_left(h, H)
        
        low_cnt = k
        high_cnt = n - k
        
        low_sum = pref[k]
        high_sum = pref[n] - pref[k]
        
        deficit = H * low_cnt - low_sum
        surplus = high_sum - H * high_cnt
        
        move_pairs = min(deficit, surplus)
        
        if M < A + R:
            return move_pairs * M + (deficit - move_pairs) * A + (surplus - move_pairs) * R
        else:
            return deficit * A + surplus * R
    
    # candidates: all unique heights
    candidates = set(h)
    
    ans = float('inf')
    for H in candidates:
        ans = min(ans, cost(H))
    
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは高さをソートし、プレフィックスの合計を構築するため、二分探索により各コスト クエリに対数時間で回答できるようになります。 機能`cost(H)`H に対して追加および削除する必要があるレンガの数を計算し、移動によるペアリング操作が有益かどうかを決定します。 最後のループでは、既存の柱の高さに等しい候補の高さのみを評価します。コスト関数はこれらの点でのみ傾きを変更するため、これで十分です。 

微妙な実装の詳細は比較です`M < A + R`。 これにより、除去と追加を移動に変換することが有益かどうかが決まります。 引っ越しの方が安い場合は、できるだけ多くの余剰レンガと不足レンガを組み合わせます。 それ以外の場合は、動きを完全に無視します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from math import inf
    
    n, A, R, M = map(int, input().split())
    h = list(map(int, input().split()))
    
    h.sort()
    pref = [0]
    for x in h:
        pref.append(pref[-1] + x)
    
    def cost(H):
        import bisect
        k = bisect.bisect_left(h, H)
        low = k
        high = n - k
        deficit = H * low - pref[k]
        surplus = (pref[n] - pref[k]) - H * high
        if M < A + R:
            m = min(deficit, surplus)
            return m * M + (deficit - m) * A + (surplus - m) * R
        else:
            return deficit * A + surplus * R
    
    ans = min(cost(x) for x in set(h))
    return str(ans)

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての柱がすでに同じ高さである場合に発生します。 その状況では、H がその高さに等しい場合、赤字と黒字の両方がゼロになり、演算が必要ないため、アルゴリズムは正しくゼロコストを生成します。 

もう 1 つのケースは、移動することが厳密に最善の場合です。 A と R が大きいが M が小さい場合、アルゴリズムは残りの演算を適用する前にすべての余剰と不足をペアにします。 のような入力の場合`1 100 100 1`高さのある`[0, 10]`、H = 5 付近で不足と余剰は両方とも 5 に等しく、アルゴリズムは合計 5 のコストがかかる 5 つの手を使用し、コストのかかる追加/削除操作を正しく回避します。 

3つ目は、移動しても無駄な場合です。 M >= A + R の場合、アルゴリズムは移動を使用せず、代わりに追加と削除に対して独立して支払いを行います。 のために`[1, 1000, 1000, 1000]`これでもコストはゼロであり、スキュー配列の場合は、コストの増加につながる誤ったペアリングが回避されます。
