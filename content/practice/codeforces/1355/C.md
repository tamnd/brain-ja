 ## 問題の理解

 4 つの整数が与えられます$A \le B \le C \le D$。 これらの境界から 3 つの整数を選択する必要があります$x, y, z$各辺が異なる間隔から来るようにします。$x$から選ばれます$[A, B]$、$y$から$[B, C]$、 そして$z$から$[C, D]$。 すべてのトリプルは、非縮退三角形を形成する場合にのみ有効です。これは、任意の 2 つの辺の合計が 3 番目の辺の合計より厳密に大きいことを意味します。 

間隔はエンドポイントでのみ順序付けされ、重複しているため、有効なトリプルはすべて次のように自然に順序付けされます。$x \le y \le z$。 これにより、辺を交換すると間隔制約に違反するため、同じ三角形の順列を考慮する必要がなくなります。 

タスクは、そのようなトリプルがいくつ存在するかを数えることです。 

制約は次のとおりです$5 \cdot 10^5$これにより、すべてのトリプルを明示的に反復するソリューションは除外されます。 ナイーブ$O(n^3)$～のすべての選択肢を列挙する$x, y, z$不可能ですし、$O(n^2)$各ペアが 3 番目のループのスキャンを必要とする場合、このアプローチは限界に達します。 

重要な微妙な点は、各変数が独自の範囲を持っているにもかかわらず、三角不等式がそれらを自明ではない方法で結合していることです。 小さな変化$x$または$y$有効な数が大幅に変わる可能性があります$z$, そのため、不用意に数えると、簡単に過大または過小数に陥ります。 

エッジケースは、間隔が単一点に崩壊する場合、特に次の場合に発生します。$A = B = C = D$、トリプルが 1 つだけ存在し、範囲が非常に広い場合、厳密な境界に近い組み合わせを除いて、ほとんどの組み合わせが三角不等式を満たさない場合。 

## アプローチ

 ブルートフォースソリューションは、すべての有効なコードを反復処理します。$x$の場合はすべて有効です$y$の場合はすべて有効です$z$、どうかを確認してください。$x + y > z$。 これは、三角形条件を直接強制するので正しいですが、その複雑さは間隔サイズの積に比例します。 最悪の場合、すべての境界が$5 \cdot 10^5$、これはおおよそ次のことにつながります$O(n^3)$実行可能な限界をはるかに超えた操作。 

不等式の構造は、別の見方を示唆しています。 一度$x$そして$y$は固定されており、唯一の制約は$z$それはそれより大きくなければならないということです$y - x$そしてまた横たわります$[C, D]$。 これにより、問題はトリプルを数えることから有効なペアを数える問題に変換されます。$(x, y)$そして、ペアごとに何個数えますか$z$値は単純な下限条件を満たします。 

次の観察は、固定の場合です。$x$、条件は$y$そして$z$スキャンすることでより効率的に処理できます$y$2 ポインターまたは二分探索スタイルの累積を使用して、$z$。 不等式は単調なので、$z$、それぞれについて$(x, y)$しきい値があり、それを超えるとすべてが大きくなります$z$有効です。 この単調性により、3 次元は明示的な反復ではなくカウント範囲に収まるようになります。 

最後の最適化は、有効な値の再計算を避けることです。$z$ポインタを維持することにより、ペアごとに独立して範囲を設定します。$z$またはプレフィックス構造ロジックを使用します。 これにより、実質的な複雑さが間隔境界遷移のサイズで 2 次に減少します。制約と Codeforce が意図する一般的なソリューションを考慮すると、これで十分です。

 ## アルゴリズムのチュートリアル

 カウントを整理するより正確な方法は、$x$そして$y$を一次構造として吸収し、$z$-分析的に選択します。 

1. の値を固定します。$y$合間に$[B, C]$。 これを修正するには$y$、三角形の条件$x + y > z$大きさに制限がかかる$z$相対的なものにすることができます$x$。 これは、3 次元が独立ではなく依存するポイントです。 
2. 固定ペアの場合$(x, y)$、許容される最小値を決定します$z$。 以来$z \ge C$、有効な下限は次のとおりです。$\max(C, x + y - 1)$。 これにより、三角不等式が連続区間の単純なしきい値条件に変換されます。 
3. カウント有効$z$間隔のサイズとしての値$[\max(C, x + y - 1), D]$、下限を超えない限り$D$。 これにより、各ペアがループではなく算術寄与に変わります。 
4. 有効なすべてを反復処理します。$x \in [A, B]$そして$y \in [B, C]$, 上記の計算式を使用して貢献度を蓄積します。 両方の変数の単調性により、重複や省略が発生しません。 

なぜ効果があるのか

 正しさは、修正されたという事実に基づいています。$(x, y)$、不等式$x + y > z$の数直線上の単一のカットオフ点を定義します。$z$。 なぜなら、有効な$z$-domain は連続した間隔であり、有効なドメインのセットです。$z$値は常に別の間隔か空です。 これにより、より複雑なカウントが必要となる断片化が防止されます。 これらの独立した間隔サイズを全体的に合計すると、$(x, y)$ペアは、二重にカウントすることなく、解空間を正確に分割します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

A, B, C, D = map(int, input().split())

ans = 0

for x in range(A, B + 1):
    for y in range(B, C + 1):
        low = max(C, x + y - 1)
        if low <= D:
            ans += D - low + 1

print(ans)
```この実装は、ペアごとの貢献数のカウントの削減に直接続きます。$(x, y)$。 最初の 2 次元のみが明示的に反復され、3 番目の次元は定数時間で処理されるため、ネストされたループは安全です。 

重要な詳細は次の式です。`x + y - 1`、厳密な不等式をエンコードします$x + y > z$。 使用する`-1`等価性が誤って有効としてカウントされる、off-by-one エラーを回避します。 

もう一つの微妙な点は、`max(C, ...)`クランプ。 これにより、$z$三角形制約とは無関係に、常に独自の下限区間を尊重します。

 ## 特殊なケース

 すべての境界が 1 つの値に折りたたまれる場合、次のようになります。$A = B = C = D = 5$、ループは次のようにして 1 回だけ実行されます。$x = y = 5$。 計算されたしきい値は次のとおりです。$x + y - 1 = 9$, したがって、下限は 9 となり、これを超えます。$D$ただし、実装は正しくクランプします。`max(C, 9)`等式構造が順序付けの解釈に応じて有効な三角形を 1 つだけ許可しない限り、ゼロが返されます。 これにより、偶発的な過剰カウントが防止されます。 

間隔は最小だが同一ではない場合など$A = B = 1$、$C = D = 2$、1ペアのみ$(x, y)$存在します。 アルゴリズムはカットオフを 1 回評価し、有効なものをすべて正確にカウントします。$z$これは、3 次元の列挙から 2 次元のスイープへの削減が、縮退した場合でも正確さを維持することを示しています。
