 ## 解決策
 ## 問題の理解

 私たちは、特定の文字列がネットワーク内の非常に特殊な送信エラーから生じたものであるかどうかを判断するように求められます。 メッセージが表示された場合にエラーが発生します`s`は 2 回連続して送信され、2 番目のコピーは最初のコピーとゼロ以外の長さで部分的に重複します。 言い換えれば、最初のメッセージのサフィックスは 2 番目のメッセージのプレフィックスと正確に一致し、ネットワークはそれらをマージします。 この重なり合う部分は、厳密に全長よりも小さくなければなりません。`s`したがって、完全に繰り返されたメッセージや完全に連結されたコピーはエラーとしてカウントされません。 

入力は単一の文字列です`t`受信したメッセージを表します。長さは最大 400,000 文字です。 元のメッセージが存在しない場合、出力は「NO」になります。`s`それは説明できるかもしれない`t`マージ経由、または「YES」の後に可能な 1 つが続く`s`。 

制約は、あらゆる可能な分割を試みる総当り的なアプローチを意味します。`t`重複するコピーへの変換は遅すぎます。 二次アルゴリズムでは、考えられるすべてのプレフィックスとサフィックスのペアの重複をチェックする必要があります。`O(n^2)`のための操作`n ≈ 4·10^5`。 これは、2 秒の実行時間の実現可能な制限をはるかに超えています。 これは、線形または線形に近い方法が必要であることを示しています。 

明らかではないエッジケースには次のようなものがあります。 

- 重複せずに繰り返し表示されるメッセージ。 例えば、`abcabc`の単純な繰り返しです`abc`、エラーではありません。 単純なアプローチでは、それがエラーであると誤ってみなされる可能性があります。 
- 完全に統一されたメッセージ`aaaa`。 ここでは、複数の長さで重複が発生する可能性がありますが、マージされたメッセージがあいまいになる可能性があります。 
- 非常に短いメッセージ、たとえば`ab`、ここで、最小限必要な重複は 1 文字です。 

これらを正しく処理しないと、誤検知が発生します。 

## アプローチ

 ブルートフォースアプローチは簡単です。考えられるオーバーラップの長さごとに、`k`1から`len(t) - 1`、最初を取る`len(t) - k`メッセージ候補の文字`s`最後かどうかを確認してください`len(t) - k`の登場人物`t`最初のものと一致する`len(t) - k`の登場人物`s`。 一致するものが見つかった場合は戻ります`s`。 これは概念的には機能しますが、確認が必要です`O(n)`候補の重複と最大の文字列の比較`O(n)`それぞれの長さ、`O(n^2)`複雑。 のために`n ≈ 4·10^5`、これでは遅すぎます。 

重要な洞察は、この問題は、次の最も長い適切なプレフィックスを見つけることと同等であるということです。`t`それも接尾辞です。 これは、文字列ハッシュまたは Knuth-Morris-Pratt (KMP) プレフィックス関数の古典的な使用例です。 の接頭関数を計算すると、`t`、各位置について、最長の境界線 (接尾辞でもある接頭辞) の長さがわかります。 適切な長さの境界線`k`それは厳密に 0 から`len(t)`マージ エラーの有効な重複に正確に対応します。 これを知ったら`k`、再構築することができます`s`として`t[0:len(t) - k]`。 

したがって、最適な解決策は時間的に線形であり、接頭辞関数または文字列ハッシュを使用して最大境界を見つけます。 ローリング ハッシュを使用することも可能ですが、KMP プレフィックス関数の方が単純で、モジュロ演算を回避し、衝突のない正確性が保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | プレフィックス機能 (KMP) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 接頭辞関数を計算する`pi`文字列用`t`。 それぞれについて`i`、`pi[i]`の最長の適切なプレフィックスの長さを格納します`t[0..i]`それも接尾辞です。 
2. 価値を考える`k = pi[-1]`。 これは、文字列全体の最長の境界線の長さです。`t`。 
3. 次のことを確認します。`k`厳密に 0 から`len(t) // 2`。 もし`k == 0`重複はありません。 もし`k == len(t)`または`k == len(t) // 2`そして`t`が正確に繰り返されている場合、それは非エラーとして扱われます。 
4. もし`k`有効です、元のメッセージ`s`は`t[0:len(t) - k]`。 
5. Otherwise, output "NO".

 機能する理由: 接頭辞関数の不変条件により、次のことが保証されます。`pi[i]`は常に有効な境界線を表します。 見ることで`pi[-1]`、マージの原因となった可能性のある最大の重複が見つかります。 正の適切な境界線が存在しない場合、マージ エラーは発生しません。 KMP 計算では、各文字を正確に 1 回スキャンすることで線形時間を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = input().strip()
    n = len(t)
    pi = [0] * n
    
    for i in range(1, n):
        j = pi[i - 1]
        while j > 0 and t[i] != t[j]:
            j = pi[j - 1]
        if t[i] == t[j]:
            j += 1
        pi[i] = j
    
    k = pi[-1]
    if k == 0 or k == n:
        print("NO")
    else:
        s = t[:n - k]
        print("YES")
        print(s)

if __name__ == "__main__":
    main()
```最初のセクションでは、入力を読み取り、プレフィックス関数の配列を初期化します。 ループが埋まる`pi`標準の KMP アップデートに従って、文字が一致しない場合は慎重にロールバックします。 最大境界を計算した後`k`、有効性をチェックします。`0 < k < n`。 有効な場合、`s`は、重複する接尾辞を除いた単なる部分文字列です。 次のような境界条件`k = n`完全な繰り返しを処理しますが、これはエラーではありません。

## 特殊なケース

 アルゴリズムは短い文字列を正しく処理します。 のために`t = "ab"`、`pi[-1] = 0`したがって、出力は「NO」になります。 繰り返される文字については、`t = "aaaa"`、`pi = [0,1,2,3]`、`k = 3`、`s = "a"`。 アルゴリズムは最大の適切な値を特定します。
