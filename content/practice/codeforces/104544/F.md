 ## 問題の理解

 整数の配列と係数値が与えられます。 この配列から、すべての連続するサブ配列が考慮され、各サブ配列には、その要素のモジュロの合計に等しい値が割り当てられます。$m$。 これらすべての部分配列値を書き留めてから、最大値の合計を計算するように求められます。$k$彼らのうち。 

データをより構造的に表示する方法は、プレフィックスの合計を定義することです。$p$、 どこ$p[0]=0$そして$p[i]=a_1+\dots+a_i$。 すべての部分配列の合計は、$l$に$r$になる$p[r]-p[l-1]$、ボードに書かれた値は$(p[r]-p[l-1]) \bmod m$。 したがって、問題はすべてのペアを取ることと同じです$i<j$そして価値観を形成する$(p[j]-p[i]) \bmod m$、次に最大のものを選択します$k$これらのペアごとのモジュラー差を計算し、それらを合計します。 

この制約は、最大で次のことが可能であることを意味します。$10^5$テスト ケースあたりの要素数、最大$10^4$テスト ケース全体に適用されますが、すべてのテストにわたる合計配列サイズには制限があります。 テスト ケースごとのサブ配列の数は次のとおりです。$O(n^2)$、到達できる$5 \times 10^9$したがって、すべての部分配列を列挙することは不可能です。 保管することさえ不可能です。 どのソリューションでも、すべてのペアごとの値を明示的に生成することを避け、代わりにそれらをまとめて推論する必要があります。$O(n \log n)$または同様のもの。 

単純なアプローチでは、すべてのプレフィックスの違いを計算して保存し、上位のものを並べ替えて合計します。$k$。 これでは時間的にも記憶力的にもすぐに失敗します。 

モジュロ演算から微妙な問題が発生します。 値$(p[j]-p[i]) \bmod m$は単調ではありません$p[i]$したがって、ラップアラウンドを慎重に処理せずに、プレフィックスの合計を並べ替えたり、差分を単純な範囲構造として取得したりすることに直接依存することはできません。 たとえば、次の場合$p[i]=9$、$p[j]=2$、 そして$m=10$、値は$3$、 それでも$p[j]<p[i]$。 このラップ動作を無視するアプローチでは、候補の数え間違いや順序の間違いが発生します。 

## アプローチ

 ブルート フォース アプローチでは、すべてのペアが明示的に構築されます。$(i,j)$、計算します$(p[j]-p[i]) \bmod m$、それらを保存し、並べ替えて、最大のものを合計します。$k$。 これは問題の定義に直接従うため、正しいです。 ただし、生成されるのは、$\frac{n(n+1)}{2}$テスト ケースごとの値は、実行可能な制限をはるかに超えています。$n$は$10^5$。 

重要な観察は、すべての値が接頭辞の合計の剰余にのみ依存するということです。$m$、各値は 2 つのプレフィックス値を比較することによって決定されます。 すべてのペアを具体化する代わりに、任意のしきい値について別の質問をすることができます。$x$、少なくともいくつのサブ配列値があるか$x$、その合計はいくらになるでしょうか？ これに効率的に答えることができれば、上位の合計を再構成できます。$k$値空間で二分探索を使用して値を取得します。 

固定閾値の場合$x$、各ペア$(i,j)$貢献する場合$(p[j]-p[i]) \bmod m \ge x$。 この条件は次のいずれかに応じて 2 つのケースに分けられます。$p[j] \ge p[i]$か否か。 これにより、条件が前のプレフィックス値のセットに対する 2 つの間隔クエリに変換されます。 プレフィックス値に対する周波数構造を維持すると、有効な値をカウントできます。$i$それぞれに$j$対数時間で。 

しきい値を超える値を数えて合計できるようになったら、しきい値を二分探索します。$x$少なくともそうなるように$k$値は$\ge x$。 次に、そのしきい値を超えるすべての値の合計を計算し、境界に等しい値の正確な数を使用して超過を調整します。

## アルゴリズムのチュートリアル

 配列をプレフィックス和モジュロに変換します$m$、モジュロの差だけなので$m$案件。 

1. プレフィックス配列の構築$p$ここで、各値は剰余として取得されます$m$。 これにより、すべてのプレフィックスが確実に存在します。$[0, m)$これにより、境界領域全体で周波数構造を使用できるようになります。 
2. 私たちは範囲全体にフェンウィックの木を維持しています$[0, m-1]$、これまでに確認されたプレフィックス値の数とその合計も保存します。 これにより、任意の間隔に含まれる以前のプレフィックスの数と、それらの合計寄与度を照会することができます。 
3. 候補値が固定の場合$x$、ペアの数を計算します$(i,j)$少なくとも価値を生み出す$x$。 それぞれについて$j$、以前のすべてを考慮します$i < j$。 条件$(p[j]-p[i]) \bmod m \ge x$2 つの互いに素な範囲に分割される$p[i]$1 つはラップが発生しないもの、もう 1 つはラップが発生するものです。 どちらの範囲も、プレフィックス値にわたる単純な間隔になります。 
4. フェンウィック ツリーを使用して、これらの間隔にわたるカウントをクエリします。$O(\log m)$、しきい値の有効なペアの合計数を累積します。$x$。 
5. 最大値を二分探索します$x$少なくともそうなるように$k$ペアには少なくとも価値がある$x$。 これにより、選択された値と選択されていない値の間のカットオフが得られます。 
6. 同じカウントロジックを使用して、このしきい値より厳密に大きいすべての値の合計を計算しますが、カウントをフェンウィックツリーからの寄与合計で置き換えます。 
7. しきい値を超える値の数が超えた場合$k$、しきい値と等しい値の数を数え、それに応じて調整することで、最小の超過値を差し引きます。 

### なぜ効果があるのか

 フェンウィック ツリーはプレフィックス値を順序付けされた間隔に分割し、すべてのペアの寄与は長さの円上の 2 つのプレフィックス値の相対位置にのみ依存します。$m$。 ラップケースと非ラップケースを分割することにより、すべての条件は最大 2 つの区間の和集合になります。 これにより、どのしきい値についても、寄与セットが互いに素なプレフィックス範囲クエリの合計として表現可能になります。 二分探索により、最上位を正確に分離することが保証されます$k$値空間内の領域と、接頭辞合計構造により、ペアを列挙することなくその領域を評価できることが保証されます。

import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        i += 1
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        if i < 0:
            return 0
        i += 1
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if l > r:
            return 0
        return self.sum(r) - self.sum(l - 1)

def count_ge(p, m, x):
    fw = Fenwick(m)
    res = 0
    for v in p:
        # count previous u such that (v - u) % m >= x

        # case 1: no wrap, v - u >= x => u <= v - x
        res += fw.range_sum(0, v - x)

        # case 2: wrap, v - u + m >= x => u >= v + m - x
        res += fw.range_sum(v + m - x, m - 1)

        fw.add(v, 1)
    return res

def solve():

        # compute how many strictly greater than threshold

 ## 特殊なケース

 サイズ 1 の最小配列は、モジュロ後の値が 0 の部分配列を 1 つだけ生成します。Fenwick 構造体に挿入するペアがないため、アルゴリズムはそれを処理し、すべてのカウントが 0 のままになります。

プレフィックスの合計が頻繁にラップアラウンドする場合$m$、カウントロジックの 2 番目の間隔が支配的になります。 に分割$[0, v-x]$そして$[v+m-x, m-1]$ラップコントリビューションが引き続きキャプチャされることを保証します。$v < x$そうでない場合、最初の間隔は空になります。
