 ## 問題の理解

 私たちは、ヤザンが 2 つの制約の下で、友人ごとに 1 つずつ、計 2 つの料理をどれだけ安く注文できるかを決定するように求められています。 

最初の料理にはお金がかかります`a`そして少なくともそうである必要があります`x`。 二皿目は有料です`b`合計請求額に関連付けられています。少なくとも次のとおりである必要があります。`y%`合計コストのうち`a + b`。 

したがって、構造は円形です。 の値`b`合計によって異なりますが、合計はによって異なります`b`。 目標は整数を選択することです`a`そして`b`両方の条件を最小限に抑えながら満たす`a + b`。 

入力は、それぞれに境界を持つ複数の独立したテスト ケースを与えます。`x`そして`y`。 各テスト ケースについて、可能な最小の総コストを出力する必要があります。`-1`有効なペアが存在しない場合。 

重要な問題は、次のような自己参照制約です。`b`。 単純な試みでは、すべてのペアを試してしまうでしょう`(a, b)`ただし、どちらの変数にも明らかな有限の上限はありません。 ただし、どちらの制約も値が大きくなるにつれてコストが増加するだけであるため、最適なソリューションは実行可能な最小値に留まり、これは大きな範囲を探索すべきではないことを強く示唆しています。 

微妙なエッジケースが現れるのは、`y = 100`。 その場合、2 番目の制約は次のようになります。`b ≥ a + b`、強制的に`0 ≥ a`、不可能なので`a ≥ x ≥ 1`。 したがって、すべてのテストケースは、`y = 100`すぐには実行不可能です。 

もう 1 つの潜在的な落とし穴は、パーセンテージ制約を次のように誤って扱うことです。`b ≥ (y/100) * a`これは、パーセンテージが最初の料理だけではなく全体に対するものであることを無視します。 

## アプローチ

 ブルートフォースアプローチでは、すべての整数のペアが試行されます。`(a, b)`ある最大限界まで、両方の制約が保持されるかどうかを確認し、最小合計を追跡します。 正しいですが、自然な上限がないため、これは計算上明確に定義されていません。`a`そして`b`10^5 のような値を課したとしても、O(N^2) では遅すぎます。 

重要な観察は、2 番目の制約を書き換えて循環依存関係を排除できることです。 以下から開始します:`b ≥ y/100 * (a + b)`再配置します:`100b ≥ y(a + b)`

`100b ≥ ya + yb`

`(100 - y)b ≥ ya`もし`y < 100`、これは次のようになります。`b ≥ (y * a) / (100 - y)`したがって、固定の場合`a`、有効な最小値`b`直接的に決定されます。 これにより、依存関係のサイクルが完全に削除されます。 

ここで、問題は最小限に抑えられます。`a + b(a) = a + ceil(y * a / (100 - y))`両方の項は次のように直線的に増加するため、`a`、合計は次のように単調増加します。`a`が増えます。 したがって、最適なソリューションでは常に可能な限り最小の値が使用されます。`a`、つまり`a = x`。 

これにより、特殊な場合を除いて、問題全体が直接計算に還元されます。`y = 100`。

 ## アルゴリズムのチュートリアル

 ### 最適な方法

 1.次のことを確認します`y == 100`。 その場合はすぐに出力してください`-1`。 これは、制約によって強制されるためです。`b ≥ a + b`、これはどんなポジティブなことでも不可能です`a`。 
2. それ以外の場合は、有効な最小値を計算します。`a`、これは常に`a = x`。 増加中`a`総コストと必要なコストの両方が増加するだけです`b`したがって、より大きな選択肢は答えを改善することはできません。 
3. 制約を直接の下限に書き換えます。`b`:`b ≥ (y * a) / (100 - y)`4. 最小の整数を計算する`b`天井分割を使用してこの境界を満たす。 
5. 出力`a + b`。 

### なぜ効果があるのか

 この変換により、次の間の依存関係ループが削除されます。`a`、`b`、合計金額。 固定の場合`a`、制約は実行可能な最小値を一意に決定します。`b`。 両方なので`a`そして`b(a)`は非減少関数です`a`、目的関数`a + b(a)`も減少しないため、その最小値は実行可能な最小値で発生する必要があります`a`。 これにより、注意を制限することが保証されます。`a = x`最適なソリューションを排除するものではありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    x, y = map(int, input().split())
    
    if y == 100:
        print(-1)
        continue
    
    a = x
    numerator = y * a
    denominator = 100 - y
    
    b = (numerator + denominator - 1) // denominator
    print(a + b)
```コードは、派生した式の後に直接続きます。 唯一の分岐は、`y == 100`case は不可能な条件を処理します。 

天井分割`(numerator + denominator - 1) // denominator`重要です。 浮動小数点演算を使用すると、特に制約が厳しく、正確な整数の正確性が要求されるため、精度エラーの危険が生じます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        x, y = map(int, input().split())
        if y == 100:
            out.append("-1")
            continue
        a = x
        b = (y * a + (100 - y) - 1) // (100 - y)
        out.append(str(a + b))
    return "\n".join(out)

# provided samples

assert run("1\n10 50\n") == "20", "balanced ratio"
