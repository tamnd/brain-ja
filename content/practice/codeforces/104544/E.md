 ## 解決策
 ## 問題の理解

 長さの 2 つの配列が与えられます$n$。 1 つの配列はポジションの現在の「値」を表し、2 番目の配列は各ポジションが時間の経過とともにどのように変化するかを表します。 We also have a process that runs for$k$秒。 毎秒 1 つのインデックスを選択します$pos$, gain the current value at that index, then decrease that chosen value by a fixed amount, while all other indices partially recover toward their original starting values.

 So the system behaves like a resource pool where every step you harvest from exactly one position, that position becomes less valuable for future use, and all other positions drift back upward toward their initial state but cannot exceed it.

 目標は、次のシーケンスを選択することです。$k$収穫総額を最大化するためのインデックス。 

制約は大きいです:$n$到達できる$2 \cdot 10^5$テスト全体にわたって、$k$と同じ大きさにすることができます$10^9$。 これにより、時間の経過に伴うシミュレーションが即座に除外されます。 毎秒明示的に処理するソリューションは、たとえ 1 つのテスト ケースであっても失敗します。 唯一の実行可能なアプローチは、プロセスをポジションごと、または状態の「サイクル」ごとの集計寄与に削減する必要があります。 

重要な問題は、要素間の結合にあります。 1 つのインデックスを選択すると、その将来の価値は減少しますが、他のインデックスは上限まで増加します。これは、決定がインデックスごとに独立していないことを意味します。 

各インデックスが単純な減少する等差数列として独立して動作すると仮定すると、単純な間違いが発生します。 他の操作によって値が復元される可能性があるため、これは失敗します。 もう 1 つの障害モードは、現在の最大値の貪欲な選択が最適であると仮定することから発生します。これは、他の最大値がどれだけ早く回復するかを考慮せずに最大値を選択しすぎると、将来の可用性が低下するために破綻します。 

## アプローチ

 ブルートフォース解釈では、毎秒シミュレーションが行われます。最適な現在位置を選択し、すべての値を更新し、これを繰り返します。 これは正しいですが、計算上実行不可能です。 各ステップで必要となるのは、$O(n)$アップデート、そして私たちはこれを行います$k$回、与える$O(nk)$までです$2 \cdot 10^{14}$最悪の場合の運用。 

重要な観察は、各要素の進化は選択の正確な順序ではなく、選択された回数にのみ依存するということです。 インデックスの合計寄与度は、インデックスが使用された回数によって決まります。これは、使用するたびにインデックスの値が次のように直線的に減少するためです。$b_i$、他の更新では、初期値を超えないことを保証するだけです。 これにより、時間が要素ごとの使用回数に分割されます。 

時間をシミュレーションする代わりに、問題を分布として扱います。$k$インデックスの中から選択します。 インデックスを選択した場合$x$回、その寄与は、次の条件に応じて固定算術合計になります。$a_i, b_i$、そして将来のリセットにより、しばらく選択されなかった後、初期値に戻ります。 

したがって、繰り返し選択されると、各インデックスは「値シーケンス」を持ちます。$a_i, a_i - b_i, a_i - 2b_i, \dots$。 問題は選択になります$k$これらすべてのシーケンスから要素を合計しますが、各インデックスのシーケンスを順番に取得できるという制約があります。 

これは、すべてのインデックスの中で次に利用可能な最良のゲインのグローバルな選択に変換され、各インデックスは限界利益の減少に寄与します。 次に可能な利益の構造を維持し、最大値を繰り返し取得して、そのインデックスの次の値を更新します。

 欠けている洞察は、実際には処理する必要がないということです。$k$個別にいつ$k$巨大です。 代わりに、単調性を利用します。各インデックスは減少する算術シーケンスを生成するため、グローバルしきい値を超える項の数を計算し、寄与を集計できます。 

## アルゴリズムのチュートリアル

 1. インデックスごとに$i$、それを一人で繰り返し選択することを想像してください。 そのゲインは減少系列を形成します$a_i, a_i - b_i, a_i - 2b_i, \dots$。 最後の正の項がいつ決定されるか$a_i - x b_i > 0$、 それで$x$おおよそです$a_i / b_i$。 これにより、各インデックスが生成できる有用なピックの数がわかります。 
2. 各指数を潜在的な利益のリストに変換します。 すべての値を保存する代わりに、等差数列構造を使用して値を推論します。 インデックスの合計寄与度$x$ピックは:$$x a_i - b_i \frac{x(x-1)}{2}.$$3. 正確に選択する必要があるため、$k$オペレーション全体が進むと、世界的な問題が分散化する$k$インデックス全体を選択して、これらの凹関数の合計を最大化します。 
4. を摂取することで得られるわずかな利益$j$- インデックスからの選択$i$は$a_i - (j-1)b_i$。 これらのわずかな利益はインデックスごとに減少するシーケンスを形成するため、全体的にはトップが必要です。$k$これらすべてのシーケンスにわたる値。 
5. すべてのシーケンスを明示的に生成する代わりに、しきい値を二分探索します。$T$、選択されたゲインの中で選択された最小のゲインを表します。$k$操作。 
6. 固定の場合$T$、各インデックスは、少なくとも次の等差数列内のすべての項に寄与します。$T$。 以下を使用して、そのような用語がいくつ存在するかを計算できます。$$cnt_i = \max\left(0, \left\lfloor \frac{a_i - T}{b_i} \right\rfloor + 1 \right).$$7. すべてを合計します$cnt_i$。 合計が少なくとも$k$、 しきい値$T$が低すぎるため、増加させます。 それ以外の場合は、それを減らします。 
8. しきい値を見つけた後、それを厳密に超えるすべての値の合計を計算し、正確に取得して調整します。$k$最大の貢献。 

### なぜ効果があるのか

 各演算は、一連の減少シーケンスから引き出された限界ゲインとして独立して寄与します。 シーケンスは単調なので、先頭を選択すると$k$結合からの要素は、カットオフより上のすべての要素と境界の部分スライスを選択することと同じです。 二分探索ではそのカットオフを一意に特定し、等差数列の公式を使用すると、明示的に列挙しなくてもカウントと合計を計算できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        def count_ge(x):
            total = 0
            for i in range(n):
                if a[i] < x:
                    continue
                total += (a[i] - x) // b[i] + 1
            return total

        def sum_ge(x):
            total = 0
            for i in range(n):
                if a[i] < x:
                    continue
                cnt = (a[i] - x) // b[i] + 1
                last = a[i] - (cnt - 1) * b[i]
                total += cnt * (a[i] + last) // 2
            return total

        lo, hi = 1, max(a)
        while lo <= hi:
            mid = (lo + hi) // 2
            if count_ge(mid) >= k:
                lo = mid + 1
            else:
                hi = mid - 1

        T = hi
        res = sum_ge(T)

        used = count_ge(T)
        res -= (used - k) * T

        print(res)

if __name__ == "__main__":
    solve()
```このコードでは、まず、しきい値を超える寄与をカウントして合計するヘルパー関数を定義します。 二分探索では、少なくとも次のような最大のしきい値が見つかります。$k$値が利用可能です。 次に、そのしきい値以上のすべての値の合計を計算し、境界レベルで余分な要素を削除することで過剰カウントを修正します。 

微妙な点は、整数の等差数列の合計に依存していることです。 正しい最終項の計算式を使用しないと、合計が不正確になります。 もう 1 つの重要な詳細は、カウント後の調整ステップです。これにより、正確に保証されます。$k$操作が含まれます。

 ## 特殊なケース

 重要なエッジケースは、次のような場合です。$a_i$に比べて小さい$k$つまり、すべてのインデックスの完全なシーケンスを消費します。 アルゴリズムは、しきい値を非常に低く設定して、すべての限界ゲインをカウントし、正確に切り捨てることでこれを処理します。$k$。 

1 つのインデックスが非常に大きなインデックスで支配されている場合、別のエッジ ケースが発生します。$a_i$そして小さい$b_i$。 二分探索では高いしきい値が正しく設定されるため、そのインデックスからの初期の大きなゲインのみが選択され、その他のゲインはカットオフを超えると何も寄与しません。 

3 番目のケースは次の場合です。$b_i$は、各インデックスが最大 1 つまたは 2 つの値に寄与するのに十分な大きさです。 整数の除算によってシーケンスの長さが即座に縮小され、しきい値ロジックが自然に有効な初期ゲインのみを選択するため、カウント式は引き続き機能します。
