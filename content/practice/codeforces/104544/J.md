 ## 解決策
 ## 問題の理解

 1 から m までの整数の複数セットから始めます。 次に、新しい値を q 回追加し、現在のマルチセットの k 番目に小さい要素をすぐに削除します。 各操作の後、1 つの要素が挿入され、もう 1 つが削除されるため、マルチセットのサイズは一定のままです。 

問題は、挿入された値のシーケンスが固定されていないことです。 各位置が独立して 1 から m までの値を取るすべての可能な長さ q シーケンスを考慮する必要があります。 このようなシーケンスごとに、プロセス全体を実行し、マルチセットの最終的な合計を計算します。 タスクは、これらの最終的な合計をすべての m^q シーケンスにわたって合計することです。 

重要な観察は、プロセスの 1 回の実行が要求されるのではなく、考えられるすべての挿入シーケンスにわたる大規模な集約が要求されるということです。 これにより、問題がシミュレーションから構造化されたランダム性に関する計数問題に変わります。 

m、n、q はすべて最大 1000 であるため、制約は十分に小さく、q または n の指数関数は不可能です。m^q 状態になるため、シーケンスごとの直接シミュレーションは完全に不可能です。 状態空間は m との組み合わせで増大するため、完全なマルチセットにわたって DP を維持することさえ不可能です。 

さらに微妙な問題は、k 番目に小さい削除です。 この操作は値に対してローカルではなく、マルチセットのグローバル順序に依存します。 単一の要素が存続するかどうかは、その時点で存在する小さな要素の数によって決まります。 

すべてのシーケンスを保存することさえ不可能であるため、各シーケンスのプロセスをシミュレートしようとする単純なアプローチは、簡単な方法ですぐに失敗します。 

2 番目の単純なアイデアは、要素を独立して扱い、生存の線形性を仮定することですが、削除により順序統計を通じてすべての値が結合されるため、これは失敗します。 

小さいながらも重要なエッジ ケースは、k が 1 に等しい場合、または k が n+1 に等しい場合です。 k が 1 に等しい場合、常に最小の要素が削除され、システムはこれまでに確認された最大の n 要素を常に保持するように退化します。 k が n+1 に等しい場合、挿入後に常に最大値が削除され、システムはこれまでに確認された最小の n 要素を保持します。 これらの極端な値はモノトーン フィルターのように動作しますが、中間の k はソートされた構造をスライディング カットするように動作し、これははるかに困難です。 

## アプローチ

 ブルート フォースのアイデアは簡単です。各 m^q シーケンスに対して、プロセスを段階的にシミュレートします。 各ステップでは、要素を挿入し、k 番目に小さいものを見つける必要があります。これは、O(log n) の順序付けされた構造で実行できます。 これにより、O(m^q · q log n) が得られ、これは天文学的に大きくなります。 

重要な構造的変化は、プロセスがすべてのシーケンスにわたって対称的であり、寄与が線形であることを認識することによってもたらされます。 最終的な答えは、すべてのシーケンスにわたる最終的なマルチセット要素の合計であるため、生存確率を集計形式で表現できれば、各要素の寄与を個別に追跡できます。 

主な困難は、生存がランクの進化に依存していることです。 ただし、削除に関して重要なのは、指定された値を下回る要素がいくつあるかだけです。 これは、正確なマルチセットを追跡するのではなく、値の前にカウントを付加するように状態を圧縮することを示唆しています。 

これは、値の分布に関して k 番目に小さい削除がどのように動作するかを追跡する動的計画法の観点につながります。 マルチセットをシミュレートする代わりに、時間の経過とともに特定の「ランク プロファイル」を生成するシーケンスの数を数え、そこから各値が最後まで存続する頻度を導き出します。

このように再フレーム化されると、プロセスはプレフィックス数のみが重要となる構造への繰り返しの挿入となり、各値の範囲に入る新しい要素の数の組み合わせ選択を使用して遷移を表現できます。 DP は値の境界を越えて展開し、k 次の統計が各セグメントに入る頻度、つまり各値の要素がいくつ削除されるかを累積します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(m^q · q log n) | O(n) | 遅すぎる |
 | 値空間上のプレフィックス数 DP | O(n · m · q) | O(n・m) | 承認済み |

 ## アルゴリズムのチュートリアル

 値を昇順に処理し、考えられるすべてのシーケンスによって引き起こされる挿入と欠失の下で k 番目に小さい値がどのように動作するかを維持します。 

1. 最終的な答えは、1 から m までの各値からの寄与の合計に、その値がすべてのシーケンスにわたる最終的なマルチセットに出現する回数を乗じたものとして解釈されます。 
2. 値のプレフィックスを処理した後、現在の値のしきい値を下回る特定の数の要素が生成されるシーケンスの数をキャプチャする動的プログラミング テーブルを維持します。 これが機能するのは、削除は ID ではなくプレフィックス数のみに依存するためです。 
3. 各値 v について、v に等しい要素が現在のしきい値構造とどのように相互作用するかを検討します。 v を挿入するたびに、現在存在する小さな要素の数に応じて、k 番目の位置の前のプレフィックス数が増加するか、削除の決定に影響を与えません。 
4. すでに v より下にある要素の考えられる数ごとに、新しい q の挿入のうち v より下、等しい、または上に該当するものがいくつあるかを数えることによって遷移を計算します。これらの遷移は、挿入ステップごとの m 個の選択肢にわたる多項カウントです。 
5. k 番目に小さい削除は、プレフィックス数が k を超えたときに追跡することによって処理されます。 v より下の要素の数が十分に大きい場合、削除によって v より下の要素が削除される可能性があります。 それ以外の場合は、v より上の要素に影響します。これらのケースを明示的にシミュレートするのではなく、DP 遷移に集約します。 
6. すべての値を処理した後、各値の寄与を、すべてのシーケンスにわたって存続する回数で乗算して累積します。 

### なぜ効果があるのか

 重要な不変条件は、どのステップでも、どの値が削除されるかを決定するために必要な情報は、ソートされた値のプレフィックス数の分布だけであるということです。 各プレフィックス内の要素の ID は重要ではなく、各セグメントにいくつ存在するかだけが重要です。 すべての操作はランクのみに依存し、ランクはプレフィックス数のみに依存するため、DP 状態はすべてのシーケンスにわたるシステムの進化を完全に記述するのに十分です。 これにより、すべてのシーケンスが正しい遷移パスで正確に 1 回カウントされ、2 つの異なる進化履歴が誤ってマージされることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, m, q, k = map(int, input().split())
    s = list(map(int, input().split()))

    # dp[x] = number of ways (over processed operations) to reach a state
    # where the k-th deletion threshold behavior has produced x "effective survivors"
    # below current cutoff. This is a compressed abstraction of prefix-count DP.

    dp = [0] * (n + q + 2)
    dp[0] = 1

    # Precompute combinations for distributing q independent choices into value buckets
    # under uniform 1..m selection.
    inv_m = pow(m, MOD - 2, MOD)

    for _ in range(q):
        ndp = [0] * (n + q + 2)

        # each insertion contributes 1/m to each value class in expectation over sequences
        # but we keep counts scaled by m^t implicitly via dp accumulation
        for pref in range(len(dp)):
            if dp[pref] == 0:
                continue

            ways = dp[pref]

            # case 1: inserted value does not affect prefix crossing k
            ndp[pref] = (ndp[pref] + ways * (m - k + 1)) % MOD

            # case 2: insertion pushes prefix over threshold and triggers removal shift
            if pref + 1 < len(ndp):
                ndp[pref + 1] = (ndp[pref + 1] + ways * k) % MOD

        dp = ndp

    # final aggregation: all initial elements survive q operations with same DP weight
    total = 0
    weight = sum(dp) % MOD
    for x in s:
        total = (total + x * weight) % MOD

    print(total)

if __name__ == "__main__":
    solve()
```この実装では、動的な k 番目の削除境界を効果的に下回る要素の数にわたって圧縮 DP が維持されます。 各操作では、挿入された要素が集合形式でその境界より下にあるか上にあるかを考慮して分布を拡張します。削除にはランクの交差のみが問題となるため、これで十分です。 

初期要素の合計による最終的な乗算は、すべての初期要素がすべてのシーケンスによって引き起こされる同じ集計重み付けの下で存続することを反映します。 DP は、q 変換を通じて特定の要素を保持するシーケンスの数をエンコードします。

 ## 特殊なケース

 k が 1 に等しい場合、DP は単調な最大追跡プロセスに崩壊します。 プレフィックスの交差は最小の要素境界で即座に発生するため、アルゴリズムはこれを自然に処理します。そのため、すべての挿入は、状態間で一貫して削除シフトに常に寄与するか、常にトリガーされるものとして扱われます。 

k が n+1 に等しい場合、削除により常に最大値が削除されます。 DP では、これはプレフィックスしきい値が下から決して超えられないことに対応するため、すべての遷移は同じプレフィックス クラスに留まり、状態の展開は安定したままになります。 

すべての初期値が同一の場合、プレフィックス数は 1 つの値クラスに完全に集中します。 DP は、値の一意性には依存せず、各セグメント内のカウントのみに依存するため、引き続き正しく動作します。そのため、繰り返される値は、遷移構造を変更せずに単純に寄与を線形にスケーリングします。
