 ## 解決策
 ## 問題の理解

 長さの順列が与えられています$n$そして、非常に特殊な種類の操作を使用して並べ替えるのがどれほど難しいかを考えたいと思います。 各操作でセグメントが選択されます$[l, r]$それを反転しますが、制約があります: 選択された左端点$l$前の操作と比較して厳密に増加する必要があります。 これは、進行するにつれてさらに右に向かってのみ反転を「開始」できることを意味します。 

任意の順列の場合、そのコストは、ソートされた恒等順列に変換するために必要な制約付き反転の最小数として定義されます。 

タスクは、単一の順列に対してこのコストを計算することではありません。 代わりに、固定の$n$、このコストをすべて合計しなければなりません$n!$順列を計算し、モジュロ結果を出力します。$10^9 + 7$。 

制約は入力スケールの観点から非常に大きく、最大で$10^5$テストケースと$n$まで$10^6$。 これにより、各順列を個別に処理したり、順列に依存する構造を構築したりするアプローチは即座に除外されます。 代わりに、ソリューションでは、すべての順列にわたって組み合わせてカウントできる構造特性の関数としてコストを特徴付ける必要があります。 

増加時の操作制限により、微妙なエッジケースが発生します。$l$。 素朴な解釈はそれを無視し、恣意的な反転を想定する可能性があり、コスト構造を大幅に過小評価することになります。 たとえば、$n = 3$、次のような順列$[2,3,1]$この制約の下では、標準のパンケーキ並べ替えモデルとは異なる動作をします。これは、左側の構造を通過した後に左側の構造を繰り返し修正することができないためです。 

もう 1 つの特殊なケースは、恒等置換そのものです。 そのコストは明らかにゼロであり、正しい合計を行うには、一般的な数式の過大なカウントによって誤ってカウントされないようにする必要があります。 

## アプローチ

 一見すると、パンケーキソートに似た貪欲なシミュレーションを使用して、各順列のコストを個別に計算しようとするかもしれません。 標準的な考え方は、最大の置き忘れられた要素を繰り返し見つけて、それを元の位置に戻すことです。 ただし、追加された制約は、$l$操作間で厳密に増加する必要があるということは、標準的な貪欲な引数を根本的に破ります。 プレフィックスに対してローカルに機能する貪欲なアルゴリズムは、以前の位置を再訪することができないため、早期の決定は後の修正を永久に制限します。 

すべての順列をシミュレートしようとしたとしても、複雑さは次のオーダーになります。$O(n \cdot n!)$、これは直ちに実行不可能です。 

重要な観察点は、$l$すべての操作を強制的に配列の領域に「コミット」し、その領域が再び反転の開始点になることはありません。 これは、プロセスが順列をセグメントに分割し、各セグメントを独立して固定できるようにし、各操作で新しい左端の未解決の位置を効果的に解決することを意味します。 

この観点から、順列のコストは、すでに左から部分的にソートされているように、順列を拡張できない「臨界境界」の数になります。 これらの境界は、接頭辞が最終的な並べ替え順序に対して有効な増加構造をまだ形成していない位置に正確に対応します。 

これにより、問題は順列に対する操作のシミュレーションから、すべての順列にわたって特定の構造遷移がどのくらいの頻度で発生するかをカウントすることに変わります。 このように再構成すると、位置と値の組み合わせカウントを使用して、すべての順列の合計を閉じた形式で表現できるようになり、最終的な答えをすべての順列に対して事前に計算できます。$n$線形回帰を使用します。

 ## アルゴリズムのチュートリアル

 この解決策は、考えられるそれぞれの寄与を事前に計算することに依存しています。$n$要素の挿入時に順列がどのように増加するかから派生した再帰を使用する$n$。 

1. 関数を定義します$dp[n]$長さのすべての順列にわたるコストの合計として$n$。 目標は計算することです$dp[n]$みんなのために$n$最大クエリ値まで。 
2. サイズの順列がどのように変化するかを考慮します$n-1$サイズの順列に拡張する$n$要素を挿入することで$n$どの位置でも。 挿入のたびに、「未分類の境界」の構造が予測可能な方法で変更されます。 重要なのは、$n$新しい強制操作を作成するか、その位置に応じてコストを保存します。 
3. いつ$n$を最後に挿入しても、既存の構造に影響を与えることはないため、以前のコストはすべて変わりません。 先に挿入すると、追加の無秩序が導入され、配置される順列の数に比例して、必要な追加操作が 1 つだけ発生します。$n$指定されたしきい値位置の前。 
4. すべての挿入位置を合計すると、総コストの増加が次の要素のみに依存する移行が生じます。$n$そして$dp[n-1]$の挿入により追加の操作が発生する順列の数をカウントする組み合わせ係数とともに、$n$。 
5. これにより、次の形式が繰り返されます。$$dp[n] = n \cdot dp[n-1] + f(n)$$どこ$f(n)$可能な各位置に最大の要素を配置することによって導入される新しい「最初の違反ポイント」の合計数を示します。 この項は多項式に簡略化されます。$n$すべての順列の合計後。 
6. 階乗を事前計算し、モジュラー算術を使用して最大値まで反復的に漸化式を評価します。$n$すべてのテストケースにわたって。 

### なぜ効果があるのか

 正確かどうかは、順列を段階的に構築するプロセスを観察し、最大要素の挿入が必要な操作の数にどのような影響を与えるかを追跡することに依存します。 重要な不変条件は、将来の操作に関連するすべての構造が、最初の未解決の位置の左側の相対順序にのみ依存するということです。 挿入してから$n$その構造にローカルでのみ影響を与えるため、コストへの寄与は完全な置換履歴とは独立して集計できます。 この切り離しにより、重複カウントや省略が発生することなく、繰り返しによって合計寄与度が正確に取得されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    ns = [int(input()) for _ in range(t)]
    max_n = max(ns)

    if max_n == 0:
        return

    dp = [0] * (max_n + 1)

    if max_n >= 1:
        dp[1] = 0

    # Precompute factorials (used implicitly in derivation context)
    fact = [1] * (max_n + 1)
    for i in range(2, max_n + 1):
        fact[i] = fact[i - 1] * i % MOD

    # Derived closed recurrence (collapsed contribution form)
    for n in range(2, max_n + 1):
        # transition derived from insertion analysis
        dp[n] = (n * dp[n - 1] + (n - 1) * fact[n - 1]) % MOD

    out = []
    for n in ns:
        out.append(str(dp[n]))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```寄与項は、最大の要素を挿入するときに影響を受ける置換の数を自然にカウントするため、実装では最初に階乗を事前計算します。 定期的な更新`dp[n]`から`dp[n-1]`一定時間で、これがソリューションを実行可能にするものです$n$まで$10^6$。 

用語`(n - 1) * fact[n - 1]`サイズのすべての順列に対応します$n-1$左境界制約により新しい強制操作を作成する挿入位置の数を乗算します。 の乗算`n`の上`dp[n-1]`サイズの各順列が次のとおりであるという事実を説明します。$n-1$に拡大します$n$サイズの順列$n$。 

よくある落とし穴は、寄与が挿入位置間で対称ではないことを忘れることです。 特定の構造ブレークポイントの前に最大要素を移動する位置のみがコストを増加させます。

 ## 特殊なケース

 のために$n=1$、順列が 1 つだけ存在し、すでにソートされています。 アルゴリズムが初期化されます`dp[1] = 0`、繰り返しは適用されないため、出力は正しいままになります。 

小型用$n$のような$n=2$、反転は 1 つだけ存在し、反復により次の結果が生成されます。`dp[2] = 1`これは、単一の未ソート順列に対して 1 つの操作が必要であるという事実と一致します。 

大型の場合$n$、階乗項が成長を支配します。 このアルゴリズムはこれをモジュロ演算で安全に処理し、すべての演算が線形であるため、オーバーフローや順列ごとの構造の再計算のリスクはありません。
