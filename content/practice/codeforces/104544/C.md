 ## 解決策
 ## 問題の理解

 ノード 1 をルートとするルート付きツリーが与えられます。 各クエリは個別のノードのサブセットを選択し、そのサブセットから正確に k 個のノードのグループを取得したときに、どの程度「深い」共通祖先が形成されるかを分析するように求められます。 

選択された任意の k ノードについて、通常の意味で LCA を計算できます。つまり、それらの k ノードからルートまでのすべてのパス上にあるツリーの最下位ノードです。 次に、この問題では、指定された m ノードの考えられる k サイズのサブセットをすべて調べ、そのようなサブセットごとに LCA を計算し、これらの LCA 結果をすべて収集することが求められます。 

これらすべての LCA の中で、ツリーの最も深いもの、つまりルートから最も遠いものにのみ焦点を当てます。 出力は、その最大の深さを達成する個別のノードの数です。 

非常に重要な意味で、制約は小さいです。 テスト ケースごとに最大 1000 個のノードがあり、すべてのテストで合計 1000 個のクエリが存在します。 これは、クエリごとに二次関数に近いものは何でも許容できることをすぐに示唆していますが、サブセットの数は組み合わせ的に増加するため、すべての k サブセットを列挙することを伴うものは不可能です。 重要なのは、この定義ではすべての k サブセットについて説明していますが、ツリー内の LCA の構造により、この展開をサブツリー内のノードごとの数に圧縮できるという点です。 

よくある落とし穴は、サイズ k のサブセットを明示的に生成しようとしたり、サブセットごとに LCA プロセスを直接シミュレートしようとしたりすることです。 m = 30 の場合でも、サブセットの数が膨大になり、これはすぐに実行不可能になります。 

もう 1 つの微妙なエッジ ケースは、選択されたすべてのノードが、あるノードの単一のサブツリーに存在する場合です。 その場合、LCA は常にそのサブツリーのより深いところにあるため、そのノードは k サブセットの LCA になることはできません。 この「単一ブランチの優位性」は、総当たりの列挙に代わる主な構造的制約です。 

## アプローチ

 直接的な解釈は、指定された m 個のノードの k サイズのサブセットをすべて列挙し、標準的な LCA 構造を使用してそれらの LCA を計算し、最も深い結果を追跡することになります。 これは定義に文字通り従っているため、概念的には正しいです。 ただし、サブセットの数は$\binom{m}{k}$、そして中程度の m の場合でも、これは大きすぎます。 LCA クエリあたりのコストは、前処理の場合は対数または定数にすぎませんが、組み合わせ爆発がすぐに支配的になります。 

重要な観察は、実際にはサブセットを列挙する必要がないということです。 私たちが気にするのは、ノード x が何らかの k サブセットの LCA として現れることができるかどうか、そしてそれがそのような最も深いノードの中に入ることができるかどうかだけです。 これにより、問題はノードごとの構造的な実現可能性の確認に軽減されます。 

ノード x を修正します。 指定された m 個のマークされたノードが x に対してどのように分散されているかを考えてください。 それらは、正確に x であるノード (x がセット内にある場合)、および x の各子サブツリーにあるノードのグループに分割されます。 cnt[x] を x のサブツリー内のマークされたノードの総数とする。 

x が何らかの k サブセットの LCA であるためには、そのサブツリー内の k 個のノードを、単一の子サブツリーにすべて含まれないように選択できなければなりません。 すべての k ノードが 1 つの子サブツリー内に完全に存在する場合、LCA は x よりも深くなります。 したがって、選択したセットに寄与する x の下のノードの少なくとも 2 つの「ソース」が必要です。 

これにより、問題は、x のサブツリーに十分なマークされたノードがあるかどうか、およびそれらのノードが少なくとも 2 つの異なるブランチに分散されているかどうか (セット内にある場合、x 自体が別のブランチを形成する可能性を含む) をチェックすることに集約されます。 

この条件が特定されると、タスクは簡単になります。すべての有効なノード x の中で、最大の深さを計算し、それを達成するノードの数を数えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | k サブセットに対するブルート フォース | O(選択(m, k) · LCA) | O(n) | 遅すぎる |
 | ノードごとのサブツリー数 | O(n + q · n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、親と深さの情報を前処理して、サブツリーの関係を自然に操作できるようにします。 

各クエリについて、最初に選択された m 個のノードをマークします。 次に、すべてのノード x について cnt[x] を計算します。これは、x のサブツリー内で選択されたノードの数です。 これは、ツリー上の単一の DFS で実行できます。 

サブツリーの数がわかったら、各ノード x を潜在的な答えの候補として評価します。 

1. ポストオーダー DFS を使用して、すべてのノードの cnt[x] を計算します。 これにより、各サブツリーで選択されたノードの数が得られます。 
2. 各ノード x について、選択したノードがその直接のブランチ全体にどのように分散されているかを決定します。 これは、x が選択されている場合は x 自体からの寄与と、cnt[child] > 0 の各子サブツリーからの寄与で構成されます。 
3. x に空ではないコンポーネントがいくつ存在するかを数えます。 コンポーネントは、x 自体 (選択されている場合)、または少なくとも 1 つの選択されたノードを含む子サブツリーのいずれかです。 
4. cnt[x] が k 以上であるかどうかを確認します。 そうでない場合、x はそのサブツリー内で k サブセット全体をホストすることができないため、直ちに破棄されます。 
5. x に少なくとも 2 つの空でない成分があり、cnt[x] >= k の場合、x は何らかの k サブセットの LCA になることができます。 
6. そのようなすべての有効なノードの中で、最大深さを計算し、それを達成するノードの数を数えます。 

深さの選択が機能する理由は、より深いノードはより厳密な祖先を表すため、「可能な限り低い LCA」という意味で、より深い有効なノードが浅いノードよりも優先されるためです。 

### なぜ効果があるのか

 x のサブツリー内のすべての k サブセットは、そのサブツリー内のどこかにその LCA を持ちます。 x 自体が LCA になる唯一の方法は、選択したノードを x の単一の子サブツリーに限定できない場合です。 これにより、LCA はさらに深くならずに x まで移動することになります。 サブツリー数条件により、十分なノードが存在することが保証され、複数コンポーネント条件により、単一の分岐に強制されないことが保証されます。 これら 2 つの条件は、問題で定義されているように、x が S₁ にいつ現れるかを正確に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n, q = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(n - 1):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    parent = [0] * (n + 1)
    depth = [0] * (n + 1)
    order = []

    # build rooted tree
    stack = [1]
    parent[1] = -1
    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            depth[v] = depth[u] + 1
            stack.append(v)

    for _ in range(q):
        tmp = list(map(int, input().split()))
        k, m = tmp[0], tmp[1]
        vs = tmp[2:]

        mark = [0] * (n + 1)
        for x in vs:
            mark[x] = 1

        cnt = [0] * (n + 1)

        # postorder accumulation
        for u in reversed(order):
            cnt[u] = mark[u]
            for v in g[u]:
                if v == parent[u]:
                    continue
                cnt[u] += cnt[v]

        best_depth = -1
        ans = 0

        for u in range(1, n + 1):
            if cnt[u] < k:
                continue

            components = 0
            if mark[u]:
                components += 1

            for v in g[u]:
                if v == parent[u]:
                    continue
                if cnt[v] > 0:
                    components += 1

            if components >= 2:
                d = depth[u]
                if d > best_depth:
                    best_depth = d
                    ans = 1
                elif d == best_depth:
                    ans += 1

        print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```ツリーは反復 DFS を使用してテスト ケースごとに 1 回ルート化されるため、再帰の深さの問題が回避されます。 次に、固定の走査順序を再利用して、各クエリのサブツリー数を迅速に計算します。 

重要な部分は、ノードごとの実現可能性チェックです。 私たちはサブセットについて直接推論しようとはしません。 代わりに、問題を、ノードの削除によって引き起こされる分解全体にわたってマークされたノードがどのように分布するかに落とし込みます。 

微妙な詳細の 1 つは、ノードが選択されたセットの一部である場合に、ノード自体を独自のコンポーネントとして扱うことです。 これが必要なのは、そうしないと、マークされたすべてのノードが子サブツリーに存在する必要があると誤って想定し、x 自体が有効な分割の形成に関与するケースを見逃してしまうためです。

## 特殊なケース

 重要なエッジ ケースは、選択されたすべてのノードが、あるノード x の単一の子サブツリー内に完全に存在する場合です。 その状況では、たとえ cnt[x] が大きくても、x を有効な LNCA 候補としてカウントすることはできません。 たとえば、S = {4, 5} のチェーン 1-2-3-4-5 では、ノード 2 の cnt[2] = 2 が、選択されたすべてのノードが 1 つの子方向にあります。 このアルゴリズムは、空ではないコンポーネントを 1 つだけ認識するため、ノード 2 を無効として正しくマークし、ノード 3 のみが最も深い有効な祖先になります。 

もう 1 つのエッジ ケースは、選択されたノード セットに候補ノード自体が含まれる場合です。 これは別のコンポーネントとしてカウントする必要があります。 そうしないと、x ∈ S であるノードが誤って拒否されてしまいます。 S = {x, u} で、u が別のサブツリーにあるツリーでは、子サブツリーが選択を分割しない場合でも 2 つのコンポーネントが作成されるため、x が有効になります。
