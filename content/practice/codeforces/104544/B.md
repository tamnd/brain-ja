 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの整数配列が与えられます。 各テスト ケースでは、すべての要素に何らかの整数係数を乗算することで配列全体をスケーリングする操作を実行できます。 これを何度でも繰り返すことができ、各乗算は 1 回の演算としてカウントされます。 

一連の演算後に重要となる唯一の量は、各配列の最大公約数です。 オリジナルの gcd が$G_a$そして$G_b$、操作後、次のようになります。$G_a \cdot A$そして$G_b \cdot B$、 どこ$A$そして$B$は、各配列に適用されるすべての乗算器の積です。 

目標は、使用する乗算演算の合計数を最小限に抑えながら、これらの最終的な gcd 値を等しくすることです。 

入力サイズはテスト ケース全体で大きいため、ソリューションは gcd を計算した後、テスト ケースごとに一定時間またはほぼ一定の時間で各答えを計算する必要があります。 値が大きく合計値が大きくなる可能性があるため、可能な乗算器の検索や演算のシミュレーションなどは不可能です。$n$合計すると数十万になります。 

一方の gcd がもう一方の gcd を割る場合、微妙な例外ケースが発生します。 その場合、1 回の乗算で 1 つの配列のすべてを修正できます。 どちらも他方を分割していない場合、1 回の操作では片側のみを拡大縮小するため、1 つのステップでそれらを位置合わせすることはできず、後で分割可能性の問題を「部分的に修正」することはできません。 

## アプローチ

 この問題を直接考える方法は、演算をシミュレートすることです。両方の配列で異なる乗算シーケンスを試し、それらの gcd が一致するかどうかを確認します。 これは、各演算で任意の整数乗数を選択できるため、分岐係数に制限がなく、小さな入力でも組み合わせが爆発的に増加するため、すぐに実行不可能になります。 

重要な観察は、配列を乗算するとその gcd がスケーリングされるだけであるということです。 配列の内部構造は無関係になります。 gcd のみが乗算的に進化します。 したがって、問題は 2 つの数値の変換に分解されます。$G_a$そして$G_b$いずれかの数値に任意の整数を掛ける演算を使用して等価にします。各演算のコストは 1 です。 

1 つの演算で任意の整数を乗算できるため、必要な係数を 1 ステップで適用できます。 つまり、要素の算術的複雑さは考慮しておらず、変更を適用する必要があるかどうかだけを考慮しています。 

そこで、2 つの数値を等しくするために必要な「サイドチェンジ」の最小回数は何回か、と考えます。 

もし$G_a = G_b$、操作は必要ありません。 

それらのいずれかに等しい目標値を選択できる場合、次のようにします。$G_a$の場合、乗算で到達できる場合にのみ反対側を修正する必要があります。 それはまさにいつでも可能です$G_a$の倍数です$G_b$。 対称的に、ターゲットを絞ることができます$G_b$の倍数であれば$G_a$。 

どちらも他方を除算しない場合、一方の単一の乗算ではギャップを埋めることができないため、両方の辺を少なくとも 1 回変更する必要があり、各辺を任意の公倍数にスケールするという 2 つの操作で十分です。

 ## アルゴリズムのチュートリアル

 1. 配列の gcd を計算します。$a$、呼んでください$G_a$。 これにより、配列全体が、すべての割り算制約を捕捉する単一の代表値に圧縮されます。 
2. 配列の gcd を計算します。$b$、呼んでください$G_b$。 同じ推論が対称的に当てはまります。 
3. もし$G_a$等しい$G_b$、両方の配列が変更せずにすでに条件を満たしているため、0 を返します。 
4. もし$G_a$分割する$G_b$、配列を乗算できるため 1 を返します。$a$いつか$G_b / G_a$そしてgcdを一致させます。 
5. もし$G_b$分割する$G_a$、対称的な理由から 1 を返します。 
6. それ以外の場合は、2 を返します。これは、どちらの gcd も単一のスケーリングではもう一方の gcd に変換できないため、公倍数を満たすように両方を一度調整する必要があるためです。 

重要な推論ステップは、各演算で乗算を完全に自由にできるため、配列ごとに複数の演算が必要ないということです。 

### なぜ効果があるのか

 一連の操作の後、各配列の gcd は、元の gcd に選択した整数の積を乗算したものになります。 1 回の操作で任意の整数を選択できるため、必要な乗算係数を 1 回のステップで適用できます。 したがって、唯一の構造上の制約は、2 つの初期 gcd 間の割り切り可能性です。 一方が他方を分割している場合は、1 回の調整でそれらを調整します。 そうでない場合は、両方とも移動する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        ga = 0
        for x in a:
            ga = gcd(ga, x)

        gb = 0
        for x in b:
            gb = gcd(gb, x)

        if ga == gb:
            print(0)
        elif ga % gb == 0 or gb % ga == 0:
            print(1)
        else:
            print(2)

if __name__ == "__main__":
    solve()
```この実装では、線形スキャンを使用して各配列をその gcd に縮小します。値が大きく、gcd を超える構造に依存できないため、これが必要です。 次に、決定ロジックは、以前に導出された可分性のケースを直接適用します。 

よくある間違いは、gcd ではなく個々の要素について推論しようとすることですが、演算は配列全体に対して均一に作用するため、要素レベルの推論は不要になります。 

## 実用的な例

 両方の配列がすでに同じ gcd を持っている場合を考えてみましょう。 計算後、両側が直ちに一致し、アルゴリズムは操作なしで早期に終了します。 

ここで、一方の gcd がもう一方の gcd の倍数である場合を考えてみましょう。 仮定する$G_a = 6$そして$G_b = 2$。 6 は 2 で割り切れるので、配列を乗算できます。$b$1 回の操作で 3 倍になり、gcd も 6 になります。 アルゴリズムは割り切れないことを検出し、1 を返します。 

最後に、gcd が 6 と 10 である場合を考えてみましょう。どちらも他方を分割しないため、単一のスケーリングでそれらを揃えることはできません。 公倍数に向かって両側を個別にスケーリングする必要があり、これには 2 つの演算がかかります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 各 gcd 計算では配列を 1 回スキャンします。 
| スペース | O(1) おまけ | 実行中の gcd 値のみを保存する |

 制約により合計が許可されます。$2 \times 10^5$要素があるため、テスト ケースごとに 1 つの線形パスで十分です。 すべての演算は単純な整数 gcd 計算であるため、ソリューションは制限内で快適に実行されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import math

    t = int(sys.stdin.readline())
    out = []
    for _ in range(t):
        n = int(sys.stdin.readline())
        a = list(map(int, sys.stdin.readline().split()))
        b = list(map(int, sys.stdin.readline().split()))

        ga = 0
        for x in a:
            ga = math.gcd(ga, x)

        gb = 0
        for x in b:
            gb = math.gcd(gb, x)

        if ga == gb:
            out.append("0")
        elif ga % gb == 0 or gb % ga == 0:
            out.append("1")
        else:
            out.append("2")

    return "\n".join(out)

# minimum case
assert run("1\n1\n5\n5\n") == "0"

# one step via divisibility
assert run("1\n2\n6 12\n2 4\n") == "1"

# two steps needed
assert run("1\n2\n6 10\n4 9\n") == "2"

# already equal complex arrays
assert run("1\n3\n2 4 6\n1 2 3\n") == "1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 同一の gcd | 0 | 操作は必要ありません |
 | 割り切れる gcd | 1 | シングルスケーリングの修正 |
 | 共素の不一致 | 2 | 両側の変更が必要 |
 | 構造化配列 | 1 | gcd 削減の正確性 |

 ## 特殊なケース

 重要なエッジ ケースは、配列が大きく異なって見えるにもかかわらず、同じ gcd を共有する場合です。 たとえば、次のような配列$[2, 4, 6]$そして$[3, 6, 9]$両方ともそれぞれ gcd 2 と 3 に減算され、どちらも他方を除算しないため、2 つの演算が必要になります。 

もう 1 つの微妙なケースは、個々の要素が関係を示唆しているのに、gcd が関係を示唆していない場合です。 たとえば、一方の配列にもう一方の配列に複数の数値が含まれている場合でも、問題となるのはグローバル gcd だけです。 このアルゴリズムは、すべての構造を単一の値に正しく圧縮し、誤解を招く要素レベルの位置合わせが決定に影響を及ぼさないようにします。
