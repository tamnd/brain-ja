 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースには、$n$分隊と$k$従業員のタイプ。 各分隊は長さのビットマスクとしてエンコードされます$k$、どこビット$j$その分隊に現在次のタイプの従業員が含まれているかどうかを示します$j$。 

各分隊を個別に、分隊ごとに 1 回だけ変更することができます。 変更は、その分隊から既存の従業員タイプを削除するか、欠落している従業員タイプをその分隊に追加することで構成されます。 概念的には、各分隊は最終的に元のビットの一部が任意の方向に反転された状態になりますが、操作は分隊ごとに 1 回だけです。

 ## アルゴリズムのチュートリアル

 私たちは選択されたビットのグローバル セットを維持し、分隊ごとに、現在含まれていないこれらの選択されたビットの数を追跡します。 

1. 配列を初期化する`miss[i] = 0`各分隊について、その分隊に欠けている選択されたビットの数を表します。 
2. からビット位置を反復します。$k-1$まで$0$。 上位ビットを含めることで最終的な答えに大きく貢献するため、上位ビットを最初に処理します。 
3. 候補ビットの場合$i$、それが各分隊にどのような影響を与えるかを計算します。 分隊が現在ビットを持っていない場合$i$、次に追加します$i$選択したセットに関して欠損数が増加します。 
4. このビットを追加することですべての間隔が維持されるかどうかを一時的に確認します。`miss[j] ≤ 1`。 いずれかの分隊に 2 つ以上の選択ビットが欠落している場合、このビットを含めることは不可能であるため、スキップします。 
5. 可能であれば、ビットを永続的に含めます$i$そして更新します`miss`それに応じて。 
6. すべてのビットを処理した後、次の合計として答えを計算します。$2^i$選択されたすべてのビットにわたって。 

重要な推論ステップは、操作をどのように解釈するかにあります。ビットをグローバルに選択すると、すべての分隊が 1 回のローカル調整後にそのビットを強制的に封じ込めるようになり、その 1 回の調整では、分隊ごとに欠落している選択ビット 1 つしか「修復」できません。 

### なぜ効果があるのか

 アルゴリズムは、現在選択されているビットのセットに対して不変条件を維持します。$S$、どの分隊にも最大で 1 ビットが欠けています。$S$。 これは、各分隊が 1 つの変更のみを実行できるという運用上の制約と一致するため、グローバル要件に対して最大 1 つの欠陥を修正できます。 新しいビットの追加を検討するときは、この不変条件が依然として維持される場合にのみそれを受け入れます。 ビットを降順で処理するため、実現可能性を維持しながら、ビットの重みに関して辞書編集的に寄与を最大化します。 これにより、選択されたセットが制約の下で最大になることが保証され、これは最適な効率に直接対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        miss = [0] * n
        chosen = 0

        # try bits from high to low
        for b in range(k - 1, -1, -1):
            can = True

            for i in range(n):
                has = (a[i] >> b) & 1
                if not has:
                    if miss[i] + 1 > 1:
                        can = False
                        break

            if not can:
                continue

            # apply bit
            chosen |= (1 << b)
            for i in range(n):
                if ((a[i] >> b) & 1) == 0:
                    miss[i] += 1

        ans = 0
        for b in range(k):
            if (chosen >> b) & 1:
                ans += (1 << b)

        print(ans)

if __name__ == "__main__":
    solve()
```実装は貪欲な構築に直接続きます。 の`miss`配列は中心的な状態です。各分隊が現在欠落している選択されたビットの数を測定します。 実行可能性チェックでは、選択した 1 つの欠落ビットを超える分隊が存在しないことが保証されます。これは、1 回の操作で修正することが不可能になるためです。 

貪欲ループはビットを高位から低位に処理し、一度拒否されたビットは決して再検討されないようにします。これは、バイナリ加重合計を最大化するための最適性要件と一致します。

 ## 特殊なケース

 最小限のケースが発生するのは、$n = 1$。 そのような状況では、1 つの分隊が 1 つの許可された変更を加えれば常にすべての要件を満たすことができるため、あらゆるビットが常に実現可能です。 アルゴリズムは上位から下位まですべてのビットを貪欲に含めます。`miss`分隊は 1 つしかないため、1 を超えることはありません。 出力はすべての合計になります$2^i$これは、1 つの分隊がグローバルな制限を課さないという事実と一致します。 

対照的なケースは、分隊がほぼバラバラな場合に発生します。 たとえば、各分隊に一意のビットが 1 つだけ含まれている場合、複数のビットを選択すると、同じ分隊内で複数の欠落カウントが強制され、早期に制約に違反します。 アルゴリズムは、どのチームもオーバーロードしない最上位ビットで正しく停止します。`miss`別のビットを含めようとするとすぐに 1 を超えます。 

これら 2 つの極端な結果は、制約が無関係な場合と制約が最大限に厳しい場合の両方でアルゴリズムが正しく動作することを示しています。
