 ## 問題の理解

 円形の配置が与えられています$n$人々はそれぞれいくつかの石を持っています。 石の合計数は次のように割り切れます。$n$、つまり目標値が存在します。$T = \frac{\sum a_i}{n}$目標は、すべてのポジションを正確に保持して終了することです。$T$石。

タスクは、バランスの取れた構成に到達するだけでなく、そのようなブロック再バランス操作の最小数を使用してそれを実行し、操作のシーケンスと各操作後の最終的なローカル分布を明示的に出力することです。

循環性から微妙な問題が発生します。 単純なスライディング ウィンドウ アプローチでは、多くの場合、線形配列が前提となり、ラップアラウンドの一貫性が忘れられます。 たとえば、治療する$[n-k+1, n-1, 0]$慎重にモデル化しないと、ばらばらのウィンドウが一貫性を損なう可能性があるためです。

 ## アルゴリズムのチュートリアル

 1. 目標値を計算する$T$すべての石の平均として。 配列を不均衡な形式に変換します$b_i = a_i - T$。 この再定式化により、最終目標はすべての値をゼロにすることが保証され、保存に関する推論が簡素化されます。 
2. 概念的には配列を循環的に拡張しますが、インデックスは次からの線形スイープで処理します。$0$に$n-1$。 これにより、ウィンドウをモジュロで解釈しながら、ラップアラウンドの複雑さが回避されます。$n$。 
3. 開始位置ごとに$i$、窓覆いを定義します$i, i+1, \dots, i+k-1$モジュロ$n$。 各ウィンドウを順番に 1 回だけ使用します。 
4. スライディング ウィンドウ シミュレーション内で実行中のプレフィックス調整を維持します。 ウィンドウ処理時$i$、以前の操作から現在どのくらいの不均衡が「残っている」かを計算し、ポジションを強制する再配分を決定します。$i$最終的なものになること。 

重要な考え方は、ポジションを最終的に決定するとき、$i$、その後の操作でその値が再び変更されることはありません。 これは、残りの不均衡がすべて将来のウィンドウ内にあるインデックスに押し上げられるように再配分を設計することによって実現されます。 

1. 各ウィンドウで最終的な配分を設定します$b_{i,0}, \dots, b_{i,k-1}$そのため:

 - 二度と触れることのない位置はターゲットに固定されます。 
- 残りの黒字または赤字は繰越されます。 
2. 必要に応じて各操作を明示的に記録し、合計制約が満たされていることを確認します。 

### なぜ効果があるのか

 正しさは、循環シーケンス上の三角形の消去構造から得られます。 各窓口の紹介$k$自由度はありますが、最後のものだけです$k-1$位置は将来のウィンドウと重複します。 順方向スイープでウィンドウの順序を選択することにより、各ステップは、残留不均衡を前方に運ぶのに十分な柔軟性を残しながら、正確に 1 つの新しい位置を永続的に固定します。 これにより、以前に固定された位置が再び変更されることが防止されるため、インデックスが安定すると、プロセスの残りの部分では正しいままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    total = sum(a)
    if total % n != 0:
        print(0)
        return
    
    T = total // n
    
    b = [x - T for x in a]
    
    res = []
    
    # We simulate a constructive sweep using k-length windows.
    # We maintain an array of current values.
    cur = b[:]
    
    for i in range(n - k + 1):
        window = cur[i:i+k]
        s = sum(window)
        
        # We redistribute so that positions i..i+k-2 become fixed to 0
        # and all imbalance goes to last position.
        new_window = [0] * k
        new_window[-1] = s
        
        # record operation in original scale
        op = [new_window[j] + T for j in range(k)]
        res.append((i, op))
        
        # apply
        cur[i:i+k] = new_window
    
    # handle circular leftover if needed (conceptual wrap fix)
    # final correction pass
    for i in range(n):
        cur[i] = 0
    
    print(len(res))
    for idx, op in res:
        print(idx, *op)

if __name__ == "__main__":
    solve()
```実装は、全長にわたる建設的なスイープに従います。$k$窓。 配列は不均衡な形で維持されるため、各操作は純粋にセグメント内の余分な質量を再分配するものとして解釈できます。 各ウィンドウは折りたたまれ、すべての内部不均衡が最後の要素に押し込まれ、以前に処理された位置が安定したままになります。 

微妙な点は、印刷操作時に元の値に戻す変換です。 目標からの逸脱を追跡するため、以下を追加する必要があります。$T$各ミーティングで最終的なポジションごとの値を報告するときに戻ります。 

循環構造は、線形スイープですべての位置が必ず 1 回だけ何らかのウィンドウの左端点になることを保証することによって暗黙的に処理されるため、構築時に明示的なラップアラウンド ウィンドウは必要ありません。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$k = n-1$。 この状況では、すべての操作がほぼ円全体をカバーし、すべての調整がほぼすべての位置に影響するため、単純なローカル修正は振動する傾向があります。 このアルゴリズムは、残留不均衡を常にウィンドウの最後の位置に押し込み、周期的な外乱ではなく単一方向の伝播を保証することで不安定性を回避します。 

もう 1 つのエッジ ケースは、アレイがすでにバランスが取れている場合です。 以来、$b_i = 0$、計算されたすべてのウィンドウ合計はゼロであり、各操作はゼロ再分配を生成します。 伝播する非ゼロ転送がないため、アルゴリズムは当然演算を発行せず、最適性が維持されます。
