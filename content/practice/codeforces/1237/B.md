 ## 解決策
 ## 問題の理解

 トンネルに入る車のタイムラインと、トンネルから出る同じ車の別のタイムラインが与えられます。 すべての車は各リストに 1 回だけ出現するため、両方のシーケンスは同じ識別子のセットの順列になります。 

トンネル内では追い越しは間接的にのみ検知可能です。 車が後から入ってきて早く出た場合、他の車を確実に追い越したとみなされます。 課題は、そのような「逆転パートナー」を少なくとも 1 台備えている車が何台あるかを数えることであり、これは、それらの車が少なくとも 1 回の強制追い越しイベントの責任があることを意味します。 

入力はサイズの 2 つの順列を提供します$n$。 1 つ目はエントリー順序を説明し、2 つ目は終了順序を説明します。 出力は、少なくとも 1 つのペアにおいて「後から入場し、先に入場する」要素として機能する車両の数です。 

制約$n \le 10^5$すべての車のペアにわたる二次ペアごとの比較は除外されます。 ナイーブ$O(n^2)$すべてのペアのチェックには最大で次のことが必要になります$10^{10}$制限時間をはるかに超えた比較。 問題を線形または線形に近い変換する必要があります。 

どの車両も順序にまったく違反しない場合、微妙なエッジケースが現れます。 たとえば、入場順序と退場順序が同じ場合、どの車にも罰金は課されません。 「位置間の不一致」を違反と誤って解釈する単純なアプローチでは、この完全に一貫したケースであっても、車両を誤ってカウントする可能性があります。 もう 1 つの注意が必要なケースは、すべての車両が退出順序に対して大幅に逆転している場合です。この場合、複数の車両に罰金が科せられる可能性がありますが、各車両が多くの逆転ペアに参加している場合でも、カウントされるのは 1 回だけです。 

## アプローチ

 ブルートフォース ソリューションがすべての車両をチェックします$(i, j)$。 各ペアについて、どちらかが後で入場し、どちらかが早く退場するかを決定します。 その場合、後から入ってきた車には罰金が科せられます。 これは定義から直接機能し、すべての反転条件を明示的にテストするので正しいです。 

ただし、このアプローチではすべてをチェックする必要があります。$\binom{n}{2}$ペア。 それぞれのチェックは、$O(1)$したがって、全体の複雑さは次のようになります。$O(n^2)$。 と$n = 10^5$、これはまったく不可能です。 

重要な点は、実際にはすべてのペアを調べる必要はないということです。 代わりに、位置を使用して両方のシーケンスを整列させることができます。 各車両を出口順序のインデックスにマッピングすると、入場シーケンスは出口位置の配列になります。 ここで問題となるのは、インデックスを特定することです。$i$後のインデックスが存在するように$j > i$より小さい値で。 言い換えれば、配列に「将来の最小違反」がある位置を探しています。 

これにより、問題は、変換された配列をスキャンして、各要素がその右側の要素よりも大きいかどうかをチェックするだけになります。 これを効率的に行うには、右側に見られる最小値を維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 車の ID から降車順序の位置までのマッピングを構築します。 これにより、入場シーケンス内の各車両をその出口インデックスに置き換えて、問題を単一の数値配列に変換できます。 追い越しの構造は出口での相対的な順序のみに依存するため、この変換ではすべての条件が維持されます。 
2. 配列を構築する`pos`どこ`pos[i]`時刻に進入した車両の降車位置です$i$。 これにより、問題は、後の要素がより小さいインデックスを見つけることに変換されます。 
3.トラバース`pos`これまでに見られた最小の出口位置を維持しながら、右から左へ。 この値は、「左側の誰かより早く退場する」ための最良の候補を表します。 
4. 各インデックスについて$i$、 比較する`pos[i]`最小のサフィックス値を付けます。 もし`pos[i]`が大きい場合は、入場順でその後に先に退場する車が存在することを意味するため、この車には罰金が科せられることになります。 
5. このようなインデックスをすべてカウントし、結果を返します。 

### なぜ効果があるのか

 エントリ順序を終了位置にマッピングした後、違反は配列内の反転、つまり前のエントリの方が後のエントリよりも大きな終了インデックスを持つことに正確に対応します。 右から左にスキャンすると、後から進入したすべての車両の中で最も早い退出がサフィックスの最小値であるという不変条件が維持されます。 現在の要素がこの最小値より大きい場合は、後から進入して先に退出した車の存在が保証され、明確な追い越しイベントの定義と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos = [0] * (n + 1)
    for i, car in enumerate(b):
        pos[car] = i

    arr = [pos[car] for car in a]

    mn = n + 1
    ans = 0

    for i in range(n - 1, -1, -1):
        if arr[i] > mn:
            ans += 1
        mn = min(mn, arr[i])

    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、出口位置マップを構築することから始まります。`pos`、各車の ID を出口インデックスに変換します。 次に、エントリシーケンスを次のように変換します。`arr`、比較は純粋に数値になります。 

変数`mn`これまでに右から見た最小の出口インデックスを格納します。 これは、後から入ってきた車両の中で最も早く出発した車両を表すため、非常に重要です。 現在の車両がこの最小値を超えて終了する場合、少なくとも 1 台の後の車両との明確な逆転を意味します。 

条件`arr[i] > mn`はアルゴリズムの中核であり、追い越しルールを直接エンコードします。

 ## 特殊なケース

 開始順序と終了順序が同じ場合、変換された配列は厳密に増加します。 サフィックスの最小条件は決してトリガーされないため、答えはゼロになります。 すべての要素が常に将来の最小値以下であるため、アルゴリズムはこれを正しく維持します。 

終了順序がエントリに対して完全に逆になると、すべての以前のエントリには、より小さい終了インデックスを持つ多くの後のエントリが含まれます。 サフィックスの最小値は早期にゼロになり、そこに留まるため、十分に大きな要素がすべてカウントされ、ほとんどの車が罰金として正しくマークされます。 

ソートされた置換における単一のスワップなど、1 つのペアのみがローカルで反転される場合、スワップに先行する要素のみが後のサフィックスの最小値を超えます。 スキャンはその位置を正確に分離し、過剰カウントを防ぎます。
