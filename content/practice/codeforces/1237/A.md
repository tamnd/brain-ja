 ## 解決策
 ## 問題の理解

 コンテストからの評価の変更を表す整数のリストが与えられます。 これらすべての変更の合計は正確にゼロです。これは、変更を加える前に利益と損失が完全にバランスしていることを意味します。 

タスクは、各値を独立して「半分の」バージョンに変換することです。 元の値ごとに$a_i$、床か天井のどちらかのみを選択できます。$a_i / 2$。 もし$a_i$が偶数の場合、両方の選択肢が一致するため、結果は固定されます。 もし$a_i$これは奇妙です。1 つ異なる候補がちょうど 2 つあります。 

難しいのは、各値を個別に選択することではなく、最終的に変換されたシーケンスの合計がゼロになるようにこれらのローカルな選択を調整することです。 

常にすべてを切り捨てたり、すべてを切り上げたりする単純なアプローチでは、グローバル制約がすぐに破られます。 常に下限をとる場合、すべての正の奇数は負の数と比較して余分な質量を失い、合計はゼロ未満にドリフトします。 常に ceil を取ると、合計はゼロより大きく変動します。 この制約により、丸めの「余分な 2 分の 1 単位」がどこに配置されるかについて慎重なバランスが求められます。 

エッジ ケースは、すべての数値が奇数である場合、または正と負が大きく偏っている場合に発生します。 たとえば、配列が次の場合、`[1, 1, -2]`、素朴な床材が与える`[0, 0, -1]`合計すると`-1`の代わりに`0`、素朴な天井が与えますが、`[1, 1, -1]`合計すると`1`。 各要素は個別には有効ですが、両方とも要件に違反します。 

重要な課題は、各奇数が ±0.5 の曖昧さをもたらし、合計の補正が相殺されるようにこれらを分散する必要があることです。 

## アプローチ

 丸めの制約を無視する場合、自然な考え方は次のように計算することです。$a_i / 2$そしてすべてを一貫して丸めます。 これで塩基配列が得られます$b_i = \lfloor a_i / 2 \rfloor$。 これは要素ごとに常に有効ですが、その合計がゼロになることは保証されません。 

以下を定義すると、エラーの構造が明確になります。$$b_i^{(0)} = \left\lfloor \frac{a_i}{2} \right\rfloor$$偶数の場合$a_i$、これは正確です。 奇数の値の場合:

 - もし$a_i > 0$、床は真の半分に対して 0.5 小さすぎます。 
- もし$a_i < 0$、floorも小さすぎますが、「小さすぎる」はよりマイナスを意味するため、その効果は符号の寄与が異なります。 

より具体的には、各奇数には 1 つの自由単位があります。オプションでその下限値を 1 増やすことができます (天井に切り替える)。 これにより、合計がちょうど 1 増加します。 

そこで問題は、ベースライン合計から開始し、合計が正確にゼロになるように、いくつかのインデックスに対して +1 を追加するかどうかを決定する必要があるということです。 

ベースラインをすべてのフロアとします。 その合計を$S$。 奇数の要素に床の代わりに天井を選択するたびに、合計が 1 ずつ増加します。正確に選択する必要があります。$-S$適格指数間の調整など。 

欠けている微妙な点は、実行可能性を確保することです。利用可能な奇数要素の数は、合計を範囲内に調整するのに十分でなければなりません。 問題によって与えられる条件により、これが常に成り立つことが保証されます。 

これにより、問題は独立した +1 増分にわたる単純な補正分布問題に変換されます。

 ## アルゴリズムのチュートリアル

 デフォルトの割り当てと制御された修正フェーズの 2 つのフェーズで答えを構築します。 

1. コンピューティング$b_i = \lfloor a_i / 2 \rfloor$すべての要素に対して。 
2. 合計を計算します$S = \sum b_i$。 
3. すべてのインデックスを特定します。$a_i$奇数です。 
4. このような各インデックスは、増加を可能にします。$b_i$必要に応じて 1 ずつ増やします。 
5. 次に、正確に分配して合計を修正する必要があります。$-S$増加します。 
6. 奇数のインデックスを繰り返し、それらのインデックスに +1 を適用します。$b_i$補正量がなくなるまで値を維持します。 
7. 結果の配列を出力します。 

重要な決定はステップ 6 です。どの奇妙な要素が選択されるかは気にせず、必要な補正予算を正確に消費することだけを考慮します。 各増分が合計に同じ影響を与えるため、どのような分布でも機能します。 

### なぜ効果があるのか

 不変条件は、初期化後、すべての要素が許容される最小値になることです。 このベースラインから有効な解に到達するには、選択した奇数の位置を 1 ずつ増やすだけで、要素ごとの制約に違反することなく合計が正確に +1 ずつ変化します。 必要な合計調整はベースライン合計とゼロの差であり、すべての調整はユニットサイズで独立して適用できるため、問題が実現可能性を保証する場合、補正ユニットを貪欲に消費してもオーバーシュートやアンダーシュートすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [int(input()) for _ in range(n)]

    b = [x // 2 for x in a]
    s = sum(b)

    need = -s

    # collect indices where we can add +1 safely (odd numbers)
    odd_idx = []
    for i, x in enumerate(a):
        if x % 2 != 0:
            odd_idx.append(i)

    for i in odd_idx:
        if need == 0:
            break
        # applying ceil instead of floor adds +1
        b[i] += 1
        need -= 1

    print(*b)

if __name__ == "__main__":
    solve()
```実装は構築ロジックに直接に従います。 整数の除算`x // 2`Python で正と負の両方の整数に対して下限動作を正しく生成します。これはここで重要です。 次に、ベースラインがゼロからどのくらい離れているかを計算し、利用可能な奇数の位置を使用して修正します。 

ループオーバー`odd_idx`調整するたびに残りの不均衡がちょうど 1 単位だけ減少するため、安全です。 問題保証により、適格なインデックスが不足することがなくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = [int(input()) for _ in range(n)]
    b = [x // 2 for x in a]
    s = sum(b)
    need = -s

    for i in range(n):
        if need == 0:
            break
        if a[i] % 2 != 0:
            b[i] += 1
            need -= 1

    return "\n".join(map(str, b)) + "\n"

 ## 特殊なケース

 微妙なケースの 1 つは、すべての数値が偶数である場合です。 この状況では、半分にした後にすべての値が固定されるため、元の制約によりベースラインの合計はすでにゼロになります。 アルゴリズムは計算します`need = 0`調整を行わず、配列は変更されないままになりますが、これは正しいことです。 

もう 1 つのケースは、すべての数値が奇数である場合です。 その後、すべてのインデックスが修正に使用できるようになります。 初期の不均衡は整数である必要があり、各補正は正確に 1 ずつ調整されるため、ループはバランスが回復するまで補正をすべてのインデックスに任意に分配するだけであり、容量が不足することはありません。 

より欺瞞的なシナリオは、次のような大きく偏ったネガティブな場合に発生します。`[-1, -1, 2]`。 ベースラインが生成するのは、`[ -1, -1, 1 ]`合計すると`-1`, そのため、1 つ修正が必要です。 最初の 2 つは奇数のインデックスのみであり、それをどちらかに適用すると、バランスの取れた有効な結果が生成されます。
