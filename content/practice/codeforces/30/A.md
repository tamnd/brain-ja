 ## 解決策
 ## 問題の理解

 3 つの整数が与えられます。`A`、`B`、 そして`n`。 タスクは整数値を見つけることです`X`次のような:$A \cdot X^n = B$

`A`王国の年間収入を表す`0`、`B`その後の収入を表します`n`年、そして`X`は年間成長係数です。 すべての値は整数のままである必要があります。`X`。 負の値も許可されます。`X`ゼロになることもあります。 

制約は非常に小さいです。 両方`A`そして`B`せいぜい`1000`絶対値で、そして`n`せいぜい`10`。 それは問題の性質を完全に変えます。 高度な数論や対数は必要ありません。 すべての妥当な整数候補に対する直接的な総当たり攻撃でも、制限時間内に簡単に収まります。 

難しいのはパフォーマンスではなく、符号とゼロの正確さです。 

危険なケースの 1 つは次のような場合です。`A = 0`。 

例えば：```
0 0 5
```方程式は次のようになります。$0 \cdot X^5 = 0$すべての整数`X`それを満足させます。 この問題では有効な答えを出力できるため、出力`0`大丈夫です。 

ただし、次のようになります。```
0 10 3
```得られるもの:$0 \cdot X^3 = 10$左辺は常に次のとおりであるため、これを満たす整数はありません。`0`。 

別の微妙なケースでは、否定的な答えと偶数の検出力が表示されます。 

考慮する：```
1 -8 2
```必要なものは次のとおりです。$X^2 = -8$偶数乗は負になることはありませんので、答えは次のようになります。`"No solution"`。 

ただし、次のようになります。```
1 -8 3
```私たちに必要なのは：$X^3 = -8$今`X = -2`奇乗は符号を保存するので機能します。 

浮動小数点ルートを使用した不注意な実装も失敗する可能性があります。 次のようなものを計算します`pow(64, 1/3)`生み出すかもしれない`3.999999999`の代わりに`4`、丸め間違いにつながります。 制約が小さいため、整数総当たり法では精度の問題がすべて回避されます。 

## アプローチ

 最も直接的なアイデアは、可能なすべての整数を試してみることです。`X`、計算する`A * X^n`と等しいかどうかを確認します`B`。 

なぜこれが機能するのでしょうか? 探索空間が狭いからです。 もし`|B| ≤ 1000`の場合、有効な整数ルートも適度に小さくなければなりません。 たとえば、次の場合`|X| ≥ 100`、その後は偶数`X²`すでに少なくとも`10000`、許容範囲を大きく外さない限り、`A = 0`。 

からのすべての整数を試します`-1000`に`1000`だけを与える`2001`候補者たち。 各候補について、べき乗を計算します。`10`。 これはわずか数万回の算術演算であり、本質的には瞬時に行われます。 

より数学的なアプローチでは、以下を分離します。$X^n = \frac{B}{A}$そして整数を計算しようとします`n`- 番目のルート。 問題は、符号、割り算、および浮動小数点の精度の処理が、元の問題そのものよりも厄介になることです。 制約が非常に小さいため、ブルート フォースは実際には最もクリーンで安全なソリューションです。 

すべての有効な答えは非常に狭い範囲内にある必要があるため、総当り攻撃が機能します。 それが分かれば、問題は単純な検索に帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての整数に対するブルート フォース | O(2000 × n) | お(1) | 承認済み |
 | 整数ルートの計算アプローチ | O(n) | お(1) | 受け入れられるが、不必要にエラーが発生しやすい |

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り`A`、`B`、 そして`n`。 
2. すべての整数を反復処理します。`x`から`-1000`に`1000`。 

この範囲は安全に十分な大きさであるため、`|B| ≤ 1000`。 それ以上の大きさがあると、`x^n`特別なゼロケースが発生しない限り、目標を大幅に上回ります。 
3. 各候補について、次を計算します。$A \cdot x^n$そしてそれを比較してください`B`。 
4. 等式が成り立つ場合、出力します。`x`すぐに終了してください。 

この問題では有効な解決策をすべて使用できるため、最初の解決策で十分です。 
5. 有効な整数が見つからないままループが終了した場合は、次のように出力します。`"No solution"`。 

### なぜ効果があるのか

 アルゴリズムは、方程式を満たす可能性のあるすべての整数候補をチェックします。 解決策が存在する場合、それはテスト範囲のどこかに出現する必要があるため、アルゴリズムは最終的にそれを見つけます。 方程式を満たす候補がない場合、整数解は存在しません。 

正確さは、すべての実行可能な整数値に対する徹底的な検索から直接得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

A, B, n = map(int, input().split())

for x in range(-1000, 1001):
    if A * (x ** n) == B:
        print(x)
        break
else:
    print("No solution")
```ループは、許可された範囲内のすべての整数候補を試行します。 Python の整数演算は、指数が整数で非負の場合、負の累乗を正しく処理します。`(-2) ** 3`になる`-8`そして`(-2) ** 2`になる`4`自動的に。 

の`for-else`ここで構造が役に立ちます。 の`else`ブロックは、ループがヒットしない場合にのみ実行されます。`break`、有効な解決策が見つからなかったことを意味します。 

範囲`[-1000, 1000]`意図的にシンプルになっています。 数学的により厳しい境界を導き出すこともできますが、利点はありません。 現在の検索サイズはすでに小さいです。 

どこでも整数演算を使用すると、浮動小数点精度の問題が完全に回避されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    A, B, n = map(int, input().split())

    for x in range(-1000, 1001):
        if A * (x ** n) == B:
            print(x)
            break
    else:
        print("No solution")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.getvalue().strip()

# provided sample
assert run("2 18 2\n") in ["3", "-3"], "sample 1"

# minimum values
assert run("0 0 1\n") == "-1000", "any integer works"

# impossible because A is zero
assert run("0 5 3\n") == "No solution", "zero times anything stays zero"

# negative root with odd exponent
assert run("1 -27 3\n") == "-3", "odd powers preserve sign"

# impossible with even exponent
assert run("1 -16 2\n") == "No solution", "even powers cannot be negative"

# maximum boundary style case
assert run("1 1000 1\n") == "1000", "largest positive root"

 ## 特殊なケース

 次の入力を考えてみましょう。```
0 0 5
```アルゴリズムは次からチェックを開始します`x = -1000`。 

次のように計算します。$0 \cdot (-1000)^5 = 0$これはすでに一致しています`B = 0`したがって、アルゴリズムはすぐに出力します`-1000`。 

奇妙に見えるかもしれませんが、それは完全に正しいです。 すべての整数がここの方程式を満たしており、ステートメントでは任意の有効な答えが許可されます。 

ここで次のことを考えてみましょう。```
0 10 3
```すべての候補者に対して`x`、左側は次のようになります。$0 \cdot x^3 = 0$以来`0`決して等しくない`10`、ループは成功せずに終了し、出力します。`"No solution"`。 

もう 1 つの重要なエッジケースは次のとおりです。```
1 -16 2
```アルゴリズムは以下のすべての整数をテストします。`-1000`に`1000`。 

否定的な候補者の場合:$(-x)^2 > 0$肯定的な候補者の場合:$x^2 > 0$正方形は常に非負であるため、ターゲットは`-16`決して現れることはできません。 徹底的な検索により正確にレポートされます`"No solution"`。 

最後に、次のことを考慮してください。```
2 18 2
```両方`x = 3`そして`x = -3`次の理由により、方程式が満たされます。$3^2 = (-3)^2 = 9$アルゴリズムは、最初に見つかった有効な値を返します。`-3`。 この問題では有効な解決策が明示的に許可されているため、この動作は正しいです。
