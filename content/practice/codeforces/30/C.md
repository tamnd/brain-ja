 ## 解決策
 ## 問題の理解

 私たちは、キング コパがシューティング ギャラリーで予想されるヒット数を最大化するのを手伝うように求められています。 ギャラリーは 2D 平面として表され、各ターゲットは特定の点に表示されます。$(x_i, y_i)$まさに特定の時間に$t_i$そしてその直後に消えてしまう。 キングのガンサイトがターゲットに現れたときに照準を合わせれば、確率で命中します。$p_i$。 照準器は単位速度で移動できるので、一点から狙うことができます$(x_1, y_1)$別の人に$(x_2, y_2)$、ユークリッド距離が必要です$\sqrt{(x_2-x_1)^2 + (y_2-y_1)^2}$時間の単位。 王はすべてのターゲットとそのタイミングを事前に知っており、ターゲットに当たる確率の合計が最大になるように一連の動きを計画したいと考えています。 

入力は次のもので構成されます$n$ターゲット ($1 \le n \le 1000$)、それぞれに座標、時間、確率が含まれます。 出力は、予想される最大ヒット数です。 

制約はいくつかの指針を与えてくれます。 と$n$1000まで、時間まで$10^9$、ナイーブなO($n^2$) 解決策は受け入れられますが、O($2^n$) は遅すぎます。 距離は負の値になる場合がありますが、ユークリッドの移動コストのみを考慮します。 確率は 0 から 1 までの実数です。 

明らかでないエッジ ケースには、時刻 0 で確率が 1 未満の単一ターゲット、時間的に非常に近くにクラスター化されているためその間を移動することが不可能な複数のターゲット、または無視すべき確率 0 のターゲットが含まれます。 たとえば、次の入力を使用します。```
1
0 0 0 0.5
```出力は0.5です。 キングが全ヒット (0 または 1) のみを得点できると想定する単純なアルゴリズムは、ここでは失敗します。 

もう 1 つの注意が必要なシナリオは、2 つのターゲットが遠すぎて時間内に到達できない場合です。```
2
0 0 1 1
1000 1000 2 1
```それでも$t_2 > t_1$、距離が大きすぎるため、王は時間内に 2 番目の目標に到達できません。 不注意な解決策では、両方を試行し、過大なカウントを試みる可能性があります。 

## アプローチ

 強引な解決策は、ターゲットのすべての順列を考慮し、キングが時間内に次のターゲットに移動できるかどうかを計算し、確率を合計することです。 これは、すべてのシーケンスを探索するため、正確性を保つために機能しますが、順列の数は次のようになります。$n!$、これは完全に不可能です$n=1000$。 

重要な洞察は、ターゲットを達成することは期待とは独立しているため、これを動的プログラミングの形式としてモデル化できるということです。 時間の増加順に目標を分類する場合は、各目標を達成した場合に達成できる最高の期待値のみを考慮する必要があります。 ターゲット向け$i$、以前のすべてのターゲットを確認できます$j$到達できるのは$i$時間内に$t_i - t_j \ge \text{distance}(i, j)$、そして次を計算します:$$dp[i] = p_i + \max(dp[j] \text{ for all valid } j)$$以前の目標が到達できない場合$i$、任意の場所で時間 0 から開始できます。これは次のように単純化されます。$dp[i] = p_i$。 これにより、次の問題が軽減されます。$O(n!)$に$O(n^2)$を考慮すると許容範囲です$n \le 1000$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべての順列) | お(ん!) | O(n) | 遅すぎる |
 | 時間ソートを使用した動的プログラミング | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのターゲットを読み取り、タプルとして保存します$(x_i, y_i, t_i, p_i)$。 
2. ターゲットを出現時間順に並べ替える$t_i$。 これにより、DP で検討した以前のターゲットは現在のターゲットより前に出現することが保証されるため、過去のみを参照します。 
3. DP 配列を初期化する`dp[i]`ターゲットで終了する予想される最大ヒット数を保存する$i$。 
4. 時間の増加順にターゲットを繰り返します。 ターゲットごとに$i$、最初は仮定します`dp[i] = p_i`、時間 0 の初期位置からこのターゲットで直接開始することを表します。 
5. 以前のターゲットごとに$j < i$、キングが移動できるかどうかを確認します。$j$に$i$利用可能な時間内に。 ユークリッド距離を計算する$\text{dist} = \sqrt{(x_i - x_j)^2 + (y_i - y_j)^2}$。 もし$t_i - t_j \ge \text{dist}$、 アップデート`dp[i] = max(dp[i], dp[j] + p_i)`。 
6. すべてのターゲットを処理した後、シーケンスはどのターゲットでも終了する可能性があるため、答えは DP 配列の最大値になります。 

なぜ機能するのか: DP の不変条件は次のとおりです。`dp[i]`最後のターゲット ヒットが次の場合に達成できる最適な予想ヒット数です。$i$。 期待は加算的であり、以前のターゲットからの実行可能な遷移を常に考慮するため、考慮されるすべてのシーケンスが有効であることが保証され、より良いシーケンスを見逃すことはありません。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

n = int(input())
targets = []
for _ in range(n):
    x, y, t, p = input().split()
    x = int(x)
    y = int(y)
    t = int(t)
    p = float(p)
    targets.append((t, x, y, p))

targets.sort()  # sort by time

dp = [0.0] * n

for i in range(n):
    t_i, x_i, y_i, p_i = targets[i]
    dp[i] = p_i  # start directly at this target
    for j in range(i):
        t_j, x_j, y_j, _ = targets[j]
        dist = math.hypot(x_i - x_j, y_i - y_j)
        if t_i - t_j >= dist:
            dp[i] = max(dp[i], dp[j] + p_i)

print(f"{max(dp):.10f}")
```コードはターゲットをタプルとして読み取り、保存します。`(t, x, y, p)`したがって、時間による並べ替えは簡単です。`math.hypot`手動の二乗や平方根を避けるために、ユークリッド距離に使用されます。 DP の初期化`p_i`原点または任意の初期位置からターゲットで始まるハンドル。 全てチェック中`j < i`有効な以前のポジションをすべて考慮するようにします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | n 個のターゲットのそれぞれについて、以前のすべてのターゲットを考慮するため、n*(n-1)/2 の比較 |
 | スペース | O(n) | DP 配列はターゲットごとに 1 つの浮動小数点を格納します。 

n ≤ 1000 の場合、O(n^2) = 10^6 の演算となり、2 秒の制限内に問題なく収まります。
