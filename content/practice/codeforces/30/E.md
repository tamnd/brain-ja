 ## 解決策
 ## 問題の理解

 単一の小文字文字列が与えられます。 この文字列内のどこかに、奇数の長さの隠れた回文が存在しますが、回文は 3 つの連続する部分に分割されています。 

- 接頭辞、
 - 中間部分、
 - 接尾辞。 

接頭辞と接尾辞は元の回文から対称的に切り取られたため、同じ長さになります。 元のパスワードは回文であるため、サフィックスはプレフィックスのまったく逆になります。 中央部分は単独では奇数長の回文のままです。 

回文を分割した後、これら 3 つの部分の間に任意のガベージ文字列が挿入されました。 最終的に表示される文字列は次のようになります。`A + prefix + B + middle + C + suffix`私たちの仕事は、可能な限り長いオリジナルの回文を復元することです。 回文自体を出力する必要はありません。 代わりに、入力文字列内の選択された部分の位置を出力します。 

3 つの部分は順番に出現する必要があります。 中間部分はプレフィックスとサフィックスのいずれも重なりません。 空の部分は構造内で内部的に許可されますが、最終出力には空ではない部分のみが含まれます。 

入力長は最大でも`10^5`これにより、重い定数を含む 3 次アルゴリズムや 2 次アルゴリズムさえも即座に除外されます。 部分文字列のトリプルをすべて総当たりで調べると、遅すぎます。 プレフィックスとサフィックスの位置のすべてのペアをチェックしても、すでにおおよその結果が得られます`10^10`可能性。 線形に近いものが必要です。`O(n log n)`。 

難しいのは、3 つの回文作品が任意のジャンクによって分離されていることです。 連続した回文を探しているわけではありません。 ちょうど 3 つの連続したブロックから構成されるサブシーケンスを探しています。 

いくつかのエッジケースでは、単純な実装が静かに破壊されます。 

考慮する：```
aaaaa
```文字列全体がすでに奇妙な回文になっています。 最適な答えは 1 つのセグメントのみを使用します。 常に 3 つの部分を構築しようとする不注意なソリューションでは、結果が短くなる可能性があります。 

考慮する：```
abxyba
```最良の施工は、`"ab" + "y" + "ba"`、全長`5`。 中間部分自体が奇妙な回文になっているはずです。 ピッキング`"xy"`中央は長さが偶数であるため無効です。 

考慮する：```
abc
```一致するプレフィックスとサフィックスが存在しません。 すべての 1 文字の文字列は奇数回文であるため、最良の答えは任意の 1 文字です。 

もう 1 つの微妙なケースは、セグメントが重なっている場合です。```
abacaba
```最適な答えは文字列全体です。 プレフィックスを取得しようとすると`"aba"`と接尾語`"aba"`重複をチェックせずに単独で実行すると、誤って文字を再利用してしまう可能性があります。 

中心的な課題は、以下を同時に最大化することです。```
2 * len(prefix) + len(middle)
```順序と回文の制約を維持しながら。 

## アプローチ

 ブルートフォースのアイデアは単純です。 考えられるすべての中間回文を列挙し、その周囲に一致する可能性のあるすべての接頭辞と接尾辞を試します。 

中間の回文間隔を固定するとします。`[l, r]`。 ここで最も長い文字列が必要になります`X`そのような`X`前に現れます`l`そして`reverse(X)`後に表示されます`r`。 

単純な実装では、左側の部分文字列をすべて列挙し、それらを反転された右側の部分文字列と文字ごとに比較できます。 がある`O(n^2)`候補部分文字列と各比較にはコストがかかる場合があります`O(n)`、につながる`O(n^3)`全体的な複雑さ。 

ハッシュを使用して部分文字列の比較を最適化しても、依然として間隔の組み合わせが多すぎます。 と`n = 10^5`、おおよそ以上のもの`10^7`Python では操作が危険になります。 

重要な観察は、構造が 2 つの独立したコンポーネントに自然に分割されることです。 

まず、中間部分は奇数の回文部分文字列である必要があります。 これは、Manacher のアルゴリズムを使用して効率的に事前計算できます。 

第 2 に、プレフィックスとサフィックスは互いに逆にするだけで済みます。 これは、順序制約のある、元の文字列とその逆文字列の間の最も長い共通部分文字列の問題です。 

文字列全体を次のように反転するとします。`t`。 位置で終わる部分文字列`i`で`s`のマップされた位置から始まる反転された部分文字列に対応します。`t`。 ローリング ハッシュまたはサフィックス構造を使用して、位置間で一致する最長拡張子を計算できます。 

ここで問題は次のようになります。 

奇数回文間隔ごとに`[l, r]`、その周囲で一致する最大のペアを見つけます。 

- 左の部分が前に終了します`l`、
 - 右の部分は後から始まります`r`、
 - 2 つの部分が逆になっています。 

すべての中心について効率的にそれに答えることができれば、最適な全長が得られます。 

承認されたソリューションでは、次の 3 つの成分が使用されます。 

- すべての奇妙な回文の管理者、
 - 部分文字列が等しい場合のローリング ハッシュ、
 - ミラー化された部分を一致させるための二分探索または LCP 計算。 

全体の複雑さは次のようになります。`O(n log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n²) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. Manacher のアルゴリズムを使用して、すべての奇数回文半径を計算します。 

各センターごとに`i`、最大半径を取得します`d[i]`次のような:```
s[i - d[i] + 1 ... i + d[i] - 1]
```回文です。 
2. 文字列を次のように反転します。`t`。 

これにより、逆一致チェックを通常の部分文字列の等価性チェックに変換できます。 
3. 両方のローリング ハッシュを構築する`s`そして`t`。 

多くの候補の接頭辞と接尾辞のペアがテストされるため、高速な部分文字列比較が必要です。 
4. 考えられるすべての中間回文について、その間隔を決定します。`[L, R]`。 

回文の中心が次の場合`i`半径があります`d[i]`、 それから：```
L = i - d[i] + 1
R = i + d[i] - 1
```5. この間隔の外側で可能な最大一致長を計算します。 

最大のものが必要です`k`次のような:```
s[a : a+k] == reverse(s[b : b+k])
```と：```
a + k - 1 < L
b > R
```すべてのペアを列挙する代わりに、ハッシュを使用して答えを二分検索します。 
6. 回復された回文の合計の長さを評価します。 

構築された回文の長さは次のようになります。```
2*k + middle_length
```7. 最良の構造を維持します。 

次の間隔を保存します。 

- 左の部分、
 - 真ん中の回文、
 - 右の部分。 
8. 空ではないセグメントのみを出力します。 

もし`k = 0`、中央の回文のみが印刷されます。 

### なぜ効果があるのか

 元の隠しパスワードはまさに次の構造になっています。```
X + M + reverse(X)
```どこ`M`は奇妙な回文です。 

Manacher は、すべての有効な奇数回文の中間が考慮されることを保証します。 

固定された中間間隔の場合、最適解はその外側の最大の可逆一致ペアにのみ依存します。 ローリング ハッシュを使用すると、対数時間でミラーリングされた候補部分の同等性をテストできます。 

実行可能なすべての構成が列挙中に表示され、すべての候補の全長が最大化されるため、アルゴリズムは最適な答えを見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

BASE = 911382323
MOD = 972663749

def manacher(s):
    n = len(s)
    d = [0] * n

    l = 0
    r = -1

    for i in range(n):
        k = 1 if i > r else min(d[l + r - i], r - i + 1)

        while i - k >= 0 and i + k < n and s[i - k] == s[i + k]:
            k += 1

        d[i] = k

        if i + k - 1 > r:
            l = i - k + 1
            r = i + k - 1

    return d

class Hash:
    def __init__(self, s):
        n = len(s)

        self.h = [0] * (n + 1)
        self.p = [1] * (n + 1)

        for i, ch in enumerate(s):
            self.h[i + 1] = (self.h[i] * BASE + ord(ch)) % MOD
            self.p[i + 1] = (self.p[i] * BASE) % MOD

    def get(self, l, r):
        return (self.h[r] - self.h[l] * self.p[r - l]) % MOD

def solve():
    s = input().strip()
    n = len(s)

    d = manacher(s)

    rs = s[::-1]

    hs = Hash(s)
    hr = Hash(rs)

    best_len = 1
    ans = [(0, 1)]

    for center in range(n):
        radius = d[center]

        L = center - radius + 1
        R = center + radius - 1

        middle_len = R - L + 1

        max_k = min(L, n - R - 1)

        low = 0
        high = max_k

        while low < high:
            mid = (low + high + 1) // 2

            left_l = 0
            left_r = mid

            right_l = n - mid
            right_r = n

            rev_left_l = n - left_r
            rev_left_r = n - left_l

            if hs.get(left_l, left_r) == hr.get(rev_left_l, rev_left_r):
                low = mid
            else:
                high = mid - 1

        k = low

        total = middle_len + 2 * k

        if total > best_len:
            best_len = total

            cur = []

            if k > 0:
                cur.append((0, k))

            cur.append((L, middle_len))

            if k > 0:
                cur.append((n - k, k))

            ans = cur

    print(len(ans))

    for x, l in ans:
        print(x + 1, l)

solve()
```最初のコンポーネントは Manacher のアルゴリズムです。 線形時間ですべての中心の周りの最大の奇数回文を計算します。 配列`d[i]`中心自体を含む半径を格納します。 

ハッシュ構造は、定数時間の部分文字列の等価性チェックをサポートします。 プレフィックス ハッシュと累乗は 1 回事前計算されます。 

メイン ループは、すべての奇数回文を中間ブロックの可能性があるものとして扱います。 それぞれについて、その外側にミラーリングされたキャラクターをいくつアタッチできるかを決定します。 

二分探索は有効な最大値を超えて検索します。`k`。 これにより、すべての長さを個別にチェックする必要がなくなります。 

微妙な点の 1 つは、逆インデックス変換です。 元の文字列の部分文字列は、反転された文字列内のミラー化された間隔に対応します。```
s[l:r]
```以下にマッピングされます:```
rs[n-r : n-l]
```ここでの 1 つ違いの間違いは非常に一般的です。 

もう 1 つの重要な詳細は、重複の防止です。 値:```
max_k = min(L, n - R - 1)
```外側の部分が中央の回文から切り離されたままであることが保証されます。
