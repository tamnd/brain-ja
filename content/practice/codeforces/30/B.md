 ## 解決策
 ## 問題の理解

 次の形式で 2 つの日付が与えられます。`DD.MM.YY`: 1 つは Codeforces 世界決勝戦の日を表し、もう 1 つはボブの生年月日を表します。 ボブは、誕生日の構成要素である日、月、年を並べ替えることができますが、個々の数字ではなく、完全な数字としてのみ並べ替えることができます。 目標は、そのような再配置の後、ボブが決勝戦当日に少なくとも 18 歳になっており、決勝戦と同じ世紀に生まれたかどうかを判断することです。 どちらかの条件が満たされない場合は参加できません。 

年は 2001 年から 2099 年を表す 2 桁の数字で、決勝戦はこの範囲で行われます。 この場合の有効な生年月日は、異なる日数を持つ月の処理や閏年の考慮など、標準のカレンダー ルールに従う必要があります。 並べ替えられた日付をチェックするための並べ替えの最大数は、コンポーネントが 3 つしかないため少なく、候補日付ごとに 6 つの並べ替えが行われます。 

単純な実装では、いくつかの微妙な制約を見落とす可能性があります。 たとえば、日と月を入れ替えると、2 月 31 日のような無効な日付が作成される可能性があります。 もう 1 つの落とし穴は、有効な参加シナリオである最終日と誕生日が一致する場合に年齢を誤って計算することです。 不注意な解決策では、世紀の要件を無視して、年を次のように扱う可能性もあります。`01`誕生年が決勝戦と同じ世紀でなければならないということは考慮せず、2001 年とします。 

## アプローチ

 ブルートフォース手法は簡単です。ボブの生年月日の 6 つの順列をすべて生成し、各順列を有効な日付として解釈し、結果の年齢が 18 歳以上かどうか、また誕生年が決勝戦の世紀と一致するかどうかを確認します。 これは順列の数が少ないため機能しますが、不可能な日と月の組み合わせによって引き起こされる無効な日付を拒否しないように注意する必要があります。 すべての順列は独立してチェックされ、順列数が 6 に固定されており、複雑さの懸念よりもはるかに低いため、このアプローチは効率的です。 

重要な洞察は、制約が小さいため、各順列を個別にチェックできるということです。 年齢を計算するには、年、月、日を順番に比較する必要があり、ボブの 18 歳の誕生日が決勝戦と一致するという特殊なケースに対処します。 また、日と月がグレゴリオ暦の規則に従って有効であることを確認する必要もあります。 この場合のうるう年は単純です。2001 年から 2099 年の範囲で 4 で割り切れる年はすべてうるう年であり、2 月のみに影響します。 これらのチェックを実施すると、解決策はアルゴリズムの最適化ではなく、直接的な実装の問題になります。

 ## アルゴリズムのチュートリアル

 1. 決勝戦の日付を日、月、年の整数に解析します。 1 世紀全体として機能するには、年を 2000 + YY として解釈します。 
2. ボブの生年月日を 3 つの整数に解析します。 
3. 3 つの数値のすべての順列を生成します。 各順列は、誕生日、月、年の候補を表します。 
4. 順列ごとに、決勝戦の世紀と一致するように 2000 を加えて年を調整します。 
5. 候補日と月が有効な暦日を形成していることを確認します。 指定された月に無効な日、または無効な閏年の 2 月を含む置換はすべて拒否されます。 
6. 最終学年から誕生年を引いて、ボブの年齢を計算します。 最終月日が誕生月日より前の場合は、年齢から1を引いてください。 
7. 年齢が 18 歳以上で、誕生年が決勝戦と同じ世紀にある場合は、YES を返します。 両方の条件を満たす順列がない場合は、NO を返します。 

機能する理由: 不変条件は、すべての順列が個別にチェックされ、可能な再配置がスキップされないことを保証することです。 カレンダーの日付を検証し、年齢を系統的に比較することで、正確さを保証します。 アルゴリズムは、少なくとも 1 つの有効な順列が年齢条件と世紀条件の両方を満たしている場合にのみ YES を返します。 

## Python ソリューション```python
import sys
import itertools
input = sys.stdin.readline

def is_valid_date(day, month, year):
    if month < 1 or month > 12 or day < 1:
        return False
    # Days in month
    if month == 2:
        if year % 4 == 0:
            return day <= 29
        return day <= 28
    if month in [4, 6, 9, 11]:
        return day <= 30
    return day <= 31

def main():
    finals = list(map(int, input().strip().split('.')))
    bob = list(map(int, input().strip().split('.')))

    f_day, f_month, f_year = finals
    f_year += 2000

    for perm in itertools.permutations(bob):
        b_day, b_month, b_year = perm
        b_year += 2000
        # must be same century
        if b_year // 100 != f_year // 100:
            continue
        if not is_valid_date(b_day, b_month, b_year):
            continue
        age = f_year - b_year
        if (f_month, f_day) < (b_month, b_day):
            age -= 1
        if age >= 18:
            print("YES")
            return
    print("NO")

if __name__ == "__main__":
    main()
```コードは最初に最終日と生年月日を解析し、次にすべての順列を反復処理します。 世紀チェックにより、ボブが以前の年を使用して若く見えることはありません。 日付検証では、不可能なカレンダーの組み合わせが拒否されます。 年齢の計算は、最終年度に誕生日がまだ発生していない場合には減算されるように注意されます。 

## 実用的な例

 **サンプル 1**

 入力:```
01.01.98
01.01.80
```| 変数 | 値 |
 | --- | --- |
 | 決勝 | [1,1,98] → 2001+97? ちょっと待って、正解: 98→2098 |
 | ボブの順列 | (1,1,80)、(1,80,1)、(80,1,1) など |
 | 有効な置換 | (1,1,80) → 2080、決勝 2098 |
 | 年齢 | 2098-2080 = 18、月/日はOK |
 | 出力 | はい |

 トレースは、正しい順列を使用すると年齢が正確に 18 になり、参加規則を満たしていることを示しています。 

**カスタム例**

 入力:```
28.02.24
29.02.06
```| 変数 | 値 |
 | --- | --- |
 | 決勝 | 2024 年 2 月 28 日 |
 | ボブの順列 | (29,2,6)、(2,29,6)、(6,2,29) など |
 | 有効な置換 | (29,2,2006) → 2006 年 2 月 29 日は無効 (うるうではない) |

 ここでは、2006 年はうるう年ではないため、2 月 29 日は失敗します。 アルゴリズムはそれを正しく拒否します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | お(6) | 3! 順列、順列ごとの定数チェック |
 | スペース | お(1) | 順列と日付チェックのための一時変数のみ |

 順列の数は 6 に固定されており、すべてのチェックは定数時間であるため、最小限のメモリで 2 秒未満で快適に実行されます。
