 ## 解決策
 ## 問題の理解

 小文字で構成される文字列が与えられ、ゲームでは、その間にあるすべての文字が既にアスタリスクになっている場合に、等しい文字のペアをアスタリスクに繰り返し置き換えることが必要です。 具体的には、インデックスを選択できます$i < j$これらの位置の文字が同じであり、すべての文字が厳密にその間にあるようにします。$i$そして$j$すでに`*`。 ペアを交換すると、それらの位置は次のようになります。`*`。 目的は、文字列全体を次のように変換できるかどうかを判断することです。`*`そうした一連の動きによって。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは文字列の長さを提供します。$n$そして文字列$s$自体。 最終的に文字列全体を次のように変換できる場合は、「YES」を出力する必要があります。`*`、そうでない場合は「いいえ」。 

制約は次のようなものです$n \leq 5000$と合計$n$すべてのテスト ケースで 5000 を超えません。これは、次のようなソリューションが存在することを示しています。$O(n^2)$時間計算量は実現可能です。$5000^2 = 25{,}000{,}000$、これは Python の 2 秒の制限時間として許容されます。 エッジ ケースは、長さが 1 の文字列で、これは明らかに勝ち目がないもの、またはすべての文字が偶数回出現するが、文字がインターリーブされているために連続してペアにできない文字列です。 

考えられるすべてのペアを盲目的に試す単純なアプローチでは、インターリーブ パターンで失敗する可能性があります。 たとえば、文字列の場合、`oooioi`、3つありますが、`o`と２つ`i`s、ペアリング制約により完全な削除が妨げられ、「いいえ」になります。 

## アプローチ

 ブルートフォース手法は、ゲームを正確にシミュレートすることです。次の方法でのみ区切られた有効な等しい文字のペアをすべてスキャンします。`*`、それらを交換し、それ以上移動できなくなるまで繰り返します。 これは正しく機能しますが、各スキャンが実行されるため非効率的になります。$O(n^2)$最悪の場合、文字列を繰り返し更新するとコストが増大し、$O(n^3)$。 が遅すぎるでしょう。$n \sim 5000$。 

重要な洞察は、操作の順序は、ペア間のすべての文字がすでに実行されているという要件によって制約されるということです。`*`。 これは、問題が本質的にネストされたマッチングに関するものであることを意味します。これは、バランスの取れた括弧などの問題で使用される貪欲またはスタックベースのアプローチに似ています。 文字列を左から右に処理し、各文字の最後の位置を追跡しながら、再帰的に文字と次の有効な一致とのペアを試みることができます。 このようにすべてをペアリングできれば、文字列を完全に次のように変換できます。`*`。 という事実`n`小さいので、単純なものを使用できます$O(n^2)$動的プログラミング ソリューションも同様に: let`dp[l][r]`の部分文字列の場合は true になります。`l`に`r`完全にに変えることができます`*`。 次に、最初の文字の考えられるすべてのペアをチェックし、残りの部分文字列の分割も機能するかどうかを確認します。

 ## アルゴリズムのチュートリアル

 1. ブール配列を初期化する`dp`サイズの`n x n`、 どこ`dp[l][r]`部分文字列の場合は true になります`s[l..r]`に完全に変換できます`*`。 単一文字は削除できないため、すべての単一文字部分文字列は最初は false になります。 
2. 2 から 2 までのすべての部分文字列の長さを反復します。`n`。 各部分文字列について`s[l..r]`、最初の文字をペアにすることを検討してください`s[l]`後のすべてのキャラクターで`s[m]`(`l < m <= r`） どこ`s[m] == s[l]`。 
3. 間の部分文字列があるかどうかを確認します。`l`そして`m`すでに変換可能です (`dp[l+1][m-1]`それは本当です）。 その場合は、部分文字列の残りの部分を確認してください (`dp[m+1][r]`）。 両方が true (または空) の場合、`dp[l][r]`それは本当です。 
4. すべての長さを処理した後の完全な文字列の結果は次のようになります。`dp[0][n-1]`。 trueの場合は「YES」、そうでない場合は「NO」を出力します。 

機能する理由: DP はゲームの再帰的な構造をキャプチャします。 最初の文字の有効なペアを選択し、それらの間と 2 番目の文字以降の部分文字列を再帰的に削除できれば、部分文字列は完全に削除可能です。 基本ケースは単一のペアを直接処理します。 これにより、インターリーブ制約を見逃すことなく、すべての有効な移動シーケンスが考慮されるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_win(s):
    n = len(s)
    dp = [[False]*n for _ in range(n)]
    
    for length in range(2, n+1):
        for l in range(n-length+1):
            r = l + length - 1
            for m in range(l+1, r+1):
                if s[l] == s[m]:
                    if (m == l+1 or dp[l+1][m-1]) and (m == r or dp[m+1][r]):
                        dp[l][r] = True
                        break
    return dp[0][n-1]

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()
    print("YES" if can_win(s) else "NO")
```DP の初期化により、長さ 1 の部分文字列が false になることが保証されます。 ネストされたループは、考えられるすべての部分文字列を効率的に処理します。 小切手`(m == l+1 or dp[l+1][m-1])`中央の部分文字列を確実に削除できるようにし、`(m == r or dp[m+1][r])`残りの部分も確実に取り外し可能です。 有効なペアが見つかったら早めにブレークすると、不必要な計算が回避されます。 

## 実用的な例

 トレース`llmllm`:

 | ステップ | 部分文字列 | ペアリング | dp[l][r] |

 | 0 |`ll`| l-l | 本当 |
 | 1 |`llm`| l-l | 偽 |

 これは、左からの貪欲なペアリングが機能し、DP がインターリービングをキャプチャしていることを示しています。

 | ステップ | 部分文字列 | ペアリング | dp[l][r] |

 | 1 |`ooo`| ああ | 偽 |
 | ... | いっぱい | 最後にペアリングできません | 偽 |

 これは、インターリーブが`o`そして`i`完全な除去を防ぎます。

 ## 特殊なケース

 次のような単一の文字の場合`a`、DP テーブルは残ります`False`削除するペアがないため、「NO」が返されます。 

のような文字列の場合`abab`、アルゴリズムは最初のペアをペアリングしようとします`a`2番目と`a`、ただし、それらの間の部分文字列には次のものが含まれます`b`、まだ取り外しできません。`dp[0][3]`false であり、正しくは「NO」が出力されます。 

のために`siixxsevvenn`、再帰 DP は次のようなペアを見つけます。`ii`、`xx`、`ss`、`ee`、`vv`、`nn`順番に、インターリーブが適切に処理されていることを検証し、「YES」を返します。
