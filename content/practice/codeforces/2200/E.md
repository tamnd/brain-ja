 ## 解決策
 ## 問題の理解

 正の整数の配列と、アリスから順番に順番を交代する 2 人のプレイヤーが与えられます。 ゲームは、現在の配列がすでに減少していない場合は直ちに終了するか、選択された要素に対して許可された 1 つの操作を実行することによって進行します。 

利用可能な操作は 1 つの数値を取得することだけです$x$それを 2 つの要素に置き換えます$y$そして$z$両方とも厳密に 1 より大きく、$x = yz$。 の順序$y$そして$z$元の位置に自由に配置できます$x$したがって、配列の長さは増加する可能性がありますが、他のすべての要素の相対位置は保持されます。 

配列が減少しなくなるか、要素に有効な因数分解の動きが存在しなくなるとすぐにゲームは終了します。 終了後、最後の配列が非降順でソートされた場合、ボブが勝ちます。 そうでなければアリスの勝ちです。 

中心となる緊張は、プレイヤーが従来の意味で配列の値を直接最大化または最小化しようとしているのではなく、その代わりに因子構造を操作して、ソートが避けられなくなる瞬間を遅らせたり強制したりすることです。 

制約が非常に厳しいため、解では因数分解の移動ごとのシミュレーションを回避する必要があります。 合計あり$n \le 10^5$および最大値$10^6$、すべての因数分解を調べたり、ゲームの状態をシミュレートしたりするアプローチは、合成数の分岐係数が大きく、繰り返しプレイすると配列サイズが指数関数的に増加するため、すぐに失敗します。 

配列が開始時にすでに非減少である場合、微妙なエッジケースが発生します。 この場合、ゲームは移動する前に終了するため、構造に関係なく常にボブが勝ちます。 もう 1 つのデリケートなケースは、すべての要素が素数または 1 の場合です。その場合、分割は不可能であり、ゲームはすぐに終了するため、最初の順序が決定的になります。 3 番目の重要な状況は、大きな合成が増加するシーケンス内にある場合です。これは、合成を分割すると単調性が崩れたり、パリティに応じてゲームが延長される可能性があるためです。 

たとえば、次のように考えてみましょう`[6, 5]`。 これはソートされていません。 アリスは 6 を 2 と 3 に分割して、次のようになります。`[2, 3, 5]`、ソートされているため、アリスの移動直後にボブが勝ちます。 ただし、`[10, 9, 8]`、分割を繰り返すことで、最適なプレイが強制終了のパリティを変更する十分な柔軟性が生まれます。 これらの例は、ゲームが基本的に、どれだけの「有用な分割」が利用可能か、そしてそれらがコントロールの同等性にどのように影響するかにかかっていることを示しています。 

## アプローチ

 直接シミュレーションでは、合成数の可能なすべての分割と、安定するまでの交互の動きをモデル化しようとします。 それぞれの数字$x$は、因子のペアに応じて複数の方法で分割でき、分割ごとに配列の構造が変わります。 因子のペアを事前に計算したとしても、それぞれの手が配列サイズを増加させ、将来の手のオプションを変更するため、ゲーム ツリーは依然として急速に成長します。 最悪の場合、次のような数字が発生します。$10^6$数十の因数分解があり、複合の連鎖によって深く分岐した状態が作成されます。 

重要な単純化は、「正確にどの因数分解が選択されるか」という観点から考えるのをやめ、代わりに各数値がゲームに寄与できる効果的な分割の数に焦点を当てることです。 有効な各分割は数値をより小さな因数に減らします。重要な唯一の特性は、すべてが素数になる前に数値を自明でない因数に意味のある分解を何回できるかということです。 

これは評価のアイデアにつながります。すべての数値が特定の数の「余分な手」に寄与し、ゲームは配列が完全に減少しなくなるか、分割が残らなくなるまでに、合計の手数が何回存在するかを数えるというものになります。 これが純粋なパリティ ゲームになると、最適なプレイはアリスとボブのどちらが最後に効果的な手を打つかによってのみ決まります。 

決定的な観察は、すべての数値が$x$の素因数の合計数に等しい固定数の演算に寄与します。$x$、多重度でカウントされ、分割されるたびに 1 つの合成が 2 つの小さな数に減らされるため、合成の場合は 1 を差し引きます。 これにより、問題は地球規模の移動予算の計算に変換されます。 

次に、論理的にシミュレーションします。配列がすでに減少していない場合は、ボブが即座に勝ちます。 それ以外の場合、利用可能な有効な操作の合計数が奇数の場合はアリスが勝ち、偶数の場合はボブが勝ちます。これは、各移動が厳密にこの分解バジェットの 1 単位を消費するためです。

 ## アルゴリズムのチュートリアル

 1. までのすべての整数について最小の素因数を事前計算します。$10^6$。 これにより、すべての入力値を高速に因数分解できます。 
2. 各テスト ケースについて、まず配列がすでに非減少であるかどうかを確認します。 そうなった場合は、移動が可能になる前にゲームが終了するため、すぐに Bob を出力します。 
3. SPF テーブルを使用して各要素を因数分解し、多重度を数えてそれに含まれる素因数の数を計算します。 これにより、どれだけの「分割ユニット」に寄与するかの尺度が得られます。 
4. 各数値を、ゲームへの有効な寄与に変換します。これは、素因数の数から、数値が 1 より大きい場合は 1 を引いたものです。これは、自明でない分割に分解できる回数を反映します。 
5. 配列全体のすべての寄与を合計して、ゲーム内で利用可能な手の合計数を取得します。 
6. この合計の等価性によって勝者を決定します。 合計が奇数の場合は、アリスが勝ちます。 互角ならボブが勝ちます。 

パリティが十分である理由は、すべての移動によって利用可能な分解の単位がちょうど 1 つ減少し、どの移動によっても因数分解がすでに提供しているものを超える追加の正味分解容量を作成できないためです。 分割の構造により、ゲームは常に完全な素数分解 (固定エンドポイント) に向かって進むことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXA = 10**6

spf = list(range(MAXA + 1))
for i in range(2, int(MAXA ** 0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXA + 1, i):
            if spf[j] == j:
                spf[j] = i

def factor_count(x):
    cnt = 0
    while x > 1:
        cnt += 1
        x //= spf[x]
    return cnt

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ok = True
    for i in range(n - 1):
        if a[i] > a[i + 1]:
            ok = False
            break
    if ok:
        print("Bob")
        return

    moves = 0
    for x in a:
        moves += max(0, factor_count(x) - 1)

    print("Alice" if moves % 2 == 1 else "Bob")

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```最初の部分では、最小の素因数ふるいを構築して、各数値を対数時間で分解できるようにします。 これにより、クエリごとの因数分解の再計算が回避されます。 

単調性チェックは、ゲームの最終的な条件であるため、他の何よりも先に実行されます。配列がソートされると、それ以上の推論は問題になりません。 

の`factor_count`関数は、SPF による繰り返し除算を使用して、多重度を持つ素因数をカウントします。 これは数値の分解深さに直接対応します。 

表現`factor_count(x) - 1`これは、完全にプライム展開された構造にはそれ以上有用な分割がないため、複合構造のみが寄与するという事実をエンコードします。 

最後に、合計の手数の同等性によって勝者が決まります。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
a = [6, 5, 4]
```| ステップ | 配列 | 並べ替えましたか？ | 追加された動き |
 | --- | --- | --- | --- |
 | 1 | [6,5,4] | いいえ | 6→1、5→0、4→1 |

 因子の寄与は以下から得られます。 

- 6 = 2 × 3 は 2 つの要素を与えます → 1 つの手
 - 5 は素数 → 0 移動
 - 4 = 2 × 2 は 2 つの要素を与えます → 1 つの手

 合計移動数 = 2、つまり偶数であるため、ボブが勝ちます。 

これは、配列が高度にソートされていないにもかかわらず、分解能力のバランスが取れており、2 番目のプレーヤーが最後の手を制御していることを確認します。 

### 例 2

 入力:```
n = 2
a = [6, 5]
```| ステップ | 配列 | 並べ替えましたか？ | 追加された動き |
 | --- | --- | --- | --- |
 | 1 | [6,5] | いいえ | 1 + 0 |

 合計手数 = 1、奇数なので、アリスが勝ちます。 

これは、ゲームがソートされた構成に安定する前に、アリスが単一の効果的な分解を強制できることを反映しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MAXA = 10**6
    spf = list(range(MAXA + 1))
    for i in range(2, int(MAXA ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, MAXA + 1, i):
                if spf[j] == j:
                    spf[j] = i

    def factor_count(x):
        cnt = 0
        while x > 1:
            cnt += 1
            x //= spf[x]
        return cnt

    def solve():
        n = int(input())
        a = list(map(int, input().split()))

        ok = True
        for i in range(n - 1):
            if a[i] > a[i + 1]:
                ok = False
                break
        if ok:
            return "Bob\n"

        moves = 0
        for x in a:
            moves += max(0, factor_count(x) - 1)

        return ("Alice\n" if moves % 2 == 1 else "Bob\n")

    t = int(input())
    out = []
    for _ in range(t):
        out.append(solve())
    return "".join(out)

 ## 特殊なケース

 重要なエッジケースは、配列がすでに減少していない場合です。 入力用`[1, 5, 5, 10]`の場合、アルゴリズムは因数分解を考慮する前にすぐに Bob を出力します。 これは、移動せずにゲームが即座に終了するというルールと一致します。 

もう 1 つのケースは、すべての数値が素数である場合です。`[2, 3, 5, 7]`。 単調性チェックにより、結果が即座に決定されます。 ソートされていない場合、分割は存在しないため、ゲームはソートされていない配列で最初のターンに終了し、移動不能の後に終了が発生した場合にのみアリスが勝利します。これはゼロ移動パリティによって捕捉されます。 

最後の微妙なケースは、次のような高度に合成された数値の配列が減少することです。`[12, 6, 4]`。 それぞれが複数の因数分解単位に寄与しますが、ゲームは再配置ではなく、利用可能な分割を使い果たすことに完全に依存するため、順序付けの複雑さに関係なくパリティによって勝者が決まります。
