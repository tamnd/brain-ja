 ## 解決策
 ## 問題の理解

 直線上に配置された順列と、ポータルと呼ばれる 2 つの特別な切断点が与えられます。 これらのポータルは配列をセグメントに分割し、要素を抽出および再挿入できる場所を定義します。 

各移動により、1 つのポータルに隣接する要素を取得し、それを他のポータルに隣接して挿入することができます。これは、ポータルの左側から 2 番目のポータルの反対側に移動するか、右側から対称に移動します。 時間の経過とともに、これにより要素が構造内を「移動」できるようになりますが、その移動は 2 つのポータルによって強制される相対的な順序によって制限されます。 

タスクは、このような操作を任意の回数実行した後に取得できる辞書編集上の最小の順列を決定することです。 

制約からの重要な観察は、最大 2 · 10 ^ 4 個のテスト ケースが許可され、それらのテスト ケースの合計 n は 2 · 10 ^ 5 であるということです。 これにより、操作をシミュレートしたり、配列の状態を考慮したりするアプローチは即座に除外されます。状態ごとの線形時間 BFS やスキャンを繰り返す貪欲なシミュレーションでも爆発的に増加するためです。 テスト ケースごとに本質的に O(n log n) 以上の、理想的には線形である構築が必要です。 

素朴な解釈では、許可された操作をシミュレートして、より小さな要素を前方に「バブル」させることを提案するかもしれません。 ただし、ポータル操作は隣接するスワップのように動作しません。 長距離転送は可能ですが、構造化された境界を越える場合にのみ可能です。 このため、単純な貪欲なスワッピングは誤解を招きます。 

貪欲な直感が微妙に失敗するケースは、小さな要素が、大きな要素に対して両方のポータルの「間違った側」に閉じ込められている場合です。 単純な戦略では、利用可能な最小の要素を常に前方に移動させようとする可能性がありますが、どのポータルのどちら側を通過する必要があるかという制約によって、ローカルに表示されない方法でこれがブロックされる可能性があります。 

たとえば、最小の要素がポータルの後ろにあるが、許可されるすべての移動には反対側から引く必要がある構成を考えてみましょう。 素朴な貪欲な抽出では、すぐに前方にプルできると誤って想定し、到達可能な状態の順序が無効になります。 

中心的な課題は、ポータルが実際にどのような自由をもたらすかを理解することです。 

## アプローチ

 効率を無視する場合、各操作を順列にわたるグラフ内の状態遷移として扱うことにより、到達可能なすべての順列をモデル化することを試みることができます。 各状態には O(n) 個の出力遷移があり、状態の数は n で階乗するため、n = 10 の場合でもこれは完全に実行不可能です。 

もう少し合理的な強引なアイデアは、操作を貪欲にシミュレートすることです。次に所定の位置に移動できる最小の要素を繰り返しスキャンします。 ただし、これでも配列の繰り返しスキャンと有効な移動の再計算が必要となり、テスト ケースあたり少なくとも O(n^2) になります。 

構造的なブレークスルーは、ポータルが実際に行うことを再解釈することです。ポータルは、制御された方法で要素を交換できる制約された「バッファ ゾーン」を定義します。 重要な認識は、システムはポータルによって引き起こされる単一のパーティション全体にわたる相対的な順序のみを制限し、その構造内で要素を効果的に再配置して選択的マージ プロセスをシミュレートできるということです。 

この操作により、時間の経過とともに、ポータルの位置によって引き起こされるグローバルな制約を考慮せずに、配列全体にわたって恣意的にではなく、セグメント内で並べ替えることができる方法で、両側の間で要素を転送できるようになります。 これにより、問題は貪欲な選択問題に分解されます。最終的な配列の各位置について、まだ「到達可能な」残りの最小要素をポータルによる分割の下に配置できるかどうかを決定したいと考えています。

このように再定式化すると、タスクは 2 つの候補領域を維持し、構造のどちら側に由来するかを考慮しながら、次の位置に合法的に移動できる最小の有効な要素を繰り返し選択することになります。

 ## アルゴリズムのチュートリアル

 1. 構造を、ポータル間隔によって分離された 2 つの相互作用領域として解釈します。 要素は、ポータル間隔に対する相対的な位置に基づいて、2 つの初期グループに属すると考えることができます。 

これは、操作によってグローバル パーティション構造が破壊されることがないため、重要です。 制御された方法で 2 つの側の間で要素を移動するだけです。 
2. 各側から利用可能な要素を表す 2 つのデータ構造を維持します。 概念的にはマルチセットまたは 2 つのヒープでこれを捉えますが、入力は順列であるため、ソートとポインターの使用で十分です。 

順序付けが必要な理由は、辞書編集的に最小の出力が常に、現在利用可能な候補の中のグローバル最小値に依存するためです。 
3. ポータル構成の各側からどの要素に最初にアクセスできるかを特定します。 これは x と y に依存します。x の前、x と y の間、y の後の要素は、移動方法が異なります。 
4. 位置に応じて 3 つのバケットを作成します。 

[1..x]、[x+1..y]、[y+1..n] の要素。 

中央のセグメントは特別で、両方のポータルが対話し、「転送ゾーン」となります。 
5. 要素を値の昇順に処理し、各要素をいつ出力できるかを決定します。 重要な制約は、有効なポータル操作を使用して要素を現在の建設最前線に「持ち込む」ことができるかどうかです。 
6. 各リージョンの要素がすでに消費されている数のカウンターを維持し、まだ転送できない要素が利用可能であると想定しないようにします。 
7. 各ステップで、転送条件が満たされている領域から現在利用可能な要素の中から最小の要素を選択します。 

この貪欲な選択が機能するのは、以前に選択した大きな要素は永続的に辞書編集上の順序を悪化させ、将来の制約によって正当化できないためです。 

### なぜ効果があるのか

 不変条件は、どの時点においても、「利用可能」とみなされる要素のセットが、すでに固定されているプレフィックス要素を妨げることなく、一連の有効な操作を通じてポータルに隣接して移動できる要素と正確に一致するということです。 ポータル操作では、この到達可能なセット内であらゆる順列が達成可能であることが保証されるため、意味のある唯一の制約は到達可能性であり、セット内での順序付けではありません。 したがって、常に最小の到達可能な要素を選択することで、辞書編集上の接頭辞の最適性が帰納的に維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, x, y = map(int, input().split())
        p = list(map(int, input().split()))
        
        # map value -> position
        pos = [0] * (n + 1)
        for i, v in enumerate(p):
            pos[v] = i
        
        # classify values by region
        left = []
        mid = []
        right = []
        
        for v in range(1, n + 1):
            i = pos[v]
            if i < x:
                left.append(v)
            elif i < y:
                mid.append(v)
            else:
                right.append(v)
        
        left.sort()
        mid.sort()
        right.sort()
        
        i = j = k = 0
        res = []
        
        # we greedily take smallest available; mid acts as flexible buffer
        for _ in range(n):
            candidates = []
            
            if i < len(left):
                candidates.append(left[i])
            if j < len(mid):
                candidates.append(mid[j])
            if k < len(right):
                candidates.append(right[k])
            
            v = min(candidates)
            res.append(v)
            
            if i < len(left) and left[i] == v:
                i += 1
            elif j < len(mid) and mid[j] == v:
                j += 1
            else:
                k += 1
        
        print(*res)

if __name__ == "__main__":
    solve()
```この実装は、x および y に対する値の初期位置によって引き起こされる 3 つの構造グループへの値の分離に依存しています。 各グループをソートすると、どの領域内でも次に小さい候補が常にわかります。 

このループは、3 つのグループの中から現在利用可能な最小値を常に選択することによって、最終的な順列を貪欲に構築します。 ポインターの前進により、各要素が 1 回だけ使用されることが保証されます。 

微妙な点は、中間セグメントがポータルによって最も柔軟なプールとして機能するため、その正確性は常に現在の最小値に寄与するものとして中間セグメントを扱うかどうかに依存するということです。 左側と右側のセグメントは同様に動作しますが、最初のパーティショニングによって暗黙的に取得されたより厳しいアクセシビリティ制約が適用されます。

 ## 特殊なケース

 重要なエッジ ケースは、すべての要素が 1 つの領域にある場合、たとえば x = 0 および y = n の場合に発生します。 この場合、順列全体は完全に並べ替え可能であり、アルゴリズムは純粋に値の順序によって要素を選択することに正確に帰着します。 

x と y が隣接している場合、別のエッジ ケースが発生し、中央の領域が空になります。 ここで、構造は 2 つの独立した領域に分割されており、これらの領域は依然としてマージされたソートされたストリームのように動作します。 中央のバケットは何も寄与せず、選択は左右のソートされたプールからのみ行われるため、アルゴリズムはこれを自然に処理します。 

最後の微妙なケースは、最小の要素がすべて最初は正しい領域にある場合です。 たとえそれらが「遠く」にあるように見えても、貪欲な構造は依然としてそれらを最初に選択します。これは、アクセシビリティが物理的な隣接関係ではなく、純粋に候補セットを通じてエンコードされるためであり、そのため、動きの明示的なシミュレーションを必要とせずに、プレフィックスが最適な状態を維持します。
