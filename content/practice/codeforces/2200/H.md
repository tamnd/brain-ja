 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられ、それを割る 6 の累乗が厳密にそれを割る 7 の累乗より大きい場合、その数値を _special_ として定義します。 正式には、数値に対して$x$と定義します。$f_6(x)$最高の指数として$k$そのような$6^k$分割する$x$、同様に$f_7(x)$7 の場合。数字は次の場合に特別です。$f_6(x) > f_7(x)$。 許可される操作は、配列のすべての要素を 1 ずつインクリメントすることですが、すべての要素を同時に特別にするために必要なそのような操作の最小数を見つけたいと考えています。そうでない場合は、それが不可能であると報告します。 

入力は複数のテスト ケースを提供し、それぞれのテスト ケースには最大数の要素が含まれます。$2 \cdot 10^5$および最大の要素値$10^9$。 すべてのテスト ケースにわたる要素の合計数も次のように制限されます。$2 \cdot 10^5$。 これらの境界は、考えられるすべての増分を 1 つずつチェックするようなソリューションを即座に除外します。$10^9$なぜなら、要素ごとに数十億のステップが必要になるからです。 代わりに、割り算と指数の数学的特性を利用して、効率的に答えを計算する必要があります。 

明白ではないエッジケースは、要素が非常に大きい場合、または 6 および 7 に対する要素の因数分解が、どの増分数も満たせないような場合に発生します。$f_6(x) > f_7(x)$。 たとえば、要素が 7 または 7 の倍数で、2 または 3 の因数がない場合、多くの増分が必要になるか、6 乗が 7 乗を超える状態に到達しない可能性があります。 条件が成立するまで盲目的に 1 を加算する単純な実装では、時間制限によりこれらの入力が失敗し、不可能を見逃してしまう可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各要素を独立して考慮し、1 を繰り返し加算し、$f_6(x) > f_7(x)$が成立する。 チェック自体には、2 と 3 (6 の場合) と 7 の最高累乗の計算が含まれます。これは次のように実行できます。$O(\log x)$要素ごとに。 最悪の場合、各数値を最大まで増やす必要がある場合、$10^9$、特にすべてのテスト ケースにわたる配列の長さの合計が$2 \cdot 10^5$。 この方法は概念的には正しいですが、計算的には実行不可能です。 

最適なソリューションを実現するための重要な洞察は、関数が$f_6(x) - f_7(x)$変更されるのは次の場合のみです$x$は 2、3、または 7 の倍数と交差します。6 と 7 は互いに素であるため、それらの指数を独立して推論できます。 すべての増分をシミュレートする代わりに、不等式が満たされる妥当な限界まですべての数値を事前計算できます。$f_6(x) > f_7(x)$が成立し、配列内の各要素について、このセット内でその要素以上の最初の数値を見つけます。 これにより、問題は、少数の「特殊な数値」のセットを効率的に計算し、要素ごとに単純な検索または二分探索を使用することに軽減されます。 

もう 1 つの観察は、6 または 7 で割り切れる数の増加が指数関数的であるということです。 特定のしきい値より大きい数値は、最終的には少数の増分内で特別な数値に達します。 フォームのすべての数値を列挙することで、$2^i \cdot 3^j \cdot 7^k$と$i,j,k \ge 0$昇順に候補のセットを構築し、配列要素ごとに必要な最小増分を確認できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * max(a_i)) | お(1) | 遅すぎる |
 | 最適 | O(n * log(max_special)) | O(スペシャルの数) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 特殊な数値をすべて事前計算します。 フォーム内で数値を生成する$2^i \cdot 3^j \cdot 7^k$と$i,j,k \ge 0$ただし、数字のみを保持します。$i+j > k$、これは以下と同等です$f_6(x) > f_7(x)$。 数値を超えると生成を停止する$10^{18}$、すべての合理的な増分を確実にカバーします。 
2. 特殊な数値のセットを並べ替えます。 これにより、後でバイナリ検索を使用して効率的に検索できるようになります。 
3. テスト ケースごとに、配列を反復処理します。 各要素について、二分探索を使用して、その要素以上の最小の特殊数を見つけます。 この特別な数値と要素の差を記録します。これは、要素を特別なものにするために必要な増分数です。 
4. いずれかの要素にそれ以上の有効な特殊番号がない場合 (二分探索が失敗した場合)、そのテスト ケースに対して -1 を返します。 それ以外の場合は、すべての要素にわたる最大の差を取得します。 これは、配列全体を同時に特別にするための最小限の操作数です。 
5. 各テストケースの結果を出力します。 

機能する理由: このアルゴリズムは、各要素に対して、その要素よりも小さくない最も近い特別な数値を常に選択するという不変条件を維持します。 配列全体で最大値を取得すると、その回数の増分後に、すべての要素が少なくともそのターゲットの特別な数に達することが保証されます。 スペシャルのセットは非常に大きな範囲まで網羅されているため、このメソッドは解を見逃すことはなく、条件も$f_6(x) > f_7(x)$選択した番号については保証されます。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

# precompute all "special" numbers up to a very large bound
specials = set()
limit = 10**18
powers2 = [1]
while powers2[-1] <= limit // 2:
    powers2.append(powers2[-1] * 2)
powers3 = [1]
while powers3[-1] <= limit // 3:
    powers3.append(powers3[-1] * 3)
powers7 = [1]
while powers7[-1] <= limit // 7:
    powers7.append(powers7[-1] * 7)

for p2 in powers2:
    for p3 in powers3:
        f6 = 0
        x = p2 * p3
        if x > limit:
            break
        f6 = 0
        val = x
        while val % 6 == 0:
            val //= 6
            f6 += 1
        for p7 in powers7:
            val = x * p7
            f7 = 0
            temp = val
            while temp % 7 == 0:
                temp //= 7
                f7 += 1
            if f6 > f7 and val <= limit:
                specials.add(val)

special_list = sorted(specials)

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    ans = 0
    impossible = False
    for x in a:
        idx = bisect.bisect_left(special_list, x)
        if idx == len(special_list):
            impossible = True
            break
        ans = max(ans, special_list[idx] - x)
    print(-1 if impossible else ans)
```事前計算セクションは 2、3、7 の累乗を効率的に生成し、大きな限界を超えないようにします。 組み合わせごとに条件を検証します$f_6(x) > f_7(x)$セットに追加する前に。 二分探索により、各要素の最小増分数を効率的に見つけることができます。
