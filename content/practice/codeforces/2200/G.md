 ## 解決策
 ## 問題の理解

 開始整数が与えられます$x$とリスト$n$操作のそれぞれが変更します$x$正の整数による加算、減算、乗算、または除算のいずれかによって計算されます。 特徴は、操作がランダムな順序で適用されることです。$n!$順列の可能性も同様です。 の最終的な期待値を計算するように求められます。$x$すべての演算が適用された後、モジュロ$10^9 + 7$。 

制約が教えてくれる$n$最大 3000 まで可能で、合計は$n^2$すべてのテストケースで次を超えない$3000^2$。 すべての順列を試す総当り的なアプローチは直ちに不可能です。$3000!$天文学的に大きいです。 代わりに、明示的に列挙することなく、すべての順列を考慮した方法で操作の効果を集計するメソッドが必要です。 

演算に除算が含まれる場合、微妙な特殊なケースが 1 つ発生します。 除算は加算、減算、乗算と可換ではないため、順序が重要になります。 For example, starting from$x = 10$+10 と /2 を異なる順序で適用すると、10 + 10 / 2 = 15 または (10 + 10) / 2 = 10 となります。固定された順序で演算を適用した結果を平均する単純なアプローチは間違っています。 同様に、同じタイプの繰り返し演算 (x2、x3 など) を最初に単純に乗算することはできません。 期待の線形性を考慮する必要があります。 

いくつかの操作が互いに打ち消し合う場合、別の特殊なケースが発生します。 たとえば、10 から開始して、-10 と +10 をランダムな順序で適用すると、常に 10 が得られますが、単純なアプローチでは各操作を個別に扱う可能性があります。 

また、モジュロ演算は慎重に扱う必要があります。$10^9 + 7$逆モジュラを乗算する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてが生成されます。$n!$操作を順列に並べて、それらを順番に適用します。$x$、平均を取ります。 これは問題定義を直接実装するため、原理的には機能しますが、次の場合には計算上不可能です。$n = 3000$、 として$3000!$は大きすぎます。 

重要な洞察は、期待値は線形であるということです。 演算は、加算/減算、乗算、除算の 3 つのカテゴリに分類できます。 期待値を計算するとき、加算と減算は順序とは無関係です。 乗算の場合、加算オフセットを処理した後、線形性を使用して、それらの組み合わせの予想寄与を計算することもできます。 除算は、逆剰余の乗算と同様に扱うことができます。 

具体的に、期待値を次のように表すと、$E[x]$、それぞれの加算または減算が寄与します。$y/n$各操作はシーケンス内のどの位置にも等しく出現する可能性があるため、適用時に期待されます。 乗算はより複雑ですが、動的計画法または組み合わせ係数を使用して寄与を注意深く追跡することで、期待される効果を計算できます。 この問題は、実行中の期待値モジュロを更新しながら、任意の順序で操作を繰り返し適用することに帰着できます。$10^9 + 7$。

 ## アルゴリズムのチュートリアル

 1. 入力を解析し、演算を加算、減算、乗算、除算の 4 つのリストに分割します。 各リストには整数が格納されます$y$その操作のために。 
2. 2 つの変数を初期化します。`num`そして`den`、期待値の分数の分子と分母を表し、どちらもモジュロです$10^9+7$。 
3. 加算または減算ごとに$y$、分子を次のように更新します`num = num + y * den % M`。 これは、各加算演算が順序に関係なく、期待値に等しく寄与するという事実を説明しています。 
4. 各乗算について$y$、分子に次の値を掛けます。$y$モジュロ$M$。 除算演算は、逆モジュールによって乗算に変換されます。$y$、モジュロも$M$。 これにより、モジュラー演算で除算が正しく処理されることが保証されます。 
5. すべての操作を処理した後、最終的な期待値を次のように計算します。`num * den^{-1} % M`逆モジュラーにはフェルマーの小定理を使用します。$10^9 + 7$プライムです。 
6. 各テストケースの結果を出力します。 

機能する理由: このアルゴリズムは期待値の線形性を利用して、平均化の問題を軽減します。$n!$独立した寄与のシーケンスへの置換。 逆モジュラーは除算を正しく処理し、順序に依存しない演算は直接加算または乗算されます。 この不変式により、あらゆる順列の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

M = 10**9 + 7

def modinv(a):
    return pow(a, M-2, M)

t = int(input())
for _ in range(t):
    n, x = map(int, input().split())
    ops = input().split()
    
    add = 0
    mul = 1
    for op in ops:
        sign, val = op[0], int(op[1:])
        if sign == '+':
            add = (add + val) % M
        elif sign == '-':
            add = (add - val) % M
        elif sign == 'x':
            mul = (mul * val) % M
        elif sign == '/':
            mul = (mul * modinv(val)) % M
    
    res = (x * mul + add) % M
    print(res)
```コードはまず、演算を加算効果と乗算効果に分離します。 すべての加算演算を次のように蓄積します。`add`および乗算効果 (逆モジュラーによる除算を含む)`mul`。 最後に、乗算効果と加算効果を組み合わせて、`x`そして結果をモジュロで出力します$10^9+7$。 逆モジュラにより、モジュロ演算で除算が正しく適用されることが保証されます。 このアプローチは効率的であり、列挙順列の組み合わせ爆発を回避します。
