 ## 問題の理解

 私たちは与えられています`M`のランキング`N`候補者たち。 各ランキングは次の順列です。`1..N`、ここで、ポジションが小さいほどランクが高くなります。 

任務は構築することです`K`新しいランキング、順列も`1..N`、公平性の条件を満たします。 

確定候補者の場合`x`、プレフィックス長`l`、およびしきい値`t`、 仮定する`x`上部に表示されます`l`少なくとも$$\left\lceil \frac{tM}{K} \right\rceil$$オリジナルの`M`投票。 

それから`x`先頭内に表示される必要があります`l`少なくとも`t`鍛造品の`K`投票。 

このステートメントは、有効な構造が常に存在することを保証します。 出力する必要があるのは 1 つだけです。 

構築に重要な寸法における制約は驚くほど小さいです。 我々は持っています`N, K ≤ 100`、 その間`M ≤ 10^4`。 これは、アルゴリズムに余裕があることを意味します。`O(NMK)`前処理と`O(KN^2)`または`O(KN^3)`実際の施工に向けて。 大まかなサイズのグラフのマッチングに関するもの`100`完全に安全です。 

微妙な部分は、この条件がすべての候補、すべてのプレフィックス長、およびすべてのしきい値に対して同時に成立する必要があるということです。 あるプレフィックス長の要件を満たす構造は、別のプレフィックス長の要件を簡単に破ってしまう可能性があります。 

上位 3 位に頻繁に登場するものの、1 位になることはめったにない候補者について考えてみましょう。 累積的なプレフィックスではなく正確な位置のみを追跡すると、プレフィックスが誤って低すぎる位置に配置される可能性があります。 

例えば：```
N = 3, M = 2, K = 1

1 2 3
2 1 3
```候補者`1`両方の投票で上位 2 位にランクインします。 有効な偽造投票でも候補者を配置する必要があります`1`上位2位以内。 第一位の周波数だけを見ると、この要件を見逃してしまいます。 

もう 1 つの落とし穴は、候補者が独立して処理できると想定していることです。 プレフィックス要件はかなり重複しています。 ある候補者は上位 2 位の統計により早い列に強制的に配置される一方、別の候補者は上位 3 位の統計によりそこに強制的に配置される可能性があります。 建設ではすべての候補者を同時に尊重する必要があります。

 ## アルゴリズムのチュートリアル

 1.すべて読む`M`オリジナルの順列。 
2. すべての候補者に対して`i`およびすべてのプレフィックス長`l`、元の投票数を数えます`i`最初のうちに`l`ポジション。 
3. コンピューティング$$c_{i,l}
=
\left\lfloor
\frac{\text{count}_{i,l}\cdot K}{M}
\right\rfloor$$これは、候補者を配置する必要がある偽造投票の最小数です。`i`上部の内側`l`ポジション。 
4. コンピューティング$$d_{i,l}=c_{i,l}-c_{i,l-1}.$$5. を構築します。`K × N`テーブルの列ごとに。 各列ごとに`l`、候補を挿入`i`その通り`d_{i,l}`回。

6. 各行を上から下に次のようにします。

2. 候補者`i`柱に接続されています`j`候補者であれば`i`列にまだ存在します`j`。 
3. 完全に一致するものを見つけます。

7. 完成した行が偽造投票です。 

### なぜ効果があるのか

 ステップ5の後、候補者は`i`正確に表示されます`c_{i,l}`最初のうちの何回か`l`列。 これは構造上真実です。`l`まさに貢献する`d_{i,l}`新しい登場。 

マッチング フェーズでは、列内に存在する候補のコピーの数が変更されることはありません。 どの行が各コピーを受け取るかを決定するだけです。 したがって、すべてのプレフィックス数は変更されません。 

ホールの条件は、すべての候補が残りの行と同じ回数だけ出現する一方、各列は 1 つの行に最大 1 回の出現しか寄与できないため成立します。 社説では、候補者のすべてのサブセットが少なくとも同じ数の列に触れており、完全な一致が保証されていることを証明しています。 

すべての行がすべての列から 1 つの候補を受け取り、すべての候補が 1 回だけ受け取られるため、各行は順列になります。 保存されたプレフィックス数は、すべての公平性要件が満たされていることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def kuhn(v, g, seen, mt):
    if seen[v]:
        return False
    seen[v] = True

    for to in g[v]:
        if mt[to] == -1 or kuhn(mt[to], g, seen, mt):
            mt[to] = v
            return True

    return False

def solve():
    N, M, K = map(int, input().split())

    pref = [[0] * (N + 1) for _ in range(N)]

    for _ in range(M):
        p = list(map(int, input().split()))

        pos = [0] * N
        for idx, x in enumerate(p):
            pos[x - 1] = idx + 1

        for cand in range(N):
            r = pos[cand]
            for l in range(r, N + 1):
                pref[cand][l] += 1

    c = [[0] * (N + 1) for _ in range(N)]
    for cand in range(N):
        for l in range(1, N + 1):
            c[cand][l] = (pref[cand][l] * K) // M

    columns = [[] for _ in range(N)]

    ptr = 0
    for l in range(1, N + 1):
        for cand in range(N):
            d = c[cand][l] - c[cand][l - 1]
            for _ in range(d):
                columns[ptr // K].append(cand + 1)
                ptr += 1

    ans = [[0] * N for _ in range(K)]

    for row in range(K):
        g = [[] for _ in range(N)]

        for col in range(N):
            for cand in columns[col]:
                g[cand - 1].append(col)

        mt = [-1] * N

        for cand in range(N):
            seen = [False] * N
            kuhn(cand, g, seen, mt)

        row_perm = [0] * N

        for col in range(N):
            cand = mt[col] + 1
            row_perm[col] = cand

        ans[row] = row_perm

        for col in range(N):
            cand = row_perm[col]
            columns[col].remove(cand)

    print("\n".join(" ".join(map(str, row)) for row in ans))

solve()
```前処理では、すべての候補者およびすべてのプレフィックス長について、その候補者がプレフィックス内に含まれる元の投票の数が計算されます。 これらのカウントから必須の値を導き出します。`c[i][l]`。 

テーブルの構築は証明に直接続きます。 変数`ptr`を線形化します`K × N`テーブル。 新たに必要なオカレンスはすべて、次の空きセルに配置されます。 この不等号は、現在許可されている列が決してオーバーフローしないことを編集保証で証明しました。 

照合フェーズ中、各列には、その列でまだ利用可能な候補が格納されます。 グラフは、残りの 1 つのコピーを含むすべての列に候補を接続します。 

完全一致により、どの候補が現在の行のどの列を占めているかがわかります。 行を書き込んだ後、使用されたオカレンスを対応する列から削除します。 

最も一般的な実装上の間違いは、中間段階で同じ候補の複数のコピーが列に存在する可能性があることを忘れることです。 使用後は 1 部のみ削除します。

 ## 特殊なケース

 いつ`N = 1`、すべての投票は単一の順列です`[1]`。 計算された値は次の条件を満たします`c(1,1)=K`、つまり、テーブルには正確に次の内容が含まれます`K`候補者のコピー`1`。 すべての一致は簡単であり、偽造された投票はすべて有効です。 

元の投票がすべて同一の場合、すべての候補者は決定的なプレフィックス頻度を持ちます。 この構造により、すべての偽造投票にまったく同じ順序が強制されます。 各列には候補が 1 つだけ含まれるため、マッチングではあいまいさが生じません。 

いつ`K > M`、一部の候補者は、最初のプレフィックスよりも多くの回数出現する必要がある場合があります。 フロア スケーリング式は必要な多重度を自動的に計算し、テーブルの構築によりそれらを一貫して拡張します。 

いつ`K < M`、いくつかの元の投票が効果的に統合されます。 プレフィックス数の定式化は、公平性の保証を維持するものです。 アルゴリズムは個々の投票については考慮せず、集計されたプレフィックス頻度についてのみ考慮します。これはまさに条件が必要とするものです。
