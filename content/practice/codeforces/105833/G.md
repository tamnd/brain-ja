 ## 解決策
 ## 問題の理解

 各頂点が近傍のセットへの発信エッジを持つ有向グラフが与えられます。 トークンは選択した頂点から始まり、2 人のプレイヤーがターンごとにエッジに沿ってトークンを移動させながらスコアを蓄積します。 トークンが移動されるたびにスコアは 1 ずつ増加しますが、次の頂点がどのように選択されるかのルールは現在の頂点の出次数によって異なります。 

頂点に外向きのエッジがない場合、ゲームは直ちに終了します。 出ていくエッジが 1 つだけある場合、移動は強制されます。 少なくとも 2 つの発信エッジがある場合、現在のプレーヤーは 2 つの異なる発信エッジを選択し、対戦相手はそれら 2 つのうちのどちらが次のポジションになるかを選択します。 

開始頂点ごとに、両側からの最適なプレイの下で最初のプレーヤーが保証できる最大手数を計算するように求められます。 プレイを強制的に無限に継続できる場合、その開始頂点の答えは -1 になります。 

グラフには最大 200,000 個の頂点と 400,000 個のエッジを含めることができます。 開始頂点ごとに遷移を個別に単純に検査するソリューションは遅すぎます。 ノードごとの線形スキャンでも二次的な動作が発生しますが、これは 1 秒の制約の下では不可能です。 これにより、独立したシミュレーションではなく、グラフ全体にわたるグローバルな構造が求められます。 

対処を誤ってしまいやすい状況がいくつかあります。 

頂点が有向サイクルの一部であり、すべての頂点が出次数を少なくとも 1 つ持ち、プレイヤーが終了を永久に回避できる場合、答えは -1 でなければなりません。 最終的に終了することを前提とした単純な最短パスまたは DP は、有限値を誤って割り当てます。 

頂点の出次数が 1 で、サイクル内を指している場合、移動の強制的な性質は、サイクル プロパティが逆方向に伝播することを意味します。 強制チェーンを無視すると、ゲームの長さが誤って切り捨てられることにつながります。 

もう 1 つの微妙なケースは、頂点に 2 つの出力エッジがあり、その両方が最終的に同じ状態に達する場合に発生します。 「2 つの選択肢は分岐を意味する」という単純な貪欲な仮定は、最初のプレイヤーのコントロールを過大評価する可能性があります。これは、対戦相手が効果的にそれを単一の到達可能な継続に減らすためです。 

## アプローチ

 ブルート フォース アプローチでは、すべての開始頂点からゲームをシミュレートし、2 人のプレイヤーの間で考えられるすべてのインタラクションを調査します。 各分岐頂点で、出ていくエッジのすべてのペアを試し、相手の最良の応答をシミュレートします。 すべての分岐ノードがグラフ上に最小-最大決定木を導入するため、これはすぐに指数関数的になります。 状態は頂点だけではなく、最適な敵対プレイの下で各頂点が何回訪問されるかにも依存するため、メモ化してもあまり役に立ちません。 

重要な観察は、ゲームが現在の頂点を超えた履歴に依存しないということです。 各頂点には値を割り当てることができます。つまり、開始プレイヤーがその時点から保証できる最大ステップ数、またはゲームが永遠に続く場合は無限大です。 

これにより、問題は 2 種類の遷移を持つグラフ DP に変換されます。 頂点に出ていくエッジが 1 つだけある場合、値は後続エッジの値に 1 を加えたものになります。 複数の外向きエッジがある場合、現在のプレイヤーは実質的に 2 人の候補を選択し、対戦相手はそれらの中から最小の結果を強制します。 これは、ノードの値が 2 つの後続ノードの選択と 2 つの結果のうち悪い方を取ることに依存すると言っているのと同じですが、プレイヤーはこの最悪の結果を最大化しようとします。 

この構造は、当然のことながら、グラフを反転して、出力エッジのない頂点が値 0 の終端状態として機能する、マルチソース伝播と同様の方法で値を計算することになります。 伝播は逆トポロジー順序で動作しますが、サイクルには特別な処理が必要です。強制終了せずに到達可能なサイクルは無限ループ状態を形成します。

この解決策は、どの頂点が「最適なプレイの下で非終端の強く接続された領域」に到達できるかを特定すること、あるいは最長の強制パスを逆方向に計算することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | 指数 | O(N + M) | 遅すぎる |
 | 逆伝播を使用したグラフ DP | O(N + M) | O(N + M) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 隣接リストを作成し、各頂点の出次数を計算します。 

これが必要なのは、移行ルールが次数が 0、1、または少なくとも 2 であるかどうかに完全に依存するためです。 
2. 出次数 0 を持つすべての頂点でキューを初期化し、値 0 を割り当てます。 

これらは、入力するとすぐにゲームが終了するため、ターミナル状態です。 
3. キューを使用して逆の方法で頂点を処理し、頂点ごとに最もよく知られている答えと、解決された出力遷移の数を維持します。 

すべての選択肢が「子の観点から評価」されると、頂点は解決可能になるという考えです。 
4. 出力エッジが 1 つだけある頂点の場合、後続値に 1 を加えたものとして値を直接伝播します。 

これは強制的な移動であるため、戦略的な選択肢は存在しません。 
5. 少なくとも 2 つの出力エッジを持つ頂点の場合、最良の 2 つの後続値を追跡します。 

対戦相手は選択した 2 つのうちの悪い結果を選択するため、実効値は現在のプレーヤーが提供できる最良のペアによって決定され、対戦相手が長いパスを回避する能力を最小限に抑えます。 
6. 伝播後にサイクルまたは未解決の頂点を検出します。 

処理後も未定義の値を持つ頂点は、遊びが無限に延長される可能性がある構造の一部であるか、その構造につながるため、-1 を割り当てます。 

### なぜ効果があるのか

 重要な不変条件は、頂点の値が固定されると、その値が最適なプレイ下でのその頂点からの保証されたステップの最大数を表すということです。 端子頂点は定義上正しいです。 強制された頂点には決定が含まれないため、正しさが逆方向に伝播されます。 分岐頂点の場合、最小-最大構造は崩壊して、最悪の結果が最大化される出力エッジのペアを選択します。これは、すべての後続値が判明すると完全に決定されます。 値は依存関係の逆の順序で既に処理された状態にのみ依存するため、その後の更新によって計算された値が無効になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    indeg = [0] * n
    outdeg = [0] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        outdeg[u] += 1
        indeg[v] += 1

    # dp[i] = best guaranteed score from i, -1 means infinite
    dp = [None] * n
    q = deque()

    for i in range(n):
        if outdeg[i] == 0:
            dp[i] = 0
            q.append(i)

    # reverse graph
    rg = [[] for _ in range(n)]
    for u in range(n):
        for v in g[u]:
            rg[v].append(u)

    remaining = outdeg[:]

    while q:
        v = q.popleft()
        for u in rg[v]:
            if dp[u] is not None:
                continue

            remaining[u] -= 1

            if outdeg[u] == 1:
                # forced transition
                dp[u] = dp[v] + 1
                q.append(u)
            else:
                # collect computed neighbors
                vals = []
                for to in g[u]:
                    if dp[to] is not None:
                        vals.append(dp[to])

                if len(vals) >= 2:
                    vals.sort(reverse=True)
                    dp[u] = vals[1] + 1
                    q.append(u)

    for i in range(n):
        if dp[i] is None:
            dp[i] = -1

    print(*dp)

if __name__ == "__main__":
    solve()
```実装は逆伝播のアイデアに従います。 最初に終端ノードを初期化し、次に反転したエッジに沿って値を後方にプッシュします。 単一の出力エッジを持つノードの場合、遷移は決定的であるため、それらの値はすぐに最終決定されます。 分岐ノードの場合は、最適な結果のペアを決定するのに十分な後続情報が得られるまで待ちます。 

よくある実装上の間違いは、サイクルを処理せずにトポロジカルな順序で値を直接計算しようとすることです。これにより、無限ループや不正確な有限応答が発生します。 もう 1 つの微妙な問題は、分岐ノードを評価するときに「利用可能なエッジ」と「すでに処理されたエッジ」が混在することです。 確定した後続値のみが寄与する必要があります。 

## 実用的な例

 小さなグラフを考えてみましょう。 

入力:```
3 3
1 2
2 3
1 3
```頂点 3 は終端です。 

| ステップ | キュー | dp[3] | dp[2] | dp[1] |
 | --- | --- | --- | --- | --- |
 | 初期化 | [3] | 0 | - | - |
 | プロセス3 | [2] | 0 | 1 | - |
 | プロセス2 | [1] | 0 | 1 | - |
 | プロセス1 | [] | 0 | 1 | 0 |

 頂点 1 は直接 3 に移動することも、2 を介して間接的に移動することもできますが、対戦相手は分岐を通じて短い方の結果を強制するため、値 0 で終了します。 

ここでサイクルを考えてみましょう。```
3 3
1 2
2 3
3 1
```| ステップ | キュー | DP |
 | --- | --- | --- |
 | 初期化 | [] | なし |
 | ターミナルノードがありません | [] | すべて未定義 |

 どの頂点も解決されないため、すべてに -1 が割り当てられ、無限再生が確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N + M) | 各エッジは逆伝播中に一定の回数処理されます。 
| スペース | O(N + M) | 隣接リストと DP 配列 |

 ## 特殊なケース

 次のような純粋なサイクル`1 → 2 → 3 → 1`終端ノードには決して到達しないため、逆伝播中に DP 値を確定することはできません。 このアルゴリズムはすべてのノードを未定義のままにし、最後にそれらを -1 に正しく変換し、無限のゲームプレイを表します。 

シンクで終わる直線状のチェーン。`1 → 2 → 3 → 4`4 には出力エッジがなく、値を決定論的に逆方向に伝播します。 各ノードは厳密に 1 つの強制サクセサーを受け取り、スコアは曖昧さなくきれいに蓄積されます。 

両方の出力エッジが同じ後続ノードにつながる分岐ノードは、アルゴリズムが最終的な値を収集し、重複したパスによって人為的に最適な選択セットが増加しないため、依然として正しく動作します。
