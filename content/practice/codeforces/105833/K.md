 ## 問題の理解

 この問題は、各エッジが関連コストを伴う列車の線であるが、コストはすぐには支払われないグラフ探索問題として見ることができます。 代わりに、レッドは移動中にエッジの「ライセンス」を取得し、最終的に駅を出るときにのみ取得します。$N$、支払いシステムは特別なルールを有効にします。$K$最も安価に購入したライセンスは実際に料金を支払う必要がありますが、他のすべてのライセンスは事実上無料です。 

最大で無向グラフが与えられます。$10^5$ノードと$2 \cdot 10^5$エッジ。 各エッジは 2 つのステーションを接続し、コストがかかります。 赤はノード 1 から始まり、ノードに到達する必要があります$N$。 旅行中、エッジのエンドポイントにいるときはいつでも、そのエッジのライセンスを購入することが許可され、その後、エッジは両方向に自由に移動できるようになります。 重要な点は、総コストは購入したすべてのエッジの合計ではなく、$K$購入したエッジのコストが最小になります。 

したがって、決定は単にどのパスを選択するかではなく、探索中にどのエッジを意図的に「収集」するかによって、最終的に購入したエッジのマルチセットが安価になるようにすることです。$K$-サブセット。 

この制約は、どの解もエッジの数が線形または線形に近い必要があることを意味します。$M$できる$2 \cdot 10^5$。 ヒープを使用した最短パス スタイルのアプローチは許容されますが、すべてのサブセットを繰り返し並べ替えたり列挙したりするものは直ちに不可能になります。 エッジを横断して購入するすべての可能な方法を単純に指数関数的に探索することは問題外です。各ステップが隣接リストや潜在的にエッジ購入の決定に分岐し、指数関数的な成長につながるからです。 

微妙な点の 1 つは、ノードに複数回アクセスすることが重要であるということです。これにより、異なる瞬間にエッジを購入できるようになります。 不注意な最短パスの解釈では、エッジは単一のパスに沿ってのみ使用できると想定されますが、ここではエッジを購入した後にバックトラックできる機能により、構造が大きく変わります。 

2 番目の明白ではない問題は、ノードに到達することが「終了」と同じではないことです。 赤は到達後も移動を続けることができます$N$、したがって一時的に超えるパス$N$または領域を再訪問することは、より良いエッジを収集するのに役立つ場合に有効です。 

3 番目の落とし穴は、1 から 2 までの単一の単純なパス上のエッジのみを考慮していると仮定していることです。$N$。 エッジを購入すると、最終ルートでの役割に関係なくトラバースが可能になるため、これは誤りです。 

## アプローチ

 ブルートフォースのアイデアは、ノード 1 からノードまでの可能なすべての方法をシミュレートすることです。$N$、各ステップで現在のエッジを購入するかどうかを決定します。 散歩中、購入したエッジのセットを維持し、最初に到達したときに$N$の合計を計算します。$K$そのセット内の最小のエッジコスト。 これは正しいですが、歩行距離に上限を設けたとしてもすぐに爆発します。$O(N)$、各ステップが複数のエッジに分岐し、購入可能なサブセットの数が指数関数的に増加します。$M$。 パスの選択を無視したとしても、各走査に最適なサブセットを評価するには、次のようなソートが必要になります。$M$価値観を繰り返します。 

重要な構造的観察は、トラバースに関して重要なのは、正確な順序ではなく、最終的にどのエッジが購入されるかだけであるということです。 トラバース自体は実行可能条件としてのみ機能します。ある時点でエンドポイントの 1 つに到達した場合、エッジを購入できます。 したがって、本当の疑問は、この意味でノード 1 からどのエッジのサブセットが「到達可能」であるか、そしてそれらの到達可能なサブセットの中で、どのようにしてエッジの合計を最小化するかということになります。$K$最小限のコスト。 

これにより、問題は、状態がノードである最短パスのような展開に変換されますが、遷移は、より多くの動きを解放するエッジの収集に依存します。 パスという観点から考えるのではなく、到達可能なエッジの接続領域を段階的に発見しながら、その結果を追跡するベストエフォート型のコスト構造を維持するものとして扱います。$K$これまでに見た中で最も安いエッジ。 

標準的なエンコード方法では、「$K$「最小要素」は、最大サイズの最大ヒープを維持することです。$K$、したがって常に最安値を維持します$K$到達可能な領域でエッジが検出されました。 トラバーサルはグラフ探索となり、新しいノードに到達するたびにその入射エッジが露出し、新しいエッジによって到達可能性がさらに拡大される可能性があります。 

これにより、ノード全体でダイクストラのようなプロセスが発生しますが、最良の状態を維持する追加の構造が必要になります。$K$これまでに収集されたエッジコスト。

 ## アルゴリズムのチュートリアル

 ノード 1 から始まるグラフ トラバーサルとしてプロセスをモデル化し、到達可能なノードを徐々に発見し、同時に使用可能なエッジを収集します。 

1. ノード 1 から開始するグラフ走査の優先キューを初期化し、ノード 1 を到達可能としてマークします。 
2. 最小限のものを保管できる構造を維持する$K$これまでに確認されたエッジコスト。 最大サイズのヒープ$K$新しいエッジ コストが到着したときにそれを挿入し、サイズが超過した場合に使用されます。$K$、最大の要素を削除します。 これにより、常に$K$収集されたすべてのエッジの中で最小のコスト。 
3. ノードの探索中$u$に付随するすべてのエッジを反復処理します。$u$。 各エッジについて$(u, v, c)$、コストを追加することでそれを「発見」しようとします$c$一番上に-$K$構造。 これが有効である理由は、一度到達できれば、$u$、その端を買うことが許されています。 
4. 他のエンドポイントの場合$v$まだ訪問されていない場合は、到達可能としてマークし、トラバーサル キューに追加します。 このステップにより、新しく利用可能なエッジを通じて到達可能性が伝播されます。 
5. 新しいノードに到達できなくなるまで続行します。 この時点で、「エンドポイントに到達するとエッジが使用可能になる」というルールに基づいて、ノード 1 から始まるすべてのエッジを使い果たしました。 
6. 現在保存されている値の合計として最終的な答えを計算します。$K$-ヒープ。 これらは、$K$到達可能なサブグラフ内の最も安価に購入可能なエッジ。 

### なぜ効果があるのか

 重要な不変条件は、どの時点においても、訪問先のノードは、すでに検出されたエッジを使用してノード 1 から到達可能なノードであるということです。 ノードが到達可能になるたびに、そのすべてのインシデント エッジが購入の対象となるため、購入できる可能性のあるエッジがスキップされることはありません。 ヒープ不変式により、すべての適格なエッジのうち最小のもののみが保持されるようになります。$K$、そして最終的な支払いは、$K$最安のエッジを購入し、大きなエッジを早期に破棄しても、最終的な金額は変わりません。 トラバーサルにより、エッジが到達可能性に影響を与える可能性がある場合、そのエンドポイントが最終的に処理されるため、有効な寄与エッジが見逃されないことが保証されます。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        x, y, c = map(int, input().split())
        g[x].append((y, c))
        g[y].append((x, c))

    visited = [False] * (n + 1)
    visited[1] = True

    pq_nodes = [1]

    # max heap via negation for keeping k smallest edges
    best = []

    while pq_nodes:
        u = pq_nodes.pop()

        for v, c in g[u]:
            if len(best) < k:
                heapq.heappush(best, -c)
            else:
                if -best[0] > c:
                    heapq.heapreplace(best, -c)

            if not visited[v]:
                visited[v] = True
                pq_nodes.append(v)

    print(-sum(best))

if __name__ == "__main__":
    solve()
```ノードが到達可能になったときにエッジを繰り返し公開する必要があるため、グラフは隣接リストとして保存されます。 の`visited`配列により、各ノードが 1 回処理されることが保証されるため、展開ループの繰り返しが防止されます。 

の`best`ヒープには負の値が格納されるため、現在保持されている候補のうち最大のものが常に先頭になります。 これにより、より良い (小さい) エッジが現れたときに、それを簡単に破棄できるようになります。 サイズ制限は、$K$これがないとすべてのエッジが保存され、効率性のメリットが失われるため、これは非常に重要です。 

ノード処理スタック`pq_nodes`キューまたは優先順位構造で置き換えることができますが、この問題では、到達可能なすべてのノードが最終的にエッジを露出し、ノードの拡張に距離の制約がないため、任意の走査順序で十分です。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$K$ノード 1 から到達可能なエッジの数を超えています。その場合、アルゴリズムはヒープを所定のサイズまで埋めることはありません$K$、最終的な合計には、収集されたすべてのエッジが当然含まれます。 たとえば、直鎖では$1-2-3-4$と$K=10$、すべてのエッジがヒープに含まれており、その合計が単純に合計パス コストになります。 

もう 1 つの微妙なケースは、同じノード間の複数の平行エッジです。 各エッジはトラバーサル中に独立して処理されるため、2 つのエッジが同じノードのペアに接続している場合でも、両方ともヒープに含めるために別々に考慮されます。 安価なものが最適な製品の一部である可能性があるため、これは不可欠です。$K$-セット。 

最後の重要なケースは、探索がノードに到達したときです。$N$早い。 アルゴリズムはノードで停止しません$N$なぜなら、それを超えた追加のノードはまだ到達可能であり、安価なエッジが露出する可能性があるからです。 早期に終了すると、これらの寄与を誤って見逃してしまうため、到達可能な領域が閉じられるまでトラバースを継続する必要があります。
