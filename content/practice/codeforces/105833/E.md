 ## 解決策
 ## 問題の理解

 私たちにはエネルギーコンテナのコレクションが与えられており、それぞれはある量のエネルギーから始まります。 コンテナ間でエネルギーを移動することは許可されていますが、すべての移動は非効率的です。あるコンテナから別のコンテナにある程度の量を移動すると、移動しようとしたものの一定の割合がプロセス中に失われます。 

目標は最大値を決定することです$x$そのため、一連の転送の後、すべてのコンテナが正確に最終的に$x$エネルギーの単位。 

この問題を言い換える有効な方法は、「漏洩のもとでの再分配」という観点から考えることです。 私たちは総エネルギーを恣意的に変更しているわけではありません。 私たちはそれを再分配するだけであり、コンテナ間でエネルギーを移動するたびに、比例した損失コストを支払います。 

制約が十分に大きいため、転送をシミュレートしようとするソリューションは直ちに実行不可能になります。 コンテナの数は最大で$10^4$、各テストには、必要な最大精度の実数値転送の算術演算が含まれます。$10^{-6}$。 この組み合わせは、答えが連続的であり、直接構築するのではなく単調な特性を使用して見つける必要があることを強く示唆しています。 転送の強引なシミュレーションには、ペアごとの動きと、組み合わせ的に爆発的に繰り返される可能性のあるバランス操作に関する推論が含まれます。 

いくつかのエッジケースは、単純な貪欲な再配布が失敗する理由を明らかにします。 

すべてのコンテナがすでに等しいエネルギーを持っている場合、たとえば入力```
3 50
2 2 2
```正解は明らかです$2$。 「余剰の移動」を試みる戦略であっても、移動が不要であると認識していなければ、依然として不必要な移動が実行され、達成可能な価値が誤って減少する可能性があります。 

損失がゼロの場合、たとえば```
2 0
1 11
```その場合、すべてのエネルギーは完全に保存され、答えは単純に平均値になるはずです。$(1+11)/2 = 6$。 方向性の流れの制約や増分バランシングを前提とした方法は、総和の保存に帰着しない場合、ここで失敗する可能性があります。 

たとえば損失が非常に大きい場合$k = 99$、転送されたエネルギーのほとんどすべてが消えます。 このような場合、問題となるのは局所的な余剰だけであり、非常に小さな値を超えると世界的な平均化は不可能になります。 ほぼ完璧な再分配を前提とするアルゴリズムでは、答えが過大評価されてしまいます。 

## アプローチ

 直接的なアプローチでは、再配布プロセスをシミュレートしようとします。 目標レベルを上回るコンテナを繰り返し特定し、その余剰を下位のコンテナに移動することができます。 転送ごとに、損失の割合に応じて総エネルギーが減少します。 概念的には簡単ですが、これは計算的には実現可能ではありません。 各バランシング ステップは他のステップに依存しており、潜在的な転送の数は効率が保証されるような制限はありません。 最悪の場合、これはすべてのコンテナにわたってスキャンと調整が繰り返されることになり、要素数が少なくとも 2 次の動作につながります。 

重要な洞察は、個別の移転について考えるのをやめ、代わりに世界的な実現可能性に焦点を当てることです。 問題は、提案された目標値についてです。$x$、少なくともすべてのコンテナで終了できるかどうかを確認できますか?$x$、移動中にエネルギーが失われることを考えると？ 

コンテナにそれ以上のものが入っている場合、$x$、再分配できる余剰エネルギーがあります。 ただし、送信されたものの一部のみが他の場所で使用できます。 これは、余剰が他のコンテナの欠損にあまり寄与しないことを意味します。 

この観察により、単調な構造が導き出されます。$x$が達成可能であれば、さらに小さい値も達成可能です。 これにより、二分探索が自然なツールになります。 

固定の場合$x$、輸送損失を考慮した後の総有効エネルギーが、到達するすべてのコンテナをサポートするのに十分であるかどうかを計算します。$x$。 これにより、問題は候補値ごとに 1 回のパス チェックに減ります。

 | 二分探索 + 実現可能性チェック | O(n log A) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのコンテナの合計初期エネルギーを計算します。 この合計は移転による損失を除いて決して変化しないため、世界予算として機能します。 
2. 候補値を確定する$x$、各コンテナ内のターゲット エネルギーを表します。 それが実現可能かどうかをテストしたいと考えています。 
3. 各コンテナについて、それがどのように関連するかを検討します。$x$。 以上のものがある場合は、$x$、過剰なエネルギーは潜在的に伝達可能です。 それが少ない場合、目標に到達するためにエネルギーが必要になります。 
4. すべての余剰金額を合計します。次のように定義されます。$\max(0, a_i - x)$。 これは、高いコンテナから移動できる総エネルギーです。 
5. この剰余金の一部のみが移転に残ります。 損失率が$k$、その後、送信された各ユニットが貢献します$(1 - k/100)$ユニットを受信側に送ります。 したがって、使用可能な転送エネルギーは比例して減少します。 
6. 有効利用可能エネルギーを次のように計算します。$$\text{available} = \text{total\_sum} - \frac{k}{100} \cdot \text{surplus}$$7. この利用可能なエネルギーが少なくとも$n \cdot x$。 そうであれば、すべてのコンテナが到達するようにエネルギーを分配することが可能です。$x$。 
8. 二分探索を使用する$x$からの範囲で$0$に$\max(a_i)$、精度要件が満たされるまで改良します。 

### なぜ効果があるのか

 重要な不変条件は、エネルギーは移動したときにのみ消失し、移動する必要があるのは目標を上回る余剰分だけであるということです。 すべての値が以下に等しい有効な最終構成$x$まさに上記の余剰が生じるプロセスとして解釈できます。$x$は再分配され、他のすべてのユニットは静止したままになります。 これは、回収不可能な損失のみが、移転しなければならない剰余金の額に比例することを意味します。 

実現可能条件は以下に単調に依存するため、$x$、増加しています$x$条件を満たすのが難しくなるだけです。 これにより、中間の可能性を逃すことなく、二分探索が有効な最大値に収束することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(x, a, n, k):
    total = 0.0
    surplus = 0.0
    
    for v in a:
        total += v
        if v > x:
            surplus += (v - x)
    
    lost = surplus * (k / 100.0)
    available = total - lost
    
    return available >= n * x

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    lo, hi = 0.0, max(a)
    
    for _ in range(60):
        mid = (lo + hi) / 2
        if can(mid, a, n, k):
            lo = mid
        else:
            hi = mid
    
    print(f"{lo:.10f}")

if __name__ == "__main__":
    solve()
```実装の中核となるのは、`can`関数。再配布プロセスを 1 つの算術チェックに圧縮します。 二分探索では、実現可能性の単調性に基づいて、候補の答えを繰り返し絞り込みます。 

微妙な点は、チェックは小さな変動の下でも安定しており、必要なエラー許容度は次のとおりであるため、浮動小数点の精度で十分であるということです。$10^{-6}$。 二分探索を 60 回繰り返すと、精度要件を余裕で超えます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose
    
    input = sys.stdin.readline
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    def can(x):
        total = 0.0
        surplus = 0.0
        for v in a:
            total += v
            if v > x:
                surplus += v - x
        return total - surplus * (k / 100.0) >= n * x
    
    lo, hi = 0.0, max(a)
    for _ in range(60):
        mid = (lo + hi) / 2
        if can(mid):
            lo = mid
        else:
            hi = mid
    return f"{lo:.6f}"

# provided samples

assert run("2 90\n1 11\n")[:5] == "1.909"

 ## 特殊なケース

 すべての値が同じ場合、たとえば`5 5 5 5`、実行可能性チェックはすぐに合格します。$x = 5$剰余金がゼロだからです。 このアルゴリズムは、人為的な削減を正確に回避します。 

いつ$k = 0$、余剰期間は完全に消滅します。 実現可能性のチェックは、合計を比較することに帰着します。$n \cdot x$、これはまさに平均化の条件です。 二分探索は自然に算術平均に収束します。 

いつ$k$100に近づくと、余剰はほぼすべて失われます。 利用可能なエネルギーが初期エネルギーの合計とほぼ等しくなるため、アルゴリズムは引き続き正しく動作しますが、中程度のエネルギーではすぐに実現可能性が失われます。$x$。 これにより、二分探索による再配布能力の過大評価が防止されます。
