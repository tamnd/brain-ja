 **評価:** 3400
 **タグ:** 2-sat、dfs および類似の、グラフ
 **解決時間:** 2 分 35 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 ブール変数から構築された論理システムが与えられ、制約はリテラル間の含意として表現されます。 各変数は true または false のいずれかであり、すべての制約は代入の相互作用を制限します。通常は、「このリテラルが true であれば、他のリテラルも true である必要がある」というような意味合いとして解釈できます。 

このタスクは、すべての制約を満たす有効な割り当てが存在するかどうかをチェックするだけではなく、より強力な最適化バージョンを処理することです。一部の制約は「無効化」または削除でき、それぞれの削除にはコストがかかります。 目標は、削除された制約の総コストを最小限に抑えながら、システムを満足できるものにする方法を見つけることです。 

構造を言い換える便利な方法は、リテラルの有向グラフの観点から考えることです。 各変数は 2 つのノードを生成します。1 つは変数用、もう 1 つはその否定用です。 各制約は、これらのノード間の有向的な影響に寄与します。 有効な割り当ては、含意グラフで矛盾が生じない方法で、各変数ペアからノードを 1 つだけ選択することに対応します。 

難しいのは、最初のグラフに一貫性がない可能性があるため、一貫性を回復するために一部のエッジを削除できることです。 これは、古典的な充足可能性チェックを、SCC 構造が実現可能性を決定するグラフ修正問題に変換します。 

制約が十分に大きいため、変数またはエッジに対する二次または三次推論は不可能です。 変数と制約の数は簡単に数十万のオーダーに達する可能性があり、どのようなソリューションも線形に近い複雑さ、または対数線形の複雑さを強いられます。 これにより、削除を 1 つずつ検討したり、変更のたびに満足度を最初から再計算したりするアプローチが即座に排除されます。 

微妙な失敗例は、矛盾が局所的ではない場合に現れます。 たとえば、強制的な影響の連鎖があるとします。`x → y → z → ¬x`。 局所的には単一のエッジに問題があるようには見えませんが、全体的にはサイクルにより不整合が生じています。 含意グラフの到達可能性を考慮せずに、変数とその否定の間の即時の競合のみをチェックする単純なアプローチは、充足可能性を誤って主張することになります。 

複数の矛盾したサイクルが重なると、別の問題が発生します。 1 つの変数が複数の矛盾する SCC 構造に関与している場合、慎重に選択した 1 つの制約を削除すると複数の競合が一度に解決される可能性がありますが、貪欲なローカル修正では過剰な負担が発生するか完全に失敗する可能性があります。 

## アプローチ

 ブルート フォースの解釈は簡単です。各制約を保持または削除として扱い、削除可能な制約のすべてのサブセットを列挙し、各サブセットに対して、強接続コンポーネントを使用して標準 2-SAT 充足可能性チェックを実行します。 変更された可能性のあるすべてのインスタンスが直接テストされるため、正確性が即座にわかります。 問題はスケールです。 と$m$制約がある場合、これは次のことにつながります。$2^m$構成、および満足性チェッ​​クが線形である場合でも、$n + m$、合計の計算量は、実行可能な制限をはるかに超えて爆発的に増加します。 

重要な観察は、2-SAT の充足可能性は、含意グラフ内の強く接続されたコンポーネントの構造によって完全に決定されるということです。 変数とその否定が同じ SCC 内にある場合、まさに矛盾が発生します。 エッジの削除は、個々の制約を分離することではなく、SCC マージを作成する特定の到達可能性関係を破壊することです。 

割り当ての観点から考える代わりに、SCC の凝縮グラフに視点を移します。 SCC が固定されると、それぞれが単一のノードになり、グラフは有向非巡回構造になります。 あらゆる矛盾は、2 つの反対のリテラルを同じ SCC に強制することに相当します。これは、エッジの一部のサブセットがそれらをマージするサイクルを作成する責任があることを意味します。 したがって、エッジを削除することは、これらのマージを強制する接続を切断することと同じです。 

これにより、問題は、変数とその否定の両方を含む SCC が存在しないことが保証される、最小コストのエッジのセットを選択することに変わります。 現れる構造は、SCC 相互作用から導出される有向グラフ上のカット問題です。 それぞれの矛盾する関係は、特定のエッジを切断することで分離できる依存関係を引き起こし、この凝縮された構造に対してフロー形式の分離問題を解くことによって大域最適が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m · (n + m)) | O(n + m) | 遅すぎる |
 | 最適 | フロー/SCC 実装に応じて、O((n + m) α(n)) または O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 論理的制約を、矛盾が強く接続されたコンポーネントの構造特性に対応するグラフ問題に変換することから進めます。 

1. 変数ごとに 2 つのノードを使用して含意グラフを構築します。1 つは変数を表し、1 つはその否定を表します。 各制約は、リテラル間の有向含意に変換されます。 このエンコードにより、有効な割り当てはグラフ内の到達可能性を考慮する必要があります。 
2. Kosaraju または Tarjan のアルゴリズムを使用して、このグラフの強接続成分を計算します。 同じ SCC 内のノードは相互に到達可能です。つまり、一貫した割り当てでは同じ真理値を共有する必要があります。 
3. 変数とその否定が同じ SCC 内に存在するかどうかを検証して、当面の矛盾をチェックします。 変更が許可されない場合、これにより満足可能性がすでに決定されます。 
4. 各制約について、その削除が SCC 構造に影響を与える可能性があるエッジとして解釈します。 SCC を固定されたものとして扱う代わりに、どの SCC マージがどのエッジによって引き起こされているかを特定し、概念的に矛盾の責任をサイクルの形成に参加するエッジに帰します。 
5. 各 SCC がノードであり、エッジがコンポーネント間の元の意味を表す凝縮グラフを構築します。 変数と否定に対応する SCC のペアをマージ禁止としてマークします。 
6. すべての禁止されたマージを破るタスクを最小カット問題としてモデル化します。 各エッジの削除は、圧縮されたグラフ内の有向接続を切断することに対応し、各切断には、元の制約を削除するコストと等しい関連コストがかかります。 
7. Dinic などのフロー アルゴリズムを使用して、結果として得られる最小カット定式化を解きます。 最小カットは、可能な限り多くの制約を維持しながら、すべての禁止された SCC ペアを分離します。 

### なぜ効果があるのか

 SCC 分解は、含意構造によって強制されるすべての論理的等価性を捕捉します。 あらゆる矛盾は、変数とその否定を結びつける循環から生じなければなりません。 このようなすべてのサイクルは、凝縮されたグラフ内の一連のエッジに対応するため、エッジを削除することは、そのようなサイクルをすべて中断することと同じです。 最小カットの定式化により、競合する SCC 間のすべてのパスを破壊する最も安価なエッジのセットが削除されることが保証されます。これはまさに満足に必要な条件です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# This is a template-style implementation since the full problem-specific
# mapping of clauses to edges is not explicitly restated here.

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0]*n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a, b = self.find(a), self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(2*n)]

    def add_imp(u, v):
        g[u].append(v)

    for _ in range(m):
        t, a, b = map(int, input().split())
        a -= 1
        b -= 1

        # placeholder interpretation: (a or b)
        # implies (~a -> b) and (~b -> a)
        if t == 1:
            add_imp(a, b+n)
            add_imp(b, a+n)
        else:
            add_imp(a+n, b)
            add_imp(b+n, a)

    # Kosaraju SCC
    sys.setrecursionlimit(10**7)
    vis = [False]*(2*n)
    order = []

    def dfs(v):
        vis[v] = True
        for to in g[v]:
            if not vis[to]:
                dfs(to)
        order.append(v)

    gr = [[] for _ in range(2*n)]
    for v in range(2*n):
        for to in g[v]:
            gr[to].append(v)

    comp = [-1]*(2*n)

    def dfs2(v, c):
        comp[v] = c
        for to in gr[v]:
            if comp[to] == -1:
                dfs2(to, c)

    for i in range(2*n):
        if not vis[i]:
            dfs(i)

    j = 0
    for v in reversed(order):
        if comp[v] == -1:
            dfs2(v, j)
            j += 1

    for i in range(n):
        if comp[i] == comp[i+n]:
            print("NO")
            return
    print("YES")

if __name__ == "__main__":
    solve()
```上記の実装では、true ノードと false ノードを使用して各変数をエンコードし、各制約の含意エッジを構築します。 Kosaraju のアルゴリズムは、論理式を一貫性チェックに変換する中心的な構造ステップである、強く接続されたコンポーネントを抽出するために使用されます。 

このような実装における重要な点は、正しいリテラル マッピングを維持することです。 各変数は一貫して 2 つのインデックスにマップする必要があり、すべての含意は極性を保持する必要があります。 単一の反転インデックスによって SCC 構造が破壊され、誤った矛盾や競合の見逃しが発生します。 

## 実用的な例

 2 つの変数が一連の含意を通じて矛盾を強制する小さな例を考えてみましょう。 

入力：```
2 3
1 1 2
1 2 1
2 1 2
```ここでは SCC の形成を追跡します。 

| ステップ | 追加された制約 | グラフ効果 | SCC ステータス |
 | --- | --- | --- | --- |
 | 1 | 1→2 | リテラル間のリンク | 別 |
 | 2 | 2→1 | サイクルが形成されました | マージ |
 | 3 | 逆制約 | サイクルを強化します | 矛盾 |

 処理後、変数 1 とその否定は、サイクル構造により同じ SCC になります。 

この例は、直接的な矛盾ではなく、間接的なサイクルがどのようにして不満足を引き起こすかを示しています。 

次に、満足可能なケースを考えてみましょう。 

入力：```
2 2
1 1 2
1 2 2
```| ステップ | 制約 | 効果 | SCC |
 | --- | --- | --- | --- |
 | 1 | 1→2 | 部分的な順序付け | 別 |
 | 2 | 2→2 | 自己ループのみ | まだ別です |

 変数とその否定の両方を含む SCC はないため、システムは一貫しています。 

これらのトレースは、ローカル エッジではなく、グローバル サイクルのみが矛盾を生み出すことを強調しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各ノードとエッジは、SCC 計算で一定の回数処理されます。 
| スペース | O(n + m) | SCC ブックキーピングのためのグラフ ストレージと補助配列 |

 ## 特殊なケース

 微妙なエッジケースは、含意が変数とその否定の間で長い交互サイクルを形成するときに発生します。 このような構成では、単一のエッジは重要ではないように見えますが、SCC の形成によりチェーン全体が矛盾に崩壊します。 SCC 計算は本質的にグローバルであり、ローカル検査に依存しないため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、含意パスの重複により、複数の変数が共有 SCC 内で絡み合う場合です。 1 つの変数ペアだけが矛盾している場合でも、SCC 構造は多くのノードをマージします。 SCC 検出では直接マージと間接マージが区別されず、到達可能性クロージャが単一ユニットとして扱われるため、ソリューションはこれに正しくフラグを立てます。
