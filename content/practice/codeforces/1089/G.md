 ## 解決策
 ## 問題の理解

 私たちには、7日ごとに繰り返される授業の週スケジュールが与えられています。 曜日ごとに、ゲスト学生のクラスがアクティブまたは非アクティブにマークされます。 このスケジュールに加えて、次のように示される目標授業日数が与えられます。$k$。 

カレンダー上で、曜日の任意の日から始まる連続した日のブロックを選択し、そのブロック内の授業日数が正確に一致するようにしたいと考えています。$k$。 このようなすべての有効なブロックの中で、ブロックの全長、つまりベルラントに滞在する暦日数を最小限に抑える必要があります。 

重要な詳細は、週が無限に繰り返されるため、土曜日の後に同じパターンで日曜日が再び来るということです。 私たちが選択するブロックは、週のサイクルに関連して任意のタイミングで開始できます。これは重要です。開始をずらすと、授業日の蓄積速度が変わる可能性があるためです。 

制約により、非常に特殊な計算上の形状が強制されます。 テスト ケースの数は 10,000 に達する場合があります。$k$まで可能です$10^8$。 これにより、各テスト ケースを毎日シミュレートするアプローチは即座に除外されます。 リニアスキャンでも、$k$最悪の場合、遅すぎると、$10^8$テストごとにステップを実行しますが、これは実行不可能です。 

利用可能な唯一の構造は周期性です。 スケジュールは 7 日ごとに繰り返されるため、1 週間あたりの授業日数は固定されており、長いセグメントは完全なサイクルと短い残りのサイクルに分解する必要があります。 ソリューションは、明示的なシミュレーションではなく、この定期的なカウントに依存する必要があります。 

毎週のスケジュールにアクティブな日がほとんどない場合、微妙なエッジ ケースが発生します。 たとえば、アクティブな日が 1 日だけで、その日が日曜日の場合、連続した授業日を達成するには、慎重に週を調整する必要があります。 安定した蓄積を前提とした素朴な貪欲スキャンでは、週の境界を越えた調整が無視されるため、必要なウィンドウを過大評価または過小評価する可能性があります。 

もう 1 つの特殊なケースは、7 日間すべてがアクティブな場合です。 この場合、毎日が貢献しており、答えは単純に次のようになります。$k$ただし、週単位で推論しようとする間違った解決策は、誤って余分なパディングを追加する可能性があります。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての開始日をシミュレートし、到達するまでに含まれる授業日数をカウントしながら、前方に拡張します。$k$。 7 日間のサイクルの開始オフセットごとに、授業日のカウンターを維持し、授業日数に達したときに停止しながら、毎日前進することができました。$k$。 次に、ウィンドウの長さを記録します。 

これは、すべての有効なセグメントを直接構築して測定するため、正しいです。 ただし、そのコストは法外です。 最悪の場合、$k = 10^8$多くのテストケースがあり、各シミュレーションは最大で$O(k)$日々。 たった 10,000 件のテストでも、これは実現可能な制限時間をはるかに超えています。 

重要な観察は、この構造が毎週繰り返されるということです。 個々の日数の観点から考えるのではなく、1 週間に何日の授業があり、部分的な週がどの程度寄与するのかという観点から考える必要があります。 サイクルの開始点を固定すると、授業日と授業以外の日の順序が周期的になるため、授業日の累積は、繰り返されるブロックにわたって線形関数になります。 

これは、回答を丸一週間と残りの接頭辞に分割することを示唆しています。 1 つの完全なサイクルで何日の授業が行われるかがわかっている場合は、定数時間で週ごとにジャンプし、追加で部分的な週を最大 1 つだけシミュレーションできます。 可能な開始曜日 (7 つの可能性のみ) ごとに、この分解を使用して最小ウィンドウを貪欲に計算できます。

 ## アルゴリズムのチュートリアル

 週次パターンを前処理し、丸 1 週間に何日の授業が存在するかを計算します。 

1. 週の活動日数の合計を計算します。 この値により、7 日間のサイクルごとに得られる授業日数が決まります。 効率よく前に進むための基本ユニットです。 
2. 0 から 6 までの週の開始日ごとに、授業日を積み上げるプロセスをシミュレートします。ただし、任意の長い時間をかけて 1 日ずつ進めるのではなく、可能であれば丸一週間を繰り返し使用します。 これにより、時間の直線的な増加が回避されます。 
3. 固定開始オフセットの場合、目標を下回ったまま丸何週間含めることができるかを計算します。$k$。 丸一週間ごとに固定の授業日数が割り当てられるため、一括で減算できます。 この手順により、問題のサイズが潜在的に小さくなります。$10^8$最大一定数の操作までのステップ。 
4. 1 週間すべてを消費した後、さらに最大 14 日間先のシミュレーションを実行します。 最適なセグメントは 1 サイクル境界内で開始するように調整でき、2 週間を超えるオーバーシュートはすでに見られたパターンを繰り返すだけであるため、この上限は十分です。 これにより、正確なポイントを確実に捉えることができます。$k$-回目の授業日が発生します。 
5. 各開始位置について、正確に到達するために必要なセグメントの合計長を計算します。$k$授業日、7 つの開始オフセットすべての最小値を取得します。 

### なぜ効果があるのか

 このアルゴリズムは、周期性と制限された調整という 2 つの構造特性に依存しています。 周期性により、7 日ごとにシステムの状態が正確に繰り返されるため、クラスの蓄積は完全なサイクルの数のみに依存します。 境界調整により、最適なウィンドウ境界が 1 サイクル内の開始と最大 1 追加サイクル内の終了によって表現されることが保証されます。 それ以外の場合、ウィンドウを丸 1 週間後方にシフトすると、より短いまたは同等の解が生成され、最適性に矛盾します。 これにより、グローバル最小値を見つけるには、7 つの開始位置と 1 週間のジャンプ後の一定の長さのシミュレーションのみをチェックするだけで十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        k = int(input())
        a = list(map(int, input().split()))
        
        total_week = sum(a)
        
        # duplicate for easy circular traversal
        b = a * 2
        
        ans = float('inf')
        
        # try each starting position in the week
        for start in range(7):
            need = k
            length = 0
            
            # if no classes in a week (shouldn't happen per constraints)
            if total_week == 0:
                continue
            
            # take full weeks if beneficial
            full_weeks = 0
            if need > total_week:
                full_weeks = (need - 1) // total_week
                need -= full_weeks * total_week
                length += full_weeks * 7
            
            # now simulate at most 14 days
            cur = start
            while need > 0:
                if b[cur] == 1:
                    need -= 1
                cur += 1
                length += 1
            
            ans = min(ans, length)
        
        print(ans)

if __name__ == "__main__":
    solve()
```実装では、まず、週に何日の授業が存在するかをカウントします。 開始日の考えられる調整ごとに、できるだけ多くの丸週を貪欲に削除し、問題をより小さな残りの問題に変換します。 次に、モジュラー演算を回避するために、剰余は 2 倍の配列上で直接シミュレートされます。 最終的な答えは、すべての開始位置合わせの最小値であり、週次サイクルの可能な限り最良のシフトを捉えます。 

実装の微妙な詳細は、次を使用して丸 1 週間を計算することです。$(k - 1) // total\_week$。 これにより、次のような場合にオーバーシュートが起こらなくなります。$k$は毎週の合計で正確に割り切れるため、剰余シミュレーションの正確性が維持されます。

 ## 特殊なケース

 主なエッジケースは、アクティブな平日が 1 つだけの場合です。 たとえば、土曜日のみがアクティブな場合、$k$授業日は丸一週間にわたって間隔を空ける必要があります。 アルゴリズムは、構造を丸一週間のジャンプに折りたたむことでこれを処理し、存在しない隣接する日を強制しようとする試みが行われないようにします。 

もう 1 つの特殊なケースは、一日中アクティブな場合です。 この状況では、週の合計は 7 になり、数式はすぐに週全体を消費します。 授業日の各単位は正確に 1 暦日に対応するため、アルゴリズムは自然に直接的な線形結果に帰着します。 

3 番目のエッジケースは次のような場合です。$k = 1$。 アルゴリズムはすべての開始位置を評価し、アクティブな開始日を直ちに見つけ、長さ 1 を生成します。一括減算が必要ないため、丸週ロジックは正しくバイパスされます。 

これらのケースは、スパース性と密度の両方の極値が、同じ周期的分解ロジックを通じて均一に処理されることを確認します。
