 ## 解決策
 ## 問題の理解

 予約されたトークンのセットとともに小さなプログラミング言語ソース ファイルが与えられます。 元のソースには、コメント、任意のスペース、およびユーザー定義の識別子が含まれる場合があります。 パーサーはコメントを削除し、スペースをスキップし、言語規則に従って最長の有効なトークンを繰り返し抽出します。 

このタスクには 2 つの異なる部分があります。 

まず、ソースによって表される正確なトークン シーケンスを再構築する必要があります。 このプロセス中、コメントは消え、スペースは意味を持たなくなります。 

次に、すべてのユーザー定義語は、決定論的なスキームに従って名前を変更する必要があります。 最初に見つかった個別の単語が最初に使用可能な小文字の識別子になり、2 番目に見つかった個別の単語が 2 番目に使用可能な小文字の識別子になり、以下同様です。 予約されたトークンは、この生成された識別子シーケンスから除外されます。 

名前を変更した後、名前を変更したトークン シーケンスを正確に生成するトークン化を行う 1 行を出力する必要があります。 このようなすべての出力の中で、スペースの数が最小限に抑えられた出力が必要です。 

制約は驚くほど小さいです。 予約されたトークンは最大 40 個、ソース行は最大 40 行、各行の長さは最大 80 です。入力全体はわずか数千文字です。 これは、高度な解析機械が必要ないことを意味します。 ソースの長さの 2 乗に比例する複雑さのアルゴリズムであっても、完全に安全です。 

難しいのは効率ではありません。 課題は、パーサーの最長一致動作を正しく再現し、隣接する出力トークン間にスペースが必要なタイミングを正確に判断することです。 

いくつかの特殊なケースは見落とされがちです。 

他の予約済みトークンのプレフィックスである予約済みトークンを考慮してください。```
Reserved: + ++
Source: ++
```パーサーはトークンを生成する必要があります`++`、2つではありません`+`トークン。 最長一致する予約トークンではなく、最初に一致する予約トークンを受け入れるパーサーは、間違ったトークン シーケンスを生成します。 

単語の定義も満たす予約済みトークンを検討してください。```
Reserved: while
Source: while abc
```トークン`while`は予約されており、決して名前を変更しないでください。 すべての英数字文字列を単語として扱うと、文字列の名前が誤って変更されてしまいます。 

より大きな単語にマージされる隣接するトークンを考えてみましょう。```
Tokens: a b
```印刷`ab`スペースを入れないと、解析結果が 2 つの単語から 1 つの単語に変わります。 少なくとも 1 つのスペースが必要です。 

逆の状況も起こります。```
Tokens: a +
```印刷`a+`完全に安全です。 スペースを追加すると、結果が長くなるだけです。 

特に微妙なケースは、2 つの予約済みトークンが別の予約済みトークンに連結される場合です。```
Reserved: + ++
Tokens: + +
```印刷`++`単一のものとして解析されます`++`パーサーは常に可能な限り長いトークンを取得するためです。 どちらのトークンも単語や数字ではない場合でも、スペースは必須です。 

隣接するトークンを区切り文字なしで書き込むことができるタイミングを正確に理解することが問題の核心です。 

## アプローチ

 ブルートフォースの観点は、最適化問題を理解するのに役立ちます。 

名前変更されたトークン シーケンスを取得した後、`k`トークン。 隣接するすべてのペアの間には、スペースを挿入してもしなくてもよいです。 がある`2^(k-1)`可能な出力。 候補出力ごとにパーサーを再度実行し、目的のトークン シーケンスが再構築されるかどうかを確認できます。 最も短い有効なものが答えになります。 

このアプローチは、スペースの考えられるすべての配置を明示的にテストするため、正しいです。 残念ながら、数十のトークンだけでも、検索スペースはすでに天文学的なものになります。 

重要な観察は、2 つの隣接するトークン間の決定が完全にローカルであるということです。 

すでにすべての識別子の名前を変更していると仮定します。 2 つの連続する出力トークンを考慮します。`A`そして`B`。 

書く場合`A+B`パーサーはまったく同じ 2 つのトークンを生成しますが、スペースは長さを増やすだけであるため、スペースを省略した方が常に適切です。 

書く場合`A+B`パーサーが他のものを生成する場合、スペースは必須です。 

他のポジションとのやり取りはありません。 トークン間に区切り文字が必要かどうか`i`そして`i+1`これら 2 つのトークンのみに依存します。 

これにより、問題は 2 つの独立したタスクに縮小されます。 

まず、トークン シーケンスを回復して名前を変更します。 

次に、隣接するペアごとに、連結によって解析結果が変わるかどうかを判断します。 

入力サイズが小さいため、パーサー自体を単純に再利用できます。 ペア用`(A,B)`、文字列を解析します`A+B`。 結果が正確であれば`[A,B]`、スペースは必要ありません。 それ以外の場合は、スペースを 1 つ挿入します。 

元のソースからトークンを抽出する同じ最長一致パーサーは、間隔の質問にも答えます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k・k) | O(k) | 遅すぎる |
 | 最適 | O(T + k · L²) | O(T) | 承認済み |

 ここ`T`はソースの全長であり、`L`トークンの最大長です。 すべての制限が小さいため、これでも十分に高速です。 

## アルゴリズムのチュートリアル

 ### 解析モデル

 パーサーはステートメントと正確に一致する必要があります。 

任意の位置で:

 1. スペースをスキップします。 
2. 現在の位置から始まるすべての予約済みトークンの中で、最も長いトークンが存在する場合はそれを取得します。 
3. それ以外の場合、現在の文字が数字の場合は、最長の数字シーケンスを使用して数値トークンを作成します。 
4. それ以外の場合は、最長の有効な単語を使用して単語トークンを作成します。 

入力は有効であることが保証されています。 

### 単語の生成

 ターゲット識別子のシーケンスは、最初に長さ順に並べられ、次に辞書順に並べられた小文字の単語で構成されます。```
a, b, ..., z, aa, ab, ...
```それ自体が予約済みトークンである識別子はスキップする必要があります。 

### 名前の変更

 解析されたトークン シーケンスをトラバースするとき:

 1. トークンが単語ではない場合は、変更しないでください。 
2. トークンが予約済みトークンの場合は、変更しないでください。 
3. それ以外の場合、この単語が以前に出現したことがない場合は、次に利用可能な生成された識別子を割り当てます。 
4. 元の単語が出現するたびに、割り当てられた識別子で置き換えます。 

### 最小間隔

 名前変更されたトークンの隣接するすべてのペアについて`(A,B)`:

 1. 文字列を形成する`A+B`。 
2. 同じトークナイザーを使用してこの文字列を解析します。 
3. 結果が正確に 2 つのトークンのシーケンスである場合`[A,B]`、追加`B`直後`A`。 
4. それ以外の場合は、前にスペースを 1 つ挿入します。`B`。 

スペースはトークン化の前にスキップされるため、常に 1 つのスペースで十分です。 

### なぜ効果があるのか

 パーサーは決定論的であり、常に各位置で最も長い有効なトークンを選択します。 

名前変更後、ターゲット トークンのシーケンスは固定されます。 残された唯一の自由は、スペースをどこに配置するかです。 

隣接するペアの場合、連結を解析してこれら 2 つのトークンを再現する場合、区切り文字を省略すると正確に有効になります。 そうでない場合は、パーサーが境界を異なる方法で解釈するため、セパレーターのない出力ではトークン シーケンスを保持できません。 

すべてのスペースの決定は 1 つの隣接するペアのみに依存し、スペースの長さは決して減少しないため、最適な戦略は、可能な限りスペースを省略し、必要な場合にのみスペースを挿入することです。 このルールをすべての境界に個別に適用すると、スペースの合計数が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

WORD_CHARS = set(
    "abcdefghijklmnopqrstuvwxyz"
    "ABCDEFGHIJKLMNOPQRSTUVWXYZ"
    "0123456789_$"
)

def is_word_start(c):
    return c.isalpha() or c == '_' or c == '$'

def tokenize(text, reserved):
    tokens = []
    i = 0
    n = len(text)

    while i < n:
        while i < n and text[i] == ' ':
            i += 1
        if i >= n:
            break

        best = None
        best_len = 0

        for tok in reserved:
            if text.startswith(tok, i) and len(tok) > best_len:
                best = tok
                best_len = len(tok)

        if best is not None:
            tokens.append(best)
            i += best_len
            continue

        c = text[i]

        if c.isdigit():
            j = i
            while j < n and text[j].isdigit():
                j += 1
            tokens.append(text[i:j])
            i = j
            continue

        j = i
        while j < n and text[j] in WORD_CHARS:
            j += 1
        tokens.append(text[i:j])
        i = j

    return tokens

def is_word_token(token, reserved):
    if token in reserved:
        return False
    if not token:
        return False
    if token[0].isdigit():
        return False
    return all(ch in WORD_CHARS for ch in token)

def generate_names(reserved):
    length = 1

    while True:
        total = 26 ** length

        for x in range(total):
            cur = []
            y = x

            for _ in range(length):
                cur.append(chr(ord('a') + (y % 26)))
                y //= 26

            name = ''.join(reversed(cur))

            if name not in reserved:
                yield name

        length += 1

def solve():
    n = int(input())

    reserved = set()
    if n:
        reserved = set(input().split())
    else:
        input()

    m = int(input())

    source_tokens = []

    for _ in range(m):
        line = input().rstrip('\n')

        pos = line.find('#')
        if pos != -1:
            line = line[:pos]

        source_tokens.extend(tokenize(line, reserved))

    gen = generate_names(reserved)

    mapping = {}
    renamed = []

    for tok in source_tokens:
        if is_word_token(tok, reserved):
            if tok not in mapping:
                mapping[tok] = next(gen)
            renamed.append(mapping[tok])
        else:
            renamed.append(tok)

    if not renamed:
        print()
        return

    answer = [renamed[0]]

    for i in range(1, len(renamed)):
        a = renamed[i - 1]
        b = renamed[i]

        merged = a + b
        parsed = tokenize(merged, reserved)

        if len(parsed) == 2 and parsed[0] == a and parsed[1] == b:
            answer.append(b)
        else:
            answer.append(' ')
            answer.append(b)

    print(''.join(answer))

if __name__ == "__main__":
    solve()
```トークナイザーは中心的なコンポーネントです。 これは 2 回使用されます。1 回目は元のトークン シーケンスを回復するため、その後 2 つの隣接する出力トークンを安全に連結できるかどうかをテストします。 

最長予約トークン ルールは、数字と単語を認識する前に実装する必要があります。 これはステートメントの優先規則と一致します。 たとえば、次の場合`while`予約されている文字列`while`単語ではなく予約されたトークンになる必要があります。 

識別子ジェネレーターは、長さと辞書編集順を増加させて小文字の文字列を列挙します。 予約セットに属する生成された名前はスキップされます。 

間隔フェーズでは、数十の特殊なケースを導出しようとするのではなく、パーサーを意図的に再利用します。 これにより、次のような予約トークンの重複に伴う間違いが回避されます。`+`対`++`または番号に隣接する識別子。
