 ## 解決策
 ## 問題の理解

 私たちには労働者の集まりが与えられ、それぞれがやりたい仕事をすでに選んでいます。 まさにあります$k$個別のジョブがあり、各ワーカーはそのうちの 1 つを指します。 少なくともジョブと同じ数のワーカーが存在するため、各ジョブに最大 1 人のワーカーを割り当てることができますが、最終的にはすべてのジョブを 1 回だけカバーする必要があります。 

複雑なのは、現在の選択では一部のジョブがカバーされないままになる可能性があり、他のジョブは複数のワーカーによって選択されることです。 これを解決するために、労働者に自分の選んだ仕事を変えるよう説得することが認められています。 を説得する$i$-番目の人件費$b_i$、説得後、別の仕事に割り当てることができます。 

目標は、すべてのジョブを確実に実行できるようにすることです。$1$に$k$1 人のワーカーにのみ割り当てられるため、説得コストの合計が最小限に抑えられます。 

制約は次のとおりです$n = 10^5$。 割り当てをシミュレートしたり、組み合わせを繰り返し試行したりするソリューションは、$O(n^2)$。 平$O(n \log n)$ソートやヒープの使用は許容されるため、実用的なターゲットになります。 これは、従業員を仕事ごとにグループで扱い、各グループ内で貪欲な決定を下すべきであることを強く示唆しています。 

ジョブが最初に 1 人のワーカーだけによって選択される場合、微妙なエッジ ケースが発生します。 私たちが意図的に移動させない限り、その労働者はその仕事に強制的に就くことになりますが、そうすれば他の仕事をカバーするのが難しくなる可能性があるため、不必要なコストが発生するだけです。 もう 1 つのエッジケースは、仕事がまったく選ばれない場合です。 その場合、他のジョブ グループからワーカーを「インポート」する必要があり、どのワーカーをコスト効率の高い方法で移動するかを選択する必要があります。 

たとえば、1 人のワーカーを除いてすべてのワーカーがジョブ 1 を選択した場合、次にジョブ 3 を選択します ($k \ge 3$) を埋めるには、誰かをジョブ 1 または 2 から移動する必要があります。最適な選択は、どの従業員を再割り当てするのが最も安価かによって完全に異なります。 

単純なアプローチでは、グローバルなコストのトレードオフを考慮せずにジョブを順番に貪欲に割り当てようとする可能性がありますが、局所的に最適な割り当てが他の場所で必要とされる低コストの柔軟性を消費してしまうと失敗します。 

## アプローチ

 この問題を直接的に考えるには、最終的には 1 つの仕事につき 1 人の代表労働者が必要になると想像してください。 各労働者は最初はジョブに「所属」しているため、各ジョブは候補者のグループを形成し、どの労働者を元の仕事に残し、どの労働者を再分配のために「犠牲」にするかを決定する必要があります。 

ブルートフォース手法では、すべてのジョブが最終的に 1 人のワーカーになるようにしながら、ジョブごとにどのワーカーが残り、どのワーカーが移動されるかを検討します。 これはすぐに組み合わせ代入問題に変わります。 仕事がある場合$t$移動したすべての労働者が別の仕事に就くことができるようになるため、労働者は、どれを残すかを選択することによって、他のすべての仕事の選択肢と相互作用します。 最悪の場合、これは指数関数的な組み合わせ、または少なくとも$O(nk)$慎重に行えばトランジションが可能になりますが、これでは遅すぎます。$10^5$。 

重要な観察は、各ジョブ内で、最終的な割り当てでそのジョブを実際に担当するのはそのうちの 1 人だけであるため、説得コストを「無料」にできるのは 1 人のワーカーだけであるということです。 その職務に就いている他のすべての従業員は再割り当ての対象となります。 ある仕事が可能な限り最良の労働者を維持すると判断した場合、そのグループ内の他のすべての労働者は、他の場所で不足している仕事を埋めるために使用できる「利用可能な供給源」になります。 

これは問題を再構成します。すべてのジョブに少なくとも 1 人の労働者を確保する必要があり、強制的に移動させる労働者の総コストを最小限に抑えたいと考えています。 同様に、ジョブごとに 1 人のワーカーをゼロコストで保持し、他のすべてのワーカーを再分配の候補として扱いたいと考えています。 ジョブごとにどのワーカーを保持するかについての最適な選択は、説得コストが最も大きいワーカーを保持することです。なぜなら、それが最も「削除にお金を払いたくない」ワーカーだからです。 

したがって、解決策は、すべてのジョブをカバーするのに十分な割り当てを確保しながら、すべての従業員コストを合計し、各ジョブ グループの最大コストの合計を差し引くことになります。 各ジョブは少なくとも 1 人の保存ワーカーを提供するため、実現可能性は自動的に決まります。

 ## アルゴリズムのチュートリアル

 決定は各職務グループ内でローカルに行われるため、従業員を最初に選択した職務に基づいて再編成します。 

1. すべての従業員を、選択したジョブごとにグループ化します。 各グループは、その職務に就く可能性のある候補者を表しており、そのうちの 1 人だけがそこに割り当てられたままでなければなりません。 
2. ジョブグループごとに、最大の説得コストを持つワーカーを見つけます$b_i$。 このワーカーは再割り当てに最もコストがかかるため、そのまま維持することを好みます。 
3. すべてのワーカーのすべての説得コストの合計を計算します。 これは、全員を説得した場合のコストを表します。 
4. この合計から最大値を引きます。$b_i$各ジョブグループから。 これは、節約されたコストを最大化するために選択された、ジョブごとに 1 人の労働者を説得せずに維持するという事実をモデル化しています。 
5. すべてのジョブを確実にカバーするために必要な最小説得時間を表す結果の値を出力します。 

ジョブごとに 1 つのワーカーのみを保持する必要がある理由は、各ジョブが最終的に 1 つのワーカーを正確に割り当てられる必要があるためです。そのため、各グループは説得を必要としない 1 つの「アンカー」割り当てを正確に提供します。 

### なぜ効果があるのか

 各ジョブは正確に 1 人のワーカーを保持する必要があります。 ジョブ グループ内では、そのジョブに割り当てたワーカーを除くすべてのワーカーを移動する必要があります。 引っ越し費用がかかるので、$b_i$、コストを最小限に抑えることは、誰かを移動させないことで支払うコストを最大化することと同じです。 移動を避けるための最良の候補者は常に、最も大きな資産を持つ労働者です。$b_i$なぜなら、他の労働者を維持すると、より価値の高い貯蓄を失うことになるからです。 これにより、ジョブ間で相互作用しないジョブごとのローカルな選択肢が作成されるため、独立した最適な選択肢の合計がグローバルに最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    max_b = [0] * (k + 1)
    total = 0
    
    for i in range(n):
        job = a[i]
        cost = b[i]
        total += cost
        if cost > max_b[job]:
            max_b[job] = cost
    
    ans = total - sum(max_b[1:])
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、ジョブごとに、そのジョブに割り当てられたワーカー間の最大コストを追跡しながら、すべての説得コストの現在までの合計を維持します。 最後の減算ステップでは、ジョブごとに 1 人の従業員を「説得済み」のカウントから除外します。 

重要な点は、再割り当てを明示的にシミュレートしないことです。 どのワーカーを配置し続けるのが最も安価であるかを計算するだけです。 からのインデックス作成$1$に$k$ジョブ ラベルを直接照合し、1 つずつ異なる複雑さを回避します。

 入力:```

```従業員を仕事ごとにグループ化し、各グループの最大コストを追跡します。 

| 仕事 | グループ内のコスト | マックス・キープ |
 | --- | --- | --- |
 | 1 | 5、7、8、2 | 8 |
 | 2 | - | 0 |
 | 3 | 4、3 | 4 |
 | 4 | - | 0 |
 | 5 | 1 | 1 |
 | 6 | - | 0 |
 | 7 | 5 | 5 |

 すべての費用の合計は、$5 + 7 + 4 + 8 + 1 + 3 + 5 + 2 = 35$。 

最大値の合計は$8 + 0 + 4 + 0 + 1 + 0 + 5 = 18$。 

結果は$35 - 18 = 17$。 これは、各ジョブが最も「移動コストが高い」労働者を維持するという考えと一致します。 

このトレースは、すべての構造がジョブごとにローカルであり、ジョブ間の決定が必要ないことを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n)$| 合計とジョブごとの最大値を計算する 1 回のパス |
 | スペース |$O(k)$| ジョブごとの最大コストを格納する配列 |

 このソリューションは制限内に問題なく適合します。$n \le 10^5$、時間とメモリの使用量は両方とも線形で最小限です。 

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    max_b = [0] * (k + 1)
    total = 0
    for i in range(n):
        total += b[i]
        max_b[a[i]] = max(max_b[a[i]], b[i])
    
    print(total - sum(max_b[1:]))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    old_stdout = sys.stdout
    sys.stdout = out
    solve()
    sys.stdout = old_stdout
    sys.stdin = old_stdin
    return out.getvalue().strip()

# provided sample
assert run("""8 7
1 1 3 1 5 3 7 1
5 7 4 8 1 3 5 2
""") == "17"

# all jobs already unique
assert run("""3 3
1 2 3
10 20 30
""") == "0"

# all choose same job
assert run("""5 3
1 1 1 1 1
1 2 3 4 5
""") == "5"

# minimal case
assert run("""1 1
1
100
""") == "0"

# mixed groups
assert run("""4 3
1 2 2 3
5 1 10 2
""") == "3"

 ## 特殊なケース

 すべてのワーカーが同じジョブを選択すると、他のジョブはすべて空になり、密なグループからワーカーを再割り当てすることによって完全に埋める必要があります。 このアルゴリズムは、そのグループ内で最もコストの高いワーカーを選択して留まる一方で、他のすべてのワーカーを除去可能なコストとしてカウントすることでこれを処理します。これにより、最もコストのかかるワーカーを維持することで、合計の説得時間を正確に最小限に抑えることができます。 

すべてのジョブにすでにワーカーが 1 人だけ存在する場合、各グループには 1 つの要素があるため、最大値はそのグループの合計と等しくなります。 減算によりすべてが削除され、コストがゼロになります。これは、説得が必要ないという事実と一致します。
