 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、$n$から番号が付けられた駅$1$に$n$。 駅間$i$そして$i+1$、長さのある道路セグメントがあります$v_i$。 どの駅でも$i$、燃料は購入できますが、各ステーションには独自の固定価格があります$a_i$リットルあたり。 

車が駅から出発する$1$タンクが空で、ステーションに到着する必要がある$n$。 タンクには容量制限がありませんが、燃料消費量は定量化されます。1 リットルの燃料で車は正確に走行できます。$d$キロメートルなので、一定の長さのセグメントを移動します$v_i$必要$\lceil v_i / d \rceil$リットル。 

課題は、車がすべての区間を通過でき、総コストが最小限に抑えられるように、各ステーションで購入する燃料の量を選択することです。 

制約により、最大で次のことが許可されます。$10^5$ステーションとセグメントの長さは最大$10^5$。 これは、次のことを強く示唆しています。$O(n)$または$O(n \log n)$解決。 考えられるすべての給油決定や燃料状態に対する動的プログラミングをシミュレートしようとするアプローチは、位置と燃料量の両方で状態空間が爆発してしまうため、遅すぎます。 

燃料消費量を整数で四捨五入することにより、微妙な問題が発生します。 セグメントが倍数よりわずかに長い場合でも、$d$、それでも追加のフルリットルが必要です。 たとえば、次の場合$d = 4$そして$v_i = 5$、それでは必要です$2$リットルではなく、$1.25$。 

もう一つの明白ではない懸念は、燃料がどこで購入されるかです。 燃料はタンクのサイズによって制限されないため、購入の決定は実現可能性ではなく純粋に価格によって決まります。 単純なアプローチでは、次のセグメントのみの燃料を購入するかどうかを各ステーションでローカルに決定しようとする可能性がありますが、後のステーションの方が安く、より早く使用できた可能性がある場合、これは失敗します。 

## アプローチ

 ブルートフォース戦略では、すべてのステーションで購入する燃料の量を検討し、ステーション間での燃料購入の可能なすべての配分をシミュレーションします。 「次のセグメントまたはそれ以上のセグメントに必要なものを正確に購入する」という制限を設けたとしても、燃料は無期限に繰り越される可能性があり、意思決定は多くのセグメントにわたって相互作用するため、選択肢は飛躍的に増加します。 

ステーションと残りの燃料に関する動的プログラミングの定式化も非現実的になります。 燃料量には制限がなく、それを離散化すると、考えられる燃料需要の合計に比例する非常に大きな状態空間が得られます。 

重要な観察は、燃料は完全に譲渡可能であり、劣化コストがないということです。したがって、唯一の意味のある要素は、現在までにこれまでに見られた最も安い価格です。 より低い価格のステーションに到達すると、その後の購入においては、その価格が以前のすべてのステーションよりも優先されます。 

したがって、道路セグメントごとに最適な戦略は、そのセグメントに必要なすべての燃料をステーション間で最低価格で購入することです。$1$今の駅まで。 現時点での最低燃料価格を維持し、それに各セグメントの燃料要件を乗算するだけで済みます。

 ## アルゴリズムのチュートリアル

 これまでに発生した最も安い燃料価格を追跡しながら、道路を左から右に処理してみましょう。 

1. 変数を初期化する`best_price`これは最初に利用可能なオプションであるため、ステーション 1 での価格が適用されます。 これは、現在使用できるリットルあたりの最低コストを表します。 
2.初期化`answer = 0`、合計コストが累積されます。 
3. 駅からの区間ごと$i$に$i+1$、必要なリットル数を次のように計算します。$$\text{liters} = \frac{v_i + d - 1}{d}$$これは、対象となるリットルの最小の整数です。$d \cdot \text{liters}$少なくとも$v_i$。 
4. 答えに次のように追加します。$$\text{answer} += \text{liters} \times \text{best\_price}$$これは、そのセグメントのすべての燃料をこれまでに入手可能な最も安い価格で購入したことを反映しています。 
5. 次のセグメントに移動する前に、以下を更新します。$$\text{best\_price} = \min(\text{best\_price}, a_{i+1})$$これにより、将来のセグメントは、より安価なステーションの恩恵を受けることができます。 
6. すべてのセグメントを処理した後、出力します。`answer`。 

### なぜ効果があるのか

 道路上のどの時点でも、以前に購入した燃料は後で無駄なく使用できます。 したがって、より低い価格のステーションに遭遇したとしても、将来の消費のために、より高い価格で燃料を早期に購入する理由はありません。 考えられる最良の戦略は、常に、これまでに確認された最も安い価格を、残りのすべてのニーズに対する燃料の実効コストとして扱うことです。 これにより、プレフィックス最小構造が作成され、各セグメントにはその時点までに到達可能な最も安価なステーションに基づいてコストが個別に割り当てられ、購入を再配置することなく総コストをさらに削減できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d = map(int, input().split())
    v = list(map(int, input().split()))
    a = list(map(int, input().split()))

    best_price = a[0]
    ans = 0

    for i in range(n - 1):
        liters = (v[i] + d - 1) // d
        ans += liters * best_price
        if i + 1 < n:
            best_price = min(best_price, a[i + 1])

    print(ans)

if __name__ == "__main__":
    solve()
```コードは貪欲な構造に直接従います。 ループは各道路セグメントを 1 回処理し、整数上限除算を使用して必要なリットルを計算します。 変数`best_price`燃料価格のプレフィックス最低額を維持し、すべてのセグメントがその時点までの利用可能な可能な限り最も安い料金で請求されるようにします。 

実装でよくある落とし穴は、最低価格を間違ったタイミングで更新してしまうことです。 現在のセグメントの価格決定ロジックを使用した後に更新する必要があります。 そうしないと、アルゴリズムによってステーションが誤って許可されてしまいます。$i+1$セグメントに使用される$i$、駅に到着する前にその区間に到達するため不可能です$i+1$。

 ## 特殊なケース

 重要なエッジケースは、後ではるかに安価なステーションが登場したときに発生します。 最初の駅は高く、最後の駅は非常に安いとします。 このアルゴリズムは、各ステーションを通過した後にのみ最低価格を継続的に更新するため、将来のセグメントのために早期に燃料を購入することを正確に回避します。 

もう 1 つのエッジケースは次のような場合です$v_i$で割り切れない$d$。 たとえば、次の場合$d = 4$そして$v_i = 5$、アルゴリズムは次のように計算します。$(5 + 3) // 4 = 2$リットル。 フロア分割を間違えると、1 リットルだけが誤って割り当てられ、コストが過小評価され、解決策が無効になります。 

最後の微妙なケースは、すべての価格が同じである場合です。 この状況では、アルゴリズムは事実上、すべてのセグメントの燃料要件にその一定価格を乗算したものを合計することになり、貪欲な構造が最適化の決定を必要とせずに単純な累積にきれいに退化することを示しています。
