 ## 解決策
 ## 問題の理解

 コンテストの各タスクは、いくつかの独立した「ポイントのグループ」で構成されており、各グループはすべて取り組むこともスキップすることもできます。 グループを受講すると、そのグループのフルスコアが得られます。 それをスキップすると、そのグループからは何も得られません。 

タスクごとに制約が課されます。タスク内のすべてのグループをスキップすることはできません。 したがって、すべてのタスクに対して、そのグループの空でないサブセットを選択する必要があります。 合計スコアは、すべてのタスクにわたって選択されたすべてのグループの合計であり、問​​題は、この合計を目標値と正確に一致させることが可能かどうかです。 

入力により複数のタスクが与えられます。 タスクごとに、そのグループのスコアを表す正の整数のリストが与えられます。 出力は、合計が必要な値と等しいグループの有効な選択 (「タスクごとに空ではない」ルールを考慮) が存在するかどうかという単純な実現可能性の答えです。 

グローバル構造は重要です。タスク内の選択はローカルですが、最終的な制約はすべてのタスクにわたってグローバルです。 これにより、ブロックごとに必須の包含を伴う制約付きサブセット合計問題になります。 

境界はタスクの数と値の合計数が大きく、最大約 10^5 スケールになります。 これにより、タスクごとにグループのすべてのサブセットを試行したり、圧縮せずに生の要素に対してナップザックを実行したりするソリューションは即座に除外されます。 O(合計要素 × ターゲット) に近い解、またはタスクごとの指数関数は合格しません。 

微妙な特殊なケースは、グループが 1 つだけあるタスクから発生します。 その場合、サブセットは空であってはならず、使用可能な唯一のサブセットがシングルトンであるため、選択が強制されます。 もう 1 つの重要なエッジ ケースは、すべてのグループ値が目標に比べて大きく、すべてのタスクが何らかの貢献をする必要があるにもかかわらず、少額の金額に達することが不可能になる場合です。 

## アプローチ

 構造を無視する場合、最も直接的な解釈は、各タスク内のすべての有効な選択肢を列挙し、タスクごとに可能なすべての合計を計算し、すべてのタスクにわたってこれらのタスク合計を結合することです。 k グループを持つ単一タスクの場合、これによりすでに 2^k - 1 個の可能な値が生成されます。 これらを n 個のタスクにわたって組み合わせると、タスク全体で組み合わせの数が倍増する指数関数的な爆発が起こります。 k が小さい場合でも、状態の総数は天文学的に大きくなり、タスクごとの合計をすべて生成するだけでも、最悪の場合、すでに O(k · 2^k) のコストがかかります。 

重要な観察は、達成可能な合計のセットを超えて、各タスクの内部構造を実際には気にしていないということです。 各タスクは小さな「実行可能な合計セット」に寄与し、全体的な問題は、各セットから正確に 1 つの値を選択し、それらを合計して目標に到達することになります。 ただし、フルセットを直接保存するとまだ大きすぎます。 

重要な簡素化は、各タスク内で少なくとも 1 つのグループを選択する必要があることに気づくことから生まれます。 つまり、各タスクは基本値に加えてオプションの追加の貢献を提供します。 タスク内の最小グループを選択すると、他のすべてはそのベースラインに対して「追加の選択肢」になります。 この方法ですべてのタスクを再定式化すると、問題は、各タスクが固定の基本寄与と一連のオプションの増分を持つ、有界サブセット合計に変換されます。 

ここで、問題はタスクに関する標準的なナップザックになります。タスクごとに、必須項目 (ベースライン) を 1 つ選択し、必要に応じて残りの値のサブセットを追加する必要があります。 目標の合計は小さいため (約 10^5)、可能な合計に対するビットセット動的プログラミングが実行可能になります。 まず必須のベースライン合計を累積し、次にすべてのオプションの寄与を使用して残りの差に到達できるかどうかを確認します。

これにより、構造がタスクごとの指数関数的なものから、各値が 1 回処理される合計に対する単一のグローバル DP に縮小されます。

 ## アルゴリズムのチュートリアル

 1. タスクごとに、グループの最小値を計算し、それを実行基準合計に加算します。 タスクを空のままにすることはできないため、これは各タスクから取得する必要がある最小スコアを表します。 

2. 各タスクについて、選択された 1 つの必須ベースラインを除くすべてのグループ値を、オプションの追加寄与として扱います。 ベースラインは最小の要素を選択するのが自然です。これは、強制的なコストを最小限に抑え、目標を達成するための柔軟性を高めるためです。 

3. すべてのタスクを処理した後、必要な合計から基本合計を差し引いて、目標を達成するためにまだ必要な残りの金額を計算します。 この値が負の場合、タスクごとの最小値を取るだけでもすでに目標を超えているため、答えは直ちに不可能になります。 

4. ブール値 DP (ビットセット) を構築します。ここで dp[x] は、すべてのタスクにわたるオプションの寄与を使用して追加の合計 x を達成できるかどうかを示します。 

5. dp[0] = true に初期化します。 これは、オプションの追加オプションを選択しないことに相当します。 

6. すべてのタスクからのすべてのオプションの値を反復し、各値 v について、以前に到達可能な合計 x によって x + v も到達可能になるように dp を更新します。 このステップは、グローバルに適用される古典的なサブセット合計遷移です。 

7. すべてのオプション値を処理した後、dp[remaining] が true であるかどうかを確認します。 「はい」の場合、目標合計は制約の下で達成可能ですが、そうでない場合は達成できません。 

### なぜ効果があるのか

 各タスクは、固定の必須の貢献と独立したオプションの増分に分解されます。 必須部分により、「タスクごとの空でないサブセット」制約が常に満たされることが保証されます。 オプションの部分は、独立した項目に対する標準的なサブセット選択問題を形成します。 この分解後はすべてのタスクが独立しているため、すべてのオプションの値を 1 つのグローバル サブセット合計 DP にマージすると、すべての有効な組み合わせが保持されます。 DP 状態は、達成可能な追加合計のセットを正確に取得するため、目標に到達することは、オプションの寄与の有効なサブセットを見つけることと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, s = map(int, input().split())

    base = 0
    optional = []

    for _ in range(n):
        k = int(input())
        arr = list(map(int, input().split()))

        m = min(arr)
        base += m

        for v in arr:
            if v != m:
                optional.append(v)

    if base > s:
        print("NO")
        return

    target = s - base

    dp = 1  # bitset: dp[x] = bit x reachable

    for v in optional:
        dp |= (dp << v)
        if dp >> target & 1:
            break

    if (dp >> target) & 1:
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```コードはまず、すべてのタスクを必須の最小貢献量とオプションの増分のリストに変換します。 ビットセット`dp`圧縮されたブール配列として使用される整数です。`v`で拡張できるすべての合計を加算します。`v`。 これにより、完全な O(n・s) 配列が回避され、ビット操作を使用して遷移が高速に保たれます。 

ターゲット ビットの検出後の早期終了は重要な最適化です。必要な合計に達すると、それ以上の処理は不要になります。

 ## 特殊なケース

 タスク全体で必要な最小値の合計がすでに目標を超えている場合、アルゴリズムは DP を構築せずに直ちに拒否します。 たとえば、次のようなケース`n=3`、各タスクには最小値があります`5`、そしてターゲット`10`ベースラインがすでに設定されているため、オプションの選択肢を検討する前に失敗します。`15`。 

各タスクにサブタスクが 1 つだけある場合、アルゴリズムは固定合計チェックに退化します。 オプションの値がないため、DP はそのままになります。`{0}`、そして答えは、強制された合計が目標と等しいかどうかによってのみ決まります。 

小さなオプションの値が多数存在する場合、ビットセット シフト操作によって到達可能な状態が密集して蓄積されます。 DP はそれらを正しくマージします。これは、各シフトがその値を 1 回選択することに正確に対応し、シフトを繰り返すと二重にカウントされることなく自然に組み合わせが考慮されるためです。
