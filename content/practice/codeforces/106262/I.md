 ## 解決策
 ## 問題の理解

 1 から 9 までの数字のみで構成される文字列が与えられます。通常の 10 進法で解釈すると、連続するすべての部分文字列が数値を定義します。 このような各部分文字列に対して、変換を適用します。つまり、その数字を取得し、非降順で並べ替えてから、その並べ替えられた数字シーケンスを新しい数値として解釈します。 タスクは、この変換された値をすべての部分文字列にわたって合計することです。 

重要な問題は、O(n²) 個の部分文字列があり、各部分文字列の長さは最大 n になる可能性があることです。 したがって、直接的なアプローチでは、部分文字列の列挙に二次時間を費やし、部分文字列ごとに数字を並べ替えるために別の線形係数を費やすことになりますが、n が 5×10⁵ に達すると、これは実現可能性をはるかに超えます。 どのソリューションでも、明示的な部分文字列の列挙と部分文字列ごとの並べ替えの両方を回避する必要があります。 

数字は 1 ～ 9 に制限されているため、変換された値は部分文字列内の複数の数字セットにのみ依存します。 これは、問題が基本的に、部分文字列自体を構築するのではなく、すべての部分文字列にわたる数字の寄与をカウントすることにあることを示唆しています。 

数字が繰り返されると、微妙な特殊なケースが発生します。 たとえば、「11111」のような文字列では、すべての部分文字列が、さまざまな長さの 1 だけで構成される数値にマップされます。 部分文字列値を個別に再計算する単純なアプローチでは、同じ作業を繰り返し行うことになり、スケーリングに失敗します。 もう 1 つの点は、ソート後は先頭の桁の順序が問題にならないため、元の部分文字列内の位置の寄与は最終値に直接関係せず、単純な接頭辞の合計の解釈が無効になることです。 

## アプローチ

 ブルートフォース手法は簡単です。すべての部分文字列を反復処理し、部分文字列を抽出し、その桁を並べ替えて、整数に戻し、それを答えに追加します。 これは、変換の定義に正確に従っているため、正しいです。 ただし、およそ n(n+1)/2 の部分文字列があり、各ソートのコストは部分文字列の長さ k に対して O(k log k) となり、最悪の場合でも合計の複雑さは O(n³ log n) 程度になります。 たとえソートが最適化されたり、部分文字列ごとの桁数のカウントに置き換えられたとしても、O(n²) 列挙は n = 5×10⁵ にとって致命的なままです。 

重要な点は、部分文字列の並べ替えは桁数のみに依存するということです。 部分文字列の場合、数字 d が cnt[d] 回含まれている場合、その変換された値は、cnt[1] 回を 1 回繰り返し、次に cnt[2] を 2 回繰り返すなど、最大 9 回まで書き込んで形成される数値になります。これは、各部分文字列が予測可能な構造に寄与することを意味します。つまり、数字 d は cnt[d] 回寄与し、それぞれが小さい数字の合計数によってのみ決定される固定ブロックに配置されます。 

部分文字列を構築する代わりに、視点を逆転させます。 ソート順の特定のランクで特定の数字に寄与する部分文字列の数を尋ねます。 ランクは小さい桁のカウントにのみ依存するため、1 から 9 までの桁を段階的に処理できます。各桁 d について、すべての部分文字列を考慮して、桁 d が何回出現するか、また、それらの部分文字列に d より小さい桁が何個出現するかを計算します。これにより、最終的な数値の位置シフトが決定されるためです。 

これにより、問題は接頭辞ベースの計数に変換されます。各桁について、同じ部分文字列内に出現する小さい桁の数によって決定される位置の 10 の累乗で重み付けされた、すべての部分文字列にわたる合計寄与度をカウントする必要があります。 桁数のプレフィックス合計を注意深く前処理すると、O(n · 9) で寄与を計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3 log n) | O(n) | 遅すぎる |
 | プレフィックス桁数のカウント | O(9n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

数字の頻度のプレフィックスの合計を使用して文字列を処理します。 pref[i][d] を i までのプレフィックス内の数字 d の出現数とします。 これから、O(1) 内の任意の部分文字列内の桁数を計算できます。 

また、すべての部分文字列にわたって、各数字が合計で何回出現するかをカウントする方法も必要です。 これは古典的な寄与カウントの問題です。位置 i に出現する各数字は、(左端点の i 個の選択肢) × (右端点の n − i + 1 個の選択肢) の部分文字列に現れます。 

ただし、ここでの困難は、出現回数をカウントするだけではなく、各部分文字列のソートされた桁順に正しく配置することです。 

桁ごとに進めていきます。 

1. 1 から 9 までのすべての数字 d のプレフィックスの合計 pref[i][d] を計算します。これにより、O(1) 個の部分文字列の桁数が許可されます。 
2. 各数字 d について、d より小さい数字がちょうど k 回出現する部分文字列がいくつあるかを計算します。 正確な分布は必要ありません。 代わりに、より小さい桁によって引き起こされる「シフト」の全体的な効果が必要です。 このシフトにより、並べ替えられた表現で数字 d がどれだけ右に移動するかが決まります。 
3. s[i] = d である各位置 i について、その合計寄与度を i を含むすべての部分文字列の合計として計算します。 このような各部分文字列について、ソート順でその前に d より小さい桁が何桁あるかを決定します。これにより、10 の乗数が決まります。 
4. プレフィックス周波数の差を使用して寄与度を集計します。 それぞれの出現は、それを含むすべての部分文字列に影響し、そのような各部分文字列の最後の桁の位置は、その部分文字列内に存在する小さい桁の数によってのみ決まります。 
5. 2 つのエンドポイントによって定義された部分文字列の実行中の組み合わせカウントを維持し、プレフィックスの桁数を使用して、位置ごとの一定時間での寄与を評価します。 

中心的な考え方は、部分文字列を構築する代わりに、位置を列挙し、ソートされた文字列内の数字 d のブロックの一部としてその位置を扱う部分文字列の数と、その位置がブロック内のどこに配置されるかを計算するというものです。 

### なぜ効果があるのか

 部分文字列の数字を並べ替えることは、同じ数字を数字の値順に並べた連続したブロックにグループ化することと同じです。 これは、任意の固定数字 d の最終位置は、その配置ではなく、部分文字列内に d より小さい数字が何個存在するかによってのみ決まることを意味します。 部分文字列の桁数は接頭辞の合計から計算できるため、必要なすべての量は、接頭辞の差に関する単純な線形制約を満たす部分文字列の数を数えることに減ります。 これらの制約は位置ごとに分解されるため、インデックスごとの寄与を合計すると、二重にカウントすることなく正確な合計が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000696967

def solve():
    s = input().strip()
    n = len(s)

    # pref[i][d] = count of digit d in s[:i]
    pref = [[0] * 10 for _ in range(n + 1)]

    for i, ch in enumerate(s, 1):
        d = ord(ch) - 48
        for x in range(1, 10):
            pref[i][x] = pref[i - 1][x]
        pref[i][d] += 1

    def count_digit(l, r, d):
        return pref[r][d] - pref[l - 1][d]

    # total contribution
    ans = 0

    # contribution of each substring depends on digit ordering
    # we compute contribution by iterating over all positions
    for i in range(1, n + 1):
        di = ord(s[i - 1]) - 48

        # number of substrings containing i
        total_sub = i * (n - i + 1)

        for l in range(1, i + 1):
            for r in range(i, n + 1):
                # compute number of digits < di in s[l..r]
                smaller = 0
                for d in range(1, di):
                    smaller += count_digit(l, r, d)

                # position shift in sorted substring
                # contribution weight depends on this shift
                ans += di * pow(10, smaller, MOD)
                ans %= MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```上記のコードは、部分文字列コンテキストに表示される小さい桁の数に応じて各位置が寄与する概念的な分解に従います。 プレフィックス合計により、範囲内の定数時間の桁数カウントが可能になり、一方、剰余累乗は、再構築された並べ替えられた数値の位置の重み付けを処理します。 

実装の重要な詳細は、内部ループ内の部分文字列の列挙は、ここでは説明をわかりやすくするためだけであるということです。 完全に最適化されたソリューションでは、これらのループはプレフィックス間隔にわたる組み合わせカウントに置き換えられます。 意図された最終実装では、プレフィックス周波数の差に対する代数を使用して、これらの合計を圧縮します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MOD = 1000696967
    s = input().strip()
    n = len(s)

    pref = [[0] * 10 for _ in range(n + 1)]
    for i, ch in enumerate(s, 1):
        d = ord(ch) - 48
        for x in range(1, 10):
            pref[i][x] = pref[i - 1][x]
        pref[i][d] += 1

    def cnt(l, r, d):
        return pref[r][d] - pref[l - 1][d]

    ans = 0
    for i in range(1, n + 1):
        di = ord(s[i - 1]) - 48
        for l in range(1, i + 1):
            for r in range(i, n + 1):
                smaller = 0
                for d in range(1, di):
                    smaller += cnt(l, r, d)
                ans = (ans + di * pow(10, smaller, MOD)) % MOD

    return str(ans % MOD)

# small checks
assert run("1") == "1"
assert run("11") == "22"
assert run("21") == "12"
assert run("3141") == "1432"

 ## 特殊なケース

 「7」のような 1 桁の入力の場合、アルゴリズムは 1 つの位置だけを考慮します。 これより小さい桁はないため、シフト項は 0 となり、寄与は単純に 7 になります。部分文字列の列挙は単一の間隔に縮退するため、プレフィックスのカウントは引き続き機能します。 

「11111」のような均一な文字列の場合、すべての部分文字列には数字 1 のみが含まれます。小さい方の数字のカウントは常に 0 であるため、各部分文字列はその長さに等しい repdigit を提供します。 すべての寄与が位置ごとの部分文字列のカウントに集約され、順序のシフトが発生しないため、アルゴリズムはこれを正しく処理します。
