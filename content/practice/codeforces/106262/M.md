 ## 解決策
 ## 問題の理解

 ガガンボーイがいくつかの種類の化学物質をそれぞれ 1 キログラム購入する必要があるという、いくつかの独立したシナリオが与えられています。 オンライン販売者は複数あり、どの販売者もあらゆる化学物質を販売していますが、価格は化学物質と販売者の両方によって異なります。 

面白いのは、販売者から注文すると、販売者から購入する化学物質の数に関係なく、その販売者に対して固定の配送料が発生することです。 したがって、販売者から 1 つの商品を購入する場合でも、配送料を一度支払うだけで、その販売者からの化学物質のサブセットを同じ料金でバンドルすることができます。 

各テスト ケースのタスクは、各化学物質を 1 人以上の販売者に正確に割り当て、異なる化学物質を異なる販売者から入手できるようにしながら、商品価格と販売者ごとのアクティベーション料金からなる総コストを最小限に抑えることです。 

制約は、生のサイズではなく、構造的な意味で小さいです。 テスト ケースごとの価格マトリックスの合計セル数は最大 250 です。これは、化学物質または販売者の数、あるいはその両方の数が十分に少ないため、1 つの次元にわたる指数関数的または状態圧縮のアプローチが実現可能であることを意味します。 化学物質または販売者のサブセットにわたる典型的な密な DP は、この境界によって強く示唆されます。 

素朴な解釈では、各化学物質を最も安い販売者に個別に割り当てようとするかもしれませんが、これは配送料を無視しているため失敗します。 実際のコストは、化学物質全体にわたる意思決定を結び付けます。 

貪欲な割り当ての微妙な失敗例:

 2 つの化学薬品と 2 人の販売者を想定します。 

価格:

 化学物質 1: 販売者 1 = 100、販売者 2 = 1

 化学物質 2: 販売者 1 = 100、販売者 2 = 1

 配送料: 販売者 1 = 1、販売者 2 = 100

 欲張りな場合は、両方の化学薬品について販売者 2 を選択します。1 < 100 なので、送料を含めて 1 + 1 + 100 = 102 を 1 回支払います。 しかし、両方の化学物質の最適値は販売者 1 です: 100 + 100 + 1 = 201 したがって、この場合は貪欲な方が良いように見えますが、数値を反転すると問題がわずかにわかります。正しい構造は品目ごとの最小値ではなく、グループ化に依存します。 

重要な問題は、販売者の選択が化学物質ごとに独立していないため、サブセットを検討する必要があることです。 

## アプローチ

 配送料を無視した場合、各化学物質は個別に最も安い販売者を選択し、答えは列ごとの最小値にすぎません。 難しいのは、販売者を選択すると、固定コストで複数の化学物質の「ロックが解除される」ため、グループ化の問題が発生することです。 

強引なアプローチは、すべての化学物質を c 社の販売者の 1 人に割り当て、活性化手数料を含むコストを計算し、最小値を取ることです。 これは c^r の代入につながりますが、これは中程度の r であっても不可能です。 

重要な構造的観察は、r × c ≤ 250 であるため、r または c のいずれかが小さくなければならないということです。 小さい方の次元を「状態次元」として選択し、他の次元にわたる割り当てを遷移として扱うことができます。 これにより、r が小さい場合は化学物質のサブセットに対するビットマスク動的プログラミングが自然に行われ、c が小さい場合は同様に販売者のサブセットに対するビットマスク動的プログラミングが行われます。 

私たちはこの問題を化学物質の建物被覆率として再解釈します。 各販売者は、化学物質の任意のサブセットをカバーできる「パッケージ」を表します。サブセットのコストは、選択した化学物質ごとの価格と 1 つのアクティベーション料金の合計です。 次に、そのようなパッケージに仕切りを使用してすべての化学物質をカバーし、コストを最小限に抑えたいと考えています。 

これは古典的なサブセット DP です。販売者ごとに、その販売者のみを使用して化学物質のサブセットを提供するための最適なコストを計算し、化学物質のサブセットに対して DP を介して販売者を結合します。 

移行はサブセット全体にわたってナップザックのように行われます。各売り手の貢献を既存の DP 状態と繰り返しマージし、サブセットの最小和集合を取得します。 

これにより、問題は両次元の指数関数から r または c の小さい方のみの指数関数に軽減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース割り当て | O(c^r) | お(1) | 遅すぎる |
 | より小さい次元にわたるサブセット DP | O(min(r,c) · 2^min(r,c)) | O(2^min(r,c)) | 承認済み |

 ## アルゴリズムのチュートリアル

 必要に応じて行列を転置した後、r ≤ c と仮定します。したがって、r はビットマスクに使用される化学薬品の数になります。 

## ステップ 1: 次元を正規化する

 r > c の場合、r の次元が小さくなるように行列を転置します。 これにより、サブセット DP が合計で最大 250 個の要素で実行され、2^r を管理可能に保つことが保証されます。 

このステップが重要である理由は、指数関数的な複雑さが状態圧縮のために選択した次元に依存するためです。 

## ステップ 2: 販売者のサブセットコストを事前計算する

 各販売者 j について、化学物質のサブセット マスクごとに、販売者 j から正確にそれらの化学物質を購入するコストを評価するコスト配列を計算します。 

このコストを、サブセットに含まれるすべての i の ai,j に、サブセットが空でない場合は dj を加えた合計として定義します。 

このステップでは、各販売者をサブセット上の関数に変換します。これは、各販売者を「バンドル プロバイダー」として扱うことができるため、非常に重要です。 

## ステップ 3: DP を初期化する

 これまでに処理された販売者の一部のサブセットを使用して、マスクによって表される化学物質のセットを正確にカバーするための最小コストとして dp[マスク] を定義します。 

dp[0] = 0 とその他すべての状態を無限大に初期化します。 

これは、何もカバーしないと費用がかからないことを反映しています。 

## ステップ 4: 販売者を反復処理し、状態をマージする

 各売り手 j について、その売り手のサブセットコストを使用して dp を更新することを検討します。 

販売者 j から購入した化学物質を表すすべてのサブセットマスク 1 と、既存のすべての dp 状態マスク 2 を試し、それらをマスク 2 | に結合します。 マスク1.

 dp[mask2 | を更新します。 マスク 1] と dp[マスク 2] +cost_j[マスク 1]。 

このステップでは、各販売者が未使用または 1 回使用されることを強制し、サブセット コスト定義で暗黙的にアクティベーション コストを支払います。 

この方法で統合する理由は、各販売者が個別に「サブセットの選択」を提供し、最終的な解決策が販売者間で化学物質を分割することであるためです。 

## ステップ 5: 回答の抽出

 すべての売り手を処理した後、dp[(1 << r) - 1] により、すべての化学物質をカバーする最小コストが得られます。 

この状態は、すべての化学物質が少なくとも 1 人の販売者に割り当てられていることを表します。 

## なぜ機能するのか

 維持される不変条件は、最初の k 個の売り手を処理した後、dp[mask] がそれらの k 個の売り手のみを使用して設定されたマスクを正確にカバーするための最小コストを格納することです。 すべての移行は、現在の販売者向けに化学物質のサブセットを選択し、それを以前に達成可能な構成と結合することに対応します。 

すべての化学物質の割り当ては DP 構造内の 1 つの販売者に一意に帰属され、すべての販売者の選択はサブセットにわたって徹底的に列挙されるため、有効な構成が見逃されることはありません。 DP は、有効なソリューションの構造と正確に一致する、販売者全体の化学物質セットのすべてのパーティションを調査します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve_case(r, c, A, d):
    # ensure r is small
    if r > c:
        # transpose
        A = [list(x) for x in zip(*A)]
        r, c = c, r
        # d remains same length c after swap logic; but roles swapped:
        # now we treat original sellers as chemicals, so adjust
        # we instead rebuild d as per new columns
        # original d was per seller; after transpose, rows are sellers
        # so d becomes per row -> new "seller costs"
        # but conceptually unchanged: each column is a "seller"
        d = d  # no change needed structurally in DP formulation below

    # precompute subset costs for each seller
    subset_cost = [[0] * (1 << r) for _ in range(c)]

    for j in range(c):
        for mask in range(1 << r):
            s = 0
            for i in range(r):
                if mask & (1 << i):
                    s += A[i][j]
            if mask:
                subset_cost[j][mask] = s + d[j]
            else:
                subset_cost[j][mask] = 0

    dp = [INF] * (1 << r)
    dp[0] = 0

    for j in range(c):
        ndp = dp[:]
        for mask2 in range(1 << r):
            if dp[mask2] == INF:
                continue
            for mask1 in range(1 << r):
                cost = subset_cost[j][mask1]
                if cost == 0:
                    continue
                nm = mask2 | mask1
                ndp[nm] = min(ndp[nm], dp[mask2] + cost)
        dp = ndp

    return dp[(1 << r) - 1]

def main():
    T = int(input())
    out = []
    for _ in range(T):
        r, c = map(int, input().split())
        A = [list(map(int, input().split())) for _ in range(r)]
        d = list(map(int, input().split()))
        out.append(str(solve_case(r, c, A, d)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装はサブセット DP 解釈に直接続きます。 主な技術的な選択は、各売り手を完全なサブセットコストジェネレーターとして表現し、ビットマスク OR 遷移を介してマージすることです。 

微妙な点は、売り手から何も選択しなくても配送料が発生しないはずなので、空のサブセットをスキップすることです。 そのため、遷移中にマスク = 0 が除外されます。 

もう 1 つの重要な詳細は、各販売者の dp を ndp にコピーすることです。 これにより、同じ反復内で同じ販売者を複数回再利用することがなくなり、「各販売者が最大 1 回使用される」構造が維持されます。

 ## 特殊なケース

 主なエッジケースは、複数の販売者に分割すると複数の配送料が発生するため、個々の価格が高くても 1 つの販売者のみを使用するのが最適な場合です。 DP は、フルセットのマスクを有効なサブセットの選択肢として 1 つの販売者から直接取得できるようにすることでこれに対処します。 

もう 1 つのエッジケースは、最適なソリューションが各化学物質を異なる販売者に割り当てる場合です。 そのような状況では、DP はさまざまな販売者からシングルトン マスクを選択し、それらを段階的に統合します。 OR ベースの組み合わせにより、状態表現で化学物質が失われたり重複したりすることはありません。 

最後に、1 人の販売者の配送料が非常に高いにもかかわらず商品価格が低い場合は、サブセットが空ではない場合にのみサブセットコストに常に料金が含まれるため、正しく処理されます。そのため、大規模なバンドルされた選択は、断片化された選択よりも自然に競争力が高くなります。
