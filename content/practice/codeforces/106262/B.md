 ## 問題の理解

 1 から 2 までのインデックスが付いた非常に大規模なプレイリストを維持しています。$n$、最初は空です。 プレイリストは、無限参照トラックの部分文字列でセグメントを上書きする操作と、セグメント内の文字頻度をクエリする操作の 2 種類の操作をサポートします。 

リファレンス トラックは、次のベース文字列から構築されます。$k$はっきりとした文字。 最初から始めると考えてください$k$一定の順序で並べられたアルファベット。 トラックは一定のサイズのブロックで形成されます$k$。 各ブロックは前のブロックの回転であり、現在のブロックの最初の文字が末尾に移動されて次のブロックが生成されます。 後$k$このような回転により、パターンが繰り返されます。 これは、無限軌道が周期的であることを意味します$k^2$、あるので$k$回転、それぞれの長さ$k$。 

更新操作ごとにセグメントが与えられます。$[a,b]$プレイリスト内で、位置から始まるこの無限周期トラックの連続した部分文字列で置き換えます。$i$。 各クエリ操作では範囲が求められます。$[a,b]$、最初のそれぞれ何回か$k$その範囲に文字が表示されます。 

重要な難しさは規模にあります。 プレイリストの長さ$n$到達できる$10^9$したがって、配列を明示的に保存することは不可能です。 操作数は最大です$10^5$したがって、各操作はほぼ対数時間以上で処理される必要があります。 これにより、完全な文字列を明示的にシミュレートしたり、それを高密度に保存したりするアプローチは即座に除外されます。 

微妙な問題は、更新によって以前のコンテンツが上書きされ、後のクエリは最新の状態を反映する必要があることです。 これにより、暗黙的な配列に対する範囲割り当てと範囲合計クエリをサポートする動的構造が強制されます。 

単純な間違いは、更新のたびに無限トラックの部分文字列を明示的に展開しようとすることです。 1 回の更新でも、最大長のセグメントが要求される場合があります。$10^9$、それらを直接構築することは不可能です。 もう 1 つのよくある失敗は、トラックが周期的に周期的であると仮定することです。$k$、追加の回転レイヤーは無視されます。これにより、文字の位置が不正確になります。 

## アプローチ

 ブルートフォース手法では、プレイリストを明示的な配列として表し、更新ごとに無限トラックから文字を 1 つずつコピーします。 各クエリは範囲をスキャンして頻度をカウントします。 これは操作の直後にあるため、概念的には正しいですが、各更新には時間がかかる場合があります。$O(n)$、そして$10^5$これは次の操作になります$10^{14}$実行可能な限界をはるかに超えた最悪の場合でも動作します。 

重要な点は、更新によって明示的に書き込まれない限り、個々の文字を実際に保存する必要がないということです。 すべては範囲ベースであり、更新は非常に定期的なソースからの割り当てです。 これは当然、割り当てられた領域のみを格納し、各セグメントを周期的なマスター トラックへのマッピングとして遅延的に表す暗黙的なセグメント ツリーを示唆しています。 

2 番目の重要な単純化は、マスター トラックが周期的であることです。$k^2$。 これにより、1 期間にわたる接頭辞の合計を使用して、無限トラックの任意の部分文字列の文字数を一定時間で事前計算できます。 これが利用可能になると、プレイリスト内のすべてのセグメントをマッピングとして解釈できるようになります。$(start, length)$を周期文字列に変換し、展開せずに効率的にカウントします。

 ## アルゴリズムのチュートリアル

 まずマスター トラックの構造を圧縮して、部分文字列のクエリにすぐに答えられるようにします。 次に、各ノードがプレイリストの連続した間隔を表し、それがマスター トラックにどのようにマッピングされるかを保存する動的セグメント ツリーを使用してプレイリストを維持します。 

### 1. 定期的なマスタートラックを構築する

 長さのある無限軌道の完全な 1 周期を構築します。$k^2$。 イニシャルから始める$k$-レターベースでは、それぞれを生成します$k$回転、それぞれの長さ$k$、それらを連結します。 これにより固定配列が得られます`T`長さの$k^2$。 

また、プレフィックス数の配列も事前に計算します。`pref[p][c]`文字を何回保存するか$c$に登場する`T[1..p]`。 

これにより、任意のセグメントのカウントを計算できるようになります。`T`で$O(k)$最大 2 つのプレフィックスの違いとラップアラウンド処理を使用する時間。 

### 2. プレイリストを暗黙的に表現します

 範囲全体にわたって動的セグメントツリーを使用します。$[1,n]$。 各ノードはセグメントを表します$[l,r]$。 ノードは 2 つの状態のいずれかになります。 

それは、葉のような割り当てられたセグメントであり、次の部分文字列に直接マッピングされます。`T`、開始位置を保存する`s`そんな位置`l`に相当する`T[s]`、または部分的な更新により子に分割されました。 

ノードが更新によって完全に上書きされた場合、その子は破棄され、そのマッピングのみが保存されます。 

### 3. 範囲の割り当ての処理

 アップデート処理時$"+ i a b"$、プレイリストセグメントを割り当てます$[a,b]$の部分文字列に`T`位置から開始$i$長さの$b-a+1$。 

現在のノードが完全にカバーされている場合は、そのマッピングを単純に上書きします。 

部分的にカバーされている場合は、その割り当てを子に分割することでその割り当てをプッシュダウンし、各子が対応するシフトされたセグメントを正しく継承するようにします。`T`、そして再帰します。 

これにより、すべてのノードが常にクリーンなマッピングを完全に表すか、`T`または、より小さな一貫した部分に分解されます。 

### 4. クエリの処理

 質問に答えるには$"? a b"$、セグメントツリーを走査し、重複するノードからの寄与を収集します$[a,b]$。 

のセグメントに直接マッピングされる完全にカバーされたノードごとに、`T`、プレフィックス テーブルを使用してその寄与を計算します。 ノードが部分的にカバーされている場合は、子に再帰します。 

ノードの寄与は、そのセグメントを変換することによって計算されます$[l,r]$間に入って$[s, s + (r-l)]$周期文字列内で事前計算されたプレフィックス合計をクエリし、ラップアラウンド モジュロを処理します$k^2$。 

### 5. なぜ効果があるのか

 どの時点でも、プレイリスト内のすべての位置は、マスター トラックへの 1 つのマッピングによって表されるか、まだ空のままです。 範囲の割り当ては常にセグメント全体を一貫して置き換えるので、どの位置にも競合するソースが蓄積されることはありません。 セグメント ツリーにより、割り当てられた領域がばらばらにカバーされることが保証され、周期的なプレフィックス構造により、実際の文字を再構築することなく、マッピングされたすべてのセグメントを独立して評価できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("l", "r", "left", "right", "start")
    def __init__(self, l, r):
        self.l = l
        self.r = r
        self.left = None
        self.right = None
        self.start = None  # None means unassigned

def build_track(k):
    base = [chr(ord('A') + i) for i in range(k)]
    T = []
    cur = base[:]
    for _ in range(k):
        T.extend(cur)
        cur = cur[1:] + cur[:1]
    return T

def build_prefix(T, k):
    m = len(T)
    pref = [[0] * (m + 1) for _ in range(k)]
    for i, ch in enumerate(T, 1):
        c = ord(ch) - ord('A')
        for j in range(k):
            pref[j][i] = pref[j][i - 1]
        pref[c][i] += 1
    return pref

def query_track(pref, k, l, length, m):
    res = [0] * k
    if length <= 0:
        return res
    l = (l - 1) % m + 1
    r = l + length - 1

    def add_segment(L, R):
        for c in range(k):
            res[c] += pref[c][R] - pref[c][L - 1]

    if r <= m:
        add_segment(l, r)
    else:
        add_segment(l, m)
        add_segment(1, r - m)
    return res

def merge(a, b):
    for i in range(len(a)):
        a[i] += b[i]
    return a

def query(node, ql, qr, pref, k, m):
    if not node or qr < node.l or node.r < ql:
        return [0] * k

    if ql <= node.l and node.r <= qr and node.left is None and node.start is not None:
        length = node.r - node.l + 1
        return query_track(pref, k, node.start, length, m)

    if node.left is None and node.start is None:
        return [0] * k

    mid = (node.l + node.r) // 2
    if node.left is None:
        node.left = Node(node.l, mid)
        node.right = Node(mid + 1, node.r)
        if node.start is not None:
            node.left.start = node.start
            node.right.start = node.start + (mid + 1 - node.l)

    return merge(
        query(node.left, ql, qr, pref, k, m),
        query(node.right, ql, qr, pref, k, m)
    )

def update(node, ul, ur, start, pref, k, m):
    if not node or ur < node.l or node.r < ul:
        return node

    if ul <= node.l and node.r <= ur:
        node.left = None
        node.right = None
        node.start = start + (node.l - ul)
        return node

    mid = (node.l + node.r) // 2
    if node.left is None:
        node.left = Node(node.l, mid)
        node.right = Node(mid + 1, node.r)
        if node.start is not None:
            node.left.start = node.start
            node.right.start = node.start + (mid + 1 - node.l)

    update(node.left, ul, ur, start, pref, k, m)
    update(node.right, ul, ur, start, pref, k, m)
    return node

def solve():
    k, n, q = map(int, input().split())

    T = build_track(k)
    m = len(T)
    pref = build_prefix(T, k)

    root = Node(1, n)

    out = []
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '+':
            i, a, b = map(int, tmp[1:])
            root = update(root, a, b, i, pref, k, m)
        else:
            a, b = map(int, tmp[1:])
            ans = query(root, a, b, pref, k, m)
            out.append(" ".join(map(str, ans)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```セグメント ツリー ノードは、構造情報と可能なベース オフセットのみをマスター トラックに運びます。 ノードが完全に上書きされると、子の格納が回避され、表現がコンパクトに保たれます。 部分的な更新またはクエリ中に、各子がマスター トラック内の正しくシフトされた開始インデックスを継承するように、ノードを遅延分割します。 

部分文字列からトラックへの変換は常に循環配列上の接頭辞の合計に還元されるため、文字ごとのシミュレーションが回避されます。

 ### 例 1

 更新により重複領域が上書きされる小規模な構成を検討します。 

| 操作 | 更新されたセグメント | 効果 |
 | --- | --- | --- |
 | + 3 2 4 | [2,4] | t[3..5] を書き込みます |
 | + 1 3 5 | [3,5] | 前の | の一部を上書きします。 
| ? 2 5 | クエリ | 最終状態をカウントします。 

最初の更新では、トラックから位置 2 ～ 4 に連続したマッピングが割り当てられます。2 番目の更新では、その領域のサフィックスが上書きされ、新しい位置に拡張されます。 クエリはセグメント ツリー内のセグメントに分割され、上書きされた部分と上書きされていない部分の両方からの寄与が結合されます。 これは、ノードを分割し、一貫したマッピングを維持することによって、部分的な上書きが正しく処理されることを示しています。 

### 例 2

 更新間に重複がないケース:

 | 操作 | セグメント | 効果 |
 | --- | --- | --- |
 | + 5 1 3 | [1,3] | プレフィックスを塗りつぶす |
 | + 2 8 10 | [8,10] | 別の領域 |
 | ? 1 10 | 完全なクエリ | 両方の領域の合計 |

 ここで、ツリーには 2 つの独立した割り当てられたセグメントが含まれています。 クエリは両方の寄与を集計し、素の更新が干渉せず、トラバーサル中に正しく結合されることを確認します。

 ## 特殊なケース

 エッジ ケースの 1 つは、同じセグメントの上書きが繰り返されることです。 この構造は、ノードが再び完全にカバーされると常に子を破棄することでこれを処理します。 これにより、古い部分マッピングが後のクエリに影響を与えるのを防ぎます。 

もう 1 つのエッジ ケースは、書き込まれなかった領域をクエリすることです。 これらは暗黙的ツリー内の欠落ノードに対応し、寄与ゼロとして扱われ、空のセグメントが誤ったカウントを生成しないようにします。 

最後の微妙なケースは、更新が以前に分割されたノードと部分的に重なる場合です。 強制伝播ステップにより、レイジー マッピングを保持するノードが再分割される前に展開されることが保証されるため、両方の半分が正しくシフトされたインデックスをマスター トラックに受け取ることができます。
