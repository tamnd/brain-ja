 ## 解決策
 ## 問題の理解

 1 から n までの直線のチェックポイントが与えられます。 水は常にチェックポイント 1 からチェックポイント n まで厳密に順方向に流れ、洪水を止める唯一の方法は、連続するチェックポイント間の n − 1 個の接続の少なくとも 1 つをブロックすることです。 

i と i + 1 の間の各接続 i は、対応するプロジェクトを実行することでブロックできます。 各プロジェクトにはお金に影響を与える値 xi があり、正の値はお金を増やし、負の値はお金を減らします。 b. 初期予算から始めます。 

プロジェクトのサブセットを任意の順序で選択できますが、各プロジェクトは最大 1 回しか使用できません。 プロジェクトは、xi が負の場合にコストを支払うのに十分な資金を現在持っている場合にのみ実行可能です。 前向きなプロジェクトは予算を増やすため、実現可能性の問題が発生することはありません。 

目標は、最終的な金額を最大化しながら、少なくとも 1 つの接続がブロックされ、実行順序が実行予算に対して有効になるようなプロジェクトのサブセットを選択することです。 

この制約により、私たちは線形または線形に近い解決策に向かうことになります。 n が最大 100000 で、xi の大きさが 10000 に制限されている場合、順列またはサブセットを直接試行する O(n^2) 戦略は不可能です。 O(n log n) であっても許容されますが、O(n^2) または部分集合に対する指数推論は合格できません。 

すべてのプロジェクトが高価なネガであり、初期予算が小さすぎてどのプロジェクトも開始できない場合、微妙な問題が発生します。 この場合、単一のエッジをブロックすることで理論的にはフラッディングが解決されますが、有効なシーケンスの最初のステップを実行する余裕はないため、答えは -1 でなければなりません。 

もう 1 つの失敗例は、すべてのプロジェクトを選択することが常に最適であると想定していることから生じます。 初期段階でネガのコストが高すぎると、その後の有益なプロジェクトへのアクセスが妨げられる可能性があるため、注文は非常に重要です。 

## アプローチ

 ブルート フォース アプローチでは、エッジのすべてのサブセットを試し、少なくとも 1 つのエッジが選択されているかどうかを確認し、実行を通じて予算がマイナスにならないように選択されたプロジェクトの順序が存在するかどうかを確認します。 サブセットごとに、すべての順列をシミュレートするか、有効なシーケンスを見つけようとします。 これはすぐに実行不可能になります。サブセットが 2^(n−1) あり、各妥当性チェックに O(k log k) かそれ以上の時間がかかる可能性があり、指数関数的な爆発につながります。 

重要な観察は、実現可能性は選択したプロジェクトの順序にのみ依存し、単一線を超えるグラフ構造には依存しないということです。 前向きなプロジェクトは予算が増えるだけなので、早めに実行するのが常に安全です。 唯一の制約はネガティブ プロジェクトから生じます。各ネガティブ プロジェクトは、実行する前に十分な資金が必要です。 

これにより、問題は利益 xi を持つアイテムのサブセットを選択することに変換されます。ここで、正の値は無料の利益であり、負の値は最小のプレフィックス リソース条件を必要とします。 すべてのポジティブなプロジェクトが実行されると、残りの問題は次のとおりです。各ステップで現在の資金が必要なしきい値を下回らないように、どのようなネガティブなプロジェクトをスケジュールできるでしょうか? 最適な構造は、常に手頃な価格のネガティブ プロジェクトをコストの高い順に実行することです。つまり、絶対損失が小さいプロジェクトを最初に優先します。 この貪欲な注文により、小さな損失を最初に安全に処理できる場合でも、大きな損失の早い段階で予算を「無駄に」することがなくなります。

 ## アルゴリズムのチュートリアル

 私たちは、最初に収益性の高いプロジェクトを処理するか、次に高価なプロジェクトを慎重に処理するかに分けて決定します。

1. プロジェクトを 2 つのグループに分割します。xi > 0 のプロジェクトと xi ≤ 0 のプロジェクトです。ポジティブなプロジェクトは常に予算を改善し、発注を制限しないため、いつでも安全に含めることができます。 
2. すべての正の xi を直ちに答えに追加し、その合計だけ現在の予算を増やします。 これにより、後の決定に使用できるリソースが最大化され、決定を遅らせる理由がなくなりました。 
3. すべてのネガティブなプロジェクトを収集し、xi の降順に並べ替えます。 これは、-100 よりも -1 のような値の方が安全に支払うことができるため、被害が最も少ない損失を最初に処理することを意味します。 
4. このソートされたリストを繰り返し処理します。 負の xi ごとに、現在のバジェットが少なくとも -xi であるかどうかを確認します。 「はい」の場合、それを実行し、予算から -xi を減算し、合計の答えに xi を追加します。 
5. 現時点でネガティブ プロジェクトに手が届かない場合は、永久にスキップします。 マイナスは予算を減らすだけなので、後でもっと手頃になることはありません。 
6. 少なくとも 1 つのプロジェクトが全体で実行されていることを確認します。 何も選択されなかった場合は、エッジのブロックに失敗したため、-1 が返されます。 

注文の背後にある重要な考え方は、損失が小さいほど将来の選択に対する柔軟性が保たれるということです。 大きな損失を早期に実行すると、小規模な損失の実行可能性が損なわれる可能性がありますが、逆の場合は実行可能性が損なわれることはありません。 

### なぜ効果があるのか

 どの時点でも、重要な唯一の制約は、現在の予算がマイナスのプロジェクトを支払うのに十分な大きさであるかどうかです。 前向きなプロジェクトは予算を増やすだけなので、一般性を失うことなく安全に最初に適用できます。 ネガティブ プロジェクトの中で、より高価な損失を早期にスワップすることは、後のステップで予算の制約を難しくするだけであるため、最適なスケジュールは、選択されたすべてのネガティブが、実現可能性を損なうことなく、コストの降順でない順序で表示されるスケジュールに変換できます。 この交換引数により、貪欲なコスト順ソート構造によって最適な解決策が除外されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, b = map(int, input().split())
    arr = list(map(int, input().split()))

    total = b
    picked_any = False

    positives = 0
    negatives = []

    for x in arr:
        if x > 0:
            positives += x
            picked_any = True
        else:
            negatives.append(x)

    total += positives

    negatives.sort(reverse=True)

    for x in negatives:
        if total >= -x:
            total += x
            picked_any = True

    if not picked_any:
        print(-1)
    else:
        print(total)

if __name__ == "__main__":
    solve()
```実装は構造に直接に従います。 プラスの貢献は無条件で有益であるため、最初にすべてのプラスの貢献を蓄積します。 次に、最も害の少ない削減が最初に試行されるように、負の値を並べ替えます。 予算チェックにより、その時点で予算が無効になるようなプロジェクトが決して実行されないことが保証されます。 ブール値フラグは、プロジェクトが正常に選択されたかどうかを追跡します。エッジをブロックしないとフラッディングの問題は解決されないため、これは必須です。 

微妙な点は、スキップされたネガを決して再検討しないことです。 これは正しいです。なぜなら、マイナスをスキップするということは、現在の予算が不十分であることを意味し、そのマイナスがより良い位置で再検討されるまで残りの操作で予算を増やすことはできないため、後で実行可能になることは決してないからです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, b = map(int, input().split())
    arr = list(map(int, input().split()))

    total = b
    picked = False

    pos = 0
    neg = []

    for x in arr:
        if x > 0:
            pos += x
            picked = True
        else:
            neg.append(x)

    total += pos
    neg.sort(reverse=True)

    for x in neg:
        if total >= -x:
            total += x
            picked = True

    return str(total) if picked else "-1"

# provided samples
assert run("6 7\n3 -1 4 1 -5\n") == "15"
assert run("5 4\n-6 -7 -6 -7\n") == "-1"

# minimum size
assert run("2 0\n5\n") == "5"

# all positives
assert run("4 1\n2 3 4\n") == "10"

# all negatives but feasible chain
assert run("4 10\n-3 -4 -5\n") == " -2".strip()

# tight budget edge
assert run("3 5\n-6 1\n") == "-1"

 ## 特殊なケース

 すべてのプロジェクトがネガティブで、最初に何も与えることができない場合、操作を開始できないため、アルゴリズムはすぐに -1 を返します。 たとえば、入力`n = 3, b = 1, [-5, -6]`最初の手頃な価格チェックに合格しないため、プロジェクトは実行されず、フラグは false のままになります。 

正の値と負の値の両方が存在するが、正の値が小さい場合、アルゴリズムにより正の値が最初に適用されることが保証され、以前は不可能であった負の値が可能になる可能性があります。 例えば、`b = 1, [2, -5]`-5 を試みる前に予算を 3 に増やしますが、マイナスは依然として実行不可能であるため、正しく失敗します。 

大きなネガが小さなネガよりも前に表示される場合、並べ替えにより、早期に予算を無駄にしないことが保証されます。 のために`b = 10, [-1, -1, -20]`、最初に 2 つの -1 操作を実行すると、バジェットが徐々に減り、順序を間違えると失敗して推論がブロックされる可能性がある -20 の早まった試行が回避されます。
