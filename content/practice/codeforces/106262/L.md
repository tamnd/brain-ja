 ## 問題の理解

 2 つの非常に大きな正方行列が与えられます$A$そして$B$、ただし完全には提供されません。 代わりに、各行列はその非ゼロのエントリによってのみ記述されます。 すべての欠落位置は暗黙的にゼロであり、非ゼロのエントリの数は、$n^2$。 

タスクは製品のトレースを計算することです$AB$。 具体的に言うと、$C = AB$、すべての対角要素の合計が必要です$C_{i,i}$、固定された大きな素数を法として計算されます。 

定義を直接展開すると、$C$は$$C_{i,i} = \sum_{k=1}^{n} A_{i,k} B_{k,i}$$トレースは次のようになります$$\mathrm{tr}(AB) = \sum_{i=1}^{n} \sum_{k=1}^{n} A_{i,k} B_{k,i}.$$入力サイズから明らかなように、$n$と同じ大きさにすることができます$10^5$、ゼロ以外のエントリの数は線形のみです。$n$。 これにより、すべてを反復するアプローチは即座に除外されます。$n^2$行列の位置を指定するか、標準の行列の乗算を実行します。 平$O(nk)$または$O(k^2)$と$k \approx 1.5n$への依存を回避する場合にのみ許容されます。$n$自体。 

主要な構造上の制約はスパース性です。すべての演算は、行列の次元ではなく非ゼロのエントリの数に応じてスケールする必要があります。 

製品マトリックスを明示的に構築する必要があると仮定すると、微妙な故障モードが現れます。 それは不可能です。$A$の多くのエントリと対話する可能性があります$B$、その逆も同様で、単純に処理すると中間の組み合わせが多すぎます。 

もう 1 つの微妙な問題は、二重カウントのリスクです。 のエントリをループすると、$A$そしてそれぞれについて、次のすべてのエントリとの一致を試みます$B$、誤って両方向に貢献を蓄積したり、インデックスの調整をミスしたりする可能性があります。 貢献は次の場合にのみ存在します。$A_{i,k}$そして$B_{k,i}$同じ中間インデックスを共有する$k$データが事前にグループ化されていない場合、誤って処理されやすくなります。 

## アプローチ

 直接解釈すると、トレース式が三重にネストされたループに拡張されます。 各ペアごとに$(i,k)$で$A$、行内のすべてのエントリを検索します$k$の$B$列を見つけるには$i$。 最悪の場合、これは、すべての非ゼロエントリをスキャンすることになります。$B$エントリーごとに$A$、与える$O(k_a k_b)$、それは約です$O(n^2)$。 これでは遅すぎる$n$は$10^5$。 

重要な観察は、次の式であるということです。$$\sum_{i,k} A_{i,k} B_{k,i}$$同じ中間インデックスを共有するエントリのペアにのみ依存します$k$。 行列の乗算の観点から考える代わりに、これをマッチング問題として再解釈できます。$k$、行からの値のすべてのペアが必要です$k$で$A$そしてコラム$k$で$B$。 

これはデータを再編成することを示唆しています。 エントリをグループ化すると、$A$行インデックスとエントリによって$B$列インデックスごとに、次に各共有インデックスごとに$k, i$一致する値を直接乗算することができます。 これにより、問題は、実際のゼロ以外のエントリのみを反復処理し、ハッシュ マップに寄与分を蓄積することになります。 

のゼロ以外の各エントリ$A$で$(i,k)$にエントリーして貢献しています$B$それはまさに$(k,i)$、インデックスを付けることができます$B$行または列ごとに適切に実行し、線形時間で照合します。 

したがって、問題は、疎な隣接リストを格納し、一致する積を効率的に合計することに帰着します。

 ## アルゴリズムのチュートリアル

 計算したい$\sum_{i,k} A_{i,k} B_{k,i}$すべてのペアを明示的に反復することなく。 

1. ゼロ以外のエントリをすべて読み取ります。$A$そして行インデックスをキーとする辞書にそれらを保存します。 行ごとに$i$、ペアのリストを管理します$(k, A_{i,k})$。 この構造により、固定行からのすべての発信接続に効率的にアクセスできます。 
2. ゼロ以外のエントリをすべて読み取ります。$B$行インデックスをキーとする辞書にもそれらを保存しますが、次のように慎重に解釈されます。$B_{k,i}$。 行ごとに$k$、ペアのリストを管理します$(i, B_{k,i})$。 これにより、共有インデックスが調整されます$k$両方の行列にわたって。 
3. 指定された係数を法とする答えのアキュムレータを初期化します。 
4. 各行インデックスを反復処理します。$k$に登場する$B$。 エントリーごとに$(i, B_{k,i})$その行で行を検索します$i$で$A$。 その行の各エントリは、$A$、 言う$(k', A_{i,k'})$、次の場合にのみ貢献します。$k' = k$。 したがって、2 番目の座標で一致する必要があります。 

無関係なエントリのスキャンを避けるために、代わりに事前にインデックスを付けます。$A$列ごとにも保存し、列ごとに保存します$k$すべてのペア$(i, A_{i,k})$。 
5. それぞれについて$k$、リストが 2 つあります。$A$-列のあるエントリ$k$、そしてすべて$B$-行のあるエントリ$k$。 これら 2 つのリストのすべてのペアを乗算し、共有構造に基づいて照合します。$A_{i,k}$そして$B_{k,i}$。 
6. 蓄積する$A_{i,k} \cdot B_{k,i}$必要な係数を答えのモジュロに代入します。 
7. 最終累積値を出力します。 

### なぜ効果があるのか

 トレースの式は、列インデックスが次のインデックスのペアを正確に分離します。$A$の行インデックスと一致します$B$、行インデックスは次のとおりです。$A$の列インデックスと一致します$B$。 共有中間インデックスによってエントリをグループ化することによって$k$、すべての有効な製品を保証します$A_{i,k} B_{k,i}$は 1 回だけカウントされます。 一致しないインデックスはトレース制約を満たさないため、他の組み合わせは不可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1006903069

def main():
    n = int(input())
    
    ka = int(input())
    A_by_col = {}
    
    for _ in range(ka):
        i, j, x = map(int, input().split())
        if j not in A_by_col:
            A_by_col[j] = []
        A_by_col[j].append((i, x))
    
    kb = int(input())
    B_by_row = {}
    
    for _ in range(kb):
        i, j, x = map(int, input().split())
        if i not in B_by_row:
            B_by_row[i] = []
        B_by_row[i].append((j, x))
    
    ans = 0
    
    for k in B_by_row:
        if k not in A_by_col:
            continue
        A_list = A_by_col[k]
        B_list = B_by_row[k]
        
        for i, bval in B_list:
            for i2, aval in A_list:
                if i2 == i:
                    ans = (ans + aval * bval) % MOD
    
    print(ans)

if __name__ == "__main__":
    main()
```実装ストア$A$列ごとにグループ化されているため、列のインデックスが$k$が集合場所になります。 それぞれについて$k$、すべてを取得します$A_{i,k}$そしてすべて$B_{k,i}$、行インデックスが次の場合にのみ乗算されます。$A$の列インデックスと一致します$B$。 各リストはスパース性制約によって制限されており、格納されたエントリの総数は線形であるため、入れ子になったループは安全です。$n$。 

重要な点は、インデックスを正しく配置することです。 よくある間違いは、両方の行列を行ごとにグループ化することです。これにより、トレース式に必要な相互一致構造が失われます。

## テストケース```python
import sys, io

MOD = 1006903069

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    ka = int(input())
    A = {}
    for _ in range(ka):
        i, j, x = map(int, input().split())
        A.setdefault(j, []).append((i, x))

    kb = int(input())
    B = {}
    for _ in range(kb):
        i, j, x = map(int, input().split())
        B.setdefault(i, []).append((j, x))

    ans = 0
    for k in A:
        if k not in B:
            continue
        for i, ax in A[k]:
            for j, bx in B[k]:
                if i == j:
                    ans = (ans + ax * bx) % MOD

    return str(ans)

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、値が$A$しかし、それに一致するインデックスは存在しません$B$。 たとえば、次の場合$A$含まれています$(2,5)=10$しかし$B$行のあるエントリがありません$5$、その後、この貢献は消滅する必要があります。 アルゴリズムでは、両方のディクショナリに存在するキーに対してのみ反復処理を行うため、これは自然に処理されます。そのため、欠落している行は反復を生成せず、偶発的な影響も生じません。 

もう 1 つの特殊なケースは、同じ中間インデックスを共有する複数のエントリです。 仮定する$A$列に 2 つのエントリがあります$k$、 そして$B$2 つのエントリが連続しています$k$。 アルゴリズムはそのグループ内で完全な外積を形成しますが、インデックスが一致するペアのみが寄与します。 これはネストされたループ内の等価性チェックによって処理され、不正なペアがカウントされないことが保証されます。
