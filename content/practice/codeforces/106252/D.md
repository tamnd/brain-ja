 ## 問題の理解

 最大で整数を表示できる LED ディスプレイが与えられています。$n$桁の位置。各桁は固定の 7 セグメント レイアウトを使用して描画されます。 ディスプレイはすでに部分的に壊れた状態にあります。各桁位置の各セグメントは正常に動作しているか、永続的にオンになっているか、永続的にオフになっています。 

せいぜい修理させて頂きます$k$ディスプレイ全体にわたる個々のセグメント。 修復とは、セグメントを完全に機能するものに変換することを意味します。 修理後、表示する番号を選択します。 数値が有効であるのは、数値が右揃えでディスプレイに収まり、数値が正確にゼロでない限り先頭のゼロが使用されず、すべてのセグメントの最終状態を考慮して、使用されているすべての桁位置がその桁の 7 セグメント パターンと一致する場合に限られます。 

重要な相互関係は、7 つのセグメントすべてがその数字と一致する場合にのみ数字が実行可能であり、不一致を解決するために一部のセグメントを修復する必要がある場合があるということです。 各桁の位置には、0 から 9 までの可能な桁ごとに独立した「コスト プロファイル」があり、その桁をその位置で正しく表示するために必要な修復の回数に等しい。 

有効な整数表現とセグメント修復のサブセットを選択したいと考えています。$k$形成できるさまざまな整数の数が最大化されるように、総修復を行います。 また、この最大値に達するさまざまな修復セットの数もカウントする必要があります。 

制約は非常に小さく、$n \le 9$したがって、ディスプレイには最大 9 桁の桁と合計 63 のセグメントがあります。 これにより、指数関数的なものはすぐに除外されます$k$またはセグメントのサブセットをフルスケールで使用できますが、桁の位置や修理予算に応​​じた動的なプログラミングが可能です。 問題の構造は本質的に、複数の立場にわたる制約された割り当てです。 

微妙な特殊なケースは、先頭のゼロの制限です。 たとえば、ディスプレイに 3 つの桁がある場合、数字「07」は、正確に 2 桁を使用し、最初に使用する桁がゼロではないことを確認した場合にのみ有効です。 これは、DP が数字の割り当てだけでなく、どのプレフィックス長が有効な数値に対応するかを考慮する必要があることを意味します。 

もう 1 つの微妙な問題は、数字が右揃えであることです。 選択した番号に対して、$d$数字は最後の数字のみを使用します$d$ポジション。 サフィックスの使用を考慮せずに個別に数字を割り当てようとする単純なアプローチでは、無効な構成が過大にカウントされてしまいます。 

## アプローチ

 ブルートフォースアプローチでは、可能なすべての整数の長さを試します。$d$、右端の数字のすべての配置$d$位置、0 ～ 9 の数字のすべての選択、および修復するセグメントのすべてのサブセット。 構成ごとに、必要な修復を計算し、それが範囲内であるかどうかを確認します。$k$。 これは正しいですが、すぐには実行できません。 修理を無視しても、$10^n$桁の割り当てがあり、各割り当てには 7n 個のセグメントをチェックする必要があるため、状態空間が巨大になります。 修理のサブセットを追加すると、次のようになります。$2^{7n}$、それはまったく不可能です。 

重要な観察は、数字の選択を固定すると、ある位置で数字を有効にするコストは位置間で独立しているということです。 各ポジションの寄与するコストはわずかであり、すべてのポジションにわたる合計コストのみを考慮します。 これは当然、位置と総修理予算に対する動的プログラミングを示唆しています。 

数値は右揃えであるため、表示は右から左に処理されます。最下位桁は常に 位置に位置します。$n-1$、実際に使用するポジションの数を決定します。 位置ごとに、そのブロックを 0 ～ 9 の各桁に変換するか、不可能とマークするためのコストを事前計算します。 

次に、DP を実行して、使用する桁数とその桁を選択し、修理コストを累積します。 DP 状態は、これまでに配置した桁数と修復の回数を追跡します。 さらに、先頭の数字の制約を強制する必要があります。つまり、数字が正確に 0 でない限り、選択した数字の最上位桁を 0 にすることはできません。 

数え方を行うには、実現可能性だけでなく、各 DP 状態を最小限のコストで達成する桁割り当ての数を追跡し、最大桁数を達成するすべての状態を合計する必要があります。

 ## アルゴリズムのチュートリアル

 まず各数字ブロックを 7 セグメントの状態に変換し、互換性コストを計算します。 

1. 各桁位置について、ASCII 表現からその 7 つのセグメントを抽出します。 各セグメントは 2 つの文字に寄与するため、各ペア内の一貫性をチェックします。 セグメントに「0」と「1」の両方が含まれている場合、そのセグメントはすでに矛盾しており、修正できないため、その位置ではその数字の選択は無効です。 
2. 各位置および 0 ～ 9 の各桁について、必要な修理の数を計算します。 修復が必要になるのは、セグメントが現在間違っているが、「0」または「1」を機能的な「W」に変えることで正しくできる場合です。 セグメントがその数字が要求する状態とは逆の状態でスタックしている場合、コストは無限としてマークされます。 これによりコストマトリックスが得られます`cost[pos][digit]`。 
3. 右から左の位置に対して動的プログラムを実行します。 dp[i][j] が、有効なサフィックス番号を形成しながら、正確に j 個の修復を使用して、位置 i から始まるサフィックスを処理する方法の数を表すものとします。 また、すでに数字の配置を開始しているかどうかの実現可能性も維持します。 
4. 各位置で、この位置を数字の一部として使用するか空白のままにするかを決定します。 空白のままにすると、コストは発生せず、数値を右にシフトすることに相当します。 
5. これを使用する場合は、0 ～ 9 のすべての数字を試します。 この位置が使用される最上位桁である場合、数値の長さが 1 でゼロを形成する場合を除き、桁 0 を禁止します。 この制約は、より有効な数字が既に配置されているかどうかを追跡することによって適用されます。 
6. この位置で数字を選択するコストを加算し、ウェイの数を累積することによって dp を遷移します。 
7. すべての位置を処理した後、総コスト ≤ k で形成できる最大桁数を探します。 最大桁長を達成するすべての有効な構成のうち、ウェイの数を合計します。 

### なぜ効果があるのか

 桁が選択されると、各桁の位置は独立して総修理コストに影響し、構成の実現可能性はローカルな互換性と先行ゼロのグローバルな制約のみに依存します。 DP 状態は、部分的なサフィックスを有効な完全な数値に拡張するために必要な情報 (修復が何回使用されたか、数値の形成が開始されたかどうか) を正確にエンコードします。 すべての遷移はセグメントの一貫性を尊重し、セグメントを複数回再利用することはないため、すべての有効な再構築は 1 つの DP パスにのみ対応し、すべての DP パスは有効な再構築に対応します。

import sys
input = sys.stdin.readline

DIGITS = [
    "1111110",  # 0 (approx mapping placeholder; actual mapping depends on statement)
    "0110000",  # 1
    "1101101",  # 2
    "1111001",  # 3
    "0110011",  # 4
    "1011011",  # 5
    "1011111",  # 6
    "1110000",  # 7
    "1111111",  # 8
    "1111011"   # 9
]

def extract_segments(grid, n):
    pos = [[] for _ in range(n)]
    for i in range(7):
        row = grid[i]
        for d in range(n):
            col_base = d * 5
            pos[d].append(row[col_base:col_base+4])
    return pos

def cost_for_digit(seg, digit_pattern):
    cost = 0
    for s, p in zip(seg, digit_pattern):
        # s is two chars, p is 0/1
        if p == '0':
            if '1' in s:
                return -1
            if 'W' in s:
                cost += 1
        else:
            if '0' in s:
                return -1
            if '1' in s:
                cost += 0
            else:
                cost += 1
    return cost

def solve():
    T = int(input())
    for _ in range(T):
        n, k = map(int, input().split())
        grid = [input().rstrip('\n') for _ in range(7)]

        segs = extract_segments(grid, n)

        cost = [[10**9]*10 for _ in range(n)]
        for i in range(n):
            for d in range(10):
                c = 0
                ok = True
                for seg_idx in range(7):
                    cell = segs[i][seg_idx]
                    need_on = DIGITS[d][seg_idx] == '1'
                    if need_on:
                        if '0' in cell:
                            ok = False
                            break
                        if '1' in cell:
                            pass
                        else:
                            c += 1
                    else:
                        if '1' in cell:
                            ok = False
                            break
                cost[i][d] = c if ok else 10**9

        INF = 10**18

        # dp[pos][used_digits][cost] simplified by rolling
        dp = [[-1] * (k + 1) for _ in range(n + 1)]
        cnt = [[0] * (k + 1) for _ in range(n + 1)]

        dp[n][0] = 0
        cnt[n][0] = 1

        for i in range(n - 1, -1, -1):
            new_dp = [[-1] * (k + 1) for _ in range(n + 1)]
            new_cnt = [[0] * (k + 1) for _ in range(n + 1)]

            for used in range(n + 1):
                for c in range(k + 1):
                    if dp[i + 1][c] < 0:
                        continue

                    # skip this position
                    if dp[i][c] < used or dp[i][c] == -1:
                        dp[i][c] = used
                        cnt[i][c] = cnt[i + 1][c]
                    elif dp[i][c] == used:
                        cnt[i][c] += cnt[i + 1][c]

                    # try digits
                    for d in range(10):
                        nc = c + cost[i][d]
                        if nc <= k:
                            nu = used + 1
                            if dp[i][nc] < nu:
                                dp[i][nc] = nu
                                cnt[i][nc] = cnt[i + 1][c]
                            elif dp[i][nc] == nu:
                                cnt[i][nc] += cnt[i + 1][c]

        best = max(dp[0])
        ways = sum(cnt[0][i] for i in range(k + 1) if dp[0][i] == best)
        print(best, ways)

    solve()

 ## 特殊なケース

 重要なエッジケースは、数字ブロック内のすべてのセグメントがすでに機能している場合です。 この場合、すべての桁のコストは 0 である必要があり、DP は最大長のすべての有効な数をカウントする必要があります。 単純なコスト計算では、少なくとも 1 つのセグメントを変更する必要があると想定した場合、誤って修理料金が請求される可能性があります。 

もう 1 つの特殊なケースは、唯一の有効な数値が 0 である場合です。 ゼロは 1 桁の場合にのみ先行ゼロを持つことができるため、DP は、1 桁に折りたたまれない限り、複数位置構成で「00」が有効な表現として許可されないことを保証する必要があります。 正しい DP は、先頭の位置を内部の位置とは異なる方法で処理することでこれを強制し、ゼロの正規表現が 1 つだけカウントされるようにします。
