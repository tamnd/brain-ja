 ## 問題の理解

 ターゲット画像が与えられます。$n \times m$グリッド。 各セルにはカラー ラベルまたはゼロが含まれます。ゼロは透明を意味します。 最終的な可視画像は、複数のレイヤーを積み重ねることによって生成されます。各位置で、最上位レイヤーの最初の不透明ピクセルによって、何が見えるかが決まります。 

レイヤーなしで開始し、新しいレイヤーを繰り返し追加できます。 新しいレイヤーは、単一の色で完全に塗りつぶされるか、完全に透明になります。 レイヤーを作成した後、その中の個々のピクセルを変更できます。コストをかけてピクセルを色にペイントできます。$a$、またはコストをかけて消去して透明にします$b$。 目標は、総コストを最小限に抑えながら、結果として得られる可視画像がターゲット グリッドと正確に一致するレイヤーのスタックを構築することです。 

重要な点は、レイヤーがオクルージョンを通じて相互作用することです。 上位レイヤーのピクセルは、透明でない限り、その下のすべてを隠します。 これは、上位レイヤーでの間違いにより、下位の正しいコンテンツが完全に無効になる可能性があることを意味するため、使用されているレイヤーで間違ったピクセルは慎重に消去または修正する必要があります。

重要な課題は、レイヤーは空間的に相互作用するものの、コスト構造はグローバルな順序付けを必要とする方法で異なる色を組み合わせていないことを認識することです。

 ## アルゴリズムのチュートリアル

 ## ステップ 1: 各色の出現を数える

 グリッドを 1 回スキャンし、各色が何回出現するかを数えます。 させて$k_c$色を含むセルの数を示します$c$。 これにより、その色にレイヤーを使用しない場合にペイントする必要があるピクセル数が正確にわかります。 

## ステップ 2: レイヤーを使用しない場合のコストを考慮する

 カラー専用レイヤーを作成しない場合$c$の場合、すべてのオカレンスを個別にペイントする必要があります。 費用は$a \cdot k_c$。 これは、構造の最適化を行わない、純粋なピクセルごとのアプローチです。 

## ステップ 3: 定数レイヤーの使用コストを検討する

 色で塗りつぶされた完全なレイヤーを作成すると$c$、すべてから始めます$n \cdot m$に設定されたセル$c$。 存在すべきではないすべての細胞$c$消去しないと、最終画像に誤って表示されてしまいます。 がある$n \cdot m - k_c$このようなセルを使用するため、コストは次のようになります。$$a + b \cdot (nm - k_c).$$レイヤーの作成では最初の項はゼロであるため、変更のみが問題となります。 

## ステップ 4: 色ごとに適切なオプションを選択する

 色ごとに、次の 2 つの戦略の最小値を採用します。$$\min(a \cdot k_c,\; a + b \cdot (nm - k_c)).$$グリッドに表示されるすべての色のこの値を合計します。 

## ステップ 5: 合計を出力する

 最終的な答えは、すべての色の最適な独立コストの合計です。 

## なぜ機能するのか

 定色レイヤーは一度作成されると完全に決定され、そのレイヤー内のすべてのピクセルが独立して有用な信号またはノイズのいずれかに寄与します。 ターゲット イメージと一致しないピクセルは、他のレイヤーが何を行うかに関係なく、明示的に消去する必要があります。 同様に、各セルは正確に 1 つの最終値に属しているため、個々のピクセルをペイントしても他の色に干渉しません。 

これにより、色間の依存関係が排除されます。レイヤーの順序付けがないため、別の色の決定に基づいて、ある色に必要な操作の数を減らすことができます。 したがって、各色のコストは独立かつ加算され、色ごとの最小値が全体的に最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m, a, b = map(int, input().split())
        cnt = {}
        nm = n * m

        for _ in range(n):
            row = list(map(int, input().split()))
            for x in row:
                cnt[x] = cnt.get(x, 0) + 1

        ans = 0
        for c, k in cnt.items():
            if c == 0:
                continue
            paint_only = a * k
            layer = a + b * (nm - k)
            ans += min(paint_only, layer)

        print(ans)

if __name__ == "__main__":
    solve()
```この実装は、色の周波数マップに依存します。 グリッド サイズは概念的にカウントに平坦化され、レイヤーをシミュレートする必要がなくなります。 重要な点は、カラー ゼロを個別に扱うことです。カラー ゼロは透明度を表し、構築コストは必要ありません。 

各色は、その頻度と合計グリッド サイズから計算された 1 つの決定に寄与します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    input = sys.stdin.readline

    def solve():
        T = int(input())
        for _ in range(T):
            n, m, a, b = map(int, input().split())
            cnt = {}
            nm = n * m
            for _ in range(n):
                for x in map(int, input().split()):
                    cnt[x] = cnt.get(x, 0) + 1
            ans = 0
            for c, k in cnt.items():
                if c == 0:
                    continue
                ans += min(a * k, a + b * (nm - k))
            print(ans)

    solve()
    return ""

# minimum size
run("1\n1 1 5 3\n1\n")

# all zeros
run("1\n2 2 1 1\n0 0\n0 0\n")

# single color
run("1\n2 3 2 10\n1 1 1\n1 1 1\n")

# mixed case
run("1\n1\n2 3 1 1\n1 2 1\n")

# sparse color test
run("1\n3 3 5 1\n1 0 0\n0 2 0\n0 0 0\n")

 ## 特殊なケース

 周波数マップにはカラー 0 のみが含まれており、コスト計算では無視されるため、完全にゼロで構成されるグリッドは正しく処理されます。 ペイントやレイヤーの作成はトリガーされないため、出力はゼロのままです。 

大きなグリッド内の単一の非常に珍しい色について、アルゴリズムは以下を比較します。$a \cdot k_c$と$a + b \cdot (nm - k_c)$。 以来$k_c$小さい場合は個別に塗装することが選択され、高価な全層構造は避けられます。 

完全に均一なグリッドの場合、消去が必要ないため、レイヤー オプションは厳密に安価になります。 アルゴリズムは同じ比較を通じてこれを正確に識別し、定層戦略を自動的に選択します。
