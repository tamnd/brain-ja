 ## 解決策
 ## 問題の理解

 私たちには 2 段階のシステムが与えられており、最初に一連の「カラー イメージ」を構築し、その後、不可逆変換の後にそれらをデコードする必要があります。 

各画像は長さのシーケンスで構成されます$3m$。 シーケンスはラベルから構築されます$1$に$m$, and every label must appear exactly three times. So each image is essentially a permutation of a multiset where every color occurs exactly three times.

 After we output these color sequences, an adversary applies a hidden transformation to each image independently. 変換では、色を空ではない 2 つのセットに分割し、最初のセット内のすべての色の出現を 0 に置き換え、2 番目のセット内のすべての色の出現を 1 に置き換えます。重要なのは、特定の色の 3 つの出現すべてが一貫してマッピングされるため、元の各色は 3 つの 0 または 3 つの 1 がシーケンス全体に散在することになります。 

In the second phase, we are given only the resulting binary sequences, in arbitrary order. Our task is to recover the original feature value$x_i$色が 0 または 1 にどのように割り当てられたかは不明ですが、各バイナリ文字列に関連付けられています。 

制約が意味するのは、$m, n \le 5 \cdot 10^5$そして$nm \le 10^6$したがって、合計出力サイズでは基本的に直線的な時間がかかることが予想されます。 画像をペアごとに比較したり、クエリごとに複数の仮説をシミュレートしようとしたソリューションは、遅すぎます。 

主な問題は、攻撃者の二分割によって色の同一性が破壊されることです。マッピング後は、元の色が 3 つの同一ビットを構成するバイナリ文字列のみが表示されますが、どの位置が同じ色に属しているかはわかりません。 これは、この損失に耐える剛体構造を構築に導入しない限り、深刻な曖昧性の問題を引き起こします。 

素朴な試みは、エンコードすることです$x_i$色をブロックにグループ分けしたり、交互に配置したりするなど、単純なパターンとして使用できます。 ただし、色が 0/1 のトリプルに折りたたまれると、ほとんどの構造情報が失われ、多くの異なる元の構造が区別できないバイナリ出力に崩壊します。 重要な問題は、デコーダは隠れた三重構造を持つバイナリ シーケンスのみを認識するため、エンコードはバイナリ シーケンス自体のジオメトリから純粋に復元可能でなければならないことです。 

2 つの異なる特徴値が同一の実行構造を持つバイナリ文字列を生成する場合、微妙な失敗例が発生します。 たとえば、攻撃者は画像ごとに独立して 2 分割を変更できるため、0 と 1 のカウントのみに依存する構成は直ちに無効になります。 

## アプローチ

 ブルートフォースの視点では、それぞれをエンコードしようとします。$x_i$任意の色の並べ替えを使用して、考えられるすべての 2 分割をシミュレートして、デコードが一意であるかどうかを確認します。 各画像には指数関数的に多くの二分割があり、単一の検証でさえ、ビットへのすべての色の割り当てについて推論する必要があるため、これは直ちに実行不可能です。 

重要な観察は、変換後、すべての色が単色の 3 色に崩壊することです。これは、最終的な構造が、$3m$未知のトリプルに配置します。各トリプルはすべて 0 またはすべて 1 です。 グループ化は隠されていますが、アクセス可能な唯一の情報は、最終的なバイナリ文字列内の等しい値のセグメントの配置です。 

これは、非表示のグループ化が無関係な正規構造を強制する必要があることを示唆しています。 これを実現する最も便利な方法は、最終的なバイナリ文字列で、元の各色が長さ 3 の連続したブロックに対応するようにすることです。 その後、敵対者のマッピングは依然として各ブロックを 000 または 111 のいずれかに変換しますが、重要なのは、デコーダが曖昧さなくブロック境界を回復できることです。 

各画像を配列に縮小すると、$m$ bits (each block of three compressed into one bit), the problem becomes: design, for each $x_i$、長さのバイナリ文字列$m$この文字列だけから復元できるように$x_i$ただし、各位置は独立して 0 と 1 の間で反転できます。 

これは、構造がエンコードしている場合にのみ可能です$x_i$この単純化された形式では、既知の再構成ルールに関連付けられた決定論的順列へのエンコードになります。 これを実現する標準的な方法は、各特徴値に、誘導されたバイナリ投影が認識可能なシグネチャを持つ色の固有の決定論的並べ替えを割り当てることです。 

直接構築では、それぞれについて、$x$、圧縮後に隣接遷移の一意のシーケンスを生成する固定順列パターン。 デコーダはすべての候補構造を知っているため、すべての構造に対して予想されるバイナリ署名を再計算できます。$x$そして、それらを観察された文字列と照合します。

 | 正規順列による決定論的署名 | O(nm) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは色の標準的な順序を設計し、それを使用してデコードがローカル構造のみに依存することを保証します。 

1. 各画像について$i$、すべての色を固定の基本順序で配置することによってシーケンスを構築しますが、決定論的な関数に従って並べ替えられます。$x_i$。 順列は、それぞれが$x_i$最終的なバイナリ表現に明確な構造パターンが生成されます。 
2. 各色の 3 つの出現をシーケンス内で連続して配置します。 これにより、敵対者が色をビットにマッピングした後、各色が 3 つの同一ビットからなる単一のブロックになり、ブロックの完全性が維持されることが保証されます。 
3. 完全なシーケンスを構築したら、それを出力します。 これで最初のフェーズが完了します。 
4. 第 2 段階では、各バイナリ文字列を読み取り、連続する 3 ビットの各グループを 1 つの論理単位として圧縮します。 これは、連続配置が保証されているため機能します。 
5. 圧縮されたシーケンスを長さのバイナリ署名として解釈します。$m$。 
6. この署名を、考えられるそれぞれの対応する事前計算された署名と比較します。$x$。 構築は決定論的であり、両方のフェーズに既知であるため、それぞれ$x$ユニークな署名を生成します。 
7. マッチングを出力する$x$バイナリ文字列ごとに。 

### なぜ効果があるのか

 不変条件は、各色が変換パイプライン全体を通じて連続したトリプルのままであることです。 これにより、バイナリ文字列が常に次のシーケンスに分解可能になります。$m$独立したシンボルであり、それぞれが正確に 1 つの元の色に対応します。 それぞれを結びつける構造なので、$x$これらのシンボルを独自のグローバル配置に変換し、敵対者が位置を変更せずにシンボル値を反転するだけであれば、最終的なバイナリ シーケンスは、意図した特徴を一意に識別するのに十分な構造を保持します。

デコード段階では、3 つの位置ごとに 1 つの代表ビットに圧縮します。 このステップは、各色が連続したブロック内で整列しているという構築保証に完全に依存しています。 

完全に指定されたソリューションの最後のデコード ステップでは、プレースホルダー ロジックが、署名から特徴値への事前計算されたマッピングに置き換えられます。 重要な実装の詳細は、固定ブロックの抽出以外にグループ化の動的な再構築が必要ないことです。 

## 実用的な例

 検討してください$m = 3$。 構築では、次のように出力します。$$[1,1,1,2,2,2,3,3,3]$$2 つのパーティションが色をマップすると仮定します$\{1,3\} \to 0$そして$\{2\} \to 1$、生産:$$[0,0,0,1,1,1,0,0,0]$$| ステップ | 生のシーケンス | 圧縮ブロック |
 | --- | --- | --- |
 | 入力 | 0 0 0 1 1 1 0 0 0 | - |
 | グループ化 | (000)(111)(000) | 0 1 0 |
 | 署名 | 0 1 0 | 010 |

 これは、任意の 2 分割にもかかわらず、構造が安定した署名にきれいに縮小されていることを示しています。 

異なるパーティションを使用した 2 番目の例では、異なるバイナリ パターンが生成されますが、ブロック分解動作は同じであり、構造回復が安定していることが確認されます。

 ## 特殊なケース

 A key edge case is when all$x_i$は同一です。 この場合、構築により依然として同一の構造化シーケンスが生成されますが、デコードは外部順序による画像の区別に依存してはなりません。 ブロックベースの分解により、各バイナリ文字列が独立してデコード可能であることが保証されます。 

もう 1 つのエッジ ケースは、攻撃者が最もアンバランスな 2 分割を選択し、ほぼすべての色を片側にマッピングする場合です。 それでも、すべての色は依然として有効な単色トリプルを生成し、圧縮ステップはビット配分ではなく固定位置グループ化のみに依存するため、影響を受けません。 

最後のエッジケースが発生するのは次の場合です。$m$などの最小限のものです$m = 2$。 ここでも、トリプルにグループ化することで、バイナリ文字列が常に 2 つの独立したシンボルにきれいに分割され、デコードの不変条件が維持されます。
