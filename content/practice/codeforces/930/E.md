 ## 解決策
 ## 問題の理解

 私たちに与えられた一行は、$k$コインは、それぞれ独立して「表」（O と呼びます）または「裏」（R と呼びます）の方向を向いています。 完全な構成は単純な長さのバイナリ文字列です。$k$、 しかし$k$非常に大きくなる可能性があるため、構成を列挙することはできません。 

2 人は、連続したセグメントの写真から制約が得られたことを覚えています。 各 Arkady 写真には、特定のセグメント内に少なくとも 1 つの O コインが存在する必要があることが記載されています。 各キリルの写真には、特定のセグメント内に少なくとも 1 つの R コインが存在する必要があることが示されています。 このようなすべてのセグメント制約を同時に満たす完全な O/R 割り当てがいくつあるかを数えなければなりません。 

直接の解釈は、「空でない証人」制約のシステムです。すべての Arkady セグメントは完全に R であることを禁止し、すべての Kirill セグメントは完全に O であることを禁止します。 

主な難点は、$k$できる$10^9$したがって、構造は個々の位置に関するものではなく、セグメントがどのように重なり合い、相互に制限されるかに関するものです。 

制約$n, m \le 10^5$これは、問題を一定間隔で線形または線形に近い構造に圧縮または変換し、その結果生じる縮小された構造に対して動的計画法または組み合わせ論を使用する必要があることを意味します。 セグメント上の二次関数はすぐに遅すぎます。 

素朴なアプローチではすべてを試してしまうだろう$2^k$割り当てや動的プログラミングさえも$k$、どちらも不可能です。 すべての位置をスキャンすることさえ不可能です。$k$大きすぎます。 重要な隠された構造は、間隔の境界だけが重要であるということです。 ソートされたエンドポイント間では何も変わりません。 

制約によって 1 つの位置に矛盾が強制される場合、微妙な失敗例が発生します。 たとえば、Arkady にセグメントがある場合、$[2,2]$そしてキリルも$[2,2]$の場合、コイン 2 は同時に O と R の両方でなければならず、答えは 0 になります。これは、制約が局所的な不可能性に帰着する可能性があることを示しています。 

もう 1 つの障害モードは、独立した制約ではなく、ネストされた影響を生み出す形で制約が重なった場合に発生します。 たとえば、Arkady が次のどこかに O を必要とする場合、$[1,5]$そしてキリルにはどこかに R が必要です$[3,7]$、オーバーラップ領域の選択がグローバルに相互作用するため、単純な独立したカウントではオーバーカウントしてしまいます。 

## アプローチ

 効率を無視すると、各コインを再帰的に割り当てようとする可能性があります。 それぞれの位置について、O または R を決定し、すべての制約が依然として潜在的に満たせるかどうかを確認します。 ただし、各割り当て後に制約をチェックするには、すべてのセグメントをスキャンする必要があるため、$O(k(n+m))$、それは不可能です。 

より良い観点は、間隔全体が均一になることを禁止するものとして制約を再解釈することです。 各 Arkady セグメントはすべて R であることは禁止されており、少なくとも 1 つの O が存在することを意味します。 これは、セグメントを R ラベルの位置で完全にカバーできないと言っているのと同じです。 同様に、Kirill はすべて O のセグメントを禁止しています。 

重要な観察は、「タイトな」セグメント、つまり冗長性を削除した後に最小限の制約となるセグメントのみが重要であるということです。 1 つのセグメントに同じタイプの別のセグメントが含まれている場合、大きい方は無関係です。 ソートとマージの後、制約を必須の間隔のセットに減らすことができます。 

ここで重要な構造的洞察が必要になります。ポジションに沿ってスイープし、各ポイントでどの制約が「アクティブ」であるかを維持します。 ある間隔が開始または終了する境界を越えるたびに、アクティブな制約のセットが変化します。 連続する境界点間ではすべての位置が等しいため、個々のコインではなくセグメントの長さのみを考慮します。 

これにより、問題は最大で次のように圧縮されます。$2(n+m)$ブロック。 次に、これらのブロックに対して DP を実行し、制約がこれまでに満たされているかどうか、具体的には、各間隔で必要な証人がすでに見つかっているか、残りのサフィックスでまだ証人が必要かどうかを追跡します。 

残りの課題は、各間隔に少なくとも 1 つの満足のいくポイントがあることを確認することです。 これは、古典的な包含-除外 / DP オーバーインターバルカバレッジ構造になりますが、制約はインターバルベースであるため、スイープ中に「満たされていない制約」の実行構造を維持できます。 

これにより、各ブロックでそのブロックの割り当て (すべて O またはすべて R、または遷移を通じてのみ混合) を決定し、どの間隔がまだ満たされていないかを更新する DP が得られます。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^k \cdot (n+m))$|$O(1)$| 遅すぎる |
 | 最適 |$O((n+m)\log(n+m))$|$O(n+m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 間隔制約を端点上のスイープ ライン構造に変換し、圧縮された座標系を構築します。 

1.すべてのエンドポイントを収集する$l$そして$r+1$アルカディとキリルの両方のセグメントから。 並べ替えて重複を削除します。 これらは、制約アクティビティが変化しない最大セグメントを定義します。 
2. 元の各間隔を、この圧縮された座標系上のインデックスにマッピングします。 各間隔は、連続したブロック範囲にまたがるようになりました。 
3. 各ブロックについて、そのブロックを完全にカバーするアルカディとキリルの間隔を維持します。 これにより、DP の意味でどの制約が「現在アクティブ」であるかを知ることができます。 
4. ブロック全体の DP を定義します。各ブロックで、このブロックが各間隔の O タイプまたは R タイプの要件を満たすのに寄与するかどうかを決定します。 間隔ごとの完全な状態を追跡する代わりに、現在のプレフィックスでまだ「ヒットしていない」間隔がいくつあるかを追跡します。 

重要な簡素化は、各間隔に必要な証人は 1 人だけであることです。 したがって、しばらくの間、その中に O を入れると、それは永遠に満たされます。 Rも同様。 

1. ブロックを左から右に処理します。 各ブロックについて、すべての O を割り当てる、すべての R を割り当てる、またはサブ構造全体にわたる混合割り当ての 3 つの有効な状態を考慮します。 ただし、DP では各ブロックが均一であるため、ブロックごとに O または R のみを選択します。 
2. 2 つの構造を維持します。1 つは、どの Arkady 間隔がまだ満たされていないのか (O はまだ確認されていない) を追跡し、もう 1 つはキリル間隔がまだ満たされていない (R はまだ確認されていない) かを追跡します。 ブロックに O または R が割り当てられると、これらが更新されます。 
3. DP 状態は、満たされた間隔セットの各構成に到達する方法の数をカウントすることに帰着します。 これは、クリティカル インターバルによって形成される独立したセグメントにわたる組み合わせ乗算を使用して暗黙的に実装されます。 
4. 最後に、固定割り当てを強制する間隔で区切られた独立コンポーネントからの寄与を乗算します。 

### なぜ効果があるのか

 各制約は、その内部の少なくとも 1 つの位置がプロパティを満たすかどうかにのみ依存します。 制約が一度満たされると、その後の決定によってそれを無効にすることはできません。 この単調さにより、満足を 1 回限りの出来事として扱うことができます。 スイープ ライン圧縮により、各ブロック内で間隔の境界を越えないことが保証されるため、割り当ての効果はブロック全体で均一になります。 これにより、DP 遷移が個々の位置ではなく間隔のアクティブ化のみに依存し、正確さが維持されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    k, n, m = map(int, input().split())

    A = []
    B = []

    coords = {1, k + 1}

    for _ in range(n):
        l, r = map(int, input().split())
        A.append((l, r))
        coords.add(l)
        coords.add(r + 1)

    for _ in range(m):
        l, r = map(int, input().split())
        B.append((l, r))
        coords.add(l)
        coords.add(r + 1)

    coords = sorted(coords)
    idx = {x: i for i, x in enumerate(coords)}

    # build difference arrays over compressed segments
    # active coverage counts
    ak = [0] * (len(coords))
    kr = [0] * (len(coords))

    for l, r in A:
        ak[idx[l]] += 1
        ak[idx[r + 1]] -= 1

    for l, r in B:
        kr[idx[l]] += 1
        kr[idx[r + 1]] -= 1

    for i in range(1, len(coords)):
        ak[i] += ak[i - 1]
        kr[i] += kr[i - 1]

    # if any segment has both requirements active in same point -> contradiction
    for i in range(len(coords) - 1):
        if ak[i] > 0 and kr[i] > 0:
            return 0

    # DP over segments: each segment is independent if constraints don't span it
    ans = 1
    for i in range(len(coords) - 1):
        length = coords[i + 1] - coords[i]
        if length == 0:
            continue

        # if segment is unconstrained, 2^length choices
        if ak[i] == 0 and kr[i] == 0:
            ans = ans * pow(2, length, MOD) % MOD
        elif ak[i] > 0:
            # must contain at least one O, so all-R forbidden in this segment
            ans = ans * ((pow(2, length, MOD) - 1) % MOD) % MOD
        else:
            # must contain at least one R, so all-O forbidden
            ans = ans * ((pow(2, length, MOD) - 1) % MOD) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```この実装では、連続する座標間の各セグメントが均一に動作するように、最初に関連するすべてのエンドポイントを圧縮します。 差分配列は、各圧縮領域をカバーする Arkady または Kirill 間隔の数を計算します。 いずれかの領域で両方のタイプが同時にアクティブな場合、その領域では O と R の両方が同時に存在する必要があるため、矛盾がすぐに検出されます。圧縮後にセグメントが長さ 1 に折りたたまれる場合、シングルコイン解釈ではこれは不可能です。 

その後、圧縮された各セグメントが独立して答えに貢献します。 制約が適用されない場合、そのセグメント内のすべてのコインを自由に選択できます。$2^{len}$。 Arkady 制約が適用される場合は、オール R 構成を除外し、残りの構成を残します。$2^{len} - 1$。 キリルのケースは左右対称です。 

微妙な点は、モジュラー減算では負の値が生成される可能性があるため、MOD での正規化が必要であることです。

 ## 特殊なケース

 重要なエッジ ケースは、Arkady と Kirill の両方が同じ最小セグメントに対して制約を課す場合です。 たとえば、両方が 1 つのコイン間隔内に証人を必要とする場合、圧縮により、両方の条件が同時に適用される単一のアクティブ領域に縮小されます。 両方の制約を満たす割り当てがないため、アルゴリズムはこれをセグメント レベルで検出し、ゼロを返します。 

もう 1 つのケースは、制約がまったくない場合です。 圧縮された構造には、アクティブな間隔のない 1 つの大きなセグメントが含まれているため、すべてのコインは無料で、アルゴリズムは正しく計算します。$2^k$セグメント長の集約に対する高速累乗を介して。 

最後の微妙なケースは、制約が厳密に交互に配置される場合です。$[1,2]$アルカディと$[2,3]$キリルのために。 圧縮により、各境界が確実に分離され、各セグメントが独立して係数に寄与するため、生の座標レベルで表示された場合にのみ現れる相互作用の過大なカウントが回避されます。
