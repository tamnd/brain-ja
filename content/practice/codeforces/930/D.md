 ## 解決策

 ## 問題の理解

 個別の整数グリッド点に配置された一連の黒いトークンが与えられます。 開始位置が固定されていない単一の白いトークンもあります。 ゲームは交互のターンで進行します。白が最初に移動し、各ターンでプレイヤーはコントロールするすべてのトークンを 4 つの基本的な方向の 1 つに正確に 1 ユニットずつ移動します。 重要な非対称性は、白いトークンが単一のピースとして移動するのに対し、各黒いトークンは毎ターン独立して任意の方向に移動できることです。 

両方のプレーヤーが最適にプレーすると仮定して、その配置から黒が勝利を強制できる場合、そのポジションは白の負けとみなされます。 タスクは、黒が勝利戦略を持っているように、白トークンの初期位置として機能する整数グリッド ポイントがいくつあるかを数えることです。 

入力サイズは最大 100,000 個の黒点に達するため、ゲームプレイをシミュレートしたり、各白の開始位置を個別に考慮したりしようとするソリューションは、すぐに失敗します。 グリッド自体が可能な位置の範囲が 200001 × 200001 に及ぶため、点のペアに対する 2 次または 2 次に近いアプローチはすでに大きすぎ、直接の状態の列挙は実行不可能になります。 

微妙なエッジケースは、白い​​トークンが黒いトークンから開始できるという事実から生じます。 これは、初期のオーバーラップが有効な状態であることを意味します。 たとえば、すべての黒のトークンが小さな領域に集まっている場合、その領域内の多くの白の開始位置は外側の開始位置とは異なる動作をします。 黒のトークンは独立して移動し、毎ターン脅威領域の形状を再形成する可能性があるため、単純な距離ベースの直感は失敗する可能性があります。 

もう 1 つの注意が必要なシナリオは、黒のトークンが対称に配置されている場合です。 たとえば、黒いトークンが原点の周りの十字形上にある場合、負けた白い位置のセットは円形でもダイヤモンド形でもありませんが、極端な投影によって形成されるマンハッタン距離エンベロープに依存します。 これにより、素朴なユークリッド推論が除外されます。 

## アプローチ

 ブルートフォースアプローチでは、白の開始位置候補ごとに、黒が勝利を強制できるかどうかを評価しようとします。 候補を黒の位置または境界ボックスの整数点に制限したとしても、これには依然として大きなグリッドと 2 人のプレーヤーの動的プロセスが必要です。 それぞれの評価では、黒いトークンが独立した動きに分岐し、方向や位置が指数関数的に分岐する多くのターンをシミュレートする必要があります。 大幅に枝刈りされた検索でも、到達可能な状態空間のサイズに比例するものに縮退しますが、それは大きすぎます。 

重要な観察は、問題は個々のトークンの軌道に関するものではなく、黒いトークンによって引き起こされる幾何学的優勢領域に関するものであるということです。 黒は毎ターンすべてのトークンを動かし、方向を独立して選択できるため、黒はトークンごとのステップごとの単位速度で全方向に効果的に外側に「影響力を拡大」できます。 これにより、構成が L1 ジオメトリでのマルチソース拡張プロセスに変わります。 

ゲームをシミュレートする代わりに、ゲームを封じ込めの問題として再解釈します。 拡大する黒の影響力による罠を常に回避できれば、白のトークンは生き残ります。 白の負け領域は、黒が最終的にすべての脱出方向を「カバー」できるポイントに対応します。 これは、黒の影響がどこまで伝わるのか、保証されたキャプチャ領域内に最初の白の位置がどの位置にあるかを理解することにつながります。

重要な単純化は、動きの対称性から生まれます。 両プレイヤーはターンごとに 1 ユニットを移動するため、ゲームはマンハッタン メトリックでの相対距離に依存します。 黒い側は、黒い点の極端な投影によって決定される L1 ジオメトリの凸状領域を効果的に定義します。 損失領域の境界は、x+y と x-y の最大化と最小化という 4 つの極値方向によって引き起こされるダイヤモンド形の包絡線によって形成されます。 

これら 4 つの極値が特定されると、すべてのグリッド点は、誘導された半平面の交点の内側にあるかどうかに基づいて一定時間内に分類できます。 答えは、これらの極値によって定義される回転された長方形 (ダイヤモンドに整列したボックス) 内の整数点の数になります。 

したがって、問題はグリッド上のゲーム理論から、ブラック トークン投影から導出される単純な幾何学的領域内の格子点の計算に縮小されます。

 ## アルゴリズムのチュートリアル

 黒の構成を、影響境界を定義する 4 つの極値に削減します。 

1. すべての黒い点にわたって x + y の最小値と最大値を計算します。 これは、北東から南西の斜め方向の最も遠い範囲を捉えています。 これが機能する理由は、グリッド内の移動によって x + y 拡張フロントのパリティ構造が維持されるためです。 
2. すべての黒い点にわたって x − y の最小値と最大値を計算します。 これは、北西-南東の対角線の制約を捉えています。 ステップ 1 と合わせて、これは黒拡張の L1 境界エンベロープを完全に説明します。 
3. これら 4 つの値を、白の開始点候補 (x、y) の制約に変換します。 有効な損失領域ポイントは、これらの境界によって引き起こされるすべての不等式を満たさなければなりません。これは、それが 2 つの対角線のストリップの交点の内側に存在することを意味します。 
4. 結果として得られる幾何学的領域を整数の格子点の数に変換します。 この領域は回転座標 (u = x+y、v = x−y) で軸に揃えられているため、カウントは長方形内の整数のペア (u、v) の数を計算し、パリティ制約を尊重しながら逆マッピングすることになります。 
5. パリティを調整します。すべての (u, v) ペアが整数 (x, y) に対応するわけではありません。 u と v が同じパリティを持つペアのみが有効です。 これにより、境界の位置合わせに応じて補正が加えられ、実効カウントが半分になります。 

### なぜ効果があるのか

 各黒いトークンは、ターンごとに 1 ユニットを 4 方向すべてに拡大する波面を定義します。 L1 距離では、これらの波面は線形に結合します。t ステップ後の到達可能なすべての点の結合は、まさに極端な投影から導出された制約の交差になります。 黒のトークンは独立して移動するため、この拡張を制限する相互作用制約はなく、極値のジオメトリのみが問題となります。 損失領域は正確に、白がこれらの拡大する波面に囲まれることを無期限に回避できる点の補数であり、完全に 4 つの極値によって捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    min_s = float('inf')
    max_s = -float('inf')
    min_d = float('inf')
    max_d = -float('inf')
    
    for _ in range(n):
        x, y = map(int, input().split())
        s = x + y
        d = x - y
        min_s = min(min_s, s)
        max_s = max(max_s, s)
        min_d = min(min_d, d)
        max_d = max(max_d, d)
    
    # transform bounds
    # valid region in (u, v) = (x+y, x-y)
    # u in [min_s, max_s], v in [min_d, max_d]
    # count integer (x,y) equivalent to counting valid parity pairs
    
    def count(a, b):
        if a > b:
            return 0
        return b - a + 1
    
    total_uv = count(min_s, max_s) * count(min_d, max_d)
    
    # half of these correspond to integer (x,y)
    # parity adjustment: u and v must have same parity
    def count_same_parity(a1, a2, b1, b2):
        # count u in [a1,a2], v in [b1,b2] with same parity
        def count_parity(l, r, p):
            # numbers in [l,r] with parity p
            first = l if l % 2 == p else l + 1
            if first > r:
                return 0
            return (r - first) // 2 + 1
        
        u_even = count_parity(a1, a2, 0)
        u_odd = count_parity(a1, a2, 1)
        v_even = count_parity(b1, b2, 0)
        v_odd = count_parity(b1, b2, 1)
        
        return u_even * v_even + u_odd * v_odd
    
    print(count_same_parity(min_s, max_s, min_d, max_d))

if __name__ == "__main__":
    solve()
```この実装では、すべての黒い点が 2 つの対角座標系に圧縮されます。 変数`s = x + y`そして`d = x - y`2 つの自然な L1 対角線をエンコードします。 これらの値の極値は、変換された空間の境界四角形を定義します。 

ヘルパー関数`count_parity`指定されたパリティの整数が範囲内にいくつあるかを計算します。一致するパリティ ペアのみが一致するため、これが必要です。`(u, v)`変換後の整数グリッド座標に対応します。 最後の式は、偶数-偶数と奇数-奇数の組み合わせを組み合わせたものです。 

ここでよくある間違いは、パリティ制約を完全に忘れることです。これにより、およそ 2 倍オーバーカウントされ、チェッカーボードのような構成で誤った結果が生成されます。

 ## 特殊なケース

 単一の黒いトークンを使用した最小限の構成は、境界定義を直接示しています。 唯一の点が (0,0) である場合、すべての極値はゼロに折りたたまれ、単一の有効な変換されたセルが生成されます。 すべての範囲が長さ 1 になり、パリティ カウントが正しく減少するため、アルゴリズムはこれを自然に処理します。 

引き伸ばされた水平線または垂直線は、対角線の極値のみが重要であることを示しています。 たとえば、点 (0,0)、(10,0)、(20,0) は、x−y では狭い境界を生成しますが、x+y では広い境界を生成し、アルゴリズムは特別なケーシングを行わずに展開異方性を正しく反映します。 

完全に対称な正方形構成では、パリティ処理が重視されます。 正方形の 4 隅すべてにある点により、変換された空間内で均等な偶数分布と奇数分布が生成されます。 パリティ補正がなければカウントは 2 倍になりますが、実装された分割により整数グリッド プリイメージの正確なカウントが保証されます。
