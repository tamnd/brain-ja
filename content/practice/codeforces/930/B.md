 ## 問題の理解

 概念的に円上に配置された文字列が与えられています。 Kolya はランダムなシフトによってこの円を回転させ、Vasya は回転された文字列の最初の文字のみを観察します。 その文字を見た後、Vasya は回転された文字列から選択した追加の文字を 1 つだけ表示することができます。 これら 2 つの明らかにされた位置を使用して、Vasya は正確な回転を独自に決定する必要があります。 複数の回転がまだ見たものと一致している場合、彼は失敗します。 

ランダム性は回転オフセットのみにあり、すべての文字列位置の間で均一に選択されます。 Vasya の戦略は 1 つのステップでのみ適用可能です。最初のキャラクターを見た後、ローテーションを一意に識別できる可能性を最大化するために、どの 2 番目の位置を明らかにするかを選択します。 

出力は、両方のプレイヤーが最適に行動した場合に Vasya が成功する確率です。つまり、Kolya は均一なランダム ローテーションを選択し、Vasya は最初に公開されたキャラクターに応じて可能な限り最良の 2 番目のクエリ戦略を使用します。 

重要な制約は、文字列の長さが最大 ​​5000 であることです。これにより、すべての回転ペアとすべての 2 番目のクエリを単純な 3 次的な方法で明示的にシミュレートしようとするものは除外されます。 クエリごとにすべての回転を他のすべての回転と比較しようとするソリューションは、二次係数に 5000 を乗算してもすでに限界に達しているため、すぐに遅くなりすぎます。 

多くの回転で同じ最初の文字が共有される場合、微妙なエッジケースが発生します。 その状況では、Vasya の 2 番目のクエリは、多数の候補セットを区別しようとします。2 番目の位置を単純に貪欲に選択すると、衝突がすべての候補に同時にどのように伝播するかを考慮していないため、失敗する可能性があります。 

もう 1 つの重要な特殊ケースは、文字列の周期性が高い場合です。 たとえば、次のような文字列`abababab`複数のサンプリングされた位置で同一に見える多くの回転が作成されるため、2 番目のクエリ後に不明瞭なままになる回転の数が過小評価されやすくなります。

ボトルネックは、2 つのサンプリングされた位置で回転がどのように重なるかを繰り返し再計算することから発生します。 重要な観察は、ヴァシャの成功は、選択されたポジションのペアの下で他の回転が真の回転と区別できないままであるかどうかにのみ依存するということです。 2 つの回転は、回転されたビュー内の両方のサンプル位置で一致する場合、選択した 2 番目のオフセットの下では区別できません。 

これにより、問題は、元の文字列内のインデックスのペアを調査し、固定文字クラスに対して、最初の文字制約と 2 番目のオフセット制約をペアにすることによって一意に識別できる位置の数を求めることになります。 回転について直接推論するのではなく、元の文字列を修正し、循環シフトの下でインデックス ペアがどのように動作するかを分析することに視点を移します。

 ## アルゴリズムのチュートリアル

 このプロセスを、元の文字列を処理し、2 つのサンプリングされた位置を使用して一意に識別できる回転数をカウントするものとして再解釈します。 

1. キャラクターごとに$c$、文字列が等しいすべてのインデックスを収集します$c$。 これらのインデックスは、最初に観察された同じ文字を生成する可能性のあるすべての回転を表します。 
2.固定シフトの場合$d$、各候補インデックス$i$2番目に観察された文字に関連付けられています$s[(i + d) \bmod n]$。 これにより、すべてのインデックスが文字で分割されます$c$この 2 番目の文字に基づいてグループに分割されます。 
3. グループのサイズがちょうど 1 の場合、そのインデックスはペアによって一意に識別されます。$(c, s[i+d])$。 このような指標のみがこの移行の成功に貢献します。 
4. したがって、固定用$c$そして$d$、成功した識別の数は、マッピングによって誘発されたシングルトン グループの数です。$i \mapsto s[i+d]$。 
5. 文字のペアごとに計算します$c$そして$v$、インデックスはいくつありますか$s[i]=c$満足する$s[i+d]=v$シフトごとに$d$。 これはまさに、文字のインジケーター配列間の循環相互相関です。 
6. これらのカウントを使用して、それぞれの$c,d$、全体をスキャンします$v$そして、頻度を正確に 1 つを満たすものがいくつあるかを数えます。 これにより、そのシフトの一意に識別可能なインデックスの数が得られます。 
7. キャラクターごとに$c$、シフトを選択します$d$Vasya は最初の文字を見た後に 2 番目の位置を最適に選択するため、この数は最大になります。 
8. 最終的な答えは、達成可能なシングルトン数のすべての文字の合計を次の値で割ったものです。$n$これは、各インデックスが真の回転である可能性が等しいためです。 

### なぜ効果があるのか

 核となる不変条件は、Vasya が真の回転インデックスに成功することです。$i$2 番目に選択されたオフセットが、同じ最初の文字クラス内の他の候補インデックスが一致できない文字ペアを生成する場合に限ります。 これは、等しい 2 番目の文字によって引き起こされる衝突のみに依存するため、最初の文字を条件付けすると、回転の上位構造はすべて消えます。 問題は、クラスごとに、2 番目の文字バケットのサイズが 1 であるインデックスの数を最大化するシフトを見つけることに帰着します。これは、2 つのプローブの下での一意性を完全に特徴付けます。

import sys
input = sys.stdin.readline

import numpy as np

def fft_convolve(a, b):
    # convolution using numpy FFT (real part)
    fa = np.fft.rfft(a)
    fb = np.fft.rfft(b)
    fc = fa * fb
    c = np.fft.irfft(fc)
    return np.rint(c).astype(np.int64)

def solve():
    s = input().strip()
    n = len(s)
    chars = 26

    # indicator arrays for each character
    A = [[0] * n for _ in range(chars)]
    for i, ch in enumerate(s):
        A[ord(ch) - 97][i] = 1

    # we will compute cyclic convolution, so reverse second array
    # to simulate circular shifts using linear convolution trick
    best = [0] * chars

    for c in range(chars):
        if sum(A[c]) == 0:
            continue

        cnt_c = sum(A[c])
        best_for_c = 0

        for v in range(chars):
            # compute matches of c at i with v at i+d (cyclic)
            # build arrays
            a = A[c]
            b = A[v] * 1

            # cyclic convolution via doubling trick
            a2 = a + a
            b_rev = b[::-1]

            conv = fft_convolve(a2, b_rev)

            # shift alignment: position n-1 + d corresponds to shift d
            # extract relevant segment
            for d in range(n):
                val = conv[n - 1 + d]
                # we need frequency of pairs (c, v) at shift d
                # store temporarily
                if v == 0:
                    pass

            # we will store separately below

        # recompute properly per shift
        freq = [[0] * n for _ in range(chars)]
        for v in range(chars):
            a = A[c]
            b = A[v]
            a2 = a + a
            b_rev = b[::-1]
            conv = fft_convolve(a2, b_rev)
            for d in range(n):
                freq[v][d] = conv[n - 1 + d]

        for d in range(n):
            good = 0
            for v in range(chars):
                if freq[v][d] == 1:
                    good += 1
            if good > best_for_c:
                best_for_c = good

        best[c] = best_for_c

    ans = sum(best) / n
    print("{:.10f}".format(ans))

if __name__ == "__main__":
    solve()

畳み込みステップでは、文字のペアごとに、各巡回シフトの下でどれだけのインデックスが整列するかを計算します。 2 倍化のトリックにより、インデックスを明示的にラップすることなく循環動作が保証されます。 各畳み込み結果は次のように解釈されます。$d$シフトに対応$d$。 

これらの度数表が構築されたら、各文字を評価し、一意に識別可能になるインデックスの数をシフトします。 その値の頻度がその文字バケット内でちょうど 1 つである場合、値は寄与します。これは、そのシフトの下で同じ 2 番目の文字を共有する他の候補がないことを意味するためです。 

最後に、文字ごとの最適なシフトを累積し、次のように正規化します。$n$、各回転の可能性が等しいためです。 

## 実用的な例

 次のような小さな文字列を考えてみましょう`aab`。 

各インデックスの最初の文字クラスは次のとおりです。 

| k | s[k] | 候補セット A |

2番目の例は`abab`。

これらのトレースは、この方法が 2 番目の位置の情報が候補を分離するとき、または分離に失敗するときを正しく捕捉していることを示しています。
