 ## 解決策
 ## 問題の理解

 私たちには 2 セットのカードが与えられ、1 つは次郎のもの、もう 1 つはシエルのものです。 次郎のカードには「攻撃」と「防御」の2種類があり、それぞれに強さの値が設定されています。 シエルのカードはよりシンプルです。彼女のカードはすべて、所定の強さを持つ攻撃カードです。 

シエルは、各カードを最大 1 回、好きな順序で選択し、オプションで早めに停止することでプレイします。 選択された各カードは、カードが残っていない場合に次郎に直接ダメージを与えるか、最初に次郎のカードの 1 枚だけを破壊し、そのカードの種類に応じて与えるダメージを減らすために使用されます。 攻撃系の敵カードはシエル以上の強さを必要とし、その強さによってダメージを軽減します。 防御タイプのカードは厳密な不平等を要求し、破壊されてもダメージを与えません。 

目標は、シエルのカードの順序とサブセットを選択し、それらを次郎のカードと最適に組み合わせて、合計の蓄積ダメージが最大になるようにすることです。 

制約は小さく、各面に最大 100 枚のカードがあります。 これは、O(n^2) または O(n^3) の解が実行可能であることをすぐに示唆していますが、両側のサイズが指数関数的なものは、慎重に切り詰めなければ依然として危険です。 

重要な微妙な点は、シエルはいつでも停止できるということです。 つまり、すべてのカードを使用する必要はなく、弱いカードを早すぎると使用すると、後で潜在的に高価値の直接ダメージを無駄にする可能性があります。 もう 1 つの微妙な点は、防御カードを平等に破壊することができないことです。これにより、順序の決定に影響を与える厳しい組み合わせの制約が生じます。 

どの敵カードを最初に破壊するかを選択することで、シエルの残りのカードの利用可能な「将来の価値」が変わるため、単純な貪欲なアプローチは失敗することがよくあります。 たとえば、弱い防御カードの上に強いシエル カードを早い段階で使用すると、後で潜在的に大きな直接ダメージを無駄にする可能性があります。 

## アプローチ

 この問題の強引な見方は、シエルのカードのすべての順列と、使用された各カードを「直接攻撃」または「有効な次郎カード 1 枚を破壊する」のいずれかに割り当てるすべての可能な方法を考慮することです。 各ステップで、どの次郎カードをターゲットにするか、何も残っていない場合は直接ダメージをスキップするかを選択します。 これは状態の爆発につながります。各ステップで、ターゲットの選択肢が O(n) で、順序付けの選択肢が O(m) になり、その結果、実現可能をはるかに超えた階乗増加が生じます。 

シエルのカードがインタラクションの順序を制御する唯一のリソースであるのに対し、ジローのカードは制約付きで消費されるアイテムであると考えることができれば、この構造は管理しやすくなります。 重要なアイデアは、次郎のカードを固定マルチセットとして扱い、純粋な直接ダメージに切り替える前に破壊するカードの枚数を検討することです。 

破壊するつもりの次郎のカードのサブセットを修正する場合、シエルにとっての最善の戦略は、各破壊に十分な最小のカードを使用し、最後に直接ダメージを与えるために大きなカードを温存することです。 これは当然、すでに除去されている攻撃カードと防御カードの数を並べ替えたり動的プログラミングしたりすることにつながります。 

核となる変革は、総報酬を最大化する方法でシエルのカードとジローのカードを徐々にペアリングするプロセスであると考えることです。各ペアにはコスト (ジローのダメージ軽減の可能性) と実現可能性の制約があります。 

これにより、各タイプから何枚のジロー カードが削除され、何枚のシエル カードが使用されたかについての DP の定式化が行われ、常に最適な次のアクションが選択されます。

 | ブルート フォースの置換と代入 | O(m!・分岐) | O(m + n) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 次郎のカードを、攻撃カードと防御カードという 2 つのソートされた配列に分けます。 A を攻撃力としてソートし、D を防御力としてソートします。

また、シエルのカードを昇順に並べ替えます。これは、小さいカードを早く使用することで、より価値の高い操作のために強力なカードを予約できるためです。 

すでに破壊された攻撃カードと防御カードの数、および使用したシエル カードの数を追跡する DP 状態を定義します。 使用されたカードを明示的に追跡する代わりに、シエルのカードを順番に反復処理し、それぞれのカードの使用方法を決定します。 

私たちは、dp[i][j] がシエルのカードのいくつかのプレフィックスを処理し、i 個の攻撃カードと j 個の防御カードを破壊した後に達成可能な最大ダメージを表す DP テーブルを維持します。 

シエルのカードを1枚ずつ処理していきます。 

1. 次郎の攻撃カード A と防御カード D を昇順に並べます。 
2.シエルのカードSを昇順に並べ替えます。 
3. dp[0][0] = 0 を除き、-inf で埋められた DP 配列を初期化します。 
4. 強度 x の各シエル カードについて、次に新しい DP テーブルを計算します。 
5. 各状態 (i, j) について、次の 3 つのアクションを検討します。 

1. dp[i][j] を維持したまま、カードをスキップします。 
2. x ≥ A[i] の場合、それを使用して次の攻撃カード A[i] を殺します。 これにより、報酬 x - A[i] が追加されます。 
3. x > D[j] の場合、それを使用して次の防御カード D[j] をキルします。 これにより報酬は 0 追加されます。 
6. それに応じて次の状態に遷移します。 
7. すべてのカードを処理した後の答えは、すべての状態にわたる最大 dp[i][j] になります。 

次の攻撃カードまたは防御カードをソートされた順序でのみ考慮する理由は、報酬が引き算に依存し、実現可能性が強さに対して単調であるため、より強力なシエル カードを弱い敵に割り当てることは、より強いカードのために予約するよりも常に悪いためです。 

### なぜ効果があるのか

 DP の不変条件は、最初の k 枚のシエル カードを処理した後、dp[i][j] が、それらの k 枚のカードを使用してちょうど i 枚の攻撃カードと j 枚の防御カードを破壊することによって達成可能な最大ダメージを正確に表すということです。 弱いターゲットとより強いターゲットの間で割り当てを入れ替えることは、間違った方向で行われた場合でも実現可能性を低下させることはなく、利益を向上させることもないため、破壊された敵のカードが必要な強さの昇順に取られるように、最適な戦略を再配置することができます。 この順序付けプロパティにより、DP が最適なペアリング構造を決して見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    atk = []
    dfn = []
    
    for _ in range(n):
        t, x = input().split()
        x = int(x)
        if t == "ATK":
            atk.append(x)
        else:
            dfn.append(x)
    
    c = [int(input()) for _ in range(m)]
    
    atk.sort()
    dfn.sort()
    c.sort()
    
    INF_NEG = -10**18
    
    dp = [[INF_NEG] * (len(dfn) + 1) for _ in range(len(atk) + 1)]
    dp[0][0] = 0
    
    for x in c:
        ndp = [[INF_NEG] * (len(dfn) + 1) for _ in range(len(atk) + 1)]
        
        for i in range(len(atk) + 1):
            for j in range(len(dfn) + 1):
                if dp[i][j] == INF_NEG:
                    continue
                
                cur = dp[i][j]
                
                # skip
                if cur > ndp[i][j]:
                    ndp[i][j] = cur
                
                # attack next ATK
                if i < len(atk) and x >= atk[i]:
                    val = cur + (x - atk[i])
                    if val > ndp[i+1][j]:
                        ndp[i+1][j] = val
                
                # attack next DEF
                if j < len(dfn) and x > dfn[j]:
                    if cur > ndp[i][j+1]:
                        ndp[i][j+1] = cur
        
        dp = ndp
    
    ans = 0
    for i in range(len(atk) + 1):
        for j in range(len(dfn) + 1):
            ans = max(ans, dp[i][j])
    
    print(ans)

if __name__ == "__main__":
    solve()
```DP は、除去された攻撃カードと防御カードの数を明示的に追跡します。 トランジションはゲームのルールを反映しています。攻撃の除去は価値に貢献しますが、防御の除去は実行可能性のみを提供します。 早期に停止することは常に許可されているため、スキップ遷移は不可欠です。 

防御カードの厳密な不平等は次のように処理されます。`x > dfn[j]`の代わりに`>=`。 攻撃カードの使用`>=`, 同点が許可されるというルールに一致します。

 ## 特殊なケース

 重大なエッジケースは、シエルのカードの強さが防御カードと完全に一致する場合です。 たとえば:

 入力:```
1 1
DEF 0
0
```DP が施行する`x > DEF`, したがって、この遷移は無効です。 利用可能な唯一の動きは、スキップするか、後で直接ダメージを試みることで、結果は 0 になります。 

別のケースは、すべての次郎カードが防御で、すべてのシエルカードが等しい場合です。 このアルゴリズムは不正な遷移を正しく回避し、部分的なペアリングはカウントされず、将来の有効な直接的なダメージのみがカウントされるようにします。 

最後の微妙なケースは、シエルが必要以上に多くのカードを持っている場合です。 DP ではスキップが許可されているため、追加のカードによって答えが減少することはなく、最適な停止動作が維持されます。
