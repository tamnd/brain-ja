 ## 解決策
 ## 問題の理解

 2D 平面上を移動するロボットが目標点 (_a_、_b_) に到達できるかどうかを判断するように求められます。 ロボットは原点 (0, 0) から開始し、文字列にエンコードされた一連の動きに従います。 文字列の各文字は方向を表します。「U」はロボットを上に、「D」は下に、「L」は左に、「R」は右に移動します。 ロボットは文字列を書き終えると、それを無限に繰り返します。 問題は、この無限シーケンスのある時点で、ロボットがターゲット座標を正確に占有するかどうかです。 

入力は、-10^9 から 10^9 の範囲の整数 _a_ と _b_ 、および長さ 100 までの文字列です。ターゲットが非常に遠くにある可能性があるため、制約は文字列のすべての繰り返しに対して文字通りロボットの動きをシミュレートすることが不可能であることをすぐに示唆しています。 文字列を何度でも繰り返した後のロボットの位置を推論するソリューションが必要です。 

エッジケースとは、繰り返しの終わりに正確に、または繰り返しの間に正確にターゲットに到達できる場合です。 たとえば、文字列がロボットを右に 1 回移動し (「R」)、ターゲットが (3, 0) にある場合、3 回繰り返した後でのみ到達できます。 不注意なシミュレーションを 1 回繰り返した後に停止すると、誤って「No」が返されてしまいます。 

もう 1 つの微妙なエッジ ケースは、完全なシーケンス後のロボットの正味の動きがゼロになる場合に発生します。 たとえば、文字列が「UDLR」の場合、ロボットは完全に繰り返すたびに原点に戻ります。 この場合、到達可能なポイントは、最初の繰り返し中に訪問したポイントだけです。 正味の移動ベクトルのみを考慮する単純なアプローチでは、これらの到達可能な中間点を捉えることができません。 

## アプローチ

 ブルートフォースアプローチは簡単です。 ロボットの動きを無限にシミュレートし、各ステップの後に位置を更新し、それが (_a_, _b_) に等しくなるかどうかを確認します。 ブルートフォースは文字通りロボットのパスをたどるので、正しいです。 ただし、ロボットが遠くの目標に到達するには最大 10^9 のステップが必要になる可能性があり、これは明らかに実行不可能です。 可能な繰り返し回数ごとに 1 回の完全な繰り返しをシミュレートしても、文字列の長さが短い一方でターゲット座標は膨大になる可能性があるため、遅すぎます。 

重要な洞察は、ロボットの動きが周期的であることに気づくことです。 (_dx_, _dy_) を、文字列を 1 回完全に繰り返した後の位置の正味の変化とします。 文字列を _k_ 回繰り返した後のロボットの位置は、初期オフセットに正味変化の _k_ 倍を加えたものに、最初の繰り返しで到達した位置を加えたものになります。 形式的には、最初の繰り返しで _i_ が移動した後のロボットの位置を (_x_i_, _y_i_) で表すとすると、到達可能な位置は、負でない整数 _k_ の (_x_i + k_dx*, y_i + k_dy_) の形式になります。 

この観察により、問題は、最初の繰り返しで到達した各位置について、(_x_i + k_dx* = a* および _y_i + k_dy* = b*) となる非負の整数 _k_ が存在するかどうかをチェックすることになります。 これは、整数における単純な方程式を解く問題です。 _dx_ または _dy_ がゼロの場合は、ゼロ除算を避けるために特別な注意が必要です。 両方がゼロの場合は、最初の繰り返し中に到達した位置を確認するだけで済みます。

 ## アルゴリズムのチュートリアル

1. すべての文字を反復処理して、文字列を 1 回完全に繰り返した後の正味の動き (_dx_、_dy_) を計算します。 移動に応じて、X 座標または Y 座標を増減します。 これにより、繰り返しごとの全体的な翻訳ベクトルが得られます。 
2. ロボットの位置を (0, 0) に初期化し、最初の繰り返し中に訪れたすべての位置をリストに保存します。 これにより、繰り返しを開始する前に、考えられるすべてのオフセットを考慮することができます。 
3. 最初の繰り返しで到達した各位置 (_x_i_、_y_i_) について、次のような非負の整数 _k_ が存在するかどうかを確認します。 

_x_i + k_dx* = a* および _y_i + k_dy* = b*。 

_dx_ がゼロの場合、これは _x_i = a_ かどうかをチェックすることになり、それ以外の場合は k を (a - x_i) / dx として計算します。 _dy_ についても同様です。 
4. 有効な _k_ は 3 つの条件を満たさなければなりません。整数であること、負でないこと、x と y の式を同時に満たさなければなりません。 任意の位置にそのような _k_ が存在する場合は、「Yes」を出力します。 
5. すべての位置をチェックした後、有効な _k_ が見つからない場合は、「No」を出力します。 

機能する理由: このアルゴリズムは、到達可能な位置は最初の繰り返しからの位置に正味の平行移動ベクトルの倍数を加えたものとして表現できるという不変式に依存しています。 最初の繰り返しからすべてのオフセットを繰り返すことにより、任意の回数繰り返した後に到達できる可能性のあるすべての位置をカバーします。 整数と非負性のチェックにより、実行可能な繰り返しのみが考慮されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a, b = map(int, input().split())
s = input().strip()

dx, dy = 0, 0
path = [(0, 0)]
for move in s:
    if move == 'U':
        dy += 1
    elif move == 'D':
        dy -= 1
    elif move == 'R':
        dx += 1
    elif move == 'L':
        dx -= 1
    path.append((path[-1][0] + (dx - path[-1][0]), path[-1][1] + (dy - path[-1][1])))

for x_i, y_i in path:
    kx = ky = None
    if dx != 0:
        if (a - x_i) % dx != 0:
            continue
        kx = (a - x_i) // dx
    else:
        if x_i != a:
            continue
        kx = 0

    if dy != 0:
        if (b - y_i) % dy != 0:
            continue
        ky = (b - y_i) // dy
    else:
        if y_i != b:
            continue
        ky = 0

    if kx == ky or dx == 0 or dy == 0:
        if kx >= 0 and ky >= 0:
            print("Yes")
            break
else:
    print("No")
```まず、正味の平行移動ベクトルを計算します。 次に、最初の繰り返しで各移動後のすべてのポジションを追跡します。 整数 _k_ をチェックするときは、ゼロによる除算を避けるためにゼロ変換を慎重に処理します。 最後の条件では、_k_ が両方の軸にわたって一貫しており、負でないことが保証されます。 の`else`で`for`有効な _k_ が見つからない場合にのみループがトリガーされます。
