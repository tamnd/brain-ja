 ## 解決策
 ## 問題の理解

 私たちには近傍の固定ツリーが与えられています。 各道路は最初はギャングによって管理されています。 時間の経過とともに、道路の所有権は変わります。毎日、特定の道路が別のギャングに占有されます。つまり、その日からその道路を管理するギャングが変わります。 

固定のギャングと固定の日については、そのギャングが現在管理している道路のみに注目し、それらの道路によって形成される部分グラフを考慮します。 元の構造はツリーであるため、エッジのサブセットはフォレストを形成します。 その森の中では、ギャングは道を繰り返すことなく道に沿って移動でき、そのような可能な限り長いルートがギャングの不安レベルを定義します。 

重要な観察は、森の中では、端を繰り返さない歩行は単純な道と同等であるということです。 頂点を再度訪問する場合は、ツリー構造内のエッジを再利用する必要がありますが、これは繰り返しなしには不可能です。 したがって、問題は、時間の経過とともに各ギャングの森の直径を維持することに帰着します。 

入力は、各ツリー エッジのギャングへの初期割り当てと、それに続く一連のエッジ所有権の時間の経過に伴う変更で構成されます。 各クエリは、特定のギャングおよび特定の日について、そのギャングの現在のフォレストの直径 (エッジの数) はいくらか、と尋ねます。 

制約は大きく、最大 100,000 個のノード、ギャング、更新、およびクエリです。 これにより、クエリごとにコンポーネントまたは BFS/DFS を再計算することは即座に除外されます。クエリごとに線形であっても遅すぎるためです。 どのソリューションも更新を段階的に処理し、動的接続のオフラインまたは償却処理をサポートする必要があります。 

単純な間違いは、クエリごとに各ギャングのグラフを再構築し、BFS または DFS を使用して直径を計算することです。 たとえば、すべてのエッジが頻繁に同じグループに属する場合、直径を 100,000 回再計算すると、およそ 10^10 の演算が必要になります。 

もう 1 つの微妙な問題は、グローバル マージを考慮せずに直径をローカルで追跡できると仮定していることです。 時間の経過とともにエッジが追加されると、端点を延長するだけでなく、コンポーネントが結合し、直径が大きく変化します。 

## アプローチ

 ブルート フォース アプローチでは、各クエリが個別に処理されます。 固定のギャングと時間に対して、その瞬間にそのギャングが所有するエッジのセットを再構築し、隣接リストを構築し、コンポーネントごとに 2 つの BFS 実行を使用して各接続コンポーネントの直径を計算します。 これは正しいですが、高価です。 各クエリは O(N) エッジに触れる可能性があり、Q 個のクエリがあり、O(NQ) が得られますが、これは制限をはるかに超えています。 

重要な構造的観察は、時間の経過に伴う各ギャングのグラフが動的なフォレストであるということです。 時間の経過とともにエッジの挿入と削除を行うだけであり、特定のタイムスタンプでオフライン クエリに応答する必要があります。 これは、ロールバック共用体検索構造と組み合わせた、長期にわたるセグメント ツリーの古典的な設定です。 

ただし、必要なのは接続性だけではありません。 直径が必要です。 ツリー メトリック内のフォレストの場合、各コンポーネントの最も遠い 2 つのノードを保存すると、コンポーネントごとの直径を維持できます。 2 つのコンポーネントが結合すると、新しい直径は古い直径と 2 つのコンポーネントの直径の端点間の距離の最大値になります。 基礎となるグラフはツリーであるため、LCA を使用して距離を計算できます。 

したがって、各エッジの所有権をギャングごとの時間間隔に分解します。 各ギャングについて、そのエッジを特定の時間範囲にわたってアクティブであるものとして扱い、それらのエッジを時間の経過とともにセグメント ツリーに挿入します。 各セグメント ツリー ノードは、ロールバック付きの DSU を使用して、その間隔でアクティブなエッジのバッチを処理し、その時間範囲に該当するすべてのクエリに応答します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとの再構築 + BFS | O(Q・N) | O(N) | 遅すぎる |
 | 経時的なセグメント ツリー + 直径追跡によるロールバック DSU | O((N + T) log T α(N)) | O(N log T) | 承認済み |

 ## アルゴリズムのチュートリアル

まず、元のツリーのルートを固定し、バイナリ リフティングを使用して最小共通祖先とすべてのノード間の距離を前処理します。 これにより、後で一定時間の距離クエリが可能になります。これは、コンポーネントを結合するときに不可欠です。 

次に、各エッジのタイムラインをギャングごとの間隔に変換します。 最初は、すべてのエッジは 0 日目から 1 つのギャングに属します。征服イベントごとにエッジが 1 つのギャングから別のギャングに移動し、その所有権が複数のセグメントに分割されます。 各セグメントは、そのギャングがエッジを所有する区間になります。 

各ギャングに対して個別に、1 から T までの時間範囲にわたるセグメント ツリーを構築します。 

次に、次のように進めます。 

1. ギャングに属するすべてのエッジ間隔について、そのアクティブな時間間隔を完全にカバーするすべてのセグメント ツリー ノードにそのエッジを挿入します。 これにより、各ノードがその時間セグメント中に同時にアクティブになるエッジのセットを表すことが保証されます。 
2. セグメント ツリー上で DFS を実行します。 各ノードで、そのノードに保存されているすべてのエッジをロールバックして DSU に適用します。 各 DSU コンポーネントは、サイズだけでなく、現在の直径を定義する 2 つの代表的なエンドポイントも保存します。 
3. 2 つのコンポーネントを結合する場合、結合後の最適な直径を計算します。 最初のコンポーネントの前の直径、2 番目のコンポーネントの前の直径、および両方のコンポーネントの端点によって形成されるすべてのクロスペアの 3 つの候補を検討します。 交差距離は、元のツリーの LCA 距離を使用して計算されます。 
4. 葉セグメント ツリー ノードにいる場合、これは 1 つの時点に対応します。 クエリされたギャングの保存されたコンポーネント情報を検索し、そのコンポーネント フォレストの直径を返すことによって、その時点のすべてのクエリに答えます。 
5. セグメント ツリー ノードの終了後、親に戻る前に、そのノードで実行されたすべての DSU 操作をロールバックします。 これにより、各セグメントが独立した状態に保たれます。 

ロールバックが必要な重要な理由は、各エッジ間隔が重複する時間セグメント間で共有され、無関係な時間ブランチ間で持続的な干渉が発生しないようにする必要があるためです。 

### なぜ効果があるのか

 どのセグメント ツリー ノードでも、DSU にはその時間間隔でアクティブなエッジが正確に含まれます。 操作の適用とロールバックは厳密にセグメント境界内で行われるため、DSU の状態は処理中のセグメントと常に一致します。 すべての接続コンポーネントは常に実際のエッジのセットで表され、すべてのマージはツリー メトリックの下で真の最長パスを保持する方法でエンドポイントを更新するため、直径の維持は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

LOG = 17

class DSU:
    def __init__(self, n, depth, up):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)
        self.best_a = list(range(n + 1))
        self.best_b = list(range(n + 1))
        self.depth = depth
        self.up = up
        self.history = []

    def find(self, x):
        while self.parent[x] != x:
            x = self.parent[x]
        return x

    def dist(self, a, b):
        l = self.lca(a, b)
        return self.depth[a] + self.depth[b] - 2 * self.depth[l]

    def lca(self, a, b):
        if self.depth[a] < self.depth[b]:
            a, b = b, a
        diff = self.depth[a] - self.depth[b]
        for i in range(LOG):
            if diff & (1 << i):
                a = self.up[i][a]
        if a == b:
            return a
        for i in reversed(range(LOG)):
            if self.up[i][a] != self.up[i][b]:
                a = self.up[i][a]
                b = self.up[i][b]
        return self.up[0][a]

    def snapshot(self):
        return len(self.history)

    def rollback(self, snap):
        while len(self.history) > snap:
            typ, x, val = self.history.pop()
            if typ == 0:
                self.parent[x] = val
            elif typ == 1:
                self.size[x] = val
            elif typ == 2:
                self.best_a[x] = val
            else:
                self.best_b[x] = val

    def union(self, a, b):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            return

        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra

        snap_vals = []

        snap_vals.append((0, rb, self.parent[rb]))
        self.parent[rb] = ra

        snap_vals.append((1, ra, self.size[ra]))
        self.size[ra] += self.size[rb]

        candidates = [
            (self.best_a[ra], self.best_a[rb]),
            (self.best_a[ra], self.best_b[rb]),
            (self.best_b[ra], self.best_a[rb]),
            (self.best_b[ra], self.best_b[rb]),
        ]

        best_pair = (self.best_a[ra], self.best_b[ra])
        best_len = self.dist(*best_pair)

        for u, v in candidates:
            d = self.dist(u, v)
            if d > best_len:
                best_len = d
                best_pair = (u, v)

        snap_vals.append((2, ra, self.best_a[ra]))
        snap_vals.append((3, ra, self.best_b[ra]))

        self.best_a[ra], self.best_b[ra] = best_pair

        for item in snap_vals:
            self.history.append(item)

```DSU は、接続性だけでなく、各コンポーネント内の直径エンドポイントも維持するように設計されています。 各ユニオン操作では、すべてのエンドポイントの組み合わせが試行され、ツリー距離メトリックに基づいて直径が正しく更新されることが確認されます。 

LCA 構造は一定時間距離クエリをサポートします。これは、すべてのマージで複数のエンドポイント ペアをテストする可能性があるため、不可欠です。 

完全な実装では、欠落しているセグメント ツリー層が時間間隔をかけてエッジ アクティベーションを適用し、呼び出します。`union`関連するセグメント内のみで、常にスナップショットの正確性が保証されます。 

## 実用的な例

 エッジが時間の経過とともに所有権を変更する小さなツリーを考えてみましょう。 特定の時点で、ギャングが 2 つのコンポーネント (長さ 2 のチェーンと長さ 3 のもう 1 つのチェーン) を形成するエッジを所有しているとします。 

DSU がコンポーネントの直径をどのように保存するかを追跡します。 

| ステップ | アクション | コンポーネントの状態 | 直径 |
 | --- | --- | --- | --- |
 | 1 | 最初のエッジを追加 | {1-2} | 1 |
 | 2 | 2 番目のエッジを追加 | {1-2-3} | 2 |
 | 3 | 素のチェーンをマージ | {1-2-3、5-6-7-8} | 最大(2,3, クロス) = 3 |

 これは、線形成長を仮定するのではなく、直径が常にエンドポイントから再計算されることを示しています。 

2 番目の例には、時間の経過とともに繰り返し再割り当てされる単一のエッジが含まれます。 DSU は、削除がロールバックによって処理されることを示しているため、コンポーネントは適切なタイミングできれいに消えます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((N + T + Q) log T α(N)) | 各エッジ間隔は O(log T) ノードで処理され、各結合はほぼ一定です。 
| スペース | O(N log T) | セグメント ツリーには、エッジ間隔と DSU ロールバック履歴が保存されます。 

各操作が対数的に分散され、DSU 操作がほぼ一定に償却されるため、複雑さは 100,000 操作の制限内に問題なく収まります。

 ## 特殊なケース

 主なエッジケースは、ギャングがある時点ですべてのエッジを失った場合です。 DSU は、そのグループにアクティブなコンポーネントがない状態に完全にロールバックする必要があり、クエリはゼロを返す必要があります。 エッジが含まれなくなったセグメント ツリー ノードはそのギャングの DSU を空のままにするため、これは自然に処理されます。 

別のエッジ ケースは、グループのエッジが複数の切断されたコンポーネントを形成し、後で新たに征服されたエッジを介してマージされる場合に発生します。 直径の更新ではクロスエンドポイントを考慮する必要があります。そうでないと、実際の最長パスが過小評価されてしまいます。 候補エンドポイントの比較により、明らかでないペアも確実にチェックされます。 

最後の微妙なケースは、同じエッジの再割り当てが複数回繰り返されることです。 間隔分解により、各所有権セグメントが互いに素であることが保証されるため、DSU は同じ時間範囲内のエッジを二重にカウントすることはありません。
