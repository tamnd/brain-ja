 ## 解決策
 ## 問題の理解

 一連のゲームにわたって 2 つの一連の処理時間が与えられています。 アリスが常に最初に動き、次にボブが同じ順序で同じゲームのシーケンスに従います。 各ゲームについて、アリスはある程度の時間をゲームに費やし、ボブは自分の時間をゲームに費やします。 

重要な問題は、どのゲームでもボブがアリスと重なることが許されないことです。 アリスがまだゲームをプレイしている間にボブがゲームに到達した場合、ボブはアリスがそのゲームを終了するまで前のプラットフォームで待機しなければなりません。 アリスが最初にスタートし決して追い越されることはないため、アリスがまだゲーム内にいるときは常に、各ゲームのボブの開始時間が事実上前倒しされます。 

ゲームのクエリ間隔については、そのサブ配列のみを考慮し、そのサブトラックから開始する両方のプレイヤーをシミュレートします。 ボブがアリスと比べてどのくらい遅れてインターバルを終了するかを計算する必要があります。 

入力制約は大きく、最大 200,000 ゲームと 200,000 クエリがあります。 各クエリを単純に線形時間でシミュレートするソリューションでは、最悪の場合、最大 400 億回の操作が必要になりますが、これは許容範囲をはるかに超えています。 これにより、セグメントに対するクエリごとのシミュレーションが即座に除外されます。 

微妙な問題は、ボブの待機動作が、アリスとボブのプレフィックス合計間の実行中の相互作用に依存することです。 この依存関係により、ゲームごとに変化する動的オフセットが作成され、そのオフセットは多くのサブ配列に対して効率的に計算される必要があります。 

単純な間違いは、答えが区間におけるボブとアリスの合計の差であると仮定することです。 たとえば、ボブの合計時間が大きい場合、答えは合計の差であると考えるかもしれません。 ボブの合計作業量が少なくても待機が蓄積される可能性があるため、これは失敗します。 小さな例でこれを説明します。 

アリス回だったら`[5, 1]`そしてボブの時間は`[1, 5]`、両方の合計は等しいですが、ボブは最初のゲームでブロックされたため、依然として遅く終了します。 

もう 1 つのよくある間違った考え方は、アリスが累積時間で厳密に進んでいる「ブロック イベント」のみをシミュレートすることです。 これは依然としてクエリごとに線形であり、スケールすることはできません。 

中心的な課題は、相互作用がプレフィックス合計の差の実行最大値のように動作することです。これは、事前に計算してマージできる構造を示唆しています。 

## アプローチ

 ブルートフォース手法では、クエリごとにボブの動きをシミュレートします。 インターバル中に 2 つのポインタを維持し、アリスとボブが各ゲームをいつ終了するかを追跡し、ボブがゲームに早く到着するたびに明示的に待機を強制します。 クエリごとに、このシミュレーションのコストは O(r - l + 1) です。 長い間隔で最大 2e5 個のクエリを実行すると、最悪の場合、O(nq) 回の操作が発生することになりますが、これは完全に実行不可能です。 

重要な洞察は、プレフィックスの違いという観点から対話を再構築することです。 アリスとボブの進歩の実質的な違いを定義してみましょう。 各ゲーム i で、アリスとボブはこの差に異なる貢献をしますが、ボブの待機は、インターバル中にボブに対してアリスが蓄積した最大赤字によって正確に決まります。 

アリスとボブのプレフィックス合計を定義すると、セグメント内の待機動作は、変換されたプレフィックス差分関数の最大値に依存します。 これは、段階的にシミュレーションするのではなく、各セグメントを少数の集計値のセットによって要約できることを意味します。 

重要な観察は、セグメントが 3 つの値、つまり合計差分、最大プレフィックス超過、および最小プレフィックス超過 (または同等に、ボブがどの程度遅れるか遅延するかを示すオフセットのペア) で表現できることです。 これらの概要は、セグメント ツリー形式でマージできます。 各ノードは、部分セグメントが受信「ラグ」を出力ラグおよび累積遅延にどのように変換するかをエンコードします。 

これにより、問題は、各ノードが関数合成のように動作するセグメント ツリー上の範囲クエリに応答するように変換されます。つまり、初期遅延が与えられると、最終遅延が生成されます。 構造は結合的であるため、セグメントを効率的に結合し、対数時間で各クエリに答えることができます。

 ## アルゴリズムのチュートリアル

 各セグメントを、アリスに対するボブの遅延の変換としてモデル化します。 

1. ゲームごとに、アリスとボブの貢献を表すペアを定義し、それらの差を相対的な進行における局所的なドリフトとして解釈します。 
2. セグメントについて、そのセグメント内の合計ドリフト、最大プレフィックス ドリフト、および最小プレフィックス ドリフトの 3 つの量を計算します。 
3. 各ノードがその間隔のこれら 3 つの値を保存するセグメント ツリーを構築します。 
4. 左右に隣接する 2 つのセグメント間のマージ操作を定義します。 

結合する場合、合計ドリフトは加算されますが、右側のセグメントのプレフィックスの極値は、左側のセグメントの合計ドリフト分だけシフトする必要があります。 
5. クエリの場合、[l, r] を表すマージされたセグメントを取得します。 
6. セグメントの概要を最終的な答えに変換します。ボブが蓄積する最大遅延は、セグメント内の最大プレフィックス ドリフトに対応します。 
7. この最大値をクエリの回答として出力します。 

重要な技術的ステップは、マージがどのように機能するかです。 左側のセグメントにより、すでにボブがある程度遅れをとっていると仮定します。 正しいセグメントに入るとき、そのすべてのプレフィックスの違いは事実上、その量だけシフトされます。 このため、結合する前に、プレフィックスの最大値と最小値を左セグメントの合計ドリフトによって調整する必要があります。 

### なぜ効果があるのか

どの時点でも、アリスに対するボブの遅延は、セグメントの処理された部分にわたるプレフィックス差分関数の最大値となります。 セグメント ツリーには、この関数を連結して再構築するために必要な情報が正確に格納されます。 プレフィックスの極値は蓄積されたドリフトに応じて線形にシフトするため、マージではすべての考えられる遅延の正しいエンベロープが保存されます。 これにより、セグメントを要約統計に圧縮するときに隠れた遅延パターンが失われないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("sum", "mx", "mn")
    def __init__(self, s=0, mx=0, mn=0):
        self.sum = s
        self.mx = mx
        self.mn = mn

def merge(left, right):
    res = Node()
    res.sum = left.sum + right.sum
    res.mx = max(left.mx, left.sum + right.mx)
    res.mn = min(left.mn, left.sum + right.mn)
    return res

class SegTree:
    def __init__(self, arr):
        n = len(arr)
        self.n = n
        self.size = 1
        while self.size < n:
            self.size *= 2
        self.data = [Node() for _ in range(2 * self.size)]

        for i in range(n):
            val = arr[i]
            self.data[self.size + i] = Node(val, max(0, val), min(0, val))

        for i in range(self.size - 1, 0, -1):
            self.data[i] = merge(self.data[2*i], self.data[2*i+1])

    def query(self, l, r):
        l += self.size
        r += self.size
        left_res = Node(0, 0, 0)
        right_res = Node(0, 0, 0)

        while l <= r:
            if l % 2 == 1:
                left_res = merge(left_res, self.data[l])
                l += 1
            if r % 2 == 0:
                right_res = merge(self.data[r], right_res)
                r -= 1
            l //= 2
            r //= 2

        return merge(left_res, right_res)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    arr = [a[i] - b[i] for i in range(n)]

    st = SegTree(arr)

    q = int(input())
    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        node = st.query(l, r)
        out.append(str(node.mx))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```実装では各ゲームを単一の値に圧縮します。`a[i] - b[i]`、そのステップでアリスがボブに対してどれだけ進んでいるかを表します。 正の値はアリスが先に進むことを意味し、負の値はボブが追いつくことを意味します。 

セグメント ツリー ノードには、合計ドリフト、最大プレフィックス ドリフト、および最小プレフィックス ドリフトが格納されます。 マージ操作では、左側の子の累積ドリフト分だけ右側の子の接頭辞の極値を慎重にシフトし、連結全体で正確さを維持します。 

各クエリは、間隔中の最大プレフィックス ドリフトを取得します。これは、アリスに対するボブの待機時間の最大値に相当し、まさに必要な終了ギャップとなります。 

一般的な微妙な点は、リーフ ノードの初期化です。空のプレフィックスはゼロ遅延ベースラインに寄与するため、各要素をプレフィックスの最大値が 0 または符号に応じた値自体のいずれかになる小さなセグメントとして扱います。 

## 実用的な例

 小さな派生例を考えてみましょう。 

アリス:`[3, 1, 2]`ボブ：`[2, 2, 1]`したがって、違いは次のとおりです。`[1, -1, 1]`クエリを処理します`[1, 3]`。 

| ステップ | セグメント | 合計 | MX | ん |
 | --- | --- | --- | --- | --- |
 | 1 | [1] | 1 | 1 | 0 |
 | 2 | [1,-1] | 0 | 1 | -1 |
 | 3 | [1,-1,1] | 1 | 1 | -1 |

 最終的な最大プレフィックス ドリフトは 1 です。これは、ボブがアリスの後に 1 ユニットを終了することを意味します。 

これは、合計が近い場合でも、中間の不均衡が答えを決定することを示しています。 

次に、完全に否定的なケースを考えてみましょう。 

アリス:`[1, 1]`ボブ：`[3, 3]`違い:`[-2, -2]`| ステップ | セグメント | 合計 | MX | ん |
 | --- | --- | --- | --- | --- |
 | 1 | [-2] | -2 | 0 | -2 |
 | 2 | [-2、-2] | -4 | 0 | -2 |

 最大プレフィックス ドリフトは 0 です。これは、ボブがアリスよりも良い意味で遅れることがないことを意味します。これは直感と一致します。ボブは常に遅いですが、強制的に待たされることはありません。

 ## 特殊なケース

 単一要素間隔は、答えがアリスとボブの時間の差だけである最も単純なシナリオです。 リーフ ノードのプレフィックス最大値はその値またはゼロ ベースラインから直接初期化されるため、セグメント ツリーはこれを自然に処理します。 

アリスとボブの時間が同一である間隔では、すべての差はゼロであるため、すべてのノードの sum、mx、および mn はゼロに等しくなります。 マージではゼロが保持され、すべてのクエリは遅延ゼロを返します。これは、どちらのプレイヤーも追い越したり待機したりしないという事実と一致します。 

次のような高度に交互に変化する値の場合、`[10, -10, 10, -10]`、正しい答えは、プレフィックス最大値がセグメント境界を越えてどのように蓄積されるかによって異なります。 マージ操作により、左側のセグメントの強い正のプレフィックスが右側のセグメントを正しくシフトすることが保証され、単純な合計ベースのアプローチでは失われる中間ピークの過小カウントが防止されます。
