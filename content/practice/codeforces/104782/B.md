 ## 解決策
 ## 問題の理解

 各セルが整数の高さを持つ長方形のグリッドが与えられます。 このグリッドを地形図と考えてください。 多くの人が指定されたセルから開始し、4 つの基本的な方向に 1 秒あたり 1 歩ずつ移動することも、静止することも選択できます。 

高さ 0 から始まり、時間の経過とともに上昇する溶岩があります。 溶岩のレベルが人が現在立っているセルの高さを超えた場合、その人は被害を受けたとみなされます。 溶岩が上昇している間、人々は移動することが許可されているため、溶岩が追い越す前に高い場所に到達しようとすることができます。 

1 から n·m までのターゲット溶岩レベル L ごとに、誰も傷つけずに溶岩をレベル L まで上げることができるように、溶岩を上げ始めるまでの最小待ち時間を知りたいと考えています。 与えられた L でそれが不可能な場合、答えは -1 になります。 

重要な問題は、人々は静的な障害物ではないということです。 彼らは時間の経過とともに位置を変えることができるため、安全条件は移動速度と地形の高さの相互作用によって決まります。 

n、m が 700 までという制約は、最大 490,000 個のセルを意味します。 完全なグリッドベースのクエリごとの最短パスの計算は非常に遅すぎます。 また、最大 10,000 人が参加するため、どのソリューションでも、1 人ごと、レベルごとのシミュレーションを回避する必要があります。 

上位のセルに囲まれた非常に低いセルから開始すると、微妙なエッジ ケースが発生します。 近くに高いセルが存在しても、そこに到達するのに時間がかかる場合は、十分に待たないと低い溶岩レベルに到達できない可能性があります。 

もう 1 つのエッジケースは、全員が非常に高い地形からスタートする場合です。 その場合、大きな溶岩レベルでもすぐに実行可能となり、多くの L 値の待ち時間がゼロになる可能性があります。 

## アプローチ

 この問題を直接考える方法は、溶岩レベル L を固定し、t 秒待ってから溶岩の上昇を開始した場合にすべての人々が生き残れるかどうかをシミュレーションすることです。 t が固定されている場合、到着時に現在の溶岩レベルを下回る高さのセルに人が決して入らないようにしながら、移動をシミュレートできます。 これは、L ごとおよび t ごとの時間拡張 BFS 問題になり、明らかに実行不可能です。 

重要な単純化は、視点を反転することです。 「安全にレベル L に到達するまでにどれくらいの時間がかかるか」を尋ねる代わりに、「各セルについて、少なくとも 1 人がレベル L に到達するまでにどれくらいの時間がかかるか」を尋ねます。 セルの高さが h の場合、時刻 t より遅くそのセルに到達するということは、時刻 t に溶岩が h を超えると安全ではなくなることを意味します。 したがって、問題は、ソースがすべて人であり、エッジが単位コストでのグリッドの移動を表す、マルチソースの最短経路問題になります。 

人が各セルに到達するまでの最小到着時間 dist[i][j] を計算します。 これを取得したら、特定の溶岩レベル L の安全条件を再解釈します。溶岩が L に達すると、そのセルは水没するため、高さが L より低い場合、セルは危険です。 時刻 t において、その高さが少なくとも現在の溶岩レベル以上のセル内に常にいる場合、その人は安全です。これは、時刻 t において必要なセルが安全でなくなる前に確実に到達できることを意味します。 

重要な観察は、L が固定されている場合、制限要因は、すべての人々が高地から脱出できる前に、高さ < L のセルが「ブロック」される最も早い時間であるということです。 これは、高さによってソートされ、到着時間によって制限されるグリッドにわたるグローバルなしきい値問題に変わります。 

セルを高さの昇順に処理します。 しきい値 L の場合、時間 t = dist[i][j] 以降、高さ < L のすべてのセルが禁止されているとみなされます。 安全性を保証する最も早い時間 t は、高さ < L のすべてのセルの最も早い到達時間の最大値です。 必要なエスケープ条件が失敗した場合、答えは -1 になります。 

これにより、高さによってソートされたセル全体にわたってプレフィックスの最大値を維持するという問題が軽減されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | L ごとのブルート フォース シミュレーション | O(n m K) 以上 | O(nm) | 遅すぎる |
 | マルチソース BFS + プレフィックス処理 | O(n m log(n m)) または O(n m + K) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッド上の K 人全員から同時にマルチソース BFS を実行します。 

各移動には 1 秒かかるため、これにより、人が各セルに到達するまでの最小時間 dist[i][j] が計算されます。 すべてのエッジの重みが同じであり、BFS は距離の増加順に拡張するため、これは正しいです。 
2. すべてのセルをトリプル (高さ、距離、位置) として保存します。 

私たちは、溶岩レベルが増加するにつれてグリッドがどのように安全でなくなるかを推論したいと思います。これは高さの順序のみに依存します。 
3. すべてのセルを高さの昇順に並べ替えます。 

これにより、しきい値 L を考慮すると、安全でなくなるすべてのセルがこの順序で連続することが保証されます。 
4. 高さ < L のすべてのセル間の最大距離を表す配列 best[L] を構築します。 

ソートされたセルをスイープし、現在の最大値の dist 値を維持します。 
5. 1 から n·m までの溶岩レベル L ごとに、best[L] を出力します。 

この値は、レベル L によって水没するすべてのセルの中での最悪の場合の「脱出期限」を表します。 
6. best[L] が未定義であるか、到達不可能な構成 (無限大として表すことができる) に対応する場合、出力 -1。 

### なぜ効果があるのか

 BFS は、人が各セルを占有することができる最も早い時間を計算します。 セルが溶岩レベル L で水没した場合、BFS 到着時間以降に人がそのセル内にいることを必要とする構成は、安全に満たすことができなくなります。 溶岩レベルは単調に増加するため、安全でないセルのセットは L とともに単調に増加します。したがって、各 L についての制限制約は、そのしきい値で安全でなくなるすべてのセルの最大 BFS 到着時間となります。 この最大値は、より長く待機することで実行可能な避難スケジュールが可能になるかどうかを完全に特徴づけます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m, k = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    dist = [[10**18] * m for _ in range(n)]
    q = deque()

    for _ in range(k):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        if dist[x][y] == 10**18:
            dist[x][y] = 0
            q.append((x, y))

    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    while q:
        x, y = q.popleft()
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                if dist[nx][ny] > dist[x][y] + 1:
                    dist[nx][ny] = dist[x][y] + 1
                    q.append((nx, ny))

    cells = []
    for i in range(n):
        for j in range(m):
            cells.append((a[i][j], dist[i][j]))

    cells.sort()

    res = [0] * (n * m + 1)
    cur = 0
    best = 0

    idx = 0
    for L in range(1, n * m + 1):
        while idx < len(cells) and cells[idx][0] < L:
            best = max(best, cells[idx][1])
            idx += 1
        res[L] = best

    print(" ".join(str(res[i]) for i in range(1, n * m + 1)))

if __name__ == "__main__":
    solve()
```最初のステージでは、標準の BFS を使用して、すべての開始者からの最短距離を計算します。 動きは均一であり、溶岩のレベルに依存しないため、これは不可欠です。 

第 2 段階では、溶岩のしきい値がこのリストの接頭辞に対応するように、グリッドを高さでソートされたリストに平坦化します。 

L 上のスイープにより、水没するセル間の実行最大距離が維持されます。 これにより、潜在的にクエリごとの 2 次計算が、並べ替え後の単一の線形スキャンに変換されます。 

初期化には注意が必要です。到達不能なセルは実質的に無限の距離にあり、しきい値よりも下にある場合は、応答が大きくなるように強制されます。 大きなセンチネルを使用すると、正確さが保証されます。 

## 実用的な例

 高さが徐々に高くなり、1 人が中央から開始する小さなグリッドを考えてみましょう。 

入力：```
2 2 1
1 2
3 4
1 1
```距離を計算します。 

| セル | 高さ | 距離 |
 | --- | --- | --- |
 | (1,1) | 1 | 0 |
 | (1,2) | 2 | 1 |
 | (2,1) | 3 | 1 |
 | (2,2) | 4 | 2 |

 次に、L をスイープします。 

| Ｌ | 高さ < L | のセル 最大距離 |
 | --- | --- | --- |
 | 1 | なし | 0 |
 | 2 | (1,1) | 0 |
 | 3 | (1,1),(1,2) | 1 |
 | 4 | (1,1)、(1,2)、(2,1) | 1 |

 これは、高さの低い領域が含まれる場合にのみ、答えがどのように増加するかを示しています。 

次に、人が低いポケットに孤立している場合を考えてみましょう。 

入力:```
3 3 1
10 10 10
10 1 10
10 10 10
2 2
```中心の高さは 1、距離は 0 ですが、周囲のセルはすべて高くなっています。 L = 2 の場合、中心のみが水没セットとなり、答えは 0 になります。L が大きい場合、より多くのセルが含まれますが、距離は小さいままであり、制約された地形でも BFS が局所的な到達可能性を捉えていることがわかります。

 ## 特殊なケース

 すべてのユーザーが同じセルから開始する場合、重要なエッジ ケースが発生します。 その場合、BFS はそのセルに距離 0 を割り当て、外側に拡張します。 遠く離れたセルには大きな距離がある可能性がありますが、それらの高さが大きな L のプレフィックスに含まれている場合にのみ問題になります。ソートされた高さのスイープでは、必要な場合にのみこれらの大きな距離が累積されるため、アルゴリズムは引き続き機能します。 

もう 1 つのエッジ ケースは、切断された低域が複数ある場合です。 移動はグリッドの隣接性によって制限されるため、BFS は他のコンポーネントのセルに大きな距離を正しく割り当てます。 これらのセルがプレフィックスの一部になると、それらの大きな距離により、対応する L 値の答えが正しく増加します。 

最後のエッジケースは、一部のセルにすべての人がアクセスできない場合です。 これらは無限の距離にあります。 このようなセルがプレフィックスに入ると、それらは最大値を支配し、より高い L 値に対して非常に大きな答えを生成します。これは、それらの溶岩レベルを安全に処理することが不可能であることを正しく反映しています。
