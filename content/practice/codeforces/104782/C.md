 ## 問題の理解

 2 種類のバスケットボールの投球のみを使用して目標スコアを作成するように求められます。1 つのタイプは 2 ポイントを追加し、もう 1 つのタイプは 3 ポイントを追加します。 整数を与える`n`、正確に形成できるかどうかを判断する必要があります。`n`これらの投げを組み合わせてポイントを獲得します。 可能であれば、使用されるスローの総数も最小限に抑える必要があります。 すべての有効な組み合わせのうち、2 点投げが何回使用され、3 点投げが何回使用されたかを出力する必要があります。 

入力は単一の整数です`n`、到達したい正確なスコアを表します。 出力はペアのいずれかです`(a, b)`意味`a`2点を投げて、`b`3ポイントを投げると正確に達成する`n`、この組み合わせでは、可能な限り最小の総スロー数、または文字列が使用されます。`No`そのような組み合わせが存在しない場合。 

制約`n ≤ 10^9`考えられるすべてのスロー数を素朴な方法で反復しようとするソリューションは直ちに除外されます。 2 ポイントスローと 3 ポイントスローの可能性のあるカウントをダブルループしても、可能性の数は直線的に増加するため、最悪の場合には遅すぎるでしょう。`n`。 

の値が小さい場合、微妙なエッジケースが発生します。`n`正確に形成することはできません。 例えば、`n = 1`明らかに次のように表すことはできません`2a + 3b`したがって、正しい出力は次のようになります。`No`。 同様に、`n = 2`として動作します`(1, 0)`、 そして`n = 3`として`(0, 1)`。 もう 1 つの明白ではない問題は、「できるだけ多くの 3 ポインターを使用する」などの貪欲な選択では、最小数のスローを提供できなかったり、有効な表現が存在する場合でもターゲットに到達できなかったりする可能性があることです。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアが試行されます`(a, b)`そのような`2a + 3b = n`。 考えられるそれぞれの値について、`a`から`0`に`n // 2`かどうかを確認します。`(n - 2a)`で割り切れます`3`。 そうであれば、計算します`b = (n - 2a) / 3`最小限でソリューションを追跡します`a + b`。 

これは、有効な分解をすべて明示的に列挙するため、正しいです。 ただし、最大で反復する必要があります`O(n)`の値`a`、そしてそれぞれに対して私たちは一定の作業を行います。 と`n`まで`10^9`、これは完全に不可能になります。 

重要な観察は、各 3 点投球が 2 点投球よりも操作ごとに多くのポイントを与えるため、投球数を最小限に抑えることは 3 点投球の数を最大化することを意味するということです。 ただし、盲目的に受け入れることはできません`n // 3`パリティ制約により調整が強制される可能性があるため、3 ポイント スローの数として使用されます。 具体的には、選択した後、`b`、残りの値`n - 3b`均等でなければなりません。 

これにより、問題は実現可能な最大値を見つけることに変わります。`b`そのような`n - 3b ≥ 0`そして`n - 3b`で割り切れます`2`。 かつてそのような`b`が見つかり、`a`次のように一意に決定されます`(n - 3b) / 2`。 

せいぜい数人の候補者をチェックするだけで済みます`n // 3`、削減するため`b`1 倍すると剰余が 3 倍になり、パリティが反転します。 これにより、有効な解決策が存在する場合には、それがすぐに見つかることが保証されます。

 ## アルゴリズムのチュートリアル

 私たちが構築したいのは`n`有効性を維持しながら、できるだけ多くの 3 ポイントスローを使用します。 

1. 3 ポイントスローの最大可能数を次のように計算します。`b = n // 3`。 これにより、以下を超えることなく 3 ポイントスローからの最大のスコア貢献が得られます。`n`。 残りの点は2点投げで処理します。 
2. その間`b`が負ではない場合は、残りのスコアがあるかどうかを確認してください`n - 3b`2 で割り切れる場合、有効な分解が見つかりました。 この条件により、2 点投げを使用してレフトオーバーを正確に形成できることが保証されます。 
3. 余りが 2 で割り切れない場合は、減少します。`b`1 増やして再試行してください。 削減`b`残りを正確に 3 ポイント変更し、パリティを切り替えるため、有効な解決策は多くても少数の調整で表示されます。 
4. そのようなものを見つけた場合`b`、計算する`a = (n - 3b) // 2`そして出力`(a, b)`。 
5. 減らすと`b`有効な構成が見つからずにゼロ未満の場合、出力`No`。 

### なぜ効果があるのか

 すべての有効な解は整数のペアに対応します`(a, b)`ディオファントスの線形方程式を満たす`2a + 3b = n`。 このようなすべてのペアの中で、スロー数を最小化することは、スロー数を最大化することと同じです。`b`3 ポイントスローを 2 ポイントスローに置き換えると、スローの総数が常に増加するためです。 

可能な限り大きなものから始めることで、`b`必要な場合にのみ減らし、より良いソリューションを決してスキップしないようにします。 パリティ条件`n - 3b ≡ 0 (mod 2)`一度実現可能性を完全に特徴づける`b`は固定されているため、次の値をチェックします`b`正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())

    b = n // 3
    while b >= 0:
        rem = n - 3 * b
        if rem % 2 == 0:
            a = rem // 2
            print(a, b)
            return
        b -= 1

    print("No")

if __name__ == "__main__":
    solve()
```このコードは、前述した貪欲な構造に従っています。 3 点スローの可能な最大数から開始し、残りを 2 点スローで表現できない場合にのみ下方調整します。 主要な実装詳細はコンピューティングです`rem = n - 3 * b`除算の前にパリティをチェックすることで、浮動小数点または無効な整数の除算を回避します。 

ループは最大で実行されるため安全です`n // 3`理論上は 1 回の繰り返しですが、実際にはパリティの変更により一定の反復回数だけが必要になります。

 ## 特殊なケース

 のために`n = 1`、アルゴリズムは次から始まります`b = 0`、余りを与える`1`。 以来`1 % 2 != 0`、減少します`b`に`-1`そして停止し、正しく出力されます`No`。 これは、2 と 3 を組み合わせて 1 を形成できないという事実と一致します。 

のために`n = 2`、から始めます`b = 0`、残りは`2`、これは 2 で割り切れるので、`a = 1`そして出力は`(1, 0)`。 これにより、アルゴリズムが 3 点調整を必要とせずに、純粋な 2 点構成を正しく処理できることが確認されました。 

のために`n = 3`、`b = 1`剰余を生み出す`0`、すぐに与える`(0, 1)`。 これは、アルゴリズムが正確に適合する場合に、より高い値のスローを正しく優先し、最小限のスロー数を生成することを示しています。
