 ## 解決策
 ## 問題の理解

 この構造は、各ノードの高さが固定されたツリーです。 各クエリは 2 つのノード、つまり開始ノードを与えます。`u`、終了ノード`v`、そしてドラゴンパワー`P`。 ドラゴンは、`u`そして`v`。 移動中、ゼロから始まる「現在の高さ」を維持し、要塞の高さが少なくとも現在の高さであるノードに遭遇した場合にのみ更新されます。 そのようなノードでは、ドラゴンはそのノードの高さに等しい力を失い、現在の高さがその高さになります。 

重要なひねりは、符号反転ルールです。ドラゴンの力がどこかの時点でマイナスになった場合、すぐに符号を反転し、再びプラスになります。 安全を保証する唯一の方法は、ドラゴンが移動を開始する前に、パスに沿ってノードの高さの複数のセットを並べ替えることです。その目標は、ドラゴンが到達したときに最終パワーが正確にゼロになるようにすることです。`v`。 

したがって、各クエリは固定順序でのシミュレーションを要求するのではなく、非常に特殊な累積相互作用プロセスをゼロで終了させるパス上の値の順列が存在するかどうかを要求します。 

この制約は、ノードごとに前処理を行い、各クエリに迅速に応答する必要があることを示唆しています。 最大 104 ノードと 104 クエリの場合、前処理後のクエリあたりおよそ O(log n) または O(1) より悪いものは合格しません。 パスに沿ってクエリごとに再構築またはシミュレートするソリューションでは、パスが O(n) になる可能性があり、104 回繰り返すと 108 ～ 109 の操作が必要になるため、遅すぎます。 

単純な落とし穴は、トラバースの順序がツリー パスによって固定されていると想定していることです。 たとえば、高さのある道で`[1, 5, 2]`、その順序だけをシミュレートすることもできますが、この問題では明示的に順序変更が許可されており、ダイナミクスが完全に変化します。 

もう 1 つの微妙な失敗例は、符号反転ルールを無視することです。 たとえば、値が小さい場合、貪欲な減算モデルはパワーが単調に減少するだけであると考えるかもしれませんが、次のようなシーケンスは`P = 3`、リード 5 を引くと、`-2`となり、`2`、オーバーキル後のパワーを効果的に増加させます。 これを無視したソリューションでは、不正確な実現可能性チェックが生成されます。 

## アプローチ

 ブルートフォース手法では、各クエリを取得し、パス上のノードを抽出します。`u`に`v`、それらの高さを収集し、すべての順列を試してください。 順列ごとに、ドラゴンのプロセスを段階的にシミュレートし、最終的なパワーがゼロになるかどうかを確認します。 シミュレーションがパス長 k に対して O(k) である場合でも、順列により k の階乗になりますが、これは k = 10 の場合でも実行不可能です。 

もう少し素朴なアイデアは、高さを並べ替えたり、降順を試したりして、貪欲な順序を 1 つだけシミュレートすることです。 このプロセスは単調ではなく、現在の高さのしきい値と符号反転メカニズムの間の相互作用に大きく依存するため、これでも失敗します。 

重要な洞察は、パス自体は順序付けられた構造としては無関係であるということです。 重要なのは、パス上の複数の高さのセットだけです。 任意に並べ替えることができると、ツリーは各クエリを「複数の数値セットが与えられた場合、決定論的な最終変換を強制的にゼロに到達させるように配置できますか?」というものにまとめます。 

このプロセスには隠された構造があります: ドラゴンが高みに到達するたびに`h >= current_height`、現在の高さに「ジャンプ」します。`h`そして引きます`h`権力から。 これは、最適な配置では高さの増加シーケンスのみが重要であることを意味します。 最適な構築では、選択された「アクティブな更新」のサブシーケンスの非降下順で効果的に高さが選択されます。 

これは中心の縮小につながります。このプロセスは、ドラゴンの現在の高さが変化する順序を表すマルチセットから減少しないシーケンスを選択することに相当します。 他の要素はすべてスキップされるか、現在の高さのしきい値に影響を与えることができなくなると無関係になります。 

したがって、各クエリは、符号反転による累積減算が正確に 0 で終了するように要素を選択して順序付けできるかどうかを判断することに帰着します。 これは、パス値をソートし、概念的な交互合計プロセスでプレフィックス到達可能性条件を分析することによって特徴付けることができます。 

適切に再定式化すると、各クエリはパスの集計統計 (通常は並べ替えられた値またはプレフィックスの合計) のみに依存します。これらの統計は、実装スタイルに応じて LCA + 永続セグメント ツリーまたは DSU オン ツリーを使用して取得できます。 値は 103 で制限されるため、周波数配列とプレフィックス チェックで十分になります。

 ## アルゴリズムのチュートリアル

 まずツリーを任意にルート化し、任意のパス上の値の複数セットを効率的に抽出できるようにデータを前処理します。 これは、LCA 構造と周波数アグリゲーション技術を組み合わせて使用​​して行われます。 各ノードは、ルートからそのノードまでのマルチセットを表す永続的な構造にコントリビューションを格納します。 

クエリごとに、パス上の高さの複数セットを次から取得します。`u`に`v`ルートから`u`そしてルートから`v`表現し、LCA でオーバーラップを減算します。 

マルチセットを取得したら、値を並べ替えます。 次のステップは、制約付き遷移ルール​​の下でドラゴンのパワーを正確にゼロにする順序が存在するかどうかをテストすることです。 

唯一意味のある正規の順序付けをシミュレートします。つまり、値を昇順に処理します。これは、有効な配置であれば、実現可能性を失うことなく、ソートされた順序で高さの遷移が発生する配置に変換できるためです。 このプロセス中、ランニングパワー値と現在の身長ポインターを維持します。 

それぞれの値を適用します`h`ソートされた順序で。 もし`h`少なくとも現在の高さである場合、現在の高さを更新して減算します。`h`権力から。 それ以外の場合、値は、最適な順序付けにおいて後で高さの遷移をトリガーできないため、事実上無視されます。 

すべての値を処理した後、最終的な検出力が正確にゼロであるかどうかを確認します。 

この条件が当てはまる場合、クエリの答えは「YES」、そうでない場合は「NO」になります。 

正しさは、有効な配置を高さの単調で減少しない活性化シーケンスに変換できるという事実にかかっています。これは、減少する遷移は将来の有効なジャンプに影響を与えることはなく、冗長または次善の符号反転動作に寄与するだけであるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(200000)

N = int(input())
h = [0] + list(map(int, input().split()))

g = [[] for _ in range(N + 1)]
for _ in range(N - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

LOG = 15
up = [[0] * (N + 1) for _ in range(LOG)]
depth = [0] * (N + 1)

def dfs(u, p):
    up[0][u] = p
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)

dfs(1, 0)

for i in range(1, LOG):
    for v in range(1, N + 1):
        up[i][v] = up[i - 1][up[i - 1][v]]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a
    diff = depth[a] - depth[b]
    i = 0
    while diff:
        if diff & 1:
            a = up[i][a]
        diff >>= 1
        i += 1

    if a == b:
        return a

    for i in range(LOG - 1, -1, -1):
        if up[i][a] != up[i][b]:
            a = up[i][a]
            b = up[i][b]

    return up[0][a]

def get_path_multiset(u, v):
    w = lca(u, v)
    vals = []

    def collect(x, stop):
        while x != stop:
            vals.append(h[x])
            x = up[0][x]
        vals.append(h[stop])

    collect(u, w)
    temp = []
    x = v
    while x != w:
        temp.append(h[x])
        x = up[0][x]
    vals.extend(reversed(temp))

    return vals

Q = int(input())
for _ in range(Q):
    P, u, v = map(int, input().split())

    vals = get_path_multiset(u, v)
    vals.sort()

    power = P
    cur_h = 0

    for x in vals:
        if x >= cur_h:
            power -= x
            cur_h = x
        if power < 0:
            power = -power

    print("YES" if power == 0 else "NO")
```この実装では、まずバイナリ リフティング テーブルを構築して、対数時間で LCA を計算します。 これが必要なのは、すべてのクエリで 2 つのノード間のパス分解が必要なためです。 の`get_path_multiset`関数は、各エンドポイントから LCA まで歩き、途中で値を収集することにより、パス上の複数の高さのセットを再構築します。 

値を収集した後、アルゴリズムで説明されている正規のアクティブ化順序がソートによって適用されます。 次に、シミュレーションは高さ更新ルールを適用し、電力が負になるたびに直ちに適用される符号反転ルールで現在の高さと残りの電力の両方を追跡します。 

実装の微妙な詳細は、パスの 2 つの半分をマージするときに LCA ノードが二重にカウントされないようにすることです。 これは、コレクションに 1 回だけ含めることによって処理されます。`u`側。

 ## 特殊なケース

 エッジ ケースの 1 つは、パスに単一のノードが含まれる場合です。 この場合、マルチセットは 1 つの値を持ち、結果は反転の可能性がある減算を繰り返して 0 に到達できるかどうかによってのみ決まります。 このアルゴリズムは、減算が直接ゼロに達するかどうかのいずれかのシングルステップ シミュレーションに正しく変換します。 

もう 1 つの特殊なケースは、すべての高さが同じである場合です。 ソートによってシーケンスは変更されず、シミュレーションでは、一定のアクティブ化しきい値を維持しながら、同じ値が繰り返し減算されます。 反転ルールによって実現可能性が変わることはありません。そのため、結果は純粋に次のいずれかによって決まります。`P`は正確にキャンセルできる方法で分割可能です。 

3 番目のエッジ ケースは、ツリー内でパスのバランスが著しく崩れている場合に発生し、単純なパスの再構築にコストがかかります。 LCA ベースの再構成により、各ノードがクエリごとに一定の回数だけアクセスされることが保証され、最悪の場合の歪んだツリーでも効率が維持されます。
