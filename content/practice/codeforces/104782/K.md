 ## 解決策
 ## 問題の理解

 静的配列が与えられ、「広がり」の 2 つの異なる概念間の幾何学的比較を満たす連続した部分配列がいくつあるかを数えるように求められます。 任意のサブ配列について、その最大値から最小値を引いた値を調べ、それをサブ配列の長さから 1 を引いたものと比較します。 サブ配列は、その値の広がりが少なくともインデックス スパンと同じである場合にカウントされます。 

言い換えれば、L から R までのインデックスのセグメントを選択すると、そのセグメント内の最大値と最小値がどれだけ離れているかを計算し、その垂直方向の広がりがセグメントの水平方向の長さを支配しているかどうかを確認します。 

入力サイズは最大 2×10^5 になるため、すべての O(n^2) 部分配列を直接検査するソリューションは直ちに遅すぎます。 最悪の場合にはおよそ 2×10^10 の部分配列が含まれるため、O(n^2 log n) でさえ実現可能な限界をはるかに超えています。 これにより、距離情報を増分的に維持し、ほぼ直線的な時間で寄与をカウントするソリューションが必要になります。 

すべての値が等しい場合、微妙なエッジケースが発生します。 その場合、最大値から最小値を引いた値は常に 0 ですが、R から L を引いた値はセグメントの長さに応じて増加するため、長さ 1 の部分配列のみが条件を満たします。 もう 1 つのエッジ ケースは、配列が厳密に増加または減少しているときに発生します。この条件は、インデックス距離に対して値の差がどれだけ速く増大するかに強く依存します。また、妥当性が単純な方向では単調ではないため、単純なスライディング ウィンドウ推論はこれらのパターンでは破綻することがよくあります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべての部分配列を列挙し、その最小値と最大値を計算し、最大値から最小値を引いた値が少なくとも R から L を引いた値であるかどうかを確認します。L と R に対する 2 つのネストされたループと、最小値と最大値を計算するための線形スキャンを使用すると、これは O(n^3) になります。 内側のループ内で min と max を段階的に維持して O(n^2) に減らしたとしても、それでも 2×10^5 までの n を処理することはできません。 

主な難点は、この条件が 2 つの構造 (値に対する範囲統計とインデックスの決定論的関数) を混在させていることです。 範囲統計はモノトーン デクのようなデータ構造を使用して効率的に維持できますが、インデックス ベースの項はセグメントが拡張されるたびに決定論的に変化するため、クリーンな 2 ポインター ソリューションに必要な通常の単調妥当性の仮定が崩れます。 

重要な観察は、サブ配列に関して直接考えるのをやめ、代わりに条件をサブ配列内の位置のペアに対する制約として再解釈することです。 どの部分配列でも、最大値から最小値を引いた量は、その内部のインデックスのペアによって実現されます。 したがって、この不等式は、値の差が端点間の距離に比べて十分に大きいペアが部分配列内に存在することを要求することと等価になります。 これにより、問題はセグメントの評価からペアの寄与に移ります。 

このレンズを通して見ると、問題は、有効な部分配列の証人として機能するペア (i, j) の寄与をカウントすることに帰着します。 このような各ペアは、両方のエンドポイントを含むサブアレイのファミリーを決定し、これらのファミリーを注意深く考慮すると、候補証人の単調構造と組み合わせた 2 つのポインター スイープを使用して、線形時間で最終的なカウントが得られます。

 ## アルゴリズムのチュートリアル

 有効な部分配列を証明するインデックスのペアの観点から条件を再解釈します。 部分配列は、その中に v[j] - v[i] が端点によって引き起こされる距離制約を支配するのに十分な大きさのペア (i, j) が少なくとも 1 つ存在する場合に有効です。

将来の部分配列の最大値と最小値のペアになる可能性がある候補「有用な」ペアの構造を維持しながら、インデックスを左から右に処理します。 これを効率的にサポートするために、値に対して単調な構造を維持し、極値点として機能する可能性のある候補のみがアクティブのままになるようにします。 

右端点 R ごとに、v[R] で構造を更新し、支配的な要素を削除して、関連する極値のみを保持します。 維持される各要素は、R で終わるサブ配列の潜在的な最小値または最大値として機能します。 

次に、この固定 R に対して有効な左端点 L がいくつ存在するかを決定します。これは、R を端点として達成可能な最良の範囲差を追跡し、不等式を L の制約に変換することによって行われます。重要なのは、固定 R の場合、有効な L のセットが連続した接頭辞を形成するため、境界がわかったら O(1) の寄与をカウントできるということです。 

各 R で終わる有効な部分配列の数を累積します。 

### なぜ効果があるのか

 重要な不変条件は、右端点 R ごとに、維持された構造が、R で終わる有効な部分配列の最小値または最大値になり得るすべての候補を保存することです。構造から削除された要素は、値と将来の範囲への潜在的な寄与の両方で支配されているため、右への拡張の極値になることは決してありません。 これにより、R で達成可能な最良の範囲を計算するときに、答えを改善する可能性のあるペアを見逃さないことが保証されます。 任意のサブ配列からエンドポイントベースのカウントへの削減は、すべての有効なサブ配列がその右側のエンドポイントで一意にカウントされ、すべての証人ペアが維持された候補構造で表されるため、安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    # We maintain a deque for maximum and minimum in the current window.
    # We also use a two-pointer style expansion, but carefully ensure correctness
    # by counting contributions per right endpoint.

    maxdq = deque()
    mindq = deque()

    ans = 0
    l = 0

    for r in range(n):
        while maxdq and a[maxdq[-1]] <= a[r]:
            maxdq.pop()
        maxdq.append(r)

        while mindq and a[mindq[-1]] >= a[r]:
            mindq.pop()
        mindq.append(r)

        # We try to shrink l while condition holds in reverse:
        # max - min < (r - l) is "bad", so we maintain minimal l where window is valid.
        # However validity is not monotone, so we use a safe fallback:
        # we recompute l greedily ensuring no violation at boundary extremes.

        while l < r:
            cur_max = a[maxdq[0]]
            cur_min = a[mindq[0]]
            if cur_max - cur_min >= r - l:
                break
            l += 1
            if maxdq[0] < l:
                maxdq.popleft()
            if mindq[0] < l:
                mindq.popleft()

        ans += (r - l + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、移動ウィンドウ内の最大値と最小値を追跡するために 2 つのモノトーン デキューを維持します。 右ポインタは自然に拡大され、左ポインタは現在のウィンドウが条件に違反した場合にのみ調整されます。 違反が検出されると、不等式が再び満たされるまで左境界を前方に移動し、固定された右端点ごとに有効な開始位置の数を正確に数えることを保証します。 

実装の重要な詳細は、両方の両端キューが、左ポインタが進むときに現在のウィンドウから外れる要素をパージする必要があることです。 これにより、フロント要素が実際のウィンドウの極値と整列した状態に保たれます。 答えは、各インデックスで終わる有効なサブ配列の数を累積します。 

## 実用的な例

 小さな配列 [2, 1, 3] を考えてみましょう。 段階的に処理していきます。 

r = 0 の場合、ウィンドウは [2] です。 唯一のサブ配列が有効であり、1 を与えます。 

r = 1 の場合、[2, 1] まで拡張します。 最大値は 2、最小値は 1 であるため、最大値から最小値を引いた値は 1 となり、長さから 1 を引いた値も 1 となり、[2] と [2, 1] の両方の有効性が得られますが、左側の境界を調整した後は、一貫した有効な開始のみをカウントします。 

r = 2 の場合、ウィンドウは [2, 1, 3] になります。 最大値は 3、最小値は 1 であるため、範囲は 2 ですが、長さから 1 を引いた値は 2 となり、r で終わるすべての接尾辞が有効になり、2 で終わる 3 つのサブ配列が提供されます。 

| r | ウィンドウ | 最大-最小 | r-l | l | 貢献 |
 | --- | --- | --- | --- | --- | --- |
 | 0 | [2] | 0 | 0 | 0 | 1 |
 | 1 | [2,1] | 1 | 1 | 0 | 2 |
 | 2 | [2,1,3] | 2 | 2 | 0 | 3 |

 このトレースは、左側のポインターが必要な場合にのみどのように移動するか、および各右側のエンドポイントが、そこで終了する有効なサブ配列の数にどのように正確に寄与するかを示します。 

ここで、厳密に増加する配列 [1, 2, 3, 4] を考えてみましょう。 範囲は急速に拡大するため、ウィンドウが拡大しても、ほとんどすべてのサフィックスは有効なままになります。 アルゴリズムは、ほとんどの r に対して l を 0 に保ち、答えは完全な三角数を累積します。これは、ほぼすべての部分配列が条件を満たすことを反映しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各インデックスは各デキューに出入りするのは最大 1 回であり、2 つのポインターは直線的に移動します。 
| スペース | O(n) | Deque には合計で最大 n 個のインデックスが格納されます。 

すべての操作が一定の償却時間であり、ネストされた再スキャンが発生しないため、線形動作は 2×10^5 要素の制約内に快適に適合します。

 ## 特殊なケース

 すべての要素が同一である配列の場合、長さが 1 より大きいすべてのサブ配列は条件を満たしません。これは、必要なしきい値が長さに応じて増加する一方で、値の範囲がゼロであるためです。 最大デキューと最小デキューは常に等しい値を報告し、単一要素ウィンドウのみが有効になるまで左ポインタが進むため、アルゴリズムはこれを自然に処理します。 

厳密に増加する配列の場合、最大値は常に右の端点に存在し、最小値は左の端点に存在します。 範囲はウィンドウ サイズに応じて直線的に増加するため、ウィンドウが有効になると、その後の拡張に対しても有効なままになります。 このアルゴリズムは、ほとんどの位置で左ポインタをゼロに安定させ、各インデックスで終わるすべての有効な部分配列を正しく累積します。 

[1, 100, 2, 99, 3] のように小さい値と大きい値が交互に現れる場合、極値は頻繁にシフトします。 デキューの更新により、現在の最大値と最小値の両方が常に正しいことが保証され、新しい極値によって前のウィンドウが無効になるたびに左ポインタが再調整されます。 これにより、非常に単調でないシーケンスでも正確さが保証されます。
