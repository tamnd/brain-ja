 ## 解決策
 ## 問題の理解

 独立したコンポーネントのコレクションが与えられ、それぞれがある程度の確率で正しく動作します。 システムは、これらのコンポーネントが少なくともしきい値数で動作する場合にのみ成功します。 コンポーネント間で一定量の「トレーニング リソース」を分配することで、コンポーネントを改善することができます。 リソースの各単位は、選択したコンポーネントの成功確率を 1 単位 (最大 1) 増加させます。 

タスクは、少なくとも K 個のコンポーネントが成功する確率を最大化する方法で、この限られたリソースをコンポーネント全体に割り当てることです。 

入力は複数のテスト ケースで構成されます。 テスト ケースごとに、コンポーネントの数、必要な動作コンポーネントの最小数、改善単位の総予算、およびすべてのコンポーネントの初期成功確率を受け取ります。 

出力は、改善ユニットを最適に分散した後に少なくとも K 個のコンポーネントが機能する、達成可能な最大確率です。 

N に関して制約は小さく、N は最大 50 です。これは、テスト ケースごとに O(N3) または O(N⁴) スタイルのソリューションがまだ許容される可能性があることを強く示唆しています。 ただし、リソース割り当ての継続的な性質により、強引な配布は不可能になります。 ユニットのすべての分布を列挙しようとするアプローチは、たとえ中程度の U であっても、整数割り当ての数が組み合わせ的に増加するため、直ちに実行不可能になります。 

重要な構造的制約は、確率が合計の「ギャップ」で 1 を超える必要がないように U が制限されていることです。つまり、リソースは常に確率の一部のサブセットを完全に飽和させるのに十分ですが、それを超えて無駄に大きくなることはありません。 これは、最適解が何らかの構造化された方法で常に確率を 1 に近づけることを示唆しています。 

見落としがちないくつかの特殊なケース:

 K が N に等しい場合、問題は「すべてのコンポーネントが成功する確率を最大化する」になります。 これは製品の最大化の問題のように見えますが、トレーニングにより選択肢間の依存関係が導入されます。 

K が 1 に等しい場合、問題は「少なくとも 1 つが機能する確率を最大化する」ことになり、これは失敗確率の積を最小化することと同じになり、最適な割り当ては最も強力な限界改善に向けて大きく偏ります。 

すべての確率が 0 で、K が 0 より大きい場合、答えは十分なトレーニングによって調整された方法で K 成分を 0 より大きくできるかどうかに完全に依存します。 

コンポーネントごとの単純な貪欲な割り当ては失敗します。これは、1 つのコンポーネントを改善すると、しきい値付きの確率式により、他のコンポーネントを改善する限界値が非線形に変化するためです。 

## アプローチ

 直接的な総当たりアプローチでは、N 個のコンポーネントに U 個の整数ユニットを分散させようとします。 整数の割り当てに制限したとしても、U 個の同一アイテムを N 個のビンに分配する方法の数は約$\binom{U+N-1}{N-1}$これは、中程度の U の場合でも膨大です。割り当てを選択した後、少なくとも K 個のコンポーネントが成功する確率を計算します。これには、N 個の要素にわたるサブセット DP が必要です。 これにより、実際の総当たり攻撃はすでに 2 倍の指数関数的になります。 

重要な観察は、目標は最終的な確率のみに依存し、どのように達成するかには依存しないということです。 各コンポーネントの確率は独立して 1 まで増加し、最終的な成功確率はこれらの最終値の単調関数になります。 これは、最終的なターゲットの確率という観点から考える必要があることを示唆しています。$p'_i$、ここでそれぞれ$p'_i \in [p_i, 1]$、合計の「コスト」は$\sum (p'_i - p_i) \le U$。 

ここで、問題は連続的になります。線形予算制約の下で最終確率を選択し、少なくとも K 個のベルヌーイ変数が成功する確率を最大化します。 

これは、対物レンズが対称で凹型の隠れた形状になっている古典的な構造です。 最適な戦略は、重要な再パラメータ化を通じて理解できます。つまり、確率について直接考える代わりに、「失敗の削減」という観点から考えます。 各コアの故障確率は次のとおりです。$q_i = 1 - p_i$、そして増加しています$p_i$減らす$q_i$ゼロになるまで直線的に。 

「少なくとも K 個が成功する」というイベントは、「最大で N-K 個の失敗が発生する」と同等です。 これは、個々の故障確率の線形減少の下でポアソン二項分布の裾確率を最適化していることを示唆しています。 

重要な構造的洞察は、最適解では、最終的な確率が限界値が均等化された少数のグループに分類されると想定できることです。 これは標準的な交換の議論から来ています。つまり、2 つのコンポーネントがトレーニング単位ごとに異なる限界利益を持っている場合、少量のリソースを一方から他方にシフトすると、平衡に達するまで目標が増加または維持されます。 これにより、「完全にトレーニング」または部分的にトレーニングされたコンポーネントの数に関するソートおよび動的プログラミングによって利用できる均等化条件が強制されます。 

これを解決するためのより具体的な方法は、確率 1 にプッシュされる成分の数を固定し、残りの分布を最適に解くことです。 N が小さいため、完全に飽和したコンポーネントのすべての選択肢を試し、必要なコストを差し引いて、問題を残りのアイテムに対する残りの U の最適な分布を計算することに縮小できます。 残りの構造は、成功したコアの数に対する標準 DP を使用して成功確率を計算できる、確率に対する制約付きの最適化になります。 

固定の最終確率ベクトルについて、O(NK) のナップザックのような DP を使用して、少なくとも K 回の成功の確率を計算します。 次に、整数の増分を確率に割り当てることによって誘導される、実現可能な最終的な確率構成を探索します。 確率は 0.0001 の倍数であるため、すべてを 10000 でスケールし、整数のリソース割り当て DP として扱うことができます。 

これにより、問題は、各個別の確率レベルまで改善されたコアの数を州が追跡する、境界のあるナップザック スタイルの DP に帰着します。 N が小さいため、完全に処理されたコアの数と累積された確率分布に対して DP を維持できます。

 ## アルゴリズムのチュートリアル

 確率は 10000 でスケールされた整数として扱われます。トレーニングの各単位では、10000 に達するまで 1 つの確率が 1 ずつ増加します。 

使用されたトレーニング ユニットの数と成功確率の分布を追跡しながら、コアを 1 つずつ構築する動的プログラミング状態を定義します。 

1. コアは独立しており、構造は独立していて交換可能ですが、値は交換できないため、固定順序でソートまたは保持します。 
2. DP テーブルを初期化します。ここで dp[i][j][s] は、i 個のコアを処理し、j 個のトレーニング ユニットを使用した後に正確に s 個のコアが成功する最高の達成確率を表します。 dp[0][0][0] = 1 に初期化します。 
3. 各コア i について、それに t 個のトレーニング ユニットを割り当てるすべての可能な方法を検討します。ここで、0 ≤ t ≤ U で、最終的な確率は min(1, p_i + t) になります。 
4. 各 DP 状態について、結果を分割することによって遷移します。コアは、トレーニング後の最終確率によって重み付けされ、成功または失敗のいずれかになります。 
5. 現在の分布を選択した確率のベルヌーイ結果と畳み込むことにより DP を更新します。 
6. すべてのコアを処理した後、s ≥ K であるすべての状態の最大値を取得します。 

重要な実装のコツは、すべての j 値を密な方法で明示的に追跡することを避けることです。 代わりに、使用されたトレーニング全体に対して DP を圧縮し、ローリング配列を再利用します。 

これが機能する理由は、少なくとも K 回の成功の確率は最終確率のマルチセットにのみ依存し、DP は予算制約の下で実行可能なトレーニングの分布をすべて二重カウントせずに列挙するためです。 

## なぜ機能するのか

DP は、独立したベルヌーイの結果を正しく集約しながら、離散トレーニング ユニットを分散する実現可能なすべての方法を強制します。 すべての状態は有効な部分割り当てに対応し、遷移は正確な確率質量を保持します。 すべての有効な割り当てとすべての確率的結果を列挙するため、離散化が入力精度と一致すると、最終状態の最大値は最適な連続割り当てと一致する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    SCALE = 10000

    for tc in range(1, T + 1):
        N, K = map(int, input().split())
        U = int(round(float(input().strip()) * SCALE))

        p = list(map(float, input().split()))
        base = [int(round(x * SCALE)) for x in p]

        # dp[used][s] = probability
        dp = [[0.0] * (N + 1) for _ in range(U + 1)]
        dp[0][0] = 1.0

        for i in range(N):
            ndp = [[0.0] * (N + 1) for _ in range(U + 1)]
            for used in range(U + 1):
                for s in range(i + 1):
                    if dp[used][s] == 0:
                        continue
                    cur = base[i]
                    for t in range(U - used + 1):
                        final = min(SCALE, cur + t)
                        prob = final / SCALE
                        nused = used + t

                        ndp[nused][s] += dp[used][s] * (1 - prob)
                        ndp[nused][s + 1] += dp[used][s] * prob

            dp = ndp

        ans = 0.0
        for used in range(U + 1):
            for s in range(K, N + 1):
                ans = max(ans, dp[used][s])

        print(f"Case #{tc}: {ans:.6f}")

if __name__ == "__main__":
    solve()
```このコードでは、費やしたトレーニングの合計と成功したコアの数に対する 2D DP を使用します。 各コアについて、実行可能なすべてのトレーニング割り当てを試行し、結果の確率に従って成功分岐と失敗分岐を更新します。 

トレーニング割り当てに対するネストされたループは、実装の重要な詳細です。 これにより、成功に対する DP が正確な確率分布を蓄積しながら、離散単位を割り当てるあらゆる可能な方法が確実に考慮されます。 

浮動小数点の累算は、必要な精度が高いため許容されます。$10^{-6}$、そしてすべての確率は制限されたままであり、正常に動作します。

 ## 特殊なケース

 K が N に等しい場合、DP はすべてのコアが成功する確率のみを追跡するようになります。 畳み込みは引き続き機能しますが、重要なのは s = N 列だけです。 このアルゴリズムは、完全に成功したパスのみを正しく蓄積します。 

U が 0 の場合、トレーニングを伴う遷移は行われません。 DP は元の確率にわたって標準的なポアソン二項分布に崩壊し、アルゴリズムは少なくとも K 回の成功についての積和構造を自然に生成します。 

すべての確率が 0 の場合、DP は最初にすべての質量を故障状態に置きます。 トレーニングにより質量が徐々に成功状態に移行し、DP は、確率をゼロ以上にするのに十分なユニットが割り当てられた場合にのみ成功が現れることを保証し、縮退した初期化ケースでも正確さを維持します。
