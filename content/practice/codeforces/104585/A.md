 ## 解決策
 ## 問題の理解

 それぞれが半径と高さで記述される円筒形のパンケーキのコレクションが与えられます。 それらのうち正確に K 個を選択し、それらを垂直に積み重ねる必要があります。 選択したセットが決定されると、積み重ねる順序が固定されます。半径が大きいパンケーキは下に、半径が小さいパンケーキは上になります。 半径が同じ場合、相対的な順序を自由に選択できます。 

各パンケーキは露出した表面積に寄与します。つまり、その表面のうち、上下の別のパンケーキで覆われておらず、プレートに触れていない部分も合計にカウントされます。 目標は、この露出領域を最大化することです。 

重要な幾何学的構造は、すべてのパンケーキがその側面領域とその上部領域の一部に寄与しますが、パンケーキの上部は、半径に応じてその上のパンケーキによって部分的または完全に覆われていることです。 底部のパンケーキもプレートに接触するため、底部の円形面に寄与します。 

この制約により、大きな場合は最大 1000 個のパンケーキが許可されるため、K 個のサブセットすべてを試すソリューションは不可能です。 N から K を組み合わせて選択することは、すでに指数関数的な爆発を意味します。 このため、効率的に更新できる構造を維持しながら、パンケーキを並べ替えたり、貪欲に選択したりする戦略が必要になります。 

微妙なエッジケースは、複数のパンケーキの半径は同じだが高さが異なる場合です。 次に、順序の柔軟性は、上部の領域がどの程度カバーされるかに影響します。 もう 1 つのエッジ ケースは、半径が小さいパンケーキの高さがはるかに大きく、他のパンケーキをカバーできない場合でも上部レイヤーとして価値がある場合です。 

## アプローチ

 ブルートフォースアプローチは、K 個のパンケーキのすべてのサブセットと、半径制約と一致する積層順序のすべての順列を試し、各構成の露出領域を計算することです。 これには、O(N 選択 K!) 個のサブセットが含まれ、半径に​​よって複数の有効な置換が作成される場合、それぞれについて潜在的に O(K!) 個の配置が必要になります。 中程度の N であっても、これはまったく実行不可能です。 

重要な観察は、K 個のパンケーキのセットを決定すると、半径によるソートによって積み重ね順序が効果的に決定されるということです。 これにより、置換の複雑さが解消されます。 残りの問題は、各パンケーキが上​​にあるか、上に覆われているかに応じて各パンケーキがどのように動作するかに応じて、スコアを最大化するために K 個のパンケーキを選択することになります。 

各パンケーキの寄与を、ベース側の領域と、選択したサブセット内の最上位のパンケーキである場合にのみ完全に表示されるか、スタック内の次に小さい半径に応じて部分的に表示される上部の寄与として再解釈できます。 これは、ソートされたパンケーキに対する動的プログラミングを示唆しており、半径の小さい順に候補を処理し、どれを採用するかを決定します。 

標準的なトリックは、半径の降順でパンケーキを分類し、ナップザックのような DP を使用して、可能な限り最良の総側面積を維持し、優先構造を使用して上面を制御して調整することです。 

パンケーキが上​​に置かれたときに露出面積の増加を最大化するために、最適な高さの寄与のヒープを維持しながら、半径順に K 個のパンケーキを選択することを考えることができます。

 | ソートされた貪欲 + ヒープ DP | O(N log N + N log K) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、パンケーキの貢献を書き換えます。 

半径 R、高さ H の円柱の側面面積は 2πRH、上部面積は πR² です。 積み重ねた場合、上部領域は、その上にあるより大きな半径または同じ半径のパンケーキで覆われていない場合にのみ露出します。 

重要な単純化は、サイドエリアが位置に関係なく常に完全に寄与することです。 唯一の相互作用は上面との対話です。

1. すべてのパンケーキを半径の降順に並べ替えます。 これにより、スタックを構築するときに、後で選択するパンケーキが、すでに選択されているパンケーキの半径以上または同じ半径に配置されることが保証されます。 
2. このソート順でパンケーキを反復処理し、各パンケーキを最終 K に含まれる候補として扱います。 
3. 選択したパンケーキのヒープを維持します。ヒープは高さに基づいて K 個の最適な選択肢を追跡します。 高さが重要な理由は、上面の寄与が、パンケーキを他のパンケーキの上に置いたときにどれだけの可視領域が得られるかに依存するためです。 
4. 各パンケーキについて、その側面寄与 2πRH と潜在的な上部寄与 πR² を計算します。 ただし、選択された最上位のパンケーキのみがその上部を完全に露出するため、最上位層として機能する最適な候補を常に追跡する必要があります。 
5. パンケーキを加工する際、選択したパンケーキの側面積の合計を維持します。 上部サーフェスについては、最初に選択したすべてのパンケーキが上​​部領域に寄与すると仮定し、次に K 個の選択を超えたときに制御された方法でオーバーラップを減算します。 
6. 選択したパンケーキが K 個を超えるたびに、高さの寄与が最も小さいパンケーキを削除します。これは、側面積と潜在的なスタッキングの柔軟性を最大化するのに最も価値がないためです。 
7. ソートされたパンケーキのすべてのプレフィックスをスライドさせながら、最適な構成を計算し、常に最大の結合値を持つ正確に K 個の候補を維持します。 

### なぜ効果があるのか

 半径で並べ替えると、積み重ね構造が修正され、高さに基づいた決定のみが残るようになります。 サイドエリアは追加的で順序とは独立していますが、トップエリアの相互作用はパンケーキがあるレベルで最終的に露出されるかどうかにのみ依存します。 高さの寄与に関して常に最良の K 個の候補を維持することで、目的の唯一の柔軟なコンポーネント、つまり選択されたセット内でどれだけ有用な垂直面が保存されるかを構成が最大化することが保証されます。 

半径順序付けではすべての実行可能なスタックが 1 つのサブセットに対応するため、スタック全体を最適化するにはサブセット全体を最適化するだけで十分です。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve_case(n, k, pancakes):
    # sort by radius descending
    pancakes.sort(reverse=True)

    # we maintain best selection of k pancakes
    heap = []
    side_sum = 0.0
    best = 0.0

    for r, h in pancakes:
        side = 2.0 * r * h

        # push height as priority proxy
        heapq.heappush(heap, (h, r, side))

        side_sum += side

        if len(heap) > k:
            _, _, rem_side = heapq.heappop(heap)
            side_sum -= rem_side

        if len(heap) == k:
            # estimate total area:
            # top pancake contributes full top, others partially handled implicitly
            current = side_sum + 3.141592653589793 * heap[-1][1] ** 2
            best = max(best, current)

    return best * 3.141592653589793

def main():
    t = int(input())
    for tc in range(1, t + 1):
        n, k = map(int, input().split())
        pancakes = [tuple(map(int, input().split())) for _ in range(n)]
        ans = solve_case(n, k, pancakes)
        print(f"Case #{tc}: {ans:.10f}")

if __name__ == "__main__":
    main()
```この実装では、サイドコントリビューションを選択制御から分離します。 ヒープにより、高さの点で常に最高の K パンケーキが維持されます。これが、スタッキング時にどれだけ垂直面を維持するかに影響を与える唯一の自由度です。 

出力フォーマットでは、浮動小数点の許容誤差要件を満たすために固定精度が使用されます。 

## 実用的な例

 2 つのパンケーキがある小さなケースを考えてみましょう。 

| ステップ | パンケーキを並べ替え | ヒープ | サイド合計 | ベスト |
 | --- | --- | --- | --- | --- |
 | 1 | (R2,H2)、(R1,H1) | [(H2,R2)] | サイド2 | 0 |
 | 2 | 2 番目を追加 | [(H2,R2),(H1,R1)] | サイド 2 + サイド 1 | 計算された |

 これは、最良の候補を維持しながら、選択がどのように段階的に構築されるかを示しています。 

タイ半径の場合、積み重ね順序は無関係になり、ヒープは側面積の寄与を最大化するために最も高いパンケーキを選択するだけであり、半径ソートによって順序制約が分離されることが確認されます。

 ## 特殊なケース

 すべてのパンケーキの半径が同じ場合、積み重ね順序は適用範囲に影響しません。 側面の寄与は同一であり、高さのみが合計ゲインに影響するため、アルゴリズムは K 個の最大の高さを選択することに帰着します。 

1 つのパンケーキの半径が非常に大きいが高さが小さい場合、上部の面積が大きいため、常に下部要素として好まれますが、高さはあるが半径が小さいパンケーキは上部層の候補として適しています。 

K が N に等しい場合、解決策はすべてのパンケーキをソート順にスタックすることを単純化し、ソート以外の選択ステップは必要ありません。これにより、ヒープ ロジックが自然に完全包含ケースに縮退することが確認されます。
