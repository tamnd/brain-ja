 ## 解決策
 ## 問題の理解

 地球地図は、各都市がノード、各一方通行道路が有向エッジである有向グラフとしてモデル化できます。 2 つの都市が相互に到達可能な場合、その都市は同じ国に属します。これは、最初の都市から 2 番目の都市への方向のある経路と、戻る方向の経路が存在することを意味します。 これはまさに強接続コンポーネントの定義であるため、グラフは自然に SCC に分割され、各 SCC は単一の国として機能します。 

グラフを SCC に圧縮すると、有向非巡回グラフが得られます。ノードは国であり、エッジは、ある国の都市から別の都市まで少なくとも 1 本の道路が存在することを表します。 

マスード氏は多くても 2 か国の書類しか作成できませんが、道路を自由に移動することは許可されています。 目標は、最大 2 つの SCC の連合から決して離脱せずに、訪問できる個別の都市の数を最大化することです。 

したがって、問題は、訪問するすべての都市が完全にそれらの SCC 内にあり、指示された道路を介して到達できるように、1 つまたは 2 つの SCC を選択することになります。 

重要な点は、2 つの SCC の選択が役立つのは、元のグラフの有向エッジを介して一方の SCC からもう一方の SCC に移動できる場合のみであるということです。 それらを使用可能な方向に接続する有向経路がない場合、単一の旅行計画でそれらの間を横断することはできません。 

制約は大きく、テスト ケースごとに最大 100,000 の都市と 100,000 のエッジがあります。 これにより、ノードまたは SCC ペアに対する二次アプローチが即座に排除されます。 コンポーネントのすべてのペアを反復処理するだけでも遅すぎます。 O(n + m) での SCC 分解など、テスト ケースごとに線形または線形に近いグラフ アルゴリズムが必要です。 

いくつかの特殊なケースは見落とされがちです。 エッジがない場合、すべての都市は独自の国であり、答えは単純に最大の SCC サイズ、つまり 1 になります。グラフがすでに強く接続されている場合、国は 1 つしか存在しないため、答えはすべてのノードになります。 もう 1 つの注意が必要なケースは、SCC がチェーン A → B → C を形成する場合です。A と C を同時に選択することは不可能です。旅行には B を通過する必要があり、これにより第三国が導入され、制約に違反します。 

## アプローチ

 強引な解釈では、可能なすべての開始都市を検討し、可能なすべての散歩をシミュレートし、その散歩が最大 2 つの SCC にのみ入るようにしながら、訪問できる都市の数を追跡することになります。 これには、元のグラフ内のパスを探索し、訪問したコンポーネントのセットを維持することが含まれます。 最悪の場合、各トラバースが多くのエッジに分岐し、指数関数的な動作が発生します。 SCC に制限しても、コンポーネントのすべてのペアを試してそれらの間の到達可能性をテストする場合はあまり役に立ちません。これにより、k が最大 n になる可能性がある O(k²) チェックが発生します。 

SCC を圧縮すると、問題の構造ははるかに単純になります。 圧縮後、DAG が得られます。 最大 2 か国を使用する有効な旅行は、1 つの SCC 内に滞在するか、SCC A から SCC B まで単一の有向エッジに沿って移動して停止するかのいずれかに対応する必要があります。 理由は、3 番目の SCC に入ると、許可されている国の数を超えてしまうためです。 

この観察により、問題は 2 種類の選択肢のみを評価することに帰着します。 1 つ目は、各 SCC の個別のサイズです。 2 番目は、凝縮グラフ内の有向エッジで接続された 2 つの SCC のサイズの合計です。 

少なくとも 2 つの長さのパスには必ず 3 つの SCC が含まれており、これは禁止されているため、DAG でより長いパスを考慮する必要はありません。 これにより、問題はグローバル グラフ トラバーサルから SCC サイズに関する単純なエッジベースの集計問題に分解されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (パス/都市または SCC のペア) | O(n²) 以上 | O(n + m) | 遅すぎる |
 | SCC + エッジ ペア チェック | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、Kosaraju や Tarjan などの標準 SCC アルゴリズムを使用して、強く接続されたコンポーネントを特定します。 各 SCC には ID が割り当てられ、その国の中に都市がいくつあるかを表すサイズも計算されます。 

次に、元のグラフのすべてのエッジをスキャンします。 各有向エッジ u → v について、u と v が異なる SCC に属している場合、コンポーネント cu からコンポーネント cv への接続を記録します。 完全な DAG 構造を保存する必要はありません。 どのコンポーネントのペアが直接接続されているかを知る必要があるだけです。 

この後、2 種類の答えの候補を計算します。 まず、各 SCC を個別に検討し、そのサイズを可能な答えとして採用します。 これは 1 か国のみを訪問することに相当します。 

次に、SCC cu → cv 間のすべての有向エッジについて、size[cu] + size[cv] の合計を考慮します。 これは、1 つの国から開始して、ちょうど 1 つの隣国に移動し、その後停止することに相当します。 

最後に、すべての単一 SCC サイズとすべての有効な SCC エッジ ペアの最大値を取得します。 

### なぜ効果があるのか

 有効な旅行プランには、最大 2 つの SCC の都市のみを含めることができます。 プランで SCC が 1 つだけ使用される場合、SCC サイズによって完全にキャプチャされます。 2 つの SCC を使用する場合は、一方の SCC からもう一方の SCC への進行方向の移動を可能にするエッジが少なくとも 1 つ存在する必要があります。 この遷移が発生すると、3 番目の SCC にアクセスするには別の遷移が必要になりますが、これは許可されません。 したがって、すべての有効な解決策は、少なくとも 1 つの有向エッジによって接続された 1 つの SCC または 1 つの SCC ペアに正確に対応し、これらを評価すると、実行可能なすべてのケースが網羅的にカバーされます。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def kosaraju(n, adj, radj):
    visited = [False] * n
    order = []

    def dfs1(u):
        visited[u] = True
        for v in adj[u]:
            if not visited[v]:
                dfs1(v)
        order.append(u)

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    comp = [-1] * n
    cid = 0

    def dfs2(u):
        comp[u] = cid
        for v in radj[u]:
            if comp[v] == -1:
                dfs2(v)

    for u in reversed(order):
        if comp[u] == -1:
            dfs2(u)
            cid += 1

    return comp, cid

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        adj = [[] for _ in range(n)]
        radj = [[] for _ in range(n)]

        edges = []
        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            radj[v].append(u)
            edges.append((u, v))

        comp, k = kosaraju(n, adj, radj)

        size = [0] * k
        for i in range(n):
            size[comp[i]] += 1

        ans = max(size)

        for u, v in edges:
            cu, cv = comp[u], comp[v]
            if cu != cv:
                ans = max(ans, size[cu] + size[cv])

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションはまず、Kosaraju の 2 パス DFS をサポートするために順方向および逆方向の隣接リストを構築します。 最初の DFS は終了順序を構築し、2 番目の DFS は反転したグラフにコンポーネント ID を割り当てます。 

SCC 圧縮後、サイズ配列は各国に属する都市の数を追跡します。 単一の国への訪問は常に許可されているため、最初の答えは最大の SCC に設定されます。 

次に、元のすべてのエッジを反復処理します。 SCC の境界を越える各エッジは、2 か国間の移動の可能性を表しています。 エンドポイントのコンポーネントのサイズを合計し、答えを更新します。 最大値を取ることは冪等であるため、同じ SCC ペア間の重複エッジまたは複数のエッジは正確さに影響しません。 

## 実用的な例

 単一のエッジ (1 → 2 → 3 → 1 および 4 → 5 → 6 → 4) とエッジ 3 → 4 で接続された 2 つのサイクルを持つグラフを考えます。 

SCC 圧縮後、サイズ 3 の C1 とサイズ 3 の C2 の 2 つのコンポーネントと、単一エッジ C1 → C2 ができます。 

| ステップ | アクション | C1サイズ | C2サイズ | ベストアンサー |
 | --- | --- | --- | --- | --- |
 | 1 | SCC を構築する | 3 | 3 | 3 |
 | 2 | エッジ C1 → C2 を処理 | 3 | 3 | 6 |

 これは、最良の戦略は、最初の国から 2 番目の国に横断してそこで停止することであることを示しています。 

次に、サイズ 2、5、および 4 の 3 つの SCC のチェーン (A → B → C) を考えます。 

| ステップ | アクション | 候補者 |
 | --- | --- | --- |
 | 1 | シングル SCC | 最大は 5 |
 | 2 | エッジ A → B | 7 |
 | 3 | エッジ B → C | 9 |

 直接的なエッジは存在せず、B を中間として使用すると 2 つの国の制限を超えるため、A → C は考慮しません。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | Kosaraju は線形時間で実行され、各エッジは 1 回処理されます。 
| スペース | O(n + m) | 隣接リスト、逆グラフ、および SCC 配列 |

 ## 特殊なケース

 エッジのないグラフは、それぞれサイズ 1 の n 個の個別の SCC を作成します。アルゴリズムはすべてのノードを独自のコンポーネントとして扱い、最良の答えが最大の SCC サイズ (1) になります。コンポーネント間のエッジが存在しないため、第 2 フェーズではこの値を超えて答えが更新されることはありません。 

完全に強接続されたグラフでは、すべてのノードが 1 つの SCC に属します。 SCC 分解により、サイズ n の単一コンポーネントが生成されます。 コンポーネント間にエッジがないため、エッジ処理ステップは何の役にも立ちません。 最終的な答えは n のままで、国が 1 つだけ存在するという事実と一致します。 

1 → 2 → 3 → 4 のようなチェーン構造では、SCC はすべて単一ノードになります。 考慮される有効なペアは (1,2)、(2,3)、および (3,4) だけです。 このアルゴリズムでは (1,3) や (1,4) は考慮されません。これにより、中間コンポーネントを通過する必要がある無効な複数国横断が正しく防止されます。
