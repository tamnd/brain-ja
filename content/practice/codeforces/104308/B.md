 ## 解決策
 ## 問題の理解

 各テスト ケースでは、同一のフォームに記入するプロセスが説明されており、各フォームでは複数の官庁から署名を集める必要があります。 すべてのオフィス i について、単一のフォームにそのオフィスからの ai 署名が必要です。 同時に、すべてのフォームにわたってそのオフィスから合計何件の署名を取得できるかについてのハードキャップバイがあります。 

オフィスの署名に加えて、最大 k 個の柔軟な署名を提供できる特別な情報源である上司がいます。 これらはいずれも、あらゆるオフィスから不足している必要な署名を置き換えることができます。 目標は、限られたオフィスの能力とこれらの普遍的な代替手段を組み合わせた場合に、何件の完全なフォームに記入できるかを決定することです。 

主な問題点は、フォームを追加するたびにすべてのオフィスのリソースが同時に消費されるため、実現可能性がオフィスごとに独立していないことです。 代わりに、各オフィス i からの総需要 x · ai が、そのオフィスから物理的に取得できるものと、制限された k 個の柔軟な署名を使用して置き換えることができるものを超えないような、フォーム x の最大数を見つけなければなりません。 

制約が十分に大きいため、フォームの構築を 1 つずつシミュレートするアプローチは不可能です。 テスト ケースあたり最大 10^5 のオフィスと最大 10^4 のテスト ケースでは、両方の値が大きい最悪のケースでは、O(n · 答え) 戦略はすぐに崩壊します。 

最も制約の多いオフィスに上司の署名を独自に割り当てるという単純で貪欲なアプローチも失敗します。 その理由は、フォームを追加するたびに赤字の配分がすべてのオフィスに移動するため、局所的な最適化では全体的な実現可能性が得られないためです。 

微妙な失敗例は、1 つのオフィスのキャパシティがわずかに不足しているのに、他の多くのオフィスに大きな余裕がある場合に発生します。 貪欲にオフィスごとに上司の署名を独立して割り当てると、早期に柔軟性を無駄にし、実際に実行可能なフォームよりも少ないフォームが可能であると誤って結論付ける可能性があります。 

## アプローチ

 この強引なアイデアは、x フォームを構築して実現可能性を検証することです。 固定 x の場合、各オフィス i は x · ai 署名を提供する必要がありますが、貢献できるのは最大 bi までです。 不足分は上司の署名によって補われます。 したがって、すべてのオフィスの合計赤字を計算し、それが最大でも k であるかどうかを確認します。 

このチェックは正しくて簡単ですが、0 から上のすべての x を試してみると、各チェックは O(n) となり、O(n · max 形式) になります。 最大形式は 10^9 まで大きくなる可能性があるため、このアプローチは実行できません。 

重要な観察は、実現可能性が x において単調であるということです。 x 個のフォームを完了できる場合は、すべての要件が直線的に下降するため、フォームの数をさらに少なくすることも可能です。 これにより、x を二分探索の探索空間として扱うことができます。 

固定 x の場合、実現可能性チェックはすべてのオフィスの合計を計算することになります: max(0, x · ai − bi)。 これは、上司からの交代が何人必要であるかを正確に表します。 この合計が k 以内であれば、x は実現可能です。 

これにより、問題が x に対する二分探索に変換され、各チェックに O(n) がかかり、効率的な解決策が得られます。

 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O(n · X) | お(1) | 遅すぎる |
 | 二分探索 + 実現可能性チェック | O(n log X) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、n、k、配列 a および b を読み取ります。 これらは、フォームごとの線形スケーリング要件とオフィスごとの制限を定義します。 
2. x 個のフォームを完了できるかどうかをチェックする関数 can(x) を定義します。 この関数は、必要な置換の総数を計算します。

各オフィス i について、必要な = x · ai を計算します。 必要量がbiを超える場合、超過分は世界的な赤字の一因となります。 
3. can(x) 内で、実行合計の赤字 = 0 を維持します。各 i について、赤字 += max(0, x · ai − bi) を計算します。 どこかの時点で赤字が k を超えた場合は、すでに実現可能性が失われているため、早期に中止することができます。 
4. x に対して二分探索を実行します。 検索範囲は 0 から始まり、安全な上限までです。 自然な限界は max(bi) + k ですが、より単純で安全な限界は 10^18 または min(bi // ai) から導出されます。 
5. 各中間点 mid について、can(mid) を評価します。 可能であれば、下限を上に移動します。 それ以外の場合は、上限を減らします。 
6. 二分探索が終了すると、最も適切な x が答えになります。 

### なぜ効果があるのか

 任意の固定 x について、実現可能性の条件は、すべてのオフィスの合計不足分を k でカバーできるかどうかにのみ依存します。 この不足分は、x とともに線形に増加する独立した非負の寄与の合計です。 したがって、x が実行可能であれば、より小さい値もすべて実行可能である必要があり、x が実行不可能であれば、より大きな値もすべて実行不可能のままです。 この単調な構造により、バイナリ検索の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        def can(x):
            need = 0
            for i in range(n):
                req = x * a[i]
                if req > b[i]:
                    need += req - b[i]
                    if need > k:
                        return False
            return need <= k

        lo, hi = 0, 10**18

        while lo < hi:
            mid = (lo + hi + 1) // 2
            if can(mid):
                lo = mid
            else:
                hi = mid - 1

        print(lo)

if __name__ == "__main__":
    solve()
```実装の中核は実現可能性機能です。 フォームの各候補数を決定論的なリソース要件チェックに変換します。 ループ内の早期停止条件は、不足分が既に k を超えた場合に不必要な合計を防ぐため重要です。 

二分探索では、上限と中間のバイアスが使用されるため、lo と hi が 1 異なる場合でも収束が正しく機能します。 このバイアスがないと、境界ケースでループが停止する可能性があります。

 ### 例 1

 n = 2、k = 3、a = [2, 1]、b = [3, 1] を考えてみましょう。 

さまざまな x 値の実現可能性をテストします。 

| × | Office 1 need | Office 2 need | Total deficit | 実現可能 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 | はい |

これは、赤字がオフィス全体でどのように蓄積するのか、そしてなぜオフィスごとの決定ではなくグローバルな合計が必要なのかを示しています。

| × | Deficits per office | Total deficit | 実現可能 |

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての bi が ai に対して極端に大きい場合に発生します。 この場合、上司の署名は必要なく、答えは純粋に min(bi // ai) によって決まります。 その限界まですべての x について不足がゼロのままであるため、アルゴリズムはこれを自然に処理します。 

k が非常に大きい場合、別のエッジケースが発生します。 その場合、制限因子は bi のみになり、実現可能性はすべての i について x · ai ≤ bi かどうかを確認することになります。 二分探索は引き続き機能しますが、オフィス間で最小比率近くに収束する可能性があります。 

最後の微妙なケースは、あるオフィスの bi が非常に小さいが、ai が非常に大きい場合です。 たとえば、ai = 10^9、bi = 1 です。このオフィスは、x ≥ 1 の実現可能性をすぐに支配しますが、アルゴリズムは、早期に拒否するのではなく、その寄与を赤字の合計に正しく集計するため、他のオフィスが余剰能力と上司の署名で補うことができます。
