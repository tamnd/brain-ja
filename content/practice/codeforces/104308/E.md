 ## 問題の理解

 整数が与えられます$m$そして配列$a$。 タスクはすべての約数を調べることです$d$の$m$、どうかを決定します$d$「安全」か「悪い」か。 除数$d$少なくとも 1 つの配列要素が存在する場合は不良とみなされます。$a_i$そのような$d$分割する$a_i$。 さもないと、$d$安全です。 目標は、約数が何個あるかを数えることです。$m$安全です。 

条件を確認する別の方法は、次の約数をフィルタリングすることです。$m$少なくとも 1 つの配列要素の約数として現れるものを除外することによって。 どの要素が除外をトリガーするかには興味がなく、それが少なくとも 1 回発生するかどうかにのみ関心があります。 

この制約により、私たちは慎重な因数分解推論を行うようになります。 の合計$n$到達できるすべてのテストケースにわたって$10^6$、 そして$m$までです$10^9$。 これにより、すべての約数をチェックしようとするソリューションは即座に除外されます。$m$すべての配列要素に対して直接。 すべてのペアを反復処理するだけでも遅すぎます。 

2 番目の微妙な問題は、同じ約数が$m$多くの配列要素に現れる可能性があります。 要素ごと、約数ごとに割り算を再計算する単純なアプローチでは、繰り返し無駄な作業が発生します。 

典型的な落とし穴は次のような場合に発生します。$m$は小さいですが、配列は大きいです。 たとえば、次の場合$m = 1$、唯一の約数は$1$、そして答えは、$a_i$等しい$0$または$1$割り切れるという意味で。 複数の約数を想定したり、特殊な構造を忘れたりする不注意な実装$m$数え間違えやすい。 

もう 1 つのエッジ ケースは、多くの配列要素が小さな約数の倍数である場合に発生します。$m$。 たとえば、次の場合$m = 12$そして配列には多くの倍数が含まれています$2$、次に除数$2$配列内に明示的に出現しない場合でも除外する必要があります。 ロジックは等式ではなく、割り算の伝播に依存します。 

## アプローチ

 ブルートフォースの観点は、自然に、すべての約数を列挙することから始まります。$m$。 以来$m \le 10^9$、約数の数は最大でも数千程度です。 各約数について$d$次に、配列全体をスキャンし、配列が存在するかどうかを確認します。$a_i$そのような$a_i \bmod d = 0$。 存在しない場合はカウントします。 

これは定義が直接チェックされるため機能します。 ただし、そのコストは、$O(n \cdot \tau(m))$テストケースごとに、$\tau(m)$は約数の数です。 と$n$まで$10^6$、 たとえ$\tau(m)$最悪の構成でも 1000 しかない場合、これは次のようになります。$10^9$テストケースごとの操作ですが、これは実行可能ではありません。 

重要な観察は、実際に関心があるのは、除数が何らかの要素を分割するかどうかではなく、少なくとも 1 つの要素を分割するかどうかであるということです。 これは、配列要素の除数セット内に表示される除数をマークすることと同じです。 クエリごとに除数を繰り返す代わりに、配列要素ごとに視点を逆転させます。$a_i$の約数をすべて列挙します。$a_i$そしてそれらを「悪い」としてマークします。 配列を処理した後は、次の約数を数えるだけで済みます。$m$マークされることはありませんでした。 

これにより、複雑さが逆転します。 今はそれぞれ$a_i$貢献する$O(\sqrt{a_i})$仕事、そしてそれ以来$\sum n \le 10^6$、合計作業量は管理可能なままです。 高速な除数の生成と効率的なメンバーシップのマーキングを確保する必要があります。 

また、両方とも$a_i$そして$m$までです$10^9$なので、平方根までの整数因数分解が可能です。

 ## アルゴリズムのチュートリアル

 私たちは、「不良」であることが確認された配列要素のすべての約数を保存するセットまたはハッシュ構造を維持します。 

1. 配列を読み取り、各要素のすべての約数を計算します。$a_i$。 各約数について$x$、それをハッシュセットに挿入します。 このセットは、少なくとも 1 つの配列要素を分割するすべての数値を表します。 このようにするのは、除算性が除外対象として重要な唯一のプロパティであるためです。 
2. すべての約数を計算します。$m$。 これは以下で行われます$O(\sqrt{m})$までテストすることで$\sqrt{m}$そしてペアリング要因。 各約数はリストにまとめられます。 
3. 約数を反復処理します。$m$。 各約数について$d$、どうかを確認してください$d$「悪い」セットに存在します。 存在しない場合は、配列要素が次の要素で割り切れないことを意味します。$d$, だからそれを数えます。 
4. 最終的なカウントを出力します。 

正しさは、セット内に除数が現れるたびに、少なくとも 1 つの配列要素がその除数で割り切れることが保証されるという事実に依存します。 したがって、除外は正確です。つまり、約数はありません。$m$本当に一部を分割しない限り削除されます$a_i$。 

### なぜ効果があるのか

 中心的な不変条件は、配列の処理後、セットには少なくとも 1 つの配列要素を分割する整数のセットが正確に含まれるということです。 すべての約数を明示的に列挙しているため、これは近似ではありません。$a_i$なので、約数が見逃されることはありません。 

この不変条件が成立すると、最後のステップは純粋に次の約数に対するフィルターになります。$m$。 除数$d \mid m$は、セット内にない場合に限り、答えで有効です。 この条件は問題のステートメントと正確に一致するため、カウントは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_divisors(x):
    divs = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            divs.append(i)
            if i * i != x:
                divs.append(x // i)
        i += 1
    return divs

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    bad = set()

    for v in a:
        i = 1
        while i * i <= v:
            if v % i == 0:
                bad.add(i)
                bad.add(v // i)
            i += 1

    divs_m = get_divisors(m)

    ans = 0
    for d in divs_m:
        if d not in bad:
            ans += 1

    print(ans)
```このソリューションでは、まず、配列要素に現れるすべての約数のグローバル セットを構築します。 これは重要な圧縮ステップです。どの要素が除数をトリガーするかを追跡するのではなく、存在だけを考慮します。 

のヘルパー関数$m$すべての約数をきれいに列挙します$\sqrt{m}$、制約を考慮するとこれで十分です$m \le 10^9$。 

最後のループは、次の約数に対する直接フィルターです。$m$。 追加の状態は必要ありません。 

実装の微妙な詳細は、両方とも$i$そして$v // i$の場合に挿入する必要があります$i \mid v$そうしないと、約数の半分が失われ、フィルタリングが不正確になります。 

## 実用的な例

 小さな例を考えてみましょう。$m = 12$そして$a = [3, 10]$。 

3 の約数が寄与する$\{1, 3\}$、および 10 の約数が寄与します$\{1, 2, 5, 10\}$。 悪い約数の結合は次のようになります。$\{1, 2, 3, 5, 10\}$。 

12の約数は、$\{1, 2, 3, 4, 6, 12\}$。 

| ステップ | a[i] の約数 | ステップ | 後の不正なセット
 | --- | --- | --- |
 | アフター3 | 1、3 | {1、3} |
 | 10時以降 | 1、2、5、10 | {1、2、3、5、10} |

 12 の約数を確認すると、4、6、12 だけが不良セットに含まれていないため、答えは 3 になります。 

このトレースは、アルゴリズムが周波数には依存せず、存在のみに依存していることを示しています。これはまさに必須のプロパティです。 

次に、次の 2 番目のケースを考えてみましょう。$m = 6$そして$a = [4, 9]$。 

4の約数は、$\{1, 2, 4\}$、9 の約数は次のようになります。$\{1, 3, 9\}$。 悪いセットは次のようになります$\{1, 2, 3, 4, 9\}$。 

6の約数は、$\{1, 2, 3, 6\}$。 悪いセットに含まれていないのは 6 だけです。 

| ステップ | a[i] の約数 | ステップ | 後の不正なセット

 | アフター4 | 1、2、4 | {1、2、4} |
 | 9時以降 | 1、3、9 | {1、2、3、4、9} |

 この結果は、除数が配列要素として明示的に出現しない場合でも、倍数が存在するとすぐに除外されることを確認します。

 ## 特殊なケース

 いつ$m = 1$、唯一の除数は 1 です。配列要素が 1 で割り切れる場合 (常に true)、不良セットには直ちに 1 が含まれます。 最後のループで単一の値がチェックされ、セット内にその値が存在することが検出されるため、アルゴリズムは正しく 0 を返します。 

すべての配列要素が同一で等しい場合$m$、のすべての約数$m$のすべての約数が原因で、不良セットに挿入されます。$m$も分割します$m$自体。 したがって、最後のループではすべての候補が除外され、0 が生成されます。 

配列要素が関係のない大きな素数の場合$m$、悪いセットには、ほとんどの場合、1 と素数自体のみが含まれます。 約数$m$複合的で関連性のないものはそのまま残るため、答えは次の約数の数と等しくなります。$m$1 との重複を差し引いたもの。
