 ## 解決策
 ## 問題の理解

 アイテムの垂直方向のスタックが与えられ、各アイテムに色が付けられます。 スタックの最上位は位置 1 で、下に行くにつれて位置が増加します。 一連のクエリがこのスタック上で実行されます。 各クエリは色を指定し、現在のスタック内でその色の最も高い出現位置を特定し、その位置を先頭から出力し、その特定の項目をスタックの最上位に移動するように要求します。 

重要な問題は、スタックが静的ではないことです。 クエリが実行されるたびに、1 つの要素が中間のどこかから抽出され、先頭に再挿入されるため、構造が変わります。 これは、将来のポジションが以前のすべての操作に依存することを意味します。 

この制約では、テスト ケースあたり最大 100,000 個の要素と 100,000 個のクエリが許可され、テスト ケース全体の合計も 100,000 によって制限されます。 これにより、クエリごとにスタックをスキャンするソリューションは即座に除外されます。 クエリごとの線形スキャンは O(nq) となり、最悪の場合は 10¹⁰ の操作となり、1 秒での実現可能性をはるかに超えます。 

主な課題は、現在の最上位の色の検索と、その位置を最上位に更新するという 2 つの操作に効率よく繰り返し答えることです。 

素朴だが微妙な失敗例は、移動後の再計算に起因します。 たとえば、色を見つけるために常に配列を上からスキャンすると、1 つの要素だけが位置を変更したとしても、同じプレフィックスを繰り返し走査することになります。 移動後に初期位置を更新せずに初期位置のみを追跡すると、別の失敗が発生します。 要素が再配置されると、インデックスが古くなり、不正確な答えが発生します。 

## アプローチ

 ブルートフォースアプローチは簡単です。 クエリごとに、必要な色の最初の要素が見つかるまでスタックを上から下にスキャンします。 そのインデックスを印刷し、物理的に取り外して前面に挿入します。 これはプロセスを直接シミュレートするため、これは正しいです。 

ただし、各クエリでは最大 n 個の要素のスキャンが必要になる場合があり、先頭へのリストの挿入にも O(n) のコストがかかります。 q クエリを超えると、これは O(nq) になり、105 スケールの入力には遅すぎます。 

重要な観察は、実際にはすべての要素の正確な位置を常に気にしているわけではないということです。 最近の動きによって引き起こされた相対的な順序のみを考慮します。 同じ色の要素は、「現在どの出現が最も高いか」という観点から独立して動作します。 私たちは、色ごとに、その候補が現在の順序のどこに位置するかを追跡し、それを効率的に更新したいと考えています。 

これを実現する標準的な方法は、仮想順序での現在の深さを表す動的な「時間ラベル」を各要素に割り当てることです。ラベルが小さいほど、上部に近いことを意味します。 要素が一番上に移動すると、新しい最小のラベルが付けられます。 高速アクセスを維持するために、最小 (最上位) の色をすばやく取得できる方法で、その出現のすべての位置を追跡する構造を色ごとに保存します。 

スタックを明示的にシミュレートする代わりに、グローバルに減少するタイムスタンプを維持します。 要素を先頭に移動するたびに、以前のタイムスタンプよりも大きな新しいタイムスタンプを割り当て、このタイムスタンプによる順序に基づいてクエリを実行します。 ただし、現在のスタック内の実際の位置も出力する必要があるため、タイムスタンプの順序から最終位置までのマッピングを維持する必要があります。 より直接的で単純な解釈では、座標圧縮を完全に回避します。遅延更新で一連の位置を使用してプロセスをシミュレートしますが、色ごとに現在の位置のソートされた構造を維持します。

クリーンで受け入れられているアプローチは、各色をデックまたは現在のインデックスの順序付けされたセットにマッピングする辞書を維持することです。また、「アクティブな位置」のグローバルな順序付けされた構造も維持します。 要素が移動されると、その古い位置が削除され、現在のすべての位置より小さい新しい仮想位置が挿入されます。 ただし、物理インデックスが必要であるため、代わりに、挿入された要素の移動オフセットを持つフェンウィック ツリーを使用してシミュレートします。 

より洗練された標準的な解決策は、色ごとの出現の相対的な順序を知る必要があるだけで、一連の「生きている位置」とシフトの BIT を維持できることを認識することです。 ただし、最も効率的で一般的な CF ソリューションは、色ごとの位置のセットと、ある位置の上に移動された要素の数を追跡するグローバル BIT を使用します。 

配列 pos[i] を要素 i の現在位置として定義します。 特定のインデックスの前に要素が何回上位に移動されたかを示す位置全体のフェンウィック ツリーを維持し、シフトを効果的に圧縮します。 要素を先頭に移動するたびに、BIT 内の古い位置をデクリメントし、現在のグローバル フロント カウンタで新しい位置を割り当てます。 

これにより、各クエリが O(log n) 操作に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最適 (フェンウィック / 位置追跡) | O((n+q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 スタックを動的インデックス空間に埋め込まれているものとして扱い、すべてを明示的に移動することなく新しい「上位位置」を挿入できるようにします。 

1. 各初期要素に大きな座標空間内の位置を割り当てます (たとえば、q+1 から q+n まで)。初期順序を維持します。 これにより、将来の挿入のための上にスペースが確保されます。 
2. これらのポジション上にフェンウィック ツリーを維持し、最初にすべてのポジションを占有済みとしてマークします。 
3. 色ごとに、その色が表示される位置の辞書または順序付けされたセットを維持します。 これにより、最上位の出現に対応する、その色の最小の現在位置を迅速に取得できます。 
4. 色 d の各クエリについて、d のセット内の最小位置 p を取得します。 これは、その色の現在の最上位の出現です。 
5. 上位からのランクを出力するには、位置 p より上にアクティブな要素がいくつあるかをフェンウィック ツリーにクエリします。 これにより、現在の 1 から始まるインデックスが得られます。 
6. 位置 p は移動されるため、フェンウィック ツリーとそのカラー セットから削除します。 
7. 通常はグローバル ポインタをデクリメントすることにより、既存のすべての位置よりも小さい新しい位置 new_p を割り当てます。 
8. new_p をフェンウィック ツリーと d のカラー セットに挿入します。 

重要なアイデアは、フェンウィック ツリーが特定の位置の上に現在いくつの要素があるかをエンコードし、色ごとの構造が現在どの要素が一番上に表示されているかを示すということです。 

これが機能する理由は、一貫した順序の不変条件を維持することにあります。フェンウィック ツリーは常に、割り当てられた座標によって順序付けされた現在の要素セットを表し、それらの座標はスタック順序を厳密に反映します。 すべての移動では、要素に厳密に最小の座標を指定することによって 1 つの要素のみを先頭に再配置し、その要素がその色のすべてのアクティブな要素の中で最初の要素になるようにします。 明示的に移動しない限り、他の要素はより小さい座標を取得しないため、相対的な順序の一貫性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 2)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        c = list(map(int, input().split()))
        d = list(map(int, input().split()))

        size = n + q + 5
        ft = Fenwick(size)

        pos = {}
        cur = q + 2

        for i, col in enumerate(c, start=1):
            ft.add(cur + i, 1)
            pos.setdefault(col, set()).add(cur + i)

        for x in d:
            p = min(pos[x])

            ans = ft.sum(p - 1) + 1
            print(ans)

            ft.add(p, -1)
            pos[x].remove(p)

            cur -= 1
            newp = cur
            ft.add(newp, 1)
            pos[x].add(newp)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、人工座標空間上の動的なプレフィックス カウンタとして使用されます。 各位置は、アクティブまたは非アクティブのいずれかの点として扱われます。 指定された位置の上にアクティブな位置がいくつあるかをクエリすることは、まさにプレフィックス合計クエリです。 

の`pos`辞書はすべての現在位置を色ごとにグループ化し、`min(pos[x])`より小さい割り当てられた座標はより高いスタック配置に対応するため、最上位の出現が得られます。 

変数`cur`継続的に下方に移動して、新たな「トップ」の位置を割り当てます。 これにより衝突が回避され、新しく移動された要素が常に最上位になることが保証されます。 

微妙な点は、配列を物理的に並べ替えることは決してないということです。 すべての動きは純粋に座標の再割り当てによって表現されます。

 | --- | --- | --- | --- | --- |
 | 1 | 2 | 位置 2 の最初の 2 | 2 | 先頭に移動 |

 | 3 | 2 | 新しいトップで 2 を更新 | 1 | 先頭に移動 |

次に、2 番目のクエリは、色 1 の最初の出現を見つけて、それを他のすべての上に移動します。これは、配列を物理的にシフトしていないにもかかわらず、相対的な順序がグローバルに変化することを示しています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict
    import sys

    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 2)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i

        def sum(self, i):
            s = 0
            while i > 0:
                s += self.bit[i]
                i -= i & -i
            return s

    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            n, q = map(int, input().split())
            c = list(map(int, input().split()))
            d = list(map(int, input().split()))

            size = n + q + 5
            ft = Fenwick(size)
            pos = {}
            cur = q + 2

            for i, col in enumerate(c, start=1):
                ft.add(cur + i, 1)

                pos[x].remove(p)
                cur -= 1
                newp = cur

                pos[x].add(newp)

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 同じ色のスタックの場合、すべてのクエリは常に同じセットをターゲットとします。 アルゴリズムは、そのセット内の最小位置を繰り返し選択し、それを削除し、それを先頭に再挿入します。 すべての要素が色を共有しているにもかかわらず、位置セットにより、現在の最上位の正しい出現が常に選択されることが保証されます。 各移動の後、フェンウィック ツリーはシフトを正しく反映するため、出力は一貫して 1 のままになります。 

厳密に交互のカラー パターンの場合、各クエリは異なるセット間で切り替わります。 移動するたびに新しい最小座標が挿入されるため、以前に移動された要素がアクセスの逆順で先頭に蓄積されます。 順序付けは配列インデックスではなく座標でエンコードされるため、アルゴリズムはこれを自然に処理し、明示的なシフトは必要ありません。 

単一クエリの場合、構造的な複雑さは発生しません。 ランクを一度計算し、削除して再挿入するだけで、フェンウィック ツリーの一貫性が保たれます。
