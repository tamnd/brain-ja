 ## 解決策
 ## 問題の理解

 複数のテストケースが与えられます。 各テスト ケースには、Roshid が入力したいテキストを表す単一の小文字文字列が含まれています。 しかし、彼のキーボードにはハードウェア障害が発生しており、標準のキーボード レイアウトの最下行に相当する特定の文字グループが機能しなくなりました。 入力文字列にこれらの壊れた文字が現れると、その文字は単に入力できないため、最終出力には決して現れません。 

タスクは、テスト ケースごとにこのフィルタリング プロセスを個別にシミュレートし、使用できない文字をすべて削除した後、結果の文字列を出力することです。 

すべてのテスト ケースの合計長が最大 1e6 であるという制約は、すべてのソリューションが入力全体にわたって線形時間で実行される必要があることを意味します。 文字ごとに一定の作業のみを行う限り、テスト ケースごとに O(n) のアプローチでも問題ありません。 文字列の連結の繰り返しや、削除ごとのスキャンの繰り返しなど、二次的なものはすべて合格しません。 

微妙な特殊ケースとして、文字列全体が壊れた文字のみで構成されている場合があります。 たとえば、入力が「mcc」のような文字列であり、すべての文字が使用できない場合、正しい出力は空行になります。 もう 1 つのエッジ ケースは、「mist」など、一部の文字のみが削除される混合文字列です。この場合、壊れた文字のみがフィルタリングされ、残りの文字は順序が正確に保持されます。 

## アプローチ

 この問題を考える最も直接的な方法は、キーボードの動作を文字通りシミュレートすることです。 各テスト ケースでは、文字列を左から右にスキャンし、各文字が入力できるかどうかを判断します。 可能であれば結果に追加し、そうでない場合はスキップします。 

単純なアプローチでは、置換操作や複数のパスでのフィルタリングを使用して、文字列から文字を繰り返し削除しようとする可能性があります。 たとえば、壊れた文字をそれぞれスキャンして、文字列からグローバルに消去することができます。 これは概念的には機能しますが、各グローバル置換は O(n) であり、複数の文字に対してこれを実行すると、フル スキャンが繰り返されることになります。 最悪の場合、これは実装オーバーヘッドに応じてテスト ケースあたり O(26 · n) またはさらに悪化しますが、厳しい制約の下では不必要であり、危険です。 

重要な観察は、セットまたはブール検索テーブルのメンバーシップ テストを使用して、各文字を一定時間で独立してチェックできることです。 これにより、プロセス全体がテスト ケースごとに 1 つの線形パスに削減され、有効な文字のみが蓄積されます。 

フィルタリングは文字ごとに独立しているため、ブルート フォースは機能しますが、文字列を繰り返し再構築すると拡張できなくなります。 最適化されたアプローチにより、すべてがストリーミング フィルターに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース (繰り返し除去) | テストごとに O(26 · n) 以上 | O(n) | 遅すぎる |
 | 最適 (シングルパスフィルタリング) | O(n) 合計 | O(1) 補助 | 承認済み |

 ## アルゴリズムのチュートリアル

 壊れたキーのセットを、ロシッドのキーボードで機能しない文字として定義します。 次に、各テスト ケースを個別に処理します。 

### ステップ

 1. すべての壊れた文字を含むセットを事前定義します。 

これにより、文字列をスキャンする際に一定時間のメンバーシップ チェックが可能になります。 
2. テスト ケースごとに、空の出力バッファを初期化します。 

ループ内での連結では二次的な動作が発生するため、文字列の連結を繰り返す代わりに文字のリストを使用します。 
3. 入力文字列内の各文字を繰り返し処理します。 

各文字について、壊れたセットに含まれているかどうかを確認します。 
4. 文字が壊れていない場合は、それを出力バッファに追加します。 

壊れている場合は、完全にスキップしてください。 
5. 文字列全体を処理した後、バッファを最終文字列に結合して出力します。 

### なぜ効果があるのか

スキャン中のどの時点でも、出力バッファには、それまでに検出された壊れていない文字が正確に含まれています。 各文字は独立して処理され、再検討されることはないため、有効な文字の相対的な順序は保持されます。 将来の決定は、壊れたセットのメンバーシップを超えた以前のフィルタリングに依存しないため、貪欲なスキャンで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    broken = set("zxcvbnm")  # broken keyboard row

    t = int(input())
    for _ in range(t):
        s = input().strip()
        res = []

        for ch in s:
            if ch not in broken:
                res.append(ch)

        print("".join(res))

if __name__ == "__main__":
    solve()
```このソリューションでは、壊れた文字の固定セットを一度構築し、それをすべてのテスト ケースに使用します。 各文字列は 1 文字ずつ処理され、有効な文字がリストに蓄積されます。 最後の結合操作は文字列サイズにおいて線形です。 

重要な実装の詳細は、文字列の連結を繰り返すのではなく、リストを使用することです。 Python では文字列は不変であるため、繰り返し`+=`パフォーマンスが大幅に低下する可能性があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

 ## 特殊なケース

 重要なケースの 1 つは、文字列全体が壊れた文字で構成されている場合です。`mcc`。 アルゴリズムは各文字を処理し、壊れたセット内で各文字を見つけて、バッファーには何も追加しません。 結果は空の文字列ですが、空行として出力されるはずです。 

もう 1 つのケースは、文字列に壊れた文字が含まれていない場合です。 例えば、`abcdef`文字ごとにスキャンされ、すべてのメンバーシップ テストが失敗し、すべての文字が追加されます。 出力は入力と正確に一致します。 

3 番目のケースは、有効な文字と無効な文字が交互に配置されている場合です。 例えば、`mist`のみを削除します`m`、出発`ist`。 各文字は周囲のコンテキストに依存せずに独立して処理されるため、アルゴリズムはこれをきれいに処理します。
