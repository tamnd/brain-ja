 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースには、偶数長の配列があります。 すべての要素が正確に 1 つのペアに属するように、配列を素のペアに分割する必要があります。 各ペアについて、答えへの寄与は、そのペア内の 2 つの値のうち大きい方になります。 目標は、これらのペアごとの最大値の合計を最小化するペアリング戦略を選択することです。 

したがって、タスクは単一の最適な一致を見つけることではなく、大きな要素によって多くのペアのコストが不必要に膨らまないよう、値をグループ化する方法を決定することです。 

制約により、最大で次のことが許可されます。$10^5$すべてのテスト ケースにわたる合計要素 (最大値)$10^9$。 これにより、すべてのペアリングを試行するアプローチは即座に除外されます。 分割方法の数$n$要素をペアにすると超指数関数的に増加するため、$n = 20$ブルートフォースはすでに実行不可能です。 有効なソリューションは大まかに実行する必要があります$O(n \log n)$ソートしているため、テストケースごとにそれ以上の効果があります$10^5$要素はすでに Python で快適に高速な限界に近づいています。 

いくつかの危険な状況については、覚えておく価値があります。 

すべての要素が等しい場合、すべてのペアのコストは同じであるため、正しいアルゴリズムはその不変性を維持する必要があります。 

配列がすでに降順でソートされている場合、最初と 2 番目、3 番目と 4 番目のペアのような単純な貪欲な方法は実際には最適ですが、最初と最後のペアは構造を通じて間接的に関与するすべてのペアに最大の要素を強制するため悲惨です。 

不正な貪欲戦略による微妙な失敗例は、値がインターリーブされる場合に発生します。たとえば、`[1, 100, 2, 99]`。 極端なペアリング`(1,100)`そして`(2,99)`収量コスト`100 + 99 = 199`、最適なペアリングをしながら`(1,2)`そして`(99,100)`収量`2 + 100 = 102`。 順序を明示的に制御しない戦略では、この構造を見逃す傾向があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 可能な配列のあらゆる組み合わせを試します。$n/2$ペアを作成し、各構成の最大値の合計を計算し、最小値を取得します。 これは、有効な構造ごとに目的を直接評価するため、正しいです。 問題は、完全一致の数が$n$要素は$(n-1)!!$、小さい段階ですでに巨大になります$n$。 のために$n = 20$、これで終わりです$10^7$可能性とそれぞれの評価コスト$O(n)$, したがって、このアプローチはすぐに崩壊します。 

重要な観察は、ペアのコストは大きい方の要素のみに依存するということです。 これは、すべての要素がそのペアの「勝者」として貢献するか、より大きなパートナーの下に隠れることを意味します。 合計を最小限に抑えるために、大きな要素の使用頻度をできるだけ低く抑えたいと考えています。 これは、大きな要素とできるだけ小さな要素を組み合わせることを示唆していますが、この直感は全体的に一貫している必要があります。 

配列がソートされると、ローカル構造について推論できるようになります。 任意の 4 つの要素を検討してください$a \le b \le c \le d$。 それらを次のようにペアにする場合$(a, d)$そして$(b, c)$、費用は$d + c$。 代わりにそれらを次のようにペアリングすると、$(a, b)$そして$(c, d)$、費用は$b + d$。 以来$c \ge b$、2 番目の構成はコストが増加することはなく、値が等しい場合を除き、厳密にはより優れています。 この交換議論は、小さい要素と大きい要素の間の交差が有害であり、ソート後に最適な構造が隣接するペアに崩壊することを示しています。 

したがって、解決策は配列をソートし、連続する要素をペアにすることになります。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 最適 (ソート + 貪欲なペアリング) | O(n log n) | O(1) または O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 現在のテスト ケースの配列を読み取ります。 問題の構造は各テスト ケース内に完全に含まれているため、ケース間の相互作用は存在しません。 
2. 配列を降順でない順に並べ替えます。 このステップにより、要素の自然な順序が明らかになり、最適なペアの形成について局所的に推論できるようになります。 
3. ソートされた配列を 2 ステップで走査し、連続する要素をペアにします。 各ペアは次のように形成されます`(a[i], a[i+1])`。 このペアリングにより、すべての小さな要素が可能な限り最も近い大きな要素と一致することが保証され、複数のペアで大きな要素が無駄になることがなくなります。 
4. 各ペアについて、2 番目の要素 (並べ替え後の大きい方の要素) を答えに追加します。 配列はソートされているので、`a[i+1]`はペアの最大値であることが保証されます。 
5. テストケースの累積合計を出力します。 

### なぜ効果があるのか

 並べ替え後、小さな要素が非常に大きな要素とペアになり、別のペアに中間値が含まれる「交差」構造を導入するペアリングは、エンドポイントを交換することで局所的に改善できます。 Each swap reduces or preserves total cost because it prevents a larger element from being overshadowed unnecessarily. Repeated application of this exchange eliminates all non-adjacent pairings, leaving only consecutive pairing as a stable configuration. この構造により、偶数の位置にある要素を除くすべての要素が最大値として 1 回だけ寄与することが保証され、これらの最大値はペアリングの段階で利用可能な最小の選択肢となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()
        ans = 0
        for i in range(1, n, 2):
            ans += a[i]
        out.append(str(ans))
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、ソートとリニア スキャンを中心に構成されています。 重要な実装の詳細は、ソート後にインデックス 1 から始まる 2 つおきの要素を合計することです。これは、これらの要素が各最適なペアの最大値として機能するためです。 合計入力サイズが次の値に達する可能性があるため、高速 I/O を使用する必要があります。$10^5$テストケース全体の整数。 

## 実用的な例

 ### 例 1

 入力:`[1, 100, 2, 99]`ソート後の配列は次のようになります`[1, 2, 99, 100]`。 

| ステップ | 配列 | ペアが形成されました | ペアのコスト | 累計額 |
 | --- | --- | --- | --- | --- |
 | 1 | [1、2、99、100] | (1,2) | 2 | 2 |
 | 2 | [1、2、99、100] | (99,100) | 100 | 102 |

 合計は 102 で、隣接するペアにより、異なるペア間で大きな値が無駄になることが回避されることがわかります。 

### 例 2

 入力:`[5, 5, 5, 5, 1, 1]`ソートされた配列:`[1, 1, 5, 5, 5, 5]`| ステップ | 配列 | ペアが形成されました | ペアのコスト | 累計額 |
 | --- | --- | --- | --- | --- |
 | 1 | [1、1、5、5、5、5] | (1,1) | 1 | 1 |
 | 2 | [1、1、5、5、5、5] | (5,5) | 5 | 6 |
 | 3 | [1、1、5、5、5、5] | (5,5) | 5 | 11 |

 ペアを交換しても両方の大きな要素を同時に減らすことができないため、再配置すると同じかそれ以上の合計が生成されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n)$テストケースごと | 並べ替えが優先され、ペアリングは線形です。 
| スペース |$O(1)$追加（入力を除く） | 蓄積とインプレースソートのみが使用されます。 

制約により、最大で次のことが許可されます。$10^5$要素の合計は 1 つであるため、テスト ケースごとに 1 回の並べ替えは十分に制限内にあります。 リニア スキャンはソートに比べて無視できます。 

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()
        ans = 0
        for i in range(1, n, 2):
            ans += a[i]
        out.append(str(ans))
    print("\n".join(out))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        from contextlib import redirect_stdout
        import io as sio
        out = sio.StringIO()
        with redirect_stdout(out):
            solve()
        return out.getvalue().strip()
    finally:
        sys.stdin = old_stdin

# sample-like test
assert run("""1
4
1 100 2 99
""") == "102"

# minimum case
assert run("""1
2
10 1
""") == "10"

# all equal
assert run("""1
6
5 5 5 5 5 5
""") == "15"

# already sorted
assert run("""1
4
1 2 3 4
""") == "6"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 4 1 100 2 99 | 102 | インターリーブは正しいソート戦略を強制します。 
| 1 2 10 1 | 10 | 有効な最小のケース |
 | 1 6 オール 5 | 15 | 対称性と等価安定性 |

 ## 特殊なケース

 次のようなインターリーブ入力の場合`[1, 100, 2, 99]`、アルゴリズムは次のように並べ替えます`[1, 2, 99, 100]`そしてペアを形成します`(1,2)`そして`(99,100)`。 2 番目の要素`2`そして`100`ソートせずにペアを作成しようとすると、少なくとも 1 つの大きな要素をより高コストの位置にインフレートする交差ペアが生成されます。 

次のような重複の多い入力の場合`[5, 5, 5, 5, 1, 1]`、ソートにより、ペアを交換しても結果が変わらない安定した隣接関係が生成されます。 このアルゴリズムは一貫して各ペアの 1 つのコピーを最大値として割り当てます。また、大きな要素はすべて等しいため、再配置しても合計を減らすことはできません。
