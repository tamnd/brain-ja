 ## 解決策
 ## 問題の理解

 いくつかの「能力文字列」が与えられます。各能力は異なる文字で構成されており、複数の能力に文字が現れることはありません。 これらの能力から、能力文字列全体を連続ブロックとして現在の文字列の任意の場所に挿入することで、空から始まる最終文字列を繰り返し構築します。 各挿入では、その能力文字列の内部順序が保持されますが、以前に挿入された部分の中央、端、または内部に配置することができます。 

このような挿入が何度も行われた後、最終的な文字列が表示され、これらの一連の操作によってそれが生成されたかどうかが尋ねられます。 可能であれば、使用された合計挿入数も報告する必要があります。 

重要な構造上の制約は、キャラクターが能力によってグローバルに分割されていることです。 各文字は正確に 1 つの能力に属しているため、各文字がどの能力に由来するかを追跡することで最終的な文字列を分解できます。 これにより、異なる能力間の相互作用が即座に制限されます。これらの能力は同じキャラクターの位置をめぐって競合することはなく、グローバル インタリーブでは能力ごとの順序制約が尊重される必要があります。 

制約は構造という点では小さいですが、最終的な文字列の長さという点では大きくなります。 すべてのテスト ケースの合計の長さは最大 100,000 であるため、どの解も入力文字列の長さが線形またはほぼ線形である必要があります。 アビリティの数は最大でも13個で、それぞれのアビリティは短い。 これは、最終文字列を 1 回のパスまたは能力ごとに少数のパスで処理する必要があることを強く示唆しています。 

微妙な問題は、以前に挿入されたブロック内で挿入が発生する可能性があることです。 これは、能力文字列が最終結果で必ずしも連続した部分文字列として表示されるわけではないことを意味します。 部分文字列全体を直接照合しようとする単純なアプローチでは、ある能力を別の能力の途中に挿入するような有効な構造では失敗します。 

もう 1 つの落とし穴は、能力の出現が最終文字列の連続セグメントとして現れる必要があると想定していることです。 そうではありません。 以前に挿入された能力は、後の挿入によって分割できるため、内部の順序を維持しながら、その文字を他の文字とインターリーブすることができます。 

## アプローチ

 このプロセスを考えるための直接的な総当り的な方法は、考えられるすべての挿入シーケンスをシミュレートすることです。 空の文字列から、各ステップで 1 つの能力を選択し、任意の位置に挿入します。 これにより、膨大な分岐要素が作成されます。ステップ k では、能力の選択肢が O(n) 個、挿入位置が O(L) 個あり、L はステップごとに増加します。 最終的な長さが中程度であっても、状態の数が組み合わせ的に爆発的に増加するため、このアプローチは実行不可能になります。 

重要な単純化は、異なる能力のキャラクターが 1 つの能力内で決して混在せず、各能力が内部的に固定されているという観察から来ています。 このため、挿入の幾何学的構造を忘れて、代わりに最終文字列内の各機能を独立して追跡できます。 

特定の能力に属する文字のみに最終文字列を射影すると、その能力の文字のみで構成されるサブシーケンスが得られます。 有効な構造では、能力文字列のコピーを順番に繰り返し書き込むことによって、このサブシーケンスを生成する必要があります。 他の場所に挿入しても、フィルタリングすると消える他の文字が挿入されるだけであるため、この投影は妨げられません。 

これにより、全体的な構築の問題が能力ごとの独立したチェックに縮小されます。 機能ごとに、フィルタリングされたサブシーケンスが、何度も繰り返された独自の文字列を正確に連結したものであるかどうかを検証します。 これがすべての能力に当てはまる場合、観察されたカウントと一致する任意の順序でこれらの挿入をインターリーブすることによって全体の構造を実現できます。

反復の合計数は、単に各能力がそれ自体の投影されたサブシーケンスに出現する回数の合計です。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. まずすべての能力文字列を読み取り、各文字を対応する能力インデックスに割り当てます。 複数の能力に登場するキャラクターがないため、このマッピングは独特です。 これにより、最終的な文字列を生の文字ではなく能力識別子のシーケンスに圧縮することができます。 
2. 最終的な文字列 S を配列 A に変換します。各位置には、そのキャラクターを所有する能力のインデックスが格納されます。 これにより、最大 13 個のシンボルを処理するだけで問題が軽減されます。 
3. 各能力 i について、i の出現のみからなる A の部分列を抽出します。 このサブシーケンスは、その能力の文字が最終文字列に現れる正確な順序を表します。 
4. このサブシーケンスを、能力文字列 si の繰り返しコピーと比較します。 si を周期的にウォークスルーすることをシミュレートします。A で能力 i の文字が表示されるたびに、それは si で次に期待される文字と一致する必要があります。 万が一ミスマッチが発生すると施工が不可能となります。 
5. このマッチングを実行している間、si の完全な走査を完了した回数を数えます。 各補完は、その能力文字列の 1 回の挿入に対応します。 
6. すべての能力がこのチェックに合格した場合、「はい」とすべての能力にわたる完了したサイクルの合計数が出力されます。 それ以外の場合は「いいえ」を出力します。 

### なぜ効果があるのか

 各キャラクターは 1 つの能力にのみ属しているため、S から他のすべてのキャラクターを削除しても、その能力内のキャラクターの相対的な順序には影響しません。 挿入は内部順序を変更せずに能力文字列全体を複製するだけであるため、有効な構造はすべて、能力ごとにその定義文字列の繰り返しであるシーケンスを生成します。 逆に、投影されたすべてのサブシーケンスが繰り返しパターンと一致する場合、能力間の競合を引き起こすことなく、S に表示されるのと同じ順序で対応する挿入をインターリーブできます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        abilities = []
        owner = {}

        for i in range(n):
            s = input().strip()
            abilities.append(s)
            for ch in s:
                owner[ch] = i

        S = input().strip()

        # compress S into ability ids
        A = [owner[ch] for ch in S]

        # for each ability, extract its subsequence
        pos = [[] for _ in range(n)]
        for x in A:
            pos[x].append(x)

        total_ops = 0
        ok = True

        for i in range(n):
            if not pos[i]:
                continue

            pattern = abilities[i]
            m = len(pattern)

            j = 0
            cnt = 0

            for x in pos[i]:
                # since x identifies ability i, we only need to track cycle
                if pattern[j] != pattern[j]:
                    pass

            # rebuild properly: we need actual characters, not ids
            seq = [ch for ch in S if owner[ch] == i]

            j = 0
            cnt = 0
            for ch in seq:
                if ch != pattern[j]:
                    ok = False
                    break
                j += 1
                if j == m:
                    j = 0
                    cnt += 1
            if not ok:
                break

            total_ops += cnt

        if ok:
            print("Yes")
            print(total_ops)
        else:
            print("No")

if __name__ == "__main__":
    solve()
```実装の中核は能力ごとのスキャンです。 能力ごとに、S に表示される文字のシーケンスを再構築し、このシーケンスが能力文字列の繰り返しによって形成されているかどうかを確認します。 ポインタ`j`は、能力文字列の 1 つのコピー内の進行状況を追跡し、それがゼロにリセットされるたびに、1 つの挿入が完了したことになります。 

微妙な点は、圧縮された識別子ではなく、元の文字を使用して能力ごとのシーケンスを再構築する必要があることです。 これにより、比較が能力の定義に直接関連付けられます。

 ## 特殊なケース

 特殊なケースの 1 つは、能力が最後の文字列にまったく表示されない場合です。 この場合、そのサブシーケンスは空であり、何も貢献しません。これは、能力が単に一度も使用されなかったため、有効です。 

もう 1 つのケースは、能力が部分的に一致しているように見えても、サイクルの途中で終了する場合です。 たとえば、パターンが次のような場合`abc`そしてその投影は`abca`、決勝`a`新しいサイクルは開始されますが、決して完了しません。すべての挿入が能力の完全なコピーに寄与するため、有効な挿入ではこのようなことは起こりません。 

3 番目のケースは、複数の能力が高度にインターリーブされている場合です。 射影によってすべての干渉が除去されるため、各能力は引き続き独立して独自のサイクル構造を形成し、アルゴリズムはインターリーブの影響を受けることなくそれらを個別に検証します。
