 ## 解決策
 ## 問題の理解

 長さの配列を構築するように求められます`n`ここで、各値は 30 ビットの非負の整数です。 この構造は、要素を固定値との不等式によって、またはペア間の XOR 関係によって関連付ける一連の制約を満たす必要があります。 

2 番目のタイプの制約は構造規則のように動作します。つまり、2 つのインデックスが次の形式の方程式でリンクされている場合です。`a[i] XOR a[j] = x`、一方の値が選択されると、もう一方の値が完全に決定されます。 これは、制約が独立した条件ではなく、配列全体に伝播する関係のシステムを定義することを意味します。 

最初のタイプの制約は、特定の位置での特定の値を禁止します。 これらは、すべての XOR 関係が値の相対構造をすでに固定した後で回避する必要がある除外として機能します。 

主な困難は、XOR 制約が連結コンポーネントを形成する可能性があり、各コンポーネント内ですべての値が一貫したビット単位の変換によって結合されるという事実から生じます。 制約ごとの単純な割り当ては失敗します。サイクル内の 1 つの矛盾または遅い禁止値により、以前の選択が無効になる可能性があるためです。 

制約はテスト ケースごとに最大 100,000 と大きいため、割り当てをテストしたり、値をバックトラックしようとしたソリューションはすぐに遅すぎます。 次のような演算が行われるため、線形または線形に近いグラフベースの構築が必要です。`O(n + m)`が唯一の実行可能な選択肢です。 

XOR 制約が一貫性のないサイクルを形成する場合、微妙な失敗のケースが発生します。 たとえば、それを導き出すと、`a1 XOR a2 = 3`、`a2 XOR a3 = 4`、 そして`a1 XOR a3 = 10`、最初の 2 つを XOR することですでに修正されているため、これら 3 つは矛盾を暗示します。`a1 XOR a3`。 サイクルに沿った一貫性を明示的に検証しないソリューションでは、無効な配列が暗黙的に構築されます。 

XOR 伝播を考慮する前に、禁止値がノードでローカルに処理される場合、別の障害モードが発生します。 インデックスで禁止されている値`i`これは、ノードの XOR オフセットによって調整された後でのみ、そのコンポーネントのグローバル代表者にとって禁止された選択になります。 この変化を無視すると、誤ったグローバル推論につながります。 

## アプローチ

 XOR 制約を無視すると、問題は、禁止された値を回避しながら個別に値を選択することになりますが、これは簡単です。 禁止された制約を無視すると、XOR 制約によってグラフが定義され、各連結成分に 1 つの基本値を割り当て、他のすべての値に XOR オフセットが続きます。 これは、一貫性要件を備えたグラフ構造をすでに示唆しています。 

ブルート フォース アプローチでは、各ノードに値を割り当て、収束するまで制約を繰り返し適用しようとします。 値が変更されるたびに、そのノードに関係するすべての制約を再チェックする必要があり、更新がグラフ全体に伝播する可能性があります。 最悪の場合、各割り当てによりすべてのエッジにわたるカスケードがトリガーされ、制約のチェーン全体で指数関数的または少なくとも二次関数的な動作が発生する可能性があります。 まで`10^5`制約がある場合、これは実行不可能になります。 

重要な観察は、XOR 制約により、各エッジが XOR の下で固定差を強制する重み付き無向グラフが定義されるということです。 接続コンポーネントの 1 つのノードで値が固定されると、そのコンポーネント内の他のすべてのノードは一意に決定されます。 これにより、システム全体をコンポーネントごとに 1 つの自由変数に減らすことができます。 

各コンポーネントを 1 つの自由度に圧縮した後、残りのタスクは、すべての禁止された制約が満たされるように、そのコンポーネントの基本値を選択することです。 各禁止条件は、ノードの XOR オフセットによって調整された後、基本値の除外に変換されます。 値領域が大きいため(`2^30`)、制約が一貫していれば、常に有効な選択肢を見つけることができます。

 ## アルゴリズムのチュートリアル

 各 XOR 制約が重みを持つエッジであるグラフとしてシステムをモデル化します。 

1. フォームの各制約を考慮したグラフを構築します。`a[i] XOR a[j] = x`無向エッジになる`(i, j)`ラベル付き`x`。 これは、値を代入すると、`i`、の値`j`強制される`a[i] XOR x`。 
2. DFS または BFS を使用して各接続コンポーネントをスキャンし、相対値を割り当てます。`dist[i]`各ノードについて、次のように解釈されます`a[i] XOR base_of_component`。 トラバース中にノードを再訪問し、暗黙の値が以前に割り当てられた値と矛盾する場合、システムが矛盾していると即座に結論付けます。 
3. 各接続コンポーネントに属するすべてのノードをそのコンポーネントとともに収集します。`dist[i]`価値観。 
4. 各コンポーネントについて、コンポーネントの基本値の禁止セットを計算します。 フォームのあらゆる制約`a[i] != x`に翻訳します`base XOR dist[i] != x`、これは以下と同等です`base != x XOR dist[i]`。 このような禁止されている変換された値をすべて、そのコンポーネントのセットに挿入します。 
5. コンポーネントの基本値を選択します。ゼロから開始して、禁止されたセットに存在しない値が見つかるまで増加します。 これが機能するのは、ドメイン サイズが禁止値の数に比べて非常に大きいためです。 
6. ベースを選択したら、コンポーネント内のすべてのノードを次のように割り当てます。`a[i] = base XOR dist[i]`。 

中心的な不変条件は、各接続コンポーネント内で、次の構築により、すべてのノード値が常にすべての XOR 制約と一致することです。`dist[i]`。 残された唯一の自由はグローバル ベースであり、禁止された制約はコンポーネントごとにこの 1 つのパラメータのみを制限します。 塩基選択中にすべての禁止条件が尊重されるため、最終的な割り当てはすべての制約を同時に満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    MAXV = (1 << 30)

    for _ in range(t):
        n, m = map(int, input().split())

        g = [[] for _ in range(n + 1)]
        type1 = [[] for _ in range(n + 1)]

        for _ in range(m):
            tmp = input().split()
            if tmp[0] == '1':
                _, i, x = tmp
                i = int(i)
                x = int(x)
                type1[i].append(x)
            else:
                _, i, j, x = tmp
                i = int(i)
                j = int(j)
                x = int(x)
                g[i].append((j, x))
                g[j].append((i, x))

        vis = [False] * (n + 1)
        dist = [0] * (n + 1)
        comp = [-1] * (n + 1)
        comps = []

        ok = True

        for i in range(1, n + 1):
            if vis[i]:
                continue
            stack = [i]
            vis[i] = True
            dist[i] = 0
            comp_id = len(comps)
            comps.append([])

            while stack and ok:
                v = stack.pop()
                comp[v] = comp_id
                comps[comp_id].append(v)

                for to, w in g[v]:
                    if not vis[to]:
                        vis[to] = True
                        dist[to] = dist[v] ^ w
                        stack.append(to)
                    else:
                        if dist[to] != (dist[v] ^ w):
                            ok = False
                            break

        if not ok:
            print("No")
            continue

        base = [0] * len(comps)
        used = [set() for _ in range(len(comps))]

        for v in range(1, n + 1):
            cid = comp[v]
            for x in type1[v]:
                used[cid].add(x ^ dist[v])

        for cid in range(len(comps)):
            b = 0
            while b in used[cid]:
                b += 1
            base[cid] = b

        ans = [0] * (n + 1)
        for v in range(1, n + 1):
            ans[v] = base[comp[v]] ^ dist[v]

        print("Yes")
        print(*ans[1:])

if __name__ == "__main__":
    solve()
```このソリューションでは、まず XOR 制約グラフを構築し、各コンポーネント内の相対的な XOR 距離を計算します。 DFS は、すべてのノードが一貫したラベルを取得することを保証し、矛盾がある場合は直ちにテスト ケースを無効にします。 

コンポーネントが特定されると、すべての禁止された制約がコンポーネントの基本値の制限に変換されます。 変革`x XOR dist[i]`は、ノード固有の制限をコンポーネントごとに統一された座標系に調整するものです。 

基本選択ループは、禁止値の数が制約の数によって制限される一方、検索スペースの範囲が広いため安全です。`2^30`。 各コンポーネントはすべての制約のごく一部にのみ寄与するため、リニア スキャンでも効率は維持されます。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
constraints:
1: a1 != 0
2: a1 XOR a2 = 1
3: a2 XOR a3 = 2
```距離を指定して 1 つのコンポーネントを構築します。`dist[1] = 0`、`dist[2] = 1`、`dist[3] = 3`。 

禁止された制約を変換します`a1 != 0`:

 ベース XOR 0 != 0 → ベース != 0。 

だから禁断のセットは`{0}`。 

私たちが選ぶ`base = 1`。 

割り当ては次のようになります。`a1 = 1`、`a2 = 0`、`a3 = 2`。 

| ノード | 距離 | 値 = ベース XOR 距離 |
 | --- | --- | --- |
 | 1 | 0 | 1 |
 | 2 | 1 | 0 |
 | 3 | 3 | 2 |

 これにより、XOR 関係が保持され、禁止された値が回避されることが確認されます。 

### 例 2 (不一致の検出)

 入力:```
1 3
a1 XOR a2 = 1
a2 XOR a1 = 0
```トラバース:`a1 XOR a2 = 1`暗示する`dist[2] = 1`。 

2 番目の制約が意味するのは、`dist[1] XOR dist[2] = 0`、強制的に`dist[2] = 0`。 

すでに持っていました`dist[2] = 1`、走査中に矛盾が発生するため、出力は`No`。 

これは、XOR 距離チェックを通じてサイクルの一貫性が強制されていることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、XOR 制約がすべてのノードにわたって長いチェーンを形成する一方で、禁止された制約が単一ノードにクラスタリングする場合です。 すべての制約が同じ基本座標に変換されるため、アルゴリズムはこれを処理します。そのため、ローカル制約の密集したセットであっても、他のコンポーネントに干渉することはありません。 

もう 1 つのエッジ ケースは、コンポーネントにゼロから始まる連続範囲をカバーする多くの禁止値がある場合です。 ドメインが禁止されたエントリの数よりも大幅に大きく、ギャップが保証されているため、有効な塩基の線形スキャンは依然として成功します。 

3 番目のケースは、ローカルでは一貫性があるが、グローバルでは一貫性がないサイクルです。 DFS ベースの距離チェックは、すべてのエッジが以前に割り当てられた距離と一致することを強制することでこれを即座に検出し、無効な割り当てが基本選択段階に到達することを防ぎます。
