 ## 解決策
 ## 問題の理解

 一連の整数が与えられ、次に一連のクエリが与えられます。 各クエリ値について$b$のすべての正の約数に興味があります。$b$。 これらの約数の中には、指定された配列内に出現するものもあれば、出現しないものもあります。 各クエリのタスクは、次の約数がいくつあるかを数えることです。$b$配列に存在しません。 

配列自体は各テスト ケースに対して静的であるため、すべてのクエリの処理中に固定参照セットとして扱うことができます。 

この制約は、配列サイズとクエリ数の両方が最大で$10^5$、配列内の値とクエリも次によって制限されます。$10^5$。 これにより、クエリごとに単純に約数を再計算することが即座に排除され、また、配列をスキャンすることによってすべてのクエリ要素について直接配列に対して割り算をチェックすることも排除されます。 クエリごとにすべての配列要素にアクセスするソリューションでは、約$10^{10}$制限時間を大幅に超えた最悪の場合の作戦。 

各クエリの約数を個別に再計算することを考えると、微妙な落とし穴が現れます。 100000 のような数値の場合、最大で反復$\sqrt{b}$クエリごとでも問題ありませんが、実行すると$10^5$特に制限が厳しい Python では、慎重に最適化しないとタイムアウトになる危険性があります。 

もう 1 つの特殊なケースは、配列内の重複に起因します。 値が複数回出現する場合でも、「現在の除数」としてカウントされるのは 1 回のみであるため、配列をセットとして扱う必要があります。 たとえば、配列が次の場合、$[2, 2, 3]$そして$b = 6$、約数は$1,2,3,6$。 両方$2$そして$3$が存在するので、答えは$2$、重複2の影響を受けません。 

## アプローチ

 各クエリの直接的なアプローチは、1 から 2 までのすべての整数を列挙することです。$b$そしてどれが分割するかを確認してください$b$、配列内のメンバーシップを確認します。 これは正しいですが、クエリごとにコストがかかるため、遅すぎます。$O(b)$、までにつながります$10^{10}$操作。 

さらに良い観察は、約数はペアであり、最大で効率的に生成できるということです。$\sqrt{b}$。 これにより、クエリごとのコストが削減されます。$O(\sqrt{b})$、しかしまだ私たちに最大のことを残します$10^5$クエリにより、合計が制限に近づく可能性があります。 

主要な構造的改善は、すべての数字が次の制限に制限されているということを認識することによってもたらされます。$10^5$。 約数を繰り返し再計算する代わりに、1 から 2 までのすべての数値の約数リストを事前計算できます。$10^5$かつてはふるいのような構造を使用していました。 その後、各クエリは事前に計算されたリストに対する単純なスキャンになり、メンバーシップ チェックを次の手順で実行できます。$O(1)$ブール配列またはハッシュ セットを使用します。 

これにより、問題は算術因数分解の繰り返しから検索問題に変換されます。

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 配列を読み取り、値でインデックス付けされたブール型プレゼンス テーブルに変換します。 これにより、配列内に数値が存在するかどうかを定数時間でチェックできるようになります。 セットの代わりにテーブルを使用する理由は、値の範囲が小さく固定されているためです。 
2. 1 ～ 100000 のすべての数値について、約数のリストを事前計算します。各整数について$i$、その倍数を繰り返して追加します$i$除数として。 これにより、ふるいのような方法ですべての約数リストが作成されます。 
3. 各クエリ値について$b$、事前計算された約数リストを取得します。 
4. すべての約数を反復します。$b$、配列のブール値テーブルに存在するとマークされていないものをカウントします。 
5. 各クエリのカウントを出力します。 

重要なアイデアは、除数の生成が完全にクエリ ループの外側に移動されるため、各クエリは事前に計算された小さな構造に対する線形スキャンになるということです。 

### なぜ効果があるのか

 数値のすべての約数は、事前計算された約数リストに 1 回だけ含まれることが保証されます。 存在テーブルは、その除数が配列内に存在するかどうかを独立して追跡します。 どちらのコンポーネントも必要なセットを正確に表現しているため、不一致を数えることで正しい答えが直接得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 100000

# precompute divisors for all numbers up to MAXV
divs = [[] for _ in range(MAXV + 1)]
for i in range(1, MAXV + 1):
    for j in range(i, MAXV + 1, i):
        divs[j].append(i)

def solve():
    t = int(input())
    out_lines = []

    for _ in range(t):
        n, q = map(int, input().split())
        arr = list(map(int, input().split()))
        queries = list(map(int, input().split()))

        present = [False] * (MAXV + 1)
        for x in arr:
            present[x] = True

        for b in queries:
            cnt = 0
            for d in divs[b]:
                if not present[d]:
                    cnt += 1
            out_lines.append(str(cnt))

    return "\n".join(out_lines)

print(solve())
```前処理ステップでは、すべての整数の除数リストが 1 回作成されるため、クエリでは算術因数分解が実行されません。 配列はブール検索テーブルに変換され、定数時間のメンバーシップ チェックが保証されます。 

各クエリ内では、実際の約数のみを反復処理します。$b$したがって、仕事は大きさではなく除数の数に比例します。$b$。 

ここでよくある間違いは、各数値の約数に Python セットを繰り返し使用することです。これにより、クエリごとのオーバーヘッドが再び発生します。 事前計算により、割り当ての繰り返しが完全に回避されます。

 ## 特殊なケース

 配列に繰り返し値が含まれている場合、次のようになります。$[2, 2, 2]$、ブール型の存在配列により、重複が結果に影響を与えないことが保証されます。 お問い合わせの場合$b = 6$、約数$1,2,3,6$存在テーブルに対してそれぞれ 1 回だけチェックされるため、重複によってカウントが膨らむことはありません。 

次のような小さな値の場合$b = 1$、除数リストに含まれるのは$[1]$。 配列に 1 が含まれていない場合、答えは 1 です。 それ以外の場合は 0 です。事前に計算された 1 の除数リストが正確で最小限であるため、アルゴリズムはこれを自然に処理します。 

最大値付近の場合$10^5$の場合、除数リストは十分に小さいままであるため、クエリごとに反復するのが効率的です。 高度に合成された数のような最悪の場合でも、除数の数は制限されたままであり、時間制限を脅かすことはありません。
