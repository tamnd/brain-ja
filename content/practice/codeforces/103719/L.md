 ## 解決策
 ## 問題の理解

 バス車両の車輪の総数が告げられます。 車両群のすべての車両は 4 輪バスまたは 6 輪バスのいずれかであり、それぞれのタイプが何台存在するかはわかりません。 タスクは、指定された総ホイール数を正確に生産できるすべての可能なフリート サイズを再構築することです。 すべての有効な構成のうち、可能な限り最小のバス数と最大数のバスを報告する必要があります。 4 輪バスと 6 輪バスの組み合わせが指定された合計を生成できない場合は、不可能であると出力します。 

入力は単一の整数 n であり、10^18 ほどの大きさになる可能性があるため、どの解も定数時間または対数時間で実行する必要があります。 可能なバス カウントを n まで反復するものは、直ちに実行不可能になります。 

重要な微妙な点は、すべての n が表現できるわけではないということです。 どちらのバスタイプも偶数のホイールを提供するため、奇数の n をまったく形成できません。 たとえば、4 と 6 の合計は常に偶数であるため、n = 7 には解がありません。 もう 1 つの特殊なケースは、値が非常に小さい場合です。 n = 2 の場合、最小のバスがすでに 4 つの車輪に寄与しているため、組み合わせも存在しません。 

## アプローチ

 強引なアイデアは、バス k の可能な数を 1 からすべて試して、合計 n に達するまでにいくつかの数の 4 輪バスと 6 輪バスを割り当てることができるかどうかを確認することです。 各 k について、4x + 6(k − x) = n となる整数 x が存在するかどうかを確認します。 これは、n − 6k が −2 で割り切れるかどうか、および結果の x が範囲内にあるかどうかをチェックすることに帰着します。 各チェックは一定時間ですが、最悪の場合、n/4 までのすべての k を反復すると、10^18 までの n には大きすぎます。 

式を書き直すと構造が単純になります。 4輪バスの台数をa、6輪バスの台数をbとする。 次に、4a + 6b = n が得られ、これを 2 で割ると 2a + 3b = n/2 が得られます。 これは、n が偶数でなければならないこと、そうでない場合は解が存在しないことをすぐに示します。 

ここで b を修正します。 次に、a は (n − 6b) / 4 として一意に決定され、それが負でない整数であることのみが必要です。 バスの数は k = a + b です。 a を代入すると、k = b + (n − 6b)/4 = n/4 − b/2 となります。 この式は、b が増加すると k が減少するという単調な関係を示しています。 つまり、妥当性制約の下で b を最小化するとバスの数が最大になり、b を最大化するとバスの数が最小になります。 

唯一の制約は、 a が負でなく整数でなければならないことです。 4a + 6b = n より、n − 6b ≥ 0 であり、4 で割り切れる必要があります。すべてが偶数であるため、割り算は b のパリティ条件になります。 したがって、非常に狭い範囲で実現可能な b 値を決定し、極値の k 値を直接抽出できます。

 ## アルゴリズムのチュートリアル

 バスと車輪に関する方程式から始めます。 各ステップでは、定数時間チェックのみが残るまで構造が抽出されます。

1. n が 2 で割り切れるかどうかを確認します。割り切れない場合は、すぐに解がないと結論付けます。 これは、4 と 6 が両方とも偶数であるため、合計も偶数でなければならないということになります。 
2. 係数を単純化するために m = n / 2 を定義します。 方程式は 2a + 3b = m となり、実現可能性を変えることなく演算サイズが削減されます。 
3. 一方の変数をもう一方の変数で表現します: a = (m − 3b) / 2。これは、任意の固定 b に対して、a が一意に決定されることを示しています。 
4. 妥当性条件を課します: a ≥ 0 および整数。 非負である場合は m − 3b ≥ 0 となり、上から b を制限します。 完全性を実現するには、m − 3b が偶数である必要があります。これは、b が m と同じパリティを持つことと同等です。 
5. これらの制約から、最小の実現可能な b と最大の実現可能な b を特定します。 b が増加すると k = a + b が減少するため、最小の b は最大のバス数を生成し、最大の b は最小のバス数を生成します。 
6. b の両方の境界値について k を計算し、出力します。 

### なぜ効果があるのか

 核となる不変条件は、すべての有効な解が、非負の範囲とパリティ条件という 2 つの独立した制約を満たす単一の整数値 b に正確に対応するということです。 b が固定されると、a が強制されます。 これにより、2 次元の検索空間が単一の有界な等差数列に分解されます。 k は b で減少する一次関数であるため、k の極値は b の実現可能な極値で発生する必要があるため、境界値のみをスキャンするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    
    if n % 2 == 1:
        print(-1)
        return
    
    m = n // 2  # 2a + 3b = m
    
    # b must satisfy:
    # 3b <= m  => b <= m // 3
    # (m - 3b) even => b % 2 == m % 2
    
    # smallest valid b
    if m % 2 == 0:
        b_min = 0
    else:
        b_min = 1
    
    # largest valid b <= m//3 with correct parity
    b_max = m // 3
    if b_max % 2 != m % 2:
        b_max -= 1
    
    if b_max < b_min:
        print(-1)
        return
    
    def buses(b):
        a = (m - 3 * b) // 2
        return a + b
    
    x = buses(b_max)  # minimum buses
    y = buses(b_min)  # maximum buses
    
    print(x, y)

if __name__ == "__main__":
    solve()
```コードはまず、n のパリティを使用して不可能なケースをフィルタリングします。 次に、問題を単純化された方程式 2a + 3b = m に変換します。 b の制約は、非負性とパリティから直接導出されます。 両方の条件を満たす b の境界値を選択し、対応するバスの数を計算します。 順序付けは意図的です。b が大きいとバスの総数が減少するため、b_max は最小の答えを返します。 

微妙な点は、整数の除算とパリティの調整を慎重に適用する必要があることです。 そうしないと、候補 b は不等式を満たしますが、整数に違反し、不正確な a が生成される可能性があります。 

## 実用的な例

 ### 例 1: n = 4

 ここで、m = 2 であるため、2a + 3b = 2 となります。 b の唯一の値は 0 であり、a = 1 となります。 

| b | a = (2 − 3b)/2 | 有効 | バス a + b |
 | --- | --- | --- | --- |
 | 0 | 1 | はい | 1 |

 最小値と最大値はどちらも 1 です。 

これにより、構成が 1 つだけ存在する場合、両方の極端な値が一致することが確認されます。 

### 例 2: n = 24

 ここで m = 12 なので、2a + 3b = 12 となります。 

| b | | 有効 | バス |
 | --- | --- | --- | --- |
 | 0 | 6 | はい | 6 |
 | 2 | 3 | はい | 5 |
 | 4 | 0 | はい | 4 |

 最大のバスは b = 0 で発生し、最小は b = 4 で発生します。 

これは、重いバスと総数の間の単調なトレードオフを示しています。

 ## 特殊なケース

 n = 1 の場合、4 と 6 の組み合わせは奇数の合計を形成できないため、アルゴリズムは奇数パリティのため直ちに拒否します。 

n = 2 の場合、パリティは除算後にのみ合格しますが、m = 1 の場合、2a + 3b は 1 に等しくないため、すべての候補値が無効になります。計算された b の範囲は空になり、不可能性チェックがトリガーされます。 

n = 4 の場合、境界ロジックは b_min = 0 および b_max = 0 を生成し、1 つのバスを持つ単一の有効な構成を生成します。 これにより、解決策が 1 つだけ存在する場合の正しさが確認されます。 

10^18 などの非常に大きな偶数 n の場合、すべての計算は整数演算の範囲内に留まり、少数の除算とパリティ チェックのみに依存するため、アルゴリズムは大きさに関係なく同じように動作します。
