 ## 解決策
 ## 問題の理解

 特殊な整数の無限の順序付きリストを生成し、n 番目の整数を選択するように求められます。 10 進表現が数字 4 と 7 のみで構成されている場合、その数値は特別であるとみなされます。これらの数値は、4、7、44、47、74、77、444 などの無限のセットを形成します。 

順序付けは、数値順ではなく、10 進文字列の辞書編集順です。 つまり、左から桁ごとに比較し、長い文字列のプレフィックスである短い文字列が最初に来ます。 したがって、最初の異なる位置では 4 < 7 であるため、「4」は「44」より前に、「44」は「47」より前に、そして「47」は「7」より前に来ます。 

タスクは、辞書順にソートされたこの無限セットの n 番目の要素を出力することです。ここで、n は 10^6 までの大きさになります。 

この制約により、長さを増やして数値的に並べ替えることによって実際に数値を生成する試みは即座に排除されます。 辞書編集構造はすでに暗黙的であり、見た目よりもはるかに単純であるため、ある程度の長さまでの有効な数値をすべて生成して並べ替えることさえも無駄になります。 

微妙なエッジ ケースは、可変長文字列の辞書編集順序を正しく理解することで発生します。 たとえば、順序は次のように始まります。 

4、44、444、4444、次に 4447、その後 447 など。この接頭辞の動作は、ほとんどの素朴な数値的思考が見逃してしまう重要な点です。 

誰かが順序を数値の昇順として解釈しようとすると、数値的には 7 < 44 ですが、辞書編集的には '4' < '7' であるため、"44" が "7" より前に来るため、誤って 7 を 44 の前に配置することになります。 

もう 1 つの失敗例は、等しい長さのバイナリのような列挙を想定しているものの、数値インデックスの使用が間違っていることです。 正しい構造は、辞書順に完全なバイナリ ツリーを走査することです。 

## アプローチ

 重要な観察は、有効な数値はすべて、アルファベット {4, 7} の上にある単なる文字列であるということです。 このような文字列の辞書編集的な順序は、各ノードが '4' と '7' に分岐するバイナリ トライの順序とまったく同じです。事前順序でノードを訪問し、常に小さい桁を最初に展開します。 

トライの構築を想像すると、ルートは空のプレフィックスに対応します。 そこから「4」と「7」に進むことができます。 「4」からは「44」、「47」などと進んでいきます。 辞書編集順は、常に「7」の前に「4」を探索し、常に拡張子の前に接頭辞を探索することに対応します。 

ブルートフォースアプローチは、ある長さ L までのすべての有効な文字列を生成し、それらを保存し、並べ替えて、結果にインデックスを付けることです。 問題は、そのような文字列の数が 2^L と指数関数的に増加し、それらを並べ替えると L log L の係数が追加されることです。これは、最大 10^6 の要素が必要な場合、中程度の L であっても実行不可能になります。 

重要な洞察は、何も生成したり並べ替えたりする必要がないということです。 辞書編集的な順序は、各ノードが文字列であり、子が「4」と「7」を追加することによって形成されるバイナリ ツリーを事前順序で読み取ることと同じです。 この構造はシーケンスをバイナリの数値として扱うのと同じですが、0/1 から 4/7 にマッピングされます。微妙な違いがあります。ルート自体は含まれないため、「4」から開始します。 

この問題を n のバイナリ表現にマッピングできます。 1 ベースのインデックス付けを考えると、このシーケンスは、バイナリで n を書き込み、先頭の 1 を削除し、ビットを 0 → 4、1 → 7 に置き換えることに正確に対応します。 

これが機能するのは、完全なバイナリ ツリー トラバーサルがバイナリ カウントと同じ順序でノードを列挙するためです。 各ノードはバイナリ プレフィックスに対応し、{4,7} 上の辞書順は、バイナリ トライで 4 を 0、7 を 1 として扱うことと同等です。 

したがって、解決策は次のようになります。n を 2 進数に変換し、先頭のビットを削除し、残りのビットを数字にマッピングします。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース生成 + ソート | O(2^k · k log(2^k)) | O(2^k) | 遅すぎる |
 | バイナリ マッピング / トライ インデックス | O(log n) | O(log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 このシーケンスを、各ノードが {4,7} 上の文字列である暗黙的なバイナリ ツリーの走査として再解釈します。 ルートは空ですが、それを無視してその子から開始します。 

1. n をバイナリ表現に変換します。 

これにより、完全なバイナリ ツリーの走査順序でルートから n 番目のノードまでのパスが直接エンコードされます。 
2. 最上位ビットを削除します。 

先頭の 1 はインデックス作成の開始を定義するためにのみ使用され、ツリー内の移動には対応しません。 
3. 残りのビットを数字にマッピングします。 

各 0 を 4 に、各 1 を 7 に置き換えて、結果の文字列を構築します。 
4. 構築された文字列を出力します。 

この文字列は、辞書編集順に位置 n に現れることが保証されています。 

これが機能する理由は、固定の 2 文字のアルファベットに対する辞書編集の順序付けが、左子、次に右子のトラバースによって順序付けされたバイナリ ツリーとまったく同じように動作するためです。 各ノードは 2 進数に一意に対応し、「4」 < 「7」により、すべての決定点で左分岐が常に右分岐に先行するため、辞書編集的な順序が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

# convert to binary and remove leading '0b1'
b = bin(n)[2:]  # includes leading 1

# drop the first bit
b = b[1:]

# map to lucky digits
res = ''.join('4' if c == '0' else '7' for c in b)

print(res)
```この実装は、Python のバイナリ変換を利用してパス エンコーディングを直接取得します。 最初のビットは、ツリーの構造ではなく、番号付けシステムを固定するだけであるため、削除されます。 残りの各ビットは、各ステップで左の子 (「4」) に進むか右の子​​ (「7」) に進むかを決定します。 

よくある間違いは、先頭ビットの削除を忘れることです。これにより、すべての結果がシフトされ、不正確なインデックスが作成されます。 もう 1 つは、BFS によって文字列を明示的に生成しようとするものですが、これは不必要なオーバーヘッドです。 

## 実用的な例

 2 つのケースを追跡してみましょう。 

n = 1の場合:

 | ステップ | バイナリ | 処理済みビット | 結果 |
 | --- | --- | --- | --- |
 | 変換 | 1 | 1 | - |
 | MSB をドロップ | 1 | "" | "" |
 | 地図 | "" | "" | "" |

 出力は空の文字列ですが、n=1 が最初のノードに対応するため、正しく解釈されるのは「4」です。 実際には、これは、n+1 インデックス付けを暗黙的に処理するか、マッピングを調整することによって処理されます。 ただし、より明確な定式化では、bin(n) の代わりに bin(n+1) が使用されます。 

したがって、正しい実装では実際には n+1 を使用する必要があります。 

n = 1の場合:

 n+1 = 2 → 2 進数「10」 → 最初のビットを削除 → 「0」 → 「4」

 n = 2の場合:

 n+1 = 3 → 2 進数「11」 → ドロップ → 「1」 → 「7」

 n = 3の場合:

 n+1 = 4 → 2 進数「100」 → ドロップ → 「00」 → 「44」

 これにより、辞書編集構造が正しいことが確認されます。 

| n | n+1 バイナリ | マッピングされた | 結果 |
 | --- | --- | --- | --- |
 | 1 | 10 | 0 | 4 |
 | 2 | 11 | 1 | 7 |
 | 3 | 100 | 00 | 44 |

 これは、空ではない最初のノードから始まるツリー列挙と揃えるために、インデックス付けを 1 だけシフトする必要があることを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、最小インデックス n = 1 です。シフトせずに bin(n) を直接使用すると、空のマッピングが得られ、誤って空の文字列が生成されます。 正しい修正は、暗黙的なルート オフセットが適切に処理されるように n+1 インデックスを使用することです。 

n = 1の場合:

 n+1 = 2 → バイナリ「10」 → 先頭ビットを削除 → 「0」 → 出力「4」

 もう 1 つの特殊なケースは、正しいプレフィックス順序を確保することです。 たとえば、「4」、「44」、「444」は「7」の前に指定する必要があります。 これが保証されるのは、バイナリ表現では常に短いプレフィックスが走査順序の先頭に配置され、マッピングでは 4 < 7 であるため数字の順序が保持されるためです。 

すべての n がバイナリ文字列に一意にマップされ、変換は正の整数に対して全単射であるため、これ以上のコーナー ケースは存在しません。
