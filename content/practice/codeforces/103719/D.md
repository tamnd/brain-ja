 ## 解決策
 ## 問題の理解

 すべての頂点が固定の正の重みを持つ有向グラフが与えられます。 まず、選択した頂点にコインを置きます。 コインが頂点に置かれるたびに、その頂点の重量がログに記録されます。 各配置の後、コインを有向エッジに沿って別の頂点まで移動することができ、このプロセスを繰り返します。 私たちは正確に実行しなければなりません$k-1$移動します。つまり、コインは正確に配置されます。$k$開始頂点を含む合計頂点。 

目標は、ログに記録された最大値ができるだけ小さくなるように、開始頂点とその後のすべての動きを選択することです。 作るのが無理なら$k-1$任意の頂点から始まる有効な動き、答えは次のとおりです。$-1$。 

この制約は、最大で次のような大きなグラフを意味します。$2 \cdot 10^5$頂点とエッジ、そして$k$と同じ大きさにすることができます$10^{18}$。 これにより、ある長さのパスを明示的にシミュレートするアプローチは即座に除外されます。$k$、線形依存性さえあるので、$k$不可能です。 唯一実行可能な戦略は、到達可能性パターンやサイクルなど、グラフの構造特性に長いウォークを圧縮する戦略です。 

重要なエッジケースは、グラフに長さのパスが含まれていない場合に発生します。$k-1$どこでも。 たとえば、グラフが最大パス長 3 の DAG であり、$k = 10$、開始頂点が十分な移動を生成できないため、答えは次のようになります。$-1$。 貪欲な動きを単に試行する単純なシミュレーションでは、グローバルなパスの枯渇を無視して、発信エッジがローカルに存在する場合には常に続行できると誤って想定してしまいます。 

もう 1 つの微妙なケースは、小さなサイクルが存在するものの開始頂点がそこに到達できない循環グラフで発生します。 たとえば、サイクルに低重みノードが含まれているが、安価な開始領域から切断されている場合、単純な「最小重み頂点を選択する」戦略は、十分なステップをサポートできない可能性があるため失敗します。 

## アプローチ

 ブルートフォース解釈では、すべての開始頂点を試してから、可能な長さのすべてのウォークを探索します。$k-1$、各ウォークに沿って最大頂点の重みを追跡します。 これはプロセス定義に直接従うため、正しいです。 ただし、歩く回数は飛躍的に増加します。$k$、そして状態をメモ化した場合でも$(v, steps)$、状態空間は次のようになります。$O(nk)$、それは不可能です$k$まで$10^{18}$。 

重要な観察は、制約は動きの正確な順序に関するものではなく、一定の長さの歩行を維持できるかどうかに関するものであるということです。$k$できるだけ重みの高い頂点を避けます。 閾値を固定すると$X$、頂点のみを考慮します。$a_i \le X$。 問題は、長い散歩道が存在するかどうかである$k-1$完全に、許可された頂点の誘導されたサブグラフの内側にあります。 

これにより、問題は単調な意思決定タスクに変換されます。$X$: 長い距離を歩く場合$k-1$重みのある頂点のみを使用して存在します$\le X$、さらに大きいもの$X$も機能します。 この単調性により、答えの二分探索が可能になります。 

固定の場合$X$, グラフを限定して実現可能性を確認します。 制限されたグラフに有向サイクルが含まれている場合、そのサイクル内に無限に留まることができ、任意の長い歩行が即座に保証されるため、$k$達成可能です。 サイクルがない場合、グラフは DAG であり、最長のパス長はトポロジカル順序付けまたは DP を使用して計算できます。 最大パス長が少なくとも以下であるかどうかを確認します。$k-1$。 

これにより、問題は、フィルタリングによって引き起こされる DAG 上でのサイクル検出と最長パスの計算と組み合わせた値に対する二分探索に変換されます。

 ## アルゴリズムのチュートリアル

 ### 最適なアルゴリズム

 1. 頂点の重みを、考えられる最大値に対するバイナリ検索ドメインとしてソートまたは考慮します。 最小のしきい値を検索します$X$有効な長さの散歩ができるようになる$k-1$の頂点のみを使用して存在します$a_i \le X$。 これが機能するのは、しきい値を高くしても頂点とエッジが追加されるだけで、到達可能性が低下することはないためです。 
2. 固定閾値の場合$X$、頂点のみを含む概念的なサブグラフを構築します。$a_i \le X$そしてそれらの間のエッジ。 
3. このサブグラフに有向サイクルが含まれるかどうかを計算します。 サイクルが存在する場合、これに対してすぐに true を返します。$X$サイクル内でループして、必要なすべての動きをカバーする任意の長さの一連の動きを生成できるためです。$k-1$。 
4. サイクルが存在しない場合、サブグラフは DAG です。 トポロジカルな順序付けを実行し、訪問した頂点の数に基づいて最長のパス長を計算します。 
5. 最長パス長が少なくとも$k$、 それから$k-1$移動は達成可能です。 それ以外の場合はそうではありません。 
6. 二分探索を使用します。$X$、ステップ 3-5 の実現可能性に応じて検索範囲を更新します。 最終的な答えは実行可能な最小限のものです$X$、 または$-1$値が機能しない場合。 

### なぜ効果があるのか

 固定しきい値の場合$X$、実現可能性は、誘導されたサブグラフが十分な長さの歩行をサポートするかどうかによってのみ決まります。 この物件はモノトーンです$X$、増加して以来$X$頂点とエッジのみを追加します。 固定サブグラフ内では、サイクルが存在して無制限のウォーク長が許可されるか、グラフが非周期的ですべてのウォーク長が DAG 内の最長パスによって制限されます。 これら 2 つの構造ケースは実現可能性を完全に特徴づけており、DAG 内にサイクルのない長いウォークが存在する中間動作を防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def can(x, n, g, a, k):
    # build induced graph
    active = [i for i in range(n) if a[i] <= x]
    if not active:
        return False

    ok = [a[i] <= x for i in range(n)]
    color = [0] * n  # 0 unvisited, 1 visiting, 2 done

    has_cycle = False

    def dfs(v):
        nonlocal has_cycle
        color[v] = 1
        for to in g[v]:
            if not ok[to]:
                continue
            if color[to] == 1:
                has_cycle = True
                return
            if color[to] == 0:
                dfs(to)
            if has_cycle:
                return
        color[v] = 2

    for v in range(n):
        if ok[v] and color[v] == 0:
            dfs(v)
            if has_cycle:
                break

    if has_cycle:
        return True

    # DAG: compute longest path via DP in topo order
    indeg = [0] * n
    for v in range(n):
        if not ok[v]:
            continue
        for to in g[v]:
            if ok[to]:
                indeg[to] += 1

    from collections import deque
    q = deque([i for i in range(n) if ok[i] and indeg[i] == 0])

    dp = [1] * n  # longest path ending at v

    while q:
        v = q.popleft()
        for to in g[v]:
            if not ok[to]:
                continue
            if dp[to] < dp[v] + 1:
                dp[to] = dp[v] + 1
            indeg[to] -= 1
            if indeg[to] == 0:
                q.append(to)

    return max(dp[i] for i in range(n) if ok[i]) >= k

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    g = [[] for _ in range(n)]

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)

    if k == 1:
        print(min(a))
        return

    lo, hi = min(a), max(a)
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(mid, n, g, a, k):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、実現可能性チェックを固定しきい値を評価する関数に分離します。 サイクルの検出には DFS カラーリングが使用されますが、フィルタリングされたサブグラフ内のサイクルの存在のみを考慮するため、これで十分です。 最長パスの計算は、グラフが非巡回であり、トポロジカル順序付け上の DP が有効な場合にのみ使用されます。 

微妙な点は、単一の頂点がすでに 1 つの配置に寄与しているため、DP は到達可能なすべてのノードを値 1 で初期化することです。 これは、ウォーク長がエッジではなく訪問した頂点をカウントするという要件と一致します。 

許可される最大頂点値では実現可能性が単調であるため、二分探索はパス長ではなく重み値に対して実行されます。

 ## 特殊なケース

 深さが非常に浅い純粋に非循環的なグラフは、サイクルベースの直観が失敗していることを示しています。 多くの低重みの頂点が存在する場合でも、サイクルが存在しないため、すべてのウォークがすぐに終了することが強制されるため、アルゴリズムは大きな頂点を正しく拒否します。$k$DP計算後。 

すべての頂点の重みが高い完全な循環グラフは、逆の動作を示します。 最小しきい値には頂点のサブセットしか含まれていない場合でも、サイクルが含まれると、無限の繰り返しが可能になるため、答えは安定し、二分探索は開始点から到達可能なサイクルを明らかにする最小のしきい値に収束します。
