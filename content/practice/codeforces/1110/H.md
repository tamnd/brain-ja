 ## 解決策
 ## 問題の理解

 固定長の数字列を構築するように求められます`n`。 この文字列のすべての部分文字列は (先頭のゼロを無視して) 数値として解釈され、次のスコアが得られます。`1`部分文字列の場合、その数値が包含範囲内にある場合`[l, r]`。 合計スコアは単にそのような部分文字列の数であり、各出現を個別にカウントするため、異なる位置から生じる同一の数値が複数回寄与します。 

タスクは、この合計スコアを最大化し、すべての最適な文字列の中で辞書編集的に最小のものを出力することです。 

制約は 2 つの異なる方向で極端です。 境界`l`そして`r`は最大 800 桁まで含めることができます。つまり、それらを組み込みの整数に変換したり、単純な算術で扱うことさえできません。 長さ`n`は最大 2000 です。これにより、ポジション上の二次関数 DP は境界線に達しますが、遷移ごとの作業が注意深く制御されていれば、依然として実行可能です。 単純なアプローチを無効にするのは組み合わせです。O(n²) 個の部分文字列があり、各部分文字列には、その値が巨大な数値間隔内にあるかどうかを判断する高速な方法が必要です。 

微妙なエッジ状態は先行ゼロです。 のような部分文字列`"01"`は数値の有効な表現とみなされないため、完全に無視されます。 これは、慎重に扱わないと単純な「文字列を数値として比較する」ロジックを壊してしまうため、重要です。 

もう 1 つの重要な観察は、部分文字列値は周囲のコンテキストではなく、その数字の内容のみに依存するということです。 ただし、すべての位置が潜在的な開始点であるため、単一のシーケンス評価ではなく、すべての開始点の合計を同時に最適化することが効果的です。 

## アプローチ

 直接的なブルート フォース ソリューションでは、すべての O(n²) 個の部分文字列を列挙し、各部分文字列を比較します。`[l, r]`大きな整数の文字列比較を使用します。 たとえ比較が O(800) だとしても、これはおよそ O(n² · 800) となり、最大制約ですでに約 32 億文字の演算になります。 これでは遅すぎます。 

もう少し構造化されたブルート フォースでは、各部分文字列を段階的に構築し、比較を維持しようとします。`l`そして`r`。 これでも O(n² · 10) 回の遷移が残り、文字列を評価するだけでなく文字列自体の桁を最適に選択する必要があるという根本的な問題は解決されません。 

重要な洞察は、視点を反転することです。 部分文字列を静的なオブジェクトとして考えるのではなく、数値が一定の範囲以下であるかどうかを認識する数字オートマトンの中を歩くものとして考えます。 数値のセットを正確に受け入れるオートマトンを構築できれば ≤`x`そうすると、オートマトンの状態に対して DP を介して部分文字列の有効性を評価できます。 

間隔を処理するには`[l, r]`として、問題を 2 つの接頭辞で区切られた言語に分割します。 

有効な部分文字列の数は次の値に等しい ≤`r`マイナスそれら ≤`l - 1`。 

「≤ x」は標準の数字 DP オートマトンであるため、これは強力です。状態は、次の接頭辞とどの程度一致したかを表します。`x`そして私たちはすでに厳密に小さくなっているのかどうか。 

このようなオートマトンを作成すると、各部分文字列は単にそのオートマトン内のパスになります。 残りの課題は、1 つの部分文字列を評価するのではなく、すべての部分文字列を同時に評価することです。 これは、すべての開始位置をオートマトンを実行する独立したプロセスとして表示し、すべての開始の寄与を合計することによって処理されます。 

次に、各開始点がオートマトンの遷移を通じて独立して寄与する文字列位置に対して DP を実行します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォースの部分文字列 + チェック | O(n² · | l | ) |
 | オートマトンDPオーバー開始 | O(n・S・10) | O(n・S) | 承認済み |

 ここ`S`は数字オートマトンのサイズで、およそ O(|r| · 2) です。

### なぜ効果があるのか

 核となる不変条件は、各位置における`i`、DP 状態は、で始まるすべての部分文字列からの寄与を集計します。`i`他のスタートとは独立して。 オートマトンは、各部分文字列の数値の正当性を保証します。 線形性により、オーバースタートの合計が独立した DP 寄与の合計と同等であることが保証されます。 各部分文字列はオートマトン内の開始位置とパスによって一意に識別されるため、相互作用が二重にカウントされたり見逃されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def sub_one(s: str) -> str:
    s = list(s)
    i = len(s) - 1
    while i >= 0 and s[i] == '0':
        s[i] = '9'
        i -= 1
    if i >= 0:
        s[i] = str(int(s[i]) - 1)
    if s[0] == '0':
        s = s[1:]
    return ''.join(s)

class Automaton:
    def __init__(self, bound: str):
        self.b = bound
        self.m = len(bound)

        # state: (i, tight)
        self.states = []
        self.id = {}

        for i in range(self.m + 1):
            for t in (0, 1):
                self.id[(i, t)] = len(self.states)
                self.states.append((i, t))

        self.dead = len(self.states)
        self.states.append(("dead", 0))

        self.trans = [[self.dead] * 10 for _ in range(len(self.states))]

        for i in range(self.m + 1):
            for t in (0, 1):
                s = self.id[(i, t)]
                if i == self.m:
                    continue
                limit = int(self.b[i]) if t else 9
                for d in range(10):
                    if t and d > int(self.b[i]):
                        continue
                    ni = i + 1
                    nt = t and (d == int(self.b[i]))
                    self.trans[s][d] = self.id[(ni, nt)]

        # dead transitions
        for d in range(10):
            self.trans[self.dead][d] = self.dead

def solve(bound: str, n: int):
    if bound == "0":
        return 0, "0" * n

    aut = Automaton(bound)
    S = len(aut.states)

    dp = [[0] * S for _ in range(n + 1)]

    # dp[i][s] = best contribution starting at i if current automaton state is s
    for i in range(n - 1, -1, -1):
        for s in range(S):
            best = -INF

            for d in range(10):
                ns = aut.trans[s][d]
                val = dp[i + 1][ns]

                # accept contribution: if state is valid and within bound progress
                if ns != aut.dead:
                    val += 1

                if val > best:
                    best = val

            dp[i][s] = best

    res = 0
    s0 = aut.id[(0, 1)]
    for i in range(n):
        res += dp[i][s0]

    # reconstruction
    ans = []
    for i in range(n):
        s = aut.id[(0, 1)]
        best = -INF
        best_d = 0
        for d in range(10):
            ns = aut.trans[s][d]
            val = dp[i + 1][ns]
            if ns != aut.dead:
                val += 1
            if val > best or (val == best and d < best_d):
                best = val
                best_d = d
        ans.append(str(best_d))

    return res, ''.join(ans)

def main():
    l = input().strip()
    r = input().strip()
    n = int(input())

    rl, sr = solve(r, n)

    if l == "0":
        ll = 0
        sl = "0" * n
    else:
        l2 = sub_one(l)
        ll, sl = solve(l2, n)

    print(rl - ll)
    print(sr)

if __name__ == "__main__":
    main()
```このソリューションは、接頭辞で区切られた数値の桁オートマトンを構築し、すべての部分文字列の先頭に対して DP を実行します。 各 DP 遷移は、部分文字列を 1 桁拡張し、現在のプレフィックスが間隔内で有効な数値を形成しているかどうかを累積することを表します。 最後の減算では下限を処理します。 

再構成パスは同じ DP 遷移を使用しますが、最適性を維持する桁を貪欲に選択し、より小さい桁への結合を解決します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、デクリメント後に下限がゼロになる場合です。`l`。 この場合、先頭のゼロ以外の数字で始まるすべての部分文字列が有効であり、DP は数字を最小限に抑えることで部分文字列の数を最大化するように縮退します。 

もう 1 つのエッジケースは次のような場合です`l`そして`r`最上位桁のみが異なります。 オートマトンは早期にほぼ完全にタイトフリーになり、ほとんどの状態が同じように動作するため、貪欲な数字の選択が安全かつ最適になります。 

3 番目のエッジケースは次のような場合です。`n`バインドされた長さに比べて小さいです。 その場合、完全長の比較に到達できる部分文字列はほとんどなくなり、有効性は完全にプレフィックスの動作によって決定され、オートマトンは未完成のパスを自動的に有効なものとして扱うことで正しく処理します。
