 ## 解決策
 ## 問題の理解

 タイルのマルチセットが与えられ、各タイルは 1 から m までの整数値を保持します。 目標は、正確に 3 つのタイルからなる互いに素なグループを繰り返し選択し、できるだけ多くのそのようなグループを形成することです。 有効なグループは、3 つの同一の値、または昇順の 3 つの連続した値のいずれかです。 各タイルは最大 1 回使用できるため、タイルがグループに参加すると、それ以降の検討から削除されます。 

出力は、指定されたマルチセットから形成できる有効なグループの最大数です。 

主な難点は、値 i のタイルが 2 つの根本的に異なる構造に参加できることです。つまり、i、i、i を使用して同じ値のトリプルを完成させることも、隣接する値を配置する方法に応じて、連続するトリプル i-2、i-1、i または i、i+1、i+2 の一部になることもできます。 これらの選択はグローバルに相互作用するため、貪欲なローカル決定は失敗します。 

n、m が 10^6 までの制約は、m において線形または線形に近いアルゴリズムより悪いアルゴリズムは遅すぎることを意味します。 二次または三次の DP 値を超えることは不可能です。 O(n log n) であっても許容されますが、多くの状態にわたるカウントの組み合わせを直接考慮しようとするものはすべて失敗します。 

連続するトリプルが局所的には明らかではない方法でオーバーラップする場合、微妙な問題が発生します。 たとえば、カウントが 3,3,3,3,3 のようなウィンドウ付近で高い場合、単純な貪欲さは、あまりにも多くの同一のトリプルを早い段階でコミットし、全体的により優れた連続するトリプルを後でブロックする可能性があります。 連続するトリプルを最初に貪欲に最大化すると、別の失敗モードが発生します。これにより、同じ値のトリプルをさらに形成するはずだった残りの重複が無駄になる可能性があります。 

失敗例：

 入力:

 1 5

 3 3 3 3 3

 最適な答えは 1 つのトリプル (3,3,3) ですが、連続したトリプルを形成しようとする貪欲なアプローチでは何も起こらず、すべてが同一で使用可能であることを見落とす可能性があります。 

これは、値ごとのローカルな決定では不十分であることを示しています。 隣接する位置間の相互作用を考慮した構造化された DP が必要です。 

## アプローチ

 ブルートフォースアプローチでは、マルチセットからトリプルを選択するすべての方法をシミュレートしようとします。 各ステップで、有効なトリプルを選択して再帰します。 これは、各状態がマルチセット構成である巨大な状態空間を探索することに相当します。 状態の表現も指数関数的であり、考えられるすべてのトリプルで分岐すると、最悪の場合、およそ O( (n/3)! ) の可能性が生じます。 これはまったく実現不可能です。 

代わりに、各値のカウントのみが重要であり、相互作用は連続する値全体にわたって厳密に局所的であることを観察することで、問題を圧縮します。 これは、拡張している連続トリプルの「オープン チェーン」の数を追跡する DP を維持しながら、値を昇順に処理することを示唆しています。 

重要な観察は、連続するトリプル i-2、i-1、i が唯一の非局所相互作用であり、幅 3 にしか及ばないことです。これにより、以前のインデックスから保持される部分構造の数を記憶する小さな状態を維持しながら、値を順番に処理することができます。 

dp[i][j][k] を暗黙的に定義します。ここで、位置 i で、i-2 と i-1 で開始され、完了を待っている未完了のチェーンの数を追跡します。 完全な DP テーブルを保存する代わりに、これを 2 つのキャリー変数を持つ貪欲な DP に縮小します。 

各値 i で、次のように決定します。 

まず、タイプ (i, i, i) のいくつかのトリプルを使用し、次に残りのカウントと以前のキャリーを組み合わせて (i−2, i−1, i) を形成します。 順序は重要です。必要な残り物のみを確実に転送しながら、完了したトリプルの数を最大化したいと考えています。 

重要な構造的削減は、制御された状態遷移の下で可能な限り多くのトリプルを貪欲に形成した後、前方に渡される要素の数だけを維持しながら、最適な戦略を値の 1 回のパスで計算できることです。 これは、連続 3 つのポジションにわたる古典的な「ローカル ウィンドウ DP」です。

ブルート フォースは選択肢を独立して扱うため失敗しますが、最適化されたソリューションは 3 という制限されたインタラクション幅を利用します。

 ## アルゴリズムのチュートリアル

 カウントのみが重要であるため、最初に入力を周波数配列 cnt[i] に圧縮します。 

1. i-2 と i-1 からどれだけの使用可能な残りが運ばれるかを追跡する DP 状態を初期化します。 これらを 2 つの変数 a と b として表します。 
2. i を 1 から m まで繰り返します。 各ステップでは、cnt[i] の利用可能なタイルがあり、また、i で終わる連続したトリプルに参加できる、前のステップからの潜在的な残りの貢献も含まれています。 
3. まず、できるだけ多くの同一のトリプル (i、i、i) を形成しようとします。 これは cnt[i] // 3 です。これを答えに直接追加し、それに応じて cnt[i] を減らします。 
4. 同一のトリプルを削除した後、連続するトリプルの形成を検討します。 インデックス i では、i-2、i-1、および i のいくつかの要素を一緒に使用できます。 このようなトリプルの数は、3 つのポジションにわたる最小可用性によって制限されますが、順次処理しているため、以前のインデックスからの寄与は、保留中の構造にすでに部分的に割り当てられているものとして処理されます。 
5. 保存された残り物を使用して、できるだけ多くの (i-2, i-1, i) トリプルを貪欲に照合し、未使用の要素が前方に伝播するようにキャリー状態を更新します。 
6. インデックス i を処理した後、i にある残りの要素が将来の連続するトリプルのキャリーの一部になるように DP 状態を更新します。 

中心的な考え方は、すべてのステップで、制御された方法で残りの容量を転送する前に、ローカルの可能性を使い果たし、将来の構成で DP が許可する以上のトリプルを作成できないようにするということです。 

### なぜ効果があるのか

 不変条件は、値 i を処理した後、利用可能なマルチセット プレフィックスを考慮して、i またはそれより前で終了するすべてのトリプルがすでに最大化されていることです。 DP 状態に保存された残りの要素は、将来の値を含むトリプルに依然として貢献できるタイルを正確に表しており、プレフィックス内の代替の再配置によって、後のトリプルの実現可能性を低下させることなく、完了したトリプルの数を増やすことはできません。 相互作用の局所性により、あらゆる最適なソリューションを、この貪欲なプレフィックス最大化特性を損失なく尊重するソリューションに変換できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    cnt = [0] * (m + 2)
    arr = list(map(int, input().split()))
    
    for x in arr:
        cnt[x] += 1

    # dp carries:
    # carry1 = leftover from i-1 that can form consecutive triples
    # carry2 = leftover from i-2 that is pending combination
    carry1 = 0
    carry2 = 0

    ans = 0

    for i in range(1, m + 1):
        # use triples of identical values first
        t = cnt[i] // 3
        ans += t
        cnt[i] -= 3 * t

        # now try to form consecutive triples (i-2, i-1, i)
        # using carry2 (i-2), carry1 (i-1), cnt[i]
        x = min(carry2, carry1, cnt[i])

        ans += x
        carry2 -= x
        carry1 -= x
        cnt[i] -= x

        # update carries: shift window forward
        carry2 = carry1
        carry1 = cnt[i]

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、入力内のすべての順序が無関係になるように、頻度カウントを構築することから始まります。 変数 ans は、完了したトリプルを蓄積します。 

同一のトリプルは、最適な配置で連続するトリプルを決して妨げないため、すぐに削除されます。 そのようなグループ化は厳密にローカルです。 

2 つのキャリー変数は、前のステップでは使用されなかった要素を表しますが、現在と次の値で連続したトリプルを形成することができます。 位置 i でできるだけ多くの連続したトリプルを形成した後、キャリーを更新することでウィンドウを前方にシフトします。 

微妙な点は、キャリーは常に将来のウィンドウの利用可能性として解釈されるため、その意味は反復ごとに変化することです。 このシフト ウィンドウ構造により、DP が一定空間になります。

## 特殊なケース

 重要なエッジ ケースは、すべてのタイルが同じ値を持つ場合です。 このアルゴリズムは 1 つのインデックスを処理し、cnt[i] // 3 つのトリプルを即座に形成し、前方には何も進めません。 のような入力の場合`6 tiles of value 7`、キャリー変数は全体を通してゼロのままで、答えは 2 になり、最適なグループ化と一致します。 

もう 1 つの特殊なケースは、値が完全に配置されているため、連続するトリプルのみが可能である場合です。 例えば`1 2 3 1 2 3 1 2 3`。 このアルゴリズムは、各ウィンドウ (1、2、3) が正確に 1 つのトリプルに寄与するように、インデックス間のキャリー伝播を使用します。 キャリーにより、グループ化が二重にカウントされたりスキップされたりすることがなくなり、最終結果は最適な 3 になります。 

最後の微妙なケースは、貪欲な同一トリプル抽出により、連続するトリプルの機会が減少するように見える場合です。 同一のトリプルはローカルであり、同じ値の要素のみを消費するため、すでに最適な値を超えて合計カウントが減少するような (i、i+1、i+2) 構造の形成をブロックすることはなく、DP はキャリー伝播を通じて正しく補正します。
