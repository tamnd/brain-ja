 ## 解決策
 ## 問題の理解

 問題は数字を与えます$n$10 進数形式ではなく、任意の基数で$b$。 の桁$n$最も重要なものから最も重要でないものの順にリストされており、タスクは次のいずれかを決定することです。$n$は 10 進数の偶数または奇数です。 たとえば、基数が 13 で数字が [3、2、7] の場合、10 進数値は次のようになります。$n$は$3\cdot13^2 + 2\cdot13 + 7 = 540$、これは偶数です。 

制約により、最大で$10^5$各桁は最大 99 まで可能です ($b \le 100$）。 完全な 10 進数を計算することは不可能です。$n$標準の整数制限をはるかに超えて、天文学的に大きくなる可能性があります。 これにより、直接計算を試みるアプローチが除外されます。$n$そしてそのパリティをチェックします。 

エッジケースは、数字が 1 つしかない場合、または基数が偶数の場合に発生します。 1 桁の数値の場合、パリティはその桁のみによって決定されます。 より大きな数値の場合、基数と数字のパリティ間の相互作用が重要になります。これは、奇数または偶数の桁に基数のべき乗を乗算すると、最終的なパリティに予測可能な形で影響を与える可能性があるためです。 

不注意なアプローチでは、計算しようとする可能性があります。$n$直接、または間違った点でモジュロ 2 を削減します。 たとえば、積を合計すると、$a_i \cdot b^{k-i}$剰余演算を考慮しないとオーバーフローしてしまいます。 もう 1 つの微妙なケースは、基数が偶数の場合です。この場合、最後の項を除くすべての項が偶数であることが保証されるため、最後の桁のみが重要になります。 この観察は非常に重要です。 

## アプローチ

 ブルートフォースメソッドは次のようになります。$n$合計することで$a_1 \cdot b^{k-1} + a_2 \cdot b^{k-2} + \dots + a_k$。 これは小規模な場合に機能します$k$そして$b$、しかし、$k$まで$10^5$、このアプローチでは、非常に大きな数値を繰り返し乗算する必要があります。 モジュロ演算を使用してモジュロ 2 を削減したとしても、すべての桁を反復処理し、次の計算能力が必要になります。$b$、これは不要です。 

最適なアプローチでは、モジュラー演算とパリティ プロパティを活用します。 数値は 2 で割り切れる場合は偶数であり、2 を法として求めることができます。偶数の底のべき乗はすべて偶数であることに注目してください。$b$が偶数の場合、最後の桁を除くすべての桁に偶数が乗算され、0 を法とする 2 が得られます。最後の桁のみ$a_k$パリティに影響します。 いつ$b$奇数です、のすべてのべき乗$b$奇数です。 したがって、各項は寄与します$a_i \cdot 1 \mod 2 = a_i \mod 2$、したがって、のパリティ$n$2 を法としたすべての桁の合計です。 

この洞察により、問題は最後の桁 (偶数基数) をチェックするか、すべての桁をモジュロ 2 で合計するか (奇数基数) のいずれかに集約されます。 ブルートフォース手法ではとにかく桁を反復処理しますが、最適な手法では桁ごとに単純なモジュロ演算を 1 つだけ実行し、大きな整数演算を完全に回避します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k log n) | お(1) | 膨大な数のため遅すぎる |
 | 最適 | O(k) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ベースを読む`b`そして桁数`k`。 これらは、指定された基数での数値の構造を定義します。 
2. を読んでください。`k`数字をリストに入れる`a`。 これらは、最も重要なものから最も重要でないものの順に並べられます。 
3. 次のことを確認します。`b`は均等です。 そうであれば、次のすべての力が`b`ゼロより大きい場合は偶数です。 したがって、最後の桁を除くすべての寄与はパリティとは無関係です。 
4. もし`b`偶数の場合、最後の桁の場合は「偶数」を出力します`a[-1]`は偶数、そうでない場合は「奇数」を出力します。 
5. もし`b`が奇数の場合、すべての桁を反復処理し、2 を法とする合計を計算します。合計が 2 で割り切れる場合は、「even」を出力します。 それ以外の場合は「奇数」を出力します。 

機能する理由: モジュロ 2 を減算する場合、偶数を乗算すると 0 が得られるため、奇数の底の奇数乗を乗算した数字のみが寄与します。 このアルゴリズムは、現在のモジュロ 2 の合計が各ステップでの数値全体のパリティを正確に反映するという不変条件を維持します。 これにより、完全な値を計算しなくても正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

b, k = map(int, input().split())
a = list(map(int, input().split()))

if b % 2 == 0:
    print("even" if a[-1] % 2 == 0 else "odd")
else:
    total = sum(a) % 2
    print("even" if total == 0 else "odd")
```このソリューションはまず、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 基本パリティをすぐにチェックします。 偶数基数の場合、最後の桁のみがチェックされるため、不必要な計算が回避されます。 奇数基の場合、2 を法とするすべての桁を合計し、完全な整数を構築することなく、結果が数値のパリティと一致することを保証します。 Off-by-one エラーは、最後の桁に正しくインデックスを付けることで回避されます。`a[-1]`。 

## 実用的な例

 サンプル 1:`13 3`数字付き`[3, 2, 7]`。 

| ステップ | 説明 | 値 |
 | --- | --- | --- |
 | b、kを読む | 13 進数、3 桁 | b=13、k=3 |
 | 数字を読み取る | 桁リスト | a=[3,2,7] |
 | チェック b パリティ | 13は奇数です | sum(a) % 2 = (3+2+7)%2 = 12%2 = 0 |
 | 出力 | 偶数 | 「偶数」 |

 これは、基数が奇数の場合、2 を法とするすべての桁の合計によりパリティが正しく決定されることを示しています。 

サンプル 2:`2 5`数字付き`[1, 0, 0, 1, 1]`。 

| ステップ | 説明 | 値 |
 | --- | --- | --- |
 | b、kを読む | 基数 2、5 桁 | b=2、k=5 |
 | 数字を読み取る | 桁リスト | a=[1,0,0,1,1] |
 | チェック b パリティ | 2 は偶数です | 最後の桁 a[-1] = 1 -> 奇数 |
 | 出力 | 奇数 | 「奇妙」 |

 これは、偶数基の場合は最後の桁のみが重要であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k) | 桁リストを 1 回通過して、剰余 2 を合計します (または最後の要素を取得します)。 
| スペース | O(k) | 数字のリストを保存する |

 与えられた`k <= 10^5`, O(k) 操作は 1 秒の制限内に十分収まり、100,000 個の整数のメモリ使用量は 256 MB 以内に収まります。

import sys, io

def run(inp: str) -> str:

    if b % 2 == 0:
        return "even" if a[-1] % 2 == 0 else "odd"
    else:
        return "even" if sum(a) % 2 == 0 else "odd"
