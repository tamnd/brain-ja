 ## 解決策
 ## 問題の理解

 平面の左側の固定開始位置から右側の固定終了位置まで移動する点の連続パスを計画しています。 水平方向の変位は固定されていますが、動きが連続的で単位速度で移動する限り、平面内の任意の曲線を自由に選択できるため、総移動時間は経路長に等しくなります。 

途中、単位時間あたりのバックグラウンドコストが一定であり、さらに垂直線上に1つまたは2つの固定の「放射性源」が配置されます。$x = 0$。 各ソースのコストは、その点までの距離の逆二乗に応じて急激に増加します。 したがって、パスの総コストは、パスの長さに、各アイランドからのすべての逆二乗距離の寄与の時間積分を加えたものになります。 

タスクは、この合計累積コストを最小化する幾何学的パスを選択することです。 

重要な構造上の詳細は、すべての島が同じ垂直線上にあることです。 これにより、ポテンシャルを含む一般的な最短経路で期待されるほとんどの対称性が破壊されます。これは、すべての「相互作用」は経路が近付いた場合にのみ発生するためです。$x = 0$。 その領域の外では、コストは純粋に加算され、均一になります。 

制約の観点から見ると、島の数は非常に少なく、多くても 2 つです。 これは、パス形状に対する最適化が低次元である限り、候補パスごとにどのような解も重くすることができることを直ちに示唆しています。 単純に平面を離散化したり、すべての曲線を検索しようとすると、無限次元の最適化を扱うことになり、これは実行不可能です。 コスト評価自体には連続積分が含まれるため、細かいグリッドをサンプリングするだけでも遅すぎます。 

よくある微妙な失敗のケースは、最適なパスが常に直線であると想定していることから発生します。 

たとえば、次の場所にある 1 つの島について考えてみましょう。$(0, 0)$、 始める$(-10, -1)$、 終わり$(10, 1)$。 直線は島の最も近くを通過します$x = 0$、逆二乗項はその点の近くで爆​​発します。 最小距離を増やすために上または下に曲がるわずかに長いパスは、長さが増加するよりも積分を減少させる可能性があります。 したがって、直線に制限することは一般的には正しくありません。 

もう 1 つの落とし穴は、パスが次の単一の「中間点」を通過する必要があると想定していることです。$x=0$線形補間によって決定されます。 これも失敗します。コスト関数が交差点の垂直座標で非線形であるためです。 

## アプローチ

 ブルートフォースの観点では、考えられるすべての連続曲線を最初から最後まで考慮し、それらの積分を計算しようとします。 多くのセグメントを持つ区分的線形パスに限定したとしても、自由度の数は大きくなり、最適化は高次元の連続問題になります。 各候補パスの評価にはすでに有理関数の統合が必要であるため、形状に対する組み合わせ検索は絶望的になります。 

重要な観察は、すべての特異点が 1 本の垂直線上にあるということです。 これは、パスが左半平面からどのように通過するかだけが「重要」であることを示唆しています$x < 0$右半平面へ$x > 0$。 各半平面の内部には点光源がないため、コストは経路長と、線上の固定点までの距離のみに依存する滑らかな寄与だけです。 

この構造は、最適なパスを得るには、単一の幾何学的自由度、つまりパスが線と交差する点を決定するだけでよいことを意味します。$x = 0$。 交差点が固定されると、各側の最適なサブパスは直線セグメントになります。これは、各半平面では、アイランドまでの距離プロファイルを調整する以外に曲げる理由がなく、その効果はエンドポイントによって完全に決定されるためです。 

したがって、問題は実際の値を選択することになります$y^\*$、交差する高さ$x = 0$。 完全なパスは 2 つの直線セグメントになります: 開始点から$(0, y^\*)$、そしてから$(0, y^\*)$目的地へ。 それぞれの選択に対して、$y^\*$、閉じた形式で正確なコストを計算できます。 

島は最大でも 2 つあるため、1 つの候補を評価する$y^\*$継続的な作業なので、最適化することができます$y^\*$結果として得られるコスト関数が滑らかで単峰性であるため、三分探索を使用します。

 ## アルゴリズムのチュートリアル

 パスを可変点で交わる 2 つの直線セグメントとして扱います$(0, y)$。 アルゴリズムはこれを最適化します$y$。 

1. 交差点の高さの候補を決定する$y$。 両方のセグメントが固定端点と端点の間の直線であるため、これによりパスのジオメトリが完全に決定されます。$(0, y)$。 
2. 2 つのセグメントの幾何学的長さを計算します。 左側のセグメントの長さは$\sqrt{10^2 + (y - A)^2}$、右のセグメントの長さは$\sqrt{10^2 + (B - y)^2}$。 これは、移動時間と一定の背景放射線を考慮したものです。 
3. 各島について、$(0, C_i)$、両方のセグメントでの寄与を個別に計算します。 各セグメントに沿った島までの二乗距離はセグメント パラメーターの二次関数であるため、次の積分は$1/d^2$閉じた形式の逆正接式に変換されます。 
4. すべての島と両方のセグメントからのすべての寄与を合計して、総コストを取得します。$f(y)$。 
5. 三項検索を実行します$y$合間に$[-10, 10]$（または安全範囲がわずかに拡大されます）。 それぞれの評価は、$O(N)$、そしてそれ以来$N \le 2$、これは実際には一定の時間です。 
6. の最小値を返します。$f(y)$。 

なぜそれが機能するのかは、コスト関数の構造に関係しています。 各半平面内で端点が固定されると、直線セグメントからの逸脱は経路長を線形に増加させますが、追加の極小値を作成しない滑らかな方法で積分項にのみ影響を与えます。 唯一のグローバルな自由度は、特異な線を横切りながらパスが各島にどれだけ近づくことができるかです。$x=0$。 その相互作用は単一のパラメータによって完全にキャプチャされます$y$、コスト効果が 1 変数の滑らかな関数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

EPS = 1e-12

def segment_cost(x1, y1, x2, y2, islands):
    dx = x2 - x1
    dy = y2 - y1

    length = math.hypot(dx, dy)
    total = length

    for c in islands:
        b = y1 - c
        k = dy / dx

        A = 1.0 + k * k
        B = 2.0 * k * b
        C = b * b

        D = 4.0 * A * C - B * B
        if D < 0:
            D = 0.0
        sqrtD = math.sqrt(D)

        def F(x):
            return math.atan((2.0 * A * x + B) / (sqrtD + EPS))

        val1 = F(x1)
        val2 = F(x2)

        total += (2.0 / (sqrtD + EPS)) * (val2 - val1)

    return total

def solve_case(N, A, B, Cs):
    islands = Cs

    def f(y):
        cost = 0.0
        cost += segment_cost(-10.0, A, 0.0, y, islands)
        cost += segment_cost(0.0, y, 10.0, B, islands)
        return cost

    lo, hi = -10.0, 10.0

    for _ in range(80):
        m1 = lo + (hi - lo) / 3.0
        m2 = hi - (hi - lo) / 3.0
        if f(m1) < f(m2):
            hi = m2
        else:
            lo = m1

    return f((lo + hi) / 2.0)

def main():
    T = int(input())
    for tc in range(1, T + 1):
        parts = input().split()
        N = int(parts[0])
        A = float(parts[1])
        B = float(parts[2])

        Cs = list(map(float, input().split())) if N > 0 else []

        ans = solve_case(N, A, B, Cs)
        print(f"Case #{tc}: {ans:.6f}")

if __name__ == "__main__":
    main()
```コードはまず、幾何学的な長さと逆二乗放射積分の両方を組み合わせて、単一の直線セグメントの寄与を評価する関数を定義します。 各島は個別に処理され、合計コストに追加されます。 

中心的な考え方は、唯一の自由変数は交差点の高さであるということです。$y$したがって、ソルバーはすべてを関数にラップします$f(y)$そして三項検索を実行します。 80 回の反復を選択すれば、必要な条件下で数値安定性を達成するには十分です。$10^{-3}$エラー許容度。 

この式には 2 次の分母が含まれ、小さな判別式の近くでは数値が不安定になるため、積分の計算には注意が必要です。 イプシロンが小さいと、逆正接の評価が安定します。 

## 実用的な例

 島が次の場所にある単一の島のシナリオを考えてみましょう。$C_1 = 0$、スタートは$( -10, -2 )$、そして最後は$(10, 2)$。 

3 つの候補交差点の高さを評価します。 

| y | 左セグメントのコスト | 右セグメントのコスト | 合計 |
 | --- | --- | --- | --- |
 | -2 | 左に短く、島から遠い | 右に長いほど島から遠ざかる | 中 |
 | 0 | 対称、島に最も近い | 対称、島に最も近い | 高い |
 | 2 | 左が長い、島から遠い | 右に短く、島から遠ざかる | 中 |

 これは、島の高さから離れるとコストが最小化されることを示しています。 

2 つの島の場合、トレードオフは両方の島への距離のバランスをとることになります。$C_1$そして$C_2$、そして最適な$y$それらの間にあります。

 ## 特殊なケース

 島がない場合、アルゴリズムは最初から最後まで直線セグメントを選択します。 三分探索では、幾何学的長さのみを含む関数が評価され、凸関数の一貫した中点動作で最小値が正しく発生します。 

交差する高さのとき$y$島座標に近づく$C_i$の場合、逆二乗特異点により積分項が大きくなります。 逆正接計算の数値安定化により、関数がすべてのテスト値に対して有限のままであることが保証され、三値探索ではコストが大幅に増加するため、特異領域を自然に回避できます。 

両方の島が存在し、互いに非常に近い場合、コストの状況はそれらの間で急激にピークになります。 両方の寄与が交差高さにおいて凸であるため、単峰構造は依然として維持され、結合された関数は三分探索で確実に特定できる単一の最小値を保持します。
