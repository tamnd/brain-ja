 ## 解決策
 ## 問題の理解

 1 から N までの番号が付けられた部屋の列が与えられます。ゲストは 1 人ずつ到着し、各ゲストには、割り当ての時点ではまだ空である、隣接する 2 つの部屋が割り当てられなければなりません。 隣接する空のペアが複数存在する場合、そのうちの 1 つが均一にランダムに選択されます。 これら 2 つの部屋は永続的に占有されます。 これは、隣接する空のペアが廊下のどこにも残らなくなるまで続き、その時点でプロセスは停止します。 

固定の部屋 K の場合、プロセスが終了したときにこの部屋が最終的に占有される確率が求められます。 

重要な点は、プロセスが決定的ではないということです。 すべてのステップで、どの隣接する空のペアを占有するかの選択によりランダム性が導入され、選択が異なると最終構成も異なります。 1 つの結果をシミュレートしているのではなく、考えられるすべての有効なランダム履歴を平均しています。 

この制約により、N は 10^7 まで許容され、プロセスをステップごとにシミュレートするアプローチは即座に除外されます。 T が大きい場合、テスト ケースごとに O(N) であっても、最悪の場合には遅すぎます。 ソリューションでは、前処理後に各テスト ケースがほぼ対数時間または定数時間で回答できるように、強力な構造の単純化を利用する必要があります。 

K が境界付近にない場合、微妙なエッジ ケースが発生します。 たとえば、N = 4 および K = 2 の場合、部屋 2 は常に最大プロセスの選択されたペアの一部であるため、答えは常に 1 になります。 素朴な直観では、すべての部屋が独立して空き状態を維持できる可能性があると考えるかもしれませんが、実際には、最終構成でペアが解除されたままにできるのは境界部屋だけです。 内部の部屋は構造的に、すべての最大結果で一致することが強制されます。これは、パス上での貪欲な隣接一致の動作の結果です。 

最初の選択でコリドーが切断されたセグメントに分割される場合、別の注意が必要な状況が発生します。 たとえば、小さな廊下でペア (2、3) を選択すると、部屋 1 が即座に隔離されます。その時点以降、部屋 1 には二度と触れることができなくなります。 この種の不可逆的な分離は、解決策を推進する中心的な構造です。 

## アプローチ

 直接シミュレーションでは、すべての有効な隣接する空のペアのセットを維持し、均一にランダムに 1 つを選択し、そのエンドポイントを削除し、ペアがなくなるまで繰り返します。 これは概念的には正しく、プロセスを正確に反映しています。 ただし、各ステップでは利用可能なエッジの動的なセットを更新する必要があり、合計で O(N) のステップがあります。 N が大きい複数のテスト ケースでは、これは実行不可能になります。 

重要な観察は、プロセスが連続する空き部屋の接続されたセグメントを超えたジオメトリに依存しないことです。 ペアが選択されると、コリドーは左右のセグメントの独立したサブ問題に分割されます。 各セグメントの展開は、より小さい N に関する元の問題と統計的に同一です。 

この再帰的分解は、マッチング プロセス全体をシミュレートする必要がないことを示唆しています。 代わりに、セグメント サイズの観点からイベントの確率を推論し、再発を導き出すことができます。 

重要な単純化は、コリドーの終点のみが異なる動作をすることです。 厳密に廊下の内側にある部屋は常に、すべての最大結果で最終的に一致するため、その確率は 1 です。問題全体は、エンドポイントの部屋が一致する確率を計算することに帰着します。 

次に、長さ n の廊下に部屋 1 が占有されている確率 f(n) の計算に焦点を当てます。 最初に選択されたペアは、n-1 個の隣接するペアに均一に分散されます。 どのペアが最初に選択されるかに応じて、部屋 1 をすぐに一致させるか、永久に隔離するか、問題を小さな独立した廊下に縮小するかのいずれかになります。 

これにより、プレフィックス サイズを完全に反復することができ、すべてのテスト ケースの最大 N にわたって線形時間で評価できます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | ステップあたり O(N)、合計 O(N^2) | O(N) | 遅すぎる |
 | プレフィックス DP の繰り返し | O(最大N) | O(最大N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ここでは、n 個の部屋があるときに部屋 1 が占有されている確率 f(n) の計算に焦点を当てます。 

1. f(n) を、一番左の部屋が占有される確率として定義します。 
2. 最初に選択された隣接するペアを検討します。 可能なペアは正確に n−1 個あり、すべて同じ確率です。 
3. 最初に選択されたペアが (1, 2) の場合、部屋 1 はすぐに占有されるため、確率は 1 になります。 
4. 最初に選択したペアが (2, 3) の場合、部屋 1 は単一の空の部屋として分離され、将来のペアの一部になることはできないため、寄与率は 0 になります。 
5. 最初に選択したペアが (k, k+1) (k ≥ 3) の場合、コリドーはサイズ k−1 の左セグメントとサイズ n−k−1 の右セグメントに分割されます。 右側のセグメントは部屋 1 には無関係で、左側のセグメントはサイズ k−1 の新しい問題とまったく同じように動作します。 したがって、寄与は f(k−1) になります。 
6. すべての可能性を合計すると、f の以前の値に関して漸化式が得られます。 
7. これを効率的に評価するには、プレフィックスの合計 S(n) = f(1) + f(2) + … + f(n) を維持します。 これにより、前処理後に各 f(n) を O(1) 時間で計算できます。 
8. ペアが存在しないため、基本ケースとして f(1) = 0 を計算します。 
9. 繰り返しを使用して f(2)、f(3)、... を最大 N まで繰り返し計算し、途中でプレフィックスの合計を保存します。 

任意のクエリ (N, K) について、K が 1 または N の場合は f(N) を返し、それ以外の場合は 1 を返します。 

### なぜ効果があるのか

 プロセス全体は、パス上でのランダムな貪欲なマッチングです。 頂点が一致しない状態を維持できる唯一の方法は、周囲の構造がフリーズする前に、頂点に付随するすべてのエッジが選択されない場合です。 内部頂点の場合、パスを最大限に一致させるとすべての内部構造が強制的にカバーされるため、これは不可能です。 一致しない内部頂点があると、2 つの隣接する自由な頂点が残り、最大性と矛盾します。 これにより、問題はエンドポイント生存のみの分析に縮小されます。 

繰り返しは、プロセスの最初のステップの分解を捉えます。 すべての結果は最初に選択されたエッジによって分割され、各ブランチはルーム 1 ですぐに終了するか、厳密に小さい独立したインスタンスに縮小されます。 これにより、ケース間の重複がなくなり、総確率質量が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    T = int(input())
    queries = []
    max_n = 1

    for _ in range(T):
        n, k = map(int, input().split())
        queries.append((n, k))
        max_n = max(max_n, n)

    if max_n >= 1:
        f = [0] * (max_n + 1)
        pref = [0] * (max_n + 1)

        f[1] = 0
        pref[1] = 0

        for n in range(2, max_n + 1):
            # f(n) = (1 + sum_{i=2..n-2} f(i)) / (n-1)
            total = 1 + (pref[n - 2] - pref[1])
            if total < 0:
                total %= MOD
            inv = pow(n - 1, MOD - 2, MOD)
            f[n] = (total % MOD) * inv % MOD
            pref[n] = (pref[n - 1] + f[n]) % MOD

    out = []
    for n, k in queries:
        if k != 1 and k != n:
            out.append(f"Case #: 1")
        else:
            out.append(f"Case #: {f[n]}")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、問題を前処理フェーズとクエリ フェーズに分割します。 前処理では、合計の繰り返しの再計算を避けるために、導出された再帰とプレフィックス合計配列を使用して、すべてのテスト ケースにわたって f[n] が最大 N まで構築されます。 

クエリ ロジックは即時です。 K がコリドーの両端にない場合、答えは常に 1 です。それ以外の場合は、事前に計算された終点確率 f[N] を返します。 

モジュール分割には注意が必要です。 10^9+7 を法として処理するため、(n−1) による除算は逆剰余を使用して実装されます。 

## 実用的な例

 N = 4、K = 1 の場合を考えてみましょう。最初に考えられる最初の手は、3 つの隣接するペア (1,2)、(2,3)、および (3,4) で、それぞれの確率は 1/3 です。 

| 最初のペア | 結果の構造 | 部屋1の運命 |
 | --- | --- | --- |
 | (1,2) | 部屋 1 はすぐに使用されました | 占有中 |
 | (2,3) | 部屋 1 は永久に隔離されます | 無料 |
 | (3,4) | 右側の小さなセグメントに縮小します。 最終的には再帰によって占有される |

 したがって、確率は 2/3 となり、既知の結果と一致します。 

ここで、N = 5、K = 2 について考えてみましょう。部屋 2 は内部です。 最初にどのペアが選択されるかに関係なく、それは直接一致するか、最終的に一致する必要がある小さなセグメントの一部になります。 構成を最大に保ちながら、最後に部屋 2 を分離したままにする一連の選択はありません。 したがって、確率は 1 になります。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(最大N) | 各 f[n] はプレフィックスの合計を使用して 1 回計算されます。 
| スペース | O(最大N) | DP およびプレフィックス配列を最大 N | まで保存します。 

前処理は、テスト ケース全体の最大コリドー サイズに応じて線形にスケールされます。これは、最適化された Python の単一パスで最大 10^7 までの N が許容され、コンパイル言語の制限内に簡単に収まります。 各クエリは O(1) で回答されます。 

## テストケース```python
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    T = int(input())
    queries = []
    max_n = 1

    for _ in range(T):
        n, k = map(int, input().split())
        queries.append((n, k))
        max_n = max(max_n, n)

    f = [0] * (max_n + 1)
    pref = [0] * (max_n + 1)

    for n in range(2, max_n + 1):
        total = 1 + pref[n - 2]
        inv = pow(n - 1, MOD - 2, MOD)
        f[n] = (total % MOD) * inv % MOD
        pref[n] = (pref[n - 1] + f[n]) % MOD

    out = []
    for i, (n, k) in enumerate(queries, 1):
        if k != 1 and k != n:
            out.append(f"Case #{i}: 1")
        else:
            out.append(f"Case #{i}: {f[n]}")

    return "\n".join(out)

# custom cases
assert run("1\n2 1\n") == "Case #1: 1"
assert run("1\n2 2\n") == "Case #1: 1"
assert run("1\n5 3\n") == "Case #1: 1"
assert run("1\n4 1\n") == "Case #1: 666666672"

 | N=2 エンドポイント | 1 | 最小のエッジケースの正確性 |
 | 対称エンドポイント | 1 | 両端は同じように動作します。 
| インテリアルーム | 1 | 内部は常に占有されています |
 | N=4 エンドポイント | 2/3 | 自明でない確率の再発 |

 ## 特殊なケース

 N = 2 の場合、可能な移動は (1,2) のみであるため、両方の部屋が常に占有されています。 アルゴリズムは正しく f(2) = 1 を返します。 

N = 5、K = 3 などの内部位置の場合、パス上のすべての有効な最大一致がその頂点をカバーする必要があります。 DP ロジックでは、そのような場合は f(n) をクエリすることさえありません。 それらはすぐに確率 1 として解決されます。 

N = 4、K = 1 のようなエンドポイントのケースでは、反復により 3 つの対称的な最初の手が正しく考慮され、即時成功、即時失敗、再帰的継続の確率がより小さなセグメントに分散されます。
