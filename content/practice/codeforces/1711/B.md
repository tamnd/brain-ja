 ## 解決策
 ## 問題の理解

 私たちは、あるクラブのパーティーを企画するよう頼まれました。$n$メンバー。 各メンバーは、招待されなかった場合に潜在的に不幸になる値を持っています。 同クラブはメンバー間の友情も追跡しており、友人同士がいる場合は各ペアでケーキを食べるという。 オーブンは一度に 2 つのケーキしか焼けないので、消費されるケーキの総数は偶数でなければなりません。 私たちの目標は、食べられるケーキの数が均等になるようにしながら、全体的な不幸を最小限に抑えることです。 

入力は複数のテスト ケースを提供します。 各テスト ケースでは、メンバーの数、友情の数、不幸の値の配列、および友情のペアが示されます。 出力は各テスト ケースの単一の整数、つまりケーキ パリティ制約の下で達成可能な最小の不幸せ度です。 

制約により許可されるのは、$n$まで$10^5$そして$m$まで$10^5$、すべての合計$n$そして$m$テストケース全体にわたって$10^5$。 これは、およそよりも複雑なアルゴリズムはすべて、$O(n + m)$テストケースごとにタイムアウトになる可能性があります。 メンバーのすべてのサブセットに対するネストされた反復。$O(2^n)$、明らかに実行不可能です。 

エッジケースには、友情のないパーティー、ケーキの同等性が些細に満たされるパーティー、またはポジティブな不幸を抱えたメンバーが 1 人いる場合などが含まれます。 別の微妙なケースは、すべてのメンバーが奇数の長さのサイクルを形成する友情を持っている場合に発生し、偶数ケーキのルールを満たすために慎重な選択を余儀なくされる可能性があります。 友情の同等性を無視した単純なアプローチでは、誤った結果が生じる可能性があります。 たとえば、次の場合$n=2$、$m=1$、 そして$a=[1,2]$、両方を招待すると 1 つのケーキ (奇数) が作成されますが、これは無効です。 正しいアプローチは、メンバーを 1 人だけ招待することです。その結果、不幸が生じます。$1$または$2$。 

## アプローチ

 ブルートフォースアプローチでは、メンバーのすべてのサブセットを列挙し、消費したケーキの数と各サブセットの合計不幸度を計算し、最小の不幸度を持つ有効なサブセットを選択します。 これは問題の制約を直接エンコードするため原理的には機能しますが、複雑さが伴います。$O(2^n \cdot m)$、これは非現実的です$n$まで$10^5$。 

重要な洞察は、ケーキの同等性は含まれる友情ペアの数によって決まるということです。 友情を無視する場合は、メンバー全員を招待することで不幸が最小限に抑えられます。$0$。 そのシナリオのケーキの数が偶数であれば、完了です。 奇数である場合は、メンバーを 1 人だけ削除するか、招待を調整してパリティを反転する必要があります。 奇数のケーキに触れる、関連する不幸が最小のメンバーを削除すると、不幸の増加が最小限に抑えられます。 すべてのメンバーが次数 0 を持つエッジ ケースの場合、パリティは自動的に満たされます。 

この観察により、問題は友情グラフをスキャンし、各メンバーの次数 (メンバーが参加している友情の数) を計算し、パリティ制約を満たすための最小不幸調整を評価することに帰着します。 複雑さは次のようになります$O(n + m)$テストケースごとに、これは許容可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * m) | O(n + m) | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$、$m$、そして不幸の配列$a$。 
2. 不幸全体を初期化する$total_a$すべての合計として$a_i$。 これは、誰も招待されないシナリオを表します。 
3. 友情がない場合、ケーキの数はゼロ (偶数) なので、出力$0$そして続けます。 
4. 各メンバーの程度、つまり、参加している友情の数を数えます。 
5. 全員が招待された場合の友情ペア (ケーキ) の合計数を計算します。 この数が偶数の場合、メンバー全員を招待し、$0$不幸。 
6. ケーキの総数が奇数の場合、パリティを調整する必要があります。 2 つのオプションを検討します。不幸が最も小さいメンバーを削除します。$a_i$奇数の学位を持つメンバーの中から、または最小限の金額で友情で結ばれたメンバーのペアを削除する$a_i + a_j$。 
7. いずれかの調整によって引き起こされる最小の不幸の増加を計算し、それを加算します。$0$最後の最小限の不幸を得るために。 
8. 結果を出力します。 

機能する理由: このアルゴリズムは、ケーキの個数が偶数であるという制約の下で不幸が最小限に抑えられるという不変条件を維持します。 平等が許される場合、メンバー全員を招待すると不幸が最小限に抑えられます。 パリティが奇数の場合、奇数次のメンバーを 1 つ削除するか、合計が最小の友情ペアを削除することで常にパリティを反転できます。これにより、不幸の増加を最小限に抑えることが保証されます。 最小限のコストの調整のみを考慮しているため、これより優れたソリューションは存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    deg = [0] * n
    edges = []
    for _ in range(m):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        deg[x] += 1
        deg[y] += 1
        edges.append((x, y))
    
    total_cakes = m
    if total_cakes % 2 == 0:
        print(0)
        continue
    
    # Option 1: remove member with odd degree and minimal a[i]
    min_single = float('inf')
    for i in range(n):
        if deg[i] % 2 == 1:
            min_single = min(min_single, a[i])
    
    # Option 2: remove one friendship pair with minimal a[x]+a[y]
    min_pair = float('inf')
    for x, y in edges:
        min_pair = min(min_pair, a[x] + a[y])
    
    print(min(min_single, min_pair))
```コードは最初にメンバーの度合いと合計友情数を計算します。 ケーキの総数が偶数の場合、印刷されます。$0$。 それ以外の場合は、単一の奇数次メンバーまたは友情ペアを削除して同等性を修正するための最小の不幸コストを見つけます。 境界チェックにより、空の友人リストによってエラーが発生しないことが保証されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各メンバーとエッジは度数と最小和を求めて 1 回スキャンされます。 
| スペース | O(n + m) | 度数の配列とエッジのリストを保存する |

 このアルゴリズムは、次の最大合計であっても 2 秒の制限内に簡単に収まります。$n$そして$m$すべてのテストケースにわたって、$n + m \le 10^5$。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    t = int(input())
    res = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        deg = [0] * n
        edges = []
        for _ in range(m):
            x, y = map(int, input().split())
            x -= 1
            y -= 1
            deg[x] += 1
            deg[y] += 1
            edges.append((x, y))
        
        total_cakes = m
        if total_cakes % 2 == 0:
            res.append("0")
            continue
        
        min_single = float('inf')
        for i in range(n):
            if deg[i] % 2 == 1:
                min_single = min(min_single, a[i])
        
        min_pair = float('inf')
        for x, y in edges:
            min_pair = min(min_pair, a[x] + a[y])
        
        res.append(str(min(min_single, min_pair)))
    return "\n".join(res)
