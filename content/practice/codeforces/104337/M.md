 ## 問題の理解

 合計でコンテストが与えられます$x$参加チーム。 すべてのチームは 3 つのカテゴリのうちの 1 つに正確に属し、各カテゴリはホストに固定金額を寄付します。 

最初のカテゴリーのチームは何も貢献しません。 2 番目のカテゴリーのチームはちょうど 1000 ドルを寄付します。 3 番目のカテゴリーのチームは、物流費として 1000 ドルとエントリー費として 1500 ドルを分割して、合計 2500 ドルを寄付します。 すべてのチームにわたるホストの総収益は次のとおりです。$y$, しかし、3つのカテゴリーへの内訳は失われています。 

タスクは、有効なトリプルを再構築することです。$(A, B, C)$チームの合計数が次のように 3 つのチーム タイプの数を表します。$A + B + C = x$そして総収益は$1000B + 2500C = y$。 そのような分解が存在しない場合は、次のように出力する必要があります。$-1$。 

制約により許可されるのは、$x$まで$10^6$そして$y$まで$10^9$。 これにより、可能なすべてのトリプルを列挙しようとするアプローチは即座に除外されます。$B$そして$C$まで必要になります$10^{12}$最悪の場合は状態。 有効な解決策では、問題を一定数の算術チェックに減らす必要があります。 

整合性を強制せずに、平均または貪欲な選択のみについて推論すると、微妙な失敗例が発生します。 たとえば、次の場合$x = 3$そして$y = 2500$1 つのタイプ C チームを割り当て、残りをタイプ A に割り当てようとするかもしれませんが、それは結果をもたらします。$C=1, B=0, A=2$、合計を与える$2500$、これは有効です。 ただし、$y = 1500$、必要になります$B=1, C=0$、出発$A=2$、しかし、もし$y = 2000$、整数の組み合わせは存在しません。 これは、実現可能性が近似ではなくディオファントス系を解くことに依存していることを強調しています。 

もう 1 つのエッジケースは次のような場合です$y$～に比べて小さすぎるか大きすぎます$x$。 最小値は 0 (すべてタイプ A)、最大値は$2500x$(すべてタイプC)。 この範囲外の値は直ちに不可能になります。 

## アプローチ

 ブルートフォース戦略は、可能なすべての値を反復処理することです。$C$0から$x$、それぞれについて、残りの予算を計算し、タイプ B チームを使用してそれを埋めることができるかどうかを確認します。 固定の場合$C$、方程式は次のようになります$1000B = y - 2500C$、 それで$B$余りが 1000 で割り切れる場合は一意に決定され、$A$から派生した$x - B - C$。 このアプローチは、次のすべての組み合わせを直接テストするため、正しいです。$C$、しかしそれは実行します$O(x)$反復、$x = 10^6$限界に達していますが、Python では厳密な最適化を行った場合にのみ許容されます。 ただし、方程式の構造により、反復を完全に回避できます。 

重要な観察は、すべてが直線的であるということです。$B$そして$C$、および係数$B$の係数は 1000 ですが、$C$方程式全体を 500 で除算すると、はるかに小さなシステムに簡略化されますが、スケーリングを行わなくても、2 つの変数と合計制約を持つ単一の線形ディオファントス方程式として扱うことができます。 検索する代わりに、1 つの変数を直接削除します。 

私たちは表現します$B = x - A - C$を収益方程式に代入します。 これにより、次の 1 つの方程式が生成されます。$A$そして$C$、しかし、さらにクリーンなアプローチは、次のように修正することです。$C$1000 を法とする方程式の構造を暗黙的に使用します。タイプ B は正確に 1000 に寄与するため、タイプ C のみが 1000 を法とする剰余に影響します。これにより、$2500C \equiv 500C \pmod{1000}$、 それで$y \bmod 1000 = 500C \bmod 1000$。 これにより直ちに制限がかかります$C$最大 2 つの剰余クラスを法 2 に変換し、最大 2 つの候補に対する定数時間検索を可能にします。 

一度$C$固定されており、$B$の寄与を差し引くことによって正確に決定されます。$C$、実現可能性は次のことを確認することに帰着します。$B$が非負であるかどうか$A = x - B - C$も非負です。

 ## アルゴリズムのチュートリアル

 タイプ B チームはちょうど 1000 を貢献し、タイプ C チームは 2500 を貢献するという観察から始めます。これにより、すべてが 500 の倍数で調整されるため、システムは高度に構造化されます。 

1. まず次のことを確認します。$y$0 から 0 までの実行可能な範囲内にあります$2500x$。 そうでない場合は、分解はまったく行われません。 このステップでは、代数を行う前に不可能なケースを排除します。 
2. 方程式を 1000 を法として換算します。$1000B$モジュロ 1000 が消えると、$2500C \equiv 500C \pmod{1000}$、 それで$y \bmod 1000$等しい必要があります$500C \bmod 1000$。 これはすぐに次のことを意味します$C$パリティのような条件を満たさなければなりません:$C$偶数か奇数かに応じて$y \bmod 1000$は 0 または 500 です。 
3. この制約から、最大 2 つの候補を試します。$C$: 剰余条件を満たす最小の非負の整数、およびその値に 2 を加えた値。合同式は 2 ステップごとに循環するため、可能性はこれらのみです。 
4. 各候補者について$C$、残りの寄与を計算します$y - 2500C$。 負の場合、または 1000 で割り切れない場合、この候補は無効です。 
5. 有効な場合、計算します。$B = (y - 2500C) / 1000$。 それから$A = x - B - C$。 かどうかを確認します$A$は非負です。 
6. いずれかの候補が有効な非負の整数を生成する場合、出力します。$(A, B, C)$。 それ以外の場合は出力します$-1$。 

### なぜ効果があるのか

 このシステムは、チーム数と総収益という 2 つの独立した線形制約によって完全に決定されます。 一度$C$固定されており、$B$割り算によって強制され、$A$合計制約によって強制されます。 モジュラー条件により、次の値のみをテストすることが保証されます。$C$これは収益方程式を満たす可能性があるため、有効な解決策はスキップされません。 すべての有効な解は同じ合同を満たす必要があるため、チェックされた候補の中に出現する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())

    if y < 0 or y > 2500 * x:
        print(-1)
        return

    # 2500C ≡ 500C (mod 1000)
    r = y % 1000

    # we try C such that 500*C % 1000 == r
    candidates = []

    # since 500*C mod 1000 cycles with period 2:
    # C even -> 0 mod 1000
    # C odd  -> 500 mod 1000
    if r == 0:
        c0 = 0
        c1 = 2
    elif r == 500:
        c0 = 1
        c1 = 3
    else:
        print(-1)
        return

    for C in (c0, c1):
        if C > x:
            continue
        remaining = y - 2500 * C
        if remaining < 0 or remaining % 1000 != 0:
            continue
        B = remaining // 1000
        A = x - B - C
        if A >= 0:
            print(A, B, C)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```このコードは、不可能な総収益範囲を拒否することから始まります。 次に、モジュロ 1000 構造を使用して検索を制限します。$C$意味のある候補者は最大でも 2 人までです。 候補ごとに、再構築します。$B$正確に除算して導き出します$A$チームの総数から。 

主な微妙な点はモジュラー削減です。タイプ B はちょうど 1000 に寄与するため、モジュロ 1000 が消え、剰余を制御するタイプ C だけが残ります。 だからこそ制限できるのです$C$正しさを失うことなく、とても積極的に。

 ## 特殊なケース

 主なエッジケースは次のような場合です$y = 0$。 アルゴリズムチェック$r = 0$、試してみます$C = 0$、すぐに取得します$B = 0$、$A = x$。 出力は、すべてのチームがタイプ A であることと一致します。 

もう 1 つのエッジケースは次のような場合です$y$最大値に近いです$2500x$。 例えば、$x = 4, y = 10000$すべてのチームを強制的にタイプ C にします。アルゴリズムは次のように評価します。$C = 4$、を取得します$B = 0$、 そして$A = 0$、有効な分解が生成されます。 

素朴な推論による失敗例は次のとおりです。$x = 2, y = 2500$。 貪欲なアプローチでは、タイプ C チームを 1 つ割り当て、残りをタイプ A のままにしようとするかもしれませんが、それでは 2500 人しか得られず、残りの構造はありません。 正しい推論では正確な可分性が強制され、両方の制約間の一貫性が保証されます。
