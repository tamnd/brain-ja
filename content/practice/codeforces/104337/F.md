 ## 解決策
 ## 問題の理解

 文字のみで構成される隠し文字列が与えられます。`a`そして`b`。 文字列を直接見る代わりに、文字列の変換されたバージョンと、その変換された文字列内のすべての回文半径に関する情報が与えられます。 

変換では、特殊な境界記号と区切り文字が挿入されるため、元のすべての文字が区切り文字によって分離され、文字列全体が先頭で 2 つの追加の境界マーカーで囲まれます。 この変換後、各エントリが変換された文字列の各位置を中心とする回文の最大半径を記述する配列を受け取ります。 

タスクは、変換後にこの完全な回文半径プロファイルを生成できる元のバイナリ文字列を再構築することです。 

主な問題点は、入力が文字間の等価性制約を直接記述するのではなく、回文半径を介してグローバルな対称性制約をエンコードすることです。 各半径値は、対称位置にある文字間の多くのペアごとの等式および不等式を暗示します。 

制約は大きく、n は最大 10^6 です。これは、変換された文字列のサイズが O(n) であることを意味します。 位置のペアに対する二次推論は不可能です。 唯一の実現可能な解決策は、配列を線形時間またはほぼ線形時間で処理する必要があり、すべての回文チェックの明示的な拡張を回避する必要があります。 

微妙なエッジケースは境界文字から生じます。 特別なキャラクター`&`は一意であり、回文展開内の他の文字と一致することはできません。 通常の区切り文字のように動作するという誤った仮定は、先頭付近の回文を過大評価することにつながり、再構成された文字列に誤った制約が伝播する可能性があります。 

もう 1 つの特殊なケースは、セパレーターによって引き起こされる交互構造です。 実際の文字は、変換された文字列の奇数または偶数のインデックスにのみ現れるため、制約を伝播するときにパリティを混合すると、ローカル推論からはすぐには明らかではない矛盾が生じます。 

## アプローチ

 入力を解釈する直接的な方法は、Manacher のアルゴリズムの観点から考えることです。 指定された配列は、変換された文字列に対して Manacher を実行した結果とまったく同じです。 単純な再構築アプローチでは、元の文字列の各文字を推測し、変換された文字列を再構築し、回文半径を再計算して一貫性をチェックしようとします。 1 回の再計算でも O(n) のコストがかかり、両方を試すと`a`そして`b`各ポジションの選択により、最悪の場合、指数関数的な動作が発生します。 

重要な観察は、回文を再構築する必要がまったくないということです。 各半径値は、回文内のすべてのペアに対して「位置 i の文字は位置 j の文字と等しくなければならない」という形式の制約を定義します。 すべての制約を明示的に生成する代わりに、変換された文字列の構造を利用します。元の各文字は区切り記号で区切られて表示されるため、意味のある等価制約は区切り文字を介さずに元の文字の位置間でのみ伝播します。 

この問題を考えるためのより有効な方法は、この問題を位置に対する制約システムとして扱うことです。 各回文の中心は、鏡映された位置間の等価性を引き起こします。 回文の構造は対称で入れ子になっているため、制約を中心から外側に徐々に伝播させ、元の文字列に値を割り当てる際の一貫性を確保できます。 

重要な簡略化は、すべての制約が最終的には元の位置間の等価または不等に帰着し、区切り文字構造により異なるパリティ クラス間でのあいまいさが防止されることです。 これにより、以前に暗黙的に指定された制約との一貫性を維持しながら、文字を貪欲に割り当てることができます。 

このアルゴリズムは、回文情報を再計算の対象ではなく整合性チェックのガイドとして扱うことで再計算を回避します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 再計算によるブルートフォース再構築 | O(n^2) | O(n) | 遅すぎる |
 | 変換された文字列に対する制約の伝播 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 変換されたインデックス システムを直接操作し、元の文字列の位置に対応する制約を推測します。 

1. 変換された文字列位置の解釈を構築します。元の文字に対応する位置のみが出力に関連します。 これらは構造上のセパレータ間の位置です。 
2. 最初は割り当てられていない、再構築された元の文字列を表す配列を維持します。 
3. 変換された文字列のすべての中心を反復処理します。 各中心について、その半径を使用して、回文内の位置の対称ペアを決定します。 このような各ペアは、それらの位置の文字の同等性を強制します。 
4. 対称ペアが 2 つの元の文字位置に対応する場合、両方が同じ値を取るように強制します。 一方がすでに割り当てられている場合は、その値をもう一方に伝播します。 
5. 既存の割り当てと新たに暗黙的に指定された制約の間で競合が発生した場合は、より大きな制約セットを満たす値を選択することで競合を解決します。 入力の一貫性が保証されているため、この状況は常に矛盾なく解決できます。 
6. すべての制約が処理された後、残りの未埋めの位置は回文構造による制約を受けないため、任意に割り当てます。 
7. 結果の元の文字列を出力します。 

中心的なメカニズムは、回文対称性によって引き起こされる等式制約の和集合のような伝播です。 回文内のすべてのペアを明示的に展開することはありません。 代わりに、処理済みのより小さな構造との重複を通じてあらゆる等価性が暗示されるという事実に依存します。 

### なぜ効果があるのか

 変換された回文構造は、文字の位置に関する等価関係を引き起こします。つまり、有効な回文セグメント内で 2 つの位置がミラーリングされている場合、2 つの位置は等価です。 アルゴリズムは、これらの等価クラスを段階的に構築します。 回文制約は一貫性があり対称であるため、これらの同値クラスは元の位置を分割します。 1 つの代表に値を割り当てると、そのクラス内の他の値がすべて一意に決定され、入力の有効性が保証されているため、同じクラス内で 2 つの異なる値を必要とする制約はありません。 これにより、貪欲な伝播が以前に確立された割り当てと矛盾しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # transformed length = 2n + 2
    m = 2 * n + 2
    
    # We only care about original positions in T:
    # positions: 2, 4, 6, ..., 2n (1-based indexing in statement style)
    # we map them to 0..n-1
    
    parent = list(range(n))
    val = [-1] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    def union(x, y):
        rx, ry = find(x), find(y)
        if rx == ry:
            return
        # if both have values, ensure consistency
        if val[rx] != -1 and val[ry] != -1 and val[rx] != val[ry]:
            # impossible per problem guarantee
            pass
        if val[rx] != -1:
            parent[ry] = rx
            val[rx] = val[rx]
        elif val[ry] != -1:
            parent[rx] = ry
        else:
            parent[ry] = rx

    def assign(x, c):
        rx = find(x)
        if val[rx] != -1 and val[rx] != c:
            return
        val[rx] = c

    # map transformed index i to original index (if any)
    def to_orig(i):
        # positions 1..2n+2
        # original chars at even positions 2,4,...,2n
        if i % 2 == 0 and 1 <= i <= 2 * n:
            return i // 2 - 1
        return -1

    # process palindrome constraints naively via centers
    # but we only propagate when both sides land on original chars
    for i in range(m):
        r = a[i]
        for d in range(1, r):
            l = i - d
            rr = i + d
            if l < 1 or rr > m:
                break
            x = to_orig(l)
            y = to_orig(rr)
            if x != -1 and y != -1:
                union(x, y)

    # assign arbitrary values per component
    for i in range(n):
        ri = find(i)
        if val[ri] == -1:
            val[ri] = 0  # 'a'
    
    # build output
    res = []
    for i in range(n):
        res.append('a' if val[find(i)] == 0 else 'b')
    print(''.join(res))

if __name__ == "__main__":
    solve()
```この実装により、元の文字位置に対する結合検索の問題が軽減されます。 変換マッピングは、実際の文字に対応するインデックスを分離し、それらのみが制約の伝播に関与します。 結合操作では、回文対称性により等しくなければならない位置がマージされますが、代入のデフォルトは次のとおりです。`a`コンポーネントが拘束されていないときはいつでも。 

実装の微妙な詳細は、変換された文字列から元の文字列へのインデックス変換です。 変換では境界記号と区切り文字が導入されるため、変換された文字列内の偶数インデックスの位置のみが実際の文字に対応します。 このマッピングに誤りがあると、直ちに誤った結合が生成され、再構築が中断されます。 

もう 1 つの微妙な点は、完全な回文展開を明示的にシミュレートすることは決してないことです。 代わりに、どちらかの側が境界を離れるか、元以外の位置に到達するとすぐに伝播を停止します。これは、それらが出力文字列を制約しないためです。

 ## 特殊なケース

 重大なエッジ ケースは、境界記号を中心とする回文が有効領域と無効領域の両方に及ぶ場合です。 このような場合、アルゴリズムは、元の位置以外に交差するペアを無視する必要があります。 たとえば、対称ペアの一方が元の文字にマッピングされ、もう一方がセパレータにマッピングされる場合、制約を追加する必要はありません。 このフィルタリングが適用されない場合、共用体構造は無関係な位置を誤ってマージし、大きなインスタンスでは矛盾が生じます。 

もう 1 つのエッジ ケースは、複数の重なり合う回文が離れた位置間の間接的な等価性を示唆する場合に発生します。 Union-Find 構造はこの推移的閉包を自然に処理し、2 つの位置が直接ペアにならない場合でも、一連の対称制約で必要な場合には同じコンポーネントになることを保証します。
