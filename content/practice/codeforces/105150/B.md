 ## 解決策
 ## 問題の理解

 私たちには 2 つの独立した累進課税システムと一定の総所得が与えられています。$X$。 ドミトリーとアンナはこの収入を 2 つの部分に分割する必要があります: ドミトリーは宣言します。$t$とアンナは宣言する。$X - t$。 各国は括弧内の所得に課税し、括弧内の所得のすべての部分に固定の割合で課税し、高所得部分には異なる税率で課税する場合があります。 

主な複雑な点は、両方の税関数が区分的に線形であるにもかかわらず、ブレークポイントと税率が異なる可能性があることです。 選択した分割について$t$、合計税額は 2 つの区分的線形評価の合計です。$t$そして1つは$X-t$。 課題は選択することです$t$それはこの合計を最小化します。 

制約は大きく、最大で$10^5$税水準と所得金額は以下のとおりです$10^{16}$。 これにより、素朴な単位当たりの方法で税金を評価したり、線形所得空間で増分的に拠出金を再計算したりするアプローチは即座に排除されます。 たとえ$O(X)$スイープは不可能なので、$X$できる$10^{16}$。 

より深い構造は、各税制が所得の凸型、連続型、区分線形関数を定義しているということです。 このような 2 つの関数の合計、1 つは次の関数に適用されます。$t$そしてもう一つは$X-t$、凸関数のままです。$t$。 これは、すべての値ではなくブレークポイントを検索することで最適なポイントを見つけられることを強く示唆しています。 

括弧の境界で微妙な問題が発生します。 ブレークポイントのみを考慮する単純な実装では、最適値が傾きが一定のセグメント内にある可能性があることを見逃す可能性があります。 もう 1 つのよくある落とし穴は、オーバーフローまたは傾きのプレフィックス合計の処理の誤りにより、大きな間隔で税金が誤って計算されることです。 

## アプローチ

 強引なアイデアとしては、考えられるすべての分割を試すことです。$t$から$0$に$X$、ブラケット定義を使用してドミトリーの税金とアンナの税金を別々に計算し、最小値を取得します。 これは、すべての有効な入力の目的関数を直接評価するため、正しいです。 ただし、単一の値に対して税金を評価するには括弧内を調べる必要があり、最悪の場合、これは次のようになります。$O(n + m)$。 まで組み合わせると$10^{16}$可能な値$t$、これは完全に不可能になります。 

重要な観察は、各税制が区分的線形関数であるということです。 隣接するしきい値間のどの間隔でも、限界税率は一定です。 つまり、合計税関数は既知のブレークポイント位置でのみ傾きが変化します。 ドミトリーの税金を次のように定義すると、$f(t)$そしてアンナの税金は$g(X-t)$の場合、総コストは次のようになります。$F(t) = f(t) + g(X-t)$。 いずれかのシステムの 2 つの連続したブレークポイント間 (2 番目の関数に合わせて適切にシフト)、両方の$f$そして$g$直線的であるため、$F$も直線的です。 したがって、最適化はこれらのブレークポイントの 1 つまたは境界で発生する必要があります。$0$そして$X$。 

これにより、問題は、Dmitry の税の傾きが変化するか、Anna の税の傾きが変化するすべての候補点を構築することになります (次のように変換されます)。$X - b_i$）、それらを分類し、これらの点でのみ目的を評価します。 各システムが最大で寄与するため、$10^5$ブレークポイントを使用すると、候補の総数を管理できます。 

特定の時点で税金を計算する効率的な方法がまだ必要です。 これは次の方法で実行できます$O(\log n)$しきい値とセグメント寄与のプレフィックス合計に対する二分検索を使用するか、$O(n)$プレフィックス構造を事前に計算し、クエリを慎重に処理した場合。 ソートされた閾値を使用すると、セグメントごとの課税額の前置累積により、直接の評価式が得られます。

 ## アルゴリズムのチュートリアル

 私たちは各税制を、セグメントにわたる前置合計を使用してあらゆる所得に対する税金を迅速に計算できる関数として扱います。 

1. 両国の各ブラケットの累積税額を事前計算します。 これにより、そのブラケットを特定し、前のブラケットの全額負担金と最後のブラケットの一部負担金を加算することで、あらゆる所得に対する税金を評価することができます。 
2. 分割点の候補のリストを作成します。 ドミトリーの場合、すべてのしきい値$a_i$が候補です。 アンナの場合、対応する分割ポイントは次のとおりです。$t$は$X - b_i$、なぜなら、アンナの収入が増えてしまったら$b_i$、ドミトリーの分け前は、$X - b_i$。 
3. 境界候補の追加$0$そして$X$。 これらは、すべての収入が一方に割り当てられたときに最適化が発生する可能性があるため、必要です。 
4. すべての候補点を並べ替えて重複を除去します。 任意の 2 つの連続する候補の間では、目的関数は線形であるため、内部点が端点を改善することはできません。 
5. 各候補者の合計税額を評価する$t$計算によって$f(t) + g(X-t)$、最小値を追跡します。 
6. 返却$t$それは最小値を生成します。 

なぜそれが機能するのかは、凸性に関係しています。 各税関数はしきい値を超えた場合にのみ傾きを増加させるため、両方の税関数が$f$そして$g$は凸状で区分的に線形です。 変革$g(X-t)$反転しますが、区分的線形構造は維持されます。 凸関数の和は凸なので、$F(t)$には大域的な最小値以外に局所的な最小値がなく、ブレークポイントの境界でのみ傾きを変更できます。 したがって、その点だけを確認すれば十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build(prefix, rates, caps):
    n = len(rates)
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i+1] = pref[i] + caps[i] * rates[i]
    return pref

def tax(x, caps, rates, pref):
    n = len(rates)
    if n == 0:
        return x * rates[0] / 100.0

    if x <= 0:
        return 0.0

    lo, hi = 0, n
    while lo < hi:
        mid = (lo + hi) // 2
        if x > caps[mid]:
            lo = mid + 1
        else:
            hi = mid

    i = lo
    res = 0.0

    if i > 0:
        res += pref[i]

    prev = caps[i-1] if i > 0 else 0
    rate = rates[i]
    res += (x - prev) * rate

    return res / 100.0

n = int(input())
if n:
    a = list(map(int, input().split()))
else:
    a = []
p = list(map(int, input().split()))

m = int(input())
if m:
    b = list(map(int, input().split()))
else:
    b = []
q = list(map(int, input().split()))

X = int(input())

pref_d = build([], p, a)
pref_a = build([], q, b)

cands = {0, X}
for v in a:
    cands.add(v)
for v in b:
    cands.add(X - v)

cands = sorted(cands)

best = None
best_t = 0

for t in cands:
    val = tax(t, a, p, pref_d) + tax(X - t, b, q, pref_a)
    if best is None or val < best:
        best = val
        best_t = t

print(best_t)
```実装の中心となるアイデアは、税を完全な括弧と部分的な最後のセグメントにわたる接頭辞の合計として評価することです。 二分探索により、収入がどのブラケットに該当するかがわかり、以前のブラケットからの全額の寄与と現在のブラケットへの部分的な寄与が加算されます。 

候補の構築ステップは非常に重要です。アンナのしきい値を次のように変換することです。$X - b_i$傾斜の変化をドミトリーの座標系に合わせます。 これにより、問題を単一変数の最適化として扱うことができるようになります。 

微妙な点は、空の税制の扱いです。 いつ$n = 0$、定額レートは 1 つだけであるため、評価ではしきい値配列へのインデックス付けを回避する必要があります。 もう 1 つの微妙な問題は、浮動小数点演算です。 この問題では整数出力が求められますが、中間税値は小数であるため、比較は浮動小数点で行われますが、必要に応じてスケーリングされた整数に置き換えることもできます。

 ## 特殊なケース

 エッジケースの 1 つは、すべてのレートがゼロの場合です。 この状況では、税金関数はまったくゼロであるため、すべての分割が最適になります。 すべての候補の評価がゼロを返し、最初の候補が選択されるため、アルゴリズムは引き続き機能します。 

もう一つのケースは次のような場合です。$X$すべてのしきい値よりも小さいです。 次に、両方の税関数が単一の線形セグメントに縮小され、最適なソリューションは純粋に所得ゼロでの一定の限界税率を比較することによって決定されます。 候補セットには 0 と X が含まれているため、正しいエンドポイントが評価されます。 

最後の微妙なケースは次のような場合です。$X$両方のシステムのすべてのしきい値よりも大きいです。 この場合、両方の関数がどこでも最後のセグメントにあり、目的はドメイン全体にわたって線形になります。 このアルゴリズムは、線形セグメント セットの端点を評価し、内部構造が重要でない場合でも正確さを保証します。
