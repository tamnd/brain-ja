 ## 解決策
 ## 問題の理解

 セグメントの行が与えられ、各セグメントには 1 から n までのインデックスが付けられます。 興味深いのは、各セグメント i に制約値 a[i] があり、i を訪れた後の次の動きがどの程度制限されるかを制御することです。 

セグメント i を選択すると、それは「アクティブ」になり、すぐに制限が課せられます。同じ日に次に選択されるセグメント j は j > a[i] を満たす必要があります。 この制限は最後に選択したセグメントにのみ依存し、当日中にのみ適用されます。 夜になるとすべてがリセットされるため、何の制限もなく新しい一日が始まります。 

タスクはすべてのセグメントを 1 回だけ訪問することですが、訪問を複数日に分けて行うこともできます。 毎日、インデックスのシーケンスを形成し、連続するすべての遷移は、その日の前のセグメントによって引き起こされた制約を満たさなければなりません。 日数を最小限に抑えたいと考えています。 

n ≤ 3⋅10^5 という制約により、すべてのパーティションを試行したり、多数の候補スケジュールをシミュレートしたりするソリューションは即座に除外されます。 O(n log n) であっても許容されますが、O(n^2) は許容されないため、線形または線形に近いものが必要です。 

貪欲な直感が微妙に失敗するケースは、ローカルな選択が最適に見えても将来の柔軟性を妨げる場合に現れます。 たとえば、小さい a[i] を持つセグメントを選択するのが早すぎると、たとえそれを延期すればより長いシーケンスが可能であっても、後で不必要な日の休憩が強制される可能性があります。 最も難しいのは、どこまで継続できるかを最大化するために、毎日の中で順序を決定することです。 

もう 1 つの注意が必要なケースは、すべての a[i] 値が大きい場合です。 その場合、各セグメントが将来の選択肢を大幅に制限し、最適なソリューションが数日で崩壊する可能性があります。 逆に、すべての a[i] が小さい場合、単一の長いチェーンが存在する可能性があります。 正しい解決策は、当然ながら両極端に適応する必要があります。 

## アプローチ

 ブルートフォース手法では、最後に選択したセグメントから制約を満たす未使用のセグメントを繰り返し選択して、日を 1 つずつ構築しようとします。 これは本質的に、各選択によって実行可能なセットが動的に変更される制約付きスケジューリングの問題です。 すべての可能性を遡ったり試したりすると、各セグメントが数日にわたって多くの位置に出現する可能性があるため、考えられるシーケンスの数は指数関数的に増加します。 

最適なローカル継続は現在の実現可能性だけでなく将来の可用性に依存するため、常に最小の有効なセグメントまたは最大の有効な次のセグメントを選択する貪欲なシミュレーションでも失敗します。 

重要な洞察は、視点を逆転させることです。毎日を貪欲に延長しようとするのではなく、どのセグメントが「後で配置するのが難しい」かを判断し、それらのセグメントがチェーンの開始または構築に早期に使用されるようにします。 制約 j > a[i] は、次のように解釈できます。i を取得した後、その日の残りの期間、すべてのセグメント ≤ a[i] へのアクセスが失われます。 したがって、a[i] はカットオフポイントのように機能します。 

このカットオフによってセグメントを並べ替えたり優先順位を付けたりすると、これらの動的な下限の下で最大増加チェーンとして毎日を構築できます。 毎日は、できるだけ「安全」な有効な次のセグメントを常に選択して、より長く継続できるようにすることで構築できます。 

これを実装するきれいな方法は、常に未使用の最小の残りのセグメント インデックスで新しい日を開始し、最後の a[i] より厳密に大きい次の利用可能なセグメントにジャンプして、貪欲に 1 日を延長することです。 これを効率的に行うために、「最初の未使用インデックス ≥ x」をサポートする構造を維持します。 

毎日が貪欲な散歩となり、次の選択は実行可能な最小の未使用インデックスに強制されます。

 ## アルゴリズムのチュートリアル

 すべての未使用のセグメント インデックスのセットを維持します。 毎日 1 つのシーケンスを構築します。

1. 1 から n までのすべてのインデックスを含む集合 S を初期化します。 
2. S が空でない場合は、S の最小の要素を取得して新しい日を開始します。それを削除し、その要素で現在の日を開始します。 
3. last を、この日最後に選択したインデックスとします。 
4. 同じ日の次のセグメントを選択するには、j > a[last] となるセグメント j が必要です。 これは下限制約です。 
5. a[last] より厳密に大きい最小要素について S をクエリします。 これにより、制限を遵守し、可能な限り 1 日を延長することができます。 
6. そのような要素が存在する場合は、S から削除し、同じ日に続行します。 
7. そのような要素が存在しない場合は、現在の日を閉じて、新しい日を開始します。 

この貪欲な拡張が有効である理由は、実現可能な最小の次のインデックスを選択しても、将来の実現可能性が必要以上に低下することがないためです。 より大きな選択肢を選択しても、以前に利用可能な継続オプションが縮小するだけです。 

### なぜ効果があるのか

 毎日は、遷移が j > a[i] を満たす必要があるというルールに基づいて、最大有効シーケンスとして構築されます。 重要な不変条件は、最後のインデックスで 1 日を終了するとき、S には合法的にそれに続く要素が残っていないということです。 このような要素が存在する場合、アルゴリズムは常に最小の有効な後続要素を選択するため、その要素が選択されます。 これにより、最初の要素とその後の遷移によって引き起こされる制約の下で、毎日が可能な限り長くなることが保証されます。 

すべてのセグメントは 1 回だけ使用され、毎日が最大であるため、連続する 2 日をマージしようとすると、境界での遷移制約に違反することになり、これ以上日数を減らすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    import bisect

    # we maintain sorted list instead of set for performance in CP style
    # but we simulate removal via a boolean array + list of active indices
    active = [True] * (n + 1)
    remaining = list(range(1, n + 1))

    # we will maintain a sorted list manually and remove via marking + periodic rebuild
    # to keep it simple and correct, we use bisect over a list of alive elements
    alive = list(range(1, n + 1))

    def find_next(x):
        # first index in alive strictly greater than x
        import bisect
        i = bisect.bisect_right(alive, x)
        return i

    res = []

    while alive:
        day = []
        cur = alive[0]
        day.append(cur)
        alive.pop(0)

        while True:
            bound = a[cur - 1]
            i = bisect.bisect_right(alive, bound)
            if i == len(alive):
                break
            nxt = alive[i]
            day.append(nxt)
            alive.pop(i)
            cur = nxt

        res.append(day)

    print(len(res))
    for d in res:
        print(len(d), *d)

if __name__ == "__main__":
    solve()
```このコードは、残りの未使用のインデックスをソートされたリストに保持します。 毎日は最小の未使用インデックスから始まります。これにより、辞書編集上避けられない方法で他のセグメントを早期にブロックする可能性のあるセグメントを延期することがないことが保証されます。 次に、制約 j > a[cur] を満たす最小のインデックスに繰り返しジャンプします。 二等分操作により、この制約が効率的に適用されます。 

微妙な実装の詳細は、`bisect_right(alive, bound)`直接の後継者を探す代わりに。 これはまさに、制約 j > a[i] がインデックスの下限検索に変換される方法です。

 ## 特殊なケース

 n = 1 の最小限の入力は、すぐに 1 日を開始し、それ以上の要素が存在しないため終了することによって処理されます。 最初の削除後に生存リストが空になるため、アルゴリズムでは自然に 1 日が生成されます。 

すべての a[i] = 0 の場合、次のインデックスは 0 より大きいため、すべての遷移は有効です。各ステップが常に後続を見つけることができるため、アルゴリズムはインデックスの昇順ですべての要素を訪問する単一のチェーンを構築し、最大のマージ動作を確認します。 

すべての a[i] = n または大きな値の場合、a[i] より大きいインデックスを持つ要素を除いて、他の要素の後に続くことはできませんが、これはほとんどの位置では不可能です。 このアルゴリズムは、それぞれ 1 つの要素を含む新しい日を繰り返し開始し、正しく n 日を生成します。
