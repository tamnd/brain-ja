### なぜ効果があるのか

 正確さは、カウント関数の単調性によって決まります。 もし$X_1 < X_2$、次に表現可能なすべての数値$\le X_1$もです$\le X_2$、 それで`count(X)`減っていない。 これにより、二分探索の有効性が保証されます。 

それぞれ固定$k$の連続した等差数列に貢献します$m$、したがって、固定層内に隙間や凹凸はありません。 レイヤー全体を合計すると、単調性が維持され、しきい値を越えて過大にカウントされなくなります。 二分探索により、プレフィックス数が到達する正確なカットオフが分離されます。$n$に対応する必要があります。$n$- 番目に小さい表現可能な数値。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count(x):
    total = 0
    p = 2
    while p <= x:
        total += max(0, (x - p) // 60)
        p <<= 1
    return total

def solve():
    n = int(input())
    
    lo, hi = 1, 10**18
    
    while lo < hi:
        mid = (lo + hi) // 2
        if count(mid) >= n:
            hi = mid
        else:
            lo = mid + 1
    
    print(lo)

if __name__ == "__main__":
    solve()
```このコードは、カウント関数を導出されたとおりに正確に実装します。 値が検索範囲を超えると、2 の累乗のループは自然に停止します。 二分探索範囲$10^{18}$さえあれば十分なので、$10^{15}$60 ステップの間隔と指数関数的なベースの増加を考慮すると、-th の数値はそのスケールを超えることはできません。 

微妙な点は、開始力が 2 であることです。 最小の意味のあるもの$2^k$は$2$、 以来$k$はポジティブです。 1 から開始すると、無効な表現が誤って含まれてしまいます。 カウントステップにおけるフロア分割により、次のような場合にマイナスの寄与がカウントされないことが保証されます。$2^k > x$。

 ## 特殊なケース

 主なエッジケースは次の場合に発生します。$X$最小の有効な基数より小さいです$2$。 この領域では、カウント関数はゼロを返さなければなりません。 2 の累乗が満たされないため、ループは何も追加することを正しく回避します。$p \le X$。 

もう一つの微妙なケースは次のような場合です。$X$たとえば、2 の 2 乗の間にあります。$X = 63$。 ここだけ$2,4,8,16,32$貢献しながら、$64$は除外されます。 それぞれが異なる 60 の倍数に寄与する可能性があり、この式により、各レイヤーが相互作用することなく独立して評価されることが保証されます。 これにより、二分探索に必要な単調性の仮定が崩れてしまう偶発的な層間カウントが防止されます。
