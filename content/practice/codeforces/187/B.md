 ## 解決策
 ## 問題の理解

 完全な有向グラフがあります`n`都市。 すべての車種について、注文したすべての都市間の移動時間を把握しています。 これらの移動時間は対称であることが保証されていないため、次のようになります。`u`に`v`から行くのとは違う費用がかかるかもしれません`v`に`u`。 

レース ラウンドでは、開始都市、目的地都市、許可される車両の最大変更数という 3 つの値が与えられます。 全行程で 1 台の車両を使用すると、乗り換えはゼロになります。 旅行中に 3 台の異なる車を使用すると、2 回乗り換えることになります。 

ドライバーは中間都市を移動し、どの都市でも瞬時に車を乗り換えることができます。 各クエリのタスクは、許容される乗り換え回数の範囲内で可能な最小移動時間を計算することです。 

制約は、意図したソリューションの形状を完全に決定します。 都市と車種の数は両方とも最大 60 であり、これは 3 次動的計画法やフロイド・ウォーシャル スタイルの前処理には十分な小ささです。 危険な値はラウンド数です。`10^5`。 これにより、クエリごとのグラフ アルゴリズムが除外されます。 たとえ`O(n^3)`クエリごとの計算は絶望的になります。 

許可される変更の最大数は 1000 で、都市の数よりもはるかに大きくなります。 これは、考えられるすべての遷移カウントに対する回答を、意味のある制限まで前処理する必要があることを強く示唆しています。 

微妙な点は、より多くの許可された変更を使用することは、実際にそれらを使用しなければならないことを意味するわけではないということです。 の答えは、`k = 10`それが最適であれば、車を 1 台だけ使用することもできます。 

もう 1 つの簡単な間違いは、「車の乗り換え」の意味を誤解していることです。 

次の例を考えてみましょう。```
2 2 1
0 5
5 0
0 1
1 0
1 2 0
```変更がまったくない場合でも、最初はどちらかの車を選択することができます。 正しい答えは、`1`、 ない`5`, 単純に2台目からスタートできるからです。 

2 番目の落とし穴は、1 台の車両の最短パスが 1 つのエッジのみを使用すると仮定していることです。 入力により直接道路コストが得られますが、グラフは完全であるため、中間都市も役立つ可能性があります。 

例：```
3 1 1
0 100 1
1 0 1
1 1 0
1 2 0
```唯一の車を使用して、1から2までの直通道路は100かかりますが、行きます`1 -> 3 -> 2`コストは 2 です。1 台の車両内のすべてのペアの最短経路を無視するソリューションでは、誤った結果が得られます。 

もう 1 つの明白ではないケースは、追加の変更を許可しても改善が得られない場合です。```
3 2 1
0 1 10
1 0 1
10 1 0

```最適なルートでは、常に先頭車両のみが使用されます。 正確に強制する不注意な DP`k`「最大でも」の代わりに変更します`k`「変更」はここでは失敗します。 

## アプローチ

 ブルートフォースの観点は単純です。 すべてのクエリについて、考えられるすべての車の順序と、乗り換えるすべての考えられる中間都市について考えることができます。 クエリで許可されている場合`k`変更があった場合は、最大で使用できます`k + 1`車のセグメント。 各セグメントでは次のいずれかを使用できます。`m`車の切り替えはどの都市でも発生する可能性があります。 小さいものでも`k`、組み合わせの数は爆発的に増えます。 

よりグラフ指向のブルート フォースでは、状態が次のような階層化された状態グラフを構築します。`(city, used_changes, current_car)`すべてのクエリに対してダイクストラを実行します。 グラフには大まかに`n * m * k`州。 と`r = 10^5`、これでもまだ高すぎます。 

重要な観察は、都市の数が少ないことです。 以来`n <= 60`、すべての都市のペアに対して高価な前処理を行う余裕があります。 

最初の重要な削減は、単一の車両内での移動を車両交換から分離することです。 1 台の固定車を使用することにした場合、2 つの都市間を移動する最適な方法は、単にその車の全ペアの最短経路になります。 それを計算すると、すべての車は最適な移動時間の完全な加重グラフのように動作します。 

この前処理の後、次のように定義するとします。`best[u][v] = minimum travel time from u to v using exactly one car`これには、車を固定したまま、車と中間都市のすべての選択肢がすでに組み込まれています。 

問題ははるかに単純になります。 車の乗り換えが許可されている場合、旅行は一連の区間にすぎず、各区間の費用はそこから発生します。`best`。 

せいぜい使用する場合`k`変更された場合、最大でも使用します`k + 1`セグメント。 

これにより、当然のことながら、セグメント数に対する動的プログラミングが行われます。 させて：`dp[t][u][v] = minimum cost from u to v using at most t segments`この遷移は、古典的な min-plus 行列の乗算です。```
dp[t][u][v] = min(dp[t-1][u][x] + best[x][v])
```以来`n`はわずか 60 なので、この DP をすべての前処理できます。`t`1 から 60 まで。都市を再訪問しても、正の重み付けの下では最適なパスを改善できないため、60 を超えるセグメントは必要ありません。 公式ソリューションでは、変更数の上限が次のとおりです。`n - 1`。 

そうすれば、すべてのクエリは`O(1)`見上げる。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース グラフ検索 | 大きすぎる、大雑把に`O(r * n^3 * m * k)`| 大 | 遅すぎる |
 | フロイド・ウォーシャル + セグメント上の DP |`O(m * n^3 + n^4)`|`O(n^3)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての車のマトリックスを読み取ります。 

各行列は、順序付けされた各都市間の 1 台の車両の移動時間を表します。 
2. すべての車に対して Floyd-Warshall を個別に実行します。 

これにより、旅行全体を通じて同じ車を使い続けた場合の、すべての都市間の真の最小移動時間が計算されます。 
3. マトリックスを構築する`best`。 

すべてのペアについて`(u, v)`、 セット：```
best[u][v] = minimum over all cars of dist_car[u][v]
```これは、そのセグメントに 1 台の車だけを選択できる場合に、可能な限り最も安価なセグメントを表します。 
4. DP テーブルを初期化します。 

させて：```
dp[0][u][v] = best[u][v]
```ここ、`0`は車両交換がゼロであることを意味するため、許可されるセグメントは 1 つだけです。 
5. 追加の車両変更のために DP を延長します。 

あらゆる人にとって`t >= 1`:```
dp[t][u][v] = min(
    dp[t-1][u][v],
    dp[t-1][u][x] + best[x][v]
)
```すべての中間都市にわたって`x`。 

最初のオプションは、追加の許可された変更を使用しないことを意味します。 2 番目のオプションは、最後のセグメントが都市から始まることを意味します`x`車1台を使って。 
6. DP のみを事前計算します。`n - 1`。 

あらゆる最適なルートを都市を繰り返さないルートに変換できるため、`n - 1`変更は不要です。 
7. 各質問に答えます。 

クエリで許可されている場合`k`変更するには、次を使用します。```
dp[min(k, n - 1)][s][t]
```### なぜ効果があるのか

 フロイド-ウォーシャル以降、あらゆる価値観`best[u][v]`からの移動に最適な方法をすでに示しています`u`に`v`ちょうど1台の車を使用しながら。 有効なレース戦略は、そのようなセグメントを単純に連結したものです。 

DP の不変式は次のとおりです。```
dp[t][u][v]
```～からの最小移動時間を保存します`u`に`v`せいぜい使用`t + 1`セグメント、最大でも同等`t`車が変わります。 

移行では、考えられるすべての最後の切り替え都市が考慮されます。`x`。 最後のセグメントが次から始まる場合`x`の場合、ルートの前半部分では最大でも`t`セグメントがあり、最後のセグメントではもう 1 つ使用されます。 考えられるすべての分割ポイントがテストされるため、最適な戦略が常に含まれます。 

すべてのコストは負ではないため、都市を繰り返しても答えを永久に改善することはできません。 最適なセグメント化されたルートは常に簡素化して使用できます。`n`セグメントなので、前処理の上限は次のとおりです。`n - 1`変更で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    n, m, r = map(int, input().split())

    cars = []

    for _ in range(m):
        dist = [list(map(int, input().split())) for _ in range(n)]

        # Floyd-Warshall for this car
        for k in range(n):
            for i in range(n):
                dik = dist[i][k]
                for j in range(n):
                    nd = dik + dist[k][j]
                    if nd < dist[i][j]:
                        dist[i][j] = nd

        cars.append(dist)

    # best one-car segment
    best = [[INF] * n for _ in range(n)]

    for i in range(n):
        for j in range(n):
            val = INF
            for c in range(m):
                if cars[c][i][j] < val:
                    val = cars[c][i][j]
            best[i][j] = val

    limit = n - 1

    # dp[t][i][j] = answer with at most t changes
    dp = [[[INF] * n for _ in range(n)] for _ in range(limit + 1)]

    for i in range(n):
        for j in range(n):
            dp[0][i][j] = best[i][j]

    for t in range(1, limit + 1):
        # start from previous layer because we may use fewer changes
        for i in range(n):
            for j in range(n):
                dp[t][i][j] = dp[t - 1][i][j]

        for i in range(n):
            for k in range(n):
                left = dp[t - 1][i][k]
                for j in range(n):
                    nd = left + best[k][j]
                    if nd < dp[t][i][j]:
                        dp[t][i][j] = nd

    out = []

    for _ in range(r):
        s, t, k = map(int, input().split())
        s -= 1
        t -= 1

        k = min(k, limit)

        out.append(str(dp[k][s][t]))

    print("\n".join(out))

solve()
```最初の主要ブロックでは、すべての車に対して個別に Floyd-Warshall が実行されます。 1 台の車でも中間都市を通過することでメリットが得られる可能性があるため、これは不可欠です。 

の`best`マトリックスは、すべての車を 1 つの汎用遷移グラフに圧縮します。 このステップを経ると、すべてのエッジはすでに「1 つの途切れることのない車の選択を使用した、可能な限り最良の動き」を意味します。 

DP レイヤーは、許可される車両変更の数に対応します。 微妙なディテールがコピーされています`dp[t - 1]`の中へ`dp[t]`移行前。 これがなければ、DP は正確に次の値を使用して答えを計算します。`t`せいぜい変化する`t`変化します。 

もう 1 つの重要な実装上の選択肢は、クエリを次のようにキャップすることです。```
k = min(k, n - 1)
```この問題により、`k`最大 1000、ただし前処理のみが必要`n - 1`。 

すべての計算は 64 ビット整数に安全に収まります。 Python の整数はこれを自然に処理します。
