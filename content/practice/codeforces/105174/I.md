 ## 問題の理解

 私たちは、正確に構成された小さな「プログラム ファイル」を構築するように求められます。$n$線。 各行の形式は非常に厳格です。中括弧内に書かれた数字で始まり、その後に一連のカンマが続きます。 コンマは単なる句読点ではなく「拍」を表し、各コンマはその行の中括弧内の数値に応じて一定の量を与えます。 

形式的には、各行は次のようになります`{x},,,,,,`どこ$x$は私たちが選んだ整数です。 の値$x$すべて 2 の累乗でなければなりません$x$異なる行にわたる値は個別である必要があり、各行には少なくとも 1 つのカンマが含まれている必要があります。 

行で値が使用されている場合$x$そして含まれています$c$カンマの場合、その行が貢献します$c \cdot x$合計スコアに。 すべての行を合計すると正確な結果が得られる必要があります$k$。 同時に、各行には厳格な長さ制限があります。$m$したがって、テキスト表現は`{x}`さらにカンマはその制限内に収まる必要があります。 

したがって、タスクは 2 つのことを同時に決定することです。つまり、どの 2 の累乗を割り当てるかです。$n$行数、および加重合計が次と等しくなるように各行にカンマの数を含める必要がある$k$すべての行は長さの制約内に収まります。 

制約は小さいです。$n \le 20$そして$k \le 100$。 これは、いかなる構築も非常に小さな目標金額に制限されるため、指数関数的推論または DP スタイルの推論が実行可能であることを直ちに示唆します。 

重要な構造上の制限は、すべての行が少なくとも寄与しなければならないという事実から来ています。$x$1 行に少なくとも 1 つのカンマがあるためです。 つまり、選択したものの合計$x$値を超えることはできません$k$、そうでない場合は、可能な最小限の構築でさえすでにオーバーシュートします。 

2 番目の微妙な制限は、すべて$x$値は以下の異なる 2 のべき乗でなければなりません$2^{30}$したがって、セットから個別の値を効果的に選択することになります。$\{1,2,4,8,\dots\}$。 

2 の大きなべき乗を早く選択しすぎると、素朴な失敗例がすぐに現れます。 たとえば、次の場合$k=10$そして私たちは選択します$x=32$1 行の場合、コンマ 1 つでも 32 が寄与し、すでに目標の合計を超えています。 この下限制約を無視したアプローチは即座に機能しなくなります。 

もう 1 つの失敗例は、文字列の長さを無視したことに起因します。 数値の代入が有効であっても、`{x}`2 の累乗が大きくなると桁の長さが長くなり、長いカンマ シーケンスが 1 行あたりの制限をオーバーフローする可能性があります。$m$。 

## アプローチ

 強引なアイデアは、次のすべての割り当てを試してみることです。$n$2 の累乗を区別し、一致するカンマ数を割り当てるためにあらゆる方法を試します。$k$。 それぞれの選択に対して、$x_i$のすべての整数合成を列挙します。$k$の中へ$n$重み付けされた部分、どこの部分$i$の倍数に貢献する$x_i$。 ディストリビューションの数は非常に急速に増加しており、$k \le 100$、各行が最大で寄与する可能性があるため、単純な列挙はコストが高くなります。$O(k)$可能なカンマ数、おおよその結果$O(k^n)$行動。 

有用な 2 のべき乗は小さいものだけであるという観察を修正すると、この構造ははるかに管理しやすくなります。 各行が少なくとも貢献しているため、$x_i$、合計は正確に次のとおりである必要があります$k \le 100$、 どれでも$x_i > 100$決して現れることはできません。 これにより、候補セットが最大 7 つの値に折りたたまれます。$1,2,4,8,16,32,64$。 これにより、問題は、任意の 2 のべき乗の組み合わせ選択から、これらの小さな値のサブセットの選択へと軽減されます。 

一度$x_i$値が固定されている場合、残りのタスクは残りの予算をこれらの重みの倍数に分配することになります。 これは非常に小さな容量の境界付きナップサックであり、各アイテムが$i$追加のカンマに応じて何回でも選択できます。 

また、選択した各行に配置できるカンマの数を制限する、行ごとの文字列の長さの制約を強制する必要もあります。$x_i$。 

これにより、行数と合計に関する動的計画法が自然に定式化されます。

 ## アルゴリズムのチュートリアル

 の候補値を修正します。$x$2 の最小累乗として:$1,2,4,8,\dots$。 以来$k \le 100$、それらのみを保持します$\le k$、正確に選択します$n$このリストとは異なるもの。 選べない場合$n$可能な最小寄与が超えない値$k$、すぐに失敗してしまいます。 

次に、処理したライン数と構築した合計ビート合計に関する動的プログラミングの状態を定義します。 

1. 次から始まる 2 の累乗候補のリストを作成します。$1$、値が超えると停止します$k$、そして私たちは少なくとも持っていることを保証します$n$候補者たち。 そうでなければ、答えは不可能です。 
2. 最初のものを選択します$n$としての候補者$x_1, x_2, \dots, x_n$。 値を大きくすると実現可能性が難しくなるだけなので、この選択は安全です。 
3. 行ごとに$i$を含めることができるコンマの数を計算します。 各行には文字の固定オーバーヘッドがあります`{`、`}`、および次の数字$x_i$したがって、許可されるカンマの最大数を計算します。$$c_i \le m - (\text{length of } \{x_i\})$$そしてまた$c_i \ge 1$。 
4. DP を定義します。$dp[i][s]$最初のものを構築できるかどうかを意味します$i$ビート合計のライン$s$。 最初は$dp[0][0] = true$。 
5. 行ごとに$i$、可能なすべてのカンマ数を試します$c_i$許容範囲内で。 それぞれの選択が貢献します$c_i \cdot x_i$合計になるので、次のように遷移します。$$dp[i][s + c_i x_i] = true$$6. DP を入力した後、次のことを確認します。$dp[n][k]$到達可能です。 そうでない場合は、-1 を出力します。 
7. 到達可能な場合は、次の選択肢を再構築します。$c_i$DP テーブルを遡って各行を必要な形式で出力します。 

これが機能する主な理由は、グローバル合計制約を除いて、各行が独立して動作するためです。 一度$x_i$が固定されている場合、唯一の相互作用は総予算がどうなるかです。$k$行間で分割されており、これがまさに DP がキャプチャするものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    # generate candidate powers of two
    xs = []
    v = 1
    while v <= k and len(xs) < n:
        xs.append(v)
        v *= 2

    if len(xs) < n:
        print(-1)
        return

    xs = xs[:n]

    # precompute max commas per line
    maxc = []
    base_len = []
    for x in xs:
        l = len(str(x)) + 2  # braces + digits
        base_len.append(l)
        maxc.append(m - l)

        if maxc[-1] < 1:
            print(-1)
            return

    # dp[i][s] = reachable
    dp = [[False] * (k + 1) for _ in range(n + 1)]
    par = [[None] * (k + 1) for _ in range(n + 1)]

    dp[0][0] = True

    for i in range(n):
        x = xs[i]
        for s in range(k + 1):
            if not dp[i][s]:
                continue
            for c in range(1, maxc[i] + 1):
                ns = s + c * x
                if ns <= k and not dp[i + 1][ns]:
                    dp[i + 1][ns] = True
                    par[i + 1][ns] = (s, c)

    if not dp[n][k]:
        print(-1)
        return

    res_c = [0] * n
    cur = k
    for i in range(n, 0, -1):
        ps, c = par[i][cur]
        res_c[i - 1] = c
        cur = ps

    for i in range(n):
        x = xs[i]
        print("{" + str(x) + "}" + "," * res_c[i])

if __name__ == "__main__":
    solve()
```実装は、2 の小さなべき乗に注意を制限することから始まります。これは、必須の少なくとも 1 つのコンマ ルールにより、値が大きくなるとすぐに予算を超えるためです。 

DP テーブルは行ごとに構築され、各行は行に対応し、各遷移はカンマの数の選択に対応します。 親ポインター テーブルには以前の合計と選択したカンマ数が保存され、最終的な文字列の再構築が可能になります。 

微妙な点は、1 行あたり 1 コンマの下限です。 これは、次から開始することで DP ループ内で直接適用されます。`c = 1`したがって、無効な空行状態が導入されることはありません。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$n$に比べて大きすぎます$k$。 たとえば、次の場合$n=20$そして$k=3$、選択することさえ$x_i=1$すべての行ですでに最小合計 20 が強制されており、これは目標を超えています。 DP が到達しないため、アルゴリズムはこれを早期に検出します。$k$。
