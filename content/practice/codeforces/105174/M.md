 ## 解決策
 ## 問題の理解

 私たちは石の山を使ったゲームを与えられました。 2 人のプレイヤーが交互にターンを行い、アリスが最初に動きます。 各ターンで、プレイヤーは現在の石の数、たとえば x を確認し、パリティに応じたルールに従って石を削除します。 

x が奇数の場合、プレイヤーには選択の余地がなく、石を 1 つだけ取り除き、山を x−1 に減らさなければなりません。 x が偶数の場合、プレーヤーには 2 つの選択肢があります。1 つの石を削除するか、ちょうど半分の石を削除してゲームをそれぞれ x−1 または x/2 に移動します。 ターンの開始時に石がゼロのプレイヤーは、何も動けないため、すぐに負けます。 

このタスクは、両方のプレイヤーが最適にプレイしたと仮定して、最初の n ごとにアリスが強制的に勝利するかどうかを判断することです。 

制約はテスト ケース 100 万件まで、ストーン カウントは 100 万件までです。 これにより、ゲームのテストごとのシミュレーションが即座に除外されます。 テスト ケースごとにリニア スキャンを実行したとしても、遅すぎます。 許容可能な解決策は、最大 10^6 までの事前計算か、勝利状態の閉形式の特徴付けのいずれかに依存する必要があります。 

素朴な推論が微妙に失敗するケースは、偶数状態と奇数状態の間の対称性を仮定したり、「半分を取る」ことが常に強いと仮定したりすることから生じます。 たとえば、n = 2 の場合、両方の手が 1 につながり、次のプレイヤーの勝ちとなるため、2 は負けになります。 n = 4 の場合、半分を取ると 2 (負け) になるため、1 を引くと 3 (勝ち) になりますが、4 が勝ちとなります。 これは、ポジションであっても、大幅な削減だけでなく、両方の移動オプションを同時に考慮する必要があることを示しています。 

もう 1 つの落とし穴は、奇数ポジションでは 1 つの手しか許可されていないため、すべての奇数ポジションが負けていると仮定することです。 これは、1 や 3 のような小さな値では誤りであり、強制チェーンが相手の負け状態につながります。 

## アプローチ

 ゲームを解決する直接的な方法は、すべての整数 x をゲームの状態として扱い、勝ちか負けかを定義することです。 状態 x から、1 回の移動で到達可能なすべての状態を調べ、それらの到達可能な状態の少なくとも 1 つが負けている場合、x を勝利としてマークします。 

これは当然、動的プログラミングの定式化につながります。 dp[x] は、現在のプレイヤーが残り x 個の石で勝利する戦略を持っているかどうかを表すものとします。 ルールによれば、x が奇数の場合、遷移は x−1 のみとなります。 x が偶数の場合、遷移は x−1 および x/2 に進みます。 これにより、dp[x] がより小さいインデックスのみに依存する再帰が得られるため、0 から n までの dp を計算できます。 

ブルートフォース DP は単純で正しいですが、毎回再計算するとコストはテスト ケースあたり O(n) となり、10^6 クエリでは不可能です。 たとえ 1 回計算されたとしても、クエリへの応答は O(1) であるため、本当の問題は、最大 n まで 1 回事前計算することを確認することです。 

重要な構造的観察は、小さなプレフィックスの後、ゲームは単純なパターンに安定するということです。 しきい値を超えた奇数の状態は、唯一の動きで直接勝ちの偶数の状態につながるため、一貫して負けになります。 しきい値を超えた州であっても、2 つの遷移のうちの少なくとも 1 つが常に負けにつながるため、一貫して勝ち続けます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとの完全な再計算 | クエリあたり O(n) | お(1) | 遅すぎる |
 | DP は最大 n | まで事前計算します。 O(n) 合計 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 0 から 1e6 までの dp 値を 1 回計算して、解を構築します。

1. 空の山からは手が存在しないため、dp[0] を負けとして初期化します。 
2. 1 から max_n までの各 x について、以前に計算された状態から dp[x] を決定します。 
3. x が奇数の場合、x − 1 への移動のみであるため、dp[x] は dp[x−1] の逆になります。 これは、強制的な動きによって相手が負けた状態になった場合に限り、現在のプレーヤーが勝つことを直接反映しています。 
4. x が偶数の場合、オプション x-1 と x/2 の両方を評価します。 どちらかが負け状態になった場合は、dp[x] を勝ちとしてマークします。 プレイヤーは利用可能な最善の手を選択するため、これにより最適なプレイがエンコードされます。 
5. dp を入力した後、dp[n] が true かどうかを出力することで、O(1) の各クエリに答えます。 

これが機能する理由は、dp[x] が有限公平ゲームにおける勝ち位置の定義を正確にエンコードしているためです。つまり、負けている状態に少なくとも 1 つの手があれば、その状態は勝ちであり、すべての手が勝ちの状態につながった場合は負けです。 すべての遷移によって x が減少するため、DP は十分に根拠があり、すべての依存関係をカバーします。 

反復を調べると、より深い構造の単純化が明らかになります。奇数の状態は x-1 から値を伝播しますが、偶数の状態は x-1 と x/2 の両方の影響を受けます。 これは、値が小さいとすぐに安定したパターンに崩れますが、DP 定式化は正確さを保証する最もクリーンな方法です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 10**6

dp = [False] * (MAXN + 1)
dp[0] = False

for x in range(1, MAXN + 1):
    if x % 2 == 1:
        dp[x] = not dp[x - 1]
    else:
        lose = False
        if not dp[x - 1]:
            lose = True
        if not dp[x // 2]:
            lose = True
        dp[x] = lose

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append("Alice" if dp[n] else "Bob")
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```DP 配列はグローバルに 1 回計算されるため、各テスト ケースは一定時間内に応答されます。 遷移ロジックは移動ルールに直接従います。奇数の状態には 1 つの強制遷移があり、偶数の状態には両方の可能な移動がチェックされ、どちらかが負けポジションにつながるかどうかが選択されます。 

よくある実装上の間違いは、クエリ ループ内で dp を再計算することです。これは、10^6 入力ですぐにタイムアウトになります。 もう 1 つの微妙な問題は、すべての手が勝っている場合ではなく、いずれかの手が負けている場合に dp[x] が true である必要があることを忘れていることです。 

## 実用的な例

 n = 5、6、7 を考えてみましょう。 

このトレースでは、ルールベースの DP 決定を使用します。 

### 例 1: n = 5

 | × | パリティ | トランジション | dp[x−1] | 決定 |
 | --- | --- | --- | --- | --- |
 | 5 | 奇数 | 4 | dp[4]=真 | dp[5]=False |

 5 では、すでに勝ち位置である 4 に進むだけなので、現在のプレイヤーは強制的に勝利を得る方法がありません。 

### 例 2: n = 6

 | × | パリティ | x−1 | x/2 | 結果 |
 | --- | --- | --- | --- | --- |
 | 6 | 偶数 | 5(F) | 3(た) | dp[6]=真 |

 6 では、5 への移動は悪くても、3 への移動は相手を負けの立場に置くので強力です。 

これら 2 つの例は、偶数の状態が半分の移動によってどのように保存されるかを示していますが、奇数の状態は前の位置によって厳密に決定されます。

10^6 遷移は単純な定数時間チェックであるため、前処理は制限内に問題なく収まります。 各クエリは一定時間内に応答されるため、最大入力サイズでもソリューションが効率的になります。

 ## 特殊なケース

 n = 1 の場合、強制移動は 0 になり、相手は動けなくなるため、その状態はすぐに勝ちになります。 

n = 2 の場合、可能な手は両方とも n = 1 (勝ち) につながるため、状態は負けであるため、逃げ道はありません。 

n = 3 の場合、強制手は負けている 2 に進み、奇数ではありますが 3 が勝ちになります。 

n = 5 などの大きな奇数の場合、強制手は 4 になり、勝ちとなるため、局面は負けになります。 これは、唯一の子が安定して勝利すると、奇数の状態が有利でなくなる遷移を示しています。 

n = 4 などの偶数値の場合、半減手は負けている 2 に進むため、1 を減算すると勝ちの状態になりますが、4 が勝ちになります。
