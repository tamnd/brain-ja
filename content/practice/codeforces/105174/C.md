 ## 解決策
 ## 問題の理解

 ワンドはまさに`n`宝石スロット。 gem には 3 つの独立したカテゴリがあります。 

最初のカテゴリは魔法攻撃力を増加させ、2 番目はマナを増加させ、3 番目は攻撃速度を増加させます。 すべての宝石はいくつかのスロットを占有し、正確に 1 つの属性に正の値を与えます。 各宝石は最大 1 回使用できます。 

占有スロットの合計が以下のジェムのコレクションを選択した後`n`、杖の最終的な力は`magic_attack × mana × attack_speed`。 

課題は、この製品を最大限に活用することです。 

最も重要な観察は、異なるカテゴリの宝石は、共有スロット制限を経由する場合を除いて決して相互作用しないということです。 1 つのカテゴリ内で重要なのは、指定された数のスロットを使用して合計属性値をどれだけ取得できるかだけです。 

スロット数は最大 2000 で、各カテゴリには最大 2000 個のジェムが含まれます。 複雑さを伴う動的プログラミング ソリューション`O(total_gems × n)`これはおよそ次のとおりなので、十分に高速です。`3 × 2000 × 2000 = 1.2 × 10^7`状態遷移。 gem のサブセットを含むものや、gem 間のすべての割り当てを直接検索することは完全に不可能です。 

いくつかの特殊なケースは注目に値します。 

1 つの属性がまったく改善されない場合、他の 2 つの属性に関係なく、最終的な製品はゼロになります。 

例えば、```
2
1 1 1
2 5
3 10
3 10
```2 つのスロットに収まるマナや攻撃速度のジェムはないため、実行可能なソリューションにはすべて製品が含まれます`0`。 

もう 1 つの微妙なケースは、最適なソリューションによってスロットが未使用のままになる可能性があることです。 

例えば、```
5
1 1 1
2 100
2 100
2 100
```各カテゴリのジェムを 1 つ使用するとスロットが 6 つ消費されますが、これは不可能です。 最適なソリューションでは、gem を 2 つだけ使用し、次のような結果が得られます。`0`1 つの属性がゼロのままであるためです。 すべてのスロットを正確に埋める必要はありません。 

3 番目の間違いは、各カテゴリーがスロットの約 3 分の 1 を受け取るべきであると想定していることです。 

例えば、```
10
3 1 1
2 100
2 100
2 100
2 1
4 1
```魔石は他のものに比べて格段に強い。 最適な割り当ては非常に不均衡であり、事前にスロットの配分を固定する戦略は最適な割り当てを逃す可能性があります。 

## アプローチ

 単純な総当たりソリューションでは、Gem のすべてのサブセットを列挙します。 サブセットごとに、占有スロットの合計と 3 つの属性の合計を計算し、有効な積の最大値を保持します。 

実行可能なすべての選択が検討されるため、これは明らかに正しいです。 残念ながら、宝石は 6000 個も存在する可能性があるため、検索スペースには次のものが含まれます。`2^6000`サブセットは天文学的に大きい。 

重要な観察は、3 つのカテゴリが独立しているということです。 それが正確にわかっていると仮定しましょう`x`スロットは魔法の宝石に消費されます。 そのカテゴリ内で唯一の問題は、次のコマンドを使用して得られる最大の魔法攻撃力です。`x`スロット。 選ばれた宝石の個々のアイデンティティはもはや重要ではありません。 

これは、3 つの独立した 0-1 ナップザック問題を解決することを直ちに示唆します。 

カテゴリごとに定義します。`best[i] = maximum attribute value obtainable using exactly i slots`。 

これら 3 つのナップザック計算の後、考えられるすべてのスロット割り当てが行われます。`a + b + c ≤ n`評価することで確認できます`best_magic[a] × best_mana[b] × best_speed[c]`。 

ナップザック ステージでは、多くのサブセットが 1 つに指数関数的に圧縮されます。`n + 1`カテゴリごとに状態が表示されるため、最終的な列挙が実用的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(m1+m2+m3)) | お(1) | 遅すぎる |
 | 最適 | O((m1+m2+m3)n+n³) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 1 つの gem カテゴリに対してナップザック ルーチンを作成します。 させて`dp[i]`正確に使用して取得できる最大の属性値を示します`i`スロット。 初期化する`dp[0]=0`そして他のすべての状態は不可能であると考えられます。 
2. すべての宝石を一度処理します。 スロット カウントを降順にトラバースして、0 ～ 1 の制限を適用します。 現在の gem を使用すると、より大きなスロット数の値が向上する場合は、その状態を更新します。 
3. このナップザックを独立して実行して、魔法、マナ、攻撃速度のジェムを獲得します。 結果として得られる 3 つの配列には、正確なスロット使用量ごとに達成可能な最良の値が含まれています。 
4. 考えられるすべてのペアを列挙します`(a,b)`最初の 2 つのカテゴリに割り当てられたスロット数。 
5. 3 番目のカテゴリで使用できる残りのスロットは最大でも`n-a-b`。 実現可能なものをすべて列挙する`c`から`0`その限界まで。 
6. 3 つのナップザック配列のいずれかであり得ない状態は無視します。 
7. 3 つの属性値の積を計算し、最大値を保持します。 

### なぜ効果があるのか

 ナップザックの計算では、1 つのカテゴリ内の宝石のすべてのサブセットが 1 回だけ考慮されるため、スロット数ごとに、達成可能な最大の属性値が格納されます。 カテゴリは宝石を共有することはなく、総スロット予算を通じてのみ相互作用するため、実現可能な全体的なソリューションはすべて、スロット使用量の 3 倍に正確に対応します。`(a,b,c)`。 最終的な列挙中に、そのトリプルが検査され、各カテゴリの最適な値がすでにわかっています。 同じ数のスロットを使用してカテゴリをより弱いサブセットに置き換えても、積が減少するだけであるため、これらのスロット数に対して 3 つの独立した最適な選択肢を組み合わせることが常に最適になります。 実行可能なすべてのスロット割り当てがチェックされるため、グローバル最大値が見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

NEG = -10 ** 18

def knapsack(m, n):
    dp = [NEG] * (n + 1)
    dp[0] = 0
    for _ in range(m):
        v, w = map(int, input().split())
        for s in range(n - v, -1, -1):
            if dp[s] != NEG:
                dp[s + v] = max(dp[s + v], dp[s] + w)
    return dp

def solve():
    n = int(input())
    m1, m2, m3 = map(int, input().split())

    atk = knapsack(m1, n)
    mana = knapsack(m2, n)
    speed = knapsack(m3, n)

    ans = 0

    for a in range(n + 1):
        if atk[a] == NEG:
            continue
        for b in range(n - a + 1):
            if mana[b] == NEG:
                continue
            limit = n - a - b
            for c in range(limit + 1):
                if speed[c] == NEG:
                    continue
                val = atk[a] * mana[b] * speed[c]
                if val > ans:
                    ans = val

    print(ans)

if __name__ == "__main__":
    solve()
```ヘルパー関数は、標準の 0-1 ナップザックを実行します。 スロット数を降順で繰り返すことにより、各 gem が最大 1 回使用されることが保証されます。 

不可能な状態は、ゼロではなく大きな負の数に初期化されます。 宝石が選択されていない場合はゼロが正当な属性値であるため、この区別は不可欠です。 

3 つの動的プログラミング テーブルを計算した後、プログラムは実行可能なすべてのスロット分布を列挙します。 内側のループが残りの容量を超えることはありません。そのため、テストされたすべての割り当ては自動的に総スロット制限を満たします。 

Python の整数には任意の精度があるため、積に特別な処理は必要ありません。
