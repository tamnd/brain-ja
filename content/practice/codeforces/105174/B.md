 ## 問題の理解

 私たちは球の表面上の動きをシミュレートしています。旅行者は半径のある球形の地球の赤道のどこかから出発します。$R$。 動きは 4 つの連続する測地線セグメントとして与えられます。距離は子午線に沿って北に進みます。$X$、次に緯度円に沿って西に距離を移動します。$X$、その後、子午線に沿って南に進みます。$X$、最後に赤道に沿って東に距離を進みます$X$。 この閉じたように見えるループが完了したら、最終位置と開始点の間の最短の表面距離を求められます。 

重要な問題は、ここでの「直線」とは地図上のユークリッド線ではなく、大圏の弧を意味することです。 南北の移動は子午線に沿って行われますが、東西の移動は緯度に応じて半径が縮小する緯度円に沿って行われます。 この歪みが、パスのキャンセルを妨げます。 

入力により球の半径が与えられます$R$そして移動距離$X$、 と$X \le 1.5R$。 この制約が重要なのは、適度な角変位が保証されるため、三角関数の評価が数値的に安定し、球面での病的な回り込み動作が回避されるためです。 

素朴な解釈では、この動きは地球が平らであるかのように扱われます。 その場合、道は明らかに原点に戻ります。 ただし、これでは、たとえ小さな入力であっても、完全に間違った答えが得られます。 たとえば、次の場合$R = 5$そして$X = 3$、平面シミュレーションにより距離が得られます。$0$、一方、最初のステップ後の緯度円の円周はより小さいため、球面の正解はゼロではありません。 

2 番目の微妙な失敗例は、緯度円の半径の縮小を考慮せずに経度の変化を計算した場合に発生します。 西と東の動きは異なる緯度で発生するため、相殺されません。 

## アプローチ

 ブルートフォース幾何学シミュレーションでは、球を離散化し、大圏の弧に沿った動きを段階的にシミュレートします。 これには、外積または球面補間を使用して、各セグメントの後に球上の 3D 座標を更新することが含まれます。 正しいのですが、これは閉じた形式の構造を持つ問題にとっては不必要な重機です。 また、数値的なドリフトが発生するため、各ステップの後に慎重な正規化が必要になります。 

重要な観察は、北に移動した後、動きが緯度で対称であることです。$X$、旅行者が緯度角度に達すると、$\varphi = \frac{X}{R}$。 西向きの動きはその緯度円に沿って起こり、その半径は$R \cos \varphi$。 これにより、直線距離が角経度の変化に変換されます。 南方への移動後、旅行者は赤道に戻りますが、緯度横断中に経度のずれが蓄積されます。 最後の東方向への移動により、赤道上の経度の移動がさらに追加されます。半径は$R$。 

したがって、全体の影響は赤道上の単一の正味経度変位に減少し、最終的な答えはその赤道の弧に沿った測地線距離になります。 

3D モーションから 1D 角度差への縮小が中心的な単純化です。すべての中間ジオメトリは、単一の累積された経度オフセットに折りたたまれます。

 ## アルゴリズムのチュートリアル

 すべての動きを球上の角量に変換します。 

1. 最初の移動後に到達した緯度を次のように計算します。$\varphi = \frac{X}{R}$。 

球面上で子午線に沿って移動すると、円弧の長さが中心角に直接マッピングされるため、これは有効です。 
2. 緯度を西に移動することによって生じる経度の変化を計算します。$\varphi$。 

その緯度円の半径は$R \cos \varphi$、したがって、角度の変化は次のようになります。$\frac{X}{R \cos \varphi}$、方向は西であるため、負の符号が付きます。 
3. 赤道上を東に移動することによる経度の変化を計算します。 

赤道半径は$R$、これは貢献します$+\frac{X}{R}$。 
4. すべての経度の変化を単一の正味角変位に結合します。$$\Delta \lambda = \frac{X}{R} - \frac{X}{R \cos \varphi}.$$これは、開始経度に対する最終位置を表します。 
5.減らす$\Delta \lambda$主角度範囲内に$[0, 2\pi)$、経度が球の周りを一周するためです。 
6. 角距離を赤道上の最短円弧距離に変換します。$$\text{answer} = R \cdot \min(\Delta \lambda, 2\pi - \Delta \lambda).$$### なぜ効果があるのか

 東西を除くすべてのセグメントは子午線に沿って移動しますが、緯度が変わるだけです。 唯一の不可逆的な変位は、緯度円に沿った移動中に発生します。この円弧の長さは、赤道上よりも経度の大きな角度のずれに対応します。 赤道に戻った後、システムは 1 次元になります。重要なのは経度だけであり、測地線の距離は半径の円上の最短の円弧に減少します。$R$。 計算では正確な角度変位が保存されるため、最後のラップアラウンド ステップではパスが交差するかどうかが正確に捕捉されます。$2\pi$境界。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def solve():
    R, X = map(float, input().split())

    if X == 0:
        print(0.0)
        return

    phi = X / R

    cos_phi = math.cos(phi)

    # net longitude change
    delta = (X / R) - (X / (R * cos_phi))

    # normalize to [0, 2π)
    two_pi = 2.0 * math.pi
    delta = delta % two_pi

    # shortest arc on circle
    delta = min(delta, two_pi - delta)

    ans = R * delta
    print(ans)

if __name__ == "__main__":
    solve()
```実装は角度の縮小の直後に行われます。 最もデリケートな部分は、赤道でのラップアラウンドの処理です。正味の経度シフトを計算した後、それを法的に正規化します。$2\pi$短い円弧を描く前に。 これにより、累積角度が 1 回転を超えたときのエラーが回避されます。このエラーは、制約下でも発生する可能性があります。$X \le 1.5R$。 

すべての演算には少数の三角関数評価と基本的な算術が含まれるため、浮動小数点の安定性は十分です。 

## 実用的な例

 小さなケースを考えてみましょう。$R = 5$、$X = 3$。 

最初の計算$\varphi = 3/5 = 0.6$。 それから$\cos \varphi \approx 0.8253$。 

| ステップ | 値 |
 | --- | --- |
 |$\varphi$| 0.6 |
 |$\cos \varphi$| 0.8253 |
 |$X/R$| 0.6 |
 |$X/(R\cos\varphi)$| 0.7273 |
 |$\Delta \lambda$| -0.1273 |

 正規化後の大きさは次のようになります。$0.1273$したがって、最終的な距離は次のようになります。$5 \times 0.1273 \approx 0.6365$、サンプル出力の予想されるスケールと一致します。 

このトレースは、視覚的にはパスが戻ってきたように見えても、緯度の歪みによって測定可能な角度のずれが生じていることを示しています。 

ここで考えてみましょう$R = 10$、$X = 10$。 ここ$\varphi = 1$、 そして$\cos 1 \approx 0.5403$。 

| ステップ | 値 |

import sys, io
import math

def solve():
    import sys
    input = sys.stdin.readline
    R, X = map(float, input().split())

    if X == 0:
        print(0.0)
        return

    phi = X / R
    delta = (X / R) - (X / (R * math.cos(phi)))

    two_pi = 2.0 * math.pi
    delta %= two_pi
    delta = min(delta, two_pi - delta)

    print(R * delta)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    from io import StringIO
    old_stdout = sys.stdout
    sys.stdout = StringIO()
    solve()
    out = sys.stdout.getvalue().strip()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out

 ## 特殊なケース

 いつ$X = 0$の場合、旅行者はまったく動かないため、すべての角度項はゼロに崩壊し、出力は正確にゼロになります。 アルゴリズムはこれを明示的に処理し、不必要な三角関数の評価を回避します。 

いつ$X$に近いです$R$、緯度角$\varphi$1 ラジアンに近づき、コサインは正常に動作しますが、1 より大幅に小さくなります。経度増幅率$1/\cos\varphi$が大きくなり、正味変位が大きくなります。 累積角度が超過する可能性があるため、ここでは正規化ステップが不可欠です。$2\pi$、そしてそれを減らすことに失敗すると、間違った円弧の選択につながります。 

いつ$X$上限に近いです$1.5R$、$\varphi \approx 1.5$ラジアン、および$\cos\varphi$小さくなる。 これにより、経度の歪みが最大化され、可能な限り最大の角変位が生成されます。 モジュロ演算により正しいラッピングが保証され、最終的な`min`このステップにより、赤道上の長いラップアラウンド パスではなく、より短い円弧が選択されることが保証されます。
