 ## 解決策
 ## 問題の理解

 私たちは一列に並べられた一連の数字を与えられ、非常に限定された種類の並べ替え操作を実行できます。 この操作では、任意の要素を交換することはできません。配列内で 2 つの位置が離れている要素のみを交換します。 これは、要素が、インデックスの同じパリティ (すべて偶数の位置またはすべての奇数の位置) にある他の要素とのみ対話できることを意味します。 

タスクは、改善が不可能になるまでこれらの許可されたスワップを繰り返し適用した後、最終的な構成を決定することです。つまり、実際には、各パリティ クラスが独立してソートされる一方で、偶数インデックスと奇数インデックスの間の相対的な順序は、混在することがないという意味で保持されます。 

入力の観点からは、長さ n の配列を読み取り、プロセスが安定した後に結果の配列を出力する必要があります。 

このタイプの問題の制約レベルは通常、スワップの O(n^2) シミュレーションが実行できないほど十分に大きいです。 n が 10^5 に達すると、隣接する有効なペアのスキャンと交換を繰り返し行うアプローチは、最悪の場合、約 10^10 の操作にまで低下します。これは、2 秒の制限時間内で実用的な制限をはるかに超えています。 これは、操作構造を直接シミュレートするのではなく、並べ替えまたは分解のトリックに還元する必要があることを直ちに示唆しています。 

2 つのパリティ グループ間で値がインターリーブされる場合、微妙なエッジ ケースが発生します。 たとえば、配列がすでにグローバルにソートされているが、パリティで区切られた順序が異なる場合、単純な「グローバル ソート チェック」では、操作が必要ないと誤って想定されてしまいます。 

次の入力を考えてみましょう。 

n = 5、配列 = [1、5、2、4、3]

 素朴なアプローチでは、配列は「ほぼソートされている」ため、スワップはほとんど必要ないと想定するかもしれません。 ただし、パリティ分離により偶数インデックス [1、2、3] と奇数インデックス [5、4] が得られ、これらは独立して進化し、グローバルにソートされていない最終的な配置が生成されます。 

これが構造上の落とし穴の中核です。変換では値の隣接性ではなく、インデックスのパリティが考慮されます。 

## アプローチ

 ブルートフォース解釈は、許可された操作を直接シミュレートします。 配列を繰り返しスキャンし、順序が狂うたびに位置 i と i + 2 の要素を交換します。 各パスにより順序付けがわずかに改善される可能性がありますが、最悪の場合、各要素はスワップを繰り返すことで配列の半分を走査する必要がある可能性があります。 これは、偶数インデックスと奇数インデックスに個別に適用されるバブル ソートと同様に動作し、パリティ グループごとに O(n^2) の動作が行われるため、全体では依然として O(n^2) になります。 

重要な観察は、スワップがパリティ境界を決して越えないということです。 インデックス 0、2、4、... の要素は 1 つの独立したシステムを形成し、インデックス 1、3、5、... の要素は別の独立したシステムを形成します。 各システム内で、許可されるスワップは、事実上、その縮小されたシーケンス内の隣接する要素間で行われます。 これはまさに、各サブシーケンスを完全に並べ替えるのに必要な操作です。 

したがって、スワップをシミュレートする代わりに、2 つのサブシーケンスを直接抽出し、それらを個別に並べ替えて、元のパリティ位置に戻します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | お(1) | 遅すぎる |
 | パリティの分割と並べ替え | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 インデックス パリティに基づいて配列を分離することで、問題を 2 つの独立した並べ替えタスクに分割します。

1. 配列を 2 つのリストに分割します。1 つは偶数のインデックスの要素を含み、もう 1 つは奇数のインデックスの要素を含みます。 これは、これら 2 つのグループ間で要素を移動する操作がないため機能します。 
2. 両方のリストを非降順で個別に並べ替えます。 各リストは、許可された操作の下で完全に接続されたスワップ グラフを表すため、リストを並べ替えることは、可能なすべてのスワップを適用することと同じです。 
3. ソートされた偶数インデックスのリストを偶数の位置に戻し、ソートされた奇数インデックスのリストを奇数の位置に戻して、元の配列を再構築します。 
4. 再構成された配列を出力します。 

重要な推論ステップは、各パリティ グループ内で、許可された操作により、縮小されたシーケンス内で隣接するスワップを効果的に実行できるようになり、完全にソートされた順序に達するのに十分であるということです。 

### なぜ効果があるのか

 この操作ではインデックスのパリティが維持されるため、配列は 2 つの独立したサブシステムに分解されます。 各サブシステム内で、元の配列内の i と i+2 を交換することは、抽出されたサブシーケンス内の隣接する要素を交換することに対応します。 隣接するスワップによって完全な置換グループが生成されるため、各サブシーケンスをソートすることは、到達可能なすべての構成をシミュレートするために必要かつ十分です。 したがって、再構築された配列は、すべての有効な操作後の正確な最終状態になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    even = a[0::2]
    odd = a[1::2]
    
    even.sort()
    odd.sort()
    
    ei = 0
    oi = 0
    res = []
    
    for i in range(n):
        if i % 2 == 0:
            res.append(even[ei])
            ei += 1
        else:
            res.append(odd[oi])
            oi += 1
    
    print(*res)

if __name__ == "__main__":
    solve()
```この実装は、概念的な分解を直接反映しています。 スライス操作ではパリティ グループが線形時間で分離され、各グループの並べ替えが複雑さを支配します。 再構築ステップでは、ソートされた 2 つの配列を慎重に交互に実行し、元のインデックス パリティが正確に保持されるようにします。 ここで最も一般的な実装ミスは、再構築中にパリティの割り当てを混同することです。これにより、たとえ両方の並べ替えられたリストが正しい場合でも、正確性が静かに損なわれます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、配列がグローバルに並べ替えられているが、パリティで区切られた順序付けがされていない場合です。 たとえば、[1、3、2、4] を考えてみましょう。 偶数の位置には [1, 2] が含まれ、奇数の位置には [3, 4] が含まれます。 アルゴリズムは両方のグループを並べ替えますが、この場合、グローバル順序は変更されず、完全な並べ替えではなく、許可された変換スペースと一致する [1, 3, 2, 4] が生成されます。 

もう 1 つの特殊なケースは、すべての要素が等しい場合です。 ソートによって相対的な順序が変更されないため、両方のパリティ リストは同一のままであり、再構築によって同じ配列が生成されます。 これにより、均一な入力下での安​​定性が確認され、意図しないスワップが発生しないことが保証されます。 

最後の微妙なケースは、n = 1 または n = 2 の場合です。n = 1 の場合、パリティ相互作用はまったくなく、配列は変更されません。 n = 2 の場合、各要素は個別のパリティ クラスに属するため、やはりスワップは不可能であり、出力は入力と正確に一致する必要があります。
