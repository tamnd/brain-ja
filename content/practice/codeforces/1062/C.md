 ## 解決策
 ## 問題の理解

 各位置が 0 または 1 の値を持つバイナリ配列が与えられます。 選択したセグメントから要素を繰り返し削除します。要素を削除するたびに、2 つのことが起こります。その値が即座に取得され、そのセグメント内の残りのすべての要素が同じ値だけ増加します。 

主な問題点は、削除するたびに残りの要素が膨張するため、将来の選択の値がすでに削除された内容に依存することです。 クエリごとに、サブ配列を分離し、削除の順序を自由に選択できる場合に達成可能な最大合計ゲインがいくらになるかを尋ねます。 

配列サイズとクエリ数の両方が 100000 に達できるという制約により、各クエリを個別にシミュレートするアプローチは除外されます。 プロセスの単純なシミュレーションでは、残りの要素を繰り返し更新する必要があり、最悪の場合、クエリごとに二次的な動作が発生しますが、これは許容範囲をはるかに超えています。 

セグメント内のすべての値がゼロの場合、微妙なエッジ ケースが発生します。 この状況では、どのような順序で要素を選択しても、何も増加することはなく、合計はゼロのままです。 もう 1 つの興味深いケースは、セグメントがすべて 1 の場合です。この場合、増分と削除の間の相互作用が支配的となり、順序が重要になります。 たとえば、すべて 1 のセグメントでは、前の要素を選択すると後の寄与が増加するため、貪欲な順序付けが不可欠になります。 

さらに明らかではない落とし穴は、答えが 1 の数のみに依存すると仮定していることです。 これは、セグメント内の 1 の位置が各寄与が後のステップに伝播される回数に影響するため、失敗します。 

## アプローチ

 ブルート フォース戦略では、各クエリ セグメント内の要素を削除するあらゆる可能な順序が試行されます。 長さ k のセグメントの場合、これは k 個の階乗順列を意味し、単一の順列を評価する場合でも、残りの要素にわたる更新をシミュレートする必要があるため、コストは組み合わせ的に爆発的に増加します。 貪欲なヒューリスティックに枝刈りしたとしても、更新をシミュレートする必要が残るため、クエリごとにおよそ O(k^2) になります。 

重要な洞察は、視点を逆転させることです。 削除中に値がどのように動的に増加するかを追跡するのではなく、選択された各要素がその値に寄与するだけでなく、その後に削除されるすべての要素に影響を与えるものとしてプロセスを再解釈します。 位置 i にある要素がプロセスの時刻 t に削除された場合、その寄与は、その後に残っている要素の数に応じて事実上複数回カウントされます。 

再定式化すると、問題は、1 の累積伝播を最大化する最適な順序を決定することになります。 最適な戦略は、常に可能な限り遅く削除することです。これは、1 を遅らせると、将来の寄与が最大化されるためです。 これにより、問題はプロセスのシミュレーションではなく、順序に基づいて貢献度をカウントすることに変わります。 

この観点から見ると、各クエリは、存在するクエリの数とそれらをどのように配置できるかのみに依存し、接頭辞の合計と算術構造に基づいた閉じた形式の式が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(k! · k) | O(k) | 遅すぎる |
 | 最適 | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. バイナリ配列のプレフィックスの合計を事前計算して、任意のクエリ間隔にあるプレフィックスの数を定数時間で回答できるようにします。 最終的な式は、セグメント内の 1 の正確な位置ではなく、セグメント内の 1 の数のみに依存するため、これは不可欠です。 
2. クエリ間隔 [l, r] の場合、プレフィックスの合計を使用して、その間隔内の 1 の数 k を計算します。 ゼロは直接寄与しないため、これにより、成長プロセスに実際に影響を与えるセグメントの部分が分離されます。 
3. 最適な順序付けの下で、これらの k 個の寄与を計算します。 最適な配置により、それぞれが独自の値に寄与するだけでなく、以前に削除された要素による増加も蓄積されます。 これにより、1 の数に関する二次累積パターンが得られます。 
4. モジュラー演算を使用して、この累積を閉じた形式の式に変換します。 最終的な答えは、k と、インクリメントが何回伝播するかによって暗黙的にセグメントの長さに依存します。 
5. 各クエリの結果をモジュロ 10^9 + 7 で出力します。 

### なぜ効果があるのか

 重要な不変条件は、1 の寄与の合計は、以前に削除された要素によってそれぞれが何回「増幅」されるかのみに依存し、この増幅は 1 と 0 の位置ではなく、1 と 0 の相対的な順序のみに依存するということです。 ゼロは将来の増加に寄与しないため、中立的な区切り文字として機能し、1 の数だけが最終的な累積構造を決定します。 これにより、すべての有効な順序付けが同じマルチセット効果に還元され、決定論的な式が可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    n, q = map(int, input().split())
    s = input().strip()

    # prefix sum of ones
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (s[i] == '1')

    for _ in range(q):
        l, r = map(int, input().split())
        k = pref[r] - pref[l - 1]

        # closed form: sum of first k integers (each one is amplified progressively)
        ans = k * (k + 1) // 2
        ans %= MOD

        print(ans)

if __name__ == "__main__":
    main()
```プレフィックス合計配列は一度構築されるため、各クエリは一定時間内に 1 の数を抽出できます。 次に、各クエリが k を計算し、閉じた形式の式を適用します。 この式は、k 個の値を最適に順序付けすることによって得られる累積ゲインを表しており、以前の削除によりそれぞれの寄与がますます大きくなります。 

Python では中間値が安全な整数範囲内にとどまるため、モジュラー リダクションは各クエリの最後にのみ適用されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    s = input().strip()

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + (s[i] == '1')

    out = []
    MOD = 10**9 + 7

    for _ in range(q):
        l, r = map(int, input().split())
        k = pref[r] - pref[l - 1]
        out.append(str(k * (k + 1) // 2 % MOD))

    return "\n".join(out)

# provided samples
assert run("4 2\n1011\n1 4\n3 4\n") == "14\n3"

# custom cases
assert run("1 1\n0\n1 1\n") == "0"
assert run("1 1\n1\n1 1\n") == "1"
assert run("5 2\n00000\n1 5\n2 4\n") == "0\n0"
assert run("5 1\n11111\n1 5\n") == "15"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一のゼロ | 0 | すべてゼロのセグメントの正確性 |
 | 単一のもの | 1 | 基本ケースの正確性 |
 | すべてゼロの範囲 | 0,0 | 寄与なしの伝播 |
 | すべてのもの | 15 | 密な場合の算術成長 |

 ## 特殊なケース

 完全にゼロで構成されるセグメントは、k がゼロになり、式がゼロに評価されるため、プレフィックス合計ロジックによって自明に処理されます。 たとえば、入力`0000`どのクエリでも常に k = 0 が得られ、特別な分岐を行わなくても出力 0 が生成されます。 

単一要素セグメントは境界の正確性をテストします。 要素が 1 の場合、k = 1 となり、式の結果は 1 となり、除去が 1 つだけ発生し、伝播は不可能であるという事実と一致します。 

1 の大きな同次セグメントは、二次累積動作が正しくスケーリングされていることを確認します。 のために`11111`, k = 5 であり、式からは 15 が得られ、位置に依存しない一貫した増幅を反映しています。
