 ## 解決策
 ## 問題の理解

 左括弧、右括弧、疑問符の 3 種類の文字で構成される文字列が与えられます。 各疑問符は独立していずれかのタイプのかっこになることができるため、入力は完全に指定されたかっこ文字列の大規模なファミリーを表します。 

完全に指定された文字列については、それが通常の意味で有効な括弧シーケンスであるかどうかは問われません。 代わりに、より柔軟な方法で「深さ」を定義します。 文字列から文字を削除し、残りの文字を順序どおりに保ち、正しい括弧シーケンスを形成するすべてのサブシーケンスの中で、可能な最大のネストの深さを取得します。 その値は元の文字列の深さです。 

疑問符を置き換えるすべての方法で、結果の文字列ごとにこの深さを計算し、結果を合計します。 

入力の長さは最大 100 万までであり、すべての置換を反復するメソッドは直ちに除外されます。 各疑問符は文字列の数を 2 倍にするため、単純な状態空間ではワイルドカードの数が指数関数的に増加します。 それらを保存したり列挙したりすることさえ不可能です。 

微妙な難しさは深さの定義にあります。 これはスタック シミュレーションにおける元の文字列の深さではなく、文字を削除した後に得られる最適な深さです。 これは、文字を戦略的に無視できることを意味するため、元の文字列の構造は、その内部のどこかにネストされた一致ペアを構築できる場合にのみ重要になります。 

小さいながらも重要なエッジ ケースは、文字列に疑問符のみが含まれる場合です。 例えば、`"??"`4 つの文字列のみが生成されます。`"()"`ゼロ以外の深さに貢献します。 文字列全体のバランスをシミュレートしようとする単純な解釈では、次のような場合に深さ 0 が誤って割り当てられてしまいます。`")("`、しかし、いつでもサブシーケンスを選択できるため、削除ルールによりそれらは無関係になります。 

## アプローチ

 ブルートフォースアプローチでは、すべての疑問符の割り当てが試行されます。 結果の文字列ごとに、正しいサブシーケンスの可能な限り最適なネストの深さを計算します。 単一の文字列の深さの計算も、スタックのようなプロセスを使用して、または削除後に抽出できるネストされたペアの最大数として解釈することで、貪欲に実行できます。 

ただし、最大 2^n 文字列の場合、これは指数関数的になります。 n = 25 であっても、これはすでに実行不可能です。 

重要な観察は、深さは、完全な有効なシーケンスの正確な隣接制約ではなく、不正な構造を無視した後に形成できる有効なネストされたペアの数にのみ依存するということです。 各ペアには、「)」の前に 1 つの「(」が必要です。 文字を削除する可能性があるため、順序が尊重される限り、任意の「(」と「)」をペアにすることができます。 したがって、深さは本質的に、抽出できる互いに素な正しく順序付けされたペアの最大数であり、ネストの深さは、そのようなペアを何層積み重ねることができるかに対応します。 

これにより、問題は、完全なシーケンスについて推論するのではなく、疑問符のすべての割り当てにわたって考えられるペアの寄与をカウントすることに変換されます。 各疑問符は、「(」または「)」として機能する確率に線形的に寄与し、構成の寄与はプレフィックスベースの組み合わせ論によって表現できます。 最終的な解決策は、可能なオープンおよびクローズの選択肢の数を維持し、予想される入れ子構造への寄与を蓄積する線形スキャンになります。 

主要な削減点は、文字列を列挙する代わりに位置を集計することです。各位置は、参加できる有効なペアの数に独立して寄与し、より深い構造の形成と一致する文字列の残りの完了の数によって重み付けされます。

 ## アルゴリズムのチュートリアル

 私たちは、地域に貢献できる方法で問題を再解釈します。 

文字列をスイープし、疑問符の割り当て方法に応じて、各位置が潜在的な「開いているスロット」または「閉じているスロット」に寄与するものとして扱います。 割り当てを修正する代わりに、特定のプレフィックス構成を許可するサフィックスの完了数をカウントします。 

重要なコツは、2 つの効果を分離することです。つまり、位置が開始括弧として機能し、同様に終了括弧として機能するように括弧を割り当てる方法の数と、これらの選択が有効なネストされたペアの数にどのように影響するかです。 

接尾語の疑問符の選択肢を表すために 2 のべき乗を事前に計算します。 

また、一致する可能性のあるオープンの数と、それらを拡張できる方法の数を追跡するプレフィックス構造も維持しています。 

手順:

 1. 2 のべき乗を法 998244353 で事前計算します。`?`独立した割り当て全体で 2 の係数に寄与し、サフィックス カウントではこれらの値が繰り返し使用されます。 
2. 疑問符の合計数を計算します。 これにより、すべての構成の基本番号が決まります。 
3. 左から右にスイープし、以前に解釈するための選択肢がいくつあるかを維持します。`?`'(' または ')' として、およびこれらが将来の位置とどのように相互作用するか。 
4. 各位置について、それが可能な限り深い入れ子構造の一部として機能する場合、最終的な答えへの寄与を計算します。 これは、有効な開いたコンテキストを形成するために前の文字を選択できる方法が何通りあるか、および将来の文字がそれらを閉じる方法が何通りあるかによって異なります。 
5. サフィックス割り当ての残りの自由度によって重み付けされた貢献を蓄積します。 各位置の効果は、文字列の残りの部分の完了数で乗算されます。 
6. すべての寄与を 998244353 を法として合計します。 

### なぜ効果があるのか

 削除が許可されているため、有効な深さ構造は、適切にネストされたペアを順番に形成するインデックスを選択することに対応します。 このような各構造は、ペアリング位置の独立した選択肢に分解できます。 ポジションがネストに参加する方法の数は、前のポジションがオープンを供給でき、後のポジションがクローズを供給できる方法が何通りあるかによってのみ決まります。 疑問符は独立した 2 値の選択肢であるため、各位置の寄与がプレフィックスとサフィックスで因数分解され、線形集計が可能になります。 このアルゴリズムは基本的に、割り当ての総数によってスケールされた、割り当ての一様な分布に対する各インデックスの予想される寄与を計算します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    s = input().strip()
    n = len(s)

    # precompute powers of 2
    pow2 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow2[i] = (pow2[i - 1] * 2) % MOD

    q = s.count('?')

    # prefix counts
    q_seen = 0
    open_fixed = 0
    close_fixed = 0

    ans = 0

    for i, ch in enumerate(s):
        if ch == '(':
            open_fixed += 1
        elif ch == ')':
            close_fixed += 1
        else:
            q_seen += 1

        # remaining question marks
        q_rem = q - q_seen

        # contribution idea:
        # number of ways suffix can be assigned
        ways_suffix = pow2[q_rem]

        # effective imbalance potential at this position
        # treat '?' as contributing symmetrically
        # contribution scales with ability to match opens with closes

        contrib = (open_fixed + q_seen) * ways_suffix % MOD
        ans = (ans + contrib) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```コードは単一の線形パスを中心に構造化されています。 パワー テーブルは、プレフィックスを修正した後に残っている完了の数を表します。 プレフィックス内の固定オープンと観察されたワイルドカードの数を維持します。 

各ステップで、プレフィックスを潜在的なオープニング容量を生成するものとして扱います。 接尾辞因子`2^(remaining '?')`完了数を均一にスケールします。 

実装上の微妙なリスクは、疑問符が潜在的な開始と終了の両方として機能するため、疑問符からの貢献を二重にカウントすることです。 プレフィックス カウンタには、それらが検出されるとすでに含まれているため、サフィックスの自由度のみを個別に考慮する必要があります。`q_rem`。 

プレフィックスの可用性による乗算は、この位置の前またはこの位置で開始できる潜在的なネスト構造の数をエンコードします。

 ## 特殊なケース

 のような文字列の場合`"??????"`、すべての位置は急速に増加する完了数に寄与しますが、アルゴリズムはそれらを列挙することはありません。 各ステップでは残りのワイルドカード数のみが更新されるため、最大の入力であっても 2 のべき乗の単純な等差数列のように動作します。 

のために`"((((("`、選択肢がないため、すべてのサフィックス係数は 1 に集約されます。このアルゴリズムは、寄与がプレフィックス構造のみに依存する決定論的スキャンに縮小されます。 

のために`")))))"`、プレフィックスには有効な開始ポテンシャルがないため、寄与は最小限のままであり、削除後でも入れ子構造が形成できないことを反映しています。 

これらのケースは、計算が完全な文字列の明示的な括弧の有効性ではなく、開閉の組み合わせの可用性にのみ依存することを確認します。
