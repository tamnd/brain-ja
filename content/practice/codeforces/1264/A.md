 ## 解決策
 ## 問題の理解

 コンテストの結果を表す、増加しないスコアの配列が与えられます。 私たちの仕事は、このランキングの上位部分を、ゴールド、シルバー、ブロンズの 3 つの連続するグループに分割することです。 銅グループ以降はメダルを獲得できません。 

分割では、サイズの制約と厳密なスコア分離の制約の両方を尊重する必要があります。 すべてのゴールド参加者はすべてのシルバー参加者よりも厳密に優れた成績を収める必要があり、すべてのシルバー参加者はすべてのブロンズ参加者よりも厳密に優れた成績を収める必要があり、すべてのブロンズ参加者は何も受け取らないすべての参加者よりも厳密に優れた成績を収める必要があります。 

その構造的な順序に加えて、金メダルの数は銀メダルと銅メダルの両方の数よりも厳密に少なくなければなりません。 最後に、授与されるメダルの総数は、最大でも全参加者の半分に制限されます。 

出力は参加者の ID ではなく、これら 3 つの連続するセグメントのサイズのみです。 

この制約は、テスト ケース全体で二次関数、さらには二次関数に近いことを実行できないことを意味します。 すべてのテストの参加者の合計数は 400,000 人に達するため、テスト ソリューションごとに O(n) または O(n log n) が必要となり、リニア スキャンが強く優先されます。 

明らかではない難しさは、厳密なスコアの低下でグループ間の境界が発生する必要があることです。 隣接する 2 人の参加者が同じスコアを持っている場合、異なるメダルの種類に分割することはできません。 これにより、多くの境界候補が無効になるため、単純な「すべての分割を試す」ことが脆弱になります。 

典型的な失敗例は、貪欲な分割が等価ブロックを無視した場合に発生します。 たとえば、スコアが`[5, 5, 5, 4, 4, 1, 1]`、選択する`g=1`そして`s=1`金と銀は同じスコアを共有するため、すぐに制約が破られます。 正しいソリューションでは、カットとスコアの移行が一致している必要があります。 

## アプローチ

 ブルートフォース戦略では、すべてのトリプルが試行されます。`(g, s, b)`順序とサイズの制約が満たされるようにします。 各候補について、スコア分離条件が成立するかどうかを検証します。 単一の構成のチェックが線形であっても、一定のサイズの配列内で 2 つのカット ポイントを選択するため、パーティションの数は 2 次になります。`n`。 これにより、テスト ケースあたりの構成はおよそ O(n²) となり、合計 400,000 個の要素にとっては遅すぎます。 

重要な観察は、有効なパーティションの構造が単調であるということです。 ゴールドサイズの値を修正したら`g`、シルバーグループは次の異なるスコアブロックから開始する必要があり、ブロンズグループも同じルールに従わなければなりません。 等しいスコアのセグメント内を「検索」する必要はありません。 私たちは常に同じ値のブロックを飛び越えます。 

これにより、同じ値のブロック境界を維持しながら配列を 1 回スキャンするという問題が軽減されます。 考えられるゴールドのサイズごとに、シルバーとブロンズを次の有効な境界まで貪欲に拡張し、同時にそれを強制します。`g < s`、`g < b`を超えず、合計が`n/2`。 配列はソートされているため、各境界はスコアが変化する場所によってのみ決定されます。 

次に、可能なゴールドの境界を繰り返し、シルバーとブロンズを貪欲に拡張し、有効な位置がいくつ残っているかを追跡することで、実現可能な最適な構成を検索します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 配列を走査し、同じスコアの連続ブロックに圧縮します。 各ブロックは、内部分割が許可されない範囲を表します。 

その理由は、ブロック内で分割すると、メダル層間の厳密な不平等に違反することになるためです。 
2. これらのブロックにサイズを持たせる`cnt[0], cnt[1], ..., cnt[k-1]`。 
3. 最初にゴールドセグメントを選択します`i`ブロック、累積サイズ`g`。 
4. シルバーはブロックから開始する必要があります`i + 1`少なくとも 1 つのブロックにまたがるため、サイズが得られるまでブロックを蓄積します。`s > g`。 
5. ブロンズはシルバーの直後に開始され、次の条件を満たす必要があります。`b > g`, そのため、ブロンズ サイズがゴールド サイズを超えるまでさらに拡張します。 
6. 有効な配置ごとに、`i`、計算します`(g, s, b)`かどうかを確認してください`g + s + b <= n // 2`。 
7. 総メダル数が最大となる構成を維持します。 

重要な点は、ゴールドが固定されると、シルバーとブロンズは最小限の有効な拡張を強制されるということです。 すべてが固定の半分の制限によって制限されるため、拡張を大きくしても残りのスペースが減るだけで、後のパーティションの実現可能性は向上しません。 

### なぜ効果があるのか

 正確さは、ソートされたスコアによって引き起こされる単調な構造に依存します。 有効なパーティションはスコア ドロップと一致する必要があるため、問題はブロック境界から 2 つのカット ポイントを選択することになります。 固定されたゴールドの境界の場合、シルバーを増やすとブロンズの利用可能なスペースが減少するだけであり、満足するのには役立たないため、最小の有効なシルバーの境界が常に最適です。`s > g`。 同じ論理がブロンズにも当てはまります。 

したがって、貪欲な拡張では、制約の下で合計サイズを最大化できる唯一の候補が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))

        # compress into blocks of equal values
        blocks = []
        i = 0
        while i < n:
            j = i
            while j < n and p[j] == p[i]:
                j += 1
            blocks.append(j - i)
            i = j

        m = len(blocks)
        best = (0, 0, 0)
        total_best = 0

        prefix = 0

        # iterate gold ending at block i
        for i in range(m):
            g = prefix + blocks[i]
            if g >= n // 2:
                break

            # build silver
            s = 0
            j = i + 1
            if j >= m:
                prefix += blocks[i]
                continue

            s_start = j
            while j < m and s <= g:
                s += blocks[j]
                j += 1
            if s <= g:
                prefix += blocks[i]
                continue

            # build bronze
            b = 0
            k = j
            while k < m and b <= g:
                b += blocks[k]
                k += 1
            if b <= g:
                prefix += blocks[i]
                continue

            if g + s + b <= n // 2:
                if g + s + b > total_best:
                    total_best = g + s + b
                    best = (g, s, b)

            prefix += blocks[i]

        if total_best == 0:
            print(0, 0, 0)
        else:
            print(*best)

if __name__ == "__main__":
    solve()
```コードは、等しいスコアのセグメントを圧縮することから始まります。そのようなセグメント内で分割すると、メダル タイプ間の厳密な順序付け要件に違反するためです。 圧縮後、各ブロックはアトミック単位として扱われます。 

次に、可能なゴールドエンドを繰り返します。 変数`prefix`ゴールド グループのサイズを効率的に追跡します。 ゴールドの選択ごとに、厳密にゴールドを超えるまでシルバーを貪欲に拡張し、その後ブロンズでも同じことを行います。 いずれかの拡張が失敗すると、設定は破棄されます。 

条件`g + s + b <= n // 2`グローバル制約を強制します。 これまでに見つかった最適な構成を追跡します。 

微妙な点は、ゴールドが大きくなりすぎると、それ以降のゴールドの価値は増加するだけなので、早期に中断することです。`g`、次の理由により実現可能性は厳密に困難になります。`n/2`制約。

 ## 特殊なケース

 重大なエッジケースは、潜在的な境界付近に大きな等しいスコアのブロックが出現する場合です。 このようなブロック内で金が終了する場合、同じブロック内で銀を開始することはできません。 圧縮ステップにより、ゴールドはブロック全体を消費するか、ブロックをまったく消費しなくなり、無効な部分分割が防止されます。 

もう 1 つのエッジケースは次のような場合です`n`特に小さいです`n < 6`。 スコアの順序付けが完璧であっても、半分の制限により、空でない 3 つのグループを割り当てることが不可能になることがよくあります。`g + s + b`少なくとも 3 つ、最大でも 3 つでなければなりません`n/2`。 

3 番目のケースは、すべてのスコアが等しい場合に発生します。 3 つの層を形成しようとすると、隣接するグループ間の厳密な不平等に違反するため、常に正しい出力が得られます。`0 0 0`。
