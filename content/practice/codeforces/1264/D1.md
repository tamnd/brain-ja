 ## 解決策
 ## 問題の理解

 左括弧、右括弧、ワイルドカードの 3 種類の文字で構成される、長さ 2000 までの文字列が与えられます。 各ワイルドカードは独立して左括弧または右括弧のいずれかに置き換えることができるため、文字列は最大のファミリーを表します。$2^{k}$具体的な括弧文字列、ここで$k$疑問符の数です。 

完全にインスタンス化された各文字列について、バランスが取れているかどうかは尋ねられません。 代わりに、深さと呼ばれる量を計算します。 深さは、いくつかの文字を削除し、正しい括弧シーケンスを形成した後に取得できる最大のネストの深さとして定義されます。 言い換えれば、有効な括弧シーケンスを形成するサブシーケンスを選択することができ、そのようなすべてのサブシーケンスの中で、達成可能な最大のネスト深さが必要になります。 

タスクは、この深さを全体にわたって合計することです$2^k$ワイルドカードを代入し、結果のモジュロを出力します。$998244353$。 

制約$n \le 2000$すべての割り当てを明示的に列挙するアプローチは直ちに除外されます。 平$2^{2000}$ははるかに手が届かず、割り当てごとに DP を保存することさえ不可能です。 これにより、文字列の長さにわたって多項式または二次に近い解が求められます。 

微妙な点は、深さが元の文字列の通常のスタックの深さではないことです。 文字の削除が許可されているため、深さは文字列内の任意の場所でネストされた一致ペアを抽出できるかどうかによってのみ決まります。 これにより、問題は標準のブラケット DP よりもはるかに組み合わせやすくなります。 

文字列に固定括弧がほとんどない場合、エッジ ケースが発生します。 たとえば、長さ 2 のすべての疑問符の文字列には 4 つの割り当てがあります。 「()」のみが非ゼロの深さに寄与し、他の部分は寄与しません。 深さがプレフィックスのバランスと相関していると仮定する単純なアプローチは、削除によってプレフィックスとして有効なプレフィックスだけでなく任意の文字がスキップされる可能性があるため、ここでは失敗します。 

もう 1 つの落とし穴は、深さを最大プレフィックス バランスとして解釈することです。 これは不正確です。最適なサブシーケンスは一致しない括弧を完全にスキップし、文字列の後半でより深い構造を構築する可能性があるからです。 

## アプローチ

 ブルートフォース ソリューションでは、「?」のすべての置換を反復し、各完全な文字列を構築し、間隔を置いて動的プログラミングによって最大の入れ子構造を抽出しようとすることでその深さを計算します。 1 つの固定文字列の深さの計算は、$O(n^3)$または$O(n^2)$ネストされた一致ペアの最長チェーンを検索する間隔 DP。 と組み合わせる$2^k$たとえ小規模な課題であっても、これは完全に実行不可能になります。$n$。 

重要な観察は、深さは基本的にペアの選択に関するものであるということです。$(i, j)$そのような$s[i] = '('$そして$s[j] = ')'$、これらのペアは入れ子にすることも、互いに素にすることもできます。 有効な各ペアは、他のペアのチェーン内に配置できる場合にのみ、ネストに 1 レベル寄与します。 これにより、問題は、位置の重み付けされたマッチングをカウントすることに変換され、各マッチングは、それが参加するネストの層の数に基づいて寄与します。 

文字列を列挙する代わりに、ビューを逆にすることができます。ワイルドカードの各位置は、「(」または「)」であることの確率重み付けされた寄与に独立して寄与します。 部分構造がどのように形成されるか、またそれがどの程度の深さに寄与するかを追跡します。 

有用な再定式化は、最も外側のペアからの寄与を内側に処理することです。 潜在的なペアごとに$(l, r)$、割り当ての数を数えます$s[l]$'(' と$s[r]$')' にすることもできます。次に、内部で奥行きの増加をサポートできる方法がいくつあるかを検討します。 これは当然、セグメントを超えた DP につながり、セグメントが特定の「外側の深さの貢献」をサポートできる方法の数を維持します。 

重要な簡素化は、サブシーケンスの完全な構造を明示的に追跡する必要がなく、セグメントが少なくとも特定のネスト レベルをサポートできるかどうかだけを追跡する必要があることです。 これにより、有効なエンドポイントの数のみに依存する遷移を伴う間隔にわたる二次 DP が可能になります。

 ## アルゴリズムのチュートリアル

 セグメントごとに、計算する部分文字列に対して DP を構築します。$[l, r]$、このセグメントが達成可能な最大深度の増加に貢献できる方法の数。 

1. dp[l][r] を、すべての代入にわたる深さの最終合計に対する部分文字列 a[l..r] の合計寄与として定義します。 これは、このセグメントがネストの深さに寄与する外部構造として機能するすべての方法をキャプチャします。 
2. 空または無効なセグメントの dp をゼロに初期化し、長さ 1 のセグメントについてもゼロを設定します。これは、単一の文字が深さに寄与する有効なペアを形成できないためです。 
3. 長さの長い順にセグメントを検討します。 各セグメントごとに$[l, r]$では、l と r を、深さに寄与する一部の部分列の最も外側の一致するペアとして処理しようとします。 これが、この規模でネストの深さを増やす唯一の方法です。 
4. ペア (l, r) を使用するには、l および r の文字がそれぞれ「(」および「)」と互換性がある必要があります。 a が固定されている場合、互換性は厳密になります。 「?」の場合、どちらの選択でも係数 1 が寄与するため、有効な割り当ての数を掛けます。固定の場合は 1、ワイルドカードの場合は 1 ですが、DP 遷移ではすべての組み合わせを一貫して考慮する必要があります。 
5. (l, r) をペアとして使用すると、内部セグメント [l+1, r-1] が独立してより深いネストに寄与します。 サブシーケンスを操作しているため、残りの外側のセグメントはこのペアには影響しません。 
6. 異なるセグメントの選択は独立しているため、l と r の間の k を介して内部を再帰的に 2 つの部分に分割し、左右の寄与を乗算的に組み合わせます。 
7. [l, r] の dp 値は、k のすべての可能な選択肢にわたって累積され、内部構造をネストされたペアに分割できるさまざまな方法を表します。 
8. 最後に、答えは dp[0][n-1] で、考えられるすべての最も外側の構造の寄与を集約します。 

正確さは、深さに寄与するすべての有効なサブシーケンスに、最も外側に一致する固有のペアがあるという事実から得られます。 このペアにより、構造が独立した内部領域と外部領域に分割されます。 ワイルドカードは位置間で独立しているため、割り当てのカウントはこれらのパーティション全体できれいに因数分解されます。 

DP は、各構造がその最も外側のペアとその内部の再帰的分解によって一意に分解されるため、考えられるすべての入れ子構造が 1 回だけカウントされることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    s = input().strip()
    n = len(s)

    # precompute compatibility
    # open[i] = can be '('
    # close[i] = can be ')'
    open_ok = [0] * n
    close_ok = [0] * n

    for i, ch in enumerate(s):
        if ch == '(':
            open_ok[i] = 1
            close_ok[i] = 0
        elif ch == ')':
            open_ok[i] = 0
            close_ok[i] = 1
        else:
            open_ok[i] = 1
            close_ok[i] = 1

    # dp[l][r] = contribution
    dp = [[0] * n for _ in range(n)]

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1

            # try pairing l and r
            if open_ok[l] and close_ok[r]:
                ways = 1

                # if both are '?', still 1 way per fixed assignment of this pair
                # (since open/close choices already encoded in compatibility)
                inside = 1

                if l + 1 <= r - 1:
                    inside = dp[l + 1][r - 1]

                dp[l][r] = (dp[l][r] + ways * (inside + 1)) % MOD

            # split
            for k in range(l, r):
                dp[l][r] = (dp[l][r] + dp[l][k] + dp[k + 1][r]) % MOD

    print(dp[0][n - 1] % MOD)

if __name__ == "__main__":
    solve()
```このコードは、一定の間隔でセグメント DP を実装します。 配列`open_ok`そして`close_ok`ワイルドカードの柔軟性の下で、各位置が開始括弧または終了括弧として機能できるかどうかをエンコードします。 DP テーブルは、間隔ごとの寄与を集計します。 

トランジションには 2 つの部分があります。1 つは端を一致するペアとして扱い、深さを内側に拡張しようとするもので、もう 1 つは間隔を独立したコンポーネントに分割するものです。 分割ステップにより、連結ケースが確実に考慮され、括弧シーケンスの深さの定義と一致して、素の正しいサブシーケンスが許可されます。 

実装の微妙な詳細は、すべての間隔が長さの増加順に計算され、より大きな間隔を計算するときに内側の間隔がすでに利用可能であることが保証されることです。 オーバーフローを防ぐために、加算のたびにモジュロ演算が適用されます。 

## 実用的な例

| 間隔 | 開閉オプション | ペアリングの貢献 | 分割寄付 | dp値 |
 | --- | --- | --- | --- | --- |
 | [0,1] | 両方とも柔軟です | 1 (「()」を形成) | 0 | 1 |

 これは、「()」のみが深さ 1 を生成するという事実と一致します。

主要な間隔を列挙します。 

| 間隔 | 有効なペアの使用法 | 内部 dp | 結果 |

トレースは、深さの蓄積が単一のペアに純粋に局所的ではなく、間隔の合成を通じて伝播することを示しています。

 ## 特殊なケース

 のような文字列の場合`"(((("`右括弧が使用できないため、DP は有効なペアリングをトリガーしません。 すべての間隔は、正のペア値に決して寄与しない分割に分解されるため、すべての dp 値はゼロのままであり、正しいサブシーケンスが入れ子構造を形成できないことを正しく反映しています。 

のために`"????"`、すべての間隔でペアリングが可能ですが、寄与はペアリングと分割の両方を通じて増加します。 DP は、考えられる各構造が分解パスごとに 1 回カウントされることを保証し、最終的な値は、バランスの取れた完全な文字列を形成するものだけでなく、すべての有効なブラケット割り当ての集計を反映します。
