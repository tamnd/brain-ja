 ## 解決策
 ## 問題の理解

 私たちには、通路によって連続したブロックに分割された座席の列が与えられます。 各ブロックは正の長さの座席セグメントであり、連続する 2 つのブロックの間には通路が 1 つだけあります。 あれば$k$通路、それからあります$k+1$ブロックとそのサイズは次の構成を形成します。$n$の中へ$k+1$正の整数。 

ブロック内の各座席には、最も近い通路までの距離に等しい料金がかかります。 つまり、同じサイズのブロック内で$m$、寄与度は対称的です。通路に近い席は寄与度 0、次に 1、というようにブロックの最も遠い端まで寄与します。 

不便さの合計は、これらのブロック内距離のすべてのブロックにわたる合計です。 この合計値を最小化するブロック サイズを選択し、その最小値を法的に達成する異なるブロック サイズ シーケンスの数もカウントする必要があります。$998244353$。 

したがって、キーオブジェクトは以下の構成物となります。$n$の中へ$k+1$正の整数。各パーツはそのサイズに応じて凸コストに寄与します。 

制約は特定の点で大きいです。 テストケースの数は最大です$10^5$、そして両方$n$そして$k$大きくてもよい、$n$まで$10^9$。 ただし、すべての合計は、$k$によって制限されています$10^6$これは、あらゆるソリューションが次の要素に線形的に依存することを強く示唆しています。$k$テストごとに許容されますが、状況に応じて何でも構いません$n$直接は無理です。 

すべての構成を列挙する素朴なアプローチ$n$の中へ$k+1$このような構成の数は膨大であるため、パーツを分割することは直ちに不可能です。$\binom{n-1}{k}$、これは指数関数的です$k$中程度の値であっても実行不可能です。 

コストの計算では、さらに微妙な問題が発生します。 構成を修正したとしても、各ブロックをシミュレートして不便さを再計算するのは問題ありませんが、すべての構成を探索するのが本当のボトルネックです。 

エッジケースが発生するのは次の場合です$k$に近いです$n-1$、つまり、自明な構造を除いて、すべてのブロックのサイズが 1 であることを意味します。$k=1$この場合、問題は 2 つの部分に分割され、コストは 1 つの変数の単純な関数になりますが、それでも広い範囲にわたって最適化する必要があります。 

特に起こりやすい間違いは、離散性制約を証明せずに、均等分割が常に最適であると仮定することです。 もう 1 つは、ブロックあたりのコストを二次関数のような動作ではなく線形として扱うことです。 

## アプローチ

 まず、単一ブロックのコストを再解釈します。 あるサイズのブロックを考えてみましょう$m$。 座席の端からラベルを付けます。最も近い通路までの距離は次のとおりです。$0,1,2,\dots$中間点までは対称になります。 総コストは以下にのみ依存する関数になります。$m$、具体的には次のように比例します。$\lfloor m/2 \rfloor \cdot \lceil m/2 \rceil$。 これは、対称距離をペアにするか、等差数列を合計することによって検証できます。 

したがって、問題は選択に帰着します$k+1$正の整数$a_1,\dots,a_{k+1}$、合計すると$n$、最小化する$$\sum f(a_i), \quad f(m) = \left\lfloor \frac{m^2}{4} \right\rfloor.$$機能$f(m)$に凸です$m$、その離散 2 番目の差は負ではないためです。 これはすぐにバランスの原則を示唆しています。質量を可能な限り均等に分配すると、凸コストの合計が最小限に抑えられます。 

したがって、最適な構造は、すべてのブロック サイズの差が最大 1 であることです。$k+1 = g$、それでは分割したいと思います$n$の中へ$g$可能な限り等しい部分:$$n = qg + r, \quad 0 \le r < g,$$それで$r$パーツにはサイズがある$q+1$、 そして$g-r$パーツにはサイズがある$q$。 

これにより、直接接続することで最小限の不便が軽減されます。$f$。 

カウント部分は組み合わせです。どのブロックにサイズを割り当てる方法が何通りあるかをカウントする必要があります。$q+1$。 ブロックは順序付けされている (シーケンスを形成している) ため、どのブロックを選択するか$r$位置が大きい値になると、レイアウトが完全に決まります。 したがって、最適なレイアウトの数は単純に次のようになります。$$\binom{g}{r}.$$強引なアイデアでは、すべての構成を試すことになります。 これは指数関数的です$n$。 最適解は、構造を単一の除算ステップと二項係数に分解します。

 ## アルゴリズムのチュートリアル

 しましょう$g = k+1$、セグメントの数。 

1. コンピューティング$g$そして分ける$n$による$g$、商を求める$q$そして残り$r$。 

凸性により均一性が強制されるため、これによって最適解の唯一の実現可能な形状が決まります。 
2. ブロックの寄与を合計して最小コストを計算します。 

各ブロックが貢献する$f(q)$または$f(q+1)$。 

次のように計算します。$$(g-r)\cdot f(q) + r \cdot f(q+1).$$3. どの方法を選択するかの数を計算します。$r$セグメント受信サイズ$q+1$。 

順序が重要であり、ブロックは位置によってのみ区別できるため、これは直接の二項係数です。$$\binom{g}{r} \bmod 998244353.$$4. 可能な限り最大限まで階乗と逆モジュラーを事前計算します。$k+1$クエリでは二項計算を繰り返す必要があるためです。 

これが機能する主な構造的理由は、バランスの取れたサイズからの逸脱を局所的に改善できることです。 2 つのブロックが少なくとも 2 異なる場合、1 つのユニットを大きい方から小さい方に移動すると、凸状性により総コストが厳密に減少します。$f$。 

## なぜ機能するのか

 ブロックあたりのコスト関数はブロック サイズが凸であるため、2 つのブロック間の不均衡があると総コストが増加します。 1 つのシートを大きいブロックから小さいブロックに移動する操作を繰り返し適用すると、合計の合計は維持されますが、すべてのサイズの違いが最大 1 になるまで厳密にコストが削減されます。 このプロセスは、次の条件によってのみ決定されるブロック サイズの一意のマルチセットに収束します。$n$そして$g$、最適性を確立します。 より大きなブロックの位置のみが自由に選択できるため、組み合わせ部分が続きます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

MAXK = 1000005

fact = [1] * (MAXK)
invfact = [1] * (MAXK)

for i in range(1, MAXK):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXK - 1] = pow(fact[MAXK - 1], MOD - 2, MOD)
for i in range(MAXK - 2, -1, -1):
    invfact[i] = invfact[i + 1] * (i + 1) % MOD

def C(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def block_cost(m):
    return (m // 2) * ((m + 1) // 2)

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    g = k + 1

    q, r = divmod(n, g)

    min_cost = (g - r) * block_cost(q) + r * block_cost(q + 1)
    ways = C(g, r)

    print(min_cost, ways)
```The factorial precomputation is necessary because each test case needs a binomial coefficient, and recomputing combinations per query would otherwise be too slow.

 機能`block_cost`単一セグメントの導出された閉じた形式をエンコードします。 コストは下限値と上限値の動作によるパリティに依存するため、整数除算は慎重に使用することが重要です。 

剰余の分布には次のものを使用します。`divmod`これは、最適な構成における唯一の自由、つまりどのブロックが追加のシートを取得するかを直接捉えます。

    import sys
    input = sys.stdin.readline

    MAXK = 50  # small for tests

    fact = [1] * (MAXK)
    invfact = [1] * (MAXK)

    invfact[MAXK - 1] = pow(fact[MAXK - 1], MOD - 2, MOD)
    for i in range(MAXK - 2, -1, -1):
        invfact[i] = invfact[i + 1] * (i + 1) % MOD

    def C(n, r):
        if r < 0 or r > n:
            return 0
        return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

    def block_cost(m):

    out = []

 ## 特殊なケース

 いつ$k = n-1$、すべてのブロックのサイズは 1 でなければなりません。アルゴリズムは次のように計算します。$g=n$、$q=1$、$r=0$、すべてのシングルトン ブロックを生成し、コストはゼロです。すべての座席が通路に隣接しているため、これは正しいことです。 

いつ$k = 1$、2つのブロックに分かれます。 アルゴリズムは次のようになります。$n = 2q + r$、等しい半分か 1 の差を与え、凸二次コストの最適なバランスに一致します。 

いつ$n$で割り切れない$k+1$、剰余の分布により正確に保証されます。$r$より大きなブロックであり、組み合わせ項はそれらの位置のすべての順列を正確に説明します。
