 ## 解決策
 ## 問題の理解

 この問題では整数の配列が与えられ、それを「サボテン配列」に変換するよう求められます。 サボテン配列は、各要素について、要素自体が極大値であるか、いくつかの変換後の前の要素と等しくなるように定義されます。 簡単に言うと、一部の要素を増やすことはできますが、減らすことはできません。目標は、これらのルールに基づいて、最終的なサボテン配列内の位置に等しい要素の数を最大化することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースは整数で始まります$n$、配列の長さ、その後に続く$n$整数。 出力では、テスト ケースごとに、変換後にサボテン条件を満たすことができる要素の最大数が報告されます。 

制約は中程度です。$n$まで到達できます$2 \cdot 10^5$すべてのテストケースにわたって、つまりナイーブ$O(n^2)$解決策が遅すぎるでしょう。 おおよそ次のような解決策が必要です$O(n)$または$O(n \log n)$テストケースごとに。 

すべての要素が同じである場合、微妙な特殊なケースが発生します。 たとえば、配列`[1, 1, 1]`何も操作しなくても、すでにサボテンの条件を満たしています。 すべての要素を貪欲に増やそうとする単純なアプローチでは、変換が過剰にカウントされたり、無効なシーケンスが生成されたりする可能性があります。 

要素が厳密に減少する場合、別の注意が必要な状況が発生します。 例えば、`[3, 2, 1]`完全に増加する配列に変換することはできず、不用意に実装すると無効な操作が試行される可能性があります。 正しい出力では、「減少できない」ルールが尊重され、実行可能な変換のみがカウントされます。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべての変換シーケンスを試すことです。 各要素について、サボテンの要件に合わせて増やすか、変更しないままにするかを試行します。 このアプローチはすべての有効なシーケンスを探索するため正しいですが、シーケンスの数は指数関数的に増加します。 のために$n = 10^5$、これにより、大まかに言って、実行不可能な数の操作が発生します。$O(2^n)$。 

重要な観察は、変換の問題は、制約された方法で「ピーク」を数えることに還元できるということです。 すべての要素は、新しいピークを開始するか (前の要素よりも厳密に大きい場合)、プラトーが継続します (前の要素と一致する場合)。 値を増やすことしかできず、減らすことはできないため、ピークの数は、連続する要素間の差と、前の要素が継続を許可するかどうかによって決まります。 この洞察により、問題は要素ごとにいくつかのチェックを行う単純な線形スキャンに帰着します。 

各変換は単一の要素に対してローカルであるため、ブルート フォースは機能しますが、指数関数的な分岐によりシーケンスが長い場合は失敗します。 「現在のピーク値」を追跡する必要があるだけであり、最後の要素が増加したかどうかを認識することで、決定空間を折りたたむことができます。$O(n)$。

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`cactus_count`ゼロに。 この変数は、サボテン条件を満たす要素の数を追跡します。 
2. 変数を初期化する`prev`ゼロに。 これにより、変換された配列の最後の要素が保存されます。 
3. 配列を左から右に繰り返します。 
4. 各要素について`a[i]`より大きいかどうかを確認します。`prev`。 その場合は増分します`cactus_count`それは新たなピークになる可能性があるからです。 
5. もし`a[i]`に等しい`prev`、前のプラトーを継続できるため、増加します`cactus_count`。 
6.アップデート`prev`前の値または現在の要素の最大値になります。 これにより、変換の非減少特性が強制されます。 
7. すべての要素をスキャンした後、`cactus_count`最大数のサボテン要素が含まれます。 

**機能する理由**: 不変条件は次のとおりです。`prev`は常に、変換された配列内の最後の有効な値を表します。 より大きい任意の要素`prev`新しいピークを開始し、次の要素と等しい`prev`高原が続きます。 決して減らないから`prev`すべての変換が有効であり、サボテン要素のカウントが正しいことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        cactus_count = 0
        prev = 0
        for x in a:
            if x > prev:
                cactus_count += 1
            elif x == prev:
                cactus_count += 1
            prev = max(prev, x)
        print(cactus_count)

if __name__ == "__main__":
    solve()
```このソリューションは、高速 I/O を使用してすべての入力を読み取ります。 重要な部分は、配列を 1 回スキャンして更新するループです。`cactus_count`そして`prev`ピーク/プラトールールに基づいて。 の`max(prev, x)`非減少制約に違反しないようにします。 サイズ 1 の配列やすでに互いに等しい要素などの境界条件は、同じロジックによって自然に処理されます。

 ## 特殊なケース

 For the edge case`[4, 3, 2, 1]`、アルゴリズムは左から右にスキャンします。 最初の要素`4`ピークを形成するので、`cactus_count = 1`。 後続の各要素は以下より小さいです`prev = 4`, したがって、何もカウントされません。 出力は`1`減少は許可されていないため、これは正しいです。 

のために`[3, 3, 3]`、`prev`0 から始まります。各要素は次と等しいです。`prev`以上なので、すべての要素がサボテンの数に影響します。 これにより、プラトー処理が正しいことが確認されます。
