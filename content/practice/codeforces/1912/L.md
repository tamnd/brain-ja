 ## 解決策
 ## 問題の理解

 それぞれ「L」または「O」のいずれかの項目の行が与えられます。 目標は、この線を任意の位置でカットして、左側の部分を自分が取り、右側の部分を友達が取るようにすることです。 両方の部分が空であってはなりません。 

制約は絶対数に関するものではなく、2 つの部分間の比較に関するものです。 あなたのセグメント内の「L」項目の数は、友人のセグメント内の「L」項目の数と異なっていなければなりません。また、「O」についても同じことが当てはまります。 有効なカット位置を見つけるか、存在しないことを報告するように求められます。 

これを再構成する便利な方法は、両方の文字の数が接頭辞と接尾辞の間で「アンバランス」である接頭辞を検索することです。 接頭辞を選択すると接尾辞は完全に決定されるため、問題は、どちらの次元でも文字数が接尾辞の数を反映していない接頭辞が存在するかどうかを確認することになります。 

制約は小さく、n は最大 200 です。これにより、必要に応じて O(n²) または O(n³) の推論がすぐに可能になりますが、プレフィックス情報を含む線形スキャンで十分であることも強く示唆されています。 

単純な落とし穴は、合計数の不均衡があれば必ず解決できると思い込んでしまうことです。 たとえば、「LOL」のような文字列では、分割ごとに少なくとも 1 文字の対称分散が強制され、すべての分割が無効になります。 もう 1 つの微妙な失敗例は、プレフィックス数が合計の半分と異なる位置を見つけるだけで十分であると想定していることです。これは、ある文字が異なっていても、もう一方の文字が等価になる可能性があることを無視しています。 

## アプローチ

 ブルートフォースのアイデアは単純です。 1 から n - 1 までのすべてのカット位置 k を試します。カットごとに、プレフィックスとサフィックスの「L」と「O」を数えて比較します。 各チェックには O(n) のコストがかかり、合計の複雑さは O(n²) になります。 n = 200 の場合、これはまだ十分小さいですが、不必要な作業です。 

重要な観察は、プレフィックス数を増分的に維持できるということです。 「L」と「O」の合計数がわかれば、各分割のサフィックス数を定数時間で導き出すことができます。 これにより、各チェックが O(1) に減り、フル スキャンが O(n) になります。 

より深い構造的洞察は、プレフィックスの蓄積を超えて、異なるカット位置間に依存性がないということです。 各分割は独立しており、必要な情報はすべて実行カウントを使用して要約できます。

 ## アルゴリズムのチュートリアル

 1. 文字列全体の「L」と「O」の合計数を計算します。 これらは、プレフィックスを選択したときに友人が受け取るものを表します。 このステップは、サフィックス数を再計算せずに導出できるようにするために必要です。 
2. 「L」および「O」のプレフィックス カウンタをゼロに初期化します。 これらは、カット位置を左から右に拡張するときに取得したものを追跡します。 
3. カット位置 k を 1 から n - 1 まで繰り返し、位置 k に文字を追加してプレフィックス カウンタを更新します。 スクラッチから再計算することを避け、プロセスを線形に保ちます。 
4. 各位置について、合計からプレフィックスを差し引いたサフィックス数を計算します。 これにより、サフィックスをスキャンせずに、友人の正確な分布が得られます。 
5. 両方の条件を確認します: prefix_L ≠ suffix_L および prefix_O ≠ suffix_O。 両方が成立する場合、このカットは有効であり、すぐに戻すことができます。 
6. 両方の条件を満たすポジションがない場合は、-1 を出力します。 

### なぜ効果があるのか

 位置 k ごとに、文字列は 2 つの固定マルチセットに分割されます。 この条件は純粋に、これら 2 つのマルチセット間のカウントの比較です。 プレフィックスとサフィックスのカウントは常にグローバル合計に合計されるため、プレフィックスが判明すると、サフィックスは完全に決定されます。 したがって、各 k を個別にチェックすることで、考えられるすべての有効なパーティションがカバーされ、問題では任意の答えが許容されるため、最初の有効なパーティションを返すだけで十分です。

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    total_L = s.count('L')
    total_O = n - total_L

    pref_L = 0
    pref_O = 0

    for i in range(n - 1):
        if s[i] == 'L':
            pref_L += 1
        else:
            pref_O += 1

        suff_L = total_L - pref_L
        suff_O = total_O - pref_O

        if pref_L != suff_L and pref_O != suff_O:
            print(i + 1)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```この解決策は、文字列に対する 1 回のパスに依存します。 まず合計を事前計算して、サフィックス値が一定時間で導出されるようにします。 両側が空ではない必要があるため、ループは n - 1 で停止します。 重要な正確性の詳細は、両方の文字を同時に厳密に不等号チェックすることです。

 ## 特殊なケース

 重要なエッジ ケースは、すべてのプレフィックスが少なくとも 1 文字で等価性を保持する場合です。 「LOL」の場合、各カットを確認すると、分布は変化しても、2 つのキャラクターのうちの 1 つは常にサイド間で一致していることがわかります。 

もう 1 つの特殊なケースは、「LLLLOOO」のような均一な文字列です。 ここでも、両方の文字で同時に対称性が持続しない限り、アルゴリズムは有効な分割を正しく検出します。 プレフィックスとサフィックスの計算により、不均衡が即座に検出されることが保証され、すべての k をテストするため、有効な分割がスキップされることはありません。
