 ## 問題の理解

 私たちには基数のある番号体系が与えられています$b$、そして、係数で割り切れるかどうかを確認したいと思います。$n$数字に対するローカル操作のみを使用します。 ベースには数字が書かれています$b$、完全な値をその数字から構築された構造化式に置き換えることができます。 式は常にモジュロ値を保持する必要があります$n$、したがって、割り算のチェックは単純化された数字ベースの形式のチェックに帰着します。 

3 種類の構造が許可されており、いずれもサイズのブロックにグループ化された数字を処理します。$k$(ベースで解釈されます)$b$）。 

最初のタイプでは、最後のものを除くすべてを無視します。$k$数字。 これは、すべての上位桁の寄与が常に の倍数である場合にのみ機能します。$n$、価値観に関係なく。 

2 番目のタイプでは、数値を連続したブロックに分割します。$k$これらのブロックを数値化して合計します。 

3 番目のタイプでは、これらのブロック間で符号を交互に配置します。 

各ブロックはベースとして扱われます。$b$整数なのでシフト$k$桁は乗算に対応します$b^k$。 したがって、実際の制約は、$b^k$モジュロで適切に動作する$n$。 

入力は多くのペアで構成されます$(b, n)$。 各ペアについて、最小のものを見つけなければなりません$k$これらの構造の少なくとも 1 つがモジュロ値を正しく保存するようにする$n$。 存在しない場合は、ゼロを出力します。 

制約は以下を意味します$10^6$すべてのテストの合計なので、$O(\sqrt{n})$またはそれ以上のテストごとのアプローチが必要です。 因数分解や桁展開のシミュレーションに関わるものすべて$n$テストごとの処理は全体として遅すぎます。 

微妙な失敗例は、すべてのモジュールに対してブロック メソッドが常に存在すると仮定することから発生します。 例えば、$b = 10, n = 6$はよく知られた割り算ルールに似ていますが、許可される線形数字の構成がモジュロ 6 の制約と一致しないため、答えはゼロになります。 小さなチェックだけを行う単純なアプローチ$k$構造条件を理解していないと、一部のグループ化が機能すると誤って結論付ける可能性があります。 

## アプローチ

 中心的な観察は、3 つの構造すべてが数値を基数の多項式として表現することに対応しているということです。$b^k$。 数字をあるサイズのブロックにグループ化すると$k$、任意の数字になります$$x = x_0 + x_1 b^k + x_2 b^{2k} + \dots$$それぞれどこで$x_i$はブロック値です。 

各割り算ルールは、べき乗を置き換える方法です。$b^k$単純な定数を使用して$\mathbb{Z}_n$:

 種類 1 の場合、実質的に次のことが求められます。$b^k \equiv 0 \pmod n$。 これにより、より高いブロックが完全に消滅します。 

種類 2 の場合は、$b^k \equiv 1 \pmod n$、その場合、すべてのブロックが均等に寄与し、合計すると元の値を法的に維持するためです。$n$。 

種類 3 の場合は、$b^k \equiv -1 \pmod n$したがって、符号を交互に繰り返すと、連続するべき乗が正しくキャンセルされます。 

したがって、タスクは最小のものを見つけることになります。$k$そのような$b^k \equiv 0, 1,$または$-1 \pmod n$、それらの中から最小の有効なものを選択します。 

ブルートフォースアプローチはすべてを試みます$k$1 から、コンピューティング$b^k \bmod n$。 これは正しいですが、最悪の場合は遅すぎます。$k$まで上がるかもしれない$n$、それぞれの計算は$O(1)$、与える$O(n)$テストごとに。 

重要な洞察は、乗算順序のような動作を見つけるだけでよいということです。$b \bmod n$これは、0 に達するかサイクルするまで累乗を繰り返すことで実行できますが、$n$テスト全体で大きくなる可能性があるため、代わりに、反復するまで、または必要な剰余に到達するまで検出力を追跡します。これは常に範囲内で発生します。$O(n)$モジュラーダイナミクスによるすべてのテストの合計。 

より構造化されたビューは、乗法モノイドモジュロを歩いているということです。$n$、3 つの目標状態のいずれかに到達するとすぐに停止します。

 ## アルゴリズムのチュートリアル

 べき乗を反復します$b$モジュロ$n$ただし、最初から再計算するのではなく、$k$、現在のパワーを維持します$p = b^k \bmod n$。 

1.初期化$p = 1$。 これは、$b^0$、空のシフト。 
2. それぞれについて$k \ge 1$、 アップデート$p = (p \cdot b) \bmod n$。 これにより、$b^k \bmod n$。 
3. もし$p = 0$、これですぐに種類 1 を使用できます。$k$、すべての上位ブロックがモジュロで消えるため$n$。 
4. もし$p = 1$、これで種類 2 を使用できます$k$、ブロック シフトは寄与を正確に保持するためです。 
5. もし$p = n-1$(これは$-1 \bmod n$)、これで kind 3 を使用できます$k$、交互の符号はパワーを正しくキャンセルするためです。 
6. 最小単位で停止します$k$これらの条件のいずれかを引き起こします。 
7. 条件が見つからずに安全な上限に達した場合、ルールは存在しないと結論付けられます。 

停止条件が機能するのは、一度$p$サイクルに入ると、新しい残基にヒットすることはありません。そのため、これ以上続けても、より小さな有効な値を生成することはできません。$k$。 

### なぜ効果があるのか

 各グループ化ルールは、次の累乗で単純な ID を強制することに対応します。$b^k$モジュロ$n$。 Kind 1 は、すべてのより高いパワーを強制的に消滅させます。これはまさに$b^k \equiv 0$。 種類 2 では、シフトされたすべてのブロックが同じように寄与する必要があります。$b^k \equiv 1$。 Kind 3 では交互のキャンセルが必要です。$b^k \equiv -1$。 このアルゴリズムはべき乗を昇順に列挙するため、これらの代数恒等式のいずれかが初めて成立する場合、それは最小の有効なグループ サイズに対応する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        b, n = map(int, input().split())

        # special quick rejection
        # we search powers of b mod n
        p = 1

        # we will cap iterations at n steps; cycle must appear before that
        ans = 10**18

        for k in range(1, n + 1):
            p = (p * b) % n

            if p == 0:
                ans = k
                break
            if p == 1:
                ans = min(ans, k)
                break
            if p == n - 1:
                ans = min(ans, k)
                break

        if ans == 10**18:
            print(0)
        else:
            # decide kind
            p = 1
            for k in range(1, ans + 1):
                p = (p * b) % n
                if k == ans:
                    if p == 0:
                        print(1, ans)
                    elif p == 1:
                        print(2, ans)
                    else:
                        print(3, ans)

if __name__ == "__main__":
    solve()
```この実装では、次のパワーを直接追跡します。$b$モジュロ$n$。 最初のループは最小のものを検索します。$k$有効な残留物を生成します。 ループは検索中に型を明示的に保存しないため、2 番目のパスではどの条件がトリガーされたかを再構築します。 

唯一の微妙な点は、次のことを保証することです$n-1$は次のように正しく解釈されます$-1 \bmod n$、これは交互合計ルールに必要です。 もう 1 つの重要な詳細は、最小の有効な値が必要であるため、条件が満たされた場合は直ちに停止する必要があるということです。$k$。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$b \equiv 0 \pmod n$。 この状況では、最初の乗算ですでにゼロが生成されます。 例えば、$b = 6, n = 3$。 アルゴリズムセット$p = 6 \equiv 0$、 それで$k = 1$上位桁のブロックはすべて消えるため、種類 1 ではすぐに有効になります。 

もう一つのケースは次のような場合です。$b \equiv 1 \pmod n$。 それから$p$は常に 1 であるため、最初の反復ですでに種類 2 がトリガーされます。$k = 1$。 これは、すべての数字ブロックが位置に関係なく変化せずに寄与するという事実に対応します。 

3 番目のケースは、サイクルが 0、1、または -1 に達しない場合です。 例えば$b = 10, n = 6$。 べき乗は、必要な構造と決して整列しない残基を循環するため、有効な構造が見つからないままループが終了します。$k$、正しくゼロが生成されます。
