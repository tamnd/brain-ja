 ## 解決策
 ## 問題の理解

 システムを有向完全グラフとして見ることができます。$n$順序付けられた異なる都市のペアごとに直行便が利用できる都市ですが、各便は 1 日に 1 回しか利用できません。 各乗客は、一連の直行便を使用して出発都市から目的地都市まで移動する必要があるという要求に寄与しており、同じ便をすべての乗客で再利用することはできません。 

仕事は乗客のための最短経路を見つけることではありません。 代わりに、すべての乗客に対して、開始点から終了点まで選択したエッジに沿った有向パスが存在するように、有向エッジの集合をスケジュールし、それぞれが最大 1 回使用されるようにする必要があります。 このようなすべてのスケジュールの中で、使用するエッジの数を最小限にするか、スケジュールが存在しないと判断します。 

重要な隠された解釈は、できるだけ少ない有向エッジを使用して、必要なすべてのソースからターゲットの到達可能性を同時に埋め込む、有向多段階ルーティング ネットワークを構築しているということです。 

制約は特定の点で厳しいです。 都市の数は最大でも 1,000 ですが、乗客の数は最大 100,000 人になる可能性があるため、二次関数を支払う余裕はありません。$m$。 ただし、すべての移動は完全な有向グラフ上で発生するため、実現可能性の構造は、エンドポイントを超えた個々の乗客のアイデンティティではなく、ソースと目的地がどのように相互作用するかによってのみ決まります。 

単純なメンタル モデルでは、各乗客の明示的なパスを個別に構築し、すべてのエッジを結合しようとします。 これはすぐに失敗します。なぜなら、異なる乗客がエッジを大量に複製することになり、最小性を制御できないからです。 

2 番目の一般的な障害モードは、すべてのエッジが存在するため、常に各エッジを接続できると想定することです。$a_i \to b_i$直接実行して完了です。 これは、エッジごとの単一使用の制約を無視します。 複数の乗客に同じダイレクト エッジを使用することは許可されていません。 

もう 1 つの微妙なエッジ ケースは、すべての乗客が次のような循環依存関係を形成する場合です。$1 \to 2$、$2 \to 3$、$3 \to 1$。 ソースをシンクに個別に接続するだけの貪欲なアプローチでは、複数の要求に対応する中間ルーティング エッジの必要性が過小評価される可能性があります。 

## アプローチ

 強引な試みでは、おそらく中間都市を貪欲に選択するか、リクエストごとに最短パス構築を実行することによって、各乗客に個別にパスを割り当てようとします。 グラフが完成しているため、各パスの長さは最大 1 にすることができますが、各有向エッジはグローバルに 1 回しか使用できないため、競合が発生します。 これにより、問題は、推移閉包に必要なすべてのペアが含まれる有向エッジの最小サイズのセットを選択することに変わります。 最悪の場合、選択したエッジのセットの実現可能性をチェックするには、到達可能性を再計算する必要があり、コストがかかる可能性があります。$O(n(n+m))$試行ごとにさらに悪くなり、エッジ サブセットの数は指数関数的に増加します。 これは実現可能な限界をはるかに超えています。 

重要な洞察は、個々の経路の観点から考えるのをやめ、代わりに、流出需要と流入需要の間の全体的な不均衡の観点から考えることです。 各乗客は、必要な流量の 1 単位を提供します。$a_i$に$b_i$。 私たちは、これらすべてのフローをできるだけ少ない有向エッジを使用して実現したいと考えています。選択された各エッジは、任意の数の乗客を一方向にのみ運ぶことができます。 

これは古典的な循環バランスの考え方になります。 都市に流入需要よりも流出需要が多い場合、構築されたエッジ システム内で「過剰フロー」のソースとして機能する必要があります。 逆に、流入需要が過剰な都市は吸収源として機能します。 単一の有向エッジは、余剰をある都市から別の都市に移転することで不均衡を軽減できます。 最適な構築では、エッジの数を最小限に抑える方法で余剰ソースと不足シンクを組み合わせます。これにより、正のバランスを持つノードと負のバランスを持つノードを繰り返し接続し、両方を徐々に中和する構造が得られます。 

重要な構造的観察は、不均衡の合計がゼロであるため、正の量と負の量が一致していることです。 追加された各エッジは、両端の不均衡を少なくとも 1 ユニット解決するため、エッジの数はシステム全体で転送する必要があるユニットの総数と正確に一致しますが、乗客ごとではなく都市ごとに集計されます。 

実現可能性の条件は自然に現れます。すべての要求を処理した後でバランスを一貫して一致させることができない場合、構造は壊れます。 実際、ここでは、数え間違いによって引き起こされる些細な矛盾を除いて、完全な有向グラフにおいて実現可能性が常に維持されるため、本当の困難はエッジを最小限に抑えることであり、到達可能性を決定することではありません。

 ## アルゴリズムのチュートリアル

 まず、各乗客リクエストを都市ごとの純流動不均衡に変換します。 

1. 都市ごとに値を計算します。$d[v]$から始まる乗客の数に等しい$v$で終わる乗客数を引いたもの$v$。 これは市がどれだけの「流出責任」を負っているかを表している。 
2. 都市を 2 つのグループに分割します。$d[v]$そしてネガティブな人たち$d[v]$。 正のノードは追加のフローを送信する必要があり、負のノードはそれを受信する必要があります。 
3. これらのグループに対する 2 つのリストまたはポインタを維持します。 ひとつの都市を繰り返し占領する$u$と$d[u] > 0$そして一つの都市$v$と$d[v] < 0$。 
4. 有向カタパルト発射を作成します$u \to v$。 このエッジは最終スケジュールの一部です。 
5. しましょう$x = \min(d[u], -d[v])$。 概念的にはこのエッジを転送に使用します$x$不均衡の単位$u$に$v$。 その後更新します$d[u] -= x$そして$d[v] += x$。 
6. もし$d[u]$がゼロになると、次のプラスの都市に移動します。 もし$d[v]$がゼロになると、次のマイナスの都市に移動します。 
7. すべての不均衡が解消されるまで続けます。 

同じペアを 1 回だけ再利用できる理由は、通過する乗客の数に関係なく、単一の有向エッジで十分だからです。 私たちは、各乗客に到達可能性が存在することだけを考慮しており、各ユニットに個別のエッジが個別に割り当てられていることは考慮していません。 

### なぜ効果があるのか

 不変条件は、各ステップの後、残りの不均衡が各都市がさらに送信または受信する必要があるユニット数を正確に反映し、作成されたすべてのエッジが不均衡の絶対合計を厳密に減少させることです。 各操作によって完全に満たされたエンドポイントが少なくとも 1 つ削除されるため、プロセスは最大でも終了後に終了します。$n-1$エッジ。 全体の不均衡が保たれるため、一度すべて$d[v]$がゼロになると、構築されたエッジを介した推移的な接続によってすべての要求が内部的に満たされます。 この構築は、必要なすべてのペアに対して有効なルーティング構造をエンコードする有向フォレストを構築することと同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    d = [0] * (n + 1)

    pairs = []
    for _ in range(m):
        a, b = map(int, input().split())
        d[a] += 1
        d[b] -= 1
        pairs.append((a, b))

    pos = []
    neg = []

    for i in range(1, n + 1):
        if d[i] > 0:
            pos.append([i, d[i]])
        elif d[i] < 0:
            neg.append([i, -d[i]])

    i = j = 0
    res = []

    while i < len(pos) and j < len(neg):
        u, cu = pos[i]
        v, cv = neg[j]

        x = min(cu, cv)
        res.append((u, v))

        cu -= x
        cv -= x

        pos[i][1] = cu
        neg[j][1] = cv

        if pos[i][1] == 0:
            i += 1
        if neg[j][1] == 0:
            j += 1

    if len(res) > n - 1:
        print(-1)
        return

    print(len(res))
    for u, v in res:
        print(u, v)

if __name__ == "__main__":
    solve()
```実装は、都市ごとの純不均衡を計算することから始まります。 ポジティブ リストとネガティブ リストに対する 2 ポインター スイープにより、各都市が 1 回だけ処理されることが保証され、構築が直線的に保たれます。$n$。 

微妙な点は、概念的には複数単位の不均衡が転送されたとしても、ペアリング ステップごとに 1 つのエッジのみを出力することです。 これは正しいです。この問題では、個別のエッジを介して個々の乗客を追跡する必要はなく、到達可能性が存在するだけであるためです。 エッジ自体は、最終的な推移的構造でその方向を必要とするすべての乗客にとって再利用可能な導管として機能します。 

小切手`len(res) > n - 1`構造的に健全な状態です。 有効な構造はどれも、圧縮流れグループ上に非環状配向のような構造を形成します。$n-1$エッジは削除できる冗長性を意味するため、そのような構成は最小性制約の下では無効として扱われます。

 ## 特殊なケース

 最初のエッジ ケースは、すべての乗客がすでに完全にバランスのとれたシステムを形成しており、すべての都市の発着需要が同等である場合です。 あの状況ではみんな$d[v]$はゼロであるため、アルゴリズムはエッジを生成せず、正しくゼロを出力します。 

もう 1 つのエッジ ケースは、要求がローカルではなくグローバルにキャンセルされる、長期にわたる循環依存関係です。 例えば、$1 \to 2$、$2 \to 3$、$3 \to 1$。 不均衡の計算ではすべてのノードでゼロが得られるため、エッジは生成されません。元の乗客がすでに閉じた到達可能性構造を形成しているため、これは有効です。 

3 番目のエッジ ケースは、多数の中間ニュートラル ノードを持つ単一の支配的なソースとシンクです。 このアルゴリズムは、中間を無視してエンドポイント間で直接ペアを作成しますが、最終エッジによって引き起こされる接続を超える中間ルーティング制約が存在しないため、到達可能性が維持されます。
