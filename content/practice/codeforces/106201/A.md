 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$グリッドであり、このグリッドの境界にある単一の開始セルを選択できます。 選択したセルから、グリッド上の幅優先拡張とまったく同じように、毎秒 4 つの隣接するセルすべてに広がるプロセスが開始されます。 単位コストで移動できるのは 4 方向のみであるため、任意のセルに到達するのに必要な時間は、選択した開始セルからのマンハッタン スタイルのグリッド距離とまったく同じになります。 

タスクは、グリッド内の任意のセルまでの最大距離が最小になるように境界セルを選択することです。 言い換えれば、4 方向の移動下で最も遠いセルの距離を最小限に抑えるために、境界上のソースを選択していることになります。 

出力は、単に最適な境界セルの座標です。 

制約により許可されるのは、$n, m \le 10^{18}$これにより、シミュレーションやグリッドのトラバースが即座に除外されます。 いずれの次元でも線形時間ですら不可能であるため、いかなる解も定数時間でなければなりません。 

素朴なアプローチは、境界セルの候補を選択し、すべてのセルまでの最大距離を計算することですが、これにはすでにグリッドをスキャンする必要があります。 これは実行不可能であり、さらに悪いことに、すべての境界セルに対してこれを実行すると、コストが 2 倍になります。$O(n + m)$、それはまだ不可能です。 

次の場合、微妙なエッジケースが発生します。$n = 1$または$m = 1$。 このような縮退したグリッドでは、すべてのセルが境界上にあり、距離構造は単純な線に崩壊します。 もう 1 つのエッジ ケースは、グリッドが対称である場合です。$n = m$、複数の最適な答えが存在し、そのいずれかが有効です。 

## アプローチ

 重要な観察は、拡散プロセスが、境界上で正確に 1 つのソースを選択する、複数のソースの距離の問題のように動作することです。 境界開始点から最も遠いセルは常に、その開始エッジに関してグリッド内で「最も深い」セルです。 

開始セルを上の行に固定すると、最悪の場合の距離は下の行によって支配されます。 同様に、下の行から開始すると、上の行がボトルネックになります。 同じ対称性が水平方向にも当てはまります。 

したがって、最適な戦略は、最も遠いエッジまでの垂直距離と水平距離の最大値を最小化する境界セルを選択することです。 直観的には、境界に沿ってできるだけ中央から開始したいと考えますが、周囲にとどまるように制約されます。 

これにより、最も遠い側への距離を最小限に抑えるという問題が軽減されます。 上の行または下の行から開始する場合、制限距離は垂直の高さから 1 を引いたものになります。左または右の列から開始する場合、制限距離は水平の幅から 1 を引いたものになります。最悪のケースを最小限に抑えるために、次のように比較します。$n$そして$m$最大リーチが小さい側を選択します。 

もし$n \le m$の場合、垂直方向の奥行きが小さいか等しいため、行境界の中央の列にあるセルを選択することをお勧めします。 もし$m < n$では、列境界の中央行にあるセルを選択します。 

より具体的には、最適点は常に長い次元の軸の中心にあり、短い次元の境界上に留まります。

 ## アルゴリズムのチュートリアル

 どの境界セルがグリッド内の任意のセルまでの最大距離を最小にするかを推論します。 

1. 比較する$n$そして$m$。 これにより、垂直または水平のどちらの広がりが最悪の場合の距離を支配するかが決まります。 
2. もし$n \le m$、水平方向の極端な値を最小限に抑えることを優先します。 開始セルを上部または下部の境界に配置し、できるだけ中心に近い列を選択します。 最高のコラムは、$j = \lceil m/2 \rceil$左端と右端までの最大距離が最小化されるためです。 
3. ケースの場合$n \le m$、どちらかの行を選択できます$i = 1$または$i = n$、両方とも対称であるためです。 私たちが選ぶ$i = 1$具体性のために。 
4. もし$m < n$代わりに、垂直方向の極端な値を最小限に抑えることを優先します。 開始セルを左または右の境界に配置し、できるだけ中央に近い行を選択します。 最高の列は$i = \lceil n/2 \rceil$。 
5. この場合、次のように修正します。$j = 1$、左または右の境界が対称であるためです。 
6. 選択した座標を出力します。 

### なぜ効果があるのか

 最も遠いセルまでのグリッド距離は、開始点が反対側の境界からどれだけ離れているかによってのみ決まります。 長い寸法の中心から離れた内部オフセットがあると、もう一方の側を補償するのに十分な改善が得られずに、一方の側までの最大距離が厳密に増加します。 開始点は境界上になければならないため、「固定」していない次元に沿って中心を置くことによって最適なトレードオフが達成されます。 これにより、すべての境界の選択肢の中で最も遠い隅までの最大距離が確実に最小化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

if n <= m:
    i = 1
    j = (m + 1) // 2
else:
    i = (n + 1) // 2
    j = 1

print(i, j)
```この実装は、相対的なサイズのみが考慮されるという観察に直接従います。$n$そして$m$案件。 行が少ないか等しい場合、境界行を固定し、列を中央に配置します。 列が少ない場合は、境界列を固定して行を中央に配置します。 

表現$(m + 1) // 2$奇数と偶数の両方の幅を適切に処理して中央の列を正しく計算し、どちらかの側への最大偏差を最小限に抑えます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

 ## 特殊なケース

 いつ$n = 1$、グリッドは事実上線です。 すべてのセルは境界上にありますが、選択した開始点から最も遠いセルが常に終了点になります。 アルゴリズムが選択するのは、$i = 1$列が中央に配置され、線の両端までの最大距離が正しく最小化されます。 

いつ$m = 1$、状況は対称的です。 アルゴリズムが選択する$j = 1$行を中央に配置して、上部と下部の端点までの距離が均等になるようにします。 

いつ$n = m$、どちらの分岐も有効な選択肢です。 このアルゴリズムは一貫して最上部の行と中央の列を選択します。これは、境界を中心とした選択の最大距離が同じであるため、最適です。
