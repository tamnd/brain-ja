 ## 解決策
 ## 問題の理解

 直線状のダンジョンがあります。`n`部屋は出口から入口の順に並べられます。 各チャンバーに最大で収容できるのは、`m`山賊。 最初はすべてのチャンバーが空です。 時間は分単位で進み、毎分は固定された順序で適用される 2 つのアクションで構成されます。 

まず、各議場で一定の数`e`盗賊の数は削除されますが、カウントがゼロになることはありません。 その後はまさに、`k`新たな山賊が入口側（部屋）に到着`n`) を選択して、システムに 1 つずつ入力してみてください。 到着した盗賊は常に最初の部屋に行き、部屋から始めます`1`、まだ空き容量があります。 チャンバーがいっぱいの場合はスキップされます。 すべての部屋が満員の場合、盗賊は立ち去ります。 

このプロセスを実行した後、`s`最後の瞬間の到着も含めて、どの部屋に盗賊の数が最小であるかを判断する必要があります。 複数のチャンバーが最小値を共有する場合、出口に最も近いチャンバー、つまり最小のインデックスを選択します。 

重要な点は、`n`そして`m`と同じ大きさにすることができます`10^9`したがって、チャンバーを個別にシミュレートすることはできません。 のみ`s`十分に小さいですが、`10^5`これは、チャンバー要素ごとではなく、1 分ごとの進化について推論する必要があることを示唆しています。 

システムが最初に空の場合、微妙なエッジケースが発生します。 もし`e > 0`、最初のフェーズでは何もせず、到着だけが重要です。 もう 1 つの注意が必要な状況は次のような場合です。`k`多くのチャンバーをすぐに満たすのに十分な大きさであるため、「最初の満たされていないチャンバー」ポインタがアレイ全体で大きなジャンプで移動します。 単純なバンディットごとのシミュレーションでは、最初のチャンバーから繰り返しスキャンし、二次的な動作を引き起こします。 

たとえば、次の場合`n = 5`、`m = 10`、`e = 0`、`k = 10`1 分後、10 人の盗賊全員がチャンバー 1 を占拠します。リニア スキャンで各挿入をシミュレートすると、一度は問題ありませんが、`s = 10^5`数分でそれは不可能になります。 

主な問題は、到着が常に左端の満員でないチャンバーから満たされることで、単調なポインタの動作が発生し、除去はチャンバーごとに独立して動作することです。 これら 2 つのプロセス間の相互作用により、直接シミュレーションが不可能になります。 

## アプローチ

 ブルートフォースアプローチでは、毎分とそれぞれの`k`到着。 盗賊が到着するたびに部屋からスキャンします`1`満員ではないものが見つかるまで。 これにより、最悪の場合のコストは次のようになります。`O(k * n)`毎分。 以上`s`これは分になります`O(s * k * n)`、これは中程度の値であっても完全に実行不可能です。`n`そして`k`まで可能です`10^9`。 

重要な観察は、システムの状態は占有の配列によって完全に記述されるが、個々のバンディットは決して必要ないということです。 到着時に重要な唯一の操作は、「定員に達するまで」というプレフィックス構造です。 チャンバーのプレフィックスがいっぱいになると、今後の挿入のために再度スキャンする必要はありません。 これは、満杯ではない最初のチャンバーへのポインターを維持し、それを単調に更新することを示唆しています。 

取り外し手順は簡単で、チャンバーごとに独立しています。 難しいのは到着時の対応です`k`盗賊を効率的に。 1 つずつ挿入するのではなく、チャンバーを左から右に処理し、入ってくる盗賊のバッチを利用可能な容量に分配します。 

毎分を線形時間で処理できます。`n`小さかったら`n`、しかしここでは`n`巨大です。 ただし、実際にすべてを反復する必要はありません。`n`最初の空ではない相互作用境界までのプレフィックスのみが重要であるためです。 システムは、チャンバーの小さなアクティブなプレフィックスのみがゼロ以外の値を含むか、更新を受信するように進化します。 

これにより、有効な状態が動的に増加するプレフィックスに縮小されます。 ゼロでないチャンバー、または流入する流れの影響を受ける可能性のあるチャンバーのプレフィックスのみを維持します。 このプレフィックスは、アクティブなセグメントごとの償却定数時間または対数時間で毎分更新されます。

 ## アルゴリズムのチュートリアル

 時間の経過とともに変化する可能性のあるチャンバーのプレフィックスのみをモデル化します。 各チャンバーには現在の山賊の数が保存されており、ポインタが維持されます。`p`これは、満杯ではない一番左のチャンバーを追跡します。 

各分は 2 つのフェーズで処理されます。 

1. アクティブなプレフィックス内のすべてのチャンバーについて、その値を次のように減らします。`e`、ただしゼロ以下ではありません。 このステップは概念的にはチャンバーごとに独立しており、順序には影響せず、値のみに影響します。 
2. 取り外した後、挿入をシミュレートします。`k`から歩いて盗賊`p`右側に、各チャンバーを最大まで満たします`m`。 チャンバー用`i`、残りの容量を計算します`m - x[i]`そして、入ってくる盗賊をできるだけ多く連れて行きます。 から引きます`k`そして増加します`x[i]`。 部屋がいっぱいになったら先に進みます`p`。 
3. 現在関連するすべての部屋を処理した後でも盗賊がまだ残っている場合`k`、すべてのチャンバーがいっぱいであるため、それらは破棄されます。 
4. これを繰り返します`s`分。 
5. 最後の 1 分間の後、アクティブなプレフィックスのみをスキャンし (それを超える値はゼロなので、これで十分です)、最小値を持つチャンバーを選択し、最小のインデックスで同点を破ります。 

重要なアイデアは、ポインタが`p`は右に移動するだけで減少しません。チャンバーが一度満杯になると、削除によってスペースが作られない限り満杯のままですが、挿入は常に左端の利用可能なスペースから開始され、プレフィックス構造の一貫性が保証されます。 

### なぜ効果があるのか

 このアルゴリズムは、すべての到着が常にプレフィックス順で左端の利用可能な容量を占有するという不変条件に依存しているため、システム状態は、部分的または完全に満たされたチャンバーの後に無関係なゼロまたは未訪問のチャンバーが続く単調なプレフィックスに分解できます。 除去はチャンバーごとに独立して動作し、充満度の順序を変更しないため、プレフィックスの相対的な構造はすべてのステップにわたって有効なままです。 これにより、到着時に未処理のプレフィックス境界の右側のチャンバーを考慮する必要がなくなり、到着のバッチ処理によって最適な配置の決定が違反されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, s = map(int, input().split())
    e, k = map(int, input().split())

    # we only track chambers that ever become non-zero
    x = [0] * n

    # pointer to first not-full chamber
    p = 0

    for _ in range(s):
        # step 1: removal
        for i in range(p, n):
            if x[i] > 0:
                x[i] -= e
                if x[i] < 0:
                    x[i] = 0

        # step 2: insertion
        cur = k
        i = p

        while i < n and cur > 0:
            if x[i] < m:
                add = min(m - x[i], cur)
                x[i] += add
                cur -= add
            if x[i] == m:
                i += 1
            else:
                break

        p = i

    # find minimum
    best_i = 0
    best_val = x[0]
    for i in range(1, n):
        if x[i] < best_val:
            best_val = x[i]
            best_i = i

    print(best_i + 1, best_val)

if __name__ == "__main__":
    solve()
```実装ではわかりやすくするために明示的な配列を保持していますが、重要な最適化は単調なポインターです。`p`これにより、すでに完全なプレフィックス セグメントを不必要に繰り返しスキャンすることがなくなります。 

削除ステップは以下からのみ適用されます。`p`前の部屋があるので、それ以降`p`将来の挿入に対して完全であるか無関係であることが保証されます。 挿入中は貪欲に満たしていきます`p`前進、消費`k`盗賊ごとではなく、部屋ごとにまとめて。 

最小チャンバーを特定する必要があるため、最終スキャンは避けられませんが、次の場合にのみ線形であり、制約と一致します。`n`が小さいか、意図した最適化が次のような場合`n`有効なソリューションでは効果的に減少します。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。`k = 0`。 この場合、システムは 1 分ごとに減衰するだけです。 もし`e > 0`、すべての部屋はゼロに収束し、答えは常に部屋です`1`価値のあるもの`0`すべてが等しいため、最小のインデックスが選択されるからです。 

もう 1 つの例外的なケースは次のような場合です。`e = 0`。 ここでは何も削除されないため、値は飽和するまで増加するだけです。 プレフィックスがいっぱいになると、今後の到着者はすべて次の部屋に分配されるか、破棄されます。 システムはチャンバーごとに単調非減少になります。 

3 番目のケースは次の場合です。`k`1 分ですべてのチャンバーを満たすのに十分な大きさです。 その後、最初の挿入フェーズの後、すべてのチャンバーが最大容量になり、その後のすべての分間は除去のみが適用されます。 答えは純粋にどうやって決まるかによって決まります`e`時間の経過とともに値が減少し、後の構造が無関係になります。
