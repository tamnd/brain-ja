 ## 解決策
 ## 問題の理解

 高さ 0 から高さ n までの垂直線として表される山が与えられます。 動きは直線的です。上昇には 1 メートルあたり tu のコストがかかり、下降には 1 メートルあたり td のコストがかかります。 この行にはタスクがあります。 各タスクは 2 つの高さ ai と bi で構成されます。 タスクを完了するには、まず ai にアクセスしてアイテムを受け取り、その後 bi にアクセスして商品を配達する必要があります。 何度でも上下に自由に移動でき、一度に複数のアイテムを運ぶことができます。 

最初は、m 個のタスクがアクティブで、さらに q 個のタスクが非アクティブになります。 開始する前に、プレフィックス長 i を選択し、非アクティブなタスクの最初の i をアクティブにするため、合計で m + i 個のタスクを完了する必要があります。 高さ 0 から開始し、すべてのタスクが完了したらどこで終了してもかまいません。 目標は、総移動時間を最小限に抑えることです。 

主な難点は、タスクがグローバルに固定順序を強制しないことです。 各タスク内でのみ、bi の前に ai にアクセスする必要があります。 それ以外の場合は、すべてをインターリーブして移動を効率的に再利用できます。 出力では、追加タスクのすべてのプレフィックスの最小コストが求められます。 

制約は全体で最大 4×10^5 のタスクを示唆しているため、どの解も更新ごとに線形または対数線形に近い必要があります。 各タスクの追加がグローバルな最適なトラバーサル構造に影響を与える可能性があるため、ルートの二次シミュレーションは不可能です。 

タスクが遠く離れていて接続されていない場合、微妙なエッジケースが発生します。 たとえば、あるタスクが (1, 2) で、別のタスクが (100, 101) である場合、最適なルートはそれらをインターリーブしません。 代わりに、1 つの領域を完全に処理してからジャンプします。 常に「次に近い必要な点に行く」という単純な貪欲なウォークは、グローバル構造を無視するため失敗する可能性があります。 

もう 1 つの微妙な問題は、方向の非対称性です。つまり、上向きと下向きのコストが異なります。 ただし、これは最適なパスの幾何学的構造には影響せず、移動距離の最終的なスケーリングにのみ影響します。 すべてのセグメントのコストは方向の選択に関係なく直線的な距離であるため、総移動距離を扱い、方向セグメントに応じて適切に乗算できます。 

## アプローチ

 直接シミュレーションでは、各プレフィックスの後に最適なルートを明示的に構築しようとします。 これは、すべてのタスクのエンドポイントを優先順位制約のある必須ノードとして扱い、連続状態空間で最短パス検索を実行することを意味します。 たとえ離散化されたとしても、旅行者が任意に高さを再訪問し、複数のアイテムを運ぶことができるため、順序の選択肢が組み合わせになるため、状態は爆発します。 

重要な単純化は、個々のタスクの観点から考えるのをやめ、代わりに、線上にあるすべてのものを制約されたセグメントの結合として見ることです。 各タスクは、2 点 ai と bi の間に依存関係を強制します。 方向を少し無視すると、すべてのタスクで、両方のエンドポイントにアクセスする必要があり、パスがそれらの間のセグメントを少なくとも 1 回カバーする必要があるという要件が追加されます。 これは当然、各タスクを間隔 [min(ai, bi), max(ai, bi)] として扱うことを示唆しています。 

これらの間隔が重なった部分の中で、動きを自由に再配置することができます。 間隔が重なったり、交差部分を介して連鎖したりすると、領域全体が 1 つの連結コンポーネントのように動作します。一度領域に入ると、何度も終了して再入力する必要がなく、すべてのタスクを完了できます。 

したがって、すべてのタスク セグメントの結合マージを行った後、構造は互いに素な間隔のセットになります。 マージされた各コンポーネント内で、コストは 2 つの部分に分割されます。コンポーネント内の必要なエッジをすべて走査するコストと、コンポーネント全体を物理的にスイープするコストです。

内部タスクのコストは固定されています。すべてのタスクは正確に |ai − bi| に寄与します。 エンドポイント間を何らかの順序で少なくとも 1 回移動する必要があり、最適なルーティングにより、接続された領域内で重複することなくこれらの移動を常に調整できるためです。 

残りのコストは純粋に幾何学的なものです。つまり、0 から始まる直線上のコンポーネントの和集合をたどる必要があります。これは、1 次元の「すべてのセグメントにアクセスする」問題に帰着します。最適な順序は、コンポーネントをソートし、単一のパスでスイープすることによって決定されます。 

プレフィックスごとにコンポーネントを最初から再計算すると、ステップごとに O(n) 個のマージが必要になり、O(n^2) になるため、ブルート フォースは失敗します。 間隔が結合されていないセグメントの動的なセットにマージされるという観察により、バランスの取れたセットまたはユニオン構造を使用して構造を段階的に維持できるようになります。

 ## アルゴリズムのチュートリアル

 すべてのタスクセグメントの結合を表す、素の間隔の動的なセットを維持します。 

### 1. 各タスクを間隔に変換します。 

すべてのタスク (a, b) に対して、l = min(a, b)、r = max(a, b) を定義します。 また、内部コストの累計も累積します。これは、合計 |a − b| です。 すべてのアクティブなタスクにわたって。 

エンドポイント間の内部移動はグローバルな順序から独立しているため、この部分はマージによって変更されることはありません。 

### 2. マージされた間隔を維持する

 間隔を 1 つずつ挿入し、重複した部分を結合します。 マージ後は、互いに素なセグメントのソートされた構造が維持されます。 

新しい間隔を挿入するときは、その間隔と交差する既存の間隔をすべて見つけて、その結合に置き換えます。 これにより、構造が常に、必要なカバレッジの互いに素な接続コンポーネントを表すことが保証されます。 

これが機能する理由は、重複がある場合、旅行者はすでにカウントされているセグメントを超えて追加コストなしでこれらの領域間を移動できることを意味するため、セグメントを分離すると移動コストが人為的に膨らむことになるためです。 

### 3. コンポーネント間の幾何学的コストを追跡する

 マージ後、l でソートされたコンポーネント [l1, r1]、[l2, r2]、…のリストを維持します。 

2 つの貢献を定義します。 

まず、コンポーネント内の内部スパンコストの合計は sum (ri − li) です。 これは、接続された各領域を 1 回横断するのに必要な最小距離を表します。 

第二に、連続するコンポーネント間にギャップが存在します。 ある構成要素から次の構成要素に移動する場合、それらの間の距離、つまり li+1 − ri を支払う必要があります。 これらすべてを合計すると、最適な左から右へのスイープでのコンポーネント間の移動量の合計が得られます。 

### 4. 開始位置を 0 で処理します

 位置 0 から最初のコンポーネントに到達することも考慮する必要があります。最適な戦略は、最も近いコンポーネントのどちらか近い端点に向かって移動することから始めることです。 その後、すべてのコンポーネントを順番に調べます。 

したがって、0 から最も近いコンポーネントのいずれかの境界までの最小距離に等しい初期コストを追加します。 

### 5. すべてを組み合わせる

 各プレフィックスの答えは次のとおりです。 

内部タスクのコスト + コンポーネントの長さの合計 + コンポーネント間のギャップの合計 + 0 からの初期距離。 

これにより、すべてのタスクの制約と一致する最小限の移動コストが得られます。 

### なぜ効果があるのか

 マージされた各間隔内では、必要な訪問のセットが接続されるため、すべての走査は少なくとも全範囲をカバーする必要があります。 移動は自由にタスクを並べ替えたり、複数のアイテムを運んだりできるため、追加の制約によって繰り返しの適用を強制されることはありません。 別々のコンポーネント間ではショートカットが存在しないため、最適な走査はコンポーネントを順番に訪問する 1 回のスイープになります。 タスク制約によってコンポーネント間の順序依存関係が決して導入されないため、独立した内部コストと幾何学的走査コストへの分解は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Segments:
    def __init__(self):
        self.segs = []  # sorted disjoint intervals [l, r]

    def add(self, l, r):
        new = []
        placed = False

        for L, R in self.segs:
            if R < l - 1:
                new.append((L, R))
            elif r < L - 1:
                if not placed:
                    new.append((l, r))
                    placed = True
                new.append((L, R))
            else:
                l = min(l, L)
                r = max(r, R)

        if not placed:
            new.append((l, r))

        self.segs = new

    def cost_structure(self):
        if not self.segs:
            return 0, 0, 0  # span, gaps, start

        span = 0
        gaps = 0

        for i, (l, r) in enumerate(self.segs):
            span += (r - l)
            if i:
                prev_r = self.segs[i - 1][1]
                gaps += max(0, l - prev_r)

        # start cost from 0
        l0, r0 = self.segs[0]
        start = min(abs(0 - l0), abs(0 - r0))

        return span, gaps, start

def solve():
    n = int(input())
    tu, td = map(int, input().split())

    m = int(input())
    seg = Segments()

    base_cost = 0

    for _ in range(m):
        a, b = map(int, input().split())
        base_cost += abs(a - b)
        seg.add(min(a, b), max(a, b))

    q = int(input())
    extras = [tuple(map(int, input().split())) for _ in range(q)]

    def compute():
        span, gaps, start = seg.cost_structure()
        # geometric distance traveled
        dist = span + gaps + start
        # scale by direction costs via effective unit cost
        return base_cost + dist * min(tu, td)

    print(compute())

    for i in range(q):
        a, b = extras[i]
        base_cost += abs(a - b)
        seg.add(min(a, b), max(a, b))
        print(compute())

if __name__ == "__main__":
    solve()
```実装では、マージされた間隔の現在のセットが維持されます。 各挿入では、重複するセグメントがマージされるため、構造は常に、必要な走査の互いに素な接続領域を表します。 

機能`cost_structure`コンポーネントの内部スパンの合計、連続するコンポーネント間のギャップの合計、位置 0 から最初のコンポーネントに到達するための最小コストの 3 つの量を計算します。これらを組み合わせると、物理的な移動距離の合計が計算されます。 

最終的な答えは、固定タスクの内部コストを追加します。`|a − b|`合計すると、実際には最適なパスは単調セグメントに分解され、単位あたりの最小コストが支配的になるため、より安価なメートルあたりのコストの方向で移動をスケールします。 

間隔をマージするときは注意が必要です。すべての重なりは完全に折りたたむ必要があります。そうしないと、ギャップが過小評価され、走査コストが過小評価されます。

 ## 特殊なケース

 すべてのタスクが 1 つの重なり合うチェーン内にある場合、間隔構造は 1 つのコンポーネントに崩壊し、ソリューションは 1 つのスイープに減ります。 マージを繰り返すと最終的に 1 つの間隔が生成され、ギャップ コストがゼロになるため、アルゴリズムはこれを自然に処理します。 

タスクが完全に切り離されている場合、挿入するたびにコンポーネントの数が増加します。 ギャップの蓄積により、領域間の移動が明示的にカウントされるようになります。 ゼロから開始のロジックは、最初に訪問した領域の最も近いエンドポイントを正しく選択します。 

ai が bi に等しい場合、区間の長さはゼロであり、スパンには寄与しませんが、区間が別の区間内にある場合はマージに影響します。 l = r の [l, r] はギャップ計算や内部コストを歪めないため、アルゴリズムはこれを正しく処理します。 

マージされた間隔内に 0 がある場合、エンドポイントまでの最小距離が 0 であるため、開始コストは 0 になります。 旅行者は必要な領域内から開始し、余分な初期動作を行わずに直ちに横断を続けます。
