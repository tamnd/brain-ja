 ## 解決策
 ## 問題の理解

 ここでは、毎日の支出を食費、備品、居酒屋での支出に分けて表す、同じ長さの 3 つの配列を扱います。 元のデータでは、毎日の合計支出額は 3 つのカテゴリすべてで同じです。 

その後、各配列は独立して「圧縮」されます。値が 1 つの配列内の連続した位置で繰り返されるたびに、それらの繰り返されたブロックは 1 つの値に折りたたまれます。 重要なのは、この圧縮は 3 つの配列のそれぞれに個別に適用されるため、それらの実行境界が相互作用しないことです。 

最初の実行では、完全な元の配列が表示され、最大で k 個の整数のシーケンス S を出力できます。 2 回目の実行では、元の配列が表示されなくなります。 代わりに、S と圧縮された配列が与えられ、圧縮が指定されたものと一致し、インデックスごとの合計が一定である有効な元の配列を再構築する必要があります。 

最大の問題は、圧縮によってランレングス情報が破壊されてしまうことです。 たとえば、圧縮された配列 [5, 7, 7, 2] からは、元の配列が [5, 5, 7, 7, 7, 2, 2] なのか [5, 7, 7, 7, 2] なのかわかりません。 再構築では、各定数セグメントの長さを決定する必要があります。 

制約は非常に直接的な意味で重要です。 長さ n は最大 30000 であるため、再構成ごとに O(n log n) または O(n) であれば問題ありません。 重要な制限は、S のサイズで、最大 60000 まで可能です。これは、S が入力に関する線形情報を保存できることをすぐに示唆していますが、最悪の場合、位置ごとに一定数以下の値を保存することはできません。 3n は 90000 に達する可能性があるため、3 つの完全な配列すべてを個別にエンコードしようとするソリューションでは、k を超える危険があります。 

素朴な試みは、圧縮を無視して、圧縮された配列のみからすべてを再構築しようとすることです。 実行境界が失われるため、これはすぐに失敗します。 たとえば、a = [1,1,2,2] が a0 = [1,2] になる場合、分割が 2+2 か 3+1 かを判断する方法はありません。 

本当の問題は、最初のパスを使用して、圧縮によって破壊された欠落情報を正確に保存する必要があることです。 

## アプローチ

 強引な考え方では、元の配列をすべて S に保存します。これにより、2 回目の実行ではデータを単純に再生できるため、完全な再構築が保証されます。 問題はサイズの制約です。a、b、c を明示的に格納するには 3n 個の整数が必要で、最悪の場合 (n = 30000、k = 60000) には k を超える可能性があります。 したがって、完全なストレージが常に可能であるとは限りません。 

重要な観察は、3 番目の配列が独立していないことです。 ai + bi + ci はすべての i に対して定数であるため、任意の 2 つの配列が完全に分かれば、3 番目の配列は一意に決定されます。 これにより、保存する必要がある実際の情報が 3 つの配列から 2 つに減ります。 

圧縮は隣接構造にのみ影響するため、2 回目の実行で正確なシーケンスを再現できることも確認する必要があります。 これを行うきれいな方法は、2 つの配列の完全な実行拡張バージョンを S に直接格納することです。各配列の長さは n であるため、2 つの配列を格納するには 2n 個の整数が必要であり、これは最悪の場合 k = 60000 の制限 k 内に収まります。 

2 回目の実行で a と b を正確に再構成すると、定数和制約を使用して c インデックスごとに c を計算できます。指定された c0 により、再構成された c が出力要件と一致する有効な圧縮構造を持つことが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 圧縮された情報のみを保存する | O(n) | O(n) | ランレングスが欠落しているため失敗します。 
| 3 つの配列をすべて保存する | O(n) | O(3n) | 最悪の場合大きすぎる |
 | 2 つの完全な配列 (a と b) を格納します。 O(n) | O(2n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最初の実行 (エンコードフェーズ)

 1. 完全な配列 a と b を読み取ります。

これらには暗黙的にすべてのランレングス情報がすでに含まれているため、それらを直接保存します。 
2. a のすべての値とその後に b のすべての値を連結して S を構築します。 

これにより、両方の配列の単一の線形エンコーディングが得られます。 
3. 出力S。 

ここでの理由は、圧縮によって破壊されるのは値ではなく、隣接構造だけであるということです。 生のシーケンスを保存しているため、再構築に必要なものは何も失われません。 

### 2 回目の実行 (デコードフェーズ)

 1. S を読み取り、2 つの半分に分割します。 

最初の n 個の値は a、次の n 個の値は b です。 
2. 完全な配列 a と b を正確に再構築します。 
3. 各インデックス i について、恒等式を使用して c[i] を計算します。 

ci = T − ai − bi。 

定数 T は、最初の再構築中に有効な元のインデックスから取得できますが、実際には元の c を復元する必要はありません。 代わりに、任意のインデックス i を取得し、元のインスタンスが一貫性を保証しているという事実を利用して T を決定できます。 正確な元の a と b を再構築するため、同じ定数 T が存在し、元の​​システムが有効性を保証している任意のインデックスをスキャンすることで回復できます。 
4. この計算された式を使用して c を構築します。 
5. 出力された構築順序によって構造的に c0 との整合性を検証します。 元の入力が有効であったため、元の a と b を正確に再構築すると、結果の c が c0 と同一の有効な圧縮形式と一致することが保証されます。 

### なぜ効果があるのか

 不変条件は、S が隣接関係や値の情報を失うことなく、元のシーケンス a と b を完全に保存することです。 この問題では、最初の実行で有効なトリプル (a、b、c) が存在することが保証されており、a と b が固定されると c は定数和条件によって一意に決定されるため、a と b を再構成すると、元のシステム全体が正確に復元されます。 c の圧縮の一貫性は、同じ基礎となるシーケンスを再構築することで自動的に得られます。

 ## 特殊なケース

 重要なエッジ ケースは、配列が位置ごとに交互になる場合です (例: a = [1,2,1,2,...])。 圧縮によりこれが全長のシーケンスに縮小され、構造に関する最大の情報が失われます。 提案されたエンコーディングでは完全なシーケンスが保存されているため、再構成は正確です。 

もう 1 つのケースは、すべての値が同一である場合です (例: a = [7,7,7,7])。 圧縮すると、これが単一の要素に折りたたまれます。 元の配列全体を S に保存するため、再構築は圧縮された構造にまったく依存しないため、このケースは他のケースと同様に動作します。 

定数和制約は、a と b が固定されるとあいまいさを導入しないため、敵対的な場合でも c の再構成は決定的なままになります。
