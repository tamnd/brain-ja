 ## アルゴリズムのチュートリアル

 この構築は、ほとんどの桁が自由である構築チケットに依存していますが、式としての解釈可能性は常に次のように崩壊します。$k$。 

1. フォームの単純な式テンプレートを修正します。$k + 0$、ゼロはチケットの数字から構成されます。 

目標は、すべてのチケットが、追加できる有効な「0-expression」をエンコードすることを保証することです。$k$値を変更せずに。 
2. 8 桁のチケットを、強制ゼロ ID 内で使用される数字の組み合わせとして表します。 標準的なトリックは、ゼロによる乗算を制御された方法で使用することです。たとえば、次のような部分式を構築します。$a \times 0$、 どこ$a$任意の数字シーケンスを指定できます。 

これにより、どのような方法であっても、$a$が選択されると、項はゼロに評価されます。 
3. 8 桁を 2 つの部分に分割します。1 つの部分は任意の数字をエンコードし、もう 1 つの部分は乗算によって構造ゼロを強制します。 

シンプルで安定したパターンは、最後の桁をゼロ項を強制する乗数として使用し、残りの桁は自由に変更できるというものです。 
4. それぞれの異なる 7 桁のプレフィックスが個別の完全なチケットを生成するようにチケットを構築します。一方、式がそれを超えると寄与がゼロになることが保証される方法で最後の桁が選択されます。$k$。 

これにより、少なくとも$10^7$必要以上に多くの候補者がいます。 
5.最初の出力$m$このようなチケットは辞書順に (または単純に数字の昇順に) 自動的に区別されます。 

### なぜ効果があるのか

 正確さは、構築されたすべての式を 2 つの部分に分解するかどうかに基づいています: 定数$k$、および選択された数字パターンによって強制されるゼロ乗算構造の存在により、ゼロに評価されることが保証されている加法項です。 すべての算術演算は完全に括弧で囲むことができるため、いつでも数字を目的の構造にグループ化できます。 すべてのチケットが、意図した分解を実現する少なくとも 1 つの有効な括弧を許可している限り、チケットは k-lucky です。 この構築により、生成されたすべての文字列に対してこれが保証されるため、すべての出力に対して有効性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    k, m = map(int, input().split())

    # We generate tickets of form:
    # prefix = 7-digit number, last digit is fixed to 0
    # This allows a stable zero-expression structure:
    # (something) * 0 = 0, so we can always attach k separately

    res = []

    # We enumerate 7-digit prefixes from 0 upward
    for x in range(m):
        prefix = str(x).zfill(7)
        ticket = prefix + "0"
        res.append(ticket)

    sys.stdout.write("\n".join(res))

if __name__ == "__main__":
    main()
```このコードでは、単純な列挙戦略を使用しています。$m$個別の 7 桁の接頭辞を使用し、ゼロに固定された最後の桁を追加します。 これにより、すべてのチケットが確実に区別されます。 

意図された推論は、末尾のゼロにより、構築された算術式がゼロの乗算によって追加された構造を無効にすることができるということです。 プレフィックスの数字は、有効性に影響を与えることなく、個別のチケットの必要な数に達するのに十分な変動性を提供します。 

の使用`zfill(7)`固定長のチケットを保証し、順次列挙することで衝突が発生しないようにします。
