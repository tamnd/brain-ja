 ## 解決策
 ## 問題の理解

 平面内に候補点のセットが与えられており、3 つの同一円の中心として機能する候補点を 3 つ正確に選択する必要があります。 3 つの円はすべて同じ半径を持つ必要があり、接触することはできますが、内部で重なり合うことはできません。 半径は事前に固定されていません。 代わりに、選択した 3 つの中心に交差することなく円を配置できるようにしながら、円をできるだけ大きくしようとしています。 

3 つの中心を選択すると、半径は 3 つの点のうち最も近いペアによって制限されます。 半径が等しい 2 つの円は、中心間の距離が半径の 2 倍以上である場合にのみ重なりません。 したがって、選択されたトリプルの場合、制限要因は 3 つの点間のペアごとの最小距離になります。 そのトリプルの最適な半径は、最小距離の半分です。 

したがって、このタスクは、ペアごとの最小距離を最大化する 3 つの点を選択し、その値を 2 で割ることと同じです。 

入力サイズは3000ポイントまでです。 30003 は約 270 億回の演算に相当するため、トリプルを超える 3 次または 3 次に近い解はすでに境界線に達しています。 すべてのペアに対する二次スキャンでも問題ありませんが、ペアごとの情報から最適なトリプルを抽出する方法には注意する必要があります。 

複数の点が円上にある場合、または縮退に近い構成を形成している場合、微妙な問題が発生します。 たとえば、多くの点が 1 つの遠く離れた外れ値を除いて互いに非常に近い場合、全体的に最良のペアのみを考慮する単純なアプローチでは、3 番目の点が候補ペアを破棄することを見逃す可能性があります。 

典型的な失敗モードは、最も遠い点のペアを選択し、3 番目の点が機能すると仮定することです。 たとえば、2 つの点が非常に離れているが、3 番目の点がそのうちの 1 つに近い場合、半径は実際にはその 3 番目の点によって強制的に小さくなります。 したがって、ペアを個別に考えるのではなく、トリプルを一緒に考える必要があります。 

## アプローチ

 ブルートフォースソリューションでは、ポイントのトリプルごとに列挙されます。 各トリプルについて、3 つのペアごとの距離をすべて計算し、最小値を取得します。 これは正しいですがコストがかかります$O(n^3)$、これは大きすぎます$n = 3000$。 

重要な観察は、固定された点のペアの場合です。$A$そして$B$、3 番目の点が半径を制限できる唯一の方法は、それがより近くにある場合です。$AB$どちらかに$A$または$B$。 したがって、候補ペアを修正する場合、ペアまでの距離の最小値を最大化することを考慮するという意味で、両方の端点からできるだけ遠くにある 3 番目の点が必要になります。 

トリプルの幾何学で直接推論する代わりに、問題を逆転させます。 最適な答えに価値があると推測するとします。$R$。 次に、すべてのペアごとの距離が少なくとも以下であるトリプルが存在するかどうかを確認するだけで済みます。$2R$。 これはグラフに関する実現可能性の問題になります。距離が少なくとも次の点である点を接続します。$2R$そして、このグラフに三角形があるかどうかを知りたいのです。 

すべてのエッジ上で三角形を直接チェックすることは、単純に実行すると依然としてコストがかかります。 ただし、次の構造を使用できます。$n \le 3000$。 各ペアごとに$(i, j)$のすべての有効な近傍を事前計算できます。$i$、隣接セットを維持します。 次に各エッジについて$(i, j)$、共通の隣人が存在するかどうかを確認する必要があります$k$両方のエッジが存在するようにします。 ビットセットを使用すると、交差チェックが高速になります。 

これは自然に答えの二分探索につながります。すべてのペアごとの距離を並べ替えるか、半径を直接二分探索し、ビットセットの交差を使用して実現可能性をチェックします。 各チェックは約$O(n^2 / 64)$、これは許容範囲です。 

より直接的な視点により、明示的な二分探索が回避されます。 すべてのペアごとの距離を計算し、並べ替えて、暗黙的にしきい値を考慮しますが、二分探索の方が推論が簡単です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース (トリプル) |$O(n^3)$|$O(1)$| 遅すぎる |
 | 二分探索 + ビットセット トライアングル チェック |$O(n^2 \log n / 64)$|$O(n^2 / 64)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての点のペア間の二乗距離を事前計算します。 これにより、比較中の浮動小数点エラーが回避され、ほとんどのロジックで整数を扱うことができるようになります。 
2. すべての一意の距離を収集します (または、0 から最大距離までの二分探索境界を使用します)。 半径を大きくしても制約が厳しくなるだけなので、答えは半径に単調に依存します。 
3. 候補半径の場合$r$、それを閾値に変換します$d = (2r)^2$。 二乗距離が少なくとも次の点のペア間のエッジのみを許可します。$d$。 
4. エッジが「これら 2 つの点が同時に半径の中心として機能できる」ことを意味するグラフを暗黙的に構築します。$r$”。
 5. 各ノードについて$i$、その隣接関係をすべてのノードのビットセットとして保存します。 この表現により、隣接するセット間の交差チェックを高速に行うことができます。 
6. 有効なトリプルが存在するかどうかを確認するには、すべてのエッジを反復処理します。$(i, j)$。 接続されている場合は、次の隣接セットの交差を計算します。$i$そして$j$。 交点にビットが設定されている場合、3 番目の点$k$有効な三角形を形成するように存在します。 
7. 三角形が存在する場合、半径$r$実現可能です。 それ以外の場合はそうではありません。 これを二分探索の述語として使用します。 

### なぜ効果があるのか

 有効な解はすべて、ペアごとの距離がすべて次の値を超える 3 つの点によって定義されます。$2r$。 これはまさに、しきい値グラフの三角形です。 ビットセット交差ステップにより、互換性のある 2 つのエッジを個別に見つけるだけでなく、三角形を完成させる 3 番目の頂点である完全に共有された近傍も確実に見つけることができます。 すべてのトリプルはエッジ ペアとその共通の近隣を介して暗黙的にチェックされるため、有効な設定が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    dist2 = [[0] * n for _ in range(n)]
    max_d = 0

    for i in range(n):
        x1, y1 = pts[i]
        for j in range(i + 1, n):
            x2, y2 = pts[j]
            dx = x1 - x2
            dy = y1 - y2
            d = dx * dx + dy * dy
            dist2[i][j] = dist2[j][i] = d
            if d > max_d:
                max_d = d

    # bitset adjacency for threshold graph
    bit = [0] * n

    def check(threshold):
        nonlocal bit
        for i in range(n):
            bit[i] = 0

        for i in range(n):
            for j in range(n):
                if i != j and dist2[i][j] >= threshold:
                    bit[i] |= (1 << j)

        for i in range(n):
            for j in range(i + 1, n):
                if bit[i] & bit[j] & (1 << i | 1 << j):
                    continue
                if bit[i] & bit[j]:
                    return True
        return False

    # binary search on squared diameter
    lo, hi = 0, max_d

    for _ in range(60):
        mid = (lo + hi) // 2
        if check(mid):
            lo = mid
        else:
            hi = mid

    radius2 = lo / 4.0
    print((lo ** 0.5) / 2.0)

if __name__ == "__main__":
    solve()
```実装は、すべての幾何学的比較が距離比較に帰着し、実行可能性チェック中の浮動小数点の不安定性が二乗によって回避されるため、すべての二乗ペアワイズ距離を計算することから始まります。 

の`check`関数は、候補二乗距離のしきい値グラフを構築します。 隣接ビットマスクはノードごとに構築されます。 有効なトリプルの条件は、2 つのノードが存在することです。$i, j$両方とも第 3 のノードに接続されるようにする$k$、ビットマスクの交差によって検出されます。 

二分探索は二乗距離にわたって実行され、最終的な半径は、実現可能な最良の二乗しきい値の平方根の半分として導出されます。 

微妙な点の 1 つは、最大 3000 ノードに対してビット操作が正しい状態を維持できるようにすることです。 Python の整数は任意のビット長を処理できるため、これは安全ですが、実際のパフォーマンスは疎な交差に依存します。

import sys, io
import math

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import sqrt

    data = inp.strip().split()
    n = int(data[0])
    pts = [(int(data[i]), int(data[i+1])) for i in range(1, 2*n, 2)]

    dist2 = [[0]*n for _ in range(n)]
    max_d = 0
    for i in range(n):
        x1, y1 = pts[i]
        for j in range(n):
            x2, y2 = pts[j]
            dx, dy = x1-x2, y1-y2
            d = dx*dx + dy*dy
            dist2[i][j] = d
            max_d = max(max_d, d)

    def check(th):
        bit = [0]*n
        for i in range(n):
            for j in range(n):
                if dist2[i][j] >= th and i != j:
                    bit[i] |= 1 << j
        for i in range(n):
            for j in range(i+1, n):
                if bit[i] & bit[j]:
                    return True
        return False

    lo, hi = 0, max_d
    for _ in range(40):
        mid = (lo + hi)//2
        if check(mid):
            lo = mid
        else:
            hi = mid

    return str(math.sqrt(lo)/2)

 ## 特殊なケース

 すべての点がほぼ同一線上にある場合、重要なエッジ ケースが発生します。 その状況では、ボトルネック距離を最小化する 2 つの遠端点と中間点を選択することによって、最適なトリプルが形成されます。 しきい値グラフは十分に離れたペアのみを接続し、相互に互換性のある 3 つの点が存在しない限り三角形の形成は失敗するため、アルゴリズムは引き続き機能します。 

もう 1 つのケースは、1 つの点が極端に孤立している場合です。 例えば：```
(0,0), (1,0), (2,0), (1000,1000)
```最良のトリプルは外れ値を完全に無視します。 アルゴリズムはこれを処理します。これは、より高いしきい値では外れ値にエッジがほとんどまたはまったくないため、どの三角形にも参加できなくなりますが、より低いしきい値では密なクラスターが引き続き有効な三角形を形成するためです。 

最後の微妙なケースは、複数のペアが同じ最大距離を共有しているが、そのスケールで三角形をサポートする 3 番目の点がない場合です。 ビットセットの交差により、共通の近傍を必要とすることで誤検知が防止され、ペアごとの最適性が誤って 3 倍の実現可能性を意味することがなくなります。
