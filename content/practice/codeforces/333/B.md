 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$ブロックされたセルがいくつかあるグリッド。 ジェラルドは境界セルにのみチップを置くことができますが、コーナーは開始位置として禁止されています。 チップを配置した後、各チップは正確にステップバイステップで移動します。$n-1$数分で常に隣接するセルに移動し、その移動により各チップがグリッドの反対側に到達します。 

動きは構造的に決定論的です。すべてのチップは、一方の境界側から反対側まで直線経路に沿って正確に移動します。$n-1$ステップ。 次に、ルールでは 3 つの失敗条件が導入されます。 チップはブロックされたセルに入ってはならず、2 つのチップが同時に同じセルを占有することはできず、2 つのチップが 1 つのステップで位置を交換することもできません。 

目標は、これらすべての制約を同時に満たせるように、できるだけ多くの開始境界位置を選択することです。 

重要な構造上の意味は、各有効なチップ配置が一方の境界エッジから反対側のエッジまでの固定「ルート」を定義し、衝突はこれらのルートが時間内にどのように交差するかによって完全に決定されるということです。 

制約が十分に大きいため、チップの動きを段階的にシミュレートしようとするソリューションは直ちに実行不可能になります。 と$n \le 1000$そして最大まで$10^5$セルがブロックされている場合、すべてのパスまたはすべてのパスのペアにわたる単純なシミュレーションは非常に遅くなります。 おおよそを超えたもの$O(n^2)$前処理はすでに厳しいものであり、多くのパス間のペアごとの相互作用チェックを伴うものは致命的になります。 

いくつかの微妙なエッジケースは見落とされがちです。 

1 つは、ブロックされたセルが「ボトルネック」を形成し、反対側からの境界エントリを切断する場合です。 たとえば、中央の列が通行できないようにブロックされている場合、開始セル自体が空いていても、その側に配置されたチップは成功できません。 

もう 1 つは、複数の開始位置が同じ強制コリドーを共有する場合です。 各パスが個別にブロックされたセルを回避したとしても、そのような 2 つのパスは合流するため、中央で衝突する可能性があります。 

最後に、スワッピングは、同じコリドー上で反対方向への対称トラバースを基本的に禁止する隠れた制約であり、特定の構成では、同じ行に沿った左から右および右から左へのエントリのペアが除外されます。 

## アプローチ

 直接的な総当たりアプローチでは、可能な開始位置をそれぞれモデル化し、その完全な軌道をシミュレートしようとします。 開始境界セルごとに、グリッド全体のパスを計算し、他のすべてのパスとの相互作用を確認できます。 それぞれのパスには長さがあるので、$O(n)$そしてそこにあります$O(n)$境界位置、これはすでに得られています$O(n^2)$パスを生成するためだけに機能し、ペアごとの衝突チェックには別の要素が追加され、$O(n^3)$最悪の場合の行動。 と$n = 1000$、これはまったく不可能です。 

重要な観察は、チップの移動が恣意的ではないということです。すべての有効なチップはグリッド全体にわたる固定コリドーを定義し、競合はグローバルではなく、共有された制約された構造に対してローカルです。 グリッド構造は、各チップが境界セルを選択し、反対側の境界に到達するまで隣接するセルを通る決定的なチェーンをたどることに効果的に対応していることを意味します。 

時間の進化について推論する代わりに、視点を反転します。ブロックされたセルが流れを中断する場合を除き、各セルは進行方向の一意の後続セルを指していると見なすことができます。 これにより、問題は、重なり合ったり競合したりせずに、素の「有効なチェーン」をいくつ選択できるかを数えることになります。 

この構造が認識されると、タスクは境界エントリに関するマッチング スタイルの選択問題に帰着します。各エントリは、その誘導されたパスが禁止されたセルにヒットすることなく反対側に到達するかどうかに応じて有効または無効になります。 スワッピングと衝突の制約により、対称コリドーの両方向を取ることができなくなり、事実上、接続された構造ごとに 1 つの選択肢を選択するルールが強制されます。 

すべての有効な開始境界位置を計算し、それらが属するコリドー構造ごとにグループ化し、グループごとに最大 1 つを選択します。

 ## アルゴリズムのチュートリアル

 1. 各境界の非コーナーセルを潜在的な開始ノードとしてモデル化します。 コーナーは明示的に禁止されており、無視すると曖昧な方向の選択が生じるため、コーナーは無視します。 
2. 各開始セルについて、反対側の境界に到達するかブロックされたセルに当たるまで、グリッドを横切る強制的な移動をシミュレートします。 このシミュレーションは決定論的なルールに従います。つまり、各ステップで、グリッドを真っ直ぐに移動することと一致する有効な次のセルが 1 つだけ存在します。 
3. シミュレーション中にチップがブロックされたセルに入った場合は、この開始位置を直ちに破棄します。 これにより、グローバルな推論を必要とせずに、最初の負け条件がローカルで強制されます。 
4. 有効なパスをシミュレートしながら、訪問したセルのシーケンスを記録するか、より効率的に各パスをそのコリドーを表す識別子に割り当てます。 コリドーは、その「入口ライン」と横断方向によって定義できます。 
5. 衝突やスワッピングの競合を防ぐために、各コリドーを単一のリソースとして扱います。 複数の開始位置が同じコリドーにマップされている場合、2 番目のチップが内部で衝突するか、対称的なスワップ シナリオが生成されるため、そこに配置できるチップは 1 つだけです。 
6. 少なくとも 1 つの有効な開始境界セルを持つ個別のコリドーの数を数えます。 
7. 有効なコリドーごとに最大 1 つのチップを配置でき、その配置を常に独立して実現できるため、このカウントを答えとして返します。 

### なぜ効果があるのか

 各チップ パスは、その開始境界位置とグリッド制約によって完全に決定されます。 2 つのチップは、誘導された経路が時空で重複する場合にのみ競合します。この決定論的な直線運動では、同じ根底にある回廊構造に属することになります。 すべての開始位置を同一のトラバース ルートによって定義された等価クラスに折りたたむことにより、異なるクラスが競合する方法で交差することはなく、同一のクラスが複数回選択されることがないため、選択された 2 つのチップが相互作用することはありません。 これにより、3 つの障害状態がすべて同時に保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    banned = set()
    for _ in range(m):
        x, y = map(int, input().split())
        banned.add((x - 1, y - 1))

    # Directions: we only care about straight corridors from one side to opposite.
    # We simulate from all non-corner boundary cells.
    dirs = []

    # top row (excluding corners): go down
    for j in range(1, n - 1):
        dirs.append((0, j, 1, 0))

    # bottom row: go up
    for j in range(1, n - 1):
        dirs.append((n - 1, j, -1, 0))

    # left column: go right
    for i in range(1, n - 1):
        dirs.append((i, 0, 0, 1))

    # right column: go left
    for i in range(1, n - 1):
        dirs.append((i, n - 1, 0, -1))

    used_corridors = set()
    ans = 0

    for sx, sy, dx, dy in dirs:
        x, y = sx, sy
        ok = True

        visited = []

        for _ in range(n - 1):
            if (x, y) in banned:
                ok = False
                break
            visited.append((x, y))
            x += dx
            y += dy

        if not ok:
            continue
        if (x, y) in banned:
            continue

        # corridor identity: endpoints define the path uniquely in straight movement
        start = (sx, sy)
        end = (x, y)
        key = (start, end)

        if key not in used_corridors:
            used_corridors.add(key)
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、可能なすべての直線境界トラバースを構築し、ブロックされたセルにヒットせずに各境界トラバースが存続するかどうかをチェックします。 各トラバースは開始境界位置と終了境界位置によって表され、決定論的な動きの下でその回廊を一意に識別します。 

ループは正確に実行されます$n-1$動きの要件に合わせて、方向ごとにステップを調整します。 禁止されたセルにアクセスすると、そのパスは直ちに無効になります。 最後の重複排除ステップでは、構造的に同一のルートが二重にカウントされないようにします。 

微妙な点は、角が生成から除外されていることです。そうしないと対角線のあいまいさが生じてしまうためです。角から開始すると、問題のルールに基づいて有効な「直線の廊下」が定義されず、答えが誤って水増しされてしまいます。

 ## 特殊なケース

 重要なエッジ ケースは、単一のブロックされたセルが境界から境界への直線のすべてのパス上にある場合です。 その場合、シミュレートされたすべての軌道は同じステップで失敗します。 各シミュレーションはすべてのステップで禁止されたセルを個別にチェックするため、アルゴリズムはこれを自然に処理します。そのため、グローバルな推論を必要とせずに、すべての候補が一貫して拒否されます。 

もう 1 つのケースは、複数の開始位置が同一の終点につながる場合です。 これらはコリドー キーを通じて折りたたまれており、対称トラバースを過剰にカウントしないようにします。 

最後に、ブロックされたセルのないグリッドは最大密度のケースを表しており、コーナー以外の境界セルごとに有効な独立したコリドーが生成されます。 このアルゴリズムは、重複排除構造からの干渉を受けることなく、それらすべてを直接カウントします。
