 ## 解決策
 ## 問題の理解

 私たちは、高さが固定された建物の列を与えられています。 あなたは建物の外の地面から開始し、あなたの目標は、インデックスが付けられた特定の建物の屋上にあるアイテムを取得することです。`m`。 移動は 2 つの独立した機構によって制限されます。ポータブルはしごを使用した垂直方向の移動と、隣接する屋根間の水平方向の移動です。 

地上から建物の屋上に到達するには、持参するはしごの高さが少なくともその建物と同じでなければなりません。 屋根に上がれば、固定接続で隣の屋根に移動できますが、重機を運ぶと移動方法が変わるという制限があります。 特に、降下する場合、効果的な移動ははしごの制約と高さの違いに依存し、同じ高さの隣接する建物間の移動は、装置があっても制限されません。 

重要な隠された構造は、目的の屋根に到達し、その後地上に戻るには、隣接する建物のシーケンスを介してのみ可能ですが、地上からのすべての侵入は、最初に登る必要がある建物の最大高さに依存し、建物間のすべての移動は、「機器を使用して降下する」制限の下で高さの移行が実現可能かどうかに依存します。 

以下を可能にする有効な一連の移動が存在するような最小ラダー長を見つけるように求められます。 

まず目標の屋根に到達し、次に機器を回収し、最後にあらゆる移動制限の下で安全に地上に戻ります。 

入力サイズは最大 100,000 の建物に達し、すべての可能なパスまたはペアごとの遷移の二次探索が除外されます。 建物間の考えられるすべてのルートをシミュレートしようとするソリューションは、非常に遅すぎます。 したがって、理想的には線形または線形に近い時間で、問題を高さ配列の構造特性に関する推論に帰着させる解決策を探しています。 

よくある失敗例は、目標とする建物の高さのみが重要であると想定した場合に発生します。 たとえば、建物の高さだけを考えてみると、`m`、答えは単純だと思うかもしれません。`h[m]`。 これは間違いです。なぜなら、より高い建物からスタートして、横に移動し、同じ高さのトランジションを使用してターゲットに到達する可能性があり、建物に直接登る必要性を効果的に回避できるからです。`m`。 

もう 1 つの微妙な間違いは、隣接するすべての建物を横切る単調な移動が常に可能であると想定していることです。 同じ高さを自由に通過できるという制約により、間接配線が可能になるプラトーが生じ、必要な最小ラダー高さに大きな影響を与えます。 

## アプローチ

 ブルートフォース解釈では、考えられるすべてのはしごの長さを試します。`L`操作全体を完了できるかどうかを確認します。 固定の場合`L`、すべての建物に最大の高さのマークを付けます。`L`地上からアクセスできるように。 このような各開始建物から、装備を使用した降下と平等に基づく横断に関するルールを尊重しながら、隣接する建物に沿った移動をシミュレートし、目標に到達できるかどうか、および戻ることができるかどうかを確認します。 

このアプローチは問題の制約を直接エンコードするため、概念的には正しいです。 ただし、候補となるはしごの長さごとに、建物グラフを完全に走査する必要がある場合があり、それにはコストがかかります。`O(n)`。 以来`L`までの範囲に及ぶ可能性があります`10^9`、単純な二分探索では依然として必要になります`O(n log H)`、境界線にありますが、合格する可能性があります。 しかし、本当の問題は、単純な実現可能性チェックでは、構造を再利用せずに配列の大部分を繰り返し再探索することになることがよくあることです。 

重要な観察は、移動ルールにより、構造が、特定の高さのしきい値の下で「安全」な、隣接する建物間のエッジによって形成される接続コンポーネントに効果的に還元されるということです。 等しい高さはゼロコストの橋として機能し、高いところから低いところへの移行は機器を運ぶ場合にのみ制限されます。 これは、実際の実現可能性は個々のパスではなく、最大高さがはしごの長さを超えない開始位置から到達可能なコンポーネントにターゲットが存在するかどうかに依存することを意味します。 

このように問題を再解釈すると、動きをシミュレートする必要はなくなります。 代わりに、しきい値の下でコンポーネントがどのように形成されるか、およびターゲットのコンポーネントが少なくとも 1 つの有効な開始点に接続されているかどうかを理解する必要があるだけです。 

これは貪欲な構造的解決策につながります。許容されるはしごの高さが増加するにつれて、より多くの建物が入口ポイントとして使用可能になり、隣接するコンポーネントが結合されます。 有効な高さの遷移を通じてターゲットの周囲の接続をどこまで拡張できるかを追跡する必要があるだけです。

 | しきい値 + 拡張 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちはこのプロセスを、ターゲットの建物から外側に向かって探索し、各拡張を含めるのに必要な最小はしごの高さを追跡しながら、有効な遷移を経て拡張するものとして再解釈します。 

1. ターゲットインデックスから開始`m`そしてそれを最初の到達可能な領域として扱います。 

私たちが直接この建物の上に立つ場合、はしごは少なくともこの建物の高さと一致する必要があります。 
2. 隣接する建物が機器の運搬に関連する均等または非増加の制約の下で移動できる限り、ターゲットから左右に拡張します。 

この拡張では、必要以上に高いはしごを必要とせずに横断できるすべての建物がキャプチャされます。 
3. 拡張中は、現在到達可能なセグメントで発生する最大高さを維持します。 

この最大値は、この接続領域の任意の部分に最初にアクセスするために必要な最小ラダー高さを表します。 
4. ルールの下では越えることができない、厳格に高さを増す障壁によって動きが妨げられる境界に遭遇した場合、私たちはその方向への拡大を停止します。 

これは、そのような境界を越えるには、少なくとも高い側と同じ高さのはしごが必要になるためであり、これは最大追跡ですでに考慮されています。 
5. どちらの方向にも拡張できなくなるまで続行します。 

結果として得られるセグメントは、制約の下でターゲットに到達およびターゲットから離れることに関連する完全な連結コンポーネントを表します。 
6. 答えは、この最終到達可能なセグメント内の最大高さです。 

これにより、初期アクセスと必要なすべての移行の両方が確実に実行可能になります。 

### なぜ効果があるのか

 このプロセスでは、移動ルールに基づいてすべての遷移が実行可能な、ターゲットの周囲に最大の連続領域が構築されます。 この領域を超えて拡張しようとすると、高さの障壁を越える必要があり、いずれにしてもより大きなはしごが必要になります。つまり、そのような拡張によって答えが減少することはありません。 維持される不変条件は、セグメント内のすべての建物は、これまでに確認された最大高さに等しい長さのはしごを使用して到達可能であり、この最大値を増やさない限り外部の建物を含めることはできないということです。 したがって、最終的な最大値は、必要な全体の横断をサポートする可能な最小のはしごの長さになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    h = list(map(int, input().split()))
    m -= 1

    left = m
    right = m
    ans = h[m]

    while True:
        changed = False

        while left > 0 and h[left - 1] <= h[left]:
            left -= 1
            ans = max(ans, h[left])
            changed = True

        while right < n - 1 and h[right + 1] <= h[right]:
            right += 1
            ans = max(ans, h[right])
            changed = True

        if not changed:
            break

    print(ans)

if __name__ == "__main__":
    solve()
```実装はウィンドウを維持します`[left, right]`ターゲットから始まる現在到達可能なセグメントを表します。 拡張ルールは、現在の境界を超えて効果的なはしごの使用量を増やす必要がない場合にのみ、隣接する建物に移動できるという制約を直接エンコードします。 展開するたびに、表示される最大高さを更新します。これにより、最初にセグメントにアクセスするために必要な最小ラダー長が決定されます。 

微妙な点は、両方の方向が独立して対称的に拡張され、同じ高さの遷移によって形成される到達可能なプラトーを見逃さないようにすることです。 ループは拡張が不可能になるまで継続し、到達可能な領域が最大限に閉じられることが保証されます。

 ## 特殊なケース

 単一の建物の場合、拡張は不可能であるため、アルゴリズムはすぐにその高さを返します。 最初のセグメントはすでに最大値であり、答えは存在する唯一の高さだけです。 

すべての高さが等しいフラット シーケンスの場合、左右両方の拡張が 1 回のスイープで配列全体にわたって進行します。 最大値は一定のままであり、はしごの長さが位置ではなく、その均一な高さのみに依存することが確認されます。 

厳密に増加してから減少する配列の場合、ピークまたはピーク付近から開始すると、拡張は最大値によって制限されます。 このアルゴリズムは、トラバースが下位領域に続いた場合でも、そのピークを最終的な答えに正しく伝播します。 

ターゲットから遠く離れた高層ビルが存在する場合、拡張は最終的には単調条件でトラバースが可能な場合にのみ到達し、トラバースが可能になると、それに応じて最大値が更新されます。 これにより、遠くにある高い制約が見逃されることがなくなります。
