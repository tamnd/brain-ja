 ## 解決策
 ## 問題の理解

 イベントホールではダイナミックなゲストの列を維持しています。 各ゲストには一意の数値識別子があります。 このラインは、注文を継続的に再形成する 3 種類の操作をサポートしています。 

ゲストは、別のゲストへの「友達紹介」を宣言して到着することができます。 その友人が現在列に並んでいる場合、到着するゲストは彼らのすぐ後ろに入る必要があります。 友人が不在の場合は、新しいゲストが行の最後に追加されます。 ゲストは時間の経過とともに何度も現れる可能性があるため、構造は再挿入をサポートする必要があります。 

ゲストはいつでも列から離れることができ、その削除によって他の全員の相対的な順序が崩れてはなりません。 

最後に、現在の列の先頭を繰り返し報告するか、列が空いていることを報告するように求められます。 

主な問題点は、挿入が単に最後ではなく、任意の既存要素の後に行われる可能性があるのに対し、削除とクエリは最大 200,000 回の操作でも効率を維持する必要があることです。 クエリごとに完全なスキャンを行うと、最悪の場合、二次的な動作が発生するため、各操作の行をスキャンするアプローチはすぐに失敗します。 

2 番目の微妙な点は、「存在する場合は友人の後ろに挿入」では、現在建物内に人がいるかどうかを迅速に検出する必要があり、いる場合はその位置に直接アクセスする必要があることです。 

頻繁に移動する人に対して繰り返し挿入すると、単純な失敗モードが表示されます。 たとえば、毎回友人を常に線形に検索すると、移動する前部要素の背後で多数の連鎖挿入が行われるようなケースでは、フル スキャンが繰り返されることになり、たとえ個々の操作が安っぽく見えても、隠れた二次関数の爆発が発生します。 

もう 1 つのエッジケースは削除です。 配列ベースのキューから要素を物理的に削除すると、削除のたびに要素を移動する動作が操作ごとに線形になり、削除が頻繁に行われる場合には再び二次的な動作が発生します。 

したがって、中心的な要件は以下をサポートする構造です。 

ゲストの迅速な存在確認、

 既知のノードの隣に高速挿入、

 既知のノードの迅速な削除、

 そして現在の最前線への素早いアクセス。 

## アプローチ

 直接のブルート フォース シミュレーションでは、キューが Python リストとして保存されます。 それぞれについて`in x y`、リストをスキャンして見つけます`y`を挿入してから、`x`その直後。 もし`y`が見つからないため、追加します。 のために`out x`、もう一度スキャンして位置を特定します`x`そしてそれを取り除きます。 のために`check`、最初の要素を返します。 

これは文字通りルールをシミュレートするため、論理的には正しいです。 ただし、各操作では最大 O(n) 要素のスキャンが必要になる場合があります。 最大 200,000 回の操作では、合計作業量は O(nq) となり、最悪の場合は 10^10 回の操作を超え、実行可能な制限をはるかに超えます。 

重要な観察点は、行の順序が常にローカルな変更を伴うリンクされた構造であるということです。 各ゲストの位置は、既知のノードの隣に挿入するか削除することによってのみ変更されます。 これは、配列のシフトをポインター操作に置き換えることを示唆しています。 

キューを二重リンクリストとしてモデル化できます。 各ゲストはノードに対応します。 ゲスト ID からノード ポインターまでの辞書を維持しているので、O(1) 内の任意のゲストにアクセスできます。 挿入はポインタの再配線になります。フレンドが存在する場合は、その直後に新しいノードを接続します。 それ以外の場合は末尾に追加します。 近隣ノードを使用してノードのリンクを解除することにより、削除も O(1) になります。 

これにより、高価なすべての線形スキャンが定時間の辞書検索とポインタの更新に変換されます。

 | --- | --- | --- | --- |
 | ブルート フォース (リスト + スキャン) | O(q・n) | O(n) | 遅すぎる |
 | 最適 (ハッシュ マップ + リンク リスト) | O(q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 明示的な先頭ポインタと末尾ポインタを含む二重リンク リストと、ゲスト ID からノードへのハッシュ マップを維持します。 

1. を格納するノード構造を作成します。`value`、`prev`、 そして`next`。 これは列のゲストを表します。 これにより、要素を移動することなく、一定時間の削除と挿入が可能になります。 
2. メンテナンス`head`そして`tail`現在の行の前後のポインタ。 これらにより、最初の要素への O(1) アクセスが与えられます。`check`。 
3. 辞書を管理する`pos[x]`各ゲスト ID をそのノードにマップします。 これにより、リストを線形に検索することがなくなります。 
4.`in x y`操作では、まず新しいノードを作成します`x`。 Then check whether`y`に存在します`pos`。 存在する場合は、その直後に新しいノードを挿入します。`y`新しいノードのリンクと周囲の隣接ノードという 4 つのポインターを更新することで、 のノードを更新します。 存在しない場合は、テールポインタを使用して最後にノードを接続します。 これにより、必要な順序付けルールが保持されます。 
5.`out x`操作、からノードを取得します`pos[x]`そしてリストから削除します。 前後のノードを再接続します。 先頭または末尾の場合は、対応するポインタを更新します。 最後に、削除します`x`辞書から。 
6. のために`check`、出力します`head.value`リストが空でない場合は、-1 を出力します。 

機能する理由: リンクされたリストは常に、ゲストの正確な現在の順序を表します。 辞書は、参照されたゲストを一定時間内に見つけることができることを保証します。 すべての挿入はローカル隣接関係のみを変更することで相対的な順序を保持し、すべての削除は残りのノード間の順序を保持します。 すべての操作は定数のローカル構造のみを変更またはクエリするため、グローバルな順序付けの不変条件に違反することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("val", "prev", "next")
    def __init__(self, val):
        self.val = val
        self.prev = None
        self.next = None

def main():
    q = int(input().strip())

    pos = {}
    head = None
    tail = None

    out = []

    for _ in range(q):
        cmd = input().split()

        if cmd[0] == "in":
            x = int(cmd[1])
            y = int(cmd[2])

            node = Node(x)
            pos[x] = node

            if y in pos:
                ny = pos[y]

                node.prev = ny
                node.next = ny.next

                if ny.next:
                    ny.next.prev = node
                ny.next = node

                if tail == ny:
                    tail = node
            else:
                node.prev = tail
                node.next = None

                if tail:
                    tail.next = node
                tail = node

                if head is None:
                    head = node

        elif cmd[0] == "out":
            x = int(cmd[1])
            node = pos.pop(x)

            if node.prev:
                node.prev.next = node.next
            else:
                head = node.next

            if node.next:
                node.next.prev = node.prev
            else:
                tail = node.prev

        else:
            if head is None:
                out.append("-1")
            else:
                out.append(str(head.val))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```Python の組み込みリストは挿入または削除中の O(1) をサポートしていないため、実装は手動の二重リンク リストに依存します。 辞書`pos`トラバースを回避する重要なコンポーネントです。 

挿入ロジックは、友人が存在するかどうかを注意深く区別します。 ノードの後に​​挿入する場合、友人が末尾である場合を処理する必要があります。`ny.next`None なので更新する必要があります`tail`。 同様に、空のリストに挿入する場合は、先頭と末尾の両方を初期化する必要があります。 

削除では境界ケースを対称的に処理する必要があります。 ヘッドを削除するにはアップデートが必要です`head`しっぽを削除するには更新が必要です`tail`。 辞書を削除すると、古い参照が二度と表示されなくなります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、参照されたフレンドが現在の末尾である場合に挿入することです。 その場合、挿入ロジックは末尾ポインターを更新する必要があります。 たとえば:

 入力:```
3
in 1 1
in 2 1
in 3 2
```処理後のリストは次のようになります`1 2 3`。 挿入時`3`後`2`、ノード`2`現時点では末尾なので更新できません`tail`構造が矛盾したままになり、後の挿入やチェックが壊れてしまいます。 アルゴリズムはこれを明示的にチェックし、`tail = node`。 

もう 1 つの特殊なケースは、head 要素を削除することです。 最初の要素が離れる場合、ヘッド ポインタは前方に移動する必要があります。 のために：```
3
in 1 1
in 2 1
out 1
```リストは次のようになります`2`。 削除ロジックは次のことを検出します。`node.prev is None`そしてアップデート`head = node.next`。 この調整がなければ、`check`削除された要素が返されます。 

最後のエッジケースは、同じ ID の再挿入が繰り返されることです。 それぞれなので`in x y`新しいノードを作成して更新します`pos[x]`、以前に発生したものはすでに削除されている必要があります。 ディクショナリにより、現在のノードのみが追跡されることが保証されるため、古いポインターにはアクセスできません。
