 ## 解決策
 ## 問題の理解

 ホテルのラウンジではダイナミックな客列を維持していますが、この列の構造は珍しいです。 各人には一意の識別子があり、現在の順序を変更またはクエリする 3 つの操作をサポートする必要があります。 

好みの知人と一緒に到着したゲストは、単に最後に加わるわけではありません。 現在ラウンジに友人がいる場合、その友人の直後に挿入されます。 それ以外の場合は、行の末尾に追加されます。 ゲストはいつでも退席することができ、列のどこにいても退場しなければなりません。 最後に、現在の列の最初の人を繰り返し報告する必要があります。 

重要な問題は、その構造が単純なキューではないことです。 挿入は任意の既存要素の検索に依存し、削除はどこででも発生する可能性があります。 最大 200,000 回の操作では、リストをスキャンして挿入ポイントや削除を見つけるソリューションは、最悪の場合の動作が二次関数になるため、時間がかかりすぎます。 

Python リストまたは両端キューを使用した単純なシミュレーションは、フレンドの検索または中間要素の削除に線形時間が必要なため失敗します。 最悪の場合は繰り返します`in x y`どこでの操作`y`終わりに近づいていると、フルスキャンが繰り返し実行されます。`out x`見つけるには別のスキャンが必要になります`x`。 

キューが空の場合、または参照された友人が存在しない場合、微妙なエッジ ケースが発生します。 たとえば:

 入力:```
check
```出力：```
-1
```どのソリューションでも、空の構造クエリを明示的に処理する必要があります。 

もう 1 つの特殊なケースは、同じ人物が繰り返し到着することです。 このステートメントにより、ゲストは時間の経過とともに複数回出現することができますが、各識別子はいつでも現在のキュー内で一意になります。 存在を追跡せずに、時間の経過とともに一意性を仮定する不注意な実装では、重複挿入が試行されたり、削除に失敗したりする可能性があります。 

## アプローチ

 直接シミュレーションでは、キューをリストに保存し、それぞれに対して`in x y`、スキャンして見つけます`y`そしてその後に挿入します。 削除の場合も同様に、検索してスキャンする必要があります。`x`。 概念的には単純ですが、最悪の場合、各操作のコストは O(n) になります。 最大 200,000 回の操作では、これは O(n²) に低下し、遅すぎます。 

重要な点は、実際の連続したシーケンスを保存する必要がないということです。 前任者と後任者の関係を維持するだけで済みます。 各要素は二重リンク構造内で固有の位置を持っており、識別子によってノードに高速にアクセスする必要があります。 

これにより、値からノードへのハッシュ マップと組み合わせたリンク リスト表現が自然に得られます。 ハッシュ マップでは任意の人に O(1) アクセスが許可され、リンク リストではノード参照を取得すると O(1) の挿入と削除が許可されます。 

この構造は、明示的な先頭ポインタと末尾ポインタを持つ動的二重リンクリストになります。 各ゲストはノードです。 誰かの後に挿入する場合は、その人とその隣にあるノードの間に新しいノードを接続します。 削除するときは、隣接するものを直接再接続します。

 | ハッシュマップ + 二重リンクリスト | O(q) | O(q) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードがゲスト ID に加えて、前後のノードへのポインタを格納する二重リンク リストを維持します。 ID をノードにマッピングする辞書も維持します。 

1. 先頭ポインタと末尾ポインタを null に設定し、空の辞書を使用して空の構造体を初期化します。 
2.`in x y`操作では、y が辞書に存在するかどうかを確認します。 
3. y が存在する場合は、ポインタを再配線してノード y の直後に x を挿入します。 y が末尾の場合、末尾を更新します。 
4. y が存在しない場合は、リストの最後に x を追加し、それに応じて tail を更新します。 リストが空の場合、先頭も末尾も x になります。 
5. のために`out x`、O(1) のノード x を辞書から取得し、その前後の隣接ノードを再接続し、必要に応じて先頭または末尾を更新し、辞書から x を削除します。 
6. のために`check`、存在する場合はヘッド ID を出力し、存在しない場合は -1 を出力します。 

各挿入または削除は一定数のポインターのみを操作するため、すべての操作は O(1) で実行されます。 

### なぜ効果があるのか

 不変条件は、二重リンク リストが常にゲストの正確な現在の順序を表し、辞書が常に現在の各ゲスト ID を対応するノードにマップすることです。 すべての更新では、ローカル リンクを再配線するだけで隣接関係が維持され、構造をグローバルに再構築することはありません。 すべての操作では一定数のノードのみが変更またはクエリされるため、構造の一貫性が保たれ、必要なすべての操作が効率的にサポートされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("val", "prev", "next")
    def __init__(self, val):
        self.val = val
        self.prev = None
        self.next = None

def solve():
    q = int(input())
    pos = {}

    head = None
    tail = None

    out = []

    for _ in range(q):
        cmd = input().split()

        if cmd[0] == "in":
            x = int(cmd[1])
            y = int(cmd[2])

            node = Node(x)
            pos[x] = node

            if y in pos:
                ynode = pos[y]
                nxt = ynode.next

                node.prev = ynode
                node.next = nxt
                ynode.next = node

                if nxt:
                    nxt.prev = node
                else:
                    tail = node
            else:
                if tail is None:
                    head = tail = node
                else:
                    tail.next = node
                    node.prev = tail
                    tail = node

        elif cmd[0] == "out":
            x = int(cmd[1])
            node = pos.pop(x)

            pv = node.prev
            nx = node.next

            if pv:
                pv.next = nx
            else:
                head = nx

            if nx:
                nx.prev = pv
            else:
                tail = pv

        else:  # check
            if head:
                out.append(str(head.val))
            else:
                out.append("-1")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```ソリューションの中核は、明示的なノード構造です。 各ノードはローカル ポインタのみを保存し、すべてのグローバル構造は`head`、`tail`、およびハッシュマップ。 

挿入中に、既存のノードの後に​​接続するか、末尾に追加します。 重要な詳細は、次のようなケースを正しく処理することです。`y`は現在の末尾です。その場合、新しいノードが新しい末尾になるからです。 

削除中は、近隣のものを慎重に更新し、調整も行います。`head`そして`tail`境界ノードを削除するとき。 これらのポインターのいずれかの更新を忘れると、誤った出力が発生する一般的な原因になります。 

辞書`pos`あらゆる人の位置を一定時間で特定できるようになり、フルスキャンが回避されます。

 ## 特殊なケース

 重要なケースの 1 つは、友人が行方不明になった後に繰り返し挿入されるケースです。 たとえば、次のように挿入すると、`x`と`y`存在しません、`x`最後まで行かなければなりません。 アルゴリズムはチェックすることでこれを処理します。`y in pos`ポインター ロジックの前に、追加動作が一貫して使用されるようにします。 

もう 1 つのケースは、現在のヘッドの削除です。 ヘッド ノードを削除すると、`prev`ポインタが null なので、明示的に移動する必要があります`head`に`node.next`。 次のノードのリンク構造は有効なままです。`prev`すでに正しく設定されているか、更新後に null になります。 

最後に、末尾ノードを削除するときに、更新します。`tail`に`node.prev`。 これを行わないと、今後末尾に挿入すると古いポインタにアタッチされ、シーケンスが破損します。
