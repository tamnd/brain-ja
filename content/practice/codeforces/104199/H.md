 ## 解決策
 ## 問題の理解

 n 桁の文字列であるキーが与えられ、一連の桁ごとの制約の下で、そのキーと互換性のある可能な n 桁の部屋番号をすべて見つけるように求められます。 各部屋番号も、0 ～ 9 の数字で構成される長さ n の文字列であり、先頭のゼロが許可されるため、実際には数値ではなく数字シーケンスの空間で作業します。 

この制約は、部屋番号の隣接する数字をキーの数字にリンクします。 1 から n-1 までのすべての位置 i について、部屋の i 番目と (i+1) 番目の桁の合計 (10 を法として計算) は、キーの i 番目の桁と等しくなければなりません。 さらに、ラップアラウンド条件があります。キーの最後の桁が、部屋の最初の桁と最後の桁の合計 (同じく 10 を法として等しい) に等しいというものです。 

したがって、キーは数字に関するモジュラー線形方程式系を定義します。各方程式には、正確に 2 つの隣接する部屋の数字が含まれ、最後の方程式はシーケンスの端を接続します。 タスクは、これらすべての制約を同時に満たすすべての数字シーケンスを列挙することです。 

n が 100000 までという制約により、桁を独立して分岐するアプローチは即座に除外されます。 10^n 個の可能性を完全に列挙することは不可能であり、強力な枝刈りを行わずに各位置で分岐するソリューションであっても失敗します。 この構造は、プレフィックスが選択されると、シーケンスの残りの部分が決定されるか、または大幅に制約されるようになり、これが検索スペースを縮小するための鍵であることを示唆しています。 

モジュラー演算から微妙なエッジ ケースが発生し、逆方向伝播に曖昧さが生じます。 たとえば、x + y ≡ k (mod 10) の場合、y がわかれば、x は 10 を法として一意に決定されますが、これはラップアラウンド値を正しく処理した場合に限られます。 モジュロ正規化を行わずに直接減算を使用する不注意な実装では、負の数値が生成されたり、誤った分岐が生成されます。 

もう 1 つのエッジ ケースは、最初と最後の桁が関係する循環制約です。 線形チェーン制約のみを強制し、最終方程式との一貫性を無視した場合、すべての隣接する制約を局所的に満たすが、全体的には失敗するシーケンスを生成する可能性があります。 

## アプローチ

 ブルートフォース戦略は、考えられるすべての部屋番号を試し、それぞれが制約に照らして検証されることです。 各候補文字列について、n-1 個の隣接する制約と 1 つのラップアラウンド制約をチェックし、候補ごとに O(n) の検証を行います。 候補は 10^n 個あるため、n が非常に小さい場合でも、これは完全に実行不可能です。 

重要な観察は、制約が 10 を法とする線形再帰を形成するということです。部屋の最初の桁を固定する場合、2 番目の桁は、a1 + a2 ≡ k1 (mod 10) という形式の最初の方程式を満たす必要があります。これにより、a1 が選択されると、a2 は 10 を法とする 1 つの可能な値に制限されます。 このプロセスを継続すると、次の各桁が前の桁から一意に決定されます。 これは、最初の数字を選択するたびに、候補シーケンスが 1 つだけ生成されることを意味します。 

ただし、最後の桁と最初の桁に関係する循環制約があるため、すべての最初の選択が有効な完全な解を生み出すわけではありません。 代わりに、最初の数字を選択することによって誘導されるすべてのシーケンスを生成し、決定論的に伝播し、最終的なモジュラー条件を満たすものをフィルターします。 

これにより、問題はすべての桁にわたる指数列挙から、それぞれが O(n) で構築される最大 10 個の候補に減らされ、合計 O(10n) 個の解が得られます。

 ## アルゴリズムのチュートリアル

 この関係を順方向再帰として解釈します。 a[i] + a[i+1] ≡ k[i] (mod 10) から、a[i] が既知であれば a[i+1] を計算できます。

1. 部屋の最初の桁の 0 から 9 までの各可能な値を試します。開始点が固定されるとシステムは決定的になるため、それぞれの選択肢によって潜在的な解決経路が定義されます。 
2. 選択した最初の桁について、最初のキー制約を使用して 2 番目の桁を計算します。 方程式を a[i+1] ≡ k[i] - a[i] (mod 10) として再配置し、0 ～ 9 の範囲に正規化します。このステップにより、有効な数値の範囲内に収まることが保証されます。 
3. 位置 2 から n-1 まで順方向に反復し、反復を繰り返し適用して次の各桁を決定します。 すべてのステップで、前の桁とキーの桁によって次の桁が完全に決定されるため、初期化後に分岐は発生しません。 
4. 完全なシーケンスを構築した後、最終的なラップアラウンド制約 a[n] + a[1] ≡ k[n] (mod 10) を検証します。 この条件を満たすシーケンスのみが有効な部屋番号です。 
5. 有効なシーケンスをすべて収集し、出力します。 

重要な構造上の考え方は、1 つの変数を固定すると方程式系が三角形になるということです。 各方程式は 1 つの自由度を排除し、チェーン構造により中間位置での独立した選択が妨げられます。 

### なぜ効果があるのか

 隣接する各制約により、ある桁から次の桁への決定的な移行が強制されます。 これは、最初の桁が固定されると、モジュラー減算を繰り返し適用することで、後続のすべての桁が一意に決定されることを意味します。 残された唯一の自由は開始桁の選択であるため、解空間は 10^n 個の候補から最大 10 個の候補シーケンスまで縮小します。 最後のラップアラウンド制約は、循環依存関係が伝播された値と矛盾しないことを保証するグローバル一貫性チェックとして機能します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    k = input().strip()

    res = []

    for start in range(10):
        a = [0] * n
        a[0] = start

        ok = True

        for i in range(n - 1):
            # a[i] + a[i+1] ≡ k[i] (mod 10)
            need = (int(k[i]) - a[i]) % 10
            a[i + 1] = need

        # check final constraint: a[n-1] + a[0] ≡ k[n-1]
        if (a[n - 1] + a[0]) % 10 == int(k[-1]):
            res.append("".join(map(str, a)))

    print(len(res))
    for r in res:
        print(r)

if __name__ == "__main__":
    solve()
```実装は再帰解釈に直接続きます。 候補の部屋番号を配列に格納し、左から右に埋めます。 モジュラー減算`(int(k[i]) - a[i]) % 10`は、負の数字を回避し、あらゆる場合に正確さを保証するための重要な詳細です。 

最終チェックでは、循環制約が明示的に適用されます。これは、前方再帰で捕捉されない唯一の条件です。

 ## 特殊なケース

 エッジ ケースの 1 つは n = 2 です。この場合、漸化式は長い連鎖のように動作せず、同じ数字のペアを含む 2 つの方程式に崩壊します。 この場合、すべての数字の選択を両方の制約に対して直接チェックでき、効果的にペアを構築し、サイクル条件を即座に検証するため、アルゴリズムは引き続き機能します。 

入力の場合:```
2
00
```start = 0 を試すと、a1 + a2 ≡ 0 と a2 + a1 ≡ 0 の両方を満たすシーケンス 00 が得られます。同じことがすべての桁に当てはまり、10 個の有効な解が生成されます。 前方構築でも一貫したペアが生成され、最終チェックは最初の制約と同等であるため、アルゴリズムはそれらをすべて正確に列挙します。 

もう 1 つのエッジ ケースは、循環制約を満たす開始桁がない場合です。 その状況では、結果リストは空のままになります。 最終チェックに合格するシーケンスがないため、アルゴリズムはこれを自然に処理します。そのため、追加の処理は必要なく、出力は正しく 0 になります。 

3 番目のケースは、モジュラー減算がラップアラウンド後にゼロになる場合です。 たとえば、k[i] = 0 および a[i] = 7 の場合、計算される次の桁は (0 - 7) mod 10 = 3 になります。これにより、負の桁が回避され、すべての値が有効な桁のままになります。これは、すべての入力にわたる正確性にとって不可欠です。
