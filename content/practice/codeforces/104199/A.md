 ## 解決策
 ## 問題の理解

 フロア 0 から開始して、目標フロア D に到達したいと考えています。エレベーターは移動するたびに、正確に 2 つのアクションを実行できます。つまり、3 フロア上がるか 2 フロア下がるということです。 各アクションは、ボタンを 1 回押したものとしてカウントされます。 タスクは、正確に D に到達するために必要なボタンを押す最小回数を決定することです。 

これは、整数状態の無限直線上の最短経路問題です。 各フロアはノードであり、すべてのノード x から、コスト 1 で x + 3 または x − 2 に進むことができます。ターゲット範囲は小さく、D は -1000 から 1000 の間であるため、状態空間は非常に小さいため、かなり直接的なグラフ検索も実行可能です。 

主な微妙な点は、D に到達するのが単調ではないことです。 +3 を使用して D に向かうとオーバーシュートする可能性があり、-2 を使用した修正が必要になります。またその逆も同様です。 「常に近くに移動する」などの貪欲な戦略は、実際の距離よりも小さいサイクルを法として得た近さの方が重要であるため、失敗します。 

単純な間違いは、常に +3 ステップのみまたは -2 ステップのみを使用するなどの決定論的な公式を試みたり、最小の非負の解による整数の実現可能性を保証せずに 3a − 2b = D を解いて a + b を最小化するような線形結合を試みたりすることです。 こうしたアプローチはすぐに壊れてしまいます。 

たとえば、D = 1 の場合、「+3 の場合、-2 は 2 ステップで 1 が得られる」と考えるかもしれませんが、これは正しいですが、D = 2 の場合、貪欲に考えると、+3 の場合、-1 の調整は不可能であり、組み合わせを検討する必要があると示唆される可能性があります。 この構造は線形最適化ではなく、2 つの移動グラフにわたる最短パスです。 

D は 1000 で制限されているため、k ステップで 0 から到達可能な完全な領域は約 ±3k 以内にあるため、数百までの k で十分です。 これは、BFS スタイルのソリューションまたは状態に対する動的プログラミングを示唆しています。 

エッジケースには次のようなものがあります。 

D = 0 の場合、すでにそこに到達しているため、答えは 0 になります。 

D が負の場合、+3 と -2 の組み合わせによってのみ到達できるため、最初に正側のオーバーシュートを許可する必要があります。 

D が 1 または 2 のように小さい場合、最適解には直接の動きではなく混合ステップが含まれます。 

## アプローチ

 ブルートフォースアプローチは、これを無限整数グラフ上の重み付けされていない最短経路問題として扱い、0 から開始して +3 と -2 を適用して状態を拡張し、最初に D に到達した時点で停止する BFS を実行することです。これは正しいです。すべての移動のコストが等しいため、BFS は最小ステップを保証します。 

ただし、制約がなければグラフは無限であるため、単純な BFS は永久に継続する可能性があります。 重要な観察は、グラフは無限であるにもかかわらず、[-1000, 1000] の範囲内の任意の D への最適なパスは、わずかに大きな境界区間のはるか外側を探索する必要がないということです。 各移動で位置が最大 3 変化するため、k ステップで [−3k, 3k] 以内になります。 1000 以内の任意の D に到達するために、約 1000 を超える k は必要ないため、およそ [-3000, 3000] の外側の位置は不要です。 これにより、訪問済みセットで BFS が実現可能になります。 

さらに構造化された観察は、これが単位コスト エッジを伴う線形ディオファントス到達可能性問題であり、BFS が合計ステップの昇順で +3 と -2 の組み合わせを効果的に探索していることです。 初めて D を打ったときは最適であることが保証されます。 

ブルートフォース BFS は機能しますが、無制限に実装すると無駄になります。 最適化されたバージョンは同じ BFS ですが、適切な状態ウィンドウが固定されており、早期停止が行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 無制限の BFS | O(∞) | O(∞) | 使用不可 |
 | 有界BFS | O(V) ここで、V ≈ 6000 | O(V) | 承認済み |

 ## アルゴリズムのチュートリアル

 各フロアをグラフ内のノードとしてモデル化し、0 から BFS を実行します。

1. 距離 0 の位置 0 から始まるキューを初期化します。これは、ボタンがまだ押されていない状態でロビーにいることを表します。 
2. フロアの再訪問を避けるために、訪問したセットを維持します。 これにより、+3 と -2 の間の循環によって引き起こされる無限ループが防止されます。 
3. キューが空でない間に、現在のフロアとそこに到達するまでに要した歩数を抽出します。 これにより、BFS はステップの昇順で状態を処理します。 
4. 現在のフロアが D に等しい場合、現在の歩数を直ちに返します。 BFS は、これが可能な最小限のプレス数であることを保証します。 
5. それ以外の場合は、2 つの近傍を生成します: current + 3 および current − 2。各近傍について、その近傍が訪問されておらず、ターゲットの周囲の妥当な範囲内にある場合は、ステップ数 + 1 でキューにプッシュします。 
6. BFS が早期リターンなしで終了した場合 (これは正しい境界では起こらないはずです)、ターゲットは到達不能ですが、この問題では gcd(3, 2) = 1 であるため、ターゲットは常に到達可能です。 

機能する理由: すべての移動には等しいコストがかかり、BFS は開始点からの距離が大きい順に状態を探索します。 すべての遷移には単位重みがあるため、最初に状態に到達するときは、最短の一連の操作を経ることが保証されます。 訪問セットにより、各状態が 1 回処理されることが保証され、冗長な展開を行わずに正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    D = int(input().strip())

    if D == 0:
        print(0)
        return

    # safe exploration bounds
    LIM = 3000

    q = deque()
    q.append((0, 0))
    visited = set([0])

    while q:
        x, d = q.popleft()

        if x == D:
            print(d)
            return

        for nx in (x + 3, x - 2):
            if -LIM <= nx <= LIM and nx not in visited:
                visited.add(nx)
                q.append((nx, d + 1))

    # theoretically unreachable
    print(-1)

if __name__ == "__main__":
    solve()
```このコードは、整数位置に対して BFS を直接実装します。 キューには、現在のフロアと、そのフロアに到達するまでに使用されたボタンの押下回数の両方が保存されます。 訪問セットにより、フロアが再処理されないことが保証され、+3 と -2 の間の繰り返しサイクルによる指数関数的な爆発が防止されます。 

範囲 LIM は、±1000 以内のターゲットへの最適なパスがそれ以上さまよう必要がないように選択されます。 この範囲を超える迂回には追加の手順が必要になり、重み付けされていないグラフのすでに最短のパスを改善できないため、これは安全です。 

## 実用的な例

 ### 例 1: D = 1

 | ステップ | 現在 | 距離 | 次の状態 |
 | --- | --- | --- | --- |
 | 1 | 0 | 0 | 3、-2 |
 | 2 | 3 | 1 | 6、1 |
 | 3 | 1 | 2 | 停止 |

 BFS は、0 → 3 → 1 の 2 ステップで 1 に到達します。これは、最適なソリューションにはオーバーシュートと復帰が必要な可能性があることを示しています。 

### 例 2: D = -5

 | ステップ | 現在 | 距離 | 次の状態 |
 | --- | --- | --- | --- |
 | 1 | 0 | 0 | 3、-2 |
 | 2 | -2 | 1 | 1、-4 |
 | 3 | -4 | 2 | -1、-6 |
 | 4 | -5 | 3 | 停止 |

 アルゴリズムは、上向きと下向きの両方の動きを含むパスを正しく検出します。 これは、負のターゲットが対称的に処理され、ゼロの両側での探索が必要であることを示しています。

## テストケース```python
import sys, io
from collections import deque

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    def solve():
        D = int(input().strip())

        if D == 0:
            return "0"

        LIM = 3000
        q = deque()
        q.append((0, 0))
        visited = set([0])

        while q:
            x, d = q.popleft()

            if x == D:
                return str(d)

            for nx in (x + 3, x - 2):
                if -LIM <= nx <= LIM and nx not in visited:
                    visited.add(nx)
                    q.append((nx, d + 1))

        return "-1"

    return solve()

# provided samples
assert run("1\n") == "2"
assert run("-5\n") == "5"

# custom cases
assert run("0\n") == "0"
assert run("3\n") == "1"
assert run("2\n") == "2"
assert run("10\n") == run("10\n")
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 D = 0 の場合、アルゴリズムは BFS に入る前にすぐに 0 を返します。 初期チェックではこれを明示的に処理するため、キュー操作は必要ありません。 

D = 2 のような小さな正の値の場合、BFS は 0 → 3 → 1 → 4 → 2 を探索し、2 に到達するには 2 つのステップが必要であることを正確に識別します。 貪欲な +3 アプローチはこれを見逃して、オーバーシュートが避けられないことを誤って示唆する可能性があります。 

D = -5 のようなネガティブなターゲットの場合、BFS は -2 の移動を繰り返すことで自然にネガティブな領域に拡大しますが、必要に応じて一時的なポジティブな位置も探索します。 訪問セットにより、0 → 3 → 1 → 4 → 2 → 0 などのサイクルが繰り返し再訪問されないことが保証されるため、検索は有限のままであり、最短パスが見つかります。
