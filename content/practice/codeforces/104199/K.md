 ## 解決策
 ## 問題の理解

 1 から n までのラベルが付けられた位置における項目の開始配置を記述する配列が与えられます。 位置 i は最初に項目 a[i] を保持します。最終的な目標は、位置 i にすべての i に対して項目 i が含まれるようにこの配置を変換することです。 

アイテムを移動する唯一の方法は、各位置に 1 台ずつ配置された一連のロボットを使用することです。 ロボットは、単一のアイテムを運び、手が空であれば現在の位置からそれを拾い上げ、位置間を移動し、必要に応じて再び落としたり拾ったりすることができます。 位置 i と j の間の移動は、i と j が 1 より大きい公約数を共有する場合にのみ可能です。 

これにより、問題は位置 1 から n にわたる到達可能性の問題に変わり、接続性は gcd 制約によって定義されます。 問題は、ロボットがこれらの制約された動きを使用してアイテムをアイデンティティ構成に再配置できるかどうかです。 

n ≤ 200000 という制約は、最悪の場合でもペアの数が 2 次であるため、位置のペア間のすべてのエッジを明示的に構築しようとするアプローチは不可能であることを意味します。 すべてのペアを反復処理して gcd を計算するだけでも、遅すぎます。 ソリューションは、明示的なグラフ構築ではなく、接続性の構造化されたビューに依存する必要があります。 

2 つの位置が直接ではなく間接的に接続されている場合、微妙なエッジ ケースが発生します。 たとえば、gcd(6,10)=2 および gcd(10,15)=5 であっても、6 は 2 を介して 10 に接続されますが、gcd(6,15)=3 もそれらを間接的に接続します。 直接の gcd エッジのみを考慮する単純なアプローチでは、動きが実際よりも制限されていると誤って結論付ける可能性があります。 

各ロボットが独自の位置を独立して固定できると仮定すると、別の失敗ケースが発生します。 たとえば、1 → 8 → 2 → 1 のようなサイクルでは、単一のロボットが自身の位置を直接「解決」しない場合でも、コンポーネント内でアイテムを回転させることができます。 

## アプローチ

 ブルート フォース アプローチでは、gcd(i, j) > 1 の場合にすべてのペア (i, j) が接続されるグラフを明示的に構築し、グラフ トラバーサルを実行して接続されたコンポーネントを見つけます。 各ノードは位置を表し、エッジは許可されるロボットの動きを表します。 コンポーネントを計算した後、各コンポーネントに初期項目とターゲット項目のまったく同じマルチセットが含まれているかどうかを確認します。 

ロボットは切り離されたコンポーネント間でアイテムを移動できないため、これは原理的には正しいです。 ただし、すべてのエッジを構築するには O(n^2) ペアをチェックする必要があり、このような密なグラフ上で単一の BFS または DFS を使用することさえ、n = 200000 では実行不可能です。 

重要な観察は、gcd(i, j) > 1 は、少なくとも 1 つの素因数を共有する i と j と同等であるということです。 ペアごとの gcd チェックの観点から考える代わりに、素数によって引き起こされる接続性を考えることができます。 すべての数値は、その素因数に対応するすべての素数「グループ」に属し、数値は共有素数を介して接続されます。 これにより、グラフが数値と素数の間の 2 部構造に変換され、素因数を共有するインデックスを素集合の共用体構造を使用して結合できるようになります。 

この関係に基づいて連結成分を計算すると、各成分は自己一貫性を持つ必要があります。すべてのインデックス i がそのターゲット位置 a[i] に到達できなければなりません。そうしないと、必要なアイテムをそこに転送できません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (明示的なグラフ) | O(n²) | O(n²) | 遅すぎる |
 | 素因数による DSU | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 インデックス 1 ～ n に対して素の集合共用体構造を構築します。 目標は、素因数の共有を介して接続されているインデックスをマージすることです。

1. 各位置が独自のコンポーネントである DSU を初期化します。 これは、最初は移動が不可能であると想定していることを表します。 
2. 1 から n までのすべての数値 i について、それを個別の素因数に因数分解します。 n が大きいため、sqrt(n) までの効率的なふるいのような前処理または試行除算に依存します。 
3. 各素数を、それが出現する最初のインデックスにマッピングする辞書を維持します。 インデックス i で素数 p に遭遇したとき、p が以前に出現したことがなければ、i をその代表として記録します。 見つかった場合は、i を以前に保存されたインデックスと結合します。 このステップでは、エッジを明示的に構築せずに、共有プライムを介して接続を構築します。 
4. すべてのインデックスを処理した後、DSU の各接続コンポーネントは、ロボットがアイテムを自由に移動できる一連の位置に対応します。 
5. 最後に、各インデックス i について、i と a[i] が同じ DSU コンポーネントに属しているかどうかを確認します。 いずれかのインデックスがこの条件を満たさない場合、変換は不可能です。 

重要な考え方は、項目は gcd グラフの接続されたコンポーネント内でのみ移動できるということであり、共有素数上の DSU はそれらのコンポーネントを正確に正確にキャプチャします。 

### なぜ効果があるのか

 基礎となる不変条件は、連続する要素が素因数を共有する一連の数値を共有する場合に限り、2 つのインデックスが移動グラフ内で接続されるということです。 DSU は、少なくとも 1 つの素因数を共有するインデックスを正確にマージし、ユニオン演算の推移性により間接的な gcd 接続をキャプチャします。 有効な移動はすべてコンポーネントのメンバーシップを保持するため、アイテムがコンポーネントを越えることはできず、コンポーネント内では転送を繰り返すことで任意の再配置が可能になります。 これにより、初期位置とターゲット位置の間のコンポーネントの同等性が必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n + 1))
        self.size = [1] * (n + 1)

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    dsu = DSU(n)

    prime_owner = {}

    def factorize(x):
        res = []
        p = 2
        while p * p <= x:
            if x % p == 0:
                res.append(p)
                while x % p == 0:
                    x //= p
            p += 1
        if x > 1:
            res.append(x)
        return res

    for i in range(1, n + 1):
        primes = factorize(i)
        for p in primes:
            if p not in prime_owner:
                prime_owner[p] = i
            else:
                dsu.union(i, prime_owner[p])

    for i in range(1, n + 1):
        if dsu.find(i) != dsu.find(a[i - 1]):
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```DSU 構造はインデックス間の接続を維持します。 素因数分解ステップでは、gcd ベースの接続性を決定するために必要な最小の素数セットを抽出します。 マッピング prime_owner は、エッジを明示的に生成することなく、素数を共有するすべての数値が単一のコンポーネントにマージされることを保証します。 

最後のループでは、すべての項目が同じ接続コンポーネント内で初期位置から必要な最終位置まで移動可能である必要があります。 

よくある実装の落とし穴は、Python ではインデックスが 1 から始まり、配列 a が 0 から始まることを忘れることです。そのため、a[i - 1] が使用されます。

 ## 特殊なケース

 エッジケースの 1 つは、すべての数値が互いに素である場合です。 この状況では、すべてのノードが DSU 構造内で分離されているため、各位置は独自のアイテムのみを保持できます。 移動エッジが存在しないため、いかなる不一致も即座に失敗します。 素数結合が発生しないため、アルゴリズムはこれを正しく検出します。 

もう 1 つの特殊なケースは、共有された小さな素数によって数値が完全に接続された構造を形成する場合です。 たとえば、多くの偶数を含むシーケンスは 1 つのコンポーネントにマージされます。 DSU はすべての偶数インデックスをマージし、完全な再配置を可能にするため、アルゴリズムはこの大きなコンポーネント内での任意の置換を正しく許可します。 

最後の微妙なケースは、接続が間接的にのみ存在する場合です。 たとえば、数字 6、10、および 15 は、素数 2、5、および 3 を介してチェーンを形成します。一部のペアの gcd が 1 であっても、DSU はそれらを 1 つのコンポーネントにマージし、正しい移動を可能にします。
