 ## 解決策
 ## 問題の理解

 私たちは、一連の小文字のラテン文字として書かれた単語を与えられています。 トークンは最初の文字から始まり、現在の文字が単語内に何回出現するかに完全に依存する決定的なルールに従って移動します。 

トークンの下の文字が文字列内で複数回出現する場合、トークンは同じ文字の他の出現箇所にジャンプできます。 文字が 1 回だけ出現する場合、トークンは強制的に 1 ステップ右に移動します。 それがすでに最後の位置にあり、その文字が一意である場合、プロセスは終了します。 

問題は、このプロセスが常に終了するのか、それとも同じ文字間のジャンプを選択することで永遠に継続できるのかということです。 

n が 100000 までの制約は、状態を繰り返し繰り返す可能性がある場合、遷移を段階的に調査するシミュレーションは安全ではないことを意味します。 繰り返しの文字により任意のジャンプが可能になるため、このプロセスでは位置を何度も再訪することができます。そのため、状態空間は事実上、最大 100,000 のノードと同一の文字によって引き起こされる多くのエッジを含むグラフになります。 終了またはサイクル検出まで実行される単純なシミュレーションは、繰り返しの再訪により、最悪の場合、二次的な動作に低下する可能性があります。 

すべての文字が同一である場合、微妙なエッジケースが発生します。 たとえば、「aaa」のような文字列では、トークンは決定論的に進むことはなく、常に前後にジャンプして無限ループを引き起こす可能性があります。 一方、「abc」のような文字列では、すべての文字が一意であるため、トークンは常に右に移動し、すぐに終了します。 

主な困難は、プロセスを実際にシミュレートするのではなく、ジャンプ構造がいつサイクルを作成するかを認識することです。 

## アプローチ

 強引な解釈では、各位置が状態として扱われます。 位置 i から、現在の文字が複数回出現する場合、同じ文字を持つ他のすべてのインデックスへの遷移を考慮します。 それ以外の場合は、i + 1 に移動します。このプロセスは、文字列から外れるか、繰り返しが保証される構成内で以前に表示された位置に戻るまで続けられます。 

これは、ジャンプの選択を固定するとプロセスが決定的であるため、概念的には機能しますが、この問題では等しい文字の間で任意の選択が可能です。これは、プロセスが単一のパスではなく分岐システムであることを意味します。 直接シミュレーションでは、すべての可能な選択肢を探索するか、状態の暗黙的なグラフ上で訪問セットを維持する必要があります。 最悪の場合、すべてのポジションが同じキャラクターを持つ他の多くのポジションと接続する可能性があり、繰り返し再訪問すると指数関数的または二次関数的な爆発が発生する可能性があります。 

重要な点は、プロセスを進める唯一の方法は、プロセスのサフィックス動作全体で 1 回だけ出現する文字を使用することであるということです。 複数回登場するキャラクター上にトークンがある場合はいつでも、以前の出現にジャンプして以前に見た状況を再作成することを選択できます。 以前の状態に戻るこの能力は、強制的な進歩が優勢でない限り、システムが周期的であることを意味します。 

したがって、問題は、プロセスが、終了するまで決定論的な右方向への移動を強制する方法で、残りの到達可能な構造内で着地するすべてのキャラクターが一意である点に到達できるかどうかをチェックすることに帰着します。 これは頻度に関する構造的な条件に集約されます。頻度が少なくとも 2 の文字が存在する場合、ルールには無期限に以前のインデックスに戻ることを妨げるものがないため、その文字の出現の間をバウンスすることによってループを構築することが常に可能です。 

したがって、文字列内のすべての文字が異なる場合にのみ、終了が発生します。

 ## アルゴリズムのチュートリアル

 この解決策は、各文字の出現をカウントし、複数回出現する文字があるかどうかを確認することに基づいています。 

1. 文字列内のすべての文字の頻度を数えます。 これは入力に対する 1 回のパスで実行され、小文字のラテン文字のみが使用されるため、サイズ 26 の固定配列が維持されます。 このステップでは、プロセス内の構造上の曖昧さをすべて捉えます。 
2. 頻度テーブルをスキャンして、頻度が 1 より大きい文字があるかどうかを確認します。そのような文字が存在するということは、トークンが常に別の同一の文字に戻るジャンプを選択できる位置が少なくとも 1 つ存在することを意味します。 
3. いずれかの周波数が 1 を超える場合、プロセスを無限にできると結論付け、NO を出力します。 それ以外の場合、すべての周波数が正確に 1 の場合、トークンは文字列から出るまで常に右に移動するため、YES を出力します。 

### なぜ効果があるのか

 このプロセスは、文字が複数回出現する場合にのみ非決定的になります。 このようなキャラクターでは、トークンは別の同一の位置に自由にジャンプできるようになり、以前の構成に戻る能力が常に保持されます。 ポジションは有限であるため、この自由のもとで繰り返される再訪がサイクルを形成します。 文字が繰り返されない場合、すべての移動は次のインデックスに強制的に移動され、状態は終了するまで厳密に進行します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    s = input().strip()

    freq = [0] * 26
    for ch in s:
        freq[ord(ch) - ord('a')] += 1

    for c in freq:
        if c > 1:
            print("NO")
            return

    print("YES")

if __name__ == "__main__":
    solve()
```解決策は、長さと文字列を読み取ることから始まります。 頻度配列は、一定空間内の各文字の出現を追跡します。 重複のスキャンは決定的なステップです。重要なプロパティは任意の位置に分岐が存在するかどうかだけであるため、動きをシミュレートしようとするものではありません。 

小切手`c > 1`単一の繰り返し文字でも可逆的な遷移メカニズムが導入され、出現を交互に繰り返すことでトークンを無限にループさせることができるため、これで十分です。

これは、トークンが 2 つの「o」の位置の間を無限にバウンスできる直感的な動作と一致します。 

### 例 2: 「abc」

 すべてのカウントは 1 であるため、トークンは常に右方向に決定論的に移動します (0 → 1 → 2 → 終了)。 出力はYESです。

 ## 特殊なケース

 「a」のような最小限の 1 文字の文字列は一意の文字で始まるため、トークンはすぐに範囲外に移動して終了します。 頻度チェックでは繰り返しは検出されず、YES が返されます。 

「aa」のような文字列は即時非終了を示します。両方の位置が同じ文字を共有するため、トークンは移動できますが、ジャンプ先の代替出現が常に存在し、2 つのインデックス間で無限ループが可能になります。 アルゴリズムは周波数 2 に正しくフラグを立て、NO を返します。 

「abcde」のような文字列には重複が含まれないため、すべてのステップが分岐なしで右方向に強制され、文字列の終わりで終了することが保証されます。
