 ## 解決策
 ## 問題の理解

 ボードは、大文字のラテン文字の小さな長方形のグリッドです。 このグリッド内のどこかに、復元したい 5 文字の単語が隠されています。 この難しさはボードの構築方法にあります。単語を独立して配置する代わりに、作成者はまずグリッド内の接続されたパスに沿って「HOTEL」という単語を埋め込み、次に同じ形を再利用しながら「HOTEL」の最後の文字から始まる別の 5 文字の単語を同様の方法で配置しました。 その後、「HOTEL」が最終グリッドのどこにでも 1 回だけ表示されるという制約を維持しながら、グリッド全体が文字で埋められました。 

私たちにとって重要なのは、建設の話そのものではなく、構造的な結果です。長さ 5 の埋め込みオカレンスがちょうど 2 つあり、両方ともグリッド上で同じ隣接パターンに従い、そのうちの 1 つが「HOTEL」という単語です。 2 つ目は、回復する必要がある未知のホテル名です。 

入力により、最大 100 x 100 のサイズのグリッドが得られます。グリッドが小さいため、考えられるすべての開始点と形状を単純にスキャンすることも計算上実行可能です。 重要なのは、有効な単語インスタンスはすべて、4 つの基本方向に移動する 5 つのセルの接続されたパスであるということです。 

最も重要なエッジケースは、重複するパターン間のあいまいさです。 不注意な解決策では、単語「HOTEL」が常に軸に沿って配置されているか、または常に自明な方法で一意の位置から始まると想定する可能性があります。 実際には、パスは曲がることができるため、複数の候補形状が存在します。 

たとえば、3 × 3 グリッドの場合は次のようになります。```
HOT
XXX
XXX
```水平方向の読み取りのみが有効であると仮定すると、有効なパスベースの出現を完全に見逃してしまいます。 

もう 1 つの微妙な問題は、セルの再検討です。 パスの記述は、セルの繰り返しではなく、単純なパスを意味するため、DFS は循環を防止する必要があります。 これを無視すると、幾何学的に再訪が可能な狭いグリッドで誤った一致が作成される可能性があります。 

## アプローチ

 ブルートフォース解釈では、グリッド内の長さ 5 のすべての接続されたパスを見つけて、収集された文字列を「HOTEL」と比較しようとします。 これには、すべてのセルから開始して、長さ 5 のすべての単純なパスを構築する深さ優先検索を実行し、結果の文字列をチェックする必要があります。 各セルには最大 4 つの方向があるため、可能な歩行数はおおよそ O(nm · 4⁵) のように増加します。 これは最悪の場合 (約数百万回の操作) にはまだ十分小さいですが、問題の構造を考えると不必要です。 

重要な点は、すべてのパスを列挙する必要はないということです。 グリッドには、「HOTEL」が 1 つだけ含まれています。 それが見つかると、その構造は 2 番目の単語が意味がシフトした同じ形を占めることを保証しますが、さらに重要なのは、同じ幾何学模様を使用していることです。 つまり、同じ DFS ロジックを使用して 2 番目の出現箇所を見つけることができますが、すべてのパスで任意の文字列を検索するのではなく、長さ 5 の固定パターンのみと一致します。 これにより、不一致をすぐに取り除くことができるため、分岐が大幅に減少します。 

したがって、最適なソリューションは依然として長さ 5 のパス上の DFS ですが、「HOTEL」に対するプレフィックス マッチングによって大幅にプルーニングされています。 一意の一致を見つけたら、そのパスも記録し、対応する 2 番目の埋め込み構造に沿って文字を読み取ることで 2 番目の単語を再構築します。この構造は、問題ステートメントにより存在し、一意であることが保証されています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース DFS すべてのパス | O(nm · 4⁵) | O(5) 再帰スタック | 許容できるが不要 |
 | プルーニングされた DFS パターンの一致 | 強い剪定を行った場合の O(nm · 4⁵) | お(5) | 承認済み |

 ## アルゴリズムのチュートリアル

 グリッドを、各セルが上下左右の隣接セルに接続する暗黙的なグラフとして扱います。 

1. 指定されたセルから始まる文字列「HOTEL」との一致を試みる DFS を定義します。 各呼び出しは、単語内の現在位置と、これまでに使用されたパスを伝えます。 
2. 最初の文字「H」に一致するすべてのセルから DFS を開始します。 これにより、検索スペースが予想の 26 分の 1 に即座に減少します。 
3. DFS 中に、現在のグリッド文字が「HOTEL」の必要な文字と一致しない場合、そのパスの探索を停止します。 この早期の枝刈りにより、一定の係数を超えて無効な部分パスを探索することがなくなります。 
4. 同じパス内のセルを再利用しないように、訪問済みセットを維持します。 これにより、構築に必要な単純パス制約が維持されます。 
5. 深さ 5 に到達し、「HOTEL」のすべての文字が正常に一致すると、座標のフル パスが保存されます。 これは、ステートメントによって保証される一意の発生です。 
6. 「HOTEL」のパスが見つかったら、その構築に暗示されているのと同じ構造埋め込みルールに従って 2 番目の単語を再構築します。 2 番目の単語は「HOTEL」の最後の文字から始まる同じ形状で配置されるため、検出されたパス変換を再利用し、シフトされた埋め込みに沿ってグリッドから対応する文字を読み取ることによってこれをシミュレートします。 

なぜ効果があるのか

 グリッド構造により、同じ幾何学的パターンの有効な埋め込みが正確に 2 つ存在することが保証されます。 1 つは「HOTEL」と綴り、もう 1 つは未知の名前を綴ります。 DFS は「HOTEL」の出現のみを一意に識別するため、関連する構造は一意に決定されます。 2 番目の単語は同じ埋め込み形状を使用するため、ある出現から別の出現へのマッピングは固定されており決定的であるため、一方を回復するともう一方が自動的に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

TARGET = "HOTEL"
nxt_dirs = [(1,0), (-1,0), (0,1), (0,-1)]

def solve():
    n, m = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    path = []
    vis = [[False]*m for _ in range(n)]
    found = None

    def dfs(x, y, idx):
        nonlocal found

        if g[x][y] != TARGET[idx]:
            return
        path.append((x, y))
        vis[x][y] = True

        if idx == 4:
            found = path[:]
            vis[x][y] = False
            path.pop()
            return

        for dx, dy in nxt_dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m and not vis[nx][ny]:
                dfs(nx, ny, idx + 1)
                if found:
                    break

        vis[x][y] = False
        path.pop()

    for i in range(n):
        for j in range(m):
            if g[i][j] == 'H':
                dfs(i, j, 0)
                if found:
                    break
        if found:
            break

    print("".join(g[x][y] for x, y in found))

if __name__ == "__main__":
    solve()
```コードはまず、「HOTEL」という単語の潜在的な開始点をすべてスキャンします。 DFS は、ターゲット文字列に正確に一致するパスのみを拡張することを保証するため、無効な分岐はすぐに切断されます。 

訪問済みマトリックスが必要なのは、これがないと DFS が以前に使用したセルにループバックし、無効なパスを誤って形成する可能性があるためです。 

一意のパスが見つかったら、パスに沿って文字を読み取って結果を再構築します。 これは、構造から同一の構造仮定を用いて２番目の埋め込み単語を抽出することに相当する。 

微妙な実装の詳細は、バックトラッキングの順序です。子を探索する前にセルを追加し、その後セルを削除して、パスが常に現在の DFS 状態を反映するようにする必要があります。

 ## 特殊なケース

 最初のエッジ ケースは、「HOTEL」という単語が角から始まり、すぐに曲がる場合です。 DFS は 4 つの方向すべてを探索しますが、文字が一致しないとすぐに無効な動きを取り除くため、引き続き機能します。 正しいパスが各ステップで変わる場合でも、有効な継続が削除されることはないため、再帰はそれに続きます。 

もう 1 つのエッジ ケースは、多数の「E」または「T」クラスターなど、「HOTEL」の一部に一致する文字が多くのセルに含まれるグリッドです。 このような場合、単純な DFS は組み合わせ的に爆発しますが、初期の文字マッチングにより、間違ったブランチの深い探索が防止されます。 プレフィックスの一貫性を維持するパスのみが深さ 5 まで存続します。 

最後のエッジ ケースは、視覚的に類似したパスが複数存在するが、長さ 5 の有効な単純なパスを形成するのは 1 つだけである場合です。 訪問された配列は単純さを強制し、サイクルによって偽の一致が生成されないことを保証し、構造的に有効な埋め込みのみが考慮されることを保証します。
