 ## 解決策
 ## 問題の理解

 グリッドは大文字で作られたホテルの看板を表しており、隠された構造が 5 文字のホテル名を非常に特殊な幾何学的な方法で 2 回エンコードしています。 1 つのコピーでは、セルから隣接するセルへ 4 つの基本方向に移動し、長さ 5 の接続されたパスを形成して、単語「HOTEL」を綴ります。この「HOTEL」パスの最後の文字から、同じ一連の移動が繰り返されて、ホテルの実際の名前である別の 5 文字の単語が形成されます。 

グリッドには、長さ 5 の 4 方向のパスとして読み取られた場合に、単語「HOTEL」の有効な出現箇所が 1 つだけ含まれています。すべてのセルが文字で埋められている場合でも、グリッド内の他のすべての構造は無関係なフィラーです。 

タスクは、「HOTEL」と綴る固有のパスを見つけ、そのパスに沿った一連の移動を再構築し、最後のセルから同じ移動シーケンスを適用して、隠された 2 番目の単語を回復することです。 

制約は十分に小さいため、考えられるすべての 5 つの長さのパスにわたる網羅的な検索が可能です。 グリッド サイズは最大 100 x 100 なので、開始点は最大 10,000 個になります。 各開始点から深さ 4 のすべての 4 方向のパスを探索すると、最悪の場合でも数百万の状態の周囲に限定された検索空間が得られますが、これは Python で許容されます。 

単純な間違いは、「HOTEL」を途切れたパターンとして検索したり、直線のみで検索したりすることです。 単語は行、列、または対角に配置する必要はありません。 これはグリッド グラフ内のパスであり、同じ単語内のセルを再訪問することはできません。 

もう 1 つの微妙な失敗例は、「HOTEL」が複数存在する可能性があると想定していることです。 この問題では一意性が保証されており、そうでないと 2 番目の単語があいまいになってしまうため、これは不可欠です。 

## アプローチ

 ブルートフォースアプローチでは、「H」を含むすべてのセルを潜在的な開始点として扱い、深さ優先検索を実行し、隣接するセルに移動し、訪問した位置をマークすることによってシーケンス H → O → T → E → L を構築しようとします。 長さ 5 が正常に完了するたびに、候補パスが生成されます。 

これが機能するのは、パスの長さが固定されており小さいため、検索ツリーの深さは開始セルから 4 エッジのみであるためです。 ただし、枝刈りを行わないと、部分パスの数は深さとともに指数関数的に増加します。 密なグリッドでは、各ステップは最大 4 方向に分岐でき、開始セルごとに最大 4⁴ = 256 のパスが生成されます。 

重要な点は、グリッド内のすべての単語を列挙する必要はないということです。 必要なのは、有効な「HOTEL」が 1 つだけ存在することです。 これにより、正しいパスが見つかったらすぐに停止できるため、実際には指数関数的な検索の大部分が探索されるのを防ぐことができます。 

パスがわかったら、2 番目の単語は純粋にジオメトリによって決定されます。これは、最初のパスの最後のセルから適用される同じ一連の動きです。

 ## アルゴリズムのチュートリアル

 グリッドを暗黙的なグラフとしてモデル化し、各セルが上下左右の隣接セルに接続します。 「HOTEL」を綴るシンプルなパスを検索します。

1. グリッド内のすべてのセルを繰り返します。 セルに「H」が含まれる場合は、それをワード パスの潜在的な開始点として扱います。 
2. このような開始ごとに、深さ優先検索を実行して、パターン「HOTEL」を 1 文字ずつ一致させようとします。 各ステップで、次に必要な文字に一致する隣接する未訪問のセルに移動します。 
3. 同じワード パス内のセルを再利用しないように、現在のパス探索中に訪問済みセットを維持します。 これにより、任意の歩行を許可するのではなく、パス構造が強制されます。 
4. いずれかの時点で DFS が深さ 5 に達し、「HOTEL」と正常に一致した場合は、このパスを形成する一連の座標を保存し、検索を直ちに終了します。 この問題により、そのようなパスが 1 つだけ存在することが保証されます。 
5. 見つかったパス内の連続する点間の方向デルタを計算します。 これらのデルタは、文字が空間的にどのように配置されるかを表します。 
6. HOTEL パスの最後のセルから開始して、これらのデルタを繰り返し適用して、さらに 4 つの位置を生成します。 これらの位置にある文字を集めて、隠されたホテル名を形成します。 

重要な考え方は、2 番目の単語は独立して検索されないということです。 これは、最初の単語の幾何学的形状を翻訳することによって完全に決定されます。 

### なぜ効果があるのか

 DFS は、すべての「H」から始まる長さ 5 の有効な単純なパスのセットを正確に探索します。 すべてのステップで文字の一致を強制するため、「HOTEL」を綴るパスのみがさらに探索されます。 一意性により、完全なパスが 1 つだけ存在することが保証されるため、最初に一致したものが正しいものになります。 翻訳ステップでは相対的な構造が保持されるため、最後のセルから同一の移動ベクトルを適用すると、曖昧さなく 2 番目の単語が再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())
grid = [input().strip() for _ in range(n)]

target = "HOTEL"
dirs = [(1, 0), (-1, 0), (0, 1), (0, -1)]

path = None

def dfs(x, y, idx, cur_path, vis):
    global path
    if path is not None:
        return
    if grid[x][y] != target[idx]:
        return
    cur_path.append((x, y))
    vis.add((x, y))

    if idx == 4:
        path = cur_path[:]
        vis.remove((x, y))
        cur_path.pop()
        return

    for dx, dy in dirs:
        nx, ny = x + dx, y + dy
        if 0 <= nx < n and 0 <= ny < m and (nx, ny) not in vis:
            dfs(nx, ny, idx + 1, cur_path, vis)
            if path is not None:
                break

    vis.remove((x, y))
    cur_path.pop()

for i in range(n):
    for j in range(m):
        if grid[i][j] == 'H':
            dfs(i, j, 0, [], set())
            if path is not None:
                break
    if path is not None:
        break

p = path

deltas = []
for i in range(1, 5):
    dx = p[i][0] - p[i - 1][0]
    dy = p[i][1] - p[i - 1][1]
    deltas.append((dx, dy))

x, y = p[-1]
res = [grid[x][y]]

for dx, dy in deltas:
    x += dx
    y += dy
    res.append(grid[x][y])

print("".join(res))
```DFS セクションは、「HOTEL」の唯一有効な幾何学的スペルを再構築する責任を負います。 訪問済みセットがないと、検索でセルが再訪問され、意図したパス構造に対応しない無効なウォークが形成される可能性があるため、訪問済みセットは不可欠です。 

デルタの抽出により、単語の形状が一連の動きとしてエンコードされます。 これが重要な抽象化です。形状が判明すると、2 番目の単語は、別のアンカー ポイントから始まるその形状の単なる翻訳になります。 

境界チェックにより、同じ変位シーケンスを適用するときにグリッドの外に出ないことが保証されます。

    grid = [input().strip() for _ in range(n)]

        nonlocal path
        if path is not None:

        if grid[x][y] != target[idx]:

                    if path is not None:
                        break

        for j in range(m):

 ## 特殊なケース

 HOTEL パスがグリッドの境界近くにある場合、微妙なエッジ ケースが発生します。 2 番目のワードは同じ移動ベクトル シーケンスを再利用するため、問題の制約によって慎重に保証されていない場合、境界を外れてしまう可能性があります。 DFS は、境界内で完全に有効な HOTEL パスのみを受け入れることを保証し、構造の定義方法により、同じ保証が変換されたパスにも暗黙的に適用されます。 

もう 1 つのエッジ ケースは、「HOTEL」の部分プレフィックスがグリッド内に複数存在するが、正常に完了するのは 1 つだけである場合です。 単純な解決策では、最初に一致するプレフィックスで停止する可能性がありますが、正確にするには、パスを受け入れる前に完全な深さ 5 に到達する必要があります。 DFS は完全一致を明示的に強制するため、完全な単語に正しく拡張されない限り、部分一致は無視されます。
