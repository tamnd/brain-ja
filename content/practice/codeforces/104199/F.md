 ## 問題の理解

 私たちは持っています$n$1 から 2 までの番号が付けられた部屋の列に並んでいる友人たち$n$。 各友人は最初、他の 1 人の友人に配送する必要があるパッケージを保持しており、すべての友人が送信者であると同時に受信者でもあります。 したがって、データは有向グラフを記述します。$n$すべてのノードが出力エッジを 1 つだけ持つノード。 

床下には部屋に合わせてコンベアシステムがありますが、建物の設置面積よりも長いです。 それは持っています$3n$ポジション:$n$位置は最初の部屋の左側に広がります。$n$位置は部屋の真下にあり、$n$ポジションが右に伸びます。 グローバル シフト操作は、すべてのパッケージを左または右に 1 つの位置に移動します。 荷物は、ある瞬間、目的地の友人の部屋の真下に置かれたときに配達されたとみなされます。 

目標は、一連の左右のシフトを適用して、すべての荷物がコンベア範囲を決して離れることなく、少なくとも 1 回は目的の位置に到達するようにすることです。 

重要な点は、各パッケージが同期して移動することです。 アイテムを個別にルーティングするのではなく、すべてのパッケージをまとめて含む厳密なラインを移動します。 これにより、問題は、各ソース位置をそのターゲット位置に少なくとも 1 回同時に位置合わせする一連のグローバル変換を見つけることに変換されます。 

制約$n \le 100{,}000$これは、どのような解も本質的に線形または線形に近いものでなければならないことを意味します。 友人のペアに対する二次推論は、すぐに遅すぎます。 すべてのシフトやペア間のすべての相互作用をシミュレートしようとするアプローチは失敗します。 

微妙なエッジ ケースは、複数のパッケージを個別に扱うと、互換性のないシフトが必要になる可能性があることです。 たとえば、1 が 2 に送信し、2 が 1 に送信する場合、一方のパッケージは位置合わせに右シフトが必要で、もう一方のパッケージは左シフトが必要であるため、単純なエッジごとの位置合わせは機能しません。 

もう 1 つの重要なケースは、2 より長い循環構造です。この場合、最適なシフトでは各エッジを個別に処理するのではなく、中間のアライメントを再利用する必要があります。 1 つのペアを満たすためにシフトすると他のペアのアライメントが破壊される可能性があるため、貪欲なローカル アライメント アプローチはここで中断されます。 

## アプローチ

 強引なアイデアは、時間の経過とともに考えられるすべてのコンベヤーのシフトをシミュレーションし、すべての荷物が目的地にいつ揃うかを確認することです。 コンベアが付いているので、$3n$位置、各シフトは単位移動であり、合計変位範囲は$O(n)$、可能な状態の数はすでに$O(n)$、各州ではすべてをチェックする必要があります$n$パッケージ。 これは次のことにつながります$O(n^2)$または、動作が遅すぎて、$n = 10^5$。 

重要な構造的洞察は、絶対的な位置の観点から考えるのをやめ、代わりにソースと目的地の間の相対的な変位に注目することです。 各パッケージ$i$位置がずれてしまうような変化を経験しなければならない$i$位置を決める$a_i$。 この要件は、いつか世界的な変化が起こると言っているのと同じです。$a_i - i$。 

したがって、すべてのパッケージはグローバル シフト値に制約を課します。 私たちはそれらを永久に同時に満足させようとするのではなく、パッケージごとに少なくとも 1 回だけ満足させます。 これにより、問題は、コンベアを左右に動かすときに通過しなければならない異なるシフト値の数を分析することになります。 

重要な単純化は、最適な戦略のシフト値が単調であることです。 左端の必要なシフトから右端の必要なシフトに移動するだけでよく、その間のすべての整数シフトは連続した移動によって実現できます。 総コストは、通過する必要がある間隔のサイズに、サイクルによって引き起こされるラップ状の構造により制約が単一の間隔内で接続されていない場合に必要な追加の移動を加えたものになります。 

問題を、必要なシフトをすべて収集することに変換します。$d_i = a_i - i$次に、0 から始まり、左または右に移動できる整数線上の 1 回の歩行で、これらすべての値を訪問するのに必要なユニットの最小移動数を計算します。ただし、その範囲内で落下を防止します。$3n$コンベア。 コンベアの幅が十分に広いため、境界は漸近的に結合しません。 実現可能性を保証するだけです。

 ## アルゴリズムのチュートリアル

 ### 重要なアイデア

 それぞれの友達$i$ある時点でコンベヤーがシフトする必要があります$x$満足する$i + x = a_i$、 それで$x = a_i - i$。 したがって、問題を必要なシフト値をすべて訪問することに集約します。 

### ステップ

 1. 一連の変位要件を計算する$d_i = a_i - i$みんなのために$i$。 

これは「いつパッケージを実行するか」を変換します。$i$揃える？」 グローバル シフトで単一の整数条件に変換されます。 
2. すべての値を並べ替えます。$d_i$。 

ソートにより、整数行上の必要な位置合わせの幾何学的構造が明らかになります。 
3. 並べ替えられた値を数直線上の点として扱い、0 から開始してすべての値を訪問する最小ウォークを計算します。 

最適なウォークは、まず一方の極値に向かって進み、次にもう一方の極値に向かって進みます。 
4. 0 から始まる点が点のクラスターの左側にあるのか右側にあるのかを判断し、最も近い端点までの距離を計算して、全スパン長を加算します。 

これは、必要な状態のすべてを処理する前に、まず必要な状態のセットに到達する必要があるという事実を説明しています。 
5. 合計距離を答えとして返します。 

重要な実装の詳細は、単調掃引中に中間値が訪問されるため、答えはセットの最小値と最大値、および 0 から最も近い辺までの距離のみに依存するということです。 

### なぜ効果があるのか

 すべての制約は単一のグローバル変数に対する等価性です$x$。 各パッケージは、必要な値を 1 つだけ提供します。$x$成功とは、そのようなすべての値を少なくとも 1 回訪問することを意味します。 有効な一連の移動は整数線上の歩行に対応し、移動コストは変位において線形であるため、値を再検討してもコスト削減には役立ちません。 したがって、最適な戦略は常に、開始点 0 を含むように拡張された、必要な点の凸包をカバーする最短パスになります。これにより、総移動量を削減できる代替順序がないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    d = [a[i] - (i + 1) for i in range(n)]
    d.sort()
    
    # include starting point 0
    left = min(d[0], 0)
    right = max(d[-1], 0)
    
    # we must cover full interval
    print(right - left)

if __name__ == "__main__":
    solve()
```中心となる変換はディスプレイスメント配列を計算することです$d_i$。 これは、グラフ構造がエンコードされる唯一の場所です。 その後はすべて、問題を 1 次元区間の問題に還元します。 

並べ替えは極値を特定するためにのみ使用されますが、実際には、最終的な式にとって重要なのは最小値と最大値だけです。 この実装では、明確さと安全性のためにソートを使用していますが、線形スキャンに減らすこともできます。 

コンベアはシフトなしで開始するため、0 を含めることは必須です。 これを考慮しないと、計算された間隔は、必要な領域内で開始すると誤って仮定することになります。
