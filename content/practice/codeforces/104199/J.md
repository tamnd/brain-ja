 ## 解決策
 ## 問題の理解

 私たちには一列の猫が与えられており、それぞれの猫が自分専用のボウルから食事をすると、一定の「幸福度寄与」が与えられます。 何匹でも使用できる共有ボウルも1つあります。 猫が自分のボウルを使用する場合、それはその価値に貢献しますが、そうでない場合は、何も貢献しません。 

一部の猫には追加の行動があります。猫 i がプッシュとしてマークされている場合、猫 i と猫 i+1 の両方が個人のボウルから食べると、合計幸福度にペナルティが適用されます。 このペナルティは、問題のあるペアごとに 1 回減算されます。 ただし、猫 i または猫 i+1 を共有ボウルに送信することで各ペナルティを回避することができ、事実上相互作用を中断できますが、その猫の貢献を失うという代償を伴います。 

したがって、各猫は、個人のボウル (その価値を維持する) か、共有のボウル (貢献度ゼロ) の二者択一の決定をします。 最終スコアは、選択された値の合計から、両方のエンドポイントが選択されたアクティブな「不良エッジ」ごとのペナルティを差し引いたものです。 

n ≤ 10^6 という制約により、線形または線形に近い解が強制されます。 すべてのサブセット、さらにはすべてのサブセットにわたる動的状態をチェックすると爆発的に増加するため、隣接するペアに対する二次関数を実行することは直ちに不可能になります。 

微妙な落とし穴は、各ペナルティが独立しており、2 つの猫のうち小さい方を削除することで貪欲に処理できると仮定していることです。 これは失敗します。猫が複数のエッジに参加している場合、1 匹の猫を削除すると複数のペナルティが同時に解除される可能性があるためです。 

別の失敗例は、ペナルティを選択から独立したものとして扱い、単純にすべての q_i を減算することです。 これは、すべての猫が個人用のボウルから食事をすることを前提としていますが、これは必ずしも最適ではありません。 

小さな具体的な罠は、ペナルティが重なった場合です。 

入力:```
3
10 10 10
2
1 100
2 100
```単純にすべての猫を取得すると 30 − 200 = −170 になりますが、中央の猫を削除するのが最適で、20 が得られます。 

これは、ローカルで貪欲な決定ではなく、グローバルな構造が必要であることを示しています。 

## アプローチ

 構造を無視するなら、個人のボウルから食事をする猫のすべてのサブセットを試してみることになります。 各サブセットでは、すべてのペナルティをチェックし、寄与を合計して O(2^n) 状態を与える必要がありますが、これは n = 30 の場合でも不可能です。 

より構造化されたビューは、各猫を折れ線グラフのノードとして解釈し、各ペナルティを i と i+1 の間のエッジとして解釈することです。 両方のエンドポイントが選択されている場合、ノードの重みからエッジ コストを差し引いた値を最大化するノードのサブセットを選択したいと考えています。 

これは、パス上の古典的な「エッジ ペナルティを伴う最大ウェイト独立セット」ですが、一工夫あります。ノードを削除すると、そのウェイトとすべてのインシデント ペナルティも削除されます。 これは、プレフィックス上の DP を示唆しています。 

各位置 i では、i−1 が選択されたかどうかだけを知る必要があります。 それは、すべての相互作用が隣接するペアに対してローカルであるためです。 これにより、問題は回線上の 2 状態の DP に縮小されます。 

i が選択されていない場合は dp0 を i までの最良の値とし、i が選択されている場合は dp1 とします。 遷移は、i-1 とエッジ (i-1, i) が存在するかどうかのみに依存します。 

i が選択されている場合は、a_i を追加します。 i−1 と i の両方が選択された場合、そのようなペナルティが存在する場合は q_{i−1} を減算します。 

これにより、指数関数的な選択が線形遷移に変換されます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | DPオンライン | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、ペナルティ情報を配列cost[i]に圧縮します。これは、iとi+1の間のペナルティ、または存在しない場合はゼロを意味します。 これにより、遷移が一定時間になります。 

次に、左から右にスキャンしながら 2 つの DP 状態を計算します。 

1. dp0 = 0、dp1 = a1 に初期化します。 これは、最初の猫の場合、私たちがそれをスキップするか、または受け入れるかのどちらかを反映しています。 
2. 2 から n までの各 i について、以前の状態に基づいて新しい状態を計算します。 dp0 と dp1 について 2 つのケースを考えます。 
3. 位置 i の dp0 の場合、cat i が共有ボウルに送信されます。 その場合、私は何も貢献せず、以前の状態の最良のものを取得します。 したがって、dp0 は max(dp0_prev, dp1_prev) になります。 これは、i を削除しても過去のペナルティには影響しないことを示しています。 
4. 位置 i の dp1 については、cat i が選択されます。 i−1 が選択されたかどうかに関係なく i が選択されるため、考えられる両方の前の状態に a_i を追加します。 
5. 前の状態でも i-1 が選択されていた場合、不良エッジがアクティブになるため、cost[i-1] を減算する必要があります。 これは dp1_prev から移行する場合にのみ適用されます。 
6. すべての i を処理すると、答えは max(dp0, dp1) になります。 

### なぜ効果があるのか

 ペナルティは隣接するインデックス間にのみ存在するため、DP 状態は前の猫が選択されたかどうかを記憶するだけで済みます。 以前の決定は、前のノードが選択されたかどうかを除いて、将来のペナルティに影響を与えることはできません。 これにより、2 状態システム上でマルコフ プロパティが形成され、完全なサブセットを追跡することなく、すべての構成が正しく表現されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

m = int(input())
cost = [0] * n
for _ in range(m):
    k, q = map(int, input().split())
    cost[k - 1] = q

dp0 = 0
dp1 = a[0]

for i in range(1, n):
    new0 = max(dp0, dp1)

    # take i
    take_from0 = dp0 + a[i]
    take_from1 = dp1 + a[i] - cost[i - 1]

    new1 = max(take_from0, take_from1)

    dp0, dp1 = new0, new1

print(max(dp0, dp1))
```DP 配列は一定のサイズに保たれ、前のステップのみを保存します。 重要な実装の詳細は、選択された前の状態から選択された現在の状態に遷移する場合にのみペナルティが適用されるということです。 

コスト配列には、i-1 と i の間のエッジを表すために i-1 によってインデックスが付けられ、隣接リストやハッシュの必要性が回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    m = int(input())
    cost = [0] * n
    for _ in range(m):
        k, q = map(int, input().split())
        cost[k - 1] = q

    dp0 = 0
    dp1 = a[0]

    for i in range(1, n):
        new0 = max(dp0, dp1)
        take0 = dp0 + a[i]
        take1 = dp1 + a[i] - cost[i - 1]
        new1 = max(take0, take1)
        dp0, dp1 = new0, new1

    return str(max(dp0, dp1))

 ## 特殊なケース

 主なエッジケースは、すべての猫がペナルティによって接続され、まばらな選択が強制される場合です。 隣接ノードの選択はコストが高すぎるため、DP は必要に応じて dp0 遷移を自然に優先することでこれを処理します。 

もう1つのケースは、個別のペナルティです。 各ペナルティはエッジごとに保存されるため、アルゴリズムは両方のエンドポイントが選択された場合にのみペナルティを正しく適用し、複数のエッジが存在する場合でも二重カウントを回避します。 

最後に、n = 1 の場合、遷移はなく、dp1 はその値に初期化され始め、それを変更するペナルティが存在しないため、答えは正しく a1 のままです。
