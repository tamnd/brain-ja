 ## 問題の理解

 私たちは、理想的なプランで各部屋に必要な数の椅子を備えたいくつかの部屋のあるホテルを与えられました。 実際、ホテルには合計で$N$複数の場所に配置する必要がある椅子$K$部屋。 制約は単に「目標に一致する」ということではありません。すべての部屋に少なくとも 1 つの椅子を設置する必要があり、理想的な要件と比較して各部屋に不足している椅子の数として定義される不足量がすべての部屋で同一でなければなりません。 

したがって、部屋がもともと期待していた場合、$a_i$椅子と私たちは置きます$x_i$椅子、それから$x_i \ge 1$そしてすべての価値観$a_i - x_i$同じ定数でなければなりません$d$、すべての部屋で共有されます。 つまり、どの部屋も均一に満たされていない状態になります。$d$、各部屋に少なくとも 1 つの椅子があることを尊重しながら。 

目標は、有効なユニフォーム不足を選択することです$d$そして、それを満たす椅子の配分を行いながら、使用されない椅子の数を最大化します。 同様に、配置する椅子の数も最小限に抑えたいと考えています。 

制約が大きいのは、$N$しかし適度に$K$。 以来$K$まで行くことができます$10^5$、どのような解も線形またはほぼ線形でなければなりません。$K$。 考えられる不足をすべて試したり、候補者ごとに椅子を繰り返し再配分したりするソリューションは、コストがかかる場合には遅すぎます。$O(K^2)$あるいはさらに悪いことに。 

いくつかの部屋の収容人数が非常に小さい場合、重要な隠れたエッジケースが現れます。 部屋にある場合$a_i = 1$の場合、唯一の有効な割り当ては強制的に$x_i = 1$したがって、その部屋の不足はゼロに固定され、世界的な不足が抑制されます。 すべての部屋が均一に大きな赤字を共有できると仮定する素朴な試みは、ここですぐに破綻します。 

## アプローチ

 問題を考える直接的な方法は、一般的な不足を推測することです$d$。 直したら$d$、その後、各部屋が受信する必要があります$x_i = a_i - d$椅子。 これにより、直ちに 2 つの実現可能条件が課せられます。$x_i \ge 1$、 それで$d \le a_i - 1$すべての部屋、つまり$d \le \min(a_i) - 1$。 次に、使用する椅子の総数は正確に指定する必要があります。$\sum (a_i - d)$に等しい$\sum a_i - Kd$を超えてはなりません。$N$。 

したがって、固定の場合$d$、実現可能性は、次のことを確認することに帰着します。$Kd \ge \sum a_i - N$。 構造が単調になる：増加する$d$使用する椅子の数が減り、予算内に収まりやすくなりますが、部屋の最小サイズにも制限されます。 

ブルートフォースアプローチでは、考えられるすべての値を試します。$d$から$0$まで$\min(a_i) - 1$、毎回必要な椅子の合計を計算し、最適な実現可能な構成を追跡します。 各小切手にかかる費用$O(K)$、最大で$1000$異なる価値観$d$、おおよそにつながります$10^8$最悪の場合の運用。 それは境界線にありますが、不要です。 

重要な観察は、実現可能性は次の線形式のみに依存するということです。$d$。 繰り返す代わりに$d$、有効な最大値を計算できます。$d$算術制約を直接使用する場合:$$Kd \le \sum a_i - N$$そして$$d \le \min(a_i) - 1.$$したがって、最適な$d$は、これら 2 つの上限の最小値です。 

一度$d$が固定されている場合、実際に配置される椅子の数は強制されるため、保存される椅子の数は単純に$N - \sum (a_i - d)$、または同等の$N - (\sum a_i - Kd)$。 

これにより、問題全体が配列に対するいくつかの集計の計算に軽減されます。

 ## アルゴリズムのチュートリアル

 ### 1. グローバル統計を計算する

 すべての部屋の収容人数の合計と、その中の最小収容人数を計算します。 これら 2 つの値は、均一な不足の実現可能性を完全に制御します。 

合計は理想的な構成で存在する椅子の数を決定し、最小値は「部屋ごとに少なくとも 1 つの椅子」という制約に違反することなく最大許容される均一な不足を決定します。 

### 2. 予算から不足の可能性がある最大値を導き出す

 合計使用量の制約を次のように書き換えます。$$\sum a_i - Kd \le N$$これは次のようになります:$$d \ge \frac{\sum a_i - N}{K}$$ただし、実現可能性と最大限の節約が必要なため、代わりに最大の値を計算します。$d$これはこの不等式に違反しません。$$d \le \frac{\sum a_i - N}{K}$$この値の下限を取得します。$d$整数でなければなりません。 

### 3. 部屋ごとの実現可能性制約を適用する

 各部屋には少なくとも 1 つの椅子を設置する必要があるため、次のようになります。$$a_i - d \ge 1 \Rightarrow d \le a_i - 1$$最も厳しい制約は最も小さな部屋から得られるため、次のようになります。$$d \le \min(a_i) - 1$$### 4. 制約を結合する

 有効な$d$予算由来の限界と構造的限界の最小値です。 また、$d \ge 0$。 

### 5. 最終的な答えを計算する

 一度$d$は固定されており、配置された椅子の総数は$\sum a_i - Kd$。 保存された椅子は次のとおりです。$$N - (\sum a_i - Kd)$$### なぜ効果があるのか

 重要な不変条件は、有効な構成は単一の整数の選択に対応するということです。$d$すべての部屋の割り当てが正確になるように、$a_i - d$。 条件により同一の欠陥が強制されるため、部屋を個別に変更する自由はありません。 これにより、検索スペースが減少します。$K$- 単一のスカラー パラメーターへの次元の割り当て。 あらゆる実現可能な解決策は、いくつかの要素によって一意に表現されます。$d$、およびすべての有効な$d$有効な構成が生成されるため、最適化を行う$d$すべての割り当てを最適化することと同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    total = sum(a)
    mn = min(a)
    
    # upper bound from "at least one chair per room"
    d1 = mn - 1
    
    # upper bound from total chairs constraint
    d2 = (total - n) // k
    
    d = min(d1, d2)
    if d < 0:
        d = 0
    
    used = total - k * d
    print(n - used)

if __name__ == "__main__":
    solve()
```実装はまず入力を読み取り、部屋全体の 1 回のパスで集計値を計算します。 値`d1`以上を減算するため、部屋が空にならないように強制します。`a_i - 1`最小制約に違反します。 値`d2`割り当てられる椅子の総数が、一律の不足額で表した場合に利用可能な供給量を超えないよう強制します。 

実現可能な最善のものを選択した後、`d`、実際に使用されている椅子の数を計算します。 最後の答えは、入手可能な椅子と中古の椅子の違いです。 

微妙なポイントはクランプです`d`ゼロに。 これがないと、次のようなケースが発生します。`total < n`たとえ不足が有意義に適用できないとしても、マイナスの赤字が生じることになります。

 ## 特殊なケース

 部屋が 1 つしかない場合、条件によりすべての椅子がその部屋に強制的に配置されるため、そうでない限り保存はできません。$N$容量制限構造が許容する容量を超えています。 アルゴリズムは計算します$d1 = a_1 - 1$そして$d2 = (a_1 - N)$、実行可能な値に正しくクランプされ、一貫した配置が得られます。 

すべての部屋の収容人数が同一の場合、最小制約が支配的な要因となり、一律の不足を増やそうとする試みは直ちに制限されます。 このアルゴリズムは、議長の予算の合計が理想的な合計を上回っているか下回っているかをチェックすることに帰着し、計算された$d$そのバランスを正しく反映しています。 

1 つの部屋の収容人数が 1 のように非常に小さい場合、$d = 0$、赤字は許されないので。 アルゴリズムはこれを次のように捉えます。$d1 = 0$、他のすべての計算が特別なケースを使用せずに最も厳しい構造的制約を遵守するようにします。
