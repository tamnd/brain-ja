 ## 問題の理解

 あります$n$キッチンにはさまざまなスパイスがあり、それぞれが名前で識別されます。 毎日の料理は正確に選んで調理されます$m$それぞれ異なるスパイスが使われていますが、どれが選ばれたのかはわかりません。 

私たちには、1 つの重要な観察結果が与えられました。それは、既知の一連のアレルギーに対してアレルギーを持っているヘルパーシェフです。$k$スパイスを使用しており、すでに料理を味わっており、アレルギー反応はありませんでした。 これにより、未知の料理構成が制約されます。選択された料理のどれもありません。$m$スパイスはヘルパーのアレルギーセットに属する可能性があります。 

つまり、皿はサイズの未知の部分集合であるということになります。$m$ただし、ヘルパーにとって安全なスパイスのみを使用します。 

今、私たちに与えられたのは$p$ゲスト。 各ゲストは独自のアレルギーリストを持っています。 私たちはゲストごとに、その料理がアレルギーを引き起こす可能性があるかどうかについて結論を下す必要があります。 実際の料理は一意に知られていないため、ヘルパーの観察と一致するすべての有効な料理を推論します。 

ゲストごとに 3 つの結果が考えられます。 すべての有効な料理がすべてのアレルゲンを回避している場合、答えは「いいえ」です。つまり、その料理は彼らにとって安全であることが保証されています。 すべての有効な料理に必ず少なくとも 1 つのアレルゲンが含まれている場合、答えは「はい」です。これは、その料理が確実に反応を引き起こすことを意味します。 それ以外の場合は、未知の処理の方法に応じて、両方の結果が発生する可能性があります。$m$-subset が選択されているため、答えは「MAYBE」です。 

制約$n \le 100$、$p \le 100$、および文字列の小さなセットは、単純なカウントとハッシュを超えた漸近的な複雑さを心配することなく、セットベースの推論、さらにはクエリごとの再計算を行うことができることを示唆しています。 

微妙な点は、ヘルパーのテストでは一部のスパイスが考慮から完全に削除されていることです。 アレルギーリストに記載されているスパイスは料理に含まれないことが保証されているため、削除されたスパイスとのみ重複するゲストのアレルギーは無関係になります。 

もう 1 つのよくある落とし穴は、有効なスパイスの世界を限定せずに、各ゲストを独立して扱うことです。 皿はサイズのサブセットではありません$m$全員から$n$スパイスを使用しますが、ヘルパーのアレルギーセットに含まれていないもののみを使用します。 

## アプローチ

 強引な解釈では、考えられるすべての有効な料理を列挙することになります。まず、ヘルパーのアレルギーのあるスパイスをフィルターで除外し、次にそれらのすべての組み合わせを生成します。$m$残りのセットからスパイスを選択し、ゲストごとに、それらの組み合わせのいずれかがアレルギー リストと一致するかどうかを確認します。 これはすぐに実行不可能になります。$n = 100$、組み合わせの数$\binom{100}{50}$は天文学的に大きいため、最大 100 人のゲストに対してチェックを繰り返すことになります。 

重要な観察は、ディッシュを明示的に構築する必要がまったくないということです。 有効な料理はすべて単にすべてです$m$- サイズが固定された縮小宇宙のサブセット$n - k$。 特定のゲストにとって、構造上の特性は 2 つだけです。それは、アレルギー セットに含まれていない許可されているスパイスがいくつ存在するか、そして、ゲストのアレルギー スパイスがそもそも料理に使用される資格があるかどうかです。 

各ゲストのアレルギー設定と安全な世界を交差させると、すべてが単純なカウントに減ります。 私たちは、そのゲストに「危険だが可能性がある」スパイスがどれだけ存在するかを追跡するだけです。

 ## アルゴリズムのチュートリアル

 ヘルパーのアレルギーのあるスパイスを禁止セットとして定義しましょう。 有効なスパイスの世界は、これらの禁止品を除くすべてです。 

各ゲストのアレルギー リスト内のスパイスを 2 つのカテゴリに分類します。有効な世界にまだ存在するものと、ヘルパーの制約によってすでに除外されているものです。 最初のカテゴリのみが答えに影響します。 

1. スパイス名からインデックスへのマッピングを構築して、文字列ではなくセットを効率的に操作できるようにします。 これにより、メンバーシップを定期的にチェックできるようになります。 
2. ヘルパーのアレルギーセットを読み、これらすべてのスパイスを禁止としてマークします。 有効なユニバースは、このセットに含まれていないすべてのスパイスであり、そのサイズは次のとおりです。$N' = n - k$。 
3. ゲストごとに、アレルギーのあるスパイスが有効な世界にいくつ残っているかを数えます。 この値を呼び出します$x$。 これは、実際に料理に含まれていてもそれらを引き起こす可能性のあるスパイスの数を表します。 
4. このゲストにとって安全なスパイスが宇宙にいくつ残っているかを計算します。$N' - x$。 アレルギー反応を起こすことなく料理に使用できるスパイスです。 
5. もし$x = 0$の場合、有効な料理にはゲストのアレルゲンは一切含まれません。 有効な料理はどれもそれらを避けているので、答えは「ノー」です。 
6. それ以外の場合、$N' - x < m$、それなら選ぶのは不可能です$m$少なくとも1つのアレルゲンを含まないスパイス。 すべての有効な料理には、彼らにとって危険なものが含まれている必要があります。したがって、答えは「はい」です。 
7. 残りのすべてのケースでは、完全に安全な選択と危険な選択の両方が存在するため、答えは「おそらく」です。 

### なぜ効果があるのか

 有効な料理はすべて均一です$m$- サイズが固定された世界のサブセット$N'$。 ゲストが特定の料理でのアレルギー反応を避ける唯一の方法は、選択した料理の一部がすべての料理を避ける場合です。$x$まだ存在する可能性のあるアレルゲンについて。 これが常に可能かどうかは、少なくとも$m$アレルギー対応の調味料をご用意しております。 以下の場合は、$m$、すべてのサブセットには少なくとも 1 つのアレルゲンが含まれている必要があります。 何もない場合は、すべてのサブセットがそれらを回避します。 それ以外の場合は両方の構造が存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
k = int(input())

all_spices = set()
bad = set()

for _ in range(k):
    bad.add(input().strip())

p = int(input())

for _ in range(p):
    ni = int(input())
    guest = set()
    for _ in range(ni):
        guest.add(input().strip())

    # compute intersection with helper-banned set
    # and compute effective dangerous spices
    x = 0
    for s in guest:
        if s not in bad:
            x += 1

    # actually x = |guest ∩ safe|, but we want safe allergens count
    # recompute properly:
    x = len([s for s in guest if s not in bad])

    safe_pool_size = n - k
    safe_non_guest = safe_pool_size - x

    if x == 0:
        print("NO")
    elif safe_non_guest < m:
        print("YES")
    else:
        print("MAYBE")
```実装は、ヘルパーのアレルギー リストを読み取り、それを禁止されたフィルターとして扱うことから始まります。 各ゲストは、フィルターを通過したアレルゲンの数を数えることによって個別に処理されます。 

変数$x$ゲストのアレルゲンのうち、料理に含まれる可能性のあるものがどれだけあるかを表します。 それが分かれば、残りの推論は、使用可能な安全なスパイスの数と必要な皿のサイズの単純な比較に集約されます。$m$。 

分岐順序が重要です。 「いいえ」のケースは、組み合わせ論に関係なく、ゲストが影響を受けることが構造的に不可能であることを表すため、最初にチェックする必要があります。 「YES」のケースは、残りの安全なプールに関する鳩の穴の議論から導き出されます。 それ以外はすべて混合ケースです。

 ## 特殊なケース

 ゲストのすべてのアレルゲンがヘルパーの禁止セットに含まれている場合、ゲストのアレルギー リスト全体が事実上考慮から除外されます。 その状況では、料理の世界にはトリガーとなるスパイスが含まれていないため、有効な料理はすべて自動的にそれらを回避します。 アルゴリズムはこれを次のように捉えます。$x = 0$、組み合わせ推論なしですぐに「NO」を出します。 

ゲストのアレルギーセット以外の安全なスパイスの数が少なすぎて料理のサイズを満たすことができない場合$m$、すべての有効な選択には、少なくとも 1 つのアレルゲンが含まれている必要があります。 計算$N' - x < m$は、この強制的な包含シナリオを直接特定し、アレルゲンがまばらに分布している場合でも「YES」を保証します。 

両方の条件が満たされない場合でも、ゲストを完全に避ける有効な料理と、少なくとも 1 つのアレルゲンを含む別の料理を構築するのに十分な柔軟性が存在します。 アルゴリズムはこれを「MAYBE」として分類し、制約されたユニバース内で実行可能な両方の組み合わせ構造が共存することを反映しています。
