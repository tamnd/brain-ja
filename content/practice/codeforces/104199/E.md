 ## 解決策
 ## 問題の理解

 レストランのキッチンで使用できる一連のスパイスの名前と、サイズが固定された 1 つの皿が与えられています。`m`フルセットの中から選んだスパイス`n`スパイス。 その料理にどのスパイスが入っているのかはわかりませんが、正確に含まれているということだけがわかります。`m`個性的なスパイス。 

調理助手がその料理をテストしたところ、アレルギー反応は出ませんでした。 このことから分かることはただ 1 つだけです。彼がアレルギーを持っているスパイスは、選ばれた人々の中に存在し得ないということです。`m`スパイス。 

その後、複数のゲストが与えられます。 各ゲストはアレルギーのあるスパイスの独自のリストを持っています。 ゲストごとに、アシスタントの観察と一致する可能性のあるすべての有効な料理に基づいて、ゲストが間違いなく反応するか、間違いなく安全であるか、それとも曖昧であるかを判断する必要があります。 

言い換えれば、サイズのすべてのサブセットを推論します。`m`から`n`アシスタントのアレルギーセットを避けるスパイス。 ゲストごとに、そのようなすべての有効なサブセットに少なくとも 1 つのアレルゲンが必ず含まれるかどうか、アレルゲンを含むものが存在しないかどうか、または両方の可能性が存在するかどうかを確認します。 

ゲストごとの出力は次のとおりです。`YES`すべての有効な料理に少なくとも 1 つのアレルゲンが含まれていなければならない場合、`NO`有効な料理にアレルゲンが含まれていない場合、および`MAYBE`料理の選び方によっては両方の状況が可能である場合。 

制約`n ≤ 100`そして`p ≤ 100`これは、集合演算を自由に操作でき、スパイスを使用して組み合わせ推論やビットマスクのような表現を考慮することさえできることを意味します。 サイズのすべてのサブセットを列挙することに依存するソリューション`m`までが含まれるでしょう`C(100, 50)`実現不可能な可能性。 問題の構造は、料理の列挙を避け、代わりにセット間の重複について推論する必要があることを強く示唆しています。 

ゲストにアレルゲンがまったくない場合、微妙なケースが発生します。 その場合、どんな料理であっても、答えはこうでなければなりません。`NO`彼らには反応する方法がないからです。 もう 1 つのエッジ ケースは、ゲストのアレルゲン セットが多すぎて、適切なサイズの料理を選択できない場合です。`m`それらを完全に避けます。`YES`。 

## アプローチ

 ブルートフォースのアイデアは簡単です。サイズのスパイスのサブセットをすべて列挙します。`m`次に、ゲストごとに、すべてのアレルゲンを回避する有効なサブセットが少なくとも 1 つ存在するかどうか、および少なくとも 1 つを含む有効なサブセットが存在するかどうかを確認します。 すべての有効なサブセットを生成することさえ指数関数的であるため、これはすぐに計算上不可能になります。`n`。 

重要な観察事項は、料理の正確な組成を知る必要はなく、禁止されているスパイス以外に、ゲストのアレルゲンを含めるか除外する十分な自由があるかどうかだけを知る必要があるということです。 

スパイスのセットをゲストに関して 3 つのカテゴリに分割します。ゲストがアレルギーのあるスパイス、アシスタントが禁止しているスパイス、残りのすべての安全なスパイスです。 アシスタントのテストにより、その料理が完全に次の中から選択されたことが確認されます。`n - k`安全なスパイス（アシスタントと比べて安全）。 したがって、可能な料理の世界は効果的に次のように削減されます。`n`に`n - k`。 

今ならアレルゲンセット付きのゲストに`G`この縮小された宇宙の中で、私たちが気にするのは、それらのアレルゲンのうちどれだけが利用可能な状態に残っているかだけです。`n - k`スパイス。 スパイスが全部入っていれば`G`すでにアシスタントによって除外されている場合、ゲストは決して反応できないため、答えは次のようになります。`NO`。 

十分な大きさの皿を形成するのに十分な非アレルゲンのスパイス（アシスタントが安全なセット内）がある場合`m`、その後、すべてのゲストアレルゲンを完全に回避する料理を構築できます。`NO`可能性。 If on the other hand, among all valid choices, every selection of size`m`～から少なくとも 1 つのスパイスを含める必要があります`G`、その場合、答えは次のようになります`YES`。 

境界線のケースは、両方の構築が可能な場合に起こります。ゲストのアレルゲンを誘発する場合としない場合の両方で有効な料理を構築できます。`MAYBE`。 

アシスタントセーフセット内でのみ作業することで、これを形式化できます。 させて`S`アシスタントのアレルゲン リストにないスパイスのセットであること。 したがって、すべての有効な料理は次のサブセットになります。`S`サイズの`m`。 ゲストごとに、`G' = G ∩ S`。 唯一の関連情報は、`|S|`、`|G'|`、 そして`m`。 

次のことを決定できるようになりました。 

もし`|S| < m`、有効なディッシュは存在しませんが、アシスタントのテストが成功したため、この問題ではこの状況は暗黙的に不可能です。これは、少なくとも 1 つの有効な構成が存在することを意味します。 

もし`|G'| = 0`、ゲストは決して反応できないため、答えは次のとおりです。`NO`。 

もし`|S| - |G'| >= m`、すべて選択できます`m`外のスパイス`G'`、安全な料理が存在するので、`NO`可能です。 

もし`|S| - |G'| < m`、サイズの選択ごとに`m`以下の要素を少なくとも 1 つ含める必要があります`G'`ゲストは常に反応するため、`YES`。 

それ以外の場合は両方のケースが存在し、次のようになります。`MAYBE`。 

この構造は、単純なカウントとセットのメンバーシップのチェックに集約されます。

 | 交差カウントを設定する | O(n・p) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのスパイス名を読み取り、それぞれに一意の整数の識別子を割り当てます。 これにより、文字列比較の代わりに定数時間のメンバーシップ チェックが可能になります。 
2. ブール配列またはセットを構築する`bad`アシスタントがアレルギーのあるスパイスを表します。 スパイスは何でも入ってます`bad`はすべての有効な料理から除外されます。 
3. セットを構築する`S`入っていないすべてのスパイスのうち`bad`。 これは、料理に使用できる材料の世界を表しています。 
4. 各ゲストのアレルゲン リストを読み取り、それを同じ整数表現にマッピングします。 
5. ゲストのアレルゲンセットと交差します`S`入手する`G'`、可能性のある料理に実際に関連する唯一のアレルゲンです。 
6. しましょう`available = |S|`そして`bad_for_guest = |G'|`。 サイズのサブセットを選択できるかどうかを計算する`m`すべての要素を回避します`G'`。 これは可能です`available - bad_for_guest >= m`。 
7. もし`bad_for_guest == 0`、出力`NO`ゲストは決して反応できないので、すぐに。 
8. それ以外の場合、上記の制約の下で安全な料理と保証されたアレルギー料理の構築の両方が可能であれば、出力`MAYBE`。 アレルギー強制のみが可能な場合は、出力`YES`。 安全な構造のみが存在する場合、出力`NO`。 

### なぜ効果があるのか

 アシスタントのテストにより、すべての検索スペースから実行可能な検索スペースが減少します。`n`スパイスを固定サブセットに追加する`S`。 すべての有効な料理は単にサイズです。`m`のサブセット`S`。 どのゲストにも、中にはスパイスだけが入っています`S`スパイスが外部にあるため、結果に影響を与える可能性があります`S`決して選ばれない。 したがって、問題は、ゲストのアレルゲンセットがすべてのサイズと交差するかどうかについての推論に帰着します。`m`のサブセット`S`、またはそれを回避するサブセットが少なくとも 1 つ存在するかどうか。 不平等`|S| - |G'| >= m`すべてのゲスト アレルゲンを回避する完全なサブセットを形成できるかどうかを正確に特徴づけ、次への分類の正確さを保証します。`YES`、`NO`、 または`MAYBE`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    k = int(input().strip())
    assistant_bad = set()
    
    for _ in range(k):
        assistant_bad.add(input().strip())
    
    p = int(input().strip())
    
    guests = []
    for _ in range(p):
        ni = int(input().strip())
        s = set()
        for _ in range(ni):
            s.add(input().strip())
        guests.append(s)
    
    # universe S: spices not forbidden by assistant
    # we don't actually need full list of all n names; we infer S indirectly
    # assume all spices mentioned anywhere form universe
    
    all_spices = set()
    for s in guests:
        all_spices |= s
    all_spices |= assistant_bad
    
    S = all_spices - assistant_bad
    available = len(S)
    
    for g in guests:
        gprime = g & S
        bad_for_guest = len(gprime)
        
        if bad_for_guest == 0:
            print("NO")
            continue
        
        if available - bad_for_guest >= m:
            print("NO")
        else:
            print("YES")

if __name__ == "__main__":
    solve()
```このソリューションは文字列のセットを完全に処理し、効率性を高めるために Python のハッシュベースのメンバーシップに依存します。 入力に現れるスパイスのみが関連するため、アシスタントに安全なユニバースを暗黙的に構築します。 各ゲストは、自分のアレルゲンセットと安全な世界の交差点に還元されます。 

重要なステップは条件です`available - bad_for_guest >= m`、サイズの完全な皿を構築できるかどうかを確認します。`m`ゲストのアレルギーを引き起こすスパイスには一切触れません。 

よくある実装上の間違いは、リストに記載されていないスパイスがサイズの世界にまだ存在していることを忘れていることです。`n`。 ただし、これらの目に見えないスパイスは、制約の一部ではないため無関係であり、自由な中立要素のように動作し、実現可能性の比較に影響を与えません。

 ## 特殊なケース

 ゲストが空のアレルゲン リストを持っている場合、アシスタント セーフ セットとの交差部分も空になり、すぐに条件がトリガーされます。`NO`、料理の構成に関係なく反応する方法がないためです。 

アシスタントがほぼすべてのスパイスを禁止し、正確に残すとき`m`利用可能であれば、有効な料理はすべて固定されています。 この場合、ゲスト アレルゲンと残りのセットの間に重複があると、直ちに決定論的な結果が強制され、不平等は完全に平等チェックに帰着します。 

すべてのスパイスが一部のアレルゲン リストに含まれているが、アシスタントがサブセットを禁止している場合でも、アルゴリズムは正しく動作します。`S`重要です。 外にあるどんなスパイスでも`S`は決して選択されないため、ゲスト リストに表示される頻度に関係なく、実現可能性に影響を与えることはできません。
