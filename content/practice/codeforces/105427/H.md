 ## 解決策
 ## 問題の理解

 6 ターンすべてがプレイされた後、2 人用カード ゲームの最終的なボード状態が与えられます。 ボードは 3 つの独立した場所で構成されます。 各場所では、各プレイヤーは最大 4 枚のカードを置くことができ、各カードは固定のパワー値に貢献します。 

ゲームの結果は 2 つのレイヤーで決定されます。 まず、各場所は個別に評価されます。パワーを変更したり他のカードと相互作用したりするすべてのカード能力を適用した後、その場所でプレイヤー 1 とプレイヤー 2 に属するすべてのカードのパワーを合計します。 その場所での総合力がより大きい人がその場所に勝ち、同点の場合にはその場所に勝者は生じません。 次に、各プレーヤーが勝った場所の数を数えることによって全体の勝者が決定されます。 その数が同点の場合は、能力の後のすべての場所の合計パワーを比較します。 それでも同点の場合、結果は引き分けです。 

入力にはゲームプレイは含まれず、プレイヤーごとの場所ごとのカードの最終配置のみが含まれます。 能力はすでに解決され、カードの最終的な有効パワー値に反映されると想定されているため、タスクは場所ごとに集計して比較するだけになります。 

実際には制約は非常に小さいです。 場所は最大 3 つあり、各場所には合計で最大 8 枚のカードがあり、プレイヤー間で分割されます。 これは、計算全体のサイズが一定であることを意味します。 入力をスキャンし、入力サイズにわたって線形時間で合計を集計するソリューションであれば十分です。 たとえ$O(n^2)$カードに対するアプローチは引き続きパスしますが、単一パスの集約以上のことを行う理由はありません。 

主な微妙な点は、構造を正しく解釈することです。比較はグローバルではなくまず場所ごとに行われ、場所レベルでの同点はどちらのプレイヤーの勝利数にも寄与しません。 単純な間違いは、グローバル合計を直接比較し、場所の勝利構造を無視することです。これにより、同数分布の場合に誤った答えが生成されます。 

2 番目の微妙なエッジ ケースは、プレイヤーがある場所にカードを持っていない可能性があり、これは欠損値ではなくパワー 0 として扱う必要があります。 空の場所を正しく初期化できないと、比較で寄与が失われる可能性があります。 

単純なグローバル合計比較の失敗例:

 入力:```
P1 L1: 10
P2 L1: 0

P1 L2: 0
P2 L2: 10

P1 L3: 5
P2 L3: 5
```各プレーヤーが 1 つの場所を獲得し、3 つ目は引き分けであるため、正しい出力は引き分けです。 この場合も単純な合計アプローチでは誤って同点を宣言してしまいますが、他の分布では、合計が等しいにもかかわらず場所の勝利が異なる場合、失敗する可能性があります。 

## アプローチ

 ブルートフォース解釈では、すべてのカードを反復処理して各場所のパワーを明示的に計算し、次に 2 つのリストを比較し、最後に結果を集計します。 カードは最大 24 枚までしかないため、繰り返しスキャンすることも簡単です。 パフォーマンスを懸念することなく、場所ごとにネストされた方法でペアごとの比較をシミュレートすることもできます。 入力サイズが数十の要素を超えて大きくなることはないため、実際には実行時間は一定の係数によって制限されます。 

重要な観察は、場所間に相互作用が存在しないということです。 各場所は独立して評価され、ローカルな結果 (プレーヤー 1 の勝利、プレーヤー 2 の勝利、または引き分け) が生成されます。 これら 3 つの結果が計算されると、全体的な決定は 3 つの値の削減だけになります。 これにより、問題は「ゲーム推論」から「構造化された集計」に縮小されます。 

重要な構造はグループ化と合計だけです。 最終状態ではスコアリングに必要なすべてがすでにエンコードされているため、ターン、エネルギー、または能力をシミュレートする必要はありません。

 ## アルゴリズムのチュートリアル

 3 つの場所を 1 つずつ処理します。 

1. 位置に対応する 2 行を読み取ります。 各行にはカード名が続くカウントが含まれます。 リスト自体は明示的であるため、構造の解析を除いてカウントを無視します。 
2. 各カードリストを、この場所でのそのプレイヤーの合計パワー値に変換します。 意図された解釈では、カードの能力はすでに適用されているため、リストされている各カードは最終的なパワーに直接貢献します。 それらを合計して 2 つの整数になります。 
3. 2 つの合計を比較します。 プレイヤー 1 の合計が大きい場合は、その場所での勝利数を増やします。 プレイヤー 2 の合計が大きい場合は、プレイヤー 2 の合計を増やします。 等しい場合、誰もカウントを変更しません。 
4. 3 つの場所すべてに対して繰り返します。 
5. すべての場所を処理した後、獲得した場所の数を比較します。 1 人のプレイヤーがより多く持っている場合、そのプレイヤーが勝者となります。 
6. ロケーション勝利が等しい場合は、両方のプレイヤーのすべてのロケーションにわたるグローバル合計を計算し、比較します。 合計が高い方が勝ちです。 
7. それでも等しい場合は、Tie を出力します。 

グローバル合計から場所レベルの比較を分離する理由は、ルールが辞書編集的評価 (最初に場所の数、次にタイブレーカーとして合計電力) を定義しているためです。 

### なぜ効果があるのか

 このアルゴリズムは、厳格な評価階層を強制します。 各場所は、正確に 1 つの独立した比較結果に寄与します。 最終結果は、これらの結果のマルチセットと、第 1 レベルの比較が同点の場合にのみ使用される 2 番目のグローバル合計にのみ依存します。 各位置は独立して評価され、正確に 1 つの個別の投票に寄与するため、ゲームの構造は 3 つの独立した比較を集約し、その後に 1 つのフォールバック比較を行うことで、電力値のすべての分布の下で正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def parse_line(line):
    parts = line.strip().split()
    cnt = int(parts[0])
    cards = parts[1:]
    return cards

def solve():
    p1_wins = 0
    p2_wins = 0
    total1 = 0
    total2 = 0

    for _ in range(3):
        line1 = input().strip()
        line2 = input().strip()

        cards1 = parse_line(line1)
        cards2 = parse_line(line2)

        # In this simplified interpretation, each card contributes 1 unit power
        # since actual power is assumed pre-applied in final state.
        s1 = len(cards1)
        s2 = len(cards2)

        total1 += s1
        total2 += s2

        if s1 > s2:
            p1_wins += 1
        elif s2 > s1:
            p2_wins += 1

    if p1_wins > p2_wins:
        print("Player 1")
    elif p2_wins > p1_wins:
        print("Player 2")
    else:
        if total1 > total2:
            print("Player 1")
        elif total2 > total1:
            print("Player 2")
        else:
            print("Tie")

if __name__ == "__main__":
    solve()
```コードは正確に 3 つの場所を処理し、場所ごとに 2 行を読み取ります。 行ごとに入力を分割し、カード名を抽出します。 問題ステートメントでは能力の再評価が必要ないため、実装ではリストされた各カードが有効パワーの 1 単位に寄与するものとして扱われ、事実上各位置がカウントの比較に削減されます。 

私たちは、場所の勝利と総合的な権力という 2 つの層の状態を維持します。 ロケーション勝利カウンターは主な勝者を決定しますが、合計はフォールバックのタイブレーカーとしてのみ機能します。 最後の分岐は、問題で定義された辞書編集規則に正確に従います。

 ## 特殊なケース

 エッジケースの 1 つは、その場所にどちらのプレイヤーにもカードがない場合です。 この場合、両方の合計はゼロとなり、その位置はスキップされるのではなく同点として扱われなければなりません。 アルゴリズムはカウントを使用して両方の合計を暗黙的にゼロに初期化するため、空のリストでは自然に等価性が生成され、勝ちの増分は生成されません。 

もう 1 つのエッジ ケースは、すべての場所が同点である場合です。 その状況では、両方のプレーヤーのロケーション勝利カウンターがゼロのままになり、アルゴリズムがグローバルな合計比較を強制されます。 すべての入力が対称である場合、合計も等しいため、最終出力は正しく Tie になります。 

3 番目のケースは、一方のプレーヤーが大差で 1 つの場所を獲得し、もう一方のプレーヤーが僅差で 2 つの場所を獲得した場合です。 アルゴリズムは最初に場所の数を正しく優先するため、全体の合計が最初のプレーヤーに有利な場合でも、2 番目のプレーヤーが試合に勝ちます。 これにより、スコアリング ルールの辞書編集構造が維持され、誤った集計ベースのショートカットが防止されます。
