 ## 解決策
 ## 問題の理解

 私たちには 3 つの異なるサイコロが与えられます。 各サイコロには 6 つの面がありますが、それらの面の値は 1 ～ 1000 の任意の整数であり、繰り返すことができます。 ゲームは、まずジョンにサイコロを 1 つ選択させ、次にハンスが残りの 2 つのサイコロのうち 1 つを選択することでプレイされます。 その後、両方のプレイヤーが選択したサイコロを振ります。 

両方のプレイヤーが同じ数字を出した場合、そのラウンドは無視され、再度振ります。 重要な結果は、同点は結果の分布には寄与せず、厳密な比較が行われるまで実験を繰り返すだけであるということです。 2 つの結果が異なる場合は、より大きい値を出した方がすぐにゲームに勝ちます。 

課題は、ハンスが後でどのサイコロを選んでも、ジョンが勝つ確率が少なくとも 2 分の 1 になるような、ジョンのサイコロの選択肢が存在するかどうかを判断することです。 複数のサイコロがこれを満たす場合、最小のインデックスを出力します。 条件を満たすものがない場合は、有効な選択肢がないことが出力されます。 

制約は小さく、サイコロは 3 つだけで、それぞれの面は 6 つだけです。 これは、問題は大きな入力に対する最適化に関するものではなく、ペアごとの比較から確率を正しく計算することにあることを意味します。 面の数が 2 次または 3 次である解は、出目の合計数がサイコロ 1 組あたり 36 に固定されているため、十分に高速になります。 

主な微妙な点は、同点除去ルールです。 同点を損失として扱ったり、同点を確率に直接含めたりする単純なシミュレーションは、不正確になる可能性があります。 たとえば、両方のサイコロが同じ場合、単純な計算ではそれぞれ 50% の勝利確率が割り当てられますが、実際にはすべてのロールが同点であるため、ゲームは決して解決されず、実質的に勝者は存在しません。 この場合はどちらの側にも寄与度がゼロとして扱われなければなりません。 

2 番目のエッジケースは、タイを除いて、あるダイが別のダ​​イを支配する場合です。 たとえば、サイコロ A と B が多くの等しい面を共有しているが、それ以外の場合は A の方が常に大きい場合、正しい勝ち確率は 1 であり、同点によって薄められるものではありません。 

## アプローチ

 ブルートフォースのアイデアは簡単です。任意の 2 つのサイコロについて、36 組の面をすべて列挙します。 各ペアについて、結果が最初のサイコロの勝ち、2 番目のサイコロの勝ち、または引き分けのいずれであるかを決定します。 勝ち負けを数えます。 同点は再ロールされるため、確率を計算するときは無視する必要があります。 

具体的には、勝ち数を A[i] > B[j] のペアの数として定義し、負け数を A[i] < B[j] の数として定義すると、これらの比較のみが重要になります。 A が B に勝つ確率は次のとおりです。 

P(A が B に勝つ) = 勝ち / (勝ち + 負け)

 ブルート フォースは、順序付けられたサイコロのペアごとにこれを直接計算します。 サイコロは 3 つしかないため、候補サイコロごとに 2 つの比較を計算し、合計で最大 6 つの比較を計算します。 各比較には 36 回の操作がかかるため、これは無視できます。 

状態空間は小さいため、より高度なテクニックは必要ありません。 唯一の本当の落とし穴は、分子と分母の両方からタイを除外してタイを正しく処理することです。 

すべてを単純化する観察は、2 つのサイコロ間のゲームが、すべての面の組み合わせに対するペアごとの優位頻度に完全に減少するということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ペア シミュレーション | O(3×3×36) | お(1) | 承認済み |
 | 最適なペアカウント | O(3×3×36) | お(1) | 承認済み |

 実際には、どちらのアプローチも同じです。 「最適化」とは、列挙がすでに最適であることを認識しているだけです。 

## アルゴリズムのチュートリアル

 各ダイ i をジョンの候補として評価します。

1. 固定されたダイ i について、それを他のダイ j と比較します。 36 個すべての顔のペア (a は i、b は j) をチェックして、i が j に勝つ頻度を計算します。 各比較は、勝ち、負け、引き分けのいずれかに影響します。 
2. サイコロのペアごとに、勝ちと負けの 2 つのカウンターを維持します。 勝ち + 負けがゼロの場合、すべての結果が引き分けであることを意味するため、どちらのダイも勝つことはできず、この組み合わせは何の役にも立ちません。 その場合、ハンスはゲームを未解決にするダイスを選択できるため、ダイス i は即座に要件を満たしません。 
3. 勝ち + 負けが正の場合、勝ちの確率 / (勝ち + 負け) を計算します。 これが少なくとも 1/2 であるかどうかを確認します。 代数的には、これは 2 * 勝ち ≥ 勝ち + 負けかどうかをチェックすることと同等であり、浮動小数点の問題を回避できます。 
4. サイコロ i は、他のサイコロの両方に対して確率条件を満たす場合にのみ有効です。 両方のチェックに合格した場合は、答えとして i を返します。 
5. ダイが通過しない場合は、有効なダイが存在しないと出力します。 

これが機能する主な理由は、ハンスがジョンの選択を見て最適にプレイするため、ジョンが選んだダイスが残りの両方の選択肢に対して独立して強いことを確認する必要があるためです。 ハンスはジョンにとって最悪の組み合わせを選択するため、正しさの条件は 2 つのペアごとの確率の最小値になります。 

### なぜ効果があるのか

 固定されたサイコロのペアの場合、すべてのロールの出目は 2 つの独立した均一な出目の比較に帰着します。 同点は、ゲームを終了させないため、結果スペースから削除される一連のメジャーを形成します。 残りの結果は、各順序ペアが均等に寄与する有限セットを形成します。 したがって、勝利確率は、有利な厳密な不等式を計算することによって完全に決定されます。 ハンスは常にジョンの勝ち確率を最小にするサイコロを選択するため、両方のペアの確率がしきい値を超えた場合にのみジョンが成功します。 これにより、2 つの対戦相手のダイス間で条件を分離できるようになり、独立したチェックの正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def win_prob(a, b):
    win = 0
    loss = 0
    for x in a:
        for y in b:
            if x > y:
                win += 1
            elif x < y:
                loss += 1
    total = win + loss
    if total == 0:
        return 0  # no resolution possible
    return win / total

dice = [list(map(int, input().split())) for _ in range(3)]

def ok(i):
    for j in range(3):
        if i == j:
            continue
        p = win_prob(dice[i], dice[j])
        if p < 0.5:
            return False
    return True

for i in range(3):
    if ok(i):
        print(i + 1)
        break
else:
    print("No dice")
```この解決策では、最初に、すべての面のペアを総当たり的に列挙することによって 2 つのサイコロ間の勝率を計算するヘルパー関数を定義します。 このロジックは勝ちと負けを明確に区別し、正確さにとって重要な引き分けを無視します。 

の`ok`この関数は、選択したダイスが他の両方のダイスに対して成功する必要があるという要件を強制します。 2 人の対戦相手に対して反復処理を行い、確率条件をチェックします。 

最後に、最小の有効なインデックスが選択されるように、サイコロを昇順にスキャンします。 

実装の微妙な詳細は、すべての比較が同点である場合の処理​​です。 ゼロを返すと、そのようなサイコロは決して良いとは見なされず、ゲームは決して解決されず、したがって勝利が保証されないという解釈と一致します。

ダイ 1 とダイ 3 の場合も同じ構造が当てはまります。ダイ 1 のより大きな値がほとんどの比較で優勢です。 

| 候補者 | vsダイ2 | vsダイ3 | 有効？ |

 ## 特殊なケース

 重要なエッジケースの 1 つは、2 つのサイコロが同一である場合です。 この状況では、すべてのロールが引き分けとなるため、勝ち + 負けはゼロになります。 アルゴリズムはこれを確率 0 にマップします。これにより、どちらのダイスも有効な保証された勝者とみなされなくなります。 これは、ゲームが決して解決しないという意図された解釈と一致します。 

別のケースは、あるダイが別のダ​​イを厳密に支配する場合です。 たとえば、サイコロ A が常にサイコロ B より大きい場合、すべてのペアが勝ち数に寄与し、確率は 1 になります。損失はゼロのままであり、同点は正規化に影響を与えないため、アルゴリズムはこれを自然に捉えます。 

3 番目のケースは、同点が頻繁に発生するが完全ではない場合です。 多くの面が等しいが、一部の面が大きいと仮定します。 このアルゴリズムは、等しい結果を正しく無視し、厳密な比較に基づいてのみ確率を計算するため、タイの重いサイコロが実際の影響を超えて誤ってペナルティを課されることがなくなります。
