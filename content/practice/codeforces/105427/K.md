 ## 問題の理解

 長さの配列のようなバッファーが与えられます。$2N$、 しかし$N$は不明です。 このバッファの構造は非常に特殊です。最初の$N$位置にはゼロ以外のバイトが格納され、残りの部分にはゼロ以外のバイトが格納されます。$N$位置にはゼロが格納されます。 言い換えれば、値が「正」(1 ～ 255) からゼロに切り替わる移行点が 1 つあり、その移行はインデックスで正確に発生します。$N$。 

バッファ全体を自由に読み取ることはできません。 代わりに、次を使用して個々の位置をクエリできます。`buf[i]`。 インデックスが有効な場合は、バイト値を受け取ります。 範囲外の場合$[0, 2N-1]$、プログラムがクラッシュします。 また、最大でも次のとおりに制限されています。$2 \log_2 N$これにより、リニア スキャン戦略が除外されます。 

必要な出力は値です$N$、最初のゼロが発生する場所を特定した後、特別な形式で印刷されます。 

重要な制約は、$N$と同じ大きさにすることができます$10^{18}$。 これにより、配列を明示的に探索したり、インデックスを段階的に増加させたりするアプローチは即座に排除されます。 対数検索も許容されますが、これは無効なインデックスを避けるために各クエリが注意深く制御されている場合に限ります。 

主な微妙な点は、有効な上限がわからないことです。$2N$あらかじめ。 無制限の範囲に対する単純なバイナリ検索では、誤って範囲外のインデックスをクエリしてしまい、即時クラッシュが発生する可能性があり、これは間違った解決策として扱われます。 したがって、課題は、境界を効率的に見つけることだけでなく、すべてのプローブが証明された安全な間隔内に留まるようにすることでもあります。 

典型的な失敗例は、次のような固定の配列サイズを想定した場合に発生します。$10^{18}$または$2 \cdot 10^{18}$正当な理由もなく。 その限界を少しでも超えていれば$2N$、クエリによってサイレントにセグメンテーション違反がトリガーされる可能性があります。 たとえば、次の場合$N = 10^{18}$、 それから$2N = 2 \cdot 10^{18}$ので、インデックスをクエリします$2 \cdot 10^{18}$は無効であり、すぐにクラッシュします。 検索スペースを慎重に制限しないソリューションは安全ではありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。インデックスから開始します。$0$そしてクエリを続けます`buf[i]`ゼロが見えるまで。 最初から$N$値がゼロ以外で、次の値がゼロである場合、最初のゼロはインデックスで正確に発生します。$N$。 この方法は構造の定義に直接従うため、正しいです。 

ただし、このアプローチは遅すぎます。 最悪の場合、それは実行されます$N$クエリ、最大で$10^{18}$。 それは許容範囲をはるかに超えています$2 \log_2 N$限界。 

重要な観察は、配列がバイナリの意味で単調であるということです。配列は、ゼロ以外の値のブロックとその後に続くゼロのブロックで構成されています。 これは、典型的な「最初の誤った位置」の問題になります。 この構造を認識すると、線形走査を二分探索に置き換えることができます。 

唯一複雑なのは、安全な検索範囲を定義することです。 以来$N \le 10^{18}$、私たちは知っています$2N \le 2 \cdot 10^{18}$、したがって、内の任意のインデックス$[0, 2 \cdot 10^{18} - 1]$安全が保証されています。 これにより、無効なメモリ アクセスの危険を冒すことなく、二分探索の固定された上限が得られます。

 ## アルゴリズムのチュートリアル

 問題を最小のインデックスを見つけることに落とし込みます$i$そのような`buf[i] == 0`。 

1. 検索範囲を初期化します$[l, r]$として$[0, 2 \cdot 10^{18} - 1]$。 この範囲は、考えられる無効なインデックスよりも厳密に小さいため、遷移点が安全に含まれます。 
2. この範囲に対して二分探索を実行します。 各中間点について$m$、クエリします`buf[m]`。 
3. もし`buf[m]`がゼロ以外の場合、まだプレフィックス領域にいることはわかっているため、遷移点は厳密に右側にある必要があります。 更新します$l = m + 1$。 
4. もし`buf[m]`がゼロの場合、境界に到達したか、境界を超えたので、次のように設定して左に移動します。$r = m$。 これにより、次の可能性が保たれます。$m$それ自体が最初のゼロです。 
5. まで続けます$l == r$。 その時点で、$l$値がゼロになる最初のインデックスです。これは次の値と等しくなります。$N$。 
6. アウトプットする`strlen(buf) = l`。 

これが機能する理由は、述語「buf[i] is zero」がインデックスに対して単調であるためです。つまり、すべてのインデックスに対して false になります。$i < N$そしてすべての人にとって真実です$i \ge N$。 このような単調な分割が存在する場合、二分探索は正確に正しく行われます。 唯一の追加の注意は、クエリされたすべてのインデックスが、固定された上限によって保証されている証明可能な有効範囲内に収まるようにすることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(i: int) -> int:
    print(f"buf[{i}]")
    sys.stdout.flush()
    resp = input().strip()
    if resp.startswith("Segmentation") or resp.startswith("Too many"):
        sys.exit(0)
    return int(resp)

def main():
    # safe upper bound: 2 * 1e18 fits constraints since N <= 1e18
    lo, hi = 0, 2 * 10**18 - 1

    while lo < hi:
        mid = (lo + hi) // 2
        val = ask(mid)

        if val == 0:
            hi = mid
        else:
            lo = mid + 1

    print(f"strlen(buf) = {lo}")
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```の`ask`関数はインタラクション層です。 クエリを必要な形式で出力し、裁判官が応答できるように出力を即座にフラッシュします。 また、早期に終了することで、セグメンテーション違反やクエリ制限の超過などの無効な応答を防ぎます。 

二分検索では、最初のゼロ インデックスが常に含まれる縮小間隔が維持されます。 更新ルールは意図的に非対称です。ゼロ以外の値は左側の境界を前方にシフトしますが、ゼロの値は右側の境界を内側に移動することで現在の位置を候補として保持します。 

の選択`2 * 10**18 - 1`上限が重要であるためです。 有効なインデックスの最大値は正確に次のとおりであるため、許可された範囲外のインデックスをクエリすることがないことが保証されます。$2N - 1$、 そして$2N \le 2 \cdot 10^{18}$。

## 特殊なケース

 重大なエッジケースは次のような場合です。$N$最大値にあります$10^{18}$。 この場合、最後の有効なインデックスは次のとおりです。$2 \cdot 10^{18} - 1$。 アルゴリズムの上限が固定されているため、インデックスをクエリすることはありません$2 \cdot 10^{18}$そうでない場合、セグメンテーション違反が発生します。 二分探索は厳密に安全な範囲内に留まり、次のように収束します。$10^{18}$予想通り。 

もう一つのケースは、$N = 2$。 バッファーは次のようになります。`[a, b, 0, 0]`。 最初の中間クエリは早い段階でゼロ領域に到達する可能性がありますが、アルゴリズムは右側の境界を正しく縮小し、最終的にインデックス 2 を分離します。遷移が開始点に非常に近い場合でも、単調な特性により正確性が保証されます。
