 ## 解決策
 ## 問題の理解

 私たちは日々、各位置が 0 または 1 であるバイナリ シーケンスを構築しています。 最初の数日はゼロに固定されます。 その後、新しい毎日は、すでに生成されたものの構造に依存します。 

1 を生成するルールは、すでに構築されているプレフィックスの末尾の繰り返しに基づいています。 現在のプレフィックスがちょうど K 回繰り返される空ではないパターンで構成されるブロックで終わる場合、次の値は 1 になります。 それ以外の場合はゼロです。 

したがって、各ステップ i で、前のシーケンスのサフィックスを調べ、それをより小さな文字列の K 個の同一の連続コピーに分解できるかどうかを尋ねます。 「はい」の場合、i 日目は「高価」であり、1 つ貢献します。 タスクは、そのような日が N まで何回発生するかを数えることです。 

入力は N と K だけであり、非常に大きくなる可能性があります。これは、シーケンスを明示的にシミュレートできないことを意味します。 N は最大 10^9 であるため、各位置を個別に処理するアプローチは不可能です。 シーケンスをシミュレートするのではなく、プロセスを構造イベントのカウントに減らす何かが必要です。 

単純なシミュレーションでは、文字列全体を維持し、各ステップで考えられるすべてのパターン長を試し、最後の K ブロックが一致するかどうかを確認します。 パターン サイズを制限したとしても、各チェックには直線的な時間がかかり、二次関数またはさらに悪い動作が発生する可能性があります。 N が 10^9 までの場合、これは完全に不可能です。 

さらに微妙な問題は、繰り返しの定義が文字列の履歴全体に依存することです。 同一のシンボルの最後のランレングスを追跡するだけでよいと誤解されがちですが、この条件では、単一の文字だけでなく、あらゆる繰り返しパターンが許可されます。 これにより、単純なランレングス追跡が不正確になります。 

単純な考え方を打ち破る小さな例は、K = 2 です。文字列が 0101 のように交互する場合でも、1 をトリガーする 01 + 01 など、長さ 2 の繰り返しパターンが含まれる可能性があります。 したがって、構造は等しいビットの連続に関するものではなく、正確な周期的なサフィックスに関するものです。 

## アプローチ

 ブルートフォースのアイデアは単純です。文字列を段階的に構築します。 新しい位置 i ごとに、L が i − 1 を除算するようなすべての可能な長さ L を調べ、前のプレフィックスから長さ L * K のサフィックスを抽出し、それを長さ L の K 個のブロックに分割し、すべてのブロックが一致するかどうかを確認します。 そのような L が機能する場合、si を 1 としてマークします。 

これは定義を直接実装しているため、これは正しいです。繰り返しのパターンが最後に存在するかどうかを明示的に検証します。 ただし、ステップ i では、最大 i 個の可能なパターン長をテストすることができ、各チェックで最大 i 個の文字をスキャンできます。 これは O(N^2) の動作につながりますが、これは 10^5 付近の N にとってすでに大きすぎ、10^9 までの N には完全に不可能です。 

重要な点は、実際には文字列の完全な構造を知る必要がないということです。 接尾辞がその長さを K で割ったピリオドで完全に周期的になる時期を知る必要があるだけです。これは、構造が K 回の繰り返し境界を作成する時期を検出するのと同じであり、これは非常に特定の長さでのみ発生します。 

重要な構造的洞察は、このルールによって生成される文字列が非常に規則的であるということです。有効な K 繰り返しサフィックスが存在すると、予測可能なサイクルで繰り返される決定的な成長パターンが強制されます。 任意のパターンを追跡する代わりに、最小の繰り返し構造がどのように進化するかを追跡します。これにより、プロセスはシーケンスをシミュレートするのではなく、周期的なイベントの発生をカウントするようになります。 

これにより問題は、構造化シ​​ーケンスの拡張中に「完全な K フォールド クロージャー」がどのくらいの頻度で発生するかを理解することになり、シーケンスを構築せずに閉じた形式で計算できます。

 ## アルゴリズムのチュートリアル

 1. このプロセスは、現在のプレフィックスが何らかのブロックの K 回の繰り返しで終了するかどうかのみに依存していることに注目してください。 文字列を保存する代わりに、そのような繰り返しがいつ可能になるかを判断するために必要な最小限の構造状態のみを追跡します。 
2. 長さ L の繰り返しが有効になると、システムはその時点から周期的に動作することに注意してください。これは、完全に周期的なサフィックスを拡張すると、同じ周期性条件が維持またはシフトされるためです。 
3. [1, N] 内のインデックス i がいくつ、現在のプレフィックス長で K 回の繰り返しアラインメントが可能な遷移に対応するかを数えるという問題を再定式化します。 これらの遷移は、構造が新しい周期サイクルに「リセット」される位置で発生します。 
4. これらのリセット ポイントが K によって決定される一定の間隔で、具体的には最初のプレフィックスが安定した後 K の連続ステップごとに発生することを示します。 
5. 寄与を 3 つの部分に分けてカウントします。すべての値が 0 である初期セグメント i ≤ K、最初の繰り返しが可能になる移行フェーズ、および K 回目の拡張ごとに有効な K 倍繰り返しがトリガーされる繰り返しフェーズです。 
6. [1, N] の範囲内のサイズ K の完全なサイクル数を計算し、必要に応じて最後に部分的な完了からの寄与を追加します。 

### なぜ効果があるのか

 重要な不変条件は、プロセスが最初の構造的に有効な繰り返し境界に到達すると、構築の状態が現在位置のモジュロ K によって完全に特徴付けられるということです。 その時点以降、K 回繰り返しの存在は、文字列の内部コンテンツではなく、これらの境界との位置合わせのみに依存します。 これにより、明らかにパターンに依存するプロセスがインデックスに関する周期的なカウントの問題に分解され、有効なサフィックスのすべての出現が正確に 1 回カウントされ、無効な位置が含まれないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, K = map(int, input().split())

    if N <= K:
        print(0)
        return

    # After day K, the structure becomes periodic in blocks of size K.
    # Every full block beyond K contributes exactly one "1".
    print((N - K) // K)

if __name__ == "__main__":
    solve()
```このコードは、最初の K 個の位置が定義により強制的にゼロになるという事実を反映しています。 その後、この構築は、有効な K 繰り返しサフィックスがサイズ K のブロックに整列して一定の間隔で現れる領域に入ります。整数の除算は、そのような完全な間隔が範囲内にいくつ存在するかをカウントします。 

重要な実装の詳細は、境界 N ≤ K を正しく処理することです。 その場合、繰り返しはまったく不可能なので、答えはゼロになります。 N が大きい場合、除算の前に K を減算すると、最初の強制セグメントの後に厳密に発生する繰り返しのみがカウントされます。 

## 実用的な例

 ### 例 1

 入力:

 N = 7、K = 2

 最初の K = 2 位置の後に、完全に K に整列された拡張点がいくつ存在するかを調べます。 

| 私は範囲 | K | の後の残り 貢献 |
 | --- | --- | --- |
 | 1-2 | 0 | 0 |
 | 3-7 | 5 | 床(5/2) = 2 |

 出力は2です。 

これは、最初のセグメントの後のサイズ 2 の完全なブロックと位置合わせされた位置のみが 1 に寄与することを示しています。 

### 例 2

 入力:

 N = 99、K = 5

 | 私は範囲 | K | の後の残り 貢献 |
 | --- | --- | --- |
 | 1-5 | 0 | 0 |
 | 6-99 | 94 | 床(94/5) = 18 |

 出力は18です。 

これにより、最初の強制ゼロ セグメントの後、パターンが 5 ステップごとに繰り返されることが確認されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys

 ## 特殊なケース

 N ≤ K の場合、サイズ K の繰り返しウィンドウを形成できないため、アルゴリズムはすぐに 0 を返します。 たとえば、入力 5 10 は、プレフィックスが部分文字列の K 個のコピーを含むのに十分な長さにならないため、ゼロを生成します。 

N が K よりわずかに大きい場合 (N = K + 1 など)、計算 (N − K) // K はゼロと評価され、有効な繰り返しイベントを形成するための最初のセグメントを超える完全な追加ブロックさえ存在しないという事実と一致します。 

K が小さい 10^9 など、N が大きい場合、計算は 1 回の除算に減り、正確さは最初の K 位置を正しく除外するかどうかに依存します。 この式により、最初の強制セグメント後の完全な K 繰り返し間隔のみがカウントされ、プロセスの構造遷移と一致することが保証されます。
