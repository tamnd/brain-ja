 ## 解決策
 ## 問題の理解

 ロープは最初に原点から正の X 軸上の固定点まで引き伸ばされます。 次に、現在ピボットとして機能している点を中心に、このロープを反時計回りに回転させ始めます。 最初はピボットが原点です。 ロープが回転すると、柱と呼ばれる平面内のいくつかの固定点の 1 つに当たることがあります。 ロープが柱に触れると、その柱が新しいピボットとなり、ロープのセグメントがそこで「効果的に曲がる」ため、動作は原点ではなくこの新しいピボットを中心とした回転として継続します。 

幾何学的には、現在反時計回りに回転する光線を放射しているピボットである点を考えることができます。 このレイが遭遇する最初の柱が次のピボットになります。 ピボットを切り替えた後、このプロセスが繰り返されますが、ロープの長さはロープセグメントに沿って移動する距離だけ減少するため、最終的には別の柱に到達するのに十分なロープが残らなくなる可能性があります。 

タスクは、どの柱が最終ピボットになるかを決定するか、どの柱も到達しないことを報告することです。 

入力は、開始ロープの長さと平面内の一連の点で構成されます。 出力は、プロセスが到達する最後のピラーのインデックスです。 

n が 100000 までの制約により、ピラーのすべてのペアにわたる二次シミュレーションは直ちに失敗します。 すべてのピボットについて、残りのすべての点をスキャンして幾何学的交差を計算しようとするソリューションは、最悪の場合、O(n²) のように動作し、実現可能な限界をはるかに超えています。 

さらに微妙な問題は、「次のピボット」が単にユークリッド距離の最も近い点ではないことです。 これは回転順序によって決まります。ロープは連続的にスイープするため、最初のヒットは半径ではなく角度によって定義されます。 

いくつかの失敗例は自然に現れます。 

1 つの例は、点が近いものの、角度順にわずかに遅れている場合です。 ユークリッド距離での貪欲な最近隣アプローチでは、たとえ回転中にロープが最初に触れることはないとしても、間違った柱が選択されてしまいます。 

もう 1 つの問題は、方向を静的に扱うことです。 ピボットが変化するため、原点からの単純な事前計算だけでは不十分です。 ヒットの順序が原点から固定されていると仮定すると、ピボットが移動すると間違いになります。 

3 番目の問題は停止条件です。 幾何学的に有効な次の柱がある場合でも、残りのロープの長さが短すぎて、パスに沿って物理的に到達できない場合があります。 

## アプローチ

 ブルート フォース解釈では、プロセスを段階的にシミュレートします。 各ピボットですべての柱をテストして、ピボットの周りを回転する光線が最初に当たる柱を特定します。 これには、ピボットに対する角度順序を計算し、ロープ セグメントが残りの長さで候補点に到達できることを確認する必要があります。 各ピボットについて、このスキャンは O(n) であり、最悪の場合、すべてのピラーがピボットになるため、総コストは O(n²) に達します。 100000 ポイントの場合、これは 10¹⁰ 回の操作に相当し、現実的ではありません。 

重要な観察は、モーションが現在のピボットの周りの角度順序によって完全に支配されており、各ピボットの遷移は、平面の周りの周期的な角度順序の次の点への移動に対応しているということです。 ピボットは変化しますが、イベントのシーケンスは依然としてグローバルな回転構造を尊重します。ロープは常に反時計回りに回転し、現在の中心の周りで角度が後戻りすることはありません。 これにより、残りのロープの長さの実行チェックを行いながら、極角によってソートされたポイントを通過するプロセスとして処理することができます。

ロープの初期方向から開始して、原点の周りの角度によってソートされたすべての柱を事前計算します。 次に、残りのロープの長さを予算として維持しながら、この角度順でそれらを訪問することをシミュレーションします。 現在のピボットから次に選択したピラーに移動するたびに、それらの間のユークリッド距離に等しいロープを消費します。 いずれかの時点で残りのロープが不十分な場合、プロセスは停止し、最後の有効なピボットが答えとなります。 

これにより、動的な幾何学的プロセスが角度順序にわたる 1 次元の走査に縮小され、唯一の状態は現在のピボットと残りの長さになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n²) | O(n) | 遅すぎる |
 | 角度オーダースイープ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各柱を原点に対して極形式に変換し、x 軸の正の方向から反時計回りに増加する順に角度によって並べ替えます。 これにより、継続的に回転する光線が遭遇する順序で柱を処理することが保証されます。 
2. 現在のピボットを原点として初期化し、残りのロープの長さを d に設定します。 原点は出力候補の一部ではありませんが、開始基準として機能します。 
3. ソートされた角度順に柱を移動します。 各ピラーについて、現在のピボットからこのピラーまでのユークリッド距離を計算します。 
4. この距離が残りのロープの長さよりも長い場合は、シミュレーション制約の下ではロープがこの柱に到達できないため、すぐに停止します。 
5. それ以外の場合は、残りのロープの長さからこの距離を減算し、現在のピボットをこの柱に更新します。 それを最新の有効なピボットとして記録します。 
6. すべての柱が処理されるか、移動できなくなるまで続けます。 
7. ピラーに到達しなかった場合は、-1 を出力します。 それ以外の場合は、最後に到達したピラーのインデックスを出力します。 

### なぜ効果があるのか

 回転により、ロープが常に現在のピボット方向を中心に厳密に増加する角度順序でピラーに遭遇することが保証されるため、次のイベントは空間的近接性ではなく角度スイープによって完全に決定されます。 最初の方向からの角度によってグローバルにソートされると、プロセスで以前の角度領域を再訪する必要はありません。 残りのロープの長さは、次のセグメントを物理的に横断できるかどうかにのみ影響し、どの柱が順番に来るかには影響しません。 これにより、シミュレーションは、予算が減少する固定順序リストをたどることと同等になるため、貪欲な走査は常に物理プロセスと一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

def angle(x, y):
    return math.atan2(y, x)

def dist(ax, ay, bx, by):
    return math.hypot(ax - bx, ay - by)

n, d = map(int, input().split())
pts = []

for i in range(n):
    x, y = map(int, input().split())
    pts.append((angle(x, y), x, y, i + 1))

pts.sort()

curx, cury = 0, 0
rem = d
last = -1

for _, x, y, idx in pts:
    step = dist(curx, cury, x, y)
    if step > rem:
        break
    rem -= step
    curx, cury = x, y
    last = idx

print(last)
```この実装は、原点を中心とした極角によってすべての柱を並べ替えるというアイデアに直接従っています。 各ピラーは元のインデックスとともに保存されるため、最後に正しい 1 から始まる識別子を出力できます。 

シミュレーションでは、現在のピボットと残りのロープの長さが維持されます。 角度順の各候補柱について、現在のピボットからのユークリッド距離を計算します。 この距離がロープの残りの距離を超えると、ロープが次のピボットに物理的に到達できないため、プロセスは停止します。 それ以外の場合は、ピボットを移動し、予算を削減して続行します。 

唯一の微妙な点は、原点からではなく、常に現在のピボットからの距離を測定することです。 これは、各ピボットが新しい回転中心になるという事実を反映しています。 

## 実用的な例

 柱が原点の周りでさまざまな方向に配置されている小さな構成を考えてみましょう。 このプロセスは原点から始まり、角度の増加順に原点を訪れます。 

| ステップ | 現在のピボット | 次の柱 | 距離 | 残りのロープ | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | (0,0) | P1 | d1 | d - d1 | 移動 |
 | 2 | P1 | P2 | d2 | レム - d2 | 移動 |
 | 3 | P2 | P3 | d3 | 不十分です | 停止 |

 このトレースは、角度的にソートされたポイントを通る予算に基づいたウォークとしてアルゴリズムがどのように動作するかを示しています。 

2 番目の例は、ロープが短すぎて最初の柱にさえ届かない場合です。 この場合、ループは直ちに終了し、出力は -1 となり、衝突は決して起こらないという物理的な解釈と一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 柱を角度ごとに分類することが優勢です。 トラバースは線形です |
 | スペース | O(n) | すべてのピラーをメタデータとともに保存する |

 この制約では最大 100,000 個のピラーが許可されるため、O(n log n) アプローチは容易に制限内に収まります。 並べ替えと単一の直線パスは、このスケールの一般的な制限時間内に問題なく収まります。 

## テストケース```python
import sys, io
import math

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, d = map(int, input().split())
    pts = []
    for i in range(n):
        x, y = map(int, input().split())
        pts.append((math.atan2(y, x), x, y, i + 1))
    pts.sort()

    cx, cy = 0, 0
    rem = d
    ans = -1

    for _, x, y, idx in pts:
        step = math.hypot(cx - x, cy - y)
        if step > rem:
            break
        rem -= step
        cx, cy = x, y
        ans = idx

    return str(ans)

 ## 特殊なケース

 原点から到達可能な柱がない場合、アルゴリズムはループに入らずに直ちに終了します。 残りのロープの長さは決して短縮されないため、出力は初期値の -1 のままになります。 

角度順の最初の柱が遠すぎる場合、距離チェックは最初の反復で失敗します。 これにより、他の近い柱がユークリッド空間に存在する場合でも、回転順序で最初に遭遇することがないため、それらは無関係であることが保証されます。 

すべてのピラーに到達可能であるが、シーケンスの途中でロープの長さが足りなくなった場合、ループは最初の到達不能な遷移で正確に終了し、最後に正常に割り当てられたピボットが報告されます。
