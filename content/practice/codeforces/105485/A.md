 ## 解決策
 ## 問題の理解

 このタスクでは、純粋にゼロからのインデックス作成を動機付ける方法として配列について説明します。 配列に長さがある場合$n$、その有効なインデックスはから実行されます$0$まで$n - 1$。 次に、この問題では、長さだけが必要な場合、そのような配列の最後の要素のインデックスを出力するように求められます。$n$が与えられる。 

したがって、入力は概念配列のサイズを表す単一の整数であり、出力はその配列内の最大の有効なインデックスです。 言い換えれば、ゼロベースのインデックスの下で長さをその最後の位置に変換しています。 

制約$1 \le n \le 100$これは、入力が非常に小さいため、定数時間から線形時間までのあらゆる計算が容易に通過することを意味します。 ただし、問題の構造では要素の反復やシミュレーションは必要ありません。 出力は、配列サイズとその最終インデックスの間の直接的な算術関係のみに依存します。 

可能な限り最小の入力を超える意味のあるエッジケースはありません。 いつ$n = 1$、配列のインデックスには単一の要素があります。$0$したがって、正しい出力は次のようになります。$0$。 インデックスが 1 から始まると誤って仮定するアプローチでは、代わりに次の出力が行われます。$1$、これはすでに有効範囲外になります。 

## アプローチ

 単純な解釈では、配列のアイデアを明示的に構築し、位置を反復処理することでその最後のインデックスを計算することになります。 からシーケンスを作成することを想像するかもしれません。$0$に$n - 1$、最後に見つかった要素を返します。 これはインデックス作成の定義を反映しているため正しく機能しますが、不必要な作業が実行されます。すべてのインデックスを生成するには$O(n)$最終的な答えは長さだけですでに決定されているにもかかわらず、演算を実行できます。 最悪の場合、これは最大 100 回の反復を意味しますが、これはここではまだ重要ではありませんが、制約が大きくなると構造が無駄になります。 

重要な観察は、ゼロベースのインデックス付けが固定関係を定義するということです。つまり、最後の有効なインデックスは常に配列のサイズより 1 小さいものになります。 これにより、配列を構築したり走査したりする必要がなくなります。 問題は完全に、単一の減算を計算することに帰着します。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$n$配列の長さを表す入力からの値。 値は少なくとも 1 であることが保証されているため、配列には常に少なくとも 1 つの有効なインデックスがあります。 
2. コンピューティング$n - 1$、これは最後の有効な 0 から始まるインデックスに対応します。 
3. 計算値を直接出力します。 

### なぜ効果があるのか

 インデックスが 0 の配列では、最初の要素のインデックスは 0 であり、要素が追加されるたびにインデックスが 1 ずつ増加します。 配置後$n$要素、最終的に到達する位置は正確に$n - 1$。 この関係は、有効なすべての場合に当てはまります。$n$入力ドメイン内なので、計算$n - 1$例外なく、常に正しい最後のインデックスが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    print(n - 1)

if __name__ == "__main__":
    solve()
```このソリューションは、単一の整数を読み取り、配列サイズと最後のインデックスの間で導出された関係を直ちに適用します。 減算は 1 回実行され、結果が出力されます。 ループ、条件、または追加のメモリ構造は必要ありません。 の使用`strip()`競技プログラミング環境ではよくあることですが、入力に末尾の空白が含まれている場合でも、安全な解析が保証されます。

import sys, io

def solve():
    n = int(sys.stdin.readline().strip())
    print(n - 1)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdout = old_stdout
    return out.strip()

# provided sample style cases

 ## 特殊なケース

 構造的に意味のある唯一のエッジケースは、配列の長さが最小限である場合です。 入力用$n = 1$の場合、計算は直接続行されます。1 を読み取り、1 を減算し、0 を出力します。これは、単一要素配列のインデックスが 0 のみであるという事実と一致します。減算ルールから逸脱すると、このケースは即座に破綻するため、ロジック全体の正確性のアンカーとして役立ちます。
