 ## 解決策
 ## 問題の理解

 私たちは 1 から n までの一次元の数直線を扱っています。 この線上には 2 種類の特別なポイントがあります。独立したエージェント (文中ではキャットワームと呼ばれます) の p 個の開始位置と、k 個のテレポート ポータルです。 目標位置 g も 1 つあります。 各エージェントは最短時間で g に到達したいと考えています。 

動きは決定的かつ均一です。左右に 1 単位ずつステップすると、1 時間単位のコストがかかります。 この直線的な動きを変更する唯一の方法は、ポータルを使用することです。 エージェントがポータルの位置に到着すると、それを無視して通常どおり歩き続けるか、厳密に左側または厳密に右側にある最も近いポータル (ポータルが存在する場合) に 1 単位時間でエージェントを送信するテレポート アクションをアクティブにすることができます。 

したがって、基礎となる構造は、線上の点に加えて、連続するポータル間の特別な「ジャンプ エッジ」を含むグラフです。 各ポータルは左右の最も近いポータルに接続し、チェーンを形成します。 各テレポート エッジは重み 1 を持ち、通常の移動も隣接する整数位置間の単位重みになります。 

各開始位置について独立して、g に到達する最短時間を計算する必要があります。 

制約は大きく、n は最大 10^9 なので、明示的にラインを構築することはできません。 p と k は最大 10^5 であるため、ポータルに対するクエリごとの線形スキャンは単純に繰り返すと遅すぎます。 構造は静的であるため、前処理が必要です。 

素朴な解釈では、すべての整数を含むグラフ上でダイクストラを使用して各開始位置からの最短経路をシミュレートしようとするかもしれませんが、これは座標範囲のサイズにより不可能です。 ポータルに限定したとしても、任意の位置とポータル間の移動を効率的に処理する必要があります。 

微妙だが重要なエッジ ケースは、まさに到着の瞬間のポータルの選択から生じます。 たとえば、ポイントがポータル上にある場合、エージェントはそれを無視するか、すぐにテレポートすることを選択する可能性があり、最適な戦略では、ポータルに到達したときに必ずしもポータルを使用する必要はない場合があります。 

## アプローチ

 ポータルを完全に無視すると、各エージェントの答えは単に g までの絶対距離になります。 これは、テレポーテーションが役に立たない場合には正しく、ベースラインの O(p) ソリューションを提供します。 

ポータルを導入すると、頂点が位置であるグラフ上の最短経路に問題が変わりますが、そのうちの k 個だけが特別な長距離エッジを持ちます。 重要な観察は、ポータルの場所とポータル間のセグメントの終点を除いて、任意の位置を決定点として考慮する必要がないということです。 テレポートを使用する最適なパスは常に、おそらくポータル以外の位置から歩いた後、何らかのポータルに到着します。 

ブルートフォース手法では、開始位置ごとに、すべての整数位置をノードとして扱う BFS またはダイクストラを実行します。 各ノードには、隣接ノードおよびポータル ジャンプへのエッジがあります。 状態空間のサイズが n (最大 10^9) であるため、これはすぐに失敗します。 

ノードをポータルと開始点/終了点のみに制限した場合でも、任意の点とポータル間の歩行距離を考慮する必要があります。 これは、ソートされたポータルによって定義された間隔に問題を圧縮することを示唆しています。 

ポータルが並べ替えられると、各ポータルは並べ替えられた順序ですぐ隣のポータルにのみ接続します。 つまり、テレポーテーションは、ソートされたポータル リスト上に単純な折れ線グラフを形成します。 残りのコストは、任意の位置から近くのポータルまで、または直接 g までの徒歩距離です。

重要な洞察は、点 x を固定すると、g への最適なパスには少数の構造形式しか存在しないということです。 g まで直接歩くか、最初にいくつかのポータルまで歩き、必要に応じてポータル チェーンに沿ってテレポートし、最終的にポータルから出て g に到達します。 テレポート エッジは常にコスト 1 を持ち、隣接するポータルを接続するため、ポータル ネットワークは直線上の最短パス問題となり、2 回のスイープで事前計算できます。 

したがって、ソートされたポータル配列の 2 方向 DP を使用して、すべてのポータルから g までの最短距離を事前に計算し、それを各開始点から最も近いポータルまでの歩行距離と組み合わせることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとの直接最短パス (グラフ展開) | O(p・n) | O(n) | 遅すぎる |
 | ポータル グラフの前処理 + クエリごとの計算 | O((p + k) log k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべてのポータルの位置が直線状のチェーンを形成するように並べ替えます。 

次に、すでにそのポータルに立っていると仮定して、各ポータルから始めて g に到達するコストを計算します。 これは、サイズ k の折れ線グラフ上の最短経路問題に帰着します。ここで、各ポータルにはコスト 1 の隣接するポータルへのエッジがあり、さらに各ポータルは絶対距離に等しいコストで g まで直接歩くことができます。 

ソートされたポータル上で 2 つのパスで動的計画緩和を実行します。 

まず、ポータル i から g まで直接歩くコストとして dp[i] を初期化します。 

次に、左から右にスイープし、dp[i-1] に隣接するポータル間のテレポートのコストを加えた値から dp[i] を更新します。 

その後、右から左にスイープして対称的な緩和を行います。 これら 2 つのパスの後、dp[i] は、徒歩またはチェーンに沿った一連のテレポーテーションの使用により、ポータル i から g までの可能な最良のコストを表します。 

すべてのポータルの dp を取得したら、各開始位置を個別に回答します。 

開始位置 x について、ポータル システムに入る最適な方法を計算します。 これは、二分探索を使用して x の左右に最も近いポータルを見つけることによって行われます。 

x から g まで直接歩くことも、ポータル i まで歩いてから dp[i] を支払うこともできます。 

したがって、答えは直線距離 |x − g| の中で最小になります。 そして、左または右のポータルが存在する場合、 |x − portal| + dp[ポータル]。 

### なぜ効果があるのか

 ポータル グラフはパス グラフであるため、一連のテレポートはこのパスに沿って移動することと同等です。 すべてのテレポート エッジのコストは等しく、隣接するノードのみを接続するため、この構造上の最短パスは 2 方向の緩和によって完全に捕捉されます。 ポータルから g までの最適なルートは、あるポータルから純粋に歩く最終セグメントと、ポータル チェーンに沿ってのみ移動する以前のセグメントに分解できます。 DP は、チェーンに沿った両方向の移動を考慮することを保証するため、有益な迂回路を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, p, k, g = map(int, input().split())
    a = list(map(int, input().split()))
    b = sorted(map(int, input().split()))

    # dp[i] = cost from portal i to g
    dp = [0] * k

    for i in range(k):
        dp[i] = abs(b[i] - g)

    # left to right relaxation
    for i in range(1, k):
        dp[i] = min(dp[i], dp[i-1] + 1)

    # right to left relaxation
    for i in range(k-2, -1, -1):
        dp[i] = min(dp[i], dp[i+1] + 1)

    # helper: lower_bound
    import bisect

    res = []
    for x in a:
        best = abs(x - g)

        i = bisect.bisect_left(b, x)

        if i < k:
            best = min(best, abs(x - b[i]) + dp[i])

        if i > 0:
            best = min(best, abs(x - b[i-1]) + dp[i-1])

        res.append(str(best))

    print(" ".join(res))

if __name__ == "__main__":
    solve()
```コードは、リスト内の隣接関係がライン上の実際の左右の隣接関係に対応するように、ポータルの位置を並べ替えることから始まります。 dp 配列には、各ポータルから出口 g までの最もよく知られているコストが格納されます。 初期値は単に g まで直接歩くことです。 

2 つの緩和パスは、パス グラフ上で最短パスの伝播を実装します。 左から右へのパスでは、左隣のポータルと 1 つのテレポート コストを経由してポータルに到達できます。 右から左へのパスは逆方向を対称的に処理し、情報がチェーンに沿って両方向に伝播することを保証します。 

各開始位置について、二分探索を使用して最も近いポータルの隣接位置を特定します。 ポータル システムに入る最適なパスは最初にポータルに到達する必要があり、いずれかの方向で最も近いエントリ ポイントが他のすべてのエントリ ポイントよりも優先されるため、重要となるのはこれら 2 つの候補だけです。 次に、そのポータルへの歩行コストと事前計算された dp 値を組み合わせて、G への直接歩行と比較します。 

よくある落とし穴は、開始点がすでにポータルであるか、2 つのポータルの間にある可能性があることを忘れることです。 どちらの場合も、二分法を介して両方の近傍を考慮することで自然に処理されます。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
n=10, p=2, k=2, g=7
a = [2, 8]
b = [4, 7]
```まずポータルを [4, 7] として並べ替えます。 

初期 dp 値は次のとおりです。 

| 私 | ポータル | |ポータル - g| |

 |---|--------|-------------|

 | 0 | 4 | 3 |

 | 1 | 7 | 0 |

 左から右へのリラックス後:

 | 私 | 前の dp | |後の dp
 | --- | --- | --- |
 | 0 | 3 | 3 |
 | 1 | 0 | 最小(0, 3+1)=0 |

 右から左への緩和後:

 | 私 | 前の dp | |後の dp
 | --- | --- | --- |
 | 1 | 0 | 0 |
 | 0 | 3 | 最小(3, 0+1)=1 |

 最終的な dp = [1, 0]。 

次にクエリを評価します。 

x = 2 の場合、直接コストは 5 です。最も近いポータルは 4、コストは |2-4| です。 + dp[0] = 2 + 1 = 3。 

x = 8 の場合、直接コストは 1 です。最も近いポータルは 7、コストは |8-7| です。 + dp[1] = 1 + 0 = 1。 

これはサンプル出力 3 1 と一致します。 

このトレースは、ポータル 4 が有用になるのは、ポータル 7 を安価に経由できるためだけであることを示しています。

| スペース | O(k) | dp 配列とソートされたポータル リスト |

 ## 特殊なケース

 微妙なケースの 1 つは、開始位置がちょうどポータル上にある場合です。 その場合、bisect の結果はそのポータル インデックスを指し、アルゴリズムは追加の処理を必要とせずに自然に dp[i] を考慮します。 たとえば、x が b[i] に等しい場合、コストは dp[i] になり、即時のテレポートの使用または直接の歩行が正しく許可されます。 

もう 1 つのケースは、ポータルが 1 つしかない場合です。 その後、両方の緩和パスは意味のあることを何も行わず、dp は単純な値 |b[i] - g| に減少します。 正解は min(|x - g|, |x - b[0]| + |b[0] - g|) になります。これは、ポータルはチェーンではなくリレーとしてのみ機能するという直観と一致します。 

最後のエッジケースは、ポータルが完全に g の片側にある場合です。 直接ウォーキングの初期化によってすでに正しい距離が取得されており、チェーンに沿った伝播によって無効なショートカットが導入されないため、DP は引き続き機能します。
