 ## 解決策
 ## 問題の理解

 私たちはプログラミング コンテストの出場者グループを与えられました。 各出場者は一連の問題を解決しており、このセットは A から Z までの異なる大文字の文字列としてエンコードされます。文字列の長さが解決した問題の数になります。 たとえば、「ACD」のような文字列は、出場者が 3 つの問題を解決したことを意味します。 

ランキング ルールは 2 層の辞書順になっています。 まず、出場者は解決した問題の数によって順位付けされ、解決した問題の数が多いほど、常に問題の少ない出場者よりも先に順位が付けられます。 第二に、同じ数の問題を解いた出場者の間での相対的な順位はペナルティ時間に依存します。 重要な点は、ペナルティタイムが与えられないことです。 我々が知っているのは解決されたカウントだけであり、ルールに従って任意の個別のペナルティ時間を割り当てた場合に、可能な完全なランキングが何回あるかを数えたいと考えています。 

したがって、不確実性は完全に同じ長さの文字列のグループ内にあります。 同じ長さの各グループは、それ自体の間で任意に並べ替えることができますが、グループの全体的な順序は長さを減少させることによって固定されます。 

入力サイズ n は最大 100000 です。各文字列は最大 26 文字です。 これにより、出場者のすべての順列に対する階乗列挙や、ペナルティの割り当てを明示的にシミュレートする試みが即座に除外されます。 サイズ k の単一グループ内であっても、k が大きい場合、k 階乗は実行不可能になります。 

微妙な点は、文字列は必ずしも一意ではないということです。 複数の出場者が同一の解決済みセットを持つ可能性がありますが、ペナルティタイムは異なることが保証されているため、順序付けの際に区別することができます。 つまり、同一の文字列は同じバケット内の別個の要素のように動作します。 

単純な間違いは、長さで並べ替えるだけでグループ サイズの階乗を乗算すればよいと考えることです。 これは実際には数学的には正しいですが、モジュラー算術処理や事前計算を行わずに階乗を直接計算しても問題はありません。 本当の隠れた問題は階乗サイズではなく、長さによって正しくグループ化し、多重度をカウントすることです。 

もう 1 つの微妙なエッジケースは、出場者全員が異なる長さを持っている場合です。 この場合、順序は完全に決定されるため、有効なランキングは 1 つだけです。 不用意なアプローチでは、サイズ 1 のグループの階乗を乗算する可能性があります。これは問題ありませんが、グループ化ロジックの誤解を示すことがよくあります。 

## アプローチ

 強引な解釈では、区別性と一致するペナルティ時間のすべての可能な割り当てを考慮し、誘導されたランキング順序を計算します。 課題ごとに、出場者の順列を導き出し、異なる順列がいくつ出現するかを数えます。 ペナルティ時間は等しい長さのグループ内でのみ関連するため、これは各グループ内のすべての順列を考慮することになります。 

サイズ k の 1 つのグループに焦点を当てると、内部順序数は k 階乗になります。 グループは独立しているため、合計の答えは、すべての長さの値にわたるグループ サイズの階乗の積になります。 

ペナルティ時間は同じ長さのクラス内での全体的な順序付けのみを誘発し、クラス間の順序付けには影響を与えないため、ブルート フォース ビューが機能します。 ただし、ペナルティ割り当てを明示的に生成または推論することは不必要であり、遅すぎます。 ペナルティの順序付けは、各固定サイズのバケット内で任意の順列を選択することと同じであることがわかります。 

したがって、問題は、解決された数によって出場者をグループ化し、係数に基づいてグループ サイズの階乗を乗算することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ペナルティに対するブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | サイズ + 階乗積でグループ化 | O(n + 26) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 考えられるそれぞれの解決済みカウントをバケットとして処理して進めます。

1. 各出場者について、文字列の長さを計算します。 これは、グループ間のランキングに影響を与える唯一の値です。 
2. 0 から 26 までの各長さの値に該当する出場者の数を数えます。各文字列の長さは最大 26 であるため、サイズ 27 の固定サイズの配列のみが必要です。これにより、グループ化は出場者ごとに定数時間になります。 
3. 1e9+7 を法とする n までの階乗を事前計算します。 これが必要なのは、各グループが階乗項に寄与しており、直接計算を繰り返すと遅すぎるためです。 
4. 答えを 1 として初期化します。 
5. 各長さのバケットについて、答えに階乗[count]を掛けます。ここで、count はそのバケット内の出場者の数です。 count が 0 または 1 の場合、寄与度は 1 であり、答えは変わりません。 乗算は、そのグループ内で可能な内部ペナルティ順序付けの数を反映します。 
6. 最終結果のモジュロ 1e9+7 を出力します。 

なぜそれが機能するのかは、ランキング ルールの構造に由来します。 すべての出場者は、解決した数によって同等のクラスに分割されます。 クラス間のグローバルな順序付けは固定されており、サイズによって厳密に減少するため、クラス間のインターリーブは不可能です。 各クラス内では、ペナルティ時間は明確になるようにのみ制約されます。これは、そのクラスの順列を選択することと同じです。 クラスは独立しているため、ランキングの総数は各クラスの順列の積、つまりクラス サイズの階乗の積になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

n = int(input())
cnt = [0] * 27

lengths = []
for _ in range(n):
    s = input().strip()
    cnt[len(s)] += 1

fact = [1] * (n + 1)
for i in range(1, n + 1):
    fact[i] = fact[i - 1] * i % MOD

ans = 1
for c in cnt:
    ans = (ans * fact[c]) % MOD

print(ans)
```この実装では、まず入力を文字列長でインデックス付けされた周波数バケットに圧縮します。 これにより、カウントのみが重要となるため、出場者を個別に保存したり並べ替えたりする必要がなくなります。 

階乗テーブルは線形時間に 1 回構築されます。 各バケットの乗算では階乗値に高速にアクセスする必要があるため、これは不可欠です。 

最後に、答えは各バケット サイズの階乗を累積します。 可換性があるため、乗算の順序は関係ありませんが、27 の可能な長さすべてを反復処理することで、ロジックが単純になり、グループの欠落が回避されます。 

よくある実装上の間違いは、複数の参加者が同じ文字列長を共有できることを忘れていることです。これにより、誤ってグループのサイズが 1 に縮小され、答え 1 が生成されてしまいます。もう 1 つの間違いは、事前計算ではなくループ内で階乗を繰り返し再計算することです。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def solve():
    input = sys.stdin.readline
    n = int(input())
    cnt = [0] * 27
    for _ in range(n):
        s = input().strip()
        cnt[len(s)] += 1

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    ans = 1
    for c in cnt:
        ans = ans * fact[c] % MOD

    print(ans)

def run(inp: str) -> str:
    global output_capture
    old_in = sys.stdin
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    old_out = sys.stdout
    sys.stdout = out
    solve()
    sys.stdout = old_out
    sys.stdin = old_in
    return out.getvalue().strip()

# sample
assert run("3\nABC\nABCD\nABCD\nDBAE\n") == "6"

# minimum size
assert run("1\nA\n") == "1"

# all distinct lengths
assert run("3\nA\nAB\nABC\n") == "1"

# all same length
assert run("4\nA\nB\nC\nD\n") == "24"

# mixed
assert run("5\nA\nB\nC\nDE\nDE\n") == str((2*1) % MOD)
