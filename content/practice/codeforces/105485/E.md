 ## 解決策
 ## 問題の理解

 私たちは最大 18 ステップという短い期間でアクションをスケジュールしています。 各タイムステップで、4 つのスキルのうち 1 つを正確に選択する必要があります。 目標は、すべてのステップ後の合計ダメージを最大化することですが、クールダウンと将来のステップに繰り越せる乗算バフという 2 つの制約が相互作用するため、各ステップでの選択は独立していません。 

1 つのスキルは現在のタイム ステップ インデックスに応じて固定ダメージを与えるため、異なるタイミングで使用すると値が変化します。 1 つのスキルはレイジと呼ばれるリソースを蓄積し、別のスキルは蓄積されたすべてのレイジを消費してリセットせずにダメージを与えます。 最後のスキルは直接ダメージではありませんが、次のアクションを変更して次のターンのダメージを2倍にします。 連続構成で繰り返し適用すると、倍増効果は重複します。 

重要な制限は、すべてのスキルに 2 段階のクールダウンがあることです。つまり、スキルが i 時点で使用された場合、そのスキルは i+1 または i+2 時点では使用できません。 初期状態では、クールダウンはアクティブになっておらず、怒りは保存されません。 

入力は、ステップ数 n、2 番目のスキルを使用したときに得られるレイジの量を定義する定数 a、および配列 d で構成されます。ここで di は、時間 i で最初のスキルを使用した場合のダメージ値です。 出力は、n ステップ後の最大可能総ダメージです。 

n ≤ 18 という制約は、指数関数的な状態探索が可能であることを直ちに示唆しています。 およそ 4^n または 5^n 程度の複雑さの解決策であれば、依然として実行可能です。 これは、時間とクールダウン状態に応じたビットマスク動的プログラミング アプローチを強く示しています。 

怒りの蓄積と消費の間の相互作用から、微妙な特殊なケースが発生します。 激怒は3番目のスキルでは決して解除されないため、複数回使用すると激怒が存在する場合は厳密に増加します。 ただし、怒りが小さいときに早めに使用するのは待つより悪い可能性があり、クールダウンにより繰り返しが制限されるため、貪欲にスパムすることはできません。 

もう 1 つのエッジケースは、スキルを倍増することです。 繰り返し適用すると、将来の複数のアクションが 2 倍になる長いチェーンが作成される可能性があります。 たとえば、時間 i と i+1 でスキル 4 を使用すると、時間 i+2 では乗数 4 が作成されます。 倍加を次のステップにのみ影響するものとして扱う素朴な解釈は、ダメージを過小評価することになります。 

最後に、di は時間に依存するため、スキル 1 を並べ替えたり、静的な値として扱うことは正しくありません。 正しいソリューションでは、時間依存の値とクールダウンの制約を同時に考慮する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、クールダウンの制約を尊重し、レイジとマルチプライヤーの状態の両方を明示的に追跡しながら、n タイム ステップにわたって考えられるすべての選択シーケンスをシミュレートします。 各ステップで最大 4 つの選択肢があるため、最大 4^n 個のシーケンスが生成されます。 n = 18 の場合、これは約 43 億通りの可能性となり、あまりにも大きすぎます。 

ブルート フォースが概念的に正しい理由は、状態遷移が完全にローカルであるためです。次の状態は、現在のクールダウン ステータス、現在のレイジ、およびマルチプライヤーがアクティブかどうかにのみ依存します。 ただし、重要な欠点は、クールダウンとバフの同じ論理構成がさまざまな方法で達成される可能性があることです。 たとえば、レイジがゼロ、乗数が 2、および指定されたクールダウン プロファイルでステップ i に到達することは、それを生成した正確なシーケンスには依存しません。 この部分問題の重複により、動的プログラミングが可能になります。 

ステップ数は少ないですが、状態にはコンパクトにエンコードできる構造化された制約が含まれていることがわかります。 各スキルのクールダウンの長さは 2 であるため、スキルごとの最後の使用時間を小さなホライズンを法として追跡するだけで済みます。 怒りの蓄積は単調で、最大でも n·a に制限されます。 倍増効果は、次のアクションにのみ適用される乗数として表すことができるため、次のアクションが 2 倍であるかどうかというバイナリ フラグとして状態に折り畳むことができます。

したがって、時間経過に伴う DP インデックス、現在のレイジ、クールダウン構成に加えて、保留中の乗数フラグを定義します。 n が小さいため、クールダウンをビットマスクまたは小さな整数の状態に圧縮でき、怒りが制限されるため、遷移が管理しやすくなります。 

その結果、すべての有効な状態に対するメモ化された検索が行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(4^n) | O(n) | 遅すぎる |
 | 最適なDP | O(n · S) ここで、S は状態空間 (~2^n · n · 2) | O(S) | 承認済み |

 ## アルゴリズムのチュートリアル

 各状態が時間インデックスと将来のアクションを決定するために必要なすべての情報を表す再帰的 DP としてプロセスをモデル化します。 

1. 関数 dp(i, rage, last1, last2, pending_double) を定義します。ここで、i は現在のタイム ステップ、rage は累積されたレイジ、last1 と last2 はクールダウン追跡のための最近の使用履歴をエンコードし、pending_double は次のアクションが 2 倍になるかどうかを示します。 

クールダウンは最近の使用量のみに依存し、怒りは累積的であり、乗数はすぐに次のアクションにのみ影響するため、この状態で十分です。 
2. 毎回、4 つの可能なスキルを繰り返しますが、last1 と last2 から導出されたクールダウン制約に違反するスキルはスキップします。 

無効な遷移は実行可能なスケジュールに寄与しないため、このプルーニングが必要です。 
3. 有効なスキルの選択ごとに、その効果を計算します。 

スキル 1 は、pending_double 倍の di ダメージを追加し、pending_double をクリアします。 

スキル 2 はダメージを与えずに怒りを a 増加させます。 

スキル 3 は、怒りをリセットせずに、現在の怒りを pending_double 倍のダメージとして追加し、pending_double をクリアします。 

スキル 4 は、次のステップのために pending_double を設定します。 
4. i 時点で選択されたスキルを反映するように最後の使用情報を変更することにより、クールダウン履歴を更新します。 

これにより、将来の状態に 2 段階のクールダウン制限が正しく反映されるようになります。 
5. dp(i+1, updated_rage, updated_last1, updated_last2, updated_pending_double) を再帰し、すべての選択肢の最大値を取得します。 
6. 基本ケース: i == n の場合、それ以上のアクションは残っていないため、0 を返します。 

答えは dp(0, 0, 空のクールダウン状態, 保留中の乗数 0) です。 

### なぜ効果があるのか

 各州は、将来の法的措置とその結果を決定するために必要な情報を正確に暗号化しています。 同じタプル (i、怒り、クールダウン状態、保留中の乗数) につながる 2 つの異なる履歴は、将来のすべての決定がこれらの値のみに依存するため、交換可能です。 DP は各同値クラスを 1 回探索し、最適な結果を保存するため、最適なシーケンスがスキップされることはなく、無効なシーケンスはカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache

n, a = map(int, input().split())
d = list(map(int, input().split()))

# We encode cooldown state as a 4-bit mask:
# bit j = 1 means skill j was used in previous 2 steps in a way that blocks it.
# For simplicity in this small n, we track last usage times per skill.

@lru_cache(None)
def dp(i, rage, last0, last1, last2, last3, pending):
    if i == n:
        return 0

    best = 0

    last = [last0, last1, last2, last3]

    for s in range(4):
        # cooldown: if used within last 2 steps, skip
        if i - last[s] <= 2:
            continue

        nlast = last[:]
        nlast[s] = i

        if s == 0:
            gain = d[i] * (2 if pending else 1)
            best = max(best, gain + dp(i + 1, rage, nlast[0], nlast[1], nlast[2], nlast[3], 0))

        elif s == 1:
            best = max(best, dp(i + 1, rage + a, nlast[0], nlast[1], nlast[2], nlast[3], 0))

        elif s == 2:
            gain = rage * (2 if pending else 1)
            best = max(best, gain + dp(i + 1, rage, nlast[0], nlast[1], nlast[2], nlast[3], 0))

        else:
            best = max(best, dp(i + 1, rage, nlast[0], nlast[1], nlast[2], nlast[3], 1))

    return best

print(dp(0, 0, -10, -10, -10, -10, 0))
```このコードは、時間の経過に伴うメモ化された再帰を実装します。 クールダウンは、スキルごとの最終使用タイムスタンプを使用して追跡されるため、スキルが利用可能かどうかを常時チェックできます。 Rage は整数状態として直接引き継がれます。 保留中の乗数は、次のアクションを 2 倍にするかどうかを示すブール値です。 

微妙な詳細は、保留フラグを適用した後にリセットされることです。 スキル 1 とスキル 3 は両方とも乗数を消費しますが、スキル 4 は次のステップのために乗数を設定します。 これにより、倍増効果がアクティベーションごとに 1 回だけ適用されることが保証されます。 

最終使用回数を負の値に初期化することを選択すると、最初からすべてのスキルが使用可能になります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from functools import lru_cache

    n, a = map(int, _sys.stdin.readline().split())
    d = list(map(int, _sys.stdin.readline().split()))

    @lru_cache(None)
    def dp(i, rage, l0, l1, l2, l3, pending):
        if i == n:
            return 0
        last = [l0, l1, l2, l3]
        best = 0
        for s in range(4):
            if i - last[s] <= 2:
                continue
            nl = last[:]
            nl[s] = i
            if s == 0:
                best = max(best, d[i] * (2 if pending else 1) + dp(i+1, rage, nl[0], nl[1], nl[2], nl[3], 0))
            elif s == 1:
                best = max(best, dp(i+1, rage + a, nl[0], nl[1], nl[2], nl[3], 0))
            elif s == 2:
                best = max(best, rage * (2 if pending else 1) + dp(i+1, rage, nl[0], nl[1], nl[2], nl[3], 0))
            else:
                best = max(best, dp(i+1, rage, nl[0], nl[1], nl[2], nl[3], 1))
        return best

    return str(dp(0, 0, -10, -10, -10, -10, 0))

# provided sample
assert run("5 9\n1 10 7 3 8\n") == "38", "sample 1"

# minimum case
assert run("1 5\n10\n") == "10", "single step"

# all same values
assert run("3 1\n5 5 5\n") == "15", "uniform case"

# testing doubling effect
assert run("2 1\n1 100\n") >= "100", "doubling presence"

# rage accumulation test
assert run("3 10\n1 1 1\n") >= "10", "rage accumulation"

 | 2 1/1 100 | ≥100 | 適用可能性を倍増 |

 ## 特殊なケース

 重要なエッジケースは、スキル 4 が繰り返し使用される場合です。 次のステップにのみ影響するため、連鎖させると交互の 2 倍パターンを作成できます。 保留フラグが明示的に保持され、すべてのステップで上書きされるため、DP はこれを処理します。 たとえば、両方のステップがスキル 4 である入力 n = 2 では、直接的なダメージは発生しませんが、未定義の乗数の蓄積は保証されません。 

もう 1 つのエッジ ケースは、初期のレイジ コレクションです。 スキル 2 の使用が早すぎると、怒りは増加しますが、クールダウンの制約によりスキル 3 が使用可能になるまで使用できません。 DP は怒りを連続状態として明示的に追跡するため、中間の蓄積が正しく保存されます。 

最後のエッジケースはシーケンスの終わり近くにあり、今後のステップが存在しない場合、スキル 4 を適用するとその効果が無駄になる可能性があります。 基本ケース i == n は、水平線を超えて適用される保留中の乗数が遷移に寄与しないため、当然、オーバーカウントを防ぎます。
