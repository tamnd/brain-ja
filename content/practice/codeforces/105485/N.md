 ## 解決策
 ## 問題の理解

 私たちは一連の数字を与えられ、固定された数の操作を実行することができます。 各操作では単一の位置が選択され、その値がちょうど 1 だけ減ります。 これを合計 k 回まで実行した後、「谷」になるインデックスの数を最大化したいと考えます。 

谷は内部位置 i であり、最初または最後の要素になることはできないことを意味し、その値はすべての変更後の両方の隣接要素よりも厳密に小さくなります。 したがって、選択された減分の構成について、多くの内部点が極小になるように配列を整形しようとしています。 

重要な制約は、各操作が非常にローカルであるということです。つまり、1 つの要素のみが削減されるということです。 値を増やすことはありません。そのため、位置 i に谷を作成する唯一の方法は、ai を下げるか、隣接する ai を下げすぎないようにして、ai が ai−1 および ai+1 に比べて十分に小さくなるようにすることです。 

入力サイズ n は最大 10^5、k は最大 10^9 です。 配列の値が大きくなる場合もあります。 この組み合わせにより、k 個の操作にわたるシミュレーションが即座に除外されます。 有効な解決策は、構造的に形成できる谷の数と、各谷にどれだけの「労力」が必要かを推論する必要があります。 

谷が重なると微妙な問題が発生します。 すべての位置で独立して谷を強制的に強制しようとすると、1 つの要素を変更すると 2 つの潜在的な谷の条件に影響を与えるため、共有コストを過小評価したり、達成可能な谷を過大評価したりする可能性があります。 もう 1 つの失敗例は、高さの違いによっては、隣りのものを低くした方がコストが安くなる場合があるのに、中心だけを低くすることが常に最適であると想定していることです。 

## アプローチ

 この強引なアイデアは、操作をシミュレートし、k 個のデクリメントをポジション間で分散するあらゆる可能性を試すことです。 各仮説の分布の後、谷がいくつ存在するかを確認します。 これは、考えられるすべての方法で k 単位の減少を n 位置に分散することに相当し、組み合わせ的に膨大になります。 列挙を無視しても、単一の構成の評価は O(n) であり、構成の数は星と棒のオーダーであり、実行可能な制限をはるかに超えています。 

より構造化された強引な方法は、貪欲に谷を 1 つずつ構築することです。 各候補位置 i について、近傍が固定されていると仮定して、ai を両方の近傍より厳密に小さくするために必要な減分数を計算します。 次に、最も安い谷を繰り返し選択します。 これは失敗します。インデックスを変更すると、近くの谷のコストが変化するため、ローカルで再計算しても選択ごとに O(n) 回のスキャンが繰り返され、O(n^2) が得られるためです。 

重要な観察は、谷が非常に特殊な形で独立しているということです。つまり、i の谷はトリプル (i−1, i, i+1) にのみ依存します。 位置 i が谷であると判断した場合、唯一の要件は、ai が隣接する両方の値より厳密に小さくなければならないことです。 値を減らすことしかできないため、近傍を増やすことは決して望まれません。 したがって、谷を形成するための最良の戦略は、隣接する AI ではなく AI のみを減らすことです。隣接する AI を下げると、この谷を助けずに他の谷が難しくなるだけだからです。 

したがって、固定 i の場合、それを谷にするためのコストは次のようになります。 

コスト(i) = max(0, min(ai−1, ai+1) − (ai − 1) + 1)

 これは次のように単純化されます。 

コスト(i) = max(0, ai − min(ai−1, ai+1) + 1)

 谷を建設する際に隣接する谷には決して触れないため、各谷のコストは独立しています。 したがって、問題は、コストの合計が k を超えないように、できるだけ多くのインデックス i を選択することになります。 

これは古典的な貪欲な選択問題になります。つまり、すべてのコストを計算し、並べ替えて、最小のコストを最初に選択します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 / O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

私たちは、問題を独立した「谷のコスト」に変換し、予算内で最大の数値を選択することに重点を置いています。 

1. 2 から n−1 までのすべてのインデックス i について、m = min(ai−1, ai+1) を計算します。 この値は、ai が谷になるために下回る必要があるしきい値を表します。 
2. ai がすでに厳密に m より小さい場合、i はすでに演算を必要としない谷の候補です。 それ以外の場合は、必要な減分数をコスト = ai − m + 1 として計算します。これは、ai を両方の近傍より厳密に小さくするために必要な最小量です。 
3. かかるコストをすべてリストにまとめます。 各コストは、他の位置に影響を与えることなく、その位置の谷を「アクティブ化」するのにどれだけのコストがかかるかを表します。 
4. コストのリストを降順でない順に並べ替えます。 この順序により、作成するのに最も安価な谷が優先されるようになります。 
5. 使用された操作の累計を維持しながら、ソートされたリストをスキャンします。 各コストについて、それを加算しても k を超えない場合は、それを含めて答えを増分します。 それ以外の場合は、それ以上の組み込みを停止またはスキップします。 
6. 選択した谷の数を返します。 

### なぜ効果があるのか

 各谷の要件はトリプルに対してローカルであり、純粋に中心要素を減らすことによって満たすことができます。 操作は値を減らすだけなので、隣接する谷に触れても別の谷のコストを減らすことはできません。 他の場所で間接的にコストが増加するリスクがあるだけです。 したがって、各バレーは固定価格の独立したアイテムとして扱うことができます。 タスクは総予算内でアイテムの数を最大化することになります。各アイテムは等しい値 (1 つの谷) を持ち、コストのみが異なるため、最小コストによる貪欲な選択が最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    costs = []
    
    for i in range(1, n - 1):
        m = min(a[i - 1], a[i + 1])
        if a[i] < m:
            costs.append(0)
        else:
            costs.append(a[i] - m + 1)
    
    costs.sort()
    
    ans = 0
    used = 0
    
    for c in costs:
        if used + c <= k:
            used += c
            ans += 1
        else:
            break
    
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、谷の形成から独立したコストへの削減を直接実装します。 内部インデックスに対するループは、位置ごとに必要な最小限のデクリメントを計算します。 ソートは常に最も安価な谷に最初に操作を費やし、固定予算 k の下でカウントを最大化するため、ソートが不可欠です。 

実装の微妙な詳細は、コストがゼロになる、すでに有効な谷の処理です。 これらは操作を消費しないため、最初に実行する必要があります。 貪欲なループには、当然のことながら、それらがすぐに組み込まれます。 

## 実用的な例

 動作を説明するために 2 つのトレースを作成します。

```コストの計算:

 | 私 | ai−1 | あい | あい+1 | 分 | コスト |
 | --- | --- | --- | --- | --- | --- |
 | 2 | 3 | 1 | 3 | 3 | 0 |

 | ステップ | コスト | 中古 | 谷 |

これは、ゼロコストの谷が常に最初に取られ、有料の谷とは相互作用しないことを示しています。

 | ステップ | コスト | 中古 | 谷 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | コンピューティングコストは直線的であり、ソートが支配的です。 
| スペース | O(n) | 店舗コスト一覧 |

 n ≤ 10^5 という制約により、O(n log n) は快適に高速になります。 k を反復せずにコストを累積するだけなので、10^9 までの k の値の範囲は無関係です。

## 特殊なケース

 最初のエッジ ケースは、n ≤ 2 の場合です。内部インデックスがないため、アルゴリズムは自然に空のコスト リストを生成します。 たとえば、入力`n=2`どの位置も谷の定義を満たすことができないため、常に 0 を返します。 

もう 1 つのケースは、多くの谷が操作なしですでに有効になっている配列です。 入力用`5 0`と配列`[5,1,5,1,5]`、すべての内部位置はすでに谷になっています。 計算されたコストはすべてゼロであるため、アルゴリズムは k を消費せずにすべてを選択します。 

3 番目のケースは、k が非常に大きいが、構造的に谷が制限されている場合です。 のために`[10,9,8,7,6]`、各内部位置のコストは 2 であるため、k=100 であっても最大 2 つの位置が存在することを考慮した場合、谷は 2 つだけ選択できます。 予算が無関係な場合でも、貪欲な選択により正しい構造的最大値が返されます。
