 ## 解決策
 ## 問題の理解

 一連の正の整数が与えられます。 1 回の操作で、2 つの異なる位置 i と j を選択し、i の値を 2 つの値のビット単位の AND に置き換えます。ai は ai & aj になります。 2 番目の値は変更されていないため、この操作では 1 つの要素のみが変更されますが、値は他の要素からビットを「吸収」します。 

目標は、このような操作を最大 n 回実行した後で、配列内のすべての要素をゼロにできるかどうかを判断することです。 

重要な詳細は、ビットごとの AND の性質です。 ビットは両方のオペランドに存在する場合にのみ存続します。 したがって、ai と aj を適用すると、ai からビットが削除されるだけであり、新しいビットが導入されることはありません。 これは、設定ビットに関して値が単調に増加しないことをすでに暗示しています。 

n ≤ 3000 という制約は、O(n²) または O(n² log n) アプローチが潜在的に受け入れられることを示唆しています。 n の 3 次のものは境界線に達しますが、定数によっては最適化された Python で渡される可能性がありますが、クリーンなソリューションではそれを回避する必要があります。 

ローカルで考えると、微妙な特殊なケースが発生します。 素朴な考えは、貪欲に各数値を個別に削減しようとすることですが、これは操作がグローバルに干渉することを無視しています。 もう 1 つの落とし穴は、すべてのビットが配列内に少なくとも 2 回出現すれば、それを削除できると想定していることです。 共有の頻度だけではなく、共有の構造が重要であるため、これは誤りです。 

たとえば、各ビットが存在するが互いに素なコンポーネントに分離されている値がある場合、単純なカウントでは成功が示唆されますが、一連の AND 演算によってそのビットを n ステップ内のどこでも削除できる位置に転送することはできません。 

本当の課題は、AND 演算を繰り返して最終的にすべての数値を 0 にできるグローバル構造を理解することです。 

## アプローチ

 演算 ai = ai & aj には非常に特殊な動作があり、ai を aj のビットのサブセットにします。 セットの観点から考えると、各数値はビットのセットであり、AND は 1 つのセットを別のセットとの共通部分に置き換えます。 

ブルート フォース アプローチでは、最大 n 個の操作のすべての可能なシーケンスをシミュレートします。 各状態は整数の配列であり、各操作は順序付きペア (i, j) を選択します。 これにより、ステップおよび深さ n ごとに n² という巨大な分岐係数が発生するため、状態空間は (n²)ⁿ として爆発しますが、これは完全に実行不可能です。 

目的を達成するには、シーケンスを列挙するのではなく、実際にどのような変換が可能かを理解する必要があります。 

重要な観察は、グローバル AND 構造に注目することです。 配列内のすべての要素のビット単位の AND を計算すると (これを G と呼びます)、交差部分を介して保持できるビットの点で、すべての要素は常に G のスーパーセットのままになります。 ただし、AND 演算では新しいビットが導入されることはありません。したがって、すべて 0 に到達する唯一の方法は、交差カスケードを繰り返すことですべてのビットを削除できるかどうかです。 

重要な構造的洞察は、各ビットを独立して解釈することです。 ビット位置は、各配列要素に存在するか存在しません。 演算 ai = ai & aj は、aj にもそのビットがない限り、ai からそのビットを削除します。 したがって、ビットは、伝播ステップ中にビットを生き続ける何らかの「キャリア」要素によって常にサポートされている場合にのみ生き残ることができます。 

これにより、ビットごとのグラフの解釈が行われます。固定ビットの場合、そのビットが 1 であるすべてのインデックスを考慮します。最終的にすべての出現がそのビットの 0 ホルダーと交差することを強制する一連の操作が存在する場合にのみ、すべての位置からそのビットを削除できます。 最大 n 個の操作が許可されているため、中央ピボット戦略を使用するのに十分な柔軟性があります。

最後の重要なアイデアは、ターゲット状態を構築することです。十分な「破壊的相互作用」を蓄積して、すべてのビットがどこからでも排除されるようにしたいと考えています。 これは、すべてのコンポーネントにわたってゼロを伝播できる一連のペアごとの交差が存在する場合に正確に可能であり、これは、十分なリダクションが実行された後にユニバーサル レデューサーとして使用できる少なくとも 1 つの要素が配列にあるかどうかをチェックすることになります。 

より単純で正しい再定式化が現れます。AND を使用すると常に値を下方向に伝播できるため、最良の戦略は、配列を繰り返しすべての要素のグローバル AND に等しい 1 つの値に折りたたんでから、そのグローバル AND が 0 である場合に限り、0 を伝播することです。 ただし、操作は方向性があり、片側のみが変更されるため、十分な操作の後、配列が少なくとも 1 つの共通のビット チェーンを共有する関係で接続されている場合に限り、すべての要素を強制的にグローバル AND にすることができることをシミュレートできます。 

これにより、要素によって引き起こされるビット単位のグラフが完全な伝播を可能にするのに十分な接続を行っているかどうかをチェックすることが簡素化されます。この問題では、より単純な必要十分条件が解決されます。つまり、すべての要素のビット単位の AND がゼロでなければなりません。そうしないと、すべての要素から同時に削除できないビットが少なくとも 1 つ存在するためです。 

したがって、問題はグローバル AND を計算し、それがゼロかどうかをチェックすることに帰着します。

 ## アルゴリズムのチュートリアル

 配列内のすべての要素のビット単位の AND を計算します。 この値は、すべての数値に存在するビットのセットを表します。 

次に、この結果がゼロかどうかを確認します。 

1. n 個の整数の配列を読み取ります。 
2. 変数 g を配列​​の最初の要素として初期化します。 
3. 配列の残りの部分を繰り返し処理し、各要素の g = g & ai を更新します。 
4. すべての要素を処理した後、g が 0 に等しいかどうかを確認します。 
5. g が 0 の場合は「Yes」を出力し、それ以外の場合は「No」を出力します。 

これが機能する理由は、すべての数値に存在するビットはシステムから決して削除できないためです。 すべての操作では、そのビットを含む少なくとも 1 つの要素にそのビットが保持されます。AND はその共有交差に新しいゼロをグローバルに導入することはないため、そのようなビットをすべての位置から完全に削除することはできません。 逆に、すべての要素に共通のビットがない場合は、すべてのビットが固定交差コアの外側のどこかに表示され、ペアごとの AND 演算を繰り返すことで、すべてのエントリがゼロになるまで配列全体のビットを段階的に削除できます。 

不変条件は、一連の操作の後でも、すべての要素のビット単位の AND が元のグローバル AND と等しいままであることです。 この不変式は、最終的に達成可能な構成を制限します。最終状態がすべて 0 の場合、そのグローバル AND は 0 になるため、最初のグローバル AND も 0 でなければなりません。 逆に、グローバル AND が 0 の場合、すべての要素に永続的にロックされるビットはないため、許容される操作数内で完全な削除が達成できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    a = list(map(int, input().split()))
    
    g = a[0]
    for x in a[1:]:
        g &= x
    
    print("Yes" if g == 0 else "No")

if __name__ == "__main__":
    solve()
```この実装は、グローバルなビットごとの AND の計算への削減に直接続きます。 唯一の微妙な点は初期化です。a[0] から開始すると、ID 値を導入せずに正確さが保証されます。 次に、ループは配列全体で AND を折り畳みます。 

出力条件はゼロまでの厳密な等価性チェックであり、すべての要素に共通のビットがあるかどうかがキャプチャされます。

 ## 特殊なケース

 エッジ ケースの 1 つは、単一要素の配列です。 n = 1 で値がゼロ以外の場合、演算は実行できないため、答えは「いいえ」になります。グローバル AND が要素自体 (ゼロではない) に等しいため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは、すべての要素がすでに 0 である場合です。 グローバル AND はゼロであるため、答えはすぐに「はい」となり、操作が必要ないという事実と一致します。 

3 番目のケースは、一部の要素がゼロで、その他の要素がゼロでない場合です。 ゼロを伴う AND はビットダウンを強制するため、グローバル AND はゼロになり、アルゴリズムは正しく Yes を出力します。これは、ゼロがシステム内でユニバーサル ビットエリミネーターとして機能することを反映しています。
