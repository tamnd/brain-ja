 ## 解決策
 ## 問題の理解

 私たちは、1 年の間にオリンピック イベントが何回開催されるかを数えるよう求められます。 重要な点は、夏季オリンピックと冬季オリンピックという 2 つの独立した一連のイベントがあることです。 それぞれは厳密な周期パターンに従います。 

夏季オリンピックの直近の基準年は 2024 年であることがわかっており、その後は 4 年ごとに繰り返されます。 冬季オリンピックも同様に 2022 年を基準年とし、4 年ごとに繰り返されます。 夏でも冬でも、あらゆる出来事が 1 つのイベントとしてカウントされます。 

L から R までの年間隔が与えられた場合、タスクは、その範囲内にオリンピックの夏と冬が何年入るかを数え、イベントの総数を出力することです。 

L と R は両方とも最大 9999 であるため、競技プログラミングの意味では制約は非常に小さいです。これにより、大きな範囲または高度なデータ構造にわたるシミュレーションの必要性が即座に排除されます。 間隔の長さは約 1 万に制限されているため、O(R − L) スキャンでも技術的には合格しますが、周期構造は一定時間での直接的な算術解を示唆しています。 

単純な落とし穴は、年ごとに反復して、各年がいずれかのシーケンスに一致するかどうかを確認することです。 ここでは安全ですが、意図した数学的構造が隠されてしまいます。 

さらに微妙な問題は、モジュラー アライメントを計算する際に負のオフセットを誤って処理することに起因します。 等差数列を調整しているため、不適切なフロア分割ロジックにより、範囲内の最初の有効なイベントが簡単にスキップされる可能性があります。 たとえば、最初の年 ≥ L の計算に不注意だと、誤って次のサイクルにジャンプしてしまう可能性があります。 

L = 2023、R = 2025 のようなケースを考えてみましょう。冬季オリンピックは 2022 年と 2026 年に近くで開催されます。 区間内の正解は2026年だけ？ 実際には 2026 年は外側にあるため、冬は 0 に寄与し、夏は 2024 年に寄与するので、答えは 1 になります。バグのある実装では、最初の冬の年を誤って 2026 年として計算し、その後包含を誤って処理したり、さらに悪いことに 2022 年を計算して、L より前にあるにもかかわらず誤って包含してしまう可能性があります。 

正しい解法では、閉区間を持つ等差数列の交差を正確にカウントする必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 L から R まで反復し、年ごとに 2 つの進行のいずれかに一致するかどうかを確認します。 年は、2024 プラス 4 の倍数、または 2022 プラス 4 の倍数に等しい場合に有効です。シーケンスが疎であり、モジュラー算術でテストするのが簡単であるため、これが機能します。 

このアプローチでは最大 10,000 回の反復が行われ、それぞれの反復で O(1) チェックが行われるため、合計で約 20,000 回の操作が行われます。 これは制約の下では自明ですが、概念的には拡大縮小できず、周期構造がわかりにくくなります。 

重要な観察は、両方のシーケンスが等差数列であるということです。 範囲内に等差数列の項がいくつあるかをカウントすることは、L 以上の最初の有効な項と R 以下の最後の有効な項を見つけてインデックスをカウントに変換することによって定数時間で行うことができます。 

これにより、問題は 2 つの独立した間隔カウント (進行ごとに 1 つ) に減らされ、それらが合計されます。

 ## アルゴリズムのチュートリアル

 夏と冬のシーケンスは残基クラス モジュロ 4 で重複しないため、独立して扱います。

1. ステップ 4 で年 a から始まる特定のシーケンスについて、[L, R] に含まれる有効な用語の数を計算します。 シーケンスは a、a+4、a+8 などであるため、すべての用語はインデックス k (年 = a + 4k) によって決定されます。 
2. a + 4k ≥ L となる最小のインデックス k を計算します。これには、4k ≥ L − a を解く必要があります。 これを k ≥ (L − a) / 4 に変換し、天井を取ります。 浮動小数点演算の代わりに、k_low = (L − a + 3) // 4 で整数演算を使用します。+3 シフトにより、正と負の差の両方に対して正しい上限動作が保証されます。 
3. a + 4k ≤ R となるような最大のインデックス k を計算します。これにより、整数の下限除算を使用して k_high = (R − a) // 4 が得られます。 
4. k_high ≥ k_low の場合、有効な項の数は k_high − k_low + 1 です。それ以外の場合、区間内に有効な項はありません。 
5. a = 2024 (夏) と a = 2022 (冬) に同じ計算を適用し、両方の結果を合計します。 

割り算のトリックが機能する理由は、両方のシーケンスがギャップや不規則性のない完全に整列した等差数列であるためです。 インデックス変換は、問題を何年にもわたる推論からシーケンス内の整数の位置に関する推論に変換します。 

### なぜ効果があるのか

 各オリンピック シーケンスは、整数インデックス k ≥ 0 に 1 対 1 でマッピングできます。変換 year = a + 4k により、順序と間隔が維持されます。 任意の間隔 [L, R] はインデックス [k_low, k_high] の間隔に対応し、元の範囲内のすべての有効な年は、このインデックス間隔内の 1 つの整数に正確に対応します。 2 つの異なる k が同じ年にマッピングされることはないため、インデックスをカウントすることは年をカウントすることと同等であり、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count(a, L, R):
    k_low = (L - a + 3) // 4
    k_high = (R - a) // 4
    if k_high < k_low:
        return 0
    return k_high - k_low + 1

L, R = map(int, input().split())

ans = count(2024, L, R) + count(2022, L, R)
print(ans)
```実装の中核は、モジュラー算術条件を直接インデックス範囲に変換するヘルパー関数です。 唯一の微妙な点は式です`(L - a + 3) // 4`、これは正の値と負の値の両方に対して上限分割として動作します。 これにより、最初の有効な用語を「手動で調整」しようとしたときによく発生する、1 つずつずれたエラーが回避されます。 

このソリューションはループを完全に回避するため、一定時間で実行され、入力範囲がはるかに大きい場合でも堅牢です。

これにより、両方のシーケンスが互いに素な等差数列であるため、各シーケンスを独立して処理して合計することが有効であることが確認されます。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    def count(a, L, R):
        k_low = (L - a + 3) // 4
        k_high = (R - a) // 4
        if k_high < k_low:
            return 0
        return k_high - k_low + 1

    L, R = map(int, input().split())
    print(count(2024, L, R) + count(2022, L, R))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out.strip()

# provided sample
assert run("2030 2050") == "11"

# minimum interval
assert run("2025 2025") == "0"

# single summer year
assert run("2024 2024") == "1"

# boundary around winter only
assert run("2022 2022") == "1"

# mixed small interval
assert run("2023 2026") == "1"

# larger symmetric interval
assert run("2020 2030") == "3"

 ## 特殊なケース

 一般的なエッジ ケースは、L が有効なイベント年の直後である場合です。 たとえば、L = 2025、R = 2027 です。夏のイベントは次の 2028 年に発生し、冬のイベントはすでに 2026 年に発生しています。正解は 1 です。 

夏の場合、k_low = (2025 − 2024 + 3) // 4 = 1、k_high = (2027 − 2024) // 4 = 0 であるため、k_high < k_low であるため、関数は正しく 0 を返します。 冬については、k_low = (2025 − 2022 + 3) // 4 = 1、k_high = (2027 − 2022) // 4 = 1 となり、2026 年にイベントが 1 つだけ与えられます。 

もう 1 つの微妙なケースは、L が基準年よりはるかに前の場合に発生します。 たとえば、L = 2000、R = 2005 です。負の差はフロア分割によって自然に処理されるため、数式は依然として正しく動作します。 夏については、k_low が 0 となり、2024 年が第一候補となりますが、R が小さいため、夏のイベントはカウントされません。 冬も同様に何も貢献しません。 この算術演算により、「開始年より前」の場合の条件付き修正が不要になります。 

これらのケースは、インデックスベースの定式化が負のオフセットと正のオフセットの両方を均一に処理することを裏付けており、これがこのソリューションが信頼できる主な理由です。
