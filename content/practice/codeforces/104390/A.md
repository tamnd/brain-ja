 ## 解決策
 ## 問題の理解

 2 人が沿線の充電ステーションを報告します。 各ステーションには位置とコンセントの数があります。 そこに存在するアウトレットの数に応じて、各ポジションが複数回表示されるポジションのマルチセットを効果的に構築します。 

Mr. X のデータは固定されています。各 AC ステーションはその座標を繰り返し提供します。`s_i`回。 Y 氏のデータも似ていますが、マージする前に、クエリで同じ式を使用してすべての座標が線形変換されます。`y -> alpha * y + beta`。 変換後、各 DC ステーションが貢献します`t_j`この新しい座標のコピー。 

両方のマルチセットが結合されると、すべてが座標によって並べ替えられ、結果が単一のシーケンスに平坦化されます。 各位置は、その長さの合計が多重度に等しいブロックに拡張されます。 クエリでは、このフラット化されたシーケンスの k 番目の位置の値が求められます。 

重要な問題は、展開された配列を明示的に構築しないことです。 要素の総数は数千万に達する可能性があるため、マージされたシーケンスを実現するアプローチは時間やメモリに収まりません。 

この制約は、データセットごとの前処理は問題ないが、各クエリは入力サイズに対してほぼ対数時間で応答する必要があることを示唆しています。 最大 100,000 ステーションと 50,000 クエリでは、クエリあたり O(N log N + Q log N) であっても許容されますが、k または総多重度における線形は許容されません。 

微妙なエッジケースは、変換後のオーバーラップです。 異なる元の Y 座標が X 座標と一致する位置にマッピングされる場合があるため、カウントを正しく合計する必要があります。 もう 1 つの微妙な点は、変換によって順序が維持されることです。`alpha >= 1`, したがって、Y ステーションの相対的な順序は変わりません。 これにより、変換後に Y を再ソートする必要がなくなります。 値のシフトとスケールのみが可能です。 

## アプローチ

 直接的なアプローチでは、すべてのステーションを繰り返し座標に拡張し、マージ ソートの標準的なマージ ステップのように 2 つのリストをマージします。 最終的な構造は、ソートされた 2 つのストリームがインターリーブされただけであるため、これは正しいです。 ただし、展開された要素の総数は非常に大きくなる可能性があるため、明示的にマージすると時間がかかりすぎ、メモリが大量に消費されます。 

重要な観察は、実際には完全にマージされたシーケンスが必要ないということです。 必要なのは k 番目の要素だけです。 これは、完全な構築ではなく選択戦略を使用することを示唆しています。 配列を構築する代わりに、候補値について、その値以下の要素がいくつあるかをチェックすることで、各クエリに答えることができます。 この数は、各配列内でプレフィックスの合計と二分探索を使用して効率的に計算できます。 

次に、応答値自体を二分探索します。 どちらの配列も位置によってソートされ、Y は変換後もソートされたままであるため、upper_bound ロジックを使用して配列ごとに要素数 ≤ v を対数時間で計算できます。 

これにより、問題は 2 つの重み付き並べ替えリストに対する順序統計クエリの繰り返しに変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 展開して結合する | クエリごとの O(総スロット数) | O(合計スロット) | 遅すぎる |
 | プレフィックス数を使用した値の二分検索 | O((N+M) log V + Q log V log N) | O(N+M) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 事前計算

 まず、対数時間で範囲内にあるステーションの数をカウントできるように、各配列をプレフィックスの合計に圧縮します。 

### 各クエリの処理

 1. Y 氏の変換をオンデマンドで関数に変換します。配列を変更する代わりに、比較しきい値のみを変換します。 これにより、クエリごとに Y を再構築することがなくなります。 
2. 回答値の候補について`v`、二分探索を使用して、≤ v である X 値がいくつあるかを計算します。`x_i`およびプレフィックスの合計`s_i`。 
3. Y 値の場合、変換条件を反転します。 私たちが望んでいるのは:`alpha * y + beta ≤ v`これは次のようになります。`y ≤ (v - beta) // alpha`これにより、元の Y 配列にしきい値が与えられます。 
4. 何個数えるか`y_j`二分探索とプレフィックス合計を使用してこのしきい値を満たす`t_j`。 
5. 両方のカウントを合計して、合計要素 ≤ v を取得します。 
6. 可能な値を二分探索して、カウントが少なくとも k になる最小の v を見つけます。 

### なぜ効果があるのか

 マージされた構造は、ソートされたマルチセットです。 述語「count ≤ v」は v において単調です。つまり、v が増加してもカウントは減少しません。 これにより、バイナリ検索の正確さが保証されます。 プレフィックス合計により多重度が正しく考慮されるため、各ステーションはアウトレットの数を正確に提供します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from bisect import bisect_right

def build_prefix(vals, w):
    # prefix sums for weights
    pref = [0] * (len(w) + 1)
    for i in range(len(w)):
        pref[i + 1] = pref[i] + w[i]
    return pref

def count_leq(vals, pref, x):
    # number of vals <= x, using prefix + bisect
    idx = bisect_right(vals, x)
    return pref[idx]

def solve():
    N, M, Q = map(int, input().split())
    x = list(map(int, input().split()))
    sx = list(map(int, input().split()))
    y = list(map(int, input().split()))
    ty = list(map(int, input().split()))

    px = build_prefix(x, sx)
    py = build_prefix(y, ty)

    total = px[-1] + py[-1]

    def count(v, a, b):
        # X part
        cx = count_leq(x, px, v)
        # Y part: alpha*y + beta <= v => y <= (v - beta) / alpha
        limit = (v - b) // a
        cy = count_leq(y, py, limit)
        return cx + cy

    for _ in range(Q):
        a, b, k = map(int, input().split())

        lo = -10**12
        hi = 10**12

        while lo < hi:
            mid = (lo + hi) // 2
            if count(mid, a, b) >= k:
                hi = mid
            else:
                lo = mid + 1

        print(lo)

if __name__ == "__main__":
    solve()
```X 配列と Y 配列は、計算中は変更されません。 プレフィックス合計数が超過`s_i`そして`t_j`「ここに寄与するステーションの数」という各クエリに対して、二分探索を介して対数時間で答えることができます。 

重要な実装の詳細は、変換不等式の逆変換です。 以来`alpha`は常に正であり、除算は方向を反転せず、整数フロア除算は境界を正しく処理します。 

二分探索はインデックスではなく応答値空間で動作するため、潜在的に巨大になる可能性のある拡張されたマルチセットに触れることはありません。 

## 実用的な例

 ### 例 1

 小規模な構成を考えます。 

X = 位置`[1, 4]`重り付き`[2, 1]`Y = 位置`[2, 3]`重り付き`[1, 2]`クエリ:`alpha = 2, beta = 0, k = 3`少なくとも 3 つの要素が ≤ v となる最小値 v を検索します。 

| v | X ≤ v | 変換された Y ≤ v | 合計 |
 | --- | --- | --- | --- |
 | 1 | 2 | 0 | 2 |
 | 2 | 2 | 1 | 3 |

 k = 3 に到達する最初の v は 2 であり、これが答えになります。 

これは、多重度が累積カウントにどのように直接影響するかを示しています。 

### 例 2

 X =`[1, 5]`と`[1, 1]`Y =`[2, 6]`と`[1, 1]`クエリ:`alpha = 1, beta = -2, k = 2`Yは`[0, 4]`。 

カウントを評価します。 

| v | X ≤ v | Y ≤ v | 合計 |
 | --- | --- | --- | --- |
 | 0 | 0 | 1 | 1 |
 | 1 | 1 | 1 | 2 |

 したがって、答えは 1 です。 

これは、変換された配列がどのように新しい順序を導入できるか、そして不等式の反転がそれをどのようにきれいに処理するかを示しています。

 重要なエッジ ケースは、変換された Y 値が X 値に正確に一致する場合です。 このような状況では、両方の投稿を上書きするのではなく、マージする必要があります。 両方の配列が独立して同じしきい値に寄与するため、不等式に基づくカウントはこれを自然に処理します。 

もう 1 つのエッジ ケースは、負のベータ値が大きく、Y 値がすべての X 値を下回る可能性があります。 しきい値が Y のシフトされた範囲に達するまで、count 関数は X の寄与のみを正しく返すため、二分探索は引き続き機能します。 

最終的なエッジ ケースは、要素の合計数に近い k が大きくなります。 二分探索の上限は十分に広い必要があります。 そうしないと、アルゴリズムの収束が早すぎる可能性があります。 値に広い安全範囲を設定すると、変換パラメータに関係なく正確さが保証されます。
