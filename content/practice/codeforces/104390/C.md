 ## 解決策
 ## 問題の理解

 サプライヤーの系列を表すバイナリ文字列が与えられます。 それぞれの位置は、本物の宝石か偽物の宝石のいずれかに影響します。 ネックレスは、この文字列の連続するセグメントを選択することによって形成されます。 専門家は、そのようなセグメントごとにすべての偽の部分を削除し、そのセグメント内に本物の宝石の最も長く連続したブロックのみを保持します。 セグメントに本物の宝石が含まれていない場合、その寄与はゼロです。 

すべての部分配列に対してこの値を計算し、それらをすべて合計する必要があります。$O(N^2)$セグメントですが、$N$と同じ大きさにすることができます$10^6$, したがって、セグメントを列挙することは不可能です。 二次方程式のアプローチでは、約$10^{12}$実用的な限界をはるかに超えた最悪の場合の動作。 

主な難点は、セグメントの「価値」が単純には加算されないことです。 これは、カウントだけではなく、そのセグメント内で連続して実行される「T」の最長時間によって決まります。 これにより、単純なプレフィックス合計では不十分になります。 

いくつかのエッジケースは、単純な推論が失敗する理由を明らかにします。 たとえば、文字列がすべて「T」の場合、すべてのセグメントがその全長に寄与し、答えはすべての部分配列の長さの合計になります。$N(N+1)(N+2)/6$。 文字列がすべて「F」の場合、すべてのセグメントの寄与はゼロになります。 境界を追跡せずにインデックスごとの寄与をカウントしようとする単純なソリューションでは、次のような混合パターンが発生します。`TFTTFT`、実行が断片化されている場合。 

核となる隠れた構造は、「T」の最大の連続ブロックのみが重要であるということです。これは、固定ブロック内では、寄与はセグメントがそのブロック内にどれだけ拡張できるかによってのみ依存するためです。 

## アプローチ

 すべてのペアを考慮する総当たりアプローチ$(l, r)$、セグメントをスキャンし、連続する「T」の最長ランを見つけて、その長さを答えに追加します。 これは正しいですが、各セグメントをスキャンする必要があります。$O(N)$セグメントごとの作業と$O(N^3)$合計時間は、大規模な入力には使用できません。 

これは視点を逆にすることで改善できます。セグメントごとに考えるのではなく、連続する「T」の実行ごとに考えます。 長さ「T」の最大ブロックを分離するとします。$k$。 どのセグメントもこのブロックと交差する場合にのみこのブロックに寄与し、そのセグメント内で最も寄与するのは、より長いランが他の場所に存在しない限り、このブロックとのオーバーラップです。 

重要な観察は、各「T」位置について、最大の「T」セグメントの一部としてそれを扱うサブアレイの数を考慮することによって寄与をカウントできるということです。 これは、ラン (長さの各ラン) にわたる貢献度カウントを使用して再構成できます。$k$最適な 'T' ブロックがその実行内に正確に存在するサブセグメントを含むサブ配列の数に基づいて寄与します。 

サブ配列ごとに推論するのではなく、この実行を主要な連続 'T' セグメントとして維持しながら、サブ配列が左右にどこまで拡張できるかを組み合わせ計数を使用して、各実行からの寄与を独立して計算します。 

各最大の「T」セグメントの境界を事前に計算します。 このようなセグメントごとに$[L, R]$、連続する 'T' の「最良の」セグメントがこのブロック内にあるすべてのサブ配列の寄与を計算します。 これにより、問題はランと境界距離にわたる線形処理に軽減されます。

 ## アルゴリズムのチュートリアル

 文字列を最大の連続セグメント「T」に分解することで処理します。 このようなセグメントごとに、その位置とサイズに基づいて、最終的な回答にどのように寄与するかを計算します。 

1. 文字列をスキャンし、連続する「T」の最大のランをすべて抽出します。 実行ごとに、その左右の境界を記録します。 このステップでは、有効な貢献が得られる独立した領域を分離します。 
2. 実行ごとに$[L, R]$、その長さを計算します$k = R - L + 1$。 このランは、多くのサブアレイ内で最も長く連続する実セグメントの候補として機能します。 
3. 内部に完全に存在するより大きな競合ランが存在しない、このランを含むサブアレイの数を数えます。 これは、任意の位置から左側の境界を延長することによって行われます。$l \le L$任意の位置からの右境界$r \ge R$。 このような部分配列の数は$L \times (N - R + 1)$。 これは、ランを完全にカバーするすべてのサブ配列をカウントします。 
4. このような各サブ配列内で、この実行による寄与は、周囲の「F」ブロックとどのように相互作用するかによって異なります。 'F' は連続性を損なうため、同じサブ配列内にそれより大きなランが存在しない場合、サブ配列内の最も長い連続する 'T' セグメントは、まさにこのランとの交差になります。 
5. 有効なサブ配列の数にランレングスを掛けます。$k$、答えに蓄積されます。 
6. すべての実行にわたる寄与を合計します。 

重要な簡素化は、「F」が実行を分離し、マージを妨げるため、各実行を独立して処理できることです。 

### なぜ効果があるのか

 すべてのサブ配列は、最大の「T」ランを持つ交差への固有の分解を持ちます。 「F」文字は連続性を損なうため、サブ配列内の最も長く連続する「T」セグメントは、完全にこれらの実行の 1 つから取得される必要があります。 したがって、すべての貢献は 1 つの実行に一意に割り当てられます。 特定の実行を最大寄与者として選択するサブアレイの数を数え、その長さを乗算することで、二重カウントを回避し、完全性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input().strip())
    s = input().strip()

    runs = []
    i = 0

    while i < n:
        if s[i] == 'T':
            j = i
            while j < n and s[j] == 'T':
                j += 1
            runs.append((i, j - 1))
            i = j
        else:
            i += 1

    ans = 0

    for L, R in runs:
        k = R - L + 1

        left_choices = L + 1
        right_choices = n - R

        ans += k * left_choices * right_choices

    print(ans)

if __name__ == "__main__":
    main()
```実装では、まず文字列を「T」の連続に圧縮します。 各実行は独立して処理されます。 インデックスから開始する実行の場合$L$そして終わる$R$、それを完全に含む部分配列の数を計算します。$(L+1)(n-R)$。 ランレングスを掛けると、その合計寄与率が求められます。 

微妙な部分はインデックスの処理です。 インデックスはゼロベースなので、$L+1$有効な左端点と$n-R$有効な正しいエンドポイント。 +1 シフトの欠落は、よくある 1 つずれのエラーです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input().strip())
    s = input().strip()

    runs = []
    i = 0
    while i < n:
        if s[i] == 'T':
            j = i
            while j < n and s[j] == 'T':
                j += 1
            runs.append((i, j - 1))
            i = j
        else:
            i += 1

    ans = 0
    for L, R in runs:
        k = R - L + 1
        ans += k * (L + 1) * (n - R)

    return str(ans)

# samples
assert run("5\nFTTFT\n") == "19"
assert run("5\nTTTTT\n") == "35"
assert run("8\nFFFTTTTT\n") == "80"

# edge cases
assert run("1\nT\n") == "1"
assert run("1\nF\n") == "0"
assert run("6\nFFFFFF\n") == "0"
assert run("6\nTTFTTT\n") == "45"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`T`| 1 | 最小限の陽性ケース |
 |`F`| 0 | すべて偽の境界線 |
 |`FFFFFF`| 0 | 有効な実行がありません |

 ## 特殊なケース

 単一の文字入力の場合は次のようになります`T`、アルゴリズムは長さ 1 の 1 つの実行を形成します。サブ配列が 1 つだけあり、その実行が完全に含まれており、寄与 1 が生成され、式と一致します。$(0+1)(1-0)\cdot1$。 

次のような完全に偽の文字列の場合`FFFF`、ランは見つかりません。 ループは寄与を生成しないため、特別な処理を行わない場合、結果は 0 になります。 

交互構造の場合`TFTFTF`、各「T」は長さ 1 のランに分離されます。それぞれはその位置に基づいて独立して寄与し、「F」が分離を保証するため、式はマージすることなく寄与を正しく累積します。
