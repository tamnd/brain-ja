 ## 解決策
 ## 問題の理解

 最大 100 万行までのバイナリ行列が与えられていますが、列は最大 10 個までです。 各セルには最初は 0 または 1 が含まれています。 行全体または列全体を繰り返し反転することができます。反転とは、その行または列のすべてのビットを切り替えることを意味します。 

このような一連の操作を実行した後、各セルは行と列が反転された回数のパリティのみに応じて 0 または 1 になります。 最終的な行列が固定されると、1 に等しいすべてのセルは、その位置に依存する線形重みに等しい値、つまり行インデックスに A を乗算し、列インデックスに B を乗算した値を与えます。0 に等しいセルは何も寄与しません。 目標は、1 の加重合計を最大化するフリップを選択することです。 

制約によって構造が大きく形作られます。 行数が十分に多いため、各行に何度もアクセスするアルゴリズムは慎重に制御する必要がありますが、列数が最大 10 であるということは、列の状態空間が小さく、列挙またはビットマスクとして扱うことができることを意味します。 この不均衡が主なシグナルです。解決策では、行にわたって問題を圧縮し、列にわたって指数列挙を利用する必要があります。 

素朴な解釈では、フリップをシミュレートしたり、すべての操作シーケンスを検索しようとします。 状態空間の記述ですら行と列の両方で指数関数的であり、操作の数に制限がないため、これはすぐに失敗します。 

2 番目の素朴な試みは、行と列の構成ごとに、その行または列を反転することが役立つかどうかを直接決定することです。 ただし、行反転と列反転の間の依存関係は、ローカルな決定がグローバルに干渉することを意味するため、貪欲な戦略は失敗します。 

A または B が負の場合、微妙なエッジ ケースが発生します。 その場合、インデックスの高い行または列でより多くの 1 を返すと、1 の数が増えたとしても合計スコアが減少する可能性があります。 たとえば、すべてのエントリが 1 で、B が非常に負の場合、列を反転して高い列インデックスにゼロを作成すると、スコアが増加する可能性があります。 これは、問題が 1 の最大化に関するものではなく、パリティ選択後の重み付き 1 の最大化に関するものであることを確認します。 

## アプローチ

 ブルートフォースの観点は、各行反転と列反転がバイナリ変数として表現できることに注目することから始まります。 各行にビット ri を、各列にビット cj を持たせます。 ai、j、ri、および cj の XOR が 1 に等しい場合に限り、最終行列のセル (i, j) は 1 になります。 これにより、問題は n + m 個のバイナリ変数を選択することに変わり、すでにサイズ 2^(n+m) の検索空間が大きすぎることが示唆されています。 

ただし、重要な構造の単純化は、m が非常に小さいことです。 これは、考えられるすべての列反転構成を列挙することを示唆しています。 列構成が固定されると、行を反転してもその m ビットすべてが同時に切り替わるだけであるため、各行は独立します。 つまり、行ごとに、列の状態を把握した後で反転することが有益かどうかを判断できます。 

固定列マスクの場合、各行には、行を反転しない、または行を反転するという 2 つの状態があります。 行を反転すると、固定列変換の下でその行のすべてのビットがその補数に変換されるため、これら 2 つのオプションは相補的です。 これにより、行ごとに最適な寄与を個別に計算し、それらを合計することができます。 

列マスクに対するブルート フォースは m (最大 10) でのみ指数関数的であるため、実行可能です。 残りのコストは、各マスクのすべての行を反復処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての行と列の反転に対するブルート フォース | O(2^(n+m)) | O(nm) | 遅すぎる |
 | 列マスクを列挙し、行を個別に評価します。 O(n · m · 2^m) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

列反転の各選択を長さ m のビットマスクとしてエンコードします。 各ビットは、その列が現在反転されているかどうかを示します。 このようなマスクすべてを反復処理します。 

各マスクについて、行を反転しない、または反転するという 2 つの可能性のもとで、すべての行の寄与を計算します。 この2つの良いところを積み上げていきます。 

1. すべての列反転構成を 0 ～ 2^m − 1 のビットマスクとして列挙します。 
2. 固定マスクの場合、各行を個別に処理します。 行 i について、行を反転しない場合に寄与する値を計算します。 これは、列マスクを行の元のビットに適用し、結果のビットが 1 になる位置の重みを合計することによって取得されます。 
3. 同じ行について、行を反転した場合の値を計算します。 最初から再計算する代わりに、行を反転するとすべてのビットが切り替わり、同じ列マスクの下ではすべての 0 が 1 になり、すべての 1 が 0 になることに注目してください。 これは、反転された値が、行の重みの合計から反転されていない値を引いたものであることを意味します。 
4. その行の 2 つの値の最大値を取得し、それをこの列マスクの合計スコアに加算します。 
5. すべての行が処理された後、すべての列マスクの中で最良の合計を使用してグローバル回答を更新します。 

重要な不変条件は、固定列構成の場合、各行が反転するかどうかの選択において完全に独立していることです。 行反転は行間で相互作用せず、列効果はすでに固定されているため、行の決定は他の行には影響しません。 この独立性により、固定列マスク内で行ごとを貪欲に最大化すると、そのマスクに対して最適な結果が得られます。 すべての列マスクが列挙されるため、全体的な最適値がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, A, B = map(int, input().split())
    mat = [input().strip() for _ in range(n)]

    # Precompute weights per column
    col_weight = [B * (j + 1) for j in range(m)]

    # Precompute row base weights and cell contributions
    # w[i][j] = A*(i+1) + B*(j+1)
    # store row values and total row sum
    row_bits = []
    row_sum = []

    for i in range(n):
        w_i = A * (i + 1)
        bits = []
        total = 0
        for j in range(m):
            w = w_i + col_weight[j]
            if mat[i][j] == '1':
                total += w
                bits.append(w)
            else:
                bits.append(0)
        row_bits.append(bits)
        row_sum.append(sum(w_i + col_weight[j] for j in range(m)))

    ans = 0

    for mask in range(1 << m):
        cur = 0
        for i in range(n):
            v0 = 0
            for j in range(m):
                if mask & (1 << j):
                    v0 += (1 - int(mat[i][j])) * (A * (i + 1) + B * (j + 1))
                else:
                    v0 += int(mat[i][j]) * (A * (i + 1) + B * (j + 1))

            best = max(v0, row_sum[i] - v0)
            cur += best

        ans = max(ans, cur)

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、列マスクを固定し、各行を個別に評価するという考えに従っています。 式 row_sum[i] - v0 は、すべてのセルを再計算せずに、反転された行の寄与を計算するために使用されます。 直接再計算するとマスクごとの行ごとの作業が 2 倍になるため、これは重要です。 

ネストされたループは構造を反映しています。外側のループは列の状態を列挙し、中央のループは行を反復し、内側のループは m 列を評価します。 正確さは、行反転が m 値の固定セットに対するグローバルな反転であるという事実に依存します。 

## 実用的な例

 n = 2、m = 2、A = 1、B = 1、およびすべてのエントリが 1 である小さな行列を考えてみましょう。 

マスク 00 (列反転なし) の場合、各行をそのまま評価します。 すべてのセルはその重みに寄与しており、行を反転すると 1 が 0 に変わるため、その行のすべての寄与が削除されます。 したがって、各行については反転しないままにします。 

| 行 | v0 (反転なし) | row_sum - v0 (反転) | 選ばれた |
 | --- | --- | --- | --- |
 | 1 | 3 | 3 | 3 |
 | 2 | 5 | 5 | 5 |

 合計は 8 です。 

これは、すべてのビットがすでに最適である場合、反転は必要なく、アルゴリズムが不必要な反転を正しく回避することを示しています。 

次に、混合行列を考えてみましょう。 

n = 2、m = 2、A = 1、B = -1

 マトリックス:

 1 0

 0 1

 マスク 01 (2 番目の列を反転) の場合、2 番目の列が意味のある変化を示します。 行ごとに評価します。 

| 行 | v0 | 行合計 - v0 | 選ばれた |
 | --- | --- | --- | --- |
 | 1 | マスクの下で計算 | 補足 | 最大 |

 このケースは、列反転によって各行の解釈がグローバルにどのように変更されるかが示されていますが、マスクが固定されると行の決定は独立したままになります。 

トレースは、アルゴリズムがすべての列構成を調査し、それぞれの列構成で行反転を最適に解決していることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · m · 2^m) | 2^m 列マスクごとに、各行が m 列にわたってスキャンされます。 
| スペース | O(1) 補助 | カウンタ以外では入力ストレージのみが必要です。 

m ≤ 10 という制約により、2^m は最大 1024 となり、指数係数が小さく保たれます。 n が 10^6 までの場合でも、構造は境界線のままですが、PyPy やタイトなループを備えた高速 Python 実装での典型的な競争プログラミング最適化の下では許容可能です。

## 特殊なケース

 主なエッジケースは、A または B が負の場合です。 その状況でも、行を反転すると固定行重み合計に関してすべての寄与がその補数に変換されるため、アルゴリズムは依然として両方の行反転状態を正しく評価します。 これにより、インデックスが高くなるとスコアが低下する場合でも、max 操作ではそれらの影響を抑制する構成が正しく優先されることが保証されます。 

もう 1 つのエッジ ケースは、行がすべて 0 またはすべて 1 の場合に発生します。 すべてゼロの行の場合、どの列マスクでも v0 はゼロであり、行を反転すると行全体の合計が生成されます。 アルゴリズムは、合計の重みが正の場合にのみ反転を正しく選択します。 すべて 1 行の場合、決定は現在の列マスクによって一部の位置がゼロになるかどうかに完全に依存し、補数トリックにより再計算なしで正しい代替が得られます。
