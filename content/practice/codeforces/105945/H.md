 ## 解決策
 ## 問題の理解

 文字列が与えられ、位置の間隔制限の下で形成できる空ではないサブシーケンスの数を数えるよう求められます。 部分シーケンスは、元の順序を維持しながら文字列から文字を選択することによって取得されますが、元の文字列内で互いに近すぎる文字を選択することはできません。 より正確には、2 つの連続した選択されたポジションを選択した場合、それらのインデックスは よりも大きく異なる必要があります。$k$。 これは、選択されたすべての文字が少なくとも$k+1$前に選択した文字の後の位置。 

出力は、そのようなすべての有効なサブシーケンスの中で、998244353 を法として取得された、結果として生じる個別の文字列の数です。 

入力サイズの合計が大きく、文字列の長さの合計が最大です。$10^6$。 制約がない場合でも、指数関数的に多くのサブシーケンスが存在するため、サブシーケンスを明示的に列挙するソリューションは即座に除外されます。 許容される解決策は、全長が直線または直線に近いものでなければなりません。 

あまり明白ではありませんが、文字列内の実際の文字は、この制約の下では個別のサブシーケンスの数に影響を与えないということです。 この制限は、文字値ではなく、選択された位置にのみ依存します。 選択された位置の各セットはサブシーケンス文字列を一意に決定するため、個別のサブシーケンスをカウントすることは、有効なインデックス セットをカウントすることと同等になります。 

よくある失敗例は、文字の最後の出現に依存する標準の個別サブシーケンス DP を適用しようとした場合に発生します。 たとえば、次のような文字列では、`aaaaa`, 素朴な考えでは、キャラクターごとに投稿をマージしようとするかもしれませんが、間隔の制約によりその構造が崩れてしまいます。 制約は位置的なものであるため、文字ベースの DP は正しく折りたたまれません。 

別の特殊なケースが発生するのは、$k = 0$。 この場合、選択された 2 つの連続する位置は少なくとも 1 異なっている必要があり、サブシーケンス ルール自体を超える制限は課されません。 正しい答えは、空ではないすべてのサブシーケンスを数えるということになります。$2^n - 1$。 プレフィックス合計に現在位置を含めるなど、間違った境界を誤って使用する繰り返しが発生すると、カウントが過剰になったり、自己依存性が生じたりします。 

## アプローチ

 ブルートフォース手法は簡単です。すべてのサブシーケンスを生成し、それぞれが間隔ルールを満たしているかどうかを確認します。 各サブシーケンスについて、隣接する選択されたインデックスを線形時間で検証します。 あるので$2^n$後続の場合、これは完全に不可能になります。$n = 30$、ましてや$10^6$。 この失敗は、指数関数的に増加するポジションのサブセットを列挙することで発生します。 

重要な洞察は、文字の観点から考えるのをやめ、代わりに最後の要素の有効な選択の観点から考えることです。 すべての有効なサブシーケンスは、最後に選択された位置によって一意に記述できます。 ポジションを固定したら$i$最後の要素として、それ以前のすべてが、ある位置で終わる有効なサブシーケンスを形成する必要があります。$j \le i-k-1$。 これにより、組み合わせ構造ではなく、プレフィックス範囲にわたってクリーンな繰り返しが作成されます。 

これにより、問題は、プレフィックスの合計を使用した位置に関する単純な動的プログラミングに変換されます。 各インデックスまたはその前で終了する有効なサブシーケンスの数を維持し、範囲の合計を使用して間隔の制約が確実に尊重されるようにします。

 ## アルゴリズムのチュートリアル

 文字列に 1 から 2 までのインデックスを付けます。$n$。 させて$dp[i]$最後に選択された位置が正確に一致する有効なサブシーケンスの数を示します。$i$。 させて$pref[i]$の合計になる$dp[1..i]$。 

1. 各ポジションごと$i$、のみで構成される新しいサブシーケンスを開始することを検討してください。$S[i]$。 これにより、次で終わる 1 つの有効なサブシーケンスが提供されます。$i$。 
2. で終わる長いサブシーケンス$i$前の終了位置から来ている必要があります$j$、ここでは間隔ルールが適用されます。$i - j > k$、同等に$j \le i - k - 1$。 これにより、最後のギャップが有効であることが保証され、以前のギャップは以前の状態によってすでに強制されています。 
3. したがって、次のように設定します。$dp[i] = 1 + pref[i-k-1]$、治療$pref[x] = 0$いつ$x \le 0$。 
4. プレフィックスの合計を更新します。$pref[i] = pref[i-1] + dp[i]$。 
5. 最終的な答えは次のとおりです。$pref[n]$、任意の場所で終わるすべての有効なサブシーケンスを集計します。 

### なぜ効果があるのか

 すべての有効なサブシーケンスには、最後に選択された一意の位置があります。$i$。 一度$i$が固定されている場合、残りのプレフィックスは、最後の位置が次の間隔制約に従っている有効なサブシーケンスです。$i$。 繰り返しでは、すべての有効なサブシーケンスがこの最後の位置によって重複せずに分割されます。 各サブシーケンスはその終端インデックスで 1 回だけカウントされるため、重複は発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        dp = [0] * (n + 1)
        pref = [0] * (n + 1)

        for i in range(1, n + 1):
            j = i - k - 1
            if j >= 1:
                dp[i] = (1 + pref[j]) % MOD
            else:
                dp[i] = 1

            pref[i] = (pref[i - 1] + dp[i]) % MOD

        print(pref[n] % MOD)

if __name__ == "__main__":
    solve()
```実装は再発の直後に行われます。 唯一の微妙な点はインデックスの処理です。$i-k-1$が非正になる場合、拡張する有効な前のサブシーケンスがありません。 プレフィックス配列により、範囲の合計が一定時間で計算されることが保証されます。 

2 番目の微妙な点は、文字列自体が使用されないことです。 入力で提供されますが、有効なサブシーケンスの数は、文字の ID ではなく、許可されたインデックス選択の構造のみに依存します。 これが、ソリューションが無視する理由です`s`全体的に。 

## 実用的な例

 次の例を考えてみましょう$n = 5, k = 1$。 選択した位置が少なくとも 2 異なる必要がある有効なサブシーケンスを計算します。 

| 私 | dp[i] の計算 | dp[i] | プレフィ[i] |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 |
 | 2 | 1 | 1 | 2 |
 | 3 | 1 + 設定[1] | 2 | 4 |
 | 4 | 1 + 設定[2] | 3 | 7 |
 | 5 | 1 + 設定[3] | 5 | 12 |

 最終的な答えは 12 です。これは、後の位置ほど、以前の有効なサブシーケンスとより自由に組み合わせることができることを反映していますが、十分に離れたもののみです。 

ここで考えてみましょう$n = 4, k = 2$、ここで、位置は少なくとも 3 異なる必要があります。 

| 私 | dp[i] の計算 | dp[i] | プレフィ[i] |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 |
 | 2 | 1 | 1 | 2 |
 | 3 | 1 | 1 | 3 |
 | 4 | 1 + 設定[1] | 2 | 5 |

 位置 4 のみが以前のサブシーケンスを拡張でき、位置 1 で終了するサブシーケンスのみが問題となるほど近くにあります。 これは、制約がインタラクション範囲を効果的に制限する方法を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n)$テストごと | 各位置は O(1) プレフィックス ルックアップで 1 回処理されます。 
| スペース |$O(n)$| dp とプレフィックスの合計の配列 |

 合計から$n$すべてのテストケースにわたって$10^6$、ソリューションは、テストごとに 1 つの線形パスを使用して、制限内で快適に実行されます。 

## テストケース```python
import sys, io

MOD = 998244353

def solve():
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()

        dp = [0] * (n + 1)
        pref = [0] * (n + 1)

        for i in range(1, n + 1):
            j = i - k - 1
            if j >= 1:
                dp[i] = (1 + pref[j]) % MOD
            else:
                dp[i] = 1
            pref[i] = (pref[i - 1] + dp[i]) % MOD

        out.append(str(pref[n] % MOD))
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# minimum case
assert run("1\n1 0\na\n") == "1"

# all equal letters, k=0 => 2^n - 1 = 7 for n=3
assert run("1\n3 0\naaa\n") == "7"

# strict spacing
assert run("1\n4 2\nabcd\n") == "5"

# larger simple case
assert run("1\n5 1\nabcde\n") == "12"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | n=1、k=0 | 1 | 最小サブシーケンス数 |
 | ああ、k=0 | 7 | 完全な後続の成長 |
 | abcd,k=2 | 5 | 強力な間隔制約 |
 | abcde,k=1 | 12 | 中間のオーバーラップ動作 |

 ## 特殊なケース

 いつ$k = 0$、反復は古典的な部分列のカウントに帰着します。 たとえば$n = 3$、dp値があります$1, 2, 4$、合計は 7 になります。この式はまだ機能します。$i-k-1 = i-1$したがって、各位置は以前のすべてのサブシーケンスを正しく拡張します。 

いつ$k \ge n$、2 つのポジションを同時に選択することはできません。 拡張はできないため、すべての dp エントリは 1 になります。 たとえば$n = 4, k = 5$、答えは 4 で、それぞれの単一の位置を個別に選択することに対応します。 

非常に小さい場合$n$、 のような$n = 1$の場合、アルゴリズムは、次の条件に関係なく正しく 1 を返します。$k$、唯一のサブシーケンスは単一の文字であるためです。
