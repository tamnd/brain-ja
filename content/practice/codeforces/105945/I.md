 ## 解決策
 ## 問題の理解

 私たちは与えられています$n$各人は 3 つの整数で構成される「名前」を持っており、これは長さ 3 のベクトルと考えることができます。 個性豊かな3人を選びたいと思っています$i, j, k$。 これら 3 つのベクトルから、それぞれの位置を割り当てます。$1,2,3$これにより、各人は 1 つの座標を正確に提供します。1 人が最初の座標を提供し、1 人が 2 番目の座標を提供し、もう 1 人が 3 番目の座標を提供します。 

これにより新しいトリプルが生成されます$t = (x_1, x_2, x_3)$。 この構築されたトリプルが、選択された 3 人のうちの少なくとも 1 人の元の名前と正確に一致する場合、構成は有効であると見なされます。 指数の 3 倍だけをカウントするわけではありません$(i,j,k)$、ただし、どの人が「一致する」人物なのかも考慮されるため、同じトリオでの異なる有効な一致は個別にカウントされます。 

制約が到達する$n = 10^5$したがって、トリプルに対する三次列挙は不可能です。 二次アプローチであっても、非常に構造化されている必要があります。$n^2$すでに$10^{10}$。 これにより、各候補の構成が一定時間またはほぼ一定の時間でチェックされ、生成される候補の数が代数的制約によって大幅に制限される解決策が求められます。 

微妙な特殊なケースは、構築されたトリプルが選ばれた 3 人全員を 1 回だけ使用するという事実から生じます。 単純なアプローチでは、ある人物を複数のポジションに再利用することを誤って許可したり、同じトリオが順列に応じて複数の有効なアイデンティティを生成できることを忘れたりする可能性があります。 もう 1 つのよくある落とし穴は、等号が座標的に部分的にだけでなく、完全なトリプルとして正確に成立する必要があることを無視していることです。 

## アプローチ

 直接的な総当りのソリューションでは、すべてのトリプルを列挙します。$(i,j,k)$、位置に割り当てる 6 つの順列をすべて試してください。$1,2,3$、結果のトリプルを構築し、指定された名前の中にそれが存在するかどうかを確認します。 これは定義に直接従うため、概念的には正しいです。 ただし、トリプルの数は、$\binom{n}{3}$のオーダーです。$10^{15}$いつ$n = 10^5$、これは完全に不可能になります。 

重要な観察は、妥当性が非常に厳格であるということです。 2 人を固定し、ポジションにどのように割り当てるかを決定すると、3 人目は大きく制約されます。これは、構築されたトリプルの 3 番目の座標が、選択した 2 人のうちの 1 人またはターゲット ID の特定の値と一致する必要があるためです。 これは、どの固定ペアでも、三人称の候補はせいぜい少数の一定数であり、各候補はハッシュを使用して一定時間で検証できることを意味します。 

私たちは、ベクトルからインデックスまでハッシュ マップ内のすべてのトリプルに事前にインデックスを付けることで、これを利用します。 次に、個別の人々の順序付きペアごとに$(i,j)$、これら 2 つが関係するポジションの一定サイズの割り当てをすべて試し、3 番目のベクトルがどのようになるかを導き出し、そのような人物が存在するかどうかを確認します。 成功した各構築は、正確に 1 つの有効な 4 倍体に対応します。 

これにより、トリプルの列挙から、常にチェックを行うペアの列挙へと問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | トリプルに対するブルートフォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | ペアの列挙 + ハッシュ |$O(n^2)$予想される |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. トリプルからのハッシュ マップにすべての名前を保存します。$(S_{i,1}, S_{i,2}, S_{i,3})$インデックスを付ける$i$。 これにより、構築されたトリプルが存在するかどうかを定数時間で検索できるようになります。 
2. 個別のインデックスのすべての順序付きペアを反復処理します。$(i, j)$。 順序ペアを使用する理由は、構築はどの人がどの座標に貢献するかに依存するため、方向が重要になるためです。 
3. 各順序ペアについて、割り当ての 6 つの順列すべてを考慮します。$i, j,$そして潜在的な3番目のインデックス$k$ポジションに$1,2,3$。 それぞれの順列により、何の候補構造が決まりますか$k$残りのスロットに貢献する必要があります。 
4. 各順列について、どの人物が ID と一致するかを 3 つの可能な選択肢に分割します$id$。 そのような選択ごとに、第三者に対して保持する必要がある制約を導き出します。 これらの制約は、トリプル全体を修正します。$k$等しくなければなりません。 

たとえば、次のように決定すると、$i$が恒等である場合、構築されたトリプルは次と等しくなければなりません$S_i$。 これにより、次の 2 つの座標が強制されます。$j$そして$k$特定の座標に一致させる$S_i$、何を一意に決定しますか$S_k$でなければなりません。 
5. 必要なトリプルを一度$k$が計算されたら、ハッシュ マップを確認します。 それが存在し、それとは異なる場合$i$そして$j$、有効な 4 倍数が見つかりました。$(i, j, k, id)$。 
6. すべての順序付きペアおよび順列にわたるすべての一致を累積します。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効な構成が 1 つの順序付きペアに正確に対応するということです。$(i,j)$順列での役割割り当ての選択も併せて行います。 2 つの役割が固定されると、3 番目のベクトルは自由ではなくなります。座標に関する等価制約により、完全に決定されたトリプルになることが強制されます。 すべての名前は一意であるため、成功した各構築は 1 つの有効なインデックスに正確に対応します。$k$したがって、表現の曖昧さから重複が生じることはありません。 これにより、列挙中にすべての有効な 4 倍が正確に 1 回カウントされるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def encode(a, b, c):
    return (a, b, c)

n = int(input())
arr = [None] * n
mp = {}

for i in range(n):
    a, b, c = map(int, input().split())
    arr[i] = (a, b, c)
    mp[(a, b, c)] = i

ans = 0

# For readability: positions 0,1,2 correspond to columns 1,2,3
# We try all ways to assign i, j, k into these columns.
from itertools import permutations

idx = [0, 1, 2]

for i in range(n):
    a1, a2, a3 = arr[i]
    for j in range(n):
        if i == j:
            continue
        b1, b2, b3 = arr[j]

        # Try all assignments of (i, j, k_placeholder) to positions
        # We will compute k required and check existence
        for p in permutations([0, 1, 2]):
            # p tells which index contributes to column 0,1,2
            # but we still need to decide identity id among i,j,k later
            # we brute id as well
            for id_case in range(3):
                # Build partial assignment constraints
                # we try to infer k as a full triple
                k = [-1, -1, -1]

                # assign i and j contributions
                cols = [None, None, None]
                cols[p[0]] = i
                cols[p[1]] = j
                cols[p[2]] = -1  # k contributes here

                # compute target identity vector
                if id_case == 0:
                    target = arr[i]
                    id_idx = i
                elif id_case == 1:
                    target = arr[j]
                    id_idx = j
                else:
                    # k is identity, so its own value must match constructed
                    target = None
                    id_idx = -1

                # if k is identity, we determine k by matching target later
                if id_case != 2:
                    # derive k coordinates
                    ok = True
                    for col in range(3):
                        if cols[col] == i:
                            val = arr[i][col]
                        elif cols[col] == j:
                            val = arr[j][col]
                        else:
                            val = target[col]
                        if cols[col] == -1:
                            k[col] = val
                    k = tuple(k)
                    if k in mp:
                        k_idx = mp[k]
                        if k_idx != i and k_idx != j:
                            # check identity condition
                            built = [0, 0, 0]
                            for col in range(3):
                                if cols[col] == i:
                                    built[col] = arr[i][col]
                                elif cols[col] == j:
                                    built[col] = arr[j][col]
                                else:
                                    built[col] = arr[k_idx][col]
                            if tuple(built) == arr[id_idx]:
                                ans += 1
                else:
                    # id is k: we must try all k candidates implicitly
                    # compute required k via remaining constraints
                    # derive k from i and j only, then check if matches constructed
                    k = [-1, -1, -1]
                    for col in range(3):
                        if cols[col] == i:
                            k[col] = arr[i][col]
                        elif cols[col] == j:
                            k[col] = arr[j][col]
                    # need missing coordinate consistency
                    if -1 not in k:
                        if tuple(k) in mp:
                            k_idx = mp[tuple(k)]
                            if k_idx != i and k_idx != j:
                                ans += 1

print(ans)
```この実装は、割り当てパターンを修正し、次に 3 番目の参加者を一意に決定された候補トリプルに減らすというアイデアに従います。 ハッシュ マップにより、存在チェックが一定時間であることが保証されます。 主な微妙な点は、インデックスの区別性を常に強制し、どの参加者が一致として指定されているかに応じて、構築されたトリプルが正しいアイデンティティ ターゲットと比較されるようにすることです。

 ## 特殊なケース

 重要なエッジ ケースは、選ばれた 3 人全員が複数の順列の下で構築されたトリプルとすでに一致している場合です。 このような状況では、単純なソリューションでは、ID を一貫して関連付けているかどうかに応じて、過大にカウントしたり、過少にカウントしたりする可能性があります。 アルゴリズムは、再構成後に選択された恒等ベクトルに対して明示的に等価性をチェックし、それぞれが有効であることを確認することでこれを処理します。$(i,j,k,id)$独立してカウントされます。 

別のエッジ ケースは、異なる人物の 2 つの座標が一致する場合に発生します。これにより、データセット内に完全なトリプルが存在しない場合でも、部分的な構築が有効に見える可能性があります。 入力セットに完全なベクトルが存在しない限り、部分一致は決して受け入れられないため、完全なトリプルのハッシュ ルックアップはこれを防ぎます。
