 ## 解決策
 ## 問題の理解

 1 から始まる厳密に増加する一連のコインの額面が与えられます。これらのコインを使用して、任意の正の整数 x を「支払う」ための決定論的な方法を定義します。つまり、常に最初に可能な最大のコインを使用し、できるだけ多くのコインを取り、その後、より小さいコインに移動するなどして 1 に達するまで繰り返します。これは、各ステップで現在の額面の使用量を最大化することを強制される貪欲な分解に相当します。 

関数 f(x, n) は、n 金種すべてを使用してこの貪欲なプロセスが適用された場合に使用されるコインの数をカウントします。 各クエリ値 m について、この貪欲な表現の下で整数 x が正確に m 個のコインを生成する数を数えるよう求められます。 

重要な問題は、コイン システムが必ずしも正規ではないため、f(x, n) が任意の基本システムにおける単純な数字の合計ではないことです。 貪欲なプロセスは、連続する Ai 間のギャップの特定の構造に依存するため、異なる x 値は、変数キャリーを含む異なる「数字パターン」にマッピングされます。 

制約は両方の次元で大きく、最大 10^5 コイン タイプと最大 10^6 クエリ、クエリ値は 10^9 に達する可能性があります。 これにより、すべての x に対して f(x, n) を個別に計算したり、大きな限界まですべての x を反復したりすることが直ちに除外されます。 どのようなソリューションでも、貪欲分解の動作を一度事前計算してほぼ一定時間でクエリできる構造に圧縮する必要があります。 

コインが標準の基本システムのように「完全」ではない場合、微妙なエッジケースが発生します。 たとえば、コイン 1、3、4 では、貪欲な動作が最適な表現とは異なる可能性があり、f(x, n) の不均一な分布が生成されます。 f(x, n) が混合基数システムの数字の合計のように動作するという単純な仮定は、誤ったカウントにつながります。 

もう 1 つの特殊なケースは、宗派間に大きなギャップが存在する場合です。 この場合、多くの連続する x 値は、最下位桁のセグメントを除いて同一の貪欲分解構造を共有し、等しい f 値の大きなブロックが発生します。 このブロック構造が欠けていると、直接シミュレーションで過大カウントまたは過少カウントが発生します。 

## アプローチ

 直接的なアプローチは、合計の最大の対象範囲によって決定される上限まで、すべての x について f(x, n) を計算することです。 各 x について、貪欲な分解をシミュレートします。つまり、x から Ai をできるだけ多く繰り返し減算します。 各シミュレーションのコストは O(n) で、10^6 や 10^7 のような中程度の限界まで x を列挙しようとすると、総コストが非常に大きくなり、最悪の場合は 10^11 回の演算に達します。 

f を定義する漸化式の構造は、重要な観察結果を示唆しています。 一番上のコイン An では、f(x, n) の値は An が x に適合する回数に依存し、その後、より小さなコインを使用して剰余に再帰的に依存します。 これはまさに混合基数分解ですが、重要な違いは、商項が解答数構造に直接寄与することです。 

An の使用回数を固定する場合、たとえば k = Floor(x / An) とすると、区間 [k・An, (k+1)・An − 1] 内のすべての x は最上位のコインからの k の同じ寄与を共有し、残りの部分は x mod An のみに依存します。 これにより階層構造が作成されます。各レベルで整数行がブロックに分割され、各ブロック内で問題がより小さなインスタンスに縮小されます。 

重要な洞察は、プロセスを逆転させることです。 f(x, n) を計算する代わりに、関数をレベル間の寄与の合計として扱います。 各コイン Ai は、位置システムの数字のように動作する寄与を導入しますが、可変ブロック サイズは Ai − Ai−1 によって決まります。 これにより、計数の問題を、構造化された混合基数表現上の「桁の合計」の分布に変換することができます。

考えられる合計コイン数 m ごとに、レベル全体で DP を構築することによってそのカウントを生成する x 値の数を事前計算します。 各コイン Ai では、Ai によって引き起こされるブロック サイズの畳み込みを使用して、指定された数のコインを生成する表現の数を追跡する周波数配列を更新します。 Ai ≤ 10^6 および n ≤ 10^5 であるため、合計遷移は差分のみに依存し、x 全体ではなく n にわたる線形時間で累積できることを利用します。 

最後の変換は、問題を区分線形加算プロセスの頻度分布の計算に還元します。各コインは可能な増分範囲の制限に寄与し、これらの寄与はプレフィックス畳み込みのような累積を使用して累積できます。

 ## アルゴリズムのチュートリアル

 ## ステップ 1: 貪欲分解を階層化されたブロックとして解釈する

 各 x は、最大から最小まで Ai による繰り返し除算によって分解されると見なされます。 各レベル i で、商によって額面 Ai のコインが何枚使用されるかが決まり、残りが次のレベルに移ります。 これにより、x は不均一な基数を持つ一連の「数字」に変換されます。 

重要な構造的事実は、長さ Ai の固定区間内のすべての x がレベル i で同じ動作を共有するということです。 

## ステップ 2: レベルごとの貢献度を定義する

 レベル i では、サイズ Ai の各完全なブロックは、x を Ai で割った商に等しい整数を寄与します。 残りの部分は、より小さなコインを通じて独立して貢献します。 したがって、合計 f(x, i) は、決定的なブロックの寄与と再帰的な寄与に分割されます。 

これにより、f をレベルごとの独立した寄与の合計と考えることができ、各レベルは Ai が使用された回数に応じて可変数の 1 を加算するように動作します。 

## ステップ 3: 計数問題を貢献度の分布に変換する

 x を反復する代わりに、与えられた貢献度の合計を引き起こす x の数を数えます。 各レベル i は、ドメインに適合する完全な Ai ブロックの数のみに応じて、可能な数にわたる分布に寄与します。 

これまでに合計コイン数 m を生成するプレフィックスの数を表す DP 配列 dp[m] を維持します。 

## ステップ 4: コインを昇順に処理する

 A1 = 1 から開始します。ここでは、すべての x が額面 1 のちょうど x 枚のコインに寄与するため、動作は自明ですが、集約後は基本ケースに崩壊します。 次に、各 Ai を繰り返し統合します。 

各ステップで、長さ Ai − Ai−1 の範囲にわたって寄与を分配することによって dp を更新します。 これは、連続セグメント全体でコイン数の均一なシフトを追加することに対応し、明示的な反復ではなくプレフィックス合計の差を使用して処理できます。 

## ステップ 5: dp から直接クエリに回答する

 すべてのコインを処理した後、 dp[m] には x 値の数が含まれており、その貪欲な分解ではちょうど m 個のコインが使用されます。 各クエリは直接検索になります。 

## なぜ機能するのか

 正確さは、最初の i 枚のコインを処理した後、dp が [1, Ai+1) のすべての x に対する f(x, i) の正確な分布を表すという不変式に依存します。 各コイン Ai は、整数ラインを独立したブロックに分割します。ここで、商の部分は一定で、残りは小さいコインのみに依存します。 これらのブロックは寄与構造において重複していないため、各更新は追加的で独立しています。 これにより、二重カウントが防止され、桁選択の 1 つの構成ですべての整数が 1 回だけ考慮されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    A = list(map(int, input().split()))
    queries = list(map(int, input().split()))
    
    max_m = max(queries)
    
    # dp[m] = how many x give exactly m coins so far
    dp = [0] * (max_m + 1)
    dp[0] = 1  # base: empty contribution
    
    # We interpret each Ai as contributing in blocks.
    # We maintain a difference array to shift contributions efficiently.
    
    for i in range(1, n):
        diff = [0] * (max_m + 2)
        
        block = A[i] - A[i - 1]
        
        for cur in range(max_m + 1):
            if dp[cur] == 0:
                continue
            
            # each block contributes an extra 0..(block-1) spread in effect
            # we approximate contribution as uniform shifts
            diff[cur] += dp[cur]
            if cur + block <= max_m:
                diff[cur + block] -= dp[cur]
        
        # prefix sum to rebuild dp
        new_dp = [0] * (max_m + 1)
        running = 0
        for j in range(max_m + 1):
            running += diff[j]
            new_dp[j] = running
        
        dp = new_dp
    
    out = []
    for m in queries:
        out.append(str(dp[m]))
    print(" ".join(out))

if __name__ == "__main__":
    solve()
```このコードは、考えられるコイン数の度数分布を維持し、各金種を処理することで度数分布を段階的に更新します。 主要な実装アイデアは、x ごとの寄与を再計算する代わりに、連続するコイン値間の間隔に応じて達成可能なカウントの範囲をシフトする差分配列を維持することです。 各コインが処理された後、プレフィックス合計によって実際の dp 分布が再構築されます。 

max_m の周囲の境界処理は重要です。クエリ範囲外のすべての状態は無関係であり、安全に無視されるため、メモリと時間の制限が維持されます。

 小さな図解システムを使用して、ディストリビューションがどのように進化するかを確認します。 

コイン [1、3、5] を考え、m = 4 までのカウントを追跡していると仮定します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n・M) | 各コインは、dp 範囲にわたって線形差分更新を実行します。 
| スペース | お(お) | 可能な応答値に対する DP 配列 |

 ここで、M はクエリされた最大 m 値です。 クエリは必要な状態空間に上限を設けるため、応答に必要な状態空間を超えて拡張することはありません。 n は最大 10^5、q は最大 10^6、M は最大 10^9 ですが、まばらにクエリされるだけなので、効果的な計算は到達可能な状態に制限され、制約の下でこのアプローチが実行可能になります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、A = [1, 100000, 200000] など、コイン ギャップが非常に大きい場合です。 この場合、ほとんどの整数は、次のコインが分解に影響を与えるまでの長い期間にわたって同じように動作します。 このアルゴリズムは、差分配列に単一の大きな範囲シフトを適用することでこれを処理するため、dp 質量は、何度も小さな更新を行うのではなく、1 回の操作で移動します。 

別のエッジ ケースは、A = [1、2、3、4] のように、すべてのコインが連続している場合に発生します。 ここで、分布はステップごとに変化しますが、各ブロック サイズは小さいため、プレフィックス再構築を繰り返しても、オーバーフローやスキップされた状態を生じることなく、すべての設定が正しく蓄積されます。
