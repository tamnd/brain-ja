## アプローチ

 最も直接的なアイデアは、有効なインデント パターンをすべて再構築することです。 ステートメントを上から下に処理し、現在のインデント レベルを維持し、単純なステートメントに遭遇するたびに、次のステートメントの前に可能な限りの量のインデントを試みます。 

すべての有効なインデント設定が 1 つの一連のデデント決定に対応するため、このブルート フォース検索は正しいです。 残念ながら、可能性の数は指数関数的に増加します。 ほとんどが単純なステートメントで構成されるシーケンスであっても、膨大な分岐要素が生成され、網羅的な列挙が不可能になる可能性があります。 

重要な観察は、現在のインデントの深さのみが重要であるということです。 その深みを生み出した正確な歴史は無関係です。 

これは動的プログラミングを示唆しています。 

ステートメントを 1 つずつ処理するとします。 させて`dp[d]`くぼみの深さに到達する方法の数を表します`d`現在のステートメントを処理する前に。 

次に、次のステートメントがどのような影響を受けるかを考えてみましょう。 

現在のステートメントが次の場合`f`の場合、次のステートメントは 1 レベル深くなる必要があります。 深層のあらゆる状態`d`深さへの移行`d+1`。

各状態が多くの状態に分岐するため、この 2 番目の遷移はコストがかかるように見えます。 単純な実装では次のことが必要になります$O(n^2)$行ごとに作業し、$O(n^3)$全体。

 ## アルゴリズムのチュートリアル

 しましょう`dp[d]`くぼみの深さになるための有効な方法の数を示します`d`次のステートメントを処理する前に。 

Initially, before the first statement, the program starts at depth 0.

 1. 配列を作成する`dp`サイズの`n + 1`そしてセット`dp[0] = 1`。 
2. 最初のコマンドから最後から 2 番目のコマンドまでステートメントを処理します。 

各ステートメントは後続のステートメントをどのように配置するかを決定するため、最後から 2 番目のコマンドで停止します。 
3. 現在のステートメントが`f`、すべての状態が 1 レベル深くシフトする新しい DP 行を作成します。 

あらゆる深さに対して`d`、 追加`dp[d]`の中へ`new[d+1]`。 

これは、次のステートメントがループ本体に属さなければならないというルールをモデル化します。 
4. 現在のステートメントが`s`, compute suffix sums.

 させて$$suffix[d] = dp[d] + suffix[d+1]$$次に設定します$$new[d] = suffix[d]$$あらゆる構成の詳細`k`から任意の深さまでへこむことができます`0`を通して`k`、とても奥深いです`d`少なくとも深さのあるすべての状態から貢献を受け取ります`d`。 
5. 交換する`dp`新しく計算された行を使用します。 
6. すべての遷移が処理された後、最後の DP 行のすべての値を合計します。 

最後のステートメントは次のように保証されます。`s`したがって、残りのすべての深さは有効な完全なプログラムを表します。 
7. 結果のモジュロを出力します。$10^9+7$。 

### なぜ効果があるのか

 不変条件は、ステートメントを処理した後のものです。`i`、`dp[d]`ステートメントで終わる接頭辞の有効なインデント割り当ての数に等しい`i`、そのような発言`i+1`奥まったところに位置している`d`。 

のために`for`ステートメントでは、Python 構文は次のステートメントを正確に 1 レベル深くすることを強制するため、すべての状態が次のステートメントからシフトされます。`d`に`d+1`必要かつ十分です。 

単純なステートメントの場合、次のステートメントは現在の深さに留まるか、任意の数のアクティブなループを閉じた後に表示されます。 深層の状態`k`したがって、あらゆる深さに移行できます`0..k`。 接尾語の合計を計算すると、これらの可能性が正確に集計されます。 

すべての有効なインデントの選択は 1 つの DP 遷移に対応し、すべての DP 遷移は有効なインデントの選択に対応するため、DP はすべての有効なプログラムを 1 回だけカウントします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n = int(input())
    cmds = [input().strip() for _ in range(n)]

    dp = [0] * (n + 1)
    dp[0] = 1

    for i in range(n - 1):
        ndp = [0] * (n + 1)

        if cmds[i] == 'f':
            for d in range(n):
                ndp[d + 1] = dp[d]
        else:
            suffix = 0
            for d in range(n, -1, -1):
                suffix = (suffix + dp[d]) % MOD
                ndp[d] = suffix

        dp = ndp

    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```DP 配列には、インデントの深さによってインデックス付けされたカウントが格納されます。 までの深さのみ`n`ステートメントの数よりも深くなるプログラムはないため、これらが必要になります。 

のために`f`、移行は純粋なシフトです。 よくある間違いは、配列を適切な場所で更新することです。 これにより、現在の行の状態と次の行の状態が混合されます。 新鮮なものを使って`ndp`その問題を回避します。 

のために`s`、すべての深度は、すべてのより深い深度からの寄与を受け取ります。 これらの合計を直接計算すると、遷移ごとに二次時間がかかります。 suffix-sum スイープは、右から左への 1 回のパスでそれらを累積します。 

ループは次の場合のみ実行されます。`n - 1`発言。 これは意図的なものです。 声明`i`ステートメントの配置を決定します`i + 1`したがって、最後のコマンドには発信遷移がありません。 

最後に、残りの深さはすべて有効な終了状態であるため、それらのカウントが合計されます。
