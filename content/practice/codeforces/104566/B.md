 ## 解決策
 ## 問題の理解

 ノード 1 をルートとする重み付きツリーが与えられています。ルートを含むいくつかの頂点は最初は赤に色付けされており、他のすべての頂点は黒です。 すべての頂点について、そのコストは、ルートへのパス上の赤い頂点を使用して定義されます。頂点自体が赤の場合、そのコストはゼロです。そうでない場合は、ルートへの一意のパスに沿って上向きに検索し、最も近い赤い祖先を見つけます。コストは、ツリーに沿ってその祖先までの距離です。 

クエリごとに、頂点のサブセットが与えられます。 ツリー内の任意の場所で最大 1 つの頂点を選択し、それを一時的に赤にすることができます。 その変更後、すべての頂点のコストが同じルールを使用して再計算されます。 タスクは、クエリされた頂点間の最大コストを最小化することです。 

入力サイズにより、テスト ケースごとにほぼ直線的な時間で考える必要があります。 ツリーには最大 100,000 のノードを含めることができ、すべてのクエリでクエリされる頂点の合計数は 2,000,000 に達する可能性があります。 これにより、ツリーのクエリごとの走査や最初からの距離の再計算が即座に排除されます。 どのソリューションでも、ツリーを 1 回前処理し、クエリ セットのサイズに応じてほぼ直線的な時間で各クエリに応答する必要があります。 

単純なアプローチでは、新しく追加された赤い頂点の可能な選択肢をすべて試した後でコストを再計算します。 単一のクエリの場合、n 個の選択肢すべてを試し、毎回すべての ki 頂点の距離を再計算することになり、クエリあたり O(n·ki) となり、これは大きすぎます。 

より微妙な失敗例は、頂点を赤にする効果がグローバルではないことを無視したことに起因します。 たとえば、クエリ頂点 v の祖先ではない頂点 x について考えてみましょう。x を赤にしても、v にはまったく影響しません。 新しい赤い頂点が全体的にすべての距離を改善すると仮定するアプローチでは、不正確な答えが生成されます。 

別の失敗モードは、追加された赤いノードの候補としてクエリ頂点のみが重要であると仮定することです。 最適なノードは、クエリ セットの外側にある場合があります。たとえば、いくつかの高コスト クエリ頂点の共有祖先などです。 

## アプローチ

 重要な観察は、すべての頂点が、そのルート パス上の最も近い赤色の祖先から計算された、明確に定義されたコストをすでに持っているということです。 パス上に見られる最後の赤い頂点を維持し、エッジの重みのプレフィックス合計を使用して距離を計算することにより、ルートから 1 つの DFS でこれらのコストを前処理できます。 

これらの基本コストが判明すると、各クエリは頂点のサブセットに対する純粋な最適化問題になります。オプションで、独自のサブツリー内の頂点のみに影響を与える 1 つの新しい「ソース」頂点を導入することで、値のセットの最大値を削減したいと考えています。 

ブルートフォース戦略では、考えられるすべての頂点 x を新しい赤いノードとして試みます。 各 x について、クエリされた各頂点 v のコストを、元のコスト、または x がルートから v へのパス上にある場合は v から x までの距離として再計算します。これはクエリごとに O(n·k) のコストがかかり、指定された制約ですぐに失敗します。 

重要な簡略化は、現在の最大の答えを決定する頂点のみに焦点を当てることです。 クエリ頂点間の現在の最大コスト値を減らすことができない場合、改善は不可能です。 これを減らすことができる場合、新しい赤いノードは、その最大値を達成するすべての頂点のルートから LCA へのパス上になければなりません。そうしないと、そのうちの少なくとも 1 つは影響を受けないからです。 

これにより、新しい赤いノードの検索スペースが大幅に減少します。 すべての頂点を考慮する代わりに、最悪の頂点の LCA によって定義された単一の候補構造のみを考慮します。 

そこから、問題は、その LCA を新しい赤いノードとして選択することが、すべての最大コスト頂点を元の最大値以下に減らすのに十分であるかどうかを確認し、そうであれば、結果として得られる新しい最大値を計算することになります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての新しい赤いノードに対するブルート フォース | O(q・n・k) | O(n) | 遅すぎる |
 | LCAに基づく最適な削減 | O(∑k log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まずツリーを前処理して、頂点ごとに 2 つの値 (ルートからの距離と、最も近い赤色の祖先に基づくコスト) を計算します。 これは単一の DFS で行われ、現在のルート距離とパス上でこれまでに確認された最も近い赤いノードの両方が伝達されます。 

LCA クエリの場合、対数時間で LCA を計算できるように、標準のバイナリ リフティング構造も構築します。 

各クエリについて、次のように処理を進めます。 

1. クエリ セット内のすべての頂点をスキャンし、現在のコストを計算します。 このスキャン中に、最大コスト値 M を特定し、残りの頂点の 2 番目の最大コスト値も追跡します。 また、コストが M に等しい頂点のセット T を収集します。これにより、現在の答えを決定する頂点が正確に分離されます。 
2. T に頂点が 1 つだけ含まれている場合、その 1 つの頂点を削減することだけを考慮すればよいため、問題はより簡単になります。 複数の頂点が最大値を共有する場合、答えを改善するには、すべての頂点を同時に減らす必要があります。 
3. T 内のすべての頂点の LCA を計算します。このノードは、すべての最大コスト頂点の祖先である最も深い頂点であり、それらすべてに影響を与える新しい赤いノードの候補は、ルートからこの LCA までのパス上に存在する必要があります。 
4. この LCA を新しい赤いノードとして選択することが、T のすべての頂点を減らすのに十分であるかどうかをテストします。T の各 v について、新しいコストは v から LCA までの距離になり、これは dist_root[v] − dist_root[LCA] に等しくなります。 これらの値のいずれかが依然として少なくとも M である場合、最大値を改善することはできません。 
5. リダクションが有効な場合、クエリ頂点間の新しい最大値を計算します。 これは 2 つの値の最大値です。元のクエリ セットからの 2 番目の最大値と、T 内の頂点の中で最大の削減コストです。 
6. クエリの答えは、元の最大値 M と上記で得られた改善された値の間の最小値です。 

### なぜ効果があるのか

 このアルゴリズムは、最大コストを達成する頂点のみが改善の対象となるという事実に基づいています。 有効な改善は、それらすべてを同時に削減する必要があります。 それ以外の場合、最大値は変更されません。 それらすべてに影響を与えることができる唯一の頂点は、すべての最大コスト頂点の祖先である頂点であり、その中で最も深い頂点は、影響を受けるすべてのノードまでの距離を最小化します。 これにより、上位の祖先は実現可能性を向上させることなく距離が増加するだけであるため、最適な候補が最大セットの LCA になるように強制されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m, q = map(int, input().split())
    red = list(map(int, input().split()))
    red_set = set(red)

    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v, w = map(int, input().split())
        g[u].append((v, w))
        g[v].append((u, w))

    LOG = (n + 1).bit_length()
    up = [[0] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)
    dist_root = [0] * (n + 1)
    parent_red = [0] * (n + 1)

    def dfs(u, p):
        up[0][u] = p
        parent_red[u] = p if u in red_set else parent_red[p]
        for v, w in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            dist_root[v] = dist_root[u] + w
            dfs(v, u)

    dfs(1, 0)

    for i in range(1, LOG):
        for v in range(1, n + 1):
            up[i][v] = up[i - 1][up[i - 1][v]]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        diff = depth[a] - depth[b]
        i = 0
        while diff:
            if diff & 1:
                a = up[i][a]
            diff >>= 1
            i += 1
        if a == b:
            return a
        for i in range(LOG - 1, -1, -1):
            if up[i][a] != up[i][b]:
                a = up[i][a]
                b = up[i][b]
        return up[0][a]

    # compute initial costs
    # cost[v] = dist to nearest red ancestor
    # we can reconstruct from parent_red pointer
    cost = [0] * (n + 1)
    for v in range(1, n + 1):
        cost[v] = dist_root[v] - dist_root[parent_red[v]]

    for _ in range(q):
        tmp = list(map(int, input().split()))
        k = tmp[0]
        nodes = tmp[1:]

        M = -1
        M2 = -1
        T = []

        for v in nodes:
            c = cost[v]
            if c > M:
                M2 = M
                M = c
                T = [v]
            elif c == M:
                T.append(v)
            elif c > M2:
                M2 = c

        if len(T) == 1:
            t_lca = T[0]
        else:
            t_lca = T[0]
            for v in T[1:]:
                t_lca = lca(t_lca, v)

        # check feasibility of using t_lca
        ok = True
        best_reduced = 0

        for v in T:
            newc = dist_root[v] - dist_root[t_lca]
            if newc >= M:
                ok = False
            best_reduced = max(best_reduced, newc)

        if not ok:
            print(M)
        else:
            ans = max(M2, best_reduced)
            print(min(M, ans))

if __name__ == "__main__":
    solve()
```このソリューションは、ルート距離を計算し、すべてのノードについて、ルート パス上で最も近い赤い祖先を識別する DFS から始まります。 これにより、任意の頂点の初期コストを定数時間で評価できるようになります。 

バイナリ リフティングは、クエリ内のすべての最大コスト頂点の共通の祖先を繰り返し計算する必要があるため、LCA クエリに使用されます。 LCA 計算は、クエリごとの唯一の対数成分です。 

各クエリは、頂点を 1 回スキャンして最大コストと 2 番目の最大コストを抽出し、最悪の頂点のセットを収集することによって処理されます。 このセットの LCA は、新しい赤い頂点を配置するための唯一の意味のある候補を定義します。 

最後に、この候補が実際にすべての最悪の頂点を現在の最大値未満に削減できるかどうかを検証し、それに応じて改善された答えを計算します。 

## 実用的な例

 クエリ対象のノードのコストが次のようなクエリを考えてみましょう。`[10, 7, 10, 3]`。 

| ステップ | アクション | M | M2 | た | LCA(T) |
 | --- | --- | --- | --- | --- | --- |
 | 1 | ノードをスキャン | 10 | 7 | [v1、v3] | - |
 | 2 | T の LCA を計算する | 10 | 7 | [v1、v3] | × |

 両方の最大コスト ノードが異なるブランチにある場合、それらの LCA が改善の唯一の候補になります。 両方のノードから x までの距離が 10 未満の場合、最大値は低下します。 それ以外の場合は、変更されないままになります。 

次に、すべてのノードにコストがある 2 番目のクエリを考えてみましょう。`[5, 5, 5]`。 

| ステップ | アクション | M | M2 | た | LCA(T) |
 | --- | --- | --- | --- | --- | --- |
 | 1 | ノードをスキャン | 5 | - | すべてのノード | - |
 | 2 | T の LCA を計算する | 5 | - | すべてのノード | ルートサブツリーノード |

 この場合、LCA を選択した後でも、少なくとも 1 つのノードのコストが 5 以上である可能性があるため、改善は不可能で、答えは 5 のままです。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + qk) log n) | DFS 前処理と、収集された最悪のノードに対するクエリごとの LCA |
 | スペース | O(n log n) | バイナリリフティングテーブルと補助配列 |

 この制約により、最大合計 10^6 のノードと合計 2×10^6 のクエリ要素が許可されるため、対数 LCA 演算と組み合わせたクエリごとの線形スキャンは制限内に快適に収まります。

 ## 特殊なケース

 クエリされたすべての頂点が赤であるか、そのすぐ上に赤い祖先があるため、すでにコストがゼロである場合、アルゴリズムは M をゼロとして正しく識別し、改善が不可能であるため、すぐにゼロを返します。 

複数の最大コスト頂点が完全に異なるサブツリーにある場合、LCA がツリー内で高くなり、それらすべてを十分に削減できなくなります。 候補の赤いノードを適用した後、少なくとも 1 つの頂点が元の最大しきい値以上のままであるため、実行可能性チェックは正しく失敗します。 

クエリに単一の頂点が含まれている場合、アルゴリズムはその頂点を改善できるかどうかを正しくチェックしますが、候補となる赤色ノードはいずれもその祖先である必要があるため、LCA 計算は頂点自体に縮退し、変更は生じず、正確性が維持されます。
