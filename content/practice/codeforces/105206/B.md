 ## 問題の理解

 負でない整数の長いシーケンスが与えられます。 目標値も与えられます`x`。 タスクは、シーケンス内を調べて、要素の合計が正確に一致する連続セグメントを見つけることです。`x`。 このようなすべてのセグメントの中から、可能な限り最大の長さを持つセグメントを選択するように求められます。 複数のセグメントがその最大長を共有する場合は、そのうちの 1 つを使用できます。 合計が正確に一致するセグメントがない場合`x`、失敗を報告します。 

出力はセグメント自体ではなく、それを記述する 2 つの値、つまりセグメントの長さと 1 から始まるインデックスを使用した開始位置です。 

制約はソリューションを形作るものです。 配列サイズは 500 万要素に達する可能性があるため、すべての部分配列を明示的に検査するメソッドは存続できません。 単純な配列にプレフィックスの合計を格納することさえ、メモリ内では限界に達しますが、慎重に行えば可能です。 合計限界は 10^16 までになります。これにより、32 ビット演算では累算に不十分であることが保証されるため、全体で 64 ビット整数が必要になります。 

重要な構造特性は、すべての数値が負ではないことです。 これにより、有効なウィンドウの移動方向が完全に決定されます。ウィンドウの合計が超過すると、`x`、これ以上拡大しても状況を解決することはできず、縮小することのみが役立ちます。 

素朴な推論を打ち破るいくつかの特殊なケースがあります。 

最初のエッジケースは次のような場合です`x = 0`。 すべての数値は負ではないため、有効なセグメントは完全にゼロで構成されるセグメントのみです。 プラスの増加を想定した単純なスライディング ウィンドウはまだ機能する可能性がありますが、合計が変化したときにのみポインタを移動する実装は、ゼロ拡張を慎重に処理しないと行き詰まる可能性があります。 

例:

```正解は`3 2`、3 つのゼロのセグメント。 

2 番目のエッジ ケースは、すべての要素が大きく、合計が次の値を超える場合です。`x`すぐに; ここでは縮小のみが問題であり、正しく縮小できないと、2 ポインタ実装で無限に拡張が試行されることになります。 

## アプローチ

 ブルートフォースソリューションでは、すべての開始インデックスを列挙します。`l`、それぞれについて`l`、 伸ばす`r`を超えるか一致するまで累計を維持しながら`x`。 一致する場合は、最適な長さを更新します。 すべての部分配列が考慮されるため、これは正しいですが、最悪の場合、O(n^2) 個のセグメントが検査され、合計作業量は O(n^2) 個の加算にまで低下します。 と`n = 5 * 10^6`、これはまったく実現不可能です。 

重要な観察は、すべての数値が負ではないという事実から得られます。 これにより、ウィンドウを維持すると、`[l, r]`合計が大きくなりすぎて増加します`r`悪化させるだけです。 この単調な動作により、両方のエンドポイントが前方にのみ移動するスライディング ウィンドウを維持できます。 各要素はウィンドウに出入りするのは最大 1 回であるため、有効な合計を線形時間で追跡できます。 

すべてのサブ配列をチェックする代わりに、常に現在の合計を表す動的間隔を維持します。 右端を貪欲に拡大し、合計が大きくなりすぎると再び有効になるまで左から縮小していきます。 合計が等しくなるたびに`x`, ウィンドウが以前のものよりも長い場合は、ベストアンサーを更新します。

 ## アルゴリズムのチュートリアル

 1. 2 つのポインタを初期化する`l = 0`、`r = 0`、および累計`s = 0`。 ベストアンサーも保存します`(best_len, best_l)`見つからないものとして初期化されます。 2 つのポインタは、検討中の現在のウィンドウを定義します。 
2.移動`r`配列全体を左から右に追加して、`a[r]`に`s`各ステップで。 これにより、現在のウィンドウが拡張され、より多くの要素が含まれます。 
3. 各拡張後、`s > x`そして`l <= r`、減算`a[l]`から`s`そして増加します`l`。 すべての値が負ではないため、これによりウィンドウの実現可能性が復元されます。つまり、合計を減らす唯一の方法は縮小することになります。 
4. いつでも`s == x`、現在のウィンドウの長さを比較します`r - l + 1`これまでに見つかった中で最高の長さです。 それより大きい場合は、最良の回答を更新します`(length, l + 1)`出力では 1 から始まるインデックスが使用されるためです。 
5. まで続けます`r`配列の最後に到達します。 最終的に保存された回答は、最長の有効なセグメントです。 

### なぜ効果があるのか

 正しさは単調性の性質に依存します: 合計が超過すると`x`、右側のエンドポイントの今後の拡張では、最初に左側から要素を削除しない限り、この問題を修正することはできません。 すべての値が負ではないため、合計は拡張時にのみ増加します。`r`、移動時にのみ減少します。`l`。 これにより、すべてのサブ配列が正しいエンドポイントを持つことが保証されます`r`は、処理中に 1 つの左ポインタ位置によって一意に表されます。 その結果、有効なウィンドウはスキップされず、制約の下で最小になった時点ですべての候補が正確に評価されます。`s <= x`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    a = list(map(int, input().split()))

    l = 0
    s = 0

    best_len = 0
    best_l = -1

    for r in range(n):
        s += a[r]

        while l <= r and s > x:
            s -= a[l]
            l += 1

        if s == x:
            length = r - l + 1
            if length > best_len:
                best_len = length
                best_l = l + 1

    if best_l == -1:
        print(-1)
    else:
        print(best_len, best_l)

if __name__ == "__main__":
    solve()
```この実装では、2 つのインデックスを使用してスライディング ウィンドウを維持します。 合計`s`常に現在のセグメントの合計を表します`[l, r]`。 内側のループは、合計が次の値を超えるたびに有効性を復元する責任があります。`x`。 各要素は左から一度だけ削除されるため、このループでは二次的な動作は作成されません。 

回答の更新は次の場合にのみ発生します。`s == x`、これまでに確認された最大ウィンドウ長を追跡します。 1 から始まる形式へのインデックスの変換は、後で調整を繰り返すことを避けるために割り当て時に処理されます。
