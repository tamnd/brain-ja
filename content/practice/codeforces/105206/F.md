 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テストケースには、$N$女の子たち、そしてそれぞれの女の子たち$i$セグメントが割り当てられています$[l_i, r_i]$。 課題は、各女の子に個別の整数の「店番号」を割り当てることができるかどうかを決定することです。$i$彼女は許可されたセグメント内で店を受け取りますが、2 人の女の子が同じ店を共有することはありません。 

お店には1からまでのラベルが付いていますが、$10^9$実際に利用可能なすべてのショップを構築する必要はないため、相対的な順序のみが重要になります。 重要なのは配置できるかどうかです$N$ポイント、間隔ごとに 1 つ、衝突なし。 

制約は大きく、すべてのテスト ケースにわたる間隔の合計数は最大です。$2 \cdot 10^5$。 これにより、テスト ケースごとの二次推論が即座に除外されます。 残りのすべての間隔を繰り返しスキャンしたり、ネストされたループですべての割り当てを貪欲に試行したりするアプローチは失敗します。 もっと近いものが必要です$O(N \log N)$テスト ケースごと、またはすべてのテスト ケースにわたる線形償却。 

ここでの一般的な失敗モードは、間隔構造を無視した貪欲な戦略から生じます。 

間違った考えの 1 つは、利用可能な最小のショップを常に任意の順序で各間隔に割り当てることです。 間隔を考慮してください。$[1, 100]$、$[1, 1]$、$[2, 2]$。 

入力順に処理して貪欲に割り当てると、有効な割り当てが存在する場合でも、最初の間隔に 1 を割り当てて 2 番目の間隔をブロックしてしまう可能性があります。$[1,1]$、2から$[2,2]$、100から$[1,100]$。 間違いは、緊急性を尊重せずに間隔を独立して扱うことです。 

もう 1 つの失敗は、左のエンドポイントでソートし、増加する位置を貪欲に割り当てていることです。 これも失敗します。早期に開始される間隔が必ずしも最も制約されているわけではないからです。 

重要な問題は、各間隔がその適切なエンドポイントによって課せられる「締め切りのような」構造を持つことです。 

## アプローチ

 ブルートフォースアプローチでは、再帰的またはバックトラッキングによってショップを割り当てようとします。 各ステップで女の子を選び、その間に利用可能なすべての店を試します。 最悪のケースでは、割り当てごとに可用性が 1 ずつ減少しますが、分岐は依然として大きいため、指数関数的な構成が検討されます。 枝刈りを行ったとしても、間隔が重なり合うと最悪の場合、急速に劣化してしまいます。 

問題の構造は、スケジューリングの解釈を示唆しています。つまり、各女の子には範囲内で一意の整数を割り当てる必要があります。これは、単位長のジョブを制約のある数直線上に配置するのと同じです。 これは、期限付きの間隔スケジュールと密接に関連しています。 

重要な洞察は、正しいエンドポイントの昇順で間隔を処理することです。 所定の位置に着いたら$x$、その時点で利用可能な最も制限された間隔、具体的にはまだ受け入れ可能な間隔の中で最も早く終了する間隔にそれを割り当てたいと考えています。$x$。 これにより、柔軟な間隔で小さなエンドポイントを無駄にすることがなくなります。 

可能なショップ位置を左から右にスイープしてシミュレートしますが、すべての整数を反復するわけではありません。 代わりに、左側のエンドポイントに到達したアクティブな間隔のセットを維持し、次に使用可能な位置を常に右側のエンドポイントが最小の間隔に割り当てます。 ある時点で最小右端点が現在の位置よりも小さい場合、それは間隔を満足できなくなったことを意味します。 

これにより、問題は、最小ヒープを使用した古典的な貪欲な実行可能性チェックに縮小されます。

 ## アルゴリズムのチュートリアル

 各間隔は次の時点で利用可能になると解釈します。$l_i$で期限切れになります$r_i$。 増加するショップインデックスの割り当てをシミュレートします。 

1. すべての間隔を左のエンドポイントで並べ替えます。 これにより、ポジションを受け取る資格が得られるようになったときに、インターバルを正確にアクティブ化することができます。 
2. ソートされた間隔に対するポインタと、正しいエンドポイント順に並べられた最小ヒープを維持します。 ヒープは、現在割り当て可能なすべての間隔を表します。 
3. 変数をスイープする`x`割り当てようとしている次のショップインデックスを表します。 すべての整数を次の値まで繰り返すのではなく、$10^9$、私たちは動くだけです`x`アクティブな間隔が少なくとも 1 つある場合。 アクティブな間隔がない場合はジャンプします`x`次の間隔の左端点まで。 
4. 割り当てる前に`x`、すべての間隔をヒープに挿入します$l_i \le x$。 これらは、この位置を使用できる可能性のある間隔です。 
5. アクティブ化後にヒープが空の場合は、ジャンプします。`x`この位置を使用できるインターバルがないため、再び前方に移動します。 これにより、意味のあるポジションのみが処理されることが保証されます。 
6. 最小の間隔を取る$r_i$山から。 この間隔は、今後の割り当てに対する制約が最も厳しいため、最も緊急です。 
7. もし$r_i < x$、この間隔にはもう有効なショップを割り当てることができないため、回答は不可能です。 それ以外の場合は、割り当てます$x$それにアクセスしてヒープから削除します。 
8. インクリメント`x`すべての間隔が割り当てられるか、矛盾が発生するまで繰り返します。 

ステップ 6 の順序の選択は重要な決定です。最も早く終了する間隔を常に満たすことで、後の実行可能性が妨げられることを防ぎます。 

### なぜ効果があるのか

 どの時点でも、すべてのアクティブなインターバルには、$l_i \le x$、したがって、彼らはポジションを受け取る資格があります$x$またはそれ以降。 その中で、小さい端点を無視して、より大きい右端点を持つ区間を選択すると、より厳しい制約が先送りされ、後で実現可能性が失われる危険があります。 実行可能な割り当ては、それぞれの位置で次のように変換できます。$x$、割り当てられる間隔は最小値を持つ間隔です。$r_i$緩い間隔と狭い間隔の間で割り当てを交換しても有効性が損なわれることはなく、スラックが改善されるだけであるためです。 この交換議論により、解決策が存在するときはいつでも、貪欲な選択によって実現可能性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        intervals = [tuple(map(int, input().split())) for _ in range(n)]
        intervals.sort()

        heap = []
        i = 0
        x = 1
        ok = True

        while i < n or heap:
            if not heap and i < n and x < intervals[i][0]:
                x = intervals[i][0]

            while i < n and intervals[i][0] <= x:
                heapq.heappush(heap, intervals[i][1])
                i += 1

            if not heap:
                continue

            r = heapq.heappop(heap)
            if r < x:
                ok = False
                break

            x += 1

        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```中心的な構造は、可能な割り当て上のスイープ ラインです。 並べ替えられた配列により、間隔が正しい時間に導入されることが保証されます。 左側のエンドポイントは挿入時にすでに満たされているため、ヒープには右側のエンドポイントのみが格納されます。 変数`x`割り当てが成功した場合、または空の領域を飛び越える必要がある場合にのみ進みます。 

微妙な点は、アクティブなインターバルがない場合のジャンプです。 これがないと、アルゴリズムは最大の大きなギャップを不必要に反復する可能性があります。$10^9$、タイムアウトが発生します。 いずれにせよ、そのギャップ内には間隔を割り当てることができないため、ジャンプは正確さを維持します。

 ## 特殊なケース

 最初のエッジ ケースは、すべての間隔が単一の点に崩壊する場合です。 入力用$[1,1], [1,1]$、ヒープには有効な割り当てが 1 つだけ含まれています。$x=1$、使用可能な 2 番目の位置がないため、2 番目の間隔はすぐに失敗します。 

もう 1 つのケースは、間隔が大きく離れている場合です。 のために$[1,1], [100,100], [200,200]$、アルゴリズムは繰り返しジャンプします`x`次に利用可能な左側のエンドポイントに移動します。 各間隔は分離されているため、ヒープが空になると反復を無駄にすることなく正しいスキップがトリガーされます。 

最後のケースは、次のような重なり合いです。$[1,10]$何度も繰り返しました。 ヒープはすべての間隔で増加し、アルゴリズムは 1 から始まる連続した整数を割り当てます。間隔の数が範囲の和集合の長さを超える場合、ヒープは最終的に次の間隔を生成します。$r < x$、容量が使い果たされたときにまさに拒否が発生します。
