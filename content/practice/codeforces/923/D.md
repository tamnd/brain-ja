 ## 解決策

 ## 問題の理解

 文字 A、B、C からなるソース文字列と、同じアルファベット上の別のターゲット文字列が与えられます。 クエリは、連続セグメント内で何度でも適用されるローカル書き換えルールのセットを使用して、ソースの選択された部分文字列をターゲットの選択された部分文字列に変換できるかどうかを尋ねます。 

許可される操作は対称的であり、部分文字列に対してのみ作用します。 それぞれの 1 文字を他の 2 文字のペアに拡張でき、3 つ連続する A のブロックを完全に消去できます。 操作は繰り返しどこにでも適用できるため、問題はステップのシミュレーションではなく、生成された変換システムの下で 2 つの文字列が同等であるかどうかを判断することです。 

各クエリは 2 つの部分文字列 (1 つは S から、もう 1 つは T から) を分離し、これらの規則に従って最初の部分文字列を 2 番目の部分文字列に変換できるかどうかを尋ねます。 最大 10^5 のクエリがあり、部分文字列の長さも長いため、クエリごとに何かを再計算することは不可能です。 各クエリが一定時間または対数時間で応答されるように、構造を事前に計算する必要があります。 

単純な試みでは、クエリされた各部分文字列の変換をシミュレートしようとします。 これは、単一の部分文字列であっても、A → BC のような拡張では指数関数的に増大する可能性があり、繰り返されるアプリケーションにわたる分岐要素により、BFS または DFS アプローチが実行不可能になるため、すぐに失敗します。 

より微妙な失敗例は、ソリューションがパターンをローカルで貪欲にキャンセルしようとした場合に発生します。 たとえば、将来の変換を考慮せずに AAA を貪欲に削除すると、後で拡張を通じて B と C を導入できるかどうかが変わり、不正確な等価性の決定につながる可能性があります。 

本当の難しさは、変換では、ローカルな書き換えからは明らかではない特定のグローバルな不変式が保持され、クエリは部分文字列に対してそれらの不変式を比較することによって応答する必要があることです。 

## アプローチ

 ブルート フォース戦略では、ソース部分文字列から開始して考えられるすべての書き換えをシミュレートし、ターゲット部分文字列に到達することを試みます。 各文字は他の 2 つに分岐できるため、1 つのステップで長さが増加し、枝刈りを行っても状態空間は指数関数的に増加します。 長さが 10^5 までの部分文字列の場合、これはまったく対処が困難です。 

重要な観察は、書き換えシステムは複雑に見えますが、強力に構造化されているということです。 文字を小さな代数システムに埋め込む場合、各演算では文字数間の線形関係が維持されます。 A → BC、B → AC、および C → AB の展開は対称的であり、各文字がベクトルに対応し、置換によってベクトルの合計が保存されるバイナリ ベクトル エンコーディングを示唆しています。 

このエンコーディングが特定されると、部分文字列の等価性は、変換をシミュレートするのではなく、各部分文字列の小さな固定サイズの要約を比較することになります。 AAA → 空ルールでは、A コンポーネントに追加の定期的な削減が導入され、生のカウントへの依存が削除され、モジュール動作に置き換えられます。 これにより、部分文字列ごとに一定数の集計値のみが必要になることが保証されます。 

したがって、問題は前処理タスクになります。つまり、O(1) 内の任意の部分文字列の不変署名を抽出できるプレフィックス集計を計算し、署名を比較することで各クエリに答えることができます。

 ## アルゴリズムのチュートリアル

 中心的なアイデアは、すべての置換ルールでベクトルの加算が維持されるように、各文字に固定の 2 次元バイナリ ベクトルを割り当てることです。 

私たちは以下を選択します:

 A = (1, 0)、B = (0, 1)、C = (1, 1)

 これが機能する理由は次のとおりです。

A → BC は (1,0) = (0,1) ⊕ (1,1) となります。 

B → AC は (0,1) = (1,0) ⊕ (1,1) となります。 

C → AB は (1,1) = (1,0) ⊕ (0,1) になります。 

したがって、すべての展開では部分文字列の XOR 合計が保持されます。 

ただし、AAA → 空というルールもあるため、これだけでは十分ではありません。 XOR システムでは次のようになります。 

A ⊕ A ⊕ A = A

 したがって、AAA を削除すると XOR 値が変更されます。つまり、XOR だけでは完全なシステムでは不変ではありません。 欠けている部分は、AAA が任意の部分文字列内に繰り返し適用できることです。これにより、基礎となる整数表現の 3 の倍数で A コンポーネントを効果的に調整できるようになります。 これは、A がトリプルのリダクション後に 2 を法として定義された量のように動作することを意味します。 

これを正しく処理するために、プレフィックスごとに 2 つの情報層を追跡します。 

1. 2 ビット エンコーディングでの (B, C) 寄与の XOR 署名。 
2. トリプルを削除する機能に基づいて削減されたカウント。これは、AAA をローカルで削除する方法から得られる A カウント モジュロ 3 とパリティ情報を格納することによって表すことができます。 

プレフィックス配列を使用すると、各部分文字列を、その等価クラスを完全に記述する正規の 4 ビット署名に縮小できます。 

これからは段階的に進めていきます。 

### アルゴリズムのステップ

 1. 各文字に 2 ビット XOR ベクトル (A = 01、B = 10、C = 11) を一貫した基準で割り当てます。 これにより、すべてのバイナリ展開で XOR が保持されるようになります。 
2. S と T の両方のプレフィックス XOR 配列を構築して、部分文字列 XOR を O(1) で計算できるようにします。 
3. A のみが AAA 削除ルールと相互作用するため、A のプレフィックス数を個別に追跡します。 
4. 3 つの A のグループは任意の部分文字列内で任意に削除できるという事実を使用して A の数を減らします。つまり、A の剰余クラス 3 を法とするもののみが内部約分可能性に影響を与えます。 
5. 部分文字列クエリごとに、以下を抽出します。 

部分文字列の XOR 署名、および縮小された A 署名。 
6. S[a..b] と T[c..d] の結果の署名を比較します。 両方が一致すれば変身可能です。 

### なぜ効果があるのか

 変換システムは、小さなアーベル不変量によって完全に捕捉される文字列の同値関係を生成します。 A、B、C の書き換えルールは XOR 構造を保持し、AAA の削除により、最大 3 の倍数までの A 座標のあいまいさが除去されます。 一連の操作によってこれらの不変式を変更することはできません。逆に、許可された拡張とキャンセルを使用して中間形式を構築することにより、同一の不変式を持つ 2 つの部分文字列を相互に変換できます。 これにより、署名は等価性のために必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# map characters to 2-bit XOR representation
# A = 01, B = 10, C = 11
def enc(ch):
    if ch == 'A':
        return 1  # 01
    if ch == 'B':
        return 2  # 10
    return 3      # 11

s = input().strip()
t = input().strip()
q = int(input())

n, m = len(s), len(t)

# prefix XOR for 2-bit representation
ps = [[0, 0]]
for ch in s:
    v = enc(ch)
    ps.append([ps[-1][0] ^ (v & 1), ps[-1][1] ^ ((v >> 1) & 1)])

pt = [[0, 0]]
for ch in t:
    v = enc(ch)
    pt.append([pt[-1][0] ^ (v & 1), pt[-1][1] ^ ((v >> 1) & 1)])

# prefix count of A for handling AAA cancellations
cs = [0]
ct = [0]

for ch in s:
    cs.append(cs[-1] + (ch == 'A'))
for ch in t:
    ct.append(ct[-1] + (ch == 'A'))

def get_xor(pref, l, r):
    return (pref[r][0] ^ pref[l - 1][0],
            pref[r][1] ^ pref[l - 1][1])

def get_a(pref, l, r):
    return pref[r] - pref[l - 1]

out = []

for _ in range(q):
    a, b, c, d = map(int, input().split())

    xs = get_xor(ps, a, b)
    xt = get_xor(pt, c, d)

    as_ = get_a(cs, a, b)
    at_ = get_a(ct, c, d)

    # reduce A count modulo 3 (AAA deletion freedom)
    if as_ % 3 != at_ % 3:
        out.append('0')
        continue

    if xs == xt:
        out.append('1')
    else:
        out.append('0')

print(''.join(out))
```このコードは、各クエリで 2 つの不変式 (XOR 署名と削減された A カウント) のみを抽出するようにプレフィックス構造を構築します。 XOR 抽出では標準のプレフィックス キャンセルが使用されますが、A カウント チェックでは AAA 削除の下で一貫性が確保されます。 A-mod-3 条件は構造的等価性を比較する前に不可能なケースを迅速にフィルタリングするため、チェックの順序が重要になります。 

微妙な点は、S と T の両方を対称的に扱う必要があることです。 AAA の削除は両方の文字列で独立して発生する可能性があるため、A が削減される方法に非対称性があると、正確性が損なわれます。 

## 実用的な例

 ### トレース例 1

 S = "AAB" と T = "ABC" を比較するクエリを考えてみましょう。 

| ステップ | S 部分文字列 | T 部分文字列 | XOR S | XOR T | モッド3S | A mod 3 T | 決定 |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 抜粋 | ＡＡＢ | ABC | (1,2) | (0,0) | 2 | 1 | 不一致 |

 XOR 値はすでに異なっているため、部分文字列は等価ではありません。 両方に A が含まれている場合でも、B と C が存在すると、不変条件は即座に破られます。 

### トレース例 2

 S = "AAAC" および T = "C" とします。 

| ステップ | S 部分文字列 | T 部分文字列 | XOR S | XOR T | モッド3S | A mod 3 T | 決定 |
 | --- | --- | --- | --- | --- | --- | --- | --- |
 | 抜粋 | AAAC | C | (1,1) | (1,1) | 3→0 | 0 | 一致 |

 AAA ブロックは内部でキャンセルされ、C だけが残ります。XOR と縮小された A 状態の両方が一致するため、変換が可能です。 

これらのトレースは、アルゴリズムが構造の進化を追跡せず、等価性を判断するのに十分な不変署名のみを追跡することを示しています。

| スペース | O(n + m) | XOR および A カウントのプレフィックス配列 |

 ## 特殊なケース

 部分文字列に多くの A が含まれているが、その数が 3 の倍数である場合、微妙なケースが発生します。 たとえば、「AAAAAA」は、AAA の削除が繰り返されると完全に減少するため、その有効な A 寄与はゼロになります。 A カウントは比較前に 3 を法として削減されるため、アルゴリズムはこれを正しく処理し、すべての完全にキャンセル可能なブロックが同じシグネチャにマップされるようにします。 

もう 1 つのエッジ ケースは、XOR は一致するが A 残基が異なる場合です。 たとえば、2 つの部分文字列は両方とも B と C の分布は同じですが、A の数が異なる場合があります。 この状況では、XOR チェックだけではそれらが誤って受け入れられますが、モジュロ 3 フィルターが等価性をブロックします。 

最後のエッジ ケースは、部分文字列の A カウントが 3 を法として同じであるが、B と C の配置が構造的に異なる場合に発生します。 ここでは、XOR シグネチャによって誤検知が防止されます。これは、許可された置換では達成できない再配置によってバイナリの不変式が変更され、拒否が発生するためです。
