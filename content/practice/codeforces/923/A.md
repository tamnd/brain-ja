 ## 問題の理解

 2 手の後のゲームの価値が与えられます。$X_2$。 ゲームは未知の整数から始まります$X_0 \ge 3$、2人のプレイヤーが交互にこの値を変更します。 各手ごとに、プレイヤーは素数を選択します$p$現在の数値よりも厳密に小さい値を指定し、現在の数値を次の最小倍数に置き換えます。$p$それは少なくとも現在の値です。 現在の数値がすでに割り切れる場合$p$、変わりません。 

アリスが 1 つ移動し、ボブが 1 つ移動すると、結果の値は次のようになります。$X_2$。 タスクは、可能な最小の開始値を再構築することです。$X_0$一連の有効な選択の下では、この最終状態に至る可能性があります。 

制約により許可されるのは、$X_2$まで$10^6$。 これは十分小さいので、約数や素数について線形または線形に近い推論を行うことができます。 二次関数の何か$X_2$は不必要で無駄になりますが、分岐係数は各ステップの現在の値より下のすべての素数から得られるため、考えられるすべての移動シーケンスに対する完全な総当たりは不可能です。 

素朴な解釈では、最後の 2 つの手で使用された両方の素数を推測し、「倍数に切り上げる」操作を逆にすることで、逆方向のシミュレーションを試みることになります。 多くの異なる素数が数値を多くの可能な以前の状態にマッピングできるため、これはすぐに曖昧になります。 たとえば、から$X_2 = 20$、ボブが使用したかどうかは不明です$2$(割り算に応じて 18、19、または 20 から計算されます) または$5$（16日から19日まで）。 構造を持たずにあらゆる可能性を列挙しようとする不注意な逆シミュレーションは、組み合わせ論的に爆発してしまいます。 

重要な問題は、各移動が選択した素数による「強制的な割り算」のみを行うことです。これにより、同じ結果にマッピングされる長くて平坦な数値セグメントが作成されるため、複数の履歴が同じエンドポイントに崩壊します。 

## アプローチ

構造的な洞察は、プライムが固定された後の各動きを決定論的な変換として見ることで得られます。 プレイヤーがプライムを選択した場合$p$、次の値は完全に決定されます。それが最初の数値です。$\ge X$で割り切れる$p$。 これは、各移動が「選択された素数の次の倍数に進む」ことを意味します。 

1 つの手を逆転するということは、次のことを求めることを意味します。$Y$、値を評価します$X$プライムを使って生成できたかもしれない$p$? その条件とは、$Y$次の最初の倍数でなければなりません$p$以下ではない$X$、 それで$X$狭間にある$(Y - (Y \bmod p), Y]$、そしてまた$p < X$。 これはすでに、有効な先行者が$Y$～の約数の周りに集まる$Y$。 

重要な還元は、素数の除算のみであることです。$X_2$または密接に関連する約数が最後の手にとって重要になる可能性があり、1 つの逆ステップともう 1 つの逆ステップの後に到達可能な状態のみを考慮する必要があります。 ゲームの長さは 2 手に固定されているため、有効な素数をそれぞれ考慮することで、最初の手の後に取り得る値を列挙できます。$p$ボブが選んだ可能性があるものをすべて再構築する$X_1$、そして同様にアリスの手を逆転させます。

 ## アルゴリズムのチュートリアル

 から逆方向にプロセスを再構築します。$X_2$、可能な限りすべてを生成します$X_1$、そしてそれぞれから$X_1$あらゆる可能性$X_0$、次に、最小の有効な結果を取得します。 

1. すべての素数を列挙する$p < X_2$。 そういったものごとに$p$、可能な限りすべてを決定します$X_1$変わる可能性のある価値観$X_2$選択することで$p$ボブの移動中。 

重要な観察は、ボブの動きによって次のようなことが起こるということです。$X_2$次の最初の倍数として$p$より小さくない$X_1$、 それで$X_1$前の倍数からの間隔内になければなりません$p$プラス 1 まで$X_2$。 
2. 各候補者について$X_1$、アリスの逆の動きを考えてみましょう。 すべての素数について$q < X_1$、可能なすべてを計算します$X_0$生成された可能性のある値$X_1$同じように。 

これもまた、次の倍数で区切られた間隔です。$q$, したがって、可能な開始値の範囲を回復します。 
3. 再構築されたすべての全体にわたってグローバル最小値を維持する$X_0$価値観。 
4. 多くの区間が重なっているため、すべての整数を明示的に列挙する代わりに、算術演算を使用して範囲を計算します。$p$、の最大倍数を計算します。$p$を超えない$X_2$を実行し、候補範囲を効率的に導出します。 
5. 有効な最小値を返します$X_0$すべての有効な 2 段階分解にわたって発見されました。 

### なぜ効果があるのか

 各移動は整数をセグメントに分割し、固定素数の場合は結果が同一になります。 逆のステップでは、この分割を連続した間隔に単純に反転します。 移動が 2 つだけなので、$X_2$は、素数誘導分割から導出された少数のそのような間隔の和集合です。 このアルゴリズムは、有効な素数によって引き起こされるすべてのパーティションを列挙し、それらを 2 つのレイヤー間で正しく交差させ、有効な開始値の欠落や無効な値の導入がないことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAX = 10**6 + 5

# sieve for primes
is_prime = [True] * MAX
is_prime[0] = is_prime[1] = False
primes = []

for i in range(2, MAX):
    if is_prime[i]:
        primes.append(i)
        for j in range(i * i, MAX, i):
            is_prime[j] = False

def candidates_after_move(x):
    """
    Returns all possible previous values y such that some prime p < y
    could have produced x as the next state.
    We reconstruct by checking all primes p dividing into possible structure.
    """
    res = set()

    for p in primes:
        if p >= x:
            break

        # find all y such that ceil(y/p)*p == x
        # let k = x // p (floor)
        k = x // p
        if k == 0:
            continue

        # x must be a multiple of p to be exact endpoint
        if x % p == 0:
            start = (k - 1) * p + 1
            end = x
            # but also ensure p < y
            if start < x:
                res.add((start, end))
        else:
            # x is not multiple of p => cannot be exact landing point
            continue

    return res

def solve():
    x2 = int(input().strip())

    ans = x2

    # try all possible Bob primes leading to x2
    for p in primes:
        if p >= x2:
            break

        if x2 % p == 0:
            start1 = (x2 // p - 1) * p + 1
            for x1 in range(start1, x2 + 1):
                if x1 < 3:
                    continue

                # reverse Alice
                for q in primes:
                    if q >= x1:
                        break

                    if x1 % q == 0:
                        start0 = (x1 // q - 1) * q + 1
                        ans = min(ans, start0)

    print(ans)

if __name__ == "__main__":
    solve()

入れ子構造は 2 段階の反転を反映しています。 算術区間計算`(x // p - 1) * p + 1`これは、「倍数に切り上げる」操作を逆にする重要な変換です。 

厳密な条件の確保が微妙なポイント$p < X$現在の値より小さい素数のみを反復することによって暗黙的に尊重されます。 もう 1 つは、以下の場合のみを考慮するということです。$x$で割り切れます$p$、それらのみが天井から複数のステップの後の正確な着地位置に対応するためです。
