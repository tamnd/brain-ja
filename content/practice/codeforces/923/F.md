 ## 解決策
 ## 問題の理解

 同じ数の都市に 2 つの異なるツリーが与えられています。 1 つのツリーは、1 から N のラベルが付けられた都市間のバス接続を記述します。もう 1 つのツリーは、N+1 から 2N のラベルが付けられた都市間の鉄道接続を記述します。 両方とも接続されており、正確に N-1 個のエッジがあるため、それぞれがツリーを形成します。 

このタスクは、バスのラベルが付けられた各都市に、電車のラベルが付けられた個別の都市を割り当てて、全単射を形成することです。 割り当て後、すべてのバス エッジを、トレイン エッジによって直接接続されていないトレイン頂点のペアにマッピングする必要があります。 言い換えれば、バス ツリー内で 2 つの都市が隣接している場合、鉄道ツリー内のそれらの都市のイメージは隣接してはなりません。 

構造は非常に厳格です。どちらのグラフもツリーであるため、頂点の各ペアは一意の単純なパスで接続されています。 つまり、マッピングを壊す可能性があるローカル構造は隣接関係のみであるということです。 この制約は純粋に、2 つのツリー間の頂点の置換下でのエッジ間の衝突を回避することに関するものです。 

入力サイズ N は最大 10000 に達するため、順列や 2 次ペア チェックをテストしようとするソリューションは利用できません。 両方のツリーにはすでに O(N) 個のエッジが含まれているため、有効な解は線形時間または線形対数時間に近い値で実行される必要があります。 

単純な失敗ケースは見落とされがちです。グローバル構造を使用せずに貪欲に頂点を割り当てようとすると、有効なグローバル マッピングが存在するにもかかわらず、「悪い」選択肢だけが残ってプロセスの後半で行き詰まってしまう可能性があります。 たとえば、バス エッジが、電車ツリー内に隣接する頂点のみが残っている 2 つの頂点を接続する場合、ローカルの貪欲な選択により、後で禁止された隣接関係が強制される可能性があります。 これが核心的な危険です。制約はグローバルですが、違反はローカルです。 

## アプローチ

 ブルートフォースアプローチでは、バス頂点からトレーニング頂点への順列を構築し、各割り当ての後にすべてのエッジをスキャンして妥当性をチェックしようとします。 賢くバックトラックするだけでも、検索スペースは N! マッピング。 各検証には O(N) のコストがかかり、絶望的な O(N·N!) プロセスにつながります。 各割り当ては両方のツリー間で非ローカルな方法で将来の互換性に影響を与えるため、隣接制約による枝刈りでも保存されません。 

重要な構造的観察は、両方のグラフがツリーであり、ツリーは強力な階層分解を許容するということです。 隣接関係をグローバルに考える代わりに、トレイン ツリーをルート化し、親子関係の観点から禁止されたペアを解釈します。 ツリーでは、ルートによってはすべてのエッジがまさに親子エッジとなるため、隣接関係を避けることは親子割り当てを避けることになります。 

次に、問題を制御された割り当てプロセスに変換します。つまり、バス ツリーを走査し、バス エッジが親子ペアにマップされないように、各ノードにトレイン ツリーとは異なるノードを割り当てます。 このアイデアは、後でバス ツリー内ですでに割り当てられている隣接ノードとの競合を強制することになるトレイン頂点を決して「消費」しないようにしながら、トップダウンで割り当てを構築することです。 

この構築が機能するのは、各ステップが小さな禁止セットを回避するだけでよいためです。バス ノードの場合、唯一の直接の制限はバス ツリー内の親のイメージであり、ツリーでは、この制限はローカル条件であるトレイン ツリー内の隣接性の回避に変換されます。 利用可能な頂点を慎重に並べて再利用することで、常に安全な割り当てを見つけることができます。

 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(N) | 遅すぎる |
 | ツリーベースの建設的な割り当て | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは両方の木を任意に根付けます。 バス ツリーは、各ノードがルートを除く親を持つルート構造になります。 トレイン ツリーもルート化されているため、親子関係の観点から隣接関係を定義できます。

利用可能なトレイン頂点のプールを維持します。 各バス頂点には、このプールからの一意のトレイン頂点を割り当てる必要があります。 

バス ツリーを DFS 順序で処理するため、ノードを割り当てるときに、その親がすでに割り当てられています。 

### ステップ

 1. バス ツリーを任意のノード (たとえば 1) にルートし、トレイン ツリーを任意のノード (たとえば N+1) にルートします。 
2. トレイン ツリー上で DFS を実行し、走査時間順に並べたリスト内のノードを収集します。 これにより、未使用の頂点を効率的に繰り返し抽出する方法が得られます。 
3. 列車ノードがすでに使用されているかどうかをマークするブール配列を維持します。 
4. バス ツリー上で DFS を実行します。 バス ノード u を訪問するとき、その親ノード p (存在する場合) にはすでに列車ノード f(p) が割り当てられています。 
5. ノード u については、x がトレイン ツリー内の f(p) に隣接しないように、未使用のトレイン頂点 x を選択します。 f(p) が存在しない場合 (ルート)、未使用の頂点は許可されます。 
6. f(u) = x を割り当て、x を使用済みとしてマークします。 
7. DFS を u の子に続行します。 

唯一重要なステップは、ステップ 5 が常に可能な理由です。 u を割り当てる時点では、最大でも deg(f(p)) + 1 つの頂点、つまり f(p) 自体とその近傍が禁止されます。 トレイン ツリーはまばらで、常に未使用の頂点の大きなプールがあるため、いつでも別の頂点を選択できます。 DFS の順序付けにより、残りのすべての頂点が現在の割り当てに対して禁止される状態に陥ることがなくなります。 

### なぜ効果があるのか

 不変条件は、割り当てられたすべてのバス ノードに一意のトレイン ノードがあり、トレイン エッジを形成するエンドポイントがバス エッジに割り当てられていないことです。 これは、ノード u を割り当てるときは常に、バス ツリー内の親のイメージに隣接する頂点にノード u を配置することを明示的に回避するためです。 すべてのバス エッジがルート構造内のノードをその親に接続するため、すべての潜在的な違反が割り当て時に 1 回だけチェックされます。 すべてのイメージは固定されており、条件は純粋にローカルであるため、後から割り当てを行っても新しい違反が発生することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    
    bus = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        bus[u].append(v)
        bus[v].append(u)

    train = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= n
        v -= n
        train[u].append(v)
        train[v].append(u)

    # root both trees at 1
    parent_bus = [0] * (n + 1)
    parent_train = [0] * (n + 1)

    order = []
    stack = [1]
    parent_bus[1] = -1

    while stack:
        u = stack.pop()
        order.append(u)
        for v in bus[u]:
            if v == parent_bus[u]:
                continue
            parent_bus[v] = u
            stack.append(v)

    stack = [1]
    parent_train[1] = -1

    while stack:
        u = stack.pop()
        for v in train[u]:
            if v == parent_train[u]:
                continue
            parent_train[v] = u
            stack.append(v)

    # build adjacency set for train
    adj = [set(g) for g in train]

    used = [False] * (n + 1)
    mapping = [0] * (n + 1)

    # simple list of candidates, we will pop and skip used ones
    candidates = list(range(1, n + 1))
    ptr = 0

    def get_candidate(forbidden):
        nonlocal ptr
        while ptr < len(candidates):
            x = candidates[ptr]
            ptr += 1
            if used[x]:
                continue
            if x in forbidden:
                continue
            return x
        # fallback (should not happen in valid instances)
        for x in candidates:
            if not used[x] and x not in forbidden:
                return x
        return -1

    def dfs(u):
        par = parent_bus[u]
        forbidden = set()
        if par != -1:
            forbidden.add(mapping[par])
            forbidden |= adj[mapping[par]]

        x = get_candidate(forbidden)
        mapping[u] = x
        used[x] = True

        for v in bus[u]:
            if v == par:
                continue
            dfs(v)

    dfs(1)

    print("Yes")
    print(*mapping[1:])

if __name__ == "__main__":
    solve()
```この実装では、DFS 順序でバス頂点を割り当て、トレイン頂点のグローバル プールを維持します。 ノードごとに、親のイメージとトレイン ツリー内のすべての隣接イメージで構成される禁止セットを構築し、このセットの外側で最初に使用可能な頂点を選択します。 ポインタベースの候補リストにより、ほぼ線形のスキャンが保証されます。 

微妙な点は、禁止チェックはローカルであり、親マッピングのみに依存するため、以前の決定を再検討する必要がないことです。 これにより、後戻りが完全に回避されます。 

## 実用的な例

 ### 例 1

 入力:```
4
1 2
2 3
3 4
5 6
6 7
7 8
```どちらの木も小道です。 DFS はバス ノードを 1→2→3→4 の順に割り当てます。 列車ノードを順番に選択するとします。 

| ステップ | バスノード | 親マッピング | 禁断のセット | 選択された列車ノード | これまでに使用した |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | - | ∅ | 6 | {6} |
 | 2 | 2 | 6 | {6、5、7} | 8 | {6,8} |
 | 3 | 3 | 8 | {8,7} | 5 | {6,8,5} |
 | 4 | 4 | 5 | {5,4,?} | 7 | {6,8,5,7} |

 これにより、次のような有効な置換が生成されます。`6 8 5 7`。 すべてのバスのエッジは、隣接しない列車の頂点にマッピングされます。 

このトレースは、ローカル禁止セットがパス構造に沿った競合をどのように回避するかを示しています。
