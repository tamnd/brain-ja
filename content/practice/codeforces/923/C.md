 ## 解決策

 ## 問題の理解

 同じ長さの整数の 2 つの配列が与えられます。 1 つの配列は暗号化された値を表し、もう 1 つの配列は順序が失われたキー値の複数セットを表します。 元のメッセージ値はそれぞれ、ビットごとの XOR を使用して 1 つのキー値と結合されていましたが、どのキーがどの暗号化された位置とペアになっていたのかはわかりません。 

私たちのタスクは、キー配列の順列と XOR 演算したときに指定された暗号化された配列を生成する可能性のある元のメッセージを再構築することですが、すべての有効な可能性の中で、辞書編集的に可能な限り最小のメッセージを出力する必要があります。 

重要な問題はペアリングです。メッセージ内のすべての要素は個別のキー値と一致する必要があり、キーを再利用できないため、1 つの位置のペアリングを選択すると、将来の選択が制限されます。 

この制約により、O(n log n) または O(n) タイプの解決策が求められます。 最大 300,000 個の要素を使用すると、すべてのペアリングを試したり、位置ごとに最適な一致を繰り返し再計算したりするアプローチは遅すぎます。 ソートと貪欲な選択は必要ですが、単純な貪欲な戦略は失敗する可能性があります。これは、XOR の局所的最小化ではグローバルな辞書編集上の最適性が保証されないためです。 

現在の位置に対して最小の XOR パートナーを選択するときに、微妙な失敗のケースが発生し、後でより適切な構成が妨げられます。 

たとえば、インデックス 1 で可能な限り最小の結果を貪欲に選択するとしますが、その場合、インデックス 2 ではるかに小さい結果を可能にするキーが消費されるとします。辞書編集上の順序は初期の位置に大きく依存するため、正しい戦略では、局所的に最小限の XOR 選択だけでなく、グローバルに初期の位置を優先する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、キー配列のすべての置換を試行し、各置換の結果として得られるメッセージを計算し、辞書編集的に最小の結果を取得します。 これは問題の定義を直接シミュレートするため、これは正しいです。 ただし、n が必要です。 割り当ては可能であり、各割り当ての評価コストは O(n) であるため、非常に小さい n を超えると完全に実行不可能になります。 

重要な観察は、同じタイプの操作を繰り返し実行しているということです。暗号化された値 Ai ごとに、Ai XOR Pj ができるだけ小さくなるようなキー値 Pj を選択したいと考えていますが、残りのキーの可用性が条件となります。 これは、ビット単位の値に対する古典的な貪欲マッチングの問題です。 

XOR 構造は、バイナリ トライ (プレフィックス ツリー) を示唆します。 各キーはビットごとのトライに挿入できます。 特定の Ai にとって、考えられる最良のパートナーは最小の XOR 結果を生成するキーであり、Ai のビットに一致する分岐を優先してトライをたどることで見つけることができます。 

ただし、出力全体にわたって辞書編集上の順序を保持する必要があるため、位置ごとに純粋に貪欲だけでは不十分です。 正しいアプローチは依然として Ai を順番に処理することに貪欲ですが、前の位置が辞書編集上の順序を支配し、できるだけ早く各出力値を最小化する必要があるため、各ステップはその Ai に使用可能な最適なキーを独立して選択する必要があります。 

より深い正当化は、Ai を位置 i に固定すると、その後の位置で改善しても、悪化した Ai を補うことはできないということです。 したがって、残りのキーを考慮して、各ステップで可能な限り最小の Ai XOR キーが常に必要になります。 このトライにより、除去を尊重しながら常に最小の XOR パートナーを効率的に見つけることが保証されます。 

したがって、問題は次の繰り返しに帰着します。 

Ai XOR Pj を最小化するキー Pj を選択し、それを削除して次に進みます。 

これはまさに、削除を伴う動的な最小 XOR 問題であり、カウントを含むバイナリ トライを使用して解決されます。

 ## アルゴリズムのチュートリアル

各ノードが通過する数値の数を格納するバイナリ トライを構築します。 各キーは、30 ビットのバイナリ表現に基づいて挿入されます。 

次に、暗号化された配列を順番に処理します。 各値 Ai について、トライをクエリして、Ai XOR キーを最小化するキーを見つけます。 このクエリは、最上位ビットから 0 までビットごとに貪欲であり、可能であれば常に XOR ビットを 0 に維持することを好みます。 

最適なキーを見つけたら、そのパスに沿ってカウントを減らして、そのキーをトライから削除します。 

### ステップ

 1. すべてのキー値をバイナリ トライに挿入し、すべてのノードにカウントを保存して、削除をサポートできるようにします。 カウントは、そのサブツリーに残っている未使用のキーの数を表します。 
2. 順番に各 Ai について、トライのルートから開始して、最も一致するキーを構築します。 29 から 0 までの各ビットで、Ai の現在のビットと一致する分岐をたどろうとします。 その分岐が存在する (正のカウントを持つ) 場合は、そのビットの XOR に 0 が寄与するため、それを採用します。 それ以外の場合は、XOR 結果に 1 を導入する反対の分岐を取る必要があります。 
3. 後でそのキーを正確に削除する必要があるため、トラバース中に、選択した再構成されたキー値を蓄積します。 
4. Ai のトラバースが終了したら、選択したキーのパスに沿ってカウントをデクリメントし、今後の考慮事項から削除します。 
5. Ai XOR selected_key を計算し、出力メッセージ値として位置 i に保存します。 

### なぜ効果があるのか

 各位置で、使用可能なすべてのキーの中から Ai XOR キーを最小化するキーを常に選択します。 トライは、すべての有効なキーをビット単位で探索し、XOR の上位ビットをできるだけ小さく保つことを常に優先するため、この選択がそのステップにとってグローバルに最適であることを保証します。 

最終メッセージの辞書編集的な順序は、シーケンス内の各位置を個別に最小化することに合わせて調整されます。位置 i でより小さい値が達成されると、その後の並べ替えによって辞書編集上の順序を改善することはできません。 したがって、ポジションごとの貪欲な選択は、グローバルな目標と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("ch", "cnt")
    def __init__(self):
        self.ch = [-1, -1]
        self.cnt = 0

class Trie:
    def __init__(self):
        self.nodes = [Node()]

    def insert(self, x):
        v = 0
        self.nodes[v].cnt += 1
        for b in range(29, -1, -1):
            bit = (x >> b) & 1
            if self.nodes[v].ch[bit] == -1:
                self.nodes[v].ch[bit] = len(self.nodes)
                self.nodes.append(Node())
            v = self.nodes[v].ch[bit]
            self.nodes[v].cnt += 1

    def erase_and_get_best(self, x):
        v = 0
        self.nodes[v].cnt -= 1
        res = 0
        path = []

        for b in range(29, -1, -1):
            bit = (x >> b) & 1
            preferred = bit
            other = bit ^ 1

            if self.nodes[v].ch[preferred] != -1:
                nxt = self.nodes[v].ch[preferred]
                if self.nodes[nxt].cnt > 0:
                    v = nxt
                    res = (res << 1) | preferred
                    path.append((v, preferred))
                    continue

            nxt = self.nodes[v].ch[other]
            v = nxt
            res = (res << 1) | other
            path.append((v, other))

        # erase along path
        v = 0
        self.nodes[v].cnt -= 1
        for b in range(29, -1, -1):
            bit = (res >> b) & 1
            v = self.nodes[v].ch[bit]
            self.nodes[v].cnt -= 1

        return res

def solve():
    n = int(input())
    A = list(map(int, input().split()))
    P = list(map(int, input().split()))

    t = Trie()
    for x in P:
        t.insert(x)

    out = []
    for a in A:
        best_key = t.erase_and_get_best(a)
        out.append(str(a ^ best_key))

    print(" ".join(out))

if __name__ == "__main__":
    solve()
```この実装は、トライ内の各決定がキーの残りの可用性を考慮するように、サブツリー数の維持に依存しています。 トラバーサルでは、XOR を最小限に抑えるために Ai とビットを一致させることが常に優先され、必要な場合にのみ逸脱します。 

実装の微妙な詳細は削除です。将来のクエリで削除されたキーが使用されないように、選択したパスに沿ったすべてのノードのカウントをデクリメントする必要があります。 正しいカウントがないと、アルゴリズムがキーを再利用したり、無効な分岐に入ったりする可能性があります。

 ## 特殊なケース

 エッジ ケースの 1 つは、複数のキーが特定の Ai に対して同じ最小 XOR 値を生成する場合です。 トライでは構造に基づいて決定的に 1 つが選択されますが、カウントが尊重される限り、有効なタイブレークはどれでも受け入れられます。 アルゴリズムは常に同じ構造パスを優先するため、これを自然に処理します。 

もう 1 つのケースは、多くのキーが長いプレフィックスを共有する場合です。 たとえば、すべてのキーが下位ビットのみで異なる場合、初期のトライ決定は常に同一の上位ビット パスに従います。 分岐は最初の異なるビットでのみ発生し、カウントによって有効な可用性が保証されるため、アルゴリズムは引き続き正しく動作します。 

3 番目のケースは、多くのポジションで Ai がゼロの場合です。 XOR はキー自体に等しいため、トライは常に利用可能な最小のキーを直接選択しようとします。 削除ロジックにより、キーが再利用されず、同じクエリが繰り返された場合でも結果が正しいままになります。
