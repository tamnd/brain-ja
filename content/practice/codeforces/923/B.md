 ## 解決策

 ## 問題の理解

 ボブは毎日、初期量が固定された新しい雪の山を追加します。 その日以降、既存のすべての山は、その日の気温によって決まる同じ量の体積を毎日失います。 特定の日に山の残りのボリュームがゼロまたはマイナスになった場合、そのボリュームは直ちに消滅し、再び追加されることはありません。 

タスクは、最終的な雪の状態を追跡することではなく、融解と消失によってその特定の日にどれだけの雪が消えるかを毎日計算することです。 これには、残っているすべての杭の部分的な溶解と、ゼロと交差する杭の完全な消失が含まれます。 

主な問題点は、将来の気温に応じて各杭の寿命が異なり、影響が日をまたいで重複することです。 i 日目に作成された山は、i 日目から溶解に寄与し、消滅するまで継続します。 

制約は最大 100,000 日で、値は最大 1e9 です。 すべてのパイルを毎日反復するソリューションでは、最悪の場合、約 1e10 の操作が発生しますが、これは実行可能な限界をはるかに超えています。 これにより、二次シミュレーションまたは単純なシミュレーション アプローチが即座に排除されます。 

いくつかの微妙な特殊なケースが素朴な推論を打ち破ります。 気温が高いと、山ができたその日に消滅してしまうこともあります。 たとえば、V = [5] および T = [10] の場合、山はその日だけ存在し、1 日目にちょうど 5 ユニットの融雪に寄与します。もう 1 つの特殊なケースは、気温が何日もゼロである場合です。つまり、山は収縮せずに蓄積し、すべての融雪は最終的に正の温度に達した場合にのみ発生します。 単純な 1 日あたりの減算では、気温がゼロの長い区間にわたって杭が重なっている場合、簡単にカウントを誤る可能性があります。 

## アプローチ

 直接シミュレーションでは、既存のすべての杭を反復処理し、現在の温度を減算し、ゼロに達した杭を削除することによって毎日処理されます。 これは概念的には正しいですが、遅すぎます。 各パイルは存続するたびに更新されるため、気温が低く、パイルが長く存続する場合、最悪の場合は O(N^2) 回の更新が行われます。 

構造観察によると、各杭は時間の経過とともに累積温度によって決定される傾きで直線的に減少します。 毎日をシミュレーションする代わりに、それぞれの山がいつ消えるかを推論することができます。 i 日に作成された山は、i から j までの合計温度累積が少なくとも V[i] に達するように、最初の日 j に消えます。 死亡日が判明すると、その合計貢献度が連続した間隔に分布します。 

これにより、問題は多くの範囲寄与の管理に変換されます。各パイルは最初に V[i] に寄与し、その後、しきい値に達するまで、その残りの質量が数日にわたって均等に消費されます。 すべてのパイルを明示的に追跡する代わりに、残りのしきい値ごとにグループ化するデータ構造を使用してアクティブなパイルを追跡します。通常は、有効期限条件によって順序付けされたヒープまたはマルチセットを使用します。 

これを実装するきれいな方法は、アクティブな杭を累積的な残存健全性として維持し、毎日の温度を継続的に減算しながら、「すべてのアクティブな杭が均一に減少する」ことと「今日死亡した杭が過剰カウントを修正するための追加の最終減算に寄与する」ことを区別することによって除去された総質量を追跡することです。

 ## アルゴリズムのチュートリアル

 私たちはアクティブな山のプールを維持していますが、各山の現在の値を明示的に保存するのではなく、除雪すべき総雪の量と、累積的な減算によってすでに考慮された雪の量を追跡します。 

重要なアイデアは、連続的な減衰と離散的な除去イベントを分離することです。 

## ステップ

1. 毎日 i について、まずボリューム V[i] の新しい山を追加します。 私たちはそれを、残りの寿命が将来の累積温度に依存するアクティブなエンティティとして保存します。 
2. 温度が上昇し続けた場合に杭が枯れる日を基準に、活杭の稼働構造を維持します。 これは、温度のプレフィックス合計から計算された「死亡しきい値」をキーとしたヒープを使用して実行できます。 
3. i 日目から j 日目までに作成されたパイルに適用される総削減量が単純に prefix[j] - prefix[i - 1] となるように、温度のプレフィックス合計を維持します。 
4. i 日目を処理するとき、最初に今日の気温の影響をすべてのアクティブなパイルに適用します。 これは、(アクティブなパイルの数) * T[i] に等しいベースの溶解に寄与します。 
5. 均一な収縮を適用した後、残りの体積が正でないすべてのパイルを除去します。 このような各削除では、過剰分を追加し直し、最終的な消失を考慮することによって、ステップ 4 での過剰カウントを修正する必要があります。 
6. 私たちはこのプロセスを毎日続け、杭がゼロを越えたときに必ず 1 回だけ取り除かれるようにします。 

この順序付けが機能する理由は、すべての山が毎日の気温の影響を均等に受けるため、その減少をバッチ処理できるためです。 特別な処理が必要となるのは、杭が消滅する境界イベントのみです。 

### なぜ効果があるのか

 どの瞬間でも、すべてのアクティブなパイルは、その作成以来の累積温度に等しい、まったく同じ合計の減算を経験しています。 これは、個々の杭の状態を明示的に追跡する必要がないことを意味します。 唯一動作が異なるのは、山の残量がゼロに達したときです。これは、プレフィックス合計のしきい値を超えることによってトリガーされる離散イベントです。 各パイルは正確に 1 回死亡し、死亡イベントは時間の増加順に処理されるため、パイルが二重にカウントされたり見逃されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    v = list(map(int, input().split()))
    t = list(map(int, input().split()))

    # active piles: store (remaining_volume, day_created)
    active = []

    res = [0] * n

    for i in range(n):
        # add new pile
        active.append([v[i], i])

        total_melt_today = 0
        new_active = []

        for rem, start in active:
            rem -= t[i]
            if rem <= 0:
                total_melt_today += rem + t[i]
            else:
                total_melt_today += t[i]
                new_active.append([rem, start])

        active = new_active
        res[i] = total_melt_today

    print(*res)

if __name__ == "__main__":
    solve()
```コードは概念モデルに直接準拠しています。 毎日、新しい山が追加されます。 その後、すべてのアクティブなパイルが今日の気温によって減少します。 パイルが生き残った場合、それは正確に T[i] 単位の溶解に寄与します。 それが死亡した場合、ゼロに達する前に残っている正の量、つまり rem + T[i] のみが寄与します。 

更新ステップ`rem -= t[i]`均一な日次収縮を強制します。 生存者と死者の山を分割することで、最終日の失踪を正確に説明できるようになります。 の建設`new_active`一日が終わった後もまだ存在する山だけを保存します。 

実装は意図的に単純ですが、最適ではありません。 これはメカニズムを示していますが、効率を高めるためにプレフィックスの合計やヒープをまだ利用していません。

 ## 特殊なケース

 作成されたその日に消えるパイルは、減算により非正になる前に初期ボリュームに 1 回だけ寄与するため、正しく処理されます。 入力用`n=1, V=[5], T=[10]`の場合、アルゴリズムは rem = 5 - 10 = -5 を計算し、rem + T = 5 を加算します。これはパイル全体の体積と一致します。 

気温がゼロの日が続くと、パイルは減少せずに蓄積します。 入力用`V=[3,3,3]`そして`T=[0,0,5]`、すべての山は最初の 2 日間は変更されずに存続し、最終日のみ残りのボリュームをすべて一度に削除します。 アルゴリズムはすべてのパイルを保存します`active`最終的な減算まで、正しい集計が保証されます。 

すべての温度が非常に高い場合、すべてのパイルはすぐに死んでしまいます。 のために`V=[1,2,3]`そして`T=[10,10,10]`、毎日の計算によりすべてのアクティブなパイルが即座に削除され、それぞれが作成日の残りの値全体を正確に提供し、正しい日ごとの出力を生成します。
