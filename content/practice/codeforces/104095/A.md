 ## 問題の理解

 各学生は 1 つのポジションだけを争うか、特定のポジションではどれも重要ではありません。 すべての役職について、その役職に応募したすべての学生を調べ、最も得票数の高い学生を選択する必要があります。 複数の学生が同じ最大投票数に達した場合、最小の学生インデックスを選択することで同点が解消されます。 

入力により学生のリストが得られ、各学生が 1 つの目標位置と投票数を宣言します。 タスクは、すべての位置を再構築することです。$1$に$m$、「最大投票数、次に最小インデックス」ルールを適用した後、どの学生がそのポジションを獲得するか。 

境界は非常に小さいです:$n \le 51$そして$m \le 12$。 これにより、効率に対する懸念が解消されます。 たとえ$O(nm)$または$O(n^2)$シミュレーションはかなり速いです。 唯一の実際の要件は、グループ化とタイブレークが正確であることです。 

最も一般的な失敗例は、同点順位を忘れたり、生徒をポジションごとに正しくグループ化できなかったりすることに起因します。 たとえば、2 人の生徒が同じ位置を同じ投票数でターゲットにしている場合、小さい方のインデックスではなく後の入力を選択すると、すべての値が処理されたとしても不正確な回答が生成されます。 

もう 1 つの微妙な問題は、ポジションが独立していると仮定しているものの、変数が共有されているか、ポジションごとの最大値がリセットされていないために、ポジション間で誤ってインデックスが混在してしまうことです。 

## アプローチ

 問題の構造はすでに最適なアプローチです。 各ポジションは独立しているため、自然な解決策は、すべての候補を選択したポジションごとにグループ化し、単純な最大値を計算することです。 

強引な解釈では、ポジションごとにすべての学生をスキャンし、最適な候補者を選択します。 これは、各位置決定が独立しており、リニア スキャンのみを必要とするため機能します。 費用は$O(nm)$それぞれの操作について、$m$ポジションはすべてチェックします$n$学生たち。 与えられた制約を考慮すると、これはすでに最小限で効率的です。 

重要な観察は、位置間に相互作用が存在しないことです。 学生は 1 つのグループにのみ所属するため、グローバルな並べ替えや照合は必要ありません。 問題全体は、辞書編集キーを使用して最大の選択を繰り返すことに帰着します。$(t_i, -i)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 実際にはどちらも事実上同じです。 グループ化されたバージョンは構造を明確にするだけです。 

## アルゴリズムのチュートリアル

 1. 配列を作成する`best_id`サイズの$m$に初期化されました$0$、各ポジションの現在の勝者を表します。 メンテナンスも行います`best_score`に初期化されました$0$ポジションごとに。 この設定は、各位置が常にその現在の最良の候補を格納するという不変式をエンコードします。 
2. 生徒一人ひとりを読みます$i$から$1$に$n$、選択した位置で$c_i$そして投票$t_i$。 
3. ポジションについて$c_i$、 比較する$t_i$に保存されている現在のベストスコア`best_score[c_i]`。 
4. もし$t_i$現在のベストスコアより大きい場合は、両方を置き換えます`best_score[c_i]`そして`best_id[c_i]`と$t_i$そして$i$。 これにより、このポジションがこれまでに確認された最高得票候補を維持することが保証されます。 
5. もし$t_i$現在の最高スコアに等しい場合は、生徒の指数を比較します。 もし$i$保存されている最良のインデックスより小さい場合は、保存されている勝者を置き換えます。 これにより、タイブレーク ルールが適用されます。 
6. すべての生徒を処理した後、出力します`best_id[1]`を通して`best_id[m]`。 

### なぜ効果があるのか

 処理中の任意の時点で、各ポジションには、そのポジションについてこれまでに確認されたすべての学生の中で最良の候補者が、辞書順に基づいて保存されます。$(t_i, -i)$。 各新入生は、厳密に優れているか、厳密に劣っているか、または投票で同点のいずれかであり、同点の場合は最小のインデックスのみが生き残ります。 すべての生徒が 1 回だけ処理され、比較は単調な更新であるため、最終的に保存される値は各位置のグローバル最大値でなければなりません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    best_score = [0] * (m + 1)
    best_id = [0] * (m + 1)

    for i in range(1, n + 1):
        c, t = map(int, input().split())
        if t > best_score[c]:
            best_score[c] = t
            best_id[c] = i
        elif t == best_score[c] and i < best_id[c]:
            best_id[c] = i

    print(*best_id[1:])

if __name__ == "__main__":
    solve()
```このソリューションでは、位置によってインデックスが付けられた 2 つの配列が維持されます。 1 つはこれまでに確認された最高の投票数を保存し、もう 1 つは対応する学生インデックスを保存します。 更新ロジックは選択ルールを直接エンコードし、最終出力はポジションごとの勝者を順番にリストするだけです。 

微妙な点は初期化：設定です。`best_score`に$0$投票数は少なくとも次の値であることが保証されているため、有効です。$1$。 もう一つの詳細は、`best_id`から始まります$0$、実際の学生インデックスは少なくとも次のとおりであるため、これは機能します。$1$したがって、最初の有効な候補が常に上書きされます。

 ## 特殊なケース

 重要なエッジケースは、複数の学生が同一の票で同じ順位を争う場合です。 アルゴリズムは、投票数が等しい場合にのみインデックスを比較することでこれを処理し、最小のインデックスが確実に保持されます。
