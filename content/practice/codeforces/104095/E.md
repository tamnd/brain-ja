 ## 解決策
 ## 問題の理解

 一連の学生が与えられ、それぞれの学生が積極的にメッセージをチェックする時間間隔が関連付けられています。 選択した瞬間に通知が送信された場合、学生はその瞬間が個人的な間隔内にある場合にのみ通知を受け取ります。 通知を受け取った場合、各生徒は固定の満足度値も提供します。 

タスクは、通知を送信する瞬間を 1 つだけ選択し、アクティブな間隔がその瞬間をカバーするすべての生徒を考慮することです。 このようなすべての有効な送信時間の中で、通知を受け取る学生の満足度値の合計を最大化したいと考えています。 追加の制約があります。選択した時間では、少なくとも k 人の生徒がメッセージを受信する必要があります。 そのような時間が存在しない場合、答えは -1 です。 

入力サイズは大きく、最大 5×10^5 の学生、最大 10^9 の時間座標を持ちます。 これにより、時間は連続的であり、反復するには大きすぎるため、考えられる各時間を直接評価するアプローチは即座に除外されます。 すべての間隔エンドポイントを反復処理してカバレッジを素朴に再計算した場合でも、最悪の場合には O(n^2) の作業が必要となり、これは制限をはるかに超えています。 

素朴な考えによる微妙な失敗例は、間隔がまばらであるが、小さな領域で大きく重なっている場合に発生します。 たとえば、k = 2 で、区間 [1, 10]、[2, 3]、[3, 4]、[4, 5] がある場合、端点のみをチェックする単純な試みでは、最良の内部点を見逃す可能性があります。これは、最適な時間が正確に端点ではなく、複数の重なり合うセグメント内にある可能性があるためです。 

もう 1 つの落とし穴は、中間位置で重複する間隔の数を適切に維持せずに、間隔の開始時刻と終了時刻だけをチェックするだけで十分であると想定していることです。 オーバーラップは境界でのみ変化しますが、最適な値はカウントだけではなく、それらの領域の完全なアクティブ セットに依存します。 

## アプローチ

 ブルートフォースのアイデアは単純です。考えられるすべての時間 t を考慮し、どの間隔に t が含まれるかを計算し、アクティブな生徒の数を数え、その値を合計します。 これは、問題で説明されているプロセスを直接シミュレートするため、正解です。 ただし、時間は 10^9 までの範囲で連続するため、候補点の数は事実上無限になります。 候補をすべてのエンドポイントに制限した場合でも、候補時間は O(n) 回となり、それぞれについてすべての間隔をスキャンする可能性があり、最悪の場合は O(n^2) 回の操作が必要になりますが、これは n が 5×10^5 までの場合は不可能です。 

重要な観察は、アクティブな間隔のセットがエンドポイント ai と bi+1 でのみ変化するということです。 連続するエンドポイント間では、アクティブな生徒のセットは一定のままです。つまり、カウントと総重みの両方が変化しません。 したがって、時点の観点から考えるのではなく、問題を分類された重要なイベントの間のセグメントに変換します。 これにより、連続ドメインが O(n) 個の意味のあるセグメントに縮小されます。 

この変換を実行すると、時間の経過とともにスイープ ラインを維持し、各エンドポイントを通過するときにアクティブ セットを更新します。 各セグメントで、アクティブな間隔の数とそれらの wi の合計という 2 つの値を追跡します。 アクティブなカウントが少なくとも k になるたびに、現在の合計で答えを更新することを検討します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 端点上のスイープ ライン | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各間隔を 2 つのイベントに変換します。1 つはアクティブになったとき、もう 1 つはアクティブでなくなったときです。 ソートされたイベントの位置を自然にスイープすることで、現在のアクティブな学生のセットを効率的に維持できます。

1. 各生徒 i に対して、アクティブ合計に wi を追加してアクティブ数を増やす開始イベントを ai に作成し、wi を削除してアクティブ数を減らす終了イベントを bi + 1 に作成します。 bi + 1 を選択すると、小数点以下の時間を必要とせずに、間隔のエンドポイントが正しく含まれることが保証されます。 
2. すべてのイベントを時間座標で並べ替えます。 並べ替えが必要なのは、時間を昇順に処理して、2 つの連続するイベント位置の間でアクティブ セットが一定に保たれるようにするためです。 
3. 2 つの変数、current_count と current_sum を両方とも 0 から初期化します。 これらは、現在通知を受け取っている学生の数と、現在の時間セグメントでの合計満足度を表します。 
4. 並べ替えられたイベントをざっと調べます。 新しい時間にイベントを適用する前に、前のイベント時間と現在のイベント時間の間のセグメントを評価します。 current_count が少なくとも k の場合、current_sum を使用して答えを更新します。 これが機能するのは、状態がセグメント全体にわたって一定であるためです。 
5. current_count と current_sum を適宜更新して、現時点でのすべてのイベントを処理します。 正確さを保つために、複数のイベントを同時に適用する必要があります。 
6. すべてのイベントが処理されるまで続行します。 current_count ≥ k という条件を満たすセグメントがない場合は、-1 を返します。 

機能する理由: このアルゴリズムは、連続するイベント ポイント間の開いた間隔内では、アクティブな間隔のセットが固定されるという不変式に依存しています。 したがって、アクティブな学生の数とその重みの合計は、そのセグメントにわたって一定のままです。 すべての有効な時間は何らかのセグメント内に存在する必要があるため、最適な答えを取得するには各セグメントを 1 回チェックするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    
    events = []
    for _ in range(n):
        a, b, w = map(int, input().split())
        events.append((a, w))        # add
        events.append((b + 1, -w))   # remove after interval
    
    events.sort()

    cur_cnt = 0
    cur_sum = 0
    ans = -1

    i = 0
    m = len(events)

    while i < m:
        t = events[i][0]

        if i > 0:
            if cur_cnt >= k:
                ans = max(ans, cur_sum)

        while i < m and events[i][0] == t:
            _, w = events[i]
            if w >= 0:
                cur_cnt += 1
                cur_sum += w
            else:
                cur_cnt -= 1
                cur_sum += w
            i += 1

    print(ans)

if __name__ == "__main__":
    solve()
```実装の中核はイベントベースのスイープです。 各間隔は正確に 2 つの更新に寄与するため、時間の経過とともに明示的に反復する必要がなくなります。 

b + 1 の使用は非常に重要です。 これにより、学生に間隔 [a, b] がある場合、時間 b ではまだアクティブであり、厳密にはその後にのみ非アクティブになることが保証されます。 これにより、浮動小数点推論が回避され、すべてが整数ベースに保たれます。 

また、更新を適用した後のすべてのイベントではなく、イベント境界間でのみ回答を維持します。 状態の変更はイベント時に正確に発生し、安定領域が変更される前に評価する必要があるため、この順序付けは重要です。

このトレースは、答えが個々のタイムスタンプではなく、イベント変更間の安定した間隔によって決定されることを示しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 2n イベントのソートが優勢で、スイープは線形です。 
| スペース | O(n) | イベントストレージとカウンター |

 この制約により、最大 5×10^5 の間隔が許可されるため、単純な整数演算で実装された場合、O(n log n) アプローチは Python で 2 秒以内に快適に収まります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、複数のイベントが同じ座標で発生する場合です。 たとえば、ある間隔が時刻 t に終了し、別の間隔が時刻 t に開始する場合、処理順序は正確さを保証する必要があります。 削除に b + 1 を使用するとあいまいさが回避され、イベントを時間ごとにグループ化することで、アクティブ セットがセグメント境界全体で一貫していることが保証されます。 

もう 1 つのケースは、k = 1 の場合です。この状況では、単一のアクティブな間隔で十分であるため、答えは単に任意の間隔にわたる最大 wi になります。 少なくとも 1 つのアクティブな間隔を持つすべてのセグメントが考慮されるため、スイープ ラインはこれを自然に処理します。 

最後の微妙なケースは、すべての間隔が完全に重なる場合です。 すべての開始イベントがすべての終了イベントの前に発生するため、アルゴリズムはすべての重みを正しく集計します。そのため、アクティブな合計は合計まで累積され、k が n を超えない限り k フィルタリングは干渉しません。
