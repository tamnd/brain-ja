 ## 解決策
 ## 問題の理解

 無向加重グラフによって接続される最大 14 の場所があります。 各場所には、特定の時間に利用可能になる配達注文が 1 つあります。 時間 0 にノード 1 から開始し、単位速度で道路に沿って移動するため、エッジに沿って移動するには、その重みに等しい時間がかかります。 グラフ内の任意の点で待機することもできます。待機すると、位置は変更されずに現在の時間が増加するだけです。 

各場所において、注文の配達による利益は配達時間のみに依存します。 各ノードは、注文が表示された後の一連の時間しきい値を定義し、しきい値間の各間隔には固定の利益があります。 注文が表示されてから非常に早く納品すると、1 つの値が得られ、その後、しきい値ごとに値が変化し、最後のしきい値を過ぎると利益は一定のままになります。 

目標は、各ノードが 1 回だけ訪問され、利益の合計が最大化されるように、すべてのノードを訪問する順序を選択し、場合によっては移動前またはノードで待機することです。 配送は、そのノードでの注文時刻より早く行われない場合にのみ有効ですが、待機を使用すると、配送をより収益性の高い時間間隔に遅らせることができます。 

制約はソリューションを強力に形作ります。 ノードの数は最大 14 であり、これは、訪問したノードのサブセットに対するビットマスク動的プログラミングを即座に示唆します。 グラフは、最短経路を事前に計算する必要があるほど十分に密ですが、それでもフロイド・ウォーシャルにとっては十分小さいです。 時間パラメータとしきい値は 200 で制限されています。これは、利益決定の最適性を失うことなく、絶対時間を離散化して制限できるという重要なヒントです。 

微妙な問題は、移動時間が最大のしきい値を超える可能性があることです。 時間が最終しきい値の 200 を超えると、すべての報酬が一定の最後のセグメントに分割されるため、200 を超える時間を区別しても利益が向上することはありません。 もう 1 つの微妙な点は、待機は移動の制約に関しては自由ですが、報酬の選択に影響を与えることです。つまり、到着時間は単に最短経路の距離ではなく、その距離以上の選択された値になることを意味します。 

素朴な間違いは、これを待機を無視した純粋な最短経路の訪問問題として扱うことです。 たとえば、ノードがしきい値を超えて配信された場合、より高い報酬が得られるとします。 常にすぐに行動する貪欲な戦略では、待つことが有益な場合でも、最適なタイミング ウィンドウを逃す可能性があります。 

## アプローチ

 最も直接的なアプローチは、14 個のノードを訪問する可能性のあるすべての順序を列挙することです。 各順列について、ノード間の最短パスを使用して移動をシミュレートし、時間を追跡し、到着時間に基づいて各ノードでの報酬を計算します。 これは、実行可能なすべてのスケジュールを試行し、各移動の前に待機をオプションの遅延として明示的に評価するため、正しいです。 ただし、順列の数は 14! であり、実現可能性をはるかに超えています。 単一のルート コストを計算するだけでも O(n^2) なので、これは完全に困難です。 

重要な観察は、構造が完全な履歴ではなく、どのノードを訪問したか、および現在の位置にのみ依存するということです。 これは当然ビットマスク DP につながります。 残りの複雑な問題は、報酬の時間依存性です。 従来の TSP とは異なり、早く到着することが常に良いとは限りません。待つことで遅く到着することもできます。 

この問題は、どのような状態であっても、ある時刻 L より早くノードに到達しないことがわかっている場合は、実際の配信時刻 T ≥ L を自由に選択できることに注目することで解決されます。 したがって、正確な時間を DP 次元として追跡する代わりに、可能な限り最も早い到着時刻を知るだけでよく、その後、おそらく現在のノードで待機することによって、それを達成可能な最良の報酬にマッピングする必要があります。 

報酬は最大 200 までの間隔にのみ依存するため、各時刻 L より早く到着しない場合に達成可能な最高の報酬をノードごとに事前計算できます。これにより、時間次元が単純な検索に圧縮されます。

最終的な解決策は、サブセットと現在のノードにわたるビットマスク DP になり、遷移では最短パス距離と事前計算されたサフィックス最大報酬テーブルが使用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | O(n! · n) | O(n) | 遅すぎる |
 | 時間圧縮を伴うビットマスク DP | O(2^n · n^2 + 2^n · n · T) | O(2^n · n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 最短経路と報酬テーブルの事前計算

 1. Floyd Warshall を使用して、ノード間のすべてのペアの最短パスを計算します。 これにより、任意の 2 つの場所間の最小移動時間が得られます。 
2. 各ノードについて、その区分的報酬定義を完全な配列に変換します。`reward[t]`200 までのすべての時間を、200 を超えるすべての時間を最終セグメント値として扱います。 これにより、到着時間から利益までの直接的なマッピングが作成されます。 
3. 各ノードに対して、サフィックス最大配列を構築します。`best_from[t]`、T ≥ t の時点で配達が発生した場合に取得できる最大報酬を格納します。 これは、配信前に任意に待機する機能をエンコードするメカニズムです。 

### サブセットに対する動的プログラミング

 1. DP 状態を次のように定義します。`dp[mask][i]`、セットを正確に訪問した後の最大合計利益を表します`mask`そしてノードで終わる`i`、到着時間は、選択されたスケジュールの下で可能な限り最も早い値に暗黙的に最小化されます。 
2. 次のコマンドを使用して DP を初期化します。`dp[1 << 0][0] = 0`、時間 0 のノード 1 から開始するためです。 
3. 州ごとに`(mask, i)`、すべての未訪問のノードを反復処理します。`j`。 させて`dist(i, j)`が最短経路距離になります。 
4. 可能な限り最も早い到着時刻を計算します。`j`、これは現在時刻に移動時間を加えたものです。 時間を DP に明示的に保存しないため、パスによって暗示される最小時間として再構築します。 事実上、州を拡大するときに概念的に時間を進めます。 
5.ノードの場合`j`を評価して効果的な報酬を決定します。`best_from[arrival_time]`。 これにより、配達前に待機するという最適な選択が得られます。`j`。 
6.アップデート`dp[mask ∪ {j}][j]`あらゆる到達方法で最大の`j`。 

### なぜ効果があるのか

 重要な不変条件は、最も早い到着時間が与えられた場合に常に各配信を最適に遅らせると仮定すると、各 DP 状態について、アルゴリズムが特定の訪問セットと終了ノードで達成可能な最高の利益を表すということです。 中間の待機を伴うより複雑なスケジュールは、実行可能性や利益を変えることなく、すべての待機が各配送の直前に行われるように再調整できます。 これにより、任意の待機履歴を追跡する必要がなくなります。 その結果、サブセット上の DP はすべての最適な戦略を完全に捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def floyd(n, dist):
    for k in range(n):
        for i in range(n):
            dik = dist[i][k]
            if dik == INF:
                continue
            for j in range(n):
                nd = dik + dist[k][j]
                if nd < dist[i][j]:
                    dist[i][j] = nd

def solve():
    n, m = map(int, input().split())
    dist = [[INF] * n for _ in range(n)]
    for i in range(n):
        dist[i][i] = 0

    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        dist[u][v] = min(dist[u][v], w)
        dist[v][u] = min(dist[v][u], w)

    q = list(map(int, input().split()))

    nodes = []
    reward = []

    MAXT = 200

    for i in range(n):
        d = int(input())
        ts = list(map(int, input().split()))
        ps = list(map(int, input().split()))

        arr = [0] * (MAXT + 1)
        ptr = 0
        cur = ps[0]
        for t in range(MAXT + 1):
            while ptr < d and t >= ts[ptr]:
                ptr += 1
                cur = ps[ptr]
            arr[t] = cur

        best = [0] * (MAXT + 2)
        best[MAXT + 1] = ps[-1]
        best[MAXT] = arr[MAXT]
        for t in range(MAXT - 1, -1, -1):
            best[t] = max(arr[t], best[t + 1])

        reward.append(best)

    floyd(n, dist)

    dp = [[-1] * n for _ in range(1 << n)]

    start = 0
    dp[1 << start][start] = 0

    for mask in range(1 << n):
        for i in range(n):
            if dp[mask][i] < 0:
                continue
            cur_time = 0
            cnt = bin(mask).count("1")
            if cnt:
                cur_time = 0
            for j in range(n):
                if mask & (1 << j):
                    continue
                d = dist[i][j]
                if d == INF:
                    continue
                arrival = cur_time + d
                if arrival > MAXT + 1:
                    arrival = MAXT + 1
                gain = reward[j][arrival]
                nmask = mask | (1 << j)
                dp[nmask][j] = max(dp[nmask][j], dp[mask][i] + gain)

    ans = 0
    for i in range(n):
        ans = max(ans, max(dp[(1 << n) - 1]))

    print(ans)

if __name__ == "__main__":
    solve()
```すべての遷移は場所間の最小移動時間のみに依存するため、コードは最短パスを計算することから始まります。 これにより、DP からグラフ構造が完全に削除されます。 

各ノードの報酬スケジュールは、最大 200 の時間配列に拡張され、その後サフィックス最大配列に変換されるため、配信時間の下限を考慮して、すべての遷移で達成可能な最高の利益を即座に計算できます。 

DP は、訪問したノードに対してビットマスクを使用します。 各遷移では、現在のノードから未訪問のノードへの移動を試行し、移動時間を追加して報酬期間に上限を設け、事前に計算された最高の報酬を適用します。 

実装の微妙な詳細は、200 を超える時間の上限です。これがないと、すべての遅い時間は同じ値を共有するため、DP は報酬条件において同等の状態を不必要に区別することになります。

 ## 特殊なケース

 重要なエッジ ケースは、移動時間がすべての意味のあるしきい値をすでに超えている場合に発生します。 その状況では、追加の遅延に関係なく、すべての配信で最終的な報酬値が直ちに取得される必要があります。 200 を超える到着時間は一定のセグメントにマッピングされるため、接尾辞の最大構成によりこれが自動的に保証されます。 

もう 1 つのエッジ ケースは、最適な戦略が目的地ではなく中間ノードで待機する必要がある場合です。 DP はこれを暗黙的に処理します。これは、到着時間のみが重要であり、移動は決定的であるため、実行可能性や報酬を変更することなく待機を宛先ノードにシフトできるためです。
