 ## 解決策
 ## 問題の理解

 の行が与えられています$n$植物はそれぞれ同じ高さから始まります$h$。 各植物について、変更しないままにするか、厳密に以下の整数の高さに切り詰めることができます。$h$。 すべての植物の最終的な高さを選択した後、次の順序を満たす必要があります。$n-1$隣接する植物間の厳密な比較。各比較は「左が右より小さい」または「左が右より大きい」のいずれかです。 

タスクは、これらすべての不等式を満たす、個別の最終高さ配列をいくつ形成できるかを数えることです。ここで、少なくとも 1 つの位置の最終高さが異なる場合、2 つの配列は異なるものとみなされます。 答えはモジュロで計算されます$10^9+7$。 

重要な観察は操作定義から直接得られます。各位置は範囲内の値のみを取ることができます。$[1, h]$、隣接制約が選択肢を結合することを除いて、この範囲内の任意の値を独立して自由に選択できます。 したがって、これは基本的に、整数シーケンスに対する制約された計数の問題です。 

制約$n \le 3000$そして$h \le 10^6$位置ごとに実際の高さの値を反復するアプローチは直ちに除外してください。 エッジごとに全値範囲にわたる高さまたは遷移を明示的に列挙しようとするソリューションは、非常に遅くなります。 に依存する定式化が必要です。$h$せいぜい線形か対数です。 

微妙なエッジケースは次のような場合です$h = 1$。 この場合、位置を減らすことはできないため、すべての要素は強制的に正確に 1 になります。有効な構成は、すべての制約が等しい値と一致する場合にのみ存在しますが、すべての比較が厳密であるため、これは不可能です。 したがって、次の場合、答えは常に 0 になります。$n > 1$そして$h = 1$。 

もう 1 つの重要なエッジ ケースは、完全に単調な制約チェーン、たとえばすべてが「<」である場合です。 その場合、有効なシーケンスは、次の範囲で厳密に増加するシーケンスに対応します。$h$、それでも多数になる可能性がありますが、厳格な上限を尊重する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、すべての高さの割り当てが試行されます。$[1, h]$それぞれについて$n$位置を確認し、各割り当てがすべての不等式を満たすかどうかを確認します。 これはすでに与えられています$h^n$可能性は、たとえ小さなものであっても完全に実行不可能です$n$。 

状態空間を圧縮する必要があります。 重要な観察は、重要なのは絶対値ではなく、不平等の連鎖によって引き起こされる相対的な順序であるということです。 すべての制約は近隣要素間の厳密な比較であるため、順序は要素をローカルで「ランク付け」し、それらのランクと一致する実際の値を割り当てる方法によって決定されます。 

相対パターンを修正する場合、つまり位置ごとにその値を前の値と比較する方法を決定する場合、実際の数値割り当ては、特定のセグメントに沿って厳密に増加する個別の値のシーケンスを選択することに対応します。 各セグメントは単調な実行のように動作します。 

標準的な縮小では、方向の変化に応じて配列を単調なブロックに分割したものとして表示します。 各ブロック内では、制約によって固定方向の厳密な単調性が強制され、ブロック間では方向が反転します。 次に問題は、値を割り当てる方法が何通りあるかを数えるということになります。$[1, h]$交互のモノトーン制約を持つシーケンスに。 

これは、プレフィックスごとに、特定の「ランク構造」で終了する方法が何通りあるかを追跡する動的プログラミングを使用して解決できますが、値空間にわたるプレフィックスの合計を使用することで、高さに関する反復を回避します。 各遷移は、上昇するか下降するかに応じて、プレフィックスまたはサフィックスの合計になります。 

重要な構造は、各位置で許容される範囲にわたる累積カウントのみが必要なため、位置全体にわたる DP と、線形な範囲遷移で可能な最終高さを維持できるということです。$h$ただし、プレフィックス合計を使用して最適化されているため、各遷移は次のようになります。$O(1)$。 

これにより、問題は指数列挙から次のような問題に軽減されます。$O(nh)$動的プログラミングは許容されます。$n \le 3000$そして$h \le 10^6$ただし、DP をさらに圧縮します。遷移は前の行のプレフィックスの合計にのみ依存するため、サイズの 2 つの配列のみを保存します。$h$。

 ## アルゴリズムのチュートリアル

 DP 配列を定義します。$dp[i][x]$最初のオブジェクトに高さを割り当てる有効な方法の数です。$i$そのような位置$i$ちょうど高さがある$x$。 から移行するだけなので、$i-1$に$i$、これを 2 つの配列に圧縮できます。 

1.初期化$dp[1][x] = 1$みんなのために$1 \le x \le h$、最初の植物は独立して任意の高さを取得できるためです。 
2. 間の各制約について$i-1$そして$i$では、関係が「<」か「>」かに応じて新しい DP 配列を更新します。 
3. 制約が「<」の場合、各値に対して$x$位置にある$i$、私たちは持っている必要があります$dp[i][x] = \sum_{y < x} dp[i-1][y]$。 これは、以前の高さが厳密に小さくなければならないことを反映しています。 
4. 制約が「>」の場合、各値に対して$x$、私たちは持っている必要があります$dp[i][x] = \sum_{y > x} dp[i-1][y]$、つまり、以前のより大きな高さをすべて合計します。 
5. これらの合計を効率的に計算するために、前の DP 配列のプレフィックス合計を構築します。 次に、「<」クエリはプレフィックス検索になり、「>」クエリは合計からプレフィックスを引いたものになります。 
6. すべてのポジションを処理した後、答えはすべてのポジションの合計になります。$dp[n][x]$のために$1 \le x \le h$。 

### なぜ効果があるのか

 有効なプレフィックス割り当ては最後の高さによって一意に特徴付けられるため、DP 状態はすべての有効な部分割り当てを完全にキャプチャします。 遷移では、隣接制約がエッジごとに 1 回だけ適用され、すべての有効なシーケンスが DP を通る 1 つのパスに寄与します。 プレフィックス合計変換はセマンティクスを変更せず、範囲合計を効率的に再表現するだけです。 すべての拡張ステップはローカルで正確さを維持し、すべての有効な継続をカバーするため、最終的な合計では、すべての有効なシーケンスが 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    n, h = map(int, input().split())
    s = input().strip()

    if h == 1:
        # only one possible array, but strict constraints make it impossible for n>1
        return 1 if n == 1 else 0

    dp = [1] * (h + 1)

    for i in range(n - 1):
        ndp = [0] * (h + 1)
        pref = [0] * (h + 1)

        for v in range(1, h + 1):
            pref[v] = (pref[v - 1] + dp[v]) % MOD

        if s[i] == '<':
            for x in range(1, h + 1):
                ndp[x] = pref[x - 1]
        else:
            total = pref[h]
            for x in range(1, h + 1):
                ndp[x] = (total - pref[x] + MOD) % MOD

        dp = ndp

    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```実装は DP 定義に直接準拠します。 プレフィックス配列は各ステップで再計算され、定数時間の範囲合計が可能になります。 「<」トランジションでは、次のプレフィックスが使用されます。$x-1$一方、「>」遷移では合計マイナス接頭辞が使用されます。$x$、厳密な不平等を注意深く維持します。 

唯一の微妙な境界は厳密性を確保することです。「<」については除外します。$x$それ自体、したがって$pref[x-1]$。 「>」については除外します$x$同様に、したがって減算します$pref[x]$。 

## 実用的な例

 ### 例 1

 入力:```
3 3
<>
```まずは以下から始めます:

 | 私 | dp 状態 |
 | --- | --- |
 | 1 | [1,1,1] |

 遷移 1 は「<」です。 

| × | 接頭語 | NDP |
 | --- | --- | --- |
 | 1 | 0 | 0 |
 | 2 | 1 | 1 |
 | 3 | 2 | 2 |

 したがって、dp は [0,1,2] になります。 

次の遷移は「>」です。 

| × | 接頭語 | 合計 | NDP |
 | --- | --- | --- | --- |
 | 1 | 0 | 3 | 3 |
 | 2 | 1 | 3 | 2 |
 | 3 | 3 | 3 | 0 |

 最終的な dp は [3,2,0]、合計は 5 です。 

これは、相対的な順序のみが重要であり、実行可能な割り当ては一貫した厳密なチェーンに対応するという考えと一致します。 

### 例 2

 入力:```
4 2
<<<
```初期 dp は [1,1] です。 

最初の「<」の後: dp は [0,1] になります。 

2 番目の「<」以降: dp は [0,0] になります。 

3 番目の「<」以降: dp は [0,0] のままです。 

長さ 4 の厳密に増加するチェーンは 2 つの値だけでは形成できないため、最終的な答えは 0 です。 

これは、値の制約が単調構造とどのように相互作用するかを示しています。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, h = map(int, sys.stdin.readline().split())
    s = sys.stdin.readline().strip()

    if h == 1:
        return str(1 if n == 1 else 0)

    dp = [1] * (h + 1)

    for i in range(n - 1):
        ndp = [0] * (h + 1)
        pref = [0] * (h + 1)

        for v in range(1, h + 1):
            pref[v] = (pref[v - 1] + dp[v]) % MOD

        if s[i] == '<':
            for x in range(1, h + 1):
                ndp[x] = pref[x - 1]
        else:
            total = pref[h]
            for x in range(1, h + 1):
                ndp[x] = (total - pref[x] + MOD) % MOD

        dp = ndp

    return str(sum(dp) % MOD)

# provided sample
assert run("3 3\n<>\n") == "5", "sample 1"

# minimum n
assert run("2 2\n<\n") == "1", "two elements increasing"

# impossible strict chain
assert run("4 2\n<<<\n") == "0", "insufficient height"

# all decreasing
assert run("3 3\n>>\n") == "5", "symmetric case"

# h = 1 edge case
assert run("3 1\n<<\n") == "0", "h=1 forces impossibility"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3 3 < > | 5 | 正しい混合トランジション |
 | 4 2 <<< | 0 | 実現不可能な厳しい成長 |
 | 3 3 >> | 5 | 対称減少の場合 |
 | 3 1 << | 0 | 縮退高さ制限 |

 ## 特殊なケース

 いつ$h = 1$、すべての位置は強制的に 1 になります。アルゴリズムは、次の場合を除き、正しく 0 を返します。$n = 1$なぜなら、厳密な不等式の下では、すべての DP 遷移はゼロに崩壊するからです。 

「<<<…」のような完全に単調なチェーンの場合、プレフィックスの合計が実行可能な範囲を超えて最終的にゼロになるため、DP は急速に崩壊します。これは、利用可能な個別の値を超えてシーケンスを厳密に増加させることは組み合わせ的に不可能であることと一致します。 

「<><><」のような交互パターンの場合、DP は複数のアクティブ状態を維持し、プレフィックスとサフィックスの遷移は有効な構成を失うことなく対称性を維持します。これにより、各有効なシーケンスが DP の進化を通じて正確に 1 回カウントされることが確認されます。
