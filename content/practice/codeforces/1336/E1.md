 ## 問題の理解

 それぞれが m ビット マスクとしてエンコードされた整数のコレクションが与えられます。 これらの数値から、空のサブセットを含む任意のサブセットを選択でき、サブセットごとに、選択されたすべての値の XOR を計算します。 その XOR 結果はバイナリで解釈され、その「値」をそのバイナリ表現の設定ビット数として測定します。 

タスクは、単一のサブセットを計算することではなく、すべてのサブセットを考慮することです。$2^n$サブセットとそのポップカウントが正確に一致する XOR を生成するサブセットの数をカウントします。$i$、すべての$i$から$0$に$m$。 

重要な構造は、サブセットの選択が GF(2) に対して線形である XOR を通じて相互作用することです。 最終的な XOR の各ビットは、そのビットが設定されている選択された要素の数のパリティのみに依存します。 

この制約により、サブセットに対するブルート フォースは不可能になります。 と$n \le 2 \cdot 10^5$、すべてのサブセットを列挙すると指数関数的になります。 サブセットの XOR 値を生成する場合でも、$O(2^n \cdot n)$、これは実現可能な限界をはるかに超えています。 

重要な構造上のヒントは、$m \le 35$これは、値が GF(2) 上の比較的低次元のベクトル空間に存在することを意味します。 これは、サブセット XOR 空間が強力な線形代数構造を持ち、サブセットを数えることは個々の要素ではなく基底ベクトルに関する推論に帰着することを示唆しています。 

すべての数値がゼロの場合、微妙なエッジケースが発生します。 すべてのサブセットは XOR ゼロを生成するため、答えは値に完全に集中します。$0$。 もう 1 つの特殊なケースは、数値がすべての次元に個別にまたがる場合です。 その場合、XOR は部分空間全体に均一に分散され、サブセットがビット間で独立していないため、サブセット サイズに関する単純な周波数推論は完全に失敗します。 

最後の落とし穴は、ビット間の独立性を前提とすることです。 XOR はビットごとに動作しますが、サブセット結合は、基底が注意深く扱われない限り、ビットが分散において独立していないことを意味します。 

## アプローチ

 直接的なアプローチでは、すべてのサブセットを列挙し、XOR を計算し、ポップカウントをカウントします。 これは定義に正確に従っているため、正しいです。 ただし、反復処理が必要です$2^n$サブセット、それぞれ最大$O(n)$XOR が機能するため、実行時間が不可能になります。 

より構造化されたビューは、サブセットから XOR の線形代数に移行することです。 各数値はベクトルです。$\mathbb{F}_2^m$。 すべてのサブセット XOR のセットは、これらのベクトルによって生成される線形部分空間を形成します。 この空間の次元がランクです$r$システムの。 

基底を取得すると、すべてのサブセット XOR は基底ベクトルの係数の選択に対応しますが、依存ベクトルは到達可能な XOR 空間を変更せずにカウントを乗算するだけです。 これにより、問題は、スパン内の各 XOR ベクトルを実現できる方法が何通りあるかをカウントし、結果をポップカウントによってグループ化することに変換されます。 

重要な観察は、サブセット構造が 2 つの部分に分解されることです。XOR 空間を決定する自由な選択と、すべての構成に次の値を乗算するだけの冗長要素です。$2^{n-r}$。 配列を基底に縮小した後は、最大でも次のものだけを扱う必要があります。$r \le m \le 35$ベクトルを使用して、マスク上の指数関数的な DP を実現可能にします。 

次に、基底ベクトルに対して DP を実行します。各基底ベクトルは XOR に寄与するか寄与せず、すべての基底ベクトルを効果的に構築します。$2^r$考えられる XOR 結果。 各結果は基底要素のサブセットに対応し、各ポップカウントを生成する要素の数を数えます。 最後に次を掛けます$2^{n-r}$依存要素を考慮するため。

 ## アルゴリズムのチュートリアル

 各数値をビット ベクトルとして扱い、GF(2) に対して線形基底を構築します。 

1. 入力配列から線形基底を構築します。 以前に保存された基底ベクトルを使用して、最も高い設定ビットを貪欲に削除することにより、各数値を挿入します。 これにより、各基底ベクトルが一意のピボット ビットを持つことが保証されるため、基底は独立したままになります。 
2. 基底に線形依存する入力数値の数を数えます。 消去後にゼロになる数値を挿入した場合、ランクは増加せず、後の乗算係数に寄与します。 
3. ランクを次のようにします$r$。 今では$r$可能なすべての XOR 結果を生成する独立したベクトル。 
4. DP 配列を初期化します。ここで、dp[x] は、XOR が x に等しい基底ベクトルのサブセットの数を表します。 空のサブセットを表す dp[0] = 1 から始めます。 
5. 各基底ベクトルを 1 つずつ処理します。 各ベクトル v について、v を取得しない (XOR を変更しないままにする) 場合と v を取得する (XOR を v で切り替える) という 2 つのケースをマージして dp を更新します。 これは、XOR 空間上の標準的なサブセット畳み込みです。 
6. すべての基底ベクトルを処理した後、dp には、基底空間で各 XOR 値を達成する方法の数が含まれます。 
7. 各 XOR 値について、そのポップカウントを計算し、対応する回答バケットに dp[値] を追加します。 
8. すべてのバケットに次の値を掛けます。$2^{n-r}$これは、XOR 空間に影響を与えることなく、各依存ベクトルを自由に含めたり除外したりできるためです。 

### なぜ効果があるのか

 線形基底により、元のセットからのすべての XOR 結果が、基底ベクトルのサブセットと従属ベクトル間の任意の選択に一意に対応することが保証されます。 これにより積構造が作成されます。つまり、到達可能な XOR のスペースは$r$GF(2) 上の - 次元ベクトル空間、およびその空間内の各点は正確に到達されます。$2^{n-r}$サブセット。 DP はベクトル空間を点ごとに 1 回だけ列挙し、最後の乗算で完全なサブセット数を復元します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    basis = [0] * m
    rank = 0

    for x in a:
        v = x
        for i in reversed(range(m)):
            if (v >> i) & 1:
                if basis[i]:
                    v ^= basis[i]
                else:
                    basis[i] = v
                    rank += 1
                    break

    vecs = []
    for i in range(m):
        if basis[i]:
            vecs.append(basis[i])

    dp = [0] * (1 << len(vecs))
    dp[0] = 1

    for v in vecs:
        for mask in range((1 << len(vecs)) - 1, -1, -1):
            dp[mask ^ v] = (dp[mask ^ v] + dp[mask]) % MOD

    pow2 = pow(2, n - rank, MOD)

    ans = [0] * (m + 1)
    for mask in range(1 << len(vecs)):
        pc = mask.bit_count()
        ans[pc] = (ans[pc] + dp[mask]) % MOD

    for i in range(m + 1):
        ans[i] = ans[i] * pow2 % MOD

    print(*ans)

if __name__ == "__main__":
    solve()
```実装は、XOR 線形基底を構築することから始まります。 各数値は既存のピボットに対して削減されるため、独立したベクトルのみが保持されます。 ランクによって、残っている自由度が決まります。 

次に、DP は基底ベクトルのすべての XOR 組み合わせを列挙します。 マスク ループでの逆の反復は、同じステップ内で更新された状態の再利用を回避し、サブセット遷移の正確さを維持するために必要です。 

最後に、到達可能な各 XOR は、依存要素によって元のサブセットが崩壊する数によって重み付けされ、次の乗算によって処理されます。$2^{n-r}$。

import sys, io

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    basis = [0] * m
    rank = 0

    for x in a:
        v = x
        for i in reversed(range(m)):
            if (v >> i) & 1:
                if basis[i]:
                    v ^= basis[i]
                else:
                    basis[i] = v
                    rank += 1
                    break

    vecs = [basis[i] for i in range(m) if basis[i]]

    dp = [0] * (1 << len(vecs))
    dp[0] = 1

    for v in vecs:
        for mask in range((1 << len(vecs)) - 1, -1, -1):
            dp[mask ^ v] = (dp[mask ^ v] + dp[mask]) % MOD

    pow2 = pow(2, n - rank, MOD)

    ans = [0] * (m + 1)
    for mask in range(1 << len(vecs)):
        ans[mask.bit_count()] += dp[mask]

    for i in range(m + 1):
        ans[i] %= MOD
        ans[i] = ans[i] * pow2 % MOD

    return " ".join(map(str, ans))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての要素がゼロである場合です。 基底は空でランクは 0 ですが、すべてのサブセットは依然として存在します。 アルゴリズムは正しく dp[0] = 1 を生成し、次の値を乗算します。$2^n$、ポップカウント 0 ですべての質量が得られます。 

もう 1 つのケースは、インプットがすでに完全な基礎を形成している場合です。 ここで、ランクは m 以下に等しく、依存したスケーリングは発生しません。 DP のみで完全に答えが決定され、追加の乗算係数は適用されないため、数えすぎが防止されます。 

3 番目のケースは、複数の要素が同じ基底ベクトルに帰着する場合です。 貪欲な挿入により、ピボット ビットごとに 1 つの代表のみが保存されることが保証され、DP での重複した状態遷移が防止され、それを超える指数関数的な爆発が回避されます。$2^m$。
