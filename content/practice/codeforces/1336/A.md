 ## 問題の理解

 都市 1 に根を張る木が与えられています。各都市は工業都市または観光都市として選択されます。$k$工業都市として選ばれた都市。 

各工業都市は首都に使節を1人派遣します。 その特使は、都市からノード 1 までツリー内の固有の最短パスに沿って移動します。このパスに沿って、特使が観光都市を通過するたびに、1 単位の幸福を獲得します。 工業都市は幸福をもたらしません。 

したがって、合計スコアは、選択されたすべての産業ノードにおける、厳密にルートへのパス上にある観光ノードの数の合計になります。 

どちらを選びたいか$k$この合計を最大化するためにノードが産業化されます。 

ツリーには最大で次のものを含めることができます$2 \cdot 10^5$ノード、つまりサイズのすべてのサブセットを試行するソリューション$k$不可能です。 平$O(n^2)$または$O(nk)$最悪の場合、スタイルの走査は失敗します。 周りに何かが必要です$O(n \log n)$または$O(n)$。 

構造上の重要な点は、各ノードの寄与が、ルートまでの距離と、ツリー内でその上にある選択された産業ノードの数に依存することです。 この依存関係は、明示的なパスの列挙ではなく、深さとサブツリー構造の観点から考える必要があることを示唆しています。 

素朴なアプローチでは、あらゆる方法で選択しようとするでしょう。$k$ノードとスコアを計算しますが、それは組み合わせです$\binom{n}{k}$、すぐには実行不可能です。 

もう 1 つの微妙な失敗例は、パスの重複を考慮せずに最も深いノードを貪欲に選択することです。 選択した 2 つのノードがルートへの長いプレフィックス パスを共有する場合、それらの寄与は独立しておらず、単純な深さのみの選択では利点が過大評価されたり、より良い構成が見逃されたりする可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、次のすべてのサブセットが列挙されます。$k$ノードを選択し、選択した各ノードのパスをルートまでたどることによって合計幸福度を計算します。 それぞれの評価にかかる費用$O(n)$、パスは長さを指定できるため、$O(n)$連鎖的に。 これは次のことにつながります$O(n \binom{n}{k})$、それは天文学的な大きさです。 

単純化するには、各ノードが構造的にどのような役割を果たしているかを理解する必要があります。 ノードの場合$v$産業として選択されると、ルートに至るまでのすべての観光ノードに 1 ユニットの幸福が貢献します。 これは、ルートへのパス上の選択されていないすべてのノードを数えるのと同じです。 

このアイデアを別の方法で書き直します。 各ノードを考慮する$v$。 その深さをこうしましょう$d(v)$。 私たちが選ぶなら$v$産業としての役割を果たした場合、その祖先のほとんどが観光業を続ける場合、その潜在的な貢献は最大化されます。 ただし、祖先は選択された複数のノード間で共有される可能性があるため、ノードごとの寄与を直接カウントするのは面倒です。 

より明確な視点は、問題を逆転させることです。 産業用ノードを合計する代わりに、選択したノードが通過する数に応じて、各ノードが合計スコアにどの程度寄与するかを考えることができます。 各ノード$u$パスが工業として通過する場合を除き、そのサブツリー (それ自体を含む) 内のすべての工業ノードの答えに 1 を寄与します。これにより寄与がブロックされます。 

これは、選択が多くの先祖に「影響を与える」ノードを優先する必要があることを示唆しています。 ノードが深くなるほど、ルートへのパス上にある他のノードが少なくなるため、深いノードを選択すると、より高い寄与が得られる傾向があります。 

重要な洞察は、各ノードの深さと、そのサブツリーに含まれるノードの数を計算することです。 次に、そのノードを産業化することがどれほど有益であるかを表す値を定義します。具体的には、ツリーのより深いノードほど、そのパス上により多くの観光ノードを生成する傾向があります。

 ## アルゴリズムのチュートリアル

 1. ノード 1 でツリーをルートし、DFS を使用してすべてのノードの深さを計算します。 

深さは、首都への経路上のノードの上に潜在的な観光都市がいくつあるかを表します。 
2. DFS 中に、各サブツリーのサイズも計算します。 

これは、ノードの「下」にノードがいくつあるか、したがって選択の決定がどのように下方に伝播するかを把握するのに役立ちます。 
3. 各ノードについて$v$、値を計算します$gain(v)$次のように定義されます。 

選択することで恩恵を受けるノードの数$v$、次のように導出できます$depth(v) - (subtree\_size(v) - 1)$。 

これは、ノードが深いほど観光への寄与が大きくなる一方、サブツリーが大きいほどパスが共有されるため限界利益が減少することを反映しています。 
4. すべてのノードを次の基準で並べ替えます。$gain(v)$降順で。 
5. 上部を選択します$k$ノード。 これらは最適な工業都市です。 
6. 選択したノードの深さを合計し、ゲイン公式によって暗黙的に処理されるオーバーラップ補正を減算することによって、最終的な答えを計算します。 

### なぜ効果があるのか

 各ノードは、選択したノードからルートまでのパス上にいくつの観光ノードがあるかによって、最終スコアに正確に寄与します。 DFS は、これらのパスを独立したサブツリー コントリビューションに分解します。 ゲイン関数は、重複するパスの寄与を加算的な独立した重みに変換します。 すべてのオーバーラップはサブツリー集約によって完全にキャプチャされるため、最も高い限界利得を持つノードを選択することで、二重カウントや相互作用の見逃しがなく、グローバルに最適な蓄積が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

n, k = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(n - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

depth = [0] * (n + 1)
parent = [0] * (n + 1)
order = []

def dfs(u, p):
    for v in g[u]:
        if v == p:
            continue
        depth[v] = depth[u] + 1
        parent[v] = u
        dfs(v, u)
    order.append(u)

dfs(1, 0)

sub = [1] * (n + 1)
for u in order:
    for v in g[u]:
        if v == parent[u]:
            continue
        sub[u] += sub[v]

gain = []
for i in range(1, n + 1):
    gain.append(depth[i] - (sub[i] - 1))

gain.sort(reverse=True)
print(sum(gain[:k]))
```DFS は深さと事後リストの両方を構築します。 深さは、すべてのパスの基本寄与構造であるルートからの距離を直接エンコードします。 サブツリーのサイズは、各ノードがその子を集約するように、逆の DFS 順序を使用して後で計算されます。 

ゲイン定義は、深さとサブツリーの重なりの間の相互作用を単一の並べ替え可能なメトリックに圧縮します。 ソートにより、幸福度全体に対する限界効果が最も強いノードを常に選択できるようになります。 頂上をまとめると$k$ゲインは、エンボイ パスをシミュレートせずに最終的な最適値を与えます。 

実装の微妙な詳細は、DFS トラバーサル順序がわかった後にサブツリー サイズを計算する必要があることです。 もう 1 つは、再帰の深さを確実に増やすことです。そうしないと、チェーン状のツリーが Python の再帰スタックをオーバーフローしてしまうからです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    sys.setrecursionlimit(10**7)

    n, k = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        g[u].append(v)
        g[v].append(u)

    depth = [0] * (n + 1)
    parent = [0] * (n + 1)
    order = []

    def dfs(u, p):
        for v in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            parent[v] = u
            dfs(v, u)
        order.append(u)

    dfs(1, 0)

    sub = [1] * (n + 1)
    for u in order:
        for v in g[u]:
            if v != parent[u]:
                sub[u] += sub[v]

    gain = [depth[i] - (sub[i] - 1) for i in range(1, n + 1)]
    gain.sort(reverse=True)
    return str(sum(gain[:k]))

 ## 特殊なケース

 鎖の形をした木は、深さがどのように支配しているかを示しています。 で`1-2-3-4-5`、最も深い 2 つのノードを選択すると、深さに合わせたゲインが得られ、アルゴリズムはゲイン値が大きいため、より深いノードを正しくランク付けします。 

星形の木は、すべての葉が同等であることを示しています。 各リーフの深さは 1、サブツリーのサイズは 1 であるため、すべてのゲインは同一であり、$k$Leave は同じ結果を生成しますが、これは並べ替えによって自然に処理されます。 

非常に不均衡なツリーは、サブツリー サイズのペナルティが重要であることを示しています。 ルートに近いノードはサブツリー サイズが大きいためゲインが減少し、より独立した観光パスに寄与する深いノード上でノードが誤って選択されるのを防ぎます。
