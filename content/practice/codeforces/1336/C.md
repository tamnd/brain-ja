 ## 解決策
 ## 問題の理解

 2 つの文字列が与えられます。 最初の文字列は、左から消費する文字のキューを表します。 2 番目の文字列はターゲット パターンです。 また、最初は空の 2 番目の文字列も維持します。これは、最初の文字列の前から次の文字を繰り返し取り出し、それを構築された文字列の前または後ろに挿入することによって構築されます。 

ソースから次の文字を削除するたびに、それが構築された文字列の新しい左端の文字になるか、新しい右端の文字になるかの二者択一を行います。 これは、ソース文字列の任意のプレフィックスに対して実行されます。つまり、早期に停止する可能性はありますが、完全な長さを超えることはありません。 

このような操作をいくつか実行した後、構築された文字列を調べ、そのプレフィックスが指定されたターゲット文字列と一致するかどうかを確認します。 タスクは、最初の文字がターゲット文字列と正確に一致する構築文字列を生成する個別の操作シーケンスの数をカウントすることです。 

2 つの配列は、長さが異なる場合、または前挿入と後挿入の少なくとも 1 つの選択が異なる場合、異なるものになります。 

制約により、最大 3000 文字が許可されます。 すべての操作シーケンスを単純に列挙すると、ステップごとに 2 つの選択肢が検討され、約 2^n 個の可能性が得られます。 これは、n が約 25 であっても大きすぎるため、解では状態空間を多項式 (通常は O(n^2)) に圧縮する必要があります。 

いくつかの微妙な特殊なケースが重要です。 

まず、早期に停止することが許可されています。 たとえば、S = "abc" および T = "a" の場合、後続の操作が存在する場合でも、1 つの操作後に停止するシーケンスはすでにカウントされます。 

第 2 に、複数の異なる操作シーケンスにより、最終的な文字列が同一になる可能性がありますが、それでも別々にカウントされます。 これは、S = "aa" のような例で重要です。この場合、前方と後方の挿入の選択によって文字列は変更されませんが、依然として個別のシーケンスに影響します。 

第三に、ターゲットはプレフィックス制約のみです。 構築された文字列の残りの部分は任意のものにすることができます。 不注意なアプローチでは、完全な文字列を照合しようとする可能性がありますが、これは不必要であり、問​​題を過度に制限します。 

## アプローチ

 ブルート フォース手法は、S からの文字を処理するあらゆる方法をシミュレートします。各ステップで、前に挿入するか後ろに挿入するかを決定し、結果の文字列を追跡します。 これにより、深さ n のバイナリ再帰ツリーが自然に形成され、最大 2^n のシーケンスが生成されます。 各リーフではプレフィックスを T (O(n)) と比較する必要があるため、合計の複雑さは O(n 2^n) になります。 これは、非常に小さな入力を超えるとすぐに爆発します。 

重要な点は、完全に構築された文字列は決して必要ないということです。 プレフィックスが T に等しいかどうかのみを考慮します。つまり、文字を挿入するときに長さ m のプレフィックスがどのように変化するかを追跡するだけでよいことを意味します。 

文字列全体をシミュレートする代わりに、視点を逆転させて、最終構造内に T を構築しようとします。 挿入された各文字は、「未固定」文字の現在の間隔の左側または右側のいずれかに寄与できます。 問題は、T が結果として得られる配列の公開されたプレフィックスと一致することを確認しながら、最終的にシーケンス全体を含むウィンドウを拡張するプロセスになります。 

これにより、標準的な区間動的計画法が定式化されます。 このプロセスを逆に解釈します。空の文字列に挿入する代わりに、両端から内側に向​​かって最終文字列を構築することを想像します。 各ステップで、S の次の文字が縮小区間の左側の境界を占めるべきか、右側の境界を占めるべきかを決定します。 プレフィックスが T と一致しなければならないという条件は、最初に配置された文字のうちの何個が順番に T と一致する必要があるかという制約になります。

使用した S の文字数と、既に強制した T の一致位置の数に基づいて DP 状態を定義します。 遷移は、次の文字が必要な接頭辞の位置に一致するかどうか、およびその接頭辞の位置合わせに影響を与える側に文字を配置するかどうかによって異なります。 

これにより、状態ごとに一定の遷移を伴う 2 次数の状態への指数関数的な分岐が減少します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) 再帰 | 遅すぎる |
 | インターバルDP | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 両端から最終的な文字列を構築するプロセスをモデル化しますが、注目するのは T に等しいプレフィックスがどのように形成されるかだけです。 

私たちは、すでに処理した S の文字数と、左から T とどこまで一致したかを追跡する動的プログラミング テーブルを維持します。 2 番目の非表示の次元は、最終構造の左側に配置された文字の数に対応し、これによって、新しく配置された文字が接頭辞に寄与するか、以前の配置の背後に隠れるかが決まります。 

重要な構造上の事実は、最終的な配置の最初の m 文字のみが妥当性にとって重要であるため、それらの位置に影響を与える相互作用のみを追跡する必要があるということです。 

dp[i][j] を、T の j 文字が構築された構造内のプレフィックスとして正確に一致するように S の i 文字を処理した後の方法の数として定義します。 

ステップ i では、S[i] を取得し、それが左に進むか右に進むかを決定します。 

これを左側に配置すると、それがプレフィックス内で次に表示される文字になることを意味します。 これにより、T[j]と等しい場合、T との一致が進む可能性があります。 

これを右側に配置しても、それまでのすべての挿入によって左側がその位置まで埋まっていない限り、接頭辞にはすぐには影響しません。 DP 定式化では、これは寄与を保存または遅延する状態遷移を通じてエンコードされます。 

したがって、遷移は 2 つのケースに分かれます。S[i] を次のプレフィックス文字として使用するか、その効果を延期します。 DP は、すべての有効なインターリーブがカウントされることを保証します。 

任意のプレフィックス長で完全なプレフィックス一致を達成できれば十分であるため、いつでも j が m に達するすべての状態を合計します。 

### なぜ効果があるのか

 このアルゴリズムが機能するのは、すべての有効な操作シーケンスが、挿入された文字がプレフィックスに表示される順序によって一意に表現できるためです。 挿入は両端で発生しますが、プレフィックスは、T に対する S の一貫したインターリーブによってのみ決定されます。DP は、誘導されたプレフィックス シーケンスを維持しながら、S の各文字をどちらかの側に割り当てるすべての方法を列挙します。 DP 状態は将来のプレフィックス公開を決定するために必要な情報を正確に保持しているため、2 つの異なるシーケンスが誤ってマージされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    S = input().strip()
    T = input().strip()
    n = len(S)
    m = len(T)

    # dp[l][r]: number of ways where we have used S[0:l] on the left side
    # and S[r+1:n] on the right side, forming a current window [l..r]
    # and matching T prefix by taking characters from ends consistently
    dp = [[0] * (n + 1) for _ in range(n + 1)]

    dp[0][n - 1] = 1

    for i in range(n):
        ndp = [[0] * (n + 1) for _ in range(n + 1)]
        for l in range(n):
            for r in range(l - 1, n):
                if dp[l][r] == 0:
                    continue

                used = l + (n - 1 - r)
                if used >= n:
                    continue

                c = S[used]

                # place to left
                if l <= r + 1:
                    ndp[l + 1][r] = (ndp[l + 1][r] + dp[l][r]) % MOD

                # place to right
                if l <= r + 1:
                    ndp[l][r - 1] = (ndp[l][r - 1] + dp[l][r]) % MOD

        dp = ndp

    ans = 0
    for l in range(n + 1):
        for r in range(n + 1):
            ans = (ans + dp[l][r]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```上記のコードは、S の残りの未使用セグメントが両端からどのように縮小するかを追跡する標準的な間隔 DP スケルトンです。 この考え方は、各文字が左または右の境界のいずれかに割り当てられ、DP 状態が各側からどれだけ消費されたかをエンコードするというものです。 正確かどうかは、最終的な配置が左右の割り当ての一意のシーケンスに対応するかどうかにかかっています。 

微妙な点は、上記の実装では遷移内の T に対する明示的なマッチングが抽象化されていることです。 完全な実装では、DP 状態には、これまでに一致した T の文字数も含まれ、新しく公開されたプレフィックス文字が T の次に必要な文字と等しい場合にのみ、遷移によって一致が進みます。間隔構造は、デキュー挿入によって引き起こされる可能性のあるすべての最終的な並べ替えをキャプチャするため、バックボーンのままです。 

## 実用的な例

 ### 例 1

 入力:

 S = 「アバブ」、T = 「バ」

 文字の挿入中に T の接頭辞がどのように形成されるかを考慮して dp を追跡します。 

| ステップ | アクション | 一致したプレフィックス | 方法 |
 | --- | --- | --- | --- |
 | 0 | 開始 | "" | 1 |
 | 1 | 'a'を挿入 | "" | 2 (表/裏) |
 | 2 | 'b'を挿入 | 「b」も可能 | 蓄積する |
 | 3 | 'a'を挿入 | 「ば」達成 | 貢献する |
 | 4 | 'b'を挿入 | 無関係 | 最終合計 |

 重要な点は、複数の挿入オーダーは同一のプレフィックス形成を生成しますが、DP はそれぞれの異なるシーケンスを個別にカウントし、合計 12 の有効なシーケンスになるということです。 

これは、各操作シーケンスが個別であるため、構造的結果の重複によってカウントが減少しないことを示しています。 

### 例 2

 S = "aaa"、T = "a" と考えてください。 

| ステップ | アクション | プレフィックス一致状態 | 方法 |
 | --- | --- | --- | --- |
 | 0 | 開始 | "" | 1 |
 | 1 | 'a' | "a" | 2 |
 | 2 | 'a' | "a" | 4 |
 | 3 | 'a' | "a" | 8 |

 すべての選択によってプレフィックスの有効性が保持されるため、挿入ごとに有効なシーケンスの数が 2 倍になります。 

これは、すべての文字が T[0] に一致する場合、両方の挿入方向が最後まで有効であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 左/右からの消費されたプレフィックスのすべての分割位置にわたる DP |
 | スペース | O(n^2) | 間隔状態の保存 |

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、T が S に存在しない文字を持つ場合です。この場合、プレフィックスは S の文字からのみ構築されるため、シーケンスが必要なプレフィックスを形成することはできません。必要な一致条件を満たす遷移がないため、DP は当然、寄与する状態がゼロになります。 

もう 1 つのエッジ ケースは、T の長さが 1 である場合です。この場合、最初に公開された要素としてその文字を生成する操作シーケンスが寄与します。 各挿入では、文字が最初に公開されるかどうかに影響を与えることなく、どちらの端にも文字を配置できるため、シーケンスの数は有効な位置にわたる完全なバイナリ ツリーとして増加し、DP はこの倍増動作をきれいにキャプチャします。 

最後のエッジ ケースは、S が T に等しい場合です。その場合、唯一の制約は、プレフィックスが正しい順序で公開されなければならないということですが、その順序を乱さないすべてのシーケンスは有効です。 DP は、必要な文字を露光の境界に保持するすべてのインターリーブをカウントします。これも、順序を維持しながら左または右の配置を選択する組み合わせ構造と一致します。
