 ## 解決策
 ## 問題の理解

 座標平面上に一連の個別の点があります。 すべてのポイントに最初のいずれかを割り当てる必要があります`k`すべての色がまったく同じ数のポイントを受け取ります。 1 つの色の品質は、その色の内部で最も近い点のペアによって決まります。この最も近い点のペアが離れるほど、色は良くなります。 最終的なスコアは、すべての色にわたるこれらの品質の合計であるため、目標は、すべての色のクラスが内部的に適切に分離されるようにすることです。 

出力は単一の数値回答ではありません。 オリジナルポイントのカラーリングです。 審査員は、各色の内部の最小二乗距離を計算し、これらの値を合計することによって、カラーリングを評価します。 

この制約により、完全に最適な検索は不可能になります。 と`n`最大 1000、割り当て可能な数は`k^n`、それは探求できるものをはるかに超えています。 すべてのバランスの取れたパーティションを考慮しても、組み合わせ的には大規模になります。 の値`k`は小さく、最大でも 25 です。これは、グループを検索するのではなく、グループを直接構築する必要があることを示唆しています。 

座標範囲は 0 ～ 1000 のみであるため、距離には制限があり、距離の 2 乗は標準の整数型に快適に適合します。 コストがかかる部分は、ポイントを他の多くのポイントと比較することです。 アン`O(n^3)`アルゴリズムでは、最大規模のテストではすでに約 10 億回の操作が必要になりますが、Python ではこれはリスクが高すぎます。 アン`O(n^2)`100万回の距離チェックが管理可能であるため、構築は実用的です。 

不注意な実装により大幅なスコアが失われるケースがいくつかあります。 座標で並べ替えた後、すべてのポイントが連続した色に配置される場合、互いに近いポイントが同じグループになる可能性があります。 たとえば、正方形を形成する 4 つの点と 2 つの色を使用すると、次のようになります。```
4 2
0 0
1 0
1 1
0 1
```のようなカラーリング`AABB`2 つの隣接するペアが作成され、スコアが低くなります。 より良い発色`ABAB`隣接するポイントを分離し、最小距離を改善します。 

もう一つの失敗例は次のような場合です。`n`の倍数ではありません`k`、しかし、声明はそれが保証されています。 整数の除算でグループ サイズを計算し、剰余を無視するコードは、問題の別のバージョンで無効な出力を暗黙のうちに生成します。 

ケース`k = 1`もケアが必要です。 色は 1 つだけなので、すべてのポイントに同じ文字を指定する必要があります。 複数のグループを想定したバランス ロジックでは、存在しない色に誤ってアクセスする可能性があります。 

## アプローチ

 ブルートフォース ソリューションでは、ポイントのすべての有効なパーティションが試行されます。`k`サイズのグループ`n / k`、すべてのグループ内の最も近いペアの距離を計算し、最適なパーティションを維持します。 これは考えられるすべての答えを調べるため、常に最適なものが見つかります。 問題はパーティションの数です。 グループ内の順序を無視しても、可能性の数は$$\frac{n!}{((n/k)!)^k k!}$$これは数十点であっても膨大になります。 のために`n = 1000`、これはまったく不可能です。 

重要な観察は、スコアは同じ色の内部の点がどれだけ近いかによってのみ依存するということです。 近くのポイントが同じ色を受け取る可能性が低いポイントの順序を作成できれば、すべての色を同時に明示的に最適化する必要はありません。 

このような順序を作成する便利な方法は、最遠点のトラバーサルです。 1 つの点から開始して、すでに選択されているすべての点から最も遠い点を繰り返し選択します。 これにより、初期のポイントが平面上に広がるシーケンスが生成されます。 このシーケンスに沿って色を周期的に割り当てると、同じ色の点は一緒にクラスター化されるのではなく、トラバース全体を通じて分離されます。 

ブルート フォース アプローチは、考えられるすべてのグループ化を考慮するため機能しますが、検索スペースが大きすぎるために失敗します。 十分に分離された順序付けによって、必要な構造の大部分がすでに捕捉されているという観察により、不可能なパーティション検索を決定論的な貪欲な構造に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最遠点の順序付け | O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての点のペア間の二乗距離を計算します。 必要なのは比較のみであり、平方根を避けることで計算の正確性が保たれるため、二乗距離で十分です。 
2. 任意の開始点を選択し、走査順序を構築します。 次の位置ごとに、すでに選択されている点への最も近い距離が最大である未使用の点を選択します。 

この選択により、各新しいポイントが現在のコレクションから可能な限り遠くに配置され、平面のさまざまな領域をカバーするシーケンスが作成されます。 
3. この順序で点に周期的に色を割り当てます。 最初の点に色が付きます`A`、2番目は色を取得します`B`、そしてその後`k`- 番目の色からやり直します`A`。 

以来`n`で割り切れます`k`、すべての色が正確に表示されます`n/k`回。 同じ色の点は次のように区切られます。`k-1`トラバースの他のポイントに影響を与えるため、近いペアが作成される可能性が低くなります。 
4. 色番号を大文字に変換し、結果の文字列を出力します。 

機能する理由: このアルゴリズムは、平面のカバレッジを最大化するために選択されたポイントがトラバースのすべてのプレフィックスに含まれるという特性を維持します。 貪欲な選択により、注文が 1 つの地域に集中するのを防ぎます。 次に、循環カラーリングにより、これらの十分に分離されたポイントがすべての色に分散されます。 これはスコアの問題であるため、この構築は数学的に最適な分割を証明するものではありませんが、色を共有する点間がしっかりと分離された有効な色を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, k, pts):
    dist = [[0] * n for _ in range(n)]
    for i in range(n):
        xi, yi = pts[i]
        for j in range(i):
            xj, yj = pts[j]
            d = (xi - xj) * (xi - xj) + (yi - yj) * (yi - yj)
            dist[i][j] = d
            dist[j][i] = d

    order = []
    used = [False] * n

    start = 0
    order.append(start)
    used[start] = True

    best = dist[start][:]

    for _ in range(n - 1):
        nxt = -1
        value = -1
        for i in range(n):
            if not used[i] and best[i] > value:
                value = best[i]
                nxt = i

        used[nxt] = True
        order.append(nxt)

        for i in range(n):
            if not used[i] and dist[nxt][i] < best[i]:
                best[i] = dist[nxt][i]

    ans = [''] * n
    for pos, idx in enumerate(order):
        ans[idx] = chr(ord('A') + (pos % k))

    return ''.join(ans)

def main():
    t = int(input())
    out = []
    for case in range(1, t + 1):
        n, k = map(int, input().split())
        pts = [tuple(map(int, input().split())) for _ in range(n)]
        out.append(f"Case #{case}: {solve_case(n, k, pts)}")
    print('\n'.join(out))

if __name__ == "__main__":
    main()
```貪欲トラバーサルでは点間の距離が繰り返し要求されるため、最初に距離行列が構築されます。 これらの値を保存すると、構築中に座標の差を再計算することがなくなります。 

の`best`配列には、選択されていないすべての点について、選択されたセットへの現在の最も近い距離が格納されます。 新しいポイントがトラバーサルに入ると、この配列のみを更新する必要があります。 これは最遠点サンプリングと同じ考え方で、新しい選択ごとに選択したセットのカバレッジが向上します。 

トラバーサルでは座標ではなく元のインデックスが保存されるため、最終的な色付けを入力と同じ順序で書き戻すことができます。 循環代入では次のように使用します。`pos % k`、入力により割り算が保証されるため、すべての色に自動的に同じポイント数が与えられます。 

Python の整数はオーバーフローしないため、最大の座標でも二乗距離は安全です。 唯一重要な境界条件は、`k = 1`ここで、モジュロ演算は引き続き機能し、すべてのポイントに同じ色が割り当てられます。

 ## 特殊なケース

 いつ`k = 1`、入力```
3 1
0 0
1 0
2 0
```受け取るにはすべてのポイントが必要です`A`。 トラバーサルは引き続き実行されますが、最後の割り当てでは最初の文字のみが使用されます。`pos % 1`は常にゼロです。 このアルゴリズムには特別な処理は必要ありません。 

対称正方形の場合:```
4 2
0 0
1 0
1 1
0 1
```座標ソートにより誤って作成される可能性があります`AABB`、隣接する角を結合します。 最も遠いトラバーサルでは、最初に反対側の領域が選択され、循環割り当てにより、各色が別々の点を受け取るカラーリングが生成されます。 

大規模なグループの場合、重要な境界は、すべての色が正確に受信する必要があることです。`n/k`ポイント。 割り当てはトラバース内の位置に基づいており、色は毎回繰り返されます。`k`要素の最終的な数は自動的にバランスがとれます。 元のインデックスに変換せずに走査順序のみに色を割り当てるなどのバグは、出力順序が入力ポイントと一致する必要があるため失敗します。
