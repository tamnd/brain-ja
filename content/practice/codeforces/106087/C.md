 ## 解決策
 ## 問題の理解

 自然数の順序付きトリプルを数えるように求められます$(a, b, c)$、それぞれの間$1$そして$n$、固定構造で加算または乗算を使用して、最初の 2 つの数値から 3 番目の数値を取得できるようにします。$a$そして$b$組み合わせて形成する$c$どちらかとして$a + b = c$または$a \cdot b = c$。 

順序が重要なので、$(1, 2, 2)$そして$(2, 1, 2)$中間のオペランドは算術動作を変更するため、これらは区別されます。 このタスクは純粋に組み合わせです。範囲内に収まりながら、これら 2 つの方程式の少なくとも 1 つを満たすトリプルの数を数えなければなりません。 

制約$n \le 10^7$すべてのトリプルに対して 3 次または 2 次の列挙を即座に除外します。 たとえ$O(n^2)$一定時間チェックを行うアプローチは、この規模では遅すぎます。 ソリューションでは、すべてのペアの反復を回避する必要があります。$(a, b)$明示的に。 

両方の操作が有効な結果を同時に生成する場合、微妙なエッジ ケースが発生します。$a \cdot b = a + b$。 これは、次のような非常に小さな値の場合にのみ発生します。$(2, 2)$、 以来$2 \cdot 2 = 4$そして$2 + 2 = 4$。 このようなケースを個別にカウントすると、慎重に処理しないと二重にカウントされてしまいます。 

## アプローチ

 直接的なアプローチでは、すべてを反復することになります$a$そして$b$、計算する$c = a + b$そして$c = a \cdot b$、どうかを確認してください。$c \le n$。 これは論理的には正しいですが、すべてをチェックする必要があります$n^2$ペア。 と$n = 10^7$、これはまったく実行不可能であり、次のオーダーで生産されます。$10^{14}$操作。 

重要な観察は、実際には選択する必要がないということです。$c$独立して。 一度$a$そして$b$固定されており、$c$は操作ごとに一意に決定されます。 したがって、問題は有効なペアを数えるということになります。$(a, b)$そのような$a + b \le n$または$a \cdot b \le n$。 

加算条件はペアのグリッド内に三角形の領域を形成し、その数は分析的に計算できます。 それぞれについて$a$、有効な$b$値はからのものです$1$に$n - a$、単純な等差級数が得られます。 

乗算条件はより構造化されています。$a$、 有効$b$値が満たされる$b \le \lfloor n / a \rfloor$。 これにより、問題が除数にわたる調和形式の合計に変換され、次のように計算できます。$O(n)$時間を短縮したり、グループ化手法を使用してさらに最適化したりすることもできますが、ここでは、制約と定数係数を考慮すると、直接の合計ですでに十分です。 

残る唯一の複雑な問題は重複です。両方の条件でカウントされたペアは、次の解に正確に対応します。$a + b = a \cdot b$。 この方程式を整理すると、$(a - 1)(b - 1) = 1$、したがって、唯一の正の整数解は次のようになります。$a = b = 2$。 この単一のペアは 1 つの有効なトリプルに寄与し、二重にカウントしてはなりません。

 ## アルゴリズムのチュートリアル

 ### 1. 加法トリプルを数える

 修正します$a$そしてすべてを数えます$b$そのような$a + b \le n$。 与えられた$a$、$b$からの範囲$1$に$n - a$、貢献$\max(0, n - a)$有効なペア。 全体をまとめると$a$三角数構造が生成されます。 

### 2. 乗算トリプルを数える

 修正します$a$そして何個かを決定します$b$満足する$a \cdot b \le n$。 これは以下と同等です$b \le \lfloor n / a \rfloor$。 それぞれについて$a$、この数量を答えに追加します。 

これが機能する理由は、線形カットオフに帰着する加算とは異なり、乗算制約が固定の第 1 オペランドごとにきれいに因数分解されるためです。 

### 3. 結果を結合する

 両方の貢献度を合計します。 この時点で、すべての有効なペアが操作ごとに 1 回カウントされます。 

### 4. 二重カウントを削除する

 両方の条件が成立する交差点を減算します。 解決中$a + b = a \cdot b$与える$(a - 1)(b - 1) = 1$したがって、唯一有効な自然な解決策は次のとおりです。$(a, b) = (2, 2)$。 これはちょうど 1 つのトリプルに寄与します$(2, 2, 4)$なので、次の場合は 1 を減算します。$n \ge 4$。 

### なぜ効果があるのか

 有効なトリプルはすべて、加算または乗算を満たすかどうかによって一意に分類されます。 加算カウントはすべての線形和有効ペアを使い果たし、乗算カウントはすべての積有効ペアを使い果たします。 それらの交差はシングルトン集合であるため、包含-排他により、問題全体が 2 つの独立した 1 次元の合計と一定の補正に削減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

# additive pairs: sum_{a=1..n} max(0, n - a)
add = n * (n - 1) // 2

# multiplicative pairs: sum_{a=1..n} floor(n / a)
mul = 0
for a in range(1, n + 1):
    mul += n // a

# overlap correction: only (2,2) if n >= 4
overlap = 1 if n >= 4 else 0

print(add + mul - overlap)
```加算部分は閉形式の三角数公式を使用して計算され、反復が回避されます。 乗算部分は、除数に対する単一ループを介して計算されます。これは、$n \le 10^7$単純な整数演算のため、PyPy または最適化された CP Python では使用できません。 

両方のループが独立してペアをカウントするため、オーバーラップの減算が不可欠です。$(2,2)$、両方の方程式を満たす他のペアはありません。

 ## 特殊なケース

 のために$n = 1$、 のみ$(1,1,2)$または$(1,1,1)$乗法制約と加法制約が厳密に制限されているため、スタイル構造は正しく縮小されます。 このアルゴリズムでは、加算 = 0、乗算 = 1、重複なし、1 が生成されます。 

のために$n = 3$、唯一の交差が必要であるため、有効な重複はありません。$c = 4$、制限を超えています。 アルゴリズムは、この範囲内の減算を正しく回避します。 

のために$n \ge 4$、ペア$(2,2)$どちらの構造でも有効になります。 減算ステップでは重複を 1 つだけ削除します。また、他の整数解は存在しないため、$(a-1)(b-1)=1$、それ以上の修正は必要ありません。
