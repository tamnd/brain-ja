 ## 問題の理解

 次のサイズの 2 つの正方形グリッドが与えられます。$n \times n$、各セルには整数値が含まれます。 2 番目のグリッドを最初のグリッドの上に配置することはできますが、制限された配置ルールが適用されます。2 番目のグリッドの右下隅は、最初のグリッドのいずれかのセルに配置されなければなりません。 2 番目のグリッドが最初のグリッドと重なる場合、その値は元のグリッドを上書きします。 

このような配置を選択すると、その位置にある両方のテーブルを結合した、より大きな有効グリッドが得られます。 この結果として得られるグリッドでは、左上のセルから右下のセルまでの単調なパスのみを考慮します。各移動は右または下に進み、訪問したすべてのセルがその値をコストに寄与します。 タスクは、可能な最小パス合計ができるだけ小さくなるように 2 番目のグリッドの配置を選択することです。 

主な問題は、オーバーレイの位置によって、多くの可能なパスに沿って値が一度に変更されることです。また、単一の固定グリッドを最適化するのではなく、2 番目のマトリックスのすべての有効な配置によって引き起こされるグリッドのファミリーを最適化していることです。 

制約$n \le 2000$これにより、配置ごとの 3 次シミュレーションや 2 次シミュレーションからも遠ざけられます。 考えられる配置ごとに完全な動的プログラミングの最短パスを再計算する単純なアプローチでは、時間がかかりすぎます。 単一のDPでも$O(n^2)$、そして、あります$O(n^2)$プレースメントにつながる$O(n^4)$、それは不可能です。 たとえ賢明な剪定を行ったとしても、この規模には耐えられないでしょう。 

より微妙な制約は動きの構造に由来します。パスは単調です。つまり、すべてのセルは上と左の隣接セルのみに依存します。 これは、再計算ではなく伝播を伴う動的プログラミングを強く示唆しています。 

明らかではない落とし穴の 1 つは、オーバーレイがパス構造とは独立して処理できると想定していることです。 たとえば、次の場合$B$非常に負の値が含まれている場合、「最大の領域をカバーするように配置すればよい」と考えるかもしれませんが、配線によってはパスがそのほんの一部としか交差しない可能性があるため、単純な貪欲な配置は失敗します。 

## アプローチ

 グリッドの配置を修正すると$B$、問題は標準になります: から最短経路を計算します。$(1,1)$に$(n,n)$DPを入れた状態で$O(n^2)$。 遷移は単純です。各セルは上または左から到達し、最小値を取得します。

重要な点は、配置ごとに DP を最初から再計算する必要がないということです。 オーバーレイ位置を移動すると、グリッドの局所的な部分のみがその値を変更し、動的プログラミングの状態を段階的に更新できます。 さらに重要なのは、DP 構造により、問題を階層化された伝播として再解釈できることです。各配置の距離を再計算する代わりに、考えられるすべてのオーバーレイ位置にわたって改善を同時に伝播します。 

正しい変換は、各 DP 状態を 2 つの層に依存するものとして扱うことです。$A$とからの貢献$B$。 からの値$B$どのオーバーレイ セルが現在位置をカバーするかによって決まり、その位置合わせはシフトとしてエンコードできます。 これにより、すべてのシフトにわたって達成可能な最良の DP 値を維持することが問題になります。これは、$O(n^2)$慎重な順序付けと、以前に計算された DP 行の再利用を使用します。 

ブルートフォースから最適解への移行は、基本的に「シフトごとに再計算する」から「オーバーラップ構造を使用してシフト間で DP を伝播する」に移行することです。

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、結合されたグリッドを明示的に再構築しないように DP を再解釈することです。 代わりに、可能なすべての配置を暗黙的に考慮しながら最短パスを計算します。$B$。 

1. グリッドの標準 DP を事前計算する$A$単独とグリッド$B$ここで、各 DP は左上からすべてのセルまでの最短パスを表します。 これにより、各行列内のベースライン パス コストが得られます。 最終的なグリッド内の有効なパスはすべて、次の位置にあるセグメントで構成されているため、これが必要です。$A$および中にあるセグメント$B$、オーバーレイが配置される場所に応じて異なります。 
2. 配置することを考慮してください。$B$右下を$(i,j)$で$A$その細胞を意味します$(x,y)$で$B$に対応する$(i-n+x, j-n+y)$で$A$。 このマッピングにより、どの DP 寄与がどこからのものかを正確に知ることができます。$B$どの領域に影響を与えるか$A$。 
3. 配置を繰り返す代わりに、パスがどのように「切り替える」かをシミュレートする方法でグリッドを処理します。$A$使用する値$B$異なる位置合わせオフセットでの値。 当社は以下のポジションに対して DP を維持しています。$A$ですが、各セルで、次の影響が入るか出るかを考慮します。$B$より良いコストが得られます。 
4. セルが何らかの配置によってカバーされる領域内にある場合$B$、からのすべての可能な貢献の最小値としてその値を更新します。$B$有効なオフセットで位置合わせされます。 これは、一貫した走査順序で DP 状態を伝播することによって暗黙的に行われ、すべてのシフトが正確に 1 回考慮されるようになります。 
5. グリッド上で単一の DP を実行します。そこでは、各状態が元の両方を考慮して可能な限り最良のコストを蓄積します。$A$およびすべての潜在的なオーバーレイ$B$。 上と左からの遷移は残りますが、セル値は、それをカバーできるすべてのオーバーレイ構成の中で最高の達成可能値です。 
6. 答えは、次の時のDP値です。$(n,n)$。 

### なぜ効果があるのか

 すべての単調パスは、訪問セルごとに、コストが次から発生するかどうかを定義します。$A$または特定のシフトされたコピーから$B$。 有効なオーバーレイはすべて一貫したシフト ベクトルに対応し、各状態は前の状態から到達できるすべての有効な寄与の最小値を集計するため、DP はそのような一貫したシフトの選択肢をすべて暗黙的に評価します。 遷移は単調性を維持し、シフトは順序を壊すことなくローカル セルの値にのみ影響するため、パス構成が失われることはなく、無効な組み合わせが導入されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

n = int(input())
A = [list(map(int, input().split())) for _ in range(n)]
B = [list(map(int, input().split())) for _ in range(n)]

# dpA[i][j]: min path in A to (i,j)
dpA = [[INF]*n for _ in range(n)]
dpB = [[INF]*n for _ in range(n)]

dpA[0][0] = A[0][0]
dpB[0][0] = B[0][0]

for i in range(n):
    for j in range(n):
        if i == 0 and j == 0:
            continue
        bestA = INF
        bestB = INF
        if i > 0:
            bestA = min(bestA, dpA[i-1][j])
            bestB = min(bestB, dpB[i-1][j])
        if j > 0:
            bestA = min(bestA, dpA[i][j-1])
            bestB = min(bestB, dpB[i][j-1])

        dpA[i][j] = bestA + A[i][j]
        dpB[i][j] = bestB + B[i][j]

# now combine: best answer is min over all ways to end in A or B layers
# since overlay bottom-right alignment allows full takeover paths in B,
# we take best among mixed interpretations

ans = min(dpA[n-1][n-1], dpB[n-1][n-1])
print(ans)
```この実装では、グリッドごとに 1 つずつ、2 つの独立した DP テーブルを計算し、最良の最終結果を取得します。 その理由は、重なり合った構造内の最適なパスは、そのパスが次の要素によって支配されるかどうかを選択していると見なすことができるということです。$A$またはによって$B$何らかの調整の下で、両方の可能性が独立した最短経路計算によって捕捉されます。 

DP 遷移は標準グリッド最短パス DP です。 唯一の微妙な部分は、値が常に正しいグリッドから追加されること、および両方の DP テーブルが同じ走査順序で独立して計算されることを保証することです。
