 ## 問題の理解

 レジスタに格納されている N ビット 2 進数をインクリメントする可逆量子演算を実装するように求められます。 レジスタはリトルエンディアン形式で指定されます。つまり、最初の量子ビットが最下位ビットを表し、最後の量子ビットが最上位ビットを表します。 

演算は古典的な 1 モジュロの加算のように動作する必要があります。$2^N$、ただし量子状態に適用されます。 入力がバイナリ値の重ね合わせである場合、変換では振幅と可逆性を維持しながら、すべての基底状態に同時に 1 を追加する必要があります。 たとえば、混ざり合っている状態。$|3\rangle$そして$|1\rangle$の重ね合わせにならなければなりません$|0\rangle$そして$|2\rangle$モジュロ 4 で増分した場合。 

制約は微妙ですが重要です。測定値や任意の回転を使用することはできません。 X ゲートとその制御されたバリアントに制限されます。 これにより、量子ゲートを使用して実装された古典的な可逆論理の領域に私たちは押し込まれます。 

レジスタ サイズ N は、古典的な意味での複雑さの問題に影響を与えるような形で明示的に制限されていません。 代わりに、主な制約は構造的なものです。任意の N に対して機能し、可逆性を維持するユニタリーを構築する必要があるため、算術ショートカットや非可逆演算に依存することはできません。 

素朴な古典的な考え方では、レジスタを整数に変換し、1 を加算して、それを書き戻すことを提案します。 これは、測定が状態を崩壊し、禁止されるため、すぐに失敗します。 もう 1 つの誘惑的な間違いは、可逆的な方法でキャリー伝播を正しく処理せずに、「すべてのビットを反転して 1 つ追加」しようとすることです。 これは、すべて 1 の入力のような境界ケースで壊れます。 

不注意なロジックが失敗する最小限の例は、次のような状態です。$|11\rangle$N = 2 の場合。モジュロ 4 をインクリメントすると、次の結果が得られます。$|00\rangle$。 最下位ビットだけを反転すると、次のようになります。$|10\rangle$、これは間違いです。 すべてのビットを反転すると、次のようになります。$|00\rangle$、しかし、これは誤って最大値に対してのみ機能し、キャリーを使用して適切に構成されていない限り、可逆回路の中間状態間で正しく一般化されません。 

主な困難は、可逆ビット操作のみを使用してバイナリ インクリメントを実装することです。 

## アプローチ

 強引な古典的な解釈では、整数値をシミュレートし、1 を加算し、バイナリ表現を書き換えます。 概念的には、これはすべてのビットを読み取り、整数を計算し、加算を実行し、結果を書き戻すことによって機能します。 ただし、量子環境では、状態を読み取るには測定が必要であり、重ね合わせが破壊されるため、これは不可能です。 たとえ古典的なシミュレータを想像したとしても、このアプローチにはコストがかかります$O(2^N)$振幅ごとの構成であり、基本的に単一要件と互換性がありません。 

正しいアプローチは、バイナリ インクリメントが 1 の単なるリップル キャリー加算であることを認識することから生まれます。古典的な可逆ロジックでは、加算は、最下位ビットから上方にキャリーを伝播する制御された NOT 演算を使用して実装されます。 各ビットは、すべての下位ビットが 1 の場合にのみ反転します。これは、複数制御された X 操作のチェーンを使用して表現できます。 

問題の構造により、これは特に明確になります。1 を追加すると、最初の 0 ビットがキャリー チェーンを停止し、後続の 1 ビットがすべて 0 に反転することを意味します。これは、制御された X ゲートのシーケンスを使用して実装でき、前のすべてのビットが 1 であることを条件に各ビットが反転されます。 

重要な洞察は、キャリーを保存された値として明示的に計算する必要がまったくないということです。 代わりに、制御構造を使用して暗黙的にエンコードします。

 ## アルゴリズムのチュートリアル

 制御された X ゲートのカスケードを使用してインクリメント操作を構築します。 

1. この演算は、インデックス 0 の最下位ビットから開始して 2 進数に 1 を加算するものとして解釈されます。 

入力状態に関係なく、1 を追加すると常に最下位ビットが切り替わるため、最下位ビットは常に反転します。 
2. 最初の量子ビットに X ゲートを適用します。 これにより、加算の最初のステップであるビット 0 の切り替えが実装されます。 
3. 1 から N-1 までの後続の各ビット i について、0 から i-1 までのすべてのビットが 1 に等しい場合にのみ、ビット i を反転します。 

この状態はまさにキャリー到達位置ｉに相当する。 
4. マルチ制御 X ゲートを使用してこの条件を実装します。以前のすべての量子ビットが制御として機能し、量子ビット i がターゲットになります。 
5. これらの制御された反転を順番に適用して、キャリーの伝播が順番に保存されるようにします。 
6. 結果は、バイナリ増分法に一致する可逆変換です。$2^N$。 

### なぜ効果があるのか

 不変条件は、ビット i を処理した後、i よりも重要度の低いすべてのビットが 1 のモジュロを加算した結果を正しく表すことです。$2^{i+1}$。 反転前にすべての下位ビットが 1 だった場合、位置 i へのキャリーは正確に 1 になります。また、controlled-X 構造により、その条件下でビット i が正確に反転することが保証されます。 各ステップは可逆的であり、すでに確立された制御のみに依存するため、情報が失われることはなく、グローバルな変換は単一のままです。

```
namespace Solution {
    open Microsoft.Quantum.Arithmetic;
    open Microsoft.Quantum.Intrinsic;

    operation Solve (register : LittleEndian) : Unit is Adj+Ctl {
        let qubits = register!;
        let n = Length(qubits);

        // Flip least significant bit
        X(qubits[0]);

        // Propagate carry
        mutable controls = new Qubit[0];

        for i in 1 .. n - 1 {
            // Apply multi-controlled X using all previous bits as controls
            Controlled X(qubits[0..i-1], qubits[i]);
        }
    }
}
```最下位ビットに対する最初の X ゲートの後、制御された各 X は、すべての下位ビットが 1 の場合にのみビット i が反転することを保証します。これはまさにバイナリ キャリー条件です。 スライス`qubits[0..i-1]`リトルエンディアン構造を自然にキャプチャし、正しい順序付けを保証します。 

微妙な点は、キャリー ビットを明示的に保存しないことです。 制御構造自体がキャリー ロジックをエンコードし、可逆性を維持します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、オール 1 レジスタです。 N = 3 の場合、次のように入力します。$|111\rangle$にマッピングする必要があります$|000\rangle$。 アルゴリズムは X をビット 0 に適用し、$|011\rangle$、その後、制御された操作を通じてキャリーを伝播します。 各上位ビットは、制御時に下位ビットがすべて 1 であったことを認識するため、順次反転します。 これにより、可逆性を失うことなく正しいラップアラウンドが生成されます。 

もう 1 つのエッジ ケースは、1 の中に 1 つのゼロが埋め込まれている場合です。$|11011\rangle$。 キャリーは最初の 0 に達するまで伝播し、その時点でビットが反転し、すべての下位ビットが 0 にリセットされます。 制御された構造により、プレフィックスにゼロが現れると制御条件が失敗し、上位ビットが変更されないため、伝播が自然に停止することが保証されます。
