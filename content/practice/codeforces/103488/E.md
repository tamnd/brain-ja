 ## 解決策
 ## 問題の理解

 配列と固定ウィンドウ サイズが与えられます。 1 回の操作で、正確な長さの連続したセグメントを選択します`k`そして、そのセグメント内のすべての要素を、そのセグメント内の現在の最小値で上書きします。 この操作を繰り返すと配列が変更されます。目標は、できるだけ少ない操作ですべての要素を等しくするか、それが不可能であると判断することです。 

重要な問題は、この操作が単純な置き換えではないことです。 これは選択したウィンドウ内の現在の最小値に依存するため、セグメントに書き込まれる値は、前の操作で配列が変更されるにつれて変化します。 これにより、より小さい値が左または右に「広がる」伝播効果が作成されますが、正確なサイズのウィンドウを通してのみ可能です。`k`。 

制約は大きく、すべてのテスト ケースの合計の長さは最大です。`10^5`。 これにより、すべての部分配列に対する演算の二次シミュレーションが直ちに除外されます。 すべてのウィンドウを繰り返し試行するソリューションであっても、各操作が`k`要素が多く、実行可能な操作の数も多くなります。 

微妙なエッジケースが現れるのは、`k = 1`。 各操作は 1 つの要素のみに触れ、それをそれ自体に置き換えるので、配列は決して変更されません。 配列がまだ定数でない場合、答えは次のようになります。`-1`。 

もう 1 つの重要なエッジケースは次のような場合です。`k = n`。 可能な操作は 1 つだけです。配列全体を取得し、すべてを最小値に設定します。 これは、配列がすでに定数でない限り、常に 1 ステップで成功します。配列がすでに定数である場合、0 ステップは必要ありません。 

ウィンドウの制約により配列の他の部分に「到達」できない位置に最小値が孤立している場合、あまり明白ではない障害モードが発生します。 たとえば、最小値が length を使用して配列全体をカバーするように拡張できない領域にのみ存在する場合、`k`Windows では、値が存在しても回答が不可能になります。 

## アプローチ

 ブルートフォース戦略では、プロセスを直接シミュレートします。 各ステップで、有効な長さのセグメントをすべてスキャンします。`k`を選択し、その最小値を計算して、更新を適用します。 収束するまでこれを繰り返すと、許可された操作に正確に従っているため、原則として正しい答えが得られます。 

問題は、各操作で次のサイズのウィンドウをスキャンする必要があることです。`k`、最大で必要になる場合があります`O(n)`最悪の場合の運用。 これにより、全体的に次のような複雑さが生じます。`O(n^2)`テストケースごとに、これは非常に遅すぎます。`n`到達する`10^5`。 

重要な観察は、操作が常にウィンドウ内の最小値を伝播するということです。つまり、値は減少するか同じままであり、増加することはありません。 これは、配列の最終値が初期配列のグローバル最小値でなければならないことを意味します。 そこで問題は、固定長の間隔を使用して、この最小値を配列全体にどのように分散させるかということです。 

操作をシミュレーションする代わりに、逆に考えることができます。 私たちは、最終的にはすべてのポジションが、最小値がすでにグローバル最小値である何らかのウィンドウでカバーされるようにしたいと考えています。 ポジションにグローバル最小値が含まれると、その後の操作でその値をさらに拡散するソースとして機能します。 

これにより、問題は固定長の間隔にわたるカバレッジと到達可能性の問題に変わります。ここで唯一有用な状態は、位置にすでにグローバル最小値が含まれているかどうかです。 プロセスは貪欲になります。進行に貢献できる最も右の有効なウィンドウを常に使用して、左から右にセグメントを「アクティブ化」しようとします。 

この貪欲な構造は、リニア スキャン ソリューションにつながります。

 ## アルゴリズムのチュートリアル

 1. 最小値を計算する`mn`配列の。 最終的な配列がそうでない場合は、`mn`、どの操作も値を増やすことはできません。`mn`最終目標として考えられるのはこれだけです。 これにより、目標はすべての要素を次と等しくすることになります。`mn`。 
2. もし`k == 1`、すべての要素が既に次と等しいかどうかを確認します。`mn`。 そうでない場合は、返品してください`-1`。 これは、ウィンドウ サイズが 1 の場合、値を変更する操作がないためです。 
3. もし`k == n`、 戻る`1`すべての要素がまだ完了していない場合`mn`、それ以外の場合は戻ります`0`。 すべてをグローバル最小値に等しくするには、配列全体に対する 1 回の操作で十分です。 
4. 該当するすべての位置を特定します。`a[i] == mn`。 これらの位置は、値を伝播できる唯一の使用可能なアンカーです。 
5. アレイを左から右にスキャンし、確実に移動できる最も遠い位置を維持します。`mn`すでに到達可能なアンカーを使用します。 それぞれのポジションで`i`、範囲内にアンカーが存在するかどうかを確認します`[i - k + 1, i]`。 このようなアンカーが存在する場合、次で終了する操作を実行できます。`i`伝播する`mn`まで`i + k - 1`。 
6. この到達可能な境界を貪欲に拡張し続けます。 延長するたびに 1 つの操作としてカウントされます。 どこかの時点でポジションが`i`既知の要素を含む有効なウィンドウでカバーすることはできません`mn`、その場合は続行不可能なので戻ります`-1`。 

### なぜ効果があるのか

 重要な不変条件は、操作を実行するたびにグローバル最小値のみを拡散するということです。 を含まないセグメント`mn`より小さい値を生成できないため、新しい状態に到達するのに役立ちません。 したがって、意味のある遷移は、すでに含まれている領域を拡張するものだけです。`mn`。 

すべての操作は固定長の連続ブロックに影響を与えるため、各操作が現在到達可能なプレフィックスを最大限に拡張するように、最適なシーケンスを再配置できます。 操作が境界を可能な限り拡張しない場合は、合計カウントを増やさずに境界を拡張する操作にシフトまたは置き換えることができます。 これにより、貪欲な戦略によって最小限の操作が生成されるか、不可能性が正しく検出されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        mn = min(a)

        if k == 1:
            if all(x == mn for x in a):
                out.append("0")
            else:
                out.append("-1")
            continue

        if k == n:
            if all(x == mn for x in a):
                out.append("0")
            else:
                out.append("1")
            continue

        # positions where value equals global minimum
        has = [0] * n
        for i in range(n):
            if a[i] == mn:
                has[i] = 1

        # prefix sum to query existence in window
        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + has[i]

        def window_has(l, r):
            if l < 0:
                l = 0
            return pref[r + 1] - pref[l] > 0

        ops = 0
        i = 0

        while i < n:
            if window_has(i - k + 1, i):
                ops += 1
                i += k
            else:
                i += 1

        out.append(str(ops))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策では、まずターゲット状態を全体的な最小値に引き下げます。 プレフィックス合計配列を使用すると、有効なウィンドウに最小値が少なくとも 1 回含まれるかどうかを定期的にチェックできます。 メインループは左から右にスキャンし、前方に貪欲に「ジャンプ」します。`k`有用な操作を実行できる有効なウィンドウが見つかったときはいつでも。 各ジャンプは 1 つの操作に対応します。 

重要な実装の詳細はウィンドウ チェックです。最小値を再計算したり、操作をシミュレートしたりする代わりに、グローバル最小値がすでに存在する場所のみを追跡します。これは、それらの位置のみが有用な伝播を開始できるためです。

 ## 特殊なケース

 いつ`k = 1`、すべての操作は単一の要素をそれ自体で書き換えるだけなので、変更は起こりません。 のような入力の場合`[1, 2, 1]`、スキャンはすぐに不均一性を検出し、戻ります。`-1`なぜなら、ウィンドウは何も伝播できないからです。 

いつ`k = n`、配列全体をカバーする唯一の可能なウィンドウです。 のために`[1, 2, 3, 1, 1]`、最小値は`1`、1 回の操作ですべてが置き換えられます。`1`。 アルゴリズムは直接返します`1`ウィンドウをスキャンせず、唯一の有効な移動シーケンスと一致します。 

最小値がまばらだが、重複するウィンドウを通じて到達できる場合。`[3, 4, 100, 5, 3]`と`k = 3`の場合でも、各最小値はそれを伝播できる少なくとも 1 つの有効なウィンドウ内にあるため、アルゴリズムは引き続き成功します。 貪欲スキャンにより、たとえ遠く離れていても、両端が確実にカバレッジに寄与します。
