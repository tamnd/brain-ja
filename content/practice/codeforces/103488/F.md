 ## 解決策
 ## 問題の理解

 いくつかのセルが壁で、他のセルは空である格子状迷路が与えられています。 文字はマークされた固定セルから始まります`H`時間ゼロで、1 分ごとに 4 つの隣接するセルのいずれかに移動するか、その場に留まることができます。 壁によって動きが妨げられている。 同時に、時間から1分ごとに目標位置が明らかになります`0`時間まで`k-1`、そして時間に`i`剣は指定されたセルにあります`(x_i, y_i)`。 

課題は、剣がそこにあるのとまったく同じタイミングでキャラクターがセルに到達できるかどうかを判断し、到達できた場合は最も早い時刻を報告することです。 

重要な構造は、プレイヤーと剣の両方が時間の経過とともに、まったく異なる方法で進化するということです。 プレイヤーは壁によって制限された単位速度のマンハッタン トランジションでグリッド上を移動しますが、剣は既知の一連の位置にテレポートするだけです。 

グリッド サイズは最大 100 x 100 で、各テストの合計セル数は最大 10,000 です。 最大 100 のテスト ケースにわたって、テストごとの最短パス計算は実行可能ですが、慎重に実装すれば、k のタイム ステップごとの 2 次関数はすべて合格します。 

微妙な点は、剣が壁に現れる可能性があるということです。つまり、剣の位置に到達するためには、その時点でセルが歩ける必要はなく、プレイヤーがそこに立っていれば十分です。 ただし、プレイヤーは壁を占領できないため、それらの位置はグリッド内の壁でない場合にのみ有効なターゲットになります。 

2 番目に重要な点は、待機が許可されていることです。 これは、パリティ制約が到達可能性を妨げないことを意味します。 時間はいつでも引き延ばすことができます。 

3 番目のエッジ ケースは、剣が時間 0 で開始位置に表示される場合であり、これは直ちに受け入れられる必要があります。 

## アプローチ

 強引なアイデアは、時間を段階的にシミュレートすることです。 毎回`t`、プレーヤーが到達できるかどうかを再計算できます。`(x_t, y_t)`まさに`t`から始まる動き`H`。 これは、タイム ステップごとに BFS または最短パスの計算を実行することを意味し、おおよそ次のような複雑さが生じます。`k * n * m`テストごとに。 最悪の場合はこうなります`10^4 * 10^4 = 10^8`テストあたりの操作数が多く、最大 100 のテスト ケースを掛けると遅すぎます。 

重要な観察は、最初から到達可能性は剣の位置に依存しないということです。 からの最短経路距離が 1 つだけ必要です。`H`グリッド内のすべてのセルに。 これらの距離がわかったら、プレイヤーがその時点で剣に到達できるかどうかを確認します。`t`単純な条件になります: 最短経路距離は最大でも`t`、その場で待機することに余分な時間が費やされる可能性があるためです。 

これにより、繰り返しのグラフ検索による問題がグリッド上の 1 つの BFS に軽減されます。 その後、剣のタイムラインを 1 回スキャンして、条件が当てはまる最も早い時間を見つけます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 時間ごとに BFS を再計算する | O(k・n・m) | O(n・m) | 遅すぎる |
 | シングル BFS + スキャン | O(n · m + k) | O(n・m) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、からの最短距離を計算します。`H`グリッド上の標準 BFS を使用してすべてのセルに送信します。 

1. 開始セルを見つけます`H`距離行列を無限値で初期化し、開始セル距離をゼロに設定します。 これは、移動せずに時間ゼロから開始することをエンコードします。 
2.BFS を実行します。`H`四方向に渡って。 有効な非壁セルに初めて到達するたびに、その距離を BFS 層の深さとして割り当てます。 これにより、その距離がそのセルに到達するために必要な最小移動回数であることが保証されます。 
3. BFS が完了すると、各セルがそこに留まるために必要な最小限の時間が確保されます。 
4. 毎回`t`から`0`に`k-1`、剣の位置を読む`(x_t, y_t)`グリッドセルが壁ではないかどうか、また、`dist[x_t][y_t] ≤ t`。 両方の条件が満たされれば、遅くとも時間内にはそのセルに到達できます`t`そして必要に応じて待ちます。 
5. 最初のそのときが答えです。 条件を満たす時間がない場合は出力`"NO"`。 

距離と時間が完全に等しい必要がない理由は、待機が常に許可されているためです。 最短経路に 3 歩かかりますが、剣が時間 5 に現れる場合、時間 3 で剣に到達し、2 分待つことができます。 

### なぜ効果があるのか

 BFS は次のことを保証します。`dist[v]`任意のセルに到達するために必要な最小移動数です`v`最初から。 同時にセルへの任意の有効な軌道`t`少なくとも次のもので構成されている必要があります`dist[v]`移動に加えて、オプションの待機ステップも追加されます。 したがって、時間ごとの到達可能性`t`と同等です`dist[v] ≤ t`。 剣の位置は時系列にチェックされるため、最初にこの条件が成立した時点が最も早いキャプチャの瞬間となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, m = map(int, input().split())
    grid = [list(input().strip()) for _ in range(n)]
    
    sx = sy = -1
    for i in range(n):
        for j in range(m):
            if grid[i][j] == 'H':
                sx, sy = i, j

    dist = [[-1] * m for _ in range(n)]
    q = deque()
    q.append((sx, sy))
    dist[sx][sy] = 0

    dirs = [(1,0), (-1,0), (0,1), (0,-1)]

    while q:
        x, y = q.popleft()
        for dx, dy in dirs:
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m:
                if grid[nx][ny] != '#' and dist[nx][ny] == -1:
                    dist[nx][ny] = dist[x][y] + 1
                    q.append((nx, ny))

    k = int(input())
    for t in range(k):
        x, y = map(int, input().split())
        x -= 1
        y -= 1

        if 0 <= x < n and 0 <= y < m and grid[x][y] != '#':
            if dist[x][y] != -1 and dist[x][y] <= t:
                print("YES", t)
                return

    print("NO")

if __name__ == "__main__":
    solve()
```BFS セクションは開始位置からの完全な距離のマップを構築し、壁を通行不能として扱います。 キューは距離が増加する順序でセルを処理するため、最初にセルに距離を割り当てるのが最適です。 

次に、クエリ ループは待機ロジックから導出された条件を直接チェックします。 入力のインデックスが 1 であるのに対し、グリッドは内部的に 0 のインデックスが付けられているため、入力座標から 1 を減算することが重要です。 

早めの返却により、最も早い有効な時間に停止することが保証されます。 

## 実用的な例

 開始点がオープンエリアの近くにあり、剣がすぐに同じ位置に表示される単純なグリッドを考えてみましょう。

ここで、最初は剣が届かなかったが、後で届くようになった場合を考えてみましょう。 

| t | 剣 (x,y) | 距離[x][y] | 条件距離 ≤ t | 結果 |

## テストケース```python
import sys, io
from collections import deque

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = []
    def input():
        return sys.stdin.readline()
    
    def solve():
        n, m = map(int, input().split())
        grid = [list(input().strip()) for _ in range(n)]
        
        sx = sy = -1
        for i in range(n):
            for j in range(m):
                if grid[i][j] == 'H':
                    sx, sy = i, j

        dist = [[-1]*m for _ in range(n)]
        q = deque()
        q.append((sx, sy))
        dist[sx][sy] = 0

        dirs = [(1,0),(-1,0),(0,1),(0,-1)]

        while q:
            x,y = q.popleft()
            for dx,dy in dirs:
                nx,ny = x+dx,y+dy
                if 0<=nx<n and 0<=ny<m:
                    if grid[nx][ny] != '#' and dist[nx][ny] == -1:
                        dist[nx][ny] = dist[x][y] + 1
                        q.append((nx,ny))

        k = int(input())
        for t in range(k):
            x,y = map(int, input().split())
            x-=1;y-=1
            if 0<=x<n and 0<=y<m and grid[x][y] != '#':
                if dist[x][y] != -1 and dist[x][y] <= t:
                    out.append(f"YES {t}")
                    return
        out.append("NO")

    solve()
    return "\n".join(out)

# minimum grid
assert run("1 1\nH\n1\n1 1\n") == "YES 0", "min case"

# unreachable
assert run("2 2\nH#\n##\n2\n2 2\n1 2\n") == "NO", "blocked"

# reachable later
assert run("2 2\nH.\n..\n3\n2 2\n2 2\n2 1\n") == "YES 2", "delayed"

# obstacle maze
assert run("3 3\nH..\n###\n..#\n3\n1 3\n3 1\n3 3\n") == "NO", "walls block"

 ## 特殊なケース

 よくある失敗例は、待機が許可されていることを忘れていることです。 剣の時間より早くセルに到達できる場合でも、正しいソリューションはそれを受け入れます。 たとえば、次の場合`dist = 2`そして時が来れば剣が現れる`5`、答えは次の時点で有効です`t = 5`、不一致により拒否されません。 

もう 1 つのエッジケースは、剣が壁のセルに表示される場合です。 BFS は通常どおりに距離を計算する必要がありますが、プレーヤーが壁を占有することができないため、チェックでは壁を拒否する必要があります。 正しい実装では明示的に検証されます。`grid[x][y] != '#'`。 

最後に、時間ゼロで剣として表示される開始セルは、BFS を仮定する前に処理する必要があります。 以来`dist[start] = 0`、条件`dist <= 0`正しく即時の成功をトリガーします。
