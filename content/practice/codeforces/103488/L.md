 ## 解決策
 ## 問題の理解

 参照文字列が与えられます`s`長さの`n`、および上限`m`別の文字列の長さについて`t`私たちが構築することを許されているということ。 タスクは文字列を生成することです`t`英小文字の上に、その長さが最大で`m`、厳密に辞書編集的には以下よりも小さくなります。`s`。 このようなすべての有効な文字列の中で、辞書編集上最大の文字列が必要です。 

重要な点は、同時に 2 つの方向で最適化を行っているということです。 私たちが欲しいのは`t`辞書順で可能な限り大きくする必要がありますが、依然として厳密に小さいままです。`s`。 同時に、最大の長さを調整することができます。`m`、小さい文字で長さを増やすと、制約に違反せずに辞書編集上の値が増加する場合があります。 

ここで使用される辞書編集順序は標準的な順序です。2 つの文字列が 1 文字ずつ比較され、最初の不一致によって順序が決まります。 一方の文字列が他方の文字列のプレフィックスである場合、短い方が小さくなります。 

制約により許可されるのは、`n`そして`m`1e6まで。 候補文字列を列挙しようとする解決策は、すべての文字列を最大の長さまで反復することさえできるため、直ちに実行不可能になります。`m`指数関数的になるでしょう。 候補構築ごとの線形スキャンでも慎重に制限する必要があるため、解は基本的に O(n) または最悪でも O(n log アルファベット) でなければなりません。 

いくつかのエッジの状況が重要です。 

もし`s`から始まる`'a'`何度も繰り返した、と言う`s = "aaaa"`、その場合、答えは次のようになります。`"aaa"`または`"aa..."`に応じて`m`で始まる文字列はすべて`'a'`等しいかそれを超える危険性があり、それより大きな文字は直ちに制約に違反します。 

もし`s`のような性格を持っています`'b'`あるいは早い段階でそれ以上のことを言う`s = "caaaa"`、その後、多くの場合、その位置を次のような小さな文字に置き換えることができます。`'b'`または`'a'`そしてサフィックスを自由に最大化します。 

各位置を局所的にのみ見て、できるだけ長く同じ状態を維持しようとする単純な貪欲は、厳密な減少の最初の点と接尾辞の結果を正しく処理できない場合に失敗する可能性があります。 

## アプローチ

 強引なアイデアは、次の長さのすべての文字列を構築することです。`m`、辞書編集的に以下より小さいかどうかを確認します。`s`、その中で最大のものを取ります。 長さ制限も`m`、これは$26^m$、それは不可能です。 

もう少し素朴なアイデアは、左から右に 1 文字ずつ答えを構築し、常に可能な限り最大の文字を試し、次と比較することで実現可能性をチェックすることです。`s`。 ただし、拡張候補ごとに完全な比較をシミュレートすると、さらに次の要素が得られます。`O(n)`チェックごとに、二次関数の動作につながります。 

重要な観察は、1 つの構造イベントのみを考慮する必要があるということです。つまり、構築された文字列が厳密に よりも小さくなる最初の位置です。`s`。 その位置の前に私たちは一致することを余儀なくされます`s`まさに、できるだけ大きく保ちたい場合に限ります。 最初の不一致では、より厳密に小さい文字を選択します。`s[i]`そして、その時点以降は、文字列の残りの部分を独立して自由に最大化できます。`s`。 

これにより、問題は分割点のスキャンに変換されます。 ポジションごとに`i`で最初の違いを作ることを検討できます。`i`、一致することを意味します`s[0..i-1]`、次に最大の文字を選択します`< s[i]`位置にある`i`、残りを埋めます（長さまで）`m`） と`'z'`。 また、次のプレフィックス全体と一致する可能性も考慮します。`s`適切なプレフィックスは辞書編集的にも小さいため、文字列を短くします。 

最適な答えとは、そのようなすべての選択肢の中で最良のものです。

 ## アルゴリズムのチュートリアル

 可能な限り最良の構造を追跡しながらストリングを加工します。 

1. あらゆる立場を考慮する`i`から`0`に`n-1`潜在的な最初の不一致点として。 この位置では、厳密に より小さい文字を選択する必要があります。`s[i]`。 そのようなキャラクターの中で最も優れているのは、`s[i] - 1`辞書順を最大化するということは、文字列を小さく保ちながら最大の有効な文字を選択することを意味するためです。 
2. ポジションごとに`i`、から構成される候補文字列を形成します。`s[0:i] + (s[i]-1) + 'z' * (m - i - 1)`、 に限って`i < m`。 これにより、位置に厳密な不平等を強制した後も、可能な限り大きく保つことができます。`i`。 
3. 最初のパラメータ内に不一致が導入されない場合も考慮します。`n`文字。 その場合、厳密に以下よりも小さくする唯一の方法は、`s`は適切なプレフィックスである必要があります`s`, そこで考えます`s[0:k]`みんなのために`k < n`そして`k ≤ m`。 
4. すべての有効な候補の中から、辞書編集的に最大のものを選択します。 
5. 最適な候補を返します。 

を埋める背後にある理由`'z'`つまり、最初の異なる位置で文字列が辞書編集的に小さいことがすでに確認されていると、それ以降の位置はすべて、次の文字列との比較に影響を与えなくなります。`s`, したがって、サフィックスを貪欲に最大化します。 

### なぜ効果があるのか

 有効なソリューションには、それが異なる最初のインデックスが必要です。`s`、または厳密なプレフィックスである必要があります。 最初の異なるインデックスで`i`、文字は厳密に以下より小さくなければなりません`s[i]`、可能な最大値より小さい選択は、実現可能性を得ることなく結果を悪化させるだけです。 それ以降、サフィックスは以下に関して制約がありません。`s`、だから選択する`'z'`どこでも辞書編集上の価値を最大化します。 考えられるすべての最初の不一致位置と接頭辞のケースを列挙するため、すべての有効な構造をカバーします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = input().strip()

    best = ""

    # Case 1: prefix-only answers
    limit = min(n, m)
    for k in range(limit):
        cand = s[:k]
        if cand > best:
            best = cand

    # Case 2: introduce first mismatch at position i
    for i in range(min(n, m)):
        if s[i] == 'a':
            continue
        prefix = s[:i]
        c = chr(ord(s[i]) - 1)
        rem_len = m - i - 1
        if rem_len < 0:
            continue
        cand = prefix + c + ('z' * rem_len)
        if cand > best:
            best = cand

    print(best)

if __name__ == "__main__":
    solve()
```コードは最初にすべてのプレフィックス オプションを試行します。`s`自動的に小さくなります。 これは、最適な答えが変更を回避する場合をカバーします。`s`代わりにそれを短くします。 

次に、厳密な減少の最初のポイントとしてすべてのポジションを試します。 位置で`i`、可能な限り最高のキャラクターを選択します`s[i] - 1`有効な場合は、次のように貪欲に拡張します。`'z'`。 境界チェック`m - i - 1 < 0`長さの制約を超えないようにします。 

微妙な点は、位置に複数の小さな文字を考慮する必要がないことです。`i`より小さい文字はすべて`s[i]-1`厳密に言えば、より悪い辞書編集結果が生成されます。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`s`完全にから成る`'a'`。 その状況では、どの位置も不一致構造内の文字を減らすことはできません。 有効な答えは厳密なプレフィックスのみです。 不一致ループはすべての位置をスキップし、プレフィックス候補のみが残るため、アルゴリズムはこれを自然に処理します。`s[:m-1]`もし`m < n`。 

もう 1 つのエッジケースは次のような場合です`m > n`。 ここでは、プレフィックスのみの候補が長さに達することはありません`n`、不一致構造はそれを超えて広がる可能性があります`n`安全に。 サフィックスが埋め込まれているため、`'z'`、アルゴリズムは依然として、許容される最大長の有効な候補を生成します。 

最後の微妙なケースは、最適なソリューションが非常に短いプレフィックスである場合です。 たとえば、次の場合`s = "baaa"`そして`m = 4`、プレフィックス`"b"`は有効ですが、辞書編集上の比較ルールによっては、一部の不一致構造を超える可能性があります。 これらは明示的にスタンドアロン候補として考慮されるため、プレフィックス ループにより、これらが見逃されないことが保証されます。
