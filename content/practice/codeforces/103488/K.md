 ## 解決策
 ## 問題の理解

 各ノードが爆弾を表し、各爆弾に色が付いているグラフが与えられます。 エッジは爆弾間の接続を表します。 選択した爆弾で爆発が始まると、それは広がる可能性がありますが、それは非常に特殊な条件下でのみです。爆弾は、隣の爆弾がすでに爆発しており、両方の爆弾がその端に沿って同じ色を共有している場合にのみ隣の爆弾をトリガーできます。 

追加のひねりがもう 1 つあります。 爆発を開始する場所を選択する前に、最大 1 つの爆弾を任意の色に変更することができます。 その後、点火する開始爆弾を 1 つだけ選択します。 その後、爆発は上記のルールに従って決定論的に伝播し、有効な伝播を通じて到達可能になったすべての爆弾は爆発したと見なされます。 課題は、最終的に爆発する爆弾の数を最大化することです。 

構造的な観点から見ると、グラフのエッジは、両方の端点が同じ色を共有する場合にのみ伝播に役立ちます。 これは、単一ノードの色を戦略的に変更して、以前は別々だった領域をマージできるという事実を除いて、各色の内部の動作がほぼ独立していることをすぐに示唆しています。 

制約は最大 30 万個のノードとエッジに及ぶため、各開始ノードまたは各再色の選択に対して個別に爆発プロセスをシミュレートしようとするソリューションは除外されます。 Anything closer to quadratic behavior will fail immediately, so the solution must rely on precomputed structure of the graph.

 欲張って増殖を考えると微妙な失敗例が出てきます。 たとえば、同じ色のノードの最大の連結コンポーネントを選択することが常に最適であると仮定する場合があります。 単一ノードの色を変更すると複数のコンポーネントがマージされる可能性があるため、これは誤りです。 

色が A、B、A である単純なチェーン 1-2-3 を考えてみましょう。色を変更しないと、大きな伝播は発生しません。 しかし、ノード 2 を A に再カラーすると、カラー A の伝播ルールに基づいて、突然 3 つのノードすべてが 1 つの接続された構造として動作します。 A naive “largest component” approach would miss this interaction entirely.

 もう 1 つのよくある間違いは、開始爆弾が複雑な意味で重要であると想定することです。 実際には、最終的な到達可能な構造を修正すると、開始ノードはいつでもその内部で選択できるため、空ではない到達可能なセットを選択する必要がある以上に最終的なサイズを制限することはありません。 

## アプローチ

 A brute-force approach would try every possible starting bomb and every possible recoloring choice. 各構成について、同じ色のエッジに制限された BFS または DFS を使用して伝播プロセスをシミュレートします。 各シミュレーションは n + m で線形であり、開始爆弾には n 個の選択肢があり、色変更には n 個の選択肢があります (何も色を変更しないオプションを含む)。 これにより、およそ O(n(n + m)) が得られますが、これは 3 × 10^5 では実現不可能です。 

重要な観察は、各色の内部の伝播が、その色によって引き起こされるサブグラフの連結成分によって支配されるということです。 再着色をしばらく無視すると、すべてのカラー クラスが接続されたコンポーネントに分割され、各コンポーネントは原子単位として動作します。つまり、その中のいずれかのノードがアクティブ化されると、最終的にはコンポーネント全体がアクティブ化されます。 

これにより、問題は個々のノードではなくコンポーネント サイズに関する推論に集約されます。 

次に、再着色操作を紹介します。 ノード v を何らかの色 c に再色付けすると、v は、v に隣接する色 c のすべてのコンポーネント間のブリッジとして機能します。生のノードを扱う代わりに、再びすべてをコンポーネントに還元します。つまり、どのカラーコンポーネントが v に隣接しているかだけを考慮します。 

各ノード v とその隣接ノードに表示される各色 c について、v を c に再色付けすると、v に接する色 c のすべての個別のコンポーネントと v 自体をマージできます。 結果のサイズは、v がまだこれらのコンポーネントの一部ではない場合、これらのコンポーネント サイズに 1 を加えた合計になります。

これは、色ごとにすべての接続コンポーネントを事前計算し、それらのサイズを保存し、ノードごとに隣接コンポーネントの識別子によってグループ化された寄与を集約するという戦略を示唆しています。 次数の合計は m 単位で線形であるため、隣接リストの反復処理は十分効率的です。 

また、ベースラインの答えを、色を変更せずにすべての色にわたる最大コンポーネント サイズとして保持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n(n + m)) | O(n + m) | 遅すぎる |
 | コンポーネントの圧縮 + 1 回の再カラー マージ | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 両方のエンドポイントが同じ色を持つエッジに限定してグラフ トラバーサル (DFS または BFS) を実行することにより、色ごとに個別に連結コンポーネントを構築します。 これにより、色によって引き起こされる各サブグラフがコンポーネントに分割されます。 これを行う理由は、単一色の内部で、爆発動作が接続された各領域を単一の単位として扱うためです。 
2. すべてのノードにコンポーネント識別子を割り当て、各コンポーネントのサイズを保存します。 これにより、後で到達可能性を繰り返し再計算するのではなく、ノードのグループを単一の重み付けされたオブジェクトとして扱うことができます。 
3. すべてのコンポーネントにわたる最大コンポーネント サイズとしてベースラインの答えを計算します。 これは、再色付けを使用しないか、再色付けしても何も改善されない場合に相当します。 
4. 各ノード v について、それを再色付けされる可能性のあるノードとみなします。 v を何らかの色 c に再着色した場合に何が起こるかを評価したいと考えています。 そのために、v のすべての近傍を検査し、それらをコンポーネント識別子によってグループ化しますが、各固定色 c 内のみに限定します。 
5. v に隣接する色 c ごとに、v に隣接する色 c の個別のコンポーネント ID のセットを収集します。それらのコンポーネント サイズを合計し、v 自体に 1 を加算します。 これは、v が c に色変更された場合に作成されるマージされた構造を表します。 
6. このようなすべての構成にわたってグローバル最大値を維持します。 最終的な答えは、ベースライン コンポーネントとすべての再色ベースのマージの間の最大値です。 

重要な効率性の考え方は、隣接ベースの集計を構築するときに各エッジが一定の回数処理されるということです。そのため、すべてのノードを潜在的なブリッジと見なしても、二次的な方法で色ごとに重い作業を重複させることはありません。 

### なぜ効果があるのか

 このアルゴリズムは、固定色内では、爆発の到達可能性がその色の誘導サブグラフの接続性と正確に同等であるという不変式に依存しています。 単一ノードの色変更は、そのノードを介して以前に分離されていた同じ色のコンポーネントを潜在的にマージすることによってのみ接続に影響を及ぼし、他の形式の長距離相互作用を作成することはできません。 したがって、到達可能なすべての爆発セットは、単一のコンポーネント、または 1 つの色変更されたブリッジ ノードを介して接続されたコンポーネントの結合に正確に対応し、アルゴリズムはそのようなすべての結合を徹底的に評価します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    c = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    comp_id = [-1] * n
    comp_size = []

    sys.setrecursionlimit(10**7)

    def dfs(start, cid):
        stack = [start]
        comp_id[start] = cid
        cnt = 0
        col = c[start]
        while stack:
            u = stack.pop()
            cnt += 1
            for v in g[u]:
                if comp_id[v] == -1 and c[v] == col:
                    comp_id[v] = cid
                    stack.append(v)
        return cnt

    cid = 0
    for i in range(n):
        if comp_id[i] == -1:
            comp_size.append(dfs(i, cid))
            cid += 1

    best = max(comp_size) if comp_size else 1

    for v in range(n):
        by_comp = {}
        for u in g[v]:
            cid_u = comp_id[u]
            if cid_u == -1:
                continue
            by_comp[cid_u] = comp_size[cid_u]

        for val in by_comp.values():
            best = max(best, val + 1)

    print(best)

if __name__ == "__main__":
    solve()
```コードはまず、色で接続された各領域をコンポーネントに圧縮し、そのサイズを保存します。 DFS は、色が一致するエッジに沿ってのみ拡張するため、同じコンポーネントに異なる色が混ざることがなくなります。 

その後、カラー ターゲティングを使用してすべての再カラーの選択肢を明示的に試す代わりに、有益な再カラーは 1 つのノードを介して複数の隣接するコンポーネントを効果的に接続するという観察を利用します。 各ノードについて、隣接するコンポーネントを調べ、最適なマージ サイズを計算します。 の`+1`色が変更されたノードがブリッジとして機能します。 

実装の微妙な点は、第 2 フェーズでは実際に色を追跡する必要がないことです。 コンポーネントは同じ色内でのみ構築されているため、コンポーネント ID はすでに色分解をエンコードしています。 

## 実用的な例

 ### 例 1

 小さなグラフを考えてみましょう。 

入力:```
5 4
1 1 2 2 2
1 2
2 3
3 4
4 5
```これにより、色が相互作用を分割するチェーンが形成されます。 

| ステップ | ノード | コンポーネントが構築されました | コンポーネントのサイズ |
 | --- | --- | --- | --- |
 | ビルド | 1-2 | コンプ A (カラー 1) | 2 |
 | ビルド | 3 | コンプ B (カラー 2) | 1 |
 | ビルド | 4-5 | コンプ C (カラー 2) | 2 |

 基本的な答えは 2 です。 

次に、ノード 2 を再色候補として検討します。 これを色 2 に再着色すると、コンポーネント B と C が隣接して接続されます。 

| ノード v | 隣人コンプ (カラー 2) | マージ結果 |
 | --- | --- | --- |
 | 2 | B、C | 1 + 1 + 2 = 4 |

 したがって、答えは 4 になります。 

このトレースは、単一のブリッジ ノードを介して複数の同じ色のコンポーネントをマージすることによって改善がもたらされることを示しています。 

### 例 2

 入力:```
4 3
1 2 3 4
1 2
2 3
3 4
```すべてのノードには個別の色があるため、すべてのコンポーネントのサイズは 1 になります。 

| ノード | 隣接コンポーネント | ベストマージ |
 | --- | --- | --- |
 | 任意 | すべてのサイズ 1 | 最大 2 |

 色を変更しても、どのノードも 2 つ以上の異なる隣接ノードを効果的に接続できないため、答えは小さいままになります。 

これは、複数の同じ色のコンポーネントがすでに 1 つのノードに隣接している場合にのみ、色の再設定が役立つことを示しています。

 ## 特殊なケース

 重要なエッジケースの 1 つは、再カラーがまったく有益ではない場合です。 たとえば、すべてのノードが分離されている場合、またはすべてのコンポーネントがすでにその色の範囲内で最大である場合、アルゴリズムはベースラインの最大コンポーネント サイズに正しくフォールバックします。 

もう 1 つのエッジ ケースは、ノードが同じ色の多数のコンポーネントを接続する場合です。 このアルゴリズムは、隣接するすべてのコンポーネント ID を集約し、コンポーネントごとにサイズを 1 回合計して二重カウントを回避するため、これを自然に処理します。 

最後のエッジ ケースは、近傍が異なる色に属しているため、色を変更しても新しい接続が作成されないグラフです。 その場合、各ノードのコンポーネントのディクショナリでは、既存のコンポーネントよりも大きな意味のあるマージは生成されず、ベースラインの答えは最適なままになります。
