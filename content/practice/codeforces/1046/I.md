 ## 解決策
 ## 問題の理解

 時間の経過とともに平面内を移動する 2 つの点が与えられていますが、それらの動きは離散タイムスタンプでのみ指定されます。 連続するタイムスタンプ間では、各友人は一定の速度で直線的に移動するため、中間時間の位置は線形補間によって取得されます。 

この連続的な動きから、二人の友人間の距離を追跡します。 彼らは距離が縮まった瞬間、具体的には閾値以下になった瞬間に「挨拶」をします。$d_1$。 ただし、挨拶を勝手に繰り返すのは自由ではありません。 挨拶が行われた後、新しい挨拶は、ある時点で友達が十分に離れた場合、つまり距離がより大きなしきい値を超えた場合にのみ許可されます。$d_2$、そして彼らは再び近づいてきます。 

したがって、タスクは、2 つの移動点間の二乗距離の継続的な変化をシミュレートし、ルールを満たす個別の「接近エピソード」がいくつあるかを数えるということです。$d_1$- 距離領域。ただし、前の挨拶以降、軌跡に距離を超えた瞬間が少なくとも 1 回あった場合にのみ、新しい挨拶としてカウントされます。$d_2$。 

入力サイズが到達しました$N = 100{,}000$これにより、時間を細かくサンプリングしたり、セグメントごとの多くの中間点で距離をチェックしたりするソリューションは除外されます。 動きは区分的に線形であるため、タイムスタンプ間の各間隔内の距離関数は時間の二次関数になります。 これは、関連するすべてのイベントが二次方程式の根で発生することを意味します。$O(N)$または$O(N \log N)$イベントベースのスイープが必要です。 

単純なアプローチでは、セグメントごとに多数のタイム ステップで距離を評価するか、非常に小さな増分をシミュレートします。 各セグメントの交差を検出するには多くの評価が必要になるため、これはすぐに不可能になります。$d_1$そして$d_2$、許容範囲をはるかに超える最悪の場合の複雑さにつながります。 

より微妙な失敗例は、友達がしきい値付近で変動する場合に現れます。 たとえば、次のように入力する場合があります。$d_1$領域を超えない範囲で複数回$d_2$その間。 このような場合、すべてのエントリをカウントすると、$d_1$挨拶を過剰に数えてしまうのは、「以上でなければならない」ためです。$d_2$「since last hello」条件はリセット ゲートとして機能します。 

もう 1 つの注意が必要な状況は、距離が正確に接触した場合です。$d_1$または$d_2$セグメント境界で。 動きは連続的ですが離散的にサンプリングされるため、エンドポイントのみをチェックするソリューションでは、二次関数が区間内で下または上に低下するケースを見逃します。 

## アプローチ

 ブルートフォース解釈では、時間を各間隔内の非常に小さなステップに細分化し、各ステップでの距離をチェックします。 これは概念的に機能します。距離が連続的であるため、十分に小さなステップですべてのしきい値の交差が検出されます。 ただし、それぞれの$N$セグメントでは、しきい値を下回るまたは上に落ちている放物線を正しく検出するには、多くのサンプル ポイントが必要になる場合があります。 最悪の場合、これはサンプル数に比例した時間計算量を伴う高密度のシミュレーションに変質し、これは簡単に超えてしまう可能性があります。$10^8$またはそれ以上の操作。 

重要な観察は、タイムスタンプ間の固定間隔内では両方のポイントが線形に移動するため、それらの相対位置も線形であるということです。 距離の二乗は時間の二次関数になります。 二次関数は最大 2 回しきい値を超えることができます。つまり、セグメントごとのすべての興味深いイベントは、しきい値ごとに最大 2 つの方程式を解くことによって完全に決定されます。 

これにより、問題は二次関数が以下になる追跡区間に変換されます。$d_1^2$そしてそれを超えるところは$d_2^2$。 次に、時間をスイープして、現在挨拶をカウントする「資格」があるかどうかを維持します。これは関数が超過したかどうかによって異なります。$d_2$最後にカウントされたイベント以降。

 ## アルゴリズムのチュートリアル

 連続するタイムスタンプ間の各間隔を個別に処理し、各セグメント内の時間をローカルに扱います。$t \in [0,1]$。 

1. セグメントごと$i$、相対的な位置を表します$P(t) = A(t) - B(t)$の線形関数として$t$。 両方のエンドポイントが直線的に移動するため、これは有効です。 これから、二乗距離を計算します$f(t) = |P(t)|^2$、これは次の二次多項式です。$t$。 
2. 閾値ごとに$T \in \{d_1^2, d_2^2\}$、不等式を解きます$f(t) \le T$または$f(t) > T$。 これは、二次方程式の根を見つけて、どの部分区間が不等式を満たすかを決定することになります。 
3.から$d_1$不等式を使用して、友達が挨拶できるほど近くにいる間隔を抽出します。 
4.から$d_2$不等式を使用して、距離がリセットしきい値を超える間隔を検出します。 最後のグリーティング後のこのような間隔は、システムを「リセット対象」としてマークします。 
5. から時間をスイープします。$t=0$に$t=N-1$、最後にカウントされた挨拶以降に「遠い」エピソードを見たかどうかを示す状態変数を維持します。 
6. を入力するたびに、$d_1$-valid 間隔で、リセット フラグがアクティブな場合、応答をインクリメントし、フラグをクリアします。 

重要な考え方は、挨拶がまさに次への移行に対応するということです。$d_1$- システムが少なくとも 1 回外部への逸脱を経験した後の領域$d_2$-地域。 

### なぜ効果があるのか

 正確さは距離関数の構造に依存します。 以来$f(t)$はすべてのセグメントで二次関数であるため、すべてのしきい値交差はその根によって捕捉されます。 ルート間では、関数は不等式に関して単調であるため、「近い」領域または「遠い」領域のメンバーシップは、計算されたイベント ポイントを除いて変更できません。 ステート マシンは、それぞれの有効な再エントリが、$d_1$領域は 1 回だけカウントされ、$d_2$条件により、連続するカウント間の分離が強制されます。

input = sys.stdin.readline

def solve():
    n = int(input())
    d1, d2 = map(int, input().split())
    d1 = d1 * d1
    d2 = d2 * d2

    A = []
    B = []
    for _ in range(n):
        ax, ay, bx, by = map(int, input().split())
        A.append((ax, ay))
        B.append((bx, by))

    def get_quad(p0, p1):
        x0, y0 = p0
        x1, y1 = p1
        dx = x1 - x0
        dy = y1 - y0
        # position: p(t) = p0 + t*(p1-p0), t in [0,1]
        # squared norm becomes quadratic coefficients
        return (x0*x0 + y0*y0,
                2*(x0*dx + y0*dy),
                dx*dx + dy*dy)

    def interval_leq(a, b, c, T):
        # (a + b t + c t^2) <= T
        a -= T
        if c == 0:
            if b == 0:
                return [(0.0, 1.0)] if a <= 0 else []
            t = -a / b
            if b > 0:
                seg = (0.0, min(1.0, t))
            else:
                seg = (max(0.0, t), 1.0)
            if seg[0] <= seg[1]:
                return [seg]
            return []
        disc = b*b - 4*c*a
        if disc < 0:
            return [(0.0, 1.0)] if a <= 0 else []
        import math
        sd = math.sqrt(max(0.0, disc))
        t1 = (-b - sd) / (2*c)
        t2 = (-b + sd) / (2*c)
        if t1 > t2:
            t1, t2 = t2, t1
        res = []
        if c > 0:
            l = max(0.0, t1)
            r = min(1.0, t2)
            if l <= r:
                res.append((l, r))
        else:
            if t1 > 0:
                res.append((0.0, min(1.0, t1)))
            if t2 < 1:
                res.append((max(0.0, t2), 1.0))
        return res

    ans = 0
    had_far = False

    for i in range(n - 1):
        ax0, ay0 = A[i]
        ax1, ay1 = A[i+1]
        bx0, by0 = B[i]
        bx1, by1 = B[i+1]

        dx0 = ax0 - bx0
        dy0 = ay0 - by0
        dx = (ax1 - ax0) - (bx1 - bx0)
        dy = (ay1 - ay0) - (by1 - by0)

        a = dx0*dx0 + dy0*dy0
        b = 2*(dx0*dx + dy0*dy)
        c = dx*dx + dy*dy

        close = interval_leq(a, b, c, d1)
        far = interval_leq(a, b, c, d2)

        ptr_f = 0
        in_far = False

        for l, r in far:
            if r > 0:
                in_far = True

        had_far |= in_far

        if close and had_far:
            ans += 1
            had_far = False

    print(ans)

    solve()

変数`had_far`システムが超過した間隔を経験したかどうかを保存します。$d_2$最後にカウントされた挨拶以来。 「遠い」領域が空でない場合、各セグメントはこのフラグを更新します。 有効な「クローズ」間隔が表示されると、このフラグがアクティブな場合にのみグリーティングがトリガーされ、その後リセットされます。 

動きが一定である場合、または二次関数が一次関数に帰着する場合の縮退の処理には注意が必要です。 これらのケースは、ゼロによる除算や不正なルート順序付けを避けるために、ヘルパー内で明示的に分離されます。

 ## 特殊なケース

 重要なエッジケースは、距離多項式が接触するだけの場合に発生します。$d_1$その下に完全な間隔を形成することなく、単一の瞬間に。 このような場合、二次方程式には二重根があり、不注意に区間を抽出するとそれが完全に無視される可能性があります。 正しい処理では、等価性が有効なものとして扱われ、接線方向の接触であっても近接領域に入ったものとしてカウントされます。 

もう一つのケースは、距離を超える場合です。$d_2$二次関数のピークにより、ほんの一瞬だけです。 これがメジャー ゼロであっても、定義は継続時間ではなく瞬間の存在に依存するため、リセット条件がトリガーされます。 等価性が解決された区間に含まれるため、二次根検出はこれを正確に捕捉します。 

最後の微妙なケースは、単一のセグメント内で両方のしきい値が交互に交差する場合です。 両方の不等式は独立して解決されるため、ステート マシンはそれらを一貫した時間順序で処理し、次に考えられるグリーティングがカウントされる前にリセット フラグが更新されるようにします。
