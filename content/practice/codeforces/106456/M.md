 ## 解決策
 ## 問題の理解

 正の整数のシーケンスが与えられ、それを配列全体をカバーする複数の連続したセグメントに分割することができます。 セグメントごとに 2 つの量を計算します。 

最初の数量はセグメント インデックスのみに依存します。 セグメントが複数の位置にまたがる場合$L$に$R$、これらのインデックスに関連付けられた奇数を合計します。つまり、追加します。$2L-1, 2(L+1)-1, \dots, 2R-1$。 この部分は純粋に位置的なものであり、配列の値とは独立しています。 

2 番目の量は、セグメント内のすべての値の gcd です。 

セグメントは、これら 2 つの量の積から固定ペナルティを引いたものに等しいスコアを与えます。$P$。 目標は、すべてのセグメント スコアの合計が最大になるように、任意の数のセグメントを選択することです。 

入力サイズが到達しました$n \le 10^5$テストごと、合計$n$テスト全体の境界も次のとおりです$10^5$。 これにより、セグメント境界を越える 2 次または 3 次の列挙が即座に除外されます。 平$O(n \log^2 n)$すべての位置が以前の多くの状態と相互作用する必要がある可能性があるため、アプローチには注意深い構造が必要です。 

主な問題は、セグメント値が値に対する gcd とインデックスの構造化関数に同時に依存することです。 Gcd はエンドポイントごとに少数の個別の状態を示唆しますが、位置の合計は代数的に単純化できるほど滑らかですが、それでもパーティション DP とグローバルに相互作用します。 

単純なアプローチでは、再計算された gcd と合計を使用して、すべてのパーティション、またはすべてのセグメント エンドポイントを試行します。 これは失敗します。$O(n^2)$セグメントごとにコストがかかります$O(1)$gcd では前処理が行われていますが、それでもトランジションが多すぎます。 

より微妙な失敗は、gcd 状態のみを使用して DP を試行し、各候補分割の位置項を再計算することから発生します。 gcd 遷移が最適化されたとしても、DP には非線形コスト関数を使用して以前のすべての分割ポイントを効率的に最大化する方法が必要です。 

各セグメントを独立して扱い、gcd の安定性に基づいて貪欲に拡張しようとすると、具体的な落とし穴が現れます。 位置の重みはセグメントの長さに応じて二次関数的に増加するため、高い gcd を持つ短いセグメントはわずかに小さい gcd を持つ長いセグメントよりも悪くなる可能性があります。 これにより、貪欲な直感は完全に打ち破られます。 

## アプローチ

 自然な開始点はパーティション DP です。 させて$dp[r]$プレフィックスの最良の回答になります$1 \dots r$。 考えられる最後のセグメントごとに$[l, r]$から拡張しようとします。$dp[l-1]$そしてセグメントの寄与度を追加します。 

ブルートフォース移行では、すべてが考慮されます。$l$、gcd と位置の合計を再計算し、セグメント スコアを評価します。 これにより、$O(n^2)$トランジションは遅すぎます$n = 10^5$。 

最初の構造的改善は 2 つの観察から得られます。 まず、固定で終わる接尾辞セグメントの gcd 値$r$だけを取る$O(\log A)$明確な価値観。 第二に、位置和は依存関係を分離する形式で書き換えることができます。$l$そして$r$。 

セグメントを次のようにします$[l, r]$。 位置和は$$W(l,r) = \sum_{i=l}^{r} (2i-1).$$等差級数を展開すると、キャンセル構造が表示されます。$$W(l,r) = (r-l+1)(l+r-1).$$プレフィックスインデックス作成に切り替えた後は、より有用な再定式化が表示されます。$i = l-1$。 するとセグメントは次のようになります$[i+1, r]$、式は次のように簡略化されます。$$W(l,r) = r^2 - i^2.$$このアイデンティティがターニングポイントになります。 混合物を除去します$l,r$位置項内の相互作用を計算し、二乗の差に変換します。 

ここで、セグメントの寄与度は次のようになります。$$G \cdot (r^2 - i^2) - P.$$したがって、DP 遷移は次のようになります。$$dp[r] = \max_{i < r} \left(dp[i] + G \cdot (r^2 - i^2) - P\right),$$ただし、という制限があります$G$セグメントの gcd です$[i+1, r]$。 

用語を並べ替えると:$$dp[r] = \max_{i < r} \left(dp[i] - G \cdot i^2\right) + G \cdot r^2 - P.$$今すぐ修正してください$r$。 考えられるそれぞれの gcd 値について$G$、有効な連続範囲を考慮する必要があります。$i$' (gcd-suffix 分解に由来)。 このような範囲ごとに次のものが必要です。$$\max_{i \in \text{range}} (dp[i] - G \cdot i^2).$$これは静的クエリになりました$i$パラメータ付き$G$。 各インデックス$i$で線形関数を定義します$G$:$$dp[i] - i^2 \cdot G.$$それでそれぞれ$i$変数内の行です$G$、スロープ付き$-i^2$そしてインターセプト$dp[i]$。 各セグメント クエリについて、特定のインデックスで評価されたインデックスの範囲の最大値が必要です。$G$。 

これは、行のセグメント ツリー構造 (Li Chao または同等のもの) になり、行のインデックスが維持されます。$i$、および指定されたインデックス間隔で制限されたクエリを実行します。$G$。 各 gcd ブロックは、この構造に対する範囲クエリをトリガーします。 

完全なソリューションは、gcd-suffix 列挙を組み合わせます。$r$インデックス上の動的な凸包構造を使用します。

 ## アルゴリズムのチュートリアル

 1. ポジションごと$r$、で終わる部分配列のすべての個別の gcd 値を列挙します。$r$、対応する左側の境界範囲とともに。 これは、以前の gcd 状態を後方に拡張し、等しい gcd が出現するたびにマージすることによって行われます。 重要な点は、そのような状態の数が$r$gcd は限られた回数しか減少できないため、対数になります。 
2. DP 配列を維持します。$dp[i]$プレフィックスに対する最良の回答を保存します$1 \dots i$。 
3. インデックス上の構造を構築する$i$状態を表す線の挿入をサポートします$i$。 各インデックスは次の行に貢献します。$$f_i(x) = dp[i] - i^2 \cdot x.$$傾きは以下に依存します$i^2$これは、以前の分割と将来の gcd 値の間の相互作用をエンコードするものです。 
4. それぞれについて$r$および値を持つ各 gcd ブロック$G$および有効なインデックス範囲$[L, R]$、次の構造をクエリします。$$\max_{i \in [L, R]} f_i(G).$$これにより、その gcd セグメントと互換性のある最適な以前の分割ポイントが得られます。 
5. 結果を残りの項と結合します。$$dp[r] = \max(dp[r], \text{query} + G \cdot r^2 - P).$$6. 計算後$dp[r]$、インデックスを挿入$r$構造に組み込むことで、将来のポジションに利用できるようになります。 

### なぜ効果があるのか

 で終わるすべての有効なパーティション$r$最後のセグメントを選択します$[i+1, r]$これは、サフィックス分解によって生成される gcd 状態の 1 つに対応します。 このような各セグメントについて、最適な寄与は、初期の最適な分割を選択することによってのみ決まります。$i$有効範囲内です。 代数的書き換えにより、すべての依存関係が分離されます。$r$単一の加法項にまとめる$G \cdot r^2$、すべてに依存しながら、$i$事前に保存できる関数でキャプチャされます。 この分離により、すべての有効なパーティションが、何らかの gcd 状態と何らかのインデックスを通じて正確に 1 回評価されることが保証されます。$i$したがって、すべての DP 遷移にわたる最大値が保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class LiChao:
    def __init__(self, xs):
        self.xs = xs
        self.n = len(xs)
        self.lines = []

        size = 1
        while size < self.n:
            size <<= 1
        self.seg = [None] * (2 * size)

    def f(self, line, x):
        m, b = line
        return m * x + b

    def add_line(self, line, idx=1, l=0, r=None):
        if r is None:
            r = len(self.xs) - 1

        if self.seg[idx] is None:
            self.seg[idx] = line
            return

        mid = (l + r) // 2
        x_mid = self.xs[mid]

        cur = self.seg[idx]

        if self.f(line, x_mid) > self.f(cur, x_mid):
            self.seg[idx], line = line, cur

        if l == r:
            return

        if self.f(line, self.xs[l]) > self.f(self.seg[idx], self.xs[l]):
            self.add_line(line, idx * 2, l, mid)
        else:
            self.add_line(line, idx * 2 + 1, mid + 1, r)

    def query_range(self, ql, qr, x, idx=1, l=0, r=None):
        if r is None:
            r = len(self.xs) - 1

        if qr < l or r < ql:
            return -10**30

        if ql <= l and r <= qr:
            if self.seg[idx] is None:
                return -10**30
            return self.f(self.seg[idx], x)

        mid = (l + r) // 2
        return max(
            self.query_range(ql, qr, x, idx * 2, l, mid),
            self.query_range(ql, qr, x, idx * 2 + 1, mid + 1, r)
        )

def solve():
    t = int(input())
    for _ in range(t):
        n, P = map(int, input().split())
        a = list(map(int, input().split()))

        dp = [0] * (n + 1)

        xs = list(range(n + 1))
        hull = LiChao(xs)

        def add_line(i):
            # line: dp[i] - i^2 * x  => m = -i^2, b = dp[i]
            hull.add_line((-i * i, dp[i]))

        add_line(0)

        for r in range(1, n + 1):
            cur_gcds = []
            cur = a[r - 1]
            l = r

            while l >= 1:
                cur = cur if l == r else __import__("math").gcd(cur, a[l - 1])
                if not cur_gcds or cur_gcds[-1][0] != cur:
                    cur_gcds.append((cur, l))
                l -= 1

            best = -10**30

            for g, L in cur_gcds:
                # valid i are in [L-1, r-1]
                ql, qr = L - 1, r - 1
                val = hull.query_range(ql, qr, g)
                best = max(best, val + g * r * r - P)

            dp[r] = best
            add_line(r)

        print(dp[n])

if __name__ == "__main__":
    solve()
```DP 配列には、最適なプレフィックス応答が格納されます。 Li Chao 構造は、以前の分割点の候補を gcd 変数内の線形関数として維持します。 各インデックスは DP 値が確定した後に挿入され、将来の遷移でそのインデックスを使用できるようになります。 

gcd 列挙ループは各エンドポイントから逆方向に進み、同一の gcd 値を間隔に圧縮します。 各間隔は、制限されたインデックス範囲を持つ 1 つのクエリに寄与し、繰り返しの再計算を回避しながら正確さを維持します。 

用語$g \cdot r^2$選択した分割インデックスではなく、現在のエンドポイントのみに依存するため、クエリ後に追加されます。 

## 実用的な例

 値がセグメント間で複数の gcd ドロップを許可する小さな配列を考えてみましょう。 サフィックス gcd 状態がどのように形成されるか、および DP 遷移が最適な分割ポイントをどのように選択するかを追跡します。 

簡単にするために、次のように概念的なトレースを取得します。$a = [2, 4, 6]$、$P = 1$。 

で$r = 1$、セグメントは 1 つだけ存在するため、最善の方法は、それを取得するか、早期に分割しないことです。 DP は次のように初期化されます。$dp[1]$から計算される$i = 0$。 

で$r = 2$、サフィックス gcd は$(4,2)$そして$(2,1)$、以前のインデックスの異なる有効範囲が生成されます。 この構造は両方を評価し、gcd 空間での線形評価に従って、以前の最良の分割インデックスを選択します。 

| r | gcd ブロック | 有効な i 範囲 | 最高の船体値 | dp[r] |
 | --- | --- | --- | --- | --- |
 | 1 | (2,1) | [0,0] | dp[0] - 0 | 計算された |
 | 2 | (4,2)、(2,1) | [1,1]、[0,1] | 範囲にわたる最大値 | 計算された |
 | 3 | 複数 | マージされた範囲 | ハル経由で評価 | 計算された |

 これは、単一のエンドポイントでの複数の gcd 状態が、同じ基礎となる構造上で複数の制約付きクエリにどのようにマッピングされるかを示しています。

 ## 特殊なケース

 単一要素配列は、セグメントが 1 つだけ存在する基本分割を DP が正しく処理するかどうかをテストします。 この場合、gcd は要素そのものであり、位置和は 1 つの項に折りたたまれるため、答えは単純です。$a_1 \cdot 1 - P$。 

すべての値が等しいなどの均一な配列では、分割とマージの間のトレードオフが強調されます。 gcd はすべてのセグメントにわたって一定のままであるため、最適な戦略は二次位置ゲインが繰り返しのペナルティを上回るかどうかに完全に依存します。 すべてのサフィックス gcd ブロックが 1 つに集約され、DP がハル構造を通じて分割と非分割の両方の選択肢を評価するため、アルゴリズムはこれを正しく処理します。 

次のような値が急速に切り替わるケース$2,3,2,3,\dots$エンドポイントごとに複数の gcd 状態を実行します。 各位置でいくつかの縮小 gcd セグメントが生成され、正確かどうかは、各セグメントが同じ DP 構造に対して個別にクエリされるかどうかに依存します。
