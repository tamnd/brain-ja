 ## 解決策
 ## 問題の理解

 ノードが 1 から n までラベル付けされたルート付き二分木が与えられます。 各ノードは、長さ 2n の未知の有効な括弧シーケンス内の 1 対の一致する括弧に対応します。 ノードの番号付けは任意ではありません。元のシーケンスによって誘導され、文字列を左から右にスキャンするときに左括弧が現れる順序でペアに番号が付けられます。 

ツリー自体は、各ペアの隣接する文字を接続する構造規則によって定義されます。 ノードが位置のペア (i, j) に対応する場合、元の文字列の i+1 と j+1 を検査します。 i+1 が左括弧の場合、ノードの左の子になります。 j+1 が開き括弧の場合、それが右の子になります。 これらの子は、左括弧が正確にその位置にある括弧ペアに対応します。 ツリーのルートはノード 1 です。 

タスクは、説明された構造の下でこの正確なツリーを生成する可能性がある有効な括弧シーケンスを再構築することです。 

入力サイズは大きく、テスト ケース全体の合計 n は最大 2×10^5 です。 どのソリューションも、テスト ケースごとに線形に近いものでなければなりません。 すべての配置を試行したり、文字列を繰り返しシミュレートしたりする二次再構成は、配置とスキャンの単純なシミュレーションでは 10^5 ノードでも 10^10 の演算を意味するため、すぐに遅すぎます。 

ツリーが入れ子構造のみを一意にエンコードしていると仮定すると、微妙な失敗例が発生します。 たとえば、2 つの子を持つルートは、両方の子が同じ外側のペア内に現れることを示唆するかもしれませんが、その構築は実際には i+1 と j+1 での隣接関係に依存します。つまり、兄弟は一般的なサブツリーの包含ではなく、「エンドポイントの後の次の左括弧」に対応します。 これを誤解すると、多くの場合、間隔内に子を恣意的に配置し、無効なシーケンスや一貫性のないシーケンスが生成されてしまいます。 

もう 1 つの特殊なケースは、ノードに子が 1 つしかない場合、または子がまったくない場合です。 単純な「常に親間隔のすぐ内側で子を開く」構造では、右側の子の開始位置が現在のトラバース位置ではなく j+1 に関連付けられるため、誤って間隔が重なったり、順序の不一致が生じたりする可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、各ノード i に開始位置と終了位置があり、親子関係が隣接制約と一致する必要があることを考慮しながら、すべての開始括弧と終了括弧に位置 1 ～ 2n を割り当てようとします。 これは、間隔間の依存関係ルールを伴う 2n 個の位置にわたる制約付き配置の問題に変わります。 バックトラッキングを試みたとしても、各ノードは複数の配置に分岐する可能性があり、構成全体は n で指数関数的に爆発的に増加します。 これは20歳くらいのnでも無理です。 

重要な観察は、正しく解釈された場合、ツリーが実際にシーケンスの決定論的な分解を定義していることです。 各ノードは間隔に対応し、i+1 と j+1 を使用する構築ルールは、すべてのノードの子がその間隔の開始直後または終了直後に出現する必要があることを意味します。 これにより、順序付けの自由度が失われます。構造を修正すると、間隔が生成された方法の逆をシミュレートすることでシーケンスを再構築できます。 

括弧を置く代わりに、ノードに位置を割り当てます。 各ノードには正確に 2 つの位置があります。1 つはノードに入るときの開始位置、もう 1 つはノードから出るときの終了位置です。 左の子は開始括弧を配置した瞬間から検出され、右の子は終了括弧を配置した瞬間から検出されるという事実を尊重して走査を実行します。 これにより、自然に、子を正しい順序で再帰的に処理しながら、ノードに入るときに '(' を発行し、ノードから出るときに ')' を発行する、深さ優先の再構築が行われます。

この構造では、左側の子は親を開いた直後に処理され、右側の子は親を閉じる直前に処理される必要があることが保証されています。これは、これらが元の構造の i+1 および j+1 遷移に正確に対応しているためです。

 ## アルゴリズムのチュートリアル

 ツリーをトラバーサルベースのエンコーディングに展開し直した場合に括弧がどのように生成されるかをシミュレートすることにより、文字列を再構築します。 

1. ルート ノード 1 から開始します。このノードはシーケンスの最も外側のペアに対応するため、有効な構造の最初の左括弧を生成する必要があります。 
2. ノード u の場合、u を入力するとすぐに '(' を出力します。これは、u に関連付けられたペアの左括弧を割り当てることに対応します。
 3. u の左の子が存在する場合は、それを再帰的に処理します。 左の子は、元の構造の位置 i+1 から来るように定義されています。つまり、u を開いた直後に最初に現れる構造でなければなりません。 
4. 左側のサブツリーを終了した後、u の右側の子が存在する場合はそれを再帰的に処理します。 これは、元のシーケンスの j の直後から始まる構造に対応するため、u のすべての左派生コンテンツの後に配置する必要があります。 
5. 両方の子が処理された後、「)」を出力します。 これにより、u に対応する区間が確定します。 
6. ルートから到達可能なすべてのノードに対してこの DFS を繰り返します。これにより、すべてのノードが 1 つの開始括弧と 1 つの終了括弧に正確に寄与するようになります。 

これが機能する理由は、各ノードを、再構成された文字列内の連続した間隔を定義する一致した位置のペアとして解釈することにあります。 構築ルールは子を i+1 と j+1 に厳密に結び付けます。これにより、左の子はオープン後の可能な限り早い時点で開始し、右の子はクローズ後の可能な限り早い時点で開始するように強制されます。 これにより、DFS 構造を超えて兄弟を順序付ける自由が失われます。 再帰では、すべてのサブツリーがその親間隔内に完全に含まれることが維持され、インターリーブは不可能です。これは、子の作成を定義する隣接制約に違反するためです。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n = int(input())
    left = [0] * (n + 1)
    right = [0] * (n + 1)

    for i in range(1, n + 1):
        l, r = map(int, input().split())
        left[i] = l
        right[i] = r

    res = []

    def dfs(u):
        res.append('(')
        if left[u]:
            dfs(left[u])
        if right[u]:
            dfs(right[u])
        res.append(')')

    dfs(1)
    print(''.join(res))

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```このコードは、各テスト ケースのツリー構造を読み取り、子を配列に格納します。 DFS 機能は、中核となる再構築メカニズムです。 ノードに入るときに開始括弧を発行し、その子の処理後に終了括弧を発行し、元の括弧ペアの間隔セマンティクスと一致します。 

唯一の微妙な点は再帰の深さです。 ツリーは最大 10^5 の長さのチェーンになる可能性があるため、スタック オーバーフローを避けるために再帰制限が増加します。 走査順序は厳密に左の子が右の子の前に従うため、左の子が i+1 遷移から派生する右の子より前に i+1 遷移から派生するという依存関係がエンコードされます。

 ## 特殊なケース

 単一ノードのツリーは、1 組のかっこに直接マップされます。 DFS はノード 1 に入り、「(」を出力し、子を見つけずに「)」を出力し、唯一の有効なシーケンスである「()」を正確に生成します。 

1 → 2 → 3 → … → n のような深いチェーンは、再帰の深さを強調します。 トラバースは構造に応じて繰り返し左 (または右) の子に入りますが、降下前に 1 つの開始と、戻った後に 1 つの終了を正確に出力し、適切なネストを維持します。 スタックは直線的に増加しますが、n フレームを超えることはありません。 

右の子のみを持つノードは、右の子が既存の内部ブロック内の位置に関連付けられておらず、左のサブツリーが完了した後に追加されることを示しています。 右のサブツリーが同じ親区間内に囲まれているため、DFS は依然として正しいネストを出力しますが、線形化の後半で表示され、j+1 に基づく構築ルールと一致します。
