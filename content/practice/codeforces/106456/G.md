 ## 解決策
 ## 問題の理解

 各テスト ケースは、N 個の独立した攻撃を伴う固定戦闘シナリオを記述します。 攻撃 i はゴブリン i をターゲットにし、その貫通 Ai がゴブリンの防御 Bi に達するかどうかに応じて、最大ダメージ Ci を与えるか、何も与えないかのどちらかです。 クエリを処理する前に、元の値でどの攻撃が成功するかを計算します。 

工夫としては、クエリ値 X ごとに、すべてのダメージを評価する前に、最大 1 つの攻撃を選択し、その貫通力を X に置き換えることができるということです。 この 1 つの変更の後、どの攻撃が成功するかを再計算し、そのダメージを合計します。 各クエリは独立しているため、変更の決定は毎回新たに行われます。 

各クエリの出力は、攻撃を変更するかどうか、およびどの攻撃を変更するかを選択した後の、考えられる最大の合計ダメージです。 

この制約は、テスト ケース全体で N と Q の両方が 2×10^5 まで大きくなる可能性があることを意味します。 これにより、すべての攻撃に対するクエリごとの線形スキャンが即座に排除されます。これは、最悪の場合、約 4×10^10 の操作が発生する可能性があるためです。 許容可能なソリューションでは、前処理後に各クエリを対数または定数作業 (通常は O(log N) または O(1)) に減らす必要があります。 

また、最良の変更が常に現在失敗している攻撃をターゲットにするか、常に現在成功している攻撃をターゲットにすることを想定している場合、単純な実装は微妙に失敗する可能性があります。 正しい選択は、各インデックスの X が Bi とどのように比較されるかによって決まるため、クエリ値としきい値の間の相互作用を無視すると、不正確な結果が得られます。 

たとえば、元の攻撃はすべてすでに成功しているが、クエリ値 X が非常に小さい状況を考えてみましょう。 単純な考えでは、存在しない失敗した攻撃を「修正」しようとしたり、答えが変わらないと誤って仮定したりする可能性があります。 実際には、高い Bi で以前に成功した攻撃を低い X に変更することは、ダメージを軽減または維持することしかできないため、最適な選択は何もしないことです。 

もう 1 つの失敗ケースは、最初は複数の攻撃が失敗していても、Bi ≤ X の攻撃だけが修正可能になる場合です。 Bi > X の攻撃を選択しても利点はありませんが、しきい値条件を無視した場合、不注意なアプローチによって攻撃が選択される可能性があります。 

## アプローチ

 まず、変更を加えずにベースラインのダメージを計算します。 これは、Ai ≧ Bi となるような、すべての i にわたる Ci の単純な合計です。 この部分はすべてのクエリに対して修正されます。 

ここで、単一の攻撃 i の貫通力を X に設定して変更することを選択した場合に何が起こるかを考えてみましょう。 

重要なのは、この変更の影響をローカルで理解することです。 攻撃 i は、Ai (または変更後の X) と Bi の比較のみに応じて、Ci または 0 のいずれかに寄与します。 他のすべての攻撃は変更されません。 

したがって、各インデックス i について、元の寄与と、Ai を X に強制した後の寄与を比較します。その差は、Bi、Ai、Ci、および X にのみ依存します。 

攻撃 i が最初に成功した場合、つまり Ai ≥ Bi は、すでに Ci に貢献しています。 修正後は、X ≥ Bi の場合にのみ Ci に寄与し、それ以外の場合は 0 に低下します。したがって、成功した攻撃の修正は中立か有害かのどちらかです。 

攻撃 i が元々失敗した場合、つまり Ai < Bi の場合、寄与は 0 になります。変更後、X ≥ Bi の場合は Ci の寄与があり、それ以外の場合は 0 のままです。したがって、失敗した攻撃のみが正の利益を生み出すことができ、防御しきい値が最大でも X の場合に限ります。 

この観察は問題を崩壊させます。各クエリ X について、Bi ≤ X の失敗した攻撃のみを考慮し、その中で最大の Ci が必要です。 

このような失敗した攻撃はすべてペア (Bi、Ci) として前処理し、Bi ごとに並べ替えて、Ci を超えるプレフィックスの最大値を維持します。 次に、各クエリは Bi での二分検索になり、その後にプレフィックス最大ルックアップが続きます。

 ## アルゴリズムのチュートリアル

ソリューションを前処理フェーズとクエリフェーズに分けます。 

1. すべての攻撃を反復し、Ai ≧ Bi であるすべての i について Ci を合計することにより、ベースライン ダメージを計算します。 この値はクエリ間で変更されないため、保存します。 
2. Ai < Bi の各インデックス i について、ペア (Bi, Ci) を記録します。 これらは、変更すると改善される可能性がある唯一の候補です。 
3. これらのペアを Bi で昇順に並べ替えます。 これにより、任意のしきい値 X に対して、使用可能なすべての候補がプレフィックスを形成するように配置されます。 
4. ソートされたリストに対して Ci のプレフィックス最大値を維持する補助配列を構築します。 この後、位置 k で終わる任意のプレフィックスについて、その範囲内のすべての Bi の中で最適な Ci を即座に知ることができます。 
5. 各クエリ X について、二分探索を使用して Bi ≤ X となる最大のインデックス k を見つけます。 そのようなインデックスが存在しない場合、このクエリの答えは単なるベースラインになります。 
6. それ以外の場合は、k でのプレフィックスの最大値を取得します。 この値は、1 つの攻撃を変更することで得られる最大の利益です。 それをベースラインに追加し、結果を出力します。 

これが機能する理由は、すべての変更が何も有益にならないか、失敗した攻撃を成功に変えるかのいずれかであるという事実から来ています。 配列内の他の構造は変更されません。 考えられるすべての改善の中で、Bi ≤ X のものだけが有効であり、それぞれの選択は独立しており、相加的に寄与するため、その中で最大の Ci が必要です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        A = list(map(int, input().split()))
        B = list(map(int, input().split()))
        C = list(map(int, input().split()))

        base = 0
        candidates = []

        for i in range(n):
            if A[i] >= B[i]:
                base += C[i]
            else:
                candidates.append((B[i], C[i]))

        candidates.sort()
        prefix = []
        best = 0
        for b, c in candidates:
            if c > best:
                best = c
            prefix.append(best)

        def answer(x):
            lo, hi = 0, len(candidates) - 1
            pos = -1
            while lo <= hi:
                mid = (lo + hi) // 2
                if candidates[mid][0] <= x:
                    pos = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

            gain = 0
            if pos != -1:
                gain = prefix[pos]

            return base + gain

        for _ in range(q):
            x = int(input())
            print(answer(x))

if __name__ == "__main__":
    solve()
```実装ではまず、常に成功する攻撃と、改善可能な可能性のある攻撃を分離します。 二分検索は、現在のクエリ X の下でアクティブになる候補のサブセットを分離します。プレフィックス最大配列により、有効な範囲が判明すると、一定時間内に最適な選択肢を取得できることが保証されます。 

微妙な点は、既に成功した攻撃を変更することは決して考慮していないということです。変更後に最大限の効果を発揮することは、何もしないよりも良いことはないからです。 これにより、単一のソート済みリストへの縮小が可能になります。 

## 実用的な例

 3 回の攻撃がある小規模なインスタンスを考えてみましょう。 

A = [1, 5, 2]、B = [3, 4, 2]、C = [10, 20, 30] があるとします。 Ai ≧ Bi を満たす攻撃 2 と攻撃 3 のみがベースライン ダメージとなります。 したがって、底 = 20 + 30 = 50 となります。 

候補リストは、元々失敗した攻撃のみで構成されます。 1 < 3 なので (B1, C1) = (3, 10) となり、これは攻撃 1 です。 ソート後も [(3, 10)] が残り、プレフィックスの最大値は [10] になります。 

クエリ X = 2 の場合、Bi ≤ 2 となる候補は存在しないため、ゲインは 0 となり、答えは 50 になります。 

| ステップ | 値 |
 | --- | --- |
 | ベース | 50 |
 | 候補者 | (3,10) |
 | X = 2 有効範囲 | なし |
 | ゲイン | 0 |
 | 答え | 50 |

 これにより、小さな X では改善を実現できないことがわかります。 

ここで X = 3 について考えてみましょう。 

| ステップ | 値 |
 | --- | --- |
 | ベース | 50 |
 | 候補 ≤ X | (3,10) |
 | 最高のゲイン | 10 |
 | 答え | 60 |

 ここでは攻撃 1 をアップグレードして成功させ、10 ダメージを追加できます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    data = inp.strip().split()
    it = iter(data)

    t = int(next(it))
    out = []

    for _ in range(t):
        n = int(next(it))
        q = int(next(it))
        A = [int(next(it)) for _ in range(n)]
        B = [int(next(it)) for _ in range(n)]
        C = [int(next(it)) for _ in range(n)]

        base = 0
        cand = []
        for i in range(n):
            if A[i] >= B[i]:
                base += C[i]
            else:
                cand.append((B[i], C[i]))

        cand.sort()
        pref = []
        best = 0
        for b, c in cand:
            best = max(best, c)
            pref.append(best)

        import bisect

        for _ in range(q):
            x = int(next(it))
            idx = bisect.bisect_right(cand, (x, 10**18)) - 1
            gain = 0
            if idx >= 0:
                gain = pref[idx]
            out.append(str(base + gain))

    return "\n".join(out)

# custom cases

# 1) minimum size, no improvement possible
assert run("1\n1 1\n5\n10\n100\n1") == "0"

# 2) single improvable attack
assert run("1\n1 1\n1\n5\n10\n5") == "10"

# 3) multiple candidates, prefix behavior
assert run("1\n3 2\n1 1 1\n2 3 4\n5 6 7\n2 3") == "6\n7"

# 4) mix of base + improvement
assert run("1\n3 1\n5 1 3\n3 2 4\n10 20 30\n3") == "60"

 | --- | --- | --- |
 | 単一の失敗 | 0 | 候補者が貢献していない |
 | 単一の改善 | 10 | しきい値での正しいアクティベーション |
 | 複数のクエリ | 6、7 | プレフィックスの最大正確性 |
 | ミックスベース + ゲイン | 60 | ベースと改善の組み合わせ |

 ## 特殊なケース

 重要なエッジケースの 1 つは、すべての攻撃がすでに成功している場合です。 この状況では、候補リストは空であるため、すべてのクエリは変更されないベースを返す必要があります。 プレフィックス配列が空であり、有効なインデックスを生成するバイナリ検索一致がないため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、X が失敗した攻撃のすべての Bi よりも小さい場合です。 それでは改善は不可能です。 二分探索では -1 が返され、ゲインは 0 のままです。これは、攻撃をアップグレードできないという事実と一致します。 

最後のケースは、失敗した複数の攻撃が同じ Bi を共有するが、異なる Ci 値を共有する場合です。 並べ替えによりそれらがグループ化され、有効なプレフィックス内の最大値のみを考慮するため、プレフィックスの最大値により、重複に関係なく常に最適な Ci が選択されます。
