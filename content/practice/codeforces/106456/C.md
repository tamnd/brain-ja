 ## 解決策
 ## 問題の理解

 各セルに負でない整数が含まれるグリッドが与えられます。 旅行者は左上のセルから開始し、右下のセルに到達する必要があります。 移動は 4 方向に許可されており、セルは何度でも再訪問できます。 

パスは、通常の意味では長さやコストによって評価されません。 代わりに、セルが再訪問されたときの繰り返しを含む、パスに沿って遭遇した一連の値を取得します。 このシーケンスから、すべての訪問値に対するビット単位の OR と、すべての訪問値に対するビット単位の AND の 2 つの量を計算します。 

目標は、最初に訪問したすべての値の OR を最小化する、最初から最後までの有効なパスを選択することです。 この最小の OR を達成するすべてのパスの中で、AND を最大化します。 

主な問題は、ノードを再訪問しても OR または AND が有益な方法で変更されないことです。 OR または AND で値を繰り返すことはべき等であるため、再訪の唯一の効果は、新しい値を導入せずに接続を支援することです。 これは、問題は基本的に、両方のエンドポイントを含む接続されたグリッド セルのセットの選択に関するものであり、接続性はグリッドの意味であることを意味します。 

選択された各セルは、その値を OR および AND 集計に組み込みます。 パスの OR は、選択した接続領域内のすべての値のビット単位の OR です。一方、AND は、その領域内のすべての値のビット単位の AND です。 

この制約は、テスト ケース全体で合計最大 2 × 10^5 セルを意味し、値は 30 ビット以内に収まります。 グリッド内のパスの数は指数関数的に増加するため、すべてのパスを明示的に探索するものは除外されます。 ビットマスクを状態ごとに直接エンコードすると、展開された状態の最短パスのバリアントでも大きすぎます。 

どちらの目標にも微妙な点が現れます。 OR 目的はすべての訪問ノードにわたるビットの結合に依存しますが、AND 目的はすべての訪問ノードにわたるビットの交差に依存します。 これら 2 つの目的は反対の単調な方向に動作するため、単一の DP を直接定式化することが困難になります。 

素朴な推論による失敗例の 1 つは、最短パスで十分であると仮定することです。 たとえば、ステップを最小限に抑えるパスには、初期に高値のセルが含まれ、OR が不必要に増加する可能性があります。 

別の失敗例は、OR 最小化をステップごとに独立したものとして扱っていることです。 たとえば、最小値の近傍をローカルに選択すると、後でパスが高ビット セルを必要とするようにトラップされ、OR がグローバルに増加する可能性があります。 

## アプローチ

 ブルートフォース手法では、考えられるすべての単純なパスを最初から最後まで列挙し、それぞれの OR と AND を計算します。 たとえ再訪問を禁止したとしても、グリッド内の単純なパスの数は n と m で指数関数的になるため、これは直ちに実行不可能になります。 

より構造化されたブルート フォースのアイデアは、各パスを一連の決定として扱い、位置と訪問セットによって定義された状態に対して DFS または BFS を実行することです。 訪問セットのみのサイズが 2^(nm) であるため、これでも爆発します。 

重要な観察は、OR と AND の両方が順序や多重度ではなく、訪問したセルのセットのみに依存するということです。 パス内のどのサイクルも最終的な OR または AND を変更しないため、有効なウォークを訪問セット上のスパニング ツリーに圧縮できます。 これにより、両方のエンドポイントを含む接続されたセルのセットを選択するという問題が軽減されます。 

次に、2 つの目的を分離します。 

OR の最小化については、各ビットを独立して考えてください。 候補 OR マスク B を決定する場合、値が B の外側のビットを含まないセルのみを使用するように制限します。問題は、(1,1) と (n,m) が有効なセルによって誘導されたサブグラフ内で接続されているかどうかになります。 最適な OR は、接続を可能にする最小のマスクです。

30 ビットしかないので、欲張ってすべてのビットを設定した状態から始めて、上位から下位まで 1 つずつ削除してみることができます。 暫定的にビットを削除した後、BFS を使用して接続を確認します。 接続が維持されている場合、そのビットは OR ではまったく不要になります。 

最小の OR マスクを修正した後、AND 目的に進みます。 ここでは、その OR マスクで許可されているセルのみを考慮します。 これらの中で、すべての訪問値のビット単位の AND を最大化するパスが必要です。 ビットは、パス上のすべてのセルにそのビットが含まれている場合にのみ、最後の AND に出現できます。 したがって、候補 AND マスク C の場合、訪問したすべてのセルに C のすべてのビットが含まれるパスが必要です。 

これもフィルタリングされたグラフでの接続チェックとなるため、BFS を使用して毎回実現可能性をテストしながら、AND マスクを少しずつ貪欲に構築できます。

 ## アルゴリズムのチュートリアル

 ### OR 最小化フェーズ

 1. 30 ビットすべてが設定されているマスク B から始めます。 これにより、すべてのセルが最初から許可されることが保証されます。 
2. ビットを上位から下位に処理します。 各ビットについて、B から暫定的に削除し、候補 B' を形成します。 
3. BFS を最初から実行し、値に B' の外側のビットが含まれていないセルのみを訪問します。 端に手が届く場合は、ビットを取り外したままにしておきます。 それ以外の場合は復元します。 
4. すべてのビットが処理された後、B は有効なパスを許可する最小の OR マスクです。 

BFS ステップでは、制約された接続性の問題、つまり、現在のマスクと互換性のない値を持つすべてのセルを削除したときにグリッドが接続されたままであるかどうかをチェックします。 

### AND 最大化フェーズ

 1. グリッドを B と互換性のあるセルのみに制限します。 
2. AND マスク C を 0 に初期化します。 
3. 高位から低位までの各ビットについて、C に暫定的に設定して C' を形成します。 
4. BFS を再度実行します。ただし、値に C' のすべてのビットが含まれるセルの走査のみを許可します。 接続が維持されている場合は、ビットを保持します。 それ以外の場合は破棄します。 
5. 最後の C は、最小の OR 制約に従ってすべてのパス間で達成可能な最大の AND です。 

### なぜ効果があるのか

 正確さは、両方の目的がビットごとのフィルターの下での接続の実現可能性に帰着するという事実に依存します。 OR の場合、実現可能性はすべての訪問ノードから禁止ビットを除外するかどうかによって異なります。 AND の場合、実現可能かどうかは、訪問したすべてのノードで必要なビットを強制するかどうかによって決まります。 どちらの制約も、ビットセットに対するモノトーン プロパティを定義します。制約を追加すると、使用可能なセルのセットが縮小されるだけで、拡張されることはありません。 この単調性により、貪欲なビット修正が有効になります。これは、ビットが不要 (または必要) であることが証明されると、その決定がその後のすべての選択に対して一貫性を保つためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

DIRS = [(1,0),(-1,0),(0,1),(0,-1)]

def bfs(n, m, grid, allowed_mask, require_mask):
    if (grid[0][0] & allowed_mask) != grid[0][0]:
        return False
    if (grid[0][0] & require_mask) != require_mask:
        return False
    if (grid[n-1][m-1] & allowed_mask) != grid[n-1][m-1]:
        return False
    if (grid[n-1][m-1] & require_mask) != require_mask:
        return False

    vis = [[False]*m for _ in range(n)]
    q = deque([(0,0)])
    vis[0][0] = True

    while q:
        x,y = q.popleft()
        if x == n-1 and y == m-1:
            return True
        for dx,dy in DIRS:
            nx, ny = x+dx, y+dy
            if 0 <= nx < n and 0 <= ny < m and not vis[nx][ny]:
                v = grid[nx][ny]
                if (v & allowed_mask) == v and (v & require_mask) == require_mask:
                    vis[nx][ny] = True
                    q.append((nx, ny))
    return vis[n-1][m-1]

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    full = (1 << 30) - 1

    # OR minimization
    B = full
    for b in range(29, -1, -1):
        if B & (1 << b):
            B2 = B ^ (1 << b)
            if bfs(n, m, grid, B2, 0):
                B = B2

    # AND maximization
    C = 0
    for b in range(29, -1, -1):
        C2 = C | (1 << b)
        if bfs(n, m, grid, B, C2):
            C = C2

    print(B, C)
```BFS 機能は両方のフェーズで共有されますが、フェーズに応じて異なる制約が適用されます。 OR フェーズでは、require_mask はゼロであり、禁止されたビットのみが問題になります。 AND フェーズでは、allowed_mask が固定され、require_mask によって、訪問されたすべてのノードに含まれなければならない必須ビットが強制されます。 

実装の微妙な詳細は、BFS 前の開始ノードと終了ノードの早期拒否です。 これにより、いずれかのエンドポイントがすでに制約に違反している場合に、不必要なトラバーサルが回避されます。 もう 1 つの重要な詳細は、両方の制約が BFS 遷移チェック内で同時に保持される必要があるということです。そうしないと、誤って無効な中間ノードが許可されてしまいます。 

## 実用的な例

 異なるパスによって異なるビットが強制的に含まれる小さなグリッドを考えてみましょう。 アルゴリズムはジオメトリを直接考慮しません。 ビットによるフィルタリングが接続を維持するかどうかのみを考慮します。 

OR フェーズでは、ビットを削除すると開始と終了が切断されるとします。 BFS はターゲットに到達できず、ビットは復元されます。 これは、保持されているすべてのビットが接続に構造的に必要であることを直接示しています。 

AND フェーズでは、ビットが開始に存在するが、接続に必要な中間領域で欠落していると仮定します。 たとえエンドポイントがビットを満たしていても、すべてのステップがビット制約を維持する必要があるため、BFS は失敗します。 これは、AND がエンドポイント値だけではなくグローバル交差制約によって決定される理由を示しています。

 ## 特殊なケース

 重要なエッジ ケースは、唯一の有効なパスが高ビット セルを必要とする場合です。 その場合、OR 最小化中にそのビットを削除しようとすると BFS が失敗し、アルゴリズムがそのビットを保持することを強制されます。 セルが削除されるとエンドポイントに到達できなくなるため、BFS はこの障害を直接エンコードします。 

AND の最大化では、最適な AND がゼロの場合に別のエッジ ケースが発生します。 これは、すべての有効なパスに特定のビットを欠落しているセルが少なくとも 1 つ含まれている必要がある場合に発生します。 ビットを設定しようとするたびに接続チェックに失敗し、C が変更されないままになるため、貪欲な構築は自然に 0 に収束します。
