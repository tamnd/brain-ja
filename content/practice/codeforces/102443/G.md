 ## 解決策
 ## 問題の理解

 だけで作られた文字列があります`+`そして`-`。 元の文字を変更せずに、どこにでも中括弧を挿入できます。 挿入後、中括弧自体が有効な括弧シーケンスを形成する必要があります。つまり、左から右にスキャンして、括弧の数が決まります。`{`文字数を決して小さくしてはなりません`}`、そして 2 つのカウントは最後に等しくなければなりません。 

中括弧を挿入する理由は、隣接するハイフンのペアをすべて区切るためです。 最後の文字列では、連続する 2 つの元の文字列ごとに`-`文字には少なくとも 1 つの中括弧が必要です。 連続した`+`文字は特別な扱いを必要としません。 

すべての有効な文字列のうち、可能な限り最小限の中括弧を使用している文字列のみを保持します。 これらは最適なエスケープ文字列です。 順序を使用して辞書順に並べ替えられます。`+ < - < { < }`、タスクは、を出力することです。`k`- 番目のもの。 未満の場合`k`最適な文字列が存在するので出力します`Overflow`。 元の入力文字列は最大 60 文字ですが、`k`と同じ大きさにすることができます`10^18`。 

最初の有用な量は数値です`r`連続する 2 つの元の文字が両方とも存在する位置の数`-`。 このような位置には、少なくとも 1 つの挿入された中括弧が含まれている必要があります。 したがって、少なくとも`r`中括弧が必要です。 ただし、中括弧はバランスのとれたシーケンスを形成する必要があるため、中括弧の合計数は偶数である必要があります。 したがって、中括弧の最小数は少なくとも最小の偶数になります。`r`。 

たとえば、`s = "--"`、禁止された隣接関係が 1 つあるため、少なくとも 1 つの中括弧が必要です。 1 つの中括弧ではバランスの取れたシーケンスを形成できないため、最適化では 2 つの中括弧を使用します。 最適な 3 つの文字列は次のとおりです。`-{-}`、`-{}-`、 そして`{-}-`。 必要な位置に 1 つのブレースを使用するだけの不注意な解決策は、バランス ブレースの条件に違反します。 

もう 1 つの特殊なケースは、連続するハイフンのない文字列です。 たとえば、```
-+-+
2
```エスケープするものは何もないので、最適な文字列は次のとおりです。`-+-+`。 以来`k = 2`、正しい出力は次のとおりです。`Overflow`。 タスクでは挿入される中括弧の最小数が要求されるため、常に一対の中括弧を挿入する解決策は間違っています。 こちらも公式サンプルの1つです。 

文字列の先頭と末尾の空のギャップ位置も中括弧の正当な場所です。 のために`s = "--"`、文字列`{-}-`中括弧が 2 つのハイフンの間になくても、これは最適です。 左中括弧は最初のハイフンの前にあり、右中括弧はハイフンの間にあるため、必要なギャップは保護され、中括弧のバランスが保たれます。 不正なギャップに直接中括弧を挿入することのみを考慮する実装では、この文字列が見逃されます。 

60 という長さの制限は、状態が複数の次元を持つ動的プログラムには十分小さいですが、エスケープされた文字列をすべて列挙するには大きすぎます。 値`k <= 10^18`また、カウントに上限を設ける必要があることも示しています。`10^18`: 状態に少なくともその数の完了があると、その正確なより大きな値が答えに影響を与えることはありません。 

## アプローチ

 直接的な総当たりの解決策では、中括弧を挿入するあらゆる可能な方法を試し、結果の中括弧シーケンスのバランスが取れているかどうかを確認し、連続するハイフンのペアをすべてチェックして、最小数の中括弧を持つ文字列のみを保持することができます。 エスケープ文字列の可能性がすべて考慮されるため、これは正しいです。 問題は検索スペースです。 最適なソリューションには、元の文字が最大 60 個あり、最悪の場合でも中括弧が最大 60 個あります。 4 つの可能な出力文字を含む文字ごとの検索ツリーの深さは最大 120 で、大まかな上限が与えられます。 

[
 1 + 4 + 4^2 + \dots + 4^{120}
 = \frac{4^{121}-1}{3},
 】

 それはおおよそです`2^240 / 3`ノード。 有効なバランスの取れた中括弧文字列をさらに慎重に総当たり的に列挙するだけでも、指数関数的になります。 60 個の中括弧の場合、1 秒で生成できるものをはるかに超える、カタルーニャ語スケールの可能性がすでに存在します。 

すべての選択をローカルでチェックでき、最終的な妥当性条件が単純であるため、ブルート フォースが機能します。 多くの異なるプレフィックスが将来まったく同じ可能性を持っているため、これは失敗します。 たとえば、消費された元の文字の数、挿入された中括弧の数、現在の中括弧のバランス、および現在のギャップにすでに中括弧が挿入されているかどうかがわかれば、その時点より前の正確な履歴は重要ではなくなります。 

この観察により、問題は有限状態の動的プログラムに変わります。 このような各状態から最適な完了の数を数えます。 これらのカウントが利用可能になると、辞書編集的なランク付けが簡単になります。各位置で、必要な順序で次に考えられる文字を考慮します。`+`、`-`、`{`、`}`、各選択肢で始まる完全な最適な文字列がいくつあるかを尋ね、その選択肢を採用するか、そのブロック全体をスキップします。 

ただ微妙な点は、オリジナルキャラクター間のギャップをどう表現するかです。 仮定する`i`すでにオリジナルキャラクターも排出されている。 現在直前に穴埋め中です`s[i]`、または最後のギャップの場合`i == n`。 もし`s[i-1]`そして`s[i]`両方です`-`、このギャップは、放出を許可される前に少なくとも 1 つの中括弧を受け取る必要があります。`s[i]`。 単一のブール値は、それがすでに発生したかどうかを記録します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 最適 |`O(n B²)`|`O(n B²)`| 承認済み |

 ここ`B`中括弧の最小数です。`B <= 60`。 

## アルゴリズムのチュートリアル

 1. 隣接するすべてのペアを数える`s[i - 1] = s[i] = '-'`。 この番号に電話してください`r`。 このようなギャップには少なくとも 1 つの中括弧が必要であるため、有効な解決策ではこれより少ない中括弧を使用することはできません。`r`ブレース。 
2. コンピューティング`B`、中括弧の最小数。以上の最小の偶数です。`r`。 中括弧はバランスのとれた括弧シーケンスを形成するため、その合計数は偶数である必要があります。 値`B`常に達成可能です。少なくとも 1 つのブレースを必要なギャップごとに配置し、残りのブレースを使用してバランスの取れたシーケンスを完成させます。 
3. 動的プログラミング状態を定義する`(i, balance, used, has)`。 ここ`i`はすでに出力されている元の文字の数です。`balance`は現在一致しない数です`{`キャラクター、`used`これまでに挿入された中括弧の総数です。`has`現在のギャップにすでに少なくとも 1 つの中括弧が含まれているかどうかを示します。 
4. 状態から、挿入を検討します`{`。 未満の場合、これは合法です`B`中括弧が使用されています。 増えます`balance`、増加します`used`、現在のギャップに中括弧があることをマークします。 
5. 挿入を検討する`}`。 これは次の場合にのみ合法です`balance > 0`以下よりも少ない`B`中括弧が使用されています。 減少します`balance`、増加します`used`、また、現在のギャップに中括弧があることをマークします。 終了中括弧は、中括弧シーケンスが無効になるため、残高ゼロでは発行できません。 
6.次のオリジナルキャラクターの排出を検討する`s[i]`。 これは、現在のギャップが必須のハイフン ギャップの 1 つではない場合、または`has`それはすでに真実です。 オリジナルキャラクターを排出後、進行`i`そしてリセット`has`次のギャップに入ったため、 false に設定されます。 
7. すべての元の文字が出力されると、終了状態に達します。 その時点では、正確に一致する状態のみが表示されます。`B`挿入された中括弧とバランスゼロは有効です。 最後のギャップには中括弧を含めることができるため、DP は次の場合でも中括弧を挿入し続けます。`i == n`。 
8. すべての状態からの有効な完了の数をメモします。 以来`k`せいぜい`10^18`、すべてのカウントの上限は次のとおりです`10^18`。 これより大きいカウントは、どちら側かを判断するのに区別がつきません。`k`彼らは横たわっています。 
9. 答えを構築する前に、初期状態のカウントを検査します。 より小さい場合`k`、印刷`Overflow`。 
10. それ以外の場合は、左から右に答えを作成します。 各状態で、辞書編集順に次の可能性のある文字を検査します。 のために`+`または`-`、オリジナルキャラクターの選択肢は最大でも1つです。 のために`{`そして`}`、DP はそのキャラクターを取得した後の完了数を示します。 ブランチに含まれる内容が以下の場合`k`文字列、そのカウントをから引きます`k`そして次の文字を試してください。 それ以外の場合は、文字を追加してその状態に移行します。 

不変条件は、すべての DP 状態が、将来の有効性に影響を与える可能性のある情報 (元の文字列がどのくらい残っているか、使用可能な中括弧の数、現在の括弧のバランス、および現在必要なギャップが既に保護されているかどうか) を正確に表していることです。 したがって、すべての法的継続は 1 回だけカウントされます。 ランク付け解除中、辞書順では、すべての補完が次の文字に従って連続したブロックに分割されるため、完全なブロックをスキップして、次の文字を含むブロックに降順します。`k`常に正しい文字列を選択します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 10**18

def solve():
    s = input().strip()
    k = int(input())
    n = len(s)

    required = 0
    for i in range(1, n):
        if s[i - 1] == '-' and s[i] == '-':
            required += 1

    B = required
    if B % 2:
        B += 1

    memo = {}

    def add_cap(a, b):
        x = a + b
        return LIMIT if x > LIMIT else x

    def count(i, balance, used, has):
        key = (i, balance, used, has)
        if key in memo:
            return memo[key]

        if used > B or balance > B:
            return 0

        if i == n:
            if used == B and balance == 0:
                return 1

            if used == B:
                return 0

        ans = 0

        # Try inserting '{'.
        if used < B:
            ans = add_cap(ans, count(i, balance + 1, used + 1, True))

        # Try inserting '}'.
        if used < B and balance > 0:
            ans = add_cap(ans, count(i, balance - 1, used + 1, True))

        # Try emitting the next original character.
        if i < n:
            required_gap = (
                i > 0 and
                s[i - 1] == '-' and
                s[i] == '-'
            )

            if not required_gap or has:
                ans = add_cap(ans, count(i + 1, balance, used, False))

        memo[key] = ans
        return ans

    total = count(0, 0, 0, False)

    if total < k:
        print("Overflow")
        return

    ans = []
    i = 0
    balance = 0
    used = 0
    has = False

    while not (i == n and used == B and balance == 0):
        choices = []

        # Original character, if legal.
        if i < n:
            required_gap = (
                i > 0 and
                s[i - 1] == '-' and
                s[i] == '-'
            )

            if not required_gap or has:
                choices.append((s[i], (i + 1, balance, used, False)))

        # Opening brace.
        if used < B:
            choices.append(('{', (i, balance + 1, used + 1, True)))

        # Closing brace.
        if used < B and balance > 0:
            choices.append(('}', (i, balance - 1, used + 1, True)))

        choices.sort(key=lambda x: x[0])

        for ch, state in choices:
            ni, nb, nu, nh = state
            ways = count(ni, nb, nu, nh)

            if ways < k:
                k -= ways
            else:
                ans.append(ch)
                i, balance, used, has = state
                break

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```最初のループでは、中括弧を含める必要があるギャップの正確な数をカウントします。 その価値観から、`B`偶数に切り上げたものになります。 特別な場合`B = 0`同じ DP では当然元の文字列のみが許可されるため、個別の処理は必要ありません。 

の`count`関数は中心となる動的プログラムです。 の`i == n`発行する元の文字が残っていないため、ケースは遷移ロジックの前に処理されますが、最終ギャップに中括弧を配置する必要がある場合があります。 州はすべての場合にのみ受け入れます`B`中括弧が使用されており、残高はゼロです。 

の`required_gap`式は間のギャップを正確にチェックします`s[i - 1]`そして`s[i]`。 これが、条件が使用する理由です`i > 0`そして`i < n`周囲のブランチを介して暗黙的に。 の`has`flag は、元の文字が発行された後にのみリセットされるため、その文字の前に挿入された中括弧はすべて同じギャップに属します。 

辞書編集上の構成は元の文字を意図的に考慮しており、`{`、 そして`}`それらを個別に並べ替え、実際の文字値で並べ替えます。 以来`+ < - < { < }`, Python の通常の文字列の順序付けでは、必要な順序がすでに与えられています。 

Python には整数オーバーフローの問題はありませんが、明示的な上限は`10^18`DP 内の個別の整数値の数を制限し、ランク付け解除プロセスに必要な唯一の精度を反映します。 上限は、DP 全体が評価された後ではなく、追加のたびに適用されます。 

## 実用的な例

 最初の公式サンプルでは、`s = "++--"`そして`k = 2`。 不良ギャップが 1 つあるため、中括弧の最小数は 2 つです。 最適な文字列は次のように並べられます。`++-{-}`、`++-{}-`、`++{-}-`、`+{+-}-`、 そして`{++-}-`。 したがって、2 番目のものが答えになります。 サンプルとこの順序は元のステートメントに記載されています。 

|`i`|`balance`|`used`|`has`| 選択されたプレフィックス |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 偽 |`+`|
 | 1 | 0 | 0 | 偽 |`++`|
 | 2 | 0 | 0 | 偽 |`++-`|
 | 3 | 0 | 0 | 偽 |`++-`|
 | 3 | 1 | 1 | 本当 |`++-{`|
 | 4 | 0 | 2 | 偽 |`++-{}`|
 | 4 | 0 | 2 | 偽 |`++-{}-`|

 最初の 2 つの位置では、元のプラスで始まる唯一の最適な文字列が辞書編集上最も古いブロックを形成します。 最初のハイフンでは、最初の候補も強制されます。 必要なギャップ内で選択`}`残高がゼロなのですぐには無理なので、`{`が選択されます。 左中括弧が挿入されると、次の元のハイフンは辞書編集上、次のハイフンよりも小さくなります。`}`したがって、アルゴリズムはペアを閉じる前にそれを発行します。 これにより、`++-{}-`。 

公式サンプル第二弾は、`s = "-+-+"`。 連続するハイフンはありませんので、`B = 0`。 最適なエスケープ文字列は元の文字列自体だけです。 以来`k = 2`、初期の DP カウントは 1 であり、アルゴリズムはすぐに出力します。`Overflow`。 

|`i`|`balance`|`used`|`has`| 選択されたプレフィックス |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 偽 |`-`|
 | 1 | 0 | 0 | 偽 |`-+`|
 | 2 | 0 | 0 | 偽 |`-+-`|
 | 3 | 0 | 0 | 偽 |`-+-+`|

 中括弧がゼロで十分な場合、最適な文字列では中括弧は許可されないため、補完は 1 つだけになります。 要求された 2 番目の完了は存在しません。 

## 複雑さの分析

 しましょう`n <= 60`元の文字列の長さであり、`B <= 60`中括弧の最小数になります。 

| 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(n B²)`| がある`O(n B²)`関連する状態があり、それぞれに一定サイズの遷移があります。 |
 | スペース |`O(n B²)`| メモ化テーブルには、状態ごとに 1 つの上限付きカウントが保存されます。 |

 追加のブール値`has`状態数を 2 倍にするだけなので、漸近的な複雑さは変わりません。 と`n`そして`B`どちらも最大 60 ですが、状態数は 100 万を余裕で下回っており、問題の 1 秒および 512 MB の制限に適合します。 

## テストケース```python
import sys
import io
from functools import lru_cache

LIMIT = 10**18

def solve_string(inp: str) -> str:
    data = inp.strip().split()
    s = data[0]
    k = int(data[1])
    n = len(s)

    required = sum(
        1 for i in range(1, n)
        if s[i - 1] == '-' and s[i] == '-'
    )

    B = required if required % 2 == 0 else required + 1

    @lru_cache(None)
    def count(i, balance, used, has):
        if used > B or balance > B:
            return 0

        if i == n:
            return int(used == B and balance == 0)

        ans = 0

        if used < B:
            ans = min(
                LIMIT,
                ans + count(i, balance + 1, used + 1, True)
            )

            if balance > 0:
                ans = min(
                    LIMIT,
                    ans + count(i, balance - 1, used + 1, True)
                )

        required_gap = (
            i > 0 and
            s[i - 1] == '-' and
            s[i] == '-'
        )

        if not required_gap or has:
            ans = min(
                LIMIT,
                ans + count(i + 1, balance, used, False)
            )

        return ans

    if count(0, 0, 0, False) < k:
        return "Overflow"

    ans = []
    i = balance = used = 0
    has = False

    while not (i == n and used == B and balance == 0):
        choices = []

        if i < n:
            required_gap = (
                i > 0 and
                s[i - 1] == '-' and
                s[i] == '-'
            )

            if not required_gap or has:
                choices.append(
                    (s[i], (i + 1, balance, used, False))
                )

        if used < B:
            choices.append(
                ('{', (i, balance + 1, used + 1, True))
            )

            if balance > 0:
                choices.append(
                    ('}', (i, balance - 1, used + 1, True))
                )

        choices.sort()

        for ch, state in choices:
            ways = count(*state)
            if ways < k:
                k -= ways
            else:
                ans.append(ch)
                i, balance, used, has = state
                break

    return ''.join(ans)

assert solve_string("++--\n2\n") == "++-{}-", "sample 1"

# Provided sample 2
assert solve_string("-+-+\n2\n") == "Overflow", "sample 2"

# Minimum-size input
assert solve_string("+\n1\n") == "+", "minimum-size input"

# Boundary case: all optimal strings for "--" are
# -{-}, -{}-, {-}-
assert solve_string("--\n1\n") == "-{-}", "first lexicographic answer"
assert solve_string("--\n2\n") == "-{}-", "second lexicographic answer"
assert solve_string("--\n3\n") == "{-}-", "last lexicographic answer"
assert solve_string("--\n4\n") == "Overflow", "past last answer"

# Maximum-size input, all characters equal
assert solve_string("+" * 60 + "\n1\n") == "+" * 60, "maximum-size input"
