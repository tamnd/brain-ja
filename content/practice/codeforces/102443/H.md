8. 新しい数字が`9`、 追加`9 * 10^k`、 どこ`k`すでに構築されているサフィックスの桁数です。 これにより、現在のサフィックスからプレフィックスが直接変更されます。`S`の中へ`9S`なので、削除する必要はありません。

### なぜ効果があるのか

 最初のフェーズの不変条件は、位置を処理した後のものです。`j`、レジスタには、位置で始まる 10 進数のサフィックスが正確に含まれています。`j+1`。 数字の場合`d >= 1`、アイデンティティ`d + 9 * 123...d = 11...110`正確に作成します`d`したがって、これらを削除すると、処理された数字が正確に削除されます。 乗算`10^k`サフィックスの位置を保持します。 したがって、処理されたすべての数字は、未処理の数字を変更することなく削除されます。 

第 2 フェーズでは、すでに構築されているサフィックスが次のようになっていると仮定します。`S`そして次のターゲット桁は`d < 9`。 多数のフォームを作成します`111...1 d S`と`9-d`主導的なもの。 その桁の合計が次の桁の合計を超えています`S`まさに`9`、したがって、次のようになります。`S`モジュロ9。 したがって、それらの差は 9 で割り切れ、加算演算によって生成できます。 を削除した後、`9-d`先頭のもの、レジスターは正確になります`dS`。 のために`d = 9`、の直接加算`9 * 10^k`与える`9S`。 したがって、すべてのターゲット数字を正しく先頭に追加できます。 

最初のフェーズは常に 0 で終了し、2 番目のフェーズは 0 で開始するため、2 つのフェーズは独立しています。 すべての演算は構造上正当であり、すべての中間値には制限があるため、最終レジスタは正確に`b`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_to_zero(s):
    ops = []
    n = len(s)

    for i, ch in enumerate(s):
        d = ord(ch) - ord('0')

        if d == 0:
            continue

        # 123...d
        c = 0
        for x in range(1, d + 1):
            c = c * 10 + x

        k = n - 1 - i
        x = c * (10 ** k)

        ops.append(("+", x))
        ops.append(("-", d))

    return ops

def build_from_zero(s):
    ops = []
    n = len(s)

    for i in range(n - 1, -1, -1):
        d = ord(s[i]) - ord('0')
        k = n - 1 - i

        if d == 0:
            # A zero cannot be introduced by deleting leading ones,
            # but it is already represented by the positional suffix.
            continue

        if d == 9:
            # Add 9 * 10^k, which simply prepends digit 9.
            ops.append(("+", 10 ** k))
            continue

        # We want:
        #
        #   111...1 d S
        #
        # with 9-d leading ones.
        #
        # The difference from S must be divisible by 9.
        c = 0
        for x in range(1, 9 - d):
            c = c * 10 + x
        c = c * 10 + (10 - d)

        x = c * (10 ** k)

        ops.append(("+", x))
        ops.append(("-", 9 - d))

    return ops

def solve():
    a, b = input().split()

    ops = build_to_zero(a)
    ops.extend(build_from_zero(b))

    print("Stable")
    print(len(ops))
    for typ, value in ops:
        print(typ, value)

if __name__ == "__main__":
    solve()

ループ構築`c`意図的に数字を使っている`1`を通して`d`。 結果として得られるアイデンティティは、最初のフェーズの核心です。 たとえば、`d = 3`、`c = 123`、 そして`3 + 9 * 123 = 1110`。 

の`build_from_zero`関数は方向を反転します。 その`k`すでに右側に構築されているターゲット位置の数をカウントします。 からの数字の場合`1`を通して`8`、の値`c`9 を乗算した後に作成される数値が正確に含まれるように選択されます。`9-d`主導的なもの。 その後の削除では、それらの数字が削除され、既存のサフィックスの前に目的の数字が残ります。 

の`d == 9`ケースは別なので`9-d`はゼロです。 削除するものは何もないので追加します`9 * 10^k`を挿入するだけです`9`正しい位置で。 

ゼロは構築時に明示的な操作を必要としません。 これらは後のステップで位置乗算によって処理されます。 このため、レジスタ自体は整数を格納する場合でも、元の入力を文字列として保持する必要があります。 

Python の整数はオーバーフローしませんが、その構築では問題の数値限界も考慮されます。 以下の入力の場合`10^9`、10 桁の入力のみ`1000000000`、最初の桁は`1`; したがって、構築された中間値は以下のままになります。`10^18`。 操作回数は最大 40 回です。

            s = str(value)

            assert s[:y] == "1" * y
            value = int(s[y:]) if s[y:] else 0

        assert 0 <= value <= 10**18

    assert value == b

 ## 特殊なケース

 のために`a = 0`そして`b = 0`、両方の構築関数は空の操作リストを返します。 アルゴリズムは出力します`Stable`そして`0`これはまさに最も単純な有効な変換です。 人工的なものはありません`+`または`-`操作が必要です。 

ゼロを含む数値については、次のように考えます。`a = 100`。 最初の桁は`1`, したがって、アルゴリズムは追加します`10^2`オブジェクト、つまりレジスタが増加します`900`、変化する`100`の中へ`1000`。 先頭を削除する`1`葉`0`。 残りの 2 つのゼロ桁は演算を生成しません。 これは、最初の桁の処理中に使用される 10 の累乗によって位置がすでに計算されているため、機能します。 

ゼロを含むターゲットについては、次のことを考慮してください。`b = 900000009`。 アルゴリズムは最終的なものを構築します`9`初め。 間にあるゼロは明示的な操作を必要としません。`9`が挿入されると、その 10 乗はすでに既存のサフィックスから 9 位置離れた位置に配置されます。 したがって、この構造ではゼロを個別に製造するのではなく、位置的なギャップとしてゼロを作成します。 

数字の場合`9`の場合、一般的な削除構造では先頭に 0 が必要になりますが、これは有効な削除操作ではありません。 アルゴリズムは、以下を追加することでこのケースを個別に処理します。`10^k`オブジェクトが増加し、`9 * 10^k`。 これは数字を直接先頭に追加します`9`なので、削除する必要はありません。 

数字の場合`1`、逆の極端な現象が発生します。 ゼロから構築する場合、先頭に 8 つの 1 が必要です。 例えば、`0 + 9 * 12345679 = 111111111`; 先頭の 8 つの葉を削除する`1`。 番号`12345679`任意ではありません。 その桁の合計は`37`、結果として得られる積は、必要な 10 進構造を正確に持ちます。 

最大入力の場合`1000000000`、最初のフェーズでは、最初の構築のみが実行されます。`1`。 操作で使用するのは、`10^9`、生産`10^10`、先頭のものを削除するとゼロになります。 残りのゼロには演算の必要はありません。 この事例では、その理由も説明されています。`10^18`境界は安全です。制約によって許可される 10 桁の入力のみがこの特別な形式を持つため、ゼロ以外の大きな桁で始まる 10 桁の数値に遭遇することはありません。 

最後の微妙な点は、出力シーケンスが最小限である必要はないということです。 のために`1 -> 9`、サンプルは 2 つの操作構造になっていますが、シンプルなサンプルは`a -> 0 -> b`構築には3つを使用します。 後者が長いという理由で拒否すると、出力要件を誤解することになります。 重要な制限は合法性だけです。`1000`操作限界、`10^18`中間限界に達し、正確な目標に到達します。
