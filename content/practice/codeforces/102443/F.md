 ## 問題の理解

 正多角形は、円の周囲にすべての頂点が等間隔に配置されています。 3 つの頂点が多角形から来ており、辺の長さに少なくとも 1 つの等しいペアが含まれるすべての三角形を数えなければなりません。 

主な問題点は、ポリゴンが 10 9 個もの頂点を持つ可能性があることです。 頂点やトリプルを明示的に調べるアプローチは機能しません。 O(n) でさえ制限時間にはすでに大きすぎるため、目的の解決策では、答えを一定数の算術演算に減らす必要があります。 

微妙なカウン​​トの問題もあります。 二等辺三角形の頂点として頂点を選択すると、他の 2 つの頂点をその頂点の周りに対称的に配置できます。 通常の二等辺三角形はすべて 1 回カウントされますが、正三角形には可能な頂点が 3 つあるため、3 回カウントされます。 私たちはまさにそのケースを正さなければなりません。 

たとえば、入力 3 の場合、多角形自体は正三角形です。 各頂点を頂点として選択できるため、直接頂点ベースの数は 3 になります。 正解は 1 なので、単純に対称ペアを数えると正三角形の数を超えてしまいます。 

もう 1 つのエッジ ケースは、均等なサイズのポリゴンです。 n=4 の場合、頂点の両側で反対側の頂点を選択すると、同じポリゴンの頂点が 2 回選択されるため、その選択は三角形を形成しません。 正しい答えは 8 ではなく 4 です。これが、有効な対称距離の数が ⌊(n−1)/2⌋ となる理由です。 

n=6 の場合、正三角形は存在します。 頂点ベースのカウントでは 6⋅2=12 となりますが、6/3=2 個の異なる正三角形があり、それぞれ 3 回カウントされます。 正三角形ごとに 2 つの追加カウントを減算し、12−2⋅2=8 を得る必要があります。

### なぜ効果があるのか

 選択したすべての頂点について、二等辺三角形の等しい辺は、頂点を、そこから等しい角距離にある 2 つの頂点に接続する必要があります。 すべてのポリゴンの頂点は等しい角度間隔にあるため、これら 2 つの頂点は、有効な k に対して反対方向にちょうど k ステップになります。 したがって、すべての二等辺三角形には少なくとも 1 つの表現がカウントされます。 

非正辺二等辺三角形には固有の頂点があるため、正確に 1 回カウントされます。 正三角形には可能な頂点が 3 つあるため、3 回カウントされます。 これらは複数の頂点表現を持つ唯一の三角形であるため、正三角形ごとに 2 つのコピーを減算すると、すべての有効な三角形が 1 回だけカウントされたままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    ans = n * ((n - 1) // 2)

    if n % 3 == 0:
        ans -= 2 * (n // 3)

    print(ans)

if __name__ == "__main__":
    solve()
```表現`(n - 1) // 2`1 つの頂点に対する有効な対称距離の数を計算します。 使用する`n - 1`それよりも`n`これは、n が偶数の場合に両側で同じ頂点を選択するのを防ぐためのものです。 

の乗算`n`考えられるすべての頂点を説明します。 Python の整数は、オーバーフローなしで最大の結果を処理します。これは、答えが 5⋅10 17 のオーダーであり、32 ビットの符号付き整数をはるかに超える可能性があるため、ここでは役に立ちます。 

割り算チェック`n % 3 == 0`唯一の過剰カウントのケースを処理します。 それが成立すると、`n // 3`は個別の正三角形の数であり、各正三角形は正確に 2 つの余分なコピーを削除する必要があります。 

頂点にわたるループがないため、アルゴリズムは、n が 3 であるか 10 9 であるかに関係なく、固定数の算術演算のみを実行します。

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline
    n = int(input())

    ans = n * ((n - 1) // 2)

    if n % 3 == 0:
        ans -= 2 * (n // 3)

    print(ans)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    try:
        sys.stdin = io.StringIO(inp)
        sys.stdout = io.StringIO()
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("3\n") == "1\n", "sample 1"
assert run("5\n") == "10\n", "sample 2"

# Minimum size, also the smallest equilateral case

# Small multiple of 3
assert run("6\n") == "8\n", "equilateral correction"

# Large odd value
assert run("999999999\n") == "499999998000000000\n", "large odd n"

# Maximum input
assert run("1000000000\n") == "499999999000000000\n", "maximum n"

 ## 特殊なケース

 n=3 の場合、アルゴリズムは頂点ごとに 1 つの対称の選択肢を計算し、3 を与えます。3∣n なので、2(3/3)=2 を減算し、1 を生成します。これは、可能な限り最小の多角形を処理し、正三角形が単純に無視できない理由を示しています。 

n=4 の場合、アルゴリズムは頂点ごとに ⌊3/2⌋=1 つの対称的な選択肢を計算し、4 を与えます。4 は 3 で割り切れないため、等辺補正はありません。結果は 4 で、正方形から 1 つの頂点を省略して得られる 4 つの三角形に対応します。 頂点から時計回りに 2 歩、反時計回りに 2 歩進むと、反対側の同じ頂点に到達するため、フロア操作は不可欠です。 

n=6 の場合、頂点ごとに対称の選択肢が 2 つあり、初期数は 12 になります。6 は 3 で割り切れるので、6/3=2 個の正三角形が存在します。 それぞれ 3 回カウントされたため、4 つの超過カウントが削除されます。 最終的な答えは、12−4=8 です。 

n=10 9 の場合、アルゴリズムは、より小さい入力の場合と同じ一定数の演算を実行します。 頂点あたりの数は次のとおりです。 

⌊ 2 10 9 −1 ⌋=499999999、

 したがって、初期カウントは

 10 9 ⋅499999999=499999999000000000。 

10 9 は 3 で割り切れないため、修正の必要はなく、その値が最終的な答えとなります。
