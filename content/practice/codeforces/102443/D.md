 ## 解決策
 ## 問題ステートメント

 (m\times n) 個のグリッドがあります。 非表示の単調パスは ((1,1)) で開始し、((m,n)) で終了し、下と右への移動のみを使用します。 その隠しパスのすべてのセルには検出器が含まれています。 

独自の単調なパスをクエリとして送信する場合があります。 インタラクターは、クエリ パスも訪問するすべての検出器セルを返します。 したがって、クエリにより、選択したパスと非表示のパスの間の交差部分が得られます。 

クエリは最大 10 件あります。 十分な情報を収集した後、正確な隠しパスを文字列として出力する必要があります。`D`そして`R`動く。 公式の制限は (1\le m,n\le1000)、(m+n>2) で、制限時間は 1 秒、メモリは 512 MB です。 

## 入力

 最初の入力行には (m) と (n) が含まれています。 その後、プログラムはインタラクターと通信します。 すべてのクエリに対して、出力します。`?`有効なパス文字列が続きます。 インタラクターは、最初に報告された検出器セルの数を返し、次にその座標を行ごと、列ごとに並べ替えて返します。 

## 出力

 隠しパスが決定したら、印刷します。`!`続いてそのシーケンス`D`そして`R`動く。 すべてのクエリと最終回答の後には改行を続ける必要があり、対話型出力はフラッシュする必要があります。 パイソンの`print`と使用するとすでにフラッシュされます`flush=True`。 

## 問題の理解

 インタラクターについて考えるのに役立つのは、単に「はい」または「いいえ」の答えではなく、正確な交差点を提供してくれるということです。 クエリが非表示パスのセルを通過すると、そのセルが応答に表示されます。 

最初は、((1,1)) と ((m,n)) だけがわかっています。 隠しパス上の 2 つの連続する既知のセルが (A=(r_1,c_1)) および (B=(r_2,c_2)) であるとします。 それらの間の隠れたパスがこれら 2 点によって定義される長方形に含まれることはわかっていますが、その曲がり角はわかりません。 

重要なのは、このような不明なセクションをすべて中央の行で分割することです。 しましょう

 [
 r_{\text{mid}}=\left\lfloor\frac{r_1+r_2}{2}\right\rfloor。 
】

 最初に行 (r_{\text{mid}}) まで進み、次に四角形全体を右に進み、最後に (B) まで進むクエリを作成します。 (A) から (B) への単調な隠しパスは行 (r_{\text{mid}}) を訪れる必要があり、その行のセルは列 (c_1) と (c_2) の間のどこかにあります。 水平部分はこれらのセルすべてをカバーしているため、2 つのパスはそこで交差する必要があります。 

その結果、すべての未知のセクションは、行の差が前の行の差の最大半分であるより小さなセクションに分割されます。 (m\le1000) なので、10 等分すれば十分です。 これは、ソリューションの背後にある二分探索構造です。 同じアイデアについての簡潔な独立した説明が、コンテストのソリューションの記事で提供されています。この記事では、クエリを 5 つの形のルートとして説明し、各クエリが残りの範囲を半分にすることが観察されています。 

微妙な点が 1 つあります。 中央の行の交点がわかっていても、新しい点を任意の動きで接続するだけでは必ずしも十分ではありません。 最後のクエリ自体は、残りの 1 行のギャップを解決する方法を示しています。 2 つの連続して報告されたポイントがちょうど 1 行だけ異なる場合、クエリの対応する部分にはちょうど 1 つの下方向への移動が含まれます。 クエリがその部分で始まる場合、`D`, the hidden path must instead start with the required right moves and go down at the end, unless the two paths coincide. クエリが次で始まる場合`R`、逆の配置が強制されます。 これが、返された座標のみを保存するのではなく、クエリ パス自体を保持する必要がある理由です。 

たとえば、((1,1)) から ((2,2)) までの (2\times2) セクションを考えてみましょう。 問い合わせてみると`DR`、次に隠しパス`DR`中間セル ((2,1)) を報告します。 そのセルが存在しない場合、非表示のパスは次のとおりである必要があります。`RD`。 この正確な違いは、この問題の独立した解決策の議論でも強調されています。 

(m=1) の場合、不注意な実装は失敗する可能性があります。 この場合、二分探索する行は存在せず、可能な唯一のパスは完全に水平になります。 たとえば、入力の場合```
1 4
```正しい最終パスは`RRR`。 この特殊なケースを使用せずに中間点プロシージャを実行しようとすると、空のクエリまたは無効なクエリが作成される可能性があります。 

別のエッジケースは (n=1) です。 唯一可能なパスは完全に垂直です。 のために```
4 1
```答えは`DDD`。 すべてのセクションに正しい手が含まれていると想定した構造では、無効なクエリが誤って生成される可能性があります。 

2 つの連続する既知の点が斜めに隣接している場合、より微妙なエッジ ケースが発生します。 たとえば、((1,3)) と ((2,4)) の間の隠しパスは次のいずれかです。`DR`または`RD`。 2 つのエンドポイントを知っているだけでは不十分です。 クエリ セグメント自体は、交差応答によって 2 つの可能性が区別されるため、検査する必要があります。 

## アプローチ

 直接的なアプローチは、考えられるすべての単調なパスを検討することです。 あります

 [
 \binom{m+n-2}{m-1}
 】

 (m+n-2) 個の動きのうち、どの (m-1) 個が下向きの動きであるかを選択するため、そのようなパスになります。 ブルート フォース ソルバーは、すべての候補パスを維持し、各クエリ応答と矛盾する候補を削除できます。 1 つの候補をチェックするには (O(m+n)) のコストがかかるため、最悪の場合の作業は次のようになります。 

[
 \シータ\left((m+n)\binom{m+n-2}{m-1}\right)。 
】

 (m=n=1000) の場合、これはおよそ (1998\binom{1998}{999}) であり、(10^{603}) 個の基本的なパスセル チェックのオーダーに相当します。 1 秒の制限により、これは完全に不可能になります。 

すべての応答が、報告されたセルを含まないパスを拒否するのに十分な情報を提供するため、ブルート フォースは概念的に機能します。 問題は、可能なパスの数が指数関数的に増加するのに対し、インタラクターが質問する機会を与えてくれるのは 10 回だけであることです。 

有益な観察は、すべての完全なパスを一度に区別する必要はないということです。 連続した確認済みセルを維持し、すべての不確実なセクションを同時に分割できます。 セクションごとに、5 の形のクエリは中央の行まで進み、セクションを右に横切って、エンドポイントまで進みます。 すべての隠れたパスは、その水平方向の中間セグメントを横切る必要があります。 したがって、1 つのクエリは、十分に大きなセクションごとに新しい確認済みポイントを同時に提供します。 

結果として得られるすべてのセクションの行距離は、四捨五入までの最大でも古い行距離の半分になります。 最大行距離は (999) のみなので、10 個のクエリで十分です。 最後の 1 行セクションは、最後のクエリの形状とその報告された交差から直接解決されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O((m+n)\binom{m+n-2}{m-1})) | 指数 | 遅すぎる |
 | 最適 | (O(10(m+n))) | (O(m+n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (m) と (n) を読み取ります。 (m=1) の場合、パスは強制的に次のようになります。`R`(n-1) 回繰り返します。 (n=1) の場合、強制的に`D`(m-1) 回繰り返します。 このようなケースではクエリは必要ありません。 
2. それ以外の場合は、確定点を((1,1))と((m,n))のみで初期化します。 これらは、必ず非表示のパスに属します。 
3. 連続する確認点 (A=(r_1,c_1)) と (B=(r_2,c_2)) の各ペアについて、(r_{\text{mid}}=\lfloor(r_1+r_2)/2\rfloor) を計算します。 クエリセグメントを次のように構築します`D`(r_{\text{mid}}-r_1) 回繰り返した後、`R`(c_2-c_1) 回繰り返した後、`D`(r_2-r_{\text{mid}}) 回繰り返しました。 これらのセグメントを連結すると、((1,1)) から ((m,n)) までの 1 つの完全な有効なパスが得られます。 
4. このパスをクエリとして送信し、報告されたすべての検出器座標を読み取ります。 現在確認されている点列をこれらの報告された座標に置き換えます。 どちらのパスも単調であり、インタラクターは行ごとに座標を報告し、次に列ごとに座標を報告するため、これらはすでにパスの順序でソートされています。 
5. 連続して報告されたポイントの各ペア間の行の差を確認します。 このような違いがすべて最大 1 つである場合は、クエリを停止します。 それ以外の場合は、新たに確認した点を使用して構築を繰り返します。 
6. クエリの数が制限されている理由を確認するには、行の差 (d) のある古いセクションを考えてみましょう。 クエリにはそのセクションの中央の行全体が含まれており、非表示のパスはそれに一致する必要があります。 その行で新しく報告されたポイントにより、セクションは行の違いが最大 (\lceil d/2\rceil) の部分に分割されます。 したがって、10 回のクエリの後、最初は最大 (999) だった差が最大 1 になります。 
7. 最終ラウンドの実際のクエリ文字列を保存します。 そのクエリの座標から位置へのマップを作成することで、連続して報告されるセルの各ペアの間にクエリのどの部分があるかを正確に知ることができます。 
8. 報告された 2 つの連続したセルが同じ行にある場合、それらの間の隠しパスは完全に次のもので構成されるように強制されます。`R`動く。 
9. 1 行だけ異なる場合は、最終クエリの対応する部分を検査します。 そのクエリ部分が次で始まる場合`D`、非表示のパスでは逆の順序を使用する必要があります。`R`続いて移動`D`。 クエリ部分が次で始まる場合`R`、隠しパスは次のようにする必要があります。`D`続いて必要な`R`動く。 このようなセクションでは下方向への移動は 1 つだけであるため、これによって非表示のパスが正確に決定されます。 
10. 再構築されたすべてのセクションを連結し、結果のパスを次のように出力します。`!`。 

### なぜ効果があるのか

 不変条件は、すべてのクエリの後、報告されたすべての座標が隠しパスの本物のセルであり、連続して報告された座標が隠しパスのまだ未知の部分を分割することです。 このような部分ごとに、クエリは中央の行を明示的に横断するため、非表示のパスはそこでクエリと交差する必要があります。 したがって、すべての新しいセクションの高さは前の行の最大半分になります。 高さが 0 または 1 になると、残りのパスは強制的に決定されるか、非表示のパスが最終クエリの最初の移動と一致するかどうかによって一意に決定されます。 したがって、再構築では間違ったターンを選択することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    m, n = map(int, input().split())

    if m == 1:
        print("! " + "R" * (n - 1), flush=True)
        return

    if n == 1:
        print("! " + "D" * (m - 1), flush=True)
        return

    points = [(1, 1), (m, n)]
    last_query = None

    for _ in range(10):
        parts = []

        for (r1, c1), (r2, c2) in zip(points, points[1:]):
            mid = (r1 + r2) // 2

            parts.append("D" * (mid - r1))
            parts.append("R" * (c2 - c1))
            parts.append("D" * (r2 - mid))

        query = "".join(parts)
        last_query = query

        print("? " + query, flush=True)

        t = int(input())
        points = [
            tuple(map(int, input().split()))
            for _ in range(t)
        ]

        if all(
            points[i + 1][0] - points[i][0] <= 1
            for i in range(len(points) - 1)
        ):
            break

    # Map every cell of the final query to its position in the query.
    qpos = {}
    r, c = 1, 1
    qpos[(r, c)] = 0

    for i, move in enumerate(last_query, 1):
        if move == "D":
            r += 1
        else:
            c += 1
        qpos[(r, c)] = i

    answer = []

    for a, b in zip(points, points[1:]):
        r1, c1 = a
        r2, c2 = b

        if r1 == r2:
            answer.append("R" * (c2 - c1))
            continue

        # Their row difference is at most one.
        ia = qpos[a]
        ib = qpos[b]

        query_segment = last_query[ia:ib]

        if query_segment[0] == "D":
            # Query uses D followed by R's.
            # The hidden path must use R's followed by D.
            answer.append("R" * (len(query_segment) - 1))
            answer.append("D")
        else:
            # Query uses R's followed by D.
            # The hidden path must use D followed by R's.
            answer.append("D")
            answer.append("R" * (len(query_segment) - 1))

    print("! " + "".join(answer), flush=True)

if __name__ == "__main__":
    main()
```最初の 2 つの特殊なケースは、グリッドに 1 行または 1 列しかない場合の不必要な対話を回避します。 どちらの場合でも、可能なパスは 1 つだけです。 

メインループは確認された検出器セルを次の場所に保存します。`points`。 クエリは連続するペアごとに独立して構築され、すべての部分が連結されます。 各部分は 1 つの確認されたポイントで始まり、次の確認されたポイントで終了するため、クエリ全体は左上隅から右下隅までの有効なパスになります。 

中間点では整数のフロア除算が使用されます。 これは、結果として得られる両方の行間隔が (\lceil d/2\rceil) を超えないことを保証するため、意図的なものです。 (d\le999) の場合、10 回の反復で十分です。 

インタラクターからの応答はすでにソートされているため、追加のソートは必要ありません。 これは、行の増加と 1 つの行内での列の順序の増加を保証する対話プロトコルに直接従うものです。 

The final`qpos`マップは実装の微妙な部分です。 エンドポイントだけから 1 行のセクションを再構築することはできません。 最終的なクエリがそのセクションを横断したかどうかを知る必要があります。`D...R`または`R...D`。 クエリのすべてのセルには一意の座標があるため、`qpos`報告された 2 つのセル間の正確なクエリ セグメントを抽出してみましょう。 

Python には整数オーバーフローの問題はありません。 生成された最大のパスには (m+n-2\le1998) 個の移動しか含まれていないため、すべての文字列と座標のコレクションは小さくなります。 

インタラクションは、すべてのクエリの後と最終的な回答の後にフラッシュする必要があります。 使用する`print(..., flush=True)`ステートメントの要求に応じて、これを直接処理します。 

## 実用的な例

 ### サンプル 1

 公式サンプルでは (3\times4) グリッドが使用されており、隠しパスは次のとおりです。`RDRDR`。 公式の対話では、さまざまな有効なクエリが使用されますが、この社説から中間点の戦略をたどることができます。 このステートメントは、サンプル内の隠しパスが次であることを確認します。`RDRDR`。 

初期確認点は((1,1))と((3,4))です。 中間行は (2) なので、最初のクエリは次のようになります。`DRRRD`。 

| ステップ | 確認した点 | クエリ | 報告されたポイント |
 | --- | --- | --- | --- |
 | 0 | ((1,1),(3,4)) |`DRRRD`| |
 | 1 | ((1,1),(2,2),(2,3),(3,4)) |`DRRRD`| ((1,1),(2,2),(2,3),(3,4)) |

 最初のセクション ((1,1)) から ((2,2)) のクエリ セグメントは次のとおりです。`DR`。 これらは連続して報告されるポイントであるため、非表示パスに内部クエリ セル ((2,1)) を含めることはできません。 したがって、隠しパスでは逆の順序を使用する必要があります。`RD`。 

中央のセクションでは、両方の点が同じ行上にあるため、パスは次のようになります。`R`。 

最後のセクションでは、クエリ セグメントは再び次のようになります。`RD`したがって、隠しパスは次のようにする必要があります。`DR`。 

3つの部分を連結すると、`RD`+`R`+`DR`、まさにその通りです`RDRDR`。 

この例は、最後のクエリを保存する必要がある理由を示しています。 報告された座標だけでは区別できません`DR`から`RD`ですが、クエリ上の位置はそうです。 

### サンプル 2

 隠しパスが次のような (5\times5) グリッドを考えてみましょう。`DDDDRRRR`。 

最初のクエリは中央の行 (3) を使用します。```
DDRRRRDD
```非表示のパスは、中央の行と端点でこのクエリと交差し、元の 5 行のセクションを小さなセクションに分割するのに十分なポイントを与えます。 

| ステップ | 最大行ギャップ | クエリの形状 | 結果 |
 | --- | --- | --- | --- |
 | 0 | 4 |`DDRRRRDD`| 真ん中の列が発見される |
 | 1 | 2 | 各セクションの五つの形のクエリ | 残りのすべてのギャップの行ギャップは最大 1 |

 最終的な再構築では、同じ行のギャップは強制的に水平になります。 1 行のギャップは、クエリの対応する部分と内部交差の有無を比較することによって解決されます。 結果のパスは次のとおりです`DDDDRRRR`。 

このトレースは、行範囲のバイナリ削減を示しています。 行数を個別に処理する必要はありません。 現在の不確実なセクションはすべて、1 つのクエリによって同時に絞り込まれます。

## テストケース

def hidden_cells(m, n, path):

    cells = [(r, c)]

    for ch in path:
        if ch == "D":
            r += 1
        else:
            c += 1
        cells.append((r, c))

    assert (r, c) == (m, n)
    return cells

def solve_offline(m, n, hidden):
    if m == 1:
        return "R" * (n - 1)

    if n == 1:
        return "D" * (m - 1)

    hidden_set = set(hidden)
    points = [(1, 1), (m, n)]
    last_query = None

    for _ in range(10):
        parts = []

        for (r1, c1), (r2, c2) in zip(points, points[1:]):
            mid = (r1 + r2) // 2
            parts.append("D" * (mid - r1))
            parts.append("R" * (c2 - c1))
            parts.append("D" * (r2 - mid))

        query = "".join(parts)
        last_query = query

        r, c = 1, 1
        response = [(r, c)] if (r, c) in hidden_set else []

        for ch in query:
            if ch == "D":
                r += 1
            else:
                c += 1
            if (r, c) in hidden_set:
                response.append((r, c))

        points = response

        if all(
            points[i + 1][0] - points[i][0] <= 1
            for i in range(len(points) - 1)
        ):
            break
    else:
        raise AssertionError("More than 10 queries required")

    qpos = {}
    r, c = 1, 1
    qpos[(r, c)] = 0

    for i, ch in enumerate(last_query, 1):
        if ch == "D":
            r += 1
        else:
            c += 1
        qpos[(r, c)] = i

    answer = []

    for a, b in zip(points, points[1:]):
        r1, c1 = a
        r2, c2 = b

        if r1 == r2:
            answer.append("R" * (c2 - c1))
            continue

        ia = qpos[a]
        ib = qpos[b]
        segment = last_query[ia:ib]

        if segment[0] == "D":
            answer.append("R" * (len(segment) - 1))
            answer.append("D")
        else:
            answer.append("D")
            answer.append("R" * (len(segment) - 1))

    result = "".join(answer)
    assert result == hidden
    return result

def run(inp: str) -> str:
    data = inp.split()
    m = int(data[0])
    n = int(data[1])
    hidden = data[2]

    return solve_offline(
        m,
        n,
        hidden_cells(m, n, hidden)
    )

# Provided sample, represented in simulator form.
assert run("3 4 RDRDR") == "RDRDR", "sample 1"

# Minimum-size grid.
assert run("1 2 R") == "R", "minimum-size horizontal"

# Single-column boundary case.
assert run("5 1 DDDD") == "DDDD", "minimum-width vertical"

# All moves of one direction.
assert run("1 8 RRRRRRR") == "RRRRRRR", "all right moves"

# Maximum-size grid, with all downs first and then all rights.
max_path = "D" * 999 + "R" * 999
assert run(f"1000 1000 {max_path}") == max_path, "maximum-size case"

# Alternating path, designed to exercise many turns.
zigzag = "RDRD" * 499 + "RD"
assert len(zigzag) == 1998
assert run(f"1000 1000 {zigzag}") == zigzag, "many turns"

 ## 特殊なケース

 (m=1) の場合、不確実性はまったくありません。 正確な入力のために```
1 4
```ロボットは右に 3 回移動する必要があるため、答えは次のようになります。`RRR`。 実装は対話型ループに入る前にこれを処理します。 

(n=1) の場合、可能なパスは垂直のみです。 のために```
4 1
```答えは`DDD`。 繰り返しますが、有効な単調パスは 1 つだけであるため、クエリは必要ありません。 

対角線上の 2 セルの場合は、重要なあいまいさです。 連続する 2 つの確認点を ((1,1)) と ((2,2)) とする。 考えられる 2 つのパスは次のとおりです`DR`そして`RD`。 クエリで使用されている場合`DR`、 それから`DR`隠しパスがレポートするように ((2,1))。 そのセルが存在しない場合、非表示のパスは次のとおりである必要があります。`RD`。 最終的な再構築コードは、対応するクエリ セグメントの最初の動きを調べることによって、まさにこのロジックをキャプチャします。 

最後に、最大次元は (1000) で、最初の行の差は最大 (999) になります。 最悪の場合の行差異のシーケンスは次のとおりです。 

[
 999、\ 500、\ 250、\ 125、\ 63、\ 32、\ 16、\ 8、\ 4、\ 2、\ 1。 
】

 したがって、最悪の場合でも 10 個のクエリで十分です。 この構築では、インタラクターが 11 番目のクエリを拒否することに依存する必要はありません。これは、インタラクティブな問題に対する防御の詳細として役立ちます。 公式プロトコルでは、10 を超えるクエリは即時に不正解であると宣言されています。
