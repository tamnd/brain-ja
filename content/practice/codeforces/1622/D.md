 ## 問題の理解

 バイナリ文字列、0 と 1 のシーケンス、および整数が与えられます。$k$。 正確に含む**最大 1 つの連続する部分文字列**を選択できます。$k$1 を取得し、その部分文字列の文字を任意に再配置します。 私たちのタスクは、この操作を 0 回または 1 回実行することで得られる異なる文字列の数をカウントすることです。 

入力は長さです$n$文字列 (最大 5000)、整数$k$、および文字列$s$。 出力は単一の数値です。取得可能な個別の文字列の合計数を法で表したものです。$998244353$。 

この制約は、すべての部分文字列を生成する総当りアプローチでは時間がかかりすぎることを示唆しています。 おおよそあります$O(n^2)$部分文字列、およびそれぞれの順列を数えることは、$O(n!)$最悪の場合。 と$n = 5000$、より賢いアプローチが必要です。 余裕があります$O(n^2)$時間の複雑さ、しかし次のようなもの$O(n^3)$または、すべての順列を明示的に生成しようとすることは不可能です。 

素朴なソリューションがつまずく可能性のあるエッジケースとしては、次のようなものがあります。$k = 0$または$k$1 の合計数より大きい。 たとえば、次の場合$k = 0$、許可される唯一の部分文字列は、ゼロの 1 を含む文字列です。 ゼロをシャッフルするだけでは何も起こらないため、元の文字列のみが可能です。 もう 1 つの微妙なケースは、文字列全体が 1 または 0 で構成されている場合です。これは、部分文字列をカウントするときに範囲外にならないように注意する必要があるためです。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての部分文字列を反復処理します。$s$、それらを数え、部分文字列に正確に含まれているかどうかを確認します。$k$1 つ目は、その部分文字列のすべての順列を計算し、それらをセットに収集します。 このアプローチはすべての選択肢を徹底的に考慮するため、原理的には正しいですが、絶望的に時間がかかります。 がある$O(n^2)$部分文字列の長さとともに順列の数は階乗的に増加します。 のために$n = 5000$、これは計算上不可能です。 

これを効率的に解決するための重要な洞察は、部分文字列を正確に修正すると、$k$1 の場合、個別の文字列の数に関して重要なのは、その部分文字列内のゼロの数だけです。 並べ替えるからです$x$ゼロと$y$結果は$\binom{x+y}{y}$異なる順列、および同じ数の 1 と 0 を含むが開始位置と終了位置が異なる 2 つの部分文字列は、元の文字列のコンテキストで同じ結果の文字列を生成する可能性があります。 

すべての順列を生成する代わりに、正確に部分文字列の数を数えます。$k$もの。 それぞれについて、組み合わせ公式を使用して部分文字列をシャッフルすることによって得られる個別の文字列の数を決定します。 最後に、ゼロ操作の実行に対応する 1 つの有効な結果として、元の文字列自体も含めます。 

これにより、問題は 2 ポインタまたはプレフィックス合計方法に縮小され、組み合わせカウント用の事前計算された階乗と組み合わせて、任意の部分文字列内の 1 の数を効率的にカウントできます。

 ## アルゴリズムのチュートリアル

 1. 文字列内の 1 のプレフィックスの合計を事前計算します。 これにより、任意の部分文字列内の 1 の数を O(1) 時間でクエリできるようになります。 させて`prefix[i]`部分文字列内の 1 の数を示します`s[0..i-1]`。 
2. もし$k = 0$、ゼロをシャッフルするだけでは文字列が変更されないため、唯一可能な操作は新しい文字列を生成しません。 すぐに 1 を返します。 
3. 可能なすべての開始インデックスを反復処理します。`l`部分文字列の。 2 ポインタ アプローチまたはネストされたループを使用して、最小値を見つけます。`r`部分文字列が`s[l..r]`正確に含まれています`k`もの。 インクリメント`r`部分文字列にそれ以上のものが含まれるまで`k`もの。 
4. 有効な部分文字列ごとに、正確に`k`1、その中のゼロの数を数えます、と言う`z`。 この部分文字列の個別の順列の数は次のとおりです。$\binom{z+k}{k}$。 二重カウントを避けるために、そのようなすべての順列の実行セットまたはカウンターを保持してください。 
5. すべての部分文字列からの寄与を合計します。 ゼロ操作を実行することを考慮して、元の文字列に 1 を追加します。 
6. 最終カウントのモジュロ 998244353 を出力します。 

これが機能する理由: 不変条件は、すべての部分文字列のすべての個別の順列を正確にカウントすることです。`k`もの。 位置と長さによってのみ個別の部分文字列を考慮することで、二重カウントを回避します。 元の文字列を含めることで、ゼロ操作も考慮されるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(a, mod):
    return pow(a, mod-2, mod)

def prepare_factorials(n, mod):
    fac = [1]*(n+1)
    inv = [1]*(n+1)
    for i in range(1, n+1):
        fac[i] = fac[i-1]*i % mod
    inv[n] = modinv(fac[n], mod)
    for i in range(n-1, -1, -1):
        inv[i] = inv[i+1]*(i+1) % mod
    return fac, inv

def comb(n, k, fac, inv):
    if k < 0 or k > n:
        return 0
    return fac[n]*inv[k]%MOD*inv[n-k]%MOD

def main():
    n, k = map(int, input().split())
    s = input().strip()
    
    ones = [0]*(n+1)
    for i in range(n):
        ones[i+1] = ones[i] + (s[i] == '1')
    
    if k == 0:
        print(1)
        return
    
    fac, inv = prepare_factorials(n, MOD)
    seen = set()
    
    for l in range(n):
        for r in range(l+1, n+1):
            if ones[r]-ones[l] == k:
                z = (r-l) - k
                seen.add(comb(z+k, k, fac, inv))
    
    result = (sum(seen) + 1) % MOD
    print(result)

if __name__ == "__main__":
    main()
```コードは最初に、O(1) 個の部分文字列クエリに対する 1 のプレフィックスの合計を計算します。 階乗と逆乗を事前に計算して、組み合わせを高速に計算します。 有効な部分文字列ごとに正確に`k`1 つでは、個別の順列の数を計算し、二重カウントを避けるためにそれをセットに追加します。 最後に、元の文字列に 1 を加算します。 

微妙な点は取り扱いを含む`k = 0`個別に、998244353 を法とする組み合わせを計算し、部分文字列内のゼロを正確に数えます。
