 ## 解決策
 ## 問題の理解

 記入するよう求められます$n \times n$異なる正の整数を含むグリッド。すべて約$n^2 + 40n$したがって、基本的にはセルの数よりわずかに大きい狭い範囲になります。 

制約はローカルです。すべてのセルは、上下左右のすぐ隣のセルと互いに素でなければなりません。 gcd が 1 であるということは「素因数が共有されていない」ことを意味するため、実際の問題は、隣接するセルが素因数を共有しないようにすることです。 

課題は、すべての値がグローバルに区別できる必要があるため、2 と 3 を交互に並べるような小さな安全なセットを単純に再利用することも、衝突を気にせずに小さな互いに素のパターンを自由に割り当てることもできないことです。 

範囲の制約も重要です。 と$n \le 2500$、グリッドには最大 625 万個のセルがありますが、値は最大約 635 万個までしかありません。 つまり、本質的には、整数の接頭辞をほぼ順列に並べたものを使用する必要があります。 「素数の無限の供給」または「恣意的に大きな構築スペース」に依存する解決策は直ちに除外されます。 

素朴なアプローチは、貪欲に数値を割り当てることです。セルごとに、すでに割り当てられている隣接セルと互いに素になるまで、1 から上の整数を試します。 これはすぐに壊れます。 たとえ各 gcd チェックが一定時間であっても、前の選択が後の選択を制約するため、検索空間は巨大になり、この規模ではバックトラッキングは実行不可能です。 

2 番目のよくある失敗は、行優先の順序で連続して番号を割り当てることです。 たとえば、1、2、3、…を埋めると、$n^2$6 や 8 などの隣接する数値は複数の近傍と因数を共有し、素数の重複に対する構造的な制御がないため、すぐに失敗します。 

本当の困難は、局所的な実現可能性ではなく、グローバルな調整です。セル内に素数が出現すると、隣接するすべての素数を汚染するため、グリッド全体での「伝播の競合」を回避する方法で素数を分散する必要があります。 

## アプローチ

 ブルート フォースの観点では、最大 4 つの近傍に対して gcd 制約をチェックしながら、未使用の整数のプールから数値を選択するものとして各セルを扱います。 これは原理的には正しいです。すべてのチェックに合格した割り当ては有効です。 問題は、ステップで$k$の場合、各近傍がその素因数の倍数をすべて無効な選択肢として導入するため、禁止値の数は急速に増加します。 最悪の場合、ほぼ全範囲を繰り返しスキャンします$[1, n^2 + 40n]$それぞれについて$n^2$セルは、次のような複雑さを与えます。$O(n^4)$、これは完全に不可能です$n = 2500$。 

重要な観察は、実際には完全な整数について推論する必要がないということです。 隣接するセルが素因数を共有していないことを確認するだけで済みます。 これは、数値の生の値ではなく、数値の素数構造を制御することを示唆しています。 

これを管理しやすくする構造は、固定の走査順序で貪欲に番号を割り当て、同時に新しい番号が隣接する番号に既に存在する素数を確実に回避するようにすることです。 各セルには最大でも 4 つの近傍があるため、各ステップの制約は非常に小さくなります。これらの近傍によって決定される禁止素数の有限セットを回避する必要があるだけです。 

整数のプールを維持し、候補値ごとにその素因数を事前計算します。 セルを埋めるとき、隣接するすべての割り当てられた数値から素因数セットが素である最初の未使用の数値を選択します。 値の範囲がわずかに大きいだけであるため、$n^2$、各数値には小さな素因数がほとんどなく、検索は制限付きスキップで成功し、有効な数値の密度により、拒否の総数は実際には線形のままです。 

これにより、問題は、グローバルな組み合わせ設計ではなく、ローカルな競合チェックを伴う制約された貪欲な割り当てに変わります。

## アルゴリズムのチュートリアル

 1 から 1 までの候補番号のリストを作成します。$n^2 + 40n$。 各数値について、ふるいを使用してその素因数分解を事前に計算し、gcd チェックを減らして小さな因子セットの共通部分チェックを設定します。 

次に、行優先の順序でグリッドを埋めます。 

1. までのすべての整数について最小の素因数を事前計算します。$n^2 + 40n$。 これにより、任意の数値を対数時間で高速に因数分解できます。 
2. 範囲内のすべての数値について、その個別の素因数を計算し、コンパクトなセットまたはビットマスクとして保存します。 
3. 数値がグリッド内ですでに使用されているかどうかをマークするブール配列を維持します。 
4. 辞書編集順にセルを走査します。$(i, j)$。 
5. 各セルについて、候補番号を 1 から順に繰り返し、素因数セットが既に割り当てられている近傍と交差しない最初の未使用の番号を選択します。 
6. その番号を割り当て、使用済みとしてマークします。 

この欲張りスキャンが許容される理由は、ほとんどの数値が有効な候補であるためです。 数値が拒否されるのは、その数値が最大 4 つの近傍のうちの 1 つと素因数を共有する場合のみであり、これは非常に小さな制限セットです。 ランダムな整数では素因数がまばらであるため、競合の可能性は低く、範囲内の追加の 40n スラックにより、十分な「安全な」数値が保証されます。 

### なぜ効果があるのか

 不変条件は、すべてのステップで、以前に入力されたすべてのセルが既に隣接条件を満たしており、隣接するセルとの共有素因数を導入しない値のみを割り当てるということです。 gcd 制約は純粋にローカルであり、素数のオーバーラップのみに依存するため、エッジに沿って素の因子セットを保持することで、グローバルな正確性が保証されます。 区別性は使用される配列を通じて独立して適用されるため、衝突は発生しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    maxv = n * n + 40 * n

    spf = list(range(maxv + 1))
    for i in range(2, int(maxv ** 0.5) + 1):
        if spf[i] == i:
            for j in range(i * i, maxv + 1, i):
                if spf[j] == j:
                    spf[j] = i

    def factors(x):
        res = set()
        while x > 1:
            p = spf[x]
            res.add(p)
            while x % p == 0:
                x //= p
        return res

    fac = [set()] * (maxv + 1)
    for i in range(1, maxv + 1):
        fac[i] = factors(i)

    used = [False] * (maxv + 1)
    grid = [[0] * n for _ in range(n)]

    for i in range(n):
        for j in range(n):
            forbidden = set()

            if i > 0:
                forbidden |= fac[grid[i - 1][j]]
            if j > 0:
                forbidden |= fac[grid[i][j - 1]]

            for v in range(1, maxv + 1):
                if used[v]:
                    continue
                if fac[v] & forbidden:
                    continue
                grid[i][j] = v
                used[v] = True
                break

    for row in grid:
        print(*row)

if __name__ == "__main__":
    solve()
```最小の素因数をふるい分けるのが中心的な前処理ステップです。 これにより、因数分解が保存された素数による繰り返し除算に減らされ、数値ごとの作業が小さく抑えられます。 

グリッド充填ループは、隣接条件を直接強制します。 重要な点は、構築中に左と上の隣だけをチェックすることです。 右および下の隣接セルは、これらのセルが埋められたときに対称的に適用されるため、必要ありません。 

値の範囲に余裕があるため、セルの有効なオプションが使い果たされることがほとんどないため、候補に対する貪欲なスキャンが機能します。

 アルゴリズムが領域を埋め始める小さなグリッドを考えてみましょう。$3 \times 3$ボード。 割り当てのプレフィックスのみを追跡します。

 ## 特殊なケース

 のために$n = 1$の場合、グリッドには隣接性の制約がないため、任意の単一の数値が有効です。 アルゴリズムは最初に使用可能な番号を割り当て、すぐに正しく終了します。

大型の場合$n$、主な懸念は、行と列に沿って禁止された素数が蓄積されることです。 各ステップがグリッドの完全な履歴ではなく、すでに埋められている 2 つの近傍のみに依存するため、この構造はこれを処理し、制約の爆発を防ぎます。
