 ## 解決策
 ## 問題の理解

 ルートがノード 1 に固定されたルート付きツリーが与えられます。各ノードには、常に真実を言うか、常に嘘をつくという 2 つの方法のいずれかで永続的に行動する人物がいます。 これに伴い、すべてのノードが$i$請求された番号を提供します$a_i$、をルートとするサブツリー内に何人の誠実な人が存在するかを記述することになっています。$i$。 

構成は、すべてのノードに対して独立して、その人が真実であるか嘘をついているかを選択するだけです。 ただし、すべての割り当てが有効であるわけではありません。 ノードが真実であるとマークされている場合、ノードが報告する数は、そのサブツリー内の真実であるノードの実際の数と一致する必要があります。 ノードが嘘つきとしてマークされている場合、報告される値は実際のサブツリー数とは異なる必要があります。 

タスクは、これらすべての制約と一致する割り当てがいくつあるかを数えることです。$998244353$。 

主な難点は、真理条件が見かけ上はグローバルであるが、実際にはローカルであるということです。すべてのノードの有効性はサブツリーの数に依存し、それらのサブツリーの数は割り当て全体に依存します。 

この制約により、テストごとに最大 5000 ノード、および最大 5000 のテストが許可されます。 これは、意図したソリューションがテストごとにほぼ線形またはほぼ線形であることを強く示唆しています。$O(n^2)$テストごとに作業限界を超えるリスクがすでにあり、状態空間が$2^n$。 

微妙なエッジケースが現れるのは、$a_i = 0$。 この場合、すべての真実のノードはそのサブツリー内に真実の子孫を持ってはなりません。これにより、構成が大幅に制限され、構造に応じて多くの強制的な嘘の割り当てが作成されます。 もう 1 つのエッジ ケースは、ノードがそのサブツリー サイズよりも大きい値を要求する場合です。 そのノードは決して真実であるはずがないため、即座に強制的に嘘つき状態になり、この制約はサブツリーの一貫性条件を通じて上方に伝播します。 

## アプローチ

 直接的なアプローチはすべてを試します$2^n$真実か嘘つきかのラベルの割り当て。 割り当てごとに、真実なノードのサブツリー数を計算し、すべてのノードの状態を検証します。 割り当てごとに線形検証を行ったとしても、これは次のようになります。$O(n \cdot 2^n)$、これは実現可能な限界をはるかに超えています。 

問題の構造を縮小する必要があります。 重要な観察は、真実性はサブツリー数を通じてのみ相互作用し、サブツリー数は加算されるということです。 これは、ツリー上でのボトムアップ動的プログラミングを示唆しており、サブツリーに含まれる真実のノードの数に基づいて各サブツリーの可能な構成を計算します。 

各ノードでは、ブール状態のみを追跡するのではなく、そのサブツリー内の真実のノードの数を考慮する必要があります。これは、「サブツリーの真実の数が次の場合、ノード i は真実である」という条件が成立するためです。$a_i$これにより、各サブツリーが可能な真実のカウントの分布を維持する DP が自然に得られます。 

ただし、すべてのカウントを保存する単純な DP は、$n$ノードごとに子を結合するとコストがかかります$O(n^2)$最悪の場合、ノードごとに$O(n^3)$。 それは遅すぎます。 

重要な構造の簡素化は、各ノードについて完全なディストリビューションが必要ないことです。 私たちが気にするのは、ノードがその制約に基づいて、強制的に真実であるか、強制的に嘘をつくか、または柔軟であるかだけです。$a_i$サブツリー内で達成できます。 子が固定されるとサブツリーのカウントが決定論的に動作することを認識すると、問題を次のように再構成できます。各サブツリーは、可能な真のカウントのセットに寄与しますが、ノードで唯一関連する問題は、その値が正しいかどうかです。$a_i$達成可能か、およびそれぞれの達成可能な数を達成する構成の数。 

これにより、各ノードがサブツリー サイズにわたるベクトルを維持しますが、子に対するナップザックのような畳み込みで結合されるツリー DP が得られます。 すべてのノードの合計サイズには制限があり、各マージはサブツリー サイズで線形に償却されるため、テストごとに全体の複雑さを二次関数に保つことができ、これは許容範囲内です。$n \le 5000$そして典型的な CF 集合体制約。

 ## アルゴリズムのチュートリアル

 ツリーを 1 にルートし、子が親の前に完全に解決されるように、ポストオーダーでノードを処理します。 

各ノードで DP を定義します$u$配列として`dp_u[k]`、サブツリー内の有効な代入の数を表します。$u$まさにそのようなこと$k$そのサブツリー内のノードは真実です。 

次に、子のサブセットを処理した後、DP が、次のように形成された部分サブツリーに真理値を割り当てるすべての方法を正しく反映するという不変条件を維持しながら、子を 1 つずつマージします。$u$そしてあの子供たち。 

すべての子をマージした後、ノードを組み込みます$u$それ自体には 2 つの可能な役割があります。 

If ノード$u$が真実である場合、それは真実のカウントに 1 を与えます。そして、そのサブツリー内の真実のカウントの合計が以下に等しいことを強制する必要があります。$a_u$。 したがって、次の構成のみ$k = a_u$このブランチでは引き続き有効です。 

If ノード$u$が嘘つきである場合、真実数に寄与する値は 0 ですが、結果として得られる真実数の合計が次と等しくないことを確認する必要があります。$a_u$。 これにより、DP から 1 つの値だけが除外されます。 

最後に、ノードの有効な構成をすべて合計します。$u$結果として得られる DP を上方に伝播します。 

### なぜ効果があるのか

 DP は正しいです。サブツリー内の真理値のすべての割り当ては、それに含まれる真理ノードの数によって一意に特徴付けることができ、サブツリーの構成は、この数に対する加算的な制約を除いて、子間で独立しているためです。 各ノードの真理条件はこの単一の集計値のみに依存するため、追加の構造情報は必要ありません。 事後マージにより、すべてのサブツリーが結合される前に完全に考慮されることが保証され、各ノードでの最終フィルタリングにより、サブツリー間の独立性を損なうことなくローカルな一貫性が確保されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def add(a, b):
    a += b
    if a >= MOD:
        a -= MOD
    return a

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = 0

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            parent[v] = u
            stack.append(v)

    dp = [None] * n

    for u in reversed(order):
        # dp_u[k] = ways in subtree u with k truthful nodes
        size = 1
        cur = [0] * 1
        cur[0] = 1

        for v in g[u]:
            if v == parent[u]:
                continue
            child = dp[v]
            new = [0] * (len(cur) + len(child))
            for i in range(len(cur)):
                if cur[i] == 0:
                    continue
                for j in range(len(child)):
                    if child[j] == 0:
                        continue
                    new[i + j] = (new[i + j] + cur[i] * child[j]) % MOD
            cur = new

        total = [0] * (len(cur) + 1)

        # u is liar
        for i in range(len(cur)):
            if i != a[u]:
                total[i] = add(total[i], cur[i])

        # u is truthful
        if a[u] < len(cur) + 1:
            total[a[u]] = add(total[a[u]], cur[a[u] - 1])

        dp[u] = total

    print(dp[0][a[0]] % MOD if a[0] < len(dp[0]) else 0)

def main():
    T = int(input())
    for _ in range(T):
        solve()

if __name__ == "__main__":
    main()
```この実装では、再帰の深さの問題を回避するために、明示的なスタックを使用して事後探索を実行します。 各ノードについて、サブツリーの真実のカウントをナップザック状態として扱い、子をマージすることによって畳み込み DP を構築します。 

各ノードの最後のステップでは、2 つのモードで制約が適用されます。liar モードでは正確なカウントが除外されます。$a_u$一方、真実モードでは、ノード自体が真実の合計に寄与するため、カウントが 1 ずつシフトされます。 シフト$a_u - 1$これは唯一の微妙なインデックス調整であり、off-by-one エラーの最も一般的な原因です。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ノードの要求値がサブツリー サイズを超える場合です。 そのような状況では、最良の場合でもサブツリーにはそれほど多くの真実のノードを含めることができないため、そのノードは決して真実ではありません。 アルゴリズムはこれを自然に処理します。`dp[a_u - 1]`は範囲外であるため、真実のブランチは何も貢献しません。 

もう 1 つのエッジケースは次のような場合です$a_u = 0$。 真実のブランチでは、これにより、`dp[-1]`、これは無効であるため、ノードは真実であることができません。 このアルゴリズムは、論理制約に一致して、ノードを嘘つきのみの投稿に正しく制限します。 

3 番目のケースは、すべてのノードが同一である線形チェーンです。$a_i$。 各マージはカウントを真実のノードごとに最大 1 つだけ上方にシフトし、無効な設定は各ステップでフィルタリングされるため、一貫性のない状態の蓄積を防ぐため、DP は依然として正しく動作します。
