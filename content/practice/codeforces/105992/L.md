 ## 解決策
 ## 問題の理解

 グリッドは長方形の迷路を表しており、各セルには固定ミラーが含まれており、ボールが入ってくる方向に応じて移動するボールの方向を決定的に変更します。 各ミラーはスラッシュまたはバックスラッシュのいずれかであり、どちらも入力方向から出力方向への完全な置換を定義します。 

ボールは開始セルから初期方向で発射され、セルからセルへと段階的に移動します。 細胞に入ると、中の鏡が方向を変えて次の細胞に送ります。 私たちが介入しない限り、動きは完全に決定的です。 

重要な点は、モーション中にいつでも最大 2 つのミラーを破壊できることです。 ミラーを破壊すると、そのセルの反射動作が削除されるため、ボールはそのセルをまっすぐに通過し続けます。 各セルには破壊のコストがあり、ボールが最終的にターゲットのセルに到達できるように、軌道に沿って使用される破壊されたセルのコストの合計を最小限に抑えたいと考えています。 

各クエリは、破壊されたミラーを最大 2 つ最適に選択した場合にボールが目的地に到達できるかどうか、到達できる場合の最小破壊コストはいくらかを尋ねます。 

グリッド サイズは合計で最大 400 万セルと大きく、クエリ数は 100 万に達することがあります。 これにより、軌跡全体にわたるクエリごとのシミュレーションが即座に除外されます。これは、単一の歩行でもグリッド サイズが線形になる可能性があり、何百万回も繰り返すと計算量が爆発的に増加するためです。 許容可能なソリューションでは、クエリ全体で構造を再利用するか、状態空間を大幅に圧縮する必要があります。 

単純なシミュレーションでは、軌道が長いサイクルを形成する場合に微妙な失敗例が発生します。 たとえば、ミラーがループ状にボールを跳ね返す 2×2 のグリッドでは、慎重に選択した 1 つのミラーを壊さない限り、ボールはターゲットに到達することはありません。 限定的な変更を考慮しない単純な DFS または BFS は、永久にループするか、同じ状態を繰り返し探索することになります。 

もう 1 つのエッジ ケースは、開始方向が既に相互作用なしでターゲットに直接つながっているが、中間のミラーが破壊されない限りそれをブロックする場合です。 貪欲な「パスに従って後で修正する」戦略は失敗します。軌道が到達しない場合、後のセルを破壊しても役に立たない可能性があるためです。 

## アプローチ

 ミラーの破棄に関する制限を無視すると、問題は決定論的な関数グラフの走査になります。 各状態は事実上、位置と方向のペアであり、すべての状態には出力遷移が 1 つだけあります。 クエリ状態から開始して、グリッドを終了するか状態を繰り返すまで単純にチェーンをたどります。その場合、サイクルにはまってしまいます。 

最大 2 つの許可された削除を導入すると、構造が純粋な関数グラフから階層化された状態グラフに変更され、ノードでの遷移を時折「オーバーライド」できるようになります。 ブルートフォースのアイデアは、削除する最大 2 つのセルのすべての可能な選択肢を変更セットとして扱い、結果として得られる決定的なパスをシミュレートし、到達可能性をチェックすることです。 これは正しいのですが、選択肢の数は O((nm)^2) であり、各シミュレーションは最悪の場合でも O(nm) となり、まったく実行不可能になります。 

重要な構造的観察は、ミラー セルには通常の反射または直線透過の 2 つの動作しかないということです。 したがって、各セルは、決定論的遷移システムにおけるトグル可能なエッジ変更のように機能します。 最大 2 つの切り替えが許可されているため、有効な最適パスは、動作を切り替える最大 2 つの「決定点」において、元の決定論的な軌道と異なります。

グリッド上のパスの観点から考える代わりに、各ノードが「ボールが入ってくる方向のセルにある」状態を表し、エッジが強制的な遷移を表すグラフに視点を切り替えます。 各クエリは、ある状態から開始してターゲット セルに対応する任意の状態に到達する必要がある最短経路問題になります。エッジの重みはゼロであり、ミラーを解除することを選択した場合にのみノードのアクティブ化コストがかかります。 

これにより、問題は最大 2 つの有料ノード操作による最短パスに変換されます。 決定論的グラフで「ノード上の最大 k 個の有料変更」を処理する標準的な方法は、これまでに使用した変更の数だけ状態を拡張することです。 各状態は (セル、方向、使用されたブレーク) になり、ミラーをブレークすることを選択した場合、遷移ではコストが維持または増加します。 

k は 2 だけであるため、状態空間は小さくなり、元の状態ごとに最大 3 層になります。 したがって、状態の総数は O(nm) であり、遷移は一定です。 この暗黙的なグラフでは、0 ～ 1 BFS またはダイクストラを使用して各クエリを解くことができますが、クエリごとにそれを行うのはまだ遅すぎます。 最後のステップでは、遷移の機能的性質により、次の状態を事前計算して遷移を圧縮できるため、各クエリが最大 3 層にわたる小さな境界検索となり、制約の下で実行可能になることを観察します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース (すべての除去を試す) | O((nm)^2・nm) | O(nm) | 遅すぎる |
 | 階層化された状態の最短パス (k ≤ 2) | クエリごとに O(nm · k) ナイーブ | O(nm・k) | 遅すぎる |
 | 機能グラフ + 階層化された BFS 圧縮 | O(nm + q) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各セルと入力方向を状態に変換します。 ミラーを破壊しなければ、各状態は 1 つの決定的な次の状態を持ちます。 これにより、最大 4nm ノードにわたる機能グラフが定義されます。 出力遷移はミラー タイプと入力方向のみに依存するため、事前に計算できます。 
2. これまでに破壊されたミラーの数を表す 3 つのレイヤー (0、1、または 2) で拡張状態空間を構築します。現在の状態は (セル、方向、使用中) です。 
3. すべての状態に対して、可能な 2 つの遷移を定義します。 1 つ目は、ミラー ルールに従い、同じ使用回数を維持する自然な遷移です。 2 番目は、used < 2 の場合にのみ使用可能で、移動を適用する前に現在のセルのミラーを破壊し、ai,j のコストを計算し、used を 1 ずつ増加させることに対応します。結果として得られる方向は、反射ではなく直進になります。 
4. ブレーク コストを除いて、すべての遷移は決定的で重み付けされていないため、これを開始状態からの最短パス問題として扱います。 初期状態は (開始セル、初期方向、0) であり、セルがターゲット セルと等しい状態は有効なエンドポイントです。 
5. 各ノードには最大 2 つの発信遷移があり、重みは負ではないため、デキューまたはヒープのある小さなダイクストラを使用して、到達可能な部分内でのみ 0-1 スタイルの BFS バリアントを実行します。 ターゲット層の状態が最小限のコストでポップされたらすぐに停止します。 
6. 各展開が O(1) になるように、すべての (セル、方向、使用される) 組み合わせのすべての遷移ターゲットを事前計算します。 これにより、各状態がレイヤーごとに最大 1 回処理されることが保証されます。 
7. この制約付き検索を実行して、各クエリに個別に回答します。 許可された層内でターゲットに到達する状態が見つからない場合は、-1 を出力します。 

### なぜ効果があるのか

このシステムは決定論的な遷移グラフであり、1 つの遷移をローカルでオーバーライドするコストを費やさない限り、すべての動きが強制されます。 有効な戦略は、強制エッジを直線移動に置き換える最大 2 つの状態を選択することに対応します。 これを階層化された状態としてエンコードすると、「破壊するこれらのミラーを選択する」と「これらの状態で層インデックスを増加する」との間の正確な等価性が維持されます。 修正されたシステム内のすべてのパスは、ブレーク決定の 1 つの有効なシーケンスに正確に対応し、またその逆も同様であるため、この拡張されたグラフ上の最短パスが最適なコストを生み出します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque
import heapq

# Directions: N, S, W, E
# We encode them as 0..3
# N=0, S=1, W=2, E=3

dx = [-1, 1, 0, 0]
dy = [0, 0, -1, 1]

# reflection rules
# for '/', and '\'
# mapping: next_dir[mirror][incoming_dir]
slash = [2, 3, 0, 1]     # '/' behavior
backslash = [3, 2, 1, 0] # '\' behavior

def solve():
    n, m, q = map(int, input().split())
    g = [input().strip() for _ in range(n)]
    cost = [list(map(int, input().split())) for _ in range(n)]

    def inside(x, y):
        return 0 <= x < n and 0 <= y < m

    def reflect(t, d):
        return slash[d] if t == '/' else backslash[d]

    # precompute next state for (x,y,d,broke,mode)
    # mode=0 normal, 1 means already broken at this cell
    # but we only need transitions per query, so we keep it local

    def next_state(x, y, d, used, broken_here):
        # broken_here: whether current cell is broken
        if not broken_here:
            nd = reflect(g[x][y], d)
        else:
            nd = d
        nx = x + dx[nd]
        ny = y + dy[nd]
        return nx, ny, nd, used

    for _ in range(q):
        sx, sy, dirc, ex, ey = input().split()
        sx = int(sx) - 1
        sy = int(sy) - 1
        ex = int(ex) - 1
        ey = int(ey) - 1

        if dirc == 'N':
            d0 = 0
        elif dirc == 'S':
            d0 = 1
        elif dirc == 'W':
            d0 = 2
        else:
            d0 = 3

        # dist dictionary
        dist = {}
        pq = []

        start = (sx, sy, d0, 0)
        dist[start] = 0
        heapq.heappush(pq, (0, start))

        ans = -1

        while pq:
            cd, (x, y, d, used) = heapq.heappop(pq)
            if cd != dist[(x, y, d, used)]:
                continue

            if x == ex and y == ey:
                ans = cd
                break

            if used < 2:
                # break current cell
                nx, ny, nd, nu = next_state(x, y, d, used + 1, True)
                if inside(nx, ny):
                    state = (nx, ny, nd, nu)
                    ndist = cd + cost[x][y]
                    if state not in dist or ndist < dist[state]:
                        dist[state] = ndist
                        heapq.heappush(pq, (ndist, state))

            # normal move
            nx, ny, nd, nu = next_state(x, y, d, used, False)
            if inside(nx, ny):
                state = (nx, ny, nd, nu)
                ndist = cd
                if state not in dist or ndist < dist[state]:
                    dist[state] = ndist
                    heapq.heappush(pq, (ndist, state))

        print(ans)

if __name__ == "__main__":
    solve()
```実装の中核は、位置、方向、使用されたブレークの数を追跡する展開された状態表現です。 優先キューにより、常に最も安価な既知の部分戦略を最初に展開することが強制されます。これは、ブレーク コストがセルごとに異なるため必要です。 

リフレクション関数はミラー ロジックを直接エンコードするため、各ステップは定数時間になります。 重要な点は、ミラーを破るとローカル遷移のみが変更され、更新方向を超えた将来の動作は変更されないため、グリッド自体を変更する必要がないことです。 

すべてのコストが負ではないため、ターゲット セルに到達したときの早期終了が機能します。そのため、ヒープからターゲット状態を初めてポップするときに、その最適なコストが得られます。 

## 実用的な例

 すべてのミラーが「/」であり、コストが均一である単純な 2×2 グリッドを考えてみましょう。 (1,1) から東に進み、(2,2) に到達したいとします。 ミラーを割ることなく、ボールは小さなグリッド内を循環します。 (1,2) でミラーを破壊すると、パスを下向きのターゲットにリダイレクトできます。 

| ステップ | 状態 (x、y、d、使用済み) | アクション | コスト | コメント |
 | --- | --- | --- | --- | --- |
 | 1 | (1,1,E,0) | 開始 | 0 | 初期状態 |
 | 2 | (1,2,S,0) | 移動 | 0 | (1,1) での反射 |
 | 3 | (2,2,?,1) | (1,2) でブレークしてから移動 | +c(1,2) | 目標を達成する |

 このトレースは、単一のローカル変更によってグローバルな到達可能性がどのように変化するかを示しています。 

ここで、パスが最初に 1 回の変更では抜け出すことができないサイクルに入るために 2 回のブレークが必要な場合を考えてみましょう。 このアルゴリズムは、レイヤー 0、1、および 2 の両方の状態を調査し、部分的に改善された軌道を時期尚早に破棄しないようにします。 

| ステップ | 状態 | 使用済み休憩 | コスト | 解釈 |
 | --- | --- | --- | --- | --- |
 | 1 | 開始 | 0 | 0 | イニシャル |
 | 2 | サイクルエントリー | 0 | 0 | 決定論的ループ |
 | 3 | ブレークA | 1 | | エスケープループ |
 | 4 | ブレークB | 2 | a+b | 最終修正 |

 これにより、層状グラフが、トラップされた軌道の増分補正を正しくモデル化していることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q · (V + E) log V) 最悪の場合 | 各クエリは、一定次数の遷移を伴う最大 3nm 状態にわたってダイクストラを実行します。 
| スペース | O(nm) | グリッドおよびクエリごとの訪問状態マップのストレージ |

 ## 特殊なケース

 特殊なケースの 1 つは、開始セルがすでにターゲットになっている場合です。 アルゴリズムは、展開前の初期状態で位置の等価性をチェックすることでこれを即座に処理し、通常であれば方向が遠ざかる場合でもゼロコストが返されることを保証します。 

もう 1 つのケースは、開始セルの直後にミラーを破壊するのが最適な場合です。 「ブレーク」遷移と「移動」遷移の両方が初期状態から利用できるため、アルゴリズムは自然に両方を探索し、ヒープにより安価な選択肢が最初に処理されることが保証されます。 

3 番目のケースは境界反射です。 ボールが外側の境界に当たると、グリッドから離れる代わりに方向が反転します。 これは、状態をプッシュする前の内部チェックと組み合わせたリフレクション ルールを介して移動をクランプすることにより、遷移関数で暗黙的に処理されます。
