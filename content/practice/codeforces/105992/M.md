 ## 問題の理解

 の配列が与えられます$n$魔法のオーブ。値はすべてゼロから始まります。 目標は、それらをターゲット配列に変換することです。$a$、それぞれの位置$i$正確に終了する必要があります$a_i$。 

2 つの操作が可能です。 最初の操作はポイント増分です。任意の 1 つのインデックスを選択し、その値を 1 つ増やし、固定コストを支払います。$x$。 2 番目の操作は範囲を 2 倍にする操作です。任意の間隔を選択します。$[l, r]$そして、その中のすべての値を 2 で乗算し、固定コストを支払います$y$。 

タスクは、最小の総コストですべてゼロからターゲット構成に到達することです。 

ソリューションを形作る重要な制約は次のとおりです。$n \le 3 \cdot 10^5$そして$a_i \le 10^9$。 これは、二次関数があればすぐに次のことを示唆します。$n$は遅すぎる一方で、値自体に関係する操作は対数レイヤーで、最も自然にはバイナリ表現を通じて処理される必要があります。 値は次のように制限されているため、$10^9$、各数値は最大 30 ビットなので、ビットごとに配列を処理するあらゆるソリューションが実現可能です。 

微妙な点は、2 倍演算が個々の要素ではなくセグメント全体に作用することです。 1 つの倍増が同時に多くの要素に影響を与える可能性があるため、これにより位置間の相互作用が生じます。 この結合を無視した単純な要素ごとの貪欲なアプローチは、すぐには正当化されません。 

各要素が独立していると仮定すると、失敗例が 1 つ現れます。 2 つの隣接する要素が共有倍増の恩恵を受けるが、増分コストを個別に支払うとします。 インデックスごとに貪欲に決定すると、共有構造が失われる可能性があります。 

たとえば、次の場合$x$大きくて、$y$が小さい場合、範囲の 2 倍化を使用する方が明らかに優れていますが、1 回の 2 倍化がセグメント全体に利益をもたらすため、決定は要素ごとにローカルではありません。 

もう 1 つの失敗例は、操作を前方に明示的にシミュレートする必要があると仮定した場合です。 値が 2 倍になると指数関数的に増加する可能性があるため、たとえ小さな入力であっても、繰り返し操作によりシミュレーションがすぐに実行できなくなります。 

## アプローチ

 ブルートフォースのアイデアは、文字通りゼロから配列を構築し、すべての操作シーケンスを試行することです。 各操作は、位置を 1 つ増やすか、セグメントを 2 倍にします。 合理的なシーケンスに限定したとしても、分岐要素は膨大です。各ステップで選択できます。$O(n^2)$セグメントまたは$n$必要なステップ数は、すべての点演算のバイナリ表現の桁の合計によって異なります。$a_i$。 これにより、まったく実行不可能な指数関数的な検索スペースが生じます。 

重要な観察は、両方の操作がバイナリ表現と明確に相互作用することです。 ポイントの増分は、低レベルの寄与を一度に 1 単位ずつ設定することに対応し、2 倍演算はすべての寄与を 1 ビット高くシフトします。 これは、構築を少しずつ処理することを示唆しています。 

ゼロから先を考えるのではなく、最終的な数値の各ビットがどのように形成されるかを検討します。 倍加するたびに、構築された構造全体が 1 ビット上に効果的にシフトされます。 ビットレベルで$k$、コントリビューションがインクリメントを使用して直接構築されるか、または 2 倍化によって前のレベルから継承されるかを決定するだけで済みます。 

これにより、問題がビット上の階層化された DP に変換されます。各階層は、前の階層と要素ごとのローカルな選択にのみ依存します。

 ## アルゴリズムのチュートリアル

 バイナリ表現を最下位ビットから上に向かって処理します。 させて$dp[i]$インデックスに対してこれまでに蓄積された最小コスト貢献を表します$i$下位ビットの処理後。 

各ビットレベルで$k$かどうかを見ます。$k$-番目のビット$a_i$は 0 または 1 です。 

1.初期化$dp[i] = 0$ビットを処理する前にコストが発生しないため、すべてのインデックスに対して実行されます。 
2. 各ビット位置について$k$0から30まで、抽出$b_i$、$k$-番目のビット$a_i$。 これは、このビットが最終値に存在する必要があるかどうかを表します。 
3. インデックスごとに$i$では、このビット レベルで寄与を取得する 2 つの方法を考えてみましょう。 

1 つの方法は、ポイント インクリメントを使用してビットを直接構築することです。 もし$b_i = 1$、これには費用がかかります$x$; もし$b_i = 0$、費用はかかりません。 

もう 1 つの方法は、以前のビット レベルですでに構築したものを再利用し、倍増効果を適用することです。 以前の構造を上に持ち越した場合、支払いを行います$y$要素ごとに 1 回、この要素を含むセグメントに影響を与える 2 倍演算の使用を反映します。 これにより、下位ビットが上方に効果的に伝播されます。 
4. DP 遷移を次のように更新します。$$dp[i] = \min(x \cdot b_i,\ dp[i] + y)$$これにより、ビットを最初から再構築するか、倍増によって以前の層から継承するかの決定が捕捉されます。 
5. すべてのビットを処理した後の最終的な答えは、次の合計になります。$dp[i]$すべてのインデックスにわたって。 

これが機能する理由は、前のビットの伝播方法を修正すると、各ビット層が独立するためです。 2 倍化では、追加コストによる場合を除き、異なるインデックス間でビットが混合されることはなく、その効果は純粋に以前に構築された構造を上方にシフトすることです。 DP 不変条件は、ビットを処理した後のものです。$k$、$dp[i]$は、最大のビットのプレフィックス寄与を実現するための最小コストを表します。$k$インデックス用$i$、各ビットが直接構築されたのか、それとも 2 倍化を通じて継承されたのかというすべての選択を考慮します。 どちらの操作も各層の要素ごとの寄与が線形であるため、インデックス間の結合は加算コストを超えて残らないため、要素ごとの最小化は有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x, y = map(int, input().split())
    a = list(map(int, input().split()))
    
    dp = [0] * n
    
    for k in range(31):
        cost_direct = []
        for i in range(n):
            bit = (a[i] >> k) & 1
            cost_direct.append(x * bit)
        
        for i in range(n):
            dp[i] = min(cost_direct[i], dp[i] + y)
    
    print(sum(dp))

if __name__ == "__main__":
    solve()
```この実装では、インデックス上に単一の DP 配列が保持されます。 各ビット レベルで、増分を使用してそのビットを形成する直接コストを計算し、それを 2 倍演算を使用して以前の構築の拡張と比較します。 各レベルは以前の DP 状態のみに依存するため、更新はインプレースで行われます。 

よくある落とし穴は、ビットが 1 であるインデックスのみに影響を与えるものとして 2 倍化を扱おうとすることです。実際には、2 倍化はすでに構築されているものをすべて伝播するため、ビットが 0 であっても依然としてコストを継承する可能性があります。$dp[i] + y$遷移。 

もう 1 つの微妙な点は、値を明示的にシミュレートすることがないことです。 DP は実際の数値ではなくコスト構造を追跡するため、オーバーフローが回避され、計算が線形に保たれます。$n \log A$。 

## 実用的な例

 配列を考慮してください$a = [1, 1]$、 と$x = 1, y = 1$。 

ビット 0 では、両方の要素にビット 1 があります。直接コストはそれぞれ 1 です。 以来$dp$0から始まるので比較します$1$対$0 + 1$したがって、両方のオプションは等しく、$dp = [1, 1]$。 

上位ビットではすべての値がゼロになるため、DP はそれ以上増加しません。 最終的な答えは 2 です。 

ここで考えてみましょう$a = [2, 3]$と$x = 2, y = 1$。 

| ビット | 私 | ビット値 | 直接コスト | 前の dp | |後の dp
 | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 | 0 | 0 |
 | 0 | 1 | 1 | 2 | 0 | 1 |
 | 1 | 0 | 1 | 2 | 0 | 1 |
 | 1 | 1 | 1 | 2 | 1 | 2 |

 ビット 1 では、両方の要素をコスト 2 で直接構築することも、2 倍のコストを追加して前のレベルから継承することもできます。 DP は、要素ごとに安価なオプションを正しく累積します。 

このトレースは、アルゴリズムが下位ビットからの最適なコスト構造を維持しながら、徐々に上位ビットを構築する方法を示しています。

 ## 特殊なケース

 エッジケースの 1 つは、すべてが$a_i = 0$。 アルゴリズムはすべてのビットを処理しますが、すべてのビットの寄与はゼロであるため、$dp[i]$全体を通してゼロのままです。 これにより、不要な操作が決して導入されないことが確認されます。 

別のケースとしては、次のような単一の大きな値があります。$a = [2^{30} - 1]$。 DP はすべてのビットを反復処理し、各レベルで増分コストを支払うか、以前のコストを引き継ぎます。 各ビットが独立して処理されるため、反復によりオーバーフローのない最小限の累積が保証されます。 

3 番目のケースは次の場合です。$y = 0$、倍増が無料になります。 再発はすぐに次のような伝播を優先します。$dp[i] + y$したがって、すべての構造は上方に継承され、ソリューションが単一の構築パスに事実上集約されます。 

最後のケースは次のような場合です。$x = 0$、増分は無料です。 その後、すべてのビットで直接構築が優勢となり、DP は一貫して直接分岐を選択し、予想どおり総コストがゼロになります。
