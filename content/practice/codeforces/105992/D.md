 ## 問題の理解

 2 つの非負の整数が与えられます`a`そして`b`、およびターゲットペア`x`そして`y`。 2 人のプレイヤーが交互にターンを行い、最初のプレイヤー (gsh) が現在の状態を正確に変換しようとします。`(x, y)`制限された手数内で、対戦相手 (AI) はこれが起こらないように努めます。 

gsh の番では、任意のマスクを使用したビット単位の演算を使用して、2 つの数値のうちの 1 つを正確に変更することができます。`v`。 彼はどちらかを置き換えることができます`a`と`a & v`または交換します`b`と`b | v`。 AI のターンでは、役割は精神的に反映されますが、実質的には逆転します。AI は次のことを設定できます。`a := a | v`または`b := b & v`。 

重要な詳細は次のとおりです`v`範囲内では完全に自由です`0 ≤ v < 2^60`したがって、何らかのマスクを使用した単一の AND または OR 演算によって達成できる限り、プレイヤーは 1 回の動きで、強制したい最終的なビット パターンを独立して決定できます。 

ゲームは原則として無限ですが、移動後の状態が正確になった瞬間に gsh が勝ちます。`(x, y)`。 そうでなければAIが勝ちます。 

制約により、最大で次のことが許可されます。`T = 10^5`独立したゲーム、最大値`2^60`。 これは、テスト ケースごとの対数係数でさえ、一般的な制限の下では境界線に達するため、いかなる解もテスト ケースごとに一定時間でなければならないことを直ちに示唆します。 

素朴な解釈では、ゲームをシミュレートしたり、一連のビット操作について推論したりすることを示唆するかもしれません。 ただし、分岐要素が膨大であり、実質的に状態の数が膨大であるため、それは不可能です。`2^120`。 ビットマスクを介した制限付き BFS さえも完全に実行不可能です。 

初期状態がすでにターゲットと等しい場合、微妙なエッジ ケースが発生します。 その場合、gsh は何も動かさずにすぐに勝ちます。 次のいずれか 1 つだけが発生した場合、別の重要なケースが発生します。`a`または`b`OR および AND 演算はビットを積極的に上書きできるため、一方はターゲットと一致し、他方は独立して調整できます。 ビットレベル構造を持たずに値の「増加」または「減少」のみを考慮したソリューションは、単一の操作でターゲット構成に直接ジャンプできる場合には失敗します。 

## アプローチ

 ブルートフォースモデルは各状態を扱います`(a, b)`ノードとして、またどちらかのプレイヤーによる各操作をトランジションとして扱います。 gsh はどのノードからでも、マスクを選択することで到達可能な任意の状態に移行できます。`v`AI も補完的な方法で同じことを行うことができます。 これにより、エッジがビット単位の変換に対応する大規模な交互グラフが作成されます。 

このモデルは正しいですが、使用できません。 無限の地平線を無視しても、個別の状態の数は`2^60 × 2^60`、そして各州は恣意的な理由により事実上指数関数的な発信の選択肢を持っています。`v`。 検索ベースのアプローチはすぐに失敗します。 

重要な観察は、ゲームが実際に重要なのは一連の動きではなく、ビットの制御性であるということです。 各操作により、1 人のプレイヤーが 1 つの変数に対して単調な動作を一方向に強制できます。AND はビットのクリアのみ、OR はビットのセットのみが可能です。 対戦相手は、他の変数に関して常に反対の極性を持っています。 

この対称性は、ゲームがビット強制の敵対的変更の下でターゲット構成に到達可能かどうかをチェックすることを意味します。 ターンを追跡する代わりに、もっと単純な質問をします。各ビット位置について、gsh は独立して次のことを保証できますか?`(a, b)`まで運転することができます`(x, y)`AI が永久にブロックできないのでしょうか？ 

重要な単純化は、各移動が 1 つの変数で選択されたビット パターンを完全に上書きできることです。 例えば、`a := a & v`gsh がどのビットを独立して決定できるようにします`a`ゼロにならなければなりません。 同様に、AI はビットを強制的に実行できます。`a`OR を使用して 1 にします。 したがって、各ビットは 2 人のプレーヤーによる制御システムのように動作し、1 人のプレーヤーがそれを必要な値に固定しようとし、もう 1 人のプレーヤーがそれに反対しようとすることができますが、反対の単調な方向にのみ動作します。 

このことから、ゲームは、必要なターゲットが避けられない敵対的強制制約と競合するビットが存在するかどうかをチェックすることになります。 これにより、問題はゲーム シミュレーションではなく、ビットごとの直接的な実行可能性チェックに集約されます。

 ## アルゴリズムのチュートリアル

 各テストケースを独立して処理し、少しずつ推論します。 

1. 0 ～ 59 の各ビット位置について、対応するビットを抽出します。`a`、`b`、`x`、 そして`y`。 これにより、AND と OR は位置をまたがってビットを混合しないため、ゲームがビットごとに独立した 2 値決定に分離されます。 
2. 固定ビットについて、各プレーヤーが何を強制できるかを観察します。 gsh は AND を使用できます`a`ビットを強制的に 0 にし、OR をオンにします`b`ビットを強制的に 1 にします。AI はその逆を行うことができます: OR`a`ビットを強制的に 1 に設定し、AND を実行できます。`b`これは、各変数に適用される操作に応じて、双方向の強制圧力があることを意味します。 
3. ターゲットが必要とする部分を少し考慮する`x_bit = 1`しかし初期の`a_bit = 0`。 1インチを生み出す唯一の方法`a`gsh の AND ではなく、AI の OR 演算を使用します。 ただし、gsh は 1 を直接設定することはできません。`a`したがって、このビットに到達するかどうかは、AI がブロッキング構成を永続的に維持するのを防ぐことができるかどうかによって決まります。 これにより制約が生じます。gsh は、敵対的な制御下で直接「1 に設定する」アクションを必要とせずに到達できるビットにのみ依存できます。 
4. 同様に、次の場合も`y_bit = 0`しかし`b_bit = 1`、gsh は強制的にクリアできる必要があります。`b`ですが、AI は AND を使用することで対抗できます。`b`最適な場合のみ。 これにより、対称的な制約が導入されます。 
5. 重要な点は、両方のプレーヤーがそのビットの矛盾を無期限に維持できる構成にない限り、ビットは実行可能であるということです。 具体的には、gsh が反対の単調操作を選択することで相手が永久に阻止できるビット フリップに依存せざるを得なくなった場合にのみ、実現可能性は失敗します。 
6. すべてのビットをチェックした後、不可能なビット構成が見つからない場合、gsh は強制的に収束させることができます。`(x, y)`、そうでない場合、答えは次のとおりです。`No`。 

### なぜ効果があるのか

 各ビットは単調操作の下で独立して進化します。OR は 1 の方向にのみビットを移動でき、AND は 0 の方向にのみビットを移動できます。両方のプレーヤーは異なる変数を使用して両方向に適用できるため、唯一の本当の障害は、目標を達成するために敵が永続的に支配できる方向にビットを逆転する必要がある場合に発生します。 これにより、ゲームは、敵対的な制御下で禁止された方向を必要とするビットがあるかどうかをチェックすることになります。 そのような競合が存在しない場合は、正しい操作を繰り返し適用することで、最終的にはすべてのビットがターゲットと一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        a, b, x, y = map(int, input().split())

        # Key observation: each bit can be analyzed independently.
        # We check whether any bit creates an irreversible conflict.

        ok = True

        for i in range(60):
            abit = (a >> i) & 1
            bbit = (b >> i) & 1
            xbit = (x >> i) & 1
            ybit = (y >> i) & 1

            # For a bit in a:
            # If we need xbit = 1 but start from abit = 0,
            # it requires OR pressure; similarly, AI can enforce 1s on a.
            # The conflict arises only when both directions are adversarially locked.
            if xbit == 1 and abit == 0:
                # cannot be reliably created under opposing OR pressure structure
                ok = False

            # For a bit in b:
            # If we need ybit = 0 but start from bbit = 1,
            # it requires AND pressure; AI can resist via AND/OR symmetry.
            if ybit == 0 and bbit == 1:
                ok = False

        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```演算はビット単位で位置ごとに独立しているため、解はビットをループします。 テスト ケースごとに、必要な変換によってビットが敵対的変更下では保証できない方向に強制的に移動するかどうかがチェックされます。 ループ内の条件は、OR および AND 対称によって暗示される不可逆性制約をエンコードします。 

早期離脱フラグ`ok`テストケースごとに一定の作業を保証します。

 ## 特殊なケース

 エッジ ケースの 1 つは、初期状態がすでにターゲットと一致している場合です。 その場合、不一致条件がトリガーされないため、すべてのビット チェックはすぐに合格します。 アルゴリズムは戻ります`Yes`将来の動きについて理由を考える必要はありません。 

別のケースは、`a`異なりますが、必要な変更はすべてビットクリアされます。 例えば、`a = 1111`、`x = 0000`。 AND は常にビットをクリアできるため、すべての異なるビットは安全な遷移を満たし、反復中に禁止条件は発生しません。 

対照的なケースは、ソリューションでビットを設定する必要がある場合です。`a`これは最初は 0 です。たとえば、次のようになります。`a = 0`、`x = 1`。 チェックはこれに即座にフラグを立て、アルゴリズムは次のように出力します。`No`これは、敵対的 OR 制御の対称性の下ではそのような作成が保証されていないことを反映しています。 

最後に、両方の変数が混合トグルを必要とする場合は、ビットごとに独立して処理され、クロスビット干渉が誤って想定されていないことが保証されます。
