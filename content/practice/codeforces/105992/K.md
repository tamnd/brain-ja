 ## 解決策
 ## 問題の理解

 私たちは、多くのラウンドにわたって実行される確率論的なボード プロセスをシミュレートしています。各ラウンドでは、まれな失敗イベントに応じてゲームが即座に終了する可能性があります。 ゲームの状態は非常に小さいです。どの時点でも、箱に収まりきらなかった「悪い」石が現在 0 個あるのか 1 個あるのかを知る必要があるだけです。 このカウントが 2 になった瞬間にゲームが終了します。 

各ラウンドには 2 つの危険源があります。 開始時に、すでに悪い石が 1 つだけある場合、対戦相手は低い確率でゲームをすぐに終了する可能性があります。 それが起こらない場合は、一連の石を通過して進みます。 各石は 2 つの方法で悪くなる可能性があります。正しく配置できない可能性があり、その後、現在のラウンドで処理された石が多すぎる場合、オーバーフローによりボックスから落ちてしまう可能性もあります。 石が悪くなるたびに、悪い石カウンターが増加し、2 つになると即座に損失が発生します。 

タスクはプロセスを直接シミュレートすることではなく、ラウンドごとに、初めて負ける確率がそのラウンド内で正確に発生する確率を計算することです。 

入力サイズにより、直接シミュレーションが不可能になります。 ラウンド数は最大 100,000 で、各ラウンドには最大 10^9 個の石を含めることができます。 これにより、石ごとのシミュレーションが即座に除外されます。 各ラウンドの遷移が非常に安価でない限り、ラウンドごとに O(n log ai) であっても遅すぎます。その場合でも、ラウンド全体での再利用を慎重に構成する必要があります。 

微妙なエッジケースは、ラウンドの開始時または処理中に負けが発生する可能性があるという事実から生じます。 たとえば、すでに「悪い石が 1 つある」状態でラウンドに入り、対戦相手が即座に負けを引き起こした場合、ラウンド内の確率はどれも重要ではありません。 ラウンド内の遷移のみをモデル化する単純なソリューションでは、この寄与が完全に失われます。 

もう 1 つの落とし穴は、ラウンドの最初の 80 石の後にオーバーフローの動作が変化することを忘れていることです。 すべての石を同じように扱うと、長いラウンドで不正確な移行確率が発生します。 

## アプローチ

 直接的な総当たり的なアイデアは、状態 0 か 1 かを追跡しながら、ラウンドごとにすべての石をシミュレートし、2 つの悪い石に当たったときに停止することです。 このプロセスはマルコフ関数であり、各遷移は現在の状態にのみ依存するため、これは原理的には正しいです。 ただし、ステップ数はすべての ai の合計であり、最悪の場合は 10^14 に達する可能性があるため、このアプローチは完全に実行不可能になります。 

重要な観察は、状態空間は小さいですが、遷移は確率的であり、線形に蓄積されるということです。 段階的にシミュレーションするのではなく、悪い石が 0 つある、悪い石が 1 つある、またはすでに負けているという 3 つの状態にわたる確率ベクトルの線形変換として各ラウンドをモデル化します。 

各石は同じ種類の線形更新を引き起こしますが、石が 80 個になると移行確率が変化します。 同じ線形変換を何度も繰り返すことは、行列のべき乗を示唆します。 これにより、対数時間で同一の遷移の長いシーケンスを飛び越えることができます。 

次に、ラウンドごとに 2 つのフェーズを構成します。最初のフェーズは最初の 79 個の石に対して、2 番目のフェーズは残りの石に対して行われます。 各フェーズは 3 x 3 の行列で表され、高速累乗により、最大 10^9 の同一ステップの効果を効率的に計算できます。 

最後に、ラウンドの開始状態の分布は前のラウンドの結果に依存するため、ラウンド全体に確率を伝播する必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 石ごとの総当たり力 | O(∑ai) | お(1) | 遅すぎる |
 | ラウンドごとの行列のべき乗 | O(n log ai) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

各ラウンドの開始時に状態全体の確率分布を維持します。 dp0 を悪い石が 0 つある状態でラウンドを開始する確率、dp1 を悪い石が 1 つだけある状態で開始する確率とします。 すでに 2 つの悪い石に達している確率の塊は、プロセスがそこで吸収されるため、破棄されます。 

各ラウンドで次のことを行います。 

1. まずラウンド開始時に即時終了条件を処理します。 私たちが状態 1 にある場合、相手は確率 r/1000 で即座に損失を引き起こす可能性があります。 この貢献をこのラウンドの回答に直接追加します。 状態 1 の残りの確率マスは、確率 1 からこの値を引いた値で存続し、状態 1 としてラウンドに進みます。 
2. 次に、3 つの状態 (状態 0、状態 1、ターミナル損失) にわたる遷移システムを使用してラウンド内プロセスをモデル化します。 各石はこれらの確率を直線的に更新します。 
3. 石が 80 個になるとオーバーフロー ルールが変わるため、ラウンドを 2 つのフェーズに分割しました。 最初のフェーズでは、p のみに基づくストーンごとの故障確率を使用します。 第 2 フェーズでは、p と追加のオーバーフロー障害 q の両方を含む修正確率を使用します。 
4. 各フェーズを 3 × 3 の遷移行列として表します。 この行列を累乗すると、多数の同一の石の効果を対数時間で計算できます。 
5. min(ai, 79) ステップに第 1 相の行列指数を適用し、残りのステップに第 2 相の行列指数を適用します。 これらの行列を乗算すると、ラウンド全体に対して 1 つの変換が行われます。 
6. この変換を基底状態 0 と 1 に個別に適用し、ラウンド中に負ける確率と、生き残った場合の状態全体の結果の分布の両方を取得します。 
7. これらの結果を使用して、このラウンドによる損失確率を計算し、次のラウンドの dp0 と dp1 も更新します。 

核となる不変条件は、各ラウンドの開始時に、dp0 と dp1 がすべての生き残る確率質量を完全に記述し、行列変換がプロセスの線形性を正確に維持することです。 ラウンド内のすべての遷移は電流分布において線形であり、損失状態への吸収により、これら 3 つ以上の状態を追跡する必要がなくなります。 変換は近似ではなく正確に適用されるため、確率の大量計算はすべてのラウンドにわたって正確なままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def inv(x):
    return pow(x, MOD - 2, MOD)

def mat_mul(a, b):
    n = 3
    res = [[0] * n for _ in range(n)]
    for i in range(n):
        for k in range(n):
            if a[i][k]:
                for j in range(n):
                    res[i][j] = (res[i][j] + a[i][k] * b[k][j]) % MOD
    return res

def mat_pow(mat, exp):
    n = 3
    res = [[0] * n for _ in range(n)]
    for i in range(n):
        res[i][i] = 1
    base = mat
    while exp > 0:
        if exp & 1:
            res = mat_mul(res, base)
        base = mat_mul(base, base)
        exp >>= 1
    return res

def build_matrix(p_fail):
    p = p_fail
    # states: 0, 1, dead
    # dead is absorbing
    return [
        [1 - p, 0, 0],
        [p, 1 - p, 0],
        [0, p, 1]
    ]

def apply(mat, vec):
    res = [0, 0, 0]
    for i in range(3):
        for j in range(3):
            res[i] = (res[i] + mat[i][j] * vec[j]) % MOD
    return res

def solve():
    p, q, r = map(int, input().split())
    n = int(input())
    a = list(map(int, input().split()))

    inv1000 = inv(1000)

    def get_fail(x, use_q):
        if use_q:
            base = p * inv1000 % MOD
            extra = q * inv1000 % MOD
            return (base + (1 - base) * extra) % MOD
        else:
            return p * inv1000 % MOD

    dp0, dp1 = 1, 0
    ans = []

    for ai in a:
        # immediate opponent action
        r_prob = r * inv1000 % MOD
        add_loss = dp1 * r_prob % MOD
        ans.append(add_loss % MOD)

        dp1 = dp1 * (1 - r_prob) % MOD

        # build matrices
        k1 = min(ai, 79)
        k2 = max(0, ai - 79)

        M0 = build_matrix(get_fail(0, False))
        M1 = build_matrix(get_fail(0, True))  # placeholder corrected below

        # correct failure rates
        pA = p * inv1000 % MOD
        pB = (pA + (1 - pA) * (q * inv1000 % MOD)) % MOD

        M0 = [
            [1 - pA, 0, 0],
            [pA, 1 - pA, 0],
            [0, pA, 1]
        ]

        M1 = [
            [1 - pB, 0, 0],
            [pB, 1 - pB, 0],
            [0, pB, 1]
        ]

        T0 = mat_pow(M0, k1)
        T1 = mat_pow(M1, k2)

        T = mat_mul(T1, T0)

        v0 = apply(T, [1, 0, 0])
        v1 = apply(T, [0, 1, 0])

        f0 = v0[2]
        f1 = v1[2]

        ans[-1] = (ans[-1] + dp0 * f0 + dp1 * f1) % MOD

        n0 = (dp0 * v0[0] + dp1 * v1[0]) % MOD
        n1 = (dp0 * v0[1] + dp1 * v1[1]) % MOD

        dp0, dp1 = n0, n1

    for x in ans:
        print(x % MOD)

if __name__ == "__main__":
    solve()
```実装では、各ラウンドを 2 つの線形システムの構成として扱います。 最初の調整では、石が処理される前に、状態 1 から即時損失の確率が削除されます。 次に、ラウンドの最初の部分用とオーバーフロー フェーズ用の 2 つの遷移行列が構築されます。 行列のべき乗は、同一の遷移の長いシーケンスを圧縮します。 

各基底ベクトルを適用すると、各状態で終了する確率と、すでに負けている確率の両方が得られます。 この二重の情報が必要なのは、現在のラウンドの損失確率を計算し、生き残った分布を前方に伝播するためです。 

よくある間違いは、マトリックスを適用する前に、対戦相手によって引き起こされた即時損失を生き残ったマスから削除するのを忘れることです。 そうしないと、後の遷移で状態 1 の確率が過大にカウントされてしまいます。 

## 実用的な例

 オーバーフローが引き起こされないように、少数の石だけが存在する小規模なシナリオを考えてみましょう。 p がゼロ以外であり、q は無関係であるとします。 

| ステップ | dp0 | dp1 | イベント |
 | --- | --- | --- | --- |
 | 開始 | 1 | 0 | イニシャル |
 | ラウンドトランジション | 計算された | 計算された | 石材加工 |
 | 終わり | 更新されました | 更新されました | 次のラウンドに持ち越し |

 これは、dp がラウンド内の詳細とは独立して進化し、集計された遷移結果のみに依存していることを示しています。 

次に、ステート 1 でラウンドを開始する場合を考えてみましょう。 

| フェーズ | dp1 前 | 即時損失 | dp1 後 |
 | --- | --- | --- | --- |
 | ラウンドの開始 | × | x・r | x(1-r) |

 これは、対戦相手の介入がラウンド内の確率的プロセスからどのように分離されるかを示しています。 マトリックスは内部ダイナミクスのみを処理し、相手のイベントは遷移前の吸収として処理されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log ai) | 各ラウンドでは 2 つの 3x3 累乗を使用します。 
| スペース | お(1) | 一定サイズの行列と DP 状態のみ |

 ## 特殊なケース

 p、q、r がすべて 0 の場合、遷移行列は決して到達しない吸収状態を除いて恒等変換になります。 このアルゴリズムは dp を正確に変更せずに維持し、すべてのラウンドで損失確率をゼロにします。 

r が最大のとき、ラウンドの開始時に dp1 がゼロ以外のときは常に、その状態からの寄与全体がそのラウンドの損失確率に即座に変換されます。 マトリックス フェーズは依然として生き残った部分にのみ適用されるため、二重カウントは発生しません。 

ai が 80 より小さい場合、第 2 フェーズ行列はまったく使用されないため、アルゴリズムは単一の行列累乗に減らされます。 これは、オーバーフロー条件が存在しない場合、相分割によってアーチファクトが発生しないことを確認します。
