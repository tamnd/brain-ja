 ## 問題の理解

 いくつかの独立したデータセットが与えられています。 各データセットには複数の種類の団子があります。 各種類には供給量が限られており、その種類の団子を食べるたびに報酬が与えられますが、同じ種類の団子を食べ続けると報酬が減少します。 

具体的には種類ごとに$i$、 がある$s_i$餃子が利用可能です。 を食べると、$j$このタイプの餃子の 1 番目、あなたが得られる満足度は、$i$そして$j$、世界的に食べるときはオンではありません。 初めての餃子タイプ$i$追加のボーナスが得られるため特別です$c_i$したがって、その値は次のようになります。$a_i + c_i$。 その後、餃子を追加するたびに、満足度は直線的に低下していきます。$j$-th (の$j > 1$) を与えます$a_i - b_i \cdot (j - 1)$。 

せいぜい食べられる$m$餃子は全種類合計です。 さらに、食べた餃子の総数が期間内に収まった場合は、グローバル ボーナスがあります。$[l, r]$、追加の固定値を獲得します$val$、どの餃子を選んだかに関係なく。 

目標は、ボーナスを含めた総合的な満足度が最大になるように、各種類の餃子を何個食べるかを選択することです。 

制約は大きく、最大で$10^5$テスト ケース、およびすべてのテストにわたるタイプの数の合計は最大で$3 \cdot 10^5$。 ただし、各タイプには最大で$10^6$原則として餃子、$m$大きくすることもできます。 これにより、すべての餃子を明示的に列挙したり、項目ごとの選択をシミュレートしたりするソリューションは即座に除外されます。 すべての個々の団子をグローバルに並べ替えるようなことを行うと、時間とメモリの両方で遅すぎます。 

価値関数の構造が重要な問題です。 各タイプは減少する等差数列を生成します。タスクは、これらすべてのシーケンスにわたって利用可能な最良のアイテムのグローバル プレフィックスを選択すると同時に、選択された合計数に応じた区分ボーナスも考慮することです。 

いくつかの微妙な特殊なケースを強調する価値があります。 

問題の 1 つは、餃子の最適な数が常に最適であるとは限らないことです。$m$。 多くの値がマイナスになる場合は、ボーナスが補わない限り、餃子を食べる量を減らしたほうが良い可能性があります。 たとえば、すべてが$a_i$とてもネガティブで、$val = 0$、最適な戦略は、餃子をゼロにすることかもしれません。 

もう一つの問題はボーナス間隔です。 餃子をもっと食べると生の満足感が増すとしても、中に着地するために早めにやめたほうがよいかもしれません。$[l, r]$。 常に必要な愚直な戦略$m$餃子を追加し、該当する場合はボーナスを追加します。次の場合は失敗します。$m > r$ただし、プレフィックスをわずかに小さくすると、ボーナス調整後の結果が大幅に高くなります。 

最後に、各タイプの最初の要素は、残りの要素とは異なる動作をします。 すべての型を次から始まる単純な等差数列として扱います。$a_i$の代わりに$a_i + c_i$最初の項目を過小評価し、項目をグローバルに混合するときに誤った順序付けにつながります。 

## アプローチ

 直接的な総当たり解釈では、すべての団子を独立した項目として扱い、すべての団子を生成します。$s_i$値を明示的に取得し、それらをグローバル リストにマージし、降順で並べ替えて、プレフィックスを取得します。 各ダンプリングにはグローバルな順序とは独立した固定値があるため、これは概念的には正しいです。 ただし、ダンプリングの総数は膨大になる可能性があり、生成または分類できる数をはるかに超えています。 合計だけを仮定しても$m$ただし、各タイプが値の減少のロングテールに寄与する可能性があるため、依然として効率的に候補を生成することはできません。 

重要な点は、それぞれのタイプが恣意的ではないということです。 その値は、最初の要素の後に一定の傾きを持つ単調減少シーケンスを形成します。 この構造により、すべての要素を明示的に生成することを回避できます。 項目を列挙する代わりに、別の質問をします。しきい値が与えられた場合$x$、すべての種類で少なくとも価値のある餃子の数はいくつありますか$x$、その合計はいくらになるでしょうか？ 

これにより、問題はしきい値による選択問題に変換されます。 計算できれば、どんなことでも$x$、少なくとも価値のあるアイテムの数$x$を選択すると、正確に選択することに対応するしきい値を二分探索できます。$k$最高のアイテム。 各タイプがしきい値を超えて寄与しているアイテムの数がわかれば、等差級数の公式を使用してそれらの合計寄与度を計算することもできます。 

これにより、完全なマルチセットを構築する必要がなくなります。 ソリューション全体は、二分探索中にタイプごとに一定時間で各タイプを繰り返し評価することに帰着します。 

最後に、ボーナス期間は選択した合計額にのみ依存します。$k$、どの項目が選択されているかではありません。 固定値の最適な合計を計算できるようになると、$k$、少数の候補者を評価するだけで済みます。$k$値を使用して、ボーナスを獲得するために生の値を犠牲にする価値があるかどうかを判断します。

 ## アルゴリズムのチュートリアル

 問題を、正確な場合に可能な限り最良の合計を計算できるようにすることに帰着します。$k$餃子が選ばれます。 

まず、しきい値が与えられた場合に次の関数を定義します。$x$、少なくとも価値のある餃子が合計でいくつあるかを計算します。$x$、そしてそれらの合計はいくらか。 

1. 種類ごとに$i$、そのシーケンス内に少なくともいくつのアイテムが含まれているかを決定します。$x$。 最初の項目には値があります$a_i + c_i$、以降のすべての項目が続きます$a_i - b_i (j-1)$。 推論を、最初の項目が適格であるかどうかと、算術末尾のいくつが適格であるかに分割します。 これにより、一定時間内のタイプごとの閉じたフォームの数が得られます。 
2. これらの数をすべてのタイプにわたって集計します。 これにより単調関数が得られます$F(x)$、少なくとも価値のあるアイテムの数$x$。 増えるから$x$候補者のみを削除します。$F(x)$単調減少です。 
3. 二分探索を行います$x$少なくとも値を持つすべての項目を選択するしきい値を見つけるには$x$少なくとも与える$k$アイテムを選択しますが、少なくとも$x+1$より少ないものを与える$k$。 このしきい値は上部の境界を表します。$k$価値観。 
4. しきい値がわかったら、それを厳密に超えるすべての項目の合計を計算します。 これらは間違いなくトップの一部です$k$。 また、正確にしきい値を持つ追加項目がいくつ必要になるか計算します。$k$、そして彼らの貢献を追加します。 
5. これにより、次の結果が得られます$S(k)$、正確に摂取することによって達成できる最大の総合的な満足度$k$餃子。 
6. 次に、ボーナスを組み込みます。 意味のある 2 つの選択肢を評価します。 1 つは取っています$k = m$、生の選択を最大化します。 もう一人は取っています$k = \min(m, r)$、これはボーナス期間内の最大サイズです。 これなら$k$少なくとも$l$、追加します$val$そのスコアに。 
7. これらの候補間の最大値を採用します。 

### なぜ効果があるのか

 餃子の選択は頂点を取ることに等しい$k$単調算術シーケンスによって暗黙的に定義されたマルチセットからの値。 しきい値法は、このマルチセット プレフィックスを正しく再構築します。これは、最適解は世界的に最大の利用可能な値で構成されている必要があり、単調な構造により上位のメンバーシップが保証されるためです。$k$単一のカットオフ値でテストできます。 

ボーナスの最適化はアイテムのアイデンティティとは独立しており、のみに依存します。$k$、したがって、検索スペースを少数の候補に減らします$k$値は、すべてのサイズにわたって完全な DP を必要とせずに最適性を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def calc_count_sum(a, b, c, s, x):
    # returns (count, sum) of values >= x in this type
    # first item
    cnt = 0
    total = 0

    # first item value
    first = a + c
    if s >= 1 and first >= x:
        cnt += 1
        total += first

    # tail: j>=2 => a - b*(j-1)
    # we need a - b*t >= x where t=j-1, t>=1
    # a - b*t >= x => t <= (a - x)/b
    if s >= 2:
        max_t = (a - x) // b
        if max_t >= 1:
            use_t = min(max_t, s - 1)
            # t from 1..use_t
            # values: a-b*t
            cnt += use_t
            # sum = sum_{t=1..u} (a - b*t)
            total += use_t * a - b * (use_t * (use_t + 1) // 2)

    return cnt, total

def get_prefix_sum(types, k):
    # binary search threshold on value range
    lo, hi = -10**12, 10**12

    while lo < hi:
        mid = (lo + hi + 1) // 2
        cnt = 0
        for a, b, c, s in types:
            cnt += calc_count_sum(a, b, c, s, mid)[0]
        if cnt >= k:
            lo = mid
        else:
            hi = mid - 1

    threshold = lo

    cnt = 0
    total = 0
    for a, b, c, s in types:
        c1, s1 = calc_count_sum(a, b, c, s, threshold)
        cnt += c1
        total += s1

    # too many elements equal to threshold, remove extras
    if cnt > k:
        excess = cnt - k
        total -= excess * threshold

    return total

def solve():
    T = int(input())
    for _ in range(T):
        n, m, val, l, r = map(int, input().split())
        types = []
        for _ in range(n):
            s, a, b, c = map(int, input().split())
            types.append((a, b, c, s))

        best = 0

        # option 1: take m items
        best = max(best, get_prefix_sum(types, m) + (val if l <= m <= r else 0))

        # option 2: take r items if beneficial
        k = min(m, r)
        if k >= l:
            best = max(best, get_prefix_sum(types, k) + val)

        # also allow k=0 implicitly
        print(best)

if __name__ == "__main__":
    solve()

機能`get_prefix_sum`値ドメインで二分検索を実行します。 重要な点は、インデックスを直接検索しないことです。 代わりに、この問題の正しい単調次元である値のしきい値を検索します。 しきい値を見つけた後、合計を再構築し、境界値を共有する余分な項目を削除することで超過数を修正します。 

最後に、メインのソリューションは、次の 2 つの意味のある選択肢のみを評価します。$k$、ボーナスは区分的に一定であるため、$k$接頭辞の合計は単調です$k$。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が負であるにもかかわらずボーナスがゼロである場合です。 アルゴリズムは依然として正確にゼロを返します。これは、正の接頭辞の合計がゼロであるためです$k$ネガティブになり、$k = 0$暗黙的に支配している。 

もう 1 つのエッジケースは次のような場合です$m$ボーナス期間の外にありますが、$r$収益性の高い地域内にあります。 アルゴリズムは明示的に評価します$k = \min(m, r)$、最高のボーナス構成を見逃さないようにします。 

最後の微妙なケースは、バイナリ検索中に多くのアイテムがしきい値を正確に共有する場合です。 余分なものを差し引く補正ステップ$(cnt - k) \cdot threshold$最終的な選択が正確であることを保証します$k$順序付けの前提に違反することなくアイテムを作成し、境界での重複が多い場合でも正確さを維持します。
