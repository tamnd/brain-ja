 ## 解決策
 ## 問題の理解

 単一の整数が与えられます`x`、固定基本コストに適用される税金または追加料金の割合を表します。 基本コストは常に 50 ユニットです。 最終的に支払う金額は、基本コストにその基本コストの追加パーセンテージを加えたものになります。 

具体的には、追加料金は次のように計算されます。`50 × x / 100`、支払い総額は`50 + 50 × x / 100`。 出力形式では、この最終値を、小数点以下 3 桁に四捨五入した 10 進数として、先頭に文字列を付けて出力する必要があります。`Vivo`。 

整数が 1 つと定数時間の算術計算しかないため、アルゴリズムの複雑さの点では入力サイズはわずかです。 それでも`x`最大 19,198,100 まで大きくても、浮動小数点演算やスケーリングされた整数演算では安全に計算が行われます。 唯一の微妙な点は、正しい丸めと書式設定にあります。 

主なエッジケースは、計算ではなくフォーマットに起因します。 いつ`x = 0`、結果は正確に残るはずです`50.000`。 いつ`x`が大きい場合、結果は 100 万近くに達する可能性がありますが、それでも標準の倍精度に快適に収まります。 もう 1 つのエッジ ケースは、適切な丸めです。次のような値です。`x = 1`生産する`50.5`、次のように出力する必要があります。`50.500`、 ない`50.5`または`50.5000`。 

不注意な実装は、整数の除算が使用される場合にも精度を失う可能性があります。`50 * x // 100`これにより、小数部分の寄与が完全に破棄され、丸めが中断されます。 

## アプローチ

 ブルートフォース解釈では、整数演算を使用して段階的にパーセンテージ計算を直接シミュレートしようとします。 追加料金を次のように計算してみるかもしれません。`(50 * x) / 100`整数の除算を使用します。 これはすでに最適に近い状態ですが、フロア分割を誤って実行すると、小数点以下が保持されるのではなく、暗黙的に切り捨てられます。 もう 1 つの単純なアイデアは、精度の制御を考慮せずにすべてを浮動小数点に変換し、生の結果を出力することです。これにより、書式設定のデフォルトに応じて丸め動作が矛盾する危険があります。 

重要な観察は、式が単一の線形式であるということです。 反復、条件構造、および複数の入力間の依存関係はありません。 これにより、問題は定数時間の算術式の評価と出力の正しいフォーマットに軽減されます。 このスケールには Python の浮動小数点演算で十分であるため、唯一の実際の要件は、書式設定ステップで小数点以下 3 桁の四捨五入を強制することです。

 ## アルゴリズムのチュートリアル

 問題の定義から直接結果を計算し、フォーマットを慎重に制御します。 

1. 整数を読み取る`x`入力から。 これは、基本コスト 50 に適用されるパーセンテージです。 
2. パーセンテージの乗数効果を次のように計算します。`x / 100.0`。 整数の除算では小数部分が切り捨てられるため、ここでは浮動小数点除算の使用が不可欠です。 
3. 基本コスト 50 にこの乗数を乗じて、追加料金を取得します。 これは、ベースに適用される正確な比例追加料金を表します。 
4. 計算された追加料金に基本コスト 50 を加算して、最終金額を取得します。 
5. 小数点以下 3 桁の固定小数点形式を使用して結果を形式設定します。 このステップでは、出力仕様で必要な丸めルールを適用します。 
6. 接頭辞を付けた結果を出力します。`Vivo `。 

### なぜ効果があるのか

 計算は次の一次関数の直接評価です。`x`。 すべての変換は元の式との等価性を維持するため、`50 × (1 + x / 100)`、アルゴリズムは意図した値から逸脱することはできません。 矛盾の唯一の潜在的な原因は数値表現であり、制御された書式設定と組み合わせた標準の浮動小数点演算を使用することで、最終的に出力される値が必要な丸めセマンティクスと一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x = int(input().strip())

base = 50.0
total = base + base * (x / 100.0)

print(f"Vivo {total:.3f}")
```このソリューションは、単一の整数を読み取り、定数時間で即座に数式を評価します。 基本値は浮動小数点として明示的に書き込まれ、式全体が浮動小数点空間に留まり、偶発的な整数の切り捨てが回避されます。 

書式設定文字列`:.3f`丸めと固定幅の 10 進数出力の両方を強制するため、これは重要です。 これがないと、Python は可変の小数点以下の桁数を出力する可能性があり、出力要件を満たさないことになります。
