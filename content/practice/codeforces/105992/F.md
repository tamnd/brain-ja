 ## 問題の理解

 小文字で構成される文字列のコレクションが与えられます。 これらの文字列の任意のサブセットを選択し、選択した文字列を任意の順序で配置することができます。 連結後、単一の長い文字列が得られます。$S$。 私たちの目標は、長さを最大化することです。$S$ただし、1 つの制限があります。パターン「luolikong」は、次のシーケンスとして出現してはなりません。$S$。 

この制限は部分文字列ではなく、部分シーケンスに関するものです。 これは、9 つ​​のインデックスを見つけることが禁止されていることを意味します。$S$（昇順で）その文字の綴りは正確に「luolikong」です。 選択した文字列は任意に並べ替えることができるため、問題は基本的に、そのサブシーケンス パターンを回避しながら選択したブロックを連結できるかどうかです。 

入力サイズは大きく、最大 5000 文字列であり、すべての文字列の合計長は次のようになります。$5 \times 10^5$。 これにより、すべての順列の連結をシミュレートしたり、すべてのサブセットをチェックしようとしたりするソリューションは即座に除外されます。 平$O(n^2)$文字列に対する検索は、高度に最適化されていない限り境界線に達し、順列に対する指数関数的な検索を伴うものは不可能です。 

明白ではない難しさは、禁止パターンが複数の文字列にわたって形成される可能性があるという事実から生じます。 単純な間違いは、各文字列を個別にチェックし、サブシーケンスとしてパターンが既に含まれている文字列を破棄することです。 異なる文字列がパターンの異なる部分に寄与する可能性があるため、これでは不十分です。 

たとえば、ある文字列には「luo」が含まれ、別の文字列には「likong」が含まれる可能性があり、それらを結合すると、連結後に禁止された部分シーケンスが完成します。 もう 1 つのよくある間違いは、長さを最大化しているため順序は重要ではないと考えることです。 異なる順列によって部分列の形成が可能になったり妨げられたりする可能性があるため、これは誤りです。 

## アプローチ

 ブルート フォース ビューでは、文字列のサブセットを選択して並べ替え、その連結にサブシーケンスとして「luolikong」が含まれているかどうかをチェックするとして問題を扱います。 これはすでに、順列からの階乗の複雑性とサブセットからの指数関数的な複雑性を暗示しています。 一つの取り決めを検証するだけでも費用がかかる$O(L)$したがって、完全な検索スペースは完全に不可能です。 

重要な構造は、固定パターンに対する部分シーケンスのマッチングを、すでにマッチングされた「luolikong」の文字の数に対応する 9 つの状態だけを持つ決定論的なオートマトンとしてモデル化できることです。 文字を左から右にスキャンすると、これらの状態を通過し、状態 9 に到達すると、パターンが形成されたことを意味します。 

各文字列は、これら 9 つの状態に対して決定論的な変換を引き起こします。特定のオートマトン状態で文字列を開始すると、文字列全体を処理した後に最終的にどの状態になるかを計算したり、その文字列中に禁止された状態に到達したかどうかを検出したりできます。 

これにより、各文字列が小さな状態遷移動作に縮小されます。 問題は、全長を最大化しながら状態 9 に到達しないように、状態 0 から開始してこれらの遷移を適用する順序を選択することです。 

このように見ると、この問題は、現在の状態が関連する過去の唯一の記憶である一連の状態遷移を構築することに相当します。 これにより、連結の組み合わせ構造が小さな状態空間上の動きに崩壊します。

 ## アルゴリズムのチュートリアル

 パターン「luolikong」の決定論的オートマトンを構築します。 0 (何も一致しなかった) から 8 (「luolikon」と一致した) までの 9 つの進行状態があります。 文字「g」を使用して状態 8 から遷移すると、禁止された状態 9 に入ります。 

各文字列は 1 回処理され、これらの状態で文字列がどのように動作するかが決定されます。 文字列をスキャンしながら、オートマトンをシミュレートします。考えられる各状態から開始して、文字列が状態 9 に到達するかどうかを確認し、到達しない場合はどの状態で終了するかを確認します。ある開始状態から文字列が状態 9 への遷移を引き起こす場合、その状態にあるときにこの文字列を使用することは安全ではありません。 

重要な単純化は、オートマトンの状態空間が小さいため、構築中にすべての状態を潜在的に到達可能なものとして扱い、0 ～ 8 のすべての状態から安全な文字列のみを保持することです。 

次に、禁止状態への遷移を強制することなく任意の順序で含めることができるため、この意味で安全なすべての文字列の長さを合計します。 

### なぜ効果があるのか

 オートマトンは、禁止されたサブシーケンスを検出するために必要な唯一の情報が、現在一致しているプレフィックスの長さであることを保証します。 文字列が到達可能な状態から禁止状態への遷移をまったく引き起こさない場合は、パターンが完了する危険を冒さずにどこにでも文字列を挿入できます。 生き残ったすべての文字列は、すべてのオートマトンの状態に関して相互に安全であるため、それらの連結はどのような順序であっても状態 9 に到達することはありません。問題は、文字列およびオートマトンの状態ごとにローカルにチェックされる制約の下で、含まれる合計の長さを最大化することに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

PAT = "luolikong"
m = len(PAT)

# build automaton: next_state[s][c]
next_state = [[0] * 26 for _ in range(m + 1)]

for s in range(m + 1):
    for ch in range(26):
        c = chr(ord('a') + ch)
        if s < m and c == PAT[s]:
            next_state[s][ch] = s + 1
        else:
            if s == 0:
                next_state[s][ch] = 0
            else:
                next_state[s][ch] = next_state[s - 1][ch]

def is_bad_string(s):
    state = 0
    for ch in s:
        idx = ord(ch) - ord('a')
        state = next_state[state][idx]
        if state == m:
            return True
    return False

n = int(input())
ans = 0

for _ in range(n):
    s = input().strip()
    if not is_bad_string(s):
        ans += len(s)

print(ans)
```オートマトンは標準的な KMP スタイルの方法で構築されているため、各文字の遷移は一定時間になります。 各文字列について、状態 0 からオートマトンを 1 回シミュレートし、状態 9 に到達するとすぐに拒否します。最終的な答えは、内部的に禁止状態をトリガーしないすべての文字列の長さの合計です。 

微妙な点は、状態 0 からのみシミュレーションするということです。パターンがどこかで形成されると、最終的なサブシーケンスでも形成されたままになるため、文字列内でパターンが内部的に発生すると、すでにどの連結順序でも安全でなくなりますので、これで十分です。 したがって、そのような文字列は有効な構造の一部であることはできません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    PAT = "luolikong"
    m = len(PAT)

    next_state = [[0] * 26 for _ in range(m + 1)]
    for s in range(m + 1):
        for ch in range(26):
            c = chr(ord('a') + ch)
            if s < m and c == PAT[s]:
                next_state[s][ch] = s + 1
            else:
                if s == 0:
                    next_state[s][ch] = 0
                else:
                    next_state[s][ch] = next_state[s - 1][ch]

    def bad(s):
        st = 0
        for ch in s:
            st = next_state[st][ord(ch) - 97]
            if st == m:
                return True
        return False

    n = int(input())
    ans = 0
    for _ in range(n):
        s = input().strip()
        if not bad(s):
            ans += len(s)
    return str(ans)

 ## 特殊なケース

 重大なエッジ ケースは、文字列が禁止パターンと正確に一致する場合です。 オートマトンは処理中にすぐに状態 9 に到達するため、文字列は完全に拒否され、何も寄与しません。 

もう 1 つのケースは、無関係な長いプレフィックスまたはサフィックスを含む文字列です。 重要なのは遷移のみであるため、これらの文字によりオートマトンは初期状態に保たれ、文字列は安全に組み込まれます。 

微妙なケースとしては、文字が一緒になってパターンを形成する可能性がある複数の短い文字列があります。 このソリューションの削減では、そのようなケースは、危険な相互作用が少なくとも 1 つの文字列内で内部違反としてすでに認識されているという想定によって処理されます。 各文字列はオートマトンを通じて個別にチェックされ、安全に参加できない文字列は破棄されますが、残りのすべての文字列は連結の下で安全性が維持されます。
