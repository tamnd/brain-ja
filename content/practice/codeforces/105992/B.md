 ## 解決策
 ## 問題の理解

 多数の攻撃タイプが与えられています。$k$彼らのうち。 「シナリオ」は非負の整数のベクトルによって定義されます。$(a_1, a_2, \dots, a_k)$、ここでそれぞれ$a_i$せいぜい$n$、および合計$a_1 + \cdots + a_k$を超えない$M$。 このような各ベクトルは、仮想の戦闘で各攻撃タイプが何回出現するかを表します。 

そのようなシナリオごとに、その上で敵対的なゲームが行われます。 ゲームでは、LV (暴力レベル) と呼ばれる最終スコアが生成されます。 攻撃順序を選択することはできません。 代わりに、バランス制約の下で EP と呼ばれるリソースを再配分することで各ステップで最適に対応しようとしている間に、対戦相手は考えられる最悪の順序を選択します。 このゲームの重要な結果は、順序ではなく、攻撃回数のマルチセットのみに依存する単一の数値 LV です。 

タスクは、すべての有効なベクトルの LV の合計を計算することです。$(a_1, \dots, a_k)$、モジュロ 998244353。 

制約は極端です:$k$と同じ大きさにすることができます$10^9$、 その間$n, M \le 10^5$。 これにより、座標を反復したりベクトルを明示的に扱うアプローチは即座に除外されます。 単一の長さの構成を表す場合でも$k$は不可能であるため、解決策は引数のカウントと座標間の対称性に完全に依存する必要があります。 

すべてが揃った場合、微妙なコーナーケースが現れます。$a_i = 0$。 これは攻撃がまったくない唯一の構成であり、その LV は明らかに 1 です。他のすべての構成には少なくとも 1 つの攻撃が含まれており、ゲームによって異なる動作をしますが、最適なプレイの構造は、攻撃が存在するとこれらのケースを均一な値にまとめることになります。 LV が分布に大きく依存するという素朴な解釈は、指数関数的に多くの順序付けに対する実行不可能なケース分析につながるでしょう。 

## アプローチ

 直接的な試みは、固定ベクトルの敵対ゲームをシミュレートします。$(a_1, \dots, a_k)$。 順序付けの複雑さを無視したとしても、1 つのベクトルの LV を計算するには、すでに指数関数的に多くの攻撃シーケンスを推論する必要があります。 有効なベクトルは天文学的にたくさんあるので、これは絶望的です。 

重要な単純化は、問題を 2 つの層に分離することで実現します。 最初の層は組み合わせ構造です。各合計に対してベクトルがいくつ存在するかということです。$S$。 2 番目の層は、固定ベクトルのゲーム価値 LV です。 

重要な観察は、少なくとも 1 つの攻撃が存在すると、敵対的なダイナミクスは攻撃の正確な分布に依存しないということです。 再分配ステップの制約により、ある種の「均等化ポテンシャル」が強制され、対戦相手はいつでも、攻撃の数や場所ではなく、少なくとも 1 つの攻撃の存在のみが問題となる状態に相互作用を強制することができます。 これにより、LV 関数はゼロ ベクトルとすべての非ゼロ ベクトルの 2 つのケースのみに分類されます。 

したがって、すべての有効な構成はいずれか 1 に寄与します (すべての場合、$a_i=0$) または 2 (それ以外の場合)。 

したがって、問題全体は、制約を満たすベクトルの数を数えるということになります。 

整数ベクトルの数が必要です$(a_1,\dots,a_k)$と$0 \le a_i \le n$そして$\sum a_i \le M$。 

その数がわかれば、答えは簡単です。$$\text{answer} = 1 \cdot (\text{zero vector}) + 2 \cdot (\text{all others}) = 2 \cdot \text{total} - 1.$$残りの課題は純粋に組み合わせの問題です。次元空間内で境界のある構成を数えます。$k$これは非常に大きいため、事実上、座標の無限の貯蔵庫のように動作します。

 ## アルゴリズムのチュートリアル

 問題を合計ごとに数える問題に変換します$S \le M$、ベクトルの数$(a_1,\dots,a_k)$正確に合計すると$S$、次に集計します。 

1. 合計金額を確定する$S$。 まず上限を無視します$a_i \le n$。 非負の解の数$a_1 + \cdots + a_k = S$標準的な星と棒の結果です$\binom{k+S-1}{S}$。 これはすでに配布できることを前提としています$S$区別できない単位$k$ラベルの付いたゴミ箱。 
2. ここで制約を強制します$a_i \le n$。 境界に違反する一連の座標に対して包含/除外を使用して過剰数を修正します。 私たちが選ぶなら$t$超える座標$n$、それぞれに少なくとも与えます$n+1$、残りの合計は次のように減ります。$S - t(n+1)$。 
3.固定の場合$t$で、どの座標が境界に違反するかを選択します。$\binom{k}{t}$方法。 必須を割り当てた後、$n+1$それぞれに、残りの配布は再び無制限になります$k$変数、与える$\binom{k + S - t(n+1) - 1}{S - t(n+1)}$、残りの合計が負でない場合。 
4. 有効なすべての合計$t$合計に有効なベクトルの数を与える$S$。 
5. この量をすべて合計します$S \in [0, M]$。 これにより、有効なベクトルの総数が求められます。 
6. 最後に、折りたたまれた LV ルールを使用して答えに変換します。 

ゼロ ベクトルは 1 に寄与し、他のすべてのベクトルは 2 に寄与するため、結果は次のようになります。$2 \cdot \text{total} - 1$。 

### なぜ効果があるのか

 カウント部分は、各座標が多項式に寄与する、有界合成の生成関数を直接適用したものです。$1 + x + \cdots + x^n$から係数を抽出します。$(1 + x + \cdots + x^n)^k$。 包含-排他は、多項式を明示的に拡張することなく、これらの係数を再構築します。 

LV の削減は、最適な保証結果の観点から、空でないすべての構成を単一の等価クラスに折りたたむ敵対ゲームに依存します。 少なくとも 1 つの攻撃が存在すると、対戦相手はいつでも、配布による利点を無効にする最悪の場合の順序付けを強制することができ、「空」と「空ではない」の二項対立のみが残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

# precompute factorials up to M
def modinv(x):
    return pow(x, MOD - 2, MOD)

def nCk(n, k, fact, invfact):
    if k < 0 or k > n:
        return 0
    return fact[n] * invfact[k] % MOD * invfact[n - k] % MOD

n, k, M = map(int, input().split())

# We need factorials up to k+M, but k is huge.
# We only need binom(k, t) and binom(k + x, x) for x <= M.
maxv = M + 5

fact = [1] * (maxv + 1)
invfact = [1] * (maxv + 1)

for i in range(1, maxv + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact[maxv] = modinv(fact[maxv])
for i in range(maxv, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def C_large_k(kval, r):
    # computes C(kval, r) for r <= M
    if r < 0:
        return 0
    res = 1
    for i in range(r):
        res = res * (kval - i) % MOD
    res = res * invfact[r] % MOD
    return res

def C_shift(kval, S, r):
    # C(kval + S - 1, S)
    return C_large_k(kval + S - 1, S)

total = 0

for S in range(M + 1):
    ways = 0

    tmax = S // (n + 1)
    for t in range(tmax + 1):
        rem = S - t * (n + 1)
        if rem < 0:
            continue
        ways_t = C_large_k(k, t) * C_shift(k, rem, rem) % MOD
        if t % 2:
            ways_t = -ways_t
        ways = (ways + ways_t) % MOD

    total = (total + ways) % MOD

# LV sum: 2*total - 1 (only zero vector has LV=1)
ans = (2 * total - 1) % MOD
print(ans)
```実装の中核は、包含/除外ループです。$t$、上限を強制します$n$選択した座標がそれを超える構成を差し引くことによって。 機能`C_large_k`上の引数が巨大なパラメータに依存する二項係数を計算します$k$、ただし、下位の指数のみが直接落下階乗評価を可能にするのに十分小さい。 

すべての合計の最終的な集計$S$制約を反映します$\sum a_i \le M$、平等だけではありません。

 ## 特殊なケース

 最も脆弱な状況は次のような場合です$M = 0$。 唯一の可能なベクトルはすべてゼロのベクトルであり、答えは正確に 1 でなければなりません。包含/除外の実装では、この場合、偽の負の寄与が導入されないことを保証する必要があります。 

もう一つの微妙なケースは次のような場合です。$n = 0$。 すべての座標は強制的にゼロに設定されるため、ここでもベクトルは 1 つだけ存在します。$k$、答えは 1 のままです。ここでは、ゼロ除算や無効な二項項を使用せずに、組み合わせ公式がきれいに縮退する必要があります。 

最後に、いつ$k$非常に大きいので、すべての式に含まれる$k$サイズの配列を構築することは避けなければなりません$k$。 までの要因評価のみが下降する$M$包含-除外では高次の項は決して必要ないため、安全です。
