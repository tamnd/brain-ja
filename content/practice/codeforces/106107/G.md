 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースには正方形の集合があり、各正方形の辺の長さは整数です。 このコレクションから、これら 3 つの正方形をエッジを揃えて配置して、隙間や重なりのない長方形を正確に並べて配置できるように、3 つの異なる正方形を選択する方法が何通りあるかを数えなければなりません。 

選択した各正方形は完全に使用する必要があり、正方形は対称であるため回転する必要はありません。また、正方形を分割したり結合したりすることはできません。 問題は純粋に、与えられた 3 つの正方形タイルがより大きな長方形を完全に形成できるかどうかです。 

この制約により、すべてのテスト ケースで合計 200,000 個の正方形が許可されるため、すべてのトリプルを直接試行するソリューションは不可能です。 テスト ケースごとの 3 次または 2 次のアプローチは生き残れません。 意図した解決策では、問題を辺の長さの頻度にわたるパターンをカウントすることに減らす必要があります。 

微妙な点は、平面上に正方形を任意に配置しているのではなく、何らかの配置が存在するかどうかを確認しているだけであるということです。 これは、配置をシミュレートするのではなく、有効な幾何学的タイルを分類していることを意味します。 

3 つの正方形の面積の合計が長方形の面積に達する場合、それらを組み合わせることができると仮定すると、単純な落とし穴が発生します。 たとえば、辺が 1、2、3 の正方形の総面積は 14 ですが、これは軸に揃えられた正方形の意味のあるタイリングという意味では完全な長方形の領域ではありませんが、面積に基づく推論だけでは不十分で誤解を招きます。 

もう 1 つのよくある間違いは、2 つの等しい正方形があれば常に十分であると想定することです。 たとえば、辺 2、2、3 は、たとえ重複が対称性を示唆しているとしても、有効な長方形タイリングを形成しません。 

最も難しいのは、正確に 3 つの正方形に対して限られた数の有効なタイル構成を特定することです。 

## アプローチ

 ブルートフォース手法では、インデックスのすべてのトリプルを試し、3 つの正方形が長方形を形成できるかどうかを確認します。 各トリプルについて、すべての幾何学的配置を試みるか、すべてのタイル構成を同等にテストします。 これはおおよそ次のことにつながります$O(n^3)$テスト ケースごとに 3 倍になりますが、これは実行可能な制限をはるかに超えています。$n$到達する$2 \cdot 10^5$。 

幾何学的チェックを最適化したとしても、ボトルネックは依然としてトリプルの数です。 重要な観察は、ちょうど 3 つの正方形を含む有効なタイリングの構造が非常に制限されていることです。 

正方形から長方形を構築することを想像すると、長方形を軸が揃った 3 つの正方形に分割する基本的な方法は 2 つだけです。 1 つは、3 つの同一の正方形を行または列に配置することです。 もう 1 つは、2 つの同一の小さな正方形を配置してストリップを形成し、1 つの大きな正方形が他の次元の残りのスペースを占めることです。 

この観察により、問題は幾何学から辺の長さにわたる頻度のカウントに変換されます。 トリプルをテストする代わりに、値のマルチセット内の 2 つの特定のパターンをカウントするだけで済みます。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、各正方形の辺の長さが何回出現するかを数えます。 これにより、問題が個々の正方形から同一サイズの周波数に軽減されます。 
2. 3 つの正方形すべての辺の長さが同じであるトリプルを数えます。 値の場合$x$表示されます$f$回であれば貢献します$\binom{f}{3}$有効なトリプル。 これは、同じ正方形の 3 行 1 列のストリップとして長方形を形成することに対応します。 
3. 2つの正方形が一辺の長さであるトリプルを数えます$a$そして、1つの正方形は辺の長さを持ちます$2a$。 それぞれの値について$a$、 もし$2a$が存在する場合、そのようなトリプルを選択する方法は次の数です。$\binom{f[a]}{2} \cdot f[2a]$。 これは、$2 \times 1$1 次元でタイリングし、残りの領域を 1 つの正方形で埋めます。 
4. すべての値に対する両方の寄与を合計し、テスト ケースの結果を出力します。 

### なぜ効果があるのか

 正確に 3 つの正方形を使用して長方形を有効にタイリングするには、3 つの等しい正方形からなる 1 つの行または列を形成するか、1 つの正方形が次元全体に広がり、他の 2 つの正方形が残りの領域を対称的に埋める 2 層構造を形成する方法で正方形を配置する必要があります。 ギャップを作成したり非正方形領域を強制したりせずに、長方形を軸が等しくない 3 つの正方形に分割する方法はありません。 これにより、すべての有効な構成が正確に 2 つのカウントされるケースに制限され、カウントが完全かつ正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import Counter

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        freq = Counter(a)
        ans = 0
        
        for x, fx in freq.items():
            if fx >= 3:
                ans += fx * (fx - 1) * (fx - 2) // 6
            
        for a_val, fa in freq.items():
            b_val = 2 * a_val
            if b_val in freq:
                ans += fa * (fa - 1) // 2 * freq[b_val]
        
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず入力を周波数マップに圧縮します。 すべての有効な構造は、各辺の長さの位置ではなく、各辺の長さが出現する回数のみに依存するため、これは不可欠です。 

同一のトリプルの組み合わせ式は、順序付けされていないインデックスの選択を直接カウントします。 2 番目の項では、1 つの値をより大きな正方形として慎重に固定し、2 つの同一のより小さな値を選択します。 トリプルはインデックス セットによって定義されるため、組み合わせを使用すると順序付けの問題が回避されます。$i < j < k$。 

実装の微妙な詳細は、生の配列ではなく周波数マップを反復処理し、テスト ケースごとの線形動作を保証します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n)$テストケースごと | 各要素は 1 回カウントされ、各周波数は 1 回処理されます。 
| スペース |$O(n)$| 周波数マップは個別の辺の長さを格納します。

from collections import Counter

    sys.stdin = io.StringIO(inp)
    output = []
    
    import sys
    input = sys.stdin.readline

    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        freq = Counter(a)
        ans = 0

            if fx >= 3:

            b_val = 2 * a_val
            if b_val in freq:
                ans += fa * (fa - 1) // 2 * freq[b_val]
        
        output.append(str(ans))
    
    return "\n".join(output)

 ## 特殊なケース

 すべての正方形が同一である場合、特殊なケースが発生します。 入力用`1 1 1`、3 つすべてを選択する方法は 1 つだけあり、有効な長方形を形成します。 アルゴリズムはこれを完全に結合項を通じて処理します。$\binom{f}{3}$、追加のロジックなしですべてのインデックス トリプルを正確にカウントします。 

もう 1 つのエッジケースは、混合パターンのみが存在する場合です。`2 2 4`。 ここでアルゴリズムは厳密な関係のみを考慮するため、無効な取り決めのカウントを回避します。$b = 2a$、無関係な値が誤って含まれることを防ぎます。 

最後の微妙なケースは、大きな周波数、たとえば多数の同一の正方形です。 結合式は急速に大きくなりますが、大きな整数であるため Python では安全なままであり、明示的にトリプルを列挙することが回避されるため、計算は引き続き線形時間で実行されます。
