 ## 問題の理解

 文字列が与えられたので、それを連続した部分に分割したいと思います。 すべての部分は非常に厳格な内部構造を満たさなければなりません。単一の整数が存在します。$x$(テスト ケース内のすべてのピースで同じ) 各ピース内で、出現するすべての文字が正確に実行されるようにする$x$回。 その作品に存在しないキャラクターは無関係ですが、どのキャラクターもそれよりも少なくても多くも登場することはできません。$x$一度出現すると。 

タスクは、そのような有効な値を選択することです。$x$次に、文字列を可能な限り最小数の有効な部分に分割します。 

制約により、最大で$10^5$すべてのテスト ケースにわたる合計文字数なので、テスト ケースごとに線形以上のソリューションはタイムアウトになる危険性があります。 たとえ$O(n \log n)$テスト ケースごとのソリューションは慎重に制御する必要がありますが、小さな定数係数を使用したリニア スキャンは安全です。 

多くの場合エラーを引き起こす単純な誤解は、セグメントがローカルで条件を満たしたら、グローバルな実現可能性を考慮せずに貪欲に拡張できると想定していることです。$x$。 もう 1 つの微妙な問題は、$x$単一のセグメントからグローバルに機能します。 たとえば、文字列が次の場合、`"aabbcc"`、試してみてもいいかもしれません$x=2$それは常に機能すると思いますが、セグメンテーションの動作は文字の分布方法に応じて大幅に変化します。 

いくつかのエッジな状況を強調する価値があります。 

文字列が`"aaaa"`、その場合、意味のある選択肢は次のとおりです。$x$は 4 の約数、つまり 1、2、または 4 です。$x=4$単一セグメントを強制する一方で、$x=1$4 つの単一文字セグメントに分割できます。 最適な答えは、セグメントを最大化することではなく、セグメントを最小化することに依存します。$x$。 

文字列が`"abac"`、選択する$x=1$動作しますが、試しています$x=2$すべての文字がグローバルに 2 で割り切れる頻度を持っているわけではないため、このメソッドはすぐに失敗します。 これは実現可能性を示しています$x$ローカルな構造ではなく、グローバルなカウントに依存します。 

修正せずに貪欲な分割を試行すると、別の失敗ケースが発生します。$x$: ローカル セグメントの有効性は、グローバルな一貫性を意味しません。$x$, そのため、後でセグメントを完了できなくなる可能性があります。 

## アプローチ

 ブルートフォース戦略は、文字列を分割するあらゆる可能な方法を試し、分割ごとに、$x$すべてのセグメントが$x$-良い。 固定パーティションの場合、有効性をチェックするには、各セグメント内の文字の頻度を数え、それらがセグメント内で均一で同一であることを確認する必要があります。 これにはすでに費用がかかります$O(n \cdot 26)$パーティションごとに、パーティションの数は指数関数的になります。$n$, そのため、小さな文字列であってもこれは完全に不可能になります。 

重要な観察は、次の値が$x$セグメントごとに任意ではありません。 選択したら、文字列全体の各文字の合計頻度を除算する必要があります。これは、文字の出現ごとに何らかのセグメントが考慮され、各セグメントが正確に寄与するためです。$x$キャラクターがそこに登場するたびに発生します。 これにより、文字列全体のすべての文字頻度が の倍数でなければならないというグローバル制約が強制されます。$x$。 それで$x$すべての文字頻度の最大公約数の約数である必要があります。 

一度$x$が修正されると、問題は決定論的になります。左から右にスキャンして、貪欲にセグメントを構築します。 現在のセグメントの周波数カウントを維持し、ゼロ以外のすべての周波数が正確になるまで拡張し続けます。$x$。 この時点では、セグメントを安全にカットできます。これ以上延長すると、すぐに条件に違反するか、有効なカットが遅れるためです。 

これにより、問題はすべての有効な候補を試行することになります。$x$グローバル gcd から導出され、各候補に対して線形貪欲セグメンテーションが実行されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティション | 指数関数 | O(n) | 遅すぎる |

 ここ$d$は gcd の約数の数ですが、文字数が 26 しかないため、実際には小さくなります。 

## アルゴリズムのチュートリアル

 1. 完全な文字列内の 26 個すべての小文字の頻度を数え、その最大公約数を計算します。 この gcd は、すべての文字に共有される最大の構造制約を表します。 
2. この gcd のすべての約数を列挙します。 各約数は次の候補値です。$x$。 有効なセグメンテーションではすべての文字数が次の値で割り切れる必要があるため、この手順で十分です。$x$。 
3. 各候補者について$x$、貪欲スキャンを使用して、左から右へのセグメントの構築をシミュレートします。 
4. 現在のセグメントの頻度配列を維持し、現在ゼロ以外のカウントを持つ文字の数を追跡します。 
5. セグメントを 1 文字ずつ拡張します。 文字数を超えた場合$x$、この選択$x$は無効なので、この候補については早期に終了します。 
6. 現在のセグメント内のゼロ以外の文字数がすべて正確になるたびに$x$、セグメントを閉じ、周波数配列をリセットし、残りの文字列のスキャンを続けます。 
7. このために形成されたセグメントの数を記録します。$x$。 すべての候補を試した後、有効なすべての中で最小のものを選択します$x$。 

正しさは、かつて$x$が固定されている場合、セグメントはすべてのアクティブ カウントが到達する最も早い位置で正確に終了する必要があります。$x$。 有効性を超えて拡張すると、同じ文字の分布が後のセグメントで複製され、将来のカットが決して減らないため、カットを遅らせてもセグメントの数は改善されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

def divisors(x):
    ds = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            ds.append(i)
            if i * i != x:
                ds.append(x // i)
        i += 1
    return ds

def solve(s):
    cnt = [0] * 26
    for ch in s:
        cnt[ord(ch) - 97] += 1

    g = 0
    for v in cnt:
        g = gcd(g, v)

    if g == 0:
        return len(s)

    best = len(s)

    for x in divisors(g):
        freq = [0] * 26
        seg = 0
        ok = True

        for ch in s:
            c = ord(ch) - 97
            freq[c] += 1
            if freq[c] > x:
                ok = False
                break

            full = True
            for i in range(26):
                if freq[i] != 0 and freq[i] != x:
                    full = False
                    break

            if full:
                seg += 1
                freq = [0] * 26

        if ok and all(v == 0 for v in freq):
            best = min(best, seg)

    return best

def main():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        print(solve(s))

if __name__ == "__main__":
    main()
```この解決策は、文字列全体を 26 の頻度カウントに圧縮して、実行可能な値を決定することから始まります。$x$。 gcd ステップは、不可能な候補をすべて早期に排除するため、非常に重要です。 

候補者ごとに$x$、スキャンはローリング頻度テーブルを維持します。 小切手`freq[c] > x`有効なセグメントは許可された数を超えることができないため、現在の構造は直ちに無効になります。 内側のループは、ゼロ以外の値がすべて等しいかどうかをチェックします。$x$有効なカットポイントを検出するものです。 

各カットの後に周波数配列をリセットすると、セグメントの独立性が維持され、グローバル制約が尊重されます。

 ## 特殊なケース

 のような文字列の場合`"aaaa"`、アルゴリズムは gcd = 4 を計算するため、可能性があります。$x$は 1、2、4 です。$x=4$、スキャンは単一のセグメントを構築し、最後に閉じて、答え 1 を生成します。終了前に完全な有効性に達するプレフィックスがないため、頻度チェックにより、早期に終了することがないことが保証されます。 

のために`"ababab"`、gcd は 3 であり、$x=3$、セグメントは最後の文字でのみ閉じます。 実行中、部分周波数は早期に「すべてが x またはゼロに等しい」条件を満たすことはなく、早期のセグメンテーションを防ぎます。 

次のような混合文字列の場合`"abac"`、gcd が 1 になり、強制的に$x=1$。 セグメント内で文字が繰り返されると規則に違反するため、各文字は独自のセグメントを形成する必要があります。$x=1$すぐに制約します。 セグメント内に重複が存在しない場合にのみ、各位置が最終的に有効なクロージャをトリガーするため、アルゴリズムは 4 つのセグメントを正しく生成します。
