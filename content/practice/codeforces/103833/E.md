 ## 解決策
 ## 問題の理解

 ペナルティ ショットをゴール上の離散化されたグリッドとしてモデル化しています。 グリッド内の各セルは、可能なショットの配置に対応します。 ゴールキーパーの場合、各セルには、ゴールキーパーがそこに向けたシュートをセーブする可能性を表す値が含まれています。 各プレーヤーの各セルには、そのプレーヤーがその場所にシュートを打った場合に得点する可能性が含まれています。 

選手を評価するには、選手のシュート確率とゴールキーパーのセービング確率をセルごとに組み合わせます。 セルの合計値は、同じ場所でのプレーヤーの成功確率とゴールキーパーのセーブ失敗確率の積です。 この合計確率が少なくとも 0.65 であれば、セルはプレーヤーにとって「良好」であるとみなされます。 プレイヤーのスコアは、グリッド内のそのような良好なセルの数です。 

私たちは最も大きなスコアを獲得した 5 人のプレーヤーを選ばなければなりません。 複数のプレイヤーが同じスコアを持っている場合、フルネームの辞書順に従って同点を解消します。 

入力サイズが小さい場合:$N, M \le 100$、プレイヤーの数は最大でも 100 人です。これは、たとえ$O(KNM)$せいぜい約$10^6$操作。 

主な微妙な点は浮動小数点比較です。 値は小数点以下 2 桁で指定されるため、精度のドリフトを避けるために、しきい値 0.65 での比較は慎重に行う必要があります。 安全なアプローチは、100 または 10000 を乗算してすべてを整数にスケールするか、小さなイプシロンと比較することです。 

重要なエッジ ケースは、主に同点処理と正確に 0.65 での浮動小数点の等価性です。 単純な厳密な比較では、境界値を誤って分類する可能性があります。 もう 1 つの落とし穴は、フルネームの辞書編集的な比較です。スペースは順序付けの一部であるため、標準の文字列比較を直接使用する必要があります。 

## アプローチ

 ブルートフォースアプローチは本質的に最終的な解決策です。 プレイヤーごとに、すべてを繰り返します$N \times M$セルを作成し、ゴールキーパー グリッドとの積を計算し、しきい値を超えている数を数えて、プレーヤーを並べ替えます。 

これが機能するのは、セルまたはプレーヤー間に相互依存がないためです。 各プレイヤーのスコアは独立しているため、問題は順位付けに続く独立した評価にきれいに分解されます。 

より遅いメンタル モデルでは、プレーヤーをペアごとに再計算または比較することを考えることになりますが、それは不要です。 各スコアが計算されたら、上位 5 つを選択するのが標準的な並べ替え問題です。 

唯一の「最適化」は、再計算構造がすでに最適であることを認識することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 並べ替えを使用したプレーヤーごとのブルート フォース | O(KNM + K log K) | O(K) | 承認済み |
 | 複雑すぎる代替案 | O(K^2 NM) | O(K) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 ### 1. ゴールキーパーのグリッドを読む

 私たちが最初に読んだのは、$N \times M$ゴールキーパーを表すマトリックス。 このグリッドはすべてのプレイヤーに対して再利用されるため、一度保存します。 

### 2. すべてのプレーヤーを名前とグリッドで解析します

 各プレイヤーについて、名前とそのプレイヤーの名前を保存します。$N \times M$確率行列。 制約が小さいため、すべてのデータを保存しても安全であり、計算が簡素化されます。 

### 3. プレーヤーのスコアを個別に計算する

 各プレーヤーについて、すべてのグリッド セルを反復処理します。 各セルで、ゴールキーパーの価値とプレーヤーの価値の積を計算します。 この積が 0.65 以上の場合、スコアが増加します。 

このステップはプレイヤーごとに独立しているため、問題が線形になります。$KNM$。 

### 4. 結果を (スコア, 名前) として保存します

 計算されたスコアとプレーヤーの名前を含むペアのリストを保持します。 この構造は並べ替えに使用されます。 

### 5. プレーヤーをスコア順および辞書順に並べ替えます

 スコアの降順に並べ替えます。 スコアが等しい場合は、名前の辞書編集順に依存します。 これにより、決定的なタイブレークが保証されます。 

### 6. 上位 5 つの名前を出力します

 ソート後に最初の 5 つのエントリを出力します。 

### なぜ効果があるのか

 重要な不変条件は、各プレーヤーのスコアが自分のグリッドと固定されたゴールキーパーのグリッドのみに依存するということです。 プレイヤー間の対話はないため、ランキングは独立したスカラー スコアを並べ替えることと同じです。 乗算としきい値処理により、各グリッド セルがブール値に換算され、スコアがセルに対する単純な加算関数になります。 加算はプレイヤー間で結合的かつ独立しているため、ランキングの問題は純粋に比較ベースの並べ替えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def parse_matrix(n, m):
    mat = []
    for _ in range(n):
        row = list(map(float, input().split()))
        mat.append(row)
    return mat

def main():
    n, m = map(int, input().split())
    k = int(input())

    keeper = parse_matrix(n, m)

    players = []

    for _ in range(k):
        name = input().strip()
        mat = parse_matrix(n, m)

        score = 0
        for i in range(n):
            for j in range(m):
                if keeper[i][j] * mat[i][j] >= 0.65 - 1e-12:
                    score += 1

        players.append(( -score, name))

    players.sort()
    for i in range(5):
        print(players[i][1])

if __name__ == "__main__":
    main()
```コードはゴールキーパー マトリックスを 1 回読み取り、各プレーヤーを個別に処理します。 スコアは否定されているため、昇順で並べ替えると自然に最も高いスコアが最初に得られます。 比較のイプシロンは、浮動小数点乗算で 0.6499999998 のような値が生成される場合の精度の問題を防ぎます。 

Python のタプル比較では最初のフィールドが等しい場合に 2 番目のフィールドが使用されるため、並べ替えステップでは辞書編集上のタイブレークも自動的に解決されます。 

## 実用的な例

 ### 例 1

 仮定してください$N = 2, M = 2$。 キーパーグリッド:

 | 0.5 | 0.8 |
 | --- | --- |
 | 0.6 | 0.9 |

 プレーヤー A のグリッド:

 | 0.9 | 0.9 |
 | --- | --- |
 | 0.9 | 0.9 |

 私たちは積を計算します:

 | 0.45 | 0.72 |
 | --- | --- |
 | 0.54 | 0.81 |

 0.65 以上のセルは 2 つのセル (0.72 と 0.81) であるため、スコア = 2。 

これは、独立したセル評価がどのように機能するかを示しています。 

### 例 2

 キーパーグリッド:

 | 1.0 | 0.5 |
 | --- | --- |
 | 0.5 | 1.0 |

 プレイヤー B:

 | 0.7 | 0.7 |
 | --- | --- |
 | 0.7 | 0.7 |

 製品:

 | 0.7 | 0.35 |
 | --- | --- |
 | 0.35 | 0.7 |

 再び適格となるのは 2 つのセルだけです。 これは対称性を裏付けています。異なる分布でも同じスコアが生成される可能性があり、辞書編集上の順序が重要なのはこのためです。

 ## 特殊なケース

 エッジケースの 1 つは、複数のプレーヤーが同じスコアを持っている場合です。 並べ替えでは二次キーとして辞書編集的な比較が使用されるため、アルゴリズムはこれを自然に処理します。 たとえば、2 人のプレーヤーが両方ともスコア 10 を持っている場合、その順序は純粋に名前の文字列比較によって決定されます。 

もう 1 つのエッジ ケースは、正確に 0.65 の浮動小数点境界です。 イプシロン ガードは、精度エラーによりしきい値に非常に近い値が誤って分類されないことを保証します。 たとえば、0.64999999997 のような計算値は、許容値がなければ誤って条件を満たしません。 

最後のエッジケースは、すべてのプレイヤーが同じマトリックスを持っている場合です。 この場合、すべてのスコアは等しく、出力は単に辞書編集上で最も小さい 5 つの名前であり、ソート ルールによって自動的に生成されます。
