 ## 解決策
 ## 問題の理解

 パイルサイズの固定セットが与えられています$A_1, A_2, \dots, A_N$。 このセットから、以下から構成される開始位置を構築します。$K$パイル。各パイルは配列から 1 つの値を独立して選択します。 したがって、構成は単なる長さです。$K$シーケンスであり、すべてのエントリは次のいずれかです。$A_i$。 構成の合計数は次のとおりです。$N^K$。 

2 人のプレイヤーがこれらのゲームをプレイします$K$山。 移動は、1 ～ 6 つの異なる山を選択し、選択した各山を少なくとも 1 つの石だけ減らすことで構成され、山ごとに異なる削減量を自由に選択できます。 行動できなかったプレイヤーが負けとなります。 

タスクはゲームをシミュレートすることではなく、ゲームが何回行われるかを数えることです。$N^K$初期設定は、モジュロを使った最適なプレーの下でポジションを失っています。$998244353$。 

制約は即座に重要になります。$K$と同じ大きさにすることができます$10^{18}$したがって、パイルを 1 つずつ処理するアプローチや、長い期間にわたって DP を実行するアプローチはすべて可能です。$K$明らかに不可能です。 構造は累乗できるものに崩壊する必要があります。 

微妙な点は、杭の選択方法は独立していますが、この動きは一度に最大 6 つの杭を結合することです。 これにより、通常の「独立した Nim ヒープの合計」構造が破壊され、パイル間のパリティのような相互作用が重要となるマルチヒープ テイク ゲームに追い込まれます。 

独立した Nim ヒープとして単純に推論すると、エッジ ケースが発生します。 たとえば、各パイルが標準 Nim 値に寄与し、その答えがパイルごとの損失確率の積であると誤って仮定した場合、たとえ小さなケースであっても失敗します。 考慮する$K=2$、$A=\{1,2\}$。 それぞれの山だけでは単純に見えるかもしれませんが、移動によって両方の山が同時に削減される可能性があり、これは独立性が損なわれ、製品の推論が不正確になることを意味します。 

もう 1 つの特殊なケースは、すべてが$A_i$は同一です。 それでも、杭間の相互作用は依然として存在するため、それを単一の山として扱うと、$K$回は無効です。 

## アプローチ

 「最大 6 つのパイル」という制限を無視すると、各パイルは独立した Nim ヒープとなり、その答えは、xor が 0 である構成をカウントすることになります。 しかし、ここでは、移動が最大 6 つのヒープに同時に影響し、Sprague-Grundy 構造が完全に変化します。 

ブルートフォースの観点では、次の各構成を扱います。$K$をゲーム状態としてパイルし、再帰的または DP ベースの Grundy 評価によって勝ちか負けかを計算しようとします。 それはすぐに爆発します。状態空間は$N^K$、すべての位置を保存したり反復したりすることさえ不可能です。 トランジションの計算に限定したとしても、それぞれの位置は膨大な数の他の位置に移動する可能性があります。 

重要な構造的洞察は、これがムーアの Nim と呼ばれる Nim の既知の一般化であるということです。つまり、プレイヤーが操作できるのは、最大でも次の動きです。$m$杭、ここに$m=6$。 ムーアの Nim の場合、負け条件は標準の xor ではなく、ビットごとのカウントによって表現されます。 

各パイルサイズをバイナリで表現します。 ビット位置ごとに、そのビットが設定されているパイルの数を確認します。 すべてのビット位置について、このカウントが次の値で割り切れるとき、位置は正確に負けています。$m+1$、つまり$7$ここ。 

これにより、ゲームは純粋な組み合わせ論の問題に変換されます。$K$要素 (からの繰り返しあり)$N$タイプ）、各要素はビットマスク（そのバイナリ表現）に寄与し、各ビットについて、シーケンス全体の 1 の合計数が一致する必要があります。$0 \bmod 7$。 

つまり、ゲーム理論の部分は消え、残るのは長さのカウントだけです。$K$蓄積されたビット寄与が有限アーベル群内にあるシーケンス$(\mathbb{Z}_7)^B$、 どこ$B$必要なビット数です (最大 7$A_i \le 100$）。 

グループ国家に対する強引な攻撃は、DP に対する攻撃となるでしょう。$7^B$状態。次のいずれかを追加することで遷移が与えられます。$N$ビットマスク。 それはすでに指数関数的です$B$、 しかし$B=7$作る$7^7 \approx 8 \times 10^5$、境界線にありますが、それでも乗算するには大きすぎます。$K$直接ステップに進みます。 重要な観察は、シミュレーションする必要がないということです。$K$直線的にステップします。 この有限状態空間上で高速累乗を使用して遷移演算子を累乗することができます。 

したがって、問題は線形変換を適用することになります。$K$サイズの状態空間の倍$7^B$、二乗を繰り返すことで対応できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ムーア状態空間上の DP + べき乗 |$O(7^{2B} \log K)$(概念的に) |$O(7^B)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1.それぞれを変換する$A_i$バイナリ表現に変換$B \le 7$ビット、ビットマスクを形成します。 各マスクは、この山がどのビット位置に「1」を与えるかを示します。 
2. DP 状態を、長さのタプルによってインデックス付けされたベクトルとして定義します。$B$ここで、各座標は、そのビット位置の 1 の 7 を法とする現在のカウントを格納します。 このタプルは、現在の部分シーケンスの累積されたパリティのような構造を表します。 
3. 山を選択する前はすべてのカウントがゼロであるため、すべてのカウンターがゼロである単一の空の状態で DP を初期化します。 
4. 1 つの杭タイプの選択に対応する遷移を構築します。$A_i$。 この遷移を適用すると、ビットマスクの座標方向のモジュロ 7 を追加することによって、現在の状態がシフトされます。これは、ある DP 状態から別の DP 状態への決定論的なマッピングです。 
5.すべてを組み合わせる$N$それらの効果を合計することで、タイプを 1 つの集約された遷移演算子に積み上げます。 これにより、状態空間上に疎な線形演算子が形成されます。 
6. このオペレーターを権力の座に上げます$K$二乗によるべき乗を使用します。 各乗算は 2 つの遷移を構成し、毎回選択されたパイルの数が効果的に 2 倍になります。 
7. 演算子の適用後$K$これを 7 で割り切れるすべてのビット数に対応するゼロ状態の値を抽出します。この値は、失われた構成の数です。 

### なぜ効果があるのか

 ムーアの Nim は、勝利条件を各ビット位置の独立したモジュラー制約に減らします。 パイル間の唯一の相互作用は、有限のアーベル群を形成するこれらのモジュラー和によるものです。 ゲーム内のすべての動きは、このグループ定式化の下でスプラーグ・グランディ分析に必要な構造を保持しており、負けた位置はこのグループの恒等要素に正確に対応します。 各パイルは固定グループ要素に寄与し、構成はシーケンスであるため、問題は長さのウォークをカウントすることになります。$K$ケイリーグラフで$(\mathbb{Z}_7)^B$、遷移演算子の累乗により、正確な到達可能性カウントが保存されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

# we use B = 7 bits since Ai <= 100
B = 7
BASE = 7

def add_state(a, mask, delta=1):
    # a is tuple of length B, values 0..6
    res = list(a)
    for i in range(B):
        if (mask >> i) & 1:
            res[i] = (res[i] + delta) % BASE
    return tuple(res)

def build_transitions(A):
    # map state -> next state counts (since each pick is deterministic shift)
    states = {}
    states[(0,) * B] = 1

    # we build one-step transition as a dict over state space
    trans = {}

    for mask in A:
        new_trans = {}
        for st, cnt in states.items():
            nxt = add_state(st, mask)
            new_trans[nxt] = (new_trans.get(nxt, 0) + cnt) % MOD
        states = new_trans

    return states

def multiply(f, g):
    # convolution over state space
    res = {}
    for s1, c1 in f.items():
        for s2, c2 in g.items():
            nxt = tuple((s1[i] + s2[i]) % BASE for i in range(B))
            res[nxt] = (res.get(nxt, 0) + c1 * c2) % MOD
    return res

def power(trans, K):
    # exponentiation over state-space transition
    res = {(0,) * B: 1}
    base = trans
    while K:
        if K & 1:
            res = multiply(res, base)
        base = multiply(base, base)
        K >>= 1
    return res

def solve():
    N, K = map(int, input().split())
    A = list(map(int, input().split()))

    trans = {}
    for x in A:
        mask = x
        # single-step transition contribution
        t = {(0,) * B: 1}
        t[(0,) * B] = 0
        t = {}
        t_state = (0,) * B
        t[t_state] = 1
        nxt = add_state(t_state, mask)
        trans[nxt] = (trans.get(nxt, 0) + 1) % MOD

    # identity over empty sequence
    dp = {(0,) * B: 1}

    # exponentiation
    def mul(f, g):
        res = {}
        for s1, c1 in f.items():
            for s2, c2 in g.items():
                s = tuple((s1[i] + s2[i]) % BASE for i in range(B))
                res[s] = (res.get(s, 0) + c1 * c2) % MOD
        return res

    def fpow(trans, k):
        res = {(0,) * B: 1}
        base = trans
        while k:
            if k & 1:
                res = mul(res, base)
            base = mul(base, base)
            k >>= 1
        return res

    dp = fpow(trans, K)

    print(dp.get((0,) * B, 0))

if __name__ == "__main__":
    solve()
```このコードは、1 つのパイル タイプを選択することによって誘発される遷移を構築し、それがモジュールのビット数状態をどのように変更するかを表します。 次に、この遷移を累乗します$K$一定の長さのシーケンスの形成をシミュレートする回数$K$。 すべてゼロの状態での最終ルックアップでは、すべてのビット位置のカウントが 7 で割り切れる構成が正確に抽出されます。 

よくある実装の落とし穴は、遷移がパイル値を直接超えるものではなく、グループ状態を超えるものであることを忘れることです。 もう 1 つは、ビット抽出と値の演算を混同しており、モジュール構造が壊れています。 解決策全体は、各パイルを固定ビットマスク ジェネレーターとして扱うことにかかっています。

| ステップ | 状態 (ビット数 mod 7) | アクション |
 | --- | --- | --- |
 | 0 | (0,0,0,0,0,0,0) | 開始 |
 | 1 | (1,0,0,0,0,0,0) | 1 つ選んでください |

 | 3 | (3,0,0,0,0,0,0) | 1 つ選んでください |

 最終状態はゼロではないため、次の場合を除いて、長さ 3 の構成が失われることはありません。$K$これは、モジュラー条件が妥当性をどのように制御するかを示しています。 

### 例 2

 入力:```
2 2
1 2
```マスクはこちら`0000001`そして`0000010`。 

| ステップ | 状態 | 選ばれた |
 | --- | --- | --- |
 | 0 | (0,0,0,0,0,0,0) | 開始 |
 | 1 | 最初の選択に依存します | 1 または 2 を選択してください |
 | 2 | 累積mod 7 | 2番目の選択 |

 唯一負ける構成は、両方のビット数が同時に 7 で割り切れる構成です。これは長さ 2 では不可能であるため、答えは 0 になります。 

これらのトレースは、状態がパイルごとにローカルではなく、ビットおよびシーケンス全体にわたってグローバルであることを強調しています。

 ## Edge Cases

 すべてのパイル サイズが同一の場合、すべてのシーケンスが各ビットに均一の寄与を生成するため、負け状態に到達する唯一の方法は次のとおりです。$K$は、すべてのビット次元で 7 で割り切れます。 累乗ではビットごとに独立して 7 を法として寄与が累積されるため、アルゴリズムはこれを正しく処理します。 

いつ$K=0$、パイルが存在せず、すべてのモジュール数がゼロであるため、アイデンティティ状態はすでに損失構成です。 DP 初期化により、この場合は遷移を実行せずに 1 が返されることが保証されます。 

いつ$N=1$、遷移は単一のビットマスク シフトの繰り返し適用に崩壊し、累乗は単純な循環グループ ウォークに減少します。 実装では引き続き、正確さを維持しながら、単一要素の遷移セットとして均一に扱います。
