 ## 解決策
 ## 問題の理解

 各ノードに直接または構造を通じて暗示される親関係があるルート付きツリーが与えられ、次の形式のクエリに答えるように求められます。与えられた 2 つのノードから、ツリー内の最も低い共通祖先を決定します。 最下位の共通祖先は、ルートからクエリされた両方のノードへのパス上にある最も深いノードです。 

入力はツリー構造を記述し、その後、一連のクエリを記述します。 各クエリは 2 つのノードで構成され、出力は両方のノードからルートに向かって上向きに移動するときに、最初の共有祖先である一意のノードである必要があります。 

主な問題は、ノードとクエリの数が非常に大きくなり、各クエリのパスを個別に再計算すると時間がかかりすぎることです。 両方のノードからミーティング ポイントまで上向きに進む単純なソリューションでは、最悪の場合、クエリあたりの時間は線形に低下し、多くのクエリが存在する場合、全体として二次関数になります。 

一方のノードが他方のノードの祖先である場合、微妙なエッジ ケースが発生します。 たとえば、ツリーが 1 → 2 → 3 → 4 のチェーンであり、(2, 4) をクエリすると、答えは 2 になります。両方のポインタを同時に上向きに移動させる素朴なアプローチは、比較前に深さを適切に調整しないと失敗する可能性があります。これは、一方のポインタが先にルートに到達し、深さが正しく処理されない限り比較が無意味になるためです。 

深さの差が最大になる、歪んだツリーでは、別のエッジ ケースが発生します。 1 つのノードが根の近くにあり、もう 1 つのノードが深い葉である場合、両側からの単純な上向きステップは非常に非効率になります。 

## アプローチ

 ブルート フォース手法では、各クエリが個別に処理されます。 クエリ (u, v) の場合、すべてのノードの親ポインターを保存し、両方のノードから上方向に繰り返し移動し、セット内の 1 つのノードの祖先を収集し、次に訪問した祖先に到達するまで他のノードから上方向に移動します。 これは正しいです。共通の祖先は両方の上向きのチェーンに出現する必要があり、より深いノードで見つかった最初の一致が最下位の共通の祖先に対応するためです。 

問題はパフォーマンスです。 祖先セットを構築して上に向かって進むと、チェーン形状のツリーの最悪の場合、クエリごとに O(n) がかかる可能性があります。 最大 q クエリの場合、これは O(nq) となり、n と q の両方が大きい場合には大きすぎます。 

重要な観察は、上向きトラバースの繰り返しは冗長な作業であるということです。 各クエリは 2 つのルート パスの交差部分を要求し、これらのパスはクエリ間で重なり合います。 単一のエッジではなく、より大きなステップで上に「ジャンプ」できるようにツリーを前処理できれば、各クエリを線形時間から対数時間に短縮できます。 

これはまさにバイナリリフティングが提供するものです。 各ノードの直接の親だけを保存する代わりに、2 の累乗の距離にある祖先を事前計算します。 次に、距離をバイナリコンポーネントに分解して、大きなジャンプによって任意のノードを上に移動できます。 両方のノードが同じ深さになったら、LCA をオーバーシュートしないようにしながらそれらを同時に持ち上げ、最終的に LCA の下の直接の子に着地し、もう一度ステップします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとに O(n) | O(n) | 遅すぎる |
 | バイナリリフティング | クエリあたり O(log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 (または指定されている場合は指定されたルート) にルートし、深さテーブルと祖先テーブルを前処理します。

1. ルートから DFS または BFS を実行して、すべてのノードとその直接の親の深さを計算します。 これにより、1 ステップに対して一定時間で上向きに移動できるベースライン構造が確立されます。 
2. テーブル up[k][v] を構築します。ここで、up[k][v] にはノード v の 2^k 番目の祖先が格納されます。これが機能する理由は、サイズ 2^k のジャンプはサイズ 2^(k-1) の 2 つのジャンプに分解でき、祖先関係に対する動的プログラミングが可能になるためです。 
3. 各ノード v に対して、up[0][v] をその親として定義します。 次に、より高いべき乗の場合、有効な場合は up[k][v] = up[k-1][up[k-1][v]] を計算します。 これにより、ジャンプが再帰的に構成され、後で対数ステップで移動できるようになります。 
4. クエリ (u, v) に答えるには、まず u がより深いノードであることを確認します。 そうでない場合は交換します。 これにより、u を上に持ち上げるときに、最初に 1 つの方向のみを調整することが保証され、位置合わせロジックが簡素化されます。 
5. 両方のノードが同じ深さになるように、より深いノードを持ち上げます。 これは、深さの差の各ビットをチェックし、事前に計算されたジャンプを適用することによって行われます。 LCA は絶対的なノード ID ではなく、ルートからの相対的な位置のみに依存するため、この手順が必要です。 
6. レベリング後、両方のノードが同じである場合は、一方が他方の祖先であるため、そのノードをすぐに返します。 
7. それ以外の場合は、両方のノードを 2 の最大乗から下に持ち上げます。 2^k 番目の祖先が異なる場合は常に、両方のノードを同時に上に移動します。 これにより、祖先が明確なままである場合にのみジャンプするため、LCA をスキップすることがなくなります。 
8. このプロセスの後、両方のノードは最下位の共通祖先のすぐ下に位置します。 それらの親である up[0][u] を返します。 

### なぜ効果があるのか

 このアルゴリズムは、各リフティング フェーズの後、u と v が常に同じ深さにあり、それらの最も低い共通の祖先が変化しないという不変条件を維持します。 最も高いパワーから下にリフトする場合、祖先パスが途中でマージされない場合にのみノードを移動します。 これにより、LCA を決して越えることがなく、安全なジャンプが存在しなくなると、両方のノードが LCA の直接の子になる必要があります。 次に、親ポインターは答えを一意に解決します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

LOG = 20

n = int(input())
up = [[0] * (n + 1) for _ in range(LOG)]
depth = [0] * (n + 1)

g = [[] for _ in range(n + 1)]

for v in range(2, n + 1):
    p = int(input())
    g[p].append(v)
    up[0][v] = p

def dfs(v):
    for to in g[v]:
        depth[to] = depth[v] + 1
        dfs(to)

dfs(1)

for k in range(1, LOG):
    for v in range(1, n + 1):
        up[k][v] = up[k - 1][up[k - 1][v]]

def lift(v, dist):
    for k in range(LOG):
        if dist & (1 << k):
            v = up[k][v]
    return v

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a

    a = lift(a, depth[a] - depth[b])

    if a == b:
        return a

    for k in reversed(range(LOG)):
        if up[k][a] != up[k][b]:
            a = up[k][a]
            b = up[k][b]

    return up[0][a]

q = int(input())
for _ in range(q):
    a, b = map(int, input().split())
    print(lca(a, b))
```このソリューションでは、まず、隣接リストと親ポインターを使用してツリーのルート表現を構築します。 DFS は深さを計算するため、深さの調整は反復的な走査ではなく直接の算術演算になります。 

バイナリ昇降テーブルはボトムアップで構築されています。 各エントリはより小さなジャンプに依存し、指数関数的な祖先の正確さを保証します。 リフト関数は距離をバイナリ形式に変換し、それに応じてジャンプを適用します。 

LCA 関数は最初に深さを等化します。これは、両方のノードが同じレベルにある場合にのみ祖先比較が意味を持つため、必要です。 次に、収束の直前まで分離を維持しながら両方のノードを一緒に登ります。 ループは実際の LCA の 1 レベル下で停止するため、最後の親が返されます。 

## 実用的な例

 1 がルートで、1 に子 2 と 3 があり、2 に子 4 と 5 があるツリーを考えてみましょう。 

クエリ: (4, 5)

 | ステップ | | b | 深さ[a] | 深さ[b] | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 4 | 5 | 2 | 2 | すでに等しい深さ |
 | 2 | 4 | 5 | 2 | 2 | チェックリフティング、祖先が異なります。 
| 3 | 2 | 2 | 1 | 1 | 両方とも上に移動しました |
 | 4 | 2 | 2 | 1 | 1 | 終了 |

 出力は 2 です。これは、両方のノードが同じ親を共有する場合の正しさを確認します。 

次に (4, 3) を考えてみましょう。 

| ステップ | | b | 深さ[a] | 深さ[b] | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 4 | 3 | 2 | 1 | スワップをより深く |
 | 2 | 4 | 3 | 2 | 1 | 4 を深さ 1 まで持ち上げます |
 | 3 | 2 | 3 | 1 | 1 | 深さを均等にする |
 | 4 | 2 | 3 | 1 | 1 | 祖先が異なる間リフト |
 | 5 | 1 | 1 | 0 | 0 | 停止し、2 の親を返します |

 出力は 1 で、LCA がルートである場合の正しい動作を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + q log n) | 前処理はバイナリリフティングテーブルを構築します。 各クエリは対数ジャンプを実行します。 
| スペース | O(n log n) | 各ノードの 2^k 祖先を保存する |

 前処理コストは n 単位で線形演算され、各クエリは log n で区切られた固定数の上向きジャンプのみを必要とします。 これは、最大 2×10^5 のノードおよびクエリまでの一般的な制約に快適に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    sys.setrecursionlimit(10**7)

    LOG = 20

    n = int(input())
    up = [[0] * (n + 1) for _ in range(LOG)]
    depth = [0] * (n + 1)
    g = [[] for _ in range(n + 1)]

    for v in range(2, n + 1):
        p = int(input())
        g[p].append(v)
        up[0][v] = p

    def dfs(v):
        for to in g[v]:
            depth[to] = depth[v] + 1
            dfs(to)

    dfs(1)

    for k in range(1, LOG):
        for v in range(1, n + 1):
            up[k][v] = up[k - 1][up[k - 1][v]]

    def lift(v, dist):
        for k in range(LOG):
            if dist & (1 << k):
                v = up[k][v]
        return v

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        a = lift(a, depth[a] - depth[b])
        if a == b:
            return a
        for k in reversed(range(LOG)):
            if up[k][a] != up[k][b]:
                a = up[k][a]
                b = up[k][b]
        return up[0][a]

    q = int(input())
    out = []
    for _ in range(q):
        a, b = map(int, input().split())
        out.append(str(lca(a, b)))
    return "\n".join(out)

 ## 特殊なケース

 歪んだチェーンは、深さ調整ロジックをテストします。 1 → 2 → 3 → 4 → 5 のようなツリーの場合、(5, 2) をクエリすると、深いノードの繰り返しリフティングが強制されます。 このアルゴリズムは、まず 5 を 3 ステップで持ち上げて 2 と揃え、次に両方のノードが 2 で出会うとすぐに祖先を認識します。各バイナリ ジャンプは深さの差のビットに正確に対応するため、中間の祖先はスキップされません。 

同じチェーン内の (2, 4) のような祖先と子孫のケースは、深さの調整の直後に解決されます。 4 を 2 段階持ち上げると 2 になり、等価性チェックは第 2 フェーズに入らずに戻ります。 これにより、不必要な上方へのトラバースが防止され、ツリー階層内で 1 つのノードが他のノードを支配する場合に正確さが確認されます。
