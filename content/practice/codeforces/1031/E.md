 ## 解決策
 ## 問題の理解

 バイナリ配列と、正確に 3 つの位置を反転する 1 つの演算が与えられていますが、これら 3 つの位置は等差数列を形成する必要があります。 言い換えれば、開始インデックスとステップ サイズを選択すると、位置の値を同時に切り替えます。$x$、$x + d$、 そして$x + 2d$。 

目的は、このような演算を使用して配列全体をゼロに変換できるかどうかを判断することです。可能であれば、演算の数を少なくしながら、これを実現する一連の演算を明示的に構築する必要があります。 

主な問題点は、各操作が遠く離れた 3 つの位置を結合するため、局所的な変更が重要な方法で伝播する可能性があることです。 私たちは個々のビットを独立して修正しているだけではなく、制御された算術パターンで反転が重なる構造で作業しています。 

制約$n \le 10^5$すべての操作を試行したり、操作のすべてのサブセットを調査したりするアプローチは直ちに除外されます。 平$O(n^2)$ポジションのペアを推論するのが遅すぎます。 線形または線形に近い時間で配列を処理し、最後近くで限られた少量の複雑な推論のみを使用する構造が必要です。 

配列がほぼ解決可能であるが、小さな一貫性のないサフィックスがある場合、微妙なエッジ ケースが発生します。 たとえば、貪欲なプロセスでは、小さなブロックだけが残るまでは正常にセグメントを削除できますが、以前の決定によりその領域のパリティが制限されていたため、最後のセグメントを解決できない可能性があります。 もう 1 つの障害モードは、すべてのプレフィックスが残りのプレフィックスに影響を与えることなく独立して修正できると仮定するものですが、すべての操作が 3 つの位置に影響を与えるため、これは誤りです。 

この問題の重要な考え方は、長距離構造を小さな「境界領域」に還元し、それを個別に総当たりで実行できるということです。 

## アプローチ

 ブルートフォースアプローチでは、各ステップで算術トリプルを選択し、反転を再帰的に適用しながら、ある制限まですべての一連の操作を試行します。 すべての有効な変換が調査されるため、これは原理的には正しいですが、状態の数は次のように指数関数的に増加します。$n$、そしてすべてのトリプルを生成することさえ$O(n^2)$。 これは実現可能な限界をはるかに超えています。 

構造上の観察によると、操作は全体にわたって線形に動作します。$\mathbb{F}_2$、そしてすべてのインデックスは算術トリプルを通じてのみ相互作用します。 これにより、配列を左から右に処理し、初期の位置の影響を段階的に排除することができます。 十分に右に移動すると、一定サイズのサフィックスだけが「不安定」のままになります。これは、制御された方法ですでに固定された構造に影響を与えずに、初期の操作が任意に後方に到達することができないためです。 

したがって、問題を 2 つの部分に分割します。 まず、配列を左から右に貪欲に修正し、次の位置までのすべての位置が確実に固定されるようにします。$n - 12$ゼロになります。 これは、現在のインデックスから始まるローカル算術累進を適用することによって行われます。 このステップは後の位置を乱す可能性がありますが、重要なのは、左側のすでに固定された位置を再び開くことはありません。 

このスイープの後、不確実なのは最後の 12 位だけです。 12 は定数であるため、ビットマスク上の BFS を使用して、このサフィックスの到達可能なすべての状態を事前計算できます。各遷移は、このウィンドウ内に有効な算術数列を完全に適用することに対応します。 到達可能な状態がわかったら、サフィックスをすべて 0 に変換するシーケンスを再構築します。 

このハイブリッド戦略が機能するのは、最初のフェーズで問題を有界状態空間に還元し、2 番目のフェーズでその有界空間を徹底的に解決するためです。

 ## アルゴリズムのチュートリアル

 配列と操作のリストを維持します。 

1. プロセスインデックスを左から$n - 12$。 各インデックスで$i$、私たちは保証します$a[i] = 0$。 1 の場合、以下から始まる慎重に選択された算術トリプルを反転する演算を適用します。$i$、 通常$(i, i+1, i+2)$、これは常に有効です。 これですぐに位置が固定されます$i$それをひっくり返すからです。 
2. このような操作ごとに、次の位置を変更します。$i$、ただし、以下の位置に影響を与えることはありません$i$。 これにより、以前の決定を決して破ることがなくなります。 
3. このスイープが終了したら、最後の 12 の位置に注意を限定します。 このサフィックスを最大サイズのビットマスクとして表現します$2^{12}$。 
4. サフィックス ウィンドウに完全に含まれるすべての可能な操作を事前計算します。 各操作は選択に対応します$x, y, z$12 の位置内で等差数列を形成します。 
5. ビットマスクを介して、初期サフィックス状態からすべてゼロの状態まで BFS を実行します。 各 BFS エッジは、サフィックス内で 1 つの有効なトリプル操作を適用することに対応します。 
6. BFS 中に親ポインタを保存して、サフィックスを修正する一連の操作を再構築します。 
7. グリーディプレフィックスフェーズとサフィックス再構築フェーズの操作を最終的な答えに結合します。 

### なぜ効果があるのか

 貪欲フェーズでは一方向の伝播が強制されます。つまり、位置が固定されると、その後の構築操作でその位置に再び触れることはありません。 これが最初になります$n - 12$永続的に安定したプレフィックスに位置します。 残りの 12 の位置は、許可された操作の下で閉じたシステムを形成します。これは、以前の決定の影響がビットマスク状態によって完全に捕捉されることを意味します。 この有限状態空間上の BFS は、解が存在する場合には、それが見つかることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ops = []
    
    # Phase 1: greedy prefix fixing up to n-12
    limit = max(0, n - 12)
    
    for i in range(limit):
        if a[i] == 1:
            # use (i, i+1, i+2)
            a[i] ^= 1
            a[i+1] ^= 1
            a[i+2] ^= 1
            ops.append((i+1, i+2, i+3))
    
    # Phase 2: BFS on suffix of size up to 12
    m = n - limit
    if m > 12:
        m = 12
    
    start_mask = 0
    for i in range(n - m, n):
        start_mask = (start_mask << 1) | a[i]
    
    # precompute operations inside window
    moves = []
    idx_map = {n - m + i: i for i in range(m)}
    
    for d in range(1, m):
        for i in range(m):
            j = i + d
            k = i + 2 * d
            if k < m:
                moves.append((i, j, k))
    
    # BFS
    MAXS = 1 << m
    dist = [-1] * MAXS
    par = [-1] * MAXS
    par_move = [-1] * MAXS
    
    q = deque([start_mask])
    dist[start_mask] = 0
    
    def apply(mask, move):
        i, j, k = move
        mask ^= (1 << i)
        mask ^= (1 << j)
        mask ^= (1 << k)
        return mask
    
    while q:
        cur = q.popleft()
        if cur == 0:
            break
        for idx, mv in enumerate(moves):
            nxt = apply(cur, mv)
            if dist[nxt] == -1:
                dist[nxt] = dist[cur] + 1
                par[nxt] = cur
                par_move[nxt] = idx
                q.append(nxt)
    
    if dist[0] == -1:
        print("NO")
        return
    
    # reconstruct suffix ops
    suffix_ops = []
    cur = 0
    while cur != start_mask:
        mv = moves[par_move[cur]]
        i, j, k = mv
        # map back to original indices
        suffix_ops.append((n - m + i + 1, n - m + j + 1, n - m + k + 1))
        cur = par[cur]
    
    ops.extend(suffix_ops)
    
    print("YES")
    print(len(ops))
    for x, y, z in ops:
        print(x, y, z)

if __name__ == "__main__":
    solve()
```プレフィックス ループにより、最後の 12 より前のすべての位置が永続的に解決されます。 サフィックス BFS は、最大 4096 のサイズの圧縮状態空間内で完全に機能します。これは、徹底的に調査するのに十分な小ささです。 

再構築フェーズでは、ビット インデックスを元の配列インデックスに注意深くマッピングし、操作の正確さを維持します。 

微妙な点は、貪欲な操作は現在のインデックスから開始する必要があるということです。 そうしないと、以前のポジションが再導入される可能性があります。 決まった選択肢は、$(i, i+1, i+2)$以下のインデックスには決して触れないため、この問題は回避されます。$i$。

 ## 特殊なケース

 最初のエッジ ケースは、配列がすでにすべて 0 である場合です。 貪欲フェーズでは操作は実行されず、サフィックス BFS はゼロ マスクから開始され、すぐに終了し、空の操作リストが生成されます。 

もう 1 つのエッジケースは次のような場合です$n \le 12$。 この場合、貪欲フェーズは完全にスキップされ、アルゴリズムは状態空間全体にわたって純粋な BFS になります。 到達可能なすべての構成が調査されるため、修正することなく正確さが保たれます。 

3 番目のエッジ ケースは、すべての 1 がグリーディ領域とサフィックス領域の境界付近に集中している場合に発生します。 グリーディ フェーズでは一部のサフィックス ビットが意図せず反転される可能性がありますが、これらの影響は初期 BFS 状態に完全に吸収され、検索は依然として正しい開始設定に対して実行されるため、ソリューションが失われないことが保証されます。
