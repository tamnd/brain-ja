 ## 解決策
 ## 問題の理解

 長さの 2 つの配列が与えられます$n-1$。 各ポジション$i$2 つの未知の連続値間の関係を説明します。$t_i$そして$t_{i+1}$、ここでそれぞれ$t_i$範囲内の整数です$[0, 3]$つまり、すべての値を 2 ビットの数値として扱うことができます。 

隣接する各ペアについて、ペアのビット単位の OR とペアのビット単位の AND が求められます。 タスクは配列が存在するかどうかを判断することです$t_1, t_2, \ldots, t_n$これらすべての制約を同時に満たし、それが存在する場合は、有効な制約を構築します。 

主要な構造は、各制約には隣接する 2 つの変数のみが含まれるため、問題はローカル互換性条件の連鎖のように動作します。 それぞれ$t_i$は近隣のものによって厳しく制限されていますが、複数のビット パターンが同じ OR と AND を生成できるため、まだ自由があります。 

制約$a_i, b_i \in [0,3]$位置ごとに 2 ビットだけを使用して作業していることを意味します。 これは、ローカル検索空間を変数あたり 4 つの可能性に制限し、線形時間での遷移の管理を可能にするため重要です。 

以来$n$まで可能です$10^5$、各ポジションのすべての可能性を個別に試したり、完全な割り当てに対してバックトラックを実行したりするソリューションは失敗します。 素朴な指数関数的構築$4^n$州は完全に実行不可能であり、$O(n \cdot 4^2)$構造のないブルートトランジションは問題ありませんが、隠れた再計算を避けるために慎重に編成する必要があります。 

制約がローカルでは有効でもグローバルでは一貫性がない場合、微妙なエッジ ケースが発生します。 たとえば、一対の制約により、同じ中間要素に矛盾する要件が強制される場合があります。 次のステップの実行可能性を維持せずに、ただちに一貫性をチェックするだけの貪欲な割り当ては、たとえ以前の選択が有効に見えたとしても、後で簡単に行き詰まる可能性があります。 

## アプローチ

 直接的な総当たりアプローチは各位置を処理します$t_i$4 つの値から選択し、制約を確認しながらそれらを順番に割り当ててみます。 各ステップで、可能なすべての値を試します。$t_{i+1}$現在の値と OR と AND の両方を満たすもの$t_i$。 これにより、各状態がいくつかの有効な次の状態に遷移できる分岐プロセスが発生します。 

すべての有効な解はこれらのローカル遷移を通るパスに対応する必要があるため、この強引な方法は正しいです。 ただし、各ステップで複数の選択肢が可能なままであるため、最悪の場合、部分的な割り当ての数が指数関数的に増加し、大まかに$4 \cdot 4^{n-1}$最悪の分岐シナリオの可能性。 

重要な点は、各位置は前の位置にのみ依存するため、すべてのパスを探索する必要がないということです。 どの値を知る必要があるかだけが必要です$t_i$位置で実現可能です$i$、そして実現可能性を前方に伝播させます。 これにより、問題は位置ごとにサイズ 4 の状態空間を持つチェーン上の動的プログラミングに縮小されます。 

どの値を維持するか$t_i$が可能であり、可能な値ごとに、シーケンスを再構築するための先行データを保存します。 遷移は隣接する制約にのみ依存するため、各ステップは状態ごとに一定時間で計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(4^n)$|$O(n)$| 遅すぎる |
 | 州全体にわたる最適な DP |$O(4n)$|$O(4n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 それぞれを解釈していきます$t_i$2ビットマスクとして。 隣接するペアに対して$(x, y)$の場合、制約は次のようになります。 

x \,|\, y = a_i,\quad x \,&\, y = b_i

 これら 2 つの方程式は、次のビット間の関係を完全に決定します。$x$そして$y$。 

### ステップ

 1. 各ポジションごと$i$のすべての値を考慮します。$t_i$で$\{0,1,2,3\}$。 これらは考えられるすべての 2 ビット状態を表し、チェーン全体に有効な遷移を伝播します。 
2. ペアごとに$(x, y)$、制約ペアを満たすかどうかを事前計算します。$(a_i, b_i)$。 これは、ビットごとの演算を使用して両方の方程式を直接チェックすることによって行われます。 ドメインのサイズが固定されているため、このステップはペアごとに一定時間です。 
3. 連続する位置で状態間の遷移グラフを作成します。 有効なペアごとに$(x, y)$、それにマークを付けてください$y$フォローできる$x$。 これにより、すべてのローカル整合性ルールがエンコードされます。 
4. 階層化された動的プログラミング プロセスを左から右に実行します。 位置 1 では、最初はすべての値が許可されます。 次のポジションごとに$i$、値のみを保持します$y$少なくとも 1 つの有効なアドレスから到達可能$x$前のレイヤーで。 
5. 到達可能な状態ごとに親ポインタを保存する$y$位置にある$i$、どの状態を記録するか$x$それにつながりました。 これにより、最終シーケンスの再構築が可能になります。 
6. すべての位置を処理した後、その位置で到達可能な状態があるかどうかを確認します。$n$。 到達可能なものがない場合は、制約システムに一貫性がなく、シーケンスが存在しません。 
7. それ以外の場合は、有効な最終状態を選択し、親ポインタを逆方向にたどることによってシーケンスを再構築します。 

### なぜ効果があるのか

 DP は、位置を処理した後も不変条件を維持します。$i$、状態のセットは、 の値を正確に表します。$t_i$これは、以下のすべての制約を満たす有効なプレフィックスに拡張できます。$i-1$。 すべての遷移は 1 つのエッジに対して OR 制約と AND 制約の両方をエンコードするため、無効な部分割り当てが存続することはありません。 逆に、グローバルに有効なソリューションは、その各プレフィックスがローカルに有効であるため、すべてのフィルタリング ステップを通過する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok(x, y, a, b):
    return (x | y) == a and (x & y) == b

n = int(input())
a = list(map(int, input().split()))
b = list(map(int, input().split()))

dp = [[False] * 4 for _ in range(n)]
parent = [[-1] * 4 for _ in range(n)]

for v in range(4):
    dp[0][v] = True

for i in range(1, n):
    for cur in range(4):
        for prev in range(4):
            if dp[i-1][prev] and ok(prev, cur, a[i-1], b[i-1]):
                dp[i][cur] = True
                parent[i][cur] = prev
                break

end = -1
for v in range(4):
    if dp[n-1][v]:
        end = v
        break

if end == -1:
    print("NO")
    sys.exit()

res = [0] * n
res[n-1] = end

for i in range(n-1, 0, -1):
    res[i-1] = parent[i][res[i]]

print("YES")
print(*res)
```遷移チェックでは、エッジごとに両方のビット単位の制約が直接適用されます。 DP テーブルは各位置の各値の実現可能性を記録し、親テーブルは再構築を可能にする単一の有効な先行データを格納します。 バックワード パスは、線形時間で 1 つの一貫した割り当てを再構築します。 

微妙な点は、最初の有効な先行者を見つけた後に中断することです。 すべてのソリューションではなく存在のみが必要なため、これは安全です。 DP は、記録された先行データが有効な継続につながることを保証します。 

## 実用的な例

 ### 例 1

 入力:```
n = 4
a = [3, 3, 2]
b = [1, 2, 0]
```到達可能な状態を追跡します。 

| 私 | 到達可能な状態 |
 | --- | --- |
 | 1 | {0,1,2,3} |
 | 2 | {1,2,3} |
 | 3 | {0,2,3} |
 | 4 | {0,1,2,3} (例は任意の有効な状態で終了します) |

 1 つの再構築パスにより次の結果が得られます。$t = [1, 3, 2, 0]$。 

これは、各ステップで複数の状態が可能のままであるものの、実行不可能な遷移が徐々に排除される様子を示しています。 

### 例 2

 入力:```
n = 3
a = [0, 3]
b = [0, 3]
```最初の制約では、同じ値を持つペアのみが許可され、強制的に$t_1 = t_2$で$\{0,1,2,3\}$。 2 番目の制約には次のことが必要です$t_2 = t_3$同様に、OR と AND の両方を強制的に 3 にします。これは次の場合にのみ発生します。$t_2 = t_3 = 3$。 これは一貫していますが、少し変更すると次のようになります。```
a = [1, 2]
b = [0, 3]
```この場合、両方の制約を同時に満たすペアは存在せず、DP は位置 2 で空になり、NO が生成されます。

 一定の状態空間により、次の場合でも線形スケーリングが保証されます。$n = 10^5$、十分に制限内です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import builtins

    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    def ok(x, y, a, b):
        return (x | y) == a and (x & y) == b

    dp = [[False] * 4 for _ in range(n)]
    parent = [[-1] * 4 for _ in range(n)]

    for v in range(4):
        dp[0][v] = True

    for i in range(1, n):
        for cur in range(4):
            for prev in range(4):
                if dp[i-1][prev] and ok(prev, cur, a[i-1], b[i-1]):
                    dp[i][cur] = True
                    parent[i][cur] = prev
                    break

    end = -1
    for v in range(4):
        if dp[n-1][v]:
            end = v
            break

    if end == -1:

    res = [0] * n
    res[n-1] = end

    for i in range(n-1, 0, -1):
        res[i-1] = parent[i][res[i]]

    return "YES\n" + " ".join(map(str, res))

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、制約によって隣接する値が完全に固定される場合です。 例えば、$a_i = b_i = 3$力$t_i = t_{i+1} = 3$。 DP は、ステート 3 のみがその位置で存続できるようにすることでこれに対処し、他のすべてのステートは自然に消滅します。 

もう 1 つのケースは、制約により複数の遷移が許可される場合です。$a_i = 3, b_i = 0$これにより、OR ではすべてのビットをカバーするが、AND では重複しない個別の値の任意のペアが許可されます。 DP は複数の状態を正しく保存し、単一の値に早まってコミットしないため、後で行き詰まりが回避されます。 

欲張りメソッドの失敗例は、初期の選択によりローカル一致はまだ許可されているものの、将来の互換性が失われている場合に発生します。 DP は、最後の再構築ステップまで値を永続的に固定せず、グローバルに有効な継続をすべて保持することでこれを回避します。
