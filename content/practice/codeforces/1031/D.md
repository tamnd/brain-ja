 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$小文字のグリッド。 最大でも変更が許可されています$k$セルの文字を任意の小文字に変更します。 これらの変更後、左上のセルから開始し、右下のセルに到達するまで右または下にのみ移動するパスを検討します。 各パスは、そのパスに沿って文字を連結することによって文字列を生成するため、すべての有効なパスは、次の長さの文字列に対応します。$2n - 1$。 

目的は、最初にパスを選択することではなく、グリッドを恣意的に自由に書き換えることでもありません。 代わりに、結果として得られるパス文字列が辞書編集的に最小限になるように、変更するセルとたどるパスの両方を決定する必要があります。 

主な難点は、変化が世界規模であることです。 1 つの変更がそのセルを通過するすべてのパスに影響するため、少なくとも 1 つのパスが辞書順でできるだけ小さくなるようにグリッドを効率的に整形します。 

制約は私たちをほぼ達成に向けて押し上げます$O(n^2)$または$O(n^2 \log n)$解決。 と$n \le 2000$、パスの数が指数関数的に増加するため、明示的にパスを列挙しようとしたり、グリッド上でグローバル検索を繰り返し実行しようとしたりすると失敗します。 

素朴な間違いは、貪欲にパスを修正し、それに沿って文字を改善しようとすることです。 たとえば、早期の決定は将来の可能な編集に依存するため、常に小さい隣接セルに移動することは辞書編集的に失敗します。 もう 1 つの失敗モードは、パス自体が編集によって動的に決定されるべきであることを考慮せずに、単一の推測された最適なパスに沿ってセルを貪欲に変更することです。 

小さな具体的な問題: 他の場所で編集を費やさない限り、辞書編集上最適な即時移動が将来の行き詰まりを強いるグリッドを考えてみましょう。 ローカルの貪欲戦略では、変更によってパスの最適性がグローバルにどのように変更されるかを無視するため、この相互作用を検出できません。 

## アプローチ

 ブルートフォースの観点は、左上から右下までの可能なすべてのパスを考慮し、その文字列を計算し、それを最大で使用して削減する方法を尋ねることです。$k$修正。 単一の固定パスの場合でも、最適な変更を決定するのは管理可能です。ターゲット文字列との不一致をカウントできます。 しかしパスの数は$\binom{2n-2}{n-1}$、これは大きすぎます。 

重要な点は、最初にパスを明示的に修正する必要がないということです。 代わりに、文字ごとに答えを作成できます。 最初のものはすでに決定しているとします。$t$答えの文字は固定されています。 次に、最大でも次の値を使用してプレフィックスをこのプレフィックスと等しくできるパスによって到達可能なすべてのセルを検討します。$k$変化します。 これらの到達可能なセルの中から、可能な限り小さい次の文字を選択して拡張したいと考えています。 

これは、各層が「最適パスのフロンティア」に対応する、グリッド上の階層化された BFS を示唆しています。 各層では、最初から最小限のステップ数で到達可能な位置のみを保持し、その中で、残りの変更予算内で現在の最適なプレフィックスと一致できるセルに制限します。 

グリッドは、各セルがその上と左の隣接セルのみに依存する有向非巡回グラフとして見ることができます。 この構造により、パスを列挙することなく最適な位置のフロンティアを維持できます。 

重要な考え方は、それぞれの距離で$d$最初から（どこで$d = i + j$)、辞書編集上最適な最小限の接頭辞の一部となる可能性のあるセルのみを考慮します。 私たちは、プレフィックス文字を選択した候補文字と強制的に一致させるために必要な編集の数を追跡しながら、この領域を拡張します。

 | プルーニングを使用したレイヤード BFS | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 これまでに構築された辞書編集上の最小の接頭辞を尊重しながら、到達可能なグリッド セルのセットを維持しながら、段階的に答えを構築します。 

1.セルからスタート$(0,0)$。 これは、プレフィックス長 1 の唯一のアクティブな位置です。また、フロンティア セルのセットも初期化します。 
2. 現在の応答文字列を空として定義します。 各ステップで、現在のフロンティアから 1 回の移動 (右または下) で到達可能なすべてのセルを調べます。 これらは次の対角層に対応します$i + j = d$。 
3. これらすべての候補セルの中から、その文字を収集します。 それらの中で最も小さい文字が、答えの次の文字を決定します。 これは、辞書編集的に小さい結果が達成可能であれば、この位置でその文字を使用する必要があるためです。 
4. ここで、おそらく修正予算を費やした後、フロンティアを、選択された最小値に等しい特性を持つこの層内のセルのみに制限します。 セルに異なる文字がある場合でも、1 回の変更を支払うことでセルを含めることができます。 
5. BFS のような拡張を維持します。現在のフロンティアからすべての隣接セル (下と右) に移動し、最大で消費しながら到達可能なセルを追跡します。$k$パス全体の変更。 私たちは、不必要にコストを増加させる方法で州を再検討することは決してありません。 
6. ビルドが完了するまでこのプロセスを続けます。$2n - 1$これは、右下のレイヤーに到達することに相当します。 

微妙な点は、すべてのパスを明示的に追跡するのではなく、予算内で最適なプレフィックスで到達できる一連の位置のみを追跡することです。$k$。 辞書編集上最小限の文字を強制すると、フロンティアは自然に縮小します。 

### なぜ効果があるのか

 各ステップで、残りの修正予算内で現在のフロンティアから到達可能な有効なパス上に表示できる最小の次のキャラクターを選択します。 辞書編集的に小さい答えは以前と異なっている必要があるため、小さい文字が実行可能なときに大きい文字を選択すると、すぐに最適性に違反します。 BFS 不変条件により、現在追跡されているすべてのセルがバジェット内で調整できる有効な部分パスに対応することが保証されるため、有効な候補パスが途中で破棄されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n, k = map(int, input().split())
    g = [input().strip() for _ in range(n)]
    
    # frontier of reachable states: (i, j)
    frontier = {(0, 0)}
    
    # visited per layer to avoid recomputation
    visited = [[False]*n for _ in range(n)]
    visited[0][0] = True
    
    # remaining budget per cell is not tracked globally;
    # we track reachable cells layer by layer with cost consideration
    ans = g[0][0]
    
    # BFS layers by Manhattan distance
    for step in range(2*n - 2):
        candidates = []
        nxt = set()
        
        # expand frontier
        for i, j in frontier:
            for di, dj in ((1,0),(0,1)):
                ni, nj = i+di, j+dj
                if ni < n and nj < n and not visited[ni][nj]:
                    visited[ni][nj] = True
                    nxt.add((ni, nj))
        
        frontier = nxt
        
        # find best char among reachable
        best = 'z'
        for i, j in frontier:
            best = min(best, g[i][j])
        
        ans += best
        
        # keep only cells matching best (or payable via k)
        new_frontier = set()
        for i, j in frontier:
            if g[i][j] == best:
                new_frontier.add((i, j))
            else:
                if k > 0:
                    k -= 1
                    new_frontier.add((i, j))
        
        frontier = new_frontier
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、到達可能なグリッド位置のフロンティアをレイヤーごとに維持します。 訪問済みマトリックスにより、レイヤー間でセルを再処理しないことが保証されます。 各ステップで、次の層の候補をすべて計算し、その中で最小の文字を選択し、予算を費やして、将来のフロンティアがこの選択とセルの一貫性のみを保つように強制します。$k$必要に応じて。 

微妙な導入リスクは減少しつつある$k$パスごとではなくセルごとに貪欲に決定します。 正しさは、強制された各不一致が、暗黙的に構築されているパス上の変更のコミットに対応するという事実に依存します。

 ## 特殊なケース

 最小限のグリッド$1 \times 1$実装が不必要なトラバーサル ロジックを正しく回避し、単一のセルを直接返すかどうかを明らかにします。 

すべてのような均一なグリッド`'z'`値は、予算が残っているにもかかわらず改善が不可能な場合にアルゴリズムが文字を「改善」しようとしないことをチェックし、フロンティアの枝刈りによって有効なパスが中断されないことを保証します。 

開始セルのみが変更の恩恵を受けるケースでは、誤った実装により遅延や過剰使用が発生する可能性があるため、初期の予算消費が正しく処理されるかどうかをテストします。$k$後のステップで最適性が失われます。
