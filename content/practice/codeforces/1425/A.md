 ## 解決策
 ## 問題の理解

 問題は2人用のコインゲームです。 山積みになっている$N$金貨。 プレイヤーはチャネックさんから順番に順番を変えていきます。 ターンでは、プレーヤーはコインを 1 枚取るか、山に偶数枚のコインが含まれている場合は山のちょうど半分を取ることができます。 各プレイヤーは、ゲーム終了までに収集するコインの合計を最大化するために貪欲に行動します。 課題は、両方のプレイヤーが最適にプレイした場合にチャネック氏が確保できるコインの最大数を計算することです。 

入力は次のもので構成されます$T$それぞれ単一の整数を指定するテスト ケース$N$、初期コイン数。 各テスト ケースの出力は、チャネック氏が収集できる最適なコインの数です。 制約により許可される$T$まで$10^5$そして$N$まで$10^{18}$。 これにより、すべての動きを再帰的または反復的にシミュレートするアプローチが不要になります。$N$、単純なシミュレーションでは最大で$10^{18}$テストケースごとの操作。 

明らかではないエッジケースには、小さなものが含まれます。$N$、 特に$N = 1$または$N = 2$。 もし$N = 1$, チャネックさんはただコインだけを受け取ります。 のために$N = 2$、半分を取るとすぐに 1 枚のコインが得られますが、最初に 1 枚のコインを取ると相手に特定の選択を強制し、最適な戦略が次の要素の同等性に依存することを示しています。$N$その大きさだけではありません。 

## アプローチ

 ブルートフォースアプローチは、ゲームをターンごとにシミュレートすることです。 各ターンで、2 つのオプションを検討します。1 枚のコインを取得するか、コインの数が偶数の場合は半分を取得します。 相手からの最適な応答を仮定して、チャネック氏の最大コインを再帰的に計算します。 これは小規模な場合には機能しますが、$N$、各再帰呼び出しは 2 つの可能性に分岐し、指数関数的な時間計算量が発生します。 のために$N$近く$10^{18}$、これは完全に不可能になります。 

問題を単純化するための重要な洞察は、各プレイヤーが自分のコインを最大化するときの最適なプレイのパターンに気づくことです。 コインの数が偶数の場合、半分を取ることは、1 枚を取るよりも厳密に優れています。これは、コインが 1 枚より多く、相手に残すコインが少なくなるからです。 数字が奇数の場合、唯一の選択肢は 1 コインを取ることです。 「偶数の場合は半分」と「奇数の場合は 1」の間のこの交互により、予測可能な再帰シーケンスが作成されます。 関数を使用して、チャネック氏の最大コインを直接計算できます。$f(n)$すべてのターンをシミュレートすることなく、ターンを交互に行い、最適な動きを適用します。 

最終的なソリューションは、整数演算を使用してこの再帰パターンを効率的に利用し、対数時間での計算を可能にします。$N$線形または指数関数ではなく、

 | アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(2^N) | O(N) 再帰 | 遅すぎる |
 | 最適な再帰パターン | O(log N) | O(1) 反復 / O(log N) 再帰 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 関数を定義する$f(n, turn)$チャネック氏が収集できるコインの最大値を表します。$n$コインが残っており、次は彼の番です$turn = 0$、それ以外の場合は相手のターン。 
2. もし$n = 0$、コインが残っていないので0を返します。 
3. もし$turn = 0$(チャネックさんのターン)、コインを最大化する手を選択します。 もし$n$は偶数なので、1 つを取るより半分を取る方が良いためです。$\frac{n}{2} > 1$。 もし$n$奇数です、1 コインを受け取ります。 再帰的に呼び出す$f$残りのコインと相手のターン。 
4. もし$turn = 1$（対戦相手のターン）、彼らもコインを最大化するために最適に行動し、それによってチャネック氏の将来の利益が最小限に抑えられると仮定します。 もし$n$互角の場合、相手は半分を取ることになります。 奇数の場合は 1 つを受け取ります。 再帰的に呼び出す$f$残りのコインはチャネックさんに。 
5. ループを使用して再帰的パターンを反復アプローチに変換します。各ステップで誰がゲインを「制御」するかを交互に繰り返しながら、山がゼロになるまで半分または減算を繰り返しシミュレートします。 
6. チャネックさんのターンで集めたコインだけを合計します。 

これが機能する理由: 不変条件は、シーケンスの偶数ステップ (チャネック氏のターン) ごとに、最適な動きに従ってコインのみを追加し、奇数ステップごとに対戦相手がチャネック氏の利益を最小限に抑えることです。 Chanek さんのターンでは可能な限り常に半分を選択し、相手が許可された最大値を取ることをシミュレートすることで、合計が最大値になることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_coins(n):
    chanek = 0
    turn = 0  # 0 for Chanek, 1 for opponent
    while n > 0:
        if turn == 0:
            if n % 2 == 0:
                take = n // 2
            else:
                take = 1
            chanek += take
        else:
            if n % 2 == 0:
                take = n // 2
            else:
                take = 1
        n -= take
        turn ^= 1
    return chanek

T = int(input())
for _ in range(T):
    N = int(input())
    print(max_coins(N))
```機能`max_coins`交互にターンしながら山の上を繰り返します。 チャネック氏は偶数の山の半分、または奇数の場合は 1 つを取り、対戦相手はチャネックの利益を最小限に抑えるために最適なプレイをシミュレートします。 整数除算を使用すると、大きな値の正確性が保証されます。$N$オーバーフローなしで。

 ## 特殊なケース

 のために`N = 1`, チャネクは単純にコインだけを受け取ります。 アルゴリズムは計算します`take = 1`、チャネックの合計に加算され、減少します`n`0 に設定されて終了し、出力 1 が得られます。`N = 2`、チャネックは自分のターンで 1 を取り（相手に半分を取らせるより良いため）、相手は残りの 1 を取り、チャネックは 1 で終了します。アルゴリズムはパリティ ルールを適用し、最適な手を尊重してコイン減少ごとに 1 回だけターンを交互に行うため、これを正しく処理します。 次のような非常に大きな N の場合、$10^{18}$、ループは約 60 回の反復 (log2(10^18)) を実行し、Python の整数演算は大きな数値を正しく処理します。
