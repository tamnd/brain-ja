 ## 解決策
 ## 問題の理解

 それぞれ長さが 2 の 4 種類の括弧文字列、「((」、「()」、「)(」、および「))」が与えられています。 入力は、各タイプが何個あるかの数を提供します。 私たちのタスクは、これらすべての文字列を何らかの順序で連結して、有効な通常の括弧シーケンスを形成できるかどうかを判断することです。 通常の括弧シーケンスとは、括弧の間に「+」と「1」を挿入した場合に有効な算術式を表すことができるシーケンスです。 例には、「(())」または「()()」が含まれます。 「))(」や「)((」のようなシーケンスは、左括弧と右括弧を正しく一致させる方法がないため無効です。

 各文字列はちょうど 2 文字を構成するため、最終的なシーケンスの全長はカウントの合計の 2 倍になります。 重要な観察点は、各タイプの文字列が開始括弧と終了括弧の「バランス」に異なる影響を与えるということです。 「((」は残高を 2 増加させ、「()」は残高を中立に保ち、「)(」は最初に減少してから残高を増加させ、「))」は残高を 2 減少させます。 

制約により、次までのカウントが可能になります$10^9$したがって、シーケンスを生成したり、連結を明示的にシミュレートしようとするソリューションは、非常に遅すぎます。 シーケンスを構築するのではなく、純粋に算術演算と不変式を使用して推論する必要があります。 

重要なエッジ ケースは、「)」で始まる文字列または「(」で終わる文字列の数が一致できる数を超えている場合です。たとえば、「)(」が 1 つあり、「((」が 1 つもない場合、ある時点で負のバランスを作成せずにそれをどこにでも配置することは不可能です。もう 1 つのエッジ ケースは、すべてのカウントがゼロであり、空のシーケンスが規則的である場合です。これらの境界条件を正しく処理することは、すべてのテストに合格するために重要です。

 ## アプローチ

 ブルートフォースアプローチでは、文字列のすべての順列を試し、連結されたシーケンスが規則的かどうかを確認しようとします。 これはすべての可能性を探索するため、原理的には正しいですが、順列の階乗増加により、文字列の数が非常に少ない場合でも実行できなくなります。 までのカウントで$10^9$、順列を試すことは不可能です。 

最適なアプローチは、ブラケットのバランスを維持することにかかっています。 すべての通常の括弧シーケンスは 2 つの条件を満たさなければなりません。 まず、開き括弧の合計数は閉じ括弧の合計数と等しくなければなりません。 次に、左から右にスキャンすると、実行残高 (開始値から終了値を差し引いた値) がマイナスになってはなりません。 これら 2 つの条件は、すべての文字列をシミュレートすることなく、カウントから直接計算できます。 

具体的には、「((」の数と「)(」の数が、「))」の数と「((」の数に等しいかどうかを確認します。これにより、合計残高がゼロになることが保証されます。非負の実行残高を満たすために、「)(」と「((」の差は、どの時点でも 1 を超えてはなりません。「)(」はシーケンスの途中で残高を減らすことができる唯一の文字列であるためです。これにより、簡潔なルールが導かれます。 「((」と「))」は最大でも 1 つである必要があり、少なくとも 1 つの「)(」がある場合は、対応する「((」を開始する必要があります。

 | --- | --- | --- | --- |
 | ブルート フォース (すべての順列を試す) | O((cnt1+cnt2+cnt3+cnt4)!) | お(1) | 遅すぎる |
 | 残高ベースのチェック | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 4 つの文字列タイプのカウントを読み取ります。$cnt1, cnt2, cnt3, cnt4$。 これらは「((」、「()」、「)(」、「))」に対応します。 
2. 左括弧の合計を次のように計算します。$2*cnt1 + cnt2 + cnt3$そして合計の閉じ括弧は次のようになります$2*cnt4 + cnt2 + cnt3$。 それらが等しいことを確認します。 そうでない場合は、通常のシーケンスには同じ数の左括弧と右括弧が必要であるため、0 が出力されます。 
3. 残高要件を確認します。 唯一注意が必要な文字列は「)(」です。これは閉じ括弧で始まるためです。開始時にマイナスのランニングバランスを避けるために、「)(」の前に少なくとも 1 つの「((」を配置する必要があります。$cnt3 > 0$そして$cnt1 = 0$、0を出力します。 
4. 「((」と「))」のカウントの差を確認します。 もし$|cnt1 - cnt4| > 1$、実行残高を非負に保つことができないため、0 を出力します。 
5. すべての条件が合格すると、1 を出力します。 

維持される不変条件は、連結されたシーケンスのすべての点で、「(」マイナス「)」の実行残高が決して負にならず、ゼロで終わるということです。 これにより、連結をシミュレートする必要がなく、通常のブラケット シーケンスが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

cnt1 = int(input())
cnt2 = int(input())
cnt3 = int(input())
cnt4 = int(input())

# check if total number of opening and closing brackets are equal
total_open = 2*cnt1 + cnt2 + cnt3
total_close = 2*cnt4 + cnt2 + cnt3

if total_open != total_close:
    print(0)
elif cnt3 > 0 and cnt1 == 0:
    # cannot start with ")("
    print(0)
elif abs(cnt1 - cnt4) > 1:
    # balance at ends is off by more than 1
    print(0)
else:
    print(1)
```このソリューションは最初に全体のバランスをチェックし、最終的なシーケンスに一致する括弧があることを保証します。 次に、トリッキーな ")(" 文字列のエッジ ケースを処理し、純粋な開始文字列 "((" と純粋な終了文字列 "))" の違いが非負の実行バランスに違反しないようにします。各条件は、通常のブラケット シーケンスのプロパティに直接対応します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    cnt1 = int(input())
    cnt2 = int(input())
    cnt3 = int(input())
    cnt4 = int(input())

    total_open = 2*cnt1 + cnt2 + cnt3
    total_close = 2*cnt4 + cnt2 + cnt3

    if total_open != total_close:
        return "0"
    elif cnt3 > 0 and cnt1 == 0:
        return "0"
    elif abs(cnt1 - cnt4) > 1:
        return "0"
    else:
        return "1"

# provided samples
assert run("3\n1\n4\n3\n") == "1", "sample 1"
assert run("0\n0\n0\n0\n") == "1", "empty sequence"

# custom cases
assert run("1\n0\n0\n1\n") == "1", "single matching brackets"
assert run("0\n0\n1\n0\n") == "0", "cannot start with )("
assert run("10\n0\n0\n12\n") == "0", "imbalance too large"
assert run("2\n1\n1\n2\n") == "1", "mixed case"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 0 0 1 | 1 | 単純な有効なシーケンス |
 | 0 0 1 0 | 0 | 「)(」で始めることはできません |
 | 10 0 0 12 | 0 | "((" と "))" の間の不均衡 |
 | 2 1 1 2 | 1 | すべてのタイプの一般的な大文字と小文字の混合 |

 ## 特殊なケース

 少なくとも 1 つの ")(" があり、"((" が存在しない場合、アルゴリズムは 0 を返します。入力の場合`0 0 1 0`、`cnt3>0`そして`cnt1=0`チェックをトリガーします。 ")(" を先頭に配置しようとすると、すぐにマイナス残高が発生します。アルゴリズムはこれを検出し、正しく 0 を出力します。

 純粋なオープン文字列と純粋なクローズ文字列の差が 1 を超える場合、次のようになります。`10 0 0 12`の場合、最終シーケンスではある時点で許可されている以上の開始括弧が必要となり、非負のランニング バランスの不変条件に違反するため、アルゴリズムは 0 を出力します。
