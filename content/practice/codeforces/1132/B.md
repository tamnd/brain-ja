 ## 解決策
 ## 問題の理解

 チョコレートバーのセットがあり、それぞれ価格が異なります。 買い物客はすべてのバーを望んでいますが、厳選された割引クーポンを持っています。 各クーポンでは固定数のバーを購入できますが、その選択範囲内で最も安いバーが無料になります。 タスクは、クーポンが最適に適用され、残りのバーが定価で購入された場合の最小総コストをクーポンごとに決定することです。 

入力はバーの数で構成されます`n`、それぞれの価格`a_i`、クーポンの数`m`、クーポンのサイズ`q_i`。 出力は次の配列です。`m`各整数は、対応するクーポンが最適に使用された場合の最小支払い額です。 

制約により許可されるのは、`n`300,000 にもなる。 これにより、クーポンごとにチョコレート バーのすべての組み合わせを試す強引なアプローチが直ちに排除されます。`C(n, q)`組み合わせて成長します。 各クーポンを単純に反復しても遅すぎるため、線形またはほぼ線形にスケールする方法が必要です。`n`。 

すべてのチョコレート バーの価格が同じ場合、明らかではないエッジ ケースが発生します。 たとえば、次の場合`n = 3`、バーは`[5, 5, 5]`、クーポンを使用すると、`q = 2`の場合、選択する最適なバーは任意のペアになります。 出力では、ペア内で最も高価なもののみの支払いを考慮する必要があります。 バーが個別であると仮定する不注意なアプローチでは、間違った計算が行われる可能性があります。 

もう 1 つの微妙なケースは、クーポンが許可する場合です。`q = n`バー。 ここでは、すべてのバーが割引対象として選択され、すべてのバーの中で最も安いバーが無料になります。 実装では、インデックス付けエラーなしでこれを処理する必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。クーポンごとに、サイズの考えられるすべてのサブセットを列挙します。`q_i`、最安値を除いた選択したバーの価格を合計し、残りのバーの合計を加算します。 これは正しく機能しますが、最悪の場合の複雑さはクーポンあたり O(n 選択 q) になります。 n が 300,000 までの場合、控えめな q 値でも天文学的な数の組み合わせが作成されるため、これは実行不可能です。 

重要な洞察は、クーポンごとに割引を最大化したいということです。 割引は、選択したセットの中で最も安いバーの価格です。 したがって、総コストを最小限に抑えるには、次のものを選択する必要があります。`q_i`クーポンの最も高価なバー。 これらのうち最も安いものを除くすべての料金を支払うと、合計から差し引かれる金額が最大になります。 これにより、すべてのバーを降順で並べ替え、接頭辞の合計を使用して上位の合計をすばやく計算するという問題を軽減できます。`q_i`バー。 合計コストは、すべてのバーの合計から上位のバーの中で最も安いバーを引いたものとなります。`q_i`。 

これにより、解は組み合わせから O(n log n + m) に変換されます。ここで、O(n log n) は並べ替え用であり、O(m) は事前計算されたプレフィックス合計を使用して各クーポンの結果を計算するためのものです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m * C(n, q)) | O(n) | 遅すぎる |
 | 最適 | O(n log n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、価格の配列`a`、`m`、およびクーポン サイズの配列`q`。 これらは、バーの数、個々の価格、クーポンの数、各クーポンが影響するバーの数を表します。 
2. 配列をソートする`a`降順で。 これにより、最も高価なバーが先頭に来るようになります。 割引を最大化するには、最適なクーポンの選択には常に最も高価なバーが含まれるため、並べ替えは非常に重要です。 
3. ソートされた配列のプレフィックスの合計を計算します。 インデックスのプレフィックスの合計`i`最初の合計を表します`i+1`最も高価なバー。 これにより、トップの合計価格の定時クエリが可能になります。`k`バー。 
4. すべてのバーの合計を計算します。 これは、クーポンの無料バーを差し引いて各クーポンの最終支払いを計算するために使用されます。 
5. クーポンサイズごと`q_i`、最適な戦略はトップを選択することです`q_i`バー。 その中で、最も安いバー (ソートされたサイズのサブセットの最後のバー)`q_i`）は無料です。 合計コストは、すべてのバーの合計からこの最も安いバーを引いたものになります。 
6. 各クーポンの結果を順番に印刷します。 

正確性を保証する不変条件は、どのクーポンでも、最大のクーポンを選択することで割引が最大化されるということです。`q_i`バー。 低価格のバーは無料のチョコレートの価値を下げるため、代替のバーのサブセットでより大きな割引はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
m = int(input())
q = list(map(int, input().split()))

a.sort(reverse=True)
prefix_sum = [0] * n
prefix_sum[0] = a[0]
for i in range(1, n):
    prefix_sum[i] = prefix_sum[i-1] + a[i]

total_sum = prefix_sum[-1]

results = []
for x in q:
    free_bar = a[x-1]  # cheapest among the top x bars
    cost = total_sum - free_bar
    results.append(str(cost))

print('\n'.join(results))
```The solution first sorts the chocolate bars and constructs a prefix sum array. の`total_sum`すべてのバーの合計を取得します。 各クーポンの上部の最後のバー`q_i`無料のチョコレートを考慮して、合計金額からバーが差し引かれます。 このアルゴリズムは、事前にソートされた配列を使用することで再計算を回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + m) | バーのソートには n log n かかります。 各クーポンの計算は、プレフィックス合計を使用して O(1) です。 |
 | スペース | O(n) | ソートされた配列とプレフィックスの合計を保存します。 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    m = int(input())
    q = list(map(int, input().split()))

    a.sort(reverse=True)
    total_sum = sum(a)
    results = []
    for x in q:
        results.append(str(total_sum - a[x-1]))
    return '\n'.join(results)

# provided samples
assert run("7\n7 1 3 1 4 10 8\n2\n3 4\n") == "27\n30", "sample 1"

# minimum size input
assert run("2\n1 2\n1\n2\n") == "2", "min size"

# all equal values
assert run("5\n5 5 5 5 5\n2\n2 5\n") == "20\n20", "all equal"

# maximum-size simplified test
assert run("6\n1 2 3 4 5 6\n1\n6\n") == "20", "full coupon"

# edge case: descending input
assert run("5\n10 8 5 3 1\n2\n2 3\n") == "27\n26", "descending input"

 ## 特殊なケース

 すべてのバーをカバーするクーポンの場合は、`q = n`, 全体的にフリーバーが一番安いです。 たとえば、バーの場合`[4, 2, 3]`そして`q = 3`、無料バーは 2、支払い総額 = 4 + 3 = 7。アルゴリズムは `a[q-1] = a を正しく選択します。
