 ## 解決策
 ## 問題の理解

 小文字の文字列があります。 1 回の操作で、文字がすべて同じである連続したブロックを選択して削除できます。 取り外した後、文字列の残りの部分が結合されます。 

目標は、できるだけ少ない操作で文字列全体を削除することです。 

重要な問題は、削除によって文字列の構造が変化してしまうことです。 もともと分離されていた文字は、中間の文字が削除されると隣接することがあります。 これは、局所的に最適ではないと思われる決定が、後でより良い機会を生み出す可能性があることを意味します。 

たとえば、次のことを考えてみましょう。```
abaca
```各文字を個別に削除すると、5 つの操作が必要になります。 より良い戦略は次のとおりです。```
abaca
delete b  -> aaca
delete both a blocks together after merging -> c
delete c
```これには 3 つの操作のみが必要です。 

文字列の長さは最大 500 です。これにより、すべての削除シーケンスを明示的に調査するアプローチは即座に除外されます。 可能な削除命令の数は指数関数的に増加します。 と$n=500$、 平$O(n^4)$すでに約 625 億のオペレーションが行われており、あまりにも遅すぎます。 動的プログラミング ソリューションが必要です$O(n^3)$。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
3
aaa
```答えは次のとおりです。```
1
```すべての文字を一度に削除できます。 常に間隔を分割する単純な DP では、誤って 3 が生成される可能性があります。 

次のことを考慮してください。```
3
aba
```答えは次のとおりです。```
2
```真ん中を削除`b`、それから二人`a`文字が隣接し、一緒に削除できます。 現在隣接している等しい文字のみを調べるアプローチでは、この可能性が失われます。 

考慮する：```
4
abab
```答えは次のとおりです。```
3
```等しい文字をすべて 1 つの削除にマージすることはできません。 中間削除後にどの文字を結合できるかを慎重に考慮する必要があります。 

これらの例は、問題が基本的に間隔と将来のマージに関するものであることを示しています。 

## アプローチ

 ブルートフォース手法では、すべての有効な削除が再帰的に試行されます。 状態ごとに、現在削除可能な均一部分文字列の 1 つを選択し、削除して続行します。 

これは、考えられるすべての操作シーケンスを調査するため、正しいです。 残念ながら、結果として得られる文字列の数は爆発的に増加します。 中程度の長さであっても、状態空間は巨大になります。 最悪の場合、実行時間は指数関数的に増加します。 

問題の構造は何か別のことを示唆しています。 削除の影響は間隔に限定されます。 部分文字列に注目するときは常に$s[l..r]$、それをクリアするための最適な方法は、その間隔にのみ依存します。 

これは当然インターバル DP につながります。 

させて$dp[l][r]$部分文字列を削除するために必要な操作の最小数を示します$s[l..r]$。 

文字を削除したいとします。$s[l]$。 1 つのオプションは、それを個別に削除してから残りをクリアすることです。$$dp[l][r] = 1 + dp[l+1][r]$$興味深い観察は、同じ文字が間隔内に別の出現箇所で存在する場合に現れます。 

もし$s[l] = s[k]$、それらの間のすべてを削除した後、これら 2 つの等しい文字は同じ削除操作に参加できます。 位置のキャラクターに追加の操作を支払う必要はありません$l$。 

これにより、次のような遷移が得られます。$$dp[l][r] = \min(dp[l][r], dp[l+1][k-1] + dp[k][r])$$最初の項は、一致する文字間のすべてを削除します。 この後、ポジションを$l$位置を含む削除とマージできます$k$。 

この観測により、指数関数的検索が 3 次区間 DP に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適な間隔 DP | O(n3) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 定義する`dp[l][r]`インデックスから部分文字列を削除するために必要な操作の最小数として`l`インデックスを付ける`r`。 
2. すべての単一文字間隔を初期化します。 

1 つの文字はいつでも 1 回の操作で削除できます。そのため、次のようになります。```
dp[i][i] = 1
```3. 間隔を長さの昇順に処理します。 

より大きな状態はそれらに依存するため、より小さな間隔はより大きな間隔よりも前に解決する必要があります。 
4. インターバルごとに`[l, r]`、削除する戦略から始めます`s[l]`別に。```
dp[l][r] = 1 + dp[l+1][r]
```これは常に有効です。 
5.あらゆる位置を検索`k`と`l < k ≤ r`そのような`s[l] == s[k]`。 

中央のセクションが消えた後、等しい文字がまとめて削除される場合があります。 
6. それぞれについて`k`の削除をマージしてみてください。`s[l]`を含む削除付き`s[k]`。```
cost = dp[l+1][k-1] + dp[k][r]
```最初の項は、2 つの等しい文字の間にあるものをすべて削除します。 2 番目の項では、文字を許可しながらサフィックスをクリアします。`l`でキャラクターを削除する操作に参加するには`k`。 
7. あらゆる可能性の中で最小値を維持します。 
8. 最終的な答えは次のとおりです。`dp[0][n-1]`。 

### なぜ効果があるのか

 DP は、インターバル内の左端のキャラクターのあらゆる運命を調べます。 

その文字が単独で削除されるか、これは次のように表されます。`1 + dp[l+1][r]`、または、最終的にはその右側のどこかに一致する文字と一緒に削除されます。 一致するポジションごとに`k`、最初にそれらの間の間隔を完全に削除する必要があります。これにはコストがかかります`dp[l+1][k-1]`。 その後のキャラクターは、`l`の文字と同じ削除操作に吸収できます。`k`なので、追加の操作は必要ありません。 

有効な最適戦略はすべて、これらのケースのいずれかに当てはまります。 漸化式はすべての最小値をとるので、`dp[l][r]`は、すべての間隔の真の最適値に等しくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    dp = [[0] * n for _ in range(n)]

    for i in range(n):
        dp[i][i] = 1

    for length in range(2, n + 1):
        for l in range(n - length + 1):
            r = l + length - 1

            dp[l][r] = 1 + dp[l + 1][r]

            for k in range(l + 1, r + 1):
                if s[l] == s[k]:
                    middle = dp[l + 1][k - 1] if l + 1 <= k - 1 else 0
                    dp[l][r] = min(
                        dp[l][r],
                        middle + dp[k][r]
                    )

    print(dp[0][n - 1])

if __name__ == "__main__":
    solve()
```DP テーブルには、間隔ごとの回答が保存されます。 1 回の操作で 1 文字が削除されるため、1 文字の間隔は 1 に初期化されます。 

間隔は長さを増やすことによって処理されます。 これにより、計算するたびに次のことが保証されます。`dp[l][r]`、繰り返しに表示されるすべての小さな間隔はすでに使用可能です。 

微妙な部分はマージトランジションです。 いつ`s[l] == s[k]`、位置に関して余分な操作を追加しません`l`。 のキャラクター`l`最終的に位置を削除する削除を結合します`k`。 まさにそれが、繰り返しで以下を使用する理由です。```
middle + dp[k][r]
```の代わりに：```
middle + 1 + dp[k][r]
```もう 1 つの簡単な間違いは、間の空の間隔を処理することです。`l+1`そして`k-1`。 いつ`k = l + 1`、その間隔のコストはゼロです。 実装では、このケースを明示的にチェックします。 

答えは次の場所に保存されます`dp[0][n-1]`、文字列全体を表します。

    for i in range(n):

 ## 特殊なケース

 ### すべての文字が同一

 入力:```
3
aaa
```DP は最初にすべての単一文字間隔を 1 に設定します。`[0,1]`、両端が`a`、マージを許可し、答えを 1 に減らします。同じことが起こります。`[0,2]`。 

最終的な答え:```
1
```このケースでは、繰り返された等しい文字が個別にカウントされるのではなく、1 つの操作にマージされることを検証します。 

### 等しい文字を別の文字で区切る

 入力:```
3
aba
```間隔`[0,2]`で始まり、で終わる`a`。 

繰り返しにより次のことが評価されます。```
dp[1][1] + dp[2][2]
= 1 + 1
= 2
```真ん中`b`が先に削除されます。 その後二人は`a`文字が隣接して一緒に消えます。 

最終的な答え:```
2
```これはまさに、現在の隣接関係のみに基づく貪欲なアプローチを打ち負かす状況です。 

### 同等の文字はありません

 入力:```
5
abcde
```すべての文字が異なるため、マージ遷移は適用できません。 

DP は以下を繰り返し使用します。```
dp[l][r] = 1 + dp[l+1][r]
```これにより次の結果が得られます:```
5
```すべての文字を個別に削除する必要があります。 

### 交互パターン

 入力:```
4
abab
```一致するペアはありますが、それらすべてを 1 つの操作にマージすることはできません。 DP は一致するすべてのポジションを調査し、達成可能な最良の値が次であることを発見します。```
3
```このケースでは、繰り返しによって文字の一致による利点が過大評価されておらず、中間の削除後に実際に達成可能なマージのみが実行されることが確認されています。
