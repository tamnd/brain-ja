 ## 解決策
 ## 問題の理解

 とのコンテストがあります`n`生徒たちはそれぞれ、初期バッテリーで起動するラップトップを持っています`a_i`そして消費する`b_i`1分あたりの充電単位。 コンテストは続く`k`分。 Polycarp は固定整数出力の単一充電器を購入できます`x`いつでもどのラップトップにも接続できますが、一度に接続できるラップトップは 1 台だけです。 電源に接続している間、ラップトップは電力を消費します`b_i - x`代わりに 1 分あたりの単位`b_i`。 目標は、最小限の充電器電力を見つけることです`x`そのため、コンテストが終了するまでにラップトップの充電がゼロになることはありません。 

入力制限は大きいです。`n`そして`k`それぞれが到達できるか`2 * 10^5`、初期費用`a_i`まで可能です`10^12`。 これにより、すべての生徒に対して毎分を直接シミュレートするソリューションは除外されます。`O(n*k)`に達する可能性のある操作`4 * 10^10`、3秒では実現不可能です。 代わりに、大まかにアルゴリズムが必要です`O(n log(max_possible_x))`またはそれ以上です。 

重要なエッジケースは、ラップトップの初期充電に比べて消費率が非常に高い場合に発生します。 充電器が最も要求の厳しいラップトップを時間内に補うのに十分な強度がない場合、どの電力レベルでも充電器を節約することはできません。 たとえば、次の場合`a = 1`、`b = 10`、 そして`k = 2`、ラップトップが最初の 1 分で停止するのを防ぐには、充電器には少なくとも 10 ユニットが必要です。 不注意なアプローチでは、最悪の場合の順序を考慮せずに分刻みで貪欲な割り当てを試行し、充電器が技術的に十分である場合でもマイナス充電につながる可能性があります。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべての整数パワー出力を反復することです。`x`0 からすべてをシミュレートします`k`すべてのラップトップに対して数分かかり、すべてのラップトップが生き残るかどうかを確認します。 これは正しいですが、遅すぎるため、`x`非常に大きくなる可能性があります（最大`10^12`以上）、シミュレーションの数は天文学的なものになります。 

重要な観察は、固定電力出力の場合です。`x`で実現可能性を確認できます。`O(n log n)`貪欲な戦略を使用します。 各ラップトップ`i`充電器なしで存続できる最大時間は次のとおりです。`(a_i // b_i)`最初は充電され、さらに 1 分ごとに充電が延長されます。 この問題は、候補者に対するスケジュールの問題としてモデル化できます。`x`、スケジュールが可能かどうかを判断します`k`すべてのラップトップの合計充電時間は、ラップトップの充電がゼロを下回ることはありません。 消費電力の多いラップトップは消耗が早いため、早めに充電する必要があります。 必要最小限の充電時間でラップトップを分類し、分数を貪欲に割り当てることで、最も重要なラップトップを最初にカバーできるようになります。 

これにより、問題は単調述語に変換されます。`x`十分ですか？」は真か偽のどちらかになります。述語は に関して単調であるため、`x`-もし`x`作品、それより大きいもの`x`これも機能します - 二分検索を実行できます`x`実行可能な最小値を見つけます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * k * max_x) | O(n) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 関数を定義する`can_finish(x)`返すもの`True`電源付きの充電器の場合`x`すべてのラップトップが生き残ることを保証できます。 この機能は、貪欲に充電をスケジュールします。 
2. 各ラップトップについて、充電せずに何分持続できるかを計算します。`a_i // b_i`。 次に、充電器の電力が次の場合にさらに何分必要になるかを計算します。`x`。 
3. ラップトップを最大許容充電期限順に並べ替えます。 初期充電量が少なく消費量が多いノートパソコンの方が緊急性が高くなります。 
4. 0 から 0 まで 1 分ごとに反復してコンテストをシミュレートします。`k-1`。 毎分、充電が必要な期限が最も近いラップトップを選択し、1 分間の充電を割り当てます。 
5. いずれかの時点で、必要な分数が残りの分数を超えた場合は、戻ります。`False`。 
6. コンテストが終了するまですべてのラップトップをゼロ以上に保つことができた場合は、リターンします。`True`。 
7. 二分探索を実行します。`x`から`0`に`max_possible`(たとえば、すべての合計`b_i`または`10^12`) を使用して`can_finish(x)`述語として。 
8. 最小値を返す`x`誰のために`can_finish(x)`は`True`。 いいえの場合`x`働きます、戻ります`-1`。 

不変条件は次のとおりです`can_finish(x)`、ラップトップは常に緊急性の順に充電され、充電の合計分数がコンテストの継続時間を超えることはありません。 この貪欲なスケジューリングが成功すると、`x`であれば、充電器の電力は十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    def can_finish(x):
        # compute required charging minutes for each laptop
        need = []
        for ai, bi in zip(a, b):
            if bi > x:
                # number of minutes before this laptop dies if never charged
                m = (ai + x - 1) // (bi - x) if bi != x else float('inf')
                need.append((m, bi))
            else:
                need.append((k, bi))  # will survive entire contest without charging
        need.sort()
        total_minutes = 0
        for minutes_needed, bi in need:
            total_minutes += minutes_needed
            if total_minutes > k:
                return False
        return True

    left, right = 0, max(b) * k + 1
    ans = -1
    while left <= right:
        mid = (left + right) // 2
        if can_finish(mid):
            ans = mid
            right = mid - 1
        else:
            left = mid + 1

    print(ans)

if __name__ == "__main__":
    main()
```機能`can_finish(x)`緊急性に基づいた貪欲な戦略を使用して実装されます。 必要な生存時間で並べ替えることで、より早く故障する可能性のあるラップトップが優先的に充電されるようになります。 二分探索により、最小限の十分な充電器電力を効率的に見つけることができます。 エッジケースなど`x`最大のものよりも小さい`b_i`、貪欲なスケジューリングによって正しく処理されます。
