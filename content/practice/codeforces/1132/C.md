 ## 解決策
 ## 問題の理解

 うちには柵があるよ`n`から番号が付けられたセクション`1`に`n`。 各画家は 1 つの連続した間隔をカバーします`[l_i, r_i]`。 もともと全部`q`塗装職人はいるが、そのうちの 2 名を解雇し、残りの 1 名を残すことを余儀なくされる`q - 2`。 

少なくとも 1 人の塗装担当者がフェンス セクションをカバーする場合、フェンス セクションは塗装されます。 目標は、ペイントされたセクションの総数ができるだけ多くなるように、どの 2 人のペインタを削除するかを選択することです。 

入力により、フェンスの長さと各ペインターがペイントした間隔が与えられます。 出力は、ちょうど 2 人のペインタを削除した後にペイントされたままになるフェンス セクションの最大数です。 

制約は、ソリューション設計を推進する最初のものです。 両方`n`そして`q`せいぜい`5000`。 削除されたペインターのすべてのペアを試すブルートフォース アプローチには、すでに約$$\binom{5000}{2} \approx 12.5 \text{ million}$$ペア。 

大きく聞こえますが、管理可能です。 本当の問題は、ペアごとにペイントされたフェンスを再計算する場合に現れます。 均等にやっています`O(n)`ペアごとに必要な作業量はおよそ$$12.5 \cdot 10^6 \cdot 5000$$まったく実行不可能な操作です。 

問題の構造は、カバレッジに関する情報を事前に計算し、削除された各ペアを定数時間または対数時間で評価する必要があることを示唆しています。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
5 3
1 5
1 5
1 5
```2 人のペインターを削除しても、フェンス全体を覆う 1 人のペインターが残るため、答えは次のようになります。`5`。 固有の被覆率のみをカウントするソリューションでは、残りの塗装部分が過小評価されてしまいます。 

もう 1 つの重要なケースは次のとおりです。```
5 3
1 2
2 3
3 4
```セクション`2`2人の画家とセクションによってカバーされています`3`こちらも二人の画家がカバーしています。 異なるペアを削除すると、異なるオーバーラップに影響します。 正確に 1 回カバーされたセクションと正確に 2 回カバーされたセクションを注意深く区別する必要があります。 

3 番目の微妙なケースは次のとおりです。```
5 3
1 1
3 3
5 5
```2 人のペインタを削除すると、ペイントされたセクションが 1 つだけ残ります。 カバレッジは非常にまばらであるため、間隔ロジックはギャップを正しく処理する必要があります。 

## アプローチ

 最も直接的なアイデアは、削除できるすべてのペインターのペアを試してみることです。 

固定ペアの場合`(i, j)`、残りの塗装担当者が塗装したすべてのセクションにマークを付け、まだ覆われているフェンス セクションの数を数えることができます。 これは文字通り問題の定義をシミュレートするものであるため、これは正しいです。 

難点はコストですね。 くらいあります`12.5 million`最悪の場合はペインターペア。 最大のカバレッジを再計算します`5000`各ペアのフェンスセクションには数百億回の操作が必要になります。 

重要な点は、ペアごとにペイント構成全体を再構築する必要がないということです。 重要なのは、2人の塗装業者を外した後にどれだけのセクションが未塗装になるかです。 

まず、フェンスのセクションごとに何人の塗装職人がそれをカバーするかを計算します。 

させて`cover[x]`その数になります。 

画家を削除するとします`i`そして`j`。 

最終的な絵画からセクションが消えるのは 2 つの状況のみです。 

もし`cover[x] = 1`、その後、ちょうど 1 人の画家がそのセクションをカバーします。 そのペインタを削除すると、そのセクションが消えます。 

もし`cover[x] = 2`、その後、ちょうど 2 人の画家がそのセクションをカバーします。 このセクションは、これらのペインタの両方が削除された場合にのみ消えます。 

少なくとも 3 つのカバレッジを持つセクションは、どの 2 人のペインタが削除されるかに関係なく、ペイントされたままになります。 

これにより、問題は最終的な絵画を再計算するのではなく、損失を数えることに変わります。 

させて：`total`= 少なくとも 1 人の画家によって最初に描かれたセクションの数。 

それぞれの画家にとって`i`、 定義する：`one[i]`= 1 回だけカバーされ、ペインターによってカバーされたセクションの数`i`。 

これらのセクションはペインターが表示されるたびに表示されなくなります`i`が削除されます。 

すべてのペアについて`(i, j)`、 定義する：`two[i][j]`= 特に画家によって正確に 2 回カバーされたセクションの数`i`そして`j`。 

これらのセクションは、両方のペインタが削除された場合にのみ消えます。 

次に、ペインターを削除した後、`i`そして`j`、残りのペイントされたセクションは次のようになります。$$total - one[i] - one[j] - two[i][j]$$今度はタスクがコンピューティングになります`one`そして`two`効率的に。 

間隔が連続しているので、`n ≤ 5000`、すべてのフェンスの位置を処理できます。 カバレッジが 1 つだけのポジションについては、責任のあるペインターを特定します。 正確に 2 つのカバレッジを持つポジションについては、責任のあるペインター ペアを特定します。 

間隔カウントを効率的にクエリするために、カバレッジが 1 に等しい位置とカバレッジが 2 に等しい位置のプレフィックス合計を構築します。 

その後、いくつかの prefix-sum クエリの後、すべてのペインタ ペアを一定時間で評価できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q²・n) 以上 | O(n) | 遅すぎる |
 | 最適 | O(nq + q²) | O(q²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのペインター間隔を読み取ります。 
2. フェンスを越えて差分配列を構築し、計算します`cover[x]`、各セクションをカバーする画家の数。 
3. カウント`total`、フェンスセクションの数`cover[x] > 0`。 
4. 配列を作成する`cnt1[x]`どこ`cnt1[x] = 1`もし`cover[x] = 1`、 さもないと`0`。 
5. 配列を作成する`cnt2[x]`どこ`cnt2[x] = 1`もし`cover[x] = 2`、 さもないと`0`。 
6. プレフィックスの合計を構築する`cnt1`そして`cnt2`。 

これらにより、任意の間隔内にちょうど 1 つまたはちょうど 2 つのカバレッジを持つ位置がいくつあるかを数えることができます。 
7. すべての画家のために`i`、計算する`one[i]`。 

これはペインタ内の位置の数と等しくなります`i`の間隔の合計カバレッジはちょうど 1 です。 
8. 画家のペアごとに`(i, j)`、両方のペインタによって正確に 2 回カバーされるポジションの数を計算します。 

正確に 2 回カバーされ、両方の画家に属する位置は、それらの間隔の交点の内側にある必要があるため、位置を次のように数えます。`cover[x] = 2`あの交差点の中。 
9. すべてのペアについて`(i, j)`、計算する$$total - one[i] - one[j] - two[i][j]$$そして最大値を維持します。 
10. 最大値を出力します。 

### なぜ効果があるのか

 フェンスセクションは、それを覆っているすべての塗装者が削除された場合にのみ消えることができます。 

セクションのカバレッジが 1 つだけの場合、セクションを削除するには、その固有のペインタを削除するだけで十分です。 このようなセクションは、`one[i]`。 

セクションにちょうど 2 つのカバレッジがある場合、責任のある両方のペインタを同時に削除する必要があります。 このようなセクションは、`two[i][j]`。 

セクションに少なくとも 3 つのカバレッジがある場合、2 人のペインターだけを削除しても、すべてのカバレッジを削除することはできません。 

消えたすべてのセクションは、これらのカテゴリのいずれかに正確に属し、どのセクションも 2 回カウントされません。 その結果、$$one[i] + one[j] + two[i][j]$$ペインタを削除した後に失われたセクションの正確な数です`i`そして`j`。 最初に塗った数からこの損失を引くと、正しい答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, q = map(int, input().split())

    segs = []
    diff = [0] * (n + 3)

    for _ in range(q):
        l, r = map(int, input().split())
        segs.append((l, r))
        diff[l] += 1
        diff[r + 1] -= 1

    cover = [0] * (n + 1)
    cur = 0
    total = 0

    for x in range(1, n + 1):
        cur += diff[x]
        cover[x] = cur
        if cur > 0:
            total += 1

    one_pos = [0] * (n + 1)
    two_pos = [0] * (n + 1)

    for x in range(1, n + 1):
        if cover[x] == 1:
            one_pos[x] = 1
        elif cover[x] == 2:
            two_pos[x] = 1

    pref1 = [0] * (n + 1)
    pref2 = [0] * (n + 1)

    for x in range(1, n + 1):
        pref1[x] = pref1[x - 1] + one_pos[x]
        pref2[x] = pref2[x - 1] + two_pos[x]

    one = [0] * q

    for i, (l, r) in enumerate(segs):
        one[i] = pref1[r] - pref1[l - 1]

    ans = 0

    for i in range(q):
        l1, r1 = segs[i]

        for j in range(i + 1, q):
            l2, r2 = segs[j]

            left = max(l1, l2)
            right = min(r1, r2)

            both = 0
            if left <= right:
                both = pref2[right] - pref2[left - 1]

            remaining = total - one[i] - one[j] - both
            if remaining > ans:
                ans = remaining

    print(ans)

if __name__ == "__main__":
    main()
```最初のフェーズでは、差分配列を使用してすべてのフェンス セクションのカバレッジ カウントを計算します。 これにより、すべての間隔を個別にマークすることがなくなり、すべてのカバレッジ カウントが`O(n + q)`時間。 

配列`one_pos`そして`two_pos`カバレッジがちょうど 1 つまたはちょうど 2 つである位置を特定します。 プレフィックス合計により、一定時間での間隔クエリが可能になります。 

値`one[i]`ペインタ内のカバレッジ 1 の位置の数をクエリすることによって取得されます。`i`の間隔。 絵を描くたびに、そのような位置はすべて消えます`i`が削除されます。 

画家のペアの場合、間隔の交差部分のみが問題になります。 カバレッジがちょうど 2 のセクションは、それが両方の画家に属している場合、つまりその交差点にある場合にのみ消えます。 交差点内のカバレッジ 2 位置の数をクエリすると、次のようになります。`two[i][j]`。 

最も一般的な実装上の間違いは、交差点が空である可能性があることを忘れることです。 その場合`both`ゼロのままでなければなりません。 

もう 1 つの簡単な off-by-one エラーは、prefix-sum クエリから発生します。 使用する```
pref[r] - pref[l - 1]
```からインデックス付けされた配列が必要です`1`有効な 0 番目のプレフィックス エントリ。

def solve():

        segs.append((l, r))

    total = 0

        cover[i] = cur

        elif cover[i] == 2:

    for i, (l, r) in enumerate(segs):
