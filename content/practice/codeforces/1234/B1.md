 ## 解決策
 ## 問題の理解

 スマートフォンのチャット インターフェイスの動作をシミュレートしています。 スマートフォンの画面に表示できるのは最大でも$k$会話。 各受信メッセージは、一意の ID で識別される友人から送信されます。 その友人との会話がすでに画面上にある場合、画面は変わりません。 会話が画面上にない場合は上部に挿入され、画面がすでにいっぱいの場合は下部の会話が削除されます。 

入力により得られるのは、$n$、メッセージの数、$k$、画面容量、および一連の$n$受信したメッセージを順番に表すフレンドID。 出力は画面の最終状態です。表示された会話の数と ID のリストが上から下の順に表示されます。 

制約は小さいです。$n, k \le 200$。 これは、私たちには余裕があることを意味します$O(nk)$効率を気にせずにアルゴリズムを構築できます。 高度なデータ構造は必要ありません。 各 ID は非常に大きくなる可能性があります ($1 \le id_i \le 10^9$)、そのため、ID によってインデックス付けされた配列を使用することは現実的ではありません。 代わりに、セットまたはリストを使用して、どの ID が画面上に表示されているかを追跡します。 

メッセージが頻繁に繰り返される場合、微妙な特殊なケースが発生します。 たとえば、次の場合$n = 3$、$k = 2$、メッセージは次のとおりです。$1, 1, 2$、単純な実装では 2 番目のコードが挿入される可能性があります。`1`繰り返しになりますが、ルールでは、会話がすでに表示されている場合、重複しても会話を移動しないことが指定されています。 別のエッジケースは、一意のメッセージの数が決して超えない場合に発生します。$k$; 画面が会話を排除する必要はありませんが、アルゴリズムは順序を正しく維持する必要があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 画面を表すリストを順番に保持します。 受信メッセージごとに、フレンド ID がすでにリストに存在するかどうかを確認します。 そうであれば、私たちは何もしません。 そうでない場合は、前面に挿入します。 リストがサイズを超える場合$k$、最後の要素を削除します。 各操作は問題のルールに直接従うため、これは単純かつ正しいです。 その複雑さは、$O(nk)$なぜなら、それぞれの$n$まで検索する必要があるメッセージ$k$リスト内の要素。 

さらに最適化するための重要な洞察は、リストとセットの両方を維持することです。 セットにより許可されるのは、$O(1)$リストは順序を維持しながら、メンバーシップをチェックします。 これにより、メンバーシップチェックが削減されます。$O(k)$に$O(1)$, しかし、この問題では、入力制約が非常に小さいため、ブルートフォース手法がすでに受け入れられています。 問題の構造 - 小さい$n$そして$k$、常に先頭に挿入することで、単純なリストのシミュレーションが十分に効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*k) | O(k) | 承認済み |
 | リスト + セット | O(n) | O(k) | やりすぎだが正しい |

 ## アルゴリズムのチュートリアル

 1. 空のリストを初期化する`screen`画面上の会話を表現します。 
2. 各メッセージ ID を反復処理します。`id_i`受信メッセージの順序で。 
3. もし`id_i`すでに入っています`screen`, 画面が切り替わらないので次のメッセージに進みます。 
4. それ以外の場合は、長さが正しいかどうかを確認してください。`screen`に等しい`k`。 存在する場合は、次の最後の要素を削除します。`screen`スペースを作るために。 
5.挿入`id_i`の前で`screen`一番上の位置に表示されることを表します。 
6. すべてのメッセージを処理した後、メッセージの長さを出力します。`screen`ID は上から下の順に表示されます。 

なぜそれが機能するのか: リスト`screen`は常に、現在の会話の上から下の順序を表します。 不変: 重複する ID は存在しません。`screen`そしてそのサイズは決して超えることはありません`k`。 前に挿入するルールと、いっぱいになったときに後ろから削除することを組み合わせることで、正しい状態が維持されます。 各決定は問題のルールに直接従うため、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
ids = list(map(int, input().split()))

screen = []

for id_i in ids:
    if id_i in screen:
        continue
    if len(screen) == k:
        screen.pop()
    screen.insert(0, id_i)

print(len(screen))
print(' '.join(map(str, screen)))
```最初の 2 行は入力を効率的に読み取ります。 の`screen`リストは上から下の順序を維持します。 それぞれについて`id_i`, まず重複をチェックします。 画面がいっぱいの場合は、`pop()`一番下の会話を削除します。`insert(0, id_i)`新しい会話を上部に追加します。 長さと内容を出力する`screen`シミュレーションが完了します。 メッセージが繰り返される、または一意のメッセージが少ないなどのエッジケース`k`これらの操作によって自然に処理されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n*k) | n 個のメッセージのそれぞれについて、メンバーシップのチェックと挿入/削除には、最大 k 回の操作がかかる可能性があります。 n,k ≤ 200 であるため許容されます。 
| スペース | O(k) | 最大k件の会話の画面リストのみが保存されます。 |

 このアルゴリズムは、2 秒の時間制限と 256 MB のメモリ制約内に簡単に収まります。$n$そして$k$。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    ids = list(map(int, input().split()))
    screen = []
    for id_i in ids:
        if id_i in screen:
            continue
        if len(screen) == k:
            screen.pop()
        screen.insert(0, id_i)
    return f"{len(screen)}\n{' '.join(map(str, screen))}"

# Provided samples
assert run("7 2\n1 2 3 2 1 3 2\n") == "2\n2 1", "sample 1"
assert run("4 3\n2 3 2 1\n") == "3\n1 3 2", "sample 2"

# Custom cases
assert run("3 2\n1 1 2\n") == "2\n2 1", "duplicate first"
assert run("5 3\n5 4 3 2 1\n") == "3\n1 2 3", "screen fills and evicts sequentially"
assert run("1 1\n10\n") == "1\n10", "single message fits screen"
assert run("6 6\n1 2 3 4 5 6\n") == "6\n6 5 4 3 2 1", "screen never full"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`3 2\n1 1 2\n`|`2\n2 1`| 繰り返されるメッセージを重複なく処理する |
 |`5 3\n5 4 3 2 1\n`|`3\n1 2 3`| 画面が繰り返しいっぱいになった場合の立ち退き命令 |
 |`1 1\n10\n`|`1\n10`| 最小サイズの入力 |
 |`6 6\n1 2 3 4 5 6\n`|`6\n6 5 4 3 2 1`| 画面がいっぱいになりますが、容量を超えることはありません |

 ## 特殊なケース

 すでに画面上に表示されている繰り返しのメッセージはスキップされます。 入力用`3 2\n1 1 2`、 最初`1`が挿入されると、2 番目の`1`すでに表示されているため無視されます。`2`上部に挿入されます。
