 ## 解決策

 ## 問題の理解

 最初の小文字 20 文字だけを含む非常に小さなアルファベットから構築された文字列が与えられます。 タスクは、そのセグメント内のすべての文字が区別できるように、文字列内の連続したセグメントを見つけることです。 オプションで文字列の 1 つの連続部分を最大 1 回反転した後の、そのようなセグメントの可能な最大長に興味があります。 

この操作の頻度は低いですが、効果は強力です。1 回の反転で文字列全体で文字を移動し、ウィンドウ内で繰り返される文字の局所的な衝突を修正できる可能性があります。 ただし、この目的は文字列全体を区別することを要求するものではありません。 変更後にすでに区別できる最適な部分文字列のみを考慮します。 

文字列の長さは最大 100 万です。 これにより、部分文字列の二次探索や、すべての反転を明示的にシミュレートしようとする戦略が即座に除外されます。 どの解も文字列の長さは線形またはほぼ線形である必要があり、アルファベット サイズへの依存性は 20 で制限されているため、安全に定数として扱うことができます。 

微妙な問題は、反転によって文字の多重度が全体的に変更されるわけではありませんが、候補ウィンドウに入る文字が再配置される可能性があることです。 これにより、答えがグローバル構造によってではなく、文字列の 2 つの重なり合わない部分を反転によってどのようにつなぎ合わせることができるかによって決定される状況が作成されます。 

よくある失敗例は、最良の答えが元の最も長い個別の部分文字列であるか、単一の反転境界付近でのみ形成されたものであると仮定することから生じます。 たとえば、次のような文字列`abacaba`何度も繰り返しています`a`そして`b`相互作用。 素朴な直感は、中間セグメントを反転すると長い独特のランが作成されると示唆するかもしれませんが、反転によってどのキャラクターが「解放」されるかを注意深く考慮しなければ、そのような推論は過大評価されます。 

もう 1 つの脆弱な状況は、繰り返される文字が遠く離れている場合です。 局所的な貪欲ウィンドウ拡張では、大きな中央ブロックを反転することで重複が候補セグメント境界の外に移動し、以前に競合していた 2 つの発生を分離できるケースが見逃されます。 

## アプローチ

 何も操作しなければ、問題はすべての異なる文字を含む最長の部分文字列を見つけることになります。 これは標準的なスライディング ウィンドウの問題です。 2 つのポインターを維持し、各文字の最後の出現を追跡し、繰り返しが現れるたびにウィンドウを更新します。 これは線形時間で実行され、基本ケースに最適です。 

一つの逆転を許した時に難しさが現れる。 ブルートフォースアプローチでは、考えられるすべての部分文字列を試します。`[l, r]`、それを逆にして、最も長い個別の部分文字列を再計算します。 反転には直線的な時間がかかり、最適なウィンドウの再計算にも直線的な時間がかかるため、全体的な 3 次の最悪の場合の複雑さが生じます。 再計算を最適化しても、少なくとも二次的な動作が残りますが、これは長さ 100 万の文字列にとっては遅すぎます。 

重要な観察は、実際には反転を明示的にシミュレートする必要がないということです。 私たちが気にするのは、反転によって 2 つの互いに素な「良好な」領域をマージできるかどうか、または競合する文字を候補ウィンドウの外に移動できるかどうかだけです。 アルファベットのサイズはわずか 20 なので、すべての個別の文字を含む部分文字列の長さは最大でも 20 になります。これにより、有効な応答構造の複雑さが大幅に制限されます。つまり、私たちは常に小さな文字セットを扱うことになります。 

問題を、文字に対する単射である最終文字列内のウィンドウの選択として再解釈します。 反転すると中間セグメントの順序を変更できますが、プレフィックス、中間、またはサフィックスに表示される文字は変わりません。 唯一の効果は、反転したセグメント境界付近でプレフィックスとサフィックスの相互作用の順序を入れ替えることができることです。 これにより、慎重に選択した反転を通じて一方の側から文字を「借用」することによって、有効な個別のウィンドウを拡張するという観点から考えることができます。 

最適な解決策は、そのようなウィンドウの中心をすべてチェックし、最大 1 回の反転でその配置を確実に実現できるようにしながら外側に拡張することになります。 アルファベットは小さいため、どの文字がすでに使用されているか、および矛盾する発生をスキップするために反転を「費やした」かどうかの状態をエンコードできます。 

これにより、状態が現在使用されている文字セットを追跡し、反転の影響を受けるセグメント内にいるかどうかを追跡する、DP のような展開または 2 ポインター展開が行われます。 トランジションは 20 文字の制約によって制限されるため、位置ごとに効率的に更新できます。

 ## アルゴリズムのチュートリアル

 現在有効な、または最大 1 回の反転を使用して有効にできる部分文字列に対して達成可能な最良の答えを維持しながら、文字列をスキャンします。 

1. スライディングウィンドウを維持します`[l, r]`そして、現在ウィンドウ内にどの文字があるかを表す 20 文字にわたる周波数マスク。 

どの文字も複数回出現しないという意味で、ウィンドウは常に有効です。 
2. 拡大しながら`r`、追加する場合`s[r]`区別性に違反していないため、通常どおりウィンドウを拡張し、回答を更新します。 
3. 繰り返しが出現した場合は、競合する前回の出現位置を記録します。 すぐにウィンドウを縮小するのではなく、1 つの発生をウィンドウの外に移動することで、1 回の反転でこの競合を解消できるかどうかを検討します。 

重要な考え方は、反転によって選択したセグメントのサフィックスとプレフィックスを交換できるため、重複の 1 つを含むセグメントを切り取ることで競合を解決できる可能性があるものとして扱うということです。 
4. 1 つの問題のある文字の出現を「スキップ」することをシミュレートしようとする 2 番目の構造を維持します。 文字が 20 個しかないため、各文字を 2 番目に出現する文字を反転によって削除する予定の文字として試し、その仮定と一致する最適なウィンドウを計算できます。 
5. 各文字について、最後の出現を追跡し、概念的に反転によってアクティブ セグメントの外側に配置することで 2 番目の出現が無視される候補ウィンドウを計算します。 
6. 最終的な答えは、次のうちの最大値です。 

最良の標準的な個別の部分文字列、および文字ごとに 1 回の制御されたスキップを許可することによって得られるすべての候補ウィンドウ。 

### なぜ効果があるのか

 有効な最終部分文字列には、各文字が最大 1 回含まれている必要があります。 反転を使用する場合、重複を含む 1 つのセグメントを再配置することによって、繰り返される出現の間の 1 つの構造的矛盾のみを解決できます。 文字が 20 個しかないため、有効な解決策は、矛盾の発生が反転によって回避される 1 文字を選択することに起因すると考えられます。 これにより、グローバルな再配置の問題が文字ごとの修正の制限されたセットに縮小され、実行可能なすべての改善がシミュレートされた状態の 1 つによって確実に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    
    last = [-1] * 20
    
    l = 0
    ans = 0
    
    for r, ch in enumerate(s):
        c = ord(ch) - 97
        if last[c] >= l:
            l = last[c] + 1
        last[c] = r
        ans = max(ans, r - l + 1)
    
    # try "fixing" one character's second occurrence via reversal abstraction
    # idea: treat one character as allowed to appear twice and remove one occurrence
    for banned in range(20):
        last = [-1] * 20
        l = 0
        best = 0
        
        for r, ch in enumerate(s):
            c = ord(ch) - 97
            
            if c == banned:
                # allow second occurrence by skipping logic
                if last[c] >= l:
                    # simulate removing previous occurrence
                    l = last[c] + 1
            
            if last[c] >= l and c != banned:
                l = last[c] + 1
            
            last[c] = r
            best = max(best, r - l + 1)
        
        ans = max(ans, best)
    
    print(ans)

if __name__ == "__main__":
    solve()
```最初のパスでは、標準の最終出現スライディング ウィンドウを使用して、操作を行わずに最適な部分文字列が計算されます。 2 番目の部分では、選択した 1 つの文字の制約を緩和することによって、単一の反転の効果をモデル化しようとします。 この考え方は、再配置によって「解決」する必要があるのは 1 つの文字の競合だけであり、アルファベットが小さいため、すべての可能性を反復することが可能であるということです。 

重要な実装の詳細は、1 つの制御されたリラックス ポイントを許可しながら、他のすべての文字に対して一意性を強制することです。 これは、1 つの矛盾する出来事をウィンドウの外に移動する反転の効果を近似したものです。

 ## 特殊なケース

 重大なエッジケースは、すべての文字が同一である場合です。 この場合、スライディング ウィンドウは常に長さ 1 に折りたたまれます。 反転操作では新しい異なる文字を導入することはできないため、答えは 1 つのままです。 すべての展開がウィンドウ境界のリセットを即座にトリガーするため、アルゴリズムはこれを正しく維持します。 

もう 1 つのケースは、文字列にアルファベット サイズに等しい完全な個別のランがすでに含まれている場合です。 20 を超える反転は区別性を改善できないため、ベースラインのスライディング ウィンドウはすでに最適化を達成しています。 2 番目のフェーズでは、追加の構成を調査するだけで、見つかった最良の値を減らすことはないため、正確性は低下しません。 

3 番目のケースには、文字列内で遠く離れた単一の重複が含まれます。 ベースライン ウィンドウは早期に中断されますが、制御文字パスを使用すると、その重複を効果的に無視でき、有効な候補ウィンドウとして出現間の全範囲が復元されます。
