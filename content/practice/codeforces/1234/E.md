 ## 解決策
 ## 問題の理解

 私たちには順序が与えられています`x`長さの`m`。 あらゆる価値観に対して`i`から`1`に`n`、特別な順列を構築します。`p_i = [i, 1, 2, ..., i-1, i+1, ..., n]`この順列が恒等順列と異なるのは、次の理由だけです。`i`前に移動されました。 

順列ごとに、連続する要素間の合計距離を計算する必要があります。`x`それらの要素がその順列内で表示されるとき。 2 つの隣接する値がある場合、`x`地位を占める`a`そして`b`順列では、それらは貢献します`|a-b|`答えに。 

タスクは、すべての順列に対してこの値を出力することです。`p_1, p_2, ..., p_n`。 

制約は、ソリューションを推進する最初のものです。 両方`n`そして`m`到達できる`2·10^5`。 がある`n`さまざまな順列があり、それぞれの答えは以下によって異なります`m-1`からの隣接するペア`x`。 直接計算するには大まかに必要になります`n·m`、これは約になります`4·10^10`最悪の場合の運用。 それは2秒以内ではまったく不可能です。 

順列の構造は非常に特殊です。 すべての順列は、1 つの値を最初の位置に移動することによって恒等式から取得されます。 つまり、ほとんどの位置は変更されず、ある置換インデックスから別の置換インデックスに移動するときに影響を受けるのは距離の小さなサブセットのみです。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
3 3
2 2 2
```すべての隣接するペアは、`(2,2)`、その距離は順列に関係なく常にゼロです。 正しい出力は次のとおりです。```
0 0 0
```隣接する値が異なるものであると想定するソリューションでは、誤って更新が導入される可能性があります。 

考慮する：```
4 2
1 4
```の答えは、`p_1`は`|1-4|=3`。 のために`p_4`、ポジションは`(2,1)`、距離を与える`1`。 1 つの端点が移動された要素と等しい場合、距離は劇的に変化します。 

考慮する：```
5 2
2 3
```ペアに多くの値が含まれることはありませんが、すべての答えは移動された要素が間隔に対してどこにあるかによって決まります。`[2,3]`。 エンドポイントのみを更新し、間隔の影響を無視するアプローチでは、誤った答えが生成されます。 

中心的な課題は、単一の隣接するペアがすべての順列にどのように同時に寄与するかを理解することです。 

## アプローチ

 ブルートフォースの解決策は簡単です。 あらゆる順列に対して`p_i`、すべての値の位置を計算してから、`m-1`隣接するペア`x`対応する距離を合計します。 

順列における位置関数`p_k`は：

-`pos(k)=1`-`pos(v)=v+1`のために`v<k`-`pos(v)=v`のために`v>k`この公式を使用すると、各距離を一定時間で評価できます。 残念ながらまだ残っています`n`順列と`m-1`ペア、につながる`O(nm)`仕事。 両方のパラメータが等しい場合`2·10^5`、操作数は約400億です。 

重要な観察は、合計の答えは隣接するペアの合計であるということです。`x`。 

順列を修正してすべてのペアを評価する代わりに、視点を逆転させます。 隣接するペアを 1 つ取ります`(a,b)`そして、すべての順列にわたってその寄与がどのように変化するかを判断します。 

させて```
g_k(a,b) = |pos_k(a)-pos_k(b)|
```どこ`k`前に移動された値です。 

ほとんどの値については、`k`、距離は恒等順列から変化しません。 ときのみ`k`1 つの端点に等しいか、2 つの端点の間にある場合、距離は変化します。 

これは、単一のペアが置換インデックスの間隔にのみ影響を与えることを意味します。 しかないので、`m-1`ペアを作成すると、各ペアを個別に処理し、その効果を差分配列に蓄積できます。 

恒等置換の答えは簡単に計算できます。```
base = Σ |x_i - x_{i+1}|
```次に、隣接するペアごとに、その寄与がすべての関連する順列の基本応答とどの程度異なるかを計算します。 これらの変更は範囲更新を使用して追加できます。 

問題全体は、置換インデックスの区間加算問題になります。`k`。

 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## 貢献度の計算式の導出

 仮定する`a < b`。 

恒等置換では、寄与は次のようになります。```
b-a
```次に、値の移動を考えてみましょう`k`前へ。 

もし`k=a`、 それから```
pos(a)=1
pos(b)=b
```貢献度は```
b-1
```ベースとの違い：```
(b-1)-(b-a)=a-1
```もし`k=b`、 それから```
pos(a)=a+1
pos(b)=1
```貢献度は```
a
```違い：```
a-(b-a)=2a-b
```もし`a<k<b`、 それから```
pos(a)=a+1
pos(b)=b
```貢献度は```
b-a-1
```違い：```
-1
```その他すべてについて`k`、貢献度は変わりません。 

したがって、1 つのペアが次のように寄与します。```
a-1          at k=a
-1           for a<k<b
2a-b         at k=b
0            elsewhere
```このコンパクトな説明がソリューション全体です。 

## アルゴリズムのチュートリアル

 1.恒等順列の答えを計算します。 

させて```
ans = Σ |x_i - x_{i+1}|
```すべての順列の答えはこの値から始まり、その後修正を受けます。 
2. サイズの異なる配列を作成する`n+3`。 

ID の答えに関連するすべての変更を保存します。 
3. 隣接するすべてのペアを処理する`(u,v)`で`x`。 

もし`u=v`、貢献度は常にゼロであり、更新は必要ありません。 
4. しましょう`a=min(u,v)`そして`b=max(u,v)`。 

導出された式は、順序付けされたエンドポイントのみに依存します。 
5. ポイント更新を追加します。`k=a`。 

修正は`a-1`。 
6. ポイント更新を追加します。`k=b`。 

修正は`2*a-b`。 
7. 範囲更新を追加します。`(a,b)`。 

すべての置換インデックスは厳密に次のとおりです`a`そして`b`受け取ります`-1`。 

これは、移動された値が 2 つのエンドポイントの間に存在し、それらの距離が 1 だけ減少する間隔です。 
8. すべてのペアが処理された後、プレフィックス合計を使用して差分配列を実際の補正に変換します。 
9. あらゆる人にとって`k`から`1`に`n`、出力```
base + correction[k]
```### なぜ効果があるのか

 値の隣接するすべてのペアについて、恒等順列と比較したその距離の正確な変化を明示的に計算します。 上記の導出により、移動された値のすべての可能な位置が網羅されます。`k`。 

ペアは次の 3 つの状況でのみ貢献します。`k`が左端点に等しい場合、`k`が正しいエンドポイントに等しい、または`k`それらの間には厳密に存在します。 更新ルールは、これらのケースを正確にエンコードします。 

合計の答えはすべての隣接するペアからの寄与の合計であるため、線形性によりすべてのペア補正を独立して追加できます。 すべての更新が蓄積された後、修正が並べ替えのために保存されます`k`はすべてのペアの寄与変化の合計に等しく、これは正確に次の差です。`f(p_k)`そしてアイデンティティの答え。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def add_range(diff, l, r, val):
    if l > r:
        return
    diff[l] += val
    diff[r + 1] -= val

def solve():
    n, m = map(int, input().split())
    x = list(map(int, input().split()))

    base = 0
    diff = [0] * (n + 3)

    for i in range(m - 1):
        u = x[i]
        v = x[i + 1]

        if u == v:
            continue

        a = min(u, v)
        b = max(u, v)

        base += b - a

        diff[a] += a - 1
        diff[a + 1] -= a - 1

        if a + 1 <= b - 1:
            add_range(diff, a + 1, b - 1, -1)

        diff[b] += 2 * a - b
        diff[b + 1] -= (2 * a - b)

    cur = 0
    res = []

    for k in range(1, n + 1):
        cur += diff[k]
        res.append(str(base + cur))

    print(" ".join(res))

solve()
```解決策は、恒等順列の答えを計算することから始まります。 これは、他のすべての答えを導き出すベースラインとして機能します。 

隣接するペアごとに、前に導出した 3 つの修正ルールを適用します。 ポイントの更新は、差分配列内の長さ 1 の範囲の更新として実装されます。 間隔`(a,b)`の範囲更新を受け取ります`-1`。 

差分配列は重要です。 これがないと、次の期間にすべてのインデックスが更新されます。`a`そして`b`アルゴリズムは二次式になります。 差分配列は、各間隔の変更を一定の作業に変換します。 

微妙な点の 1 つは、次のアップデートです。`k=b`。 その値は`2a-b`、 ない`a-b`または`a-1`。 これは、次の場合の正確な距離から直接得られます。`b`それ自体が前面に移動されます。 

もう 1 つの簡単な間違いは、連続する等しい値を処理することです。 いつ`u=v`、距離は常にゼロです。 派生式は個別のエンドポイントを想定しているため、完全にスキップする必要があります。 

すべての算術演算は 64 ビット整数内に快適に収まります。 最大の答えは次のとおりです`m·n`、 約`4·10^10`。

 ## 特殊なケース

 次のことを考慮してください。```
3 3
2 2 2
```すべての隣接するペアには同一のエンドポイントがあります。 アルゴリズムは各ペアを即座にスキップします。`u == v`。 更新は適用されず、基本の答えはゼロのままで、すべての置換の答えはゼロになります。```
0 0 0
```次に、次のことを考えてみましょう。```
5 2
1 5
```基本的な答えは`4`。 ペア用`(1,5)`、間隔`(1,5)`受け取ります`-1`、つまり順列`2,3,4`全員が 1 単位を失います。 で`k=5`、特別なエンドポイント補正が貢献します`-3`、答えを与える`1`。 出力は次のようになります。```
4 3 3 3 1
```これにより、適切なエンドポイントが更新されたことが検証されます`2a-b`正しく処理されます。 

最後に次のことを考慮してください。```
5 2
2 3
```基本的な答えは`1`。 

更新内容は次のとおりです。```
k=2 : +1
k=3 : +1
```エンドポイント間に間隔は存在しません。 答えは次のようになります。```
1 2 2 1 1
```これは境界ケースをチェックします。`b=a+1`これにより、間隔更新が誤って空の範囲に適用されることがなくなります。
