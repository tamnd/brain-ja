 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 それぞれのショップには商品価格のリストがあります。 目標は、これらのさまざまな価格をすべて単一の統一価格に置き換えて、すべてのアイテムをこの単一の価格で販売しても、元の価格と比較して総収益が減らないようにすることです。 

言い換えれば、元の総収益が指定されたすべての価格の合計である場合、数値を 1 つ選択する必要があります。`x`販売するような`n`価格のアイテム`x`それぞれが合計収益を示します`n * x`、これは少なくとも元の合計でなければなりません。 そのようなすべての有効な値の中で、`x`、できるだけ小さいものが必要です。 

各クエリは独立しているため、テスト ケースごとにこの計算を繰り返します。 

制約は小さいです。`n ≤ 100`そして`q ≤ 100`。 これは、単一のクエリに対して 3 次またはそれより悪い動作を示すソリューションであっても合格する可能性が高いことを意味します。 ただし、問題の構造は、不必要なシミュレーションを避け、代わりに直接の数学的条件を探す必要があることを示唆しています。 

すべての値が同一である場合、素朴だが重要なエッジ ケースが発生します。 たとえば、すべての価格が`1`、合計は`n`、最低一律価格も`1`。 「最大値の一致」または「要素ごとの切り上げ」を誤って試行する推論は、グローバル制約を無視すると失敗する可能性があります。 

もう 1 つの微妙な失敗例は、値が大きく異なる場合に発生します。 例えば、`[1, 100, 100]`合計があります`201`、正しい均一価格は次のとおりです。`ceil(201/3) = 67`。 最大値や中央値を誤って使用するアプローチでは、制約は個々の値ではなく合計に関するものであるため、間違った答えが得られます。 

## アプローチ

 この問題を考える強引な方法は、考えられるすべての候補の均一価格を試してみることです。`x`。 それぞれについて`x`かどうかを確認します。`n * x ≥ sum(a_i)`。 そのような最小のもの`x`が答えです。 以来`x`最大ですべての要素の合計までの範囲になる可能性がありますが、これには最大約`10^9`最悪の場合、たとえ制約が小さいとしても、これは不要です。 

重要な観察は、条件が配列の合計にのみ依存するということです。 計算すると元の収益が確定します`S = sum(a_i)`。 新たな収入は、`n * x`。 最小の整数が必要です`x`次のような:`n * x ≥ S`これは単純な不等式です。 それを満たす最小の整数は次の上限です。`S / n`。 

これにより、問題は候補の検索からクエリごとに 1 つの算術式を計算することに変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリごとの O(S / n) | お(1) | 概念的には遅すぎる |
 | 最適 | クエリごとに O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 同じ推論を使用して、各クエリを独立して解決します。 

1. 商品の数量を読み取ります`n`現在のクエリの場合。 This defines how many times the new uniform price will be applied in total revenue computation.
 2. Read the array of prices and compute their sum`S`。 これは、元の総収益と一致するか、それを超える必要があることを表します。 
3. 最小の整数を計算します`x`そのような`n * x ≥ S`。 これは、次の整数上限除算を実行することと同等です。`S`による`n`。 
4. この値をクエリに出力します。 

唯一の微妙なステップは、整数の上限分割です。 浮動小数点除算を使用する代わりに、次のように安全に計算します。`(S + n - 1) // n`、精度の問題なく正確性が保証されます。 

### なぜ効果があるのか

 制約`n * x ≥ S`統合後の収益は`x`そしてアイテムの数。 有効な解はこの不等式を満たす必要があり、これより小さい値はこの不等式に違反します。 機能以来`n * x`単調増加`x`、有効な最小の整数はまさにその上限です。`S / n`、ソリューションが必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        a = list(map(int, input().split()))
        s = sum(a)
        ans = (s + n - 1) // n
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションはクエリごとの処理を中心に構成されています。 合計の計算は唯一の意味のある集計ステップであり、他のすべては 1 つの算術変換に帰着します。 整数の除算式は浮動小数点計算を完全に回避し、大きな合計でも正確性を保証します。 

## 実用的な例

 ### 例 1

 入力:```
n = 5
a = [1, 2, 3, 4, 5]
```合計を計算します`S = 15`。 

| ステップ | n | 和 S | 計算 | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | 5 | 15 | (15 + 4) // 5 | 3 |

 出力は`3`。 これにより、総収益が確認されます。`5 * 3 = 15`オリジナルと正確に一致します。 

このトレースは、均等条件が厳しいケースを示しています。これは、最適価格がそれを超えることなく正確に収益を維持することを意味します。 

### 例 2

 入力:```
n = 3
a = [1, 2, 2]
```私たちは計算します`S = 5`。 

| ステップ | n | 和 S | 計算 | 結果 |
 | --- | --- | --- | --- | --- |
 | 1 | 3 | 5 | (5 + 2) // 3 | 2 |

 出力は`2`。 ここで、元の合計は 5 ですが、`3 * 1 = 3`小さすぎるし、`3 * 2 = 6`で十分です。 

これは、切り上げが必要な理由を示しています。床を敷くと収益が過小評価されるからです。

とすれば`n ≤ 100`そして`q ≤ 100`、合計の操作は非常に小さく、十分に制限内です。 単純な実装でも効率的です。

 ## 特殊なケース

 主なエッジケースは次のような場合です`n = 1`。 アルゴリズムは計算します`(a1 + 0) // 1 = a1`、これは正しいです。なぜなら、可能な均一価格は値そのものだけだからです。 

もう 1 つのケースは、すべての値が同一である場合です。 もし`a = [k, k, ..., k]`、 それから`S = n * k`、 そして`(S + n - 1) // n = k`、元の値を正確に保持します。 

さらに興味深いケースは、次のように値が大きく異なる場合です。`a = [1, 100, 100]`。 ここ`S = 201`、 そして`n = 3`したがって、計算により次のようになります。`67`。 手動で確認すると、`3 * 66 = 198`小さすぎる一方で、`3 * 67 = 201`要件を満たしており、天井の動作が正しいことが確認されています。
