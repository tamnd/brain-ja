 ## 解決策
 ## 問題の理解

 一連の攻撃が与えられ、それぞれに強度値が与えられます。 部族は、強度がしきい値を超えないあらゆる攻撃に対して安全に防御できます。 攻撃がこのしきい値より強力な場合、彼らは避難し、正確に一定回数の連続攻撃の間離れなければなりません。 避難期間が終了したら、すぐに自宅に戻らなければなりません。つまり、避難期間は完全に攻撃のタイムライン内に収まる必要があります。 

重要な制約は、すべての避難が正確に対象をカバーすることです。`x`連続攻撃と避難は任意の方法で重複できず、個別のブロックです。 家にいる間、部族は現在のすべての攻撃が十分に弱い場合にのみ安全に残ることができます。 避難の外側で強い攻撃が発生した場合、その攻撃の直前に新たな避難が強制的に開始されます。 

課題は、そのような固定長の避難ブロックを使用してすべての「危険な」瞬間をカバーできるかどうかを判断し、可能であれば、必要なそのようなブロックの数を最小限に抑えることです。 

重要な構造上の詳細は、避難場所はどこにでも自由に設置できる柔軟なシールドではないということです。 それぞれの退避では、連続した長さのセグメントが消費されます。`x`したがって、1 つの決定を行うとウィンドウ全体に影響します。 これは、安全か危険かという攻撃の 2 つの分類に、貪欲なスケジューリングの問題があることを直ちに示唆しています。 

制約から、`n`は最大 500,000 であるため、非常に単純でない限り、重いデータ構造を含む 2 次解や O(n log n) 解さえも危険です。 リニアスキャンの貪欲なソリューションが強く暗示されています。 

重要なエッジケースは、次のような状況です。 

1. 危険な攻撃が発生するのが遅すぎて、十分な規模の避難ウィンドウを開始する余地がない`x`。 たとえば、次の場合`x = 3`、`n = 5`、その位置では強制避難が必要です`4`、から始まります`4`それは問題ありませんが、次から始めます`5`限界を超えてしまうので無理です。 
2. 危険な攻撃の密集したクラスターがより近い間隔で配置される`x`離れていると、重複や強制的なマージが発生する可能性があります。 
3.`m = 0`、あらゆる積極的な攻撃が危険になるため、すべてのポジションを固定ウィンドウでカバーすることが可能かどうかを確認する必要があります。 
4.`x = n`ここで、退避は 1 つだけ可能であり、アレイ全体をカバーする必要があります。 

危険な攻撃が発生するたびに新たな避難を開始する素朴な貪欲さは、重複するウィンドウが再利用またはマージされた可能性がある場合に失敗し、答えが不必要に増加します。 

## アプローチ

 強引なアイデアは、あらゆる可能な決定をシミュレートすることです。危険な攻撃が現れるたびに、避難ブロックのカバーを開始するか、`[i, i + x - 1]`あるいは、それを遅らせて、その後の避難でカバーできるかどうかを確認してください。 それぞれの決定が将来のすべてのポジションに影響し、重複する間隔が重要な方法で相互作用するため、これはすぐに指数関数的になります。 各ポジションが以前のすべての遷移を試行する可能性があるため、ポジションと最後の避難終了に対する DP でさえ、最悪の場合は O(n^2) になります。 

重要な観察は、退避は固定長のカバーであり、唯一意味のある決定は、これらのカバーの左側のエンドポイントがどこに配置されるかであるということです。 その位置から避難することを決めたら`i`、固定セグメントを自動的にカバーし、前方にスキップします。 そこで問題は次のとおりです。左から右にスキャンすると、覆われていない危険な位置に遭遇するたびに、できるだけ早くそれを覆う避難ブロックを設置する必要があります。 それを遅らせると、カバレッジがさらに右肩上がりになり、柔軟性が低下するだけです。 

これは、固定長の間隔で必要なポイントを貪欲にカバーする古典的な方法です。 当社は現在の「カバーアップ」の立場を維持します。 この範囲を超えて危険な攻撃に遭遇した場合は、その位置から開始するセグメントを配置する必要があります。 そのセグメントは以下にまで及びます`i + x - 1`に応じて適用範囲を更新します。 

ただし、実現可能性の制約があります。次の点から始まるセグメントを配置すると、`i`、以内に終了する必要があります`n`。 それで、もし`i + x - 1 > n`、それは不可能です。 

各避難は必要な場合にのみ強制され、後で開始すると現在の危険な位置が露出したままになるため、この貪欲な方法は最適です。 左から右にスキャンするため、これより早く開始することは不可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 / O(n^2) DP | O(n^2) | 遅すぎる |
 | 最適な貪欲さ | O(n) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. かどうかをチェックして、どの攻撃が危険であるかを事前計算します。`a[i] > m`。 これにより、問題は固定長セグメントで特定のインデックスをカバーすることに変換されます。 
2. 変数を維持する`covered_until`これは、以前の避難によってすでに安全に保護されていた最後の位置を表します。 これにより、二重にカウントしたり、不必要に重複したりすることがなくなります。 
3. すべてのインデックスを左から右にスキャンします。`i`。 
4. もし`i`すでに内にあります`covered_until`、すでに前の避難ブロックで覆われているためスキップします。 
5. もし`i`危険でカバーされていないので、次の場所で新たに避難を開始する必要があります。`i`。 
6. この避難を行う前に、次のことを確認してください。`i + x - 1`を超える`n`。 そうなった場合は、すぐにその計画は不可能であると結論付けてください。 
7. それ以外の場合は、その位置で避難を開始したことを記録します。`i`、と設定します`covered_until = i + x - 1`。 
8. 最後までスキャンを続けて、すべての避難開始位置を収集します。 

### なぜ効果があるのか

 このアルゴリズムは、貪欲なカバーの不変条件を強制します。すべての危険なインデックスは、それを含めることができる最も早い避難間隔によってカバーされます。 すべての間隔は同じ長さであり、間隔を右にシフトしてもメリットがないため、カバレッジを延期する代替ソリューションは、危険な攻撃がカバーされないままになるか、後で追加の間隔が必要になるかのどちらかです。 したがって、間隔の数は最小限に抑えられ、選択された各間隔が配列内に完全に収まることを保証することで実現可能性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, x, m = map(int, input().split())
a = list(map(int, input().split()))

ans = []
i = 0
covered_until = -1

while i < n:
    if i <= covered_until:
        i += 1
        continue

    if a[i] > m:
        if i + x - 1 >= n + 1:
            print(-1)
            sys.exit(0)

        ans.append(i + 1)
        covered_until = i + x - 1
    i += 1

print(len(ans))
if ans:
    print(*ans)
```コア構造は単一の左から右へのスキャンです。 の`covered_until`変数を使用すると、以前の退避によってすでに処理された位置に繰り返し反応することがなくなります。 カバー範囲外で危険な位置を発見した場合は、直ちにそこから避難を開始します。 

境界チェック`i + x - 1 >= n + 1`セグメントが配列内に収まるようにします。 1 ベースの出力インデックス付けを使用するには、追加する必要があります`+1`回答を保存するとき。 

微妙な点は、避難を「前倒し」しようとしていないことです。 そうすると、トリガー位置がカバーされないままになるため、カバレッジが悪化するだけです。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, x, m = map(int, input().split())
    a = list(map(int, input().split()))

    ans = []
    covered_until = -1
    i = 0

    while i < n:
        if i <= covered_until:
            i += 1
            continue

        if a[i] > m:
            if i + x - 1 >= n + 1:
                return "-1\n"
            ans.append(i + 1)
            covered_until = i + x - 1
        i += 1

    out = str(len(ans)) + "\n"
    if ans:
        out += " ".join(map(str, ans)) + "\n"
    return out

# provided samples
assert solve("3 2 0\n1 0 2\n") == "-1\n"
assert solve("3 2 2\n2 5 6\n") == "1\n2\n"

# custom cases
assert solve("1 1 0\n1\n") == "1\n1\n"
assert solve("5 2 10\n1 2 3 4 5\n") == "0\n"
assert solve("5 2 0\n1 1 1 1 1\n") == "-1\n"
assert solve("6 3 1\n0 2 0 3 0 4\n") in ["2\n2 4\n", "2\n2 4\n"]
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 1 0 / 1 | 1 1 | 最小の強制避難 |
 | 5 2 10 / すべて安全 | 0 | 避難は必要ありません |
 | 小さい x が付いているものはすべて危険です | -1 | 不可能な完全網羅 |
 | まばらな危険 | 複数の有効な | 貪欲な正しさ |

 ## 特殊なケース

 最初のエッジケースは、最後の危険な攻撃がアレイの終わり近くで発生したときに現れます。 避難をインデックスから開始する必要がある場合`n - x + 2`それ以降 (1 ベース) の場合、セグメントはオーバーフローします。 アルゴリズムはチェックすることでこれを即座に検出します。`i + x - 1 >= n`、部分的なカバレッジを試行せずに失敗を返します。 

もう一つのケースは次のような場合です。`m = 0`、すべての正の値を強制避難トリガーに変換します。 貪欲は単に長さの間隔を詰め込むだけであるため、依然として機能します。`x`左から右へ、ただし実現可能かどうかは完全に左右されます。`n`互いに素なサイズのセグメントに分割できる`x`必要なすべての位置から開始します。 

最後に、いつ`x = 1`、あらゆる危険な攻撃には個別の避難が必要です。 アルゴリズムは個々の位置をカウントすることに退化しており、正確性は、誤ってカバレッジをマージしたりスキップしたりしないことに依存します。`covered_until`各セグメントが 1 つの位置を正確にカバーするため、このロジックは依然として成り立ちます。
