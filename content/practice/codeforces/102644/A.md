 ## 解決策
 ## 問題の理解

 この問題は、気分が幸せと悲しみの 2 つの状態しか考えられない人のことを表しています。 毎秒、確率で今の気分が変わるかも`p`、または確率で同じまま`1 - p`。 私たちは幸せな状態から始めて、その人がその後再び幸せになる確率を見つける必要があります。`n`秒。 

入力には、シミュレートする秒数と、1 秒間に気分が変化する確率が含まれます。 必要な出力は、これらの結果を経て幸福になる最終的な確率です。`n`トランジション。 

の値`n`到達できる`10^9`、これにより、毎秒のシミュレーションが即座に除外されます。 直接シミュレーションでは 1 秒あたり 1 回の操作が必要となり、線形ソリューションでも最悪の場合は 10 億回の更新が必要になります。 確率は単純な 2 状態構造を持っているため、ソリューションでは反復的な遷移を効率的に処理し、演算の数を比例から比例に減らす方法を使用する必要があります。`n`のビット数に比例する`n`。 

実装上の主な落とし穴は、次の値が大きいことに起因します。`n`そして確率を正しく扱うことからも。 たとえば、入力の場合`1 0.7`、答えは`0.3`なぜなら、1秒後も幸せでいる唯一の方法は、気分を変えないことだからです。 不注意な実装は戻ってくる可能性があります`0.7`切り替え確率を最終的なハッピー確率として扱うことによって。 

もう 1 つのよくある間違いは次のような場合に発生します。`n`は均等です。 入力用`2 0.1`、答えは`0.82`, なぜなら、2回切り替わるか、まったく切り替わらない場合、気分は幸せだからです。 毎秒変化しない確率のみを考慮するソリューションでは、次の計算が行われます。`0.81`そして、偶数回切り替えた後に幸福に戻る道を逃します。 

## アプローチ

 簡単なアプローチは、毎秒幸せになる確率と悲しい気持ちになる確率を追跡することです。 まず、幸せになる確率は、`1`そして悲しい確率は`0`。 毎秒、遷移ルール​​を使用して両方の値を更新します。 現在の幸せな確率が`h`そして悲しい確率は`s`、すると、次に幸せな確率は`h * (1 - p) + s * p`、次の悲しい確率は`h * p + s * (1 - p)`。 

この方法は確率遷移に直接従うため、正しいです。 問題はトランジションの回数です。 いつ`n`は`10^9`、これには 10 億回の更新が必要ですが、これは利用可能な時間をはるかに超えています。 

重要な観察は、毎秒同じ変換が確率のペアに適用されるということです。 同じ変換を何度も繰り返す場合は、まさに行列のべき乗が役立つ状況です。 1 つの遷移を 2 行 2 列の行列として表し、その行列をべき乗することができます。`n`2進累乗を使用します。 

各秒が同じ遷移ルール​​の独立した適用であるため、ブルート フォースは機能しますが、秒数が大きくなりすぎると失敗します。 遷移自体が行列として表現できるという観察により、すべてを適用できます。`n`対数時間での遷移。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | お(1) | 遅すぎる |
 | 最適 | O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 1 秒間の気分の変化を表す遷移マトリックスを作成します。 

現在の状態が列ベクトルとして表される場合`[happy, sad]`、1 つのトランジションで次のように変更されます。```
[1-p  p] [happy]
[ p  1-p] [sad]
```この行列には、2 つの状態の間で考えられるすべての遷移確率が含まれています。 
2. この遷移行列をべき乗します。`n`2進累乗を使用します。 

行列に状態ベクトルを乗算する代わりに`n`何度も、行列を二乗することを繰り返します。 ちょっとしたとき`n`が設定されている場合、その二乗行列が最終的な答えに寄与します。 
3. 結果の行列を初期状態に適用します。 

初期状態は`[1, 0]`なぜならその人は幸せになり始めるからです。 に累乗した行列を乗算した後、`n`の乗、結果として得られるベクトルの最初の成分は、幸せになる確率です。 

なぜ効果があるのか:

 遷移行列は、プロセスの 1 秒を正確に表します。 行列の乗算は遷移を結合するため、行列自体を乗算します。`n`回はトランジションの実行を表します`n`回。 2 進累乗では、二乗を繰り返して同じ行列のべき乗を計算します。これにより、正確な数学的意味が維持され、演算数が削減されます。 初期状態ベクトルは既知であるため、最後の乗算により、すべての遷移後に幸せになる正確な確率が抽出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def multiply(a, b):
    return [
        [
            a[0][0] * b[0][0] + a[0][1] * b[1][0],
            a[0][0] * b[0][1] + a[0][1] * b[1][1],
        ],
        [
            a[1][0] * b[0][0] + a[1][1] * b[1][0],
            a[1][0] * b[0][1] + a[1][1] * b[1][1],
        ],
    ]

def power(matrix, n):
    result = [[1.0, 0.0], [0.0, 1.0]]
    while n > 0:
        if n & 1:
            result = multiply(result, matrix)
        matrix = multiply(matrix, matrix)
        n >>= 1
    return result

def solve():
    n, p = input().split()
    n = int(n)
    p = float(p)

    transition = [
        [1.0 - p, p],
        [p, 1.0 - p],
    ]

    result = power(transition, n)

    answer = result[0][0]
    print("{:.10f}".format(answer))

solve()
```の`multiply`関数は 2 つの 2 x 2 行列の乗算を実行します。 行列は常にこのように小さいため、4 つの式を直接記述することで不必要なループを回避できます。 

の`power`関数はゼロ遷移の適用を表すため、単位行列で始まります。 2 進累乗中に、設定されたすべてのビットが`n`対応する遷移行列の累乗を答えに加算します。 各ビットの後で行列を二乗することで、広い範囲の遷移をスキップできます。 

最後の行列はすべてを表します。`n`数秒間の動き。 初期状態なので、`[1, 0]`、結果の行列の最初の列のみが重要であり、位置の値が重要です。`[0][0]`ハッピーエンドになる確率です。 

必要な誤差は次のとおりであるため、浮動小数点精度で十分です。`10^-6`。 Python の整数はべき乗の結果に関与しないため、オーバーフローの心配はありません。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    def multiply(a, b):
        return [
            [
                a[0][0] * b[0][0] + a[0][1] * b[1][0],
                a[0][0] * b[0][1] + a[0][1] * b[1][1],
            ],
            [
                a[1][0] * b[0][0] + a[1][1] * b[1][0],
                a[1][0] * b[0][1] + a[1][1] * b[1][1],
            ],
        ]

    def power(matrix, n):
        result = [[1.0, 0.0], [0.0, 1.0]]
        while n:
            if n & 1:
                result = multiply(result, matrix)
            matrix = multiply(matrix, matrix)
            n >>= 1
        return result

    n, p = sys.stdin.readline().split()
    n = int(n)
    p = float(p)
    m = [[1 - p, p], [p, 1 - p]]
    ans = power(m, n)[0][0]

    sys.stdin = old_stdin
    return "{:.10f}".format(ans)

 ## 特殊なケース

 1秒の場合`1 0.7`、アルゴリズムは行列を作成します。```
[0.3 0.7]
[0.7 0.3]
```指数は 1 なので、行列は 2 乗されません。 答えは左上の値です。`0.3`これは、1 回の移行後も幸せなままであることを正しく表しています。 

2秒の場合`2 0.1`、指数はバイナリ値で表されるため、アルゴリズムは遷移行列を 2 乗します。`10`。 2 乗行列には、2 回スイッチングする場合とまったくスイッチングしない場合を含む、すべての 2 ステップ パスの結合確率が含まれます。 左上の値は次のようになります。`0.82`。 

次のような非常に大きな値の場合、`1000000000 0.5`、すべての遷移には、変化または維持される確率が等しくなります。 正の秒数が経過すると、幸せになる確率は正確に次のようになります。`0.5`。 2 進累乗は、秒を 1 つずつ繰り返すことなく、この答えに到達します。 

次のような非常に小さな確率の場合、`10 0.000001`、乗算を繰り返すと、不注意に実装すると精度が失われる可能性があります。 マトリックス手法では、標準の浮動小数点演算で計算を維持し、ほぼ等しい大きな値の減算を回避して、必要な許容誤差内の結果を生成します。
