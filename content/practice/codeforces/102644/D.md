 ## 解決策
 # 問題の理解

 この問題では、頂点に次の番号が付けられた有向グラフが得られます。`1`に`n`そして、正確に使用する可能なウォークの数を尋ねます`k`有向エッジ。 ウォークでは頂点とエッジが再利用される可能性があるため、タスクは単純なパスに関するものではありません。 開始頂点と終了頂点のすべての選択肢が答えに含まれます。つまり、正確に接続された有効な頂点シーケンスをすべてカウントします。`k`トランジション。 結果はモジュロで出力する必要があります`1,000,000,007`。 

入力サイズは、グラフ自体は小さいが、パスの長さは非常に大きくなる可能性があるという観察に基づいて設計されています。 頂点の数は最大です`100`したがって、頂点数の三次作業を伴うアルゴリズムは合理的です。 しかし、`k`到達できる`10^9`これにより、パスを一度に 1 ステップずつ処理する動的プログラミング ソリューションは除外されます。 長さの答えを計算する単純な再帰`1, 2, ..., k`前後が必要になります`10^11`行列演算を考慮する前でも遷移が発生するため、一般的なコンテストの制限に収まりません。 

いくつかのケースでは、単純な実装が簡単に壊れてしまいます。 もし`k = 1`、答えは単に有向エッジの数です。 例えば：```
3 2 1
1 2
2 3
```答えは`2`、散歩だけなので。`1 -> 2`そして`2 -> 3`。 長さゼロのパスの答えを初期化する実装では、誤って 3 つの単一頂点もカウントしてしまう可能性があります。 

サイクルを含むグラフも重要なケースです。```
3 3 2
1 2
2 3
3 1
```答えは`3`、有効な散歩は次のとおりであるため、`1 -> 2 -> 3`、`2 -> 3 -> 1`、 そして`3 -> 1 -> 2`。 頂点の再訪問が許可されているため、訪問済みの配列を使用した深さ優先検索では、これらのウォークが誤って削除されてしまいます。 

エッジのないケースも処理する必要があります。```
2 0 5
```答えは`0`。 すべて 1 のベクトルから開始し、遷移が不可能であることを忘れた解は、誤った正の値を返します。 

# アプローチ

 直接的なアプローチは、長さによってパスをシミュレートすることです。 させて`dp[v]`現在の長さの頂点で終了するウォークの数を表します`v`。 最初は、長さが 0 の場合、すべての頂点が開始点になる可能性があるため、各頂点は 1 つの空のウォークに寄与します。 追加のエッジごとに、すべての発信エッジを追跡してカウントを更新します。 これは正しいです。なぜなら、歩くたびに`i + 1`長いウォークを延長することによって形成されます`i`もう一つのエッジで。 

問題は次の値です。`k`。 1 回の更新でエッジを調べる必要があり、更新の数は`k`。 最悪の場合、次のような事態に陥る可能性があります。`n(n - 1)`エッジがあるため、作業はおよそ`10^9 * 10^4`、利用可能な時間を大幅に超えています。 

便利な構造は、1 つの遷移を繰り返し適用することが、まさに行列のべき乗の設計目的であるということです。 グラフを隣接行列として表すことができます。`A`、 どこ`A[i][j]`頂点からの直接エッジの数を示します`i`頂点へ`j`。 この問題では複数のエッジがないため、値は 0 または 1 のみです。 

行列を乗算するとき、エントリは`(i, j)`の`A^2`からの 2 つのエッジ ウォークの数をカウントします。`i`に`j`。 同じ推論がより高次のべき乗にも当てはまります。`A^k`パスの長さに対するすべての答えが含まれています`k`。 以来`k`が大きい場合、2 進累乗により行列の乗算の数が減ります。`k`に`log(k)`。 

最終的な答えは、次のすべてのエントリの合計です。`A^k`なぜなら、考えられるすべての開始頂点と終了頂点のペアが合計数に寄与するからです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k * m) | O(n) | 遅すぎる |
 | 最適 | O(n3 log k) | O(n²) | 承認済み |

 # アルゴリズムのチュートリアル

 1. 隣接マトリックスの構築`A`。 からのすべての有向エッジに対して、`u`に`v`、 セット`A[u][v] = 1`。 このマトリックスは、グラフ内の 1 ステップの動きを表します。 
2. コンピューティング`A^k`2進累乗を使用します。 現在のビットの場合、`k`が設定されている場合、解答行列に現在のべき乗を乗算します。`A`。 それから正方形`A`次のビットの行列を準備します。 これが機能するのは、すべての整数累乗が 2 の累乗の組み合わせとして表現できるためです。 
3. べき乗が終了したら、結果の行列のすべての要素を加算します。 各エントリは 1 つの順序付けされた頂点ペア間のウォーク数を表すため、それらの合計がウォークの総数になります。 

なぜ機能するのか: 重要な不変条件は、いくつかのビットを処理した後、`k`、累積された行列は、 のバイナリ表現からすでに選択された 2 のすべてのべき乗の積に等しくなります。`k`。 2 つの行列を結合するとウォークの 2 つの連続した部分が結合されるため、行列の乗算ではパス カウントの意味が保持されます。 したがって、二乗を繰り返すと、経路長の行列が作成されます。`1, 2, 4, 8`など、必要なものを乗算すると、長さの行列が正確に得られます。`k`。 

# Python ソリューション```python
import sys

input = sys.stdin.readline

MOD = 10 ** 9 + 7

def multiply(a, b, n):
    res = [[0] * n for _ in range(n)]
    for i in range(n):
        for k in range(n):
            if a[i][k]:
                aik = a[i][k]
                for j in range(n):
                    res[i][j] = (res[i][j] + aik * b[k][j]) % MOD
    return res

def solve():
    n, m, k = map(int, input().split())

    mat = [[0] * n for _ in range(n)]
    for _ in range(m):
        a, b = map(int, input().split())
        mat[a - 1][b - 1] = 1

    ans = [[0] * n for _ in range(n)]
    for i in range(n):
        ans[i][i] = 1

    while k:
        if k & 1:
            ans = multiply(ans, mat, n)
        mat = multiply(mat, mat, n)
        k >>= 1

    result = 0
    for row in ans:
        result += sum(row)
        result %= MOD

    print(result)

if __name__ == "__main__":
    solve()
```隣接行列は、開始頂点を表す行と終了頂点を表す列で保存されます。 乗算関数は行列乗算の定義に従い、中間頂点を選択します。`k`散歩を 2 つの連続した部分に分割することを意味します。 

恒等行列は乗算の中立要素を表すため、最初の答えとして使用されます。 のバイナリ表現の場合、`k`にはまだ処理されたビットが含まれておらず、べき乗も選択されていないため、累積された積が恒等として開始される必要があります。 

乗算ルーチンは、左側の行列からゼロのエントリをスキップします。 多くのグラフはまばらであるため、これにより、必要な三次最悪のケースを維持しながら、実際には不必要な作業が回避されます。 Python の整数はすでに任意の精度をサポートしていますが、すべての値は剰余化されます。`MOD`乗算中に数値を小さく保つため。

# エッジケース

 のために`k = 1`、アルゴリズムは不必要な拡張を実行しません。 2 進累乗では元の隣接行列がすぐに使用され、すべてのエントリを合計すると、既存のエッジが正確にカウントされます。 入力時:```
3 2 1
1 2
2 3
```行列には 2 つの 1 が含まれるため、出力は次のようになります。`2`。 

循環グラフの場合、行列の乗算は訪問した情報を保存せずに遷移をカウントするため、頂点の再訪問は自然に処理されます。 の上：```

```正方行列には、可能な 2 つのエッジ ウォークが 3 つ含まれます。 再訪問をブロックするグラフ走査では、それらすべてが失われます。 

エッジのないグラフの場合:```

```隣接行列は完全にゼロです。 すべての乗算ではゼロが維持されるため、最終的な合計もゼロになります。 これにより、頂点の存在がウォークの存在を暗示するかのように扱われることが回避されます。
