 ## 解決策
 ## 問題の理解

 大文字と疑問符の文字列を維持します。 疑問符は、後で任意の大文字の英字になる可能性があります。 文字列を左から右に読むと、リマッ​​クの気分が変わります。幸せと悲しみの 2 つの状態しかありません。 目的は、文字列全体が処理された後、すべての疑問符が何回置換されたときに Limak が満足するかを数えるということです。 単一文字が更新されるたびに、同じカウントを再度出力する必要があります。 制約は大きく、文字列の長さと更新数は両方とも 200,000 に達する可能性があるため、更新のたびに文字列全体をスキャンするソリューションでは、最悪の場合、約 40000000000 回の操作が実行されることになります。これは、通常のコンテストの制限に収まる量をはるかに超えています。 問題の説明と制限は Codeforces Gym 102644H からのものです。 

重要なのは、ムードには 2 つの状態しかないということです。 プレフィックスの履歴全体を覚える必要はなく、セグメントが入ってくるムードを外向きのムードに変換する方法が何通りあるかだけを覚えておく必要があります。 この小さな状態空間により、答えを動的に維持できるようになります。 

よくある間違いは、疑問符を独立して扱い、個別に適切な文字のみをカウントすることです。 文字は現在の気分を通じて相互作用するため、これは失敗します。 たとえば、次の文字列を使用すると、`A?`、正解は`6`。 最初`A`幸せから悲しみに変わるので、2 番目の文字は気分を再び幸せにする必要があります。 各位置で有効な文字を個別にカウントする不用意な解決策では、その依存関係を見逃してしまいます。 

もう 1 つのエッジ ケースは、セグメントがまったく影響を及ぼさない場合です。 入力の場合:```
1 1
B
1 A
```出力は次のとおりです。```
19
18
```

`B`は雰囲気を変えない手紙ですが、`A`それを裏返します。 フリップのみをカウントし、ニュートラルな選択肢の数を無視するソリューションでは、誤った結果が得られます。 

3 番目のエッジ ケースは、疑問符のみで構成される文字列です。 のために：```
2 0
??
```答えは`403`。 最初の文字がリマクを悲しませ、2 番目の文字が気分を修復する組み合わせを含め、考えられるすべての文字のペアを考慮する必要があります。 現在正常なプレフィックスの数を追跡するだけの方法では、これらの可能性が失われます。 

## アプローチ

 ブルートフォースの解決策は簡単です。 すべての疑問符について、26 文字すべてを試し、気分の変化をシミュレートし、幸せな状態で終わる置き換えを数えます。 これは、可能な文字列のセットを正確にチェックするため、正しいです。 ただし、疑問符が 200,000 個ある場合、取り得る文字列の数は`26^200000`したがって、それらのごく一部を生成することさえ不可能です。 

より良い方向性は、すべてのキャラクターが 2 つの状態の間の遷移のみを実行することを観察することで得られます。 文字列のセグメントは 2 行 2 列の行列で表すことができます。 行は開始ムードを表し、列は最終ムードを表し、各値はその移行を可能にする置換の数を格納します。 2 つのセグメントが結合されると、最初のセグメントが中間のムードを選択し、2 番目のセグメントがそこから継続するため、それらの行列が乗算されます。 

1 つの文字には小さな固定マトリックスがあります。 たとえば、疑問符は 26 個の可能な文字すべてを考慮し、すべての文字の寄与を適切な遷移に追加します。 文字列全体がこれらの行列の積になります。 更新は 1 つの位置にのみ影響するため、セグメント ツリーは範囲の積を保存し、更新によって影響を受けるノードの対数のみを再計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(26^x * n) ここで、x は疑問符の数です | O(n) | 遅すぎる |
 | 最適 | O(n) ビルド後の更新ごとに O(log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各文字を 2 行 2 列の遷移行列として表します。 最初の行と列は開始時の幸せな状態または悲しい状態に対応し、2 番目の次元は終了時の状態を表します。 セル内の値は、そのトランジションを作成する文字の選択肢の数です。 
2. 各リーフに 1 文字の行列を格納するセグメント ツリーを構築します。 内部ノードには 2 つの子の積が保存されます。 行列乗算が使用されるのは、左側の子が最初に何が起こるかを記述し、右側の子がその後に何が起こるかを記述するためです。 
3. 最初の答えは、幸せに始まり幸せに終わる方法の数です。 これは、ツリーのルートにある happy から happy までの行列エントリです。 
4. 更新のたびに、変更された文字のリーフ マトリックスを置き換えます。 ルートに到達するまですべての祖先を再計算します。 1 つの位置に依存するノードは O(log n) のみなので、更新は高速です。 
5. パスを再構築した後、ルート行列に格納されている新しい happy to happy 値を出力します。 

これが機能する理由: セグメント ツリーの不変条件は、すべてのノードがその区間の正確な遷移行列を格納することです。 葉は 1 つの文字を直接表すため、正しいです。 2 人の子が正しい場合、それらの行列を乗算すると、左の区間の後のすべての可能なムードと、右の区間までのすべての継続が考慮されるため、親も正解になります。 帰納法により、ルートは文字列全体を表し、その happy to happy エントリは正確に必要な数になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def multiply(a, b):
    return [
        [
            (a[0][0] * b[0][0] + a[0][1] * b[1][0]) % MOD,
            (a[0][0] * b[0][1] + a[0][1] * b[1][1]) % MOD
        ],
        [
            (a[1][0] * b[0][0] + a[1][1] * b[1][0]) % MOD,
            (a[1][0] * b[0][1] + a[1][1] * b[1][1]) % MOD
        ]
    ]

def char_matrix(c):
    res = [[0, 0], [0, 0]]
    for x in range(26):
        ch = chr(ord('A') + x)
        if ch in "AEIOU":
            res[0][1] += 1
            res[1][0] += 1
        elif ch == "H":
            res[0][0] += 1
            res[1][1] += 1
        elif ch in "SD":
            res[0][1] += 1
            res[1][1] += 1
        else:
            res[0][0] += 1
            res[1][1] += 1
    if c != "?":
        res = [[0, 0], [0, 0]]
        if c in "AEIOU":
            res[0][1] = 1
            res[1][0] = 1
        elif c == "H":
            res[0][0] = 1
            res[1][1] = 1
        elif c in "SD":
            res[0][1] = 1
            res[1][1] = 1
        else:
            res[0][0] = 1
            res[1][1] = 1
    return res

def solve():
    n, q = map(int, input().split())
    s = list(input().strip())

    size = 1
    while size < n:
        size *= 2

    tree = [[[1, 0], [0, 1]] for _ in range(2 * size)]

    for i, c in enumerate(s):
        tree[size + i] = char_matrix(c)

    for i in range(size - 1, 0, -1):
        tree[i] = multiply(tree[i * 2], tree[i * 2 + 1])

    ans = [str(tree[1][0][0])]

    for _ in range(q):
        i, c = input().split()
        i = int(i) - 1
        pos = size + i
        tree[pos] = char_matrix(c)
        pos //= 2
        while pos:
            tree[pos] = multiply(tree[pos * 2], tree[pos * 2 + 1])
            pos //= 2
        ans.append(str(tree[1][0][0]))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```行列乗算関数は、2 つの連続する間隔を結合します。 左側の間隔が右側の間隔より前に読み取られるため、順序は重要です。 乗算の順序を逆にすると、文字列が逆方向に記述されます。 

の`char_matrix`この関数は、固定文字と疑問符の両方を処理します。 疑問符の場合、考えられるすべての大文字で始まり、その遷移が累積されます。 状態のインデックス付けは状態を想定します`0`幸せな状態を意味します`1`は悲しいことを意味するため、最終的な答えは常に次の場所に保存されます。`[0][0]`。 

セグメント ツリーは、インデックス作成を簡素化するために 2 のべき乗のサイズを使用します。 余分なリーフは空のセグメントを表し、空のセグメントを乗算しても遷移数が変化しないため単位行列を使用します。 Python の整数はオーバーフローしませんが、すべての乗算結果は剰余化されます。`10^9+7`値を小さく保つためです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q log n) | ツリーを構築すると、すべてのキャラクターが 1 回変更され、更新のたびにルートからリーフへのパスが 1 つ変更されます。 |
 | スペース | O(n) | セグメント ツリーには、各ノードに一定サイズの行列が格納されます。 |

 この制約では 200,000 件の更新を処理する必要があるため、対数更新が必要です。 行列のサイズは 2 x 2 に固定されており、ツリーの走査とは別に、すべてのツリー演算定数が機能します。

 ## 特殊なケース

 文字列の場合`A?`、アルゴリズムは次の行列を作成します。`A`これは、幸せから悲しみへの移行のみを許可し、それを疑問符マトリックスと組み合わせます。 最後のハッピーからハッピーへのエントリは、2 番目の文字が雰囲気を修復する置換のみをカウントします。`6`。 

単一文字更新の場合:```
1 1
B
1 A
```木には意味のある葉が 1 枚だけ含まれています。 葉を交換するとすぐに根が変わります。 答えは次から変わります`19`に`0`なぜなら`A`常に初期の幸せな状態を反転します。 

すべて疑問符の文字列の場合、各リーフには 26 の可能な遷移すべての合計が含まれます。 セグメント ツリーの乗算により両方の中間ムードが維持されるため、一時的に悲しくなったパスは破棄されません。 これが、2 文字の場合に次のような結果が得られる理由です。`403`すぐに幸せな選択だけを数えるのではなく。
