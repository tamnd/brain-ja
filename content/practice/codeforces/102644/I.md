 ## 解決策
 ## 問題の理解

 この問題は、最大 200 個の頂点を持つ有向グラフを記述します。 パスは正確に次のシーケンスです。`k`有向エッジ、頂点またはエッジは複数回出現する場合があります。 すべてのクエリに対して、頂点から始まる異なるウォークの数が尋ねられます。`s`、頂点で終了`t`、正確に含まれています`k`エッジ。 答えはモジュロで出力する必要があります`1,000,000,007`。 

入力グラフには最大 200 個の頂点と 200 個のクエリを含めることができますが、必要なパスの長さは`10^9`。 可能な歩行の数は時間とともに指数関数的に増加するため、パスの直接シミュレーションは不可能です。`k`。 すべてのステップを処理する動的プログラミングのアプローチでも、次の理由により遅すぎます。`k`小さな値に制限されません。 頂点の数が少ないことが重要な制約です。これにより、頂点に対して操作を実行できるようになります。`200 x 200`行列。 

不注意な解決策は場合によっては失敗する可能性があります。 もし`k`が大きいため、一度に 1 つのエッジを反復しても完了しません。 たとえば、単一エッジの場合`1 -> 1`そしてクエリ`(1, 1, 1000000000)`、答えは`1`ただし、ステップバイステップのシミュレーションでは 10 億回の遷移が必要になります。 

もう 1 つのよくある間違いは、パスが頂点を再訪問できることを忘れていることです。 入力の場合:```
2 2 3
1 2
2 1
1 1 3
```正しい出力は次のとおりです。```
0
```可能なウォークは 2 つの頂点間で交互に実行されるだけなので、3 つのエッジの後は頂点で終了します。`2`、頂点ではありません`1`。 グラフを単純なパス問題として扱うと、誤った結果が生成されます。 

3 番目のエッジ ケースは、空のグラフです。 例えば：```
3 0 2
1 2 5
3 3 1
```出力は次のとおりです。```
0
0
```エッジが存在しないため、正の長さのウォークは作成できません。 

## アプローチ

 強引なアイデアは、開始頂点から可能なすべてのウォークを追跡することです。 クエリごとに、次のエッジを選択する深さ優先検索を実行できます。`k`回数を数えて目的地に到着する回数を数えます。 これは、有効なウォークをすべて正確に列挙するため、正しいです。 ただし、散歩の数は次のように増加する可能性があります。`n^k`したがって、頂点が 200 しかないグラフであっても、次の場合には不可能になります。`k`到達する`10^9`。 

最初に観察した方が良いのは、頂点間の遷移のみを考慮しているということです。 させて`A[i][j]`からのエッジがあるかどうかを表します`i`に`j`、より正確には、からの片エッジ パスの数`i`に`j`。 行列の乗算では、遷移が自然に結合されます。 エントリー`(i, j)`の`A^2`からの両エッジ パスがいくつあるかを示します。`i`に`j`考えられるすべての中間頂点が考慮されるためです。 同じアイデアはどの長さにも拡張されます。したがって、答えは次のとおりです。`(s, t)`の要素`A^k`。 

残された問題は、`k`巨大になる可能性があります。 2 進累乗は、通常の累乗とまったく同じようにこれを解決します。 べき乗を事前計算します`A^(1), A^(2), A^(4), A^(8)`、 等々。 それぞれのビット`k`どの力を掛け合わせる必要があるかを示します。 

クエリは 200 個しかないため、べき乗を一度計算して再利用する方が良いでしょう。 各クエリに必要なのは、最大 30 個の行列ベクトル スタイルの遷移だけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^k) | O(k) | 遅すぎる |
 | 行列のべき乗 | O(n^3 log k + qn^2 log k) | O(n^2 log k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 隣接マトリックスの構築`A`。 値`A[i][j]`頂点からの直接エッジの数を格納します`i`頂点へ`j`。 複数のエッジがないため、すべてのエントリは次のいずれかになります。`0`または`1`。 
2. 行列のべき乗を事前計算します。 店`A`、`A^2`、`A^4`、`A^8`、可能な限り最大のビットまで続行します。`k`カバーされています。 次の各行列は、前の行列自体を乗算することによって取得されます。 
3. お問い合わせの場合`(s, t, k)`、現在の結果として単位行列から開始し、次のビットをスキャンします。`k`。 
4. ちょっとしたときはいつでも`k`が設定されている場合は、現在の結果に対応する事前計算された電力を乗算します。 
5. 行の値を返します`s`、 カラム`t`最終的な行列の。 

2 進累乗が機能する理由は、すべての正の整数が 2 のべき乗の合計として表現できるためです。 行列の乗算ではパス構成の意味が保持されるため、選択したべき乗を乗算すると、必要な数のエッジが正確に結合されます。 

なぜ機能するのか: いくつかのビットを処理した後`k`、維持された行列は、指数の処理された部分を使用してパスの数を表します。 セットされたビットに遭遇すると、次のように乗算します。`A^(2^i)`可能なすべての部分パスに正確にその数のエッジを追加します。 不変式は、すべてのビットが処理されるまで真のままであり、その時点で行列は次と等しくなります。`A^k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def multiply(a, b):
    n = len(a)
    bt = [[b[j][i] for j in range(n)] for i in range(n)]
    res = [[0] * n for _ in range(n)]

    for i in range(n):
        ai = a[i]
        ri = res[i]
        for j in range(n):
            s = 0
            bj = bt[j]
            for k in range(n):
                s += ai[k] * bj[k]
            ri[j] = s % MOD
    return res

def solve():
    n, m, q = map(int, input().split())

    mat = [[0] * n for _ in range(n)]
    for _ in range(m):
        a, b = map(int, input().split())
        mat[a - 1][b - 1] = 1

    powers = [mat]
    for _ in range(31):
        powers.append(multiply(powers[-1], powers[-1]))

    ans = []
    for _ in range(q):
        s, t, k = map(int, input().split())
        s -= 1
        t -= 1

        vec = [0] * n
        vec[s] = 1

        bit = 0
        while k:
            if k & 1:
                new_vec = [0] * n
                p = powers[bit]
                for i in range(n):
                    if vec[i]:
                        vi = vec[i]
                        row = p[i]
                        for j in range(n):
                            new_vec[j] = (new_vec[j] + vi * row[j]) % MOD
                vec = new_vec
            k >>= 1
            bit += 1

        ans.append(str(vec[t]))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```行列乗算ルーチンは 2 番目の行列の転置コピーを使用するため、各内部ループは連続した行にアクセスします。 これにより、列のインデックス付けを繰り返し行う必要がなくなり、Python での 3 次乗算が高速化されます。 

クエリ フェーズでは 2 つの完全な行列を乗算しません。 代わりに、開始ベクトルに必要な行列を乗算します。 開始ベクトルには単一の`1`ソース頂点で、エッジを取る前の 1 つの空のパスを表します。 すべてのビットが処理された後、目的の位置には長さのウォークの数が含まれます。`k`。 

指数ループは、次の値までの値を処理します。`10^9`なので、反復回数は 30 ～ 31 回で十分です。 値を Python の整数制限内に保ち、必要な出力と一致させるために、累算のたびにモジュロ演算が適用されます。 

## 実用的な例

 サンプルの場合:```

1 2
2 3
3 1
2 1

```最初のクエリは次のように追跡できます。 

| ステップ | 現在の指数ビット | ベクトル状態 |
 | --- | --- | --- |
 | 開始 | なし |`[1,0,0]`|
 | 使用`A^2`| ビットセット | 長さ 2 のパスをカウントします。 
| 使用`A^4`| ビットセット | 長さ 6 のパスをカウントします |

 選択したパワーを組み合わせた後の頂点の値`2`は`2`、これは長さ 6 の 2 つの有効な歩と一致します。 

問い合わせについては`(1,3,1)`、最初の電力のみが使用されます。 

| ステップ | 現在の指数ビット | ベクトル状態 |
 | --- | --- | --- |
 | 開始 | なし |`[1,0,0]`|
 | 使用`A`| ビットセット |`[0,1,0]`|

 頂点`3`価値がある`0`、からの直接のエッジがないため、`1`に`3`。 

これらの例は、アルゴリズムが単純なパスではなく長さによって歩行をカウントすること、およびべき乗プロセスが短い長さと長い長さの両方を正しく処理することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^3 log K + qn^2 log K) | 行列の累乗には 3 次乗算が必要ですが、各クエリではベクトル乗算が使用されます。 
| スペース | O(n^2 log K) | 事前に計算されたべき乗を保存します。 

と`n <= 200`、三次前処理は実行可能です。 の大きな値`k`はわずか約 30 バイナリ ステップに削減されるため、アルゴリズムは制約に適合します。

 ## 特殊なケース

 エッジのないグラフの場合、隣接行列は完全にゼロになります。 すべての行列累乗はゼロのままであるため、正のステップ数を要求するすべてのクエリは正しくゼロを返します。 

次のようなサイクルの場合:```
2 2 1
1 2
2 1
1 1 1000000000
```隣接行列の累乗により、交互の動きが正しく保存されます。 指数は個別のステップではなくビット単位で処理されるため、解は 10 億回の遷移をシミュレートすることなく答えに到達します。 

繰り返し訪問する場合、行列乗算の解釈には、すでに訪問した頂点に戻るパスが当然含まれます。 行列累乗は単純なパスではなくウォークをカウントするため、特別な処理は必要ありません。
