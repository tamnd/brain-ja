 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースは一連の射撃レーンを記述します。`i`含まれています`A_i`一列に並べられたターゲット。 ティムは一連のショットを発射し、各ショットは正確に 1 つのレーンに割り当てられます。 

射撃の仕組みは特殊で、射撃の結果は全体で 1 番目、3 番目、5 番目などの射撃であるか、2 番目、4 番目、6 番目などの射撃であるかによって決まります。 奇数回のショットでは、選択したレーンに残っている最初のターゲットが破壊されます。 偶数番目のショットでは、最初に残ったターゲットはスキップされ、2 番目に残ったターゲットが存在する場合は破壊されます。 その時点でレーンに 2 番目のターゲットが含まれていない場合、そのショットはすべてのターゲットを外すことになるため無効となり、そのようなショットは禁止されます。 

課題は、無効な動きを一切行わずにすべてのターゲットを正確に 1 回破壊する、すべてのショットに対する一連のレーン選択が存在するかどうかを判断することです。 存在する場合は、有効なシーケンスも 1 つ出力する必要があります。 

制約は大きく、すべてのテスト ケースで、レーンの総数は 30 万、ターゲットの総数は 50 万に達します。 これにより、レーンを繰り返しスキャンしてショットを 1 つずつシミュレートしたり、線形検索に依存する高価なショットごとの状態更新を維持したりする戦略は除外されます。 どのソリューションも、ターゲットの数に応じて本質的に線形時間で動作する必要があります。 

ローカルで考えると微妙な問題が見えてきます。 単純な考えは、ターゲットがまだ存在するレーンを常に射撃することです。 これは、偶数番号のショットの動作が異なり、レーン内に唯一残っているターゲットをスキップする可能性があるため、すぐに失敗します。これにより、ターゲットが残っている場合でも一部の構成を事実上完了できなくなります。 

小規模な場合には、別の故障モードが発生します。 たとえば、1 つのレーンに 2 つのターゲットがある場合、常に 2 発のショットが機能すると予想されるかもしれませんが、2 番目のショットは偶数になり、最初の除去後に存在しない 2 番目のターゲットに命中しようとするため、ターゲットの合計数が偶数であっても強制的に失敗します。 

3 番目の重要なエッジ ケースは、すべてのレーンにターゲットが 1 つだけある場合です。 最初のショットで 1 つのターゲットを除去した後、2 番目のショットは少なくとも 2 つのターゲットがまだ残っているレーン上で動作する必要がありますが、それは不可能であるため、サイズ 1 のレーンにまたがる合計 1 つ以上のターゲットの場合、答えは直ちに否定になります。 

これらの例は、答えが総カウントだけではなく、プロセス全体を通して有効な偶数ショットのシーケンスを維持できるかどうかに依存することを示唆しています。 

## アプローチ

 ブルートフォース戦略では、考えられるすべてのレーン選択シーケンスをシミュレートします。 各ステップで、グローバル ショット インデックスの現在の同等性を考慮して、有効なショットを許可するレーンを選択します。 各レーンに残っているターゲットのリストを維持し、可能なすべての選択を再帰的に、または状態全体にわたる BFS 経由で試みます。 

このアプローチは、構成の状態空間を直接探索するため、原理的には正しいです。 ただし、分岐係数は空ではないレーンの数に比例し、各遷移によってレーン構造が変更されます。 効率的なデータ構造を使用したとしても、ショットごとに 1 つのレーンの構造が将来の有効性に影響を与える形で変更されるため、状態の数はショットの数に応じて指数関数的に増加します。 ターゲットの合計が最大 500,000 になると、これは完全に不可能になります。 

重要な観察は、パリティ制約が厳格なペアリング構造を作成するということです。 各レーンは独立していません。 代わりに、奇数のショットで最初のターゲットを削除し、偶数のショットで 2 番目に残ったターゲットを削除するというパターンでターゲットが消費されます。 これは、残りの要素を除いて、すべてのレーンが一連のペアの除去のように動作することを意味します。 システムが一貫しているのは、レーン上で均等なショットを実行するたびに、そのレーンに少なくとも 2 つのターゲットがすでに残っている必要があるようにショットを配置できる場合に限られます。

これは、必要なグローバル条件につながります。つまり、奇数のショットの後のあらゆる瞬間に、次の偶数のショットが常に有効な場所で実行できるように、十分な構造が残っていることを確認する必要があります。 これを保証する唯一の方法は、レーン内のターゲットを一貫した交互の消費パターンでペアにすることですが、これは簡単な実行可能条件をカウントでチェックすることになります。 

実際、各レーンは、floor(A_i / 2) に等しい特定の数の「ペアの機会」に貢献します。 これらは安全な偶数ショットの消費に対応します。 奇数レーンの残りの単一ターゲットは奇数ショットのみで消費される必要があり、奇数ショットの総数はシーケンスの長さを決定すると固定されます。 このシステムは、偶数ショットをサポートできるレーンを使い果たすことなく、すべてのペアの消費をスケジュールできる場合に正確に実現可能です。 

これにより、問題は、現在利用可能な 2 番目のターゲットがあるレーンと、そうでないレーンの数を維持する、カウントを超える貪欲な構築に帰着します。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 各レーンについて、少なくとも 2 つのターゲットがあるかどうかを計算します。 1 つのターゲットを持つレーンと、少なくとも 2 つのターゲットを持つレーンの 2 つのグループを維持します。 偶数番号のショットをサポートできるのは 2 番目のグループだけであるため、この区別は重要です。 
2. 1 から A までの合計ショットを反復することにより、ショットのシーケンスの構築をシミュレートします。ここで、A はターゲットの合計数です。 現在のショットのレーンを常に決定します。 
3. 現在のショット インデックスが奇数の場合、まだターゲットが残っているレーンの最初のターゲットを破壊することができます。 現在少なくとも 1 つのターゲットが残っているレーンを選択します。 可能であれば、少なくとも 2 つのターゲットがあるレーンを推奨します。これは、1 つのターゲットのレーンで構造を維持することで、後の行き止まりを防ぐためです。 どのレーンにもターゲットがない場合、建設は失敗します。 
4. 現在のショットインデックスが偶数の場合、いずれかのレーンで 2 番目のターゲットの除去を実行する必要があります。 これは、残りのサイズが少なくとも 2 であるレーンが少なくとも 1 つ存在する場合にのみ有効です。 そのようなレーンを選択し、その 2 番目に残っているターゲットを削除します。 そのような車線が存在しない場合、建設は不可能です。 
5. 削除するたびに、レーンの残りの数を更新し、必要に応じて「少なくとも 2 つ」カテゴリと「1 つまたはゼロ」カテゴリの間で移動します。 
6. 各ショットに対して選択したレーン インデックスを記録し、最終シーケンスを構築します。 

中心的な考え方は、奇数のステップは柔軟な消費ステップであるのに対し、偶数のステップはレーン内の構造的な深さを必要とする制約された操作であるということです。 貪欲なポリシーでは、常にその深さを維持することが優先されます。 

なぜそれが機能するかは、レーン状態の不変条件に関係しています。 どの時点でも、すべてのレーンは 2 つの状態のいずれかになります。ターゲットが少なくとも 2 つ残っているか、多くても 1 つあります。 ショットでも最初の状態でしかサーブできません。 このアルゴリズムにより、均等なショットが必要な場合は常に、最初の状態ですべてのレーンが使い果たされていないことが保証されます。 これは、すべての偶数操作が満たされる前に、残りのターゲットを持つすべてのレーンをシングルトンに折りたたむことを常に避けるため、保証されます。 より深いレーンを使用するという貪欲な優先により、将来の偶数ステップの実現可能性が最初に維持されます。また、各レーンは大きなカウントから小さなカウントへ単調に移行するため、以前に復元された機能が失われたり再生成されたりすることがなく、実現可能性の条件が単調になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        total = sum(a)
        if total == 0:
            print("NO")
            continue
        
        # We maintain two lists of lanes by remaining count
        # store (remaining, index)
        from collections import deque
        
        big = deque()
        small = deque()
        
        for i, x in enumerate(a):
            if x >= 2:
                big.append([x, i])
            elif x == 1:
                small.append([x, i])
        
        res = []
        
        # helper: get any valid lane for odd/even
        def pop_big():
            while big and big[0][0] <= 1:
                small.append(big.popleft())
            if not big:
                return None
            x, i = big[0]
            big[0][0] -= 1
            return i
        
        def pop_any():
            while big and big[0][0] == 0:
                big.popleft()
            if big:
                big[0][0] -= 1
                return big[0][1]
            while small:
                if small[0][0] == 0:
                    small.popleft()
                else:
                    small[0][0] -= 1
                    return small[0][1]
            return None
        
        for shot in range(1, total + 1):
            if shot % 2 == 0:
                lane = pop_big()
                if lane is None:
                    print("NO")
                    break
                res.append(lane + 1)
            else:
                lane = pop_any()
                if lane is None:
                    print("NO")
                    break
                res.append(lane + 1)
        else:
            print("YES")
            print(*res)

for _ in range(1):
    solve()
```この実装では、均等なショットをサポートするのに十分な深さが現在あるかどうかによってレーンを分離する 2 つのデキューが維持されます。 の`pop_big`この機能は、ショットであっても常に少なくとも 2 つのターゲットが残っているレーンから消費するように強制します。`pop_any`利用可能なターゲットが消費される可能性がある奇数ショットに使用されます。 

微妙な点は、両端キューには変更可能な残りのカウントが格納されるため、カウントがゼロになったときに遅延クリーンアップに依存していることです。 これにより、構造のスキャンや再バランスを繰り返し行う必要がなくなります。 正確性は、各レーンの残りのカウントが減少するだけであるという事実に依存しているため、古いエントリは安全にスキップできます。 

奇数ショットと偶数ショットの処理の順序は重要です。 たとえショットが任意のレーンから消費されることを許可された場合、シングルトンレーンのみが残っている場合、構造はすぐに壊れてしまいます。 

## 実用的な例

 ### 例 1

 車線を考慮する`[3, 1, 1]`、合計ショット数`5`。 

残りのカウントを追跡します。 

| ショット | タイプ | 選択されたレーン | | 後の状態
 | --- | --- | --- | --- |
 | 1 | 奇数 | レーン1 | [2,1,1] |
 | 2 | 偶数 | レーン1 | [1,1,1] |
 | 3 | 奇数 | レーン1 | [0,1,1] |
 | 4 | 偶数 | 不可能 | ≥2 の車線なし |

 ショット 4 では、レーンに 2 つのターゲットが残っていないため、プロセスは失敗します。 これは、十分な合計ターゲットがあるだけでは不十分であることを示しています。 レーンごとの構造的な深さが重要です。 

### 例 2

 車線を考慮する`[4, 2]`、合計ショット数`6`。 

| ショット | タイプ | 選択されたレーン | | 後の状態
 | --- | --- | --- | --- |
 | 1 | 奇数 | レーン1 | [3,2] |
 | 2 | 偶数 | レーン1 | [2,2] |
 | 3 | 奇数 | レーン1 | [1,2] |
 | 4 | 偶数 | レーン2 | [1,1] |
 | 5 | 奇数 | レーン1 | [0,1] |
 | 6 | 偶数 | レーン2 | [0,0] |

 すべてのターゲットが正常に消費されます。 レーンを交互に切り替えることで、偶数ショットでも常に有効なターゲット ペアを利用できるようになります。

def run(inp: str) -> str:

    from collections import deque

    def solve():
        t = int(input())
        out_lines = []
        for _ in range(t):
            n = int(input())
            a = list(map(int, input().split()))
            total = sum(a)
            if total == 0:
                out_lines.append("NO")
                continue

            small = deque()

                if x >= 2:
                    big.append([x, i])
                elif x == 1:
                    small.append([x, i])

            res = []

            def pop_big():
                while big and big[0][0] <= 1:
                    small.append(big.popleft())
                if not big:
                    return None
                big[0][0] -= 1
                return big[0][1]

            def pop_any():
                while big and big[0][0] == 0:
                    big.popleft()
                if big:
                    big[0][0] -= 1
                    return big[0][1]
                while small:
                    if small[0][0] == 0:
                        small.popleft()

                out_lines.append("YES")
                out_lines.append(" ".join(res))

        return "\n".join(out_lines)

    return solve()

 ## 特殊なケース

 重要なエッジケースは、すべてのレーンにターゲットが 1 つだけある場合です。 アルゴリズムはすべての奇数ショットを直ちにシングルトン消費にルーティングしますが、レーンに 2 番目のターゲットが含まれていないため、最初の偶数ショットは不可能になります。 構造はこれを正確に識別します。`pop_big`最初の偶数ステップで失敗します。 

もう 1 つのエッジ ケースは、2 つのターゲットを持つ 1 つのレーンです。 最初のショットは有効な状態を作成しますが、2 番目のショットは偶数であり、もう存在しない 2 番目のターゲットを消費する必要があります。 最初の削除後にレーンが「大きい」から「小さい」に移行し、2 番目の操作に有効なソースが残らないため、アルゴリズムはこれを捕捉します。 

より大きな構造的エッジケースは、ターゲットの総数が十分であるにもかかわらず、ターゲットが不均一に分散している場合に発生します。`[3, 3, 1]`。 局所的に貪欲に消費すると、すべての偶数ステップが満たされる前に、誤ってすべてのレーンがサイズ 1 に縮小される可能性があります。 このアルゴリズムは、消費のために常に深いレーンを優先し、最終ステップまで少なくとも 1 つの有効な偶数対応レーンを保持することでこれを回避します。
