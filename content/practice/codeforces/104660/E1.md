 ## 解決策
 ## 問題の理解

 次のサイズのラテン方陣を構築するように求められます。$n \times n$、からの数字で満たされたグリッドを意味します。$1$に$n$すべての数値が各行に 1 回、各列に 1 回ずつ出現するようにします。 この標準的な制約に加えて、左上から右下までの対角線の合計は固定されており、その対角線の要件を満たす有効なラテン方陣を作成するか、それが不可能であると報告する必要があります。 

入力は複数のテスト ケースで構成されます。 各テスト ケースのサイズは次のとおりです。$n$そして目標値$k$。 各テスト ケースの出力は、条件を満たす有効なラテン方陣、または不可能を示す単語のいずれかです。 

複雑さの観点から見ると、重要な意味は、以下の場合を除き、テスト ケースごとの任意の置換やグラフ マッチングが許容される体制にはないということです。$n$小さいです。 この構造は、解決策が建設的なパターンであるか、枝刈りを伴う後戻り検索であることを強く示唆しています。 対角制約は行間の唯一の結合であるため、この単一のグローバル合計条件を除いて、行ごとの独立性はほぼ真です。 

ターゲット合計が実行可能な範囲外にある場合、微妙なエッジ ケースが発生します。 可能な最小の対角和は次のとおりです。$n$(すべての対角要素は 1)、最大のものは$n^2$(すべての対角線のエントリは$n$）。 どれでも$k$この間隔外では直ちに不可能になります。 

もう 1 つの失敗モードは、対角線を考慮せずにラテン方陣を貪欲に埋めようとする場合に発生します。 たとえば、標準的な巡回ラテン方陣は、$n = 4$は構造的には有効ですが、その対角和は固定されています。 必要な場合は、$k$とは異なり、多くの場合に有効な解決策が存在する場合でも、単純な構築は常に失敗します。$k$。 

## アプローチ

 自然な出発点は、正方形を 1 行ずつ構築することを考えることです。 各行について、次の順列を選択します。$1 \ldots n$、列が値を繰り返さないことを維持しながら。 これは基本的にラテン方陣を段階的に構築することであり、列使用状況の追跡によるバックトラッキングとしてモデル化できます。 

この総当りアプローチは、各行の有効な順列をすべて試し、列の一意性に違反する構成や対角和をオーバーシュートする構成を拒否することで機能します。 これは、すべての有効なラテン方格を体系的に探索し、すべての制約が同時に満たされる場合にのみ構成を受け入れるため、これは正しいです。 

ただし、ラテン方陣の数は非常に急速に増加します。 たとえ$n = 5$、可能性の数が十分に大きいため、枝刈りを行わない素朴な検索は実行不可能になります。 最悪のケースでは、$n!$行ごとの並べ替え数$n$行、おおよそ$(n!)^n$これは合理的な制限をはるかに超えています。 

この問題を解決可能にする重要な観察は、制約が行と列でローカルであり、対角和が唯一のグローバル結合であるということです。 これにより、積極的な枝刈りが可能になります。部分対角和が目標を超えるか、最良の場合の完了でも到達できなくなるとすぐに、分岐を破棄できます。 さらに、列の制約により分岐係数が大幅に減少します。 

したがって、解決策は、すべてのラテン方陣を盲目的に列挙するのではなく、すべてのステップで実現可能性をチェックする、制約付きの置換構築になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ラテン方陣の総当り列挙 |$O((n!)^n)$|$O(n^2)$| 遅すぎる |
 | 行と対角の枝刈りによるバックトラック |$O(\text{pruned search})$|$O(n^2)$| 少額でも承ります$n$|

 ## アルゴリズムのチュートリアル

 各列で既に使用されている数値を維持しながら、バックトラッキングを使用して行ごとにラテン方陣を構築します。 

1. まず、目標の対角和が満たされているかどうかを確認します。$k$実現可能ですらあります。 もし$k < n$または$k > n^2$、各斜めの入り口が間にあるため、建設は存在できません。$1$そして$n$。 
2. グリッドと柱を使用する構造を準備します。 列トラッカーは、列内で数値が繰り返されないことを保証します。 
3. 行を埋める再帰関数を定義します。$r$。 各行で、次のすべての順列を試します。$1 \ldots n$列の制約を尊重します。 
4. 候補行を構築する際、対角線への寄与も追跡します。 私たちがその位置にいるなら$(r, r)$、選択した値が累計に反映されます。 
5. 行を完了した後、残りの対角和の境界を計算します。 将来の可能な最小限の貢献は、$1$残りの対角セルごとに最大値は$n$セルごとに。 残りの必要な金額がこの範囲外にある場合は、すぐにバックトラックされます。 
6. すべての行を埋めることに成功し、対角和が次と等しい場合$k$、グリッドを出力します。 

重要な枝刈りステップは、残りの対角和の実現可能性をチェックすることです。 これがなければ、検索スペースは爆発的に広がります。 これにより、無効な部分割り当てのほとんどが直ちに破棄されます。 

### なぜ効果があるのか

 このアルゴリズムは、再帰の深さごとに部分的なラテン方陣を維持するため、行と列の制約は常にローカルで満たされます。 唯一のグローバル制約は対角和であり、各ステップで、残りの未記入の対角セルが目標和に到達するのに十分な柔軟性を持っていることを確認します。 これにより、不変条件が確立されます。つまり、再帰によって探索される部分状態は、実行不可能であるために明示的に削除されない限り、完全に有効な解決策に拡張できます。 すべての有効な構成は列制約の下で行を並べ替えることによって到達できるため、検索は有効な解空間にわたって完了します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, k):
    grid = [[0] * n for _ in range(n)]
    used = [[False] * (n + 1) for _ in range(n)]

    cols = [set() for _ in range(n)]
    ans = None

    def backtrack(r, diag_sum):
        nonlocal ans
        if ans is not None:
            return

        if r == n:
            if diag_sum == k:
                ans = [row[:] for row in grid]
            return

        remaining = n - r
        min_possible = diag_sum + remaining * 1
        max_possible = diag_sum + remaining * n
        if not (min_possible <= k <= max_possible):
            return

        def gen(row, curr, used_row):
            if len(curr) == n:
                yield curr[:]
                return
            for v in range(1, n + 1):
                if not used_row[v] and v not in cols[len(curr)]:
                    used_row[v] = True
                    curr.append(v)
                    cols[len(curr) - 1].add(v)
                    yield from gen(row, curr, used_row)
                    cols[len(curr) - 1].remove(v)
                    curr.pop()
                    used_row[v] = False

        for perm in gen(r, [], [False] * (n + 1)):
            grid[r] = perm
            new_diag = diag_sum + perm[r]
            backtrack(r + 1, new_diag)
            if ans is not None:
                return

    backtrack(0, 0)
    return ans

def main():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        res = solve_case(n, k)
        if res is None:
            print("IMPOSSIBLE")
        else:
            for row in res:
                print(*row)

if __name__ == "__main__":
    main()
```コードは行ごとの構築戦略に従います。 の`cols`構造体は、各列でどの値がすでに使用されているかを追跡することにより、ラテン方格プロパティを強制します。 再帰ジェネレータは、これらの制約の下で行の有効な順列をすべて構築します。 

対角和は、行を割り当てるときにのみ更新されます。`perm[r]`。 これにより、行間の結合が最小限に抑えられ、単一の整数に局所化されます。 

残りの行に基づくプルーニング条件により、検索が完全な列挙に劣化するのを防ぐことができます。

 | 0 | - | 空 | 0 |
 | 1 | [1,2,3] | [1 2 3] | 1 |
 | 2 | [2,3,1] | [1 2 3; 2 3 1] | 4 |

 このトレースは、対角線がどのように段階的に蓄積されるかを示しています。 各行の選択は、ローカルなラテン語制約とグローバル合計の両方に影響します。 

次に、失敗したケースを考えてみましょう$n = 3, k = 2$。 最初の行を配置した後に達成可能な最小の対角和でもすでに実現可能範囲を超えているため、アルゴリズムはすぐに分岐を拒否します。 

| ステップ | 行 | 部分グリッド | 対角線の合計 | 実現可能範囲 |

 ## 特殊なケース

 いつ$k < n$の場合、アルゴリズムは検索が開始される前に即座に拒否します。 これは、すべての対角エントリを$1$目標に達しません。 

のために$n = 2, k = 3$、検索スペースは小さいです。 バックトラッキングは順列を試みます$[1,2]$最初の行と$[2,1]$2 行目では、対角和を持つ有効な正方形が生成されます。$1 + 1 = 2$。 これは合わないので$k$場合は、元に戻って別の配置を試し、最終的に正しい構成が存在する場合はそれを見つけます。 

といった不可能なケースに対しては、$n = 3, k = 2$の場合、残りの行の達成可能な最小対角和がすでに目標を超えているため、すべての部分割り当ては最初の行の後で切り捨てられます。 これは、枝刈り条件が早期の検索を支配し、完全な探索を妨げている様子を示しています。
