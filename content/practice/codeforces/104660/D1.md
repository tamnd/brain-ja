 ## 解決策
 ## 問題の理解

 長さはわかっていますが、内容は不明な、隠れたバイナリ配列を操作しています。 私たちのタスクは、特定の位置の値を要求するクエリを使用して配列全体を再構築することです。 

面白いのは、ジャッジがアレイを静的に維持しないことです。 一定数のクエリが実行されるたびに、隠れた配列は、少数の操作セットから敵対的に選択された変換を受ける可能性があります。 これらの操作には、すべてのビットを反転する、配列を反転する、両方を実行する、または何も実行しないなどが含まれます。 これらの変更は発表されないため、正しく考慮しない限り、以前に観察した値が現在の非表示の状態と一致しない可能性があります。 

出力は、対話の終了時に完全に再構成された配列であることが期待されており、ソリューションは厳密なクエリ制限内に収まる必要があります。 これにより、同じ位置を繰り返しプローブしたり、変更が疑われるたびにアレイを最初から再構築しようとしたりするアプローチが即座に排除されます。 唯一の実行可能な方向は、クエリを最小限に抑えながら、その場で変換を検出して修正することです。 

すべてを形作る主な制約は、配列サイズに対するクエリ制限です。 配列は中程度のサイズまで (この問題ファミリーでは通常約 100 ビット) であるため、O(n) 再構成は問題ありませんが、安定性を確認するために位置を再クエリする戦略はすぐに制限を超えます。 これにより、対称的な位置からの情報をペアにし、少数の「センチネル」クエリを使用して変換が発生したときを検出する戦略が推進されます。 

微妙な失敗例は、対称位置のペアをクエリした直後に変換が発生する場合に発生します。 たとえば、インデックス 1 とインデックス n をクエリし、その後配列が逆になったとします。 これを積極的に検出しないと、それらの値が依然として同じ位置に対応していると誤って仮定することになります。 もう 1 つの失敗ケースは、すべてのビットが同一または完全に対称である場合です。これにより、参照ペアを意図的に維持しない限り、単純な比較を使用して反転または補完を検出することが不可能になります。 

## アプローチ

 ブルートフォース戦略では、安定性を確保するためにすべてのポジションを複数回繰り返しクエリします。 プロセス全体を通じてインデックス i のクエリを数回試行して、その値が変化するかどうかを検出し、多数決に基づいて再構築することもできます。 変換は決定論的であるため、これは原理的には機能しますが、クエリ制限の下では失敗します。 配列のサイズが B の場合、インデックスごとに一定回数でもクエリを繰り返すと、O(B²) クエリが発生します。これは、B が約 100 で変換が頻繁に行われる場合、許容されるバジェットをはるかに超えます。 

重要な観察は、実際にすべての変更をグローバルに検出する必要はないということです。 2 つのチェックポイント間で 4 つの変換のうちどれが発生したかを検出するだけで済みます。 可能性は 4 つしかないため、変換を一意に識別するには 2 つの情報で十分です。 

ここで、対称プローブが強力になります。 常にペア (i, n - i + 1) をクエリすると、再構築プロセス中に 2 つの特別なタイプのペアを追跡できます。 1 つのペアは値が等しいことがわかっている位置で構成され、もう 1 つのペアは値が異なることがわかっている位置で構成されます。 これらのペアは検出器として機能します。 クエリのブロックごとに、これらのセンチネルの位置を再クエリします。 それらの関係が変化した場合、補完または逆転が起こったかどうかを推測できます。 

変換が特定されると、それを最初から再導出するのではなく、それに応じて保存された知識を調整します。 これにより、クエリ制限内に留まりながら、配列を線形に埋め続けることができます。

## アルゴリズムのチュートリアル

 2 つのポインターを維持します。1 つは配列の左端から始まり、もう 1 つは配列の右端から始まります。 また、2 つの特別な参照インデックスも維持します。1 つは鏡像位置で値が等しいことがわかっているもの、もう 1 つは値が異なることがわかっているものです。 これらの参照は、変換を検出するために使用されます。 

1. 2 つのポインタを初期化する`l = 1`そして`r = n`。 配列を準備する`ans`既知の値を発見したときに保存します。 プレースホルダーも保持します`same_idx`そして`diff_idx`、最初は未定義です。 
2. ペアで位置を繰り返しクエリします。次の値を要求します。`l`そして`r`。 として保存します`ans[l]`そして`ans[r]`。 設定により内側に移動`l += 1`そして`r -= 1`。 ペアリングにより対称性が確実に利用され、反転が検出可能になります。 
3. 10 クエリの固定ブロックごとに、センチネル インデックスを使用して変換を検出します。 両方が定義されている場合は、それらを再クエリし、保存されている値と比較します。 変化のパターンから、反転、反転、両方が発生したか、または何も発生しないかがわかります。 
4. センチネルが 1 つだけ存在する場合でも、それを使用して検出を試みますが、形式はより弱いものになります。 どちらもまだ存在しない場合は、十分な構造が収集されるまで検出をスキップします。 
5. 変換が検出されると、全体の論理状態を更新します。`ans`。 反転すると、インデックスが対称的に交換されます。 補数はすべてのビットを反転します。 組み合わせた操作では、両方の変換が適用されます。 
6. すべてのポジションが埋まるまでこのプロセスを続けます。 最後に、再構成された配列を出力します。 

重要な不変条件は、いつでも、`ans`現在の変換状態での非表示配列を表します。 センチネル ペアは、現在の変換が同一、反転、補数、またはその両方であるかどうかと常に一致します。 すべての変換は反転可能であり、すべての位置に均一に影響を与えるため、クエリを再質問するのではなく、格納された配列を更新することで正確さが維持されます。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    B = int(input().strip())
    ans = [-1] * B

    same_idx = -1
    diff_idx = -1

    l, r = 0, B - 1
    q_count = 0

    def ask(i):
        nonlocal q_count
        q_count += 1
        print(i + 1)
        sys.stdout.flush()
        return int(input().strip())

    def detect():
        nonlocal same_idx, diff_idx, ans

        def fix(x):
            return ans[x] if x != -1 else -1

        flip = False
        rev = False

        if same_idx != -1:
            v = ask(same_idx)
            if ans[same_idx] != v:
                flip = True
        else:
            ask(0)
            input()

        if diff_idx != -1:
            v = ask(diff_idx)
            if ans[diff_idx] != v:
                flip = not flip
                rev = True
        else:
            ask(0)
            input()

        if flip:
            ans = [1 - x if x != -1 else -1 for x in ans]

        if rev:
            ans = ans[::-1]

    while l <= r:
        if q_count > 0 and q_count % 10 == 0:
            detect()

        if l == r:
            ans[l] = ask(l)
            break

        ans[l] = ask(l)
        ans[r] = ask(r)

        if ans[l] == ans[r]:
            same_idx = l
        else:
            diff_idx = l

        l += 1
        r -= 1

    for i in range(B):
        if q_count % 10 == 0:
            detect()
        print(ans[i] if ans[i] != -1 else 0)

    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```このコードは、対称充填、周期的同期、状態修正という 3 つの考え方に基づいて構成されています。 の`ask`関数は対話を集中化し、出力を即座にフラッシュすることを保証します。これは対話型の問題では不可欠です。 

の`detect`関数は、格納された配列と可能な変換を調整する責任があります。 これはセンチネルの位置に依存し、それらを再クエリし、保存されている値と比較します。 不一致に基づいて、ビット単位の反転または反転が発生したかどうかを推測し、配列全体に修正を適用します。 

実装の微妙な点は、変換中に未知の値を慎重に扱う必要があることです。 の`-1`プレースホルダーにより、反転または反転中に初期化されていない位置が誤って有効なデータとして解釈されることがなくなります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、配列が完全に対称で、すべての値が同一である場合です。 このような場合、値の比較だけでは反転を検出することが不可能になるため、アルゴリズムはプロセスの早い段階で異なることが確認された専用のペアに依存します。 このペアがなければ、変換は区別できません。 

もう 1 つのケースは、センチネル ペアが確立される前に変換が発生する場合です。 この状況では、アルゴリズムは一時的に検出をスキップし、十分な情報が存在するまで構造の収集を続けます。 たとえば、最初の 10 個のクエリが構築によって消費された場合、最初の検出サイクルには依然として有効な diff ペアが不足している可能性があります。 アルゴリズムは、推測ではなく修正を延期することでこれを許容します。 

最後のエッジ ケースは、残りの塗りつぶされていない領域が単一のインデックスに折りたたまれるときに発生します。 このアルゴリズムは引き続き検出チェックを実行しますが、不必要な対称クエリを回避し、最後の値が直接読み取られ、曖昧さなく配置されるようにします。
