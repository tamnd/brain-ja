 ## 解決策
 ## 問題の理解

 次のサイズの正方形グリッドが与えられます$n \times n$、整数で埋められます。 このグリッドから 3 つの値を計算する必要があります。 

まず、位置を意味する主対角上の要素の合計である行列のトレースを計算します。$(1,1), (2,2), \dots, (n,n)$。 

次に、各行をチェックして、繰り返し値が含まれているかどうかを確認します。 行に重複が含まれている場合は、問題があるとみなされます。 少なくとも 1 つの繰り返し要素が含まれるという意味で、有効な順列ではない行の数が必要です。 

3 番目に、列に対して同じチェックを実行し、重複を含む列の数を数えます。 

出力は、トレース、不良行数、不良列数という 3 つの数値だけです。 

制約は十分に小さいため、$O(n^2)$トラバースは簡単です。 トレースを計算して重複を検出するには、すべてのセルを少なくとも 1 回検査する必要があるため、どのような解でも当然のことながらセル数は線形になります。 これにより、最悪の場合でも数百万回の操作を快適に行うことができます。 

唯一の微妙なエッジケースは、重複の検出方法です。 単純なアプローチでは、各行と列を繰り返し並べ替えようとする可能性がありますが、制約があればそれでも問題は解決します。 ただし、最もクリーンなアプローチは、スキャン中に行と列ごとにセットを使用することです。 

不注意な実装で失敗する可能性のある小さな例としては、行に繰り返し値が含まれているが、有効な範囲値もすべて含まれている場合があります。 たとえば:

 入力:```
3
2 2 2
1 2 3
3 2 1
```値が範囲内であっても、最初の行は繰り返しのため無効です。 正しい出力では、その行は不良行としてカウントされる必要があります。 

もう 1 つの微妙なケースは、行とそれに対応する列の両方に重複が存在する場合です。 両方を独立してカウントする必要があります。 

## アプローチ

 ブルートフォース手法では、対角線をスキャンしてトレースを計算し、行と列ごとに並べ替えて、隣接する重複をチェックします。 各行のソートにかかるコスト$O(n \log n)$、すべての行と列に対してこれを行うと、$O(n^2 \log n)$。 と$n$数百まではまだ許容されますが、不要です。 

重要な観察は、順序付けは必要なく、一意性のみが必要であるということです。 これにより、問題はメンバーシップ チェックの繰り返しとなり、ハッシュ セットを使用すると行ごとに線形時間で実行できます。 各行をスキャンすると、要素がセットに挿入され、重複がすぐに検出されます。 入力の読み取り中に個別のセットを維持するか列値を蓄積する場合、同じことが列にも当てはまります。 

これにより、計算全体が定数時間挿入による行列の 1 回のパスに削減されます。

 | --- | --- | --- | --- |
 | ブルート フォース (行/列のソート) |$O(n^2 \log n)$|$O(n^2)$| 承認済み |
 | ハッシュセットスキャン |$O(n^2)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 列の状態を維持しながら、行列を行ごとに処理します。 

1. トレースの変数をゼロとして初期化します。 また、各列で検出された値を追跡するためのセットの配列 (列ごとに 1 つ)、および不良行と不良列のカウンターも準備します。 
2. 各行について$i$、その行の値を追跡するための空のセットと、行が有効かどうかを示すフラグを作成します。 
3. 各要素を反復処理する$a[i][j]$。 それを行セットに追加します。 すでに存在する場合は、その行を無効としてマークします。 同時に列に追加します$j$のセット; その列にすでに存在する場合は、その列を無効としてマークします。 
4. もし$i == j$、値をトレース アキュムレータに追加します。 
5. 各行の終了後、その行が無効な場合は、不良行カウンタをインクリメントします。 
6. すべての行を処理した後、重複フラグが立てられている列セットの数を数えるか、挿入中に無効な列を単純に追跡します。 

より単純な実装では、列の完全なセットの維持を回避するために、列ごとにすでに無効とマークされているかどうかを示すブール配列と、列ごとに表示された値のセットを維持します。 

### なぜ効果があるのか

 各行と列の重複が 1 回だけチェックされ、セットのメンバーシップにより、最初の繰り返し出現が即座に検出されることが保証されます。 セットには一意の値のみが格納されるため、反復すると必ず一定の予想時間内に衝突が発生します。 トレースはこのロジックから独立しており、対角エントリから直接計算されるため、重複検出の正確さは影響しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    cols = [set() for _ in range(n)]
    bad_cols = [False] * n
    bad_rows = 0
    trace = 0

    for i in range(n):
        row = set()
        row_bad = False
        arr = list(map(int, input().split()))

        for j in range(n):
            val = arr[j]

            if i == j:
                trace += val

            if val in row:
                row_bad = True
            else:
                row.add(val)

            if val in cols[j]:
                bad_cols[j] = True
            else:
                cols[j].add(val)

        if row_bad:
            bad_rows += 1

    bad_cols_count = sum(bad_cols)
    print(trace, bad_rows, bad_cols_count)

if __name__ == "__main__":
    solve()
```コードは行ごとおよび列ごとにセットを維持します。 行の重複は、単一行の反復内でローカルに検出されます。 列の重複は各セルを処理する際に段階的に追跡され、2 回目の走査を回避します。 対角線の状態がインラインでチェックされ、トレースが 1 回のパスで確実に蓄積されます。 

よくある実装上の間違いは、列を一度だけ不良としてマークするのを忘れることです。 ブール配列により、同じ列で重複が繰り返されてもカウントが膨らまないことが保証されます。

    import sys
    input = sys.stdin.readline

    n = int(input())
    cols = [set() for _ in range(n)]
    bad_cols = [False] * n
    bad_rows = 0
    trace = 0

    for i in range(n):
        row = set()
        row_bad = False
        arr = list(map(int, input().split()))
        for j in range(n):
            val = arr[j]
            if i == j:
                trace += val
            if val in row:
                row_bad = True
            else:
                row.add(val)
            if val in cols[j]:
                bad_cols[j] = True
            else:
                cols[j].add(val)

        if row_bad:
            bad_rows += 1

    bad_cols_count = sum(bad_cols)
    return f"{trace} {bad_rows} {bad_cols_count}"

assert run("3\n1 2 3\n4 5 6\n7 8 9\n") == "15 0 0"

# all-equal rows/columns

 ## 特殊なケース

 サイズ 1 の最小行列は、アルゴリズムが単一要素の行と列を有効なものとして正しく扱うかどうかをテストします。 入力用`1\n7\n`の場合、行セットには要素が 1 つだけ含まれるため、重複は検出されず、列セットは同様に動作します。 トレースは単純に 7 であり、両方のカウンタは 0 のままです。 

次のような完全に定数の行列`2\n1 1\n1 1\n`すべての行と列で重複検出をトリガーします。 行スキャンでは、セットへの 2 回目の挿入がすぐに失敗し、2 行目の処理時に同様に各列が繰り返されるため、両方の行が無効としてマークされます。 アルゴリズムは両方のカウンタを正確に 2 回増分します。 

1 行のみに重複が含まれる混合ケース。たとえば、`3\n2 2 2\n1 2 3\n3 1 2\n`、行と列のロジックが独立していることを確認します。 最初の行は行フラグを設定しますが、列はこの特定の配置で繰り返しエントリをトリガーすることなく値を蓄積します。これは、列の追跡が行レベルの重複状態の影響を受けないことを示しています。
