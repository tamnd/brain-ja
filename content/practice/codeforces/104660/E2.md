 ## 問題の理解

 私たちは構造化されたシステムを構築することが求められています。$n \times n$～の数字で埋められたグリッド$1$に$n$各数値が各行に 1 回、各列に 1 回ずつ出現するようにします。 これは古典的なラテン方陣の要件です。 それに加えて、主対角に関連する追加のグローバル制約があります。対角のエントリの合計は、指定されたターゲット値に等しくなければなりません。$k$。 ラテン平方特性と対角和の要件を同時に満たすことが不可能な場合は、有効な構造が存在しないことを報告しなければなりません。 

入力は、正方形のサイズと必要な対角和で構成されます。 出力は、対角条件を満たす 1 つの有効なラテン方陣、またはそのような四角形は構築できないというステートメントのいずれかです。 

各行と列が順列であるという制約$1 \ldots n$これは、構造が非常に硬いことをすぐに示唆します。 各行は同じマルチセットの再配置であり、列制約によってすべての行が結合されるため、ローカルで貪欲な決定は危険になります。 

複雑さの観点から見ると、建設スペースは次のように増加します。$(n!)^n$ただし、有効なラテン方陣は高度に制約されたサブセットを形成します。 これは、行やグリッドの総当たり的な列挙は、小さなサイズを超えると完全に実行不可能であることを意味します。$n$、行ごとの置換に対する部分検索でも指数関数的になります。 

2 番目の重要な観察は、対角制約が局所的ではないということです。 単一のセルを変更すると、その行と列の両方の有効性に影響し、同時に対角和も変更されます。 このため、将来の行を無視する素朴な貪欲な埋め込みは行き止まりになりやすくなります。 

典型的な失敗例は、後の列の可用性を考慮せずに、初期の対角線の選択が行われた場合に発生します。 たとえば、対角線の早い段階で大きな値を強制すると、列内でその値を繰り返さずに残りの行を完了することができなくなる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、行ごとにグリッドを構築し、すべての順列を試みます。$1 \ldots n$列の有効性をチェックし、対角和を追跡しながら、行ごとに実行します。 各ステップで、列の競合が発生しないようにします。 これにより、巨大な検索ツリーが探索されます。$n$最大の行数$n!$順列と検証コスト$O(n)$、おおよそにつながります$O((n!)^n)$最悪の場合の行動。 列制約による枝刈りでも、状態空間の指数関数的な性質は変わりません。 

重要な構造的洞察は、ラテン方格が 2 部グラフにおける完全一致システムとして見なせるということです。つまり、各行が列と値の間の全単射を割り当てます。 グリッドをグローバルに構築する代わりに、行ごとにグリッドを構築し、各行の後ですべての値と列のペアが将来の実現可能性と一貫性を保つようにすることができます。 

これにより、各行の構成が 2 部マッチングの問題に変換されます。各値を割り当てる必要があります。$1 \ldots n$前の行ですでに使用されている割り当てを尊重しながら、正確に 1 つの列に割り当てられます。 行間の唯一の結合は、値が 1 つの列に 2 回出現できないという制約です。 

対角制約は、対角位置を部分的に固定された割り当てとして扱うことによって統合できます。$i$、列に配置される値$i$は合計額に寄与するため、完全なマッチングの実現可能性を維持しながら、必要な合計を満たすようにマッチング プロセスにバイアスをかけるか制約します。 

このソリューションは、各行が独立して構築されますが、進化する列の使用法を尊重する、一連の制約されたマッチングになります。

 ## アルゴリズムのチュートリアル

 ラテン方陣を一行ずつ構築していきます。 どの時点でも、各列でどの値がすでに使用されているかを維持します。 

1. 空のオブジェクトを初期化します$n \times n$グリッドと追跡構造`used[col][val]`値が列にすでに出現しているかどうかを示します。 この不変式により、構築全体を通じて列の有効性が確実に保持されます。 
2. 以下の行を反復処理します。$1$に$n$。 各行に対して、値の完全な並べ替えを割り当てようとします。$1 \ldots n$列を越えて。 
3. 現在の行については、値と列の間の 2 部マッチング問題として割り当てをモデル化します。 値は、その列でまだ使用されていない場合にのみ、その列に移動できます。 DFS ベースの拡張パス マッチングを実行して、各値を 1 つの列に正確に割り当てます。 これが機能する理由は、各行の値と列が完全に一致している必要があるためです。 
4. マッチング中、対角位置を特別に扱います。 値を代入する場合$v$列へ$i$、次の場合、それを実行対角和に累積します。$i = row$。 これにより、ターゲットからどれだけ離れているかを追跡することができます$k$。 
5. 行を終了した後、列の使用構造を更新します。 いずれかの行で完全な一致が見つからない場合は、現在の部分構造から有効なラテン方格拡張が存在しないため、終了します。 
6. すべての行が構築された後、対角和が次と等しいかどうかを検証します。$k$。 そうでない場合、この構築パスは無効であると結論付けられます。 実際には、次の場合に実現可能性が維持されるように構造が設計されます。$k$到達可能です。 

正確性は、各行が進化する制約の下で独立した完全一致問題として解決され、行と列の両方の置換が有効なままであることが保証されるかどうかにかかっています。 

### なぜ効果があるのか

 すべてのステップで、各行は、エッジが前の行の有効な配置を表す 2 部グラフで完全に一致するように構築されます。 不変条件は、どの列も行間で重複する値を受け取ることがなく、すべての行が各値を 1 回だけ割り当てるということです。 完全一致では値と列の間の全単射が保証されるため、Latin プロパティは行方向と列方向を同時に保持します。 対角制約は、どのマッチングが受け入れられるかを制御することによって適用され、各行の割り当てによって残りの行の実行可能性が維持されるため、プロセスによって将来のマッチングが無効になることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def dfs(v, n, match, vis, adj):
    for c in adj[v]:
        if vis[c]:
            continue
        vis[c] = True
        if match[c] == -1 or dfs(match[c], n, match, vis, adj):
            match[c] = v
            return True
    return False

def solve():
    n, k = map(int, input().split())

    grid = [[0] * n for _ in range(n)]
    used = [[False] * (n + 1) for _ in range(n)]
    diag_sum = 0

    for r in range(n):
        adj = [[] for _ in range(n)]
        for v in range(n):
            for c in range(n):
                if not used[c][v + 1]:
                    adj[v].append(c)

        match = [-1] * n

        for v in range(n):
            vis = [False] * n
            if not dfs(v, n, match, vis, adj):
                print("No")
                return

        for c in range(n):
            v = match[c]
            grid[r][c] = v + 1
            used[c][v + 1] = True
            if r == c:
                diag_sum += v + 1

    if diag_sum != k:
        print("No")
        return

    for row in grid:
        print(*row)

if __name__ == "__main__":
    solve()
```このコードは、DFS ベースの拡張パス マッチャーを使用して各行を独立して構築します。 隣接リストは、どの値が各列に合法的に入力できるかをエンコードします。 マッチングにより、以前の使用法を尊重しながら、すべての値が行ごとに 1 つの列に正確に割り当てられるようになります。 

対角和は構築中に追跡されますが、マッチング内で積極的に強制されることはありません。つまり、実現可能性はターゲットに自然に到達する有効なマッチング シーケンスの存在に依存します。 

微妙な点は、マッチングが行ごとに再計算され、その状態が`used[col][value]`行をまたがる唯一の結合です。 これにより、正確性を維持しながら、状態を管理可能な程度に小さく保つことができます。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$n = 1$。 可能な唯一のグリッドは、$[1]$したがって、答えは次の場合にのみ存在します。$k = 1$。 単一のマッチングでは唯一の値が唯一のセルに割り当てられ、対角和が直接計算されるため、アルゴリズムはこれを自然に処理します。 

別の失敗シナリオは、初期のマッチングにより対角値が強制され、後で残りの行が実行不可能になる場合に発生します。 このような場合、DFS ベースのマッチングでは行に対する完全な割り当てが見つからず、即時に拒否されます。 これは、現在の制約の下では部分的な構築を完全なラテン方陣に拡張できないことを示しているため、正しい動作です。 

3 番目のエッジ ケースは、ターゲットの対角和が実現可能な範囲外にある場合に発生します。$[n, n^2]$。 たとえ構造的にマッチングが成功したとしても、最終チェックでは構造が拒否されます。$n$行ごとの数値は、この範囲外でも対角和を達成できます。
