 ## 解決策
 ## 問題の理解

 指定された配列かどうかを尋ねられます。`c`初期配列から開始して生成できます`[1]`現在の配列のサブシーケンスの合計に等しい新しい要素を繰り返し追加することによって。 サブシーケンスには 1 から配列のサイズまでの任意の長さを指定でき、サブシーケンス内の要素は連続している必要はありません。 各操作の後、新しい要素が配列内のどこかに追加されます。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、最終的な配列と配列自体のサイズが提供されます。 最終的な配列をこの方法で構築できる場合、出力は「YES」、それ以外の場合は「NO」になります。 

制約を考慮すると、`n`と同じ大きさにすることができます`2*10^5`テストケースごと、およびすべての合計`n`テストケース全体で次を超えない`2*10^5`。 これは、次の二次方程式の解を意味します。`n`遅すぎるでしょう。 おおよそ線形または線形演算、理想的にはテスト ケースごとに O(n log n) または O(n) が必要です。 の値`c`にも到達できます`2*10^5`したがって、カウントや周波数マップなどの操作は、その範囲を効率的に処理する必要があります。 

明らかではないエッジケースには、小さな値が繰り返されるシーケンスが含まれます。 たとえば、次のような配列`[1, 1, 1]`は、1 の部分列の合計を繰り返し加算してさらに 1 を生成できるため、有効です。 不注意なアプローチでは、要素が一意であるか単調であるかのみをチェックする可能性があり、そのようなシーケンスが誤って拒否される可能性があります。 もう 1 つの注意が必要なケースは次のような場合です。`c`1 より大きい要素が 1 つあります。たとえば、`[2]`; これは不可能です。`[1]`、最初の操作では常に少なくとも 2 つの要素が生成されるため、1 より大きい単一の要素が単独で現れることはありません。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての操作シーケンスをシミュレートしようとします。 から始まる`[1]`、各ステップで部分列のすべての合計を生成し、次の結果が得られるかどうかを確認できます。`c`。 原理的には正しいですが、サブシーケンスの数は配列のサイズに応じて指数関数的に増加するため、このアプローチは実行不可能です。 と`n`まで`2*10^5`、すべてのサブシーケンスを生成またはチェックすることは計算上不可能です。 

重要な洞察は、周波数マップを使用して問題に貪欲にアプローチできるということです。 配列を順方向に構築する代わりに、逆に考えることができます。`c`では、各要素がより小さな要素の組み合わせから得られるかどうかを尋ねます。 新しい各要素が、これまでの配列の現在の合計以下でなければならないことを観察すると、残りの最大の要素をより小さな要素の合計に分割することで常に「消費」するプロセスをシミュレートできます。 これにより、複数の数値セットを維持し、必要な数値と一致するまで最大の要素を繰り返し分割するという問題が軽減されます。 

実際には、次のすべての要素の合計から始めます。`c`すべての数字が揃うまで、それを 2 つの半分 (奇数の場合は床と天井) に分割し続けます。`c`が考慮されます。 これは、最大ヒープ (優先キュー) を使用して常に最大の数値を分割し、頻度マップを使用して各ターゲット数値が何回出現する必要があるかを追跡します。 ヒープ操作のため、アプローチは O(n log n) です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(2^n) | 遅すぎる |
 | ヒープを使用した逆貪欲 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての入力を読み取り、テスト ケースを保存します。 
2. 各テスト ケースについて、最終的な配列の合計を計算します。`c`。 この合計は、逆構造の最初の「要素」を表します。これは、どのシーケンスも、最終的にはこの合計を生成することから開始する必要があるためです。 
3. 合計のみを含む最大ヒープを作成します。 要素の頻度のカウンターを維持します。`c`。 
4. ヒープが空ではない場合:

 - 最大の要素をポップします`x`。 
- もし`x`の要素に一致します`c`正の周波数の場合は、周波数を減少させて続行します。 
- もし`x`1、または残りの最大要素より小さい`c`しかし、正確にはそうではありません`c`、生産することは不可能です`c`; 「いいえ」を返します。 
- それ以外の場合は分割`x`2つの部分に分けて、`x // 2`そして`x - x // 2`、両方をヒープに戻します。 これは生成をシミュレートします。`x`より小さな要素から。 
5. すべての要素を処理した後、すべての周波数が`c`ゼロの場合は「YES」を返します。 それ以外の場合は「NO」を返します。 

これが機能する理由: 不変条件は、各ステップで、残りの必要な数に一致するように分割できる可能性のある要素がヒープに含まれていることです。 最大のものを分割することで、残りより大きい数を見逃すことがなくなり、頻度マップによって有効なターゲットのみがカウントされることが保証されます。 いずれかの時点で数値を残りの要素に対応する要素に分割できない場合は、`c`、シーケンスは不可能です。 

## Python ソリューション```python
import sys
import heapq
from collections import Counter

input = sys.stdin.readline

def can_construct(c):
    freq = Counter(c)
    total = sum(c)
    max_heap = [-total]
    heapq.heapify(max_heap)
    
    while max_heap:
        x = -heapq.heappop(max_heap)
        if freq[x]:
            freq[x] -= 1
            continue
        if x == 1:
            return False
        a = x // 2
        b = x - a
        heapq.heappush(max_heap, -a)
        heapq.heappush(max_heap, -b)
    return all(v == 0 for v in freq.values())

t = int(input())
for _ in range(t):
    n = int(input())
    c = list(map(int, input().split()))
    print("YES" if can_construct(c) else "NO")
```この解決策は、ターゲット配列の合計を最大ヒープに変換することから始まります。 各反復では、必要な最大の要素の一致が試行されます。 要素が周波数マップ内にある場合、その要素は消費されます。 それ以外の場合は分割され、フォワード構築で合計がどのように形成されたかを反映します。 ヒープ内で負の数値を使用すると、Python の最小ヒープが最大ヒープとして動作できるようになります。 要素が一致しない、または 1 であるというエッジ ケースは、条件チェックによって自然に処理されます。
