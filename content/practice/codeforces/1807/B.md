 ## 解決策
 ## 問題の理解

 私たちはキャンディーの袋をいくつか持っています。 偶数個のキャンディーが入った袋は常にミハイに行き、奇数個のキャンディーが入った袋は常にビアンカに渡されます。 

袋の順番は決まっていません。 ゲームが始まる前に、好きなように並べ替えることができます。 袋が左から右に処理されるにつれて、各プレイヤーは受け取った袋からキャンディーを蓄積します。 

目標は、ゲームの開始前を除き、すべてのバッグが処理された後、ミハイのキャンディーの合計数がビアンカの合計よりも厳密に多くなるような順序付けが存在するかどうかを判断することです。 

制約は非常に小さいです。 各テスト ケースには最大 100 個のバッグがあり、最大 1000 個のテスト ケースがあります。 たとえ$O(n^2)$解決策は簡単に十分に高速になります。 課題は効率ではなく、有効な順序付けが存在するかどうかを決定する特性を認識することです。 

よくある間違いは、明示的な順序を構築して各ステップの後に不等式を維持することに重点を置くことです。 例えば：```
1
4
1 2 3 4
```貪欲なシミュレーションでは順序を見つけることができますが、問題は順序が存在するかどうかを尋ねるだけです。 もっと簡単な条件があります。 

もう 1 つの微妙なケースは、偶数のバッグが 1 つしかない場合です。```
1
4
1 1 1 2
```偶数キャンディーの合計は$2$, 一方、奇妙なキャンディーの合計は$3$。 最終的にはビアンカの合計がミハイを上回るため、ミハイが永遠に先を行くことはできません。 正しい答えは、`NO`。 

3 番目のエッジ ケースは、すべてのバッグが奇数である場合です。```
1
3
1 3 5
```最初に処理されたバッグはビアンカに送られる必要があり、ミハイの合計は$0$そしてビアンカは肯定的です。 必要な不等式はすぐに失敗します。 正しい答えは、`NO`。 

最後に、次のことを考慮してください。```
1
3
2 2 1
```偶数の合計は$4$そして奇数の和は$1$。 正しい答えは、`YES`。 最大の偶数値と最大の奇数値を比較するだけの不注意なアプローチでは、これを見逃してしまいます。 

## アプローチ

 最も直接的な強引なアイデアは、バッグのあらゆる組み合わせを試してゲームをシミュレートすることです。 順列ごとにバッグを 1 つずつ処理し、ミハイとビアンカの合計を更新し、各ステップ後にミハイが厳密に先行しているかどうかを確認します。 

このアプローチは、考えられるすべての順序を検査するため、正しいです。 問題は、$n!$順列。 たとえ$n = 10$、これはすでに約 360 万の順列になります。 のために$n = 100$、それはまったく不可能です。 

より良い解決策を見つけるには、実際に何が重要なのかを理解する必要があります。 

すべての偶数のバッグを最初に配置するとします。 それらのバッグのそれぞれは、ミハイの合計だけを増やします。 これがアドバンテージを築く最善の方法であることは明らかです。 すべての偶数袋を処理した後、ミハイは偶数袋の全額を集めましたが、ビアンカはまだ何も集めていません。 

これで、奇数のバッグを任意の順序で処理できるようになりました。 奇妙なバッグはすべて、ビアンカの合計のみ増加します。 ミハイの合計は二度と変わりません。 

この観察は非常に重要です。 すべての偶数バッグの合計がすべての奇数バッグの合計より大きい場合、最初にすべての偶数バッグを処理した後、ミハイはビアンカの最終的な最終合計よりも大きいリードで奇数フェーズを開始します。 ビアンカは決して追いつけないので、中間状態もすべて安全です。 

偶数バッグの合計が奇数バッグの合計以下の場合、プロセス全体の終了時点で、ミハイの合計はビアンカの合計より厳密には大きくなりません。 この要件はすべてのステップの後に成立する必要があるため、最後のステップの後にも必ず成立する必要があります。 そのような順序は存在しません。 

問題全体は 2 つの合計を比較することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n! \cdot n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの場合、2 つの変数を初期化します。`even_sum`そして`odd_sum`。 
2. すべてのバッグを調べます。 
3. 袋に偶数個のキャンディーが入っている場合、その値を`even_sum`。 
4. それ以外の場合は、その値を`odd_sum`。 
5. すべてのバッグを処理した後、2 つの合計を比較します。 
6. もし`even_sum > odd_sum`、印刷`YES`。 
7. それ以外の場合は、印刷します`NO`。 

なぜ効果があるのか:

 最終的な合計は、順序に関係なく固定されます。 ミハイは常に偶数値のバッグの合計で終了し、ビアンカは常に奇数値のバッグの合計で終了します。 

もし`even_sum <= odd_sum`、必要な不等式は最終状態ですでに失敗しているため、順序付けは機能しません。 

もし`even_sum > odd_sum`、すべての偶数バッグをすべての奇数バッグの前に置きます。 最初のフェーズでは、ビアンカの合計はゼロのままですが、ミハイの合計は増加します。 第 2 フェーズでは、ミハイの合計は次のようになります。`even_sum`、ビアンカの累計は決して超えることはありません`odd_sum`。 以来`even_sum > odd_sum`, ミハイはプロセス全体を通して厳密に先行し続けます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    even_sum = 0
    odd_sum = 0

    for x in a:
        if x % 2 == 0:
            even_sum += x
        else:
            odd_sum += x

    print("YES" if even_sum > odd_sum else "NO")
```解決策は証明に直接続きます。 

このループは、パリティに従ってすべてのバッグ値を 2 つのグループに分割します。`even_sum`はミハイの最終的な合計を表しますが、`odd_sum`ビアンカの最終的な合計を表します。 

すべての値が処理された後は、比較が 1 回だけ必要になります。 厳密な不平等が重要です。 使用する`>=`このステートメントでは、最終状態を含め、すべての有効な時点で厳密にさらに多くのキャンディーをミハイが持つ必要があるため、このステートメントは間違っています。 

空のパリティ グループに対して特別な処理は必要ありません。 均等な袋がない場合は、`even_sum`がゼロになり、比較により当然正しい結果が得られます。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        even_sum = sum(x for x in a if x % 2 == 0)
        odd_sum = sum(x for x in a if x % 2 == 1)

        ans.append("YES" if even_sum > odd_sum else "NO")

    sys.stdout.write("\n".join(ans))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run(
"""3
4
1 2 3 4
4
1 1 1 2
3
1 4 3
"""
) == "YES\nNO\nNO"

# minimum size
assert run(
"""1
1
2
"""
) == "YES"

# single odd bag
assert run(
"""1
1
1
"""
) == "NO"

# all equal even values
assert run(
"""1
5
2 2 2 2 2
"""
) == "YES"

# equality boundary
assert run(
"""1
2
1 1
"""
) == "NO"

# larger mixed case
assert run(
"""1
6
2 4 6 1 3 5
"""
) == "YES"

 ## 特殊なケース

 ### すべてのバッグは奇妙です

 入力:```
1
3
1 3 5
```アルゴリズムは以下を計算します。 

| 偶数合計 | 奇数合計 |
 | --- | --- |
 | 0 | 9 |

 以来`0 > 9`false の場合、出力されます`NO`。 

これは現実と一致します。 最初に処理されたバッグはビアンカに行かなければならないため、初手以降はミハイが厳密に先行することはできません。 

### 合計が等しい

 入力:```
1
2
1 1
```アルゴリズムは以下を計算します。 

| 偶数合計 | 奇数合計 |
 | --- | --- |
 | 0 | 2 |

 答えは`NO`。 

より一般的には、2 つの合計が等しいときは常に、最終状態ではミハイとビアンカが同点になります。 条件としてはミハイが厳密に有利であることが求められており、平等は認められない。 

### 偶数バッグは 1 つだけ

 入力:```
1
4
1 1 1 2
```アルゴリズムは以下を計算します。 

| 偶数合計 | 奇数合計 |
 | --- | --- |
 | 2 | 3 |

 答えは`NO`。 

たとえ 2 個のキャンディーが入った袋が最初に置かれたとしても、ミハイの最終的な合計はまだ 2 個にすぎません。ビアンカは最終的に 3 個に達するため、必要な不等式は最後まで成立しません。 

### 大きな均等な利点

 入力:```
1
3
2 2 1
```アルゴリズムは以下を計算します。 

| 偶数合計 | 奇数合計 |
 | --- | --- |
 | 4 | 1 |

 答えは`YES`。 

偶数のバッグを最初に置きます。`[2, 2, 1]`。 

バッグを処理した後の累計は次のようになります。 

| ステップ | ミハイ | ビアンカ |
 | --- | --- | --- |
 | アフター2 | 2 | 0 |
 | アフター2 | 4 | 0 |
 | 1以降 | 4 | 1 |

 ミハイはコンディションの予測通り、終始厳密に先頭を走り続けた`even_sum > odd_sum`。
