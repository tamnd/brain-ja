 ## 解決策
 ## 問題の理解

 小文字で構成される文字列が与えられ、文字クラス全体を繰り返し 2 進数に「折りたたむ」ことができます。 1 つの操作で文字を選択するとします。`x`、そして、出現するすべての要素をグローバルに書き換えます。`x`文字列のいずれかに`0`または`1`。 異なる文字を個別にマッピングでき、各文字を選択した時点で 2 つのバイナリ値のうちの 1 つを正確に割り当てることができます。 

すべての文字にバイナリ値を割り当てた後、結果の文字列はバイナリ文字列になります。 目標は、この最終的なバイナリ文字列が完全に交互になるように、つまり隣接する文字のペアがすべて異なるように割り当てを選択できるかどうかを判断することです。 

重要な問題は、文字列構造を位置レベルで直接編集できないことです。 個々の文字を反転することはできません。 代わりに、各文字は、その出現箇所すべてにわたって一貫してマッピングされる必要がある厳格なブロックとして機能します。 

制約の範囲は狭く、テスト ケースあたりの合計の長さは最大 2000、テスト ケースの数は最大 100 です。 これにより、テスト ケースごとにおよそ 2 次までの任意の解が可能になりますが、定数が低い場合は 3 次の解でもほとんど合格しない可能性があります。 ただし、問題の構造は、はるかに単純な実現可能条件が存在することを強く示唆しています。 

交互のパターンで異なるバイナリ値が必要となる両方の位置に文字が出現する場合、微妙なエッジ ケースが発生します。 たとえば、`aa`、どのようにマッピングしても`a`、結果は常に`00`または`11`、どちらも無効です。 これは、競合するパリティ位置間での文字の重複が中心的な障害であることをすぐに示しています。 

もう 1 つの特殊なケースは、長さ 1 の文字列です。 任意の 1 文字を次のいずれかにマッピングできます。`0`または`1`、両方とも定義上有効な代替文字列です。 

## アプローチ

 ブルートフォースの観点は、それぞれの個別の文字をバイナリ変数として考えることから始まります。 あれば`k`個別の文字の場合、それぞれに次のいずれかを割り当てます。`0`または`1`、生産`2^k`課題。 割り当てごとに、結果の文字列を構築し、それが交互に現れるかどうかを確認します。`O(n)`時間。 これにより、全体的な複雑さが生じます。`O(n · 2^k)`。 最悪の場合、すべての文字が区別できるため、`k = n`、検索空間は指数関数的になり、`n = 20`、ましてや`2000`。 

重要な観察は、交互は隣接性制約のみに依存するということです。 あらゆるインデックスに対して`i`、私たちは必要とします`s[i] != s[i+1]`マッピング後。 2つのポジションの場合`i`そして`i+1`同じ元の文字が含まれている場合、マッピング後にそれらは等しくなる必要があり、これはただちに交互に違反します。 したがって、隣接する 2 つの位置に文字が出現すると、答えは不可能になります。 

より一般的に、パリティ構造を見ると、その文字のすべての出現がグローバルに交互に配置される必要がある位置に一貫して収まるように、各文字に値を割り当てようとしていることがわかります。 ただし、交互制約はアルファベットの構造にはまったく依存せず、文字列に繰り返し隣接する文字が隠れて含まれているかどうかのみに依存します。 

これにより、大幅に単純化されます。構築が失敗する唯一の方法は、隣接する位置に文字が出現する場合です。 そのような隣接関係が存在しない場合は、必要な交互パターンを選択し、最初の出現位置のパリティに従って各文字を一貫してマッピングすることで、常に有効な交互バイナリ文字列を構築できます。 どの文字も隣接する 2 つの同じ結果を強制することはないため、一貫性は常に達成可能です。 

したがって、問題は、インデックスが存在するかどうかを確認する 1 回のスキャンに帰着します。`i`そのような`s[i] == s[i+1]`。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、文字列を読み取ります。`s`。 局所構造を検査するだけなので、前処理は必要ありません。 
2. 文字列を左から右にスキャンし、各文字を次の文字と比較します。 これが機能する理由は、交互は隣接するものの間でのみ定義されるため、違反は隣接制約に起因する必要があるためです。 
3. もし見つけたら`s[i] == s[i+1]`、答えはすぐに結論づけられます。`"NO"`。 これは、同じ文字が両方出現すると必然的に同じバイナリ値にマッピングされ、隣接する等しいビットが生成され、交互が壊れるためです。 
4. 隣接する等しい文字が見つからずにスキャンが完了した場合、出力`"YES"`。 この場合、境界で矛盾を強制する文字がないため、交互パターンを尊重する方法で常に一貫してバイナリ値を割り当てることができます。 

### なぜ効果があるのか

 重要な唯一の制約は、文字によって 2 つの隣接する位置が等しくなるかどうかです。 このような制約が存在する場合、どのように割り当てても変更は不可能です。`0`そして`1`。 そのような制約が存在しない場合、隣接するすべての文字が 2 つの異なる文字に接続され、エッジを越えて強制的に等しくなる文字がないため、誘導されたバイナリ文字列が交互になるようにバイナリ値を自由に割り当てることができます。 これにより、グローバル割り当ての問題が純粋にローカルなチェックに軽減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        ok = True
        for i in range(n - 1):
            if s[i] == s[i + 1]:
                ok = False
                break
        
        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()
```このソリューションは、各テスト ケースを個別に読み取り、単一のリニア スキャンを実行します。 重要な実装の詳細は、これ以上検査しても結果を変えることができないため、繰り返される隣接する文字が見つかったらすぐに停止することです。 

実現可能性は代入のシミュレーションではなく、構造上の不可能性の検出のみに依存するため、ロジックではバイナリ文字列を明示的に構築しようとしません。

 ## 特殊なケース

 単一文字の場合は、違反する隣接制約がないため、長さ 1 の文字列が常に成功することを示しています。 アルゴリズムは文字列を読み取りますが、何も見つかりません`i`そのような`s[i] == s[i+1]`、そして戻ります`"YES"`すぐに。 

次のような 2 つの等しい文字の場合`aa`最初の比較時に失敗条件をトリガーします。 スキャンで検出されるのは、`s[0] == s[1]`、フラグを false に設定し、停止します。 これは、隣接する同一の文字を交互のバイナリ値に分離することが不可能であることを正確に捉えています。 

隣接する文字が繰り返されていない長い文字列。`abcabcabc`、条件をトリガーせずに合格し、グローバルな実現可能性がローカルの隣接構造によって完全に決定されることを確認します。
