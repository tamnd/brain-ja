 ## 解決策
 ## 問題の理解

 内部でボールが動いています`n × m`長方形のグリッド。 ボールは常に斜めに移動するため、移動するたびに両方の座標が次のように変化します。`±1`。 

方向は垂直成分と水平成分で構成されます。 例えば、`DR`行と列の両方を増やすことを意味しますが、`UL`両方を減らすことを意味します。 次の動きがグリッドから離れるたびに、対応する方向の成分が反転されます。 上壁または下壁にぶつかると、垂直コンポーネントが反転します。 左右の壁に当たると水平成分が反転します。 コーナーに到達すると両方が反転します。 

仕事は歩数を数えることではありません。 ボールがターゲット セルに初めて到達する前に、バウンドが何回発生したかをカウントする必要があります。 ボールがそのセルに到達しない場合は、次のように出力します。`-1`。 

最も重要な制約は、すべてのテスト ケースにわたるすべてのグリッド サイズの合計が最大でも`5 · 10^4`。 それは驚くほど小さいです。 たとえ個々の次元が達成できたとしても`25000`、すべてのテスト ケースにわたるセルの合計数は制限されています。 これは、同じ状態を無期限に再訪することを避ければ、動きのシミュレーションが実現可能であることを強く示唆しています。 

微妙な点は、セルに入った後にボールがバウンドすることです。 方向が変わる前に、セル自体が訪問されます。 最初に反映してから位置を確認するシミュレーションでは、誤った答えが生成される可能性があります。 

もう 1 つの微妙な点は、ボールがターゲット セルを決して含まないサイクルに入る可能性があることです。 運動は決定論的であるため、一度同じ状態が現れると未来は永遠に繰り返される。 

考慮する：```
2 4
start = (2,1), DR
target = (2,2)
```ボールは次のように動きます。```
(2,1) -> (1,2) -> (2,3) -> (1,4) -> ...
```細胞`(2,2)`決して訪れません。 サイクル検出を行わないシミュレーションは永久に実行されてしまいます。 正しい答えは、`-1`。 

もう 1 つの簡単な間違いは、ターゲットに到達する前にバウンスを数えるのではなく、バウンスを数えるということです。 

例：```
3 3
start = (1,3), UR
target = (2,2)
```ボールが最初に届く`(2,2)`上の壁で一度跳ねた後。 答えは`1`。 シミュレーションを続行し、その後のバウンスをカウントすると、結果は不正確になります。 

3 番目のコーナーケースは、開始位置がすでにターゲットに等しい場合に発生します。 

例：```
3 3
start = (2,2), DR
target = (2,2)
```答えは`0`なぜなら、ボールは動きが起こる前にすでにそこにあるからです。 

## アプローチ

 簡単なシミュレーションでボールを一度に 1 歩ずつ追跡します。 移動するたびに位置を更新し、必要なリフレクションを実行し、バウンスをカウントします。 

運動規則は決定論的であるため、このアプローチは正しいです。 問題は、ボールが繰り返すまでに非常に長い時間移動する可能性があることです。 寸法は次のように大きくすることができるため、`25000`、純粋なステップバイステップのシミュレーションでは、何百万もの移動が必要になる可能性があります。 

重要な観察は、バウンスの間に興味深いことは何も起こらないということです。 

ボールが現在次の場所にあるとします。`(r,c)`何らかの方向性を持って。 壁にぶつかるまでは、ただ斜めにまっすぐ進みます。 そのセグメント中、行と列はステップごとに同じ量だけ変化します。 

すべての動きをシミュレートする代わりに、次のバウンスに直接ジャンプできます。 させて```
dr ∈ {+1,-1}
dc ∈ {+1,-1}
```現在の方向を表します。 

次の垂直壁までの距離は次のように決定されます。`dr`:```
if dr = +1: n - r
if dr = -1: r - 1
```同様に、次の水平壁までの距離は次のようになります。```
if dc = +1: m - c
if dc = -1: c - 1
```これら 2 つの距離のうち小さい方が、次のバウンス イベントまでに残っている斜めのステップの数を示します。 

この対角線のセグメントに沿って移動しているときに、行と列の両方のオフセットが一致すると、ターゲットに正確に到達します。 すべての中間セルをステップ実行することなく、これを代数的にテストできます。 

バウンス位置にジャンプした後、必要な方向コンポーネントを反転し、バウンスカウンターを増加させて続行します。 

システムの状態は次のとおりです。```
(row, column, direction)
```あるのは`4nm`可能な状態。 状態が繰り返されると、将来の軌道も同様に繰り返されます。 合計から`nm`すべてのテストで最大でも`5 · 10^4`、訪問した州を簡単に保存できます。

 | ブルートフォース | O(手数) | お(1) | 遅すぎる |
 | 最適 | O(バウンス状態の数) ≤ O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 方向文字列を 2 つのコンポーネントに変換します`dr`そして`dc`、それぞれに等しい`+1`または`-1`。 
2. 開始セルがすでにターゲットセルと等しい場合は、戻り値を返します。`0`。 
3. 訪問した州のセットを維持する`(row, column, dr, dc)`。 
4. 状態を処理する前に、その状態がすでに表示されているかどうかを確認します。 そうなった場合、軌道はサイクルに入り、ターゲットには決して到達できません。 戻る`-1`。 
5. 次の垂直壁と次の水平壁までのステップ数を計算します。 
6. しましょう`k`これら 2 つの値のうち小さい方の値になります。 ボールは正確に飛びます`k`次のバウンスイベントの前に斜めのステップ。 
7. ターゲットがこの対角線上にあるかどうかを確認します。 両方の座標が直線的に移動するため、次の場合にセグメント中にターゲットに到達します。 

-`(i2 - row)`と同じ符号を持っています`dr`、
 -`(j2 - col)`と同じ符号を持っています`dc`、
 - 必要な行と列のオフセットが等しい。 

ターゲットが次の範囲内にある場合`k`ステップの場合、現在のバウンス数を返します。 
8. ボールをバウンス位置に直接移動します。```
row += dr * k
col += dc * k
```9. バウンス位置が上または下の境界線にある場合は、反転します。`dr`。 
10. バウンス位置が左右の境界線上にある場合は、反転します。`dc`。 
11. バウンス数を 1 つ増やし、ステップ 4 から続けます。 

### なぜ効果があるのか

 2 つの連続したバウンドの間で、ボールは 1 つの真っ直ぐな対角線をたどります。 そのセグメント上で訪問されるすべてのセルは、行オフセットと列オフセットの間の固定線形関係を満たします。 ターゲットがそのセグメントに属しているかどうかを確認するだけで、次のバウンスまでにターゲットに到達するかどうかを判断できます。 

すべての中間位置が検査対象の対角セグメント上にあるため、シミュレーションは常に、考えられるターゲットの発生をスキップすることなく、あるバウンス状態から次のバウンス状態にジャンプします。 

動きは決定的です。 一度州になると`(row, column, dr, dc)`繰り返されると、将来のすべての状態も同様に繰り返されます。 繰り返しの前にターゲットが見つからなかった場合、後で見つかることはありません。 これにより、返品が保証されます。`-1`繰り返し状態の場合は正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

DIR = {
    "DR": (1, 1),
    "DL": (1, -1),
    "UR": (-1, 1),
    "UL": (-1, -1),
}

def solve():
    t = int(input())

    for _ in range(t):
        n, m, r, c, tr, tc, d = input().split()

        n = int(n)
        m = int(m)
        r = int(r)
        c = int(c)
        tr = int(tr)
        tc = int(tc)

        dr, dc = DIR[d]

        if r == tr and c == tc:
            print(0)
            continue

        visited = set()
        bounces = 0
        answer = -1

        while True:
            state = (r, c, dr, dc)

            if state in visited:
                break

            visited.add(state)

            dv = (n - r) if dr == 1 else (r - 1)
            dh = (m - c) if dc == 1 else (c - 1)

            k = min(dv, dh)

            row_diff = tr - r
            col_diff = tc - c

            if row_diff * dr >= 0 and col_diff * dc >= 0:
                if row_diff == col_diff * dr * dc:
                    steps = abs(row_diff)
                    if steps <= k:
                        answer = bounces
                        break

            r += dr * k
            c += dc * k

            bounced = False

            if r == 1 or r == n:
                dr *= -1
                bounced = True

            if c == 1 or c == m:
                dc *= -1
                bounced = True

            if bounced:
                bounces += 1

        print(answer)

solve()
```方向文字列は 2 つの符号付きコンポーネントに変換されます。 これにより、水平な壁からの反射は変化するだけなので、反射が非常に簡単になります。`dr`、垂直の壁で跳ね返されると変化するだけです`dc`。 

核となるアイデアはジャンプの長さです`k`。 すべての動きをシミュレートするのではなく、壁に触れる前にボールがどれくらいの距離を移動できるかを計算します。 その対角線セグメント全体が一度に処理されます。 

ターゲットチェックは最もデリケートな部分です。 対角線のセグメントに沿って、両方の座標は大きさがまったく同じステップ数だけ変化します。 平等```
row_diff == col_diff * dr * dc
```は、その要件を 4 方向すべてに対して同時にエンコードします。 

もう 1 つの微妙な詳細は、バウンス数のタイミングです。 まず、ターゲットが現在のセグメント上にあるかどうかを確認します。 存在する場合、答えはすでに発生したバウンスの数になります。 バウンス位置に到達した後にのみ、バウンスカウンターがインクリメントされます。 

サイクル検出は完了状態を使用します`(row, column, dr, dc)`。 異なる方向で同じセルに到着すると、将来の軌道が異なる可能性があるため、位置のみを使用するのは正しくありません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm) | 各状態は最大 1 回処理されます。 
| スペース | O(nm) | 訪問済み状態セット |

 可能な状態の数は最大で`4nm`, 各セルは 4 方向に組み合わせることができるためです。 この問題は、すべての合計が次のことを保証します。`nm`テスト ファイルの値は最大でも`5 · 10^4`、したがって、合計作業量は問題なく制限内に収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    DIR = {
        "DR": (1, 1),
        "DL": (1, -1),
        "UR": (-1, 1),
        "UL": (-1, -1),
    }

    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n, m, r, c, tr, tc, d = input().split()

        n = int(n)
        m = int(m)
        r = int(r)
        c = int(c)
        tr = int(tr)
        tc = int(tc)

        dr, dc = DIR[d]

        if (r, c) == (tr, tc):
            out.append("0")
            continue

        vis = set()
        b = 0
        ans = -1

        while True:
            state = (r, c, dr, dc)

            if state in vis:
                break

            vis.add(state)

            dv = (n - r) if dr == 1 else (r - 1)
            dh = (m - c) if dc == 1 else (c - 1)

            k = min(dv, dh)

            rd = tr - r
            cd = tc - c

            if rd * dr >= 0 and cd * dc >= 0:
                if rd == cd * dr * dc:
                    if abs(rd) <= k:
                        ans = b
                        break

            r += dr * k
            c += dc * k

            if r == 1 or r == n:
                dr *= -1

            if c == 1 or c == m:
                dc *= -1

            b += 1

        out.append(str(ans))

    return "\n".join(out)

 ## 特殊なケース

 ### 開始位置はすでに目標です

 入力:```
1
3 3 2 2 2 2 DR
```アルゴリズムは、シミュレーション ループに入る前にこの条件をチェックします。 移動は必要ないため、次のように出力されます。```
0
```このチェックがないと、シミュレーションは継続して実行され、より大きな値が返される可能性があります。 

### ターゲットがサイクルに出現しない

 入力:```
1
2 4 2 1 2 2 DR
```トレース：```
(2,1,DR)
→ (1,2,UR)
→ (2,3,DR)
→ (1,4,UR)
→ (2,3,DL)
→ ...
```最終的には、以前に見られた状態が再び現れます。 ターゲット`(2,2)`処理された対角線セグメントには決して属していないため、アルゴリズムは次の値を返します。```
-1
```繰り返し状態チェックにより、無限ループが防止されます。 

### セグメントの終わりに正確に目標に到達しました

 入力:```
1
6 4 1 2 3 4 DR
```最初の対角線セグメントの長さは`k = 2`:```
(1,2) → (2,3) → (3,4)
```ターゲットはそのセグメントの最後のセルです。 ターゲットチェックでは`steps <= k`、エンドポイントが含まれており、アルゴリズムは正しく出力します。```
0
```厳密な不等式を使用すると、このケースが誤って見逃されてしまいます。 

### コーナーバウンス

 入力:```
1
2 2 1 1 1 2 UL
```ボールは方向から始まります`UL`、すぐに角に到達します`(1,1)`バウンス状態であり、コーナーが処理されるときに両方向成分が一緒に反転されます。 

この実装は、上または下の境界に触れると垂直コンポーネントを反転し、左または右の境界に触れると水平コンポーネントを個別に反転します。 コーナーは自然に両方のフリップを引き起こし、問題のルールに正確に一致します。
