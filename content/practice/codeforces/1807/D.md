 ## 解決策
 ## 問題の理解

 整数の配列と一連のクエリが与えられます。 各クエリは、特定の部分配列内のすべての要素を固定値で上書きした場合、配列の合計が奇数になるかどうかを尋ねます。 クエリは配列を永続的に変更しません。 各クエリについて、仮定の上書き後の合計が奇数の場合は「YES」、偶数の場合は「NO」が必要です。 

配列のサイズ$n$クエリ数は最大 200,000 に達する可能性があります$q$200,000 にすることもできますが、すべての合計$n$そしてすべて$q$全体のテストケースは 200,000 未満にとどまります。 これは、クエリごとではなく、テスト ケースごとに線形作業を行う余裕があることを意味します。 アン$O(n \cdot q)$最悪の場合、$4 \cdot 10^{10}$操作。 

考慮すべきエッジ ケースには、非常に小さな配列、配列全体をカバーするクエリ、置換値が非常に大きいクエリなどがあります。 たとえば、配列が次の場合、`[2]`クエリでは、唯一の要素を次のように設定するよう求められます。`1`、合計は次のようになります`1`これは奇妙ですが、答えは「YES」です。 クエリごとに配列全体の合計を再計算する単純なアプローチは、小さな配列では機能しますが、大きな配列では失敗します。 

もう 1 つの微妙な点は、**パリティ** のみを考慮していることです。 大きな数自体は完全な算術演算を必要としません。 奇数か偶数かが分かれば十分です。 よくある間違いは、大きな数値を使用して合計を計算することで、オーバーフローや不必要な計算の危険性があります。 

## アプローチ

 ブルートフォース手法では、クエリ範囲を反復し、要素を置換し、合計を計算し、パリティをチェックします。 これは問題を正確にシミュレートするため機能します。 クエリごとに、最大で次のことを実行できます。$r - l + 1$サイズ 200,000 の配列に対して 200,000 のクエリを実行すると、最悪のケースが発生します。$O(n \cdot q) = O(4 \cdot 10^{10})$が遅すぎます。 

重要な洞察は、全額ではなく**パリティ**のみが必要であるということです。 要素を置換する代わりに、古い合計から置換された要素の合計と新しい値の合計を引いたものとして新しい合計を計算できます。 置換される範囲の長さを次のようにします。$m = r - l + 1$。 新しい合計のパリティは次のとおりです。```
new_sum_parity = (old_sum - sum_of_range + m * k) % 2
```パリティのみが重要であるため、減算と加算はモジュロ 2 で実行できます。各要素のモジュロ 2 は 0 または 1 です。元の範囲のモジュロ 2 の合計は、プレフィックス合計配列モジュロ 2 を使用して事前に計算できます。置換値の乗算$k$範囲の長さによって$m$モジュロ 2 は単純に$0$もし$k$偶数であるか、$m % 2$もし$k$奇数です。 

この観察により、クエリ処理が次のように削減されます。$O(1)$元の配列のプレフィックスの合計を計算した後、クエリごとに。 これは、指定された制約に対して効率的に機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * q) | O(n) | 遅すぎる |
 | 最適 | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 を法とする配列全体の合計を計算します。これは、配列の現在のパリティを表します。 偶数の場合は 0、奇数の場合は 1 だけが必要です。 
2. 2 を法とするプレフィックス合計配列を計算します。`prefix[i]`最初の和を法とする2になります`i`要素。 これにより、任意のサブ配列の合計パリティに対して O(1) クエリが可能になります。`[l, r]`を使用して`prefix[r] - prefix[l-1]`モジュロ 2。 
3. クエリごとに`(l, r, k)`、長さを計算します`m = r - l + 1`。 プレフィックス合計配列から 2 を法とする範囲合計のパリティを計算します。 
4. パリティを計算します。`m * k`。 これは`0`もし`k`偶数である、または`m % 2`もし`k`奇数です。 
5. 新しい配列パリティを次のように計算します。`(total_parity - range_parity + replacement_parity) % 2`。 
6. 結果が 1 の場合は、「YES」を出力します。 それ以外の場合は、「NO」を出力します。 

これが機能する理由: すべての算術演算は 2 を法として行われます。不変条件は、2 を法とする加算と減算のシーケンスが正しいパリティを与えるということです。 各クエリは独立しているため、実際の配列を変更することはなく、事前に計算されたプレフィックスの合計と配列の合計のパリティのみに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        prefix = [0] * (n + 1)
        total_parity = 0
        for i in range(n):
            prefix[i + 1] = (prefix[i] + a[i]) % 2
            total_parity = (total_parity + a[i]) % 2

        for _ in range(q):
            l, r, k = map(int, input().split())
            m = r - l + 1
            range_parity = (prefix[r] - prefix[l - 1]) % 2
            replacement_parity = (m % 2) if (k % 2 == 1) else 0
            new_parity = (total_parity - range_parity + replacement_parity) % 2
            print("YES" if new_parity == 1 else "NO")

if __name__ == "__main__":
    solve()
```このコードは、最初に 2 を法とするプレフィックスの合計を計算して、サブ配列パリティ クエリを迅速に実行できるようにします。 次に、各クエリは O(1) で処理され、全体のパリティに対する範囲の置換の影響が計算されます。 微妙なポイントとしては、`l-1`1 から始まるインデックスのプレフィックス配列内で、大きな数を避けるためにすべての算術モジュロ 2 を削減します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q) | プレフィックス合計の計算は O(n)、各クエリは O(1) |
 | スペース | O(n) | プレフィックスの合計を法 2 でストアする |
