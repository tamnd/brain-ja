 ## 解決策
 ## 問題の理解

 各テスト ケースは、タスクのリストを受け取る非常に小さなスケジューリング システムを記述します。 すべてのタスクには識別子と優先度の値があり、システムはタスクが実行される順序を決定する必要があります。 

重要な点は、タスクがシステムに挿入された順序ですでに与えられているということです。 2 行目にはその挿入オーダーのタスク ID がリストされ、3 行目には各タスクの対応する優先度が示されます。 スケジューリングでは、常に優先度の値が最も小さいタスクが最初に選択されます。 複数のタスクが同じ優先度を共有する場合、システムは以前に挿入されたタスクを選択することによって関係を解除します。 

したがって、出力は、このルールに基づいて実行される順序で配置された、入力タスク ID の単純な並べ替えです。 

制約は非常に小さいです。 テスト ケースごとにタスクが最大 100 個、テスト ケースが最大 10 個ある場合、O(n^2) の並べ替えアプローチであっても、制限内で実行するのは簡単です。 これにより、このソリューションには標準の並べ替えを超える高度なデータ構造や最適化が必要ないことがすぐに分かります。 

複数のタスクが同じ優先順位を共有する場合、微妙なエッジケースが発生します。 このような状況では、正確さは元の広告掲載オーダーを保存するかどうかに完全に依存します。 たとえば、入力が次の場合、

 ID: 7 3 9

 優先順位: 5 1 5

 この場合、優先度 1 によりタスク 3 が最初に実行される必要があり、タスク 7 と 9 (両方とも優先度 5) の間では、7 の方が先に出現するため、9 よりも先に実行される必要があります。 優先順位のみで並べ替える単純なアプローチでは、7 と 9 が誤って交換されてしまいます。 

## アプローチ

 スケジューラをシミュレートする最も直接的な方法は、リストを繰り返しスキャンし、最も優先度の低い残りのタスクを選択することです。 タスクを選択するたびに、そのタスクに削除済みのマークが付けられ、続行されます。 これはスケジューラの定義に正確に従っているため、これは正しいです。 

ただし、各選択では、残りのすべてのタスクをスキャンして最小優先度を見つける必要があります。 n 個のタスクがある場合、これは n 個の選択を意味し、それぞれのコストは O(n) となり、テスト ケースごとに O(n^2) になります。 ここでは n が 100 のみですが、このアプローチは不必要な作業であり、より大きな制約に拡張すると概念的に扱いにくくなります。 

重要な点は、スケジューラが複合キーによるタスクの並べ替えと同等であるということです。 主キーは優先度、副キーは挿入順序です。 元のインデックスを各タスクに添付すると、これら 2 つのフィールドを使用して 1 回のパスですべてのタスクを並べ替えることができます。 2 つのタスク間の比較はこれらのルールによって完全に決定されるため、並べ替え操作によりすべてのスケジュール決定が自然に解決されます。 

したがって、問題は、トリプルのリストを構築し、(優先順位、インデックス) による安定した並べ替えを実行することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース選択 | O(n^2) | O(n) | 承認済み |
 | (優先度、インデックス) で並べ替え | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. タスク ID のリストと優先度のリストを読み取ります。 インデックスがタイブレーク ルールを表すため、各タスクをその挿入インデックスとペアにします。 
2. 各タスクの優先度、インデックス、ID を格納する構造を構築します。 インデックスは元の到着順序をエンコードするため、非常に重要です。 
3. 最初に優先度を調べ、次にインデックスを調べる比較を使用して、すべてのタスクを並べ替えます。 インデックスにより、同じ優先順位の中で、より早いタスクがより前に残ることが保証されます。 
4. ソート後、タスクIDを順番に抽出して出力します。 

ここで並べ替えが機能する理由は、タスクがこれら 2 つの基準によってグローバルにランク付けされると、すべてのスケジュール決定が独立しているためです。 優先順位やタスクセットには動的な変更がないため、グローバルな順序付けによって実行順序が完全に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []
    
    for _ in range(T):
        n = int(input())
        ids = list(map(int, input().split()))
        pr = list(map(int, input().split()))
        
        tasks = []
        for i in range(n):
            tasks.append((pr[i], i, ids[i]))
        
        tasks.sort()
        
        res = [str(task[2]) for task in tasks]
        out.append(" ".join(res))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、まず各タスクにそのインデックスを付加し、挿入順序が 2 次ソート キーとして保持されるようにします。 タプルのソート`(priority, index, id)`両方のスケジュール ルールを直接エンコードします。 ソート後はIDのみを抽出して出力します。 

ここでよくある間違いは、ソート キーのインデックスを忘れることです。 Python のソートは安定していますが、インデックスを明示的に含めずに安定性に依存すると、構造が変更されたり、別の言語が使用されたりした場合に脆弱になります。 明示的に並べ替える`(priority, index)`正確性を保証します。 

## 実用的な例

 タスクを含むテスト ケースを考えてみましょう。 

ID: 4 1 3 2

 優先順位: 2 1 2 1

 次のようにタプルを構築します`(priority, index, id)`:

 | インデックス | ID | 優先順位 | タプル |
 | --- | --- | --- | --- |
 | 0 | 4 | 2 | (2, 0, 4) |
 | 1 | 1 | 1 | (1, 1, 1) |
 | 2 | 3 | 2 | (2, 2, 3) |
 | 3 | 2 | 1 | (1, 3, 2) |

 並べ替え後:

 | 位置 | タプル |
 | --- | --- |
 | 0 | (1, 1, 1) |
 | 1 | (1, 3, 2) |
 | 2 | (2, 0, 4) |
 | 3 | (2, 2, 3) |

 出力は次のようになります。`1 2 4 3`。 

このトレースは、等しい優先度がどのようにインデックスによって厳密に解決され、各優先度グループ内で安定した挿入順序が確保されるかを示しています。 

次に、より単純なケースを考えてみましょう。 

ID: 10 20 30

 優先順位: 5 5 5

 すべてのタスクは同じ優先順位を共有するため、順序は挿入インデックスに完全に依存します。 ソートされた順序はそのまま残ります`10 20 30`、優先順位が等しい場合、アルゴリズムがアイデンティティ順序に縮退することが確認されました。

 ## 特殊なケース

 すべての優先順位が同一の場合、アルゴリズムは保存されているインデックスに完全に依存します。 各タプルは次のようになります`(p, i, id)`同等の`p`したがって、並べ替えは、次の順序で並べることになります。`i`。 出力は元の挿入シーケンスと正確に一致します。これは必要な動作です。 

優先度が最も低いタスクが入力の最後に表示される場合でも、優先度フィールドが比較の優先順位を占めるため、並べ替えではそのタスクが最初に配置されます。 インデックスは優先順位が一致する場合にのみ重要となるため、遅れて到着した優先順位の低いタスクは、先に到着した優先順位の高いタスクよりも正しくジャンプします。
