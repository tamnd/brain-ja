 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースは、無向の単純なグラフを記述しますが、通常のエッジ リスト形式ではありません。 代わりに、グラフは三角形のコレクションとして間接的に指定されます。 各線には、三角形を形成する 3 つの異なる頂点が示されており、実際のグラフは、これらの三角形のいずれかに現れるすべてのエッジの結合によって取得されます。 

タスクは、グラフに長さ 5 の単純なサイクルが含まれているかどうかを判断することです。 このようなサイクルが存在する場合、それを形成する 5 つの頂点を循環順序で出力する必要があります。 それ以外の場合は、-1 を出力します。 

入力の構造は重要です。任意の疎グラフまたは密グラフを自由に想定できるのではなく、三角形の和集合であるグラフを想定します。 これはすでに高度なローカル クラスタリングを暗示しています。つまり、すべてのエッジが少なくとも 1 つの三角形に属し、多くのエッジが複数の三角形に参加する傾向があります。 

制約が十分に大きいため、単純なサイクルの列挙は不可能です。 最大約 10,000 個の頂点と n^{1.5} 個の三角形のオーダーで、誘導されるエッジの数は数百万に達する可能性があります。 頂点の単純な 5 タプルをすべて列挙しようとするアプローチや、長さ 4 のパスをすべて列挙しようとするアプローチは、組み合わせ爆発によりすぐに失敗します。 ノードのペア間のすべての長さ 3 のパスを反復処理するだけでも、単純な方法では遅すぎます。 

微妙なエッジケースは、三角形の繰り返し構造から生じます。 不注意な実装では、各三角形が独立していると想定し、それぞれを別個のクリークとして扱い、三角形の境界をまたぐサイクルが欠落する可能性があります。 たとえば、三角形 (1,2,3)、(3,4,5)、(5,1,6)、(6,7,2)、(2,4,7) は、単一の三角形の内部には表示されない 5 つのサイクルを集合的に形成することがあります。 すべてのソリューションは、個々の三角形ではなく、和集合グラフで動作する必要があります。 

もう 1 つの落とし穴は、5 サイクルの検出が浅い深さの近傍を個別にチェックすることによって実行できると仮定していることです。 5 サイクルは複数の三角形を簡単に通過できるため、単一の三角形または三角形のペアのローカル チェックだけでは不十分です。 

## アプローチ

 直接的なブルート フォース戦略は、グラフの完全な隣接リストを構築し、順序付けられた個別の頂点の 5 タプルをすべて試して、それらがサイクルを形成しているかどうかを確認することです。 これは概念的には簡単です。5 つのノードを選択し、必要な 5 つのエッジの存在を確認します。 正しさは明らかですが、選択肢の数は n^5 程度であり、10^4 までの n ではまったく実現不可能です。 

もう少し構造化されたブルート フォースは、開始ノード u を固定し、DFS を使用して u から始まる長さ 4 のすべてのパスを試行し、それらが u に戻るかどうかを確認することです。 枝刈りを行ったとしても、高密度領域ではノードごとにおよそ O(deg^4) の構造が探索されますが、それでも数億または数十億の操作にまで縮退します。 

重要な構造的観察は、サイクルを直接列挙する必要がないということです。 5 サイクルは、頂点の繰り返しを避ける、u から v までの長さ 3 のパスに延長できるエッジ u-v が存在する場合にのみ存在します。 言い換えれば、5 サイクル u-a-b-c-v-u は、エッジの端点間の長さ 3 のパスに対応します。 

これにより、問題はサイクルの検索から、隣接するノード間の制約された長さ 3 のパスの検索に移ります。 これはまだ自明ではありませんが、セット交差とビットセット表現を利用して到達可能性クエリを高速化できるようになりました。 

グラフ サイズ n ≤ 10^4 は、ビットセット手法を強く示唆しています。 ビットセットを使用すると、隣接クエリがワードレベルの操作になり、交差を迅速に計算できます。 また、すべての証人パスを数える必要はなく、1 つの証人パスを見つけるだけでよいという事実も利用します。

隣接関係をビットセットとして表し、それを使用して 3 ステップのパスの潜在的な中間セグメントを検出します。 次に、候補エッジ (u, v) ごとに、u から 2 つのステップで到達可能であり、同時に v の近傍に接続する中間頂点 b を見つけようとします。これにより、パスから事前計算された近傍の交点までの探索スペースが削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての 5 タプルを列挙する | O(n^5) | お(1) | 遅すぎる |
 | DFS すべての長さ 4 のパス | O(n · d^4) | O(n) | 遅すぎる |
 | ビットセットの交差 + エッジのセンタリング | O(n^2 / w + m · n / w) 償却 | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 5 サイクル条件を、近傍の交差を使用して検出できるパターンに変換したいと考えています。 

1. すべての三角形からグラフの隣接構造を構築します。 各三角形 (x、y、z) に対して、エッジ x-y、y-z、z-x を追加します。 最後に、完全な無向グラフが得られます。 
2. 隣接関係を各頂点のサイズ n のビットセットとして保存します。 これにより、O(n / word_size) で隣接性と交差をチェックできます。 
3. 最大 2 ステップで u から到達可能なすべての頂点を表す、第 2 レベルの到達可能性構造 N2[u] をビットセットとして事前計算します。 u のすべての近傍の近傍の結合を計算することによって、それを計算します。 これにより、u から始まる潜在的な長さ 3 のパス内のすべての可能な中間頂点がキャプチャされます。 
4. 各エッジ (u、v) を繰り返します。 このエッジを使用する 5 サイクルは、パス u → a → b → c → v に対応する必要があります。 
5. 固定エッジ (u, v) について、N2[u] にある頂点 b を見つけようとします。 これにより、u から b への 2 段階のパス、つまり、ある a については u → a → b が存在することが保証されます。 
6. このような各候補 b について、今度はそれを v に向かって拡張しようとします。N(b) と N(v) の交差を計算します。 この交点の頂点 c はいずれも b-c および c-v を満たし、潜在的な 5 サイクルの最後の 2 つのエッジを与えます。 
7. そのような c が見つかった場合、u-a-b が成り立つような 1 つの中間ノード a を記憶することによって完全なサイクルを再構築します。 単なる存在ではなく実際のパスを回復できるように、N2 の構築中に証人の親を保存します。 
8. 有効なシーケンス u-a-b-c-v が見つかったら、サイクル u、a、b、c、v を出力し、そのテスト ケースを終了します。 

### なぜ効果があるのか

 すべての単純な 5 サイクルには、少なくとも 1 つのエッジ (u、v) が含まれます。 このエッジを修正すると、サイクルがその終点間の長さ 3 のパスに分割されます。 N2[u] の構築では、そのようなパスのすべての有効な 2 番目の頂点がその中に現れることが保証されます。 最後の交差ステップは、残りの 2 つのエッジを v に強制的に閉じます。すべてのステップで隣接制約が正確に保持されるため、検出されたシーケンスはすべて有効な単純な 5 サイクルである必要があり、有効な 5 サイクルは最初のエッジが処理されるときに検出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())

        adj = [set() for _ in range(n)]

        for _ in range(m):
            x, y, z = map(int, input().split())
            x -= 1
            y -= 1
            z -= 1
            adj[x].add(y); adj[y].add(x)
            adj[y].add(z); adj[z].add(y)
            adj[z].add(x); adj[x].add(x)

        # fix accidental self-add if any (safe guard)
        for i in range(n):
            if i in adj[i]:
                adj[i].remove(i)

        # build bitsets
        bit = [0] * n
        for i in range(n):
            b = 0
            for j in adj[i]:
                b |= 1 << j
            bit[i] = b

        # precompute 2-hop neighborhoods (bitset union of neighbors)
        bit2 = [0] * n
        for i in range(n):
            b = 0
            for j in adj[i]:
                b |= bit[j]
            b &= ~(1 << i)
            bit2[i] = b

        found = False

        nodes = list(range(n))

        for u in range(n):
            if found:
                break
            for v in adj[u]:
                if u >= v:
                    continue

                # try to find b in N2[u]
                cand = bit2[u]
                # iterate bits of cand
                bmask = cand
                while bmask:
                    lb = bmask & -bmask
                    b = (lb.bit_length() - 1)
                    bmask -= lb

                    if b == u or b == v:
                        continue

                    # intersection N(b) & N(v)
                    inter = bit[b] & bit[v]
                    inter &= ~(1 << u)
                    inter &= ~(1 << v)

                    if inter:
                        lc = inter & -inter
                        c = (lc.bit_length() - 1)

                        # now find a such that u-a-b
                        for a in adj[u]:
                            if a != b and (bit[a] >> b) & 1:
                                print(u + 1, a + 1, b + 1, c + 1, v + 1)
                                found = True
                                break
                        if found:
                            break
                if found:
                    break

        if not found:
            print(-1)

if __name__ == "__main__":
    solve()
```この実装は、隣接性チェックを圧縮するためにビット操作に大きく依存しています。 最も重要な点は、ビットマスクを使用して近傍を表現することです。これにより、2 ホップ拡張と交差チェックの両方を迅速に行うことができます。 

再構成ステップは、中間セグメントの候補が見つかるまで意図的に延期されます。 これにより、コストがかかりすぎるすべてのペアの完全なパス情報を保存することが回避されます。 

ループ順序は、最初にエッジを修正し、次に中間頂点の構造化された候補のみを探索するように選択されます。これにより、探索空間の爆発が防止されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、複数の三角形が 5 サイクルを形成せずに高密度の局所構造に崩壊する場合です。 このような場合、ビットセットの交差により中間頂点の多くの候補が生成されますが、開始エッジに戻る一貫したパスを完了できるものはないため、アルゴリズムはすべての候補を正しく使い尽くして -1 を返します。 

有効な 5 サイクルが多くの三角形と頂点を共有する場合、別のエッジ ケースが発生します。 隣接セットが大きい場合でも、ビットセットの交差により、パス構造の両方の半分を同時に満たす頂点のみが確実に分離され、誤検知が防止されます。 

最後の微妙なケースは、複数の異なる 5 サイクルが同じエッジを共有する場合です。 このアルゴリズムは、中間頂点の候補に対する反復中に発生した最初の有効な再構成を検出します。 任意の有効なサイクルが受け入れられるため、これで十分です。
