 ## 解決策
 ## 問題の理解

 私たちには、ジョブの有向非循環グラフとしてモデル化できる生産システムが与えられています。 各ジョブの処理には一定の時間がかかり、あるジョブから別のジョブに移動すると追加の転送時間が発生します。 有効な生産計画は 1 つ以上の開始ジョブから開始され、ジョブ間の指示された遷移に従い、最終的に 1 つ以上の最終ジョブで終了します。 計画の合計リード タイムは、訪問したすべてのジョブの処理時間に、選択したルートに沿ったすべての移行時間を加えた合計です。 

このタスクは、有効な開始から有効な終了までの可能な最大リード タイムを計算することです。 この最大時間を計算した後、最適な生産ルートが一意であるかどうかも判断する必要があります。 ちょうど 1 つのジョブ シーケンスがこの最大値に達する場合、そのルート上の一連のジョブに続く合計時間を出力する必要があります。 複数の異なるルートが同じ最大時間を達成した場合は、合計時間の後に文字 M が出力されます。 

このステートメントでは仮想開始ジョブと終了ジョブの挿入について言及していますが、実際の構造はより単純です。ジョブはノード、遷移は有向エッジで、グラフにはサイクルがないことが保証されています。 これにより、トポロジー的な順序付けが存在し、最長パスの計算が明確に定義されることが保証されます。 

制約は小さく、テスト ケースあたり最大 50 個のジョブと 100 個の遷移です。 これにより、グラフ上の線形または線形に近い動的計画法を超えるものは即座に除外されます。 O(n^3) のアプローチでも単独では合格しますが、複数のテスト ケースにわたって繰り返され、オーバーヘッドが発生するため、O(n + m) または O(nm) のトポロジカル DP が意図された構造になります。 

開始ノードが複数存在する場合、微妙な障害が発生することがあります。 たとえば、ジョブ 0 とジョブ 1 の両方に受信エッジがなく、両方とも等しい合計コストでジョブ 2 に到達できる場合、最初のセグメントのみが異なる 2 つの最適なパスが存在します。 任意の開始ノードを選択する単純な解決策では、一意であると誤って結論付けられてしまいます。 

複数のパスが最終ノードでのみ接続され、それより前に分岐している場合には、別の問題が発生します。 たとえば、2 つの異なるルートが同じコストで同じ最大終了ジョブに到達する場合、両方とも有効な最適解とみなされ、たとえそれらのサフィックスが一致したとしても出力は M でなければなりません。 

## アプローチ

 ブルート フォース ソリューションでは、DAG 内のすべての開始ノードからすべての終了ノードまでの可能なパスをすべて列挙し、その合計コストを計算し、最大値を追跡します。 グラフは非周期的ですが、最悪の場合でも指数関数的であるため、分岐に応じてパスの数が指数関数的に増加する可能性があります。 50 個のノードがある場合でも、バイナリ分岐構造はすでに 2^50 のオーダーでパスを作成できますが、これは実現不可能です。 

重要な観察は、グラフにはサイクルがないため、最適な部分構造が維持されるということです。つまり、ノードに到達する最適な方法は、そのノードに到達するための最適な方法にのみ依存します。 これにより、問題はノードの重みとエッジの重みを使用した DAG 上の最長パスの問題に変わります。 

ノードをトポロジカルな順序で処理し、ノードごとに、そのノードで終了する達成可能な最大リード タイムを計算できます。 これに加えて、その最大値を達成する個別の方法の数も維持しますが、最適な方法が一意であるかどうかのみを考慮するため、この数の上限は 2 にします。 

DP が完了したら、すべてのターミナル ノードを調べて、最大値を持つノードを選択します。 次に、先行ポインタを使用してパスを再構築します。 再構築中のいずれかの時点で、最適な値を生成できる有効な先行処理がノードに複数ある場合、その答えは曖昧であるとマークされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスに対するブルート フォース | 指数 | O(n + m) | 遅すぎる |
 | DAG DP と再構築およびカウント | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

各ジョブを処理時間に等しい重みを持つノードとして扱い、各遷移を送信時間に等しい重みを持つ有向エッジとして扱います。 

1. グラフの隣接リストを構築し、トポロジカルソートの度数を計算します。 グラフ構造が順序通りに与えられていないため、これが必要になります。 
2. すべてのジョブに対してトポロジカル ソートを実行します。 グラフは非巡回であるため、この順序付けにより、ノードを処理するときに、そのノードに到達できるすべてのノードがすでに処理されていることが保証されます。 
3. dp[v] がジョブ v で終了するときに達成可能な最大リード タイムを表す DP 配列を初期化します。パスはどのエントリ ノードでも開始できるため、最初に dp[v] をすべてのノードの v の処理時間に設定します。 
4. Ways 配列を維持します。ways[v] は、v に到達する最適なウェイの数を記録し、上限は 2 です。これにより、組み合わせ的に大きな数をカウントせずに、一意性が侵害されているかどうかを検出できます。 
5. トポロジ順にノードを移動します。 送信コスト w の各有向エッジ u → v について、u への最適パスを v に拡張することを検討します。候補値は dp[u] + w + process[v] です。 この値が dp[v] より大きい場合、dp[v] を置き換え、ways[v] をウェイズ[u] に設定し、u を v の先行者として保存します。値が等しい場合、ways[u] をウェイズ[v] に追加しますが、上限は 2 で、v には複数の最適な先行者があることを記録します。これは後で再構築に影響します。 
6. すべてのエッジを処理した後、出力エッジのないすべてのノードの中から最適な終端ノードを特定します。 複数の端末が同じ dp 値を達成した場合、一意性はすでに壊れています。 
7. 選択した終端ノードから先行ポインタを逆方向にたどることにより、パスを再構築します。 どこかの時点で複数の先行手法が同じ最適な dp 値を生成できる場合、その解決策は曖昧であるとマークされます。 
8. 再構成が一意である場合は、パスを反転して出力します。 それ以外の場合は M を出力します。 

正確さは、DAG 内のすべてのパスが最適なサブパスで構成されているという事実に依存します。 パスのプレフィックスがそのエンドポイントにとって最適でない場合、パス全体を最適にすることはできません。 これにより、すべての先行関数がわかったら、dp[v] を独立して計算できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(n, m, times, edges):
    adj = [[] for _ in range(n)]
    indeg = [0] * n

    for u, v, w in edges:
        adj[u].append((v, w))
        indeg[v] += 1

    # topological sort
    from collections import deque
    q = deque([i for i in range(n) if indeg[i] == 0])
    topo = []

    while q:
        u = q.popleft()
        topo.append(u)
        for v, w in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

    dp = times[:]
    ways = [1] * n
    parent = [-1] * n

    for u in topo:
        for v, w in adj[u]:
            cand = dp[u] + w + times[v]
            if cand > dp[v]:
                dp[v] = cand
                ways[v] = ways[u]
                parent[v] = u
            elif cand == dp[v]:
                ways[v] = min(2, ways[v] + ways[u])

    best = max(dp)
    candidates = [i for i in range(n) if dp[i] == best]

    if len(candidates) != 1:
        return str(best) + ",M"

    end = candidates[0]

    if ways[end] > 1:
        return str(best) + ",M"

    # reconstruct
    path = []
    cur = end
    while cur != -1:
        path.append(cur)
        cur = parent[cur]
    path.reverse()

    return str(best) + "," + ",".join(map(str, path))

def main():
    data = sys.stdin.read().strip().splitlines()
    i = 0
    out = []

    while i < len(data):
        if not data[i].strip():
            i += 1
            continue

        n, m = map(int, data[i].split())
        i += 1

        times = list(map(int, data[i].replace(",", " ").split()))
        i += 1

        edges = []
        for _ in range(m):
            u, v, w = map(int, data[i].split())
            edges.append((u, v, w))
            i += 1

        out.append(solve_case(n, m, times, edges))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```この解決策は、隣接リストを構築し、次数追跡を使用してトポロジー順序を計算することから始まります。 これにより、ノードを処理するときに、すべての受信コントリビューションがすでに確定していることが保証されます。 

dp 配列には、各ジョブで終了する最良のリード タイムが保存され、すべての遷移にはエッジ送信時間と宛先ノードの処理時間の両方が含まれます。 ノード コストは遷移だけではなく状態の一部であるため、これは重要です。 

親配列は再構築に使用されます。 最適な遷移が一意である場合にのみ、単一の先行データを保存します。 あいまいさは、ways 配列を使用して個別に追跡されます。この配列は 2 にクランプされているため、一意のケースと非一意のケースのみを区別します。 

最後に、すべてのノードの中から最適なエンドポイントを選択します。 複数のノードが結合している場合、または最適なエンドポイント自体に複数の最適なウェイがある場合は、M を返します。そうでない場合は、親ポインターを逆方向にたどることによってパスを再構築します。 

## 実用的な例

 ### 例 1

 最適なパスが一意である小さなグラフを考えます。 

ノードの重みを次のようにします`[2, 7, 2, 6]`そしてエッジは、1 つのパスのみが最大コストを達成するチェーン状の構造を定義します。 

| ステップ | ノード | dpアップデート | 方法 | 親 |
 | --- | --- | --- | --- | --- |
 | 初期化 | すべて | dp = ノードの重み | 1 | - |
 | プロセス0 | 0 | 2 | 1 | - |
 | プロセス1 | 1 | 9 | 1 | 0 |
 | プロセス3 | 3 | 17 | 1 | 1 |

 最終的な答えは、ノード 3 につながる一意のパスです。 

このトレースは、すべてのノードに最適な先行処理が 1 つだけ存在するため、曖昧さなく再構築が進行することを示しています。 

### 例 2

 ここで、2 つの異なるパスがシンクで同じ最適値に到達する場合を考えてみましょう。 

| パス | コスト |
 | --- | --- |
 | 0→1→5 | 53 |
 | 0→2→5 | 53 |

 どちらのルートもノード 5 で同一の最大 dp を生成します。DP 中に、dp[5] は同じ値で 2 回到達するため、ways[5] は 2 になります。 

これにより、最終コストが明確に定義されている場合でも、出力が強制的に M になります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、複数の開始ノードが存在する場合です。 この状況では、dp 初期化はすべてのノードを潜在的な開始点として扱います。 2 つのスタートが等しいコストの共有チェーンにつながる場合、両方とも同じシンクに寄与し、ウェイが 1 より大きくなり、曖昧さが強制されます。 

もう 1 つのエッジ ケースは、同じ最大 dp 値を持つ複数のターミナル ノードが存在する場合です。 各端末が独自の内部構造を持っているとしても、複数の最適なエンドポイントが存在するということは、単一の支配的な運用パスが存在しないことを意味します。 

最後の微妙なケースは、ノードに最適な先行処理が 1 つだけ存在するが、その先行処理自体は複数の最適なパスを介して到達可能である場合に発生します。 この場合、親の再構築では引き続き単一のチェーンが生成されますが、非一意性が早期に検出され、M が正しく出力されるため、誤解を招く再構築が防止されます。
