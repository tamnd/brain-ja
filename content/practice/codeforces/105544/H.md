 ## 解決策
 ## 問題の理解

 私たちには一定額の現金と銀行預金の機会のリストが与えられます。 各機会に参加するには特定の金額を費やす必要があり、その見返りとして固定額の利子が得られます。 制約は、各入金オプションは最大 1 回まで選択でき、選択したオプション全体で費やされる合計金額が利用可能な現金を超えることはできないということです。 目標は、得られる合計利息を最大化するこれらの入金オプションのサブセットを選択することです。 

これは構造的には、各アイテムにコストと価値があり、容量の制約の下で価値を最大化したいというナップザック問題です。 「コスト」は必要な入金額、「価値」は得られる利息です。 

制約は十分に小さいため、二次動的計画法ソリューションが実現可能です。 銀行の数は最大 100、現金限度額は最大 1000 です。単純な総当りのサブセット列挙では、すべての銀行が考慮されます。$2^N$サブセット、約まで成長します$10^{30}$最悪の場合は完全に不可能です。 これは、予算の次元を超えた動的プログラミングのアプローチを即座に示唆します。 

すべての入金要件が利用可能な現金を超える場合、微妙なエッジケースが発生します。 たとえば、現金が 10 ですべての場合、$w_i > 10$の場合、選択はできず、答えは 0 でなければなりません。DP を誤って (たとえば、到達不能状態を適切に設定せずに) 初期化する単純な実装では、誤って無効な値が伝播され、ゼロ以外の答えが生成される可能性があります。 もう 1 つのケースは、複数の組み合わせが同じコストで異なる値を生み出す場合です。 アルゴリズムは常に最大値を維持するようにする必要があります。 

## アプローチ

 強引なアイデアは、銀行のオファーのすべてのサブセットを試してみることです。 サブセットごとに総コストと総利息を計算し、最も有効な値を保持します。 これはすべての可能性を直接評価するため機能しますが、それはすぐに不可能になります。$N$指数関数的な成長により約 25 を超えます。 

問題の構造から、古典的な 0/1 ナップザック パターンが明らかになります。 各銀行のオファーはアイテムであり、入金限度額はその重量であり、利子はその価値です。 容量は利用可能な現金です$C$。 サブセットを明示的に追跡する代わりに、動的プログラミング配列を構築できます。$dp[c]$正確に、または最大で使用して達成可能な最大の利息を表します$c$現金。 

重要な改善は、各アイテムが最大 1 回しか使用されないことを認識することからもたらされます。 これにより、各項目の容量を降順で繰り返すことができ、同じ項目を複数回再利用することがなくなります。 これにより、複雑さが指数関数から多項式に軽減されます。

 ## アルゴリズムのチュートリアル

 当社では、各銀行のオファーをコストと価値のあるアイテムとして扱い、可能な限り予算ごとに達成可能な最高の利息を積み立てます。$C$。 

1. サイズの DP 配列を初期化します。$C + 1$、すべてのエントリは 0 から始まります。これは、アイテムがゼロの場合、予算に関係なく利息を獲得できないことを表します。 
2. 各銀行のオファーを 1 つずつ処理します。 銀行の場合$i$、そのコストを$w_i$そしてその値は$v_i$。 
3. この銀行について、予算を逆方向に繰り返します。$C$まで$w_i$。 逆方向では、この反復内で同じバンクを複数回再利用することがなくなります。 
4. 予算ごとに$c$、このバンクを使用することで結果が改善されるかどうかを検討します。現在の値を比較します。$dp[c]$と$dp[c - w_i] + v_i$。 更新します$dp[c]$後者の方が大きい場合。 
5. すべての銀行を処理した後、答えは DP 配列の最大値になります。これは、予算を超過することなく達成可能な最良の利息を表します。 

### なぜ効果があるのか

 処理中のどの時点でも、DP 配列は、それまでに処理されたバンクのみを使用して達成可能な最高の金利をエンコードします。 逆方向反復により、更新時に次のことが保証されます。$dp[c]$、値$dp[c - w_i]$0/1 制約を維持しながら、現在のバンクを含まない状態を指します。 この不変式により、バンクのすべての有効なサブセットが 1 回だけ考慮され、無効な再利用が発生しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    C = int(input().strip())
    v = list(map(int, input().split()))
    w = list(map(int, input().split()))
    n = len(v)

    dp = [0] * (C + 1)

    for i in range(n):
        cost = w[i]
        val = v[i]
        for c in range(C, cost - 1, -1):
            dp[c] = max(dp[c], dp[c - cost] + val)

    print(max(dp))

if __name__ == "__main__":
    solve()
```このソリューションでは、1 次元 DP 配列を使用してメモリを圧縮します。 各反復では配列が適切に更新されますが、前の状態が遷移に対して有効なままであるように、容量の降順でのみ更新されます。 最大の金額を費やすことができるため、最終的な答えはすべての容量の最大値として採用されます。$C$、必ずしも正確ではありません$C$。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    C = int(input().strip())
    v = list(map(int, input().split()))
    w = list(map(int, input().split()))
    n = len(v)

    dp = [0] * (C + 1)
    for i in range(n):
        for c in range(C, w[i] - 1, -1):
            dp[c] = max(dp[c], dp[c - w[i]] + v[i])

    return str(max(dp))

 ## 特殊なケース

 すべての項目のコストが予算を超えている場合、DP 配列は変更されずゼロのままである必要があります。 たとえば、$C = 3$、$w = [5, 6]$、内側のループは決して実行されないため、遷移はできません。 最終的な正解は 0 になります。 

予算にぴったり合った商品の場合など$C = 10$、$w = [10]$、DP アップデート セット$dp[10] = v_1$、 以来$dp[0]$は 0 であり、遷移は有効です。 これにより、等価境界が正しく処理されることが確認されます。 

複数の商品で費用が重複する場合$C = 10$、$w = [5, 5]$、後方反復により、最初の項目を処理した後でも、使い捨て制約に違反することなく 2 番目の項目を最初の項目と結合でき、正しい結合値が得られることが保証されます。
