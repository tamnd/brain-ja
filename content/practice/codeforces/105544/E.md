 ## 解決策
 ## 問題の理解

 より大きな長方形の庭園内に配置された、軸を揃えた長方形のスラブのセットが与えられます。 各スラブの垂直方向の位置は固定されています。つまり、その下端と上端の y 座標は不変ですが、スラブを水平方向に左または右に移動することができます。 

重要な相互作用ルールがあります。2 つのスラブが垂直投影で重なる場合、左右の順序は初期構成と一致していなければなりません。 言い換えれば、垂直方向の重なりにより、相対的な x 順序の交換を禁止する制約が生じます。 さらに、垂直に重なり合う 2 つのスラブが水平方向に近接している場合、それらの間に少なくとも所定の最小間隔を維持する必要があります。 スラブは水平に接触する場合がありますが、必要な間隔を侵すことはできません。 

目標は、垂直座標を維持し、順序制約と間隔制約の両方を尊重して、すべてのスラブを水平方向に再配置して、構成の全体的な境界幅が最小化されるようにすることです。 庭全体の垂直方向のスパンは固定されているため、幅を最小限に抑えると、そのまま未使用面積が最大になります。 

主な問題点は、制約が単純な方法ではグローバルではないことです。 2 つのスラブは、それらの垂直範囲が交差しない限り直接相互作用しない可能性がありますが、オーバーラップのチェーンによる推移性により、多くのスラブにわたって順序付けの制約が強制される可能性があります。 

制約から、テスト ケースごとに最大 100 個のスラブがあり、最大 32 個のテスト ケースがあることがわかります。 これにより、O(n^2) または O(n^2 log n) の解が快適に得られます。 すべてのペアにわたる 3 次のものはまだ潜在的に問題ありませんが、不要です。 順序の階乗または指数探索は不可能です。 

微妙な失敗例は、スラブが順序制約を間接的に伝播する複数の重複グループを形成するときに発生します。 たとえば、スラブ A は B と重なり、B は C と重なりますが、A は C と重なりません。直接の重なりのみをチェックし、推移的な制約を無視する単純なアプローチでは、誤って無効な並べ替えが許可される可能性があります。 

もう 1 つの問題は、すべてのスラブがグローバルに相互作用すると仮定していることです。 スラブが垂直方向に分離している場合、順序の制約は課されず、スラブを完全に接続されているものとして扱うと、不必要な制約が発生し、幅が正しく最小化されません。 

## アプローチ

 構造を無視すると、x 位置を貪欲に割り当てたり、スラブのすべての順列を総当たり的に割り当てたりして、制約の伝播をシミュレートしようとする可能性があります。 順序ごとに、間隔の制約が満たされていることを確認しながら左から右に位置を割り当て、結果の幅を計算します。 これは正しいです。有効な構成はすべて、すべての制約と一致する全体的な順序付けに対応するからです。 

ただし、nがあります！ 可能な順列があり、n = 20 であっても、これはすでに実行不可能になります。 n が 100 までの場合、これは完全に不可能です。 

重要な観察は、制約は垂直投影が重なっている場合にのみ存在するということです。 これにより、問題がグラフ構造に変わります。各スラブはノードであり、y 間隔が交差する場合、2 つのノード間にエッジが存在します。 各接続コンポーネントは、内部順序制約を使用して配置する必要があるスラブのグループを定義しますが、異なるコンポーネントは順序に関して相互に制約しません。 

1 つの連結コンポーネント内では、オーバーラップによって引き起こされる部分的な順序を尊重する必要があります。 重要なのは、2 つのスラブが y 方向に重なっている場合、それらの相対的な順序は初期構成から固定されることです。 これにより、有向制約が与えられます。最初にスラブ i がスラブ j の左側にあり、それらが垂直に重なる場合、i は j の左側に留まらなければなりません。 

したがって、各接続コンポーネントは有向非巡回制約システムになります。 コンポーネント内のタスクは次のようになります。合計スパンを最小化するこれらの制約と一致する線形順序を見つけます。ここで、エッジはスラブ幅と間隔に等しい最小ギャップを課します。

これは、各制約を x 座標の差分制約に変換した後、DAG 内の最長パスを見つけることと同じです。 

各スラブを変数 x[i] (左の座標) を使用してノードに変換します。 j より前のすべての制約 i について、以下が必要です。 

x[j] ≥ x[i] + 幅[i] + 間隔

 これは差分制約グラフです。 すべての制約を尊重する実現可能な最小の割り当てが必要です。これは、この制約グラフ内のソースからの最長パスです。 

重み 0 のエッジを持つスーパー ソース ノードをすべてのノードに追加し、制約を緩和します。 グラフは一貫した順序付けの構築による DAG であるため、位相順序または符号を反転した最短パスを使用できます。 

最後に、コンポーネントの答えは、x[i] + width[i] の最大値によって決まります。 最終的な答えは、すべてのコンポーネントの最大値です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | O(n! · n) | O(n) | 遅すぎる |
 | グラフ制約 + 最長パス | O(n^2) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは構造化された方法でソリューションを構築します。 

1. まず、どのスラブが垂直方向に相互作用するかを特定します。 2 つのスラブの y 間隔が重なる場合、それらのスラブは接続されます。 重複関係は対称であるため、この目的のために無向グラフを構築します。 このステップでは、個別に解決できる独立したグループを分離します。 
2. DFS または BFS を使用して連結成分を計算します。 コンポーネントをまたぐ制約がないため、各コンポーネントは独立して処理されます。 
3. 各コンポーネント内で、有向順序制約を導出します。 コンポーネント内のスラブ i と j のすべてのペアについて、それらの垂直範囲が重なり、i が最初に j の左側にある場合、width[i] に必要な間隔を加えたものに等しい重みを持つ有向エッジ i → j を追加します。 これは、j が i の十分右側に配置されなければならないという事実をエンコードします。 
4. 次に、すべての制約を満たす、実行可能な x 座標の割り当てを計算します。 すべての x[i] をゼロに初期化し、制約を繰り返し緩和します。 概念的には、各エッジ i → j に対して、x[j] を少なくとも x[i] + w[i] + d に更新します。 これは、DAG 構造上の最長パス伝播の問題です。 
5. 各コンポーネントで制約グラフのトポロジカルソートを実行し、その順序でノードを処理し、距離を更新します。 これにより、ノードを処理するときに、受信するすべての制約がすでに解決されていることを保証します。 
6. x 座標が決定されたら、x[i] + width[i] のすべてのスラブの最大値としてコンポーネントのスパンを計算します。 最小の x はアンカーリングにより実質的にゼロになるため、このスパンはそのコンポーネントで達成可能な最小幅を表します。 
7. 最終的な答えは、コンポーネント間のスパンの合計、またはレイアウトの解釈に応じて、コンポーネントを独立して並列に配置できる場合の最大値になります。 コンポーネントは互いに制約しないため、互いの内部制約に影響を与えることなく並べて配置できます。そのため、コンポーネントの幅を合計します。 

### なぜ効果があるのか

 重要な不変条件は、すべてのエッジが、垂直に重なるスラブ間の分離に必要な下限をエンコードしていることです。 有効な取り決めは、そのような不平等をすべて満たさなければなりません。 これらの制約をトポロジー的に順序付けられた構造にわたる最長パスの計算に変換することで、すべてのノードの位置がすべての先行ノードを尊重しながら可能な限り厳密になるようにします。 制約はオーバーラップ チェーンに沿ってのみ伝播し、各コンポーネントは独立して処理されるため、制約が無視されたり二重にカウントされたりすることはありません。 これにより、実現可能性と最小の合計幅の両方が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict, deque

def solve():
    t = int(input())
    for _ in range(t):
        n, d = map(int, input().split())
        rects = []
        for i in range(n):
            x1, y1, x2, y2 = map(int, input().split())
            rects.append((x1, y1, x2, y2))

        # build vertical overlap graph
        g = [[] for _ in range(n)]
        for i in range(n):
            x1i, y1i, x2i, y2i = rects[i]
            for j in range(i + 1, n):
                x1j, y1j, x2j, y2j = rects[j]
                if not (y2i <= y1j or y2j <= y1i):
                    g[i].append(j)
                    g[j].append(i)

        vis = [False] * n
        comp_id = [-1] * n
        comps = []

        for i in range(n):
            if not vis[i]:
                q = [i]
                vis[i] = True
                comp = []
                while q:
                    u = q.pop()
                    comp.append(u)
                    comp_id[u] = len(comps)
                    for v in g[u]:
                        if not vis[v]:
                            vis[v] = True
                            q.append(v)
                comps.append(comp)

        ans = 0

        for comp in comps:
            idx = {v: k for k, v in enumerate(comp)}
            m = len(comp)

            # build directed constraints
            dag = [[] for _ in range(m)]
            indeg = [0] * m

            for i in comp:
                for j in comp:
                    if i == j:
                        continue
                    x1i, y1i, x2i, y2i = rects[i]
                    x1j, y1j, x2j, y2j = rects[j]

                    if not (y2i <= y1j or y2j <= y1i):
                        if x1i < x1j:
                            u = idx[i]
                            v = idx[j]
                            dag[u].append((v, x2i - x1i + d))
                            indeg[v] += 1

            # topological DP
            q = deque([i for i in range(m) if indeg[i] == 0])
            dist = [0] * m

            while q:
                u = q.popleft()
                for v, w in dag[u]:
                    if dist[v] < dist[u] + w:
                        dist[v] = dist[u] + w
                    indeg[v] -= 1
                    if indeg[v] == 0:
                        q.append(v)

            best = 0
            for i in range(m):
                orig = comp[i]
                x1, y1, x2, y2 = rects[orig]
                best = max(best, dist[i] + (x2 - x1))

            ans += best

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず垂直方向のオーバーラップ接続を構築して、独立したグループを分離します。 次に、各グループは、エッジが強制的な水平方向の分離をエンコードする有向制約システムに変換されます。 トポロジカル DP は、必要な最大オフセットを伝播することによって、実行可能な最も狭い配置を計算します。 最後に、各コンポーネントは、その最小達成可能な幅に寄与します。 

微妙な点は、制約は重複する垂直間隔に対してのみ作成されることです。 これにより、不要なエッジが防止され、グラフが O(n^2) 処理に十分な疎性を保つことが保証されます。 

## 実用的な例

 一連の垂直方向の重なりを形成する 3 つのスラブの小さな構成を考えてみましょう。 スラブ 1 はスラブ 2 とオーバーラップし、スラブ 2 はスラブ 3 とオーバーラップしますが、スラブ 1 はスラブ 3 とオーバーラップしません。これにより、推移的な制約チェーンが作成されます。 

| ステップ | 処理されたノード | 距離配列 | アクション |
 | --- | --- | --- | --- |
 | 1 | 1 | [0, 0, 0] | 開始 |
 | 2 | 1→2 | [0, w1+d, 0] | 間隔を強制する |
 | 3 | 2→3 | [0, w1+d, w1+d+w2+d] | チェーンを伝播する |

 これは、直接的なオーバーラップがなくても、間接的な制約がどのように蓄積されるかを示しています。 

ここで、2 つの独立した垂直グループを考えてみましょう。 1 つのグループは庭の下部にスラブが集まっており、もう 1 つのグループは上部にあります。 これらは決して相互作用しないため、それらの距離は独立して計算され、それらの寄与が加算されます。 

| ステップ | コンポーネント | 結果の幅 |
 | --- | --- | --- |
 | 1 | 下位グループ | W1 |
 | 2 | 上位グループ | W2 |
 | 3 | 合計 | W1 + W2 |

 これは、コンポーネント間の独立性が不可欠であることを示しています。 それらをマージすると、人為的な制約が誤って導入されてしまいます。

 n ≤ 100 であり、複数のテスト ケースがあってもペアワイズ チェックの合計数は少ないままであるため、2 次複雑度は許容可能です。 最悪の場合の密なオーバーラップ シナリオでは、メモリ使用量はエッジの保存によって支配されます。

 ## 特殊なケース

 スラブが推移的なチェーンのみを介してオーバーラップする場合、重大なエッジ ケースが発生します。 たとえば、スラブ A は B と重なり、B は C と重なりますが、A と C は重なりません。 このアルゴリズムは、制約グラフを通じて A → B → C の伝播を引き続き正しく実行し、正しい間隔の累積を保証します。 

もう 1 つのエッジ ケースは、垂直方向に重なるスラブがない場合です。 この状況では、すべてのスラブは独自のコンポーネントであり、エッジは作成されず、すべての距離はゼロのままです。 計算された答えは、元の幅の合計まで正確に減少します。これは、圧縮が不可能であることを意味します。 

最後のエッジ ケースは、すべてのスラブが垂直に重なる密なオーバーラップです。 これにより、制約の完全なグラフが生成されますが、制約は初期順序と一致しており、サイクルが導入されていないため、トポロジカル DP は引き続き機能します。
