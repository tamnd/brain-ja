 ## 解決策
 ## 問題の理解

 私たちには、米粒一袋に関するいくつかの独立したシナリオが与えられています。 各シナリオには、個々の穀物の重量とすべての穀物の合計重量という 2 つの層の不確実性があります。 

各グレインは、ある平均値を中心とした対称間隔にある整数の重みを持つことが知られています。 これとは別に、すべての穀物の総重量も別の対称区間内に収まるように制約されます。 問題は、すべてのグレインが独自の許容範囲を尊重し、すべてのグレインの合計が許容合計範囲内に収まるように、すべてのグレインに整数の重みが割り当てられているかどうかです。 

私たちは重みを構築することを求められるのではなく、そのような構成が論理的に可能かどうかを判断することだけを求められます。 

テスト ケースごとの制約は小さく、最大 1000 グレインと最大 1000 のテスト ケースがあります。 これは、ケースごとの線形スキャンでもすでに約 10^6 の演算に達するため、どのような解法もテスト ケースごとに定数時間である必要があることを直ちに示唆します。これはまだ問題ありませんが、分布に対する入れ子推論を伴うものは不必要で過剰なものになります。 

平均値だけを考えると、微妙な落とし穴が生じます。 素朴な考えは、平均穀物重量範囲を合計間隔によって暗示される平均と比較することです。 これは不正確です。なぜなら、全体の制約は粒子ごとの平均ではなく合計にあり、極値の構成が重要だからです。 

もう 1 つの潜在的な間違いは、スケーリングせずに境界を独立して扱うことです。 合計範囲は n でスケールされますが、不注意な実装では粒単位の境界を乗算するのを忘れる可能性があり、不正確な実現可能性チェックにつながる可能性があります。 

## アプローチ

 強引な解釈では、許容範囲内で粒子の重みの可能な割り当てをすべて試し、必要な間隔内の合計が生成される割り当てがあるかどうかを確認します。 単一のテスト ケースであっても、各グレインには最大約 2001 個の可能な値の範囲があるため、組み合わせの数はおよそ 2001 個になります。$(2001)^n$、これは非常に小さい n の場合でも完全に実行不可能です。 問題の構造から、個々の割り当てを調べる必要がないことがわかります。 

重要な観察は、重みの正確な分布は気にせず、合計の可能な範囲だけを気にするということです。 各グレインは独立しており、加法的に寄与するため、すべてのグレインが最小値をとる場合に最小の総和が達成され、すべてのグレインが最大値をとる場合に最大の総和が達成されます。 これにより、問題全体が、達成可能な合計間隔と必要な合計間隔という 2 つの間隔が重なっているかどうかを確認することに変わります。 

達成可能な合計範囲を計算したら、実現可能性はこれら 2 つの区間が交差するかどうかを確認することになります。

 ## アルゴリズムのチュートリアル

 各テスト ケースについて、少数の決定的なステップを進めます。 

1. 単一穀物の可能な最小重量を次のように計算します。$a - b$。 これは 1 粒あたりの最小許容値です。 
2. 単一の穀物の最大可能重量を次のように計算します。$a + b$。 これは 1 粒あたりの最大許容値です。 
3. 両方を乗算します$n$可能な最小および最大の合計重みを取得するには、次のようにします。$S_{\min} = n(a - b)$そして$S_{\max} = n(a + b)$。 このステップは、各グレインが独立して寄与しており、合計を押し上げるために各グレインの極端な部分を選択できるため、正当化されます。 
4. 入力から許容される合計重量間隔を次のように計算します。$[c - d, c + d]$。 
5. これら 2 つの間隔が交差するかどうかを確認します。 具体的には、達成可能な最大合計が最小許容合計以上であり、最小達成可能合計が最大許容合計以下であることを検証します。 
6. 両方の条件が当てはまる場合は、「Yes」を出力します。 それ以外の場合は「いいえ」を出力します。 

### なぜ効果があるのか

 独立した有界変数の合計は、すべての変数をそれ自身の極値に押し上げることによって常にその極値に達します。 すべての最小値の選択からの逸脱は合計を増加させ、すべての最大値の選択からの逸脱は合計を減少させるため、中間の構成は到達可能な間隔をこれ以上拡張できません。$[n(a-b), n(a+b)]$。 したがって、問題は正確には、この到達可能な間隔が必要な間隔と重なっているかどうかを確認することになります。これは実現可能性にとって必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, a, b, c, d = map(int, input().split())
    
    min_sum = n * (a - b)
    max_sum = n * (a + b)
    
    low = c - d
    high = c + d
    
    if max_sum >= low and min_sum <= high:
        print("Yes")
    else:
        print("No")
```実装は、導出された間隔推論に直接続きます。 重要な詳細は、粒子ごとの間隔の両方のエンドポイントを n 倍に正しくスケーリングすることです。 よくある間違いは比較することです$a-b$そして$a+b$乗算せずに合計境界を直接使用するため、集計は無視されます。 

オーバーラップ条件は対称的です。どちらのエンドポイントでも実現可能性を検証できますが、一方が他方を厳密に含むのではなく、両方のエンドポイントをチェックして、間隔が交差していることを確認する必要があります。 

## 実用的な例

 2 つのサンプル ケースをトレースして、間隔比較がどのように動作するかを確認します。

 | コンピューティング | 17 | 23 | 119 | 161 | [83、119] | はい |

 達成可能な合計範囲は [119, 161] ですが、必要な範囲は [83, 119] です。 間隔は 119 で接しているため、すべての粒子が最小値をとる境界ケースで実現可能性が正確に保たれます。 

### 例 2

 入力:`11 11 10 234 2`| ステップ | 最小粒度 | 最大粒度 | 最小合計 | 最大合計 | 合計間隔 | 結果 |

これらの例は、境界接触が有効であり、厳密な分離が失敗の原因となることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    t = int(input())
    out = []
    for _ in range(t):
        n, a, b, c, d = map(int, input().split())
        min_sum = n * (a - b)
        max_sum = n * (a + b)
        low = c - d
        high = c + d
        out.append("Yes" if (max_sum >= low and min_sum <= high) else "No")
    return "\n".join(out)

 ## 特殊なケース

 重要なエッジケースの 1 つは、間隔が 1 つの点で正確に接触する場合に発生します。 たとえば、達成可能な最大の合計が必要な最小の合計と等しい場合でも、正解は「はい」になります。 条件では非厳密な不等式が使用され、境界の実現可能性が確実に受け入れられるため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、n が 1 に等しい場合です。問題は 2 つの間隔が直接重なっているかどうかをチェックすることに帰着しますが、1 を乗算すると間隔が維持されるため、スケーリング ステップは依然として正しく機能します。 

3 番目のケースは、b が 0 に等しい、または d が 0 に等しい場合です。これにより、一方または両方の間隔が単一の点に折りたたまれます。 交差チェックでは特別なケースを使用せずに縮退区間が自然に処理されるため、アルゴリズムは引き続き機能します。
