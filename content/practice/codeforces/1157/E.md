 ## 解決策
 ## 問題の理解

 2 つの配列が与えられています`a`そして`b`、それぞれの長さ`n`、からの整数を含む`0`に`n-1`。 再注文できます`b`勝手に。 注文を選択した後、`b`、新しい配列を構築します`c`各要素はどこにあるのか`(a_i + b_i) % n`。 私たちの目標は再注文することです`b`となることによって`c`辞書編集的に最小になります。 

辞書編集的な順序は辞書の順序と同じように機能します。2 つの配列が異なる最初の位置によって、どちらが小さいかが決まります。 たとえば、最初の要素が異なる場合、後の要素に関係なく、小さい最初の要素が優先されます。 これは、最初のエントリを最小限に抑えることに重点を置く必要があることを意味します。`c`後のエントリについて心配する前に。 

制約`n ≤ 2·10^5`2 秒の制限があるということは、およそ O(n log n) 回の操作は許容できるものの、すべての順列を反復処理することはできないことを意味します。`b`(O(n!)) または O(n^2) のネストされたループを実行します。 したがって、単純な総当たりアプローチは実行不可能です。 

考慮すべきエッジケースは、すべての要素が`a`が同じであるか、すべての要素が同じである場合、`b`は同じです。 たとえば、次の場合`a = [1,1,1]`そして`b = [2,2,2]`、並べ替えによって辞書編集上の順序が変更されることはありません。 全て`c_i = (1+2)%3 = 0`、 それで`c = [0,0,0]`。 モジュラー演算を考慮しない不用意な貪欲なアプローチは、モジュロによるラップアラウンド効果を考慮せずに、誤って「最小値と最小値のペア」を試みる可能性があります。`n`。 

最初の要素を最小化すると、後の要素が最適ではなくなる場合、別の微妙なケースが発生します。 例えば、`a = [2,1]`そして`b = [1,2]`。 私たちが選ぶなら`b_1 = 1`最小限に抑える`(2+1)%3 = 0`、次の要素`(1+2)%3 = 0`偶然でもいいです。 しかし、もし`b`異なる値を持っていた場合、単純な「常に可能な限り最小のものを選択する」では、モジュラーラップアラウンドがより大きな 2 番目の要素を作成する場合、辞書編集上最小のシーケンスが得られない可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 のすべての順列を生成できます。`b`、計算する`c`各順列について、辞書順に最小のものを追跡します`c`。 これは正しいですが、O(n! · n) の操作が必要であり、これは不可能です。`n = 2·10^5`。 

最適化のための重要な洞察は、モジュラー加算が循環数直線のように動作することに気づくことから得られます。 それぞれについて`a_i`、選びたい`b_j`そのような`(a_i + b_j) % n`最小化されます。 これは最小値を見つけることと同じです`b_j ≥ n - a_i`もし可能なら; そうでない場合`b_j`存在する場合、利用可能な最小のものを選択します`b_j`。 保管することで`b`ソートされ、マルチセットのような構造 (または`SortedList`Python では)、実行可能な最小限のものを効率的に選択できます。`b_j`それぞれに`a_i`O(log n) 時間で完了します。 

これにより、複雑さが階乗から O(n log n) に軽減されます。 仕分け`b`は O(n log n) を必要とし、n 個の選択のそれぞれに対して対数検索と削除が必要です。

 ## アルゴリズムのチュートリアル

 1. 配列のソート`b`昇順で。 これにより、ターゲット以上の最小要素を効率的に選択できます。 
2. 空のリストを初期化する`c`結果の配列を保存します。 
3. インデックスごとに`i`から`0`に`n-1`、 考慮する`a_i`。 最小値を計算する`b_j`から`b`そのような`(a_i + b_j) % n`最小限です。 具体的には、最小のものを探します`b_j`≥`n - a_i`。 そのような場合`b_j`存在する場合はそれを選択します。 それ以外の場合は、残っている最小のものを選択します`b_j`。 
4.追加`(a_i + b_j) % n`に`c`そして削除します`b_j`利用可能な要素から。 
5. すべての位置まで続けます。`c`満たされています。 

機能する理由: あらゆる段階で、現在の位置が`c`利用可能なものを考慮すると最小化されます`b`要素。 モジュラー算術ラップアラウンドにより、ゼロに到達できない場合でも可能な限り最小の合計が得られます。 仕分け`b`また、バイナリ検索またはマルチセットを介して選択することで正確性が維持され、各ステップで貪欲に選択することで辞書編集的な最小性が保証されます。 

## Python ソリューション```python
import sys
import bisect
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
b = list(map(int, input().split()))
b.sort()

from collections import deque
b_list = deque(b)
c = []

for ai in a:
    # find the smallest b_j such that (ai + b_j) % n is minimal
    target = n - ai
    idx = bisect.bisect_left(b_list, target)
    if idx < len(b_list):
        bj = b_list[idx]
        del b_list[idx]
    else:
        bj = b_list[0]
        del b_list[0]
    c.append((ai + bj) % n)

print(' '.join(map(str, c)))
```コードは最初にソートされます`b`効率的な選択が可能になります。`bisect_left`最小のものを見つけます`b_j`これはラップアラウンドの最小合計要件を満たします。 そうでない場合`b_j`存在する場合、全体的に最小のものが選択されます。 両端キューを使用すると、どちらの側からでも効率的に削除できます。

## テストケース```python
import sys, io
from collections import deque
import bisect

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    b.sort()
    b_list = deque(b)
    c = []
    for ai in a:
        target = n - ai
        idx = bisect.bisect_left(b_list, target)
        if idx < len(b_list):
            bj = b_list[idx]
            del b_list[idx]
        else:
            bj = b_list[0]
            del b_list[0]
        c.append((ai + bj) % n)
    return ' '.join(map(str, c))

# Provided sample
assert run("4\n0 1 2 1\n3 2 1 1\n") == "1 0 0 2", "sample 1"

# Minimum-size input
assert run("1\n0\n0\n") == "0", "min-size"

# All equal values
assert run("3\n1 1 1\n2 2 2\n") == "0 0 0", "all equal"

# Maximum-size input simplified (stress test)
n = 10**5
inp = f"{n}\n" + " ".join(["0"]*n) + "\n"
