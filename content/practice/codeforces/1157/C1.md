 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$。 1 から 1 までのすべての値が含まれるカードの列として考えてください。$n$は 1 回だけ表示されます。 各移動では、現在の行の左端または右端からカードを 1 枚削除することのみが許可され、削除された値を記録します。 これにより、選択された値のシーケンスが構築されます。 

目標は、合計を最大化することやすべてのカードを収集することではなく、選択した順序で厳密に増加するシーケンスを形成する選択された値の数を最大化することです。 また、この最大長を達成する左/右決定の有効なシーケンスを 1 つ出力する必要があります。 

制約$n \le 2 \cdot 10^5$考えられるすべてのピックシーケンスをシミュレートする戦略は直ちに除外されます。 各ステップは 2 つの選択肢に分岐するため、単純な検索は指数関数的に行われます。 すべての部分配列と最後に選択された値を考慮する動的プログラミング ソリューションであっても、慎重に線形動作に落とし込まない限り、サイズが大きすぎます。 

ローカルで最適な選択がグローバル構造と矛盾する場合、微妙な問題が発生します。 たとえば、常に 2 つの端のうち小さい方を選択することは、増加順序を維持するのに役立つため合理的であるように思えますが、これにより、配列の奥深くに隠された大きな増加する尾部へのアクセスがブロックされる可能性があります。 

もう 1 つの失敗モードは、現在の目的のみに基づいた貪欲な選択です。 次のような入力では$[1, 100, 2, 3, 4]$、常に小さい方の端を最初に選択すると、1 が取られ、その後不十分な継続が強制されますが、決定がわずかに遅れると、はるかに長い増加シーケンスが生成されます。 

したがって、重要な問題は、出力シーケンスに対する単調制約を伴う、縮小間隔にわたってグローバルに一貫した戦略が必要であるということです。 

## アプローチ

 ブルートフォースの見方は簡単です: 各間隔で$[l, r]$、両方の選択を試してください$a_l$そして$a_r$それらが最後に選択した値より大きい場合は、再帰的に実行し、最良の結果を取得します。 これは高さの二分木を調べます$n$、与える$O(2^n)$最悪の場合は状態。 「最後の値」はさまざまなパスにわたって多くの可能性を考慮するため、メモ化を行ったとしても、最後に選択された値への依存により状態を効果的に圧縮することができなくなります。 

関連する唯一の制約が最後に選択した値であることに気づくと、構造は単純化され、各ステップでそれを 2 つの利用可能な端と比較するだけになります。 このプロセスでは常に左または右のポインタが内側に進むため、残りの構造は常に連続した部分配列になります。 重要な観察は、次に選択される値が現在の最後の値よりも厳密に大きいことを保証する以上に、将来の結果を考慮する必要がないということです。 これにより、将来の選択に対する柔軟性がより高く保たれるため、可能であれば常に小さい有効な端を選択する貪欲なシミュレーションが可能になります。 一方の端だけが有効な場合、私たちはそれを取ることを余儀なくされます。 どちらの端も有効でない場合、プロセスは停止します。 

これにより、指数関数的な分岐が縮小ポインターの単一の線形スキャンに変わります。

 ## アルゴリズムのチュートリアル

 現在の間隔で 2 つのポインターを維持します。`l`そして`r`、および変数`last`最後に選択された値を構築されたシーケンスに保存します。 一連の動きも構築します。 

1.初期化`l = 0`、`r = n - 1`、と設定します`last = 0`すべての値は正であり、1 から始まるためです。 
2. その間`l <= r`、2人の候補者を検査します`a[l]`そして`a[r]`。 
3. 両方の場合`a[l]`そして`a[r]`以下である`last`、有効な増加継続が存在しないため、停止します。 
4. 両方がより大きい場合`last`、2 つの値のうち小さい方を選択し、対応するポインタを内側に移動します。 

より小さい値を選択すると、将来の選択に対するより弱い下限が維持され、将来の有効な選択肢の数を減らすことができません。 
5. そのうちの 1 つだけがより大きい場合`last`、もう一方は増加シーケンスを拡張できないため、一方を選択する必要があります。 
6. それぞれの有効な選択の後に、`'L'`または`'R'`答えと更新へ`last`。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは残りの間隔にすべての未使用の要素が含まれていることを維持し、これまでに構築されたシーケンスは厳密に増加しています。 両方の端が有効な場合、小さい方の端を選択しても、達成可能な最適な長さが減少することはありません。これは、大きい方の有効な端の後に開始される可能性のある将来のシーケンスも、小さい方の端の後に開始することができますが、その逆はできないためです。 これにより、「オーバーシュート」を防ぎ、将来のピックをブロックすることがなくなります。 すべてのステップで要素が 1 つだけ削除され、再検討されることはないため、プロセスは最大長の有効なシーケンスを貪欲に構築します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    l, r = 0, n - 1
    last = 0
    ans = []

    while l <= r:
        left = a[l]
        right = a[r]

        if left <= last and right <= last:
            break

        if left > last and right > last:
            if left < right:
                ans.append('L')
                last = left
                l += 1
            else:
                ans.append('R')
                last = right
                r -= 1
        elif left > last:
            ans.append('L')
            last = left
            l += 1
        else:
            ans.append('R')
            last = right
            r -= 1

    print(len(ans))
    print("".join(ans))

if __name__ == "__main__":
    solve()
```実装は 2 ポインター構造に直接に従います。 の`last`変数は厳密に増加する制約を強制します。 重要な詳細は厳密な比較です`> last`すべての値が異なるため、正確さが保証されます。 

両端が有効な場合、比較は`left < right`より小さい候補に対する貪欲な優先順位をエンコードします。 これが最適性に影響を与える唯一の決定点です。 

ループの終了条件`l <= r`すべての要素が最大 1 回考慮されるようにします。 

## 実用的な例

 ### 例 1

 入力:$[2, 1, 5, 4, 3]$| l | r | 左 | 右 | 最後 | 選択 | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 4 | 2 | 3 | 0 | Ｌ | 2 |

 | 1 | 3 | 1 | 4 | 3 | R | 2,3,4 |
 | 1 | 2 | 1 | 5 | 4 | R | 2、3、4、5 |

 アルゴリズムが構築される$[2,3,4,5]$、長さ 4 に達し、最適なものと一致します。 

このトレースは、アルゴリズムが、グローバルに有効でない場合に、より小さいローカル値を取得する誘惑を回避し、代わりに実現可能性を優先する方法を示しています。 

### 例 2

 入力:$[1, 3, 2, 4]$| l | r | 左 | 右 | 最後 | 選択 | 答え |

 最適な長さ 3 が得られます。 ここでの重要な動作は、3 を取得した後、アルゴリズムが 2 を正しくスキップし、4 を続行することです。 

これは、局所的な単調性が後戻りせずに意思決定を導くのに十分であることを示しています。

 ## 特殊なケース

 次のような最小限の配列$[1]$アルゴリズムの初期化の正確さを示します。 両端が一致するため、唯一の有効な動きは、その要素を取得して、長さ 1 のシーケンスを生成することです。 

次のような完全に減少する配列$[4,3,2,1]$各ステップで片側のみが有効な場合、アルゴリズムは常に右端を取得するように退化することを示しています。 シーケンスは最大から最小の順に消費されるため、各ピックは厳密に増加しています。 

みたいなパターン$[1,6,2,5,3,4]$「より小さい有効な終端を選択する」ルールの必要性を強調しています。 複数のステップでは両端が有効であり、常に小さい方を選択することで将来の柔軟性が損なわれず、完全なシーケンスを抽出できます。
