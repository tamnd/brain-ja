 ## 解決策
 ## 問題の理解

 正確に分配する必要がある`n`全体的に問題を解決した`k`連続した日々。 

させて`a[i]`その日に解決した問題の数になります`i`。 毎日少なくとも 1 つは問題が含まれている必要があります。 シーケンスは厳密に増加する必要があり、毎日の値は最大で 2 倍増加する可能性があります。$$a_i < a_{i+1} \le 2a_i$$すべての値の合計は正確に一致する必要があります`n`。 

タスクは何かを最適化することではありません。 有効なシーケンスを 1 つ構築するか、そのようなシーケンスが存在しないことを確認するだけで済みます。 

制約は異常です。 日数は次のように大きくすることができます`10^5`、問題の総数は次のように大きくなる可能性があります。`10^9`。 可能なシーケンスを検索しようとするアルゴリズムは絶望的です。 1 日に多くの候補州を保存するだけでもコストがかかりすぎます。 ほぼ直線的な時間で実行される直接的な構築的なメソッドが必要です。`k`。 

最初の観測値は、可能な限り最小の有効なシーケンスから得られます。 値は厳密に増加する正の整数である必要があるため、最小シーケンスは次のようになります。$$1,2,3,\ldots,k$$合計は誰の$$\frac{k(k+1)}2$$もし`n`がこの値より小さい場合、すべての有効なシーケンスには少なくともその数の総問題が存在する必要があるため、解決策は存在しません。 

2 番目の微妙なケースは、シーケンスが強制的に大きすぎる場合に発生します。 仮定する`k=3`そして`n=100`。 任意の最初の値から開始`x`、可能な最大のシーケンスはおよそ$$x,\ 2x,\ 4x$$合計で`7x`。 増加制限により、シーケンスにパックできる合計の量が制限されます。 構築では、成長の下限と上限の両方を尊重する必要があります。 

考慮する`n=5, k=3`。 

最小可能額は次のとおりです$$1+2+3=6$$したがって、正しい答えは`NO`。 陽性性のみをチェックする不注意な実装では、誤った出力が行われる可能性があります。`1 1 3`, しかし、順序は厳密には増加していません。 

考慮する`n=8, k=3`。 

有効な答えは、$$1\ 2\ 5$$いいえ、それは無効です。`5 > 2·2`。 残りの問題を貪欲に最終日に放り込んでしまうと、倍増の制限を忘れがちです。 

考慮する`n=26, k=6`。 

最小シーケンスはすでに使用しています$$1+2+3+4+5+6 = 21$$配布する追加問題は 5 つだけです。 分布では、単調性と 2 倍の制約の両方を維持する必要があります。 すべての追加要素を最後の要素に追加するだけで、$$1\ 2\ 3\ 4\ 5\ 11$$違反するもの`11 ≤ 10`。 

これらの例は、すべての局所的な制約を維持しながら追加額のバランスを取ることが難しいことを示しています。 

## アプローチ

 ブルートフォースアプローチでは、合計が次のような増加するシーケンスを生成しようとします。`n`そして倍加条件をテストします。 中程度の値であっても、これは膨大なものになります。 固定和で増加する整数シーケンスの数は組み合わせ的に増加します。`n`到達できる`10^9`。 徹底的な検索はまったく不可能です。 

重要な観察は、すべての有効なシーケンスを基本シーケンスとして見ることができるということです。$$x,\ x+1,\ x+2,\ \ldots,\ x+k-1$$さらに、日ごとにいくつかの追加の増分が配布されます。 

最初の値が固定の場合`x`、達成可能な最小額は次のとおりです。$$kx + \frac{k(k-1)}2.$$これは、可能な最大の開始値を見つけることを直ちに示唆します。`x`最低額が超えないもの`n`。 

大きな開始値が役立つのはなぜですか? すべての要素を 1 つ増やすと消費されるため、`k`すべての制約を自動的に保持しながら、合計の単位を調整します。 私たちはたくさんのものを吸収したいと思っています`n`残りの少量を処理する前に、可能な限りこのようにしてください。 

固定後`x`、余分な量が残っています$$r = n - \left(kx + \frac{k(k-1)}2\right).$$シーケンスは次のように始まります$$x,\ x+1,\ \ldots,\ x+k-1.$$今、配布しています`r`追加ユニット。 倍加制約は、各位置をどれだけ増加できるかを決定します。 左から右に処理すると、各要素は次のいずれかに達するまで成長する可能性があります。$$2a_{i-1}$$またはまだ必要な量。 この貪欲な分散により、最初に前の要素が最大化され、後の要素のためにできるだけ多くのスペースが作成されます。 

すべての位置を処理した後に剰余がゼロになった場合、有効なシーケンスが得られます。 そうしないと目標金額を達成できません。

 ## アルゴリズムのチュートリアル

 1. 可能な最小合計を計算します。$$S_{\min}=\frac{k(k+1)}2$$もし`n < Smin`、印刷`NO`。 
2. 最大の整数を見つける`x`そのような$$kx+\frac{k(k-1)}2 \le n.$$これは$$x=\left\lfloor\frac{n-\frac{k(k-1)}2}{k}\right\rfloor.$$可能な最大の開始値を選択すると、すべての制約が自動的に満たされながら、合計のほとんどが吸収されます。 
3. 基本配列を構築する$$a_i = x+i$$ゼロベースのインデックスを使用します。 
4. 残量を計算する$$r = n-\sum a_i.$$5. 位置を末尾から先頭に向かって処理します。 

ポジションについて`i`を維持する最大の増加を決定します。$$a_i \le 2a_{i-1}.$$利用可能な容量は、$$2a_{i-1}-a_i.$$6.追加$$\min(r,\text{capacity})$$に`a_i`から同じ金額を引きます。`r`。 
7. すべての位置が処理されるまで続行します。 
8. もし`r`まだ陽性です、印刷します`NO`。 それ以外の場合は印刷します`YES`そしてそのシーケンス。 

### なぜ効果があるのか

 基本シーケンスは、最初の値を持つ最小の有効なシーケンスです。`x`。 同じ最初の値を持つより大きな有効なシーケンスは、非負の増分を追加することによってのみ取得できます。 

残りの合計を分配する場合、後の位置を増やしても、前の位置に関係する制約には影響しません。 各位置にできる限り多くの値を与えることで、シーケンスの将来の容量が最大化されます。 この貪欲なプロセスが残りのユニットをすべて吸収できない場合、すべてのポジションがすでに最大法的価値に達しているため、他の分配はできません。 したがって、アルゴリズムは、有効なシーケンスが存在する場合にのみ成功します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    if n < k * (k + 1) // 2:
        print("NO")
        return

    x = (n - k * (k - 1) // 2) // k

    a = [x + i for i in range(k)]

    cur_sum = sum(a)
    rem = n - cur_sum

    for i in range(k - 1, 0, -1):
        cap = 2 * a[i - 1] - a[i]
        add = min(rem, cap)
        a[i] += add
        rem -= add

    if rem != 0:
        print("NO")
        return

    print("YES")
    print(*a)

solve()
```最初のチェックは、基本的な不可能条件を処理します。 厳密に増加するシーケンスであっても`1,2,...,k`を超える`n`、構築は存在しません。 

値`x`実行可能な最大の開始値として選択されます。 これは、残りの調整を以下に減らすための重要なアイデアです。`k`。 

配列には、最初は次で始まる最小の有効なシーケンスが含まれています。`x`。 その合計が超えないことが保証されています`n`。 

残りは右から左に分配されます。 各位置について、倍加制約が厳しくなる前にどのくらいの余地が残っているかを正確に計算します。 この量を超えて追加すると、問題の条件に違反します。 

最終的な残量チェックは必須です。 いくつかの値`n`たとえ表現できないとしても`n`最低額を超えています。 このような場合、貪欲な充填はすべての容量に達しますが、残りの部分はまだ存在しており、不可能であることがわかります。 

すべての算術演算は 64 ビット整数に快適に収まります。 Python の整数はこれを自動的に処理します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n, k = map(int, input().split())

    if n < k * (k + 1) // 2:
        return "NO\n"

        a[i] += add

        return "NO\n"

    return "YES\n" + " ".join(map(str, a)) + "\n"

 ## 特殊なケース

 次のことを考慮してください。```
5 3
```有効な最小合計額は次のとおりです。$$1+2+3=6$$以来`5 < 6`、アルゴリズムはすぐに出力します`NO`。 これにより、合計は満たしているが厳密な増加に違反する構築が防止されます。 

考慮する：```
8 3
```アルゴリズムが構築される`[1,2,3]`残りあり`2`。 

最後のポジションには定員があります$$2\cdot2-3=1$$そうなります`4`、残りを残す`1`。 

最初の要素の厳密な順序に違反するため、中間の位置を増やすことはできません。 残りは生き残るため、アルゴリズムは次のように出力します。`NO`。 

これにより、次のようなシーケンスが正しく拒否されます。`1 2 5`、合計は満たしていますが、倍増制限に違反しています。 

考慮する：```
100 3
```アルゴリズムは大きな値から始まります`x`、その後、残りの金額を分配しようとします。 すべてのポジションは最終的には最大の法的価値に達します。 余分な合計がまだ残っている場合、アルゴリズムは不可能を報告します。 これは、多くの素朴で貪欲なソリューションが見落としている上限成長の制限を捉えています。
