 ## 解決策
 ## 問題の理解

 数字は数字の文字列として与えられます。`1`に`9`そしてマッピング`f`同じ範囲内の各桁から別の桁へ。 タスクは、最大 1 つの連続する数字セグメントを選択し、各数字を置き換えることによって、結果の数値を最大化することです。`x`そのセグメントでは`f(x)`。 他のすべての桁は変更されません。 

入力により得られるものは、`n`、桁数、数字`a`文字列として、およびそれを表す 9 つの整数のリストとして`f(1)`を通して`f(9)`。 出力は、操作を 1 回実行するかまったく実行しないことによって取得できる最大の数値です。 

与えられた`n`最大 200,000 で、制限時間は 2 秒です。考えられるすべてのサブセグメントを単純に考慮するアルゴリズムでは、次のオーダーが必要になります。`O(n^2)`動作が遅すぎます。 線形または線形算術的なアプローチが必要です。 

明らかではないエッジケースには、適用するシーケンスが含まれます。`f`後の桁を増やす前に、一時的に桁を減らすことができます。 たとえば、次の場合`a = 987`そして`f(9) = 8, f(8) = 9`、素朴な貪欲な人は、次の時点で置き換えを開始しようとするかもしれません。`9`たとえ変更しないままにしておくと、全体の数値が大きくなります。 別のエッジ ケースは、すべての桁がそれ以下の値にマップされる場合に発生します。この場合、最適な措置は、操作をまったく実行しないことです。 例えば、`a = 123`そして`f = [1,1,1,4,5,6,7,8,9]`生成する`123`置換によって桁が増加しないためです。 

## アプローチ

 ブルートフォースアプローチは単純です。可能なすべての連続サブセグメントを反復処理し、適用します。`f`そのセグメント内の数字に変換し、結果の数値を計算します。 発生した最大数を記録してください。 これが機能するのは、問題によって許可される操作はすべて、連続したセグメントの置換として表現できるためです。 ただし、サブセグメントの数は増加します。`n(n+1)/2`、それで、`n = 2*10^5`、このアプローチには次のオーダーが必要になります。`2*10^10`という操作が行われますが、これは非現実的です。 

最適な解決策を得るために重要な点は、最初の位置から数字の置換を開始する必要があるということです。`f(x) > x`限り交換を続けます`f(x) >= x`。 一度`f(x) < x`、これ以上交換を延長すると数値が減少するため、交換を中止します。 これが機能するのは、操作が連続して最大 1 回のみ適用される必要があり、数値の前の大きな桁の方が後の桁よりも最終的な数値に大きな影響を与えるためです。 これにより、数値を左から右に 1 回スキャンし、次の単純な比較に基づいて各桁を置換するかどうかを決定する貪欲なソリューションが得られます。`f(x)`そしてアクティブな置換セグメント内にいるかどうかを示すフラグ。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. フラグを初期化する`started`に`False`置換セグメントを開始したかどうかを示します。 空のリストを初期化する`result`最終的な数値を構築します。 
2. 各桁を反復処理します。`d`元の番号は左から右へ。 変換する`d`比較のために整数に変換する`f(d)`。 
3. もし`f(d) > d`、数字を次のように置き換えます`f(d)`そしてセット`started`に`True`。 置換された数字を以下に追加します`result`。 
4. もし`f(d) == d`を確認してください。`started`フラグ。 もし`started`は`True`で置き換えを続けます`f(d)`(変化なし)。 もし`started`は`False`、元の数字を追加します`result`。 
5. もし`f(d) < d`そして`started`は`True`、置換セグメントを停止します。 セット`started`に`False`元の数字を追加します`result`。 もし`started`は`False`、元の数字を追加するだけです。 
6. すべての数字を処理した後、`result`リストを文字列に変換して出力します。 

ここで不変なのは、置換セグメントを開始したら、置換によって数値が減少するまで各桁を最大化するということです。 操作は連続している必要があるため、セグメント内の桁をスキップすることはできません。 開始または終了が早くても遅くても結果が小さくなるため、これにより最大数が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = input().strip()
f = list(map(int, input().split()))

result = []
started = False

for ch in a:
    digit = int(ch)
    mapped = f[digit - 1]
    if mapped > digit:
        result.append(str(mapped))
        started = True
    elif mapped == digit:
        result.append(str(digit) if not started else str(mapped))
    else:
        result.append(str(digit))
        if started:
            started = False

print(''.join(result))
```このソリューションでは、結果の配列を初期化し、数値を反復処理します。 整数への変換が必要な理由は、`f`は整数のリストです。 の`started`フラグにより​​、置換が連続していることが保証され、比較によって置換の開始、継続、または停止が正しく処理されます。 結果リストを最後に結合すると、文字列の連結が繰り返されることがなくなります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = input().strip()
    f = list(map(int, input().split()))
    result = []
    started = False
    for ch in a:
        digit = int(ch)
        mapped = f[digit - 1]
        if mapped > digit:
            result.append(str(mapped))
            started = True
        elif mapped == digit:
            result.append(str(digit) if not started else str(mapped))
        else:
            result.append(str(digit))
            if started:
                started = False
    return ''.join(result)

# provided samples
assert run("4\n1337\n1 2 5 4 6 6 3 1 9\n") == "1557", "sample 1"

# custom cases
assert run("3\n987\n1 2 3 4 5 6 7 8 9\n") == "987", "no replacement needed"
assert run("5\n11111\n9 8 7 6 5 4 3 2 1\n") == "99999", "all digits increased"
assert run("4\n4321\n1 2 3 4 5 6 7 8 9\n") == "4321", "all digits mapped to smaller values"
assert run("6\n123456\n2 3 4 5 6 7 8 9 1\n") == "234567", "replacement starts at first digit"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | f(x) ≤ x | 987 987 | 操作をスキップできます |
 | 11111 f(x) > x | 99999 | すべての数字の最大置換 |
 | 4321 (f(x) < x |) 4321 | 桁が減少する前に正しく停止します。 
| 123456 f(x) > x | 234567 | 初回増加時から交換開始 |
