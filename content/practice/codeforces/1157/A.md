 ## 解決策
 ## 問題の理解

 特定の変換関数を繰り返し適用することによって生成された数値を調べることが求められます。 数字の場合$x$、まずそれに 1 つ追加します。 結果の数値の末尾にゼロがある場合は、ゼロになるまですべて削除します。 これは関数を定義します$f(x)$。 数字$y$から到達可能と言われています$x$申請する場合$f$から始まるゼロ回以上の回$x$最終的に生成する$y$。 

入力は単一の整数です$n$、出力は、から到達可能な個別の数値のカウントです。$n$。 到達可能な番号には次のものが含まれます$n$それ自体と、繰り返し適用して得られる数値$f$。 

制約$1 \le n \le 10^9$ということを暗示します$n$標準の整数型に適合し、アルゴリズムはすべての数値を反復処理することを避けるべきです。$n$なぜなら、それには最大10億回の操作が含まれる可能性があるからです。 解は、理想的には、桁数または演算数が線形または対数である必要があります。 

エッジケースは、数値が多くのゼロで終わるか、10 のべき乗をわずかに下回る場合に発生します。 例えば、$n = 999$後に大きなジャンプを生成します$f(999) = 1$。 単純に毎回 1 ずつ増分してゼロを削除すると、実装がこれらのジャンプを慎重に処理しない場合、循環や数値の欠落が発生する可能性があります。 もう 1 つのエッジ ケースは、末尾に複数のゼロがある数値です。次のようなものです。$n = 1000$、1 つのアプリケーションがすぐにジャンプします。$1$。 

## アプローチ

 ブルートフォースアプローチはシンプルです。$n$そして繰り返し適用する$f$、数値が繰り返されるまでセット内の各数値を保存します。 これにより、プロセスは最終的に以前に確認された数値に到達する必要があるため、正確さが保証されます (数値はすべて正であり、関数は末尾のゼロを減らし、最終的にはループしてより小さい数値になります)。 最悪の場合、演算数はリダクションを繰り返す間に発生する合計桁数とほぼ同じになります。 However, for$n = 10^9$、これは数十億ステップに達する可能性があり、1 秒の制限には遅すぎます。 

重要な観察は、以下から到達できる唯一の数字であるということです。$n$とは異なるものです$n$末尾のゼロを削除した後、1 ずつ増分します。 したがって、によって生成された数値のカウントを追跡できます。$f$すべての中間数値を明示的に保存せずに。 代わりに、繰り返し計算できます。$f(n)$以前に確認された値に達するか、0 に減少するまで、生成される各数値は区別されます。$f$サイクルまたは減少が発生するまで、数値を厳密に増加させます。 

最適なアプローチでは、変換を適用する単純なループを使用します。$f$以前に表示された数値に達するまで。 すべての数値を明示的に保存するのではなく、カウンターを維持します。 各アプリケーションは末尾のゼロの数を減らすため、シーケンスは以前に確認された数値よりも大きな数値を再訪することができず、少数のステップでの終了が保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n) | O(n) | 遅すぎる |
 | 最適 | O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタを 0 に初期化し、現在の数値を設定します。$x = n$。 カウンタは、到達可能な個別の番号の数を追跡します。 
2. まで続くループを開始します。$x$0になります。 
3. カウンタを 1 つインクリメントしてカウントします。$x$到達可能なものとして。 
4. コンピューティング$x = x + 1$。 除算を繰り返して末尾のゼロをすべて削除します$x$最後の桁がゼロ以外になるまで 10 ずつ増加します。 
5.次のことを確認します$x$以前に訪問した番号に達しました (このアプローチでは、1 桁の数に減れば、残りの番号はすべて 1 桁であることがわかり、数えた後に終了できます)。 
6. 個別の数値の合計数を返します。 

なぜ機能するのか: 不変条件は、すべてのアプリケーションが$f$末尾のゼロを無視すると、前よりも厳密に大きい数値が生成されます。 末尾のゼロは、シーケンス内で同じ数値が重複して表現されるのを防ぐために削除されます。 最終的に、シーケンスは 10 未満の数値またはすでに出現した数値に達するため、数値が 2 回カウントされることはなく、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def reachable_count(n):
    seen = set()
    x = n
    while x not in seen:
        seen.add(x)
        x += 1
        while x % 10 == 0:
            x //= 10
    return len(seen)

n = int(input())
print(reachable_count(n))
```ソリューションではセットを使用します`seen`すでに訪問した番号を追跡し、重複がカウントされないようにします。 内側のループは末尾のゼロを削除し、関数を実装します。$f(x)$。 数値が以前に確認された数値まで増加または減少するため、アルゴリズムは終了します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log n) | 各ステップでは、n の最大桁数である後続のゼロが減ります。 各番号は最大 1 回アクセスされます。 |
 | スペース | O(log n) | このセットには、桁数に比例して、桁ごとに最大 1 ずつ増加する、それぞれの個別の数値が格納されます。 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    return str(reachable_count(n))

# Provided sample
assert run("1098\n") == "20", "sample 1"

# Custom cases
assert run("9\n") == "9", "single digit number"
assert run("1000\n") == "4", "trailing zeros"
assert run("999\n") == "10", "just below power of 10"
assert run("1\n") == "9", "minimum n"
assert run("123456789\n") == "9", "large n with unique digits"

## 特殊なケース

 のために`n = 1000`、`f(1000) = 1001 -> 1001`次にゼロを削除すると、`1001`それから`1002`。 アルゴリズムは正しくカウントします`1000, 1001, 1002, 1003`そして終了します。 のために`n = 999`、`f(999) = 1000 -> 1`次に進みます`2..9`、それぞれ 1 回ずつ数えます。 内側のループは続行する前にゼロを削除するため、後続のゼロまたは 10 のべき乗のすぐ下の数値を含むすべてのエッジ ケースは正しく処理されます。
