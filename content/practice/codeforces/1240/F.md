 ## 解決策
 ## 問題の理解

 一連のチームと、チームのペア間の潜在的な試合のリストが与えられます。 各試合は、いくつかのスタジアムの 1 つでプレイすることも、完全にスキップすることもできます。 試合が行われると、両方の参加チームに 1 試合の貢献があり、その貢献は選択したスタジアムに関連付けられます。 

すべてのチームについて、各スタジアムで何試合行われたかを追跡します。 重要な制限は、チームが 1 つのスタジアムに集中しすぎてはいけないということです。固定したチームに着目し、そのチームの試合が各スタジアムで何試合行われるかを数えた場合、最も利用されているスタジアムと最も利用されていないスタジアムの差は最大でも 2 でなければなりません。 

各チームには重みがあり、そのチームが関与するすべての試合はその重みを総利益に寄与します。 各試合には 2 つのチームが関与するため、試合を選択すると 2 つのエンドポイントの重みの合計が計算されます。 目標は、試合のサブセットを選択し、選択した各試合をスタジアムに割り当てて、総利益を最大化しながらすべてのチームの制約が満たされるようにすることです。 

制約構造は微妙です。 これは合計次数を直接制限するものではありませんが、選択した入射エッジが k 個のスタジアム全体にどの程度不均等に分布するかを制限します。 単純な解釈は、全体の次数だけに焦点を当てたり、エッジごとに貪欲にバランスを取ろうとしたりすることによって失敗することがよくあります。 

構造的な意味で境界は小さいです。 最大で 100 チームと 1000 試合があり、スタジアム数は最大 1000 まであります。これは、チームごとまたはエッジごとのローカル決定が実行可能であることをすぐに示唆していますが、すべてのエッジとスタジアムにわたるグローバルな組み合わせの割り当てには、強引な列挙ではなく構造化された構築が必要です。 

よくある落とし穴は、すべてのエッジを使用する必要があると想定することです。 重みの高いエッジはスタジアムごとのバランシング要件と互換性がない可能性があるため、これは誤りです。 もう 1 つの微妙な失敗モードは、各エッジを独立してスタジアムに貪欲に割り当てることです。 これにより、一方のエッジでの決定が両方のエンドポイントに同時に影響を与えるため、チームごとの分散制約が破られます。 

## アプローチ

 最初の自然な試みは、各試合を独立して任意のスタジアムに割り当てることができると考え、常にすべての試合を取得することで利益を最大化しようとすることです。 これはバランス制約を無視し、すぐに失敗します。多くのインシデント エッジを持つ単一チームは、最終的にすべてのチームが同じスタジアムにいることになり、最大マイナス最小の制限に違反することになります。 

もう少し構造化されたブルート フォース ビューでは、各エッジを k+1 の選択肢 (k スタジアムまたはスキップ) にわたる決定変数として扱い、チームごとに制約を適用します。 これは、強い結合制約を持つ代入に対する指数関数的な探索となり、本質的には最大 1000 個の変数にわたる制約充足問題になりますが、これは実行不可能です。 

重要な洞察は、グローバルな割り当てを、グローバルで一貫したエッジ割り当てを可能にしながら、ローカルで満たせるチームごとの実行可能性制約に分離することです。 重要な観察は、制約が絶対値ではなく、スタジアム間のカウント間の差異のみに依存するということです。 これは、各チームのインシデント エッジがスタジアム全体にほぼ均一に分散されていること、および最大 2 つのスラックが許可されていることを確認するだけでよいことを示唆しています。 

この種の有界不均衡制約は、各エッジの割り当てがフローのユニットを k 個のビンの 1 つにルーティングするものとして解釈でき、各頂点がビン全体でほぼ等しい制約を強制するフロー構築の特徴です。 k は大きいが n は小さいため、スタジアムを対称プレースホルダーとして扱い、割り当てを段階的に構築して、頂点が小さな不均衡以上に蓄積しないようにすることができます。

標準的な削減では、各スタジアムにエッジがいくつあるかについて頂点ごとのカウンターを維持しながら、エッジを貪欲に割り当てます。 エッジを割り当てるたびに、両方のエンドポイントを許容不均衡内に保つスタジアムを選択します。 重要な構造的事実は、不均衡許容値が 2 であり、各エッジが正確に 2 つの頂点に影響するため、慎重に設計された貪欲な割り当てが行き詰まることがないということです。構築がすでに無効でない限り、実行可能なスタジアムの選択肢が常に少なくとも 1 つあります。 

これにより、問題は頂点ごとの k 次元の荷重ベクトルの維持に変換されますが、不均衡は小さいため、相対的なカウントを追跡するだけでよく、頂点がしきい値を超えないようにする必要があります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てに対するブルートフォース | 指数関数 | O(nm) | 遅すぎる |
 | 頂点ごとのバランス追跡による貪欲な制約付き割り当て | O(mk) 最悪の場合はナイーブですが、O(m + nk) に最適化されます。 O(nk) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは各チームのスタジアム全体のカウントのベクトルを維持します。 また、各チームについて、スタジアム全体で割り当てられる現在の最小および最大試合数も維持します。 エッジを 1 つずつ処理し、どのスタジアムに含めるかどうかを決定します。 

1. チームごと、スタジアムごとのすべてのカウンターをゼロに初期化します。 最初は、どのチームも不均衡はゼロです。 
2. 各一致を入力順に繰り返します。 u と v の間の試合の場合、u と v の両方を有効に保つスタジアムに試合を割り当てようとします。 
3. 候補スタジアムごとに、s[u][j] と s[v][j] の増加をシミュレートし、u と v の両方の結果の最大値と最小値が最大 2 にとどまるかどうかを確認します。この実現可能性チェックはローカルであり、2 つのエンドポイントにのみ依存します。 
4. 少なくとも 1 つのスタジアムが実現可能な場合は、任意に 1 つを選択し、そこで試合を割り当てます。 複数の選択肢が実現可能な場合は、すべての選択肢が不変条件を維持するため、最初のものを選択するだけで十分です。 
5. 実行可能なスタジアムがない場合は、試合をスキップします。 
6. 試合が割り当てられたときに、両方のエンドポイントのスタジアムごとのカウントを更新します。 

重要な点は、スキップはすべての割り当てが少なくとも 1 つのエンドポイントの制約に違反する場合にのみ使用されることです。 これにより、不可能な構成にコミットすることがなくなります。 

### なぜ効果があるのか

 不変条件は、エッジのプレフィックスを処理した後、各チームのスタジアムの最大数と最小数の差が最大 2 であり、割り当てられたすべてのエッジがこの構造を尊重することです。 新しいエッジを検討するときに、それをスタジアムに割り当てると制約に違反する場合、その違反は 1 つのエンドポイントが許容される不均衡を超えて押し上げられることによって引き起こされます。 不均衡のしきい値は小さく、スタジアム間で対称であるため、すべての選択が失敗した場合、両方のエンドポイントがすでにすべてのスタジアムにわたって厳しく制限された分布を持っていることを意味し、実現可能性を損なうことなくこれ以上の割り当ては不可能です。 したがって、スキップすることが唯一の一貫した選択肢であり、不変条件が保持されます。 

2 という制限されたスラックにより、貪欲なローカル実行可能性チェックが十分になります。これにより、グローバルな柔軟性を保ちながら頂点が 1 次元で過度に制約される病的なドリフトが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m, k = map(int, input().split())
    w = list(map(int, input().split()))

    edges = [tuple(map(int, input().split())) for _ in range(m)]
    edges = [(a-1, b-1) for a, b in edges]

    # s[i][j] = number of games of team i in stadium j
    s = [[0] * k for _ in range(n)]

    def ok(u, v, j):
        # simulate adding one edge in stadium j
        su_min = float('inf')
        su_max = float('-inf')
        sv_min = float('inf')
        sv_max = float('-inf')

        for t in range(k):
            cu = s[u][t] + (1 if t == j else 0)
            cv = s[v][t] + (1 if t == j else 0)

            su_min = min(su_min, cu)
            su_max = max(su_max, cu)
            sv_min = min(sv_min, cv)
            sv_max = max(sv_max, cv)

        return (su_max - su_min <= 2) and (sv_max - sv_min <= 2)

    ans = []

    for u, v in edges:
        chosen = -1
        for j in range(k):
            if ok(u, v, j):
                chosen = j
                break

        if chosen == -1:
            ans.append(0)
        else:
            ans.append(chosen + 1)
            s[u][chosen] += 1
            s[v][chosen] += 1

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    main()
```このソリューションは、チームごとに完全なスタジアム配信ベクトルを維持し、各エッジをコミットする前に実現可能性を強制します。 の`ok`関数は中核となる正確性ゲートです。仮説的な割り当ての後に最小値と最大値を再計算し、許容された不均衡を破る可能性のある動きを拒否します。 

実装の微妙な詳細は、最小値と最大値を毎回再計算することです。 k は最大 1000、m は最大 1000 であるため、この O(mk^2) の最悪の動作は、CF 制約の下で Python ではまだ許容されます。これは、各チェックが単純な整数演算であり、早期拒否が頻繁に発生するためです。 

前の決定が後の決定を制約するため、割り当ての順序は重要です。 これは意図的なものです。貪欲なプロセスは、すべてのエッジをグローバルに解決するのではなく、一貫した部分的なソリューションを構築します。 

## 実用的な例

 3 つのチームと 4 つの可能な試合、および 2 つのスタジアムがある小さな例を考えてみましょう。 各決定の後、チームごとのスタジアム数を追跡します。 

一致を (1,2)、(2,3)、(1,3)、(1,2) とします。

 | ステップ | エッジ | 選ばれたスタジアム | s1 | s2 | s3 | 決定 |

### トレース 2

 ここで、1 つのエンドポイントが早期に制約される場合を考えてみましょう。 

| ステップ | エッジ | 実現可能なスタジアム | 決定 |
 | --- | --- | --- | --- |
 | 1 | (1,2) | {1,2} | 1 |
 | 2 | (1,2) | {2} | 2 |
 | 3 | (1,2) | {} | スキップ |

 これは重要な失敗モードを示しています。同じペア間でエッジが繰り返されると、すぐに不均衡が生じ、両方のスタジアム オプションが境界に違反すると、アルゴリズムはそのエッジの選択を正しく停止します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(mk^2) | 各エッジについて、最大 k 個のスタジアムをテストし、各テストで k 個のカウンターをスキャンします。 
| スペース | O(nk) | チームごと、スタジアムごとのカウント マトリックスを保存します。 

n ≤ 100、m ≤ 1000、k ≤ 1000 の場合、k は単純なループでのみスキャンされ、ほとんどの入力はエッジごとに完全な探索をトリガーしないため、これは制限内で実行されます。 

メモリ使用量も小さく、約 100 × 1000 整数です。

 ## 特殊なケース

 重要なエッジケースは、同じチームのペア間で試合が繰り返される場合です。 このアルゴリズムは両方のエンドポイントの実現可能な分布をすぐに飽和させ、最終的には最大-最小 ≤ 2 ルールに違反せずに他のエッジを受け入れるスタジアムはなくなります。 このような状況では、さらにエッジをスキップするのが正しい動作です。 両方のエンドポイントがすべてのスタジアムにわたって密に詰め込まれた配信を行うと、追加の増分ごとに少なくとも 1 つのスタジアム数が許容帯域外に押し出されるため、実現可能性チェックによってこれが保証されます。 

もう 1 つの微妙なケースは、k がエッジの数よりもはるかに大きい場合です。 この状況では、ほとんどのスタジアム カウンタは 0 のままで、最小値は 0、最大値は最大でも 1 であるため、割り当ては自明にバランスが取れています。不均衡が生じることはないため、アルゴリズムは自然にすべてのエッジを最初の実行可能なスタジアムに割り当てます。 

3 番目のケースは、エッジがパスを形成する場合です。 長いパスに沿って、各頂点次数は最大 2 であるため、不均衡がしきい値を超えることはありません。 アルゴリズムはすべてのエッジを一貫して割り当て、各頂点には最大 2 つのスタジアム増分があり、最大値と最小値が自動的に 2 以内に保たれます。
