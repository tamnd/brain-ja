 ## 解決策
 ## 問題の理解

 のサイズの長方形のボードが与えられます$n \times m$。 サイズの長方形ブロックもあります$a \times b$。 課題は、そのようなブロックがグリッドに整列していて重なり合わず、そして重要なことに回転できない場合に、ボード上に何個配置できるかを決定することです。 

解釈は簡単です。ボードを左上隅からタイル状に並べ、各ブロックを幅の固定方向に配置します。$a$そして高さ$b$。 問題は、垂直方向に沿って完全なブロックがいくつ適合するか、水平方向に適合する完全なブロックがいくつあるか、そしてこれら 2 つの数を組み合わせるということになります。 

入力は複数のテスト ケースで構成され、それぞれがボードの寸法とブロックの寸法を表す 4 つの整数を与えます。 テスト ケースごとに、適合するブロックの最大数を表す単一の整数を出力します。 

制約は十分に小さいため、各テスト ケースは一定時間内に処理する必要があります。 まであったとしても$10^5$テスト ケースでは、ケースごとに数回以上の算術演算を実行するソリューションは遅すぎます。 これにより、グリッド上のシミュレーションやブロックを 1 つずつ配置する試みが直ちに排除されます。 

この種の問題で時々犯す微妙な間違いは、回転が許可されていると想定していることです。 ローテーションが許可されている場合は、両方を考慮する必要があります。$(a, b)$そして$(b, a)$配置を決定し、より良い結果をもたらします。 もう 1 つの間違いは、部分的なオーバーラップや貪欲なパッキング戦略を考慮しようとすることです。グリッド構造によりソリューションが純粋に算術的に行われるため、ここでは不要です。 

強調する価値のあるエッジケースは、次のような場合です。$a > n$または$b > m$。 この場合、どのブロックもまったく適合せず、答えはゼロになるはずです。 たとえば、次の場合$n = 3, m = 3, a = 5, b = 1$の場合、垂直方向の配置は不可能なので、出力は次のようにする必要があります。$0$水平方向の空間が存在するにもかかわらず。 

## アプローチ

 この問題を考える最も直接的な方法は、ブロックの配置をシミュレーションすることです。 グリッド内のすべての可能な左上の位置を反復処理して、ブロックが適合するかどうかを確認できます。 これには、以下のチェックが含まれます。$n \cdot m$テスト ケースごとに位置を指定し、各チェックには定数時間の検証が含まれます。 これは次のことにつながります$O(nm)$テスト ケースごとに、これはすでに不要ですが、概念的にはまだ管理可能です。 

ただし、このシミュレーションは問題の構造を無視しています。 ブロックがグリッドに整列した固定長方形であることがわかると、配置が行と列に沿って独立していることがわかります。 垂直方向に沿ってのみフィットできます$\lfloor n / a \rfloor$完全なブロックが積み上げられています。 水平方向に沿ってのみフィットできます$\lfloor m / b \rfloor$ブロックを並べて。 一方向のすべての有効な配置は、別の方向の配置と独立して結合されるため、合計数はそれらの積となります。 

これにより、幾何学的パッキング タスクの問題が 2 つの整数の除算と乗算に削減されます。 構造上の重要な洞察は、回転や部分的な配置が許可されていないため、グリッドが独立したストリップに分解されるということです。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースは独立しているため、状態を保存せずに個別に処理できます。 
2. テスト ケースごとに 4 つの整数を読み取ります。$n, m, a, b$、ボード寸法とブロック寸法を表します。 目標は、どれだけ満たされているかを計算することです$a \times b$長方形が収まる$n \times m$矩形。 
3. 整数除算を使用して、垂直方向に収まるブロックの数を計算します。$n // a$。 これは、行全体の高さを表します。$a$ボードの高さを超えずに積み重ねることができます。 
4. 整数除算を使用して、水平方向に適合するブロックの数を計算します。$m // b$。 これは、幅全体の列数を表します。$b$全面に配置できます。 
5. これら 2 つの値を乗算して、ブロックの総数を求めます。 これが機能するのは、すべての垂直スロットがすべての水平スロットと独立して結合して、有効な配置領域を形成できるためです。 
6. テストケースの結果を出力します。 

### なぜ効果があるのか

 重要な特性は、次元の分離可能性です。 すべてのブロックは連続した領域を占有する必要があるため、$a \times b$領域であり回転できません。すべての有効な配置は、次の中から垂直インデックスを選択することに一意に対応します。$\lfloor n / a \rfloor$可能性と水平インデックス$\lfloor m / b \rfloor$可能性。 これらの選択肢の間には相互作用はなく、残った領域が部分的に別のブロックに寄与することはありません。 これにより、有効な配置のデカルト積構造が作成され、2 つの整数商の乗算の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, a, b = map(int, input().split())
    print((n // a) * (m // b))

t = int(input())
for _ in range(t):
    solve()
```このソリューションは各テスト ケースを読み取り、整数の除算を直接適用して、各次元に適合する完全なセグメントの数を計算します。 関係する値は Python 整数内に十分に収まるほど小さいため、乗算ステップは安全です。 

よくある落とし穴は、整数の除算を忘れて浮動小数点の除算を使用することです。これにより、精度の問題が発生します。 もう 1 つの間違いは、切り捨てではなく切り上げようとすることです。 完全なブロックのみがカウントされるため、フロア分割は不可欠です。 

乗算は可換であるため、ここでは演算の順序は重要ではありませんが、構造を 2 つの別々の除算として維持することで、明確さが向上し、次元が混在するリスクが軽減されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        n, m, a, b = map(int, input().split())
        return (n // a) * (m // b)

    t = int(input())
    out = []
    for _ in range(t):
        out.append(str(solve()))
    return "\n".join(out)

 ## 特殊なケース

 いつ$a > n$の場合、垂直商はすぐにゼロになり、アルゴリズムは幅に関係なくゼロを出力します。 たとえば、入力`n=4, m=10, a=5, b=2`生成する`(4//5)*(10//2) = 0*5 = 0`、ブロックを配置できないという事実と一致します。 

いつ$b > m$、同じ対称性が水平方向にも当てはまります。 垂直方向のスタッキングが可能であっても、水平方向のフィットが不足しているため、結果はゼロになります。 

両方の次元が均等に分割される場合、次のようになります。`n=8, m=6, a=2, b=3`、計算は次のようになります`(8//2)*(6//3) = 4*2 = 8`これは、残りのスペースがない完全なグリッド パーティションに正確に対応します。
