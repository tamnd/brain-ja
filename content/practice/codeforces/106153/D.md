 ## 問題の理解

 このタスクは、指定された分数が 10 進数で書かれたときに終端小数を生成するか、無限反復小数を生成するかを決定することを中心に展開します。各テスト ケースでは整数の分母が与えられ、暗黙的に分数を考慮します。$\frac{1}{n}$。 目標は、小数拡張が最終的に停止するか、繰り返しサイクルで永遠に継続するかを判断することです。 

10 進数表現は、分子で完全に減算された後、分母に 2 と 5 以外の素因数が含まれなくなった時点で終了します。これは、基数 10 の構造に由来しています。$10 = 2 \cdot 5$。 2 または 5 の因数はすべて 10 の累乗に吸収され、小数部が整数になるまで 10 進展開で桁をシフトできます。 

入力サイズにより、多くのテスト ケースと大きな値が許容​​されます。$n$これにより、10 進展開またはモジュラー Long 除算のシミュレーションが即座に除外されます。 10 による除算を繰り返したり、数字を構築したりしても、大きな数値に対して直接実行すると、特に次のような場合に非常に遅くなります。$n$は、その大きさよりも因数分解構造が重要になるほど十分に大きい場合があります。 

微妙なエッジケースが現れるのは、$n = 1$。 この場合、分数はすでに整数であるため、明らかに終了しています。 もう 1 つの例外的なケースは次のような場合です。$n$これらはサイズに関係なく常に終了するため、2 または 5 の累乗になります。 反対に、たとえば 3 のような 1 つの素因数が追加されると、完全に終了が中断されます。$n = 6$生成する$0.1666...$、小さくてシンプルですが、無限に繰り返します。 

素朴なアプローチでは、10 の大きなべき乗の割り切り可能性をチェックしたり、ある限界までテストしてみたりするかもしれません。$10^k \equiv 0 \pmod{n}$。 これは、必要な指数が非常に大きくなる可能性があり、最初に無関係な要素を削除しないとプロセスが実行不可能になるため、失敗します。 

## アプローチ

 強引なアイデアは、次の小数展開を直接シミュレートすることです。$\frac{1}{n}$長い除算を使用します。 各ステップで、余りに 10 を掛けて桁を取り、余りが 0 になるかどうかを確認します。 ゼロになると、10 進数は終了します。 

このアプローチは正しいです。なぜなら、long 除算は 10 進表現を正確に構築するからです。 ただし、最悪のケースは分数が繰り返されるときに発生します。この場合、剰余は値を法として循環します。$n$。 せいぜいあるので$n$可能な残り、このシミュレーションにはかかる可能性があります$O(n)$テストケースごとのステップ。 大量の入力と複数のクエリの場合、これでは遅すぎます。 

重要な点は、プロセスをシミュレートする必要がまったくないということです。 小数が終了する唯一の理由は、分母から 2 と 5 の因数をすべて取り消しても何も残らないからです。 これは、10 の累乗では因数 2 と 5 のみが導入されるため、他の素因数は 10 を乗算しても削除できないためです。 

したがって、割り算をシミュレートする代わりに、次から 2 と 5 のすべての因数を繰り返し削除します。$n$。 残った値が 1 の場合、10 進数は終了します。 それ以外の場合は無限です。

 ## アルゴリズムのチュートリアル

 数値が 2 と 5 で割り切れる間は、数値を繰り返し割ります。 そのような要因が存在しなくなったら、結果が 1 であるかどうかを確認します。 

1. 整数を読み取る$n$現在のテストケースの場合。 これは、分析している分数の分母を表します。 
2. その間$n$は 2 で割り切れるので、2 で割ります。各割り算では、因数分解から 2 の累乗が 1 つ取り除かれます。 2 のべき乗はまさに 10 進数に吸収できるものであるため、このステップは安全です。 
3. その間$n$これにより、上記と同じ理由で、10 進数のスケーリングと互換性のあるすべての要素が削除されます。 
4. これらの要因を完全に取り除いた後、$n$そうでない場合は、他の素因数が残ります。つまり、10 のべき乗を乗算しても消去できません。 
5. 次の場合は「NO」を出力します。$n = 1$それ以外の場合は「YES」を出力します。 

### なぜ効果があるのか

 終了小数点がある場合は、何らかの累乗が存在することを意味します$10^k$そのような$\frac{1}{n} \cdot 10^k$は整数になります。 以来$10^k = 2^k \cdot 5^k$、これは次のすべての素因数を意味します。$n$2 と 5 に含まれている必要があります。 から 2 と 5 の要素をすべて削除します。$n$この条件が成立する場合には 1 がそのまま残されるため、このチェックは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    while n % 2 == 0:
        n //= 2
    while n % 5 == 0:
        n //= 5
    if n == 1:
        print("NO")
    else:
        print("YES")

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```実装の中核は、繰り返される因子除去ループです。 乗算は可換であり、両方のループは割り切れなくなるまで独立して数値を減らすため、2 と 5 を削除する順序は重要ではありません。 

最終チェックでは、2 と 5 だけで構成されたクリーンな分母と、まだ他の素数が含まれている分母を区別します。 

微妙な点の 1 つは、この問題の出力規則が通常のステートメントと逆になっていることです。正規化後、1 より大きい残りの値は無限小数に対応し、ここでは「YES」とラベル付けされています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    out = []
    t = int(input())
    for _ in range(t):
        n = int(input())
        while n % 2 == 0:
            n //= 2
        while n % 5 == 0:
            n //= 5
        out.append("NO" if n == 1 else "YES")
    return "\n".join(out) + "\n"

# provided samples (illustrative)
assert run("2\n20\n6\n") == "NO\nYES\n"

# all ones
assert run("3\n1\n2\n5\n") == "NO\nNO\nNO\n"

# pure powers of 2 and 5
assert run("2\n32\n125\n") == "NO\nNO\n"

# mixed with other primes
assert run("3\n3\n7\n14\n") == "YES\nYES\nYES\n"

## 特殊なケース

 のために$n = 1$、2 または 5 で割り切れないため、ループは何も行いません。最終値は 1 のままであるため、アルゴリズムは正しく「NO」を出力します。 

のために$n = 8$、2 による除算を繰り返すと、4、2、そして最後に 1 になります。最終的な状態はクリーンで、終了が確認されます。 

のために$n = 45$、5 を 2 回削除して 9 を取得しますが、9 をこれ以上減らすことはできません。 9 には因数 3 が含まれているため、アルゴリズムはそれを無限であると正しく識別します。 

それぞれの場合において、重要な不変条件が保持されます。つまり、2 と 5 のすべての因数を取り除いた後、残りの数値は、分母を 10 の累乗として書くことの障害を正確に表します。
