 ## 解決策
 ## 問題の理解

 グラフがあります`n`子供たち。 のみ`m`ペアは友達としてマークされ、各友情エッジには初期重みが設定されます。`f`。 

先生は正確に演技します`k`遠足。 各エクスカーション中に、順序付けられていない子のペアがすべての可能なペアから一様にランダムに選択されます。 すべての選択は独立しているため、同じペアが何度も選択される可能性があります。 

選択したペアが友情エッジの場合、次の 2 つのことが起こります。 

まず、そのエッジの現在の友情値が、この遠足の答えに貢献します。 

次に、遠足が終了すると、そのエッジの友情値が 1 増加し、今後の遠足に影響します。 

選択したペアが友情エッジではない場合、貢献度はゼロとなり、変化することはありません。 

すべての全体に対する予想される合計貢献度を計算する必要があります。`k`遠足。 答えは有理数です。 それをモジュロで出力するように求められます`10^9+7`これは、分子に分母の逆剰余を掛けることを意味します。 

グラフ自体はまばらです。 すべてのテスト ケースにわたって、友情エッジの合計数は最大で`10^5`、エクスカーションの合計数は最大でも`2·10^5`。 これにより、友情値のすべての可能な状態に関するシミュレーションが即座に除外されます。 考えられる履歴の数は、次のように指数関数的に増加します。`k`。 

重要な課題は、友情の価値が時間の経過とともに進化することです。 友情エッジは、すでに選択されている場合により価値が高くなります。 一見すると、これによりエクスカーション間の依存関係が作成されますが、期待により、直接的な確率的状態シミュレーションが示唆するよりもはるかに積極的にプロセスを分離することができます。 

いくつかの特殊なケースは注目に値します。 

友情エッジのないグラフを考えてみましょう。```
n = 100
m = 0
k = 24
```選択されたすべてのペアの寄与はゼロです。 答えはまさにゼロです。 友情エッジの数で割る式、または少なくとも 1 つの友情を仮定する式は、このケースを処理する必要があります。 

最小の非自明なグラフを考えてみましょう。```
n = 2
m = 1
k = 3
f = 5
```可能なペアは 1 つだけなので、毎回選択されます。 貢献内容は次のとおりです。```
5 + 6 + 7 = 18
```すべての旅行を独立して扱い、常に元の友情値を使用するソリューションでは、誤った結果が生成されます。`15`。 

もう 1 つの微妙なケースは、友情の値が異なる場合です。```
n = 3
m = 2
edges:
(1,2) = 100
(2,3) = 1
```将来の選択によって生成される期待される増加は、最初の重みではなく、友情エッジが選択される頻度にのみ依存します。 これら 2 つの効果を誤って混合すると、多くの場合、二重カウントが発生します。 

## アプローチ

 ブルートフォースアプローチでは、確率プロセス全体がモデル化されます。 

各ツアーでは、次のいずれかを選択します。`C(n,2)`ペア。 友情エッジの場合、その値は増加します。 プロセスの状態は、現在の友情値のベクトルです。 1 つのステップの後では、多くの可能な状態があり、2 つのステップの後ではさらに多くの状態があり、その後`k`ステップを踏むと状態の数が膨大になります。 

各友情エッジが選択された回数だけを追跡したとしても、状態空間のサイズはおおよそ、最大でも次の整数構成の数になります。`k`の間で`m`エッジ、これは完全に不可能です。 

強引なアイデアはプロセスに正確に従うため正しいですが、問題の限界に達するずっと前に不可能になります。 

解決策を解く観察は、期待の直線性です。 

州全体を追跡するのではなく、一度に 1 つのエクスカーションに焦点を当てます。 

させて```
T = C(n,2)
```可能なペアの総数になります。 

エッジが友情値から始まると仮定します。`f`。 

現在遠足中の場合`i`(0 からインデックス付き)、そのエッジの値は次と等しい```
f + (# times this edge was selected during previous i excursions)
```以前の選択の予想数は簡単に計算できます。 

各エクスカーションは確率でこのエッジを選択します```
1 / T
```独立して。 

最初のものの中には`i`エクスカーションの場合、このエッジが選択されると予想される回数は```
i / T
```したがって、逸脱時のこのエッジの期待値は`i`は```
f + i/T
```エクスカーション時にエッジが選択される確率`i`またまたです```
1/T.
```したがって、エクスカーション中のこの特定のエッジの予想される寄与は`i`は```
(1/T) · (f + i/T).
```すべての友情エッジを合計すると、```
(Σf)/T + m·i/T².
```これをすべてのツアーで合計します`i = 0 ... k-1`。 

最初の項は次のようになります```
k·Σf / T.
```第二期は、```
m/T² · Σi
= m/T² · k(k-1)/2.
```これはすでに最終的な式です。 

確率プロセス全体は、次の 2 つの集計値に分解されます。```
S = Σf
```そして```
m.
```グラフに関するその他の情報は重要ではありません。

 | 最適 | テスト ケースあたり O(m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`m`、 そして`k`。 
2. コンピューティング```
T = n(n-1)/2
```これは、順序付けられていない子のペアの合計数です。 
3.すべての友情エッジを読んで蓄積します```
S = Σf.
```個々のエンドポイントが最終的な式に現れることはなく、最初の友情値の合計のみが重要になります。 
4. 初期の友情値から期待される貢献度を計算します。```
k · S / T.
```すべてのエクスカーションでは、確率で特定の友情エッジが選択されます`1/T`。 
5. 友情値の増加によって生成される期待される貢献を計算します。```
m · k(k-1)/2 / T².
```遠足用`i`、すべての友情エッジには追加の価値が期待されています`i/T`、すべてのエッジとすべての偏位を合計すると、この項が生成されます。 
6. 2 つの項を剰余として加算します。`10^9+7`。 
7. モジュラー逆関数を使用する`T`そして`T²`部門を表すために。 

### なぜ効果があるのか

 友情エッジの現在の値は、初期値に以前に選択された回数を加えたものに等しくなります。 

以前の選択の数は、独立した指標変数の合計です。 期待値の線形性により、その後の期待値`i`以前の小旅行はまさに`i/T`。 

エッジの値と、エクスカーションでエッジが選択されるイベントとの間の独立性を期待する必要はありません。`i`、直接計算するため```
E[ value × indicator ]
```として```
(1/T) × E[value].
```現在のエクスカーションのインジケーターは、現在の値を決定する以前のすべてのエクスカーションとは独立しています。 

すべての友情エッジとすべての旅行に対するこれらの期待を合計すると、期待される合計貢献度が正確に得られます。 すべての変換では期待値の等価性が維持されるため、最終的な式は正しいものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())

    for _ in range(t):
        n, m, k = map(int, input().split())

        s = 0
        for _ in range(m):
            a, b, f = map(int, input().split())
            s = (s + f) % MOD

        T = n * (n - 1) // 2

        invT = pow(T % MOD, MOD - 2, MOD)
        invT2 = invT * invT % MOD

        part1 = (k % MOD) * s % MOD * invT % MOD

        pairs_sum = (k % MOD) * ((k - 1) % MOD) % MOD
        pairs_sum = pairs_sum * pow(2, MOD - 2, MOD) % MOD

        part2 = (m % MOD) * pairs_sum % MOD * invT2 % MOD

        ans = (part1 + part2) % MOD
        print(ans)

solve()
```実装は派生した式に直接に従います。 

変数`s`すべての初期友情値の合計を保存します。 最終的な式には合計のみが表示されるため、個々のエッジを保存する必要はありません。`T`は、可能な順序なしのペアの数です。 素数を法とする除算は、逆モジュラーを使用して実装されます。 以来```
T²
```第二項に出てくるので計算してみます`invT`一度四角形にします。 

数量```
k(k-1)/2
```非常に大きくなる可能性があるため、すべての乗算はモジュロで実行されます。`MOD`。 

よくある間違いは、次を使用して 2 番目の項を計算することです。`k(k+1)/2`。 正しい合計は```
0 + 1 + ... + (k-1),
```等しい`k(k-1)/2`。 

もう 1 つのよくある間違いは、友情のエッジのみが価値を獲得できることを忘れることです。 第 2 項に乗算する係数は次のとおりです。`m`ペアの総数ではありません。

    t = int(input())
    out = []

        s = 0

            a, b, f = map(int, input().split())

        part2 = (m % MOD) * pairs_sum % MOD * invT2 % MOD

    return "\n".join(out)

## 特殊なケース

 入力:```

```我々は持っています：```
S = 0
m = 0
```式は次のようになります```
10·0/T + 0 = 0.
```どのペアも何も貢献しないため、答えは正確にゼロです。

```ここ`T = 1`。

= 12 + 6
= 18.
```実際の値のシーケンスは次のとおりです。```
3, 4, 5, 6
```誰の合計も`18`。
