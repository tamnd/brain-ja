 ## 解決策
 ## 問題の理解

 文字列が与えられています`s`区切り文字なしで連続して書かれた正の整数のシーケンスを表します。 各数値にはゼロ以外の数字のみが含まれます。 別に、「適切な」整数が与えられます。`x`、これも完全にゼロ以外の数字で構成されています。 タスクは、元の配列内で隣接する 2 つの整数を見つけて、その合計が等しくなるようにすることです。`x`そして文字列内の位置を報告します`s`。 位置は 1 から始まり、1 を含みます。 

入力サイズ`s`最大 500,000 文字にすることができ、`x`それ自体は最大 200,000 桁まで含めることができます。 これは、候補ペアの数が長さの 2 次になる可能性があるため、すべての数値ペアを明示的に生成することを伴うアプローチを即座に除外します。`s`。 それはまた、変換に頼ることができないことを意味します`x`ほとんどのプログラミング言語の標準整数型に変換されます。 治療しなければなりません`x`文字列として取得し、文字列ベースまたは数字単位の算術演算を実行します。 

明らかではない特殊なケースには、一方の数値が非常に短く、もう一方の数値が非常に長い場合が含まれます。 たとえば、`s = "12"`そして`x = 3`、唯一の有効な分割は`1 + 2`、 ない`12 + 0`。 もう 1 つの微妙なケースは、分割が異なる長さに整列する可能性がある場合です。`s = "1256133"`そして`x = 17`。 ここ、`12 + 5 = 17`しかし、等しい長さの分割のみを試みる単純なアプローチでは、それを見逃してしまう可能性があります。 

## アプローチ

 ブルートフォースアプローチは、考えられるすべての分割を反復します。`s`空ではない連続する 2 つの部分文字列に変換し、それらを整数に変換し、それらの合計が等しいかどうかを確認します。`x`。 すべての有効な分割が検査されるため、これは原理的には正しく機能します。 ただし、分割数は長さに比例します。`s`、潜在的に巨大な整数への各変換にはコストがかかります。 最悪の場合、O(n * m) 時間がかかります。ここで、n は長さです。`s`m は長さです`x`。 n は最大 500,000、x は最大 200,000 桁なので、これでは遅すぎます。 

最適なソリューションを導き出す重要な観察は次のとおりです。`x`すべての配列要素は「適切な」数値であり、ゼロが含まれていないことを意味します。 したがって、合計を文字列として考えると、キャリーの伝播は単純かつ決定的になります。 分割を試してみることができます`s`最初の部分文字列の最後の桁と 2 番目の部分文字列の最初の桁が、`x`追加中。 基本的に、境界付近でいくつかの候補分割を試みるだけで済みます。`x`。 具体的には、最初の数値の長さは次のとおりです。`len(x)`または`len(x) - 1`(桁上げを使用してより小さい数値を追加しても、`x`)、2 番目の数値は残りの桁を取得します。 

最適なアプローチでは、最初の数値の長さの候補を 2 つだけ反復し、文字列ベースの加算を実行します。 これにより、各候補の演算数が O(|x|) に減り、全体として O(|x|) の解が得られますが、これは制約を考慮すると許容範囲内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | O(n + m) | 遅すぎる |
 | 最適 | O(m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.治療する`x`文字列として。 長さを決定する`L`。 任意の最初の数字`a_i`どちらの長さでも構いません`L`または`L-1`追加でキャリーがあるので。 これらを長さの候補とします。 
2. 候補の長さごとに`len1`、最初を取る`len1`の桁`s`最初の数字として`a_i`。 残りの数字は 2 番目の数字を形成します`a_{i+1}`。 
3. 文字列ベースの加算を実行します。`a_i`そして`a_{i+1}`最下位から 1 桁ずつ。 キャリーを追跡します。 結果を比較してください`x`。 
4. 加算が一致する場合`x`、両方の部分文字列の 1 から始まる位置を出力します。`s`。 有効な分割が見つかったらすぐに停止します。 
5. 一致する分割がない場合 (問題によって解決が保証されているため、発生するはずはありません)、次の候補長に進みます。 

なぜ機能するのか: それ以来`x`は適切な数値であり、2 つの適切な数値の合計により一意の一連の数字が生成され、最初の数値の長さをテストします。`len(x)`または`len(x)-1`すべての有効な候補者が確実にカバーされるようにします。 不変条件は、有効な分割が生成されることです。`x`これら 2 つの長さのいずれかの最初の数値がなければなりません。そうでない場合、合計は次の値を超えるか下回ります。`x`桁ごとに測定した場合。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def add_strings(a, b):
    res = []
    carry = 0
    i, j = len(a) - 1, len(b) - 1
    while i >= 0 or j >= 0 or carry:
        x = int(a[i]) if i >= 0 else 0
        y = int(b[j]) if j >= 0 else 0
        total = x + y + carry
        res.append(str(total % 10))
        carry = total // 10
        i -= 1
        j -= 1
    return ''.join(reversed(res))

s = input().strip()
x = input().strip()
n, m = len(s), len(x)

for len1 in [m, m - 1]:
    if len1 <= 0 or len1 >= n:
        continue
    a1 = s[:len1]
    a2 = s[len1:]
    if add_strings(a1, a2) == x:
        print(1, len1)
        print(len1 + 1, n)
        break
```の`add_strings`関数は、数値全体を整数に変換せずに桁ごとの加算を実行し、オーバーフローを防ぎます。 ループオーバー`len1`長さのみをチェックします`len(x)`そして`len(x) - 1`、キャリーの考慮事項によって正当化されるように。 1 ベースのインデックスは、Python の 0 ベースのスライスを考慮しています。
