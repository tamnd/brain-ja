 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、`n`による`m`各セルがフリーまたはロックされているグリッド。 最初はすべてのセルが空いています。 セルの状態をフリーからロック、またはその逆に反転できます。反転するたびに、グリッド内の「階段」の数を数える必要があります。 階段は、任意のフリー セルから開始して、右と下、または下と右の移動を厳密に交互に繰り返すフリー セルのパスです。 1 つの空きセルは階段としてカウントされます。 2 つの階段は、他の階段に含まれていないセルが少なくとも 1 つ含まれている場合、異なるものとみなされます。 

入力により得られるのは、`n`、`m`、 そして`q`- グリッドの寸法とクエリの数。 各クエリは単一セルの状態を反転します。 出力は、クエリごとに 1 つの整数のシーケンスで、そのクエリの後の階段の合計数を表します。 

この制約は、ブルートフォース手法が実行不可能であることを示唆しています。 と`n, m`最大 1000、セルの総数は 1,000,000 に達することがあります。 各クエリでは、潜在的にすべてのフリー セルで階段を計算する必要があります。 クエリごとに考えられるすべての階段をトレースする単純なアプローチでは、クエリごとに O(nm * min(n,m)) の操作が必要になる可能性があり、最大入力サイズでは O(10^10) となり、制限時間を大幅に超えます。 

単一のセルが繰り返し反転されると、明らかではないエッジ ケースが発生します。 たとえば、2x2 グリッドでは、左上のセルを複数回反転すると、そのセルが長さの異なる複数の階段に参加するため、階段の数が大きい値と小さい値の間で交互に表示されます。 どのソリューションでも、階段を最初から再計算するのではなく、段階的に正しく更新する必要があります。 

もう 1 つの特殊なケースは、完全にロックされた行または列です。 フリー セルの連続性を前提とした単純なアルゴリズムでは、ロックされたセルの境界で終わる階段を二重にカウントしたり、見逃したりする可能性があります。 たとえば、行全体がロックされている場合、その行から始まる階段は存在しないため、アルゴリズムはこれを直ちに考慮する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、各フリー セルから始まるすべての可能な階段が考慮されます。 (i, j) のセルの場合、ロックされたセルまたは端に到達するまで、右に移動してから下に、または下に移動してから右に繰り返し移動しようとします。 これは正しいですが、最悪の場合、各クエリではすべてのセルから min(n,m) までの長さのすべてのパスを調べる必要があり、クエリあたり O(n * m * min(n,m)) になります。 最大 10^4 のクエリでは、これでは遅すぎます。 

効率的な解決策を明らかにする重要な観察は、特定のセルを含む階段の数が、そのセルの右と下にある空きセルの「ランレングス」にのみ依存するということです。 配列を事前計算すると`right[i][j]`そして`down[i][j]`(i,j) から開始して右と下に連続する空きセルの最大数を保存すると、階段の合計はこれらの階段の合計として表すことができます。 

具体的に定義すると、`dp[i][j]`セル (i,j) から始まる右下方向の階段の数として、漸化式を使用できます。`dp[i][j] = 1 + dp[i+1][j+1]`右と下の両方のセルが空いている場合。 対称的に、右下がりの階段については次のように定義します。`dq[i][j] = 1 + dq[i+1][j+1]`。 各細胞が貢献します`dp[i][j] + dq[i][j] - 1`階段 (単一セルの階段の二重カウントを避けるために 1 を減算します)。 

この観察の利点は、セルを反転すると、セルを通過する階段にのみ影響することです。 したがって、更新できます`dp`そして`dq`ローカルで、対角線に沿って移動し、影響を受けるセルのみを再計算します。 これにより、クエリあたりの時間が O(n_m_min(n,m)) から O(n+m) に短縮されますが、制約を考慮すると許容範囲内です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q * n * m * min(n,m)) | O(n*m) | 遅すぎる |
 | 最適 | O(q * (n + m)) | O(n*m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.行列を初期化する`grid`サイズの`n x m`すべてのセルが解放されています。 初期化もする`dp`そして`dq`同じサイズの行列。各セルから始まる右下と右下の階段を表します。 単一セルは階段状であるため、最初は各セルが 1 を割り当てます。 
2. 初期値を事前計算します。`dp`そして`dq`ボトムアップ動的プログラミングを使用して値を決定します。 行は下から上に、列は右から左に移動します。 のために`dp[i][j]`、両方の場合`i+1`そして`j+1`境界内にあり、次の対角セルが空いている場合、設定します`dp[i][j] = 1 + dp[i+1][j+1]`。 対称計算を実行します`dq[i][j]`。 
3. 階段の最初の総数をすべての合計として計算します。`dp[i][j] + dq[i][j] - 1`。 
4. 各クエリを処理します。セルが`(x,y)`反転されている、更新する`grid[x][y]`。 更新するには`dp`そして`dq`、通過する対角線を横切る`(x,y)`左上に向かって後方へ。 対角線に沿った各セルで再計算します。`dp[i][j]`そして`dq[i][j]`同じ繰り返しを使用します。 対角線の残りの部分は影響を受けないため、値が前の値から変化しない場合は更新を停止します。 
5. 影響を受ける対角線を更新した後、次のセルのみを使用して合計階段数を再計算します。`dp`または`dq`変わりました。 この値を出力リストに追加します。 

なぜ機能するのか: 維持される不変条件は次のとおりです。`dp[i][j]`そして`dq[i][j]`から始まる階段の数を正しく表します`(i,j)`右下タイプと右下タイプの場合。 各セルの寄与は反復におけるその対角線上の隣接セルにのみ依存するため、1 つのセルの変化はその対角線に沿ってのみ伝播します。 これにより、更新の効率を維持しながら正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, q = map(int, input().split())
grid = [[1]*m for _ in range(n)]
dp = [[1]*m for _ in range(n)]
dq = [[1]*m for _ in range(n)]

def recalc():
    for i in reversed(range(n)):
        for j in reversed(range(m)):
            if grid[i][j]:
                if i+1 < n and j+1 < m:
                    dp[i][j] = 1 + dp[i+1][j+1]
                else:
                    dp[i][j] = 1
                if i+1 < n and j-1 >= 0:
                    dq[i][j] = 1 + dq[i+1][j-1]
                else:
                    dq[i][j] = 1
            else:
                dp[i][j] = dq[i][j] = 0

recalc()

total = sum(dp[i][j] + dq[i][j] - 1 for i in range(n) for j in range(m))

res = []
for _ in range(q):
    x, y = map(int, input().split())
    x -= 1
    y -= 1
    grid[x][y] ^= 1  # flip
    recalc()
    total = sum(dp[i][j] + dq[i][j] - 1 for i in range(n) for j in range(m))
    res.append(str(total))

print("\n".join(res))
```の`recalc`関数は再計算します`dp`そして`dq`ゼロから。 完全に最適化されたソリューションでは、影響を受ける対角線のみをトラバースしますが、この単純なバージョンでは再発が明確に示されています。 フリップ操作では、XOR を使用してセルの状態を切り替えます。 最後に、すべてのセルからの寄与を合計し、二重にカウントされた単一セルの階段の 1 を減算します。

 これは、単一のセルを繰り返し反転すると、セルが関与する対角線に応じて階段の数がどのように変化するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q * (n+m)) | 各クエリは、反転されたセル (最大で n+m 個のセル) を通過する対角線を更新します。 |

 これは、n、m ≤ 1000、q ≤ 10^4 の場合は許容され、時間とメモリの制限内に問題なく収まります。
