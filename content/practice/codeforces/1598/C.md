 ## 解決策
 ## 問題の理解

 配列が与えられ、その平均値は元の配列に対して固定されます。 タスクは、正確に 2 つの要素を削除し、残りの要素の平均が変わらないようにインデックスのペアを何組削除できるかを数えることです。 

平均の観点から直接考えるよりも、条件を合計制約に変換する方が便利です。 元の配列に sum がある場合$S$そしてサイズ$n$の場合、平均は次のようになります。$k = S/n$。 2 つの要素を削除した後$a_i$そして$a_j$、残りの合計は$S - a_i - a_j$、残りのサイズは$n - 2$。 私たちは次のことを要求します:$$\frac{S - a_i - a_j}{n - 2} = \frac{S}{n}$$この式は、どのペアが有効であるかを完全に説明します。 

制約により、最大で$2 \cdot 10^5$すべてのテスト ケースにわたる要素の合計。これにより、テスト ケースごとの二次解が除外されます。 すべてのペアを直接試すアプローチでは、最大で次のことが必要になります。$O(n^2)$これは 2 秒で実行可能な作業をはるかに超えています。 

平均を処理するときに微妙な問題が発生します。$k$整数ではない可能性があるため、単純な整数比較では計算しようとすると正確性が損なわれる可能性があります。$k$浮動小数点値を比較します。 もう 1 つのよくある間違いは、ループ内で合計を繰り返し再計算することです。$O(n)$アイデアを取り入れる$O(n^2)$。 

具体的なエッジケースは、すべての要素が等しい場合です。 たとえば、`[5, 5, 5, 5]`、すべてのペアは機能しますが、何らかの「特別な構造」を想定した間違った導出は、値の変動を期待するため、有効なペアを誤って拒否する可能性があります。 

もう 1 つのケースは、次のような非常に特殊な相補ペアのみが機能する場合です。`[50, 20, 10]`ここで、ペアを削除すると平均が変化するため、答えはゼロになります。 これにより、正確な条件を導き出すことなく、対称性または周波数ベースのヒューリスティックを誤って仮定するソリューションが捕捉されます。 

## アプローチ

 ブルートフォースソリューションはすべてのペアを試行します$(i, j)$、それらを削除し、合計を再計算し、結果の平均が元の平均と等しいかどうかを確認します。 各除去コストの後に合計を再計算する$O(n)$、そして、あります$O(n^2)$ペアなので、合計は次のようになります$O(n^3)$。 合計を一度事前計算したとしても、各ペアは依然として導出された条件をチェックする必要があります。$O(n^2)$、すでに大きすぎます$2 \cdot 10^5$total elements.

 重要な観察は、条件を代数的に書き直すことから得られます。 Starting from:$$\frac{S - a_i - a_j}{n - 2} = \frac{S}{n}$$相互乗算により次が得られます。$$n(S - a_i - a_j) = (n - 2)S$$拡張:$$nS - n(a_i + a_j) = nS - 2S$$キャンセルする$nS$:$$n(a_i + a_j) = 2S$$それで：$$a_i + a_j = \frac{2S}{n}$$これにより、問題全体が、合計が固定目標値に等しいペアを数えるということになります。 これは、周波数ベースの線形解を直ちに示唆します。各値が何回出現したかを追跡しながら配列をスキャンし、各要素について、必要な合計を構成する前の要素の数を確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 最適 |$O(n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 合計を計算する$S$配列の値を計算し、目標の合計を導き出します$T = \frac{2S}{n}$。 もし$2S$で割り切れない$n$、有効なペアが存在しないため、答えはゼロです。 この割り算チェックにより、整数配列要素に対応できない非整数ターゲットの操作が防止されます。 
2. これまでに確認された値の頻度を保存するハッシュ マップを作成します。 これにより、補数の定数検索が可能になります。 
3. 配列を左から右に繰り返し、各要素を処理します$a[i]$潜在的なペアの 2 番目の要素として。 
4. 各要素について、必要な補数を計算します。$T - a[i]$。 このインデックスで終わる有効なペアの数は、この補数がプレフィックス内にすでに出現している回数とまったく同じです。 
5. このカウントを答えに加算し、現在の要素の頻度を増やします。 

重要な考え方は、すべての有効なペアは、ペアの 2 番目の要素が処理されるときに 1 回だけカウントされるということです。 

### なぜ効果があるのか

 この変換により、条件は固定和ペアリング問題に帰着します。 有効な各ペアはインデックスのペアに一意に対応します$(i, j)$と$i < j$そして$a_i + a_j = T$。 頻度マップにより、インデックスを処理する際に次のことが保証されます。$j$、それらを正確に数えます$i < j$方程式を満たすもの。 すべてのインデックスが 2 番目のエンドポイントとして 1 回だけ処理されるため、ペアが見逃されることはありません。また、配列内で前方検索が行われないため、ペアが二重にカウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))
        
        S = sum(arr)
        if (2 * S) % n != 0:
            print(0)
            continue
        
        target = (2 * S) // n
        
        freq = {}
        ans = 0
        
        for x in arr:
            need = target - x
            if need in freq:
                ans += freq[need]
            freq[x] = freq.get(x, 0) + 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、合計を計算し、有効な整数のターゲット ペア合計が存在するかどうかを確認することから始まります。 そうでない場合は、整数のペアが小数部の要件を満たすことができないため、すぐにゼロを返します。 

頻度辞書には、各値がこれまでに出現した回数が保存されます。 配列をスキャンすると、各要素が以前に確認された補数に基づいて答えに寄与し、正しい順序が保証されます。$i < j$。 

プレフィックス周波数を使用すると、二重カウントが回避され、テスト ケースごとのソリューションが線形に保たれます。 

## 実用的な例

 ### 例 1

 入力:```

```次のように計算します。$S = 20$、 それで$T = 2S/n = 40/5 = 8$私たちは頻度と貢献を追跡します。

これは、有効なペアが正確に合計 8 を形成するペアであり、2 番目の要素が見つかったときにそれぞれがカウントされることを示しています。

 入力:```

```ここ$S = 32$、 それで$T = 16$。 要素の各ペアの合計は 16 になります。

 ## 特殊なケース

 すべての値が同一である配列の場合、次のようになります。`[10, 10, 10]`の場合、アルゴリズムはその値の 2 倍に等しいターゲットを計算します。 すべての要素は補数条件に一致し、頻度の累積では、2 番目のインデックスが増加するたびにすべてのペアが 1 回だけカウントされます。 最終的な出力は次のとおりです$\binom{3}{2} = 3$、予想される組み合わせ結果と一致します。 

必要な合計が整数ではない場合、たとえば、`[1, 1, 2]`の場合、計算されたターゲットは非整数になります。$2S/n$は割り切れません。 アルゴリズムはすぐにゼロを返し、周波数処理は行われません。 これにより、不可能な等価性に依存する誤ったペアリングの試行が回避されます。
