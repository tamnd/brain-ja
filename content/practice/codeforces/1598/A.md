 ## 解決策
 ## 問題の理解

 2 行のグリッドがあります。`n`ゲームのレベルを表す列。 Monocarp は左上隅から始まります`(1, 1)`そして右下隅に到達したいと考えています`(2, n)`。 各セルは安全 (`0`) またはトラップ (`1`）。 移動は、対角線を含む 8 つの隣接するセルのいずれかに移動できますが、グリッドから出ることはできません。 Monocarp がトラップセルに入ると、彼はすぐに死にます。 入力により開始が保証されます。`(1, 1)`そして終わり`(2, n)`安全です。 

タスクは、複数のテスト ケースの開始から終了までのパスが存在するかどうかを判断することです。 以来`n`最大 100 で、行が 2 つしかなく、グリッド サイズが小さいです。 これにより、線形または二次的なアプローチが可能になります。`n`制限時間2秒以内で気持ちよく走るために。 

1 つの列が連続するトラップによってブロックされ、Monocarp がもう 1 つの列をジグザグに移動することを余儀なくされる場合、微妙なエッジ ケースが発生します。 たとえば、`n = 4`そしてグリッド:```
0111
1110
```上の列は開始時にほぼ完全にブロックされ、下の列は最後にブロックされます。 決して後戻りしない不注意な左から右への貪欲なアプローチでは、誤って「YES」と報告される可能性がありますが、有効なパスはなく、正しい答えは「NO」です。 もう 1 つのエッジ ケースは、次のような頻繁な斜めの移動を必要とする交互のトラップです。```
0101
1010
```ここには適切なジグザグのパスが存在するので、それを識別する必要があります。 

## アプローチ

 ブルート フォース手法では、開始セルから完全な深さ優先検索または幅優先検索を実行します。 各セルは最大 8 つの隣接セルを訪問できる可能性がありますが、セルの総数は`2 * n`。 したがって、BFS/DFS は次の環境で動作します。`O(n)`テストケースごとに、これは問題ありません`n ≤ 100`。 実装は簡単ですが、グリッドの構造が単純であることを考えると、やりすぎになる可能性があります。 

より高速なソリューションの重要な観察点は、パスが各列のトラップによって制限されていることです。 列の両方の列にトラップがある場合、Monocarp はその列を通過できません。 それ以外の場合は、必要に応じて列の間をジグザグに移動することができます。 基本的に、最初の列の後に両方のセルがトラップになっている列が存在するかどうかを確認するだけで済みます。 そのような列が存在する場合、Monocarp はゴールに到達できません。 それ以外の場合は可能です。 これにより、単純な条件チェックを使用した列に対する単一の線形スキャンに解決策が削減されます。 

ここでの話は、BFS は動きが制限されないため機能するが、2 列グリッドでは障害物が完全に通行可能性を決定するということです。 ダブルトラップカラムが障壁であることを観察すると、問題は次のように単純化されます。`O(n)`グラフを走査せずにチェックします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | BFS / DFS | テスト ケースあたり O(n) | O(n) | 承認済み |
 | リニアカラムチェック | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 テスト ケースごとに、次の内容を読んでください。`n`2 つのグリッド行は文字列として表示されます。 
2. フラグを初期化する`possible = True`パスが存在するかどうかを追跡します。 
3. 1 から 1 までの列を反復処理します。`n-1`(0 からインデックス付き)、安全であることが保証されている最初の列は無視されます。 
4. 各列について、上部と下部の両方のセルにトラップが含まれているかどうかを確認します (`1`）。 「はい」の場合は設定します`possible = False`そして休憩する。 これは、両方のセルがブロックされている列を横切ることができず、それを回避する方法がないためです。 
5. すべての列をスキャンした後、次の場合は「YES」を出力します。`possible`True のままで、それ以外の場合は「NO」を出力します。 

機能する理由: 不変条件は、すべての列で、Monocarp が常に少なくとも 1 つの安全なセルを占有することができるということです。 列に両方のセルがトラップとして含まれている場合、Monocarp はそれを越えて進むことができず、代替パスは存在しません。 開始セルと終了セルは安全であるため、唯一の障害となるのは完全にブロックされた列であり、このアルゴリズムはそれを正しく識別します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    top = input().strip()
    bottom = input().strip()
    
    possible = True
    for i in range(n):
        if top[i] == '1' and bottom[i] == '1':
            possible = False
            break
    print("YES" if possible else "NO")
```コードは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`複数のテストケースを処理します。 入力行を削除して改行文字を削除します。 列に対するループによって二重トラップがチェックされ、二重トラップが見つかった瞬間にそれ以上のスキャンが停止されます。 これにより、不必要なチェックが回避され、完全にブロックされた列に関するアルゴリズムの推論と一致します。 単純なブール値フラグを使用することで、パスの存在を誤って報告することがなくなります。

 ## 特殊なケース

 2 行 3 列のグリッドの場合:```
3
111
001
```1列目は上段にトラップがありますが、下段は安全です。 2列目に二重トラップがある？ いいえ、トップがあります`1`、 底`0`。 最後の列は安全です。 このアルゴリズムは列をスキャンし、ダブルトラップ列を見つけず、正しく「YES」を出力します。 これは、ソリューションが最小限のグリッドを正しく処理し、列ごとに少なくとも 1 つの安全なセルがあればパスが存在すると認識することを示しています。 

最大サイズの入力の場合 (`n = 100`)、アルゴリズムはテスト ケースごとに 100 チェックのみを実行するため、特別な最適化を行わなくても出力は効率的に生成されます。
