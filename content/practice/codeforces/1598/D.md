 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、$n$プログラミングの問題。 各問題にはトピックと難易度があり、両方とも整数で表されます。 トピックと難易度が同じ問題は 2 つありません。 私たちのタスクは、3 つすべてが異なるトピックを持つか、または 3 つすべてが異なる難しさ (またはその両方) を持つ 3 つの異なる問題を選択できる方法が何通りあるかを数えることです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは問題の数が指定されています$n$その後$n$各問題のトピックと難易度をリストした行。 出力はテスト ケースごとに 1 つの数値、つまり有効な問題のトリプルの数です。 

制約を考慮すると、$n$まで到達できます$2 \cdot 10^5$単一のテスト ケースでの合計と、$n$すべてのテストケースにわたって、また、次のように制限されます$2 \cdot 10^5$。 これにより、考えられるすべてのトリプルを明示的にチェックするアプローチは即座に除外されます。$O(n^3)$操作は次のとおりです$10^{15}$最悪の場合、2 秒の制限時間には遅すぎます。 

多くの問題が同じトピックや難しさを共有する場合、明白ではないエッジケースが発生します。 たとえば、トピックに関する問題が 4 つあるとします。`[1,1,2,3]`そして困難`[1,2,3,4]`、単純なアプローチでは、トピックや困難の重複を考慮せずに、すべてのトリプルが有効であると誤って仮定する可能性があります。 過剰カウントについては慎重に考慮する必要があります。 

## アプローチ

 ブルートフォース手法は簡単です。3 つの問題のすべての組み合わせを生成し、それらが「すべてのトピックが異なる、またはすべての難易度が異なる」条件を満たしているかどうかを確認します。 正しいのですが、これは$O(n^3)$そして完全に不可能$n \sim 10^5$。 

重要な洞察は、組み合わせ論を使用して間接的にトリプルをカウントすることです。 トリプルの合計数は、$\binom{n}{3} = n(n-1)(n-2)/6$。 ここから、両方の条件を満たさないトリプルを差し引くことができます。つまり、トピックを共有する問題が少なくとも 2 つあり、難しさを共有する問題が少なくとも 2 つあるものです。 これを効率的に行うために、トピック別、難易度別、および正確な (トピックと難易度) のペアごとに問題の数を追跡します。 

具体的には、トピックが表示された場合$x$回、それから$\binom{x}{2} \cdot (n-x)$トリプルには、このトピックに関する問題が少なくとも 2 つと、他の問題からの 1 つが含まれます。 同様に、困難についても計算します。 次に、正確なペア数を含む包含-除外を使用して、トピックと難易度の両方を共有するトリプルを二重にカウントすることを回避します。 これにより、次の問題が軽減されます。$O(n^3)$に$O(n)$各問題が一定時間内のカウントに寄与するため、テスト ケースごとに異なります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 組み合わせ論を使用して、制約なしで問題のトリプルの総数を計算します。`total_triples = n * (n-1) * (n-2) // 6`。 
2. 同じトピックを共有する問題の数を数えます。 登場するトピックごとに`x`時々、あります`x * (x-1) // 2`そのトピックに関する 2 つの問題を選択する方法。 これを乗算します`(n - x)`このトピック以外の 3 番目の問題については、 すべてのトピックを合計します。 
3. 難しい場合はステップ 2 を繰り返します。 
4. 正確な (トピック、難易度) のペアを数えます。 登場するペアごとに`y`回、計算する`y * (y-1) // 2`これを前の合計から差し引きます。 これにより、2 つの問題が主題と難易度の両方を共有する場合の過大なカウントが修正されます。 
5. 「無効な」トリプル (トピックの共有と難しさの共有) の合計をから引きます。`total_triples`有効なトリプルの数を取得します。 

機能する理由: すべてのトリプルは、少なくとも 1 つの条件を満たすか、無効としてカウントされます。 包含/除外調整により、両方の条件を満たさないトリプルを誤ってカウントしないことが保証されます。 トピック、困難、および正確なペアの数を事前に計算することにより、すべての組み合わせを明示的に反復することを回避します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import Counter

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        problems = [tuple(map(int, input().split())) for _ in range(n)]
        
        topic_count = Counter()
        difficulty_count = Counter()
        pair_count = Counter()
        
        for a, b in problems:
            topic_count[a] += 1
            difficulty_count[b] += 1
            pair_count[(a, b)] += 1
        
        total_triples = n * (n - 1) * (n - 2) // 6
        
        invalid = 0
        for cnt in topic_count.values():
            invalid += cnt * (cnt - 1) // 2 * (n - cnt)
        for cnt in difficulty_count.values():
            invalid += cnt * (cnt - 1) // 2 * (n - cnt)
        for cnt in pair_count.values():
            invalid -= cnt * (cnt - 1) // 2 * (n - cnt)
        
        print(total_triples - invalid)

if __name__ == "__main__":
    solve()
```この実装では高速 I/O を使用し、`Counter`トピック、難易度、および正確なペアごとの問題の数を追跡します。 最後のループの減算は過剰カウントを処理し、複数の問題がトピックと難易度の両方を共有するようなエッジケースの正確性を保証します。

 ## 特殊なケース

 すべての問題が同じトピックまたは難易度を共有している場合、アルゴリズムは一部のトリプルが無効であることを正確に識別します。 たとえば、問題に関しては、`(1,1),(1,2),(1,3)`、トピックの無効な数は次のとおりです。`3*2//2*(3-3)=0`、難易度はすべて固有であるため、出力は次のようになります。`1`。 カウンタはカウントを正確に追跡し、包含/除外によりトリプルが誤ってカウントされないようにします。
