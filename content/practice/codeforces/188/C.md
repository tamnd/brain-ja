 ## 解決策
 ## 問題の理解

 2 つの正の整数が与えられているので、それらの最小公倍数を計算する必要があります。 最小公倍数は通常 LCM と略され、両方の数値で余りを残さずに割り切れる最小の正の整数です。 

たとえば、数値が 10 と 42 の場合、210 は 10 と 42 の両方で割り切れ、これより小さい正の数はその性質を持ちません。 

制約は非常に小さいです。 どちらの数値も最大 1000 であるため、かなり非効率な方法でもすぐに終了します。 とはいえ、この問題は基本的には数学の問題であり、すぐに答えを計算する標準的な公式があります。 入力には 2 つの数値しか含まれていないため、実行時間は事実上一定です。 

よくある間違いは、数値を直接乗算し、積が常に LCM であると想定することです。 

考慮する：```
Input:
6 8
```正しい答えは次のとおりです。```
24
```不用意に実装すると、次のような出力が得られる可能性があります。```
48
```6 × 8 = 48 であるため、積は両方の数値で割り切れますが、そのような最小値ではありません。 

もう 1 つの微妙なケースは、一方の数字がもう一方の数字をすでに割っている場合に発生します。```
Input:
5 10
```正しい答えは次のとおりです。```
10
```大きい方の数値はすでに両方の値の公倍数になっています。 製品 50 を返品することは正しくありません。 

## アプローチ

 最も直接的なアプローチはブルートフォースです。 2 つの数値のうち大きい方から開始して、両方の入力で割り切れる整数が見つかるまで、連続する整数を繰り返しテストします。 最初の数値は LCM です。 

これが機能するのは、LCM の定義がまさに「最小の正の公倍数」であるためです。 最終的には公倍数が現れるはずなので、検索は終了します。 

たとえ制約が小さいとしても、ブルートフォースは不必要な作業を行います。 最悪の場合、答えに到達する前に多くの候補番号をテストする可能性があります。 

重要な観察は、最大公約数 (GCD) と最小公倍数の関係です。$$\text{LCM}(a,b)\times\text{GCD}(a,b)=a\times b$$この公式が機能するのは、GCD が 2 つの数値を乗算するときに 2 回カウントされる係数を表すためです。 GCD で除算すると、その重複が削除されます。 

Euclid のアルゴリズムを使用して GCD を計算すると、LCM はすぐに次のようになります。$$\text{LCM}(a,b)=\frac{a\times b}{\text{GCD}(a,b)}$$Euclid のアルゴリズムは非常に高速に実行されるため、このアプローチはエレガントかつ効率的になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(LCM(a,b)) | お(1) | これらの制約は受け入れられますが、非効率的です。 
| 最適 | O(log(min(a,b))) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り`a`そして`b`。 
2. コンピューティング`g = gcd(a, b)`Euclid のアルゴリズムを使用します。 

Euclidのアルゴリズムは繰り返し置き換える`(a, b)`と`(b, a % b)`2 番目の値がゼロになるまで。 残りのゼロ以外の値は GCD です。 
3. 以下を使用して最小公倍数を計算します。$$\text{lcm}=\frac{a\times b}{g}$$積では共通因数が 2 回カウントされるため、除算は GCD によって行われる必要があります。 
4. 結果の LCM を出力します。 

### なぜ効果があるのか

 正しさはアイデンティティから導き出される$$\text{LCM}(a,b)\times\text{GCD}(a,b)=a\times b.$$GCD には、両方の数値に共有される因子が正確に含まれています。 乗算するとき`a`そして`b`、これらの共有因子は 2 回現れます。 GCD で除算すると、すべての共有因子のコピーが 1 つ削除され、両方の入力に必要なすべての素因数が含まれる最小の数が残ります。 その数はまさに最小公倍数です。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

a, b = map(int, input().split())

print(a * b // gcd(a, b))
```このソリューションは 2 つの整数を読み取り、Python の組み込み関数を使用してそれらの最大公約数を計算します。`gcd`関数。 

式`a * b // gcd(a, b)`GCD と LCM の間の数学的関係を直接実装します。 結果が整数になることが保証されているため、整数除算が使用されます。 

覚えておく価値のある実装の詳細の 1 つは、操作の順序です。 乗算は除算の前に行う必要があります。 固定幅の整数型を使用する言語では、これによりオーバーフローが発生する可能性がありますが、Python の整数は自動的に増加するため、ここでのリスクはありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io
from math import gcd

def solve():
    a, b = map(int, input().split())
    print(a * b // gcd(a, b))

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    global input
    input = sys.stdin.readline

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return out

# provided sample
assert run("10 42\n") == "210\n", "sample 1"

# custom cases
assert run("1 1\n") == "1\n", "minimum values"
assert run("5 10\n") == "10\n", "one divides the other"
assert run("6 8\n") == "24\n", "shared factors"
assert run("1000 1000\n") == "1000\n", "maximum equal values"
assert run("999 1000\n") == "999000\n", "coprime near upper bound"
```| テスト入力 | 期待される出力 | 検証内容 |

次に、次のことを考えてみましょう。```

```アルゴリズムは以下を計算します。```
gcd(6, 8) = 2
lcm = (6 × 8) / 2 = 24
```出力は次のとおりです。```
24
```これにより、GCD で除算すると、重複した共通因子が積から削除されることが確認されます。 

最後に、等しい数を考えます。```
1000 1000

gcd(1000, 1000) = 1000

```結果は正確に元の数値であり、両方の入力が同一である場合の正しい最小公倍数です。
