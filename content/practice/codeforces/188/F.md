 ## 解決策
 ## 問題の理解

 タスクは、単一の正の整数を取得し、それを基数 2 で表現することです。つまり、係数 0 または 1 の 2 の累乗のみを使用してそれを書き換えます。通常の 10 進数表現の代わりに、2 の累乗の合計がその数値になることを示すバイナリ文字列が必要です。 

たとえば、数値 5 は 4 と 1 の選択に対応するため、そのバイナリ表現は次のようになります。`101`。 バイナリ文字列内の各位置は、特定の 2 のべき乗が合計に含まれるかどうかを表します。 

制約は非常に小さく、n は最大 1,000,000 です。 これは、単純なビット操作や繰り返し除算を行っても、パフォーマンス上の問題が発生する危険がまったくないことを直ちに意味します。 対数時間で実行されるソリューション、またはビット数が線形の場合でも十分なソリューションです。 1,000,000 のバイナリ長は最大でも 20 ビットであるため、出力自体は小さいです。 

構造上、隠れた例外的なケースはありませんが、実装上の落とし穴がいくつか頻繁に現れます。 1 つは、誤って先行ゼロを生成してしまうことです。たとえば、次のようなものを出力します。`000101`の代わりに`101`。 もう 1 つは、2 による除算を使用し、間違った順序でビットを追加した場合に、2 進数を誤って反転してしまうことです。 3 番目は、値 1 を誤って処理しており、これは直接出力されるべきです。`1`余分な書式設定は必要ありません。 

## アプローチ

 この問題を考える強引な方法は、2 の累乗を繰り返しチェックしてバイナリの構築をシミュレートすることです。 1、2、4、8 などから開始して、各累乗が残りの値に適合するかどうかをテストし、適合する場合はそれを減算することができます。 バイナリ表現は基本的に 2 のべき乗に対する貪欲な分解であるため、このアプローチは正しいです。 ただし、これは不必要に間接的であり、n までのすべてのべき乗または反復を繰り返す必要があり、ここではまだ小さいですが、概念的には非効率です。 

より直接的な強引なアプローチは、2 による除算を繰り返すことです。数値を 2 で除算し、毎回余りを記録し、ビットを収集します。 これが機能するのは、2 による除算が各ステップで最下位ビットを抽出するためです。 問題は正確さではなく出力順序です。 剰余は最下位ビットから最上位ビットの順に出力されるため、最後に反転する必要があります。 

重要な観察は、バイナリ表現が 2 による除算を繰り返したときの剰余のシーケンスであるということです。これにより、問題は対数長の単純なループに縮小され、最大入力に対して最大約 20 回の反復が生成されます。 文字列ビルダーや文字リスト以外の追加のデータ構造は必要ありません。

 ## アルゴリズムのチュートリアル

 1. 入力整数 n を変換する数値として受け取ります。 
2. n を 2 で繰り返し除算し、毎回剰余を保存します。剰余によって、現在の最下位ビットが 0 か 1 であるかがわかるからです。 
3. 各除算の後、n を n // 2 に置き換えて、より重要なビットに移動します。 
4. 最初の剰余は最下位ビットに対応するため、各剰余をリストに格納します。 
5. n が 0 になると、すべてのビットが処理されたため、ループを停止します。 
6. 収集された剰余は最下位ビットから最上位ビットの順に生成されているため、反転します。 
7. それらを 1 つの文字列に結合して出力します。 

この順序付けの手順が必要な理由は、バイナリ展開が位置に応じて行われるためです。 各部門は現在の最下位位置から情報を抽出するため、自然な生成順序は最終的な表現とは逆になります。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは n を n = 2q + r に分解します。ここで、r は 0 または 1 のいずれかです。その剰余 r は、正確に現在の最下位 2 進数です。 n を q に置き換えてその桁を削除すると、残りの数値が元の値の上位ビットを表すという不変条件が保持されます。 n がゼロになるまでこれを繰り返すと、2 の累乗のすべての寄与が 1 回だけ抽出されることが保証されるため、最終的な反転シーケンスは一意のバイナリ表現となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

bits = []

while n > 0:
    bits.append(str(n % 2))
    n //= 2

print(''.join(reversed(bits)))
```このソリューションは整数を読み取り、モジュロ 2 を使用して最下位ビットを繰り返し抽出します。抽出された各ビットは文字列として保存されます。 これらのビットは逆の順序で収集されるため、結合する前に最後にリストを逆にします。 

微妙だが重要な詳細は、n が 0 になったときに停止するということです。さらに続けると、先頭にゼロが追加されますが、これは正規のバイナリ表現の一部ではありません。 もう 1 つの詳細は、ビットを早期に文字列に変換することです。これにより、最終的な結合操作が簡素化されます。 

## 実用的な例

 ### 例 1: n = 5

 | ステップ | n | n%2 | ビット |
 | --- | --- | --- | --- |
 | 1 | 5 | 1 | [1] |
 | 2 | 2 | 0 | [1, 0] |
 | 3 | 1 | 1 | [1, 0, 1] |
 | 4 | 0 | 停止 | [1, 0, 1] |

 逆にすると、`101`。 これにより、アルゴリズムがバイナリ表現を最下位ビットから上に向かって正しく再構築していることが確認されます。 

### 例 2: n = 6

 | ステップ | n | n%2 | ビット |
 | --- | --- | --- | --- |
 | 1 | 6 | 0 | [0] |
 | 2 | 3 | 1 | [0, 1] |
 | 3 | 1 | 1 | [0, 1, 1] |
 | 4 | 0 | 停止 | [0, 1, 1] |

 逆転すると与える`110`、これは 6 = 4 + 2 に一致します。 

このトレースは、最下位ビットが 0 の場合でも、正しくキャプチャされ、保存されていることを示しています。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input().strip())

    bits = []
    while n > 0:
        bits.append(str(n % 2))
        n //= 2

    return ''.join(reversed(bits))

# provided sample
assert run("5\n") == "101", "sample 1"

# minimum value
assert run("1\n") == "1", "minimum case"

# power of two
assert run("8\n") == "1000", "power of two"

# all bits set
assert run("7\n") == "111", "all ones case"

# random mid value
assert run("10\n") == "1010", "alternating pattern"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 | 1 | 最小の有効な入力 |
 | 8 | 1000 | 単一の上位ビット |
 | 7 | 111 | 連続したもの |
 | 10 | 1010 | 交互のバイナリ パターン |

 ## 特殊なケース

 入力用`1`、アルゴリズムは n = 1 で始まり、追加されます。`1 % 2 = 1`、その後、n を 0 に減らして停止します。 ビットリストは次のようになります。`[1]`、そしてそれを逆にしても結果は得られます`1`。 これにより、単一ビットの場合が空の出力や余分なパディングを生成せずに処理されることが確認されます。 

入力用`8`、ループは剰余を生成します`[0, 0, 0, 1]`。 逆転すると与える`1000`。 これは、バイナリ形式の末尾のゼロが正しく保存され、途中で破棄されないことを示しています。
