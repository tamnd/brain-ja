 ## 解決策
 ## 問題の理解

 HQ9+ (4 つの命令を持つおもちゃの言語) で書かれたプログラムを表す文字列を分析するように求められます。`H`、`Q`、`9`、 そして`+`。 実行時に出力を生成するのは最初の 3 つだけです。`H`「Hello, World!」を印刷します。`Q`プログラム自体を出力し、`9`「99 Bottles of Beer」の歌詞を印刷します。 の`+`この命令は内部アキュムレータを変更しますが、何も出力しません。 入力文字列内の他の文字は無視されます。 

入力は、1 ～ 100 個の ASCII 文字を含む 1 行です。`!`(33) そして`~`(126)。 私たちの仕事は、このプログラムを実行すると出力が生成されるかどうかを判断することです。 何かを出力する命令が少なくとも 1 つある場合、出力は単純な「YES」、それ以外の場合は「NO」です。 

この問題は十分に制約されているため、文字列の線形スキャンが可能です。 最大長が 100 文字であっても、各文字を繰り返し処理して、`H`、`Q`、 または`9`必要な操作は最大 100 回ですが、2 秒の制限時間内では無視できる程度です。 

エッジ ケースは、完全に次のもので構成される文字列です。`+`文字またはその他の非出力文字。 例えば、`"+++"`「NO」を生成する必要がありますが、`"H++"`次の理由により、「YES」が生成されるはずです。`H`。 もう 1 つのエッジ ケースは、出力生成命令が最後に表示される文字列です。`"abc9"`。 不注意な実装では、スキャンの停止が早すぎたり、すべての文字が正しくチェックされなかった場合に「NO」が返される可能性があります。 

## アプローチ

 ブルートフォース手法は、プログラムをシミュレートすることです。つまり、各文字を反復処理して、対応するアクションを実行します。 これには実際の印刷やカウントが含まれますが、出力が行われるかどうかのみを考慮しているため、完全なシミュレーションは必要ありません。 この言語には命令が 4 つしかないため、総当り攻撃は機能しますが、必要な情報は次の情報だけであるため、概念的には過剰です。`H`、`Q`、 または`9`。 

最適なアプローチは、プログラムを実行する必要がないという観察を活用します。 出力は、文字列内の少なくとも 1 つの文字が次のいずれかである場合にのみ発生します。`H`、`Q`、 または`9`。 これにより、問題は単純なメンバーシップ チェックに集約されます。文字列を反復処理し、3 つの文字のいずれかに遭遇するとすぐに「YES」を返し、何も見つからなかった場合にのみ「NO」を返します。 このアプローチは入力の長さが線形であり、いくつかの変数を超えると追加のメモリを必要としません。

 ## アルゴリズムのチュートリアル

 1. 入力文字列を読み取り、末尾の改行を削除します。 これにより、プログラム コード自体のみが処理されるようになります。 
2. 文字列内の各文字を繰り返し処理します。 各ステップで、キャラクターが`H`、`Q`、 または`9`。 これらは、出力を生成する唯一の命令です。 
3. 文字が一致した場合は、すぐに「YES」を出力して終了します。 1 つの出力生成命令によってプログラムが出力を生成することが保証されるため、スキャンを続ける必要はありません。 
4. 3 つの文字のいずれにも遭遇せずにループが終了した場合は、「NO」を出力します。 これは、プログラムに出力生成命令がない場合を示しています。 

機能する理由: このアルゴリズムは、プログラム内に出力が存在する場合、出力を生成する命令が最初に出現したときに検出されるという不変条件を維持します。 すべての出力生成命令は明示的に既知であり、大文字と小文字が区別されるため、他の文字から出力が発生することはなく、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

program = input().strip()

for char in program:
    if char in "HQ9":
        print("YES")
        break
else:
    print("NO")
```コードはプログラム文字列を読み取り、各文字を反復処理します。 の`in`check は出力生成命令を識別します。 の`break`出力が検出されたらすぐに終了するようにします。 の`else`の条項`for`ループが実行されるのは、ループが何も発生せずに完了した場合のみです。`break`これにより、「出力なし」の場合をきれいに処理できるようになります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    program = input().strip()
    for char in program:
        if char in "HQ9":
            return "YES"
    return "NO"

# Provided samples
assert run("Hello!\n") == "YES", "sample 1"
assert run("+++\n") == "NO", "sample 2"

# Custom cases
assert run("Q\n") == "YES", "single output instruction"
assert run("abcdefg\n") == "NO", "no instructions"
assert run("abcHxyz\n") == "YES", "output instruction in middle"
assert run("99Bottles\n") == "YES", "contains 9 producing output"
assert run("++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++\n") == "NO", "maximum-size non-output"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | Q | はい | 単一出力命令 |
 | abcdefg | いいえ | 出力命令なし |
 | abcHxyz | はい | 中央の出力命令 |
 | 99ボトル | はい | 9個入り |
 | ++++... (最大 100) | いいえ | 最大サイズの非出力入力 |

 ## 特殊なケース

 完全に以下から構成されるプログラムを考えてみましょう。`+`文字:`"++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++"`。 ループは各文字をチェックしますが、何も見つかりません`H`、`Q`、 または`9`、そして`else`句は「NO」を出力します。 これにより、アルゴリズムが非出力命令のみを含む文字列を正しく処理することが確認されます。 

シングルのプログラムの場合`9`一番最後に：`"abc9"`、ループが繰り返されます`a`、`b`、`c`行動を起こさずに到達する`9`、「YES」を出力し、すぐに終了します。 これは、文字列の後半で検出された出力が正しく処理され、早期終了によって偽陰性が生成されないことを示しています。
