 ## 解決策
 ## 問題の理解

 文字列のセットが与えられているので、文字列から文字列に戻すなど、文字列間で文字を自由に移動できます。 目的は、すべての文字列が同じになるようにすべての文字を再配置できるかどうかを判断することです。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、文字列の数と文字列自体を指定します。 出力は、再配置が可能かどうかに応じて、単純な「YES」または「NO」です。 

制約は中程度です。 各テスト ケースには最大 1000 個の文字列を含めることができ、各文字列の長さは最大 1000 文字ですが、すべてのテスト ケースのすべての文字の合計は 1000 に制限されています。これは、文字列ごとまたはテスト ケースごとではなく、合計文字数が線形であるアルゴリズムを使用できることを意味します。 

重要な微妙な点は、文字が不均等に分散されている場合に発生します。 たとえば、「a」、「a」、および「b」という 3 つの文字列がある場合、「a」の合計数は 2 で、「b」は 1 です。各文字列は最終的に各文字の数が同じでなければならないため、3 つの同一の文字列を作成する方法はありません。 不注意な実装では、頻度を考慮せずに、すべての文字列に同じ文字セットが含まれていることのみをチェックする可能性があり、この場合は誤った「YES」が生成されます。 

## アプローチ

 ブルートフォースアプローチは、すべてが一致するまで文字列間で文字を移動することをシミュレートすることです。 たとえば、文字を繰り返し移動して、すべての文字列を最初の文字列と一致するように変換しようとすることができます。 これは理論的には正しいですが、現実的ではありません。各文字を個別に移動するには、文字列ごとに最大 1000 回の移動が必要となり、最悪の場合の操作数が 100 万回以上になる可能性がありますが、問題の制約を考慮すると、これは不必要です。 

重要な洞察は、文字の順序は重要ではないことを認識することです。 任意の文字を任意の文字列のどこにでも挿入できます。 これにより、問題はすべての文字列にわたる各文字の合計数をチェックすることになります。 有効な解決策を得るには、各文字の合計数が文字列の数で割り切れる必要があります。 そうでない場合、その文字をすべての文字列に均等に分配することは不可能であり、したがってすべての文字列を同一にすることは不可能です。 

これにより、潜在的に複雑なシミュレーション問題が単純な計数問題に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(合計文字数 * n) | O(合計文字数) | 遅すぎる |
 | 最適 | O(合計文字数) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. アルファベットの各文字のカウンターを初期化し、現在のテスト ケース内のすべての文字列にわたるその文字の合計数を表します。 これは、文字「a」から「z」でインデックス付けされたサイズ 26 の配列を使用して行われます。 
2. 各文字列を繰り返し処理します。 文字列内の文字ごとに、対応するカウンタをインクリメントします。 この反復の最後に、カウンターはすべての文字列にわたる各文字の合計出現数を保持します。 
3. 各カウンタの値を確認します。 すべてのカウンタが文字列の数で割り切れる場合`n`, 文字を均等に再配置することができるので、「YES」を出力します。 で割り切れないカウンタがある場合`n`、すぐに「NO」を出力します。 これが機能するのは、割り算により、すべての文字列が各文字の正確に同じ数を受け取ることができるためです。 

これが機能する理由: 不変条件は、文字の再配布に制約がないことです。 したがって、平等の唯一の要件は、各文字列が各文字の均等なシェアを受け取ることです。 合計数が文字列の数で割り切れる場合、有効な再配布が存在します。 それ以外の場合は、そうではありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    counts = [0] * 26  # total counts of 'a' to 'z'
    
    for _ in range(n):
        s = input().strip()
        for ch in s:
            counts[ord(ch) - ord('a')] += 1
    
    possible = all(count % n == 0 for count in counts)
    print("YES" if possible else "NO")
```このソリューションはテスト ケースの数を読み取り、それぞれを個別に処理します。 テスト ケースごとに、各文字の出現数をカウントします。 モジュロ演算子を使用すると、各文字を均等に分散できます。 サイズ 26 の配列を選択すると安全かつ効率的であり、辞書のオーバーヘッドが回避されます。 末尾の改行を削除するには、入力のストリッピングが必要です。 

## 実用的な例

 ### 例 1

 入力文字列：「caa」、「cbb」

 | 手紙 | 合計数 | 2で割り切れますか？ |
 | --- | --- | --- |
 | | 2 | はい |
 | b | 2 | はい |
 | c | 2 | はい |

 すべてのカウントが 2 で割り切れる場合、出力: YES。 文字を再配置して、両方の文字列で「cab」を形成することができます。 

### 例 2

 入力文字列: "cba"、"cba"、"cbb"

 | 手紙 | 合計数 | 3で割り切れますか？ |
 | --- | --- | --- |
 | | 2 | いいえ |
 | b | 4 | いいえ |
 | c | 3 | はい |

 一部のカウントが 3 で割り切れない場合、出力: NO。 

これにより、割り切れない文字数により再配布が不可能な場合をアルゴリズムが正しく識別していることが確認できます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(合計文字数) | すべての文字をテスト ケースごとに 1 回だけ繰り返します。 
| スペース | お(26) | 文字を数えるための固定サイズの配列 |

 すべての文字列の長さの合計 ≤ 1000 を考慮すると、これは制限時間内で十分に実行されます。 空間なんて些細なことだ。 

## テストケース```python

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    # call solution
    t = int(input())
    for _ in range(t):
        n = int(input())
        counts = [0] * 26
        for _ in range(n):
            s = input().strip()
            for ch in s:
                counts[ord(ch) - ord('a')] += 1
        possible = all(count % n == 0 for count in counts)
        print("YES" if possible else "NO")
    return output.getvalue().strip()

# Provided samples

# Custom test cases

 ## 特殊なケース

 文字列が 1 つある場合は、常に YES が出力されます。 文字の合計文字数が文字列の数で割り切れる場合、アルゴリズムは異なる長さの文字列を正しく処理します。 たとえば、「abc」、「a」の場合、カウントは a=2、b=1、c=1 になります。 n=2 の場合、b と c は 2 で割り切れず、出力は NO です。 これにより、アルゴリズムが文字の分布と文字列の数の両方を適切に考慮していることが確認できます。
