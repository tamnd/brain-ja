 ## 解決策
 ## 問題の理解

 次のシーケンスがあります$n+1$でつながっている部屋$n$ドア。 各ドア$i$番号があります$a_i$タッチしない場合に自動的に開く正確な秒数を示します。 一部の部屋にはバイナリ文字列に基づいたキーが最初に含まれています$s$、ここで、`1`鍵がその部屋に存在することを意味します。 部屋から始めます$1$時に$0$、そして毎秒、あなたは現在の部屋で鍵を拾ったり落としたりする可能性があります。 各秒の終わりに、ドアが開いている場合、またはドアを開けるための鍵を持っている場合は、次の部屋に移動することができます。また、自由に前の部屋に戻ることもできます。 鍵は使い捨てで、最大 1 つまで持ち運ぶことができます。 

目標は、ドアごとに計算することです$i$、部屋に到着できる最も早い秒数$i+1$、部屋から始まります$1$時に$0$。 ドアの答えがわかるという意味で、各ドアは独立しています。$i$後でさらに他の部屋に行きたいかどうかには依存しません。 

制約により許可されるのは、$n$まで$2 \cdot 10^5$、との合計$n$テストケース全体の上限も次のとおりです。$2 \cdot 10^5$。 秒単位での総当りシミュレーションは非常に遅すぎます。$a_i$と同じ大きさにすることができます$2 \cdot 10^5$、合計時間の次元が巨大になります。 代わりに、次のような線形の解決策が必要です。$n$テストケースごとに。 

明らかではないエッジケースには、時間とともに開くドアが含まれます$0$、すぐに使用できる鍵のある部屋、および到達するよりも遅れて開く一連のドア。 たとえば、次の場合$a_1 = 0$そして$s = "1"$、すぐにキーを選択し、それを使用して次の場所に移動できます。$0$数秒、部屋に到着$2$時に$1$。 キーの使用状況を適切に考慮しないと、到達可能な最も早い時間を過大評価する可能性があります。 

## アプローチ

 素朴なアプローチは、完全な BFS または毎秒のシミュレーションです。 ドアごとに、鍵の有無にかかわらずどの部屋に到達できるかを追跡し、目的の部屋に到達するまで時間を段階的に増加させます。 これは正しいですが、複雑さは次のとおりです。$O(n \cdot T)$、 どこ$T = \max(a_i)$。 以来$T$できる$2 \cdot 10^5$そして$n$まで$2 \cdot 10^5$、これはおおよそ次のようになります$4 \cdot 10^{10}$動作が遅すぎます。 

重要な洞察は、部屋内の移動は事実上 3 つの量の問題であるということです。ドアが自動的に開く最も早い時間 ($a_i$)、左に最も近いキー ($l_i$)、および右に最も近いキー ($r_i$）。 一度に持ち運べる鍵は 1 つだけであるため、部屋ごとに、左右の鍵を取得してドアを開けるために使用できる最も早い時間を事前に計算できます。 その後、部屋に到着する最も早い時間$i+1$左キーまたは右キーを使用してドアが自動的に開くまで待つ必要があります。 

この観察により、問題は 3 つの線形パス (左から右へのパス、右から左へのパス、および最小値を計算する最後のパス) に集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 秒単位のブルート フォース シミュレーション | O(n * max(a_i)) | O(n) | 遅すぎる |
 | 左/右キー到達時間を事前計算する | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析します: 読み取り$n$、 配列$a$、文字列$s$。 
2. 2 つの配列を初期化する`left`そして`right`サイズ $n`, representing the earliest time a key can reach each door from the left and from the right. Initialize `左`with infinity, and`右`を無限大にします。 
3. **左から右へのパス**: 最後に確認されたキー時間を追跡します。 

のために`i`から`0`に`n-1`:

 - 余裕がある場合`i`キーが含まれています (`s[i] == '1'`）、 セット`last_key = 0`キーがすぐに利用可能になるためです。 
- もし`last_key`定義されており、`left[i] = last_key + 1`そして増加します`last_key`動きを考慮してステップごとに 1 ずつ増加します。 

これは、鍵を選択して右に移動し、部屋ごとに 1 秒を追加するモデルです。 
4. **右から左へのパス**: 左のパスと対称です。 

のために`i`から`n-1`まで`0`:

 - 余裕がある場合`i`キーが含まれています (`s[i] == '1'`）、 セット`last_key = 0`。 
- もし`last_key`定義されており、`right[i] = last_key + 1`そして増加します`last_key`左に移動してから戻ることを考慮して、ステップごとに 1 ずつ増加します。 
5. 各ドアの最短到達時間を計算します。 

それぞれについて`i`から`0`に`n-1`:

 -`ans[i] = min(a[i], left[i], right[i])`これには、左からのキーを使用するか、右からのキーを使用してドアが自動的に開くまで最小限の待ち時間で済みます。 
6. 結果を印刷します。 

なぜ機能するのか: 不変条件は次のとおりです。`left[i]`キーが左から到着する最小時間を格納します。`right[i]`右から。 一度に取得できる鍵は 1 つだけであるため、目的のドアに向かって一方向に移動することが常に最適です。 最小限のものを採用する`a[i]`鍵が到達する前に自動的に開くドアを処理します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        s = input().strip()
        INF = 10**9

        left = [INF] * n
        right = [INF] * n

        # Left to right
        last_key = -INF
        for i in range(n):
            if s[i] == '1':
                last_key = 0
            else:
                if last_key != -INF:
                    last_key += 1
            if last_key != -INF:
                left[i] = last_key

        # Right to left
        last_key = -INF
        for i in range(n-1, -1, -1):
            if s[i] == '1':
                last_key = 0
            else:
                if last_key != -INF:
                    last_key += 1
            if last_key != -INF:
                right[i] = last_key

        ans = []
        for i in range(n):
            ans.append(str(min(a[i], left[i], right[i])))
        print(' '.join(ans))

if __name__ == "__main__":
    solve()
```このコードは、高速 I/O を備えたアルゴリズムを実装し、左右のキー到達時間を事前計算します。 番兵`-INF`アクセス可能なキーがない部屋が計算に影響を与えないようにします。 インクリメント`last_key`各ステップで 1 つずつ部屋間の移動をモデル化します。 最終的な最小値は、キーを使用する場合と自動ドアが開くのを待つ場合を比較します。
