 ## 解決策
 ## 問題の理解

 同じ頂点セットの 2 つの DFS 事前順序トラバーサルが与えられています。`{0,1,...,n}`。 

木自体は不明です。 私たちが知っている唯一のことは、両方の走査でルートが`0`が最初に表示され、DFS 中のすべての頂点の子の順序は任意です。 

Tortinita の走査を生成する子の順序の選択肢が存在し、Arietta の走査を生成する子の順序の選択肢も存在する場合、ツリーは共通と呼ばれます。 

このような一般的なツリーすべての中で、可能な最大の深さを見つけなければなりません。 

主な問題点は、DFS 事前注文ではツリーが一意に決定されないことです。 多くの異なるルートを持つツリーが同じ走査を生成する可能性があります。 両方の置換によってどの祖先と子孫の関係が強制されるのかを正確に理解し、可能な限り深い共通ツリーを構築する必要があります。 

入力サイズにより、二次関数は即座に除外されます。 すべての合計`n`までです`10^6`、と同じくらいあるかもしれません。`10^4`テストケース。 平`O(n√n)`不快だろう。 おおよその必要があります`O(n log n)`総仕事量。 

微妙な点は、2 つのトラバースが同じ頂点ラベルを使用していることです。 位置を比較しているのではなく、異なる DFS オーダーに表示される同じ頂点を比較しています。 

もう 1 つの簡単な間違いは、1 つの DFS 注文に現れるすべての間隔が自動的にサブツリーになると想定することです。 例えば：```
a = [1,2,3]
b = [2,1,3]
```セグメント`{1,2}`は両方の置換で連続していますが、共通ツリーではどちらの頂点ももう一方の親になることはできません。 答えはただ`1`。 

2 番目の罠は、有効なサブツリーが入れ子構造を形成することです。 2 つの候補サブツリー間隔が部分的に重なることはありません。 たとえば、間隔`[1,4]`そして`[3,6]`両方を有効なサブツリー範囲にすることはできません。 正しい解決策は、この層流特性を利用する必要があります。 

## アプローチ

 ブルート フォース ビューでは、考えられるすべての共通ツリーを再構築し、その深さを計算します。 

なぜこれが概念的に機能するのでしょうか? すべてのサブツリーは、すべての DFS 事前注文で連続したブロックを占有する必要があります。 間隔の境界を繰り返し選択し、再帰的にツリーを構築し、一貫性をテストすることができます。 

問題は、可能な区間分解の数が膨大であることです。 すべての間隔を確認する場合でも、`Θ(n²)`候補者を単純に検証するには、別の要素がかかります。`n`。 と`n = 10^6`複数のテストケースにわたって、これは完全に不可能です。 

最初の観察は、2 つの任意の順列を扱うのは扱いにくいということです。 1 つの順列を完全に削除できます。 

させて`pos[v]`頂点の位置になる`v`アリエッタのDFSオーダーで。 すべての値を置き換えます`a[i]`による`pos[a[i]]`。 

この再ラベル付けの後、Arietta の DFS 順序は次のようになります。```
0,1,2,...,n
```そしてトルティニータの順序は単一の順列になります`c`。 

これで、Arietta のツリー内のすべての有効なサブツリーが連続値の間隔に対応します。 

次の観察は重要な観察です。 

セグメントを想定します`c[l..r]`サブツリーを表します。 

そのルートはセグメントの最初の要素でなければなりません。 

アリエッタの順序は恒等順列であるため、そのサブツリーの頂点は正確に連続した値の範囲でなければなりません。 

つまり:```
c[l] = min(c[l..r])

max(c[l..r]) - min(c[l..r]) = r - l
```2 番目の条件は、セグメント内の値が完全な連続した間隔を形成していることを示します。 

したがって、問題全体は次のようになります。 

すべての開始位置について`l`、最大のものを見つけます`r`この2つの条件を満たしていること。 

結果として得られる有効な間隔は、サブツリー間隔とまったく同じように動作します。 それらは層状ファミリーを形成します。いずれか 2 つが互いに素であるか、一方が他方を含んでいます。 すべての位置から始まる最大有効間隔がわかれば、最大深度を回復することは単純な入れ子問題になります。 

残りの課題は、有効な最大間隔をすべて効率的に見つけることです。 

社説では分割統治を一定期間ごとに使用しています。 再帰セグメントの場合`[L,R]`、中間点を横切るすべての有効な間隔を処理します。 

左半分に接尾辞の最小値/最大値、右半分に接頭辞の最小値/最大値を使用すると、条件を代数等式に書き換えることができ、再帰レベルごとの線形時間で左端点と右端点を一致させることができます。 

これにより、`O(n log n)`解決。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n²) | 遅すぎる |
 | 分割統治 + インターバル再構成 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. 順列を正規化する

 ビルド:```
pos[v] = position of v in b
```そして定義します```
c[i] = pos[a[i]]
```さて、アリエッタの命令は恒等の並べ替えです。 

### 2. 有効なサブツリー セグメントの特徴付け

 セグメント`[l,r]`次の場合に限り、共通のサブツリーに対応します。```
c[l] = min(c[l..r])
```そして```
max(c[l..r]) - min(c[l..r]) = r - l
```最初の条件は、サブツリーのルートが最初に現れることを示します。 

2 番目の条件は、値が 1 つの連続した間隔を形成することを示します。 

### 3. すべての位置から開始して最大有効間隔を計算します。 

しましょう`R[l]`は最大の有効な右端点を示します。 

分割統治を使用します。 

再帰間隔の場合`[L,R]`中点付き`mid`、両方の半分を再帰的に解決してから、中点を横切る区間を処理します。 

事前計算:```
left suffix minima/maxima
right prefix minima/maxima
```左側のエンドポイントごとに`i`、 させて：```
mn = minimum on [i,mid]
mx = maximum on [i,mid]
```以下の位置のみ`c[i]`新しい最小値はサブツリーのルートとして機能します。 

2 つのケースが存在します。 

最終セグメントの最大値は左半分から来ます。 

それから：```
j = i + mx - mn
```そして残りの条件を直接確認します。 

最大値は右半分から来ます。 

それから：```
max_right - j = mn - i
```これは、左右の位置のマッチングの問題になります。 

右のポジションを次のようにグループ化して保存します。```
max_right - j
```単調ポインタを使用して実現可能な最大値を取得します`j`。 

これにより、再帰ノードのすべての交差間隔が線形時間で処理されます。 

### 4. 間隔をツリーとして解釈する

 すべての有効な間隔はサブツリーに対応します。 

有効な間隔が交差することはないため、各位置で始まる最大間隔が入れ子構造を定義します。 

位置を左から右に移動します。 

現在アクティブな間隔のスタックを維持します。 

インターバルが終了したら削除します。 

位置決め時`i`有効な間隔を開始すると、その右のエンドポイントをプッシュします。 

スタック サイズは、再構築された共通ツリー内の現在の深さに等しくなります。 

最大スタック サイズを追跡します。 

### 5. ルートを追加します

 順列は頂点を除外します`0`。 

非ルート頂点の中で最も深いネストがある場合、`d`の場合、実際のツリーの深さは次のようになります。```
d + 1
```それが必要な答えです。 

### なぜ効果があるのか

 正規化後、Arietta のツリー内のすべてのサブツリーは、連続した値の間隔に対応します。 

DFS 事前順序プロパティは、サブツリー ルートがそのセグメント内で最初に表示されるように強制し、最小条件を与えます。 

連続する値のセットは、正確に次のような特徴があります。```
max - min = length - 1
```これで 2 番目の条件が得られます。 

したがって、有効なセグメントはまさに共通のサブツリーです。 

分割統治ステップでは、すべての間隔が半分に完全に収まるか、中間点を横切るため、すべての最大有効セグメントが検索されます。 交差の場合は、導出された 2 つの方程式によって徹底的に処理されます。 

サブツリー間隔は層状ファミリーを形成するため、間隔のネストの深さは最も深い共通ツリーの深さに等しくなります。 スタックの再構築では、このネストの深さを正確に計算します。 

したがって、アルゴリズムは可能な最大の深さを返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())

        a = [0] + list(map(int, input().split()))
        b = [0] + list(map(int, input().split()))

        pos = [0] * (n + 1)
        c = [0] * (n + 1)
        R = [0] * (n + 1)

        for i in range(1, n + 1):
            pos[b[i]] = i

        for i in range(1, n + 1):
            c[i] = pos[a[i]]

        for i in range(1, n + 1):
            pos[c[i]] = i

        mn = [0] * (n + 2)
        mx = [0] * (n + 2)

        buckets = [[] for _ in range(2 * n + 5)]
        ptr = [0] * (2 * n + 5)

        sys.setrecursionlimit(1 << 20)

        def dc(l, r):
            if l >= r:
                return

            mid = (l + r) >> 1

            dc(l, mid)
            dc(mid + 1, r)

            mn[mid] = mx[mid] = c[mid]
            for i in range(mid - 1, l - 1, -1):
                mn[i] = min(mn[i + 1], c[i])
                mx[i] = max(mx[i + 1], c[i])

            mn[mid + 1] = mx[mid + 1] = c[mid + 1]

            buckets[c[mid + 1] - (mid + 1) + n].append((c[mid + 1], mid + 1))

            for i in range(mid + 2, r + 1):
                mn[i] = min(mn[i - 1], c[i])
                mx[i] = max(mx[i - 1], c[i])
                buckets[mx[i] - i + n].append((mn[i], i))

            for i in range(mid, l - 1, -1):
                if mn[i] != mn[i + 1]:

                    j = i + mx[i] - mn[i]

                    if (
                        mid < j <= r
                        and mn[j] > mn[i]
                        and mx[j] < mx[i]
                    ):
                        if j > R[i]:
                            R[i] = j

                    key = mn[i] - i + n

                    vec = buckets[key]

                    while (
                        ptr[key] < len(vec)
                        and vec[ptr[key]][0] > mn[i]
                    ):
                        ptr[key] += 1

                    if ptr[key]:
                        k = vec[ptr[key] - 1][1]

                        if mx[k] > mx[i]:
                            if k > R[i]:
                                R[i] = k

            for i in range(mid + 1, r + 1):
                key = mx[i] - i + n
                buckets[key].clear()
                ptr[key] = 0

        dc(1, n)

        stack = []
        ans = 0

        for i in range(1, n + 1):
            while stack and stack[-1] <= i:
                stack.pop()

            if R[i]:
                stack.append(R[i])
                if len(stack) > ans:
                    ans = len(stack)

        print(ans + 1)

solve()
```最初の部分では、2 つの順列を 1 つの順列に正規化します。`c`。 

分割統治ルーチンは、各位置から始まる最大有効間隔を計算します。 配列`mn`そして`mx`現在の再帰セグメントの左側にサフィックス minima/maxima を保持し、右側にプレフィックス minima/maxima を保持します。 

最もデリケートな部分は 2 番目の交差ケースです。 方程式```
max_right - j = min_left - i
```値によって右のエンドポイントをグループ化できます`max_right - j`。 単調ポインタは、各再帰ノード内での線形作業を保証します。 

最後に、スタックは間隔のネストを再構築します。 現在の位置より前で終了する間隔は削除され、新しく開始された間隔は追加されます。 最大スタック サイズは、最も深いネスト レベルと同じです。

## 特殊なケース

 次のことを考慮してください。```
n = 2
a = [1,2]
b = [2,1]
```正規化後:```
c = [2,1]
```セグメント`[1,2]`最初の要素がセグメントの最小値ではないため、失敗します。 アルゴリズムは有効な間隔を割り当てず、スタックは空のままになり、答えは次のようになります。`1`。 

ここで次のことを考えてみましょう。```
n = 5
a = [1,2,3,4,5]
b = [1,2,3,4,5]
```すべてのプレフィックス間隔は有効です。```
[1,5]
[2,5]
[3,5]
[4,5]
```それらは完全に入れ子になっています。 スタックの深さが到達しました`4`、そして最終的な答えは`5`、ルートの下にある長さ 5 のチェーンに対応します。 

より微妙なケースは、2 つの候補区間が部分的に重なる場合です。 有効性条件により、両方が同時に存在することは自動的に防止されます。 再構築中、区間は層状ファミリーを形成するため、スタック表現は正しいままであり、区間が交差することはありません。 これがまさに、間隔ネストのみを使用して深さを計算できる理由です。
