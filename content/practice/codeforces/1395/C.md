 ## 解決策
 ## 問題の理解

 2 つの小さな整数配列が与えられます。 最初の配列のすべての要素について、2 番目の配列から 1 つの要素を選択し、ビットごとの AND を使用して結合する必要があります。 これにより、最初の配列内の各位置に新しい値が生成されます。 これらすべての組み合わせを選択した後、結果として得られるすべての値に対してビット単位の OR を計算し、この最終的な OR をできるだけ小さくする必要があります。 

これを理解するもう 1 つの方法は、最初の配列の各要素が 2 番目の配列から 1 つのパートナーを「選択」する必要があり、各選択によってビットのグローバルな結合に寄与するビットマスクが生成されるということです。 OR はビットを永続的に蓄積するため、選択した AND 結果に現れるビットは最終的な答えに現れます。 目標は、この結合内でできるだけ少ないビットが残るようにペアリングを選択することです。 

制約は小さいです。両方の配列のサイズは最大 200 で、各数値は 9 ビットに収まります。つまり、すべての値は 0 ～ 511 の範囲内にあります。この組み合わせは重要です。 ビット幅が小さいため、数値の大きさではなくビットのサブセットの観点から考えることができ、要素の数が少ないため、サブセットまたは状態に対する動的プログラミングが可能になります。 

単純なアプローチでは、n 個の要素のそれぞれに m 個の選択肢のうちの 1 つを個別に割り当てようとします。 それはすでに mⁿ の可能性を与えていますが、これは中程度の n であっても完全に実行不可能です。 考えられるすべての OR 結果を組み合わせから直接計算しようとすると、爆発的な結果になります。 

さらに微妙な失敗例は、貪欲な思考から生じます。 各 aᵢ に aᵢ と bⱼ を局所的に最小化する bⱼ を割り当てようとするかもしれません。 単一の cᵢ を削減しても、小さいグローバル OR が保証されないため、これは機能しません。 早期に導入されたビットは、他の制約により後で避けられない場合があります。 

たとえば、ある aᵢ が特定の bⱼ を使用することによってのみビットを回避できるが、別の aₖ には選択の余地がなく、とにかくそのビットを強制する場合、aᵢ に対する貪欲な選択は意味がありません。 すべての割り当て間の結合は、OR を通じてグローバルに行われます。 

## アプローチ

 ブルートフォース解釈では、各 aᵢ に m 値の 1 つを割り当て、結果の OR を計算します。 各代入により n 個の値 cᵢ = aᵢ & bⱼ が生成され、それらの OR が計算されます。 これには mⁿ の割り当てを探索する必要があり、OR では早期の局所最適性の保証ができないため、枝刈りさえも意味のある助けにはなりません。 n = 200 では、これは計算の限界をはるかに超えています。 

重要な点は、ビットごとの OR の構造にあります。 最終的な答えは 9 ビット マスクです。 つまり、最終結果は 2⁹ = 512 通りしかありません。 割り当てを直接決定する代わりに、逆に考えることもできます。つまり、最終的な OR マスクを推測し、それが達成可能かどうかを確認します。 

候補マスク X を修正します。結果として得られるすべての (aᵢ & bⱼ) が X のサブマスクになるように、各 aᵢ a bⱼ を割り当てることができるかどうかを知りたいのです。選択されたペアのいずれかが X の外側にビットを導入する場合、その候補はすぐに失敗します。 したがって、各 aᵢ について、(aᵢ & bⱼ) ⊆ X となる bⱼ のみを考慮します。 

ここで問題は、各 aᵢ に対して、X と互換性のある bⱼ が少なくとも 1 つ存在するかということです。 すべての i が「はい」の場合、X は達成可能です。 これが機能する理由は、最後の OR が X 内に収まるように制限しているだけだからです。どの bⱼ が使用されるかを区別することは気にせず、各 aᵢ が有効な選択肢を持つことだけを考慮します。 

これにより、問題は 512 個の候補をチェックすることになり、それぞれが n・m 個のペアをスキャンする必要があります。 これは簡単に十分に高速です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース割り当て | O(mⁿ) | O(n) | 遅すぎる |
 | すべての OR マスクを試す | O(2⁹ · n · m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 0 から 511 までのすべての可能なビットマスク X を反復処理し、X が最終的な答えになるかどうかをテストします。

1. 候補マスク X から開始し、それがターゲット OR 結果であると仮定します。 これを、X の外側のビットがどの cᵢ にも出現することを許可されないという制約として解釈します。 
2. 各要素 aᵢ について、(aᵢ & bⱼ) が X のサブマスクであるような bⱼ が少なくとも 1 つ存在するかどうかを確認します。これにより、aᵢ をその bⱼ に代入しても禁止ビットが導入されないことが保証されます。 
3. ある aᵢ に対してそのような bⱼ が存在しない場合、制約に違反せずに aᵢ を割り当てることはできないため、X は不可能です。 
4. すべての aᵢ に少なくとも 1 つの有効な bⱼ がある場合、X は実現可能です。 可能なすべての X の最小値として答えを更新します。 

微妙な点は、X が固定されると実現可能性は要素ごとに独立するということです。 私たちは割り当てを共同で最適化しているわけではありません。 存在を確認するだけです。 OR 結合はすでに X にエンコードされているため、消滅します。 

### なぜ効果があるのか

 固定マスク X の場合、有効な割り当ては X 内のビットのみを生成する必要があります。1 つの aᵢ に互換性のある bⱼ がない場合、その aᵢ に対するすべての可能な割り当ては禁止ビットを導入するため、X を最終的な OR にすることはできません。 

逆に、すべての aᵢ に少なくとも 1 つの互換性のある選択肢がある場合、インデックスごとに独立して割り当てることができ、X の外側にビットを導入することはありません。生成されるすべてのマスクは X のサブセットであるため、その OR も X のサブセットであり、最終的な OR が X を超えることはできません。すべての要素を実現できるマスクのみを受け入れるため、X は実現可能です。 

したがって、アルゴリズムは最終的な OR で達成可能な最小の上限を検索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    INF = 10**9
    ans = INF

    for mask in range(1 << 9):
        ok = True

        for i in range(n):
            found = False
            for j in range(m):
                if (a[i] & b[j]) | mask == mask:
                    found = True
                    break
            if not found:
                ok = False
                break

        if ok:
            ans = min(ans, mask)

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、各候補マスクの実現可能性テストを直接実装します。 鍵となる表現`(a[i] & b[j]) | mask == mask`AND 結果のすべてのビットが候補マスクに含まれているかどうかをチェックします。 これは以下と同等です`(a[i] & b[j]) ⊆ mask`。 

n と m が最大 200 であり、外側のマスク ループの反復回数が 512 回のみであるため、ネストされたループは許容されます。 

実装の微妙な詳細の 1 つは、初期段階で重大な問題です。aᵢ に対して有効な bⱼ が見つかると、それ以上の j 値のチェックを停止します。 同様に、いずれかの aᵢ が失敗すると、マスクのチェックを完全に停止します。 これにより、無駄な作業が防止されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    INF = 10**9
    ans = INF

    for mask in range(1 << 9):
        ok = True
        for i in range(n):
            found = False
            for j in range(m):
                if (a[i] & b[j]) | mask == mask:
                    found = True
                    break
            if not found:
                ok = False
                break
        if ok:
            ans = min(ans, mask)

    return str(ans)

2 6 4 0
2 4
""") == "2"

# minimum size
assert run("""1 1
0
0
""") == "0"

1 2

""") == "0"

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての aᵢ がゼロである場合です。 すべての bⱼ は AND の後にゼロを生成するため、すべてのマスクが実行可能であり、最小値はゼロです。 マスク = 0 の場合、すべてのペアが 0 のサブマスクである 0 を生成するため、アルゴリズムはこれを処理します。したがって、実現可能性はすぐに当てはまります。 

もう 1 つのエッジ ケースは、一部の aᵢ に小さなマスクと互換性のある bⱼ がない場合です。 たとえば、aᵢ に bⱼ との AND によって削除できない上位ビットがある場合、そのビットを除くすべてのマスクはそのインデックスで失敗します。 アルゴリズムは、そのマスクの実現可能性チェックのステップでこれを正確に検出します。 

最後のケースは、異なる aᵢ が bⱼ の互換性のない選択を必要とする場合です。 このアルゴリズムは選択内容を同期しようとしません。 代わりに、固定マスクの下で要素ごとの存在のみをチェックし、OR 境界を修正した後にその独立性を正しくキャプチャします。
