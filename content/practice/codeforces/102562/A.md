 ## 解決策
 ## 問題の理解

 ゲームは 12 列の 6 列のボードで構成されます。 最下位の 8 列が実際のプレイエリアですが、その上の 4 列は駒が落ちている間のみ使用されます。 一部のセルは最初にブロックされており、配置されたすべてのピースは、完全な行が削除されるまで、その占有されているセルが永久にブロックされたセルに変わります。 

入力により、最大 5 つのテトロミノ ピースのシーケンスと、表示されているボードの最初にブロックされたセルが得られます。 ベンはすべてのピースを回転させたり、水平に動かしたり、落下させたりすることができます。 目的は、考えられるゲームを 1 つ見つけることではなく、完了した行から得られる合計スコアを最大化する動きを選択することです。 

ピース数の小さな制限が重要な制約です。 通常のテトリス シミュレーションには膨大な数の可能な位置がありますが、ピースが最終的にどこに着地するかについて決定する必要があるのは 5 つだけです。 これにより、すべてのピースの配置を効率的に圧縮できれば、網羅的な検索が可能になります。 

不注意な実装は通常、3 つの場所で失敗します。 1 つ目は、回転自体が回転中の衝突によって制限されていることを忘れていることです。 最終的な方向は有効に見えるかもしれませんが、中間の回転位置がブロックされたセルと重なるため、到達できない可能性があります。 

2 番目の間違いは、行を間違ってクリアすることです。 1 回の配置後に複数の行が消える可能性があり、削除されたすべての行の上の行が一緒に下に移動します。 たとえば、1 つの正方形のピースが 2 行の最後の欠けているセルを完成させると、両方の行が消え、スコアは 2 つの別々の 100 スコアではなく 300 になります。 

3 番目の間違いは、余分な列にピースを配置してしまうことです。 落下エリアは、駒をボードに入れるためだけに存在します。 合法的な最終配置では、すべての占有セルが下 8 行内に収まっている必要があります。 

## アプローチ

 直接的な解決策は、考えられるあらゆる移動シーケンスをシミュレートすることです。 スポーン位置から、左に移動、右に移動、時計回りに回転、反時計回りに回転、または下に移動という 5 つの選択肢を常に試すことができます。 ピースが下に移動できなくなった場合は、それを設定して次のピースに進むことを選択できます。 

これは正しいです。すべての合法的なゲームは、この検索ツリーを通る 1 つのパスにすぎないからです。 ただし、分岐要素は大きく、多くの異なる移動シーケンスが同じ最終配置に達します。 ピースの数は少ないにもかかわらず、パスの数はすぐに増加します。 

重要な観察は、スコアは配置された各駒の最終位置にのみ依存し、そこに到達するまでに使用された一連の動きには依存しないということです。 1 つの現在の駒と 1 つのボードの状態については、到達可能なすべての状態で幅優先検索を実行できます。 これにより、すべての移動履歴を保存することなく、あらゆる可能な合法的な着陸位置が得られます。 

ピースに対して考えられるすべての着地を生成した後、それぞれを再帰的に試します。 ピースが 5 つしかないため、再帰によって到達するボード状態の数は管理可能なままです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | すべての動作シーケンスで O(5^M) | お(お) | 遅すぎる |
 | 最適 | O(すべての DFS 状態にわたる到達可能なプレースメントの数) | O(DFS 状態の数) | 承認済み |

 ## アルゴリズムのチュートリアル

1. ボードを 12 ビットマスクとして保存します。 セットされたビットは、セルが使用できないことを意味します。 ビット演算により衝突チェックが一定時間行われます。 
2. すべてのテトロミノの 4 つの回転を事前計算します。 各回転は、ピースの原点を基準とした占有セルのリストとして保存されます。 
3. 現在のピースに対して、スポーン状態から開始して BFS を実行します。 状態には原点座標と回転インデックスが含まれます。 あらゆる状態から 5 つの可能な動きを試してください。 トランジションは、回転および移動された駒のすべてのセルがボード内にあり、ブロックされたセルと重ならない場合にのみ追加されます。 
4. BFS 状態が下方に移動できないときはいつでも、それが着陸可能な位置です。 すべてのセルが実際の 8 行の領域内にある場合は、そこにピースを配置することをシミュレートします。 
5. ピースを配置した後、そのセルをブロック済みとしてマークします。 完全に埋まった行をすべて見つけて削除し、その上の行を下に移動して、削除された行の数に応じたスコアを加算します。 
6. 次の部分に戻ります。 答えはすべての選択肢の中の最大スコアです。 ピースに正当な着地位置がない場合、現在の分岐は終了します。 

なぜ効果があるのか:

 BFS グラフ内のすべてのエッジが 1 つの有効なゲームの手を表すため、BFS は正当な手によって到達可能な状態を正確に列挙します。 下方向への移動が不可能になってから初めて駒を設置できるため、あらゆる配置が集められます。 次に、再帰的検索により、すべての部分の最終位置のすべての法的な選択が検査されます。 合法的なゲームはスキップされず、シミュレートされたすべてのゲームが正しくスコア付けされるため、見つかった最大値が最適なスコアになります。 

## Python ソリューション```python
import sys
from functools import lru_cache

input = sys.stdin.readline

pieces = {
    'I': [(0, 1), (1, 1), (2, 1), (3, 1)],
    'O': [(1, 0), (2, 0), (1, 1), (2, 1)],
    'T': [(1, 0), (0, 1), (1, 1), (2, 1)],
    'L': [(0, 0), (0, 1), (0, 2), (1, 2)],
    'J': [(1, 0), (1, 1), (1, 2), (0, 2)],
    'S': [(1, 0), (2, 0), (0, 1), (1, 1)],
    'Z': [(0, 0), (1, 0), (1, 1), (2, 1)],
}

def rotate(shape):
    res = []
    for x, y in shape:
        res.append((3 - y, x))
    minx = min(x for x, y in res)
    miny = min(y for x, y in res)
    return [(x - minx, y - miny) for x, y in res]

rots = {}
for c, s in pieces.items():
    cur = s
    arr = []
    for _ in range(4):
        if cur not in arr:
            arr.append(cur)
        cur = rotate(cur)
    rots[c] = arr

def solve():
    n = int(input())
    seq = input().strip()

    board = [0] * 12
    lines = [input().strip() for _ in range(8)]
    for i, line in enumerate(lines):
        r = 7 - i
        for j, c in enumerate(line):
            if c == '#':
                board[r] |= 1 << j

    def valid(shape, x, y, b):
        for dx, dy in shape:
            nx = x + dx
            ny = y - dy
            if nx < 0 or nx >= 6 or ny < 0 or ny >= 12:
                return False
            if b[ny] & (1 << nx):
                return False
        return True

    def place(shape, x, y, b):
        nb = b[:]
        for dx, dy in shape:
            nb[y - dy] |= 1 << (x + dx)

        removed = 0
        keep = []
        for row in nb:
            if row == 63:
                removed += 1
            else:
                keep.append(row)

        while len(keep) < 12:
            keep.append(0)

        return keep, removed * (removed + 1) * 50

    def landings(piece, b):
        ans = set()
        q = [(0, 11, 0)]
        seen = {(0, 11, 0)}
        head = 0
        while head < len(q):
            x, y, r = q[head]
            head += 1
            shape = rots[piece][r]

            down = (x, y - 1, r)
            can_down = valid(shape, x, y - 1, b)
            if not can_down:
                if all(y - dy < 8 for dx, dy in shape):
                    ans.add((x, y, r))

            nxt = []
            for nx, ny, nr in [
                (x - 1, y, r),
                (x + 1, y, r),
                (x, y - 1, r),
                (x, y, (r + 1) % len(rots[piece])),
                (x, y, (r - 1) % len(rots[piece]))
            ]:
                if (nx, ny, nr) not in seen:
                    if valid(rots[piece][nr], nx, ny, b):
                        seen.add((nx, ny, nr))
                        q.append((nx, ny, nr))
        return ans

    @lru_cache(None)
    def dfs(idx, state):
        b = list(state)
        if idx == n:
            return 0

        best = 0
        piece = seq[idx]

        for x, y, r in landings(piece, b):
            nb, gain = place(rots[piece][r], x, y, b)
            best = max(best, gain + dfs(idx + 1, tuple(nb)))

        return best

    print(dfs(0, tuple(board)))

solve()
```ボードの表現は主な実装の詳細です。 各行は 6 ビットの整数であるため、ピースが行と衝突するかどうかを確認するには、数ビットの操作だけが必要です。 内部行の番号付けは最下位の 0 から始まり、重力に自然に一致します。 

BFS は、最終的な座標をチェックするだけではなく、元のゲーム ルールを使用します。 これにより、到達不可能な回転を受け入れることがなくなります。 スポーン原点は一番上の余分な行にあるため、初期状態では行 11 が使用されます。 

行クリア コードは、すべての行全体を一度に削除します。 削除後は、クリアされた行より上の行が下に落ちるため、空の行が先頭に追加されます。 

Python の整数は、最大スコアがその制限に比べて小さいため、ここではオーバーフローしません。 メモ化キーは、既に使用されたピースの数ごとに完全なボードを保存し、同じ未来につながる異なる履歴をマージします。

 ## 特殊なケース

 最初のエッジ ケースは、到達不能な回転です。 ピースは最終位置に適合する方向を持っている可能性がありますが、必要な回転移動が回転中に衝突する可能性があります。 BFS はすべての中間状態をチェックするため、そのような不正な配置は決して生成されません。 

2 番目のエッジ ケースは、複数の同時行クリアです。 プレースメントが一度に 2 行を埋める場合、スコアはその 1 つのイベントで削除された行数から計算されます。 クリア関数はシフトする前にすべての行をカウントするため、必要な三角スコアが生成されます。 

3 番目の特殊なケースは、追加の行です。 駒は落下中に一時的にそれらの列を占有することができますが、そこに配置することはできません。 配置チェックでは、占有されているすべてのセルが 8 個未満の内部行を持つことを要求し、無効な最終状態を防ぎます。
