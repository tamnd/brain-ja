 ## 解決策
 ## 問題の理解

 各ノードが個別の重みを持つツリーが与えられます。 目的地ノードが 2 つのノード間の一意の単純なパスに沿った最大重みノードである場合、サルは任意の開始ノードから別のノードにジャンプできます。 各ジャンプの後、プロセスは新しいノードから続行され、考えられるすべての開始ノードから開始して、個別のノードをいくつ訪問できるかを知りたいと考えます。 

主な問題は、ジャンプが許可されるかどうかが、ローカルな隣接関係だけでなく、パスに沿ったグローバル情報に依存することです。 直接の解釈は、ノード u から任意のノード v にジャンプでき、その場合、u から v へのパス上のどのノードも a[v] よりも大きな重みを持たない、つまり a[v] がそのパスを支配することになります。 

入力はツリーであるため、ノードのすべてのペアには一意のパスがあります。 すべてのノード k について、k から開始して有効なジャンプを繰り返した場合に到達可能なノードの数を計算する必要があります。 

制約は大きく、すべてのテスト ケースにわたるノードの合計数は最大 8 × 10^5 です。 これにより、パス クエリを使用して開始ノードごとに独立してジャンプをシミュレートしようとするソリューションは即座に除外されます。 テスト ケースごとの二次関数や、ノードごとに O(n log n) であっても遅すぎます。 ほぼ線形または線形算術的なグローバル構造が必要です。 

微妙な問題は、到達可能性が対称的ではなく、明らかに単調ではないことです。 重みの高いノードは、多くのノードをそのノードに「引き寄せる」ことができますが、中間の最大値が介入すると、パスの状態によって動きがブロックされる可能性があります。 

単純な間違いは、ノードから常に隣接ノードまたはより重みの高いノードにジャンプできると想定することです。 たとえば、重みが 3、1、2 のライン 1-2-3 を考えてみましょう。パス 2-1-3 に沿った最大値は 3 であるため、ノード 2 から 3 にジャンプすることはできませんが、正しい構造を考慮しない限り、パス 2-1-3 はツリーの意味で単純ではありません。また、その場合でも、条件は隣接性や順序付けではなく完全なパスの最大値に依存します。 これは、ローカルの貪欲な推論が失敗していることを示しています。 

## アプローチ

 ブルートフォース解釈は簡単です。 各開始ノード k について、到達可能なすべてのジャンプをシミュレートしようとします。 現在のノード u から、考えられるすべてのターゲット v を考慮し、v へのパス u 上の最大値が a[v] に等しいかどうかを確認します。 そうであれば、v は到達可能です。 これ以上ノードを追加できなくなるまで、新しく到達したノードから拡張を続けます。 

各ペア (u, v) のパス最大値のチェックは O(log n) の LCA で実行できるため、単一の到達可能性拡張は最悪の場合でもすでに O(n^2 log n) になります。 この展開は開始ノードごとに繰り返されるため、密な探索シナリオでは合計は O(n^3 log n) になりますが、n が 10^5 までの場合、これはまったく実行不可能です。 

重要な構造的洞察は、「a[v] がパス u から v までの最大値である」という条件は、すべてのエッジを低い重みから高い重みの方向に向けると、パス上の最大値がバリアのように機能するパスによって動きが制限される、ということと同じであるということです。 任意のパス クエリの観点から考えるのではなく、上位ノードが下位ノード間の接続を「制御」する構造を探索するものとしてプロセスを再構成します。 

これを正確に行う標準的な方法は、重みの昇順にノードを処理し、徐々にノードを追加し、エッジを介してすでにアクティブなコンポーネントに接続する動的フォレストを維持することです。 ノードをアクティブ化するたびに、そのノードをすでにアクティブ化されている隣接ノードとマージします。 これにより、最大制約の増加によって接続が制御される構造が構築されます。 

到達可能性の質問に答えるために、視点を逆にします。固定ノード k の場合、このプロセスは、動的に構築されたフォレスト内の接続パス上の最も重みの高いノードとして k に関連付けられるノードの数を数えるのと同じです。 これは、単調なアクティブ化プロセスの下でコンポーネントを維持することになり、DSU のような構造を使用して追跡できます。

重要な観察は、ノードが重みの昇順にアクティブ化されると、各ノードがすでにアクティブ化されている隣接ノードに接続し、その結果生じる構造が、各コンポーネントが明確に定義された最大値を持つマージのツリーを形成することです。 ノードの答えは、このプロセスで到達できる最も重みの高いノードが「所有」するコンポーネントのサイズに対応します。 

これにより、union-find スタイルのソリューションが得られますが、順序付けには注意が必要です。アクティベーションをシミュレートし、コンポーネントのサイズを維持します。

 ## アルゴリズムのチュートリアル

 重みの昇順にノードを処理します。 このプロセス中に、ノードを徐々に「アクティブ化」し、すでにアクティブな隣接ノードに接続します。 

1. すべてのノードを重みで昇順に並べ替えます。 これは、ノードが移動可能になる順序を定義します。 この順序の理由は、有効なパス制約は最大値によって決定されるため、高い重みがエンドポイントとして機能する前に、低い重みを最初に導入する必要があるためです。 
2. 最初はすべてのノードが非アクティブで独自のセット内にある状態で、ノード全体にわたって素のセット共用体構造を維持します。 
3. 重みでソートされた順序でノードを反復します。 ノード u を処理するときは、そのノードをアクティブとしてマークします。 この時点で、u は、u が関与する将来のパスの現在の最大候補になります。 
4. u の近隣 v ごとに、v がすでにアクティブな場合、u と v を含む DSU セットをマージします。これにより、すべての中間ノードが現在の重みレベル以下であるため、パス最大制約に違反することなく相互に到達可能な領域が接続されます。 
5. u をすべてのアクティブな近傍とマージした後、u が属する連結コンポーネントのサイズを記録します。 このサイズは、有効なジャンプ シーケンスの制御最大値として u を介して到達できるノードの数を表します。 
6. このコンポーネント サイズをノード u の答えとして保存します。 

### なぜ効果があるのか

 アクティブ化プロセスのどの時点でも、すべてのアクティブなノードの重みは現在のノード以下です。 完全にアクティブ ノード内にあるパスの最大値は、それらのノードの 1 つと等しくなります。昇順に処理するため、DSU コンポーネントは、パス制約を満たすために未処理のより重みの高いノードが必要ない最大領域を表します。 各結合は、ジャンプをブロックするより高い中間最大値を導入することなく、到達可能性の有効な拡張に正確に対応します。 重みは個別であり、アクティベーションは単調であるため、各コンポーネントのサイズはノードが処理される時点で固定され、後で上位ノードが下位ノードの到達可能性を遡って変更することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        adj = [[] for _ in range(n)]
        for _ in range(n - 1):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            adj[u].append(v)
            adj[v].append(u)

        a = list(map(int, input().split()))

        order = sorted(range(n), key=lambda x: a[x])

        parent = list(range(n))
        size = [1] * n
        active = [False] * n
        ans = [0] * n

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(x, y):
            x = find(x)
            y = find(y)
            if x == y:
                return
            if size[x] < size[y]:
                x, y = y, x
            parent[y] = x
            size[x] += size[y]

        for u in order:
            active[u] = True
            for v in adj[u]:
                if active[v]:
                    union(u, v)
            ans[u] = size[find(u)]

        sys.stdout.write("\n".join(map(str, ans)) + "\n")

if __name__ == "__main__":
    solve()
```コードはアクティベーションのアイデアに直接従っています。 隣接リストにはツリー構造が格納されます。 配列`order`ノードが重みの増加順に処理されるようにします。 DSU は、アクティブなノード間でのみ接続されたコンポーネントを維持します。 

の`active`モノトーン構造ではまだ利用できない隣接ノードにノードを接続してはいけないため、配列は不可欠です。 これがないと、現在の最大境界構造では許可されていないノードを介してコンポーネントが誤ってマージされてしまいます。 

各ノードの応答は、DSU コンポーネントのサイズを使用して、アクティブになった瞬間に取得されます。 その瞬間は、すべての許可されたパスに沿った有効な最大値として機能するノードで到達できるノードの完全なセットを正確にキャプチャします。

 ## 特殊なケース

 重要なエッジ ケースは、最も重みの高いノードがツリーの中心にある場合です。 たとえば:

 入力:```
1
5
1 2
2 3
3 4
4 5
3 1 5 2 4
```ここでは、ノード 2 (値 5) が最後にアクティブになり、以前にアクティブだったすべてのノードをチェーンを通じて接続します。 アクティブ化中、より小さなノードは小さなコンポーネントのみを形成しますが、最大のノードがアクティブ化されると、すべてがマージされます。 ユニオンはすでにアクティブなネイバーとのみ実行されるため、DSU はこれを正しくキャプチャし、不正なパスが導入されないようにします。 

もう 1 つのエッジ ケースは、低重みのノードを中心とするスターです。 すべての葉はさまざまな順序で後または前に活性化するため、最初は葉が孤立したままになります。 センターがアクティブになった場合にのみ、複数のコンポーネントとマージされ、コンポーネントのサイズが突然増加します。 マージは対称的であり、構造の仮定ではなくアクティブ化状態のみに依存するため、アルゴリズムはこれを自然に処理します。
