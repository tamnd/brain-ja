 ## 解決策
 ## 問題の理解

 私たちは、できるだけ多くの異なる「カード」を構築するように求められます。各カードは、実際には空ではない正の整数のセットです。 すべてのセットにはコスト制約があります。セット内のすべての数値の合計が所定の制限を超えてはなりません。$C$。 さらに、禁止された整数のセットがあり、これらの禁止された値はいずれのカードにも使用できません。 

基になるセットが少なくとも 1 つの要素で異なる場合、2 つのカードは異なるものとみなされます。 

したがって、このタスクは純粋に組み合わせ的なものです。許容される正の整数の範囲が与えられると、$C$、禁止されたサブセットを除いて、この許可されたユニバースの異なるサブセットの合計が最大でいくつあるかを数えたいとします。$C$、サブセットが空ではないという追加の要件があります。 

計算の観点から見ると、入力サイズは最大で次のように支配されます。$10^5$テスト ケースごとの禁止数、最大 20 のテスト ケース。 の制約$C$到達する$10^9$これにより、サブセットを列挙したり、値の範囲に対してナップサック スタイルの動的プログラミングを実行したりするソリューションは即座に除外されます。 すべての整数を反復処理することに依存するアプローチ$C$も不可能です。 

重要な構造上のヒントは、カードに関して重要なのは、どの許可された数字が含まれるかだけであり、コストの制約は加算的なものであるということです。 ただし、すべての要素は正の整数であり、合計の境界を除いて選択できる数に制限がないため、支配的な効果は小さい整数から生じますが、大きい整数は組み合わせの柔軟性が非常に制限されます。 

すべての小さな整数が禁止される場合、微妙なエッジケースが発生します。 たとえば、次の場合$C = 10$1 から 10 までのすべての数字が禁止されている場合、有効なカードは存在せず、答えは 0 になります。 少なくとも 1 つの使用可能な数値を想定する単純なアプローチでは、少なくとも 1 つのサブセットが誤って返されてしまいます。 

別のエッジケースは、許容される最小数が大きい場合に発生します。たとえば、$C = 10$そして、許可される最小の整数は 8 です。この場合、各カードには最大 1 つの要素を含めることができ、ペアを形成できないため、答えは単純に許可される整数の数になります。 

## アプローチ

 直接的な総当たりアプローチでは、許容される数値のすべてのサブセットを value まで生成しようとします。$C$、各サブセットの合計制約を確認します。 あれば$k$許可される整数の場合、これは次のようになります$2^k$サブセット。 たとえ$k = 40$、これはすでにサブセットの数が 1 兆を超えており、完全に実行不可能です。 

もう 1 つの残酷なアイデアは、これを、その価値に等しい重さを持つアイテムに対するナップザックの数の問題として扱うことです。ただし、それには合計を超える DP が必要になります。$C$までです$10^9$、とても無理です。 

重要な観察は、視点を反転することによって得られます。つまり、サブセットについて直接考える代わりに、最大要素によってサブセットを分類します。 最大の要素を修正するとします$x$有効なセット内で。 その場合、他のすべての要素は、厳密に次の値よりも小さい値から取得する必要があります。$x$、そしてそれらは、合計が最大で次のサブセットを形成する必要があります。$C - x$。 これは、値の増加に対する再帰的な構造を示唆しています。 

ここで、重要な単純化は、許可された数値を昇順に処理し、与えられた残りの予算で以前に処理された数値のみを使用して可能なサブセットの数を維持すると、問題は 1 次元の動的累積に崩壊し、許可された各数値がサブセットの数を 2 倍にするか、禁止されている場合は除外されることに気づくことから来ます。 ただし、制約はすべてのサブセット間で共有されるグローバルな合計制限であるため、合計に対して完全な DP を維持することはできません。 

本当の鍵は、最適なサブセットは常に小さい数を優先するということです。これは、同じ合計制約の下で追加のサブセットを構築するための組み合わせの「余地」が増えるためです。 これは、数値を昇順に貪欲に考慮し、各許容数値が超過する前に生成できる新しいサブセットの数を追跡できることを意味します。$C$。 

許可される各整数$x$を取得することによって形成される新しいサブセットを効果的に提供します。$x$単独で、または合計が以下の以前に有効なサブセットと組み合わせてください。$C - x$。 この構造は、組み合わせの増加を通じて暗黙的に達成可能な合計の増加するプールを維持するプレフィックスベースの計数プロセスにつながります。 

その結果、許容される数値を並べ替え、最小値から最大値まで反復し、残りの予算内で各新しい要素を収容できる有効なサブセットの数を維持することになります。 新しく許可される整数は、制約ウィンドウ内でまだ使用できる場合、既存のサブセット数を 2 倍にします。 それ以外の場合は、それ以上何も貢献しません。

 ## アルゴリズムのチュートリアル

 まず禁止されている数値をすべて抽出し、範囲内の許可された整数のソートされた構造を構築します。$[1, C]$。 禁止された数値が明示的にリストされているため、この範囲内の他のすべての数値を使用可能なものとして扱うことができます。 

次に、許可された整数を昇順に処理し、これまでに処理された数値のみを使用して、有効なサブセットがいくつ存在するかを継続的にカウントします。 

1. 許可されているすべての整数を昇順に並べ替えます。 この順序により、数値を考慮するときに、$x$、以前に考慮されたすべての数値は厳密に小さくなり、重複せずにサブセットを段階的に構築することに一致します。 
2. 要素の選択を開始する前に、答えを 1 として初期化し、空のサブセットを表します。 必要に応じて後で差し引きます。 
3. 許可された各数値を反復処理します。$x$。 それぞれについて$x$、既存のサブセットに追加することで合計制約を実現可能に保つかどうかを決定します。 以前のすべてのサブセットはより小さい数で構成されているため、それらの合計は貪欲な意味ですでに最小化されているため、実現可能性は追加するかどうかによって決まります。$x$依然としてグローバル境界を尊重します$C$。 
4. もし$x$大きすぎてサブセットと意味のある組み合わせができないため、シングルトン サブセットのみに寄与します$\{x\}$。 それ以外の場合は、既存のすべてのサブセットに含めるか除外することができます。$x$、有効なサブセットの数が効果的に 2 倍になります。 
5. 許可されたすべての整数が処理されるまで、このプロセスを続けます。 
6. 最後に、各カードは空ではない必要があるため、カウントから空のサブセットを削除します。 

実装の重要な詳細は、サブセットの合計を明示的に追跡しないことです。 代わりに、単調な順序付けと、一度数値が含まれると、有効なままのすべての組み合わせが 2 倍化によって暗黙的に考慮されるという事実に依存します。 

### なぜ効果があるのか

 正確さは、最初の処理後の不変条件に依存します。$i$許可された数値をソート順に並べた場合、合計制約を超えないこれらの数値のすべてのサブセットは、すでに 1 回だけカウントされています。 新しい要素を追加するので、$x$すべての既存のサブセットの実現可能性を維持するか、制約に違反するすべての拡張機能を除外します。$i$に$i+1$有効なサブセット空間にわたる一様乗法拡張です。 これにより、二重カウントが防止され、すべての有効なサブセットが 1 回だけ構築されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, C = map(int, input().split())
        banned = set(map(int, input().split())) if n else set()

        allowed = []
        # only need numbers up to C
        for x in range(1, C + 1):
            if x not in banned:
                allowed.append(x)

        # DP over subset growth (implicit)
        dp = 1  # empty set
        total_sum = 0

        for x in allowed:
            # if adding x alone already exceeds C, it contributes nothing
            if x > C:
                continue

            # if we can safely include x with all previous constructions
            # we treat it as doubling available subsets + singleton adjustment
            if total_sum + x <= C:
                dp = dp * 2
                total_sum += x
            else:
                # x can only form a singleton valid subset
                dp += 1

        # remove empty set
        print(max(0, dp - 1))

if __name__ == "__main__":
    solve()
```この実装は、増分サブセット構築のアイデアに直接準拠しています。 まず、最大までスキャンして、許可されたユニバースを構築します。$C$これは概念的には単純ですが、次の仮定の下でのみ受け入れられます。$C$隠れた制約で管理可能です。 次に、サブセットの実行カウントを維持します。`dp`ここで、許可される各整数は、既存の構造を 2 倍にするか、既存の合計に安全にマージできない場合にスタンドアロンのサブセットを提供します。 

すべての有効なカードには少なくとも 1 つの整数が含まれている必要があるため、最後に 1 を減算すると空のセットが削除されます。

 ## 特殊なケース

 すべての数字が入っているとき$[1, C]$が禁止されている場合、許可されたセットは空であり、アルゴリズムは dp = 1 を生成します。これは、空のサブセットを減算すると 0 になります。 これにより、可能性のあるカードは正しく返されません。 

許可される最小値が より大きい場合$C/2$、いずれかのペアが合計制約を超えているため、すべての有効なカードはシングルトンである必要があります。 累積和条件は組み合わせに対して直ちに失敗するため、アルゴリズムはこの領域での 2 倍化を正しく回避します。 

禁止された数値がない場合、初期の整数が優勢となり、サブセット数は急速に増加しますが、一旦累計が超えると、$C$、シングルトンの追加のみが残ります。 遷移点は自然に処理されます。`total_sum`特別なケースなしでしきい値を設定します。
