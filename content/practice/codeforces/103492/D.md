 ## 解決策
 ## 問題の理解

 正の整数 x が与えられ、その周囲の素数を使用して値を構築します。 まず、f(x) を厳密に x より大きい最小の素数として定義します。したがって、これは x の次の素数になります。 次に、同じ考えを f(x) に再度適用して、f(f(x)) を与えます。これは、単に次の素数の後の素数です。 

これら 2 つの素数から、それらの平均を取ることによって数値 g(x) を形成します。つまり、それらを加算して 2 で割ります。タスクは、結果として得られる数値 g(x) 自体が素数であるかどうかを判断することです。 

入力は最大 100,000 の独立したクエリで構成され、各 x は 10^18 までの大きさになります。 これにより、素数性をテストしたり、クエリごとに x の周囲の素数を個別に検索したりするアプローチが即座に除外されます。 どのソリューションでも、テスト ケースごとに大きな素数を実際に計算することは避けなければなりません。 

非常に小さな値では、微妙なエッジケースが現れます。 x = 1 の場合、次の素数は 2 と 3 であるため、g(x) は素数である 2 になります。 x = 2 の場合、次の素数は 3 と 5 であるため、g(x) は 4 になり、これは素数ではありません。 これらの小さな入力は、答えが x の大きさではなく、最初のいくつかの素数の構造のみに依存する可能性があることをすでに示唆しています。 

主な問題は、x が非常に大きくなる可能性があるため、推論は明示的な値ではなく、連続する素数の特性に依存する必要があることです。 

## アプローチ

 g(x) を評価する最も直接的な方法は、素数が見つかるまで上向きに検索して f(x) を計算し、次に同じ方法で f(f(x)) を計算し、最後にそれらの平均が素数かどうかを確認することです。 これは定義上は正しいですが、すぐに計算上の限界に達します。 10^18 までの x の場合、次の素数を見つけるには、高度な素数テストが必要になり、潜在的に大きなギャップをスキャンする必要があり、これを 100,000 クエリに対して実行するのは不可能になります。 

重要な観察は、実際には素数の数値は気にしておらず、素数の構造的関係だけを気にしているということです。 p1 = f(x) および p2 = f(f(x)) とします。 これらは連続する素数です。 値 g(x) は、単に 2 つの連続する素数間の中間点です。 

ここで、より単純な構造的な質問をします。連続する 2 つの素数の中点自体が素数になることはありますか? このような中点 m が素数の場合、p1 < m < p2 となり、連続する 2 つの素数の間に厳密に素数が存在することになります。 これは、間隔が極端に小さい場合を除き、連続性の定義に矛盾します。 唯一の例外は素数シーケンスの先頭で発生し、連続する素数 2 と 3 には中点 2 があります。 

したがって、問題全体は、連続する素数のペアが (2, 3) であるかどうかをチェックすることに集約されます。これは、x が十分に小さく、次の素数が 2 になる場合にのみ発生します。

 ## アルゴリズムのチュートリアル

 1. 各 x について、x の後の次の素数が 2 であるかどうかを判断します。2 が最小の素数であり、2 より小さい正の整数には異なる次の素数がないため、これは x = 1 の場合にのみ発生します。 
2. x = 1 の場合、連続する素数は 2 と 3 であるとすぐに識別されるため、中点は 2 (素数) になります。 
3. x ≥ 2 の場合、次の素数 f(x) は少なくとも 3 であり、次の素数 f(f(x)) は少なくとも 5 であり、連続する奇数素数を形成します。 
4. (2, 3) より大きい 2 つの連続する奇数素数の中点は、厳密に 2 つの連続する素数の間に位置するため、素数になることはできません。これは、そのうちの 1 つと等しくない限り不可能です。 
5. x = 1 の場合のみ YES を出力し、それ以外の場合は NO を出力します。 

### なぜ効果があるのか

p1 = f(x) および p2 = f(f(x)) とします。 これらは連続する素数です。 g(x) = (p1 + p2) / 2 が素数であるとします。 したがって、g(x) は厳密に p1 と p2 の間にあります。 これは、連続する 2 つの素数の間に素数が存在することを意味し、その定義に矛盾します。 この推論が破綻する唯一のケースは、間隔が 2 と 3 で始まる場合であり、ギャップが最小であるために中間点が動作的に 1 つのエンドポイントと一致します。 したがって、x = 1 だけが生き残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        x = int(input())
        if x == 1:
            out.append("YES")
        else:
            out.append("NO")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装は、主要な推論全体が単一の構造的条件に崩壊することを反映しています。 関数 f(x) と 2 番目の素数 f(f(x)) は、明示的に計算されることはありません。これらの唯一の関連する特性は、それらが連続する素数を形成することであるためです。 この決定は、これらの素数が (2, 3) (x = 1 に正確に対応する) であるという特殊なケースにあるかどうかを確認することに帰着します。 

すべての x ≥ 2 が同じ構造的結果を生成するため、この条件を超えるエッジ処理は必要ありません。 

## 実用的な例

 ### 例 1: x = 1

 | ステップ | f(x) | f(f(x)) | g(x) |
 | --- | --- | --- | --- |
 | 1 | 2 | 3 | (2 + 3) / 2 = 2 |

 中点は素数である 2 に等しいため、出力は YES になります。 これは、連続する素数が (2, 3) であり、中点を素数にすることができる唯一の構成です。 

### 例 2: x = 2

 | ステップ | f(x) | f(f(x)) | g(x) |
 | --- | --- | --- | --- |
 | 1 | 3 | 5 | (3 + 5) / 2 = 4 |

 結果は 4 (複合値) であるため、出力は NO になります。 これは、素数が 3 以降で始まると、連続する素数の間の中点は素数になることができないという事実を反映しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from sys import stdout
    import sys as _sys

    input = _sys.stdin.readline
    def solve():
        t = int(input())
        out = []
        for _ in range(t):
            x = int(input())
            out.append("YES" if x == 1 else "NO")
        print("\n".join(out))

    old_stdout = sys.stdout
    sys.stdout = io.StringIO()
    solve()
    res = sys.stdout.getvalue().strip()
    sys.stdout = old_stdout
    return res

# minimum input

# small non-trivial

# large value
assert run("1\n1000000000000000000\n") == "NO"

 ## 特殊なケース

 唯一意味のあるエッジ ケースは、素数チェーンが 2 と 3 で始まる x = 1 の場合です。x = 1 の場合、アルゴリズムは直接 YES を出力し、計算された中点 (2 + 3) / 2 = 2 と一致します。 

x ≥ 2 の場合、実行は常に NO 分岐に分類されます。 たとえば、x = 2、f(x) = 3、および f(f(x)) = 5 の場合、中点 4 が得られますが、これは正しく拒否されます。 

決定は大きな素数の算術特性には依存せず、可能な最小の素数構成の同一性にのみ依存するため、それ以上の境界問題は発生しません。
