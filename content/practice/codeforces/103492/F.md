 ## 解決策
 ## 問題の理解

 複数の文字列が与えられているので、文字列ごとに、非常に特殊な構造を形成するサブシーケンスの数を数えなければなりません。 

有効なサブシーケンスは 2 つのフェーズで構築されます。 まず、固定文字列が含まれている必要があります`nunhehheh`順番にサブシーケンスとして。 その後、文字のみで構成される空でないシーケンスを含める必要があります。`a`。 これら`a`文字は連続している必要はありませんが、固定パターンの完了後に後続の順序で出現する必要があります。 

したがって、文字列の場合`S`、実際にインデックスを選択できる方法が何通りあるかを数えています。`i1 < i2 < ... < ik`結果の文字が形成されるように`nunhehheh`少なくとも 1 つが続く`a`。 

主な難点は、部分文字列ではなく部分シーケンスをカウントしているため、文字が任意にスキップされる可能性があり、インデックスの選択が異なると、結果として得られる文字が同じであっても異なるサブシーケンスが生成されることです。 

すべての文字列の合計の長さが到達できる制約`10^6`サブシーケンスを明示的に列挙しようとするアプローチは除外されます。 サブシーケンスに対するブルート フォースの長さは指数関数的になるため、すべてのサブセットに対する動的プログラミングですら不可能です。 非常に小さな定数係数を使用して、文字列ごとに線形または線形に近いスキャンを強制されます。 

微妙なエッジケースは、文字列にパターンが含まれている場合です。`nunhehheh`重複して複数回。 パターンを形成するインデックスの個別の選択は個別にカウントする必要があり、それらの選択はそれぞれ独立してさまざまな選択方法に拡張できます。`a`その後のキャラクターたち。 

もう 1 つのエッジ ケースは、パターンは含まれるが、パターンは含まれない文字列です。`a`その後。 例えば、`nunhehhehbbb`プレフィックス パターンが何度も存在するにもかかわらず、サフィックス要件が満たされていないため、有効なサブシーケンスはゼロです。 

同様に、次のような文字列`aaaaaaaa`には多くのサブシーケンスがあります`a`ただし、完全に満たされない限り何も貢献しません。`nunhehheh`サブシーケンスは以前に存在します。 

## アプローチ

 ブルート フォース アプローチでは、入力文字列のすべてのサブシーケンスを生成し、それぞれがパターンに一致するかどうかを確認しようとします。`nunhehheh`少なくとも 1 つが続く`a`。 次の長さの文字列のため、これはすぐに失敗します。`n`もっている`2^n`後続。 たとえ`n = 40`、これは実行不可能になります、そしてここで`n`できる`10^5`。 

サブシーケンスを明示的に構築する必要がないことを認識することで、問題を軽減できます。 文字列を左から右にスキャンしながら、順番にパターンに一致する方法が何通りあるかを数えるだけで済みます。 これは、古典的な部分列カウントの動的プログラミング構造です。 

まず、次のプレフィックスを一致させる方法が何通りあるのかを追跡します。`nunhehheh`。 パターンが完了したら、次のフェーズに入ります。そこでは、空ではない部分列を選択できる方法が何通りあるかを数えます。`a`後から登場するキャラクターたち。 

重要な観察は、パターン部分とサフィックス部分は 2 つの DP フェーズに分離できるが、慎重に相互作用する必要があるということです。 完了したすべての試合`nunhehheh`後で収集できる「ソース」になる`a`さまざまな意味でのキャラクター。 それぞれ`a`サフィックスを開始するか、既存のサフィックスの組み合わせを 2 倍にします。 

ブルート フォースはすべてを列挙するため概念的には機能しますが、指数関数的な爆発により失敗します。 DP が機能するのは、すべての文字で、固定パターンとサフィックス状態の部分一致のカウントのみを維持するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブシーケンス | O(2^n) | O(n) | 遅すぎる |
 | パターン + サフィックス上の DP 状態 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 パターンを定義します`P = "nunhehheh"`長さは 9 です。文字列のスキャン中に 2 種類の状態を維持します。 

1 つの状態は、次のプレフィックスに一致するサブシーケンスの数をカウントします。`P`。 2 番目の状態では、完了した一致をカウントします。`P`すでに少なくとも 1 つの収集を開始している`a`。 

また、各文字がサブシーケンス数を拡張するために使用されるかスキップされるように、トランジションを慎重に処理する必要があります。 

1. DP 配列を初期化する`dp`サイズ 10 の場合`dp[j]`最初のものと一致する方法の数を表します`j`パターンの文字`P`。 セット`dp[0] = 1`なぜなら、空のプレフィックスを照合する方法は 1 つだけだからです。 
2. 別の変数を初期化する`dpA = 0`これは、すでに少なくとも 1 つが選択されている、完了したパターン マッチの数を表します。`a`。 
3. 文字列を左から右にスキャンします。 キャラクターごとに`c`、まず、各文字がサブシーケンス拡張ごとに最大 1 回使用されるように、パターン DP を逆の順序で更新します。 それぞれについて`j`8 から 0 まで下げる場合`c == P[j]`を追加します。`dp[j]`の中へ`dp[j+1]`。 

このステップにより、短いプレフィックスに必要な状態を上書きすることなく、パターンの部分一致を拡張するすべての方法を正しくカウントできるようになります。 
4. 現在のキャラクターがそうでない場合`a`、影響しません`dpA`そして続けます。 
5. キャラクターが`a`、接尾辞の遷移を処理します。 完成したすべてのパターンが一致します`dp[9]`新しいサフィックスを開始することも、既存のサフィックスの選択肢を拡張することもできます。 それで更新します`dpA = 2 * dpA + dp[9]`。 

2 を掛けることは、これを選択するか選択しないかのどちらかに対応します。`a`すでにアクティブなすべての接尾辞サブシーケンスに対して。 の追加`dp[9]`完了したパターン一致から新しいサフィックス サブシーケンスを開始することに対応します。 
6. すべての文字を処理すると、答えは次のようになります。`dpA`。 

正しさは、接尾語フェーズに入ると、さらにすべてが完了するという事実に依存します。`a`文字は、アクティブな完成パターン インスタンスごとに独立した 2 値の選択肢です。 

### なぜ効果があるのか

 プレフィックス上の DP は、次の不変式を維持します。`dp[j]`最初のプレフィックスと正確に一致する、処理されたプレフィックスのサブシーケンスを常にカウントします。`j`の登場人物`P`。 逆の更新順序により、同じステップ内で再利用することなく、各文字が正しく寄与することが保証されます。 

サブシーケンスが到達すると`dp[9]`、完成したパターンインスタンスになります。 その瞬間から、その後のすべての`a`無視されるか、サブシーケンスに含まれます。 これにより、アクティブな完了インスタンスごとに二重構造が作成され、新しい完了インスタンスはサフィックス DP に新しい開始点を提供します。 プレフィックスのカウントとサフィックスの累積を分離することで、二重カウントや組み合わせの欠落がなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

PAT = "nunhehheh"

t = int(input())
for _ in range(t):
    s = input().strip()

    dp = [0] * 10
    dp[0] = 1
    dpA = 0

    for ch in s:
        for j in range(8, -1, -1):
            if ch == PAT[j]:
                dp[j + 1] = (dp[j + 1] + dp[j]) % MOD

        if ch == 'a':
            dpA = (dpA * 2 + dp[9]) % MOD

    print(dpA % MOD)
```この実装は DP 定式化を直接反映しています。 順方向に更新すると、同じ遷移ステップで 1 つの文字を複数回使用できるようになるため、パターン状態に対する逆ループは非常に重要です。 

変数`dpA`に遭遇した場合にのみ更新されます`a`、なぜなら、`a`接尾辞の構築に貢献します。 用語`dp[9]`新しく完了したパターン マッチをサフィックス状態に挿入します。

## テストケース```python
import sys, io

MOD = 998244353

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    PAT = "nunhehheh"
    t = int(input())
    out = []

    for _ in range(t):
        s = input().strip()

        dp = [0] * 10
        dp[0] = 1
        dpA = 0

        for ch in s:
            for j in range(8, -1, -1):
                if ch == PAT[j]:
                    dp[j + 1] += dp[j]
                if ch == 'a':
                    dpA = dpA * 2 + dp[9]

        out.append(str(dpA % MOD))

    return "\n".join(out)

 ## 特殊なケース

 最初のエッジ ケースは、複数の重複した発生が発生する場合です。`nunhehheh`同じ文字列内に存在します。 それぞれの出現が個別の充填方法に対応しているため、DP では当然それらすべてがカウントされます。`dp[9]`、そしてそれぞれが接尾辞の形成に別々に貢献します。 アルゴリズムはこれを処理します。`dp[9]`はブール値の状態ではなくカウントです。 

2 番目のエッジ ケースは、文字列に何も含まれない場合です。`a`全然。 何度もパターンを形成しても、`dpA`決して遷移しないので、答えはゼロのままです。 これにより、サフィックスが空であってはならないという要件が正しく適用されます。 

3 番目のエッジケースは、長期にわたる実行です。`a`パターンが完成する前に。 これらは何もしません。`dp[9]`はまだゼロであるため、接尾辞の累積にはソースがありません。 少なくとも 1 回完全なパターンが一致した後でのみサフィックスのカウントが開始され、インターリーブの正確性が維持されます。
