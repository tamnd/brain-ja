 ## 解決策
 ## 問題の理解

 n 個のタイルが配置された円形のボードが与えられます。各タイルは、それを踏むと固定の整数値を与えます。 最初のタイルの前からタイル 1 から開始し、タイル 2、次にタイル 3 というように決定的に移動し、n の後で 1 に戻ります。 タイルに着地するたびに、その値がランニング スコアに追加され、増減する可能性があります。 

各クエリは、訪問したタイルの累積合計が目標値 x と正確に等しくなるように、必要な最小ステップ数を要求します。 「ステップ」とはタイルに着地することを意味するため、k ステップ後、この無限周期ウォークで長さ k の接頭辞を訪問したことになります。 

重要な観察は、n ステップの後、配列の完全な 1 サイクルが正確に完了するため、すべての完全なサイクルが同じ合計 S = a1 + a2 + ... + an に寄与するということです。 k ステップ後のスコアは、全サイクルと次のサイクルのプレフィックスの合計になります。 

制約は大きく、n と m はテスト ケースごとに最大 100,000、合計は最大 500,000 になります。 これにより、ステップや単純なプレフィックス スキャンに対するクエリごとのシミュレーションが除外されます。 クエリごとに線形なソリューションは、最悪の場合、約 10^10 の演算を超えますが、これは制限をはるかに超えています。 クエリごとに線形または線形に近い時間、および対数または定数時間での前処理が必要です。 

合計サイクル合計 S がゼロの場合、微妙なエッジ ケースが発生します。 この場合、サイクルを繰り返してもスコアは変化しないため、重要なのはプレフィックスの合計だけです。 S がゼロ以外の場合、完全なサイクル数を選択することでスコアを調整できますが、残りはプレフィックスの合計と正確に一致する必要があります。 もう 1 つのエッジ ケースは負のターゲットです。値が減少する可能性があるため、明示的に追跡しない限り、プレフィックスの合計は有用な方法で単調になりません。 

## アプローチ

 ブルートフォース戦略は簡単です。 各クエリ x について、配列の無限の繰り返しに沿ってステップごとに歩くことをシミュレートし、x に達するか妥当な限界を超えるまで累計を維持します。 最悪の場合、特に S が小さいかゼロの場合、回答には多くの完全なサイクルが必要になる可能性があるため、クエリごとに最大 O(n * 回答サイクル) のスキャンに陥る可能性があります。 m が 10^5 までなので、これは明らかに実行不可能です。 

重要な構造的洞察は、無限ウォーク内のすべての位置が、k 個の完全なサイクルと基本配列のプレフィックスとして記述できることです。 接頭辞の合計 P[i] = a1 + ... + ai と合計の合計 S = P[n] を定義すると、t ステップ後に次のようになります。 

スコア(t) = k * S + P[r]、ここで、t = k * n + r、0 ≤ r < n。 

したがって、問題は、x がこの形式で記述できるかどうか、およびすべての有効な分解の中で最小の t を見つけることができるかどうかを尋ねることに帰着します。 

各プレフィックス値 P[r] について、x - P[r] が S で割り切れ、商 k が負でないような整数 k を選択できるかどうかを確認します。 S = 0 の場合、サイクルによって合計が変化しないため、条件は x = P[r] に縮退します。 

すべてのプレフィックスの合計を事前計算し、オプションで各プレフィックス値の最小インデックス r を保存します。 その後、各クエリはすべての候補をチェックし、実現可能性を評価することになります。 n が大きいため、クエリごとにすべての r を繰り返すのは遅すぎるため、代わりにプレフィックスの合計をグループ化し、各値の最も古い出現のみを保持します。 これが機能するのは、r が早いほど、同じサイクル数に対して常に小さい t が与えられるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(m · n · サイクル) | お(1) | 遅すぎる |
 | プレフィックス + モジュラー分解 | O(n + m · d) ここで、 d = 個別のプレフィックス状態 | O(n) | 承認済み |

 実際の最適化は、各プレフィックス合計の最初の出現のみが重要であることを認識し、プレフィックス値のハッシュ マップを前処理した後に各クエリを定数時間演算に減らすことです。 

## アルゴリズムのチュートリアル

 ## 前処理

 1. 配列を左から右に 1 回スキャンしながら、プレフィックスの合計 P[i] を計算します。 

総和 S = P[n] も記録します。

このステップでは、考えられるすべての部分サイクル寄与をエンコードします。 
2. bestPos[v] に P[i] = v となる最小のインデックス i が格納される辞書 bestPos を構築します。 

最も古いインデックスのみを保持します。これは、そのプレフィックス値に対して最小のステップ数が得られるためです。 

## クエリ処理

 1. S がゼロの場合、サイクルを繰り返してもスコアは変わりません。 クエリ x については、x が bestPos に存在するかどうかを確認します。 そうであれば、答えは bestPos[x] ですが、そうでない場合は不可能です。 
2. S がゼロ以外の場合、bestPos に格納されているすべてのプレフィックス合計 v を反復処理します。 
3. 各プレフィックス合計 v について、差デルタ = x - v を計算します。 
4. デルタが S で割り切れるかどうかを確認します。割り切れない場合、このプレフィックスは x につながりません。 
5. 割り切れる場合は、k = delta // S を計算します。 
6. 完全なサイクルを負の数にすることはできないため、k ≥ 0 のみを考慮します。 
7. 答えの候補は k * n + bestPos[v] です。 すべての有効な候補者の最小値を追跡します。 

## なぜ機能するのか

 到達可能なすべての状態は、完全なサイクル数に次のサイクルのプレフィックスを加えたものに正確に対応します。 プレフィックスの合計によってサイクル内の部分的な寄与が一意に決まり、完全なサイクルの数によって n の倍数のステップでどれだけ進んだかが決まります。 すべてのプレフィックス合計は最も古いインデックスで記録されるため、常にそのプレフィックス コンポーネントの最小ステップ数を選択します。 可分性条件により、ターゲットとサイクル寄与の間の一貫性が確保され、k を非負に制限することで、時間的にのみ前進することが保証されます。 これにより、有効なウォークのすべての可能な分解が網羅されるため、すべての有効な候補の最小値が正しい答えになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    prefix = [0] * (n + 1)
    best = {}

    for i in range(1, n + 1):
        prefix[i] = prefix[i - 1] + a[i - 1]
        if prefix[i] not in best:
            best[prefix[i]] = i

    S = prefix[n]

    for _ in range(m):
        x = int(input())

        if S == 0:
            if x in best:
                print(best[x])
            else:
                print(-1)
            continue

        ans = 10**30

        for v, idx in best.items():
            delta = x - v
            if delta % S != 0:
                continue
            k = delta // S
            if k < 0:
                continue
            ans = min(ans, k * n + idx)

        print(-1 if ans == 10**30 else ans)

if __name__ == "__main__":
    solve()
```コードは最初にプレフィックスの合計を構築し、各値の最初の出現のみを保存します。 この削減により、二次関数の動作が妨げられます。 総和 S を抽出して、サイクルの繰り返しが到達可能性に影響を与えるかどうかを判断します。 

各クエリは、すべての個別のプレフィックス合計値をテストすることによって処理されます。 算術チェックによりターゲットとサイクル構造間の互換性が強制され、最小ステップ式は完全なサイクルとプレフィックスへの分解を直接反映します。 

よくある落とし穴は、S = 0 の場合を忘れることです。 それを分離しないと、除算とモジュラー論理が破綻します。 もう 1 つの微妙な点は、各プレフィックスの合計がすべて出現するのではなく、最初に出現したものを使用することです。これにより、ステップ数が最小限に抑えられます。 

## 実用的な例

 配列 [1, -3, 4] について考えてみましょう。 プレフィックスの合計は P = [1, -2, 2]、合計合計 S = 2 です。 

クエリ x = 3:

 | 接頭辞 v | いずみ | デルタ = x - v | デルタ%S | k | ステップ = k・n + idx |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | 0 | 1 | 1・3 + 1 = 4 |
 | -2 | 2 | 5 | 1 | - | 無効 |
 | 2 | 3 | 1 | 1 | - | 無効 |

 最小は 4 ステップです。 

これは、異なるプレフィックス アライメントが異なるサイクル カウントにどのように対応するか、および 1 つの組み合わせだけが有効な分解を生成することを示しています。 

ここで、x = 1 について考えてみましょう。 

| 接頭辞 v | いずみ | デルタ | デルタ%S | k | ステップ |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 0 | 0 | 0 | 1 |
 | -2 | 2 | 3 | 1 | - | 無効 |
 | 2 | 3 | -1 | -1 モッド 2 | - | 無効 |

 答えは 1 ステップで、最初のタイルですぐに達成されます。 

これらの例は、分解が初期寄与と循環寄与の両方に正しく一致することを確認します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        prefix = [0] * (n + 1)
        best = {}

            prefix[i] = prefix[i - 1] + a[i - 1]
            if prefix[i] not in best:
                best[prefix[i]] = i

        for _ in range(m):
            x = int(input())
            if S == 0:
                print(best.get(x, -1))

                    continue
                k = delta // S

                    continue
                ans = min(ans, k * n + idx)

            print(-1 if ans == 10**30 else ans)

    out = io.StringIO()
    sys.stdout = out
    solve()
    return out.getvalue().strip()

 ## 特殊なケース

 すべての値が 0 の場合、どのステップ数を実行してもスコアは変わりません。 どのクエリ x についても、ステップ 0 で到達できるのは x = 0 だけであり、他のすべてのターゲットは不可能です。 アルゴリズムは、S = 0 を検出し、プレフィックスの存在を最大限にチェックすることで、これを正しく処理します。 

配列に負の値のみが含まれている場合、プレフィックスの合計は厳密に減少しますが、サイクルの繰り返しにより、構造に応じてより多くの負のターゲット、またはさらに正のターゲットに到達することができます。 S を使用したモジュラー条件により、一貫した分解のみが受け入れられることが保証され、最も早いプレフィックス インデックスによって最小限のステップが保証されます。 

n = 1 の場合、プレフィックス構造は単一の繰り返し値に折りたたまれます。 このアルゴリズムは、ステップ数が乗数と等しい、x がその値の倍数であるかどうかをチェックするものであり、直接シミュレーションと一致します。 

x が全サイクルの合計に等しい場合、正解は正確に n ステップであり、アルゴリズムは v = 0 (最初の要素の前の暗黙的なプレフィックス) と k = 1 の組み合わせを通じてこれを取得します。
