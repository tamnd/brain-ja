 ## 解決策
 ## 問題の理解

 長さ n の完全な置換シーケンスと呼ばれる構造が与えられます。これは、1 から n までの数値のすべての置換を辞書順に 1 回だけリストし、それらを単一の長い配列に連結することによって形成されます。 したがって、1 つの順列を扱う代わりに、すべての順列を連続して含むシーケンスを扱うことになります。 

固定 m の場合、サイズ m のすべての順列を調べます。 このような順列 t ごとに、完全なシーケンスのうち t に正確に等しい連続する部分配列がいくつあるかを数えたいと思います。 最後に、サイズ m のすべての順列 t にわたるこのカウントを合計します。 

したがって、タスクは、順序に関係なく、巨大な連結シーケンス内の長さ m のウィンドウが 1 から m の順列を形成する個数を数えることです。 

入力には複数のテスト ケースが含まれており、各テスト ケースには n と m が与えられます。 答えは非常に大きくなる可能性があるため、すべては 1e9 + 7 を法として計算されます。 

完全なシーケンスには n! ブロックであり、各ブロックは長さ n の順列です。 辞書編集的な順序について言及されていますが、それは各ブロックの内部構造には影響せず、ブロックの順序にのみ影響します。 

この制約により、n は最大 10^6 および最大 10^5 のテスト ケースが許可されるため、順列を反復したり、シーケンスを構築したりするソリューションは不可能です。 十分に事前計算しない限り、テスト ケースあたり O(n) であっても遅すぎます。 閉じた形式の式が必要です。 

シーケンス自体の長さが n * n! と天文学的に長いため、単純な解釈ではすぐに問題が発生します。 

m = 1 の場合、微妙なエッジ ケースが現れます。その後、シーケンス全体で各値が何回出現するかを数えます。 すべての順列には 1 から n までの各数値が 1 つだけ含まれるため、完全な連結には正確に n が含まれます。 値 1 の出現回数。位置全体に一様に分布していると仮定する不注意な試みは、簡単にこれを誤ってカウントする可能性があります。 

もう 1 つのエッジ ケースは m = n です。 この場合、順列内の長さ n の各ウィンドウは単なる順列そのものであるため、各ブロックは正確に 1 つの有効な部分配列に寄与します。 すべてのブロックにわたって、答えは n! でなければなりません。

 ## アルゴリズムのチュートリアル

 ### 最適な計算

 1. すべてのテスト ケースにわたって最大 n までの階乗を事前計算します。 最終的な式は m に依存するため、これは必須です。 そして（ん、ん）！ 多くのクエリの場合、テスト ケースごとに階乗を再計算すると時間がかかりすぎます。 
2. 各テスト ケースについて、n と m を読み取ります。 完全な順列シーケンスの構造は、そのサイズ n! を超えると無関係です。 
3. サイズ n の単一の順列内の有効な部分配列の数を計算します。 長さ m のウィンドウは、値 1 から m の順列が含まれている場合にのみ有効です。 
4. 1 つの順列にウィンドウ位置がいくつ存在するかを数えます。 各ウィンドウは開始インデックスによって決定されるため、そのような位置は (n - m + 1) 個あります。 
5. 固定ウィンドウの場合、1..n の順列が何回このウィンドウを有効にするかを計算します。 ウィンドウ内の m 個の特別な値の順序を m で選択します。 残りの n - m の値を (n - m) に配置します。 方法。 
6. これらのカウントを結合して、すべての順列にわたる合計寄与度を取得します。 各順列は同じ数の有効なウィンドウに寄与するため、n! を掛けます。 
7. キャンセル後、単純化された式 (n - m + 1) * m! を直接計算します。 * (n - m)! モジュロ 1e9 + 7。 

### なぜ効果があるのか

 核となる不変条件は、サイズ n のすべての順列が、m 個の値の固定セットを正確に m! の固定ウィンドウ位置に配置する可能性が等しいということです。 （ん、ん）！ 方法。 この均一性により、有効なウィンドウの数が特定の置換構造や辞書編集上の順序に依存しないことが保証されます。 完全なシーケンスはすべての順列の素結合にすぎないため、カウントの線形性により、順列ごとの結果を n 倍することができます。 ブロック間の相互作用はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    T = int(input())
    queries = []
    max_n = 0
    
    for _ in range(T):
        n, m = map(int, input().split())
        queries.append((n, m))
        if n > max_n:
            max_n = n

    fact = [1] * (max_n + 1)
    for i in range(1, max_n + 1):
        fact[i] = fact[i - 1] * i % MOD

    for n, m in queries:
        if m > n:
            print(0)
            continue
        ans = (n - m + 1) % MOD
        ans = ans * fact[m] % MOD
        ans = ans * fact[n - m] % MOD
        print(ans)

if __name__ == "__main__":
    main()
```この実装は、事前に計算された階乗に完全に依存しています。 式はモジュラー乗算を使用して直接評価され、除算や逆モジュラーを回避するため、解が安定してシンプルになります。 

唯一の微妙な点は、(n - m + 1) を確実に正しく処理することです。これは負でないことが必要であり、m ≤ n であるため常に有効です。

 ## 特殊なケース

 m = 1 の場合、アルゴリズムはすべての順列にわたって単一の要素をカウントすることになります。 式は n! となり、各順列には各数値が 1 つだけ含まれ、n! 個存在するという事実と一致します。 順列。 

m = n の場合、長さ n の唯一のウィンドウが順列自体であるため、すべての順列は 1 つの有効な部分配列に寄与します。 式は n! と評価され、これは順列の数と一致します。 

m = n - 1 など、m が n に近い場合、順列ごとのウィンドウの数は少なくなりますが、階乗項は大きくなります。 すべてのウィンドウが残りの要素の一意の配置に対応し、重複や二重カウントが発生しないため、乗算構造でも正確さが保たれます。
