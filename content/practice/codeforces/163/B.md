 ## 解決策
 ## 問題の理解

 私たちは、_n_ のグループから _k_ 個のレミングを選択し、選択したすべてのレミングが割り当てられた棚に到達するのに必要な時間 _t_ を最小限に抑えながら、より重いレミングがより高い棚を占めるように、それらを高さの増加する _k_ 個の棚に割り当てるように求められます。 各レミングには体重 _m_ と登る速度 _v_ があり、レミングが高さ _i・h_ の棚に到達するまでの時間は、上限として計算されます。$(i·h)/v$。 出力は、選択したレミングのインデックスを最も低い棚から最も高い棚までの順序で表示します。 

制約は重要です。 _n_ が最大 10^5 の場合、レミングのすべてのサブセットを考慮したり、すべての可能な割り当てを個別にシミュレートしようとしたりするソリューションは遅すぎます。 およそ O(n log n) または O(n log max_time) で実行されるアルゴリズムが必要です。ここで、max_time はバイナリ検索空間に関係します。 最大 10^4 の高さ、および最大 10^9 の速度と重みは、整数演算、特に除算と上限の計算を慎重に処理する必要があることを意味します。 

エッジケースには、複数のレミングの体重は同じだが速度が異なる状況が含まれます。 _k_ 個の最も重いレミングを選択する素朴な貪欲なアプローチは、実行可能な最小時間内に割り当てられた棚にいくつかのレミングが到達できない場合、失敗する可能性があります。 もう 1 つの微妙なケースは、多くのレミングがその高さに比べて極端に速いか遅い場合であり、これが達成可能な最小値に影響を与える可能性があります。 

## アプローチ

 ブルートフォース手法では、サイズ _k_ のすべてのサブセットを試行し、それらを重量で並べ替え、各レミングが割り当てられた棚を登る時間を計算します。 これは原理的には正しいですが、計算上不可能です。サブセットの数は次のとおりです。$C(n, k)$これは、n=10^5 および k=5 の場合、天文学的な値になります。 すべての割り当てをチェックするのにかかる時間は飛躍的に長くなります。 

重要な洞察は、最小時間 _t_ が二分探索を使用して決定できるということです。 候補 _t_ について、i 番目の棚に時間がかかる棚に順番に到達できる _k_ 個のレミングが存在するかどうかを確認できます。$\ge i·h / v$。 これにより、問題は組み合わせ選択から実現可能性チェックに変わります。 レミングを重量で分類すると、利用可能な最小の重量を最も低い棚に割り当てることができ、重量が減少しない制約が保証されます。 実現可能性チェック中に、候補 _t_ 内のそれぞれの棚に到達できる最速の _k_ レミングを選択します。 

このアプローチでは、解は O(n log n log T) に減ります。ここで、T は可能な登坂時間の範囲です。 時間の経過に伴う外部二分探索により、達成可能な最小限の _t_ が絞り込まれ、各実現可能性チェックには、ソートされたレミングを 1 回通過して、優先キューまたは最速の候補のリストが保持されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(n, k) * k) | O(k) | 遅すぎる |
 | 二分探索 + 貪欲な選択 | O(n log n log(max_time)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力値を読み取ります: レミングの数 _n_、棚の数 _k_、高さの増分 _h_、レミングの重量 _m_、および速度 _v_。 
2. 各レミングの体重、速度、元のインデックスをタプルにペアリングします`(weight, speed, index)`。 
3. レミングを重量の降順に並べ替えます。 これにより、最初に選択したレミングを最下位の棚に割り当てることが、重み付け順序の制約を満たすことが保証されます。 
4. 時間 _t_ の二分探索範囲を初期化します。 下限は 0 で、上限は任意の大きな数値にすることができます。$10^{18}$これは、レミングが必要とする可能性のある最大登坂時間を安全に上回っています。 
5. 候補時間 _t_ の実現可能性チェックを実装します。 ソートされたレミングを反復処理し、次に必要な棚に到達できるレミングのリストを維持します。棚 i の場合、レミングは次の条件を満たしている必要があります。$v \ge i·h / t$。 レミングが適格であれば、それを候補者のリストに追加します。 _k_ 個のレミングが収集されると、割り当てが可能になります。 
6. 二分探索を適用します。現在の _t_ が実行可能な場合は、上限を減らしてより小さい _t_ を探索します。 それ以外の場合は、下限を増やします。 
7. 最小の実現可能な _t_ を見つけた後、棚と重みの順序を尊重して、ソートされたリストから最初の _k_ 個の適格なレミングを選択して割り当てを再構築します。 
8. 選択したレミングの元のインデックスを、最も低い棚から最も高い棚までの順序で出力します。 

機能する理由: 重量による並べ替えにより、重量の制約に違反することなく、選択したレミングを常に棚に割り当てることができます。 二分探索により _t_ を最小化することが保証され、各候補の実現可能性をチェックすることで、選択されたすべてのレミングがその時間内に割り当てられた棚に物理的に到達できることが保証されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def lemmings_jump():
    n, k, h = map(int, input().split())
    m = list(map(int, input().split()))
    v = list(map(int, input().split()))
    
    lemmings = sorted([(m[i], v[i], i + 1) for i in range(n)])  # (weight, speed, index)
    
    left, right = 0, 10**18
    result_indices = []

    def feasible(t):
        count = 0
        selected = []
        for weight, speed, idx in lemmings:
            required_time = (count + 1) * h
            if speed * t >= required_time:
                selected.append(idx)
                count += 1
                if count == k:
                    break
        if count == k:
            nonlocal result_indices
            result_indices = selected
            return True
        return False

    while left < right:
        mid = (left + right) // 2
        if feasible(mid):
            right = mid
        else:
            left = mid + 1

    feasible(left)
    print(' '.join(map(str, result_indices)))

lemmings_jump()
```この解決策は、レミングとその重さ、速度、元のインデックスをペアにすることから始まります。 重量で並べ替えると、レミングを順番に選択することで重量順序の要件が満たされることが保証されます。 二分探索では、候補時間が実行可能な割り当てを可能にするかどうかを繰り返しチェックすることで、最小時間を効率的に見つけます。 実現可能性チェックでは、浮動小数点エラーを回避するために、速度に時間を乗算し、必要な高さと比較します。
