 ## 解決策
 ## 問題の理解

 給水所を表すラベル付きの頂点を持つ接続された無向グラフがあります。 Busy Beaver は、考えられるすべてのスパニング ツリーに次数以上のステーションが含まれるという特性を持つグラフがいくつあるかを知りたいと考えています。`K`。 入力により得られるのは、`N`そして`K`そして、この条件を法として満たすすべての接続されたグラフをカウントする必要があります。`998244353`。 

主な難点は、この条件がグラフ自体ではなく、すべてのスパニング ツリーについて説明していることです。 グラフには多数のスパニング ツリーが存在する可能性があるため、それらを直接チェックすることは不可能です。 制約`N <= 5000`また、グラフ、スパニング ツリー、さらにはエッジのすべてのサブセットを列挙しようとするものはすべて除外されます。 可能なグラフの数はすでに`2^(N(N-1)/2)`、そのため、解決策では、候補をグラフで走査するのではなく、構造の特徴付けと動的プログラミングを使用する必要があります。 

有益な観察は、`K`は常に半分より大きい`N`。 これは、2 つの異なる頂点が両方とも次数を持つことができないことを意味します`K`同じツリー内では、ツリーの次数の合計は`2N-2`。 そのため、「高次の頂点が存在する」という条件は、見た目よりもはるかに厳格になります。 

いくつかの特殊なケースは見落とされがちです。 もし`N = 5`そして`K = 4`、条件はすべてのスパニング ツリーで次数 4 の頂点を要求します。 完全なグラフはこれを満たしますが、サイクルは満たしません。 入力の場合:```
5 4
```答えは、すべての接続されたグラフの数ではありません。これは、多くの接続されたグラフにはパスであり、最大次数 2 のスパニング ツリーがあるためです。 

もう 1 つのケースは、グラフに明らかな中心局が 1 つある場合です。 のために：```
7 5
```頂点 1 を削除すると 6 つの孤立した頂点が残るため、頂点 1 を中心とする星形が機能します。 元のグラフの次数だけをチェックする不注意な解決策は、重要なプロパティがグラフ自体の大きな次数ではなく調音動作に由来するグラフでは失敗する可能性があります。 

## アプローチ

 最初の試みは、スパニング ツリーについて直接推論することです。 グラフのすべてのスパニング ツリーを生成し、その頂点の 1 つに少なくとも次数があるかどうかを確認できます。`K`、有効なグラフをカウントします。 プロパティはスパニング ツリーにわたって正確に定義されているため、これは正しいのですが、スパニング ツリーの数は急速に増加します。 単一の密なグラフであっても、膨大な数のスパニング ツリーが存在する可能性があるため、このアプローチは使用できなくなります。 

重要な点は、スパニング ツリー条件を頂点の削除に関するステートメントに置き換えることです。 

接続されたグラフの場合`G`、頂点を削除することを検討してください`v`。 させて`components(G-v)`残りの接続コンポーネントの数になります。 すべてのスパニング ツリーでは、次数が`v`少なくとも`components(G-v)`。 これは、削除後のすべてのコンポーネントが`v`経由で接続し直す必要があります`v`木の中で。 

逆方向も便利です。 いくつかの頂点が少なくとも`K`コンポーネントを削除した後、すべてのスパニング ツリーに少なくとも次数を与える必要があります`K`。 以来`K > N/2`、そのような頂点が 2 つ存在することはできません。 したがって、すべての有効なグラフには特別な頂点が 1 つだけあります。`v`そのような`G-v`少なくとも`K`コンポーネント。 

これで、固定された特別な頂点のグラフをカウントし、次の値を乗算するだけで済みます。`N`。 

取り外し後`v`、コンポーネントの数が非常に多いため、ほとんどの頂点を分離する必要があります。 させて`t`シングルトンコンポーネントを超える追加の頂点の数になります。 少なくともあるはずなので、`K`間のコンポーネント`N-1`残りの頂点、`t`せいぜい`N-K-1`。 

のグループの場合`s`頂点が 1 つの非シングルトン コンポーネントを形成する場合、2 つのことが必要です。 内部グラフが接続されている必要があり、これらの頂点の少なくとも 1 つが`v`。 各サイズの接続されたグラフの数を事前計算し、これをコンポーネントの重みとして使用します。 

残りのタスクは、最大でも 1 つの小さなパーティション DP です。`N-K-1`非シングルトン頂点。

 ## アルゴリズムのチュートリアル

 1. DP に必要なサイズの接続されたラベル付きグラフの数を事前計算します。 もし`conn[i]`接続されているグラフの数です。`i`頂点の場合、標準的な反復は、固定頂点を含む連結コンポーネントを選択することによって行われます。 反復は二次時間で実行されます。 
2. 固定された特別な頂点の場合、サイズのコンポーネントを作成する重みを計算します。`s`。 シングルトンコンポーネントには重みがあります`1`。 のために`s >= 2`、コンポーネントはこれらの接続された任意のグラフにすることができます。`s`特別な頂点は少なくとも 1 か所でそれに接触し、重みを与える必要があります。`conn[s] * (2^s - 1)`。 
3. しましょう`dp[i]`並べ方の数を表す`i`非シングルトン頂点を有効なコンポーネントに変換します。 残りの頂点は孤立したコンポーネントになります。 遷移するには、それらの中から固定頂点を 1 つ含むコンポーネントを選択します。`i`頂点を選択し、そのサイズを選択し、コンポーネントのウェイトを乗算します。 
4. 考えられるすべての数字について`i`非シングルトン頂点の場合は、それらの頂点を`N-1`特別ではない頂点を追加し、対応する寄与を追加します。 
5. 選択した 1 つの特別な頂点の数を次のように乗算します。`N`特別な頂点が一意であるためです。 

なぜ効果があるのか:

 不変条件は、特別な頂点を選択した後、有効なグラフはすべて、削除後に残った接続コンポーネントによって一意に記述されるということです。 このような各コンポーネントは、シングルトン、または DP によってカウントされる重み付けされた非シングルトン コンポーネントの 1 つです。 特別な頂点からのエッジも、すべてのコンポーネントに少なくとも 1 つの接続を持たせることによって処理されます。 2 つの特別な頂点は存在できないため、次のように乗算します。`N`二重にカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    N, K = map(int, input().split())

    limit = N - K
    m = N - 1

    fact = [1] * (N + 1)
    invfact = [1] * (N + 1)
    for i in range(1, N + 1):
        fact[i] = fact[i - 1] * i % MOD
    invfact[N] = pow(fact[N], MOD - 2, MOD)
    for i in range(N, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD

    def comb(a, b):
        if b < 0 or b > a:
            return 0
        return fact[a] * invfact[b] % MOD * invfact[a - b] % MOD

    conn = [0] * (limit + 2)
    conn[1] = 1
    pow2 = [1] * (limit + 2)
    for i in range(1, limit + 2):
        pow2[i] = pow2[i - 1] * 2 % MOD

    for n in range(2, limit + 2):
        total = pow2[n * (n - 1) // 2]
        bad = 0
        for s in range(1, n):
            bad += comb(n - 1, s - 1) * conn[s] % MOD * pow2[(n - s) * (n - s - 1) // 2]
            bad %= MOD
        conn[n] = (total - bad) % MOD

    weight = [0] * (limit + 2)
    for i in range(1, limit + 2):
        weight[i] = conn[i] * (pow2[i] - 1) % MOD
    weight[1] = 1

    dp = [0] * (limit + 1)
    dp[0] = 1
    for i in range(1, limit + 1):
        cur = 0
        for take in range(2, i + 1):
            cur += comb(i - 1, take - 1) * weight[take] % MOD * dp[i - take]
            cur %= MOD
        dp[i] = cur

    ans = 0
    for used in range(limit + 1):
        ans += comb(m, used) * dp[used] % MOD
        ans %= MOD

    ans = ans * N % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```コンポーネント DP には接続されたグラフのカウントが必要なので、コードは最初に接続されたグラフのカウントを構築します。 までのサイズのみ`N-K+1`せいぜい半分程度`N`非シングルトン部分が大きくなると、コンポーネントが少なすぎるためです。 

の`conn`recursion は、固定頂点を含むコンポーネントを選択した場合に、接続されていないグラフを差し引くことによって、接続されているすべてのグラフをカウントします。 2 のべき乗項は、残りの頂点内の任意のエッジをカウントします。 

の`weight`配列には、特別な頂点を削除した後の単一コンポーネントの寄与が格納されます。 要因`(2^s - 1)`そのコンポーネントから特別な頂点までの近傍の空でない選択肢の数です。 

メイン DP は非シングルトン部分のみをカウントします。 他のすべての頂点は強制的に分離されるため、DP の結果がわかった後、どの頂点が参加するかを選択します。 最終的な乗算`N`特別な頂点が一意であるため安全です。

 ## 特殊なケース

 のために`N=5, K=4`この場合、特別な頂点は残りの 4 つの頂点を少なくとも 4 つのコンポーネントに分離する必要があります。 DP では追加の頂点はゼロのみが許可されるため、有効な構造は特別な頂点を中心とする星形のグラフだけです。 アルゴリズムはそれらのグラフを正確にカウントし、可能な中心を乗算します。 

のために`N=7, K=5`この場合、特別な頂点を削除すると、6 つの頂点の間に少なくとも 5 つのコンポーネントが残る必要があります。 これは、最大 1 組の頂点を結合できることを意味します。 コンポーネント DP は、非シングルトン頂点を 2 つだけ許可し、それ以外はすべて分離されたものとして扱うことで、これを処理します。 

グラフに考えられる高次の中心が 2 つある場合、次の値を乗算するとカウントが危険になります。`N`二重カウントになります。 ここではそんなことは起こりえない。 2 つの頂点は両方とも少なくとも次数を強制します`K`すべてのスパニング ツリーでは、すべてのスパニング ツリーに少なくとも次数の合計が必要です`2K`よりも大きい`2N-2`なぜなら`K > N/2`。 アルゴリズムはこの一意性の特性に依存しています。
