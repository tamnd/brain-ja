 ## 解決策
 ## 問題の理解

 このタスクで説明されているプロセスは、一連の操作を受ける名刺の山に関するものです。 最初は、未知の数のカードが 1 つのスタックに配置されています。 時間の経過とともに、現在存在する最小のスタックに対して操作が繰り返し実行されます。そのスタックは、最大でもカード 1 枚分のサイズ差がある 2 つの部分に分割され、結果として得られる両方のスタックがシステムに戻されます。 

このような分割を一定回数実行した後、最後に存在する最小スタックのサイズがわかります。 この最終的な状況から、タスクは元のスタック サイズを再構築し、特に観察された最終状態と一致する可能な最小および最大の初期カード数を見つけることです。 

入力は複数の独立したシナリオで構成されます。 各シナリオでは、すべての操作後に観測された最小スタック サイズと、実行された分割操作の数という 2 つの整数が提供されます。 シナリオごとに、最終構成に至る可能性のある最小および最大の初期スタック サイズを出力する必要があります。 

主要な構造上の制約は、各操作で現在の最小の山のみが分割され、分割は常に可能な限りバランスがとれていることです。 これにより、大きなパイルを徐々に小さなパイルに縮小する決定論的な進化ルールが作成されますが、その方法では、パイル サイズ間の限定された関係が維持されます。 

テストあたりの両方のパラメーターは最大 40 で、テスト ケースは最大 1600 個あるため、どの解もテストあたり一定時間であるか、最悪の場合でも非常に狭い範囲で線形である必要があります。 大規模な構造でのシミュレーションや分割での指数関数的分岐を伴うものは、すべてのテスト ケースで繰り返されると、たとえ 1 つのケースが小さい場合でも、遅すぎます。 

最小のパイル サイズがすでに 1 である場合、微妙なエッジ ケースが発生します。その状況では、サイズ 1 のパイルを意味のある方法で最大 1 だけ異なる 2 つの正の部分に分割できないため、分割動作が退化します。 この基本条件を慎重に処理しない単純なシミュレーションは、誤ってループしたり、不可能な状態を生成したりする可能性があります。 

もう 1 つのデリケートな状況は、複数の異なる初期パイル構成により、k 回の操作後に最終的な最小パイル サイズが同じになる場合です。 たとえば、同じサイズの山の間で分割が異なる順序で発生した場合、異なる初期合計が同じ一連の最小の山に収束する可能性があります。 この非一意性こそが、可能な最小値と最大値の両方の初期値を要求される理由です。 

## アプローチ

 強引なアイデアは、推定された初期パイル サイズから先のプロセスをシミュレートすることです。 固定の初期値の場合、複数セットのパイル サイズを維持し、最小のパイルを繰り返し抽出し、それをほぼ同じ半分に 2 つに分割し、それらを挿入し直します。 k 回の操作の後、結果の最小値が指定されたターゲット n と一致するかどうかを確認します。 

このアプローチは、説明されているプロセスを正確に再現するため、概念的には単純で正しいものです。 ただし、状態空間は急速に拡大します。 分割するたびに山の数が 1 つずつ増加するため、k ステップ後には k+1 つの山ができます。 初期値をブルートフォースで試してみると、1 ～ 10^6 のような適度な範囲であっても、1600 のテスト ケースでは実行不可能になります。 マルチセット操作により各シミュレーション自体のコストは O(k log k) となり、最悪の場合は爆発が発生します。

重要な点は、実際には構成全体を追跡する必要がないということです。 すべての操作は現在の最小の山にのみ依存し、その山はカウントを除いて、より大きな山の正確な配置とは無関係に進化します。 マルチセット全体をシミュレートする代わりに、逆の推論を行うことができます。つまり、各分割でパイル x を 2 つのパイル Floor(x/2) と ceil(x/2) に置き換えます。 この変換は決定論的であり、合計が保存されます。 

最終的な最小杭サイズから逆算して、杭の考えられる祖先を再構築するという観点から考えることができます。 観察されたそれぞれの山は、2 つのほぼ等しい部分の結合から生じた可能性があり、あるいは他の部分に対する操作を通じて変化しないままであった可能性もあります。 この構造はバイナリ分割ツリーになります。各初期パイルは最終的にパリティ分割に応じて 1 または 2 に等しいリーフのコレクションを生成します。 

重要な単純化は、k 個の分割の後、正確に k+1 個のパイルが存在することです。 最終的な杭の最小サイズがわかっているため、その最小値に達するのに十分な分割深さを生成するには、元の単一杭がどのくらいの大きさでなければならないかを制限できます。 このプロセスは、元のサイズをほぼバランスのとれたバイナリ分解ツリーに効果的に分散します。最悪の場合の初期サイズは、不均衡の伝播を最大化する方法で常に分割することに対応し、最良の場合は完全にバランスの取れた分割に対応します。 

これにより、パイル システムを明示的に構築することなく、分割操作を通じて繰り返し反転されたときに値がどのように増加するかを追跡する問題が軽減されます。

 ## アルゴリズムのチュートリアル

 1. k 回の操作の後、システムには正確に k+1 個のスタックが含まれることを観察します。 これは、各操作で 1 つのスタックが削除され、2 つのスタックに置き換えられ、毎回合計カウントが 1 ずつ増加するためです。 
2. 最終的な最小スタック サイズは n として与えられます。 この値は、元のスタックから始まる概念的な分割プロセスの一部のリーフに対応する必要があります。 
3. 初期値の限界を理解するには、サイズ x の単一のスタックが繰り返しほぼ等しい半分に分割されたときにどのように動作するかを考えてください。 各分割により、合計を一定に保ちながらサイズが分散されますが、不均衡が軽減されます。 
4. 可能な最小の初期値は、k ステップ後にサイズ n の最小の山を生成する最も効率的な方法に対応します。 これは、すべての段階で分割が可能な限りバランスが取れており、大きな山を小さな山に分解する速度を最大化するときに発生します。 
5. 可能な最大の初期値は、ルールと一致する最も歪んだ展開に対応します。 これは、分割によって不均衡が伝播し、大きなスタックの削減が遅れ、k 個の操作を強制しながら質量を少数の大きなスタックに集中させるときに発生します。 
6. サイズの進化は、バイナリの増加を使用してモデル化できます。 各分割は効果的に寄与を半分にするため、k 個の分割を反転することは、観測された最小値に、マージされた回数から導出される係数を乗算することに相当します。 
7. すべての分割は、反転すると最大で 2 倍の効果に寄与するため、境界は k によって決定される幾何学的範囲に減少します。最小の初期値は k+1 個の杭全体に n を均等に分配するように増加しますが、最大値は k 個の分割の前にすべての質量を集中させることに対応します。 

### なぜ効果があるのか

このプロセスでは、各ノードがサイズが最大 1 だけ異なる 2 つの子に分割されるツリーが定義されます。 これにより、すべてのステップで合計が保持され、分割ツリーの高さが正確に k になることが保証されます。 考えられるすべての初期構成はそのようなツリーに対応し、逆にすべての有効なツリーは実行可能な一連の操作に対応します。 ノードが選択されると分割は決定的であるため、唯一の自由は、分割がどのように動作するかではなく、時間の経過とともにどのようにパイルを分割するかにあります。 これにより、システム全体が、制約された平衡分岐の下で固定総質量が k+1 個のリーフ全体にどのように配分されるかについて推論するようになり、極値の初期値が一意に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())

        # After k splits, there are k+1 piles.
        # Each split keeps total sum invariant.
        # Final minimum pile is n, so total sum is at least (k+1)*n.
        # This is achieved when all piles are n.
        min_initial = (k + 1) * n

        # For maximum, all mass can be concentrated before splitting,
        # but each split forces at least one increase in pile count,
        # leading to a binary expansion effect bounded by 2^k.
        max_initial = n * (1 << k)

        print(min_initial, max_initial)

if __name__ == "__main__":
    solve()
```コードは、分割プロセスから導出された構造境界を直接エンコードします。 係数 k+1 が表示されるのは、すべての操作で杭の数が 1 つだけ増加するためです。そのため、プロセスを逆にすると、最終構成が元の質量を k+1 個の部分に分割したものとして扱われます。 上限は、k ステップを逆方向にトレースすると、各分割がセグメントの寄与を最大 2 倍にすることができるという事実を使用します。これは、バイナリ分割ツリーにおける最悪の場合の不均衡の蓄積に対応します。 

シフト操作には注意が必要`1 << k`なぜなら、k は 40 に達する可能性がありますが、Python の整数制限内に安全に収まるためです。 乗算の順序も概念的に重要です。乗算の前にシフトを適用すると、固定幅言語では不必要な中間オーバーフローが回避されますが、Python では自然に処理されます。 

## 実用的な例

 n = 2 および k = 3 のシナリオを考えてみましょう。境界を段階的に計算します。 

| ステップ | 杭数 | 解釈 |
 | --- | --- | --- |
 | 開始 | 不明 | 初期シングルパイル |
 | 1以降 | 2山 | 最初の分割 |
 | 2以降 | 3 山 | 2番目の分割 |
 | 3以降 | 4 山 | 最終構成 |

 最小の初期値は、(k+1)・n = 4・2 = 8 です。これは、すべての最終パイルが正確に 2 であることに対応し、分割中に不均衡が導入されなかったことを意味します。 

最大の初期値は、n・2^k = 2・8 = 16 です。これは、各逆分割がますます大きくなる不均衡なパイルにマージされ、許容される限り値が集中する場合に対応します。 

このトレースは、パイル数の進化が分布とは独立しており、バイナリ分割の深さと組み合わされた全体の保存のみが境界を決定することを示しています。 

ここで、n = 5、k = 2 について考えてみましょう。 

| ステップ | 杭数 | 解釈 |
 | --- | --- | --- |
 | 開始 | 不明 | シングルパイル |
 | 1以降 | 2山 | 分割 |
 | 2以降 | 3 山 | 再び分割 |

 最小の初期値は 3・5 = 15、最大の初期値は 5・4 = 20 です。k が小さいとギャップが狭くなり、分岐の深さが制限されていることを反映します。 

これらの例は、杭数の増加が両方の境界を支配する重要な構造的制約であることを裏付けています。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import log2  # placeholder if needed
    # direct embedded solution
    data = inp.strip().split()
    t = int(data[0])
    idx = 1
    out = []
    for _ in range(t):
        n = int(data[idx]); k = int(data[idx+1]); idx += 2
        out.append(str((k+1)*n) + " " + str(n*(1<<k)))
    return "\n".join(out)

 ## 特殊なケース

 k = 0 の場合、分割は発生せず、システムは単一のスタックのままになります。 この式は min = max = n を与え、初期構成がすでに最終構成であるという事実と一致します。 

n = 1 で k が大きい場合、最小値は k+1 になりますが、最大値は 2^k と指数関数的に増加します。 これは、分割の逆解釈によって単一のユニットが繰り返し複製される可能性はあるが、1 未満には減らないというプロセスを反映しています。 

n と k の両方が大きい場合、支配的な要因は指数関数的な上限になります。 最小のパイルは固定されていますが、分割の深さが繰り返されると非常に不均一な分布が可能になり、初期サイズの実行可能な間隔が広くなります。
