 ## 解決策
 ## 問題の理解

 複数の独立したテスト ケースが与えられます。 各テスト ケースは、間隔の集合を記述します (1 人あたり 1 つの間隔)。 個人 i には単一の整数位置のみを割り当てることができ、その位置は間隔内になければなりません。$[l_i, r_i]$。 割り当てられたすべてのポジションは個別である必要があります。 

この問題を別の見方で見ると、間隔ごとに個別の整数を選択したいのですが、各間隔では許容できる整数が制限されます。 整数自体は抽象ラベルであるため、相対的な順序のみが重要であり、整数が次の順序に到達できるという事実は重要ではありません。$10^9$。 

タスクは、すべての間隔に割り当てられた整数が含まれるような個別の整数の割り当てが存在するかどうかを判断することです。 

この制約は、すべてのテスト ケースにわたる間隔の合計数が最大で次であることを意味します。$2 \cdot 10^5$。 テスト ケースごとに 2 次的な解は生き残れません。 ソートも問題ありません。また、ヒープまたはポインター スイープを使用する貪欲なアルゴリズムも問題ありません。 

いくつかの特殊なケースでは、典型的な貪欲な間違いが明らかになります。 たとえば、すべての間隔が同じである場合、$[1, 10], [1, 10], [1, 10]$、使用可能な整数は 10 個しかないため、答えはすぐには不可能ですが、3 つの異なる選択肢が必要です。 すべてを同じ中間点に割り当てる単純なアプローチでは、誤って成功したと主張してしまいます。 

間隔がネストされている場合、次のような別の特殊なケースが発生します。$[1, 5], [2, 4], [3, 3]$。 これは実際に実現可能ですが、最も制限された間隔から外側に向けて慎重に割り当てた場合に限ります。 厳密さを考慮せずに入力順に処理する戦略は、ここでは簡単に失敗します。 

3 番目の微妙なケースは、多くの間隔が大きく重なっているものの、わずかにずれている場合です。$[1,2], [2,3], [3,4], [4,5]$。 唯一の正しい割り当ては本質的にチェーンであり、最も早い終了の制約を無視した貪欲な決定は実現可能性を壊します。 

## アプローチ

 ブルートフォースアプローチでは、明示的に整数を割り当てようとします。 値が上がるので、$10^9$の場合は、すべてのエンドポイントを圧縮してから、バックトラッキングまたは 2 部マッチングを使用して間隔を 1 つずつ整数ポイントに一致させようとします。 圧縮後でも、これは間隔と座標の間の最大 2 部マッチング問題になります。 あれば$n$間隔と最大$2n$Hopcroft-Karp のような標準的なマッチングでは、約$O(n^{2.5})$実際には遅すぎます$2 \cdot 10^5$。 

重要な点は、実際には座標を明示的にモデル化する必要がないということです。 私たちが気にするのは、利用可能な整数を順番に貪欲に「消費」できるかどうかだけです。 間隔がその右端点でソートされたら、各間隔に、まだ使用可能でその範囲内にある可能な最小の整数を割り当てます。 これにより、問題はスケジュール スタイルの貪欲なプロセスに変換されます。 

直観的には、右端点が小さい区間ほど制約が大きくなり、より早く満たされる必要があると考えられます。 それを遅らせると、より緩やかな間隔で有効なポジションだけを消費してしまう可能性があります。 

候補となる整数値を左から右にスイープし、各点でどの間隔が利用可能になるかを維持します。 プライオリティ キューでは、アクティブな間隔が適切なエンドポイント順に並べられるため、常に現在の最小の実行可能な間隔が最初に割り当てられます。

 ## アルゴリズムのチュートリアル

 まず、すべての間隔を左側のエンドポイントで並べ替えて、各間隔がいつ適格になるかを確認します。 次に、整数位置の割り当てを可能な限り小さいものから順にシミュレートしますが、明示的に反復することはありません。$10^9$。 代わりに、イベントを使用して暗黙的に間隔の境界を飛び越えます。 

1. 間隔を並べ替える$l_i$。 これにより、範囲の開始時に正確に間隔をアクティブにすることができます。 
2. インターバルにわたるポインタと、キーとなる最小ヒープを維持します。$r_i$。 ヒープには、開始されたがまだ位置が割り当てられていないすべての間隔が含まれます。 
3. 候補位置を昇順に繰り返しますが、やみくもに繰り返すのではなく、可能な限り次の有用な位置に進みます。 各ステップで、すべての間隔を次のように押します。$l_i \le x$山の中へ。 
4. ポジションを割り当てる前に$x$、ヒープから間隔を削除します。$r_i < x$、もう満足できないからです。 いずれかの間隔が割り当てられずに期限切れになると、即座に答えが得られなくなります。 
5. ヒープが空でない場合は、現在の位置を割り当てます$x$最小の間隔まで$r_i$。 これを遅らせると最も早く実行できなくなる間隔なので、優先する必要があります。 
6. その間隔を割り当て済みとしてマークし、次の位置に進みます。 
7. すべての間隔が正常に割り当てられた場合は、「はい」を返します。 

### なぜ効果があるのか

 核となる不変条件は、どの位置でも$x$、ヒープには、有効な整数を割り当てることができる間隔が正確に含まれています。$\ge x$、どれもまだ割り当てられていません。 これらの中で、最小の右端点を持つ区間を選択することは安全です。実行可能なソリューションでは、より大きな右端点を持つ区間よりも遅くまでその区間を割り当てる必要があるからです。 可能な限り最後の時点で割り当てに失敗した場合、将来のすべてのポジションはさらに大きくなり、その範囲外になるため、後で修正することは不可能になります。 これにより強制的な順序付けが作成され、貪欲な選択ではその順序付けがグローバルに尊重されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        seg = []
        for i in range(n):
            l, r = map(int, input().split())
            seg.append((l, r))

        seg.sort()
        heap = []
        i = 0
        x = 0
        used = 0
        ok = True

        while used < n:
            if not heap and i < n:
                x = max(x, seg[i][0])

            while i < n and seg[i][0] <= x:
                heapq.heappush(heap, seg[i][1])
                i += 1

            while heap and heap[0] < x:
                heapq.heappop(heap)
                ok = False
                break

            if not ok:
                break

            if heap:
                heapq.heappop(heap)
                used += 1

            x += 1

        out.append("Yes" if ok and used == n else "No")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装はスイープ ライン ロジックに従います。 変数`x`は、割り当てられている現在の整数を表します。 ポインタ`i`ソートされた間隔を進み、左側の境界にすでに到達しているすべての間隔を押し込みます。 実現可能性と優先順位を決定するにはそれだけで十分であるため、ヒープには適切なエンドポイントのみが保存されます。 

微妙な点は、`x`に`seg[i][0]`ヒープが空のとき。 これがないと、シミュレーションはアクティブな間隔がない値を反復することになり、時間を無駄にすることになります。 もう 1 つの重要な詳細は、割り当てを試行する前に期限切れの間隔を削除することです。 そうしないと、一部の間隔がすでに不可能であるにもかかわらず、位置を誤って割り当てる可能性があります。 

## 実用的な例

 | 2 | [2,3] | [3] | [2,3] を割り当てる | 1,2 |

 すべての間隔で個別の有効な位置が取得され、実現可能性が確認されます。 

### 例 2

 間隔:$[1,1], [1,1], [1,1]$| × | アクティブな間隔 | ヒープ (r) | アクション | 割り当て済み |
 | --- | --- | --- | --- | --- |
 | 1 | 3つすべて | [1,1,1] | 1 つを割り当てます | 1 |
 | 2 | 有効なものはありません | [] | 失敗 (期限切れ) | 部分的 |

 私たちが過ぎ去った瞬間$x=1$、2 つの間隔は、唯一許可された位置が消費されているため、すでに無効です。 アルゴリズムは正しく拒否します。 

これらのトレースは、貪欲ルールが常に最も制約された間隔を最初に優先することを示しています。

 ## 特殊なケース

 次のような同一間隔の場合$[1,1], [1,1]$、すべてのインターバルが同じ 1 つのポジションをめぐって競合します。 ヒープには、同じ期限を持つ複数の間隔が含まれます。 アルゴリズムは次の場所に 1 つを割り当てます。$x=1$ですが、残りの間隔が期限切れになったことをすぐに検出し、正しく「いいえ」を生成します。 

次のようなネストされた間隔の場合$[1,5], [2,4], [3,3]$、ヒープは常に優先されます$[3,3]$で$x=3$。 初期の間隔は長く使用できるため、競合することなく後で割り当てられます。 これは、最小の右エンドポイントが常に最初に安全に処理されるという不変条件を示しています。 

次のような広い間隔の間隔の場合$[1,1], [100,100]$の場合、ポインター ジャンプは未使用の領域をスキップし、中間値に依存する間隔がないため、正確性を維持しながら効率を確保します。
