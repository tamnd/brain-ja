 ## 解決策
 # 問題の理解

 問題は、人間に優しい形式で書かれた電話番号を比較することです。 Vasya は連絡先に 1 つの新しい番号を追加したいと考えていますが、3 つの既存のレコードがそれぞれ同じ実際の電話番号を参照しているかどうかを知る必要があります。 

電話番号は、3 桁の市外局番/事業者コードと 7 桁の加入者番号で構成されます。 コードは明示的に記述することも省略することもできますが、その場合は次のように扱う必要があります。`495`。 国の接頭辞は次のように表示されます。`+7`または`8`、区切り文字`-`任意の数字の間に挿入できます。 コードを括弧で囲むこともできます。 

入力には、Vasya が追加したい 1 つの電話番号が含まれており、その後にすでに保存されている 3 つの電話番号が続きます。 保存されているすべての数値について、出力する必要があります。`YES`新しい番号とまったく同じコードおよび加入者番号を表す場合、それ以外の場合は出力`NO`。 

各数値には最大でも数十文字しか含まれないため、制約は小さくなります。 これは、高度なデータ構造や重い文字列アルゴリズムが必要ないことを意味します。 文字をリニア スキャンするだけで十分ですが、それを数回実行しても、使用可能な制限をはるかに下回ります。 重要な部分はパフォーマンスではなく、すべての可能な形式を 1 つの共通の表現に正しく正規化することです。 

難しいケースは、同じ数字がさまざまな方法で現れることから発生します。 例えば：```
Input:
8(495)430-23-97
+7-4-9-5-43-023-97
4-3-0-2-3-9-7
```最初の 2 つの数字は同じ電話番号を表します。`8`そして`+7`は同等であり、コードは`495`。 3 番目の数字にはコードがないため、そのコードは次のようになります。`495`、それも同様です。 ダッシュを削除するだけでプレフィックスを変更しないソリューションでは、これらのケースが誤って分離されてしまいます。 

もう 1 つのエッジ ケースは、コードが欠落している場合です。```
Input:
4302397
84954302397
```正しい出力は次のとおりです`YES`、最初の数値は次のように解釈される必要があるため、`4954302397`、2つ目も同様です`4954302397`変換後、`8`接頭辞。 不用意に実装すると、目に見える数字だけを比較して、暗黙のコードを見逃してしまう可能性があります。 

記号を削除した後の数値が 11 桁の場合、別の間違いが発生します。```
Input:
84951234567
1234567
```2 番目の数字は最後の 7 桁だけではありません。 デフォルトのコードもあります`495`したがって、正しい比較は次のとおりです。`4951234567`そして`4951234567`、不完全な文字列の間ではありません。 デフォルトのコードを無視すると、偽陰性が発生します。 

# アプローチ

 簡単なアプローチは、区切り文字を削除した後で文字列を直接比較してみることです。 入力が小さいため、これは魅力的です。 すべて削除できます`-`、かっこを削除し、残りの文字列が一致するかどうかを確認します。 書式設定文字は実際の数値に影響を与えないため、これは場合によっては正しいことになります。 

問題は、目に見える表現が実際のデータではないことです。 同じ電話番号に異なるプレフィックスを付けたり、コードを省略したりできます。 ブルート フォース アプローチでは、入力フォーマットのあらゆる解釈をシミュレートする必要があります。 文字数が少ない場合でもこれは可能ですが、不必要に複雑になり、間違いが発生しやすくなります。 

重要な観察は、すべての有効な電話記録が、3 桁のコードと 7 桁の加入者番号というまったく同じ 2 つの情報を記述していることです。 すべての入力文字列をこれら 2 つの部分に変換すると、比較は簡単になります。 

書式設定記号を削除した後、残りの数字は 2 つの形状のいずれかになります。 長さが 7 の場合、コードは省略され、先頭に追加されます。`495`。 長さが 11 の場合、最初の桁は国の接頭語 (`8`)、次の 3 桁がコードです。 最後の 7 桁は常に加入者番号です。 同じ正規化された 10 桁の表現をすべての比較に使用できます。 

このブルートフォースのアイデアは入力が小さいため機能しますが、意味ではなく表現を比較するため、概念的には失敗します。 正規化ステップでは、問題を多くのケースでの文字列一致から単純な等価性チェックに変換します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 比較あたり O(k) | O(k) | 受け入れられるがエラーが発生しやすい |
 | 最適 | 数値ごとに O(k) | O(k) | 承認済み |

 ここ`k`電話文字列の長さです。 以来`k`どちらも高速ですが、正規化がクリーンな解決策です。 

## アルゴリズムのチュートリアル

 1. Vasya が追加したい電話番号を読み取り、正規化された形式に変換します。 正規化された形式は、3 桁のコードとそれに続く 7 桁の加入者番号を含む 10 桁の文字列になります。 
2. 数値を正規化するには、最初に数字以外の文字をすべて削除します。 このステップの後は、意味のある数字だけが残ります。 
3. クリーンアップされた文字列が 7 桁の場合は、次の値を追加します。`495`最初に。 これは、コードが明示的に記述されていない番号を処理します。 
4. クリーンアップされた文字列が 11 桁の場合、先頭の文字列を削除します。`8`または`7`国を表現し、残りの 10 桁を保持します。 これらの数字の最初の 3 桁はコードで、最後の 7 桁は加入者番号です。 
5. 保存されている 3 つの電話番号をそれぞれ同じ方法で正規化します。 
6. すべての正規化された保存数値を正規化されたターゲット数値と比較します。 印刷する`YES`それらが等しいとき、そして`NO`さもないと。 

これが機能する理由は、正規化によって書式設定のみの問題であるすべての差異が除去されるためです。 変換後、実際のコードと加入者番号が等しい場合、2 つの数値は正確に等しくなります。 

不変条件は、すべての正規化された文字列が実際の電話番号を 1 つだけ表すということです。 アルゴリズム中に、不完全な表現やフォーマットされた表現を比較することはありません。そのため、同じ数値の異なるスペルは常に同じ値に集約されます。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def normalize(s):
    digits = ''.join(c for c in s if c.isdigit())

    if len(digits) == 7:
        return '495' + digits

    if digits[0] in '78':
        digits = digits[1:]

    return digits

def solve():
    target = normalize(input().strip())

    ans = []
    for _ in range(3):
        cur = normalize(input().strip())
        ans.append("YES" if cur == target else "NO")

    print('\n'.join(ans))

if __name__ == "__main__":
    solve()
```の`normalize`function はソリューションのアイデア全体です。 まず、数字のみを保持してダッシュと括弧を削除します。 電話形式では、残りの文字列が 7 桁または 11 桁であることが保証されます。 

7 桁の場合は、デフォルトのコードを挿入することで処理されます。 11 桁の場合、最初の桁は国の接頭語にすぎないため、比較する前に削除されます。 

比較段階は意図的に単純になっています。 すべての書式設定の決定はすでに解決されているため、文字列の等価性は電話番号の等価性と同じです。 

区切り文字はどこにでも出現する可能性があるため、元の文字列の固定位置によるインデックス作成のリスクはありません。 コードは、形式が保証されているクリーンアップされた数字列のみに依存します。
