 ## 解決策
 ## 問題の理解

 目標の桁の合計が与えられ、その桁がすべて異なり、その桁の合計がその目標に正確に一致する最小の正の整数を構築する必要があります。 

出力は単なる有効な数値ではなく、標準の 10 進数の順序での最小の数値です。 つまり、効果的に個別の数字のセットを選択し、その配置を決定し、それらから辞書編集的に可能な限り最小の数を形成していることになります。 

重要な制約は、数字が一意である必要があるということです。 数字の範囲は 0 ～ 9 のみであるため、10 を超える個別の数字を使用することはできません。さらに重要なことに、個別の数字を使用して達成可能な合計の最大値は固定されています。 可能な最大のセットは 0 ～ 9 のすべての数字で、その合計は 45 です。45 を超える入力は直ちに不可能になります。 

これにより、合計が制限された最大 10 桁という非常に狭い検索スペースが作成されます。 

ゼロの存在により、微妙な特殊なケースが発生します。 ゼロは合計には何も寄与しませんが、順序に影響します。 たとえば、数字 0 の使用は許可されていますが、最後の数字の先頭の数字として使用することはできません。 先頭のゼロを適切に処理せずに選択した数字を並べ替える単純なアプローチでは、誤って無効な最小表現が生成される可能性があります。 

もう 1 つのエッジ ケースは、1 や 2 のような少額の場合で、貪欲な選択は順序付け戦略に応じて異なる動作をします。 たとえば、和の制約を満たしながら辞書編集上の値を最小化しようとする場合、最小の桁から上に向かって数字を選択することは最適ではありません。 

## アプローチ

 強引なアイデアは、1 から 9 (およびオプションで 0) までの数字のすべてのサブセットを試し、それらの合計をチェックし、すべての順列を生成して最小の有効な数値を見つけることです。 探索空間は有限であるため、これは原理的には正しいです。$2^{10} = 1024$サブセット、最大 10 個までです。 サブセットごとの順列。 ただし、これでも最悪の場合には数百万の候補数が発生することになりますが、問題の構造を考えるとこれは不必要です。 

重要な観察は、合計が正確に一致する個別の数字のサブセットが必要であるということです。$x$、結果として得られる数値をできるだけ小さくしたいと考えています。 結果の数値を最小限に抑えるために、より小さい桁ができるだけ早く表示されるようにします。 ただし、桁が小さいと合計額の減少も遅くなり、固定された目標額に効率的に到達する必要がある場合には逆の結果になります。 

これにより、古典的な貪欲な緊張が生じます。個別の数字を使用しながらすぐに合計に到達するには、最初に大きな数字を優先する必要があります。 ただし、最終的な数を最小限にするには、後でそれらを昇順に並べる必要があります。 

したがって、正しい戦略は、9 から 1 までの数字を貪欲に選択し、残りの合計を超えない場合は常に 1 桁を取ることです。 これにより、使用する桁数をできる限り少なくし、より大きな貢献を早期に優先順位付けすることが保証されます。 セットを選択した後、それを昇順に並べ替えて、可能な限り最小の数を構成します。 

数字 0 は合計自体には決して役に立ちませんが、必要に応じて含めることができ、ソート順で常にゼロ以外のすべての数字の後に配置されます。これにより、唯一の数字でない限り、自然に先頭の数字になることがなくなります。

 ## アルゴリズムのチュートリアル

 1. 目標金額が達成されているかどうかを確認します$x$その場合、0 ～ 9 のすべての数字を使用してもその合計に達しないため、すぐに -1 を出力します。 これにより、施工前に不可能なケースが排除されます。 
2. 空のリストを初期化して選択した数字を保存し、変数を設定します`rem = x`まだ達成する必要がある残りの合計を表します。 
3. 9 から 1 までの数字を繰り返します。各桁で`d`、どうかを確認してください`d <= rem`。 そうであれば、含めてください`d`回答セットに入力して減算します`d`から`rem`。 残りの合計を減らすのに役立たないため、ここでは 0 を省略します。 
4. ループ後、次の場合`rem`がゼロではない場合、出力は -1 です。 これは、1 から 9 までの個別の数字を使用して合計を正確に表すことができないことを意味します。 
5. それ以外の場合は、選択した数字を昇順に並べ替え、それらを連結して最終的な数字を形成します。 並べ替えが必要なのは、可能な限り小さい整数が必要であり、小さい桁を前に置くと常に数値が小さくなります。 

### なぜ効果があるのか

 9 から下への貪欲な選択により、桁数が大きくなると残りの合計がより積極的に削減されるため、使用する桁数が可能な限り少なくなります。 数字を再利用することはないため、この構造は、合計がちょうど x になる {1..9} のサブセットを選択するのと同じです。 このようなすべてのサブセットの中で、有効な解は桁の順序のみが異なり、これらの桁を並べ替えると、常に最小の整数が得られます。 したがって、アルゴリズムは問題をサブセット選択 (実現可能性を考慮して貪欲に最適) と順序付け (ソートされた最小表現) に分離し、正確性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(x):
    if x > 45:
        return "-1"
    
    rem = x
    chosen = []
    
    for d in range(9, 0, -1):
        if d <= rem:
            chosen.append(d)
            rem -= d
    
    if rem != 0:
        return "-1"
    
    chosen.sort()
    return "".join(map(str, chosen))

t = int(input())
out = []
for _ in range(t):
    x = int(input())
    out.append(solve(x))

print("\n".join(out))
```実装は貪欲な構築に直接続きます。 実現可能性チェック`x > 45`不必要な作業を回避します。 9 から 1 への逆方向ループにより、大きな桁が優先されるため、選択される要素の数が最小限に抑えられます。 貪欲な選択だけでは最小の数値順序が保証されないため、最後に並べ替えることが不可欠です。 

よくある実装上の間違いは、選択する前に数字を並べ替えたり、1 から上向きに反復したりすることです。これにより、小さな数字が多数生成される傾向があり、解が存在する場合でも合計に到達できない可能性があります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、合計が 45 に等しい場合です。アルゴリズムは 9 から 1 までの数字を選択し、利用可能なすべての数字を 1 回だけ消費します。 並べ替えると 123456789 が生成されます。これは、すべての桁の最小順列です。 

もう 1 つのエッジ ケースは、合計が 8 や 10 など、到達可能なサブセット境界をわずかに上回っている場合です。x = 10 の場合、貪欲なプロセスは 9 と 8 をスキップし、7 (大きすぎて適合しない) を選択し、最終的に 9? を選択します。 実際にはできないので、9 がスキップされ、8 がスキップされ、7 がスキップされ、6 がスキップされ、5 がスキップされ、4 がスキップされ、3 がスキップされ、2 がスキップされ、1 と 9 は完了できないため、9 が選択されます。 いや、合わないよ。 最終選択は【9? 無効] の場合、rem はゼロ以外のままであるため、出力は -1 になります。 これは、貪欲な選択とは単に疲れ果てるまで選択することではないことを示しています。 実現可能性は残額によって検証する必要があります。 

最後の微妙なケースは x = 1 です。アルゴリズムは数字 1 を直接選択し、1 桁の出力を生成します。 0 を含めようとすると、合計を満たすことができず、扱いを誤ると順序に誤った影響を与える可能性があるため、有害です。
