 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、目標は特定の操作を何度でも使用してすべての要素を等しくすることです。 この操作では、要素を選択し、その値を隣接する要素の 1 つに追加し、その要素を削除することができます。 概念的には、これは数値を隣接する数値に「結合」する形式です。 出力は、残りのすべての数値が等しくなるために必要なこのような操作の最小数です。 

入力は複数のテスト ケースで構成され、各テスト ケースの配列サイズは最大 3000、値は最大 10^5 です。 すべてのテスト ケースにわたる配列サイズの合計は 3000 を超えないため、配列ごとに 2 次複雑度のアルゴリズムを使用できます。 要素を削除して方向を選択する方法の数は階乗的に増加するため、操作のすべてのシーケンスを試行する単純な指数関数的なアプローチは実行できません。 

すべての要素がすでに等しい場合、エッジ ケースが発生します。この場合、答えはゼロになります。 要素が 1 つだけの配列では、当然ながら操作は必要ありません。 合計が均等に分割できない配列は、要素を盲目的に結合する貪欲なアプローチによって間違った答えが生成される可能性があるため、慎重に処理する必要があります。 例えば、`[1, 2, 3]`この問題は、部分和を考慮せずに単に左から右にマージするだけでは解決できません。配列の合計が 6 であるため、合計をセグメント化する方法に応じて 1、2、または 3 つのパーティションを形成できるからです。 

## アプローチ

 ブルートフォースアプローチでは、マージのすべてのシーケンスを試み、最終的な配列の等価性を追跡します。 これは原理的には正しいですが、実際には不可能です。 長さ n の配列の場合、削除する要素の選択肢は n つあり、各ステップで要素の数は 1 つずつ減ります。 シーケンスの総数は n で階乗になり、n = 20 の場合でも膨大になります。そのため、n = 3000 の上限ではブルート フォースは失敗します。 

重要な点は、マージの順序は、どの連続セグメントの合計が目標値になるかという点だけが重要であるということです。 要素を隣接要素とマージするとセグメントの合計が効果的に構築されるため、逆に考えることができます。すべての要素が持つ必要がある最終値がわかっている場合は、元の配列をその合計で連続したセグメントに分割することを試みることができます。 各要素の最終値は、配列の合計の約数である必要があります。 候補となる各除数 (より具体的には、最大要素と合計値の間の各整数) について、配列をその値を合計するセグメントに分割できるかどうかを確認します。 長さ k の各セグメントは k-1 回の演算で 1 つの数値に折りたたまれるため、最小演算数は要素の総数から有効なセグメントの最大数を引いたものになります。 

これにより、問題は、考えられるターゲット セグメントの合計を反復して実行可能性をチェックすることになり、特定の制約に対して効率的になります。

 ## アルゴリズムのチュートリアル

 1. 配列の合計を計算します。 すべての要素を等しくしたい場合は、最終値の候補はこの合計を均等に除算する必要があります。 
2. 変数を初期化する`min_ops`n-1へ。 これは、1 つを除く各要素をマージする必要がある最悪のシナリオを表しています。 
3. 最初の要素から開始して、可能な連続セグメントの合計を繰り返します。 各プレフィックスの合計について`s`、合計が等しくなるまでセグメントを拡張してみます。`s`。 セグメントが超過した場合`s`、この合計は無効です。 
4. 有効なそれぞれについて`s`ここで、配列は合計の連続したセグメントに完全に分割できます。`s`、演算数を次のように計算します。`n - number_of_segments`。 アップデート`min_ops`これが小さければ。 
5. 考えられるすべてのセグメントの合計を確認した後、`min_ops`最小限の操作が含まれています。 

機能する理由: この操作により、任意の要素を隣接する要素とマージでき、連続するセグメントを単一の数値に効果的に折りたたむことができます。 各セグメントの合計が同じ値になるようにすることで、マージ後に残りの数値がすべて等しいことが保証されます。 不変条件は、配列を等和の連続セグメントに分割する有効な分割は、各セグメント内の内部要素をマージすることによって実現できるということです。 長さ k の各セグメントには k-1 回のマージが必要なため、必要な操作の数は、要素の合計数からセグメントの数を引いたものとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_operations(arr):
    n = len(arr)
    total = sum(arr)
    min_ops = n - 1
    
    for target_len in range(1, n + 1):
        if total % target_len != 0:
            continue
        target_sum = total // target_len
        current_sum = 0
        segments = 0
        valid = True
        for num in arr:
            current_sum += num
            if current_sum > target_sum:
                valid = False
                break
            elif current_sum == target_sum:
                segments += 1
                current_sum = 0
        if valid and segments == target_len:
            min_ops = min(min_ops, n - segments)
    return min_ops

t = int(input())
for _ in range(t):
    n = int(input())
    arr = list(map(int, input().split()))
    print(min_operations(arr))
```このソリューションは、まずテスト ケースの数を読み取ります。 配列ごとに合計を計算し、考えられるすべての数のセグメントに対して繰り返します。 内側のループは累計を蓄積し、それが次の値に等しい有効なセグメントを形成できるかどうかを確認します。`target_sum`。 最小操作数は、要素の合計数から有効なセグメントの数を引いたものとして計算されます。 境界条件は自然に処理されます。単一要素の配列または等しい値の配列では、直ちに演算がゼロになります。

## 特殊なケース

 入力用`[1,2,3]`、アルゴリズムは合計 6 を計算します。6 を除算するセグメント長 (1、2、3、および 6) のみが考慮されます。target_len=3、target_sum=2 の場合、累計では 2 の有効なセグメントを形成できません。`[1,2,3]`, したがって、これは拒否されます。 For target_len=2, target_sum=3, segments`[1,2]`そして`[3]`2 つの有効なセグメントを形成し、セグメントごとに 3-2=1 回の操作が必要です。 アルゴリズムはマージを正確に識別します`[1,2]`3 に入って出発`[3]`1 つの操作が与えられ、全体の最小操作は次のとおりです。
