 ## 解決策
 ## 問題の理解

 要素が互いに「近い」配列の特定のサブセットを数えるように求められます。 より正確には、整数の配列があります。`a`長さの`n`、サイズの数が必要です-`m`タプル内の最大要素と最小要素の差が最大で次のようなタプル`k`。 出力はモジュロです$10^9+7$。 

入力は複数のテスト ケースを表し、それぞれがシーケンスとタプル制約を指定します。 出力はテスト ケースごとに 1 つの整数、つまり有効なタプルの数を法的に表したものです。$10^9+7$。 

制約が示唆するのは、`n`と同じ大きさにすることができます$2 \cdot 10^5$、 しかし`m`は小さく、最大でも 100 です。これは、すべてを試す単純なアプローチを意味します。$C(n, m)$演算の数が組み合わせ的に増加するため、タプルを直接演算することは不可能になります。 代わりに、小さなものを活用する方法が必要です。`m`そして配列の順序付けされた構造。 

明らかではないエッジ ケースには、すべての要素が同じである配列や、`k`はゼロです。 たとえば、`n=3`、`m=2`、`k=0`、 そして`a=[1,1,2]`、同一の要素のペアのみが有効です。 差分をグローバルに見るだけの不注意なアプローチでは、要素を含むタプルが過剰にカウントされてしまいます。`2`。 

## アプローチ

 ブルートフォース手法では、サイズのインデックスのすべての組み合わせが生成されます。`m`、各タプルの最大値と最小値の差を確認します。 これは正しいですが、実行不可能です。すべてを生成します。$C(2 \cdot 10^5, 100)$タプルは天文学的に大きいため、妥当な時間内に実行することはできません。 

最適化する上で重要な点は、要素を並べ替えることができるため、連続した部分配列を操作できることです。 配列がソートされると、任意のサイズのタプルが`m`最小の要素をインデックスに持つ`i`ウィンドウ内の他のすべての要素は、最大で最大の要素で終わる必要があります。`k`より大きい`a[i]`。 これにより、問題は有効な範囲内のインデックスの組み合わせを数えるというものになります。 

以来`m`小さいし、`n`大きいため、階乗モジュロを事前に計算します$10^9+7$組み合わせを効率的に計算できるようになります。 それぞれについて`i`、最大のインデックスを見つけます`j`そのような`a[j] - a[i] <= k`。 次に、次で始まる有効なタプルの数`a[i]`は`C(j - i, m - 1)`、私たちが選択するからです`m-1`からの追加要素`j-i`後の要素`i`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^m) | O(n) | 遅すぎる |
 | 最適 | O(n log n + n * m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗および逆階乗モジュロを事前計算する$10^9+7$最大まで`n`すべてのテストケースにわたって。 これにより、次の式を使用して組み合わせを迅速に計算できます。$C(n, r) = \text{fact}[n] \cdot \text{inv\_fact}[r] \cdot \text{inv\_fact}[n-r]$。 
2. 各テスト ケースについて、次の内容を読んでください。`n`、`m`、`k`、および配列`a`。 選別`a`昇順で。 並べ替えにより、有効な差分内の要素が連続していることが保証されます。 
3. 変数を初期化する`ans = 0`。 これにより、有効なタプルの数が累積されます。 
4. 各インデックスを反復処理します。`i`0から`n-1`。 要素については`a[i]`、2 ポインター アプローチを使用して最大のインデックスを見つけます。`j`そのような`a[j] - a[i] <= k`。 
5. このウィンドウ内の要素の数が`count = j - i`少なくとも`m-1`を追加します。`C(count, m-1)`に`ans`。 それ以外の場合、サイズのタプルはありません`m`から開始できます`a[i]`。 
6. 出力`ans % MOD`テストケース用。 

機能する理由: 並べ替えにより、間にあるすべての要素が保証されます。`i`そして`j`以内にいる`k`の`a[i]`。 2 ポインター アプローチにより、要素を再スキャンすることなく、有効なウィンドウのみを効率的に考慮することが保証されます。 組み合わせ論により、このウィンドウ内のすべてのタプルが正しくカウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
MAX = 2 * 10**5 + 100

fact = [1] * MAX
inv_fact = [1] * MAX

# precompute factorials and inverse factorials modulo MOD
for i in range(1, MAX):
    fact[i] = fact[i-1] * i % MOD

inv_fact[MAX-1] = pow(fact[MAX-1], MOD-2, MOD)
for i in range(MAX-2, -1, -1):
    inv_fact[i] = inv_fact[i+1] * (i+1) % MOD

def comb(n, r):
    if n < r or r < 0:
        return 0
    return fact[n] * inv_fact[r] % MOD * inv_fact[n-r] % MOD

t = int(input())
for _ in range(t):
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()
    ans = 0
    j = 0
    for i in range(n):
        while j < n and a[j] - a[i] <= k:
            j += 1
        count = j - i - 1
        if count >= m - 1:
            ans = (ans + comb(count, m-1)) % MOD
    print(ans)
```このソリューションでは、まず組み合わせ計算を準備します。 ソートにより、要素が最大で異なるウィンドウを見つけることができます。`k`。 2 ポインターのアプローチにより、冗長な作業が回避され、配列の線形スキャンが保証されます。 重要な微妙な点は、次から 1 を引くことです。`j - i`なぜならインデックスの要素は`i`はすでに最小値としてカウントされています。
