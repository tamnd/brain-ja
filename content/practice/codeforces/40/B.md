 ## 解決策
 ## 問題の理解

 まずは、`n × m`チェス盤。 左上のセルは黒なので、通常のチェス盤とまったく同じように色が交互に表示されます。 最初に黒いセルだけが再描画プロセスに参加します。 

分に`0`、すべての黒いセルが色を受け取ります`0`。 その後、分ごとに`i`、4 つの斜めの隣接セルがすでに色を持っているすべての黒セルを再ペイントします。`i - 1`。 同じ分のすべての再描画が同時に行われます。 

セルはプロセス中に何度も再描画される場合があります。 タスクは、正確に再描画されたセルの数をカウントすることです。`x`回。 

基板の寸法は最大でも`5000 × 5000`、これは、到達できるセルの総数を意味します。`25,000,000`。 ボード全体を何度も繰り返してシミュレーションすることは不可能です。 この規模の Python では、単一のフルグリッド BFS スタイルのプロセスでもすでにコストが高くなります。 値`x`と同じ大きさにすることができます`10^9`、分ごとのシミュレーションは完全に排除されます。 

本当の課題は、再描画ルールが実際に幾何学的に何を意味するのかを理解することです。 

いずれかの寸法が等しい場合、微妙なエッジケースが発生します。`1`。 

例えば：```
1 5
1
```正しい答えは次のとおりです。```
3
```最初は 3 つの黒いセルがあり、どのセルにも 4 つの斜めの隣接セルがないため、プロセスはすぐに停止します。 これらの各セルは、1 分間に 1 回だけペイントされます。`0`。 

不用意に実装すると、レイヤーを無限に縮小し続けようとし、誤ってマイナスの寸法が生成されたり、存在しないセルがカウントされたりする可能性があります。 

もう 1 つの注意が必要な状況は次のような場合です。`x`可能な再描画回数よりも大きいです。 

例：```
3 3
2
```正しい答えは次のとおりです。```
0
```中央の黒いセルは 2 回ペイントされますが、隅の黒いセルは 1 回だけペイントされます。 3 回目の再描画に耐えられるほど長く生き残るセルはありません。 

単純なシミュレーションでは、「無限に」と書かれているため、再描画が永久に続くと誤って考える可能性がありますが、十分なステップを経るとプロセスは安定し、それ以上のセルは適格になりません。 

黒セルの数が対称ではないため、均一な寸法のボードも慎重に取り扱う必要があります。 

例：```
2 3
1
```黒のセルは次のとおりです。```
B W B
W B W
```参加するセルは 3 つだけです。 答えは`3`、 ない`4`。 

チェス盤のパリティ構造は、ソリューション全体を通じて重要です。 

## アプローチ

 最も直接的なアイデアは、プロセスを分ごとにシミュレートすることです。 

すべての黒セルの現在の再描画数を保存し、ボードを繰り返しスキャンすることができます。 各反復中に、直前の 1 分間に 4 つの斜めの隣接要素がすべて再描画されたかどうかを確認します。 「はい」の場合、現在のセルも再描画されます。 

このシミュレーションは、ステートメントに正確に従っているため、正しいです。 問題はコストです。 レイヤーの数はおおよそ次の数まで増やすことができます。`min(n, m) / 2`、各反復でボード全体をスキャンします。 最大寸法`5000`、これは数千万または数億の操作になり、Python ではすでに不快です。 さらに重要なことは、ボード自体に 2,500 万個のセルが含まれる可能性があるため、大規模な補助構造を保管するだけでもコストがかかることです。 

重要な観察は、再ペイントが境界線からレイヤーを剥離するのとまったく同じように動作することです。 

黒セルは、4 つの斜めの隣接セルがすべて存在し、前のステップでも生き残った場合にのみ、もう 1 回の再描画に耐えられます。 つまり、セルは境界線の近くにあってはなりません。 1 回再ペイントすると、最も外側の斜めのレイヤーが消えます。 もう一度再ペイントすると、次のレイヤーが消えます。 

したがって、黒いセルが再描画される回数は、境界線までの最小対角距離のみに依存します。 

プロセスをシミュレートする代わりに、各対角層に属する黒セルの数を直接数えることができます。 

セルが再描画されても生き残ると仮定します。`x - 1`。 それなら少なくともそうあるべきだ`x - 1`垂直方向と水平方向の両方で、すべての境界線から一歩離れます。 これらのレイヤーを削除すると、内側の長方形が残ります。```
(n - 2(x - 1)) × (m - 2(x - 1))
```その長方形内のすべての黒いセルは少なくとも再描画されます`x`回。 

で表すと`f(k)`少なくとも再描画された黒セルの数`k`必要な答えは次のとおりです。```
f(x) - f(x + 1)
```なぜならそれらはまさに再描画まで生き残る細胞だからです`x - 1`しかしそれを超えることはありません。 

長方形内の黒セルを数えるのは簡単です。 左上隅が黒なので、セル内の黒のセルの数は`a × b`長方形は次のとおりです。```
(a * b + 1) // 2
```同じパリティアライメントでカウントした場合。 

これにより、問題全体が数回の算術演算に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm · min(n, m)) | O(nm) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`m`、 そして`x`。 
2. 関数を定義する`count_black(a, b)`内の黒セルの数を返します。`a × b`左上隅が黒い長方形。 

式は次のとおりです。```
(a * b + 1) // 2
```黒と白のセルが交互に配置され、面積が奇数の場合は黒が追加のセルを獲得するためです。 
3. しましょう`k = x - 1`。 

正確に再描画されたセル`x`時代は生き残らなければなりません`x - 1`縮むステップ。 
4. 少なくとも残る長方形の寸法を計算します。`x`再塗装:```
a1 = n - 2k
b1 = m - 2k
```どちらかの次元が正でない場合、それほど長く生存する細胞はありません。 
5. 少なくとも残る長方形の寸法を計算します。`x + 1`再塗装:```
a2 = n - 2(k + 1)
b2 = m - 2(k + 1)
```6. 以下を計算します。```
at_least_x = count_black(a1, b1)
at_least_x_plus_1 = count_black(a2, b2)
```正でない寸法を持つ四角形を、セルが含まれていないものとして扱います。 
7. 最終的な答えは次のとおりです。```
at_least_x - at_least_x_plus_1
```### なぜ効果があるのか

 黒いセルは、斜めに隣接する 4 つすべてが前のステップで生き残った場合にのみ、再度再描画できます。 この条件では、各反復中にすべての境界線からちょうど 1 つの対角線レイヤーが削除されます。 

後`k`反復では、生き残ったセルは正確に、削除することによって得られた長方形内の黒いセルです。`k`4 つの側面すべてから行と列を表示します。 

それで`f(k)`少なくとも再描画されたセルを正しくカウントします`k`回。 連続したレイヤーを減算すると、再描画されたセルが正確に分離されます。`x`回。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_black(a, b):
    if a <= 0 or b <= 0:
        return 0
    return (a * b + 1) // 2

def solve():
    n, m = map(int, input().split())
    x = int(input())

    k = x - 1

    at_least_x = count_black(n - 2 * k, m - 2 * k)
    at_least_x_plus_1 = count_black(n - 2 * (k + 1), m - 2 * (k + 1))

    print(at_least_x - at_least_x_plus_1)

solve()
```ヘルパー関数は、問題の幾何学的な核心を処理します。 残りの四角形の寸法が正でない場合、その数のレイヤーに生き残るセルはないため、関数はすぐに 0 を返します。 

表現`(a * b + 1) // 2`左上隅の黒から始まる市松模様の黒のセルを数えます。 これは偶数領域と奇数領域の両方で機能します。 

変数`k = x - 1`セルが正確に再描画される前に、セルが生き残る必要がある縮小操作の回数を表します。`x`回。 

The implementation avoids simulation entirely. No arrays, BFS, or recursion are needed. すべては、斜めのレイヤーの幾何学的解釈から生まれます。 

One easy mistake is confusing “painted exactly`x`回」と「生き残る」`x`正確にペイントされたセル`x`回はラウンドを通じてのみ存続します`x - 1`、そのため、コードでは`k = x - 1`。 

もう 1 つの一般的なオフバイワンの問題は、次の層を計算するときに発生します。 引き算します`2 * (k + 1)`再描画を追加するたびに、各辺から 1 行 1 列が削除されるためです。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    import sys
    input = sys.stdin.readline

    def count_black(a, b):
        if a <= 0 or b <= 0:
            return 0
        return (a * b + 1) // 2

    n, m = map(int, input().split())
    x = int(input())

    k = x - 1

    at_least_x = count_black(n - 2 * k, m - 2 * k)
    at_least_x_plus_1 = count_black(n - 2 * (k + 1), m - 2 * (k + 1))

    print(at_least_x - at_least_x_plus_1)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup
    return out.getvalue().strip()

# provided sample
assert run("3 3\n1\n") == "4", "sample 1"

# minimum board
assert run("1 1\n1\n") == "1", "single cell"

# no further repaint possible
assert run("1 5\n2\n") == "0", "thin board"

# center survives longer
assert run("5 5\n3\n") == "1", "only center survives"

# large dimensions with impossible x
assert run("5000 5000\n3000\n") == "0", "x too large"

# rectangular board
assert run("2 3\n1\n") == "3", "parity handling"

 ## 特殊なケース

 単一行のボードを考えてみましょう。```
1 5
1
```アルゴリズムは以下を計算します。```

a1 = 1
b1 = 5
a2 = -1
b2 = 3
```それで：```
at_least_x = 3
at_least_x_plus_1 = 0
```答えは`3`。 

すべての黒いセルが 1 分に 1 回ペイントされるため、これは正しいです。`0`ただし、斜めに隣接するセルが 4 つあるセルはないため、再描画は続行されません。 

ここで次のことを考えてみましょう。```
3 3
2
```次のように計算します。```
k = 1
a1 = 1
b1 = 1
a2 = -1
b2 = -1
```それで：```
at_least_x = 1
at_least_x_plus_1 = 0
```答えは`1`。 

中央のセルだけが 2 回再描画できるほど長く残ります。 最初のレイヤーが縮小すると、隅の黒いセルが消えます。 

最後に、均等なサイズの基板について考えてみましょう。```
2 3
1
```残りの長方形は、`x = 1`完全なボード自体です:```

```黒マスの数は次のとおりです。```

```これにより、チェッカーボードのカウント式が混合パリティ次元を正しく処理することが確認されます。
