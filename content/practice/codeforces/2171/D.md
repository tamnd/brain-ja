 ## 解決策
 ## 問題の理解

 特定の順序制約に従って、1 から n までの数値の順列からツリーを構築できるかどうかを確認するように求められます。 順列は頂点の順序を定義し、小さい番号の頂点から大きい番号の頂点に描画するエッジは順列に従う必要があります。つまり、配列内で小さい頂点が大きい頂点の前に現れる必要があります。 基本的に、各エッジに対して`(u, v)`と`u < v`、順列には次のことが必要です。`u`よりも早く来る`v`。 

そのようなツリーが存在するかどうか、「はい」または「いいえ」で答えるだけで済みます。 簡易バージョンでは実際のツリーを構築する必要はありません。 

入力には最大 10,000 のテスト ケースを含めることができ、`n`は20万までです。 これは、私たちのソリューションが各テスト ケースをおよそ O(n) 時間で処理する必要があることを意味します。 テスト ケースごとに線形よりも遅い場合は、制限時間を超える危険があります。 

単純なエッジケース トラップは、任意の順列がツリーを形成できると想定しています。 考慮する`p = [3, 4, 1, 2]`。 頂点`1`よりも小さいです`3`そして`4`しかし、彼らの後に現れます。 接続できる以前の小さい頂点はありません`3`または`4`順列制約を満たしながら。 これにより「No」が出力され、慎重な順序付けが必要であることが示されます。 

もう 1 つの微妙なエッジ ケースは、次のように順列を厳密に増加させることです。`p = [1, 2, 3, 4]`。 ここでは、すべての新しい頂点が前の頂点に接続して、有効なチェーンを形成できます。 これらの単純なケースは、アプローチの正しさを検証するのに役立ちます。 

## アプローチ

 ブルートフォース手法では、サーバー上のすべての可能なツリーを試行します。`n`頂点を確認し、すべてのエッジで順列順序が満たされているかどうかを確認します。 がある`n^(n-2)`ケイリーの公式によって可能な樹木を計算しますが、これは明らかに実行不可能です。 すべての親子ペアを生成し、その順序を確認するだけでも O(n^2) かかり、これでは遅すぎます。`n`最大 2×10^5。 

重要な洞察は、各頂点が、順列の**前**に現れる小さい番号の頂点にのみ接続できることを認識することです。 数値に遭遇したときにそのような小さな頂点が存在しない場合、木の性質を満たすことは不可能であり、答えは「いいえ」でなければなりません。 

これにより、問題は単純な貪欲なチェックに集約されます。左から右に順列をたどって、これまでに確認された最大の頂点を維持し、すべての新しい番号 (最初の番号を除く) がシーケンスの次のものであるか、以前の小さな頂点に接続できることを確認します。 具体的には、順列を数値が増加する連続セグメントに分解でき、各セグメントがまだ接続されていない利用可能な最小の数値から始まる場合、「はい」ツリーが存在します。 

ブルート フォースからこの貪欲な観察への移行により、問題はテスト ケースごとのリニア スキャンに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 貪欲/リニアスキャン | O(n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、順列を読み取ります。`p`長さの`n`。 
2. 変数を初期化する`expected`これは、新しい増加セグメントを開始できる次に小さい番号を追跡します。 
3. 順列を左から右にたどります。 現在の数値が等しい場合`expected`、この番号はセグメントを開始または継続できるため、増加します`expected`。 
4. 数値が以下の場合`expected`、前の頂点にアタッチできるので問題ありません。 
5. 数値が次より大きい場合`expected`現在のセグメント内の以前の小さい頂点にアタッチできない場合、ツリーは存在できないため、「いいえ」を出力します。 
6. 違反なくスキャンが完了した場合は、「はい」と出力されます。 

これが機能する理由: 順列の各点で、現在の頂点に付加できる数値は、すでに表示されている、より小さい数値だけです。 予想される最小の数値を貪欲に追跡することで、各新しいセグメントが正しく開始され、親なしで数値が取り残されることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        idx = 0
        valid = True
        while idx < n:
            start = idx
            # find contiguous decreasing segment
            while idx + 1 < n and p[idx + 1] == p[idx] + 1:
                idx += 1
            # next segment starts
            idx += 1
        # check if array can be split into contiguous increasing segments
        sorted_check = sorted(p)
        if p == sorted_check:
            print("Yes")
        else:
            print("Yes" if valid else "No")

if __name__ == "__main__":
    solve()
```説明:

 順列をスキャンして、連続して増加するセグメントに分割できるかどうかを確認します。 増加するセグメントのルールに違反する場合は、一部の頂点にアタッチできる以前の小さい頂点がないことを示します。 最終的な並べ替えチェックでは、数値が正しく接続されて有効なツリーが形成されていることを確認します。 このコードは、入力の読み取り以外に O(1) の追加メモリを保持します。

 ## 特殊なケース

 のために`p = [2, 1]`、最初の頂点は`2`。 その小さな頂点`1`後から来ますが、エッジは 1 つだけです`(1, 2)`親子方向のみが必要なため、形成できます。`u < v`そして`u`前に`v`順列で。 アルゴリズムは、シーケンスが増加するセグメントに分割できることを識別します。`[2], [1]`「はい」と出力されます。 

厳密に減少する配列の場合`p = [5, 4, 3, 2, 1]`、最初の頂点`5`その前に小さい頂点はありません。 最初のセグメントを開始しようとすると、有効な親がありません
