 ## 問題の理解

 同じ長さの 2 つの配列が与えられています。`a`そして`b`、ここで、の各要素は、`a`は最大でも対応する要素です`b`。 課題は変革することです`a`の中へ`b`2 つの許可された操作を使用する: の 1 つの要素をインクリメントする`a`1 ずつ、またはすべての要素を 2 倍します`a`。 これを最小限の操作数で実行し、この最小数を達成する一連の操作の数もカウントしたいと考えています。 

制約は厳しいです:`n`最大200,000まで可能で、`b_i`最大 1,000,000 まで可能です。 可能なシーケンスの数は操作の数に応じて指数関数的に増加するため、すべての操作シーケンスの総当りシミュレーションは直ちに実行不可能になります。 それぞれの倍加はすべての要素に影響します。これは、単純な方法で要素を独立して扱うことができないことを示唆しています。 シーケンスはどの操作が適用されるかだけでなく、順序やインクリメント操作で影響を受けるインデックスによっても区別されるため、カウント部分にも注意が必要です。 

明らかではないエッジケースには、次のような場合が含まれます。`a_i`すでに等しい`b_i`、答えは操作がゼロであるか、または 1 つの要素が他の要素よりも大幅に大きく、多くの 2 倍化ステップが強制される場合です。 もう 1 つの注意が必要なシナリオは、要素を 2 倍にして正しく位置合わせする前に、要素ごとに異なる増分数が必要な場合に発生します。 例えば、`a = [1,1]`、`b = [4,3]`シーケンスは 1 つだけあります: インクリメント`a_1`2倍、2倍`[4,2]`、増分`a_2`3へ。 

## アプローチ

 ブルートフォースアプローチでは、増分と倍加のあらゆる組み合わせを再帰的に調査します。 考えられるすべてのシーケンスを試して、どのシーケンスに到達するかを追跡することもできます`b`その通り。 これは原理的には機能しますが、中程度の場合、シーケンスの数は簡単に 2^20 を超える可能性があります。`b_i`が鈍くなるにもほどがあります。 さらに、それはスケールしません`n`20万で。 

重要な点は、2 倍化はグローバル操作であり、増分はローカルであるということです。 逆に考えることもできます。`b`に到達するまで操作を元に戻すことができます。`a`。 2 倍は逆に 2 倍になり (偶数の場合)、増分は逆に減分になります。 これにより、ビット操作を使用した動的プログラミング アプローチが可能になります。要素ごとに、その変換パスをビットのシーケンスとして表すことができます。ここで、0 は半分のステップを表し、1 は減分ステップを表します。 必要な倍加ステップの合計数は、最も多くの倍加を必要とする要素によって決まります。`a`。 倍加位置を修正すると、残りのローカル増分を要素ごとに独立して選択できるため、シーケンスを組み合わせてカウントできるようになります。 

したがって、最適なアプローチでは、最初にすべての要素にわたって必要な 2 倍演算の最大数が計算されます。 次に、要素ごとに、各倍増ステップの後に必要な増分数を計算します。 演算の合計は、すべての増分の合計に 2 倍化の最大数を加えたものになります。 シーケンスのカウントは、利用可能な位置全体に増分を分配するための 10^6+3 を法とする二項係数の乗算に帰着します。

 | 最適 | O(n * log max_b) | O(n * log max_b) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.各要素について`i`、差を計算します`d_i = b_i - a_i`。 これは、増分のみを使用した場合に必要な合計増加量を表します。 
2. 2 倍演算の効果を考慮します。 から始まる`b_i`に達するまで、2 で割る (偶数の場合) か 1 を引く (奇数の場合) を繰り返します。`a_i`。 各要素に必要な 2 倍演算の数を追跡します。 これにより、逆方向に作業するときにターゲットをオーバーシュートすることがなくなります。 
3. 2 倍化演算の最小数は、すべての要素にわたって必要な 2 倍化の最大数によって決まります。 これは、各倍増がグローバルであり、最も遅い要素がスケジュールを決定するためです。 
4. 倍加スケジュールが決定したら、倍加の影響を考慮した後、各要素の残りの増分数を計算します。 これらの増分は、相互に相対的に任意の順序で配置できますが、2 倍にすることによって指示される位置を尊重する必要があります。 
5. 配列を組み合わせて数えます。 2 倍化ステップごとに、合計が目標と一致するように要素に増分を割り当てる方法の数を計算します。 10^6+3 を法とするモジュラー算術を使用して、各要素の可能性を乗算します。 
6. 操作の合計数を、最大 2 倍化ステップと合計増分の合計として合計します。 この合計と 10^6+3 を法としたシーケンスの数を返します。 

機能する理由: 逆に作業すると、オーバーシュートが発生しないことが保証されます。`b_i`半分にするか減分すると値が厳密に減少するためです。 最大 2 倍化ステップを計算することで、すべての要素をグローバルに整列させることができます。 組み合わせアプローチを使用したシーケンスのカウントは、2 倍の位置が固定されると各要素の増分が独立するため機能します。 この不変条件により、シーケンスの過小カウントまたは過大カウントが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 10**6 + 3

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        max_pow = 0
        incs = [0]*n
        # compute doublings and increments for each element
        for i in range(n):
            x, y = a[i], b[i]
            pow_count = 0
            inc_count = 0
            while y > x:
                if y % 2 == 1:
                    y -= 1
                    inc_count += 1
                else:
                    y //= 2
                    pow_count += 1
            if y != x:
                inc_count += x - y
            max_pow = max(max_pow, pow_count)
            incs[i] = inc_count

        total_ops = max_pow + sum(incs)
        
        # count sequences
        seq_count = 1
        for inc in incs:
            seq_count = (seq_count * pow(2, inc, MOD)) % MOD
        
        print(total_ops, seq_count)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず複数のテスト ケースの入力を効率的に読み取ります。 各要素の変換は次から逆に追跡されます。`b_i`に`a_i`半減と減分を使用します。 最大倍増ステップはグローバルに追跡され、増分は要素ごとにカウントされます。 最後に、各増分は各 2 倍化ステップの前後に発生する可能性があるため、10^6+3 を法とする 2 の累乗を使用してシーケンスを計算します。
