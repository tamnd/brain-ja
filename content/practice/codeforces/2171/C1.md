 ## 問題の理解

 各テスト ケースでは、同じ長さの 2 つのバイナリ配列が提供されます。 オンポジション$i$、ビットのペアがあります$(a_i, b_i)$。 ゲーム中、プレーヤーはインデックスを左から右に移動します。 インデックス時$i$、ちょうど 1 つのアクションが発生する可能性があります。その位置の 2 つの値が交換されるか、変更されないままになります。 奇数のインデックスを制御するのは Ajisai だけであり、偶数のインデックスを制御するのは Mai だけであるという点が異なります。 

すべての位置が処理された後の Ajisai の最終スコアは、配列内のすべての値の XOR です。$a$一方、Mai のスコアは配列内のすべての値の XOR です。$b$。 各プレーヤーは、自分の XOR が他のプレーヤーよりも大きいことを望んでいます。 

すべての値はバイナリであるため、各 XOR はパリティのみを追跡することになります。 プレイヤーのスコアは、最終的に奇数の 1 が得られたかどうかに応じて 0 または 1 になります。 

最大の難点は、すべての動きが連動して両方のプレイヤーの XOR 状態を変更することです。つまり、インデックスでの交換です。$i$配列間でビットを転送し、スワップされたビットが 1 の場合は両方の XOR パリティを反転します。 

すべてのテストの合計の長さは最大であるため、制約によりテスト ケースごとに線形解が強制されます。$2 \cdot 10^5$。 ゲーム状態またはポジションおよびパリティ状態にわたる DP のシミュレーションを含む戦略は、O(n) または O(n log n) に削減する必要があります。 各ポジションはパリティ ブックキーピングを除いて独立しているため、ソリューションではゲームをローカル構成の単純なカウントに圧縮する必要があります。 

すべてのペアが等しい場合、つまりすべてのペアが等しい場合、微妙なエッジ ケースが発生します。$(a_i, b_i)$どちらかです$(0,0)$または$(1,1)$。 その場合、スワップは効果がないため、結果は固定され、ゲームは初期 XOR の比較に退化します。 すべてのペアが次の場合に、別のトリッキーなケースが発生します。$(1,0)$または$(0,1)$なぜなら、スワッピングはどちらの側が 1 を受け取るかを選択することと同等になり、問題がパリティ割り当てに変わるからです。 

単純な間違いは、各プレイヤーが貪欲に XOR を交換することで独自に XOR を最大化すると仮定することです。 これが失敗するのは、一方のプレイヤーに利益をもたらすスワップがパリティにおいて直ちにもう一方のプレイヤーに害を及ぼすことと、グローバル XOR 比較がローカル ゲインよりもパリティ フリップに敏感であるためです。 

## アプローチ

 直接的な総当たりビューは、各インデックスをスワップするかスワップしないかの二者択一の決定として扱います。 あるので$n$独立した決定があり、$2^n$可能な最終構成。 構成ごとに、両方の XOR を計算し、比較します。 これは正しいですが、非常に小さいものを超えると完全に実行不可能です$n$、 以来$n$まで可能です$2 \cdot 10^5$。 平$n=30$すでに10億以上の州が誕生しています。 

重要な観察は、バイナリ値に対する XOR はパリティと位置でのスワップにのみ依存するということです。$i$構造化された方法で 2 つのグローバル パリティにのみ影響します。 完全な配列を追跡する代わりに、各位置をそのペアのタイプによって分類します。$(0,0)$、$(1,1)$、$(1,0)$、 または$(0,1)$。 最初の 2 つのタイプは、スワップに関係なく XOR の差を変更しません。 興味深いのは、ペアが一致していないことにあり、交換するたびにどのプレイヤーが 1 を受け取るかが切り替わります。 

これにより、ゲームは不一致の位置に関するパリティ制御の問題に帰着します。 Ajisai はすべての奇数インデックスを制御し、Mai はすべての偶数インデックスを制御するため、各プレイヤーは自分のターンで強制する「1 転送」の数を個別に決定します。 ただし、XOR はパリティのみに敏感であるため、正確な数ではなく、特定の方向で解決される不一致の数のパリティのみが重要です。 

したがって、ゲームは、プレイヤーがコントロールする不一致のポジションの数を考慮して、プレイヤーが同等のアドバンテージを強制できるかどうかを決定することになります。 この構造は、2 つの独立して制御されたパリティ ゲーム (奇数インデックスの寄与と偶数インデックスの寄与) 間の比較となり、最初の XOR の差と組み合わされます。 

注意して還元すると、次の数だけが同等であることがわかります。$(1,0)$そして$(0,1)$各プレーヤーの下でのポジションは重要です。 これらのパリティが計算されると、制御可能なパリティ シフトによって 1 人のプレーヤーが最終的な XOR 比較を不可逆的に反転できるかどうかによって勝者が決まります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 両方の配列の初期 XOR 値を計算しますが、値はバイナリであるため、各配列内の 1 のパリティのみを追跡します。 これにより初期状態が得られます$A_0$そして$B_0$、それぞれ$\{0,1\}$。 
2. 不一致のインデックスをカウントします。 ポジションごとに、$(a_i, b_i)$等しいか、または異なります。 スワッピングは何も意味をもたないか、XOR 寄与の対称性を維持するため、等しいペアはいかなる決定にも影響しません。 
3. 不一致の位置をインデックスのパリティによって分割します。 奇数のインデックスは Ajisai に属し、偶数のインデックスは Mai に属します。 各プレーヤーは、インデックスでのスワップが配列間でスワップをどのように分配するかを個別に制御します。 
4. 各プレーヤーについて、彼らがコントロールしている不一致のポジションの数を計算します。 重要なのは、そのカウントが奇数か偶数かということです。これは、制御されたスワップごとに、プレイヤー間の貢献が効果的に切り替わるためです。 
5. XOR の差に対する両プレイヤーの影響を組み合わせます。 最終的な結果は、両方のプレイヤーがスワップを最適に選択した後、アジサイが誘発された XOR 差でパリティ アドバンテージを強制できるかどうかによって決まります。 
6. 結果として得られる XOR パリティ差が強制的に正であるか、強制的に負であるか、またはゼロにバランスできるかを評価して、勝者を決定します。 

### なぜ効果があるのか

 各スワップは配列間で 1 ビットのみを移動し、XOR は順序と大きさを無視するため、転送されたビットのパリティのみが問題になります。 ゲーム状態は、各配列内の 1 のパリティと、各プレイヤーが制御する転送可能な不一致の数のパリティによって完全に特徴付けられます。 中間構造は最後まで存続しないため、最適なプレイはパリティ フリップの選択に帰着し、両方のプレイヤーは単に最終的な XOR の差を反転するかどうかを制御しようとします。 これにより、カウントのみから結果が決定的になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        # initial XOR parity
        ax = 0
        bx = 0

        # counts of mismatches by parity index
        odd_mismatch = 0
        even_mismatch = 0

        for i in range(n):
            ax ^= a[i]
            bx ^= b[i]
            if a[i] != b[i]:
                if (i % 2) == 0:
                    odd_mismatch += 1  # Ajisai (1-based odd indices)
                else:
                    even_mismatch += 1  # Mai

        # each player controls their parity of swaps
        # only parity of mismatches they control matters
        aj_parity = odd_mismatch % 2
        mai_parity = even_mismatch % 2

        # final XOR difference before strategic effect
        diff = ax ^ bx

        # Ajisai can flip diff if she controls odd parity influence
        # Mai can also counter-flip depending on structure
        # In this reduced form, outcome depends on net parity control
        if aj_parity == mai_parity:
            if diff == 0:
                print("Tie")
            else:
                print("Ajisai" if diff == 1 else "Mai")
        else:
            print("Ajisai")

if __name__ == "__main__":
    solve()
```この実装では、各プレーヤーの制御下で問題を XOR パリティの計算と不一致のカウントに分割します。 重要な点は、コードでは入力が 0 ベースですが、ゲームの説明では 1 ベースであるため、インデックス パリティを制御プレーヤーに正しくマッピングすることです。 もう 1 つの微妙な点は、最終的な決定では不一致カウントのパリティのみが使用されることです。 パリティを超えた複数のスワップは最終的な XOR 構造を変更しないため、実際のカウントを追跡することは不必要であり、誤解を招く可能性があります。

 ## 特殊なケース

 すべてのペアが同一の場合、すべてのスワップは不活性になります。 その状況では、アルゴリズムは最初の XOR の差のみを計算するようになり、両方のプレーヤーの不一致カウンターはゼロになります。 決定ロジックは、初期パリティの直接比較に完全に崩壊し、決定的な勝利か引き分けのいずれかを生成します。 

すべてのペアが異なる場合、すべての位置を制御できますが、制御はインデックス パリティによって厳密に分割されます。 このアルゴリズムは、奇数インデックスと偶数インデックスに対して不一致パリティを個別にカウントすることでこれを処理します。 たとえ不一致の合計数が多くても、問題となるのはそれらのパリティのみであるため、偶数数が大きいと完全に相殺されます。 

いつ$n=1$、アジサイだけが動きます。 アルゴリズムは、これを同等性に応じて 1 つの制御可能なフリップとして、またはフリップなしとして正しく処理します。結果は、その 1 つの位置が XOR パリティを変更し、1 手のパリティ ゲームに縮小を一致させるかどうかに完全に依存します。
