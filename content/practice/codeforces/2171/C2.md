 ## 解決策
 ## 問題の理解

 2 つの整数配列で 2 人プレイのゲームをシミュレートするように求められます。`a`そして`b`、それぞれの長さ`n`。 プレイヤーは順番に行動します。あじさいは奇数ターンに移動し、マイは偶数ターンに移動します。 プレイヤーのターンでは、現在の要素を交換できます`a[i]`と`b[i]`またはそのままにしておきます。 Ajisai の目標は、配列内のすべての要素の XOR を最大化することです。`a`最後に、Mai はすべての要素の XOR を最大化したいと考えています。`b`。 後`n`順番が回ってきたら、どのプレイヤーが最適なプレイで勝利を保証できるか、あるいはゲームの結果が引き分けになるかどうかを判断する必要があります。 

入力サイズでは、テスト ケースごとに最大 200,000 個の要素、最大 10^6 の値が許可されます。 これは、すべての可能なスワップ (2^n の可能性) を反復する解決策は実行不可能であることを意味します。 したがって、総当たりの列挙ではなく、ビットレベルの推論または貪欲な意思決定を使用するソリューションを見つける必要があります。 

配列が同一であるか、多くのゼロが含まれている場合、微妙なエッジ ケースが発生します。 たとえば、次の場合`a = [0, 0]`そして`b = [0, 0]`、どちらのプレイヤーもスワップによって XOR を増やすことができないため、ゲームは引き分けになります。 もう 1 つのトリッキーなシナリオは、あるプレイヤーの最適なスワップにより、相手の XOR が自分のプレイヤーよりも大きくなる場合です。 単純で貪欲な戦略は、相手のカウンタープレイを考慮せずに局所的に最大の手を選択する可能性があります。 

## アプローチ

 素朴なアプローチは、スワップの 2^n の組み合わせをすべて試してみることです。 各要素には 2 つの状態 (交換されているかどうか) があり、組み合わせごとに最終的な XOR を計算して、どのプレイヤーが勝つかを確認します。 これは正しいですが、絶望的に遅いです。n = 2 * 10^5 の場合、2^n の可能性のほんの一部でさえ反復することができません。 

重要な洞察は、XOR が各ビットで独立して動作するということです。 各ビット位置を個別に検討してください。 インデックスに関するプレーヤーの決定`i`そのインデックスのそのビットの XOR にのみ影響を与えることができます。 Ajisai は奇数のインデックスを制御し、Mai は偶数のインデックスを制御するため、ビットごとに何個カウントできるか`1`は奇数のインデックスに存在し、偶数のインデックスにはいくつ存在しますか。 そのビットの最終的な XOR は次のようになります。`1`の数であれば`1`配列内のそのビットの s は奇数です。 

各プレイヤーはそのビットを作りたいと考えています`1`彼らの配列と`0`相手のアレイ内で。 これは、各ビットの「Nim ゲーム」の変形に相当します。 慎重な推論の後、最上位の最初の異なるビットが勝者を決定します。配列内のそのビットの 1 のカウント (スワップ オプションを考慮) が特定のパリティ条件を満たしている場合、奇数のインデックスを制御しているプレーヤーが勝ちます。 そうしないと、偶数インデックスのプレーヤーが勝利を強要する可能性があります。 この決定的な点で少しも違いがなければ、ゲームは引き分けです。

 ## アルゴリズムのチュートリアル

 1. すべてのテスト ケースに対してループを初期化します。 テスト ケースごとに、次の内容を読んでください。`n`、`a`、 そして`b`。 
2. 最上位 (10^6 までの値の場合は 20 番目) から最下位 (0 番目) までの各ビット位置について、そのビットが奇数インデックスの位置と偶数インデックスの位置に個別に設定されている要素の数を数えます。 させて`odd`奇数のインデックスでのカウントになり、`even`偶数のインデックスで。 
3. 両方の場合`odd`そして`even`偶数である場合、ビットが寄与します`0`両方のプレイヤーの XOR に変換され、結果には影響しません。 次の部分に進みます。 
4. 少なくとも 1 つがあれば、`odd`または`even`これは奇妙ですが、このビットが決定的です。 最初のプレイヤー (Ajisai) が XOR を強制できるかどうかを決定します。`1`彼らのアレイ上で。 パリティが奇数インデックスのプレイヤーに有利な場合、Ajisai が勝ちます。 偶数インデックスのプレイヤーに有利な場合は、Mai が勝ちます。 
5. すべてのビットをスキャンしても決定的なビットが見つからない場合、ゲームは引き分けとなります。 

機能する理由: 各ビットの XOR は独立しています。 プレーヤーの動きは、制御されたインデックスでのみビットを切り替えることができます。 XOR 比較では上位ビットが下位ビットよりも優勢であるため、最上位ビットから順に分析することで、異なる最上位ビットから勝者を決定できます。 カウントが異なるパリティを生成する最初のビットが、勝利戦略を定義します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        winner = "Tie"
        for bit in reversed(range(21)):  # 0..20 for numbers up to 10^6
            odd = even = 0
            for i in range(n):
                if (a[i] >> bit) & 1:
                    odd += 1 if i % 2 == 0 else 0
                    even += 1 if i % 2 == 1 else 0
                if (b[i] >> bit) & 1:
                    odd += 1 if i % 2 == 0 else 0
                    even += 1 if i % 2 == 1 else 0
            if odd % 2 == 0 and even % 2 == 0:
                continue
            if odd % 2 == 1 and (odd % 4 == 1 or even % 2 == 0):
                winner = "Ajisai"
            else:
                winner = "Mai"
            break
        print(winner)

if __name__ == "__main__":
    solve()
```このソリューションはテスト ケースをループし、各インデックス パリティで設定されたビットをカウントし、決定的なパリティを持つ最上位ビットをチェックします。 0 ベースのインデックスを使用すると、奇数ターンと偶数ターンが問題文と確実に一致します (Ajisai: 奇数ターン → 偶数インデックス)。 微妙な点には、ビットの順序 (上位から順) と 0 から始まるインデックスの一貫した処理が含まれます。
