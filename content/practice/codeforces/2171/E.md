 ## 解決策
 ## 問題の理解

 連続するすべての要素の 3 つの要素において、最大 6 つのインデックスが「不良」になるように、1 から n までの整数の順列を構築するように求められます。 i で始まる 3 つの連続する数値がペアごとに互いに素である場合、インデックス i は不正です。 順列に含まれる不良インデックスが最大 6 つであれば、その順列は適切です。 

より簡単に言うと、連続する 3 つの数値のほぼすべてのグループで、少なくとも 2 つの数値が 1 より大きい共通因数を共有するように、数値 1 から n を並べ替えたいと考えています。不良インデックスを最小化する必要はなく、それらの数が ≤ 6 であることを確認するだけです。 

入力では、テスト ケースの数 t と、その後に t 個の整数 n が続きます。 出力は、適切な順列を表すテスト ケースごとの n 個の整数のシーケンスです。 

制約により、テスト ケースごとに最大 200,000 の n が許可され、すべてのテスト ケースにわたる n の合計も 200,000 で制限されます。 これにより、すべての n! を試行するソリューションは除外されます。 順列。 各テストケースには O(n) 構造が必要です。 エッジ ケースは、小さな n (n=3 など) で発生します。この場合、トリプレットが 1 つだけ存在するため、それが 6 つを超える不良インデックスとしてカウントされないようにする必要があります。 

## アプローチ

 単純なアプローチでは、考えられるすべての順列を試し、6 以下になるまで不良インデックスを数えます。 これは正しいですが、完全に実行不可能です。 n≥10 の場合の合理的な計算よりも速く増加します。 n=10 の場合でも、300 万を超える順列があります。 

重要な観察は、悪いインデックスを数えたり最小化したりする必要がないということです。 **連続する互いに素な三つ組が多すぎるのを防ぐ体系的な方法**が必要なだけです。 連続する整数は互いに素であることがよくあります。 ただし、偶数と奇数を分離すると、2 つの偶数を含む連続するすべてのトリプレットは、少なくとも 1 つのペアで 1 より大きい gcd を持つことが保証されます。 

したがって、すべての偶数を最初に配置し、次に奇数を配置するという建設的なアプローチが可能です。 必要に応じて隣接する要素の小さなスワップをインターリーブすることにより、最大でも一定数 (≤6) の不正なインデックスが表示されるようにすることができます。 これは、境界に小さな奇数のみを持つトリプレットの数が制限されているため、すべての n に対して機能します。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、n を読み取ります。 
2. 2 つのリストを生成します。1 つは 2 ～ n の偶数で、もう 1 つは 1 ～ n の奇数です。 
3. 偶数リストの後に奇数リストを連結して順列を形成します。 
4. この順列を出力します。 

機能する理由: 少なくとも 1 つの偶数を含むすべてのトリプレットは、あるペアの gcd ≥ 2 を持つことが保証されます。 最後の小さな奇数内に完全に収まる 3 連符のみが不良となる可能性があります。 このようなトリプレットを形成する境界には最大でも 6 つの数値があるため、問題の定義によれば、その順列は常に「良好」です。 この方法は線形時間で有効な解を構築し、不良インデックスの数 ≤ 6 という制約を満たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    evens = list(range(2, n+1, 2))
    odds = list(range(1, n+1, 2))
    perm = evens + odds
    print(" ".join(map(str, perm)))
```説明: まず、t 個のテストケースを読み取ります。 各 n について、偶数のリストが次のように生成されます。`range(2, n+1, 2)`奇数と`range(1, n+1, 2)`。 それらを連結すると、不適切なインデックスが多すぎることを回避する順列が生成されます。 最後に、出力のために数値をスペースで結合します。
