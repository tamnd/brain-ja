 ## 解決策
 ## 問題の理解

 いくつかの隠し配列が与えられ、それぞれに少数の異なる整数が含まれています。 配列は 1 から n の順序で並べられており、各クエリでインデックスのリストを選択し、その順序でそれらの配列の連結を受け取ることができますが、要素間に区切り文字はありません。 唯一の追加情報は、連結結果の全長です。 

タスクは、順序も含めて、すべての個々の配列を表示どおりに再構築することです。 

問題は、値が小さいためそのサイズにあるのではなく、配列が不透明なブロックであるという事実にあります。 クエリは、互いにくっついた複数の配列の平坦化されたシーケンスを返します。1 つの配列がどこで終わり、次の配列が始まるかを示す直接のマーカーはありません。 また、クエリは最大 20 個に制限されているため、各インデックスを個別にクエリすることはできません。 

素朴なアプローチでは、各インデックス i を単独でクエリし、配列 ai を直接復元します。 それは正しいのですが、n が 20 を超えるとクエリ制限ですぐに失敗します。したがって、どのソリューションも慎重に選択したバッチ クエリからグローバル構造を抽出する必要があります。 

連結形式によって微妙な問題が発生します。 クエリ結果のすべての値がわかっていても、基になる配列の長さがすでにわかっていない限り、どのセグメントがどのクエリされたインデックスに属しているかはわかりません。 これは、主な困難は値を読み取ることではなく、値をソース配列に位置合わせすることであることを意味します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各インデックスを個別にクエリし、その配列全体を読み取り、保存します。 これが機能するのは、単一インデックスのクエリが曖昧さのない 1 つの配列を返すためです。 この問題は純粋に操作上の問題です。n 個のクエリが発生し、制限の 20 をはるかに超えて、最大 1000 個に達する可能性があります。 

したがって、クエリから抽出された情報を圧縮する必要があります。 重要な点は、各クエリが単に値のリストを返すのではなく、隠れた構造の合計を返しているということです。 各配列は値の固定マルチセットを提供し、複数のインデックスに対するクエリは、それらの配列のマルチセット和集合を同じ順序で返します。 

これにより、問題は署名による身元確認の問題に変わります。 連結されたシーケンス内の境界を見つけようとするのではなく、少数のクエリにわたって各配列に一意の「動作」を割り当て、その動作からメンバーシップを回復します。 

重要な点は、各配列インデックスがバイナリ署名にエンコードされるようにクエリを設計することです。 その後、すべての値は元の配列の署名を継承します。 値が署名によってグループ化されると、各グループは 1 つの非表示配列に対応します。 

残りの唯一の要件は、各インデックスが一意の署名を取得することを保証することです。 最大 1000 個の配列の場合、一意のコードを割り当てるには 10 ～ 20 ビットで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (各インデックスをクエリ) | O(n) クエリ | O(要素の合計) | クエリが多すぎます |
 | ビットマスク署名の再構築 | O(20 · n + 合計要素) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各インデックス i に長さ 20 の個別のバイナリ コードを割り当てます。このコードは配列の識別子として機能します。

1. 0 ～ 19 のビット位置 b ごとに、コード内の b 番目のビットが 1 であるすべてのインデックス i からなるクエリを形成します。応答は、それらのインデックスに属するすべての配列の連結を示します。 すべての戻り値を解析します。 
2. クエリ結果に現れるすべての値 x について、それがビット位置 b に現れたことを記録します。 20 個のクエリすべてにわたって、各値に 20 ビットの署名が蓄積されます。 
3. 各値は 1 つの非表示配列に属しているため、同じ配列のすべての値は同じ 20 ビット署名を共有します。 この署名は、まさにその配列インデックスに割り当てたコードです。 
4. すべての値を、復元された署名に基づいてグループ化します。 各グループは 1 つの元の配列に対応します。 
5. 最後に、各インデックスのバイナリ コードを対応するグループに変換することにより、インデックス順に配列を出力します。 

微妙な点は、連結された応答内の境界を決して推測しようとしないことです。 代わりに、構造化クエリに繰り返し参加して、各値にその起源をラベル付けします。 

### なぜ効果があるのか

 各クエリは、配列インデックスがクエリに関与しているかどうかという少しの情報を定義します。 すべての値は 1 つの配列に永続的に関連付けられるため、その値が出現するたびにその配列の参加パターンが継承されます。 20 個のクエリが集合して各配列の一意の識別子を形成するため、連結の内部順序を再構築することなく値を完全に分類できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())

    B = 20
    groups = {}

    # assign each index a bitmask signature (1 << i)
    # but we encode it across B queries
    for b in range(B):
        query = []
        for i in range(1, n + 1):
            if (i >> b) & 1:
                query.append(i)

        if not query:
            print("? 0")
            sys.stdout.flush()
            _ = input()
            continue

        print("? {} {}".format(len(query), " ".join(map(str, query))))
        sys.stdout.flush()

        data = list(map(int, input().split()))
        total_len = data[0]
        arr = data[1:]

        for x in arr:
            if x not in groups:
                groups[x] = 0
            groups[x] |= (1 << b)

    # now we must invert mapping: signature -> list of values
    rev = {}
    for val, mask in groups.items():
        rev.setdefault(mask, []).append(val)

    # output arrays in index order
    # each index i corresponds to mask i
    res = []
    for i in range(1, n + 1):
        mask = i
        arr = rev.get(mask, [])
        res.append(str(len(arr)))
        res.extend(map(str, arr))

    print("! " + " ".join(res))
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```この実装では、それぞれがインデックス エンコーディングの 1 ビットに対応する 20 個のバッチ クエリを構築します。 各クエリの応答は順番にスキャンされ、検出されたすべての値が、どのクエリに出現したかを示すビットマスクを蓄積します。そのビットマスクがその識別子になります。 

最後の再構成ステップでは、値を同一のマスクごとにグループ化します。 同じ非表示配列に属するすべての値は同じ参加パターンを共有するため、最終的には同じバケットになります。 

主な微妙な点は、各クエリの後にフラッシュすることと、各応答の最初の整数を全長として慎重に解析することです。これは、再構築には必要ないためです。 

## 実用的な例

 これは対話型であるため、単純化された静的シミュレーションを考えてみましょう。 

n = 4 で配列が次のようになると仮定します。 

配列 1: [5, 7]

 配列 2: [2]

 配列 3: [9, 11]

 配列 4: [4]

 バイナリ コード 1..4 を割り当てます。 

1 = 01、2 = 10、3 = 11、4 = 100 (概念的に拡張)

 ビット 0 クエリの場合、インデックス 1 と 3 を要求します。応答には、連結された配列 1 と 3 が含まれます: [5, 7, 9, 11]。 ここでのすべての値はビット 0 でマークされます。 

ビット 1 クエリの場合、インデックス 2 と 3 を尋ねます。応答は [2, 9, 11] を返します。 値 9 と 11 もビット 1 を受け取るようになりました。 

すべてのビットを処理した後、各値には署名が付けられます。 

5,7 → 01

 2→10

 9、11→11

 4→100

 シグネチャによるグループ化により、配列が正確に再構築されます。 

| ビットクエリ | 戻り値 | 更新された署名 |
 | --- | --- | --- |
 | 0 | 5 7 9 11 | 5,7:+1; 9,11:+1 |
 | 1 | 2 9 11 | 2:+2; 9,11:+2 |
 | 2 | 4 | 4:+4 |

 これは、重複するクエリが境界を必要とせずに起点情報をエンコードする方法を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

| スペース | O(要素の合計) | 署名によるグループ化の保存 |

 ## 特殊なケース

 特殊なケースとしては、2 つの配列に同一の値が含まれる場合があります。 その状況では、これらの値はすべてのクエリで同一の動作を共有するため、完全なクエリでも区別できません。 それらの署名は同一であるため、アルゴリズムはそれらを自然に同じグループにマージします。 これは、クエリ内に異なるソースからの同一の値を区別する情報がないという事実を反映しています。 

もう 1 つのケースは、単一の要素を持つ配列です。 このような配列は依然として完全な署名を受け取り、シングルトン グループを形成します。 境界検出が必要ないため、シングルトンはより大きな配列とまったく同じように動作します。 

最後に、非常に不均衡なインデックス パターンは正確さに影響しません。 一部のクエリがスパースである場合でも、すべてのインデックスは依然としてビットの一意の組み合わせに関与しているため、すべての配列には完全な署名が蓄積されます。 

再構築は、連結された応答内の順序付けに依存せず、クエリ全体での一貫した包含パターンのみに依存するため、安定した状態を保ちます。
