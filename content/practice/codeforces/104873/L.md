 ## 解決策
 ## 問題の理解

 頂点が都市の交差点を表し、エッジが一方通行の道路を表す有向非循環グラフが与えられています。 非周期的な条件は、交差点から出発し、指示された道路をたどって最終的に同じ場所に戻る方法がないことを意味します。 これは、すべての有向パスが有限であることをすでに暗示していますが、そのようなパスの長さを制限するものではありません。 

各通りは 3 色のいずれかで塗装する必要があります。 色を付けたら、任意の有向パスを調べ、単一色のエッジのみを考慮します。 単色パスは、すべてのエッジが同じ色を持つパスで、その長さは含まれるエッジの数になります。 要件は、そのような単色パスが 42 エッジを超えてはいけないことです。 

タスクは、この制約が 3 つの色すべてに同時に適用されるように、すべてのエッジに色を割り当てることです。 

この制約では、最大 50,000 個の頂点と 200,000 個のエッジが許可されます。 これにより、エッジまたは頂点上の二次関数、または二次関数に近いものはすべて除外されます。 すべての解は本質的にエッジの数が線形またはほぼ線形である必要があります。$m \log m$は許容されますが、すべてのパスを明示的に探索しようとするものは不可能です。 

微妙な点は、グラフは非巡回ですが、最長の有向パスは依然として非常に大きく、潜在的に線形である可能性があることです。$n$。 恣意的に、または度数などの局所的な情報のみに基づいて色を割り当てた場合、長い単色のチェーンを作成するのは簡単です。 

たとえば、次のような単純なチェーンを考えてみましょう。```
1 → 2 → 3 → 4 → ... → 100
```すべてのエッジが赤色の場合、パス全体は長さ 99 の有効な赤色のパスとなり、直ちに要件に違反します。 素朴な方法で色を交互にしても役に立ちません。色付けが不十分だとパスが構造をスキップし、依然として長く一貫したセグメントを形成する可能性があるからです。 

主要な問題は、すべての長い有向パスが十分な頻度で「色の切り替え」を強制されるように、エッジの色をグローバルに調整する必要があることです。 

## アプローチ

 強引なアイデアは、可能なすべてのパスとすべての色について、最長の単色の継続を明示的に追跡することです。 DAG 内のパスの数は指数関数的に増加する可能性があるため、これはすぐに失敗します。 すべてのパスにわたる動的プログラミングでも、指数関数的に多くの部分構造を組み合わせることが暗黙的に必要になります。 

重要な観察は、DAG であるグラフが自然なグローバル順序付けを与えているということです。つまり、すべての頂点にトポロジー ランクを割り当てることができ、すべてのエッジがその順序で上位ランクから下位ランクへ (または慣例によってはその逆) なります。 これにより、すべてのエッジに沿って厳密に減少する頂点上の単調数値ポテンシャルを定義できるようになります。 

このような可能性が得られると、目標は純粋に組み合わせによるものになります。つまり、色のエッジです。そのため、色を共有するエッジの長いシーケンスによって、この可能性がどのように発展するかに矛盾が生じます。 

42 のような定数境界を強制する標準的な方法は、ポテンシャルを小さな基数表現でエンコードし、桁差の構造を使用することです。 各頂点に、DAG 内の最長パスの深さに等しいラベルを割り当てます。 次に、この整数を基数 3 で書き込み、制限された桁数 (この制約では最大約 11 桁ですが、概念的には最大 42 桁を安全に許容できます) で表現します。 

あらゆるエッジに$u \to v$、グラフは非巡回であるため、深さは厳密に次から減少します。$u$に$v$。 したがって、これら 2 つの数値の 3 進数表現を比較すると、それらが異なる最上位桁の位置が存在します。 その桁の位置を使用してエッジの色を決定し、その位置の桁の値を使用して 3 つの色を区別します。 

これにより、非常に強力な構造特性が作成されます。単色のパスに沿って、すべてのエッジの「識別桁の位置」が強制的に固定されます。 つまり、パスに沿った頂点ラベルの進化は 1 桁の位置内で繰り返し減少するように制約され、その桁がアンダーフローするまでに一定の回数だけ減少する可能性があります。 これにより、単色パスの長さは小さな定数で制限され、安全には 42 以内になります。 

これが機能するのは、カラーリングが構造全体を直接エンコードしようとするのではなく、すべての長いパスが最終的に固定桁レベルの座標の限られた範囲を使い果たすことを強制するためです。

 ## アルゴリズムのチュートリアル

 各頂点の深度値を構築し、数字ベースの比較を使用して色を割り当てます。 

1. DAG のトポロジー的順序付けを計算します。 これが必要なのは、すべてのエッジがこの順序で前から後へ進む必要があり、頂点に対する動的プログラミングが可能になるためです。 
2. 頂点ごとに計算する$v$値$dp[v]$、から始まるパス内のエッジの最大数として定義されます。$v$。 これは、逆のトポロジー順序で計算されます。 この値は、DAG 内のグローバルな「高さ」として機能します。 
3. それぞれを変換する$dp[v]$基数 3 の表現に変換します。 値は最大でも$n$、この表現は短く、明確に定義されています。 
4. 各有向辺について$u \to v$、の進数 3 表現を比較します。$dp[u]$そして$dp[v]$、それらが異なる最上位桁の位置を見つけます。 このポジションに電話をかける$k$。 
5. エッジの色の割り当て$u \to v$位置の数字の値に基づいて$k$で$dp[v]$：桁0はR、桁1はG、桁2はBに対応します。 
6. 各エッジに割り当てられた色を入力順に出力します。 

最上位の異なる桁を使用する理由は、エッジの端点間で上位の桁がすべて同一であることが保証され、同じ色を維持するパスに沿って一貫した「不一致レベル」が強制されるためです。 

### なぜ効果があるのか

 指示された道に沿って、$dp$は厳密に減少するため、基数 3 の表現は、辞書編集的に重要度の高いものから低いものへと減少することによって進化します。 パスが単色の場合、そのパス内のすべてのエッジは同じ最上位の異なる桁位置を選択する必要があります。 これは、パス内のすべての頂点がその位置より上の同一の数字を共有し、その数字だけが遷移を制御することを意味します。 

この桁は最大 2 から 0 までしか減少できないため、それ以上の減少をサポートできなくなるまで変更できるのは一定の回数だけです。 これは、単色パスの長さを、42 をはるかに下回る小さな定数によって直接制限します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def toposort(n, adj):
    indeg = [0] * (n + 1)
    for u in range(1, n + 1):
        for v in adj[u]:
            indeg[v] += 1

    stack = [u for u in range(1, n + 1) if indeg[u] == 0]
    order = []

    while stack:
        u = stack.pop()
        order.append(u)
        for v in adj[u]:
            indeg[v] -= 1
            if indeg[v] == 0:
                stack.append(v)

    return order

def main():
    n, m = map(int, input().split())
    edges = []
    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        edges.append((u, v))
        adj[u].append(v)

    order = toposort(n, adj)

    pos = [0] * (n + 1)
    for i, v in enumerate(order):
        pos[v] = i

    dp = [0] * (n + 1)

    for u in reversed(order):
        best = 0
        for v in adj[u]:
            best = max(best, dp[v] + 1)
        dp[u] = best

    def get_digits(x):
        d = []
        while x > 0:
            d.append(x % 3)
            x //= 3
        return d

    digits = [get_digits(dp[i]) for i in range(n + 1)]

    color_map = ['R', 'G', 'B']

    out = []

    for u, v in edges:
        du = digits[u]
        dv = digits[v]

        k = max(len(du), len(dv)) - 1
        while k >= 0:
            au = du[k] if k < len(du) else 0
            av = dv[k] if k < len(dv) else 0
            if au != av:
                break
            k -= 1

        if k < 0:
            out.append('R')
        else:
            out.append(color_map[dv[k]])

    print("\n".join(out))

if __name__ == "__main__":
    main()
```この解決策は、発信エッジ上の動的プログラミングが明確に定義されるように、トポロジー的順序を構築することから始まります。 dp 配列には、各頂点から始まる最長パスが格納されます。これは、頂点を逆のトポロジー順序で処理することによって計算されます。 

これらの表現は複数のエッジに対して再利用されるため、各 dp 値は一度基数 3 に変換されます。 これにより、エッジ処理中に変換が繰り返されることが回避されます。 

各エッジについて、最初の違いが見つかるまで、桁配列を最上位端から下に向かって比較します。 その位置によって色が決まり、宛先頂点の桁によって 3 つの色のどれが使用されるかが決まります。 異なる桁が存在しないフォールバック ケースは、等しい dp 値に対応します。これは縮退し、固定カラーに安全にマッピングされます。

 ## 特殊なケース

 長い直鎖は最も重要なストレスケースです。 dp 値はチェーンに沿って単調に減少するため、アルゴリズムは各エッジが一貫した桁位置ルールによって管理されることを保証し、均一な色が持続するのを防ぎます。 

高度なソース ノードは、分岐エッジが誤って同一の桁構造を共有するかどうかをテストします。 各エッジは宛先桁を個別に比較するため、発信エッジは 1 つのクラスに集約されるのではなく、自然に色全体に分散されます。 

複数のノードが同一の dp 値を共有する DAG は、桁比較でのフォールバック動作をテストします。 その場合、アルゴリズムは固定の色を割り当てますが、有向パスに沿って同じ dp 値が発生しないため、これらのエッジは長いチェーンを形成できません。
