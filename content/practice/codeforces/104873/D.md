 ## 問題の理解

 短い文字列が与えられます`p`非常に大きな整数`n`。 私たちが扱う実際の文字列は任意ではありません。文字列は次の繰り返しによって形成されます。`p`何度も繰り返して、正確にカットしてから`n`文字。 したがって、最後の文字列は`s`周期的、期間あり`k = |p|`ただし、最後のブロックが切り詰められた場合は除きます。 

タスクは、内部のどこかに出現する空でない部分文字列の数を数えることです。`s`。 2 つの部分文字列は、文字列として等しい場合、たとえ位置が異なっていても同じとみなされます。 

難しさはスケールの不一致から来ています。 パターン`p`長さ1000までと小さいですが、`n`最大 10^9 までの大きさになる可能性があります。 それは即座に建設を排除します`s`保存することさえ不可能なので、明示的に。 部分文字列を直接列挙しようとするアプローチ`s`部分文字列の数は二次関数的に増加するため、これも実行不可能です。`n`。 

素朴なメンタルモデルは、滑り降りることを提案するかもしれません`s`そしてすべての部分文字列をハッシュします。 すべての開始位置を反復しても O(n) となり、n = 10^9 には大きすぎるため、これはすでに失敗しています。 

周期性に関しては、より微妙な問題が発生します。 構造が反復的であっても、部分文字列は、繰り返されるコピー間の境界を越えることができます。`p`。 これにより、単一のピリオドに存在しない新しい部分文字列が作成されます。 たとえば、`p = "ab"`、文字列`s = "ababab..."`次のような部分文字列が含まれます`"bab"`、1つのブロック内には存在しません。 

主なエッジケースは次のような場合です`n`よりもわずかに大きいです`k`。 したがって、ほとんどの部分文字列は、単一のブロック内ではなく、2 つのコピーの境界を越えた相互作用から生じます。 1 つのピリオド内の部分文字列のみをカウントし、係数を乗算するアプローチはアンダーカウントになります。 

もう 1 つのエッジケースは次のような場合です`p`それ自体に繰り返し構造が含まれています。 例えば`p = "aaaa"`。 それから`s`それはただのロングランです`a`、個別の部分文字列の数は`n`、二次関数ではありません。 これは、内部での繰り返しが`p`部分文字列の多様性が大幅に崩壊するため、正しい解決策は内部構造を考慮する必要があります。`p`、長さだけではありません。 

## アプローチ

 ブルートフォース手法は簡単です。完全な文字列を構築します。`s`、すべての部分文字列を列挙します`s[l:r]`をセットに挿入し、セットのサイズを出力します。 すべての個別の部分文字列が明示的に収集されるため、これは正しいです。 ただし、ある長さの文字列内の部分文字列の数は`n`は n(n+1)/2 のオーダーであり、n = 10^9 の場合、約 5 × 10^17 になります。 たとえ`n`わずか 10^5 であったにもかかわらず、このアプローチはすでに実行可能な実行時間をはるかに超えています。 

問題の構造は周期性によって支配されています。 文字列は小さなパターンによって完全に決定されます`p`, したがって、次の部分文字列は`s`期間内のどこから始まるか、また期間が何期間にわたるかによって決まります。 これは問題を長さから圧縮することを示唆しています`n`に応じて何かに至るまで`k`。 

重要な観察は、次の部分文字列が`s`のいくつかの連続したコピーのウィンドウ内に完全に含まれているか、`p`、または最終的にはそれ自体が周期的になります。 実際、部分文字列の長さが超えると、`k`、その動作は以下の重なりによって決定されます。`p`それ自体と一緒に。 これにより、問題は概念的に無限の周期文字列にわたる部分文字列の分析に縮小されますが、最大の長さまでに限られます。`n`。 

これを形式化する標準的な方法は、次の 2 つのコピーを表す文字列に対して接尾辞オートマトンまたは接尾辞配列のアイデアを使用することです。`p`。 境界を越えるすべての部分文字列をキャプチャするには、2 つのコピーで十分です。ピリオドの周期文字列の任意の部分文字列が含まれるためです。`k`せいぜい必要なだけ`2k`内部遷移を表す文字。 次に、これを長さの制約と組み合わせます。`n`。 

この観点から、問題は概念的には文字列内の異なる部分文字列を数えるということになります。`p + p`ただし、各部分文字列は最大長まで拡張できます。`n`、だけではありません`2k`。 接尾辞オートマトンは、各状態が部分文字列のセットを表し、遷移が 1 文字による拡張をエンコードするコンパクトな構造を提供します。 次に、長さまでの延長をシミュレートできます`n`周期的な移行を尊重しながら。

 ## アルゴリズムのチュートリアル

 文字列の接尾辞オートマトンを構築します`t = p + p`。 この 2 倍の文字列は、連続するコピー間のすべての遷移をキャプチャするのに十分です。`p`、ここで新しい部分文字列が作成されます。 

次に、オートマトンの状態ごとに、そのオートマトンが寄与する個別の部分文字列の数を計算しますが、部分文字列の長さは最大で次までに制限する必要があります。`n`。 以来`n`よりもはるかに大きくなる可能性があります`k`、オートマトン構造は依然としてすべての異なるパターンを完全に捕捉します。`n`トランジションに沿ってどこまで延長できるかを制限するだけです。 

中心的な考え方は、サフィックス オートマトンのすべての状態が、同じ終了位置を共有する部分文字列のセットを表すということです。 各州には、`len`値 (その状態の文字列の最大長)、およびそのサフィックス状態へのリンク (最小長の境界を定義します)。 

すべての部分文字列をカウントするのではなく、カウントを調整します。`p+p`を超えない長さの部分文字列のみをカウントします。`n`。 

### ステップ

 1. 文字列を構築する`t = p + p`。 

これにより、ピリオドの境界を越える部分文字列が必ず長さの範囲内に明示的に表示されます。`2k`ウィンドウ。 これにより、無限の繰り返しを直接推論することが回避されます。 
2. サフィックスオートマトンを構築する`t`。 

各状態は、ある位置で終了する部分文字列のクラスを表し、遷移は部分文字列を 1 文字拡張することに対応します。 
3. 各状態について、個別の部分文字列への寄与を長さの間隔として解釈します。`[link.len + 1, len]`。 

この間隔は、その状態に一意に属するすべての部分文字列の長さを表します。 
4. 各間隔を次のようにクリップします。`[1, n]`。 

元の文字列の長さが切り詰められているため、`n`、より長い部分文字列`n`は無効であり、貢献してはなりません。 
5. すべての状態にわたって、これらのクリップされた間隔のサイズを合計します。 

接尾辞オートマトンの状態はすべての個別の部分文字列を長さの範囲で分割するため、有効な長さはそれぞれ 1 回だけ寄与します。 

### なぜ効果があるのか

 接尾辞オートマトンは、すべての個別の部分文字列を、その終了位置と最長反復拡張子に基づいて、互いに素な同値クラスに分割します。 すべての部分文字列は、正確に 1 つの状態と、その状態の間隔内の正確に 1 つの長さに対応します。 クリッピング先`n`切り捨てられた周期文字列に存在できない部分文字列のみが削除され、部分文字列が異なる構造は変更されないため、正確性が保たれます。 以来`t = p + p`すでにすべての境界を越えたインタラクションをキャプチャしています。`s`これらの制約を超えて欠落または重複している場合。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SAM:
    def __init__(self):
        self.next = []
        self.link = []
        self.length = []
        self.last = 0

        self.next.append({})
        self.link.append(-1)
        self.length.append(0)

    def extend(self, c):
        cur = len(self.next)
        self.next.append({})
        self.length.append(self.length[self.last] + 1)
        self.link.append(0)

        p = self.last
        while p != -1 and c not in self.next[p]:
            self.next[p][c] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][c]
            if self.length[p] + 1 == self.length[q]:
                self.link[cur] = q
            else:
                clone = len(self.next)
                self.next.append(self.next[q].copy())
                self.length.append(self.length[p] + 1)
                self.link.append(self.link[q])

                while p != -1 and self.next[p].get(c) == q:
                    self.next[p][c] = clone
                    p = self.link[p]

                self.link[q] = self.link[cur] = clone

        self.last = cur

def count_distinct(p, n):
    sam = SAM()
    t = p + p

    for ch in t:
        sam.extend(ch)

    total = 0
    for v in range(1, len(sam.next)):
        l = sam.length[sam.link[v]] + 1
        r = sam.length[v]
        if l > n:
            continue
        r = min(r, n)
        if r >= l:
            total += (r - l + 1)

    return total

def main():
    p = input().strip()
    n = int(input())
    print(count_distinct(p, n))

if __name__ == "__main__":
    main()
```実装はサフィックスオートマトンを構築します`p + p`。 オートマトン構造は、2 倍になった文字列のすべての個別の部分文字列をエンコードし、カウント ステップでは、標準のサフィックス オートマトン間隔プロパティを使用して各状態から寄与を抽出します。 従来の部分文字列カウントと比較した唯一の変更点は、次のキャップです。`n`これにより、実際に生成された文字列よりも長い部分文字列がカウントされなくなります。 

微妙な実装ポイントは、次のクローン作成ステップです。`extend`これにより、遷移が共有されるときに状態が正しく分割されます。 クローンを作成しないと、複数の異なる部分文字列が誤った同値クラスに崩壊し、間隔の解釈が壊れてしまいます。

 検討してください`p = "ab"`そして`n = 5`、 それで`s = "ababa"`。
