 ## 解決策
 ## 問題の理解

 私たちには、鎖でつながれた一連の船が与えられています。 容器 i と i+1 の間には狭い接続部があり、水位が一定の高さ hi に達した場合にのみ適切な連通管のように動作し始めます。 それ以下の高さでは、水は 2 つの容器の間で自由にバランスをとることができません。 代わりに、片側が橋の高さまで水を満たし、その後反対側に溢れて、両側がそのしきい値に達するまで徐々に水を押し進めます。 

各実験はすべての容器が空の状態で始まります。 選択した開始容器に水を継続的に注ぎます a。 水は、これらの高さの障壁の物理法則に従って広がります。 別の指定された容器に水が最初に現れた瞬間にプロセスが停止する。 実験の答えは、その瞬間までにどれだけの水が注がれていたかです。 

重要な問題は、水が a から b までの経路に沿って瞬時に伝播しないことです。 隣接する両側が独立してその橋の高さに到達した後でのみ各橋を通過します。これにより、ルート上で遭遇する橋の最大高さによって制御される段階的な伝播プロセスが作成されます。 

この制約により、最大 200,000 個の容器と 200,000 回の実験が許可されるため、クエリごとにシミュレーションを再計算するソリューションはすぐに遅すぎます。 クエリごとの線形スキャンでも、最悪の場合は許容範囲をはるかに超える二次的な動作が発生します。 各クエリが対数時間またはほぼ一定の時間で応答できるように、チェーンを前処理する構造が必要です。 

パス上の橋の最大高さが一方の端近くにあり、均等に分散されていない場合、微妙なエッジ ケースが発生します。 最大の高さのみが重要であるという単純な考えは失敗します。コストは、新しいしきい値を超えたときにすでに充填されている容器の数に依存するためです。 たとえば、最大のバリアがパスの早い段階で現れる場合、最大値が同じであっても、システムはそれが終わり近くに現れる場合とは大きく異なる動作をします。 これにより、単一の最大値のみを追跡するソリューションは除外されます。 

もう 1 つの微妙なケースは、a と b が隣接している場合です。 その場合、答えは純粋に単一のブリッジに依存しますが、それでも「通信前の両面充填」ルールを尊重する必要があります。 橋を渡る即時の流れを想定した誤ったショートカットは、必要な量を過小評価することになります。 

## アプローチ

 直接シミュレーションでは、開始容器の水位を繰り返し増加させ、こぼれを伝播させ、b が最初に水を受け取ったときの追跡という物理を模倣します。 水位がわずかに増加するたびに到達可能な領域が変化するため、単純なシミュレーションではパス グラフ上で繰り返し緩和を効果的に実行します。 最悪の場合、水の各単位は O(n) 個の血管を通って伝播する可能性があり、このプロセスはしきい値が増加するたびに最大 O(n) 回繰り返されます。 これにより、クエリごとの動作が O(n²) 以上悪化し、指定された制限では使用できなくなります。 

重要な観察は、水位が橋の高さの 1 つを越えたときにのみシステムの構造が変化するということです。 2 つの連続する橋の高さの間では、トポロジー的な変化はありません。船舶の同じグループは部分的に分離されたままであり、現在の「アクティブ領域のサイズ」のみが問題となります。 これは、各橋が 1 回だけ関連するため、高さの昇順に橋を処理することを示唆しています。 

これにより、問題はパス グラフ上の結合プロセスに変換され、エッジが hi の増加順にアクティブになります。 各アクティベーションは 2 つのコンポーネントをマージし、水を積極的に受け取る領域のサイズを変更します。 クエリの答えは、a を含むコンポーネントが b に到達するまでにどれだけの時間注ぎ続けるかによって決まります。

ただし、このプロセスで各クエリに個別に応答するのはまだ時間がかかりすぎます。 欠けている構造は、これがパス上に Kruskal マージ ツリーを構築するのとまったく同じであるということです。各内部ノードはブリッジのアクティブ化に対応し、ツリーは時間の経過とともにコンポーネントがどのようにマージされるかをエンコードします。 このツリーが存在すると、クエリのコストがバイナリ ツリー上のパス集約問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース シミュレーション | O(n²) | O(n) | 遅すぎる |
 | パス集約を使用した Kruskal マージ ツリー | O(n log n + q log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 このラインを橋の高さ順に並べた合流の階層に変換します。 

1. 各容器をサイズ 1 の最初のコンポーネントとして扱います。 i と i+1 の間の各ブリッジは、重み hi を持つエッジです。 
2. すべての橋を高さの順に並べ替えます。 各橋が完全に使用可能になる瞬間を物理システムの観点からシミュレーションします。 
3. Kruskal マージ ツリーを構築します。 ブリッジが 2 つのコンポーネントを接続するたびに、それらの結合を表す新しい内部ノードが作成され、そのノードにブリッジの高さが割り当てられます。 子はマージされる 2 つのコンポーネントであり、新しいノードのサイズはそれらのサイズの合計になります。 
4. 各内部ノードについて、子サブツリー内から開始してそのノードの合流高さまで容器を上昇させるのに必要な「水コスト」を計算します。 子サブツリーがすでに内部の最大ブリッジ高さに達している場合、その時点からマージ高さまで、そのサブツリー内のすべての容器は固定サイズの単一ブロックとして機能するため、コストはそのサイズに比例して増加します。 
5. この構造をルートにして、すべてのノードについて 2 つの値を計算できます。1 つは左の子から親のマージ高さまで、同様に右の子から上に移動するコストです。 これらの値は、(現在の高さ間隔) にアクティブ コンポーネントのサイズを乗じた形の寄与を累積します。 
6. クエリ (a、b) に答えるために、マージ ツリー内で最も低い共通の祖先を見つけます。 答えは、a から LCA までに移動するコストと、b から LCA まで移動するコストを足したものです。 

### なぜ効果があるのか

 マージ ツリーは、物理システムの構造が変化する瞬間を正確にエンコードします。 各内部ノードは、以前は独立していた 2 つの水域が単一の通信システムになる橋の高さに対応します。 2 つの連続する合流高さの間では、有効成分のサイズは一定であるため、水の蓄積は時間の経過とともに直線的になります。 ルート パスに沿ったコスト分解により、これらの線形セグメントが正確に捕捉されます。 元の線の a から b までのパスはマージ ツリーのリーフ間のパスに対応するため、LCA は進化を 2 つの独立した上向きの進化に分割し、水が両側から合流するまでどのように広がるかを正確に一致させます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return a
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return a

def solve():
    n = int(input())
    h = list(map(int, input().split()))
    t = int(input())
    queries = [tuple(map(int, input().split())) for _ in range(t)]

    m = n
    tot = 2 * n - 1

    # Kruskal tree nodes: 0..n-1 are leaves
    parent = [-1] * tot
    w = [0] * tot
    sz = [1] * tot
    adj = [[] for _ in range(tot)]

    edges = [(h[i], i, i + 1) for i in range(n - 1)]
    edges.sort()

    dsu = DSU(tot)
    nxt = n

    for wt, u, v in edges:
        ru = dsu.find(u)
        rv = dsu.find(v)
        if ru == rv:
            continue
        cur = nxt
        nxt += 1

        parent[ru] = cur
        parent[rv] = cur
        w[cur] = wt
        sz[cur] = sz[ru] + sz[rv]

        dsu.parent[ru] = cur
        dsu.parent[rv] = cur
        dsu.parent[cur] = cur
        dsu.size[cur] = sz[cur]

        adj[cur].append(ru)
        adj[cur].append(rv)

    root = nxt - 1

    LOG = 20
    up = [[-1] * tot for _ in range(LOG)]
    cost = [[0] * tot for _ in range(LOG)]
    depth = [0] * tot

    # find parent-child edge weight structure via DFS
    children = [[] for _ in range(tot)]
    for v in range(n, root + 1):
        for c in adj[v]:
            children[v].append(c)

    def dfs(v):
        for c in children[v]:
            depth[c] = depth[v] + 1
            up[0][c] = v
            cost[0][c] = (w[v] - w[c]) * sz[c]
            dfs(c)

    # initialize roots of original components
    up[0][root] = -1
    cost[0][root] = 0
    dfs(root)

    for k in range(1, LOG):
        for v in range(tot):
            if up[k - 1][v] != -1:
                p = up[k - 1][v]
                up[k][v] = up[k - 1][p]
                cost[k][v] = cost[k - 1][v] + cost[k - 1][p]

    def lift(v, anc):
        res = 0
        diff = depth[v] - depth[anc]
        for k in range(LOG):
            if diff & (1 << k):
                res += cost[k][v]
                v = up[k][v]
        return res

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        diff = depth[a] - depth[b]
        for k in range(LOG):
            if diff & (1 << k):
                a = up[k][a]
        if a == b:
            return a
        for k in reversed(range(LOG)):
            if up[k][a] != up[k][b]:
                a = up[k][a]
                b = up[k][b]
        return up[0][a]

    out = []
    for a, b in queries:
        a -= 1
        b -= 1
        if a == b:
            out.append("0")
            continue
        v = lca(a, b)
        ans = lift(a, v) + lift(b, v)
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このコードは、Kruskal スタイルのユニオンを使用してチェーン上にマージ階層を構築します。 各内部ノードには、2 つのセグメントが結合する高さと、結果として得られるコンポーネントのサイズが格納されます。 DFS は、サブツリーのサイズに子と親のマージ高さの差を乗じたものに等しいコスト寄与を各子に割り当てます。 これは、コンポーネントが拡張している間に注がれた量に直接対応しますが、次のしきい値ではまだマージされていません。 

次に、バイナリ リフティングを使用して、これらのセグメント コストを効率的に蓄積しながら、任意のノードから LCA までジャンプします。 最終的な答えは、両方のエンドポイントから LCA までの上昇コストの合計であり、水が最初にもう一方の容器に到達する瞬間を表します。 

## 実用的な例

 橋の高さが [2、5、3] である小さなシステムを考えて、容器 1 から容器 4 までを尋ねます。 

| ステップ | アクティブなマージの高さ | コンポーネントのサイズ | アクション | 累積コスト |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | [1,1,1,1] | 1 から注ぎ始めます | 0 |
 | 1 | 2 | [2,1,1] | 最初の橋をマージ | 直線的に成長する |
 | 2 | 3 | [3,1] | 2 番目の有効領域をマージ | 増加が早くなります |
 | 3 | 5 | [4] | 完全な接続に達しました | 停止 |

 このトレースは、コストがブリッジの最大値だけでなく、コンポーネントのサイズがどのように増加するかにも依存することを示しています。 

ここで、単一のブリッジの高さが 7 である隣接ノード間のクエリを考えてみましょう。システムはサイズ 1 から開始し、7 まで拡大し、その後すぐに両側を接続します。そのため、コストは、計算されたマージ寄与と一致する、両側の傾き 1 を持つ線形増加関数の下の領域と正確になります。 

## 複雑さの分析

 | --- | --- | --- |

 この制約により、最大 200,000 のノードとクエリが許可されるため、線形前処理による対数クエリ時間は制限内に問題なく収まります。

 ## 特殊なケース

 単一ブリッジの場合、アルゴリズムはマージ ツリー内の 1 つの内部ノードに減ります。 DFS はブリッジの高さに比例する単一のコストを割り当て、両方のエンドポイントがそのノードに直接持ち上げられます。 計算されたコストは、通信が開始されるまで両方の容器を対称的に充填する物理プロセスに等しくなります。 

早期マージ後に a と b が同じ初期コンポーネント内にあるクエリの場合、LCA はツリー内で低くなり、両方のリフト パスが短くなります。 両方のエンドポイントがコンポーネントを共有すると、その祖先を超えてコストがさらに増加することはないため、このアルゴリズムは二重カウントを正しく回避します。 

一方の側がもう一方のエンドポイントに出会う前に繰り返しマージする非常にアンバランスなツリーの場合、バイナリ リフティングにより関連する祖先パスのみが通過されることが保証され、各セグメント コストは各マージ間隔中のアクティブ コンポーネント サイズの増加に正確に対応します。
