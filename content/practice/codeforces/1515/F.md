 ## 解決策
 ## 問題の理解

 この問題は、地震によって国の道路網が破壊され、道路が破壊されたというシナリオを説明しています。`n`都市と`m`道路が寸断された状態。 各都市は一定量のアスファルトから始まり、道路を建設すると一定量のアスファルトが消費されます。`x`、接続されている 2 つの都市のいずれかから供給できます。 アスファルトは、修復された道路ですでに接続されている都市間を流れることができます。これは、ネットワークがリソースの動的なプールを形成することを意味します。 課題は、正確に修復することですべての都市間の接続を回復できるかどうかを判断することです。`n-1`道路を検索し、そうであれば、有効な修復シーケンスを出力します。 

入力により都市の数が得られます`n`、可能性のある道路の数`m`、アスファルトのコスト`x`、初期アスファルト量`a_i`各都市のリストと`m`候補道路。 接続が不可能な場合、出力は「NO」、または「YES」の後に一連のメッセージが続きます。`n-1`有効な修理命令を表す道路インデックス。 

制約は次のことを示します`n`そして`m`まで可能です`3*10^5`アスファルトの量は非常に多くなる可能性があるため、O(n log n) または O(m log n) アルゴリズムが許容されます。 組み合わせ爆発のため、すべてのスパニング ツリーを総当たりで列挙することは不可能です。 修復できるまで未使用のすべてのエッジを繰り返し試行する単純なアプローチでは、時間がかかりすぎて、大きな入力でタイムアウトになってしまいます。 

すべての都市のアスファルトの総量がすべてを接続するのにかろうじて十分な場合、明らかではないエッジケースが発生します。 たとえば、次の場合`n=3`、`x=5`、アスファルトの量は`[2, 3, 5]`、および 3 つの道路すべてが利用可能であるため、間違った開始道路を選択し、アスファルトが不均一に消費されると、不注意な実装は失敗する可能性があります。 もう 1 つの微妙な点は、都市によってはアスファルトがゼロの状態から始まる可能性があるため、他の都市に「供給」するのに十分なアスファルトを有する都市を巻き込む早期接続が必要であることです。 

## アプローチ

 ブルートフォースアプローチでは、エッジを 1 つずつ選択し、接続されたコンポーネントのアスファルトの合計が少なくとも`x`。 これには、未使用のエッジをすべて繰り返しスキャンして接続を維持する必要があり、最悪の場合は O(mn) になります。 と`n`そして`m`3*10^5 までは、これは明らかに実行不可能です。 ブルートフォースは、アスファルトの利用可能性に関する問題のルールに直接従うため機能しますが、スキャンが繰り返されるため、大規模なインスタンスでは失敗します。 

重要な洞察は、都市をグラフ内のノードとして、修復プロセスをスパニング ツリーの構築として見ることで得られます。 アスファルトの合計が以下の接続コンポーネント`x`別の道路を追加することはできないため、十分なアスファルトがあるコンポーネントから常に延長する戦略が必要です。 これは当然、接続されたコンポーネントを維持するためにユニオン検索 (DSU) 構造を使用することと、貪欲なアプローチを使用することになります。つまり、アスファルトの総量が少なくとも`x`。 十分なアスファルトを備えた「アクティブな」コンポーネントのキューと、これらのコンポーネントをまだ接続されていない都市に接続するエッジを優先することで、これを効率的に実装できます。 これにより、各ステップで実行可能なエッジのみが考慮され、不必要なスキャンが回避されます。 

コンポーネントを慎重に結合し、アスファルト全体を更新することで、すべてを修復できます。`n-1`隣接リストとパス圧縮およびサイズによるユニオンを備えた DSU を使用して、O(n + m) 時間で道路を作成します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | O(n + m) | 遅すぎる |
 | 貪欲な DSU | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 都市の数を読み取る`n`、道路`m`、アスファルトの費用`x`、アスファルトの量`a[i]`、および道路リスト`(u, v)`1からインデックスが付けられます。 
2. 接続されたコンポーネントを追跡するために素集合結合 (DSU) 構造を初期化し、各コンポーネントに含まれるアスファルトの合計を保存します。 
3. 各都市のエッジの隣接リストを作成し、近隣と道路インデックスの両方を保存します。 
4. 現在アスファルトが舗装されているすべての都市でキューを初期化します ≥`x`。 これらは、ネットワークを成長させるための出発点の候補となります。 
5. キューが空でない場合:

 ａ． 街をポップする`u`行列から。 

b. すべてのエッジを反復処理します。`u`隣人へ`v`。 

c. 近隣ごとに次のことを確認します。`u`そして`v`DSU を使用する別のコンポーネント内にあります。 

d. その場合は、結合されたコンポーネントのアスファルトの合計が少なくとも`x`。 

e. If the edge is feasible, repair it: append its index to the answer, merge the components in DSU, and update the total asphalt as`(asphalt_u + asphalt_v - x)`。 

f. 新しいコンポーネントにアスファルトがある場合 ≥`x`、そこから代表的な都市を 1 つ押し戻して拡大を続けます。 
6. 処理後、すべての都市が同じコンポーネントに属しているかどうかを確認します。 If yes, print "YES" and the repair sequence. それ以外の場合は、「NO」を出力します。 

これが機能する理由は、常に十分なアスファルトを備えたコンポーネントからネットワークを成長させるためです。 アスファルトは接続されたコンポーネント内に溜まることができるため、実行可能な修理が行われないという状況に遭遇することはありません。 DSU は、サイクルを作成せず、スパニング ツリーに向けてフォレストを拡張するエッジのみを追加することを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

class DSU:
    def __init__(self, n, asphalt):
        self.parent = list(range(n))
        self.size = [1] * n
        self.asphalt = asphalt[:]

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, x, y):
        x_root = self.find(x)
        y_root = self.find(y)
        if x_root == y_root:
            return False
        if self.size[x_root] < self.size[y_root]:
            x_root, y_root = y_root, x_root
        self.parent[y_root] = x_root
        self.size[x_root] += self.size[y_root]
        self.asphalt[x_root] += self.asphalt[y_root]
        return x_root, y_root

n, m, x = map(int, input().split())
a = list(map(int, input().split()))
edges = []
adj = [[] for _ in range(n)]
for idx in range(m):
    u, v = map(int, input().split())
    u -= 1; v -= 1
    edges.append((u, v))
    adj[u].append((v, idx))
    adj[v].append((u, idx))

dsu = DSU(n, a)
used = [False] * m
queue = deque(i for i in range(n) if a[i] >= x)
answer = []

while queue and len(answer) < n-1:
    u = queue.popleft()
    u_root = dsu.find(u)
    for v, idx in adj[u]:
        if used[idx]:
            continue
        v_root = dsu.find(v)
        if u_root == v_root:
            continue
        total = dsu.asphalt[u_root] + dsu.asphalt[v_root]
        if total < x:
            continue
        used[idx] = True
        answer.append(idx + 1)
        new_root, old_root = dsu.union(u_root, v_root)
        dsu.asphalt[new_root] -= x
        if dsu.asphalt[new_root] >= x:
            queue.append(new_root)

if len(answer) == n-1:
    print("YES")
    print("\n".join(map(str, answer)))
else:
    print("NO")
```DSU クラスには、各コンポーネントの親とサイズだけでなく、アスファルト全体も格納されます。 このキューにより、道路に資金を提供できる都市から常に修復を試みることができます。 二重カウントを避けるために、エッジを使用済みとしてマークします。 結合するたびに、結合されたコンポーネントのアスファルトを更新し、さらに修理に資金を提供できる場合はキューに再追加します。 このアルゴリズムは、サイクルのない接続を保証し、アスファルトの制約を尊重します。
