 ## 解決策
 ## 問題の理解

 並んでいます`n`最初はすべてのコンピューターがオフになっており、フェニックスはすべてのコンピューターをオンにしたいと考えています。 彼は、現在オフになっているコンピュータのスイッチを手動でオンにすることができますが、さらに工夫が必要です。隣のコンピュータの両方がすでにオンになっているコンピュータは、手動介入なしで自動的にオンになります。 このタスクは、手動スイッチを何回連続して実行すると、すべてのコンピューターがオンになるかをカウントすることです。 手動で切り替えられるコンピューターのセットが異なる場合、または順序が異なる場合、シーケンスは別個であるとみなされます。 結果は素数を法として報告する必要があります`M`。 

入力`n`は最大 400 まで可能であり、3 次またはそれ以下の多項式複雑さのアルゴリズムが実現可能である可能性があることを示唆しています。 モジュロ`M`は大きくて素数であるため、必要に応じて逆モジュラーを安全に使用できます。 非常に小さなシーケンスでは、微妙なエッジ ケースが発生します。たとえば、次のような場合です。`n = 3`、最初に端のコンピュータの電源をオンにすると、中央のコンピュータが自動的にアクティブになり、手動操作の数が減ります。 自動アクティベーションを考慮しないと、誤ったカウントが得られます。 連続するコンピューターがさまざまな順序でオンになっている場合、別の注意が必要な状況が発生します。単純なカウントでは、自動アクティベーションにより同等のシーケンスが 2 重にカウントされる可能性があります。 

## アプローチ

 ブルートフォース手法では、フェニックスが手動で電源を入れる可能性のあるすべてのコンピュータのシーケンスを列挙することになります。 コンピューターのサブセットごとに、すべての順列を生成し、自動アクティベーションによって最終的にすべてのコンピューターがオンになるかどうかを確認できます。 このアプローチは正しいですが、次の要素に基づいています。`n`そして明らかに実行不可能です`n = 400`、 として`400!`天文学的に大きいです。 

重要な洞察は、セグメントに対する動的プログラミングを使用して、問題を組み合わせてモデル化できることを認識することで得られます。 自動アクティブ化ルールはコンピュータを分割します。アクティブな 2 台のコンピュータの中央にあるコンピュータの電源が自動的にオンになるため、Phoenix がどのコンピュータを手動でアクティブ化する必要があるかに注目するだけで十分です。 これは、手動によるアクティベーションの間に非アクティブなすべてのコンピューターが最終的に自動的にオンになるように、順序付けられたコンピューターのサブセットの数をカウントすることに相当します。 この構造は再帰的であり、DP に自然に適しています。 

定義できます`dp[l][r]`からのコンピュータの部分配列の有効なシーケンスの数として`l`に`r`。 基本ケースはセグメント長が 1 の場合で、これは正確に 1 つの方法でオンにできます。 長いセグメントの場合は、そのセグメントで手動でアクティブ化する「最初のコンピュータ」の可能な選択を繰り返し、左右のサブセグメントのカウントを再帰的に組み合わせることができます。 セグメント内では独立したアクティベーションの順序を自由に変更できるため、階乗は自然に表示されます。 モジュロ演算はモジュロを尊重するために全体で使用されます。`M`。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n) | 遅すぎる |
 | 最適 (DP + 組み合わせ論) | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗および逆階乗モジュロを事前計算する`M`。 These allow fast computation of binomial coefficients, which count ways to interleave sequences of independent subsegments.
 2. DP テーブルを定義する`dp[l][r]`どこ`dp[l][r]`インデックスからのコンピュータの手動アクティベーションの有効なシーケンスの数を表します。`l`に`r`(1 ベース)。 すべてのエントリをゼロに初期化します。 
3.ベースケースを設定する`dp[i][i] = 1`みんなのために`i`。 長さ 1 のセグメントを手動でアクティブにする方法は 1 つだけです。 
4. セグメント長を 2 から 2 まで繰り返します。`n`。 各セグメントごとに`[l, r]`、すべてのポジションを考慮します`k`で`[l, r]`そのセグメント内で手動でアクティブ化された最初のコンピュータとして。 この選択により、セグメントが左側に分割されます`[l, k-1]`そして正しい`[k+1, r]`。 
5. セグメントのシーケンス数を次のように計算します。`dp[l][k-1] * dp[k+1][r] * C(left_size + right_size, left_size)`、 どこ`C(a, b)`は二項係数です。 組み合わせ係数は、最初の手動アクティブ化を基準とした左右のサブセグメントのアクティブ化のすべてのインターリーブを考慮します。 
6. すべての選択肢を合計します。`k`取得するため`dp[l][r]`。 モジュロを適用する`M`各ステップで。 
7. 最終的な答えは次のとおりです。`dp[1][n]`。 

正しさを保証する不変式は次のとおりです。`dp[l][r]`すべてのコンピュータが存在するシーケンスを常にカウントします。`[l, r]`自動アクティベーションに従って、最終的にはオンになります。 より小さいセグメントを再帰的に結合し、インターリーブの可能性を考慮することにより、すべての有効なシーケンスを 1 回だけ列挙します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, M = map(int, input().split())
    
    # Precompute factorials and inverse factorials modulo M
    fac = [1] * (n + 1)
    inv = [1] * (n + 1)
    
    for i in range(2, n + 1):
        fac[i] = fac[i - 1] * i % M
    
    # Fermat's little theorem for modular inverse since M is prime
    inv[n] = pow(fac[n], M - 2, M)
    for i in range(n - 1, 0, -1):
        inv[i] = inv[i + 1] * (i + 1) % M
    
    def C(a, b):
        if b < 0 or b > a:
            return 0
        return fac[a] * inv[b] % M * inv[a - b] % M

    dp = [[0] * (n + 2) for _ in range(n + 2)]
    for i in range(1, n + 1):
        dp[i][i] = 1
    
    for length in range(2, n + 1):
        for l in range(1, n - length + 2):
            r = l + length - 1
            total = 0
            for k in range(l, r + 1):
                left = dp[l][k - 1] if k > l else 1
                right = dp[k + 1][r] if k < r else 1
                left_size = k - l
                right_size = r - k
                total += left * right % M * C(left_size + right_size, left_size) % M
                total %= M
            dp[l][r] = total
    
    print(dp[1][n])

if __name__ == "__main__":
    main()
```階乗により、高速な計算が可能になります。`C(a, b)`事前計算後の一定時間内。 DP テーブルはすべてのセグメントと境界条件を処理します。`dp[l][k-1]`そして`dp[k+1][r]`乗算を簡略化するために、空のサブセグメントの場合は 1 に設定されます。 オーバーフローを防ぐために、モジュロは一貫して適用されます。
