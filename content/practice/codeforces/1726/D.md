 ## 解決策
 ## 問題の理解

 ツリーの向こうに少数の余分なエッジを持つ接続された無向グラフが与えられます。 各エッジについて、色を赤にするか青にするかを決定する必要があります。 色を修正した後、2 つの誘導サブグラフを調べます。1 つは赤いエッジのみで形成され、もう 1 つは青いエッジのみで形成されます。 これらの各サブグラフは頂点を接続されたコンポーネントに分割し、それぞれが生成するコンポーネントの数を数えます。 目標は、これら 2 つのコンポーネント数の合計ができるだけ小さくなるようにカラーリングを選択することです。 

重要な量は、各サブグラフの個別の構造ではなく、エッジが 2 つの色の間でどのように分布するかです。これは、すべてのエッジが一方のサブグラフの接続を同時に助けながら、他方のサブグラフから削除されるためです。 

m が最大でも n + 2 であるという制約は決定的です。 n 個の頂点と正確に n - 1 個のエッジを持つ接続されたグラフはツリーです。 最大 3 つの余分なエッジを追加するということは、グラフのサイクルが非常に少なく、構造上の意味で最大でも 3 つの独立したサイクルしかないことを意味します。 これにより、考慮しなければならない根本的に異なるスパニング構造の数が大幅に制限されます。 2^m は n において指数関数的であるため、エッジの任意の分割をサイズ m/2 または同様の 2 つのセットに分割しようとする解決策は直ちに不可能です。 

単純な考えとしては、色を貪欲にまたはランダムに割り当ててみることです。 これは失敗します。ローカルな決定により、多くのコンポーネントが強制される形で 1 つのカラー クラスが簡単に切断される可能性があるためです。 たとえば、サイクル内で色を交互にしたり、単一の「不良」エッジをカットしたりすると、コンポーネントの数が予期せず増加する可能性があります。 サイクル間の相互作用はグローバルです。サイクルから 1 つのエッジを削除すると、その色のコンポーネントが 1 つだけ増加するため、サイクル エッジを誤って分散すると、c1 と c2 の両方が同時に悪化する可能性があります。 

誤解を招きやすいもう 1 つのケースは、複数のサイクルがエッジを共有する場合です。 「すべてのサイクル エッジを 1 つの色に配置する」などの貪欲なルールでは、その色の成分が減る可能性がありますが、他の色が多くの孤立した頂点に断片化され、c₂ が過剰に増加する可能性があります。 

## アプローチ

 強引に試す場合は、m 個のエッジのそれぞれに赤または青を割り当て、連結成分を 2 回再計算します。 コンポーネントの計算は O(n + m) であるため、ブルート フォースのコストは O(2^m · (n + m)) です。 m ≈ n であっても、これは天文学的な大きさです。 

m が n に非常に近いため、問題の構造は扱いやすくなります。 n - 1 個のエッジを持つ接続されたグラフはツリーであり、追加のエッジごとに 1 つのサイクルが作成されます。 追加のエッジは最大 3 つであるため、グラフはわずか数サイクルの「ほぼツリー」になります。 これは、グラフのスパニング ツリーがすべての接続のバックボーンであり、サイクル構造を変更できるのは少数のエッジだけであることを意味します。 

重要なアイデアは、スパニング ツリーから始めることです。 ツリー エッジは接続に不可欠ですが、非ツリー エッジはサイクルを作成するだけです。 木のエッジの大部分を 1 つの色に割り当て、いくつかのサイクル エッジを慎重に分散すると、各色が誘発するコンポーネントの数を正確に制御できます。 

さらに深い観察は、c₁ + c₂ を最小化することは、両方の色誘発構造の間で「有用性を共有する」エッジの数を最大化することと同等であるということです。 ツリー エッジは本来非対称です。各ツリー エッジは接続にとって重要であるため、それらを分割することでベースライン コンポーネントが決定されます。 サイクル エッジを使用すると、他の色に大きな損傷を与えることなく 1 つの色の接続を「修復」できますが、最大でも 3 つあるため、割り当てパターンをブルート フォースしたり、制御された方法で個別に処理したりできます。 

これにより、スパニング ツリーを構築して一定数の残りのエッジを処理するという問題が軽減され、組み合わせ爆発のリスクなしに構成を明示的にテストしたり、貪欲に割り当てたりすることができます。

 ## アルゴリズムのチュートリアル

 スパニング ツリーを中心にソリューションを構築し、非ツリー エッジを個別に扱います。 

1. まず、DFS または DSU を使用してグラフのスパニング ツリーを構築します。 

このツリーは、すべての頂点が循環せずに接続されている基本構造を定義します。 ツリー以外のすべてのエッジは、サイクルを閉じる追加のエッジとして識別されます。 
2. スパニング ツリーに属するすべてのエッジにマークを付けます。 

これらのエッジは、接続を確保するために必要な最小限のセットです。 ツリーのエッジを削除するとツリーが分割されるため、その割り当てがコンポーネント数の主な要因となります。 
3. スパニング ツリーの一部ではない残りのエッジをすべて収集します。 

m ≤ n + 2 であるため、そのようなエッジは最大 3 つあります。 これらのエッジは、サイクルを形成するエッジに正確に対応します。 
4. これらのいくつかの余分なエッジの赤または青への可能な割り当てをすべて試します。 

エッジは最大 3 つなので、これは最大 23 = 8 件になります。 それぞれのケースについて、各色でどのサイクルが「アクティブ化」されるかを考慮して、接続にどのような影響を与えるかをシミュレートします。 
5. 余分なエッジの割り当てごとに、各色が持つコンポーネントの数を計算します。 

すべてが 1 つの色であれば、木の端だけでも単一の接続された構造が保証されます。 カラーからツリー エッジを削除するか、サイクル エッジによる接続の置き換えに失敗するたびに、コンポーネント数が増加します。 私たちはこれを DSU を使用して一貫して評価します。 
6. c₁ + c₂ を最小にする割り当てを選択し、それに応じて最終的な色付け文字列を構築します。 

構造上の重要な点は、木の端が硬いバックボーンを定義していることです。 目的を改善できる唯一の柔軟性は、少数のサイクル エッジを分散することで得られ、そのスペースは使い果たすほど小さいです。 

### なぜ効果があるのか

 接続されたグラフはすべて、スパニング ツリーと追加のエッジに縮小できます。 スパニング ツリー エッジは、削除によって接続コンポーネントが直接増加する唯一のエッジです。 余分なエッジの数は一定であるため、唯一意味のある組み合わせの選択は、それらの少数のエッジがツリー構造とどのように相互作用するかです。 すべての割り当てを使い果たすことで、c₁ と c₂ の間のトレードオフを改善できる構成を見逃さないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1
        return True

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m = map(int, input().split())
        edges = []
        for i in range(m):
            u, v = map(int, input().split())
            edges.append((u - 1, v - 1, i))

        dsu = DSU(n)
        used = [False] * m
        extra = []

        for u, v, i in edges:
            if dsu.union(u, v):
                used[i] = True
            else:
                extra.append(i)

        # at most 3 extra edges
        k = len(extra)

        best = m + 5
        best_mask = 0

        for mask in range(1 << k):
            red = DSU(n)
            blue = DSU(n)

            for u, v, i in edges:
                if i in extra:
                    idx = extra.index(i)
                    if (mask >> idx) & 1:
                        red.union(u, v)
                    else:
                        blue.union(u, v)
                else:
                    red.union(u, v)
                    blue.union(u, v)

            c1 = len({red.find(i) for i in range(n)})
            c2 = len({blue.find(i) for i in range(n)})

            if c1 + c2 < best:
                best = c1 + c2
                best_mask = mask

        res = ['0'] * m
        for u, v, i in edges:
            if i in extra:
                idx = extra.index(i)
                if (best_mask >> idx) & 1:
                    res[i] = '1'
            else:
                res[i] = '1'

        out.append("".join(res))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず DSU を使用してスパニング ツリーを構築し、サイクルを閉じるエッジを「エクストラ」としてマークします。 このようなエッジは最大でも 3 つしかないため、赤と青の間で考えられるすべての割り当てを列挙します。 割り当てごとに、色ごとに 1 つずつ、2 つの DSU 構造を再構築し、それぞれが誘発する連結成分の数を計算します。 最適な設定が保存されます。 

微妙な点は、この実装では木のエッジが両方の DSU に常に含まれていることです。 これは、ベースラインの接続性が共有され、サイクル エッジのみがグラフの分割方法を決定するという考えを反映しています。 DSU コンポーネントのカウント ステップでは、サイクル強化の欠如によって引き起こされる断片化を正確に捕捉します。

 ## 特殊なケース

 重要なエッジケースは、グラフがすでにツリーになっている場合です。 この場合、余分なエッジがないため、両方の DSU は同じように動作し、すべての構成で c₁ = c₂ = 1 が生成されます。アルゴリズムは当然、同じ色のすべてのエッジを返し、列挙ステップは事実上スキップされます。 

もう 1 つのケースは、すべての余分なエッジが頂点を共有する重なり合うサイクルを形成する場合です。 それでも、それらの数は最大 3 であるため、すべての割り当てを列挙することで、「1 つの色にまとめられた」動作と「複数の色に分割された」動作の両方を確実に評価できます。 DSU の再計算は、これらのサイクルによって断片化が減少するか増加するかを正確に捕捉します。 

最後のケースは、すべての余分なエッジを 1 つの色に割り当てると有益であるように見えますが、実際には他の色の成分が増加する場合です。 徹底的なチェックにより、そのような非対称のトレードオフが直接比較されることが保証され、貪欲なバイアスによって最適なバランスが失われることが防止されます。
