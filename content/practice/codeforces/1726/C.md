 ## 解決策
 ## 問題の理解

 長さのバランスのとれた括弧文字列が与えられます。$2n$。 この文字列内の各位置は、グラフ内の頂点として扱われます。 2 つの頂点$i$そして$j$からの部分文字列が正確に一致するときに、無向エッジによって接続されます。$i$に$j$バランスのとれたブラケットシーケンスをそれ自体で形成します。 

タスクは、このグラフを明示的に構築することではなく、グラフが大きすぎるため、グラフに含まれる連結成分の数を決定することです。 

主な問題点は、エッジがローカルな隣接関係ではなく部分文字列のグローバル構造に依存することです。 元の文字列はすでにバランスが取れていますが、ほとんどの部分文字列はバランスが取れていないため、グラフは暗黙的に疎であり、組み合わせ的に理解する必要があります。 

制約により、線形または線形に近い解決策が求められます。 すべてのテスト ケースの合計の長さは最大でも$10^5$したがって、部分文字列をチェックしたり、ペアごとに接続をシミュレートしようとするアルゴリズムはすぐに失敗します。 平$O(n^2)$単一のテスト ケースがすでに到達している可能性があるため、部分文字列のスキャンは不可能です。$10^5$。 

微妙なエッジ ケースは、すべてのバランスの取れたブラケット文字列を独自にプリミティブ セグメントに分解できるという事実から生じます。プリミティブ セグメントは、バランスのとれた最小のプレフィックスです。 例えば、`"()(())"`に分割します`"()"`そして`"(())"`。 グラフの構造は、これらのプリミティブ ブロックがどのように配置されているかに正確に依存することがわかります。 

単純なアプローチでは、プレフィックスの合計またはスタックを使用してすべての部分文字列の有効性をチェックすることによってインデックスを接続しようとします。 これは、接続性が非常に密であることを誤って示唆しますが、バランスのとれた部分文字列が内部的に決して負にならない正確なゼロサム セグメントに対応する必要があるということを見逃しています。 この制約は、エッジをプリミティブ ブロックの内側に制限するものです。 

## アプローチ

 ブルートフォースソリューションではすべてのペアをチェックします$i < j$かどうかを確認します。$s[i..j]$スタックまたはプレフィックス バランス チェックを使用してバランスをとり、DSU でそれらの頂点を結合します。 単一の部分文字列のコストをチェックする$O(n)$最悪の場合、$O(n^2)$部分文字列、結果として$O(n^3)$実行可能な限界をはるかに超えた行動。 

これは、バランスの取れた部分文字列のチェックがプレフィックスの合計に還元できることに気づくことで改善できます。つまり、部分文字列の合計バランスがゼロで、開始レベルを下回るプレフィックスが含まれていない場合、部分文字列はバランスが取れています。 プレフィックスの合計を使用しても、すべてのペアの反復処理は 2 次のままです。 

重要な構造的洞察は、接続性がバランスのとれたシーケンスの原始的な分解によって完全に支配されるということです。 各プリミティブ ブロックは、バランス ゼロに戻り、内部的にゼロに触れることは決してない、最小のバランス プレフィックスです。 このようなブロック内では、構造が自己完結型コンポーネントのように動作するため、有効なバランスのとれた部分文字列を介して任意の頂点を他の頂点に接続できます。 ただし、2 つの異なるプリミティブ ブロック間では、境界を越えるバランスのとれた部分文字列は存在しません。これは、境界を越えるとプレフィックス バランス制約に違反するためです。 

したがって、各プリミティブ セグメントは、グラフ内の 1 つの連結成分に正確に対応します。 問題は、文字列のスキャン中にプレフィックスの合計が何回ゼロに戻るかを数えることに帰着します。

 ## アルゴリズムのチュートリアル

 1. バランスカウンターを維持しながら、文字列を左から右にトラバースします。`'('`およびデクリメント`')'`。 これは、ブラケット構造内でどれだけ深くネストされているかを追跡します。 
2. バランスカウンターがゼロになると、基本的なバランスセグメントが完了します。 これは、最後のカットポイントから現在位置までの部分文字列が、最小限の自己完結型の有効なブロックであることを意味します。 
3. 残高が 0 に戻るたびに答えが増加します。これは、そのような各イベントがグラフ内の切断されたコンポーネントの終わりを示すためです。 
4. 文字列の終わりまで続けて、すべてのプリミティブがカウントされていることを確認します。 

ステップ 2 の背後にある直感は、ゼロに戻るバランスのとれたプレフィックスは、プレフィックス制約に違反せずに、より小さなバランスのとれた部分に分割できないため、構造単位として機能するということです。 

### なぜ効果があるのか

 プリミティブ セグメントは、実行残高がゼロから始まり、内部は厳密に正のままで、最後にのみゼロに戻る最大の連続領域です。 1 つのプリミティブ ブロック内で始まり、その外側で終了するバランスの取れた部分文字列は、中央でバランスがゼロになる点を通過する必要があり、分解が強制されます。 これにより、エッジがプリミティブ境界を越えて頂点を接続することができなくなります。 プリミティブ ブロック内では、バランスのとれた部分文字列は同じブロック内の頂点のみを接続できるため、ブロック内のすべての頂点は有効なエッジを介して相互に到達可能です。 これにより、プリミティブ ブロックと接続コンポーネントの間に 1 対 1 の対応関係が作成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    bal = 0
    components = 0

    for ch in s:
        if ch == '(':
            bal += 1
        else:
            bal -= 1

        if bal == 0:
            components += 1

    print(components)
```このソリューションは、各テスト ケースを個別に処理します。 バランス カウンタは、文字ごとに一定時間でプレフィックスの有効性を追跡します。 カウンタがゼロに戻るたびに、プリミティブ ブロックが終了し、コンポーネント数が増加します。 

重要な実装の詳細は、バランスをゼロに戻すことによって暗黙的に行われる場合を除いて、何もリセットしないことです。 これにより、明示的なセグメント化や部分文字列の処理が不要になります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output

    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()

        bal = 0
        ans = 0
        for c in s:
            bal += 1 if c == '(' else -1
            if bal == 0:
                ans += 1
        print(ans)

    return output.getvalue()

 ## 特殊なケース

 主なエッジケースは、文字列全体が 1 つの深くネストされた構造である場合です。`"(((())))"`。 この場合、残高は最後に 1 回だけゼロに戻るため、アルゴリズムは 1 つの成分を正しく出力します。 ローカル パターンに基づいて分割しようとすると、誤ってオーバーカウントされてしまいます。 

別のケースは、次のような完全に交互のプリミティブです。`"()()()"`。 2 文字ごとにバランスがゼロになり、3 つのコンポーネントが生成されます。 このアルゴリズムは、各リセットを分割点として自然にキャプチャし、これらのリセット間で交差する部分文字列がないため、接続は各ペア内に限定されます。 

のような混合構造`"(())()()"`ネストされたプリミティブとフラット プリミティブが共存できることを確認します。 最初のリセットはネストされたブロックの後に発生し、後続のリセットは各ブロックの後に発生します。`"()"`、正確に 3 つのコンポーネントが生成されます。 これは、バランスの取れたサブストリングがこれらのリセット ポイントを越えることができないという事実と一致します。これは、そうすることにより、文字列内のプレフィックスのバランスに違反する必要があるためです。
