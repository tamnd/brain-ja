 ## 問題の理解

 あります\(N\)まっすぐな道路に沿って設置されている信号機。 それらの一部は壊れています。`0`文字列内で動作するものは次のように表されます。`1`。 各修理チームは、1 つの連続セグメント内のすべてのライトを修理できます。 チームは選択することも無視することもでき、作業がすでに修復されたライトと重なっている場合でも、追加のチームを選択することができます。 課題は、壊れたすべての照明を少なくとも 1 回修理するチームの異なるサブセットの数を数えるということです。 

答えは、チームの最小数を求めることではありません。 不要なチームを含むサブセットを含め、考えられるすべてのサブセットが重要です。 2 つのサブセットは、異なるチーム インデックスが含まれている場合は異なります。 

両方\(N\)そして\(M\)これにより、チームのすべてのサブセットを試行するものは除外されます。\(2^{5000}\)彼らのうち。 \(O(NM)\) を中心とした解決策は受け入れられます。\(25\)Python では 100 万回の演算が可能ですが、\(O(N^2M)\) のようなアプローチでは限界に近すぎます。

## アプローチ

 直接的な解決策では、次のすべてのサブセットを列挙します。\(M\)チーム。 サブセットごとに、選択したすべてのセグメントでカバーされるライトをマークし、壊れたライトがすべて到達したかどうかを確認できます。 これは正しいです。考えられるすべての答えが 1 回だけ検査されるからです。 ただし、サブセットの数は\(2^M\)、それはすでに不可能です\(M=5000\)。 

有益な観察は、線上の間隔には単純な要約があるということです。 大通りを左から右に走査しているとき、将来に影響を与えるすでに選択されたチームに関する唯一の情報は、現在到達している最も遠い位置です。 どのチームがそのカバレッジを作成したかを知る必要はありません。 

させて`dp[x]`選択されたチーム間の最大の正しいエンドポイントが正確に一致するように、すでに処理されたチームの中からチームを選択する方法の数を表します。`x`。 その位置から開始するチームを処理するとき`i`、そのようなチームを選択すると、同じ最大の正しいエンドポイントが維持されるか、それがチームの正しいエンドポイントまで増加します。 すべてのチームが からスタートした後、`i`の光の場合、考慮されます。`i`壊れています。最大カバレッジがその前に終了するすべての州`i`は無効なので削除されます。 

ブルートフォース手法は、すべてのサブセットを明示的に追跡するため機能します。 サブセットが多すぎるため失敗します。 現在カバーされている最も遠い位置のみが重要であるという観察により、同じ将来の動作を持つすべてのサブセットが 1 つの動的プログラミング状態に圧縮されます。

 ## アルゴリズムのチュートリアル

 1. すべてのチームを左側のエンドポイントごとにグループ化して保存します。 スイープは昇順で位置を処理するため、位置に到着すると`i`そこから始まるチームだけを考慮する必要があります。 

2.初期化`dp[0] = 1`。 これはまだチームを選択していないことを表しており、現在の最大カバーポジションがゼロであることを意味します。 

3. すべてのチームにとって`[i, r]`現在の位置から開始して、このチームが選択されていないか、または選択されているかのように、動的プログラミングの状態を更新します。 現在の最大カバレッジが以下の場合`r`、このチームを選択すると、状態は次のようになります。`r`。 現在の最大値がすでに少なくとも`r`, チームを選択しても状態は変わらないので、その状態は単純に2倍になります。 

4. すべてのチームが開始した後`i`が処理されている場合は、信号機が点灯しているかどうかを確認してください。`i`壊れています。 壊れている場合は、少なくとも最大のカバレッジを持つ州のみ`i`有効です。 小さい状態はすべて破棄されます。 

5. すべての位置を処理した後、残りのすべての状態を合計します。 残りのすべての状態は、すべての壊れた光をカバーしたチームのサブセットに対応します。 

不変条件は、終了後の位置です。`i`、すべての非ゼロ状態`dp`壊れたライトをすべて正しく処理したチームのサブセットの数を正確に表します。`i`、それらのチームがカバーする最も遠い位置ごとにグループ化されます。 壊れたライトが発生した場合、それに到達しない状態を削除すると、無効なサブセットが正確に削除され、すべての有効なサブセットが保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7

def solve():
    n = int(input())
    s = input().strip()
    m = int(input())

    by_left = [[] for _ in range(n + 1)]
    for _ in range(m):
        l, r = map(int, input().split())
        by_left[l].append(r)

    dp = [0] * (n + 1)
    dp[0] = 1

    for i in range(1, n + 1):
        for r in by_left[i]:
            add = 0
            for j in range(r):
                add += dp[j]
            add %= MOD

            for j in range(r + 1, n + 1):
                dp[j] = (dp[j] * 2) % MOD

            dp[r] = (dp[r] * 2 + add) % MOD

        if s[i - 1] == '0':
            for j in range(i):
                dp[j] = 0

    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```配列`by_left`現在の位置から開始するチームを繰り返し検索する必要がなくなります。 動的プログラミング配列には、次のインデックスがあります。`0`に`N`、ここでインデックス`x`現在選択されているチームが正確な位置に到達することを意味します`x`。 

で終わるチームの更新`r`は重要な実装の詳細です。 以下の州`r`すべてが状態に移行します`r`チームが選ばれた場合。 少なくとも州`r`このチームはカバーされる最大ポジションを改善しないため、現在のインデックスのままです。 より大きな州の場合は 2 を掛けると、チームを引き受けるかスキップするかの選択が考慮されます。 

このコードは、変更されるすべての状態が古い値に従って処理されるため、2 番目の配列を必要としない方法で更新を実行します。 以上の位置`r`の値は 2 倍になりますが、`r`すべての小さいポジションの古い値に、次の時点の古い値を加えたものから計算されます。`r`。
