 ## 解決策
 ## 問題の理解

 私たちの生徒の数は奇数であり、各生徒は明確な体力値を持っています。 パートナーのいない生徒を 1 人だけ残し、残りの生徒をすべてペアに分けなければなりません。 ペアは 2 つのメンバーのうち小さい方の強度に寄与するため、強度 10 と 3 のペアは 3 に寄与します。除外される可能性のあるすべての生徒について、すべてのペアの可能な最大の合計寄与が必要です。 

出力は 1 つの値ではありません。 元の生徒ごとに 1 つの答えが含まれています。答えは次の位置にあります。`i`は、その生徒が参加しなかった場合の最高の合計スコアを示します。 

この問題が興味深いのは制約が主な理由です。 まで`3 * 10^5`生徒たちは、考えられるすべての除去を試し、それぞれに最適な組み合わせを再計算する必要があります。およそ 2 次の作業が必要になります。`9 * 10^10`最悪の場合の運用。 これは、競技プログラミング ソリューションが対応できる範囲をはるかに超えています。 1 回の並べ替え後にすべての生徒をまとめて処理できるパターンを見つける必要があります。 

いくつかの特殊なケースでは、一般的な状況のみを処理する実装が機能しなくなる可能性があります。 可能な限り最小の入力では、生徒は 3 人だけです。 たとえば、強みで言えば、`3 1 2`力強く生徒を排除する`3`葉`[1,2]`、スコアは`1`。 削除中`1`葉`[2,3]`、与える`2`。 削除中`2`葉`[1,3]`、与える`1`。 正しい出力は次のとおりです`1 2 1`。 常に最大の生徒がペアに参加することを前提とする解決策は、ここで失敗する可能性があります。 

もう 1 つのよくある間違いは、削除された生徒がソート後に後続のすべての位置のパリティを変更することを忘れていることです。 入力用`1 2 3 4 5`を削除すると`3`、残りのソートされたリストは`1 2 4 5`。 最適なスコアは`1 + 4 = 5`。 元のインデックスを何もシフトしていないかのように扱うと、間違った位置のセットが選択されます。 

## アプローチ

 直接的な解決策は、可能な限りすべての生徒を排除することから始まります。 生徒を 1 人削除した後、残りの強みを分類または維持して、最適なペアを構築します。 偶数の生徒からなる固定ソート済みリストの場合、最適な戦略は簡単に見つかります。つまり、各ペアから小さいメンバーをできるだけ大きく取るというものです。 これは、答えが最後から数えて 2 つおきの要素の合計、または同等の偶数インデックスにあるすべての要素の昇順の合計であることを意味します。 

ブルートフォースアプローチは、排除される可能性のあるすべての生徒に必要な正確な状況をチェックするため、正しいです。 問題は繰り返し作業の量です。 がある`n`削除の可能性があり、それぞれの処理がほぼ必要になります`n`学生たち、につながる`O(n^2)`不要な仕分けを避けてから作業してください。 と`n = 300000`、それはすでに不可能です。 

重要な点は、削除するたびに残りの配列を実際に再構築する必要がないということです。 すべての生徒を一度並べ替えます。 並べ替えられた強みを次のようにします`a[0], a[1], ..., a[n-1]`。 位置にある要素を削除すると`r`、残りの配列内の選択された要素は、前の偶数インデックスとまったく同じです。`r`そしてその後の元の奇数インデックス`r`。 

理由はインデックスシフトです。 削除された位置より前の要素はインデックスを保持するため、偶数の位置は選択された位置のままになります。 削除された位置以降の要素は 1 ステップ左に移動するため、元の奇数インデックスは偶数インデックスになり、答えに寄与します。 

これにより、問題は 2 つの単純な合計を維持することに変わります。 偶数インデックスの値のプレフィックス合計は、除去の左側からの寄与を示します。 奇数のインデックスの値のサフィックスの合計により、右側からの寄与が得られます。 すべての答えは、これら 2 つの値の組み合わせにすぎません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元の位置を維持したまま、生徒を強さ順に並べ替えます。 ペアの寄与はどちらの生徒が弱いかによってのみ決まるため、ソートによって最終的なペアの順序を推論することができます。 
2. プレフィックス配列を構築します。`pref[i]`位置の前に偶数のインデックスを持つソートされた要素の合計を格納します`i`。 学生がそのポジションにいるとき`i`前のすべての偶数位置が削除されます`i`変更せずに貢献し続けます。 
3. サフィックス配列を構築します。`suf[i]`位置からの奇数のインデックスを持つソートされた要素の合計を格納します`i`最後まで。 ポジションを解除した後`i`、その後のすべての要素が 1 位置左にシフトされるため、元の奇数の位置が選択された偶数の位置になります。 
4. ソートされた位置ごとに`i`、計算する`pref[i] + suf[i + 1]`。 これは、ソートされた位置で生徒を削除するための答えです`i`。 プレフィックスは変更されていない左側を処理し、サフィックスはシフトされた右側を処理します。 
5. 並べ替えステップで保存された元のインデックスを使用して、回答を元の入力順序に復元します。 必要な出力は、生徒に与えられた順序に従います。 

機能する理由: 残りの学生の固定セットの場合、最適なペアリングは常に、ソートされた残りのシーケンスの最小要素から始まる 2 つおきの要素を取得します。 1 つの要素を削除すると、その要素以降の位置のパリティにのみ影響します。 削除された位置の前では、選択されたインデックスは元の偶数インデックスとまったく同じです。 その後、選択されたインデックスは元の奇数インデックスとまったく同じになります。 アルゴリズムはこれら 2 つのグループを正確に計算するため、生成されたすべての値が、対応する削除された生徒の最適なスコアとなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = list(map(int, input().split()))

    arr = sorted((value, idx) for idx, value in enumerate(s))

    pref = [0] * (n + 1)
    for i, (value, _) in enumerate(arr):
        pref[i + 1] = pref[i]
        if i % 2 == 0:
            pref[i + 1] += value

    suf = [0] * (n + 1)
    for i in range(n - 1, -1, -1):
        suf[i] = suf[i + 1]
        if i % 2 == 1:
            suf[i] += arr[i][0]

    ans = [0] * n
    for i, (_, original_idx) in enumerate(arr):
        ans[original_idx] = pref[i] + suf[i + 1]

    print(*ans)

if __name__ == "__main__":
    solve()
```ソートステップでは、強度と元の位置の両方が保存されます。 強さの順序はペアリング引数に必要ですが、元のインデックスは最終的な答えを入力順序に戻すために必要です。 

プレフィックス構築では、ソートされた偶数の位置にのみ値が追加されます。 意図的に使用している`pref[i]`立場を答えるとき`i`削除された要素自体を含めてはいけないためです。 

接尾辞の構築は右から左にスキャンし、ソートされた奇数の位置にある値を収集します。 ポジションを外すとき`i`、右側の部分は次から始まります`i + 1`、これが答えが使用する理由です`suf[i + 1]`。 

Python の整数は、可能な合計サイズを自動的に処理します。 考えられる最大の答えは次のとおりです。`1.5 * 10^14`これは、手動処理が必要な言語では 32 ビット整数型をオーバーフローさせます。 

## 実用的な例

 サンプル入力の場合:```
3
3 1 2
```ソートされた配列は`[1, 2, 3]`。 

| ソート位置を削除しました | 接頭辞偶数寄与 | 接尾辞の奇数の貢献 | 答え |
 | --- | --- | --- | --- |
 | 0、値 1 | 0 | 1 | 1 |
 | 1、値2 | 1 | 0 | 1 |
 | 2、値 3 | 1 | 0 | 1 |

 元の順序に戻す`[3,1,2]`与える`[1,2,1]`。 最弱の生徒を除去すると、より強い 2 人の生徒が一緒になるため、真ん中の生徒が最良の結果をもたらします。 

別の例:```
5
1 2 3 4 5
```ソートされた配列はすでに`[1,2,3,4,5]`。 

| ソート位置を削除しました | 接頭辞偶数寄与 | 接尾辞の奇数の貢献 | 答え |
 | --- | --- | --- | --- |
 | 0、値 1 | 0 | 6 | 6 |
 | 1、値2 | 1 | 6 | 7 |
 | 2、値 3 | 1 | 4 | 5 |
 | 3, value 4 | 4 | 0 | 4 |
 | 4, value 5 | 4 | 0 | 4 |

 削除中`2`葉`[1,3,4,5]`、最適なペアが寄与する場所`1 + 4 = 5`。 最初の大きな答えは、選択した位置により多くの大きな要素を保持することによって得られます。

 ## 特殊なケース

 生徒が 3 人だけの場合でも、プレフィックス配列とサフィックス配列に十分な境界位置が含まれているため、アルゴリズムは機能します。 入力用`3 1 2`、ソートされた最初の要素を削除するとサフィックスの寄与のみが使用され、中央の要素を削除するとプレフィックスの寄与が使用され、最大の要素を削除すると最小の値が唯一のペアの寄与として残ります。 

削除された生徒が最初または最後に近い場合、インデックスの移動が最も一般的な間違いの原因となります。 入力用`1 2 3 4 5`、削除`1`葉`[2,3,4,5]`。 答えは、削除された位置の後の元の奇数インデックスを使用します。`3 + 5 = 8`。 サフィックス配列は正確に次の位置から始まるため、このシフトを正しくキャプチャします。 

非常に大きな強度の場合、ペアの数が依然として十分に大きくなり、32 ビットの演算が失敗する可能性があります。 次のような入力`1000000000 1 999999999`生徒が 3 人だけの場合でも 10 億近くの回答が生成され、これより大きなケースでは 32 ビットの制限を超える可能性があります。 実装では Python 整数が使用されるため、累算は正確なままになります。
