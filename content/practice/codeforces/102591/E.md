 ## 解決策
 # 問題の理解

 都市は無向グラフとして表されます。 各交差点は頂点であり、各道路はエッジであり、道路のパスを所有しているということは、そのエッジが移動可能であることを意味します。 Daniyar は、それらの道路によって形成される部分グラフが頂点 1 の自宅からすべてのお気に入りの店まで移動できるように、可能な限り最小の道路セットを選択したいと考えています。 

これは各店舗への最短ルートを個別に求めているわけではありません。 1 本の道路で複数の店舗にアクセスできるため、選択した道路が経路の一部を共有する場合があります。 タスクは、大きなグラフ内の重要な頂点の小さなセットを接続するために必要なエッジの最小数を見つけることです。 

グラフには最大 100,000 個の頂点と 100,000 個のエッジを含めることができます。 これらの制限があると、二次的な作業量でさえ利用可能な操作をはるかに超えるため、多くの可能なエッジ グループを検査するアルゴリズムは不可能になります。 BFS などの通常の最短パス アルゴリズムは、グラフ サイズが線形であるため問題ありませんが、課題は、複数の宛先へのパスを組み合わせる必要があることです。 ショップの数は最大 4 ですが、これがサブセットベースの動的プログラミング ソリューションを可能にする重要な制限です。 

単純なアプローチを破る小さなケースがいくつかあります。 店舗が自宅と同じ頂点にある場合、その店舗にはパスは必要ありません。

## アプローチ

 簡単なアイデアは、頂点 1 からすべての店舗までの最短パスを見つけ、それらのパスからすべてのエッジを取ることです。 これは実装が簡単で、有効なパスのセットが得られます。 問題は、ルート間の共有が無視されていることです。 同じ中間道路を通って 2 つの店舗にアクセスできる場合、このアプローチでは共用部分の料金を複数回支払うことになります。 

別の強引な方法では、考えられるすべてのエッジのコレクションを試し、すべての端末が接続されているかどうかを確認します。 可能なエッジ セットの数は次のとおりです。$2^M$、次の場合はまったく不可能です。$M$100000に達します。 

この問題をシュタイナー木の問題として見るのが正しい方法です。 一般的なグラフでは、任意の端末を接続する最小のツリーを見つけることは困難ですが、ここでは端末の数がわずかです。 覚えているのは、どの重要な頂点がすでに接続されているかだけです。 

端子のすべてのサブセットとすべてのグラフ頂点について、現在の頂点を合流点にしつつ、そのサブセットを接続するために必要な最小限の道路数を保存します。 2 つの小さな接続された構造が同じ頂点で交わる場合、それらをマージできます。 マージ操作が行われるたびに、最短パスの伝播によって改善された値がグラフ全体に広がります。 

ブルートフォースソリューションはグラフ全体を検索空間として扱うため失敗します。 端子が少ないだけという観察により、難しい部分を次のように圧縮できます。$2^K$州、どこで$K$ホーム頂点を追加した後は最大 5 になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | エッジ セットに対するブルート フォース |$O(2^M \cdot (N+M))$|$O(N+M)$| 遅すぎる |
 | 独立した最短パス |$O(K(N+M))$|$O(N+M)$| 一般的に不正確 |
 | サブセット動的プログラミング |$O(3^K N + 2^K(N+M))$|$O(2^K N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 重複するショップ位置を削除し、頂点 1 を端子として追加します。 端末の数は最大 5 つになりました。 

動的プログラミングは特別な頂点のみに依存します。 同じ頂点が複数回出現する場合は、一度接続すると、すべての出現が満たされます。 

1. ステートを作成する`dp[mask][v]`。 マスクはどの端末がすでに接続されているかを示します。`v`接続された構造が現在終了している頂点です。 すべての単一端末状態を、それ自体の端末で値 0 で初期化します。 

単一のターミナルはそれ自体を接続するための道路を必要としません。 他の値はすべて、まだ構築されていないため、無限として始まります。 

1. マスクごとに、空ではない 2 つの素な部分に分割します。 各パーツに最適な構造を同じ頂点で組み合わせてみてください。 

端子セットを接続する構造が1つの場合`a`もう1つは端末セットを接続します`b`、両方を同じ頂点に配置すると、接続された構造が作成されます。`a | b`。 このため、移行は次のようになります。$$dp[mask][v] = \min(dp[mask][v], dp[sub][v] + dp[mask \setminus sub][v])$$1. マスクのすべてのマージ トランジションの後、現在の値を開始距離として使用してマルチソース BFS を実行します。 

マージ ステップでは、1 つの頂点ですでに結合している 2 つの構造のみが許可されます。 BFS は、通常の道路を介してエンドポイントを拡張することを考慮します。 どの道路も 1 パスのコストがかかるため、通常の BFS はまさに必要な最短パス緩和です。 

1. すべてのマスクを処理した後、答えはすべての端子を含む状態での最小値になります。 

最終的に接続された構造は、任意の頂点で終了することができます。 唯一の要件は、すべての重要な頂点が同じ選択された道路のセットに属していることです。 

なぜ効果があるのか:

 不変条件は、マスクを処理した後、`dp[mask][v]`は、からのターミナルを正確に含む、接続されたサブグラフ内の道路の最小数を表します。`mask`頂点を含みます`v`。 最初は、これは単一の端末に当てはまります。 2 つの有効な小さな構造をマージすると、別の有効な接続された構造が作成され、すべての最適な構造は、いくつかの会合頂点で 2 つの小さな末端グループに分離できます。 次に、BFS はグラフ内でミーティング ポイントを移動する最も安価な方法を見つけます。 考えられるすべての分割とすべてのエンドポイントが考慮されるため、完全な端末状態には最適なシュタイナー ツリー サイズが含まれます。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    shops = list(map(int, input().split()))

    graph = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    terminals = [0]
    for x in shops:
        x -= 1
        if x not in terminals:
            terminals.append(x)

    t = len(terminals)
    full = (1 << t) - 1
    inf = 10 ** 9

    dp = [[inf] * n for _ in range(1 << t)]

    for i, vertex in enumerate(terminals):
        dp[1 << i][vertex] = 0

    for mask in range(1, 1 << t):
        sub = (mask - 1) & mask
        while sub:
            other = mask ^ sub
            if sub < other:
                first = dp[sub]
                second = dp[other]
                current = dp[mask]
                for v in range(n):
                    value = first[v] + second[v]
                    if value < current[v]:
                        current[v] = value
            sub = (sub - 1) & mask

        dist = dp[mask]
        queue = deque()

        for v in range(n):
            if dist[v] < inf:
                queue.append(v)

        while queue:
            u = queue.popleft()
            for v in graph[u]:
                if dist[v] > dist[u] + 1:
                    dist[v] = dist[u] + 1
                    queue.append(v)

    print(min(dp[full]))

if __name__ == "__main__":
    solve()
```端末構築では、動的計画テーブルを構築する前に、繰り返されるショップを削除します。 これにより、マスクの数が最小限に抑えられます。 

このテーブルには、端末のサブセットごとに 1 つの行があります。 端子が最大 5 つあるため、状態の最大数は 32 のみです。各状態には、グラフの頂点ごとに 1 つの距離値が含まれます。 

サブセット ループはペアのみを使用します。`sub < other`、重複したマージを回避します。 BFS キューは、すでに有限値を持つすべての頂点から開始され、緩和が複数ソースの最短パス検索に変わります。 

可能な最大の答えは最大でもエッジの数であるため、Python の整数はここではオーバーフローしません。 無限値は、考えられる答えよりもはるかに大きい値が選択されます。 また、グラフ サイズが 100000 になる可能性があるため、この実装では再帰ではなく反復 BFS が使用されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(3^K N + 2^K(N+M))$| 各サブセットはサブセットのマージと 1 つの BFS |
 | スペース |$O(2^K N)$| DP テーブルには、すべてのサブセットとすべての頂点が格納されます。 

ここ$K$はホームを追加した後の一意の端末の数です。$K \leq 5$。 したがって、指数部分はせいぜい小さな定数ですが、グラフ処理は線形のままです。$N+M$。 これは、100,000 個の頂点とエッジの制限に適合します。 

## テストケース```python
import sys
import io
from collections import deque

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, m, k = map(int, input().split())
    shops = list(map(int, input().split()))

    graph = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    terminals = [0]
    for x in shops:
        x -= 1
        if x not in terminals:
            terminals.append(x)

    t = len(terminals)
    inf = 10 ** 9
    dp = [[inf] * n for _ in range(1 << t)]

    for i, x in enumerate(terminals):
        dp[1 << i][x] = 0

    for mask in range(1, 1 << t):
        sub = (mask - 1) & mask
        while sub:
            other = mask ^ sub
            if sub < other:
                for i in range(n):
                    dp[mask][i] = min(dp[mask][i], dp[sub][i] + dp[other][i])
            sub = (sub - 1) & mask

        q = deque(i for i, x in enumerate(dp[mask]) if x < inf)
        while q:
            u = q.popleft()
            for v in graph[u]:
                if dp[mask][v] > dp[mask][u] + 1:
                    dp[mask][v] = dp[mask][u] + 1
                    q.append(v)

    return str(min(dp[-1]))
