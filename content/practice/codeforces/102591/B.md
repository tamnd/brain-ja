 ## 問題の理解

 ベリーを円形に配置しました。 各ベリーには 1 から N までの一意の重みがあり、入力内の順序は円の周りの位置を表します。 移動は、隣接する 2 つのベリーに連続した重みがあり、大きい方がちょうど 1 重い場合にのみ可能です。 重いベリーは軽いベリーを取り除き、それ自体の重さを保ちます。 タスクは、ある一連の動きで重み N のベリーを除くすべてのベリーを除去できるかどうかを判断することです。 

主な観察は、すべてのウェイトに正確に 1 つの食べる可能性があるという事実から来ています。 ベリー k は、ベリー k+1 がまだ生きていて隣接している場合にのみ消滅できます。 k を削除するには k+1 が必要なので、削除の順序は実際には強制されます。 ベリー 1 はベリー 2 の前に、ベリー 2 はベリー 3 の前に、というようにベリー N-1 が最後に消えるまで続きます。 問題は、可能な手を探索することではなく、この 1 つの要求された順序が達成可能かどうかを確認することです。 

N が 2 * 10^5 までの制約により、異なる移動シーケンスを試行するシミュレーションが除外されます。 状態検索には膨大な数の可能性があり、削除のたびに円全体をスキャンする直接シミュレーションでも O(N^2) の操作が必要となり、この入力サイズには多すぎます。 線形または線形に近いアプローチが必要です。 

不適切な実装が失敗する可能性があるエッジケースがいくつかあります。 N = 1 の場合、移動は必要ないため、答えは YES でなければなりません。```
Input:
1
1
```正しい出力は YES です。 常に 1 と 2 の間の隣接性をチェックすることから始まるソリューションでは、存在しない値にアクセスすることになります。 

もう 1 つの微妙なケースは、連続するペアが存在するが、それを早期に削除するのは間違いである場合です。 次のサンプルを考えてみましょう。```
Input:
4
4 1 3 2
```ペア 3 と 2 は隣接していますが、最初に 2 つを削除すると、有用なイーターが存在せずに 4 と 1 が分離されたままになるため、ゲームは終了できません。 有効な手が存在するかどうかを常にチェックするだけのソリューションでは、間違った結果が得られます。 

円形の境界も重要です。 例えば：```
Input:
3
2 1 3
```値 1 と 2 は円を介して隣接しているため、2 が 1 を食べ、次に 3 が 2 を食べます。正しい出力は YES です。 最初の位置と最後の位置の間の接続を忘れた実装では、このケースが誤って拒否されます。 

## アプローチ

 ブルートフォース ソリューションでは、考えられるすべての有効な手を試し、考えられるすべての除去順序を再帰的に探索します。 これはルールに正確に従っており、少なくとも 1 つのパスが 1 つのベリーに到達する場合に受け入れられるため、これは正しいです。 問題は、可能なパスの数が急速に増加することです。 ベリーがほんの少ししかない場合でも、複数の選択肢がある可能性があり、N = 2 * 10^5 の場合、このアプローチは完全に不可能です。 

重要な観察は、総当たりが実際には存在しない選択肢を探索するということです。 撤去命令は強制される。 k+1 は k を削除できる唯一のベリーであるため、ベリー k はベリー k+1 より前に削除する必要があります。 k+1 が消滅すると、その後 k が消滅することはありません。 これにより、プロセス全体が、1、次に 2、そして 3 などをそれぞれ適切なタイミングで削除できるかどうかを確認するだけになります。 

残りの課題は、要素が円から消える間、隣接性を維持することです。 配列で表される二重リンクリストで十分です。 すべての重みについて、現在の左右の近傍の重みを保存します。 重み k が削除されると、その 2 つの近傍が隣接するようになります。 各ベリーは 1 回ずつ取り除かれるため、全体の作業は直線的になります。

 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 循環リンクリストを作成します。 すべてのベリー値について、どの値がそのすぐ左側にあるのか、どの値がすぐ右側にあるのかを保存します。 入力順序により、最後の位置と最初の位置の間の接続を含む、この情報が直接得られます。 
2. ベリーを 1 から N-1 まで昇順に処理します。 ステップ k で、ベリー k が現在ベリー k+1 の隣にあるかどうかを確認します。 これがｋが消える唯一の方法である。 
3. k+1 が k の左隣でも右隣でもない場合、必要な削除順序は発生し​​ないため、答えは NO です。 
4. k を削除できる場合は、その 2 つの近傍を直接接続し、リンク リストから k を破棄します。 次の反復は、更新された円に対して動作します。 
5. 1 から N-1 までのすべての値をこの順序で削除できれば、ベリー N だけが残るので、答えは YES です。 

なぜ効果があるのか:

 不変条件は、値 k を処理する前に、k より小さいすべての値がすでに削除されており、k から N までのすべての値がまだ存在していることです。 k+1 が k を食べることができる唯一の存在であるため、k+1 が消える前にベリー k が消えなければなりません。 これにより、すべての有効なゲームで除去順序の増加が必要になります。 アルゴリズムは、必要な削除が必要なときに実行できるかどうかを正確にチェックし、リンク リストの更新により、すべての削除後に真の循環隣接関係が維持されます。 すべてのチェックが成功した場合、同じ一連の削除がゲームを終了する有効な方法となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        print("YES")
        return

    left = [0] * (n + 1)
    right = [0] * (n + 1)

    for i, x in enumerate(a):
        left[x] = a[(i - 1) % n]
        right[x] = a[(i + 1) % n]

    for x in range(1, n):
        if left[x] != x + 1 and right[x] != x + 1:
            print("NO")
            return

        l = left[x]
        r = right[x]
        right[l] = r
        left[r] = l

    print("YES")

if __name__ == "__main__":
    solve()
```の`left`そして`right`配列は、位置ではなくベリーの重みに基づいて近傍を格納します。 削除順序は元のインデックスではなく重みに基づいているため、これは便利です。 

1 から N-1 までのループは強制消滅命令に従います。 x を削除する前に、円には固定の始まりがないため、コードは両方向をチェックします。そのため、x+1 はどちらの近傍になる可能性があります。 

x が削除されると、その左隣と右隣が隣接します。 代入により二重リンクリストの両方向が更新されるため、元の配列のシフトが回避されます。 これは、O(N) ソリューションと、リストの途中から繰り返し削除するソリューションとの違いです。 

最大 2 * 10^5 までのインデックスと値のみが保存されるため、オーバーフローは問題になりません。ここでは Python の整数で十分です。

```| 現在の値を確認 | 左隣 | 右隣 | 必要なネイバー | アクション |

 ベリー 1 が隣接するにはベリー 2 が必要ですが、隣接するベリー 1 は両方とも 4 と 3 です。ベリー 1 が最初に必要な削除であるため、後の操作は役に立ちません。 答えは「ノー」です。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | すべてのベリーは 1 回初期化され、多くても 1 回削除されます。 
| スペース | O(N) | サイズ N + 1 の 2 つの隣接する配列が格納されます。 

このソリューションはベリーごとに一定量の作業のみを実行するため、制約に適合します。 メモリ使用量も線形なので、最大 2 * 10^5 の N に適しています。

def solution(inp: str) -> str:

    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        return "YES\n"

    left = [0] * (n + 1)
    right = [0] * (n + 1)

        left[x] = a[(i - 1) % n]

        if left[x] != x + 1 and right[x] != x + 1:
            return "NO\n"
        l = left[x]
        r = right[x]
        right[l] = r
        left[r] = l

    return "YES\n"

assert solution("4\n4 1 3 2\n") == "NO\n", "sample 2"

 ## 特殊なケース

 シングルベリーの場合:```
Input:
1
1
```削除するものがないため、アルゴリズムはすぐに YES を返します。 これにより、存在しない重み 2 にアクセスしようとすることが回避されます。 

サンプルの失敗例の場合:```
Input:
4
4 1 3 2
```削除命令は強制されているため、アルゴリズムは最初に重み 1 をチェックします。 その隣は 4 と 3 であるため、ウェイト 2 はイーターとして使用できません。 アルゴリズムは直ちに停止し、NO を返します。 

循環隣接の場合:```
Input:
3
2 1 3
```リンク リストには、1 の近傍が 2 および 3 として格納されます。2 が左の近傍であるため、最初のチェックは成功します。 1 を削除すると 2 と 3 が結合され、次のチェックも成功します。 アルゴリズムは配列を線ではなく円として正しく扱うため、YES を返します。
