 ## 解決策
 ## 問題の理解

 コンピュータのスピーカーの音量は現在次のように設定されています。`X`に変更したいと思います。`Y`。 毎秒、正確に 1 つの操作を実行できます。 操作により音量が増減します。`1`またはによって`Z`。 ボリュームは常に次の有効範囲内にある必要があります。`0`に`100`、各操作後に到達する中間値を含みます。 タスクは、ターゲット ボリュームに到達するまでに必要な最小秒数を計算することです。 

制約は非常に小さいです。 可能なすべてのボリュームは次の範囲の整数です。`0`そして`100`、したがって、状態空間全体には次のものだけが含まれます。`101`頂点。 このような小さなグラフを使用すると、到達可能なすべての状態を直接調査できます。 すべての状態で 4 つの遷移が生成されたとしても、総作業量は 1,000 操作を大幅に下回ります。 幅優先検索などのグラフ アルゴリズムは、制限内に問題なく収まります。 

状態空間を検索する代わりに数式を導出しようとすると、いくつかのエッジ ケースが見落とされやすくなります。 

もし`Z = 0`、大きな動きは何もしません。 例えば：```
Input:
5 8 0
```正しい答えは、`3`、なぜなら、`+1`音量が変わります。 で割ることに基づく式`Z`ゼロによる除算が定義されていないため、失敗します。 

ターゲットから一時的に離れることが有益な場合には、別の微妙なケースが発生します。 考慮する：```
Input:
1 4 5
```答えは`3`。 最適なシーケンスの 1 つは、`1 -> 0 -> 5 -> 4`。 目標に向かって進むだけの貪欲な戦略では、決してこの道を発見することはできません。 

境界値も重要です。 例えば：```
Input:
100 99 10
```答えは`1`。 ボリュームから`100`増やすことはできません`10`中間状態は有効な範囲内に留まらなければならないためです。 どの実装でも、間隔を離れる動きを拒否する必要があります`[0, 100]`。 

## アプローチ

 最も直接的な解決策は、考えられるすべてのボリュームを状態として表示することです。 1 つのボリュームから 4 つの操作を試行できます。`1`、減算`1`、 追加`Z`、減算します`Z`。 すべての操作には 1 秒かかるため、すべてのエッジの重みは同じになります。 開始ボリュームから幅優先検索を実行すると、所要時間の短い順に状態にアクセスします。 初めて目標に到達するときの最小秒数がわかりました。 

総当り検索でもすでに高速です。`101`州。 最悪の場合、幅優先検索は各状態を 1 回処理し、4 つの出力遷移を検査します。その結果、`404`移行チェック。 

閉じた形式の数式を構築しようとすることは、見た目よりもはるかに困難です。 両方向に移動できる機能、すべての中間ボリュームが内部に留まるという制限`[0, 100]`、および特殊なケース`Z = 0`多くのコーナーケースを作成します。 問題を最短経路の問題として扱うと、これらすべての複雑な問題が解消されます。 幅優先検索は、状況ごとに個別の推論を必要とせずに、迂回路、境界、繰り返し操作を自然に処理します。

 ## アルゴリズムのチュートリアル

 1. サイズの距離配列を作成します`101`すべての値を次のように初期化します`-1`。 この配列は、各ボリュームに到達するまでに必要な最小秒数を記録します。 
2. 開始ボリュームの距離を設定します`X`に`0`そして押します`X`列に並びます。 幅優先検索では、常に距離が増加する順に状態を展開します。 
3. フロントボリュームをキューから繰り返し削除します。 
4. 適用して次の 4 つの可能なボリュームを生成します。`+1`、`-1`、`+Z`、 そして`-Z`。 
5. 間隔外にある生成されたボリュームをすべて無視します。`[0, 100]`、そのような動きは許されないからです。 
6. 有効なボリュームがこれまでにアクセスされたことがない場合は、その距離を現在の距離に 1 を加えたものとして割り当て、キューにプッシュします。 幅優先検索は長いパスの前に短いパスを探索するため、最初の訪問が常に最適です。 
7. キューが空になるか、目標ボリュームに達するまで続行します。 
8. 記録された距離をボリュームに出力します`Y`。 

### なぜ効果があるのか

 幅優先検索では、キューから削除されたすべての状態が開始状態から可能な最小距離をすでに持っているという不変条件が維持されます。 許可されたすべての操作には正確に 1 秒かかるため、すべてのグラフ エッジの重みは同じになります。 新しい状態が発見されると、可能な限り短い一連の操作によってその状態に到達します。 ボタンを押すすべての正当なシーケンスはこのグラフ内のパスに対応し、すべてのグラフのパスは正当な操作シーケンスに対応します。 幅優先検索では重み付けされていないグラフの最短パスが計算されるため、記録された距離は`Y`まさに最低限必要な時間です。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve():
    x, y, z = map(int, input().split())

    dist = [-1] * 101
    dist[x] = 0

    q = deque([x])

    while q:
        cur = q.popleft()
        if cur == y:
            break

        for nxt in (cur + 1, cur - 1, cur + z, cur - z):
            if 0 <= nxt <= 100 and dist[nxt] == -1:
                dist[nxt] = dist[cur] + 1
                q.append(nxt)

    print(dist[y])

if __name__ == "__main__":
    solve()
```距離配列には 2 つの目的があります。 既知の最短時間を保存し、ボリュームがすでにアクセスされているかどうかもマークします。 これにより、同じ状態を複数回処理することが回避されます。 

すべての反復では、正確に 4 つの候補手を考慮します。 境界チェックは距離配列にアクセスする前に行われるため、次のような無効なボリュームが存在しません。`-1`または`101`安全に無視されます。 

早期退場時`cur == y`はオプションですが、最適な答えがすでに見つかった後の不要な作業を回避します。 

実装では次のことも処理します。`Z = 0`当然。 その場合のトランジションは`cur + z`そして`cur - z`どちらも等しい`cur`、すでに訪問されているため、無限ループは発生しません。

## テストケース```python
import sys
import io
from collections import deque

def solve():
    input = sys.stdin.readline
    x, y, z = map(int, input().split())

    dist = [-1] * 101
    dist[x] = 0
    q = deque([x])

    while q:
        cur = q.popleft()
        if cur == y:
            break
        for nxt in (cur + 1, cur - 1, cur + z, cur - z):
            if 0 <= nxt <= 100 and dist[nxt] == -1:
                dist[nxt] = dist[cur] + 1
                q.append(nxt)

    print(dist[y])

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    solve()
    sys.stdin = backup_stdin
    sys.stdout = backup_stdout
    return out.getvalue()

assert run("0 10 3\n") == "4\n", "sample 1"
assert run("10 0 3\n") == "4\n", "sample 2"
assert run("0 0 5\n") == "0\n", "already at target"
assert run("5 8 0\n") == "3\n", "Z equals zero"
assert run("100 99 10\n") == "1\n", "upper boundary"
assert run("1 4 5\n") == "3\n", "temporary detour"
```| テスト入力 | 期待される出力 | 検証内容 |

 |`0 0 5`|`0`| 開始時のボリュームはすでにターゲットと等しくなります。 |
 |`5 8 0`|`3`| 大きな移動の長さはゼロです。 |
 |`100 99 10`|`1`| 有効範囲外の移動は拒否されます。 |

 ## 特殊なケース

 いつ`Z = 0`、グラフには、によって生成された自己ループが含まれています。`+Z`そして`-Z`。 考慮する：```
Input:
5 8 0
```検索は次から始まります`5`。 ゼロを加算または減算して生成された移動は、`5`、すでに訪問されているため、無視されます。 幅優先検索は次まで継続します`6`、`7`、 そして`8`、正解を導き出す`3`。 

迂回が必要な場合でも、幅優先検索は、より長いパスに移動する前に現在の距離ですべての状態を探索するため、成功します。 入力用```
1 4 5
```検索は到達します`0`一歩進んだ後、`5`2つのステップを経て、最後に`4`3つのステップの後。 ターゲットとの絶対差を常に減らす貪欲なアルゴリズムでは、このシーケンスは決して考慮されません。 

現在のボリュームがすでに最大境界にある場合、不正な移動は直ちに破棄されます。 のために```
100 99 10
```への移行`110`有効範囲外のため無視されます。 残りの法的措置は、`99`1 秒で目標に到達します。これが最適な答えです。
