 ## 解決策
 ## 問題の理解

 バイナリ正方行列が与えられ、行と列の巡回シフトを使用してそれを並べ替えることができます。 これらのシフトは値を変更せず、位置を回転するだけです。したがって、最終的に重要なのは、ビットを反転するために支払いを開始する前に行列をどのように調整するかです。 

行と列の回転シーケンスを選択した後、個々のセルを反転 (0 から 1 または 1 から 0 に切り替える) することができ、各反転には 1 単位のコストがかかります。 目標は、行列を単位行列に変換することです。つまり、すべての対角セルは 1 であり、すべての対角以外のセルは 0 でなければなりません。 

重要な難点は、対角線を元の位置に固定する必要がないことです。 行と列を循環的にシフトすることにより、行インデックスの循環シフトと列インデックスの循環シフトを効率的に選択できます。 これは、対象とする対角線が固定されていないが、元の行列に対して「移動」できることを意味します。 

各テスト ケースは独立しています。 行列のサイズは最大 2000 で、テスト全体のセルの総数は最大 400 万個であるため、どのソリューションでもアライメントごとに 3 次または繰り返しの大量の再計算を回避する必要があります。 

単純なアプローチでは、すべての行シフトとすべての列シフトを試行し、O(n^2) 個のアライメントを与えます。 それぞれの位置合わせについて、対角線とそれ以外をすべてゼロにするために必要な反転の数を計算します。 これには O(n^3) のコストがかかり、遅すぎます。 

あるシフトの下ではマトリックスがすでに対角線に近い構造を持っているが、他のシフトの下ではそうではない場合、微妙なエッジケースが現れます。 たとえば、順列のような行列では、1 つの特定の巡回アライメントだけが完全な対角線を生成します。 行シフトのみまたは列シフトのみが重要であると想定する不用意なアプローチは、両方の次元が相互作用するため失敗します。 

## アプローチ

 シフト演算を無視する場合、問題は単純です。恒等と比較して不一致のセルをすべて反転する必要があります。これは恒等行列との差をカウントするだけです。 複雑なのは、最初に行と列を循環的に回転できることです。 

ブルートフォース戦略は、循環シフトの可能なすべてのペア (行に 1 つと列に 1 つ) を試行することです。 シフト ペアを適用した後、すべてのセルをチェックし、行列をユニタリにするために必要な反転の回数を数えます。 行シフトには n 個の選択肢があり、列シフトには n 個の選択肢があり、各評価のコストは O(n^2) であるため、計算をどれだけ慎重に再利用するかに応じて、合計の複雑さは O(n^4) または O(n^3) になります。 いずれにせよ、これは n の制限 (2000 まで) をはるかに超えています。 

重要な洞察は、シフトでは行と列のみが循環的に再インデックスされるということです。 マトリックスの移動について考える代わりに、ターゲットの対角線の選択について考えることができます。 巡回シフト行列の対角は、j - i が n を法とする定数であるインデックスのペア (i, j) に対応します。 したがって、各シフト構成は対角オフセットの選択に対応します。 

対角オフセット d を固定すると、すべてのセル (i, j) は、j - i ≡ d (mod n) の場合は対角線上にあり、それ以外の場合は非対角線上にあるとして分類されます。 固定 d の場合、コストを直接計算できます。対角セルは 1 になる必要があり、対角以外のセルは 0 になる必要があります。コストは不一致をカウントするだけです。 

したがって、n^2 のシフト ペアを試行する代わりに、n 個の可能な対角オフセットを試行するだけで済みます。 各評価には O(n^2) のコストがかかり、O(n^3) になります。 これは最悪の場合でもまだ大きすぎます。 

各セルが各対角線の選択に独立して寄与していることを観察することで、さらに削減します。 A[i][j] が 1 の場合、ちょうど 1 つの対角オフセット (j - i がそのオフセットと一致する場合) に役立ちます。 他のすべてのオフセットでは、0 であるべき非対角セルであるため、そこに 1 があるとペナルティが発生します。 同様に、0 が選択された対角線上にある場合、ペナルティが発生します。

O(n^2) でオフセットごとの寄与を事前計算できます。セルごとに 2 つの集約構造を更新します。1 つは各対角線上に 1 がいくつ入るかを数え、対角外のコストを暗黙的に導き出します。 これにより、テスト ケースごとに合計 O(n^2) で最適なオフセットを計算できます。 

これにより、配置の検索からモジュラー対角クラスごとのコントリビューションの集約までの問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシフト | O(n^4) | O(n^2) | 遅すぎる |
 | すべての対角線を直接チェックする | O(n^3) | O(n^2) | 遅すぎる |
 | 対角寄与度の集計 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 不一致コストを最小限に抑える対角オフセットを選択するという問題を再構成します。 

1. 考えられるすべての対角オフセット d について、その対角線上にあるものがいくつあるかを計算します。 対角クラスを (j - i mod n) によって定義します。 選択した対角線上のセルのみが 1 である必要があるため、この手順が必要です。 
2. オフセット d ごとに、対角セルの数 (正確に n) を計算します。 したがって、対角外のセルは n^2 - n になります。 
3. 固定 d の場合、コストは次のように計算されます。0 を含むすべての対角位置は 1 に反転され、1 を含むすべての非対角位置は 0 に反転されます。これにより、コストが 2 つの独立した部分に分割されます。 
4. 各 d について、事前に計算されたカウントを使用してコストを計算します。 

対角線の不一致は (n - ones_on_diagonal[d]) です。 

対角線以外の不一致は (total_ones - ones_on_diagonal[d]) です。 
5. 総コストは次のようになります。 

コスト[d] = (n - 対角線上の対角[d]) + (対角線上の対角の合計[d])。 
6. すべての d を反復処理し、最小コストを取得します。 

これが機能する理由は、巡回シフトによって (j - i mod n) の同じ値を共有するセルが変化しないためです。 主要な対角線とみなされる対角線だけを回転させます。 したがって、すべての有効なシフトされた構成は、これらの対角クラスの 1 つを選択することに正確に対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t_line = input().strip()
    while t_line == "":
        t_line = input().strip()
    t = int(t_line)

    for _ in range(t):
        line = input().strip()
        while line == "":
            line = input().strip()
        n = int(line)

        grid = []
        total_ones = 0

        for _ in range(n):
            row = input().strip()
            grid.append(row)
            total_ones += row.count('1')

        diag_ones = [0] * n

        for i in range(n):
            row = grid[i]
            for j, ch in enumerate(row):
                if ch == '1':
                    diag_ones[(j - i) % n] += 1

        ans = 10**18

        for d in range(n):
            ones_on_diag = diag_ones[d]
            cost = (n - ones_on_diag) + (total_ones - ones_on_diag)
            ans = min(ans, cost)

        print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、モジュラー差分 (j - i) を使用して、対角クラスごとにすべての 1 を集計します。 これは、考えられるすべての循環行および列シフトの影響をエンコードします。 次に、対角線の内側と外側で必要な修正の数を計算することで、各対角線の選択を評価します。 

微妙な点は、シフトを明示的にシミュレートすることは決してないということです。 モジュロ インデックス作成では、考えられるすべての巡回アラインメントがすでにキャプチャされています。 

## 実用的な例

 ### 例 1

 入力:```
n = 3
010
011
100
```合計と対角寄与を計算します。 

| 私 | j | A[i][j] | (j - i mod 3) |
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | 1 |
 | 1 | 1 | 1 | 0 |
 | 1 | 2 | 1 | 1 |
 | 2 | 0 | 1 | 1 |

 したがって、diag_ones = [1, 3, 0]、total_ones = 4 となります。 

次にコストを評価します。 

d = 1 の場合、対角には 3 つの 1 があるため、対角反転 = 3 - 3 = 0、非対角反転 = 4 - 3 = 1、合計 = 1 となります。 

他の d 値の場合、コストは大きくなります。 

これにより、最良の位置合わせは、対角クラス 1 が主対角になるようにシフトすることに対応していることが確認されます。 

### 例 2

 入力:```
n = 2
10
10
```すべての 1 は列 0 にあります。 

| 私 | j | A[i][j] | (j - i mod 2) |
 | --- | --- | --- | --- |
 | 0 | 0 | 1 | 0 |
 | 1 | 0 | 1 | 1 |

 したがって、diag_ones = [1, 1]、total_ones = 2 となります。 

どちらの d 値でも、コスト = (2 - 1) + (2 - 1) = 2 となります。 

これは対称性を示しています。シフトなしで位置合わせが向上し、両方の対角線は同等に有効ですが、依然として 2 回の反転が必要です。

 ## 特殊なケース

 最小限の 1x1 マトリックスには構造的自由がありません。 唯一の要件は、単一セルを 1 に等しくすることです。そのため、セルが 0 から始まる場合は、1 回の反転が必要です。 対角クラスが 1 つしかなく、計算が直接的な不一致数に減少するため、アルゴリズムはこれを処理します。 

完全にゼロで満たされた行列には、対角位置合わせの利点がありません。 すべての対角位置はゼロであり、反転する必要があるため、対角の選択はすべて同じコストを生成します。 diag_ones[d] がすべての d に対してゼロであり、コストが一定になるため、アルゴリズムはこれを反映します。 

1 で満たされた行列は、非対角ペナルティを強調します。 配置を最大化するために対角線が選択された場合でも、対角線以外のものはすべて反転する必要があります。 この式は、total_ones - diag_ones[d] を通じてこれを直接取得し、非対角補正の正確な累積を保証します。
