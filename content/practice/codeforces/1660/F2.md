 ## 解決策
 ## 問題の理解

 プラス記号とマイナス記号のみからなる文字列が与えられます。 この文字列の部分文字列は、連続する 2 つのマイナスを 1 つのプラスに繰り返し置き換えることによって、バランスのとれた文字列、つまりプラス記号とマイナス記号の数が等しい文字列に変換できる場合に有望とみなされます。 各入力文字列について、空ではない有望な部分文字列をすべて数え、同じ部分文字列が異なる位置に出現するたびに重複を数えるよう求められます。 

制約は重要です。 各文字列には最大 200,000 文字を含めることができ、最大 10,000 のテスト ケースを含めることができます。 すべてのテスト ケースにわたる文字列長の合計も 200,000 に制限されています。これは、ソリューションの文字列長がほぼ線形である必要があり、理想的にはテスト ケースごとに O(n) または O(n log n) である必要があることを意味します。 すべての部分文字列を個別にチェックする単純なソリューションでは、テスト ケースごとに O(n²)、つまり最大 4×10¹⁰ の操作が必要になりますが、これは 2 秒の制限時間では実現不可能です。 これは、すべての部分文字列を明示的に生成または検査することはできないことを意味します。 

微妙なエッジ ケースには、マイナスだけで構成される文字列、プラス記号とマイナス記号が交互に並ぶ文字列、非常に短い文字列などがあります。 たとえば、文字列「----」には「--」や「----」のような有望な部分文字列がありますが、置換操作によってバランスの取れたシーケンスが生成される回数を正確に考慮する必要があります。 置換操作の影響を考慮せずに単純に部分文字列をカウントすると、一部の有望な部分文字列が過小評価されてしまいます。 同様に、文字列「+-+-」は 2 文字の部分文字列ごとにすでにバランスが取れているため、不用意なアプローチではインデックス付けに応じて過大にカウントされたり、過少にカウントされたりする可能性があります。 

## アプローチ

 ブルートフォース手法は簡単です。 考えられるすべての部分文字列を反復処理し、各部分文字列について、「--」を「+」に置き換えることを繰り返しシミュレートし、結果の文字列のバランスが取れているかどうかを確認します。 これは原理的には機能しますが、O(n²) 個の部分文字列が必要であり、置換のシミュレーションでは部分文字列ごとに O(n) の係数が追加される可能性があり、最悪の場合は O(n³) になります。 明らかにこれは非現実的です。 

重要な洞察は、数値バランスの観点から部分文字列を表現することから得られます。 プラスを +1、マイナスを -1 とみなします。 バランスの取れた部分文字列の正味合計はゼロになります。 置換操作は、「-2」(2 つの連続するマイナス) を「+1」に変換し、実質的に残高を 3 増やすものとして解釈できます。これにより、部分文字列を左から右に走査して累積和 (または残高) を維持しながら、最小残高が後続の置換によって補償できないレベルを下回らない場合、その部分文字列は有望であることがわかります。 残高プレフィックスの合計を追跡し、ハッシュ マップを使用して、O(n) 回で調整された各プレフィックスの出現をカウントできます。これは、古典的な問題でゼロサム部分配列を数えるのと同様です。 

この変換により、問題は弦を 1 回スキャンし、実行中のバランスを維持し、マップを使用してそれぞれの有効なバランスが発生する頻度を追跡し、置換操作の効果を注意深く調整することに軽減されます。 これにより、すべての部分文字列を明示的に生成する必要がなくなります。

 ## アルゴリズムのチュートリアル

 1. 文字列を数値に変換します。「+」の場合は +1、「-」の場合は -1。 これにより、文字列操作の代わりに整数の合計を操作できるようになります。 
2. 変数を初期化する`balance`ゼロと辞書へ`count`調整された残高の発生を追跡するため。 から始めます`count[0] = 1`空のプレフィックスを考慮するため。 
3. 文字列を 1 文字ずつ走査し、更新します`balance`各文字の数値に応じて。 
4. 奇妙な位置でマイナスが発生するたびに (または、バランスをとるために交換が必要になる可能性がある状態に)、`balance`これにより、事前に交換操作が効果的にシミュレートされます。 
5. 辞書を調べる`count`調整された電流に対して`balance`。 このバランスが以前に発生した回数は、現在の文字で終わる有望な部分文字列の数を示します。 この数だけ答えを増やします。 
6. ディクショナリ内の現在の調整済み残高のカウントをインクリメントします。 
7. 文字列の最後まで続けて、すべての寄与を合計して、有望な部分文字列の総数を計算します。 

なぜ機能するのか: 維持される不変条件は次のとおりです。`count[balance]`現在の位置で終わる有望な部分文字列を形成するために拡張できるプレフィックス部分文字列の数を表します。 置換操作を考慮してバランスを調整すると、最終的にバランスの取れた文字列に変換できるすべての部分文字列が正しくカウントされるようになります。 各文字で終わるすべての接頭辞が、そこで終わるすべての有効な部分文字列に寄与するため、有望な部分文字列が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

for _ in range(int(input())):
    n = int(input())
    s = input().strip()
    
    balance = 0
    count = {0: 1}
    result = 0
    
    for ch in s:
        if ch == '+':
            balance += 1
        else:
            balance -= 1
        
        # Adjust balance to account for replacement of -- with +
        adj_balance = balance
        while adj_balance % 2 != 0:
            adj_balance -= 3
        
        result += count.get(adj_balance, 0)
        count[adj_balance] = count.get(adj_balance, 0) + 1
    
    print(result)
```コードは実行バランスを維持し、潜在的な置き換えの影響を捉えるように調整します。 辞書を使用すると、以前のカウントへの O(1) アクセスが保証されます。 文字列上のループは文字列の長さに比例した線形時間を保証し、3 による調整は累積的な方法で置換操作をキャプチャします。
