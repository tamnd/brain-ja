 ## 問題の理解

 次の文字列が与えられます。`'+'`そして`'-'`。 空ではないすべての部分文字列について、それが「有望」であるかどうかを判断する必要があります。 

操作を適用した後、部分文字列は有望であると言えます。```
"--" -> "+"
```何度でもバランスのとれた文字列を得ることができます。つまり、最終的な文字列には同じ数のプラスとマイナスが含まれます。 

この操作では、隣接する 2 つのマイナス記号が削除され、1 つのプラス記号に置き換えられます。 すべてのアプリケーションはシンボルの長さと数の両方を変更するため、これらの数がどのように変化するかを正確に理解する必要があります。 

簡単なバージョンの長さは最大 3000 で、すべてのテスト ケースの長さの合計も最大 3000 です。これは、$O(n^2)$解決策が意図されています。 がある$O(n^2)$部分文字列なので、部分文字列ごとに一定の時間または小さな償却時間を費やすことは許容されます。 アン$O(n^3)$アプローチには大まかに必要になります$27 \cdot 10^9$最悪の場合は動作が制限され、限界をはるかに超えています。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

部分文字列を考慮してください`"---"`。 

カウントは次のとおりです。```
plus = 0
minus = 3
```バランスが取れていません。 しかし、ひとつの操作でこうなります。`"+-"`、バランスが取れています。 この部分文字列の正しい答えは有望です。 現在のカウントが均衡しているかどうかをチェックするだけのソリューションでは、この問題を見逃してしまいます。 

部分文字列を考慮してください`"--"`。```
plus = 0
minus = 2
```1 回の操作で生成される`"+"`。 

プラスが 1 つ、マイナスが 0 つになり、バランスが取れていません。 それ以上の操作はできません。 この部分文字列は期待できません。 差が縮まるかどうかだけを確認するという安易なアプローチでは、誤って受け入れてしまう可能性があります。 

部分文字列を考慮してください`"-+-"`。 

隣接はありません`"--"`どこにもないため、操作は実行できません。 弦のバランスが取れていないため、期待できません。 カウントのみを使用し、可用性を無視するソリューションは、`"--"`ペアはここで失敗します。 

## アプローチ

 最も直接的なアプローチは、すべての部分文字列を列挙し、考えられるすべての操作シーケンスをシミュレートすることです。 これは文字通り定義に従っているので正しいです。 残念ながら、操作の選択が異なると中間文字列も異なる可能性があり、可能性の数は指数関数的に増加します。 貪欲にシミュレーションしようとしても、やはりお金がかかってしまいます。$O(length)$部分文字列ごとに以上、少なくとも$O(n^3)$時間。 

重要な観察は、実際には最後の文字列自体を気にしていないということです。 ある数の演算によってプラスとマイナスのカウントが等しくなるかどうかだけを気にします。 

部分文字列に次のものが含まれているとします。 

-$p$プラス記号
 -$m$マイナス記号

 各操作で 2 つのマイナスが消費され、1 つのプラスが作成されます。 

操作を適用した後$k$回:

 - プラスになる$p + k$- マイナスになる$m - 2k$結果として得られる文字列のバランスを保つには、$$p+k = m-2k$$それは与える$$3k = m-p$$したがって、必要な操作の数は一意に決定されます。$$k = \frac{m-p}{3}$$これにより、すぐに 2 つの必要条件が得られます。 

初め、$m-p$負ではなく、3 で割り切れる必要があります。 

次に、実際に実行できなければなりません。$k$操作。 

利用できる操作はいくつありますか? すべての操作には、隣接するマイナス記号のペアが必要です。 させて$c$の出現数になります`"--"`部分文字列の内側。 

重要な事実は、各操作がそのようなペアを 1 つ消費し、部分文字列に$c$隣接するマイナスのペアは、最初は最大でも実行できます$c$操作。 この問題に関しては、まさにそれが必要な情報です。 

したがって、部分文字列は次の場合に有望です。$$m-p \ge 0$$

$$(m-p) \bmod 3 = 0$$

$$c \ge \frac{m-p}{3}$$以来$n \le 3000$、すべて列挙できます$O(n^2)$部分文字列を保持し、以下を維持します。 

- 現在の残高$m-p$- 隣接するマイナスペアの現在の数

 右のエンドポイントを拡張しながら段階的に拡張します。 

それにより、$O(n^2)$解決。

 ## アルゴリズムのチュートリアル

 1. 開始位置を固定する`l`。 
2. 初期化します。 

-`diff = 0`を表す`(minus - plus)`現在の部分文字列内。 
-`pairs = 0`、隣接する数を表します`"--"`現在の部分文字列内のペア。 
3. 右側のエンドポイントを延長します`r`から`l`に`n-1`。 
4.追加する場合`s[r]`:

 - そうだとしたら`'-'`、増分`diff`。 
- そうだとしたら`'+'`、デクリメント`diff`。 
5. もし`r > l`そして両方とも`s[r-1]`そして`s[r]`は`'-'`、増分`pairs`。 

これにより、隣接するマイナスのペアがすべて 1 回だけカウントされます。 
6. 必要な操作数は次のとおりです。$$k=\frac{\text{diff}}{3}$$でもそのときだけ`diff >= 0`そして`diff % 3 == 0`。 

1. もし

 -`diff >= 0`-`diff % 3 == 0`-`pairs >= diff // 3`この部分文字列は有望であるため、答えに 1 を追加します。 
2. すべての開始位置について繰り返します。 

### なぜ効果があるのか

 部分文字列の場合$p$プラスと$m$マイナス、バランス調整後$k$操作には必要なもの$$p+k=m-2k.$$並べ替えると$$k=\frac{m-p}{3}.$$したがって、必要な操作の数は固定されています。 もし$m-p$負であるか、3 で割り切れません。有効な整数ではありません$k$存在します。 

各操作は、隣接するマイナスのペアを 1 つ消費する必要があります。 させて$c$は部分文字列内のそのようなペアの数になります。 私たちがパフォーマンスできるのはせいぜい$c$操作なので、必要な$k$満たさなければなりません$k \le c$。 

これらの条件も十分です。 いつでも$k \le c$、選択できます$k$隣接するマイナスのペアを正確に実行します$k$操作、カウントに達する$$(p+k,\;m-2k),$$これらは構造的には等しい。 したがって、部分文字列は、アルゴリズムがそれを受け入れるときに正確に約束されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    
    for _ in range(t):
        n = int(input())
        s = input().strip()
        
        ans = 0
        
        for l in range(n):
            diff = 0      # minus - plus
            pairs = 0     # number of "--" pairs
            
            for r in range(l, n):
                if s[r] == '-':
                    diff += 1
                else:
                    diff -= 1
                
                if r > l and s[r] == '-' and s[r - 1] == '-':
                    pairs += 1
                
                if diff >= 0 and diff % 3 == 0 and pairs >= diff // 3:
                    ans += 1
        
        print(ans)

solve()
```外側のループは部分文字列の左端を固定します。 内側のループは、右端を一度に 1 文字ずつ拡張します。`diff`店舗`minus - plus`両方のカウントを別々に保持するのではなく。 バランス条件はそれらの差のみに依存するため、これで十分です。 

新しいキャラクターが追加されるたびに更新します`diff`一定時間内に。 また、新しいキャラクターと前のキャラクターが結合しているかどうかもチェックします。`"--"`ペア。 そうすれば、`pairs`1つ増えます。 

受け入れ条件は、まさに以前に導出された数学的特徴付けです。 順序が重要です。 まず必要なのは`diff >= 0`負の値は負の操作数を意味するためです。 次に、3 で割り切れる必要があり、最後に十分な数の隣接するマイナスのペアが存在することを確認します。 

すべてのカウンターは Python 整数に快適に収まり、ペア チェックは次の場合にのみ実行されるため、インデックス作成の落とし穴はありません。`r > l`。
