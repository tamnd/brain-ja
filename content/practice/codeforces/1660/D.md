 ## 解決策
 ## 問題の理解

 各値の絶対値が -2 から 2 までと非常に小さい整数の配列が与えられます。この配列から、連続した中間セグメントを残してプレフィックスとサフィックスを削除することができます。 残りのセグメントは空である可能性もあります。 

タスクは、残りの数値の積ができるだけ大きくなるように、左右のどこを切り取るかを選択することです。 すべてを削除すると、積は 1 として定義されるため、空の部分配列が常に有効な候補になります。 

各テスト ケースは独立しているため、製品自体ではなく、前後から削除された要素の数を出力するだけで済みます。 

制約は全体として厳しく、すべてのテスト ケースで合計要素数は最大 200,000 です。 これにより、積の二次計算または位置ごとの再計算が即座に排除されます。 すべてのソリューションは、テスト ケースごとに線形であるか、すべてのテストにわたって線形に償却される必要があります。 

ここでは、いくつかのエッジ動作が重要です。 ゼロを含むセグメントは積 0 を持ち、空のセグメントが 1 を生成するよりも悪いため、ゼロは特に重要です。負の値は符号の反転を引き起こすため、単一の要素を削除または保持すると積の符号が変わる可能性があります。 たとえば、`[-1, -1]`の場合、完全な積は 1 ですが、すべてを削除しても 1 になるため、複数の回答は同点になります。 

考えられるすべての部分配列の積を再計算する単純な戦略は、O(n²) 個の部分配列があるため失敗します。 プレフィックス積を事前に計算したとしても、ゼロを処理し、最適なカットを選択するには、算術演算だけでなく、符号の変化についての推論が必要です。 

## アプローチ

 ブルートフォースソリューションでは、カット位置のすべてのペアを試します。`(l, r)`私たちが保管するという意味`a[l..r]`、その積を計算し、最大値を追跡します。 これには O(n²) 個のサブ配列が必要で、プレフィックス積が注意深く維持されている場合、各積の計算は O(1) ですが、ゼロと負のパリティを処理するには、依然として慎重な再計算またはリセットが必要です。 最適化を行ったとしても、すべての有効なセグメントを列挙するのは、合計 2e5 の要素に対して遅すぎます。 

重要な点は、任意の部分配列が要求されるのではなく、連続したセグメントのみが要求され、値が {-2, -1, 0, 1, 2} に制限されることです。 この制限により構造が崩壊します。ゼロのみが配列を独立したブロックに分割し、各ブロック内の符号は負のパリティによってのみ決定されます。 

ゼロのないブロック内では、すべてを保持することで積の絶対値が最大化されます。 要素を削除する唯一の理由は、符号を修正するかゼロを避けることです。 ゼロは積をゼロにリセットするため決定的であり、最適なセグメントはすべてのゼロを回避するか、符号補正された大きさを最大化する慎重に選択された領域を含みます。 

これをより正確に確認する方法は、ゼロ以外の要素のすべての位置を考慮することです。 最適なセグメントは、ゼロのない最大の間隔内にある必要があり、その間隔内で唯一意味のある決定は、負の数が偶数であるか奇数であるかです。 偶数の場合は、セグメント全体を維持するのが最適です。 それが奇数である場合は、最初の否定までの接頭辞または最後の否定の後の接尾辞を削除して、ちょうど 1 つの否定的な効果を削除する必要があります。 

これにより、ゼロで区切られたセグメントをスキャンし、セグメントごとに最大 2 つの候補カットを評価するという問題が軽減されます。

 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を 1 回スキャンし、各ゼロをハード境界として扱うことで、各テスト ケースを独立して処理します。 

1. 配列をゼロを含まない最大のセグメントに分割します。 ゼロを含むセグメントは積 0 を生成するため、このような各セグメントは独立して分析できます。これは、より良いオプションが存在しない限り、値 1 の空のセグメントを選択するよりも常に悪い結果となります。 
2. ゼロのないセグメントごとに、その中の負の数の位置を計算します。 これらのポジションにより、セグメント全体の積がプラスかマイナスかが決まります。 
3. 負の数が偶数の場合、最大の絶対値を持つ正の積が得られるため、セグメント全体を保持することが最適です。 
4. 負の数が奇数の場合、積を正にするためには、正に 1 つの負を除外する必要があります。 2 つの可能性を評価します。セグメント内の最初のネガまでのすべてを削除するか、最後のネガから最後まですべてを削除します。 これら 2 つのうちの良い方は、パリティを固定しながら、より多くの絶対値を保持します。 
5. すべてのゼロフリー セグメントにわたって、最良の結果のセグメントを追跡します。 また、製品 1 を持つ空のセグメント オプションと比較します。 
6. 元の配列の前後から削除された要素の対応する数を出力します。 

重要な推論ステップは、ゼロのないセグメント内では、±2 または ±1 を乗算すると常に絶対値が増加または保持されるため、最適性に影響を与える唯一の要素は積が正か負かであるということです。 それが修正されれば、セグメントは長いほうが常に優れています。 

### なぜ効果があるのか

 ゼロのない連続領域内では、積の大きさは包含に関して単調です。つまり、要素を追加しても絶対値が減少することはありません。 唯一の障害は標識です。 符号は負の数のパリティのみに依存するため、最適解ではセグメント全体を保持するか、負の寄与を 1 つだけ除去するプレフィックス/サフィックスを削除する必要があります。 ゼロは問題を独立した部分問題に分割し、セグメント間の比較により、実現可能な最良の符号補正された積または空の配列のベースラインを選択することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        best_prod = 1
        best_l = n
        best_r = 0

        i = 0
        while i < n:
            while i < n and a[i] == 0:
                i += 1
            if i == n:
                break

            start = i
            neg_pos = []
            while i < n and a[i] != 0:
                if a[i] < 0:
                    neg_pos.append(i)
                i += 1
            end = i - 1

            # consider full segment
            if len(neg_pos) % 2 == 0:
                l, r = start, end
                if r - l + 1 > best_r - best_l + 1:
                    best_l, best_r = l, r
            else:
                # remove prefix up to first negative
                l1 = neg_pos[0] + 1
                r1 = end
                # remove suffix from last negative
                l2 = start
                r2 = neg_pos[-1] - 1

                if r1 >= l1 and (r1 - l1 + 1 > best_r - best_l + 1):
                    best_l, best_r = l1, r1
                if r2 >= l2 and (r2 - l2 + 1 > best_r - best_l + 1):
                    best_l, best_r = l2, r2

        if best_l == n:
            print(0, 0)
        else:
            print(best_l, n - best_r - 1)

if __name__ == "__main__":
    solve()
```このソリューションは各テスト ケースを調べて、これまでに見つかった最良の有効なセグメントを維持します。 ゼロフリーの各セグメントは線形時間で処理され、負の要素のインデックスのみが保存されるため、メモリはセグメントごとに一定に保たれます。 

微妙な点は比較基準です。積を明示的に計算する代わりに、セグメントの長さを比較します。これは、固定のゼロフリー セグメント内では、パリティを固定する有効な変換がすべての非ゼロの大きさを保持し、絶対値において長いセグメントが短いセグメントよりも厳密に優勢であるためです。 このため、算術値ではなく構造のみを追跡すれば十分です。 

もう 1 つの詳細は、最良のセグメントの変換です`[best_l, best_r]`削除に戻ります。 削除中`best_l`先頭から要素を削除すると 0 から始まる左カットが行われ、末尾から削除すると次のようになります。`n - best_r - 1`。 

## 実用的な例

 ### 例 1

 入力配列:`[2, 0, -2, 2, -1]`セグメントに分割します。`[2]`そして`[-2, 2, -1]`。 

のために`[2]`、マイナスはゼロなのでそのままにします。 商品は2です。 

のために`[-2, 2, -1]`, ネガが2つあるのでフルセグが有効です。 商品は4です。 

| セグメント | ネガティブ | アクション | 結果 |
 | --- | --- | --- | --- |
 | [2] | 0 | 満腹を保つ | 2 |
 | [-2,2,-1] | 2 | 満腹を保つ | 4 |

 最良のセグメントは 2 番目のセグメントであるため、それを完全に保持します。つまり、最初の 2 つの要素を削除します。 

これにより、ゼロが独立した最適化領域を正しく分割していることが確認されます。 

### 例 2

 入力配列:`[1, 1, -2]`単一セグメント`[-2]`フルアレイを考慮した後。 

負数 = 1 なので、その周囲のプレフィックスまたはサフィックスを削除する必要があります。 最善の方法は、その前にすべてを削除し、そのままにすることです`[-2]`、または空の配列との比較に応じて完全に削除します。 

| セグメント | ネガティブ | オプション 1 | オプション 2 |
 | --- | --- | --- | --- |
 | [1,1,-2] | 1 | [-2] | [] |

 空の配列には積 1 が含まれており、-2 よりも優れているため、すべての要素を削除するのが最良の答えです。 

これは、空のセグメントは常に明示的に比較する必要があることを示しています。

 ## 特殊なケース

 微妙なケースとしては、配列全体にゼロのみが含まれる場合があります。 すべてのセグメントは積 0 を生成しますが、空の配列は 1 を生成します。アルゴリズムでは、セグメントをまったく選択しないことを明示的に許可する必要があります。 そうしないと、ゼロを含むセグメントが誤って返されてしまいます。 

もう 1 つのケースは、ネガがまばらで孤立している場合です。 最初または最後のネガティブの周囲の間違った側を削除すると、必要以上に多くのポジティブな貢献を誤って破棄する可能性があります。 正しく処理すると、有効な修正間の最大長が維持され、ネガティブが 1 つだけ削除されることが保証されます。 

最後に、すべてのセグメントが積 1 を持ち、どの答えも有効であるため、すべてが正の配列には特別な注意が必要です。 最も長いセグメントが常に優先されるため、アルゴリズムはこれを自然に処理しますが、タイによって不必要な削除を強制してはなりません。
