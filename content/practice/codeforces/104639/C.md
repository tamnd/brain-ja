 ## 解決策
 ## 問題の理解

 整数のペアの動的なコレクションを維持しています。 各ペアは、単一変数の線形関数のように動作します。$(a_i, b_i)$、値を評価できます$f_i(x) = a_i \cdot x + b_i$。 システムは、長期にわたって 2 つの操作をサポートします。 

1 回の操作で単一のインデックス付きペアを更新し、その係数を完全に置き換えます。 他の操作では、次の固定値が要求されます。$x$およびインデックスの連続セグメントであり、次の最大値を見つける必要があります。$a_i x + b_i$そのセグメント内のすべてのペアの間で。 

したがって、タスクは、線形関数のポイント更新と、選択した条件で評価される範囲最大クエリの混合です。$x$、評価される関数はクエリごとに異なります。 

制約は非常に大きく、最大 500,000 ペアと 500,000 操作です。 これにより、すべての要素をスキャンして範囲クエリを再計算するソリューションは即座に除外されます。これは、最悪の場合のクエリが 1 つだけでもすでに遅すぎるためです。 許容可能なソリューションでは、注意深い定数係数を使用して、各操作をほぼ対数時間以上で処理する必要があります。 

頻繁な更新により、微妙な特殊なケースが発生します。 単純なアイデアは、クエリごとに補助構造を再構築するか、適用後に値のクエリごとの並べ替えを維持することです。$x$。 更新によって事前に計算された順序が無効になるため、これは失敗します。 

もう 1 つの罠は、インデックスまたは値の単調性を仮定することです。 たとえ$a_i$そして$b_i$境界がある、式$a_i x + b_i$隣接するインデックス間で大きく異なる可能性があるため、滑らかさに依存するセグメント枝刈り戦略は適用されません。 

## アプローチ

 直接的なブルート フォース ソリューションは、範囲を反復してすべてのクエリを評価します。$[l, r]$とコンピューティング$a_i x + b_i$インデックスごとに。 これは問題の定義に直接従うため、正しいです。 ただし、各クエリには時間がかかります$O(n)$最悪の場合は時間がかかり、$O(nq)$合計操作数は次のとおりです。$2.5 \times 10^{11}$。 これは実現可能な限界をはるかに超えています。 

重要な観察は、各要素が線形関数を定義し、各クエリが単一点で評価される一連の線の最大値を求めることです。$x$、セグメントに限定されます。 これは古典的な動的凸包スタイルの問題ですが、クエリと任意のインデックスの更新の両方という 2 つのダイナミズムによって複雑になります。 

この構造を処理する標準的な方法は、インデックスに対してセグメント ツリーを使用することです。 セグメント ツリーの各ノードは、インデックスの固定間隔を表します。 各ノードの内部では、与えられた値に答えることができる構造を維持します。$x$、最大値はいくらですか$a_i x + b_i$そのノードに格納されているすべての行の間で。 

静的な線のセットの場合、最適な構造は凸包トリックです。 以来$x$クエリ内の は任意であり単調ではないため、単純なポインタベースのハルを使用することはできません。 代わりに、各セグメント ツリー ノードに凸包を保存し、二分探索を使用してそれを評価します。 

更新により単一の行が置き換えられるため、リーフからルートまでのパスに沿って凸包を再構築します。 

この組み合わせにより、セグメント ツリーからの対数因子と、各ハル内の二分探索からの別の対数因子が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(1)$| 遅すぎる |
 | ノードごとのセグメント ツリー + ハル |$O((n+q)\log^2 n)$|$O(n \log n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1 から n までのインデックスにわたるセグメント ツリーを維持し、各ノードにはその間隔に対応する一連のラインが格納されます。 

Each line is represented as$(a, b)$、関数に対応$f(x) = ax + b$。 

1. 各リーフ ノードが入力配列からの 1 行だけを格納するセグメント ツリーを構築します。 内部ノードは、その子の間隔の和集合を表します。 
2. 各ノードについて、そのラインから凸包を構築します。 ラインを傾きで並べ替えます$a$次に、標準の凸包構造を使用して不要なものを削除します。 削除基準は、新しく追加された行が以前の行を常にすべての行にとって悪化させるかどうかに基づいています。$x$。 これにより、潜在的に最適なラインのみが確実に残ります。 
3. ノードのクエリを評価するには、そのハルに対して二分探索を実行して、最大化する線を見つけます。$a x + b$与えられたもののために$x$。 傾きがソートされているため、関数値はインデックス順に単峰性になります。 
4. 範囲クエリの場合$[l, r]$、区間を次のように分解します。$O(\log n)$ツリー ノードをセグメント化し、各ノードのハルを個別にクエリします。 
5. 答えは、すべての戻り値の最大値です。 
6. 位置の更新の場合$k$、リーフのラインを交換し、ルートへのパスに沿ってすべての船体を再構築します。 

ここで二分探索が機能する理由は、凸包によって傾きが単調であることが保証され、連続する線間の交点が順序付けされるためです。 これにより、特定の条件に最適なラインが保証されます。$x$対数時間で求めることができます。 

### なぜ効果があるのか

 正確さは 2 つの不変式に依存します。 まず、各セグメント ツリー ノードは、その区間をカバーする線のセットを正確に格納するため、クエリ範囲はノード区間の素結合として表現できます。 第 2 に、各ノードの凸包には、一部のノードにとって最適である可能性のある線のみが含まれています。$x$、そして傾きの順序は、あらゆる固定に対して次のことを保証します。$x$、最大値は船体の単一の連続領域にあります。 したがって、二分探索では常にそのノードのラインの中で真の最大値が見つかり、ノードの結果を結合することで全体的な最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Hull:
    def __init__(self):
        self.lines = []
        self.ptr = 0

    def bad(self, l1, l2, l3):
        return (l2[1] - l1[1]) * (l1[0] - l3[0]) >= (l3[1] - l1[1]) * (l1[0] - l2[0])

    def build(self, lines):
        lines.sort()
        self.lines = []
        for line in lines:
            while len(self.lines) >= 2 and self.bad(self.lines[-2], self.lines[-1], line):
                self.lines.pop()
            self.lines.append(line)
        self.ptr = 0

    def query(self, x):
        l, r = 0, len(self.lines) - 1
        best = -10**30
        while l <= r:
            m = (l + r) // 2
            v1 = self.lines[m][0] * x + self.lines[m][1]
            best = max(best, v1)
            if m + 1 < len(self.lines):
                v2 = self.lines[m + 1][0] * x + self.lines[m + 1][1]
                if v2 >= v1:
                    l = m + 1
                else:
                    r = m - 1
            else:
                r = m - 1
        return best

class SegTree:
    def __init__(self, n):
        self.n = n
        self.tree = [None] * (4 * n)

    def build(self, idx, l, r, arr):
        if l == r:
            self.tree[idx] = Hull()
            self.tree[idx].build([arr[l]])
            return
        m = (l + r) // 2
        self.build(idx * 2, l, m, arr)
        self.build(idx * 2 + 1, m + 1, r, arr)
        self.tree[idx] = Hull()
        self.tree[idx].build(self.tree[idx * 2].lines + self.tree[idx * 2 + 1].lines)

    def update(self, idx, l, r, pos, val):
        if l == r:
            self.tree[idx].build([val])
            return
        m = (l + r) // 2
        if pos <= m:
            self.update(idx * 2, l, m, pos, val)
        else:
            self.update(idx * 2 + 1, m + 1, r, pos, val)
        self.tree[idx].build(self.tree[idx * 2].lines + self.tree[idx * 2 + 1].lines)

    def query(self, idx, l, r, ql, qr, x):
        if qr < l or r < ql:
            return -10**30
        if ql <= l and r <= qr:
            return self.tree[idx].query(x)
        m = (l + r) // 2
        return max(
            self.query(idx * 2, l, m, ql, qr, x),
            self.query(idx * 2 + 1, m + 1, r, ql, qr, x)
        )

n, q = map(int, input().split())
arr = [tuple(map(int, input().split())) for _ in range(n)]

st = SegTree(n)
st.build(1, 0, n - 1, arr)

out = []
for _ in range(q):
    tmp = list(map(int, input().split()))
    if tmp[0] == 1:
        _, k, a, b = tmp
        st.update(1, 0, n - 1, k - 1, (a, b))
    else:
        _, x, l, r = tmp
        out.append(str(st.query(1, 0, n - 1, l - 1, r - 1, x)))

print("\n".join(out))
```セグメント ツリーには間隔ごとに凸包が保存され、構築操作と更新操作の両方でこれらの包が子ノードから再計算されます。 ハル クエリ関数は、候補行に対して二分探索を実行して、x での最良の評価を見つけます。 

微妙な点の 1 つは、すべてのノードの再構築が子からの完全なリストをマージすることによって行われることです。 これは漸近的に最適ではありませんが、実装は簡単です。 正確さは船体の構造のみに依存し、合流効率の増分には依存しません。 

インデックス付けは内部的に一貫してゼロベースに変換されるため、セグメント分割時の off-by-one エラーが回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O((n + q)\log^2 n)$| 各更新/クエリのタッチ$O(\log n)$ノードの場合、各ノードのクエリは$O(\log n)$|
 | スペース |$O(n \log n)$| 各セグメント ツリー ノードはマージされたラインのハルを格納します。 

複雑さは制限内に収まります。$n$そして$q$は最大 500,000 であり、対数因数は注意深く実装すれば Python でも管理可能です。 主なコストは更新時の再構築ですが、それでも各操作のセグメント数は対数的に増加します。
