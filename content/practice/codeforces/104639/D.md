 ## 解決策
 ## 問題の理解

 いくつかの頂点のペアがすでにエッジによって接続されている、無向の単純なグラフが与えられています。 実行できる操作は新しいエッジを追加することですが、既存のエッジを削除したり、平行エッジや自己ループを導入したりすることはできません。 

最終的な目標は、このグラフを強力な構造特性を持つグラフに変換することです。つまり、2 つの頂点が一連のエッジを介して互いに到達できる場合は常に、頂点間に直接エッジが存在している必要があります。 言い換えれば、到達可能性と隣接性は、最終的なグラフで一致する必要があります。 

この状態は非常に厳しい結果をもたらします。 グラフの接続された領域内では、頂点のすべてのペアが最終的に直接接続される必要があります。そうでないと、頂点間にエッジのないパスが存在します。 したがって、各接続コンポーネントは、最終的なグラフではクリークになる必要があります。 

タスクは、この条件を達成するために追加する必要があるエッジの最小数を計算することです。 

制約は最大 100 万個の頂点と 100 万個のエッジに達します。 これは、頂点のペアを直接考慮しようとする解決策は不可能であることを直ちに示唆しています。 コンポーネントがどのように処理されるかに注意しないと、コンポーネントごとの 2 次の動作でも遅すぎます。 線形または線形に近いグラフの走査が唯一の実行可能な方向です。 

微妙な点は、コンポーネントを安価に結合してグラフを「修正」することができないことです。 以前に切断された 2 つのコンポーネントを接続すると、結合された構造内のすべての頂点が、新しいエッジを介して他のすべての頂点から到達可能になるため、結合されたセット全体にわたって欠落しているエッジもすべて追加する必要があります。 これは、コンポーネントを個別に処理するよりもすぐにコストが高くなります。 

単純な間違いは、すべてを 1 つの大きなクリークに接続し、そこから欠落しているエッジを数えることができると考えることです。 これは、コンポーネント間に単一のエッジを追加すると、到達可能性の構造がグローバルに変更され、追加の必要なエッジのカスケードが強制されることを無視しています。 

たとえば、内部エッジのない、サイズ 2、2、2 の 3 つのコンポーネントについて考えてみましょう。 これらをすべて 1 つのコンポーネントに接続すると、最終的にサイズ 6 のクリークを形成する必要があり、これには 15 個のエッジが必要ですが、それらを分離したままにするには、コンポーネントごとに合計 3 つのエッジだけが必要なので、9 つのエッジが追加されます。 この違いは重大であり、マージが最適ではない理由を示しています。 

## アプローチ

 強引なアプローチは、違反を繰り返し修正するプロセスをシミュレートすることです。 同じ接続コンポーネント内で直接接続されていない頂点のペアを検索し、そのエッジを追加し、クロージャーが達成されるまで続行することができます。 各チェックでは、到達可能性と隣接性を検証するために BFS または DFS が必要であり、追加するたびに構造が再度変更されます。 

このアプローチの問題は、サイズ n の単一コンポーネントに n² 個の欠落エッジが必要になる可能性があり、挿入のたびに接続性の再計算がトリガーされる可能性があることです。 これにより、コンポーネントごとに 3 次の最悪のケース、または少なくとも 2 次のオーバーヘッドが発生します。これは、n が 10⁶ までの場合の実行可能な制限をはるかに超えています。 

重要な観察は、各連結コンポーネント内の最終構造が完全に決定されるということです。つまり、まさにそれらの頂点上で完全なグラフになる必要があります。 エッジを追加するプロセスを 1 つずつシミュレートする必要はありません。 完全なグラフから欠けているエッジの数を数えるだけで済みます。 

これを認識すると、問題は分解タスクに集約されます。 元のグラフの連結成分を見つけます。 コンポーネントごとに、それをクリークにするために必要なエッジの数を計算します。 コンポーネントに s 個の頂点があり、現在 e 個のエッジがある場合、完全なグラフには s・(s−1)/2 個のエッジが含まれることになるため、そのコンポーネントに対して正確に s・(s−1)/2 − e 個のエッジを追加する必要があります。 

これをすべてのコンポーネントについて合計すると、最終的な答えが得られます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n³) 最悪の場合 | O(n + m) | 遅すぎる |
 | 接続コンポーネントのカウント | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 接続されたコンポーネントの構造に依存しているため、アルゴリズムはそれらを検出し、そのサイズとエッジ数を測定することに重点を置いています。 

1. グラフの隣接リスト表現を構築し、すべての頂点にわたる訪問済み配列を準備します。 これにより、接続されている各コンポーネントを効率的に調べることができます。 
2. すべての未訪問の頂点から DFS または BFS を実行して、一度に 1 つの接続コンポーネントを識別します。 トラバース中に、このコンポーネントに属するすべての頂点を収集し、これらの頂点から検出されるエッジの数を数えます。 

各無向エッジは隣接リストに 2 回出現するため、エッジのカウントは慎重に処理する必要があります。そのため、カウントの一貫性を確保するか、後で適切に分割します。 
3. 各コンポーネントについて、そのサイズ s を計算します。 完全なグラフに含める必要があるエッジの数は、s・(s−1)/2 です。 これを、そのコンポーネントに現在存在するエッジの数と比較します。 
4. 必要なエッジと既存のエッジの差を回答に追加します。 
5. すべてのコンポーネントの合計を出力します。 

### なぜ効果があるのか

 重要な不変条件は、接続されたコンポーネントが推移性の要件に関して独立していることです。 2 つの頂点が異なるコンポーネント内にある場合、それらの間にパスは存在しないため、この条件ではこれらのコンポーネント間のエッジは要件になりません。 コンポーネント内で 2 つの頂点間にパスが存在すると、最終的なグラフには頂点間の直接エッジが含まれる必要があります。 これにより、すべてのコンポーネントがクリークに進化することが強制され、条件に違反することなく、そのクリークの欠落しているエッジを正確に追加することを回避できるソリューションはありません。 これにより、コンポーネントの分解が十分かつ必要になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m = map(int, input().split())

adj = [[] for _ in range(n)]
for _ in range(m):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    adj[u].append(v)
    adj[v].append(u)

visited = [False] * n

def dfs(start):
    stack = [start]
    visited[start] = True
    nodes = 0
    edges = 0

    while stack:
        u = stack.pop()
        nodes += 1
        for v in adj[u]:
            edges += 1
            if not visited[v]:
                visited[v] = True
                stack.append(v)

    return nodes, edges // 2

ans = 0

for i in range(n):
    if not visited[i]:
        sz, e = dfs(i)
        ans += sz * (sz - 1) // 2 - e

print(ans)
```この実装では、反復 DFS を使用して、大規模なチェーンでの再帰の深さの問題を回避します。 各エッジは、トラバーサル中に 2 回 (各エンドポイントから 1 回) カウントされるため、コンポーネントごとの最終的なエッジ数を計算するときは 2 で割ります。 

よくある落とし穴は、エッジをグローバルではなくコンポーネントごとにカウントする必要があることを忘れていることです。 単純にすべてのエッジを合計し、グローバル n・(n−1)/2 から減算すると、最終的なグラフは 1 つの単一クリークでなければならないと誤って想定されますが、これは必須ではありません。

```4 つの頂点すべてを含む 1 つのコンポーネントがあります。

出力は3です。 

これにより、コンポーネントの一部がすでに密になっている場合でも、接続されたコンポーネント全体の完全な閉包に基づいて計算が行われることが確認されます。

```3 つのコンポーネント: {1,2}、{3}、{4,5} があります。 

| コンポーネント | サイズ | 既存のエッジ | 完全なエッジ | 追加されました |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各頂点とエッジは DFS 中に 1 回処理されます。 
| スペース | O(n + m) | 隣接リストと訪問先配列 |

 この制約により、最大 100 万個の頂点とエッジが許可され、この線形時間トラバースは制限内に快適に収まります。 メモリ使用量もグラフのサイズに比例します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from collections import deque

    input = _sys.stdin.readline
    sys.setrecursionlimit(10**7)

    n, m = map(int, input().split())
    adj = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].append(v)
        adj[v].append(u)

    visited = [False] * n

    def dfs(start):
        stack = [start]
        visited[start] = True
        nodes = 0
        edges = 0
        while stack:
            u = stack.pop()
            nodes += 1
            for v in adj[u]:
                edges += 1
                if not visited[v]:
                    visited[v] = True
                    stack.append(v)
        return nodes, edges // 2

    ans = 0
    for i in range(n):
        if not visited[i]:
            sz, e = dfs(i)
            ans += sz * (sz - 1) // 2 - e

    return str(ans)

# provided sample
assert run("4 3\n1 2\n1 3\n2 3\n") == "3"

# single node
assert run("1 0\n") == "0"

# already complete components
assert run("3 3\n1 2\n2 3\n1 3\n") == "0"

# two disjoint edges
assert run("5 2\n1 2\n4 5\n") == "0"

# chain graph
assert run("4 3\n1 2\n2 3\n3 4\n") == "3"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一ノード | 0 | 簡単なコンポーネントの処理 |
 | 完全な三角形 | 0 | 余分なエッジは必要ありません |
 | 互いに素なエッジ | 0 | 独立したコンポーネント |
 | チェーン | 3 | 1 つのコンポーネント内の完全なクロージャ |

 ## 特殊なケース

 単一の孤立した頂点は、サイズ 1 のそれ自体のコンポーネントです。 式 s・(s−1)/2 はすぐに 0 を与えるため、エッジは追加されません。 DFS は頂点をマークし、そのコンポーネントに対してゼロ エッジを返すため、アルゴリズムはこれを自然に処理します。 

完全に接続されたコンポーネントはすでにクリーク条件を満たしています。 トラバーサル中、すべてのエッジはコンポーネントごとに 1 回だけカウントされ、すでに s・(s−1)/2 と一致するため、減算の結果は 0 になります。 エッジカウントは各コンポーネントに局所的に行われるため、過剰カウントのリスクはありません。 

長いパス グラフは、DFS の深さとエッジカウントの正確性について最悪のケースをテストします。 すべての頂点が接続されているにもかかわらず、n−1 個のエッジのみが存在し、式はクリークを完成させるために必要な欠落エッジの数を正確に計算します。
