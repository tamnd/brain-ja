 ## 解決策
 ## 問題の理解

 整数の配列と、それに定義された 2 人用ゲームが与えられます。 アリスが最初に動き、各動きでプレイヤーは配列内の任意の 2 つの位置を選択し、それらの 2 つの値を新しい整数のペアに置き換えます。この整数のペアは、絶対差を厳密に減少させながら合計を保持します。 ゲームはどのペアにもそのような動きが不可能になるまで続き、動けなかったプレーヤーが負けます。 

ゲームの開始前に、要素が 3 つだけ残っている限り、要素をいくつでも削除できます。 各テスト ケースについて、最適なプレイの下でアリスが強制的に勝利する開始位置につながる、最後の 3 つのインデックスの選択肢がいくつあるかを数えなければなりません。 

n の制約はテスト ケースごとに最大 5×10^5 で、合計 n は最大 3×10^6 です。 これにより、各トリプルのゲームをシミュレートしようとするソリューションや、テスト ケースごとにおよそ O(n log n) または O(n) よりも悪いものさえも即座に排除されます。 出力はすべてのトリプルのカウントであるため、問題の構造では 3 つの数値に関するゲームを単純な分類に落とし込み、頻度の集計によるカウントを許可する必要があります。 

値が非常に近い場合、微妙なエッジケースが発生します。 たとえば、[5, 5, 6] のようなトリプルの場合、どのペアも差が 0 か 1 のどちらかであるため、移動することはできません。また、整数値を維持して合計を維持しながら、差が 1 である場合はそれ以上減らすことはできません。 したがって、この構成は末期であり、先発プレイヤーにとっては負けるに違いありません。 一方、[1、3、10] のようなトリプルは明らかに移動が可能であり、プレイヤーは最終状態に達するまで直感的に大きなギャップを減らし続けることができます。 主な困難は、どのトリプルが終端で、どのトリプルが勝利しているかを正確に特定することです。 

## アプローチ

 ブルートフォースのアイデアは簡単です。インデックスのトリプルをすべて列挙し、それらの 3 つの値に基づいてゲームをシミュレートし、アリスが勝つかどうかを判断します。 O(n^3) 個のトリプルがあり、各シミュレーションには複数の分岐するゲーム状態が含まれるため、これは直ちに実行不可能です。 大量の枝刈りを行ったとしても、各移動が新しいペア状態を作成するため、トリプルあたりの構成の数は依然として急速に増加します。 このアプローチは、制約が大きくなるずっと前に失敗します。 

重要な観察は、この演算では、選択された 2 つの数値の合計を維持しながら、それらの差のみが減少するということです。 これは、少なくとも 2 の差があるペアは厳密に「強化」できるが、差が 0 または 1 のペアはすでに最も圧縮された整数形式であることを意味します。 3 つの数字のセットの場合、少なくとも 2 の差があるペアがない場合、ゲームは直ちに終了します。これは最終状態を完全に特徴づけます。 

したがって、完全なゲーム ツリーを分析する代わりに、トリプルに少なくとも 2 異なる値のペアが含まれているかどうかを判断するだけで済みます。そのようなペアが存在しない場合、ポジションは最終的なものとなり、最初のプレーヤーが負けます。 それ以外の場合、そのポジションは勝ちです。 

これにより、タスクは、最大値から最小値を引いた値が 1 以下のトリプルを数え、可能なすべてのトリプルからそれらを減算するだけになります。

 ## アルゴリズムのチュートリアル

 私たちは問題を、値のトリプルを分類することに縮小します。

1. 配列内のそれぞれの個別の値の頻度を数えます。 これにより、インデックスを列挙せずにトリプルについて推論することができます。 
2. 配列から任意の 3 つの要素を選択する方法の合計数を計算します。 これは C(n, 3) です。 これは、考えられるすべての最終的な選択肢を表します。 
3. 「悪い」トリプル、つまりアリスにとって負けているトリプルを特定します。 トリプルは、手が不可能な場合に正確に負けます。これは、トリプルの最大値と最小値の差が 1 以下の場合に発生します。これは、3 つの値すべてが 1 つの値または 2 つの連続する整数値のいずれかに存在する必要があることを意味します。 
4. 3 つの値がすべて等しいトリプルを数えます。 各値 x に対して、これは C(cnt[x], 3) に寄与します。 
5. 値が 2 つの隣接する値 x および x+1 からのみ得られるトリプルを数えます。 この結合されたバケットからのトリプルの総数は C(cnt[x] + cnt[x+1], 3) ですが、これにはすでにカウントされている「すべて等しい」ケースが含まれるため、C(cnt[x], 3) と C(cnt[x+1], 3) を減算します。 
6. すべての x を合計して、負けたトリプルの合計数を取得します。 
7. トリプルの合計から負けたトリプルを引いて答えを求めます。 

### なぜ効果があるのか

 この操作では、差が少なくとも 2 であるペアを減らすことが常に許可されます。したがって、トリプルにそのようなペアが含まれている限り、少なくとも 1 つの手が存在します。 逆に、すべての値がサイズ 1 の範囲内にある場合は、整数値を保持したままペアをさらに縮小することはできないため、位置は終端になります。 これにより、負けの条件は「トリプル内のすべての値が 1 単位間隔内にある」ことと等価になります。これはまさに数え方の公式が捉えているものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def C3(x):
    if x < 3:
        return 0
    return x * (x - 1) * (x - 2) // 6

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    freq = defaultdict(int)
    for x in a:
        freq[x] += 1

    total = C3(n)

    bad = 0
    keys = sorted(freq.keys())

    for x in keys:
        bad += C3(freq[x])

    for x in keys:
        if x + 1 in freq:
            bad += C3(freq[x] + freq[x + 1]) - C3(freq[x]) - C3(freq[x + 1])

    print(total - bad)

if __name__ == "__main__":
    solve()
```コードはまず、配列を周波数マップに圧縮して、トリプルを組み合わせてカウントできるようにします。 関数 C3 は 3 つの要素の組み合わせを安全に計算します。 合計トリプルを計算し、単一の値または 2 つの隣接する値から形成されたすべての損失構成を減算します。 

隣接ループは、すでに含まれている純粋な値の寄与を減算することで、二重カウントを慎重に回避します。 

## 実用的な例

 配列を考えてみましょう`[1, 1, 2, 2]`。 

私たちには次のような周波数があります。`1 -> 2`、`2 -> 2`。 トリプルの合計は C(4, 3) = 4 です。 

不正なトリプルを計算します。 

すべての等しいトリプルは、両方の値に対して C(2,3)=0 に寄与します。 

ペア (1,2) については、C(4,3)=4 マイナス C(2,3) マイナス C(2,3) を計算し、4 を与えます。 

So bad = 4、答えは 0 です。すべての要素がサイズ 1 の範囲内にあるため、すべてのトリプルが失われます。 

ここで考えてみましょう`[1, 3, 10]`。 

すべての頻度は 1 です。合計のトリプルは 1 です。値の繰り返しがないため、C(3) の寄与は存在しません。 隣接するペアも存在しないため、悪い = 0。答えは 1 で、このトリプルが勝っていることを意味します。 

これは、大きなギャップが少なくとも 1 つの還元可能なペアが存在することを保証するという直観と一致します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import comb
    import collections

    def C3(x):
        return x * (x - 1) * (x - 2) // 6 if x >= 3 else 0

    def solve():
        n = int(input())
        a = list(map(int, input().split()))
        freq = collections.Counter(a)
        total = C3(n)

        bad = 0
        keys = sorted(freq)

        for x in keys:
            bad += C3(freq[x])

        for x in keys:
            if x + 1 in freq:
                bad += C3(freq[x] + freq[x + 1]) - C3(freq[x]) - C3(freq[x + 1])

        print(total - bad)

    solve()
    return ""

# minimum size
assert run("3\n1 2 3\n") == "", "min size"

# all equal
assert run("5\n7 7 7 7 7\n") == "", "all equal"

# two consecutive values
assert run("4\n1 1 2 2\n") == "", "adjacent mix"

# non-consecutive spread
assert run("4\n1 3 10 20\n") == "", "spread values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3 1 2 3 | 依存します | 最小限の有効な三重構造 |
 | 5 7 7 7 7 7 | 0 | すべてのトリプルが負けています |
 | 1 1 2 2 | 0 | 隣接値のみの場合 |
 | 1 3 10 20 | ポジティブ | 優れた構成が存在します |

 ## 特殊なケース

 すべての要素が同一の場合、すべてのペアの差が 0 であるため、すべてのトリプルに有効な手が存在しないことは明らかです。アルゴリズムは、これを C(cnt[x], 3) 項内で完全にカウントし、トリプルの合計から完全に減算し、予想どおりゼロを生成します。 

値が 2 つの連続する整数の間で交互に現れる場合、次のようになります。`[4,4,5,5,5]`、すべてのトリプルは依然としてサイズ 1 の範囲に制限されています。結合された C(cnt[x]+cnt[x+1],3) 項はすべての選択をキャプチャし、内部結合の減算によりオーバーカウントがなくなり、すべてのトリプルが損失として正しくマークされます。 

配列に大きく分離された値が含まれている場合、次のようになります。`[1, 100, 200]`、隣接値条件が成立せず、単一値の繰り返しが存在しないため、不良トリプルはカウントされません。 すべてのトリプルが勝利し、式は合計 C(n,3) に還元され、少なくとも 1 つの還元可能なペアが常に存在するという事実と一致します。
