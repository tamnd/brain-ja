 ## 解決策
 ## 問題の理解

 実行時間が固定されている参照プログラムが与えられています。$T$、およびリスト$n$実行時間がわかっている他のプログラム。 整数の乗数を選択するように求められます$k \ge 2$制限時間は$k \cdot T$リスト内のすべてのプログラムが終了するのに十分です。つまり、すべてのプログラムが終了します。$t_i \le k \cdot T$。 すべての有効な値の中で、可能な限り最小の値を出力する必要があります。$k$。 

条件を書き換えると、各プログラムは下限を課します。$k$: 与えられた$t_i$、必要です$k \ge \frac{t_i}{T}$。 以来$k$整数でなければならない場合、真の制約は次のようになります。$k \ge \left\lceil \frac{t_i}{T} \right\rceil$。 したがって、最終的な答えは、これらのプログラムごとの要件のすべてのプログラムにわたる最大値であり、次のような追加の制約があります。$k \ge 2$。 

制約$n \le 10^5$そして$t_i \le 10^9$線形時間で答えを計算する必要があることを示唆しています。 ソートを伴うアプローチは不要であり、必要よりも遅くなりますが、それでも許容できます。 ただし、1 回のパスで十分です。 

すべてのプログラムが他のプログラムと比較して非常に高速である場合、微妙なケースが発生します。$T$。 この場合、すべての比率は 1 未満になるため、計算された最大値は 1 になりますが、この問題では明示的に次のことが強制されます。$k \ge 2$。 たとえば、次の場合$T = 1000$そしてすべて$t_i \le 500$、すべてのプログラムが既に成功しているにもかかわらず、正解は 2 です。$k = 1$。 

別の特殊なケースが発生するのは、$t_i$よりもはるかに大きいです$T$、これにより答えは次のようになります。$10^9$規模。 乗算は 64 ビット整数の範囲内であるため、Python では安全ですが、固定幅言語では注意が必要です。 

## アプローチ

 この問題を考える直接的な方法は、考えられる値をすべて試してみることです。$k$, 2 から順に実行し、すべてのプログラムが満たしているかどうかを確認します。$t_i \le kT$。 それぞれについて$k$、これにはすべてをスキャンする必要があります$n$プログラムなので、各チェックにコストがかかります$O(n)$。 最悪の場合、$k$くらいまで成長するかもしれない$10^9$、そのため、このアプローチは完全に実行不可能になります。 

重要な観察は、実現可能性が単調であるということです。$k$。 ある場合$k$機能する、それからさらに大きい$k$も機能します。 これにより、問題は最小の整数を見つけることに帰着します。$k$これは一連の下限を満たすもので、各プログラムから独立して直接導出できます。 

各プログラムは要件に貢献します$k \ge \lceil t_i / T \rceil$。 検索する代わりに$k$、これらの要件を直接計算し、最大値を取得します。 これにより、問題はある間隔での検索から単一パスの集約に集約されます。

 | k に対するブルート フォース |$O(n \cdot k)$|$O(1)$| 遅すぎる |

 ## アルゴリズムのチュートリアル

 1.読む$n$そして$T$。 These define the scaling baseline for all comparisons.
 2. Initialize a variable$k\_req = 2$なぜなら、この問題では、データに関係なく、最小許容乗数 2 が強制されるからです。 
3. 各プログラム時間ごとに$t_i$、合格となる最小の乗数を計算します。 これは$\left\lceil \frac{t_i}{T} \right\rceil$。 
4.アップデート$k\_req = \max(k\_req, \lceil t_i / T \rceil)$。 これにより、これまでに確認されたすべての制約が満たされたままになります。 すべてのプログラムが同じグローバルを独立して制約するため、最大値が使用されます。$k$。 
5. すべてのプログラムを処理した後、出力します。$k\_req$。 

### なぜ効果があるのか

 各プログラムは独立した不等式を課します$kT \ge t_i$、次のように並べ替えることができます。$k \ge t_i / T$。 すべての制約が同時に成立する必要があるため、$k$その中で最も強い者を満足させなければなりません。 上限は、端数の要件を整数の実現可能性制約に変換します。 すべてのプログラムの最大値を取ると、最も厳しい制約が正確に保持されるため、最終値は必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, T = map(int, input().split())
    arr = list(map(int, input().split()))
    
    k_req = 2
    
    for t in arr:
        # compute ceil(t / T)
        k = (t + T - 1) // T
        if k > k_req:
            k_req = k
    
    print(k_req)

if __name__ == "__main__":
    main()
```実装の中核は整数の上限の計算です。`(t + T - 1) // T`これにより、浮動小数点演算が回避され、大きな値の正確性が保証されます。 すべての比率が 1 を示唆する場合でも、制約によりそれが許可されないため、2 への初期化は必須です。

## テストケース```python
import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    
    n, T = map(int, input().split())
    arr = list(map(int, input().split()))
    
    k_req = 2
    for t in arr:
        k_req = max(k_req, (t + T - 1) // T)
    
    return str(k_req)

# provided sample
assert solve("5 1000\n998 244 353 1111 2333\n") == "3"

# all small values, forces k=2
assert solve("3 100\n10 20 30\n") == "2"

# exact multiples
assert solve("3 10\n10 20 30\n") == "3"

# large single outlier
assert solve("4 1000\n1 2 3 1000000\n") == "1000"

# minimum case
assert solve("1 5\n1\n") == "2"
```| テスト入力 | 期待される出力 | 検証内容 |

| 倍数 | 3 | 正確な除算の正確さ |
