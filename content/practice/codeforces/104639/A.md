 ## 解決策
 ## 問題の理解

 2 つの別々のプログラミング コンテストの順序付けされた結果が与えられます。 各コンテストでは個々のチームがランク付けされますが、最終的に重要なのは個々のチームではなく大学の成績です。 

各コンテストでは、大学は複数のチームによって代表されますが、最も成績の良いチームのみが重要となります。 したがって、両方のコンテストの最初のステップは、コンテストのリストに表示される各大学の最高 (最上位) の順位を維持することによって、チーム レベルのランキングを大学レベルのランキングに圧縮することです。 

コンテストごとに 1 つずつ、大学の 2 つのランキングを取得したら、それらを 1 つの最終的な順序に統合する必要があります。 マージ ルールは、2 つのソートされたリストの安定したマージのように動作します。各コンテストでのランクに基づいて大学を繰り返し比較します。 ある大学が最初のコンテストのランキングで他の大学より早く登場した場合、その大学は優れていると見なされます。 コンテスト間で同じ順位の場合は、最初のコンテストの順位が優先されます。 

統合後、大学が両方のリストに表示されるため、重複が表示されます。 順序を維持して、マージされたシーケンス内の各大学の最初の出現のみを保持します。 

出力は、最終的な重複排除された大学のランキングです。 

この制約により、コンテストごとに最大 10^4 チームが許可されるため、単純な O(n^2) 比較または最高ランクの繰り返しスキャンはすでに境界線に達していますが、それでも Python では許容できる可能性があります。 ただし、マージ ステップは前処理後に線形である必要があります。そうでない場合、リストの削除を繰り返したり、リスト内のメンバーシップ チェックを繰り返したりして実装すると、TLE が発生します。 

大学のランキングを先に崩さずにチームリストを直接結合しようとすると、微妙な失敗例が発生します。 これでは、同じ大学の複数のチームが別の競争相手として誤って扱われてしまいます。 

大学が 1 つのコンテストにのみ出場する場合、別の特殊なケースが発生します。 最終ランキングに表示される必要があり、人為的なペナルティなしで正しくマージされる必要があります。 

## アプローチ

 直接的なアプローチは、プロセス全体を文字通りシミュレートすることです。 コンテストごとに、ランク付けされたリストをスキャンし、大学ごとに、最初に出現したインデックスをスコアとして保存します。 これにより、大学をラン​​クにマッピングする 2 つの辞書が生成されます。 

次に、マージされたシーケンスを繰り返し構築します。 各ステップで、まだ配置されていない残りの大学をすべて比較し、比較ルールに従って最良のものを選択し、追加して検討から削除します。 これは、カスタム注文で最小値を繰り返し選択することに相当します。 

問題は、この選択ステップにコストがかかることです。 U 個の大学がある場合、次善の大学を選択するには、O(U) 個の候補者をスキャンし、O(U) 回繰り返す必要があり、O(U^2) になります。 U が 10^4 までの場合、これは約 10^8 の演算となり、Python では遅すぎます。 

重要な観察は、各コンテストを固有の大学のランキング リストに変換した後、両方のリストがすでに希望する順序で並べ替えられていることです。 最後のルールは、まさに 2 つのソートされたシーケンスの安定したマージであり、比較は各リストのランク位置に基づいて辞書順に行われ、最初のリストが優先されるタイブレークとなります。 

これにより、2 つのポインターを使用して事前にソートされた 2 つのリストをマージし、その後セットを使用して重複排除を行うという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース選択 | O(U^2) | お(う) | 遅すぎる |
 | 2 ポインターのマージ | O(n + m) | お(う) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、各コンテストのチームリストを独自の大学ランキングに圧縮します。

1. 最初のコンテスト リストを上から下に読んでください。 大学ごとに、これまで見たことのないものは順番に記録していきます。 これにより、最初のランキング リストが作成されます。 2 回目のコンテストでも同じことが行われます。 このステップは、大学ごとに最高のチームのみが重要であり、最も早いチームが最高のランクに対応するため、有効です。 
2. これら 2 つのリストを順序付けられたシーケンスとして扱います。 ここで、各リストを指す 2 つのポインターを使用してそれらをマージします。 各ステップで、両方のリストの現在の候補者を比較します。 
3. 両方のポインタが異なる大学を指している場合は、最終的な順序で先に表示される方を追加します。 順序付けの規則は、最初のリストの早い位置が優先されるというものです。 それ以外の場合は、2 番目のリスト内の位置を比較します。 実際には、これは、欠損値が無限大として扱われるペア (rank_in_first、rank_in_second) に基づいてマージすることと同じです。 
4. 1 つのリストが使い果たされた場合は、他のリストの残りの要素を追加します。 
5. 合併中、すでに出力されている一連の大学を維持します。 大学がすでに出力されている場合はスキップします。 これが必要なのは、大学が両方のリストに表示される可能性があり、最終出力では重複を削除する必要があるためです。 
6. 両方のリストが完全に処理されるまで続行します。 

これらの手順の後、出力リストには、各大学が正しいマージされた順序で 1 回だけ含まれます。 

### なぜ効果があるのか

 各コンテストのリストは、ランクの昇順にすでに並べ替えられています。 マージ ルールは、これら 2 つの並べ替えられた順序における相対的な位置に基づいて、任意の 2 つの大学間の一貫した順序付けを定義します。 比較は推移的であり、ランク ペアの辞書編集的な順序と一致しているため、2 ポインター プロセスによって生成されるマージされたシーケンスはグローバルな順序を保持します。 重複排除は正確さに影響を与えません。なぜなら、一度統合された順序に大学が出現すると、それ以降に出現した大学は厳密に悪い順位を表しており、無視しても問題ないからです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_ranking(arr):
    seen = set()
    res = []
    for x in arr:
        if x not in seen:
            seen.add(x)
            res.append(x)
    return res

def solve():
    n, m = map(int, input().split())
    a = [input().strip() for _ in range(n)]
    b = [input().strip() for _ in range(m)]

    r1 = build_ranking(a)
    r2 = build_ranking(b)

    pos1 = {u: i for i, u in enumerate(r1)}
    pos2 = {u: i for i, u in enumerate(r2)}

    i = j = 0
    used = set()
    out = []

    while i < len(r1) or j < len(r2):
        while i < len(r1) and r1[i] in used:
            i += 1
        while j < len(r2) and r2[j] in used:
            j += 1

        if i >= len(r1) and j >= len(r2):
            break
        if i >= len(r1):
            u = r2[j]
            j += 1
        elif j >= len(r2):
            u = r1[i]
            i += 1
        else:
            u1 = r1[i]
            u2 = r2[j]

            if pos1.get(u1, float('inf')) < pos1.get(u2, float('inf')):
                u = u1
                i += 1
            elif pos1.get(u1, float('inf')) > pos1.get(u2, float('inf')):
                u = u2
                j += 1
            else:
                if pos2.get(u1, float('inf')) <= pos2.get(u2, float('inf')):
                    u = u1
                    i += 1
                else:
                    u = u2
                    j += 1

        if u not in used:
            used.add(u)
            out.append(u)

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に各コンテスト リスト内の重複する大学を圧縮し、最初に出現した大学のみを保持します。これは、それらが最高のチーム ランクを表すためです。 次に、一定時間内に比較できるように位置マップを構築します。 マージ ループは、冗長な処理を避けるために、既に使用されている大学をスキップしながら、ポインターを慎重に進めます。 タイブレーク条件により、大学の相対順序が等しい場合の決定的な動作が保証されます。

 ## 特殊なケース

 特殊なケースの 1 つは、ある大学が 1 つのコンテスト リストに何度も登場する場合です。 たとえば、入力が`A A A A B`、圧縮ステップでは、次のことのみが保証されます。`A B`残っています。 実行中、アルゴリズムはそれ以降の出現を無視します。`seen`set はそれらをすぐにフィルターします。 この手順を行わないと、マージ ロジックは繰り返し発生したものを別個のエントリとして誤って扱い、重複が生成されてしまいます。 

別の特殊なケースは、大学が 1 つのコンテストにのみ出場する場合に発生します。 たとえば、次の場合`X`ランキングは 1 位ですが 2 位ではありません。`pos2`デフォルトは無限大です。 これにより、比較中に、純粋に最初のコンテストの順序に従って配置されることが保証され、これは、コンテストに欠席してもペナルティが課されないという意図されたルールと一致します。 

最後のケースは、コンテスト間の完全な逆転です。 2 つのランキングが逆の場合でも、すべての比較はランク ペアの辞書編集上の一貫した順序に基づいて解決され、最初の競合を優先することで同順位が破られるため、ペアごとの比較ルールによって決定的な順序付けが保証されます。
