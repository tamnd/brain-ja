 ## 解決策
 ## 問題の理解

 次の長さの部分的に既知のパスワード文字列が与えられます。`n`。 各位置は、最終的なパスワード文字に使用できるものをすでに制限しています。 一部の位置は特定の文字に固定されており、一部の位置は小文字とその大文字バージョンの間で柔軟であり、一部の位置は完全に不明で、どちらの場合でも任意の数字または文字になる可能性があります。 

これらのローカル制約に加えて、最終的な文字列は 3 つのグローバル条件を満たす必要があります。つまり、少なくとも 1 つの大文字、少なくとも 1 つの小文字、および少なくとも 1 つの数字が含まれている必要があります。 さらに、最終的な割り当て後は、隣接する 2 つの文字が同一であってはなりません。 

このタスクは、位置制限とグローバル有効性ルール (法 998244353) の両方を満たす完全なパスワードの数をカウントすることです。 

長さの制約`n ≤ 10^5`すべての有効な文字列を列挙しようとするアプローチは直ちに除外されます。 ポジションごとに 52 の選択肢を分岐させるだけでも、指数関数的な爆発につながります。 この構造は、文字列に対する動的プログラミング アプローチを示唆しています。これは、隣接性の制約によってローカル状態の依存性が強制される一方、大文字/小文字/数字の要件により、構築中に追跡する必要があるグローバル状態が導入されるためです。 

大文字と小文字を区別できる小文字と隣接制限との間の相互作用から、微妙なエッジ ケースが発生します。 たとえば、次の場合`s[i] = 'a'`そして`s[i+1] = 'A'`、それらを独立した選択肢として扱うと、両方が同じ大文字にマップされる可能性があるため、大文字と小文字の変換後に禁止された等価性が誤って許可される可能性があります。 もう 1 つの特殊なケースは、多くのポジションが`'?'`, キャラクターがカテゴリにグループ化されていない限り、単純な DP トランジションは高価になります。 

## アプローチ

 ブルートフォース戦略では、次の条件と一致する各位置の文字を再帰的に選択することによって、文字列の有効な補完をすべて生成しようとします。`s`。 それぞれの位置で、許可されているすべての文字を試し、最後に有効性をチェックします。 これは、すべての制約を直接尊重するため、概念的には機能しますが、分岐要素は膨大です。ポジションごとに最大 62 の選択肢があり、おおよその結果が得られます。`62^n`最悪の場合の可能性も。 隣接性による枝刈りでも、検索の指数関数的な性質は変わりません。 

重要な観察点は、文字列を拡張するために過去から必要な唯一の情報は、最後に選択された文字と、少なくとも 1 つの大文字、小文字、および数字をすでに見たかどうかであるということです。 位置制約は、インデックスごとに許可される文字セットに前処理することができ、遷移はこれらのセットと隣接性の不平等にのみ依存します。 

これにより、問題は、状態が 3 つのブール フラグと前の文字を追跡する位置に関する動的プログラミングに帰着します。 前の文字全体を直接保存すると大きすぎるため、文字を 62 個の記号 (小文字 26 個、大文字 26 個、数字 10 個) からなる有限のアルファベットに圧縮し、遷移で隣接関係を明示的に処理します。 

DP は、位置ごとに、次のように定義された状態に到達する方法が何通りあるかを計算します。`(position, last_char, mask)`どこ`mask`これまでに大文字、小文字、数字を確認したかどうかをエンコードします。 各ステップは、次の有効な文字に展開されます。`last_char`現在の位置制約によって許可されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(62^n) | O(n) | 遅すぎる |
 | DP オーバー位置、最後の文字、マスク | O(n · 62 · 3) | O(62・8) | 承認済み |

 ## アルゴリズムのチュートリアル

 文字は、サイズ 62 の統一されたアルファベットにエンコードされます。各文字は、大文字、小文字、または数字の 3 つのタイプのいずれかに属します。 また、3 ビット マスクも維持します。ビット 0 は少なくとも 1 つの大文字が検出されたことを意味し、ビット 1 は小文字を意味し、ビット 2 は数字を意味します。 

### 1. 位置ごとに許可される文字を事前計算します。 

インデックスごとに`i`、可能な文字のリストを作成します。 

もし`s[i]`は`'?'`、62 文字すべてを許可します。 

もし`s[i]`数字または大文字の場合は 1 文字に固定されます。 

もし`s[i]`は小文字の場合、その小文字または対応する大文字のいずれかになります。 

このステップでは、問題を固定候補セット上の均一な DP に変換します。 

### 2. DP を位置 0 で初期化します。 

最初の位置では、許可されているすべての文字を試します。 各選択により、文字タイプに基づいてマスクが初期化されます。 このステップでは、事前の文字制約はありません。 

### 3. ポジション間の移行

 ポジションごとに`i > 0`、新しい DP テーブルを計算します。 州ごとに`(last_char, mask)`前の位置から、許可されている各文字で拡張してみます`c`位置にある`i`。 トランジションをスキップします。`c == last_char`。 次のタイプで OR 演算することでマスクを更新します。`c`。 

隣接制約はローカルに適用され、すべてのグローバル制約はマスクを通じて蓄積されます。 

### 4. 結果を蓄積する

 すべての位置を処理した後、マスクが以下に等しいすべての DP 状態を合計します。`111`バイナリでは、少なくとも 1 つの大文字、小文字、数字が表示されたことを意味します。 

### なぜ効果があるのか

 各位置の選択は明示的に表され、各遷移で隣接関係が強制されるため、すべての有効なパスワードは DP 状態を通る 1 つのパスに正確に対応します。 逆に、許可された文字セットではメモリ制約が適用され、遷移では隣接性制約が適用され、最終マスクではグローバルな文字タイプ要件が適用されるため、すべての DP パスは有効な文字列を構築します。 無効な文字列は有効な終了状態に入ることはできません。また、規則に一致するすべての選択肢が列挙されるため、有効な文字列は除外されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def char_type(c):
    if '0' <= c <= '9':
        return 1 << 2
    if 'a' <= c <= 'z':
        return 1 << 1
    return 1 << 0

def expand_char(c):
    if c == '?':
        chars = []
        for i in range(26):
            chars.append(('a', i))
            chars.append(('A', i))
        for i in range(10):
            chars.append(('0', i))
        return list(range(62))
    if 'a' <= c <= 'z':
        return [ord(c) - ord('a'), ord(c.upper()) - ord('A') + 26]
    if 'A' <= c <= 'Z':
        return [ord(c) - ord('A') + 26]
    return [ord(c) - ord('0') + 52]

def ctype(idx):
    if idx < 26:
        return 1 << 1
    if idx < 52:
        return 1 << 0
    return 1 << 2

def solve():
    s = input().strip()
    n = len(s)

    allowed = []
    for i in range(n):
        if s[i] == '?':
            allowed.append(list(range(62)))
        elif 'a' <= s[i] <= 'z':
            a = ord(s[i]) - ord('a')
            b = ord(s[i].upper()) - ord('A') + 26
            allowed.append([a, b])
        elif 'A' <= s[i] <= 'Z':
            allowed.append([ord(s[i]) - ord('A') + 26])
        else:
            allowed.append([ord(s[i]) - ord('0') + 52])

    dp = [[0] * 62 for _ in range(8)]

    for c in allowed[0]:
        dp[ctype(c)][c] += 1

    for i in range(1, n):
        ndp = [[0] * 62 for _ in range(8)]
        for mask in range(8):
            for last in range(62):
                val = dp[mask][last]
                if not val:
                    continue
                for c in allowed[i]:
                    if c == last:
                        continue
                    nmask = mask | ctype(c)
                    ndp[nmask][c] = (ndp[nmask][c] + val) % MOD
        dp = ndp

    ans = 0
    for last in range(62):
        ans = (ans + dp[7][last]) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、すべての文字を 62 状態に圧縮することに依存しているため、隣接関係は単純な整数比較になります。 DP テーブルにはマスクと最後の文字の組み合わせごとにカウントが保存され、部分問題が再計算されることがなくなります。 マスクの更新は単純なビット単位の OR であり、これにより、遷移ごとに必要な文字タイプを一定時間追跡することができます。 

よくある落とし穴は、小文字が固定されていないことを忘れていることです。小文字によって小文字と大文字の間の分岐が発生し、これは DP 遷移中ではなく前処理で処理する必要があります。 もう 1 つの微妙な点は、位置 0 での初期化です。ここでは隣接関係が適用されないため、許可されたすべての文字を個別にシードする必要があります。 

## 実用的な例

位置 0 では、`'a'`なることができる`a`または`A`。 位置 1 では、`'?'`すべての文字を許可しますが、前の選択とは異なる必要があります。 位置 2 では、`'0'`固定されています。

 | --- | --- | --- | --- | --- |

ここで考えてみましょう`??1`。

これは、DP がすべての有効な部分構造を維持しながら、制約を徐々に蓄積する方法を示しています。

 ## 特殊なケース

 主なエッジケースは、2 つの隣接する文字が`s`同じ文字をさまざまなケースで制限します。 例えば、`s = "aA"`両方の位置が同じ基礎となる文字を表すように強制します`a/A`、しかし、隣接性は平等を認めません。 DP はこれを処理します。これは、両方の位置が同じエンコードされたインデックス セットに拡張され、遷移によって等しいインデックスが明示的にブロックされ、必要な場合に有効な拡張がゼロになるためです。 

もう 1 つのケースは、ワイルドカードで囲まれた長い数字の文字列です。 数字は数字マスク ビットにのみ寄与するため、DP は大文字と小文字の要件が他の場所で満たされる必要があることを保証します。 そうしないと、それらの状態が最終マスクに到達することはありません`111`。 これにより、隣接性は満たしているが必要な文字クラスを欠いている文字列を過剰にカウントすることがなくなります。 

最後に、すべてのキャラクターが揃ったら、`'?'`、DP は完全な自由を模索しますが、ローカルで隣接性を強制し、たとえアルファベットが大きくても、連続した同一文字がカウントされないようにします。
