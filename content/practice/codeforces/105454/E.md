 ## 解決策
 ## 問題の理解

 私たちに与えられたグループは、$n$ちょうど 3 人の異なるメンバーからなるチームを形成したいと考えています。 ただし、すべてのトリプルが許可されるわけではありません。$m$同じチームに一緒に出場できない禁断のペア。 有効なチームとは、そのトリオ内に禁止されたペアが出現しないような 3 人のグループです。 

タスクは、指定されたメンバーから有効なトリプルをいくつ形成できるかをカウントすることです。順序は重要ではなく、各メンバーは異なるチームで複数回使用できます。 2 つのチーム間で少なくとも 1 人が異なる場合、2 つのチームは異なるものとみなされます。 

制約$n \le 300$重要な構造上のヒントです。 すべてのトリプルに対する単純な列挙は、単独ですでに実行可能です。$\binom{300}{3} \approx 4.5 \cdot 10^6$ただし、ルックアップ構造を使用してトリプルごとの有効性をチェックすることで、時間制限内に収まります。 ただし、 までの対応も必要となりますので、$m \le 45{,}000$禁止されたペアの場合、ソリューションは高速な隣接性チェックをサポートする必要があります。 

微妙なエッジ ケースは、密な制限により有効なトリプルがまったく存在しない場合です。 たとえば、特定の人が関与するすべてのペアが禁止されている場合、その人を含むトリプルは機能しませんが、他のノード間のトリプルは依然として存在する可能性があります。 もう 1 つのエッジ ケースは、禁止されたペアがまったく存在しない場合です。この場合、答えは単純です。$\binom{n}{3}$。 

2 番目の明白ではない問題は、名前によるインデックス作成です。 入力には文字列が使用されるため、整数インデックスへの効率的なマッピングが必要です。 そうしないと、トリプル ループ内で繰り返される文字列比較が遅すぎます。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべてのトリプルを反復処理します。$(i, j, k)$と$i < j < k$を選択し、3 つのペアのいずれかが禁止されているかどうかを確認します。 ブール型の隣接行列またはハッシュ セットを使用すると、各チェックは次のようになります。$O(1)$、つまり完全な列挙が実行されます$O(n^3)$時間、最悪の場合でも約 2,700 万回の反復$n=300$。 これはすでに限界に近づいていますが、慎重に実装すれば、最適化された Python ではまだ許容可能です。 

重要な観察は、高速ペア ルックアップ以外に何も構築する必要がないということです。 制約は各トリプル内のローカル ペアを削除するだけであるため、DP や包含-排他などのより深い組み合わせ構造は必要ありません。 つまり、すべての候補トリプルを独立して検証できるということです。 

名前をインデックスに変換し、禁止された隣接行列 (またはビットセットのセット) を構築し、すべての組み合わせをスキャンして有効なトリプルを直接カウントします。 これ以上複雑な戦略は、出力自体が$\Theta(n^3)$最悪の場合は列挙。

 ## アルゴリズムのチュートリアル

 1. すべての名前を読み取り、それぞれに 0 から 0 までの一意の整数インデックスを割り当てます。$n-1$。 これにより、関係への常時アクセスが可能になります。 
2. 2D ブール構造を作成する`bad[i][j]`ペアかどうかを示す$(i, j)$は禁止されています。 両方の方向がマークされるように対称化します。 これにより、後で一定時間チェックすることが保証されます。 
3. 応答カウンターをゼロに初期化します。 これにより、有効なトリプルの数が累積されます。 
4. すべてのトリプルを反復処理します。$i < j < k$。 各トリプルについて、3 つのペア関係を確認します。$(i, j)$、$(i, k)$、 そして$(j, k)$。 
5. これらのペアのいずれも禁止されていない場合は、答えをインクリメントします。 それ以外の場合は、トリプルをスキップします。 
6. 最終カウントモジュロを出力します。$10^9 + 13$。 

これが機能する理由は、すべての無効なトリプルには少なくとも 1 つの禁止されたペアが含まれている必要があり、すべての有効なトリプルには禁止されたペアが含まれていないためです。 順序付けされていないトリプルをすべて 1 回だけ列挙し、それぞれが個別にチェックされるため、カウントは正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 13

def solve():
    n, m = map(int, input().split())
    
    name_to_idx = {}
    for i in range(n):
        name = input().strip()
        name_to_idx[name] = i

    bad = [[False] * n for _ in range(n)]

    for _ in range(m):
        a, b = input().split()
        a = name_to_idx[a]
        b = name_to_idx[b]
        bad[a][b] = True
        bad[b][a] = True

    ans = 0

    for i in range(n):
        for j in range(i + 1, n):
            if bad[i][j]:
                continue
            for k in range(j + 1, n):
                if not bad[i][k] and not bad[j][k]:
                    ans += 1

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```この解決策は、各名前をインデックスにマッピングすることから始まります。これにより、トリプル ループ内での文字列比較の繰り返しが回避されます。 隣接行列`bad`は対称であるため、禁止された各ペアが 2 回保存され、順序に関係なく 1 回の検索が可能になります。 

トリプル ループはインデックスが増加するように構成されており、各組み合わせが正確に 1 回カウントされることが保証されます。 内部では、を使用して早めに剪定します`bad[i][j]`、最初のペアが無効な場合、トリプル全体が無効になるためです。 この小さな最適化により、密なグラフにおける不必要な内部ループの反復が削減されます。 

最後に、3 つのペア チェックがすべて合格した場合にのみ、答えをインクリメントします。

 ## 特殊なケース

 いつ$n = 3$禁止されたペアがない場合、アルゴリズムは 1 つのトリプルを正確にチェックして受け入れ、1 を生成します。ループ構造は、特別なケースを使用せずにこれを自然に処理します。 

すべてのペアが禁止されている場合、すべてのトリプル チェックは最初または 2 回目の比較で失敗します。 たとえば$i=0, j=1, k=2$、少なくとも 1 つ`bad[i][j]`、`bad[i][k]`、`bad[j][k]`は true であるため、カウンタは増加しません。 

単一のノードが他のすべてのノードと互換性がない場合。`a`他のすべてのトリプルとともに禁止されています。`a`中に拒否されます`(i,j)`またはその後のチェック。 残り$n-1$ノードは依然としてノード間で有効なトリプルを形成しており、列挙では当然、変更を加えずにそれらの組み合わせのみがカウントされます。
