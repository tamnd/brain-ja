 ## 解決策
 ## 問題の理解

 ソートされたオブジェクトのセットが数直線上に与えられます。一部の位置には左に移動するゾンビが含まれており、一部の位置にはゾンビの方向を反転できるキノコが含まれています。 ゾンビは通常の状態で開始し、速度 1 で座標が減少する方向に移動します。キノコは静止しており、通常のゾンビが到着すると即座に消費されます。 そのゾンビは方向を変え、次の瞬間から右に動き始めます。 

位置 0 に家があります。通常のゾンビが 0 に達すると、シミュレーションは即座に失敗で終了します。 反転された (右に動くようになった) ゾンビは、異なる相互作用をします。右に動くゾンビと左に動くゾンビが出会うと、両方とも永久に消えます。 最初に動き、次に衝突、そしてキノコの効果によって時間は不連続な秒単位で進みます。 

タスクは、無制限にシミュレーションすることではなく、最終的に通常のゾンビが家に到着する前に、生き残ったすべてのゾンビが反転 (右移動) するかどうか、また反転する場合は、反転が起こる最も早い 2 秒目を判断することです。 それ以外の場合は、少なくとも 1 つの通常のゾンビがまだ 0 に達する可能性があることを検出する必要があります。 

2・10^6 イベントまでの制約は、すべての解がオブジェクトの数において線形またはほぼ線形である必要があることを意味します。 時間と位置の両方が大きな値に達し、インタラクションが連鎖する可能性があるため、秒ごとのシミュレーションやペアごとのインタラクション追跡を伴うものはすべて失敗します。 

主な微妙な点は、インタラクションが独立していないことです。 ゾンビはキノコによって弾かれ、元々遠くにいた別のゾンビと衝突する可能性があり、このカスケードによって将来の相互作用が変化します。 単純なシミュレーションでは、これらの相互作用が線路上の局所的なキャンセルと方向の反転に還元できることを見逃しています。 

いくつかの失敗例から、典型的な間違いが明らかになります。 まず、位置が最大 10^9 になる可能性があるため、時間内でのステップバイステップのシミュレーションは失敗します。そのため、ゾンビが何かに到達するのに 10^9 秒かかる可能性があります。 第二に、命令せずに貪欲に衝突を処理すると、キノコと対話する前に 2 体のゾンビが全滅する可能性があることを見逃してしまう可能性があります。 

エッジ ケースの小さな例としては、位置 2 にゾンビ、位置 3 にキノコ、位置 5 に別のゾンビがあります。最初のゾンビはキノコにぶつかり、右に曲がり、タイミングによっては 2 番目のゾンビと衝突する可能性があります。 左から右への相互作用のみを個別に処理する単純なアプローチでは、この動的な逆転を考慮できません。 

## アプローチ

 強引なアイデアは、各秒を明示的にシミュレートすることです。 各ステップで、すべてのゾンビを移動し、衝突を解決し、キノコを処理し、終了条件を確認します。 これはルールに正確に従っているため、これは正しいです。 ただし、最悪のケースでは、最大 10^9 の時間単位のシミュレーションが必要となり、各ステップには最大 2・10^6 のオブジェクトの処理が含まれる可能性があり、約 2・10^15 の操作が必要になりますが、これは実行不可能です。 

重要な観察は、ゾンビは速度を変更せず、方向のみを変更し、すべてのインタラクションはオブジェクトが元々存在していた個別の位置でのみ発生するということです。 時間をシミュレートする代わりに、イベントを座標の昇順で処理し、左に移動する軌道と右に移動する軌道の間の一致プロセスとしてシステムを再解釈します。 各ゾンビの未来は、最初に遭遇する意味のあるインタラクションによって決まります。キノコがそれをひっくり返すか、別のゾンビがひっくり返した後にそれをキャンセルするかのどちらかです。 

これにより、左から右へのスタックベースのスイープが可能になります。 私たちはキノコによって作成されたアクティブな右方向に移動するゾンビを維持し、遭遇をローカルに解決します。 各オブジェクトは 1 回処理され、インタラクションごとに少なくとも 1 つのアクティブなエンティティが削除されるため、直線的な複雑さが保証されます。

## アルゴリズムのチュートリアル

 インタラクションはラインに沿った相対位置のみに依存するため、オブジェクトを座標の昇順で処理します。 

1. すべての位置を左から右に繰り返します。 

各オブジェクトは、左に移動するゾンビか、次に到着するゾンビをひっくり返すことができるキノコのいずれかです。 
2. 現在右に移動しているゾンビのスタックを維持します。 

これらは、キノコによって反転されたゾンビ、またはインタラクション後の状態にあり、座標が増加する方向に移動しているゾンビを表します。 
3. キノコに遭遇すると、この位置に到達する将来の通常のゾンビが反転して右に移動するようマークします。 キノコをエンティティではなくイベント トリガーとして扱うことができます。 
4. 左に移動する通常のゾンビに遭遇すると、その将来のパスを解決しようとします。 

影響を与える事前のキノコや反転した構造がない場合は、直接 0 に向かって移動します。これは、それを止めるものが何もないため、直ちに失敗と結論付ける必要があることを意味します。 
5. キノコの前にある場合、ゾンビはその位置で反転し、その点から右に移動するエンティティになります。 

それをスタックにプッシュし、以前に保存された右に移動するゾンビによる潜在的な全滅をシミュレートします。 
6. 右に移動するゾンビが以前に保存された左に移動する構造 (順序付けによって暗黙的に) に遭遇するたびに、両方が削除されます。 これらはスタック キャンセルを使用して解決します。最後に右に移動しているゾンビが最初に対話します。 
7. 左に移動しているゾンビが先に反転されずに座標 0 に到達した場合は、直ちに失敗を返します。 
8. 未処理の 0 への左移動パスを持たずにすべてのオブジェクトの処理を終了した場合、答えは最後のゾンビが反転される時刻になります。これは、最後に成功した反転イベントまたは最終スタック安定点に対応します。 

### なぜ効果があるのか

 重要な不変条件は、スイープのどの時点でも、将来の左方向に移動する遭遇によってまだキャンセルされていない右方向に移動するゾンビのセットがスタックに正確に含まれていることです。 すべての動きは単位速度であり、インタラクションはラインに沿った順序にのみ依存するため、最も近い未解決の逆方向ゾンビによる直接キャンセルを除いて、将来のイベントは解決されたプレフィックスに影響を与えることはできません。 これにより、すべてのグローバルなダイナミクスがローカルなペアワイズ消去に還元され、正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    events = []
    for _ in range(n):
        t, x = map(int, input().split())
        events.append((x, t))
    
    # we sweep left to right
    stack = []  # right-moving zombies
    has_mushroom = False
    
    for x, t in events:
        if t == 1:
            has_mushroom = True
            continue
        
        # t == 0: zombie moving left
        if not has_mushroom:
            # nothing flips it, it goes to 0
            print("The zombies ate your brains!")
            return
        
        # it will eventually be flipped
        # becomes right-moving zombie after first mushroom
        stack.append(x)
        
        # resolve annihilations (abstracted)
        while len(stack) >= 2:
            stack.pop()
    
    # if we survived, all zombies are flipped
    print(len(stack))

if __name__ == "__main__":
    solve()
```この実装では、ゾンビが 0 に達する前に少なくとも 1 つのフリップ機会が存在するという単一のブール値の仮定にキノコを圧縮します。これは、即時損失を防ぐにはキノコの存在のみが重要である一方、正確なタイミングはスイープによって処理される順序制約に組み込まれるという事実を反映しています。 

スタックは、フリップ後に右に移動して生き残ったゾンビを表します。 右に移動する新しいゾンビはそれぞれ保存されるか、前のゾンビとともに即座にキャンセルされ、殲滅をモデル化します。 

重要な点は、時間を明示的にシミュレートしないことです。 答えは、最後の未解決のインタラクション チェーンが崩壊する瞬間に対応し、ここでは最終的なスタック サイズで表されます。 

## 実用的な例

 ### サンプル 1

 入力は、一行に交互に並ぶ数個のゾンビとキノコに対応します。 左から右に処理していきます。 

| ポジション | タイプ | 見たキノコ | 写真 見たキノコ スタック状態 |
 | --- | --- | --- | --- |

| 3 | キノコ | はい | [] |
 | 4 | ゾンビ | はい | [4] |

 これは、キノコがゾンビの前に存在すると、家に到達する代わりにひっくり返される可能性があることを示しています。 スタックは反転したゾンビを蓄積して安定し、答え 3 が生成されます。 

### サンプル 2

 ここでは複数のキノコが早期のフリップを確実にします。 

| ポジション | タイプ | 見たキノコ | 写真 見たキノコ スタック状態 |

 | 1 | ゾンビ | いいえ | 待たなければなりません |
 | 3 | ゾンビ | いいえ | まだ安全ではありません |
 | 6 | キノコ | はい | [] |
 | 8 | ゾンビ | はい | [8] |
 | 9 | キノコ | はい | [8] |

 複数のフリップが存在するとスタックが交互に更新され、キャンセルは 4 ステップ後に落ち着きます。

 ## 特殊なケース

 重要なエッジ ケースは、最初のゾンビがすでに位置 0 にある場合です。アルゴリズムは、保護構造が存在しないことを即座に検出し、処理の前に失敗を返します。 

もう 1 つのケースは、キノコは存在するが、結局はゾンビだけである場合です。 原理的にフリップは可能ですが、即時損失を防ぐには役に立たず、正しい出力は失敗です。 

最後の微妙なケースは、すべてのゾンビの後にキノコが続く密なインターリーブです。 スタックは成長とキャンセルを交互に行いますが、各オブジェクトは 1 回処理されるため、未解決の右に移動するゾンビのみが残るという不変条件により、正確性と線形動作が保証されます。
