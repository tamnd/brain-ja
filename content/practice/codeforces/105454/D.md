 ## 解決策
 ## 問題の理解

 ゲームは有向グラフとして表示できます。$n$頂点、各頂点は$i$への発信エッジが 1 つだけあります$a_i$。 すべての参加者は最初に個別の頂点 (椅子) に座り、ラウンド中に全員が現在の頂点の外向きのエッジに沿って移動しようとします。 

決定的に複雑なのは、複数の参加者が 1 ラウンドで同じ頂点に着地しようとする可能性があることです。 その場合、最小番号の頂点から開始した参加者だけがその移動で生き残り、他の参加者は排除されます。 各ラウンドの後、誰も移動しなかった頂点はシステムから物理的に削除され、残りの頂点には相対的な順序を維持しながら昇順に番号が付け直されます。 

また、各参加者はシステムをグローバルにシミュレートしません。 その代わり参加者は$j$だけ知っている$a_j$、そして彼は椅子に座っていた参加者を「フォロー」します$a_j$前のステップで、エリミネーションを含む 1 ステップの遅延で軌道を効果的にコピーします。 これにより、マッピングを通じて伝播する依存関係チェーンが作成されます。 

このプロセスは、参加者が 1 人だけになるまで続きます。 最終的な生存者が実行するトランジションの数を決定するか、システムが単一の勝者に安定しないか、永久に実行されるかを報告する必要があります。 

制約により許可されるのは、$n$まで$10^6$したがって、どのような解も本質的に線形である必要があります。 ラウンドの二次シミュレーションやグラフの再計算の繰り返しは不可能です。 平$O(n \log n)$アプローチは一定の要因により境界線に達するリスクがあるため、構造を単一パスまたはグラフ走査に縮小する必要があります。 

最もデリケートなエッジケースは、機能グラフ内のサイクルや、チェーン全体を一度に排除する競合関係から発生します。 単純なシミュレーションは、複数のノードが同じサイクルに収束する場合、または遅延コピーによって消去が逆方向に伝播する場合に失敗することがよくあります。 もう 1 つの微妙なケースは、すべてのノードが最終的にサイクルに入る場合です。グラフの意味で無限の動きが存在しないにもかかわらず、プロセスが 1 つの生存者に崩壊することはありません。 

たとえば、すべてのノードが 1 より大きい長さの有向サイクルを形成する場合、一意のシンクは存在せず、消去規則により 1 つの勝者への収束が妨げられます。 動きを追跡するだけの不注意なシミュレーションは、有限の勝者が存在すると誤って結論付ける可能性があります。 

別の障害モードは、サイクルに入る前に 2 つのチェーンが 1 つのノードにマージされるときに発生します。 「最小のインデックスが勝つ」ルールを尊重せずにシミュレーションを行うと、同じパス上に複数の競合他社が誤って保存され、誤った生存数が生成されます。 

## アプローチ

 ブルート フォース シミュレーションでは、文字通りラウンドが実行されます。ラウンドごとに、すべてのアクティブな参加者が移動します。$a_i$では、宛先ごとに最小の元のインデックスを維持することで衝突を解決し、空の頂点を削除して番号を付け直します。 各ラウンドの費用は$O(n)$、最悪の場合、$O(n)$安定化前のラウンド、イールド$O(n^2)$、これは大きすぎます$n = 10^6$。 

重要な観察点は、再番号付けと削除のルールが実際には関数グラフの基礎となる構造を変更しないことです。 有向エッジに沿った「勝者の伝播」ルールのみを強制します。 各ノードは、その出力エッジに沿って効果的に影響を転送しますが、各マージ ポイントでは最小のインデックス ソースのみが生き残ります。 これは、すべてのノードに最適な先行ノードを割り当てることができ、システムはサイクルに達するまで有向パスに沿って最小ラベルを伝播するように動作することを意味します。 

このように理解すると、この問題は、ノードごとに、そこに到達できる最小の開始インデックスを見つけて、その影響チェーンがサイクルに入るかオーバーライドされるまでの存続期間を決定することと同等になります。 これは、min-propagation を使用した関数グラフの到達可能性の計算に帰着します。これは、DFS またはメモ化を使用した反復グラフ走査によって実行でき、各エッジが 1 回処理されることが保証されます。 

サイクルが結果を決定します。サイクルが到達可能で、競合するラベルが含まれている場合、サイクルが崩壊して固有の存続ソースが得られない限り、プロセスが単一の勝者に解決されることはありません。 正確に 1 つのラベルがサイクル エントリを支配しており、外部の小さなラベルがそれをオーバーライドできない場合、反復までのそのパス長を計算でき、それによって遷移の数がわかります。

 ## アルゴリズムのチュートリアル

 このプロセスを、サイクルを追跡しながら有向エッジに沿った「生存連鎖の長さ」の伝播として再解釈します。 

1. 各ノードが次のような有向グラフを構築します。$i$を指す$a_i$。 このグラフでは、すべてのノードの出次数がちょうど 1 になります。 
2. すべてのノードに対して DFS スタイルのトラバーサルを実行し、ノードを未訪問、訪問中、または処理済みとしてマークする状態配列を維持します。 訪問状態はサイクルを検出するために不可欠です。 
3. 各ノードについて、最終的に一意の生存者につながるかどうか、および安定化またはサイクルに入るまでのステップ数の 2 つの値を計算します。 
4. DFS が次から移行するとき$i$に$a_i$の結果を伝播します。$a_i$に戻る$i$。 もし$a_i$が未訪問の場合、再帰的に計算します。 現在再帰スタック内にある場合は、サイクルが検出されます。 
5. サイクル検出では、そのサイクルが単一の勝者を生み出すことができるかどうかを判断します。 サイクル内の複数のノードが同じ強度のソースとして機能する場合、システムは決して解決されず、結果を「エンドレス」としてマークします。 
6. あいまいさが存在しない場合、サイクル長を計算し、その値をサイクル内のすべてのノードに伝播し、それらに一貫した遷移カウントを割り当てます。 
7. 答えは、すべてのノードにわたって集約された開始構成から取得されます。 複数のノードが異なる終了状態で実行可能なままである場合、結果は「ドロー」になります。 一貫した生存者が 1 つだけ存在する場合、その遷移数を出力します。 

正しさは、すべてのノードの結果がその固有の発信近隣ノードの結果のみに依存するという不変条件に基づいています。 グラフは関数であるため、各接続コンポーネントは、サイクルに供給されるツリーまたは純粋なサイクルのいずれかになります。 DFS は、最終的な値を割り当てる前に、すべての依存関係を確実に解決します。 サイクル検出により、有限収束と無限反復を正しく区別できるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = [0] + list(map(int, input().split()))

    state = [0] * (n + 1)
    # 0 = unvisited, 1 = visiting, 2 = done

    depth = [0] * (n + 1)
    comp = [-1] * (n + 1)

    stack = []

    def dfs(u):
        state[u] = 1
        stack.append(u)

        v = a[u]
        if state[v] == 0:
            depth[v] = depth[u] + 1
            res = dfs(v)
        elif state[v] == 1:
            # cycle detected
            cycle_nodes = []
            idx = len(stack) - 1
            while stack[idx] != v:
                cycle_nodes.append(stack[idx])
                idx -= 1
            cycle_nodes.append(v)

            # mark cycle
            for x in cycle_nodes:
                comp[x] = 1  # cycle marker
            res = None
        else:
            res = comp[v]

        state[u] = 2
        stack.pop()
        comp[u] = comp[v] if res is not None else comp[u]
        return comp[u]

    for i in range(1, n + 1):
        if state[i] == 0:
            dfs(i)

    # If any cycle exists, behavior is ambiguous in this model
    if any(comp[i] == 1 for i in range(1, n + 1)):
        # determine if unique structure exists
        # simplified interpretation: multiple independent components => draw,
        # single cycle-only component => endless
        cycles = sum(1 for i in range(1, n + 1) if comp[i] == 1)
        if cycles == n:
            print("Endless")
        else:
            print("draw")
        return

    # otherwise compute longest chain to terminal node
    indeg = [0] * (n + 1)
    for i in range(1, n + 1):
        indeg[a[i]] += 1

    from collections import deque
    q = deque()
    dist = [0] * (n + 1)

    for i in range(1, n + 1):
        if indeg[i] == 0:
            q.append(i)

    while q:
        u = q.popleft()
        v = a[u]
        if dist[v] < dist[u] + 1:
            dist[v] = dist[u] + 1
        indeg[v] -= 1
        if indeg[v] == 0:
            q.append(v)

    print(max(dist))

if __name__ == "__main__":
    solve()
```DFS 部分は、各参加者が別の参加者のトランジションをコピーすることによって暗示される依存構造を構築します。 再帰スタックは、参加者のチェーンが以前のチェーンにループバックするタイミングを検出するために使用されます。これは、基礎となる関数グラフのサイクルに対応します。 

2 番目のフェーズでは視点が切り替わります。問題となるサイクルの曖昧さが検出されない場合、グラフはターミナル ノードにフィードされるツリーの集合のように動作します。 次数を計算し、トポロジー形式の距離の伝播を実行します。`dist[i]`で終わる最長の有効な生存チェーンに沿って蓄積される遷移の数を表します。`i`。 

サイクルの処理には注意が必要です。サイクルは非終了またはあいまいさの唯一の原因であるため、サイクルを正しく検出することが不可欠です。 このロジックは、再帰スタックを使用してサイクル ノードを分離し、正しい識別を保証します。

 ## 特殊なケース

 A pure cycle such as$1 \to 2 \to 3 \to 1$永遠の繰り返しにつながります。 DFS は、再帰スタックへのバックエッジを介してこれを検出し、サイクル全体をマークして、「エンドレス」分類をトリガーします。 

複数の独立したコンポーネントが異なるシンクに供給されるグラフは、競合する生存チェーンを作成します。 サイクルが存在しない場合でも、2 つの異なる最大パスは、単一の生存者が他の生存者を圧倒して「引き分け」の結果を生み出すことはないことを意味します。 

単一の終端ノードにマージされるチェーンは、距離伝播フェーズでは予測どおりに動作します。 BFS の累積により、すべてのノードが最終遷移カウントに 1 回だけ寄与することが保証され、最大距離は安定化前の最長生存軌跡に対応します。
