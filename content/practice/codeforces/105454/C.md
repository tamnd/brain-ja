 ## 解決策
 ## 問題の理解

 都市は、各家が頂点であり、各道路が重みのないエッジである無向接続グラフです。 郵便ハブは、正確に 1 つの頂点に配置する必要があります。 その後、複数の配達が計画されており、各配達は荷物を発送元の家から目的地の家まで移動することで構成されます。 配達ごとに、宅配業者はまず配達元からハブまで歩き、次にハブから目的地まで歩き、通過する道路ごとに 1 単位のコストを支払います。 

固定ハブの総コストは、すべての配送にわたるこれらのコストの合計です。 課題は、この総コストを最小限に抑えるハブの場所を選択することです。 

入力サイズは、グラフのノード数はそれほど多くないが、最悪の場合、最大で高密度のエッジを持つ可能性があることを示唆しています。 n と m の積制約により、同時に大きな値が得られなくなります。これは通常、目的の解空間では O(nm) または O(n(n+m)) の解が許容される一方で、k の 2 次または n の 3 次は範囲外であることを示します。 

単純な考えでは、考えられるすべてのハブを試し、そのハブからの最短パス検索を実行するか、距離を繰り返し再計算することによって総コストを計算することになります。 これは、すべての候補ハブの最短パスを再計算する必要があり、グラフの繰り返しの走査につながるため、すぐにコストが高くなります。 

配信がない場合、微妙なエッジケースが発生します。 その状況では、すべてのノードのコストがゼロになるため、どの頂点も有効になります。 正しいソリューションでは、少なくとも 1 つの配信が存在することを前提としてはいけません。 

複数のハブが最小コストを実現する場合には、別の特殊なケースが発生します。 この問題では、それらのいずれかを返すことが許可されているため、解決策は正確性を超えて決定的なタイブレークを強制しようとしてはなりません。 

## アプローチ

 直接的なアプローチは、考えられる各ハブを個別に評価することです。 固定ハブ x の場合、x からすべてのノードまでの最短パス距離を計算し、配信 (c, d) ごとに dist(c, x) + dist(x, d) を加算します。 グラフは重み付けされていないため、各最短パスの計算は BFS を使用して実行できます。 すべての候補ハブに対して BFS を繰り返すということは、n 回の BFS トラバーサルを実行することを意味し、それぞれのコストは O(n + m) になります。 これにより、O(n(n + m)) 回の操作が発生し、最悪の場合、制約 n · m ≤ 10^8 によって暗示される許可される作業の上限に近づきます。 これは概念的には正しいですが、繰り返し構造が無駄になります。すべての BFS が同じ距離情報を再計算します。 

重要な観察は、コスト式がエンドポイント間で明確に分離されていることです。 固定ハブ x の場合、総コストはリクエストに含まれるすべてのエンドポイントの合計になります。 各配信は dist(x, c) と dist(x, d) に寄与するため、ノード u がソースまたは宛先として出現する回数に等しい重み w[u] を定義できます。 ハブ x の合計コストは、w[u] · dist(x, u) のすべてのノード u にわたる合計になります。 これにより、ペアへの依存が完全に削除され、問題は各候補ルートからの重み付けされた距離の合計を評価することに変わります。 

ここで、タスクは、重み付けされていないグラフ、または少なくともこれらの重み付けされた合計を評価するのに十分な構造内のすべてのペアの最短経路距離を計算することになります。 最悪の場合、ノードの各ペア間に距離が必要になるため、各ノードから BFS を実行するのが最も簡単な方法です。 すべての距離が判明すると、各候補ハブの加重合計の計算が直接集計になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ハブごとに BFS を再計算する | O(n(n + m)) | O(n) | 最悪の場合遅すぎる |
 | 全ペア BFS + アグリゲーション | O(n(n + m)) | O(n^2) | 制約の下で受け入れられる |

 ## アルゴリズムのチュートリアル

1. グラフを読み取り、隣接リストを作成します。 グラフは重み付けされていないため、BFS は最短パスを計算する自然な方法です。 
2. 配列 w を構築します。ここで、w[u] は、すべての配信エンドポイントにわたってノード u が出現する回数をカウントします。 各配信は送信元に +1、宛先に +1 貢献します。 この再定式化により、ペアごとの寄与がノードごとの重みに置き換えられます。 
3. 1 から n までのすべてのノード s について、BFS を実行して、s から他のすべてのノードまでの最短距離である dist[s][*] を計算します。 最終的なコストは、考えられるすべてのハブからすべての重み付けされたノードまでの距離に依存するため、このステップが必要です。 
4. 固定音源 s からの距離を計算した後、すべてのノード u にわたる w[u] · dist[s][u] を合計することによってそのコストを計算します。 これは、ハブが s に配置された場合の合計コストを表します。 
5. 計算されたコストが最小のノードを追跡します。 複数のノードが同じ最小値を達成する場合、いずれか 1 つを保存できます。 
6. 最適なノードを出力します。 

BFS レイヤー構造は、各エッジに単位重みがあるため、最短距離の正確性を保証します。そのため、BFS で最初にノードが訪問されたときは、その最小距離に対応します。 

### なぜ効果があるのか

 ペアの寄与からノードの重みへの変換では、各配信がちょうど 2 つの独立した最短パス項に寄与するため、総コストが維持されます。 最短経路距離は無向グラフの対称性を満たし、和の直線性が保たれるため、端点ごとに項を再グループ化しても合計値は変わりません。 この分解が行われると、すべての候補ハブが同じ固定重み付き距離関数に対して評価されるため、すべてのノードの最小値を選択することは、元の最適化問題を解くことと同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def bfs(start, adj, n):
    dist = [-1] * (n + 1)
    q = deque([start])
    dist[start] = 0

    while q:
        v = q.popleft()
        for to in adj[v]:
            if dist[to] == -1:
                dist[to] = dist[v] + 1
                q.append(to)
    return dist

def main():
    n, m = map(int, input().split())
    adj = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b = map(int, input().split())
        adj[a].append(b)
        adj[b].append(a)

    k = int(input())
    w = [0] * (n + 1)

    for _ in range(k):
        c, d = map(int, input().split())
        w[c] += 1
        w[d] += 1

    # edge case: no deliveries
    if k == 0:
        print(1)
        return

    best_node = 1
    best_cost = float('inf')

    for s in range(1, n + 1):
        dist = bfs(s, adj, n)
        cost = 0
        for i in range(1, n + 1):
            cost += w[i] * dist[i]
        if cost < best_cost:
            best_cost = cost
            best_node = s

    print(best_node)

if __name__ == "__main__":
    main()
```BFS 関数は、キューを使用して単一ソースの最短パスを計算します。 外側のループは、各ノードを候補ハブとして評価します。 各候補について、同じ距離配列を再利用して線形時間で重み付き合計を計算します。 

実装の微妙な詳細は、距離を -1 で初期化することです。 これにより、グラフの接続が保証されている場合でも、ノードの再訪問が回避され、到達不能な状態が明確に区別されます。 もう 1 つの重要な点は、重みの累積を BFS 計算から分離することです。 これらを混在させると、BFS 内で重複した合計が繰り返され、実行時間が大幅に増加します。 

## 実用的な例

 距離を追跡しやすい小さなグラフを考えてみましょう。 各ノードを潜在的なハブとして評価し、エンドポイントの周波数に基づいて加重和を計算するとします。 

単純なトレースでは、ノード 1、2、3 がライン 1-2-3 を形成し、配信 (1,3) および (3,1) があると仮定します。 この場合、w[1] = 2、w[3] = 2、w[2] = 0となります。 

各候補ハブについて:

 | ハブ | 1 までの距離 | 2 への距離 | 3 までの距離 | コスト計算 |
 | --- | --- | --- | --- | --- |
 | 1 | 0 | 1 | 2 | 2・0 + 0・1 + 2・2 = 4 |
 | 2 | 1 | 0 | 1 | 2・1 + 0・0 + 2・1 = 4 |
 | 3 | 2 | 1 | 0 | 2・2 + 0・1 + 2・0 = 4 |

 すべてのノードが結合しているため、どのノードも有効です。 これは、エンドポイントの対称性が対称的なコスト分布につながることを示しています。 

ここで、ほとんどの配信が 1 つのエンドポイントを共有する、つまり多くのペアがノード 1 から開始して異なるノードに向かうという、偏ったケースを考えてみましょう。 次に、w[1] が大きくなり、重み付けされた距離を最小限に抑えると効果的にハブが高周波ノードに引き寄せられるため、最適なハブはノード 1 から他のノードへの最短パスの中心に向かって移動します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n(n + m)) | BFS は各ノードから実行され、各 BFS はすべてのエッジを 1 回処理します。 
| スペース | O(n^2) | 距離行列はソースごとに暗黙的に保存または再計算されます。 

n · m ≤ 10^8 という制約により、最悪の場合の積が制限されたままとなるため、n 回の BFS 走査の実行が確実に実行可能になります。 n が最大 10^4 であり、距離の保存やソースごとの再計算が制限内に収まるため、メモリは許容されます。

 ## 特殊なケース

 配信がない場合、アルゴリズムは BFS を実行せずに有効なノードを直接返します。 これにより、不必要な計算が防止され、コスト配列が未使用のままの場合の未定義の動作が回避されます。 

すべての配信エンドポイントが 1 つのノード (たとえばノード 1) に集中しているグラフの場合、重み配列はノード 1 までの距離を最小化する方向に候補ハブからの距離に大きくバイアスをかけます。BFS ベースのコスト評価はこれを正しく反映します。これは、すべてのコスト寄与が w[1] · dist(x, 1) に減少するため、最適なノードはノード 1 までの距離を最小化する 1 つになります。 

サイクルまたは完全なグラフなどの完全に対称なグラフでは、すべてのノードが均一なエンドポイント分布の下で同一の加重和を生成します。 アルゴリズムは、候補間で同一のコスト値を評価し、最初に見つかった最小値を受け入れることで、これを自然に保存します。
