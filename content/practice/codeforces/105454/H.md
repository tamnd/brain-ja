 ## 解決策
 ## 問題の理解

 a から b までの整数の範囲が与えられており、この範囲内にちょうど 6 つの正の約数を持つ数値がいくつあるかを数える必要があります。 範囲内の各整数 x について、概念的に因数分解し、約数の数を決定し、その数が 6 に等しいかどうかを確認します。 

素朴な解釈では、範囲内のすべての数値を反復処理し、その約数の数を個別に計算することがすぐに示唆されます。 b が最大 5,000 万の場合、区間には簡単に数千万の値が含まれる可能性があるため、数値ごとに O(√n) さえも費やす解は遅すぎます。 数値ごとに直接除数を列挙するには、(b − a + 1) × √b のオーダーの演算が必要になりますが、これは一般的な制限をはるかに超えています。 

さらに微妙な問題が、除数カウント条件自体に現れます。 ちょうど 6 つの約数を持つ数値は構造的に制限されているため、単純に数えると同じパターンが繰り返し再計算されてしまいます。 たとえば、32 には約数 {1, 2, 4, 8, 16, 32} があり、44 には約数 {1, 2, 4, 11, 22, 44} があります。 どちらも平方素数の権力構造の産物ですが、強引なアプローチではそれを利用できません。 

エッジケースは、狭い範囲と境界値から発生します。 たとえば、a = b = 1 の場合、1 には約数が 1 つしかないため、答えは 0 になります。 a = 32 および b = 32 の場合、32 は有効であるため、答えは 1 になります。 不注意なアプローチでは、単純な部分因子テストではなく正しい指数処理が必要となるため、除数の数え方に応じて 36 や 64 などの数値が誤って含まれる可能性があります。 

重要な観察は、「約 6 個」は非常に強力な算術制約であり、これにより、約数を 1 つずつ数える代わりに、すべての有効な数値を明示的に特徴付けることができるということです。 

## アプローチ

 ブルートフォース手法では、区間内のすべての整数を反復処理し、平方根までのすべての数値をチェックして約数を数えます。 これが機能するのは、d が √x に達するとすべての約数のペア (d, x/d) が見つかるため、正確さが簡単になるためです。 ただし、最悪の場合、最大 5,000 万の番号ごとに約 7,000 回のチェックが必要となり、実行時間が不可能になる可能性があるため、そのコストは O(n√n) と増大します。 

重要な構造的洞察は、「x の約数を数える」という観点から考えるのをやめ、代わりにちょうど 6 つの約数を持つすべての整数を分類することです。 

数値 x に 6 つの約数があるのは 2 つの場合のみです。 これは、p が素数で約数 1、p、p^2、p^3、p^4、p^5 を与える p^5 の形式であるか、p と q が異なる素数である p^2 q の形式です。 除数関数は乗法であり、(e1 + 1)(e2 + 1) ... = 6 が必要なため、これらは正確に 6 の除数とカウントの積を生成する唯一の素因数分解です。6 の因数分解は 6 と 2 × 3 であり、これら 2 つの構造に正確に対応します。 

これにより、問題は、これら 2 つの形式のすべての数を b まで生成し、[a, b] にいくつあるかを数えるというものに縮小されます。 すべての整数を処理する代わりに、小さな候補セットを生成します。 √b までの素数が構築に十分であるため、候補の総数は最大制約でも管理可能です。

 ## アルゴリズムのチュートリアル

 すべての有効な構造はこの範囲の素数に依存するため、最初にふるいを使用して √b までの素数を事前計算します。

1. エラトステネスのふるいを使用して、√b までのすべての素数を生成します。 これにより、p^2 q の形式の数値を効率的にテストして構築できるようになります。 
2. 各素数 p を反復処理して、p^5 を生成します。 p^5 が [a, b] 内にある場合は、それをカウントします。 これは、最初の構造的なケースを直接処理します。 
3. 各素数 p を反復処理し、p^2 を計算します。 このような値ごとに、q ≠ p であるすべての素数 q を反復し、p^2 · q を形成します。 結果が [a, b] にある場合は、それを数えます。 これは 2 番目の構造ケースをカバーします。 
4. セット内のすべての有効な数値を累積するか、直接数えることによって累積します。 セットを使用すると、異なる表現が同じ値を生成する場合に発生する可能性のある重複が回避されますが、この構造では慎重に処理すれば重複は事実上不可能になります。 
5. 最終的なカウントを出力します。 

### なぜ効果があるのか

 ちょうど 6 つの約数を持つすべての整数には、指数パターンが 6 に乗算される素因数分解が必要です。 有効なパターンは、単一の素数の 5 乗、または 1 つの素数の 2 乗と別の素数の 1 乗の積だけです。 このアルゴリズムは、√b までの素数の完全なセットを使用して、これらの指数パターンに一致するすべての数値を体系的に構築するため、これらのケースを正確に列挙し、その他のケースは列挙しません。 これらの形式以外の整数は、約数が少なすぎる (素数べき乗が小さすぎる) か、多すぎる (複数の上位の指数または追加の素因数) ため、正しく除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def sieve(n):
    is_prime = [True] * (n + 1)
    is_prime[0] = is_prime[1] = False
    for i in range(2, int(n**0.5) + 1):
        if is_prime[i]:
            step = i
            start = i * i
            for j in range(start, n + 1, step):
                is_prime[j] = False
    return [i for i in range(2, n + 1) if is_prime[i]]

def solve():
    a, b = map(int, input().split())
    limit = int(b ** 0.5) + 1

    primes = sieve(limit)

    ans = 0
    used = set()

    for p in primes:
        v = p ** 5
        if a <= v <= b:
            if v not in used:
                used.add(v)
                ans += 1

    for i, p in enumerate(primes):
        p2 = p * p
        if p2 > b:
            break
        for j, q in enumerate(primes):
            if q == p:
                continue
            v = p2 * q
            if v > b:
                continue
            if v >= a and v not in used:
                used.add(v)
                ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```sieve 構造は √b まで素数化されますが、p^2 q または p^5 の形式の有効な数は √b を超えない少なくとも 1 つの素因数を持たなければならないため、これで十分です。 

最初のループは p^5 を明示的に処理します。 これはまれですが、p^2 q 構造に適合しないため、直接確認する必要があります。 

2 番目のネストされたループは p^2 q を構築します。 q ≠ p チェックは、有効な構造ではない p^3 に相当する同じ素数を誤って 2 回処理することを防ぎます。 

このセットは一意性を保証しますが、列挙が一貫している場合には数学的に重複は発生しません。 これは、実装の重複に対する保護手段として機能します。

## 特殊なケース

 重要なエッジ ケースは、間隔に小さな素数とそのべき乗のみが含まれる場合です。 たとえば、1 ～ 10 を入力すると、有効な数値は生成されません。 p^5 も p^2 q も範囲内で形成できないため、アルゴリズムはこれを正しく処理します。 

もう 1 つのエッジ ケースは、p^2 q が異なるペアと一致する場合です。 たとえば、p = 2 と q = 3 は 12 を生成しますが、他のペアは 12 を生成しないため、重複は発生しません。 実装内のセットは、列挙順序が不完全であっても安全性を保証します。 

最後に、[49999990, 50000000] のように a と b が大きく、境界が厳密である場合、生成は区間密度に依存しないため、アルゴリズムは依然として少数の候補素数のみを評価します。 これにより、範囲の配置に関係なく、一貫したパフォーマンスが保証されます。
