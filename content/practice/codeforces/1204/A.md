 ## 解決策
 ## 問題の理解

 電車は時々出発します$$1, 4, 16, 64, \dots$$これはまさに 4 の累乗です。時間を指定すると、$s$、これらの出発時刻のうち、厳密に次の時刻よりも小さいものがいくつあるかを数える必要があります。$s$。 

珍しい部分は、$s$は 10 進数で与えられません。 代わりに、先行ゼロのないバイナリ文字列として指定され、その値は次のように大きくなります。$2^{100}-1$。 通常の 64 ビット整数では、すべての可能な値を格納するには不十分です。 

この制約は、数値全体を標準の整数型に変換することを避けるべきであることを即座に示唆しています。 バイナリ表現には最大 100 ビットが含まれるため、線形時間で文字列に直接作用するソリューションは簡単に十分に高速です。 

重要な観察は、すべての列車の出発時刻が 4 のべき乗であるということです。$$4^k = 2^{2k}.$$2 進数では、4 のべき乗は次のようになります。$$1,\ 100,\ 10000,\ 1000000,\dots$$それぞれに 1 つの設定ビットがあり、そのビットは偶数の位置にあります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
1
```時間はまさに$1$。 出発時間は必ず前でなければなりませんので、$s$、まだ電車は出発していません。 答えは次のとおりです。```
0
```4 以下の 4 の累乗を数える解$s$誤って 1 を返します。 

次のことを考慮してください。```
100
```これは$4$10進数で。 時間的には電車のみ$1$早く出発したので、答えは次のようになります。```
1
```繰り返しますが、使用して$\le$の代わりに$<$2が生成されます。 

別の微妙なケースは次のとおりです。```
101
```それは$5$。 出発時刻$1$そして$4$どちらも以前のものなので、答えは次のようになります。```
2
```両方の数値のバイナリ長は同じですが、これは前の例とは異なります。 純粋な 4 のべき乗と、同じビット長のより大きな数を区別する必要があります。 

## アプローチ

 直接的な総当たりのアイデアは、4 のべき乗を繰り返し生成することです。$$1,4,16,64,\dots$$より小さいものがいくつあるか数えます$s$。 以来$s < 2^{100}$、関連する 4 の累乗は約 50 個しかありません。最初にバイナリ文字列を大きな整数に変換すると、このアプローチは実際には十分に高速になります。 

より興味深い解決策は、数値の変換をまったく回避します。 

出発時刻は 4 のべき乗であり、まさにその数値です。$2^{2k}$。 次のバイナリ表現があるとします。$s$長さがある$L$。 

バイナリの長さが厳密に小さい 4 のすべてのべき乗$L$は自動的に以下より小さくなります$s$。 それらの長さは$$1,3,5,\dots$$なぜなら$2^{2k}$バイナリ長です$2k+1$。 

そのような力の数は$$\left\lfloor \frac{L-1}{2} \right\rfloor.$$残っているのは、4 のべき乗が同じバイナリ長を持つかどうかを判断することです。$s$もカウントする必要があります。 

長さのバイナリ文字列の場合$L$、その力は$$2^{L-1}.$$の場合のみ4のべき乗になります。$L-1$偶数、つまり$L$奇数です。 

もし$L$奇妙であり、$s$バイナリ文字列よりも厳密に大きいです$$1\underbrace{00\dots0}_{L-1\text{ zeros}},$$その場合、追加の 4 の累乗も次の値よりも小さくなります。$s$そして数えなければなりません。 

これにより、問題全体がバイナリ文字列自体の検査に集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(L) | お(1) | 承認済み |
 | 最適 | O(L) | お(1) | 承認済み |

 ここ$L \le 100$バイナリ文字列の長さです。 

## アルゴリズムのチュートリアル

 1. バイナリ文字列を読み取ります$s$。 
2. しましょう$L$その長さになります。 
3. バイナリの長さが厳密に以下の 4 のべき乗をすべて数えます。$L$。 

この番号は次のとおりです。$$\left\lfloor \frac{L-1}{2} \right\rfloor.$$4. もし$L$偶数、4 のべき乗は 2 進数の長さではない$L$, したがって、現在のカウントを出力します。 
5. もし$L$奇数です、比較してください$s$先頭に次の文字列が含まれるバイナリ文字列`1`その後にゼロだけが続きます。 

この文字列は次のことを表します$2^{L-1}$、長さを持つ 4 の固有の累乗$L$。 
6. もし$s$厳密にその文字列より大きい場合は、答えに 1 を加えます。 
7. 結果を出力します。 

なぜ効果があるのか:

 すべての 4 のべき乗は、偶数の指数に 1 つの設定ビットが正確に含まれる 2 進数に対応します。 2進数の長さが以下の数値の間で$L$、そのようなすべてのべき乗は自動的に以下より小さくなります。$s$、そしてそれらのカウントは正確に$\lfloor (L-1)/2 \rfloor$。 いつ$L$が奇数である場合、追加の候補が 1 つあります。$2^{L-1}$。 より厳密に小さい場合は正確にカウントする必要があります。$s$。 4 のべき乗は一度に 2 ビットの指数ずつ増加するため、他の 4 のべき乗は区間内に存在できません。 したがって、アルゴリズムは時間前の出発を正確にカウントします。$s$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
n = len(s)

ans = (n - 1) // 2

if n % 2 == 1:
    if s != "1" + "0" * (n - 1):
        ans += 1

print(ans)
```最初の部分では、バイナリの長さが入力の長さよりも厳密に小さい 4 のべき乗の数を計算します。 

表現`(n - 1) // 2`奇数の長さを数えることから直接得られます。$$1,3,5,\dots < n.$$残る唯一の問題は、同じバイナリ長の 4 の累乗を含めるべきかどうかです。 そのような力は、次の場合にのみ存在します。`n`奇数です。 

奇数の長さの場合`n`、関連するパワーは正確に次の文字列です。```
1000...000
```と`n-1`ゼロ。 入力がこの文字列と等しい場合、出発時刻は厳密には以前ではありません。`s`, なので追加しません。 同じ長さの他のバイナリ文字列の方が大きいため、4 の累乗をカウントする必要があります。 

整数変換は必要ないため、数値のサイズを気にする必要がなくなります。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    s = input().strip()
    n = len(s)

    ans = (n - 1) // 2

    if n % 2 == 1:
        if s != "1" + "0" * (n - 1):
            ans += 1

    return str(ans)

# provided sample
assert run("100000000\n") == "4", "sample 1"

# custom cases
assert run("1\n") == "0", "minimum value"
assert run("100\n") == "1", "exact power of 4"
assert run("101\n") == "2", "just above a power of 4"
assert run("11\n") == "0", "even length, no same-length power of 4"
assert run("1111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111111\n") == "50", "maximum length 100 bits"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`|`0`| 最小値における厳密な不等式 |
 |`100`|`1`| 正確な 4 の累乗自体はカウントされません。 
|`101`|`2`| 同じ長さですが 4 のべき乗より大きい |
 |`11`|`0`| 偶数長の数値には同じ長さの 4 のべき乗がありません。 
| 100個 |`50`| 許可されるバイナリの最大長 |
