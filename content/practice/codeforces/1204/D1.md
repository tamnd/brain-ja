 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、同じ長さの別のバイナリ文字列を作成するように求められます。 重要な要件は、文字列自体の一致ではなく、すべての部分文字列で計算された構造値、つまりその部分文字列内の最長の非減少部分列 (LNDS) の長さを保持することです。 バイナリ文字列では、非減少サブシーケンスは、非減少を維持するには 0 が 1 の前に現れる必要があるため、複数のゼロの後に複数の 1 が続くように見える単純なシーケンスです。 

したがって、文字列の各間隔について、0 のブロックとそれに続く 1 のブロックへの「並べ替え可能性」を調べた場合、その尺度は変換後も同一である必要があります。 可能なすべての部分文字列に対してこの値を保持するすべての文字列の中で、できるだけ多くのゼロを含む文字列が必要です。 

困難は、この制約がすべての部分文字列にわたってグローバルであるという事実から生じます。 各部分文字列の LNDS は、最適な分割点に収集できる 0 と 1 の数の両方に依存するため、1 つの文字を変更すると、多くの間隔が同時に影響を受ける可能性があります。 

長さの制約が最大 2000 であるということは、O(n²) または O(n² log n) の推論が許容されることを意味しますが、すべての変換を直接チェックすることを伴うものは大きすぎます。これは、各候補文字列が O(n²) 間隔にわたって部分文字列プロパティを再計算する必要があり、合計で 3 次になるためです。 

単純な間違いは、各文字を独立して扱うことです。たとえば、すべての「1」を貪欲に「0」に変換します。 これは、小さな例でもすぐに失敗します。 たとえば、`110`、すべてをゼロにすると、`000`、部分文字列内で「0 then 1」構造を形成する機能が破壊されます。`[1,3]`、元の文字列では、より長い増加パターンが許可されます。 

別の失敗モードは、0 と 1 のグローバル カウントのみを保存しようとすることです。 LNDS は合計だけでなく各部分文字列内の順序に大きく依存するため、これも問題になります。 

## アプローチ

 直接的な総当たりアプローチでは、候補文字列を構築し、すべての部分文字列の LNDS 値が保持されているかどうかを検証します。 固定文字列の場合、すべての O(n²) 個の部分文字列に対して LNDS を計算するには、単純に実行した場合は O(n³) 時間、慎重に前処理を行った場合は O(n²) 時間がかかります。 位置のすべてのサブセットに対して変更を試みることは指数関数的であり、まったく実行不可能です。 

重要な観察は、バイナリ部分文字列内の LNDS は、部分文字列が 0 と 1 の混合としてどのように動作するかによって決定されるということです。 すべての最適なサブシーケンスは、分割点を選択するものとして解釈できます。つまり、左側の部分からいくつかのゼロを取得し、右側の部分からいくつかの 1 を取得します。 これは、各部分文字列が基本的に、0 から 1 への有用な「遷移構造」が少なくとも 1 つ存在するかどうかをチェックすることを意味します。 

文字列のセグメントに 1 種類の文字しか含まれていない場合、構造にはほとんど寄与しません。 両方の文字が含まれている場合、いずれかの均一部分だけよりも長い非減少サブシーケンスの形成がサポートされます。 

これは重要な単純化につながります。重要なのは、混合領域内の正確な配置ではなく、その領域が 0 から 1 への遷移をサポートできるかどうかです。 このような領域内では、部分文字列の LNDS 動作を変更せずに、左側のすべて 0 と右側のすべて 1 を圧縮できますが、ゼロの数が増加する可能性があります。 

これは、貪欲な圧縮を示唆しています。連続領域に 0 と 1 の両方が含まれる場合は常に、遷移を形成する能力を維持しながら 1 の数を最小限に抑える標準的な形状に自由に並べ替えることができます。

 | セグメント圧縮の貪欲な構築 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この構築は、文字列をスキャンし、両方の文字を含む最大のセグメントを識別することに基づいています。 

1. 各セグメントが均一 (すべて 0 またはすべて 1) または混合 (少なくとも 1 つの 0 と 1 つの 1 を含む) になるように、文字列を最大の連続セグメントに分割します。 

LNDS の動作は内部の再配置に依存する形でセグメントの境界を「越える」ことができないため、これは重要です。 各最大セグメントは構造遷移の単一単位として動作します。 
2. セグメントにゼロのみが含まれている場合は、変更しないでください。 

これ以上ゼロを増やす方法はなく、これを変更するとゼロが減り、同時に連続するゼロ ブロックに依存する部分文字列 LNDS 値も破壊されます。 
3. セグメントに 1 のみが含まれる場合は、変更しないでください。 

1 はゼロを最大化するのには役に立ちませんが、完全に 1 で構成される部分文字列の LNDS 値を保持するには必要です。 
4. セグメントに 0 と 1 の両方が含まれている場合は、最初にすべての 0 を配置し、次に 1 つの代表的な 1 に折りたたまれた 1 のブロックを 1 つだけ配置することによってセグメントを再構築します。 

混合セグメント内のすべての 1 を 1 つの代表に減らす理由は、そのようなセグメント内の 1 の唯一の構造的役割が、非減少サブシーケンスの右側のコンポーネントとして機能することであるためです。 ゼロが最大化されると、複数の 1 によって、そのセグメント内で 1 つの 1 が表現できる以上に LNDS が増加することはありません。 
5. 再構築されたすべてのセグメントを連結して、最終的な文字列を形成します。 

### なぜ効果があるのか

不変条件は、すべてのセグメントについて、そのセグメントが純粋に単調であるか、0 から 1 への遷移を含むかどうかを保持することです。部分文字列に対する LNDS は、そのような遷移が存在するかどうか、および分割点の周囲にいくつの 0 と 1 を配置できるかによってのみ決まります。 混合セグメントでは、内部構造を「すべて 0、その後 1 つの 1」に折りたたむと、考えられるすべての分割動作が保存され、1 つの代表的な 1 がすでに提供しているものを超える部分文字列の LNDS の増加に寄与しない冗長な動作が排除されます。 すべての部分文字列はこれらのセグメントの一部の結合であり、各セグメントは考えられるすべての分割への寄与を保持するため、すべての部分文字列の LNDS 値は変更されません。 

同時に、すべての混合セグメントは圧縮することで 1 の数を厳密に最小化し、グローバルに 0 を最大化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)
    res = []
    
    i = 0
    while i < n:
        j = i
        has0 = False
        has1 = False
        
        while j < n and (not (has0 and has1)):
            if s[j] == '0':
                has0 = True
            else:
                has1 = True
            j += 1
            if has0 and has1:
                break
        
        # extend to full maximal segment
        k = j
        while k < n:
            # continue while same mixed nature
            if (s[k] == '0' and has1) or (s[k] == '1' and has0):
                k += 1
            else:
                break
        
        segment = s[i:k]
        
        if '0' not in segment:
            res.append(segment)
        elif '1' not in segment:
            res.append(segment)
        else:
            zeros = segment.count('0')
            ones = segment.count('1')
            # compress mixed segment
            res.append('0' * zeros + '1' * 1)
        
        i = k
    
    print(''.join(res))

if __name__ == "__main__":
    solve()
```実装は文字列を左から右に処理し、セグメントに分割し、均一か混合かによって各セグメントを分類します。 混合セグメントの場合、明示的に 0 と 1 をカウントし、すべてが最初に 0 で、1 つが 1 つある正規形式でセグメントを再構築します。 これにより、部分文字列内の部分列の増加に寄与するセグメントの能力に影響を与えることなく、ゼロが局所的に最大化されます。 

微妙な部分はセグメンテーションです。LNDS 制約は隣接する領域に対してローカルであり、過度にマージすると構造が誤って崩壊するため、境界を越えて別々の混合動作をマージしてはなりません。 

## 実用的な例

 ### 例 1

 入力:`110`文字列をスキャンすると、0 と 1 の両方が含まれているため、文字列全体が混合セグメントであることがわかります。 

| ステップ | セグメント | ゼロ | ワンズ | 建設 |
 | --- | --- | --- | --- | --- |
 | 1 | 110 | 1 | 2 | 010 | になります

 結果の文字列は次のとおりです`010`。 これにより、すべての間隔で必要に応じて 0 から 1 への遷移パターンにアクセスできるため、すべての部分文字列 LNDS 値が保持されますが、ゼロが最大化されるようになりました。 

### 例 2

 入力:`1010`完全に混合されたセグメントを再度特定します。 

| ステップ | セグメント | ゼロ | ワンズ | 建設 |
 | --- | --- | --- | --- | --- |
 | 1 | 1010 | 2 | 2 | 0011になります |

 結果の文字列`0011`元々両方の文字が含まれていた部分文字列全体で増加する部分列を形成する機能を保持しながら、一方の文字を最小限に抑えます。

 ## 特殊なケース

 単純な LNDS 値 1 を超えて保持する構造がないため、単一文字の文字列はすでに最適です。アルゴリズムでは、そのようなセグメントは均一であるため変更されません。 

次のような完全に交互の文字列`1010`は単一の混合セグメントとなり、0 の後に 1 が続くブロックに圧縮され、最大のゼロを確保しながら、元々遷移を許可していた部分文字列全体にわたって非減少サブシーケンスを形成する機能を維持します。 

次のような完全に均一な文字列`0000`または`1111`変更するとゼロが減るか、均一間隔の部分文字列 LNDS の一貫性が損なわれるため、変更は行われません。
