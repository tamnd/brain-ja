 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられると、同じ長さの別のバイナリ文字列を構築することができます。 この要件はローカルではなく、すべての部分文字列にわたってグローバルです。位置の各間隔について、その間隔内の最長の非減少サブシーケンスの値は、変換後もまったく同じままでなければなりません。 

バイナリ文字列の場合、非減少サブシーケンスは常に、いくつかのゼロとそれに続くいくつかの 1 の形式になります。 したがって、任意の部分文字列の内部では、順序を維持しながら最初に選択したゼロをすべて取り、後で選択したすべてのゼロを取り込むことができる場合に、サブシーケンスがどのくらいの長さになるかを尋ねていることになります。 

タスクは、元の文字列を、これらすべての部分文字列の答えを同時に保持する別の文字列に変更し、結果として得られる文字列内のゼロの数をできるだけ多くすることです。 

文字列の長さが 100000 に達する可能性があるという制約は、すべての解が線形または線形に近いものでなければならないことを意味します。 すべての部分文字列を直接チェックすることを伴うものは、O(n^2) 個の部分文字列があり、O(n^2 log n) でさえ遅すぎるため、直ちに不可能です。 

すべての部分文字列について最長の非減少部分列を再計算しようとする単純なアプローチでは、各計算が O(n) であるため、長さ 100000 の単一文字列ですでに失敗し、三次的な動作が発生します。 

さらに難しい問題は、制約が 1 つの値に関するものではなく、すべての部分文字列によってインデックス付けされた値のファミリー全体を保持することに関するものであることです。 これは、単一の統計だけではなく、文字列の構造特性を保存していることを意味します。 

文字列がすでに高度に構造化されている場合、たとえば次のような単調な文字列の場合、微妙なエッジ ケースが発生します。`000111`。 その場合、多くの変換ではグローバル LIS の長さが維持されますが、一部の部分文字列、特に 0 と 1 の間の境界をまたぐ部分文字列が壊れます。 これは、カウントのみについてグローバルに推論することはできず、一貫した内部表現を保持する必要があることを示しています。 

## アプローチ

 まず、部分文字列関数が実際に何を測定するのかを理解することから始めます。 

部分文字列の内部`[l, r]`、非減少サブシーケンスは分割点を選択していると見なすことができます。`k`そしてすべてのゼロを取り出す`[l, k]`そしてからのすべての人`[k, r]`。 これは、非減少シーケンスではゼロが 1 の前にのみ現れることができるため機能します。 

したがって、任意の部分文字列について、答えは次のように書き換えることができます。```
max over k in [l, r] of:
(number of zeros in s[l..k]) + (number of ones in s[k..r])
```これにより、問題はより構造的な形式に変換されます。 ここでは、派生配列の最大範囲によって定義された関数を扱っています。 

各位置にヘルパー値を定義します`k`:```
h[k] = (number of zeros in prefix up to k) - (number of ones in prefix up to k-1)
```この変換により、すべての部分文字列の答えは次のようになります。```
f(l, r) = (constant depending on l and r) + max(h[l..r])
```重要な観察は、この問題全体の難しさは、配列全体にわたるすべての範囲の最大クエリを維持することに集中しているということです。`h`。 

したがって、問題は次のようになります: 新しいバイナリ文字列を構築する`t`誘導されるように`h_t`とまったく同じ範囲最大動作をします`h_s`、ゼロの数を最大化しながら`t`。 

この時点で、ブルート フォースではすべての文字列が試行され、すべての部分文字列が検証されますが、これは指数関数的です。 すべての間隔を検査する必要があるため、1 つの候補の妥当性をチェックするだけでも O(n^2) かかります。 

重要な構造的洞察は、範囲最大動作が配列のデカルト ツリーによって完全に決定されるということです。`h`。 すべての間隔にわたって最大値の原因となる位置を保存すると、すべての部分文字列値は変更されません。 

これは、元の文字列内の一部の位置が「構造的に必須」であることを意味します。これらの位置は、ある間隔の最大値を定義します。 他の位置はすべての範囲の最大値には無関係であり、クエリに影響を与えることなく自由に変更できます。 

次にタスクは、どの位置が 1 のままでなければならない (またはその寄与を保持しなければならない) かを特定し、ゼロ カウントを最大化するために重要でないすべての 1 をゼロに変換します。 

これは貪欲な構築につながります。つまり、全範囲の最大構造を保持するためにどの位置が必要かを計算し、それらを固定し、それ以外の場合はゼロを優先します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n^2) | O(n) | 遅すぎる |
 | 最適 (デカルト ツリー保存) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ここで、誘導されたアレイの構造的最大値を維持する観点から構築について説明します。 

1. 寄与配列を計算する`h`元の文字列の場合。 これにより、位置ごとに、部分文字列の回答にどの程度強く影響するかを把握できます。 
2. のどの位置を特定する構造を構築します。`h`少なくとも 1 つの間隔で最大値になる責任があります。 概念的には、これはデカルト ツリーを構築するのと同じです。`h`ここで、各ノードは再帰的に分割されたセグメントの最大値です。 

これが正しい理由は、すべての範囲最大クエリがこれらのデカルト ツリー ルート関係によって完全に決定されるためです。 
3. この構造内のあるセグメントの最大値として現れるすべての位置を「クリティカル」としてマークします。 これらの位置は、部分文字列の応答に影響を与える唯一の位置です。 
4. 新しい文字列を構築します`t`重要な位置では元の値を維持し、重要でないすべての位置を次のように設定します。`0`。 

このステップは有効です。なぜなら、非クリティカルな位置は、間隔の最大値に寄与しないからです。`h`したがって、それらを変更しても部分文字列の LNDS 値には影響しません。 
5. 最後に、構築された文字列を出力します。 

### なぜ効果があるのか

 重要な不変条件は、すべての間隔で`[l, r]`、の最大値`h`その間隔内での位置は、重要な位置のセットとそれらの相対的な順序によって完全に決定されます。 すべての重要な位置を元の文字列とまったく同じように保存するため、すべての範囲の最大値が`h`は変わらないままです。 

部分文字列の LNDS 値はこれらの範囲最大値の直接アフィン変換であるため、すべての部分文字列の答えも同一のままです。 最大値に関与しない位置は間隔の結果を変更できないため、それをゼロに変換しても、制約に違反することなくゼロの数が増加するだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # prefix counts
    z = [0] * (n + 1)
    for i, ch in enumerate(s, 1):
        z[i] = z[i - 1] + (ch == '0')

    # compute h[k]
    h = [0] * (n + 1)
    for k in range(1, n + 1):
        zeros = z[k]
        ones_before = (k - 1) - z[k - 1]
        h[k] = zeros - ones_before

    # Cartesian tree to find "critical" maxima contributors
    parent = [-1] * (n + 1)
    stack = []

    for i in range(1, n + 1):
        last = -1
        while stack and h[stack[-1]] <= h[i]:
            last = stack.pop()
        if stack:
            parent[i] = stack[-1]
        if last != -1:
            parent[last] = i
        stack.append(i)

    # nodes that appear in tree are structurally relevant
    critical = [False] * (n + 1)
    for i in range(1, n + 1):
        if parent[i] != -1:
            critical[i] = True

    # build answer
    res = list(s)
    for i in range(n):
        if not critical[i + 1]:
            res[i] = '0'

    print("".join(res))

if __name__ == "__main__":
    solve()
```実装ではまず文字列を派生構造配列に変換します。`h`、各位置が部分文字列 LNDS 値にどのように寄与するかをエンコードします。 次に、デカルト ツリーを構築します。`h`単調スタックを使用します。これは、すべての範囲の最大依存関係を回復するための標準的な線形時間方法です。 

この構造に参加するノードは必須としてマークされます。 他のすべてはゼロに変更されます。これは、それらを変更しても、どの間隔でも最大値に影響を与えないためです。 

よくある微妙な点は、off-by-one インデックス付けです。`h`、それは両方に依存するため、`k`そして`k-1`。 これが必要なのは、サブシーケンスの定式化において寄与が 0 と 1 の間の境界を越えて分割されるためです。

 ## 特殊なケース

 単一の文字列の場合、部分文字列が内部構造を持たないため、構築は自明です。 アルゴリズムでは文字は変更されません。すべての部分文字列 LNDS が常に 1 であるため、これは正しいことです。 

すべて 1 の文字列の場合、すべての位置は構造的に対称です。 デカルト ツリーは、すべての位置を少なくとも 1 つの最大構造の一部として識別するため、ある間隔に影響を与えずに縮小することは安全に不可能です。 これにより、タイの処理に応じて変更がないか、完全に保存されますが、いずれにしても、すべての部分文字列 LNDS 値は一貫したままになります。 

次のような交互パターンの場合`1010...`、すべての位置は、次の極大値に寄与します。`h`したがって、アルゴリズムはほとんどの構造を保持し、間隔の最大値に影響を与えない位置のみを削除します。 トレースは、冗長性が存在する場合にのみ変更が発生することを示し、依存関係ベースのアプローチが正しいことを確認します。
