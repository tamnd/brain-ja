 ## 問題の理解

 長さが与えられています`n`正の整数の配列ですが、配列は任意ではありません。 その中のすべての値は、厳密な構造規則を満たす必要があります。各数値は次のいずれかです。`1`、または、その半分が配列内のどこかに存在する偶数です。 これは、到達するまで繰り返し 2 で割ることによって、すべての値を追跡できることを意味します。`1`、そのチェーン上のすべての中間値も配列内に存在する必要があります。 

その構造的な制約に加えて、私たちは多様性について何かを語られます。 配列には以下を含める必要があります`l`そして`r`個別の値 (包括的)。 このような配列を構築することは求められません。すべての有効な配列の要素の最小値と最大値の合計を決定することだけが求められます。 

制約は十分小さいので、`n`これは、任意の値空間を探索しているわけではないことをすぐに示唆しています。 有効な数値の構造は非常に制約されています。 すべての有効な数値は、次から始まる二重連鎖に属します。`1`したがって、値は 2 の累乗のように見えますが、繰り返しは許可されます。 

微妙な点は、「2 による除算による閉包」により、有効な個別の値のセットが、次から始まる倍増チェーンのプレフィックスになるように強制されることです。`1`。 含めると`8`、 それから`4`、`2`、 そして`1`も存在する必要があります。 これにより、次のような不規則な組み合わせが排除されます。`{1, 2, 8}`それなし`4`。 

エッジケースは次の場合に発生します。`l`そして`r`個別の値の数を厳密に制限します。 たとえば、次の場合`l = r = 1`、値が大きくなると追加の必須要素が導入されるため、可能な配列はすべて 1 だけです。 もう一つのコーナーは、`n`大きいですが`r`が小さいため、小さな数値を大量に繰り返す必要があります。 

値の有効なサブセットをすべて列挙して多重度を割り当てようとする素朴なアプローチは、すぐに組み合わせ的になってしまいます。これは、サイズが 20 までのサブセットの数は依然として大きく、カウントを割り当てると指数層がさらに追加されるためです。 2 のべき乗の構造により、貪欲な構築が可能になります。 

## アプローチ

 ブルート フォース手法では、クロージャー ルールを満たす有効な個別の値のセットを選択し、配布しようとします。`n`それらの間の位置を計算し、結果の合計を計算します。 各候補セットについて、数値が次のとおりであることを確認します。`x`が含まれており、すべての値`x/2, x/4, ..., 1`も含まれます。 有効なチェーンに限定したとしても、各値が何回出現するかを考慮する必要があります。 

有効な個別のセットはその最大要素によって完全に決定されるため、可能な有効なチェーンの数は少ないですが、多重度の分布は柔軟なままです。 分布を強引に列挙すると、指数関数的な複雑さが生じます。`n`、おおよそのパーティションのオーダーに相当します。`n`最大 20 個の値にまたがるが、これは不可能です。 

重要な観察は、シーケンスのプレフィックスのみを考慮しているということです。`1, 2, 4, 8, ...`。 個別の値の数を固定すると`k`の場合、最適な値のセットが強制されます。`{1, 2, 4, ..., 2^(k-1)}`。 このプレフィックスの長さを超える構造を選択する自由はありません。 

値のセットを修正したら、各値を何回割り当てるかによって合計が決まります。 値が大きいほど合計が「高価」になるため、チェーンを有効に保つ必要があることを考慮しながら、可能な限り多くの要素を最大許容値に割り当てることによって最大合計が得られます。 最小合計はその逆です。できるだけ小さい値を優先しますが、それでも十分な個別の値が存在することを確認する必要があります。 

これにより、問題はすべての可能性を試行することになります`k`で`[l, r]`、それぞれについて`k`、強制チェーンの下で可能な限り最良の最小値と最大値の合計を計算します。`{1, 2, ..., 2^(k-1)}`。

 ## アルゴリズムのチュートリアル

 すべての有効な値はこのシーケンスから得られるため、2 の累乗シーケンスを事前計算します。 

1. 個別の値の可能な数ごとに`k`から`l`に`r`、標準的な値のセットを構築します`v_i = 2^(i-1)`のために`i`から`1`に`k`。 有効な構造はプレフィックス チェーンでなければならないため、これは割り算の制約によって強制されます。 
2. 固定の場合`k`、配布方法は当社が決定します`n`この中での出来事`k`有効性を維持しながら値を変更します。 この制約は、繰り返しを許可する以上にカウントを制限しないため、すべての分布が存在する限り、どのような分布も有効です。`k`必要に応じて値が少なくとも 1 回表示されます。 
3. 合計を最小化するために、最初にできるだけ多くの要素を最小値に割り当てます。 これは貪欲な充填プロセスです。区別性を満たすために必要な値を 1 つずつ配置し、残りのスロットを最小値に割り当てます。`1`。 
4. 合計を最大化するには、逆のことを行います。 必要な各値を 1 つずつ割り当て、残りのスロットを最大値に分配します。`2^(k-1)`。 
5. それぞれの結果の合計を計算します。`k`、有効なすべてのグローバル最小値と最大値を追跡します。`k`。 

重要な点は、プレフィックス長を固定した後は、コスト構造が単調であるため問題が線形になることです。つまり、2 の大きい累乗が常に小さい累乗を支配するため、貪欲な割り当てが両方向で最適になります。 

### なぜ効果があるのか

 クロージャ プロパティは、すべての有効な個別の値のセットが倍増シーケンスのプレフィックスを形成するように強制します。 このプレフィックス長が固定されると、追加の構造上の選択はなくなり、多重度の割り当てのみが行われます。 合計への寄与はすべて線形であり、大きさによって順序付けされているため、最適化は、最小値または最大値のいずれかに応じて最小値または最大値にカウントを貪欲に割り当てることによって決まります。 小さい値と大きい値の間で質量単位を交換すると、合計が固定方向に厳密に変更されるため、並べ替えを行っても結果は改善されません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, l, r = map(int, input().split())

    # precompute powers of two up to 20 (safe upper bound)
    pw = [1]
    for _ in range(1, 25):
        pw.append(pw[-1] * 2)

    min_ans = float('inf')
    max_ans = 0

    for k in range(l, r + 1):
        # construct values 1,2,4,...,2^(k-1)
        vals = pw[:k]

        # MINIMUM: put one of each, rest go to 1
        min_sum = sum(vals)
        min_sum += (n - k) * vals[0]

        # MAXIMUM: put one of each, rest go to largest
        max_sum = sum(vals)
        max_sum += (n - k) * vals[-1]

        min_ans = min(min_ans, min_sum)
        max_ans = max(max_ans, max_sum)

    print(min_ans, max_ans)

if __name__ == "__main__":
    solve()
```コードでは、必要な値に直接インデックスを付けることができるように、最初に 2 の累乗を構築します。 可能な個別のカウントごとに`k`、唯一の有効な構造は最初のものであると想定します。`k`2 の累乗。 次に、各値が 1 回出現するベースライン合計を計算します。 そこから残りを分配します`n - k`最小化するか最大化するかに応じて、要素を最小値または最大値に変換します。 

よくある間違いは、それぞれの個別の値が少なくとも 1 つ存在する必要があることを忘れることです。そのため、追加分を配布する前に、ベースラインの合計には各値が 1 つだけ含まれます。

 ## 特殊なケース

 いつ`l = r = 1`、構造は値のみに崩壊します。`1`より大きな値を指定すると、追加の個別の要素が強制されるためです。 アルゴリズムはこれを処理します。`k = 1`単一の値リストを生成します`[1]`、最小値と最大値の両方が次のようになります。`n`。 

いつ`k`など大きいです`k = 20`、値は指数関数的に増加するため、大きな累乗が 1 つ含まれるだけでも合計を支配します。 貪欲な割り当てにより、追加の要素は常にどちらかに配置されます。`1`または`2^(k-1)`、組み合わせ推論を必要とせずに、極端な動作を正確に捕捉します。 

もし`n`等しい`k`、配布する追加の要素はなく、答えは単に最初の要素の合計です。`k`2 の累乗。 実装はこれを処理します。`(n - k)`はゼロになり、基礎合計のみが残ります。
