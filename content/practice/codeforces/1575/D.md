[CF 1575D - 25 で割り切れる](https://codeforces.com/problemset/problem/1575/D)

 **評価:** 1800
 **タグ:** ブルート フォース、DFS および類似の、DP
 **解決時間:** 2 分 1 秒
 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 部分的に未知の整数を表す、最大長 8 の非常に短い文字列が与えられます。 一部の位置には固定数字が含まれており、一部には「ここでは任意の数字が許可される」ことを意味するワイルドカード アンダースコアが含まれており、また一部には文字 X が含まれており、すべての X 位置が同じ数字の選択を共有する必要があることを意味します。 

このタスクは、25 で割り切れる有効な整数を生成する完全な桁の割り当ての数を数えることです。同時に、正確に 0 でない限り、最終的な数値の先頭にゼロを付けることはできないという通常のルールも尊重します。 X によって導入される結合は、位置ごとに独立したアンダースコアとは異なり、複数の位置をグローバルに結合するため、主な複雑さになります。 

制約の長さは非常に短いため、漸近的に効率的な文字列処理の必要性は直ちに排除されます。 すべての数字の割り当てを試すソリューションであっても、最悪の場合でも共有数字の選択肢が最大 9 つ、各ワイルドカード位置の選択肢が 10 つであり、管理可能な検索スペースが得られるため、妥当性があります。 

微妙な難しさは複雑さではなく正確さです。 一般的な故障モードは 2 つあります。 

1 つは、X のグローバル制約を無視することです。たとえば、次のような文字列です。`1X2X`、各 X を個別に扱うと、異なる桁の割り当てなど、無効な割り当てが過剰にカウントされます。 

もう 1 つは、先行ゼロの誤った処理です。 単純な置換では、次のような文字列が可能になる可能性があります。`0X`に変わっていく`00`、数値全体がゼロでない限り無効です。 

最後に、25 で割り切れるかどうかは、完全に最後の 2 桁によって決まります。 不注意なアプローチで、部分的な構成の可除性をチェックしたり、接尾辞制約の適用を忘れたりすると、有効な補完を誤って数えることになります。 

## アプローチ

 当然、強引なアプローチが考えられます。 すべてのワイルドカード位置に個別に数字を割り当てることも、X の数字を選択して、結果として得られるそれぞれの数字をテストすることもできます。 長さは最大 8 であるため、割り当ての可能性をすべて列挙し、両方の制約を満たすものを数えることができます。 

ただし、この構造は純粋な 10^8 列挙型よりも若干制限されています。 すべてのアンダースコアは最大 10 の係数に寄与し、X はグローバルに 10 の選択肢のみを寄与します。 8 つのアンダースコアと X の最悪のケースでも、これは依然として約 10^9 の可能性であり、候補文字列ごとに単純に実装すると大きすぎる境界線になります。 

重要な観察は、25 で割り切れる可能性は最後の 2 桁のみに依存するということです。 これにより、グローバル条件が長さ 2 の接尾辞の制約に折りたたまれます。 完全な数値を生成して割り切れるかどうかを確認する代わりに、有効な語尾を構築し、プレフィックスを一貫して埋めることができる方法が何通りあるかを数えることに集中できます。 

2 番目の重要な観察は、先行ゼロ制約は最初の非固定または割り当てられた桁の位置にのみ依存し、X にどの桁が使用されているかがわかれば独立して処理できるということです。 

これにより、制御された列挙が可能になります。つまり、X の数字を選択し、すべてのアンダースコアの位置を埋め、制約、特に接尾辞の有効性と先行ゼロの有効性をローカルで検証します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての割り当てのブルートフォース列挙 | O(10^k) | お(1) | 遅すぎる |
 | X 桁 + 制約付き列挙を修正 | O(10 * 10^k) と効果的な枝刈り O(10^6) | お(1) | 承認済み |

 ここで k ≤ 8 であるため、最適化された列挙は問題なく制限内に収まります。 

## アルゴリズムのチュートリアル

 X の役割と独立したワイルドカードを分離して進めます。 

1. まず、文字列内の X のすべての位置を収集します。 何もない場合、X は追加の制約に寄与しないものとして処理されます。 
2. 0 から 9 までのすべての可能な数字 d を X の値として試します。これが必要なのは、すべての X 文字が 1 つの値を共有する必要があり、事前にそれがわからないためです。 
3. d を選択するたびに、すべての X が d に置き換えられた文字列の作業バージョンを構築します。 これにより、問題は数字とアンダースコアのみを含む問題に変換されます。 
4. 次に、アンダースコアを埋めます。 各アンダースコアは独立して 0 から 9 までの任意の数字を取るため、概念的にはすべての割り当てを列挙します。 ただし、必要な場合を除き、完全な文字列を明示的に構築することはありません。 代わりに、制約を適用しながら構成をカウントします。 
5. 完了した各割り当てについて、最後の 2 桁を確認します。 それらが 25 で割り切れる数値を形成する場合、その数値は有効です。 長さが短いため、このチェックは一定時間になります。 
6. 先行ゼロの有効性も強制します。 最初のゼロ以外の数字を見つけます。 すべての数字が 0 の場合、その数値は文字列全体が 0 の場合にのみ有効です。 それ以外の場合、最初のゼロ以外の数字の前の先行ゼロは許可されますが、数値が次のようなものではないことを確認する必要があります。`0000`一貫性のない扱いを受ける。 
7. X 桁のすべての選択肢にわたる寄与を合計します。 

### なぜ効果があるのか

 正確さは、X に割り当てられた値によって解空間を分割することで得られます。すべての有効な補完は、X 桁の 1 つの選択肢に正確に対応するため、二重にカウントしたり、構成を見逃したりすることはありません。 X が固定されると、残りの選択肢はすべてアンダースコアごとに独立します。 割り算の制約は最後の 2 桁のみに依存し、割り当て後に完全に決定されるため、最後にチェックするだけで十分です。 先行ゼロ制約はグローバル プレフィックス構造のみに依存します。グローバル プレフィックス構造は完全な割り当てで保存され、無効な数値がカウントされないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def valid_num(s):
    # leading zero rule
    if len(s) > 1 and s[0] == '0':
        # check if all zeros
        return any(c != '0' for c in s) == False

    # divisible by 25 check
    return int(s[-2:]) % 25 == 0 if len(s) >= 2 else int(s) % 25 == 0

def solve():
    s = input().strip()
    n = len(s)

    x_positions = [i for i, c in enumerate(s) if c == 'X']
    underscore_positions = [i for i, c in enumerate(s) if c == '_']

    ans = 0

    # all X must share same digit
    for xd in range(10):
        base = list(s)
        for i in x_positions:
            base[i] = str(xd)

        # enumerate all underscore assignments
        # since n <= 8, brute is acceptable with recursion
        def dfs(idx):
            nonlocal ans
            if idx == len(underscore_positions):
                cand = ''.join(base)
                if valid_num(cand):
                    ans += 1
                return

            pos = underscore_positions[idx]
            for d in range(10):
                base[pos] = str(d)
                dfs(idx + 1)

        dfs(0)

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずすべての X 位置を特定し、それらに対する 10 個の可能な数字の割り当てをすべて試行します。 このような割り当てごとに、アンダースコア位置に対して深さ優先検索が実行されます。 各再帰ステップでは、数字が 1 つのアンダースコアに割り当てられます。 文字列が完全にインスタンス化されると、検証されます。 

重要な実装の詳細は、共有リストの変更です`base`これにより、再帰中に文字列が繰り返しコピーされることがなくなります。 これは、このような小さな制約下でもパフォーマンスにとって重要です。 

可分性は、最後の 2 桁に対する Python のモジュロ演算に依存して、最終的に構築された文字列に対してのみチェックされます。 先頭のゼロの有効性は、文字列全体がゼロであるかどうかを明示的にチェックするヘルパー関数内で処理されます。 

## 実用的な例

 インプットを考慮する`25`。 

ここではワイルドカードや X 文字がないため、DFS は簡単です。 

| ステップ | X 桁 | アンダースコアの割り当て | 構築された文字列 | 有効なサフィックス | 有効 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | なし | なし | 25 | はい | はい |

 これにより、有効な数値が 1 つだけ生成されます。 

次に入力を考えてみましょう`_5`。 

25 で割り切れる 5 で終わる数字をすべて数えなければなりません。つまり、最後の 2 桁は 25 または 75 でなければなりません。 

| ステップ | X 桁 | アンダースコア | 文字列 | 最後の 2 桁 | 有効 |
 | --- | --- | --- | --- | --- | --- |

 これは、接尾辞の構造のみが重要であり、アンダースコアの選択は厳しくフィルタリングされていることを示しています。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、代入後に文字列がすべて 0 になる場合です。 たとえば、入力`X_`ここで、X は 0 として選択され、アンダースコアも 0 となります。`00`。 これは、数値全体がゼロであり、先行ゼロ規則で許可されているため有効です。 検証関数がすべての文字がゼロであるかどうかを明示的にチェックし、それを許可するため、アルゴリズムはこれを処理します。 

もう 1 つの特殊なケースは、先頭にゼロがあり、その後に有効な接尾辞が続く場合です。`_25`。 アンダースコアを 0 として割り当てると生成されます。`025`、これは先頭にゼロがあり、数値のゼロではないため無効です。 文字列はすべてゼロではなく、ゼロで始まるため、チェックでは正しく拒否されます。 

最後の微妙なケースは、次のような複数の X 位置です。`X_X`。 DFS はそれらを独立して割り当てません。 代わりに、列挙が開始される前にそれらはすべて 1 桁に固定され、位置間の一貫性が確保され、数えすぎが防止されます。
