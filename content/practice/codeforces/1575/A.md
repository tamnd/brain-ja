 ## 解決策
 ## 問題の理解

 すべて同じ長さの、異なる本のタイトルのコレクションがあります。 これらの書籍は、通常の辞書編集順では並べ替えられていません。 

2 つのタイトルを比較する場合、最初に相違する位置が見つかるまで、左から右にスキャンします。 その位置が奇数の場合は、小さい文字が最初に来る必要があります。 その位置が偶数の場合は、大きい文字が最初に来る必要があります。 

タスクは、このカスタム順序に従って書籍をソートした後、書籍の元の索引を出力することです。 

制約$n \cdot m \le 10^6$が重要な観察です。 文字列データの総量は最大 100 万文字です。 カスタム コンパレーター中に文字列を 1 文字ずつ繰り返し比較するソリューションは、コストが高くなる可能性があります。 各文字列を 1 回変換してから、言語の組み込みソートを使用するソリューションは、制限内に問題なく収まります。 周囲の複雑さ$O(nm)$前処理プラス$O(n \log n)$並べ替えは完全に許容されます。 

よくある間違いは、偶数の位置を間違って比較することです。 このステートメントでは 1 から始まる位置が使用されます。 位置 2、4、6、... は下降しています。 Python では文字列は 0 から始まるため、インデックス 1、3、5、... は偶数の位置に対応します。 

考慮する：```
2 2
AA
AB
```位置 2 では、降順に比較します。 以来$B > A$、文字列`AB`前に来るべきです`AA`。 位置 2 を昇順として扱うと、間違った順序が生成されます。 

最初の違いが偶数の位置に現れる場合には、別の微妙なケースが発生します。```
2 3
ABC
AAC
```最初の違いは位置 2 です。位置 2 は下降しているため、`ABC`前に来る`AAC`たとえ、通常の辞書編集順では`AAC`初め。 

## アプローチ

 ブルートフォース手法では、比較ルールを直接実装し、そのコンパレータを使用して並べ替えます。 各比較では、最大でスキャンできます。$m$文字。 並べ替えには必要なもの$O(n \log n)$比較、与える$O(nm \log n)$時間。 合計 100 万文字では、特にカスタム コンパレータが高価な言語では、これでも必要以上に重くなる可能性があります。 

順序付けの構造は、より明確なアイデアを示唆しています。 奇数の位置では通常のアルファベット順にします。 偶数の位置では、アルファベットの逆順が必要です。 

すべての偶数位置の文字を変換するとします。 交換する$$A \leftrightarrow Z,\quad B \leftrightarrow Y,\quad C \leftrightarrow X,\ldots$$この変換後、均等な位置にある大きな元の文字が、小さな変換後の文字になります。 偶数位置での降順比較は通常の昇順比較に変換されます。 

すべての文字列がこの方法で変換されると、カスタム順序は、変換された文字列上で正確に標準の辞書編集順序になります。 その後、通常どおり並べ替えることができます。

 ## アルゴリズムのチュートリアル

 1. すべての文字列を読み取り、元のインデックスを記憶します。 
2. 文字列ごとに、変換されたバージョンを構築します。 
3. 奇数の位置にある文字は変更しないでください。 
4. 偶数の位置にある文字の場合は、アルファベットのミラーに置き換えます。$$c \mapsto \text{'Z'} - (c-\text{'A'})$$これにより、降順比較が昇順比較に変換されます。 
5. ペアを保存する`(transformed_string, original_index)`。 
6. 変換された文字列によってすべてのペアを並べ替えます。 
7. 元のインデックスをソート順に出力します。 

### なぜ効果があるのか

 2つの文字列を取ります$a$そして$b$。 させて$k$それらが異なる最初の位置になります。 

もし$k$が奇数の場合、変換では両方の文字が変更されません。 通常の辞書編集的な比較におけるそれらの順序は、問題で必要とされる順序とまったく同じです。 

もし$k$が偶数の場合、変換により各文字がアルファベットのミラーに置き換えられます。 大きな元のキャラクターは、小さな変換されたキャラクターになります。 したがって、問題で必要とされる降順比較は、変換後は昇順比較になります。 

最初の異なる位置は同じままであるため、変換された文字列は、元の文字列が昇順、降順、終了順で比較されるのとまったく同じように、通常の辞書編集順で比較されます。 したがって、変換された文字列をソートすると、必要な順序が正確に生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def transform(s):
    chars = list(s)
    for i in range(1, len(chars), 2):  # 0-based indices => even positions in statement
        chars[i] = chr(ord('Z') - (ord(chars[i]) - ord('A')))
    return ''.join(chars)

def solve():
    n, m = map(int, input().split())

    arr = []
    for idx in range(1, n + 1):
        s = input().strip()
        arr.append((transform(s), idx))

    arr.sort()

    print(*[idx for _, idx in arr])

if __name__ == "__main__":
    solve()
```前処理フェーズでは、すべてのタイトルの変換された表現が作成されます。 ループはインデックスから始まります`1`Python は 0 から始まるインデックスを使用しており、問題の偶数の位置がインデックスに対応しているためです。`1, 3, 5, ...`。 

The transformation uses the alphabet mirror. 例えば、`A`になる`Z`、`B`になる`Y`、 そして`Z`になる`A`。 

変換後は、カスタム コンパレータは必要ありません。 Python のネイティブ文字列の順序は、すでに目的の順序と一致しています。 最終出力では、保存されている元のインデックスが使用されます。

 ## 特殊なケース

 インプットを考慮する```
2 2
AA
AB
```最初の違いは位置 2 で発生します。そこでのルールは降順であるため、`AB`前に来なければなりません`AA`。 The transformation maps`AA -> AZ`そして`AB -> AY`。 以来`AY < AZ`、通常の並べ替えでは正しい順序が返されます。 

考慮する```
2 3
ABC
AAC
```最初の違いは位置 2 で発生します。元の比較は次のとおりです。`B`対`A`、位置 2 は下降しています。 変換後の文字列は次のようになります`AYC`そして`AZC`。 変換された比較は通常の昇順で行われるようになり、依然として正しい文字列が最初に配置されます。 

考慮する```
2 4
AZAZ
AZAY
```最初の違いは位置 4、つまり下降位置に現れます。 この変換では位置 2 と 4 のみが変更され、最初の異なる文字の位置は維持されます。 すべての偶数位置の比較が一貫して逆転されるため、順序付けは正しいままになります。
