 ## 解決策
 ## 問題の理解

 私たちは、`n × m`グリッド。 すべてのセルには 3 つの方向のうちの 1 つが保存されます。 

の値`1`ボールが 1 つのセルを右に移動することを意味します。 の値`2`ボールが 1 セル下に移動することを意味します。 の値`3`ボールが 1 セル左に移動することを意味します。 

1列目から次々とボールが落ちていきます。 ボールがセルを訪れてそこから離れると、そのセルの値は永続的に次のように変更されます。`2`。 言い換えれば、ボールがセルを使用した後、そのセルに到達する将来のボールはすぐにそこから下に落ちます。 

各ボールについて、ボールがグリッドから出る列を決定する必要があります。 移動は左、右、または下のみであるため、ボールは最終的に下の列を通って出発し、答えはボールが出発する列になります。 

グリッドの寸法は最大でも`1000 × 1000`, したがって、最大 100 万個のセルが存在する可能性があります。 到達できるボールの数`100000`。 

すべてのボールを単純にシミュレーションするにはコストがかかりすぎます。 1 つのボールが多くのセルを訪問する可能性があります。 まであるので、`100000`ボールを使用して、すでに処理された領域を繰り返し歩くと、数億、さらには数十億の操作が生成されます。 

重要な観察は、セルが最初に訪問されたときにのみ特別な動作をするということです。 その瞬間以降、その値は`2`永遠に。 セルが処理されると、今後のボールはすぐにそのセルをスキップできるようになります。 

多くのボールが同じ列からスタートする場合、微妙なケースが発生します。```
1 1 3
1
1 1 1
```最初のボールは右に移動し、セルを次のように変更します。`2`。 2 番目のボールはすぐに下に移動します。 3球目もすぐに下がります。 

常に元のグリッドに従うシミュレーションでは、すべてのボールに対して同一のパスが誤って生成されてしまいます。 

もう 1 つの簡単な間違いは、水平方向の移動が下に移動する前に複数のセルにわたって継続する可能性があることを忘れていることです。```
1 3
1 1 2
1
```ボールは列 1 から列 2 に移動し、次に列 2 から列 3 に移動し、列 3 を通って下に向かって離れます。 

開始セルのみを調べるソリューションでは、列 1 が不正確になります。 

もう 1 つの重要なケースは、セルが既に変換されている場合です。`2`。```
2 2 2
1 1
2 2
1
```最初のセルはすでに下向きになっています。 ボールはすぐに次の列に入るはずです。 セルの処理後に元の水平方向の動作を再適用しようとする試みは間違っています。 

## アプローチ

 ブルートフォースのアイデアはシンプルです。 すべてのボールについて、そのエントリー列から開始して、現在の方向を繰り返したどります。 ボールがセルを離れるたびに、そのセルを次のように変更します。`2`。 

このシミュレーションはルールに正確に従っているため、正確です。 問題はその稼働時間だ。 

セルには、さまざまなボールが何度もアクセスできます。 最悪の場合、ボールが横切る可能性があります`O(nm)`細胞。 まで`10^5`ボールを使用すると、総作業量が膨大になります。 

重要な観察は、各セルが変化するのは最大でも 1 回であることです。 

値が次のセルにボールが来たとします。`1`または`3`。 離れると、セルは次のようになります。`2`。 今後ボールがそのセルに到達すると、すぐに下向きに進みます。 そのセルの高価な水平動作は二度と必要ありません。 

これは、処理されたセルを今後の検索から「削除」されたものとして扱うことを示唆しています。 ボールがすでにセルに到達したとき`2`、すでに処理されたセルの長いチェーンをたどる代わりに、その下の次の未処理のセルに直接ジャンプしたいと考えています。 

これはまさに、Disjoint Set Union 構造で実行できることです。 

すべての列について、行にわたる DSU を維持します。 セルが永続的に処理されるようになったら、そのセルを下の行と結合します。 その後、その後のクエリで、その列内のまだ処理されていない最初の行を即座に見つけることができます。 

各セルは最大 1 回処理され、パス圧縮によりすべての DSU 操作はほぼ一定時間になります。 総仕事量はセルの数とボールの数を加えたものに比例します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合は O(knm) | O(1) グリッドの向こう側 | 遅すぎる |
 | 最適 | O(nm α(n) + k α(n)) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### データ構造

 列ごとに、行全体に DSU を作成します。`1..n+1`。 

行`n+1`番兵とは「グリッドの外」を意味する。 

行の場合`r`列内`c`すでに処理されています、私たちは結合します`r`と`r+1`。 検索操作では、以下の最初の行が返されます。`r`それはまだ現役です。 

### ステップ

 1. グリッドを保管します。 
2. DSUアレイを作成する`parent[row][column]`。 
3. すべてのボールについて、ポジションから開始します`(1, start_column)`。 
4. 現在の行がグリッド内にあるときに、DSU find を使用して、現在の列の最初の未処理の行にジャンプします。 
5. 返された行が`n + 1`、ボールは現在の列を通ってグリッドから離れました。 その列を回答として記録します。 
6. それ以外の場合は、そのセルに保存されている方向を検査します。 
7. セルの行と同じ列内の次の行を結合して、セルを処理済みとしてマークします。 

セルは二度と水平移動を実行しないため、将来のボールはそれをスキップする必要があります。 
8. 値が`1`、右側の列に移動します。 
9. 値が`3`、左側の列に移動します。 
10. 値が`2`、同じ列に留まります。 
11. いずれの場合も、処理対象セルのすぐ下の行から続けます。 

セルが使用されると、セルは永続的に下向き矢印のように動作します。 その場所からの将来の移動はその下から始まります。 
12. ボールがグリッドから出るまで繰り返します。 

### なぜ効果があるのか

 不変条件は、列の DSU が常に、セルがすでに処理されている行を正確にスキップすることです。 

ボールが初めてセルを訪れたとき、セルの元の方向を実行し、そのセルを次の行と結合することで将来の考慮から永久に削除します。 

同じ列と行に後から到達するボールは、DSU を使用してそのセルを飛び越えます。これは、セルがすでに`2`そしてすぐにボールを下に送ります。 

すべてのセルは一度だけ削除され、その後のすべてのアクセスは正しくバイパスされるため、シミュレートされた動作は問題のルールと正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())

    a = [list(map(int, input().split())) for _ in range(n)]
    starts = list(map(int, input().split()))

    parent = [[r for _ in range(m)] for r in range(n + 2)]

    def find(r, c):
        while parent[r][c] != r:
            parent[r][c] = parent[parent[r][c]][c]
            r = parent[r][c]
        return r

    ans = []

    for start_col in starts:
        r = 1
        c = start_col - 1

        while True:
            r = find(r, c)

            if r == n + 1:
                ans.append(str(c + 1))
                break

            direction = a[r - 1][c]

            parent[r][c] = find(r + 1, c)

            if direction == 1:
                c += 1
            elif direction == 3:
                c -= 1

            r += 1

    print(" ".join(ans))

solve()
```グリッドは 0 から始まる列インデックスで保存されますが、DSU 行は 1 から始まるインデックスを使用します。 これは問題のステートメントを反映し、センチネル行を作成します`n + 1`表現しやすい。 

DSU は列ごとに独立して維持されます。`parent[r][c]`列内の次の候補行を教えてくれます`c`。 セルが処理されると、その行をその下にある最初の利用可能な行にリンクしてセルを削除します。 

最もデリケートな部分は更新順序です。 セルを削除する前に、セルの元の方向を読み取る必要があります。 その後、セルは永続的に処理されたとみなされるため、DSU をすぐに更新します。 

行の増分は、方向の実行後に発生します。 ボールは常にセルから出て、次の行に続きます。 水平方向の移動では列が変更されるだけです。
