 ## 解決策
 ## 問題の理解

 グリッドは都市地図を表しており、一部のセルには電柱が含まれています。 各セルは平面上の整数の座標点に対応し、値 1 はその位置に極が存在することを意味します。 グリッド内のすべての座標点について、ユークリッド距離で最も近い極を調べ、その距離を 2 乗します。 タスクは、すべてのグリッド点にわたってこの値を合計することです。 

したがって、概念的には、空のセルまたは塗りつぶされたセルはすべて、最も近い極を見つけるまで「外側に目を向け」、その極までの距離の 2 乗を計算します。 極セルであっても、それらの最も近い極がそれ自体であるため、寄与はゼロになります。 

グリッド サイズは最大 2000 x 2000、つまり最大約 400 万点になります。 極が多数ある場合、またはグリッド全体を繰り返しスキャンする場合、すべての極に対する単純なセルごとの検索は遅すぎます。 各極からの単一ソース BFS ですら、重複する領域にわたって作業を繰り返すことになるため、不可能です。 

あまり目立たない問題は、距離がマンハッタンではなくユークリッドであることです。 これにより、軸が揃ったレイヤーではユークリッド距離が伝播しないため、標準的なマルチソース BFS トリックが削除されます。 

極がまばらな場合、微妙なエッジケースが現れます。 極が 1 つしかない場合、すべてのセルがその 1 点までの二乗距離に寄与するため、答えはグリッド上の二次値の大きな合計になります。 極が密集している場合、多くの地域は崩壊して寄与がゼロになります。 局所性またはグリッド伝播を前提としたソリューションでは、両方の極端な点を正しく処理する必要があります。 

複数の極が等距離にある場合、別の特殊なケースが発生します。 定義には最小距離のみが必要なので、同点は問題ではありませんが、正しく構成されていないダイクストラ スタイルの実装では、誤って二重カウントになったり、一貫性のない緩和が発生したりする可能性があります。 

## アプローチ

 直接的なアプローチでは、セルごとにすべての極までの距離が計算され、最小値がとられます。 これは定義に文字通り従っているため、正しいです。 ただし、最悪の場合、極が O(nm) まである場合、これは O((nm)^2) に縮退し、大きすぎます。 

極の数が少ない場合でも、たとえば k の総当たり力は O(nmk) ですが、それでも最悪の場合約 4e6 × 4e6 に達し、完全に実行不可能です。 

重要な観察は、答えは最も近い極にのみ依存し、ユークリッド距離の二乗には幾何学的解釈があるということです。つまり、各極について、支配的なボロノイ領域が定義されます。 各グリッド点は、正確に 1 つの極の領域、つまり最も近い極の領域に属します。 各領域内で、その極までの距離の二乗を合計する必要があります。 

したがって、問題は、離散グリッド上でユークリッド ボロノイ図を計算し、領域ごとに二乗距離の寄与を累積することに帰着します。 

直接的なボロノイ構築は重いですが、代わりに距離変換を使用してすべてのセルに最も近い極を計算できます。 古典的なトリックは、分離可能な 1D 二乗距離変換を使用して、O(nm) で 2D ユークリッド距離変換を計算することです。 これにより、すべての極にわたる大域的最小化が 2 つのパスに変換されます。最初は行に沿って、次に列に沿って、それぞれが二乗距離関数の候補「放物線」を維持します。 

すべてのセルの二乗距離がわかれば、それを直接合計できます。 残っている唯一の詳細は、極をゼロ ソースとして扱い、マンハッタンやチェビシェフの変形ではなく、正確なユークリッド二乗距離変換を計算する必要があるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | セルごとのブルート フォースとすべての極 | O(nm・nm) | O(nm) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 極がゼロソースで空のセルが無限であるバイナリグリッド上で標準の 2 パスユークリッド距離変換を使用します。

1. 各グリッド セルに極が含まれている場合は 0 に置き換え、それ以外の場合は大きな数を置き換えます。 これは、最も近い極までの距離を最小化問題としてエンコードします。 
2. すべての行に対して独立して、1D 二乗距離変換を計算します。 このステップでは、行内の各セルについて、その行内のすべてのソースの二乗水平距離の最小値と、後で運ばれる最良の垂直寄与を計算します。 重要な考え方は、適切にエンベロープを構築した後、二乗ユークリッド距離が独立した x 成分と y 成分に分離されるということです。 
3. 行を処理した後、各列を独立した 1D 配列として扱い、同じ変換を垂直方向に実行します。 これにより、水平方向と垂直方向の寄与が完全二乗ユークリッド距離に結合されます。 
4. 両方のパスの後、各セルには最も近い極までの二乗距離が含まれます。 グリッド全体のすべての値を合計します。 

微妙な部分は、2 パス分解が有効である理由です。 二乗ユークリッド距離は (dx^2 + dy^2) を満たし、変換は二次関数の下側包絡線を維持することによって機能し、軸に沿って分離可能なままになります。 

### なぜ効果があるのか

 各極は、f(x, y) = (x - xi)^2 + (y - yi)^2 の形式の格子点上の関数を定義します。 これを展開すると、x^2 + y^2 - 2xxi - 2yyi + 定数となります。 x と y の依存関係は、最小化内で線形に分離されます。 距離変換は、各次元でこれらの放物線関数の下側包絡線を維持し、すべての点で完全な二乗距離を最小化する極を選択するようにします。 変換は 1D の二乗距離に対して正確であり、次元間で分離可能であるため、2 つのパスを合成することで 2D グリッド全体で正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def dt_1d(f):
    n = len(f)
    d = [0] * n
    v = [0] * n
    z = [0.0] * (n + 1)

    k = 0
    v[0] = 0
    z[0] = -INF
    z[1] = INF

    def sep(i, j):
        return ((f[j] + j * j) - (f[i] + i * i)) / (2 * (j - i))

    for q in range(1, n):
        p = v[k]
        s = sep(p, q)
        while k > 0 and s <= z[k]:
            k -= 1
            p = v[k]
            s = sep(p, q)
        k += 1
        v[k] = q
        z[k] = s
        z[k + 1] = INF

    k = 0
    for i in range(n):
        while z[k + 1] < i:
            k += 1
        j = v[k]
        d[i] = (i - j) * (i - j) + f[j]
    return d

def main():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n + 1)]

    INF = 10**18

    row_dist = []
    for i in range(n + 1):
        f = []
        for j in range(m + 1):
            f.append(0 if grid[i][j] == '1' else INF)
        row_dist.append(dt_1d(f))

    total = 0
    for j in range(m + 1):
        col = [row_dist[i][j] for i in range(n + 1)]
        col = dt_1d(col)
        total += sum(col)

    print(total)

if __name__ == "__main__":
    main()
```最初のフェーズでは、各位置がその行構造内の最も近い極への水平二乗距離の寄与を知る行ごとの表現を構築します。 2 番目のフェーズでは、同じ変換を垂直方向に適用し、行の結果を完全な 2D 距離に結合します。 

実装の重要な詳細は、非極セルに大きな INF 値を使用することで、その方向に極が存在しない限り非極セルが最小値になることはありません。 行変換と列変換への分離は順序を維持する必要があります。これは、それらを逆にしても機能しますが、中間状態の一貫した解釈が必要となるためです。 

## 実用的な例

 3x3 グリッドの原点に単一の極があるサンプルを考えてみましょう。 

行変換では最初に水平距離が生成されるため、極を含む行は次のようになります。 

(0, 1, 4) x=0 からの距離は 0,1,2 の 2 乗であるため。 

次に、垂直変換によって同じ考え方が列の下に適用され、対称性が強化されます。 

| ステップ | セル (0,0) | (0,1) | (0,2) |
 | --- | --- | --- | --- |
 | 行パス後 | 0 | 1 | 4 |
 | 列通過後 | 0 | 1 | 4 |

 これは、水平構造が維持され、垂直伝播が行内の正確さを妨げないことを示しています。 

ここで、対角にある 2 つの極について考えてみましょう。 行変換により 2 つの競合する放物線が生成され、エンベロープにより、垂直方向のリファインメントによって対角の優位性が解決される前に、各セルが水平方向により近い極を選択することが保証されます。 

これは、中間行の結果が、2 番目のパスで正しくマージされる部分優勢領域を既にエンコードしていることを示しています。

 ## 特殊なケース

 極が 1 つだけ存在する場合、アルゴリズムは 1 つの座標までの二乗距離を計算します。 行変換は正しい水平距離を割り当て、列変換は垂直距離を独立して伝播するため、すべてのセルは最終的に (dx^2 + dy^2) となり、定義と一致します。 

すべてのセルが極の場合、初期配列のすべてのエントリはゼロになります。 すべての最小値はソース セル自体で達成されるため、どちらの変換でもゼロが保持され、最終的な合計はゼロになります。 

極がまばらで遠く離れている場合、影響の各領域は距離変換の凸包絡線構造によって独立して処理されます。 中間行の結果が水平方向の影響を「ぼやけている」ように見える場合でも、2 番目のパスでは垂直方向の寄与を対称的に組み込むことにより、真の 2D 最近極構造が正しく復元されます。
