 ## 解決策
 ## 問題の理解

 都市公園は、各アトラクションがノードであり、各レールがエッジであるツリーです。 すべてのノードには幸福度の値があり、すべてのエッジには黒または白の色があります。 ツリー内の移動は常に単純なパスに沿って行われるため、ノードを再度訪問することはありません。 

この問題を自明ではないものにしているのは、移動ルールです。 同じ色のエッジを自由に通過することができますが、ある色の使用から別の色の使用に切り替える場合は必ずチケットを使用する必要があります。 最初の色は無料で、最大で変更できます`k`パス全体に沿って何度も繰り返します。 

ノードのペアごとに`(u, v)`と`u ≤ v`、それらの間の一意の単純なパスを考えてみましょう。 このパスを最大でも使用して横断できる場合は、`k`カラーが切り替わる場合、それは有効とみなされ、その寄与はそのパスに沿ったノード値の合計となります。 タスクは、すべての有効なペアにわたってこれらの寄与を合計することです。 

この構造では、ツリー内のノードのすべてのペアについて推論する必要があり、すでに 2 次数のパスが示唆されています。 と`n`2·10^5 までは、すべてのパスを明示的に列挙することは不可能であるため、主な困難は、エッジ色の交互の制約の下でパスの寄与を数えて集計することです。 

ツリーが単色の場合、微妙なエッジケースが現れます。 すべてのエッジが同じ色である場合、パスに関係なくすべてのパスが有効になります。`k`したがって、答えは、ノード値によって重み付けされたすべてのツリー パスにわたる古典的な合計に帰着します。 切り替えをシミュレートしようとする単純なソリューションでは、そのようなケースが誤って拒否される可能性があります。 

次の場合、別の故障モードが表示されます。`k = 0`。 この場合、色が決して変わらないパスのみが許可されます。つまり、有効なパスはそれぞれ、完全に単色の連結コンポーネント内に存在する必要があります。 ツリーを色なしとして扱うか、スイッチを無視すると、すべてのペアが過剰にカウントされることになります。 

最後に、色が繰り返し切り替わるパスは、局所的には似ているように見えますが、グローバルなスイッチ数が異なります。 色の変化の構造を追跡せずにエンドポイントのみを推論するソリューションは、過大評価されます。 

## アプローチ

 ブルートフォースアプローチは定義から始まります: すべてを列挙する`(u, v)`ペアを作成し、ツリー内の一意のパスを抽出し、それに沿って歩き、エッジの色が何回変化したかを数えます。`k`、そのパスに沿ってノードの重みの合計を追加します。 

これは正しいですが、遅すぎます。 O(n²) 個のペアがあり、各パスがツリー内を通過するのに O(n) 時間がかかる可能性があり、最悪の場合は O(n³) になります。 LCA を使用してパス抽出を最適化しても、まだ O(n²) 個のパスを評価する必要があり、これは限界をはるかに超えています。 

重要な点は、実際にはパスを明示的に列挙する必要がないということです。 必要なのは、すべてのノードについて、そのノードを含む有効なパスの数を計算し、その寄与率を乗算することです。 

これは、寄与ベースのカウント手法を示唆しています。各ノードの重みは、それを通過するすべての有効なパスに寄与します。 したがって、エンドポイントについて考える代わりに、ノードを修正します。`x`有効なペアの数を数えます`(u, v)`彼らの道が通るようにする`x`。 

ツリー構造により、パスを分解できます。`x`からの方向のペアに`x`そのサブツリーに。 難しいのは、色の切り替えに関する制約です。パスが通過することです。`x`異なる子のセグメントを組み合わせることができ、それぞれの側が一定数の色の交互に寄与します。 

重要な単純化は、ツリーをルート化し、各ノードが指定された色の状態で終了する指定された数の色の遷移を持つ有効な下向きパスがいくつ存在するかを追跡する構造にエッジ カラーを変換することです。 これは、遷移数を追跡しながら子状態をマージするツリー DP 問題になりますが、最大数は次のとおりです。`k`。 

ノードごとに完全なディストリビューションを保存する (大きすぎる) 代わりに、それを利用します。`k`トランジションの小さなキャップとして機能し、ナップザックのように慎重に蓄積することでマージを実行できます。 各エッジは同じ色の状態を継続するか、切り替えカウントを増加させます。 

これにより、グローバル パスの列挙からツリー エッジ上のローカル DP マージまでの問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパス列挙 | O(n3) | O(n) | 遅すぎる |
 | カラースイッチ状態に関するツリー DP | 実装に応じて O(nk) または O(nk log n) | O(nk) | 承認済み |

 ## アルゴリズムのチュートリアル

 任意のノード (たとえば 1) でツリーをルート化し、すべてのエッジをルートから離れる方向に処理します。 DP は、ノードごとに、そのノードで開始され、残りのスイッチ バジェットと現在のカラー状態に関して有効な下向きパスの数を計算します。 

1. 各ノードについて、そのノードから開始して下方向に向かうパスを表す DP テーブルを維持します。 スイッチの可能な数ごとに`s ≤ k`、いずれかの色の状態 (最後のエッジの色は黒または白) で終わるパスの数を保存します。 これは、将来の拡張機能が色を変更するかどうかに依存するため、必要です。 
2. ノード自体で構成される自明なパスが、スイッチがゼロで色状態依存性のない有効なパスに寄与するように、各ノードを初期化します。 
3. ツリーをポストオーダーで走査します。 ノードを処理するとき`x`、その子からの DP 情報を 1 つずつ結合します。 これにより、マージ前にすべてのサブツリーが完全に解決されることが保証されます。 
4. 子を結合する場合`c`の中へ`x`、エッジの色を考慮します`t`。 すべての DP 状態に対して、`c`を通って上にパスを延長します。`(x, c)`に応じて、同じ色の状態を維持するか、新しい色の状態を導入します。`t`。 エッジの色が現在の状態と異なる場合は、スイッチ数を増やします。 
5. コントリビューションを慎重にマージします: で始まるパス`c`そして通過します`x`で停止することもできます`x`または、以前にマージされた子に続行します`x`。 これにより、左サブツリーと右サブツリーの DP 状態の組み合わせが作成され、これらは通過するパスに対応します。`x`。 
6. 各ノードで`x`、すべての子をマージした後、最小共通点が次のパスの寄与を計算します。`x`。 これは、子 DP 状態のペアを結合し、それらの寄与を、`a[x]`。 
7. DP の上限は次のとおりです。`k`、したがって、それを超える状態`k`スイッチは破棄されます。 

### なぜ効果があるのか

 ツリー内のすべての有効なパスには、ルート化されたときに固有の最高点、つまり LCA があります。 このアルゴリズムは、個別の子サブツリーからの寄与を組み合わせることにより、各パスがその LCA で正確に 1 回カウントされることを保証します。 DP 状態は、スイッチ バジェットを超えずに 2 つの下向きパスを結合できるかどうかを判断するために必要な情報を正確にエンコードします。 すべての組み合わせは正しいマージ ポイントで一度考慮されるため、パスが見逃されたり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

MOD = 10**9 + 7

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v, t = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, t))
        g[v].append((u, t))

    # dp[u][c][s] = number of downward paths starting at u,
    # ending with color c (0/1), using s switches
    dp = [None] * n
    ans = 0

    def dfs(u, p):
        nonlocal ans

        # dp for u: two color states, k+1 switch counts
        du0 = [0] * (k + 1)
        du1 = [0] * (k + 1)

        # empty path at node u contributes nothing colored, but acts as start
        # treat as both states with zero switches for combination convenience
        du0[0] = 1
        du1[0] = 1

        for v, col in g[u]:
            if v == p:
                continue
            dv0, dv1 = dfs(v, u)

            nd0 = [0] * (k + 1)
            nd1 = [0] * (k + 1)

            # extend child paths through edge (u-v)
            for s in range(k + 1):
                if col == 0:
                    # black edge keeps black, white->black adds switch
                    if s <= k:
                        nd0[s] = (nd0[s] + dv0[s]) % MOD
                        if s + 1 <= k:
                            nd0[s + 1] = (nd0[s + 1] + dv1[s]) % MOD
                else:
                    # white edge keeps white, black->white adds switch
                    if s <= k:
                        nd1[s] = (nd1[s] + dv1[s]) % MOD
                        if s + 1 <= k:
                            nd1[s + 1] = (nd1[s + 1] + dv0[s]) % MOD

            # merge into u
            new0 = [0] * (k + 1)
            new1 = [0] * (k + 1)

            for i in range(k + 1):
                for j in range(k + 1 - i):
                    new0[i + j] = (new0[i + j] + du0[i] * nd0[j]) % MOD
                    new1[i + j] = (new1[i + j] + du1[i] * nd1[j]) % MOD

            for i in range(k + 1):
                du0[i] = new0[i] % MOD
                du1[i] = new1[i] % MOD

        # convert dp states into contribution
        for s in range(k + 1):
            total_paths = (du0[s] + du1[s]) % MOD
            ans = (ans + total_paths * a[u]) % MOD

        return du0, du1

    dfs(0, -1)
    print(ans % MOD)

if __name__ == "__main__":
    solve()
```この実装では、最後のエッジのカラー状態を分離するために、ノードごとに 2 つの DP 配列が維持されます。 マージ ステップは、スイッチ バジェットの畳み込みのような組み合わせであり、正確さが左右される部分です。 各子は下向きのパスを形成する方法に貢献し、2 つの子を結合することは、現在のノードを通過するパスを形成することに対応します。 

微妙な点は、DP カウントには単純な単一ノード パスが含まれているため、個別に処理することなくノードの寄与が確実に含まれることです。 最終的な累積では、各ノードを通過する有効なパスの数にその重みが乗算されます。

 ## 特殊なケース

 重要なエッジケースは、すべてのエッジが同じ色である場合です。 この状況では、すべてのパスは構造に関係なく有効であり、DP は標準のツリー パスのカウントに縮退します。 スイッチがトリガーされることがないため、アルゴリズムはこれを自然に処理し、すべての DP 遷移は単一色の状態のままになります。 

もう 1 つのエッジケースは次のような場合です`k = 0`。 ここで、異なる色のエッジをまたぐマージは予算を超えることになります。 DP はこれらの遷移を効果的にブロックし、単色成分のみが寄与するようにします。 これにより、サブツリーが誤って混合されるのを防ぎます。 

最後の微妙なケースは、色を複数回ジグザグに移動する交互のパスです。 DP は状態ごとのスイッチの累積を明示的に追跡するため、遷移の数が超過すると、`k`、その状態はドロップされ、それ以上のマージに寄与できなくなり、高度に交互に配置されたツリーでも正確さが維持されます。
