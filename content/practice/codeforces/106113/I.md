 ## 解決策
 ## 問題の理解

 私たちは持っています`N`結晶。 各クリスタルは色の名前で識別されるファミリーに属しており、パワー値を持っています。 

正確に選択する必要があります`K`ただし、選択した 2 つの結晶が同じファミリーに由来することはできないという制限があります。 目的は、それらの力の合計を最大化することです。 

人数が少なくて無理な場合は`K`異なる家族を印刷します`IMPOSIBLE`。 

いくつかの選択が同じ最大合計パワーを達成する場合、結晶インデックスのソートされたリストが辞書編集的に最小のものを出力する必要があります。 

入力サイズが主な課題です。 まであります`10^6`クリスタル、ファミリー名は長い文字列になる場合があります。 結晶のすべてのペアを比較したり、大規模なコレクションを繰り返しソートしたりするソリューションは、非常に遅すぎます。 アルゴリズムは基本的に各クリスタルを 1 回処理し、ファミリーごとに集約された情報のみを保持する必要があります。 

微妙な詳細は、辞書編集上のタイブレークです。 パワーを最大化するだけでは十分ではありません。 2 つの異なる最適な選択の総検出力が同じになる可能性があるため、辞書編集的に並べ替えられた最小のシーケンスを生成するインデックスを慎重に選択する必要があります。 

次の例を考えてみましょう。```
4 1
RED 10
RED 10
BLUE 10
GREEN 5
```最大パワーは`10`。 

考えられる最適な答えはインデックスの選択です`1`、`2`、 または`3`。 

正しい出力はインデックスです`1`、 なぜなら`[1]`辞書編集的には以下より小さい`[2]`または`[3]`。 

もう 1 つの重要なケースは、複数のファミリーが同じ最高のパワーを持ち、最後の利用可能なスロットをめぐって競合する場合に発生します。```
5 2
A 10
B 10
C 10
D 5
E 1
```のいずれか 2 つ`A`、`B`、 そして`C`同じ最大値を与える`20`。 

正解はインデックスを使用します`[1, 2]`、 ない`[1, 3]`または`[2, 3]`、 なぜなら`[1, 2]`は辞書編集上最小です。 

最後のエッジケースは、同じ最大出力を持つ複数のクリスタルがファミリーに含まれている場合です。```
4 2
RED 7
RED 7
BLUE 5
GREEN 1
```家族向け`RED`、両方の指数`1`そして`2`同じ貢献を達成します。 インデックスの選択`1`辞書編集的には常にインデックスを選択するのと同じくらい優れています`2`。 

## アプローチ

 ブルートフォースソリューションでは、次のすべてのサブセットが試行されます。`K`クリスタルを使用して、すべてのファミリーが異なるかどうかを確認し、合計パワーを計算して、最適な有効な選択を維持します。 たとえ`N = 50`、サブセットの数が指数関数的に増加するため、これはすでに絶望的です。 と`N = 10^6`、そのようなアプローチは完全に不可能です。 

最初の観察は、どのファミリーでも、その最も強い結晶だけが最適なソリューションに現れる可能性があるということです。 家族に権力がある場合`3`、`8`、 そして`12`、パワーのあるクリスタル以外のものを選択します`12`総電力を減らすことしかできません。 

これにより、すべてのファミリーを 1 つの値に圧縮できます。`V = maximum power in that family`。 

複雑な問題がまだ 1 つあります。 ファミリには、次のようなパワーを持つ複数のクリスタルが含まれる場合があります。`V`。 それらはすべて同じ量を寄与するため、それらの中で最小のインデックスを維持する必要があります。 インデックスが大きくなると、最終的な答えが辞書編集的に悪くなるだけです。 

この圧縮の後、すべてのファミリは次のようになります。```
(best_power, best_index)
```ここで、問題は次のように変わります。 

正確に選択してください`K`家族。 

選ばれた各家族が貢献します`best_power`。 

すべての最大検出力の選択の中で、選択されたインデックスの辞書順に最小のソートされたリストを返します。 

パワーを最大化するには、次のようにします。`K`家族の最大の権力。 

唯一のあいまいさは、複数のファミリーが遮断電力を共有する場合に発生します。 

仮定する：```
powers = [15, 12, 12, 12, 8]
K = 3
```力のある家族`15`を選択する必要があります。 

力のある家族`8`決して選択することはできません。 

権力のある御三家のうち`12`、さらに 2 つの選択肢が必要です。 

これらすべてのファミリーはまったく同じ検出力を提供するため、辞書編集規則が決定要因になります。 代表インデックスが最小であるファミリーを選択する必要があります。 

これにより、明確な戦略が得られます。 

1. 各ファミリーの最大電力とそれを達成する最小の指数を計算します。 
2. 家族を権力順に並べ替えます。 
3. 遮断電力を決定します。 
4. カットオフを厳密に上回るすべてのファミリーを選択します。 
5. カットオフに等しいファミリーの中から、より小さい代表インデックスを優先して、必要な数だけ選択します。 
6. 結果のインデックスを並べ替えて出力します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 | O(N + F log F) | O(F) | 承認済み |

 ここ`F`は個別のファミリーの数です。 

## アルゴリズムのチュートリアル

 1. すべてのクリスタルを読み取り、ファミリー名ごとにグループ化します。 
2. ファミリごとに、次の 2 つの値を維持します。 

- これまでに見られた最大のパワー。 
- 検出力が最大値と等しい最小のインデックス。 
3. すべてのクリスタルを処理したら、`F`は個別の家族の数になります。 
4. もし`F < K`、印刷`IMPOSIBLE`各ファミリーから 1 つのクリスタルを選択しても、まだ十分なクリスタルが提供されないためです。 
5. すべての家族をペアに変換します`(power, index)`どこ：

-`power`家族の最大パワーです。 
-`index`はその検出力を実現する最小の指数です。 
6. これらのペアを検出力の降順に並べ替えます。 
7. しましょう`T`の力になってください`K`この順序の - 番目のファミリー。 これが遮断電力です。 
8. 力が次より大きい家族をすべて選択します。`T`。 それらのいずれかを置き換えると総電力が減少するため、これらを含めることは必須です。 
9. さらに何つのファミリがまだ必要であるかを数えます。 
10. 力が等しいすべての家族を集めます`T`。 
11. これらのしきい値ファミリーを代表的なインデックスでソートし、必要な数を正確に取得します。 
12. 選択したすべてのインデックスを収集し、徐々に並べ替えて、合計検出力とともに出力します。 

### なぜ効果があるのか

 すべての家族が独立して総電力に貢献します。 選択したクリスタルを同じファミリーの別のクリスタルに置き換えても、ファミリーの最大パワーを超える合計を改善することはできないため、すべての最適なソリューションでは、選択した各ファミリーの最大パワーのクリスタルを使用する必要があります。 

各ファミリーを達成可能な最大の貢献まで削減した後、総電力を最大化することは、`K`家族の最大の権力。 厳密にカットオフを超えるファミリはすべての最適解に属する必要がありますが、厳密にカットオフを下回るファミリは最適解に属することはできません。 

唯一の自由は、まさに電力が遮断された瞬間に家族から得られるものです。 このような家族はすべて同じ金額を寄付するため、どの家族が選ばれたとしても、合計の力は変わりません。 辞書編集的に最小のソートされたインデックス リストを取得するには、それらの結合されたファミリーの中から最小の代表的なインデックスを選択します。 それ以外の選択をすると、小さいインデックスが大きいインデックスに置き換えられ、並べ替えられたシーケンスが辞書編集的に大きくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    families = {}

    for idx in range(1, n + 1):
        color, power = input().split()
        power = int(power)

        if color not in families:
            families[color] = [power, idx]
        else:
            best_power, best_idx = families[color]

            if power > best_power:
                families[color] = [power, idx]
            elif power == best_power and idx < best_idx:
                families[color][1] = idx

    if len(families) < k:
        print("IMPOSIBLE")
        return

    items = [(p, idx) for p, idx in families.values()]
    items.sort(key=lambda x: -x[0])

    threshold = items[k - 1][0]

    chosen_indices = []
    total_power = 0

    equal_group = []

    for power, idx in items:
        if power > threshold:
            chosen_indices.append(idx)
            total_power += power
        elif power == threshold:
            equal_group.append((idx, power))

    need = k - len(chosen_indices)

    equal_group.sort()

    for idx, power in equal_group[:need]:
        chosen_indices.append(idx)
        total_power += power

    chosen_indices.sort()

    print(total_power)
    print(*chosen_indices)

solve()
```辞書には各家族にとって最高のクリスタルだけが保管されています。 より大きな権力が見つかった場合、家族の記録は置き換えられます。 同じ最大パワーが再び現れた場合、小さい方のインデックスが維持されます。 

すべてのファミリーが圧縮された後は、アルゴリズムが元のクリスタルを再度必要とすることはありません。 ソートされたファミリー リストによってカットオフ電力が決まります。 カットオフを超えるファミリーは、すべての最適解の固定メンバーですが、結合されたファミリーは個別に処理されます。 

タイブレーク ルールは、ファミリー名や累乗ではなく、選択したインデックスの最終的な辞書編集順序に依存するため、しきい値グループはインデックスによって並べ替えられます。 

Python の整数は総電力を安全に処理します。これは、可能な最大合計が次のとおりであるためです。`10^6 × 10^9 = 10^15`、Python の任意精度の整数の範囲内に十分収まります。

import sys
import io

def run(inp: str) -> str:
    data = io.StringIO(inp)
    input = data.readline

    n, k = map(int, input().split())

    families = {}

    for idx in range(1, n + 1):
        color, power = input().split()
        power = int(power)

        if color not in families:
            families[color] = [power, idx]
        else:
            bp, bi = families[color]
            if power > bp:
                families[color] = [power, idx]
            elif power == bp and idx < bi:
                families[color][1] = idx

    out = []

    if len(families) < k:
        out.append("IMPOSIBLE")
        return "\n".join(out)

    items = [(p, idx) for p, idx in families.values()]
    items.sort(key=lambda x: -x[0])

    threshold = items[k - 1][0]

    chosen = []
    total = 0
    eq = []

        if p > threshold:
            chosen.append(idx)
            total += p

    eq.sort()

    for idx, p in eq[:need]:
        chosen.append(idx)
        total += p

    chosen.sort()

    out.append(str(total))
    out.append(" ".join(map(str, chosen)))
    return "\n".join(out)
