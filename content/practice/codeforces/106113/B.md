 ## 解決策
 ## 問題の理解

 ボブは都市のネットワークを通じてメッセージを広めたいと考えています。 都市は無向グラフの頂点であり、エッジは隣接する 2 つの都市間を 1 週間で情報が移動できることを意味します。 

ボブはすべての都市を訪れる必要はありません。 彼に可能な訪問命令は 2 つだけです。 最初の順序では、インデックスが小さいものから大きいものまで、奇数のインデックスを持つ都市を訪問します。 2 番目の順序では、指数が小さいものから大きいものまで均等な指数を持つ都市を訪問します。 週に訪れた都市`k`その週に情報を広めるための追加の出発点になります。 毎週、情報を知った有権者が近隣住民にメッセージを伝えます。 

タスクは、2 つの戦略のうち良い方を選択し、すべての都市がメッセージを理解するまでに必要な週数を出力することです。 どちらの戦略も最終的にすべての都市に到達できない場合、答えは次のとおりです。`-1`。 

重要な観察は、後で訪れた都市が依然として役立つ可能性があるということです。 たとえば、数週間後に切断されたコンポーネントにアクセスすると、以前の訪問ではそのコンポーネントに到達できなかったとしても、そこからメッセージが開始されるようになります。 

グラフには最大で次のものを含めることができます`100000`したがって、毎週シミュレーションして繰り返しメッセージを広めるアプローチはコストがかかりすぎます。 このサイズでは、ほぼ直線または`O((n+m) log n)`仕事。 グラフの走査を 1 回または 2 回実行することは許容されますが、訪問のたびに別の走査を実行することは許可されません。 

実装を簡単に破壊してしまう特殊なケースがいくつかあります。 都市が 1 つだけある場合、答えは次のようになります。`1`ボブは一度そこを訪れる必要があるからです。```
Input:
1 0
```正しい出力は次のとおりです。```
1
```既存のエッジからのみ BFS を開始するか、少なくとも 1 つのネイバーが失敗すると想定するソリューション。 

もう 1 つのケースは、ある戦略が切断されたコンポーネントを決して訪問しない場合です。 例えば：```
Input:
4 1
1 2
```奇妙な都市の訪問のみを使用する`1`そして`3`、それで都市`3`そして`4`それらの訪問から到達した場合にのみカバーできます。 市`4`孤立していてメッセージを受信しません。 同じ問題が偶数戦略でも発生する可能性があります。 答えは`-1`どちらの戦略もすべての都市をカバーしていない場合。 

最後の微妙なケースは、訪問時間が重要であるということです。 週に訪れた都市`3`1週間前に情報を広めることはできません`3`。 訪問したすべての都市をその週に利用可能であるかのように扱う`1`間違った結果が得られます。 

## アプローチ

 直接的な解決策は、キャンペーンを週ごとにシミュレーションすることです。 選択された 1 つの戦略については、ボブが毎週どの都市を訪れるかがわかります。 訪問するたびに、現在情報が提供されているすべての都市から BFS を実行し、グラフ全体がカバーされているかどうかを確認できます。 これは、ステートメントで説明されているとおりのプロセスに従っているため、正しいです。 

問題は、同じエッジが何度も探索されることになるということです。 最悪の場合、ボブは約`n/2`都市とBFSのコスト`O(n+m)`。 総作業量はおおよそになります`O(n(n+m))`、それは可能性をはるかに超えています`n = 100000`。 

重要な観察は、プロセス全体が開始点が遅れた最短パスとして見なせるということです。 

ボブが街を訪れたら`u`週に`t`、その後、その都市は別の都市に通知することができます`v`で：```
t + shortest_distance(u, v)
```数週間。 

固定戦略の場合、訪問する都市ごとに開始時間が異なるソースになります。 すべてのソースの最小到着時間が必要です。 これはまさに、すべてのエッジに重みがある最短経路問題です。`1`ただし、各ソースは独自の初期距離から始まります。 この問題は、優先キューを使用したマルチソース BFS スタイルのトラバーサルで解決できます。 

奇数の都市の場合は、city`i`週に訪問されます`(i+1)/2`。 偶数都市の場合、都市`i`週に訪問されます`i/2`。 選択した戦略とその訪問週からのすべての都市で優先キューを初期化し、可能な限り最も早い到着時間を伝播します。 

同じアルゴリズムが両方の戦略を処理します。 2 回実行して、小さい方の有効な答えを採用するだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n(n+m)) | O(n+m) | 遅すぎる |
 | 最適 | O((n+m) log n) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 都市グラフの隣接リストを作成します。 情報はどちらの方向にも伝わる可能性があるため、各エッジは両方向に保存されます。 
2. 奇数都市戦略の問題を 1 回解決します。 奇数番号の都市をすべて、訪問週を最初の到着時刻として優先キューに入れます。 
3. 最短パスのトラバースを実行します。 到着時刻のある都市のたびに`t`キューから削除されました。各近隣の時間を改善してみてください`t+1`。 これにより時間が短縮される場合は、ネイバーを更新してキューにプッシュします。 
4. 横断が終了したら、すべての都市の中で最大の到着時間を見つけます。 一部の都市の到着時間が依然として無限である場合、この戦略ではグラフ全体に情報を与えることができません。 
5. 均等都市戦略についても同じプロセスを繰り返します。 唯一の違いは、各ソース都市に割り当てられる最初の週です。 
6. 2 つの戦略から小さい方の有効な結果を返します。 両方の戦略が失敗した場合は、戻ります`-1`。 

なぜ効果があるのか:

 固定戦略の場合、訪問するすべての都市がメッセージの開始点となる可能性があります。 優先キュー アルゴリズムは、各都市に情報が得られる既知の最小週を常に保持します。 すべてのエッジに正確に 1 週​​間が追加されるため、緩和ステップではすべてのソースからのすべての可能なパスが考慮されます。 各都市の最終値は、訪問可能なすべての都市の最小値です。```
visit_week + graph_distance
```ちょうど今週が市がメッセージを受け取ることができる最も早い週です。 これらの値の最大値を取得すると、最後の都市に通知が届く週が求められます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve_strategy(n, graph, start_parity):
    inf = 10**18
    dist = [inf] * (n + 1)
    pq = []

    for city in range(1, n + 1):
        if city % 2 == start_parity:
            week = (city + 1) // 2 if city % 2 == 1 else city // 2
            dist[city] = week
            heapq.heappush(pq, (week, city))

    while pq:
        time, u = heapq.heappop(pq)

        if time != dist[u]:
            continue

        for v in graph[u]:
            if dist[v] > time + 1:
                dist[v] = time + 1
                heapq.heappush(pq, (dist[v], v))

    ans = max(dist[1:])
    if ans == inf:
        return -1
    return ans

def main():
    n, m = map(int, input().split())

    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        graph[u].append(v)
        graph[v].append(u)

    odd = solve_strategy(n, graph, 1)
    even = solve_strategy(n, graph, 0)

    if odd == -1:
        print(even)
    elif even == -1:
        print(odd)
    else:
        print(min(odd, even))

if __name__ == "__main__":
    main()
```機能`solve_strategy`グラフアルゴリズム全体が含まれています。 その`start_parity`議論により、ボブがどの都市を訪れるかが決まります。 各ソースの開始時間が異なるため、初期距離配列は通常の BFS 初期化ではありません。 週に訪れた都市`k`距離から始まる`k`、 ない`0`。 

初期値が異なるため、通常のキューの代わりにプライオリティキューが使用されます。 通常の BFS はすべてのソースが同時に開始される場合に機能しますが、ここでは 1 週間に訪問する都市を指定します。`1`週に訪問する前に必ず処理する必要がある`20`両方が拡張を待っている場合。 

古いエントリ チェック:```
if time != dist[u]:
    continue
```より良いパスを見つけた後、都市をキューに何度も挿入できるため、これが必要です。 最新の最短値のみを展開する必要があります。 

最終的な最大到着時間は 1 つの戦略の答えです。 それが無限のままである場合、一部の都市は、その戦略で訪問した都市によって到達できなくなります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n+m) log n) | 各都市とエッジは、2 つの戦略それぞれの優先キュー トラバーサルを通じて処理されます。 |
 | スペース | O(n+m) | 隣接リストにはグラフが保存され、配列には到着時間が保存されます。 |

 グラフは 2 回しか走査されないため、制約によりこの複雑さが許容されます。 このアルゴリズムにより、ボブが訪問するたびに BFS が繰り返されることが回避されます。 

## テストケース```python
import sys
import io
import heapq

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def solve_strategy(n, graph, parity):
        inf = 10**18
        dist = [inf] * (n + 1)
        pq = []

        for i in range(1, n + 1):
            if i % 2 == parity:
                t = (i + 1) // 2 if i % 2 else i // 2
                dist[i] = t
                heapq.heappush(pq, (t, i))

        while pq:
            t, u = heapq.heappop(pq)
            if t != dist[u]:
                continue
            for v in graph[u]:
                if dist[v] > t + 1:
                    dist[v] = t + 1
                    heapq.heappush(pq, (t + 1, v))

        return -1 if max(dist[1:]) == inf else max(dist[1:])

    n, m = map(int, input().split())
    graph = [[] for _ in range(n + 1)]

    for _ in range(m):
        u, v = map(int, input().split())
        graph[u].append(v)
        graph[v].append(u)

    a = solve_strategy(n, graph, 1)
    b = solve_strategy(n, graph, 0)

    if a == -1:
        ans = b
    elif b == -1:
        ans = a
    else:
        ans = min(a, b)

    sys.stdin = old_stdin
    return str(ans) + "\n"
