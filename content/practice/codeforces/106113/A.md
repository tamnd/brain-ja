 ## 解決策
 ## 問題の理解

 人型ロボットは座標から開始します`(0, 0)`2D 平面上で一連の動きを実行します。 

コマンド文字列内の各文字は 1 つの動きを表します。`F`ロボットを上に移動させて増加させます`y`1までに。`B`ロボットを下に移動させ、減少させます`y`1までに。`L`ロボットを左に動かし、減少させます`x`1までに。`R`ロボットを右に動かし、増加させます`x`1までに。 

すべてのコマンドを処理した後は、最終的な水平位置のみを考慮します。 決勝なら`x`座標が負の場合、印刷します`"Izquierda"`。 プラスの場合は印刷します`"Derecha"`。 正確にゼロの場合は、次のように出力します。`"Linea Recta"`。 

入力サイズが小さいです。 手数は最大でも 1000 なので、単純なシミュレーションでも十分な速度です。 文字列を 1 回通過すると、最悪の場合でも 1000 回の操作しか実行されません。 

間違いの主な原因は、間違った座標に注意を払うことです。 縦移動のみ変化`y`、ただし出力はのみに依存します`x`。 

次の入力を考えてみましょう。```
5
FFFFF
```ロボットは次で終了します`(0, 5)`。 正しい出力は次のとおりです。```
Linea Recta
```両方の座標を使用して最終位置を分類しようとする不注意な解決策は、ロボットがどこかに移動したため、直線上にあるとみなすべきではないと誤って結論付ける可能性があります。 

もう 1 つの簡単な間違いは、左右の動きが互いに打ち消し合う可能性があることを忘れていることです。```
4
LRLR
```最終的な水平位置は、`0`、したがって、答えは次のようになります。```
Linea Recta
```単に`L`または`R`文字列に「」が含まれていると、間違った結果が得られます。 

3 番目のエッジ ケースは、水平移動がまったくない場合に発生します。```
3
FBF
```ロボットは次の時刻に終了します`x = 0`、垂直変位に関係なく。 答えはまだ残っています:```
Linea Recta
```## アプローチ

 最も直接的な解決策は、説明どおりにロボットを正確にシミュレートすることです。 から始める`x = 0`そして`y = 0`、すべての文字を処理し、移動ルールに従って座標を更新します。 すべてのコマンドが処理された後、次の最終値を検査します。`x`対応する単語を出力します。 

コマンドは最大 1000 個あるため、このシミュレーションでは 1000 個の更新のみが実行されます。 それは事実上瞬時に行われます。 

さらに簡潔な観察は、最終的な答えは、次の数の差のみに依存するということです。`R`コマンドとその数`L`コマンド。 垂直方向の動きは決定に影響を与えません。 両方の座標を維持する代わりに、左右の動きを直接カウントすることもできます。 

どちらの観点からも、同じ線形時間の解決策が得られます。 シミュレーション バージョンは問題ステートメントを正確に反映しており、検証が簡単です。

 ## アルゴリズムのチュートリアル

 1.読む`N`、コマンドの数。 
2. コマンド文字列を読み取ります。 
3.初期化`x = 0`。 
4. 文字列内の各文字を処理します。 

そのキャラクターが`L`、デクリメント`x`。 

そのキャラクターが`R`、増分`x`。 

キャラクター`F`そして`B`水平位置には影響しないため、無視できます。 
5. 文字列全体を処理した後、検査します。`x`。 
6. もし`x < 0`、印刷`"Izquierda"`。 
7. もし`x > 0`、印刷`"Derecha"`。 
8. それ以外の場合は印刷します`"Linea Recta"`。 

### なぜ効果があるのか

 水平座標は 0 から始まります。 毎`L`それを 1 ずつ減らします。`R`それを1つ増やします。 他のコマンドの変更はありません`x`。 すべてのコマンドが処理された後の最終値は、`x`は正確に原点からのロボットの水平変位です。 このステートメントは、この値の符号のみから出力を定義するため、`x`負、正、またはゼロの場合、必要な答えが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
s = input().strip()

x = 0

for c in s:
    if c == 'L':
        x -= 1
    elif c == 'R':
        x += 1

if x < 0:
    print("Izquierda")
elif x > 0:
    print("Derecha")
else:
    print("Linea Recta")
```垂直座標は出力に影響を与えないため、実装では水平座標のみが保持されます。 

ループ内のみ`L`そして`R`状態を変更します。 無視する`F`そして`B`変更するだけなので完全に安全です`y`。 

最後の条件は、ステートメントで要求される順序に正確に従います。 まず陰性と陽性のケースをチェックすると、残りの可能性は次のようになります。`x = 0`に対応します。`"Linea Recta"`。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(input())
    s = input().strip()

    x = 0
    for c in s:
        if c == 'L':
            x -= 1
        elif c == 'R':
            x += 1

    if x < 0:
        return "Izquierda\n"
    elif x > 0:
        return "Derecha\n"
    else:
        return "Linea Recta\n"

# provided samples
assert run("5\nFFLRF\n") == "Linea Recta\n", "sample 1"
assert run("4\nFFRR\n") == "Derecha\n", "sample 2"
assert run("8\nFRFRLLBL\n") == "Izquierda\n", "sample 3"

# custom cases
assert run("1\nL\n") == "Izquierda\n", "single left move"
assert run("1\nR\n") == "Derecha\n", "single right move"
assert run("4\nLRLR\n") == "Linea Recta\n", "cancelling moves"
assert run("3\nFBF\n") == "Linea Recta\n", "only vertical moves"

 ## 特殊なケース

 すべての動きが垂直である場合を考えてみましょう。```
3
FBF
```アルゴリズムは次から始まります`x = 0`。 各キャラクターはどちらかです`F`または`B`、 それで`x`決して変わりません。 ループ後は、`x`はゼロのままで、アルゴリズムは次のように出力します。```

```ロボットが左右に動くことはなかったので、これは正しいです。 

ここで、水平方向の移動をキャンセルすることを検討してください。```

```更新内容は次のとおりです。`0 → -1 → 0 → -1 → 0`最終値はゼロなので、出力は次のようになります。```
Linea Recta
```たとえ水平方向の動きが発生したとしても、正味の変位はゼロであり、まさにこの問題で評価が求められているものです。 

最後に、強い負の変位を考えてみましょう。```
5
LLLLF
```水平座標は次のように展開されます。`0 → -1 → -2 → -3 → -4`決勝戦`F`変わらない`x`。 以来`x = -4`、アルゴリズムは次のように出力します。```
Izquierda
```これにより、水平移動後の垂直移動によって分類が変更されないことが確認されます。
