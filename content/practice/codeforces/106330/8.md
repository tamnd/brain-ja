 ## 解決策
 ## 問題の理解

 この問題では、フェニックスが偶数のコインを持っていることが説明されています。 コインの重さは 2 のべき乗であり、$2^1$まで$2^n$。 すべてのコインを同じ枚数の 2 つのグループに分割する必要があります。目標は、2 つのグループの合計重量の差をできるだけ小さくすることです。 

入力には、いくつかの独立したケースが含まれています。 それぞれの場合の値は、$n$コインが何枚存在するかを教えてくれます。 出力は、2 つのグループの合計間の絶対差の最小値です。 

制約は十分に小さいため、目的のソリューションには高度なデータ構造は必要ありません。 可能な限り最大の$n$は 30 で、テスト ケースの数は最大 100 です。これは、テスト ケースごとに少量の作業を実行するソリューションは十分に高速であることを意味します。 ただし、選択するすべての方法を徹底的に検索すると、$n/2$可能なパーティションの数は指数関数的に増加するため、コインは依然として無駄になります。 のために$n=30$、選択肢の数はおおよそ次のとおりです。$\binom{30}{15}$、何億もの可能性があります。 

主な課題は、2 の累乗がどのように動作するかを認識することです。 最大の重みがすべての小さな重みを組み合わせたものよりも優先されるため、ランダムに見えるパーティションは役に立ちません。 配置では最大のコインを慎重に配置する必要があります。 

よくある間違いは、コインの最大の半分を一方のグループに入れ、最小の半分をもう一方のグループに入れようとすることです。 たとえば、次のようなとき$n=4$、重みは$2,4,8,16$。 その分割によりグループが得られます$16+8$そして$2+4$、18 の差が生じます。最適な分割は次のとおりであるため、正解は 6 です。$16+2$そして$8+4$。 最大のコインを他の大きなコインと単純にグループ化すべきではありません。 

次の場合には、別のエッジケースが発生します。$n=2$。 唯一考えられる分割は、$2$そして$4$したがって、答えは 2 です。 2 つのグループが完全にバランスできると仮定した場合、より大きなケースの公式に基づく解では、誤ってゼロが生成される可能性があります。 

## アプローチ

 強引なアイデアは、考えられるすべての選択を試すことです。$n/2$最初の山のコイン。 選択ごとに、その重みを計算し、合計の重みから減算し、最小の差を更新します。 すべての有効な分割が考慮されるため、これは正しいです。 問題は、可能性の数が多すぎることです。 と$n=30$、すべての選択肢を試してみることは、周りを確認することを意味します$\binom{30}{15}$これは、各ケース内で演算を行う前でさえ、約 1 億 5,500 万のケースに相当します。 

重要な観察は、2 のべき乗の構造から得られます。 一番大きなコインは、$2^n$、多くの小さなコインの合計よりもはるかに大きくなります。 山を近くに保つには、最大のコインをいくつかの最小のコインと一緒に配置する必要があります。 残りの大きなコインは他の山を形成する必要があります。 

最適な構造は、最大のコインと最小のコインを一緒に置くことです。$n/2-1$コイン。 もう一方の山には中央が含まれます$n/2$コイン。 これにより、両方の山に同じ数のコインが与えられ、最大の貢献が可能な限り最小の重みによって部分的にキャンセルされるため、差が最小限に抑えられます。 

差は直接計算できます。 最初の山に含める$2^n$そして最小の$n/2-1$権力。 2 番目の山には、中央から次までのパワーが含まれています。$2^{n-1}$。 べき乗を反復しながら合計を維持できるため、実装でグループを明示的に構築する必要はありません。

 ## アルゴリズムのチュートリアル

 1. 最小のコイン重量から始めます。$2$、最大 2 の累乗を生成します。$2^n$。 差は重みの合計に依存するため、実際の値が必要です。 
2. 最大のコインと最小のコインを追加します。$n/2-1$コインを最初の山に置きます。 最大のコインは最大の不均衡を生み出すため、入手可能な最も安価なコインと組み合わせることで、差を減らす最善の機会が得られます。 
3.残りを追加します$n/2$コインを2番目の山に置きます。 両方の山に、必要な数のコインが正確に含まれています。 
4. 2 つの山の合計の差の絶対値を計算し、出力します。 

機能する理由: 2 つの累乗は急速に増大するため、山間の比較では最大のコインが決定要因となります。 大きなコインを組み合わせると、差はそれらによって支配されます。 最大のコインを補う唯一の方法は、可能な限り最小のコインとペアにすることです。 選択された構造により、最大の杭に最小限の追加重量が与えられるため、他の有効な分割ではこれより小さな差が生じることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())

        total_left = 0
        total_right = 0

        powers = []
        cur = 2
        for _ in range(n):
            powers.append(cur)
            cur *= 2

        for i in range(n // 2 - 1):
            total_left += powers[i]

        total_left += powers[-1]

        for i in range(n // 2 - 1, n - 1):
            total_right += powers[i]

        ans.append(str(abs(total_left - total_right)))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```コードは最初に一連のコイン重量を作成します。 以来$n$が最大 30 である場合、累乗をリストに保存するのは簡単で、累乗を繰り返す必要がありません。 

最初のループは、最適な最初の杭の小さな支持部分を構築します。 インデックス範囲は次で停止します。$n/2-2$、正確に与える$n/2-1$小さなコイン。 その後、最大のコインが個別に追加されます。 

2 番目のループは中央のコインから始まり、最大のコインの前のコインまで続きます。 これで 2 番目の山が形成されます。 境界線は間違いやすいものです。特に$n=2$ここで、最初のループはゼロ回実行する必要があります。 使用する$n//2-1$自然にそのケースに対処します。 

Python の整数は、心配することなく、可能な限り最大の重みをここに格納できます。$2^{30}$はまだ通常の整数制限をはるかに下回っています。

 ## 特殊なケース

 のために$n=2$、入力は次のとおりです。```
1
2
```生成される重みは次のとおりです。$2$そして$4$。 最初の山は最大のコインを受け取り、2 番目の山は残りのコインを受け取ります。 違いは$4-2=2$。 最初の山に常に追加の小さなコインがあると仮定する方法は、何もないため、ここでは失敗します。 

のために$n=4$、入力は次のとおりです。```
1
4
```重みは次のとおりです。$2,4,8,16$。 アルゴリズムは最初の山を次のように作成します。$2+16=18$そして2番目は$4+8=12$。 差は 6 です。すべての大きなコインを一緒にすると、さらに悪い結果が得られます。これは、最大のコインを小さなコインと組み合わせる必要がある理由を示しています。 

より大きなケースの場合:```
1
6
```重みは次のとおりです。$2,4,8,16,32,64$。 最初の山は次のようになります$2+4+64=70$、そして 2 番目の山は次のようになります。$8+16+32=56$。 その差は 14 です。構造は依然として同じ不変条件に従います。つまり、最大の重量を含む杭には可能な限り最小の追加重量が含まれます。
