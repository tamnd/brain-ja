 ## 問題の理解

 このゲームには、フョードル、マトロスキン、シャリクの 3 人の参加者がいます。 それぞれが 3 つの古典的な動きから 1 つを選択します。`rock`、`paper`、 または`scissors`。 プレーヤーは、自分の動きが他の両方のプレーヤーの動きを同時に破った場合にのみ勝ちます。 タスクは、そのようなプレーヤーが存在するかどうかを判断し、その識別子を出力するか、または出力することです。`?`ラウンドに固有の勝者がいない場合。 元のタスクでは通常のルールが使用されます。つまり、じゃんけんははさみに勝ち、はさみは紙に勝ち、紙はじゃんけんに勝ちます。 

入力は 3 つの文字列で構成され、各参加者に 1 つずつ固定順序で割り当てられます。 出力は単一の文字です。`F`、`M`、 または`S`対応する勝者、または`?`誰も勝者と宣言できないとき。 

入力には常に正確に 3 つの手が含まれるため、制約は非常に小さいです。 これは、3 人のプレーヤー間のすべての考えられる関係をチェックするソリューションはすべて一定時間で実行されることを意味します。 高度なデータ構造やアルゴリズムは必要ありません。 主な課題はパフォーマンスではなく、ゲーム ロジックを正しく処理し、2 人のプレーヤーのじゃんけんでは正しいが 3 人のプレーヤーの場合は間違っているという仮定を回避することです。 

最初のトリッキーなケースは、すべてのプレイヤーが同じ手を選択する場合です。 例えば：```
rock

rock
```正しい出力は次のとおりです。```

```すべての比較は引き分けであるため、他の 2 人に勝てるプレイヤーはいません。 不用意な解決策は、繰り返された手を「多数決」としてカウントし、勝者を誤って選択する可能性があります。 

もう 1 つの注意が必要なケースは、2 人のプレイヤーが同じ手を持っていて、3 番目のプレイヤーがそれに負ける手を持っている場合です。```

最後のエッジケースは、3 つの動きがすべて異なる場合です。```
scissors

```正しい出力は次のとおりです。```
?
```それぞれの手が他の手に勝ち、また他の手に負けるため、グループ全体を支配する人はいません。 

## アプローチ

 直接的なアプローチは、定義を文字通りシミュレートすることです。 各プレイヤーについて、自分の手を他の 2 つの手と比較し、両方の比較が勝ちであるかどうかを確認します。 この条件を満たすプレイヤーが 1 人だけいる場合、そのプレイヤーが答えとなります。 これが機能するのは、勝者が他の 2 人の参加者とのペアごとの比較によって完全に定義されるためです。 

ブルート フォース バージョンでは、一定数のケースがチェックされます。 プレーヤーが 3 人の場合、比較はわずか数回しか実行されないため、演算数はすでに最小限になっています。 多くのプレイヤーが参加するより大きなバリエーションでは、他のすべての参加者に対して勝者となる可能性のあるすべてのプレイヤーを試すことはコストが高くなりますが、この問題にはそのような構造はありません。 

重要な観察は、可能な手は 3 つだけであり、勝者は、その手が他の両方の手を打ち負かす唯一のプレイヤーでなければならないということです。 スコアを数えたり、ラウンドをシミュレーションしたりする必要はありません。 認識する必要があるのは、次の 3 つの勝ちパターンだけです。`rock`二人に対して`scissors`、`scissors`二人に対して`paper`、 そして`paper`二人に対して`rock`。 

参加者の数が固定されているため総当り攻撃が機能しますが、パターン チェックを単純化することで不必要な比較が削除され、ロジックの検証が容易になります。

 ## アルゴリズムのチュートリアル

 1. 参加者の順番に 3 つの手を読みます。 出力文字は元のプレーヤーの位置に依存するため、順序を守ることが重要です。 
2. Check each possible winning situation. プレイヤーは、自分が倒した手に対して自分の手が 2 回現れた場合に勝ちます。 例えば、`rock`他の 2 つの動きが両方とも正しい場合に勝ちます。`scissors`。 
3. これらのパターンのいずれかが一致する場合、対応するプレイヤーのレターを印刷します。 2 つの異なる動きで同じ 2 つの動きを両方とも倒すことはできないため、3 つの有効なパターンは重複できません。 
4. 勝ちパターンがどれも一致しない場合は、次のように出力します。`?`。 これは、すべての手に勝者と敗者の両方が存在する引き分けおよび循環ケースをカバーします。 

なぜ効果があるのか:

 正当な勝者は両方の対戦相手を倒さなければなりません。 ジャンケンでは、考えられる 3 つの反対の動きのそれぞれを破る手が 1 つだけあります。 したがって、可能な唯一の勝利構成は、2 つのムーブに対して 1 つのムーブを繰り返すことです。 アルゴリズムはそのようなすべての設定をチェックするため、勝者が存在する場合はそのプレーヤーを見つけます。 一致する構成がない場合、誰も両方の対戦相手を倒すことはできません。これは、結果が正確に不明であることを意味します。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

def solve():
    moves = [input().strip() for _ in range(3)]

    if moves[0] == "rock" and moves[1] == "scissors" and moves[2] == "scissors":
        print("F")
    elif moves[0] == "scissors" and moves[1] == "paper" and moves[2] == "paper":
        print("F")
    elif moves[0] == "paper" and moves[1] == "rock" and moves[2] == "rock":
        print("F")
    elif moves[1] == "rock" and moves[0] == "scissors" and moves[2] == "scissors":
        print("M")
    elif moves[1] == "scissors" and moves[0] == "paper" and moves[2] == "paper":
        print("M")
    elif moves[1] == "paper" and moves[0] == "rock" and moves[2] == "rock":
        print("M")
    elif moves[2] == "rock" and moves[0] == "scissors" and moves[1] == "scissors":
        print("S")
    elif moves[2] == "scissors" and moves[0] == "paper" and moves[1] == "paper":
        print("S")
    elif moves[2] == "paper" and moves[0] == "rock" and moves[1] == "rock":
        print("S")
    else:
        print("?")

if __name__ == "__main__":
    solve()
```プログラムはまず 3 つの入力文字列を配列に格納します。ここで、インデックスは`0`フョードル、索引です`1`はマトロスキン、インデックス`2`シャリックです。 これにより、入力順序と必要な出力文字の間の関係が維持されます。 

条件ブロックは勝利状態を直接エンコードします。 各ブロックは、1 人の参加者が他の 2 人の参加者の同じ手を打ち負かす手を選択することを記述します。 考えられる勝利の配置は 9 つだけであるため、それらを明示的にチェックすることで、コンパクトな問題での間違いを回避できます。 

決勝戦`else`残りのすべての状態を処理します。 これには、すべての引き分け、すべての 3 つの異なる手のケース、およびプレーヤーが両方の対戦相手に勝てないケースが含まれます。
