 ## 解決策
 ## 問題の理解

 最初は「(」と「)」のみを含む括弧の文字列が与えられ、2 種類のクエリをサポートするように求められます。 最初のタイプは、一致した特定のかっこをドットに変更します。 2 番目のタイプは、特定のセグメント内の単純な規則的な括弧シーケンスを形成する連続した部分文字列の数をカウントします。 単純な RBS は、空ではなく、ドットで開始または終了しないものです。 各更新の後、今後のクエリには変更された文字列が反映される必要があります。 重要な課題は、文字列が最大 300,000 文字であり、最大 300,000 のクエリが存在する可能性があることです。 これにより、クエリごとに O(n²) 回の操作が必要となるため、考えられるすべての部分文字列を列挙したり、各部分文字列を個別にチェックしたりするアプローチは除外されます。 

主なエッジケースには、削除クエリ後に部分的に点線になるセグメントが含まれます。 たとえば、文字列が "(()())" で、最も外側のペアを削除した場合、内側の部分文字列は有効な RBS のままですが、外側の部分文字列は単純ではなくなります。 重複するセグメントに影響を与える連続した削除クエリでは、別の微妙な問題が発生します。構造が動的に変化するため、カウントをグローバルに事前計算することはできません。 クエリでは、すでに単純な RBS であるが、以前の削除後に内部ドットが含まれているセグメントを要求することもできます。 これらのドットを無視すると、カウントが不正確になります。 

## アプローチ

 ブルート フォース アプローチでは、タイプ 2 クエリごとに、クエリされたセグメント内のすべての部分文字列が検査されます。 考えられるすべての (i, j) ペアを反復処理して、`s[i..j]`除去プロセスをシミュレートするかバランス配列を計算することにより、単純な RBS を形成します。 これは原理的には正しいですが、クエリごとに O(n²) が必要であり、n と q が 3×10⁵ までの場合、これは法外です。 たとえば、長さ 105 のセグメントに対する 1 つのクエリには、およそ 10¹⁰ のチェックが必要となり、制限時間を大幅に超えます。 

重要な観察は、単純な RBS は括弧のプレフィックスの合計という観点からその構造によって特徴付けられるということです。 括弧のバランスと有効な一致の数を維持すると、単純な RBS 部分文字列の数をセグメント長に対して線形時間で計算できます。 削除クエリが発生した場合、影響を受ける位置のみを更新する必要があります。 セグメント ツリーまたはバイナリ インデックス付きツリーは、間隔にわたるバランスとカウントを効率的に追跡でき、対数時間の更新とクエリを可能にします。 基本的に、この問題はブラケット残高に関するダイナミック レンジ クエリに帰着します。このクエリでは、更新ごとにペアがドットとしてマークされ、各クエリは単純な RBS に対応する有効な範囲をカウントします。 

ブルートフォースアプローチは概念的には単純ですが、実行不可能です。 保存された残高情報を含むセグメント ツリーを使用すると、カウントを効率的に計算し、更新を動的に適用できます。 開き括弧と閉じ括弧の数、完全なペアの数、ドットの接頭辞/接尾辞情報を保存することにより、各クエリと更新を O(log n) 時間で実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n²) | O(n) | 遅すぎる |
 | 残高追跡を備えたセグメント ツリー | クエリ/更新ごとに O(log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列をノードの配列として表します。各ノードには、開き括弧、閉じ括弧、ドットのいずれであるかが格納されます。 各ノードは、補助値 (開き括弧と閉じ括弧の数、およびその間隔内の完全な単純 RBS の数) も維持します。 
2. この配列に対してセグメント ツリーを構築します。 各セグメントには、その中の完全な RBS の総数、左端の不一致の開き括弧の数、および右端の不一致の閉じ括弧の数が格納されます。 2 つのセグメント間のマージ操作では、完全な RBS カウントが結合され、左セグメントの開き括弧と右セグメントの閉じ括弧が一致することによって、一致しないカウントが調整されます。 
3. タイプ 1 クエリ (削除) の場合、2 つの特定の位置をドットに更新します。 これには、セグメント ツリー内の対応するノードをゼロ ブラケットおよびゼロ コンプリート RBS に設定し、ルートへのパスに沿って親ノードを更新して正しいカウントを維持することが含まれます。 
4. タイプ 2 クエリ (カウント) の場合、セグメント ツリーに間隔をクエリします。 結果は、そのセグメント内の完全な単純な RBS の合計数になります。 セグメントは削除前に単純な RBS であることが保証されているため、すべての内部カウントが有効であり、ツリー マージ ロジックによりドットが確実に尊重されます。 
5. セグメント ツリーの高さにより、各更新操作またはクエリ操作には O(log n) 時間がかかります。 これにより、すべてのクエリを効率的に処理できます。 

機能する理由: セグメント ツリーは、削除された括弧 (ドット) を考慮して、各ノードがその間隔内の完全な単純な RBS の数を正確に反映するという不変条件を維持します。 2 つのセグメントをマージする場合、一致しない括弧は正しく伝播され、カウントの一貫性が確保されます。 更新はローカライズされるため、今後のクエリは常に現在の状態で動作します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ['open', 'close', 'total']
    def __init__(self, c):
        if c == '(':
            self.open = 1
            self.close = 0
        elif c == ')':
            self.open = 0
            self.close = 1
        else:
            self.open = 0
            self.close = 0
        self.total = 0

def merge(left, right):
    matched = min(left.open, right.close)
    total = left.total + right.total + matched
    open_br = left.open + right.open - matched
    close_br = left.close + right.close - matched
    res = Node('.')
    res.open = open_br
    res.close = close_br
    res.total = total
    return res

class SegmentTree:
    def __init__(self, s):
        self.n = len(s)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.tree = [Node('.') for _ in range(2*self.size)]
        for i in range(self.n):
            self.tree[self.size+i] = Node(s[i])
        for i in range(self.size-1, 0, -1):
            self.tree[i] = merge(self.tree[2*i], self.tree[2*i+1])
    
    def update(self, pos):
        pos += self.size
        self.tree[pos] = Node('.')
        while pos > 1:
            pos >>= 1
            self.tree[pos] = merge(self.tree[2*pos], self.tree[2*pos+1])
    
    def query(self, l, r):
        l += self.size
        r += self.size
        left_res = Node('.')
        right_res = Node('.')
        while l <= r:
            if l % 2 == 1:
                left_res = merge(left_res, self.tree[l])
                l += 1
            if r % 2 == 0:
                right_res = merge(self.tree[r], right_res)
                r -= 1
            l >>= 1
            r >>= 1
        return merge(left_res, right_res).total

n, q = map(int, input().split())
s = input().strip()
st = SegmentTree(s)

for _ in range(q):
    t, l, r = map(int, input().split())
    l -= 1
    r -= 1
    if t == 1:
        st.update(l)
        st.update(r)
    else:
        print(st.query(l, r))
```この解決策は、各ノードが単一の文字を表す、初期文字列にセグメント ツリーを構築します。 マージ関数は、2 つのセグメントにわたって単純な RBS を形成できる括弧のペアの数をカウントし、一致しない括弧を伝播します。 更新すると括弧がドットに変わり、変更が上方に伝播されます。 クエリは、任意のセグメント内の単純な RBS 部分文字列の総数を効率的に計算します。
