 ## 解決策
 ## 問題の理解

 クモのコレクションが与えられ、それぞれに「脚の構成」を表す番号としきい値がラベル付けされています。$k$。 可能な限り多くのスパイダーを選択して、強力なペアごとの互換性ルールを使用して、ディフェンダーと呼ばれる特別なグループを形成したいと考えています: 値を持つ選択された 2 つのスパイダーに対して$x$そして$y$、それらのビットごとの XOR は少なくとも$k$。 

タスクは、このサブセット内のすべてのペアが次の条件を満たすように、最大​​サイズのインデックスのサブセットを選択することです。$x_i \oplus x_j \ge k$。 サイズが少なくとも 2 の有効なサブセットが存在しない場合は、次の値を返します。$-1$。 

入力サイズが到達しました$3 \cdot 10^5$、これは直ちに除外します$O(n^2)$ペアチェック。 たとえ$O(n \log n)$ソリューションは、すべてのペア間の明示的な比較ではなく、並べ替えまたはビット単位の分割を中心に注意深く構成する必要があります。 

いくつかのエッジの状況が重要です。 もし$k = 0$の場合、XOR は常に非負であるため、制約は自明になり、すべてのスパイダーを選択できます。 もし$k$が大きい場合、たとえば要素間の可能な XOR よりも大きい場合、どのペアも機能せず、答えは次のようになります。$-1$。 別の微妙なケースは、最適なセットが単純に「すべての有効な要素」ではなく、要素が最上位ビットに基づいて分離される構造を構築する必要がある場合に現れます。$k$。 

## アプローチ

 ブルート フォース アプローチでは、スパイダーのすべてのサブセットを試し、すべてのペアごとの XOR 値が少なくとも以下であるかどうかを検証します。$k$。 これはクモの数が指数関数的に増加しており、$n = 40$、各サブセットチェックにコストがかかるため$O(n^2)$そしてそこにあります$2^n$サブセット。 

条件を再構築する必要がある$x \oplus y \ge k$。 重要な観察は、XOR 比較は数値が異なる最上位ビットによって制御されるということです。 二進数で考えると、最初のビットは$x$そして$y$Different は XOR が大きいか小さいかを決定します。 

させて$b$に設定されている最上位ビットになります$k$。 XOR が以下のペア$k$一致する必要があります$k$すべての上位ビットで失敗する$b$特定の方法で。 これは当然、プレフィックス (ビットまで) かどうかに基づいて数値を分割することを示唆しています。$b$）に対応しています。 

これをより構造的に確認する方法は、数値に対してバイナリ トライを構築することです。 各ノードはプレフィックスを表し、トライの初期で分岐する数値は大きな XOR を持つ傾向があります。 制約$x \oplus y \ge k$ノードをグループ化する方法に対する制限になります。グループ内では、次の条件で決定される「禁止された類似性領域」にペアが入ることは許可されません。$k$。 

最適な構築は、バイナリ トライ再帰を使用した貪欲な分割から得られます。 各ビットで、数値を 2 つのグループ (0 と 1) に分けます。 の対応するビットに応じて、$k$、両方のグループを一緒に保持できるか、それとも分離してフィルタリングする必要があるかを決定します。 ビットの場合$k$が 1 の場合、同じ側を混合すると危険になり、1 つのブランチからのみ再帰選択が強制されます。 0 の場合、両方の分岐を結合できる可能性がありますが、クロスペアが有効なままであることを確認する必要があります。これは、上位ビットの XOR 構造によって保証されます。 

最後のアイデアは、各トライ ノードを再帰的に評価し、実行可能な最良のサブツリーを返すことによって最大の有効なセットを計算し、あらゆるレベルで互換性が維持されるようにすることです。

 ## アルゴリズムのチュートリアル

 1. すべての数値のバイナリ トライを構築し、各値を最上位ビット (30 番目) から 0 までビットごとに挿入します。これにより、XOR 関係が構造内でローカルになるように、数値がプレフィックスごとに編成されます。 
2. 再帰関数を定義する`solve(node, bit)`をルートとするサブツリーに含まれるインデックスの最大の有効なセットを計算します。`node`、からのビットを考慮して`bit`下向きに。 
3. リーフ ノードに到達した場合は、単一の要素が常に有効であるため、そこに格納されている単一のインデックスを返します。 
4. 現在のビットが$k$が 1 の場合、単純な方法で両方の子を安全に混合することはできません。 しきい値制約を尊重しながら、有効な内部構造を生成する一方の側を選択する必要があります。 両方の子を独立して評価し、その中でより大きい有効なサブセットを返します。 
5. 現在のビットが$k$が 0 の場合、両方のブランチが共存できる可能性があります。 このビット レベルでは違反が導入されず、互換性はより深いビットのみに依存するため、両方の子からの結果を再帰的に計算し、それらをマージします。 
6. ルートから計算されたインデックスのリストを最終的な答えとして返します。 サイズが 2 未満の場合は、-1 を出力します。 

### なぜ効果があるのか

 トライでは、長いプレフィックスを共有する数値がグループ化され、XOR 比較は完全に最初の異なるビットに依存します。 再帰はこの構造を反映しています。各ビットで、制約が分離を強制するかどうかを決定します (ビット$k$は 1)、またはマージを許可します (ビットは 0)。 これにより、選択された数値のペアは、それらが異なる最上位ビットで検証され、まさに XOR が決定されます。 すべての決定は最初の違反部分を尊重するため、$k$、無効なペアを導入することはできず、サブツリーの組み合わせを通じて最大限の互換性のあるグループ化が探索されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("ch", "idxs")
    def __init__(self):
        self.ch = [-1, -1]
        self.idxs = []

def add(root, x, i):
    v = root
    for b in range(29, -1, -1):
        bit = (x >> b) & 1
        if v.ch[bit] == -1:
            v.ch[bit] = len(trie)
            trie.append(Node())
        v = trie[v.ch[bit]]
    v.idxs.append(i)

def dfs(v, bit):
    node = trie[v]
    if bit < 0:
        return node.idxs[:]

    kbit = (K >> bit) & 1
    left = node.ch[0]
    right = node.ch[1]

    if left == -1 and right == -1:
        return node.idxs[:]

    res = []

    if kbit == 0:
        if left != -1:
            res += dfs(left, bit - 1)
        if right != -1:
            res += dfs(right, bit - 1)
        return res
    else:
        best = []
        if left != -1:
            best = dfs(left, bit - 1)
        if right != -1:
            cand = dfs(right, bit - 1)
            if len(cand) > len(best):
                best = cand
        return best

n, K = map(int, input().split())
a = list(map(int, input().split()))

trie = [Node()]
for i, x in enumerate(a):
    add(trie[0], x, i + 1)

ans = dfs(0, 29)

if len(ans) < 2:
    print(-1)
else:
    print(len(ans))
    print(*ans)
```この実装では、各パスが数値に対応するバイナリ トライを構築します。 各終端ノードには、そこで終わる入力要素のインデックスが格納されます。 次に、DFS は、次のビットを使用して、最上位ビットから下方向に実現可能性を評価します。$K$サブツリーをマージできるか、それとも競争的に選択する必要があるかを決定します。 返されるリストは、そのサブツリーで検出された最大の有効なセットです。 

微妙な点は、次のビットで$K$値が 1 の場合、子をマージしません。マージすると、XOR がそのビットで必要なしきい値を下回る可能性があるペアが作成されるためです。 代わりに、2 つのサブツリーを競合する候補として扱います。 

## 実用的な例

 ### 例 1

 入力:```
6 8
2 8 4 16 10 14
```これらの値に対してトライを構築し、ビット 3 から下方向に評価します (8 = 1000₂ であるため)。 

ビット 3 では、そのビットが設定されているかどうかに応じて、数値がグループに分割されます。 以来$k$このレベルの のビットは 1 であり、両方のブランチをマージすることはできないため、各ブランチを個別に評価します。 

| ステップ | ビット | Kビット | 左のサイズ | 適切なサイズ | 選ばれた |
 | --- | --- | --- | --- | --- | --- |
 | ルート | 3 | 1 | 2 | 3 | 右 |
 | 次へ | 2 | 0 | マージ | マージ | すべて |
 | 次へ | 1 | 0 | マージ | マージ | すべて |
 | 次へ | 0 | 0 | マージ | マージ | すべて |

 最終的には、次のような最大の互換性のあるサブセットに対応するインデックスを選択することになります。`{2, 10, 16}`。 

これは、競合する最上位ビットで構造により分割が強制され、1 つのサブツリーのみが生き残ることを示しています。 

### 例 2

 入力:```
4 0
1 2 3 4
```ここ$k = 0$したがって、すべての XOR は自動的に ≥ 0 になります。トライ トラバーサルでは常にマージ ブランチが使用されます。 

| ステップ | ビット | Kビット | アクション |
 | --- | --- | --- | --- |
 | ルート | 29..0 | 0 | すべてをマージする |

 すべてのインデックスが含まれており、`{1,2,3,4}`。 

これにより、制約が消えるとアルゴリズムが完全な選択に正しく折りたたまれることが確認されます。

 ## 特殊なケース

 いつ$k = 0$の場合、再帰は常にマージ ブランチを取得するため、すべてのリーフが収集され、完全なセットが返されます。 入力用`3 0 / 5 7 9`の場合、DFS は制限分岐をトリガーせず、すべてのインデックスを期待どおりに生成します。 

いつ$k$配列内の可能な XOR を超えています。`2 100 / 1 2`、最上位の異なるビットにあるすべての分岐は、有効なペアを生成できません。 DFS は一貫してノードごとに最大 1 つのサブツリーを選択し、最終的には 1 つの要素だけが生き残り、$-1$サイズの制約があるため。 

すべての数値が同一の場合、XOR は常に 0 になります。 もし$k > 0$、すべてのペアが無効であるため、各サブツリーはシングルトン候補に縮退し、最終的な答えは次の場合を除いて無効になります。$k = 0$。
