 ## 解決策
 ## 問題の理解

 開き括弧と閉じ括弧のみで構成される固定文字列が与えられます。 クエリごとに、構造的な意味で適切に動作することが保証されているこの文字列のセグメントが渡され、そのセグメント内の正確さのより強力な概念に従って「適切」である部分文字列がいくつあるかを数えなければなりません。 

ここでの正しさの概念は、標準的な釣り括弧の定義ではありません。 代わりに、単一のドットまたは連続したドットを繰り返し消去できる場合、文字列は有効であると見なされます。`"()"`何も残らないまでペアリングします。 このバージョンにはドットが存在しないため、有効な部分文字列がネストまたは連結された有効なブラケット ブロックのように動作する構造を効果的に使用していますが、従来のスタック バランスよりも若干寛容な折りたたみルールが適用されます。 

それに加えて、「単純な」有効な部分文字列は追加の境界条件を満たす必要があります。つまり、空ではなく、ドットで開始または終了してはなりません。 このバージョンでは、これらの条件は縮退ケースの除外に変換されますが、重要な構造上の結果は、単純な有効な部分文字列が、より大きなクエリ セグメント内に「自己完結型」である適切な形式のバランスの取れたセグメントに正確に対応することです。 

各クエリは、単純で有効な構造であることがすでに保証されている部分文字列を提供します。 その中の部分部分文字列自体が単純で有効な構造であるものがいくつあるかを数えなければなりません。 

制約は大きく、最大 300,000 文字と 300,000 クエリがあります。 これにより、クエリごとにすべての部分文字列を検査するソリューションは即座に除外されます。 二次関数または偶数関数$O(n \log n)$クエリごとのアプローチは失敗します。 各クエリをほぼ定数または対数的な作業に減らす前処理が必要です。 

微妙なエッジ ケースは、バランスのとれたすべてのセグメントがクエリ内で独立しているわけではないということです。 たとえば、重複する有効な部分文字列は個別にカウントする必要があります。 のような文字列で`"()()"`、 両方`"()"`ブロックとフル`"()()"`は有効であり、最大のブロックのみをカウントする単純なカウント戦略では内部構造を見逃してしまいます。 

もう 1 つの落とし穴は、従来のプレフィックスと合計のバランスで十分であると想定していることです。 バランスは有効な構造を識別するのに役立ちますが、別の有効なセグメント内の有効なサブセグメントの数を直接カウントするわけではありません。 ネストされた有効な間隔の寄与を集計する方法が必要です。 

## アプローチ

 ブルート フォースのアイデアは単純です。クエリ セグメントごとに、すべてのペアを列挙します。$(i, j)$、どうかを確認してください$s[i..j]$は有効なバランスの取れた構造であり、さらに単純さを検証します。 スタックベースのチェックにより検証が行われます$O(n)$、したがって、各クエリは次のようになります$O(n^2)$最悪の場合、文字列の長さとクエリの数の両方が大きい場合、これは実行可能な制限をはるかに超えます。 

重要な観察は、有効な部分文字列が括弧シーケンスの構造分解において一致するペアのように動作するということです。 すべての位置は、正規分解で一意に一致する括弧と組み合わせることができ、ネストされたセグメントのツリー状構造を形成します。 この構造がわかると、すべての有効な部分文字列は、この分解のノード、または連続した有効なブロックを形成する隣接する兄弟ノードの結合に対応します。 

これにより、問題は、指定された間隔内で、「有効なノード」または「有効なノードの連結」がいくつ存在するかをカウントすることになります。 部分文字列ごとの有効性を再計算する代わりに、一致する構造を事前計算し、有効なコンポーネント間をジャンプできる表現を構築します。 

これを実装する標準的な方法は、スタックを使用して一致するブラケットを計算し、各位置が一致するパートナーを認識する配列を構築することです。 これから、プリミティブな有効セグメントの親子構造を導き出します。 この問題は、各クエリ範囲内に完全に含まれるセグメントの数をカウントすることに帰着します。これは、フェンウィック ツリーやセグメント エンドポイントのオフライン スイープなどの範囲カウント手法を使用して処理できます。 

ブルート フォースは妥当性を繰り返し再計算するため失敗しますが、最適解ではすべての有効な部分文字列が構造化された標準間隔のセットに圧縮され、範囲クエリでそれらがカウントされます。

 ## アルゴリズムのチュートリアル

 この問題を、一致する括弧セグメントによって表される有効な間隔をカウントすることに還元することで解決します。 

1. まずスタックを使用して、すべての位置に対応する括弧を計算します。 すべての閉じ括弧は、一致しない最新の開き括弧とペアになります。 これにより関数が得られます`match[i]`。 
2. 一致する配列を使用して、プリミティブの有効なセグメントの構造を構築します。 ペアを見つけるたびに`(l, r)`どこ`r = match[l]`、私たちは治療します`[l, r]`基本有効ブロックとして。 
3. 単純な有効な部分文字列は、これらのプリミティブ ブロックの 1 つであるか、隙間なく完全に位置合わせされた連続ブロックの連結であることがわかります。 
4. 構造を、文字列に沿ったアトミックな有効なセグメントのシーケンスに圧縮します。 各セグメントには開始インデックスと終了インデックスがあり、有効な連結を形成している場合、連続するセグメントをマージできます。 
5. セグメント エンドポイントの配列を作成し、右側のエンドポイントに対してフェンウィック ツリー (またはセグメント ツリー) を使用します。 左の境界が移動するときにセグメントをアクティブ化できるように、左の端点でセグメントを並べ替えます。 
6. お問い合わせの場合`[l, r]`を満たしているセグメントの数を数えます。`l ≤ start`そして`end ≤ r`。 これは標準的な 2D の計数問題です。 
7. セグメントとクエリの両方を左のエンドポイントで並べ替え、右から左にスイープしてフェンウィック ツリーを更新することで、すべてのクエリにオフラインで回答します。 

### なぜ効果があるのか

 すべての単純な有効な部分文字列は、プリミティブの一致ブロックへの 1 つの正規分解に正確に対応します。 スタック マッチングによりペアリングの一意性が保証されるため、有効な部分文字列が欠落したり二重にカウントされたりすることはありません。 この分解で部分文字列を区間に変換することにより、すべてのクエリは区間エンドポイントに対する優勢カウント問題になり、Fenwick 構造が正確に処理します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    n, q = map(int, input().split())
    s = input().strip()

    match = [-1] * n
    stack = []

    for i, c in enumerate(s):
        if c == '(':
            stack.append(i)
        else:
            if stack:
                j = stack.pop()
                match[i] = j
                match[j] = i

    segments = []
    for i in range(n):
        if s[i] == '(' and match[i] != -1:
            l = i
            r = match[i]
            if l < r:
                segments.append((l, r))

    segments.sort()

    queries = []
    for idx in range(q):
        _, l, r = map(int, input().split())
        queries.append((l - 1, r - 1, idx))

    queries.sort(reverse=True)

    bit = Fenwick(n)
    ans = [0] * q

    ptr = len(segments) - 1

    for l, r, qi in queries:
        while ptr >= 0 and segments[ptr][0] >= l:
            bit.add(segments[ptr][1] + 1, 1)
            ptr -= 1

        total = bit.sum(r + 1)
        ans[qi] = total

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```スタック セクションは括弧の正確なペアを構築するため、すべての最大有効なプリミティブ間隔が識別されます。 セグメンテーションのステップでは、アトミックな有効な構造を表すこれらの間隔が抽出されます。 

フェンウィック ツリーには、セグメント エンドポイントの数が保存されます。 クエリを処理するときは、クエリ範囲内で始まるセグメントのみがアクティブであることを確認し、クエリの右側の境界より前で終了するセグメントの数をカウントします。 これにより、完全に含まれる有効なセグメントの数が直接計算されます。 

左エンドポイントによるソートは、より小さい左境界を持つクエリに関連する各セグメントが確実に 1 回挿入されるようにするため、非常に重要です。 

## 実用的な例

 小さな文字列の例をトレースします`s = ")()()("`カウントのメカニズムを説明するために仮想のセグメントを使用します。

 ## 特殊なケース

 キーエッジケースは次のような完全にネストされた構造です。`"(((())))"`。 アルゴリズムは、ネストされたすべてのレイヤーが個別の有効なセグメントとして寄与することを保証する必要があります。 スタックマッチングにより間隔が作成されます`(1,8)`、`(2,7)`、`(3,6)`、`(4,5)`、すべて挿入されます。 全範囲をカバーするクエリでは、4 つのセグメントすべてがカウントされ、ネストされた有効な部分文字列の予想される組み合わせ構造と一致します。 

もう 1 つの重要なケースは括弧を交互に使用することです`"()()()()"`。 ここではネストは存在せず、互いに素なプリミティブ ブロックのみが存在します。 セグメント抽出では 4 つの間隔が得られ、全範囲にわたるクエリでは、有効な部分文字列を形成している個々のブロックとその連結の両方が正しくカウントされます。 

微妙な境界のケースは、単一のプリミティブ ブロックに等しいクエリです。 有効なものだけを挿入するので、`(l,r)`ペアの場合、1 つのブロックに正確に一致するクエリは、正確に 1 つの寄与を返し、有効な部分文字列ではない部分的な重複の過剰カウントを回避します。
