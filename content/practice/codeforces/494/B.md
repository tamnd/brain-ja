 ## 解決策
 ## 問題の理解

 2 つの文字列が与えられています。`s`そして`t`。 タスクは、重複しない 1 つまたは複数の部分文字列を選択できる方法が何通りあるかを数えることです。`s`選択された各部分文字列には次のものが含まれます。`t`その中のどこかに。 部分文字列は互いに素である必要があります`s`、選択の順序は文字列の自然な順序に従います。 答えはモジュロで与えられる必要があります$10^9 + 7$。 

入力できる長さは次のとおりです。$10^5$。 考えられるすべての部分文字列を調べる素朴なアプローチ`s`部分文字列の数が のオーダーであるため、すぐには実行不可能です。$n^2$までの可能性があります$10^{10}$制限時間を大幅に超えた作戦。 これは、おそらく動的プログラミングを使用した、効率的な線形または線形に近いソリューションが必要であることを示します。 

微妙なエッジケースが発生する場合`t`重複して複数回出現します。 たとえば、次の場合`s = "aaa"`そして`t = "aa"`、有効な部分文字列は次のとおりです。`"aa"`位置 1 から開始し、`"aa"`位置 2 から開始し、両方を重複せずに使用する組み合わせ。 不用意に実装すると、重複を見逃したり、重複してカウントしたりする可能性があります。 もう 1 つのエッジケースは次のような場合です`t`より長いです`s`またはまったく表示されません。 このような場合、答えは正しく 0 になるはずです。 

## アプローチ

 ブルートフォース手法では、考えられる重複しない部分文字列をすべて列挙します。`s`、それぞれに以下が含まれているかどうかを確認します。`t`、組み合わせをカウントします。 正式には、開始インデックスごとに`i`、すべての終了インデックスを反復処理します。`j > i`、どうかを確認してください`s[i:j]`含まれています`t`、これらを動的プログラミングと組み合わせて、重複しないようにします。 このアプローチは原理的には機能しますが、部分文字列の数は$\frac{n(n+1)}{2}$、につながる$O(n^3)$各部分文字列がチェックされる場合の操作`t`明示的に。 これは不可能です$n = 10^5$。 

重要な洞察は、すべての部分文字列を明示的にチェックする必要がないということです。 代わりに、すべての開始位置を事前に計算できます。`s`どこ`t`が発生します。 次に、次のように繰り返すことができます`s`また、動的プログラミングを使用して、各位置で終わる部分文字列を選択する方法を数えます。 させて`dp[i]`プレフィックスから有効な部分文字列を選択する方法の数になります。`s[0..i]`。 それぞれのポジションについて、`t`終了したら、以前のソリューションを拡張するか、新しいシーケンスを開始できます。 これにより、次の発生を計算した後の複雑さが線形時間に軽減されます。`t`、それぞれの有効なエンディングが DP に 1 回だけ寄与するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n^2) | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのポジションを事前計算します。`s`どこ`t`が発生します。 これは、KMP などの文字列マッチング アルゴリズムや、単純なスライディング ウィンドウを使用して実行できます。$O(n + m)$時間。 
2. DP 配列を初期化する`dp`長さの`n+1`どこ`dp[i]`インデックスまたはその前で終わる有効な部分文字列を選択する方法の数を表します`i`。 プレフィックス合計配列も維持します`pref`DP 値の合計をすばやく計算します。 
3. 反復処理する`s`左から右へ。 それぞれのポジションで`i`、 もし`t`で終わる`i`、前にプレフィックスから部分文字列を選択するすべての方法を追加します。`i - len(t)`プラス、次のものだけからなる 1 つの新しい部分文字列`t`自体。 これは次のように表現できます`dp[i] = (pref[i - len(t)] + 1) % MOD`。 
4. プレフィックス合計配列を更新します。`pref[i] = (pref[i-1] + dp[i]) % MOD`。 
5. すべてのポジションを処理した後、`pref[n]`重複しない部分文字列を選択する方法の総数が含まれます。`t`。 

機能する理由: 各 DP エントリは、以前の重複しない位置から解を拡張するだけであるため、二重にカウントすることなく、その位置で終わるすべての有効な組み合わせをカウントします。 プレフィックス合計は、これらすべての寄与を効率的に集約します。 すべての発生を考慮するため、`t`エンドポイントとして、すべての有効な構成は 1 回だけカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def main():
    s = input().strip()
    t = input().strip()
    n, m = len(s), len(t)
    
    # Step 1: find all positions where t occurs using a sliding window
    match = [0] * n
    for i in range(n - m + 1):
        if s[i:i+m] == t:
            match[i + m - 1] = 1  # mark the ending position of t

    # Step 2: DP array
    dp = [0] * (n + 1)
    pref = [0] * (n + 1)
    
    for i in range(n):
        if match[i]:
            dp[i+1] = (pref[i - m + 1] + 1) % MOD
        pref[i+1] = (pref[i] + dp[i+1]) % MOD
    
    print(pref[n] % MOD)

if __name__ == "__main__":
    main()
```コードの各セクションはアルゴリズムのステップに直接対応します。 すべての終了位置をマークします`t`部分文字列を繰り返しスキャンすることを避けるため。 DP アレイ`dp`各位置でシーケンスを終了する方法をカウントします。`pref`累積合計を維持して、以前のポジションからの貢献を迅速に計算します。 微妙なポイントは、`i - m + 1`重複を避けるためにプレフィックス合計ルックアップで使用します。 

## 実用的な例

 のために`s = "ababa"`そして`t = "aba"`:

 | 私 | 一致[i] | dp[i+1] | プレフィ[i+1] |
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 |
 | 1 | 0 | 0 | 0 |
 | 2 | 1 | 1 | 1 |
 | 3 | 0 | 0 | 1 |
 | 4 | 1 | 4 | 5 |

 この表は、最初の出現場所が次のとおりであることを示しています。`i=2`1 を寄与し、2 番目の出現は`i=4`以前のすべての組み合わせに 1 を加えた合計 5 つの方法が寄与し、サンプル出力と一致します。 

のために`s = "aaa"`そして`t = "aa"`:

 | 私 | 一致[i] | dp[i+1] | プレフィ[i+1] |
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 |
 | 1 | 1 | 1 | 1 |
 | 2 | 1 | 2 | 3 |

 これにより、アルゴリズムが重複の発生を正しく処理していることが確認されます。

 ## 特殊なケース

 もし`s`の発生はありません`t`、`match`配列はゼロのままなので、`dp`増加することはなく、出力は正しく 0 になります。重複する場合、アルゴリズムは、現在の文字列より前の位置からのみ拡張することによって、重複しない部分文字列がカウントされるようにします。`t`終わります。 のために`s = "aaa"`そして`t = "aa"`、DP 配列は正しくカウントされます。`[aa at 0-1]`、`[aa at 1-2]`、 そして`[aa at 0-1 and 1-2]`個別の有効な構成として。
