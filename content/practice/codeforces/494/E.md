 ## 問題の理解

 私たちは、コンピュータ上で行われる 2 人のプレーヤーの組み合わせゲームの勝者を決定するように求められています。$n \times n$ボード。 ボードは黒と白のセルで構成されます。 最初は、特定の長方形のみが白で、残りは黒です。 プレイヤーは交互に手を動かします。1 つの手は最大でも任意のサイズの正方形を選択することで構成されます$k$右下のセルが白になり、その正方形内のすべてのセルが反転します。 行動できなかったプレイヤーが負けとなります。 ハメドが先に動く。 

入力はボードを効率的にエンコードします。すべてのセルをリストするのではなく、$m$すべての白いセルを定義する長方形。 以来$n$と同じ大きさにすることができます$10^9$そして$m$まで$5 \cdot 10^4$、ボードを明示的に保存するソリューションはメモリ不足になるか、遅すぎる可能性があります。 これは、ボードの圧縮表現を処理し、すべてのセルをシミュレートせずにゲームの状態を計算するアプローチが必要であることを意味します。 

微妙な点は移動ルールにあります。プレイヤーは右下隅が白い正方形を選択し、その正方形を反転する必要があります。 単純なアプローチでは、重なり合う長方形が無視されたり、大きくてまばらなボードを効率的に処理できなかったりする可能性があります。 たとえば、5×5 ボードの (5,5) に白のセルが 1 つだけあり、k=3 の場合、(5,5) で終わるサイズが 3 までの正方形のみが有効です。 右下の条件を忘れると、誤った結果が生成されます。 

もう 1 つのエッジケースは次のような場合です$k > 1$小さな白いクラスターが複数存在します。 これは Sprague-Grundy フレームワークにおける古典的な公平なゲームであるため、独立した手の XOR 値を決定するには、オーバーラップを慎重にカウントする必要があります。 

## アプローチ

 ブルートフォースソリューションでは、明示的に$n \times n$ボードを作成し、すべての白いセルを反復処理し、最大サイズのすべての可能な正方形をシミュレートします。$k$そのセルを右下隅にします。 考えられる各四角形はサブゲームを表し、全体の勝者はこれらの四角形のグランディ数値の XOR を使用して決定されます。 複雑さは法外です。ボードには次のようなものがあります。$10^{18}$すべてのセルを反復処理することは完全に不可能です。 

重要な洞察は、このゲームを **独立したパイル上の Nim** の変形として見ることで得られます。各白セルはゲームの XOR 合計に寄与します。 右下の白いセルを持つ正方形のみが問題であり、正方形の反転は決定論的な操作であるため、セルのスプラーグ グランディ数は座標の法にのみ依存します。$k+1$。 これにより、次の問題が軽減されます。$10^9 \times 10^9$セルは最大でも$(k+1) \times (k+1)$独立した杭。 白セルをその座標モジュロにマッピングすることにより$k+1$パリティをカウントすると、ボードを実体化せずに全体の XOR を効率的に計算できます。

 ## アルゴリズムのチュートリアル

 1. 入力値を読み取る$n$、$m$、 そして$k$。 これらは、ボードのサイズ、長方形の数、および最大許容正方形サイズを定義します。 
2. 辞書 (またはサイズの 2D 配列) を初期化します。$(k+1) \times (k+1)$) 各剰余クラスのモジュロの白セルのパリティをカウントします。$k+1$。 同じモジュロ クラス内のセルは許可された動きの下で同じ方法で相互作用するため、これにより独立したサブゲームがキャプチャされます。 
3. 各四角形を繰り返します。 左上が長方形の場合$(a,b)$そして右下$(c,d)$、この四角形内のすべてのセルを考慮します。 各セルを明示的に参照する代わりに、次の式を使用して、対応するモジュロ クラスのカウントを更新します。$(i \mod (k+1), j \mod (k+1))$対応するパイルの XOR に影響します。 
4. すべてのモジュロ クラスにわたるカウントの全体的な XOR を計算します。 各パイルはカウント モジュロ 2 に等しいサイズの Nim ヒープのように動作するため (二乗反転ゲームの特性)、各カウントはモジュロ 2 とみなされます。 
5. XOR がゼロの場合、現在のプレーヤー (ハメド) は完璧なプレーで勝つことができないため、マレックが勝ちます。 そうでなければ、ハメドが勝ちます。 

機能する理由: 組み合わせゲーム理論では、Nim では独立したサブゲームを山として表現できます。 モジュロ$(k+1)$分解により、あるパイル上の手が他のパイルに影響を与えないことが保証され、パイル サイズの XOR によって勝者が完全に決定されます。 同じ正方形を 2 回反転するとセルが元の状態に戻り、有効なパイル サイズのモジュロ 2 が減少するため、パリティは十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m, k = map(int, input().split())
    count = [[0]*(k+1) for _ in range(k+1)]

    for _ in range(m):
        a, b, c, d = map(int, input().split())
        for i_mod in range(k+1):
            row_count = ((c - i_mod) // (k+1) - (a-1 - i_mod)//(k+1)) 
            if row_count <= 0:
                continue
            for j_mod in range(k+1):
                col_count = ((d - j_mod)//(k+1) - (b-1 - j_mod)//(k+1))
                if col_count <= 0:
                    continue
                count[i_mod][j_mod] ^= (row_count * col_count) % 2

    xor_sum = 0
    for i in range(k+1):
        for j in range(k+1):
            xor_sum ^= count[i][j]

    print("Hamed" if xor_sum else "Malek")

if __name__ == "__main__":
    main()
```最初のセクションではコンパクトを初期化します。$(k+1) \times (k+1)$剰余クラスを表すグリッド。 各四角形は、各モジュロの組み合わせに該当するセルの数に基づいて、複数の剰余クラスに寄与します。 整数の除算式を使用してパリティを直接カウントします。 最後に、すべてのカウントを XOR して勝者を計算します。 

微妙な点としては、各モジュロ クラスのセル数を計算し、ゼロ カウントを処理する際のオフバイ 1 補正が含まれます。 を忘れて`-1`整数の除算を調整すると、エッジに揃えられた四角形のカウントが不正確になります。 

## 実用的な例

 **サンプル 1**

 入力:```
5 2 1
1 1 3 3
2 2 4 4
```| 長方形 | モジュロ位置 | XOR アップデート |
 | --- | --- | --- |
 | 1,1-3,3 | (0,0)、(0,1)、(0,2)、(1,0)... | 各クラスに 1 名 |

最終的な XOR 合計 = 1 なので、ハメドは完璧なプレイで最初のターンを失い、出力は「マレック」になります。 

**カスタム入力**```
4 1 2
1 1 4 4
```すべてのセルは白、モジュロ 3 グリッドはすべて 1 を数えます。 XOR 合計 = 0 なので、出力は「 Malek 」になります。 

これらのトレースは、モジュロ グループ化によって、大規模なボードに依存せずに、ボードがどのように管理可能な山に縮小されるかを示しています。$n$。
