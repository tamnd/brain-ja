 ## 解決策
 ## 問題の理解

 私たちは、異なる要素のすべてのペアが互いに素である、未知の正の整数の配列を扱っています。 この配列を操作できる唯一の方法は、2 つの位置の積を返すクエリを使用することです。 各クエリは 2 つのインデックスを選択し、対応する非表示の値の積を返します。 

タスクは、そのような積クエリの数を最小限に抑えながら配列全体を再構築することです。 配列サイズの制約は、慎重に構造化された再構築戦略が許可されるほど十分に小さいですが、厳密なクエリ バジェット モデルでは単純な要素ごとの分離が依然として限界に達するほど十分に大きいです。 

重要な構造上の約束は非常に強力です。どの 2 つの異なる要素も共通の素因数を共有しません。 これは、クエリされた 2 つの製品が 1 つのインデックスで重複している場合、製品に 2 つの異なる要素が含まれる場合は常に、異なる製品間で共有される情報のみが 1 つの共通要素から得られることを意味します。 

単純なアプローチでは、固定参照要素と組み合わせることによって各要素を独立して決定しようとします。 たとえば、インデックス 1 を固定してすべてのペア (1, i) をクエリすると、直積 a1 * ai が得られます。a1 が既知であれば、他のすべてがすぐに続きます。 しかし、a1 は不明であり、それを個別に回復するには、追加のクエリ全体のコストがかかり、合計クエリ数は約 2N になります。 

明らかではないエッジケースは、オーバーラップ構造を保証せずに要素を順番に回復しようとする場合です。 (1,2)、(3,4)、(5,6) のような素なペアをクエリすると、共有因子構造は得られず、gcd 関係は役に立たなくなります。 たとえば、値 [2,3,5,7] の場合、積 (2・3)=6 と (5・7)=35 はインデックスを共有しないため、gcd(6,35)=1 では回復可能な要素が得られません。 正しい出力は依然として元の配列ですが、そのようなクエリ戦略はすべての再構築可能性を破壊します。 

したがって、問題は効率的にクエリを実行することだけではなく、gcd による個々の隠れた値の抽出を可能にするオーバーラップの設計にも問題があります。 

## アプローチ

 直接的な強引な方法は、各要素を未知のものとして扱い、位置ごとに複数のクエリを使用して要素を分離しようとすることです。 いくつかの j 値について (i, j) をクエリし、gcd を使用して連立方程式を解くことによって、各 ai を回復しようとすることができます。 ただし、各要素には未知の近傍を除去するのに十分な独立した方程式が必要であるため、このような方法はすぐに O(N^2) クエリに縮退します。 

重要な洞察は、製品が重複する場合に 1 つの隠れた変数を共有する仕組みを利用することで得られます。 ai * aj と aj * ak など、インデックス j を共有する 2 つの積の場合、その gcd は次のようになります。 

gcd(ai * aj, aj * ak) = aj * gcd(ai, ak)

 すべての個別の要素は互いに素であるため、gcd(ai, ak) = 1 となり、gcd は正確に aj になります。 これにより、共有インデックスが直接抽出できるものになります。 

これは、要素を重複するトリプルにグループ化すると、2 つのクエリだけを使用して各トリプルの中間要素を回復できることを意味します。 隣接する製品の各ペアは中央のインデックスを共有するため、隠れた価値を引き出すことができます。 

2 つのクエリごとに 1 つの要素を分離する代わりに、2 つのクエリごとに 1 つの要素を分離し、同時に 3 位置ずつ進みます。 これにより、効率が約 2N クエリから約 2N/3 に向上します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^2) クエリ | お(1) | 遅すぎる |
 | トリプルオーバーラップ構造 | O(N) クエリ | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 3 つの連続するインデックスの重複グループで処理することにより、配列を構築します。

1. 3 つのインデックス i、i+1、i+2 のスライディング ウィンドウを修正します。 目的は中央要素ai+1の回収です。 
2. ウィンドウ内の最初の 2 つの要素の積をクエリし、x = ai * ai+1 を取得します。 
3. ウィンドウ内の最後の 2 つの要素の積をクエリし、y = ai+1 * ai+2 を取得します。 
4. gcd(x, y) を計算します。 両方の積に ai+1 が含まれているため、ai と ai+2 が互いに素であるため、gcd は ai+1 を正確に分離します。 これにより ai+1 が得られます。 
5. 復元された中間要素を保存し、ウィンドウを 3 位置ずつ前方に移動し、このプロセスを繰り返します。 
6. トリプル全体を処理した後、最後に残ったインデックスを処理します。 構築は 3 つのグループに基づいているため、残る要素は最大 2 つです。 これらは、既知の隣接要素とペアにするか、必要に応じて最終的な直接クエリによって回復できます。 

これが機能する理由は 1 つの不変式に関係しています。復元されたすべての gcd は、1 つの共通インデックスを共有する 2 つの製品から得られ、インデックスの他のすべてのペアは互いに素です。 これにより、gcd 操作後に無関係な要因が残らないことが保証されます。 各ステップでは、近隣からの汚染なしに 1 つの未知の要素をきれいに分離し、その後の操作は未回収の値に依存しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(i, j):
    print("?", i, j)
    sys.stdout.flush()
    return int(input())

def solve():
    n = int(input())
    a = [0] * (n + 1)

    i = 1
    while i + 2 <= n:
        x = ask(i, i + 1)
        y = ask(i + 1, i + 2)
        a[i + 1] = gcd(x, y)
        i += 3

    # remaining tail handling
    if n % 3 == 1:
        if n >= 2:
            a[n] = ask(n - 1, n) // a[n - 1]
    elif n % 3 == 2:
        a[n - 1] = ask(n - 1, n) // a[n]

    print("!", *a[1:])

def gcd(x, y):
    while y:
        x, y = y, x % y
    return x

if __name__ == "__main__":
    solve()
```このソリューションは、クエリを出力し、応答を即座に読み取る対話型のクエリ ヘルパーを中心に構造化されています。 gcd 関数は依存関係を避けるために手動で実装されます。 

メインループは 3 つのインデックスのステップで進みます。 各反復では 2 つのクエリを正確に実行し、トリプルの中央の要素を回復します。 重要な点は、トリプルの両方のエンドポイントを一度に復元しようとしないことです。これは、gcd 抽出に必要なオーバーラップ構造が失われるためです。 

末尾の処理は、完全なトリプルの後に残っている要素の数によって異なります。 最大 2 つのインデックスのみが残るため、そのうちの 1 つが推論された後、既知の積を既知の近傍で除算することによってインデックスが回復されます。 

正確さは、共素性条件から導かれる、すべての除算が正確であることを保証することに依存します。 

## 実用的な例

 配列 [2、3、5、7、11、13] を考えてみましょう。 

インデックスをトリプルで処理します。 

| ステップ | クエリ x | クエリy | gcd(x, y) | 既知の値 |
 | --- | --- | --- | --- | --- |
 | (1,2,3) | 2・3=6 | 3·5=15 | 3 | a2=3 |
 | (4,5,6) | 7・11=77 | 11・13=143 | 11 | a5=11 |

 処理後、既知の製品からの除算を使用して残りの値を直接計算します。 

このトレースは、各中間要素が干渉することなく独立して抽出されていることを示しており、クロストリプルコンタミネーションが発生していないことが確認されています。 

次に、より小さな例 [6、35、77] を考えてみましょう。 値は素数ではありませんが、どの位置でもペアごとに互いに素のままです。 

| ステップ | クエリ x | Query y | gcd(x, y) | 既知の値 |
 | --- | --- | --- | --- | --- |
 | (1,2,3) | 6・35=210 | 35・77=2695 | 35 | a2=35 |

 gcd は、値が複合値であっても、異なるインデックス間の共主性が維持される限り、中間要素を分離します。 

これは、値の大きさと構成に対する堅牢性を示しています。

 ## 特殊なケース

 重要なエッジ ケースは、N が 3 で割り切れない場合です。値 [a1、a2、a3、a4] を持つ N=4 を想定します。 アルゴリズムは (1,2,3) を処理し、a2 を回復します。 次に、インデックス 4 が残りますが、以前のクエリによって間接的にインデックス 3 に関する部分的な情報も残ります。 最終的なリカバリでは、残った要素の両方の隣接要素が既知であると仮定することを避けなければなりません。 そうしないと、初期化されていない値で除算が試行されます。 

別のエッジ ケースは N=1 です。 クエリは必要なく、単一の要素が直接出力されます。 トリプル戦略を適用しようとすると、範囲外のインデックスに誤ってアクセスする可能性があります。 

最後の微妙なケースは、値が大きく複合的な場合です ([30, 49, 77] など)。 値は多くの内部要素を共有しますが、インデックス間のペアごとの共主性により、gcd の動作は共有された中間要素を依然として分離します。 アルゴリズムは素数に依存せず、インデックス間の共素性にのみ依存するため、安定した状態を保ちます。
