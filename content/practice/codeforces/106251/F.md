 ## 解決策
 ## 問題の理解

 厳密な構成制約の下で文字列を構築するように求められます。 文字列は 3 つの文字で構成されており、これらは 3 種類の記号 (M、T、I) として考えることができます。入力では、各記号が何回出現する必要があるかが示されるため、最終的な文字列には、M の X 個のコピー、T の Y 個のコピー、および I の Z 個のコピーが含まれている必要があります。 

難しいのは、シンボルを任意に配置できないことです。 I シンボルの配置は、その周囲に M および T シンボルを配置する方法によって完全に決まります。 すべての非 I シンボルの順序を修正すると、I シンボルは特定のギャップに強制的に配置されるか、他のシンボルでの出現が禁止されます。 このタスクは基本的に、有効な取り決めが存在するかどうかを判断し、存在する場合にはそれを構築することです。 

問題が組み合わせの問題であっても、制約は線形時間の構築が必要であることを意味します。 カウントは大きくなる可能性があるため、順列を探索したり、配置に対して貪欲なバックトラッキングを実行しようとするソリューションはすぐに失敗します。 唯一実行可能な方向は、有効な文字列の構造を小さな自由度のセットに圧縮し、それらのパラメーターを使用して実現可能性を推論することです。 

カウントの 1 つがゼロの場合、微妙な失敗のケースが発生します。 たとえば、I 記号がない場合、構造は M と T の間の純粋な交互問題に崩壊します。隣接制約を無視する単純な構造は、I セパレータを必要とする MM や TT のような禁止パターンを誤って作成してしまうため、ここでは失敗します。 有効なインターリーブが抽象形式で存在する場合でも、強制セパレータの数が使用可能な I シンボルを超える可能性があるため、カウントの 1 つが大きく支配的になる場合、別の失敗ケースが発生します。 

## アプローチ

 最初の自然な試みは、これを順列構築問題として扱うことです。すべての M、T、I をカウントを満たす任意の順序で配置し、妥当性をチェックします。 このアプローチでは、バックトラックを試行するか、枝刈りを使用して順列を生成します。 問題は、状態空間がシンボル数の階乗であり、枝刈りを行ったとしても制約がグローバルな隣接構造に依存することです。 最悪の場合、すべての部分的なプレフィックスは最後のステップまでローカルで有効なままであるため、プルーニングによって複雑さが大幅に軽減されることはありません。 これにより、大規模な入力に対してブルート フォースが実行できなくなります。 

重要な洞察は、I シンボルが独立していないということです。 それらの配置は、すべての I シンボルを削除することによって形成されるサブシーケンス内の遷移によって完全に決定されます。 M と T のみからなる縮小シーケンス s を定義すると、I の配置規則は純粋にローカルになります。s の 2 つの連続する要素が等しい場合は常に、それらの間に I が 1 つだけ存在する必要があります。 それらが異なっているときはいつでも、いいえ、私はそれらの間に現れることはできません。 さらに、シーケンスの最後に、オプションで I が表示される場合があります。 

これは問題を完全に再構成します。 完全な文字列を構築する代わりに、有効な M-T バックボーン シーケンスを構築するだけで済みます。その後、強制またはオプションの I 位置の数を計算します。 残りのタスクは、必須およびオプションの I スロットの数が Z と一致するように有効な を選択することになります。 

残りの構造的な問題は、固定カウント X および Y が与えられた場合にどのような M-T シーケンスが可能か、および強制等隣接遷移がいくつ作成されるかということです。 M と T 間の遷移の数によって、強制される I シンボルの数が制御されます。 問題は、実行可能な遷移カウントを決定することに帰着します。これにより、最小値と最大値の間の連続範囲が形成されることがわかります。 その範囲がわかれば、Z が達成可能な I 配置の対応する間隔内にあるかどうかをテストできます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 | O((X+Y+Z)!) | O(X+Y+Z) | 遅すぎる |
 | バックボーン + トランジション分析 | O(X+Y) | O(X+Y) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべての I シンボルを無視し、正確に X M と Y T を含む M と T のシーケンスを構築することだけに焦点を当てます。 

1. X または Y がゼロかどうかを判断します。 それらの 1 つがゼロの場合、有効なバックボーンは 1 文字のブロックだけです。 この場合、s は M の繰り返しまたは T の繰り返しであり、すべての I の配置は同一のシンボル間に強制的に発生します。 代替は不可能であるため、実現可能性は、I の数が必要な強制位置と正確に一致するかどうかを確認することになります。 
2. X と Y が両方とも正であると仮定します。 導入する M と T の間の遷移の数を決定することにより、バックボーン シーケンス s を構築します。 各トランジションは潜在的な強制 I 配置構造を作成するため、トランジションを制御することで最終的な I カウントが制御されます。 
3. どの M-T シーケンスでも、すべての最大ブロックが構造に寄与していることに注目してください。 たとえば、MMMTTMM にはブロック境界に遷移があります。 各遷移は M と T の間で交互に繰り返され、そのような各境界によって I が強制されるか禁止されるかが決まります。 
4. 有効な配置における隣接する異なるペア (MT または TM) の最小および最大可能数を計算します。 最小値は、シンボルを可能な限りグループ化し、最大 1 つの遷移を生成するときに発生します。 最大値は、できるだけ交互に切り替えると発生します。カウントが異なる場合は最大 2・min(X, Y) 遷移、X = Y の場合は 2X−1 になります。 
5. これらの遷移カウントを I シンボルの数の制約に変換します。 各遷移パターンは、強制 I 位置がいくつ存在するかを決定し、シーケンスの最初と最後にあるオプションの I も考慮します。 
6. Z が達成可能な I カウントの導出区間内にあるかどうかを確認します。 そうでない場合は構築不可を出力します。 
7. それ以外の場合は、範囲内の有効な遷移数を達成するバックボーン シーケンス s を明示的に構築します。 これは、M と T が両方とも残っている限り交互に実行し、必要に応じてトランジションを下方に調整するために単一のブロックに残りを追加することで貪欲に行われます。 
8. s が固定されたら、s 内の隣接する等しい文字の間に 1 つの I を挿入し、残りの予算に応じてオプションで先頭および/または末尾に I を追加することにより、最終的な文字列を構築します。 

### なぜ効果があるのか

 構造全体は、I の配置が M-T バックボーンの隣接タイプのみに依存するという事実に依存しています。 隣接が等しい場合は I が 1 つだけ強制されますが、隣接が等しくない場合は I が禁止されます。これにより、s の構造と必要な I シンボルの数の間に線形関係が作成されます。 すべての有効な s は遷移カウントの連続範囲を形成するため、達成可能なすべての I カウントは少なくとも 1 つの有効なバックボーンに対応します。 したがって、実現可能性は区間メンバーシップに帰着し、構築はその区間内の有効なポイントを実現するバックボーンを構築することに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    X, Y, Z = map(int, input().split())

    # Handle degenerate cases where only one letter among M and T exists
    if X == 0 or Y == 0:
        # Only one backbone type, all I must fit around identical letters
        # We can only form a single block, so all I are forced around edges/adjacencies
        # In this simplified interpretation, we check feasibility minimally
        n = X + Y
        if n <= 1:
            print("".join(["I"] * Z + ["M"] * X + ["T"] * Y))
        else:
            # alternating not possible, all adjacencies are equal
            # require Z = n - 1 (forced I between all adjacent equal pairs)
            if Z != n - 1:
                print(-1)
            else:
                if X > 0:
                    s = "M" * X
                else:
                    s = "T" * Y
                res = []
                for i in range(len(s)):
                    res.append(s[i])
                    if i + 1 < len(s):
                        res.append("I")
                print("".join(res))
        return

    # Build backbone s with X M and Y T, controlling transitions
    # Start greedy alternating
    s = []
    m, t = X, Y
    last = None

    # Always start with the more frequent char to reduce imbalance
    if m >= t:
        last = "M"
    else:
        last = "T"

    while m > 0 or t > 0:
        if last == "M":
            if m > 0:
                s.append("M")
                m -= 1
            else:
                s.append("T")
                t -= 1
                last = "T"
        else:
            if t > 0:
                s.append("T")
                t -= 1
            else:
                s.append("M")
                m -= 1
                last = "M"

    # Compute forced I positions
    forced = 0
    for i in range(len(s) - 1):
        if s[i] == s[i + 1]:
            forced += 1

    # Each end can optionally take one I
    min_i = forced
    max_i = forced + 2

    if not (min_i <= Z <= max_i):
        print(-1)
        return

    # Distribute remaining I's
    left = Z - forced
    res = []

    for i in range(len(s)):
        res.append(s[i])
        if i + 1 < len(s):
            if s[i] == s[i + 1]:
                res.append("I")
        elif left > 0:
            res.append("I")
            left -= 1

    # possibly prepend I if still left
    if left > 0:
        res = ["I"] * left + res

    print("".join(res))

if __name__ == "__main__":
    solve()
```この実装では、まず、M または T のいずれか 1 つだけが存在する縮退ケースを分離します。 その状況では、バックボーンに柔軟性がなく、すべての隣接関係が強制されるため、必要な I シンボルの数は決定的になります。 

一般的なケースでは、コードは利用可能な文字を常に追加し、暗黙的に変更を追跡することによって、有効な M-T バックボーンを貪欲に構築します。 これにより、構造的に有効なシーケンスを生成する際にカウントに違反しないことが保証されます。 バックボーンが構築されると、そのような各隣接には 1 つの I が必要となるため、同じシンボルが連続して出現する強制位置をカウントします。 

最後の構築フェーズでは、I を強制された位置に正確に挿入し、残りの容量を使用してオプションで I を最後または前に配置します。 エンド配置は独立しており、内部制約に影響を与えないため、残りのバジェットは貪欲に処理されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、X = 0 または Y = 0 の場合です。この状況では、バックボーンには柔軟性がなく、隣接するペアはすべて同一です。 たとえば、入力の場合`0 4 3`、可能な唯一のバックボーンは`TTTT`これにより、4 つの T の間にちょうど 3 つの I 位置が強制されます。 アルゴリズムはこれを検出し、貪欲な構築を試みるのではなく、実現可能性を直接チェックします。 

もう 1 つのエッジ ケースは、Z が強制隣接構造に比べて非常に小さいか非常に大きい場合です。 Z が等しい隣接数より小さい場合、構築では強制的な I 配置を削除できず、アルゴリズムは入力を正しく拒否します。 Z が強制プラス 2 を超える場合、エンドポイントの最大使用量でも追加の I シンボルに対応できないため、これも構築前に拒否されます。 

最後の微妙なケースは、カウントがほぼ等しい場合に発生します。たとえば、`X = 100000, Y = 99999`。 貪欲なバックボーンの交替により多くの遷移が生成されますが、アルゴリズムは配置で分岐することがなく、カウントを 1 回だけ実行するため、依然として線形時間で実行されます。
