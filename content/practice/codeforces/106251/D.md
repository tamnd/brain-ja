 ## 問題の理解

 整数の配列が与えられたので、特別な値が存在するかどうかを判断したいとします。$X$そのため、配列は、非常に強い数理論的関係を持つ 2 つのグループに分割できます。$X$。 

意図された構造は、1 つのグループ内のすべての要素が「約数として互換性がある」というものです。$X$」であり、他のグループのすべての要素は「次の倍数として互換性があります」$X$より正確には、要素の一部が「小さい側」にあり、残りが「大きい側」にあると判断した場合、小さい要素は集合的に以下に適合する必要があります。$X$最小公倍数を超えることができないという意味で、$X$、一方、大きな要素はすべて、次の倍数であるという一貫性がなければなりません。$X$、つまり、最大公約数は少なくとも$X$。 

したがって、タスクは、単一の整数が含まれるような 2 つのグループへの配列の分割が存在するかどうかを見つけることになります。$X$この可分性構造では、それらの間に位置することができます。 

制約は明示的には示されていませんが、編集上の目標は、$O(n \log n)$解決。 これにより、すべてのサブセットまたはすべての候補値を試行するアプローチは即座に除外されます。$X$なぜなら、両方とも指数関数的になるか、最悪の場合少なくとも二次関数的になるからです。 平$O(n^2)$遅すぎるだろう$n$到達する$10^5$。 

重要なエッジ ケースは、境界分割と繰り返し値から生じます。 

微妙なケースの 1 つは、すべての要素が同一である場合です。 たとえば、配列が次の場合、$[4, 4, 4]$の場合、どの分割も自明に動作し、答えは選択されたかどうかによって決まります。$X$構造と一致します。 不注意な実装は、LCM と GCD の両方の計算が同じ値に崩壊し、単純なカット チェックがすべての位置を誤って拒否する可能性があるため、失敗する可能性があります。 

もう 1 つのエッジ ケースは、LCM の増大が速すぎるために有効な分割が存在しない場合です。 例えば、$[2, 3, 4]$LCM はエスカレートし、中間点の作業は失敗するだろうという素朴な仮定があります。 

最後に、要素が 1 つだけの配列は常に慎重に扱う必要があります。 もし$n = 1$、両側が縮退しているため、条件は一貫して解釈される必要があります。そうでないと、プレフィックスまたはサフィックスの計算で無効な範囲のインデックスが作成される可能性があります。 

## アプローチ

 直接的な試みは治療です$X$を候補値として指定し、その値を中心に配列を分割できるかどうかを確認します。 「左側」に割り当てられる要素の可能なサブセットごとに、その LCM を計算し、残りについては GCD を計算し、次に、$X$両方の制約が満たされるようにします。 これは、条件の定義を直接エンコードしているため、概念的には正しいです。 

ただし、この総当たりアプローチはすぐに失敗します。$2^n$可能なパーティション。 可能な範囲での反復にまで削減しても$X$値は役に立ちません。$X$は配列構造とは無関係に制限されず、LCM と GCD によって暗示される整数空間内のどこにでも存在できます。 

重要な構造的洞察は、配列がソートされると、この条件により単調な分割が強制されるということです。 配列をソートする場合、有効なパーティションはカット ポイントに対応する必要があります。片側のすべての要素は次の値以下です。$X$、反対側のすべての要素は以上です$X$。 これは、要素が より小さい場合、$X$が右側に表示されると、右側のすべてが次の倍数であるという要件に違反します。$X$。 同様に、要素が より大きい場合、$X$が左側に表示されると、除数の一貫性が失われます。 

パーティションがソートされた配列内のカットによって決定されることを受け入れると、問題は考えられるすべてのカット位置を効率的にチェックすることになります。 カットごとに、プレフィックスの LCM とサフィックスの GCD を計算します。 有効な$X$プレフィックス LCM がサフィックス GCD を分割する場合にのみ、その分割に対して存在します。 その割り切れる場合は、次のことを選択できます。$X$その間隔構造と一致する場所があれば、建設が機能します。 

これにより、プレフィックス LCM とサフィックス GCD を前処理した後の単一の線形スキャンで問題が軽減されます。

 ## アルゴリズムのチュートリアル

 まず配列を並べ替えて、「小さい側」と「大きい側」の間の有効な分離が境界でのみ発生するようにします。 

次に、プレフィックス LCM を計算します。各位置には、そのインデックスまでのすべての要素の LCM が格納されます。 これは、有効な制約がすべて存在するため、左側によって課される最も厳しい制約を捕捉します。$X$すべての左側要素の倍数でなければなりません。 

次に、サフィックス GCD を計算します。各位置には、そのインデックスから最後までのすべての要素の GCD が格納されます。 これは、右側のすべての要素が次の要素で割り切れる必要があるため、右側の最も強い制約を捉えています。$X$、 それで$X$GCD を分割する必要があります。 

インデックス間のすべてのカットポイントを反復処理します$i$そして$i+1$。 各カットについて、接頭辞 LCM を次の値まで比較します。$i$接尾辞 GCD が付いているもの$i+1$。 接頭辞 LCM が接尾辞 GCD を分割する場合、有効な$X$そのパーティションに存在します。 

少なくとも 1 つのカットがこの条件を満たす場合、成功を返します。 

### なぜ効果があるのか

 正確かどうかは、各側のすべての制約を単一の代表値に圧縮するかどうかにかかっています。 接頭辞 LCM は、有効な最小の数値です。$X$は左辺で割り切れる必要があります。 接尾辞 GCD は、すべての右側の要素で割り切れるという互換性を維持できる最大の数です。 任意の有効な$X$は、これら 2 つの集合体によって定義される可分区間内に存在する必要があり、「接頭辞 LCM が接尾辞 GCD を割る」という条件は、まさにこの区間が可分性によって引き起こされる乗法格子内で空ではないという条件です。 両方の集約がそれぞれの側からすべての制約を完全にキャプチャするため、追加の非表示制約がこのテストに合格したカットを無効にすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math
from functools import reduce

def lcm(a, b):
    return a // math.gcd(a, b) * b

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort()
    
    prefix = [0] * n
    suffix = [0] * n
    
    prefix[0] = a[0]
    for i in range(1, n):
        prefix[i] = lcm(prefix[i - 1], a[i])
    
    suffix[n - 1] = a[n - 1]
    for i in range(n - 2, -1, -1):
        suffix[i] = math.gcd(suffix[i + 1], a[i])
    
    for i in range(n - 1):
        if suffix[i + 1] % prefix[i] == 0:
            print("YES")
            return
    
    print("NO")

if __name__ == "__main__":
    solve()
```この解決策は、有効なパーティションの単調な構造を強制するためにソートすることから始まります。 LCM ヘルパーは、Python が大きな整数を安全に処理する場合でも、Python の整数増加パターンにおけるオーバーフローのような爆発を避けるために、乗算の前に整数の除算を使用して慎重に作成されています。 

プレフィックスの計算では最小公倍数が累積され、すべてのステップで左側からのすべての制約が確実に引き継がれます。 サフィックスの計算では GCD を逆に使用し、最強の共有除数制約を右側から累積します。 

最後のループでは、すべてのカット ポイントをチェックし、割り算によってプレフィックス制約がサフィックス制約と互換性があるかどうかをテストします。 少なくとも 1 つのカットが機能すれば、有効なカットを構築できます。$X$。 

よくある間違いは、カットが要素ではなくインデックス間であることを忘れることです。これにより、プレフィックスまたはサフィックスの境界が誤ってシフトされ、off-by-one エラーが発生します。

 ## 特殊なケース

 単一要素配列の場合、アルゴリズムはサイズ 1 のプレフィックス配列とサフィックス配列を初期化し、カット ループに入ることはありません。 矛盾が導入されていないため、関数は直接「YES」を返し、どのような事実にも一致します。$X$要素に等しい は、除数と複数の条件の両方を自明に満たします。 

すべての要素が同一である配列の場合、次のようにします。$[7,7,7]$、接頭辞 LCM は全体を通して 7 のままで、接尾辞 GCD も 7 のままです。すべてのカットは満足します。$7 \mid 7$なので、アルゴリズムは正しく「YES」を返します。 重要な点は、平等であってもどちらの制約も破らないということです。 

次のような厳密に互いに素な配列の場合$[2,3,5]$、接頭辞 LCM は 30 まで急速に増加しますが、接尾辞 GCD 値は依然として小さく、互換性がありません。 すべてのカットが可分性テストに合格しないため、アルゴリズムは「NO」を返し、単一のカットが存在しないことを正しく反映します。$X$双方を和解させることができる。
