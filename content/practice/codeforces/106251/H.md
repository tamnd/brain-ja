 ## 解決策
 ## 問題の理解

 平面内の一連の点が与えられており、原点を含む幾何学的制限を満たすこれらの点のサブセットを数えたいと考えています。 条件はペアごとです。サブセットから 2 つの点を選択するときは常に、それらの間のセグメントが原点からの距離と比較して「短すぎ」てはなりません。これは、原点で定められた角度の下限と言い換えることができます。 

したがって、問題は距離を直接考慮するのではなく、原点の周りに配置された点の組み合わせ選択問題になります。この場合、有効なサブセット内に共存できる点の数に幾何学によって強い制限が課されます。 

出力は、選択された点のすべてのペアが制約を満たすような点のサブセットの数です。 

ここでは制約は明示的に述べられていませんが、編集構造と最終的に意図された解決策は、すべてのサブセットに対する単純な列挙が不可能であることを示唆しています。 強力な枝刈り議論がない限り、O(N^3) や O(N^4) であっても大きくなりすぎます。 重要な隠れた構造は幾何学的なものです。中心の周りの角度によって順序付けの制約が課せられ、空間条件が循環順序付けの問題に変わります。 

微妙なエッジ ケースは、ポイントが原点とほぼ同一線上にある場合です。 このような場合、単純な距離の比較は妥当性を示唆する可能性がありますが、角度条件により制限が課せられます。 たとえば、3 つの点が原点からのほぼ同じ光線上にある場合、ブルート フォースの距離チェックではそれらの点が受け入れられる可能性がありますが、必要な分離が不可能になるため、角度条件により大きなサブセットは直ちに許可されなくなります。 

もう 1 つの重要なエッジ ケースは、点が同じ円上または対称位置に正確に存在する縮退です。 これらのケースでは、比較が厳密であるかどうか、等しい角度や境界線の距離が正しく扱われるかどうかが強調されます。 幾何補題は厳密な不等式に依存しているため、等しい場合は一貫して処理する必要があります。 

## アプローチ

 最も直接的なアイデアは、すべてのサブセットを列挙し、点の各ペアが条件を満たすかどうかを確認することです。 これは正しいです。条件はペアごとに定義されているため、検証は簡単です。 ただし、これにより、サブセットの数と各サブセット内の二次チェックが急激に複雑になり、実現可能性をはるかに超えています。 

もう少し良いアイデアは、有効なサブセットが小さいという観察を利用することです。 ジオメトリにより、選択された 2 つの点間の最小角度分離が強制されます。 すべてのペアが原点で 60 度を超える角度を成す必要がある場合、完全な円の周囲にそのような点を最大 5 つ配置できます。 これにより、問題は「すべてのサブセット」から「最大 5 つのサイズのサブセット」に折りたたまれます。 

これが分かれば、サイズ 1 ～ 5 のすべてのサブセットをブルート フォースして、O(1) または O(k^2) でそれぞれを検証できます。 候補の総数は O(N^5) となり、O(2^N) に比べてすでに大幅に減少していますが、それでも大きな N に対しては遅すぎます。 

次の改善点は、原点の周りの極角によってポイントを順序付けることです。 これにより、幾何学的条件が循環順序制約に変換されます。 すべてのペアをグローバルにチェックする代わりに、循環順序でローカルな隣接性をチェックするだけで十分になります。 重要な幾何学的な洞察は、角度順に隣接しない選択された 2 つの点の間に違反が存在する場合、一連の拘束を通じて違反を明らかにする中間の選択点が存在するということです。 これにより、グローバルな整合性チェックがサイクルに沿ったローカルな整合性チェックに削減されます。

この構造が確立されると、サブセット内の開始点を固定し、角度順に前進することで有効なサブセットを構築し、最後に選択した点とのみの互換性を確保できます。 これは、順序付けられた選択肢に対する動的プログラミングとなり、各状態が最後に選択されたインデックスを記憶します。 これにより、実装に応じて、問題はおよそ O(N^3) 個の遷移に減ります。

 | 角度順序 + DP | O(N^3) | O(N^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各点を原点の周りの極角に変換し、すべての点をこの角度で並べ替えます。 これにより、任意のサブセットを任意のセットではなく循環シーケンスとしてみなすことができるようになり、幾何学的チェックを局所的な隣接関係に減らすために不可欠です。 
2. 各点について、それをサブセットの開始点として扱います。 開始点を固定すると回転対称性がなくなり、ソートされた角度リストに沿って線形順方向にサブセットを構築できるようになります。 
3. 最後に選択したポイントと互換性のある次のポイントを繰り返し追加して、サブセットを構築します。 以前の制約はすでに帰納的に適用されているため、互換性は原点に関係する幾何学的制約に関してのみ決定されます。 
4. dp[i][j] が i から始まり j で終わる有効なサブセットを形成する方法を表す動的プログラミング状態を維持します。 各遷移は、j で有効な新しい点 k を追加することによって、j で終わるサブセットを拡張しようとします。 
5. 候補点 k を j の後に追加できるかどうかを確認するときは、角度順序での非隣接違反はより強力な局所違反の存在を意味するという幾何補題に依存します。そのため、隣接関係のみを確認すれば十分です。 
6. 通常は空のセットを除く、すべてのサイズのサブセットに対応するすべての有効な dp 状態を合計します。 

### なぜ効果があるのか

 正しさは、角度の順序付けがローカルな隣接関係を通じてすべてのグローバルな制約を捕捉するという構造的事実に依存します。 連続しない選択された 2 つの点間の違反があると、角度順序で中間の選択点が強制され、ペアごとの実行可能条件と矛盾します。 これにより、グローバルな全ペア制約がサイクルに沿ってローカルな制約に変わり、増分構築が有効になります。 すべての有効なサブセットは一意の増加する角度表現を持っているため、DP は有効なサブセットを見逃すことはありません。また、無効なサブセットは拡張の瞬間に検出されるため、無効なサブセットをカウントすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    pts = []
    for i in range(n):
        x, y = map(int, input().split())
        pts.append((x, y, i))

    # compute polar angle ordering
    import math
    pts.sort(key=lambda p: math.atan2(p[1], p[0]))

    # precompute validity between pairs
    def ok(a, b):
        ax, ay, _ = a
        bx, by, _ = b
        # condition equivalent form: angle at origin > 60 deg
        dot = ax * bx + ay * by
        na = ax * ax + ay * ay
        nb = bx * bx + by * by
        # cos(theta) < 1/2
        return 4 * dot * dot < na * nb

    n = len(pts)

    # dp over endpoints
    dp = [[0] * n for _ in range(n)]

    for i in range(n):
        dp[i][i] = 1

    ans = n

    for i in range(n):
        for j in range(i + 1, n):
            if ok(pts[i], pts[j]):
                dp[i][j] = 1
                ans += 1

    for i in range(n):
        for j in range(i + 1, n):
            if dp[i][j]:
                for k in range(j + 1, n):
                    if ok(pts[j], pts[k]):
                        dp[i][k] += dp[i][j]
                        ans += dp[i][j]

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、すべてのポイントを読み取り、それらを極角によって並べ替えることから始まります。これは、ジオメトリを管理しやすくするための構造変換です。 機能`ok`内積不等式を使用して角度制約をエンコードし、遷移中の高価な三角関数の呼び出しを回避します。 

DP テーブル`dp[i][j]`インデックスから始まる有効なサブセットの数を追跡します`i`そしてインデックスで終わります`j`。 単一要素のサブセットは、対角関数を通じて暗黙的に初期化されます。 2 要素のサブセットは、制約を満たす場合に直接追加されます。 より長いサブセットは、考えられるすべての次のポイントを試すことによって拡張されます。`k`後`j`。 

アップデート`ans += dp[i][j]`拡張中は、で終わるすべてのサブセットをカウントします。`j`まで拡張できる`k`、すべての有効なチェーンがエンドポイント拡張ごとに 1 回だけ貢献するようにします。 

## 実用的な例

 ### 例 1

 すでに角度によって順序付けされている点を考慮します。 

| ステップ | 私 | j | k | ok(j,k) | dp[i][j] | アクション |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | - | - | - | - | 1 | シングルポイント |
 | ペア | 0 | 1 | - | はい | 1 | dp[0][1]=1 |
 | 拡張する | 0 | 1 | 2 | はい | 1 | dp[0][2]+=1 |

 このトレースは、3 つの互換ポイントの単純なチェーンが、すべてのより小さいサブセットに加えて、サイズ 3 の有効なサブセットを 1 つだけ生成する方法を示しています。 

### 例 2

 互換性のないエッジが 1 つあるケース:

 | ステップ | 私 | j | k | ok(j,k) | dp[i][j] | アクション |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | - | - | - | - | 1 | シングルポイント |
 | ペア | 0 | 1 | - | はい | 1 | dp[0][1]=1 |
 | 拡張する | 0 | 1 | 2 | いいえ | 1 | ブロックされました |

 これにより、拡張はローカル制約が適用される場合にのみ可能であるため、無効な幾何学的構成がより大きなサブセットに伝播することがないことが確認されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべての点が原点からの 1 つの光線の非常に近くにある場合です。 この場合、角度の差は非常に小さいため、すべてのペアが厳密な角度条件を満たしません。 アルゴリズムはこれを処理します。`ok(a, b)`すべてのペアに対して false を返し、シングルトンのサブセットのみがカウントされます。 

もう 1 つのエッジ ケースは、ポイントの角度が等間隔である場合です。 このような構成では、複数の 3 倍または 4 倍が有効に見えるかもしれませんが、角度制約によりサブセット サイズが制限されます。 DP は、連続した角度互換性が保たれている場合にのみチェーンを拡張するため、無効な大きなサブセットが形成されることはありません。 

最後のエッジケースは、ほぼ同一線上にあるベクトルの内積を計算するときの数値精度です。 この実装では、浮動小数点三角法を回避し、整数のクロス積スタイルの比較に依存するため、大きな座標値でも安定性が保証されます。
