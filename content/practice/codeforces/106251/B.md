 ## 解決策
 ## 問題の理解

 この問題は、タスクの完全なバイナリ ツリーを記述します。 ツリーには特定の高さがあり、最初はルート タスクのみが使用可能です。 がある`p`プロセッサー。 1 単位時間中に、各プロセッサは現在利用可能なタスクを最大 1 つまで完了できます。 タスクを完了すると、その子が今後の処理に使用できるようになります。 目標は、ツリー内のすべてのタスクを完了するのに必要な最小時間を見つけることです。 

入力は複数のテスト ケースで構成されます。 各テストにより、ツリーの高さと利用可能なプロセッサの数がわかります。 各ケースの出力は、すべてのノードを処理するために必要な最小ラウンド数です。 

主な制約圧力は、高さが十分に大きいため、すべてのノードをシミュレートするのは不可能です。 高さの完全な二分木`h`含まれています`2^h - 1`したがって、高さが 50 程度であっても、すでに膨大な数のノードが作成されます。 すべてのタスクを反復するソリューションは指数関数的であり、機能しません。 実行時間がノードの総数ではなく、高さとプロセッサの数に依存するメソッドが必要です。 

難しいのは、プロセッサが別のレベルに進む前に 1 つのレベル全体を完了する必要がないことです。 よくある間違いは、レベルごとに処理し、レベルの未完了のノードが新しく利用可能なノードと混合できないと想定することです。 できます。 例えば：```
h = 3
p = 2
```ツリーレベルには以下が含まれます`1, 2, 4`ノード。 ルートが処理された後、2 番目のレベルには 2 つのタスクがあるため、2 番目の瞬間がそれらを終了します。 3 番目のレベルには 4 つのタスクがあり、さらに 2 分かかります。 答えは`4`。 レベル間の残りのプロセッサー容量を無視したレベルベースのシミュレーションでは、より大きな値を生成できます。 

もう 1 つのエッジ ケースは、レベル上にノードよりもプロセッサの数が多い場合です。 のために：```
h = 3
p = 10
```答えは`3`。 ルート、その子、最後のレベルに 1 秒かかります。 追加のプロセッサーを搭載しても、依存関係の連鎖を減らすことはできません。 

## アプローチ

 直接的なアプローチは、ツリーをシミュレートすることです。 準備ができているタスクの数を追跡し、最大で処理できます。`p`それらを 1 秒ごとに実行し、完了したタスクの子を追加します。 これは正確な実行順序に従っているため、正しいです。 問題は木の大きさです。 高さあり`h`、 がある`2^h - 1`タスクを実行するため、シミュレーションは指数関数的な作業を実行します。 高さ50の場合は約`10^15`操作、それは不可能です。 

有益な観察は、個々のノードの ID は重要ではないということです。 どの瞬間においても、利用可能なタスクの数だけが重要です。 完全なバイナリ ツリーは非常に規則的な構造を持っています。すべてのタスクを詳細に処理する場合`i`、 その通り`2^i`タスクは次の深さで利用可能になります。 

前の深さからの未完了のタスクの数を引き継ぎながら、ツリーを深さごとにスキャンできます。 現在の深度が`2^i`新しいタスク。 一部のプロセッサは、以前の深さからのタスクの仕上げにまだ占有されている可能性があるため、このラウンドで使用可能な量は、新しいタスクに残りの量を加えたものになります。 この合計を次のように割ります。`p`何回の完全なラウンドが必要かを知り、残りを次の深さのために保管します。 

重要な洞察は、レベル間の唯一の依存関係は残された作業だけであるということです。 レベルでプロセッサを使用した後に残っているタスクの数がわかれば、ツリー内のそれらのタスクの正確な位置は問題ではなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^h) | O(2^h) | 遅すぎる |
 | 最適 | O(h) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 未完了のタスクも経過時間もゼロの状態から開始します。 レベルはその親レベルが完了した後にのみ表示されるため、ツリーをルート レベルから下方向に処理します。 
2. あらゆる深さに対して`0`に`h - 1`、その深さで作成されたタスクの数を計算します。 完全なバイナリ ツリーには正確に次のものがあります。`2^depth`この深さのノード。 
3. 新しく作成したタスクを、前の階層の未完了のタスクに追加します。 この値は、現在処理できるすべてのものを表します。 
4. できるだけ多くのフルプロセッサラウンドを使用します。 フルラウンドの数は、利用可能なタスクの合計を で割ったものです。`p`、残りのタスクは残りです。 
5. すべての深度が処理された後、いくつかのタスクがまだ完了していない場合は、さらに 1 ラウンドを追加します。 これらは、前のラウンドには完全には当てはまらなかった最も深いレベルのタスクです。 

機能する理由: ある深度を処理した後、アルゴリズムは、さらに深くなる前にまだプロセッサーを必要とするタスクの数を正確に保存します。 次の深さのすべてのタスクは、現在の深さのタスクを完了することによってのみ生成されるため、このカウントのみを維持すると、将来に影響を与えるすべてが保存されます。 ツリー構造は十分に規則的であるため、他の情報は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        h, p = map(int, input().split())

        left = 0
        res = 0

        for depth in range(h):
            cur = (1 << depth) + left
            res += cur // p
            left = cur % p

        if left:
            res += 1

        ans.append(str(res))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```ループは正確に処理します`h`そのため、ランタイムはノードの総数に依存しません。 表現`1 << depth`計算する`2^depth`浮動小数点演算を使用しないため、累乗の使用による精度の問題が回避されます。 

変数`left`現在のレベルが処理された後、未完了のタスクを保存します。 これは、次の反復に必要な状態全体です。 による除算`p`完了したラウンドをカウントし、残りが次の残りの量になります。 

最深レベルでは新しいタスクが作成されないため、最終チェックが必要です。 最後の分割後にノードが残っている場合でも、最後のプロセッサ ラウンドが 1 回必要になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O(h) | 各ツリーの深さは 1 回処理されます。 |

import sys, io

def solution(data):
    inp = io.StringIO(data)
    out = []

    t = int(inp.readline())
    for _ in range(t):
        h, p = map(int, inp.readline().split())

        left = 0
        res = 0

        for depth in range(h):
            cur = (1 << depth) + left
            res += cur // p
            left = cur % p

        if left:
            res += 1

        out.append(str(res))

    return "\n".join(out)
