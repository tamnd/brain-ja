 ## 解決策
 ## 問題の理解

 タスクは、タイルのセットが$N \times N$グリッドは特定の接続ルールに基づいて完全にペアにすることができ、その場合はそのようなペアを生成します。 各タイルはグリッド セルを占有し、タイル タイプに応じたセグメンテーションの下で、2 つのタイルが同じ「行セグメント」または同じ「列セグメント」に配置されている場合、2 つのタイルがペアを形成できます。 

生のグリッド座標は重要な実際の構造ではありません。 重要なのは、同じタイプのタイルが行と列でどのように連続したランを形成するかです。 行内でタイルのタイプが変わると、その行は自然に均一なタイプの最大のセグメントに分割されます。 垂直方向の列にも同じことが当てはまります。 各タイルは、まさに 1 つの水平セグメントと 1 つの垂直セグメントに属しており、これら 2 つのセグメントはタイルがどのように相互作用するかを定義します。 

ペアリングは、2 つのタイルがこれらの共有セグメントの 1 つを通じて相互に「認識」できる場合に有効です。 したがって、本当の問題は、各ペアが水平セグメントまたは垂直セグメントのいずれかを共有するように、すべてのタイルをペアに分割できるかどうかです。 

この制約は、すべてのタイルまたはセグメントにわたって二次関数を使用する余裕がないことを意味します。 グリッドサイズが最大であっても、$10^5$セルの場合、任意のタイル ペア間の接続を繰り返しチェックするソリューションは失敗します。 構造は、線形または線形に近いサイズのグラフに縮小する必要があり、ペアリングはきれいな不変式を伴うグラフ問題になります。 

行と列自体が相互作用グラフを直接形成すると仮定すると、微妙な失敗例が発生します。 これにより、異なるタイプのタイルが誤って接続されてしまいます。 たとえば、行が`A A B B`そして私たちはすべてを結びつけます`A`セグメンテーションに関係なく同じ行にタイルを配置すると、タイプ境界を越えたペアリングが誤って許可されてしまいますが、これは実際の「最大セグメントによる接続」ルールによって禁止されています。 

もう 1 つの失敗例は、列のセグメンテーションを無視したことに起因します。 列では、最大の均一タイプの実行内でのみ垂直ペアリングが許可されるため、列全体を単一ノードとして扱うと制約が失われ、無効なペアリングが生成されます。 

したがって、重要な困難は、ペアリング自体ではなく、「セグメントの共有」が正確にエンコードされた正しい相互作用グラフを構築することです。 

## アプローチ

 セグメンテーション ルールを少し無視すると、問題は古典的なグラフのペアリング タスクになります。各タイルはエッジであり、端点を共有するエッジをペアにしたいと考えます。 この単純化された世界では、行と列を 2 部グラフの頂点としてモデル化でき、各タイルは行と列を接続します。 ペアリングは、頂点で交わるエッジをグループ化することになり、条件は各接続コンポーネントが偶数のエッジを持つことになります。 

このアイデアはすでに正しい構造方向を示唆しています。つまり、ペアリングはグラフ内のローカル接続によって完全に制御され、グローバルな実現可能性は接続されたコンポーネント内のパリティに依存します。 

ただし、「行」と「列」はアトミックではなくなっているため、これをグリッドに直接適用すると失敗します。 これらはタイル タイプによって分割されます。つまり、エッジの真のエンドポイントは完全な行と列ではなく、タイプの一貫性を維持するより細かいセグメントになります。 

重要な観察は、頂点を再定義することで正確さを復元できるということです。 行と列全体を使用する代わりに、それらを同一のタイル タイプの最大の連続セグメントに分割します。 これが完了すると、各タイルは水平セグメントと垂直セグメントの間のエッジになります。 これにより、単純化されたグラフ問題とまったく同じ構造が復元されますが、正しい制約がエンコードされています。 

この変換後、タスクは再び、この新しいグラフのすべての接続コンポーネントに偶数のエッジがあるかどうかをチェックし、偶数のエッジがある場合は、コンポーネント内の一致する隣接エッジを繰り返し削除することによってペアを構築します。 

ブルート フォース ビューから最適なビューへの移行は、不正なグローバル行ノードと列ノードをローカルで整合性のあるセグメント ノードに置き換えることにあります。これにより、ペアリングが許可されている場所での隣接関係が正確に維持されます。

 | セグメントグラフの縮小 | O(N \log N) または O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを行ごとにスキャンし、すべてのタイルが同じタイプを共有する最大の連続セグメントに各行を分割します。 このような各セグメントがグラフの頂点になります。 このようなセグメント内でのみ水平方向の相互作用が発生する可能性があるため、これが必要になります。 
2. 列に対しても同じことを行い、垂直セグメントの頂点を作成します。 これにより、垂直方向の制約が水平方向の制約と同じように尊重されるようになります。 
3. 位置にある各タイルについて$(i, j)$、水平セグメントの頂点と垂直セグメントの頂点を特定し、それらの間にエッジを作成します。 このエッジは、そのタイルが関与する 2 つの構造的制約の間の接続としてそのタイルを表します。 
4. すべてのタイルがエッジに変換された後、問題は次のようになります。ペアになったエッジが頂点を共有するようにエッジをペアにできるかどうかです。 これは、グラフの各接続コンポーネントに偶数のエッジがあることを確認することと同じです。 
5. 各連結成分について、エッジの数を計算します。 いずれかのコンポーネントのサイズが奇数の場合は、すべてのペアリングで正確に 2 つのエッジが削除されるため、ペアリングが不可能であることを返します。 
6. すべてのコンポーネントが偶数の場合は、深さ優先トラバーサルを使用してペアを構築します。 各頂点で、すべてのインシデントの不一致エッジを収集し、それらをローカルで貪欲にペアリングし、最大 1 つの不一致エッジを親に押し上げます。 
7. DFS は、コンポーネントのルートに戻るときに、一致しないエッジが残らないことを保証し、完全なペアリングを生成します。 

### なぜ効果があるのか

 重要な不変条件は、DFS 中に、すべてのサブツリーが上向きに渡される「ペアになっていないエッジ」を最大でも 1 つ維持するということです。 この不変条件は、ノードに付随するすべてのローカル エッジを貪欲にペアにすることができ、パリティのみが 1 つを残す必要があるかどうかを決定するため成り立ちます。 各コンポーネントは偶数のエッジで始まるため、パリティにより、ルートがペアになっていないエッジを受信することがなくなり、完全なキャンセルが強制されます。 セグメンテーションのステップにより、許可されたすべての隣接関係が 1 回だけ表現されることが保証されるため、有効なペアリングが失われることはなく、無効なペアリングが導入されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]

def solve():

    g = [list(input().strip()) for _ in range(n)]

    row_id = [[-1] * n for _ in range(n)]
    col_id = [[-1] * n for _ in range(n)]

    rid = 0
    for i in range(n):
        j = 0
        while j < n:
            k = j
            while k < n and g[i][k] == g[i][j]:
                k += 1
            for t in range(j, k):
                row_id[i][t] = rid
            rid += 1
            j = k

    cid = 0
    for j in range(n):
        i = 0
        while i < n:
            k = i
            while k < n and g[k][j] == g[i][j]:
                k += 1
            for t in range(i, k):
                col_id[t][j] = cid
            cid += 1
            i = k

    edges = []
    deg = {}

    for i in range(n):
        for j in range(n):
            u = row_id[i][j]
            v = rid + col_id[i][j]
            edges.append((u, v))
            deg[u] = deg.get(u, 0) + 1
            deg[v] = deg.get(v, 0) + 1

    adj = {}
    for idx, (u, v) in enumerate(edges):
        adj.setdefault(u, []).append((v, idx))
        adj.setdefault(v, []).append((u, idx))

        if not adj[start]:
            continue

        parent = {}

            if it[u] == len(adj[u]):
                stack.pop()
                continue

            v, eid = adj[u][it[u]]
            it[u] += 1

            used[eid] = True

```この実装では、最初に各行と列を最大均一セグメントに圧縮し、各セルに 2 つの識別子 (水平方向と垂直方向に 1 つ) を割り当てます。 各タイルはこれらの識別子間のエッジとなり、隣接リストが結果のグラフを表します。 

DFS 構造は接続処理を保証する一方で、主要な実現可能性条件はコンポーネント パリティを通じて暗黙的にエンコードされます。 完全な実装では、ノードごとに一致しないエッジを明示的に追跡します。 ここでの構造は、正しいグラフ表現を構築することに重点を置いています。 

よくある落とし穴は、行セグメントと列セグメントを個別に再計算する必要があることを忘れていることです。 それらを混在させると、誤った隣接が発生します。 もう 1 つの微妙な問題は、セグメント ID が行と列全体でグローバルに一意であることを保証することです。これは、列 ID を行セグメントの総数でオフセットすることで処理されます。 

## 実用的な例

 同一のタイルが明確なセグメントを形成する小さなグリッドを考えてみましょう。 

入力:```
3
AAA
ABA
AAA
```行のセグメント化では、最初の行と 3 番目の行がそれぞれ 1 つのセグメントに分割され、2 番目の行は 3 つのセグメントに分割されます。 列のセグメンテーションも同様に動作します。 結果のグラフには、各セルの行セグメント ノードと列セグメント ノードを接続するエッジがあります。 

中央セルをトレースする:

 | セル | 行セグメント | 列セグメント | エッジ |
 | --- | --- | --- | --- |
 | (1,1) | R0 | C0 | (R0、C0) |
 | (1,2) | R0 | C1 | (R0、C1) |
 | (2,2) | R1 | C1 | (R1、C1) |

 これにより、セグメンテーションによって相互作用の境界が正しく分離されることが確認されます。 

2 番目の例は均一グリッドです。 

入力:```
2
AA
AA
```すべての行と列が 1 つのセグメントに折りたたまれ、小さな完全な 2 部構造が生成されます。 すべてのコンポーネントのエッジ数は均等であるため、ペアリングは簡単に可能です。 これは偶数成分の不変条件を示しています。 

## 複雑さの分析
