 ## 解決策
 ## 問題の理解

 1 から n までの整数の順列が与えられます。これは、すべての位置が正確に 1 つの他の位置を指し、すべての位置が正確に 1 回指すことを意味します。 この構造は、各ノードが 1 つの出力エッジと 1 つの入力エッジを持つ有向グラフとして見ることができるため、グラフは互いに素な有向サイクルに分解されます。 

ここでのタスクは、各サイクルが特定のパターンで色付けされるように、各ノードに 3 つの色のうち 1 つを割り当てることです。 均等な長さのサイクルの場合、サイクルに沿って 2 つの色を交互に配置する必要があります。 奇数の長さのサイクルの場合、サイクルに沿って 2 つの色を交互に配置しますが、1 つのノードが交互にきれいに収まらないため、3 番目の異なる色を受け取ります。 

出力は、1 から n までの各インデックスに割り当てられた単純な色です。 

一般的な Codeforce の制限 (通常は 10^5 または 10^6 の 2 倍程度) までのサイズの置換によって暗示される制約により、要素のペアに対する二次シミュレーションは即座に除外されます。 ノードを繰り返し再訪問したり、サイクルごとに配列をスキャンしたりするアプローチは遅すぎます。 線形トラバースが必要です。これは、訪問したノードをマークし、サイクルを直接実行することにより、各ノードを一定の回数訪問する必要があることを示唆しています。 

すべてのサイクルの長さが 1 である場合、微妙なエッジ ケースが発生します。 たとえば、順列が [1] の場合、サイクルは奇数の長さを持ち、単一のノードで構成されます。 単純な交互の色付けアプローチでは、2 つの色を割り当てようとして 3 番目の色を一貫して割り当てることができませんが、正しい出力は単に、このノードが特別な色で色付けされる必要があるということです。 

もう 1 つのエッジ ケースは、[2, 3, 4, ..., n, 1] などの大きな単一サイクルです。 その長さが奇数の場合、ちょうど 1 つのノードが特別な色になる必要があり、不注意な実装では、サイクルの途中で色付けを再開するか、走査全体で状態を保持できない場合に、誤って 2 つの特別なノードを割り当てる可能性があります。 

## アプローチ

 ブルートフォース手法では、未訪問のノードを繰り返し選択し、最初に戻るまで順列ポインタをたどり、サイクル全体を保存しながら色の割り当てを試みます。 これはすでに最適に近づいていますが、実装が非効率である場合、サイクルを複数回再スキャンまたは再ウォークする可能性があり、長さ n の単一サイクルがあり、構造の検出に繰り返しスキャンが使用される最悪のケースでは二次的な動作が発生する可能性があります。 

重要な観察は、順列構造により、互いに素なサイクルへの分割が保証され、各サイクルを独立して処理できることです。 サイクルに入ると、そのサイクルを一度だけ通過し、色を記録または直接割り当てることができ、そのノードに再度アクセスすることはありません。 これにより、ローカル サイクル構造を超えたグローバルな推論の必要がなくなります。 

したがって、最適な解決策は、すべてのノードを 1 回通過し、未訪問のノードに遭遇するたびにサイクル トラバーサルを開始し、サイクル内のパリティ位置に従ってオンザフライでノードを色付けすることです。 サイクルの長さが奇数の場合は、交互パターンの完了後に最後のノードに特別な色を意図的に割り当てます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サイクル再スキャン | O(n^2) | O(n) | 遅すぎる |
 | 1 回のサイクル分解 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. すべてのノードに対して false に初期化された訪問先配列を維持します。 これにより、各ノードが正確に 1 つの処理されたサイクルに属し、後の走査で再訪問されることがなくなります。 
2. 1 から n までのすべてのノードを繰り返します。 未訪問のノードが見つかると、それが新しいサイクルの開始点になります。 
3. 開始ノードに戻るまで、順列ポインタを繰り返したどってサイクルを横断します。 移動中に、サイクル内に出現する順序でノードをリストに収集します。 色付けはサイクルに沿った隣接関係に依存するため、この順序は重要です。 
4. サイクルが収集されたら、その長さ k を決定します。 k が偶数の場合、2 つの色を使用してリストに沿って交互に色を割り当て、サイクル内の隣接するノードが異なる色を受け取るようにします。 
5. k が奇数の場合、最初の k から 1 を引いたノードに交互の色を割り当て、その後、最後のノードに特別な 3 番目の色を割り当てます。 これにより、奇数サイクルで純粋な 2 色の交互を不可能にするパリティの不一致が解決されます。 
6. 割り当てられた色を、ノードによってインデックス付けされた出力配列に保存します。 

この走査が安全である理由は、ノードを離れると、その出力エッジに従うことは常に同じサイクル内に留まり、誤って構造をマージしたり分割したりすることがないためです。 

### なぜ効果があるのか

 順列により、すべてのノードが 1 つの単純な有向サイクル内に存在することが保証されます。これは、グラフが互いに素な閉ループに分解されることを意味します。 サイクル内では、各ノードはサイクル順序の無向の意味でちょうど 2 つの隣接ノードを持ちます。 ラップアラウンド時にパリティが一貫しているため、2 つの色を交互に使用することは、偶数の長さのサイクルで完全に機能します。 奇数長サイクルでは、エッジごとにパリティが反転するため、先頭に戻ると矛盾が生じますが、この矛盾は、ちょうど 1 つのノードで交互を中断することで解決されます。 サイクルは互いに素であるため、あるサイクルの色付けが別のサイクルを制約することはなく、独立した処理が有効です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = [0] + list(map(int, input().split()))

    vis = [False] * (n + 1)
    color = [''] * (n + 1)

    for i in range(1, n + 1):
        if vis[i]:
            continue

        cycle = []
        cur = i

        while not vis[cur]:
            vis[cur] = True
            cycle.append(cur)
            cur = p[cur]

        k = len(cycle)

        if k % 2 == 0:
            for j in range(k):
                color[cycle[j]] = 'R' if j % 2 == 0 else 'B'
        else:
            for j in range(k - 1):
                color[cycle[j]] = 'R' if j % 2 == 0 else 'B'
            color[cycle[-1]] = 'G'

    print("".join(color[1:]))

if __name__ == "__main__":
    solve()
```コア実装はサイクル抽出の直後に続きます。 訪問済み配列により、サイクルをまたがるノードの再訪問が防止され、線形の複雑さが保証されます。 サイクル リストでは順序が維持されるため、エッジに沿って交互の色が一貫して表示されます。 唯一の微妙な決定は、最後に収集されたノードに特別な色を割り当てることで奇数サイクルを処理することです。これは、走査順序がサイクル順序と一致するため機能します。 

## 実用的な例

 p = [2, 1, 4, 3] で与えられるサイズ 4 の順列を考えてみましょう。 これにより、(1, 2) と (3, 4) の 2 つのサイクルが形成されます。 

| ステップ | 現在のノード | これまでに構築されたサイクル | アクション |
 | --- | --- | --- | --- |
 | 1 | 1 | [1] | 訪問 1 |
 | 2 | 2 | [1、2] | エッジをたどって 1 に戻り、停止します |
 | 3 | 3 | [3] | 新しいサイクルを開始する |
 | 4 | 4 | [3、4] | サイクルを閉じる |

 どちらのサイクルも同じ長さなので、色を交互に切り替えます。 サイクル (1、2) は R、B になり、サイクル (3、4) は R、B になります。 

ここで、長さ 3 の単一サイクルである p = [2, 3, 1] について考えてみましょう。 

| ステップ | 現在のノード | これまでに構築されたサイクル | アクション |
 | --- | --- | --- | --- |
 | 1 | 1 | [1] | 開始 |
 | 2 | 2 | [1、2] | 続ける |
 | 3 | 3 | [1、2、3] | 最初に戻る |

 サイクル長が奇数であるため、ノード 1 と 2 は交互の色 R と B を受け取り、ノード 3 は G を受け取ります。 

これらの例では、走査順序がサイクル構造と一致し、色付けが各サイクル内で独立して一貫していることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ノードはサイクル トラバーサル中に 1 回だけ訪問されます。 
| スペース | O(n) | 訪問された配列、カラー配列、およびサイクル バッファーのストレージ |

 このソリューションは、すべての操作がノードごとに一定の作業であり、ネストされたトラバーサルが発生しないため、置換ベースの問題の一般的な制約内に問題なく適合します。

 ## 特殊なケース

 n = 1、p1 = 1 などの単一ノード サイクルでは、長さ 1 のサイクルが生成されます。 トラバーサルではそのノードのみが収集され、長さが奇数であるため、アルゴリズムによって特別な色が直接割り当てられます。 ループは最初に戻った直後に終了するため、サイクル ロジックは引き続き機能します。 

n = 5、p = [2, 3, 4, 5, 1] などの完全に接続されたサイクルは、すべてのノードを順番に収集することによって処理されます。 カラーリングでは、最初の 4 つのノードに交互の色が割り当てられ、5 番目のノードが特別なカラー スロットに配置されます。 サイクル リストには各ノードが 1 回だけ含まれ、最後の位置は走査順序によって一意に定義されるため、走査により、正確に 1 つのノードが特別な色を受け取ることが保証されます。
