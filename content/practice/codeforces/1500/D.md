 ## 解決策
 ## 問題の理解

 We are given an$n \times n$タイル スタンドを表すグリッド。各セルには特定の色のタイルが含まれます。 Kostya は、考えられるサブスクエアのサイズごとに知りたいと考えています$k$、 幾つか$k \times k$サブスクエアには最大でも次のものが含まれます$q$独特の色。 サブスクエアは、左上隅とそのサイズによってのみ決定されます。 出力は整数のリストです。$k$1から$n$、サイズの有効な部分正方形の数$k$。 

グリッドのサイズ$n$最大 1500 に達する可能性があります。これは、すべてのサブスクエアを個別に調べる単純なアプローチでは遅すぎる可能性があることを意味します。 の合計数$k \times k$サブスクエアは$(n - k + 1)^2$以上をまとめると、$k$おおよそ与えます$O(n^3)$サブスクエア。 それぞれについて、線形スキャンで異なる色を数えると、$k^2$細胞、私たちは到達します$O(n^5)$最悪の場合の操作は完全に不可能です。 

明らかではないエッジケースには、色が繰り返されるグリッドが含まれます。 たとえば、すべてのタイルが同じ色である 3x3 グリッドは、すべての色が異なるグリッドとは異なるカウントを生成します。 のために$q=1$の場合、ソリューションでは単一色のみの正方形を検出する必要があります。検出しないとカウントが間違ってしまいます。 もう一つの微妙なケースは次のような場合です。$q \ge n^2$; その場合、すべての部分正方形はその色に関係なく有効になります。 最後に、いつ$n=1$、単一のセルを 1x1 の部分正方形として正しく処理する必要があります。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべての左上隅を反復処理します。$(i,j)$可能なすべてのサイズ$k$。 各サブスクエアについて、セット内のすべての色を収集し、そのサイズが以下を超えていないかどうかを確認します。$q$。 This is correct, but its complexity is$O(n^3 \cdot k^2) = O(n^5)$最悪の場合、許容限度をはるかに超えます。 

重要な洞察は次のとおりです$q$これにより、色のセットを効率的に表現し、一定時間または短い固定時間でそれらをマージすることができます。 サブスクエアごとにすべての色を単純に数える代わりに、情報を段階的に構築できます。 各セルに最大で次のセットを保存する動的プログラミングのアプローチを考えてみましょう。$q+1$そのセルで終わるサブスクエアに表示される最小の色。 サブスクエアをサイズから拡大する場合$k-1$に$k$、左上隅、右端の列、および下の行のカラー セットを組み合わせるだけで済みます。 最初のものだけを追跡するため、$q+1$色を指定すると、組み合わせたセットが次の値を超える場合にその正方形が無効であるかどうかをすぐに知ることができます。$q$。 

このアプローチでは、各サブスクエア内のすべてのセルを個別に反復処理する必要がなくなるため、複雑さが大幅に軽減されます。 代わりに、最大でもサイズの小さいセットをマージします。$q+1$各拡張の合計時間は$O(n^2 q^2)$、これは実現可能です$n=1500$そして$q \le 10$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^5) | 部分平方あたり O(k^2) | 遅すぎる |
 | 最適 (DP + 小型セット) | O(n^2 q^2) | O(n^2 q) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2D 配列を初期化する`dp[i][j]`各エントリには、最大でソートされたリストが保存されます。`q+1`で終わるサブスクエア内の異なる色`(i,j)`現在のサイズの場合。 
2. サイズについて`k=1`、 それぞれ`dp[i][j]`単に色です`c[i][j]`。 を満たす正方形をすべて数えます。`q`すぐに。 
3. サイズについて`k > 1`、すべての可能な右下隅を反復処理します。`(i,j)`の`k x k`四角。 3 つのコンポーネントをマージしてカラー セットを構築します。`(k-1)x(k-1)`で終わるサブスクエア`(i-1,j-1)`、長さの右端の列`k-1`、長さの一番下の行`k-1`。 ソートされたマージを使用し、最初のものだけを保持する`q+1`色。 
4. マージされたカラーセットに次のものが含まれている場合`<= q`色、このサイズのカウントを増やします`k`。 
5. すべてのサイズに対してこのプロセスを繰り返します。`k`1から`n`。 カウントを出力します。 

なぜ効果があるのか​​: 各ステップで、`dp[i][j]`の色の完全な概要が含まれています。`k x k`で終わるサブスクエア`(i,j)`。 までだけマージすることで、`q+1`色については、サブスクエアが個別の色の許容数を超えているかどうかを早期に検出します。 不変条件は、すべてが可能であるということです`k x k`サブスクエアは 1 回だけ考慮され、そのカラー セットは正しく維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, q = map(int, input().split())
    c = [list(map(int, input().split())) for _ in range(n)]
    
    counts = [0] * n
    # dp[i][j] stores the color set for the current size k ending at (i,j)
    dp = [[[] for _ in range(n)] for _ in range(n)]
    
    for i in range(n):
        for j in range(n):
            dp[i][j] = [c[i][j]]
            if q >= 1:
                counts[0] += 1
    
    for k in range(2, n+1):
        new_dp = [[[] for _ in range(n)] for _ in range(n)]
        for i in range(k-1, n):
            for j in range(k-1, n):
                merged = set()
                merged.update(dp[i-1][j-1])
                for x in range(i-k+1, i):
                    merged.add(c[x][j])
                for y in range(j-k+1, j):
                    merged.add(c[i][y])
                if len(merged) <= q:
                    counts[k-1] += 1
                new_dp[i][j] = list(merged)[:q+1]
        dp = new_dp
    
    print('\n'.join(map(str, counts)))

if __name__ == "__main__":
    main()
