 ## 問題の理解

 2 つの循環的な色のシーケンスがあります。 

最初のシャンデリアは配列を繰り返します`a`長さの`n`、2番目のシャンデリアは配列を繰り返します`b`長さの`m`。 当日`d`、最初のシャンデリアは位置を示します`(d - 1) mod n`、2番目は位置を示します`(d - 1) mod m`。 

両方のシャンデリアが同じ色を表示する日もあります。 それ以外の日は異なる色で表示されます。 不一致日数が正確に一致する日を見つけるように求められます`k`。 

難しいのは、`k`と同じ大きさにすることができます`10^12`。 一日ずつシミュレーションすることはできません。 

カラー値は各シーケンス内で異なります。 色は両方のシーケンスに表示される場合がありますが、同じシーケンスに複数回表示されることはありません。 この独自性が、この問題の重要な構造的特性です。 

長さは到達可能です`500000`、したがって、`O(nm)`前処理は不可能です。 ソリューションは、線形または線形に近い状態を維持する必要があります。`n + m`。 

特に危険な間違いは、パターンが毎回繰り返されると仮定することです。`lcm(n,m)`日を計算してから、1 つの期間のすべての日を明示的に構築します。 いつ`n = 499999`そして`m = 500000`、最小公倍数はおおよそ次のとおりです。`2.5 × 10^11`多すぎて枚挙に暇がありません。 

ある色が 1 つのシャンデリアにのみ存在する場合、別の微妙なケースが発生します。```
n = 2, m = 2
a = [1, 2]
b = [1, 3]
```色`2`そして色`3`一致する日を作成することはできません。 両方の配列に色が存在するかどうかを確認せずにすべての位置をペアリングしようとするソリューションでは、存在しない一致がカウントされます。 

3 番目のエッジケースは、共通の色が両方のシーケンスに存在するが、その位置がモジュロとして互換性がない場合に発生します。`gcd(n,m)`。```
n = 4, m = 6
a = [1, 2, 3, 4]
b = [5, 6, 1, 7, 8, 9]
```色`1`位置に表示されます`0`そして`2`。 以来`gcd(4,6)=2`、合同```
x ≡ 0 (mod 4)
x ≡ 2 (mod 6)
```解決策がありません。 その色は決して同じ日を生み出すことはありません。 CRT の実装が不注意であると、誤ってカウントされる可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 毎日、両方のサイクルのアクティブな位置を計算し、色を比較し、不一致をカウントします。 不一致数が一定に達すると、`k`、現在の日付を返します。 

これが機能するのは、プロセスの定義が直接的なためです。 残念ながら、答えは近くにあるかもしれません`10^12`したがって、シミュレーションには最大 1 兆回の反復が必要になります。 

最初の観察は、興味深い日は一致する日だけであるということです。 最初の日に一致する日が何日発生するかを数えることができる場合`x`数日、それから```
mismatches(x) = x - matches(x).
```答えは一番小さな日になる`x`そのような```
x - matches(x) ≥ k.
```これはすぐに二分探索を示唆します。 

残りの問題は、マッチング日数を効率的にカウントすることです。 

すべての色は各シーケンスで最大 1 回しか出現しないため、色は最大 1 つの合同系を生成​​できます。```
day ≡ position in a (mod n)
day ≡ position in b (mod m)
```一般的な色ごとに、このシステムには解がないか、一致する日の等差数列が 1 つ生成されます。 進行には期間がある`lcm(n,m)`。 

したがって、日数について考える代わりに、一般的な色について考えます。 すべての一般的な色について、中国剰余定理を使用して最初に一致する日を決定します。 次に、制限を与えると、`x`、各進行の項が最大で何個あるかを数えます。`x`。 

一般的な色の総数は最大で`min(n,m)`、最大でも`500000`により、この前処理が可能になります。
