 ## 解決策
 ## 問題の理解

 友人から Nastya への贈り物を表す整数の配列が与えられます。 彼女は、最初の 2 つのインデックスの要素の合計が他の 2 つのインデックスの要素の合計と等しくなるように、配列内で 4 つの異なるインデックスを見つけたいと考えています。 入力は配列のサイズとそれに続く配列自体で構成され、出力はそのようなインデックスが存在する場合はインデックス自体とともに「YES」、それ以外の場合は「NO」になります。 

この制約により、配列サイズは最大 200,000、各要素は 250 万個までにすることができます。 2 秒の制限時間を考えると、すべての 4 倍を反復するアルゴリズムでは次のオーダーが必要になります。$O(n^4)$まったく実行不可能な操作です。 すべてのペアを単純に反復しても、潜在的に$O(n^2)$、最悪の場合、4 * 10^10 の演算に達する可能性があります。 したがって、すべての 4 倍体の単純な列挙を避ける必要があります。 

明らかではないエッジ ケースには、すべての要素が等しい配列、または多くの要素が重複している配列が含まれます。 不注意なアプローチでは、同じインデックスを 2 回選択したり、要素を共有するペアを考慮できなかったりする可能性があります。 たとえば、配列では`[1, 1, 1, 1]`インデックスの一意性が強制されていない場合、単純な合計比較では誤って「NO」が出力される可能性があります。 もう 1 つの微妙なケースは、要素が 4 つだけの小さな配列です。 アルゴリズムは最小入力サイズを正しく処理する必要があります。 

## アプローチ

 ブルートフォース手法では、4 つのインデックスのすべての組み合わせを反復処理します。$x, y, z, w$、2 つの要素のペアの合計を計算し、それらを比較します。 この方法は正しいですが、次のことが必要です$O(n^4)$不可能な操作$n = 2 \times 10^5$。 もう少し良いアプローチは、すべてのペアを反復処理し、それらの合計を計算し、各合計を対応するインデックスとともに保存することです。 素のインデックスで 2 回発生する合計を見つければ、解決策が得られます。 合計をハッシュ マップに保存すると、重複を効率的に検出できるようになります。 

重要な洞察は、すべての 4 回転を比較する必要はないということです。 代わりに、すべてのペアを反復処理し、それらの合計をそれらを生成したインデックスにマッピングし、このマップで衝突をチェックすることができます。 重複しないインデックスで合計が繰り返される場合、4 つの異なるインデックスがすぐに見つかります。 制約を考慮すると、すべてのペアを反復処理すると、$O(n^2)$、これは小さな配列には許容されますが、それでも大きすぎる可能性があります。$n = 2 \times 10^5$。 ただし、200 個を超える要素があると、和の範囲が限られているため、鳩の巣原理によ​​る繰り返し和が保証されるため、問題は一般性を失わずに最初の 200 個の要素のみを考慮するように制限できます。 これにより、複雑さが軽減されます。$O(200^2) = 40,000$、十分に速いです。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^4) | お(1) | 遅すぎる |
 | ペアサムハッシュ | O(min(n,200)^2) | O(min(n,200)^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列に 200 を超える要素がある場合は、最初の 200 要素に切り捨てられます。 これが機能するのは、個別の合計の数が最大要素によって制限されるためです。そのため、鳩の穴の原理により、最初の 200 要素内のペア間で繰り返された合計は、解を保証するのに十分です。 
2. ペアの合計を、その合計を生成するインデックスにマッピングする空のハッシュ マップを初期化します。 
3. すべてのインデックスのペアを反復処理します。$i$そして$j$切り捨てられた配列内。 
4. インデックスの要素の合計を計算します。$i$そして$j$。 
5. この合計がすでにハッシュ マップにある場合は、保存されているインデックスが現在のペアと重複していないかどうかを確認します。 それらが互いに素である場合は、「YES」と 4 つのインデックスを出力して終了します。 
6. 合計がマップにない場合、またはインデックスが重複する場合は、この合計の現在のペアを保存します。 
7. すべての反復の後、素のインデックスを持つペアの合計が繰り返されない場合は、「NO」を出力します。 

機能する理由: このアルゴリズムは、考えられる各ペアの合計をインデックスの一意のペアにマッピングすることに依存しています。 すべてのペアを体系的にスキャンすることにより、初めて合計が素のインデックスで繰り返されるときに、合計が等しく、インデックスがすべて異なることが保証されます。 配列を 200 要素に切り詰めても、200 要素を超えると切り詰められた配列のペア間で合計が繰り返されることが保証されるため、安全です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    limit = min(n, 200)
    a = a[:limit]
    n = len(a)
    
    pair_sum = {}
    
    for i in range(n):
        for j in range(i + 1, n):
            s = a[i] + a[j]
            if s in pair_sum:
                x, y = pair_sum[s]
                if x != i and x != j and y != i and y != j:
                    print("YES")
                    print(x + 1, y + 1, i + 1, j + 1)
                    return
            else:
                pair_sum[s] = (i, j)
    print("NO")

solve()
```この解決策では、まず配列を 200 要素に切り詰めて、二次方程式のアプローチを実現可能にします。 ネストされたループはペアの合計を効率的に計算し、ハッシュ マップを使用して繰り返される合計を迅速に検出します。 解決策を報告す​​る前に、インデックスの一意性が慎重に適用されます。 インデックスは印刷前に 1 ベースに変換されます。
