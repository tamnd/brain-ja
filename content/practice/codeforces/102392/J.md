 ## 解決策
 ## 問題の理解

 奇数 (n) 個の頂点上に完全な無向グラフがあります。 その (\frac{n(n-1)}2) エッジのすべてに正の重みがあります。 

すべてのエッジをサイクル配列に分割する必要があります。 1 つの配列内の連続するエッジは頂点を共有する必要があり、各エッジの周囲の 2 つの遷移は異なるエンドポイントを使用する必要があるため、配列はグラフ内の閉じた軌跡を記述します。 サイクル配列は頂点を再訪することができます。 重要なのは、エッジが周期的に配置されており、各エッジがその各端点を介して 1 つのエッジに隣接していることです。 

2 つの連続するエッジ (e_i,e_{i+1}) の場合、寄与はそれらの重みのうち大きい方になります。 1 つのサイクル配列の価格は、配列全体に関するこれらの寄与の合計です。 必要な出力は、すべてのグラフ エッジをそのような配列に分割した場合の可能な最小合計価格です。 

(n) が奇妙であることが、問題が単純になる構造的な理由です。 すべての頂点には次数 (n-1) があり、これは偶数です。 サイクル配列の頂点に入るエッジは、その頂点から出る 1 つのエッジと必ずペアにする必要があるため、頂点に入るすべてのエッジはペアに分割できます。 

頂点の数は最大 (999) ですが、グラフは密集しています。 (n=999) の場合、次の内容が含まれます。 

[
 \frac{999\cdot998}{2}=498501
 】

 エッジ。 これにより、サイクル、サイクル分解、または任意のペアを列挙するアルゴリズムが即座に除外されます。 すべてのエッジの 1 つの循環順序付けでも、およそ (498500!/2) 個の可能性があります。 意図したソリューションでは、目的を頂点で分離できるという事実を利用する必要があります。 

重みは (10^9) まで大きくなる可能性があるため、答えは 32 ビットの符号付き整数に収まりません。 最大のすべてが等しいインスタンスでは、答えは (498501) ですが、個々の重みが大きくなると、(10^{15}) 程度になる可能性があります。 Python の整数はこれを自動的に処理しますが、C++ 実装では次の処理が必要になります。`long long`。 

1 つの小さなエッジ ケースは (n=3) です。 すべての頂点には正確に 2 つの入射エッジがあるため、各頂点で可能なペアは 1 つだけです。 例えば、```
3
1 2 1
2 3 1
1 3 1
```答えは(3)です。 すべての頂点に少なくとも 4 つの入射エッジがあると仮定するソリューションや、誤ったペアリング ループを実行するソリューションでは、このケースが見逃される可能性があります。 

もう 1 つの重要なケースは、等しい重みです。 のために```
3
1 2 5
2 3 5
1 3 5
```答えは(15)です。 すべての隣接のコストは (5)、三角形には 3 つの隣接があります。 エッジを重みで区別しようとする不注意な実装では、誤って同じ重みのエッジを破棄したり、そのうちの 1 つだけをカウントしたりする可能性があります。 

3 番目のケースは、大きな重みに関するものです。 のために```
3
1 2 1000000000
2 3 1000000000
1 3 1000000000
```答えは (3000000000) です。 32 ビット整数を使用するとオーバーフローが発生します。 アルゴリズム自体は加算のみを実行するため、実装では最終的な合計を保持できる整数型を使用するだけで済みます。 

## アプローチ

 直接的なアプローチでは、考えられるサイクル分割を列挙し、それぞれの価格を計算して、最小値を維持しようとします。 すべての有効な分割が最終的に考慮されるため、これは正しいです。 問題は可能性の数です。 (m=\frac{n(n-1)}2) の場合、すべての (m) 個のエッジを含む 1 つのサイクルだけを考慮しても、無向設定では ((m-1)!/2) 個の異なる巡回順序付けが得られます。 (n=999)、(m=498501) の場合、これは実行可能なものをはるかに超えています。 いくつかのサイクルを列挙したり、頂点ですべてのペアを試行したりすると、さらに状況が悪化します。 

有益な観察は、価格を頂点にローカルに割り当てることができるということです。 

1 つのエッジ (e=(u,v)) を考えます。 そのサイクル配列内で、(u) を通じて正確に 1 つの隣接エッジと比較され、(v) を通じて正確に 1 つの隣接エッジと比較されます。 したがって、頂点 (u) では、入射エッジがペアに分割され、各ペアが 2 つの重みの最大値に寄与します。 サイクル分割全体におけるすべての価格寄与は、まさに 1 つのそのような頂点に属します。 

したがって、グローバル問題は、独立したローカル問題の集合になります。すべての頂点で、その (n-1) 個の入射エッジをできるだけ安価にペアにします。 

1 つの頂点におけるインシデントの重みを最大から最小の順に並べると、次のようになるとします。 

[
 w_1\ge w_2\ge w_3\ge w_4\ge\cdots\ge w_{n-2}\ge w_{n-1}。 
】

 (\frac{n-1}{2}) 個のペアがあります。 ペアごとの最大値の合計を最小化するには、2 つの最大値をペアにし、次に大きい 2 つの値をペアにする必要があります。 

[
 (w_1,w_2),(w_3,w_4),\ldots
 】

 結果として貢献度は

 [
 w_1+w_3+w_5+\cdots+w_{n-2}。 
】

 なぜこの組み合わせが最適なのでしょうか? 最大の要素はあるペアの最大値でなければならないため、すべてのペアは少なくとも (w_1) を支払います。 それを 2 番目に大きい値と組み合わせた後、残りの問題は残りの値に関して同じ形式になります。 同様に、大きな値と小さな値をペアにすると、大きな値がすでにペアのコストを決定しているため、その小さな値が無駄になります。 最大値から最小値まで連続して値をペアリングすると、ペアの最大値となる大きな値の数が最小限に抑えられます。 

残りの問題は、すべての頂点でこれらの最適なペアを個別に選択することで、実際に有効なサイクル配列を生成できるかどうかです。 できる。 選択された各ペアを、その頂点でどのエッジがどのエッジに続くかを示す遷移としてみなします。 未使用のエッジから開始して、現在のエンドポイントでペアのエッジをたどります。 頂点に到達するたびに、そこにあるちょうど 1 つのペアが部分的に使用されるため、そのペアを完成させる固有のエッジが存在します。 このプロセスを続けると、最終的には開始点に戻ります。これは、エッジの数が有限であり、すべてのエッジに 2 つのペアの端点があるためです。 結果として得られる閉じたトレイルは有効なサイクル配列です。 完了したら、別の未使用のエッジから再度開始します。 

結果として生じる構築は、局所的に最適なすべてのペアを実現するため、極小値の合計は単なる下限ではありません。 それは達成可能であり、まさに全体最適です。 これは、公式社説で使用される中心的な縮小です。

 ## アルゴリズムのチュートリアル

1. すべての (m=\frac{n(n-1)}2) エッジを読み取り、各エッジを 2 つのエンドポイントとその重みとして保存します。 グラフは完成しているため、最終的にはすべての頂点が正確に (n-1) 個の入射エッジを受け取ることになります。 
2. すべての頂点について、すべての入射エッジの重みを収集します。 (n) は奇数、(n-1) は偶数であるため、これらの重みはペアに分割できます。 
3. インシデントの重みを降順に並べ替えます。 位置 (0) と (1)、位置 (2) と (3)、位置 (4) と (5) などをペアにします。 各ペアの最大値は、単にそのペアの最初の要素です。 
4. 位置 (0、2、4、\ldots) の重みを答えに追加します。 これにより、他のすべての頂点とは独立して、その頂点の可能な最小寄与が計算されます。 
5. すべての頂点に対してこれを繰り返します。 すべてのサイクル配列内の 2 つの連続するエッジのすべての隣接は、正確に 1 つの頂点で発生するため、これらのローカル寄与を合計すると、グローバル価格のすべての項が正確に 1 回カウントされます。 

重要な不変条件は、すべての有効なサイクル分割がすべての頂点で入射エッジのペアリングを引き起こす一方で、ソートされたペアリングがその頂点に対して可能な最小コストを与えるということです。 独立して選択されたペアは閉じたトレイルとして追跡できるため、有効なサイクル分割に対応します。 したがって、この金額を下回るソリューションは存在せず、正確にその金額を達成するソリューションが存在します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    edges = n * (n - 1) // 2

    incident = [[] for _ in range(n)]

    for _ in range(edges):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        incident[u].append(w)
        incident[v].append(w)

    ans = 0

    for v in range(n):
        incident[v].sort(reverse=True)
        ans += sum(incident[v][i] for i in range(0, n - 1, 2))

    print(ans)

if __name__ == "__main__":
    solve()
```最初のループは、完全なグラフ内のエッジの数である (\frac{n(n-1)}2) 個のエッジを正確に読み取ります。 そのエッジは両方の頂点でローカル ペアリングに参加しているため、各重みは両方のエンドポイントのリストに追加されます。 

すべての頂点について、リストには正確に (n-1) 個の要素が含まれます。 範囲`range(0, n - 1, 2)`訪問インデックス (0,2,4,\ldots,n-3)。 各訪問要素は 1 つの最適なペアの大きい方の要素であるため、これらの値を加算すると、その頂点の最小寄与が得られます。 

ソートは頂点ごとに独立して行われます。 各頂点の入射エッジは最大 (998) なので、これは十分に高速です。 入力自体には既に (\Theta(n^2)) エッジが含まれているため、二次スケールの処理は避けられません。 

明示的なサイクル構築は必要ありません。 この証明は、最適なローカル ペアリングがサイクル配列として同時に実現可能であることを示していますが、答えはそれらの合計価格のみを求めています。 構築を回避すると、時間と実装の複雑さの両方が節約されます。 

Python の整数型は、答えが (2^{31}-1) より大きくなった場合のオーバーフローも回避します。
