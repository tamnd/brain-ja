 ## 解決策
 ## 問題の理解

 元のツリーは頂点 (1) をルートとし、すべての頂点 (i>1) には親 (p_i<i) とエッジの重み (w_i) があります。 これらすべての親値とすべてのエッジの重みを含むマルチセットには (2n-2) 個の要素がありますが、配列がシャッフルされたため、それらの役割は失われます。 

特定の 1 つのツリーを再構築する必要はありません。 頂点 (1) から頂点 (n) までの考えられるすべてのパス長 (k) について、そのパス上の重みの可能な最大の合計が必要です。 そのパス上に正確に (k) 個のエッジを持つことができる有効なツリーがない場合、(k) の答えは (-1) になります。 

重要な問題は、シャッフルされた配列内のすべての数値が親値またはエッジの重みになる可能性があることです。 親として使用される数値には構造上の制限がありますが、重みとして使用される数値にはそのような制限はありません。 解決策は、これら 2 つの役割を分離することで得られます。 

(n\le 10^5) の場合、シャッフルされた配列にはほぼ (2\cdot10^5) 個の要素が含まれます。 1 秒の制限時間により、二次関数は除外され、考えられるツリーや順列の列挙も確実に除外されます。 基本的にすべての入力値を定数または対数の回数だけ処理する必要があります。 (O(n\log n)) の解決策で十分であり、コンテストの公式論説では、その実装に同じ漸近限界を使用しています。 

一見合理的と思われる貪欲な実装が失敗する可能性のあるエッジケースがいくつかあります。 

考慮する```
3
2 2 2 2
```ソート後の最初の値は (2) ですが、頂点 (2) の親は (2) より小さくなければなりません。 どのような配置でも有効なツリーを形成することさえできないため、正しい出力は次のようになります。```
-1 -1
```不注意な解決策は、1 つ (2) を重みとして予約し、別の (2) を (p_2) として使用しようとする可能性があり、(p_2<2) に静かに違反します。 

重複する値も重要です。 のために```
4
1 1 1 1 1 1
```異なる値は 1 つ (1) だけです。 可能な唯一のパスにはエッジが 1 つあり、その重みは (1) です。 正しい出力は次のとおりです```
1 -1 -1
```等しい値を異なる可能なパス頂点として扱うソリューションでは、誤って長いパスが要求される可能性があります。 

それほど明白ではないケースは、より小さい値が繰り返されているにもかかわらず、値 (i) がパスに強制的に追加される場合です。 例えば、```
6
1 1 1 4 4 4 4 4 5 5
```ソート後の 4 番目の値は (4) であるため、頂点 (4) がパス上に強制的に追加されます。 強制的なパス値は (1) と (4) ですが、(5) はオプションのパス値です。 有効な長さは (2) と (3) です。```
-1 10 13 -1 -1
```単純に最小の個別の値を取る単純な戦略では、(4) が必須であるという事実を見落としてしまいます。 

最後に、(k=n-1) は真の境界ケースです。 のために```
4
1 2 3 3 3 3
```パスにはすべての頂点が含まれている必要があるため、可能な長さは (3) のみです。 親値 (1、2、3) を予約した後、残りの 3 つの最大の値はすべて (3) となり、次のようになります。```
-1 -1 9
```ハミルトニアン ルートから (n) までのパスのエッジの数 (n-1) と、そのパス上の頂点の数 (n) の区別は、オフバイ 1 エラーの原因となりやすいです。 

## アプローチ

 ブルートフォース手法では、(2n-2) 個の配列要素のすべてに親の値と重みのシーケンス内の位置を割り当て、結果のツリーが有効かどうかを確認して、そのパス長と重みの合計を記録します。 これは、重複する値を無視する場合でも、((2n-2)!) の配置を考慮することを意味します。 (n=10^5) では、配置の数が非常に多いため、1 つの配置を一定時間で検査すること自体が無意味になります。 (O(n)) の各配置をチェックすると (O(n(2n-2)!)) が得られるため、総当たりはパターンを発見するために使用される小さなインスタンスにのみ役立ちます。 

ブルート フォースが機能するのは、考えられるすべての役割の割り当てを明示的に調査するためです。 これらの割り当てのほとんどすべてが無関係であるため、失敗します。 有益な観察は、親の値が非常に厳格に並べ替えられた特性を持っているということです。 

シャッフルされた配列を次のようにソートします

 [
 a_1\le a_2\le\cdots\le a_{2n-2}。 
】

 有効なツリーの場合、(i\le n-1) ごとに最初の (i) 要素に (i) より大きい値を含めることはできません。 同様に、

 [
 a_i\le i.
 】

 その理由を確認するには、頂点 (2,3,\ldots,i+1) には (i) 個の親の値が必要ですが、それらの親はすべて最大で (i) です。 (a_i>i) の場合、使用可能な値は最大でも (i) 個未満であるため、最初の (i) 頂点がすべて法的な親を受け取ることはできません。 したがって、単一の違反は、有効なツリーが存在しないことを意味します。 大幅な値下げは初めて。 

2番目のより強力な結果があります。 仮定してください

 [
 a_i=i。 
】

 この場合、頂点 (i) は (1) から (n) までのパス上になければなりません。 (i) より小さい値は最大で (i-1) 個あり、頂点 (2,\ldots,i) はすでに正確に (i-1) 個の正当な親値を必要としています。 これらの値は下位の頂点によって完全に消費されるため、(i) より大きいすべての頂点には少なくとも (i) の親があります。 (n) から (1) に戻るパスは、(i) を経由せずに (i) より大きい値から (i) より小さい値にジャンプすることはできません。 したがって、(i) がパス上に強制的に追加されます。 

(c) を (a_i=i) を満たすインデックス (i\in[1,n-1]) の数とする。 これらの (c) 値は、(1) から (n) までのすべての可能なパスに出現する必要があるため、(c) よりも少ないエッジを持つパスは存在できません。 

ここで、配列内に出現するすべての個別の値を考慮します。 パスには同じ頂点を 2 回含めることはできないため、その親の値は異なります。 パスには (k) 個のエッジがあるため、正確に (k) 個の親値、つまり (n) を除くパスの頂点を使用します。 したがって、(k) は配列内の個別の値の数を超えることはできません。 

重要な部分は、これら 2 つの制限の間のすべての (k) が実際に達成可能であるということです。 すべての強制値から始めます。 もう 1 つのパス エッジが必要な場合は、まだ選択されていない最小の個別の値を追加します。 次に、選択した値が並べ替えられ、(1) と (n) の間に配置されてパスが形成されます。 

利用可能な最小値を選択すると機能するのはなぜですか? ソート条件 (a_i\le i) は、パスの外側のすべての頂点をサポートするのに十分な小さな親値を保証します。 より具体的には、パスを修正した後、すべてのパスの親値の出現を 1 つ削除します。 残りの親候補の値と、まだ親が必要な頂点を並べ替えます。 昇順にペアリングします。 親候補がその割り当てられた頂点よりも小さくない場合、パスの頂点と割り当てられていない頂点の最大数がその値に達するまでの数を数えることは、元の並べ替え条件 (a_i\le i) と矛盾します。 これは公式社説で使用された建設的な議論です。 

特定のパスが実現可能になると、その最適な重みは非常に簡単になります。 正確に (k) 個の配列要素がパスの親値として使用されます。 残りの要素はすべて重みにすることができ、重みには上限制限がありません。 したがって、最大パスの重みは、選択された各パス値の 1 つの出現を削除した後に残ったすべての要素の中から最大の (k) 個の要素を取得することによって取得されます。

これでアルゴリズム全体が得られます。 配列をソートして、不可能な値や強制された値を検出します。 次に、オプションのパス値を最小から最大まで追加します。 各加算の後、残りのマルチセット内の (k) 個の最大値の合計が必要になります。 値 (1,\ldots,n-1) に対するフェンウィック ツリーは、残りの出現回数とその合計の両方を維持するため、(O(\log n)) でこのクエリを実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(n(2n-2)!)) | (O(n)) | 遅すぎる |
 | 最適 | (O(n\log n)) | (O(n)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. (2n-2) 値を読み取り、並べ替えます。 並べ替えにより、プレフィックス条件 (a_i\le i) が明らかになります。これは、有効なツリーが存在するかどうかを確認する最も簡単なテストです。 
2. (1) から (n-1) までのすべてのソート位置 (i) をチェックします。 (a_i>i) の場合は、パス長ごとに (-1) を出力して停止します。 有効なツリーなど存在するはずがないので、すべての答えは不可能です。 
3. すべての値の度数表を作成し、すべての配列値のすべての出現を含むフェンウィック ツリーを初期化します。 後で選択した親値を削除し、残っている大きな値をクエリする必要があるため、フェンウィック ツリーには出現回数と合計の両方が保存されます。 
4. ソートされた配列を再度スキャンします。 (a_i=i) 場合は常に、値 (i) を強制としてマークし、フェンウィック ツリーから (i) の出現を 1 つ削除し、現在のパス長 (k) を増やします。 頂点 (i+1) に入るパス エッジの親値として 1 つのコピーが消費されるため、出現箇所を 1 つだけ削除するのは正しいことです。 
5. すべての強制値が処理された後、現在の値 (k) の答えを計算します。 残りのマルチセットには、強制パスの親として使用されなかったすべての値が含まれるため、可能な限り最適なパスの重みは、その (k) 個の最大要素の合計になります。 
6. 値 (x=1,2,\ldots,n-1) を昇順に処理します。 (x) が発生し、まだ強制されていない場合は、(x) の 1 つの発生を削除し、それを新しいパス頂点としてマークし、(k) を増分します。 昇順は、残りの値が依然として有効な親として機能できることを保証する、まさに貪欲な選択です。 
7. このような加算のたびに、(k) 個の最大の残りの値の合計をクエリし、それをこのパス長の答えとして保存します。 実現可能なすべての長さは強制カウントと個別の値の数の間にあるため、他のパス長は発生しません。 
8. この範囲外のすべての回答は (-1) のままにしておきます。 回答配列はこの方法ですでに初期化されているため、別個に構築する必要はありません。 

不変条件は、パス長 (k) を処理した後、フェンウィック ツリーには、(k) 個の選択されたパスの親の値を予約した後も重みとパス外の親に使用できる値のマルチセットが正確に含まれていることです。 選択されたパス自体は、ソートされたプレフィックス条件と貪欲な最小値構造によって実現可能です。 重みには構造的な制約がないため、(k) 最大の残りの値を選択することが最適です。 したがって、保存されているすべての答えは達成可能であり、最大のものでもあります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.cnt = [0] * (n + 1)
        self.s = [0] * (n + 1)

    def add(self, x, dc, ds):
        n = self.n
        cnt = self.cnt
        sm = self.s
        while x <= n:
            cnt[x] += dc
            sm[x] += ds
            x += x & -x

    def sum_smallest(self, k):
        if k <= 0:
            return 0

        idx = 0
        cnt = 0
        sm = 0

        bit = 1 << (self.n.bit_length() - 1)
        while bit:
            nxt = idx + bit
            if nxt <= self.n and cnt + self.cnt[nxt] <= k:
                idx = nxt
                cnt += self.cnt[nxt]
                sm += self.s[nxt]
            bit >>= 1

        if cnt < k:
            value = idx + 1
            sm += (k - cnt) * value

        return sm

    def sum_largest(self, k, total_count, total_sum):
        return total_sum - self.sum_smallest(total_count - k)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    m = 2 * n - 2

    a.sort()

    for i in range(1, n):
        if a[i - 1] > i:
            return " ".join(["-1"] * (n - 1))

    freq = [0] * n
    forced = [False] * n

    bit = Fenwick(n - 1)

    total_sum = 0
    for x in a:
        freq[x] += 1
        total_sum += x
        bit.add(x, 1, x)

    total_count = m

    k = 0

    for i in range(1, n):
        if a[i - 1] == i:
            forced[i] = True
            freq[i] -= 1
            bit.add(i, -1, -i)
            total_count -= 1
            total_sum -= i
            k += 1

    ans = [-1] * (n - 1)

    if k > 0:
        ans[k - 1] = bit.sum_largest(k, total_count, total_sum)

    for x in range(1, n):
        if freq[x] > 0 and not forced[x]:
            freq[x] -= 1
            bit.add(x, -1, -x)
            total_count -= 1
            total_sum -= x
            k += 1

            ans[k - 1] = bit.sum_largest(k, total_count, total_sum)

    return " ".join(map(str, ans))

if __name__ == "__main__":
    sys.stdout.write(solve())
```親の値に関するすべての構造情報がそのプレフィックスによって取得されるため、ソートされた配列が最初に使用されます。 厳密に (n-1) 個の親値があり、(n) 番目の頂点自体が親になることができないため、条件は位置 (1,\ldots,n-1) を通じてのみチェックされます。 

の`freq`配列には、どの個別の値が可能なパス頂点としてまだ利用可能であるかが記録されます。 の`forced`配列は、後の貪欲スキャンが同じ値に達したときに強制値が 2 回選択されるのを防ぎます。 これは、値が何度も出現する場合に重要です。 

フェンウィック ツリーには、すべてのプレフィックスの 2 つの数量、残りの出現数とその合計が格納されます。`sum_smallest(t)`フェンウィック ツリーを介したバイナリ リフティングによって残りの最小要素 (t) の合計を求めます。 目的のプレフィックスが、同じ値が複数出現する値の途中で終了する場合、残りのコピーは最後にまとめて処理されます。 

残りの最大値 (k) の合計は次のように取得されます。 

[
 \text{合計値}-\text{最小値の合計}(m-k)\text{値}。 
】

 これにより、別個の最大次数統計構造が必要なくなります。 

Python の整数には任意の精度があるため、パスの合計には特別なオーバーフロー処理は必要ありません。 可能な最大の合計は (O(n^2)) のみですが、固定整数幅に依存しなくても実装は正しく行われます。 

インデックス変換も意図的です。 数学的配列には 1 からインデックスが付けられますが、Python リストには 0 からインデックスが付けられます。 テスト`a[i - 1] > i`数学的条件 (a_i>i) に正確に対応し、`ans[k - 1]`(k) 個のエッジを含むパスの答えを格納します。

(i\le2) に対する唯一の等価性 (a_i=i) は (a_1=1) であるため、実現可能な最小パス長は (1) です。 

| ステップ | 選択されたパス値 | 残りのマルチセット | (k) | 最高額 |

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(n\log n)) | 並べ替えには (O(n\log n)) かかり、フェンウィックの更新とクエリは (O(n)) 回あり、それぞれに (O(\log n)) かかります。 |
 | スペース | (O(n)) | 並べ替えられた配列、頻度配列、回答配列、およびフェンウィック ツリーはすべて (O(n)) メモリを使用します。 |

 入力には (2n-2=O(n)) 個の数値が含まれるため、アルゴリズムは並べ替えとフェンウィック操作とは別に線形量のデータを処理します。 (n\le10^5) の場合、これは意図した (O(n\log n)) 範囲と 256 MB のメモリ制限内に収まります。 公式コンテスト ソリューションでは、(O(n\log n)) 個の時間構造と (O(n)) 個の補助データ構造も使用します。

    data = list(map(int, inp.split()))
    it = iter(data)
    n = next(it)
    a = [next(it) for _ in range(2 * n - 2)]

    a.sort()

    for i in range(1, n):
        if a[i - 1] > i:
            return " ".join(["-1"] * (n - 1))

    freq = [0] * n
    forced = [False] * n
    bit = Fenwick(n - 1)

    total_count = len(a)
    total_sum = sum(a)

    for x in a:
        freq[x] += 1
        bit.add(x, 1, x)

    k = 0

    for i in range(1, n):
        if a[i - 1] == i:
            forced[i] = True
            freq[i] -= 1
            bit.add(i, -1, -i)
            total_count -= 1
            total_sum -= i
            k += 1

    ans = [-1] * (n - 1)

    if k:
        small = bit.sum_smallest(total_count - k)
        ans[k - 1] = total_sum - small

    for x in range(1, n):
        if freq[x] and not forced[x]:
            freq[x] -= 1
            bit.add(x, -1, -x)
            total_count -= 1
            total_sum -= x
            k += 1

            small = bit.sum_smallest(total_count - k)
            ans[k - 1] = total_sum - small

    return " ".join(map(str, ans))

def run(inp: str) -> str:
    return solution(inp)

 ## 特殊なケース

 ### 有効なツリーがありません

 のために```
3
2 2 2 2
```ソートされた配列は (a_1=2) で始まります。 頂点 (2) の親は (1) でなければならないため、(2) が出現してもその役割を果たすことはできません。 有効性スキャンは (a_1>1) を即座に検出し、返します。`-1 -1`。 フェンウィック ツリーは決してクエリされないため、無効なインスタンスが誤って妥当なパス合計を生成することはありません。 

### 繰り返される値

 のために```
4
1 1 1 1 1 1
```唯一の明確な値は (1) です。 最初にソートされた位置は (a_1=1) を満たすため、1 が唯一の可能なパス エッジの必須の親値になります。 残りの 7 つのコピーは重みやその他の親に使用できますが、パス上に配置できる 2 番目の個別の頂点値はありません。 アルゴリズムは、片エッジの答えを (1) として記録し、他の位置は (-1) のままにします。 

### パス値を先頭から強制的に離します

 のために```
6
1 1 1 4 4 4 4 4 5 5
```ソートされた接頭辞は次の条件を満たします

 [
 a_1=1、\qquad a_2=1、\qquad a_3=1、\qquad a_4=4。 
】

 したがって、(1) と (4) がすべてのパスに強制的に適用されます。 初期のパス長は (2) です。 1 つと 1 つを削除すると、最大値のうち 2 つと 4 つが残るため、残った 2 つの最大値の合計は (10) になります。 これにより、(k=2) の答えが得られます。 

次の未使用の個別値は (5) です。 1 つ (5) を削除すると、パスの長さは (3) になり、残りの 3 つの最大の値は (5,4,4) となり、その合計は (13) になります。 これ以上明確な値はないため、(k=4) と (k=5) は依然として不可能です。 最終的な出力は次のとおりです`-1 10 13 -1 -1`。 

### 最大パス長

 のために```
4
1 2 3 3 3 3
```等式 (a_1=1)、(a_2=2)、および (a_3=3) は、3 つの親値すべて (1、2、3) をパスに強制します。 したがって、(k=3=n-1) が唯一の実現可能な長さです。 (1、2、3) のそれぞれの出現を 1 つ削除すると、パスの重みとして使用できる値の中に (3) の 3 つのコピーが残るため、答えは (9) になります。 アルゴリズムはそれを次の場所に保存します`ans[2]`これは (k=3) に対応し、パスの (n) 個の頂点を (n) 個のエッジとして扱うというよくある間違いを回避します。
