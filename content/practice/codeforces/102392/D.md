 ## 解決策
 ## 問題の理解

 入力長を (L=2n) とします。 元の巡回順序が破壊され、記号のみが残っているため、入力は小文字のマルチセットです。 長さ (n) の (L) 個の循環部分文字列がすべて異なるように、これらの文字を循環に再配置する必要があります。 部分文字列が印刷文字列の末尾をまたぐ場合があるため、最後の文字と最初の文字は同じサイクルに属します。 公式声明では、区別すべき循環ウィンドウが正確に (2n) 存在することが確認されています。 

重要な問題は、文字列に最大 (10^6) 文字を含めることができることです。 考えられるすべての順列を検査するアルゴリズムは完全に不可能であり、すべての (2n) ウィンドウを文字ごとに明示的に比較するアルゴリズムであっても、何度も繰り返すとコストが高くなりすぎます。 アルファベットには 26 文字しかありませんが、これはここでは便利な小さなパラメータです。 1 回のパスですべての文字を数えて、それらの 26 の周波数から構築を行うことができます。 

一見合理的に見える構築が失敗する小さなケースがいくつかあります。 のために`aa`、長さは4ですか？ いいえ、ここでは (L=2)、必要なウィンドウの長さは 1 です。 両方の循環ウィンドウは同じ文字であり、答えが得られます。`NO`。 のために`aaaa`、（Ｌ＝４）であり、必要なウィンドウの長さは２である。 すべてのアレンジメントには 2 つの連続したものが含まれます`a`文字、そして実際には 2 文字のウィンドウ`aa`複数回発生するため、答えは次のようになります。`NO`。 

境界の場合`aabb`は異なります。 サイクル`aabb`窓がある`aa`、`ab`、`bb`、 そして`ba`したがって、4 つはすべて異なり、答えは次のようになります。`YES`。 「文字が繰り返されると構築が不可能になる」などの不用意なルールでは、この有効なケースが拒否されてしまいます。 

もう一つのデリケートなケースは、`aaaabb`、長さは 6、必要なウィンドウの長さは 3 です。 のコピーが 4 つあります`a`そして2部のコピー`b`。 どのような配置でも長さ 3 のウィンドウの繰り返しを避けることはできないため、答えは次のようになります。`NO`。 対照的に、`aaaabc`4つあります`a`文字と残りの 2 つの異なる文字。 アレンジメント`aabaac`窓がある`aab`、`aba`、`baa`、`aac`、`aca`、 そして`caa`、すべて異なるため、この境界ケースは受け入れられる必要があります。 

## アプローチ

 直接的なアプローチでは、(L) 個のシンボルのすべての順列を列挙し、その巡回長 (n) ウィンドウが区別できるかどうかをテストします。 列挙中に等しい記号を別個のものとして扱う場合、候補は (L!) 個あります。 各候補には (L) 個の巡回ウィンドウがあり、各ウィンドウの文字を文字コスト (n) で比較すると、(O(L! \cdot L \cdot n)=O(L!L^2)) の文字演算が得られます。 (L=10^6) では、候補を生成することさえ考慮できません。 等しい文字を区別できないものとして扱うと候補の数は減りますが、最悪の場合でも階乗になります。 

有益な観察は、実際には取り決めを探す必要がないということです。 答えは、最も一般的な文字の頻度によってほぼ完全に決まります。 その周波数を (m) とします。 (m\leq n=L/2) の場合、文字列全体をソートするだけで十分です。 (m) が (n) より大きくなると、その文字の大きなブロックを意図的に分割する必要があります。 可能な周波数範囲はわずかで、それぞれが直接構造を持っています。 この周波数ベースの特性評価は、受け入れられているソリューションの背後にある中心的な考え方です。 コンテストの問題に対する公開された解決策は、例外的な (m=L-2) 境界を含む、まさにこれらのケースを使用しています。 

(m\leq n) の場合にソートされた構造が機能する理由は、1 つの文字の実行がサイクルの半分以上を占めることができないためです。 ソートされたサイクルでは、異なる位置から始まる各ウィンドウは、文字実行間で異なる遷移パターンを持ちます。 長さ (n) のウィンドウを繰り返すと、2 つの開始位置にウィンドウ全体で同じラン境界が表示されるようになり、(n) よりも長い文字ランが必要になります。 周波数限界によってそれが排除されます。 

(m>n) の場合、ソートすると長すぎるランが作成されるため、支配的な文字を別の文字の周囲に分割します。 (m\leq L-3) の場合、支配的な文字の (n-1) 個のコピーを取り、その後ろに別の 1 文字を置き、その後に残りの支配的なコピーを置き、残りのすべての文字を追加します。 意図的に配置された 1 つのセパレーターにより、サイクリック ウィンドウが衝突する正確な場所でロングランが中断されます。 

ケース (m=L-2) は、可能な限り厳しい境界です。 ドミナント文字の外側に残るシンボルは 2 つだけです。 それらが異なる場合は、(n-1) 個の優勢文字、最初の少数文字、別の (n-1) 個の優勢文字、および 2 番目の少数文字を配置すると、有効なサイクルが得られます。 2 つの少数記号が等しい場合、4 を除くすべての長さについて構築は不可能です。 長さ 4 の場合、`aabb`有効です。 

最後に、(m>L-2) の場合、他の文字が占める位置はせいぜい 1 つまたは 2 つです。 これにより、同じドミナント文字で構成される長さ (n) のウィンドウが多すぎるため、ウィンドウの繰り返しが避けられなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(L!L^2)) | (O(L)) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. (L) を入力長とし、26 文字すべての出現をカウントします。 最大頻度 (m) を持つ文字 (a) を見つけます。 シャッフル後は元の位置は意味を持たないため、頻度分布のみが必要です。 
2. (L=2) の場合、2 つの文字が異なる場合を正確に受け入れます。 各巡回ウィンドウの長さは 1 なので、2 つの位置には異なる文字が含まれている必要があります。 
3. (L\geq3) の場合、(m>L-2) の場合は直ちに拒否します。 長い (a) ランを十分に分割するには非 (a) 文字が少なすぎるため、長さ (n) の循環ウィンドウを繰り返す必要があります。 
4. (m=L-2) の場合、(a) ではない 2 つの文字を検査します。 それらが同じである場合、そうでない場合は拒否します (L=4)。 (L=4) の場合、マルチセットは正確に次のようになります。`{a,a,b,b}`、 そして`aabb`動作します。 
5. (m=L-2) と 2 つの少数文字が異なる場合、次のように構成します。 
(a^{n-1}ba^{n-1}c)。 
各少数文字は、長いブロックを区切ります。`a`文字、および 2 つの区切り文字が異なるため、2 つの境界の周囲の循環ウィンドウが一致することはありません。 
6. (n<m<L-2) の場合、任意の文字 (b\neq a) を選択し、(a) のコピーを (n-1) 個、次に (b) を 1 個、次に (a) の残りのコピーをすべて配置し、最後に (a) 以外の残りのすべての文字を配置します。 結果の形式は次のとおりです
 (a^{n-1}ba^{m-n+1}R)、
 ここで、(R) には残りの非 (a) 文字がすべて含まれます。 

最初のブロックには、ドミナント文字の正確に (n-1) 個のコピーが含まれるため、長さ (n) のウィンドウがその中に完全に残ることはできません。 挿入された (b) は 2 つの主要なブロックを分離し、他のすべての非 (a) 文字は最後のブロックに延期されます。 これにより、すべての巡回ウィンドウにセパレータ構造に対する一意の位置が与えられます。 
7. (m\leq n) の場合、文字をソートされた順序で出力します。 最大ランの長さは最大 (n) であり、ソートされた循環配列は開始位置ごとに異なるラン境界パターンを持ちます。 したがって、その（n）長のウィンドウはペアごとに異なります。 

### なぜ効果があるのか

 すべての構築の背後にある不変条件は、2 つの等しい循環ウィンドウが、まったく同じ順序でまったく同じ文字列のシーケンスに遭遇する必要があるということです。 ソートされた場合、繰り返しウィンドウには (m\leq n) と矛盾して (n) よりも長い実行が必要になります。 ヘビー キャラクタの構築では、すべての長さ (n) ウィンドウが挿入されたセパレータおよび残りの非ドミナント ブロックと固有の関係を持つように、ドミナント キャラクタが分割されます。 極端な場合 (m=L-2)、2 つの境界を区別するには 2 つの異なる少数文字が必要です。 (m>L-2) の場合、オールドミナント ウィンドウの繰り返しを防ぐのに十分なセパレータがありません。これは不可能であることがわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_string(s: str):
    L = len(s)

    cnt = [0] * 26
    for ch in s:
        cnt[ord(ch) - 97] += 1

    if L == 2:
        if cnt[0] == 1 and cnt[1] == 1:
            return "YES", "ab"
        # More generally, any two different letters work.
        if max(cnt) == 1:
            letters = [chr(i + 97) for i, x in enumerate(cnt) if x]
            return "YES", "".join(letters)
        return "NO", ""

    mx = max(cnt)
    w = cnt.index(mx)
    a = chr(w + 97)

    if mx > L - 2:
        return "NO", ""

    others = [i for i in range(26) if cnt[i] and i != w]

    if mx == L - 2:
        if len(others) == 1:
            if L == 4:
                b = chr(others[0] + 97)
                return "YES", a * mx + b * cnt[others[0]]
            return "NO", ""

        b = chr(others[0] + 97)
        c = chr(others[1] + 97)
        half = L // 2
        ans = a * (half - 1) + b + a * (half - 1) + c
        return "YES", ans

    if mx > L // 2:
        b_idx = others[0]
        b = chr(b_idx + 97)

        first_a = L // 2 - 1
        remaining_a = mx - first_a

        cnt[b_idx] -= 1

        tail = []
        for i in range(26):
            if cnt[i]:
                tail.append(chr(i + 97) * cnt[i])

        ans = a * first_a + b + a * remaining_a + "".join(tail)
        return "YES", ans

    # mx <= L/2
    ans = []
    for i in range(26):
        if cnt[i]:
            ans.append(chr(i + 97) * cnt[i])

    return "YES", "".join(ans)

def main():
    s = input().strip()
    ok, ans = solve_string(s)

    if ok == "NO":
        print("NO")
    else:
        print("YES")
        print(ans)

if __name__ == "__main__":
    main()
```最初の部分では、1 回のリニア スキャン内の文字をカウントします。 可能な文字は 26 個しかないため、最大頻度を見つけて他の文字を収集するには、スキャン後に継続的な追加作業が必要になります。 

一般的な (L-2) 境界規則が (L\geq3) に対して記述されているため、(L=2) の場合は個別に処理されます。 位置が 2 つある場合、必要なウィンドウの長さは 1 であるため、2 つの文字が等しいかどうかで答えがすぐに決まります。 

の`mx > L - 2`check は全体的に不可能な条件です。 後の分岐では区切り文字が必要なときに少なくとも 2 つの非優勢な位置が存在すると想定されるため、これは構築分岐の前に発生する必要があります。 

いつ`mx == L - 2`、残りの文字数はちょうど 2 です。`others`したがって、残りの両方の位置に同じ文字が含まれることを意味する 1 つの要素、またはそれらが異なることを意味する 2 つの要素のいずれかになります。 長さ 4 の例外はまさに有効です`aabb`場合。 

のために`mx > L // 2`、最初の支配的なブロックは`L // 2 - 1`文字。 別の文字の 1 つのコピーがセパレータとして削除され、残りの主要なコピーが 2 番目の主要なブロックを形成します。 次に、残りの頻度配列を使用して、すべての未処理の文字が追加されます。 末尾を作成する前にセパレータ カウントをデクリメントすることが重要です。そうしないと、1 つのコピーが 2 回印刷されてしまいます。 

最後の分岐は単にソートされた構造です。 Python 文字列の乗算は、大きな繰り返しブロックを直接構築し、(10^6) の入力サイズが十分に大きいため、個々の文字を繰り返し追加すると不必要にコストがかかるため、ここでは Python 文字列乗算が役立ちます。 

部分文字列のハッシュや明示的なウィンドウ比較は必要ありません。 構築自体が必要なプロパティを与えるため、実装では入力マルチセットを再現するだけで済みます。

## テストケース```
# helper: run solution on input string, return output string
def run(inp: str) -> str:
    s = inp.strip()
    ok, ans = solve_string(s)
    if ok == "NO":
        return "NO\n"
    return "YES\n" + ans + "\n"

def valid_cycle(original: str, output: str) -> bool:
    lines = output.strip().splitlines()
    if lines[0] == "NO":
        return False

    ans = lines[1]
    if len(ans) != len(original):
        return False

    if sorted(ans) != sorted(original):
        return False

    L = len(ans)
    n = L // 2

    windows = set()
    for i in range(L):
        w = "".join(ans[(i + j) % L] for j in range(n))
        if w in windows:
            return False
        windows.add(w)

    return len(windows) == L

# Provided sample 1.
out = run("cbbabcacbb")
assert valid_cycle("cbbabcacbb", out), "sample 1"

# Provided sample 2.
assert run("aa") == "NO\n", "sample 2"

# Provided sample 3.
out = run("afedbc")
assert valid_cycle("afedbc", out), "sample 3"

# Minimum-size input.
assert run("ab") == "YES\nab\n", "minimum size"

# All characters equal.
assert run("aaaa") == "NO\n", "all equal"

# L = 6, max frequency = L - 2, with two different minority characters.
out = run("aaaabc")
assert out == "YES\naabaac\n", "two different minority characters"

# Heavy majority, but not at the impossible boundary.
out = run("aaaaabbc")
assert out == "YES\naaabaabc\n", "heavy majority construction"

# Maximum-size input, max frequency exactly L/2.
large = "a" * 500_000 + "b" * 500_000
out = run(large)
assert out.startswith("YES\n"), "maximum size"
assert out[4:].strip() == large, "maximum size sorted construction"

 ## 特殊なケース

 のために`aa`、アルゴリズムは長さ 2 の専用分岐に入ります。 最大周波数は 2 であるため、2 つの必要な長さ (1 つのウィンドウ) は両方とも`a`。 印刷します`NO`、唯一可能な結果と一致します。 

のために`aaaa`、長さは 4 であり、(m=4>L-2=2) です。 不可能チェックがすぐに実行されます。 非のものが十分ではありません`a`文字を使用してサイクルを長さ 2 の別個のウィンドウに分割するため、後で構築が試行されることはありません。 

のために`aabb`、長さは 4 で、(m=2=L/2=L-2) になります。 2 つの少数の位置には同じ文字が含まれているため、通常は (L-2) の場合は不可能になります。 特別な長さ 4 の例外はそれを受け入れて生成します。`aabb`。 その循環ウィンドウは次のとおりです。`aa`、`ab`、`bb`、 そして`ba`。 

のために`aaaabb`、長さは 6 および (m=4=L-2) ですが、両方の少数位置には次の値が含まれます。`b`。 長さが 4 ではないため、アルゴリズムは次のように出力します。`NO`。 問題は、ソートされた配置が失敗することだけではありません。 どのような配置でも、6 つの異なる長さ 3 の循環ウィンドウを作成するには、分離文字が不十分です。 

のために`aaaabc`の場合、支配的な文字は 4 回出現し、正確に (L-2) になりますが、残りの 2 つの文字は異なります。 構造は (a^{2}ba^{2}c) であり、次のようになります。`aabaac`。 その 6 つの周期的な長さ 3 のウィンドウは次のとおりです。`aab`、`aba`、`baa`、`aac`、`aca`、 そして`caa`したがって、すべてのウィンドウはユニークです。 

のために`aaaaabbc`、長さ 8 の文字列内にドミナント文字が 5 回出現します。 ここでは (n=4) および (n<m<L-2) であるため、重多数構成が使用されます。 それは創造します`aaa`+`b`+`aa`+`bc`、つまり`aaabaabc`。 主要な文字はセパレータを中心に分割され、並べ替えられた配置でウィンドウが繰り返されるのを防ぎます。 

最大サイズ50万の場合`a`文字数と 500,000`b`文字の場合、最大頻度はちょうど (L/2) です。 アルゴリズムはソートされたブランチに分類され、同じソートされた文字列を出力します。 大きな入力は線形周波数カウントと直接文字列構築によって処理されるため、そのサイズによって漸近的な動作が変化することはありません。
