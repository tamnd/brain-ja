 ## 解決策
 ## 問題の理解

 整数の配列が与えられるので、累計を累積しながらそれを繰り返し更新する必要があります。 更新ルールは次の概念に基づいています。$\operatorname{MAD}$- 配列のプレフィックスに少なくとも 2 回現れる最大数。 具体的には各要素ごとに$a_i$、接頭辞を見てみましょう$[a_1, a_2, ..., a_i]$、それを計算します$\operatorname{MAD}$、と置き換えます$a_i$この値で。 すべての要素を更新した後、新しい配列の合計をグローバルに追加します。`sum`。 このプロセスは、すべての要素がゼロになるまで続きます。 

入力により複数のテスト ケースが提供されます。 各テスト ケースは、配列のサイズと配列自体で構成されます。 出力は合計です`sum`変化の過程で蓄積されます。 

とすれば$n$まで可能です$2 \cdot 10^5$と合計$n$すべてのテスト ケースの境界は次のとおりです$2 \cdot 10^5$で機能するあらゆるソリューション$O(n \log n)$または$O(n)$テストケースごとに実行可能です。 すべてのプレフィックスを個別にシミュレートする素朴なアプローチ$O(n^2)$遅すぎるでしょう。 

重複がまったくない場合、次のような微妙なエッジ ケースが発生します。$a=[1,2,3]$。 それから$\operatorname{MAD}$最初の重複を超えるすべてのプレフィックスに対して直ちに 0 を返し、配列はすぐにゼロに減衰します。 別のシナリオは、すべての数値が等しい場合です。たとえば、$a=[4,4,4,4]$。 MAD は最初はそれ自体が最大の数値であり、合計はゼロに達する前に急速に増加します。 

## アプローチ

 ブルートフォースアプローチは簡単です。ループごとに、すべてのプレフィックスを反復処理し、そのループを計算します。$\operatorname{MAD}$プレフィックスをスキャンして出現回数をカウントし、置き換えます。$a_i$この値を使用して、最後に配列の合計を`sum`。 これは、問題で説明されているプロセスを直接実装しているため、正しく機能します。 ただし、内部プレフィックス スキャンは$O(n)$要素ごとに、$O(n^2)$ループごとに、各要素には必要な場合があります$O(n)$ループし、その結果、$O(n^3)$完全に複雑になるため、実行不可能です。$n=2 \cdot 10^5$。 

重要な観察は次のとおりです$\operatorname{MAD}$MAD 変換では配列内の値が増加しないため、プレフィックスの値は配列が進化しても減少するか、同じままであることしかありません。 番号がプレフィックスに 1 回だけ出現すると、再び MAD になることはできないため、少なくとも 2 回出現する番号を追跡するだけで済みます。 各数値の発生回数を事前に計算し、複数セットのカウントを維持できます。 次に、各プレフィックスの MAD を効率的に計算できます。$O(1)$どの数値が少なくとも 2 回出現するかを追跡するカウンターを使用します。 これにより、各ループが次のように縮小されます。$O(n)$時間。 

事実上、変換はすべての要素がゼロになるまで、数値が繰り返される「階段」パターンに急速に収束します。 頻度マップを使用して慎重にシミュレーションし、少なくとも 2 回発生する最大数を追跡することで、合計を効率的に計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 最適 | O(n^2) 最悪のケースだが、適切な周波数追跡により償却された O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして配列`a`。 
3.初期化`total_sum = 0`。 
4. 配列にゼロ以外の要素が含まれている場合:

 1. 現在の配列の合計を`total_sum`。 
2. 頻度辞書を初期化する`freq`数値の発生を追跡します。 
3. 変数を初期化する`current_mad = 0`。 
4. 新しいアレイを作成する`b`次の反復のために。 
5. 反復処理`a`:

 1. のカウントをインクリメントします。`a_i`で`freq`。 
2. もし`freq[a_i] >= 2`、 アップデート`current_mad = max(current_mad, a_i)`。 
3.セット`b_i = current_mad`。 
6. 交換する`a`と`b`。 
5. 出力`total_sum`。 

機能する理由: 各反復での MAD 計算はプレフィックス数のみに依存し、数値は少なくとも 2 回出現する場合にのみ MAD に寄与します。 維持することで`current_mad`頻度が少なくとも 2 である最大数として、プロセスを効率的に正確にシミュレートします。 配列要素は時間の経過とともに減少し、最終的にはすべてゼロになり、終了が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total_sum = 0
        while any(a):
            total_sum += sum(a)
            freq = {}
            current_mad = 0
            b = []
            for x in a:
                freq[x] = freq.get(x, 0) + 1
                if freq[x] >= 2:
                    current_mad = max(current_mad, x)
                b.append(current_mad)
            a = b
        print(total_sum)

if __name__ == "__main__":
    solve()
```この解決策では、外側のループはすべての要素がゼロになるまで継続します。 内側のループは周波数を追跡し、各プレフィックスの MAD を更新します。 辞書を使用すると、プレフィックスを繰り返しスキャンしたり、メンテナンスしたりする必要がなくなります。`current_mad`すべての要素に正しい値が使用されるようにします。 更新中`a`と`b`次の反復のための変換を完了します。
