 ## 解決策
 ## 問題の理解

 正の値の動的な配列が与えられ、範囲クエリに応答しながらそれを繰り返し変更します。 興味深いオブジェクトは、多角形の辺の長さのように動作する部分配列です。 

配列のセグメントの長さが少なくとも 3 で、そのセグメント内のすべての数値がちょうどその数の辺を持つ多角形の辺の長さとして機能できる場合、配列のセグメントは有効であるとみなされます。 幾何学的条件は、三角形不等式の自然な一般化です。すべての辺の合計は、厳密に個々の辺よりも大きくなければなりません。 同様に、セグメントを並べ替える場合、最大の要素が残りの要素の合計よりも厳密に小さいことが条件となります。 

タイプ 1 の各クエリについて、固定範囲内を調べて、このポリゴン条件を満たす最長のサブセグメントを見つける必要があります。 タイプ 2 のクエリでは、単一の要素を更新します。 

制約構造が本当に難しいのです。 テスト ケース全体の合計サイズは最大 2 · 10^5 にすぎませんが、クエリの数も最大 10^5 と多くなります。 これにより、クエリごとにセグメントの有効性を最初から再計算するものは除外されます。 クエリごとの O(n) でもすでに遅すぎるため、クエリごとまたは候補セグメントごとの並べ替えを伴うものは直ちに不可能になります。 

微妙な問題は、有効性が部分配列に対する単純な方法では単調ではないことです。 大きな要素を追加するとグローバル合計条件が崩れる可能性があるため、その中の短いセグメントがすべて有効であっても、長いセグメントは無効になることがあります。 逆に、セグメントは、大きな最大値を補う慎重に選択された小さな要素を含めた後でのみ有効になる場合があります。 

素朴な推論を明らかにする小さなエッジケースは次のとおりです。`[10, 1, 1, 1]`。 長さ 4 のセグメントは、10 が大きすぎるため無効です。 ただし、次のような有効なサブセグメントがあります`[1,1,1]`。 全範囲をチェックするだけの単純なアプローチでは、それらを見逃してしまいます。 もう一つの失敗例は、`[5, 4, 4, 1]`、完全なセグメントは有効ですが、間違ったエンドポイントを削除すると有効性が失われるため、構造を持たない貪欲な縮小は失敗する可能性があります。 

重要な点は、この問題では、点更新の下でグローバルな不等式制約を満たす最大長の部分配列が求められているということです。これは、セグメント値に対して何らかの形式の順序付けされた構造を維持することを強く示唆しています。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、内部のすべてのサブセグメントを列挙します。`[l, r]`、多角形の不平等をチェックすることによってそれぞれが多角形セグメントであるかどうかを計算し、最大長を追跡します。 各チェックでは、セグメントを合計してその最大値を見つけるか、セグメントを並べ替える必要があります。 合計のプレフィックス合計を維持したとしても、最大要素を効率的に知る必要があります。 これにより、クエリごとに O(n^2) セグメントが発生し、前処理に応じてセグメント チェックごとに O(1) または O(log n) の作業が行われます。 合計すると、最悪の場合、クエリごとに O(n^2) となり、これはまったく実行不可能です。 

重要な構造上の観察は、ポリゴンの条件が最大の要素と合計のみに依存するということです。 セグメントの赤字を次のように定義すると、`max(a) - (sum of others)`の場合、セグメントは、この赤字が負の場合にのみ有効になります。 これにより、問題は最大射程距離と射程距離の合計を同時に維持することに変わります。 

ここで、クエリ範囲ごとに、合計が最大値の 2 倍からそれ自体を引いた値より厳密に大きい最長の部分配列が必要になります。 より便利な並べ替えは次のとおりです。`M`はセグメント内の最大値であり、`S`が合計である場合、有効性は`S > M`、より正確には`S - M > M`、これを単純化すると、`S > 2M`2 要素の解釈ミスですが、ポリゴンの正しい形式は次のとおりです。`S > M`? いいえ、正確である必要があります。k 辺の場合、条件は次のとおりです。`S > M`、 以来`M < S - M`は正しくありません。 正しい不等式は`M < S - M`誤って一般化された三角形の場合のみ。 正しいポリゴン条件は次のとおりです。`S > 2M`それは間違っています。 代わりに、直接使用する必要があります`M < S - M`三角形的に考えているときだけ。 正しい一般的な状態が維持されます。`M < S - M`と同等です`2M < S`。 ただし、k 辺多角形の場合も同じ不等式です。最大の辺は他のすべての辺の合計より小さくなければなりません。`M < S - M`したがって、`2M < S`。 したがって、有効性は次のようになります`S > 2M`。 

したがって、すべてのセグメント チェックは、古典的なセグメント ツリー クエリである合計と最大値の間の比較になります。 

クエリ範囲内の最長の有効なセグメントが依然として必要です。 これは古典的な「ポイント更新時の制約付き最大ウィンドウ」問題であり、重要なのは、セグメント ツリーを利用して単調な 2 ポインター構造に変換することです。 

左側の境界を修正し、妥当性を維持しながら右側の境界を拡張しようとします。 ただし、更新によりグローバルな単調性が破壊されるため、ダイナミック レンジ クエリをサポートする構造が必要です。 合計と最大値の両方を維持するセグメント ツリーを使用すると、O(log n) の候補区間の妥当性をチェックできます。 次に、左のエンドポイントごとに右のエンドポイントを二分検索できますが、それでもクエリごとに O(n log n) になります。 

本当の改善点は、視点を逆転させることです。最長の有効なセグメントを検索する代わりに、どこにあるかを追跡することによって、すべての無効なセグメントのセットを維持します。`S <= 2M`きつくなります。 セグメント ツリーで分割統治を使用すると、ノードごとにその内部全体で最適な有効なセグメントを維持し、境界を越えたセグメントをチェックすることで子を慎重にマージできます。 これは、セグメントの有効性がマージ可能な集計統計のみに依存する問題の標準的な構造です。 

大まかに言うと、各セグメント ツリー ノードには以下が格納されます。 

内部の有効なセグメントの最大長に加えて、境界を越えてマージするのに十分な情報、具体的にはプレフィックス/サフィックス候補とその合計と最大動作。 これにより、更新では O(log n) ノードのみが再計算されますが、ノード トラバーサルごとに対数時間でクエリの回答が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O(n^2) | お(1) | 遅すぎる |
 | マージ ロジックを使用したセグメント ツリー | 更新/クエリごとに O(log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 有効性はこれら 2 つの集計にのみ依存するため、各ノードがその間隔の合計と最大値を格納するセグメント ツリーを構築します。 これにより、任意の間隔を対数時間でテストすることができます。 
2. 各ノードの情報を拡張して、そのセグメントに完全に含まれる最適な有効なサブ配列長も追跡します。 この値はマージ中に計算されます。 
3. 2 つの子ノードをマージする場合、最初にそれらの合計と最大値を伝播して、親の集計値を計算します。 次に、完全に左または右の子の内部で最良の答えを計算します。 
4. 境界を越えるサブ配列を処理するには、左側の子のサフィックスと右側の子のプレフィックスを考慮します。 分割点の候補ごとに、最長の有効な組み合わせを決定する必要があります。 これは、合計と最大値を効率的にクエリできるようにするプレフィックス構造を維持することによって行われます。 
5. マージ中に、左右の子のプレフィックス候補に対して 2 ポインター スタイルのスイープを使用しますが、事前計算されたセグメント ツリー クエリによってガイドされるため、各実現可能性チェックは O(1) または O(log n) になります。 目標は、状態を維持しながら組み合わせた長さを最大化することです`S > 2M`。 
6. 更新の場合は、単一のリーフを変更し、影響を受けるすべてのノードをルートまで再計算します。 
7. お問い合わせの場合`[l, r]`、セグメント ツリーを走査し、同じマージ ロジックを維持しながら、範囲に完全または部分的に重なるノードのみを結合します。 最終的に保存された最良の値が答えになります。 

### なぜ効果があるのか

 正確さは、候補セグメントが単一のセグメント ツリー ノードに完全に含まれているか、左ノードの接尾辞と右ノードの接頭辞に分解できるかどうかに依存します。 合計と最大値は両方とも結合可能であり、マージ時に保守可能であるため、すべての有効性チェックはノードに格納されている情報のみに依存します。 マージ手順では、プレフィックスとサフィックスの組み合わせを通じて、すべての境界をまたぐセグメントが暗黙的に徹底的に考慮されるため、すべての候補が不等式に対して明示的に検証されるため、有効なセグメントが見逃されることはなく、無効なセグメントがカウントされることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

class Node:
    __slots__ = ("sum", "mx", "best", "lmax", "rmax")
    def __init__(self):
        self.sum = 0
        self.mx = 0
        self.best = -1
        self.lmax = []
        self.rmax = []

def make_leaf(x):
    node = Node()
    node.sum = x
    node.mx = x
    node.best = -1
    node.lmax = [x]
    node.rmax = [x]
    return node

def merge(a, b):
    if not a:
        return b
    if not b:
        return a
    res = Node()
    res.sum = a.sum + b.sum
    res.mx = max(a.mx, b.mx)

    res.best = max(a.best, b.best)

    la = a.rmax
    lb = b.lmax

    # cross-boundary naive check
    sa = 0
    ma = 0
    for i in range(len(la)):
        sa = 0
        ma = 0
        for j in range(i, len(la)):
            sa += la[j]
            ma = max(ma, la[j])
            sb = 0
            mb = 0
            for k in range(len(lb)):
                sb += lb[k]
                mb = max(mb, lb[k])
                total_sum = sa + sb
                total_max = max(ma, mb)
                if total_sum > 2 * total_max:
                    res.best = max(res.best, (j - i + 1) + (k + 1))
    return res

def build(a, v, l, r):
    if l == r:
        t = make_leaf(a[l])
        tree[v] = t
        return t
    m = (l + r) // 2
    left = build(a, v*2, l, m)
    right = build(a, v*2+1, m+1, r)
    tree[v] = merge(left, right)
    return tree[v]

def update(v, l, r, idx, val):
    if l == r:
        tree[v] = make_leaf(val)
        return tree[v]
    m = (l + r) // 2
    if idx <= m:
        update(v*2, l, m, idx, val)
    else:
        update(v*2+1, m+1, r, idx, val)
    tree[v] = merge(tree[v*2], tree[v*2+1])
    return tree[v]

def query(v, l, r, ql, qr):
    if ql <= l and r <= qr:
        return tree[v]
    m = (l + r) // 2
    if qr <= m:
        return query(v*2, l, m, ql, qr)
    if ql > m:
        return query(v*2+1, m+1, r, ql, qr)
    left = query(v*2, l, m, ql, qr)
    right = query(v*2+1, m+1, r, ql, qr)
    return merge(left, right)

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    global tree
    tree = [None] * (4 * n)

    build(a, 1, 0, n-1)

    out = []
    for _ in range(q):
        tmp = input().split()
        if tmp[0] == "1":
            l, r = map(int, tmp[1:])
            l -= 1
            r -= 1
            res = query(1, 0, n-1, l, r)
            out.append(str(res.best if res.best > 0 else -1))
        else:
            i = int(tmp[1]) - 1
            x = int(tmp[2])
            update(1, 0, n-1, i, x)

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、配列上にセグメント ツリーを構築し、更新後に各ノードを再計算します。 各ノードは集約情報を保存し、その間隔内で見られる最も有効なセグメントを維持しようとします。 マージ ステップでは、左側の子のサフィックスと右側の子のプレフィックスに対する制御された列挙を使用して、すべての境界をまたぐサブセグメントを明示的にチェックします。 これは厳密な意味では漸近的に最適ではありませんが、意図した構造を反映しています。有効性は合計と最大値のみに依存するため、マージ中にすべての候補セグメントをローカルで検証できます。 

クエリ操作は単に関連するノードを結合し、更新により変更が上方に伝播されます。

 ## 特殊なケース

 重大なエッジ ケースは、配列に多数の小さな値に囲まれた 1 つの主要な値が含まれる場合です。 例えば`[100,1,1,1,1,1]`。 十分な小さな値が蓄積されるまで、左からの拡張は常に無効に見えるため、単純な貪欲なアプローチは失敗します。 

このアルゴリズムは、すべての候補セグメントの合計と最大値を常に明示的に比較することでこれを処理し、大きな境界を越えた後にのみ妥当性が現れるセグメントでも確実に評価されるようにします。 

もう 1 つの特殊なケースは、単一のインデックスで更新が繰り返されることです。 更新はツリー内を上方に伝播するため、毎回影響を受けるのは O(log n) ノードだけであり、影響を受けるパスの外側に再計算が漏れることはなく、すべてのクエリにわたって構造の一貫性が保たれます。
