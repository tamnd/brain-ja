 ## 解決策
 ## 問題の理解

 私たちは、1 から n までの 2 つの異なる整数を 1 行に隠すシステムと対話しています。それらを x₁ および x₂ (x₁ < x₂) と呼びます。 私たちはそれらの場所を知りません。情報を抽出する唯一の方法は、選択した位置でクエリを発行することです。 

各クエリは位置 x です。 システムは、2 つの隠れた点のどちらが x に近いかに基づいて応答します。 x が隠れ点の 1 つと正確に等しい場合、システムはそれを直接確認します。 それ以外の場合は、x₁ と x₂ までの距離を比較し、近い方を選択し、その選択した点が x の左側にあるか右側にあるかを判断します。 

重要な問題は、応答が両方の点について同時に直接的に何も教えてくれないことです。 現在どの隠れ点が近いかに関する方向情報のみを明らかにします。これは、アイデンティティではなくジオメトリに依存します。 

このタイプの対話型問題では制約が極端です。n は 10⁹ まで大きくなり、クエリの数は約 125 に制限されます。 これにより、位置をスキャンしたり、構造を持たずに線形または対数スケールで両方の点を独立して調整したりする戦略は即座に除外されます。 唯一の実行可能な方向は、応答関数の単調な動作を利用し、二値決定によって検索スペースを削減することです。 

クエリ ポイントがまさに隠れた位置の 1 つである場合、微妙なエッジ ケースが発生します。 その場合、応答は方向ではなく平等になります。 たとえば、隠れた点が 3 と 10 の場合、x = 3 をクエリすると「=」が返されますが、x = 4 をクエリすると、3 と 10 のどちらが近いかに基づいて方向応答が返されます。 すべての応答に方向性があると仮定する単純な二分探索は、ここで破綻する可能性があります。これは、等価性が順序付けロジックに適合せず、最終発見として扱う必要があるためです。 

もう 1 つの重要なエッジ ケースは、クエリがちょうど x₁ と x₂ の間の中間点にある場合です。 この状況では、両方の塔の距離が等しく、問題は正しい塔が選択されることを指定します。 このタイブレーク ルールにより、応答関数が単調になり、二分探索に使用できるようになります。 

## アプローチ

 ブルートフォース戦略では、両方の隠れポイントが発見されるまで、1 から n までのすべての位置のクエリを試みます。 これは正しいです。なぜなら、最終的には x₁ と x₂ の両方にヒットし、等しい応答を受け取ることになるからです。 ただし、最悪の場合、n 個のクエリが必要になり、最大 10⁹ に達する可能性があり、125 クエリの制限をはるかに超えています。 両方のターゲットを時間内に達成する保証はないため、ランダム サンプリングに制限しても役に立ちません。 

重要な構造上の観察は、特定のクエリでどの点が近いかは分からないが、システムは効果的に隠れた中点 M = (x₁ + x₂) / 2 を定義しているということです。任意のクエリ x について、x が M より小さい場合、x₁ は x₂ より近いことが保証されるため、応答は純粋に x₁ によって決定されます。 x が M より大きい場合、応答は純粋に x₂ によって決まります。 まさに M では、距離的には双方の可能性が同じですが、タイブレークにより一貫性が求められます。 

これは、応答方向が M に単一の遷移点を持つ単調関数のように動作することを意味します。x₁ または x₂ を個別に知らなくても、この遷移点を二分探索できます。 M が判明すると、問題はきれいに分割されます。x₁ は完全に [1, M] にあり、x₂ は完全に [M, n] にあり、各セグメント内では、すべてのクエリはターゲットが 1 つだけ存在するかのように動作します。 これにより、問題は 2 つの独立した標準対話型検索に減ります。

 ## アルゴリズムのチュートリアル

 ソリューションは 2 つのフェーズで構築されます。2 つのタワーの影響を分離する中間点領域を特定し、次に各タワーを独立して特定します。

1. 位置を出力し、応答を読み取り、出力をすぐにフラッシュするクエリ関数を定義します。 インタラクションは各フラッシュ後にのみ進行するため、これが必要です。 
2. [1, n] の x を二分探索して、応答が動作を変える遷移点を見つけます。 位置 x で、応答が「>」の場合、最も近い塔が右側にあることを意味し、これは x が中点領域の左側にあることを意味します。 応答が「<」の場合、x は中点領域の右側にあります。 これにより、x に関する単調な述語が得られます。 
3. 検索間隔 [l, r] を維持します。 Mid = (l + r) / 2 の場合、mid をクエリし、応答に基づいて間隔を調整し、一意の分割位置 M に向かって縮小します。 
4. M が特定されると、重要な構造的事実がわかります。[1, M] のすべての点は x2 よりも x1 に近く、[M, n] のすべての点は x1 よりも x2 に近くなります。 これにより、問題は 2 つの独立した単一ターゲット検索に変わります。 
5. x₁ を見つけるには、[1, M] で二分探索を行います。 この範囲内の位置 x をクエリすると、この領域では x₂ が常に遠くにあるため、システムの指向性応答は x₁ のみを参照します。 応答が「>」を示す場合、x₁ は x の右側にあります。 そうでなければ、それは左に横たわるか、平等に達します。 
6. 同じプロセスを [M, n] で繰り返して、x₂ を見つけます。 
7. 両方が見つかったら、昇順に出力して終了します。 

正確性は 1 つの不変条件に左右されます。つまり、中点 M が固定されると、近い方のタワーの正体は M の各側で一定になります。これにより、比較のあいまいさがなくなり、すべての二分探索ステップが単一の隠れた値に対する標準的な単調探索のように動作することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(x: int) -> str:
    print(x)
    sys.stdout.flush()
    return input().strip()

def find_mid(n: int) -> int:
    l, r = 1, n
    while l < r:
        mid = (l + r) // 2
        res = ask(mid)

        if res == "<":
            l = mid + 1
        else:
            r = mid
    return l

def find_point(l: int, r: int) -> int:
    while l < r:
        mid = (l + r) // 2
        res = ask(mid)

        if res == ">":
            l = mid + 1
        else:
            r = mid
    return l

def main():
    n = int(input())

    mid = find_mid(n)

    x1 = find_point(1, mid)
    x2 = find_point(mid, n)

    if x1 > x2:
        x1, x2 = x2, x1

    print("! {} {}".format(x1, x2))
    sys.stdout.flush()

if __name__ == "__main__":
    main()
```最初の検索では、2 つの隠れた点の影響が切り替わる中間点を分離します。 2 番目と 3 番目の検索は標準的なバイナリ検索です。これは、各制限セグメント内ですべての応答を担当できるのは 1 つの隠れポイントのみであるためです。 最後のスワップは、中間点が正確にタワーに位置する場合、または検索が境界で重複する場合を処理します。 

よくある実装上の間違いは、等価応答をバイナリ順序付けの一部として扱うことです。 等価性が見つかった場合は即時終了として扱われるべきですが、たとえ無視されたとしても、中間点分割の構造により、二分探索ロジックが壊れることはありません。 

## 実用的な例

 3 と 8 に隠れ点がある、n = 10 の小さな構成を考えてみましょう。 

まず、5.5 にある中間点領域を見つけます。そのため、M は 6 に解決されます。 

### 中間点探索トレース

 | クエリ x | 応答 | 間隔更新 |
 | --- | --- | --- |
 | 5 | ">" | r = 5 |
 | 3 | "= | 停止 (正確なタワーが見つかりました) |

 実際には、等号が早期に現れる可能性がありますが、そうでない場合は、二分探索は M = 6 に収束します。 

これにより、位置 1 から 6 は x1 によって支配され、位置 6 ～ 10 は x2 によって支配されることが確認されます。 

### [1, 6] で x₁ を見つける

 | クエリ x | 応答 | 間隔更新 |
 | --- | --- | --- |
 | 3 | "= | x₁ = 3 が見つかりました |

 これは、左側の領域内では、応答が x₁ のみに依存していることを示しています。 

### [6, 10] で x₂ を求める

 | クエリ x | 応答 | 間隔更新 |
 | --- | --- | --- |
 | 8 | "= | x₂ = 8 が見つかりました |

 トレースは、中間点分割が判明すると、各半分が標準の単一ターゲットの対話型検索のように動作することを示しています。

 ## 特殊なケース

 隠れた点が隣接している場合、たとえば x₁ = 4 と x₂ = 5 の場合、中点は 4.5 となるため、M は整数の処理に応じて 4 または 5 になります。 応答が 4 と 5 の間で 1 回だけ反転するため、最初のフェーズは依然として正しく収束します。左側の二分探索では 4 が分離され、右側の二分探索では曖昧さなく 5 が分離されます。 

クエリが早い段階で隠れた点に正確に到達した場合、たとえば x = x₁ をクエリした場合、システムはすぐに「=」を返します。 アルゴリズムは、その検索ブランチを直ちに終了し、他の間隔を続行する必要があります。 明示的に最適化されていない場合でも、等価性により自然に検索空間が 1 つの値に縮小され、正確さが維持されます。 

M = 1 や M = n など、中点検索が終点に収束すると、セグメントの 1 つが空になります。 この場合、残りのセグメント内のすべてのクエリは依然として他のタワーを正しく識別します。これは、すべての応答が 1 つの隠れたポイントによって支配され、問題が縮退した単一ターゲット検索に帰着するためです。
