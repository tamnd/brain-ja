 ## 解決策
 ## 問題の理解

 この問題は正確に移動する最速の方法を求めています`n`単位。 キャラクターは一定の速度で任意の距離を歩くことができます`a`、または正確に飛躍を実行します`b`単位。 飛躍には常に 3 秒かかります。 歩行は継続しますが、最終的な位置は正確でなければなりません`n`したがって、アクションの組み合わせはターゲットの距離を正確にカバーする必要があります。 

入力により、歩行速度、跳躍の長さ、合計距離が得られます。 出力は可能な最小時間、または`-1`一連の歩行と跳躍が目的地に正確に着地できない場合。 

距離は次のように大きくすることができます`10^18`, そのため、動きをシミュレートしたり、あらゆる回数のジャンプを試したりすることは不可能です。 考えられるすべてのリープ カウントをループするには、最大で`10^18 / 1`これは 1 秒の制限をはるかに超えています。 解決策では、問題を数回の算術演算 (通常は対数計算程度) に減らす必要があります。 

難しい部分は、大きな値そのものではなく、算術境界です。 ソリューションでは、単独歩行が機能する場合、一部の跳躍回数のみが有効な場合、および最適な跳躍回数が明らかでない場合を正しく処理する必要があります。 

例えば：```
Input:
2 4 11

Output:
-1
```不注意な解決策では、2 回の飛躍を試みる可能性があります。`4 + 4 = 8`、残りの3ユニットを歩きます。 ただし、歩行速度が 2 なので、残りの距離を秒数でカバーすることはできません。 総距離は到達不可能です。 

もう 1 つのエッジ ケースは、最速の戦略が可能な最大数のリープを使用する場合です。```
Input:
1 5 10

Output:
6
```2 回のジャンプで 10 単位すべてをカバーし、6 秒かかります。 常に歩行を優先するソリューションでは 10 が出力されますが、これは最適ではありません。 

3 番目のケースは、割り算によってうるう回数を選択する必要がある場合です。```
Input:
3 6 15

Output:
5
```1 回の跳躍で 6 単位がカバーされ、残りの歩行単位は 9 単位になります。 これは 5 秒で完了します。 3 回のリープではオーバーシュートが発生し、0 回のリープでは速度が低下します。 

## アプローチ

 直接的な総当りの解決策では、あらゆる可能な回数の飛躍が試行されます。 使用する場合`k`跳躍、彼らはカバーします`k * b`距離を指定し、残りの距離を歩きます。 残りの距離が負ではなく、次で割り切れるかどうかを確認できます。`a`、時間を計算します。 

このアプローチは正しいです。なぜなら、考えられるあらゆる移動計画は、その跳躍の数によって完全に記述されるからです。 ただし、最悪の場合は、`n / b`可能性。 以来`n`できる`10^18`、これは次のように大きくすることができます`10^18`小切手。 

重要な観察は、時間の公式が飛躍の回数と単純な線形関係を持っているということです。 あれば`k`飛躍します、時刻は次のとおりです。```
k * 3 + (n - k * b) / a
```並べ替え:```
n / a + k * (3 - b / a)
```最初の部分は依存しません`k`。 唯一変化する部分は次の係数です。`k`。 以来`b >= 2a`、係数は固定符号を持つかゼロです。 歩くよりも跳躍の方が速いのであれば、できるだけ多くの跳躍が必要です。 跳躍が遅い場合は、跳躍をできるだけ少なくする必要があります。 

残りの課題は、有効な飛躍カウントを見つけることです。 有効な`k`以下を満たす必要があります:```
k * b + walking_distance = n

walking_distance is divisible by a

k * b ≡ n (mod a)
```これはモジュラー方程式です。 最大公約数と逆モジュラーを使用してこれを解き、どちらがより良い時間を与えるかに応じて、最小または最大の有効な解を選択します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n / b) | お(1) | 遅すぎる |
 | 最適 | O(log(min(a, b))) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. コンピューティング`g = gcd(a, b)`。 合同`k * b ≡ n (mod a)`の場合にのみ解決可能です`n`で割り切れます`g`。 そうでない場合は、何回跳んでも残りの歩行距離を有効にすることができないため、答えは不可能です。 
2. すべてを次の値で割って式を簡略化します。`g`。 得られるものは次のとおりです。`b/g * k ≡ n/g (mod a/g)`今`b/g`そして`a/g`は互いに素なので、`b/g`逆モジュロを持っています`a/g`。 
3. 解決策を 1 つ見つける`k0`逆モジュラーを使用します。 有効なうるう回数はすべて次の形式になります。`k = k0 + t * (a/g)`ある整数に対して`t`。 
4. 解決策を可能な範囲に限定する`0 <= k <= n/b`。 この範囲内に解決策がない場合、旅行は完了できません。 
5. 有効な最小値を取るか最大値を取るかを決定します。`k`。 もし`b < 3a`, 歩く方が事実上速いので、跳躍の回数を最小限に抑えます。 もし`b > 3a`、リープは時間を節約するため、リープの数を最大化します。 もし`b = 3a`、すべての有効な選択肢には同じ時間がかかります。 
6. 選択した値を使用して答えを計算します。`k`。 

なぜ効果があるのか:

 考えられるすべての戦略は、まさに 1 つの数字、つまり飛躍の数によって表されます。 その数字が決まれば、残りの距離と時間が決まります。 モジュラー方程式は、考えられるすべての有効なうるう回数を見つけ、線形時間式は、そのセットのどの端が最適であるかを示します。 正しい極値をチェックするので、結果として生じる時間は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def egcd(a, b):
    if b == 0:
        return a, 1, 0
    g, x, y = egcd(b, a % b)
    return g, y, x - (a // b) * y

def solve():
    a, b, n = map(int, input().split())

    g, _, _ = egcd(a, b)

    if n % g != 0:
        print(-1)
        return

    mod = a // g
    max_k = n // b

    if mod == 1:
        low = 0
        high = max_k
    else:
        bg = b // g
        ng = n // g

        _, x, _ = egcd(bg, mod)
        inv = x % mod

        k0 = (ng % mod) * inv % mod

        if k0 > max_k:
            print(-1)
            return

        low = k0
        high = k0 + ((max_k - k0) // mod) * mod

    if b < 3 * a:
        k = low
    elif b > 3 * a:
        k = high
    else:
        k = low

    remaining = n - k * b
    print(3 * k + remaining // a)

solve()
```の`egcd`関数は、逆モジュラーの計算に必要な係数を与えます。 換算された乗数と法は互いに素であることが保証されているため、逆関数は方程式を換算した後にのみ必要になります。 

変数`mod`有効なリープカウント間の間隔です。 1つ有効になると`k`が既知である場合、他のすべての有効な値は正確に異なります`mod`。 このコードは、許可された間隔内で有効な最小値と最大値を計算します。 

間の比較`b`そして`3a`最適化の方向を決定します。 いつ`b < 3a`、各跳躍はあまりにも短い歩行時間を置き換えるため、より多くの跳躍を使用すると痛手になります。 いつ`b > 3a`、さらに飛躍するたびに結果が向上します。 有効な選択肢はすべて同順位であるため、等しい場合は問題になりません。 

すべての計算では Python 整数が使用されるため、最大の大きな値は`10^18`オーバーフローしないでください。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    a, b, n = map(int, sys.stdin.readline().split())

    def egcd(a, b):
        if b == 0:
            return a, 1, 0
        g, x, y = egcd(b, a % b)
        return g, y, x - (a // b) * y

    g, _, _ = egcd(a, b)

    if n % g != 0:
        ans = -1
    else:
        mod = a // g
        max_k = n // b
        if mod == 1:
            low, high = 0, max_k
        else:
            bg = b // g
            ng = n // g
            _, x, _ = egcd(bg, mod)
            k0 = (ng % mod) * (x % mod) % mod
            if k0 > max_k:
                ans = -1
                sys.stdin = old
                return str(ans) + "\n"
            low = k0
            high = k0 + ((max_k - k0) // mod) * mod

        k = low if b < 3 * a else high
        ans = 3 * k + (n - k * b) // a

    sys.stdin = old
    return str(ans) + "\n"

assert run("1 2 10\n") == "10\n", "sample 1"
assert run("2 4 11\n") == "-1\n", "sample 2"

assert run("1 5 10\n") == "6\n", "all leaps"
assert run("3 6 15\n") == "5\n", "divisibility"
assert run("10 20 1000000000000000000\n") == "150000000000000000\n", "large values"
assert run("5 10 7\n") == "-1\n", "unreachable remainder"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |

 ## 特殊なケース

 のために`2 4 11`、アルゴリズムはすぐに gcd 条件をチェックします。 以来`gcd(2,4)=2`そして`11`が 2 で割り切れない場合、合同式には解がありません。 歩行可能な残りを残す可能性のある飛躍回数はありません。 

のために`1 5 10`、歩行距離は常に 1 で割り切れるため、すべての飛躍カウントは有効です。係数は負です。`5 > 3 * 1`したがって、アルゴリズムは可能な最大のうるう回数を選択します。`2`。 最終回は`2 * 3 = 6`。 

のために`3 6 15`、縮小された方程式により、正しいパリティでのうるうカウントが可能になります。 有効な選択肢は次のとおりです`k = 1`範囲内のみ。 残りの距離は`9`、かかります`3`歩くまで数秒、与える`6`? 実際には飛躍が必要です`3`数秒で歩くのに時間がかかります`3`秒なので合計は`6`。 モジュラー ステップにより、オーバーシュートする 2 回のジャンプなどの無効な選択が防止されます。 

非常に長い距離の場合、アルゴリズムは配列を作成したり、次の値に比例するループを実行したりすることはありません。`n`。 ユークリッド アルゴリズムのみを使用するため、宛先が近くにある場合でも実行時間は小さいままです。`10^18`。
