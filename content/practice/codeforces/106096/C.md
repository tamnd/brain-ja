 ## 解決策
 ## 問題の理解

 グリッドが与えられています`n`行と`m`列。 各セルには、そのセルが呪文の影響を受けた場合に得られる報酬を表す正の値が含まれています。 

攻撃の中心として正確に 1 つのセルを選択します。 攻撃が行われると、十字型の領域、つまり選択されたセル自体に加えて、4 つの基本方向 (上下左右) のすぐ隣のセル (グリッド内に隣接するセルが存在する場合) に影響します。 

タスクは、この十字型パターンの値の合計が最大になるように中央のセルを選択することです。 

したがって、すべての有効な中心について`(i, j)`、次のように計算します。 

の値`(i, j)`プラスの値`(i-1, j)`、`(i+1, j)`、`(i, j-1)`、`(i, j+1)`それらが存在する場合。 

出力は、すべての可能な中心にわたる最大の合計です。 

制約`n, m ≤ 100`グリッドには最大でも 10,000 個のセルがあることを意味します。 数万回の操作は 1 秒の制限内では無視できるため、セルごとに一定量の作業を再計算するソリューションは十分に高速です。 ここでは、中心ごとに行または列を繰り返しスキャンする必要があるものはすべて問題ありませんが、その必要はありません。 

微妙なエッジケースは境界セルから発生します。 4 つの近傍がすべて存在すると誤って仮定すると、無効な位置にアクセスしたり、ガベージ値が追加されたりすることになります。 たとえば、`1 × 4`グリッド：```
2 1 2 1
```列 1 で完全な交差を計算しようとすると、左隣が存在しないため、正しい合計は次のようになります。`2 + 1 = 3`そのセンターのために。 盲目的にアクセスする単純な実装`j-1`クラッシュするか、不正確な合計が生成される可能性があります。 

もう 1 つの特殊なケースは、グリッドが次のような場合です。`1 × 1`。 その場合、唯一の有効なセンターは、それ自体の値のみを提供します。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのセルについて、それを十字の中心として扱い、最大 5 つのセルをチェックして合計を計算します。 各チェックは定数時間であるため、これは次のようになります`O(nm)`総仕事量。 これはすでに制約内に快適に収まっています。 

遅いがまだ考えられる単純なバージョンは、固定近傍ウィンドウを反復処理するか、行と列を動的にスキャンすることによってクロスサムを再計算することです。 それでも、グリッドが小さいため、通過することはできますが、不必要な複雑さが生じ、境界ミスが発生する可能性が高くなります。 

重要な観察は、必要な形状が固定されており、非常に小さいということです。 異なるセンター間には依存関係はありません。 各候補の回答は独立しているため、プレフィックス合計、BFS、または前処理構造は必要ありません。 問題は、すべてのグリッド セルにわたって一定サイズのステンシルを評価することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | 隣接セルを再計算するセルごとのブルート フォース | O(nm) | お(1) | 承認済み |
 | 最適な直接隣接和 | O(nm) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドを 2D 配列に読み取ります。 すべての値を保存するので、インデックスによって近傍に安全にアクセスできます。 
2. 変数を初期化する`best = 0`(or a very small number if negative values were allowed; here all values are positive so zero is safe).
 3. すべてのセルを反復処理します。`(i, j)`グリッド内で。 各セルは、十字の中心となる可能性があります。 
4. 各セルについて、以下から始まる累計を計算します。`grid[i][j]`。 これは攻撃の中心を表します。 
5. If`i > 0`、 追加`grid[i-1][j]`。 これには、上記のセルが存在する場合にのみ安全に含まれます。 
6. もし`i < n-1`、 追加`grid[i+1][j]`。 これには、以下のセルが安全に含まれます。 
7. もし`j > 0`、 追加`grid[i][j-1]`。 有効な場合、これには左隣が含まれます。 
8. もし`j < m-1`、 追加`grid[i][j+1]`。 これには右隣も含まれます。 
9. アップデート`best`現在の値の最大値と計算された合計で計算されます。 
10. すべてのセルが処理された後、出力します。`best`。 

実装における重要な考え方は、すべての近隣アクセスを境界チェックによって保護する必要があるということです。 これらの条件がなければ、エッジ セルは正確性を損なうことになります。 

### なぜ効果があるのか

 すべての有効な攻撃領域は、正確に 1 つの中央セルに対応します。 その領域の寄与は、そのセルとその 4 つの直交する隣接セルにのみ依存します。 考えられるすべての中心を列挙し、それらに対応する領域の正確な値を計算するため、実行可能なすべての攻撃を 1 回だけ検査します。 したがって、すべての計算値の最大値は最適解と等しくなければなりません。 

異なるセンター間には相互作用が存在しないため、二重にカウントされたり、構成が欠落したりするリスクはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
grid = [list(map(int, input().split())) for _ in range(n)]

best = 0

for i in range(n):
    for j in range(m):
        s = grid[i][j]

        if i > 0:
            s += grid[i - 1][j]
        if i < n - 1:
            s += grid[i + 1][j]
        if j > 0:
            s += grid[i][j - 1]
        if j < m - 1:
            s += grid[i][j + 1]

        if s > best:
            best = s

print(best)
```グリッドは変更せずに直接保存されます。 各セルは独立して評価されます。 4 つの条件チェックにより、この問題で最も一般的なエラーの原因である無効なインデックスにアクセスしないことが保証されます。 

更新ステップはオーバーヘッドを避けるために単純に保たれています。 グリッドが小さいため、Python のネストされたループで十分です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    from math import inf

    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    best = 0
    for i in range(n):
        for j in range(m):
            s = grid[i][j]
            if i > 0:
                s += grid[i - 1][j]
            if i < n - 1:
                s += grid[i + 1][j]
            if j > 0:
                s += grid[i][j - 1]
            if j < m - 1:
                s += grid[i][j + 1]
            best = max(best, s)

    return str(best)

 ## 特殊なケース

 単一セルグリッド`1 1`は最も単純な境界です。 このアルゴリズムは唯一のセルを評価し、有効な隣接セルを見つけず、無効なインデックス アクセスを入力することなくその値を正しく返します。 

で`1 × m`グリッドでは、垂直方向の隣接は存在しません。 条件付きチェックにより、水平方向の寄与のみが追加されることが保証され、問題は各位置を中心とする長さ 3 のセグメントの最大合計を見つけるという問題に効果的に軽減されます。 

で`n × 1`グリッドでは、同じ対称性が垂直方向に適用されます。 このアルゴリズムは、特別な処理を必要とせずに、クロスを垂直線に縮小します。 

エッジとコーナーのセルは部分的にのみ交差に寄与します。 それぞれは境界チェックによって自然に処理されるため、個別の論理パスは必要なく、境界を手動で処理するときに通常発生するオフバイワンエラーを防ぎます。
