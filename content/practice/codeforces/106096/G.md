 ## 解決策
 ## 問題の理解

 2 つのユニット間の 1 対 1 の戦いが与えられ、毎秒ダメージを交換します。 各ユニットには固定の攻撃値と固定の体力値があり、毎秒両方が同時にダメージを与えます。あなたのユニットはその攻撃によって対戦相手の体力を減らし、対戦相手はその攻撃によってあなたのユニットの体力を減らします。 

戦闘が始まる前に、多数の「パンケーキ」を使用してユニットを強化することができます。 各パンケーキは攻撃力または体力をちょうど 1 ポイント増加させることができます。 これらのアップグレードは、攻撃力と体力の​​間で任意に配分できます。 タスクは、ユニットが戦闘で生き残るために必要なパンケーキの最小数を決定することです。つまり、相手が死ぬまでにユニットの体力がゼロまたはマイナスにならないようにすることです。 

インタラクションは決定的であるため、戦闘全体は、同時ラウンドが何ラウンド発生するかを尋ねることに相当します。 攻撃力が高ければ、相手はより早く死にます。 相手の攻撃が高い場合、体力はより早く失われます。 最も難しいのは、追加の攻撃と追加の体力のバランスをとる方法を選択することです。 

制約では、最大 10^9 の値が許可されます。 これにより、パンケーキのさまざまな割り当てを直接シミュレートするアプローチは即座に排除されます。 攻撃と健康の間の考えられるすべての分割を反復することさえ不可能です。なぜなら、その場合、答えのサイズが線形になるためです。最悪の場合、約 10^9 になる可能性もあります。 

ラウンド数は体力を攻撃力で割った値に制限されるため、固定構成での戦いを単純にシミュレーションするのは問題ありませんが、本当の課題は、アップグレードを配布するあらゆる方法を模索することです。 

両方のユニットが同じラウンドで死亡した場合、微妙なケースが 1 つ発生します。 この問題では、生き残ることが要件であるため、同時死亡は失敗として扱われます。 たとえば、両方の攻撃が等しく、両方のヘルス値が等しい場合、最初の交換の後、両方ともゼロに下がります。 「早く負ける」人はいないとしても、これは容認できません。 

もう 1 つの特殊なケースは、攻撃が非常に小さい場合です。 あなたの攻撃が 1 で、相手の体力が非常に大きい場合、戦闘は非常に長く続き、体力のアップグレードは攻撃のアップグレードよりもはるかに価値がありますが、これはラウンド数について推論することなく明らかではありません。 

## アプローチ

 最終的にアップグレードされた攻撃と体力の値を修正すると、戦いは完全に決定的になります。 あなたの最終攻撃が A、相手の攻撃が B、あなたの最終体力が H、相手の体力が K であるとします。相手が死ぬには、およそ ceil(K / A) ラウンドが必要です。 これらのラウンド中、毎回ダメージ B を受けるため、合計ダメージはラウンド数の B 倍になります。 生存するには、H がこのダメージよりも厳密に大きい必要があります。 

これにより、選択した A と H について明確な実行可能性チェックが行われます。総当たりアプローチでは、パンケーキを攻撃と体力に分配するあらゆる可能な方法が試行されます。 攻撃に x パンケーキ、体力に y を費やしたと仮定すると (x + y = P)、結果の統計が存続するかどうかを確認できます。 0 から上のすべての P を試し、それぞれについてそれをすべての x に分割すると、答えのサイズは 2 次になります。 P 自体が大きくなる可能性があるため、これでは遅すぎます。 

重要な観察は、攻撃と体力の寄与が戦闘時間に与える影響が対称ではないということです。 攻撃力を増加させると、相手の体力が分割されるため、非線形的にラウンド数が減少します。 健康状態の増加は直線的に増加します。 これは、攻撃とヘルスを独立した線形寄与として扱うのではなく、一方を修正して、もう一方の最小要件を計算する必要があることを示唆しています。

攻撃に入るパンケーキの数を修正できます。 x 攻撃を追加すると、A = a1 + x となります。 A が固定されると、最低限必要な体力が直接決定されます。つまり、対戦相手に対して何発生き残るかを計算し、自分の体力が少なくともその量であることを確認します。 これにより、問題は x に関する単一変数の最適化に変換されます。 x は最悪の有効範囲で最大でも a1 + a2 + h2 であり、この関数は凸状に動作するため (攻撃はラウンドを減らすことで助けられ、体力は線形に助けられます)、攻撃が大きくなりすぎてラウンドの改善が停止するまで、すべての x を 0 から上にチェックすることができます。 

具体的に言うと、Aがh2を超えると相手は一撃で死ぬので、これ以上攻撃力を上げても恩恵はありません。 これにより、有用な検索スペースが制限されます。

 ## アルゴリズムのチュートリアル

 1. 攻撃アップグレードの可能な数 x を 0 から繰り返します。各 x について、A = a1 + x を設定します。 あるポイントを超えると対戦相手が 1 ラウンドで死亡するため、攻撃力の増加が依然として戦闘時間に影響を与える値のみを考慮します。 
2. この攻撃値で戦闘が何ラウンド続くかを計算します。 相手はラウンド R = ceil(h2 / A) を必要とします。 これはユニットがダメージを受ける回数を表します。 
3. 生存に必要な健康状態を計算します。 各ラウンドは a2 ダメージを与えるため、受けるダメージの合計は R * a2 となります。 あなたの健康状態は厳密にこの量より大きくなければならないため、必要な健康状態は少なくとも R * a2 + 1 です。 
4. 現在の健康状態 h1 がすでにこの要件を満たしている場合は、パンケーキ x 個で十分であり、答えを更新できます。 
5. それ以外の場合は、必要なヘルス アップグレードの数を計算します: y = max(0, required_health - h1)。 この分割の合計パンケーキは x + y であり、すべての x の最小値を追跡します。 
6. 見つかった最小値を返します。 

これが機能する理由は、固定の攻撃レベルごとに、体力についてそれ以上の決定を行う必要がないためです。追加の体力によってラウンド数が減ることはないため、最適なソリューションは生き残るために必要なだけの体力を使用します。 

### なぜ効果があるのか

 固定攻撃値 A の場合、ラウンド数は完全に決定され、体力には依存しません。 ラウンドが修正されると、生存は健康状態が線形しきい値を超えるかどうかにのみ依存します。 したがって、最適性は、x + required_health(A) を最小化する最適な A を選択することになります。 必要以上にヘルスを使用するソリューションは、同じ A に対して厳密に悪影響を及ぼします。また、A を変更する再分配は、予測可能な単調な方法でラウンド数を変更します。 これにより、考えられる各 A を個別に評価することで、すべての最適な割り当てが確実にカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a1, h1, a2, h2 = map(int, input().split())

    ans = float('inf')

    x = 0
    while True:
        A = a1 + x

        rounds = (h2 + A - 1) // A
        need_h = rounds * a2 + 1

        if need_h <= h1:
            ans = min(ans, x)
        else:
            ans = min(ans, x + (need_h - h1))

        if A > h2 and need_h > h1:
            break

        x += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このループは攻撃を徐々に増加させ、選択ごとに正確な生存要件を計算します。 停止条件は、攻撃が相手の体力を超えると相手は 1 ラウンドで死亡し、さらに攻撃を増やしてもラウンド数は改善されず、コストが増加するだけであるという事実に依存しています。 

実装によくある落とし穴は、両方の攻撃が同時に発生することを忘れていることです。 そのため、サバイバルでは、ヒットごとの結果を単純に比較するのではなく、ラウンドと相手の攻撃を掛け合わせた後の体力に関する厳密な不平等が使用されます。

 ## 特殊なケース

 開始時に両方のユニットが対称である場合、戦闘は両方がゼロになると 1 ラウンドで終了します。 生存には厳密な積極性が必要であり、健康状態が増加しない限り正常に失敗するため、アルゴリズムは少なくとも 1 つのアップグレードを強制します。 

対戦相手の攻撃が自分の体力に比べて非常に大きい場合、アルゴリズムは体力のアップグレードが初期の x 値を支配し、ラウンドが減少して初めて攻撃の増加が関連することをすぐに発見します。 このループは、特別なケースを必要とせずに、健康を重視したソリューションに自然に移行します。 

あなたの攻撃がすでに相手の体力を超えている場合、ループはただちに 1 ラウンドの戦いを評価します。 その場合、生存は h1 > a2 かどうかをチェックすることになり、そうでない場合、アルゴリズムは攻撃アップグレードを無駄にすることなく、適切なだけのヘルス アップグレードを正しく追加します。
