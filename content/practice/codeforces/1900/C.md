 ## 解決策
 ## 問題の理解

 私たちには根付き二分木が与えられています。 すべてのノードには 1 つの文字が含まれます。 

-`'L'`「左の子のところに行く」という意味です
 -`'R'`「正しい子供のところに行きなさい」という意味です
 -`'U'`「親のところに行く」という意味です

 要求された目的地が存在しない場合、旅行者はその場に留まります。 

旅人はルートから始まります。 開始する前に、ノードに書かれている文字を変更する場合があります。 変更ごとに 1 回の操作が必要になります。 

私たちの目標は、変更をできるだけ少なくしながら、旅行者が散歩中に少なくとも 1 枚の葉に到達できるようにすることです。 

まず最初に気づくのは、私たちは無限の移動プロセス全体に興味がないということです。 最終的に何らかの葉に到達するかどうかだけを気にします。 ツリーは有限であるため、ルートからリーフまでのパスを選択すると、重要なノードはそのパス上のノードだけになります。 

すべてのテスト ケースにわたるノードの合計数は最大で$3 \cdot 10^5$。 すべてのリーフを個別に試行し、ツリーの大部分を繰り返し走査するアルゴリズムは、二次関数になる可能性があります。 と$3 \cdot 10^5$ノード、$O(n^2)$まったく実現不可能ですが、$O(n)$または$O(n \log n)$簡単に十分に高速です。 

微妙な点は、ノードのラベルが`'U'`必ずしも悪いわけではありません。 ノードが、選択されたルートからリーフへのルートの一部ではないとします。 そこで何が起こっても私たちは気にしません。 旅行者にたどってもらいたいルート上のノードのみが答えに寄与します。 

もう 1 つの簡単な間違いは、ルート上のすべてのノードが下を向いている必要があると考えることです。 考慮する：```
1('L')
/
2
```ノード 2 はすでにリーフです。 旅行者がノード 2 に到達すると、目標は達成されます。 ノード 2 自体から実行される移動について気にする必要はありません。 

具体的な例:```
n = 2
s = "LU"

1 -> right child = 2
```ルートは左に行こうとしていますが、右の子しか存在しません。 旅人は永遠に根元から立ち往生してしまいます。 ルートを次から変更します`'L'`に`'R'`コストは1で、すぐに葉に到達します。 正解は 1 です。 

不注意なシミュレーションベースのソリューションも、`'U'`ラベル。 例えば：```
1('L')
|
2('U')
```旅人は1から始まり、1と2を永遠に行き来する。 ただし、ノード 2 のみをその下のどこかのリーフを指すように変更すると、問題を解決できる可能性があります。 現在のラベルのシミュレーションではなく、ツリー全体にわたるグローバルな最適化が必要です。 

## アプローチ

 強引なアイデアは、すべての葉を個別に考慮することです。 選択した葉について、根から葉までの一意のパスを確認します。 そのパス上のすべての内部ノードは、トラベラーをパス内の次のノードに誘導する必要があります。 現在のラベルがすでにその必要な方向と一致している場合、そのノードのコストは 0 です。 それ以外の場合は 1 です。これらのコストを合計すると、その特定のリーフに到達するために必要な変更の数が得られます。 すべての葉の最小値を取ると答えが得られます。 

この推論は実際には正しいです。 問題は効率です。 すべての葉のルートから葉へのパスを明示的に再構築すると、大きく歪んだツリーには次のものが含まれる可能性があります。$O(n)$長さのパスを持つ葉$O(n)$、につながる$O(n^2)$仕事。 

重要な観察は、ノードのコスト寄与は、次にどの子を選択するかによってのみ依存するということです。 

現在ノードにいるとします。$v$。 

最適なリーフが左側のサブツリーにあると判断した場合、ノード$v$私たちを左に送らなければなりません。 このノードのコストは次のとおりです。 

- ラベルが次の場合は 0`'L'`それ以外の場合は - 1

 同様に、右のサブツリーに進むと、コストは次のようになります。 

- ラベルが次の場合は 0`'R'`それ以外の場合は - 1

 これにより、問題がツリー DP に変わります。 

させて`dp[v]`ノードから開始して何らかのリーフに到達するために必要な変更の最小数を示します`v`。 

リーフの場合、これ以上の変更は必要ありません。`dp[v] = 0`。 

内部ノードの場合は、既存のすべての子を試します。 左に行く場合は、現地の改造費に加えて支払います`dp[left]`。 正しく行けば、対応するローカル修正コストに加えて支払います。`dp[right]`。 

それらの選択肢の最小値は次のようになります`dp[v]`。 

各ノードは 1 回処理されるため、ツリー全体は線形時間で解決されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリー構造とラベル文字列を読み取ります。 
2. 定義する`dp(v)`ノードから開始していくつかのリーフに到達するために必要な最小限の変更数として`v`。 
3. もし`v`葉です、戻ります`0`。 

到達した目標を満たすノードにはすでに到達しています。 
4. このノードの答えを無限大として初期化します。 
5. 左の子が存在する場合は、次のように計算します。```
cost = (label[v] != 'L') + dp(left_child)
```これは、必要に応じて現在のラベルを変更し、最適に左側のサブツリーからリーフに到達することを表します。 
6. ノードの応答をその値で更新します。 
7. 正しい子が存在する場合、次を計算します。```
cost = (label[v] != 'R') + dp(right_child)
```8. 取得した最小値でノードの応答を更新します。 
9. 計算された値を返します。 
10. テストケースの答えは次のとおりです。`dp(root)`。 

### なぜ効果があるのか

 ルートからリーフまでのすべてのパスは、そのパスに沿った一連の子の選択によって一意に決定されます。 各ノードでの唯一の決定は、選択したリーフが左側のサブツリーにあるか右側のサブツリーにあるかということです。 

選択したパスが左側の子を通過する場合、現在のノードには以下が含まれている必要があります。`'L'`。 他のラベルは 1 回だけ変更する必要があります。 ローカルコストを支払った後、残る問題は、左の子からリーフに到達することと同じです。 同じ議論が右側の子にも当てはまります。 

すべての有効なルートからリーフへのルートはローカルな決定と最適な部分問題に分解されるため、再帰化では考えられるすべてのリーフが検査され、それらの間の最小合計変更数が計算されます。 サブツリーのサイズに関する帰納法により、`dp(v)`ルートを含むすべてのノードに対する真の最適解です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 20)

t = int(input())

for _ in range(t):
    n = int(input())
    s = input().strip()

    left = [0] * (n + 1)
    right = [0] * (n + 1)

    for i in range(1, n + 1):
        l, r = map(int, input().split())
        left[i] = l
        right[i] = r

    dp = [0] * (n + 1)

    def dfs(v):
        if left[v] == 0 and right[v] == 0:
            dp[v] = 0
            return 0

        res = 10 ** 9

        if left[v]:
            res = min(
                res,
                (0 if s[v - 1] == 'L' else 1) + dfs(left[v])
            )

        if right[v]:
            res = min(
                res,
                (0 if s[v - 1] == 'R' else 1) + dfs(right[v])
            )

        dp[v] = res
        return res

    print(dfs(1))
```DFS は、各サブツリーの DP 値を 1 回だけ計算します。 リーフに到達するとすでに目的が満たされているため、リーフはすぐに 0 を返します。 

内部ノードの場合、反復は証明からの推論を直接反映します。 左側のサブツリーを選択した場合、現在のノードは旅行者を左側に向ける必要があります。 表現```
(0 if s[v - 1] == 'L' else 1)
```は、まさにそのノードで必要な変更コストです。 

ラベルはゼロから始まるインデックスの文字列に格納されますが、ノードには 1 から番号が付けられます。そのため、コードは次のようにアクセスします。`s[v - 1]`。 

ノードは子を 1 つだけ持つことができます。 この実装では、既存の子のみが評価されます。これは重要です。リーフに到達しようとするときに、存在しない子に向かって移動することは決して役に立ちません。 

再帰の深さは次のとおりです$n$縮退ツリーでは、テスト ケースを処理する前に再帰制限が増加します。

 ## 特殊なケース

 ### ノードには子が 1 つだけあります

 入力:```
1
2
LU
0 2
0 0
```ルートには左の子はなく、右の子が 1 つあります。 

アルゴリズムは正しい遷移のみを評価します。```
cost = 1 + dp(2)
```そして行方不明の左の子供を完全に無視します。 結果は 1 です。ルートを次のように変更する必要があるため、これは正しいです。`'R'`。 

### コストが異なる複数のリーフ

 入力:```
1
3
ULU
2 3
0 0
0 0
```根はどちらの葉にも届きます。 

Going left costs:```
1 + 0 = 1
```正しく進むには次のようなコストがかかります。```
1 + 0 = 1
```DP は最小値をとり、1 を返します。アルゴリズムは特定のリーフに早すぎるコミットをすることはありません。これは最適化のために不可欠です。 

### ディープチェーン

 入力:```
1
4
UUUU
2 0
3 0
4 0
0 0
```ルートからリーフへの唯一のパスは次のとおりです。```
1 -> 2 -> 3 -> 4
```各内部ノードは左を指す必要があるため、ノード 1、2、および 3 はそれぞれ 1 回の変更が必要です。 

DP は以下を計算します。```
dp(4)=0
dp(3)=1
dp(2)=2
dp(1)=3
```そして 3 を返します。 

### 葉のラベルは無関係です

 入力:```
1
2
LR
2 0
0 0
```ノード 2 はすでにリーフです。 そのラベル`'R'`ノード 2 に到達するとすぐに目的が達成されるため、問題はありません。 

アルゴリズムは以下を割り当てます。```
dp(2)=0
```問題の定義と正確に一致するラベルを検査する必要はありません。
