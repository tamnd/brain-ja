 ## 問題の理解

 それぞれの位置が使用可能またはブロックされているセルの行が与えられます。 水を保持できるのは使用可能な位置のみですが、ブロックされた位置はラインを独立した領域に分割する永続的な壁として機能します。 初期状態では水は存在しません。目標は、使用可能なすべてのセルに最終的に水が含まれるようにすることです。 

使用可能な空のセルに水を明示的に入れることができます。これが、カウントする必要がある唯一の操作です。 2 番目の操作では、空のセル間で水を移動できますが、この移動は任意であり、目的にはチャージされません。 伝播ルールもあります。空の使用可能なセルの両側にすぐに水がある場合、自動的に満たされます。 

課題は、水を直接配置する回数を最小限に抑えながら、配置、移動、伝播の両方を使用して最終的に使用可能なすべてのセルを満たすことができるようにすることです。 

セル数の制約はテスト ケースごとに最大 100 個であるため、高度なデータ構造や線形スキャンを超える最適化は必要ありません。 文字列に対して 2 次またはそれより悪い解であればまだ安全ですが、問題の構造は、答えがグローバル検索ではなくローカル パターンのみに依存していることを強く示唆しています。 

空のセグメントが長いにもかかわらず、さまざまな方法で囲まれている場合、微妙な失敗のケースが発生します。 たとえば、内壁のない長く伸びたドットについて考えてみましょう。 単純なアプローチでは、すべてのドットに水が必要であると想定されるかもしれませんが、戦略的に配置された 2 つの水源のみからの伝播でセグメント全体を満たすことができます。 もう 1 つのエッジ ケースは、ブロックされたセルによってセグメントが中断される場合です。これにより、伝播がリセットされ、各セグメントが独立します。 

## アプローチ

 伝播ルールを無視すると、問題は単純にすべての空のセルに水を配置することになり、これは自明の理ですが、最適化は完全に無視されます。 この単純な戦略はドットごとに 1 つの操作を必要とし、長く連続するセグメントが存在する場合には明らかに最適ではありません。 

もう少し思慮深い総当たりアプローチでは、水を配置する場所のすべての選択肢を試し、伝播をシミュレートします。 長さ n のセグメントの場合、k 個の配置を選択すると C(n, k) 程度の組み合わせが得られ、各シミュレーションは O(n) となるため、中程度の n の場合でもこれは実行不可能になります。 

重要な観察は、伝播は空のセルの連続ブロックの両端に水があることのみに依存するということです。 セグメント内に 2 つの水源が存在すると、それらの間のすべてを埋めることができ、セグメント内に追加の配置は不要になります。 これにより、問題は、「アンカー」を「.」の各最大連続セグメント内に最適に配置する方法を決定することになります。 文字。 

長さ L のセグメントの場合、両端に水を配置すると中央のすべてが満たされます。そのため、配置の各ペアがそれらの間のブロックをカバーできるため、1 つのセグメントはおよそ ceil(L / 2) 個の配置に寄与します。 ブロックされたセルはこのロジックをリセットするため、各セグメントを独立して処理できます。

 ## アルゴリズムのチュートリアル

 文字列を処理し、「.」の最大の連続セグメントを分離します。 細胞。 ブロックされたセルはセグメント間の相互作用を妨げるため、このような各セグメントは独立して処理されます。

1. 文字列を左から右にスキャンして、連続する「.」のセグメントを特定します。 文字。 このセグメントは、水が継続的に伝播できる唯一の領域です。 
2. 長さ L のセグメントの場合、端から内側に向​​かってセルをペアにすることで必要な配置の数を計算します。 各配置は、奇数長セグメントの中央を除いて、最良の場合、2 つのセルを埋めるのに効果的に貢献できます。 
3. したがって、セグメントに必要な配置数は (L + 1) // 2 です。 
4. 「#」で区切られたすべてのセグメントのこの値を合計します。 
5. 合計を答えとして返します。 

ペアリングの背後にある直観は、単一の水の配置が、繁殖のための 2 つの境界源の 1 つとして機能する場合に最も効率的であるということです。 セルをペアにすることで、すべての配置が水の内部への拡散に最大限に貢献するようにします。 

### なぜ効果があるのか

 空のセルの各セグメントは、ブロック壁により独立しています。 セグメント内では、2 つの水源の間にセルを挟むことができる場合にのみセルが満たされます。 これは、セグメントを完全に埋める構成では、各内部領域を「カバーする」少なくとも 1 組の配置を暗黙的に定義する必要があることを意味します。 最適な戦略は、各配置を複数のそのようなペアの片側として再利用することです。これはまさに、連続するセルをペアリングすることで達成されることです。 式 (L + 1) // 2 は、2 近傍アクティベーション ルールの下で線形チェーンをカバーするために必要なエンドポイントの最小数を示します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input().strip())
    s = input().strip()

    ans = 0
    i = 0

    while i < n:
        if s[i] == '#':
            i += 1
            continue

        j = i
        while j < n and s[j] == '.':
            j += 1

        length = j - i
        ans += (length + 1) // 2

        i = j

    print(ans)
```コードは単一のリニア スキャンに依存しています。 「.」のブロックが出現するたびに 文字が見つかった場合は、セグメント式を適用する前に完全に展開されます。 主要な実装の詳細は、i から j へのジャンプであり、これにより各文字が 1 回だけ処理されることが保証されます。 

式 (length + 1) // 2 は、前述のペアリング ロジックを直接実装します。 整数の除算は偶数と奇数の両方のケースを均一に処理し、特殊な場合の分岐を回避します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input().strip())
        s = input().strip()

        ans = 0
        i = 0
        while i < n:
            if s[i] == '#':
                i += 1
                continue
            j = i
            while j < n and s[j] == '.':
                j += 1
            ans += (j - i + 1) // 2
            i = j

        out.append(str(ans))

    return "\n".join(out)

 次のような単一のドット入力`.`長さ 1 のセグメントを形成します。アルゴリズムは (1 + 1) // 2 = 1 を計算し、単一の配置が必要であることを正しく反映します。 

次のような完全にブロックされた入力`#####`セグメントはまったく生成されません。 スキャンはセグメント処理ブランチに入らないため、累積された答えはゼロのままで、水を必要とするセルがないという事実と一致します。 

のような交互パターン`.#.#.`長さ 1 の複数のセグメントに分割されます。それぞれが 1 つの演算に寄与し、セグメントの独立性により、最終結果が孤立したセルの単純な合計になることが保証され、ブロックされたセルが伝播境界を完全にリセットすることが確認されます。
