 ## 問題の理解

 1 から 1 までの数字の順列が与えられます。$n$そして、要素が 1 つだけ残るまで部分配列から極小値と極大値を繰り返し削除した結果を求める一連のクエリです。 極小値は、その近傍よりも小さい要素 (両端に近傍要素が 1 つだけある) であり、極大値は、その近傍よりも大きい要素です。 削除プロセスは交互に行われます。最初に極小値を除くすべてを削除し、次に極大値を除くすべてを削除し、要素が 1 つ残るまで繰り返します。 目標は、各クエリで最後に残った要素を効率的に計算することです。 

以来$n$そして$q$どちらも最大です$10^5$の場合、各削除ステップをシミュレートする単純なアプローチでは時間がかかりすぎます。 サイズの部分配列を考えてみましょう$n$それは高、低、高、低を交互に繰り返します...; 各削除ステップで要素のおよそ半分が削除される可能性があるため、単純なシミュレーションでは次のことが必要になる場合があります。$O(n \log n)$クエリごとに、おおよその結果は$10^5 \cdot 17 \approx 1.7 \cdot 10^6$クエリごとの操作。 これは許容範囲内にあるように思えますが、サブ配列が完全な配列で多くのクエリが重複する場合、すべてを繰り返し再計算すると制限時間を超えてしまいます。 より近い解決策が必要です$O(n + q)$または$O(n \log n + q)$合計で。 

エッジケースには、答えが要素自体であることが自明である単一要素のサブ配列と、最初の削除ですでに最終要素が得られている可能性がある 2 要素のサブ配列が含まれます。 もう 1 つの微妙な点は、厳密に増加または減少するサブ配列は、どちらの操作が最初に行われるかに応じて、すぐに最初または最後の要素に折りたたまれることです。 

## アプローチ

 ブルートフォースアプローチは、削除プロセスを直接シミュレートすることです。 クエリごとに、部分配列を抽出し、それを繰り返しスキャンして極小値または極大値を特定し、その他を削除し、1 つの要素が残るまで続行します。 この方法はルールを忠実に実装しているため機能しますが、各スキャンが実行されるため、大規模な配列または多数のクエリの場合は遅くなりすぎます。$O(k)$長さの部分配列の場合$k$、スキャン数は対数です。$k$。 

より高速なソリューションのための重要な洞察は、このプロセスにおける順列の構造を観察することで得られます。 最初の極小値の削除後は、元の部分配列の「谷」である要素のみが残ります。 2 回目の極大値の削除後は、生き残った元素のうちのピークのみが残ります。 重要なのは、部分配列の長さが 1 または 2 であれば、答えはすぐに得られるということです。 より大きな部分配列の場合、2 つの削除 (最小値、次に最大値) の後、残った要素が厳密に隣接要素の間にある部分列を形成することがわかります。 順列では、部分配列の最初と最後の要素がアンカーとして機能します。それらは、1 つの近傍のみに対する局所的な極値であるため、多くの場合存続します。 この観察により、部分配列の最初のいくつかの要素と次のいくつかの要素のローカル構造をチェックすることで完全なシミュレーションを回避でき、クエリごとに定数時間の計算が可能になります。 

最終的なソリューションでは、事前に計算された左右の隣接比較の組み合わせを使用して、すべての削除ステップをシミュレートすることなく、生き残った要素を特定します。 基本的に、生き残った要素は、存在する場合は最初の内部極小値または極大値、そうでない場合は最初または最後の要素です。

 ## アルゴリズムのチュートリアル

 1. 順列の連続する要素間の差の配列を事前計算します。 これにより、増加と減少を迅速に特定できます。$O(1)$隣人チェックごとに。 
2. クエリごとにインデックスを抽出します。$l$そして$r$。 もし$l = r$、すぐに戻ります$a[l]$。 もし$r = l + 1$、最小値を返します$a[l]$そして$a[r]$最初の操作がタイプ 1 の場合、または最大操作がタイプ 2 の場合。これらは基本ケースを処理します。 
3. それ以外の場合は、部分配列の最初の 3 つの要素を調べます。$a[l], a[l+1], a[l+2]$。 部分配列が極小値で始まる場合 (最初の要素が 2 番目の要素より小さい場合)、部分配列は最初の演算後も存続します。 そうでない場合、最初の 2 つの要素の極小値が、最初の操作後に残った候補になります。 
4. 同様に、最後の 3 つの要素を調べます$a[r-2], a[r-1], a[r]$。 最後の要素が極小値である場合、最初の操作でも存続する可能性があります。 このチェックは主に、最小値が最後にあるような特殊なケースに関係します。 
5. 最初の極小値削除の候補が特定されたら、そのうちのどれが 2 番目の削除 (極大値) にも生き残るかを確認します。 順列では、これは、生き残った最小値の中で最大のものを取ることに相当します。 これは、事前に計算された比較を使用して一定時間で実行できます。 
6. 生き残った要素を返します。 

機能する理由: このアルゴリズムは、順列が個別の整数のシーケンスであるという事実を利用しています。 最初の削除では、常に極小値である要素のサブセットが保持されます。 すべての要素は個別であるため、これらの最小値は大きな数値で区切られます。 2 番目の削除では、それらのうちの最大値のみが保持されます。 順列では、この構造により、2 つの削除後に最大 1 つの要素が残ることが保証され、残った要素はエッジの小さなウィンドウのみを比較することで判断できるため、完全なシミュレーションが回避されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, q = map(int, input().split())
a = list(map(int, input().split()))

for _ in range(q):
    l, r = map(int, input().split())
    l -= 1
    r -= 1
    length = r - l + 1

    if length == 1:
        print(a[l])
        continue
    if length == 2:
        print(max(a[l], a[r]))
        continue

    # identify first deletion (local minima)
    if a[l] < a[l+1]:
        first_candidate = a[l]
    elif a[r] < a[r-1]:
        first_candidate = a[r]
    else:
        # pick first local minimum inside
        for i in range(l+1, r):
            if a[i] < a[i-1] and a[i] < a[i+1]:
                first_candidate = a[i]
                break
    # after second deletion (local maxima), pick largest surviving
    left_val = a[l]
    right_val = a[r]
    middle_val = first_candidate
    print(max(left_val, middle_val, right_val))
```このソリューションでは、まずサイズ 1 または 2 の部分配列を直接処理します。 長い部分配列の場合、エッジと内部位置をチェックすることにより、最初の削除で極小値の候補が特定されます。 順列は異なるため、最初の削除の後は、残っている要素の最大値のみを考慮する必要があります。 コードは、極小値の候補の中から最大値を取ることによってこれを計算し、部分配列が終了します。
