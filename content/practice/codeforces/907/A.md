 ## 解決策
 ## 問題の理解

 3 匹のクマとマーシャのサイズを表す 4 つの小さな整数が与えられます。 クマは 3 つの車のサイズを必要とし、父親の車から息子の車へと厳密に減少します。 各クマは 1 台の特定の車に割り当てられます。父親が最大の車、母親が中央、息子が最小の車に割り当てられます。 

サイズのキャラクター`a`サイズの車に入ることができます`b`場合のみ`a ≤ b`。 ただし、車を好きになるにはさらに厳密な条件が必要です。具体的には、車がキャラクターに比べて大きすぎてはいけません。`b ≤ 2a`。 したがって、それぞれのクマは、割り当てられた車に適合し、「気に入る」ことができなければなりません。 

マーシャは 3 台の車すべてに乗車できるため、すべての車のサイズが少なくともマーシャのサイズに制限されます。 彼女は最小の車だけを好みます。そのため、最小の車のサイズには上限が課されます。 

タスクは、すべての制約を満たす車両サイズの有効なトリプルを構築するか、そのようなトリプルが存在しないことを判断することです。 

入力値は 100 で制限されているため、解は一定時間で動作するか、最悪の場合でも狭い範囲で線形に動作する必要があります。 広い範囲にわたって反復するアプローチは必要ありませんが、100 を超えるトリプル ブルート フォースでも依然として実行可能です。 本当の課題は、不等式を狭い範囲に変換し、最小の車両が固定されると、中間の車両と最大の車両がベア制約によってほぼ直接的に決定されることに気づくことです。 

マーシャの制約が息子ベアの上限と矛盾する場合、エッジケースが発生し、個々の制約がすべて一貫しているように見えても、システムが実行不可能になります。 たとえば、マーシャが十分に大きいため、最小の車を息子のクマが気に入らないほど大きすぎると強制した場合、解決策は存在しません。 

## アプローチ

 ブルートフォースのアイデアは、整数の 3 倍体をすべて試すことです。`(S, M, L)`そのような`1 ≤ S < M < L ≤ 100`。 各トリプルについて、すべての制約をチェックします。各クマは自分の車に適合し、気に入る必要があり、マーシャはすべての車に適合し、最小の車のみを気に入る必要があります。 範囲が狭いため、これは最大でも約 100 の組み合わせ、または 100 万チェックであり、すでに境界線に達していますが、まだ許容可能です。 

ただし、これは構造を無視しています。 各クマは、割り当てられた車の範囲を個別に制限します。 条件`a ≤ b ≤ 2a`各クマを有効な車のサイズの間隔に変換します。 父親が一番大きな車を押し込む`[V1, 2V1]`、母親が`[V2, 2V2]`、そして息子は`[V3, 2V3]`。 これらの間隔は、厳密な順序と一致している必要があります。 

マーシャは 3 台すべての車の間にカップリングを導入します。すべての車は少なくとも`Vm`、最小の車も最大でも`2Vm`。 これにより、最小の自動車は基本的に狭い間隔に固定されます。`[Vm, min(2Vm, 2V3)]`、息子も気に入っているはずなので。 

最小の車を選択したら、順序と上限を尊重することで、中間の車と最大の車を貪欲に導き出すことができます。 この構造により検索が不要になります。チェックする必要があるのは、最小の自動車のいくつかの候補値のみです。`Vm`またはそれに近い値があり、それぞれが決定的な構築または失敗につながります。

 ## アルゴリズムのチュートリアル

 1. 最小の車の有効範囲を計算します。 マーシャの制約と息子ベアの制約を同時に満たす必要があるため、次の交差点に位置する必要があります。`[Vm, ∞)`そして`[V3, 2V3]`。 これにより、`S ∈ [Vm, 2V3]`。 
2. この交差点が空いている場合、有効な最小の車は存在しません。 その場合、解決策は存在しません。 
3. 候補となる最小の車のサイズを選択します`S`。 自然な選択は、`S = max(Vm, V3)`可能であれば、下限制約と上限制約の両方を満たすためです。 
4. 中間車のサイズを計算する`M`。 厳密に次より大きくなければなりません`S`ただし、母グマの制約も満たさなければなりません`V2 ≤ M ≤ 2V2`。 最小の有効な選択肢は次のとおりです。`M = max(S + 1, V2)`。 
5. もし`M`上限に違反しています`M > 2V2`、この候補の最小の車は失敗したため、破棄します。 
6. 車の最大サイズを計算する`L`。 満たさなければなりません`L > M`そして`V1 ≤ L ≤ 2V1`。 選ぶ`L = max(M + 1, V1)`。 
7. もし`L > 2V1`、構築は失敗します。 それ以外の場合は、有効なトリプルになります。 
8. 出力`(L, M, S)`。 

この構造は暗黙的に厳密な順序を保証し、各ベアの制約を尊重します。 最初の最小の自動車の選択が失敗した場合、増加するため、他に実行可能な調整は存在しません。`S`の制約を強化するだけです`M`そして`L`。 

### なぜ効果があるのか

 重要な不変条件は、厳密な順序を維持しながら、各ステップで各車の実現可能な最小値を貪欲に選択することです。 すべての有効な範囲は連続間隔であるため、最小の許容値を選択しても、その車にとってより大きな選択肢が存在する可能性がある有効なソリューションがブロックされることはありません。 失敗は、ローカルな選択が不適切であるというよりは、制約の交差部分が空であることが原因で発生します。 各制約は凸状の間隔を形成するため、実現可能性は組み合わせ構造ではなく、間隔の重なりのみに依存します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

V1, V2, V3, Vm = map(int, input().split())

# smallest car candidate range
S = max(Vm, V3)
if S > 2 * V3:
    print(-1)
    sys.exit()

# middle car
M = max(S + 1, V2)
if M > 2 * V2:
    print(-1)
    sys.exit()

# largest car
L = max(M + 1, V1)
if L > 2 * V1:
    print(-1)
    sys.exit()

print(L)
print(M)
print(S)
```コードは貪欲な構造を直接実装します。 マーシャと息子のクマの両方に一致する最も小さい実現可能な値として、最小の車が選択されます。 次に、中型車両と最大車両は、厳密な順序を維持し、各クマの間隔制約を満たすために必要なだけ上向きに強制されます。 各実現可能性チェックにより、そのクマの最大許容サイズを決して超えないことが保証されます。 

微妙な点は、厳密な不平等が次のように処理されることです。`S + 1`そして`M + 1`、確保する`S < M < L`追加のスワップやロジックの並べ替えは必要ありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    V1, V2, V3, Vm = map(int, input().split())

    S = max(Vm, V3)
    if S > 2 * V3:
        return "-1\n"

    M = max(S + 1, V2)
    if M > 2 * V2:
        return "-1\n"

    L = max(M + 1, V1)
    if L > 2 * V1:
        return "-1\n"

    return f"{L}\n{M}\n{S}\n"

# provided sample
assert run("50 30 10 10") == "50\n30\n10\n"

# all equal-ish boundary
assert run("10 9 8 8") != ""

# impossible case (Masha too large for son constraint)
assert run("10 9 8 20") == "-1\n"

# tight chain
assert run("100 50 25 25") != ""

# minimal spread
assert run("2 1 1 1") != ""

 ## 特殊なケース

 マーシャが息子クマの最大好感度の上限を超えて最小の車を強制的に使用する場合、重大なエッジケースが発生します。 入力用`V3 = 10, Vm = 25`、最小の車はマーシャの場合は少なくとも25でなければなりませんが、息子のクマの場合は最大でも20でなければなりません。 交差部分が空であるため、アルゴリズムは次の場合に早期に正しく拒否します。`S > 2 * V3`。 

もう 1 つの微妙なケースは、最小の車両を修理した後、中間の車両が許容範囲を超えて強制的に動かされる場合です。 たとえば、次の場合`S = 50`そして`V2 = 10`、アルゴリズムセット`M = max(51, 10) = 51`、しかし、もし`2V2 = 20`、小切手`M > 2V2`失敗を引き起こします。 これは、実現可能性は段階的に決定され、個々の制約が許容的であるように見えても、すべての制約を同時に満たせるわけではないことを示しています。 

最後の境界ケースは、すべての制約がその上限で正確に揃う場合です。たとえば、`M = 2V2`または`L = 2V1`。 「同様の」条件では平等が許可され、厳格な順序付けのみが個別に適用されるため、貪欲な構造は依然として機能します。`+1`調整。
