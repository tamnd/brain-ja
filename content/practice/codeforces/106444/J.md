 ## 解決策
 ## 問題の理解

 位置に対する値の配列とクエリのリストが与えられます。 各クエリは、配列の連続したセグメントを指定します。 各セグメントについて、その中のすべての要素を調べ、最大値が発生する場所を特定します。 複数の位置が最大値を共有する場合、問題には暗黙的に一貫したタイブレーク ルール (通常は一番左または最小のインデックス) が必要になります。 

すべてのクエリについて、この「最も高い山」のインデックスをセグメント内に記録します。 最後のタスクは、配列内の各位置について、その位置を最大値の位置として選択するクエリの数を計算することです。 

したがって、各クエリに最大値そのもので答えるのではなく、すべてのクエリ間隔にわたって各インデックスが argmax になる頻度をカウントしています。 

制約 (多数のクエリと潜在的に大きな配列サイズ) は、各セグメントをスキャンして最大値を再計算すると時間がかかりすぎることを意味します。 素朴な解決策では、各クエリをその範囲にわたって線形時間で検査し、最悪の場合は二次的な動作につながります。 これは、最大 200,000 個の要素またはクエリを含む Codeforces の問題の一般的な制限をすぐに超えます。 

値が繰り返される場合、さらに微妙な問題が発生します。 等しい最大値が存在する場合、一貫性のないタイブレークによりカウント分布が変化する可能性があります。 正しく実装するには、同じ最大値に対して同じ決定論的なインデックスが常に選択されるようにする必要があります。 

小さな例で問題を説明します。 配列が`[1, 3, 2, 3]`。 問い合わせについては`[1, 4]`、インデックス 2 と 4 の両方の値は 3 です。常に左端の最大値を選択する場合は、インデックス 2 が選択されます。 位置を追跡せずに最大値が見つかるたびに答えを更新する不注意な実装では、代わりにインデックス 4 が誤って選択され、最終的な頻度カウントが歪む可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、各クエリが個別に処理されます。 クエリ範囲の場合`[l, r]`、間のすべての要素をスキャンします。`l`そして`r`最大値とそのインデックスを追跡します。 これは、答えの定義に直接従うため、正解です。 ただし、ある場合は、`m`サイズの配列に対するクエリ`n`、各クエリにはコストがかかる場合があります`O(n)`最悪の場合、`O(nm)`総仕事量。 両方のとき`n`そして`m`が大きい場合、これは実行不可能になります。 

重要な点は、配列が静的であり、範囲最大クエリのみが必要であるということです。 これにより、「このセグメントの最大値は何か、それがどこに発生するか」を対数時間または定数時間で答えることができるデータ構造を前処理することができます。 最大値とそのインデックスの両方を格納する配列上のスパース テーブルにより、任意のクエリ範囲の argmax を計算できます。`O(1)`後`O(n log n)`前処理中。 

各クエリに効率的に答えることができれば、範囲を更新したり、動的構造を維持したりする必要はありません。 各インデックスが返される回数を最大値としてカウントするだけです。 

元のアイデアにおける範囲集約とサフィックス累積についての言及は、インデックスごとの繰り返し更新を周波数配列と最終累積ステップに置き換えることに対応します。 コストのかかる範囲ごとの伝播を行う代わりに、クエリごとに選択されたインデックスを直接インクリメントします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | スパース テーブル + カウント | O((n + m) log n) | O(n log n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ## アルゴリズムのチュートリアル

 1. 範囲最大クエリをサポートする配列上にスパース テーブルを構築します。 各エントリには値とそのインデックスの両方が格納されるため、関係を決定的に解決できます。 インデックスを保存する理由は、最終的な答えが値ではなく位置に依存するためです。 
2. クエリ範囲を 2 の累乗の等しい長さの 2 つの重複する区間に分解できるように、対数を事前計算します。 これにより、定数時間のクエリが可能になります。 
3. クエリ範囲ごとに`[l, r]`、スパース テーブルを使用して、そのセグメント内の最大要素のインデックスを取得します。 このステップは、範囲にわたる明示的なスキャンを置き換えます。 
4. 周波数配列を維持する`cnt`、 どこ`cnt[i]`インデックスを選択したクエリの数を表します`i`最大値として。 
5. すべてのクエリ結果インデックスについて`p`、増分`cnt[p]`1つずつ。 これにより、選択した位置ですべての寄与が直接集計されます。 
6. すべてのクエリを処理した後、周波数配列を出力します。 

### なぜ効果があるのか

 各クエリは、範囲内の最大値の位置という決定論的なルールに従って、インデックスを 1 つだけ個別に選択します。 スパース テーブルにより、この選択が一定時間内のすべてのクエリに対して正しいことが保証されます。 すべてのクエリは正確に 1 つのインデックスに正確に 1 単位の重みを与えるため、インデックスごとのカウントを累積すると、選択の正確な分布が保存されます。 クエリ間に相互作用は存在しないため、個別に計算された結果に対する線形集計で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_sparse(a):
    n = len(a)
    LOG = (n).bit_length()
    st = [[(0, 0)] * n for _ in range(LOG)]
    
    for i, v in enumerate(a):
        st[0][i] = (v, i)
    
    j = 1
    while (1 << j) <= n:
        length = 1 << j
        half = length >> 1
        for i in range(n - length + 1):
            left = st[j - 1][i]
            right = st[j - 1][i + half]
            if left[0] >= right[0]:
                st[j][i] = left
            else:
                st[j][i] = right
        j += 1
    
    return st

def query(st, l, r):
    length = (r - l + 1).bit_length() - 1
    left = st[length][l]
    right = st[length][r - (1 << length) + 1]
    if left[0] >= right[0]:
        return left[1]
    return right[1]

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    st = build_sparse(a)
    cnt = [0] * n
    
    for _ in range(m):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        p = query(st, l, r)
        cnt[p] += 1
    
    print(*cnt)

if __name__ == "__main__":
    solve()
```スパース テーブルの構築では、間隔の長さごとに、その間隔内の最大要素のインデックスが格納されます。 クエリ中に、範囲は 2 つの重複する 2 の累乗ブロックに分割され、それらの事前計算された最大値が比較されます。 大きい方の値のインデックスが返されます。 

周波数配列は結果を直接蓄積します。 各クエリは正確に 1 つの増分に寄与するため、ループの後にそれ以上の処理は必要ありません。 

タイブレークには注意が必要です。 比較には、`>=`そのため、値が等しい場合は、左側の間隔が優先され、より小さいインデックスが決定的に選択されます。 

## 実用的な例

 配列を考えてみましょう`a = [2, 1, 3, 3]`クエリ付き`[1,4]`、`[2,3]`、 そして`[3,4]`。 

最初のクエリの場合`[1,4]`、最大値は`3`、インデックス 3 と 4 で発生します。タイブレーク ルールはインデックス 3 を選択します。 

2 番目のクエリの場合`[2,3]`、セグメントは`[1,3]`、最大値はインデックス 3 です。 

3 番目のクエリの場合`[3,4]`、両方のインデックスには以下が含まれます`3`、左端のインデックス 3 が選択されます。 

| クエリ | 範囲 | 最大インデックス | CNTの状態 |
 | --- | --- | --- | --- |
 | 1 | [1,4] | 3 | [0,0,1,0] |
 | 2 | [2,3] | 3 | [0,0,2,0] |
 | 3 | [3,4] | 3 | [0,0,3,0] |

 このトレースは、最大構造が同一であるため、すべてのクエリが一貫して同じインデックスに解決されることを示しています。 

2 番目の例では、`a = [5, 1, 4, 2]`クエリ付き`[1,2]`、`[1,3]`、`[3,4]`。 

| クエリ | 範囲 | 最大インデックス | CNTの状態 |
 | --- | --- | --- | --- |
 | 1 | [1,2] | 1 | [1,0,0,0] |
 | 2 | [1,3] | 1 | [2,0,0,0] |
 | 3 | [3,4] | 3 | [2,0,1,0] |

 これは、重複する範囲が同じ支配的なインデックスを繰り返し強化する様子を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n + m) | スパーステーブルの前処理には時間がかかります`n log n`、各クエリは O(1) |
 | スペース | O(n log n) | スパース テーブルには、配列の複数のレベルが格納されます。 

実際には前処理とクエリ処理の両方がほぼ線形であるため、このソリューションは一般的な制約内に問題なく適合します。 入力サイズが大きい場合でも、定数時間のクエリ動作により高速な実行が保証されます。

 ## 特殊なケース

 すべての要素が等しい場合、すべてのクエリは完全にタイブレークに依存します。 のような配列の場合`[5, 5, 5]`そしてクエリ`[1, 3]`の場合、左偏りのマージにより、スパース テーブルは一貫してインデックス 1 を返します。 繰り返されたクエリはインデックス 1 にのみ蓄積され、大きく偏った度数分布が生成されます。 比較ルールはクエリ時だけでなくすべてのマージ ステップで決定論を強制するため、アルゴリズムはこれを正しく処理します。 

単一要素の配列の場合、入力に関係なく、すべてのクエリ範囲が同じインデックスに折りたたまれます。 のために`a = [42]`、任意のクエリ`[1,1]`常にインデックス 1 を返し、スパース テーブルは単一のレイヤーに縮退します。 クエリ ロジックでは 1 を超える最小範囲長が想定されていないため、アルゴリズムは引き続き機能します。
