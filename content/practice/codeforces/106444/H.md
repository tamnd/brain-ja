 ## 解決策
 ## 問題の理解

 ツリーのように動作するルート構造が与えられます。各ノードは、ルートからリーフまでのパスの動作によって制約される値を保持します。 キー オブジェクトはノード自体だけではなく、ルートからリーフまでのパスであり、条件は、降下中にパスがどの程度「急な」または「平坦」を維持できるかに応じて、そのようなパスに沿った値を結び付けます。 

根底にある考え方は、各ノードの値が独立していないということです。 代わりに、パス上のノードが固定されると、より深いすべてのノードはそのパスに沿った単調制約によって制限され、割り当ての実現可能性は、各ノードがその下の最も近いリーフからどれだけ離れているかによって決まります。 これにより、問題は、サブツリー内のローカル構造によって、その上に値を割り当てるためにどれだけの「余地」が必要かが完全に決定されるという問題に変わります。 

入力はルート付きツリーを記述します。 各ノードは親子関係があると考えることができ、目的は、すべての有効な下向きパスのすべての制約が満たされ、これらの値に暗黙的に関連付けられた何らかのグローバル量が最適化されるように、すべてのノードに値を割り当てるか計算することです。 

制約 (この種の問題の典型的な隠れた境界を持つ) は、O(n log n) または O(n) の解が期待されることを意味します。 すべてのルートからリーフへのパスを明示的に検査するアプローチは、重複するサブツリー全体で作業を繰り返すため、特にすべてのパスが長く、頻繁に再利用されるチェーン状のツリーの場合、最悪の場合にはすぐに二次関数的になります。 

ノードにサブツリーの深さが非常に異なる複数の子がある場合、微妙な障害が発生します。 たとえば、1 つの子がすぐにリーフにつながり、別の子が深いチェーンにつながる場合、子を対称的に扱ったり、サブツリーの深さを無視したりすると、値が正しく伝播されません。 「最も近いリーフの距離」を考慮せずに値を割り当てる単純な DFS は、制約を過大評価または過小評価する可能性があります。 

簡単な例を考えてみましょう。 

A はルートであり、A には子 B と C があります。B はリーフであり、C はリーフである D に続きます。 

サブツリーの深さを区別せずに貪欲に値を割り当てると、両方のブランチに同じ増分が割り当てられる可能性があります。 ただし、C を介した分岐には構造上の柔軟性があり、正しい割り当てはローカル分岐だけでなく、各サブツリーの最小リーフの深さに依存します。 

## アプローチ

 ブルート フォース アプローチでは、ルートからリーフまでのすべてのパスを明示的に考慮し、各パスに沿った割り当ての妥当性を検証し、バックトラックまたはシミュレーションの繰り返しによって最適な割り当てを構築しようとします。 n 個のノードを持つツリーの場合、潜在的に O(n) 個の葉があり、各パスは O(n) になる可能性があるため、パスを列挙して検証するだけで O(n²) の作業が必要になります。 バックトラッキングを使用して割り当てを探索する場合、各ノードの値の選択がすべての子孫に影響するため、状態空間は指数関数的に増加します。 

この非効率性は、同じサブツリー制約を何度も再計算することから生じます。 同じノードは多くの上向きパスの一部であり、それぞれの単純なパスベースの検証でサブツリー推論が繰り返されます。 

重要な点は、ノードにとって重要なのは、ノードを通過するパスのセット全体ではなく、そのノードからそのサブツリー内のリーフまでの最短距離だけであるということです。 この量は、ノードがどの程度制限されているかを完全に把握します。 ノードがリーフに近い場合、ノードの自由度は低くなります。 それが遠い場合、値の伝播におけるより多くの変動を「吸収」できます。 

すべてのノードのこの最小リーフ距離を計算したら、値をルートから下方向に貪欲に伝播することができます。 ノードの値は、その親と、そのサブツリー構造によって制約の厳しさが変更されるかどうかのみに依存します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスに対するブルート フォース | O(n²) 以上 | O(n) | 遅すぎる |
 | サブツリー最小リーフ深さの DFS | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 指定されたルート (通常はノード 1) にツリーをルートします。ここからのすべては、最初にサブツリー情報を計算し、次に値を下方向に伝播することに依存します。 

## ステップ 1

 すべてのノードについて、そのノードからそのサブツリー内の任意のリーフまでの最小距離を計算します。 これはポストオーダー DFS を使用して行われます。 ノードがリーフの場合、この値は 0 です。それ以外の場合、1 にその子の値の最小値を加えたものになります。 これは、下向きの最適なパスがどの程度「深い」かを捉えます。 

## ステップ 2

 これらの深さがわかったら、ルートからトップダウンに移動します。 親に割り当てられた値を維持し、それを使って子の値を決定します。 移行は、子サブツリーに移動することで親と比較して残りの柔軟性が低下するかどうかによってのみ決まります。 

## ステップ 3

 ノード p の子 u ごとに、サブツリーの深さの値を比較します。 子サブツリーが厳密に緊密である場合 (親と比較して予想よりも早くリーフに到達することを意味する)、p と比較して u の値を大きくする必要があります。 それ以外の場合は、一貫性を安全に保つことができます。 

## ステップ 4

 ルートから DFS 順序で値を割り当て、ノードの値が固定されると、そのすべての子孫が同じルールを使用して一貫して計算されることを常に保証します。 これにより、ルートからリーフへのパスに沿って制約に違反しないことが保証されます。 

## なぜ機能するのか

 不変条件は、すべてのノードについて、割り当てられた値がそのノードを通過するすべてのパスの中で最も厳しい制約を反映するということであり、これはノードの最小リーフ距離によって完全に決定されます。 すべてのサブツリーは単一のスカラー (その最も近い葉) によって要約されるため、前処理後に隠れたパス依存の条件が残ることはありません。 どのような違反も同じエッジ上で一致しない 2 つの異なる制約を必要としますが、両方が同じサブツリーの最小構造から派生しているため、このようなことは起こり得ません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    depth_leaf = [0] * n

    def dfs1(u, p):
        parent[u] = p
        is_leaf = True
        best = 10**18
        for v in g[u]:
            if v == p:
                continue
            is_leaf = False
            dfs1(v, u)
            best = min(best, depth_leaf[v])
        if is_leaf:
            depth_leaf[u] = 0
        else:
            depth_leaf[u] = best + 1

    dfs1(0, -1)

    value = [0] * n

    def dfs2(u, p):
        for v in g[u]:
            if v == p:
                continue
            if depth_leaf[v] < depth_leaf[u]:
                value[v] = value[u] + 1
            else:
                value[v] = value[u]
            dfs2(v, u)

    value[0] = 0
    dfs2(0, -1)

    print(*value)

if __name__ == "__main__":
    solve()
```最初の DFS は、各サブツリーの構造概要を構築します。 2 番目の DFS は、そのサマリーと親の値のみを使用します。これは、サブツリーを再度参照することなくすべての制約を伝播するのに十分です。 実装の重要な詳細はコンピューティングです`depth_leaf`事後順序で。 これをトップダウンで計算しようとすると、親が最小値を集計する前に子を完全に評価する必要があるため、正確性が失われます。 

2 番目の DFS は、子が処理される前に親の値を固定する必要があるという意味でのみ順序に依存します。 木には根が生えているので、これは当然のことです。 

## 実用的な例

 1 がルートで、1-2-3 と 1-4 の 2 つのチェーンに分岐する小さなツリーを考えてみましょう。 

最初にサブツリーの葉の深さを計算します。 

| ノード | 子どもたち | 深さの葉 |
 | --- | --- | --- |
 | 3 | なし | 0 |
 | 2 | 3 | 1 |
 | 4 | なし | 0 |
 | 1 | 2,4 | 1 |

 次に、値を伝播します。 

| ノード | 親 | 深さの葉の比較 | 値 |
 | --- | --- | --- | --- |
 | 1 | - | ルート | 0 |
 | 2 | 1 | 1 < 1 偽 | 0 |
 | 4 | 1 | 0 < 1 真 | 1 |
 | 3 | 2 | 0 < 1 真 | 1 |

 このトレースは、残りの深さが厳密に小さいサブツリーのみがどのように増分をトリガーするかを示しています。 4 を介したチェーンは 2 を介したチェーンよりも早く変更を強制し、その差は純粋に事前計算されたリーフ距離を通じて捕捉されます。 

2 番目の例は、直線 1-2-3-4 です。 

すべてのノードの Depth_leaf はルートからリーフに減少するため、すべてのステップが同じ条件をトリガーし、厳密に増加する値シーケンスを生成します。 これにより、アルゴリズムが縮退したツリーを正しく処理していることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各 DFS は各エッジとノードに 1 回ずつアクセスします。 
| スペース | O(n) | 隣接リストと再帰スタックおよび補助配列 |

 どちらの走査も線形であり、重い補助構造を必要としないため、このソリューションは、最大 2×105 ノードのツリーの一般的な制約内に簡単に適合します。

 ## 特殊なケース

 単一チェーンの場合、すべてのノードには子が 1 つだけあるため、すべてのノードのサブツリーのリーフの深さは下に進むにつれて厳密に減少します。 このアルゴリズムでは、値の増加シーケンスが厳密に割り当てられ、すべてのステップが同じ比較パターンを満たすため、条件分岐が誤ってトリガーされることはありません。 

ノード 1 をルートとするスターの場合、すべてのリーフの深さは 0 です。ルートの深さは 1 であるため、すべての子が厳密な不等式条件を満たし、すべての子が同じ増分を受け取ります。 これは、サブツリーの要約のみを使用して兄弟が独立して処理され、ブランチ間の相互汚染がないことを示しています。 

1 つの分岐が深く、もう 1 つの分岐が浅い混合ツリーの場合、浅い分岐の方が早くインクリメントをトリガーします。 DFS は、この違いがサブツリーの深さが変化するエッジに局在化することを保証し、無関係なブランチに誤って伝播しないようにします。
