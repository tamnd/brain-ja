 ## 解決策
 ## 問題の理解

 行のコレクションが与えられ、各行には、最終的な答えへの寄与が 2 つのグローバル連続変数にどのように依存するかを定義するパラメーターがあります。 2D 平面内の点を選択すると、各行がその点にコストを割り当てると考えることができます。 総コストはすべての行の合計であり、タスクはこの総コストを最小化する点を選択することです。 

重要な構造特性は、各行のコスト関数が平面上の単一の線形式ではなく、最大数の線形式であることです。 そのため、各列によって形成される表面は区分的に線形で凸面になります。 これらの行表面を合計すると凸性が維持されるため、グローバル関数は連続領域にわたって凸になります。 これにより、一意のグローバル最小領域が存在することが保証され、ローカル ミニマ トラップが排除されます。 

これは凸最適化構造を持つ Codeforces 問題であるため、暗黙の制約は大きくなります。 行数が十分に大きいため、$O(n^2)$あるいは繰り返しても$O(n \log n)$外部検索内の評価が遅くなりすぎます。 2D 検索空間全体で関数を何度も評価する単純なアプローチは合格しません。 

微妙な難しさは、関数が凸関数であっても、単一点での評価が簡単ではないことです。 各行では、いくつかの線形ケースのうちどれがアクティブであるかを決定する必要があり、それを行ごとに独立して行うと、高い定数係数が得られます。 

典型的なエッジケースは、すべての行が同じパラメータを持つ場合に発生します。 その場合、表面全体は単一の凸面に縮小され、最適値は一貫した境界点で自明になります。 単純な 3 項検索はまだ機能する可能性がありますが、不注意に実装すると、特にほぼ等しい値を比較する場合に浮動小数点精度が不安定になる可能性があります。 

もう 1 つのエッジ ケースは、最適な点が多くの行の領域間の境界上に正確に存在する場合です。 このような場合、浮動小数点比較が不安定であれば、行ごとの単純な領域選択が 2 つの式の間で変動する可能性があります。 

## アプローチ

 まず、直接的なブルートフォース解釈を観察することから始めます。 候補点を選ぶと$(x, y)$、すべての行を反復処理し、それらの区分的線形コスト関数を評価することで、総コストを計算できます。 各行は一定数の比較を必要とするため、1 回の評価にコストがかかります$O(n)$。 最小値を見つけるには、ネストされた三項探索などの 2D 凸最適化戦略を使用できます。$x$、それぞれについて$x$、検索してください$y$、毎回全コストを再計算します。 

これではすぐに高価になってしまいます。 各三項検索で約 60 回の評価が必要な場合でも、入れ子構造により数千の完全な評価が行われます。$O(n)$スキャンの結果、$O(n \cdot \log^2 C)$、これは大規模なものには遅すぎます$n$。 

重要な観察は、関数が 2 次元で凸であることですが、さらに重要なのは、各行の寄与が 3 つの線形関数の最大値であることです。 つまり、プレーンは、各行が線形に動作する領域に分割できるということです。 これらの領域の境界は直線であるため、関数は全体的に領域ごとの線形式の合計になります。 

クエリごとに各行を再計算する代わりに、これらの領域の構造を行ごとに事前計算します。 各行は 3 つの線形候補を提供し、アクティブな線形形式は、クエリ ポイントが 2 つのしきい値境界を基準にしてどこにあるかによって異なります。 これらの境界は、次の比較として表現できます。$x$そして$y$事前計算された定数と 1 つの追加の対角しきい値に対して。 

これらのしきい値が抽出されると、各行は以下との比較のみに依存するケースに分類できます。$x$または$y$、両方を複雑な方法で同時に行うわけではありません。 これにより、評価がソートされた構造に対する範囲カウントの問題の組み合わせに縮小されます。 

次に、これらのしきい値パラメーターによって行をソートし、固定クエリ ポイントについて、異なるしきい値領域に該当する行からの寄与の合計を計算できる 2 つのマージソート ツリー スタイル構造を構築します。 各ノードは関連する線形係数のプレフィックス合計を格納するため、クエリは対数トラバーサルと事前計算された配列内での二分探索になります。 

これにより、各評価が$O(n)$おおよそに$O(\log^2 n)$、少数の凸探索反復または直接最適化と組み合わせる場合には、これで十分です。

 ## アルゴリズムのチュートリアル

 1. 各行を 3 つの線形式に前処理して、その行のさまざまな領域での寄与を定義します。$(x, y)$飛行機。 このステップが必要なのは、元のコスト定義が区分的であり、効率的に集計するには明示的な線形形式が必要であるためです。 
2. 各行から、どの領域がアクティブであるかを決定する 3 つの幾何学的しきい値を抽出します。 これらのしきい値は、線形部分を分離する垂直、水平、および対角の境界条件に対応します。 
3. 行の動作が切り替わるタイミングを制御するしきい値に基づいて行を並べ替えます。$x$そして$y$。 並べ替えにより、後で行ごとの分岐ではなく範囲分割によってすべてのクエリに回答できるようになります。 
4. 2 つのマージソート ツリーを構築します。各ツリーには、行の寄与に関連付けられたさまざまな係数のプレフィックス合計が格納されます。 1 つのツリーは 1 つのしきい値レジームによって支配されるクエリをサポートし、もう 1 つは補完的なレジームを処理します。 この分離により、行ロジックを繰り返し再計算することが回避されます。 
5. クエリ時に、しきい値がクエリ ポイントの片側にあるかどうかに基づいて、行をグループに分割します。 各グループは一貫した線形式に対応しているため、行ごとの分岐は必要ありません。 
6. 各グループについて、セグメント ツリーを使用して係数の合計を計算します。 各クエリは、完全なスキャンではなく、少数のプレフィックス合計計算の組み合わせになります。 
7. 集計された値を組み合わせて、候補の最終コストを計算します。$(x, y)$。 これにより、対数時間での凸関数の単一評価が生成されます。 

正確性は、しきい値による並べ替えによって引き起こされる各パーティション内で、すべての行が 1 つの固定線形式を正確に使用するという不変条件に基づいています。 すべての行が一貫して分類されるため、合計はどのクエリ ポイントでも正確なままになります。

class MergeSortTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.tree = [[] for _ in range(2 * self.size)]
        self.pref = [[] for _ in range(2 * self.size)]
        for i, v in enumerate(arr):
            self.tree[self.size + i] = [v]
        for i in range(self.size - 1, 0, -1):
            self.tree[i] = sorted(self.tree[2 * i] + self.tree[2 * i + 1])
        for i in range(1, 2 * self.size):
            s = 0
            self.pref[i] = []
            for v in self.tree[i]:
                s += v
                self.pref[i].append(s)

    def query(self, l, r, x):
        res = 0
        l += self.size
        r += self.size
        while l <= r:
            if l % 2 == 1:
                res += self._sum_leq(l, x)
                l += 1
            if r % 2 == 0:
                res += self._sum_leq(r, x)
                r -= 1
            l //= 2
            r //= 2
        return res

    def _sum_leq(self, i, x):
        import bisect
        idx = bisect.bisect_right(self.tree[i], x)
        return self.pref[i][idx - 1] if idx else 0

 ## 特殊なケース

 重要なエッジ ケースは、すべての行が同一のしきい値パラメーターを持つ場合に発生します。つまり、すべての行が、次の条件に関係なく、常に同じ線形式を選択します。$(x, y)$。 この状況では、マージソートツリーは単一の均一な合計に縮退します。 このアルゴリズムは引き続きバイナリ検索を通じてクエリを処理しますが、すべての検索で完全なプレフィックスまたはゼロが返され、分岐の正しさに依存することなく一貫した結果が得られます。 

別のエッジ ケースは、クエリ ポイントがしきい値の境界上に正確に位置する場合に発生します。 たとえば、行が使用から切り替わった場合、$x$-に支配される$y$- で支配的な表現$x = 5$、正確にクエリする$x = 5$一貫してどちらかの側を選択しなければなりません。 二分検索では厳密な不等号分離が使用されるため、ソートされた構造により決定論的な処理が保証され、境界値は常に同じプレフィックス セグメントに分類されます。 

最後のケースは、行がレジーム間で均等に分割され、最大の断片化が発生する場合です。 その場合でも、各クエリはマージソート ツリーで対数分割を実行するだけであり、行ごとの評価はトリガーされません。 これは、しきい値の敵対的な分布の下でも、最悪の場合のパフォーマンスが安定したままであることを確認します。
