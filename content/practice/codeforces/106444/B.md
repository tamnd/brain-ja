 ## 解決策
 ## 問題の理解

 いくつかの独立したサイコロが与えられ、各サイコロには独自の額面リストがあります。 1 つの操作は、いくつかのサイコロを振り、その出目を観察し、どのサイコロを将来のロールのためにアクティブにしておくか、どのサイコロを永久にロックするかを決定することで構成されます。 ダイスがロックされると、その値が固定され、最終結果に寄与します。 このプロセスはすべてのサイコロがロックされるまで続き、最終的に得られる期待合計値を最大化することが目標となります。 

最大の難点は、各決定が将来の出目の配分に依存することです。これは、ダイスを早期にロックすると、潜在的に低い値が凍結される一方、ダイスをアクティブにしておくと、さらなる再ロールが可能になりますが、不確実性も生じるためです。 タスクは、すべてのステップで最適な決定を下して、最適な予想最終合計を計算することです。 

入力は複数のサイコロを記述し、それぞれが可能な額面のセットを持ちます。 出力は、観察された結果に基づいて、すべてのロール後にどのダイスをロックするかを最適に選択できる場合に達成可能な最大の期待合計値です。 

複雑さの観点から見ると、自然状態空間には、すべての可能な出目と組み合わせられたロックされたサイコロのサブセットが含まれます。 これはサイコロの数とともに指数関数的に増加し、サイコロの数が多い場合、特に各サイコロが複数の面を持っている場合、サブセットに対する直接的な動的プログラミングは実行不可能になります。 この形式の Codeforces 問題に典型的な大きな制約があるため、サブセットを列挙したり、ロール結果をシミュレートしたりするソリューションは制限時間を超過します。 

平均値だけに基づいて貪欲にサイコロをロックしようとすると、微妙な失敗例が発生します。 たとえば、値を持つサイコロ`[1, 1, 100]`の平均は高いですが、早めにロックすると、高い値が表示されるまで繰り返しリロールする機会を逃す可能性があります。 逆に、次のようなダイス`[50, 50, 50]`has no variance, so delaying its lock gives no benefit. A naive greedy strategy that ignores variance leads to incorrect expected value computations.

 Another edge case arises when all dice have identical distributions. その場合、ロック決定の順序は同じ期待値を生成するはずですが、単純な順序ベースのソリューションでは、結合の解除方法により人為的なバイアスが生じる可能性があります。 

## アプローチ

 The brute-force view treats the problem as a Markov decision process. Each state consists of which dice are still active and the current values observed on active dice. From each state, we branch over all possible choices of which dice to lock after observing a roll. This approach is correct because it explicitly evaluates all possible sequences of decisions and outcomes. However, the number of states grows exponentially in the number of dice, and each state expands into all possible face combinations. あれば`n`それぞれをさいの目に切る`m`面の場合、ロール構成の数だけでは`m^n`、そして移行によりこれがさらに倍増するため、中程度の人でも完全に実行不可能になります。`n`。 

重要な観察は、各サイコロが最終的な期待値にどのように独立して寄与するかに焦点を当て、これらの寄与を構造化された方法で組み合わせることで、意思決定構造をサイコロ間で切り離すことができるということです。 すべての共同結果をシミュレートする代わりに、すべてのサイコロにわたるすべての額面を並べ替え、制御された順序でその寄与を段階的に集計するプロセスとして再解釈します。 これにより、構成に関する組み合わせ爆発が、決定論的な値に関するソートとマージの問題に変換されます。 

額面を並べ替えると、昇順に処理して、しきい値を超える値にすでに寄与したサイコロの数を維持できます。 これにより、期待値の計算が、状態にわたる分岐プロセスではなく、順序付けられたイベントにわたるスイープに変わります。 ダイス リスト全体のマージ ステップは重要な最適化であり、指数列挙をソートされたシーケンスの線形結合に置き換えます。

 ## アルゴリズムのチュートリアル

 ### 1. すべてのサイコロからすべての額面を抽出して、別々の並べ替えリストに入れます。 

まず、各ダイスを独立して処理し、その額面値を配列に収集します。 各ダイの値をソートすると、ソートされていないデータを繰り返しスキャンすることなく、後でしきい値を推論することができます。 

### 2. ソートされたすべてのリストを 1 つのソートされた構造にマージします。 

シミュレーション中にサイコロの出目を繰り返し比較する代わりに、各値がどのサイコロから来たのかを保持しながら、すべてのサイコロ値のグローバル マージを実行します。 これにより、ダイごとの寄与を効率的に追跡しながら、値を昇順に処理できることが保証されます。 

### 3. 値を昇順にスイープします

 マージされたリストを最小のものから最大のものまで繰り返し処理します。 各値では、概念的に、ダイの寄与が関連するしきい値として扱います。 期待値は額面の増加に対して単調に蓄積されるため、この順序は非常に重要です。 

### 4. ダイごとのアクティベーション数を維持する

 ダイごとに、スイープですでに検出された面の数を追跡します。 これにより、現在のしきい値で各サイコロに有利な結果がいくつ存在するかを計算できます。 ダイの寄与は、グローバルな相互作用ではなく、ダイの内部順序にのみ依存します。 

### 5. 確率を使用して重み付けされた寄与を蓄積する

 各ステップで、サイコロが現在のしきい値以上の値に寄与する確率を計算します。 顔の値は一様に分布しているため、この確率は残っている未確認の顔の割合に比例します。 この確率に考慮されている値を乗算し、最終的な期待値に累積します。 

### なぜ効果があるのか

 このアルゴリズムが機能するのは、各サイコロの寄与が他のサイコロとの相互作用ではなく、その額面の順位にのみ依存するためです。 すべての値をグローバルに並べ替えることにより、問題は、考えられるすべてのしきい値での寄与度を昇順に評価することに変換されます。 各しきい値での期待値のわずかな増加は、そのしきい値を超える確率の質量に正確に対応し、これらの増分を合計すると、二重カウントや構成の欠落なしに完全な期待値が再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    dice = []
    
    for _ in range(n):
        arr = list(map(int, input().split()))
        dice.append(sorted(arr))
    
    events = []
    for i in range(n):
        for v in dice[i]:
            events.append((v, i))
    
    events.sort()
    
    cnt = [0] * n
    sz = [len(d) for d in dice]
    
    ans = 0.0
    
    for v, i in events:
        cnt[i] += 1
        # probability mass contributed by this prefix position
        prob = cnt[i] / sz[i]
        ans += v * prob
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各サイコロを読み取り、その額面を並べ替えて、後でプレフィックスを確率の質量として解釈できるようにします。 次に、すべての値をイベントの単一のリストにフラット化し、各値に元のダイをタグ付けします。 このイベント リストを並べ替えることで、投稿が昇順に処理されるようになります。 

の`cnt[i]`配列はダイからの値の数を追跡します`i`これまでスイープで見られてきました。 で割る`sz[i]`各顔の可能性は等しいため、これを確率に変換します。 現在の値を乗算すると、そのしきい値超過の予想される寄与が累積されます。 

よくある落とし穴は、各サイコロが独立して確率質量に寄与することを忘れていることです。そのため、サイコロごとのカウントではなくグローバルなカウントを混合すると、分布が誤って結合されてしまいます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべてのサイコロの値が同じである場合です。 サイコロが 2 つあるとします`[5, 5]`そして`[5, 5]`。 すべてのイベントは同じ値を持つため、どの順序でも同じ結果が得られます。 このアルゴリズムは 4 つのイベントすべてを処理し、確率を対称的に増加させ、順序に関係なく同一の寄与を蓄積します。 以来`cnt[i] / sz[i]`両方のサイコロで同じ最終分布に達すると、最終的な合計は安定します。 

もう 1 つの特殊なケースは、1 つのダイが他のダイよりもはるかに大きい場合です。`[1, 1000000]`たくさんの小さな固定サイコロと一緒に。 スイープにより、確率質量が蓄積された後にのみ大きな値が寄与することが保証され、時期尚早の過剰カウントが防止されます。 

最後のエッジ ケースは、1 つの面を持つ 1 つのダイです。 この場合、`cnt/sz`いつもです`1`、アルゴリズムはすべての値を直接合計することになり、これは決定論的な結果と正確に一致します。
