 ## 解決策
 ## 問題の理解

 この問題の基礎となるオブジェクトは、すぐにはきれいな形式で表示されません。 物語を取り除いた後の核となる構造は、$n$人間が何らかの順序で処理される過程で蓄積される「怒り」という要素と量。 各順序は単一の整数値、つまり怒りの合計を生成し、すべての順列にわたってこれらの値の複数セットが得られます。 

テキストに隠されている重要な再定式化は、順列の観点から直接考える代わりに、各順序を正規の数値表現にエンコードして、各位置が独立した限定された選択に寄与できるということです。 具体的にはそれぞれの要素が$i$のみに依存する範囲内の値を提供します。$i$、合計の怒りは、これらの要素ごとの寄与の合計になります。 これにより、順列の依存関係が削除され、独立した選択セットの積に置き換えられます。 

この変換が行われると、問題は次のようになります。$n$独立したリスト、ここでリスト$i$以下のすべての整数が含まれます$0$に$i-1$、完全な選択ごとに、各リストから値を 1 つだけ選択します。 すべての選択により合計が生成されます。私たちが興味を持っているのは、$k$-すべての可能な選択の中でそのような最大の合計。 

制約はステートメントの一部では明示的に述べられていませんが、「指数関数的に大きいマルチセット上の k 番目の要素」の存在は、すべての構成を列挙することが不可能であることを強く示唆しています。 構成の合計数は次のとおりです。$1 \cdot 2 \cdot \ldots \cdot n$、階乗的に成長します。 中程度の場合でも$n$、すべての合計を強引に列挙することは不可能であり、すべての値を並べ替えることさえ問題外です。 これにより、組み合わせの空間を遅延して探索し、最初に大きな金額を優先するアプローチが強制されます。 

素朴な推論による一般的な失敗例は、合計に対して動的計画法を試みることです。 合計の範囲は管理できるように見えますが、状態の数は増加するにつれて増加します。$O(n^2)$要素ごとに、それでも直接は得られません$k$-追加の選択メカニズムを使用しない場合の 2 番目に大きい値。 もう 1 つの落とし穴は、独立性によって上位の値を貪欲に直接組み合わせることができると想定していることです。 1 つの座標でわずかに小さい値を選択すると、さまざまな組み合わせのロックが解除される可能性があるため、これは問題になります。 

## アプローチ

 ブルートフォース手法では、各リストから 1 つの値の可能な選択肢をすべて列挙し、結果の合計を計算します。 これはマルチセットの定義と直接一致するため正しいですが、複雑さの点ですぐに失敗します。 組み合わせの数は、$n!$, それでさえ$n = 15$すでに 10 億を超える州が生成されており、列挙することは不可能です。 

より構造化された観察は、各リストがすでにソートされており、問題は合計を最大化またはランク付けするために各リストから 1 つの要素を選択することに帰着します。 これは古典的な「並べ替えられたリストからの k 個の最適な組み合わせ」問題です。 強引な爆発はすべての組み合わせを探索することで起こりますが、重要な構造は、単一の座標を調整することで、どのような状態でもより良い状態にも悪い状態にも変換できるということです。 これにより、ノードがインデックスのタプルであり、エッジが 1 つの座標を減分することによって移動するグラフが形成されます。 

これにより、組み合わせ空間に対して最良優先検索を適用できるようになります。 可能な最大の合計から開始し、一度に 1 つの座標を減らしながら、次に最適な候補を繰り返し生成します。 優先キューは候補を合計の降順に維持し、訪問セットは重複を防ぎます。 これは本質的に、陰的グラフにおけるダイクストラのアルゴリズムの k-best 状態の類似物です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 |$O(n!)$|$O(n!)$| 遅すぎる |
 | 組み合わせに対する最良優先検索 |$O(k \cdot n \log k)$|$O(k \cdot n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 それぞれの立場を再解釈します$i$ソートされたリストがあるものとして$A_i = [0, 1, \dots, i-1]$。 便宜上、各リストを逆にして減少させ、初期状態を可能な最大の合計に揃えます。 

インデックスのタプルで状態を表します$(p_1, p_2, \dots, p_n)$、 どこ$p_i$リストからどの要素を選択したかを示します$i$。 状態の値は次の合計です。$A_i[p_i]$全体$i$。 

次に、次のように進めます。 

1. 各リストを作成する$A_i$降順で$A_i[0]$は最大値です$i-1$。 これにより、初期状態が可能な最大合計に対応することが保証されます。 
2. 状態を使用して優先キューを初期化します。$(0, 0, \dots, 0)$逆索引形式では、すべてのリストから最大の要素を選択することを意味します。 関連する合計は$\sum (i-1)$。 
3. 同じインデックスタプルを複数回処理することを避けるために、訪問済みセットを維持します。 これが必要なのは、座標デクリメントのシーケンスが異なると同じ構成になる可能性があるためです。 
4. プライオリティキューから合計が最も大きい状態を繰り返し抽出します。 各抽出により、順番に次に大きな目に見えない合計が得られます。 
5. 状態がポップされると、座標を 1 つ減らして近傍を生成します$p_i$できれば1まで。 各近傍は、選択された 1 つの値をそのリスト内の次に小さい値に置き換えることに対応し、これにより、その座標について可能な最小限の方法で合計が削減されます。 
6. 見えない各近傍を、計算された合計とともにヒープにプッシュします。 
7. 一旦停止します。$k$-番目の状態が抽出されます。 その合計が答えです。 

これが機能する理由は、一連の独立した座標減少によって最大構成からすべての有効な構成に到達できるためです。 優先キューにより、すべてのフロンティア構成の中で、常に最大の残りの合計が次に拡張されるため、抽出順序はグローバル ランキングと一致します。 訪問セットでは、各構成が 1 回だけ考慮されることが保証され、異なるパスを介した同じ状態の冗長な探索が防止されます。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    # Each list Ai = [0..i-1], we store it in decreasing order
    a = []
    for i in range(1, n + 1):
        a.append(list(range(i - 1, -1, -1)))

    # initial state: take index 0 from each list (maximum elements)
    start_idx = tuple([0] * n)
    start_sum = sum(a[i][0] for i in range(n))

    heap = [(-start_sum, start_idx)]
    seen = set([start_idx])

    cnt = 0

    while heap:
        neg_sum, state = heapq.heappop(heap)
        cnt += 1

        if cnt == k:
            print(-neg_sum)
            return

        for i in range(n):
            if state[i] + 1 < len(a[i]):
                new_state = list(state)
                new_state[i] += 1
                new_state = tuple(new_state)

                if new_state not in seen:
                    seen.add(new_state)
                    new_sum = -neg_sum - a[i][state[i]] + a[i][state[i] + 1]
                    heapq.heappush(heap, (-new_sum, new_state))

    print(0)

if __name__ == "__main__":
    solve()
```実装は概念モデルを直接反映しています。 各状態はインデックスのタプルとして格納され、合計を否定することによってヒープが最大優先度のキューとして使用されます。 近傍生成ステップでは、座標が 1 つだけ変更されます。これは、選択された 1 つの要素をそのリスト内の次に小さいオプションに置き換えることに対応します。 合計の更新は、最初から再計算するのではなく段階的に行われるため、$O(n)$遷移ごとの再計算。 

微妙な点は、各リストは降順で格納されるため、初期状態はすべてのインデックスのゼロに対応する必要があることです。 これにより、開始時の最大構成の正確さが保証されます。 

## 実用的な例

 検討してください$n = 3$。 リストは次のとおりです。$A_1 = [0]$、$A_2 = [1,0]$、$A_3 = [2,1,0]$。 最大の状態は、$(0,0,0)$合計付き$0 + 1 + 2 = 3$。 

もし$k = 1$の場合、アルゴリズムはすぐに 3 を返します。 

もし$k = 2$、私たちはポップします$(0,0,0)$、次に近傍を生成します。 

インデックス 2 を変更すると、$(0,0,1)$合計付き$0 + 1 + 1 = 2$、

 インデックス 1 を変更すると、$(0,1,0)$合計付き$0 + 0 + 2 = 2$、

 インデックス 0 の変更は無効です。 

ヒープには、合計が 2 の 2 つの状態が含まれています。2 番目の抽出では 2 が返されます。 

| ステップ | 状態 | 合計 | アクション |
 | --- | --- | --- | --- |
 | 1 | (0,0,0) | 3 | 開始 |
 | 2 | (0,0,1) | 2 | インデックス 2 から生成 |
 | 3 | (0,1,0) | 2 | インデックス 1 から生成 |

 このトレースは、アルゴリズムが中間値を欠落することなく降順で合計を正しく列挙していることを示しています。 

2 番目の例は、$n = 2$、$A_1=[0]$、$A_2=[1,0]$: 状態は$(0,0)=1$、$(0,1)=0$。 抽出された順序は 1、次に 0 であり、予想されるランキングと一致します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(k \cdot n \log k)$| それぞれの$k$抽出された状態は最大で生成されます$n$隣接ヒープ、各ヒープの操作コスト$\log k$|
 | スペース |$O(k \cdot n)$| まで保管します$k$訪問した州、それぞれの規模$n$|

 複雑さは最上位のみを探索することによって引き起こされます$k$すべてではなく構成$n!$可能性があり、典型的な制約の下で快適に適合します。$k$せいぜい周りにいる$10^5$。

 ## 特殊なケース

 主なエッジケースは次のような場合です$n = 1$。 このアルゴリズムは引き続き単一のリストを初期化し、ヒープには 1 つの状態だけが含まれます。 近隣生成は発生せず、すぐに応答が返されます。 これにより、基本ケースでは特別な処理が必要ないことが確認されます。 

もう一つのケースは次のような場合です。$k$は、到達可能な構成の合計数に等しくなります。 その状況では、ヒープは最終的にすべての状態を使い果たし、最後に抽出された値が返されます。 訪問セットにより、状態間に複数のパスが存在する場合でも、各構成が順序付けに 1 回だけ寄与することが保証されます。 

最後のエッジケースは、複数の座標が同じ合計を生成する場合です。 ヒープには同じ値を持つ個別の状態が含まれる場合がありますが、正確性は値の一意性ではなく状態の同一性に依存します。 訪問セットは重複を防ぎ、すべての等しい値の状態はマルチセットのランキング内の任意の順序で有効であるため、等しい値間の抽出順序は正確さに影響しません。
