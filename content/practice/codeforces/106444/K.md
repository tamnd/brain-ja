 ## 解決策
 ## 問題の理解

 このタスクでは、3 つの位置レイヤーにわたる階層的なルート計画の問題について説明します。 最下位レベルでは、都市内の個々の場所、国にグループ化された都市内、そして最後にグローバル構造にグループ化された国々があります。 旅行者は、その都市を出る前にその都市のすべての場所を訪問し、その国を出る前にその国のすべての都市を完了しなければなりません。 都市内では移動が柔軟で、何度でもその場所を訪れることができますが、都市と国の間​​ではその構造により、出国前に完了するという厳格なルールが課せられます。 

各場所のペアには交通費がかかります。 目標は、都市や国間の順序制約を尊重しながら、ある都市のある場所から開始し、階層全体で必要なすべての場所を訪問し、指定された目的地で終了するまでの最小総コストを計算することです。 コストは都市内の移動と都市間の移動の両方に依存し、最終的な答えは両方の最適な組み合わせを反映する必要があります。 

この構造によって暗示される制約は十分に大きいため、すべての位置を単一のグラフとして均一に扱うアプローチは直ちに実行不可能になります。 まである場合$N$場所のすべてのサブセットにわたる単純な最短パスまたは DP は、次のようにスケールされます。$O(2^N)$あるいはせいぜい$O(N^3)$、すぐに壊れます$N$数百を超えます。 したがって、階層分解はオプションではなく、問題を管理可能な部分問題に減らす唯一の方法です。 

微妙なエッジ ケースは、都市内ではノードの再訪問が許可されるが、都市間では許可されないという事実から生じます。 単純なアプローチでは、あらゆる場所での再訪問が誤って禁止される可能性があり、コストが人為的に増加することになります。 都市間の最適な移行が都市内の入口点と出口点の両方に依存する場合、別のエッジケースが発生します。 この依存関係を無視すると、エッジで重要な状態情報が失われる、誤った「圧縮された都市グラフ」が生成されます。 

たとえば、ある都市に非対称コストの 2 つの場所 A と B があり、すべての場所を訪問する必要があるとします。 入口点と出口点に関係なく都市の単一の最短経路コストを仮定すると、A から B を経由して別の都市への移行が誤って過小評価または過大評価され、全体的な最適性が損なわれる可能性があります。 

## アプローチ

 ブルート フォース ビューでは、システム全体が 1 つの巨大な状態グラフとして扱われます。 州は、どの場所を訪問したか、および旅行者が現在どこにいるかをエンコードする必要があります。 遷移は、元の距離グラフに沿った移動に対応し、必要なすべてのノードが訪問されるまでコストが累積されます。 これは、すべての場所にわたる古典的なビットマスク動的プログラミングであり、おおよその複雑さがあります。$O(2^N \cdot N^2)$。 これはすぐに不可能になります$N$20～25くらいを超えます。 

重要な観察点は、構造が階層的で分離可能であるということです。 都市内では、ある場所から入り、その間のすべてのノードを訪問しながら別の場所から出るための最良の方法だけを気にします。 これにより、各都市がエンドポイントのペアにわたる完全な伝達関数に縮小されます。 同じ考え方が国にも当てはまります。つまり、各国はその都市にわたる状態移行システムに還元でき、各都市はエンドポイント間のコストによってすでに要約されています。 最後に、同じロジックを使用して国レベル自体を再度圧縮できます。 

問題は、最下位レベルでの全ペア最短パスに対するフロイド・ウォーシャルと組み合わせた「サブセット DP 圧縮」と、より高いレベルでのビットマスク DP を繰り返し適用することになりますが、常に縮小された状態空間上で行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての場所に対するブルートフォース |$O(2^N \cdot N^2)$|$O(2^N)$| 遅すぎる |
 | 階層型 DP 圧縮 |$O(\sum \text{local DP + Floyd + transitions})$|$O(N^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 各都市内の最短経路を計算する

 すべての都市について、内部の位置グラフに対してフロイド-ウォーシャルを実行します。 これにより、中間の再訪問が許可されている場合でも、その都市内の任意の場所のペア間の最小コストが得られます。 このステップが必要なのは、後の DP では生のエッジではなくペアごとの距離のみが必要になるためです。 

### ステップ 2: 各都市をエンドポイント DP 状態に圧縮する

 各都市について、特定の場所から開始し、その都市内のすべての場所を訪問し、別の場所で終了するための最小コストを返す場所のサブセットに対して DP を計算します。 

この DP は、訪問した場所と現在のエンドポイントのビットマスクによってインデックス付けされます。 遷移は、事前に計算された最短パスを使用して未訪問ノードに移動することにより、訪問済みセットを拡張しようとします。 結果は行列です$costCity[u][v]$u から始まり v で終わる都市全体を横断するための最小コストを意味します。 

都市内の有効なルートはすべて訪問の順列にすぎず、フロイド-ウォーシャルはすでに連続する訪問間の最短移動を保証しているため、この圧縮は正しいです。 

### ステップ 3: 国内の都市レベルの移行を構築する

 ここで各都市をノードとして扱いますが、位置 u から都市に入り、位置 v から出るにはコストがかかることを考慮する必要があります。$costCity[u][v]$。 都市ごとの入口と出口の位置の固定ペアについては、都市全体のビットマスク DP を使用して、国内のすべての都市を横断する最適な方法を計算します。 

DP 状態は都市のサブセットにわたって定義されており、都市ごとに入口と出口の選択肢も用意されています。 これにより、特定の都市の出入口位置のペアごとに、その国のすべての都市を完了するための最小シルバーコストが得られます。 

このステップでは、各国の縮小表現、つまり都市内の入口と出口の位置を最適な国レベルのコストにマッピングする関数が生成されます。 

### ステップ 4: 最適な都市訪問順序を抽出する

 DP から、ある国の都市の最適な順序を再構築または暗黙的に導き出します。 特殊な構造により固有の最適パスが保証されるため、DP が固定されれば複数の順列を考慮する必要がありません。 

この順序は、都市間のエンドポイントの選択肢をどのようにつなぎ合わせるかを決定するため、非常に重要です。 

### ステップ 5: 都市間のブロンズ遷移を計算する

 固定された都市の順序を考慮して、連続する都市間の正確なエンドポイント遷移を計算することでソリューションを改良します。 隣接する都市のペアごとに、前の都市の考えられるすべての出口位置を次の都市のすべての入口位置に接続する DP を実行します。 

これにより、都市間の移行と一貫して都市内のエンドポイントを考慮した洗練されたコストが生成されます。 

### ステップ 6: 国レベルで繰り返す

 同じアイデアを 1 つ上のレベルで繰り返します。 国も同様に、エンドポイント間の移行に圧縮されます。 再び国に対してビットマスク DP を実行し、次に国の独自の最適な順序を再構築し、最後に境界位置に対して DP を使用してそれらをステッチします。 

### なぜ効果があるのか

 このアルゴリズムは、あらゆるレベルで、詳細なグラフ走査問題を境界状態を越える完全な伝達関数に置き換えます。 不変条件は、圧縮された各単位 (都市または国) が、内部構造を必要とせずに、入口点と出口点のペア間の最適コストを正しくエンコードすることです。 ユニット間の遷移はこれらの境界コストのみに依存するため、グローバルな最適性は、DP 合成によって保存されたローカルな最適性から得られます。

## 実用的な例

 元のステートメントには明示的なサンプルが含まれていないため、国ごとに 2 つの都市を含む単純化されたインスタンスを考えてみましょう。 

都市 1 には場所 A と B があり、A から B までのコストは 3、B から A までのコストは 1 になります。都市 2 には場所 C と D があり、それらの間の対称コストは 2 です。 

まず都市の DP テーブルを計算します。 

| ステップ | 都市 1 州 | 都市 2 州 |
 | --- | --- | --- |
 | フロイド・ウォーシャル | A-B最短固定 | C-D最短固定 |
 | エンドポイント DP | A→B = 3、B→A = 1 | C→D = 2、D→C = 2 |

 ここで、最良の順序が都市 1、次に都市 2 であると仮定します。総コストを最小限に抑えるために、都市 1 の出口と都市 2 の入り口を選択して、エンドポイント間の遷移を計算します。 

| 移行 | 選択 | コスト |
 | --- | --- | --- |
 | 市内1番出口 | B | 支出コストが低いため最適 |
 | 都市 2 エントリー | C | 最小受入コスト |
 | 総縫製コスト | A→B + B→C + C→D | 合計最小値 |

 これは、エンドポイントの選択が都市の内部構造と外部遷移の両方にどのように依存するかを示しています。

 ## 特殊なケース

 主なエッジケースは、都市に同様に最適な入口と出口のペアが複数ある場合です。 その状況では、任意の代表ペアを選択すると、全体的な最適性が損なわれます。 DP は、1 つだけではなく、すべてのエンドポイントの組み合わせを保存する必要があります。 

別のエッジ ケースは、中間ノードが再利用されるかどうかによって都市内の最短パスが異なる場合に発生します。 Floyd-Warshall はこれを解決しますが、サブセット DP の前に適用された場合に限ります。 

最後の微妙なケースは、最適な都市の順序が前の都市内の出口ポイントの選択に依存する場合です。 したがって、DP は、移行が国レベルで完全に評価され、レイヤー間の一貫性が確保されるまで、エンドポイントの選択へのコミットメントを遅らせる必要があります。
