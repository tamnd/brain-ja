 ## 解決策
 ## 問題の理解

 整数の配列が与えられます`a`そして順列`p`サイズの`n`。 配列はノードに割り当てられた数値を表し、順列は各ノードが次のような有向グラフを定義します。`i`ノードを指す`p[i]`。 クエリには 3 つのタイプがあります。`a`、置換エッジに続く特定のノードから到達可能なすべてのノードに値を追加し、置換内の 2 つのエントリを交換して、グラフ構造を変更します。 出力では、先行するすべての更新が適用された後、合計クエリに答えるだけで済みます。 

制約は高いです:`n`そしてクエリの数`q`は最大 200,000 まで可能で、次の値は`a[i]`そしてアップデート`x`大きさは 10^8 に達する可能性があります。 たとえば、更新ごとに到達可能なすべてのノードを反復処理する単純なアプローチでは、最悪の場合で最大 O(nq) 時間がかかり、これは 4×10^10 の演算程度になります。 これは妥当な時間内で実行できる速度をはるかに超えているため、より慎重なデータ構造とアルゴリズムが必要です。 エッジ ケースには、長いサイクルでノードから開始されるクエリ (不注意な BFS/DFS が何度も繰り返される可能性がある)、および複数のクエリを通じて同じノードに蓄積される更新が含まれます。 順列にサイクルまたは自己ループがある場合、更新は繰り返しではなく、ノードごとに 1 回だけ適用する必要があります。 

## アプローチ

 ブルートフォース手法は簡単です。合計クエリの場合は、以下を繰り返します。`l`に`r`そして合計を計算します。 到達可能性の更新のために、以下から始まる BFS または DFS を実行します。`v`そして追加します`x`訪れたそれぞれに`a[u]`; スワップの場合は単に交換します`p[i]`そして`p[j]`。 これは正しいですが、非常に遅くなります。到達可能なセットが大きい場合、単一のタイプ 2 クエリに O(n) 時間がかかる可能性があり、q = 2×10^5 と組み合わせると、合計操作が 4×10^10 に達する可能性があります。 明らかに、これはスケールが合いません。 

重要な洞察は、順列グラフの構造を活用することです。 すべてのノードの出次数 1 があるため、グラフは完全にサイクルを構成し、そのサイクル内にツリーが指されています。 グラフをサイクルを表す強連結成分 (SCC) に分解できれば、SCC ごとに合計の更新を効率的に追跡できます。 開始がサイクル内にある場合、同じサイクル内のノードは常に同じ到達可能セットを持ち、サイクルを指すノードは到達可能性が予測可能なツリーを形成します。 順列更新 (タイプ 3 クエリ) は十分にまばらであるため、構造を遅延的に再構築したり、マッピングを維持したりできます。 範囲更新による部分配列の合計を効率的に処理するには、任意のインデックスのセット (ここでは、到達可能なコンポーネントに属するインデックス) への値の追加をサポートするように拡張されたセグメント ツリーまたはバイナリ インデックス ツリー (フェンウィック ツリー) が理想的です。 

最適なアプローチは 2 つのアイデアを組み合わせたものです。`a`O(log n) で合計クエリに答えるため、およびタイプ 2 更新の場合は、サイクルとポインターを通じて到達可能なノードのセットをノードごとに維持します。 すべてのノードが正確に 1 つを指すため、到達可能なセットは、ツリーの森をオイラー ツアーに平坦化した後の間隔によって、または DSU-on-tree などを使用してジャンプを事前計算することによって表すことができます。 微妙な点は、タイプ 3 スワップは到達可能なセットを破壊して再構成する可能性があるため、スワップが将来の更新の開始ノードに影響を与える場合にのみマッピングを更新することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n q) | O(n) | 遅すぎる |
 | セグメント ツリー + SCC/インターバル マッピング | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列上のセグメント ツリーを初期化します。`a`範囲合計クエリとポイント更新を可能にします。 これにより、タイプ 1 クエリが効率的に処理されます。 
2. 順列グラフを作成します。 各ノードの出次数 1 があるため、DFS を実行してサイクルを識別し、各ノードにサイクル ID とサイクルまでの距離でラベルを付けます。 サイクル内のノードは SCC として表すことができますが、サイクル内を指すツリーはフラット化順序によって処理されます。 
3. SCC ごとに、サイクル内のノードのリストを記録し、ノードからそのコンポーネントへのマッピングを維持します。 これにより、サイクル内の任意のノードから到達可能なセットを迅速に識別できます。 
4. タイプ 2 クエリの場合、開始ノードのコンポーネントを特定します。 サイクルの場合、到達可能なセットはサイクル全体と、そのサイクルに到達できるノードです。 セグメント ツリーを使用して更新を効率的に適用するには、次のようにします。`x`このセットに対応する位置に移動します。 サイクルを指すツリー内のノードを連続した間隔に平坦化した場合は、単一の範囲更新で十分です。 
5. タイプ 3 クエリの場合、swap`p[i]`そして`p[j]`。 これにより、壊れて新しいサイクルが形成される可能性があるため、影響を受けるノードをダーティとしてマークします。 後続のタイプ 2 クエリがダーティ ノードから開始されると、その到達可能なセットが再計算されます。 この遅延再計算により、スワップごとの O(n) 作業が回避されます。 
6. タイプ 1 クエリの場合は、単純にセグメント ツリーにクエリを実行して、次の合計を求めます。`l`に`r`。 セグメント ツリーには、以前のすべての更新がすでに組み込まれています。 

機能する理由: このアルゴリズムは、すべてのセグメント ツリーの値が現在の値に対応するという不変条件を維持します。`a[i]`タイプ 2 アップデートをすべて適用した後。 タイプ 2 更新の到達可能セットは、更新ごとに各ノードに対して常に 1 回だけ計算されるため、値が過剰にカウントされることはありません。 タイプ 3 スワップ後の遅延再計算により、グラフ全体を毎回再計算しなくても正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

class SegmentTree:
    def __init__(self, data):
        self.n = len(data)
        self.tree = [0] * (2 * self.n)
        for i in range(self.n):
            self.tree[self.n + i] = data[i]
        for i in range(self.n - 1, 0, -1):
            self.tree[i] = self.tree[i << 1] + self.tree[i << 1 | 1]

    def update(self, idx, val):
        idx += self.n
        self.tree[idx] += val
        while idx > 1:
            idx >>= 1
            self.tree[idx] = self.tree[idx << 1] + self.tree[idx << 1 | 1]

    def query(self, l, r):
        l += self.n
        r += self.n
        res = 0
        while l <= r:
            if l & 1:
                res += self.tree[l]
                l += 1
            if not r & 1:
                res += self.tree[r]
                r -= 1
            l >>= 1
            r >>= 1
        return res

def main():
    n = int(input())
    a = list(map(int, input().split()))
    p = list(map(lambda x: int(x) - 1, input().split()))
    q = int(input())

    seg = SegmentTree(a)
    graph = [[] for _ in range(n)]
    for i in range(n):
        graph[i].append(p[i])

    visited = [0] * n
    component = [-1] * n
    order = []

    def dfs(u, comp_id):
        if visited[u] == 1:
            return
        visited[u] = 1
        for v in graph[u]:
            dfs(v, comp_id)
        component[u] = comp_id
        order.append(u)

    comp_id = 0
    for i in range(n):
        if visited[i] == 0:
            dfs(i, comp_id)
            comp_id += 1

    node_to_comp_nodes = [[] for _ in range(comp_id)]
    for u in range(n):
        node_to_comp_nodes[component[u]].append(u)

    for _ in range(q):
        parts = list(map(int, input().split()))
        t = parts[0]
        if t == 1:

                seg.update(u, x)
