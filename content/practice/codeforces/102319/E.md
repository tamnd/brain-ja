 ## 問題の理解

 並んでいます`n`ランタン、まさに`k`そのうちの 1 つはオンになっており、`4 <= k <= n <= 100`。 ランタンのサブセットについて裁判官に質問することができます。 そのサブセットに次のものが含まれる場合、`x`ランタンに火が灯る、裁判官は明らかにしない`x`。 代わりに、次の約数の数を返します。`x`それは複合的なものです。 

させて`F(x)`その反応を表します。 例えば、`F(4) = 1`、の唯一の合成約数であるため、`4`は`4`自体。 また、`F(3) = 0`、 なぜなら`3`プライムです。 

課題は、どちらであるかを正確に判断することです。`k`ランタンは点灯しており、最大でも使用しています`2 * 10^5`クエリ。 

の小さな値`n`欺瞞的です。 あり得る`C(100, 4) = 3,921,225`4 つのランタンのサブセットが異なるため、4 つのサブセットをすべてテストするにはすでにコストがかかりすぎます。 同時に、`n <= 100`これは、クエリの 2 次または 3 次数が制限内に収まることを意味します。`C(100, 3) = 161,700`。 

主な難点は、`F(x)`1対1ではありません。 例えば、`F(25) = F(26) = 1`、 なぜなら`25`合成約数があります`{25}`そして`26`合成約数があります`{26}`。 点灯するランタンの数によって答えが一意に決まると仮定する戦略は、静かに失敗します。 

値に関する境界の問題もあります`4`。 我々は持っています`F(3) = 0`しかし`F(4) = 1`、これにより 4 つが特に便利になります。 たとえば、次の場合`n = 4, k = 4`、4 つのランタンすべてをクエリすると、次のようになります。`1`、ただし、最大 3 つの点灯したランタンを含むサブセットは次のようになります。`0`。 通常の二分探索に基づく方法では、裁判官の応答を単純に隠れカウントとして扱うことはできません。 

提供されているサンプルは対話型であるため、表示される応答は通常の入出力テスト ケースを形成しません。 サンプルの`0`応答は、バッチ プログラムが独自に再現できるデータではなく、元の対話記録からの応答です。 

## アプローチ

 直接的なアプローチは、4 要素のサブセットごとにクエリを実行することです。 4 要素のサブセットには、0 ～ 4 個の点灯したランタンが含まれます。 これらの可能性の中で唯一、`x = 4`ゼロ以外の答えがあるため、`0`、`1`、`2`、 そして`3`この相互作用に関連する複合約数はありません。 その結果、4 つのランタンに関するクエリは返されます。`1`ちょうどそのランタンが 4 つすべて点灯しているときです。 

すべての 4 サブセットがテストされると、少なくとも 1 つの陽性の 4 サブセットに属するときにランタンが点灯します。 これは正しいです。なぜなら、`k >= 4`したがって、すべての点灯しているランタンは、他の 3 つの点灯しているランタンと組み合わせることができます。 

問題はクエリ数です。 最悪の場合、これは実行されます`C(100, 4) = 3,921,225`クエリ、これは制限をはるかに超えています`200,000`。 

重要な点は、実際には、正確に 4 つのランタンを含むサブセットをクエリする必要がないということです。 代わりに、列全体から小さなランタンのセットを削除することができます。 

セットを選択するとします`T`の`t`ランタンを検索し、以下のランタンを除くすべてのランタンをクエリします。`T`。 もし`r`中のランタン`T`がオンの場合、クエリされたセットには正確に次の内容が含まれます`k - r`灯された提灯。 結果的に答えは`F(k-r)`。 

次に、最小の正を選択します`t`そのような`F(k-t) != F(k)`。 

この問題の制約については、`t = 1, 2, 3`どれにも十分です`k`から`4`を通して`100`。 これは許容範囲の有限な特性であるため、事前計算中に検証できます。`F`。 ここで関連する最長の等ランの長さは 3 です。 

そのような_最小_の選択`t`これがクエリを便利にするものです。 あらゆる人にとって`r < t`、ミニマリティが与える`F(k-r) = F(k)`。 

のために`r = t`定義上、`F(k-t) != F(k)`。 

のクエリされた補数`t`-要素セットには最大でも含めることができます`t`点灯したランタンは除外されます。 したがって、その応答は`F(k)`まさにいつ`r = t`、つまり、すべてのランタンがいつ入るかを正確に意味します。`T`がオンになっています。 

不可解な除数応答をきれいな応答に変換しました。`t`-way AND テスト。 以来`t <= 3`、可能な限りすべてをテストできます`t`-要素セット。 最悪のケースは、3 要素のサブセットがすべて存在する場合です。`161,700`クエリ。

## アルゴリズムのチュートリアル

 1. 事前計算`F(x)`、すべての合成約数の数`x`から`1`を通して`100`。 もし`x = p_1^{a_1} ... p_m^{a_m}`、約数の合計は`(a_1 + 1) ... (a_m + 1)`。 その中で、一つは、`1`そしてまさに`m`素数なので、`F(x) = tau(x) - m - 1`。 
2.読む`n`そして`k`、次に最小のものを見つけます`t`で`{1, 2, 3}`誰のために`F(k-t)`とは異なります`F(k)`。 制約`k >= 4`これらすべてのインデックスが正であることを保証します。 
3. 候補セットを検討する`T`まさに`t`提灯。 ～の補完について質問する`T`、以下のランタンを除くすべてのランタンが含まれることを意味します。`T`。 
4. しましょう`r`点灯しているランタンの数になります`T`。 クエリされた補数には以下が含まれます`k-r`提灯に火が灯ったので裁判官が戻ってくる`F(k-r)`。 
5. もし`r < t`、最小限の選択`t`与える`F(k-r) = F(k)`。 もし`r = t`、すべてのランタン`T`が点灯し、応答が`F(k-t)`とは異なります`F(k)`。 以来`r`超えることはできません`t`、応答は異なります`F(k)`ちょうどすべてのランタンが入ったとき`T`がオンになっています。 
6. すべてを列挙する`t`-要素のサブセット`T`。 その補数が異なる答えを生成するときはいつでも、`F(k)`、すべてのランタンにマークを付けます`T`点灯したまま。 
7. すぐに停止してください`k`提灯がマークされています。 マークのあるランタンはすべて本物に点灯しており、正確に点灯しているため、`k`点灯したランタン、完全にマークされたセットが答えです。 

### なぜ効果があるのか

 不変条件とは、`t`-要素セットは、すべての要素が一致したときに、その補完クエリから異なる応答を受け取ります。`t`提灯が灯っています。 以下の内容を含むセットの場合`t`点灯したランタン、補数には次のいずれかが含まれます。`k, k-1, ..., k-(t-1)`ランタンが点灯しており、それらの値はすべて以下と同じ応答を持ちます。`k`最小の定義によると`t`。 もしすべてなら`t`ランタンが点灯し、補完物が含まれます`k-t`ランタンに火を灯すと、また違った反応が生まれます。 

なぜなら`t <= 3`その間`k >= 4`、すべての点灯したランタンは少なくとも 1 つに属します。`t`- 点灯したランタンのみで構成される要素のサブセット。 そのようなサブセットが検出され、そのランタンにマークが付けられます。 逆に、検出されたサブセットは完全に点灯しているランタンで構成されている必要があるため、消灯しているランタンは検出されたサブセットに属することはできません。 したがって、マークされたセットは、まさに点灯したランタンのセットです。 

## Python ソリューション

 次のプログラムは実際の対話型ソリューションです。 イニシャルを読みます`n`そして`k`、各クエリをすぐに出力し、ジャッジの応答を読み取り、最後に復元された設定を出力します。```python
import sys
from itertools import combinations

input = sys.stdin.readline

def composite_divisor_count(x):
    if x <= 1:
        return 0

    divisors = 0
    for d in range(2, x + 1):
        if x % d != 0:
            continue

        # d is composite iff it has a divisor other than 1 and itself.
        composite = False
        for q in range(2, int(d ** 0.5) + 1):
            if d % q == 0:
                composite = True
                break

        if composite:
            divisors += 1

    return divisors

def main():
    n, k = map(int, input().split())

    f = [0] * (k + 1)
    for x in range(1, k + 1):
        f[x] = composite_divisor_count(x)

    base = f[k]

    t = -1
    for candidate in range(1, 4):
        if f[k - candidate] != base:
            t = candidate
            break

    # This is guaranteed by the constraints of the problem.
    if t == -1:
        return

    answer = [False] * n
    found = 0

    for excluded in combinations(range(n), t):
        query = ['1'] * n
        for i in excluded:
            query[i] = '0'

        print("? " + ''.join(query), flush=True)

        response = int(input())
        if response == -1:
            return

        if response != base:
            for i in excluded:
                if not answer[i]:
                    answer[i] = True
                    found += 1

            if found == k:
                break

    result = ''.join('1' if x else '0' for x in answer)
    print("! " + result, flush=True)

if __name__ == "__main__":
    main()

プログラムストア`F(k)`で`base`。 の検索`t`意図的にから始める`1`、可能な限り最小のものを使用するため、`t`これは、除外された点灯しているランタンの数が少なくても、フルセットと同じ答えが得られることを保証するものです。 

組み合わせごとに、クエリはすべての値に初期化されます。`'1'`キャラクターと選択したもの`t`位置がに変更されます`'0'`。 これは候補セットを補完するものであり、不可欠です。 候補者自体にクエリを実行すると、`r`それよりも`k-r`となり、最小性の議論は適用されなくなります。 

応答は以下とのみ比較されます。`base`。 クエリで点灯しているランタンの正確な数を知る必要はありません。 異なる応答があれば、すべてが次のように結論付けられます。`t`除外されたランタンが点灯しています。

import itertools

def composite_divisor_count(x):
    if x <= 1:
        return 0

    ans = 0
    for d in range(2, x + 1):
        if x % d != 0:
            continue

        composite = False
        for q in range(2, int(d ** 0.5) + 1):
            if d % q == 0:
                composite = True
                break

        if composite:
            ans += 1

    return ans

def solve_offline(n, hidden):
    k = sum(hidden)

    f = [0] * (k + 1)
    for x in range(1, k + 1):
        f[x] = composite_divisor_count(x)

    base = f[k]

    t = None
    for candidate in range(1, 4):
        if f[k - candidate] != base:
            t = candidate
            break

    assert t is not None

    answer = [False] * n

    for excluded in itertools.combinations(range(n), t):
        r = sum(hidden[i] for i in excluded)
        response = f[k - r]

        if response != base:
            for i in excluded:
                answer[i] = True

        if sum(answer) == k:
            break

    return ''.join('1' if x else '0' for x in answer)

3 番目のエッジケースは、`k = 34`。 ここ`F(34) = F(33) = 1`、そのため、単一ランタンの補完は再び失敗します。 しかし`F(32) = 4`、与える`t = 2`。 このアルゴリズムはすべてのペアをテストし、2 つの点灯したランタンで構成されるペアを正確に検出します。 以来`k = 34`は 2 つよりもはるかに大きいため、点灯したランタンはすべてそのようなペアに属しており、すべてが回収されます。 

4 番目のエッジケースは、`k = 35`。 値が満たされている`F(35) = F(34) = F(33) = 1`したがって、最初の違いは次の時点で発生します。`t = 3`、 と`F(32) = 4`。 これは、3 要素のサブセットすべてを検査する必要がある可能性があるため、クエリ数が最悪のケースです。 あるのは`C(100,3) = 161,700`そのようなサブセットは`n = 100`、下に残ります`200,000`限界。 点灯しているランタンが 3 個未満である 3 つのサブセットの場合、クエリされた補数には次のものが含まれます。`35`、`34`、 または`33`灯籠を灯して帰還`1`。 3 つの点灯したランタンの葉を含む 3 つのサブセット`32`灯籠を灯して帰還`4`、つまり、目的のサブセットが正確に検出されます。 

最後に、すべてが終わったら、`n`ランタンがオンになり、クエリされたすべての除外セットが完全に点灯します。 最初の違い`t`まだによってのみ決定されます`k`、最初に検出されたサブセットはすぐにそのメンバーをマークします。 アルゴリズムはすべての値が完了するとすぐに停止します。`k`位置はマークされているため、この場合、考えられるすべてのクエリを網羅する必要はありません。
