 ## 問題の理解

 を含むコインシステムがあります。`n`宗派を含む異なる宗派`1`。 アンドリューは、連続した間隔ですべての金額を個別に支払う必要があります`[l, r]`。 それぞれの金額について、価値の合計が正確にその金額となるコインの最小数が必要です。 

追加の宗派を導入する可能性があります`c`、 どこ`1 <= c <= r`。 加算後、からの各金額は、`l`を通して`r`新しいコインは必要に応じて何度でも使用できます。 目的は、これらすべての金額の最小コイン数の合計を最小限に抑えることです。 新しい金額が合計を改善しない場合は、印刷します`0`。 複数の宗派で同じ最高の合計が得られた場合、そのどれもが有効です。 公式の問題ページには、以下で使用されているのと同じ 2 つのサンプルが提供されています。 

興味深い制約は、`r - l <= 50`。 の絶対値`r`は 200000 になる可能性があるため、次の値に比例して作業を実行するアルゴリズム`r`それは合理的ですが、考えられるすべての新しい宗派に対して個別にそれを行うのは合理的ではありません。 食料品の金額は最大 51 ですが、新しい金額は 200,000 まで可能です。 既存の金種数は最大 420 であるため、オリジナルのコイン システムの標準的な動的プログラムにはコストがかかります`O(nr)`、最大のケースでは約 8,400 万の基本的な遷移。 二次または三次依存性`r`は問題外です。 

誤って対処しやすい特殊なケースがいくつかあります。 要求された間隔が既存のコインである単一の金額で構成されている場合、追加によってそれを改善することはできません。 たとえば、```
3
1 1
1 2 3
```正しい出力は`0`、金額なので`1`すでに 1 コインのコストがかかり、1 コイン未満を使用する支払いはできません。 常に何らかの候補宗派を選択するような不注意な実装では、誤って印刷される可能性があります。`1`。 

最適な新しい額面は、次の額面よりも小さい可能性があります。`l`。 例えば、```
1
100 150
1
```非常に便利な新しい価値のあるコインがあります`50`。 100 から 150 までのすべての金額は、2 枚または 3 枚のコインを使用して支払うことができますが、100 近くのコインを追加しても、間隔のごく一部が安くなるだけです。 候補者を制限する`[l, r]`したがって、不正確です。 

新しいコインが間隔幅よりも大きい場合には、別の微妙なケースが発生します。 仮定する`r-l=10`そしてコインを追加します`c`10 より大きい。ターゲットは、潜在的に、`c`, しかし、世界的に最高の額面を見つける目的のために、それらの数枚を、それらの合計が価値となる 1 枚のコインに置き換えることができます。 その代替はまだせいぜい`r`間隔幅よりも大きいままです。 この観察を怠ると、候補者の評価が不必要に高価になることにつながります。 

最後に、既存の宗派を新たな改善として扱ってはなりません。 すでに存在するコインを追加すると、最小値は変更されません。 アルゴリズムはそのような候補を単純にスキップします。 

## アプローチ

 直接的なアプローチでは、考えられるすべての新しい金種を検討し、完全な硬貨両替問題を再度解決します。 確定候補者1名に対して`c`、通常の動的プログラムを実行できます`dp[x] = 1 + min(dp[x - coin])`すべての金額で最大`r`、現在は元の額面プラスを使用しています`c`。 標準的な再帰では最適な表現の最後のコインが考慮されるため、これは正しいです。 

ただし、このアプローチでは、すべての候補に対してほぼ同じ計算が繰り返されます。 まであります`r`候補者と各民主党は`O(nr)`時間。 最悪の場合こうなります`O(nr²)`、 だいたい`420 * 200000²`、これは約 16 兆 8,000 億のトランジションに相当します。 

重要な観察は、実際には元のコイン システムを再計算する必要がないということです。 最初の計算`base[x]`、すべての場合に必要な元のコインの最小数`x <= r`。 次に、特定の機能を追加する方法を尋ねます。`c`それらの値を変更します。 

小型の新しいコインの場合、検査できる通貨単位はわずかしかありません。 より正確に言うと、`W = r - l + 1`。 

ショッピング間隔には最大 51 個の金額があるため、`W <= 51`。 すべての候補者に対して`c <= W`で新しい DP を計算できます。`O(r)`繰り返しを使用する時間`new[x] = min(base[x], new[x-c] + 1)`。 

あるのは`W`そのような候補者に与える`O(rW)`時間。 

はるかに有用な観察により、すべての候補が処理されます`c > W`。 を使用して、あるターゲットの表現を考えてみましょう。`k >= 2`新しいコインのコピー。 それらのコピーは価値に貢献します`kc`。 宗派を追加する代わりに`c`、宗派を追加することを想像してください`kc`。 以来`kc <= x <= r`、これはまだ許可されている新しい宗派です。 以来`c > W`、これも有効な大型候補です。 の`k`コインは 1 つのコインに置き換えられたため、結果として得られる表現は悪くありません。 

したがって、すべての候補のうち、`W`、すべてのターゲットに対して最大 1 回使用されるグローバルに最適な候補が常に存在します。 そのような固定されたものについては、`c`、 額`x`～からしか改善できない`base[x]`に`min(base[x], base[x-c] + 1)`、

いつ`x >= c`。 私たちが持っているのは`W`目標額が大きいため、各大規模候補者は`O(W)`時間。 多くてもあります`r`候補者、別の候補者を与える`O(rW)`学期。 

動的プログラミングが 1 つの固定コイン システムを完全に解決するため、総当たり法が機能します。 候補者ごとにシステムを再構築するため、失敗します。 間隔幅に関する観察により、候補を完全な DP が必要な金種の小さなセットと、新しいコインの 1 回の使用のみを考慮する必要がある大きなセットに分けることができます。

 ## アルゴリズムのチュートリアル

 1. 既存の宗派を読み取り、計算します。`base[x]`、あらゆる金額を形成するために必要な既存のコインの最小数`x`から`0`を通して`r`。 値`base[0]`はゼロであり、宗派は`1`すべての金額が到達可能であることを保証します。 
2. すべての買い物金額の元の合計を計算します。`l`を通して`r`。 これは、新しい宗派が有用であるためには超えなければならない価値です。 
3. しましょう`W = r - l + 1`。 すべての候補者の宗派について`c`と`1 <= c <= W`すでに存在する場合はスキップしてください。 それ以外の場合は、次から一時的な DP 配列を構築します。`0`を通して`r`。 以下の金額については`c`、新しいコインは使用できないため、その価値は正確に`base[x]`。 のために`x >= c`、最適解は、新しいコインを使用しないか、少なくとも 1 回使用して、次の繰り返しを与えます。`min(base[x], new[x-c] + 1)`。 
4. 一時的な DP 値を合計します。`[l, r]`。 合計がこれまでに確認された最良の合計よりも小さい場合は、この候補を思い出してください。 
5. すべての候補者に対して`c > W`、再び既存の宗派をスキップします。 ターゲットごとに`x`で`[l, r]`、新しいコインを使用しないこと、コストがかかることを検討してください。`base[x]`、またはそのコピーを 1 つ使用すると、費用がかかります`base[x-c] + 1`いつ`x >= c`。 小さい方の値を採用します。 
6. 合計が最小になる候補を維持します。 最小の合計が元の合計と等しい場合、出力`0`; それ以外の場合は、記憶されている金種を出力します。 

中心的な不変条件は次のとおりです`base[x]`元の金種のみを使用して、常に正確な最適値が得られます。 小規模な候補の場合、再帰では新しいコインのあらゆる可能な使用回数が考慮されます。`new[x-c]`にはすでに最適な表現が含まれています`x-c`。 大きな候補の場合、複数のコピーを使用する解は、別の法定の大きな額面の 1 つのコピーを使用する解に変換できるため、1 つの新しいコインだけを考慮しても、全体的な最適な答えを除外することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(data: str) -> str:
    it = iter(map(int, data.split()))
    n = next(it)
    l = next(it)
    r = next(it)

    coins = [next(it) for _ in range(n)]
    coin_set = set(coins)

    # Original minimum-coin DP.
    INF = r + 1
    base = [INF] * (r + 1)
    base[0] = 0

    # Unbounded coin change.
    for c in coins:
        if c > r:
            continue
        for x in range(c, r + 1):
            v = base[x - c] + 1
            if v < base[x]:
                base[x] = v

    width = r - l + 1
    original_total = sum(base[l:r + 1])

    best_total = original_total
    best_coin = 0

    # Small candidates: a full DP over [0, r] is affordable because
    # there are at most width <= 51 of them.
    for c in range(1, min(width, r) + 1):
        if c in coin_set:
            continue

        cur = base[:]

        for x in range(c, r + 1):
            v = cur[x - c] + 1
            if v < cur[x]:
                cur[x] = v

        total = sum(cur[l:r + 1])

        if total < best_total:
            best_total = total
            best_coin = c

    # Large candidates: c > width.
    # A globally optimal large candidate never needs to be used twice.
    for c in range(width + 1, r + 1):
        if c in coin_set:
            continue

        total = 0

        for x in range(l, r + 1):
            v = base[x]

            if x >= c:
                nv = base[x - c] + 1
                if nv < v:
                    v = nv

            total += v

        if total < best_total:
            best_total = total
            best_coin = c

    return str(best_coin)

def main():
    data = sys.stdin.buffer.read().decode()
    print(solve(data))

if __name__ == "__main__":
    main()
```最初の DP 構造`base`。 額面を一度に 1 つずつ処理し、金額を昇順に処理することは、標準的な無制限のコイン交換の繰り返しです。`c`、`base[x-c]`すでに任意の数のコピーを使用している可能性があります`c`。 

小規模候補ループのコピー`base`その後、新しい額面を使用してすべての金額を緩和します。 から始まる`base`これは、新しいコインを 0 回使用してもよいと言っているのと同じです。 順方向トラバーサルにより、繰り返しの使用が自動的に可能になります。 

分割で使用するのは、`width`、 ない`r-l`、まさにあるからです。`r-l+1`買い物金額。 使用する`r-l`ここでは、間隔の量が 1 つの場合、off-by-one エラーが発生します。 

大規模な候補者の場合、`x-c`負の値になる可能性があるため、コードチェックが行われます。`x >= c`インデックス作成前`base`。 それ以外の金額はありません`[0,r]`が必要です。 Python の整数では、オーバーフローの問題も回避されますが、関連するすべての合計は通常の 64 ビット整数の制限よりもはるかに小さくなります。 

すでに存在する候補者`coin_set`スキップされます。 既存の金種を追加してもコイン システムを改善することはできず、それを処理しても時間の無駄になるだけです。
