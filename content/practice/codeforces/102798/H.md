 ## 解決策
 # 問題の理解

 チャット グループと学生のコレクションがあります。 学生が参加したり脱退したりできるため、グループは時間の経過とともに変化します。 生徒がグループ内でメッセージを送信すると、現在そのグループに所属している他の生徒全員が 1 つのメッセージを受信します。 このタスクは、すべての生徒について、イベント ログ全体を処理した後に受信したメッセージの合計数を計算することです。 

入力には、グループの数、生徒の数、およびイベントの時系列リストが記述されます。 参加イベントは学生をグループに追加し、脱退イベントは学生をグループから削除します。メッセージ イベントは、1 人の学生がそのグループの他の現在のメンバーにメッセージをブロードキャストすることを意味します。 出力は生徒ごとに 1 つの値で、その生徒に届いたメッセージの数を表します。 

制限は大きく、最大 100,000 のグループ、200,000 の学生、および 1,000,000 のイベントが可能です。 メッセージごとにグループのすべてのメンバーを訪問する直接シミュレーションでは、時間がかかりすぎます。1 つのグループには数十万人の生徒が含まれており、操作が数百万回も行われる可能性があるためです。 100 万のイベントがある場合、ソリューションはイベントごとにほぼ一定の時間を維持し、ほぼ直線的な複雑さを許容する必要があります。 

厄介な点は、送信者が自分のメッセージを受信しないことです。 グループ内で送信されたすべてのメッセージを単純にカウントし、それをすべてのメンバーに渡すソリューションでは、カウントが過剰になります。 例えば：```
1 1 1
3 1 1
```学生はグループ 1 に参加し、メッセージを送信します。 正しい出力は次のとおりです。```
0
```すべてのメンバーに 1 つのメッセージを追加する不用意なアプローチでは、1 が出力されます。 

もう 1 つの微妙なケースは、同じグループを離れ、その後同じグループに参加することです。 考慮する：```
1 1 1
3 1 1
2 1 1
1 1 1
3 1 1
```正しい出力は次のとおりです。```
0
```唯一のメンバーが送信者であるため、最初のメッセージは誰も受信しません。 学生が退席して再参加し、2 番目のメッセージでも同じ結果が得られます。 学生がかつてグループに所属していたことだけを記憶するソリューションでは、以前のメンバーシップ期間からのメッセージを誤ってカウントしてしまう可能性があります。 

# アプローチ

 ブルートフォースアプローチは簡単です。 すべてのグループのメンバーを維持します。 メッセージ イベントが発生すると、そのグループのすべてのメンバーを反復処理し、送信者を除くメンバーの回答を増加させます。 これは、メッセージ配信の定義に直接従うため、正しいです。 

この問題は、大規模なグループが多数のメッセージを受信した場合に発生します。 1 つのグループに 200,000 人の学生が含まれ、1,000,000 件のメッセージを受信した場合、シミュレーションでは約 2,000 億件のメンバー更新が実行されます。 データ構造の操作自体は問題ありませんが、アクセス数が制限時間を大幅に超えています。 

重要な点は、メッセージが発生したときにすべてのメンバーを更新する必要がないということです。 代わりに、各生徒は後で自分の受信メッセージを計算する責任を負うことができます。 特定の学生およびグループの場合、受信するメッセージの数は、メンバーであった間にそのグループで送信されたメッセージの数から、同じメンバーシップ期間中に個人的に送信したメッセージを差し引いたものになります。 

これにより、問題はメンバーシップの間隔の追跡に変換されます。 アクティブな各メンバーシップには、学生が参加したときにグループがすでに受信したメッセージの数と、学生がグループに残っている間に送信したメッセージの数という 2 つの情報のみが必要です。 

グループごとに、グローバル メッセージ カウンターを保存します。 結合すると、現在のカウンターが記録されます。 退会すると、そのグループからの学生の貢献が確定します。 メッセージを送信すると、そのグループのグループ カウンタと送信者の個人カウンタのみが増加します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 最悪の場合、O(メッセージ総数 × グループ サイズ) | O(会員数) | 遅すぎる |
 | 最適 | O(s) | O(s) | 承認済み |

 # アルゴリズムのチュートリアル

 1. 配列を保持する`group_messages`どこ`group_messages[g]`グループ内でこれまでに送信されたメッセージの総数です`g`。 すべてのメッセージ イベントは、この 1 つの値を増やすだけで済みます。 
2. 各学生とグループのペアの現在のメンバーシップ情報を保持します。 学生がグループに参加すると、現在の値を保存します。`group_messages[g]`このメンバーシップ期間中にこの学生が送信したメッセージの数をリセットします。 これにより、今後受信するメッセージを計算するための明確な開始点が作成されます。 
3. 生徒がメッセージを送信すると、グループのメッセージ カウンタが増加します。 また、このメッセージは後で受信カウントから削除する必要があるため、そのグループの送信者自身の送信メッセージ カウンタも増やします。 
4. 学生がグループを脱退した場合、メンバーシップ期間中にグループ内で発生したメッセージの数を計算します。 この学生が送信したメッセージを減算し、その結果を学生の最終回答に加算します。 アクティブなメンバーシップ レコードを削除します。 
5. すべてのイベントが処理された後も、一部の生徒はまだグループのメンバーである可能性があります。 受信したメッセージも回答に含める必要があるため、これらのアクティブなメンバーシップを脱退イベントと同じ方法で終了させます。 

機能する理由: グループ カウンターの差分は、メンバーシップ間隔ごとに、学生がグループに属している間に発生したすべてのメッセージを正確にカウントします。 そのセット内で学生が受信すべきではない唯一のメッセージは、学生自身のメッセージであり、個別にカウントされて削除されます。 すべてのメッセージは、メッセージを受信できる学生ごとに 1 つのメンバーシップ間隔に属しているため、メッセージが見逃されたり 2 回カウントされたりすることはありません。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, s = map(int, input().split())

    group_messages = [0] * (n + 1)
    answer = [0] * (m + 1)

    active = {}

    for _ in range(s):
        t, x, y = map(int, input().split())

        if t == 1:
            active[(x, y)] = [group_messages[y], 0]

        elif t == 2:
            start, sent = active.pop((x, y))
            answer[x] += group_messages[y] - start - sent

        else:
            group_messages[y] += 1
            active[(x, y)][1] += 1

    for (x, y), (start, sent) in active.items():
        answer[x] += group_messages[y] - start - sent

    print("\n".join(map(str, answer[1:])))

if __name__ == "__main__":
    solve()
```配列`group_messages`各グループの世界史を表します。 学生のメンバーシップ間隔は、参加時に取得された値を使用して処理されるため、ロールバックする必要はありません。 

辞書`active`現在存在するメンバーシップのみを保存します。 鍵となるのはペアです`(student, group)`、保存される値は、参加時のグループのメッセージ数と、グループ内にいる間にその生徒が送信したメッセージの数です。 

メッセージの動作は定数時間です。 ここで、送信者の個人カウンタを増やすのを忘れるという間違いが起こりやすく、その場合、自分が送信したメッセージが受信メッセージとしてカウントされてしまいます。 

最後のループでは、グループから決して離れない生徒を扱います。 未完了のメンバーシップ間隔がまだ残っているため、すべてのイベントが処理された後にそれらの間隔を閉じる必要があります。 

受信メッセージの最大数は 32 ビット整数の制限を超える可能性があるため、Python 整数で十分です。

 # エッジケース

 単一メンバーのグループの場合:```
1 1 2
1 1 1
3 1 1
```学生は唯一のグループに参加し、1 つのメッセージを送信します。 グループカウンターが増加しますが、生徒の個人送信カウンターも増加します。 有効なメンバーシップが確定すると、計算は次のようになります。`1 - 0 - 1 = 0`, したがって、答えは正しいです。 

繰り返し結合の場合:```
1 1 5
1 1 1
3 1 1
2 1 1
1 1 1
3 1 1
```最初のメッセージは最初のメンバーシップ間隔に属し、寄与はゼロです。 2 番目の結合では新しいグループ カウンター値が記録されるため、前のメッセージが 2 番目の間隔に影響を与えることはできません。 最終計算でも生徒自身のメッセージが削除され、ゼロが返されます。 

複数のメンバーがいるグループの場合:```
1 2 3
1 1 1
1 2 1
3 1 1
```グループ カウンタは 0 から 1 になります。生徒 1 は 1 つの送信メッセージを記録しますが、生徒 2 はグループ内に送信メッセージがありません。 終了処理により生徒 1 が与えられます`1 - 0 - 1 = 0`そして生徒２`1 - 0 - 0 = 1`。 

最後までグループに残る生徒の場合は次のとおりです。```
1 2 2
1 1 1
1 2 1
```休暇イベントはありません。 最後のクリーンアップ手順では、両方のアクティブなメンバーシップがログの最後に残されたかのように正確に処理されます。
