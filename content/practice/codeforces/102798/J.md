 ## 解決策
 # 問題の理解

 ゲームには石の山の列が含まれています。 ボブは、ゲームが始まる前に、すべての山の色を黒または白から選択します。 白い山は通常のニムの山と同じように動作します。プレイヤーは白い山から任意の正の数の石を取り除くことができます。 黒いパイルは異なります。 黒の山を含む移動は、1 つの山、現在最小の黒の山でのみ許可されます。 目標は、開始位置でアリスが負ける色の割り当ての数を数えることです。その場合、最適なプレイでボブが勝ちます。 

入力により、杭の数とその石の数がわかります。 有効なカラーリングは、パイルごとに黒または白の 1 つの選択です。 出力は、結果として得られる公平なゲームのグランディ値が 0 になるような選択肢の数です。 

杭の数は最大です$10^5$、一方、山には最大で$10^{18}$石。 これにより、シミュレーション、ゲーム状態の検索、またはパイル サイズ自体に応じたあらゆる方法が即座に除外されます。 石の数の 60 の可能なビットに対して小さな係数だけを使用して、山の数が線形に近いものが必要です。 値が大きいということは、xor ベースの技術が関与している可能性が高いことを示唆しています。 

いくつかのケースは誤って処理されやすいものです。 黒積みがないのでポジションはニムだけ。 例えば：```
Input
2
1 1

Output
1
```唯一負ける色は、xor が 0 であるため、両方の山が白である場合です。 少なくとも 1 つの黒い山があることを前提とした解決策では、このケースは見逃されます。 

もう 1 つの重要なケースは、最小の黒い山が複数回出現する場合です。 例えば：```
Input
2
1 2

Output
1
```両方の山を黒く着色するのは負けです。 最小の黒い山はサイズ 1 の山で、2 番目の山はそれが消えた後に次の黒い山になります。 通常の Nim パイルのように黒いパイルを独立して処理すると、間違った結果が得られます。 

最後のエッジケースは単一の山です。```
Input
1
3

Output
0
```どの色を塗っても最初のプレイヤーが負けることはありません。 黒の山の特別な動作を忘れた直接の XOR 実装では、2 つの色のうちの 1 つが誤ってカウントされてしまいます。 

## アプローチ

 強引な解決策では、あらゆる色を試すことになります。 それぞれについて、$2^n$可能性がある場合、ゲームを分析してアリスが負けるかどうかを計算します。 たとえ1つのカラーリングをチェックするだけだったとしても$O(n)$、合計作業量は次のようになります。$O(n2^n)$、それは不可能です$n=10^5$。 

重要な観察は、ゲームはまだ公平なゲームであるため、グランディの値を使用できるということです。 白いパイルは、通常の Nim と同様に、xor を通じて正確にパイル サイズを提供します。 唯一の難しい部分は、黒い山のセットのグランディ値を見つけることです。 

黒い山が並べ替えられたとします。 変更できるのは最小の黒いパイルのみです。 完全に除去されると、次に小さな黒い山が利用可能になります。 これにより、単純なパターンが作成されます。 黒の最小値が$m$、表示されます$c$すべての黒の山が同じサイズである場合、黒のグランディ値は次のようになります。$$m-((c+1)\bmod 2)$$それ以外の場合は次のようになります。$$m-(c\bmod 2)$$これは、色の選択肢を最小の黒色値によってグループ化するだけでよいことを意味します。 選択された最小値では、すべての小さなパイルが白でなければなりません。 次に、白の山の値と黒の寄与の xor がゼロになるように、より大きな山に色を付ける方法をカウントする必要があります。 

残りの計数問題は、サブセット XOR 問題です。 値は最大までなので、$10^{18}$、60 ビットにわたってバイナリ線形基底を維持します。 これにより、ターゲット xor を形成できるかどうか、およびそれを形成するサブセットの数がわかります。 

すべてのカラーリングが独立しているため、力技が機能します。 色が指数関数的に多いため、失敗します。 黒の最小値のみが重要であるという観察により、ゲーム分析は少数の XOR カウント クエリに削減されます。

 ## アルゴリズムのチュートリアル

 1. すべての山を徐々に並べ替えます。 最小の黒い山は個々のインデックスではなく値グループによって決定されるため、等しい値をまとめて処理します。 
2. 最大値から最小値までグループを処理します。 グループを処理する前に、維持される xor 基底には、より大きな値を持つパイルが正確に含まれます。 これらは、より大きな黒い山になる可能性のある山です。 
3. 現在値について$v$周波数付き$c$、このグループに最小の黒い山が含まれる選択肢を数えます。 このグループから選択される黒い山の数は、パリティによってのみ重要になります。 がある$2^{c-1}$奇数のサイズの選択肢と$2^{c-1}-1$空ではない偶数サイズの選択肢。 
4. より大きな値に少なくとも 1 つの黒い山が含まれるケースを数えます。 黒の Grundy 値は、現在のグループから選択されたカウントのパリティによって異なります。 残りの条件は、必要な xor を持つ大きな山のサブセットを見つけることになります。これは線形基底によって答えられます。 
5. 大きな山がすべて白である場合を数えます。 これは、すべての黒の山が同じサイズである特殊なケースです。 大きな山は白で固定されるため、この寄与を直接確認できます。 
6. 現在のグループを終了したら、このグループのすべての値を xor 基底に挿入します。 最小黒値が小さいほど、より大きなパイルになる可能性があります。 

なぜ効果があるのか:

 黒の山がない限り、すべてのカラーリングは正確に 1 つの最小の黒値を持ちます。 アルゴリズムは、その値に対応する反復でそのカラーリングをカウントします。 For a fixed minimum value, the formula for the black Grundy value depends only on the parity of the chosen piles at that value and whether a larger black pile exists. The linear basis counts exactly the possible white xor values among larger piles, so every coloring with total Grundy value zero is counted once and every other coloring is rejected.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7
LOG = 61

class XorBasis:
    def __init__(self):
        self.b = [0] * LOG
        self.rank = 0

    def add(self, x):
        for i in range(LOG - 1, -1, -1):
            if (x >> i) & 1:
                if self.b[i]:
                    x ^= self.b[i]
                else:
                    self.b[i] = x
                    self.rank += 1
                    return

    def can_make(self, x):
        for i in range(LOG - 1, -1, -1):
            if (x >> i) & 1:
                if self.b[i]:
                    x ^= self.b[i]
                else:
                    return False
        return True

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    pow2 = [1] * (n + 1)
    for i in range(1, n + 1):
        pow2[i] = pow2[i - 1] * 2 % MOD

    basis = XorBasis()
    ans = 0
    greater_count = 0
    greater_xor = 0

    i = n - 1
    while i >= 0:
        j = i
        while j >= 0 and a[j] == a[i]:
            j -= 1

        v = a[i]
        c = i - j
        odd = pow2[c - 1]
        even = (odd - 1) % MOD

        # Larger piles are not all white.
        for parity, ways in ((1, odd), (0, even)):
            sg = v - parity
            target = sg ^ greater_xor
            if basis.can_make(target):
                add = ways * pow2[greater_count - basis.rank] % MOD
                ans = (ans + add) % MOD

                if target == greater_xor:
                    ans = (ans - ways) % MOD

        # All black piles have this same value.
        for parity, ways in ((1, odd), (0, even)):
            sg = v - (1 - parity)
            current_white = v if (c - parity) % 2 else 0
            if greater_xor ^ current_white ^ sg == 0:
                ans = (ans + ways) % MOD

        for _ in range(c):
            basis.add(v)
            greater_count += 1
            greater_xor ^= v

        i = j

    # No black piles, pure Nim.
    total_xor = 0
    for x in a:
        total_xor ^= x
    if total_xor == 0:
        ans = (ans + 1) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、ウォークスルーのグループ化されたスキャンに従います。 xor 基底には、黒の最小値が固定されているときに色が未決定のままになる唯一の山があるため、より大きな値のみが格納されます。 

の`rank`フィールドはサブセットのカウント式で使用されます。 基底にランクがある場合`r`そしてそこにあります`k`値の場合、表現可能なすべての xor は正確に次のように生成されます。$2^{k-r}$サブセット。 コードは、ターゲットの xor が到達可能であることを確認した後、この事実を使用します。 

の引き算`ways`カウントされた白いサブセットにすべての大きな山が含まれる場合を処理します。 これはまさに無効な状況であり、実際にはより大きな黒の山が存在しないため、別の等サイズ黒計算に属します。 

すべての値は Python 整数として保存されるため、$10^{18}$制限には特別な処理は必要ありません。 基底ループは 61 ビットを使用します。$10^{18}<2^{60}$。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old

    n = int(data[0])
    a = list(map(int, data[1:]))

    MOD = 10 ** 9 + 7

    from collections import Counter
    # Reference implementation for small tests only
    ans = 0
    for mask in range(1 << n):
        black = [a[i] for i in range(n) if mask >> i & 1]
        white = [a[i] for i in range(n) if not (mask >> i & 1)]
        if not black:
            x = 0
            for v in white:
                x ^= v
            ans += x == 0
            continue
        m = min(black)
        c = black.count(m)
        same = all(x == m for x in black)
        sg = m - ((c + int(same)) % 2)
        x = sg
        for v in white:
            x ^= v
        ans += x == 0
    return str(ans) + "\n"

assert run("2\n1 2\n") == "1\n"
assert run("1\n3\n") == "0\n"
assert run("1\n1\n") == "0\n"
assert run("3\n1 1 1\n") == "6\n"

 ## 特殊なケース

 黒の山がない場合、アルゴリズムは最後にケースを個別に処理します。 ゲームは通常の Nim になります。そのため、唯一負ける色の割り当ては、すべての山が白で、xor の合計が 0 になるものだけです。 

いくつかの山が最小の黒値を共有する場合、アルゴリズムはそれらを独立して扱うことはありません。 等しい値をグループ化し、パリティごとに黒の選択肢をカウントします。 入力の場合:```
2
1 1
```グループのサイズは 2 です。 奇数サイズの可能な黒のサブセットの数は 2 で、空でない偶数のサブセットの数は 1 です。 これらのケースは特別な黒いグランディ配合と組み合わされ、合計 4 つが正確​​に生成されます。 

サイズ 3 の単一の山の場合:```
1
3
```どちらの可能な色もゼロ以外のグランディ値を生成します。 白人のニムも黒人の行動も負ける状態を生み出すので、最終的な答えはゼロのままです。
