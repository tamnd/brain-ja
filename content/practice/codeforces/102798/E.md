 ## 解決策
 ## 問題の理解

 私たちは持っています`n`敵の手下。 の`i`-番目のミニオンは次で始まります`a[i]`健康。 正確に実行します`m`ワンダメージ攻撃。 各攻撃はまだ生きているミニオンの中から均一に選択され、そのミニオンの体力を 1 つ減らします。 ミニオンは体力がゼロになると消滅します。 

タスクは、最終的に死亡するミニオンの予想数を計算することです。`m`攻撃します。 

重要な制約は次のとおりです`n <= 15`そして`m <= 100`。 の小さな値`n`サブセット動的プログラミングを強くお勧めします。`2^15 = 32768`死んだミニオンの可能性のあるセット。 ただし、ヘルス値により、考えられるすべてのヘルス構成を直接保存することは不可能になります。 答えに影響を与える情報のみを保存する必要があります。 

よくある間違いは、ダメージの合計が少なくとも一部のミニオンの体力の合計である場合、それらのミニオンは死ぬに違いないと仮定することです。 攻撃はランダムなので、さまざまなミニオンにダメージが無駄になる可能性があります。 

例えば：```
1 1
5
```答えは`0`, なぜなら、1つのダメージで体力が5のミニオンを倒すことはできないからです。 

もう 1 つのエッジ ケースは、一部のミニオンがすでに残りのダメージをすべて正確に必要としている場合です。```
2 3
1 100
```最初のミニオンは確実に死ぬが、2番目のミニオンは十分なダメージを受けることができない。 答えは`1`。 

## アプローチ

 考えられるすべての攻撃シーケンスを直接シミュレーションすることは不可能です。 がある`n^m`ターゲットの可能な選択肢、さらには`n = 15`、`m = 100`、この数字は調査できる範囲をはるかに超えています。 

重要な観察は、最終的な答えはどのミニオンが死んだかによってのみ決まるということです。 生きているすべてのミニオンの正確な残り体力は必要ありません。 死んだミニオンの固定セットの場合`S`、すべてのミニオン`S`ヘルスダメージを完全に消費しました。 残りの攻撃は他のミニオンにのみ分散されます。 

2 つの動的プログラムを使用します。 

最初の DP は、死んだミニオンのセットが正確に存在する確率を計算します。`S`一定回数の攻撃後。 移行では、死亡した最後のミニオンが考慮されます。 ミニオンなら`x`現時点ではデッド セットに参加していますが、以前の状態は次のとおりである必要があります。`S`それなし`x`、そして生き残ったミニオンを攻撃した以前の攻撃の数は、すでに費やされた合計ヘルスによって決まります。 

2 番目の DP は、ミニオンを殺さずに残りの攻撃をミニオンのセットに配置できる方法が何通りあるかをカウントします。 これら 2 つの値を組み合わせると、考えられるすべての最終デッド セットの確率寄与が得られます。

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    N = 1 << n

    comb = [[0] * (m + 1) for _ in range(m + 1)]
    for i in range(m + 1):
        comb[i][0] = comb[i][i] = 1
        for j in range(1, i):
            comb[i][j] = comb[i - 1][j - 1] + comb[i - 1][j]

    sm = [0] * N
    cnt = [0] * N
    for mask in range(1, N):
        b = mask & -mask
        idx = b.bit_length() - 1
        sm[mask] = sm[mask ^ b] + a[idx]
        cnt[mask] = cnt[mask ^ b] + 1

    f = [0.0] * N
    f[0] = 1.0

    for step in range(1, m + 1):
        nf = [0.0] * N
        for mask in range(N):
            c = cnt[mask]
            if mask:
                x = mask
                while x:
                    b = x & -x
                    i = b.bit_length() - 1
                    prev = mask ^ b
                    need = step - 1 - sm[prev]
                    if need >= a[i] - 1:
                        nf[mask] += f[prev] * comb[need][a[i] - 1]
                    x ^= b
                nf[mask] /= (n - c + 1)
            if n > c:
                nf[mask] += f[mask] / (n - c)
        f = nf

    g = [[0.0] * N for _ in range(m + 1)]
    for mask in range(N):
        g[0][mask] = 1.0

    for step in range(1, m + 1):
        for mask in range(1, N):
            b = mask & -mask
            i = b.bit_length() - 1
            rest = mask ^ b
            for take in range(min(step, a[i] - 1) + 1):
                g[step][mask] += comb[step][take] * g[step - take][rest]

    ans = 0.0
    full = N - 1
    for mask in range(N):
        rem = m - sm[mask]
        if rem >= 0:
            ans += f[mask] * g[rem][full ^ mask] * cnt[mask]

    print("{:.12f}".format(ans))

if __name__ == "__main__":
    solve()
```この実装では、サブセット情報が整数マスクに保持されます。`sm[mask]`ヘルス値を繰り返し合計することを回避します。そうしないと、別の要素が追加されてしまいます。`n`トランジションの内側。 

以前の攻撃回数のみが必要なため、確率 DP はレイヤーごとに更新されます。 最後のクエリでは残りの攻撃数を要求できるため、2 番目の DP ではすべてのレイヤーが保持されます。 

結果は期待値であるため、すべての計算では浮動小数点が使用されます。 値は倍精度に対して十分小さいままです。

## 特殊なケース

 ミニオンが利用可能なすべての攻撃よりも多くのダメージを必要とする場合、そのミニオンはデッド セットに表示されることはありません。 必要なヘルス合計に到達できないため、サブセット DP は当然、寄与分をゼロにします。 

複数のミニオンがヘルス 1 の場合、それぞれが 1 回の攻撃で死亡する可能性があるため、正しく処理されます。 確率 DP は、死亡が固定順序で発生すると仮定するのではなく、考えられるすべてのサブセットを区別します。 

すべてのミニオンが直後に死亡したとき`m`攻撃の場合、生き残ったミニオン DP は残りの攻撃がゼロの状態でコールされ、唯一の有効なディストリビューションは空のディストリビューションです。 これが理由です`g[0][mask] = 1`すべてのマスクが必要です。
