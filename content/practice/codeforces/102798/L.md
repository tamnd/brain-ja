 ## 解決策
 ## 問題の理解

 ギアのコレクションを取り揃えております。 ギア付き`t`歯の費用`t`コインとその後`k`方向性を示す期間`k mod t`。 選択したギアのセットでは、考えられる方向のすべてのタプルに必ずしも到達できるわけではありません。 問題は、総コストが最大になるギアを選択することです`b`到達可能な方向タプルの数ができるだけ多くなるようにします。 この膨大な数を出力する代わりに、その自然対数を出力します。 

サイズのある歯車の場合`t1, t2, ...`、時計が表示できるさまざまな状態の数は正確に次のとおりです。$$\operatorname{lcm}(t_1,t_2,\dots,t_n)$$なぜなら、1 回の完全最小公倍数の期間の後、すべてのポインターはその開始方向に戻り、そのサイクル内の小さな時間ごとに異なるグローバル状態が生成されるからです。 

予算はせいぜい`30000`、最大で`30000`テストケース。 クエリごとに個別に機能するソリューションでは、指数関数や二次関数に近い作業を行うことはできません。 正しいアプローチは、動的プログラミング手法を使用して、最大予算までのすべての回答を 1 回前処理することです。`30000^2`操作。 

いくつかのケースでは、誤って対処されやすいものがあります。 予算あり`2`、単一の 2 歯ギアを選択すると 2 つの状態が得られるため、答えは次のようになります。`ln(2)`。 空のプロダクトから開始したプログラムが、常に 1 つのギアが許可されていることを忘れると、ゼロが返される可能性があります。 

予算に合わせて`7`、サイズのギアを選択する`3`そして`4`lcmを与える`12`、これは単一の 7 歯ギアよりも優れています。 答えは次のとおりです。```
7
```出力あり:```
2.484906650
```利用可能な最大の装備を常に使用する貪欲な戦略では、`7`そして失敗する。 

もう 1 つの罠は、同じ素数のべき乗を複数選択することです。 ギアを入れる`2`そして`4`費用`6`、しかし彼らの lcm は`4`、 ない`8`。 最適な変換では、重複する素因数のカウントを回避する必要があります。 

## アプローチ

 強引な解釈では、総コストが予算内に収まるすべての可能なギアのコレクションを試し、その lcm を計算し、最大のものを保持します。 これは、すべての有効な設計を直接検査するため、正しいです。 ただし、可能なサブセットの数は指数関数的に増加します。 可能なギアの選択肢が 20 しかないとしても、すでに 100 万を超えるサブセットがあり、実際の有用な選択肢の数はさらに多くなります。 

重要な観察は、lcm が素数パワーから構築されていることです。 選択した 2 つのギアに異なる主力が含まれている場合`p^a`そして`q^b`、それらをこれら 2 つの主要な累乗で置き換えると、コストを小さく保ちながら同じ lcm 寄与が得られます。 公式チュートリアルでは、この削減について説明しています。最適なソリューションにはギアとしての主力のみが必要です。 

この削減の後、問題はナップザックになります。 各プライムは選択肢のグループに影響します。このプライムのギアを選択しないか、次のいずれかを選択します。`p`、`p^2`、`p^3`、 等々。 選択する`p^k`追加します`p^k`コストと`ln(p^k)`答えに。 各素数の累乗は 1 つだけ選択できるため、これはグループ化されたナップザックです。 

状態は、特定の予算で得られる最良の対数を保存します。 対数は lcms の乗算を加算に変換するため、ナップザック値の遷移は単純な加算になります。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 以下のすべての素数を生成します。`30000`ふるいで。 各素数は、ナップザック内の 1 つのグループを表します。 
2. 素数ごとに`p`、可能な歯車を生成します`p, p², p³, ...`値が最大である間`30000`。 同じ素数の 2 つのべき乗を取得しても lcm は増加しないため、これらはこの素数にとって唯一有用な選択肢です。 
3. グループ化されたナップザックをプライム グループ上で実行します。 各素数について、現在の DP 状態をコピーし、その素数の可能なすべての累乗を加算してみます。 移行は次のとおりです。$$dp[new\_cost] = \max(dp[new\_cost], dp[old\_cost] + \ln(power))$$同じ素数を二度選択することはできないため、コピーが必要です。 

1. すべての素数を処理した後、事前に計算されたクエリを使用してすべてのクエリに答えます。`dp[b]`。 

不変条件は、最初のいくつかの素数を処理した後、`dp[x]`総コストが最大の素数のみを使用して形成できる lcm の最大対数です。`x`。 すべての有効な選択は、現在の素数をスキップするか、そのべき乗の 1 つを正確に選択するため、グループ化された遷移では考えられるすべての最適な状態が考慮されます。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

MAX_B = 30000

def build():
    is_prime = [True] * (MAX_B + 1)
    is_prime[0] = is_prime[1] = False
    primes = []
    for i in range(2, MAX_B + 1):
        if is_prime[i]:
            primes.append(i)
            if i * i <= MAX_B:
                for j in range(i * i, MAX_B + 1, i):
                    is_prime[j] = False

    dp = [0.0] * (MAX_B + 1)

    for p in primes:
        powers = []
        x = p
        while x <= MAX_B:
            powers.append(x)
            x *= p

        old = dp[:]
        for cost in range(MAX_B + 1):
            best = old[cost]
            for x in powers:
                if cost >= x:
                    best = max(best, old[cost - x] + math.log(x))
            dp[cost] = best

    return dp

def solve():
    dp = build()
    t = int(input())
    ans = []
    for _ in range(t):
        b = int(input())
        ans.append("{:.9f}".format(dp[b]))
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```すべてのテスト ケースが同じ最大バジェットを共有するため、ふるいはプライム グループを 1 回だけ構築します。 素数の累乗リストには有効な素数累乗のみが含まれるため、重複した素数寄与が lcm に入力されることはありません。 

グループ化されたトランジションでは、`old = dp[:]`素数を処理する前に。 このコピーがないと、遷移により 1 回の反復で同じ素数の 2 つの累乗が選択され、無効な lcm が生成される可能性があります。 

必要な出力は次の対数のみであるため、ここでは浮動小数点値は安全です。`1e-6`精度。 可能な最大値は、Python の浮動小数点演算に十分な大きさです。

 ## 特殊なケース

 予算に合わせて`1`、可能なギアは一方向のみです。 DP は値 0 で始まり、lcm の 1 を表すため、正しく返されます。`ln(1)=0`。 

予算に合わせて`6`、不注意な実装は歯車を選択する可能性があります`2`そして`4`の lcm を請求します`8`。 両方の選択肢が主要なグループに属しているため、グループ化されたナップザックではその移行は許可されません。`2`。 それは選択することができます`4`、 または`2`、しかし両方ではありません。 

予算に合わせて`7`、最大のギアが常に最適であるとは限らないため、貪欲な選択は失敗します。 DP はプライムのグループを選択できます`3`価値のあるもの`3`そしてプライムのグループ`2`価値のあるもの`4`、lcmを生成します`12`、最大でもすべてのギアのコストを上回ります。`7`。 

前処理はクエリの数ではなく最大バジェットのみに依存するため、バジェットが大きい場合でもアルゴリズムは機能します。 入力には多くのリクエストを含めることができますが、それぞれのリクエストは直接検索によって応答されます。
