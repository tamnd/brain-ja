 ## 解決策
 # 問題の理解

 この問題のグラフには、非常に規則的な構造が隠されています。 頂点は連続したレイヤーに配置されます。 すべてのレイヤーには同じ数の頂点が含まれており、エッジはスケルトン パターンに従って隣接するレイヤーの頂点を接続します。 タスクは、この層状の配置を無向グラフのみから復元することです。 

入力は、頂点とエッジの数、その後に続くすべてのエッジを使用してグラフを記述します。 出力には、検出されたレイヤー化、つまり存在するレイヤーの数、各レイヤーに含まれる頂点の数、各レイヤーに属する頂点が記述されている必要があります。 グラフに重要な階層構造が含まれていない場合、グラフ全体が単一のレイヤーとして扱われます。 

制約はグラフの走査を中心に設計されています。 グラフには約 10 万個の頂点とエッジが含まれる可能性があるため、頂点のすべてのペアに対してコストのかかる作業を繰り返し実行したり、可能なすべての階層化を試みたりするソリューションは適合しません。 ソリューションは、ほとんどの操作で線形時間に近い時間を維持し、追加の走査回数を最小限にする必要があります。 

主な問題は、レイヤーが指定されていないことです。 不注意な解決策では、次数が最小の頂点が常に最初のレイヤーであると仮定する可能性がありますが、同じ頂点が最後のレイヤーにも出現する可能性があります。 もう 1 つのよくある間違いは、分割の可能性を見つけた後で、残りのレイヤーが一貫して継続していることを確認せずに停止してしまうことです。 

たとえば、次のような単純なパスを考えてみましょう。```
Input
4 3
1 2
2 3
3 4
```1 つの分割だけを検索する単純な実装では、最初の 2 つの頂点を出力し、残りの半分も同じ構造を満たす必要があることを無視する可能性があります。 正しい出力は次のとおりです。```
4 1
1
2
3
4
```すべてのレイヤーに 1 つの頂点が含まれているためです。 

もう 1 つのエッジ ケースは、すべての頂点が同じ次数を持つグラフであるため、任意の低次数の頂点を選択するだけでは十分ではありません。 例えば：```
Input
4 4
1 2
2 3
3 4
4 1
```不注意なアプローチでは、パスのような分解を強制しようとする可能性がありますが、サイクルはサイズ 2 の 2 つの層として表すことができます。```
2 2
1 4
2 3
```検証段階では、無効な推測を拒否し、実際のスケルトン分解のみを保持する必要があります。 

## アプローチ

 直接的なアプローチは、考えられるすべての最初の層を試してみることです。 考えられる頂点のすべてのサブセットについて、それが有効な層状グラフの最初の部分を形成しているかどうかをテストし、その後、残りの層を拡張し続けることができます。 有効な答えはこれらの選択肢のいずれかで始まる必要があるため、これは正しいですが、可能なサブセットの数は指数関数的であるため、中程度のサイズのグラフであっても不可能になります。 

もう少し優れた強引なアイデアは、開始頂点を選択し、幅優先検索を繰り返し実行して距離を決定することです。 これは、スケルトン内のレイヤーが距離グループに対応するという事実を利用します。 ただし、多くの可能な開始点からこれを実行すると、コストがかかりすぎます。 すべての頂点から完全な BFS を実行するには O(n(n + m)) の操作が必要ですが、これはこのサイズのグラフで許容される制限をはるかに超えています。 

重要な点は、最小次数の頂点は最外層に属している必要があるということです。 それが厳密にスケルトンの内部にある場合、両側に隣接するものがあるため、最小次数を持つことができません。 構造は対称であるため、1 つの最小次数頂点が最初の層に属すると想定できます。 

最初の層の頂点と 2 番目の層のその隣接頂点の 1 つがわかったら、2 回の BFS 実行でグラフをこのエッジの両側に分離するのに十分です。 すべての頂点について、選択した 2 つの端点との距離を比較します。 最初の端点に近い頂点は最初の辺に属し、2 番目の端点に近い頂点はもう一方の辺に属します。 これにより、最初のレイヤーの境界が得られます。 

1 つのレイヤーが既知になると、後続のすべてのレイヤーが強制されます。 次のレイヤの頂点は、現在のレイヤに隣接する、前のレイヤには出現していない頂点です。 構築は、すべての頂点が割り当てられるまで続行できます。 

残りの作業は検証です。 推測された最初の層が間違っている可能性があるため、生成された層をチェックする必要があります。すべての層が同じサイズである必要があり、各頂点が隣接する層と予期された接続を正確に持っている必要があります。 検証された分解のみが受け入れられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数関数または O(n(n + m)) はバリアントに応じて | O(n + m) | 遅すぎる |
 | 最適 | O(m√m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 次数が最小の頂点を見つけます。 構造は対称であるため、有効な解を失うことなくこの頂点を最初の層に配置できます。 
2. この最小次数の頂点のすべての隣接点について、それらの間のエッジを第 1 層と第 2 層の間の可能な接続として扱います。 両方のエンドポイントから BFS を実行します。 

距離によってグラフが 2 つの側面に分割されます。 最初の端点に近い頂点はスケルトンの最初の部分に属し、2 番目の端点に近い頂点は残りの部分に属します。 
3. 最初の面を最初のレイヤーの候補として使用します。 そのサイズが頂点の数を分割できるかどうかを確認します。 すべてのレイヤーのサイズは等しいため、レイヤーの可能な数はこれだけになります。 
4. レイヤーを 1 つずつ展開します。 次のレイヤーは、現在のレイヤーに隣接するすべての未割り当ての頂点で構成されます。 

スケルトン グラフでは、エッジは近くのレイヤーのみを接続するため、これが機能します。 現在の最後の層の未割り当ての隣接層は、次の層でなければなりません。 
5. 完全な分解を確認します。 すべてのレイヤーが同じサイズであること、およびすべての頂点に、そのレイヤー内および隣接するレイヤーへの必要な数の接続があることを確認してください。 
6. 有効な分解が見つかった場合は、それを印刷します。 機能する候補がない場合は、1 つのレイヤー内のすべての頂点を含む自明な分解を出力します。 

なぜ効果があるのか​​:

このアルゴリズムは、階層化されたグラフの距離プロパティに依存します。 2 つの連続するレイヤーを接続するエッジの場合、そのエッジの片側のすべての頂点は 1 つの端点に近くなり、もう一方の側のすべての頂点はもう一方の端点に近くなります。 これにより、BFS を使用して最初の分割を回復できるようになります。 有効なスケルトンはレイヤーをスキップできないため、1 つのレイヤーが固定されると、残りのレイヤーは一意に決定されます。 最終的な検証では誤った推測が削除されるため、出力されるすべての分解は必要な構造を満たします。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def bfs(start, graph):
    n = len(graph) - 1
    dist = [-1] * (n + 1)
    dist[start] = 0
    q = deque([start])

    while q:
        x = q.popleft()
        for y in graph[x]:
            if dist[y] == -1:
                dist[y] = dist[x] + 1
                q.append(y)

    return dist

def check_layers(layers, graph, n):
    if not layers:
        return False

    size = len(layers[0])
    if size == 0 or n % size != 0:
        return False

    if any(len(layer) != size for layer in layers):
        return False

    where = [-1] * (n + 1)
    for i, layer in enumerate(layers):
        for x in layer:
            if where[x] != -1:
                return False
            where[x] = i

    for x in range(1, n + 1):
        if where[x] == -1:
            return False

        same = 0
        prev = 0
        nxt = 0

        for y in graph[x]:
            if where[y] == where[x]:
                same += 1
            elif where[y] == where[x] - 1:
                prev += 1
            elif where[y] == where[x] + 1:
                nxt += 1
            else:
                return False

        if same > 2:
            return False

        if where[x] == 0:
            if prev != 0:
                return False
        else:
            if prev == 0:
                return False

        if where[x] == len(layers) - 1:
            if nxt != 0:
                return False
        else:
            if nxt == 0:
                return False

    return True

def solve():
    n, m = map(int, input().split())
    graph = [[] for _ in range(n + 1)]
    deg = [0] * (n + 1)

    for _ in range(m):
        a, b = map(int, input().split())
        graph[a].append(b)
        graph[b].append(a)
        deg[a] += 1
        deg[b] += 1

    mn = min(deg[1:])
    start = next(i for i in range(1, n + 1) if deg[i] == mn)

    ans = None
    d1 = bfs(start, graph)

    for nxt in graph[start]:
        d2 = bfs(nxt, graph)

        first = []
        ok = True
        for i in range(1, n + 1):
            if d1[i] == d2[i]:
                ok = False
                break
            if d1[i] < d2[i]:
                first.append(i)

        if not ok:
            continue

        layers = [first]
        used = [False] * (n + 1)
        for layer in layers:
            for x in layer:
                used[x] = True

        while len(layers[-1]) < n:
            cur = []
            for x in layers[-1]:
                for y in graph[x]:
                    if not used[y]:
                        used[y] = True
                        cur.append(y)
            if not cur:
                break
            layers.append(cur)

        if sum(map(len, layers)) == n and check_layers(layers, graph, n):
            ans = layers
            break

    if ans is None:
        print(1, n)
        print(*range(1, n + 1))
    else:
        print(len(ans), len(ans[0]))
        for layer in ans:
            print(*layer)

if __name__ == "__main__":
    solve()
```BFS 関数は、選択した頂点からの距離を計算します。 ここで BFS が使用される唯一の理由は、グラフの層状の性質です。つまり、層間を移動すると最短経路距離が予測どおりに変化します。 

メイン ループは、最小次数の頂点のすべての近傍を第 2 層アンカーの可能性としてテストします。 選択した頂点の次数が最小であり、作業の総量が意図した範囲内に収まるため、そのような近傍は十分に少なくなります。 

の`check_layers`機能はソリューションのセーフティネットです。 すべての頂点がそのレイヤーとそのすぐ隣のレイヤーにのみ接続していることを確認することで、誤った推測を検出します。 頂点が使用済みとしてマークされると、その頂点は別のレイヤーに表示されないため、割り当ての順序は重要です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m√m) | 最小次数の頂点には最大で O(√m) 個の可能な近傍があり、各候補には線形グラフ処理が必要です。 |
 | スペース | O(n + m) | 隣接リスト、BFS アレイ、レイヤー ストレージはすべてリニア メモリを使用します。 |

 このアルゴリズムは、頂点のすべてのペアに対する操作を回避します。 グラフは少ない回数だけ処理されるため、大きな入力サイズに適合します。

 ## 特殊なケース

 1 つの頂点を含む最小サイズのグラフの場合、エッジは存在せず、分割される可能性もありません。 このアルゴリズムは近隣ループに入ることはなく、単純な 1 層の答えを返します。 これにより、欠落した近傍へのアクセスや空のレイヤーの作成が回避されます。 

複数の頂点が最小次数を共有するグラフの場合、アルゴリズムは一意の開始点を想定しません。 候補を 1 つ選択し、最終的な検証に依存します。 その選択によって有効なスケルトンが生成されない場合は、別の近傍または自明な答えが考慮されます。 

サイクルなどの対称グラフの場合、距離の比較により不明確な分割が作成される可能性があります。 検証ステップは、無効な距離パーティションが印刷されるのを防ぐものです。 レイヤ接続ルールを満たすパーティションのみが生き残ります。 

すべてのレイヤーに頂点が 1 つだけあるパスなど、非常に小さなレイヤーの場合は、等サイズ条件が機能します。 このアルゴリズムではレイヤーに複数の頂点を含める必要がないため、これらのケースは自然に処理されます。
