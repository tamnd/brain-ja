 ## 解決策
 ## 問題の理解

 次のような長方形のグリッドが与えられます。$n$行と$m$列。 各セルは単一の文字ではなく、固定長の短い文字列です。$k$。 したがって、グリッド内のすべての位置に「単語」が格納され、グリッド内のすべての単語は非常に厳密なパターンに従うことになります。 

グリッドには特別なセルが 1 つだけあります。 その他すべて$n \cdot m - 1$セルにはまったく同じ文字列が含まれていますが、特殊なセルはこの一般的な文字列とは少なくとも 1 文字異なります。 グリッドにはそのような外れ値が 1 つだけ含まれることが保証されており、私たちのタスクは行と列を出力してその外れ値を見つけることです。 

構造は重要です。個々の文字を比較するのではなく、長さのブロック全体を比較しています。$k$。 入力形式はすべてを連結します。$m \cdot k$行ごとに文字数が異なるため、推論する前に各セルを再構築する必要があります。 

制約$n, m \le 200$せいぜい意味する$40{,}000$細胞、そして$k \le 10$各トークンの抽出を安価に行うことができます。 これにより、すべてのセルに対する線形スキャンよりも複雑なものは即座に排除されます。$O(nm \cdot k)$操作は簡単です。 

すべてのセルのペアを比較する素朴なアプローチは次のようになります。$O((nm)^2 \cdot k)$、最悪の場合、比較は数十億件に達し、不要になります。 

いくつかの特殊なケースは分離する価値があります。 

奇数セルの文字列の最後の文字のみが異なる場合でも、文字ごとのグローバル頻度チェックによって正しく検出されますが、単純な全文字列ハッシュ手法により、衝突や書式ミスがないことを保証する必要があります。 

もし$k = 1$の場合、問題は、1 つのエントリを除いてすべてが同一であるグリッド内で一意の要素を見つけることにまで発展します。 複数文字の文字列を想定するメソッドは、特殊な大文字小文字のエラーを発生させずにこのケースを処理する必要があります。 

異常な文字列が視覚的には一般的な文字列に似ているが、1 文字だけ異なっている場合でも、行方向または列方向の部分スキャンによってその文字列が正しく分離されますが、これは比較がプレフィックスではなく完全なトークンに対して行われた場合に限られます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのセル文字列を再構築し、それぞれを他のすべての文字列と比較します。 すべての候補セルについて、グリッド内に同一の文字列がいくつ存在するかを数えます。 文字列が 1 回だけ出現するセルが答えです。 

これが機能するのは、この問題が一意の外れ値を保証しているためです。 ただし、すべてのペアを比較するには時間がかかりすぎます。$O((nm)^2 \cdot k)$操作。 と$nm = 40{,}000$、これは周りにつながります$1.6 \times 10^9$これは一般的な限界を超えています。 

重要な観察は、ペアごとの比較が必要ないということです。 通常のセルはすべて同一であるため、正しい文字列が少なくとも 2 回出現します。 奇妙なものは 1 回だけ表示されます。 これにより、問題は周波数識別タスクに変換されます。 

したがって、構造を比較する代わりに、各セルを 1 つの識別子 (完全な文字列) に圧縮し、カウントを保存し、一意の出現箇所を見つけます。 これにより、問題は線形スキャンとハッシュまたは辞書カウントに軽減されます。 

入力文字列レイアウトの構造も重要です。各行は次の文字列の連結です。$m$長さのブロック$k$したがって、正しい解析が不可欠です。 一度解析されると、すべては標準周波数の問題に帰着します。$nm$アイテム。

 ## アルゴリズムのチュートリアル

 この問題は、各セルを文字列トークンとして扱い、出現回数をカウントすることで解決します。 

1.読む$n, m, k$。 これらは、存在するセルの数と各セル文字列の大きさを定義します。 
2. 各行について、長さの完全な連結文字列を読み取ります。$m \cdot k$。 後でブロックにスライスします。 
3. 各行を次のように分割します。$m$部分文字列、それぞれの長さ$k$。 各部分文字列は、位置にある 1 つのグリッド セルを表します。$(i, j)$。 
4. 各セル文字列を、出現回数を追跡するハッシュ マップ (または辞書) に挿入します。 その際、最初に出現した位置も保存します。 
5. すべてのセルを処理した後、周波数マップをスキャンし、1 回だけ出現する文字列を見つけます。 これが異常細胞です。 
6. その一意の文字列に対応する保存された座標を出力します。 

挿入中に座標を保存する理由は、後で位置を再計算するときにグリッドを再度通過する必要があり、これは不必要であるためです。 

### なぜ効果があるのか

 すべての非特殊セルは問題定義によって同一であるため、頻度マップ内の同じキーに寄与します。 特殊セルは少なくとも 1 文字が異なり、異なるキーを形成することが保証されます。 このようなセルは 1 つだけ存在するため、その頻度は正確に 1 ですが、他のすべてのセルの頻度は少なくとも 1 重複数以上です。 一意性制約により、選択に曖昧さがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m, k = map(int, input().split())
    
    freq = {}
    pos = {}
    
    for i in range(n):
        row = input().strip()
        for j in range(m):
            cell = row[j * k:(j + 1) * k]
            if cell not in freq:
                freq[cell] = 0
                pos[cell] = (i + 1, j + 1)
            freq[cell] += 1

    for cell, cnt in freq.items():
        if cnt == 1:
            r, c = pos[cell]
            print(r, c)
            return

if __name__ == "__main__":
    main()
```実装における主な詳細は、慎重にスライスすることです。各セルはインデックスから始まります。$j \cdot k$そしてで終わります$(j+1)\cdot k$。 ここでのオフバイワンエラーが最も一般的なミスの原因です。 

また、出力座標を格納するときに行インデックスが 0 ベースから 1 ベースに変換されることも保証します。

 行 2: AA BB CC

 | ステップ | セル | 周波数マップの状態 |

 | 2 | BB | {AA: 1、BB: 1} |
 | 3 | BB | {AA: 1、BB: 2} |
 | 4 | AA | {AA: 2、BB: 2} |
 | 5 | BB | {AA: 2、BB: 3} |

 固有の要素は CC で、記録された位置にあります。 

このトレースは、位置を直接比較する必要はなく、周波数だけを比較する必要があることを示しています。

 | 2 | XY | {XY: 2} |

 ## 特殊なケース

 重要なエッジ ケースは、特別なセルが、それ以外は同一の文字列内で 1 文字だけ異なる場合です。 その場合、プレフィックスベースのグループ化は失敗しますが、完全な文字列ハッシュにより正しく分離されます。 

もう 1 つのケースは、一意のセルが最初の行または最初の列に表示される場合です。 最初の遭遇時に位置を保存するため、後で重複が処理された場合でも、座標を正確にキャプチャします。 

最後のケースは、すべてのセルがほぼ同一に見えるが、印刷不可能な ASCII 文字が異なる場合です。 文字列を生のバイト シーケンスとして扱うため、頻度カウントの信頼性は維持され、文字セマンティクスの影響を受けません。
