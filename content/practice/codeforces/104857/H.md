 ## 解決策
 ## 問題の理解

 入力サイズとともに増加する 2 つの相互再帰関数が与えられていますが、各関数は線形的にわずかに小さい整数に依存するのではなく、かなり小さい引数、具体的には現在の入力の半分のバージョンで評価されるもう一方の関数に依存します。 この定義には、入力自体に比例する直接コストと、再帰呼び出しから生じる競合コストも含まれます。 

各クエリ値について$m$、ゼロの基本値から開始して両方の関数の値を計算するように求められます。 各クエリは独立していますが、再帰構造は同一であるため、実際のタスクは、単純にシミュレーションするのではなく、この結合された再帰の閉じた動作を理解することです。 

入力範囲により、総当たりの拡張が不可能になります。 それぞれ$m$と同じ大きさにすることができます$10^{15}$したがって、すべての値をゼロまで反復したり、完全な DP テーブルを構築したりするアプローチは実行不可能です。 ただし、再帰の深さは対数です。$m$これは、正しい解決策が次のバイナリ構造に沿って計算を圧縮することを強く示唆しています。$m$。 

この種の相互再帰における微妙な落とし穴は、再帰項がしきい値を超えた後でのみ線形項を支配できることを認識せずに、基本ケースからの単調伝播を仮定することです。 これにより通常、小さい値が恒等関数に従い、大きい値が再帰的爆発パターンに切り替わる区分的な動作が作成されます。 

## アプローチ

 直接シミュレーションでは、次の計算が試行されます。$f(n)$そして$g(n)$ゼロに達するまで両方の定義を繰り返し拡張します。 各評価は入力サイズの半分で他の関数の 4 つの再帰呼び出しに分岐するため、再帰ツリーは指数関数的に成長します。 メモ化しても、個別の状態の数は依然として増加する可能性があります$O(m)$最悪の場合、圧縮が認識される前に多くの中間整数が出現する可能性があるためです。 

重要な観察は、再発が の正確な値に決して依存しないことです。$n$、線形項を取るかどうかのみに基づいて$n$または依存する再帰項$n/2$。 これは、ソリューションの構造が完全に次のバイナリ表現によって決定されることを意味します。$n$, 半分にすることはビットをシフトすることに対応するためです。 

間の相互依存関係$f$そして$g$対称性が崩れます。 どちらの関数も同じ構造規則を満たしており、それぞれが直接コストのどちらかを選択しようとします。$n$そしてもう一方の関数は 4 倍に増幅されます。$n/2$。 どちらの関数も名前を交換するまでは同一に定義されているため、同じ基本条件から同一に進化します。 

これにより、問題が 1 回だけ再発することになります。$$A(n) = \max(n, 4 \cdot A(\lfloor n/2 \rfloor)), \quad A(0)=0$$そして両方の答えは次と等しい$A(n)$。 

各ステップで引数が半分になるため、計算は対数再帰になります。

 ## アルゴリズムのチュートリアル

 単一関数を計算します$A(n)$クエリごとに 2 回出力します。 

1. 再帰関数を定義する$A(n)$入力の値を返す$n$。 もし$n = 0$、指定された基本値を返します$A(0)$。 これにより再帰が固定され、無限降下が防止されます。 
2. ポジティブな場合$n$を評価して候補の再帰寄与を計算します。$A(n // 2)$。 これは、両方の関数が半分の入力に依存するという元の問題の構造を反映しています。 
3. 再帰的な結果を 4 で乗算します。 これは、元の定義の 4 つの対称呼び出しに対応し、単一のスケーリングされた寄与に集約されます。 
4. 線形コストを比較する$n$再帰的コストを伴う$4 \cdot A(n // 2)$。 2 つの最大値を返します。 これは、現在のレベルに対して直接支払うか、再帰構造にコストを委任するかの競合を捉えています。 
5. それぞれの結果をメモする$n$再帰中に発生しました。 各クエリはチェーンのみをトラバースするため、$n, n/2, n/4, \dots$、繰り返されるサブ問題は効率的に再利用されます。 

### なぜ効果があるのか

 再帰の各レベルで、関数には 2 つの意味のある拡張方法しかありません。現在の入力サイズを直接支払うか、半分のサイズの 4 つの部分問題に拡張するかのいずれかです。 どちらの選択でも部分問題の同じ構造が維持されるため、再発は自己相似になります。 これにより、最適な値が$n$の最適値のみに依存します。$n/2$、他の中間構造は結果を改善したり悪化させたりすることはできません。 間の対称性$f$そして$g$両方の関数が同じ反復パスをたどることが保証され、すべての入力に対して同一になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

f0, g0, T, MOD = map(int, input().split())

memo = {}

def A(n):
    if n == 0:
        return f0  # same for both due to symmetry assumption in recurrence base handling
    if n in memo:
        return memo[n]
    half = A(n // 2)
    memo[n] = max(n, 4 * half)
    return memo[n]

for _ in range(T):
    m = int(input())
    ans = A(m) % MOD
    print(ans, ans)
```この実装は再帰構造を直接反映しています。 メモ化辞書は必須です。そうしないと、再帰によってクエリ間で同じ半分の状態が繰り返し再計算されてしまうからです。 

重要な点は、すべてのクエリが同じメモ テーブルを共有していることです。これは正しいことです。なぜなら、繰り返しは決定的であり、次の値のみに依存するからです。$n$、クエリの順序ではありません。 もう 1 つの詳細は、結果がモジュロで計算されることです。$M$モジュロを取ると線形項と再帰項の間の順序が崩れてしまうため、再帰内ではなく出力時にのみ実行されます。

def run(inp: str) -> str:

 ## 特殊なケース

 エッジ ケースの 1 つは、入力が正確にゼロの場合です。 再帰は直ちに停止し、さらに半分にしようとせずに基本値を返す必要があります。 入力$n=0$基本ケースを直接トリガーするため、それ以上の計算は発生しません。 

もう一つのケースは次のような場合です。$n=1$。 ここで再帰的ブランチは評価します$A(0)$、したがって、間の決定は$1$そして$4 \cdot A(0)$関数が線形のままかジャンプするかを決定します。 これは、漸化式が恒等関数から逸脱する可能性がある最初の点です。 

3 番目のケースは 2 の大きな累乗で、繰り返しの半分化が分岐の不規則性なく正確に整数に到達します。 このような場合、再帰はクリーンなパスをたどります$n \to n/2 \to n/4 \dots$、メモ化により各レベルが 1 回計算されるようになり、最適な対数パフォーマンスが得られます。
