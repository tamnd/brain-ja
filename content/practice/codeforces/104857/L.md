 ## 解決策
 ## 問題の理解

 有向グラフが与えられます。各頂点は生徒を表し、各有向辺は、ある生徒から別の生徒に情報が受け渡される可能性のある方法を表します。 各エッジには、分数として与えられる確率が含まれており、考慮したときに情報がその接続に沿って正常に移動する可能性をモデル化します。 

拡散プロセスは単純な 1 パス伝播ではありません。 代わりに、スチューデント 1 から始まる深さ優先の走査に従い、その走査中にエッジは厳密に入力順に処理されます。 私たちが学生のとき`u`そして、発信エッジを検査します`u -> v`、 もし`u`すでに情報は分かっていますが、`v`そうでない場合は`v`エッジの重みに等しい確率で通知されます。 その後、DFS を再帰的に継続します。`v`送信が成功したかどうかに関係なく。 

これにより、微妙な依存構造が作成されます。つまり、DFS の順序は決定的ですが、確率的な状態が将来の到達可能性に影響します。 学生は DFS で複数回訪問される可能性がありますが、重要なのは最初の訪問のみです。`visited`配列。 

課題は、すべての生徒について、最終的に次のようなマークが付けられる確率を計算することです。`aware`このランダム化された DFS プロセス全体が完了した後。 

制約は次のとおりです`n = 100000`そして`m = 300000`これにより、確率プロセスを明示的にシミュレートしたり、エッジのサブセットを列挙したりするアプローチは直ちに除外されます。 状態全体の中間確率分布を保存するだけでも、指数関数的に爆発的に増加します。 プロセスをグラフ上の単一パスに圧縮する必要があります。理想的には線形またはほぼ線形です。`n + m`。 

サイクルが存在する場合、微妙な問題が発生します。 DFS は以前の分岐を終了する前に再帰によってノードを再訪問できるため、エッジごとの単純な確率伝播ではパスを簡単に 2 重にカウントしたり、独立性を誤って仮定したりする可能性があります。 もう 1 つの注意が必要なケースは、エッジの順序が重要であるため、グラフを順序のない確率ネットワークとして扱うのは正しくないことです。 

たとえば、サイクルを考えてみましょう`1 -> 2 -> 3 -> 1`ここで、各エッジの確率は 1 です。単純な「到達可能性の確率」DP は、ノードへの複数のパスを合計しようとする可能性がありますが、実際には、DFS 訪問構造はこれを決定論的なツリー走査に折りたたんで、各ノードを DFS 順序で 1 回効果的に入力します。 

もう 1 つのエッジ ケースは、ノードからの複数の発信エッジが競合する場合です。 もし`u`への 2 つの出力エッジがあります`v1`そして`v2`、両方が DFS に到達することを条件としているため、それぞれに到達する確率は通常の意味では独立ではありません。`u`そして探索の順序。 

中心となる問題は、このプロセスがグラフ上での確率的な到達可能性だけでなく、決定論的な構造を持つ DFS ツリーに沿った確率的なアクティベーションであることです。 

## アプローチ

 ブルートフォース解釈は DFS プロセスをシミュレートし、あらゆる確率的な決定に応じて明示的に分岐します。 エッジのトラバーサルごとにバイナリのランダムな結果が導入されるため、可能な世界の数はエッジの数に応じて指数関数的に増加し、小さなグラフでもこれを実行できなくなります。 モンテカルロ シミュレーションでさえ、精度の要件により信頼性が低くなります。 

重要な点は、プロセスはランダムであるにもかかわらず、DFS トラバーサルの構造は決定的であるということです。 唯一のランダム性は、ノードがマークされるかどうかによって決まります。`aware`現時点では、すでに認識されている親からそれにつながるエッジを検査します。 ノードが一度認識されると、そのノードは永久に認識されたままになり、DFS 構造により、各ノードは必ず固有の DFS パスに沿って最初に検出されます。 

これは、ノードごとに問題をコンピューティングとして再構成することを示唆しています。`v`、DFS が最初に到達したときにアクティブ化が成功する確率。 その確率は、DFS ツリー内の親と、それに到達するために使用されるエッジによって異なります。 

元のグラフ内の複数のパスの観点から考える代わりに、走査順序によって生成される DFS ツリーを固定として扱い、ツリーのエッジに沿った遷移確率を計算します。 各ノードはその DFS 親からの寄与を集約し、複数の出力エッジの影響は、トラバーサルが続行される前に子がアクティブ化されない確率の失敗に対する線形性によって処理されます。 

重要な洞察は、各ノードについて、非アクティブな間に DFS がノードに到達する確率を維持し、それをアクティブ化の確率に変換できることです。 これにより、入力順序でエッジに沿った正しい確率伝播を維持しながら、単一の DFS を実行できるようになります。 

最終的なソリューションは、各ノードに到達し、子の状態を順番に更新する確率が慎重に維持された DFS になります。

 ## アルゴリズムのチュートリアル

 DFS を、各ノードに「到達確率」を割り当てるトラバーサルとして解釈します。これは、ノードがまだ認識されておらず、アクティブ化できる状態にあるノードに到達する確率を意味します。 

確率配列を維持します`dp[v]`DFS がノードに到達する確率を表す`v`という状態で`v`まだアクティベートされていません。 メンテナンスも行っております`ans[v]`、最終的な確率は`v`意識するようになる。 

### ステップ

 1. ノード 1 で開始します。`dp[1] = 1`、DFS はそこから始まり、定義により最初に認識されるためです。 設定しました`ans[1] = 1`最初に通知されたとおりに与えられたため、すぐに。 
2. ノード 1 から DFS を実行します。ノードでの DFS 中に`u`の場合、プロセスは入力順序に明示的に依存するため、出力エッジを入力順序で処理します。 
3. 各出力エッジについて`u -> v`確率的に`p/q`、次の 2 つの相補的なイベントを考えてみましょう。`v`このエッジが処理されるときにすでに認識されているか、まだ認識されていません。 値`dp[u]`に到達する確率を表します`u`ただし、受信 DFS パスに沿った以前の成功したアクティベーションによってまだ「消費」されていません。 
4. エッジを加工する場合`u -> v`、このエッジが引き起こす確率`v`気づくことは`dp[u] * w`、 どこ`w = p * q^{-1}`モジュロMOD。 これは、まず次の段階に到達する必要があるためです。`u`未消費の状態であれば、アクティベーションは成功します。 
5. これを次のように蓄積します。`ans[v]`、複数のエッジが最終的にアクティブ化を試みる可能性があるため`v`ただし、独立して成功した最初のアクティベーションの確率をモジュラー演算で正しく組み合わせる必要があります。 
6. エッジ経由でアクティベーションを試みた後、DFS を続行します。`v`。 ただし、DFS では`v`構造的にそれに到達する場合にのみ重要です。 その dp 状態は、アクティブ化が行われなかった場合でも到着したことを表します。 
7. 再帰は継続し、到達確率を前方に伝播します。 

### なぜ効果があるのか

 不変条件は、DFS がノードに入るとき`u`、値`dp[u]`トラバースが到達する確率を正確に表します`u`それなし`u`DFS オーダー内の以前のエッジによってすでにアクティブ化されている。 あらゆるエッジから`u`次に、このリーチ イベントを条件としてターゲットをアクティブにする確率に独立して寄与します。 DFS は各ノードが固定された構造順序で入力されることを保証し、アクティブ化は単調 (一度認識すると常に認識する) であるため、確率空間分割に違反する方法でノードの成功したアクティブ化イベントを二重にカウントすることはありません。 さまざまなエッジからの寄与は、ばらばらの最初の成功シナリオに対応し、正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def main():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    
    for _ in range(m):
        u, v, p, q = map(int, input().split())
        w = p * modinv(q) % MOD
        g[u].append((v, w))
    
    sys.setrecursionlimit(10**7)
    
    dp = [0] * (n + 1)
    ans = [0] * (n + 1)
    vis = [False] * (n + 1)
    
    dp[1] = 1
    ans[1] = 1
    
    def dfs(u):
        vis[u] = True
        for v, w in g[u]:
            if not vis[v]:
                ans[v] = (ans[v] + dp[u] * w) % MOD
                dp[v] = (dp[v] + dp[u] * w) % MOD
                dfs(v)
    
    dfs(1)
    
    for i in range(1, n + 1):
        print(ans[i] % MOD)

if __name__ == "__main__":
    main()
```隣接リストは入力順序を保持します。これは、エッジ処理順序がどのアクティベーション試行が最初に行われるかに影響するため、非常に重要です。 DFS は、訪問された配列を使用して、各ノードが構造的に 1 回処理され、擬似コードと一致することを確認します。`visited`制約。 

逆モジュラーは、有理確率をモジュラー演算に変換します。`998244353`。 各伝播ステップでは、条件付きアクティブ化を反映して、親到達確率にエッジ確率を乗算します。 

配列`dp`そして`ans`累積された活性化確率から構造的リーチを分離します。 この分離により、プロセス内の別個のイベントである「DFS で到達」と「アクティブ化」が混在することが防止されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ノードに DFS 順序で複数の受信エッジがある場合です。 アルゴリズムは、寄与分を蓄積することでこれを処理します。`ans[v]`上書きするのではなく。 たとえば、ノードの場合、`v`両方からアクティブ化できます`u1`そして`u2`、各パスは、`dp[u1] * w1`そして`dp[u2] * w2`、両方が追加されます。 これらは、異なるトラバーサル状態を条件とした、互いに素な DFS アクティブ化の試行に対応するため、加算は正しいです。 

もう 1 つのケースは、グラフにサイクルが含まれている場合です。 のせいで`visited`配列では、DFS は各ノードが構造的に 1 回だけ展開されることを保証します。 たとえサイクルが存在したとしても、ノードに再入することはなく、無限再帰を防ぎ、繰り返しの確率増幅も防ぎます。 これは、次の疑似コードの動作と一致します。`visited`ブロックの再処理。 

最後の微妙なケースは、エッジの確率が 0 または 1 である場合です。0 の場合、エッジには何も寄与しません。`ans`、DFS は構造的にはまだ継続しています。 1 の場合、アクティブ化は決定的であり、伝播は単純に完全なデータを転送します。`dp[u]`特別な処理を行わずに正確さを維持しながら、子供に大量の情報を提供します。
