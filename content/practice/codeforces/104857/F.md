 ## 解決策
 ## 問題の理解

 バルーンの色のシーケンスが与えられます。各バルーンの色は短い小文字の文字列で表されます。 このタスクは、風船の総数の半分を厳密に超えて表示される色が存在するかどうかを判断することです。 そのような色が存在する場合は、それを出力します。 それ以外の場合は、失敗文字列「uh-oh」が出力されます。 

この構造は本質的に、文字列のマルチセットにおける優位性に関するものです。 厳密な多数要素が存在するかどうかを識別し、存在する場合はそれを返すこと以外に、頻度をリストしたり、その他のことを計算したりすることは求められません。 

入力サイズは最大 100,000 個の文字列で、それぞれの長さは 10 です。これは、文字列のすべてのペアを比較したり、候補ごとにリスト全体を繰り返しスキャンしたりするアルゴリズムは遅すぎることを直ちに示唆しています。 ハッシュを使用して線形時間で頻度をカウントするソリューションが適切です。これは、操作の合計数が挿入と検索の合計が 100,000 程度であり、一般的な制限内に十分収まるためです。 

どの色も 50% のしきい値を超えない場合、微妙なエッジ ケースが発生します。 たとえば、入力が赤、青、黄のような 3 つの異なる色で、それぞれが 1 回出現する場合、出力色は適格ではなく、答えは「えーっ」でなければなりません。 もう 1 つの特殊なケースは、風船のちょうど半分が 1 色の場合です。 たとえば、n = 4 の場合、色がちょうど 2 回出現する場合、それは厳密な「半分以上」の要件を満たさないため、受け入れられるべきではありません。 

もう 1 つの重要なケースは、複数の色が存在するが、カウントが赤 = 3、緑 = 2 の 5 つの風船など、1 つがしきい値をわずかに超えていない場合です。他の色が頻繁に存在する場合でも、主要な色のみが有効です。 

## アプローチ

 直接的なアプローチは、リスト全体をスキャンして各色の出現をカウントし、個別の色ごとに別のスキャンで頻度を再計算することです。 これには色ごとに O(n) の作業が必要となり、すべての色が異なる場合は最悪の場合 O(n^2) になります。 n が 100000 までの場合、これは遅すぎます。 

重要な観察は、同一の文字列にわたって集約された頻度のみを考慮しているということです。 入力の読み取り中に周波数マップを維持すると、単一パスで最大周波数を決定できます。 これにより、問題はカウントし、最大カウントが n/2 を超えているかどうかを確認するようになります。 

別の見方としては、これは文字列に関する古典的な多数要素の問題であるということです。 Boyer-Moore 多数決のようなアルゴリズムは存在しますが、制約を考慮すると、ハッシュ マップがよりシンプルで同様に効率的なソリューションを提供するため、ここでは不要です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | カラーごとのブルート フォース カウント | O(n^2) | お(1) | 遅すぎる |
 | 周波数マップ | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 入力の読み取り中に各色が何回出現するかを保存する辞書を維持します。 

1. 色の頻度を保存するために空のハッシュ マップを初期化します。 これにより、平均して文字列ごとに一定時間の更新とクエリが可能になります。 
2. 各バルーンの色を 1 つずつ読み取り、マップ内のその数を増やします。 これにより、入力処理の終了までに、追加のパスを必要とせずに完全な周波数情報が得られます。 
3. マップを更新するときに、最も高い頻度で色を追跡します。 これにより、後でマップをスキャンすることが回避され、ソリューションが厳密に線形に保たれます。 
4. すべての色を処理した後、最大周波数を n を 2 で割った値と比較します。それが厳密に大きい場合は、対応する色を出力します。 
5. それ以外の場合は、「uh-oh」を出力します。 

厳密な比較を使用する理由は重要です。半分の等価性は問題の条件を満たしません。 

### なぜ効果があるのか

処理中のどの時点でも、周波数マップは、これまでに確認された各色の発生数を正確に反映します。 したがって、最後に最大頻度を持つ色が、データセット全体のグローバル マキシマイザーになります。 正しさの条件は、単一の値が n/2 を超えるかどうかのみに依存するため、答えを決定するには最大頻度を特定するだけで十分です。 配列の他の構造特性は重要ではありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    freq = {}
    best_color = ""
    best_count = 0

    for _ in range(n):
        c = input().strip()
        freq[c] = freq.get(c, 0) + 1

        if freq[c] > best_count:
            best_count = freq[c]
            best_color = c

    if best_count > n // 2:
        print(best_color)
    else:
        print("uh-oh")

if __name__ == "__main__":
    solve()
```ソリューションは辞書を維持します`freq`出現回数をカウントします。 変数`best_count`これまでに確認された最大の周波数を追跡し、`best_color`どの色が達成したかを記憶します。 これにより、辞書の 2 回目のパスが回避されます。 

よくある間違いは、`>= n // 2`の代わりに`> n // 2`、ちょうど半分の確率で表示される色を誤って受け入れます。 もう 1 つの潜在的な落とし穴は、文字列を読み取るときに改行文字を削除するのを忘れることです。これにより、同じ色が異なるキーとして扱われてしまいます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各バルーンは、平均 O(1) 回の辞書操作で 1 回処理されます。 
| スペース | O(k) | ハッシュ マップに格納された k 個の異なる色、最悪の場合 k = n |

 この制約では最大 100,000 個のバルーンが許可されるため、ハッシュを使用したリニア スキャンは快適に効率的です。 各文字列は短く、個別の色のみが保存されるため、メモリの使用も安全です。

 特殊なケースの 1 つは、すべての色が異なる場合です。 周波数マップは引き続き各色を 1 回記録しますが、n/2 を超える値はありません。 入力の場合:```

```アルゴリズムは各周波数を 1 として追跡し、1 が 2 より大きくないため、正しく「うーん」を出力します。 

もう 1 つのケースは、過半数が存在するにもかかわらず、連続しない位置に表示される場合です。 例えば：```
