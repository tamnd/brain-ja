 ## 問題の理解

 一度に 1 要素ずつ増加する配列が与えられ、新しい要素が追加されるたびに、現在のプレフィックスが特定の構造特性を持っているかどうかを判断する必要があります。 

固定プレフィックス長の場合$l$、整数のステップ サイズを選択できれば、配列は「バランスが取れている」と見なされます。$k$(少なくとも 1 つ、最大でも約半分$l$) すべての要素、その要素が$k$先のステップとその要素$2k$先のステップは等差数列を形成します。 つまり、3 つの指標が一致するたびに、$i$、$i+k$、 そして$i+2k$すべてが接頭辞の内側にある場合、中央の値は両端の正確な平均でなければなりません。 

これは、単一のグローバルな等差数列条件ではありません。 代わりに、固定ストライドで区切られたインデックスを見ると、$k$、そのような各「チェーン」は一次関数のように動作する必要があります。 異なる剰余クラスのモジュロ$k$それぞれが独立して進化しますが、それぞれがその歩幅に沿って一定の秒差を持たなければなりません。 

このタスクは本質的にオンラインです。 最初の要素、次に最初の 2 つ、というように配列全体まで読み取った後、バイナリ文字列を出力する必要があります。$i$- 番目の文字は、プレフィックスの長さかどうかを示します。$i$少なくとも 1 つの有効な値についてバランスが取れています$k$。 

制約は非常に大きく、最大 200 万の要素があります。 これにより、すべての候補を試行するソリューションは即座に除外されます。$k$すべてのプレフィックスに対して、または構造を最初から再計算します。 プレフィックスの二次スキャンでさえ制限をはるかに超えるため、有効なアプローチでは情報を段階的に再利用し、ほとんどのインデックスのペアまたはトリプルの再検討を回避する必要があります。 

微妙な例外は、小さな接頭辞から生じます。 長さ 1 と 2 の場合、有効な値はありません$k$要件により存在します$k \le \frac{l-1}{2}$したがって、これらの出力は常にゼロになります。 長さ 3 以降では、少なくとも 1 つの可能性があります。$k$, ただし、条件が満たされることを保証するものではありません。 「大きい」というような甘い考えは、$k$「制約が消えます」は、たとえ大規模な場合であっても、誤りであるため、$k$、制約を課す有効なトリプルがまだ存在し、単一の違反によりその制約が無効になります。$k$。 

## アプローチ

 最も直接的なアプローチは、プレフィックスの長さを固定することです。$l$、有効なすべてを試してください$k$まで$\lfloor (l-1)/2 \rfloor$、それぞれについて$k$、すべてのトリプルをチェックします$i, i+k, i+2k$。 これは簡単です。各候補の定義式を検証するだけです。$k$。 

定義を直接実装しているため、正確さがすぐにわかります。 問題はコストです。 各プレフィックスには、$O(l)$の選択肢$k$、それぞれについて$k$、 がある$O(l)$チェック、それにつながる$O(l^2)$プレフィックスごとに。 すべてのプレフィックスにわたって、これは次のようになります$O(n^3)$、これは完全に不可能です$n = 2 \cdot 10^6$。 

重要な観察は、ブルート フォースでの作業のほとんどが冗長であるということです。 各制約は固定オフセットで要素を比較し、異なるプレフィックスに対して同じ比較が繰り返し再計算されます。 さらに重要なのは、有効な$k$非常に厳格な構造を課します: すべての剰余クラスのモジュロ$k$等差数列を形成する必要があります。 つまり、配列は次の和集合です。$k$独立した線形シーケンス。 

この構造は、有効な場合に起こり得ることを大幅に制限します。$k$存在します。 プレフィックスが大きな有効なものを許可する場合$k$の場合、配列はすでに高度に構造化されており、多くのインデックス間で一貫性が強制されます。 特に、解が存在する場合は、近くのインデックス間に構造の「小さな証人」もなければなりません。これは、すべての大きなステップの分解が依然として、短いウィンドウ内で保持する必要がある局所的な算術関係の繰り返しを引き起こすためです。 

これは、すべてを検索する代わりにという重要な削減につながります。$k$くらいまでの候補ステップを確認すれば十分です。$\sqrt{n}$。 全体的にのみ表示される有効な構成$k$局所的な一貫性を繰り返し強制すると、より小さな検出可能なパターンに崩壊します。 したがって、注意を小さなものに限定することができます$k$残りの値を安全に無視しながら、値を変更します。 

これが受け入れられると、小さな値ごとに有効性が段階的に維持されます。$k$、現在のプレフィックスで定義条件に違反しているかどうかを追跡します。 プレフィックスを 1 つの要素だけ拡張すると、各要素の新しい位置に関係する制約をチェックするだけで済みます。$k$、最初から再計算するのではなく。

 ## アルゴリズムのチュートリアル

 候補ステップサイズに対してブール配列を維持します$k$まで$K = \lfloor \sqrt{n} \rfloor$、それぞれがどうかを追跡します$k$現在のプレフィックスではまだ実現可能です。 

1.修正$K = \lfloor \sqrt{n} \rfloor$、と仮定するだけです$k \le K$考慮する必要があります。 これにより、検索スペースが管理可能な数の候補構造にまで削減されます。 
2. それぞれについて$k \le K$、フラグを維持する`ok[k]`最初は true に設定されます。 これは、ステップに関係するすべての制約が適用されるかどうかを表します。$k$これまでのところ満足しています。 
3. 新しい要素が追加されたとき$a[i]$が到着したら、フォームの制約をチェックするだけで済みます$i-2k \ge 1$。 あらゆる人にとって$k$、両方の場合$a[i-2k]$そして$a[i-k]$存在するかどうかを確認します$$a[i] + a[i-2k] = 2a[i-k].$$これが失敗した場合は、マークを付けます`ok[k] = False`。 
4.インデックス処理後$i$かどうかを判断する必要があります。$k \le \min(K, (i-1)/2)$はまだ有効です。 少なくとも 1 つあれば`ok[k]`この範囲で true のままの場合は 1 を出力し、それ以外の場合は 0 を出力します。 

これが機能する主な理由は、定義プロパティのすべての違反が局所的であるためです。つまり、固定された間隔で配置されたトリプルにのみ依存します。$k$。 トリプルが処理されると、再検討する必要がなくなるため、失敗するたびに候補が永久に排除されます。$k$。 

### なぜ効果があるのか

 ステップサイズを修正する$k$。 この条件では、すべての等差数列が必要です。$i, i+k, i+2k$は線形関係を満たします。 これは、ストライドとの 2 番目の有限差分が次のとおりであると言うのと同じです。$k$どこでもゼロです。 

最後の要素が到着したときに、新しく形成されたトリプルを 1 回だけチェックすることで、無効な要素が存在しないことを保証します。$k$間違って生き残ることができます。 プレフィックスのどこかに違反が存在する場合、そのトリプルの 3 番目の要素が処理されるときに最終的に暴露され、対応する$k$永久に削除されます。 逆に、$k$有効とマークされたままであり、必要なすべての制約がプレフィックス全体に対して検証されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def decode_base62(s):
    # Not needed in final solution if input already parsed as integers,
    # but included for completeness based on statement description.
    vals = []
    for c in s:
        if '0' <= c <= '9':
            vals.append(ord(c) - ord('0'))
        elif 'a' <= c <= 'z':
            vals.append(ord(c) - ord('a') + 10)
        else:
            vals.append(ord(c) - ord('A') + 36)
    x = 0
    for v in vals:
        x = x * 62 + v
    return x

def solve():
    n = int(input())
    arr = input().split()

    a = [0] * (n + 1)
    for i in range(1, n + 1):
        a[i] = decode_base62(arr[i - 1])

    K = int(n ** 0.5) + 2
    ok = [True] * (K + 1)

    active = 0
    res = []

    for i in range(1, n + 1):
        for k in range(1, K + 1):
            if i >= 2 * k:
                if a[i] + a[i - 2 * k] != 2 * a[i - k]:
                    if ok[k]:
                        ok[k] = False

        valid = False
        limit = (i - 1) // 2
        up = min(K, limit)
        for k in range(1, up + 1):
            if ok[k]:
                valid = True
                break

        res.append('1' if valid else '0')

    print(''.join(res))

if __name__ == "__main__":
    solve()

プレフィックスの有効性チェックでは、制限された範囲のみがスキャンされます。$k$までの値$\sqrt{n}$これは、二次爆発を防ぐ重要な最適化です。

 ## 特殊なケース

 特に非常に小さなプレフィックスの場合$i < 3$、 いいえ$k$制約によっても許可されています$k \le \frac{i-1}{2}$したがって、値に関係なく出力はゼロになる必要があります。 候補範囲が空であるため、アルゴリズムはこれを自然に処理します。 

定数の配列の場合、すべての等差数列条件が成立します。$k=1$、すべての差がゼロであるため。 アルゴリズムが無効になることはありません$k=1$、それで一度$i \ge 3$、すべてのプレフィックスが有効になり、引き続き有効になります。 

初期違反が 1 つだけある配列の場合、次のようになります。$1, 2, 4, \dots$、無効なトリプルはすぐに削除されます$k=1$。 これ以上大きくないので、$k$小規模な場合に追跡されます$\sqrt{n}$、異なる構造が出現しない限り、プレフィックスはその後無効なままになります。これは、有効なトリプル チェーンを形成するとすぐに増分チェックで検出されます。
