 ## 解決策
 ## 問題の理解

 一連のクラスにわたる出席状況を表すバイナリ文字列が与えられます。 ストリークは、1 の最大の連続セグメントであり、ゼロまたは文字列の末尾で囲まれた連続した出席クラスのブロックを意味します。 

最大でもフリップすることが許可されています`m`ゼロを 1 にします。 これらのフリップを実行すると、文字列が変化するため、ストリークのセットも変化します。 結果として得られるすべての文字列のうち、最大でも到達可能な文字列は`m`裏返しに、すべてのストリークの長さを昇順でない順に並べ替えます。 目標は、k 番目に大きいストリークの長さを最大化することです。 以下の場合は、`k`ストリークの場合、k 番目の値は次のように定義されます。`-1`。 

重要なオブジェクトは、単に最長のセグメントではなく、複数のセグメントの順序です。 以来`k ≤ 5`、私たちは上部の数本の縞だけを気にしますが、これは強力な構造上の制限です。 

制約`n ≤ 2 × 10^5`そして`m ≤ n`いかなる解も線形に近いか、最大でも線形でなければならないことを意味します。`O(n log n)`。 ゼロを反転するすべての選択肢を試したり、結果として得られるすべての構成を明示的に列挙したりするアプローチは、組み合わせ的に爆発的に発生します。 

素朴な解釈は次のようになります: どちらを選ぶか`m`ゼロを反転し、すべてのストリークを再計算し、k 番目に大きいストリークを追跡します。 ゼロの選択肢の数は`C(n, m)`、それはたとえ小さくても実行不可能です`n`。 

もう少し良いものの、まだ間違っている貪欲なアイデアは、隣接するゼロを反転することによって、既存の最大のストリークを常に拡張することです。 k 番目の位置については、1 つの大きなストリークを延長するよりも 2 つの小さなストリークをマージする方が適切である可能性があるため、これは失敗します。 

複数の中程度のストリークがランキングをめぐって競合する場合、微妙なエッジケースが発生します。 

例：```
s = 10100101, m = 2, k = 2
```最も長いストリークを貪欲に拡張する場合、1 つの長いブロックを作成し、他のブロックは小さいままにする可能性がありますが、最適な構成では、代わりに 2 番目に大きいストリークを最大化するために 2 つのバランスのとれたストリークをマージまたは作成する可能性があります。 

別の失敗例は、縞が異なるサイズのギャップによって分離されている場合に発生します。 1 つの領域でフリップを費やすと、他の場所で使用できるストリークの数が減少する可能性があり、これは k 次の統計に直接影響します。 

重要な問題は、フリップによって長さが増加するだけでなく、セグメントがマージされ、非ローカルな方法でストリークの数が変更されることです。 

## アプローチ

 ブルートフォースの方法は、次のものを選択することです。`m`ゼロの位置を反転し、結果の文字列を再構築し、すべての最大の 1 ランを抽出し、それらを並べ替えて、k 番目に大きいものを評価します。 これは定義に直接従うため、正しいです。 ただし、ゼロのサブセットを選択すると、すでに指数関数的な動作が誘発されます。 選択を無視しても、構成コストごとにストリークを再計算します`O(n)`、合計は実現不可能になります。 

構造観察は逆転の視点から得られます。つまり、どのゼロを反転するかを選択する代わりに、k 個の最良のストリークを構築し、それらのストリーク全体に反転がどのように分散されるかを考えます。 以来`k ≤ 5`、「重要なオブジェクト」の数は少ないです。 これは、一定数のターゲットに対する動的プログラミングまたは貪欲な割り当てを示唆しています。 

問題を、候補値を最大化しようとするものとして再構成できます。`L`k 番目に大きいストリークを求め、実現可能性を確認します。 k 番目のストリークの長さを固定する場合、少なくとも次のものを作成できるかどうかを尋ねることができます。`k`長さが少なくとも以下の適切な値である互いに素なセグメント`m`反転します。 

これは当然、答えの二分探索につながります。 固定閾値の場合`L`、少なくとも同じ長さのストリークをできるだけ多く構築しようとします。`L`貪欲な拡張を使用して可能な限り。 各ストリークでは 1 を収集し、場合によってはその間で 0 を変換する必要があり、断片化によるフリップの無駄が回避されるため、近くのセグメントをマージすることが常に最適です。 

重要な貪欲なアイデアは、一定の長さのストリークを形成することです。`L`、必要な長さに達するまで、常に既存のものから拡張し、近くのゼロを吸収する必要があります。 縞が形成されたら、前進して繰り返します。 これは、選択された各ストリークが最大で重複しないように最適なソリューションを再配置できるため、最適です。 

以来`k`は小さいので、少なくとも取得できるかどうかだけを知る必要があります。`k`特定の有効なストリーク`L`。 「はい」の場合は、増加してみます`L`。

 ## アルゴリズムのチュートリアル

 答えを二分探索することによって問題を解決します。述語は、少なくとも次のものを取得できるかどうかを確認します。`k`少なくとも一定の長さの縞`L`。 

1. 検索範囲を設定します。`L`から`0`に`n`。 各値は、ストリークの目標の最小長を表します。 目標は最大値を見つけることです`L`少なくともそうなるように`k`長さの縞模様`L`形成することができる。 
2. 固定の場合`L`、文字列を左から右にスキャンし、貪欲に縞を構築します。 有効なストリークに拡張できるセグメントに遭遇すると、それを接続または拡張するためにフリップとしてゼロを消費します。 これは、スライディング ウィンドウ スタイルの拡張を使用して行われます。 
3. スキャン中、少なくとも有効な長さのストリークが蓄積されるたびに`L`、それを確定し、次の位置から再開します。 これにより、重なりが防止され、ストリーク間の独立性が保証されます。 
4. 使用したフリップの回数のカウンターを維持します。 いずれかの時点で必要なフリップが超過した場合`m`、私たちは早期に停止し、これを拒否します`L`。 
5. 少なくとも建設できれば`k`縞模様、私たちはマークします`L`可能な限り大きな値を試してください。 それ以外の場合は、検索スペースを減らします。 

貪欲な構築が機能する理由は、選択された各ストリークが可能な限り左揃えになるように最適なソリューションを変換できるためです。 フリップを遅延したり、フリップを再分配したりしても、達成可能な切り離されたセグメントの数が減少するだけです。 

## なぜ機能するのか

 固定ターゲット長の場合`L`、基本的にはできるだけ多くの長さを梱包しています-`L`可能な限りセグメントを文字列に追加します。ゼロは、フリップを使用して補うことができるギャップとして機能します。 貪欲スキャンでは常に、可能な限り最も早いセグメントが最初に消費され、後続のセグメント用に最大限の残りのスペースが残ります。 セグメントを延期する代替の配置は、必要なフリップの数を減らすことなくコストを右方向に押し上げるだけであるため、有効なストリークの総数を改善することはできません。 

二分探索は実現可能性が単調であるため有効です。`k`長さの縞模様`L`、その後、任意の長さに合わせて形成することもできます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(s, n, m, k, L):
    i = 0
    used = 0
    cnt = 0

    while i < n:
        if s[i] == '0':
            i += 1
            continue

        j = i
        used_local = 0
        length = 0

        while j < n and length < L:
            if s[j] == '1':
                length += 1
            else:
                if used + used_local + 1 > m:
                    break
                used_local += 1
                length += 1
            j += 1

        if length >= L:
            used += used_local
            cnt += 1
            i = j
        else:
            i += 1

        if used > m:
            return False
        if cnt >= k:
            return True

    return cnt >= k

def solve():
    n, m, k = map(int, input().split())
    s = input().strip()

    lo, hi = 0, n
    ans = -1

    while lo <= hi:
        mid = (lo + hi) // 2
        if can(s, n, m, k, mid):
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    if k > n:
        print(-1)
    else:
        print(ans)

if __name__ == "__main__":
    solve()
```「少なくとも L 長さの k ストリークを達成できるか」という述語は単調であるため、解決策は答えに対する二分探索から始まります。 の`can`関数は、左から右へ貪欲にストリークを構築することをシミュレートします。 

内部`can`、文字列をスキャンし、`'1'`, そこからスタートして連勝を伸ばそうとします。 展開内のゼロは、必要な反転として扱われます。 現在のストリーク候補に対してグローバルおよびローカルで使用されるフリップの数を追跡します。 ストリークが長さに達すると`L`、私たちはそれをコミットし、そのフリップを世界予算に追加し、前進します。 

重要な実装の詳細は、一度ストリークに含まれたポジションを再利用しないことです。 これにより、縞が分離されたままとなり、定義に一致することが保証されます。 

を超えた場合も早期に終了します`m`またはすでに形成されている`k`ストリーク。チェックごとにランタイムを線形に保ちます。

 ## 特殊なケース

 エッジ ケースの 1 つは、文字列に既に含まれている内容が次の値よりも少ない場合です。`k`縞模様ですが、反転を使用してマージできます。 例えば：```
s = 10001, m = 1, k = 1
```このアルゴリズムは中央のギャップを横切って拡張し、1 回のフリップを使用して、単一の長いストリークを正しく形成します。 貪欲スキャンは常に最も早い有効な位置から拡張しようとするため、両端をマージします。 

もう一つのケースは次のような場合です。`k`完全に変換した後でも、可能なストリークの数よりも大きくなります。```
s = 00000, m = 2, k = 3
```2 つのゼロを 1 に変えても、最大で 2 つの縞が作成できるため、答えは次のようになります。`-1`。 実現可能性チェックは決して達成されない`cnt >= k`、それですべて`L > 0`失敗。 

3 番目のケースは、フリップが豊富であるが、ストリーク構造が断片化されている場合です。```
s = 1010101, m = 10, k = 3
```ここで、最適戦略はすべてを 1 つの長いストリークにマージしますが、`k = 3`、分割することを余儀なくされ、答えは利用可能なフリップの総数ではなく、存在できる互いに素なセグメントの数によって制限されます。
