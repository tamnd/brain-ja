 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$各セルに整数の色が含まれるグリッド。 すべての色について、その色を持つすべてのセルを調べ、そのようなセルの順序付けされたすべてのペアを考慮します。 各ペアについて、座標間のマンハッタン距離を計算し、すべての色にわたるこれらすべての距離を合計します。 

したがって、タスクは任意のセル間の距離に関するものではなく、厳密に各色グループ内の距離に関するものです。 各色はグリッド上の点のセットを形成し、すべてのセットを合計した、各セット内のペアごとのマンハッタン距離の合計が必要です。 

制約$n, m \le 1000$までを暗示$10^6$細胞。 最悪の場合、すべてのセルが同じ色を共有するため、色ごとの単純な 2 次アプローチは明らかに失敗します。$10^{12}$ペア。 すべてのペアにわたるリニア スキャンさえ不可能です。 

微妙な点は、問題が順序付きペアをカウントしていることです。$(i, j)$、順序のないペアだけではありません。 これにより、一意のペアと比較して寄与が 2 倍になります。 単純な解決策では、順序付けされていない距離が計算され、2 を掛けるのを忘れて、不正確な結果が生じる可能性があります。 

重要なエッジケースには次のようなものがあります。 

すべてのセルが同じ色のグリッド。 例えば：```
2 2
1 1
1 1
```順序のないペアはすべて 2 回寄与するため、正解は 8 です。 

もう 1 つのケースは、すべての色が一意である場合です。```
2 2
1 2
3 4
```どの色も複数のセルを持たないため、答えは 0 です。 グループ サイズをチェックせずにペアごとの差を計算しようとする単純な実装では、グループが慎重に処理されないと、不必要な作業が試行されたり、インデックス作成エラーが発生したりする可能性があります。 

## アプローチ

 ブルートフォース ソリューションでは、各色を修正し、そのすべての座標を収集し、順序付けされたすべてのペア間の距離を計算します。 色が出たら$k$倍、これには費用がかかります$O(k^2)$。 すべての色を合計すると、これは次のように縮退します。$O(n^2 m^2)$最悪の場合、1 つの色がグリッド全体を占める可能性があるためです。 

重要な観察は、マンハッタン距離が行座標と列座標からの独立した寄与にきれいに分離されていることです。 2点の場合$(x_1, y_1)$そして$(x_2, y_2)$、$$|x_1 - x_2| + |y_1 - y_2|$$は、純粋に x ベースの項と純粋に y ベースの項の合計として処理できます。 

これは、色のすべての x 座標を y 座標とは独立して扱うことができることを意味します。 貢献度の合計は次のようになります。 

(ペアごとの合計 |x_i - x_j| + ペアごとの合計 |y_i - y_j|) の色の合計。 

ここで問題は、色グループごとに 1D 配列内の絶対差の合計を 2 回 (行に対して 1 回、列に対して 1 回) 計算することに帰着します。 

1D シーケンスの場合、ソートされた値により、プレフィックス累積を使用して線形時間でペアごとの絶対差の合計を計算できます。 すべてのペアを比較する代わりに、実行中のプレフィックス合計を維持し、スイープ中に寄与を蓄積します。 

これにより、ソート後に各色グループが二次から線形に減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O((nm)^2)$|$O(nm)$| 遅すぎる |
 | 最適 |$O(nm \log nm)$|$O(nm)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. セルを色別にグループ化する

 グリッドを 1 回スキャンし、色ごとに行インデックスと列インデックスの 2 つのリストを保存します。 マンハッタン距離が独立した x と y の寄与に分割されるため、この分離が必要です。 

### 2. 色ごとに行座標を処理します。 

その色の行インデックスのリストを並べ替えます。 絶対的な差分をペアごとの比較ではなく構造化されたプレフィックスの合計に置き換えることができるように、並べ替えが必要です。 

### 3. 行から寄与度を計算する

 ソートされた行全体で現在のプレフィックス合計を維持します。 値を処理するとき$x_i$、以前のすべての値$x_j$貢献する$x_i - x_j$、将来のすべての拠出は、後で逆累積で処理されます。 これにより、ペアごとの差が線形更新に変換されます。 

### 4. 列座標についても繰り返します。 

同じ手順を列インデックスにも適用します。 これは、マンハッタン距離の垂直成分を独立して考慮します。 

### 5. すべての色の寄与を合計する

 各色は独立して寄与するため、すべてのグループにわたる結果が蓄積されます。 

### なぜ効果があるのか

 固定色の場合、次のように計算します。$$\sum |x_i - x_j| + \sum |y_i - y_j|$$加算の線形性により、座標の分割が可能になります。 ソートされたプレフィックス方法では、各要素がソート順でその前後にある要素の数に比例するため、すべてのペアが正しい大きさで 1 回だけカウントされることが保証されます。 色間の相互作用は存在しないため、色を個別に処理することで正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def sum_abs_pairs(arr):
    arr.sort()
    res = 0
    prefix = 0
    for i, x in enumerate(arr):
        res += x * i - prefix
        prefix += x
    return res

def solve():
    n, m = map(int, input().split())
    rows = defaultdict(list)
    cols = defaultdict(list)

    for i in range(n):
        line = list(map(int, input().split()))
        for j, c in enumerate(line):
            rows[c].append(i)
            cols[c].append(j)

    ans = 0
    for c in rows:
        ans += sum_abs_pairs(rows[c])
        ans += sum_abs_pairs(cols[c])

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、色をキーとした 2 つのハッシュ マップが維持されます。 各色は行と列の位置を個別に蓄積します。これはマンハッタン距離の分解を維持するために不可欠です。 

機能`sum_abs_pairs`コアの最適化です。 ソート後、固定要素の ID を使用します。$x_i$、以前のすべての要素は合計に寄与します$x_i \cdot i - \text{prefix sum}$。 これにより、明示的なペアの列挙が回避されます。 

よくある間違いは、順序なしリストを反復処理することです。 ソートを行わないと、接頭辞の減算は絶対的な差に対応せず、結果が不正確になります。

```色を独自に処理します。

このトレースは、同一の座標が行の寄与をゼロにし、列の差が優勢であることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    def sum_abs_pairs(arr):
        arr.sort()
        res = 0
        prefix = 0
        for i, x in enumerate(arr):
            res += x * i - prefix
            prefix += x
        return res

    def solve():
        n, m = map(int, input().split())
        rows = defaultdict(list)
        cols = defaultdict(list)

        for i in range(n):
            line = list(map(int, input().split()))
            for j, c in enumerate(line):
                rows[c].append(i)
                cols[c].append(j)

        ans = 0
        for c in rows:
            ans += sum_abs_pairs(rows[c])
            ans += sum_abs_pairs(cols[c])

        return str(ans)

    return solve()

# sample 1
assert run("2 2\n1 1\n2 2\n") == "2"

# sample 2
assert run("1 3\n1 2 1\n") == "2"

# all unique
assert run("2 2\n1 2\n3 4\n") == "0"

# all same
assert run("2 2\n1 1\n1 1\n") == "8"

# line test
assert run("1 4\n5 5 5 5\n") == "12"

 ## 特殊なケース

 密な単色のグリッドは最も敏感なケースです。 例えば：```
2 2
1 1
1 1
```アルゴリズムは行を保存します`[0,0,1,1]`とコラム`[0,1,0,1]`その色のために。 並べ替えると、両方とも次のようになります`[0,0,1,1]`。 行の貢献度は$(1-0) + (1-0) + (1-0) + (1-0) = 4$、列の貢献度は同じで、合計は 8 になります。 プレフィックスサム法により、各ペアが方向ごとに正確に 1 回カウントされることが保証され、対称性の順序付けにより正しい 2 倍の寄与が生成されます。 

2 番目のエッジ ケースは、多くのシングルトン カラーです。 各リストのサイズは 1 なので、並べ替え後はペアがないため、プレフィックス ロジックの寄与は 0 になります。 行と列の寄与が両方ともゼロのままであるため、アルゴリズムは自然に不必要な作業をスキップします。
