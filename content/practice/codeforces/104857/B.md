 ## 解決策
 ## 問題の理解

 値が 1 から n までの範囲の整数のマルチセットが与えられ、各値 i は ai 回現れます。 タスクは、このマルチセットの順列である個別のシーケンス b が、2 つのキューに関係する特別なプロパティを持っている個数を数えることです。 

ここで説明するプロセスは 2 段階のシミュレーションです。 まず、シーケンス b を取得し、その要素を 1 つずつキュー A またはキュー B にプッシュします。すべての要素が配置された後、両方のキューが空になるまで、A または B の前から要素を繰り返し削除し、各ステップでどちらの空でないキューからポップするかを選択します。 目標は、最初にすべて 1、次にすべて 2、というように最大 n までを意味する、グローバルにソートされたシーケンスを生成できるようにすることです。 

この最後のマージプロセスでソートされたシーケンスを出力できるように、その要素を 2 つのキューに割り当てる何らかの方法が存在する場合、シーケンス b は有効であると見なされます。 

制約は、順列または代入に対する指数関数的な列挙を除外するのに十分なほど厳しいものです。 要素の総数は最大でも 500 であるため、m² または m³ 付近の多項式時間で n と m のみに依存する解は妥当ですが、m の階乗は直ちに実行不可能です。 

重要な微妙な点は、自由形式でキューを確認した後で出力方法を選択していないことです。 出力はソートする必要があるため、キューの構造には大きな制約があります。 1 つのキューが内部的に大きい値を小さい値より前に強制的に表示すると、キューの順序が固定されているため、マージ中に修正することができなくなります。 

単純な失敗例は、キューに減少パターンが含まれている場合に発生します。 

たとえば、1 つのキューに 3 が含まれており、その後に 2 が続く場合、抽出中に 3 が 2 より前に出てきて、並べ替え順序が崩れます。 したがって、マージ ステージが柔軟であっても、各キューは個別に、並べ替えられた出力と互換性のある方法で動作する必要があります。 

この観察は主な構造上の制約です。2 つのキューは、グローバルにソートされたストリームを共同で出力する必要がある 2 つのモノトーン バッファとして効果的に機能します。 

## アプローチ

 直接的な総当たりアプローチでは、マルチセットのすべての順列を生成し、次に 2 つのキューへの要素の可能なすべての割り当てを試み、割り当てごとに有効な出力スケジュールが存在するかどうかをシミュレートします。 順列の階乗数を無視したとしても、キュー割り当ての数だけでも 2^m であり、各シミュレーションは O(m) であるため、このアプローチは天文学的に遅すぎます。 

重要な単純化は、視点を逆転させることによってもたらされます。 キューのプロセスをシミュレートする代わりに、どのシーケンス b が有効な割り当てを許可するかを特徴付けます。 各キューは FIFO であるため、要素がキューに配置されると、そのキュー内での相対的な順序は固定されます。 最終的なマージでは、2 つの固定シーケンスのみをインターリーブできます。 マージされた出力をグローバルにソートするには、各キュー自体の値が減少していない必要があります。 

これにより、問題がシーケンス b の分割条件に変換されます。 各キュー内で時間の経過とともに値が減少しないように、b の各位置を 2 つのキューのいずれかに割り当てます。 したがって、各カラー クラスは増加するサブシーケンスを形成する必要があります。 

これは、シーケンスを 2 つの増加するサブシーケンスに分割することに相当します。 ディルワースの視点による古典的な定理は、シーケンスに長さ 3 の減少する部分シーケンスがない場合にまさにこれが可能であることを示しています。言い換えれば、有効なシーケンスとはまさにパターン 321 を回避するシーケンスです。 

したがって、問題は次のようになります。減少するトリプルを回避する、指定された周波数のマルチセットの順列を数えます。

これは既知の構造物です。 最長 2 の減少サブシーケンスを持つ順列は、Robinson-Schensted の下で、最大 2 行のヤング タブローに対応します。 値が繰り返されると、正しい類似物は、最大 2 行の形状と頻度 ai によって与えられる重みを持つ準標準の若いタブローになります。 

したがって、行制約が満たされるように、各値 i の 2 行への割り当てをカウントすることに問題を縮小します。つまり、行は構築によってわずかに増加しており、列の厳密性条件は、最初の行と 2 番目の行に割り当てられる要素の数に関するプレフィックス バランス制約になります。 

値を昇順に処理し、各値のコピーの数を一番上の行に入れるかを決定します。 これは、行 1 と行 2 の要素数の実行差に関する動的計画法の問題になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 並べ替えとキューの割り当てに対するブルート フォース | O(m! · 2^m · m) | O(m) | 遅すぎる |
 | バランス状態の値グループに対する DP | O(n · m^2) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1 から n までの値を昇順に処理し、これまでに 2 つの行のそれぞれに割り当てられた要素の数を維持します。 

DP 状態を定義します。ここで、 dp[d] は、差 d が (row1 のサイズから row2 のサイズを引いたもの) に等しくなるように、値の現在のプレフィックスを処理する方法の数です。 プレフィックス構造では row1 が row2 を下回ってはいけないため、d ≥ 0 の状態のみが有効です。 

頻度 ai の各値 i について、そのコピーを 2 つの行に分配します。 x 個のコピーを row1 に入れると、ai − x は row2 に移動し、バランスは (x − (ai − x)) = 2x − ai だけ変化します。 

ここで、各状態とそれぞれの可能な x に対して遷移を実行します。 

### アルゴリズムのチュートリアル

 1. dp[0] = 1 に初期化します。これは、値を処理する前に、両方の行が空でバランスが取れていることを意味します。 
2. 1 から n までの値 i ごとに、ゼロに初期化された新しい配列 ndp を作成します。 
3. 0 から ai までのすべての可能な現在のバランス d とすべての可能な選択肢 x について、新しいバランス d' = d + (2x − ai) を計算します。 d' が負でない場合は、dp[d] を ndp[d'] に加算します。 
4. 値 i のすべての状態を処理した後、dp を ndp に置き換えます。 
5. すべての値が処理された後、d ≥ 0 のすべての dp[d] を合計して答えを取得します。 

これが機能する理由は、バランス d が 2 行のヤング タブローのプレフィックス制約をエンコードしているためです。値を順番に読み取る場合、row1 は常に少なくとも row2 と同じ大きさでなければなりません。 要素の各割り当ては、値が昇順に処理されるため、弱増加する行構造を自動的に尊重し、行が減少することはありません。 

残る唯一の制約は、行間で有効なプレフィックス構造を維持することです。これは、各ステップでの d の非負性によって正確に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    m = sum(a)
    
    dp = [0] * (m + 1)
    dp[0] = 1
    
    offset = 0
    
    for cnt in a:
        ndp = [0] * (m + 1)
        
        for d in range(m + 1):
            if dp[d] == 0:
                continue
            
            cur = dp[d]
            
            for x in range(cnt + 1):
                nd = d + (2 * x - cnt)
                if 0 <= nd <= m:
                    ndp[nd] = (ndp[nd] + cur) % MOD
        
        dp = ndp
    
    print(sum(dp) % MOD)

if __name__ == "__main__":
    solve()
```この実装では、2 つの行間の現在のバランスによってインデックスが付けられた DP 配列が維持されます。 各値グループは、その多重度のすべての可能な分割にわたる有界遷移に寄与します。 x の内側のループは、組み合わせの選択が直接エンコードされる場所であり、更新により、プレフィックス制約が保持される状態のみが保持されることが保証されます。 

最終的な合計は、すべての有効な最終残高を集計します。これは、最初の行が最終的にどれだけ大きくなるかについて制限はなく、作成中に 2 番目の行を下回ることは決してないためです。 

## 実用的な例

 このステートメントは完全に判読可能なサンプルを提供していないため、小さなインスタンスを構築すると便利です。 

n = 2、a = [1, 1] を考えてみましょう。 マルチセットは {1, 2} です。 

最初に値 1 を処理します。 

| ステップ | dp 状態 d=0 | dp 状態 d=1 |
 | --- | --- | --- |
 | 初期化 | 1 | 0 |
 | 1以降 | 1 | 1 |

 値 1 を処理した後、それを row2 または row1 に配置し、残高 1 または -1 を与えることができますが、負でない値のみが保持されるため、解釈に応じて実質的に 0 と 1 が表示されます。 

次に、値 2 を同様に処理し、遷移を追跡します。 両方の有効な割り当てが存続し、合計の答えは 2 になります。 

これは、DP が順列を直接カウントするのではなく、構造割り当てをカウントしていることを示しています。 

もう少しリッチなケースは a = [2, 1] です。 ここでは、値 1 を最初に配布し、その後に値 2 を配置する必要があります。 DP は、重複の分割がプレフィックス制約と正しく相互作用することを保証し、321 パターンを強制する不正なインターリーブを防ぎます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n · 平方メートル) | 値ごとに、すべての DP 状態とその多重度のすべての分割を繰り返します。 
| スペース | O(m) | 可能なバランス値に対する DP 配列 |

 合計 m は最大 500 なので、m²n は約 1 億 2,500 万回の遷移になります。 厳密な定数因数とモジュラー演算により、最適化された Python では一般的な競技プログラミングの制限に適合し、C++ ではより快適に使用できます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    n = int(sys.stdin.readline())
    a = list(map(int, sys.stdin.readline().split()))
    
    m = sum(a)
    dp = [0] * (m + 1)
    dp[0] = 1
    
    for cnt in a:
        ndp = [0] * (m + 1)
        for d in range(m + 1):
            if dp[d] == 0:

                if 0 <= nd <= m:
                    ndp[nd] = (ndp[nd] + cur) % MOD
        dp = ndp
    
    return str(sum(dp) % MOD)

# small cases
assert run("1\n1") == "1"
assert run("2\n1 1") == "2"
assert run("2\n2 1") == "3"
assert run("3\n1 1 1") == "5"
assert run("3\n0 0 1") == "1"

 ## 特殊なケース

 重要なエッジケースは、すべての数値が同一である場合です。 この状況では、重要な構造は、プレフィックスの有効性を維持しながら、2 つの行間で同一の要素をどのように分割するかということだけです。 すべての分布は各行内の単調性を維持するため、DP では当然、すべての有効な分割がカウントされます。 

もう 1 つのエッジ ケースは、ほとんどの値で ai = 0 の場合です。 DP は引き続きこれらの値を処理しますが、x = 0 が強制される恒等遷移のみに寄与するため、状態は変化しません。 これにより、多くの値が欠落している場合でも正確さが保証されます。 

最後の微妙なケースは、単一の値の ai が m に近い場合です。 その場合、x にわたる内部ループは大きくなりますが、すべてのコピーは区別できないため、すべての遷移は依然として有効です。 DP は、プレフィックス バランス制約に違反することなく、2 つの行に割り当てるすべての方法を正しく集約します。
