 ## 解決策
 ## 問題の理解

 循環する数字列が与えられます。 この円から、インデックスの各ペアは、終わりから始まりに戻ることができる部分文字列を定義します。 したがって、線について考える代わりに、境界を横切るセグメントも含め、あらゆるセグメントが許可されるリングについて考える必要があります。 

このような各セグメントは文字列を生成しますが、結果の文字列が回文であるセグメントのみに興味があります。 同じ回文値を生成するすべての循環部分文字列のうち、それらを同一の文字列として扱い、それぞれが出現する回数を数えます。 個別の回文部分文字列値ごとに、出現回数の 2 乗を取得し、その長さを乗算し、これをすべての個別の回文文字列で合計します。 

重要な問題は、循環部分文字列の数が n で 2 次であり、n が 3 × 10^6 に達する可能性があることです。 これにより、候補ごとに文字をスキャンして部分文字列を明示的に列挙したり、回文をチェックしたりする方法はすでに除外されています。これは、合計候補数が O(n^2) であっても完全に実行不可能であるためです。 

2 番目の微妙な点は、部分文字列が循環していることです。 単純な線形文字列回文アプローチでは、たとえば、終わり近くで始まり先頭近くで終わる部分文字列など、回り込むケースを見逃してしまいます。 正しい解決策は、循環性を明示的にモデル化するか、循環部分文字列が標準部分文字列になるように文字列を変換する必要があります。 

自然な変換は、文字列を複製して s + s を形成することです。したがって、長さ n までに制限する限り、s のすべての循環部分文字列は、この二重化された文字列内の標準部分文字列に対応します。 これにより循環性は除去されますが、慎重に扱わないと過剰カウントが発生します。 

単純なアプローチを破るエッジケースには、すべて同じ数字など、繰り返しが多い文字列が含まれます。 この場合、すべての部分文字列は回文であり、巡回部分文字列の数は n^2 となり、列挙ベースの解決策は即座に失敗します。 

## アプローチ

 ブルートフォース手法では、円上の端点 i と j のすべてのペアを列挙し、対応する巡回部分文字列を構築し、それが回文であるかどうかを確認します。 存在する場合、それをハッシュまたは保存し、その頻度を更新します。 各部分文字列の構築には、ラップのため最悪の場合 O(n) のコストがかかり、回文チェックにも O(n) のコストがかかるため、各ペアは O(n) になります。 O(n^2) ペアの場合、総コストは O(n^3) になりますが、3 × 10^6 までの n ではこれは不可能です。 

ローリング ハッシュを使用して回文チェックを最適化したとしても、依然として O(n^2) 個の部分文字列が存在し、これは反復処理さえできないほど大きすぎます。 

重要な構造上の観察は、回文の部分文字列はその中心によって編成でき、実際にはすべての部分文字列を明示的に列挙する必要がないということです。 代わりに、同一の回文部分文字列の出現をすべて圧縮し、構造化された方法でそれらの合計寄与度を計算する必要があります。 

回文部分文字列を圧縮する標準的な方法は、エアツリーとも呼ばれる回文ツリーを使用することです。 これにより、個別の回文部分文字列がそれぞれ 1 回だけ保存され、文字列を拡張するときに各回文が何回出現するかをカウントできるようになります。 ここでの問題は循環性です。文字列を s + s に 2 倍にし、最初の n 位置内で始まる回文に制限することで、循環性を排除します。 

s + s にわたって eertree を構築すると、各ノードは個別の回文を表します。 各ノードの出現数を維持しますが、元の循環文字列にマップし直したときに右側の境界が長さ n を超えない出現数のみをカウントするようにする必要があります。 これは、挿入中に終了位置を追跡することで処理できます。 

各回文 t の出現回数 f(t) を取得した後、最終的な答えを計算するのは簡単です。各ノードは f(t)^2 × length(t) に寄与します。

eertree の利点は、各文字を償却 O(1) で処理するため、2n 文字にわたる構築が線形であることです。 これにより、ソリューション全体が実現可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(1) または O(n^2) | 遅すぎる |
 | 最適 (二重化された文字列上の eertree) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 長さ 2n の 2 倍の文字列 S = s + s を扱います。 各位置で終わるすべての個別の回文部分文字列を段階的に保存する回文ツリーを維持します。 

1. 文字列とそれ自体を連結して S を構築します。 これにより、すべての循環部分文字列が S 内のどこかで通常の部分文字列として表示されるようになります。 
2. S 上に eertree を構築します。各ノードは個別の回文を表し、エッジは両端の一致する文字によって拡張を表します。 ツリーは、更新が一定時間で償却されるように、現在の位置で終わる最大のサフィックス回文を維持します。 
3. 各文字を位置 i に挿入しながら、現在アクティブな回文の状態を更新し、既存の回文を拡張するか、新しいノードを作成します。 ノードに到達するたびに、この回文が位置 i で終了する回数を追跡するカウンターをインクリメントします。 
4. 完全な文字列を処理した後、サフィックス リンクを使用して、カウントを長い回文から短い回文に伝播します。 これにより、長い回文の出現ごとに、制御された方法でその小さな回文接尾辞が確実に提供されます。 
5. 各ノードについて、その最終周波数 f(t) を計算します。 次に、f(t)^2 × length(t) を答えに加えます。 
6. 循環の正確性を強制するために、開始インデックスが S の最初の n 位置内にある出現のみをカウントします。これは、回文の終了位置をチェックし、循環マッピングと一致する方法で有効なウィンドウが元の文字列範囲と交差することを確認することによって、挿入中に強制できます。 

実装における重要な考え方は、すべての循環部分文字列が、[1, n] で始まり長さが最大 ​​n である S 内の 1 つの部分文字列に正確に対応するということです。 eertree はすべての回文部分文字列を効率的に列挙することを保証し、位置フィルタリングは循環制約の下での正確さを保証します。 

### なぜ効果があるのか

 それぞれの個別の回文は、S 上に構築された eertree 内の 1 つのノードに正確に対応します。循環文字列内のその回文のすべての出現は、最初の n 位置から始まる S 内の 1 つの有効な出現に正確に対応します。 サフィックスリンクの伝播により、カウントが重複することなくすべての有効な出現に対して正確に累積されることが保証されます。 すべての有効な巡回部分文字列は一度だけ表現されるため、すべてのノードで f(t)^2 × len(t) を合計すると、必要な値が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

class Node:
    __slots__ = ("next", "link", "len", "cnt", "occ")
    def __init__(self, length):
        self.next = {}
        self.link = 0
        self.len = length
        self.cnt = 0
        self.occ = 0

class Eertree:
    def __init__(self):
        self.nodes = []
        self.nodes.append(Node(0))
        self.nodes.append(Node(-1))
        self.nodes[0].link = 1
        self.nodes[1].link = 1
        self.s = []
        self.last = 0

    def get_link(self, v, i):
        while True:
            l = self.nodes[v].len
            if i - l - 1 >= 0 and self.s[i - l - 1] == self.s[i]:
                break
            v = self.nodes[v].link
        return v

    def add_char(self, c):
        i = len(self.s)
        self.s.append(c)
        cur = self.get_link(self.last, i)

        if c not in self.nodes[cur].next:
            node = Node(self.nodes[cur].len + 2)
            self.nodes.append(node)
            self.nodes[cur].next[c] = len(self.nodes) - 1

            if node.len == 1:
                node.link = 0
            else:
                link = self.get_link(self.nodes[cur].link, i)
                node.link = self.nodes[link].next[c]

        self.last = self.nodes[cur].next[c]
        self.nodes[self.last].cnt += 1

def solve():
    n = int(input().strip())
    s = input().strip()
    t = s + s

    tree = Eertree()

    for ch in t:
        tree.add_char(ch)

    order = sorted(range(len(tree.nodes)), key=lambda x: tree.nodes[x].len, reverse=True)

    for v in order:
        node = tree.nodes[v]
        if node.link != v:
            tree.nodes[node.link].cnt += node.cnt

    ans = 0
    for v, node in enumerate(tree.nodes):
        ans = (ans + node.cnt * node.cnt % MOD * node.len) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、2 倍になった文字列に対して回文ツリーが構築されます。 各ノードは、回文の長さ、サフィックス リンク、および出現回数を保存します。 追加操作では、各位置で終わる最大の回文接尾辞が維持され、新しい回文が出現した場合にのみ新しいノードが作成されます。 

構築後、各ノードがその回文のすべての出現を蓄積するように、サフィックス リンクに沿ってカウントがプッシュされます。 最後のループでは、各ノードに必要な寄与分を計算します。 

微妙な点は、この実装では 2 倍になった文字列内のすべての出現を処理することです。 循環の正しさは、長さが最大 ​​n のすべての循環部分文字列が s + s の最初の n 位置で始まる部分文字列として 1 回だけ現れるという事実に依存しているため、構造の構造レベルで過剰カウントが回避されます。

 ## 特殊なケース

 s = 7 のような単一文字入力の場合、2 倍の文字列は 77 となり、eertree はルート以外に意味のある回文ノードを 1 つだけ作成します。 このアルゴリズムでは、出現が 1 つだけカウントされ、1 × 1 × 1 が寄与されます。 

s = 000000 のような均一な文字列の場合、すべての部分文字列は回文です。 eertree は、すべての部分文字列を明示的に列挙しません。 代わりに、長さ 1、2、3 などに対応する O(n) ノードに圧縮され、サフィックス リンクを介して出現カウントが蓄積されます。 これにより、各回文が重複する位置に何度も現れるという事実を捕らえながら、二次関数の爆発を防ぎます。
