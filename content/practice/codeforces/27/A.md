 ## 解決策
 ## 問題の理解

 システムにすでに存在するテストのインデックスが与えられます。 すべてのインデックスは正の整数であり、すべてのインデックスは個別です。 ここでのタスクは、リストにない最小の正の整数を見つけることです。 

これは古典的な「最小欠損正」のアイデアですが、制約が十分に小さいため、高度なデータ構造は必要ありません。 既存のテストの数は最大 3000 であり、すべてのインデックスも最大 3000 です。$O(n^2)$このソリューションは最悪の場合でも約 900 万回の操作を実行しますが、これは Python の 2 秒の制限内に簡単に収まります。 

主な問題はパフォーマンスではなく、検索を正しく処理することです。 すべての小さな正の整数がすでに存在しない限り、答えは最大値に 1 を加えたものではありません。 

次の入力を考えてみましょう。```
3
1 7 2
```正しい答えは、`3`、 ない`8`。 次のインデックスは、未使用の最小の正の数である必要があります。 

もう 1 つの簡単な間違いは、次から検索を開始することです。`0`。 テストインデックスは正の整数のみです。 

例：```
4
2 3 4 5
```正しい答えは、`1`最小の正の整数がすぐに欠落するためです。 

3 番目のエッジ ケースは、次のすべての値が発生した場合に発生します。`1`に`n`が存在します。 

例：```
5
1 2 3 4 5
```答えは次のようになります`6`。 配列内にすでに存在する数値のみをチェックする不注意な実装では、何も出力されない可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 から開始`1`そして、現在の番号が配列内に存在するかどうかを繰り返し確認します。 最初に見つからなかった数字が答えです。 

値が存在するかどうかをテストするには、配列全体を線形にスキャンします。 候補値は最大 3000 個あり、各検索では 3000 個の要素すべてが検査される可能性があるため、最悪の場合の複雑さは次のようになります。$O(n^2)$。 

この問題に関しては、これでも十分高速です。 Python では約 900 万件の比較が許容されます。 

それでも、問題の構造により、より明確な解決策が得られます。 数値がどこに表示されるかではなく、数値が存在するかどうかのみを考慮します。 つまり、メンバーシップのクエリが中心的な操作になります。 セットは平均してメンバーシップ チェックをサポートします$O(1)$時間。 

観察は簡単です。値がセットに格納されたら、数値をテストできます。`1, 2, 3, ...`最初の欠損値が見つかるまで、1 つずつ実行します。 

答えは最大でも次のとおりであることが保証されています`n + 1`。 あれば`n`異なる正の整数とすべての数値`1`を通して`n`存在するなら`n + 1`が欠けています。 これにより、せいぜいチェック後に停止できます`n + 1`候補者たち。

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`および既存のテストインデックスのリスト。 
2. すべてのインデックスをセット内に格納します。 

セットを使用すると、迅速なメンバーシップ チェックが可能になります。これはまさに、「この番号はすでに存在しますか?」を尋ねるときに必要なものです。 
3. 以下の整数を反復処理します。`1`に`n + 1`。 

答えは超えることはできません`n + 1`。 すべての値が`1`を通して`n`が存在する場合、欠落している最小の陽性値は次のとおりである必要があります。`n + 1`。 
4. 各整数について`x`、セット内に存在するかどうかを確認します。 

もし`x`がありません、印刷します`x`すぐに止めてください。 
5. スキャン中に検出された最初の欠落番号が、必要な次のテスト インデックスになります。 

### なぜ効果があるのか

 このアルゴリズムは、正の整数を昇順にチェックします。 ある値に達する前に`x`、すべての小さな正の整数は、セット内に存在することがすでに検証されています。 いつ`x`見つからない最初の値は、まさに配列に欠落している最小の正の整数です。 

スキャンは順番に進行し、最初のギャップで停止するため、アルゴリズムはより小さい有効な回答をスキップできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

# solution

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    used = set(arr)

    for x in range(1, n + 2):
        if x not in used:
            print(x)
            return

solve()
```最初のステップでは、入力配列を読み取り、それを次の名前のセットに変換します。`used`。 メンバーシップのチェックは平均して一定時間になるため、この変換が最適化の鍵となります。 

ループはから実行されます`1`を通して`n + 1`包括的な。 上限は重要です。 すべての数字が`1`に`n`が存在する場合、答えは次のようになります。`n + 1`。 使用する`range(1, n + 1)`そのケースを見逃すでしょう。 

欠損値が見つかると、関数はそれを出力し、すぐに戻ります。 数値は昇順に処理されるため、スキャンを続ける必要はありません。 

すべての値が非常に小さいため、ここでは整数オーバーフローの問題は発生しません。 実装では主に、慎重な境界と正しい停止条件が重要です。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = int(input())
    arr = list(map(int, input().split()))

    used = set(arr)

    for x in range(1, n + 2):
        if x not in used:
            print(x)
            return

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup_stdout
    return out.getvalue().strip()

# provided sample
assert run("3\n1 7 2\n") == "3", "sample 1"

# minimum size input
assert run("1\n1\n") == "2", "single existing value"

# missing 1
assert run("4\n2 3 4 5\n") == "1", "smallest positive missing immediately"

# consecutive sequence
assert run("5\n1 2 3 4 5\n") == "6", "answer is n + 1"

# unordered values
assert run("6\n4 2 1 6 3 7\n") == "5", "handles unsorted input"

# maximum-style boundary pattern
assert run("3\n3000 2999 1\n") == "2", "large values do not matter"

## 特殊なケース

 次の場合を考えてみましょう`1`すぐになくなってしまいます。 

入力：```
4
2 3 4 5
```セットはこうなります`{2, 3, 4, 5}`。 アルゴリズムは次からチェックを開始します`1`。 以来`1`存在しないため、印刷されます`1`すぐに。 これにより、可能な限り最小の答えが正しく処理されます。 

ここで、からのすべての値が`1`を通して`n`存在する。 

入力：```
5
1 2 3 4 5
```アルゴリズムチェック`1`、`2`、`3`、`4`、 そして`5`、それらはすべてセット内に存在します。 次にチェックします`6`が欠落しているため、印刷されます`6`。 このため、ループは次の時点まで実行する必要があります。`n + 1`。 

最後に、ギャップのある順序付けされていない入力について考えます。 

入力：```
6
7 3 1 2 6 4
```セットはこうなります`{1, 2, 3, 4, 6, 7}`。 チェックは次のように行われます。 

-`1`存在します
 -`2`存在します
 -`3`存在します
 -`4`存在します
 -`5`存在しません

 アルゴリズムは出力します`5`。 セットにはメンバーシップ情報のみが保存されるため、元の順序は重要ではありません。
