 ## 解決策
 ## 問題の理解

 私たちには次のようなサイクルがあります`n`環状に配置された都市。 連続する各都市はすでに外環状道路で結ばれており、`n`街にもつながっています`1`。 

追加で与えられます`m`新しい道路。 新しい道路はそれぞれ、カーブで 2 つの都市を接続しており、その道路全体がリングの内側か外側にある必要があります。 2 つの新しい道路は、共有端点でのみ接触できます。 それ以外の交差点は通行禁止です。 

タスクは、新しい道路ごとに、道路が交差しないように内側に行くべきか外側に行くべきかを決定することです。 そのような代入が存在する場合は、次の長さの文字列を出力します。`m`それぞれのキャラクターがどこにいるのか`i`または`o`。 それ以外の場合は印刷します`Impossible`。 

リングが都市の循環順序を固定していることに気づくと、幾何学構造ははるかに単純になります。 道路は単に円の弦です。 2 つのコードは、その端点がサイクル内で交互に配置されるときに、円内で正確に交差します。 

制限は十分に小さいため、道路のすべてのペアを明示的に比較できます。 以来`m ≤ 100`、せいぜいあります`4950`ペア。 それはすぐに次のことを示唆します`O(m²)`グラフの構築は安全です。 より洗練された幾何学的データ構造は不要です。 

危険な部分はパフォーマンスではなく、交差条件を正しくモデル化していることです。 不注意な実装では、特にエンドポイントが番号付けの終わりに回り込む場合に、巡回順序が間違ってしまうことがよくあります。 

微妙なケースの 1 つは、2 つの道路が終点を共有する場合です。 このような道路は禁止された交差点を作ることはありません。 

例：```
5 2
1 3
1 4
```これらの道路は市内でのみ接しています`1`, したがって、両方とも内側に描画される可能性があります。 共有頂点を無視する単純な交互エンドポイント チェックでは、頂点が交差していると誤ってマークされる可能性があります。 

もう 1 つの簡単な間違いは、エンドポイントが正規化されていない場合に発生します。 

例：```
6 2
5 2
1 4
```最初の道をそのままにしておくと、`(5,2)`に変換する代わりに`(2,5)`、間隔チェックが不安定になり、交差点を見逃す可能性があります。 

より微妙な幾何学的問題は、円形構造に起因します。 

例：```
6 2
1 4
2 5
```円の周りを歩くと命令が出されます`1 2 4 5`。 エンドポイントは交互になるため、同じ側に配置するとコードが交差します。 正しい解決策では、一方の道路を内側に、もう一方の道路を外側に強制する必要があります。 

最後に、制約が互いに矛盾する構成があります。 

例：```
6 3
1 4
2 5
3 6
```すべてのペアは交差するため、すべてのペアは反対側になければなりません。 これにより、制約の奇妙なサイクルが形成されますが、これは 2 つの側面だけでは不可能です。 正しい出力は次のとおりです`Impossible`。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべての道は独立して内側か外側を選択します。`2^m`可能な割り当て。 割り当てごとに、道路のすべてのペアをチェックし、交差するペアが反対側に配置されていることを確認できます。 

これは、条件が純粋にペアごとであるため機能します。 2 本の道路が幾何学的に交差する場合にのみ重要です。 残念ながら、さえ`m = 100`作る`2^100`天文学的に大きい。 最悪の場合、このアプローチを保存できる枝刈り戦略はありません。 

重要な観察は、すべての交差ペアが二項制約を課すことです。 

2 つの道路が交差する場合は、そのうちの 1 つが内側になければなりません。 

典型的な2色塗りの状態です。 各道路はブール変数として考えることができます。`True`内部を意味します、`False`外という意味です。 

2 つの道路が交差するときは常に、それらの値は異なる必要があります。 これにより、問題はグラフが 2 部構成であるかどうかを確認することに変換されます。 それぞれの道が頂点になります。 対応する道路が交差する場合、2 つの頂点を接続します。 次に:

 グラフが 2 部構成の場合、一方のパーティションを内側に、もう一方を外側に置くことができます。 

グラフが 2 部構成でない場合、奇妙なサイクルによって矛盾した要件が強制されます。 

この問題は、各交差ペアによって以下が生成されるため、一般に 2-SAT インスタンスとも呼ばれます。`(A or B) and (!A or !B)`強制するもの`A != B`。 

この特定の問題については、2 部構成のチェックがより簡単で完全に十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m · m²) | O(m) | 遅すぎる |
 | 最適 | O(㎡) | O(㎡) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての道路を読み取り、それぞれを正規化します。`a < b`。 

これにより、すべての道路を循環順序上の標準間隔として扱うことができます。 
2. 道路のペアごとに、それらが交差するかどうかを判断します。 

二つの道`(a,b)`そして`(c,d)`端点が交互になる場合は交差します。`a < c < b < d`または`c < a < d < b`エンドポイントでのタッチは許可されているため、共有エンドポイントは無視されます。 
3. 各道路を頂点とするグラフを作成します。 

2 つの道路が交差する場合は、それらの頂点の間に無向エッジを追加します。 
4. DFS または BFS を使用してグラフを 2 色にしてみます。 

色の割り当て`0`片側と色`1`もう一方へ。 
5. エッジをトラバースするたびに、隣接する頂点が反対の色を受け取るように強制します。 

これは、交差する道路がリングの反対側になければならないという要件と一致します。 
6. 端点がすでに同じ色を持つエッジに遭遇した場合、グラフは 2 部ではありません。 

その場合は印刷してください`Impossible`。 
7. それ以外の場合は、色を文字に変換します。 

例えば：`0 -> i`

`1 -> o`結果の文字列を出力します。 

### なぜ効果があるのか

 グラフは、禁じられた状況を正確に捉えています。 すべてのエッジは、幾何学的に交差するため同じ側に描画できない 2 つの道路を表します。 

有効な図面は、隣接する頂点が異なる割り当てを受けるように、すべての道路に 2 つの側面の 1 つを割り当てることと同じです。 これはまさに 2 部グラフのカラーリングの定義です。 

グラフが 2 部構成の場合、色付けにより有効な構成が直接わかります。 2 部構成でない場合、奇妙なサイクルではサイクル全体で色を交互に配置する必要があり、最終的には矛盾が生じます。 その場合、有効な配置は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def intersect(a, b, c, d):
    if len({a, b, c, d}) < 4:
        return False

    return (a < c < b < d) or (c < a < d < b)

def solve():
    n, m = map(int, input().split())

    roads = []

    for _ in range(m):
        a, b = map(int, input().split())

        if a > b:
            a, b = b, a

        roads.append((a, b))

    graph = [[] for _ in range(m)]

    for i in range(m):
        a, b = roads[i]

        for j in range(i + 1, m):
            c, d = roads[j]

            if intersect(a, b, c, d):
                graph[i].append(j)
                graph[j].append(i)

    color = [-1] * m

    def dfs(v, c):
        color[v] = c

        for to in graph[v]:
            if color[to] == -1:
                if not dfs(to, c ^ 1):
                    return False
            elif color[to] == c:
                return False

        return True

    for i in range(m):
        if color[i] == -1:
            if not dfs(i, 0):
                print("Impossible")
                return

    ans = ''.join('i' if c == 0 else 'o' for c in color)
    print(ans)

solve()
```最初の重要な詳細は、エンドポイントの正規化です。 すべての道路は次のように保存されます`a < b`。 この手順を行わないと、代替エンドポイント テストの一貫性が失われます。 

の`intersect`関数は幾何学的条件を直接実装します。 2 つのコードは、2 番目のコードの一方の端点が厳密に最初のコードの間隔の内側にあり、もう一方の端点が外側にある場合に交差します。 共有エンドポイントは合法的な交差点であるため、チェックの前に除外されます。 

グラフの構築では、道路のすべてのペアを 1 回比較します。 以来`m ≤ 100`、これには最大で約5,000小切手の費用がかかります。 

DFS は通常の 2 部構成のカラーリングを実行します。 表現`c ^ 1`間を反転します`0`そして`1`。 隣接する頂点と同じ色の頂点を再度訪問すると、奇妙なサイクルが見つかり、すぐに終了します。 

最後に、色は次のように変換されます。`i`そして`o`。 一貫したマッピングは機能します。

import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def intersect(a, b, c, d):
        if len({a, b, c, d}) < 4:
            return False

        return (a < c < b < d) or (c < a < d < b)

    n, m = map(int, input().split())

    roads = []

    for _ in range(m):
        a, b = map(int, input().split())

        if a > b:
            a, b = b, a

        roads.append((a, b))

    graph = [[] for _ in range(m)]

    for i in range(m):
        a, b = roads[i]

        for j in range(i + 1, m):
            c, d = roads[j]

            if intersect(a, b, c, d):
                graph[i].append(j)
                graph[j].append(i)

    color = [-1] * m

    def dfs(v, c):
        color[v] = c

        for to in graph[v]:
            if color[to] == -1:
                if not dfs(to, c ^ 1):
                    return False
            elif color[to] == c:
                return False

        return True

    ok = True

    for i in range(m):
        if color[i] == -1:
            if not dfs(i, 0):
                ok = False
                break

    if not ok:
        return "Impossible"

    return ''.join('i' if c == 0 else 'o' for c in color)

## 特殊なケース

 道路が終点を共有していることを考えてみましょう。```
5 2
1 3
1 4
```正規化後は、`(1,3)`そして`(1,4)`。 交差チェックでは、最初に 4 つの端点が区別されていないことが認識されるため、すぐに戻り値が返されます。`False`。 グラフにエッジは追加されません。 両方の道路が同じ色を受け取る場合があります。`ii`。 

ここで、逆のエンドポイントを考えてみましょう。```
6 2
5 2
1 4
```正規化変換`(5,2)`の中へ`(2,5)`。 円周の順序は次のようになります。`1 2 4 5`が交互に続くので、道路は交差します。 エッジが追加され、グラフでは反対の色が強制されます。 正規化がなければ、間隔ロジックは失敗します。 

最後に、不可能な三角形について考えてみましょう。```
6 3
1 4
2 5
3 6
```各ペアが交互に表示されるため、グラフは 3 サイクルになります。 DFS は色を割り当てます。```
0 -> 0
1 -> 1
2 -> 0
```しかし頂点`0`そして`2`隣接しているため、競合が発生します。 アルゴリズムは正しく印刷します`Impossible`。
