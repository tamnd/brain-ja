 ## 解決策
 ## 問題の理解

 総当りトーナメントの欠落した結果を再構築するように求められます。 _n_ 人の参加者がいて、各参加者は他のすべての参加者と 1 回だけ対戦します。 各試合には明確な勝者と敗者があり、同じ固有の能力を持った参加者は 2 人としていません。「スリープ スピード」が低いほど、より高いスピードを持つ相手に対する勝利が保証されます。 入力は 1 つを除くすべての一致結果で構成されており、私たちのタスクは欠落している一致を見つけることです。 

入力は有向グラフとして考えることができます。各参加者はノードであり、参加者 _x_ から _y_ までのエッジは _x_ が _y_ に勝ったことを示します。 すべての速度が異なるため、このグラフは参加者の厳密なランキングを形成します。 片方のエッジ（欠けているゲーム）だけがありません。 どの 2 つのノード間にエッジがないのかを特定し、暗黙のランキングに従って勝者を決定する必要があります。 

_n_ ≤ 50 の制約を考慮すると、一致の合計数は最大 50 · 49/2 = 1225 です。すべてのゲームを線形に処理することは可能であり、パフォーマンスの問題なく _n_ で二次演算を使用することもできます。 

主な微妙な点は、互いにプレイしなかった 2 人の参加者を正確に識別することから生じます。 「一致しない人」を単純に検索すると、数え間違えたり、順序を誤解したりする可能性があります。 たとえば、n=3 のトーナメントの結果は次のようになります。```
1 2
2 3
```参加者 1 はまだ 3 をプレイしていません。1 が 2 に勝ち、2 が 3 に負けているため、勝者は 1 でなければなりません。不用意にアプローチすると、誤って 3 1 または 2 1 が出力される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、結果からすべての参加者の速度を再構築しようとします。 参加者ランキングのすべての順列を試し、すべての既知の一致をシミュレートし、どの順列が一貫しているかを確認できます。 その後、失われた一致が再構築されたランキングから追跡されます。 これは正しいですが、やりすぎです。順列の数は n! であり、n = 50 はおろか、n = 10 であっても不合理です。 

重要な洞察は、各参加者が正確に n−1 ゲームをプレイするということです。 したがって、欠落したゲームに関与した 2 人を除くすべての参加者は、n-1 試合をプレイしたことになります。 参加者ごとのゲーム数を数えると、ゲームに参加できなかった 2 人の参加者をすぐに特定できます。 ペアがわかると、2 つの相対的な順序はトーナメントの推移的特性に従います。つまり、より多くの勝利を収めた参加者はスリープ速度が低くなければならないため、欠落している試合に勝つことになります。 これにより、問題は度数を数えて 1 回の比較を行うだけになり、参加者の数が線形になります。 

ストーリーは次のとおりです。すべての結果が一意のランキングを決定するため、総当たり攻撃は原理的に機能します。 しかし、すべての順列を試すのは不可能です。 正確に 2 人の参加者がゲームに参加していないことが観察されると、候補セットはすぐに 1 つのペアに減り、勝ちの推移的な特性によって方向が決定されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (順列シミュレーション) | お(ん!) | O(n) | 遅すぎる |
 | 度数のカウント + 推移比較 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`games_played`サイズ n、すべてゼロ。 この配列は、各参加者がこれまでにプレイしたゲームの数を追跡します。 また、参加者ごとの勝利のリストを初期化します。`wins`、すべてゼロ。 
2. 提供されたすべての一致結果を繰り返し処理します。 参加者 x が y を破った試合ごとに、増分します。`games_played[x-1]`そして`games_played[y-1]`1つずつ。 インクリメント`wins[x-1]`1つずつ。 これにより、参加者ごとの試合数と勝利数の両方を追跡できるようになります。 
3. すべての一致を処理した後、スキャンします。`games_played`n−1 未満のゲームをプレイした 2 人の参加者を見つけます。 これらは、行方不明の試合に関与した 2 人の参加者です。 
4. 2 人の参加者の勝利数を比較します。 異なる速度を持つトーナメントでは勝利が推移的に蓄積されるため、より多くの勝利を収めたチームのスリープ速度は低くなければなりません。 最初に勝者を出力し、次に敗者を出力します。 

これが機能する理由: 試合に参加できなかった 2 人を除くすべての参加者は、正確に n−1 試合を行うことになります。 トーナメントのランキングは厳格であるため、より多くの勝利を収めた参加者が常により少ない勝利を収めた参加者に勝ちます。 これにより、欠落している一致を明確に決定できることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
games_played = [0] * n
wins = [0] * n
total_games = n * (n - 1) // 2 - 1

for _ in range(total_games):
    x, y = map(int, input().split())
    games_played[x - 1] += 1
    games_played[y - 1] += 1
    wins[x - 1] += 1

# find two participants with fewer than n-1 games
missing = [i for i in range(n) if games_played[i] < n - 1]
a, b = missing

# winner is participant with more wins
if wins[a] > wins[b]:
    print(a + 1, b + 1)
else:
    print(b + 1, a + 1)
```最初のセクションではカウンターを初期化します。 勝利数と合計ゲーム数をカウントすることで、行方不明の 2 人の参加者を検出できます。 ゼロベースのインデックスを使用すると、off-by-1 エラーが防止され、出力に 1 を追加すると、参加者の数が入力と確実に一致します。 このソリューションは、トーナメントのシミュレーションを完全に回避し、不変のプロパティ (プレイされたゲームと勝利数) のみに依存します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    n = int(input())
    games_played = [0] * n
    wins = [0] * n
    total_games = n * (n - 1) // 2 - 1
    for _ in range(total_games):
        x, y = map(int, input().split())
        games_played[x - 1] += 1
        games_played[y - 1] += 1
        wins[x - 1] += 1
    missing = [i for i in range(n) if games_played[i] < n - 1]
    a, b = missing
    if wins[a] > wins[b]:
        print(a + 1, b + 1)
    else:
        print(b + 1, a + 1)
    return output.getvalue().strip()

# provided sample
assert run("4\n4 2\n4 1\n2 3\n2 1\n3 1\n") == "4 3", "sample 1"

# minimum size
assert run("3\n1 2\n2 3\n") == "1 3", "minimum 3 participants"

# 4 participants missing last match
assert run("4\n1 2\n1 3\n2 3\n4 1\n4 2\n") == "4 3", "4 missing match vs 3"

# 5 participants, last match between strongest and weakest
