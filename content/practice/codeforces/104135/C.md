 ## 解決策
 ## 問題の理解

 要素の行を表す一連の数値が与えられます。各要素には、値と除去コストという 2 つの属性があります。 このゲームでは、隣接する 2 つの要素を繰り返し選択し、値の小さい方を削除し、関連する削除コストを支払うことができます。 要素が閉じられるため、削除のたびに配列の構造が変化し、隣接関係は常に動的になります。 

このプロセスは何度でも続行されますが、常に配列内に少なくとも 1 つの要素を残す必要があります。 また、固定予算があり、削除するたびにその予算の一部が消費されます。 目標は、予算制約の下で一連の削除を実行した後、配列に残る最小値を最大化することです。 

制約の観点から見ると、配列サイズは最大 100000 に達する可能性があり、バジェットは 10^18 に達する可能性があります。 これにより、操作を段階的にシミュレートしたり、一連の削除を列挙しようとしたりするソリューションは即座に除外されます。 n で 2 次的なアプローチ、または重い定数を使用する n log n のアプローチも潜在的には許容されますが、O(n log n) よりも悪いものは遅すぎます。 

主な問題点は、削除が恣意的ではないことです。削除は隣接性に依存し、各操作では選択された隣接ペアの小さい方が削除されます。 これは、特定の要素の削除が他の要素から独立していないことを意味します。 代わりに、実現可能性は、その要素を隣接するペアの小さい方として繰り返し「公開」できるかどうかに依存します。 

いくつかの微妙な特殊なケースについては、覚えておく価値があります。 すべての要素がすでに大きくてもコストがゼロの場合は、積極的に削除して非常に高い最小値を残すことができます。 コストが非常に大きい場合は、何も削除できない可能性があるため、答えは単純に配列の最小要素になります。 もう 1 つの特殊なケースは、最適な戦略が 1 つの要素だけを残す場合です。 この問題では少なくとも 1 つの要素が残る必要があるため、すべてを削除しないようにする必要があります。 

誤解を招きやすい単純な例は、世界的に安価な要素が中央にあるものの、高価な要素に囲まれている場合です。 たとえ局所的に削除するのが安価であっても、最初に隣接するものを削除しない限り、有効な隣接ペアの中で小さい方になることはできないため、構造によってその削除がブロックされる可能性があります。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての削除シーケンスをシミュレートしようとします。 各ステップで、隣接するペアを選択し、小さい方を削除し、そのコストを予算から差し引きます。 演算のたびに配列の形状が変化し、可能なシーケンスの数が n とともに指数関数的に増加するため、これにより巨大な状態空間が形成されます。 n = 40 の場合でも、これは実行不可能になります。 

重要な観察は、実際にプロセスをシミュレートするように求められているのではなく、特定の最小値が確実に残るように十分な要素を削除できるかどうかを判断するだけであるということです。 これは、視点を逆転することを示唆しています。つまり、削除をシミュレートする代わりに、候補の答え x が達成可能かどうかをテストします。 

値xを固定します。 最大でも s を費やしながら、x 未満の値を持つすべての要素を削除できるかどうかを知りたいと考えています。 これができれば、残りのすべての要素の値が少なくとも x になるため、最小値は少なくとも x になります。 これにより、問題は x ごとに独立して解決できる決定問題になり、当然のことながら答えの二分探索が行われます。 

自明ではない部分は、固定 x の実現可能性を判断することです。 少なくとも x の値を持つ要素は、削除しないことを選択した場合は決して削除できないため、それらを「保護された」ものとして扱います。 x より小さい値を持つ要素は削除する必要があります。 このような要素にはそれぞれコストがかかりますが、実際に削除できるかどうかは、プロセス中に隣接する要素とペアにできるかどうかによって決まります。

重要な構造の単純化は、生き残った要素によってブロックされる前に、有効な隣接ペアに参加していることを常に確認する限り、削除可能な要素は最終的に削除できることです。 これにより、削除時に少なくとも 1 つの隣接要素が存在していれば、互いの正確な位置に関係なく削除できる順序で削除をいつでも整理できるため、問題は x より小さい値を持つすべての要素にわたるコストの累積に帰着します。 

したがって、固定 x の場合、実現可能性は x 未満の値を持つすべての要素のコストを合計し、この合計がバジェット s 内にあるかどうかをチェックすると同時に、すべての要素が削除されるわけではないことも保証します (値 ≥ x を持つ要素が少なくとも 1 つ存在する必要があります)。 

これにより問題が x に関する単調述語に変換され、二分探索が可能になります。

 ## アルゴリズムのチュートリアル

 1. 答えは既存の要素の値と等しくなければならないため、値を最終的な最小の答えの候補として並べ替えるか、概念的に扱います。 これにより、検索空間が最大 n 個の可能性に縮小されます。 
2. 最終的な配列の最小許容値を表す候補しきい値 x に対する二分探索。 
3. 固定 x の場合、配列を反復処理し、値が x より厳密に小さい要素をすべて識別します。これらの要素は削除する必要があるためです。 
4. これらの要素を除去するための総コストを累積します。 これは、しきい値に違反するすべての要素を排除するために必要な最小限の支出を表します。 
5. この合計コストが予算内であるかどうかを確認します。 s を超える場合、問題となる要素をすべて除去することはできないため、x は実行できません。 
6. 値 ≥ x を持つ要素が少なくとも 1 つ存在することを確認します。 存在しない場合は、十分な予算があっても、しきい値を満たす有効な最終要素を残すことはできません。 
7. 両方の条件が満たされる場合、x を実行可能としてマークし、値を増やしてみます。 それ以外の場合は減らしてください。 
8. 二分探索が完了したら、実現可能な最大の x を出力します。 

### なぜ効果があるのか

 重要な不変条件は、実現可能性は予算を超えずにしきい値を下回るすべての要素を削除できるかどうかのみに依存し、削除の正確な順序には依存しないということです。 特定の要素を削除する有効な削除シーケンスでは、常にそのコストが 1 回だけ支払われます。また、隣接制約によって必要なコストの合計が増加することはなく、順序が制限されるだけです。 削除は常にスケジュールを設定して、各取り外し可能な要素が最終的にペアになり、上位の生き残った要素によってブロックされる前に削除されるため、総コストはしきい値を下回るすべての要素のコストの合計となります。 したがって、決定問題は x において単調であり、二分探索の正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def feasible(a, c, s, x):
    total = 0
    has_good = False
    n = len(a)

    for i in range(n):
        if a[i] >= x:
            has_good = True
        else:
            total += c[i]

    return has_good and total <= s

def solve():
    n, s = map(int, input().split())
    a = list(map(int, input().split()))
    c = list(map(int, input().split()))

    vals = sorted(set(a))
    
    lo, hi = 0, len(vals) - 1
    ans = vals[0]

    while lo <= hi:
        mid = (lo + hi) // 2
        x = vals[mid]

        if feasible(a, c, s, x):
            ans = x
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、まず配列とコスト構造を読み取り、次に候補となる回答を配列の個別の値のみに圧縮します。 実現可能性関数は、しきい値を下回るすべての要素を削除するコストを計算し、少なくとも 1 つの有効な生存者が存在するかどうかを確認します。 

二分探索では、すべての値が次の値に達するという不変条件が維持されます。`ans`は実現可能であり、現在の中間点が有効な場合は常に上方向に拡張されます。 

実装の微妙な点は、隣接関係の操作を明示的にシミュレートしないことです。 元の問題が動的に表現されているにもかかわらず、最適なスケジューリングでは総コストが削除順序に依存しないため、これは意図的なものです。 

## 実用的な例

 | --- | --- | --- | --- | --- |

 総コストは 10 で予算内です。要素はまだ 4 つ以上あるので、4 は実現可能です。 これは、すべての小さな要素を削除できることをメカニズムが正しく識別していることを示しています。 

ここで、x = 5 について考えてみましょう。 

| 私 | a[i] | c[i] | a[i] < 5? | 総費用 |

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, s = map(int, input().split())
    a = list(map(int, input().split()))
    c = list(map(int, input().split()))

    def feasible(a, c, s, x):
        total = 0
        has_good = False
        for i in range(len(a)):
            if a[i] >= x:
                has_good = True
            else:
                total += c[i]
        return has_good and total <= s

    vals = sorted(set(a))
    lo, hi = 0, len(vals) - 1
    ans = vals[0]

    while lo <= hi:
        mid = (lo + hi) // 2
        x = vals[mid]
        if feasible(a, c, s, x):
            ans = x
            lo = mid + 1
        else:
            hi = mid - 1

    return str(ans)

 ## 特殊なケース

 すべての要素が候補しきい値を下回る場合、最終的な最小値を固定する生き残った要素がないため、実行可能性チェックは直ちに失敗します。 アルゴリズムはそのようなしきい値を正しく拒否します。`has_good`false のままとなり、無効な回答を防ぐことができます。 

予算がゼロの場合、価値の低い要素を削除しようとするとプラスのコストが発生するため、実行可能な唯一の答えは最小要素になります。 チェックでは当然これが強制されます。`total`削除が必要な場合は常にプラスになります。 

すべてのコストがゼロの場合、しきい値を下回るすべての要素は自由に削除できるため、答えは可能な最大要素値になります。 アルゴリズムはこれを捕捉します。`total`決して超えない`s`、そして実現可能性は生き残った要素の存在にのみ依存します。 

値が厳密に増加または減少している場合でも、実現可能性は構造や隣接性ではなく、しきい値による分割のみに依存し、順序はコスト計算とは無関係になるため、二分探索は引き続き機能します。
