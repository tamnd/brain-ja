 ## 解決策
 ## 問題の理解

 同じ長さの数値のリストが 2 つ与えられ、順序を変更できるのは 2 番目のリストのみです。 並べ替えた後、インデックスによって要素をペアにし、すべてのペアの合計が固定の上限内に収まるかどうかを確認します。 

これについて考えると便利な方法は、最初の配列の各値が「すでにコミットされたコスト」を表し、2 番目の配列の各値がそれらのコストに自由に割り当てられる「補完予算」を表すということです。 目標は、ポジションが制限を超えないようにこれらの予算を割り当てることです。 

制約は小さく、各テスト ケースには最大 50 個の要素があり、最大 100 個のテスト ケースがあります。 これは、テスト ケースごとに 2 次のアルゴリズムであっても、十分に高速であることを意味します。 3 次または指数関数は理論的には許容されますが、不要です。 

ここでよく見られる単純な間違いは、両方の配列をソートせずに要素を恣意的または貪欲に一致させようとすることです。 たとえば、最初の配列の最大の要素と 2 番目の配列のランダムな要素のペアは、有効な配置が存在する場合でも失敗する可能性があります。 考慮する`a = [1, 4]`、`b = [2, 5]`、`x = 6`。 貪欲にペアリングすると`(4, 5)`まず、並べ替えてもすぐに制約を解除します。`b`として`[5, 2]`両方のペアが有効になります。 

もう 1 つの微妙な失敗は、次のような仮定から生じます。`a`のいくつかの要素と組み合わせることができます`b`, その後、残りは自動的に機能します。 それは小さなものを使用することを無視します`b`早すぎると、後で実現可能性が妨げられる可能性があります。 

## アプローチ

 強引なアイデアは、次のすべての順列を試してみることです。`b`ペアリングが機能するかどうかを確認します。 これは、考えられるすべての割り当てを検討するため正しいですが、次のように増加します。`n!`。 たとえ`n = 50`、順列の数が天文学的に大きいため、これは完全に実行不可能です。 

重要な洞察は、単調制約、つまりより小さい値を使用して代入問題を解いているということです。`a`を満たすのが簡単であるため、より大きな柔軟性と組み合わせる必要があります。`b`、およびより大きな値`a`～より小さい値のペアが必要です`b`。 

これは、すべての順列を試すのではなく、両方の配列をソートし、構造化された方法でペアにすることを示唆しています。 正しい戦略は、最小の要素をペアにすることであることが判明しました。`a`可能な最大の有効な要素を含む`b`または同様に、一貫した逆の方法で最小値から最大値へのペアリングを行います。 並べ替えは、問題を組み合わせ一致から決定論的な貪欲チェックに変換します。 

これが機能する理由は、有効な割り当てが存在する場合、順序を維持する割り当てが存在するためです。順序に違反する 2 つの割り当てを交換しても、実現可能性が損なわれることはなく、多くの場合、スラック分散が改善されます。

 ## アルゴリズムのチュートリアル

 の要素のペアが存在するかどうかをテストしたいと考えています。`b`すべてのペアが`a`下に留まる`x`。 

1. 配列のソート`a`非降順およびソート配列`b`降順ではない順に。 並べ替えは、順列ではなく構造について推論できるため、不可欠です。 
2. 逆配列`b`。 逆転後の最大の要素は、`b`最初に来てください。 これにより、どの「予算」をどの「コスト」に割り当てるかを制御する貪欲なペアリング戦略の準備が整います。 
3. インデックスごとに`i`から`0`に`n - 1`、どうかを確認してください`a[i] + b[n - 1 - i] <= x`。 これは、次の最小要素をペアにします。`a`の最大の要素を持つ`b`、2 番目に小さいものと 2 番目に大きいもの、というようになります。 

この組み合わせの背後にある理由は、`b`無駄なスラックという点で「高価」です。 それらを小さな値に割り当てると、`a`より大きな値の実現可能性をブロックしないようにします。`a`。 

いずれかのペアが条件に違反する場合、有効な再配置は存在しないと直ちに結論付けます。 

### なぜ効果があるのか

 両方の配列を並べ替えた後、それらの間の有効な割り当てを検討します。 より大きな要素が含まれる交差代入が存在する場合、`a`のより大きな要素とペアになっています`b`一方、小さい要素は`a`内のより小さい要素とペアになっています`b`、これら 2 つのペアを交換しても制約は悪化せず、多くの場合、実現可能性が向上します。 このようなスワップを繰り返し適用すると、有効な解はソートされた配列の反対側に一致する解に変換されます。 これにより、逆ペアリングのチェックで十分であることがわかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        line = input().strip()
        while line == "":
            line = input().strip()
        n, x = map(int, line.split())
        
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a.sort()
        b.sort(reverse=True)
        
        ok = True
        for i in range(n):
            if a[i] + b[i] > x:
                ok = False
                break
        
        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```この解決策は、ケースを区切る空白行の処理を含め、各テスト ケースを注意深く読むことから始まります。 仕分け`a`昇順で、そして`b`降順で貪欲な構造を確立します。 

コアループは、検証する必要がある唯一のペアリングをチェックします。 違反が現れた瞬間に、残りの要素を再配置しても、固定インデックスのペアで失敗した制約を修正できないため、早期に停止できます。 

微妙な実装の詳細が逆転している`b`両方を同じ方向にソートし、反対側からインデックスを付けるのではなく。 どちらも同等ですが、逆にするとペアリング ロジックがより明確になります。

 ## 特殊なケース

 最小限のエッジケースは次のような場合です`n = 1`。 このアルゴリズムは 1 回の比較に限定され、並べ替えは効果がありません。 ペアリングでは、可能な唯一の合計が以下の範囲内に収まるかどうかを直接チェックします。`x`。 

境界が狭いケースは次の場合に発生します。`a[i] + b[j]`正確に等しい`x`すべてのペアに。 アルゴリズムは厳密な違反のみを拒否するため、これを受け入れます。これにより、等式制約の下での正しさが確認されます。 

失敗が発生しやすいシナリオは、両方の配列に大きな値が繰り返し含まれている場合です。 例えば、`a = [4, 4, 4]`、`b = [3, 3, 3]`、`x = 6`。 貪欲なペアリングチェック`4 + 3 = 7`、すぐに拒否します。これは、すべての組み合わせが順列まで同一であるため、並べ替えが不可能であることと一致します。
