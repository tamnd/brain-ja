 ## 解決策
 ## 問題の理解

 オリンピックの予選ステージで可能な最小のカットオフ合計スコアを計算するように求められます。 各参加者は 2 つのコンテストに参加しますが、審査員は部分的な情報しか覚えていません。各コンテストの 100 位のスコアと、上位 100 人の参加者に対する他のコンテストのスコアの下限です。 具体的には、最初のコンテストでは、100 位が得点しました。`a`、上位 100 人の参加者全員が少なくとも`b`2回目のコンテストでポイントを獲得。 同様に、2 回目のコンテストでも 100 位が得点しました。`c`、上位 100 人の参加者全員が少なくとも`d`最初のコンテストでポイントを獲得。 合計スコアによるランキングの場合、100位に入った参加者の最低合計スコアを決定します。 

入力は複数のテスト ケースで構成されます。 各ケースは 4 つの整数です`a, b, c, d`制約付き`0 ≤ a, b, c, d ≤ 9`、`d ≤ a`そして`b ≤ c`。 制約は小さく、テスト ケースごとに O(1) の操作が可能です。 主な課題は効率ではなく、スコアをどのように組み合わせて可能な限り最小のカットオフを生成するかを推論することです。 

素朴な解決策では、すべての参加者のスコアをシミュレートしようとするかもしれませんが、特に参加者の正確な数が指定されていないため、それはすぐに非現実的になります。 エッジ ケースには、最初のコンテストの 100 位のスコアが、トップ 100 を争う 2 番目のコンテストの最低スコアよりも低い場合、またはその逆の状況が含まれます。 たとえば、次の場合`a = 0, b = 0, c = 0, d = 0`、最小合計スコアは明らかに 0 です。不注意なアプローチでは、完全な参加者リストではなく、上位 100 人のスコアの最悪の組み合わせのみを考慮する必要があるという事実を見落とす可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、指定された範囲を尊重する参加者の可能なスコア分布をすべて列挙し、100 番目の合計スコアを見つけようとします。 各参加者は制約内で任意の値を取得できるため、組み合わせ爆発が発生します。 参加者が 100 人いる場合、スコアが 0 ～ 9 であっても、操作数は過剰になりますが、限界が小さいため理論的には可能です。 

重要な洞察は、すべての参加者をシミュレートする必要はないということです。 100 番目の合計スコアのみに興味があります。 カットオフを最小限に抑えるために、カットオフをさらに高くする可能性がある他のすべての参加者には、所定のデータと一致する最低の許容スコアが割り当てられていると仮定できます。 したがって、合計の最大値を選択すると、最小合計スコアが得られます。`a + b`そして`c + d`。`a + b`最初のコンテストの 100 番目の参加者が 2 番目のコンテストで最小値を取った場合の合計を表し、`c + d`最初のコンテストで最小値を獲得した場合、2 番目のコンテストの 100 番目の参加者の合計を表します。 各コンテストの 100 位は、他のコンテストで少なくとも所定のスコアを獲得している必要があるため、カットオフはこれらのいずれよりも低くすることはできません。 

この観察により、問題は単純なものに分解されます。`max(a + b, c + d)`テスト ケースごとの計算により、テスト ケースごとの解は O(1) になります。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、整数を読み取ります。`a, b, c, d`。 
3. 最初のコンテストの 100 位のスコアと、上位 100 位の中での 2 番目のコンテストの最小スコアの合計を計算します。`sum1 = a + b`。 
4. 2 番目のコンテストの 100 位のスコアと、上位 100 位の中の最初のコンテストの最小スコアの合計を計算します。`sum2 = c + d`。 
5. 最大値を取る`sum1`そして`sum2`。 これは、100 番目の参加者が指定された制約に違反することなく取得できる最小の合計スコアを表します。 
6. この最大値を出力します。 

機能する理由: 合計スコアが以下の仮説シナリオ`max(a + b, c + d)`少なくとも 1 つのコンテストで 100 位の条件に違反する場合。`a + b`コンテスト 1 の 100 人目の参加者がコンテスト 2 の最低人数を満たしていることを確認し、`c + d`コンテスト 2 の 100 番目の参加者がコンテスト 1 の最小値を満たしていることを確認します。最大値を取得すると、合計を最小限に抑えながらすべての制約が尊重されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c, d = map(int, input().split())
    print(max(a + b, c + d))
```このコードはテスト ケースの数を読み取り、それぞれのテスト ケースを反復処理します。 4 つの整数の各セットについて、100 位までの 2 つの合計スコアを計算し、その最大値を出力します。 使用する`sys.stdin.readline`多くのテスト ケースで高速 I/O を保証します。 の`map(int, input().split())`4 つの値を効率的に整数に変換します。

 与えられた`t ≤ 3025`テスト ケースごとの操作が最小限であるため、これは 1 秒の時間制限と 512 MB のメモリ制約内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    
    t = int(input())
    for _ in range(t):
        a, b, c, d = map(int, input().split())
        print(max(a + b, c + d))
    
    return output.getvalue().strip()

# Provided samples
assert run("2\n1 2 2 1\n4 8 9 2\n") == "3\n12", "sample 1 & 2"

# Custom cases
assert run("1\n0 0 0 0\n") == "0", "all zeros"
assert run("1\n9 9 9 9\n") == "18", "all maximum values"
assert run("1\n5 5 5 5\n") == "10", "all equal"
assert run("1\n3 7 6 2\n") == "10", "mixed values"
assert run("1\n0 9 9 0\n") == "9", "max cross scenario"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 0 0 0 0 | 0 | 最小値のエッジケース |
 | 9 9 9 9 | 18 | 最大値のエッジケース |
 | 5 5 5 5 | 10 | すべて等しい値のシナリオ |

## 特殊なケース

 もし`a = d = 0`そして`b = c = 9`、 それから`a + b = 0 + 9 = 9`そして`c + d = 9 + 0 = 9`。 最大値は 9 で、これは正しく 100 位の最小合計スコアを示します。 このアルゴリズムは、どちらが優勢であるかに関係なく、最初のコンテストの最小値が 2 番目のコンテストの最小値と組み合わされる状況を正しく処理します。
