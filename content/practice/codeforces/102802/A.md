 ## 解決策
 ## 問題の理解

 ジョージは、座標平面上に配置された円形のクッキーのコレクションを持っています。 各 Cookie は、その中心の座標と半径によって記述されます。 彼は、側面が座標軸に平行で、すべてのクッキーが完全に収まる長方形の天板を必要としています。 目標は、そのような鍋の可能な限り小さな面積を見つけることです。 

を中心としたクッキー`(x, y)`半径あり`r`から届く`x - r`に`x + r`水平方向とから`y - r`に`y + r`垂直に。 パンは軸に沿って配置されているため、水平サイズはすべてのクッキーの左端と右端の点のみに依存し、垂直サイズは最下位と最上位の点のみに依存します。 

Cookie の数は次のように大きくなります。`100000`したがって、このソリューションでは、考えられるすべての Cookie のペアを調べたり、考えられる四角形を試したりすることはできません。 数秒の制限付きで、`O(N^2)`この方法では、最悪の場合でも約 100 億回の操作が実行されることになりますが、これは実用的なレベルをはるかに超えています。 シングルパスかそれに近いものが必要です。 

座標値と半径は次の範囲に達します。`10^7`規模的には。 最終的な幅と高さはどちらも約`4 * 10^7`、周囲の領域を作成します`10^15`。 これは、実装には大きな積を安全に保持できる整数型が必要であることを意味します。 Python の整数はこれを自動的に処理します。 

いくつかの特殊なケースによって、不用意なソリューションが壊れる可能性があります。 クッキーが 1 つだけの場合、パンはそのクッキーの直径と両方向で単純に一致する必要があります。 例えば：```
Input
1
0 0 5

Output
100
```異なる Cookie 間の距離のみを考慮するソリューションは、ペアがないため失敗します。 

もう 1 つのよくある間違いは、Cookie の半径によって境界ボックスが拡張されることを忘れることです。 例えば：```
Input
2
0 0 1
2 0 1

Output
16
```Cookie は次の水平座標を占めます。`-1`に`3`、幅を与える`4`、および垂直座標から`-1`に`1`、高さを与える`2`、つまり面積は`8`、 ない`16`。 中心を長方形の角として使用する不注意な実装では、間違った寸法が計算されてしまいます。 

上記の例の正しい出力は、実際には次のようになります。```
8
```長方形はクッキーを覆うだけでよく、クッキーの中心間の距離をあらゆる方向に 2 倍にする必要はありません。 

## アプローチ

 簡単なアプローチは、すべての Cookie をチェックし、現在の最小座標と最大座標を追跡することによって、四角形を見つけるプロセスをシミュレートすることです。 これはすでに本質的な考え方です。 より単純なバージョンでは、すべての Cookie を他のすべての Cookie と比較して、極端な境界を決定する可能性がありますが、そのパフォーマンスは`O(N^2)`比較。 と`N = 100000`、これは約になります`10^10`比較。 

問題の構造から、より簡単な観察が得られます。 最終的な四角形は、4 つの値によって完全に決定されます。つまり、Cookie が到達する最小の X 座標、Cookie が到達する最大の X 座標、Cookie が到達する最小の Y 座標、および Cookie が到達する最大の Y 座標です。 各 Cookie は、2 つの可能な x 境界と 2 つの可能な y 境界のみを提供します。 

総当たりアプローチは、答えがすべての Cookie の極点に依存するため機能しますが、それらの極値を繰り返し検索すると失敗します。 各 Cookie が個別に極値を更新できるという観察により、問題を入力全体の 1 回のスキャンに減らすことができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^2) | お(1) | 遅すぎる |
 | 最適 | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在の外接四角形を表す 4 つの変数を初期化します。 x および y の最小値を非常に大きな数値に設定し、x および y の最大値を非常に小さな数値に設定します。 これにより、Cookie が処理されると拡張される空の四角形が作成されます。 
2. 各 Cookie を読み取り、その 4 つの極点を計算します。 左端は、`x - r`、右端は`x + r`、下端は`y - r`、上端は`y + r`。 
3. これら 4 つの境界を使用して、保存されている最小値と最大値を更新します。 直接更新する理由は、最終的な四角形が個々の Cookie の位置ではなく、最も遠くに到達した位置にのみ依存するためです。 
4. すべての Cookie が処理された後、長方形の幅を次のように計算します。`max_x - min_x`そして高さは`max_y - min_y`。 
5. 幅と高さを掛けます。 これより小さな長方形は極端な Cookie 境界の 1 つを含むことができないため、結果の値は可能な最小のパン領域になります。 

なぜ効果があるのか:

 スキャン中のすべての時点で、保存された値は、これまでに処理されたすべての Cookie を含む軸に揃えられた最小の長方形を表します。 新しい Cookie を追加する場合、その全領域が長方形の内側に収まる必要があるため、可能な変更は 4 つの辺のうちの 1 つ以上を拡張することだけです。 すべての Cookie が処理された後、保存された四角形にはすべての Cookie が含まれ、すべての辺が少なくとも 1 つの Cookie 境界によって強制されます。つまり、どの辺も内側に移動できません。 このようにして 4 辺すべてが固定された長方形が、可能な最小限のパンです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    min_x = float("inf")
    max_x = float("-inf")
    min_y = float("inf")
    max_y = float("-inf")
    
    for _ in range(n):
        x, y, r = map(int, input().split())
        
        min_x = min(min_x, x - r)
        max_x = max(max_x, x + r)
        min_y = min(min_y, y - r)
        max_y = max(max_y, y + r)
    
    print((max_x - min_x) * (max_y - min_y))

if __name__ == "__main__":
    solve()
```プログラムは、アルゴリズムで説明されている 4 つの境界を維持します。 各入力 Cookie は、その左、右、下、上端を即座に提供します。 

更新は、すべての Cookie を保存するのではなく、入力を読み取っている間に行われます。 これにより、メモリの使用量が一定に保たれ、不必要な作業が回避されます。 最後の乗算は、完全な外接する四角形がわかった後にのみ実行されます。 

初期化に無限大を使用しているにもかかわらず、浮動小数点計算はありません。 座標と半径は整数であるため、すべての境界と最終領域も整数になります。 Python の整数演算は、固定サイズの整数型を使用する言語で発生する可能性のあるオーバーフローの問題も回避します。
