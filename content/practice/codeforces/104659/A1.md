 ## 問題の理解

 無限の 2D グリッド上のターゲット ポイントが与えられており、非常に特殊な種類の動きを使用して原点から出発してそのターゲット ポイントに到達できるかどうかを判断したいと考えています。 各移動の長さは固定されており、1 から始まり、次に 2、次に 4 というように、毎回 2 倍になります。 i 番目の移動では、正確に移動する必要があります$2^i$4 つの基本的な方向のいずれかに進みます。 

目的地に到達できるかどうかを判断するだけでなく、可能であれば目的地に到達するための有効な一連のルートを構築することもタスクとなります。 

動きの構造により、制約された二進法に似たシステムで座標を表現することが根本的に問題となります。 各ステップは 1 ビットの「移動パワー」を消費し、そのパワーが x または y 座標にどのように寄与するかは方向によって決まります。 

(元の Expogo スタイルの問題と同様に) 制約では、通常、大きな範囲までの座標が許可されるため、すべてのパスにわたるシミュレーションが除外されます。 全方向シーケンスに対する総当り検索では、各ステップで 4 つずつ分岐し、30 の動きであっても、これはすでに超えています。$4^{30}$、それは天文学的な大きさです。 ソリューションでは、座標から直接パスを構築する必要があります。 

両方の座標が偶数である場合、微妙なエッジケースが表示されます。 たとえば、最初のステップで (0, 0) から (2, 2) に到達すると、すでにシステムのパリティ構造が破綻しています。 すべての移動の長さは 2 のべき乗であるため、パリティ制約は逆方向に伝播します。2 で割ることにより、すべての段階で整合性が維持される必要があります。 これを無視した素朴な試みは、すべてのポイントが到達可能であると誤って仮定することになります。 

もう 1 つの一般的な失敗ケースは、マンハッタン距離のパリティが十分であると想定していることです。 たとえば、(1, 1) と (2, 0) は、座標の合計が同様の実現可能性を示唆しているとしても、制約の下では大きく異なる動作をします。 

## アプローチ

 ブルート フォース ソリューションでは、座標の大きさによって決まる最大限界まで、長さ方向のすべてのシーケンスを探索しようとします。 各ステップで、4 つの方向の 1 つを選択し、対応する 2 の累乗を x または y から減算します。 これにより、考えられるすべてのパスが正しく列挙されますが、状態空間は指数関数的に増加します。 最大 40 の手が必要な場合、可能性の数は次のようになります。$4^{40}$、これは実行可能な計算をはるかに超えています。 

重要な観察は、有効な構築における最後の手は、x または y のいずれかの最低のバイナリ レベルを解決する必要があるということです。 最後の移動のサイズは 1 であるため、x または y は正確に ±1 だけ変更できます。 これにより、完了していない各ステップで少なくとも 1 つの座標が奇数になります。 どの軸が奇数パリティの原因であるかを修正したら、最後の移動の方向を一意に決定し、調整後に両方の座標を半分にすることで問題を軽減できます。 

これにより、問題はターゲットから後方への貪欲な再構築に変わります。 前進するパスを構築する代わりに、一度に 1 つの動きを剥がし、現在の動きの影響を除去した後、両方の座標が 2 で割ったときに整数のままであることを常に確認します。

 ## アルゴリズムのチュートリアル

 ターゲット点から開始して原点に向かって逆方向に進む一連の動きを再構築します。 

1. まず、現在の座標 (x, y) を考慮します。 x と y の両方がゼロの場合、構築は完了です。 逆に構築されたシーケンスは有効な答えです。 
2. x と y が両方とも偶数の場合、サイズは移動しません$2^k$整数前の状態からそのような状態に至る可能性があります。 これは、構成が無効であり、解決策が存在しないことを意味します。 その理由は、すべての移動がパリティを正確に 1 つの座標方向に反転させるためです。 
3. x が奇数の場合、最後の移動が x 座標に影響を与えたはずです。 私たちはそれが左から来たのか、右から来たのかを判断しなければなりません。 次の状態との整合性を保ちながら、(x-1)/2 と (x+1)/2 のどちらが整数であるかをテストします。 両方の座標を 2 で割った後、次の座標が整数になる方向を選択します。 
4. y が奇数の場合、同じ推論を垂直方向に適用し、半分にした後に整数性が維持されるかどうかに応じて、上または下に移動するかを選択します。 
5. 選択した移動を適用した後、移動を減算し、両方の座標を 2 で割ることにより、(x, y) を前の状態に更新します。また、対応する方向を回答シーケンスに追加します。 
6. (0, 0) に達するまでこのプロセスを繰り返します。 収集されたシーケンスは逆順になっているため、最後にそれを逆にします。 

正確さは構造的不変式に依存します。つまり、各ステップの後、現在の (x, y) は、いくつかの動きの接頭辞の後に到達可能な有効な状態を表し、動きが残っている場合は必ず 1 つの座標が奇数でなければなりません。 これにより、後方再構成には矛盾を引き起こす曖昧さがなくなり、すべての有効なパスがパリティ駆動の決定の一意のシーケンスに対応することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y = map(int, input().split())
    
    if x == 0 and y == 0:
        print("")
        return

    ans = []

    while x != 0 or y != 0:
        if x % 2 == 0 and y % 2 == 0:
            print("IMPOSSIBLE")
            return

        # decide direction based on parity
        if x % 2 != 0:
            # try East or West
            if ((x - 1) // 2) % 2 == y % 2:
                ans.append('E')
                x = (x - 1) // 2
            else:
                ans.append('W')
                x = (x + 1) // 2
            y = y // 2
        else:
            # y is odd
            if ((y - 1) // 2) % 2 == x % 2:
                ans.append('N')
                y = (y - 1) // 2
            else:
                ans.append('S')
                y = (y + 1) // 2
            x = x // 2

    print("".join(ans[::-1]))

if __name__ == "__main__":
    solve()
```実装は後方構築に直接続きます。 両方の座標がゼロに達すると、ループは停止します。 両方の偶数状態のパリティ チェックは、即時に実行不可能な条件です。 反復ごとに座標の大きさがおよそ半分に減り、対数的な深さが確保されます。 

方向の選択は、どの調整が有効な半減ステップにつながるかをテストすることによって実装されます。 最後の動きから最初の動きまでのパスを構築するため、逆の構築はリストに保存され、最終的に逆にされます。 

微妙な詳細は、負の数での整数の除算の動作です。 Python のフロア分割はここでも正しく機能します。選択された動きが分割前の均等な遷移を保証し、正確性が維持されるからです。

 ## 特殊なケース

 最も重要なエッジケースは、両方の座標が非終端状態にある場合です。 たとえば、(2, 2) から開始すると、直ちに強制的に失敗します。 有効な後方再構成では、2 のべき乗の一連の移動によって両方の座標が同時に 2 で割り切れる状態を作成できないため、アルゴリズムはこれを各反復の先頭で検出して終了します。 

別のケースは、(0, 8) のような純粋に軸が揃ったターゲットです。 再構成では x 座標に触れることはなく、アルゴリズムは y を半分にすることによって繰り返し解決します。 各ステップは垂直方向の動きに明確にマッピングされ、シーケンスは 8 の単純な 2 値分解になります。 

3 番目のケースは、(5, 3) のように、水平方向と垂直方向の決定の間で繰り返し切り替えを強制するような方法で、座標のパリティが交互になる場合です。 アルゴリズムは依然としてステップごとに大きさを減らし、少なくとも 1 つの座標が奇数であるという不変条件により、両方の座標がゼロに達するまで有効な方向が常に利用可能であることが保証されます。
