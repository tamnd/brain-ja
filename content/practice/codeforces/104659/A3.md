 ## 問題の理解

 無限の 2D グリッド上の目標点が与えられており、原点から出発してそこに到達したいと考えています。 許可される唯一の動きは、長さが 2 の累乗であるジャンプであり、各動きは厳密に 4 つの基本的な方向のいずれかに進む必要があります。 ジャンプ サイズはタイム ステップによって事前に固定されています。最初の移動の長さは 1、2 番目の移動の長さは 2、3 番目の移動の長さは 4 などとなり、i 番目の移動の長さは 2^(i-1) になります。 

タスクは、一定回数の移動後にターゲット ポイントに正確に着地できるかどうかを判断し、可能であれば、それを達成する有効な一連の方向を構築することです。 

動きの構造により、問題は非常に制約されます。 各ステップでは、最終変位の 2 進数が異なるスケールで固定されるため、構築は座標のビット単位の分解のように動作します。 これは、すべてのステップが 4 つの可能性に分岐するため、考えられるすべての方向の選択に対する単純なシミュレーションがステップ数とともに指数関数的に増加することを直ちに意味します。 中程度の距離であっても、これは完全に不可能です。 

通常、制約では、10^9 以上の非常に大きな絶対値までの座標が許可されます。つまり、グリッド内の状態を明示的に探索したり、位置に対して最短パス検索を実行したりするアプローチは失敗します。 状態空間は構造なしで成長し、分岐係数は一定のままであるため、状態を越えた BFS さえも不可能です。 

パリティ制約に起因する微妙な障害ケースもあります。 たとえば、中間ステップで両方の座標が偶数である場合、2 で割ることは完全性を維持し安全ですが、両方が奇数である場合、有効な手を行っても状態をきれいに減らすことはできません。 このパリティ構造を尊重せずに単純に「方向を試す」単純な貪欲なアプローチは、(2, 2) のような状況で行き詰まり、不注意な減算が非整数の中間状態につながります。 

## アプローチ

 ブルート フォース ソリューションでは、各ステップを 4 つの方向からの選択として扱い、座標をカバーするのに必要なビット数までの長さのすべての可能なパスをシミュレートします。 これにより、分岐係数 4 の検索ツリーが形成されるため、k ステップ後には 4^k 個の状態になります。 k は座標の大きさの対数とともに増加するため、これは依然として急速に爆発し、控えめな入力でも実用的ではなくなります。 ブルート フォース手法は、考えられるすべてのパスを探索するため、原理的には正しいですが、座標範囲が小さな値を超えるとすぐに失敗します。 

構造上の重要な洞察は、移動サイズが 2 の累乗であるということです。これは、各ステップが最終的な x または y 変位の 1 ビットを効果的に決定することを意味します。 原点から前向きに考えるのではなく、目標から逆算して考えます。 各ステップで、サイズ 2^k の移動を「元に戻す」ことを試み、問題を 2 で割ることによって得られるより小さな座標系に縮小します。 

重要な観察は、すでに原点にいない限り、すべての段階で少なくとも 1 つの座標が奇数でなければならないということです。 両方の座標が偶数であれば、安全に 2 で割って続行できます。 正確に 1 つの座標が奇数である場合は、現在の 2 のべき乗ステップに正しい方向を選択して、その座標を減らす必要があります。 両方が奇数の場合、前の有効なステップではそのような状態を生成できないため、構成が不可能になります。 

この後方再構成により、問題は、座標のバイナリ表現に対する決定論的な貪欲なプロセスに変換されます。

 ## アルゴリズムのチュートリアル

 移動を元に戻すことを繰り返して、ターゲットから原点に戻るパスを構築します。

1. x と y の両方がゼロの場合、すでに原点に到達し、構築は終了します。 
2. x と y が両方とも偶数の場合、両方を 2 で割ります。 これは、偶数の座標は常に 2 倍の小さい整数として表現できるため、一貫した方法で前のステップの動きを逆転させることに相当します。 
3. x と y が両方とも奇数の場合は、停止して、解が存在しないことを報告します。 2 で除算した後に両方の座標が奇数になる状態を生み出す方向の選択はどのステップにも存在しないため、この構成は有効な移動からは発生しません。 
4. 1 つの座標だけが奇数である場合は、その軸の正または負の方向に現在の 2 のべき乗ステップを減算するかを決定する必要があります。 x が奇数であるとします。 東または西に移動すると、2 で割った後の有効な次の状態が得られるかどうかを検討します。 この決定は、結果として得られる縮小された座標のパリティをチェックすることによって行われ、次のステップで無効な「両方奇数」状態に移行しないようにします。 y が奇数の場合、同じロジックが対称的に適用されます。 
5. 選択した方向を記録し、奇数の座標から選択した 2 の符号付き累乗を減算して座標を更新します。 
6. 原点に到達するまで繰り返します。 

正確さは、各ステップの後、ペア (x, y) が 2 つの手の残りのべき乗の合計として表現可能なままであるという不変式に依存します。 パリティ条件は、将来の分解が不可能になる状態に決して入らないことを保証します。 各ステップでは、バイナリ長で少なくとも 1 つの座標の大きさが減少するため、プロセスは終了する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_one(x, y):
    if x == 0 and y == 0:
        return ""

    res = []

    while x != 0 or y != 0:
        if x % 2 == 0 and y % 2 == 0:
            return "IMPOSSIBLE"

        if x % 2 != 0:
            # decide E or W
            # try moving east
            nx, ny = (x - 1) // 2, y // 2
            if (nx + ny) % 2 == 0:
                res.append('E')
                x, y = nx, ny
            else:
                res.append('W')
                nx, ny = (x + 1) // 2, y // 2
                x, y = nx, ny
        else:
            # y is odd, decide N or S
            nx, ny = x // 2, (y - 1) // 2
            if (nx + ny) % 2 == 0:
                res.append('N')
                x, y = nx, ny
            else:
                res.append('S')
                nx, ny = x // 2, (y + 1) // 2
                x, y = nx, ny

    return "".join(res)

def main():
    x, y = map(int, input().split())
    ans = solve_one(x, y)
    print(ans)

if __name__ == "__main__":
    main()
```このコードは、後方再構成を直接実装します。 ループは、各移動を反転した後、現在の縮小座標を維持します。 両方の座標が偶数である場合、分割ステップは一貫したバイナリ層を剥がすことに対応します。 

1 つの座標が奇数の場合、コードは、縮小されたペアのパリティをチェックすることによって、どの方向が有効な次の状態につながるかをテストします。 これにより、以降のステップが無効になる構成に陥ることが回避されます。 この構造では逆の順序で答えが構築されるため、最終的な文字列はすでに開始点からターゲットまでの正しい移動順序になっています。 

実装の微妙な詳細は、1 を引くか 1 を加えた後の整数の除算です。`(x - 1) // 2`そして`(x + 1) // 2`は、x が奇数の場合にのみ有効であり、除算の正確性が保証されます。 y についても同様です。 これらの操作の前に奇数パリティを強制しないと、整数の丸めによって不正な状態が暗黙的に生成されてしまいます。 

## 実用的な例

 インプットを考慮する`(x, y) = (2, 3)`。 

アルゴリズムを段階的に追跡していきます。 

| ステップ | × | y | アクション | 結果の (x, y) |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 3 | y は奇数です。テスト N/S | S → (2, 1) を選択 |
 | 2 | 2 | 1 | y は奇数です。テスト N/S | N → (2, 0) を選択 |
 | 3 | 2 | 0 | x は偶数、y は偶数 | 除算 → (1, 0) |
 | 4 | 1 | 0 | x は奇数です。テスト E/W | E→(0,0)を選択 |

 一連の動きはトランジションの逆順に構築され、最終的には原点に到達します。 これは、アルゴリズムがパリティ解決と半分化をどのように切り替えるかを示しています。 

次に、次のような不可能なケースを考えてみましょう`(x, y) = (2, 2)`。 

| ステップ | × | y | アクション |
 | --- | --- | --- | --- |
 | 1 | 2 | 2 | 両方とも偶数 → 除算 |
 | 2 | 1 | 1 | 両方とも奇妙→不可能 |

 2 番目のステップでは、両方の座標が奇数になります。これは、有効な変換後でも少なくとも 1 つの座標が残らなければならないという構造上の要件に違反します。 アルゴリズムは正しく終了します。 

これらの例は、この方法がパリティ進化によって厳密に制御されていること、およびすべてのステップで大きさがきれいに減少するか、不可能性を早期に検出することを示しています。

 ## 特殊なケース

 元のケース`(0, 0)`移動する必要がないため、すぐに処理されます。 アルゴリズムは、ゼロ ステップと一致する空のシーケンスを返します。 

のようなケース`(1, 0)`は、決定が直接 1 つの手になる奇数 x 分岐を示しています。 アルゴリズムは、考えられる両方の削減を評価し、たとえシーケンスが即座に終了したとしても、将来の状態の有効性を保持する方を選択します。 

のために`(0, 1)`、動作は x 軸ロジックを反映しており、パリティ ベースの決定プロセスにおける軸間の対称性が確認されています。 

のために`(2, 2)`、アルゴリズムは 1 つの除算ステップを実行して、`(1, 1)`そして、両方の座標が奇数である無効な状態を即座に検出します。 これは、不可能条件が間違ったパスを強制的に進めるのではなく、解決不可能な構成の伝播をどのように防ぐかを示しています。
