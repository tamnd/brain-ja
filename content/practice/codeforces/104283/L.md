 ## 解決策
 ## 問題の理解

 位置 0 から位置 N までの数直線があり、厳密にこの間隔内の個別の整数座標に石が配置されています。 単一のバリアは、連続する整数の各ペアの間の未知の半整数位置に配置されるため、均一に選択された 0 から N − 1 までのいくつかの i に対して、事実上バリアは i + 0.5 になります。 

2 人のプレーヤーが、固定されたバリアの位置をめぐって決定的なゲームをプレイします。 移動は、石を 1 つ選択し、それを正の整数だけ移動することで構成されます。 バリアの左側にある石はさらに左にのみ移動でき、バリアの右側にある石はさらに右にのみ移動できます。 石は 0 と N で他の石や壁を越えることはできません。また、2 つの石が同じ位置を占めることはできません。 正当な手を持たなかったプレイヤーは負けます。 Pt が先に動き、両プレイヤーが最適にプレイします。 

ランダム性があるのはバリア位置のみです。 考えられるそれぞれの障壁に対して、決定的なゲーム結果が得られます。 Pt が勝つバリア ポジションの割合を計算し、それを法 1000000007 で出力する必要があります。 

この制約は、ゲームの直接シミュレーションが不可能であることを意味します。 状態空間は石の数が指数関数的であるため、単一のポジションを評価するだけでも最適なプレイを理解する必要があります。 N は大きくなる可能性があり、N 個の可能なバリア位置のそれぞれを考慮する必要があるため、ソリューションでは、前処理後に位置ごとの評価を O(1) に近い値、つまり対数に減らす必要があります。 

すべての石がバリアの片側にある場合、微妙なエッジケースが現れます。 たとえば、すべての石がバリアの右側にある場合、右方向への移動のみが許可され、左側は何も貢献しません。 逆に、すべての石が左側にある場合は、左側の構造のみが重要になります。 もう 1 つのエッジ ケースは、石が壁または別の石に隣接しており、その移動性が即座にゼロになる場合です。これは、石がゲームの状態にまったく寄与するかどうかに影響します。 

## アプローチ

 ブルートフォースの観点は、バリアの位置を修正し、ゲームの結果を計算しようとすることです。 固定バリアの場合、石は 2 つの独立した領域に分割されます。 各領域内では、石は一方向にのみ移動でき、互いに交差することはできません。つまり、石の相互作用は純粋に局所的であることを意味します。 単純なソルバーは、最適なプレーをシミュレートするか、すべての構成にわたってグランディ値を計算しようとします。 ただし、単一のバリアであっても、状態遷移は石間の相対距離に依存し、これらを最初から再計算するには O(M) 以上のコストがかかります。 すべての N 個のバリア位置に対してこれを行うと、O(NM) または O(NM log M) になり、これは大きすぎます。 

重要な構造上の観察は、バリアが固定されると、ゲームが 2 つの独立した一方的な移動ゲームに分解されるということです。 各辺は、独立した「ギャップ ヒープ」のセットに縮小できます。 石を分類すると、各石は、許可された方向にある最も近い障害物との間の空きスペースを効果的に制御します。 石を移動すると、そのギャップが正の量だけ減少するだけです。これはまさに Nim ヒープであり、各ヒープ サイズがギャップの長さであり、移動はそのギャップを任意に減少させることに対応します。 したがって、サイドのゲーム価値は、そのサイドのすべてのギャップ長の XOR になります。 

これにより、2 つの XOR 集計の計算に対する固定障壁の問題が軽減されます。1 つは左側の石について、連続する石と左側の壁の間のギャップを使用し、もう 1 つは右側の石について、ギャップと右側の壁を使用します。 残りの難しさは、バリアが移動するため、石の分割がすべての N 位置にわたって動的に変化することです。 最初から再計算する代わりに、ソートされたストーンに対してプレフィックスとサフィックスの構造を前処理して、各分割が対数時間で回答できるようにします。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NM) | お(お) | 遅すぎる |
 | 最適 | O(M log M + N log M) | お(お) | 承認済み |

 ## アルゴリズムのチュートリアル

 まずは石の位置を整理します。 これにより、安定した順序が与えられ、バリア分割が左側の石の接頭辞と右側の接尾辞に対応するようになります。 

次に、左側の解釈のためにプレフィックス ギャップ XOR を計算します。 概念的には、位置 0 に壁を追加します。並べ替えられた順序での各石の寄与は、前の境界 (前の石または壁のいずれか) からの距離です。 これらの距離の実行 XOR を維持することで、石の接頭語に対して左側のゲーム値をすぐに取得できるようになります。 

右側のサフィックス ギャップ XOR も計算します。 ここでは視点を反転し、位置 N の壁を境界として扱います。 石の各接尾語は右側の壁で終わる一連のギャップを形成し、これらのギャップの XOR が右側のゲーム価値を完全に特徴づけます。 

前処理の後、0 から N − 1 までの考えられる各バリア位置 i を考慮します。各 i について、位置 ≤ i にある石の数を決定します。これにより、左右のセット間の分割点 k が得られます。 これは、ソートされた石のリストに対する二分探索を使用して効率的に計算できます。 

各バリア i について、ゲーム価値は、k 個の石の左側のプレフィックス値と残りの M − k 個の石の右側のサフィックス値の XOR です。 この XOR がゼロ以外の場合、最適なプレイで最初のプレーヤーが勝ちます。 私たちはそのような障壁を数えます。 

最後に、N 個のバリア位置はすべて同じ確率であるため、逆モジュラーを使用して勝利カウントを 1000000007 を法とする N で除算します。 

これが機能する理由は、バリアの各側が、互いに素なヒープに対する独立した減算ゲームであるという不変条件に基づいています。 どのような動きもバリアを越えて影響を伝達することはできないため、ゲーム全体は 2 つのニムのような構造の素の合計になります。 すべてのギャップ長の XOR は、各側の正規の Grundy 表現として保存され、結合された XOR がゼロ以外の場合に限り、グローバル位置が優先されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def modinv(x):
    return pow(x, MOD - 2, MOD)

def build_prefix_xor(stones):
    m = len(stones)
    pref = [0] * (m + 1)

    xor_val = 0
    prev = 0
    for i in range(1, m + 1):
        xor_val ^= stones[i - 1] - prev
        pref[i] = xor_val
        prev = stones[i - 1]
    return pref

def build_suffix_xor(stones, N):
    m = len(stones)
    suf = [0] * (m + 1)

    xor_val = 0
    nxt = N
    for i in range(m - 1, -1, -1):
        xor_val ^= nxt - stones[i]
        suf[i] = xor_val
        nxt = stones[i]
    return suf

def solve():
    N, M = map(int, input().split())
    stones = []
    if M > 0:
        stones = list(map(int, input().split()))
    stones.sort()

    pref = build_prefix_xor(stones)
    suf = build_suffix_xor(stones, N)

    ans = 0

    for i in range(N):
        # number of stones <= i
        lo, hi = 0, M
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if mid > 0 and stones[mid - 1] <= i:
                lo = mid
            else:
                hi = mid - 1
        k = lo

        left = pref[k]
        right = suf[k]

        if left ^ right:
            ans += 1

    print((ans * modinv(N)) % MOD)

if __name__ == "__main__":
    solve()
```この実装は、ソート後にプレフィックスとサフィックスの両方の XOR 構造を線形時間で更新できるという事実に依存しています。 各バリアの二分探索により、左側に属する石の数が決まります。 k が 0 または M に等しい場合、辺の 1 つが空になり、XOR にゼロが寄与する境界では注意が必要です。 

## 実用的な例

 N = 5 で石が位置 [1、3] にある小さな構成を考えてみましょう。 

プレフィックスとサフィックスの構造を計算します。 

| ステップ | k | 左 XOR | 右 XOR | 合計 XOR |
 | --- | --- | --- | --- | --- |
 | 0 のバリア | 0 | 0 | (3-1)+(5-3)=4 | 4 |
 | 2のバリア | 1 | (1-0)=1 | (3-1)+(5-3)=4 | 5 |
 | 4のバリア | 2 | (1-0)+(3-1)=3 | (5-3)=2 | 1 |

 3 つの位置はすべてゼロ以外の XOR を与えるため、すべてのケースで Pt が勝ちます。 

ここで、N = 4 で [2] に 1 つの石があると考えます。 

| ステップ | k | 左 XOR | 右 XOR | 合計 XOR |
 | --- | --- | --- | --- | --- |
 | 0 のバリア | 0 | 0 | (2-0)+(4-2)=4 | 4 |
 | 1 のバリア | 0 | 0 | (2-0)+(4-2)=4 | 4 |
 | 2のバリア | 1 | (2-0)=2 | (4-2)=2 | 0 |
 | 3 のバリア | 1 | (2-0)=2 | (4-2)=2 | 0 |

 ここでは、2 つの障壁だけが Pt のポジションを失うことにつながります。これは、石の周りの対称性がバランスの取れたポジションを生み出す動作と一致します。

 ## 特殊なケース

 石がない場合は、どの障壁位置でも両側が空いています。 すべての局面は先手プレイヤーにとって最終的な負け状態であるため、勝てる確率はゼロです。 プレフィックスとサフィックスの両方の XOR 配列がどこでもゼロのままであり、すべてのバリアが損失構成に寄与するため、アルゴリズムはこれを処理します。 

すべての石がすべてのバリアの片側にある場合、2 つの XOR コンポーネントのうちの 1 つは常に 0 で、もう 1 つはすべてのスプリットにわたって一定です。 この場合、片側 XOR がゼロ以外であるかどうかに応じて、すべてのポジションが勝っているか、すべてのポジションが負けています。 一方の寄与が空の XOR 値になるため、プレフィックスとサフィックスの構築にはこれが自然に反映されます。 

石が壁の近くまたは互いに隣接して密に詰め込まれている場合、一部のギャップ値がゼロになりますが、これは XOR には影響しません。 構築にはこれらの長さゼロの寄与が暗黙的に正しく含まれており、ゲームの状態は変更されず、縮退した構成でも正確さが維持されます。
