 ## 解決策
 ## 問題の理解

 固定された順序で配置された一連の山が与えられます。 各山にはある程度の数の石が含まれており、プレイヤーは交互にターンします。 ターンでは、プレイヤーはパイルを選択しますが、厳密な依存関係があります。パイルは、その前のすべてのパイルがすでに完全に空になっている場合にのみ使用できます。 選択した山の中で、プレイヤーは正の数の石を取り除くことができます。 

ゲームはインデックス L から R までのパイルのセグメントでプレイされ、動けなかったプレイヤーが負けます。 さらに、1 つの山の石の数が変更される更新にも対応しています。 

重要な構造上の制約は、プレーは左から右へのみ進むことができるということです。 これは、ゲームがパイル間で自由に分岐するのではなく、固定された順序で展開され、パイル i が空になるまでパイル i+1 にアクセスできないことを意味します。 

複雑さの観点から見ると、パイルの数が十分に大きいため、クエリごとにセグメントの結果を最初から再計算すると時間がかかりすぎます。 各クエリに対するゲームの単純なシミュレーションでは、範囲内のすべての石またはすべての杭を処理する必要があり、クエリあたりの時間が直線的に増加します。これは、n と q の両方が大きい一般的な制約とは互換性がありません。 

杭に石が含まれていない場合、微妙なエッジケースが発生します。 たとえば、山がすでに空の場合、その山は一連の強制的な動きから事実上消えてしまい、ゲームの流れが変わります。 もう 1 つの重要なケースは、範囲内のすべての山が空の場合です。この場合、手は存在せず、最初のプレイヤーが即座に負けます。 

## アプローチ

 この問題に直接アプローチする方法は、ゲームをシミュレートすることです。 L から R の範囲に関するクエリの場合、L から R まで繰り返しスキャンし、最初の空でない山を見つけて、そこから石をいくつか取り除き、手がなくなるまで交互にターンします。 ただし、このシミュレーションは基本的に非効率的です。各移動で最大でも 1 つの山しか空にならず、最悪の場合、クエリ間で同じ構造を何度も再訪する可能性があります。 最大 10^5 のパイルと 10^5 のクエリを使用すると、二次関数の動作が生じます。 

重要な観察は、ルールの構造から来ています。プレイヤーは、現在アクセス可能な山から任意の正の数の石を取り除くことができます。 つまり、最適な動きは常に 1 ターンで山全体を取り除くことです。 石を残しておく理由は決してありません。そうすることで、将来の山へのアクセスを変更せずに、余分な強制的な動きを対戦相手に渡すだけだからです。 

これが認識されると、到達すると 1 ターンでクリアされるため、空ではない各パイルはゲーム内で 1 回の強制移動に貢献します。 セグメント上のゲーム全体は、空ではない山の上で左から右の順に必須の移動を交互に繰り返す単純なシーケンスになります。 勝者は、セグメント内の空でない山の数が奇数か偶数かによって完全に決まります。 

これにより、各クエリは、各要素がアクティブ (ゼロ以外) または非アクティブ (ゼロ) のいずれかになる動的配列上のパリティ クエリに縮小され、ポイントの更新によってパイルの状態が変更されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | クエリあたり O(n) | お(1) | 遅すぎる |
 | フェンウィック/セグメント ツリーと同等 | 更新/クエリごとに O(log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは問題をバイナリ配列を維持することに帰着させます。各山は、石が少なくとも 1 つ含まれている場合は 1、それ以外の場合は 0 として表されます。

1. 各パイル値を空でないかどうかを示すブール値に変換します。 これにより、パイルのサイズではなく存在のみが重要となるため、ゲームプレイに関連するすべての情報がキャプチャされます。 
2. 2 つの操作を効率的にサポートするデータ構造を構築します。1 つは山が変化したときの 1 つの位置の更新、もう 1 つは範囲内の値の合計のクエリです。 ここでの合計はアクティブな杭の数を表します。 
3. 更新クエリの場合、新しい値 x がゼロより大きい場合は位置 i を 1 に設定し、それ以外の場合は 0 に設定します。これにより、表現とゲームの動作の一貫性が保たれます。 
4. L から R までの範囲クエリの場合、その間隔内のアクティブなパイルの合計を計算します。 これにより、ゲームセグメント内で強制された手の数が得られます。 
5. パリティに基づいて勝者を決定します。アクティブなパイルの数が奇数の場合は、最初のプレーヤーが最初、3 番目、5 番目などの動きをしたので勝ちます。 それ以外の場合は、2 番目のプレーヤーが勝ちます。 

正しさは、各アクティブなパイルが順番に 1 つの不可逆的な動きに寄与するという事実にかかっており、プレイヤーはパイルの順序を変更したりスキップしたりすることはできません。 

### なぜ効果があるのか

 ゲームは常に左から右に厳密に進行します。 山が現在の焦点になると、最適なプレイヤーは常に 1 回の動きですぐに山を空にします。 将来の決定が以前の山に影響を与えることはできず、部分的な移動はアドバンテージをもたらしません。 これにより、ゲームは空ではないパイルのセットに対する単一の移動の決定的なシーケンスに強制されます。 プレイヤーは交互に手を動かすため、結果はこのシーケンスの長さが奇数か偶数かによってのみ決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def main():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))

    ft = Fenwick(n)
    state = [0] * (n + 1)

    for i in range(1, n + 1):
        state[i] = 1 if arr[i - 1] > 0 else 0
        ft.add(i, state[i])

    out = []

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            i = int(tmp[1])
            x = int(tmp[2])
            new_state = 1 if x > 0 else 0
            diff = new_state - state[i]
            if diff != 0:
                state[i] = new_state
                ft.add(i, diff)
        else:
            l, r = int(tmp[1]), int(tmp[2])
            cnt = ft.range_sum(l, r)
            if cnt % 2 == 1:
                out.append("1")
            else:
                out.append("-1")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```フェンウィック ツリーは、空ではないパイルの数を維持します。 各更新では、パイルが空と空以外の間で遷移するかどうかに応じて、最大 ±1 だけ 1 つの位置が調整されます。 各クエリはプレフィックスの合計の差を計算して、範囲内のアクティブなパイルの数を取得します。 

微妙な実装の詳細は、原石の数をデータ構造に保存しないことです。 重要なのはバイナリ状態のみであるため、すべての更新は単純なしきい値チェックに集約されます。 

## 実用的な例

 5 つの杭の初期構成を考えてみましょう。`[3, 0, 2, 0, 1]`。 

範囲を問い合わせる`[1, 5]`位置 1、3、5 にアクティブなパイルが与えられるため、カウントは 3 になります。 

| ステップ | アクティブパイル | カウント | パリティ |
 | --- | --- | --- | --- |
 | イニシャル | 1、3、5 | 3 | 奇数 |

 カウントが奇数なので先攻の勝ちとなります。 

ここで、山 3 を 0 に更新して、配列を作成することを考えてみましょう。`[3, 0, 0, 0, 1]`。 

に関する質問`[1, 5]`2 つのアクティブなパイルが生成されます。 

| ステップ | アクティブパイル | カウント | パリティ |
 | --- | --- | --- | --- |
 | アップデート後 | 1、5 | 2 | 偶数 |

 これで 2 番目のプレイヤーが勝ちとなります。 

これらのトレースは、ゲーム全体がインターバル内にどれだけの有効な手が残っているかを追跡することに帰着することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | 操作ごとに O(log n) | 各更新と範囲の合計は、対数の高さでのフェンウィック ツリーの伝播によって処理されます。 
| スペース | O(n) | フェンウィック ツリーと状態ストレージの配列 |

 実際には対数係数は小さいままであるため、これは 10^5 演算の一般的な制約内に問題なく適合します。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from math import *
    from collections import *
    
    # Fenwick + solution bundled
    input = sys.stdin.readline

    class Fenwick:
        def __init__(self, n):

            while i <= self.n:

            while i > 0:

    n, q = map(int, input().split())
    arr = list(map(int, input().split()))

    ft = Fenwick(n)
    state = [0] * (n + 1)

    for i in range(1, n + 1):
        state[i] = 1 if arr[i - 1] > 0 else 0
        ft.add(i, state[i])

    out = []
    for _ in range(q):
        t = input().split()
        if t[0] == '1':
            i = int(t[1]); x = int(t[2])
            ns = 1 if x > 0 else 0
            if ns != state[i]:
                ft.add(i, ns - state[i])
                state[i] = ns

            l = int(t[1]); r = int(t[2])
            cnt = ft.range_sum(l, r)
            out.append("1" if cnt % 2 else "-1")

    return "\n".join(out).strip()

 ## 特殊なケース

 次のような完全に空の範囲`[0, 0, 0]`アクティブなパイルはゼロになります。 このアルゴリズムはゼロの合計を正しく計算し、ゼロは偶数であるため、最初のプレーヤーが正当な手を持っていないという事実と一致して、2 番目のプレーヤーが勝つことを出力します。 

単一の空でないパイルは、単一の強制移動として動作します。 フェンウィック ツリーはカウント 1 を返しますが、これは奇妙です。したがって、最初のプレイヤーが勝ちます。これは、彼らがすぐにその山を空にし、それ以上手を残さないという事実と一致します。 

更新によってパイルが 0 と 0 以外の間で切り替わるシーケンスは、正しく処理されます。これは、更新ごとに、Fenwick 構造内でそのインデックスの寄与が正確に ±1 だけ変更され、後続のすべての範囲合計の正確さが維持されるためです。
