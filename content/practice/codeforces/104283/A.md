 ## 解決策
 ## 問題の理解

 複数の独立したクエリが与えられます。 各クエリは、次の閉じた数値間隔を定義します。`l`に`r`、次の 2 つのパラメータとともに、ターゲット桁の合計`x`そしてランク`k`。 その間隔内で、概念的に、桁の合計が正確に一致するすべての正の整数を調べます。`x`。 これらの数値を昇順にリストすると、タスクは`k`このフィルタリングされたリストの - 番目の要素。 未満の場合`k`そのような数字は存在します、答えは次のとおりです`-1`。 

重要な問題は、数値をフィルタリングすることではなく、それを迅速に行うことです。 の値`l`そして`r`十分に大きいため、範囲内のすべての整数を反復処理することは現実的ではありません。 たとえ 1 つのクエリで最大約 10^18 の値が許可されたとしても、それらを直接スキャンすると時間制限をはるかに超えてしまいます。 

桁合計制約により、間隔の長さに依存しない構造が導入されます。 問題は、各数値を個別に推論するのではなく、指定された範囲までに有効な数値がいくつ存在するかを数えることに帰着します。 「整数 ≤ n の桁の合計がちょうど x になる数」という形式のプレフィックス クエリに答えることができると、間隔バージョンは 2 つのプレフィックス カウントの差になります。 

素朴なアプローチでは、すべての数値を列挙します。`[l, r]`、桁の合計を計算し、有効なものを収集し、k 番目を選択します。 次の場合、これはすぐに失敗します。`r - l`大きいです。 たとえば、次の場合`l = 1`そして`r = 10^18`、1パスすら不可能です。 

メモ化を行わずに桁合計フィルタリングを実装する場合、より微妙な失敗例が発生します。 数値ごとの桁の合計の再計算は低コストですが、それでも範囲全体を反復処理する必要があります。 ボトルネックとなるのは番号ごとのコストではなく、番号の数です。 

本当のエッジケースは次のような場合です`k`は大きいですが、有効な数はまばらです。 たとえば、次のような範囲で`[10^17, 10^18]`次のような厳密な桁の合計制約を使用する`x = 1`、有効な数値は少数しかありません (10 の累乗など)。 リニアスキャンでは、答えに到達するまでにほぼ 1 兆回の無駄なチェックが行われることになります。 

## アプローチ

 ブルートフォースのアイデアは単純です。`l`に`r`、各数値の桁の合計を計算し、一致するものを保存します`x`、k番目の要素を返します。 これは、必要な順序を直接構築するため、正しいです。 ただし、実行します`O(r - l + 1)`クエリごとの反復回数が増加し、最悪の場合、これは実行可能な制限をはるかに超えます。 

重要な観察は、「桁の合計が x に等しい」という条件がプレフィックスに優しいということです。 スキャン間隔の代わりに、しきい値を下回る有効な数値がいくつあるかを数えることができます。`n`。 関数を定義すると`F(n, x)`の整数として`[0, n]`桁の合計が正確に`x`、次にカウント`[l, r]`になる`F(r, x) - F(l - 1, x)`。 

これにより、問題は桁をめぐる計数問題に変換されます。これはまさに桁動的計画法の設計対象です。 プレフィックス数を効率的に計算できるようになると、最小の数値を二分探索することで答えを見つけることができます。`y`で`[l, r]`有効な整数の数は次のようになります。`y`間隔内に達する`k`。 

この構造は、カウントするための数字 DP と、k 番目の要素を見つけるための二分探索になります。

 ## アルゴリズムのチュートリアル

 この問題を 2 つの概念レイヤーで解決します。有効な数値を限界までカウントし、そのカウント関数を使用して範囲内で k 番目の有効な数値を見つけます。 

### 1. 桁 DP カウント関数を構築する

 関数を定義します`count(n, x)`それは整数の個数を返します`[0, n]`桁の合計が正確に得られる`x`。 最上位から最下位まで数字を処理し、残りの合計とまだ接頭辞の境界にあるかどうかを追跡します。`n`。 

各桁位置で、現在の制限制約を超えないすべての可能な桁を試します。 それに応じて残りの合計を減らし、再帰的に続行します。 状態は、位置、残りの合計、および厳しい制約に関してメモ化されます。 

これが機能するのは、いかなる数値もその桁シーケンスによって一意に表現され、実現可能性は残りの桁合計容量のみに依存するためです。 

### 2. 範囲クエリをプレフィックス数に変換する

 クエリごとに、間隔内に有効な数値がいくつ存在するかを計算します。`[l, r]`使用:`total = count(r, x) − count(l − 1, x)`もし`total < k`、答えはすぐにわかります`-1`。 

このステップが機能するのは、数字 DP が累積カウントを示し、減算によって間隔が分離されるためです。 

### 3. k 番目の有効な数値の二分探索

 最小の数を探します`y`で`[l, r]`次のような:`count(y, x) − count(l − 1, x) ≥ k`この述語は単調です`y`なので、二分探索はきれいに適用されます。 条件が true になる最初の位置は、まさに k 番目の有効な数値です。 

### なぜ効果があるのか

 正しさは 2 つの単調な構造から得られます。 初め、`count(n, x)`は減少していない`n`より大きな上限を追加しても有効な数値は削除されないためです。 第二に、間隔に制限する`[l, r]`固定プレフィックスを差し引いた後も単調性を維持します`count(l - 1, x)`。 これにより、二分探索が常に k 番目の要素が出現する最初の有効なしきい値に収束することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from functools import lru_cache

def digit_dp(n, target_sum):
    s = str(n)

    @lru_cache(None)
    def dfs(pos, remaining, tight):
        if remaining < 0:
            return 0
        if pos == len(s):
            return 1 if remaining == 0 else 0

        limit = int(s[pos]) if tight else 9
        res = 0

        for d in range(limit + 1):
            res += dfs(pos + 1, remaining - d, tight and d == limit)

        return res

    return dfs(0, target_sum, True)

def count_upto(n, x):
    if n < 0:
        return 0
    return digit_dp(n, x)

def solve():
    t = int(input())
    for _ in range(t):
        l, r, k, x = map(int, input().split())

        base = count_upto(l - 1, x)
        total = count_upto(r, x) - base

        if total < k:
            print(-1)
            continue

        lo, hi = l, r
        ans = r

        while lo <= hi:
            mid = (lo + hi) // 2
            cur = count_upto(mid, x) - base

            if cur >= k:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```桁DP関数`digit_dp`有効な数値を境界までカウントする責任があります。 鍵の状態は、`(pos, remaining_sum, tight)`、 どこ`tight`のプレフィックスを超えないことを保証します`n`。 キャッシュがないと再帰によって同一の部分問題が指数関数的に何度も繰り返されるため、メモ化は不可欠です。 

機能`count_upto`この DP をラップし、エッジ ケースを処理します。`n < 0`、計算時に必要です`count(l - 1, x)`。 

メインループは、間隔内の有効な候補の数を計算し、次に二分探索を実行します。`[l, r]`。 二分検索内の述語は、プレフィックス ベースラインによってシフトされた同じカウント ロジックを再利用します。

 ## 特殊なケース

 厄介なケースが発生するのは、`l = 0`または`l = 1`、コンピューティング以来`count(l - 1, x)`取り扱いが必要です`-1`。 この実装では、負の入力に対して明示的にゼロを返し、接頭辞の減算が正しく動作することを保証します。 

もう一つの微妙なケースは次のような場合です。`x = 0`。 数字だけ`0`これを満たすため、ゼロを除く範囲はすぐに返される必要があります。`-1`。 DP は、数値の末尾の桁の合計の完全な消費のみを受け入れるため、これを正しく処理します。 

最後のエッジケースが現れるのは、`k`範囲内の有効な値の合計数と等しくなります。 その場合でも、二分探索は次のように収束する必要があります。`r`もし`r`それ自体は有効です。 単調述語により、off-by-one エラーなしで正しい境界が正しく選択されることが保証されます。
