 ## 解決策
 ## 問題の理解

 各テスト ケースには、基数と 2 つの指数パラメーターを表す 3 つの整数が与えられます。 評価する式は、同じ基数の累乗である 2 つの数値の最大公約数であり、指数は階乗です。 具体的に比較してみると、$n^{a!}$そして$n^{b!}$、GCD を取得し、結果のモジュロを出力します。$10^9+7$。 

式の構造は、数値の生のサイズよりも重要です。 中程度の値であっても、$a$そして$b$、階乗は非常に速く爆発するため、指数自体は天文学的に大きくなります。 これにより、明示的に計算しようとする試みが即座に排除されます。$a!$または$b!$偶数なので整数として$20!$すでに一般的な 64 ビットの制限を超えています。 

The input constraints imply multiple test cases, with values large enough that naive factorial computation or direct exponentiation would not fit in time. 明示的に構築しようとするアプローチ$n^{a!}$階乗増加を処理する前でさえ、べき乗だけではすでに遅すぎるため、これは不可能です。 

構造的に重要な特殊なケースがいくつかあります。 

いつ$n = 0$、指数が正である限り、両方の数値はゼロになります。 階乗は有効な入力に対して常に少なくとも 1 であるため ($0! = 1$)、両方の項は$0^{\text{positive}}$、これはゼロと評価されます。 ゼロとゼロの GCD はゼロです。 

いつ$n = 1$、指数のサイズに関係なく、両方の数値は常に 1 です。 結果は常に 1 です。 

誰かが直接法を使って階乗を計算しようとすると、微妙な失敗例が発生します。$10^9+7$。 指数の削減はモジュロで実行する必要があるため、情報が失われます。$10^9+6$、 ない$10^9+7$、フェルマーの定理による。 間違った係数を使用すると、まったく間違った検出力が得られます。 

別の故障モードは次の仮定から生じます。$\gcd(n^x, n^y) = n^{\gcd(x,y)}$。 それは間違いです。 正しい単純化では、指数の GCD ではなく、最小指数が使用されます。 

## アプローチ

 直接解釈すると計算されます$a!$そして$b!$、次に評価します$n^{a!}$そして$n^{b!}$、最後に GCD を計算します。 これは数学的には正しいですが、まったく実行不可能です。 階乗値を計算するだけでもすぐにオーバーフローしてしまい、制限時間内にそのような指数を使って累乗することは不可能です。 

重要な観察は、両方の数値が同じ基数を共有していることです。$n$。 ゼロ以外の場合$n$、同じ基数のべき乗は、2 つのべき乗の GCD が小さい方の指数のべき乗であるという単純な特性を満たします。 これにより、問題全体はどの階乗が小さいかを理解することに帰着します。 階乗は非負の整数に対して厳密に増加するため、比較すると$a!$そして$b!$比較するのと同じです$a$そして$b$。 したがって、最終的な答えの指数は次のようになります。$\min(a, b)!$。 

残りの課題は、$(\min(a,b))!$まだ巨大です。 必要なのは指数モジュロだけです$10^9+6$、弾性率$10^9+7$が素数であり、次の場合にフェルマーの定理による指数換算が可能になります。$n \not\equiv 0 \pmod{10^9+7}$。 

したがって、問題は、指数のモジュラー階乗を計算し、次に単一のべき乗モジュラーを実行することに帰着します。

 ## アルゴリズムのチュートリアル

 問題を次のモジュール累乗の計算に書き換えます。$n$ここで、指数はより小さい階乗に依存します。 

### ステップ

 1.読む$a, b, n$そして決定します$k = \min(a, b)$。 

これが機能するのは、階乗が順序を厳密に保持するためです。そのため、基数が小さくなると階乗も小さくなります。 
2. 些細な塩基はすぐに処理します。 

もし$n = 0$、両方の数値がゼロであるため、GCD はゼロになります。 

もし$n = 1$、どの力も 1 のままなので、答えは 1 つです。 
3. コンピューティング$k!$ただしモジュロのみ$10^9+6$、モジュロではありません$10^9+7$。 

これが必要なのは、素数モジュラスでのべき乗により指数モジュロの削減が可能になるためです。$\varphi(M)$。 
4. コンピューティング$e = k! \bmod (10^9+6)$。 

これを各ステップで乗算と減算を繰り返して実行します。 
5. 最終結果を次のように計算します。$n^e \bmod (10^9+7)$高速累乗を使用します。 

### なぜ効果があるのか

 表現$\gcd(n^{a!}, n^{b!})$両方の数値が同じ底のべき乗であるため、単純化されます。 一方のべき乗をもう一方のべき乗で割る唯一の方法は指数を減らすことなので、共通のべき乗は小さい方の指数によって制限されなければなりません。 これにより、$n^{\min(a!, b!)}$。 階乗関数は整数に対して厳密に増加するため、$\min(a!, b!) = (\min(a,b))!$。 素数法でのべき乗は指数法にのみ依存するため、指数のモジュラー約分は有効です。$10^9+6$ただし、底が係数で割り切れない場合に限ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
PHI = MOD - 1

def modexp(a, e):
    res = 1
    a %= MOD
    while e > 0:
        if e & 1:
            res = (res * a) % MOD
        a = (a * a) % MOD
        e >>= 1
    return res

t = int(input())
for _ in range(t):
    a, b, n = map(int, input().split())
    
    k = min(a, b)
    
    if n == 0:
        print(0)
        continue
    if n == 1:
        print(1)
        continue
    
    fact = 1
    for i in range(1, k + 1):
        fact = (fact * i) % PHI
    
    print(modexp(n, fact))
```コードはまず、問題の構造を単一の指数の計算に還元します。 階乗は係数に基づいて計算されます$10^9+6$を使用するため、これは非常に重要です。$10^9+7$指数演算が誤って歪められる可能性があります。 べき乗モジュラールーチンは標準の 2 進累乗であり、指数の対数時間を保証します。 

特殊なケース$n = 0$そして$n = 1$未定義の動作や不必要な計算を防ぎます。 特に、$0^e$正の場合は常にゼロです$e$、階乗は陽性を保証します。

## テストケース```python
import sys, io

MOD = 10**9 + 7

def solve():
    input = sys.stdin.readline
    MOD = 10**9 + 7
    PHI = MOD - 1

    def modexp(a, e):
        res = 1
        a %= MOD
        while e:
            if e & 1:
                res = res * a % MOD
            a = a * a % MOD
            e >>= 1
        return res

    t = int(input())
    for _ in range(t):
        a, b, n = map(int, input().split())
        k = min(a, b)

        if n == 0:
            print(0)
            continue
        if n == 1:
            print(1)
            continue

        fact = 1
        for i in range(1, k + 1):
            fact = fact * i % PHI

        print(modexp(n, fact))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from io import StringIO
    old_stdout = sys.stdout
    sys.stdout = StringIO()
    solve()
    out = sys.stdout.getvalue()
    sys.stdout = old_stdout
    return out.strip()

# provided samples (interpreted cleanly)
assert run("2\n1 3 1\n1 5 2\n") == "1\n2"
assert run("1\n2 2 3\n") == "9"

# custom cases
assert run("1\n0 5 7\n") == "0"
assert run("1\n1 100 999\n") == "1"
assert run("1\n3 3 2\n") == "4"
assert run("1\n4 2 10\n") == "100000"  # 10^2! = 10^2 = 100

 | --- | --- | --- |
 | 0 5 7 | 0 | ゼロベースの動作 |
 | 1 100 999 | 1 | 単一不変性 |
 | 3 3 2 | 4 | 等しい階乗 |

 ## 特殊なケース

 いつ$n = 0$、指数のサイズに関係なく、両方のべき乗はゼロになります。 アルゴリズムは階乗計算の前にこれを明示的にチェックするため、不必要な作業が回避され、正確にゼロが返されます。 

いつ$n = 1$、すべての累乗が 1 に等しいため、指数のサイズは無関係になります。 早期リターンにより階乗計算が防止され、大規模な計算であっても正確性が保証されます。$a, b$。 

いつ$a = b$の場合、アルゴリズムは両方の式を正しく同じ累乗するため、GCD は値自体と等しくなります。 階乗計算は引き続き実行されますが、両方のパスが収束するため、正確さには影響しません。 

いつ$a$または$b$ゼロです、$0! = 1$したがって、指数は常に少なくとも 1 になります。 階乗は 1 から始まり、決して 0 を生成しないため、アルゴリズムはこれを自然に処理します。
