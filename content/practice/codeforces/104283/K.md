 ## 解決策
 ## 問題の理解

 原点から始まる整数格子点上を歩いています。 目的地は固定点です$(R_x, R_y)$。 各ステップで、移動ルールにより、位置をさまざまな方向にシフトできるいくつかのローカル遷移が許可されますが、第 1 象限に留まるように制約され、同じグリッド ポイントを複数回訪問することはできません。 

タスクは、次の場所から有効なパスがいくつ存在するかを数えることです。$(0,0)$に$(R_x, R_y)$ここで、各パスは、境界制限を尊重し、座標の再訪を回避する一連の許可された移動です。 

入力は複数のテスト ケースを与え、それぞれがターゲット座標を指定します。 それぞれについて、個別の有効なパスの数を法的に出力する必要があります。$10^9+7$。 

複雑さの観点から見ると、テスト ケースの数は膨大です。$5 \cdot 10^4$、座標も大きくなる可能性があります。 これにより、パスを明示的に構築または探索しようとするソリューションは即座に除外されます。これは、中程度の分岐でも指数関数的に爆発的に増加するためです。 有効な解決策は、理想的には、問題を閉じた形式の式またはテスト ケースごとの直接の組み合わせ計算に削減する必要があります。$O(1)$または$O(\log n)$。 

この種の問題における微妙な問題は、「座標を再訪しない」という制約によって構造の単純化が隠れてしまうことがよくあることです。 単純な解釈ではグラフを任意のものとして扱いますが、実際には、許可される移動ルールは、到達可能な状態空間が状態の単調な順序付けで実質的に非循環になるような方法で象限制限と相互作用します。 これを無視して一般的なグラフ検索を実行すると、アルゴリズムはサイクルによりオーバーカウントするか、タイムアウトになります。 

エッジ ケースは、1 つの座標がゼロの場合に発生します。 たとえば、到達する$(0, k)$または$(k, 0)$多くの場合、動きのオプションが大幅に崩壊し、すべての方向が利用可能であると仮定する単純な再帰は、境界遷移が一貫して処理されない限り対称性を破り、不正確なカウントを生成します。 

## アプローチ

 ブルートフォースアプローチでは、各座標がノードであり、エッジが許可された動きに対応するグラフとしてグリッドを扱います。 次から DFS を実行できます。$(0,0)$、訪問したノードをマークし、到達したすべてのパスをカウントします。$(R_x, R_y)$。 訪問されたセットは再訪問禁止制約を強制するため、これは概念的には単純で正しいものです。 

ただし、分岐係数は各ステップで最大 5 であり、到達可能な状態の数は両方の座標で増加します。 中程度のターゲットであっても、サイクルのある有向グリッド内の単純なパスの数は天文学的に多くなります。 最悪の場合の複雑さは指数関数的に増加します$R_x + R_y$、これは与えられた制約の下では実行不可能です。 

重要な洞察は、複数の動作方向が存在するにもかかわらず、象限制限と動作の構造の組み合わせにより、隠れた単調な順序付けが課されるということです。 すべての有効なパスは、一連の「効果的な東」と「北」の寄与として一意に解釈でき、最終的な効果は、水平方向と垂直方向の進歩がいつ起こるかを選択することと同等です。 追加の動きによって、個別のエンドポイントに関して新しい組み合わせの自由が導入されるわけではありません。 代わりに、基礎となる格子カウント構造を変更せずに、中間ジオメトリのみを再形成します。 

この減少が認識されると、問題は崩壊し、からの単調パスを数えることになります。$(0,0)$に$(R_x,R_y)$ユニット右とユニットアップステップのみを使用します。 すべての有効なパスは、次のいずれかの選択に対応します。$R_x + R_y$合計ステップは垂直 (または水平) であり、二項係数に直接つながります。

 ## アルゴリズムのチュートリアル

 ### ステップ 1: パス構造を解釈する

 私たちは、すべての有効な動作シーケンスを、目標に向かう単位の水平方向と垂直方向の進行の組み合わせとして再解釈します。 重要な観察は、複数の移動タイプにもかかわらず、到達するには正味の変位のみが重要であるということです。$(R_x, R_y)$、すべての有効なパスは同じ総変位制約を引き起こします。 

### ステップ 2: 単調なグリッド ウォークに減らす

 問題を、正確に次のシーケンスを選択するものとして扱います。$R_x$水平移動と$R_y$垂直方向の動き。 有効なパスはすべて、これらの動きの順序に対応します。 この単調な解釈では、座標は循環を形成せずに厳密にターゲットに向かって進むため、再訪問禁止制約は自然に満たされます。 

### ステップ 3: ステップの並べ替えをカウントする

 の異なるシーケンスの数$R_x + R_y$を含むステップ$R_x$同じ水平移動と$R_y$同じ垂直方向の動きは次のとおりです。$$\binom{R_x + R_y}{R_x}$$これはモジュロで計算されます$10^9+7$。 

### ステップ 4: 階乗を事前計算する

 まであるので、$5 \cdot 10^4$クエリと潜在的に大きな座標の場合、すべてのクエリにわたる最大座標合計まで階乗とモジュラー逆数を事前計算します。 

### ステップ 5: O(1) の各クエリに答える

 各テスト ケースは、単一のモジュラー二項係数評価を使用して回答されます。 

### なぜ効果があるのか

 すべての有効なパスは正確に作成されるように強制されます$R_x$正味の水平方向の進歩と$R_y$正味の垂直方向の進歩。 元の移動セットでは迂回が許可されていますが、ポイントを再度訪問することなくターゲットに到達するには、そのような迂回は最終的にキャンセルされる必要があるため、追加の個別のエンドポイントに相当するパスのクラスは作成されません。 これにより、有効なパスと以下を含むマルチセットの順列の間の全単射が確立されます。$R_x$水平と$R_y$垂直ステップ。これにより、二項係数式の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def modinv(x):
    return pow(x, MOD - 2, MOD)

def main():
    data = sys.stdin.read().strip().split()
    t = int(data[0])
    pairs = []
    max_n = 0
    
    idx = 1
    for _ in range(t):
        rx = int(data[idx]); ry = int(data[idx+1])
        idx += 2
        pairs.append((rx, ry))
        max_n = max(max_n, rx + ry)
    
    fact = [1] * (max_n + 1)
    invfact = [1] * (max_n + 1)
    
    for i in range(2, max_n + 1):
        fact[i] = fact[i - 1] * i % MOD
    
    invfact[max_n] = modinv(fact[max_n])
    for i in range(max_n, 0, -1):
        invfact[i - 1] = invfact[i] * i % MOD
    
    def ncr(n, r):
        if r < 0 or r > n:
            return 0
        return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD
    
    out = []
    for rx, ry in pairs:
        out.append(str(ncr(rx + ry, rx)))
    
    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装では、階乗および逆階乗を必要な最大値まで事前計算します。$R_x + R_y$。 次に、各クエリは標準モジュラー恒等式を使用して単一の二項係数を評価します。 

一般的な実装の落とし穴は、テスト ケースごとに階乗を再計算することです。これにより、複雑さが増大します。$O(T \cdot N)$。 もう 1 つの微妙な問題は、逆階乗は、値ごとに独立してモジュラー逆数を計算するのではなく、最大の階乗の単一のモジュラー逆数を使用して構築し、下方に伝播する必要があることを忘れていることです。

 ## 特殊なケース

 重要なエッジ ケースは、次のような 1 つの座標がゼロの場合です。$(0, k)$。 この状況では、二項式は次のようになります。$\binom{k}{0} = 1$、単調なパスが 1 つだけ存在することを意味します。 これは、動きが完全に 1 つの軸に沿って強制されるという直観と一致します。 

別のエッジケースが原点です$(0,0)$、移動が必要ない場所。 式は次のようになります。$\binom{0}{0} = 1$、空のパスを有効なソリューションとして正しくカウントします。 

最後に、両方の座標が大きい場合、階乗事前計算により、オーバーフローや再計算の問題が発生せず、すべてのクエリが独立した定数時間評価のままになります。
