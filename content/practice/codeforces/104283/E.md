 ## 解決策
 ## 問題の理解

 すべてのノードに値が格納されるツリーが与えられます。 ツリー構造は変わりませんが、ノード値は変わります。 2 種類の操作に答える必要があります。単一ノードに格納されている値を更新することができ、もう 1 つはサブツリーをクエリして、そのサブツリー内のすべてのノードの中で現在存在する最大値を見つけることができます。 

唯一の構造上の約束は、グラフがツリーであるため、任意の 2 つのノード間にはパスが 1 つだけ存在し、エッジの総数は n マイナス 1 であるということです。 隠された重要な詳細は、「v のサブツリー」はツリーのルートの選択に依存するということです。そのため、ノード 1 をルートとして固定すると (これがこのような問題の標準的な解釈です)、すべてのノードは、それ自体とそのルート付きツリー内のすべての子孫で構成される明確に定義されたサブツリーを持つことになります。 

制約はテスト ケースごとに最大 2×10^5 ノード、テスト ケースごとに最大 10^4 まであり、素朴な方法でクエリごとにサブツリーに触れるソリューションは直ちに除外されます。 クエリごとの直接トラバーサルはクエリごとに O(n) に低下し、最悪のケースではテスト ケースごとに O(n^2) になります。 複数のテスト ケースを使用すると、これは実現可能な限界をはるかに超えます。 サブツリー クエリとポイント更新が両方とも対数またはそれに近い構造が必要です。 

ツリーがチェーンの場合、微妙なエッジケースが現れます。 その場合、サブツリーはノードのサフィックスに縮退する可能性があります。 クエリごとの単純な DFS では、長いパスを繰り返したどることになります。 もう 1 つの特殊なケースは、同じノード上で更新が繰り返され、その後にクエリが実行される場合です。この場合、単純なソリューションでは、結果が正しくキャッシュされなかった場合、中間更新が正しく反映されずにサブツリー値が再計算される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。タイプ 2 のクエリごとに、クエリされたノードから DFS を実行し、そのサブツリー内のすべてのノードをスキャンして、最大値を追跡します。 更新クエリの場合は、新しい値をノードに割り当てるだけです。 これは、サブツリー最大値の定義に直接従うため、正しいです。 

ただし、コストが問題です。 n 個のノードを持つツリーでは、サブツリーに O(n) 個のノードを含めることができます。 すべてのクエリに対して完全な DFS を実行し、q 個のクエリがある場合、総コストは O(nq) になります。 n と q がどちらも大きい可能性があるため、これは容易に 10^10 演算に達してしまい、実行不可能です。 

重要な観察は、ツリーを線形化するとサブツリー クエリが範囲クエリになるということです。 DFS 順序トラバーサルを実行し、各ノードにエントリ時間 tin[u] を割り当てる場合、u のサブツリーはこの順序付けの連続セグメントになります。 u のサブツリー内のすべてのノードは、連続した間隔 [tin[u], tout[u]] に現れます。 これにより、問題は、ポイント更新および範囲最大クエリの下で値の配列を維持することに変わります。 

問題が動的更新と範囲最大クエリを伴う静的配列になると、セグメント ツリーまたはフェンウィック ツリーのバリアントが自然に適合します。 最大のクエリが必要なため、セグメント ツリーが標準的な選択になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとのブルート フォース DFS | クエリあたり O(n)、合計 O(nq) | O(n) | 遅すぎる |
 | オイラー ツアー + セグメント ツリー | 更新/クエリごとに O(log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 DFS 順序付けを使用してツリーを配列表現に変換し、各サブツリーが連続セグメントになるようにします。 次に、更新と範囲最大クエリをサポートするために、この配列にセグメント ツリーを構築します。

1. 任意のルート (通常はノード 1) を選択し、DFS トラバーサルを実行して、各ノードにフラット化された配列内の位置を割り当てます。 各ノードは、最初にアクセスされたときにエントリ時間を取得します。 これにより、サブツリー内のすべてのノードが連続したセグメントを占有するようになります。 
2. DFS 中に、各サブツリーのサイズまたは終了時間も計算します。 ノード u のサブツリーは、オイラー順序付けの tin[u] から tout[u] までのセグメントに対応します。 このプロパティにより、サブツリー クエリを範囲クエリにすることができます。 
3. A[tin[u]] がノード u の値と等しくなるように配列 A を構築します。 この配列はツリーを線形形式で表します。 
4. A に対してセグメント ツリーを構築します。各セグメント ツリー ノードには、その範囲内の最大値が格納されます。 これにより、範囲最大クエリに対数時間で答えることができます。 
5. 更新クエリ「ノード u を x に設定」の場合、配列内のその位置 tin[u] を特定し、そのインデックスでセグメント ツリーを更新します。 
6. クエリ「v のサブツリーの最大値」の場合、セグメント [tin[v], tout[v]] を計算し、その区間内の最大値をセグメント ツリーにクエリします。 

これが機能する理由は、オイラー ツアー プロパティから次のとおりです。DFS では、サブツリーに入ると、戻る前にサブツリーを完全に横断するため、すべての子孫が連続した間隔にグループ化されます。 セグメント ツリーは、更新とクエリの両方でこれらの間隔にわたって正しい最大値を維持し、すべての操作後の正確さを維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.seg = [0] * (2 * self.size)
        for i in range(self.n):
            self.seg[self.size + i] = arr[i]
        for i in range(self.size - 1, 0, -1):
            self.seg[i] = max(self.seg[2 * i], self.seg[2 * i + 1])

    def update(self, idx, val):
        i = self.size + idx
        self.seg[i] = val
        i //= 2
        while i:
            self.seg[i] = max(self.seg[2 * i], self.seg[2 * i + 1])
            i //= 2

    def query(self, l, r):
        l += self.size
        r += self.size
        res = -10**18
        while l <= r:
            if l % 2 == 1:
                res = max(res, self.seg[l])
                l += 1
            if r % 2 == 0:
                res = max(res, self.seg[r])
                r -= 1
            l //= 2
            r //= 2
        return res

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        g = [[] for _ in range(n + 1)]

        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        values = list(map(int, input().split()))

        tin = [0] * (n + 1)
        tout = [0] * (n + 1)
        arr = [0] * n
        timer = 0

        stack = [(1, 0, 0)]
        while stack:
            u, p, state = stack.pop()
            if state == 0:
                tin[u] = timer
                arr[timer] = values[u - 1]
                timer += 1
                stack.append((u, p, 1))
                for v in g[u]:
                    if v != p:
                        stack.append((v, u, 0))
            else:
                tout[u] = timer - 1

        st = SegTree(arr)

        q = int(input())
        for _ in range(q):
            tmp = input().split()
            if tmp[0] == '1':
                u = int(tmp[1])
                x = int(tmp[2])
                st.update(tin[u], x)
            else:
                v = int(tmp[1])
                print(st.query(tin[v], tout[v]))

if __name__ == "__main__":
    solve()
```DFS は再帰の深さの問題を回避するために反復的に実装されます。 各ノードには、セグメント ツリーの位置に直接マッピングされる検出インデックスが割り当てられます。 セグメント ツリーはテスト ケースごとに 1 回構築され、操作ごとに更新されます。 重要な点は、tout[u] をサブツリー範囲内の最後のインデックスとして格納し、クエリが包括的であることを保証することです。 

更新操作はセグメント ツリー内の 1 つのリーフのみに触れ、上位に向かって祖先を再計算します。 クエリ操作は範囲を O(log n) セグメントに分割し、それぞれが最大候補を提供します。

 ### 例 1

 4 つのノードからなる単純なツリーを考えます。1 は 2 と 3 に接続され、3 は 4 に接続されます。ノードの値は [5, 1, 7, 3] です。 3 のサブツリーをクエリし、ノード 4 を 10 に更新して、再度クエリを実行するとします。 

| ステップ | 操作 | 錫/客引き関連 | セグメント値 | 答え |

 | 2 | 更新(4=10) | 4 でポイント更新 | [7,10] | - |

 これは、更新がセグメント ツリーを通じて将来のサブツリー クエリにどのように即座に影響するかを示しています。

 ## 特殊なケース

 単一ノード ツリーは、tin と tout の両方がゼロに崩壊する最も単純なケースです。 アルゴリズムは arr[0] を正しく割り当て、セグメント ツリー クエリは範囲を複雑にすることなくノード値を直接返します。 

1-2-3-4-5 のような偏ったツリーでは、サブツリー クエリは長く連続した範囲になります。 オイラー ツアーでは、チェーン全体が確実に順番に保存されるため、サブツリーのクエリはセグメント ツリーの間隔まで短縮されます。 内部ノードでの更新は O(log n) セグメント ツリー ノードのみを介して正しく伝播され、構造上の仮定が崩れることはありません。 

すべての値が同一の場合、セグメント ツリーは最大値を決定的に再計算するため、更新を繰り返しても正確さに影響しません。 各セグメントがその範囲の最大値を格納するという不変式は、値が変更されていない場合でも安定したままになります。 

扱いにくいケースは、DFS 順序の最後のノードでもあるリーフ ノードを更新する場合です。 その場合、tin[u] は配列内の最後のインデックスと等しくなります。 セグメント ツリーの更新は最後のリーフにのみ適用され、上向きに正しく伝播されます。また、tout は排他的ではなく包含的なインデックスとして定義されているため、off-by-one エラーは発生しません。
