 ## 問題の理解

 私たちは1から1までの番号が付けられた家が長く並んでいる中で、一番左の家に立っています。$n$。 私たちは正確に実行しなければなりません$k$移動するたびに、現在の家から別の家にジャンプすることになります。 すべてのジャンプは、ハウス インデックスの絶対差に等しいコストに寄与し、すべての移動の合計コストは正確に一致する必要があります。$s$。 

タスクは、最短経路を見つけたり、距離を最大化することではありません。 代わりに、次のシーケンスを構築する必要があります。$k$連続する位置が異なり、累積移動距離の合計が一致するように訪問した家$s$。 私たちは家を再訪問することが許されているので、単純な道ではなく散歩のような構造になっていますが、その場にとどまることはできません。 

主な難点は、シーケンスの長さが固定されており、各ステップが次の範囲で負ではない量を寄与することです。$1$に$n-1$。 これにより、制約された構成の問題が発生します。つまり、正確に合計しています。$k$絶対的な差。それぞれは位置を選択することによって間接的に選択されます。 

制約はすでに貪欲または建設的な解決策を示唆しています。 の値$n$非常に大きくなる可能性があります$10^9$したがって、ハウスの反復処理に依存するアプローチは不可能です。 移動回数$k$までです$2 \cdot 10^5$、直線的な構築が可能になります。 総距離$s$と同じ大きさにすることができます$10^{18}$これにより、ステップごとの検索や距離を超えた DP が即座に除外されます。 

単純なアプローチでは、考えられるすべての長さのシーケンスをシミュレートしようとします。$k$おそらく、位置と残りの距離によって定義された状態にわたるバックトラッキングまたは BFS を介して。 状態空間が次のようなものであるため、これはすぐに失敗します。$O(nk)$原則として、距離は最大で連続しているため、位置を制限しても役に立ちません。$n$。 

同等性を計画せずに、貪欲な「常に極端に進む」戦略を試みると、さらに微妙な問題が発生します。 たとえば、1 と 2 の間を繰り返し往復すると、$n$移動ごとの距離を最大化しますが、すべての中間合計が達成可能であることを保証するものではありません。 すべての手がプラスであるため、オーバーシュートが回復できない貪欲な戦略。 

## アプローチ

 ブルートフォースビューでは、各移動を次の家を選択し、距離を蓄積するものとして扱います。 開始位置から、可能なすべての次の家に分岐し、次の位置まで再帰的に続行します。$k$ステップが選択されます。 これは、すべての有効なシーケンスを列挙するため正しいですが、分岐要素は次のとおりです。$n-1$、深さは$k$、指数関数的な複雑さにつながります。 残りの距離による枝刈りでも、依然として多くの状態が残ります。$s$大きくて連続的です。 

重要な観察は、問題は個々の位置ではなく、それぞれの動きがどれだけの距離に寄与するかであるということです。 可能な単一の移動の最大値は次のとおりです。$n-1$、エンドポイント間をジャンプすることで達成されます。 これは、ほとんどの動きは最大のジャンプである必要があり、合計を微調整するために調整が必要なのは少数の動きだけであることを示唆しています。 

2 つの極端な値の間を繰り返し往復して大きな寄与を生成し、次にいくつかのステップを調整して、制御された小さな量だけ合計を増減するシーケンスを構築することを考えることができます。 それぞれの動きは絶対的な差として独立して寄与するため、左から右へ貪欲に動きを設計して、ターゲットの下または上で動けなくなることがないようにすることができます。 

最終的な構築は、隣接制約を破ることなく、最大ジャンプを小さな迂回路に分割することで常に最大ジャンプを削減できるという考えに基づいています。

 ## アルゴリズムのチュートリアル

 ハウス 1 から開始して、段階的にシーケンスを構築します。 

1. 移動ごとに可能な最大貢献度を計算します。これは、$n-1$。 もし$s > k \cdot (n-1)$、可能な限り最大のジャンプでもターゲットに到達できないため、解決策はありません。 これにより、即時不可能な状態が生じます。 
2.現在位置を1に初期化し、残り距離を把握する$rem = s$。 
3. それぞれについて$k$貪欲に次のポジションを決めていきます。 各ステップで、残りの移動で残りの距離を完了することを妨げない、可能な限り最大のジャンプを使用しようとします。 これは、次のことを保証することを意味します。$$rem - (n-1) \cdot (k - i - 1) \le \text{chosen move distance} \le n-1$$この制約により、将来のステップの実行可能性が保証されます。 
4. 選択した距離を実現するために、適切な方向で可能な限り遠い家を選択します。 現在の位置にいる場合$x$、1 または$n$。 将来の最大拠出額を考慮した上で、必要な残額を達成できるエンドポイントを選択します。 
5. 次の位置を選択した後、残りの距離を更新して続行します。 

中心的なアイデアは、柔軟性を最大化するために極端な位置を活用しながら、残りのターゲットの到達可能な範囲内に常に留まるということです。 

### なぜ効果があるのか

 この構造では、現在の予算から必要以上に支出することがないため、各移動の後、残りの移動回数を使用して残りの距離を達成できるという不変条件が維持されます。$n-1$動きごとに。 各ステップで残りの合計が実行可能な範囲内に収まるため、行き止まりに到達することはありません。 エンドポイントはユニバーサル調整ポイントとして機能し、必要に応じて方向を切り替えることで、必要なすべての違いを実現できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k, s = map(int, input().split())

    if s < k or s > k * (n - 1):
        print("NO")
        return

    print("YES")

    cur = 1
    rem = s
    res = []

    for i in range(k):
        left_moves = k - i - 1

        # We choose next position among [1, n]
        # Try both endpoints and pick a valid one
        # that keeps feasibility for remaining steps

        # candidate 1: go to 1
        d1 = abs(cur - 1)
        if rem - d1 <= left_moves * (n - 1) and rem - d1 >= left_moves:
            res.append(1)
            rem -= d1
            cur = 1
            continue

        # candidate 2: go to n
        d2 = abs(cur - n)
        res.append(n)
        rem -= d2
        cur = n

    print(*res)

if __name__ == "__main__":
    solve()
```実装では、各ステップで貪欲な実現可能性チェックが維持されます。 重要な部分は、移動を選択した後の残りの合計が、可能な最小残り距離 (すべてのステップが少なくとも 1 ずつ移動) と最大可能残り距離 (すべてのステップが 1 ずつ移動) の間にあることを確認することです。$n-1$）。 

最初にハウス 1 を試してからハウスに戻るという決定$n$任意です。 両方のエンドポイントは対称であり、少なくとも 1 つの選択肢が機能することが実現可能性によって保証されます。 のアップデート`rem`残りの予算を正確に追跡できるようにするとともに、`cur`絶対差を計算するために必要な現在位置を追跡します。 

よくある間違いは、下限制約を忘れることです$rem \ge left\_moves$、残りの各移動が少なくとも 1 単位の距離に貢献する必要があることを強制します。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$s$まさに可能な最小値です$k$。 これにより、すべての移動が正確に 1 単位の距離に貢献することになります。つまり、隣接する家の間を交互に移動する必要があります。 実行可能性チェックでは残りのステップごとに少なくとも 1 つのユニットを保持する動きの選択を強制し、将来の柔軟性を低下させるジャンプを防ぐため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジケースは次のような場合です$s = k \cdot (n-1)$ここで、すべての移動はエンドポイント間の全長ジャンプでなければなりません。 この場合、構築は 1 と の間で決定論的に交互に行われます。$n$。 どのステップでも削減は必要ないため、貪欲な選択は常に有効です。 

3 番目の微妙なケースは次の場合に発生します。$n=2$。 すべての動きは正確に 1 に寄与するように強制されます。アルゴリズムは 1 と 2 の間の単純な交互に縮小され、実現可能範囲は曖昧さのない単一の有効なシーケンスに集約されます。
