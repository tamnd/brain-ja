 ## 解決策
 ## 問題の理解

 グリッドには、塗りつぶされたセルと空のセルの 2 種類のセルが含まれています。 星と呼ばれる幾何学的なオブジェクトを配置することができます。各星は、中央の 1 つの塗りつぶされたセルと、4 つの基本方向に伸びる 4 本の直線のアームで構成されます。 4 つのアームはすべて同じ長さでなければならず、その長さは少なくとも 1 つである必要があります。 サイズのあるスター`s`したがって、正確に中央のセルに加えて占有します`s`同じ行と列に沿った各方向のセル。 

課題は、グリッド内の塗りつぶされたセルのセット全体が、グリッド内の任意の場所に配置されたそのような星の集合の結合として説明できるかどうかを判断することです。 スターは任意に重なり合うことができるため、唯一の要件は、入力内のすべての塗りつぶされたセルが少なくとも 1 つのスターで覆われ、スターがグリッドの外側にはみ出さないことです。 

出力を最小化する必要はありません。 有効な分解は最大でも`n·m`星は許容されます。 

制約`n, m ≤ 1000`最大 100 万個のセルを意味します。 これにより、4 方向に繰り返しスキャンして、すべての中心からすべての可能性のある星を明示的にテストしようとするソリューションは即座に除外されます。 すべてのサイズのすべての星を単純に列挙すると、最悪の場合には 3 次の動作に達してしまいますが、これは受け入れられません。 

さらに微妙な問題は、星が重なり合う可能性があり、局所構造間の通常の独立性が失われることです。 可能な最大アーム長を理解せずに早めにコミットする貪欲な配置は、簡単に失敗する可能性があります。 

典型的な失敗例の 1 つは、複数の星がアームを共有する場合です。```
..*..
.***.
*****
.***.
..*..
```各中心にサイズ 1 の星だけを貪欲に配置すると、問題を最小化する必要がないにもかかわらず、表現の複雑さを軽減できる大きな構造を捉えることができなくなります。 本当の問題は最適化ではなく、正確さです。必要なすべてのセルが何らかの有効なスター構成に属し、各スターが完全なアームと内部的に一貫していることを確認する必要があります。 

星の中心は存在するが、1 つの方向が壊れている場合、別の特殊なケースが発生します。```
..*..
.**..
*****
.....
.....
```ここでは中心は存在しますが、上向きの腕が欠けているため、たとえ局所的な密度が高く見えても、その中心では有効な星は形成されません。 

これらの例は、正確さが候補中心の周りの完全な対称アーム構造の検証に依存することを示しています。 

## アプローチ

 強引なアイデアは、すべてを処理することです。`'*'`細胞を潜在的な中心として、腕を外側の四方向すべてに伸ばしてみてください。 各中心について、一方向が壊れるまでサイズの増加を試みます。 これにより、その中心の星の最大サイズが得られます。 1 つのセンターをチェックするのにかかるコストは、`O(min(n, m))`、そして、あります`O(nm)`中心となるため、全体の複雑さは次のようになります。`O(nm·min(n, m))`、約に達します`10^9`最悪の場合の運用。 これでは遅すぎます。 

重要な所見は、グリッドはばらばらの構造によって説明される必要がないということです。 代わりに、カバレッジを確保することだけが必要です。 これにより、可能な最大の有効な中心から下に向かって貪欲に星を構築することができます。 

各セルについて、事前に計算された連続する星の数を使用して、可能な最大の星のサイズを計算できます。`'*'`4方向のセル。 セルにアーム長がある場合`k`、その場合、それはさまざまなサイズの星の中心になることができます`1`を通して`k`。 そのような中心をすべて特定したら、すべての極大星 (有効な最大サイズを持つ星) を取得することができ、これらの大きな星はすでにグリッドの大部分をカバーしています。 覆われていない残りの部分`'*'`細胞は小さな星の中心か、すでに大きな星に覆われている腕の一部でなければなりません。 

これは当然、可能な最大サイズの星をすべての有効な中心に貪欲に配置し、残りの構造をカバーするために重なりに依存する構造につながります。 

左、右、上、下の 4 つの DP 配列を事前計算します。各エントリには連続したデータが格納されます。`'*'`カウントします。 これにより、次のようにセルごとの最大星のサイズを定数時間で計算できます。```
size = min(up, down, left, right) - 1
```この値が正の場合、セルはスターをホストできます。 

すべての星を生成した後、それらの範囲を別のグリッドにマークします。 もしあれば`'*'`カバーされていないままの場合、構成は無効です。

 | ブルートフォース | O(nm・min(n,m)) | お(1) | 遅すぎる |
 | 最適 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 方向性のある前処理と貪欲な配置を使用して、構造化された方法でソリューションを構築します。 

1. 4 つの補助グリッドを計算する`up`、`down`、`left`、 そして`right`。 各セルには連続した回数が格納されます。`'*'`セルはそれ自体を含めて、そこからその方向に伸びます。 これにより、グリッドを再スキャンすることなく、ローカルアームの容量を知ることができます。 
2. すべてのセルについて`(i, j)`含まれている`'*'`、星の可能な最大サイズを次のように計算します。`k = min(up[i][j], down[i][j], left[i][j], right[i][j]) - 1`。 減算により、腕の長さの制約から中央のセルが削除されます。 
3. もし`k > 0`を中心に星を記録します。`(i, j)`サイズ付き`k`。 これは、その位置に固定されている最大の有効な星を表します。 
4. 最初はすべて false のブール値カバレッジ グリッドを維持します。 記録された各星について、その星がカバーするすべてのセル (中心とそのサイズまでの 4 本の腕すべて) にマークを付けます。 単一の星では説明できない場合でも、重なり合う星が集合的にグリッドを説明できるため、このステップは不可欠です。 
5. すべての最大の星を配置した後、グリッドをスキャンします。 もしあれば`'*'`セルがカバーされていないため、回答は不可能です。 
6. 記録されたすべての星を出力します。 

重要な考え方は、有効なスター中心に寄与する可能性のあるすべてのセルが最初に最大化されるということです。 存在する可能性のある小さな星は、これらの極大構造とのオーバーラップを通じて暗黙的に処理されます。 

### なぜ効果があるのか

 正しさは、すべての有効な星が完全に連続したセグメント内に存在しなければならないという事実に基づいています。`'*'`4方向すべてにセルを配置します。 DP アレイはこれらのセグメントを正確に捕捉します。 セルがサイズ 1 の星をサポートできない場合、その星が有効な星の中心の一部であることは不可能であるため、除外しても安全です。 

最大の星を配置すると、その領域の潜在的な貢献がすべて使い果たされます。 そこに配置された可能性のある小さな星は、それ以上の星の範囲内に完全に含まれるため、有効な構成が失われることはありません。 したがって、もしあれば、`'*'`解明されていないままであるため、有効な星の組み合わせによっては説明できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
g = [list(input().strip()) for _ in range(n)]

up = [[0]*m for _ in range(n)]
down = [[0]*m for _ in range(n)]
left = [[0]*m for _ in range(n)]
right = [[0]*m for _ in range(n)]

for i in range(n):
    for j in range(m):
        if g[i][j] == '*':
            left[i][j] = (left[i][j-1] if j > 0 else 0) + 1

for i in range(n):
    for j in range(m-1, -1, -1):
        if g[i][j] == '*':
            right[i][j] = (right[i][j+1] if j+1 < m else 0) + 1

for j in range(m):
    for i in range(n):
        if g[i][j] == '*':
            up[i][j] = (up[i-1][j] if i > 0 else 0) + 1

for j in range(m):
    for i in range(n-1, -1, -1):
        if g[i][j] == '*':
            down[i][j] = (down[i+1][j] if i+1 < n else 0) + 1

stars = []
covered = [[False]*m for _ in range(n)]

for i in range(n):
    for j in range(m):
        if g[i][j] == '*':
            k = min(up[i][j], down[i][j], left[i][j], right[i][j]) - 1
            if k > 0:
                stars.append((i, j, k))
                for t in range(k+1):
                    covered[i][j+t] = True
                    covered[i][j-t] = True
                    covered[i+t][j] = True
                    covered[i-t][j] = True

ok = True
for i in range(n):
    for j in range(m):
        if g[i][j] == '*' and not covered[i][j]:
            ok = False

if not ok:
    print(-1)
else:
    print(len(stars))
    for x, y, s in stars:
        print(x+1, y+1, s)
```このソリューションでは、まず方向情報を 4 つの DP パスに圧縮し、星のサイズを評価する際の繰り返しのスキャンを回避します。 重要な点は、カバレッジ マーキングには中心と 4 本のアームすべてが対称に含まれている必要があることです。 ここでの 1 つ違いの間違いは、星のサイズが大きいため、正しさが損なわれます。`k`正確にスパンする`k`細胞は外側に向かってではなく、`k+1`。 

最後の検証ステップで漏れがないことを確認します`'*'`細胞は星の影響の外側に留まります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    g = [list(sys.stdin.readline().strip()) for _ in range(n)]

    up = [[0]*m for _ in range(n)]
    down = [[0]*m for _ in range(n)]
    left = [[0]*m for _ in range(n)]
    right = [[0]*m for _ in range(n)]

    for i in range(n):
        for j in range(m):
            if g[i][j] == '*':
                left[i][j] = (left[i][j-1] if j > 0 else 0) + 1

    for i in range(n):
        for j in range(m-1, -1, -1):
            if g[i][j] == '*':
                right[i][j] = (right[i][j+1] if j+1 < m else 0) + 1

    for j in range(m):
        for i in range(n):
            if g[i][j] == '*':
                up[i][j] = (up[i-1][j] if i > 0 else 0) + 1

    for j in range(m):
        for i in range(n-1, -1, -1):
            if g[i][j] == '*':
                down[i][j] = (down[i+1][j] if i+1 < n else 0) + 1

    stars = []
    covered = [[False]*m for _ in range(n)]

    for i in range(n):
        for j in range(m):
            if g[i][j] == '*':
                k = min(up[i][j], down[i][j], left[i][j], right[i][j]) - 1
                if k > 0:
                    stars.append((i, j, k))
                    for t in range(k+1):
                        covered[i][j+t] = True
                        covered[i][j-t] = True
                        covered[i+t][j] = True
                        covered[i-t][j] = True

    ok = True
    for i in range(n):
        for j in range(m):
            if g[i][j] == '*' and not covered[i][j]:
                ok = False

    if not ok:
        return "-1\n"
    out = [str(len(stars))]
    for x, y, s in stars:
        out.append(f"{x+1} {y+1} {s}")
    return "\n".join(out) + "\n"

 ## 特殊なケース

 重要なエッジケースは、潜在的な中心が部分的な対称性を持つ場合です。 左右のアームが存在するが、一方の垂直方向がすぐに途切れるグリッドを考えてみましょう。 DP 配列は正しく割り当てます`up`または`down`1として、作成`min(...) - 1 = 0`、その位置での不正なスターの作成を防ぎます。 

もう 1 つのエッジ ケースは、すべてのセルをカバーするためにオーバーラップが必要な星の細いチェーンです。 アルゴリズムは完全性を前提とするのではなく、常に最終的なカバレッジをチェックするため、小さな星が多数配置されている場合でも、カバレッジの欠落を正確に検出します。 

最後のエッジ ケースは、完全に空のグリッドです。 この場合、スターは生成されず、出力は単にゼロになります。これは、スターはオプションであり、塗りつぶされたセルをカバーするためにのみ必要であるという要件と一致します。
