 ## 問題の理解

 2 種類のセルで満たされた長方形のグリッドが与えられます。占有セルは としてマークされています。`*`とマークされた空のセル`.`。 課題は、星と呼ばれる幾何学的オブジェクトの重ね合わせとしてグリッドを説明することです。 星は、中央のセルを選択し、4 つの等しい長さのアームを 4 つの基本方向に伸ばすことによって定義されます。 アームはすべて正の長さでなければならず、中心を含むアームに沿ったすべてのセルはグリッド内にあり、`*`。 

出力は、一意の分解を再構築するように求めているわけではありません。 代わりに、有効な星のコレクションは、すべての星が存在する限り許容されます。`*`グリッド内の星は、すべての星の結合によって生成された少なくとも 1 つの星セルで覆われています。 重複は許可されているため、複数の星が同じセルをペイントできます。 

重要な問題は、星が制約されたオブジェクトであることです。有効な星は対称的な十字の形状を強制し、中心は`*`継続的なもの`*`四方向すべてにチェーンを張ります。 どれでも`*`そのような構造の一部ではないものは、他の星の腕または中心によって覆われているとして説明可能でなければなりません。 

制約は小さく、両方の次元が最大 100 です。これにより、テスト ケースごとにほぼ 3 次または軽度の 2 次の作業を超えるものは即座に排除されます。 各セルは最大 100 個の可能な半径をサポートできるため、各セルで考えられるすべての星の完全な列挙はすでに実現可能です。 

素朴なアプローチでは、それぞれを治療しようとする可能性があります。`*`グローバルな一貫性を確保せずに、独立して貪欲にそれを何らかの星に割り当てます。 細胞が複数の重複する候補星の一部であるように見えても、実際には必要なすべての方向をカバーする構成が 1 つだけである場合、これは失敗します。 

より微妙な失敗例は、セルがアーム上にあるものの、それ自体が有効な中心ではない場合に発生します。 たとえば、次のような長い水平セグメントについて考えてみましょう。`*`垂直サポートなし。 貪欲な方法では、それに沿って星を中心に配置しようとするかもしれませんが、それらの中心には有効な垂直アームがないため、他の場所で小さな星が重なっていることでセグメントが説明可能であっても、分解は不可能になります。 

もう 1 つの問題は、センターを二重にカウントすることです。すべての有効なセンターを個別にマークし、カバレッジが自動であると仮定すると、すべてのセンターを確実にカウントできない可能性があります。`*`実際には、正の長さの少なくとも 1 つのスター アームが到達可能です。 

## アプローチ

ただし、これでもまだ冗長な作業が行われます。多くのセルは中心になることができません。`*`四方向すべてに。 重要な観察は、有効な星の中心は、連続する最小の長さによって完全に決定されるということです。`*`4方向のセグメント。 すべてのセルについてこれらの長さを計算すると、各位置で可能な星の最大サイズがすぐにわかります。 

これにより、問題は建設的な抽出問題に変わります。すべての有効な星を計算してから、カバレッジを検証します。 重複が許可されているため、最小限のセットを選択したり、冗長性を回避したりする必要はありません。 必要なのは正しさだけです。 適合する任意の星を含めることができます。

 ## アルゴリズムのチュートリアル

 1. すべてのセルについて、連続するセルの数を計算します。`*`s は、それ自体を含めて上、下、左、右に伸びます。 これは、グリッド上で 4 回の DP パスで実行できます。 これが機能する理由は、各方向がその方向の前のセルにのみ依存するため、ローカル情報が線形時間でグローバルに伝播するためです。 
2. 各セルについて、4 つの方向の値の最小値から 1 を引いた値として、可能な最大の星のサイズを決定します。 星のサイズがあるため、1 を引く必要があります。`s`必要`s`中心から少しずつ離れています。つまり、中心自体が 1 単位に貢献します。 
3. この計算されたサイズが少なくとも 1 であるすべてのセルを収集します。そのような各セルは、有効な星の中心を表します。 
4. これらの星を出力リストに記録します。 この問題は最小性を必要としないため、星の数を最適化することはしません。 
5. false に初期化された別のブール グリッドを構築します。 各星について、その星によって覆われているすべてのセル、つまり中心とその半径までの 4 本の腕すべてにマークを付けます。 
6. すべての星をマークした後、元の星がすべて揃っていることを確認します。`*`セルが覆われています。 もしあれば`*`カバーされていない場合、グリッドを表現できないため、-1 を出力します。 

重要な考え方は、どの星が細胞を「所有」しているかを決して決定しようとしないということです。 代わりに、すべての有効な星が存在することを確認し、それらの結合がグリッドを説明していることを確認するだけです。 

### なぜ効果があるのか

 私たちが構築する各星は、その中心の方向制約に関して最大になります。 つまり、セルがより大きな有効な星の中心である可能性がある場合、DP はすでにその半径を正確に捕捉しています。 分解におけるすべての有効な星は同じ方向制限を尊重する必要があるため、これらの候補に限定しても必要な構造は削除されません。 

星は任意に重なり合うことができるので、結合がグリッドをカバーする有効な星のスーパーセットのみが必要です。 DP で生成されたセットはそのようなスーパーセットであり、最後の検証ステップで正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [list(input().strip()) for _ in range(n)]

    up = [[0]*m for _ in range(n)]
    down = [[0]*m for _ in range(n)]
    left = [[0]*m for _ in range(n)]
    right = [[0]*m for _ in range(n)]

    for i in range(n):
        for j in range(m):
            if g[i][j] == '*':
                left[i][j] = (left[i][j-1] + 1) if j > 0 else 1

    for i in range(n):
        for j in range(m-1, -1, -1):
            if g[i][j] == '*':
                right[i][j] = (right[i][j+1] + 1) if j + 1 < m else 1

    for j in range(m):
        for i in range(n):
            if g[i][j] == '*':
                up[i][j] = (up[i-1][j] + 1) if i > 0 else 1

    for j in range(m):
        for i in range(n-1, -1, -1):
            if g[i][j] == '*':
                down[i][j] = (down[i+1][j] + 1) if i + 1 < n else 1

    stars = []
    cover = [[False]*m for _ in range(n)]

    for i in range(n):
        for j in range(m):
            if g[i][j] == '*':
                s = min(up[i][j], down[i][j], left[i][j], right[i][j]) - 1
                if s > 0:
                    stars.append((i, j, s))

    for i, j, s in stars:
        cover[i][j] = True
        for d in range(1, s+1):
            cover[i+d][j] = True
            cover[i-d][j] = True
            cover[i][j+d] = True
            cover[i][j-d] = True

    for i in range(n):
        for j in range(m):
            if g[i][j] == '*' and not cover[i][j]:
                print(-1)
                return

    print(len(stars))
    for i, j, s in stars:
        print(i+1, j+1, s)

if __name__ == "__main__":
    solve()
```実装は、すべての幾何学的制約をセルごとの定数時間クエリに圧縮する 4 つの方向性 DP 配列から始まります。 計算するときの1の減算`s`DP カウントには中心自体が含まれますが、星のサイズは腕の長さのみで定義されるため、これは重要です。 

カバレッジ シミュレーションでは、各スターを明示的に拡張します。スターの総数は次の範囲に制限されているため、これは安全です。`n*m`、各拡張コストは最大でも`O(n+m)`最悪の場合は星ごとに。 制約を 100 にすると、これは引き続き効率的になります。 

最後の検証ループでは、`*`セルは説明されないままになっており、これが正確さのために必要な唯一のグローバル条件です。

 ## 特殊なケース

 まれなケースが発生するのは、`*`セルには垂直方向または水平方向の連続性がありません。 その状況では、すべての方向の DP 値が崩壊し、計算されたサイズが 0 になるため、セルがスターの中心として選択されることはありません。 そのようなセルが他のスターによってカバーされていない場合、最終検証でそれが検出され、構成が拒否されます。 

もう 1 つのエッジ ケースは、次のような長い水平線です。`*`垂直方向のサポートがありません。 すべてのセルには左右の連続性がありますが、上下は 1 に等しいため、星は形成できません。 アルゴリズムは正しく星を生成せず、星があったとしても検証に失敗します。`*`存在します。 

最後のケースは、有効な星が重なり合っていて、カバー範囲が冗長である場合です。 このアルゴリズムは、一意性や最小性に依存せず、有効な拡張の存在のみに依存し、最終的なカバレッジ チェックですべての冗長性が吸収されるため、引き続き機能します。
