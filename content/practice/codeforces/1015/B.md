 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの文字列が与えられます。一方の文字列は文字の開始配列を表し、もう一方の文字列はターゲット配列を表します。 許可される唯一の操作は、開始文字列内の隣接する 2 つの文字を交換することです。 交換するたびに文字が左または右に 1 つずつ移動するため、複数回の交換で文字列の順序を徐々に変更できます。 

タスクは、これらの隣接するスワップを使用して開始文字列をターゲット文字列に変換できるかどうかを判断し、可能であれば、長さが最大 10000 の有効なスワップ シーケンスを出力することです。 

重要な構造上の観察は、隣接するスワップによって文字の任意の並べ替えを実現できるが、それは文字列のマルチセット制約内でのみ実現できるということです。 2 つの文字列の文字頻度が同一でない場合、交換は文字の順序を変更するだけであり、文字列内に存在する内容を変更することはないため、一連の交換は役に立ちません。 

n ≤ 50 という制約は十分小さいため、答えを作成する際に文字列に対する操作を直接シミュレートできます。 スキャンとシフトを繰り返す二次プロセスであっても、総作業量は最悪の場合でもフェーズごとに約 2500 スワップに制限されるため、許容範囲内に収まります。 

実現可能性を確認せずに貪欲に文字を一致させようとすると、微妙な失敗のケースが発生します。 たとえば、周波数の不一致を無視すると、残りのサフィックスに存在しない文字を「狩り」しようとして、無限または無効な構築が生じる可能性があります。 もう 1 つのエッジ ケースは、貪欲戦略が一致する文字を見つけたものの、それを段階的に正しく移動させず、スワップ後にインデックスの不整合が発生する場合です。 

## アプローチ

 強引なアイデアは、これを文字列の順列空間における最短経路問題として扱うことです。 各状態は順列であり、移動するたびに隣接する文字が入れ替わります。 これにより、n! のグラフが形成されます。 BFS は s から t への一連のスワップを見つけます。 これは正しいですが、n = 10 の場合でも、10 であるため完全に実行不可能です。 すでに 300 万の状態を超えており、各状態には最大 n 個の遷移があります。 

重要な洞察は、最短パスは必要なく、有効なパスのみが必要であるということです。 これにより、建設的な貪欲なアプローチが可能になります。文字列を左から右に整列させ、一度に 1 つの位置を固定します。 位置 i が処理されるとき、隣接するスワップを使用して、t[i] の正しい文字が位置 i に確実に導入されます。 交換するたびにキャラクターが一歩近づき、定位置になるまで繰り返します。 

これが機能するのは、プレフィックスが修正されると、その後の操作でそれを妨げる必要がなくなるからです。 固定されていない接尾辞内の文字のみを移動します。

 | --- | --- | --- | --- |
 | 順列上の BFS | お(ん!) | お(ん!) | 遅すぎる |
 | 貪欲な隣接スワップ | O(n^3) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 変更可能な文字リスト上で変換を直接シミュレートします。 

1. s と t の複数の文字セットが同一であるかどうかを確認します。 そうでない場合、一連のスワップでは一方を他方に変換できないため、すぐに -1 を返します。 スワップによって文字数が保持されるため、これが必要になります。 
2. 文字列 s をリストに変換して、O(1) 時間で文字を交換できるようにします。 
3. 0 から n - 1 までの各位置 i を反復し、それを t[i] の最終位置として扱います。 
4. 各位置 i について、s[j] が t[i] に等しくなるインデックス j が見つかるまで、i から前方にスキャンします。 これにより、所定の位置に移動できる有効なオカレンスが確実に選択されます。 
5. j が見つかったら、s[j] と s[j - 1] を繰り返し交換し、j が i に等しくなるまで毎回 j をデクリメントします。 各スワップは操作として記録されます。 
6. すべての位置に対してこのプロセスを続けます。 最終的に、s は t と同一になります。

この段階的なシフトが機能する理由は、隣接する要素を交換することで文字を左方向に「バブリング」できるためです。 スワップのたびに、ターゲット位置までの距離が 1 つだけ減少します。最終確定後に文字を i の左側に移動することはないため、プレフィックスは固定されたままになります。 

### なぜ効果があるのか

 不変条件は、位置 i を処理した後、プレフィックス s[0..i] が t[0..i] と正確に一致し、それ以上の操作によってこのプレフィックスが変更されることはないということです。 各ステップでは、i で始まるサフィックス内の要素のみが交換されるため、それより前の位置は変更されません。 常に接尾辞から一致する文字を選択するため、後の位置の実現可能性が損なわれることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = list(input().strip())
    t = list(input().strip())

    if sorted(s) != sorted(t):
        print(-1)
        return

    ops = []

    for i in range(n):
        j = i
        while j < n and s[j] != t[i]:
            j += 1

        while j > i:
            s[j], s[j - 1] = s[j - 1], s[j]
            ops.append(j)  # 1-based position of swap
            j -= 1

    print(len(ops))
    if ops:
        print(*ops)

if __name__ == "__main__":
    solve()
```この解決策は、並べ替えを使用した実現可能性のチェックから始まります。並べ替えは完全に文字数によって定義されるため、これで十分です。 メインループは、左から右にターゲット文字列を構築します。 内部検索によって必要な文字の有効な出現が検出され、その後の交換フェーズによってその文字が所定の位置に移動されます。 

よくある間違いは、スワップのたびにインデックスが変化することを忘れることです。 この実装では、リストを物理的に変更し、スワップ ループ中に文字の現在位置を追跡することで、再計算を行わずに正確さを確保することで、この問題を回避します。 

もう 1 つの微妙な点は、出力のインデックス付けです。 この問題では 1 から始まるスワップ位置が必要なので、j-1 と j の間のスワップ位置に関して減分する前に j を出力します。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ターゲット文字列で複数の同一文字間で文字を移動する必要がある場合です。 たとえば、「aabb」を「bbaa」に変換するには、各文字の正しい出現を慎重に選択する必要があります。 アルゴリズムは、常に現在の位置から前方へ検索し、間違った文字を再利用するのではなく、サフィックスにまだ存在する文字を確実に選択するため、これを正しく処理します。 

もう 1 つのケースは、正しい文字がすでに位置 i にある場合です。 その状況では、内部のスワップ ループは完全にスキップされ、プレフィックスは変更されません。 これにより、不要な操作が防止され、10000 移動制限内に確実に収まるようになります。 

最後のケースは、必要な文字が文字列の末尾にのみ存在する場合です。 アルゴリズムは依然としてそれを見つけて、ステップごとにそれを残します。 各スワップはターゲット位置までの距離を厳密に短縮し、オーバーシュートや以前の位置を破壊することなく終了することを保証します。
