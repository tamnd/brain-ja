 ## 解決策
 ## 問題の理解

 いくつかのテスト ケースが与えられ、それぞれが飛行機上の完全な加重移動システムを記述します。 すべての都市は整数の座標を持つ点であり、任意の都市のペア間を直接飛行することができます。 フライトの料金は、両方のエンドポイントが最初の k 都市に含まれるかどうかによって異なります。 両方の都市が主要都市であれば、航空券は無料です。 それ以外の場合、コストはそれらの間のマンハッタンの距離になります。 

このタスクは、出発都市 a から目的地都市 b までの移動にかかる最小の総コストを見つけることです。この場合、任意の順序のフライトと途中の停留所を利用できます。 フライトは、主要都市間の特別なゼロコストエッジを備えた完全なグラフを形成するため、問題は本質的に、非常に構造化されたコストルールを備えた密な重み付きグラフで最短経路を見つけることになります。 

この制約により、テスト境界線ごとに O(n^2) エッジを使用する素朴な最短経路アプローチが作成されますが、慎重に処理すれば総和 n ≤ 2・10^5 で許容されます。 ただし、テスト ケースごとに O(n^2) 個のエッジを考慮する必要があるため、明示的な完全なグラフでダイクストラを実行することは不可能です。 

kが大きいと微妙な困難が現れます。 多くの都市が主要都市であれば、それらはゼロコストの勢力を形成し、私たちはそれらの間を自由に移動できることを意味します。 これにより、コストを大幅に削減できる「テレポーテーション バックボーン」が作成されますが、それは最適に使用した場合に限られます。 

素朴な考えを打ち破るエッジケースには、次のような状況が含まれます。 

テレポートは長距離を迂回する可能性があるため、常に最も近い都市を使用するという欲張った選択は失敗します。 

たとえば、2 つの主要都市が遠く離れているが、どちらも異なる地域に近い場合、それらの都市を経由する旅行は国内では無料ですが、都市への到達は無料ではありません。 大都市を中間拠点として利用することを無視した単純な戦略は、コストを過大評価することになります。 

もう 1 つの失敗ケースは、k = 0 の場合です。これは、フリー エッジがないことを意味します。 次に、問題は完全なマンハッタン グラフ内の純粋な最短経路に帰着します。最適な経路は常に a から b への直線です。 

## アプローチ

 ブルートフォースソリューションでは、問題を完全な重み付きグラフとして扱い、すべての O(n^2) エッジでダイクストラのアルゴリズムを実行します。 都市の各ペアについて、両方が主要でない限りマンハッタンの距離を計算します。両方が主要な場合、エッジの重みは 0 です。 考えられるすべてのフライトが明示的に考慮されているため、これは正しいです。 

ただし、これにはテスト ケースごとに O(n^2) 個の遷移を評価する必要があり、n が大きい場合は不可能になります。 合計 n が 2・10^5 までの場合、密なグラフを 1 回パスするだけでも制限時間を超えてしまいます。 

重要な観察は、ゼロコスト エッジの構造により、すべての主要都市が内部コストがゼロの単一の接続されたコンポーネントに崩壊するということです。 主要都市セットに入ると、そのセット内を無料で移動でき、主要都市から出ることができます。 これは、メジャーからメジャーへのすべての移行を考慮するのではなく、この「フリー ハブ」を使用して 2 点間の距離を短縮できるかどうかのみを考慮することを意味します。 

したがって、最短経路は少数の候補戦略に減ります。 マンハッタンの距離を使用して a から b に直接移動するか、主要都市クラスターをテレポーテーションの橋として使用します。つまり、a からいくつかの主要都市に移動し、主要都市間を自由に移動し、次に別の主要都市から b に移動します。 専攻間の内部移動は自由であるため、これは以下を最小限に抑えることと同じになります。 

distance(a, u) + distance(v, b)。ここで、u と v は任意の主要都市です。 

これにより、すべてのペアではなく、少数の候補点のセットをチェックする問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (完全なグラフ上のダイクストラ) | O(n²) | O(n²) | 遅すぎる |
 | 最適 (大都市の削減を使用) | テストあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 都市 a と都市 b の間のマンハッタンの直線距離を計算します。 任意の 2 つの都市間を直接飛行できるため、これは常に有効な答えです。 
2. 主要都市がない場合 (k = 0)、すぐにこの直線距離を返します。 フリー エッジがなければ、中間構造によってパスを改善することはできません。 
3. 主要都市が少なくとも 1 つある場合は、主要都市グループをブリッジとして使用する最適な方法を計算します。 このために、a を任意の主要都市に接続し、b を任意の主要都市にどれだけ安く接続できるかを検討します。 
4. 都市 a から主要都市までの最小距離を計算します。 これは、無料のテレポーテーション ネットワークに入る最も安価な方法です。 
5. 主要都市から都市までの最小距離を計算します。 b. これは、無料ネットワークを終了する最も安価な方法を表します。 
6. これら 2 つの値を加算して、大都市ルートを使用した回答候補を作成します。 
7. 最終的な答えは、直接パスと主要都市ブリッジ パスの間の最小値です。 

主要セットまでの最小距離のみが必要な理由は、そのセット内では移動コストがゼロであるため、可能な限り最適な出入りコストを超えて特定の主要都市に出入りするかを追跡する必要がないためです。 

機能する理由: 最適なパスは、a から主要都市まで、主要コンポーネント内、主要都市から b までの 3 つのセグメントに分解できます。 中央のセグメントにはコストがゼロであるため、最適性に影響しません。 すべての主要都市はゼロコストで相互に到達できるため、最適な入口点と出口点のみが重要となり、サブグラフ全体が単一の重みゼロのノードに折りたたまれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def dist(i, j, xs, ys):
    return abs(xs[i] - xs[j]) + abs(ys[i] - ys[j])

def solve():
    n, k, a, b = map(int, input().split())
    a -= 1
    b -= 1

    x = [0] * n
    y = [0] * n

    for i in range(n):
        x[i], y[i] = map(int, input().split())

    direct = abs(x[a] - x[b]) + abs(y[a] - y[b])

    if k == 0:
        print(direct)
        return

    majors = list(range(k))

    min_a_to_major = float('inf')
    min_b_to_major = float('inf')

    for i in majors:
        min_a_to_major = min(min_a_to_major,
                             abs(x[a] - x[i]) + abs(y[a] - y[i]))
        min_b_to_major = min(min_b_to_major,
                             abs(x[b] - x[i]) + abs(y[b] - y[i]))

    via_major = min_a_to_major + min_b_to_major

    print(min(direct, via_major))

t = int(input())
for _ in range(t):
    solve()
```この実装では、関連する点間のマンハッタン距離が直接計算されます。 重要な単純化は、参入コストと撤退コストを評価する際に、注目を k 個の主要都市のみに制限することです。 これにより、グラフ構造の構築が回避されます。 

入力では 1 から始まる都市ラベルが使用されますが、配列は 0 から始まるため、インデックス付けには注意が必要です。 もう 1 つの微妙な点は、空のメジャー セットに対する不必要な反復を避けるために k = 0 を個別に処理することです。 

## 実用的な例

 ### 例 1

 入力:```
n = 6, k = 2, a = 3, b = 5
major cities: 1, 2
```まず直接距離を計算します。

 両方の主要都市を評価した後、主要都市 3 から主要セットへの最も安価な入口と、5 への出口が最も安価であることがわかります。このアルゴリズムにより、都市 1 をハブとして使用すると、直接旅行に比べて総コストが削減されることが確認されます。 

これは、幾何学的最短パス上にない場合でもメジャー セットがどのようにショートカットとして機能するかを示しています。 

### 例 2

 入力:```
n = 3, k = 1, a = 3, b = 1
```都市 1 のみが主要です。 

| ステップ | 直接 | 最小→メジャー | 最小b→メジャー | メジャー経由 | 答え |
 | --- | --- | --- | --- | --- | --- |
 | 計算する | 3→1 | dist(3,1) | 距離(1,1)=0 | 合計 | 分 |

 ここでの最適ルートは、主要都市をコスト​​ゼロのピボットとして使用します。 直接距離が存在する場合でも、この構造により、形状に応じて潜在的に異なるコスト構造が可能になります。 

これは、単一の主要都市であっても、最適なルーティング動作が大幅に変わる可能性があることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テストあたり O(n) | 最大 k 個の主要都市をスキャンし、一定時間の距離を計算します。 
| スペース | O(n) | すべての都市の座標を保存します |

 すべてのテスト ケースの合計複雑さは都市の総数に線形であり、2 · 10^5 の制約内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        n, k, a, b = map(int, input().split())
        a -= 1
        b -= 1

        x = []
        y = []
        for _ in range(n):
            xi, yi = map(int, input().split())
            x.append(xi)
            y.append(yi)

        direct = abs(x[a] - x[b]) + abs(y[a] - y[b])

        if k == 0:
            return direct

        min_a = float('inf')
        min_b = float('inf')

        for i in range(k):
            d1 = abs(x[a] - x[i]) + abs(y[a] - y[i])
            d2 = abs(x[b] - x[i]) + abs(y[b] - y[i])
            min_a = min(min_a, d1)
            min_b = min(min_b, d2)

        return min(direct, min_a + min_b)

    t = int(input())
    out = []
    for _ in range(t):
        out.append(str(solve()))
    return "\n".join(out)

 ## 特殊なケース

 k = 0 の場合、アルゴリズムは大都市ループに入らず、a と b の間のマンハッタン距離を直接返します。 これは、ゼロコストのエッジが存在しないという事実と一致するため、すべてのパスは 1 つの直接フライトに集約されます。 

k = n の場合、すべての都市が主要都市となるため、旅行コストはすべてゼロになります。 アルゴリズムは最小距離を正しく計算しますが、メジャーを介した参入と退出のコストはいずれの場合もゼロであるため、依然としてゼロを返します。 

aやb自体が大都市であれば、自動的に入国・退出コストはゼロになります。 主要都市で計算された最小値には当然その都市自体が含まれており、アルゴリズムがゼロコスト コンポーネント内で開始または終了する最適なパスを見逃さないようにします。
