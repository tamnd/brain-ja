 ## 問題の理解

 を構築するように求められています。$n \times m$すべての行が次の数値の順列である行列$0$に$m-1$。 これは、各行にはすべての値が 1 回だけ含まれますが、行は互いに異なっていてもよいことを意味します。 

マトリックスが構築されると、各列は次のマルチセットを誘導します。$n$価値観。 各列ごとに$i$、計算します$v_i$、その列の MEX。 最後に、これらすべてを取得します$v_i$値を取得し、そのシーケンスの MEX を計算します。 目標は、この最終値を最大化することです。 

したがって、問題は個々のセルに関するものではなく、各列にどの値が表示されるかを制御すること、特に各列に特定の数値が含まれないようにする期間を制御することです。 

重要な制約は、すべてのテスト ケースの合計サイズが最大でも次であることです。$2 \cdot 10^5$したがって、テスト ケースごとに、どのような構成も線形または線形に近いものでなければなりません。 二次関数の何か$n \cdot m$すぐに失敗してしまうだろう。 

単純な考え方による微妙な失敗例は、各列を個別に最大化しようとすることから生じます。 たとえば、列を調整せずに各行を恣意的または貪欲に埋めようとすると、多くの列の MEX 0 が誤って 0 になることが簡単に発生し、最終的な答えはすぐに 0 になります。もう 1 つの誤解を招きやすいアイデアは、列ごとの値の出現のバランスをとることで各列の MEX を独立して最大化しようとすることですが、置換制約によりすべての列が強力に結合されるため、独立した推論が破綻してしまいます。 

## アプローチ

 ブルートフォースパースペクティブでは、考えられるすべての行の置換を構築し、結果の行列を評価しようとします。 有効な置換に限定しても、次のようなものがあります。$(m!)^n$可能な行列ですが、これは完全に実行不可能です。 

より構造化されたブルート フォースが値ごとに決定を試みる可能性があります。$x$、各行が順列であるという制約の下で、どの列に表示されるべきか。 これはすでに行と列にわたる複雑なマッチング問題になっており、有効性をチェックするには行ごとの制約を維持する必要があり、少なくとも 2 次かそれ以上のものになります。 

重要な単純化は、行の観点から考えるのをやめ、代わりに循環シフト構造の観点から考えることです。 各行にはすべての値が含まれている必要があるため、最初の行を次のように固定できます。$[0,1,2,\dots,m-1]$、このシーケンスをシフトすることで他の行を生成します。 これにより、すべての行が順列であることが保証され、列の分布を強力に制御できます。 

列をずらしたら$i$による$i \bmod m$、その後、各列は循環パターンになります。$0..m-1$。 この構造により、繰り返しによって MEX が低下する前に、各列に表示される個別の値の数を制御できます。 

主な洞察はコラムにあります。$j$、値が$0,1,\dots,k-1$少なくとも使用するとすべて表示されます$k$明確な循環シフトですが、それを超えることはできません$n$行。 これは、可能な限り最良のグローバル MEX が両方の側面によって制限されていることを直ちに暗示します。つまり、以下を超えるものはサポートできません。$n$列ごとに個別のオカレンスが発生するため、それ以上を導入することはできません。$m$全体的に明確な価値観。 最適値は次のようになります。$\min(n, m)$。 

この境界が特定されると、構築は最初の部分で次のことを保証することになります。$k = \min(n,m)$値、すべての列にすべての値が含まれます$0..k-1$したがって、すべての列 MEX は少なくとも$k$同時に、グローバル MEX が正確になるように、これらの値のそれぞれが少なくとも 1 つの列で欠落していることを確認します。$k$。 

これは、周期的なラテン方陣形式の構造によって実現されます。$M_{i,j} = (i + j) \bmod m$。 これにより、すべての行が順列であり、すべての列にも各値が 1 回だけ含まれることが保証されます。$n=m$、または構造化されたプレフィックス$n < m$、最適な MEX パターンを実現するには十分です。

 ## アルゴリズムのチュートリアル

 1. 答えを次のように計算します。$s = \min(n, m)$。 これは、利用可能な個別の行または列の相互作用の数を超える MEX を強制できないという事実からわかります。 
2. 巡回シフト規則を使用して行列を構築します: 各セルに対して$(i, j)$、割り当てます$(i + j) \bmod m$。 これにより、シフトによりすべての剰余の剰余の順序が保持されるため、すべての行が順列であることが保証されます。$m$。 
3. 構築された行列を出力します。 

明らかではない部分は、この単純な循環パターンで列 MEX を制御するのに十分である理由です。 各列には行全体に均等に分散された値が含まれているため、最初の$s$値は列全体で構造化された方法で表示され、以下の MEX が早期に崩壊しないようにします。$s$。 

### なぜ効果があるのか

 この構造はラテン語の長方形構造を形成します。 各行はモジュラー加算の定義による順列です。 各列には、予測可能な残基の広がりが含まれています。 あらゆる値に対して$x < s$、その値が十分な数の列に出現する行が十分にあるため、すべての列に同時に存在することができません。 これにより、列値の MEX を正確に最大まで駆動できるようになります。$s$、制約のため、これより大きな値は達成できません。$s \le \min(n,m)$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())

        k = min(n, m)
        print(k)

        for i in range(n):
            row = [(i + j) % m for j in range(m)]
            print(*row)

if __name__ == "__main__":
    solve()
```コードは最初にすべてのテスト ケースを読み取ります。 それぞれのケースに対して、制限パラメーターを計算します。$k = \min(n,m)$、達成可能な最高の美しさを決定します。 次に、行インデックスによって基本順列をシフトすることによって各行を構築します。 これにより、追加の簿記を必要とせずに、すべての行の有効性が保証されます。 

よくある実装の落とし穴は、モジュロを行値ごとではなく列インデックスごとに適用する必要があることを忘れたり、混同したりすることです。$i+j$対$i \cdot j$、これは行の順列プロパティを破壊します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
