 ## 解決策
 ## 問題の理解

 私たちは一緒にパーティーをします`n`人々はそれぞれ一定の数のキャンディーを持ってきます。 各人は正確に 2 の累乗の数のキャンディーを他の人に与えることができ、最大 1 人に与え、最大 1 人から受け取ることができます。 目標は、全員が同じ数のキャンディーを手に入れることができるようにキャンディーを並べ替えることができるかどうかを判断することです。 

入力は複数のテスト ケースを提供します。 テストケースごとに人数を取得します`n`そして配列`a`初期のキャンディーの数。 出力は`"Yes"`与えられたルールの下ですべての数を均等にするためにキャンディーを再配布できる場合、そうでない場合`"No"`。 

制約については慎重な検討が必要です。`n`まで可能です`2*10^5`、合計`n`すべてのテストケースで次を超えない`2*10^5`。 各キャンディーの数は最大です`10^9`。 これにより、可能なすべての転送を直接シミュレートしたり、授受のすべてのサブセットを試行したりしようとするアルゴリズムが排除されます。ブルート フォースでは、指数関数的に多くの操作が必要になります。 代わりに、2 のべき乗の特性とキャンディーの数の違いを活用するアプローチが必要です。 

誰もがすでに同じ数のキャンディーを持っている場合、明らかではないエッジケースが発生します。 答えは次のようになります。`"Yes"`たとえ移動が必要なかったとしても。 もう 1 つの微妙なケースは、差が 2 のべき乗ではない場合、またはドナーとレシーバーの間で 1 対 1 に一致できない場合です。 たとえば、ある人が 1 つのキャンディーを持っていて、もう 1 人が 3 つのキャンディーを持っている場合、ここでは 2 は 2 のべき乗の差ではないため、2 のべき乗の 1 つのステップで転送してそれらを等しくすることは不可能です。 

## アプローチ

 ブルートフォースアプローチでは、各個人について考えられるすべての転送を列挙し、有効な再分配が存在するかどうかを確認しようとします。 のために`n = 10^5`の場合、候補手の数が指数関数的に増加し、すべての組み合わせをチェックするのは不可能であるため、このアプローチはすぐに失敗します。 

重要な洞察は、各転送は 2 のべき乗であり、各人は最大でも 1 つの与える行為と 1 つの受け取る行為に参加できるということです。 この制限により、転送をシミュレートするのではなく、違いについて推論することができます。 させて`target`キャンディーの平均数になります。 以上のものを持っている人なら誰でも`target`差額を正確に渡す必要があり、それよりも少ない人は差額を正確に受け取らなければなりません。 すべての差異が 2 の個別のべき乗の合計として表現でき、一意にペアリングできる場合 (各ドナーとレシーバー)、再分配が可能です。 

貪欲なアプローチは次のとおりです。1 人あたりのターゲット キャンディーを計算し、その差を計算し、すべての余剰と不足が独自の 2 のべき乗の転送によって解決できるかどうかを確認します。 これにより、問題はビットをカウントすることになります。各ビット位置の余剰と不足は正確にバランスが取れていなければなりません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | ビットマスク/貪欲 | O(n * log(max(a_i))) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`そして配列`a`キャンディーの数。 キャンディーの合計を計算し、`total`。 
2. 次のことを確認します。`total`で割り切れます`n`。 そうしないと均等分配が不可能となり、出力されます。`"No"`。 
3. 計算する`target = total // n`。 
4. 2 つのリストを初期化します。`give`各人が寄付しなければならない金額（プラスの差）と`receive`各人が受け取らなければならない金額（絶対値のマイナスの差）。 
5. 各人について計算します`diff = a[i] - target`。 もし`diff > 0`、に追加`give`; もし`diff < 0`に絶対値を追加します`receive`。 
6. の各値について`give`そして`receive`、ビット演算を使用して、それを個別の 2 のべき乗の合計に分解します。 2 のべき乗ごとに何回の転送が必要になるかを追跡します。 
7. の 2 のべき乗ごとに必要な転送数を比較します。`give`そして`receive`。 完全に一致する場合は出力します`"Yes"`。 それ以外の場合は出力`"No"`。 

それが機能する理由: すべての人は最大 1 人に寄付し、最大 1 人から受け取ります。そのため、許可される唯一の動きは、2 のべき乗の金額ごとに 1 人の寄付者から 1 人の受取人にちょうど 1 人だけです。 2 の累乗のカウントのバランスを取ることで、必要なすべての転送に対して 1 対 1 のマッピングが存在することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_equalize(a):
    n = len(a)
    total = sum(a)
    if total % n != 0:
        return False
    target = total // n
    give_bits = [0] * 31
    receive_bits = [0] * 31
    for x in a:
        diff = x - target
        if diff > 0:
            for i in range(31):
                if diff & (1 << i):
                    give_bits[i] += 1
        elif diff < 0:
            diff = -diff
            for i in range(31):
                if diff & (1 << i):
                    receive_bits[i] += 1
    return give_bits == receive_bits

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print("Yes" if can_equalize(a) else "No")
```このソリューションでは、各差を 2 のべき乗に分解し、各ビットが何個必要かカウントします。 サイズ 31 のリストを使用すれば十分です。`a_i <= 10^9`(30 ビットに収まります)。 これらのカウントを比較すると、すべての黒字が、固有の 1 対 1 の 2 のべき乗の振替で赤字と一致することが保証されます。

 - 受信: 1 (2 ～ 4) → ビット 0 = 1
