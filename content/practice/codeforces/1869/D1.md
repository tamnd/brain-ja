 ## 解決策
 ## 問題の理解

 私たちは一緒にパーティーをします`n`それぞれが一定数のキャンディーを持っている人々`a_i`。 各人は正の数のキャンディーを他の 1 人に渡し、各人は他の 1 人からキャンディーを受け取ります。 与えられるキャンディーは 2 の累乗でなければならず、誰も現在持っている以上のキャンディーを与えることはできません。 

目標は 2 つあります。1 つ目は、各人が 1 つだけを与え、1 つから受け取ること (キャンディーの譲渡の完全な 1 対 1 マッピング)、そして 2 つ目は、すべての譲渡の後、最終的に全員が同じ数のキャンディーを手に入れることです。 入力は複数のテスト ケースで構成され、それぞれが指定します`n`そしてリスト`a`。 有効な転送構成が存在する場合、出力は「Yes」、存在しない場合は「No」となります。 

制約は厳しいです:`n`テスト ケースごとに 2×10^5 に達する可能性があり、すべてのテスト ケースの合計も 2×10^5 に制限されます。 これにより、階乗となる転送のすべての順列を試行するソリューションが除外されます。`n`。 

エッジケースには、すべてのキャンディーが既に等しい状況 (自明のことながら「はい」) や、キャンディーの合計が次の値で割り切れない状況が含まれます。`n`、すぐに解決が不可能になります。 小さい`n = 2`これは 1 対 1 スワップの最小サイズであるため、特殊なケースでもあります。 

## アプローチ

 この強引な方法では、ある人から別の人にキャンディーを与えるすべての順序を 2 の累乗で試し、結果の状態をシミュレーションして、最終的に全員が平等になるかどうかを確認します。 これには、サイズのすべての順列を反復処理する必要があります。`n`、それぞれ最大 log(max(a_i)) の 2 のべき乗分割があり、複雑さは O(n! × log(max(a_i))) になります。 これは、2×10^5 までの n には実現できません。 

重要な観察は、すべての人の純利益または純損失が正確に一致する必要があるということです。`target - a_i`、 どこ`target`各人が持つべき最終的なキャンディーの数です。 平均がすべての人に等しくなるようにするには、`target`キャンディーの合計数を で割った値でなければなりません`n`。 これが整数でない場合、解は不可能です。 

2 の累乗の譲渡制限を考慮すると、各個人の純損益が 2 の累乗の合計として表現できる必要があります。 具体的には、次のような違いがあります。`a_i`そして`target`は、異なる 2 の累乗の和に分解できます。 誰もが正確に 1 人に与え、正確に 1 人から受け取るため、送信および受信の 2 の累乗の転送セットは完全にバランスが取れている必要があります。 

そこで出てくるアプローチは、それぞれの違いを確認することです。`target - a_i`は 2 のべき乗の和として表すことができます。 すべての正および負の差にわたって 2 の各べき乗がいくつ必要になるかを数えることにより、2 の各べき乗の合計が正確に一致するかどうかを検証できます。 存在する場合、有効な割り当てが存在します。 これにより、あらゆる順列をシミュレートすることがなくなります。

 | 最適 | O(n × log(max(a_i))) | O(log(max(a_i))) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`n`そしてリスト`a`。 キャンディーの総数を計算する`S`そして決定します`target = S // n`。 もし`S % n != 0`全員が平等になることは不可能なので、「いいえ」と出力して続行します。 
2. 2 つのカウンターを初期化します。`give`そして`receive`、それぞれは 2 のべき乗値からその数へのマップとして表示されます。 
3. ひとりひとりに`i`、計算します`diff = a[i] - target`。 もし`diff > 0`、この人はキャンディーを配らなければなりません。 もし`diff < 0`、彼らは受け取らなければなりません`-diff`キャンディー。 
4. ゼロ以外のそれぞれについて`diff`、それを 2 の累乗に分解します。 これは、ビット 0 から 30 までを反復することによって行われます (`a_i ≤ 10^9`)、対応する電力を増加させます。`give`もし`diff > 0`またはで`receive`もし`diff < 0`。 
5. すべての人々を処理した後、解決策が存在するには、与えるために必要な 2 の累乗の複数セットが、受け取るために必要な複数セットと正確に一致する必要があります。 一致する場合は、「はい」を出力します。 それ以外の場合は、「いいえ」を出力します。 

機能する理由: 2 のべき乗に分解すると、2 のべき乗のキャンディーを与えたり受け取ったりすることで、各人の正味の差が確実に満たされます。 全員が 1 人に与え、1 人から受け取る必要があるため、各力の合計数のバランスが取れている必要があります。 この不変条件により、すべての転送シーケンスを明示的にシミュレートしなくても正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        total = sum(a)
        if total % n != 0:
            print("No")
            continue
        target = total // n
        
        give = {}
        receive = {}
        
        for x in a:
            diff = x - target
            if diff == 0:
                continue
            power = 0
            if diff > 0:
                while diff:
                    if diff & 1:
                        give[power] = give.get(power, 0) + 1
                    diff >>= 1
                    power += 1
            else:
                diff = -diff
                while diff:
                    if diff & 1:
                        receive[power] = receive.get(power, 0) + 1
                    diff >>= 1
                    power += 1
        
        if give == receive:
            print("Yes")
        else:
            print("No")

solve()
```コードはまず、1 人あたりの目標のキャンディーを計算します。 次に、各人が与えたり受け取ったりしなければならない 2 の累乗の数を計算します。 これらの数を比較すると、1 対 1 マッピングの制約に違反することなく、必要なすべての転送を実行できることが保証されます。 負の差分とビット単位の分解を正しく処理するために細心の注意が払われます。 ディクショナリを使用すると、不必要に大きな配列を作成することがなくなります。
