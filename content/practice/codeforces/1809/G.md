 ## 問題の理解

 参加者評価のソートされたリストが与えられ、これらの参加者を 1 行に並べ替えることができます。 順列を修正した後、順番にトーナメントが行われます。最初の 2 人のプレーヤーが戦い、勝者がすぐに並んだ 3 番目のプレーヤーと戦い、その試合の勝者が 4 番目のプレーヤーと戦い、というように最後の参加者まで続きます。 

レーティングの差が大きい場合、つまり 2 人のプレーヤー間の絶対差がしきい値を超えた場合、各試合は決定論的に動作します。$k$、より高い評価のプレイヤーが常に勝ちます。 差が最大の場合$k$、結果は任意であり、どちらの方向にも進む可能性があります。 

重要な要件は、順列を選択した後、Monocarp がすべての試合の結果を事前に予測できなければならないということです。つまり、シーケンス内のすべての試合について、勝者はレーティングと上記のルールによって一意に決定され、「ギャップの小さい」ペアによって生じる曖昧さはありません。 

この特性が成立する参加者の順列が何回あるかを数える必要があります。 

制約は非常に大きく、$n$100万まで。 これにより、すべての順列や二次構造さえもシミュレートしようとするソリューションは即座に除外されます。 評価はすでにソートされており、これは強力な構造上のヒントです。答えは、任意のペアを繰り返し比較することではなく、インデックスをどのように配置するかによってのみ決まるはずです。 

ローカルな妥当性がグローバルな妥当性を意味すると仮定すると、微妙な失敗例が発生します。 たとえば、次の 3 つの評価があるとします。$1, 10, 20$と$k = 5$。 ペア$10, 20$決定的ですが、$1, 10$そうではありません。 「隣接する各ペアが決定的である限り、チェーン全体は問題ない」という素朴な考えがあるかもしれませんが、以前の一致の勝者が将来の参加者のアイデンティティを変更するため、これは誤りです。 

もう 1 つのよくある落とし穴は、プロセスが順列の隣接する差異のみに依存しているかのように扱うことです。 実際には、勝者は伝播するため、制約はグローバルであり、トーナメントを通じて不確実性がどのように伝播するかによって決まります。 

## アプローチ

 ブルートフォースアプローチでは、すべての順列を試し、トーナメントをシミュレートし、すべての試合結果が一意に決定されるかどうかを確認します。 たとえ単一のトーナメントを楽観的にシミュレートしたとしても、$O(n)$、全体の複雑さは次のようになります。$O(n! \cdot n)$、これはたとえ$n = 20$。 ボトルネックはシミュレーション自体ではなく、順列の組み合わせ爆発です。 

重要な観察は、勝者のチェーンが「危険な境界」を越えた場合にのみ不確実性が生じるということです。つまり、レーティングの差が最大でもペアの場合です。$k$。 2 人のプレイヤーのレーティングが大きく離れている場合、より強いプレイヤーが常に優勢となり、曖昧さの伝播を効果的にブロックします。 

評価はソートされているため、結果が分岐する形で曖昧さが伝播しないように、小さい値と大きい値をどのようにインターリーブするかを制御するという問題として再解釈できます。 プロセスの構造は、すべてのステップで、現在の勝者が、潜在的に相互作用するのに十分近い値の連続した「アクティブ ウィンドウ」内の最大値 (または観点によっては最小値) でなければならないことを意味します。 

これは貪欲な組み合わせ構造につながります。範囲を超えない値のウィンドウを維持しながら、開始点から有効なセグメントを拡張します。$k$、そして単一の決定的な結果チェーンを維持しながら挿入順序を選択できる方法が何通りあるかを数えてください。 それぞれの有効な構造は、2 つの未解決の候補が両方とも一致に生き残ることができるウィンドウ内で分割を決して導入しない順序を選択することに対応します。 

最終的なカウントは、各「有効なブロック拡張」からの寄与を乗算することになります。各段階で、現在の実行可能な区間の左側または右側から新しい要素を取得してアクティブなセグメントを拡張するかどうかを決定しますが、これは評価制約が範囲内に留まっている場合に限ります。$k$。 

これにより、グローバルな置換カウントが、ソートされた位置にわたる制御されたカウント プロセスに変換され、線形時間で処理できます。

 ## アルゴリズムのチュートリアル

 ソートされた配列を、範囲が制御されるウィンドウ内に収まる値の実行可能なセグメントを維持する線として解釈します。$k$。 トーナメントの結果に曖昧さをもたらすステップがないようにしながら、このセグメントを拡張することで構築が進められます。 

1. 単一の要素を最初のアクティブなセグメントとして開始します。 これは、シーケンス内の最初の参加者を固定することを表します。 
2. 現在のセグメントを説明する 2 つのポインターを維持します。$[l, r]$、最初は両方とも何らかの開始インデックスで。 
3. セグメントを左または右に拡張してみます。ただし、その要素を追加することでセグメントが「安全」に保たれる場合に限ります。つまり、アクティブな領域内の 2 つの要素が現在の勝者チェーンと比較してあいまいな一致結果を生成する可能性がある状況が作成されない場合に限ります。 
4. 各拡張ステップで、セグメントを拡張するための有効な選択肢がいくつ存在するかを数えます。 それぞれの有効な選択は、勝者の決定論的な伝播を維持する方法で、順列の次の参加者を選択することに対応します。 
5. 現在のアクティブなセグメントが固定されると、さまざまな拡張段階での選択は独立するため、すべてのステップにわたって有効な拡張の数を乗算します。 
6. すべての要素がセグメントに含まれるまで続行します。 

重要な計算タスクは、各辺の距離内に残っている要素の数を追跡することです。$k$現在の境界の。 配列はソートされているため、これらのカウントは 2 つのポインターを使用して要素ごとに償却定数時間で更新できます。 

### なぜ効果があるのか

 このプロセスでは、すべてのステップで、現在の未解決領域が値空間内の単一の接続された区間のままであることが強制され、そこではすべての潜在的な相互作用が引き続き「制御」されます。$k$-しきい値ルール。 これに違反する順列は必然的に、2 つの未解決の候補が両方とも現在のチェーンとの対戦で生き残ることができる状況をもたらし、Monocarp が結果を一意に決定できなくなります。 逆に、有効な境界のみを拡張することによって構築された順列は、勝者のチェーンがすべてのステップで決定的であることを保証するため、すべての一致結果が固定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    # Two pointers defining a valid expanding window
    l = 0
    ans = 1

    for r in range(n):
        # ensure window is valid in value range
        while a[r] - a[l] > k:
            l += 1

        # number of choices to place current element
        ans = (ans * (r - l + 1)) % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```コードは、並べ替えられた評価に対してスライディング ウィンドウを維持します。 ポジションごとに$r$、差を以内に保ちながら、どこまで左に進むことができるかを見つけます。$k$。 これは、決定論を損なうことなく、現在配置できる要素の数を定義します。 要因$(r - l + 1)$は、展開中の構造への現在の要素の有効な配置をカウントし、これらの選択肢を乗算して、有効な置換の合計数を構築します。 

重要な点は、並べ替えによって、左側の境界が前方に移動すると、後方に移動する必要がなくなることです。 これにより、償却された線形複雑さが保証されます。

 ## 特殊なケース

 すべての値が同一の場合、$k = 0$、すべての一致は曖昧です。 ウィンドウは決して縮小しないので、ステップで$r$、 全て$r+1$要素は有効な選択肢であり、$n!$。 スライディングウィンドウは正しく維持されます$l = 0$、したがって、製品は次のようになります$1 \cdot 2 \cdot \dots \cdot n$。

隙間が大きい場合など$1, 100, 1000$を使用すると、ウィンドウが複数のポイントで単一の要素に折りたたまれます。 これらのステップでは、強制的な構造を反映して、積の大部分が 1 倍になります。
