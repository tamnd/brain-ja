 ## 解決策
 ## 問題の理解

 長さの整数配列を構築するように求められます。$n$ここで、各要素は、非常に特殊な組み合わせプロパティがそのすべての部分配列にわたって保持されるように、狭い境界範囲内に存在する必要があります。 

連続するすべてのセグメントは、その要素の合計という単一の値を提供します。 中でも$\frac{n(n+1)}{2}$正確には部分配列$k$そのうちの部分配列は正の和を持つ必要があり、残りのすべての部分配列は負の和を持つ必要があります。 ゼロサム部分配列は暗黙的に許可されていないため、構築では合計が正確にゼロである部分配列の生成を回避する必要があります。 

重要な問題は、部分配列の合計を計算することではなく、すべての部分配列の合計の符号パターンが規定のグローバル カウントと一致するように配列を整形することです。 

制約$n \le 30$非常に小さいです。 これにより、指数関数的なものはすぐに除外されます$n$しかし、より重要なのは、すべてのサブ配列に対する検索や DP ではなく、構造化されたパターンを構築することが期待されていることを示唆していることです。 値の範囲$[-1000, 1000]$十分な幅があるため、オーバーフローや密なパッキングを心配することなく、大きな正と負の定数を使用して寄与をきれいに分離できます。 

すべてのサブ配列が厳密に正または厳密に負であるという要件から、微妙なエッジ ケースが発生します。 和がゼロの部分配列を一度でも作成すると、その構築は無効になります。 プレフィックスの合計を制御せずに正と負のバランスをとる素朴な貪欲さは、通常、ゼロサム境界を生成します。 たとえば、交互に$1, -1, 1, -1$次のような多くのゼロサム部分配列を作成します。$[1, -1]$。 したがって、本当の制約は、カウントを制御するだけではなく、プラスの累積効果とマイナスの累積効果を厳密に分離することです。 

もう 1 つの落とし穴は、サブ配列の正数が個々の要素のみに依存すると仮定していることです。 そうではありません。 単一の大きな正の要素が多くのサブアレイを支配する可能性がある一方で、単一の大きな負の要素が多くのセグメントにわたる正の要素を破壊する可能性があります。 解決策はこの非対称性を利用する必要があります。 

## アプローチ

 ブルートフォースの試みでは、値を割り当ててからすべてのサブ配列をカウントし、正確に値が割り当てられているかどうかを確認します。$k$そのうちの合計は正になります。 候補配列を修正したとしても検証コストがかかる$O(n^2)$。 すべての配列を検索しようとした場合、値を次の値に制限することもできます。$[-1000, 1000]$、検索空間は次のようになります。$(2001)^n$、完全に不可能です。 

すべての部分配列の合計を増分的に追跡しながら各位置をバックトラッキングするなど、より構造化されたブルート フォースでも、各拡張子が依然として影響を与えるため失敗します。$O(n)$部分配列、指数関数的な分岐を与えます。 

重要な観察は、実際には個々のサブ配列を個別に推論する必要がないということです。 代わりに、部分配列が高度に制御された、ほぼ決定的な方法で動作するように配列を構築できます。 この形式の問題における標準的なトリックは、すべての部分配列の合計が主に少数の支配的な要素に依存するように強制することです。 

これを行うには、2 種類の値 (大きな正の定数と大きな負の定数) で構成される配列を構築します。 配置する正と負の数を慎重に選択することで、正の合計を持つように「強制」されるサブ配列の数を制御できます。 

これを機能させる構造は、プレフィックス構造を介してサブ配列のグローバル バランスに独立して寄与するものとして各位置を扱うことです。 正の要素の数を固定し、負の要素と比較して十分に大きくすると、制御された接頭辞の意味で負の要素よりも多くの正の要素が含まれる場合に限り、部分配列は正になります。 これにより、任意の合計について推論するのではなく、問題を正の寄与の位置の選択に縮小することができます。 

次に、タスクを、正確に次のようなシーケンスを構築することに縮小します。$k$サブ配列は正の寄与によって支配されます。 なぜなら$n$が小さい場合は、左から右に積極的に正を割り当てることができ、新しい正の各要素が予測可能な数の新しい正の部分配列に寄与するようにします。

 ## アルゴリズムのチュートリアル

 構築はターゲットの分割に依存します$k$特定のサブ配列を選択して正になることに対応する寄与に変換します。 サインの動作が安定するように、慎重に選択した大きな定数を使用して優位性を強制します。 

1. 空の配列と完全なターゲットから開始します。$k$、まだ実現する必要がある正の和の部分配列の数を表します。 
2. 位置を左から右に繰り返します。 それぞれのポジションで$i$、導入できる新しい正の部分配列の数に基づいて、正の値を配置するか負の値を配置するかを決定します。 

重要な考え方は、position に正の値を配置することです。$i$正確に作成します$i$で終わるサブ配列$i$、その値が残りを支配する場合、それらの部分配列はすべて正になります。 
3. 残っている場合$k$少なくとも$i$、位置に大きな正の数値を配置します。$i$そして引きます$i$から$k$。 これは、で終わるすべてのサブ配列を貪欲に考慮します。$i$以前のインデックスから開始します。 

これが機能する理由は、そのような配置ごとに、で終わるすべてのサブ配列が「アクティブ化」されるためです。$i$正として扱い、大きさを厳密に分離することで後でキャンセルされないようにします。 
4. もし$k < i$の場合は、代わりに大きな負の数値を入力します。 これにより、この位置に関係するサブ配列が誤って正になることがなくなり、明示的に計算されたサブ配列のみがカウントに寄与するという不変条件が維持されます。 
5. すべての位置を処理した後、意図しない正の部分配列が表示されないように、残りの制約されていない位置を十分に大きな負の値で調整します。 

### なぜ効果があるのか

 不変条件は、処理後の位置です。$i$、 またはそれ以前で終了するサブ配列のうちの正の和のサブ配列の数$i$はまさに私たちが引いた金額です$k$。 それぞれのポジティブな配置が正確に貢献します$i$新しい正の部分配列は、で終わるすべての接頭辞を支配するため、$i$、および負の配置は、それらを含む候補の正の合計を抑制するため、新しい正の部分配列に寄与するものはゼロです。 セグメント間のキャンセルを防ぐために大きさが選択されるため、サブ配列の符号は、指定された正の「アンカー」位置が含まれるかどうかのみに依存し、カウントが正確で重複しなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        
        a = []
        # we construct using a greedy decomposition of k into triangular contributions
        # position i contributes at most i new positive subarrays
        
        for i in range(1, n + 1):
            if k >= i:
                a.append(1000)   # strong positive anchor
                k -= i
            else:
                a.append(-1000)  # strong negative blocker
        
        print(*a)

if __name__ == "__main__":
    solve()
```このコードは、左から右への貪欲な割り当てを実装しています。 各インデックスで$i$、「使う」かどうかは私たちが決める$i$残りの割り当ての単位$k$。 正の値を選択すると、この位置がアンカーとなり、すべてのサブ配列が次で終わることを保証します。$i$ポジティブで、正確に貢献している$i$有効な部分配列。 その寄与を賄えない場合は、新しい正の部分配列が作成されないように大きな負の値を設定します。 

の選択$1000$そして$-1000$これは、大きさの強力な分離を保証し、混合部分配列が意図した符号の動作を誤ってキャンセルすることを防ぐため、意図的に行われます。 

微妙な点は、以前の決定を決して再検討しないことです。 これは、各位置の寄与が独立しており、サブ配列のエンドポイントに関して加算されるため安全です。

 ## 特殊なケース

 重大なエッジケースは、$k = 0$ここで、すべての部分配列は負の値でなければなりません。 アルゴリズムは、すべてのポジティブな配置を即座に拒否し、配列を次のように埋めます。$-1000$。 すべての要素が厳密に負であるため、すべての部分配列の合計は負になります。 

もう一つのエッジケースは、$k = \frac{n(n+1)}{2}$ここで、すべての部分配列は正の値でなければなりません。 この場合、すべての位置が満たされます。$k \ge i$したがって、アルゴリズムは配列全体を次のように埋めます。$1000$。 すべての部分配列の合計は、厳密に正の数値の合計であるため、正になります。 

微妙な中間のケースが発生するのは、$k$三角形ではありません。 貪欲なものは分解されるのでまだ機能します$k$個別の整数の合計に変換する$i$、値が使用できない場合は常に、以前のコミットメントを破ることなくスキップされます。 これにより、各位置がそのインデックスに基づいて独立して寄与するため、部分的な寄与が干渉しないことが保証されます。
