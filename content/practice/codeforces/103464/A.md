 ## 解決策
 ## 問題の理解

 ステゴサウルスのコレクションが与えられ、それぞれが持つスパイクの数を表す単一の整数値に関連付けられています。 このコレクションから、任意の 2 つの異なるステゴサウルスを選択し、外観がどの程度似ているかを測定する必要があります。ここで、類似性はスパイク数の絶対的な差として定義されます。 

このタスクは、数値の差が可能な限り小さい値のペアを見つけて、その最小の差を出力することに要約されます。 

アルゴリズムの用語で言い換えると、配列が与えられ、2 つの異なる要素間の最小絶対差を計算する必要があります。 

制約から分かる重要な点は次のとおりです。$n \le 10^5$これにより、二次ペアごとの比較アプローチが即座に除外されます。 素朴な二重ループは大まかに調べます$\frac{n(n-1)}{2}$ペア、最悪の場合は約$5 \times 10^9$操作。 これは、競技プログラミングにおける一般的な 1 秒または 2 秒の制限をはるかに超えています。 

実際には、いくつかの特殊なケースが重要です。 多くの値が同じ場合、たとえば次のような入力がある場合`1 1 1 1`の場合、等しいペアを選択すると差がゼロになるため、正解はゼロです。 ソートされていない配列内の隣接する位置のみをチェックする不注意なアプローチは、前処理後に等しい値が隣接することが保証されない場合、ここで失敗します。 

別の微妙なケースは、値が広範囲に分散している場合に現れます。たとえば、`0 100 50 49 51`。 正しい答えは、(50, 49) または (50, 51) のペアから得られる 1 です。 順序付け後に近さについてグローバルに推論しないソリューションでは、そのようなペアを見逃す可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 私たちはステゴサウルスのすべてのペアを試し、スパイク数の絶対的な差を計算し、最小値を維持します。 これは、変換を行わずに答えの定義を直接評価するため機能します。 ただし、すべてのペアをチェックする必要があるため、速度が非常に遅くなり、$O(n^2)$比較。 

重要な洞察は、絶対差がソート下で適切に動作することを認識することから得られます。 配列を並べ替える場合、値の点で最も近いペアが並べ替えられた順序で隣り合って表示される必要があります。 これは、非隣接ペアには間に少なくとも 1 つの要素があり、その中間要素は隣接要素間のギャップを減らすことしかできず、より良い隣接候補を超えてギャップを増やすことはできないためです。 

したがって、すべてのペアを比較するのではなく、ソート後に連続する要素のみを比較する必要があります。 これにより、ソートされた配列を 1 回スキャンして、隣接する最小の差分を追跡するという問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 並べ替え + スキャン |$O(n \log n)$|$O(1)$または$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$n$そしてスパイク数の配列。 これは、分析する必要があるデータセットを形成します。 
2. 配列を降順でない順に並べ替えます。 並べ替えは、値空間内の近くの数値が配列内で隣接するように値を再配置するため、非常に重要です。 
3. 変数を初期化する`ans`非常に大きな数で。 この変数は、これまでに見つかった最小の差を追跡します。 
4. 配列を最初の要素から最後から 2 番目の要素まで繰り返し、隣接する各ペアを調べます。 
5. 各インデックスについて$i$、間の差を計算します。`a[i+1]`そして`a[i]`。 配列はソートされているため、この差は負でないことが保証されており、以下を含む可能な限り最も近い比較を表します。`a[i]`その右側にあります。 
6.アップデート`ans`この差が現在保存されている値より小さい場合。 これにより、これまでに確認された最良の候補を常に保持できるようになります。 
7. すべての隣接するペアを処理した後、出力します。`ans`。 

### なぜ効果があるのか

 正しさは、ソートされた配列内で任意のペアが存在するという事実に依存します。$(i, j)$と$j > i + 1$それらの間の隣接するペアよりも小さな差を生み出すことはできません。 正式には、どんなものに対しても、$i < k < j$、 我々は持っています：$$a[j] - a[i] = (a[j] - a[k]) + (a[k] - a[i])$$ソート後はどちらの項も負ではないため、差の合計は少なくとも区間内の隣接するギャップの 1 つと同じくらい大きくなります。 これにより、グローバル最小値が連続する要素間で必ず発生することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

a.sort()

ans = float('inf')

for i in range(n - 1):
    diff = a[i + 1] - a[i]
    if diff < ans:
        ans = diff

print(ans)
```コードはアルゴリズムに直接に従います。 並べ替えステップにより、ローカル比較のみが必要になることが保証されます。 隣接するペアにわたるループは、関連するすべての候補ペアがそこに表されるため、安全です。 使用する`float('inf')`は、入力値の境界を気にせずに最小トラッカーを初期化する便利な方法です。 

よくある実装上の間違いは、配列のソートを忘れることです。これにより、最適なペアが完全に欠落してしまいます。 もう 1 つの微妙な問題は、ソートされていないデータで絶対差を使用し、近傍のみをチェックすることです。これは、ソートされていない配置では近さが局所的ではないため、正しくありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    a.sort()
    ans = float('inf')
    for i in range(n - 1):
        ans = min(ans, a[i + 1] - a[i])
    return str(ans)

# provided samples
assert run("5\n2 6 0 19 10\n") == "2"
assert run("7\n1 2 1 2 4 2 3\n") == "0"
assert run("2\n10 15\n") == "5"

# custom cases
assert run("2\n0 0\n") == "0", "all equal"
assert run("3\n1000000000 0 500000000\n") == "500000000", "large spread"
assert run("4\n1 100 101 102\n") == "1", "clustered values"
assert run("5\n5 4 3 2 1\n") == "1", "reverse order input"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`0 0`ケース | 0 | 重複の処理 |
 | 大きなスプレッド | 500000000 | 大きな値の正確性 |
 | クラスター化された値 | 1 | 隣接最小値検出 |
 | 逆順 | 1 | 仕分けの必要性 |

 ## 特殊なケース

 次のような重複の多い入力の場合`4 4 4 4`、アルゴリズムは定数配列にソートされ、隣接する差分はすべてゼロになるため、特別な処理を行わなくても結果は正確にゼロになります。 

逆ソートされた入力の場合、`5 4 3 2 1`、並べ替えると次のように変換されます`1 2 3 4 5`、最小隣接差は 1 になります。並べ替えをスキップし、元の近傍のみをチェックする単純なアプローチでは、4 や 3 などのより大きなギャップを誤って結論付けることになります。 

次のような大きな値の分離の場合`0 1000000000 500`、並べ替えにより、最も近いペアが次のように表示されます。`(500, 0)`または`(1000000000, 500)`、順序付け後に隣接する比較から正しい最小値が抽出されます。
