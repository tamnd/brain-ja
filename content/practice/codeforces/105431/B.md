 ## 解決策
 ## 問題の理解

 概念的に単位グリッド位置に分割された長方形のフィールドが与えられます。$a \times b$。 まさに$N$同一の単位正方形のタイルをすべてこのグリッド内に配置する必要があります。 

配置は 2 つの構造的な方法で制限されます。 

まず、タイルは、占有されているすべてのセルから「左下が閉じた」形状を形成する必要があります。 タイルが何らかのセルに配置される場合、タイルの下または左側に空の隙間が現れないように、その西および南方向に直接フィールドの境界までのすべてがすでに覆われている必要があります。 これにより、占有されているセルはグリッド内で理想的な順序のように動作するように強制されます。$(i, j)$使用されている、すべてのセル$(i' \le i, j' \le j)$も使用する必要があります。 幾何学的には、形状は北東の境界によって完全に決定され、その境界は単調です。 

第 2 に、北または東方向の「最も外側」の境界にあるタイルのうち、すべてのタイルが南西の原点の角から同じマンハッタン距離を持っていなければなりません。 マンハッタンからは距離があるので、$(1,1)$は$i + j - 2$、この要件により、すべての最大境界セルが単一の対角線上に配置されます。$i + j = K$一定の$K$。 これにより、境界が任意の階段から直線の斜めのカットオフに変わります。 

したがって、有効な形状は、グリッド全体を取得し、それを対角線で切断することによって形成される形状とまったく同じです。$i + j \le K$と交差します。$a \times b$四角形を作成し、残っているセルの数を数えます。 課題は、そのような構成で正確に生成できる方法が何通りあるのかを数えることです。$N$タイル。 

制約により許可されるのは、$a, b \le 10^4$したがって、すべてを反復するソリューションはすべて$a \cdot b$セルが遅すぎる。 大まかに実行できるソリューションが必要です$O(a + b)$または$O((a + b)\log(a + b))$。 いっぱい$O(a b)$スキャンは約$10^8$、これは Python では限界か遅すぎます。 

微妙なエッジケースは、対角線が完全に長方形の外側にある場合です。 非常に小さい場合$K$、セルは含まれません。 非常に大きい場合$K$、長方形全体が含まれます。 もう 1 つの重要なケースは、複数の連続した値が存在する場合です。$K$満たすグリッド点がないため、新しいセルは追加されません$i + j = K$; これらの範囲内では、有効な構成の数は複数にまたがる可能性があります。$K$値は正しく数えられる必要があります。 

## アプローチ

 強引な解釈では、制約の下で有効な単調形状を選択するためにあらゆる方法が試みられます。 有効な「接頭辞が閉じた」形状に限定したとしても、依然として、オブジェクト内のすべての単調境界を列挙する必要があります。$a \times b$グリッド。 各境界は右上隅から左下隅までの単調な格子パスに対応するため、その数は組み合わせ的に増加します。 このようなパスの数は指数関数的に増加します。$a + b$、ブルートフォースが実行不可能になります。 

重要な構造的観察は、2 番目の条件により、単調形状のファミリー全体が 1 パラメーターのファミリーに崩壊するということです。 任意の階段境界の代わりに、境界は単一の対角線上に正確に存在する必要があります。$i + j = K$。 これにより、すべての組み合わせの自由が失われます。各有効な構成は、選択することによってのみ決定されます。$K$。 

この縮小が行われると、問題は純粋に算術的なものになります。 それぞれについて$K$を満たす格子点の数を計算します。$i + j \le K$。 このカウントは単調です$K$、それで、次はいくつあるかを調べます。$K$値は正確に生成します$N$。

 ## アルゴリズムのチュートリアル

 斜めのカットの下にある格子点を数えるという観点から問題を書き直します。 固定の場合$K$と定義します。$f(K)$整数ペアの数として$(i, j)$そのような$1 \le i \le a$、$1 \le j \le b$、 そして$i + j \le K$。 

### ステップ

 1. 各対角和に何組のペアがあるかを計算します。$t = i + j$。 

それぞれについて$t$、有効なペアの数は、ボックス制約と方程式の両方を満たす整数解の数です。$i + j = t$。 これは 2 つの間隔の標準的なオーバーラップです。 
2. アレイを構築する$s[t]$、 どこ$s[t]$正確に対角線上にあるセルの数を数えます$t$。 

この配列は区分的に線形です。増加し、おそらく長方形の上部で平坦なままになり、その後減少します。 
3.変換$s[t]$プレフィックス合計に変換$f(t)$。 

これにより、レベルで切り取られた三角形領域内のセルの数が得られます。$t$。 
4. 全体を反復処理する$t$から$2$に$a + b$、どこを追跡するか$f(t) = N$。 
5.以来$f(t)$非減少の、任意の連続セグメント$t$値の場所$s[t] = 0$平らな領域を作成します。 プレフィックスの合計が等しい場合$N$そのようなセグメントにわたって、それぞれ$t$そのセグメント内にある構成は有効であり、すべてをカウントします。 

### なぜ効果があるのか

 2 番目の条件により、すべての最大要素が同じ値を共有することが強制されるため、形状から対角線への変換は有効です。$i + j$。 これにより、合計が最大のすべての点のセットとして境界が一意に決定されます。$K$。 すべての有効な構成は、まさにそのような構成の 1 つに対応します。$K$、そして構造の単調性により、無効な形状がカウントされず、有効な形状が見逃されることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    N, a, b = map(int, input().split())
    
    max_sum = a + b
    
    # s[t] = number of (i, j) with i+j = t
    s = [0] * (max_sum + 1)
    
    for t in range(2, max_sum + 1):
        lo_i = max(1, t - b)
        hi_i = min(a, t - 1)
        if lo_i <= hi_i:
            s[t] = hi_i - lo_i + 1
    
    ans = 0
    pref = 0
    
    for t in range(2, max_sum + 1):
        pref += s[t]
        if pref == N:
            ans += 1
    
    print(ans % MOD)

if __name__ == "__main__":
    solve()
```実装の中核は、各対角線上にいくつのグリッド ポイントがあるかを計算することです。 定額の場合$t$、 有効$i$両方を満たさなければなりません$1 \le i \le a$そして$1 \le t - i \le b$、区間交差点に変わります。 次に、プレフィックスの累積により、各対角しきい値までに含まれるセルの数が再構築されます。 

実装の微妙な点は、2D グリッドを明示的に構築しないことです。 すべてが対角線ごとに整数の範囲をカウントすることに還元されるため、ソリューションは線形に保たれます。$a + b$。

 ## 特殊なケース

 重要なエッジケースが次のような場合に発生します。$N = 0$または$N = 1$。 このような状況では、最小の対角線のみが寄与し、答えは複数の対角線が存在するかどうかによって異なります。$K$新しいセルが追加されていない値。 空の対角線が寄与するため、アルゴリズムはこれを自然に処理します。$s[t] = 0$、フラットなプレフィックス領域を作成します。 

もう一つのケースは次のような場合です。$N = a \cdot b$、つまり、長方形全体を塗りつぶす必要があります。 これは次の場合にのみ発生します$K \ge a + b$、したがって、最後のプレフィックスの合計のみが等しくなります$N$、有効な構成が 1 つだけ生成されます。
