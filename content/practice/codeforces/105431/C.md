 ## 解決策
 ## 問題の理解

 タスクは単一の整数を取得することです$N$、音楽のリズムのビートの合計数を表し、小さな構成要素の合計として表します。 各構成要素のサイズは 2 または 3 でなければならず、それらの合計は正確に次のようになっている必要があります。$N$。 出力は単なる合計ではなく、明示的な分解です。最初に使用されているブロックの数、次にブロック サイズのリストが表示されます。 

より厳密に考えると、「有効なリズムのグループ化」という意味ではすべての分解が許可されるわけではないため、構造が重要になります。ただし、この問題では、制約は 2 と 3 のみを使用するように単純化されています。 唯一の要件は、選択した 2 と 3 のマルチセットの合計が正確に一致することです。$N$。 

制約$N \le 10^6$これは、線形または定数時間の構築が必要であることを意味します。 2 ブロックと 3 ブロックのすべての組み合わせを検索しようとすると、組み合わせが爆発的に増加します。 2 と 3 のすべてのシーケンスを総当たり的に列挙しようとすると、候補の数は次のように指数関数的に増加します。$N$、各位置は 2 つの選択肢に分岐する可能性があり、可変長のシーケンスが必要になるためです。 

ケアせずに貪欲に考えると、微妙なエッジケースが現れます。 可能な限り常に 3 を選択し、最後に実現可能性をチェックすると、たとえ解決策が存在していても、局所的に失敗する可能性があります。 たとえば、$N = 7$、取る$3 + 3$1 が残りますが、これは修正できませんが、$3 + 2 + 2$有効です。 パリティを修復しない素朴な貪欲さは、これらのケースで破綻するでしょう。 

もう 1 つのエッジ ケースは、有効な入力が最小であることです。 のために$N = 2$、ブロックは 1 つだけ可能です。 のために$N = 3$、1ブロックのみも可能です。 不正なループや負の剰余ロジックを回避するには、これらの基本ケースを適切に処理する必要があります。 

## アプローチ

 ブルートフォースアプローチでは、合計が次の値に等しい 2 と 3 のすべてのシーケンスを構築しようとします。$N$。 これを形式化する 1 つの方法は、各ステップで 2 または 3 を減算し、ゼロに達するまで継続する再帰関数です。 これは、最大の深さのバイナリ ツリーを探索します。$N/2$、最小ステップは 2 であるため、再帰状態の数はおおよそ次のように増加します。$O(2^{N/2})$、次のような中程度の値であっても完全に実行不可能になります。$N = 50$。 

重要な点は、これは意味のある意味での検索の問題ではないということです。 すべての有効な分解は、単純な線形方程式を解くことに対応します。$$2x + 3y = N$$負でない整数の場合$x, y$。 すべての解決策を見つける必要はありません。解決策は 1 つだけです。 これにより、問題は組み合わせの探索から構成的数論に移ります。 

2 と 3 の構造は連続する整数であるため重要であり、すべての表現可能性が保証されます。$N \ge 2$。 この構造はパリティ調整の問題になります。3 のみを使用するのがほぼ最適であり、2 は残ったパリティを修正するためにのみ使用されます。$N \mod 3 = 1$。 

したがって、貪欲に 3 秒を取得し、残りをローカルに調整することで、単一パスでソリューションを構築できます。

 ## アルゴリズムのチュートリアル

 3 の数を最大化し、無効な剰余を修正することで分解を構築します。 

1. 完全な 3 ブロックがいくつ収まるかを計算します。$N$、初期設定$y = N // 3$。 残りはこうしましょう$r = N \mod 3$。 3 ではブロック数が最小限に抑えられるため、これによりほぼ最適な開始点が得られます。 
2. もし$r = 0$、終わりました。 分解は次のもののみで構成されます。$y$3個のブロック。 
3. もし$r = 1$の場合、1 の余りは 2 と 3 を使用して表すことができないため、現在の構造は無効です。 1 つの 3 を 2 つの 2 に変換することでこれを修正します。 これにより、合計が 3 減って 4 が加算され、実質的に残りが 1 から 4 にシフトされ、2 つの 2 として表現できます。 
4. もし$r = 2$、残りは直接使用できるため、単純に 2 の 1 つのブロックを分解に追加します。 
5. 最後に、集めた 3 と 2 をすべて出力します。 

重要な設計上の選択は、このシステムの唯一の障害である剰余 1 の補正ステップです。 

### なぜ効果があるのか

 不変条件は、残りを処理した後のすべての段階で、選択されたブロックの合計が次の値に等しいということです。$N$、すべてのブロックは 2 または 3 です。唯一の問題のある剰余は 3 を法とする 1 であり、1 つの 3 を 2 つの 2 に置き換える変換は、制御された方法でモジュラー構造を変更しながら総和を保持します。 2 と 3 は 2 以上のすべての整数を生成するため、有効なすべての整数が生成されます。$N$に到達可能であり、調整により無効な残基に陥ることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input().strip())

threes = n // 3
rem = n % 3

res = []

if rem == 0:
    res = [3] * threes
elif rem == 1:
    if threes >= 1:
        threes -= 1
        res = [3] * threes + [2, 2]
    else:
        res = [2] * (n // 2)
elif rem == 2:
    res = [3] * threes + [2]

print(len(res))
print(*res)
```このコードは、前述した貪欲な構造を直接実装しています。 剰余ロジックは明示的に処理され、剰余 1 の特殊なケースでは、1 つの 3 ブロックを犠牲にすることで実現可能性が保証されます。 3 が残っていないフォールバック ケースでは、次のような小さな値の正確性が保証されます。$N = 2$または$N = 4$。 

出力の順序は重要ではないため、すべての 3 を最初にグループ化し、次に 2 をグループ化するだけで十分であり、実装が簡単になります。

 ## 特殊なケース

 のために$N = 2$、アルゴリズムは剰余を入力します$2$3 がゼロの場合。 1 つの 2 を直接出力し、調整ロジックをトリガーせずに有効性を維持します。 

のために$N = 4$、最初の貪欲は 1 つ 3 と残り 1 を与え、これにより修正ステップがトリガーされます。 アルゴリズムは 1 つの 3 を 2 つの 2 に変換し、$2 + 2$。 これにより、残り 1 の修正が唯一の重要な障害をきれいに処理していることが確認されます。 

のために$N = 5$1 つの 3 と残りの 2 から始めます。アルゴリズムの出力は次のとおりです。$3 + 2$、構造の変更を必要としない単純な組み合わせを示し、直接剰余 2 分岐の正しさを検証します。
