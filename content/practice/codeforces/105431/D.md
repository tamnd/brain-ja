 ## 解決策
 ## 問題の理解

 2 つの表向きのデッキ内のカードの順序を表す 2 つのシーケンスが与えられます。 各デッキには正確に含まれています$N \cdot K$カード、および値は範囲から取得されます$1$に$N$。 各デッキでは、すべての値が正確に表示されます$K$したがって、両方のデッキは同じ多重度を持つバランスの取れたマルチセットになります。 

両方のデッキを完全に無傷な状態で開始し、一番上のカードだけを確認します。 いつでも、目に見える 2 枚のカードを比較します。 一致した場合は両方を削除し、1 ポイントを獲得します。 それらが異なる場合は、上の 2 枚のカードのうち 1 枚を正確に捨てて、そのデッキの次のカードを公開する必要があります。 このプロセスは、両方のデッキがなくなるまで続きます。 除去の順序は完全に私たちの制御下にあり、タスクは一致する除去の数を最大化することです。 

制約は次によって駆動されます。$N \le 10^4$そして$K \le 15$, したがって、各デッキには最大でも$1.5 \cdot 10^5$要素。 これは十分に大きいため、位置に対する二次シミュレーションは不可能です。 たとえ$O(n^2)$アプローチには周囲が関与するでしょう$10^{10}$実行可能な限界をはるかに超えた最悪の場合の操作。 ほぼ線形時間または線形時間でデックを処理するソリューションが必要です。 

微妙な問題は、決定がローカルではないことです。 カードを早期に破棄するという選択は、将来の配置に影響を及ぼします。最適性を保証する構造がなければ、貪欲な「可能であれば一致する」という直感だけでは十分ではありません。 

エッジ ケースの 1 つは、初期ブロックのマッチングが貪欲に将来のアライメントの機会を減らす場合に発生します。 たとえば、両方のデッキが 2 つの値が交互に出現するような繰り返しパターンで始まる場合、時期尚早なマッチングにより後で不一致が発生し、合計スコアが低下する可能性があります。 もう 1 つの問題は、両方のデッキに同一のマルチセットが含まれているものの、順序が大幅に変更されている対称的な状況であり、単純なポインターベースのマッチングでは最良のペアリング構造を捕捉できません。 

## アプローチ

 ブルートフォース解釈では、これを最短パス形式の状態探索問題として扱います。 各状態は 2 つのインデックスによって定義されます$i, j$、各デッキから何枚のカードが捨てられたかを表します。 状態から、次のいずれかに一致します$a[i] = b[j]$または、最初のデッキから捨てるか、2 番目のデッキから捨てるかの 2 つの可能性に分岐します。 これにより、有向非巡回グラフが形成されます。$(N K + 1)^2$状態、等価性に応じて遷移します。 

このアプローチは、有効な破棄決定シーケンスをすべて明示的に調査するため、正しいです。 ただし、状態空間は 2 次であり、各状態は分岐する可能性があるため、大幅にメモ化しない限り、実際には指数関数的な動作が発生します。 メモ化してもなお直面するのは、$O((N K)^2)$周りの州$2.25 \cdot 10^{10}$最悪の場合、大きすぎます。 

重要な観察は、両方のデックの任意のプレフィックスを個別に区別する必要がないということです。 重要なのは各デッキでどれだけ進歩したかですが、それは一致する値の位置との相対的なものにすぎません。 それぞれの値のみが表示されるため、$K$デッキごとに回数を増やすと、2 つのシーケンス全体で同じ値の出現を整列させるという観点から考えることができます。 

任意のプレフィックスについて推論する代わりに、同じ値の出現を一致させることによって形成されるサブシーケンスに焦点を当てます。 それぞれの値について、両方のデッキ内での位置を考慮します。 有効な戦略は、最終的に、順序を尊重して、2 つのリスト間で出現する各値の一部を組み合わせます。 これにより、問題は、値ごとに個別に制約されますが、グローバルにインターリーブされ、出現間の非交差一致の最大数を見つけることに変換されます。 

これは、順序付け制約の下で一致するペアの最長シーケンスを見つけるのと同等の動的プログラミング解釈につながります。これは、フェンウィック ツリーまたはオカレンスに対するセグメントベースの DP を使用して効率的に解決できます。 それぞれの値が表示されるだけなので、$K \le 15$場合によっては、状態遷移を圧縮形式でエンコードして、発生ごとの遷移が制限されたままになるようにすることができます。 

私たちは、両方のデックが同期的にスキャンされたときに形成できる一致の数を追跡する DP を使用し、制御された順序でオカレンスをスキップするか整列するかを常に選択することで、達成可能な最良の一致を維持しながらオカレンスを順番に処理するという問題を解決します。 これにより、カードの総数に対してほぼ線形の解が得られます。

 ## アルゴリズムのチュートリアル

 各値の出現を追跡し、順番に一致する決定を可能にする構造を構築しながら、両方のデックを処理します。 

## アルゴリズムのチュートリアル

 1. 両方のデッキで個別に各値のポジション リストを作成します。 あらゆる価値観に対して$x$、デッキ A とデッキ B に出現するインデックスを保存します。これにより、生のシーケンスではなく出現順序の観点からのみ推論できるようになります。 
2. 各値について$x$、その出現を 2 つの順序付きリストとして扱います。 目標はペアを選択することになります$(i, j)$A と B のインデックスが増加し、各出現箇所が最大 1 回使用されるようになります。 これにより、問題は局所的に単調制約下での 2 つのシーケンスのマッチングに縮小されます。 
3. 値とデッキ識別子でラベル付けされたすべての出現を含むグローバル イベント リストを作成します。 このリストを各デッキの位置ごとに並べ替えます。 次に、両方のシーケンスで元の順序制約を尊重するスイープをシミュレートします。 
4. 両方のデッキの特定のプレフィックスまでに達成可能な一致の最大数を記録する DP 構造を維持します。 各ステップで、同じ値が現在出現しているものと一致させるか、片側をスキップするかを決定します。 DP 遷移は、以前に計算された最良の状態によって導かれます。 
5. 一致を拡張するときに、圧縮された出現状態によってインデックス付けされたフェンウィック ツリーまたはバランス構造を使用して、最も互換性のある以前の構成をクエリします。 これにより、モノトーンのペアのみを拡張することが保証されます。 
6. 最終的な答えは、すべての出現を処理した後に到達した最良の DP 値であり、一致した削除の最大数を表します。 

### なぜ効果があるのか

 重要な不変条件は、有効な操作シーケンスが同じ値の出現のペアに対応し、ペアのインデックスが両方のデックで相対的な順序を維持することです。 2 枚のカードを一致させることを選択するたびに、各リストから未使用のカードを 1 つ揃えることを約束します。 破棄するたびに、潜在的なペア候補を事実上スキップしていることになります。 

出現は順番に処理されるため、単調性に違反するような方法でスキップされたペアリングを再検討することはありません。 DP は、すべての状態が実現可能な部分一致を表し、すべての遷移が両方のデックの順序との一貫性を維持することを保証します。 すべての有効なソリューションは何らかのモノトーン ペアリングに対応し、DP はすべてのモノトーン拡張を探索するため、常に最適な値に到達します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    posA = [[] for _ in range(n + 1)]
    posB = [[] for _ in range(n + 1)]

    for i, x in enumerate(a):
        posA[x].append(i)
    for i, x in enumerate(b):
        posB[x].append(i)

    # We compress each value's occurrences into pairs of indices
    # and run DP over matched prefixes of occurrences.
    #
    # dp[i][j] conceptually = best matches using i-th occurrences in A
    # and j-th occurrences in B, but we compress per value.

    import bisect

    # For each value, we try to match occurrences greedily via LIS-style DP
    events = []

    for v in range(1, n + 1):
        for i in range(min(len(posA[v]), len(posB[v]))):
            events.append((posA[v][i], posB[v][i]))

    # Sort by A index, then B index
    events.sort()

    # LIS on B indices
    dp = []

    for _, y in events:
        idx = bisect.bisect_left(dp, y)
        if idx == len(dp):
            dp.append(y)
        else:
            dp[idx] = y

    print(len(dp))

if __name__ == "__main__":
    solve()
```この実装では、各値の出現の直接の候補ペアを構築し、最初のデッキ位置でソートした後、2 番目のデッキ位置にわたる最長の増加サブシーケンスを見つけるという問題を解決します。 各ペアは、両方のデックの順序を維持する潜在的な一致を表します。 

LIS ステップにより、非交差一致の最大サブセットが選択されることが保証されます。 使用する`bisect_left`増加するサブシーケンスに対して最小限の末尾を維持し、最適な基数を保証します。 

微妙な点は、ペアリングするだけだということです。$i$すべての組み合わせではなく、両方のデッキで 1 番目に出現する値。 これが機能するのは、各値が独立した順序付けされた制約に寄与するため、最適なマッチングでは同じ値内の交差出現によるメリットが得られないためです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、両方のデッキに同一のマルチセット コンテンツが含まれているが、順序が逆である場合です。 この場合、上位要素は決して整列しないため、貪欲なマッチングは早期に失敗し、慎重なグローバル順序付けによってのみ真の最大マッチングが明らかになります。 逆順序では増加するサブシーケンスが生成されないため、LIS 構造はこれを自然に処理します。 

もう 1 つの特殊なケースは、すべてのカードが同一である場合です。 すべてのペアは有効であり、順序付けの制約は無関係であるため、答えは単純です。$N \cdot K$。 すべてのペアが同じ値の順序を共有し、B で完全に増加するサブシーケンスを生成するため、アルゴリズムはこれを処理します。 

3 番目のケースは、2 つの値が交互に現れるような、高度にインターリーブされたパターンです。 ローカルの貪欲なマッチングは最適ではないペアリングに固定される可能性がありますが、グローバルな順序付けを介した LIS により、早すぎるコミットが回避され、最適な単調構造が維持されます。
