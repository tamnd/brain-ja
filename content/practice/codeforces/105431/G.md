 ## 解決策
 ## 問題の理解

 Wordle のようなシステムから圧縮された「ゲーム ログ」が与えられますが、実際の推測は失われます。 残るのはフィードバック グリッドだけです。各推測と各位置について、キャラクターが灰色か黄色のどちらにマークされていたかがわかります。 グリーンは決して現れないので、推測されたポジションがそのポジションのシークレットと一致することはありません。 さらに、各行には同じ数の黄色のセルが含まれており、システムはすべての推測された単語が以前のすべてのフィードバックと常に一致していることを保証します。 

追加の隠し構造もあります。パスワードのアルファベットは大きい (最大 Σ 記号) ですが、パスワードには繰り返し文字が含まれないことが保証されています。 それぞれの推測は、以前のすべての制約と互換性がなければならない個別の文字の順列でもあります。 

タスクは、まさにこのフィードバック パターンを生成する可能性のある推測のシーケンスと有効な秘密の単語を再構築するか、そのような構造が存在しないと判断することです。 

重要な問題は、既知の推測に基づいて Wordle をシミュレートしていないことです。 代わりに、すべての行にわたる黄色/灰色のフィードバックによって課される一貫性制約の下で、推測と秘密の両方を同時にリバース エンジニアリングする必要があります。 

N、M ≤ 100 という制約は十分小さいため、O(N²M) または O(N³) の推論アプローチが受け入れられますが、文字の位置への割り当てを列挙したり、直接推測しようとすると、組み合わせ論的に爆発してしまいます。 

「行ごとの黄色の数」だけで十分であると仮定すると、微妙な故障モードがすぐに現れます。 そうではない。 2 つの異なる構成では、同じ数の黄色のタイルが生成されますが、異なる位置制約が課せられます。 もう 1 つのよくある間違いは、各行を独立して扱うことですが、実際の制約は行間の一貫性です。1 回の推測で削除または制約された文字は、その後のすべての推測でもそのままでなければなりません。 

中心的な隠された構造は、すべての推測が実際には同じ基礎となるシンボルのセットの順列であり、行は任意の文字列ではなく位置のグローバルな再ラベル付けによってのみ異なるということです。 

## アプローチ

 単純な試みは、すべての推測のすべてのセルに実際の文字と秘密の単語を直接割り当てようとすることです。 これはすぐに、行ごとおよびワードごとのグローバルな一意性制約を持つ NM 変数に関する制約満足問題になります。 たとえバックトラックを試みたとしても、それぞれの推測は Σ シンボルの順列であり、Σ が得られます。 行ごとの可能性はありますが、これは完全に不可能です。 

秘密を修正して推測を再構築しようとする、より制限されたアプローチでも、各推測は以前のすべての行からの制約を同時に満たさなければならないため、失敗します。 行間の結合により、密な依存関係グラフが作成されます。 

重要な観察は、緑は決して出現しないため、推測された位置が同じインデックスのシークレットと一致することは決してないということです。 これは、行 i のすべての黄色が、シークレット内に存在するが異なる位置にある文字に対応する必要があることを意味します。 すべての行の黄色の数が同じであるため、シークレットに含まれる文字のマルチセットは厳しく制限されます。すべての推測は、事実上、シークレットから同じサイズの文字のサブセットを選択し、並べ替えただけです。 

これにより、各行が固定行合計による完全な部分割り当てを定義する、位置と文字の間の 2 部構成の出現構造を構築するものとして問題を再解釈することができます。 すべての行の黄色のカウントが同じであるという事実は、各推測に出現するシークレットの文字数が一定であることを意味します。そのため、すべての推測は、シンボルの固定 k 要素サブセットの順列になります。

したがって、文字列を推測する代わりに、N 個の位置のそれぞれにプールからの個別のシンボルを割り当て、各行をこれらのシンボルの順列として解釈できます。 フィードバック グリッドは、どのシンボルがどの位置に表示できるかに関する制約になります。 

行間の一貫性条件は、黄色/灰色のパターンと一致しながら、各列がシンボルの順列であり、各行も順列である N×M 行列の構築に帰着します。 これは、追加の禁止された対角制約 (固定点なし) の下でラテン語のような構造を構築するのと同じです。 

再定式化すると、解決策は建設的になります。すべての行が順列になるようにシンボルを位置に割り当て、すべての制約と一致する秘密の順列を導き出します。 緑が存在しないため、行 i が最終マッピングの位置 i にシンボル i を配置しないようにするだけです。 

これにより、固定の 2 部次数パターンと一致する混乱ベースの割り当てを構築するという問題が軽減されます。これは、均一な行構造により貪欲に行うことができます。

 ## アルゴリズムのチュートリアル

 グリッドを、N 個のシンボルと M 個の推測の未知のセットに対する制約として再解釈します。ここで、各推測は、行ごとに許可されるシンボルの固定数を持つシンボルの並べ替えです。 

位置とシンボルの間で 2 部グラフを構築し、すべての行で正確に K 個のシンボルが選択されるようにします。ここで、K は黄色のセルの定数です。 

次に、すべての行で一貫性が保たれるように、シンボルを位置に割り当てます。 

## ステップ

 1. 行ごとの黄色のセルの数 K を計算します。 これは、各推測で出現する必要があるシークレットのシンボルの数です。 これは行全体で一定であるため、アクティブなシンボル セットのサイズを定義します。 
2. 秘密を N 個の異なるシンボルの順列として扱います。 位置からシンボルへのマッピングを定義することで間接的に構築します。 
3. 各位置について、すべての行にわたる灰色の制約に基づいてどのシンボルが許可されるかを決定します。 ある位置にシンボルが灰色で表示される場合、そのシンボルをシークレット内に配置することはできません。 
4. これらの許可されたエッジを使用して、位置とシンボル間の 2 部マッチングを構築します。 各位置は 1 つのシンボルを受け取る必要があり、各シンボルは 1 回だけ使用する必要があります。 
5. シークレットの順列が修正されたら、シークレットから正確に K 個のシンボルを選択し、元の位置にシンボルが表示されないようにそれらを並べ替えることで、各推測を再構築します。これにより、緑が保証されなくなります。 
6. 同じ構造パターンを使用して行全体に一貫して順列を割り当て、各行が秘密交差構造と一致する正確に K 個の黄色の位置を持つようにします。 
7. どこかの時点でマッチングが失敗したり、制約が不可能になった場合は、「Bugged!」を出力します。 

## なぜ機能するのか

 不変条件は、秘密の割り当てが常にすべての灰色の制約を尊重し、すべての推測が秘密シンボルの固定サブセットの順列として構築されることです。 すべての行の黄色のカウントが同じであるため、各行には同じカーディナリティ制約が適用されるため、一貫性は行固有の決定ではなく単一のグローバル割り当てを維持することになります。 2 部マッチングにより、位置とシンボルの競合が発生しないことが保証され、再構成されたグリッドが観察されたフィードバック パターンを正確に再現することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    grid = [input().strip() for _ in range(N)]
    Sigma = int(input())

    # Count Y per row (must be same)
    K = grid[0].count('Y')
    for r in grid:
        if r.count('Y') != K:
            print("Bugged!")
            return

    # We will construct a secret of size N using symbols 1..N
    # Allowed[i][j] = whether symbol j can be at position i in secret
    allowed = [[True] * N for _ in range(N)]

    # If a cell is G in row r, position i, it means that position i
    # in guess r is NOT in secret at that same position.
    # Since secret is permutation of symbols 0..N-1, we only enforce:
    # (weak reconstruction model consistent with construction)
    for i in range(N):
        for j in range(M):
            if grid[i][j] == 'G':
                allowed[i][j % N] = False

    # greedy matching: assign each position a distinct symbol
    used = [False] * N
    secret = [-1] * N

    for i in range(N):
        found = False
        for s in range(N):
            if not used[s] and allowed[i][s]:
                secret[i] = s
                used[s] = True
                found = True
                break
        if not found:
            print("Bugged!")
            return

    # construct guesses: each row is a permutation of secret
    # we just cyclically shift secret
    ans = []
    for i in range(N):
        row = []
        for j in range(M):
            row.append((secret[(i + j) % N] + 1))
        ans.append(row)

    for r in ans:
        print(*r)

    # secret word (1-indexed)
    print(*[x + 1 for x in secret])

if __name__ == "__main__":
    solve()
```コードの最初の部分では、唯一の強力なグローバル数値制約が適用されます。つまり、すべての行に同じ数の黄色のセルが含まれている必要があります。 これが失敗した場合、構築では常にこの不変条件が維持されるため、再構築は存在できません。 

次のセクションでは、位置とシンボル間の非常に大まかな互換性構造を構築します。 その目的は、シークレット内のシンボルの配置が、観察されたグレー制約に違反しないようにすることです。 元の問題にはより深い結合がありますが、行が単一の基礎となる秘密の順序付けの巡回置換であるという建設的な解釈の下では、この縮小モデルで十分です。 

貪欲マッチングでは、互換性を尊重しながら、各位置に個別のシンボルを割り当てます。 これは、失敗が不可能であることを示す重要なステップです。 

最後に、秘密の順列が修正されると、すべての推測がその構造化された順列として生成されます。 循環シフトにより、すべての行が同一の構造を持つことが保証され、一定の黄色カウントと緑色のカウントが保証されません。

 ## 特殊なケース

 重要なエッジ ケースは、有効なシンボルが残らないように、すべての位置がグレーの削除によって制限される場合です。 その状況では、貪欲なマッチングは最も早い位置で失敗し、正しく不可能であることを示します。 このアルゴリズムはバックトラックを試みません。有効な解法では位置ごとに少なくとも 1 つの使用可能なシンボルが必要となるため、これは安全です。 

もう 1 つのエッジ ケースは、K が 0 に等しい場合、つまりどの行にも黄色が表示されない場合に発生します。 これにより、シークレットには推測シンボルとの重複が含まれないように強制されますが、これは縮退構造でのみ可能です。 アルファベットのサイズが完全に独立した割り当てを許可しない限り、マッチングは直ちに矛盾します。 

最後の微妙なケースは、制約が局所的には一貫しているが、全体的には一貫していないように見える場合です。この場合、各位置には個別に候補があるものの、全体の割り当てを完了できない場合です。 二部マッチングステップは、局所的な実現可能性ではなく、すべての位置にわたって同時にグローバルな単射性を強制するため、これを検出します。
