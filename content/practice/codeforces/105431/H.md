 ## 解決策
 ## 問題の理解

 ラテン文字の大文字と小文字で構成される単一の文字列が与えられます。 概念的には、以前の問題は、この文字列のすべての個別の部分文字列を列挙し、各部分文字列を元の文字列に出現する回数とともに出力します。 

問題は、部分文字列を列挙することではなくなりました。 実際のひねりは、最終的に何が検証されるかにあります。 審査員は、これらの部分文字列リストの正確な形式の出力をチェックしません。 代わりに、最終的な印刷出力に各文字が何回出現するかのみを考慮します。 さらに、出力はチェックされる前にランレングス エンコーディングを使用してさらに変換されます。 したがって、実際のタスクは、このすべての変換の後、最終的に出力されるテキストに各 ASCII 文字が何回出現するかを決定することです。 

したがって、計算は部分文字列の出力に関するものではなくなりました。 それは、仮想の完全な部分文字列リストがどのように巨大な文字列に拡張されるか、ランレングス エンコーディングがそれをどのように圧縮するか、そしてその圧縮後に最終的な文字頻度がどのように動作するかを理解することです。 

入力サイズは最大 1e6 まで可能で、明示的に部分文字列を列挙したり、出力構造をシミュレートしたりするアプローチは即座に除外されます。 部分文字列の数だけでも 2 次であるため、直接展開することは不可能です。 完全な出力文字列を構築するという観点から考えることさえ、メモリや時間の制限をはるかに超えてしまうため、実行不可能です。 

出力には部分文字列の文字と、10 進文字列として書き込まれた出現回数の数字の両方が含まれるという事実から、微妙な問題が発生します。 単純な実装では、数字の寄与を無視するか、無視できるものと想定しますが、サンプルは、数字が最終的な度数分布の重要な部分であることを示しています。 

隠れた主な問題は、すべての部分文字列が独自のテキストに加えて、その出現数のテキスト表現を提供することです。 どちらの部分も文字の頻度に影響を与えるため、部分文字列を明示的に生成せずに両方を考慮する必要があります。 

## アプローチ

 ブルート フォース戦略では、すべての部分文字列を明示的に列挙し、元の文字列内での出現回数をカウントし、部分文字列のテキストを追加し、カウントの 10 進数表現を追加し、すべてを連結し、最後にランレングス エンコードとそれに続く文字数のカウントをシミュレートします。 

O(n^2) 個の部分文字列が存在するため、これはすぐに失敗します。また、単一の部分文字列の出現数のカウントを最適化できたとしても、すべての部分文字列を反復すると、n が 1e6 までの実行可能な制限をすでに超えてしまいます。 出力文字列自体の構築は天文学的に大きくなります。 

重要な点は、実際には部分文字列を明示的に構築する必要がないということです。 集計された貢献のみが必要です。 

各部分文字列は、その文字を複数回出力に提供します (印刷リストでは 1 回だけ)。 各部分文字列には、元の文字列内の頻度に対応する数字も含まれます。 ランレングス エンコーディング ステップでは、文字の総頻度は変更されません。同一の連続文字がグループ化されるだけで、文字の削除や作成は行われません。 したがって、各文字の最終的な頻度は、RLE 拡張前の出力文字列内の頻度と同じになります。 

これにより、ランレングス エンコーディングを完全にシミュレートする必要がなくなりました。 問題は、概念的な完全な部分文字列リストの出力に各文字がどのくらいの頻度で現れるかを計算することに帰着します。 

ここで、出力を 2 つの部分に分割します。 まず、すべての部分文字列テキスト。 次に、それらの出現回数をすべて 10 進数で表現します。

部分文字列のテキスト投稿については、視点を部分文字列から位置に切り替えることができます。 文字列内の各位置 i は、正確に i * (n - i + 1) 個の部分文字列に現れます。 このようなすべての部分文字列は、その文字を出力に 1 回だけ提供します。 これにより、文字に対する直接的な O(n) 寄与式が得られます。 

数値の寄与については、出現回数 k を持つ部分文字列の数を k ごとに数え、k の桁頻度を考慮する必要があります。 これは、サフィックス オートマトンを使用して処理できます。サフィックス オートマトンでは、各状態が、同じエンド位置セット、したがって同じ出現数を共有する部分文字列をグループ化します。 各状態は部分文字列の長さの範囲に寄与し、その状態のすべての部分文字列は occ[v] の桁を 1 回だけ寄与します。 

この分離により、明示的に列挙することなくすべてを集約できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 部分文字列の総当たり列挙 | O(n² 以上) | O(n²) | 遅すぎる |
 | サフィックスオートマトン + 集計カウント | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 部分文字列の貢献

 1. 文字列内の位置 i ごとに、それが含まれる部分文字列の数 (i * (n - i + 1)) を計算します。 

これは、左端点 (i 個の選択肢) と右端点 (n - i + 1 個の選択肢) の選択肢をカウントします。 このような各部分文字列は、位置 i にある文字のコピーを 1 つだけ提供します。 
2. この寄与を対応する文字の頻度に加算します。 

これにより、出力の部分文字列名内に出現するすべての文字が完全に考慮されます。 

### サフィックスオートマトンを使用した部分文字列頻度のグループ化

 1. 文字列の接尾辞オートマトンを構築します。 

各状態は、同じエンド位置セットを共有する部分文字列のセットを表します。 
2. 各状態 v の occ[v] を計算します。これは、その状態によって表される終了位置の数です。 

この値は、状態によって表されるすべての部分文字列の出現数とまったく同じです。 
3. 各状態について、len[v] - len[link[v]] を使用して、それが表す部分文字列の数を決定します。 

これにより、その状態に対応する個別の部分文字列の数が得られます。 
4. このような部分文字列ごとに、occ[v] の 10 進表現が出力に 1 回だけ提供されます。 

したがって、occ[v] の桁頻度カウントに、状態内の部分文字列の数を乗算する必要があります。 

### 数字の集計

 1. 各状態 v について、occ[v] の桁を抽出し、そのカウントに状態区間内の部分文字列の数を乗算して加算します。 
2. すべての州からの桁の寄与を結合して、合計桁頻度を取得します。 

### 最終出力

 1. 文字と数字の頻度を集計した後、少なくとも 1 回出現するすべての文字を ASCII 順にソートして出力します。 

### なぜ効果があるのか

 重要な不変条件は、元の文字列のすべての部分文字列がちょうど 1 つの接尾辞オートマトン状態間隔に属し、その間隔内のすべての部分文字列が同じ出現数を共有することです。 これにより、オートマトンの状態によるグループ化で部分文字列が欠落したり二重にカウントされたりしないことが保証されます。 ランレングス エンコーディングでは文字の多重度の合計が維持されるため、最終的な答えを得るには、圧縮前に頻度を計算するだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

class SuffixAutomaton:
    def __init__(self, s):
        self.next = []
        self.link = []
        self.len = []
        self.occ = []
        self.last = 0

        self.next.append({})
        self.link.append(-1)
        self.len.append(0)
        self.occ.append(0)

        for ch in s:
            self.extend(ch)

        for i in range(len(self.next)):
            self.occ[i] = 0
        v = 0
        for i, ch in enumerate(s):
            v = self.transition(v, ch)
            self.occ[v] += 1

        order = sorted(range(len(self.len)), key=lambda x: self.len[x], reverse=True)
        for v in order:
            if self.link[v] != -1:
                self.occ[self.link[v]] += self.occ[v]

    def extend(self, c):
        cur = len(self.next)
        self.next.append({})
        self.len.append(self.len[self.last] + 1)
        self.link.append(0)
        self.occ.append(0)

        p = self.last
        while p != -1 and c not in self.next[p]:
            self.next[p][c] = cur
            p = self.link[p]

        if p == -1:
            self.link[cur] = 0
        else:
            q = self.next[p][c]
            if self.len[p] + 1 == self.len[q]:
                self.link[cur] = q
            else:
                clone = len(self.next)
                self.next.append(self.next[q].copy())
                self.len.append(self.len[p] + 1)
                self.link.append(self.link[q])
                self.occ.append(0)

                while p != -1 and self.next[p].get(c) == q:
                    self.next[p][c] = clone
                    p = self.link[p]

                self.link[q] = self.link[cur] = clone
        self.last = cur

    def transition(self, v, s):
        while v != -1 and s not in self.next[v]:
            v = self.link[v]
        if v == -1:
            return 0
        return self.next[v][s]

def digits(x):
    return list(str(x))

def solve():
    s = input().strip()
    n = len(s)

    freq = defaultdict(int)

    for i, ch in enumerate(s, 1):
        freq[ch] += i * (n - i + 1)

    sa = SuffixAutomaton(s)

    for v in range(len(sa.next)):
        if v == 0:
            continue
        cnt_states = sa.len[v] - sa.len[sa.link[v]] if sa.link[v] != -1 else sa.len[v]
        if sa.occ[v] == 0 or cnt_states <= 0:
            continue
        d = digits(sa.occ[v])
        for ch in d:
            freq[ch] += cnt_states

    for c in sorted(freq.keys()):
        print(c, freq[c])

if __name__ == "__main__":
    solve()
```コードの最初の部分では、直接位置の組み合わせを使用して、部分文字列内の文字からの寄与を計算します。 次に、サフィックス オートマトンは、各出現回数に対応する部分文字列の数を集計し、それに応じて桁の寄与を分配します。 

微妙な点は、部分文字列を明示的に構築しないことです。 すべての寄与は、位置的包含数またはオートマトン状態のグループ化のいずれかから導出されます。

 ## 特殊なケース

 次のような単一文字列の場合`"a"`、位置式は 1 * 1 = 1 を与え、それを超える部分文字列周波数の複雑さはありません。 オートマトンには意味のある状態が 1 つだけあり、桁の寄与は最小限のままです。 

次のような均一な文字列の場合`"aaaaa"`、すべての部分文字列は重度の重複を共有し、多くの同一の周波数グループを作成します。 接尾辞オートマトンは、すべての部分文字列を同一の endpos セットに正しくマージし、出現回数が二重にカウントされないようにします。
