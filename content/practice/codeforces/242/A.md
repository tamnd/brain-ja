 ## 解決策
 ## 問題の理解

 各プレイヤーがコインを投げた回数がわかります。 ヴァシャはひっくり返った`x`回とペティアがひっくり返った`y`回。 すべての表には 1 ポイントが与えられますが、すべての裏には何も与えられません。 

ヴァレラさんは正確な最終スコアを覚えていませんが、3 つの事実を覚えています。 Vasyaは少なくとも`a`頭、ペティアは少なくとも得た`b`頭で、ヴァシャはペティアよりも厳密に先にゴールした。 

すべてのペアを印刷する必要があります`(c, d)`次のような:

 -`c`Vasya の可能な頭の数です
 -`d`Petya の可能な頭の数です。 
-`a ≤ c ≤ x`-`b ≤ d ≤ y`-`c > d`出力ペアは辞書編集上の昇順で表示される必要があります。 つまり小さいということです`c`が最初に来て、平等に`c`、小さい`d`が最初に来ます。 

制約はわずかです。 すべての値は最大でも`100`。 考えられるすべてのペアをチェックする場合でも、必要なのはせいぜい`101 × 101 = 10201`反復回数は 2 秒の制限ではまったく簡単です。 これは、直接の総当たり列挙を直ちに示唆します。 

この問題における唯一の本当の危険は、不等式または反復範囲を間違えることです。 

簡単な間違いの 1 つは、引き分けを許すことです。 Vasya が勝者でなければならないため、条件は厳密です`c > d`、 ない`c ≥ d`。 

次の入力を考えてみましょう。```
2 2 1 1
```考えられるスコアは次のとおりです。```
2 1
2 2
1 1
1 2
```のみ`(2, 1)`Vasya は Petya よりも多くの頭を持つ必要があるため、これは有効です。 を使用した不注意な実装`>=`誤って含めてしまいます`(1,1)`そして`(2,2)`。 

もう 1 つの微妙なケースは、Petya の最小スコアがほとんどの Vasya スコアに対してすでに大きすぎる場合に発生します。 

例：```
3 5 1 4
```Petya は常に少なくとも`4`頭。 Vasya が持つことができるのは最大でも`3`。 有効な結果が存在しないため、正しい出力は次のようになります。```
0
```勝者の条件をチェックせずに、範囲内のすべてのペアを盲目的に出力する不用意な解決策は、ここでは失敗します。 

注文も重要です。 ペアはすでに辞書順にソートされている必要があります。 繰り返すと`c`小さいものから大きいものまで、それぞれに`c`反復する`d`小規模から大規模まで、生成された注文は自動的に要件を満たします。 

## アプローチ

 最も簡単なアプローチは、考えられる最終スコアのペアをすべて試してみることです。 

Vasya のスコアの範囲は次のとおりです。`a`に`x`。 Petya のスコアの範囲は次のとおりです。`b`に`y`。 すべてのペアについて`(c, d)`これらの範囲内で、`c > d`。 「はい」の場合、そのペアを保存します。 

すべての有効なゲーム結果がこれらの範囲内の 1 つのペアに正確に対応し、出力されたすべてのペアがステートメントのすべての条件を満たすため、この総当たり手法は正しいです。 

ブルートフォースアプローチはすでに制限内に問題なく収まっています。 最悪の場合でも約 1 万足をテストしますが、これは無視できる程度です。 

検索スペースはすでに非常に小さいため、ここでは隠れた最適化トリックはありません。 実際の観察は、制約が意図的に小さいため、直接実装することが意図された解決策であることを認識することです。 数式や複雑な枝刈りを導出しようとすると、意味のある方法でパフォーマンスが向上することはなく、コードが読みにくくなるだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース列挙 | O((x - a + 1)(y - b + 1)) | O(回答数) | 承認済み |
 | 最適化された数学的導出 | O(回答数) | O(回答数) | 不要 |

 ## アルゴリズムのチュートリアル

 1. 4 つの整数を読み取ります`x`、`y`、`a`、 そして`b`。 
2. 空のリストを作成する`ans`すべての有効なスコアペアを保存します。 
3. Vasya の可能なスコアを反復する`c`から`a`に`x`。 

これらはすべて、ヴァシャが少なくとも得点したというヴァレラの記憶と一致する値です。`a`表であり、フリップの数を超えることはできません。 
4. それぞれについて`c`、Petya の可能なスコアを反復します。`d`から`b`に`y`。 

これらはすべて、Petya が記憶している下限と一致する値です。 
5. かどうかを確認します。`c > d`。 

Vasyaは厳密にゲームに勝たなければなりません。 同点は引き分けに相当するため、含めてはなりません。 
6. 条件が成立する場合は追加します。`(c, d)`回答リストへ。 
7. 保存されているペアの数を出力します。 
8. すべてのペアを生成された順序で印刷します。 

なぜなら`c`最初に増加し、`d`2 番目に増加すると、出力は自動的に辞書順に並べ替えられます。 

### なぜ効果があるのか

 このアルゴリズムは、記憶されている下限とコイン投げの回数によって課せられる物理的制限を満たすすべての可能なスコアのペアを検査します。 

各ペアについて、問題から正確な勝利条件をチェックします。 実行可能な結果はすべてネストされたループのどこかに表示されるため、有効なペアを見逃すことはできません。 Vasya のスコアが Petya のスコアより厳密に大きいペアのみを追加するため、無効なペアは出力されません。 

反復順序により、辞書編集上の順序が自動的に保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    x, y, a, b = map(int, input().split())

    ans = []

    for c in range(a, x + 1):
        for d in range(b, y + 1):
            if c > d:
                ans.append((c, d))

    print(len(ans))

    for c, d in ans:
        print(c, d)

solve()
```プログラムは上記のアルゴリズムに直接従います。 

外側のループは、Vasya のすべての可能なスコアを反復します。 内部ループは、Petya のすべての可能なスコアを反復処理します。 条件`c > d`Vasya が勝つ要件と完全に一致します。 

範囲は使用します`x + 1`そして`y + 1`なぜならパイソンの`range`上部の終点は除外されます。 を忘れて`+1`可能な最大スコアを誤ってスキップしてしまう可能性があります。 

最初の出力行には有効なペアの合計数が含まれている必要があるため、回答は印刷前に保存されます。 その数は列挙が終了した後にのみわかります。 

順序付けの要件はループ構造によって自然に処理されます。 以来`c`単調増加し、`d`固定ごとに単調増加`c`、生成されたシーケンスはすでに正しくソートされています。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    x, y, a, b = map(int, input().split())

    ans = []

    for c in range(a, x + 1):
        for d in range(b, y + 1):
            if c > d:
                ans.append((c, d))

    out = [str(len(ans))]

    for c, d in ans:
        out.append(f"{c} {d}")

    print("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output

# provided sample
assert run("3 2 1 1\n") == (
    "3\n"
    "2 1\n"
    "3 1\n"
    "3 2\n"
), "sample 1"

# minimum-size input
assert run("1 1 1 1\n") == (
    "0\n"
), "minimum case"

# exactly one valid pair
assert run("2 1 2 1\n") == (
    "1\n"
    "2 1\n"
), "single valid answer"

# no valid outcomes
assert run("3 5 1 4\n") == (
    "0\n"
), "Petya always ahead or tied"

# boundary ordering check
assert run("3 3 1 1\n") == (
    "3\n"
    "2 1\n"
    "3 1\n"
    "3 2\n"
), "lexicographical order"

# maximum-size style case
out = run("100 100 100 100\n")
assert out == "0\n", "largest equal bounds"
