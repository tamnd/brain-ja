 ## 解決策
 ## 問題の理解

 カウンターのグラフが与えられます。各カウンターはゼロから始まり、無向のワイヤーで接続されています。 カウンタのボタンを押すと、それ自体の値が 1 ずつ増加し、直接接続されているすべての近隣の値も 1 ずつ増加します。 

カウンターのサブセットを選択し、選択した各カウンターを 1 回だけ押すことができます。 すべてのボタンを押すと、すべてのカウンタはそれ自体と選択されたすべての隣接カウンタからの増分を蓄積します。 カウンタ i の最終値が指定されたターゲット値 a[i] と等しい場合、そのカウンタは「一致した」とみなされます。 いずれかのカウンターがターゲットに一致すると、ヴァレラは負けます。 どのカウンターも目標値と等しくない場合にのみ勝利します。 

このタスクは、頂点がターゲット値に達しないように押す頂点のサブセットが存在するかどうかを判断し、存在する場合は有効なサブセットを出力することです。 

n、m ≤ 100000 という制約は、どの解もグラフのサイズが線形または線形演算に近くなければならないことを意味します。 エッジまたは頂点上の二次関数はすぐに遅すぎます。 これはまた、すべてのサブセットにわたるグローバル検索は指数関数的であるため、推論は接続コンポーネントごとにローカルまたは構造的である必要があることも示唆しています。 

孤立した頂点が存在する場合、微妙なエッジ ケースが発生します。 頂点の次数が 0 の場合、それを押すとそれ自体に 1 だけ追加され、他の頂点に影響を与えることはできません。 a[i] が 1 の場合、その頂点を押すとすぐに負け条件が作成されます。 逆に、a[i] が 1 でない場合、グローバルな一貫性に応じて役立つ場合もあればそうでない場合もありますが、独立して動作します。 

もう 1 つの注意が必要な状況は、二部構成の伝播効果で発生します。各プレスが隣接するものに対称的に影響を与えるため、システムはコンポーネント全体にわたって線形であるため、実現可能性は局所的な貪欲な選択ではなく、制約全体にわたるパリティと一貫性に依存します。 

## アプローチ

 素朴なアプローチは、頂点のすべてのサブセットを試して、結果の値をシミュレートすることです。 各サブセットは最終値を計算するのに O(n + m) かかり、2^n 個のサブセットがあるため、n = 40 の場合でもこれは完全に不可能になります。 

より構造化された観察は、頂点を押すと、それ自体とすべての隣接頂点に「1」が与えられるということです。 これは、各頂点の最終的な値が、単にその閉じた近傍内で押された頂点の数であることを意味します。 i を押した場合は x[i] を 1、それ以外の場合は 0 と定義すると、i の最終値は次のようになります。 

Final[i] = x[i] + i のすべての近傍 j にわたる x[j] の合計。 

これは整数上の線形システムです。 a[i] と一致させようとしているのではなく、明示的にそれを避けようとしています。 したがって、次のものが必要です。 

すべての i について x[i] + sum(x[j]) ≠ a[i]。 

有効な x を直接検索する代わりに、視点を反転します。 重要な洞察は、グラフをコンポーネントとして解釈し、接続された各コンポーネントを個別に処理することです。 コンポーネント内では、制約が密接に結合されています。 この構造は、問題を決定論的な伝播に還元できるようなものです。単一のノードが押されるかどうかを選択すると、他のすべてのノードは一貫性条件によって決定されます。 

これを考えるのに役立つ方法は、「望ましい不一致」状態を割り当てることです。 各頂点について、選択した構成の下でそれが「安全」か「安全でない」かを定義します。 コンポーネント内の開始決定を修正すると、エッジから導出された方程式を使用して強制的な選択を伝播できます。 各エッジは対称的に寄与するため、隣接する制約間の差異により決定的な関係が生じます。 

核となる縮小点は、システムを各接続コンポーネントのパリティ伝播問題として扱うことができることであり、ルート値の選択によって他の値がすべて一意に決定されます。 次に、結果の代入が禁止されているすべての等式 a[i] を回避しているかどうかを確認します。 割り当てられている場合は、そのコンポーネントの割り当てを受け入れます。 それ以外の場合は、ルートを反転して再試行します。 両方が失敗すると、コンポーネントは使用できなくなります。

これが機能するのは、参照頂点を押すかどうかの選択に対応して、各コンポーネントがコンポーネントごとに 1 つの自由度を持つ一貫した線形システムを誘導するためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^n · (n + m)) | O(n + m) | 遅すぎる |
 | コンポーネントの伝播 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 コンポーネントごとの一貫性の観点から条件を書き直し、接続されたコンポーネントごとにソリューションを構築します。 

1. グラフの隣接リストを作成し、DFS または BFS を使用して接続されているすべてのコンポーネントを識別します。 

これが必要なのは、相互作用がコンポーネントをまたがないため、各コンポーネントを独立して解決できるためです。 
2. 各コンポーネントについて、任意のルート ノードを選択し、暫定的な状態 x[root] = 0 を仮定します。 

この仮定は単なる出発点にすぎません。 システムは線形であるため、コンポーネントごとに 1 つの自由度が存在します。 
3. コンポーネントをトラバースし、押されたノードからの寄与の合計がエッジ全体で一貫していなければならないという制約に基づいて、他のすべてのノードの暗黙の値を計算します。 

具体的には、ルートの選択に関して各ノードの状態を表す派生関係を維持します。 
4. 伝播後、この割り当てに基づいてコンポーネント内のすべてのノードの最終値を計算します。 

このステップでは、final[i] = a[i] を満たすノードがあるかどうかをチェックします。これにより損失が発生します。 
5. 禁止値に一致するノードがない場合は、この割り当てを受け入れ、x[i] = 1 であるすべてのノードを記録します。 

これらはまさにヴァレラがプレスするカウンターだ。 
6. 割り当てが失敗した場合は、根の仮定を反転し (0 ではなく x[root] = 1)、伝播を繰り返します。 

各コンポーネントの 2 進自由度は 1 つだけであるため、可能性は 2 つだけです。 
7. 両方の割り当てによってコンポーネント内で競合が発生する場合は、有効なグローバル ソリューションが存在しないと結論付け、-1 を返します。 

### なぜ効果があるのか

 各接続コンポーネントは、選択したプレスの線形結合によってすべての頂点値が決定されるシステムを定義します。 すべてのエッジが対称的に寄与するため、コンポーネント内の 1 つの変数が固定されると、他のすべての変数が強制されます。 これにより、コンポーネントごとの検索スペースが 2 つのグローバル状態に減少します。 

このアルゴリズムは、考えられる両方の状態をチェックし、条件 Final[i] = a[i] に違反する頂点があるかどうかを検証します。 すべての制約は伝播を通じて直接適用されるため、有効な解決策はこれら 2 つの状態のいずれかで現れる必要があります。 どちらも機能しない場合、そのコンポーネント内で印刷機を割り当てても、禁じられた等価性の生成を回避できず、グローバルな解決策は不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)
    
    a = list(map(int, input().split()))
    
    vis = [False] * n
    parent = [-1] * n
    comp = []

    def dfs(start):
        stack = [start]
        vis[start] = True
        comp_nodes = []
        
        while stack:
            u = stack.pop()
            comp_nodes.append(u)
            for v in g[u]:
                if not vis[v]:
                    vis[v] = True
                    parent[v] = u
                    stack.append(v)
        return comp_nodes

    def evaluate(root_choice):
        x = {}
        for v in comp:
            x[v] = -1
        
        root = comp[0]
        x[root] = root_choice
        
        stack = [root]
        while stack:
            u = stack.pop()
            for v in g[u]:
                if v in x and x[v] == -1:
                    x[v] = x[u]  # consistent propagation
                    stack.append(v)
        
        # compute final values
        ok = True
        final = {}
        for u in comp:
            s = x[u]
            for v in g[u]:
                if v in x:
                    s += x[v]
            final[u] = s
            if final[u] == a[u]:
                ok = False
        
        if not ok:
            return None
        return x

    ans = []

    for i in range(n):
        if vis[i]:
            continue
        comp = dfs(i)

        res0 = evaluate(0)
        if res0 is None:
            res1 = evaluate(1)
            if res1 is None:
                print(-1)
                return
            ans.append(res1)
        else:
            ans.append(res0)

    out = []
    for d in ans:
        for k, v in d.items():
            if v == 1:
                out.append(k + 1)

    print(len(out))
    print(*out)

if __name__ == "__main__":
    solve()
```DFS は、各コンポーネントを独立して解決できるように、グラフを連結コンポーネントに分割します。 各コンポーネントの内部では、`evaluate`関数は、ルートのバイナリ選択を想定し、その選択を近隣ノード全体に伝播します。 各ノードは訪問した近隣ノードからその状態を継承し、コンポーネント全体で一貫した割り当てを構築します。 

伝播後、コードは同じコンポーネント内の各ノードとその隣接ノードからの寄与を合計することによって最終値を再計算します。 いずれかのノードがその禁止値 a[u] に一致する場合、その割り当ては拒否されます。 

最終出力では、すべてのコンポーネントにわたって値 1 が割り当てられたすべてのノードが収集されます。 

実装上の微妙なリスクは、伝播を等価コピーとして扱うことです。 これが機能するのは、コンポーネント内ではシステムの自由度が 1 つまで減少するためです。 このプロパティがないと、単純なコピーは正しくなくなります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、ターゲットが正確に 1 である完全に孤立した頂点です。その場合、それを押すとすぐに値 1 が生成され、損失が発生します。 シングルトン コンポーネントでは両方のルートの選択がテストされ、a[i] が生成されると両方が拒否されるため、アルゴリズムがこれを処理します。 

もう 1 つのエッジ ケースは、一貫性のために交互の割り当てが必要なツリー コンポーネントです。 伝播はコンポーネント内で均一であるため、ノードが禁止値と一致すると、評価中に矛盾が直ちに明らかになり、無効な割り当てが受け入れられなくなります。 

最後のエッジ ケースは、多くの隣接コンポーネントが互いに強化し合う高密度のコンポーネントです。 この場合でも、評価ステップでは最終的な合計が明示的に再計算されるため、構造に関係なく a[i] との偶発的な一致が検出され、正確さが保証されます。
