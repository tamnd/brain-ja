 ## 解決策
 ## 問題の理解

 最大の暗黙的なグリッドが与えられています。$10^9 \times 10^9$ただし、使用できるセルはごく一部です。 使用可能な各領域は、水平セグメント、つまり行番号と列の連続間隔として指定されます。 これらのセグメントを組み合わせると、平面上でアクセス可能なセルのまばらなセットが定義されます。 

キングは 1 つの許可されたセルから開始し、別の許可されたセルに到達したいと考えます。 各移動により、彼は 8 つの隣接するセルのいずれかに移動できますが、その目的のセルも許可されている場合に限ります。 タスクは、そのような移動の最小数を計算するか、ターゲットが到達不可能であると判断することです。 

重要な問題は、グリッドを明示的に構築できないことです。 許可されたすべてのセルを個別に保存することさえ、最悪の場合には実行不可能になります。$10^9$。 ただし、すべてのセグメントで許可されるセルの合計数は最大でも$10^5$つまり、隣接性に注意すれば、問題をこれらのセルのグラフとして扱うことができます。 

この制約により、グリッド全体をスキャンしたり、インデックスを作成せずにセルごとのグローバル BFS を試みたりするアプローチは直ちに除外されます。 理論的には、各セルが同じ行または隣接する行内の多くの近くのセグメントを認識する可能性があるため、ステップごとに明示的な隣接セルに対する単純な BFS も失敗します。 

微妙なエッジケースは、セグメントの重なり方から生じます。 複数のセグメントは同じ行間隔を定義できますが、それらを別々の切断された構造として扱ってはなりません。 もう 1 つのエッジ ケースは、動きが斜めおよび垂直であることです。これは、隣接関係が同じ行内だけでなく、重複またはほぼ重複している列を持つ隣接する行にも存在することを意味します。 

単純な障害シナリオは、重複する間隔での接続が必要な場合です。 

入力:```
(1,1) -> (1,10)
segments:
row 1: [1,3], [4,7], [8,10]
```行が完全にカバーされている場合でも、マージや隣接推論を行わずにセグメントを独立して扱う不注意なアルゴリズムでは、セグメント間の移動は不可能であると誤って判断する可能性があります。 

正しい動作は、これらすべての間隔が順番に接続されているため、行は完全に走査可能です。 

## アプローチ

 ブルート フォース アプローチでは、許可されたすべてのセルがノードとして扱われ、キングに隣接する 2 つのセル間のエッジが接続されます。 これはすでに次のことを示唆しています$10^5$ノード。 各ノードについて、8 方向すべてを直接チェックするには、ハッシュ セットでの座標検索が必要になります。 この部分は実現可能ですが、本当の問題は、単純な隣接拡張が空のスペースを繰り返しスキャンし、行間隔の構造を利用していないことです。 

長いセグメントに沿ってセルごとに移動を拡張しようとすると、さらに深刻な非効率が発生します。 長さのセグメント$L$誘発するだろう$O(L)$完全な連続間隔にわたる移動は圧縮可能である必要があるにもかかわらず、BFS 遷移。 

重要な観察は、行上の連続した間隔内では、すべてのセルが実質的に水平方向の動きと同等であるということです。 各セルを個別に扱う代わりに、各セグメントを構造として扱い、境界または隣接する行との重なり付近でのみセグメント間の遷移を許可する必要があります。 

これにより、問題は、ノードがセグメントに対応し、エッジがジオメトリが近いセグメント間で起こり得るキングの動きを表すグラフに縮小されます。 総セグメント数は$10^5$、並べ替えとスイープの手法を使用して隣接関係を構築できます。 

各セグメントを行ごとにマップし、行ごとに間隔を並べ替えて、重複する間隔または隣接する間隔を暗黙的に接続します。 次に、セグメント全体で BFS を使用し、現在どのインターバルにいるのか、そしてそのインターバル内でキングが概念的にどこまで立つことができるのかを維持します。 

問題は、間隔のエンドポイントを越える最短パスとなり、垂直方向に移動する場合にのみ遷移が発生します (列に移動する)。$r \pm 1$)、または行内のギャップを横切るとき。

 ## アルゴリズムのチュートリアル

 各セグメントを区間ノードとして扱うことで問題を圧縮します。 主なアイデアは、これらのセグメント上で BFS を実行することですが、セグメント内の開始位置と終了位置も考慮する必要があります。 

1. すべてのセグメントを行ごとにグループ化し、左の端点で並べ替えます。 これにより、重複をすばやくマージし、同じ行内の隣接性を判断することができます。 行内の接続は間隔の重複または重複に近い部分に依存するため、並べ替えが必要です。 
2. 各行について、重複または接触している間隔を最大連続ブロックにマージします。 このステップにより、冗長セグメントを個別に扱わないことが保証され、行内の水平方向の移動に明示的なセルごとの走査が必要ないことが保証されます。 
3. マージされた各間隔からその行インデックスへのマッピングを構築し、行ごとの間隔をソート順に保存します。 この構造は、垂直方向の接続を効率的に見つけるために使用されます。 
4. 開始セルを含む区間から始まる BFS を構築します。 どのマージされた間隔に含まれるかを特定します。$(x_0, y_0)$。 これは、行の間隔リスト内の二分探索によって行われます。 
5. 各 BFS 状態は、特定の行のある間隔に到達したことを表します。 その間隔から、行の間隔への移動を試みることができます$r-1$、$r$、 そして$r+1$。 水平方向の動きはインターバル構造によってすでに吸収されています。 
6. 隣接する行に移動するには、列範囲が現在の間隔と交差するか隣接する (チェビシェフの意味で 1 単位以内) 間隔がその行に存在するかどうかを確認します。 これは、斜めおよび垂直に移動する王の能力を捉えています。 
7. このような間隔が存在する場合は常に、距離 +1 でそれをキューに入れます。 再訪問を避けるために、訪問済みセットを一定期間にわたって使用します。 
8. BFS は、ターゲット セルを含む間隔に到達するまで、または到達可能な間隔がすべて使い果たされるまで継続します。 

### なぜ効果があるのか

 どの時点でも、キングは間隔内のどこかに位置します。 単一の間隔内では、水平移動は完全に接続されているため、BFS 距離は変化しません。 状態の変化は、キングがある区間から別の区間に移動するときにのみ発生します。これには少なくとも 1 回の移動が必要です。 間隔をノードに集約し、それらの間の遷移のみを追跡することにより、セルごとの拡張を回避しながら最短パス距離を正確に保持します。 BFS の不変条件は、最初にインターバルに到達したときに、そのインターバル内の任意の場所に立つために必要な最小移動数を見つけたことです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

def merge(intervals):
    intervals.sort()
    merged = []
    for l, r in intervals:
        if not merged or merged[-1][1] < l - 1:
            merged.append([l, r])
        else:
            merged[-1][1] = max(merged[-1][1], r)
    return merged

def find_interval(intervals, y):
    # binary search to find interval containing y
    lo, hi = 0, len(intervals) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        l, r = intervals[mid]
        if l <= y <= r:
            return mid
        if y < l:
            hi = mid - 1
        else:
            lo = mid + 1
    return -1

def solve():
    x0, y0, x1, y1 = map(int, input().split())
    n = int(input())
    
    rows = defaultdict(list)
    for _ in range(n):
        r, a, b = map(int, input().split())
        rows[r].append((a, b))
    
    for r in rows:
        rows[r] = merge(rows[r])
    
    # locate start and target rows
    if x0 not in rows or x1 not in rows:
        print(-1)
        return
    
    start_idx = find_interval(rows[x0], y0)
    target_idx = find_interval(rows[x1], y1)
    
    if start_idx == -1 or target_idx == -1:
        print(-1)
        return
    
    start = (x0, start_idx)
    target = (x1, target_idx)
    
    q = deque([start])
    dist = {start: 0}
    
    while q:
        x, i = q.popleft()
        d = dist[(x, i)]
        
        if (x, i) == target:
            print(d)
            return
        
        l, r = rows[x][i]
        
        for dx in (-1, 0, 1):
            nx = x + dx
            if nx not in rows:
                continue
            
            for j, (l2, r2) in enumerate(rows[nx]):
                if r2 < l - 1 or l2 > r + 1:
                    continue
                state = (nx, j)
                if state not in dist:
                    dist[state] = d + 1
                    q.append(state)
    
    print(-1)

if __name__ == "__main__":
    solve()
```この解決策は、許可されているすべてのセグメントを行ごとにグループ化し、重複する間隔または隣接する間隔をマージすることから始まります。 これにより、各行が互いに素な最大セグメントで表現されるようになり、接続性チェックが簡素化されます。 

BFS 状態は、行とその行内の間隔のインデックスで構成されるペアとして定義されます。 間隔内では、移動の目的ではすべてのセルが同等であるため、これで十分です。 

各状態について、同じ行とその隣接する 2 つの行を検査します。 キングは垂直または斜めにステップできるため、現在のインターバルと重なるか接触するインターバル (境界の差が最大 1) には 1 回の移動で到達できます。 

訪問された辞書により、同じ間隔を 2 回再処理することがなくなり、セグメント全体の線形複雑さが維持されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、同じ行内の複数のセグメントがちょうど 1 列のギャップだけ離れている場合です。 キングは斜めに移動できるため、隣接する行がギャップを埋める場合、サイズ 1 のギャップがグラフを切断するとは限りません。 マージ ステップでは、次を使用して隣接関係を維持する必要があります。$l-1$そして$r+1$厳密な重複ではなくチェックを行います。 

もう 1 つのエッジ ケースは、開始点またはターゲットが間隔の境界に正確に位置する場合です。 二分探索では、包含境界を正しく処理する必要があります。 そうしないと、有効な開始セルがセグメント外として拒否される可能性があります。 

最後のエッジ ケースは、パスが多数の小さな独立したセグメントを含む行を移動する必要がある場合に発生します。 適切な BFS 状態圧縮がなければ、各セグメントを個別に再訪問すると拡張が繰り返されることになりますが、訪問セットのインターバル インデックスによってこの爆発が防止されます。
