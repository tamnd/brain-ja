 ## 解決策
 ## 問題の理解

 数直線上のセグメントのリストが与えられ、それぞれが左右の端点によって定義されます。 タスクは、他のすべてのセグメントを完全に含む単一のセグメントがそれらの中に存在するかどうかを見つけることです。 そのようなセグメントが存在する場合は、その 1 から始まるインデックスを返す必要があります。 それ以外の場合は、-1 を返します。 

入力サイズは最大 100,000 セグメントに達し、各座標は 10 億に達する可能性があります。 O(n²) アルゴリズムでは約 10¹⁰ の操作が実行され、2 秒の制限時間を大幅に超えるため、すべてのセグメントを他のすべてのセグメントと比較するソリューションは除外されます。 出力は単一の整数であるため、問題は本質的に、グローバル包含プロパティを満たすセグメントの検索です。 

明らかではないエッジ ケースには、すべてのセグメントが互いに素であるか、長さが等しいが、完全には重なり合わないシナリオが含まれます。 たとえば、セグメントが`1 2`、`2 3`、 そして`3 4`、単一のセグメントに他のすべてのセグメントが含まれることはないため、出力は次のようにする必要があります。`-1`。 セグメントが 1 つしかない場合には、別の微妙なケースが発生します。 自明のことですが、それ自体が含まれているため、出力は次のようになります。`1`。 

## アプローチ

 ブルートフォースアプローチは、各セグメントに他のすべてのセグメントが含まれているかどうかをチェックすることです。 これには、すべてのセグメントにわたって 2 つのネストされたループが必要で、O(n²) 回の比較が行われます。 これは非常に小規模な場合には機能しますが、`n`、実行不可能になるとき`n`数百億回の演算が行われるため、 は 100,000 になります。 

最適化の重要な観察は、その左端点がすべての左端点の中で最小であり、その右端点がすべての右端点の中で最大である場合にのみ、セグメントが他のすべてをカバーするということです。 これにより、問題は最小値を見つけるだけになります。`l`そして最大の`r`次に、これらの値と正確に一致するセグメントがあるかどうかを確認します。 このアプローチでは、時間計算量が O(n²) から O(n) に軽減され、セグメントの保存以外に一定の追加スペースのみが使用されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力順序を維持するために、すべてのセグメントを元のインデックスとともにリストに読み取ります。 これにより、最後に正しい 1 から始まるインデックスを返すことができます。 
2. 2 つの変数を初期化します。`min_left`そして`max_right`、すべてのセグメントの中で最小の左端点と最大の右端点を追跡します。 
3. セグメントを繰り返し処理します。 セグメントごとに更新します`min_left`セグメントの左端点が小さい場合は更新します`max_right`セグメントの右端点が大きい場合。 
4. 最初のパスの後、セグメントを再度繰り返して、左端点が次の値に等しいセグメントを見つけます。`min_left`そして右端点が等しい`max_right`。 そのようなセグメントが存在する場合は、そのインデックスを返します。 それ以外の場合は -1 を返します。 

不変条件は、他のすべてをカバーするセグメントの左端点がグローバル最小値に等しく、右端点がグローバル最大値に等しい必要があることです。 これにより、他のセグメントがそれを超えて拡張されないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
segments = []

min_left = float('inf')
max_right = float('-inf')

for i in range(n):
    l, r = map(int, input().split())
    segments.append((l, r, i + 1))  # store 1-based index
    if l < min_left:
        min_left = l
    if r > max_right:
        max_right = r

answer = -1
for l, r, idx in segments:
    if l == min_left and r == max_right:
        answer = idx
        break

print(answer)
```このソリューションはセグメントを読み取り、グローバルな左エンドポイントと右エンドポイントの最大値を計算し、両方に一致するセグメントをチェックします。 元のインデックスをタプルに保存すると、追加の検索を行わずに 1 から始まる位置をすぐに返すことができます。 唯一の微妙な点は初期化です`min_left`そして`max_right`極端なケースを正しく処理し、回答を報告するときに 1 から始まるインデックスを使用することを忘れないようにします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各セグメントは 2 回処理されます。1 回目は最小/最大値の検出、もう 1 回目はカバレッジの確認です。 
| スペース | O(n) | すべてのセグメントを保存して元のインデックスを保存します。 

このソリューションは、n=100,000 の 2 秒制限と 256 MB のメモリ制限内に簡単に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    segments = []
    min_left = float('inf')
    max_right = float('-inf')
    for i in range(n):
        l, r = map(int, input().split())
        segments.append((l, r, i + 1))
        min_left = min(min_left, l)
        max_right = max(max_right, r)
    for l, r, idx in segments:
        if l == min_left and r == max_right:
            return str(idx)
    return "-1"

# provided sample
assert run("3\n1 1\n2 2\n3 3\n") == "-1", "sample 1"

# custom cases
assert run("1\n7 7\n") == "1", "single segment"
assert run("4\n1 5\n2 3\n1 5\n4 5\n") == "1", "segment covers all"
assert run("3\n2 4\n1 5\n3 5\n") == "2", "middle segment covers all"
assert run("5\n1 3\n2 4\n3 5\n2 5\n1 5\n") == "5", "last segment covers all"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1\n7 7`| 1 | 単一のセグメントはそれ自体をカバーします。 
|`4\n1 5\n2 3\n1 5\n4 5`| 1 | 複数のセグメント、最初のセグメントがすべてをカバー |
 |`3\n2 4\n1 5\n3 5`| 2 | 中間セグメントはすべてをカバーし、注文処理をテストします。 
|`5\n1 3\n2 4\n3 5\n2 5\n1 5`| 5 | 最後のセグメントはすべてをカバーし、正しいインデックスの選択を確認します。 

## 特殊なケース

 シングルセグメントの場合`1 1`、`min_left`そして`max_right`どちらも等しい`1`。 セグメントは両方に一致するため、出力は次のようになります。`1`。 

完全に重なり合わないセグメントの場合、次のようになります。`1 2`、`2 3`、`3 4`、`min_left`は`1`そして`max_right`は`4`。 両方にまたがるセグメントはないため、アルゴリズムは正しく出力します。`-1`。 

同一の最小/最大エンドポイントを持つ複数のセグメントの場合、アルゴリズムは、1 から始まるインデックス要件を維持し、カバレッジ条件を満たす入力順序の最初のセグメントを返します。
