 ## 問題の理解

 正の整数を表す 10 進数の文字列が与えられます。$n$数字。 それに加えて、固定ステップサイズもあります$k$。 ターゲットは別の整数を構築することです$y$数字がピリオドで繰り返されるようにする$k$、位置のすべての桁を意味します$i$位置の数字と一致する必要があります$i+k$両方の位置が存在する限り。 

この制約により、数値は最初の値によって完全に決定されるようになります。$k$数字。 これらが選択されると、それらを循環的にコピーすることによって残りの数値が形成されます。 

タスクは、そのような数値を構築するだけではなく、指定された入力数値以上の最小の数値を見つけることです。 

重要な問題は、2 つの制約間の相互作用にあります。周期構造は桁の変化を制限しますが、不等式条件では、制約された構造と元の数値を辞書編集的に比較する必要があります。 

以来$n$最大 200,000 に達する可能性があるため、候補を列挙したり、全範囲をバックトラッキングして桁ごとの選択をシミュレートしようとするアプローチは遅すぎます。 数字列に対して線形時間で機能するソリューションが必要です。 

いくつかの特殊なケースは過小評価されがちです。 

1 つの問題は、周期プレフィックスがすでに入力に近いものの、まだわずかに小さい場合に発生します。 たとえば、次の場合$x = 123123$と$k = 3$、繰り返しのパターンは完璧に機能し、答えはそれ自体です。 しかし、もし$x = 124123$、プレフィックス「124」の使用は機能しますが、不一致になるまでだけ誤ってコピーし、早期に停止した場合、プレフィックスをインクリメントする効果を伝播できない可能性があります。 

もう 1 つの微妙なケースは、「999」を「1000」に変えるなど、プレフィックスをインクリメントすると桁上げが発生して長さが増加する場合に発生します。 固定長を前提とした単純なアプローチ$k$この増加を誤って切り捨てたり誤って処理したりすると、無効な出力または最小ではない出力が発生します。

問題の構造は、より直接的な視点を示唆しています。 すべての有効な数値は最初の数値によって決まるため、$k$桁数の場合、問題は、繰り返し展開される最小のプレフィックスを選択することになります。$x$。 

これは貪欲な構築につながります。 まず長さの接頭辞を取得します$k$入力から入力し、それを繰り返して候補番号を形成します。 この候補がすでに十分に大きい場合は、プレフィックスを小さくしても結果が辞書編集順に小さくなるだけであるため、これが最適です。 候補が小さすぎる場合は、接頭辞を 1 ずつ増やして繰り返し構造を再構築する必要があります。 

重要な点は、プレフィックスが固定されると残りの数値が強制されるため、意味のある唯一の決定は、現在のプレフィックスで十分であるか、それとも増加する必要があるかということです。 これにより、全体にわたるポジションごとの意思決定が回避されます。$n$数字。

 ## アルゴリズムのチュートリアル

 私たちは最初のものを扱います$k$整数の生成器としての数字。 

1. 最初の部分を抽出します$k$文字列として入力された数字$p$。 これは、構造全体に影響を与えることができる唯一の部分です。 
2. 候補番号を作成する$y$繰り返すことで$p$長さに達するまで$n$。 これにより、現在のプレフィックスと一致する最小の番号が生成されます。 
3. この候補を入力された数値と比較します。 すでに入力値以上である場合、それが答えになります。有効な数値が小さいと、より小さいプレフィックスが必要となり、結果が減少するだけであるためです。 
4. 候補が入力より小さい場合、プレフィックスをインクリメントします$p$あたかも 10 進数であるかのように。 これにより、オーバーフローによりプレフィックスが長くなる場合を含め、キャリーの伝播が自然に処理されます。 
5. 更新されたプレフィックスを繰り返して、回答を再構築します。$p$長さまで$n$。 This new construction is guaranteed to be the smallest valid number strictly greater than the original input.

 ### なぜ効果があるのか

 Every valid number in this problem is fully determined by its first$k$数字。 構築プロセスでは、常に固定プレフィックスと一致する最小の数値が生成されます。 2 つの有効な数値を比較すると、それらの接頭辞を辞書順に比較することになります。 プレフィックスが小さすぎると、入力を超える有効な候補に到達する唯一の方法はプレフィックスを最小限に増やすことです。これを繰り返すことで、すべてのサフィックス位置にわたって最小性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build(p, n):
    # repeat prefix p to length n
    res = []
    k = len(p)
    for i in range(n):
        res.append(p[i % k])
    return ''.join(res)

def add_one(p):
    p = list(p)
    i = len(p) - 1
    while i >= 0 and p[i] == '9':
        p[i] = '0'
        i -= 1
    if i < 0:
        return '1' + ''.join(p)
    p[i] = chr(ord(p[i]) + 1)
    return ''.join(p)

n, k = map(int, input().split())
x = input().strip()

p = x[:k]
cand = build(p, n)

if cand >= x:
    print(n)
    print(cand)
else:
    p = add_one(p)
    cand = build(p, n)
    print(n)
    print(cand)
```この解決策は、周期構造を定義するプレフィックスを抽出することから始まります。 の`build`関数は、このプレフィックスを繰り返すことによって完全な候補を構築します。これは、周期的制約を直接実現したものです。 入力との比較により、このプレフィックスが十分であるかどうかが判断されます。 

そうでない場合は、`add_one`桁上げ伝播を使用して標準的な桁単位の増分を実行します。 すべての数字が次のようなエッジケースです。`'9'`で始まる長いプレフィックスを生成することで処理されます。`'1'`、定期的なルールに基づいて繰り返された場合でも正しく動作します。 

よくある間違いは、入力に対して最初の不一致位置のみを変更しようとすることです。 これは失敗します。1 つの増分が後続のすべての反復ブロックに影響するため、正しい操作ではプレフィックスを整数として扱う必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())
    x = input().strip()

    def build(p, n):
        k = len(p)
        return ''.join(p[i % k] for i in range(n))

    def add_one(p):
        p = list(p)
        i = len(p) - 1
        while i >= 0 and p[i] == '9':
            p[i] = '0'
            i -= 1
        if i < 0:
            return '1' + ''.join(p)
        p[i] = chr(ord(p[i]) + 1)
        return ''.join(p)

    p = x[:k]
    cand = build(p, n)
    if cand >= x:
        return f"{n}\n{cand}"
    p = add_one(p)
    cand = build(p, n)
    return f"{n}\n{cand}"

# provided sample
assert run("3 2\n353\n") == "3\n353"

# all equal digits
assert run("4 2\n1111\n") == "4\n1111"

# needs increment
assert run("3 2\n341\n") == "3\n343"

# carry overflow
assert run("3 2\n999\n") == "3\n999"

# prefix overflow edge
assert run("4 2\n9899\n") == "4\n9999"

 ## 特殊なケース

 エッジ ケースの 1 つは、プレフィックス内のすべての数字が次のような場合です。`'9'`。 のような入力の場合`x = 999`と`k = 2`、プレフィックス「99」は「100」に増加します。 繰り返し構造では更新されたプレフィックスが直接使用されるため、アルゴリズムはここで周期的制約を破りません。 「100」を繰り返すと「100」が生成され、これは有効で入力よりも大きくなります。 

もう 1 つのケースは、オーバーフローによりプレフィックス長が増加する場合です。 プレフィックスが長くなっても、繰り返しでは新しいプレフィックスが一貫して使用され、最初のプレフィックスを読み取る以上に固定長の仮定に依存することがないため、構築は依然として機能します。$k$ジェネレーターとしての数字。 

最後の微妙なケースは、入力がすでに周期的であるものの、最小ではない場合です。 このアルゴリズムは、接頭辞を繰り返すと同じ数値が得られることを正しく認識し、最初の比較ですぐに等しいことが分かるため、不必要な変更を回避します。
