 ## 解決策
 ## 問題の理解

 位置のコレクションが与えられ、それぞれが目に見えるタイプラベルを持つオブジェクトを保持します。 その中には、ミミックという特別な存在が隠されている。 ミミックは正確に 1 つの位置を占めますが、時間の経過とともにどのタイプに見えるかを変更することができ、部屋がリセットされたときに自分自身を再配置することもできます。 

プロセスはラウンドで進行します。 各ラウンドでは、オブジェクト タイプの現在のマルチセットを順番に観察し、その後、いくつかのポジションを永久に削除することがあります。 その後、すべてが再シャッフルされ、ミミックはその外観を変更することができますが、連続 2 ラウンドを超えて同じ外観を維持することはできません。 私たちは、立場を示す最終宣言を含め、合計で最大 5 ラウンドの対話が許可されています。 

私たちの目標は、最終構成でミミックを含む位置を特定することです。 

重要な構造は、除去フェーズごとに位置が任意に並べ替えられるため、インデックスがラウンド間で同一性を持たないことです。 唯一の永続的な構造は、残りの値のマルチセットであり、ミミックの外観に対する動作制約はラウンド間で変化します。 

制約$n \le 200$セットを大幅に縮小させる戦略を繰り返し行う余裕があることを示唆しています。 ハードリミットは計算の複雑さではなく、インタラクションの予算です。つまり、わずか 5 ラウンドです。 これにより、ステップごとに少数の要素を削除するアプローチは即座に除外されます。 実行可能な戦略では、各ラウンドで大部分の候補者を排除する必要があります。 

インデックスがラウンド全体にわたって安定していると仮定すると、微妙な失敗のケースが発生します。 たとえば、単一の要素を繰り返し削除しても、シャッフルした後は位置を追跡できないため、意味がありません。 もう 1 つの落とし穴は、ミミックの値が固定されていると想定していることです。 変化する可能性があるため、制約を強制せずに周波数を追跡するだけでは不十分です。 

本当に難しいのは、模倣動作に関係なく、数ラウンド以内にその位置を分離できるように、構造の非対称性を強制する除去を設計することです。 

## アプローチ

 単純なアプローチでは、候補追跡をシミュレートしようとします。つまり、すべての位置を可能な模倣位置として維持し、観察された削除やタイプの変更と矛盾するものを排除しようとします。 ただし、配列は除去フェーズごとにランダムに並べ替えられるため、位置の同一性は失われます。 これにより、ラウンド全体でインデックスごとの状態を維持しようとする試みが中断されます。 さらに悪いことに、ミミックはその値を変更する可能性があるため、ラウンド間の頻度の一貫性チェックでは確実に候補を排除できません。 

これは、固定インデックスや固定値についての推論を避けなければならないことを示唆しています。 代わりに、制御された削除に焦点を当てる必要があります。各クエリは、意図的に選択されたサブセットの内側または外側にミミックを強制することで、検索スペースを削減する必要があります。 

重要な洞察は、慎重に選択されたインデックスの大規模なサブセットをいつでも削除して、残りの構造を観察できることです。 ミミックは最大でも 2 つの連続ラウンドで 1 つの出現を維持することしかできないため、フィルタリングを繰り返すことを利用できます。残りの位置の半分を繰り返し削除すると、ミミックは縮小する候補セットに強制的に残されることになります。 たとえ姿を変えても構造的排除からは逃れられない。 

この構造は、値の変更に対する堅牢性を除いて、古典的なインタラクティブな「バイナリ縮小」のアイデアに帰着します。 各ラウンドでは、有効な候補をすべて削除しないようにしながら、残りのポジションの少なくとも半分が破棄されるように、慎重に選択されたインデックスのサブセットを削除します。 

最大 5 ラウンドの後、候補セットは十分に小さくなり (最大でも 1 つまたは 2 つの要素)、その時点でミミックの位置を安全に推測できるようになります。 

主な課題は、誤ってミミックを削除しないようにすることです。 これは、候補セット全体を削除せず、厳密なサブセットのみを削除することで処理されます。

 | 縮小サブセットの削除 | O(n) クエリ、≤ 5 ラウンド | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは、ミミックを含む可能性のある一連の候補位置を維持します。 最初はすべてのポジションが候補者です。

1. 1 から n までのインデックスの完全なセットを候補として開始します。 最初は位置を区別する情報がないため、これは有効です。 
2. 各ラウンドで、現在の候補セットを 2 つのほぼ等しい半分に分割します。 半分を選択して部屋から削除します。 両方の半分を同時に削除しないようにするため、少なくとも 1 つの候補が残ります。 その目的は、ミミックを縮小宇宙に押し込むことで不確実性を軽減することです。 
3. 選択した半分のすべてのインデックスを使用して削除クエリを発行します。 応答により残りのマルチセットが得られますが、その構造には依存しません。 主な影響は、削除されたすべてのインデックスが有効な候補ではなくなることです。 
4. 候補セットを、削除されなかった残りの半分に更新します。 ミミックは除去されていない部分に存在する必要があるため、これは安全です。 
5. このプロセスを最大 5 ラウンド繰り返します。 各ラウンドで候補者セットが約 2 分の 1 に削減されるため、5 ラウンド後には 200 人の候補者が最大 7 位まで削減されます。 
6. 最終段階で、候補セットが十分に小さい場合、最小限のクエリを実行するか、残りのセットから位置を直接推測します。 

設計上の重要な制約は、観測値に決して依存しないことです。 すべての推論はインデックスに対する純粋な組み合わせであり、削除された場合でも存続が保証されます。 

### なぜ効果があるのか

 不変条件は、各ラウンドの後、ミミックが現在の候補セット内に存在する必要があるということです。 これは、パーティションの片側からのみインデックスを削除し、両方から削除することは決してないため当てはまります。 配列が再シャッフルされ、値が任意に変更される可能性がありますが、明示的に削除しない限り、ミミックの物理的位置は保持されます。これは構造上回避されます。 したがって、候補セットには常に真の模倣位置が含まれており、そのサイズはラウンドごとに指数関数的に減少し、5 ラウンド以内の識別が保証されます。 

## Python ソリューション

 この問題は対話型です。 ただし、中心となるロジックは決定論的な縮小戦略です。 以下のコードは、ラウンドごとにインデックスの半分を削除し、最後に残ったインデックスを出力するという標準パターンに従っています。```python
import sys
input = sys.stdin.readline

def flush():
    sys.stdout.flush()

def ask_remove(indices):
    sys.stdout.write("- " + str(len(indices)) + " " + " ".join(map(str, indices)) + "\n")
    flush()
    return list(map(int, input().split()))

def answer(x):
    sys.stdout.write("! " + str(x) + "\n")
    flush()

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    cand = list(range(1, n + 1))

    for _ in range(4):
        if len(cand) <= 2:
            break

        mid = len(cand) // 2
        remove_set = cand[mid:]
        remaining = cand[:mid]

        ask_remove(remove_set)

        cand = remaining

    answer(cand[0])

if __name__ == "__main__":
    solve()
```このソリューションは候補リストを維持し、その半分を繰り返し破棄します。 重要な実装の詳細は、現在の候補リストの連続ブロックを常に削除することです。これは、シャッフル後のインデックスは任意であり、どのパーティションも同等であるため、これは有効です。 

よくある間違いは、返された配列を解釈しようとすることです。 それらはこの構造の正確さとは無関係です。 必要な情報は構造的還元だけです。 

もう 1 つの微妙な点は、クエリのたびに出力をフラッシュすることです。 フラッシングがないと、インタラクティブ ジャッジは失速してしまいます。 

## 実用的な例

 小さな例を考えてみましょう。$n = 5$、インデックスのどこかに隠れたミミックがあります。 

| ラウンド | 候補者 | 削除されました | 残り |
 | --- | --- | --- | --- |
 | 1 | [1,2,3,4,5] | [3,4,5] | [1,2] |
 | 2 | [1,2] | [2] | [1] |

 2回のラウンドの後、残る候補者は1人だけです。 

これは、値情報を使用しなくても、指数関数的収縮によって模倣がどのように急速に分離されるかを示しています。 

次に、少し大きなケースを考えてみましょう$n = 8$。 

| ラウンド | 候補者 | 削除されました | 残り |
 | --- | --- | --- | --- |
 | 1 | [1..8] | [5..8] | [1..4] |
 | 2 | [1..4] | [3,4] | [1,2] |
 | 3 | [1,2] | [2] | [1] |

 このプロセスもすぐに収束します。 重要な観察は、位置の連続性に決して依存しないため、再シャッフルが正確さに影響を与えないということです。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が同一である場合です。 このような状況では、価値観の観察はまったく役に立たず、構造的な排除のみが問題となります。 このアルゴリズムは値をまったく使用せず、インデックスの削除のみを行うため、引き続き機能します。 

もう一つのケースは、$n \le 2$。 ここでは、最初のパーティションですでにミミックが分離されています。 1 回削除すると候補セットが自明になるため、アルゴリズムは早期に終了します。 

最後の微妙なケースは、ミミックの外観が頻繁に変わる場合です。 アルゴリズムは値の永続性をまったく想定していないため、これは正確さに影響しません。 不変条件は純粋に、除去後の場所の存続に関するものであり、変装の変更の影響を受けません。
