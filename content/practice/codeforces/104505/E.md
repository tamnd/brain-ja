 ## 解決策
 ## 問題の理解

 私たちには、3 次元空間に固定された一連のドローンが与えられます。 各ドローン i には座標 (x_i、y_i、z_i) と重み w_i があります。 任意の整数座標 (x、y、z) で特別なプライマリ ドローンの位置を自由に選択できます。 位置を選択するコストは、その地点までのユークリッド距離の 2 乗のすべてのドローンの合計にドローンの重量を乗じたものとして定義されます。 

言い換えれば、すべてのドローンは w_i 回 ((x - x_i)^2 + (y - y_i)^2 + (z - z_i)^2) を寄与し、この合計値を最小化する (x, y, z) を選択したいと考えます。 複数の整数点が同じ最小コストを達成する場合、辞書編集的に最小のものを返さなければなりません。つまり、最初に x が小さく、次に y、次に z が優先されることを意味します。 

この制約により、最大 100,000 のドローン、最大 200,000 の座標、最大 1,000 の重みが許可されます。これにより、グリッドから候補位置を試行したり、次元ごとにサイズ 200,000 の範囲内のすべての点の目標を評価したりするアプローチは即座に除外されます。 探索空間は座標範囲内で立方体であるため、x と y にわたる 2 次元のスキャンさえ不可能です。 

重要な構造的観察は、コストが x、y、z にわたる独立した合計にきれいに分離されていることです。 つまり、式は、座標軸ごとに 1 つずつ、3 つの独立した 1 次元 2次関数の合計に拡張されます。 

ユークリッド距離のために座標が相互作用すると考えるのは素朴な誤解です。 典型的な間違ったアプローチは、幾何学的中央値の問題として扱うか、重みを付けずに座標方向の中央値を試行することですが、ここではどちらも失敗します。 

複数の重み付けされた構成が同じ最適値を生成する場合、微妙なエッジ ケースが発生します。 たとえば、すべての点が対称である場合、複数の整数最小化子が存在し、辞書編集的な順序が決定要因になります。 各次元を個別に解決するアプローチでも、一貫したタイブレークを保証する必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。入力座標の範囲内で考えられるすべての整数座標 (x、y、z) を試し、各選択肢の合計コストを計算します。 これは目的関数の定義を直接評価するため、正しいです。 ただし、座標範囲は各次元で最大 200000 に及び、これはおよそ 8 × 10^15 個の候補点を意味します。 単一点を評価するだけでも O(n) のコストがかかり、合計実行時間は 10^21 演算程度と天文学的に大きくなり、これはまったく実行不可能です。 

重要な洞察は、目的関数を代数的に拡張することです。 固定次元、たとえば x の場合、すべてのドローンの寄与は次のようになります。 

∑ w_i (x - x_i)^2

 これを拡張すると、

 ∑ w_i (x^2 - 2x x_i + x_i^2)

 これは次のように書き換えることができます

 x^2 ∑ w_i - 2x ∑ (w_i x_i) + 定数

 これは x の凸二次関数です。 整数上の凸二次方程式には、実数値の最小化子に近い単一のグローバル最小値があります。 同じ構造が y と z に対して独立して成り立ちます。 

したがって、問題は 3 つの独立した 1 次元の重み付き 2 次関数を最小化することに帰着します。 それぞれは、加重平均を計算し、その周囲の最も近い整数の候補をチェックすることで解決できます。 

この関数は凸関数であるため、実際の最適値の周りの一定数の整数点のみを評価するだけで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · R^3) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ここで R は座標範囲のサイズで、およそ 200000 です。 

## アルゴリズムのチュートリアル

 目的は 3 つの分離可能な 2 次式の合計であるため、x、y、z を独立して扱います。

1. 総重量 W = ∑ w_i を計算します。 これは、各次元の加重平均の正規化係数を表します。 
2. 加重合計 S_x = ∑ w_i x_i、S_y = ∑ w_i y_i、S_z = ∑ w_i z_i を計算します。 これらは、各軸に沿って点の「質量」がどこにあるかをエンコードします。 
3. 各座標の実数値の最小値を S_x / W、S_y / W、S_z / W として計算します。これは、導関数をゼロに設定することによって得られる、各二次関数の静止点です。 
4. 整数座標が必要なので、各実数ミニマイザーの周囲の候補整数を検討します。 各次元について、加重平均の床と天井の周囲の小さな近傍 (通常は最大 2 つまたは 3 つの値) をチェックします。 凸性により、整数に対するグローバル最小値がこの近傍にあることが保証されます。 
5. 候補 x、y、z 値の各組み合わせについて、定義を使用して直接全コストを計算します。 
6. 発生する最小コストを追跡します。 複数のトリプルが同じコストを達成する場合は、(x, y, z) を比較して辞書編集的に最小のものを選択します。 

### なぜ効果があるのか

 各座標は、独立した凸二次関数に寄与します。 凸性は、局所最小値が大域最小値であることを保証し、整数領域の場合、最適値は実数値の静止点の近くに存在する必要があります。 フルコストは 3 つの独立した凸関数の合計であるため、各座標を個別に (正しい整数丸めを使用して) 最小化すると、グローバル ミニマイザーが生成されます。 辞書編集的なタイブレークは、評価後に完全な候補を比較することによって明示的に処理され、複数の整数最小化子が存在する場合でも正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    
    sx = sy = sz = sw = 0
    
    points = []
    for _ in range(n):
        x, y, z, w = map(int, input().split())
        sx += x * w
        sy += y * w
        sz += z * w
        sw += w
        points.append((x, y, z, w))
    
    # real-valued candidates
    def candidates(s, wsum):
        if wsum == 0:
            return [0]
        base = s / wsum
        c = int(base)
        return [c - 1, c, c + 1, c + 2]
    
    cx = candidates(sx, sw)
    cy = candidates(sy, sw)
    cz = candidates(sz, sw)
    
    best_cost = None
    best = (10**30, 10**30, 10**30)
    
    def cost(x, y, z):
        res = 0
        for xi, yi, zi, wi in points:
            dx = x - xi
            dy = y - yi
            dz = z - zi
            res += wi * (dx*dx + dy*dy + dz*dz)
        return res
    
    for x in cx:
        for y in cy:
            for z in cz:
                c = cost(x, y, z)
                cand = (x, y, z)
                if best_cost is None or c < best_cost or (c == best_cost and cand < best):
                    best_cost = c
                    best = cand
    
    print(best[0], best[1], best[2])

if __name__ == "__main__":
    solve()
```この実装では、まず重み付けされた合計を集計して、各座標の連続最小化子を特定します。 次に、各ミニマイザーの周囲に小さな離散候補セットを生成し、元のコスト定義を使用してそれらの点のみを正確に評価します。 候補に対するネストされたループのサイズは一定であるため、漸近的な複雑さには影響しません。 

辞書編集上の要件は、コストが同点になるたびに最適なトリプルを保存し、タプルを直接比較することによって処理されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    pts = []
    sx = sy = sz = sw = 0
    for _ in range(n):
        x, y, z, w = map(int, input().split())
        sx += x*w
        sy += y*w
        sz += z*w
        sw += w
        pts.append((x,y,z,w))

    def cand(s):
        c = int(s / sw)
        return [c-1, c, c+1]

    cx, cy, cz = cand(sx), cand(sy), cand(sz)

    def cost(x,y,z):
        return sum(w*((x-xi)**2+(y-yi)**2+(z-zi)**2) for xi,yi,zi,w in pts)

    best = None
    best_cost = None
    for x in cx:
        for y in cy:
            for z in cz:
                c = cost(x,y,z)
                if best_cost is None or c < best_cost or (c == best_cost and (best is None or (x,y,z)<best)):
                    best_cost = c
                    best = (x,y,z)

    return f"{best[0]} {best[1]} {best[2]}"

 ## 特殊なケース

 縮退したケースは、すべてのドローンの位置が同じである場合です。 加重平均は同じ座標に等しいため、候補セットはその 1 点に集約されます。 アルゴリズムはそれを直接評価して返し、正確さを保ちます。 

もう 1 つのエッジ ケースは、加重平均が 2 つの整数の間に正確に位置する場合に発生します。 たとえば、平均が 2.5 の場合、2 と 3 の両方をチェックする必要があります。 候補生成には両方の近傍が含まれており、直接評価により正しいものが選択されることが保証されます。 両方のコストが等しい場合、辞書編集的な比較では小さい方の座標が選択されます。 

最後のエッジケースは、重みのバランスが極端に崩れている場合です。 単一の大きな w_i が合計を支配し、最適な座標をそのドローンの位置に押し上げます。 候補の生成は重み付き平均を中心に行われ、重み付き平均はすでにこの優位性を反映しているため、アルゴリズムには依然として正しい領域が含まれており、それを正確に評価します。
