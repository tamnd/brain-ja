 ## 解決策
 ## 問題の理解

 私たちは、ダイナミックなグローブ サイズを一列に並べて維持しています。 いつでも 2 つのことが起こる可能性があります。 単一の位置で値が変更されるか、配列の固定サブセグメントに焦点を当てたクエリが与えられ、値のマルチセットに少なくとも 2 つの等しいサイズのペアが含まれるように、そのセグメント内の 4 つの異なる位置を選択できるかどうかを決定する必要があります。ただし、2 つのペアがおそらく異なる 2 つのサイズに対応するという追加の制約があります。 

簡単に言うと、クエリ範囲の場合$[l, r]$、2 つの値を見つける必要があります$X$そして$Y$、必ずしも異なるわけではなく、 の 2 つの異なるインデックス$X$プラス 2 つの異なるインデックス$Y$, すべて範囲内です。 もし$X = Y$の場合、実際には同じ値が少なくとも 4 回出現する必要があります。 出力は、有効な選択範囲の 4 つの位置を返す必要があります。 

配列はオンラインで更新されるため、ポイント更新では単一の要素が変更され、クエリは現在の状態を反映する必要があります。 更新とクエリの両方がインターリーブされます。 

制約$n, q \le 10^5$これは、クエリごとに周波数情報を最初から再計算するソリューションは失敗することを意味します。 平$O(n)$クエリごとにつながる$10^{10}$2秒の制限では不可能な最悪の場合の操作。 これにより、対数または対数に近い時間で範囲クエリとポイント更新の両方をサポートする構造が即座に強制されます。 

微妙なエッジ ケースは、範囲に多くの繰り返し値があるにもかかわらず、要件を満たさない場合です。 たとえば、次のような範囲$[1,1,2,2,3]$2 つの有効なペアを形成できないため、これでは不十分です。 少なくとも 2 つの異なる値が 2 回出現するかどうかだけをチェックする単純なアプローチでは、次のような構成が誤って受け入れられてしまいます。$1,1,2,3$、有効なペアが 1 つだけ含まれています。 

もう 1 つの障害モードは、最も頻度の高い 2 つの値を見つけるだけで十分であると仮定することです。 これは、クエリ間隔内で高頻度の値が十分な素のインデックスを生成しないように頻度が分散されている場合に問題が発生します。 

## アプローチ

 各クエリに対する直接的な総当たり戦略では、範囲をスキャンし、頻度マップを構築し、すべての値のペアを試して、2 つの素なペアを抽出できるかどうかを確認します。 これは、すべての出現を明示的にカウントするため正しいですが、コストがかかります$O(r-l+1)$クエリごとに発生し、最悪の場合は次のように縮退します。$O(n)$クエリごとに。 

主要な障害は、実際には完全な周波数分布が必要ないことです。 知る必要があるのは、結合された寄与により 2 つのペアを選択できる 2 つの値が存在するかどうか、および 1 つの値だけですでに少なくとも 4 回の出現に寄与しているかどうかだけです。 これにより、問題は完全なカウントから、セグメントごとに候補の多い要素の小さなセットを維持することに軽減されます。 

重要な観察は、有効な回答は範囲内の「多大な貢献者」の非常に少数のサブセットから得られる必要があるということです。 値が少なくとも 4 回出現すると、問題は直ちに解決されます。 それ以外の場合は、少なくとも 2 回出現する値を考慮するだけで済みます。 ただし、実際には、同時に重要となるこのような値の数には制限があります。これは、どのセグメントにも、ペアの形成が可能な頻度で少なくとも 2 つの異なる値しか含めることができないためです。 

これにより、ノードごとに、潜在的に役立つ可能性のある候補値の小さなリスト (通常はそのセグメント内で最も頻繁に使用されるいくつかの値) を維持するセグメント ツリーが起動されます。 クエリ中に、対象となるセグメントの候補リストを結合し、これらの候補のみの頻度を集計して、実現可能性をテストします。 

これが機能するのは、有効な解決策には、クエリ範囲のセグメント分解にローカルに頻繁に使用される値が少なくとも 1 つ含まれている必要があるためです。そのため、候補を限定することで完全性を維持しながら作業を大幅に削減できます。

 ## アルゴリズムのチュートリアル

 配列上にセグメント ツリーを構築します。 各ノードは、そのセグメントからの候補値の小さなリストを保存します。 マージの効率が維持されるように、リストのサイズは一定 (通常は 10 または 20 などの小さな数値) に保たれます。 

### ステップ

 1. 各リーフが単一の値とそのインデックスを格納するセグメント ツリーを構築します。 内部ノードは子候補リストをマージします。 マージでは最も関連性の高い候補のみが保持され、リストが制限されたままになります。 この圧縮は、最悪の場合の爆発を回避するために必要です。 
2. お問い合わせの場合$[l, r]$、セグメント ツリーを走査し、範囲の一部を完全にカバーするノードから候補リストを収集します。 これにより、有効な回答に含まれる可能性のある値を含む候補値の複数セットが得られます。 
3. 収集された各候補値について、クエリ範囲内での出現回数を計算します。 これは、値ごとにソートされた位置のリストを保存し、二分探索を使用して位置の数をカウントすることで実行できます。$[l, r]$。 このステップでは、その値が少なくとも 2 回発生するか、または 4 回発生するかどうかを識別します。 
4. いずれかの候補が少なくとも 4 つの頻度を持っている場合、その位置のうち 4 つを直ちに出力します。 
5. それ以外の場合は、候補のすべてのペアを試します$X, Y$。 各ペアについて、次の 2 つの異なる出現を選択できるかどうかを確認します。$X$そして 2 つの異なる発生$Y$。 もし$X \neq Y$、両方の周波数が少なくとも 2 である必要があります。 もし$X = Y$、少なくとも 4 つの出現が必要ですが、これはすでに以前に処理されているはずです。 
6. 有効なペアが見つかったら、範囲内の各値の出現リストの最初の 2 つの位置を取得して、実際のインデックスを出力します。 

### なぜ効果があるのか

 正しさは、有効な解がクエリ範囲内に複数回出現する値にのみ依存するという事実に依存します。 値が少なくとも 4 回出現する場合、その値は直接検出されます。 それ以外の場合、2 つのペアへの有効な分解には、それぞれが少なくとも 2 回の出現に寄与する 2 つの値が含まれている必要があります。 このような値は、範囲をカバーする少なくとも 1 つのセグメント ノードに候補として表示される必要があるため、収集された候補セットに含まれることが保証されます。 制限された候補リストにより、計算の効率を維持しながら、実行可能なペアを見逃すことがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left, bisect_right

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.arr = arr
        self.tree = [[] for _ in range(4 * self.n)]
        self.build(1, 0, self.n - 1)

    def merge(self, a, b):
        # merge two candidate lists, keep small bounded set
        c = a + b
        # remove duplicates
        seen = set()
        res = []
        for x in c:
            if x not in seen:
                seen.add(x)
                res.append(x)
            if len(res) >= 10:
                break
        return res

    def build(self, idx, l, r):
        if l == r:
            self.tree[idx] = [self.arr[l]]
            return
        mid = (l + r) // 2
        self.build(idx * 2, l, mid)
        self.build(idx * 2 + 1, mid + 1, r)
        self.tree[idx] = self.merge(self.tree[idx * 2], self.tree[idx * 2 + 1])

    def query(self, idx, l, r, ql, qr):
        if ql <= l and r <= qr:
            return self.tree[idx]
        mid = (l + r) // 2
        res = []
        if ql <= mid:
            res += self.query(idx * 2, l, mid, ql, qr)
        if qr > mid:
            res += self.query(idx * 2 + 1, mid + 1, r, ql, qr)
        # deduplicate and bound
        seen = set()
        out = []
        for x in res:
            if x not in seen:
                seen.add(x)
                out.append(x)
            if len(out) >= 20:
                break
        return out

def solve():
    n, q = map(int, input().split())
    A = list(map(int, input().split()))

    pos = {}
    for i, v in enumerate(A):
        pos.setdefault(v, []).append(i)

    st = SegTree(A)

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '0':
            i = int(tmp[1]) - 1
            x = int(tmp[2])

            old = A[i]
            if old != x:
                pos[old].remove(i)
                pos.setdefault(x, []).append(i)
                A[i] = x

        else:
            l = int(tmp[1]) - 1
            r = int(tmp[2]) - 1

            cand = st.query(1, 0, n - 1, l, r)
            ok = False

            for v in cand:
                cnt = bisect_right(pos[v], r) - bisect_left(pos[v], l)
                if cnt >= 4:
                    idxs = [i for i in pos[v] if l <= i <= r][:4]
                    print(*[i + 1 for i in idxs])
                    ok = True
                    break

            if ok:
                continue

            # try pairs
            for i in range(len(cand)):
                for j in range(i + 1, len(cand)):
                    a = cand[i]
                    b = cand[j]

                    ca = bisect_right(pos[a], r) - bisect_left(pos[a], l)
                    cb = bisect_right(pos[b], r) - bisect_left(pos[b], l)

                    if ca >= 2 and cb >= 2:
                        ia = [x for x in pos[a] if l <= x <= r][:2]
                        ib = [x for x in pos[b] if l <= x <= r][:2]
                        print(*(ia + ib))
                        ok = True
                        break
                if ok:
                    break

            if not ok:
                print(-1)

if __name__ == "__main__":
    solve()
```セグメント ツリーには圧縮された候補リストが格納されるため、各クエリは全範囲をスキャンするのではなく、少数の潜在的な値のみを検査します。 の`pos`Dictionary は値ごとにソートされたインデックス リストを保持し、二分検索による高速な頻度チェックを可能にします。 更新中に、クエリ時間のカウントが正しく行われるように、これらのリストが維持されます。 

実装の微妙な点は、候補リストに意図的に上限が設定されていることです。 制限がなければ、マージ操作は最悪の場合直線的に増大し、パフォーマンス保証が破壊される可能性があります。

 ## 特殊なケース

 重大なエッジ ケースは、正確に 1 つの値が優勢であるものの、4 つの値を形成するには十分ではない場合です。 例えば、$[1,1,1,2,3]$2 番目の値が 2 回発生することはないため、失敗するはずです。 このアルゴリズムは、最初に「頻度 ≥ 4」の場合を明示的にチェックし、次に候補間で有効なペアを検索するため、これを処理します。 

もう 1 つのエッジ ケースは、有効な答えは存在するが、両方の寄与値がセグメント ツリー分解の狭い部分内にのみ現れる場合です。 候補のマージにより、クエリ範囲をカバーする少なくとも 1 つのノードに両方の値が存在することが保証されるため、圧縮中にこれらの値が失われることはなく、大量のセグメンテーションの下でも正確さが維持されます。
