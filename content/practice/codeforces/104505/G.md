 ## 解決策
 ## 問題の理解

 固定された順序でプレイされる一連のレベルが与えられます。 開始時に、ヒーローはある程度の初期パワーを持ち、各レベルで 2 匹のモンスターが利用可能になります。 プレイヤーはレベルごとに 1 つのモンスターを正確に選択する必要があり、唯一の制約は、選択したモンスターのパワーがヒーローの現在のパワーを超えてはいけないということです。 

モンスターを倒した後、主人公の力はそのモンスターの力だけ増加します。 これによりフィードバック ループが作成されます。早い段階で弱いモンスターを選択すると、後でより強力な選択肢をアンロックできなくなる可能性がありますが、現在のパワーが小さすぎる場合は、利用可能なより強力なモンスターを選択することが不可能になる可能性があります。 

タスクは、最終的なパワーや最適なスコアを計算することではなく、実行可能性を判断することだけです。つまり、主人公がすべてのレベルを順番に生き残ることを可能にする一連の選択肢がレベルごとに 1 つ存在するかどうかです。 

この制約では、最大 2000 レベル、最大 10^6 の値が許可されます。 各レベルが 2 つの可能性に分岐し、2^n 通りの可能なパスが生成されるため、選択肢に対する単純な指数関数的な検索はすぐに大きすぎますが、これは実行可能な計算をはるかに超えています。 

貪欲な直感が微妙に失敗するケースは、局所的に強力なモンスターが将来のアクセスを妨げる場合に現れます。 たとえば、早い段階で大型モンスターを選択すると、両方のモンスターが残りの力を超えて後のレベルが不可能になる場合、「常に可能な限り強いものを選択する」という欲張りな戦略は失敗する可能性があります。 逆に、常に可能な限り弱いものを選択すると、将来のオプションを解放するのに十分な力が増加しない可能性があるため、失敗する可能性があります。 

したがって、指数関数的な爆発を避けながら、各レベル後に到達可能なすべての電力状態を追跡することが困難になります。 

## アプローチ

 ブルートフォース手法では、これを階層化グラフ内のパス検索として扱います。 各レイヤーはレベルに対応し、各状態は可能なヒーローパワーです。 レベル i でパワー x の状態から、モンスター a_i または b_i を選択することでレベル i+1 に移行できます (ただし、モンスター a_i または b_i が ≤ x の場合)。新しい状態は x + a_i または x + b_i になります。 

これは、状態を超えた BFS または DFS を即座に示唆します。 問題は、個別の電力値の数が急速に増加することです。 最悪の場合、すべての選択により新しい個別の合計が作成されるため、i レベルの後には O(2^i) 状態になる可能性があります。 n = 2000 では、これは完全に不可能です。 

重要な観察は、シーケンスの数は指数関数的であるにもかかわらず、到達可能なパワー値の構造には強い単調性があるということです。つまり、固定レベルでは、特定のパワーが到達可能であれば、より小さなパワーもすべて事実上支配されており、個別に追跡する必要はありません。 これにより、状態空間を各レベルの到達可能な最大パワーに圧縮することができ、より正確には、単一の貪欲なフロンティアに縮小できる「最良の代表」のセットに圧縮することができます。 

各レベルで、考えられるすべてのパワーを追跡する必要はありません。 これまでのところ、達成可能な最大パワーのみを考慮します。これは、パワーが小さい状態では、同じレベルで最大の状態でもロックを解除できないものをロック解除できないためです。 遷移では実現可能性 (x ≥ a_i または b_i) のチェックのみが必要なため、プロセスは 1 つの値、つまり、常に最良の実現可能なオプションを選択すると仮定した場合の、各レベルの処理後の可能な最良の現在の電力を維持することになります。 

各レベルでの決定は簡単になります。a_i と b_i のうち、現在の電力以下の最大値を採用します。 どちらも実現可能でない場合は失敗します。 

この貪欲さが機能するのは、より大きな実行可能なモンスターを選択しても、より小さなものを選択する場合と比較して、将来の選択肢が減ることはないからです。 どちらの選択肢も 1 つのレベルを消費しますが、より大きな選択肢では、将来の到達可能なしきい値が厳密に増加または維持されます。

## アルゴリズムのチュートリアル

 単一の変数を維持しながらレベルを順番に処理します`power`、現在のレベルで達成できる最大のヒーローの強さを表します。 

1.初期化`power = f`、開始時の強さ。 これは、決定が行われる前の可能な限り最良の状態を表します。 
2. 1 から n までの各レベル i について、2 匹のモンスターを検査します。`a_i`そして`b_i`。 
3. 2 つのモンスターのうちどちらが倒せるかを確認します。つまり、そのモンスターの力が現在の値以下であることを意味します。`power`。 
4. どちらのモンスターも倒すことができない場合は、ただちにゲームを完了できないと判断します。 
5. 倒せるモンスターが 1 体だけの場合は、それを選択し、そのパワーを追加します。`power`。 
6. 両方とも倒せる場合は、大きい方を選択します。 これにより、`power`1レベルを消費するのと同じコストで、将来的に不利益を被ることはありません。 
7. すべてのレベルが正常に処理された後、ゲームを完了できることが出力されます。 

### なぜ効果があるのか

 このプロセスは、どのレベルにおいても、現在達成可能な最大電力のみが重要であるという事実に基づいています。 2 つの状態が同じレベルに存在する場合、将来の制約はすべて「続行するには電力が少なくともあるしきい値でなければならない」という形式であるため、より高い電力を持つ方が他方を支配します。 遷移は電力を増加させるだけなので、電流値が高くなっても将来の実現可能性が低下することはありません。 したがって、到達可能な最大パワーのみを維持すれば十分であり、実行可能な最大のモンスターを貪欲に選択することで、すべてのステップでこの最大値が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, f = map(int, input().split())
    power = f

    for _ in range(n):
        a, b = map(int, input().split())

        can_a = a <= power
        can_b = b <= power

        if not can_a and not can_b:
            print("N")
            return

        if can_a and can_b:
            chosen = max(a, b)
        else:
            chosen = a if can_a else b

        power += chosen

    print("S")

if __name__ == "__main__":
    solve()
```ソリューションは単一の実行値を保持します`power`そしてそれをレベルごとに更新します。 重要な実装の詳細は、選択する前に常に実現可能性をチェックし、無効なモンスターを決して追加しないようにすることです。 両方の選択肢が有効な場合、将来の到達可能性を最大化するために明示的に最大値を採用します。 

チェックの順序は重要です。モンスターを選択する前に、失敗のケースを検出する必要があります。 そうしないと、無効な追加によって誤って電力が増加し、不可能性がマスクされる可能性があります。

 ## 特殊なケース

 重要なエッジケースは、両方のモンスターのパワーが現在のパワーとまったく同じである場合です。 アルゴリズムはこれを有効なものとして扱い、選択を許可する必要があります。 たとえば:

 入力:```
2 3
3 3
3 3
```レベル 1 では、両方とも実行可能であるため、いずれかの 3 を選択し、パワーを 6 に増加します。レベル 2 では、やはり両方とも実行可能であり、成功します。 どちらの選択肢も同じであるため、貪欲なルールは重要ではありません。 

もう 1 つのエッジ ケースは即時デッドロックです。 

入力:```
1 2
3 3
```唯一のレベルでは、両方のモンスターがパワーを超えているため、アップデートの前にチェックは正しく失敗を引き起こします。 

3 番目の微妙なケースは、1 つのモンスターは実行可能だがサイズが小さく、もう 1 つは実行不可能な場合です。 

入力:```
1 5
2 10
```有効なのは 2 だけなので、それを選択する必要があります。 実現可能性をチェックせずに最大値を選択すると、誤って 10 が選択され、ケースが誤って受け入れられます。 最大値を取得する前に実現可能性をチェックすることは、正確性を確保するために不可欠です。
