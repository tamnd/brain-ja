 ## 解決策
 ## 問題の理解

 フェスティバルは、循環的なタイムラインとして見ることができます。$N$永遠に繰り返される日々と成長システム$M$レベル。 ヤンはレベル 1 から開始し、レベルに到達したいと考えています$M$ちょうど 1 つのサイクルに参加しながら、$N$ただし、サイクルのどこからでも開始日を選択できます。 

毎日$j$には 2 つの独立したコスト要素があります。 まずアップグレード: ヤンがレベルに達している場合$i$、彼はレベルにジャンプすることができます$i+1$当日$j$費用のために$c_{i,j}$、そして、同じ日に複数のアップグレードを連鎖させることができ、連続した移行の合計を支払うことで、事実上、1 日に複数のレベルにジャンプすることができます。 第二に、滞在する場合: 一日の終わりの場合$j$ヤンはレベルにある$i$、彼は宿泊費を支払わなければなりません$d_{i,j}$。 唯一の例外は、選択したサイクルの最終日であり、宿泊費は支払われません。 

重要な自由度は、開始日によって両方のコスト マトリックスの列の順序が変更されることです。 彼がその日から始めるなら$x$、彼は順番に日々を経験します$x, x+1, \dots, N, 1, \dots, x-1$、このローテーション順序の最終日は宿泊費が無料です。 

目標は、開始日と考えられるすべてのアップグレード戦略のすべての選択肢にわたって総コストを最小限に抑えることです。 

制約$N, M \le 1500$これは、すべての状態と遷移にわたる単純なシミュレーションでは、3 次以上の動作を回避する必要があることを意味します。 より近い解決策$O(NM^2)$それ以上の場合は通過できません。 この構造は、循環シフトに対する追加の最適化を伴う動的プログラミングの定式化を強く示唆しています。 

ローテーションと「最終日は無料」ルールとの相互作用から、微妙な問題が発生します。 1 日目を最終日として固定したり、回転対称性を無視した単純な解決策では、不正確なコストが計算されます。 もう 1 つの一般的な障害モードは、同日の複数のレベルにわたる累積的な移行を考慮せずに、アップグレードをレベルごとに独立したものとして扱うことです。 

## アプローチ

 直接的なアプローチでは、考えられるすべての戦略をシミュレートします。つまり、開始日を選択し、毎日シミュレートし、レベル ジャンプの最適なシーケンスを計算します。 開始日を固定したとしても、レベル 1 からレベルに移行するための最も安価な方法を毎日知る必要があります。$M$一連のトランジションを使用して、毎日の終わりのレベルに応じて宿泊費を蓄積します。 

これは、固定順序で日数のプレフィックスを処理した後、特定のレベルになるための最小コストを追跡する動的プログラミング状態を示唆しています。 ただし、1 つの固定スタートの場合でも、滞在コストはその日のすべてのアップグレード後の最終レベルに依存するため、その日のレベル間の移行は独立していません。 

重要な観察点は、アップグレードが単調であるということです。Yan は次からのみ移動します。$i$に$i+1$、同じ日に複数のステップが連鎖を形成します。 これにより、1 日あたりの遷移構造が折れ線グラフ上の最短パスになります。$M$エッジの重みは日によって異なります。 さらに、宿泊費は一日の終わりのレベルにのみ依存するため、DP 移行に組み込むことができます。 

固定の日数ローテーションについては、次のように定義します。$dp[i]$その日をそのレベルで終了するための最小コストとして$i$。 毎日、新しい配列を計算します$ndp$その日のアップグレードコストを使用して可能なすべての上向きチェーンを許可し、結果のレベルに基づいて宿泊コストを追加します。 これは基本的に、毎日の DAG 上の最短パスです。 

ローテーションを処理するために、可能なすべての開始日を最終日の候補として扱います。 回転ごとに DP を最初から再計算するのではなく、プロセスが円形配列の連続したセグメントのみに依存していることがわかります。 したがって、1 回転ごとに 1 回 DP を実行することで、すべての開始位置を評価します。$O(N^2 M)$ただし、これは計算を再利用し、何日もかけて慎重に DP 遷移を行うことで最適化できます。 

最終的に最適化されたソリューションは、ローテーションごとの DP を維持しますが、毎日の移行を実行します。$O(M)$プレフィックス緩和を使用すると、全体的に複雑になります$O(NM)$実装戦略に応じて、ローテーションごとに、またはそれ以上の効果が得られます。 回転は$N$では、毎日が開始点としてローリング方式で 1 ​​回だけ処理されるように、再利用を活用しています。

 ## アルゴリズムのチュートリアル

 この問題を、サイズのベクトルに日変換を繰り返し適用するものとして再解釈します。$M$、次に、最終日には宿泊費がかからないすべての循環シフトの最小値を取得します。 

コストがレベルを通じてどのように上方に伝播するかを毎日事前計算し、その日のアップグレードが完了した後に宿泊費を組み込みます。 

1. 開始日を固定する$s$。 から始まる周期的な順序で日をシミュレートします。$s$、治療日$s-1$宿泊無料最終日となります。 これにより、回転が線形 DP 問題に変換されます。 
2.初期化$dp$そのような$dp[1] = 0$そして他のすべてのレベルは無限です。 これは、一日が始まる前にレベル 1 から開始することを反映しています。 
3. 日を順番に処理します。 特定の日について$j$、上向き遷移のみを使用してすべてのレベルに到達する最適な方法を計算します。$c_{i,j}$。 これを行うには、レベル 1 から 2 までをスキャンします。$M$、レベルに到達するための最小コストを維持します$i$滞在するか、レベルから来ることによって$i-1$そして支払い$c_{i-1,j}$。 これにより、レベルのチェーンに沿って「その日のうちの最短パス」が構築されます。 
4. レベルのアップグレードを完了するためのコストを取得したら$i$当日$j$、宿泊費を加算させていただきます$d_{i,j}$ただし、選択したローテーションの最終日を除き、この追加をスキップします。 
5. 結果の配列を新しい配列として保存します$dp$。 これは、その日を終えるまでの最低コストを表します$j$すべての決定を経て、各レベルで。 
6.すべての処理が完了したら$N$固定開始日の場合は、すべてのレベルの最小値を回答候補として記録します。 
7. 考えられるすべての開始日に対して繰り返し、すべての結果の最小値を取得します。 

重要な点は、日中の緩和が直線的であるということです。$M$なぜなら、遷移は上向きにのみ進み、パス グラフを形成するからです。 

### なぜ効果があるのか

 いつでも、状態は現在のレベルによって完全に記述され、将来のすべてのコストはそのレベルと残りの日数のみに依存します。 DP の不変条件は、1 日の処理後に、$dp[i]$その日をそのレベルで終了するために可能な最小コストを表します$i$、その日および選択したローテーションの前日のすべての有効なアップグレード順序を考慮します。 すべての遷移は留まるか、次のレベルに移行するかのいずれかであり、コストは加算的で日ごとに異なるため、前のレベルの最適なプレフィックスが判明すると、1 日以内に別の順序で状態を改善することはできません。 これにより、日全体および毎日のレベル進行の両方で最適な下部構造が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    N, M = map(int, input().split())
    
    c = []
    for _ in range(M - 1):
        c.append(list(map(int, input().split())))
    
    d = []
    for _ in range(M):
        d.append(list(map(int, input().split())))
    
    # We will try every starting day, but we do DP efficiently per start.
    # Precompute arrays for convenience
    ans = INF

    # We rotate by starting index s
    for s in range(N):
        dp = [INF] * (M + 1)
        dp[1] = 0

        # process N days starting from s
        for step in range(N):
            j = (s + step) % N

            ndp = [INF] * (M + 1)

            # within-day upward relaxation
            ndp[1] = dp[1]

            for i in range(2, M + 1):
                ndp[i] = min(ndp[i - 1] + c[i - 2][j], dp[i])

            # accommodation cost except last day
            if step != N - 1:
                for i in range(1, M + 1):
                    ndp[i] += d[i - 1][j]

            dp = ndp

        ans = min(ans, min(dp[1:]))

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、可能な開始日ごとに動的プログラムを実行します。 開始ごとに、$N$日を順番に並べます。 キーの内部遷移は、レベルを 1 回通過する際の上方への到達可能性を計算します。`ndp[i]`レベルに対する以前の最高コストを維持する$i$またはレベルから来ます$i-1$その日のアップグレード費用が追加されます。 

宿泊料金は、明細書に 1 日の終わりに支払われると指定されているため、アップグレード フェーズの後に追加されます。 チェックを入れると、選択したローテーションの最終日がこの追加から除外されます。`step != N - 1`。 

初期化`dp[1] = 0`コストが支払われる前に、レベル 1 からエンコードが開始されます。

 ## 特殊なケース

 重要なエッジケースの 1 つは、宿泊費がアップグレード費用に比べて非常に高額である場合です。 このような状況では、将来の調整ペナルティを軽減するために早期に高レベルに急ぐことが最適な戦略であり、DP は 1 日以内に複数のレベルのジャンプを許可する必要があります。 

別のエッジ ケースは、アップグレード コストが数日間ゼロになる場合に発生します。 そうすればヤンはレベルに到達できる$M$また、ソリューションでは、調整が中間日にわたって引き続き正しく適用され、選択したローテーションの最終日のみスキップされることを保証する必要があります。 

3 番目のエッジケースは、$N=1$。 サイクルは退化し、その日だけが最後の自由日でもあります。 正解は、宿泊費が支払われないため、アップグレード費用のみがゼロになります。 

日内の緩和では任意の上向きの動きが可能であり、最終日の条件では最後の調整寄与が明示的に削除されるため、これらはそれぞれ DP によって自然に処理されます。
