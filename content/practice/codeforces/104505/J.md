 ## 解決策
 ## 問題の理解

 私たちには次のようなシステムが与えられています$m$シンボル。それぞれ最初は 2 つの状態のいずれかにあり、$n$スイッチ（レバー）。 各レバーは、正確に 2 つの異なるシンボルに接続されています。 レバーを引くと、接続された両方のシンボルの状態が反転します。0 は 1 になり、1 は 0 になります。レバーは最大 1 回使用でき、引くレバーのサブセットを選択できます。 

目標は、すべてのフリップを適用した後、すべてのレバーの最終構成となるようなレバーのサブセットが存在するかどうかを判断することです。$m$シンボルは、指定されたターゲット バイナリ文字列と一致します。 存在する場合は、レバーの有効なサブセットを出力する必要があります。 

各レバーは効果的に 2 つの位置を切り替えるため、問題は、初期状態とターゲット状態の間で必要な最終的な差に一致する各頂点でのパリティ変更を誘発する端点を持つエッジを選択することです。 

制約は大きく、最大で$5 \cdot 10^5$レバーとシンボル。 これにより、エッジのサブセットを考慮したり、密な行列に対してガウス消去を実行したりするアプローチは除外されます。 平$O(n^2)$エッジや頂点を推論することは不可能です。 各エッジが一定の回数処理されるように、この構造を利用する必要があります。 

レバーによって引き起こされたグラフが切断されると、微妙なエッジケースが発生します。 各接続コンポーネントは独立してパリティ条件を満たさなければなりません。 たとえば、コンポーネントの合計不一致が奇数であるにもかかわらず、それを内部的に修正するエッジがない場合、答えは不可能です。 別の失敗例は、コンポーネント内の不一致ノードの単純な貪欲ペアリングが、任意のペアリングが常に可能であると想定している場合に発生します。 実際、サイクルが重要です。 

## アプローチ

 各シンボルをノード、各レバーを無向エッジと考えると、レバーの選択は両方のエンドポイントを切り替えることに対応します。 値を定義しましょう$d[v]$頂点での初期状態とターゲット状態の間の XOR として$v$。 次に、すべての頂点に対して次のようなエッジを選択する必要があります。$v$、選択された入射エッジの数は以下に一致します。$d[v]$モジュロ 2。 

これは古典的な定式化です。つまり、発生パリティが指定された頂点パリティ ベクトルと一致するエッジのサブセットが必要です。 線形代数の用語では、これはグラフの入射行列を使用して GF(2) 上の系を解くことです。 

ブルートフォースアプローチでは、エッジのすべてのサブセットを試行したり、最大サイズのサブセットに制限したりすることもあります。$n$、結果の頂点パリティをチェックします。 つまり$O(2^n \cdot m)$、完全に不可能です。 

より構造化された試みは、これを線形方程式として扱い、ガウス消去法を実行することです。$m$変数と$n$方程式。 これでもまだ大きすぎます。行列はまばらですが、一般的な消去法では依然として大まかに劣化します。$O(nm)$。 

重要な点は、すべてのソリューションではなく、有効なソリューションのみが必要であるということです。 グラフ上では、コンポーネントごとにソリューションを構築することでパリティ制約を満たすことができます。 接続されたコンポーネント内では、スパニング ツリーを選択し、それを使用してパリティを上または下にプッシュできます。 これにより、問題はツリー状の伝播に縮小され、余剰パリティがエッジに沿って固定されます。 

各接続コンポーネントをルート化し、不一致を計算し、DFS を通じて奇妙なものを貪欲にペアリングまたは伝播します。 各エッジが一度考慮され、段階的に答えが構築されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot m)$|$O(m)$| 遅すぎる |
 | 最適 |$O(n + m)$|$O(n + m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 シンボルを頂点としてモデル化し、レバーをエッジとしてモデル化します。 

1. 不一致配列を計算する$d[v]$、 どこ$d[v] = a[v] \oplus target[v]$。 これは頂点かどうかを表します$v$インシデントの選択されたエッジからの奇数のフリップが必要です。 
2. すべてのレバーを使用してグラフの隣接リストを作成します。 
3. 訪問した配列と選択したエッジを保存するリストを維持します。 
4. 未訪問の頂点ごとに、DFS を実行して、接続されているコンポーネントのスパニング ツリーを抽出します。 DFS は、ノードをルートとするサブツリーに、上方にプッシュする必要がある奇数パリティ要件があるかどうかを返します。 
5. DFS 中は、最初に子を処理します。 子供のために$u$、そのパリティバランスを再帰的に計算します。 子がまだ満たされていないパリティ (値 1) を持っていることを返した場合、現在のノードと子の間のエッジを選択する必要があります。 このエッジを選択すると両方のエンドポイントが反転するため、そのレバーを記録し、現在のノードのパリティ要件を切り替えます。 
6. すべての子を処理した後、現在のノードの更新されたパリティ要件をその親に返します。 
7. コンポーネント全体を処理した後、ルートがパリティを満たしているかどうかを確認します。 そうでない場合、それを修正する親エッジがないため、構成は不可能です。 

重要な点は、エッジを選択するとパリティが局所的に解決されますが、反転が上向きに伝播し、修正がルートに向かって移動できるようになることです。 

### なぜ効果があるのか

 DFS は不変条件を維持します。ノードのサブツリーを処理した後、ルートを除くそのサブツリー内のすべての頂点は、サブツリー内のエッジのみを使用してすでにパリティ制約を満たしています。 残っている不一致は、上方に繰り上げられる単一ビットとして表されます。 すべてのエッジは最大 1 回、子サブツリーが奇妙な要件を報告する場合にのみ使用されるため、すでに処理されたサブツリー内に不整合が生じることはありません。 コンポーネントに有効な解決策がある場合、この上向きの伝播は、エッジの実行可能な選択と正確に一致します。 そうでない場合、コンポーネントのルートは未解決のパリティで終了し、不可能であることがわかります。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

n, m = map(int, input().split())

g = [[] for _ in range(m)]
for i in range(n):
    u, v = map(int, input().split())
    u -= 1
    v -= 1
    g[u].append((v, i))
    g[v].append((u, i))

target = list(map(int, input().split()))

visited = [False] * m
used_edge = [False] * n
answer = []

def dfs(v, parent):
    visited[v] = True
    need = target[v]

    for to, eid in g[v]:
        if to == parent:
            continue
        if not visited[to]:
            child_need = dfs(to, v)
            if child_need:
                used_edge[eid] = True
                answer.append(eid + 1)
                need ^= 1

    return need

for i in range(m):
    if not visited[i]:
        root_need = dfs(i, -1)
        if root_need:
            print(-1)
            exit()

print(len(answer))
print(*answer)
```隣接リストには各レバーの両方のエンドポイントとそのインデックスが保存されるため、選択したセットを再構築できます。 DFS は、頂点をルートとするサブツリーがその親エッジからの反転をまだ必要としているかどうかを示すパリティ ビットを返します。 

の`need`変数は、ノードでの現在の未解決のパリティを表します。 子サブツリーが 1 を返すたびに、そのエッジがアクティブ化されます。これにより、子の要件が反転され、XOR を使用して親の要件が切り替わります。 これは、レバーを適用した効果を反映します。 

よくある落とし穴は、DFS ツリーが任意ではないことを忘れていることです。つまり、パリティの伝播にはツリーのエッジのみが使用されます。 二重カウントを防ぐためにバックエッジは無視されます。 もう 1 つの微妙な問題は再帰の深さです。グラフは最大で長いチェーンになる可能性があるためです。$5 \cdot 10^5$。 

## 実用的な例

 ### 例 1

 入力:```
2 3
1 2
2 3
1 0 1
```私たちはチェーンを構築します$1 - 2 - 3$。 ターゲットの不一致ベクトルはすべて 0 であるため、反転は必要ありません。 

| ノード | 入ってくるニーズ | 子が処理されました | 選択されたエッジ | 最新のニーズ |
 | --- | --- | --- | --- | --- |
 | 3 | 1 | なし | なし | 1 |
 | 2 | 0 | 3 は 1 を返します | (2,3) | 1 |
 | 1 | 1 | 2 は 1 を返します | (1,2) | 0 |

 DFS は 1 から開始し、チェーンを通じてニーズを伝播し、両方のエッジを選択してパリティを一貫して解決します。 これは、ルートのバランスがとれるまでパリティ補正が上向きに伝播することを示しています。 

### 例 2

 入力:```
3 2
1 2
2 3
0 0 1
```チェーンはありますが、反転が必要なのはノード 3 だけです。 

| ノード | 入ってくるニーズ | 子が処理されました | 選択されたエッジ | 最新のニーズ |
 | --- | --- | --- | --- | --- |
 | 3 | 1 | なし | なし | 1 |
 | 2 | 0 | 3 は 1 を返します | (2,3) | 1 |
 | 1 | 0 | 2 は 1 を返します | (1,2) | 1 |

 ルートは未解決のパリティで終了するため、解決策は存在しません。 アルゴリズムは正しく -1 を出力します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n + m)$| 各レバーは、隣接リストの DFS トラバース中に 1 回だけ処理されます。 
| スペース |$O(n + m)$| 最悪の場合のグラフ表現と再帰スタック |

 制約により、最大で$5 \cdot 10^5$ノードとエッジが含まれるため、線形時間トラバーサルは制限内に快適に収まります。 メモリ使用量はグラフ サイズ内で線形のままです。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    n, m = map(int, input().split())
    g = [[] for _ in range(m)]
    for i in range(n):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, i))
        g[v].append((u, i))

    target = list(map(int, input().split()))
    vis = [False] * m
    ans = []

    sys.setrecursionlimit(10**7)

    def dfs(v, p):
        vis[v] = True
        need = target[v]
        for to, eid in g[v]:
            if to == p:
                continue
            if not vis[to]:
                child = dfs(to, v)
                if child:
                    ans.append(eid + 1)
                    need ^= 1
        return need

    for i in range(m):
        if not vis[i]:
            if dfs(i, -1):
                return "-1\n"
    return str(len(ans)) + ("\n" + " ".join(map(str, ans)) if ans else "")

 ## 特殊なケース

 ターゲット パリティの和が奇数である切断されたコンポーネントは、すべてのエッジが 2 つの頂点を反転し、グローバル パリティを維持するため修正できません。 DFS は最終的にルートでゼロ以外の値を返し、拒否を引き起こします。 

チェーンが長いと再帰の深さが強調されます。 このアルゴリズムは引き続き各エッジを 1 回処理しますが、再帰制限を増やさないと Python でクラッシュします。 

すべて修正が必要な複数の子を持つノードは、欲張りペアリングが機能する理由を示しています。1 を返す各子は、厳密に 1 つのエッジ選択を強制し、トグルにより二重修正が上方に漏れないようにします。
