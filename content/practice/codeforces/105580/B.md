 ## 解決策
 ## 問題の理解

 それぞれの長さの 3 つの並列リストが与えられます。$N$、ギタリスト、ベーシスト、ドラマーという 3 つの異なる役割のミュージシャンを表します。 各ミュージシャンにはスキル値があり、正確に形成する必要があります$N$グループ。各グループには各役割の 1 人が含まれます。 

グループの価値は、その 3 人のメンバーの最大スキルとして定義されます。 利益の合計は、これらのグループ値の合計です。 タスクは、すべてのミュージシャンが 1 回だけ使用され、グループの最大値の合計ができるだけ大きくなるように、ミュージシャンをグループに割り当てることです。 

制約$N \le 10^5$大まかに考えることを強いられる$O(N \log N)$またはそれより良い条件。 3 つの配列間のすべてのマッチングを試みる解決策は、代入の階乗増加を伴うため、直ちに不可能になります。 分岐または後戻りするペアごとのマッチング戦略であっても、組み合わせ的に爆発する可能性があります。 

貪欲なペアリングがグローバル構造を無視する場合、微妙な失敗例が発生します。 たとえば、ある役割には多くの小さな値があり、別の役割には非常に大きな値がいくつかあるとします。 計画せずにローカルでペアリングすると、最大値が増加しないグループ内の大きな値が「無駄になる」可能性があります。 

次の小さな例を考えてみましょう。 

入力:```
G: 1 100
B: 1 2
D: 1 3
```If we pair greedily without structure, we might end up using 100 in a group with 1 and 1, producing 100, and then the remaining group is (1,2,3) giving 3, total 103. But a different pairing is impossible here, so this is fine. 本当の問題は、1 つの配列に多数の大きな値が存在し、グループ間で慎重に分散する必要がある場合に明らかになります。 

主なリスクは、間違った方向への単純な並べ替えや、任意の極端な不一致により、大きな値の合計寄与が減少する可能性があることです。 

## アプローチ

 ブルートフォースアプローチでは、3 つの配列にわたってトリプルを割り当てるすべての方法を列挙しようとします。 1 つの順列を修正して他の順列を一致させたとしても、依然として次のような問題に直面します。$N!$可能性。 それぞれの評価にかかる費用$O(N)$、したがって、これは実現可能な限界をはるかに超えています。 

より構造化された総当たり攻撃では、配列をソートし、固定パターンで最大値と最大値をペアにしようとする可能性があります。 これは高速ですが、正当な理由が必要です。 問題は、最適な割り当てを表現しやすい順序を常に想定できるかどうかです。 

重要な洞察は、実際に何が答えに寄与するかを観察することから得られます。 各グループは最大値を寄与するため、選択された 3 つの要素のうち最大の要素のみが問題になります。 逆に考えると、そのグループにすでに割り当てられているさらに大きな値によってブロックされない限り、それぞれの大きな値はグループを「要求」できます。 

これは、大きな値を可能な限り異なるグループに配置する必要があることを示唆しています。これは、大きな値を積み重ねると貢献が無駄になり、最大カウントのみが無駄になるためです。そのため、大きな値を同じグループにマージすると潜在的な利益が破棄されます。 

これは貪欲な戦略につながります。つまり、すべてのロールのすべての値を降順で並べ替え、それらを 1 つずつグループに割り当て、ロール全体で構造化された循環的な方法で、次に大きい未使用の値を次に使用可能なグループに常に配置します。 より正確には、各インデックスが一致するように位置を合わせます。$i$からグループを形成します$i$ソートされた各ロールの - 番目の要素。 したがって、各グループの最大値は、単純にその 3 つの整列された値の最大値になります。 

この位置合わせが機能するのは、並べ替えによって各位置に対して次のことが保証されるためです。$i$、残りの要素はすべて以前の要素よりも大きくないため、配置を遅らせても潜在的な最大値が「失われる」ことはありません。

 | ブルートフォース | 指数 | O(N) | 遅すぎる |
 | 並べ替え + 貪欲な配置 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 問題を 3 つの同期された並べ替えリストに分割することで、解決策を構築します。 

1. ギタリスト、ベーシスト、ドラマーを表す 3 つの配列を読み取ります。 これらは、ポジション間で 1 対 1 に一致する必要がある独立したプールを表します。 
2. 3 つの配列をそれぞれ非昇順に並べ替えます。 これにより、左から右に反復するときに、常に各ロールで残っている最も強力な候補が最初に表示されるようになります。 大きな値が初期のグループ形成に影響を与える必要があるため、この順序は非常に重要です。 
3. 要素をインデックスでペアにする: グループを形成する$i$を使用して$i$-番目のギタリスト、$i$-番目のベーシスト、そして$i$-番目のドラマー。 これにより、$N$曖昧さのない固定グループ。 
4. 各グループについて、選択した 3 つの値の最大値としてその寄与を計算します。 これを現在の合計に追加します。 
5. 総和を出力します。 

唯一の明白ではないステップは、ソート後のインデックスごとのペアリングがなぜ有効なのかです。 直感的には、ソートによって役割間の「ランク」が調整されるため、$i$各配列の - 番目の要素は、$i$- 番目に有力な残りの候補者。 同等のランクを一致させることで、すでに強力なグループ内の強力な要素を無駄にするような、非常に強い要素と非常に弱い要素の混合が回避されます。 

### なぜ効果があるのか

 この構造は、各トリプルの最大値のみが重要であるという事実に基づいています。 並べ替え後の位置の任意の要素$i$位置にあるすべての要素と少なくとも同じ大きさであることが保証されます$j > i$。 つまり、グループを形成するとき、$i$、残りの要素から取得できる最良の最大値は、現在位置合わせされたトリプルによってすでに表されています。 より大きな要素を後のグループに移動しようとする代替の再配置では、最大値は同じグループ内の複数の大きな要素から累積されないため、総和は改善されずに、より小さい最大値が前のグループに強制的に移動されます。 これにより、交換時の最適性が維持されます。配列がソートされ整列されると、グループ間で割り当てを交換しても合計を増やすことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    g = list(map(int, input().split()))
    b = list(map(int, input().split()))
    d = list(map(int, input().split()))

    g.sort(reverse=True)
    b.sort(reverse=True)
    d.sort(reverse=True)

    ans = 0
    for i in range(n):
        ans += max(g[i], b[i], d[i])

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、3 つの役割配列を読み取り、降順に並べ替えます。 並べ替えにより、残っている最も強力な候補が同じインデックスに配置されるようになります。 次に、ループはインデックスによって暗黙的に各グループを構築し、整列された 3 つの値の最大値として各グループの寄与を計算します。 この実装は Python の効率的なソートに依存しており、追加のデータ構造を回避します。 

よくある間違いは、昇順で並べ替えたり、インデックスを間違って混合したりすることです。 もう 1 つの微妙な問題は、明示的なグループ化構造が必要であると仮定していることですが、グループごとの最大値のみが重要であるため、これは不必要です。

 | 私 | ギ[i] | B[i] | D[i] | グループ最大 |

 | 私 | ギ[i] | B[i] | D[i] | グループ最大 |

これは、単一のグループが複数の大きな値を吸収するのを防ぎ、整列させたときに強い値がグループ全体に自然に分散する様子を示しています。

## テストケース```python
import sys, io

def solve():
    input = sys.stdin.readline
    n = int(input())
    g = list(map(int, input().split()))
    b = list(map(int, input().split()))
    d = list(map(int, input().split()))

    g.sort(reverse=True)
    b.sort(reverse=True)
    d.sort(reverse=True)

    ans = 0
    for i in range(n):
        ans += max(g[i], b[i], d[i])

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    solve()
    return out.getvalue().strip()

# provided sample

""") == "3"

 ## 特殊なケース

 エッジ ケースの 1 つは、1 つの配列に非常に大きな値が 1 つだけあり、他の配列は一律に小さい場合です。 例えば：```
n = 3
G = [100, 1, 1]
B = [2, 2, 2]
D = [3, 3, 3]
```並べ替え後:```
G = [100, 1, 1]
B = [2, 2, 2]
D = [3, 3, 3]
```インデックスごとにグループ化すると、次のようになります。 

| 私 | G | B | D | 最大 |
 | --- | --- | --- | --- | --- |
 | 0 | 100 | 2 | 3 | 100 |
 | 1 | 1 | 2 | 3 | 3 |
 | 2 | 1 | 2 | 3 | 3 |

 このアルゴリズムは、100 を独自のグループに正確に分離し、希釈されるのを防ぎます。 

もう 1 つのケースは、すべての配列が同一であるがソートされていない場合です。```
G = [3, 1, 2]
B = [2, 3, 1]
D = [1, 2, 3]
```ソート後はすべて [3,2,1] になり、グループ化により一貫した位置合わせされた最大値が生成されます。 ソートを行わないと、任意のペアリングによって大きな値が最適ではない位置に分散され、合計が減少する可能性があります。
