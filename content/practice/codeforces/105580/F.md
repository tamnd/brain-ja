 ## アルゴリズムのチュートリアル

 この問題を次の素因数の割り当てとして再解釈します。$V$規制当局へ。

2. 各レギュレーターごと$i$、どの素数をサポートできるかを決定します。 レギュレーターはプライムのみを取ることができます$p$もし$p \le m_i$。 それ以外の場合は、次のように設定する必要があります$1$。

4. 素数を降順に処理します。$p$。 この順序は、大きな素数には適格なレギュレーターが少ないため、ブロッキングを避けるために最初に割り当てます。 
5. 素数が出現するたびに$p$、候補リストから未使用のレギュレーターに割り当てます。 利用可能なレギュレータが不足すると、すぐに不可能と結論付けます。 
6. すべての素数出現を割り当てた後、使用されていないレギュレータはすべて次のように設定されます。$1$。 使用されるレギュレーターは、割り当てられたプライムに設定されます。 

### なぜ効果があるのか

 正確さは、各レギュレータが 1 つの乗算係数に寄与するという事実に基づいています。$1$またはプライム。 これは、各レギュレーターが因数分解で最大 1 回使用できることを意味します。$V$。 問題は素数の出現とレギュレーターの間の二部マッチングになり、レギュレーターがその素数を許可する場合にのみエッジが存在します。 

素数の順序が減少する貪欲な割り当ては機能します。これは、素数が大きくなると配置が厳密に制限されるためです。 大きな素数を配置できない場合は、より小さな素数を交換しても大きな素数の適格性が増加しないため、より小さな素数を使用して再配置しても容量の制約に違反することなく問題を解決できません。 したがって、最も制約された要素を最初に処理することで、実現可能性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def factorize(x):
    primes = []
    d = 2
    while d * d <= x:
        if x % d == 0:
            cnt = 0
            while x % d == 0:
                x //= d
                cnt += 1
            primes.append((d, cnt))
        d += 1
    if x > 1:
        primes.append((x, 1))
    return primes

def solve():
    M, V, N = map(int, input().split())
    m = list(map(int, input().split()))

    factors = factorize(V)

    # expand prime factors into list of occurrences
    items = []
    for p, c in factors:
        for _ in range(c):
            items.append(p)

    # sort primes descending
    items.sort(reverse=True)

    used = [False] * N
    ans = [1] * N

    # for each prime occurrence, assign to best available regulator
    for p in items:
        idx = -1
        for i in range(N):
            if not used[i] and m[i] >= p:
                idx = i
                break
        if idx == -1:
            print(-1)
            return
        used[i] = True
        ans[i] = p

    print(*ans)

if __name__ == "__main__":
    solve()

次に、素数を降順に並べ替えて、より大きな素数が最初に割り当てられるようにします。 割り当てループは、各素数をサポートできる未使用のレギュレーターに各素数を配置しようとします。 そのようなレギュレーターが存在しない場合は、早期に終了します。 

各レギュレーターは素数を受け取ると使用済みとしてマークされ、各レギュレーターが最大 1 つの素因数に寄与するという制約が強制されます。 未使用のレギュレーターが残っている$1$、許可された中立要素と一致します。 

微妙な点は、有効なインデックスの貪欲スキャンは線形であるということですが、これは問題ありません。$N \le 50$。 規模が小さいため、より複雑なマッチングは必要ありません。

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$V = 1$。 因子リストは空になるため、すべてのレギュレーターは未使用のままとなり、次のように設定する必要があります。$1$。 素数の割り当ては行われず、初期配列はすべて 1 であるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、必要な素数がすべての素数よりも大きい場合です。$m_i$。 たとえば、次の場合$V = 17$そしてすべて$m_i = 10$、因数分解すると単一の 17 が生成されますが、規制当局はそれを受け入れることができません。 代入ループはすぐに失敗し、リターンします。$-1$。
