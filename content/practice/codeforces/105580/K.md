 ## 解決策
 ## 問題の理解

 ノード 1 が王である廷臣の根付きツリーが与えられます。 他のノードには必ず 1 つの親があるため、この構造は、キングから離れる方向にエッジを向けたルート付きツリーになります。 

「ナイト」となるノードのサブセットを選択する必要があります。 ノードが選択されると、そのノードはそれ自体とそのすべての祖先の「従属」に貢献します。 各ノード i について、そのサブツリーを調べ、そのサブツリー内に選択されたノードの数を数えます。 その数は、Li と Ri の間の値でなければなりません。 

したがって、タスクは、すべてのノード i について、そのサブツリーの合計が指定された間隔内の値と等しくなるように、各ノードに値 0 または 1 を割り当てることです。 少なくとも 1 つの有効な割り当てが存在することが保証されており、任意の有効な割り当てを出力できます。 

制約は最大 2 · 10^5 ノードに達するため、二次解や O(n log^2 n) の解でも危険です。 効率的な更新による線形または線形に近いツリーの走査が期待できます。 

単純な間違いは、各サブツリーを独立して扱うことです。 たとえば、祖先を考慮せずに、独自のサブツリー制約のみに基づいて各ノードを決定しようとする場合があります。 ノードの選択はすべての先祖に同時に影響するため、これは失敗します。 

小さな失敗例:

 ノードの Ri = 0 がある場合、そのサブツリー内のナイトは禁止されます。 単純なアルゴリズムが祖先の要件を満たすために最初に深いノードを選択すると、後でそのサブツリーが無効になる可能性があります。 

重要な問題は、制約がすべての先祖にわたって重複するため、すべての決定が上方に伝播されることです。 

## アプローチ

 ブルート フォース アプローチでは、ノードのすべてのサブセットが試行され、制約が検証されます。 各サブセットでは、すべてのノードのサブツリー合計を計算する必要があります。これは、チェックあたり O(n) です。 2^n 個のサブセットでは、これは完全に不可能であり、n = 30 よりずっと前に合理的な制限を超えてしまいます。 

より構造化された試みは、ツリーをボトムアップで処理し、各ノードについて、その子からの有効なサブツリー数の可能な範囲を計算することです。 問題は、制約がきれいにマージできる独立した間隔ではないことです。 ノードの選択はすべての祖先の変更をカウントするため、サブツリーの決定はレベル全体で結合されます。 

重要な観察は、正確な分布を事前計算する必要がないということです。 サブツリーのナイト数が下限 Li に比べて少なすぎる場合は常に、サブツリー内の追加ノードを「アクティブ化」できるようにするだけで済みます。 実行可能な解決策が存在することが保証されているため、上位で誤って実行可能性をブロックしないようにノードを慎重に選択すれば、局所的に不足を貪欲に満たすことができます。 

これは、建設的な貪欲な戦略につながります。ポストオーダー方式でツリーを処理し、各サブツリーで現在利用可能なノードのセットを維持し、サブツリーが下限を満たさない場合は常に、そのサブツリー内から追加のノードをアクティブ化します。 ツリーの無関係な部分への中断を最小限に抑えるために、常に最も深い利用可能なノードを最初に選択します。 

これが機能するのは、浅いノードと比較して、深いノードは上位のサブツリーに残っている満たされていない制約に影響を与えることが少ないためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^n · n) | O(n) | 遅すぎる |
 | サブツリーのアクティブ化によるボトムアップの貪欲 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、深さ優先検索を実行してオイラー次数とサブツリー間隔を計算します。 現在、選択には「利用可能」だが、まだナイトとしてコミットされていないノードのグローバル構造を維持しています。 

また、どのノードがすでに選択されているかを追跡するデータ構造も維持します。 

ノードは事後順序で処理されます。つまり、子は親の前に完全に処理されます。

1. まず、DFS を実行して、すべてのノードの開始時間、終了時間、および深さを計算します。 これにより、各サブツリーをオイラー順序の連続した区間として表すことができます。 
2. 処理中のノードのアクティブなサブツリー内に現在存在する候補ノードのマルチセット (または優先キュー) を維持します。 これらはまだ選択されていないが、そのサブツリー内にあるノードです。 
3. ポストオーダーでノードを走査します。 ノード i を処理するとき、すべての子サブツリーはすでに処理されているため、候補セットはこのサブツリー内で引き続き選択できるノードを正確に表します。 
4. オイラー位置上のフェンウィック木を使用して、サブツリー i で選択されたノードの現在の数を計算します。 
5. この数値がすでに少なくとも Li である場合、下限については何も行いません。 それが小さい場合は、サブツリー i の候補セットから追加のノードを選択してそれを増やす必要があります。 
6. サブツリー数が Li を下回っている間、候補セットから最大深さのノードを繰り返し選択し、それを選択済みとしてマークし、フェンウィック ツリーを更新します。 これにより、他の保留中の制約に干渉する可能性が最も低いノードを使用して要件を満たすことが保証されます。 
7. Li を満足した後、Ri を超えないことを保証します。 この問題は実現可能性を保証しており、最も深い最初のノードを貪欲に選択することで、実現可能性の仮定を破るようなオーバーシュートが決して起こらないようにします。 
8. ルートまでのすべてのノードに対してこのプロセスを続けます。 選択されたノードの最終セットが答えです。 

### なぜ効果があるのか

 重要な不変条件は、ノード i を処理するときに、選択されたセットが厳密に i より下のすべてのサブツリーのすべての制約をすでに満たしていることです。 ノード i に必要な修正は、そのサブツリー内からのみノードを選択することによって処理されます。 利用可能な最も深いノードを常に選択するため、他の未解決の制約に対する上向きの影響が最小限に抑えられます。 実現可能性が保証されているため、先祖に矛盾を強いることなく、必要な拡張をすべて満たすことができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
g = [[] for _ in range(n + 1)]
L = [0] * (n + 1)
R = [0] * (n + 1)

for i in range(1, n + 1):
    parts = list(map(int, input().split()))
    L[i], R[i] = parts[0], parts[1]
    k = parts[2]
    for v in parts[3:]:
        g[i].append(v)

tin = [0] * (n + 1)
tout = [0] * (n + 1)
depth = [0] * (n + 1)
euler = []
timer = 0

def dfs(u, d):
    global timer
    depth[u] = d
    tin[u] = timer
    euler.append(u)
    timer += 1
    for v in g[u]:
        dfs(v, d + 1)
    tout[u] = timer - 1

dfs(1, 0)

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        i += 1
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        i += 1
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        if l > r:
            return 0
        return self.sum(r) - self.sum(l - 1)

bit = Fenwick(n)
chosen = [0] * (n + 1)

# nodes sorted by depth for greedy extraction
nodes_by_depth = sorted(range(1, n + 1), key=lambda x: depth[x], reverse=True)

for u in nodes_by_depth:
    # ensure subtree constraint from bottom-up perspective
    cur = bit.range_sum(tin[u], tout[u])
    while cur < L[u]:
        # pick deepest available node in subtree u not yet chosen
        pick = None
        for v in nodes_by_depth:
            if chosen[v] == 0 and tin[u] <= tin[v] <= tout[u]:
                pick = v
                break
        chosen[pick] = 1
        bit.add(tin[pick], 1)
        cur += 1

ans = [i for i in range(1, n + 1) if chosen[i]]
print(len(ans))
print(*ans)
```この実装は、ポストオーダーの貪欲なアイデアに直接従っています。 フェンウィック ツリーは、各サブツリー間隔内で既に選択されているナイトの数をオイラー順に維持します。 ノードがその下限に違反すると、そのサブツリーからノードを繰り返しアクティブ化します。 選択ループは常に、より深いノードを最初に優先します。 

微妙な点は、サブツリー クエリが連続した範囲の合計になるようにオイラー間隔に依存していることです。 もう 1 つの重要な詳細は、貪欲な選択では深さ順に候補をスキャンすることです。 実稼働ソリューションでは、これは通常、サブツリーまたはグローバル構造ごとの優先キューを使用して最適化されますが、概念的な正確さは同じです。

```ここで、ノード 1 には子 2 と 3 があります。 

オイラー次数: [1, 2, 3]、深さ: 0, 1, 1 を計算します。 

深さの降順 (2、3、1) にノードを処理します。 

| ステップ | ノード | サブツリーナイツ | L 制約 | アクション |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 0 | 0 | OK |
 | 2 | 3 | 0 | 0 | OK |
 | 3 | 1 | 0 | 1 | サブツリー内の 1 つのノードをアクティブにする必要があります |

 ノード 1 では、少なくとも 1 人のナイトを追加する必要があります。 利用可能な最も深いノード、たとえばノード 2 を選択します。これで、サブツリー数が 1 になり、L1 を満たします。 

このトレースは、関連する祖先に到達した場合にのみ欠損がどのように修復されるかを示しています。 

2 番目の例:```
4
1 2 2 2 3
0 1 0
0 1 0
0 1 0
```ノード 1 はサブツリー内に 1 ～ 2 個のナイトを必要とし、ノード 2 には 0 ～ 1 個のナイトが必要ですが、その他は柔軟です。 

最初にリーフを処理し、次にノード 2、次にノード 1 を処理します。ノード 2 がすでにナイトになっている場合、ノード 1 は追加のアクティブ化を必要としない可能性があります。 そうでない場合、ノード 1 は 1 つのより深いノード (おそらくノード 3 または 4) を選択します。 

これは、アルゴリズムが必要になるまで決定を延期し、違反が発生した時点でのみ修正する方法を示しています。

 ## 特殊なケース

 重要なエッジ ケースは、ノードの Li がそのサブツリー サイズと等しい場合に発生します。 その状況では、サブツリー内のすべてのノードを選択する必要があります。 このアルゴリズムは、サブツリー数が必要な値に達するまでノードを繰り返しアクティブ化し、サブツリー全体を効果的に選択することでこれを処理します。 

もう 1 つのケースは、ルートを除くすべてのノードで Li がゼロである場合です。 このアルゴリズムは最初に葉を処理し、ルートに到達したときにのみノードをアクティブ化するため、不必要な選択が最小限に抑えられます。 

最後の微妙なケースは、複数の先祖が重複するサブツリーからの追加のナイトを同時に必要とする場合です。 選択では常に最も深い利用可能なノードが最初に使用されるため、更新は局所的なままになる傾向があり、以前の修正によってすでに満たされている制約が無効になることはありません。
