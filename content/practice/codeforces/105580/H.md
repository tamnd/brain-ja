 ## 解決策
 ## 問題の理解

 数直線上に配置されたドミノの駒のセットが与えられます。 各ピースは整数座標に位置し、高さを持っています。 アレクセイは、選択した座標 K から左右を見て、K の厳密に左側に最も近いドミノと、K の厳密に右側に最も近いドミノを特定します。そのような近隣のドミノが存在する場合、彼はそれがそれぞれ外側、左側、または右側に落ちるようにそれを押します。 

ドミノは一度倒れ始めると、次のピースに当たっただけでは止まりません。 その代わりに、到達距離はその高さによって決まります。 位置 X、高さ H で倒れるドミノは、右に倒れる場合は X+1 から X+H まで、左に倒れる場合は X-H から X-1 までの区間内のすべてのドミノに影響します。 その範囲内のドミノも落下し、独自の高さと方向で同じプロセスを再帰的にトリガーします。 

最後のタスクは、両方の最初のプッシュがシステム全体に伝播した後に最終的に倒れるドミノの数を決定することです。 

制約は大きく、最大 100,000 個のドミノと最大 1,000 万個の座標があります。 それぞれの転倒を素朴にシミュレートし、新たに影響を受けるドミノを繰り返しスキャンするソリューションは、限界をはるかに超える最悪の場合、二次的な動作に低下します。 これにより、新たにヒットしたピースを線形に繰り返し検索したり、前処理を行わずに到達間隔を再計算したりするアプローチは即座に除外されます。 

微妙な難しさはエフェクトの連鎖にあります。 複数のドミノが倒れてドミノに到達する可能性がありますが、カウントされるのは 1 回だけです。 もう 1 つのエッジ ケースは、K の片側にドミノが存在しない場合に発生します。つまり、カスケードが 1 つだけ開始されるか、まったく開始されないことを意味します。 また、座標がまばらで順序付けされていないことも重要です。そのため、並べ替えなしでは位置に直接インデックスを作成することはできません。 

エッジケースの小さな例としては、ドミノが手の届かないところに配置されている場合があります。 

入力:```
3 10
0 3
5 3
9 1
```一番右のドミノを押しても中央に到達できない場合、チェーンはすぐに停止します。 連続した位置を仮定する単純なアプローチでは、空の空間に誤って伝播する可能性があります。 

## アプローチ

 ブルートフォース シミュレーションでは、倒れたドミノの現在のセットが繰り返し拡張されます。 ドミノが倒れるたびに、他のすべてのドミノをスキャンして、それらが到達範囲内にあり、まだ倒れていないかどうかを確認します。 これは、N 個のドミノのそれぞれが残りすべてのドミノの別のスキャンをトリガーする可能性があるため、単純な O(N²) 最悪の場合の動作につながります。 

この非効率性は、新たに影響を受けるドミノを任意の間隔で繰り返し検索することから生じます。 重要な点は、実際には毎回すべての位置を検索する必要はないということです。 ドミノが座標によってソートされている場合、すべての伝播ステップはソートされた配列に対する範囲拡張になります。 すべてをスキャンする代わりに、到達可能な間隔内ですべてのドミノをすばやく見つけて一度に処理できる構造を維持できます。 

これにより、問題は、各ドミノが最大 1 回アクセスされる、ソートされたリストに対する到達可能性プロセスに変換されます。 キューまたは DFS のような伝播を使用して、要素を再度訪問することなく間隔を拡張し、ソートされた配列上でポインターを進めます。 各ドミノは 1 回キューに入れられ、単一の展開に寄与し、ソート後に線形の複雑さが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²) | O(N) | 遅すぎる |
 | ソートされた伝播 | O(N log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべてのドミノを座標で並べ替えます。 これは、空間到達範囲を線形配列内の連続したセグメントとして扱うことができるため、不可欠です。 

次に、最初のアクティブ化ポイントを特定します。 ソートされた座標の二分探索を使用して、K の厳密に左側に最も近いドミノと、K の厳密に右側に最も近いドミノを見つけます。 最初に押されるのはこれら 2 つだけなので、これらが唯一の開始点です。 

3 番目に、キューを使用して左方向と右方向の伝播を個別にシミュレートします。 各キュー エントリは、倒れたばかりのドミノを表しており、その影響は外側に広がります。 

4 番目に、ドミノを処理するときに、ドミノの方向に基づいて到達可能な間隔を計算します。 位置 X 、高さ H の右下がりのドミノの場合、(X, X+H] の座標を持つすべてのドミノをアクティブにします。リストはソートされているため、現在の位置からポインターを進めて、この範囲内のすべてのインデックスを見つけることができます。同様に、左下がりのドミノの場合は、(X−H, X) に展開します。

 第 5 に、まだアクセスされていない新たに到達したドミノはすべて、フォールドとしてマークされ、トリガーされたドミノと同じ方向のキューに押し込まれます。 これにより、伝播が正しく継続されることが保証されます。 

最後に、訪問されたすべてのドミノを数えます。 

### なぜ効果があるのか

 重要な不変条件は、ドミノがキューから取り出されるたびに、その到達間隔内にあるすべてのドミノがすでに処理されているか、または 1 回だけキューに入れられるということです。 ソートされた配列内で単調に順方向にスキャンするため、インデックスが再訪問されたり、誤ってスキップされたりすることはありません。 各ドミノは、目に見えない状態から見える状態に 1 回だけ遷移し、その影響は伝播方向に 1 回だけ適用されます。 これにより、訪問セットの合計が、最初の 2 つのプッシュからの連鎖間隔拡張を通じて到達可能なすべてのドミノと正確に一致することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left, bisect_right
from collections import deque

def solve():
    n, k = map(int, input().split())
    dom = []
    for _ in range(n):
        x, h = map(int, input().split())
        dom.append((x, h))
    
    dom.sort()
    xs = [x for x, _ in dom]
    
    vis = [False] * n
    q = deque()

    # left initial
    i = bisect_left(xs, k) - 1
    if i >= 0:
        vis[i] = True
        q.append((i, -1))  # direction: left

    # right initial
    j = bisect_right(xs, k)
    if j < n:
        vis[j] = True
        q.append((j, 1))   # direction: right

    while q:
        idx, d = q.popleft()
        x, h = dom[idx]

        if d == 1:
            reach = x + h
            nxt = idx + 1
            while nxt < n and dom[nxt][0] <= reach:
                if not vis[nxt]:
                    vis[nxt] = True
                    q.append((nxt, 1))
                nxt += 1
        else:
            reach = x - h
            nxt = idx - 1
            while nxt >= 0 and dom[nxt][0] >= reach:
                if not vis[nxt]:
                    vis[nxt] = True
                    q.append((nxt, -1))
                nxt -= 1

    print(sum(vis))

if __name__ == "__main__":
    solve()
```この解決策は、空間関係がインデックスベースの間隔になるようにドミノを並べ替えることから始まります。 最初の 2 つのプッシュは、K の周囲の二分探索を使用して検出されます。微妙な点の 1 つは、各側のすべてのドミノではなく、厳密に最近傍を選択する必要があることです。そのため、次を使用します。`bisect_left`そして`bisect_right`。 

方向によって伝播間隔が決まるため、BFS キューにはインデックスと方向の両方が格納されます。 ドミノが倒れると、ドミノは押し出された方向と常に同じ方向に伝播し続けます。これは、問題によって方向が最初の押しごとに固定されていると定義され、伝播によってその方向が保存されるためです。 

内側のループはポインターを単調に進め、各インデックスが方向チェーンごとに最大 1 回アクセスされるようにします。 これにより、最初からスキャンを繰り返すことが回避され、線形の全走査が保証されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、K が 2 つのドミノの間にあるが、どちらの側もそれ以上伝播できない場合です。 この状況では、最初の近傍のみが訪問されます。 キューは最大 2 つのエントリで初期化され、新しいノードを追加せずに両方のエントリがすぐに到達可能な間隔を使い果たすため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、各ドミノが次のドミノにかろうじて到達する長いチェーンです。 各ドミノが一度キューに入り、以前の要素を再チェックすることなくソートされたインデックスを通じて直線的に伝播が継続されるため、アルゴリズムは引き続き正しく実行されます。 

最後のケースは、すべてのドミノが K の片側にある場合です。二分ロジックにより、最初のシードが 1 つだけ作成されることが保証され、BFS は当然、O(N) によって境界が定められた連続セグメントにわたる単方向のトラバースになります。
