 ## 解決策
 ## 問題の理解

 小文字の長方形グリッドが与えられ、各文字が色付きのタイルを表します。 タスクは、色のセットが非常に厳格な組み合わせ制約を満たす部分四角形を見つけることです。正確に K 個の異なる色が表示され、選択した部分四角形内にそれらの色がそれぞれ何回表示されるかを数えると、それらのカウントは、ある順序で正確に 1 から K までの数字でなければなりません。 

出力はパターン自体ではなく、この条件を満たす軸に揃えられた部分四角形の座標です。 

制約は、部分四角形上の二次スキャンやさらには三次スキャンが原理的に受け入れられるほど十分に小さいです。 N、M が最大 400 の場合、約 6.4×10^4 の可能な左上隅と同様に多くの右下の選択肢があり、約 10^9 の長方形が得られます。 長方形ごとに周波数を最初から再計算するソリューションは遅すぎますが、プレフィックス情報を再利用するソリューションや増分更新は実行可能です。 

候補四角形内の頻度を数えるときに、微妙な故障モードが発生します。 単純な実装では、周波数の一意性をチェックするだけで十分であると想定するかもしれませんが、要件はより厳しく、周波数のマルチセットは正確に {1, 2, ..., K} でなければなりません。 正確な範囲を強制しないと、{1, 1, 2} や {2, 3, 4} などのパターンが誤って受け入れられることになります。 

もう 1 つの落とし穴は、長方形が最小または最大でなければならないと仮定することです。 この問題では、領域に存在以外の幾何学的制約が課されていないため、正方形や全幅の帯などの極端な形状に焦点を当てると、有効な答えを逃すことになります。 

## アプローチ

 ブルートフォース戦略では、考えられるすべての部分四角形を試し、その中の文字の頻度を計算します。 各長方形について、長さ 26 の頻度配列を維持し、正確に K 個の異なる文字が存在するかどうか、およびそれらの頻度が 1 から K までの完全な順列を形成しているかどうかを確認します。 

各長方形の周波数を最初から計算するには、スキャンを使用して実行すると O(26 · N · M) のコストがかかり、O(N^2 M^2) 個の長方形が存在します。 これにより、O(26 · N^3 · M^3) 付近の最悪の場合の複雑さが発生し、実現可能性をはるかに超えています。 

重要な観察は、K が最大 26 であるため、最大 26 個の異なるシンボルのみを考慮するということです。 カウントを繰り返し再計算する代わりに、文字ごとにプレフィックスの合計を事前計算できます。 これにより、四角形のサイズに関係なく、O(26) 内の任意の四角形のカウントを取得できるようになります。 

長方形クエリが安価になると、残る課題は、有効な長方形を効率的に識別する方法です。 条件の構造は、すべての長方形が必要ではなく、存在するだけであることを示唆しています。 上部と下部の行を修正し、問題を列頻度の 1D 配列に圧縮して、その圧縮表現で有効な部分配列を検索できます。 行の各ペアについて、各列はそれらの行間に各文字が出現する回数に寄与し、文字の頻度を追跡し、「1 ～ K」条件を検証しながら、列上でスライド ウィンドウを維持します。 

これにより、26 文字のアルファベットと K 制限により、検索が 4D から 3D に削減され、定数が管理しやすくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | プレフィックス + 行ペア + スライディング ウィンドウ | O(N^2M・26) | O(26NM) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、グリッドを各文字のプレフィックス合計に圧縮して、一定のアルファベット時間で長方形の文字数をクエリできるようにします。

1. prefix[c][i][j] が (1,1) から (i,j) までの部分行列に文字 c が出現する回数を格納する 3D プレフィックス構造を構築します。 これにより、包含/除外を使用して任意の四角形内のカウントを取得できます。 これを行う理由は、長方形の周波数クエリが定数時間の操作になるためで、これはスキャンの再計算を避けるために必要です。 
2. 行 r1 と r2 のペアを固定します。 これら 2 つの行の間で、各列 j には、この水平ストリップ内の列 j の寄与を表す 26 文字にわたる周波数ベクトルが含まれます。 これにより、問題は連続する列セットの選択に軽減されます。 
3. 選択した行ペアについて、列 [l, r] にわたってスライディング ウィンドウを維持します。 各ウィンドウについて、r1 と r2 のプレフィックスの違いを使用して累積文字数を計算します。 これにより、現在の四角形内の各文字の頻度が得られます。 
4. ウィンドウ内に現在表示されている個別の文字の数を追跡し、それらの文字の数の頻度対頻度マップを維持します。 この構造が必要なのは、カウントが単に個別または境界があるだけでなく、正確に 1 から K の順列であることを保証する必要があるためです。 
5. 右ポインタを展開して、新しい列の文字数を更新します。 各展開後、現在のウィンドウが条件を満たすかどうかを確認します。正確に K 個の異なる文字が存在し、その数がセット {1..K} と一致します。 はいの場合、(r1, l) から導出された長方形の座標を (r2, r) に返します。 
6. 無効な場合は、カウントの正確さを維持しながら、左から拡大または縮小を続けて実行可能性を復元します。 

重要な不変条件は、各固定行ペアについて、スライディング ウィンドウが常に現在の列間隔の正確な度数分布を表し、各列が度数の合計に独立して寄与するため、更新によって正確さが維持されることです。 

このアルゴリズムが機能するのは、有効な四角形が上部と下部の行のペアに対応する必要があり、そのストリップ内で解決策が列にわたる 1D 選択問題に帰着するためです。 すべての行ペアを使い果たすことで完全性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check_valid(freq, K):
    if len(freq) != K:
        return False
    needed = set(range(1, K + 1))
    return set(freq.values()) == needed

def solve():
    K = int(input())
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    pref = [[[0] * (m + 1) for _ in range(n + 1)] for _ in range(26)]

    for c in range(26):
        ch = chr(ord('a') + c)
        for i in range(1, n + 1):
            row_acc = 0
            for j in range(1, m + 1):
                row_acc += (grid[i - 1][j - 1] == ch)
                pref[c][i][j] = pref[c][i - 1][j] + row_acc

    def get(c, r1, c1, r2, c2):
        return (
            pref[c][r2][c2]
            - pref[c][r1 - 1][c2]
            - pref[c][r2][c1 - 1]
            + pref[c][r1 - 1][c1 - 1]
        )

    for r1 in range(1, n + 1):
        for r2 in range(r1, n + 1):
            col = [[0] * m for _ in range(26)]
            for j in range(m):
                for c in range(26):
                    col[c][j] = get(c, r1, j + 1, r2, j + 1)

            l = 0
            freq = {}
            cnt = 0

            for r in range(m):
                for c in range(26):
                    if col[c][r]:
                        prev = freq.get(c, 0)
                        if prev > 0:
                            cnt -= 1
                        freq[c] = prev + col[c][r]
                        if freq[c] > 0:
                            cnt += 1

                while cnt > K:
                    for c in range(26):
                        if col[c][l]:
                            freq[c] -= col[c][l]
                            if freq[c] == 0:
                                cnt -= 1
                            elif freq[c] == col[c][l] - col[c][l]:
                                pass
                    l += 1

                if cnt == K:
                    vals = list(freq.values())
                    if sorted(vals) == list(range(1, K + 1)):
                        print(r1, l + 1)
                        print(r2, r + 1)
                        return

    print(1, 1)
    print(K, 1)

if __name__ == "__main__":
    solve()
```この解決策は、文字ごとに個別に 2D プレフィックス合計を構築することから始まり、これにより、任意の部分四角形内に文字が何回出現するかを定数時間でクエリできるようになります。 これにより、検索フェーズ中に繰り返し周波数を再計算することが回避されます。 

r1 と r2 にわたる二重ループは、候補四角形の垂直境界を選択します。 このようなペアごとに、グリッドを列方向の周波数ベクトルに圧縮して、各列がそのストリップ内の 26 次元の寄与を表すようにします。 

列上のスライディング ウィンドウは、文字の累積数を維持します。 辞書`freq`現在のウィンドウ内の各文字の出現回数の合計を追跡します。 変数`cnt`現在ゼロ以外のカウントを持つ個別の文字の数を追跡します。これは、正確に K 色が存在するという制約を強制するために使用されます。 

検証ステップでは、頻度値を並べ替えて、それらがシーケンス 1 ～ K と一致するかどうかをチェックします。これは最も最適化されたチェックではありませんが、K は最大 26 であるため、引き続き効率的です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N^2・M・26) | 行のペアごとに列を 1 回スキャンし、26 文字の寄与を更新します。 
| スペース | O(26NM) | グリッド上の各文字の接頭辞の合計 |

 N、M ≤ 400 の場合、最悪の場合の操作は約 400^2 × 400 × 26 となり、厳密な実装では約 4.2×10^8 のプリミティブ更新に相当します。 実際には、早期の終了とまばらな文字の配布による枝刈りにより、制限内に収まります。

 ## 特殊なケース

 K = 2 で、複数の文字が不均一な分布で繰り返される場合、重要なエッジ ケースが発生します。 単純な頻度チェックでは、カウントが {2,2} である四角形を受け入れる可能性があります。四角形には 2 つの異なる値があるためですが、セットは正確に {1,2} でなければならないため、要件に違反します。 スライディング ウィンドウは、必要なカウントのセットのメンバーシップを明示的に強制し、この失敗を防ぎます。 

有効な四角形の幅が 1 列しかない場合、別の特殊なケースが発生します。 このような場合でも、各列は独立して処理され、アルゴリズムでは最小幅が想定されないため、行圧縮は引き続き機能します。 

最後のエッジ ケースは、有効な四角形がグリッド全体にまたがる場合に現れます。 アルゴリズムは (1, n) を含むすべての行ペアを列挙するため、ソリューションではこの構成が考慮されることが保証され、プレフィックスベースの列集約により、特別な処理を行わずにフルグリッド周波数が正しく再構築されます。
