 ## 解決策
 ## 問題の理解

 地下鉄システムを記述する無向グラフが与えられましたが、それが非常に厳密な幾何学的構造によって生成できるかどうかを判断する必要があります。 

この建設には際立った中央駅があります。 このステーションからは、少なくとも 3 つの独立した「光線」が出現し、各光線は単純なステーションのチェーンです。 光線に沿って中心から遠ざかるにつれて、距離が離れたステーションに遭遇し、各光線は独自の有限の長さを持ちます。 中心から一定の距離ごとに、レイごとに 1 つのステーションが存在する可能性があり、同じ距離にあるすべてのそのようなステーションは、概念的には、システムの周りをサイクルで接続する「リング」にグループ化されます。 

したがって、構造的には、意図したオブジェクトは、共通のルートから始まるいくつかのパスに加え、異なるパスにわたって対応する深さレベルを接続してサイクルを形成する追加のエッジのように見えるグラフです。 

入力は、最大 100,000 のノードと 200,000 のエッジを持つ単なる無向グラフです。 どのノードが中心であるかは知らされず、グラフをこの構造に適合させる中心の選択肢が存在するかどうかを判断する必要があります。 

この制約は、線形または線形に近い処理が必要であることを強く示唆しています。 すべてのノードをルートとして試して完全なチェックを再計算するようなことは、最悪の場合、10^10 の演算が発生する可能性があるため、非常に遅くなります。 

いくつかの失敗例は、単純に読んだだけでは明らかではありません。 

実際には有効なグラフ内で間違ったルートを選択すると、BFS の階層化が矛盾しているように見える可能性があります。 たとえば、真の構造が有効であるにもかかわらず、中心ではなく光線上のノードから BFS を開始した場合、位置合わせされるはずのない同じ深さにノードが表示され、リング条件が崩れる可能性があります。 

もう 1 つの微妙なケースは、余分なエッジを持つ「局所的に妥当な」ツリーであるものの、レベルごとに一貫したサイクルを形成していないグラフです。 たとえば、レベルにノードが含まれているが、それらのノードによって誘導されたエッジが単一のサイクルを形成していない場合、次数を検証するだけの貪欲チェックでは依然として間違った構造が受け入れられる可能性があります。 

最後に、グラフが接続されており、中心候補のように見える高次数のノードがある可能性がありますが、一部のノードに 2 つの独立した「下向き」分岐がある場合、次数が妥当であるように見えても、構造を光線に分解することはできません。 

## アプローチ

 ブルートフォースアプローチでは、すべてのノードを潜在的なセンターとして試行します。 候補ルートごとに BFS を実行して距離を計算し、グラフがレイおよびリング構造の制約を満たしているかどうかを検証します。 各検証は O(n + m) であるため、合計コストは O(n(n + m)) になります。これは 2 · 10^5 エッジには大きすぎます。 

重要な観察は、中心が非常に強い構造特徴を持っているということです。 意図した構造では、少なくとも 3 つの光線に対応する、少なくとも 3 つの独立した単純なパスが直ちに開始される唯一のノードです。 これにより、候補はすでに十分に大きな次数のノードに制限されます。 

候補中心が選択されると、BFS 階層化が意味を持つようになります。各レイは単純なパスであるため、各ノードは前の層に 1 つの親を持つ必要があります。 BFS 用語で 2 つの親を持つノードやレイヤーをスキップするエッジなど、これから逸脱すると、構造は即座に壊れます。 

各層内では、「リング」条件により、同じ距離にあるノード上に誘導されたサブグラフが単一サイクルを形成するように強制されます。 つまり、レイヤー内のすべてのノードには、同じレイヤー内にちょうど 2 つの隣接ノードが必要であり、エッジの数はそのレイヤー内のノードの数と等しくなければなりません。 

これにより、問題は、高次のノードのみをルートとして試行し、BFS の一貫性とレイヤーごとのサイクル構造を検証することに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのルートを試す) | O(n(n + m)) | O(n + m) | 遅すぎる |
 | ルート候補 + BFS 検証 | O(n + m) | O(n + m) | 承認済み |

## アルゴリズムのチュートリアル

 それぞれの考えられる中心をテストし、有効な光線とリングの分解を生成できるかどうかを検証します。 

1. 次数が少なくとも 3 であるすべてのノードを収集し、それらを潜在的な中心として扱います。 その理由は、中心は少なくとも 3 つの光線を開始する必要があるため、少なくとも 3 つの直接の隣接光線が必要であるということです。 
2. 候補中心ごとに BFS を実行して、そこからの距離を計算します。 グラフがこのノードから接続されていない場合、グラフはすぐに失敗します。 
3. BFS 中に、すべてのエッジが同じレベルのノードまたは隣接するレベルのノードを接続するように強制します。 距離が 1 より大きく異なるノードをエッジが接続する場合、階層化はレイとリングに対応できません。 
4. ルートを除くすべてのノードについて、その隣接ノードの中で 1 つだけが前の BFS 層に存在することを確認します。 これにより、各ノードが 1 つのレイ パスに属することが強制され、複数の親方向への分岐が防止されます。 
5. BFS 距離に基づいてノードをグループ化します。 深さレベルごとに、端点が両方ともそのレベル内にあるエッジによって形成される誘導サブグラフを検査します。 レベル内の各ノードには、そのような隣接ノードが 2 つだけ存在する必要があり、これにより構造が単一サイクルであることが保証されます。 
6. また、最大深度まですべてのレベルが空ではないこと、およびルートに BFS ツリー内に少なくとも 3 つの子があり、これは少なくとも 3 つのレイに対応することを確認します。 

いずれかの候補ルートについてすべてのチェックに合格した場合、グラフは有効です。 

### なぜ効果があるのか

 有効な中心をルートとする BFS ツリーは、レイが一意の親チェーンに対応するため、レイの構造を正確に再構築します。 親数の制約により分岐が排除され、各ノードが中心からの 1 つの単純なパスに属することが保証されます。 

レベル内サイクル条件はリング構造を強制します。つまり、各距離レイヤーは、複数の切断されたコンポーネントやパスではなく、単一のサイクルに近づく必要があります。 いずれかのレベルがこれを満たさない場合、等距離にあるすべてのステーションが周期的に接続されるという要件に矛盾します。 

垂直 (レイ) 制約と水平 (リング) 制約の両方が強制されるため、チェックに合格したグラフは構造と正確に一致する必要があります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def check(root, n, g):
    dist = [-1] * (n + 1)
    parent_count = [0] * (n + 1)
    level_nodes = {}

    q = deque([root])
    dist[root] = 0

    while q:
        u = q.popleft()
        for v in g[u]:
            if dist[v] == -1:
                dist[v] = dist[u] + 1
                q.append(v)

    for u in range(1, n + 1):
        if dist[u] == -1:
            return False
        level_nodes.setdefault(dist[u], []).append(u)

    if len(level_nodes[0]) != 1:
        return False

    for u in range(1, n + 1):
        for v in g[u]:
            if dist[v] == dist[u] + 1:
                parent_count[v] += 1
            elif dist[v] == dist[u] - 1:
                pass
            elif dist[v] == dist[u]:
                pass
            else:
                return False

    if parent_count[root] != 0:
        return False

    for u in range(1, n + 1):
        if u != root and parent_count[u] != 1:
            return False

    for d, nodes in level_nodes.items():
        if d == 0:
            if len(nodes) != 1:
                return False
            continue
        if len(nodes) < 3:
            return False
        for u in nodes:
            cnt = 0
            for v in g[u]:
                if dist[v] == d:
                    cnt += 1
            if cnt != 2:
                return False

    if len(g[root]) < 3:
        return False

    return True

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    candidates = [i for i in range(1, n + 1) if len(g[i]) >= 3]

    for c in candidates:
        if check(c, n, g):
            print("Yes")
            return

    print("No")

if __name__ == "__main__":
    solve()
```BFS 検証には高速な近隣反復が必要なため、実装は隣接リストを構築することから始まります。 

の`check`関数は、固定ルートのすべての構造検証を実行します。 最初に BFS を実行して距離を計算します。 これらの距離により、候補となる「光線」が定義されます。 

次に、接続性を検証し、レベルごとにノードを整理します。 の`parent_count`配列は、ルート以外の各ノードが前の層からつながるエッジを 1 つだけ持つことを強制します。これは必須の光線プロパティです。 

次に、各レベルの内部構造を検証します。 同じレベルの近傍をカウントすることで、各層が 2 つの通常のグラフを形成することが保証されます。これは、接続され有効な場合にはサイクルである必要があります。 各レベルに少なくとも 3 つのノードがあるという制約により、意味のあるリングが存在することが保証されます。 

最後に、ルートに少なくとも 3 つの隣接光線があることを確認し、少なくとも 3 つの光線の要件に一致します。 

外側のループは、次数が 3 以上のノードのみを試行します。これにより、不可能な候補に時間を浪費することなく、考えられるすべての中心が捕捉されます。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    input = sys.stdin.readline

    def check(root, n, g):
        dist = [-1] * (n + 1)
        parent_count = [0] * (n + 1)
        level_nodes = {}

        q = deque([root])
        dist[root] = 0

        while q:
            u = q.popleft()
            for v in g[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    q.append(v)

        for u in range(1, n + 1):
            if dist[u] == -1:
                return False
            level_nodes.setdefault(dist[u], []).append(u)

        if len(level_nodes[0]) != 1:
            return False

        for u in range(1, n + 1):
            for v in g[u]:
                if dist[v] == dist[u] + 1:
                    parent_count[v] += 1
                elif dist[v] == dist[u] - 1:
                    pass
                elif dist[v] == dist[u]:
                    pass
                else:
                    return False

        for u in range(1, n + 1):
            if u != root and parent_count[u] != 1:
                return False

        for d, nodes in level_nodes.items():
            if d == 0:
                continue
            if len(nodes) < 3:
                return False
            for u in nodes:
                cnt = sum(1 for v in g[u] if dist[v] == d)
                if cnt != 2:
                    return False

        if len(g[root]) < 3:
            return False

        return True

    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]
    for _ in range(m):
        a, b = map(int, input().split())
        g[a].append(b)
        g[b].append(a)

    candidates = [i for i in range(1, n + 1) if len(g[i]) >= 3]
    for c in candidates:
        if check(c, n, g):
            return "Yes"
    return "No"

 ## 特殊なケース

 分岐のない単一ノードまたは単一コンポーネントのグラフは、少なくとも 3 つの光線を持つ有効な中心として機能するノードがないため、すぐに失敗します。 BFS チェックは、ルート次数の条件でこれを検出します。 

すべてのノードがクリーンな BFS 構造を持っているため、単純なパス グラフは欺瞞的ですが、次数が 3 以上のノードがないため、ルート候補も考慮されません。 

純粋なスター グラフはレイ要件を満たしますが、すべてのノードが同じレベルの隣接ノードを 2 つ正確に持つサイクルを最初のレベルで形成できないため、リング条件を満たしません。 

複数のサイクルが一貫性のない方法で接続されているグラフは失敗します。これは、一部の BFS レベルに、同じレベルのエッジが単一の 2 規則構造を形成していないノードが含まれているためです。これは、ローカル次数が許容できるように見えても、リング要件に違反します。
