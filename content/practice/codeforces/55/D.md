 ## 解決策
 ## 問題の理解

 私たちは、ヴォロディアが美しいと呼ぶ所定の範囲内の数字を数えるように求められます。 ゼロ以外の各桁で割り切れる数値は美しいです。 たとえば、128 は 1、2、8 で割り切れるため、美しい値になります。単一のテスト ケースで下限が決まります。$l$そして上限$r$、そしてそれらの間の美しい数値のカウントを出力する必要があります。 

入力では最大 10 個のクエリが可能で、各数値は次のように大きくできます。$9 \cdot 10^{18}$。 これにより、範囲内のすべての数値を反復する解決策は実行不可能であることがすぐにわかります。単一の範囲にさえ次の値が含まれる可能性があるためです。$10^{18}$数字。 各数値を個別にチェックする単純なソリューションでは、4 秒で実行できるよりもはるかに多くの操作が必要になります。 

明らかでないエッジ ケースには、105 や 120 など、桁が 0 の数値が含まれます。ルールではゼロ以外の桁のみが考慮されるため、桁が 0 であってもその数値は失格になりません。 もう 1 つの特殊なケースは、1 桁の数字です。 定義上、すべての 1 桁の数字は美しいです。なぜなら、各数字はそれ自体を分割するからです。 たとえば、1 ～ 9 の範囲では 9 が返されます。 

## アプローチ

 ブルート フォースのアプローチは簡単です。指定された範囲内のすべての数値を反復処理し、その桁を抽出し、ゼロ以外の各桁の割り算をテストします。 これは論理的には正しいですが、操作の数は容易に達成できます。$10^{18}$クエリごとに。これは受け入れられません。 

最適化するには、数値の桁による割り算が桁自体にのみ依存することを観察します。 任意の数値の桁数は、次の数値までは最大 19 です。$10^{18}$。 これは、数値を桁ごとに構築し、割り算に影響を与える状態を追跡する、digit-DP と呼ばれる動的プログラミングの形式を使用できることを示唆しています。 

重要な洞察は、数字を直接反復する代わりに、考えられる数字の組み合わせを列挙し、これまでに使用されたすべての非ゼロ数字の最小公倍数 (LCM) を維持できることです。 完全に構築された数値がこの最小公倍数で割り切れる場合、その数値は有効です。 LCM は、1 から 9 までの数字の LCM である 2520 を決して超えることがないため、効率的に表すことができます。また、選択した数字が上限の接頭語に従っているかどうかを示す「タイト」フラグを維持することで、上限の制約を処理することもできます。 

これにより、問題の反復が軽減されます。$10^{18}$最大 19 のポジション、2520 の LCM ステート、および 2 つのタイトなステートを列挙するまでの数ですが、これは管理可能です。

 ## アルゴリズムのチュートリアル

 1. ターゲット数値を数字列に変換します。 これにより、最上位桁から 1 桁ずつ数値を構築することができます。 
2. 再帰関数を定義する`dfs(pos, lcm, tight)`どこ`pos`は現在の桁位置、`lcm`これまでに選択されたすべての非ゼロ数字の最小公倍数であり、`tight`プレフィックスが依然として上限と一致するかどうかを示します。 
3. もし`pos`最後の桁を超えている場合、形成された数値が次の数で割り切れる場合は 1 を返します。`lcm`、それ以外の場合は 0。 
4. この位置で試行する最大桁を決定します。 もし`tight`true の場合、最大値はこの位置のターゲット番号の桁です。 それ以外の場合は 9 です。 
5. 0 から許可される最大値までのすべての可能な数字を反復処理します。 につながる数字をスキップします。`lcm`間違ってゼロになっている（これは、選択されたすべての数字がゼロの場合にのみ発生しますが、そうではありません）。 
6. 数字がゼロ以外の場合は、新しい LCM を計算します。 新しいタイト フラグは、数字が上限の数字と一致する場合にのみ true になります。 
7. 再帰呼び出し`dfs`更新されたものを使用して次の位置を取得します`lcm`そして`tight`。 
8. 結果に基づいて結果をメモ化する`(pos, lcm, tight)`to avoid redundant calculations.
 9. 範囲内の美しい数値の最終的な数`[l, r]`は`count(r) - count(l-1)`、 どこ`count(x)`デジットDP関数を使用します。 

なぜ機能するのか: 不変条件は次のとおりです。`dfs(pos, lcm, tight)`常に、これまでに構築されたプレフィックスを使用して数値をカウントし、ゼロ以外の桁の正確な最小公倍数を維持し、上限を尊重します。 メモ化により、各状態が正確に 1 回計算されることが保証されます。 LCM 表現は数字が 1 ～ 9 であるため制限されており、大きくなりすぎることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import gcd
from functools import lru_cache

def lcm(a, b):
    if a == 0 or b == 0:
        return max(a, b)
    return a * b // gcd(a, b)

def count_beautiful(n):
    s = str(n)
    length = len(s)

    @lru_cache(None)
    def dfs(pos, cur_lcm, tight):
        if pos == length:
            return 1 if cur_lcm != 0 and n % cur_lcm == 0 else 0
        limit = int(s[pos]) if tight else 9
        total = 0
        for d in range(0, limit+1):
            if d == 0:
                new_lcm = cur_lcm
            else:
                new_lcm = lcm(cur_lcm, d)
            new_tight = tight and (d == limit)
            total += dfs(pos+1, new_lcm, new_tight)
        return total

    return dfs(0, 0, True)

t = int(input())
for _ in range(t):
    l, r = map(int, input().split())
    print(count_beautiful(r) - count_beautiful(l-1))
```このコードでは、まず、ゼロ以外の数字を処理するための LCM ヘルパーを定義します。`count_beautiful`数値を digit-DP の文字列に変換します。 の`dfs`機能は現在の LCM と気密性を追跡します。 の`lru_cache`状態をメモ化します。 各クエリについて、カウントを減算して範囲カウントを取得します。 LCM 更新でゼロ桁をスキップすることは、ゼロによる除算を避けるために不可欠です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(19 * 2520 * 2 * 10) | 19 ポジション、2520 の可能な LCM、タイト フラグ 2 状態、コールごとに最大 10 桁 |

 DP は数値のサイズではなく、位置、最小公倍数、タイトネスに応じてスケールするため、最大の数値を簡単に処理できます。$10^{18}$4秒以内に。
