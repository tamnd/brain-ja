 ## 解決策
 ## 問題の理解

 We have`n`円状に配置された位置。 ノミは 1 つの位置から始まります。 最初の 1 分後は 1 ステップ、2 分後は 2 ステップ、3 分後は 3 ステップというように進みます。 

問題は、この移動パターンが最終的に円上のすべての位置を訪れるかどうかです。 

ノミが現在その位置にいる場合`p`、その後数分後に`k`それは次の場所に移動します:$p+k \pmod n$入力には単一の整数が含まれています`n`、円内の位置の数。 出力は次のようになります。`"YES"`すべてのポジションが少なくとも 1 回訪問された場合、それ以外の場合`"NO"`。 

制約は非常に小さく、最大 1000 ポジションのみです。 多くのステップを含む直接シミュレーションでも十分に高速です。 高度な最適化や複雑な数学は必要ありません。 それでも、この問題の興味深い部分は、なぜ答えが次の条件にのみ依存するのかを理解することです。`n`素数または複合値です。 

簡単な間違いの 1 つは、ジャンプの長さが変化し続けるため、ノミが常にあらゆるものにアクセスすると仮定することです。 その直感は、次の複合値については当てはまりません。`n`。 

例えば：```
n = 4
```訪問したポジションは次のとおりです。```
0 -> 1 -> 3 -> 2 -> 2 -> ...
```位置`0`開始後に再び訪れることはなく、動きはより小さなサイクルに閉じ込められます。 正しい出力は次のとおりです`"NO"`。 

もう一つの微妙なケースは、`n = 1`。```
1
```位置は 1 つだけなので、ノミはすぐにすべての位置を訪問してしまいます。 正しい答えは、`"YES"`。 

不注意な実装では、繰り返し位置を確認した後で停止するのが早すぎる可能性もあります。 いくつかの位置が一度も訪問されなかったことがすでにわかっている場合を除き、繰り返しだけでは失敗と結論付けるのに十分ではありません。 例えば：```
n = 2
```ノミは両方の位置を永久に交互に繰り返しますが、これは実際には円全体を覆うのに十分です。 正しい出力は次のとおりです`"YES"`。 

## アプローチ

 最も直接的なアプローチはシミュレーションです。 現在位置を追跡し、長さのジャンプを繰り返し適用します`1, 2, 3, ...`。 ある位置に到達するたびに、その位置を訪問済みとしてマークします。 

状態空間が小さいため、ブルートフォースが機能します。 あるのは`n`したがって、最終的には動きを繰り返す必要があります。 十分なジャンプの後、すべてのポジションがマークされていれば、私たちは答えます`"YES"`、 さもないと`"NO"`。 

この問題のサイズでは、数千の手をシミュレートすることさえ完全に許容されます。 と`n ≤ 1000`、`O(n^2)`プロセスは依然として最大で約 100 万の操作を実行します。 

さらに興味深い観察は数論から得られます。 

後`k`移動した場合の総移動距離は次のようになります。$1+2+3+\cdots+k = \frac{k(k+1)}{2}$実際の位置は、この値を法としてのみ依存します。`n`。 

ノミは、次の場合に限り、あらゆる場所を訪れます。`n`プライムです。 

なぜ？ 複合用`n`、何らかの約数が存在します`d < n`。 十分なジャンプの後、蓄積された動きがモジュロの繰り返しを開始します`d`、すべてのポジションへのアクセスを禁止します。 プライム用`n`、モジュラー動作はすべての残基を循環します。 

公式観察を別の表現で表現すると、ノミはジャンプ構造の最大公約数が正確に一致するときにすべての位置を訪問し、`n`プライムでのみ発生する有利な状態が続く`n`そしてのために`n = 1`。 

以来`n`小さい場合は、単純に次のことを確認できます。`n`プライムです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 承認済み |
 | 最適 | O(√n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る`n`。 
2. 特殊なケースに対処する`n = 1`。 

ノミはそこから始まるため、単一の位置を完全に訪問することは自明です。 
3. かどうかを確認します。`n`プライムです。 

すべての約数を試します`2`まで`√n`。 約数が割り切れる場合`n`、 それから`n`複合です。 
4. もし`n`プライムです、印刷します`"YES"`。 

プライムサイズの円により、移動パターンが最終的にすべての剰余モジュロをカバーできるようになります`n`。 
5. それ以外の場合は印刷します`"NO"`。 

複合サイズの円は、すべての位置を訪問する前に、ノミをより小さな繰り返し構造に強制します。 

### なぜ効果があるのか

 数回ジャンプした後のノミの位置は累積和の剰余に依存します`n`。 プライム用`n`、円上のモジュラー演算は小さな繰り返しサブセットに分割されないため、すべての位置に到達可能になります。 複合用`n`、動きは約数によって決定されるポジションのサブセットに限定されます。`n`。 

素数性は動きが円全体をカバーするかどうかを正確に特徴付けるため、アルゴリズムは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(x):
    if x < 2:
        return False

    d = 2
    while d * d <= x:
        if x % d == 0:
            return False
        d += 1

    return True

def solve():
    n = int(input())

    if n == 1 or is_prime(n):
        print("YES")
    else:
        print("NO")

solve()
```この解決策は、標準的な素数性テストから始まります。 2 より小さい数は素数ではありません。 次に、すべての約数を試します`d`その間`d * d <= x`。 

約数は常にペアで表示されるため、平方根までをチェックするだけで十分です。 もし`x`より大きい約数がありました`√x`の場合、ペアになった約数はすでに よりも小さくなります。`√x`。 

特別な取り扱いは、`n = 1`1 は数学的に素数ではないので重要ですが、この問題の答えはまだありません`"YES"`ノミがすでに唯一の位置を占めているからです。 

この実装は一定の追加メモリを使用し、指定された制約に対してほぼ瞬時に終了します。
