 ## 解決策
 ## 問題の理解

 私たちは、$n \times m$グリッド。 一部のセルにはパイが含まれており、複数のパイが同じセルを共有する場合があります。 

各ターンには 2 つのフェーズがあります。 まず、Volodya は 1 つのパイを選択し、それを 4 つの方向のいずれかに 1 セルずつ移動します。 パイがすでに境界上にある場合は、境界の 1 つの端を通ってボードの外にパイを移動し、即座にゲーム全体に勝つことができます。 その後、ゲームがまだ終了していない場合、ヴラドはボードのちょうど 1 つのユニット境界端をブロックします。 一度ブロックされると、そのエッジを使用してパイを外側に移動することはできなくなります。 

この試合は、両プレイヤーが完璧なプレーをしたと仮定して、最終的にヴォロディアが勝利を収めることができるかどうかにかかっています。 

ボードの寸法は最大 100 で、パイの数は最大 100 です。 これらの制限はごくわずかであり、これは、本当の困難は実装の複雑さではなく、ゲーム理論上の正しい観察を見つけることであることを示しています。 ゲーム状態にはすべてのパイの位置と既にブロックされている境界エッジのセットが含まれるため、ゲーム状態に対する総当り検索は依然として不可能です。 たとえ$100 \times 100$ボードには 400 の境界エッジがあるため、ブロックされたエッジのサブセットの数だけでも天文学的になります。 

この問題の危険な部分は、経路探索のように見えますが、実際のゲームは国境へのアクセスのみに依存していることです。 「パイが境界線に到達できればヴォロディアが勝つ」といった素朴な考えは完全に間違っています。なぜなら、すべての国境の出口は最終的には封鎖される可能性があるからです。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

パイのないボードを考えてみましょう。```
2 2 0
```正しい答えは、`NO`ヴォロディアには動くものが何もないからです。 ボードの寸法またはボーダーのサイズを処理せずにチェックするだけの実装$k=0$別々に失敗します。 

もう 1 つの微妙なケースは、パイがすでに境界線で始まっている場合です。```
2 2 1
1 2
```答えは`YES`。 Volodya は、Vlad が何かをブロックする前に、最初の動きですぐに勝ちます。 移動順序を忘れると、間違った結果が生じます。 

最も重要で注意が必要なケースは、多くのパイがあるが、すべてがボードの奥深くにある場合です。```
5 5 20
3 3
3 3
...
```パイがたくさんあったとしても、答えはまだあります`NO`。 ヴラドはターンごとに境界エッジを 1 つだけブロックしますが、ヴォロディアもパイを境界に持ってくるのに時間がかかります。 決定的な量はパイの数だけではなく、十分な量のパイがヴラドが封印するよりも早く出口を脅かすことができるかどうかです。 

最後の微妙な点は、境界セルが異なれば出口の数も異なるということです。 コーナー セルには外側につながる 2 つの境界エッジがあり、コーナー以外の境界セルには 1 つの境界エッジがあります。 すべての境界セルを均等に扱うと、重要な情報が失われます。 

## アプローチ

 ブルートフォースアプローチでは、ゲームの状態全体がモデル化されます。 すべての円の位置とすべてのブロックされた境界エッジを追跡し、ミニマックスまたは逆行解析を実行します。 ゲームは有限かつ決定論的であるため、これは理論的には正しいです。 

問題は、状態数がすぐに爆発的に増加することです。 ボードには、$2n + 2m$境界エッジ。 各エッジがブロックされているかどうかは、大まかに次のとおりです。$2^{2n+2m}$パイの位置を考慮する前でも可能性があります。 と$n=m=100$、これは完全に絶望的です。 

重要な観察は、ゲームが考慮しているのは 1 つのことだけであるということです。それは、ヴラドが盤面を完全に封じるのに何ターン必要かということです。 

Vlad のすべての動きは、ちょうど 1 つの境界エッジをブロックします。 境界エッジの総数は次のとおりです。$$2n + 2m$$これらすべての端が封鎖される前に、ヴォロディアがブロックされていない出口にパイを強制的に到達させることができれば、彼の勝ちです。 

ここで、単一のパイの観点から考えてみましょう。 境界セルまでの最小距離が次であると仮定します。$d$。 次に、Volodyaは正確に必要です$d$移動して境界上に配置し、もう 1 回移動してボードから離れます。 パイが後で逃げられるように$d+1$ヴォロディアが動く。 

一方、これらの各移動の後、ヴラドは一方のエッジをブロックします。 後$t$ターン、ヴラドが正確にブロックした$t$境界エッジ。 

重要な洞察は、パイが開いたままにするためにすべての出口が必要ではないということです。 境界に到達した時点で使用可能なエッジが 1 つだけ必要になります。 ボード全体には$2n+2m$合計で終了すると、Vlad は最終的にブロック容量を使い果たします。 

公式ソリューションはこれをさらに簡素化します。 最も近い境界までの距離が 4 以下のパイが少なくとも 1 つ存在する場合、Volodya が勝ちます。 そうでなければヴラドが勝ちます。 

なぜ 4 なのか? ローカル領域の周囲にある個別の出口の総数が多すぎて、ヴラドが十分に早く封印できないためです。 境界に十分近いパイは、Vlad がすべての可能性を閉じる前に、まだ開いているエッジへのアクセスを強制することができます。 すべてのパイが 4 よりも遠くにある場合、ヴラドには完全な防御を準備する十分な時間があります。 

したがって、ゲームは、境界線から距離 4 以内にパイがあるかどうかをチェックすることになります。

 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 指数 | 遅すぎる |
 | 最適 |$O(k)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 基板の寸法とパイの数を読み取ります。 
2. 位置の各パイについて$(x,y)$、ボード境界までの最小距離を計算します。 

4 つの距離は次のとおりです。$$x-1,\ n-x,\ y-1,\ m-y$$それらの最小値は、最初に境界セルに到達するまでに必要な移動回数を示します。 
3. どのパイでもこの最小距離が最大 4 の場合は、すぐに出力します。`YES`。 

境界線にこれほど近いパイは、ヴラドが関連するすべての境界線を封印する前に、常に脱出を強制することができます。 
4. すべてのパイの距離が 4 より大きい場合、次のように出力します。`NO`。 

ヴラドには、パイが危険になる前に完全な封鎖を組織するのに十分な時間があります。 

### なぜ効果があるのか

 ゲームは完全にタイミングによってコントロールされます。 

遠くにあるパイ$d$境界ニーズから$d+1$逃げるために動く。 ヴラドは各移動後にブロックされたエッジを 1 つだけ獲得します。 もし$d \le 4$、パイは境界領域に十分早く到達するため、利用可能な出口が避けられないままになります。 ヴラドは、これほど少ないターンですべての可能な逃走経路を同時に封鎖することはできません。 

すべてのパイの距離が少なくとも 5 である場合、Volodya はすぐに脱出を試みるまでに多くのターンを必要とします。 ヴラドはこの時間を利用して戦略的に出口を阻止し、最終的にはあらゆる逃亡を阻止することができます。 重要なのは境界エッジのみであるため、境界が制御されると内部の動きは役に立たなくなります。 

この二分法は、アルゴリズムによってチェックされた条件と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())

for _ in range(k):
    x, y = map(int, input().split())

    dist = min(x - 1, n - x, y - 1, m - y)

    if dist <= 4:
        print("YES")
        sys.exit()

print("NO")
```難しい部分はゲーム プロパティを検出することであるため、実装は意図的に小さくなっています。 

円ごとに、境界セルに到達するために必要な最小ステップ数を計算します。 座標は 1 から始まるため、上部の距離は次のようになります。`x - 1`、下の距離は`n - x`、左の距離は`y - 1`、適切な距離は`m - y`。 

距離が最大 4 のパイを見つけた瞬間に、すぐに停止して出力できます。`YES`。 Volodya が必要とするのは 1 回の脱出成功だけなので、それ以上のパイは問題ありません。 

初期の`sys.exit()`不要な処理を回避し、コードをシンプルに保ちます。 

よくあるオフバイワンの間違いは、「境界セルまでの距離」と「ボードから離れるまでの距離」を混同することです。 定理はすでにこれを正しく説明しています。 境界距離が最大 4 であるかどうかのみをチェックします。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, m, k = map(int, input().split())

    for _ in range(k):
        x, y = map(int, input().split())

        dist = min(x - 1, n - x, y - 1, m - y)

        if dist <= 4:
            print("YES")
            return

    print("NO")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run(
"""2 2 1
1 2
"""
) == "YES", "sample 1"

# no pies
assert run(
"""5 5 0
"""
) == "NO", "no pies"

# pie exactly distance 4
assert run(
"""10 10 1
5 5
"""
) == "YES", "distance exactly 4"

# pie too far
assert run(
"""20 20 1
10 10
"""
) == "NO", "deep interior"

# multiple pies, one winning
assert run(
"""30 30 3
15 15
20 20
5 10
"""
) == "YES", "one reachable pie"

# smallest board
assert run(
"""1 1 1
1 1
"""
) == "YES", "already on boundary"

 ## 特殊なケース

 空のボードの場合を考えてみましょう。```
2 2 0
```アルゴリズムはパイのループに入ることは決してないので、直接出力します。`NO`。 

Volodya には正当な動きがないため、これはゲームに一致します。 

ここで、すでに境界上にある円について考えてみましょう。```
3 3 1
1 2
```計算された距離は次のとおりです。$$0,\ 2,\ 1,\ 1$$最小値は 0、最大値は 4 であるため、アルゴリズムは次のように出力します。`YES`。 

Volodya は、Vlad が行動する前にパイを外に移動することで即座に勝ちます。 

次に、まさにクリティカルしきい値にあるパイを考えてみましょう。```
10 10 1
5 5
```距離は次のとおりです。$$4,\ 5,\ 4,\ 5$$最小距離は 4 なので、答えは次のようになります。`YES`。 

これにより、包含境界条件がチェックされます。 使用する`< 4`の代わりに`<= 4`ここで失敗するだろう。 

最後に、しきい値をわずかに超えた円を考えてみましょう。```
12 12 1
6 6
```距離は次のとおりです。$$5,\ 6,\ 5,\ 6$$最小距離は 5 なので、アルゴリズムは次のように出力します。`NO`。 

これは最小の損失内部構成であり、カットオフ付近のオフバイワンエラーをキャッチします。
