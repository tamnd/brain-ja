 ## 解決策
 ## 問題の理解

 ボード上の 4 つの整数から始めます。 また、適用する必要がある 3 つの演算の正確な順序もわかります。各演算は加算または乗算です。 各ステップで、現在利用可能な 2 つの数字を選択し、それらに必要な演算を適用し、結果をボードに戻します。 3 回の操作の後、数字は 1 つだけ残ります。 

タスクは、可能な最小の最終値を見つけることです。 

難しいのは、演算の順序は固定されていますが、各演算にどの 2 つの数値を参加させるかの選択は完全に柔軟であることです。 組み合わせが異なると、まったく異なる結果が生じる可能性があります。 

制約は非常に小さいです。 数値は 4 つだけで、演算はちょうど 3 つあります。 すべてのステップで可能なすべてのペアリングを試したとしても、状態の総数は小さいままです。 ブルートフォース検索は制限時間内であれば完全に実用的です。 

数値は最大 1000 であるため、中間積は 64 ビット整数内に快適に収まります。 すべての数値が 1000 で、すべての演算が乗算である場合、可能な最大値が表示されます。$1000^4 = 10^{12}$これは Python の整数の範囲内に十分収まります。 

不正な実装をサイレントに破壊する可能性のあるエッジケースがいくつかあります。 

複数の等しい値が存在する場合でも、それらを別の位置として扱う必要があります。 考慮する：```
1 1 2 2
+ * +
```最初のものを選択する`1`そして二番目`1`を選択するのとは異なります`1`そして`2`。 セットを使用して不注意に実装すると、有効な状態が失われます。 

操作の順序を入れ替えることはできません。 例えば：```
1 2 3 4
+ * *
```申請しなければなりません`+`初め。 たとえ、より小さな答えが得られるとしても、足す前に乗算することはできません。 

各ステップで、隣接する要素だけでなく、任意のペアを選択できます。 例えば：```
1 10 1 10
* + +
```最良の最初の動きは 2 つを乗算することです`1`結果を小さく保つため。 検索を隣接する要素に限定すると、最適な答えが得られなくなります。 

もう 1 つの微妙な点は、ゼロが存在する場合、加算と乗算は互換性がないことです。 考慮する：```
0 5 6 7
* + +
```最適な動きは増えていく`0`と`7`すぐに生産する`0`、これにより、後で合計が小さくなります。 現在の最小値のみに基づいた貪欲な戦略は失敗する可能性があります。 

## アプローチ

 最も直接的な解決策はブルートフォースです。 すべてのステップで、現在利用可能な番号の中で考えられるすべてのペアを試します。 各ペアに対して必要な操作を適用し、次の状態を構築し、再帰的に続行します。 

最初は 4 つの数値があるため、次のようになります。$\binom{4}{2}=6$考えられる選択肢。 

1 回の操作の後、3 つの数値が残り、次のようになります。$\binom{3}{2}=3$選択肢。 

最後に数字が 2 つ残ったので、選択肢は 1 つだけです。 

可能な実行パスの総数は次のとおりです。$6 \times 3 \times 1 = 18$それは小さいです。 あらゆる可能性を探る再帰的な深さ優先検索も即座に実行されます。 

単純な総当り実装では、考えられるすべての括弧と順列を個別に生成できますが、それはすぐに乱雑になり、状態が重複してしまいます。 もっと明確な観察は、ゲーム自体がすでに状態遷移を自然に定義しているということです。 各ステップで必要なのは、現在の数値のマルチセットと次の操作のインデックスだけです。 

これにより、コンパクトな再帰検索が実現します。 

1. 2 つのインデックスを選択します。 
2. 現在の操作を適用します。 
3. 小さいリストを再帰的に実行します。 
4. 最終的な最小値を追跡します。 

検索ツリーには葉が 18 個しかないため、枝刈りや動的プログラミングは必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 明示的な列挙によるブルート フォース | O(4! × 括弧) | お(1) | 承認済み |
 | 再帰的な状態検索 | お(18) | O(3) 再帰の深さ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 4 つの初期整数と 3 つの演算を読み取ります。 
2. 再帰関数を定義する`dfs(arr, step)`どこ`arr`は残りの番号の現在のリストであり、`step`次にどの操作を適用する必要があるかを示します。 
3. もし`arr`数値が 1 つだけ含まれている場合は、すべての操作が終了したため、数値を返します。 
4. それ以外の場合は、すべてのインデックスのペアを試します`(i, j)`と`i < j`。 
5. 操作を適用する`ops[step]`に`arr[i]`そして`arr[j]`。 

操作が`+`、それらの合計を計算します。 

操作が`*`、積を計算します。 
6. 選択したペアを削除し、新しい結果を挿入して、次の配列を構築します。 

残りの数値は値を変更しません。 順序は論理的には重要ではありませんが、一貫した構造を維持すると実装が簡素化されます。 
7. この次の状態から可能な最小の結果を再帰的に計算します。 
8. すべてのペアの選択肢の最小値を取得します。 
9. 再帰的検索によって返された最終的な答えを出力します。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは問題ステートメントで許可されているすべての合法的な措置を調査します。 有効な操作シーケンスはすべて、再帰ツリー内の 1 つのパスに正確に対応します。 再帰ではそのようなパスをすべてチェックし、その中で最小の最終値を返すため、最適な答えを見逃すことはありません。 

各レベルで 1 つの操作が消費されるため、再帰の深さはちょうど 3 です。 最終的には 1 つの数字だけが残り、それがその特定の一連の選択によって生成される最終結果になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

nums = list(map(int, input().split()))
ops = input().split()

def dfs(arr, step):
    if len(arr) == 1:
        return arr[0]

    best = float('inf')

    n = len(arr)

    for i in range(n):
        for j in range(i + 1, n):

            if ops[step] == '+':
                val = arr[i] + arr[j]
            else:
                val = arr[i] * arr[j]

            nxt = []

            for k in range(n):
                if k != i and k != j:
                    nxt.append(arr[k])

            nxt.append(val)

            best = min(best, dfs(nxt, step + 1))

    return best

print(dfs(nums, 0))
```再帰関数は問題のプロセスを直接反映します。 現在の配列はボードにまだ書き込まれている数値を表しますが、`step`次にどの操作を使用する必要があるかを示します。 

基本ケースは、数字が 1 つだけ残っている場合に表示されます。 この時点で、一連の操作全体がすでに適用されているため、残りの値がその分岐の結果になります。 

ネストされたループは、順序付けされていないすべてのペアを列挙します。 使用する`i < j`を選択することで重複作業を回避できます。`(a, b)`選択するのと同じです`(b, a)`加算と乗算の両方に。 

次の状態は慎重に構築されます。 選択した 2 つを除くすべての数値をコピーし、新しく計算した値を追加します。 これにより、重複した番号が正しく保存されます。 セットを使用したり、値による削除を行うと、同じ数値が複数回出現する可能性があるため危険です。 

Python の整数は大きな値を自動的に処理するため、ここではオーバーフローは問題になりません。 固定幅整数を使用する言語では、可能な最大値は次のとおりであるため、64 ビット型で十分です。$10^{12}$。

```最適なパスのトレース:

別のパス:

 | ステップ | 現在の数値 | 操作 | 選択されたペア | 結果 |

def solve():

    nums = list(map(int, input().split()))

    def dfs(arr, step):
        if len(arr) == 1:
            return arr[0]

        best = float('inf')
        n = len(arr)

        for i in range(n):
            for j in range(i + 1, n):

                if ops[step] == '+':
                    val = arr[i] + arr[j]
                else:
                    val = arr[i] * arr[j]

                    if k != i and k != j:
                        nxt.append(arr[k])

                nxt.append(val)

                best = min(best, dfs(nxt, step + 1))

        return best

    print(dfs(nums, 0))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    backup = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup
    return out.getvalue().strip()

## 特殊なケース

 値が重複する場合を考えてみましょう。```
1 1 2 2
+ * +
```このアルゴリズムは、値ではなくインデックスによって数値を処理します。 再帰中に 2 つを選択する場合があります`1`s、または`1`そして`2`、さまざまな将来の状態を生成します。 すべてのインデックス ペアは独立して探索されるため、有効な構成が失われることはありません。 

次に、固定順序制約を調べます。```
1 2 3 4
+ * *
```最初の再帰レベルが常に適用されます`+`なぜなら`step = 0`。 アルゴリズムは乗算を最初に考慮することはありません。 最適なパスの 1 つは次のとおりです。```
1 + 2 = 3
3 * 3 = 9
9 * 4 = 36
```ただし、最小パスは次のとおりです。```
1 + 4 = 5
2 * 3 = 6
5 * 6 = 30
```再帰により、必要な順序ですべての有効なペアがチェックされることが保証されます。 

最後に、ゼロの場合を考えてみましょう。```
0 5 6 7
* + +
```最初のレベルでは、アルゴリズムは 6 つの乗算の選択肢すべてを調査します。 1つの枝が増える`0 * 7`、すぐに生産`0`。 後の加算により合計が小さく保たれ、最適な答え 11 が得られます。考えられるすべてのペアがテストされるため、ゼロの有益な使用を見逃すことはできません。
