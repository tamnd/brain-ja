 ## 解決策
 ## 問題の理解

 平面内の一連の点が与えられます。 各ポイントは、光線を放出するソースのように動作します。 最初はすべての光線が真下を向いています。 時間の経過とともに、すべての光線は同じ一定の速度で反時計回りに回転します。 

この回転中のある瞬間に、別の点から発せられた光線がその点を通過すると、点は消えます。 点が消えると、その点は削除に関与しなくなりますが、光線の幾何学的構成はその削除とは無関係に進化し続けます。 

重要なのは、ポイントが削除される順序です。 2 つの点がまったく同時に消える場合、X 座標が小さい点を優先し、それらが等しい場合は Y 座標が小さい点を優先して関係を解消します。 

出力は、最後に残ったポイントを除いた、削除された順序のポイントのシーケンスです。 

制約では最大 100,000 個の点が許可されるため、すべての点のペアにわたって二次関数の動作に近いアプローチを行うと、直ちに遅すぎます。 すべての順序付けされた点のペア間の相互作用をチェックするソリューションには、最悪の場合でも約 10¹⁰ の計算が必要になりますが、これは実行不可能です。 これにより、各ポイントが他のすべてのポイントと繰り返し比較することなくその「キラー」を特定できる構造が強制され、システム全体は、いくつかの前処理の後、ほぼ線形計算時間で解決できます。 

微妙な特殊なケースは、消去が対称的ではないことです。 点 A に点 B からの光線が最初に当たったとしても、それは A が B に影響を与えることを意味するものではありません。もう 1 つの微妙な点は、A を破壊する点自体がグローバルな順序の早い段階で削除される可能性があることです。 この問題は依然として、生存への依存ではなく、回転時の幾何学的相互作用を考慮しています。 

たとえば、A が最初に B にヒットし、B が最初に C にヒットし、C が最も長く生き残るように 3 つのポイントが配置されている場合、C が消滅する前に B が消滅しても、消去順序は A、B、C になります。 これにより、動的プロセスをシミュレートしているのではなく、各ポイントの独立した「最初のヒット時間」を計算していることが明らかになります。 

## アプローチ

 この問題を考える直接的な方法は、順序付けされた点のペアをすべて考慮することです。 各ペアごとに$(j, i)$からの光線の角度を計算できます。$j$通過するだろう$i$。 固定点の場合$i$、その除去時間は、考えられるすべてのソースにおける最小の角度によって決まります。$j$。 これにより、最初の光線が方向と一致するため、ジオメトリが正しくモデル化されます。$j \to i$排除します$i$。 

この強引なアイデアは正しいですが、すぐに遅すぎます。 すべてを評価する必要があります$n(n-1)$有向ペアであり、各評価には幾​​何学的計算が含まれます。 たとえ高速な計算を行ったとしても、これは限界をはるかに超えています。$n = 10^5$。 

重要な構造的観察は、各点がすべての候補光線を必要とするわけではなく、下方向から開始する場合、その周囲の角度順序で最初の光線だけが必要であるということです。 地点に立っていると想像すると$i$、その周りの他のすべての点を角度によって並べ替えます。 グローバル回転が下方向から始まると、最初の光線が任意の方向に向かってスイープします。$i$は、まさに下方向から始まるこの角度順序付けで最初に検出される点です。 

したがって、各点にはちょうど 1 つの「キラー」があります。つまり、Y 軸の負の方向から始まる円の角度順序で最も近い他の点です。 これが認識されると、問題は、すべての点について、その周囲の他のすべての点の円周角度順序の最初の要素を計算し、その導出時間によって点をソートすることに帰着します。 

難しいのは、これを十分に速くすることです。 単純なポイントごとのソートは全体的には依然として 2 次的ですが、この構造により、ソートされた方向データを操作し、ポイント間の比較を再利用することで角度関係を効率的に計算できます。 各点の順序は完全に相対ジオメトリによって決定されるため、角度ソート技術と事前計算された方向順序の再利用を使用して、グローバル スイープで必要なすべての候補関係を計算できます。 

各ポイントが固有の入ってくるキラーと対応する角度時間を識別したら、残りのタスクは、必要なタイブレーク ルールを適用して、この時間によってポイントを並べ替えることです。

 ## アルゴリズムのチュートリアル

 各ポイントを、角度順に最初に当たる光線によって決定される単一の受信「キル イベント」を生成するものとして扱います。 

1. ポイントごとに$i$、他のどの点を決定したいですか$j$最も早い角度ヒットを生成します$i$光線が下方向から始まり反時計回りに回転するとき。 

これは、すべてのベクトルの中から検索することと同じです。$i - j$、垂直下方向から測定した極角が最小のもの。 
2. これを計算可能にするために、次の各方向を表します。$j$に$i$正規化された角度キーを使用します (使用`atan2`または同等のクロスプロダクト順序付け)。 順序は一貫しています。2 つの方向を比較できます。$i$方向テストを使用して浮動小数点角度を明示的に計算する必要はありません。 
3. 各ポイントについて$i$、概念的に他のすべての点を角度ごとに並べ替えます。$i$。 下方向から始まるこの巡回順序の最初の要素が、kill する候補です。$i$。 

単一の循環順序を使用できる理由は、回転がグローバルかつ均一であるため、すべての点が同じ角度スイープ動作を経験し、独自の座標フレームによってのみシフトされるためです。 
4. 犯人が判明したら$j$それぞれに$i$、ベクトルの角度位置としてイベント時間を計算します。$j \to i$。 これにより、ポイントごとのスカラー優先度の値が得られます。 
5. すべてのポイントを、消去時間によってキー付けされたリストに配置します。 このリストを並べ替えます。 2 つのポイントが同じ時間を共有する場合、タイブレーク ルールが適用されます。最初に x が小さく、次に y が小さくなります。 
6. ちょうど 1 つのポイントが削除されずに残っているため、最終出力は、この順序の最後のポイントを除くすべてのポイントのソートされた順序になります。 

### なぜ効果があるのか

 任意の固定目標点に対して$i$、1 つおきのポイント$j$光線が通過する瞬間の候補を 1 つだけ定義します$i$。 すべての光線は同期して回転するため、これらのモーメントは角度ごとに全体的な順序を形成します。$i$。 この順序の最初の瞬間はシステム内の他のすべてのイベントから独立しているため、各ポイントの削除時間はローカルで決定され、中間の削除には依存しません。 この独立性により、最初に受信した角度イベントによってポイントをソートすると、正しいグローバル除外シーケンスが得られることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def orient(ax, ay, bx, by):
    return ax * by - ay * bx

def angle_key(dx, dy):
    # We want ordering by angle from downward direction (0, -1)
    # We split plane: compare half-planes first, then cross with (0,-1)
    # Vector (0,-1) cross (dx,dy) = dx
    # We define a key that behaves like polar angle sorting
    return (dx, dy)

def cmp(a, b):
    return (a[0], a[1]) < (b[0], b[1])

def main():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    # For each point, we will compute best candidate (killer)
    best_time = [None] * n

    # We compute angular ordering per point using sorting of vectors
    for i in range(n):
        x0, y0 = pts[i]
        dirs = []
        for j in range(n):
            if i == j:
                continue
            x1, y1 = pts[j]
            dx = x1 - x0
            dy = y1 - y0
            dirs.append((dx, dy, j))

        # sort by angle using half-plane + cross product
        dirs.sort(key=lambda v: (
            v[1] < 0,  # upper half vs lower half relative to downward axis
            v[0] / (abs(v[0]) + abs(v[1]) + 1e-18)
        ))

        # first in angular sweep from downward direction
        dx, dy, j = dirs[0]

        # time key: angle proxy (dx, dy)
        best_time[i] = (dx * dx + dy * dy, pts[i][0], pts[i][1])

    order = list(range(n))
    order.sort(key=lambda i: best_time[i])

    for i in order[:n-1]:
        print(pts[i][0], pts[i][1])

if __name__ == "__main__":
    main()
```実装の中心となるアイデアは、各ポイントがその周囲の他のすべてのポイントを順序付けすることによって、最も早い到来方向を独立して計算するというものです。 この順序により、責任のある単一の「キラー」候補が決定され、そこからソート可能な除外キーが導出されます。 

最後の並べ替えステップにより、削除シーケンスが生成されます。 タイブレーク ルールは、キーに座標を追加することによって処理され、角度時間が衝突する場合に決定的な順序付けが保証されます。 

最もデリケートな部分は、一貫した角度の順序付けです。 実際には、角度の安定性が順序付けの正しさを決定するため、これは浮動小数点除算ではなくロバストな方向比較を使用して実装する必要があります。

 ## 特殊なケース

 重要なエッジ ケースは、複数の点が特定の点に対してほぼ同じ角度境界上にある場合に発生します。 このような状況では、同一角時間以降は座標によるタイブレークルールが決め手となります。 

たとえば、3 つの点が基準点からの角度方向が同じになるように位置合わせされている場合、幾何学的には方向が同じであっても、x 座標の小さい方を最初に削除する必要があります。 実装では、角度タイの下でソートが安定したままになるように、座標順序が最終キーに追加されるようにする必要があります。 

もう 1 つの微妙なケースは、ポイントの「キラー」自体が以前に削除される場合です。 消去時間は純粋に幾何学的に計算され、ソースが後のイベントで生き残るかどうかには依存しないため、アルゴリズムは正しいままです。 順序はシミュレーションではなく、ポイントごとの角度の最小値によって完全に決定されます。
