 ## 解決策
 ## 問題の理解

 私たちは、人の名前と電話番号の関連付けを保存する単純な電話帳を扱っています。 システムは、保存されている名前の番号を更新するか、指定された名前に関連付けられている現在の番号を要求する一連の操作を受け取ります。 タスクは、これらの操作をシミュレートし、各クエリに対して正しい結果を返すことです。 

各入力操作は、文字列キーから数値へのマッピングの挿入または更新、または指定されたキーの値を取得するリクエストのいずれかです。 名前が以前に追加されたことがない場合、その名前に対するクエリは、その名前が存在しないことを返す必要があり、通常は「not found」などの特別な値で表されます。 

この制約は、操作の数が十分に大きくなり、クエリごとに以前に保存されたすべてのエントリをスキャンするソリューションでは速度が遅すぎる可能性があることを意味します。 すべてのルックアップを線形に検索する単純なリストベースのアプローチでは、最悪の場合、二次時間まで劣化し、拡張できません。 

主なエッジ ケースは、同じ名前が複数回更新される場合、クエリがこれまで挿入されたことのない名前を参照する場合、および同じ名前に対するクエリが多数繰り返される場合に発生します。 たとえば、操作が「alice 123」を挿入し、「alice 456」を挿入し、「alice」をクエリする場合、後の更新によって以前の値が上書きされるため、正解は「456」になります。 古いエントリを置換せずにエントリを追加する単純なアプローチでは、最初の値が誤って返されるか、すべての出現値を検索する必要があります。 

もう 1 つのエッジ ケースは、挿入が実行されていないときに「bob」をクエリするなど、欠落しているキーをクエリすることです。 正しい出力では、0 のようなデフォルトの数値を返すのではなく、不在を明示的に反映する必要があります。0 が有効な電話番号でもある場合、誤解を招く可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、すべての操作をペアのリストに保存し、クエリごとにリストを逆方向にスキャンして、その名前に対する最新の割り当てを見つけます。 最新の更新によって現在の値が決定されるため、これが機能します。 ただし、n 個の操作があり、すべての操作がクエリである最悪のケースでは、各クエリが O(n) エントリをスキャンする可能性があり、全体で O(n^2) 時間がかかります。 入力サイズが大きい場合、これは現実的ではありません。 

重要な観察は、問題の構造が歴史的な再構築を必要としないということです。 どの時点でも、各名前の最新の値のみが重要です。 これにより、以前のすべての更新を 1 つの現在の状態に圧縮できます。 ハッシュ テーブル (辞書) は、各名前を最新の電話番号に直接マッピングすることで、これを自然にサポートします。 挿入と更新は単純な上書きになり、クエリは直接検索になります。 

これにより、問題全体が、効率的な平均 O(1) 操作による変更可能なキーと値のストアの維持に集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (クエリごとのスキャン履歴) | O(n^2) | O(n) | 遅すぎる |
 | ハッシュマップ (辞書) | O(n) 平均 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 空のハッシュ マップを初期化して、名前と電話番号のマッピングを保存します。 この構造は、その時点における電話帳の現在の状態を表します。 
2. 入力から各操作を順番に読み取ります。 各操作は更新またはクエリのいずれかであり、後の操作は前の更新に依存するため、出現した順序で処理されます。 
3. 操作が挿入または更新の場合は、マッピングをハッシュ マップに保存または上書きします。 名前の最新の番号のみが有効であるため、上書きは必須です。 
4. 操作がクエリの場合は、名前がハッシュ マップに存在するかどうかを確認します。 存在する場合は、保存されている数値を出力します。 それ以外の場合は、「見つかりません」などのセンチネル値を出力します。 
5. すべての操作が処理されるまで続行し、すべてのクエリがその前に発生したすべての更新の状態を反映していることを確認します。 

### なぜ効果があるのか

 どの時点でも、ハッシュ マップには名前ごとに 1 つのエントリが含まれており、これはこれまでに確認された最新の更新に対応します。 これは不変条件を形成します。つまり、最初の k 個の操作を処理した後、マップはそれらの操作に対する正しい電話帳の状態を表します。 更新では古い値を上書きすることで不変状態が維持され、クエリでは構造が変更されず、正確さが維持されます。 すべての操作は 1 回だけ処理され、最新の値以外の履歴情報は必要ないため、最終的な答えは必要な動作と一致する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    phone = {}

    q = int(input().strip())
    for _ in range(q):
        parts = input().split()
        if not parts:
            continue

        if parts[0] == "add":
            name = parts[1]
            number = parts[2]
            phone[name] = number

        elif parts[0] == "find":
            name = parts[1]
            if name in phone:
                print(phone[name])
            else:
                print("not found")

if __name__ == "__main__":
    solve()
```このソリューションは、という辞書を維持します。`phone`各名前の最新の番号を保存します。 あらゆる人にとって`add`操作では、値が直接割り当てられ、以前のエントリが上書きされます。 あらゆる人にとって`find`操作では、辞書内で定数時間の検索を実行し、保存されている数値または`"not found"`。 

実装の重要な詳細は、Python 辞書の上書き動作です。これは、古いものを新しい更新で置き換えるという要件に自然に一致します。 もう 1 つの微妙な点は、デフォルト値を想定するのではなく、欠落しているキーを明示的に処理することです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    for _ in range(q):
        parts = sys.stdin.readline().split()
        if parts[0] == "add":

            name = parts[1]

 ## 特殊なケース

 同じ名前を繰り返し更新する場合、アルゴリズムは常にディクショナリ内の以前の値を置き換えます。 たとえば、「alice 1」を挿入し、次に「alice 2」を挿入すると、最終的な状態は次のようになります。`alice → 2`、クエリは 2 を返します。上書き動作は直接的であり、追加のロジックは必要ありません。 

挿入前のクエリの場合、ディクショナリは空であるため、すべての検索はメンバーシップ チェックに失敗します。 のようなクエリ`find unknown`正しく返します`"not found"`これは、アルゴリズムがデフォルトの数値を想定するのではなく、明示的に存在をチェックするためです。 

更新とクエリの混合シーケンスの場合、ディクショナリが以前のすべての操作を処理した後の状態を表すという不変条件により、すべてのステップでの正確さが保証されます。
