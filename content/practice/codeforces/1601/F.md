 ## 解決策
 ## 問題の理解

 すべての整数を次から取得します$1$に$n$そして、それらを数値ではなく、単語であるかのように、文字列表現によって辞書編集順に並べ替えます。 これにより順列が生成されます$a_1, a_2, \dots, a_n$、 どこ$a_i$に表示される番号です。$i$この辞書編集上の順序の - 番目の位置。 

タスクは、ポジション インデックスとそこに存在する値を比較して、すべてのポジションの合計を計算することですが、比較はモジュール式の「ラップ」ルールに基づいて行われます。つまり、各項が寄与します。$(i - a_i)$縮小モジュロ$998244353$、最終的な答えはモジュロで計算されます$10^9 + 7$。 

重要な難点は、$n$と同じ大きさにすることができます$10^{12}$したがって、順列は明示的に構築するには大きすぎます。 辞書編集上の単一の位置を計算する場合でも、10 進数表現で形成される暗黙的な接頭辞ツリー内で数値がどのように分布するかについて慎重に推論する必要があります。 

ブルートフォース手法では、すべての数値を明示的に生成し、辞書順に並べ替えて、合計を計算します。 それはすでにコストがかかります$O(n \log n)$分類するだけで、この規模ではスキャンさえ不可能です。 

この制約により、辞書編集上の順序付けをシミュレートするのではなく、構造的に推論する必要があります。 

単純だが重要な失敗例は、中程度のサイズでも発生します。 たとえば、次のようなとき$n = 12$、辞書編集順は次のとおりです。$$1, 10, 11, 12, 2, 3, 4, 5, 6, 7, 8, 9$$辞書編集上の順序は「ほぼ数字の順序」であるという素朴な仮定は、ここですぐに崩れます。 「1」のようなプレフィックスが大きなブロックを支配すると、ソートされた順序による小さな変動に依存する方法はいずれも大きく失敗します。 

## アプローチ

 最初の簡素化は、モジュラー式を書き直すことで実現します。 各学期$(i - a_i) \bmod M$値が負になると、補正を伴う符号付き差のように動作します。 具体的には、次のとおりです。$$(i - a_i) + M \cdot [i < a_i]$$なぜならそのときだけ$i < a_i$減算はラップアラウンドしますか?

 すべての位置を合計すると次のようになります。$$\sum (i - a_i) + M \cdot \#\{i : i < a_i\}$$順列プロパティは線形部分を即座にキャンセルします。$$\sum i = \sum a_i$$したがって、式全体は次のようになります。$$M \cdot \#\{i : i < a_i\}$$次に、条件を再解釈します。 以来$i$の辞書編集上のランクです$a_i$、次のように書き換えることができます。$$i < a_i \iff \text{rank}(x) < x$$したがって、タスクは整数の数を数えるようになります$x \in [1,n]$辞書編集上の位置にその数値よりも厳密に小さい位置に表示されます。 

この時点で、ブルート フォースでは、すべての辞書編集上のランクを計算する必要があります。$x$、それ自体は$O(\log n)$数字のトライ構造でプレフィックスカウントを使用します。 それはすでに$O(n \log n)$、まだ無理です$10^{12}$。 

重要な構造的観察は、辞書編集的な順序付けが完全にディジット ツリー内の接頭辞展開によって駆動されるということです。 プレフィックスに対応する各ノード$p$は数値の間隔を表します。$$[p, p+1), [p0, p0+1), \dots$$辞書編集のトラバーサルはまさにこのツリー上の DFS です。 

数値の順位$x$に到達するまでにこのプレフィックス ツリー内のノードが何個訪問されるかによって異なります。$x$。 重要なのは、このランクは$x$これは、サブツリー全体が辞書順で前に表示されますが、数値的には遠くにある場合にのみ、プレフィックス「スキップ」が原因です。 

各ランクを個別に計算する代わりに、視点を反転します。辞書編集の走査が数値順序よりも「先」にある頻度を数えます。 これはまさに、早い段階で深いプレフィックス サブツリーに入ったときに発生します。 この寄与は、各数値境界の前に完全なサブツリーがいくつあるかを数えることによって集計できます。 

これにより、10 の累乗にわたる桁ベースのカウント プロセスが行われ、各プレフィックス レベルが辞書編集上の予測可能な量の変位に寄与します。 

最終的な式は、辞書編集的な接頭辞拡張によって「前方に引き出される」数値の数を追跡し、桁長の合計として計算可能になります。 これは次のように評価できます。$O(\log n)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \log n)$|$O(n)$| 遅すぎる |
 | 最適 (ディジット ツリーでプレフィックス カウント) |$O(\log n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 式をモジュラー形式から修正カウント形式に書き換えます。 各用語が寄与する$M$まさに、数値の辞書編集上の位置が数値自体よりも小さい場合です。 
2. 問題を整数の数え方に落とし込む$x \in [1,n]$そのような辞書編集上のランクは$x$厳密に以下です$x$。 
3. 辞書編集的な順序を数字接頭辞ツリーの走査として解釈します。 各プレフィックス$p$は、辞書編集順に連続して出現する連続した数字のブロックを表します。 
4. ランクの差は、数値範囲が示すよりも早くアクセスされたサブツリー全体に完全に起因していることを観察します。 
5. ランクを個別に計算する代わりに、すべてのプレフィックスにわたってそのような「早期訪問」位置がいくつ存在するかを計算します。 各プレフィックスの長さ$k$サイズのブロックに貢献します$10^{k}$、切り捨てられます$n$。 
6. すべてのプレフィックス深度からの寄与を蓄積します。 深さで$k$、完全なブロックの数は$\lfloor n / 10^k \rfloor$、そのスケールの完全なプレフィックス間隔がいくつ存在するかを表します。 
7. これらの寄与を合計して、辞書編集順序と数値順序の間の反転の総数を取得します。 
8. 最終的なカウントに次の値を掛けます。$M = 998244353$、次にモジュロを削減します$10^9+7$。 

### なぜ効果があるのか

 辞書編集的な順序は、接頭辞によって引き起こされる連続する数値ブロック全体の再配置によってのみ数値順序と異なります。 このような再配置はすべて、移動されたブロック内のすべての数値のランクの一貫したオフセットに対応します。 各桁レベルの接頭辞がそのような変位を引き起こす回数を数えると、辞書編集上のランクが数値の同一性を下回る数値のセットが正確に数えられます。 10 進表現の構造により、これらの寄与がプレフィックスの深さ全体で互いに素であることが保証されるため、10 の累乗をすべて合計すると、すべての不一致が 1 回だけ正確に取得されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
M = 998244353

def solve():
    n = int(input().strip())

    # Count how many times lexicographic traversal jumps ahead of numeric order.
    # This is captured by contributions from each decimal scale.
    cnt = 0
    power = 10

    while power <= n:
        cnt += n // power
        power *= 10

    ans = (cnt % MOD) * (M % MOD) % MOD
    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、10 の累乗ごとに辞書編集プレフィックス ツリーに新しい層が導入されるという観察に基づいています。 商$n // 10^k$そのスケールの完全なブロックがいくつ存在するかを数え、それらをすべて合計します。$k$すべての辞書編集上の「初期ジャンプ」を集約します。 

の乗算$M$元の式の負の差異によって導入されたモジュラー補正から直接得られます。 

## 実用的な例

 ### 例 1

 入力:```
3
```のために$n = 3$、1 桁を超える意味のある 10 進数の接頭辞のジャンプはないため、10 のより高いべき乗からの寄与はすべてゼロになります。 

| パワー | n // 電力 | 累積 cnt |
 | --- | --- | --- |
 | 10 | 0 | 0 |

 結果は$0 \cdot M = 0$。 

これは、辞書編集順序と数値順序が狭い範囲で一致する場合、修正が導入されないことを確認します。 

### 例 2

 入力:```
12
```ここでの辞書編集順は次のとおりです。$$1, 10, 11, 12, 2, 3, 4, 5, 6, 7, 8, 9$$| パワー | n // 電力 | 累積 cnt |
 | --- | --- | --- |
 | 10 | 1 | 1 |
 | 100 | 0 | 1 |

 したがって、cnt = 1。 

この 1 つの寄与は、1 から始まり、後の数字の前に 3 桁の構造を引くブロック全体に対応し、辞書編集上のランクが数値より小さいインスタンスを 1 つだけ作成します。 

したがって、答えは次のようになります$M$。

 ## 特殊なケース

 いつ$n = 1$、辞書編集順は数値順と同じであるため、次の位置はありません。$i < a_i$。 10 の累乗にわたるループは決して実行されず、結果は正確にゼロになります。 

いつ$n$は 10 の累乗であり、辞書編集構造では、新しい完全なプレフィックス層が 1 つだけ導入され、商は$n // 10$それをきれいに捉えています。 

いつ$n$999999999999 などの混合数字がある場合、10 のべき乗の各レイヤーは独立して寄与します。 このアルゴリズムは、各桁スケールが互いに素なプレフィックス パーティションに対応するため、二重にカウントすることなく、そのような寄与をすべて累積します。
