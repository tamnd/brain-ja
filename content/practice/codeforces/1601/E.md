 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられた一連の日があり、それぞれに所定のチケット料金が設定されています。 各チケットは、有効化されると連続 k 日間有効です。 複数の生徒が特定の間隔でジムに通いたいと考えている場合は、いつでもチケットを購入して、未使用のチケットを保存して後で有効にすることができます。 目標は、希望する日数をすべてカバーするために各学生が費やさなければならない最小合計金額を計算することです。 

入力では、n、q、k に続いてチケットコストの配列が与えられます。`a`各生徒の間隔を記述する長さ n、q のクエリ`[l_j, r_j]`。 各生徒にとって、出力は支払わなければならない最小の総コストです。 

制約は大きく、n と q はそれぞれ最大 300,000、チケットのコストは最大 10^9 になります。 各学生の日数をシミュレートし、考えられるすべてのチケット購入日を反復する単純なアプローチは O(n * q) であり、最悪の場合、9×10^10 の演算になる可能性があります。 これは 2 秒の制限には遅すぎます。 したがって、O(n + q)、または最悪でも O(n log n + q) に近いアプローチが必要です。 

k = 1 の場合、微妙なエッジケースが発生します。これは、各チケットが 1 日のみをカバーすることを意味します。 この場合、各学生は毎日チケットを購入する必要があるため、最小限の解決策は、その間隔でのチケット費用の合計だけです。 もう 1 つのエッジ ケースは、チケットのコストが大幅に変動する場合に発生します。学生は、たとえアクティベーションが遅れたとしても、安い日に​​チケットを事前に購入することでお金を節約できる可能性があります。 現在だけを見て不用意に貪欲にアプローチすると、この機会を逃してしまう可能性があります。 たとえば、次の場合`a = [1, 100, 1]`k = 2 の場合、2 ～ 3 日目に訪問する学生は、単純に購入すると 2 日目に 100 を費やしますが、1 日目に 1 で購入して 2 ～ 3 日目に使用することができ、お金を節約できます。 

## アプローチ

 強引な方法では、各生徒を個別にシミュレートします。 学生 j の場合、日から開始します`l_j`、利用可能なチケットのリストと残りの有効期限を毎日管理します。`i`で`[l_j, r_j]`、有効なチケットがない場合はアクティブにするか、必要に応じて新しいチケットを購入します。 毎日、過去 k 日分の有効なチケットを確認する必要があります。 最悪の場合、これは生徒あたり O(k * n) となり、全体では O(n * k * q) になります。 k から n までの場合、これは明らかに遅すぎます。 

重要な洞察は、問題は、長さ k のウィンドウにわたってチケットコストのスライド最小値を維持することに帰着するということです。 チケットを購入すると、次の k 日間をカバーできるため、任意の間隔をカバーするための最適な戦略`[l_j, r_j]`次の k 日間で利用可能な最小チケットコストを繰り返し選択することです。 この観察により、配列を事前計算できるようになります。`dp[i]`どこ`dp[i]`1 日目をカバーするための最小合計コストです。 単調なキューまたはセグメント ツリーを使用すると、すべての日を反復しながら、過去 k 日間の最小値を効率的に維持できます。 この場合、各学生間隔のコストは単純に次のようになります。`dp[r_j] - dp[l_j - 1]`定義すると`dp[0] = 0`。 

これらの値を 1 回事前計算することで、生徒ごとのクエリを O(1) に削減し、使用するデータ構造に応じて O(n + q) または O(n log n + q) のソリューションを生成します。

 | --- | --- | --- | --- |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`dp`長さ n+1、`dp[0] = 0`。`dp[i]`1 日目から i 日目までをカバーする最小コストが保存されます。 
2. 毎日 i を 1 から n まで繰り返します。 過去 k 日間の最小コストを表す単調キューまたはインデックスのデキューを維持します。毎日、`dp[i]`の最小値です`dp[i-1], dp[i-2], ..., dp[i-k]`プラス`a[i]`。 これにより、事実上、i 日目をカバーできるチケットを購入する最も安い日が選択されます。 
3.充填後`dp`、各生徒の質問に答えます`[l_j, r_j]`計算に帰着する`dp[r_j] - dp[l_j - 1]`。 これが機能する理由は、`dp[i]`最小コストを累積して差し引く`dp[l_j-1]`この学生が必要としない接頭辞を削除します。 
4. 各生徒の結果を出力します。 

不変条件は、毎日私が、`dp[i]`は、必要な時期に早めにチケットを購入するという最適な戦略を使用して、i 日までのすべての日をカバーするための最小総コストを正確に表します。 サイズ k のスライディング ウィンドウが常に以前の最小値をキャプチャすることを保証することにより、`dp`、チケットの有効性が尊重されることを保証し、より安価な組み合わせは不可能です。 

## Python ソリューション```python
import sys
from collections import deque
input = sys.stdin.readline

n, q, k = map(int, input().split())
a = list(map(int, input().split()))
dp = [0] * (n + 1)

# deque will store indices of the last k dp values in increasing order
dq = deque()
for i in range(1, n + 1):
    # remove indices outside the k-day window
    while dq and dq[0] < i - k:
        dq.popleft()
    # maintain monotonic increasing order of dp values
    while dq and dp[dq[-1]] >= dp[i - 1]:
        dq.pop()
    dq.append(i - 1)
    # dp[i] = min(dp[i-1..i-k]) + a[i-1]
    dp[i] = dp[dq[0]] + a[i - 1]

for _ in range(q):
    l, r = map(int, input().split())
    print(dp[r] - dp[l - 1])
```私たちが使用するのは`i-1`インデックス作成時`a`Python のリストは 0 から始まるためです。 デックにより、常に最小値が選択されることが保証されます`dp`過去 k 日間で効率的に。 生徒ごとに減算すると、`dp[l-1]`は、間隔外のプレフィックスを削除し、希望する日の正確な最小コストを提供します。
