 ## 解決策
 ## 問題の理解

 バイナリ文字列と、そこからちょうど 2 つの隣接する文字を交互に削除する 2 人のプレイヤーが与えられます。 移動するたびに連続するペアが削除されるため、文字列はターンごとに 2 文字ずつ縮小します。 隣接するペアが存在しない文字列に直面すると、プレイヤーは即座に負けます。これは文字列の長さが 0 または 1 の場合に発生します。 

重要な問題は、動きを構築することではなく、両方のプレイヤーが最適な選択をした場合に勝者を決定することです。 アリスは常に最初に動くため、ゲームは、文字列が短すぎて続行できなくなる前に、有効な手を合計で何回行うことができるかによって完全に決まります。 

文字列の長さの制約は小さく、最大 100 個で、テスト ケースは最大 1000 個あります。 これは、テスト ケースあたり O(n²) のシミュレーションでも許容されることを意味しますが、問題の構造は、文字列あたり O(n) の推論を目指す必要があることを示唆しています。 

微妙な点は、0 と 1 の正確な配置は、手が存在するかどうかを超えて、長期的なプレイではあまり重要ではないということです。 各移動は長さを 2 減らすだけであり、文字列を縮小する以上に新しい隣接制約を作成する移動はありません。 したがって、ゲームは基本的に、特定のパターンではなく、どれだけ多くの手をプレイできるかが重要です。 

素朴な思考を打ち破るエッジケースは、パリティではなく構造に焦点を当てすぎることから生じます。 

たとえば、次のような文字列を考えてみましょう。`01`。 アリスはすぐにそれを削除し、勝ちます。 のために`1111`、アリスはペアを削除し、ボブはペアを削除しますが、アリスには移動がありません。 のために`0011`、アリスはペアを削除し、その場を離れます。`01`、ボブはそれを削除し、空のままにします。 その後、アリスは何もできずに負けます。 これらの例は、局所的な構造ではなく、手のパリティが結果を決定することを示しています。 

よくある誤った直感は、交互の文字やグループ化が重要であると考えることです。 実際には、移動するたびに長さが 2 ずつ減少するため、移動数は基本的に、文字列が短くなりすぎるまで、互いに素な隣接するペアをどれだけ除去できるかによって決まります。 

## アプローチ

 ブルートフォース手法では、ゲームの状態を完全にシミュレートします。 各ステップで、プレイヤーは可能なすべての隣接ペアの削除を試み、結果の文字列を再帰的に評価し、対戦相手の立場を失うような動きがあるかどうかを判断します。 これは、文字列に対する標準のミニマックス検索です。 

問題は、州の数が非常に急速に増加していることです。 長さが 20 の場合でも、分岐係数は最大 19 であり、文字列に対するメモ化が慎重に設計されていない限り、状態は頻繁に繰り返されますが、構造化された方法ではありません。 長さが 100 までの場合、このアプローチは完全に不可能になります。 

重要な観察は、すべての移動が常に長さを正確に 2 だけ削減し、文字列の縮小を除いて、将来の移動の可用性に関連するその他の変更を行わないことです。 つまり、可能な合計移動数は、文字列の長さが 0 または 1 になるまでに隣接するペアを何回削除できるかによってのみ決まります。 

したがって、ゲームは合計で何手の手が存在するかを数え、アリスが最後の手を打つかどうかを確認することに要約されます。 合計の手数が奇数の場合は、アリスの勝ちです。 互角の場合はボブが勝ちます。 

明示的に動きを計算する必要さえありません。 移動回数は単純に`len(s) // 2`なぜなら、すべての動きは正確に 2 文字を削除し、最終的な動きの数を決定するためにどのペアが選択されるかによって動きは左右されないからです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (州を越えるミニマックス) | O(指数) | O(n) | 遅すぎる |
 | 最適 (パリティ観測) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 このアルゴリズムは、ゲームを単純なパリティ チェックに縮小することに依存しています。 

1. 文字列を読み取り、その長さを計算します。 文字の構造は最終的な決定には無関係であるため、実際の内容は無視されます。 
2. 完全な移動を何回実行できるかを決定します。 各移動で正確に 2 文字が削除されるため、移動数は長さを 2 で割った整数になります。 
3. パリティに基づいて勝者を決定します。 手数が奇数の場合、アリスが最後の手を行い、ボブは有効な手なしで残されます。 互角の場合は、ボブが最後の動きをし、その後アリスが負けます。 
4. アリスが勝った場合は「DA」を出力し、勝てなかった場合は「NET」を出力します。 

この削減が有効である理由は、固定量だけ長さを減少させる以上に利用可能な構造のパリティを変更する移動は存在しないためです。 どの隣接するペアが選択されたかに関係なく、すべての動きは正確に 2 文字を消費するため、戦略に応じて動きの合計数を増減できる分岐効果はありません。 

### なぜ効果があるのか

 不変条件は、一連の有効な移動の後、残りの文字列の長さは常に`n - 2k`どこ`k`行われた移動の数です。 この値が 2 未満になった時点でゲームは終了します。したがって、可能な最大手数は次のように固定されます。`n // 2`、選択肢とは独立しています。 両方のプレイヤーがアリスから始まる手を交互に行うため、アリスは、この固定シーケンスで最後の手を獲得した場合にのみ勝ちます。これは次と同等です。`n // 2`奇妙であること。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    s = input().strip()
    moves = len(s) // 2
    if moves % 2 == 1:
        print("DA")
    else:
        print("NET")
```コードは各テスト ケースを読み取り、すぐに長さの計算に削減します。 必要な計算は整数を 2 で割ることだけです。これは可能な削除の総数に相当します。 パリティ チェックによって勝者が直接決まります。 

よくある間違いは、削除をシミュレートしたり、実際のペアを追跡しようとしたりすることです。 ゲームはどの特定のペアが除去されるかには依存せず、枯渇するまでに除去が何回発生するかのみに依存するため、これは不要です。 

## 実用的な例

 ### 例 1:`01`| ステップ | 文字列の長さ | 行われた動き | 次のプレイヤー |
 | --- | --- | --- | --- |
 | 0 | 2 | 0 | アリス |
 | 1 | 0 | 1 | ボブ (移動なし) |

 アリスは 1 つだけ行動しますが、これは奇妙であるため、アリスが勝ちます。 

これは、長さ 2 の場合、唯一可能な手を取るアリスが常に勝つことを裏付けます。 

### 例 2:`0011`| ステップ | 文字列の長さ | 行われた動き | 次のプレイヤー |
 | --- | --- | --- | --- |
 | 0 | 4 | 0 | アリス |
 | 1 | 2 | 1 | ボブ |
 | 2 | 0 | 2 | アリス (動かない) |

 ここではちょうど 2 つの移動があります。 ボブは 2 番目の動きを行い、アリスは有効な動きを持たないままになります。 手数は互角なのでアリスが負けます。 

これは、最終的な結果は、文字の配置ではなく、削除の合計数が奇数であるか偶数であるかのみに依存することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 各テスト ケースでは、文字列の長さを計算するために文字列を 1 回だけスキャンします。 
| スペース | お(1) | カウンタを超えて余分な構造体は格納されません。 

合計入力サイズが小さく、各テスト ケースが読み取り後に一定時間で処理されるため、ソリューションは制約内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        s = input().strip()
        moves = len(s) // 2
        out.append("DA" if moves % 2 == 1 else "NET")
    return "\n".join(out)

# provided samples
assert run("3\n01\n1111\n0011\n") == "DA\nNET\nNET"

# minimum size
assert run("1\n1\n") == "NET"

# simple win
assert run("1\n00\n") == "DA"

# alternating pattern
assert run("1\n0101\n") == "NET"

# maximum-ish small test
assert run("1\n" + "01"*50 + "\n") == "NET"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1`|`NET`| 単一のキャラクター、移動なし |
 |`00`|`DA`| 最小の勝利ケース |
 |`0101`|`NET`| 偶数長の交互パターン |
 |`01*50`|`NET`| より大きな偶数構造、パリティの一貫性 |

 ## 特殊なケース

 次のような単一の文字の場合`0`、アルゴリズムは次のように計算します。`len = 1`、 それで`moves = 0`、「NET」と出力されます。 これは、アリスがすぐに有効な手を持っていないという事実と一致します。 

のようなペアの場合`01`、`moves = 1`、これは奇妙であるため、アリスが勝ちます。 実行中、アリスは唯一のペアを削除し、ボブは動くことができません。 

のような文字列の場合`1111`、アルゴリズムは次のように計算します。`moves = 2`。 アリスが最初の動きをし、ボブが 2 番目の動きをします。アリスにはもう手はありません。 偶数パリティにより、アリスが負けることが正しく予測されます。 

次のような交互文字列の場合`010101`、長さだけが重要です。 さまざまな削除命令が存在するにもかかわらず、アルゴリズムは依然として次のような結果をもたらします。`moves = 3`、つまり、アリスが最後の手を獲得したため、アリスが勝ちます。
