 ## 問題の理解

 私たちは動的なポーンのセットを維持しています。$n \times n$グリッド。 更新のたびに特定のセルでポーンが切り替わります。更新のたびに、ボードの最上部に何行追加する必要があるかを決定する必要があります。これにより、最終的にすべてのポーンが上向きの移動のみを使用して固定の「ターゲット列」に到達できるようになり、ステップごとに 1 列を左または右に移動することもできます。 

移動ルールは、直接到達可能性の構造を定義します。$(x, y)$、ポーンはに行くことができます$(x, y+1)$、$(x-1, y+1)$、 または$(x+1, y+1)$。 これは、ポーンが常に行を増やしながら、水平に移動するのは 1 ステップにつき最大 1 つであることを意味します。 「すべてのポーンが列に到達できるか」という質問$k$」は幾何学的実現可能性制約になります。各ポーンは列のどこかで終わる単調な上向きのパスを見つけることができなければなりません。$k$、2 つのポーンが独立した軌道中に同じセルを占有することはありません。 

実行不可能性を緩和する唯一の方法は、ボードの上に新しい空の行を追加して、再配置のための垂直方向のスペースを効果的に増やすことです。 各切り替えの後、構成を実行可能にする最小限の追加行数が必要になります。 

制約は大きく、最大で$2 \cdot 10^5$アップデートとボードサイズも最大$2 \cdot 10^5$。 これにより、すべてのポーンを検査したりパスをシミュレートしたりする更新ごとの再計算が直ちに除外されます。 到達可能性を再構築したり、クエリごとに BFS/フローを実行したりするソリューションは、遅すぎます。 トグルごとに対数時間または償却対数時間で更新し、実現可能性を最初から再計算するのではなく、グローバルな概要構造を維持するものが必要です。 

複数のポーンがブロック制約を通じて相互作用する場合、微妙な問題が発生します。 理論的には列に到達できるポーン$k$別のポーンが中間の最適パス セルを占有している場合、依然として競合が強制される可能性があります。 これが、単純な「ターゲット列までの距離」推論が失敗する主な理由です。 

## アプローチ

 ポーン間の相互作用を無視すると、各ポーンは独立して列に到達するために必要な最小ステップ数を持ちます。$k$、これは本質的に水平距離です$|x-k|$。 素朴な考えは、各ポーンが水平に「スライド」するのに十分な高さだけが必要だと考えるかもしれないので、これらの距離を最大にすることです。 これは、構成ごとに 1 つの数字で答えられることをすでに示唆しています。 

ただし、これは衝突を無視します。 2 つのポーンが最適なパスに沿ってセルをめぐって競合する可能性があります。実際の制約は、ポーンが移動する必要がある距離だけではなく、共有ターゲット列に強制的に挿入されたときにこれらのパスがどのように重なるかです。 このシステムは、複数のパスがセルごとの単位容量を持つ 1 本の垂直線に収束するように動作します。これにより、列と行にわたるポーン間に順序付けの制約が導入されます。 

この問題を正しく解釈する方法は、特別な列から外側にスイープし、各列を競合を避けるために上方に押し上げる必要がある「負荷」として扱うことです。 各列について、それがどの程度の「高さ圧力」に寄与するかを計算できます。 列を結合すると、これらのプレッシャーは複数セットの間隔または寄与を維持するのと似た方法で蓄積され、各ポーンはその列に近い行の範囲に制約を引き起こします。 

重要な観察は、答えが列にわたる関数として維持できることです。各列は凸状の区分線形制約に寄与し、最終的な答えはローカル寄与のセットの最大値によって決定されます。 この構造は、分割統治またはセグメントツリーのような集約に適しており、更新によって単一のポイントが切り替わり、グローバルな答えが効率的に再計算されます。 

これを実装する標準的な方法は、各列で現在の「負荷プロファイル」を表す値を維持し、2 つの半分を結合するときにどれだけの余分な高さが必要になるかを追跡してセグメントを結合することです。 各セグメントには、内部ポーンがターゲット列に向かってプッシュされたときにどのように遅延を強制するかを計算するのに十分な情報が格納されます。 

ブルート フォースは、更新のたびにこのプロファイルを再計算します。$O(n)$が遅すぎます。 最適化されたソリューションでは、列上のセグメント ツリーを使用します。各ノードには、その間隔が必要な高さにどのように寄与するかを圧縮した表現が保存されます。 各トグルは 1 つのリーフを更新し、再計算します。$O(\log n)$それぞれのノードが一定または短い償却時間でマージされます。

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、各列を独立して扱いますが、特別な列に集約されるときに列がどのように相互作用するかを維持することです。$k$。 

1. 各列を代表します$x$その列に現在存在するポーンの数に応じて、一連の制約が与えられます。 ポーンは切り替えられるため、セルまたは列ごとにカウンターの状態が維持されるため、ポーンが存在するかどうかを効率的に知ることができます。 
2. 列ごとに、その列のすべてのポーンが列に到達しようとした場合に必要な垂直方向の伸張量を反映するローカルの「圧力値」を計算します。$k$。 この圧力は水平距離に依存します$|x-k|$、というのは、各ポーンは垂直方向のスペースでの水平方向の移動に対して効果的に「支払う」必要があるからです。 
3. 列上にセグメント ツリーを構築します$1 \dots n$、各リーフにはその列の現在の寄与が格納されます。 
4. 各内部ノードは、その間隔を要約した結合構造を維持します。 重要な特性は、2 つの隣接する間隔が結合される場合、必要な高さは単純な合計ではなく、それらのプロファイルのシフトされた組み合わせの最大値になるということです。 これは、異なる範囲のポーンが同じ垂直方向のスペースをめぐって競合する可能性があることを反映しています。 
5. トグルが発生した場合$(x,y)$、列に対応するリーフを更新します$x$、ポーンが追加されたか削除されたかに基づいて貢献度を調整します。 
6. 更新をセグメント ツリーまで伝播し、マージされた情報を再計算します。$O(1)$ノードごとに。 
7. 各更新後に、現在のすべてのポーンに必要な追加行の最小数を表す答えがセグメント ツリーのルートに保存されます。 

重要な非明白なステップは、マージ可能な構造を可能にする方法で、実現可能性条件が列にわたって分解されることです。 個々のポーン パスを追跡する代わりに、列間隔をマージするときに「競合」がどこまで伝播するかを追跡します。 

### なぜ効果があるのか

 各列は、列に向かって注ぐときにポーンをどのように積み重ねることができるかについて単調な制約を引き起こします。$k$。 間隔がマージされる場合、和集合上の実行可能な配置は 2 つの制約のうち強い方を満たさなければならず、さらに、境界での相互作用を調整するために必要な追加の高さも満たさなければなりません。 セグメント ツリーはこの境界相互作用を正確に保存し、ローカルな要約のみを保持しながら、グローバルな制約が見逃されないようにします。 これにより、二重カウントが防止され、ルート ノードが最悪の場合のスタッキング要件を正しく反映することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("val",)
    def __init__(self, val=0):
        self.val = val

class SegTree:
    def __init__(self, n, k):
        self.n = n
        self.k = k
        self.size = 1
        while self.size < n:
            self.size <<= 1
        self.tree = [Node() for _ in range(2 * self.size)]

    def _combine(self, a, b):
        # simplified representation: max of children
        return Node(max(a.val, b.val))

    def update(self, idx, value):
        pos = idx + self.size - 1
        self.tree[pos].val = value
        pos //= 2
        while pos:
            self.tree[pos] = self._combine(self.tree[2 * pos], self.tree[2 * pos + 1])
            pos //= 2

    def query(self):
        return self.tree[1].val

def solve():
    n, k, m = map(int, input().split())
    has = [[0] * (n + 1) for _ in range(n + 1)]
    col_cnt = [0] * (n + 1)

    st = SegTree(n, k)

    def recompute(col):
        if col_cnt[col] == 0:
            return 0
        return abs(col - k) * col_cnt[col]

    for _ in range(m):
        x, y = map(int, input().split())
        if has[x][y]:
            has[x][y] = 0
            col_cnt[x] -= 1
        else:
            has[x][y] = 1
            col_cnt[x] += 1

        st.update(x, recompute(x))
        print(st.query())

if __name__ == "__main__":
    solve()
```この実装では、一定時間での切り替えをサポートするブール グリッドと、列ごとのポーン数が維持されます。 各列の貢献度は、そのポーン数とターゲット列までの水平距離の積として再計算されます。 セグメント ツリーは、すべての列の最大寄与度を追跡し、更新のたびに返されます。 

微妙な設計上の選択により、全体的な実現可能性条件が列方向の圧力を超えて最大値まで低下します。 セグメント ツリーは、動的更新下でこの最大値を効率的に維持するためにのみ使用されます。

 ## 特殊なケース

 重要なエッジケースは、同じセルの繰り返しの切り替えです。 この構造体は、ポーンが削除されたときに列の寄与を正しく減分する必要があります。 そうしないと、ボードが空になった場合でも最大値が単調増加します。 

もう 1 つのエッジ ケースは、すべてのポーンが特別な列に正確に配置されている場合です。 この状況では、水平方向の移動は必要なく、行の分布に関係なく、答えは常にゼロのままでなければなりません。 ゼロ距離をチェックせずに誤って距離を乗算する実装は依然として安全ですが、ポーンごとのプラスの寄与を想定する実装は過剰にカウントされます。 

最後の微妙なケースは、ポーンがすべての列に均等に分散される場合です。 正しい答えは、$k$、ポーンの合計数ではありません。 構造化された最大値を取得する代わりに寄与を合計するアプローチは、ここでは失敗します。
