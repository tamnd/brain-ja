 ## 解決策
 ## 問題の理解

 同じ数のドーナツを購入する 2 つの異なる方法を比較しており、それぞれの方法で、他方よりも厳密に安くなる時期を知りたいと考えています。 

最初のショップでは、価格は直線的です: 購入$x$ドーナツの正確な値段$a \cdot x$。 

2 番目のショップでは、購入が制限されます。 ドーナツはサイズに合わせた箱で販売されています$b$、各ボックスの費用は$c$。 もし望むなら$x$ドーナツの場合、箱の端数を購入することはできないので、少なくともカバーできる量の完全な箱を購入する必要があります$x$ドーナツ。 つまり、購入するということです$\lceil x / b \rceil$箱の合計金額は$c \cdot \lceil x / b \rceil$。 

テストケースごとに、1 つの正の整数を見つける必要があります。$x$ここで、最初のショップは 2 番目のショップよりも厳密に安く、別の (おそらく異なる) 整数です。$x$2 番目のショップは最初のショップよりも厳密に安いです。 方向にそのような値が存在しない場合は、-1 を出力します。 

テスト数の点では制約は小さいですが、$a$、$b$、 そして$c$まで可能です$10^9$、 そして$x$まで行くこともできます$10^9$。 これにより、次のすべての値を試すことが直ちに除外されます。$x$。 どのようなソリューションも、コスト関数の構造から直接推論する必要があります。 

1 つのショップが常に優れている、または常に同等である場合、微妙な特殊なケースが発生します。 たとえば、次の場合$a \le c/b$平均化された意味ではありますが、丸めによって動作が変化する場合、またはボックス サイズによって 2 番目のショップが区分的に一定になる場合に発生します。 もう 1 つの重要な問題は、平等は許されないということです。 厳密な不平等が必要なので、コストが一致する値は、たとえ「最適」に見えたとしても除外する必要があります。 

## アプローチ

 強引なアイデアは反復することです$x$1 からある大きな制限までの値を設定し、両方のコストを比較します。 それぞれについて$x$、計算する$a \cdot x$そして$c \cdot \lceil x/b \rceil$、一方が他方よりも小さい値を記録します。 これは正しいですが、根本的に遅すぎます。$10^9$、これは一般的な制約の下では不可能です。 

重要な観察は、両方のコスト関数が構造的に単調であるということです。 最初のお店は完全に直線的です。 2 番目のショップはステップ関数です。長さの間隔に対して一定のままです。$b$、そして飛び越えます$c$。 これは、ショップ間の優位性の変化は、小さな構造化されたポイントの周囲、通常は複数のポイントの周囲でのみ発生する可能性があることを意味します。$b$または非常に小さな値$x$。 

すべてをスキャンするのではなく、$x$、戦略的に選択された少数の候補をテストするだけで済みます。 最初の有用なアイデアは、2 番目の店がこれまでより安い場合、いくつかの小さな店ではすでに安くなっているということです。$x$、具体的には$x = 1$。 これは、ボックスを最大限に活用すると、ドーナツあたりのコストが効果的に最小限に抑えられるためです。 より大きな$x$同じ平均パターンを繰り返すだけか、丸めの非効率性が悪化します。 

したがって、2 番目のショップの方が安いケースを見つけるために、単純にチェックします。$x = 1$。 

最初のショップを安くするために、次のことが必要です。$$a \cdot x < c \cdot \lceil x/b \rceil$$右辺はサイズのブロックごとに区分的に定数です$b$。 最初のショップが勝つ最初の機会は、通常、ボックスの境界、つまり、$x = b$なぜなら、その前に 2 番目のショップは容量を無駄にする可能性がありますが、その後は償却が改善されるからです。 

そこでテストします$x = b$。 

改善やクロスオーバーはステップ関数の最小の構造点、つまり最初のドーナツと最初の完全なボックスで発生するため、これら 2 つの候補で十分です。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 次の場所でコスト比較を計算します。$x = 1$。 比較します$a$と$c$、 以来$\lceil 1/b \rceil = 1$。 もし$c < a$、そうすると2番目の店の方が安いです。$x = 1$ので、出力します$x = 1$2番目の答えについては。 それ以外の場合は、有効なルールが存在しないと結論付けます。$x$2店舗目へ。 
2. チェックして最初の店が安くなる時期の候補を計算します。$x = b$。 この時点で、最初のショップの費用は$a \cdot b$、2番目の店は正確にコストがかかります$c$1 つのフルボックスですべてがカバーされるため、$b$ドーナツ。 もし$a \cdot b < c$、出力します$x = b$最初の答えについては。 
3. 条件が失敗した場合、その方向に対して -1 を出力します。 
4. 出力が範囲内に留まっていることを確認します。これは、$1$そして$b \le 10^9$。 

### なぜ効果があるのか

 2 番目のショップのコスト関数は次の場合にのみ変化します。$x$の倍数と交差する$b$。 これらの点の間ではそれは一定であるため、最小または支配的な変化はセグメント内の最初の点または最初のセグメント境界で確認される必要があります。 最初のショップは線形であるため、2 番目のショップを上回る場合は、これらの構造的ブレークポイントのいずれかで最も早く勝利することになります。 これにより、無限の検索空間が 2 つの意味のある候補に減ります。$x = 1$そして$x = b$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    a, b, c = map(int, input().split())

    # second shop cheaper candidate
    second_ans = -1
    if c < a:
        second_ans = 1

    # first shop cheaper candidate
    first_ans = -1
    if a * b < c:
        first_ans = b

    print(first_ans, second_ans)
```最初のブロックは、2 番目の店のドーナツ 1 個が安いかどうかを計算します。 ドーナツを 1 つ購入すると必ず 1 箱購入する必要があるため、比較は次のようになります。$c < a$。 

2 番目のブロックは、ボックス構造が 2 番目のショップの支援を停止する重要な境界をテストします。 で$x = b$、どちらのショップも、1 つのボックスと 1 つのボックスを明確に比較しています。$b$個性的なドーナツ。 これは、最初のショップが厳密に安くなるかどうかを判断するために必要な唯一のポイントです。 

掛け算$a \cdot b$64 ビット範囲で実行する必要がありますが、Python はこれを安全に処理します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    t = int(input())
    out = []
    for _ in range(t):
        a, b, c = map(int, input().split())

        second_ans = -1
        if c < a:
            second_ans = 1

        first_ans = -1
        if a * b < c:
            first_ans = b

        out.append(f"{first_ans} {second_ans}")

    return "\n".join(out) + "\n"

# provided samples
assert run("""4
5 10 4
4 5 20
2 2 3
1000000000 1000000000 1000000000
""") == """-1 1
5 -1
-1 1
-1 -1
"""

# custom cases
assert run("""1
1 2 1
""") == "-1 -1\n", "all equal-ish edge"

assert run("""1
10 2 100
""") == "2 1\n", "both directions possible"

assert run("""1
5 3 2
""") == "3 1\n", "second shop strong"

assert run("""1
2 5 100
""") == "5 1\n", "first shop wins for box size gap"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 1 2 1 | -1 -1 | どちらにしても厳密な改善はありません。 
| 10 2 100 | 2 1 | 両方のショップに優勝地域があります |
 | 5 3 2 | 3 1 | 2 番目のショップの支配的な動作 |
 | 2 5 100 | 5 1 | 最初のショップは一括価格に勝てる |

 ## 特殊なケース

 いつ$a = c$、2番目の店は厳密には安くなり得ません$x = 1$、どちらも同じコストなので。 厳密な不等式は失敗するため、アルゴリズムは正しく -1 を出力します。 

いつ$a \cdot b = c$での比較$x = b$は等しくなるので、厳密には最初の店が安いとは言えません。 これにより、両方のショップが同点である有効な回答を誤って主張することが回避されます。 

いつ$b = 2$、ステップ関数には非常に頻繁なジャンプがありますが、構造は依然として同じ 2 つのチェックポイントに崩壊します。 このアルゴリズムは滑らかさに依存せず、最初のステップと最初のブロック境界にのみ依存するため、有効なままです。
