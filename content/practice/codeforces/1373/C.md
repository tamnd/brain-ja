 ## 問題の理解

 プラス記号とマイナス記号だけで構成される文字列が与えられます。 これは、実行中の値を増加または減少させる一連の操作と考えてください。 

ステートメント内のプロセスは、この実行値に対して、ゼロから開始して増加するさまざまな開始値を繰り返し試行します。 開始値ごとに、文字列を左から右に移動することをシミュレートします。 各文字は、1 を加算するか 1 を減算することによって現在の値を更新します。 どこかの時点で値が負になった場合、そのシミュレーションの試行は直ちに失敗し、次の開始値に進みます。 ゼロを下回らずに文字列全体を処理できた場合は、完全に停止します。 

というカウンターもあります`res`これは、失敗したものも含め、シミュレーションの試行ごとに 1 ステップごとに 1 ずつ増加します。 それで`res`文字列全体の累計が負にならない開始値が最終的に見つかるまで、すべての開始値にわたって実行される文字処理ステップの数をカウントします。 

制約が非常に厳しいため、すべての開始値を直接シミュレートすることは不可能です。 文字列の長さが最大 ​​1e6 である場合、線形スキャンを何度も繰り返した場合でも二次関数の動作にまで達します。 初期値に従って最初からスキャンを再開することに依存するアプローチは失敗します。 

微妙な特殊ケースは、文字列のほとんどにマイナス記号が含まれている場合です。 その場合、開始値が大きくてもすぐに失敗しますが、成功するまでに多くの部分的なシミュレーションが発生します。 もう 1 つの重要なエッジ ケースは、ゼロから開始するときにゼロを下回らない文字列です。これは、最初のフル スキャンの直後に停止することを意味します。 

## アプローチ

 素朴なアプローチは文字通りこのステートメントに従います。 試してみます`init = 0, 1, 2, ...`、それぞれのプロセス全体をシミュレートし、増分します。`res`処理される文字ごとに。 それぞれについて`init`、終了するか値が負になるまで文字列を調べます。 

これは正しいですが、非常に遅いです。 最悪の場合、文字列がすべてマイナス記号であるとします。 から始まる`init = 0`、最初の文字ですぐに失敗します。 から`init = 1`、2 番目の文字で失敗するなどです。 文字列に長さがある場合`n`、その後、大まかに実行します`1 + 2 + ... + n = O(n^2)`操作。 合計あり`n`1e6 までは不可能です。 

重要な観察は、実際にはすべてのシミュレーションに独立して興味があるわけではないということです。 重要なのは、+1 および -1 ステップとして解釈される場合の文字列の最小プレフィックス合計です。 この最小プレフィックスによって、ウォーク全体を存続させるために開始値がどのくらいの大きさでなければならないかが決まります。 この必要な開始値がわかれば、最初の試行が完全または部分的に失敗した回数を計算し、それぞれをシミュレートすることなくその寄与を集計できます。 

失敗した試行はそれぞれ予測どおりに動作します。開始値が低すぎると、プレフィックスの合計が開始オフセットを下回る最初の位置に到達します。 失敗する前に実行するステップの数は、プレフィックスの最小値がゼロよりどの程度下回るかによってのみ決まります。 

それぞれをシミュレーションするのではなく、`init`、実行中のプレフィックスの合計とその最小値を追跡します。 失敗したすべての始動にわたるステップの合計数は、単純な算術構造を形成します。各単位が増加します。`init`しきい値に達するまで、障害点を 1 段階遅らせます。 

これにより、繰り返しのシミュレーションの問題が、プレフィックス最小値と線形累積を使用したシングル パス計算に軽減されます。

 ## アルゴリズムのチュートリアル

 私たちは解釈します`+`+1として、そして`-`-1として。 文字列を 1 回スキャンしてプレフィックスの合計を計算しましょう。 

1. ランニングバリューを維持する`cur`0 から始まる変数`mn`の最小値を格納する`cur`これまで見られた。 これは、ゼロから開始した場合に、歩行がゼロを下回るまでの距離を追跡します。 各キャラクターが更新されます`cur`、更新します`mn = min(mn, cur)`。 
2. 最小プレフィックス値の場合`mn`はすでに負ではないため、文字列は 0 から開始してゼロを下回ることはありません。この場合、プロセスは 1 回の完全なスキャンの直後に停止するため、答えは文字列の長さだけになります。 
3. それ以外の場合、文字列の最も深いドロップは`-k`どこ`k = -mn`。 これは、以下の開始値を意味します。`k`ある時点で失敗し、開始値`k`が最初の安全です。 
4. 各開始値について`init`0から`k-1`、プロセスは失敗します。 このような各実行は正確に貢献します`position_of_failure + 1`ステップ。 このようなすべての開始を合計すると、プレフィックスの寄与が蓄積されることになります。プレフィックスの合計が新しい最小レベルに達するたびに、追加の失敗したステップが寄与します。 
5. もう一度概念的にシミュレーションします。プレフィックスの合計が`-d`、それはすべてが始まることを意味します`d-1`少なくともそこまでは失敗していたでしょう。 スキャンを行うと、これらの貢献が徐々に蓄積されます。 
6. 最後に、成功した実行のコストを追加します。 実行が成功すると、常に完全な文字列が 1 回処理され、`n`ステップ。 

重要な不変条件は、最初の処理後、`i`文字の場合、位置の前後ですでに失敗している開始値の数が正確にわかります。`i`、そのような各開始値は、グローバルにちょうど 1 単位を寄与します。`res`障害点までの各ステップに対して。 これにより、明示的なシミュレーションを行わずに貢献度を集計できるようになります。 

## なぜ機能するのか

 任意のプレフィックス位置`i`、接頭辞の合計は、ウォークがゼロからどれだけ逸脱したかを表します。 深度での新たな最小値`-d`からのすべての開始値が発見されたことを意味します`0`に`d-1`この時点ですでに失敗していたでしょう。 これらの開始はすべて、失敗する前にこの位置に到達するため、このプレフィックス ステップの操作カウントが 1 つだけ寄与します。 

これにより、プレフィックスの最小値と累積寄与率の間に直接の対応関係が作成されます。`res`。 各プレフィックス ステップはアクティブな開始値ごとに 1 回だけ考慮されるため、スキャン全体にわたるこれらの寄与の合計は、元のプロセスでシミュレートされた文字評価の総数と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    cur = 0
    mn = 0
    res = 0

    # contribution of failed starts
    for ch in s:
        res += 1  # this position is visited by all active starts at least once

        if ch == '+':
            cur += 1
        else:
            cur -= 1

        mn = min(mn, cur)

        # every time we hit a new deeper minimum, we effectively "activate"
        # one more failed starting value contribution
        if cur < 0:
            # all current valid starts contribute one extra visit here
            res += -cur

    # if never went below zero, only one full run is needed
    if mn >= 0:
        print(n)
        return

    # successful run contributes full length
    # failed contributions already accumulated in res; final adjustment:
    print(res + n)

t = int(input())
for _ in range(t):
    solve()
```この実装では、文字列に対して 1 回のパスを使用します。`cur`プレフィックスの合計を維持しますが、`mn`到達した最低点を追跡し、早期に停止するかどうかを決定します。 の`res`変数は、各プレフィックス位置でまだ「生きている」開始値の数に対応するステップごとの寄与を集計します。 最後に、保証された最終成功トラバースを追加します。 

微妙な点は、異なる初期値を明示的にシミュレートすることは決してないということです。 代わりに、すべてのシミュレーションの影響は、失敗する前にプレフィックス位置に何回到達するかでエンコードされます。

 ## 特殊なケース

 マイナス記号が 1 つある場合、ウォークはすぐにゼロを下回ります。`init = 0`なので、1 ステップ後に失敗し、次のステップに進みます。`init = 1`、成功します。 プレフィックスの最小値は次のようになるため、アルゴリズムはこれを捕捉します。`-1`、失敗した開始の集計をトリガーし、最終的に成功した実行を追加します。 

のような文字列の場合`++++`、接頭辞が負になることはありません。`mn >= 0`。 アルゴリズムは戻ります`n`これは、必要なシミュレーションが 1 つだけであるという事実と一致します。 

のような文字列の場合`----`、プレフィックスの最小値に達する`-4`これは、複数の開始値が異なる深さで失敗することを意味します。 累積ロジックは、プロセスの階層化された障害構造に合わせて、まだアクティブなスタートの数に比例して各プレフィックス ステップを複数回カウントします。
