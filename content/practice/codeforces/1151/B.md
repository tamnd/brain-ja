 ## 解決策
 ## 問題の理解

 各行が一連の選択肢を表す整数のグリッドが与えられ、すべての行から正確に 1 つの数値を選択する必要があります。 行ごとに 1 つの数値を選択した後、選択したすべての数値のビット単位の XOR を計算します。 タスクは、この XOR を厳密に正にできるかどうかを判断し、そうであれば、これを達成する有効な列の選択を出力することです。 

重要なオブジェクトはグリッド自体ではなく、行の選択肢のセットです。 各行は 1 つの値のみを提供し、最終的な結果は、XOR の下でこれらの値がどのように相互作用するかによって異なります。 

制約は十分小さいので、$O(nm)$あるいは$O(nm \log m)$行ごとの推論。 と$n, m \le 500$、合計 250,000 個の要素を管理できるため、すべての組み合わせを探索するのではなく、すべての行を検査して、行ごとに単純なローカル決定を行うことができます。$n$。 

主な微妙なケースは、行列内のすべての数値がゼロの場合です。 その場合、考えられるすべての選択で XOR がゼロになるため、答えは不可能になるはずです。 少し分かりにくいケースとしては、すべての行に同一の値のみが含まれる場合があります。たとえば、各行が次のようになります。`[7, 7, 7]`。 それでも、どの選択を行っても次と等しい XOR が生成されます。$7 \oplus 7 \oplus \cdots$、行のパリティによってはゼロになる可能性があり、個々の行よりも構造が重要です。 

単純な間違いは、ゼロ以外の要素が存在する場合はそれを貪欲に選択できると考えることです。 XOR はグローバルであるため、これは失敗します。ゼロ以外の要素は後で他の要素とキャンセルされる可能性があります。 正しい推論では、最終的な XOR で少なくとも 1 ビットを意図的に強制的に残す必要があります。 

## アプローチ

 ブルートフォース ソリューションでは、行ごとに 1 つの要素を選択するあらゆる方法が試行されます。 つまり$m^n$それらの組み合わせは、たとえ$n = 20$。 これが正しい理由は簡単です。考えられるすべての XOR 結果を直接チェックし、ゼロ以外の結果がないかどうかを検証します。 失敗点は組み合わせ爆発です。 

XOR の構造を使用して問題を圧縮する必要があります。 XOR は、最終結果が 0 の場合、行全体ですべてのビットが相殺されるという意味で、ビット全体にわたって線形です。 これは、完全な組み合わせを検討することを避け、少なくとも 1 つのビット位置がアンバランスになるようにする必要があることを示唆しています。 

重要な観察は驚くほど単純です。すべての行に少なくとも 1 つの非ゼロ要素が含まれている場合、少なくとも 1 つの行が選択されたビットを変更する値に寄与していることを確認することで、常に非ゼロの XOR を生成する選択を構築できます。 本当に不可能な唯一のケースは、行列内のすべての要素がゼロの場合です。 

これを利用するには、最初に任意のベースライン選択を選択し、通常はすべての行から最初の列を取り出し、XOR を計算します。 すでにゼロ以外の場合は完了です。 ゼロの場合は、ちょうど 1 行を別の列に変更して、別の値を生成することによって問題を修正しようとします。行が定数でない限り、その値は存在する必要があります。 

これにより、問題は、代替選択によって XOR 状態が変更される 1 つの行を見つけるだけになります。

 ## アルゴリズムのチュートリアル

 単純な候補ソリューションを構築し、必要に応じて修復します。 

1. まず、各行の最初の列を選択します。 これにより、有効な完全な選択が即座に得られ、最初の XOR を計算できるようになります。 
2. 選択したすべての値の XOR を計算します。 この XOR がゼロ以外の場合、現在の選択内容はすでに条件を満たしているため、それを直接出力できます。 
3. XOR がゼロの場合は、最終的な XOR を変更する方法で選択を変更する必要があります。 
4. 行を 1 つずつスキャンし、現在選択されている値と異なる値を持つ列がその行に存在するかどうかを確認します。 
5. そのような行が見つかった場合は、その選択を別の列に切り替えます。 ゼロ XOR 構成で 1 つの値を反転すると、ゼロ以外の差が生じる必要があるため、これにより XOR がゼロから非ゼロに変更されることが保証されます。 
6. 更新された選択内容を出力します。 

ステップ 5 が機能する理由は、XOR の合計が 0 の場合、1 つの値を置き換えるためです。$x$別の値で$y$XORを変更します$x \oplus y$、次の場合は非ゼロになります$x \ne y$。 これにより、ゼロ状態が即座に解除されます。 

### なぜ効果があるのか

 すべての行がすべての列にわたって同じ値を持つ場合、選択に関係なく、すべての行が同じ数値を与えるため、XOR は固定され、XOR された数値と等しくなります。$n$回。 その数値がゼロの場合、変更はできません。 それ以外の場合、最初の XOR はすでに非ゼロになっています。$n$奇数、またはゼロの場合$n$は偶数ですが、この場合、すべての行は定数であるため、結果を変更するための変更は存在しません。 したがって、このアルゴリズムは、すべてゼロの行列の場合にのみ正確に失敗し、正しく「NIE」が得られます。 それ以外の場合は、少なくとも 1 行に個別の値が含まれているため、1 回の反転でゼロ以外の XOR を強制できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(n)]

    choice = [0] * n
    x = 0

    for i in range(n):
        choice[i] = 0
        x ^= a[i][0]

    if x != 0:
        print("TAK")
        print(*[c + 1 for c in choice])
        return

    for i in range(n):
        base = a[i][0]
        for j in range(1, m):
            if a[i][j] != base:
                choice[i] = j
                x ^= a[i][0]
                x ^= a[i][j]
                print("TAK")
                print(*[c + 1 for c in choice])
                return

    print("NIE")

if __name__ == "__main__":
    solve()
```構築は固定ベースラインの選択から始まり、XOR 計算が簡単になります。 修復フェーズでは慎重に 1 行のみを変更し、XOR の違いを局所的に推論できるようにします。 アップデート`x ^= old ^ new`XOR 和の 1 つの要素を置換することによる正確な代数効果を反映します。 

異なる要素の内部スキャンは、成功すると XOR がゼロ以外に調整されることが保証されるため、安全です。

 ## 特殊なケース

 最もデリケートなケースは、すべての行に同じ値が含まれている場合です。 この状況では、列を変更しても何も起こらないため、唯一の決定要因はパリティと値の均一性です。 繰り返される値がゼロの場合、すべての XOR が強制的にゼロになるため、解は存在しません。 ゼロ以外の場合、初期 XOR はすでに固定されており、パリティに応じてゼロになる場合とゼロでない場合がありますが、それを変更する方法はないため、正確性は完全に行に明確な代替値があるかどうかの検出に依存します。 

もう 1 つの微妙なケースは、行列に非ゼロ要素が存在するにもかかわらず、初期 XOR がゼロである場合です。 アルゴリズムは、単一行の変更を強制することでこれを処理します。XOR の変更は局所的であり、値が異なる場合に非ゼロであることが保証されるため、これで十分です。
