 ## 解決策
 ## 問題の理解

 私たちには、次の 2 つの個人的な特徴を持つ学生が列を成しています。$a_i$目の前の人がどれだけ嫌われているかを測定します。$b_i$、後ろにいる人をどれだけ嫌っているかを測定します。 学生の不満は、その学生の立場に直線的に依存します。$i$位置にあります$j$、彼らの不満は$a_i \cdot (j-1) + b_i \cdot (n-j)$。 列の不満の合計は、生徒全員の個別の不満の合計です。 私たちの目標は、キューを再配置してこの合計を最小化することです。 

入力により提供されるのは、$n$学生たちと$a_i$そして$b_i$値があり、出力は単一の整数であり、不満の合計は最小限です。 

以来$n$まで可能です$10^5$、任意のアルゴリズム$O(n^2)$複雑さが遅すぎます。 これにより、すべての順列を試行することが除外されます。$O(n!)$。 おおよそ次のような解決策が必要です$O(n \log n)$または$O(n)$。 

重要な微妙な点が生じるのは、$a_i$そして$b_i$生徒によって大きく異なります。 単純なアプローチでは、学生を小さなレベルに配置しようとする可能性があります。$a_i$正面に大きく$b_i$しかし、相対的な違いが重要な場合、これは失敗する可能性があります。 たとえば、2人の生徒が$a_1=1, b_1=100$そして$a_2=100, b_2=1$、生徒 1 を前に置くと不満が最小限に抑えられ、生徒 2 を後ろに置くと不満が最小限に抑えられます。 重要なのは、これらのトレードオフのバランスをとるグローバルな順序を見つけることです。 

## アプローチ

 強引な解決策は、キューのすべての順列を生成し、それぞれの合計の不満足度を計算することです。 それぞれの計算には時間がかかります$O(n)$時間もあるし、$n!$順列。 と$n=10^5$、$n!$天文学的に大きいため、総当たり攻撃は実行不可能です。 

重要な観察は、不満が立場内で直線的であるということです。 特定の生徒に対して$i$、それらを 1 つ前に移動すると、項が減少します。$a_i \cdot (j-1)$による$a_i$しかし増加します$b_i \cdot (n-j)$による$b_i$。 したがって、それらを前進させるための限界コストは次のとおりです。$a_i - b_i$。 これは、次のことを意味します。$a_i > b_i$、彼らの不満は列の後ろに行くほど早く増大するので、彼らを前の方に配置する必要があります。 逆に、もし$a_i < b_i$、後ろに向かっていくはずです。 学生を並べ替える基準$a_i - b_i$降順でこの原則を捉えています。 

ソート後、生徒をソート順に前から後ろに配置すると、合計が最小になります。 各生徒の不満は、この並べ替えられたキュー内の生徒の位置に基づいて直接計算されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む$n$そして$a_i, b_i$生徒一人ひとりの価値観。 それらを次のタプルとして保存します。$(a_i, b_i)$。 
2. 差を計算します$a_i - b_i$生徒一人ひとりに。 この値は、生徒が後ろよりも前にいることをどれだけ強く好むかを表します。 
3. 生徒を降順に並べ替えます。$a_i - b_i$。 差が大きい生徒は前に移動します。列の後ろに来ると不満が早く高まるためです。 
4. 変数を初期化する`total`ゼロに。 ソートされた学生を反復処理して、ポジションに割り当てます$1$に$n$。 ポジションにある生徒ごとに$j$、不満を次のように計算します。$a_i \cdot (j-1) + b_i \cdot (n-j)$そしてそれを追加します`total`。 
5. 出力`total`。 

なぜ機能するのか: 並べ替え基準$a_i - b_i$2 人の生徒の交換が順序に違反するのは、生徒の成績がより高い場合のみです。$a_i - b_i$が後から配置されると、全体的な不満が増大します。 不満関数の線形性により、一度並べ替えると、この順序からの偏差によって合計が増加することが保証されるため、貪欲なアプローチは全体的に最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
students = []

for _ in range(n):
    a, b = map(int, input().split())
    students.append((a, b))

# Sort by a_i - b_i descending
students.sort(key=lambda x: x[0] - x[1], reverse=True)

total = 0
for idx, (a, b) in enumerate(students):
    position = idx + 1
    total += a * (position - 1) + b * (n - position)

print(total)
```コードはまず、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 並べ替えではキーにラムダ関数を使用します`a_i - b_i`そして順序を逆にして、最大の違いが前に来るようにします。 このループは、人間が判読できるキューの位置に一致する 1 から n までの位置を割り当てます。 によるインデックス付け`idx + 1`は、0 から始まる Python インデックスを 1 から始まる位置に正しくマップします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(sys.stdin.readline())
    students = [tuple(map(int, sys.stdin.readline().split())) for _ in range(n)]
    students.sort(key=lambda x: x[0]-x[1], reverse=True)
    total = 0
    for idx, (a, b) in enumerate(students):
        pos = idx + 1
        total += a*(pos-1) + b*(n-pos)
    return str(total)

# provided samples
assert run("3\n4 2\n2 3\n6 1\n") == "12", "sample 1"
assert run("4\n1 5\n3 2\n4 4\n2 3\n") == "28", "sample 2"

# custom cases
assert run("1\n10 20\n") == "0", "single student"
assert run("2\n1 1\n1 1\n") == "2", "two equal students"
assert run("3\n100000000 1\n1 100000000\n50 50\n") == "200000001", "large disparity values"
assert run("5\n5 1\n4 2\n3 3\n2 4\n1 5\n") == "35", "descending a, ascending b"
