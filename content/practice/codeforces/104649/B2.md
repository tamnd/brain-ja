 ## 解決策
 ## 問題の理解

 この問題は、離散時間にわたって進化するプロセスを記述しており、寄与が非常に特殊な方法で現れ、その後増加します。 それぞれの瞬間に、いくつかの新しいユニットが導入されます。 一度導入されると、各ユニットは一定のままではなく、その後のステップごとにその寄与が 2 倍になります。 

各タイム ステップでのこのシステムの合計観測値が与えられます。 それぞれの観測値は、これまでに出現したすべてのユニットからの貢献度の合計であり、古いユニットは 2 倍になるまでの時間が長いため、貢献度が高くなります。 タスクは、このプロセスを逆にして、観測された合計が一致するように各タイム ステップで導入される必要がある新しいユニットの数を回復することです。 

入力は、隠れたプロセスの一連の集約された測定値として見ることができます。 出力は、各タイム ステップでの新しい寄与の「誕生」を表す別のシーケンスであり、重複する指数関数的な増加を解きほぐします。 

この制約は、すべてのユニットの成長を単純にシミュレーションすると遅すぎることを意味します。 各ユニットを個別に直接シミュレーションした場合、新しいユニットごとに将来のすべてのタイム ステップを更新する必要があり、最悪の場合は 2 次の動作が発生します。 一般的な Codeforce の制限では、ステップ数が約 10^5 に達すると、これはすぐに実行不可能になります。 

2 番目の微妙な問題は、貢献が大きく重複していることです。 連続する値の差を新しい単位に直接帰する単純な貪欲な試みは、古い単位が一定の量ではなく増加する量に寄与するため、失敗します。 たとえば、観察されたシーケンスが突然のジャンプで始まる場合、そのジャンプは新しく導入されたユニットと以前のすべてのユニットの 2 倍化の両方に起因する可能性があります。 

小さな具体的な失敗例がこれを説明するのに役立ちます。 観察された値が次のとおりであると仮定します。 

入力:

 t = [1, 2, 4]

 単純なアプローチでは、各ステップで +1 単位が追加されると考えるかもしれません。 これは誕生 [1, 1, 1] を示唆しますが、値 [1, 3, 7] が生成され、一致しません。 不一致は、前の単位が 2 倍になり続けるため、連続する値間の差が独立していないために発生します。 

正しいソリューションでは、以前のステップからの指数キャリーをキャンセルしながら、新しく導入されたユニットの正確な寄与を分離する必要があります。 

## アプローチ

 ブルートフォース再構築では、各ステップで導入された各ユニットを明示的に追跡します。 タイム ステップごとに、以前に導入されたすべてのユニットを反復処理し、その寄与を 2 倍にして更新し、新しいユニットを追加します。 これによりプロセスが正しくシミュレートされますが、n 個のステップのそれぞれが以前のすべての寄与を更新する可能性があるため、O(n^2) 操作のコストがかかります。 n が最大 10^5 であるため、これは実現可能な限界をはるかに超えています。 

重要な観察は、プロセスが直線的であり、一定の繰り返しに従っていることです。 既存の各ユニットは各ステップでその寄与を 2 倍にします。これは、合計の観測値が連続する状態間の単純な関係を満たすことを意味します。 時刻 t に導入された新しいユニットの数を b[t]、観測された合計を f[t] と表すと、t−1 から t に移動するときに、以前のすべての寄与が 2 倍され、その後 b[t] が加算されます。 

これにより、次のような直接的な関係が得られます。 

f[t] = 2 * f[t−1] + b[t]

 この式を並べ替えると、隠れたシーケンスが分離されます。 

b[t] = f[t] − 2 * f[t−1]

 これにより、個々の貢献を追跡する必要が完全になくなります。 前の値がわかれば、各値を一定時間で計算できます。 問題全体は、アレイ上の単一の線形パスに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | 線形再構成 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 観測値 f[0..n−1] のシーケンスを読み取ります。 これらは、各タイム ステップでの累積寄与を表します。 
2. 以前の履歴がないため、最初の値 f[0] をまったく新しい寄与として扱います。 これは直接 b[0] = f[0] を与えます。 
3. 1 から n−1 までの後続のインデックス t ごとに、前の状態からの期待される寄与を 2 * f[t−1] として計算します。 これは、もう 1 回の倍加ステップ後のすべての以前のユニットを表します。 
4. 現在の観測値からこの予想される繰り越し寄与分を差し引いて、新しい寄与分を分離します。 

b[t] = f[t] − 2 * f[t−1]
 5. 各ステップの b[t] を保存または出力します。 以前の観測値が判明すると、各値は独立します。 

微妙な点は、2 倍化が過去の状態全体に均一に適用されるため、グローバルに因数分解できることです。 これにより、減算によってすべての歴史的な重複を完全にキャンセルできるようになります。 

### なぜ効果があるのか

 各ステップで、システムは以前の合計を取得し、その内部のすべての寄与を 2 倍にすることによって進化します。 これは、過去全体が単一の集計量に 2 を掛けたもののように動作することを意味します。2 倍になった前の合計と現在の観測値との間の偏差は、そのステップで新たに導入された単位のみから生じる必要があります。 加算は線形であり、2 倍は合計に分布するため、交互作用項は現れず、漸化式は正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    f = list(map(int, input().split()))
    
    if n == 0:
        return
    
    b0 = f[0]
    print(b0, end=" ")
    
    prev = f[0]
    for i in range(1, n):
        cur = f[i] - 2 * prev
        print(cur, end=" ")
        prev = f[i]

if __name__ == "__main__":
    solve()
```反復は f[t−1] のみに依存するため、解は以前の観測値のみを保持します。 各ステップでは、一定時間内に新しい非表示の値が計算されます。 最初の要素は、減算対象となる以前の状態がないため、個別に処理されます。 

一般的な実装の落とし穴は更新です`prev`間違っています。 観測値を保存する必要があります`f[t]`、再構築された値ではありません`b[t]`、繰り返しは観察された合計に基づいて定義されるためです。 

もう 1 つの微妙な問題は、整数のサイズです。 値は 2 倍化の繰り返しにより急速に大きくなる可能性があるため、Python 整数の使用は安全ですが、より厳密な言語では 64 ビット以上が必要です。

 ## 特殊なケース

 重要なエッジ ケースは、シーケンスが最初のステップの後に新しい挿入がなく、指数関数的 2 倍化に完全に従う場合です。 入力の場合:```
3
1 2 4
```アルゴリズムは b[0] = 1 を計算し、次に b[1] = 2 − 2·1 = 0、および b[2] = 4 − 2·2 = 0 を計算します。これにより、初期状態が設定されると、システムは追加の寄与なしで進化し、再帰によってきれいにゼロが生成されることが確認されます。 

別のエッジ ケースは、各ステップで新しいコントリビューションが導入され、急速に増加するシーケンスが作成されるときに発生します。 のために：```
3
1 3 8
```b[0] = 1、b[1] = 3 − 2・1 = 1、b[2] = 8 − 2・3 = 2 が得られます。前方にトレースすると、再構成された各加算が 2 倍を超えた超過と正確に一致することが示され、重複する指数関数的増加が増分の分離を妨げないことが確認されます。
