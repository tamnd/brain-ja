 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、連続する繰り返しを最小限にするように求められます。 形式的には、配列の等価性を、連続する 2 つの要素が等しい位置の数として定義します。 タスクは、連続するペアを同じ新しい番号に置き換える操作を実行し、隣接する等しいペアの合計数を最大 1 に減らすことです。 目標は、配列ごとにそのような操作の最小数を計算することです。 

入力は複数のテスト ケースで構成され、各テスト ケースのサイズは最大 200,000 です。すべてのテスト ケースの配列サイズの合計も 200,000 を超えません。 これは、タイムアウトを避けるために、アルゴリズムはテスト ケースごとの配列サイズでほぼ直線的な時間で実行する必要があることを意味します。 すべてのペアを繰り返し反復する二次解法は、最悪の場合 10^10 の演算が必要になる可能性があるため、機能しません。 

明らかではないエッジ ケースは、配列がほぼ均一である場合、または孤立したブロックに繰り返し値が出現する場合に発生します。 たとえば、配列`[1,1,1,1,1]`等しい要素の長い連続を破るには 2 つの操作が必要です。 繰り返されるペアをグループ化せずにカウントするだけの単純なアプローチでは、特に重複するペアを処理する場合に、操作のカウントを誤る可能性があります。 

もう 1 つの注意が必要なシナリオは、次のような操作が必要ない場合です。`[1,2,1,2,1]`、すでに等価性 0 を持っています。不注意な解決策では、とにかく操作を適用しようとする可能性があります。 

## アプローチ

 ブルートフォースアプローチは簡単です。 配列を繰り返しスキャンして、連続する等しい要素を見つけ、許可された操作を実行してそれらを分割できます。 各演算の後、配列を更新し、等価数が最大 1 になるまで繰り返します。このアプローチは正しいですが、各演算で等価性が 1 ずつ減少するだけであり、最大 n 個の等しいペアが存在する可能性があるため、このアプローチは最悪の場合 O(n^2) を要する可能性があります。 n が 2×10^5 までの場合、これは遅すぎます。 

重要な洞察は、操作を明示的にシミュレートする必要がないということです。 連続する等しい要素は自然にブロックを形成します。 各ブロックの長さ`l`貢献する`l-1`平等へ。 ブロックの長さを減らすには`l`最大でも 1 つの等しいペアまで、おおよその必要があります`(l-1 - 1) // 2 + 1`場合の操作`l>1`、これを単純化すると、`(l-2)//2 + 1`。 長さが 1 または 2 のブロックの場合、操作は必要ないか、または 1 回の操作が必要です。 主な観察は、重複するペアの演算により、追加のブックキーピングを行わずにブロックを効率的にカバーできるということです。 これらのブロックを数えて、ブロックごとに必要な演算を計算するだけで済みます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | ブロックカウント | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を読み取ることから始めます。 変数を初期化する`operations`ゼロに。 これにより、必要な操作の数が蓄積されます。 
2. 配列を反復処理して、連続する等しい要素を特定します。 2 つのポインタを維持します。`i`ブロックの開始として、そして`j`現在のスキャンインデックスとして。 毎回`a[j]`とは異なります`a[i]`、ブロックは終了します。 
3. 長さのブロックごとに`l`（から`i`に`j-1`）、 もし`l <= 2`、手術は必要ありません。 もし`l > 2`、計算する`(l-2) // 2 + 1`これを追加します`operations`。 この公式は、各操作でペアを新しい値に設定することにより、ブロック内の 2 つの位置を固定できるという事実に基づいています。 
4. スタートポインタを移動する`i`に`j`配列の最後まで繰り返します。 
5. 合計を印刷します`operations`配列の場合。 

機能する理由: 連続する等しい値のブロックを処理し、式を適用することにより、各ブロックが最大でも 1 つの等しいペアに削減されることが保証されます。 ブロック内の操作は隣接する等しいペアに影響を与えるため、重複は自動的に処理されます。 シングルトンやすでに最小限のブロックに対して無駄な操作はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_operations(n, a):
    operations = 0
    i = 0
    while i < n - 1:
        if a[i] == a[i + 1]:
            j = i + 1
            while j < n and a[j] == a[i]:
                j += 1
            length = j - i
            if length > 2:
                operations += (length - 2)
            i = j
        else:
            i += 1
    return operations

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(min_operations(n, a))
```このコードは、スキャン ポインターを使用して、等しい値のブロックを見つけます。 内側のループは、値が変更されるまでブロックを拡張します。 2 を超える長さのブロックごとに、次を追加します。`(length - 2)`これにより、これらの操作の後、ブロックが最大 1 つの等値に縮小されることが保証されます。 外側のポインターは、二重カウントを避けるためにブロックを飛び越えます。

 ## 特殊なケース

 内部ポインターは各ブロックの末尾までスキャンするため、配列の先頭、中間、または末尾にある長いブロックは正しく処理されます。 単一の等しいペアは、次の理由により追加の操作をトリガーしません。`length > 2`チェック。 分離された繰り返しとサイズがちょうど 2 のブロックも操作数を増大させないため、off-by-one エラーが回避されます。 このアルゴリズムは自動的にシングルトンをスキップし、不必要な操作を排除します。
