 ## 解決策
 ## 問題の理解

 整数の長さのログを使用した単純な 2 人用ゲームで勝者を決定するように求められます。 がある$n$2 人のプレイヤーが交代で 1 つのログを 2 つの正の整数部分に分割します。 最初に行動できなかったプレイヤーが負けます。 各テスト ケースはログの数とその長さを提供し、出力は両方が最適にプレイしたと仮定してどちらのプレイヤーが勝つかを示す必要があります。 

入力制約は小さく、テスト ケースあたり最大 50 ログ、ログ長は最大 50 です。テスト ケースは最大 100 個まで存在できますが、すべてのテスト ケースにわたるログの総数は管理可能です。 これらの境界は、高度に最適化されたデータ構造やアルゴリズムが必要ないことを示唆しています。 テスト ケースごとにリニア スキャンを行うだけで十分です。 

重要なエッジ ケースは、すべてのログの長さが 1 である場合に発生します。その状況では、最初のプレーヤーは何も動けず、すぐに負けます。 たとえば、入力が次の場合`1\n1`、出力は次のようになります。`maomao90`エラーゴーンには利用可能な動きがないためです。 もう 1 つの微妙なケースは、ログの合計が偶数または奇数の場合です。スプリットごとにログの総数が 1 ずつ増加するため、スプリットの総数のパリティによって、どちらのプレイヤーが最初に手数を使い果たすかが決まります。 

## アプローチ

 ブルートフォースアプローチでは、ゲームをターンごとにシミュレートします。 最大の丸太を選択し、それを分割し、順番を変えて、分割できなくなるまで続けることができます。 これは概念的には正しいですが、すべてのステップでログのセット全体を追跡する必要があります。 最悪の場合、分割ごとにログの数が 2 倍になり、考えられるシーケンスの数が指数関数的に増加します。 これは、入力サイズが小さい場合でも明らかに非効率です。 

問題を単純化する洞察は、長さの対数に注目することです。$1$を超える長さのログは分割できません。$1$いつでも分割できます。 分割するたびに、ログの合計数が 1 つずつ増加します。 したがって、ゲームは純粋に利用可能な分割の合計数によって分析できます。 させて$k$より長い長さのログの数になります。$1$。 これらのログはそれぞれ、2 つの小さなログになるまでに 1 回の分割が必要となり、最終的にはすべてが 1 つの長さのログに減ります。 したがって、可能な分割の総数は、長さが次よりも大きいログの数と等しくなります。$1$。 Errorgorn が最初に動くので、この数字が奇数であれば、彼は最後の分割を行って勝ちます。 互角の場合は、maomao90 が勝ちます。 これにより、問題は 1 を超える長さのログの数を数えてパリティをチェックすることになります。パリティは線形です。$n$。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 
2. 各テスト ケースについて、ログの数を読み取ります。$n$ログの長さのリスト$a_1, a_2, \dots, a_n$。 
3. 長さが次を超えるログの数を数えます。$1$。 これは、ゲーム内で発生する可能性のある分割の合計数です。 
4. このカウントが奇数の場合、最初に動いた errorgorn が最後のスプリットを行います。 印刷する`"errorgorn"`。 
5. カウントが偶数の場合、maomao90 が最後のスプリットを行います。 印刷する`"maomao90"`。 

機能する理由: 長さが 1 を超える各ログは、利用可能な 1 つの移動にのみ寄与します。 プレイヤーは交互に手を動かし、手の数の平等によって誰が最後のターンを持つかを決定します。 この単純な不変条件によって勝者が完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    logs = list(map(int, input().split()))
    moves = sum(1 for x in logs if x > 1)
    if moves % 2 == 1:
        print("errorgorn")
    else:
        print("maomao90")
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`各テスト ケースを個別に処理します。 1 より大きいログのカウントはジェネレーター式を使用して行われるため、中間リストの作成が回避されます。 モジュロ演算によりパリティが決定され、勝者が直接決定されます。 追加のデータ構造は必要ありません。

## テストケース```python

    sys.stdin = io.StringIO(inp)

    sys.stdout = out

        n = int(input())

        moves = sum(1 for x in logs if x > 1)

            print("errorgorn")
        else:
            print("maomao90")
    return out.getvalue().strip()

# Provided samples

assert run("1\n1\n50") == "errorgorn", "single long log"

## 特殊なケース

 入力などのすべて 1 の場合`1\n3\n1 1 1`、1 を超えるログの数はゼロです。 ゼロは偶数であるため、アルゴリズムは正しく出力します。`maomao90`、エラーゴーンに動きがないことを反映しています。 

単一の長いログの場合は、次のように入力します。`1\n1\n50`、ログの数 >1 は 1 であり、これは奇数です。 アルゴリズムの出力`errorgorn`、エラーゴーンが唯一の動きをして勝つことを反映しています。 これらのエッジ ケースは、パリティ ベースのロジックが極端な場合でも堅牢であることを裏付けています。
