 ## 問題の理解

 2 つの配列が与えられています。`a`そして`b`、同じ長さの`n`。 目標は、変革できるかどうかを判断することです`a`の中へ`b`特定の操作を使用して。 この操作により 2 つの位置を選択できるようになります`l`そして`r`値が等しい配列内で、`a[l] = a[r]`、次に部分配列に対して循環回転を実行します。`a[l..r]`。 これにより、その部分配列内の各要素が 1 つ左に移動され、最初の要素が最後に移動されます。 この操作は必要に応じて何度でも実行できます。 

各テスト ケースは次のことを保証します。`b`の順列です`a`。 これは、配列に同じ要素の複数セットが含まれることを意味するため、唯一の障害は要素の順序付けです。 配列の長さ`n`最大 200,000 まで大きくなり、すべてのテスト ケースの合計も 200,000 に制限されます。 したがって、考えられるすべての回転を明示的に検査するソリューションは、非常に遅すぎます。 テスト ケースごとに線形または線形に近い時間で機能するアプローチが必要です。 

明白ではないエッジケースは、要素が次の場合に発生します。`a`は一度だけ出現します。 たとえば、次の場合`a = [1, 2, 3]`そして`b = [3, 1, 2]`、要素が繰り返されないため、操作は実行できません。そのため、等しいエンドポイントを必要とする循環回転は実行できません。 回転をシミュレートする単純なアプローチは、ここで失敗するか、無限ループに陥る可能性があります。 もう 1 つの注意が必要なケースは、繰り返し要素が出現する場合に発生しますが、それらの相対的な位置が`b`ルールで許可されていないローテーションを強制的に行うことになります。 例えば、`a = [1, 1, 2]`そして`b = [2, 1, 1]`孤独だから変身できない`2`繰り返されたものを超えて移動することはできません`1`有効な回転がありません。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての有効な操作をシミュレートしようとします。 等しい値を持つインデックスのペアごとに、部分配列を回転し、配列が徐々に変化するかどうかを確認できます。`b`。 このアプローチは原理的には正しいですが、現実的ではありません。`n`最大 200,000 個の場合、有効な回転の選択肢は O(n^2) 個あり、それぞれの実行に O(n) 時間がかかり、最悪の場合の複雑さは O(n^3) となり、完全に実行不可能です。 

重要な点は、左端の値に一致する要素の上に要素を移動する唯一の有用な操作であるということです。 したがって、問題は貪欲に一致できるかどうかを確認することになります。`b`右から左へ。 要素が`b`の最後の一致しない要素と一致しません`a`、回転を実行するには、以前にその要素の別の出現を確認しておく必要があります。 これは、要素の最後の位置と、移動を許可するために残っている「重複」の数だけを追跡する必要があることを意味します。 この洞察があれば、私たちは次のことを行うことができます。`b`端から端まで、一致する要素を消費しようとします。`a`または重複をスキップします。 要素に遭遇した場合、`b`対応する未消費のオカレンスが存在しない`a`、変身は不可能です。

 | ブルートフォース | O(n^3) | O(n) | 遅すぎる |
 | 貪欲な右から左 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのポインタを初期化する`i`そして`j`配列の最後に`a`そして`b`、 それぞれ。 背面から要素を合わせていきます。 
2. 辞書を管理する`count`スキップした重複要素の数を追跡するため`b`後で照合できる可能性があります。 
3. その間`j >= 0`、 比較する`a[i]`そして`b[j]`。 それらが等しい場合、この要素は正常に一致しています。 両方のポインタを左に移動します。 
4. もし`a[i]`等しくない`b[j]`、どうかを確認してください`b[j]`に残りカウントがあります`count`辞書。 その場合は、そのカウントをデクリメントし、回転を可能にする複製を効果的に「消費」し、移動します。`j`動かずに放置`i`。 
5. もし`b[j]`一致しません`a[i]`重複は残っていない`count`、変換は不可能です。 「いいえ」を返します。 
6. もし`i`～の始まりを過ぎて移動する`a`その間`j`まだ一致しない要素があり、変身も不可能です。 
7. すべての要素が正常に一致すると、`b`、「YES」を返します。 

なぜ機能するのか: 維持される不変条件は次のとおりです`count`は常に、将来回転を実行するために使用できる要素を表します。 最後から一致させることで、重複を前方に移動するために必要な回転が有効であることが保証されます。 これにより、許可された循環回転を明示的にシミュレートすることなく、正しくモデル化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_transform(n, a, b):
    i = n - 1
    j = n - 1
    count = {}
    while j >= 0:
        if i >= 0 and a[i] == b[j]:
            i -= 1
            j -= 1
        elif j < n - 1 and b[j] == b[j + 1] and count.get(b[j], 0) > 0:
            count[b[j]] -= 1
            j -= 1
        else:
            if i < 0:
                return False
            count[a[i]] = count.get(a[i], 0) + 1
            i -= 1
    return True

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    print("YES" if can_transform(n, a, b) else "NO")
```機能`can_transform`貪欲な右から左へのマッチングを実装します。 の`count`辞書は、要素の余分な出現を追跡します。`a`循環回転を可能にします。 複数の同一要素が存在する場合には慎重に対処します。`b`連続して表示され、以前にスキップされた重複を消費します。 境界条件はチェックによって管理されます`i >= 0`アクセスする前に`a[i]`。
