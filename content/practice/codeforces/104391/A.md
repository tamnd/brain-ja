 ## 解決策
 ## 問題の理解

 一列に配置された一連のエネルギー セル値が与えられます。 私たちがフィードする必要があるマシンは、固定された完全な二分木構造を持っています。$K$レイヤーなので、含まれています$2^{K-1}$一番下の葉と合計$2^K - 1$ノード。 

タスクは、配列を切り取ることです。$N$細胞を正確に$2^{K-1}$連続した空ではないセグメント。 各セグメントは、左から右の順序でリーフ ノードに割り当てられます。 リーフの値は、そのセグメントの合計です。 すべての内部ノードは 2 つの子の合計を取るため、リーフ セグメントが固定されると、すべてのノードの値が決定されます。 

構造を結合する制約が 1 つあります。すべての内部ノードについて、その左と右の子サブツリーの合計値間の絶対差が以下を超えてはなりません。$D$。 各サブツリーはリーフの連続ブロックに対応し、各リーフは配列の連続セグメントに対応するため、すべてのノードは 2 つの連続サブ配列の合計を効果的に比較します。 

出力は、有効な葉セグメントを生成するカットを選択する方法の数です。ここで、有効性はすべての内部ノードが差分制約を満たすかどうかによって完全に定義されます。 

制約は十分小さいので、$K \le 9$, したがって、葉の数は最大で$2^8 = 256$、 そして$N \le 300$。 これにより、指数関数的なものはすぐに除外されます$N$またはカット構成の数で。 ただし、次のことは許可されます。$O(K \cdot N^3)$スタイル動的プログラミング、$N^3 \approx 27 \cdot 10^6$慎重に実装すれば Python で実現可能です。 

微妙なエッジ ケースは、内部ノード値が配列の固定間隔の合計にのみ依存するという事実から生じます。 サブツリーの値がセグメントが内部でどのようにグループ化されるかに依存すると誤って仮定すると、問題が複雑になり、不要な状態が導入される可能性があります。 重要な観察点は、ある間隔をカバーするノードについて、$[l, r]$、その合計値は常に$\sum_{i=l}^r A_i$、その間隔がどのようにさらに分割されるかには関係ありません。 

固定されたバイナリ ツリー構造を尊重せずに、これを汎用パーティション DP として処理しようとすると、別の失敗ケースが発生します。 セグメントをランダムにグループ化すると、必要なリーフの左から右への対応が崩れ、無効な構成が過剰にカウントされます。 

## アプローチ

 ブルートフォースアプローチでは、あらゆる配置方法が試行されます。$2^{K-1} - 1$間のカット$N-1$ギャップ、それはすでに与えています$\binom{N-1}{2^{K-1}-1}$可能性。 のために$N = 300$セグメント数は最大 256 ですが、これは天文学的に大きく、まったく実現不可能です。 

すべてのパーティションを生成したとしても、それぞれに対して完全なバイナリ ツリーを構築し、すべてのノードの合計を計算し、すべての内部ノードで制約を検証する必要があります。 それは少なくとも追加します$O(N + 2^K)$パーティションごとに動作するため、事態はさらに悪化します。 

重要な簡素化は、最初にツリー構造を修正することから始まります。 セグメントを左から右の順序でリーフに割り当てたら、自由になるのは配列をどこで切り取るかだけです。 ツリーの内部構造は固定されており、実際の値には依存しません。 これにより、各ノードを配列の連続した間隔で動作しているものとして扱うことができます。 

これにより、ツリー ノードと配列間隔にわたる動的プログラミングの定式化が可能になります。 各ノードについて、指定された間隔を分割する有効な方法がいくつ存在するかを計算します。$[l, r]$そのサブツリーに必要なリーフの数を正確に計算します。 各内部ノードで、区間の考えられるすべての分割点を試し、左右の子からの解を結合し、事前に計算された区間の合計を使用して制約を確認します。

 ## アルゴリズムのチュートリアル

 バイナリ ツリーの最上部で計算をルート化し、すべてのノードをそのサブツリー内の固定数のリーフに関連付けます。 この数値は常に 2 の累乗であり、その深さによって決まります。 

次に、配列の特定のセグメント上でノードを何通り実現できるかをキャプチャする DP 状態を定義します。 

1. プレフィックスの合計を事前計算して、間隔の合計が$\sum_{i=l}^r A_i$一定時間でクエリできます。 これが必要なのは、ノードの制約が間隔の合計にのみ依存するためです。 
2. 再帰的 DP 関数を定義する$dp(node, l, r)$、サブ配列を分割する有効な方法の数を意味します$[l, r]$正確に葉の数に換算します`node`、そのサブツリー内のすべての制約を尊重します。 
3. もし`node`葉、区間全体$[l, r]$は 1 つのセグメントを形成するため、有効な方法は 1 つだけです。 リーフには子がないため、このレベルでは制約は適用されません。 
4. もし`node`が内部である場合、そのリーフ セットを左右の子に分割します。 考えられるすべての分割ポイントを試します$t$そのような$l \le t < r$。 この選択により、左側の子が次の操作を実行することが決定されます。$[l, t]$そして右の子は$[t+1, r]$。 
5. 各スプリットポイントについて$t$、次のように計算します。$$dp(left, l, t) \times dp(right, t+1, r)$$ただし、制約が満たされている場合に限ります。$$\left| \sum_{i=l}^{t} A_i - \sum_{i=t+1}^{r} A_i \right| \le D$$6. すべての有効な分割ポイントの合計$t$入手する$dp(node, l, r)$。 
7. 最終的な答えは次のとおりです。$dp(root, 1, N)$、ルートはツリー全体に対応します。 

### なぜ効果があるのか

 各 DP 状態は、固定サブツリー間隔内のリーフ セグメントを定義するカット位置の選択に正確に対応します。 再帰では、すべてのサブツリーが連続した部分配列を使用し、ノードでのすべての分割が配列内の 1 つの分割点に正確に対応することが強制されます。 すべてのノード制約は固定間隔の合計にのみ依存するため、分割の有効性はより深い決定とは独立しており、部分問題は独立かつ乗算的なままになります。 これにより、構成が 2 回カウントされたり、有効な構成が除外されたりすることがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

MOD = 10**9 + 7

def solve():
    N, K, D = map(int, input().split())
    A = list(map(int, input().split()))

    # prefix sums
    pref = [0] * (N + 1)
    for i in range(N):
        pref[i + 1] = pref[i] + A[i]

    def seg_sum(l, r):
        return pref[r] - pref[l]

    # number of leaves in each node at each depth
    # we build structure explicitly: full binary tree
    size = 1 << (K - 1)

    # build tree nodes by index:
    # node 1 is root, children 2*i and 2*i+1
    # total nodes up to 2^K - 1
    max_nodes = (1 << K)

    from functools import lru_cache

    @lru_cache(None)
    def dp(node, l, r):
        # number of leaves under this node
        depth = (node.bit_length() - 1)
        # leaf nodes are those at depth K-1, but easier:
        # node index >= 2^(K-1) are leaves
        if node >= (1 << (K - 1)):
            return 1

        res = 0
        left_child = node * 2
        right_child = node * 2 + 1

        for t in range(l, r):
            if abs(seg_sum(l, t) - seg_sum(t, r)) <= D:
                res += dp(left_child, l, t) * dp(right_child, t, r)
        return res % MOD

    ans = dp(1, 0, N)
    print(ans % MOD)

if __name__ == "__main__":
    solve()
```この実装はペアのメモ化に依存しています$(node, l, r)$。 各状態は、固定間隔に適用される固定サブツリー構造を表します。 リーフの状態はノード インデックスの範囲によって検出されます。これは、ツリーが完全なバイナリ ヒープ表現であるため機能します。 

トランジションは、考えられるすべての分割ポイントを列挙し、プレフィックスの合計を使用して制約をチェックします。 乗算では、左右の独立したサブツリー構成が結合されます。 

よくある微妙な間違いは、異なる DP 状態の異なるノード間で同じ間隔を再利用できることを忘れていることです。そのため、効率化のためにメモ化が不可欠になります。

 ## 特殊なケース

 主なエッジケースは次のような場合です$D = 0$。 この場合、すべての内部ノードは、左右のサブツリーの合計が正確に等しい必要があります。 制約チェックは各分割点で厳密な等価フィルターになるため、DP は引き続き機能します。 分割によって等間隔の合計が生成されない場合、分割は直ちに破棄されます。 

もう一つのケースは次のような場合です。$K = 1$。 リーフは 1 つだけであるため、配列全体が 1 つのセグメントを形成する必要があります。 ルートもリーフ ノードであり、分割せずに 1 を返すため、DP はこれを正しく処理します。 

より微妙なケースは、複数の異なる分割構成により上位ノードでは同一の間隔合計が得られるが、下位レベルのパーティションでは異なる場合に発生します。 DP は、各状態が間隔だけでなくツリー内のノードにも関連付けられ、構造的に異なる分解が個別にカウントされるようにするため、それらを正しく区別します。
