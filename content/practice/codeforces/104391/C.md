 ## 解決策
 ## 問題の理解

 数直線上に区間の集合が与えられ、各区間は左端と右端を持つ「山」を表します。 ある間隔が完全に内側にある場合、その間隔は別の間隔の子とみなされます。これは、その左端点が小さくなく、右端点が大きくないことを意味します。 

この包含関係から、すべての間隔がその中に厳密に含まれるすべての間隔を指す有向構造を構築します。 インターバルのスコアは、そのインターバルから始まり、含まれる任意のインターバルに繰り返し移動する最長チェーンの長さとして定義されます。 間隔に他の間隔が含まれていない場合、そのスコアは 1 です。 

タスクは、間隔ごとにこのスコアを計算し、すべての間隔にわたる最大スコアを報告することです。 

入力サイズは 400,000 間隔に達し、座標は最大 10 億になります。 すべての間隔を他のすべての間隔と比較するソリューションは、最悪の場合、10^11 のオーダーで比較する必要があるため、直ちに除外されます。 ソートベースの O(n^2) 戦略や単純なグラフ構築でさえ、遅すぎます。 

構造も任意ではありません。 包含は単調条件の 2 つの座標のみに依存します。つまり、子は大きいか等しい左端点と小さいか等しい右端点を持たなければなりません。 これは 2 次元の支配関係であり、問​​題の本質は、部分的に順序付けられた平面内の点を効率的にクエリして更新することにあることを示唆しています。 

多くの間隔が同じ左端点を共有する場合、微妙なエッジ ケースが発生します。 その場合、包含は右側のエンドポイントのみに依存し、等左グループ内の依存関係が慎重に処理されない場合、単一の座標による単純な順序付けでは誤った結果が簡単に生成される可能性があります。 もう 1 つの特殊なケースは、深くネストされたチェーンです。この場合、答えが O(n) に達する可能性があり、慎重に順序付けしないと再帰が安全でなくなります。 

## アプローチ

 直接的なアプローチは、包含グラフを明示的に構築することです。 すべての間隔 i について、すべての間隔 j をチェックし、j が i 内にある場合はエッジを追加します。 次に、このグラフに対して DFS または DP を実行して、最長パスを計算します。 これは正しいです。スコアの定義はまさに有向非巡回グラフの最長パスであるからです。 問題は構築コストです。すべてのペアをチェックするには O(n^2) 個の比較が必要ですが、n が 400,000 の場合、これは制限をはるかに超えています。 

重要な点は、明示的なエッジが必要ないということです。 各間隔について、その中のすべての間隔の最大 dp 値を知る必要があるだけです。 これにより、問題は点の動的なセットに対する範囲クエリに変わります。ここで、各間隔は点 (L, R) であり、L_j ≥ L_i および R_j ≤ R_i であるすべての点をクエリしたいとします。 

これは二次元の支配問題です。 L を小さくして間隔を並べ替えると、間隔 i を処理する時点で、L が大きいすべての間隔がすでに処理されています。 残りの問題は、R に対する制約を効率的に処理することであり、これは、圧縮された R 座標に対するフェンウィック ツリーを使用するプレフィックス最大クエリに減らすことができます。 

ただし、区間が同じ L を共有する可能性があるため、L だけによる並べ替えでは十分ではありません。その場合、同じグループ内の区間は R の順序付けに基づいて相互に依存する可能性があります。 これにより、等しい L グループを個別に処理する必要が生じ、グローバル構造への更新をコミットする前にグループ内の遷移が正確であることが保証されます。

 | ブルート フォース ペア チェック + DP | O(n^2) | O(n^2) | 遅すぎる |
 | グループ化処理によるソートスイープ + BIT | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 このソリューションは、右のエンドポイントにわたって到達可能な最良の dp 値を維持しながら、左のエンドポイントの降順でスイープ間隔を設定することに依存しています。 

### 1. 右端点の座標圧縮

まず、すべての R 値をより小さい範囲に圧縮します。 フェンウィック ツリーには連続したインデックスが必要なため、これが必要になります。 圧縮により順序が維持されます。これが必要な唯一のプロパティです。 

### 2. L を減少させて間隔を並べ替えます

 すべての区間を L の降順に並べ替えます。L が大きい区間が先に処理され、区間を処理するときに、L が等しいものを除いて、L_j ≥ L_i を持つすべての可能な候補がすでに表示されていることが保証されます。 

これにより、依存関係のグローバルな方向性が確立されます。 

### 3. 等しい L のグループでの処理間隔

 同じ左端点を持つすべての間隔は一緒に処理されます。 このようなグループ内では、封じ込めは R 値のみに依存します。 区間 j の R が i より小さいか等しい場合、j は i の子になることができますが、その逆はできません。 

これは、グループ内で、小さい間隔が大きい間隔よりも前に計算されるように、R の昇順で処理する必要があることを意味します。 

### 4. 2 本のフェンウィック ツリーを維持する

 以前に処理されたすべてのグループの結果を保存するグローバル フェンウィック ツリーを使用します。 これは、厳密に大きな L 値を含むクエリに答えます。 

また、現在のグループ用に一時的なフェンウィック ツリーも維持します。 これは、同じ L を共有する間隔間の依存関係を処理します。 

グループ内の各区間 i について、その dp 値を 1 に 2 つの値の最大値を加えたものとして計算します。つまり、R ≤ R_i である以前に処理されたグループ内の最良の dp と、R ≤ R_i である同じグループ内の以前の要素の間の最良の dp です。 

これにより、考えられるすべての子が正しくキャプチャされます。 

### 5. 構造を更新する

 グループ全体の dp 値を計算した後、それらすべてをグローバル フェンウィック ツリーに挿入します。 これにより、将来のグループがそれらを使用できるようになります。 

### 6. グローバル最大値を追跡する

 dp 値を計算する際、確認された最大値を維持します。これが最終的な答えになります。 

### なぜ効果があるのか

 すべてのステップで、グローバル フェンウィック ツリーは、厳密に大きな L、完全に処理された固定 dp 値を持つすべての間隔を表します。 グループ フェンウィック ツリーは、R の増加順に並べられた現在の等しい L ブロックのプレフィックスを正確に表します。すべての有効な子リレーションシップは、これら 2 つのカテゴリのいずれかに正確に分類されるため、dp に寄与するすべての遷移が 1 回だけ考慮され、無効な遷移が導入されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def update(self, i, v):
        while i <= self.n:
            if v > self.bit[i]:
                self.bit[i] = v
            i += i & -i

    def query(self, i):
        res = 0
        while i > 0:
            if self.bit[i] > res:
                res = self.bit[i]
            i -= i & -i
        return res

def main():
    n = int(input())
    seg = []
    rs = []

    for idx in range(n):
        l, r = map(int, input().split())
        seg.append((l, r, idx))
        rs.append(r)

    rs = sorted(set(rs))
    rid = {v: i + 1 for i, v in enumerate(rs)}

    seg.sort(key=lambda x: (-x[0], x[1]))

    fw_global = Fenwick(len(rs))
    dp = [0] * n

    i = 0
    ans = 0

    while i < n:
        j = i
        curL = seg[i][0]

        group = []
        while j < n and seg[j][0] == curL:
            group.append(seg[j])
            j += 1

        group.sort(key=lambda x: x[1])

        fw_local = Fenwick(len(rs))

        for l, r, idx in group:
            ri = rid[r]
            best = fw_global.query(ri)
            best = max(best, fw_local.query(ri))
            dp[idx] = best + 1
            fw_local.update(ri, dp[idx])

        for l, r, idx in group:
            fw_global.update(rid[r], dp[idx])
            if dp[idx] > ans:
                ans = dp[idx]

        i = j

    print(ans)
    print(*dp)

if __name__ == "__main__":
    main()
```フェンウィック ツリーは、圧縮された右エンドポイント上のプレフィックス最大構造として使用されます。 グローバル構造は、すでに処理された左側のエンドポイントからの結果を蓄積しますが、ローカル構造は、現在の等しい L グループ内の依存関係を解決します。 dp 遷移は常に「最適な囲み間隔 + 1」であり、プレフィックス クエリによって実装されます。 

ソート順序は重要です。L を減らすと、グローバルな依存関係の正しい方向が確保され、グループ内の R を増やすと、同じ L の包含が正確になります。 

## 実用的な例

 ### サンプル 1

 入力間隔は次のとおりです。 

(9,13)、(11,13)、(7,11)、(1,9)、(2,6)、(3,8)、(6,7)

 L を減少させてソートした後、処理は (11,13) から始まり、次に (9,13) というように続きます。 

(11,13) の場合、これより大きい L 間隔は存在しないため、dp = 1 になります。 

(9,13) の場合、グローバル構造内に (11,13) が表示されますが、11 ≥ 9 および 13 ≤ 13 であるため、これを拡張して dp = 2 を与えることができます。 

このプロセスを続けると、(1,9) → (2,6) → (6,7) という最も深いネスト チェーンが形成され、間隔 (9,13) で最大深さ 3 が生成されます。 

最終的な dp 値は予想される出力と一致します。 

2 1 1 3 1 2 1

 トレースにより、有効なコンテインメント遷移のみが dp の増加に寄与し、無関係な間隔間で相互干渉が発生しないことが確認されます。 

### サンプル 2

 間隔:

 (1,3)、(1,6)、(1,5)、(1,1000)、(1,4)

 すべての間隔は同じ L を共有するため、すべてが 1 つのグループ内で解決されます。 

R で並べ替えると次のようになります。 

(1,3)、(1,4)、(1,5)、(1,6)、(1,1000)

 Rの小さいものから順に加工していきます。 各間隔では、より小さいすべての間隔が潜在的な子として認識されます。 これにより、dp 値が増加する連鎖が作成されます。 

dp(1,3)=1

 dp(1,4)=2

 dp(1,5)=3

 dp(1,6)=4

 dp(1,1000)=5

 この例では、グループ内処理の重要性を分離します。 これがないと、等しい L 依存関係が完全に失われます。

## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての間隔が同じ左端点を共有する場合です。 この場合、答え全体は正しいエンドポイントによる順序付けのみに依存します。 このアルゴリズムは、R でグループを並べ替え、ローカルのフェンウィック ツリーを使用することでこれを正しく処理し、各間隔がより小さい間隔に基づいて構築されるようにします。 

別のエッジ ケースは、[1,10]、[2,9]、[3,8]、[4,7] のようなネスト チェーンを厳密に増加させることです。 ここで、各間隔は前の間隔に依存します。 グローバル フェンウィック ツリーは、dp 値を正しく伝播します。これは、各間隔がすべての大きな L 間隔の後に処理されるため、チェーンが増分的に再構築されるためです。 

3 番目のエッジ ケースには、[1,2]、[3,4]、[5,6] などの互いに素な間隔が含まれます。 どれにも別のものが含まれていないため、すべての dp 値は 1 のままです。Fenwick クエリは一貫して 0 を返し、重複していない領域間での偶発的な伝播を防ぎます。
