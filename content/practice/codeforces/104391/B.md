 ## 解決策
 ## 問題の理解

 私たちは果物のコレクションを与えられました。 各果物には重量があり、最大 19 種類の毒についての説明が付いています。 毒の種類ごとに、果物にはその毒が含まれているか、その解毒剤が含まれているか、どちらも含まれていないかのいずれかになります。 重要なのは、同じレシピの果物に毒とその解毒剤の両方が含まれることはありません。 

インタラクションは 2 つのフェーズで発生します。 まず、最初に食べる果物を選択します。 毒レシピが含まれている場合、それらはアクティブな毒状態になります。 同じ果物に含まれる解毒剤は、現時点ではまったく役に立ちません。 

その後もノンウムは果物を食べ続ける。 次の各果物は、現在有効なすべての毒レシピに対する解毒剤が含まれている場合にのみ食べることができます。 そのような果物を食べると、解毒剤が適用され、現在の毒状態はすぐに解消されますが、持続しません。 同じ果物にも新しい毒が導入された場合、解毒ステップが解決された後、その新しい毒は新しい活性状態になり、さらに食べることを強制される可能性があります。 

最終的には、何らかの順序で果物を摂取した後に、毒が作用しなくなる状況に到達することが目標となります。 総コストは、最初に毒を入れた果物の後に食べたすべての果物の重量の合計です。 最初の果物は、少なくとも 1 つの毒を含むすべての果物の中から Nu-Kee によって選択され、彼女は可能な限り最大の最小回復コストを強制しようとします。 その後、Non-Um は追加の消費を最小限に抑えるために最適にプレイします。 

果物に毒が含まれていない場合、答えは単純にゼロになります。 

主な困難は、ポイズン状態が最大 19 個のレシピのサブセットであるため、ビットマスクとして表現できるという事実にあります。 これは、最大 2^19 の状態にわたる状態グラフを即座に示唆します。 

制約は大きく、果物は最大 80,000 個、毒状態の可能性は最大 2^19 です。 これにより、単純な方法でフルーツごと、状態ごとの遷移を直接シミュレートしようとするソリューションは除外されます。 どのソリューションでも、ビットマスクのサブセット全体で遷移を効率的に集約する必要があります。 

微妙なエッジケースは、果物に毒が導入されており、将来の要件と部分的に重なる解毒剤も含まれている場合です。 もう1つは、果物に毒がない場合で、これは最終的な回復オプションとして効果的に機能します。 

## アプローチ

 強引な解釈では、すべての状態が活性毒のビットマスクとして扱われます。 状態 S から、互換性のあるすべての果物 f を試します。これは、S が f の解毒マスクのサブセットであることを意味します。 互換性がある場合、f のポイズン マスクに等しい新しい状態に移行し、コスト w_f を支払います。 各初期状態から最短パスを実行すると、答えが得られます。 

これは正しいですが、まったく実行不可能です。 各状態には最大 N 個の送信チェックがあり、2^19 個の状態があるため、約 80,000 × 524,288 の操作が必要となり、これは大きすぎます。 

重要な観察は、遷移が果物ごとに 2 つのマスク (毒マスク P_f と解毒マスク A_f) にのみ依存することです。 P_f からのフルーツの最良の継続コストが分かると、任意の状態 S へのその寄与は S ⊆ A_f かどうかの関数になります。 これにより、問題はすべてのフルーツに対する反復クエリに変換されます。各状態 S について、(w_f + dp[P_f]) の S ⊆ A_f を満たすすべてのフルーツに対する最小値が必要です。 

これは、ビットマスク上の古典的なスーパーセット-サブセット DP 構造です。 すべての解毒剤マスク A について最良のフルーツ値を維持できれば、S のスーパーセットに対するクエリは標準の SOS DP で答えることができます。 難しいのは、dp[P_f] が計算中に変化するため、値を動的に更新する必要があることです。

これは、状態に対してダイクストラを実行することで解決されます。 状態が確定するたびに、dp[S] は固定されます。 次に、毒マスクが S であるすべての果物を更新し、それらの寄与 w_f + dp[S] を再計算し、更新された値を解毒マスクによってインデックス付けされた構造にプッシュします。 これにより、解毒マスクをめぐる世界的な構造を維持し、各州の「最も相性の良い果物」の質問に答えることができます。 

これにより、フルーツ全体にわたる集約された遷移が注意深く維持された 2^S 状態にわたるグラフ検索が行われます。

 ## アルゴリズムのチュートリアル

 各毒/解毒剤の構成を長さ S のビットマスクとして表します。 

### 1. マスクの事前計算

 果物ごとに次のように計算します。 

- P_f: 毒ビットマスク
 - A_f: 解毒剤ビットマスク
 - w_f: 重量

 P_f = 0 のフルーツは、潜在的な終端状態として特別に処理されます。 

### 2. 状態の定義

 dp[S] を、毒状態 S から完全に回復するために必要な最小合計追加重量として定義します。 

私たちの目標は、すべての S について dp[S] を計算し、以下を評価することです。 

P_f ≠ 0 である各果物 f について、候補解答 = dp[P_f] とし、そのようなすべての果物の最大値を取得します。 

### 3. 逆依存構造

 各 dp[S] はフルーツを介した遷移に依存します。 

dp[S] = (w_f + dp[P_f]) の S ⊆ A_f を持つフルーツ f の分。 

したがって、各フルーツは dp[P_f] に依存する値を提供し、A_f のサブセットであるすべての状態 S に適用されます。 

### 4. 州に対するダイクストラ

 状態 S に対して最短パス プロセスを実行します。 

- dp[S] = ∞を初期化します。 
- 「すでに完全に回復した」状況に対応するすべての S から開始します (P_f = 0 のフルーツまたは空の状態に至る遷移によって処理されます)。 
- 状態を超えて優先キューを使用します。 

状態 S が確定すると、P_f = S となるすべてのフルーツ f を処理します。そのような各フルーツについて、dp[P_f] がわかったので、その寄与値を計算します。 

val_f = w_f + dp[S]。 

次に、このフルーツを、解毒マスク A_f によってインデックス付けされた構造に挿入または更新します。 

### 5. 解毒剤マスクに対するクエリメカニズム

 配列 best[A] を維持し、解毒剤マスクが正確に A である果物の中で最小の val_f を格納します。 

状態 S に答えるには、次のものが必要です。 

best[A] のすべての A ⊇ S に対する最小値。 

これはビットマスクに対するスーパーセット クエリであり、ベストに対する標準の SOS DP 前処理を使用して応答されます。 

更新の各バッチの後、クエリが有効なままになるように、スーパーセット DP を再構築するか増分的に維持します。 

### 6. 回答の抽出

 P_f ≠ 0 の各初期フルーツ f のコストは dp[P_f] です。 Nu-Kee はそのような最悪の果物を選択するため、最大の dp[P_f] を採用します。 

果物に毒がない場合、出力は 0 になります。 

## なぜ機能するのか

 このアルゴリズムは、決定を 2 つの層 (毒の状態遷移のグローバル構造と、解毒剤によって課されるローカルな互換性制約) に分離します。 すべてのフルーツは厳密に 1 つの遷移ルール​​に寄与し、そのルールはサブセットの包含によって定義される状態のファミリー全体に均一に適用されます。 DP は、状態の最適な回収コストが一度固定されると、再び改善されないことを保証するため、フルーツの寄与が安定し、スーパーセット構造を通じて正しく伝播されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

INF = 10**30

def solve():
    n, s = map(int, input().split())
    
    fruits = []
    has_poison = False

    for _ in range(n):
        tmp = list(map(int, input().split()))
        w = tmp[0]
        p_mask = 0
        a_mask = 0
        for i in range(s):
            if tmp[i+1] == -1:
                p_mask |= (1 << i)
            elif tmp[i+1] == 1:
                a_mask |= (1 << i)
        fruits.append((w, p_mask, a_mask))
        if p_mask:
            has_poison = True

    if not has_poison:
        print(0)
        return

    # dp over poison states
    N = 1 << s
    dp = [INF] * N
    dp[0] = 0

    # bucket fruits by poison mask
    by_p = [[] for _ in range(N)]
    for w, p, a in fruits:
        by_p[p].append((w, a))

    # best[A] = best value among fruits with antidote mask A
    best = [INF] * N

    # helper: rebuild superset DP
    def rebuild():
        # copy best and do SOS over supersets
        f = best[:]
        for i in range(s):
            bit = 1 << i
            for mask in range(N):
                if mask & bit:
                    f[mask ^ bit] = min(f[mask ^ bit], f[mask])
        return f

    pq = [(0, 0)]
    vis = [False] * N

    while pq:
        d, mask = heapq.heappop(pq)
        if vis[mask]:
            continue
        vis[mask] = True
        dp[mask] = d

        # update fruits with this poison mask resolved
        for w, a in by_p[mask]:
            val = w + d
            if val < best[a]:
                best[a] = val

        # rebuild structure (simple but safe for constraints S<=19)
        sup = rebuild()

        # try to relax all states
        for nxt in range(N):
            if vis[nxt]:
                continue
            # check if any fruit can serve nxt
            if sup[nxt] < INF:
                if sup[nxt] < dp[nxt]:
                    dp[nxt] = sup[nxt]
                    heapq.heappush(pq, (dp[nxt], nxt))

    ans = 0
    for w, p, a in fruits:
        if p:
            ans = max(ans, dp[p])

    print(ans)

if __name__ == "__main__":
    solve()

 ## 特殊なケース

 重要なエッジケースは、果物に毒と解毒剤の両方が含まれている場合です。 その場合、解毒剤が現在の状態を除去した後、その毒を新しい状態として扱う必要があります。これにより、すぐに連鎖させても安全であると誤って判断するのを防ぐことができます。 遷移では貪欲なローカル決定ではなく、常に明示的な状態変更が行われるため、DP 定式化はこれを処理します。 

もう 1 つのエッジケースは、複数の果物が同じ解毒マスクを共有しているが、毒の結果が異なる場合です。 このアルゴリズムは、解毒剤マスクあたりの最良のコストのみを維持しながら、dp[P_f] を通じて毒の状態を区別することで、それらを正しく集計します。
