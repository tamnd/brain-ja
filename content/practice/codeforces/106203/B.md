 ## 解決策
 ## 問題の理解

 次の三角配列が与えられます。`n`行。 行`i`正確に含まれています`i`整数。 このプロセスは上の行から開始され、下の行だけが残るまで繰り返し 1 つずつ行を破棄します。 

価値のあるクリスタルの場合`x`が削除されると、そのすぐ下の 2 つのクリスタルのうち大きい方が選択されます。 左の子に value があるとします。`a`そして正しい子供には価値がある`b`。 もし`a > b`、左の子は に変わります。`a - x`。 それ以外の場合は、右側の子が次のように変更されます。`b - x`。 もう一人の子は変わらず。 

最後の行を除くすべての行が消えたら、一番下の行のクリスタルの値を出力する必要があります。 

三角形の中に含まれるのは、$$1+2+\dots+n=\frac{n(n+1)}2$$数字。 以来`n ≤ 1000`、要素の総数は最大 500500 です。各クリスタルを一定の回数処理するアルゴリズムは、簡単に十分に高速です。 セル数の二次というのはおおよその意味です$2.5 \times 10^{11}$限界をはるかに超えた操作。 

微妙な点は、クリスタルはその子の 1 つを即座に変更し、その後の決定では元の値ではなく更新された値を使用する必要があることです。 

考慮する```
2
5
1 10
```トップクリスタルが選ぶ`10`、 以来`1 ≤ 10`に変更します。`10-5=5`。 

答えは```
1 5
```元の値をどこでも使用すると、間違った結果が生成されます。 

ミスのもう 1 つの原因は、同点の場合です。 値が等しい場合は、左側の子は選択されません。 

のために```
2
3
7 7
```状態`a ≤ b`が適用されるため、適切なクリスタルは次のようになります。`7-3=4`。 

正しい答えは、```
7 4
```使用する`>=`の代わりに`>`左側のクリスタルを誤って変更してしまう可能性があります。 

負の数も重要です。```
2
-5
2 1
```以来`2 > 1`、左側のクリスタルが選択され、$$2-(-5)=7.$$答えは```
7 1
```間違った順序で減算すると、`-7`。 

## アプローチ

 最も直接的なアイデアは、説明どおりに儀式を正確にシミュレートすることです。 最初の行から始めて、各結晶を調べて、その下の 2 つの値を比較します。 どちらが大きいかに応じて、その子をすぐに変更します。 

最後の行を除くすべての結晶が 1 回処理されるため、このシミュレーションはすでに効率的です。 処理されたセルの総数は次のとおりです$$1+2+\dots+(n-1)=\frac{n(n-1)}2,$$これは、約 50 万回の操作に相当します。`n=1000`。 

エネルギーが流れる経路を追跡したり、再帰的にたどったりする、より複雑なアプローチを想像する人もいるかもしれません。 各クリスタルには 2 つの選択肢がある可能性があるため、すべての可能なパスに対するこのような強引な攻撃は指数関数的になります。 幸いなことに、プロセス自体が選択を一意に決定し、各クリスタルは 1 人の子供にのみ影響します。 後戻りは必要ありません。 

重要な点は、三角形をその場で簡単に更新できるということです。 1行`i`加工されているため、再度使用されることはありません。 今後のすべての決定は、行内のすでに更新された値のみに依存します。`i+1`。 これにより、補助構造を使用せずに値を直接上書きできます。

 | 考えられるすべてのパスを列挙する | O(2^n) | O(n) | 遅すぎる |
 | インプレイスシミュレーション | O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 三角形全体を 2 次元配列に読み取ります。 
2. 行を上から下に処理します。 行`i`行に影響を与える`i+1`なので、列を終えた後`i`もう二度と必要ありません。 
3. ポジションごとに`j`並んで`i`、 させて`x`そのクリスタルの現在値になります。 
4. 二人の子供を比べてください。`triangle[i+1][j]`そして`triangle[i+1][j+1]`。 
5. 左の子の方が厳密に大きい場合は、次のように置き換えます。$$\text{left}-x.$$それ以外の場合は、右側の子を次のように置き換えます。$$\text{right}-x.$$同じ行の前のクリスタルによってすでに値が変更されている可能性があるため、比較では現在の値を使用する必要があります。 

1. 最後から 2 番目の行が処理されるまで続行します。 
2. 最後の行を出力します。 

### なぜ効果があるのか

 行の処理後`i`、列状の結晶によって引き起こされるあらゆる変化`0,1,\dots,i`すでに行に組み込まれています`i+1`。 今後の操作は以前の行に影響を与えることはできません。 

不変条件は、行を開始する前です。`i`、その上のすべての行はルールに従ってすでに完全に破棄されており、行`i`儀式のその瞬間に存在するであろう価値観が含まれています。 各クリスタルの処理ではステートメントとまったく同じ操作が適用されるため、不変条件は true のままです。 最後から 2 番目の行が終了すると、一番下の行には正確に最終エネルギーが含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
triangle = [list(map(int, input().split())) for _ in range(n)]

for i in range(n - 1):
    for j in range(i + 1):
        x = triangle[i][j]
        if triangle[i + 1][j] > triangle[i + 1][j + 1]:
            triangle[i + 1][j] -= x
        else:
            triangle[i + 1][j + 1] -= x

print(*triangle[-1])
```三角形は、入力に表示されるとおりに正確に保存されます。 後の計算では常に更新された値が必要となるため、配列を適切に変更するのは自然なことです。 

外側のループは行を上から下に処理します。 行`i`含まれています`i+1`要素があるため、内側のループはそれらすべてを実行します。 

比較には、`>`そしてそうではありません`>=`。 ステートメントでは左側の子が厳密に大きい場合にのみ指定されるため、等しい値では右側の子を選択する必要があります。 

Python の整数は大きな値を自動的に処理するため、オーバーフローは問題になりません。 別の言語の固定サイズの整数では、64 ビット型が必要になります。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    triangle = [list(map(int, input().split())) for _ in range(n)]

    for i in range(n - 1):
        for j in range(i + 1):
            x = triangle[i][j]
            if triangle[i + 1][j] > triangle[i + 1][j + 1]:
                triangle[i + 1][j] -= x
            else:
                triangle[i + 1][j + 1] -= x

    return " ".join(map(str, triangle[-1]))

# minimum size
assert run("1\n7\n") == "7"

# equal values, right child must be chosen
assert run("2\n3\n7 7\n") == "7 4"

# negative top value
assert run("2\n-5\n2 1\n") == "7 1"

# simple chain
assert run("3\n1\n2 3\n4 5 6\n") == "4 2 3"

# all equal values
assert run("3\n1\n1 1\n1 1 1\n") == "1 0 -1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 7`|`7`| 最小サイズ |
 |`2 / 3 / 7 7`|`7 4`| タイは右の子に行きます |
 |`2 / -5 / 2 1`|`7 1`| 負の値の正しい処理 |
 |`3 / 1 / 2 3 / 4 5 6`|`4 2 3`| 通常の伝播 |
 | すべてのもの |`1 0 -1`| 複数の提携と繰り返しのアップデート |
