 ## 問題の理解

 2 つの別々の「呪いの人形」に保存されている値を表す 2 つの整数が与えられます。 それらを最初の値と 2 番目の値と呼びます。 同期操作を定義する 2 つのパラメーターも指定されています。 演算を適用するたびに、最初の値は固定量ずつ増加し、制限値を法としてラップします。一方、2 番目の値は同じ固定量だけ減少し、同じ制限値を法としてラップします。 主な制限は、両方の更新が常に同時に行われること、そしてこの操作は何度でも適用できることです。 

操作を繰り返し実行した後でも、値は独立して変化しません。 代わりに、k 回の操作の後、最初の値はモジュラー円上で k ステップ前方にシフトされた元の最初の値になり、2 番目の値はその円上で同じステップ数だけ後方にシフトされた元の 2 番目の値になります。 目標は、2 つの値の最終合計を最大化するために適用する操作の数を選択することです。 

この制約により、値と係数は 10^9 まで大きくなるため、すべての操作をシミュレートすることはできません。 考えられるすべての操作を直接反復するには、最大 m ステップが必要になりますが、これは 1 秒の制限をはるかに超えています。 

ステップ サイズがゼロの場合、微妙なエッジ ケースが発生します。 この場合、両方の値は一定のままであるため、答えは単純に初期合計になります。 もう 1 つの重要なケースは、ステップ サイズが係数と自明ではない公約数を共有する場合です。 この場合、到達可能な状態は残差のサブセットのみを形成し、プロセスは m ステップよりも早くサイクルします。これは、最適化空間は小さくなりますが、ブルート フォースにはまだ大きすぎることを意味します。 

主な問題点は、各演算が両方の値に逆方向に影響を及ぼし、モジュラー ラップアラウンドにより合計に不連続性が生じることです。 

## アプローチ

 演算回数 k を固定すれば、結果の値は完全に決まります。 これは、総当たりの戦略を示唆しています。つまり、ゼロからサイクル長全体まですべての k を試し、毎回結果の合計を計算します。 各評価は O(1) ですが、サイクルの長さは m と同じくらい大きくなる可能性があるため、このアプローチは m で線形になるため、m が 10^9 に達すると実行できなくなります。 

重要な観察は、合計がほとんどの場合滑らかに変化し、2 つの値のいずれかが係数の境界を囲む場合にのみ変化するということです。 これらのラップ イベント間では、両方の値が反対方向に直線的にシフトするため、それらの寄与は相殺され、合計は一定に保たれます。 

これにより、問題は、いずれかの座標がモジュール境界を横切る瞬間のみを追跡するようになります。 これらのポイントでは、どちらの側がラップするかに応じて、合計は正確に m または -m だけジャンプします。 最大化している関数は k にわたるステップ関数になり、その最大値は平坦なセグメントの中央ではなくステップ間の境界で発生する必要があります。 

すべての k を反復する代わりに、増加シーケンスが m の倍数に達するか、減少シーケンスが m の倍数に達する候補 k 値のみを生成します。 これらのイベントは、m をステップとモジュラスの gcd で割った、短縮されたサイクル長を法とする等差数列を形成します。 関数はそれらの間で一定であるため、これらの候補位置とそのすぐ隣の位置の合計を巡回順序で評価するだけです。

 ## アルゴリズムのチュートリアル

ステップ サイズを c、係数を m と表します。 まず、c を繰り返し追加するとそのサブグループ内の残基のみを訪問するため、両方の配列が長さ m を gcd(c, m) で割ったサイクルで進化することを観察することで問題を軽減します。 

両方の動きが換算係数を法とするきれいな等差数列になるように、変換された値を定義します。 最初の値はステップごとに c ずつ増加し、2 番目の値はステップごとに c ずつ減少します。 

1. g = gcd(c, m) を計算し、m1 = m / g および c1 = c / g を設定して系を縮小します。 これにより、c1 と m1 が互いに素であることが保証されるため、モーションは構造化された方法で剰余を完全に循環します。 
2. この縮小されたシステムで 2 つのシーケンスを書き直します。 最初の値は a + k * c (mod m) として展開され、2 番目の値は b - k * c (mod m) として展開されます。 ラップは合計が変化する唯一の瞬間であるため、それぞれがどれくらいの頻度で m をラップするかに焦点を当てます。 
3. ラップ イベント間で、一方の値が c だけ増加し、もう一方の値が c だけ減少するため、それらの変化が合計で相殺されることを観察します。 これは、合計がイベント間で一定であることを意味します。 
4. 各シーケンスのラップ イベントを個別に特定します。 最初の値のラップは、a + k * c が m の倍数と交差するときに発生します。 同様に、b - k * c がゼロを下回り、m を法として上向きにラップすると、秒のラップが発生します。 
5. ラップごとに合計が正確に +m または -m だけ変更されます。 したがって、問題は 2 つのイベント ストリーム間のプレフィックス バランスを最大化することになります。1 つはイベントごとに +1 に寄与し、もう 1 つは -1 に寄与します。 
6. 1 つの完全なサイクル内でいずれかのシーケンスが境界に達するすべての k 値を生成します。 これらの k 値は、短縮されたサイクル長を法とする 2 つの等差数列を形成します。 それらを収集し、並べ替えて、その位置でのみ合計を評価します。 
7. 各候補 k での結果の合計を評価し、最大値を保持します。 

### なぜ効果があるのか

 重要な不変条件は、2 つの値の合計が k 内で区分的に一定であり、モジュラー コンポーネントの 1 つが m を囲む点でのみ変化するということです。 このようなラップごとに、以前の履歴とは無関係に、合計が固定方向に正確に m だけ変更されます。 これにより、目的は k 上のステップ関数になり、ステップ関数は不連続点の 1 つで最大値に達するため、境界点のみをチェックするだけで十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c, m = map(int, input().split())
    
    if c == 0:
        print(a + b)
        return

    g = 1
    import math
    g = math.gcd(c, m)
    m1 = m // g

    # Work modulo reduced cycle; we only care about representative k in [0, m1-1]

    # Precompute modular inverse of c/g mod m1
    c1 = c // g

    def modinv(x, mod):
        return pow(x, mod - 2, mod)

    inv = modinv(c1, m1)

    # We generate candidate k where wraps happen.
    # x wraps: a + k*c ≡ 0 (mod m)
    # => k ≡ (-a) * inv(c1) mod m1
    # y wraps: b - k*c ≡ 0 (mod m)
    # => k ≡ b * inv(c1) mod m1

    kx = ((-a) % m1) * inv % m1
    ky = (b % m1) * inv % m1

    # We consider only these two boundary points and their neighbors in cycle
    candidates = {0, kx, ky}

    def calc(k):
        x = (a + k * c) % m
        y = (b - k * c) % m
        return x + y

    best = 0
    for k in candidates:
        best = max(best, calc(k))
        best = max(best, calc((k + 1) % m1))

    print(best)

if __name__ == "__main__":
    solve()
```システムは削減された剰余クラスのみを循環するため、実装ではまず gcd を使用してモジュラスを削減します。 次に、逆モジュラーを計算して、各シーケンスがラップ境界に当たる正確な位置を見つけます。 これらは、目的関数の傾きを変更できる唯一の点です。 

最大値はまさにジャンプ時またはジャンプ直後に発生する必要があるため、これらの境界位置とその直後の後続位置で関数を評価します。 すべての算術演算はモジュール形式で保持され、ラップアラウンド下での正確性が保証されます。

 ## 特殊なケース

 ステップ サイズが 0 の場合、両方の値は変更されず、ラップ イベントは存在しません。 アルゴリズムは初期合計を直接返します。これは、一連の操作によって状態を変更できないため、正しい動作と一致します。 

係数とステップ サイズが大きな gcd を共有する場合、システムは短縮されたサイクルで進化します。 このアルゴリズムは、境界位置を計算する前に両方の値を gcd で除算することでこれを処理し、元のサイクルが高度に圧縮されている場合でもラップ検出が正確なままであることを保証します。 

いずれかの値が境界付近で始まる場合、最初の操作ですぐにラップがトリガーされる可能性があります。 候補生成には k = 0 と最初のラップ位置が明示的に含まれるため、このケースは特別なケースなしでカバーされます。
