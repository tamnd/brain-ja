 ## 問題の理解

 ソース文字列が与えられます`s`および 2 つのターゲット文字列`t1`そして`t2`全長が等しい`|s|`。 タスクは分割することです`s`選択した位置でカットして、一連の連続した部分に分割します。 切断後、これらの部分を左から右にスキャンし、各部分を 2 つのアキュムレータの 1 つに完全に割り当てます。`a`または`b`。 ピースの順序は保持されますが、各ピースは分割できず、完全にどちらかに配置される必要があります。`a`または`b`。 結局のところ、私たちが望んでいるのは、`a`まさになる`t1`そして`b`まさになる`t2`。 目標は、削減の数を最小限に抑えることです。`s`。 

カットはピースの境界を定義します。 と`k`カット、取得します`k+1`個。 次に、各ピースが建物の構築に貢献するかどうかを選択します`t1`または`t2`、各ターゲット文字列内の相対的な順序が維持されます。 

制約により許可されるのは、`|s|`まで`10^4`、したがって、周りの解決策`O(n^2)`はすでに限界に達しており、立体的なものは不可能です。 ただし、実際の構造は、セグメンテーションの数が指数関数的に増加するため、パーティションを明示的に列挙することは避けたいことを示唆しています。 

文字が繰り返される場合、微妙な問題が発生します。 両方に同じキャラクターが登場する場合`t1`そして`t2`、単一文字の貪欲な割り当てや単純なマッチングは失敗する可能性があります。これは、決定がローカルの文字マッチングではなく、セグメント全体の将来の互換性に依存するためです。 

2 番目の重要な状況は、最適なソリューションが分離を遅らせる必要がある場合に発生します。 カットが早すぎると、たとえもう少し大きなピースでも機能するにもかかわらず、一貫して割り当てることができないピースを無理に配置する可能性があります。 

## アプローチ

 直接的なアプローチは、セグメンテーションの観点から考えることです。あらゆる方法で分割を試みます。`s`連続したブロックに分割し、分割ごとにブロックを割り当ててみます。`t1`または`t2`秩序を保ちながら。 これは、カット位置を次から選択することに相当します。`n-1`ギャップを調べてから、ブロックの双方向インターリーブによって両方のターゲット文字列を再構築できるかどうかを確認します。 

固定セグメンテーションをチェックする場合でも、ブロックのシーケンスが一致するように貪欲に割り当てられるかどうかを検証する必要があります。`t1`そして`t2`, そのため、完全な総当たりのカット数は指数関数的に増加します。 カットにキャップを付けてパーティションにまたがる動的プログラミングを試みたとしても、各カットが両方の文字列の将来の一致制約を同時に変更するため、状態空間はすぐに実行不可能になります。 

重要な観察は、問題は任意のパーティションに関するものではなく、決定論的な割り当てが可能な最大ストレッチのグループ化に関するものであるということです。 各ポジションの割り当てを決定したら、`s`どちらかに`t1`または`t2`、カットが必要な唯一の理由は、隣接する位置が存在する場合です。`s`さまざまなターゲットに行きます。 ただし、私たちは独立してポジションを割り当てる自由はありません。 割り当てでは、各ターゲット文字列内の文字の順序が尊重される必要があります。 

これは、問題をインターリーブ方法の選択として再構成することを示唆しています。`t1`そして`t2`形成する`s`から文字を取得する間のスイッチの数を最小限に抑えながら、`t1`そしてから`t2`。 各スイッチは、元の文字列表現のカットに正確に対応します。

 ## アルゴリズムのチュートリアル

 建物をシミュレーションする DP を定義します。`s`左から右へ、どれだけの量を消費したかを追跡しながら、`t1`そして`t2`。 重要なのは、その位置です。`s`ステップでであるため、暗黙的です`k`私たちは一致しなければなりません`s[k]`。 

1. DP テーブルを作成します`dp[i][j][p]`、 どこ`i`から使用した文字数です`t1`、`j`から`t2`、 そして`p`最後に取得した文字がどこから来たのかを示します`t1`または`t2`。 これは、プレフィックスを形成するために各ターゲットがどれだけ消費されたかを正確にエンコードします。`s`。 
2. 文字が使用されていない開始状態から DP を初期化し、最初の文字について両方の可能性を試します。`s`。 もし`s[0] == t1[0]`、から始めることができます`t1`、同様に`t2`。 最初のセグメントはカットされないため、これは重要です。 
3. 各州について、次の文字を考慮して建設を延長することを検討します。`s`どちらからでも`t1`または`t2`、次の文字が一致する場合。 前のステップと同じソースから続行する場合は、カットを追加しません。 それ以外の場合は、カット数を 1 つ増やします。 
4. 可能な限りすべてのことを繰り返します`(i, j)`合計の進行状況が昇順にある状態`i + j`、各遷移はちょうど 1 文字を消費するため、`s`。 
5. 答えは、次のすべての状態の最小値です。`i + j = |s|`そして`(i, j)`マッチ`(len(t1), len(t2))`、考えられる最後のソースの両方を考慮します。 

重要な点は、キャラクターの取得を切り替えるたびに、`t1`そして`t2`では、元の文字列セグメント化に効果的なカットが導入されています。 

### なぜ効果があるのか

 DP は、すべての有効なインターリーブをエンコードします。`t1`そして`t2`それが形成する`s`そして、そのようなすべてのインターリーブは、次のセグメント化に一意に対応します。`s`ここで、同一のソース選択の最大の実行が 1 つの部分を形成します。 あらゆるカットは、ソースが変化するトランジションに帰着します。 DP はソース間のトランジションを最小限に抑えるため、カット数を直接的に最小限に抑えます。 有効な割り当ては各ターゲット文字列内の文字順序を尊重する必要があり、これは 2 ポインター消費構造によって厳密に強制されるため、このモデルの外にセグメンテーションは存在できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t1 = input().strip()
    t2 = input().strip()

    n = len(s)
    n1 = len(t1)
    n2 = len(t2)

    INF = 10**9

    # dp[i][j][p] = min cuts, p=0 from t1, p=1 from t2
    dp = [[[INF] * 2 for _ in range(n2 + 1)] for _ in range(n1 + 1)]

    # initialize
    if n1 > 0 and s[0] == t1[0]:
        dp[1][0][0] = 0
    if n2 > 0 and s[0] == t2[0]:
        dp[0][1][1] = 0

    for i in range(n1 + 1):
        for j in range(n2 + 1):
            for p in range(2):
                cur = dp[i][j][p]
                if cur == INF:
                    continue
                k = i + j
                if k == n:
                    continue
                if i < n1 and s[k] == t1[i]:
                    cost = cur + (0 if p == 0 else 1)
                    if cost < dp[i + 1][j][0]:
                        dp[i + 1][j][0] = cost
                if j < n2 and s[k] == t2[j]:
                    cost = cur + (0 if p == 1 else 1)
                    if cost < dp[i][j + 1][1]:
                        dp[i][j + 1][1] = cost

    ans = min(dp[n1][n2][0], dp[n1][n2][1])
    print(ans)

if __name__ == "__main__":
    solve()
```DP は、各ターゲット文字列のすでに消費された文字数によってインデックスが付けられます。 における暗黙の位置`s`いつもです`i + j`これにより、3 つの文字列すべての間の同期が保証されます。 状態遷移は次のいずれかに拡張されます。`t1`または`t2`、ソースを切り替えるとコストが増加しますが、これはまさに新しいカット境界を導入することに相当します。 

微妙な点は初期化です。どちらからでも開始できます。`t1`または`t2`カットはピース間に定義されており、最初のピースは常にフリーであるため、カットをカウントする必要はありません。

 ## 特殊なケース

 重要なエッジケースの 1 つは、両方の場合です。`t1`そして`t2`同じ文字から始めます。 その状況では、両方の DP 初期遷移が有効であり、アルゴリズムはバイアスなしで両方の可能性を探索します。 たとえば、次の場合`s = "ab"`、`t1 = "a"`、`t2 = "b"`、どちらの開始選択も有効であり、単一のカット ソリューションが生成されます。 

1 つのターゲット文字列がもう 1 つのターゲット文字列内に完全にインターリーブされている場合、別のエッジ ケースが発生します。`s`。 スイッチング コストはソースを変更する場合にのみ適用され、連続する文字を消費する場合には適用されないため、DP はこれを自然に処理します。 

最後のケースは、有効な配置が複数存在する繰り返し文字です。 DP は文字マッチングの一意性に依存しないため、すべての有効なパスが探索され、状態間の緩和を通じて最小カット構成が維持されます。
