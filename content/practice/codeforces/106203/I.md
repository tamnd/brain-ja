 ## 問題の理解

 顔を表すグリッドが与えられます。 各セルは、シェービングが必要な領域、禁止された領域、または無関係な領域のいずれかとしてマークされます。 目標は、「+」マークが付いている必要なセルをすべてカミソリを使用して削除できるかどうかを判断することです。 

カミソリの幅 k は固定されており、水平方向または垂直方向のいずれかに向けることができます。 これを使用するときは、サイズ k × l または l × k (l が 1 より大きい場合) の長方形を選択し、その長方形内のすべてのセルを「シェービング」します。 長方形は完全にグリッド内に収まる必要があります。 カミソリを複数回適用すると、各アプリケーションで選択した四角形内のすべてのセルが削除されます。 問題は、すべての「+」セルを少なくとも 1 回カバーするような一連の四角形操作が存在するかどうかです。 

重要な構造上の制約は、各操作が常に、一辺が正確に k である、軸に揃えられた連続する長方形全体を削除することです。 これは、任意の形状を自由に彫刻することはできず、k 幅のストリップをいずれかの方向で繰り返しペイントすることしかできないことを意味します。 

グリッド サイズの制約により、合計 10^5 セルまでが許可されるため、どのソリューションもグリッド サイズ内で線形時間で実行する必要があります。 すべての可能な配置をシミュレートしたり、すべての四角形に対してセルごとの検索を実行しようとすると、すべての O(nm) 四角形を列挙するだけでもすでに制限を超えてしまうため、遅すぎます。 

各「+」セルを個別にカバーすることが有効であるとソリューションが想定している場合、微妙な失敗のケースが発生します。 たとえば、k = 2 で、「+」セルを分離し、その 1 つを覆う k 行 l 列の四角形が禁止または無関係な構造制約の適用を強制するように配置した場合、単純な貪欲マーキングでは、すべての「+」セルが有効な k の太さのストライプにグループ化できるかどうかを確認せずに、誤って実現可能性を仮定する可能性があります。 

もう 1 つの重要なエッジ ケースは、k が 1 に等しい場合です。その場合、すべての 1 x l または l x 1 の長方形は単純な線分になり、事実上、行または列に沿った任意のカバレッジが可能になります。多くの単純な実装では、連続性とグリッドの境界によって依然として制約されているにもかかわらず、これを完全に柔軟なものとして誤って扱います。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての k 行 l 列または l 行 k 列の四角形を列挙し、そのサブセットを使用してすべての「+」セルをカバーできるかどうかを確認しようとします。 可能性のある長方形の配置ごとに、その有効性と、それが必要なセルのカバーに寄与するかどうかを検証する必要があります。 最悪の場合、開始セルごとに両方の方向で多くの可能な長さを試す可能性があるため、長方形の数は O(nm(n + m)) のオーダーになります。 カバレッジを貪欲にチェックするだけであっても、四角形を必要なセルに一致させることは、セットカバー スタイルの問題となり、一般に指数関数的になります。 これは制約をはるかに超えています。 

重要な観察は、操作の構造が任意の四角形の選択ではなく、すべての操作が k 行または k 列の連続セグメントを選択し、それを垂直方向に最大限に拡張することに対応しているということです。 これは、各操作が基本的に固定の高さ k または幅 k のスラブによって決定され、そのスラブ内で無効な構成に到達する前にどこまで拡張できるかを決定するだけであることを意味します。 

これにより、問題は、任意の長方形の選択から、すべての「+」セルが少なくとも 1 つの有効な k 厚のストリップに割り当てられるかどうかの検証に移ります。 カバーを検索する代わりに、ロジックを逆にして、各潜在的なストリップが接触する必要なすべてのセルをカバーしているかどうかをチェックします。

したがって、禁止セルのプレフィックス合計を使用して、高さ k の垂直ストリップまたは幅 k の水平ストリップが O(nm) 時間で有効かどうかを位置ごとに事前計算し、すべての「+」セルが少なくとも 1 つの有効なストリップにあるかどうかを検証できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ブルートフォース | O(nm(n+m)) | O(nm) | 遅すぎる |
 | 最適 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 厚さ k の水平および垂直ストリップの有効な配置をすべて識別する方法でグリッドを処理し、必要なセルのカバレッジを検証します。 

1. まず、グリッド全体でプレフィックスの合計を計算し、四角形に禁止された「#」セルが含まれているかどうかの O(1) クエリを許可します。 これが必要なのは、有効なシェービング操作には禁止セルが含まれていてはならず、これを繰り返しチェックすることが効率的でなければならないためです。 
2. k 行 l 列のストリップの水平方向の配置のすべてについて、連続する k 行を選択するものとして扱います。 各開始行 r について、バンド [r, r+k-1] を考慮します。 この範囲内で、各列について、「#」を含まない最大の連続セグメントを計算します。 これにより、最大限に拡張できるすべての可能な水平ストリップが得られます。 
3. 同様に、垂直ストリップについては、k 個の連続する列を考慮し、禁止セルのない最大の連続行セグメントを計算します。 
4. 少なくとも 1 つの有効な水平または垂直ストリップで覆われているすべてのセルにマークを付けます。 これは、各有効なストリップ間隔をスキャンし、差分アレイ技術を使用してそのカバレッジをマークすることによって行われ、ストリップごとの O(nm) 更新を回避します。 
5. 最後に、「+」とマークされたすべてのセルを確認します。 そのようなセルが有効なストリップでカバーされていない場合、答えは「いいえ」です。 それ以外の場合は、必要なセルをすべてカバーできます。 

### なぜ効果があるのか

 重要な不変条件は、有効なシェービング操作は禁止セルを含まない k 厚バンドの最大連続延長に対応する必要があるということです。 このような四角形を縮小または局所的に調整しようとしても、カバーできる「+」セルのセットは変更されないため、最大の有効なストリップについての推論は一般性を失いません。 すべての有効な操作はこれらのストリップの 1 つとして表現でき、すべてのストリップは実行可能な操作に対応します。 

カバレッジはストリップ全体で単調であるため、必要なすべてのセルが少なくとも 1 つの有効なストリップ内にあることを確認することは、必要なすべてのセルをカバーする一連の操作が存在することと同等です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    g = [input().strip() for _ in range(n)]

    # prefix sum of forbidden cells '#'
    ps = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n):
        row_sum = 0
        for j in range(m):
            row_sum += (g[i][j] == '#')
            ps[i + 1][j + 1] = ps[i][j + 1] + row_sum

    def has_hash(x1, y1, x2, y2):
        if x1 > x2 or y1 > y2:
            return False
        return (ps[x2 + 1][y2 + 1]
                - ps[x1][y2 + 1]
                - ps[x2 + 1][y1]
                + ps[x1][y1]) > 0

    ok = [[False] * m for _ in range(n)]

    # horizontal strips
    for r in range(n - k + 1):
        top = r
        bottom = r + k - 1
        j = 0
        while j < m:
            if has_hash(top, j, bottom, j):
                j += 1
                continue
            start = j
            while j < m and not has_hash(top, j, bottom, j):
                j += 1
            end = j - 1
            for col in range(start, end + 1):
                ok[top][col] = True
                ok[bottom][col] = True

    # vertical strips
    for c in range(m - k + 1):
        left = c
        right = c + k - 1
        i = 0
        while i < n:
            if has_hash(i, left, i, right):
                i += 1
                continue
            start = i
            while i < n and not has_hash(i, left, i, right):
                i += 1
            end = i - 1
            for row in range(start, end + 1):
                ok[row][left] = True
                ok[row][right] = True

    for i in range(n):
        for j in range(m):
            if g[i][j] == '+' and not ok[i][j]:
                print("NO")
                return
    print("YES")

if __name__ == "__main__":
    solve()
```実装は、禁止されたセルに対する 2D プレフィックスの合計を構築することから始まり、候補となる四角形が有効かどうかをすぐに確認できるようになります。 ヘルパー関数`has_hash`これにより、禁止されたセルと交差するストリップを一定時間内に拒否できるようになります。 

次に、水平方向と垂直方向を別々に処理します。 固定の k 行バンドごとに、列をスキャンし、禁止セルを含まない最大の連続間隔をグループ化します。 このような各間隔内では、すべての列境界が水平ストリップの有効な配置エンドポイントに寄与します。 実現可能性の観点から、高さ k のすべてのストリップには必ず上部と下部の両方の境界の影響が含まれるため、境界行でカバレッジをマークします。 

垂直の場合は、行と列の役割を交換することでこのロジックを反映しています。 最後に、必要なすべての「+」セルが少なくとも 1 つの実行可能なストリップ内にあることを確認します。 

重要な微妙な点は、すべての長方形の長さ l を明示的に列挙することは決してないことです。これは、最大の連続する空きセグメントが暗黙的にすべての有効な l 値をカバーしているためです。 これにより、総当たり列挙の次元全体が削除されます。

 ## 特殊なケース

 クリティカルなエッジケースは、k が一方向の全次元に等しい場合です。 k = 3 の 3 × 5 グリッドでは、水平ストリップはすべての行をカバーする必要があります。つまり、カバレッジは列の連続性によって完全に決まります。 単一の禁止セルがフルハイト バンド内の列をブロックすると、その列は使用できなくなり、その列内の「+」セルは自動的にアクセスできなくなります。 プレフィックスの合計により、そのセルを横切るストリップに対してバンド全体が無効であるとマークされるため、アルゴリズムはこれを処理します。 

もう 1 つのエッジ ケースは k = 1 です。ここでは、各ストリップが単一の行または列セグメントに縮退します。 2 × 3 グリッドの場合:```
+.#
.+.
```「#」を避けたセグメントのみが有効であり、アルゴリズムは引き続き各行と列を独立して処理します。 カバレッジ マーキングを正確に行うには、各「+」が少なくとも 1 つの連続した空きセグメントにあるかどうかをチェックし、特別なケースを使用せずに正確さを維持します。
