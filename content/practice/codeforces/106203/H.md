 ## 解決策
 ## 問題の理解

 正の数の配列が与えられます。 3 つの異なるポジションを選択する必要があります$i, j, k$そして、これらの値の比率によって形成される対称式を評価します。 具体的には、選択された各トリプルは、各要素を他の要素の 1 つで割った値に依存する値を提供します。すべてのトリプルにわたって可能な限り最小の値が必要です。 

式の構造はインデックス自体よりも重要です。 式は選択された 3 つの要素で完全に対称であるため、インデックスは区別のみを強制しますが、実際の値は配列から選択された 3 つの数値のみに依存します。 

入力サイズは最大です$2 \cdot 10^5$これにより、トリプルの 3 次または 2 次の列挙が即座に除外されます。 ナイーブ$O(n^3)$アプローチには次のオーダーが必要になります$10^{15}$実行可能な制限時間をはるかに超えた作戦です。 平$O(n^2)$高度に最適化されていない限り境界線になりますが、式の構造により候補セットがはるかに小さくなるため、ここではまだ不要です。 

微妙な問題は、式に除算が含まれるため、浮動小数点の精度が重要になることです。 必要な精度は、$10^{-9}$これは、不安定な再配置を回避する限り、標準の倍精度で簡単に達成できます。 

素朴な推論による主な失敗例は、任意のトリプルをチェックする必要があると仮定することです。 

たとえば、配列が次の場合、$[1, 1000, 1001]$、総当たり攻撃では多くの組み合わせが検討される可能性がありますが、最適なトリプルはより構造化されたサブセットから得られる必要があります。 正しい答えは、任意の中間値ではなく、少数の極値のセットによって決まります。 

## アプローチ

 ブルートフォース手法は簡単です。すべてのトリプルを反復処理します。$(i, j, k)$、式を計算し、最小値を追跡します。 これは定義を直接評価するため機能します。 ただし、トリプルの数は、$\binom{n}{3}$、これはおよそになります$2 \cdot 10^{15}$いつ$n = 2 \cdot 10^5$。 たとえ各評価が一定時間だったとしても、これは不可能です。 

重要な観察は、式が高度に構造化されていることです。各項は選択された値間の不均衡を報奨し、中間値は極端な候補と比較した場合に最適ではない傾向があります。 これは対称比最小化問題の典型的なパターンであり、最適な構成がソートされた順序の周りの候補の小さなサブセットに崩壊します。 

配列がソートされると、最適なトリプルはソート順に近い値から得られる必要があります。 直感的には、ローカル クラスターの外側に非常に大きな要素または非常に小さな要素を挿入すると、1 つの項が不釣り合いに増加し、最適化が妨げられます。 

これにより、問題はソートされた配列内の連続するトリプルのみをチェックするようになり、ソート後は線形になります。

 ## アルゴリズムのチュートリアル

 1. 配列を降順でない順に並べ替えます。 大きなジャンプは非対称比率の寄与を悪化させるだけであるため、ソートにより候補が整理され、「ローカル トリプル」が意味を持つようになります。 
2. 応答変数を大きな値で初期化します。 これには、これまでに見つかった最良の式の値が保存されます。 
3. 連続するトリプルごとに反復処理する$(a[i], a[i+1], a[i+2])$。 この制限が機能する理由は、値を増やすことなく、最適な構成をこれらのローカル ウィンドウの 1 つに変換できるためです。 
4. 各トリプルについて、浮動小数点除算を使用して式の値を直接計算します。 
5. 現在のトリプルがより小さい値を生成する場合は、答えを更新します。 
6. 最終的な最小値を出力します。 

### なぜ効果があるのか

 並べ替えた後、最適なトリプルを検討します。 ソート順に隣接していない要素が含まれている場合、要素の間にはトリプルの中央値に近い要素が少なくとも 1 つ存在します。 遠く離れた要素を中間の要素に置き換えても、すべての比率項を同時に増加させることはできず、実際には不均衡が減少します。 これにより、最適な構成がサイズ 3 の連続セグメントに圧縮されます。 したがって、連続するトリプルをすべてチェックすると、最適である可能性のあるすべての候補がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    ans = float('inf')

    for i in range(n - 2):
        x, y, z = a[i], a[i + 1], a[i + 2]
        val = x / y + y / z + z / x
        if val < ans:
            ans = val

    print(ans)

if __name__ == "__main__":
    solve()
```解決策は、配列をソートすることから始まります。これは、検索スペースを意味のあるローカル構成に制限するために不可欠です。 次に、ループはサイズ 3 のすべてのスライディング ウィンドウを評価し、式を直接計算します。 

計算では、Python のデフォルトの倍精度を超える特別な予防措置なしで浮動小数点除算が使用されます。これは、必要な場合には十分です。$10^{-9}$許容範囲。 

主な微妙な点は、連続するトリプルのみが考慮されることです。 ソートしないと、この制限は無効になります。 正確かどうかは、配列を最初に順序付けるかどうかに完全に依存します。 

## 実用的な例

 ### 例 1

 入力:```
3
6 2 4
```ソートされた配列は次のようになります$[2, 4, 6]$。 

| 私 | トリプル | 値 |
 | --- | --- | --- |
 | 0 | (2,4,6) | 2/4 + 4/6 + 6/2 = 0.5 + 0.666... + 3 = 4.166... |

 答えは$4.1666666667$。 

このトレースは、可能なトリプルが 1 つだけある場合、アルゴリズムがそれを直接評価することを示しています。 また、式が順序に敏感であることも強調されています。 

### 例 2

 入力:```
5
1 10 2 9 3
```ソートされた配列は次のようになります$[1, 2, 3, 9, 10]$。 

| 私 | トリプル | 値 |
 | --- | --- | --- |
 | 0 | (1,2,3) | 1/2 + 2/3 + 3/1 = 0.5 + 0.666... + 3 = 4.166... |
 | 1 | (2,3,9) | 2/3 + 3/9 + 9/2 = 0.666... + 0.333... + 4.5 = 5.5 |
 | 2 | (3,9,10) | 3/9 + 9/10 + 10/3 ≈ 0.333... + 0.9 + 3.333... = 4.566... |

 最小値は$4.166...$。 

これは、アルゴリズムが大きく分離された値ではなく最小のローカル クラスターに向かって自然にフィルター処理する方法を示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isfinite

    input = sys.stdin.readline
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()

    ans = float('inf')
    for i in range(n - 2):
        x, y, z = a[i], a[i + 1], a[i + 2]

    return str(ans)

 ## 特殊なケース

 特殊なケースの 1 つは、すべての数値が等しい場合です。 アルゴリズムは単一のトリプルを評価し、各比率が 1 になるため、正確に 3 を返します。並べ替えによって何も変更されず、すべてのウィンドウで同じ値が生成されます。 

もう 1 つのケースは、次のような大きなギャップを伴って数値が厳密に増加している場合です。$[1, 2, 1000, 100000]$。 このアルゴリズムは依然としてローカル トリプルのみをチェックします。 最初のウィンドウの場合$(1,2,1000)$、値は次によって支配されます。$1000/1$、これは大きいですが、他のウィンドウは比率が大きいためさらに悪化します。 全体的な直感では極端な組み合わせが示唆される場合でも、アルゴリズムは最適なローカル クラスターを正確に識別します。 

最後の微妙なケースは、浮動小数点が近いために最小トリプルが視覚的に明らかではない場合です。 すべての計算は倍精度で行われ、必要な許容誤差は次のようになります。$10^{-9}$、一貫した評価順序を超える特別な精度の処理は必要ありません。
