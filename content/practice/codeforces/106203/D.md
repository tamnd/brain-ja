 ## 問題の理解

 次の形式のべき乗方程式の指数には、非常に小さく珍しい制限が与えられています。$a^n + b^n = c^n$。 古典的な数理論の設定とは異なり、$n$大きいです、ここ$n$は 0 または 1 であることが保証されています。タスクは、整数が存在するかどうかを判断することです。$a$そして$b$、両方とも範囲内です$[-10^9, 10^9]$、この等価性が与えられた条件に対して成り立つように、$n$そして$c$、追加のルールが 1 つあります: 式$0^0$は無効とみなされ、それを評価する必要がある解決策候補はすべて拒否されます。 

入力は単一のペアを与えます$(n, c)$。 有効なペアを構築する必要があります。$(a, b)$存在しない方程式またはレポートを満たします。 

制約$n \in \{0, 1\}$は、問題を 2 つのまったく異なる代数の世界に分解します。 のために$n = 1$、方程式は線形であり、正常に動作します。 のために$n = 0$の場合、ゼロ以外の数値の 0 乗は 1 に等しいため、式は縮退します。$0^0$は禁止されており、代数的解決ではなくケース分割が導入されます。 

重要な微妙な点は、候補の構築で誤って評価が必要になる可能性があることです。$0^0$。 たとえば、次を使用しようとすると、$a = 0$または$b = 0$いつ$n = 0$、無効な式を暗黙的に呼び出していないことを確認する必要があります。 

両方のブランチでエッジケースが発生します。 

いつ$n = 1$、方程式は次のようになります$a + b = c$。 単純な間違いは、境界を尊重せずに分割が機能すると仮定することです。 たとえば、次の場合$c = 2 \cdot 10^9$、選択する$a = b = c$は制約に違反しますが、次のような有効な解決策は$a = 10^9, b = 10^9$まだ動作します。 もし$c = 0$、選択する$a = c, b = 0$それは問題ありませんが、任意の分解を選択する場合でも境界を尊重する必要があります。 

いつ$n = 0$、方程式は次の数を数えることになります。$a$そして$b$非ゼロの基数は 1 に寄与するため、非ゼロです。これにより、離散的なケースが生じます。 

両方がゼロ以外の場合、合計は 2 になります。 ちょうど 1 つがゼロ以外の場合、合計は 1 になります。 両方ともゼロの場合、式は次の理由により無効です。$0^0$。 

それで$c$この体制では意味のある値は 1 または 2 のみであり、禁止された構成による追加の制限があります。$(0, 0)$。

 ## アルゴリズムのチュートリアル

 の値に基づいてソリューションをケースに分割します。$n$。 

1. もし$n = 1$、方程式を次のように書き換えます$a + b = c$。 合計する整数のペアを自由に選択できます。$c$。 安定した選択は、$a = 0$、$b = c$、両方ともすべての有効な範囲内にあるため、$c$。 これにより、オーバーフローや境界の問題が完全に回避されます。 
2. もし$n = 0$、各項はインジケーターのように動作します。基数がゼロ以外の場合は 1 が寄与し、基数がゼロの場合は 0 が寄与します。 使用を明示的に避けなければなりません$0^0$、つまりペア$(0, 0)$は許可されていません。 
3. この解釈では、左辺は値のみを取ることができます。 

- 両方がゼロの場合は 0 (次の理由により無効)$0^0$）
 - 1 つだけがゼロ以外の場合は 1
 両方がゼロ以外の場合は - 2
 4. これでターゲットが一致しました$c$：

- もし$c = 0$が必要となるため、それを達成することはできません。$(0,0)$、これは無効です。 
- もし$c = 1$、私たちが選択します$a = 1$、$b = 0$。 
- もし$c = 2$、私たちが選択します$a = 1$、$b = 1$。 
- そうでなければ、解決策は存在しません。 

### なぜ効果があるのか

 のために$n = 1$満足のいくペア$a + b = c$べき乗は標準の整数演算で等価性を維持するため、これは有効です。 のために$n = 0$、の値$x^0$ゼロ以外の場合は 1 に固定されます$x$、0 の場合は未定義で、離散状態システムが強制されます。 左辺は各変数がゼロであるかどうかのみに依存するため、考えられるすべての有効な結果は 3 つの許可された構成によって網羅されます。 他の算術構造が式に影響を与えないため、隠れたケースは存在しません。

 ## 特殊なケース

 のために$n = 1, c = 0$、アルゴリズムの出力$a = 0, b = 0$。 これは呼び出されません$0^0$累乗は次の場合にのみ使用されるため、$n = 1$なので、式は標準的な加算のままです。 等式は次のように自明に成り立ちます$0 + 0 = 0$。 

のために$n = 0, c = 0$、有効な解釈には両方が必要です。$a$そして$b$ゼロになるはずですが、これにより強制的に次の評価が行われます。$0^0$両方の意味で。 これは明示的に禁止されているため、アルゴリズムはこのケースを正しく拒否します。
