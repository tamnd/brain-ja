 ## 解決策
 ## 問題の理解

 ポイントの更新を通じて時間の経過とともに変化する整数の配列が与えられます。 各更新の後、XOR を使用して定義された特定の「バランス」プロパティを持つ配列内の位置の数を答えることができなければなりません。 

インデックスの場合$i$、厳密に左側のすべての要素の XOR を考慮します。$i$、および厳密に右側にあるすべての要素の XOR$i$。 これら 2 つの XOR 値が等しい場合、インデックスは特別であるとみなされます。 

クエリは、配列の 1 つの要素を変更するか、特別なインデックスの現在の数を要求します。 

配列の長さとクエリの数は両方とも最大です。$2 \cdot 10^5$これにより、クエリごとにプレフィックスとサフィックスの XOR を最初から再計算することが直ちに除外されます。 各更新後のフルスキャンは次のようになります。$O(nq)$、これは許容範囲をはるかに超えています。 

微妙なエッジケースが境界に現れます。 のために$i = 0$の場合、左側の XOR は空であるため、ゼロになります。 のために$i = n-1$の場合、右側の XOR は空であり、やはりゼロです。 正しいソリューションでは、これらの定義を一貫して処理する必要があります。そうでないと、プレフィックスまたはサフィックスの処理における off-by-one ロジックは、単一要素または 2 要素の配列で失敗します。 

たとえば、配列が次の場合、$[5]$、左右の XOR は両方とも 0 であるため、インデックス 0 は常に有効です。 単純な実装が空の XOR 規則を忘れた場合、このケースが誤って除外される可能性があります。 

## アプローチ

 直接的なアプローチでは、クエリごとにプレフィックス XOR とサフィックス XOR が再計算されます。 更新のたびに 2 つの配列を再計算し、条件を満たすインデックスをカウントします。 各再計算にはコストがかかります$O(n)$、につながる$O(nq)$総仕事量。 と$2 \cdot 10^5$これでは、操作が数桁遅すぎます。 

重要な観察は、プレフィックスまたはサフィックス構造の必要性を完全に排除する方法で条件を書き換えることができるということです。 

させて$P$配列全体の XOR になります。 させて$pref[i]$の要素の XOR になる$0$に$i$。 次に、インデックスの左XOR$i$は$pref[i-1]$、右の XOR は次のようになります。$P \oplus pref[i]$。 条件は次のようになります。$$pref[i-1] = P \oplus pref[i]$$ID を使用してください$pref[i] = pref[i-1] \oplus a[i]$。 代入すると次のようになります。$$pref[i-1] = P \oplus (pref[i-1] \oplus a[i])$$キャンセルする$pref[i-1]$両側で XOR プロパティを使用すると、次の結果が得られます。$$0 = P \oplus a[i]$$これは次のように単純化されます。$$a[i] = P$$したがって、インデックスは、その値が配列全体の XOR と等しい場合にのみ有効になります。 

これにより、全体の問題は、配列のグローバル XOR と各値の頻度という 2 つのことを更新中に維持することになります。 タイプ 2 の各クエリは、現在グローバル XOR と等しい要素の数を示す単一の検索になります。

 ## アルゴリズムのチュートリアル

 配列全体の XOR と配列内の値の頻度マップという 2 つの状態を維持します。 

1. 初期配列内の各要素の出現を数えることによって頻度マップを初期化し、すべての要素の XOR を計算します。 これにより、今後のすべてのクエリのベースライン状態が設定されます。 
2. 位置での更新クエリの場合$i$、まず、周波数マップとグローバル XOR の両方から古い値の寄与を削除します。 新しい値を適用する前に配列の状態が一貫している必要があるため、これが必要です。 
3. 新しい値を位置に適用します。$i$、それに応じて周波数マップと XOR を更新します。 このステップの後、維持された状態は再び現在の配列を正確に反映します。 
4. バランスの取れたインデックスの数を求めるクエリの場合、現在のグローバル XOR 値の頻度を返します。 これが機能するのは、インデックスの値が XOR の合計と正確に等しい場合に、インデックスが有効であることが証明されたからです。 

### なぜ効果があるのか

 正確かどうかは、プレフィックス XOR に関して左右の XOR 式を書き換えてから、プレフィックス変数を完全に削除するかどうかにかかっています。 最後の条件は、各要素と単一のグローバル スカラー、つまり配列全体の XOR 間の点ごとの等価性に帰着します。 そのスカラーは常に更新時に正確に維持されるため、有効なインデックスをカウントすることは、配列内のそのスカラーの出現をカウントすることと同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    freq = {}
    total_xor = 0

    for v in a:
        total_xor ^= v
        freq[v] = freq.get(v, 0) + 1

    out = []

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            i = int(tmp[1])
            x = int(tmp[2])

            old = a[i]
            if freq[old] == 1:
                del freq[old]
            else:
                freq[old] -= 1

            total_xor ^= old

            a[i] = x

            total_xor ^= x
            freq[x] = freq.get(x, 0) + 1

        else:
            out.append(str(freq.get(total_xor, 0)))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```このソリューションでは明示的な配列を保持するため、一定時間内に更新を適用できます。 XOR アキュムレータは、古い値を削除して新しい値を追加することによって更新されます。これは、XOR 自体が逆数であるため機能します。 頻度辞書は、指定された値に一致する要素の数を追跡し、クエリの回答は単純な辞書検索です。 

よくある間違いは、古い値を上書きする前にその頻度を減らすのを忘れることです。これにより、複数の更新後にカウントが膨らむことになります。 

## 実用的な例

 配列を考慮してください$[1, 2, 3]$。 

合計 XOR を次のように計算します。$1 \oplus 2 \oplus 3 = 0$。 ゼロに等しい要素はないため、答えは 0 になります。 

| ステップ | 配列 | 合計 XOR | 周波数マップ | 答え |
 | --- | --- | --- | --- | --- |
 | イニシャル | [1,2,3] | 0 | {1:1、2:1、3:1} | 0 |

 次に、インデックス 1 を値 1 に更新します。$[1, 1, 3]$。 

| ステップ | 配列 | 合計 XOR | 周波数マップ | 答え |
 | --- | --- | --- | --- | --- |
 | アップデート後 | [1,1,3] | 3 | {1:2,3:1} | 1 |

 ここでは、3 に等しいインデックス値のみが有効であり、そのような要素は 1 つだけ存在します。 

このトレースは、アルゴリズムがプレフィックスの計算をまったく必要とせず、単一の集約不変式の一貫した維持のみを必要とすることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 |$O(n + q)$| 更新ごとに、マップおよび XOR アキュムレータ内の一定数のエントリが変更されます。 
| スペース |$O(n)$| 頻度マップには、個別の値ごとに最大 1 つのエントリが保存されます。 

両方の制限が入力のサイズにおいて線形であり、すべての操作が平均して定数時間であるため、ソリューションは制約内に快適に適合します。

 ## 特殊なケース

 次のような単一要素配列の場合$[x]$、アルゴリズムは合計 XOR を次のように計算します。$x$。 頻度マップには、次のものが 1 つだけ含まれています。$x$、それで、もし$x = 0$空のプレフィックスとサフィックスは特殊なケースではなく XOR ID で暗黙的にエンコードされるため、実装はこれを正しく処理します。 

同じインデックスで更新を繰り返す場合、削除および挿入の手順により、頻度マップで値が 2 重にカウントされることがなくなります。 各更新では、新しい値を追加する前にまず古い値が減算され、マップが常に現在の配列を正確に反映するという不変性が維持されます。 

すべての値がゼロである配列の場合、すべての更新を通じて合計 XOR はゼロのままです。 すべてのインデックスは常に有効であり、頻度マップは常に次の値を返します。$n$、バランスの取れたポジションの定義と一致します。
