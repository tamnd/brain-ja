 ## 解決策
 ## 問題の理解

 各エッジにカラーラベルが付けられた有向グラフが与えられます。 このグラフのウォークでは頂点とエッジを再訪することができますが、ウォークに沿った色が厳密に交互になる場合にのみ「有効」になります。つまり、同じ色の 2 つの連続するエッジを横断することは決して許可されません。 

タスクは、そのような有効なウォークを使用してノード 1 からどの頂点に到達できるかを判断することです。 この制約の下で到達できるすべての頂点について、出力に含めます。 

重要な点は、到達可能性は現在のノードだけでなく、使用される最後のエッジの色にも依存するということです。 ノードを追跡するだけの単純な到達可能性の概念では不十分です。異なる最終エッジの色で同じノードに到達すると、将来の異なる可能性が生じるからです。 

入力サイズでは、すべてのテスト ケースにわたって合計で最大 100 万個のノードとエッジが許可されます。 これにより、すべてのパスを明示的に列挙しようとするソリューションは即座に除外されます。 パス上の単純な BFS にすべての状態を保存したとしても、サイクルと繰り返しの再訪問により可能なウォークの数が指数関数的に増加するため、爆発的に増加します。 

同じ色の複数のエッジがサイクルを形成する場合、微妙なエッジ ケースが発生します。 たとえば、色 1 のエッジによって完全に接続されたノードのチェーンについて考えてみましょう。ノード 1 からノード 2 に到達することはできますが、別の色 1 のエッジを使用してノード 2 から続行することはできません。 色の制約を無視する単純な BFS では、すべてのノードが到達可能であると誤ってマークされますが、正しい答えは代替ルールの尊重に依存します。 

もう 1 つの特殊なケースは、異なる色の複数の入力エッジを介して到達可能なノードです。 たとえば、ノード 2 からの赤エッジ経由でノード 3 に到達でき、ノード 4 からの青エッジ経由でもノード 3 に到達できる場合、ノード 3 からの次の遷移はどちらの到着を考慮するかによって異なります。 これらの状態をノードごとに 1 つの訪問済みフラグに集約すると、正確性が失われます。 

## アプローチ

 簡単なアイデアは、パス上で BFS または DFS を実行することです。 各状態は、現在のノードと最後に使用されたエッジの色を表します。 状態から、最後の色と異なる色を持つすべての出力エッジを試します。 これは問題の制約を直接エンコードしているため、これは正しいです。 ただし、これは単純に実装するとすぐに非効率になります。異なる入力色で同じノードを何度も再訪する可能性があり、グラフに多くのエッジが含まれる可能性があるためです。 

重要な観察は、状態空間を適切に構造化した場合、状態空間は実際には大きくないということです。 任意のパスを探索する代わりに、フォームのペア (ノード、最後の色) を考慮するだけで済みます。 各エッジ遷移は、この状態を一定時間で更新します。 各エッジは制限された回数だけ処理されるため、これを展開された状態グラフ上のグラフ走査として扱うことができます。 

ただし、これでもさらに最適化することができます。 すべての色の状態を明示的に展開する代わりに、遷移が完全な履歴ではなく最後のエッジの色にのみ依存することがわかります。 これは、色ごとにグループ化された隣接リストを維持し、最後に使用された色を伝える BFS を実行することを示唆しています。 各エッジは、互換性のある受信状態ごとに 1 回、事実上考慮されます。 

ブルートフォースのアイデアは、すべての有効なウォークを探索するため機能しますが、同一の状態遷移の再計算が繰り返されるため失敗します。 最適化されたビューでは、すべてのパス履歴が小さな状態グラフに圧縮され、意味のあるそれぞれの区別が最後に使用された色にすぎません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | パス上の DFS/BFS (状態圧縮なし) | 指数 | O(n + m) | 遅すぎる |
 | BFS の (ノード、最後のカラー) 状態 | O(n + m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各エントリに隣接色とエッジの色の両方を格納する隣接リストを作成します。 この表現により、トラバーサル中の色の互換性に基づいて遷移をフィルタリングすることができます。 
2. BFS 状態を (node, last_color) のペアとして定義します。 last_color は、「前のエッジがない」ことを意味する特別な値として開始され、ノード 1 からの最初の移動で任意の色を使用できるようになります。 
3. キューを状態 (1、なし) で初期化します。 また、同じ状態を再処理しないように、(node, last_color) をキーとする訪問済みの構造も維持します。 
4. キューから状態 (v、c_prev) をポップします。 各出力エッジ (v → to、c) については、c が c_prev と異なる場合にのみ考慮されます。 これにより、各ステップで局所的に交互の色条件が適用されます。 
5. 新しい状態 (to、c) に到達したら、その状態を訪問済みとしてマークし、キューにプッシュします。 このような各トランジションは、有効なカラフルなウォークの延長を表します。 
6. BFS が終了したら、最後の色に関係なく、任意の状態で到達したすべてのノードを収集します。 これらのノードは、少なくとも 1 つの有効なカラフルなウォークによって到達可能なノードです。 

重要な考え方は、最後の色が異なる状態は決してマージしないということです。その違いは将来の遷移に影響するからです。 BFS が安定すると、到達可能なすべての状態は、何らかの交互カラー ウォークの有効なプレフィックスを表します。 

### なぜ効果があるのか

 BFS は、ノードが最後のエッジの色情報で拡張されたグラフを探索します。 すべての遷移は、保存された状態がノード 1 からの有効な交互カラー ウォークに対応するという不変条件を保持します。すべての有効なウォークはそのような遷移のシーケンスに分解できるため、元のグラフ内の到達可能な頂点はすべて、少なくとも 1 つの到達可能な状態で出現する必要があります。 逆に、BFS によって生成されるすべての状態は、前のエッジと色が異なるエッジに沿ってのみ拡張するため、構築による有効なウォークに対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque, defaultdict

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        
        g = [[] for _ in range(n + 1)]
        for _ in range(m):
            u, v, c = map(int, input().split())
            g[u].append((v, c))
        
        # BFS over (node, last_color)
        # last_color = 0 means "no previous edge"
        q = deque()
        q.append((1, 0))
        
        visited = set()
        visited.add((1, 0))
        
        reachable = set([1])
        
        while q:
            v, pc = q.popleft()
            for to, c in g[v]:
                if c == pc:
                    continue
                state = (to, c)
                if state not in visited:
                    visited.add(state)
                    reachable.add(to)
                    q.append(state)
        
        print(*sorted(reachable))

if __name__ == "__main__":
    solve()
```隣接リストには有向エッジとその色が格納され、発信遷移に対する定数時間の反復が可能になります。 BFS キューには完全な状態情報が保存されるため、色の制約がローカルで適用されます。 

よくある実装の落とし穴は、初期状態では任意の色を許可する必要があることを忘れていることです。 これが、初期の last_color がゼロに設定され、実際のエッジの色と一致しないことが保証される理由です。 

もう 1 つの微妙な問題は、訪問された構造です。 ノードのみを訪問済みとしてマークすると、最後の色の異なるノードに到達すると新しい遷移が可能になる可能性があるため、有効な状態が誤って削除されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 各状態 (ノード、カラー) はエッジ遷移ごとに最大 1 回訪問され、合計の遷移はエッジ内で線形です。 
| スペース | O(n + m) | 隣接関係リストと訪問済み状態セットのストレージ |

 この制約により、すべてのテスト ケースにわたって最大 100 万のエッジが許可され、各エッジが一定の回数処理されるため、この線形走査は制限内に快適に収まります。

 ## 特殊なケース

 キー エッジ ケースは、すべてのエッジが同じ色を共有する直線状のチェーンです。 このような場合、ノード 1 からの最初のステップのみが有効になり、後続のすべての遷移はブロックされます。 同じ色を再利用しようとするとすぐに状態条件に違反するため、BFS は拡張を正しく停止し、最初のホップを超えるノードは追加されません。 

もう 1 つのエッジ ケースは、最後の色が異なる複数のパスを介してノードに到達できる場合です。 このアルゴリズムは両方の状態を独立して正しく保存するため、将来の遷移が時期尚早に破棄されることはありません。 たとえば、赤のエッジと青のエッジを介してノード 2 に到達した場合、両方の状態 (2、赤) と (2、青) がアクティブのままとなり、ノードのみの訪問配列では見逃されるさまざまな発信拡張が可能になります。
