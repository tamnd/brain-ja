 ## 解決策
 ## 問題の理解

 グリッド上に 2 つのセルのセットがあります。 一部のセルにはカモメが含まれており、同じ数のセルに餌が含まれています。 コマンドは残りのカモメと方向を選択します。 カモメは、その方向に残っている別のカモメが含まれていない最初のセルに到達するまで移動します。 このコマンドは、目的のセルに食べ物が含まれている場合にのみ成功します。そうすれば、カモメと食べ物が消えるからです。 

タスクは、すべてのカモメに対して 1 つのコマンドを出力して、すべてのカモメが餌を食べるか、食べられないと判断するようにすることです。 

重要な点は、食べ物が動きを妨げないことです。 カモメだけが、別のカモメが飛べる距離に影響を与えます。 これは、カモメが食物セルのすぐ隣にいる場合にのみコマンドが成功する可能性があることを意味します。 カモメの間に別のカモメがいる場合、選ばれたカモメは餌に到達する前に止まります。 それらの間に空のセルがある場合、選択されたカモメは停止するのが早すぎます。 

入力サイズはグラフ ソリューション用に設計されています。 すべてのテスト ケースにわたるカモメの総数は最大 5000 羽であるため、線形または$O(n \sqrt n)$全体の入力が快適です。 考えられるすべてのコマンド シーケンスを試す解決策は不可能です。$n!$可能な注文。 カモメと食物細胞のすべてのつがいを繰り返し検索しても、近づいてくるでしょう。$O(n^2)$ここではそれが可能ですが、本当の課題は、グローバルに有効な一連の動きを選択することです。 

不注意な実装は、ローカルで有効な動きが別のカモメの唯一の可能な一致を破壊する場合に失敗する可能性があります。 例えば：```
1
2
1 1
1 3
1 2
2 3
```正しい出力は次のとおりです。```
No
```最初のカモメ`(1,1)`の食べ物の隣にあります`(1,2)`、食べられるので。 2番目のカモメ`(1,3)`残った食べ物は食べられない`(2,3)`水平方向にも垂直方向にも隣接していないからです。 常に最初に利用可能な食べ物を取るという貪欲なアプローチは行き詰まる可能性があります。 

もう 1 つのエッジ ケースは、考えられるすべてのペアが機能するが、その順序が危険に見える場合です。```
1
3
2 2
2 4
4 2
2 3
2 5
3 2
```正しい出力は次のとおりです。```
Yes
```いくつかの選択肢が考えられます。 カモメは食べると消えてしまうので、新たなブロッカーを作ることができません。 ソリューションは、複雑な注文のシミュレーションではなく、完全なペアのセットを選択することに重点を置く必要があります。 

## アプローチ

 直接的な強引なアイデアは、現在餌を食べることができるカモメを繰り返し探し、それを取り除き、続行することです。 これはプロセスを正確にシミュレートし、考えられるすべての選択肢を試行すれば解決策を見つけることができます。 問題は選択肢の多さです。 悪いケースでは、各段階で多くの可能な手があり、探索されるシーケンスの数が階乗的に増加する可能性があります。 

有益な観察は、コマンドが成功するたびに、隣接するカモメと餌が削除されるということです。 削除されたカモメは決して戻らないため、選択された有効なペアは、エンドポイントの 1 つが削除されるまで有効のままです。 これにより、問題は順序付けの問題からペアリングの問題に変わります。 

二部グラフを作成できます。 左側にはカモメが含まれており、右側には食物細胞が含まれています。 カモメと食物セルがグリッド内で隣接している場合にエッジを追加します。 このグラフが完全に一致すると、すべてのカモメに食べられる個別の餌が与えられます。 コマンドは、一致したペアを 1 つずつ実行するだけで済みます。 他のカモメを削除しても障害物が取り除かれるだけなので、順序は関係ありません。 

各セルに隣接するセルが最大 4 つあるため、グラフがまばらになります。したがって、エッジの数はカモメの数の最大 4 倍になります。 最大の 2 部マッチング アルゴリズムで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) | 遅すぎる |
 | 二部マッチング | O(E√V) | お(え) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのカモメとすべての食物細胞を保管します。 すべてのカモメに 0 から n-1 までのインデックスを付けます。 
2. カモメがその上下左右のすべての食物セルに直接接続されている 2 部グラフを作成します。 これらはまさに成功する可能性のある動きです。 
3. Hopcroft-Karp を実行して、カモメと食物セルの間で最大の一致を見つけます。 このアルゴリズムは、複数の最短の拡張パスを繰り返し見つけて反転します。これは、一度に 1 つのパスを検索するよりもはるかに高速です。 
4. 一致するサイズが n より小さい場合、一部のカモメには固有の餌を割り当てることができないため、次のように出力します。`No`。 
5. それ以外の場合は、一致したペアごとに、カモメの位置から餌の位置への方向を出力します。 2 つのセルが隣接しているため、これらのコマンドはそれぞれ有効です。 

なぜ効果があるのか:

 コマンドは、選択したカモメと食べた餌が隣接するセルを占有している場合にのみ成功します。 マッチングにはまさにそのようなペアが含まれており、すべてのカモメと食べ物が 1 回ずつ表示されます。 一致したペアを実行すると、両方のエンドポイントが削除されます。 他のカモメを削除しても、今後一致する手を無効にすることはできません。カモメが減れば、ブロックするセルも少なくなるからです。 したがって、完全な一致とは、完全に有効なコマンド シーケンスです。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

def solve_case(n, gulls, foods):
    food_id = {pos: i for i, pos in enumerate(foods)}

    graph = [[] for _ in range(n)]
    for i, (r, c) in enumerate(gulls):
        for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
            nxt = (r + dr, c + dc)
            if nxt in food_id:
                graph[i].append(food_id[nxt])

    match_left = [-1] * n
    match_right = [-1] * n
    dist = [0] * n

    def bfs():
        q = deque()
        found = False
        for i in range(n):
            if match_left[i] == -1:
                dist[i] = 0
                q.append(i)
            else:
                dist[i] = -1

        while q:
            u = q.popleft()
            for v in graph[u]:
                nxt = match_right[v]
                if nxt == -1:
                    found = True
                elif dist[nxt] == -1:
                    dist[nxt] = dist[u] + 1
                    q.append(nxt)
        return found

    def dfs(u):
        for v in graph[u]:
            nxt = match_right[v]
            if nxt == -1 or (dist[nxt] == dist[u] + 1 and dfs(nxt)):
                match_left[u] = v
                match_right[v] = u
                return True
        dist[u] = -1
        return False

    matching = 0
    while bfs():
        for i in range(n):
            if match_left[i] == -1 and dfs(i):
                matching += 1

    if matching != n:
        return None

    ans = []
    for i, food in enumerate(match_left):
        r1, c1 = gulls[i]
        r2, c2 = foods[food]
        if r2 == r1 - 1:
            ans.append((i + 1, "U"))
        elif r2 == r1 + 1:
            ans.append((i + 1, "D"))
        elif c2 == c1 - 1:
            ans.append((i + 1, "L"))
        else:
            ans.append((i + 1, "R"))
    return ans

def main():
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        gulls = [tuple(map(int, input().split())) for _ in range(n)]
        foods = [tuple(map(int, input().split())) for _ in range(n)]

        res = solve_case(n, gulls, foods)
        if res is None:
            out.append("No")
        else:
            out.append("Yes")
            for x, d in res:
                out.append(f"{x} {d}")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```隣接しない食品には決して到達できないため、グラフの構築では隣接する 4 つのセルのみをチェックします。 食品の位置を格納する辞書により、各隣接性チェックを一定時間で実行できます。 

一致する配列には、すべてのカモメの現在のパートナーと餌が保存されます。 の値`-1`頂点が現在一致していないことを意味します。 ホップロフト・カープが使用するもの`dist`拡張パスをレイヤーに編成することで、失敗した同じパスを繰り返し探索することを回避できます。 

答えを生成する際に、一致した食べ物がカモメ座標と比較されます。 方向は 1 つの座標の違いによって決まります。 一致するプロパティによってすべてのコマンドが成功したことがすでに証明されているため、動きをシミュレートする必要はありません。

## 特殊なケース

 最初のエッジケースは不完全なマッチングです。 2羽のカモメがいる例では、`(1,1)`そして`(1,3)`、最初のカモメだけが近くに餌を持っています。 このアルゴリズムはグラフ エッジを 1 つだけ作成するため、Hopcroft-Karp は両方のカモメと一致することができず、結果を返します。`No`。 

2 番目のエッジケースは、貪欲な注文が間違ったペアを選択する可能性がある場合です。 アルゴリズムは、早期に移動をコミットすることはありません。 それはまず、すべてのカモメの食物への完全な割り当てを見つけます。 一致が存在すると、実行順序に関係なく、すべてのコマンドが動作することが保証されます。 

最小のケースにはカモメ 1 匹とその隣に餌が 1 つあります。 グラフにはエッジが 1 つあり、一致するサイズは 1 つで、生成された方向は食品に直接到達します。 これは、方向生成が可能な限り最小の入力を正しく処理することも確認します。
