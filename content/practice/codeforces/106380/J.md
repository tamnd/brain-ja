 ## 解決策
 ## 問題の理解

 この問題は、固定の実験セットを備えたコース登録システムについて説明しています。 生徒が一人ずつ到着し、実験を選択します。 実験を選択した最初の生徒はその実験のインデックス 1 を受け取り、次の生徒はインデックス 2 を受け取ります。 後で、すでに割り当てられている 2 つのポジションは、そのポジションが異なる実験に属している場合でも、そのポジションを占めている学生を交換することができます。 すべてのイベントの後、現在その位置を占めている学生を含むすべての実験をインデックスの昇順で印刷する必要があります。 

入力には実験とイベントの数が含まれます。 タイプ 1 のイベントは、新しい学生 ID を 1 つの実験の最後に追加し、そこに次に利用可能なインデックスを作成します。 タイプ 2 のイベントは、保存されている学生 ID を交換することによって、選択された 2 つのポジションのみを変更します。 出力では、すべての実験の位置の内部順序が保持される必要があります。 

制約はデータ構造選択の鍵となります。 まであります$3 \times 10^5$実験と$3 \times 10^5$イベントがあるため、実験リスト全体を移動してスワップをシミュレートすると遅すぎます。 1 つの実験には多数の生徒が含まれる可能性があるため、1 つの実験のサイズで対数的な操作が必要です。 保存されている生徒の総数は、最大でもタイプ 1 イベントの数です。$3 \times 10^5$したがって、生徒ごとに 1 つのノードを持つデータ構造が実現可能です。 

主なエッジ ケースは、実験インデックスが独立しているという事実から生じます。 

学生が空の実験に参加したとします。```
Input
2 1
1 2 100000001
```イベントの後、実験 2 には 1 人の生徒が含まれます。 出力には、その学生 ID を含むインデックス 1 が含まれている必要があります。 実験番号を生徒の位置として扱う不注意な実装では、生徒が間違って配置される可能性があります。 

もう 1 つの注意が必要なケースは、サイズが大きく異なる異なる実験で同じ位置を交換することです。```
Input
3 3
1 1 100000001
1 1 100000002
1 2 100000003
2 1 2 2 1
```交換前の実験 1 は、`[100000001, 100000002]`そして実験2は`[100000003]`。 スワップにより、実験 1 の 2 番目の位置が実験 2 の最初の位置と交換され、実験 1 が次のようになります。`[100000001, 100000003]`そして実験2は次のようになります`[100000002]`。 位置ではなく実験全体を交換するソリューションでは、間違った結果が生成されます。 

最後のエッジケースは、学生を決して受け入れない実験です。```
Input
3 0
```3 つの出力行にはすべてゼロのみを含める必要があります。 すべての実験に少なくとも 1 つの値が保存されていると想定するコードは、ここでは失敗します。 

## アプローチ

 直接的なアプローチでは、各実験を通常のリストとして保存します。 生徒の追加は簡単で、最終的な出力も簡単です。 難易度はタイプ2のイベントです。 2 つの位置を交換するには、各リスト内の任意のインデックスにアクセスする必要があります。 リンク リストを使用した場合、インデックスへのアクセスには直線的な時間がかかります。 通常の配列を使用した場合、アクセスは高速ですが、動的配列と多くの挿入を使用した実験の総数は慎重な管理を必要とします。 さらに重要なのは、すべてのイベントを検索し、影響を受けた実験データを再構築するという強引なアイデアは、$O(m^2)$、それは周りにあります$9 \times 10^{10}$最悪の場合の運用。 

この問題を処理しやすくする観察結果は、各実験に必要な操作が 3 つの操作のみであるということです。つまり、後ろに追加する、位置を読み取る、位置を書き込むということです。 要素を途中に挿入したり削除したりすることはありません。 これは、あらゆる実験をランダム アクセスをサポートする動的シーケンスで表現できることを意味します。 

暗黙的トレプは自然に適合します。 明示的なインデックスを保存するのではなく、シーケンスの順序をツリー構造に保存します。 すべてのサブツリーのサイズにより、対数時間で k 番目の要素を含むノードを見つけることができます。 追加とは、現在のトレップを新しい単一ノードのトレプとマージすることです。 2 つの位置を交換すると、2 つの k 番目のクエリとそれに続く 2 つの割り当てになります。 

ブルートフォース手法は、最終的な配置を正しくモデル化するため機能しますが、ランダム アクセスの繰り返しと大きなシーケンスの移動にはコストがかかりすぎるため、失敗します。 暗黙的トリープは、すべてのイベントを対数作業に削減しながら、同じシーケンス動作を維持します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(m^2)$|$O(m)$| 遅すぎる |
 | 最適 |$O(m \log m)$|$O(m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 実験ごとに空の暗黙的 treap ルートを 1 つ作成します。 各ノードは 1 つの学生 ID を表し、位置をすぐに見つけられるようにサブツリーのサイズを保存します。 
2. 学生が実験を選択したら、その学生 ID を含む新しい treap ノードを作成し、それを実験の現在の treap の右側にマージします。 これにより、学生は次に利用可能なインデックスに配置されます。 
3. スワップ イベントが表示されたら、サブツリー サイズを使用して最初に要求された位置にあるノードを見つけます。 同様に、2 番目に要求された位置にあるノードを見つけます。 保管されている学生証のみを交換してください。 
4. すべてのイベントを処理した後、すべての実験のトレプを順番に走査します。 走査順序は元のインデックス順序と同じであるため、収集された ID はすでに実験インデックスによって並べ替えられています。 

これが機能する理由: 暗黙的 treap によって維持される不変条件は、その順序での走査がその実験における位置のシーケンスとまったく同じであるということです。 新しいノードが最後にマージされるため、追加ではこの順序が維持されます。 スワップでは 2 つの位置に格納されている値のみが変更されるため、シーケンスの順序は変わりません。 最後の走査ではすべての位置を昇順で訪問するため、生成された名簿は必要な出力と一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(1 << 25)

left = [0]
right = [0]
size = [0]
value = [0]
priority = [0]

seed = 123456789

def rng():
    global seed
    seed ^= seed << 7
    seed ^= seed >> 9
    return seed & 0xFFFFFFFF

def new_node(v):
    value.append(v)
    priority.append(rng())
    left.append(0)
    right.append(0)
    size.append(1)
    return len(value) - 1

def pull(x):
    size[x] = size[left[x]] + size[right[x]] + 1

def merge(a, b):
    if not a:
        return b
    if not b:
        return a
    if priority[a] > priority[b]:
        right[a] = merge(right[a], b)
        pull(a)
        return a
    else:
        left[b] = merge(a, left[b])
        pull(b)
        return b

def kth(x, k):
    while True:
        lsz = size[left[x]]
        if k == lsz + 1:
            return x
        if k <= lsz:
            x = left[x]
        else:
            k -= lsz + 1
            x = right[x]

def collect(x, out):
    if x:
        collect(left[x], out)
        out.append(value[x])
        collect(right[x], out)

def solve():
    n, m = map(int, input().split())
    roots = [0] * (n + 1)

    for _ in range(m):
        event = list(map(int, input().split()))
        if event[0] == 1:
            _, i, x = event
            roots[i] = merge(roots[i], new_node(x))
        else:
            _, i1, j1, i2, j2 = event
            a = kth(roots[i1], j1)
            b = kth(roots[i2], j2)
            value[a], value[b] = value[b], value[a]

    ans = []
    for i in range(1, n + 1):
        cur = []
        collect(roots[i], cur)
        if cur:
            ans.append(str(len(cur)) + " " + " ".join(map(str, cur)))
        else:
            ans.append("0")
    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```配列`left`、`right`、`size`、 そして`value`Treap ノードをグローバルに保存します。 オブジェクトの代わりに配列を使用すると、生徒の総数が到達できるため、Python メモリのオーバーヘッドが削減されます。$3 \times 10^5$。 

の`merge`新しい学生は常に実験の終了時に参加するため、この関数は追加のみに使用されます。 ランダムな優先順位によってトリープのバランスが保たれるため、高さは高い確率で対数のままになります。 

の`kth`この関数は、最も頻繁に行われるランダム アクセス操作中に不要な再帰を避けるために反復されます。 左側のサブツリーのサイズを使用して、ターゲット位置が左側のサブツリー内にあるか、現在のノードにあるか、右側のサブツリー内にあるかを決定します。 

暗黙的トレプでは明示的なインデックスが保存されないため、最後の走査では順序どおりの順序が使用されます。 ツリーの形状はマージ中に変化しますが、順序どおりのシーケンスは常に実験の順序のままです。

 ## 特殊なケース

 空の実験の場合、アルゴリズムはルートをゼロに保ちます。 最後の走査中に、ゼロルートは空のリストを生成するため、出力行には次の内容のみが含まれます。`0`。 空のシーケンスは自然に表現されるため、treap ロジック内には特別なケースはありません。 

異なるサイズの実験間で交換するには、この 2 つは次の呼び出しを行います。`kth`自分のトラップ内を独立して検索します。 たとえば、実験 1 が`[1,2]`そして実験2は`[3]`、実験 1 の位置 2 を実験 2 の位置 1 と交換すると、保存された値が次のように変更されます。`[1,3]`そして`[2]`。 ツリー構造は移動しないので、他のすべてのインデックスは変更されません。 

一人の学生実験の場合、`kth`受け取る`k = 1`。 左側のサブツリーのサイズはゼロであるため、すぐにそのノードを返します。 これにより、最小の有効なインデックスでの 1 つ違いの間違いが回避されます。
