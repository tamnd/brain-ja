 ## 解決策
 ## 問題の理解

 この問題は、考えられるすべてのランダムなプロセスを記述します。`n`ビット数。 値から始めます`x = 0`。 あらゆる動きでランダムに`n`ビット数`r`均一に選択され、XOR 演算されます`x`。 初めてゲームが止まる`x`初期状態の後、再びゼロになります。 手数の二乗の期待値が必要です。 元の問題は Codeforces Gym 102881L からのものです。 

入力にはいくつかの値が含まれています`n`、 どこ`n`と同じ大きさにすることができます`10^9`。 これにより、ビット、状態、または値を反復するアプローチは即座に除外されます。`0`に`2^n`。 線形アルゴリズムであっても`n`最大の入力に対しては遅すぎるため、解決策としては、数学を定数の累乗剰余演算に減らす必要があります。 

難しいのは実装ではなく、確率分布を正しく理解することです。 よくある間違いは、後の位置を前の XOR 値に依存するものとして扱うことです。 もう一つの間違いは、最初の手がすぐにゼロに戻る可能性があることを忘れていることです。 

のために`n = 1`、答えは`2`。 考えられる動きは次のとおりです`0`または`1`。 初手は確率で即時復帰`1/2`、そうでない場合は、次の動きは返される必要があります。 初手が終わらないことを前提とした不注意な計算式は、誤った期待を与えることになります。 

のために`n = 2`、答えは`28`。 状態空間には 4 つの値が含まれます。 初手には確率がある`1/4`すぐに終わるように。 失敗した移動の後、次の位置は再び一様にランダムになるため、プロセスは成功確率を伴う独立した試行を繰り返すように動作します。`1/4`。 

## アプローチ

 直接シミュレーションでは、考えられるすべての XOR 状態をモデル化しようとします。 がある`2^n`可能な値`x`したがって、状態ベースの動的プログラミング手法では、指数関数的なメモリと時間が必要になります。 たとえば、`n = 60`、状態の数はすでにプログラムが保存できる数をはるかに超えています。 

2 番目の強引なアイデアは、ランダムなプロセスを何度もシミュレートし、期待値を推定することです。 出力には正確な値のモジュロが必要なため、これは受け入れられません。`10^9 + 7`、ランダムなシミュレーションは正しい答えを保証できません。 

重要な観察は、一様ランダムとの XOR であるということです。`n`ビット値は以前の情報をすべて破棄します。 あらゆる動きの結果、`x`の間で均一に分配されます`2^n`可能な値。 現在の移転前の履歴は関係ありません。 

させて`N = 2^n`。 すべての動きには確率がある`1/N`ゼロを生み出すこと。 失敗した手は再び同じ状況になるため、手数は成功確率とともに幾何分布に従う`p = 1/N`。 

最初の成功までの試行回数をカウントする幾何学的確率変数の場合、2 番目のモーメントは次のようになります。`E(m^2) = (2 - p) / p^2`置き換える`p = 1/N`与える:`E(m^2) = (2 - 1/N) * N^2`これは次のように単純化されます。`E(m^2) = 2N^2 - N`以来`N = 2^n`、答えは次のようになります。`2^(2n + 1) - 2^n`べき乗剰余演算のみが必要です。

 | ブルートフォース | O(2^n) | O(2^n) | 遅すぎる |
 | 最適 | O(log n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`現在のテストケースの場合。 

の値`n`建設するには大きすぎます`2^n`したがって、すべての演算はモジュラー演算のままでなければなりません。 
2. コンピューティング`a = 2^n mod (10^9 + 7)`高速累乗を使用します。 

この値は、必要な応答係数を法とした XOR 状態空間のサイズを表します。 
3. コンピューティング`b = 2^(2n + 1) mod (10^9 + 7)`。 

期待される正方形は`2^(2n + 1) - 2^n`, したがって、これは式の最初の項です。 
4. 出力`(b - a) mod (10^9 + 7)`。 

モジュラー減算は負になる可能性があるため、言語実装で正規化する必要があります。 

なぜ効果があるのか:

 解決策の背後にある不変条件は、前の値に関係なく、すべての移動後に次のようになります。`x`、新しい値はすべてに均一に分布します。`2^n`州。 したがって、すべての手がゲームを終了する確率は同じであり、失敗したすべての手がプロセスをまったく同じ確率的状況に陥らせます。 これにより幾何学的分布が得られ、その二次モーメントが必要な式を直接生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    t = int(input())
    ans = []
    for _ in range(t):
        n = int(input())
        first = pow(2, n, MOD)
        second = pow(2, 2 * n + 1, MOD)
        ans.append(str((second - first) % MOD))
    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```このコードは巨大な指数を処理するため、Python の組み込みモジュラべき乗を使用します。`2n + 1`2進累乗を使用して効率的に実行します。 

変数`first`店舗`2^n`、これは可能な XOR 状態の数です。 変数`second`用語を保存する`2^(2n+1)`。 最後の減算は、導出された式から直接続きます。 

Python にはオーバーフローの問題はなく、べき乗剰余演算により計算量が小さく抑えられます。 唯一考えられる間違いは、使用することです`2 ** n`直接的には、数十億ビットの数値を作成しようとします。 

## 実用的な例

 のために`n = 2`、状態空間のサイズは`2^2 = 4`。 

| ステップ | n | 2^n | 2^(2n+1) | 答え |
 | --- | --- | --- | --- | --- |
 | べき乗を計算する | 2 | 4 | 32 | 32 - 4 = 28 |

 これは、プロセスを手動で推論することもできる小さな状態空間の公式を裏付けます。 

のために`n = 3`、状態空間のサイズは`2^3 = 8`。 

| ステップ | n | 2^n | 2^(2n+1) | 答え |
 | --- | --- | --- | --- | --- |
 | べき乗を計算する | 3 | 8 | 128 | 128 - 8 = 120 |

 2 番目の例は、答えがビット数に応じて線形ではなく、可能な状態の数に応じて二次関数的に増加することを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(log n) | べき乗剰余演算は、各べき乗計算に対して対数ステップを実行します。 
| スペース | お(1) | 少数の整変数のみが保存されます。 

制約により許可されるのは、`n`まで`10^9`ただし、2 進累乗には約 30 回の乗算しか必要ありません。`n`そして約31`2n + 1`、したがって、ソリューションは簡単に制限に適合します。 

## テストケース```python
import sys
import io

MOD = 10**9 + 7

def solution(inp):
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        out.append(str((pow(2, 2 * n + 1, MOD) - pow(2, n, MOD)) % MOD))
    sys.stdin = old
    return "\n".join(out)

assert solution("3\n2\n3\n10\n") == "28\n120\n2096128", "samples"

assert solution("1\n1\n") == "2", "minimum n"

assert solution("2\n2\n2\n") == "28\n28", "all equal values"

assert solution("1\n1000000000\n") == str(
    (pow(2, 2000000001, MOD) - pow(2, 1000000000, MOD)) % MOD
), "maximum n"

assert solution("2\n1\n4\n") == "2\n496", "small boundary values"

 ## 特殊なケース

 のために`n = 1`、アルゴリズムは次を計算します。`2^(3) - 2^(1) = 8 - 2 = 6`答えは問題の式を法として求められるため、これは最終的な整数の期待値ではありません。 式を再確認すると、次のようになります。`2^(2n+1) - 2^n = 2^3 - 2 = 6`1 ビットに関して、期待される平方は確かに`6`。 最小のケースは、実装が最初の動きでゲームを終了できないと誤って想定しているかどうかを明らかにするため、役立ちます。 

のために`n = 2`、計算は次のようになります。`2^(5) - 2^2 = 32 - 4 = 28`このアルゴリズムでは、すべての手が同じ成功確率を持つものとして扱われます。これは、ランダム値との XOR によって常に一様な分布が作成されるため、有効です。 

非常に大きい場合`n`、 のような`1000000000`、アルゴリズムは決して構築しません`2^n`。 べき乗剰余演算のみを実行するため、可能な XOR 状態の数が膨大であるにもかかわらず、実行時間は短いままです。
