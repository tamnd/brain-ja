 ## 解決策
 ## 問題の理解

 無向グラフで表された国があります。 人は 0 日目に未知の都市からスタートし、同じ都市に留まるか、1 日に 1 本の道を移動することができます。 入手可能な唯一の情報は、爆弾爆発の時系列リストです。 それぞれの爆発記録には日付と都市が示されており、爆発日より遅くともその都市に爆弾が設置されたことを意味します。 爆弾は仕掛けられたのと同じ順序で爆発することが保証されているため、最初のログ エントリは最初に仕掛けられた爆弾に対応し、2 番目のエントリは 2 番目に仕掛けられた爆弾に対応し、以下同様となります。 

タスクは、爆発ログ全体を生成できる開始都市の数を数えることです。 

グラフには最大 2,000 の都市と 10,000 の道路が含まれますが、爆発レコードの数は 1000,000 に達する可能性があります。都市の数は十分に小さいため、都市のすべてのペア間の情報を計算することは可能ですが、考えられるすべての経路を処理することは不可能です。 すべての開始都市、すべてのイベント、およびすべての可能な移動シーケンスを含むアプローチは、限界をはるかに超えています。 100 万件のイベントにより、前処理を行った後に O(q) またはそれに近いスキャンを使用する必要があります。 

主なエッジケースは、爆弾が設置された直後に爆発する必要がないという事実から生じます。 たとえば、都市 3 で 10 日目に爆発した爆弾は 2 日目に仕掛けられた可能性があるため、爆発日を正確な訪問日として使用すると誤った結果が得られます。 もう 1 つの問題は、爆発日に大きなギャップがある場合でも、植栽の順序が重要であることです。 例えば：```
3 2 2
1 2
2 3
1 3
2 1
```正しい出力は次のとおりです。```
1
```2 番目の爆弾は最初の爆弾の後に仕掛けられたに違いありません。 開始都市が各爆発都市に個別に到達できるかどうかだけをチェックする不用意な解決策では、さらに多くの都市がカウントされる可能性があります。 

もう 1 つのエッジ ケースは、連続して仕掛けられた爆弾の間を移動する時間がない場合です。 例えば：```
2 1 2
1 2
1 1
1 2
```正しい出力は次のとおりです。```
0
```本部が都市 1 の場合、最初の爆弾は都市 1 の 0 日目に設置する必要がありますが、2 番目の爆弾もその後に設置する必要があります。 都市 1 から都市 2 に移動できる日はありません。 

## アプローチ

 直接的なアプローチでは、考えられるすべての本部都市を試し、爆発シーケンスが満たされるかどうかをシミュレートします。 事前に計算された最短経路を使用する場合でも、すべての開始都市に対してすべてのイベントを繰り返しチェックする必要があります。 最悪のケースは約 O(nq) になり、これは最大入力の約 2 * 10^9 チェックに合格しません。 

重要な観察は、爆弾が仕掛けられた正確な日を追跡する必要がないということです。 私たちが知る必要があるのは、それぞれの爆弾がどれくらい遅れて設置されたかを知ることだけです。 最後の爆弾が都市 c に d までに仕掛けられたと仮定します。 最も遅い植え付け時期は単純に d です。 ログを逆に進むと、前の爆弾は、その人がその都市から次の爆弾が設置された都市まで歩くのに十分な時間がある十分な早めに設置されなければなりません。 

i 番目の爆弾が都市 c_i にあり、次の爆弾が時刻 L_(i+1) までに設置できる場合、i 番目の爆弾は遅くとも次の時刻までに設置できます。 

L_i = min(d_i, L_(i+1) - dist(c_i, c_(i+1)))

 L_1 を計算した後、最初の爆弾は本部が L_1 日以内に c_1 に到達できることのみを必要とします。 有効な本社はすべて、c_1 への最短経路距離が最大でも L_1 である都市です。 

グラフは重み付けされていないため、グラフ サイズにより、すべての都市から BFS を介してすべてのペアの最短パスが実現可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 最適 | O(n(n+m)+q) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての都市間の最短距離を計算します。 道路のコストは等しいため、すべての都市から BFS を 1 回実行します。 結果として得られる距離行列により、任意の 2 つの爆弾設置場所間を移動するのに必要な時間を即座に答えることができます。 
2. 爆発ログを読み、日付と都市を順番に記録します。 出来事は時系列で示されていますが、必要な計算は最後の爆弾から遡って行われます。 
3. 最後のイベントから開始します。 それを制限できる爆弾が後から存在しないため、最も遅い設置可能時間は爆発の日です。 
4. 最後から 2 番目のイベントから最初のイベントに移動します。 すべての爆弾について、次の爆弾までの移動に必要な最短時間だけ期限を短縮します。 また、自身の爆発日も上限として尊重します。 
5. 最初の爆弾の最も遅い設置可能時間を見つけた後、最初の爆弾都市までの距離がその値を超えないすべての都市を数えます。 

逆方向スキャンの背後にある不変条件は、爆弾 i を処理した後、格納される期限は、爆弾 i を植えることができる最も遅い日であると同時に、爆弾以降のすべての爆弾が順番に植えられることを許可するということです。 移行では次のステップに必要な最小移動時間が正確に差し引かれるため、考えられるすべてのスケジュールが計算された境界を満たす必要があります。 逆に、前の爆弾の後に必要なだけすぐに後続の爆弾を設置すると、境界が負でない場合はいつでも有効なスケジュールが構築されます。 

## Python ソリューション```python
import sys
from collections import deque
from array import array

input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())

    graph = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append(v)
        graph[v].append(u)

    dist = []
    for s in range(n):
        cur = [-1] * n
        cur[s] = 0
        dq = deque([s])
        while dq:
            u = dq.popleft()
            for v in graph[u]:
                if cur[v] == -1:
                    cur[v] = cur[u] + 1
                    dq.append(v)
        dist.append(cur)

    days = array('i')
    cities = array('h')
    for _ in range(q):
        d, c = map(int, input().split())
        days.append(d)
        cities.append(c - 1)

    latest = days[-1]
    for i in range(q - 2, -1, -1):
        latest = min(latest - dist[cities[i]][cities[i + 1]], days[i])
        if latest < 0:
            print(0)
            return

    first = cities[0]
    ans = 0
    for x in range(n):
        if dist[x][first] <= latest:
            ans += 1
    print(ans)

solve()
```BFS フェーズでは、後方動的計算で使用される距離行列を構築します。 グラフは重み付けされていないため、各 BFS は都市間の移動に必要な最小日数を示します。 

イベントを格納する配列により、100 万レコードの Python リストによる大きなメモリ オーバーヘッドが回避されます。 逆ループには現在の締め切りと次の都市の関係のみが必要なので、イベント リスト全体は複製されません。 

逆ループでの減算は、実装の重要な詳細です。 現在の爆発日制限を適用する前に、連続する爆弾の位置間の距離を差し引きます。 値がマイナスになると、どんなに早い植付順序であってもログを満たすことができなくなります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n(n+m)+q) | BFS はすべての都市から実行され、イベント ログが 1 回スキャンされます。 
| スペース | O(n²+q) | 距離マトリックスとコンパクトなイベント ストレージが維持されます。 

n が 2000 に等しい場合、BFS の前処理は約 2,400 万回のエッジ チェックになります。 残りの作業は、最大 100 万件のイベントを 1 回通過するだけであり、制限内に問題なく収まります。

 ## 特殊なケース

 不可能な注文の例:```
2 1 2
1 2
1 1
1 2
```最後の爆弾の期限は 1 です。逆に考えると、2 番目の都市に移動するには 1 日かかるため、最初の爆弾は遅くとも 0 日目までに設置する必要があります。 最初の爆弾は 1 日目に爆発するため、期限は 0 のままです。必要な順序を満たしながら 0 日以内に最初の爆弾都市に到達できる都市はないため、答えは 0 です。 

単一の爆弾の場合:```
4 2 1
1 2
3 4
5 1
```爆弾は都市 1 に 0 日目から 5 日目までのいつでも設置できた可能性があります。本部は都市 1 または都市 2 に設置できますが、都市 3 または 4 には接続されていないため、設置することはできません。 このアルゴリズムは最初の爆弾都市までの距離のみをチェックするため、まさにこれら 2 つの可能性が得られます。
