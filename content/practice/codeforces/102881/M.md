 ## 問題の理解

 シーケンスは次のすべての整数で始まります。`1`まで`n`。 各整数はその 10 進数の合計で置き換えられ、その桁の合計が厳密に増加する最も長い部分列の長さを見つけることがタスクとなります。 部分列は元の数値の順序を維持する必要があるため、桁の合計を並べ替えることはできません。 

難しさはサイズから来ます`n`。 番号には最大で次の値を含めることができます`100000`数字なので、すべての数字を読み取っても、`1`に`n`不可能です。 シーケンスの反復処理に依存するアプローチは、利用可能な入力サイズと比較して指数関数的にスケールが大きくなります。 の 10 進表現に直接作用するメソッドが必要です。`n`。 

有用な観察は、変換されたシーケンス内のすべての値が正の整数であり、厳密に増加するシーケンスには各値の出現が最大 1 つ含まれるため、答えは表示される最大桁の合計よりも大きくならないということです。 

逆方向がポイントです。 可能な最大桁合計が`m`、その後、桁の合計が以下になる数字を選択することができます。`1, 2, 3, ..., m`この順序で。 左から右に桁を増やすと、より大きな桁の合計を持つ数値を作成できるため、一連の桁の合計には当然これらの増加する値が含まれます。 結果として、LIS の長さは、次の数値によって達成可能な最大桁数の合計となります。`1`に`n`。 

エッジ ケースはすべて、最大桁数の合計の計算に関連しています。 たとえば、入力が次の場合:```
10
```桁の合計は次のとおりです。```
1 2 3 4 5 6 7 8 9 1
```正しい出力は次のとおりです。```
9
```不注意な解決策では、次の桁の合計が使用される可能性があります。`n`それ自体と出力`1`、次のような小さい数値は無視されます。`9`桁の合計がはるかに大きくなります。 

別のケースは次のとおりです。```
100
```最大桁合計は依然として`18`、によって達成されました`99`。 番号`100`桁の合計があります`1`したがって、最後の数字だけを見ると間違った結果が得られます。 

次のような桁数の多い数値の場合:```
777
```最大桁合計は`21`、の桁の合計`777`。 最高の数字は、`699`、その桁の合計は`24`、答えは次のようになります。```
24
```## アプローチ

 直接的なアプローチは、次からすべての数値を生成することです。`1`に`n`、その桁の合計を計算し、標準の最長増加部分列アルゴリズムを実行します。 これが機能するのは、LIS が元の数値ではなく、桁の合計の順序にのみ依存するためです。 問題はそれです`n`持つことができる`100000`桁数が多いため、生成される値の数は信じられないほど多くなります。 たとえ`O(n log n)`次の場合には LIS 実装を開始できません`n`それ自体は通常のメモリに収まりません。 

重要な削減点は、シーケンス全体が必要ないということです。 答えは、表示される最大桁の合計によってのみ決まります。 その値がわかったら、有効な増加サブシーケンス内で、より小さな正の数字の合計をその前に置くことができます。 この問題は桁操作の問題になります。指定された巨大な整数を超えないすべての整数の桁の最大合計を見つけます。 

上限の下で桁の合計を最大化するには、数値をできるだけ大きくしながら、後の桁をできるだけ大きくする必要があります。 プレフィックスが以下より小さくなった場合`n`、その後のすべての数字は次のようになります。`9`。 これにより、通常の貪欲な候補が得られます。番号をそのままにするか、ゼロ以外の桁を 1 つ減らして、後続のすべての桁を次の桁に置き換えます。`9`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n log n) | O(n) | 遅すぎる |
 | 最適 | O(k) | お(1) | 承認済み |

 ここ、`k`の桁数です`n`。 

## アルゴリズムのチュートリアル

 1. 数値には次の値を含めることができるため、数値を文字列として読み取ります。`100000`数値であり、組み込みの整数型には収まりません。 
2. 元の数値の桁の合計を計算します。 これも候補の一つなので、`n`それ自体が最大桁合計を持つ可能性があります。 
3. ゼロ以外の数字を 1 回ずつ減らしてみます。 ポジションを下げた後`i`、その後のすべての数字は次のようになります。`9`それは、以下の可能な最大の数を作成するためです。`n`選択したプレフィックスを付けます。 
4. これらすべての候補の中で最大の桁の合計を保持します。 この値が答えです。 

なぜ効果があるのか:

 しましょう`M`以下の数値の最大桁合計になります。`1`に`n`。 変換されたすべての値は範囲に属します`1`に`M`、したがって、増加するサブシーケンスはこれよりも長い長さを持つことはできません。`M`。 

下限については、任意の桁の合計を考慮します。`x`から`1`に`M`。 最大桁数の合計を貪欲に構築すると、最大値までのすべての値に数値の昇順で到達できることがわかります。 これらの数値を取得すると、桁の合計を含む部分列が得られます。`1,2,...,M`。 LIS の長さは少なくとも`M`、上限は最大でも`M`、つまり、答えは正確に`M`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    digits = list(map(int, s))
    n = len(digits)

    ans = sum(digits)

    for i in range(n):
        if digits[i] == 0:
            continue

        cur = sum(digits[:i]) + (digits[i] - 1) + 9 * (n - i - 1)
        ans = max(ans, cur)

    print(ans)

if __name__ == "__main__":
    solve()
```通常の整数型では値を表すことができないため、入力は文字列として保存されます。`100000`数字。 最初の候補は次の桁の合計です。`n`自体。 

ループは、数値を小さくできるすべての位置を考慮します。 その数字を 1 つ減らすと、プレフィックスは有効なままとなり、サフィックスには次の値が入ります。`9`s は、その小さい接頭辞を持つすべての数値の可能な最大の桁の合計を示します。 すべての候補の最大値が、必要な LIS 長になります。 

答えは最大でも次の合計のみであるため、オーバーフローの懸念はありません。`100000`桁なので、最大でも`900000`。 この実装では、変更された文字列の作成が回避され、累計のみが使用されます。

## テストケース```python
import sys
import io

def solve_case(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    s = sys.stdin.readline().strip()

    digits = list(map(int, s))
    n = len(digits)

    ans = sum(digits)

    for i in range(n):
        if digits[i] != 0:
            ans = max(ans, sum(digits[:i]) + digits[i] - 1 + 9 * (n - i - 1))

    sys.stdin = old_stdin
    return str(ans) + "\n"

assert solve_case("10\n") == "9\n", "sample 1"
assert solve_case("99\n") == "18\n", "sample 2"

assert solve_case("1\n") == "1\n", "minimum input"
assert solve_case("100000\n") == "27\n", "large boundary pattern"
assert solve_case("99999\n") == "45\n", "all digits equal to maximum"
assert solve_case("101\n") == "10\n", "off by one around zeros"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 のために`10`、アルゴリズムは、元の桁の合計と、最初の桁を減らすことによって形成された候補をチェックします。 オリジナルが与える`1`、変化しながら`10`の中へ`9`桁の合計を与える`9`、したがって、答えは次のとおりです`9`。 

のために`100`、元の数値のみが寄与します`1`。 最初の桁を減らすと、`099`を表します`99`、桁の合計付き`18`。 アルゴリズムはこの候補を見つけて返します。`18`。 

のために`777`、元の桁の合計は`21`。 最初の桁を減らすと、`699`、その桁の合計は`24`。 アルゴリズムはこれが優れていることを検出し、出力します`24`。 

次のような数値の場合、`101`、最初の桁を減らすと、`99`、 ない`100`, なぜなら、後続の数字はすべて`9`。 これにより、桁の合計を最大化する際に先頭のゼロを誤って扱うというよくある間違いを回避できます。
