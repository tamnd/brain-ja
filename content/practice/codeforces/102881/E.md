 ## 解決策
 ## 問題の理解

 正の整数の配列があります。 更新では、連続した範囲が選択され、その範囲内のすべての数値に 2 つのビット単位の変換のうちの 1 つが適用されます。 最初の変換は値を置き換えます`x`と`x | (x - 1)`、2番目はそれを次のように置き換えます`x ^ (x - 1)`。 更新のたびに、配列の合計を出力する必要があります。 

重要な部分は、これら 2 つの式がビットに対して実際に何を行うかを理解することです。 もし`x`もっている`k`末尾のゼロ、その後`x - 1`それらの 0 を正確に 1 に変更し、最下位の 1 ビットを 0 に変更します。 

のために`x | (x - 1)`、後続のゼロはすべて 1 になりますが、残りのビットは変更されません。 例えば、`12 (1100)`になる`15 (1111)`。 この操作では、末尾に 0 が 1 つ以上ある数値のみが変更され、その後の数値は奇数になります。 

のために`x ^ (x - 1)`、設定された最下位ビットから下のすべてのビットが 1 になり、上位ビットはすべて消えます。 の値`k`末尾のゼロは次のようになります`2^(k+1)-1`。 例えば、`12 (1100)`になる`7 (0111)`。 これも常に奇数を生成します。 

制約が大きい: 配列サイズと演算数の両方が制限に達する可能性があります。`3 * 10^5`。 範囲内のすべての要素に触れるソリューションは、最悪の場合のパフォーマンスが低下するため、遅すぎます。`9 * 10^10`要素の更新。 多くの要素を一度に要約できる対数データ構造が必要です。 

よくある間違いは、合計だけを追跡することです。 合計だけでは、将来の操作によって数値がどのように変化するかを知ることはできません。 たとえば、値`4`そして`6`両方の合計は組み合わせることができますが、2 番目の操作では動作が異なります。 欠落している情報は、末尾のゼロの数です。 

もう 1 つの特殊なケースは、2 のべき乗を含む範囲です。 入力の場合:```
1 1
8
1 1 1
```答えは次のとおりです。```
15
```なぜなら`8 (1000)`になる`15 (1111)`。 値が奇数になるだけであると仮定した解決策では、追加された下位ビットが失われます。 

別の特殊なケースは、最初の操作の後に 2 番目の操作を適用することです。 のために：```
1 2
4
1 1 1
2 1 1
```出力は次のとおりです。```
7
1
```最初の更新では、`7`、2番目の更新で変更が加えられます`7`に`1`。 元の値に 2 番目の演算を適用する不注意な実装`4`誤って生成してしまう`7`。 

## アプローチ

 直接的な解決策では、各クエリ範囲内のすべての位置を反復し、ビット演算を使用して新しい値を計算します。 各操作は要素ごとに独立しているため、これは正しいです。 ただし、`n`そして`q`どちらも等しい`300000`、最悪の場合にはおおよその内容が含まれます`n * q`要素の変更は可能時間を大幅に超えています。 

重要な観察は、変換が後続のゼロの数のみに依存するということです。 いずれかの操作の後、数値は奇数になるため、その要素のその後の動作ははるかに単純になります。 これは、セグメント ツリーがすべての正確な値を保存する必要がないことを意味します。 必要なのは、セグメント内の末尾ゼロのカウントが考えられる値の数と、セグメントの合計を知ることだけです。 

もう 1 つ微妙な点があります。 セグメント ツリーの遅延伝播では、セグメントが更新されたことだけでなく、どの変換シーケンスをその子に渡す必要があるかを記憶する必要があります。 可能な保留中の変換は小さいです。 それらは、アイデンティティ、第一の操作、第二の操作、そしてすべてを変える一定の操作です。`1`。 変換を繰り返すとすぐにそのうちの 1 つに崩れてしまうため、これら 4 つの状態で十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 最適 | O((n + q) log n * 20) | O(n * 20) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. セグメントツリーを構築します。 すべてのノードについて、そのセグメントと配列の合計を保存します。`cnt[i]`正確に持つ値の数です`i`末尾のゼロ。 子にプッシュする必要がある操作を記述する遅延変換を保存します。 

表示できる最大値は以下のとおりです`2^19`したがって、最大 19 個の末尾のゼロが可能です。 
2. 最初の操作をセグメント全体に適用すると、すべての値が`i > 0`末尾のゼロは次のように増加します`2^i - 1`。 この変更後は、すべての値が奇数になります。 

保存されたカウントを使用して合計を更新し、すべてのカウントを`cnt[0]`。 
3. セグメント全体に 2 番目の操作を適用する場合、`i`末尾のゼロは次のようになります`2^(i+1)-1`。 新しい合計はカウントから直接計算できます。 

繰り返しますが、結果として得られる値はすべて奇数であるため、セグメント全体が次のようになります。`cnt[0]`。 
4. 変換を合成した結果として得られる定数演算を適用すると、すべての値は次のようになります。`1`。 合計がセグメント長になり、すべての値の末尾にゼロが付きます。 
5. 部分的な範囲更新の場合は、降順の前に保留中の遅延変換を子にプッシュします。 その後、合計と末尾のゼロのカウントを加算して、子をマージします。 
6. 更新するたびに、平方根の合計が答えになります。 

なぜ効果があるのか:

 セグメント ツリーは、操作に必要な情報を正確に保持します。 どちらのビット単位の演算の効果も、元の値の末尾のゼロのカウントにのみ依存します。 保存されたカウントにより、個々の値を知らなくても新しい合計を計算できます。 すべての変換は 4 つの遅延状態のいずれかで表すことができ、これらの状態は正しく構成されるため、遅延更新は常に、操作をすべての要素に直接適用した場合と同じ結果を生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXB = 20

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    size = 4 * n
    tree_sum = [0] * size
    cnt = [[0] * MAXB for _ in range(size)]
    lazy = [0] * size

    def tz(x):
        return (x & -x).bit_length() - 1

    def apply(node, l, r, op):
        length = r - l + 1

        if op == 1:
            add = 0
            for i in range(1, MAXB):
                add += cnt[node][i] * ((1 << i) - 1)
            tree_sum[node] += add

        elif op == 2:
            new_sum = 0
            for i in range(MAXB):
                new_sum += cnt[node][i] * ((1 << (i + 1)) - 1)
            tree_sum[node] = new_sum

        else:
            tree_sum[node] = length

        cnt[node][0] = length
        for i in range(1, MAXB):
            cnt[node][i] = 0

    def compose(old, new):
        if new == 0:
            return old
        if old == 0:
            return new

        if old == 1 and new == 1:
            return 1
        if old == 2 and new == 2:
            return 3
        if old == 1 and new == 2:
            return 3
        if old == 2 and new == 1:
            return 2
        if old == 3:
            return 3
        if new == 3:
            return 3

        return new

    def push(node, l, r):
        if lazy[node] and l != r:
            mid = (l + r) // 2
            op = lazy[node]
            apply(node * 2, l, mid, op)
            apply(node * 2 + 1, mid + 1, r, op)
            lazy[node * 2] = compose(lazy[node * 2], op)
            lazy[node * 2 + 1] = compose(lazy[node * 2 + 1], op)
            lazy[node] = 0

    def build(node, l, r):
        if l == r:
            tree_sum[node] = a[l]
            cnt[node][tz(a[l])] = 1
            return
        mid = (l + r) // 2
        build(node * 2, l, mid)
        build(node * 2 + 1, mid + 1, r)
        pull(node)

    def pull(node):
        tree_sum[node] = tree_sum[node * 2] + tree_sum[node * 2 + 1]
        for i in range(MAXB):
            cnt[node][i] = cnt[node * 2][i] + cnt[node * 2 + 1][i]

    def update(node, l, r, ql, qr, op):
        if qr < l or r < ql:
            return
        if ql <= l and r <= qr:
            apply(node, l, r, op)
            lazy[node] = compose(lazy[node], op)
            return

        push(node, l, r)
        mid = (l + r) // 2
        update(node * 2, l, mid, ql, qr, op)
        update(node * 2 + 1, mid + 1, r, ql, qr, op)
        pull(node)

    build(1, 0, n - 1)

    ans = []
    for _ in range(q):
        t, l, r = map(int, input().split())
        update(1, 0, n - 1, l - 1, r - 1, t)
        ans.append(str(tree_sum[1]))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```の`cnt`配列は実装の中核です。 これらは、両方の変換に必要な情報を正確に保持しながら、個々の値の保存を回避します。 

の`apply`関数は完全なセグメント更新を処理します。 最初の 2 つのケースでは、末尾のゼロの頻度から新しい合計を計算します。 最後のケースは、いくつかの保留中の操作を組み合わせて、すべての値を強制的に変換する場合に使用されます。`1`。 

の`compose`関数は、一般的な遅延伝播のバグを防ぎます。 順序が重要であるため、後の操作で以前の遅延フラグを単純に置き換えることはできません。 たとえば、最初の操作を適用してから 2 番目の操作を適用することは、2 番目の操作のみを適用することと同じではありません。 

再帰では内部でゼロから始まるインデックスが使用されます。 入力範囲は更新中に 1 回変換されるため、繰り返しの変換や 1 つずつの間違いが回避されます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + q) log n * 20) | すべてのセグメント操作は O(log n) ノードに触れ、各ノードの更新では 20 個の末尾ゼロの可能性のあるカウントがスキャンされます。 |
 | スペース | O(n * 20) | 各セグメント ツリー ノードには、20 個のカウンターといくつかの追加の値が格納されます。 |

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import builtins
    data = sys.stdin.read().split()
    if not data:
        return ""
    it = iter(data)
    n = int(next(it))
    q = int(next(it))
    arr = [int(next(it)) for _ in range(n)]

    res = []

            if t == 1:
                arr[i] |= arr[i] - 1
            else:
                arr[i] ^= arr[i] - 1
        res.append(str(sum(arr)))
    return "\n".join(res)

 ## 特殊なケース

 2 のべき乗の場合:```
1 1
8
1 1 1
```値`8`末尾にゼロが 3 つあります。 最初の操作は追加します`2^3 - 1 = 7`、与える`15`。 セグメント ツリーには 1 つの値が格納されます。`cnt[3]`したがって、増加分を直接計算し、値を次の値に移動します。`cnt[0]`。 

合成の場合:```
1 2
4
1 1 1
2 1 1
```最初のアップデート後、`4`になる`7`、奇数として表されます。 2 番目の更新では、すべての奇数の値が次のようになります。`1`。 遅延状態の構成では、保留中の変換が 2 つの操作を個別に誤って処理するのではなく、組み合わされた結果であることが記録されます。
