 ## 解決策
 # 問題の理解

 接続された重み付きグラフと正の値の配列が与えられます。`s`。 タスクは、最小のインデックス付き頂点を見つけることです。`x`すべての頂点に書かれた値がちょうどからの最短距離になるようにします。`x`その頂点へ。 特別な条件は、`x`は有効な長さ 0 のパスとはみなされないため、次の値は`x`それ自体は、で始まり、で終わる空ではない最短の閉じたウォークの長さです。`x`。 グラフには正のエッジの重みがあり、平行なエッジや自己ループはありません。 

制限が十分に大きいため、すべての頂点を開始点として試すことは不可能です。 まで`2 * 10^5`頂点とエッジでは、単一のダイクストラ実行は許容されますが、すべての頂点から 1 回実行するには、おおよその時間がかかります`O(n * (n + m) log n)`利用可能な時間をはるかに超えた操作。 このソリューションでは、考えられるすべての開始頂点に関する情報を同時に抽出する必要があります。 

この問題の特殊な部分は、ソース頂点に格納されている値です。 通常の最短パス配列では、ソースには次のものが含まれます。`0`。 ここには、その頂点で開始および終了する最短の正のサイクルが含まれています。 正の重みを持つ無向グラフでは、最も安価な閉じたウォークは最も軽い隣接エッジを横切ってすぐに戻ることができるため、この値はその頂点に入射する最小エッジ重みの 2 倍になります。 

よくある間違いは、他のすべての頂点までの距離が正しい頂点を受け入れながら、その頂点自体の値を確認するのを忘れることです。 例えば：```
3 2
4 2 2
1 2 2
2 3 2
```正しい出力は次のとおりです`2`。 頂点`2`頂点に達する`1`そして`3`距離的に`2`、空でない場合の最短の戻りの散歩も`4`。 他の頂点までの距離だけをチェックする不用意なソリューションでは、頂点が誤って受け入れられる可能性があります。`1`または`3`、いくつかの頂点までの外側の距離は同じですが、それらの自己距離は次のとおりである必要があるためです。`4`、 ない`2`。 

複数の頂点が配列を満たす可能性がある場合、別のエッジ ケースが発生します。 この問題では最小のインデックスが求められます。 例えば：```
4 4
6 3 6 6
1 3 6
1 2 3
3 2 3
4 2 3
```正しい出力は次のとおりです`1`。 いくつかの距離関係は対称的に見えますが、最小の有効なインデックスのみを出力する必要があります。 

最後の罠は、不可能な距離の配列です。 例えば：```
3 3
1 5 5
1 2 2
2 3 2
1 3 10
```出力は`-1`。 値は、グラフが実際に許容する距離よりも短い距離で一部の頂点に到達できるため、開始頂点が配列を生成できないことを主張しています。 

## アプローチ

 簡単なアプローチは、すべての頂点を原点の候補としてテストすることです。 選択した頂点に対して`x`、からディクストラを実行します。`x`、計算されたすべての距離を次と比較します。`s`、さらに特別な値であることを確認します。`s[x]`からの最短の空でない閉じたウォークに一致します`x`。 これは定義を直接チェックするので正しいです。 ただし、最悪の場合は、`n`ディクストラが走る。 と`n`そして`m`両方の周りに`200000`、これはおおよそになります`200000 * 400000 log(200000)`実行不可能な操作です。 

重要な観察は、配列全体を新しい人工頂点から見ることができるということです。 仮想頂点を作成する`z`そしてそれを元のすべての頂点に接続します`i`重量のあるエッジで`s[i]`。 配列が何らかのソースに対して有効な場合`x`、からの最短距離`z`すべての頂点が正確に`s[i]`。 直接エッジによってこの距離が与えられ、ラベルがすでに最短距離のように動作しているため、元のグラフ エッジを使用するパスをこれより短くすることはできません。 

残りの問題は、どの頂点が本当のソースであった可能性があるかということです。 有効なソースの場合`x`、人工エッジ`z -> x`到達する唯一の方法ではありません`x`距離を置いて`s[x]`。 から行けます`z`他の頂点へ`u`、支払い`s[u]`、その後、元のグラフを移動して、`x`。 これは、からの最短の空でない閉じたウォークに対応します。`x`。 

そこで、最初にすべての頂点が距離のあるソースとして機能するマルチソース ダイクストラを実行します。`s[i]`。 このプロセス中、すべての頂点に到達する 2 つの最適な距離を維持しますが、2 つの距離は異なる開始頂点から取得する必要があります。 頂点の 2 番目に優れたソース`i`正確な長さのパスが存在するかどうかを示します`s[i]`それは人工的なエッジから始まるものではありません`i`。 それが存在するなら、`i`考えられる答えです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n(n + m) log n) | O(n + m) | 遅すぎる |
 | 最適 | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての元の頂点をマルチソース ダイクストラのソースとして初期化します。 頂点`i`距離から始まる`s[i]`およびソース識別子`i`。 これは、仮想頂点を明示的に保存せずに追加することをシミュレートします。 
2. ダイクストラ中に、すべての頂点に対して最適な距離と 2 番目に最適な距離を維持します。この場合、2 つの保存されたエントリは異なるソース識別子を持つ必要があります。 最初の原点は単純に直接の人工エッジである可能性があるため、2 つの異なる原点のみを考慮します。 
3. グラフのエッジを通常どおりリラックスさせます。 パスが頂点に到達すると、ソース識別子がすでに存在するかどうかに応じて、その最良のエントリまたは 2 番目に最適なエントリのいずれかを更新します。 
4. ダイクストラが終了したら、すべての頂点を昇順にチェックします。 最初の条件は、頂点に到達する最適な距離が等しい必要があることです。`s[i]`。 これより短い距離が存在する場合、指定された配列は最短パス ツリーを表すことができません。 
5. 2 番目の条件は、2 番目に最適な距離も等しい必要があることです。`s[i]`。 これは、頂点自体を人為的な開始点として使用せずに、同じ値で頂点に到達できることを意味します。これはまさに、ソースに戻る必要な空でないパスです。 
6. 両方の条件を満たす最初の頂点を出力します。 存在しない場合は出力`-1`。 

なぜ効果があるのか:

 マルチソース ダイクストラは、概念的にすべての頂点に接続された仮想ソースからの最短パスを計算します。 有効な距離配列とは、すべての頂点が人工的な直接距離を可能な限り最短の距離に保つ必要があることを意味します。 唯一の特別な頂点は実際のソースです。これは、その直接の人工エッジが禁止されたゼロ移動パスを表すためです。 別のソースからの等しい長さのパスの存在は、元のグラフ内での実際のウォークによって値を生成できることを証明しています。 したがって、2 番目に最適な距離基準は、考えられる元の音源を正確に識別します。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    s = list(map(int, input().split()))

    graph = [[] for _ in range(n)]
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append((v, w))
        graph[v].append((u, w))

    INF = 10**30

    best_d = [INF] * n
    best_o = [-1] * n
    second_d = [INF] * n
    second_o = [-1] * n

    heap = []

    for i, x in enumerate(s):
        best_d[i] = x
        best_o[i] = i
        heapq.heappush(heap, (x, i, i))

    def update(v, d, o):
        if best_o[v] == o:
            if d < best_d[v]:
                best_d[v] = d
                return True
            return False

        if second_o[v] == o:
            if d < second_d[v]:
                second_d[v] = d
                return True
            return False

        if d < best_d[v]:
            second_d[v] = best_d[v]
            second_o[v] = best_o[v]
            best_d[v] = d
            best_o[v] = o
            return True

        if d < second_d[v]:
            second_d[v] = d
            second_o[v] = o
            return True

        return False

    while heap:
        d, v, o = heapq.heappop(heap)

        if d != best_d[v] and d != second_d[v]:
            continue

        for u, w in graph[v]:
            nd = d + w
            if update(u, nd, o):
                heapq.heappush(heap, (nd, u, o))

    for i in range(n):
        if best_d[i] != s[i]:
            print(-1)
            return

    for i in range(n):
        if second_d[i] == s[i]:
            print(i + 1)
            return

    print(-1)

if __name__ == "__main__":
    solve()
```初期化により、仮想ノードの構築が置き換えられます。 明示的に追加する代わりに`z`、すべての頂点は、それを接続するエッジと等しい距離から始まります。`z`。 

の`update`関数は実装の中核です。 異なる開始頂点を持つ 2 つの最小パスのみが保持されます。 2 番目のパスは別の人工エッジを表す必要があるため、同じ原点からの 2 つのエントリを保持しても役に立ちません。 

ダイクストラ緩和では、Python の通常の整数型を通じて 64 ビット スタイルの整数が使用されます。 パスの長さがおよそに達する可能性があるため、これは重要です。`2 * 10^14`。 改善後に頂点に複数の古いエントリが含まれる可能性があるため、古いヒープ チェックが必要です。 

最終スキャンは意図的にインデックスの昇順で行われます。 最初の有効な頂点が自動的にインデックス付きの最小の回答になります。
