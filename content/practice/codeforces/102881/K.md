 ## 解決策
 ## 問題の理解

 この問題は植物の列について説明しています。 植物`i`身長から始まる`h_i`そして成長します`g_i`各単位時間の後の単位。 最初の整数時間を見つける必要があります`t`植物を左から右に高さの降順に並べた場合。 注文がどうしても並べ替えられない場合は、報告する必要があります`-1`。 

入力により、植物の数、初期の高さ、および成長率が得られます。 出力は、すべての隣接するペアが次の条件を満たす場合の最小の非負の整数モーメントです。`height[i] <= height[i + 1]`。 

重要な観察は、最終条件は隣接する植物にのみ依存するということです。 すべての植物が次の植物よりも高くない場合、シーケンス全体がソートされます。 隣接するペアごとに、いつ不等式が真になるかを知る必要があるだけです。 

制約`n <= 100000`何度もチェックするアプローチは不可能であることを意味します。 高さと成長率は到達する可能性があるため、答えは非常に大きくなる可能性があります。`10^9`、そのため、時間通りにバイナリ検索を行うには慎重な取り扱いが必要であり、不要です。 隣接する各ペアを 1 回処理して、`O(n)`アルゴリズム。 

よくある間違いは、成長を段階的にシミュレーションすることです。 たとえば、ある植物が別の植物よりもはるかに速く成長する場合、交雑時間は数十億時間以上になる可能性があり、シミュレーションは絶望的になります。 もう 1 つの間違いは、最も高い植物と最も低い植物だけをチェックすることです。 並べ替えはローカルなプロパティであるため、すべての隣接するペアが重要です。 

次の入力を考えてみましょう。```
3
5 4 3
1 2 3
```正しい出力は次のとおりです`1`。 時間に`0`高さは`5, 4, 3`、ソートされていません。 しばらくすると、次のようになります。`6, 6, 6`。 最大値が最終的に最大値でなくなるかどうかのみをチェックする不注意な実装では、中間の関係も必要であるという事実を見落とす可能性があります。 

もう 1 つのエッジ ケースは、2 つの植物の成長速度は同じだが順序が間違っている場合です。```
2
10 5
3 3
```正しい出力は次のとおりです`-1`。 それらの差は決して変わらないので、最初の植物は常に高いままになります。 ゼロを処理せずに成長差で除算する実装は、ここで失敗します。 

## アプローチ

 直接的なアプローチは、時間をシミュレートすることです。 毎回、すべての植物の高さを更新し、順序がソートされているかどうかを確認します。 これは正しいです。問題で説明されているプロセスを文字通りに従っているからです。 ただし、最初の有効時間は非常に長くなる可能性があります。 答えが近くにあるなら`10^9`、シミュレーションには約`10^14`すべてのタイム ステップですべての操作が検査されるため、`n`植物。 

有益な観察は、すべての隣接するペアが時間に関して数学的な制限を与えるということです。 植物用`i`そして`i + 1`、次のものが必要です。`h_i + g_i * t <= h_(i+1) + g_(i+1) * t`並べ替えると次のようになります。`(g_i - g_(i+1)) * t <= h_(i+1) - h_i`これは 1 つの不等式です`t`。 左側の植物の成長が速い場合、不平等により時間の上限が生じます。 適切な植物がより速く成長すると、下限が作成されます。 両方の成長率が等しい場合、最初の順序は決して変更されません。 

すべての下限と上限を収集した後、答えは単にそれらを満たす最小の非負の整数になります。 ブルートフォースはタイムラインを直接検索するため機能しますが、不等式アプローチは各ペアが将来の関係全体を一度に記述するため機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(答え * n) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 可能な範囲の回答から始めます。 最小有効時間は次のとおりです。`0`したがって、下限を次のように初期化します。`0`。 上限は無制限です。 
2. 隣接する植物のペアごとに、将来の高さを比較します。 維持する条件は次のとおりです。`h_i + g_i*t <= h_(i+1) + g_(i+1)*t`この不等式を整理すると、このペアが可能な限り最も早い時間を制限するのか、それとも最も遅い時間を制限するのかが分かります。 
3. もし`g_i - g_(i+1)`が正の場合、左側の植物の高さがより速く成長します。 このペアは、ある最大時間までしかソートされた状態を維持できないため、上限を更新します。 
4. もし`g_i - g_(i+1)`が負の場合は、右側の植物の方が早く丈が伸びます。 ペアは最終的には正しくなりますが、それは最小限の時間が経過した後でのみなので、下限を更新します。 
5. もし`g_i - g_(i+1)`がゼロの場合、両方のプラントは常に同じ量だけ変化します。 それらの順序は決して変わらないため、最初の比較によって答えが可能かどうかが決まります。 
6. すべてのペアが処理された後、下限が上限より大きい場合、すべての条件を満たす時間はありません。 それ以外の場合、下限は最初の有効な整数モーメントになります。 

これが機能する理由: 並べ替えられたすべてのシーケンスは、隣接するすべての不等式を満たさなければなりません。 アルゴリズムは、これらの各不等式を可能な時間値の制限に変換します。 すべての制限の交差部分は、シーケンス全体がソートされるときの一連の時間となります。 その交差部分の負でない最小値を取得すると、必要な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    h = list(map(int, input().split()))
    g = list(map(int, input().split()))

    low = 0
    high = 10**30

    for i in range(n - 1):
        dg = g[i] - g[i + 1]
        dh = h[i + 1] - h[i]

        if dg == 0:
            if dh < 0:
                print(-1)
                return
        elif dg > 0:
            high = min(high, dh // dg)
        else:
            need = (-dh + (-dg) - 1) // (-dg)
            low = max(low, need)

    if low <= high:
        print(low)
    else:
        print(-1)

if __name__ == "__main__":
    solve()
```コードは、すべての有効な時刻の交差を表す 2 つの変数を保持します。`low`可能な限り早い回答を保存しますが、`high`最新の考えられる答えを保存します。 

成長の差が正の場合、不等式は以下を必要とするため、整数除算は安全です。`t <= dh / dg`。 もし`dh`が負の場合、結果の上限は負になり、時間を負にすることはできないため、最終範囲は自動的に無効になります。 

マイナスの成長差の場合、コードは除算の上限を計算します。 time は整数でなければならないため、これは必須です。 ここで通常の整数除算を使用すると、負の値に対して間違った方向に丸められ、1 単位が小さすぎる答えが生成される可能性があります。 

到達できる値は、`10^9`、そして答えは 32 ビット整数の制限を超える可能性があるため、Python の任意精度整数はオーバーフローの問題を自然に回避します。

 ## 特殊なケース

 成長率が等しい場合、アルゴリズムは除算を試行しません。 例えば：```
2
10 5
3 3
```成長の差はゼロで、最初の植物の方が高く始まります。 両方の植物は同じ速度で背丈を伸ばすので、その差は`5`決して変わりません。 アルゴリズムはすぐに戻ります`-1`。 

単一の植物の場合:```
1
100
50
```順序付け条件に違反する隣接ペアはありません。 初期の下限はそのまま残ります`0`、したがって、答えは次のとおりです`0`。 

ペアが小数点以下の時間で正確にソートされる場合、整数の上限が重要になります。```
2
10 0
1 3
```不平等はこうなる`10 + t <= 3t`、 それで`10 <= 2t`、 意味`t >= 5`。 アルゴリズムは天井除算を使用し、戻り値を返します。`5`、これは条件が成立する最初の整数モーメントです。 

制限が矛盾している場合、アルゴリズムは空の範囲を検出します。 たとえば、1 つのペアには`t >= 5`一方、別のものが必要とする`t <= 3`。 両方を満たす整数はないため、最終チェックは`low <= high`失敗します、そして答えは`-1`。
