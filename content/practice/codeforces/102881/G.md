 ## 解決策
 ## 問題の理解

 最初は空の番号付きキューブのコレクションがあります。 各操作では、数値が指定された包含範囲内にあるすべてのキューブが追加されます。`[l, r]`。 各操作の後に、これまでにコレクションに出現したすべての数値の最大公約数を出力する必要があります。 

入力は一連の間隔加算です。 重要な詳細は、コレクションは増加するだけであるため、各答えは現在の間隔だけでなく以前のすべての間隔にも依存するということです。 すべての操作後の出力は、現在のグローバル GCD です。 

実行できる操作数は、`10^5`、間隔内の値は次のように大きくできます。`10^18`。 これにより、間隔内の数値の反復が即座に除外されます。 1 つの間隔には最大で次のものを含めることができます。`10^18`したがって、すべての値にアクセスして 1 つの大きなクエリを処理することさえ不可能です。 クエリごとに定数時間または対数時間の更新が必要です。 

重要なエッジ ケースは、大きく見える間隔から発生しますが、数学的には単純です。 単一値の間隔と複数値の間隔はまったく異なる動作をします。 たとえば、次の入力を使用します。```
1
2250 2250
```答えは次のとおりです。```
2250
```追加された唯一のキューブに値があるため`2250`。 

別のケースは次のとおりです。```
2
10 10
15 15
```答えは次のとおりです。```
10
5
```2番目の答えはそうではありません`15`、現在のキューブは`10`そして`15`、GCD は`5`。 

最も重要な境界ケースは、2 つの連続した値を持つ区間です。```
1
7 8
```答えは次のとおりです。```
1
```不注意な解決策では、エンドポイントのみを使用して GCD を計算し、次の結果を取得しようとする可能性があります。`gcd(7, 8) = 1`これはここではたまたま機能しますが、理由はもっと深いです。連続する整数を含むすべての区間には GCD があります。`1`。 このプロパティにより、間隔の処理を回避できるようになります。 

## アプローチ

 直接的なアプローチでは、追加されたすべての数値を維持し、クエリのたびにコレクション全体の GCD を計算します。 セットの GCD は問題で要求された値と正確に一致するため、これは正しいです。 ただし、制約があるとすぐに失敗します。 次のような間隔`[1, 10^18]`には京の数値が含まれているため、値を保存することさえ不可能であり、各演算後の GCD の再計算には最大で`10^23`すべてのクエリに対する操作。 

問題を変える観察は、区間内の個々の数値を知る必要がないということです。 その間隔によって提供される GCD のみが必要です。 

少なくとも 2 つの数値を含む区間には、その中に 2 つの連続する整数が存在します。 2 つの連続する整数の GCD は常に`1`、さらに数値を追加しても GCD を増やすことはできません。 したがって、インターバルごとに`[l, r]`どこ`l < r`の GCD に貢献します`1`。 

間隔に数値が 1 つだけ含まれている場合、その寄与は単にその数値になります。 

問題全体は、前の答えの GCD と新しい間隔の寄与を維持することに帰着します。 答えが出たら`1`、将来のすべての GCD が含まれるため、再び変更することはできません。`1`残る`1`。

 | --- | --- | --- | --- |
 | ブルートフォース | O(挿入された値の合計数) | O(挿入された値の合計数) | 遅すぎる |
 | 最適 | O(q log A) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 現在の GCD を次のように初期化します。`0`。 のGCD`0`そして値`x`は`x`これにより、最初の更新が自然に機能します。 
2. インターバルごとに`[l, r]`、この間隔で追加される GCD を決定します。 もし`l`そして`r`が異なる場合、間隔には連続した数値が含まれるため、その寄与は次のようになります。`1`。 それ以外の場合、その貢献度は`l`。 
3. GCD 演算を使用して、新しい投稿と現在の回答を結合します。 更新された値は、これまでに確認されたすべての数値の GCD です。 
4. 更新された GCD を出力します。 

なぜ機能するのか: すべてのクエリの後に維持される不変条件は次のとおりです。`current_gcd`は、その時点までに出現したすべての立方体の GCD に等しくなります。 新しい間隔が追加されると、その間隔内のすべての数値の GCD は、その単一の値または`1`。 古いコレクションの GCD とこの新しい間隔を取得すると、結合されたコレクションの GCD が正確に得られるため、不変式は true のままです。 

## Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    q = int(input())
    ans = 0
    out = []

    for _ in range(q):
        l, r = map(int, input().split())

        if l != r:
            add = 1
        else:
            add = l

        ans = gcd(ans, add)
        out.append(str(ans))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```変数`ans`これまでに処理されたすべてのキューブの GCD を保存します。 開始時刻`0`最初のクエリに特別なケースが必要になることを回避します。`gcd(0, x)`返品`x`。 

コードは間隔ごとに、複数の数値が含まれているかどうかをチェックします。 条件`l != r`間隔には包括的な値が含まれるため、これで十分です。エンドポイントが異なる場合は、内部に少なくとも 2 つの連続した整数が存在することを意味します。 

このアップデートでは、Python の組み込みユークリッド アルゴリズム実装を使用します。`math.gcd`までの値を処理します。`10^18`効率的に。 過去の情報は 1 つの整数で完全に要約されるため、配列や間隔のストレージは必要ありません。

## テストケース```python
import sys
import io
from math import gcd

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    q = int(sys.stdin.readline())
    ans = 0
    out = []

    for _ in range(q):
        l, r = map(int, sys.stdin.readline().split())
        if l != r:
            ans = gcd(ans, 1)

            ans = gcd(ans, l)
        out.append(str(ans))

    print("\n".join(out))

    sys.stdin = old_stdin
    sys.stdout = old_stdout

 ## 特殊なケース

 単一値の場合:```
1
2250 2250
```アルゴリズムが見る`l == r`、つまり間隔が寄与します`2250`。 以前の GCD は`0`、新しい答えを作る`gcd(0, 2250) = 2250`。 

複数の個別値の場合:```
2
10 10
15 15
```最初のアップデートで得られるもの`10`。 2番目は貢献します`15`、したがって、答えは次のようになります`gcd(10, 15) = 5`。 現在の GCD には必要な情報がすべて含まれているため、アルゴリズムではどちらのキューブも保存する必要はありません。 

連続した値を含む間隔の場合:```
1
7 8
```間隔が貢献する`1`両方含まれているので`7`そして`8`、 そして`gcd(7, 8) = 1`。 グローバルな答えは次のようになります`1`。 今後の操作では、答えが維持されます。`1`より大きい GCD を持つ整数はないため、`1`既存の GCD と組み合わせると、`1`。
