 ## 解決策
 # 問題の理解

 タスクは文字から作られた文字列を並べ替えることです`a`、`b`、 そして`c`2 つの位置の交換を使用します。 特別な制限があります: 文字列には最大 1 つの文字列が含まれます。`b`。 再配置後は、隣接するすべてのペアに同じ文字が含まれるか、一意の文字が含まれる必要があります。`b`。 つまり、可能性を排除した上で、`b`、残りの文字は 1 つまたは 2 つの均一なブロックを形成する必要があります。 ターゲットの形状は、単一の繰り返し文字、または 1 つの文字のブロックの後に続くものです。`b`、その後に 1 文字の別のブロックが続きます。 元の問題ステートメントと制限は Codeforces Gym 102881J からのものです。 

入力により、文字列と文字列自体の長さが得られます。 出力は、必要な任意のスワップの最小数、または`-1`有効な取り決めが存在しない場合。 

届く長さは`100000`したがって、多くの可能な再配置を試みる解決策は不可能です。 二次アルゴリズムは、最悪の場合でも約 100 億の演算を実行しますが、これは 1 秒の制限をはるかに超えています。 線形または線形に近いアプローチが必要です。 小さなアルファベットがこれを可能にする重要な制限です。 

いくつかのケースは見落とされやすいものです。 ない場合`b`、隣接するペアはすべて等しい必要があるため、最後の文字列に 2 つの異なる文字を含めることはできません。 たとえば、入力の場合```
3
abc
```答えは`-1`交換後も文字列にはまだ次のものが含まれているためです。`a`、`b`、 そして`c`、すべての隣接するペアを有効にすることはできません。 

もう 1 つの特殊なケースは、単一の文字です。 例えば、```
1
a
```すでに条件を満たしているので、答えは次のようになります。`0`。 を前提としたソリューション`b`存在するか、常に 2 つのブロックを作成する場合、ここで失敗する可能性があります。 

とき`b`の両面が存在します。`b`同じ文字を含める必要はありません。 例えば、```
3
acb
```なることができる`abc`1 回の交換で、答えは`1`。 次の形式の文字列のみをチェックする不注意なアプローチ`aaa...bbb...`有効な回答を拒否します。 

## アプローチ

 強引なアイデアは、次の最終位置を選択することです。`b`、左側の文字を選択し、右側の文字を選択して、ターゲット文字列を構築し、それに到達するまでに必要なスワップをカウントします。 すべての有効な最終文字列がまさにこの構造を持つため、この考えは正しいです。 

ただし、考えられるすべてのターゲットを単純に直接比較するのは無駄です。 まであります`n`可能な場所`b`そしてそれぞれの比較はすべてに影響します`n`ポジション、与える`O(n^2)`仕事。 と`n = 100000`、これは遅すぎます。 

重要な点は、アルファベットが小さいことです。 固定ターゲット配置の場合、スワップ数は、間違った場所にある文字の数からのみ計算できます。 スワップをシミュレーションする必要はありません。 

選択した任意の位置に対して、`b`と選択されたサイド文字を使用して、現在の文字列を 3 つのターゲット グループに分割します。`a`、含むべき位置`b`、および含むべき位置`c`。 2 つのグループ間の不一致は、2 つの間違って配置された文字を交換することで直接修正できます。 残りの 3 ウェイ サイクルには 2 回のスワップが必要です。 文字タイプが 3 つしかないため、この計算は定数時間です。 

プレフィックス数により、その数を知ることができます。`a`、`b`、 そして`c`文字は任意の間隔で表示されます。 可能な限りの最終位置を試します`b`そして、そうでない2人に対する4つの選択肢`b`側面。

 ## アルゴリズムのチュートリアル

 1. 何個数えるか`b`文字が存在します。 ない場合`b`、可能な最後の文字列は次のとおりです。`a`またはすべて`c`。 答えは、スワップによって置き換える必要がある文字の数が少ないことです。 両方の場合`a`そして`c`存在する場合は、小さいグループを大きいグループに入れ替えることができます。 
2. ある場合`b`、その可能なすべての最終位置を考慮します`b`。 残りのポジションは左側と右側に分割されます。`b`。 
3. 考えられるサイド文字のペアごとに、すべての位置を選択したパターンに一致させるために必要な交換の数を計算します。 サブキャラクターは`a`または`c`。 
4. 不一致マトリックスを構築します。 行は現在の文字を表し、列はその位置で必要な文字を表します。 正反対の不一致が最初に解決されます。 たとえば、置き忘れた`a`そして置き忘れた`c`1回の交換で直ります。 
5. すべての直接スワップの後、残るエラーは次のようなサイクルだけです。`a`必要としている`b`、`b`必要としている`c`、 そして`c`必要としている`a`。 このようなサイクルごとに 2 つのスワップが必要です。 

機能する理由: すべての有効な最終文字列には 1 つのオプションが必要です`b`最大でも 2 つの均一な領域を分離します。 アルゴリズムは、その構造のあらゆる選択肢をチェックします。 各構造について、不一致行列は正確な最小スワップを示します。これは、スワップで解決できるのは最大 2 つの反対の不一致であり、未解決の 3 文字のサイクルが唯一残っている可能性であるためです。 したがって、すべての構造にわたって最小値を取ると、全体的な最適値が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mismatch_cost(mat):
    ans = 0

    for i in range(3):
        for j in range(i + 1, 3):
            x = min(mat[i][j], mat[j][i])
            ans += x
            mat[i][j] -= x
            mat[j][i] -= x

    left = 0
    for i in range(3):
        for j in range(3):
            if i != j:
                left += mat[i][j]

    ans += (left // 3) * 2
    return ans

def solve():
    n = int(input())
    s = input().strip()

    cnt = [0, 0, 0]
    for ch in s:
        cnt[ord(ch) - ord('a')] += 1

    if cnt[1] == 0:
        print(min(cnt[0], cnt[2]))
        return

    pref = [[0, 0, 0]]
    for ch in s:
        cur = pref[-1][:]
        cur[ord(ch) - ord('a')] += 1
        pref.append(cur)

    def add_segment(mat, l, r, target):
        amount = [
            pref[r + 1][0] - pref[l][0],
            pref[r + 1][1] - pref[l][1],
            pref[r + 1][2] - pref[l][2],
        ]
        for c in range(3):
            mat[c][target] += amount[c]

    answer = n

    for pos in range(n):
        for left_char in (0, 2):
            for right_char in (0, 2):
                mat = [[0, 0, 0] for _ in range(3)]

                add_segment(mat, 0, pos - 1, left_char)
                add_segment(mat, pos + 1, n - 1, right_char)

                current = ord(s[pos]) - ord('a')
                mat[current][1] += 1

                answer = min(answer, mismatch_cost(mat))

    print(answer)

solve()
```の`mismatch_cost`機能はソリューションの中核です。 1 回のスワップで各側の 1 つの間違いが修正されるため、まず反対の間違いのペアをすべて削除します。 その後、残りの不一致は 3 文字すべてを含むサイクルを形成する必要があり、各サイクルには 2 つのスワップがかかります。 

プレフィックス配列には、各位置までのすべての文字のカウントが保存されます。 これにより、各候補位置が可能になります。`b`文字列全体を再度スキャンすることなく評価されます。 の`add_segment`ヘルパーは、元の文字の間隔を不一致行列への寄与に変換します。 

を含む位置`b`その位置の元の文字は、`a`、`b`、 または`c`。 コードはターゲットに直接追加します`b`これは当然、交換する必要があるかどうかを考慮します。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline
    n = int(data())
    s = data().strip()

    cnt = [0, 0, 0]
    for ch in s:
        cnt[ord(ch) - 97] += 1

    if cnt[1] == 0:
        ans = min(cnt[0], cnt[2])
        sys.stdin = old
        return str(ans) + "\n"

    pref = [[0, 0, 0]]
    for ch in s:
        x = pref[-1][:]
        x[ord(ch) - 97] += 1
        pref.append(x)

    def calc(mat):
        ans = 0
        for i in range(3):
            for j in range(i + 1, 3):
                x = min(mat[i][j], mat[j][i])
                ans += x
                mat[i][j] -= x
                mat[j][i] -= x
        rem = sum(mat[i][j] for i in range(3) for j in range(3) if i != j)
        return ans + rem // 3 * 2

    def add(mat, l, r, t):
        if l > r:
            return
        for c in range(3):
            mat[c][t] += pref[r + 1][c] - pref[l][c]

    ans = n
    for p in range(n):
        for a in (0, 2):
            for c in (0, 2):
                mat = [[0] * 3 for _ in range(3)]
                add(mat, 0, p - 1, a)
                add(mat, p + 1, n - 1, c)
                mat[ord(s[p]) - 97][1] += 1
                ans = min(ans, calc(mat))

    sys.stdin = old
    return str(ans) + "\n"

assert run("5\naaccc\n") == "1\n", "split around b creation"

 ## 特殊なケース

 のために`abc`、アルゴリズムはいいえを認識します`b`。 最後の文字列は完全に次のようにする必要があります。`a`または完全に`c`ですが、文字列には両方が含まれています。 スワップでは文字タイプを削除できないため、答えは次のようになります。`-1`。 

のために`a`、いいえ、`b`ブランチは文字列をすべて比較します`a`対すべて`c`。 既存のキャラクターを維持するにはスワップを必要としないため、答えは次のようになります。`0`。 

のために`acb`、アルゴリズムは可能な限りのことを試みます`b`位置。 いつ`b`が中央に配置され、左右のブロックが`a`そして`c`、最後の 2 つの位置だけが間違っています。 1 回の交換で問題が解決され、最適な答えが得られます。`1`。 

の両側が一致する文字列の場合、`b`異なる文字を使用する場合は、左右のブロック文字の列挙によって大文字と小文字が直接処理されます。 これは、文字列全体が 1 つの繰り返し文字になることを想定していません。これが、より単純な解決策が犯す主な構造上の間違いです。
