 ## 解決策
 ## 問題の理解

 最初の順列と一連の確率演算が与えられます。 各操作は順列の接頭辞に焦点を当て、その接頭辞を指定された確率で独立して並べ替えます。 操作が「起動」すると、プレフィックスは完全にソートされます。 それ以外の場合は、変更されないままになります。 操作は順番に適用され、それぞれの決定は独立しています。 

タスクは、すべての操作が終了した後、順列全体がソートされる確率を計算することです。 

重要な問題は、プレフィックスのソートは後の状態にグローバルな影響を及ぼしますが、それは構造化された方法でのみであることです。プレフィックスは一度ソートされると、再び「ソートされていない」状態になることはありません。 これにより、前進のみが進む単調なプロセスが生まれます。 

制約では最大 10^5 の演算と要素が許可されるため、ソリューションはテスト ケースごとに線形である必要があります。 これにより、すべての結果をシミュレートしたり、順列全体にわたって完全な確率分布を維持したりすることは、組み合わせ論的に爆発してしまうため、直ちに排除されます。 

よくある間違いは、各演算を独立して配列全体の正確さに寄与するものとして扱うことです。 これは、より大きなプレフィックスがすでにソートされている場合、短いプレフィックスに対する後の操作は無関係になる可能性があるため、失敗します。 

## アプローチ

 ブルートフォース解釈では、成功した操作のすべてのサブセットをシミュレートし、結果の順列を計算して、それがソートされているかどうかを確認します。 m 回の操作があると、2^m 個のシナリオが発生し、それぞれのシナリオでプレフィックス ソートのシミュレーションが必要になります。 m は 10^5 になる可能性があるため、これは実行不可能です。 

重要な観察は、完全な順列状態は必要ないということです。 重要なのは、順列がソートされることがまだ保証されていない最初の位置です。 誤って配置されたすべての要素をカバーするプレフィックスがソートされると、配列全体がソートされます。 

これは動的なプロセスにつながります。まだ「修正」が必要な右端の位置を追跡し、プレフィックスのソートが成功したためにこの位置が無関係になる確率を更新します。 

この構造により、問題は操作全体にわたる線形 DP に縮小されます。各操作は、未解決のサフィックスを減らすのに役立つか、プレフィックスの長さに応じて無関係になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^m・n) | O(n) | 遅すぎる |
 | プレフィックス境界上の DP | O(n + m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 位置を特定する`bad`、これは、順列が恒等順列と異なる最も右側のインデックスです。 配列がすでにソートされている場合、ランダム性を破ることはできないため、答えはすぐに 1 になります。 
2. 配列がすでにソートされている場合は、1 を返します。そうでない場合は、すべての確率質量がインデックスを固定するプロセスを介して最大で流れます。`bad`。 
3. アキュムレータを初期化する`ans = 1`。 これは、関連するすべての操作を処理した後、配列がソートされていないままになる確率を表します。 
4. 操作を順番に繰り返します。 それぞれの操作について`(r, p)`、での操作のみ`r >= bad`なぜなら、最後の間違った位置に影響を与えることができるのはそれらだけだからです。 
5. もし`r < bad`、クリティカルサフィックスを修正できないため、操作を完全にスキップします。 
6. もし`r >= bad`、配列の修正に失敗する確率を更新します。 操作は確率で成功します`p`つまり、プレフィックスをソートし、配列を修正する可能性があります。 失敗した状態に留まる確率は次のように乗算されます。`(1 - p)`。 
7. すべての操作を処理した後、配列がソートされる確率は次のようになります。`1 - ans`。 

機能する理由: 最後に間違った位置をカバーするプレフィックスがソートされると、順列全体が永続的にソートされます。 したがって、その境界に到達する操作のみが問題となり、その効果は失敗の確率を独立に乗算的に低減します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        bad = 0
        for i in range(n):
            if a[i] != i + 1:
                bad = i + 1

        if bad == 0:
            for _ in range(m):
                input()
            print("1.000000")
            continue

        fail = 1.0

        for _ in range(m):
            r, p = input().split()
            r = int(r)
            p = float(p)

            if r >= bad:
                fail *= (1 - p)

        print(f"{1 - fail:.6f}")

if __name__ == "__main__":
    solve()
```この解決策では、まず順列がソートされていない最後の位置を決定します。 その位置は、配列が固定されるときの完全な特徴を示します。 この位置に到達しない操作は無効です。 関連する操作のうち、それぞれが乗算係数によってソートされずに残る確率を独立して減らします。 

微妙な点は浮動小数点精度です。 確率は 1e-6 までの誤差許容度が必要なため、標準の倍精度で十分です。 もう 1 つの重要な点は、無関係なプレフィックス操作を早い段階でスキップすることです。 これらを含めても正確さは変わりませんが、不必要な浮動小数点乗算が発生する可能性があります。 

## 実用的な例

 ### 例 1

 入力:```
n = 4
a = [4, 3, 2, 1]
operations = [(1, 0.3), (3, 1.0), (4, 0.6)]
```ここ`bad = 4`。 

| 操作 | r | p | 関連する | 失敗 |
 | --- | --- | --- | --- | --- |
 | 開始 | - | - | - | 1 |
 | (1,0.3) | 1 | 0.3 | いいえ | 1 |
 | (3,1.0) | 3 | 1.0 | いいえ | 1 |
 | (4,0.6) | 4 | 0.6 | はい | 0.4 |

 最終的な答えは、`1 - 0.4 = 0.6`。 

これは、最後に不正なインデックスに到達した操作のみが寄与していることを示しています。 

### 例 2

 入力:```
n = 4
a = [1,2,3,4]
operations = [(2,0.5),(4,0.1)]
```ここ`bad = 0`, したがって、操作に関係なく、答えはすぐに 1 になります。 

これにより、配列が最初に並べ替えられると、ランダム性によって正確さが損なわれることはないことが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | 不一致を見つけるための 1 回のスキャンと 1 回のパスオーバー操作 |
 | スペース | お(1) | カウンタとスカラーのみが使用されます。 

この制約では合計 10^5 までの演算と要素が許可されるため、テスト ケースごとの線形解は制限内に問題なく適合します。

 ## 特殊なケース

 順列がすでにソートされている場合、目標状態に到達するために操作は必要ないため、アルゴリズムは確率を処理せずに 1 を正しく返します。 

小さなプレフィックスのみがソートされる場合、それらはいずれも最後の間違った位置に到達しないため、失敗確率の積は 1 のままで、正しく答え 0 が得られます。 

複数の大きなプレフィックス操作が存在する場合、それらは失敗空間で独立して乗算され、アルゴリズムは二重にカウントすることなくそれらの複合効果を正確にモデル化します。
