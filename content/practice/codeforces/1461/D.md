 ## 解決策
 ## 問題の理解

 配列から始めて、非常に具体的な分割ルールを繰り返し適用します。 

現在の配列について、計算します。$$mid = \left\lfloor \frac{\min + \max}{2} \right\rfloor$$値が最大以下のすべての要素`mid`1 つのグループを形成し、値がより大きいすべての要素`mid`もう一方を形成します。 分割後、2 つのグループのうちの 1 つだけを保持し、もう 1 つを破棄します。 

すべてのクエリ値について`s`、要素の合計が正確に一致する配列を生成するような選択のシーケンスが存在するかどうかを判断する必要があります。`s`。 

最も重要な観察は、分割は位置ではなく値のみに依存するということです。 相対的な順序は保持されますが、配列を並べ替えると、すべての分割は連続した値の範囲の分割になります。 これにより、プロセスがソートされた配列の再帰的分割に変わります。 

制約が大きいため、すべてのクエリを個別にシミュレートすることはできません。 すべてのテスト ケースで、配列要素の合計数とクエリの合計数は両方とも最大`10^5`。 あらゆる解決策`O(nq)`およそ時間がかかる可能性があるため、遅すぎるでしょう。`10^{10}`最悪の場合の運用。 に近いものが必要です`O(n log n)`前処理とその後の非常に高速なクエリ処理。 

いくつかの特殊なケースは見落とされがちです。 

すべての値が等しい配列を考えてみましょう。```
[5, 5, 5, 5]
```計算された`mid`もです`5`したがって、すべての要素は左側の部分に配置され、右側の部分は空になります。 これ以上の分割はできません。 唯一達成可能な合計は`20`。 不注意に再帰的な実装を行うと、範囲が決して縮小しないため、永久に再帰が行われる可能性があります。 

考慮する：```
[1, 2]
```合計額`3`分割を実行せずに達成できます。 一部のソリューションでは、分割後に合計のみを記録し、現在のセグメント自体を含めることを忘れています。 次にクエリを実行します`3`誤って「いいえ」を返します。 

別の微妙なケースは次のとおりです。```
[1, 1, 100]
```最初の分割は分離します`[1,1]`そして`[100]`。 達成可能な金額は、`102`、`2`、 そして`100`。 クエリ`101`たとえそれが達成可能な金額の間にあるとしても、拒否する必要があります。 問題は、任意のサブセットの合計を求めることではありません。 再帰的な分割プロセスによって生成された合計のみが重要です。 

## アプローチ

 ブルートフォース解釈とは、考えられるあらゆる選択肢のシーケンスに明示的に従うことです。 現在の各配列から左部分または右部分のいずれかを保持し、バイナリ再帰ツリーを作成します。 到達可能なすべての配列は、1 つの達成可能な合計に寄与します。 

これはプロセスの定義と直接一致するため、正しいです。 残念ながら、配列を表現し、それらを繰り返し再分割するにはコストがかかります。 最悪の場合、大きな配列を繰り返しスキャンし、多数のコピーを作成します。 まで`10^5`要素全体を考慮すると、このアプローチはすぐに非現実的になります。 

重要な観察は、ソート後、すべての再帰状態がソートされた配列の連続セグメントに対応するということです。 

ソートされた配列セグメントが次のようになっているとします。`a[l...r]`。 分割しきい値は次のとおりです。$$mid = \left\lfloor \frac{a[l] + a[r]}{2} \right\rfloor$$セグメントはソートされているため、すべての値が`<= mid`セグメントとすべての値の接頭辞を形成します`> mid`接尾語を形成します。 分割位置は二分探索で求めることができます。 

これで、実際の配列を追跡する必要がなくなりました。 状態はインデックス間隔によって完全に記述されます`[l, r]`。 

このような各セグメントには明確に定義された合計があります。 この再帰的なプロセス中に表示されるセグメントは、達成可能な配列に対応するため、すべての達成可能な合計を事前に計算し、それらをセットに格納できます。 

達成可能な合計がすべて判明すると、各クエリは単純なメンバーシップ テストになります。 

分割ごとに値の範囲が分割されるため、再帰は効率的です。 セグメントは 1 回だけ処理され、バイナリ検索によってパーティション ポイントが特定されます。

 ## アルゴリズムのチュートリアル

 1. 配列をソートします。 

ソート後の各分割は、連続するセグメントを 2 つの連続するサブセグメントに分割することに対応します。 
2. プレフィックス合計配列を構築します。 

これにより、任意のセグメントの合計が可能になります`[l, r]`一定時間で計算されます。 
3. ソートされた配列セグメント全体に対して再帰的プロシージャを開始します。 

最初のセグメントは元の配列を表し、その合計は常に達成可能です。 
4. セグメントの場合`[l, r]`、その合計を計算し、セットに挿入します。 

すべての再帰セグメントは、許可された操作を通じて取得できる有効な配列に対応します。 
5. もし`a[l] == a[r]`、 停止。 

セグメント内のすべての値は同一です。 さらに分割すると、すべての要素が同じ側に配置されるため、再帰は終了する必要があります。 
6. コンピューティング$$mid = \left\lfloor \frac{a[l] + a[r]}{2} \right\rfloor$$7. 二分探索を使用して、値が次より大きい最初の位置を見つけます。`mid`。 

これにより、問題で定義されたとおりに、左グループと右グループの間の境界が特定されます。 
8. 境界によって実際にセグメントが分割されない場合は、停止します。 

これにより、片側が空の場合の無駄な再帰が防止されます。 
9. 左側のセグメントを再帰的に処理します。 
10. 右セグメントを再帰的に処理します。 
11. 前処理が完了したら、その値が達成可能な合計のセットに存在するかどうかを確認して、すべてのクエリに答えます。 

### なぜ効果があるのか

 再帰は、許可された操作を正確に反映します。 

再帰的なセグメントの場合`[l, r]`、その中の値は、プロセス中に表示される可能性のある配列の要素そのものです。 したがって、セグメント合計は達成可能であり、記録する必要があります。 

逆に、元のプロセスのすべての法的分割は、しきい値に従って要素を分割します。`mid`。 ソートされたセグメントでは、そのパーティションはアルゴリズムで使用される二分探索分割とまったく同じです。 再帰では、結果として得られる両方のセグメントが調査されるため、出現する可能性のあるすべての配列が表現されます。 

したがって、再帰によって構築されたセットには、達成可能なすべての合計と、達成可能な合計のみが含まれます。 クエリ応答は、そのセット内のメンバーシップを確認することに帰着します。 

## Python ソリューション```python
import sys
from bisect import bisect_right

input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n, q = map(int, input().split())
        a = sorted(map(int, input().split()))

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] + a[i]

        possible = set()

        def dfs(l, r):
            seg_sum = pref[r + 1] - pref[l]
            possible.add(seg_sum)

            if a[l] == a[r]:
                return

            mid = (a[l] + a[r]) // 2
            p = bisect_right(a, mid, l, r + 1)

            if p == l or p == r + 1:
                return

            dfs(l, p - 1)
            dfs(p, r)

        dfs(0, n - 1)

        for _ in range(q):
            s = int(input())
            answers.append("Yes" if s in possible else "No")

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```分割ルールは値のみに依存するため、最初のステップでは配列を並べ替えます。 ソートが完了すると、すべての再帰状態は連続したインデックス範囲になります。 

プレフィックス合計配列を使用すると、セグメント合計を一定時間で計算できます。 これがないと、各再帰呼び出しでセグメント全体をスキャンする必要があり、複雑さが大幅に増加します。 

の`possible`set には、達成可能なすべての合計が格納されます。 セグメント自体が有効な取得可能な配列を表すため、セグメントにアクセスするとすぐにその合計が挿入されます。 

停止条件`a[l] == a[r]`重要です。 すべての値が等しい場合、意味のある分割は存在しません。 このチェックを省略すると、無限再帰が発生する可能性があります。`bisect_right`より厳密に大きい最初の値を見つけます`mid`、問題定義と正確に一致します。 以下に等しい値`mid`左側の部分に属します。 

小切手```
if p == l or p == r + 1:
    return
```空のパーティションから保護します。 このような分割によってセグメントが削減されることはありません。 

最後に、セット メンバーシップを使用して、各クエリは一定の予想時間内に応答されます。
