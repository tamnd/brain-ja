 ## 解決策
 ## 問題の理解

 2 種類のセルで構成されるグリッドが与えられています。 でマークされた塗りつぶされたセル。`*`とマークされた空のセル`.`。 このグリッド内に、有効な「スプルース形状」がいくつ存在するかを数えたいとします。 スプルースは常に下向きに成長する三角形です。上部のセルが 1 つあり、そのすぐ下に幅の広い行があり、その下にさらに幅の広い行があり、というようになります。 次の各行は、左に 1 セル、右に 1 セルずつ拡張され、この三角形の内側のすべてのセルには次の内容が含まれている必要があります。`*`。 

より正確には、スプルースの最上部としてセルを選択した場合、行ごとに下方向に拡張してみることができます。 深さで`i`、スプルースには、一定の長さの連続した水平セグメントが必要です。`2i - 1`根の下の中心にあり、これらすべてのセルは`*`。 このような構造の有効なプレフィックスはすべて個別のスプルースとしてカウントされるため、単一の場所が異なる高さの複数のスプルースに寄与する可能性があります。 

このタスクは、グリッド内のすべての可能な上部位置にわたる有効なスプルースの総数を、すべての高さで合計して計算することです。 

この制約により、テスト バッチごとに合計 500 x 500 個のセルが許可されます。これは、O(nm√) または O(nm²) のソリューションが許容される可能性があることを示唆していますが、3 次元を超えるものは避けなければなりません。 すべてのセルから三角形を段階的に展開しようと直接試みると、重複するチェックが何度も繰り返される危険があります。 

セルが次の場合に微妙なエッジケースが発生します。`*`ただし、境界または星が欠けているため、高さ 2 まで拡張することはできません。 各行が有効であるかどうかを個別にチェックするだけの単純なアプローチでは、連続していない形状が誤ってカウントされる可能性があります。 

たとえば、次のことを考えてみましょう。```
.*.
***
```センターボトム構造では小さなスプルースしか使用できません。 一番上の行`*`2 列目が埋まっていても、大きな三角形を形成しません。 対称拡大制約を強制しないアプローチでは、オーバーカウントが発生します。 

もう 1 つのエッジ ケースは、完全に塗りつぶされたグリッドです。 このような場合、すべてのセルが複数の高さの有効なルートになるため、答えは急速に大きくなります。そのため、アルゴリズムは各三角形を明示的に再計算するのではなく、寄与を効率的に蓄積する必要があります。 

## アプローチ

 ブルートフォース戦略はすべてのセルから始まります`(i, j)`そしてトウヒを下向きに成長させようとします。 高さの場合`1`、確認するだけで済みます`(i, j)`。 高さの場合`2`、チェックします`(i+1, j-1)`を通して`(i+1, j+1)`、身長の場合`3`、次の幅の広いセグメントなど、境界または境界に達するまで続きます。`.`。 

これはスプルースの定義に直接従うため、これは正しいです。 ただし、オールスター グリッドの最悪のケースでは、各セルは最大 O(n) の高さまで拡張でき、拡張ごとに O(n) のコストがかかり、O(n³) の動作が得られます。 n = 500 では、これは遅すぎます。 

重要な観察は、背の高いトウヒが`h`セルで終わるかどうかは、高さの小さなスプルースを拡張できるかどうかにのみ依存します。`h-1`その真上に加えて、現在の行に正しく中心に配置された連続する星が十分に含まれているかどうかを確認します。 これにより、重複する下部構造が作成されます。各セルでスプルースがどのくらいの大きさに終わることができるかがわかれば、その情報を再利用してより大きなセルを構築できます。 

私たちは定義します`dp[i][j]`頂点が次の位置にあるトウヒの最大の高さとして`(i, j)`。 セルが`*`、そのベースの高さは少なくとも 1 です。各レベルは対称的に拡張されるため、それを拡張するには、より小さいスプルースをサポートするために斜め下に隣接する両方のレベルが必要です。 これにより、問題は、各状態が下の行のみに依存する動的計画計算に変換されます。 

下から上に計算し、セルを処理するときに次の行に関するすべての情報がすでにわかっていることを確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 遅すぎる |
 | 下からのDP | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. DP テーブルの初期化`dp`すべてゼロの場合、ここで`dp[i][j]`スプルースの最大高さを次から保存します`(i, j)`。 もし`grid[i][j]`は`*`、基本ケースとして 1 に設定します。 これは、すべての星が少なくとも高さ 1 の些細なスプルースであることを反映しています。 
2. 各セルはその下の行に依存するため、グリッドを下から上に移動します。 この順序により、計算時に次のことが保証されます。`dp[i][j]`、必要なすべての値が列に並んでいます`i+1`はすでに利用可能です。 
3. 各セルについて`(i, j)`含まれている`*`、スプルースを延長してみます。 延長は両方の場合にのみ可能です`(i+1, j-1)`そして`(i+1, j+1)`有効であり、少なくとも高さのスプルースをサポートできます`k-1`。 これにより、三角形の構造が連続的かつ中心に保たれます。 
4.セット`dp[i][j]`に`1 + min(dp[i+1][j-1], dp[i+1][j+1])`延長が可能な場合。 最小限に設定すると、トウヒが最も弱い支持枝を超えて成長することができなくなります。 
5. すべての値を合計して答えを累積します。`dp`。 それぞれ`dp[i][j]`スプルースが何本から始まるかを数えます`(i, j)`すべての有効な高さにわたって。 

### なぜ効果があるのか

 各スプルースは、その上部のセルとその高さによって一意に識別されます。 反復により、スプルースの高さが確保されます。`h`に存在します`(i, j)`両方のサブトウヒの高さが同じである場合にのみ`h-1`次の行の必要な対角の子に存在します。 これは、三角形の幾何学的定義を正確に反映しています。 下から上に構築するため、必要なときにすべての依存関係がすでに解決されているため、有効な構成がスキップされたり、無効な拡張子が許可されたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    
    dp = [[0] * m for _ in range(n)]
    
    ans = 0
    
    for i in range(n - 1, -1, -1):
        for j in range(m):
            if grid[i][j] == '*':
                if i == n - 1:
                    dp[i][j] = 1
                else:
                    left = dp[i + 1][j - 1] if j - 1 >= 0 else 0
                    right = dp[i + 1][j + 1] if j + 1 < m else 0
                    dp[i][j] = 1 + min(left, right)
                ans += dp[i][j]
    
    print(ans)

t = int(input())
for _ in range(t):
    solve()
```DP テーブルはボトムアップで入力されるため、すべてのセルは下の行のすでに計算された値に依存できます。 境界チェックは無効な斜めアクセスを防ぎます。トウヒはグリッドの外側に拡張できないため、これは非常に重要です。 

各スプルースの各レベルが有効な構造に寄与するため、最終的な答えはすべての dp 値の合計になります。

 ## 特殊なケース

 単一セルグリッド`*`最も単純な有効なスプルースです。 アルゴリズムは dp 値 1 を割り当て、それを 1 回カウントします。拡張は不可能であるため、定義に直接一致します。 

dp はすべてのセルで 0 のままであるため、完全に空のグリッドではどこでも 0 が生成されます。 遷移はトリガーされないため、合計は正確にゼロになります。 

完全に塗りつぶされたグリッドは、成長動作を示します。 上の行の各セルは、対角線の子が常に存在し、最大の三角形構造を生成するため、大きな dp 値を蓄積します。 繰り返しにより、すべてのオリジンですべてのプレフィックスの高さが正しくカウントされます。このため、単純な実装では、すべての有効な高さではなく最大の高さのみを考慮して過小カウントまたは過大カウントされることがよくあります。
