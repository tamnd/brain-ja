 ## 解決策
 ## 問題の理解

 それぞれ 0 から 9 までの一連の数字と、加算、減算、乗算の任意の組み合わせが可能な一連の許可された演算子が与えられます。 タスクは、結果として得られる式の値を最大化するために、連続する数字の各ペアの間に演算子を 1 つだけ配置することです。 この式は標準的な演算子の優先順位に従います。乗算は加算や減算よりも強く結合され、加算と減算は左から右に評価されます。 

シーケンスの長さが最大 ​​100,000 桁になる可能性があることを考えると、演算子の可能な配置をすべて試行するアプローチは直ちに実行不可能になります。$3^{10^5}$演算子の配置方法。 これは、指数関数的な増加を回避するアプローチ、理想的には線形または線形演算が必要であることを意味します。 

0 と 1 では、乗算が他の数値とは異なる方法で相互作用するため、明らかではないエッジ ケースが発生します。 たとえば、ゼロを乗算すると実行中の積が消滅するため、「2_0+3」は 3 を生成し、0 を生成する「2_0*3」よりも優れている可能性があります。同様に、1 を乗算しても値は増加しないため、1 を加算する方が望ましい場合もあります。 入力桁には負の数値は存在しませんが、減算では加算とは異なり累計が減少する可能性があるため、許可されたセットに減算が含まれる場合は慎重に考慮する必要があります。 

常に最大の 2 つの数値を乗算する不注意で貪欲なアプローチは、シーケンス内にゼロが出現した場合、または小さな数値の加算により最終合計が 1 を含む乗算チェーンよりも大きくなる場合に失敗する可能性があります。 

## アプローチ

 ブルートフォース手法では、数字間の演算子のあらゆる組み合わせを試します。 これは、考えられるすべての表現を検討するため、原則的には正しいですが、その複雑さは次のとおりです。$O(3^{n})$、これは絶対に不可能です$n$100,000まで。 すべてのサブ配列とそれらの間で考えられるすべての演算子を単純な方法で考慮する動的プログラミング アプローチであっても、おおよそ次のようになります。$O(n^2)$が遅すぎます。 

重要な洞察は、桁の範囲が狭い (0 ～ 9) と優先順位規則により、乗算が許可されている場合はシーケンスをゼロで分割できるということです。これは、何かにゼロを乗算すると積がゼロにリセットされるためです。 ゼロを超えると、一連の数字に対して加算か乗算かを決定するだけでよく、これは小さな数字に対して貪欲に行うことができます。 たとえば、1 と乗算の両方が許可されている場合、1 を乗算すると値は増加しませんが、加算すると値が増加するため、多くの場合、それらを乗算するよりも加算する方が適切です。 ゼロのない一連の数字の場合は、左から右に反復処理を行って、現在の数字が 0 または 1 で、加算と乗算の両方が許可されている場合は加算が望ましい、またはそうでない場合は決定します。 それ以外の場合は乗算。 

したがって、最適なアプローチは、0 の周囲をセグメント化し、1 を含むシーケンスを異なる方法で処理し、許可された演算子セットを尊重する、貪欲な左から右へのスキャンです。 減算は加算と同様に処理できます (存在する場合)。ただし、合計が不必要に減少しないように常に慎重に適用されます。

 ## アルゴリズムのチュートリアル

 1. 一連の数字を解析してリストにし、許可される演算子を O(1) ルックアップのセットに記録します。 許可される演算子が 1 つだけの場合、解決策は簡単です。その演算子をどこにでも挿入します。 
2. 乗算が許可されており、シーケンスにゼロが含まれている場合は、シーケンスをゼロで区切られたサブ配列に分割します。 加算が許可されている場合は、各ゼロの前にプラスが付きます。ゼロによる乗算は積をリセットするためです。 ゼロ自体は、合計を最大化するために加算または減算できる個別の数値として扱われます。 
3. ゼロを含まない数字の各部分配列を繰り返します。 これらについては、左から右に繰り返して、各ペアの間にどの演算子を配置するかを決定します。 加算が許可されており、現在の桁または次の桁が 0 または 1 の場合は、乗算では値が増加しないか、ゼロに減少するため、加算を実行します。 それ以外の場合は、乗算を配置します。 
4. 結果のセグメントを再度連結し、許可されている場合はゼロの周囲にプラス演算子またはマイナス演算子を挿入し、その他の場所では乗算を行います。 
5. 構築された式を出力します。 

機能する理由: 不変条件は、各位置で、0 と 1 を考慮して、実行中の積または合計に対する次の桁の寄与を最大化することです。 ゼロで分割すると、不必要に値が減ってしまう乗算でゼロが生成されなくなります。また、1 を含む加算を選択すると、1 を乗算して合計が無駄にならないようになります。 これにより、桁の範囲と演算子の優先順位規則が制限されているため、全体的に最適な式が生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))
ops = set(input().strip())

if n == 1:
    print(a[0])
    sys.exit()

# Only one operator allowed
if len(ops) == 1:
    op = ops.pop()
    print(op.join(map(str, a)))
    sys.exit()

res = []
for i in range(n - 1):
    res.append(str(a[i]))
    x, y = a[i], a[i + 1]

    if '*' in ops:
        if '+' in ops:
            if x <= 1 or y <= 1:
                res.append('+')
            else:
                res.append('*')
        elif '-' in ops:
            if x <= 1 or y <= 1:
                res.append('-')
            else:
                res.append('*')
        else:
            res.append('*')
    else:
        if '+' in ops:
            res.append('+')
        else:
            res.append('-')
res.append(str(a[-1]))
print(''.join(res))
```最初のセクションでは、演算子が 1 つだけ許可される簡単なケースを扱います。 次に、メイン ループはローカルで貪欲な決定を行います。1 より大きい桁には乗算が選択され、0 または 1 が表示された場合は加算または減算が選択され、値が小さくなるのを回避します。 最後の要素は演算子なしで追加されます。
