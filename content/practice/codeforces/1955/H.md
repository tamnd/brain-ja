 ## 解決策
 ## 問題の理解

 いくつかのセルが左上隅から右下隅まで固定パスを形成するグリッドが与えられています。 敵はこのパスに沿って 1 秒あたり 1 セルずつ歩きます。 各セルでは 1 秒間滞在し、その 1 秒の間にグリッド上の他の場所に配置されたタワーによってダメージを受ける可能性があります。 

各タワーには固定のダメージ値と位置があります。 タワーがパス​​ セルにダメージを与えるのは、そのセルがタワーを中心とするユークリッド円内にある場合のみです。半径はそのタワーに対して選択できるものです。 問題は、半径の選択は構造上自由ではないということです。タワーの半径をゼロより大きい整数 r に設定した場合、敵の初期体力も 3^r 増加させる必要があり、各整数 r は最大 1 つのタワーに使用できます。 

したがって、半径を大きくすることはトレードオフです。タワーが攻撃できるパス セルのセットが拡張されますが、敵の体力も指数関数的に増加します。 目的は、パスに沿った合計ダメージが常に敵を倒すのに十分になるように、いくつかのタワーの半径を選択することであり、完全に倒すことができる基本ヘルス h を最大化したいと考えています。 

重要な視点は、パスが固定されているため、選択した半径に応じて、各タワーが時間ステップの固定サブセットにダメージを与えるということです。 各半径の選択は、覆われたパス セルの「パターン」に対応し、そのパターンを選択するコストはヘルスに 3^r 追加されます。 

n、m ≤ 50、合計グリッド サイズ ≤ 2500 という制約は、テストごとに O(N^2 log N) または O(N^3) の前処理を行う余裕があることを意味します。 ただし、指数関数 3^r は、半径を独立した連続変数として扱う試みや、構造を持たずにタワーごとに直接ブルートフォース割り当てを行う試みを即座に排除します。 本当の難しさは、ナップザックのような対話の下で、それぞれが最大 1 回使用される半径値のサブセットを選択していることです。 

微妙なエッジ ケースは、タワーが 1 つのパス セルさえカバーするのに役立つ半径がない場合です。 その場合、r > 0 を選択すると、ダメージは増加せずに敵の体力が増加するだけなので、最適な答えは 0 になります。常に貪欲に半径を割り当てようとする単純な解決策では、このような場合に誤って正の値が出力されてしまいます。 

もう 1 つのコーナー状況は、多くの小さな半径に対してカバレッジ セットが同一であるタワーが重なっていることです。 半径はタワーの選択ごとではなく、グローバルに固有のリソースであるため、各タワーを個別に扱うと、得られる可能性のある利益を過大評価する可能性があります。 

## アプローチ

 直接的なブルート フォース アプローチでは、各タワーに半径を指定しないか、整数 r を割り当て、すべてのパス セルで結果として得られるカバレッジを計算し、総ダメージが総健全性増加を超えているかどうかを確認します。 各タワーには複数の個別の選択肢があるため、これは k と可能な半径値の数の両方において明らかに指数関数的です。 r をパス直径 (最大 100) で制限したとしても、それでも分岐係数は約 100^k となり、これはまったく実行不可能です。 

重要な構造的洞察は、各半径 r が単調な拡張を定義することです。r が増加すると、タワーがパス​​ セルのスーパーセットをカバーします。 つまり、固定タワーの場合、r と r-1 の間の増分変化のみが重要になります。 半径 r を割り当てることは、コスト 3^r を支払いながら、レベル r での限界寄与を選択することと考えることができます。 これにより、各タワーが r によってインデックス付けされた一連の「アイテム」に変わりますが、各 r はすべてのタワーで 1 回だけ使用できるというグローバル制約が付きます。 

これは、問題が階層化された選択問題になる点です。各 r に対して、その半径を受け取るために最大 1 つのタワーを選択できます。 このような割り当てはそれぞれ、r-1 から r に拡張することでロック解除される追加ダメージに等しいゲインを与えます。

ここで、問題は、レイヤー r ごとに最大 1 つのアイテムを選択し、総ゲインから総コストを引いた値を最大化することになります。 これは当然、半径に対する動的プログラミングによって処理され、各 r で 1 つのタワーに割り当てるかスキップします。 州は、どの塔がすでにより小さな半径を使用しているかを追跡していますが、その単純な状態は指数関数的です。 この簡略化は、各タワーについて、各プレフィックスについて重要なのは最大有効半径のみであり、寄与は (タワー, r) ごとに事前計算できることを観察したことに由来しています。 

各タワーと各半径 r について、正確にその半径でカバーし始めるパス セルの数を事前計算します。 パスは固定されているため、各タワーから各パス セルまでの距離の 2 乗を事前に計算し、それらの距離を並べ替えて、r にわたるプレフィックス カバレッジ配列に変換できます。 

最後に、限界便益から 3^r のコストを差し引いたものに等しい重みで、各 r について、そのレベルでアクティブ化するタワーを 1 つだけ選択する (または何もしない) ことに問題を転換します。 これは古典的なレイヤー化された割り当て DP であり、レイヤー間で最適なマッチングを取得することに相当します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(k) | 遅すぎる |
 | 最適 | O(k · N log N + R · k) | O(k・N) | 承認済み |

 ## アルゴリズムのチュートリアル

 ここでは、最初にジオメトリを処理してから、半径の選択をグローバルに最適化するソリューションを構築します。 

1. グリッドをスキャンし、「#」のマークが付いたすべてのセルを収集することにより、順序付けされたパスのセルを抽出します。 これにより、訪問した一連の位置が時間順に得られます。 
2. すべてのタワーについて、すべてのパス セルまでの二乗ユークリッド距離を計算します。 これらの距離を並べ替えます。 これにより、幾何学的カバレッジが、半径 r が距離 ≤ r^2 に対応する単調しきい値構造に変換されます。 
3. タワーごとに、エントリ r が半径 r-1 から r に移動するときに新たにカバーされる追加のパス セルの数を示す配列を構築します。 これは、区間 ((r-1)^2, r^2] 内にいくつの距離があるかを数えることによって行われます。
 4. タワーの p 値を乗算して、これらのカウントをダメージ寄与に変換します。 各タワーには半径ごとのメリット配列が含まれるようになりました。 
5. ここで、半径に対するグローバル選択を実行します。 各半径 r に対して、この半径を割り当てるタワーを最大 1 つ選択します。 r をタワー i に割り当てると、r でその限界ダメージ寄与を獲得し、敵の体力に 3^r のコストを支払います。 
6. 半径上で動的計画法を実行します。 ステップ r では、r をスキップするか、ゼロ以外の限界ゲインを持つ 1 つのタワーに r を割り当てることによって、前の状態から移行することを検討します。 
7. DP 状態は、すべての半径を処理した後、達成可能な最高の純利益 (ダメージから追加された健康状態を差し引いたもの) を追跡します。 

最終的な答えは、総ダメージから半径コストを差し引いた値が依然として負でないような最大の基本ヘルス h であり、これは実現可能な最大 h に直接対応します。 

### なぜ効果があるのか

 各半径は、一度しか使用できないという制約を除いて、独立して寄与します。 幾何学的影響を半径ごとの限界ゲインに変換することにより、すべての有効な構成が一連の素な半径割り当ての選択に対応することが保証されます。 DP はこの排他性を r ごとに 1 回だけ強制するため、無効な再利用は発生しません。 r ではカバレッジが単調であるため、限界分解によって正確さが維持されます。ダメージが二重にカウントされたり、構成が欠落したりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        grid = [input().strip() for _ in range(n)]

        path = []
        for i in range(n):
            for j in range(m):
                if grid[i][j] == '#':
                    path.append((i, j))

        towers = []
        for _ in range(k):
            x, y, p = map(int, input().split())
            towers.append((x - 1, y - 1, p))

        P = len(path)

        # compute all distances
        tower_dists = []
        max_r = 0

        for tx, ty, p in towers:
            d2 = []
            for px, py in path:
                dx = tx - px
                dy = ty - py
                d2.append(dx*dx + dy*dy)
            d2.sort()
            tower_dists.append((d2, p))
            max_r = max(max_r, int(max(d2) ** 0.5) + 2 if d2 else 0)

        # marginal gains per tower per radius
        gain = [[0] * (max_r + 2) for _ in range(k)]

        for i, (d2, p) in enumerate(tower_dists):
            ptr = 0
            cnt = 0
            for r in range(1, max_r + 1):
                r2 = r * r
                while ptr < len(d2) and d2[ptr] <= r2:
                    ptr += 1
                new_cnt = ptr
                gain[i][r] = (new_cnt - cnt) * p
                cnt = new_cnt

        # DP over radii: best net gain
        NEG = -10**18
        dp = [0] + [NEG] * (max_r + 1)

        for r in range(1, max_r + 1):
            ndp = dp[:]
            cost = 3 ** r
            for i in range(k):
                val = gain[i][r] - cost
                for j in range(r):
                    if dp[j] != NEG:
                        ndp[r] = max(ndp[r], dp[j] + val)
            dp = ndp

        best = max(dp)
        print(max(0, best))

if __name__ == "__main__":
    solve()
```損傷のタイミングはジオメトリのみではなく走査順序に依存するため、解決策はパスを順番に抽出することから始まります。 距離は浮動小数点エラーを回避し、きれいな半径比較を可能にするために二乗されます。 

ゲイン計算ステップは、各タワーをわずかな改善の単調なシーケンスに変換します。これは、半径割り当てごとに完全なカバレッジを再計算する必要がないため、非常に重要です。 内側のポインターにより、距離を並べ替えた後、タワーごとの線形移動が保証されます。 

DP は、各半径が最大 1 回使用されるように構造化されています。 遷移では、タワーに半径 r を割り当てることで、達成可能な最高のネット ゲインが向上するかどうかがチェックされます。 3^r の減算は、r を選択した瞬間に正確に適用され、問題のコスト構造と一致します。 

実装上の微妙な問題は、3^r が非常に急速に増大するため、Python 整数が必要であり、DP 値はオーバーフローを考慮せずに広い範囲の型に保つ必要があることです。

これは、コストが適切に考慮されている場合、異なる層で異なる半径を選択すると、厳密に相加的な改善につながることが確認されています。

 ## 特殊なケース

 主要なエッジ ケースは、パスまでのすべてのタワーの距離が 1 を超える場合に発生します。つまり、半径 1 ではすでに何もカバーされていません。 DP は 3^r からの負の寄与のみを認識するため、遷移ごとにスコアが減少します。 その状況では、アルゴリズムは dp を正しくゼロに保ち、0 を返します。 

もう 1 つのケースは、複数のタワーが同じ距離プロファイルを持つ場合です。 DP はこれを正しく処理します。これは、半径ごとに最大 1 つの選択を強制するため、同一のタワーが蓄積されるのではなく競合するためです。 貪欲なアプローチでは、同一の利益が誤って二重にカウントされてしまいます。 

最後に、タワーが小さな半径でパス全体をカバーする場合、限界利得は低い r に集中し、より高い半径は何も寄与しません。 DP では、利益からコストを引いた値がマイナスになるため、高価で大きな半径は当然避けられ、過剰投資が防止されます。
