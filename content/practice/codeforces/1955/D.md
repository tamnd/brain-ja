 ## 解決策
 ## 問題の理解

 長さのサブセグメントを数えるように求められます`m`配列内で`a`別の配列と比較して「良好」である`b`長さの`m`。 サブセグメントは、その要素を再配置した後、少なくとも次の場合に良好であるとみなされます。`k`そのうちの要素と一致します`b`。 実際には、これは、サブセグメントと`b`少なくとも含まれています`k`要素。 

入力は複数のテスト ケースを提供し、それぞれに配列が含まれます`a`そして`b`、および整数`n`、`m`、`k`。 全部の合計サイズは`a`テスト ケース全体の配列が次を超えない`2 * 10^5`、同様に`b`。 これにより、効率的に実行できる操作の総数が制限されます。 すべてのサブセグメントを反復して比較するソリューション`b`要素ごとに`O(n * m)`最悪の場合、これは到達する可能性があるため、時間は遅すぎます。`2 * 10^5 * 2 * 10^5 = 4 * 10^10`操作。 

エッジケースには、要素が繰り返されるサブセグメントが含まれます。`k = m`(完全一致が必要)、`k = 1`(最小限の一致が必要)、および`a`または`b`繰り返しの数字が含まれています。 単純なアプローチでは、個別の要素が誤ってカウントされたり、複数の重複が含まれる場合に失敗したりする可能性があります。 たとえば、次の場合`a = [1,1,1]`そして`b = [1,2,3]`と`k = 2`、アルゴリズムはこのセグメントを誤って良好としてカウントしてはなりません。`1`で`b`セグメントに一致させることができます。 

## アプローチ

 ブルートフォースアプローチでは、長さのサブセグメントごとに反復処理が行われます。`m`で`a`、そしてそれぞれについて、次のマルチセット交差を計算します。`b`。 一致をカウントするには、サブセグメントのすべての要素を反復処理し、次の要素と比較する必要があります。`b`。 これは定義を直接実装しているため正しく機能しますが、`O(n * m)`テストケースごとに複雑さがあり、大規模な場合は失敗します`n`そして`m`。 

重要な洞察は、一定の長さのスライディング ウィンドウを維持できるということです。`m`以上`a`内の要素と一致する要素の数を追跡します`b`周波数マップを使用します。 最初に、次の各数値の出現を数えます。`b`辞書で。 次に、ウィンドウを横にスライドさせると、`a`、現在のウィンドウに表示される要素の数を表す別の辞書を維持します。`b`。 要素がウィンドウに入ると、要素がウィンドウ内に存在する場合は一致カウントをインクリメントします。`b`まだ完全には一致していません。 要素がウィンドウの外に出ると、それが以前に交差に寄与していた場合、一致カウントが減分されます。 これにより、複雑さが軽減されます。`O(n)`テストケースごとに使用`O(m)`周波数追跡のための追加スペース。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m) | O(m) | 遅すぎる |
 | スライディング ウィンドウ + 周波数マップ | O(n) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列の頻度辞書を構築する`b`。 各キーは数値であり、値はそのキーが出現する回数です。 これにより、サブセグメント内の要素が一致するかどうかを効率的にチェックできます。`b`。 
2. 最初のスライディング ウィンドウを初期化します。`m`の要素`a`。 ウィンドウ内の要素と一致する要素の数を維持します。`b`必要な頻度を超えずに。 ウィンドウに入る要素ごとに、要素が存在する場合は一致カウンタをインクリメントします。`b`まだ最大数に達していません`b`。 
3. 現在のウィンドウの一致カウンタが少なくとも`k`。 そうであれば、答えを増やします。 
4. ウィンドウを一度に 1 要素ずつ前方にスライドさせます。 シフトごとに、ウィンドウから出る要素を削除し、ウィンドウに入る要素を追加します。 頻度辞書に従って一致カウンタを更新します。 削除するときに、要素が一致に寄与していた場合はカウンターをデクリメントします。 追加するときに、貢献している場合は増分します。 
5. 配列の最後まで繰り返します。 答えは、一致カウンターが少なくとも存在するウィンドウの合計数になります。`k`。 

機能する理由: 各ステップで、一致カウンターは、現在のウィンドウ内の要素に対応する要素の数を正確に反映します。`b`頻度を超えずに。 ウィンドウをスライドすると、このカウントが効率的に更新され、正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import Counter

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        b_count = Counter(b)
        window_count = Counter()
        matches = 0
        result = 0

        # Initialize first window
        for i in range(m):
            x = a[i]
            if x in b_count:
                if window_count[x] < b_count[x]:
                    matches += 1
                window_count[x] += 1
        if matches >= k:
            result += 1

        # Slide the window
        for i in range(m, n):
            out_elem = a[i - m]
            in_elem = a[i]

            if out_elem in b_count:
                if window_count[out_elem] <= b_count[out_elem]:
                    matches -= 1
                window_count[out_elem] -= 1

            if in_elem in b_count:
                if window_count[in_elem] < b_count[in_elem]:
                    matches += 1
                window_count[in_elem] += 1

            if matches >= k:
                result += 1

        print(result)

if __name__ == "__main__":
    solve()
```この解決策は、次の周波数を数えることから始まります。`b`、次にウィンドウをスライドさせます`a`、一致を更新し、各ステップで良好なサブセグメントの状態を確認します。 微妙な部分は、増加と減少を確実にしています。`matches`で許可される最大出現回数を尊重します。`b_count`、繰り返される数値を正しく処理します。 エッジ境界は、慎重にインデックスを作成することで管理されます。`i - m`ウィンドウから出る要素の場合。
