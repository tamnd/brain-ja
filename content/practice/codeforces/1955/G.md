 ## 問題の理解

 整数の長方形グリッドが与えられます。 移動は左上のセルで開始し、右下のセルで終了します。各ステップでは、1 つのセルを下に移動するか、1 つのセルを右に移動することしかできません。 このようなすべての移動シーケンスは単調なパスを形成します。 

固定パスの場合、そのパス上のすべての値を取得し、その最大公約数を計算します。 異なるパスには異なるセルのセットが含まれるため、異なる GCD が生成される可能性があります。 タスクは、すべての有効な単調パスで取得できる最大 GCD を決定することです。 

これを再構成する便利な方法は、接続された「階段」パスを選択することです。$(1,1)$に$(n,m)$、最大の整数が必要です$g$すべての訪問セルが次の条件で割り切れるパスが少なくとも 1 つ存在するようにします。$g$。 

制約は重要です。$10^4$テスト ケースはありますが、すべてのテストにわたるセルの合計数は最大でも$2 \cdot 10^5$。 これにより、候補値ごとまたはパスごとにパス DP を明示的に再計算するものはすべて即座に除外されます。 すべてのパスを試行するソリューションは、次の点で指数関数的です。$n+m$、セルごとに GCD 状態を追跡する DP であっても、除数ごとに冗長に再計算する場合は大きすぎます。 

グリッドに異なる素因数を共有する小さな値が多数ある場合、微妙なエッジ ケースが発生します。 GCD は値が単調ではないため、常により大きな値を持つ近傍を選択する単純な貪欲パスは大失敗する可能性があります。 

2 番目の明白ではない失敗ケースは、割り算構造を維持するために、最適な GCD パスが意図的により小さい数を通過する必要がある場合です。 例えば：```
2 3
6 5 6
6 6 6
```最適なパス GCD は 6 ですが、貪欲な「小さな値を避ける」アプローチでは、5 を経由しようとして、すぐに答えが破棄される可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。左上から右下まですべての単調パスを列挙し、その値を収集し、GCD を計算し、最大値を追跡します。 このようなパスの数は$\binom{n+m-2}{n-1}$、中程度のグリッドでも指数関数的に増加します。 100x100 グリッドの場合、これは天文学的に大きいため、直接列挙することは不可能です。 

より構造化された強引な観察は、逆に考えることです。 候補値を固定するとします$g$。 すべてのセルを以下で割り切れるマークを付けることができます。$g$、マークされたセルのみを使用する単調なパスが存在するかどうかを尋ねます。 これは標準の到達可能性 DP です。 そのようなパスが存在する場合、$g$実現可能です。 

これにより、問題は次のように変換されます。最大のものを見つける$g$グリッドが次の倍数に制限されるようにする$g$左上から右下への有効なパスがまだ含まれています。 

重要な洞察は、恣意的に試みる必要はないということです。$g$。 すべての有効な答えは、選択したパス上のすべてのセルの値を除算する必要があります。特に、パスによって誘導されるすべての部分構造の両方の端点を除算する必要があります。 これは、推測ではなく GCD 状態に直接取り組むことを示唆しています。$g$。 

直す代わりに$g$、パスに沿って可能な GCD を伝播します。 各セルでは、そのセルに到達する任意のパスによって達成可能なすべての可能な GCD のセットを維持します。 隣接セルからの移行では、前の GCD を取得し、それを現在のセル値と組み合わせます。 GCD は厳密に減少するか同じままであるため、実際にはセルごとの個別の値の数は少ないままであり、数理論の特性によって制限されます (各ステップでは現在の値の約数のみを導入できます)。 

これにより、問題は、各状態が GCD 値のセットであるグリッド上の DP に変わります。

 ## アルゴリズムのチュートリアル

 すべてのセルについて計算します$(i,j)$、からの有効なパスによって達成可能なすべての GCD 値のセット$(1,1)$あの細胞に。 

1. 各セルにマップまたは到達可能な GCD のセットを格納する DP 構造を初期化します。 で$(1,1)$、唯一の値は$a_{1,1}$、パスには要素が 1 つしかないためです。 
2. グリッドを行ごと、列ごとに移動します。 各セルについて、上隣接セルと左隣接セルからの遷移を考慮します。これは、単調パスではこれらが唯一の有効な先行セルであるためです。 
3. 各先行世代の GCD 値$g$、新しい値を計算します$g' = \gcd(g, a_{i,j})$。 入れる$g'$現在のセルのセットに追加します。 
4. 両方の近隣からの貢献をマージします。 これにより、セルに到達するすべてのパスが確実に表現されます。 
5. すべてのセルを処理した後、答えは右下のセルのセットに格納されている最大値になります。 

重要な設計上の選択は、生のパスを決して保存せず、その GCD サマリーのみを保存することです。 セルに到着するすべてのパスは、単一の整数状態によって要約されます。 

### なぜ効果があるのか

 DP の不変条件は、すべてのセルで$(i,j)$、保存されたセットには、からの有効な単調パスの可能なすべての GCD が正確に含まれます。$(1,1)$に$(i,j)$。 1 つのセルによるパスの拡張は、単一のセルを介した GCD にのみ影響するため、前方遷移では正確さが維持されます。$\gcd$新しい値での操作。 パスの他のプロパティは重要ではありません。 すべての有効なパスは上または左の隣接パスから取得される必要があるため、これら 2 つのセットをマージするとすべての可能性が排除されます。 

最後のセルはすべての有効なパス サマリーを集約するため、その中の最大の要素が達成可能な最良の GCD になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]

        dp = [[set() for _ in range(m)] for _ in range(n)]

        dp[0][0].add(a[0][0])

        for i in range(n):
            for j in range(m):
                if i == 0 and j == 0:
                    continue

                cur = set()

                if i > 0:
                    for g in dp[i-1][j]:
                        cur.add(gcd(g, a[i][j]))

                if j > 0:
                    for g in dp[i][j-1]:
                        cur.add(gcd(g, a[i][j]))

                dp[i][j] = cur

        print(max(dp[n-1][m-1]))

if __name__ == "__main__":
    solve()
```このソリューションは、セットの DP テーブルを構築します。 各セルは、上と左に隣接するセルからの寄与をマージし、GCD 更新を使用して各パス状態を圧縮します。 での初期化$(0,0)$すべてのパスが正しく開始されるようにします。 

よくある間違いは、両方の受信方向を個別にマージする必要があることを忘れていることです。 もう 1 つの微妙な問題は、結果を結合する代わりに上書きすることです。これにより、有効なパスが破棄されます。 セルごとに新しいセットを使用すると、反復後の汚染を回避できます。

 ## 特殊なケース

 1x1 グリッドには 1 つのパスと 1 つの値のみが含まれるため、DP は答えで直接初期化されます。 アルゴリズムは開始セットをその値に正しく設定し、それを返します。 

すべての値がペアごとに互いに素である場合、すべての gcd 遷移はすぐに 1 に崩壊します。DP はこの崩壊をすべてのパスに正しく伝播し、最終的な答えはルーティングに関係なく 1 になります。 

グリッドが一定の場合、すべての遷移は同じ値を保持します。$\gcd(x, x) = x$。 DP はそれより小さい値を導入することはなく、最終セルは元の数値を保持します。 

高い値のパスが低い値を経由する迂回を必要とする場合でも、DP はそのパスをキャプチャします。これは、DP が大きさに基づいてプルーニングを行わず、gcd 状態のみに基づいてプルーニングを行うためです。 有効な中間 gcd はすべて保存され、最適なパスが早期に失われないことが保証されます。
