 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times n$3 つの値によって完全に決定されるグリッド。左上のセルと、下方向と右方向への移動を制御する 2 つの固定増分です。 1 ステップ下に移動すると常に追加されます$c$1 歩右に移動すると、常に追加されます$d$。 このため、開始値が固定されると、グリッド内のすべてのセルはその座標の一次関数として表現できます。 

このグリッドが概念的に構築された後、次のマルチセットが与えられます。$n^2$任意の順序の整数。 タスクは、このマルチセットが、指定されたオブジェクトに対して一意に定義されたグリッドに表示される値のセットと正確であるかどうかを判断することです。$n$、$c$、 そして$d$。 グリッド レイアウトを再構築する必要はありません。値がマルチセットと正確に一致するグリッドが存在することを確認するだけです。 

制約により、ほぼ線形または$O(n^2 \log n)$最悪の場合、テストごとに。 すべてのテスト ケースにわたる要素の合計数は最大でも$2.5 \cdot 10^5$、テストごとのソートやハッシュにおける二次関数は問題ありませんが、考えられるすべての開始値をシミュレートしたり、大量の再計算を行ってセルごとの一貫性をチェックしようとするものは遅すぎます。 

配列の順序が重要であると考えると、素朴な落とし穴が生じます。 そうではありません。 もう 1 つの微妙な失敗モードは、局所的な相対的な違いのみが重要であると仮定することです。 たとえば、グリッドを固定せずに行方向または列方向のパターンを検証しようとすると、重複が存在する場合や並べ替えによって構造が非表示になった場合に誤検知が発生します。 

小さな失敗例を直観的に考えてみましょう。$n=2$、$c=1$、$d=2$、グリッドは次のようにする必要があります$$\begin{pmatrix} x & x+2 \\ x+1 & x+3 \end{pmatrix}$$マルチセットは正確に次のようにする必要があります$\{x, x+1, x+2, x+3\}$。 ソートされた順序で隣接性のみをチェックしようとすると、間隔は正しいが構造を形成できない不正なマルチセットを誤って受け入れる可能性があります。 

## アプローチ

 ブルートフォース解釈では、考えられるすべての値を試します。$a_{1,1}$出発点の候補として。 各候補について、漸化関係を使用してグリッド全体を構築し、結果のマルチセットを指定された配列と比較します。 値の範囲は最大なので、$10^9$、開始値は、列挙を実現できるように直接制限されていません。 さらに悪いことに、それぞれの建設に費用がかかります$O(n^2)$、試行する候補者の数に意味のある制限がないため、このアプローチは完全に実行不可能になります。 

重要な構造的観察は、グリッドがその最小要素によって完全に決定されるということです。 なぜなら両方とも$c$そして$d$が正の場合、下または右にステップごとに値が厳密に増加します。 これは、グリッド内の最小要素は次のとおりである必要があることを意味します。$a_{1,1}$、そしてそこからグリッド全体を決定論的に再構築することができます。 

配列をソートしたら、最小値を左上隅として扱うことができます。 そこから、グリッドのすべての期待値が一意に決定されます。 残る唯一の問題は、マルチセットにそれらの値が正確に含まれているかどうかです。 

重要な削減は、2D 構造を 1D 検証問題に変えることです。ジオメトリについて推論する代わりに、生成された期待値のシーケンスをソートされた配列に対して検証します。

 ## アルゴリズムのチュートリアル

 私たちは、ソートによって意図された構造が明らかになるという事実を利用します。 

1. サイズの配列をソートする$n^2$。 これにより、最小の要素が次の要素に対応すると想定される順序付けの候補が得られます。$a_{1,1}$。 グリッド内のすべての移動は厳密に次の理由により値を増加させるため、これは正当化されます。$c, d \ge 1$。 
2. 最小の要素を開始値の候補とします。$x$。 これにより、グリッド全体が一意に固定されます。 
3. ポジションごとに$(i, j)$、期待値を計算します。$$x + i \cdot c + j \cdot d$$これは、再帰を左上から繰り返し適用した結果に直接続きます。 
4. 各計算値を、同じインデックスでソートされた配列と比較します (行優先のトラバーサルを使用)。 不一致が発生すると、マルチセットはプログレッシブ スクエアを表現できなくなります。 
5. すべての値が正確に一致する場合、配列は有効です。 

走査に使用される順序は、ソートされた配列と一致している必要があります。 構築と並べ替えの両方で全体的な順序付けが強制されるため、行優先の列挙は値の増加に合わせて調整されます。$c, d > 0$、両方の次元にわたって単調な成長を保証します。 

### なぜ効果があるのか

 この構造により、行方向と列方向の両方でグリッドが厳密に増加します。 これにより、グリッド値が行優先の順序で平坦化されたときに、厳密に増加するシーケンスを形成することが保証されます。 ソートでは同じマルチセットの一意の昇順も生成されるため、マルチセットが構築されたグリッドとまったく同じである場合にのみ、両方のシーケンスが一致する必要があります。 これにより、配置に関する曖昧さが解消されます。最小の要素が固定されると、他の値はすべて 1 つの有効な位置を持ちます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c, d = map(int, input().split())
        b = list(map(int, input().split()))
        
        b.sort()
        start = b[0]
        
        expected = []
        for i in range(n):
            for j in range(n):
                expected.append(start + i * c + j * d)
        
        expected.sort()
        
        if expected == b:
            print("YES")
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```この解決策は、入力マルチセットをソートすることから始まります。 グリッドの単調な構造は、平坦化されたときに固有の増加順序を保証するため、これは不可欠です。 

次に、グリッドが有効である場合に、最小値から始めてグリッドがどうなるかを再構築します。 式$start + i \cdot c + j \cdot d$行と列の増分を繰り返し適用することで直接導出されます。 

最後に、生成されたマルチセットを入力と比較します。 両方を並べ替えることで、位置レイアウトではなく、順序付けされていないコレクションを比較していることが保証されます。 

微妙な点は、方向や順列を推測しようとしていないことです。 厳格なポジティブさ$c$そして$d$は一意の増加方向を保証するため、他の配置では制約を満たすことができません。

 ## 特殊なケース

 重要なエッジ ケースは、入力配列に重複が出現する場合です。 以来$c, d \ge 1$、真のグリッドには重複が含まれないため、数値が繰り返されるとすぐにその構築が無効になります。 並べ替えでは重複が保持され、生成された厳密に増加するシーケンスとの比較は最初の繰り返し値で失敗するため、アルゴリズムはこれを自然に処理します。 

もう 1 つの微妙なケースは、最小の要素が実際には正しくない場合です。$a_{1,1}$。 ただし、グリッドは厳密に両方向に増加するため、他の位置にこれより小さい値を含めることはできないため、最小の要素が常に正しい開始点である必要があります。 これにより、初期化における曖昧さが解消されます。 

最終的なエッジケースが大きい$n = 500$、グリッドには 250,000 個の要素があります。 このソリューションはソートと線形生成のみを実行し、テスト ケースごとに 2 次の動作に移行する可能性のあるネストされた再計算を回避するため、安全性を保ちます。
