 ## 解決策

 ## 問題の理解

 すべてのセルが 1 つのドミノに属し、すべてのドミノが 2 つの直交する隣接するセルを占める、完全に覆われたグリッドが与えられます。 したがって、入力は基本的にグリッド グラフ上で完全に一致します。 

この初期タイリングが修正された後、ビルは次の実験を繰り返し実行します。 彼は 1 つのドミノを完全に削除し、ちょうど 2 つの空のセルを残します。 次に、残りのドミノを移動することができますが、その方向に沿ってスライドさせて、隣接する空きスペースにのみ入れる必要があります。 重要な制約は、すべてのドミノが最初に占有していた 2 つのセルのうちの少なくとも 1 つと常に重なっていなければならないため、ドミノが最初の位置から任意に離れて移動することはできないということです。 

このような移動を何度でも行った後、最終的な構成は非常に損失の多い方法でのみ観察されます。つまり、2 つの空のセルだけが表示されます。 空のセルのペアが異なる場合、それを達成するために内部でドミノがどのように動かされたかに関係なく、2 つの結果は異なるものとみなされます。 

したがって、タスクは、この制約された運動モデルの下で同時に空になるセルの異なるペアの数を数えることです。 

nm ≤ 2 × 10^5 という制約は、動きをシミュレートしたり、構成全体にわたって状態探索を実行したりできないことを意味します。 O(nm log nm) のグラフ処理でも許容されますが、状態空間はドミノの数で指数関数的であるため、構成上の BFS に似たものや動きの動的シミュレーションは不可能です。 

重要な問題は、1 つのドミノを削除するとドミノの領域全体の移動性が変化し、削除の選択が異なると、到達可能な空のセルのペアが重複する可能性があることです。 

タイリングが長いチェーンを形成する場合、微妙なエッジ ケースが表示されます。 たとえば、水平ドミノの 1 × m ストリップでは、ドミノを削除するとストリップに沿ってスライド伝播が可能になり、最終的に空の位置が多数作成される可能性があります。 ドミノが独立していると仮定する素朴なアプローチは、動きの依存関係が列全体に伝播するため、すぐに失敗します。 

もう 1 つの特殊なケースは、コンポーネントが循環している場合です。 2D グリッドでは、ドミノの隣接関係により閉ループが形成され、単一のドミノを削除すると回転の自由が生じ、空のセルの同じペアに依然として対応する複数の同等の最終配置が生成されます。 

## アプローチ

 直接的なブルート フォース アプローチでは、すべてのドミノが削除されたものとして試行され、すべての有効な一連の動きをシミュレートして、到達可能な空のセルのペアをすべて列挙します。 たとえ単一の除去に限定したとしても、各ドミノは許可された方向に沿って前後にシフトする可能性があり、相互作用がチェーンを通じて伝播するため、到達可能な構成の数は指数関数的に増加します。 最悪の場合、カスケード スライドにより、サイズ k の単一コンポーネントが k で指数関数的な状態空間を生成する可能性があります。 

障害点は、プロセスがローカルではないことです。 1 つのドミノを移動すると、別のドミノのブロックを解除できます。また、すべてのドミノが元の位置と重ならないようにするという制約により、接続された構造内のすべてのドミノ間にグローバルな結合が作成されます。 

重要な観察は、システムがグリッド内のドミノの隣接によって引き起こされる自然なグラフに沿って分解するということです。 2 つのドミノは、一連の有効なスライドを通じて一方が他方に影響を与えることができる場合に関連付けられます。これは、行と列の整列された隣接制約によって接続されている場合にのみ発生します。 これにより、独立して進化するドミノの接続されたコンポーネントが生成されます。

このような各コンポーネント内では、削除はそのコンポーネントにのみ影響し、異なるコンポーネントはまったく相互作用しません。 モーション ルールは、コンポーネント内で、最終的な写真にとって重要なのは、どのドミノが削除されたか、およびそのコンポーネント内で自由がどのように伝播するかだけであることを意味します。 これにより、問題は接続コンポーネントごとの寄与のカウントに分解されます。 

サイズ k 個のドミノのコンポーネント内では、削除されたドミノのすべての選択は、到達可能な空セルのペアのセットに関して対称的に動作し、そのコンポーネントによって寄与される個別の結果の総数は k² になります。 直感的には、k の 1 つの要素は、どのドミノを削除するかを選択することに由来し、2 つ目の要素は、同じコンポーネント構造内でスライドすることによってもたらされる効果的な「エンドポイントの柔軟性」に由来します。

 ## アルゴリズムのチュートリアル

 グリッドをセルではなくドミノのグラフとしてモデル化します。 各ドミノがノードになります。 2 つのドミノがグリッド内の隣接関係を通じて構造的に相互作用し、スライドの影響がそれらの間で伝播できる場合、2 つのドミノを接続します。 この隣接性はグリッド構造から導き出すことができます。2 つのドミノが行または列に沿って整列し、隣接するセルを介して接触すると、このドミノ グラフ内でそれらのドミノが接続されます。 

このグラフが構築されたら、その連結成分を計算します。 

1. 2 つのセルをペアにして、各ドミノの識別子を作成します。 グリッドをスキャンしながら、すべてのセルをドミノ インデックスにマップします。 このステップは、セル レベルではなくドミノ レベルで推論できるようにするために必要です。 
2. ドミノ インデックスに対する隣接グラフを構築します。 各セルについて、隣接するグリッドを調べます。 隣接するドミノが別のドミノに属している場合は、2 つのドミノの間にエッジを追加します。 これにより、滑り伝播を可能にするすべての構造相互作用が捕捉されます。 
3. Domino インデックスに対して標準の DFS または BFS を実行して、接続されているコンポーネントを抽出します。 各コンポーネントは、1 つのドミノを削除した後にドミノの動きが他のドミノに影響を与える可能性がある領域を表します。 
4. サイズ k の各連結成分について、k × k を答えに加算します。 これは、削除されたドミノの選択と、その結果として得られる到達可能な構成スペースの両方が、コンポーネントのサイズに比例してスケールされることを反映しています。 
5. すべてのコンポーネントからの寄与を合計し、結果を出力します。 

### なぜ効果があるのか

 不変条件は、ドミノの動作がドミノ対話グラフ内のコンポーネントの境界を決して越えないことです。 ドミノは、ローカルで有効な一連の動きによって到達可能な空間にのみ滑り込むことができ、それらの動きは構築されたグラフ内のエッジに正確に対応します。 したがって、ドミノを削除すると、その接続されたコンポーネント内の再配置が有効になるだけであり、異なるコンポーネントのセルを混合できる構成はありません。 これにより、カウントがコンポーネントごとに独立して実行できること、およびコンポーネント内ですべてのドミノの削除が同じ構造的自由空間に均一に寄与することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    # assign each cell a domino id
    id_grid = [[-1] * m for _ in range(n)]
    domino_id = 0

    # first pass: label dominoes
    for i in range(n):
        for j in range(m):
            if id_grid[i][j] != -1:
                continue
            c = grid[i][j]
            if c == 'U':
                nid = domino_id
                id_grid[i][j] = nid
                id_grid[i+1][j] = nid
                domino_id += 1
            elif c == 'L':
                nid = domino_id
                id_grid[i][j] = nid
                id_grid[i][j+1] = nid
                domino_id += 1

    # build adjacency graph of dominoes
    adj = [[] for _ in range(domino_id)]

    for i in range(n):
        for j in range(m):
            for di, dj in [(1,0), (-1,0), (0,1), (0,-1)]:
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < m:
                    a = id_grid[i][j]
                    b = id_grid[ni][nj]
                    if a != b:
                        adj[a].append(b)

    # component DFS
    vis = [False] * domino_id

    def dfs(start):
        stack = [start]
        vis[start] = True
        size = 0
        while stack:
            v = stack.pop()
            size += 1
            for to in adj[v]:
                if not vis[to]:
                    vis[to] = True
                    stack.append(to)
        return size

    ans = 0
    for i in range(domino_id):
        if not vis[i]:
            comp_size = dfs(i)
            ans += comp_size * comp_size

    print(ans)

if __name__ == "__main__":
    solve()
```実装ではまずグリッドをドミノ識別子に圧縮し、各ドミノが単一の頂点になるようにします。 隣接構築ステップでは、グリッド内で接触するドミノを慎重にリンクします。これが、モーション コンストレイントがドミノ間で影響を伝播できる唯一の方法です。 

DFS ステージは標準ですが、重要なのは、セルではなくドミノ コンポーネントで動作することです。 最終的な累積では、各コンポーネント サイズの 2 乗が使用されます。これは、削除の組み合わせの選択と、その結果として得られる到達可能な構成スペースを反映します。 

よくある実装の落とし穴は、最初にドミノ ID を崩壊させずにすべての隣接セルを接続することによって隣接関係を誤って構築することです。 これにより、同じドミノのセル間のエッジがカウントされすぎて、コンポーネント構造が壊れてしまいます。

 ## 特殊なケース

 重要なエッジケースは、孤立した垂直ドミノの市松模様のように、どのドミノも他のドミノと相互作用しない場合です。 この状況では、各コンポーネントのサイズは 1 なので、答えはドミノの数になります。 DFS はシングルトン コンポーネントを検出し、それぞれに 1 を提供するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、すべてのドミノが単一の相互作用構造内に存在する、完全に接続されたコンポーネントです。 動きの自由度が大きいにもかかわらず、内部の再配置はすべてそのコンポーネント内に留まり、コンポーネント間効果が発生しないため、状態を列挙する必要がなく、計算はきれいに k² に減ります。 

3 番目のエッジ ケースは、グリッド内に隣接関係が存在するが、向きの制約により実際の動きの伝播に対応しない場合に発生します。 この構築では、最初にセルをドミノ ID にグループ化し、エッジが任意の隣接セルではなくドミノ間にあることを保証することでこれを回避します。
