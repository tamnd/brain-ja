 ## 解決策

 ## 問題の理解

 それぞれ最大 20 ビットの整数のリストが与えられます。 2 つの位置を繰り返し選択し、ある数値から別の数値にビットをプッシュするビット単位の変換を適用できます。一方の数値はペアのビット単位の AND になり、もう一方はビット単位の OR になります。 

各演算では、配列全体の各ビット位置で設定されたビットの合計数が保存されます。これは、固定ビットの場合、ペアごとの変換では、選択した 2 つの数値にわたってそのビットに存在する 1 の数が変更されないためです。 

このような演算を任意の数実行した後、結果として得られるすべての数値の二乗和を計算し、それを最大化したいと考えます。 

入力サイズでは最大 200,000 個の数値が許可され、各数値は最大 20 ビットを持ちます。 これは、ペアに対する単一の 2 次プロセスですら遅すぎるため、ペア操作をシミュレートするアプローチは不可能であることを直ちに示唆します。 おそらくビット数を乗じた、n の線形または線形演算に近い値が必要です。 

主な問題は、操作が値を再配置するだけでなく、制限された方法でビットを継続的に再分配することです。 最終的な構成は任意ではありませんが、二乗和を最大化するためにビットを数値に集中させる方法を決定することが主なタスクとなる十分な柔軟性があります。 

単純な間違いは、配列を並べ替えたり、大きな数値を貪欲に組み合わせたりすれば十分だと考えることです。 たとえば、値について考えてみましょう。`[1, 2, 4]`。 ローカル ペアリング戦略では、最初に大きな値を組み合わせる可能性がありますが、最適な結果は、大きさではなくビット寄与の分散に依存します。 もう 1 つの失敗例は、複数の数値セットが保存されるか、単に並べ替えられるだけであると想定している場合です。 この操作では明らかに値が変更されるため、このようなアプローチでは実際の自由度が失われます。 

もう 1 つの微妙な問題は、AND は値を減らし、OR は値を増やすため、常に 1 つの要素の OR を最大化する方向に進む必要があると仮定していることです。 方向的には正しいですが、ビットごとの保存を理解していないと、誤った貪欲なマージの決定につながります。 

## アプローチ

 ブルートフォースアプローチでは、収束するまでペア間で可能なすべての操作をシミュレートします。 各操作では 2 つの値が変更され、プロセスは無限のステップ数にわたって継続される可能性があります。 長さ k のシーケンスに限定しても、各数値は 20 ビットの状態であり、それらが n 個存在するため、状態空間は指数関数的になります。 これはすぐに実行不可能になります。 

重要な観察は、整数の観点から考えるのをやめ、代わりに各ビットを独立して調べることです。 ビット位置が固定されている場合、配列内の 1 の数は決して変わりません。 これは、各ビット k が正確に cnt_k 個のビットに寄与し、最終的な数値に分配する必要があることを意味します。 

したがって、問題は再分配タスクになります。各ビット k が正確に cnt_k 個の数値に割り当てられるように、これらのビット寄与を数値に割り当てる必要があり、結果の整数の二乗和を最大化したいと考えます。 

これで構造がより明確になりました。 二乗は集中力に大きな報酬を与えます。 2 乗の交差項により値が増幅されるため、複数の上位ビットを同じ数値に入れると有益です。 たとえば、ビット 2^18 と 2^17 を 1 つの数値に結合すると、それらを分離するよりもはるかに大きなゲインが得られます。 

したがって、各ビットのコピー数が固定であることを考慮して、ビットをできるだけ均等に数値に詰め込みたいと考えています。 

標準的な貪欲な構造では、数値を増分的に構築し、常に次に利用可能なビットを現在最も小さい数値に割り当てます。 これにより、負荷のバランスを継続的に確保しながら、より小さい番号が段階的に埋められ、後でより高いビットを蓄積できるようになるため、高ビット集中が自然に出現することを可能にします。 

クリーンな実装では、現在の値に対する最小ヒープが使用されます。

 ## アルゴリズムのチュートリアル

 二乗に最大の影響を与える大きな寄与が最初に配置されるように、ビットを最高位から最低位まで処理します。 

1. 各ビットが現在いくつの数値に含まれているかを数えます。 ビット位置 k ごとに、そのビットが設定されている配列要素の数として cnt[k] を計算します。 各ビットの合計数は不変であるため、この値は動作中に変化することはありません。 
2. すべての n 個の数値を含む最小ヒープをゼロから初期化します。 各ヒープ要素は、構築中の数値の現在値を表します。 
3. 19 から 0 までの各ビット位置 k に対して、このビットを cnt[k] 回繰り返し割り当てます。 各割り当ては、ヒープから現在の最小の数値を取得し、それに 2^k を加算して、それをプッシュバックします。 最小の要素を選択する理由は、小さなベースに上位ビットを追加すると、二次利得の将来の可能性を最大化する方法で限界利益が増加するためです。 
4. すべてのビットを処理した後、すべての最終数値の二乗和を計算します。

正確さは、すべてのステップで、各ビット k が正確に cnt[k] 回使用されるビットの有効な部分割り当てを維持するという不変条件から得られます。また、そのようなすべての部分割り当ての間で、ヒープ戦略は分散のバランスを可能な限り維持します。 このバランスにより、最適ではない方法で 1 つの数値を時期尚早にオーバーロードすることなく、上位ビットをスタックできるようになります。 2 乗は集中度に報酬を与えるため、このプロセスはビット重みのビンへの最適なパッキングを効果的にシミュレートします。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    cnt = [0] * 20
    for x in a:
        for b in range(20):
            if x >> b & 1:
                cnt[b] += 1

    heap = [0] * n
    heapq.heapify(heap)

    for b in range(19, -1, -1):
        for _ in range(cnt[b]):
            x = heapq.heappop(heap)
            x += (1 << b)
            heapq.heappush(heap, x)

    ans = 0
    for x in heap:
        ans += x * x

    print(ans)

if __name__ == "__main__":
    solve()
```この解決策は、入力をビットごとのカウントに圧縮することから始まります。これは、任意の操作後に関連性が残る唯一の情報です。 ヒープは、最終的な数値の進化する構築を表します。 ビットを割り当てるたびに、バランスを維持しながら、時間の経過とともに複数のビットが単一の要素に蓄積されることを可能にするために、現在の最小の数値を意図的に選択します。 

ビットを上位から下位に処理することにより、二乗に対する構造的影響が最も重要となる早い段階で大きな寄与が確実に配置されます。 

## 実用的な例

 概念的な小さな例を考えてみましょう。`n = 3`、値`[1, 2, 4]`。 ビット数は、ビット 0、1、および 2 に対してそれぞれ 1 回発生します。 

ヒープを初期化します`[0, 0, 0]`。 

ビット 2 の処理後:

 | ステップ | ヒープ状態 | アクション |
 | --- | --- | --- |
 | 1 | [0, 0, 0] | 最小値に 4 を代入します |
 | 2 | [0、0、4] | |

 ビット 1 の処理後:

 | ステップ | ヒープ状態 | アクション |
 | --- | --- | --- |
 | 1 | [0、0、4] | 最小値に 2 を代入 |
 | 2 | [0、2、4] | |

 ビット 0 の処理後:

 | ステップ | ヒープ状態 | アクション |
 | --- | --- | --- |
 | 1 | [0、2、4] | 最小値に 1 を代入 |
 | 2 | [1、2、4] | |

 最終的な合計額は`1 + 4 + 16 = 21`。 

このトレースは、構造化された値を徐々に構築しながら、各ビットがどのように独立して割り当てられるかを示しています。 

次に、ビットが繰り返される場合を考えてみましょう。`a = [3, 5]`。 バイナリは`011`そして`101`。 ビット 0 に 2 つ、ビット 1 に 1 つ、ビット 2 に 1 つあります。 

から始めます`[0, 0]`。 

ビット 2 の後:

 | ヒープ | アクション |
 | --- | --- |
 | [0, 4] | ビット 2 を割り当てる |

 ビット 1 の後:

 | ヒープ | アクション |
 | --- | --- |
 | [2、4] | ビット 1 を割り当てる |

 ビット 0 の後:

 | ヒープ | アクション |
 | --- | --- |
 | [3、5] | 両方を割り当てる |

 最終的な合計額は`9 + 25 = 34`。 

これは、より高いビットがどのように初期構造を形成し、より低いビットが最終的な分布を洗練するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(20 n log n) | 各ビット割り当てでは、n 要素にわたるヒープ操作が使用されます。 
| スペース | O(n) | ヒープには n 個の構築された値が格納されます。 

この制約により、最大 2×10^5 要素と最大 20 ビット反復が許可されるため、最大数百万回のヒープ操作が可能となり、制限内に十分収まります。

 ## 特殊なケース

 n が 1 に等しい最小入力には演算は含まれません。 ヒープには要素が 1 つだけ含まれており、割り当てが発生しないため、アルゴリズムは単一値の 2 乗を正しく返します。 

すべて 0 の場合は、ビットカウントとヒープ初期化が中立性を保つかどうかをテストします。 すべての cnt[b] がゼロであるため、ヒープは変更されず、最終的な合計はゼロとなり、期待と一致します。 

すべての数値が同一である場合は、対称性が貪欲な割り当てを破っていないことをチェックします。 同一の候補が複数存在する場合でも、ヒープ操作ではそれらが均一に扱われ、最終的な構成でも総ビット数が考慮されるため、二乗和への正しい集計が保証されます。
