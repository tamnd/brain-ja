 ## 解決策
 ## 問題の理解

 長方形のブレッドボードがあります`n`行と`m`内部ノードの列。 ボードの 4 つの側面に沿ってポートがあります。 左側と右側が貢献します`n`それぞれのポートが、上部と下部の側面に寄与します`m`それぞれのポート。 

すべてのポートは赤または青に色付けされます。 ボード内に引き込まれたワイヤを使用してポートを接続する場合があります。 各ワイヤは、赤色のポートと青色のポートを 1 つずつ正確に接続する必要があります。 ポートは最大 1 つの接続に参加できます。 

幾何学的制限は驚くほど寛容です。 ワイヤは水平および垂直に移動し、節点で曲がったり、節点で交わったりする可能性があり、正の長さの重複セグメントのみが禁止されます。 

タスクは、赤と青の接続の最大可能数を計算することです。 

制約から最初に気づくことは、`n`そして`m`それぞれが到達できるか`10^5`。 ポートの合計数は、$$2n + 2m \le 4 \cdot 10^5.$$ボードには概念的に最大で`10^10`ノード。 ボード内のセル、パス、またはグラフの頂点をモデル化することはできません。 ソリューションは境界ポートのみに依存する必要があります。 

よくある間違いは、ジオメトリによって複雑な配線制約が生じると想定することです。 実際、簡単なバージョンでは、ほぼ完全に計算の問題に陥ります。 

次の例を考えてみましょう。```
1 1 0
R
R
R
R
```4 つのポートはすべて赤色です。 青いポートがまったくないため、接続を確立できません。 

答えは次のとおりです。```
0
```ポートの合計をカウントして 2 で割るだけの不注意な解決策では、誤って返されます。`2`。 

次に、次のことを考えてみましょう。```
1 1 0
R
B
R
B
```赤のポートが 2 つ、青のポートが 2 つあります。 

答えは次のとおりです。```
2
```ボードには 1 つの内部ノードしか含まれていませんが、2 つの独立した接続は可能です。 1 つは左右のポートを使用し、もう 1 つは上下のポートを使用します。 ノードの容量に基づく推論は、答えを過小評価することになります。 

別の微妙なケースは次のとおりです。```
2 1 0
RR
RB
B
B
```赤色のポート = 3、青色のポート = 3。 

答えは次のとおりです。```
3
```正しい容量は、色数が少ないことと同じです。 特定の接続用に特定の行または列を予約しようとすると、実際には存在しない人為的な制限が作成されます。 

本当の課題は、ジオメトリによって達成可能なマッチングがこの色数の範囲を下回らないことを証明することです。 

## アプローチ

 ブルートフォースの観点は、すべての赤いポートとすべての青いポートを接続の可能なエンドポイントとして扱い、選択されたすべてのペアがボード内で同時に配線できるかどうかを尋ねることです。 

それは当然、幾何学的なグラフ構造、平面的なルーティング引数、さらには巨大なグリッド上のフローを示唆しています。 ボードには最大で次のものを含めることができます`10^10`内部ノードなので、明示的な表現は絶望的です。 圧縮流モデルでも大きすぎます。 

重要な観察点は、ブレッドボードが見た目よりもはるかに柔軟であるということです。 

選択した赤色のポートを選択した青色のポートに接続するとします。 最初のポートから開始して、ボードに入り、未使用の水平通路に移動し、横断して移動し、必要に応じて垂直に移動し、最後に 2 番目のポートに到達します。 ワイヤはノードで接触することが許可され、セグメントの重なりのみが禁止されるため、行と列の大規模な集合は、自由度の高いルーティング ネットワークのように機能します。 

この問題に対する編集上の解決策は、より強力なステートメントに依存しています。 

赤と青の境界ポート間の任意の一致を実現できます。 

これが真になると、ジオメトリは完全に消えます。 残りの唯一の制限は、各色の使用可能なポートの数です。 

あれば`R`赤いポートと`B`青色のポートでは、すべての接続が各色の 1 つのポートを消費します。 ソリューションには以下のものを含めることはできません`min(R, B)`接続。 

上記のルーティング定理は、この限界が常に達成可能であることを示しています。 

したがって、答えは単純に次のようになります。$$\min(R, B)$$どこ`R + B = 2n + 2m`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース ルーティング / フロー | 少なくとも O(nm)、通常はさらに悪くなります。 O(nm) | 遅すぎる |
 | 最適な計数 | O(n + m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 4 つの境界文字列を読み取ります。 
2. 4 つの側面すべてで赤色になっているポートの数を数えます。 
3. 4 つの側面すべてで青色に着色されているポートの数を数えます。 
4. すべての有効な接続は、赤色のポートと青色のポートをそれぞれ 1 つずつ消費するため、ソリューションには 2 つ以上のポートを含めることはできません。`min(red, blue)`接続。 
5. ブレッドボードの配線構造は、赤と青の組み合わせを実現できるほど豊富であるため、この上限は達成可能です。 
6. 出力`min(red, blue)`。 

### なぜ効果があるのか

 すべての接続では、赤色のエンドポイントと青色のエンドポイントを 1 つずつ使用します。 これにより、すぐに次の上限が得られます。`min(red, blue)`。 

重要な部分は、基板の形状が追加の制限を課さないことを示しています。 ワイヤはノードを共有する可能性があり、エッジのオーバーラップのみが禁止され、グリッドには任意の数の独立した水平および垂直セグメントが含まれるため、赤と青のペアのコレクションを同時に配線できます。 ハードバージョンでは、フロー解釈を通じてこれを形式化します。 簡易バージョンでは、結果として得られる容量は、カラーバランスのとれたエンドポイント ペアの最大可能数と正確に等しくなります。 

上限は常に達成可能であるため、容量は正確に`min(red, blue)`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())

    left = input().strip()
    right = input().strip()
    top = input().strip()
    bottom = input().strip()

    red = (
        left.count('R') +
        right.count('R') +
        top.count('R') +
        bottom.count('R')
    )

    total = 2 * n + 2 * m
    blue = total - red

    print(min(red, blue))

if __name__ == "__main__":
    solve()
```実装は数学的特徴付けに直接従います。 

最初の 4 つの文字列には、境界上のすべてのポートが含まれています。 赤色のポートを数えるのは、両方の色を個別に数えるよりも若干簡単です。 ポートの総数が判明すると、青色のカウントが次のように取得されます。`total - red`。 

の値`q`このバージョンでは常に 0 であり、答えには影響しませんが、入力形式に表示されるため読み取られます。 

大規模なデータ構造は必要ありません。 このソリューションでは、各文字が 1 回だけ処理されます。
