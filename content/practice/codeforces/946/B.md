 ## 問題の理解

 2 つの山のサイズを表す 2 つの正の整数が与えられます。 決定論的プロセスでは、非常に特殊なルールを使用してこれら 2 つの値を繰り返し変更します。つまり、一方の値が他方の値の少なくとも 2 倍である場合、大きい方の値から小さい方の値の 2 倍を減算します。 プロセスは、どちらの値ももう一方の 2 倍以上でない場合、またはどちらかの値がゼロになった場合にのみ停止します。 

タスクは、固定数のステップをシミュレートすることではなく、すべての可能な削減が適用された後に最終的な安定したペアを決定することです。 

制約により、次の値まで許容されます。$10^{18}$, これにより、ステップバイステップのシミュレーションが即座に除外されます。 1 回の減算ステップは低コストである可能性がありますが、最悪の場合、反復回数は数値の大きさに比例します。 たとえば、から始めて、$(10^{18}, 1)$、単純なシミュレーションでは約$5 \cdot 10^{17}$実行可能な制限時間をはるかに超えた作戦です。 

重要な問題は、このプロセスが対称的な減算ではないことです。 一方の値がもう一方の値の少なくとも 2 倍である場合にのみトリガーされます。 この状態では、一方の側が塊となって急速に縮小するロングランが発生しますが、役割が交代する場合も発生します。 不注意なシミュレーションは、一方のみが優勢であると仮定したり、1 つの変数を削減した後、条件がすぐに反転して反対の演算が可能になる可能性があることを忘れたりするため、失敗することがよくあります。 

典型的なエッジケースは、リダクションをトリガーする間で値が交互に現れる場合です。 

入力:```
12 5
```正しい出力:```
0 1
```単純なアプローチでは、チェックごとに 1 回しか減算されず、状態変更の直後に発生する反復的な連鎖的な削減を見逃してしまう可能性があります。 

## アプローチ

 ブルート フォース シミュレーションはルールに直接に従います。つまり、次のことを繰り返しチェックします。$a \ge 2b$または$b \ge 2a$、それに応じて減算を実行します。 各操作は問題のステートメントを正確に反映しているため、これは正しいです。 ただし、各ステップでは厳密に少なくとも 1 つの変数が削減され、最悪の場合、そのサイズに比べてほんのわずかな量しか削減されません。 一方の数値が他方の数値よりはるかに大きい場合は、次のようにします。$a = 10^{18}$そして$b = 1$、その後、各有効なステップは減少します$a$2 倍、おおよそ次のようになります$5 \cdot 10^{17}$繰り返し。 

重要な観察は、同じ形式の減算を繰り返すと、ひねりを加えた Euclid のアルゴリズムのように動作することです。小さい方の値のコピーを 1 つ減算するのではなく、サイズの塊に分けて減算します。$2b$。 これは、多くの繰り返されるステップを単一の整数除算ステップに置き換えることができることを意味します。 もし$a \ge 2b$、操作を 1 回のショットでできるだけ多く適用したいと考えています。$$a \leftarrow a \bmod (2b)$$それぞれの操作が減少するため、$a$まさに$2b$、そしてその条件が成り立たなくなるまで続けます。 

同じ考え方が対称的に当てはまります。$b$。 これにより、各フェーズで少なくとも 1 つの変数が劇的に縮小するため、プロセスがユークリッド アルゴリズムと同様の対数縮小に変わります。 

微妙な点は、バルクを削減するたびに両方の条件を再評価する必要があることです。これは、制御が切り替わる可能性があるためです。$a$そして$b$終了前に複数回。

 ## アルゴリズムのチュートリアル

 どちらの側も操作をトリガーできなくなるまで、可能な最大の有効な削減を繰り返し適用します。 

1. 両方の値が正であるかどうかを確認します。 どちらかがゼロになると、ルールを適用できないため、プロセスは直ちに終了します。 
2. もし$a \ge 2b$、 交換する$a$と$a \bmod (2b)$。 これにより、各演算で正確に削除されるため、繰り返されるすべての減算が 1 つのステップに圧縮されます。$2b$。 
3. アップデート後$a$、削減したため、すぐに条件を再確認します。$a$許可するかもしれない$b \ge 2a$真実になること。 
4. もし$b \ge 2a$、 交換する$b$と$b \bmod (2a)$、上記と同じ理由です。 
5. どちらの条件も当てはまらないまで繰り返します。 

この順序付けが機能する理由は、各モジュロ演算が、どちらの側が優勢かを変更する可能性のある中間状態をスキップすることなく、繰り返される有効な減算の効果を保持するためです。 

### なぜ効果があるのか

 このプロセスでは、そのフェーズ中、小さい値は変化しないまま、大きい値は厳密に減少するという不変条件が常に維持されます。 各バルク リダクションは、同一の合法的な動きの最大シーケンスをシミュレートします。 Since each modulo step reduces at least one number to strictly less than twice the other, the system eventually reaches a state where neither condition can hold, matching the termination condition of the original process.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b = map(int, input().split())
    
    while True:
        if a == 0 or b == 0:
            break
        
        if a >= 2 * b:
            a %= 2 * b
            continue
        
        if b >= 2 * a:
            b %= 2 * a
            continue
        
        break
    
    print(a, b)

if __name__ == "__main__":
    solve()
```このソリューションは、2 つの対称的なバルク削減ルールを使用して、プロセスをループとして直接エンコードします。 重要な実装上の選択は、減算を繰り返す代わりにモジュロを使用することです。これにより、各フェーズが一定時間で実行されることが保証されます。 の`continue`ステートメントは、単一の更新後に支配関係が変化する可能性があるため、各削減後にアルゴリズムが両方向を即座に再評価することを保証します。 

注文には注意が必要です。`a`最初に条件を付けてから、`b`条件はプロセス構造と一致し、新しく有効になった遷移のスキップを回避します。

 ## 特殊なケース

 エッジ ケースの 1 つは、値がすでに安定した構成にあり、どちらももう一方の 2 倍以上でない場合です。 たとえば、次のように入力します。```
7 12
```アルゴリズムは最初にチェックします$a \ge 2b$、これは誤りです。 それからチェックします$b \ge 2a$、これも誤りです。 ループはすぐに終了し、出力します。$7 12$、ルールを適用できないため、正しい動作と一致します。 

もう 1 つのエッジ ケースは、リダクションを繰り返すと値が正確に 0 になる場合に発生します。 例えば：```
2 1
```ここ、$a \ge 2b$成立するので、$a = 2 \bmod 2 = 0$。 1 つの値がゼロであるため、プロセスはすぐに停止し、次の出力が生成されます。```
0 1
```これにより、モジュロベースのリダクションが特別なケーシングを必要とせずに正確な割り算を正しく処理できることが確認されます。
