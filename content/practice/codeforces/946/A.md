 ## 解決策
 ## 問題の理解

 整数のリストが与えられ、このリストを任意の方法で 2 つのグループに分割できます。唯一のルールは、すべての要素が 2 つのグループのうちの 1 つに正確に属している必要があることです。 一方のグループはスコアにプラスに寄与しますが、もう一方のグループはマイナスに寄与します。 より正確に言うと、この 2 つのグループを$b$そして$c$、私たちが気にする値は、次の要素の合計です。$b$の要素の合計を引いたもの$c$この値をできるだけ大きくしたいと考えています。 

この設定は、各要素がどのグループに配置されるかに応じて、最終的な式に独立して影響を与えることをすぐに示唆します。$b$) または 1 回減算されます ($c$)、各要素の決定はローカルですが、目的は単一のグローバル合計を通じて要素を結合します。 

制約は小さく、最大 100 個の数値で、それぞれの範囲は -100 ～ 100 です。これにより、高度な最適化や枝刈り戦略の必要性が排除されます。 すべての要素にわたる代入の指数関数的な列挙も、この規模では必要ありませんが、概念的には依然として有効です。 線形または線形に近い貪欲な推論で十分です。 

すべての数値が負の場合、微妙なエッジケースが発生します。 素朴な直感では、グループ間でこれらを混合すると値のバランスが取れるのではないかと思われるかもしれませんが、すべての要素が 1 つのグループに強制的に入れられるため、負の数値を正のグループに入れると実際にはスコアが低下し、負のグループに入れるとプラスの寄与に変わります。 たとえば、入力の場合$[-5]$に入れて$b$収量$-5$、しかしそれを入れる$c$収量$5$したがって、最適な答えは次のようになります。$5$。 符号の反転を考慮せずに「正のグループにはより大きな数値が含まれるはずである」と仮定する戦略は、ここでは失敗します。 

もう 1 つの特殊なケースは、値がゼロであることです。 割り当てに関係なく、ゼロは合計に影響を与えませんが、グループ サイズの「バランス」を試みたり、並べ替えに依存したりする不注意な実装では、目的を改善することなく誤って構造を変更し、グループを誤って処理する可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、各要素をいずれかのグループに割り当てる可能性があるすべてが考慮されます。$b$またはグループ$c$。 それぞれについて、$n$要素には 2 つの選択肢があります。$2^n$可能なパーティション。 各パーティションについて、両方のグループの合計を計算するには次の時間がかかります。$O(n)$、全体的な複雑さは次のようになります。$O(n \cdot 2^n)$。 と$n = 100$、これは天文学的に大きくなり、完全に実行不可能になります。 

重要な観察点は、次の式であるということです。$B - C$要素間の依存関係を削除する方法で書き換えることができます。 要素の場合$a_i$に置かれます$b$、貢献します$+a_i$。 に置かれている場合$c$、貢献します$-a_i$。 したがって、各要素は独立して次のいずれかに寄与します。$+a_i$または$-a_i$そして、これらの署名された貢献の合計を最大化したいと考えています。 

これにより、問題は要素ごとに次のようなことを決定することになります。$a_i$または$-a_i$の方が大きいです。 貢献を最大化するために、常に正の値を選択します。$|a_i|$、なぜなら、$a_i$そして$-a_i$、大きい方が常に$|a_i|$正しく割り当てた場合: 正の数値は$b$、負の数は次の場所に進みます。$c$。 

したがって、最適な戦略は、すべての要素の絶対値を単純に合計することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n \cdot 2^n)$|$O(n)$| 遅すぎる |
 | 最適 (記号の選択) |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数のリストを読み取ります。 

各要素は、その寄与が割り当てられているグループにのみ依存するため、独立して処理されます。 
2. アキュムレータ変数をゼロに初期化します。 

これにより、達成可能な最大値が保存されます。$B - C$。 
3. 各要素について$a_i$、その絶対値を計算し、アキュムレータに追加します。 

これは、より良い配置を選択することに相当します$a_i$で$b$またはそれを置く$c$、これらの選択により結果が得られるため、$a_i$そして$-a_i$それぞれ。 
4. すべての要素を処理した後、アキュムレータを出力します。 

ステップ 3 の背後にある推論がソリューションの核心です。すべての要素は独立してプラスまたはマイナスのいずれかに寄与しており、その寄与を最大化する方向を常に選択します。 

### なぜ効果があるのか

 目的関数は、独立した選択の合計に分解されます。$$B - C = \sum_{i=1}^{n} x_i$$それぞれどこで$x_i$どちらかです$a_i$または$-a_i$。 各項は他の項から独立しているため、合計を最大化すると、各項を個別に最大化することになります。 選択する$\max(a_i, -a_i)$各インデックスの利回り$|a_i|$つまり、局所的な改善は不可能であるため、全体的な改善は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

ans = 0
for x in a:
    ans += abs(x)

print(ans)
```このソリューションは線形時間で入力を読み取り、配列を 1 回反復します。 アキュムレータ`ans`は、目的を独立した要素ごとの寄与に分解することを直接反映します。 重要な実装の詳細は次のとおりです。`abs(x)`条件分岐ではなく。 どちらも同等ですが、絶対値形式の方が符号間違いのリスクが軽減されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))
    return str(sum(abs(x) for x in a))

# provided samples
assert run("3\n1 -2 0\n") == "3"

# all positive
assert run("4\n1 2 3 4\n") == "10"

# all negative
assert run("4\n-1 -2 -3 -4\n") == "10"

# single element
assert run("1\n-100\n") == "100"

# includes zeros
assert run("5\n0 0 0 0 0\n") == "0"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて肯定的 | 10 | 標識を反転する必要はありません。 
| すべて否定的 | 10 | C グループへの最適な反転 |
 | 単一要素 | 100 | 境界の正確性 |
 | すべてゼロ | 0 | 中立要素が正しく処理される |

 ## 特殊なケース

 次のような単一の負の要素の場合、`[-7]`、アルゴリズムは次のように計算します。`abs(-7) = 7`、これはグループに入れることに相当します$c$。 代わりにグループに配置された場合$b$、貢献度は次のようになります。$-7$、これは厳密にはさらに悪いことであり、貪欲な選択が正しいことを確認します。 

次のようなゼロの配列の場合`[0, 0, 0]`の場合、配置に関係なく、各要素の寄与はゼロになります。 このアルゴリズムは、特別な場合の決定を行わずにゼロを正しく累積します。また、すべての割り当てが同等であるため、再配置しても結果が改善されません。
