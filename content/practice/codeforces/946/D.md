 ## 解決策

 ## 問題の理解

 週ごとのスケジュールが数日に分けて与えられ、毎日が固定数の時間枠に分割されます。 各スロットで、イワンは講義を行うか、講義を行わないかのどちらかです。 入力は単純に 0 と 1 のグリッドであり、1 はその時間に講義がスケジュールされていることを意味します。 

イワンは最大でもスキップできます`k`一週間を通して講義を行います。 どの講義をスキップするかを選択した後、彼の毎日の出席ルールは非常に厳密になります。少なくとも 1 つの講義に出席する日は、その日の最初の講義の直前に到着し、最後に出席した講義の直後に退席します。 これは、たとえ出席した講義の間に空白期間があったとしても、彼は最初に出席した講義から最後に出席した講義までの連続した間隔全体にわたって依然として大学に滞在していることを意味します。 

したがって、1 日の費用は、講義に何回出席したかではなく、欠席決定後の最初に出席した講義と最後に出席した講義との間の距離によって決まります。 ある日すべての講義を欠席した場合、その日の費用はゼロになります。 

目標は最大でも配布することです`k`これらの毎日の時間間隔の合計が最小になるように、すべての日にわたってスキップされます。 

制約は十分に厳しいので、指数関数的な影響を排除できます。`k`または1日あたりの講義数で。 両方`n`、`m`、 そして`k`最大でも 500 であるため、次のような解決策が提案されます。`O(n * k^2)`または`O(n * k)`は許容されますが、講義のサブセットを列挙するようなことは完全に実行不可能です。 

実際には、いくつかの特殊なケースが重要です。 講義が含まれない日は、貢献度に関係なく常にゼロになります。`k`。 1 日のすべての講義を維持した場合、費用は単純に最初と最後の講義の間です。`1`。 もう 1 つの微妙なケースは、スキップすると 1 つの講義を除いてすべてが削除される場合に発生します。これにより、他の場所の間隔に関係なく、間隔が長さ 1 に縮小されます。 

単純な間違いは、講義をスキップするとコストが直線的に削減されると考えることです。 たとえば、次のような日に`100001`、中間の講義を削除しても、間隔のエンドポイントが変更されない限り役に立ちません。 もう 1 つの間違いは、実際にはコストが削除後に選択された極端なエンドポイントにのみ依存するにもかかわらず、各講義を独立して扱っていることです。 

## アプローチ

 総当たり的な視点は、1 日あたり考えることから始まります。 毎日、以下を超えない限り、保持する講義のサブセットを選択できます。`k`全日の合計スキップ数。 固定サブセットの場合、保存されている最も古い講義と最新の講義をスキャンして、毎日のコストを計算します。 これはすぐに指数関数的に増加します。なぜなら、毎日だけでも最大`2^m`サブセットと全体`n`日々、組み合わせスペースは限界をはるかに超えて爆発します。 

重要な構造の単純化は、1 日の中で保持される講義の内部配置は重要ではなく、保持される講義の中での最小位置と最大位置のみが重要であるということです。 1 日に削除するレクチャーの数を修正したら、残りのサイズのサブセットを選択して、その期間を最小限に抑えようとします。 その最適なサブセットは常に、講義位置のソートされたリスト内の連続したブロックです。 

これにより、毎日が小さな事前計算に短縮されます。その日の可能なスキップ数ごとに、その日に費やされる最小の時間が計算されます。 毎日が、使用されたスキップの数によってインデックス付けされたコスト配列に圧縮されると、問題は、最大でも分散する数日間にわたる典型的なナップザックになります。`k`合計スキップ数。

 ## アルゴリズムのチュートリアル

 まず、毎日を次のことがわかるコンパクトな表現に変換します。`t`この日はスキップします。その日に大学で費やすことができる最小限の時間は何時間ですか。 

1. 毎日、すべての講義の位置を収集します。 これらのポジションは日に日に厳密に増加しています。 
2. ある日は`c`講義、削除したらどうなるかを考えてください`t`彼らのうち。 保管いたします`c - t`講義。 
3. 時間間隔を最小限に抑えるために、すべての連続するサイズのグループを試します。`c - t`講師職のソートされたリストに表示されます。 インデックスで始まるウィンドウの場合`i`、費用は`pos[i + c - t - 1] - pos[i] + 1`。 
4. そのようなすべてのウィンドウの最小値を取得します。 これにより、最適な支出コストが得られます`t`この日はスキップします。 
5. もし`c - t <= 0`つまり、すべての講義を削除するため、コストはゼロになります。 
6. このコスト表を毎日作成した後、数日間かけて動的プログラミングを実行します。 させて`dp[j]`正確に使用して日のプレフィックスを処理した後に費やされる最小合計時間を表します。`j`スキップします。 
7. 毎日、新しい DP 配列を計算します。`ndp`。 以前に使用したスキップの可能なすべての回数について`j`を代入してみます`t`現在の日付への追加のスキップ、更新`ndp[j + t]`と`dp[j] + cost_day[t]`。 
8. これを一日中繰り返し、最終的な答えは次の最小値になります。`dp[0..k]`。 

### なぜ効果があるのか

 重要な不変条件は、毎日の処理後に、`dp[j]`正確に配布するためのすべての方法で費やされる最小限の合計時間を保存します。`j`これまでに確認された日の間でスキップされます。 1 日あたりの圧縮が有効なのは、コストを増加させたり削除数を変更したりすることなく、保存された講義がその日の講義のソート順で連続したセグメントを形成するように、1 日の最適なソリューションを変換できるためです。 ナップザック移行では、毎日の決定は割り当てられるスキップの数のみに依存し、1 日あたりのコスト関数が固定されるとこれらの決定は独立するため、最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    
    days = []
    for _ in range(n):
        s = input().strip()
        pos = [i for i, ch in enumerate(s) if ch == '1']
        days.append(pos)

    INF = 10**18
    dp = [INF] * (k + 1)
    dp[0] = 0

    for pos in days:
        c = len(pos)
        
        cost = [INF] * (k + 1)
        
        if c == 0:
            cost = [0] * (k + 1)
        else:
            for t in range(k + 1):
                if t >= c:
                    cost[t] = 0
                else:
                    keep = c - t
                    best = INF
                    for i in range(c - keep + 1):
                        j = i + keep - 1
                        best = min(best, pos[j] - pos[i] + 1)
                    cost[t] = best

        ndp = [INF] * (k + 1)
        for used in range(k + 1):
            if dp[used] == INF:
                continue
            for t in range(k + 1 - used):
                ndp[used + t] = min(ndp[used + t], dp[used] + cost[t])

        dp = ndp

    print(min(dp))

if __name__ == "__main__":
    solve()
```コードはまず毎日を講義の位置のリストに変換します。これにより、間隔についての推論が純粋に算術的に行われます。 の`cost[t]`計算により、削除後に得られる重要な観察結果がエンコードされます。`t`講義では、最適な残りのセットは、ソートされた位置にわたるスライディング ウィンドウです。 

第 2 段階は単純な DP マージです。 ネストされたループオーバー`used`そして`t`スキップのすべての有効な分布を超過することなく考慮するようにします。`k`。 バウンド`k + 1 - used`無効な状態を防ぎ、遷移を制限内に保ちます。 

実装によくある落とし穴は、すべてのレクチャーを削除するとコストがゼロになる必要があるということを忘れていることです。 もう 1 つは、「保持されたカウント」と「削除されたカウント」を混同することです。これにより、ウィンドウ サイズが不正確になります。 スライディング ウィンドウの計算では常に次を使用する必要があります。`c - t`保持された講義の数として。

 ## 特殊なケース

 講義のない日は、事前に計算されたポジション リストが空になることで処理されます。 コスト配列はすべてのスキップ カウントに対して 0 に設定されます。これは、スキップが他の場所でどのように割り当てられているかに関係なく、時間が費やされないことを正しく反映しています。 

すべての講義がなくなる日が重要になるのは、`k`大きいです。 この場合、一度、`t`講義数を超えると、コストは強制的にゼロになり、DP はすべてのスキップを 1 日丸ごとの削除に正しく移行できます。 

1 日あたり 1 回の講義がある最小のケースは、スライディング ウィンドウが単一の要素に縮退してコストが発生するため、正しく動作します。`1`その講義をスキップしない限り。
