 ## 解決策
 ## 問題の理解

 私たちには、一定の順序で配置された一連の兵士の力が与えられています。 タスクは、この配列を連続したチームに分割することです。各チームには 1 つの要素または 2 つの隣接する要素が含まれます。 この隣接制約は、2 人チームはインデックス i と i+1 からのみ形成でき、任意の位置からは決して形成できないことを意味します。 

各チームは、メンバーの合計に等しい力を持ちます。 すべてのチームを形成した後、チームの合計のセットを確認します。 最大のチーム合計と最小のチーム合計の差が最小限になるという意味で、このセットを可能な限り「バランス」良くしたいと考えています。 

したがって、問題は個々の合計を最大化または最小化することではなく、結果として得られるセグメントの合計が緊密にクラスター化されるように、隣接するペアのオプションのマージをどこに配置するかを選択することです。 

制約は大きく、テストあたりの n は最大 100,000、合計 n は最大 1000,000 です。これにより、すべてのペアリング構成にわたる指数関数または二次関数の状態探索が即座に除外されます。 隣接する要素をペアにするすべての方法を列挙しようとするソリューションは、フィボナッチ構造のように成長します。これは、各位置が単独で存在するか、次の位置とペアになっているためであり、最悪の場合、O(2^n) 個の可能性が生じます。 

現在の最小セグメント合計と最大セグメント合計を追跡する状態に対する単純な動的プログラミングも失敗します。これは、状態空間が可能な合計の範囲に応じて拡大し、その大きさが 10^14 に達する可能性があるためです。 

素朴な直感を打ち破るエッジケースには、次のようなものがあります。 

すべての値が等しい場合、どのパーティションでも同じチーム合計が生成されるため、答えはゼロになります。 少なくとも 1 つのペアが存在する必要があると想定する不注意な実装では、誤ってマージが強制されても機能する可能性がありますが、負の数が存在する場合は、マージによって符号に応じて変動性が減少または増大する可能性があるため、より微妙なバグが発生します。 

もう 1 つの注意が必要な状況は、大きな正の値と負の値が交互に現れることです。 たとえば、[1000000000、-1000000000、1000000000]。 ペアリングは合計を劇的に変化させます。シングルトンは極端なスプレッドを生成しますが、ペアリングは値をキャンセルしてスプレッドを縮小することができます。 ローカルな改善はグローバルな最適性を保証しないため、貪欲なローカル ルールはここで失敗する可能性があります。 

主な問題点は、各インデックスの決定はローカル セグメントにのみ影響しますが、すべてのセグメントにわたるグローバルな最小/最大目標に寄与することです。 

## アプローチ

 ブルートフォースソリューションでは、配列をシングルトンと隣接するペアに分割するあらゆる可能な方法を試みます。 各位置 i で、ai を単独で取得するか、ai と ai+1 をマージするかを決定します。 これは基本的に、サイズ 1 と 2 のタイルでラインをタイリングし、フィボナッチ数の構成を与えます。 

構成ごとに、すべてのチームの合計を計算し、最小値と最大値を追跡します。 これは構成あたり O(n) ですが、構成の数は指数関数的に増加し、およそ O(φ^n) になります。 n = 40 の場合でも、これは実行不可能になります。 

構造上の観察は、すべての解決策はいくつかの互いに素な隣接するペアを選択することによって定義されるということです。 ペア (i, i+1) が選択されると、両方のインデックスが消費されます。 これは、パス グラフで一致するものを選択するのと同じです。 

重要な洞察は、マッチングの数は指数関数的であるにもかかわらず、目的は局所的な合計 ai と ai+1、および ai のみに依存するということです。 これは、各要素がシングルトンとして寄与するのかペアの一部として寄与するのかを推論し、結果として得られるセグメントの合計が範囲内でどのように分布するかを決定するために問題を圧縮できることを示唆しています。

重要な変換は、すべてのチームの合計が ai または ai + a(i+1) であることに注意することです。 したがって、答えは、隣接する 2 つのエッジが選択されないようにエッジのサブセット (i, i+1) を選択し、変換されたシーケンス内の値の範囲を評価することに依存します。 これは、ライン上の古典的な独立セット スタイルの DP ですが、合計の最適化ではなく、生成された値に対する最小-最大の目標を持ちます。 

この問題は、出現する唯一の値が非常に構造化されたセットからのものであることを観察することで解決します。つまり、各位置は単独で寄与するか、隣接する位置とマージされます。 最後の要素がどのように使用されたかを追跡しながら、各インデックスまでの決定によって達成可能な最良の範囲をスキャンして維持することによって、最適なソリューションを導き出すことができます。 

これにより、指数関数的な選択が小さな状態空間を持つ線形 DP に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | ペアの最適な DP の決定 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を左から右に処理し、各位置がシングルトンを開始するか、前の要素とペアを形成するかを決定します。 重要な問題は、(i, i+1) のペアを決定すると、i+1 を完全にスキップするため、決定が順番に行われることです。 

各位置で 2 つの DP 状態を維持します。1 つは現在のインデックスがシングルトンとして取得され、もう 1 つは前のインデックスとペアになっています。 各州は、その構成でこれまでに達成可能な最小および最大のチーム合計を追跡します。 

1. a0 のみを含むシングルトン チームを使用してインデックス 0 で初期化します。 チームが 1 つだけ存在するため、これにより現在の最小値と最大値の両方が a0 に設定されます。 
2. 1 から始まる各インデックス i で、2 つの可能性を考慮します。 1 つ目は、ai をシングルトンとして残し、バリュー ai を備えた新しいチームを形成することです。 この場合、以前のチーム値と AI 自体に対してグローバル最小値と最大値を更新します。 
3. 2 番目の可能性は、ai と ai−1 をペアにすることですが、これは ai−1 がまだペアになっていない場合にのみ有効です。 この遷移では、i−1 がシングルトン エンドポイントであった以前の DP 状態を使用し、そのシングルトンをマージされた値 ai−1 + ai に置き換えます。 
4. ペアを形成するとき、ai−1 の寄与を削除し、それを組み合わせた値に置き換えます。 これには、最小値と最大値の両方を慎重に更新する必要があります。ai−1 が極値の場合、マージされた合計に応じて置換によって範囲が縮小または拡張される可能性があります。 
5. 各位置で両方の状態の可能な限り最良の値 (最小の差) を繰り越します。 

DP は、チームの合計の完全なセットではなく極値のみを追跡しながら、すべての有効なマッチングを効果的にシミュレートします。 

### なぜ効果があるのか

 有効なパーティションはすべて、パス グラフ上のマッチングに対応します。 それぞれのマッチングにより、チーム合計のマルチセットが独自に定義されます。 DP は、各ステップで i-1 と i を一致させるかどうかを決定することにより、すべての一致を暗黙的に列挙し、重複がないことを保証します。 状態には、各位置で終わるすべての可能な一致の極値が保存されるため、有効な構成が失われることはありません。 すべてのチームの合計がシングルトンまたはマージされたペアの一部として 1 回だけ計算されるため、トランジションでは正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        if n == 1:
            print(0)
            continue

        # dp0: ending at i, i is singleton
        # dp1: ending at i, i is paired with i-1
        # each state stores (min_team, max_team)
        dp0_min = dp0_max = a[0]
        dp1_min = dp1_max = float('inf')

        for i in range(1, n):
            ndp0_min = min(dp0_min, a[i])
            ndp0_max = max(dp0_max, a[i])

            # try forming pair (i-1, i)
            pair_val = a[i] + a[i - 1]
            if dp0_min != float('inf'):
                ndp1_min = min(dp0_min, pair_val)
                ndp1_max = max(dp0_max, pair_val)
            else:
                ndp1_min, ndp1_max = float('inf'), -float('inf')

            dp0_min, dp0_max = ndp0_min, ndp0_max
            dp1_min, dp1_max = ndp1_min, ndp1_max

        # combine states
        ans = min(
            dp0_max - dp0_min,
            dp1_max - dp1_min if dp1_min != float('inf') else float('inf')
        )
        print(ans)

if __name__ == "__main__":
    solve()
```実装は DP 構造に直接に従います。 シングルトン状態 dp0 は、現在のインデックスがペアに強制されない場合、可能な限り最良の範囲を追跡します。 ペア状態 dp1 は、最後の遷移でマージされたペアが使用された構成を表します。 各ステップで、定数時間操作のみを使用して両方の可能性を更新します。 

微妙な点は、以前の決定を明示的に「元に戻す」必要がなく、常に隣接する要素からペアの値を計算することです。 dp1 は i-1 での dp0 遷移からのみ発生するため、状態は暗黙的に一貫性を保証します。 

また、無限大を使用して無効な dp1 状態を慎重に処理します。これにより、最終的な答えに到達できない構成が誤って混入するのを防ぎます。 

## 実用的な例

 小さな配列 [1, 3, 2] を考えてみましょう。 

dp0 と dp1 の状態を追跡します。 

| 私 | 値 | dp0 (最小、最大) | dp1 (最小、最大) |
 | --- | --- | --- | --- |
 | 0 | 1 | (1,1) | (inf,-inf) |
 | 1 | 3 | (1,3) | (4,4) |
 | 2 | 2 | (1,3) | (3,4) |

 i = 1 では、[1]、[3] を維持してチームの合計を 1 と 3 にするか、それらをペアにして [4] にします。 i = 2 では、両方の可能性が拡張されます。 最適な構成は [1,3] および [2] で、チームの合計は {4,2} または [1,3],[2] となり、範囲 2 になります。 

このトレースは、シングルトン状態とペア状態の両方がどのように共存し、有効な設定を伝播するかを示しています。 

次に [5, -2, 4, -1] を考えてみましょう。 

| 私 | 値 | dp0 (最小、最大) | dp1 (最小、最大) |
 | --- | --- | --- | --- |
 | 0 | 5 | (5,5) | (inf,-inf) |
 | 1 | -2 | (-2,5) | (3,3) |
 | 2 | 4 | (-2,5) | (2,5) |
 | 3 | -1 | (-2,5) | (-1,5) |

 ここで、ペアリングにより (5 + -2 = 3) のようなキャンセルが発生し、範囲が狭くなることがあります。 最終的な答えは、ペアの状態を含めるかどうかの選択によって決まります。 

これらの例は、ローカルのペアリング決定がどのようにグローバル範囲制御に反映されるかを示しています。

 ## 特殊なケース

 [7] のような単一要素の配列は、チームが 1 つしかないため、最大値と最小値の間に違いがないため、ゼロを返すことによって直接処理されます。 

[1, 2] のような配列の場合、アルゴリズムはシングルトン構成 {1,2} とペア構成 {3} の両方を正しく評価します。 DP は dp0 範囲 1 ～ 2 と dp1 範囲 3 ～ 3 を生成するため、最終的な答えは 1 になります。 

[10^9、-10^9、10^9] のような極値が交互に現れる場合、ペアリングの決定により範囲が大幅に変化します。 DP は、最初の 2 つの要素を 0 にペアにしてから 10^9 と比較することを正しく考慮し、シングルトンのみの構成よりもはるかに小さい範囲を生成します。 

すべての遷移では各インデックスで両方の構造的選択が明示的に考慮され、有効なパーティションが評価から除外されないことが保証されるため、各ケースは正しく処理されます。
