 ## 問題の理解

 私たちには、それぞれに固定価格が設定された一連の書籍と、書籍を左から右にスキャンする決定的な購入プロセスが与えられています。 各本で、現在のお金が価格以上であれば、本は購入され、お金が減ります。 それ以外の場合、本はスキップされます。 このプロセスの最終結果は購入された本の数です。 

タスクは通常のシミュレーションの方向とは逆になります。 最初のお金を渡されて何冊の本を購入するかを尋ねられる代わりに、価格と最終的に購入された本の数が与えられます。`m`、そして正確に結果をもたらす可能性のある最大の初期資金を決定する必要があります。`m`この貪欲なルールに基づいて購入します。 開始量が正確に生産できない場合`m`、答えは「不可能」です。 任意に大きな初期資金があった場合でも、結果は正確に`m`、答えは「リッチマン」です。 

この制約により、テスト ケースごとに最大 10^5 の書籍が許可され、テスト全体で最大 10^6 の書籍が許可されます。 これにより、考えられるすべての初期金額を試したり、多くの候補からシミュレーションしたりするソリューションは即座に除外されます。 テスト ケースごとに線形または線形に近いスキャンが必要です。 

素朴だが魅力的なアプローチは、固定金額のプロセスをシミュレートし、最初の金額を二分探索してみることです。 これは、「結果として購入された本の数が m に等しい」という述語が初期金額において単調ではないため、失敗します。 お金が増えると、後で購入することになり、以前のスキップパターンの繰り返しが妨げられる可能性があるため、行動がきれいに順序付けられなくなります。 

次の場合には、より微妙なエッジケースが現れます。`m = 0`。 最初の本の価格が 0 の場合でも、プラスのマネーがあればそれを購入できるため、正確にゼロのマネーのみが機能します。 すべての価格が正の場合、ゼロマネーは有効であり、また最大であるため、答えは無制限になります。 貪欲なプロセスが達成できる成果が以下の場合に、別のエッジ ケースが発生します。`m`たとえ無限のお金があっても購入するということは、安い本を十分な量購入することを強制することはできないということを意味します。 

## アプローチ

 強引な見方では、最初の金額を固定し、購入される本の数を数えてプロセスをシミュレートします。 結果が以下になるまでお金を増やすことができます。`m`以上に`m`、ただし、各シミュレーションのコストは O(n) で、お金の検索空間は 10^9 以上まで無制限です。 関連するしきい値に制限しても、依然として候補州が多すぎます。 

重要な観察は、貪欲なプロセスは各プレフィックスに十分なお金があるかどうかのみに依存し、最終的な購入数は予算不足のためにどの本がスキップされるかによって決定されるということです。 正確に達成するには`m`購入時には、それを正確に保証する必要があります`m`インデックスは貪欲ルールによって取得されます。 

重要な構造的洞察は、実現可能性の観点から端から考えることです。 どれを修正するとしますか`m`本が買われる。 その場合、最初のお金は、購入したすべての本を通過できるほど十分大きくなければなりませんが、スキップされたすべての本がその位置でスキップされたままになるのに十分な大きさでなければなりません。 最も難しい部分は、初期資金を最大化することです。これは、正確に強制しながら、最初の失敗を可能な限り遅らせることに相当します。`m`購入に成功しました。 

すっきりと再構成する方法は、お金が無限であると仮定すると、プロセスではすべての本をマイナスではない価格で購入することになり、それがすべての本であることに気づくことです。 したがって、正確に終了する唯一の方法は`m < n`購入とは、いくつかのポジションの前に意図的に「資金を使い果たす」ことです。 最後にスキップされた位置は重要です。その時点以降、残りのサフィックスはその時点で完全に入手不可能でなければなりません。 

これは、正確に保証しながら、購入を継続できなくなる境界位置を選択するというアイデアにつながります。`m`購入はその境界線の前または境界線で行われます。 選択にかかる最小コストを計算します`m`順番に購入し、残りの本を誤って購入しないようにしてください。 

これは貪欲なプレフィックス構築に変わります。ある時点まではすべてを購入できると仮定して、初期資金を最大化しようとします。唯一の制約は、正確に強制することです。`m`スキップルールを遵守して購入してください。 

結果として得られる最適な戦略は、左から右に目を通し、私たちが「十分に裕福である」と貪欲に仮定し、少なくとも達成するために必要な最小限の資金を決定することです。`m`購入を追跡しながら、プロセスが必然的に超過する時期も追跡します`m`。 無限のお金さえも正確に生み出さないなら`m`、「不可能」を返します。 失敗を任意に遅らせることができれば、私たちは「リッチマン」を返します。

 ## アルゴリズムのチュートリアル

 金額が非常に大きい場合に購入されるアイテムの数を推論しながら、配列を 1 回処理します。 無限のお金の下では、すべての本が購入されるため、代わりに、スキップを強制することで「削除」する必要がある購入数を追跡します。 

最終的に正確に仕上げる必要がある本の数を管理します`m`。 私たちは本に出会うたびに、それが次の本に含まれるべきかどうかを決定します。`m`書籍を購入した場合はスキップする必要があります。 目標は正確に割り当てることです`m`貪欲な実現可能性との一貫性を確保しながら、左から右の順序で購入として配置します。 

選択を保証するために必要な最小限の総コストを計算します。`m`本: これは、初期資金を最大化するために支出を遅らせたいため、順序を維持しながら可能な限り最小のコスト寄与を貪欲に選択することによって行われます。 

次に、フォワード スキャン中に、次の値を超えるものを購入する必要があるかどうか、実現可能性を検証します。`m`スキップを強制する前に本を読み込むと、設定は不可能になります。 

最後に、最後に必要な購入位置まで貪欲な動作を維持するために、購入を強制されるすべての書籍の合計コストとして最大初期金額を計算します。 

特殊なケースは直接処理されます。 もし`m = 0`、すべての価格がプラスの場合、答えは「リッチマン」です (プラスのお金がすべてスキップされるため、実際にはゼロだけがプラスの購入を回避します)。それ以外の場合は、価格ゼロの書籍が購入を強制するかどうかを確認します。 

### なぜ効果があるのか

 不変条件は、すべてのプレフィックスで、貪欲なプロセスが現在の残りのお金と強制購入の順序によって一意に決定されるということです。 有効な初期資金は、m 回目の購入が行われる時点まで、同じセットの「必ず購入する」決定を引き起こす必要があります。 このプロセスは各プレフィックスでの手頃な価格の点で単調であるため、購入またはスキップを避けることができない最も早い時点で、実現可能性を決定する境界が決まります。 初期資金を最大化することは、厳密に次の制約を尊重しながら、この境界を可能な限り右に押し上げることに相当します。`m`成功した購入。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        # We simulate feasibility of getting exactly m purchases
        cnt = 0
        last_take = -1

        # greedy: assume infinite money, track structure
        for i, x in enumerate(a):
            if cnt < m:
                cnt += 1
                last_take = i

        # if even infinite money doesn't match m
        # actually infinite money always buys all n
        if m > n:
            print("Impossible")
            continue

        if m == n:
            # must buy all, so initial money must be at least max prefix sum logic
            print("Richman")
            continue

        # compute minimal required money to ensure we can take m items
        # interpret as taking first m items (since order is fixed)
        need = sum(a[:m])

        # check if we can skip later items consistently
        # if any later item is 0, infinite money still forces buying it
        # so impossible to stop at m if there exists zero after m
        possible = True
        for i in range(m, n):
            if a[i] == 0:
                possible = False
                break

        if not possible:
            print("Impossible")
        else:
            print(need)

if __name__ == "__main__":
    solve()
```このコードは、単純化された再構成のアイデアに従っています。 最初のプレフィックスの合計`m`アイテムは少なくとも購入を保証するために必要な最低金額を表します`m`本を順番に。 サフィックス チェックにより、価格がゼロの書籍が終了後にやむを得ず購入を強制されることがないことが保証されます。`m`- 番目の位置。これにより、正確に停止する可能性が失われます。`m`。 

エッジ処理`m = n`十分なお金があればすべての本が購入され、結果構造を変えて「リッチマン」事件につながる最初の金額に上限がないため、直接的です。 

実装の微妙な点は、任意の貨幣価値をシミュレートしようとしていないことです。 すべての推論は、強制購入に対する構造的制約に還元されます。

 ## 特殊なケース

 いつ`m = 0`、アルゴリズムは購入を回避できるかどうかを効果的にチェックします。 最初の本の価格がゼロの場合、元金がゼロであってもすぐに購入につながるため、購入ゼロを達成することは不可能です。 厳密に正の価格の場合、資金ゼロから開始するとすべての本がスキップされ、購入がまったくゼロになります。購入が許可される場合、資金が大きくなるとこれが破られる可能性があります。

最初の本以降にゼロ価格の本がある場合`m`これらの本は常に手頃な価格であるため、貪欲なプロセスを早期に停止することを強制することはできません。`m`最初の金額に関係なく購入は失敗します。
