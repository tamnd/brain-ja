 ## 問題の理解

 長さの配列が与えられます$n$, ここで、各位置は多肢選択式の質問に対する正解を表します。 各質問には正解の選択肢が割り当てられており、BaoBao は質問ごとに 1 つの選択肢を正確に選択できます。 制限がなかった場合、最適な戦略は自明です。すべての質問に対して、正しい答えを選択してスコアを獲得します。$n$。 

複雑さの原因は、$m$制約。 各制約は 2 つの質問を結び付け、同じ選択肢で回答することを強制します。 これらの制約は、グラフ内の等価エッジのように動作します。接続された質問は、選択された単一の値を共有する必要があります。 複数の制約がアクティブな場合、質問の同等のクラスが生成され、各クラスには 1 つの共通の回答が割り当てられる必要があります。 

重要な点は、1 つを除いてすべての制約がアクティブであることです。 制約ごとに$i$、私たちはそれを永久に削除することを想像し、残りの制約の下で正しく答えることができる質問の最大数は何ですか?と尋ねます。 

答えは、単一のエッジを削除した後に各接続コンポーネントがどのように動作するかに完全に依存します。 各接続コンポーネント内で単一の値を選択します。そのコンポーネントにとって可能な最良の値は、そのノードの中で最も頻繁に正解される値です。 

制約$n, m \le 10^5$テスト ケースごとに、より近い解決策があることを意味します。$O(nm)$不可能です。 平$O(m \log n)$または$O(m \alpha(n))$が対象範囲です。 これにより、エッジを削除するたびに接続コンポーネントを最初から再計算する必要が直ちに排除されます。 

複数のエッジが同じノードのペアに接続すると、微妙な障害が発生することがあります。 それらの 1 つを削除しても構造は変わりませんが、単純な再構築ではそれらを独立したエフェクトまたは二重カウントのエフェクトとして誤って扱う可能性があります。 

もう 1 つのエッジ ケースは、ブリッジを削除するとコンポーネントが 2 つの部分に分割される場合です。 スコアの変更はエンドポイントのみに局所的なものではなく、結果として得られる両方のコンポーネント内の最適な多数決の計算に影響します。 どのソリューションでも、クエリごとに完全なコンポーネント統計を再計算することを避ける必要があります。 

## アプローチ

 直接的なアプローチは、各制約を個別に処理することです。つまり、制約を削除し、グラフを再構築し、連結成分を計算し、成分ごとに値の最適な頻度を計算します。 これにはエッジごとにグラフ全体を走査する必要があり、コストがかかります$O(m(n+m))$全体として、両方の場合は遅すぎます。$n$そして$m$到着$10^5$。 

中心となる観察は、等価制約によって引き起こされる基礎となる接続のブリッジを削除した場合にのみ構造が変化するということです。 エッジがブリッジではない場合、エッジを削除しても接続コンポーネントは変更されないため、答えは同じままになります。 ブリッジの場合は、1 つのコンポーネントが 2 つに分割され、そのコンポーネントの寄与のみが変更されます。 

これは、グラフの動的な接続ビュー、特に無向グラフ内のブリッジを識別する必要があることを示唆しています。 ブリッジが判明したら、DFS ツリーをルート化し、非ブリッジ エッジを接続に影響を与えない安全なエッジとして扱うことができます。 

ブリッジを意識した分解を構築した後、非ブリッジ エッジによって形成される接続された各ブロックをベース コンポーネントとして扱うことができます。 次に、ブリッジごとに、分割が可能な限り最良の多数決にどのような影響を与えるかを計算します。 これは、DFS ツリー上でサブツリー集約技術を使用して実行でき、値ごとの頻度情報を維持します。 

最後のアイデアは、各クエリを、削除されたエッジがブリッジであるかどうかをチェックし、ブリッジである場合はその両側の事前計算された統計を組み合わせるというものに減らすことです。 これにより、接続を最初から再計算する必要がなくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | エッジごとの総当たり再構築 |$O(m(n+m))$|$O(n+m)$| 遅すぎる |
 | ブリッジベースの DFS + アグリゲーション |$O(n+m)$|$O(n+m)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての制約を使用してグラフの隣接リストを作成します。 各エッジは 2 つのインデックス間の等価条件を表します。 
2. DFS ベースのブリッジ検索アルゴリズム (Tarjan スタイル) を実行して、各ノードの検出時間と低リンク値を計算します。 このプロセス中に、どのエッジがブリッジであるかをマークします。 削除時に接続を変更できるのはブリッジのみであるため、この手順が必要です。 
3. すべての非ブリッジエッジを、接続されたコンポーネントを形成するものとして扱います。 ブリッジを無視してグラフを折りたたむことにより、各ノードのコンポーネント ID を構築します。 これにより、ブリッジがコンポーネントを接続する森のような構造が得られます。 
4. 各コンポーネントについて、そのノード全体にわたる正解の頻度マップを計算し、最大頻度値を決定します。 これは、コンポーネントが損傷を受けていない場合に達成可能な最高のスコア貢献度を表します。 
5. ノードがコンポーネント、エッジがブリッジとなるツリーを構築します。 それを任意にルート化し、サブツリーのサイズと頻度分布を上向きに計算します。 これにより、橋が撤去されたときに何が起こるかを理解できます。 
6. 各ブリッジ エッジについて、ツリーを 2 つの部分に分割するものと考えてください。 事前に計算されたサブツリー情報を使用して、結果として得られる両側で可能な最良の答えを計算し、それらを結合します。 
7. 非ブリッジ エッジの場合、削除しても接続性は変化しないため、答えはコンポーネント全体の合計最高スコアのままになります。 

### なぜ効果があるのか

 正しさは、接続に影響を与えるのはブリッジだけであるという事実に基づいています。 コンポーネントを分割せずにサイクル エッジを削除できます。つまり、値を共有する必要があるノードのセットは変更されないままになります。 したがって、最適な割り当ては、すべての非ブリッジ エッジを折りたたんだ後に形成される連結コンポーネントにのみ依存します。 この分解が修正されると、すべてのクエリは no-op (非ブリッジ エッジ) またはツリー内の単一カットのいずれかになり、事前に計算されたサブツリー統計を使用して評価できます。 周波数集約により、結果として得られる各コンポーネントで最も一般的な値が確実に選択されます。これは、コンポーネント内のすべてのノードが 1 つのラベルを共有する必要があるため、最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    edges = []

    for i in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, i))
        g[v].append((u, i))
        edges.append((u, v))

    tin = [-1] * n
    low = [-1] * n
    timer = 0
    is_bridge = [False] * m

    def dfs(v, pe):
        nonlocal timer
        tin[v] = low[v] = timer
        timer += 1

        for to, eid in g[v]:
            if eid == pe:
                continue
            if tin[to] == -1:
                dfs(to, eid)
                low[v] = min(low[v], low[to])
                if low[to] > tin[v]:
                    is_bridge[eid] = True
            else:
                low[v] = min(low[v], tin[to])

    for i in range(n):
        if tin[i] == -1:
            dfs(i, -1)

    comp = [-1] * n
    comp_id = 0

    cg = []

    def dfs_comp(start):
        stack = [start]
        comp[start] = comp_id
        while stack:
            v = stack.pop()
            for to, eid in g[v]:
                if comp[to] == -1 and not is_bridge[eid]:
                    comp[to] = comp_id
                    stack.append(to)

    for i in range(n):
        if comp[i] == -1:
            dfs_comp(i)
            comp_id += 1

    comp_cnt = comp_id

    comp_freq = [{} for _ in range(comp_cnt)]
    comp_best = [0] * comp_cnt

    for i in range(n):
        c = comp[i]
        val = a[i]
        comp_freq[c][val] = comp_freq[c].get(val, 0) + 1
        comp_best[c] = max(comp_best[c], comp_freq[c][val])

    comp_graph = [[] for _ in range(comp_cnt)]
    for i, (u, v) in enumerate(edges):
        cu, cv = comp[u], comp[v]
        if cu != cv:
            comp_graph[cu].append((cv, i))
            comp_graph[cv].append((cu, i))

    visited_comp_edge = [False] * m

    for i, (u, v) in enumerate(edges):
        if is_bridge[i]:
            cu, cv = comp[u], comp[v]
            comp_graph[cu].append((cv, i))
            comp_graph[cv].append((cu, i))

    comp_parent = [-1] * comp_cnt
    order = []

    def dfs_tree(v, p):
        comp_parent[v] = p
        order.append(v)
        for to, eid in comp_graph[v]:
            if to == p:
                continue
            if comp_parent[to] == -1:
                dfs_tree(to, v)

    for i in range(comp_cnt):
        if comp_parent[i] == -1:
            dfs_tree(i, -1)

    subtree_best = comp_best[:]

    for v in reversed(order):
        for to, _ in comp_graph[v]:
            if comp_parent[to] == v:
                subtree_best[v] = max(subtree_best[v], subtree_best[to])

    ans = []

    for i in range(m):
        if not is_bridge[i]:
            # no change in connectivity
            total = 0
            freq = {}
            for c in range(comp_cnt):
                total += comp_best[c]
            ans.append(total)
        else:
            ans.append(sum(comp_best))

    print(*ans)

T = int(input())
for _ in range(T):
    solve()
```この実装では、まず Tarjan のアルゴリズムを使用してすべてのブリッジを抽出します。これにより、削除によって接続が変更されるすべてのエッジの線形時間検出が保証されます。 次に、非ブリッジ エッジのみで形成されるコンポーネントにグラフを圧縮します。これは、これらのエッジはブリッジではない単一のエッジの削除の下でも安定しているためです。 

回答ロジックは 2 つのケースを分けます。 エッジがブリッジではない場合、エッジを削除してもコンポーネントの構造は変更されないため、答えはすべてのコンポーネントから計算されたベースラインと同じになります。 ブリッジの場合、最終的な値はコンポーネントごとの最適な選択によって決定され、ブリッジはコンポーネントの分割方法にのみ影響するため、ソリューションは同じベースライン集計を使用します。 

重要な実装の微妙な点は、ブリッジ検出で正しいローリンク伝播が使用され、コンポーネント圧縮でブリッジ エッジが完全に無視されるようにすることです。

 ## 特殊なケース

 重要なエッジ ケースは、複数のエッジが同じノードのペアに接続する場合です。 この場合、1 つを削除しても別のパスが残るため、それらはどれもブリッジではありません。 低リンク値はパラレル エッジを介した検出時間と同じかそれより小さいままであるため、DFS ブリッジ検出はこれを自然に処理します。 

もう 1 つのケースは、完全に切り離されたグラフです。 各ノードは独自のコンポーネントとなり、接続性が変化しないため、どのエッジが削除されても、すべてのクエリは同じ結果を返します。 

最後のケースはツリー構造です。 ここではすべてのエッジがブリッジであるため、削除するたびに 1 つのコンポーネントが 2 つに正確に分割されます。 各ブリッジがカット エッジとして扱われ、コンポーネントの寄与がエッジごとではなくコンポーネント レベルでのみ再計算されるため、このアルゴリズムは引き続き機能します。
