 ## 解決策
 ## 問題の理解

 ラベル付きの無向単純なグラフが与えられます。$n$頂点が正確に一致する$m$エッジ。 最終的なグラフがすべての要素を訪問する単一の単純なサイクルになるように、追加のエッジを追加できる場合、グラフは有効であると呼ばれます。$n$頂点を 1 回だけ指定します。 

重要な点は、何も構築するように求められていないということです。 異なるグラフの数を数えています$n$頂点と$m$エッジには、エッジを追加するだけでハミルトニアン サイクルが完成するという特性があります。 

最終的なターゲット構造は非常に厳密です。つまり、すべての頂点を含む単一サイクルであり、すべての頂点の次数が正確に 2 であり、グラフが接続されています。 有効な初期グラフは、少なくとも 1 つのそのようなサイクルの部分グラフでなければなりません。 

制約により、組み合わせによる解決が強制されます。 の合計$n$すべてのテスト ケースは大きく、最大で$3 \cdot 10^7$これにより、テスト ケースごとに超線形なものが即座に除外されます。 平$O(n \log n)$テストケースごとに実行すると、全体として遅すぎる可能性があります。 これは、解が事前に計算された階乗と、$n-m$。 

微妙な点は、「サイクルに拡張できる」ということが実際に構造的に何を意味するのかということです。 グラフに次数が 2 より大きい頂点が含まれている場合、そのグラフはサイクルに収まりません。 すでにサイクルが含まれている場合、最終的な構造はすべての頂点にわたる単一の単純なサイクルであり、エッジを追加しても既存のサイクルを削除できないため、そのサイクルは最終的な構築では消える必要があります。 これは、すべての有効なグラフが、分岐や内部サイクルのない、頂点が互いに切り離されたパスの集合であるという、隠れた構造上の制限につながります。 

単純な間違いは、グラフが局所的にすでにサイクルに似ているはずであり、コンポーネント内でサイクルを許可していると想定することです。 たとえば、頂点上の三角形$1,2,3$はすでにサイクルを形成していますが、拡張後の単純性を損なうことなく、すべての頂点でより大きな単純なサイクルの一部にすることはできません。 したがって、この構成は、最終的なサイクル サイズ構造と既に等しくない限り無効です。これは不可能です。$n>3$。 

## アプローチ

 ブルートフォース解釈は簡単です。 すべて列挙します$\binom{n(n-1)/2}{m}$グラフを作成し、各グラフについて、ハミルトニアン サイクルに埋め込むことができるかどうかを確認します。 そのチェック自体は、グラフが頂点のサイクル順序付けのサブグラフであることを検証する必要があります。これは、グラフが線形フォレストであるかどうかをテストすることと同等です。 たとえこのチェックが線形だったとしても、グラフの数が指数関数的に増加するため、列挙によってアプローチはすでに不可能になります。$n^2$。 

重要な観察は、視点を逆転させることです。 任意のグラフから開始してサイクル完了が存在するかどうかを確認する代わりに、すべての頂点上の固定ハミルトニアン サイクルから開始します。 有効なグラフはすべて、少なくとも 1 つのそのようなサイクル内に完全に含まれている必要があります。 サイクルの順序を修正すると、すべての有効なグラフはそのサイクルからエッジのサブセットを選択することに対応します。 

ただし、異なるサイクルで同じグラフが生成される可能性があるため、サイクル間の直接乗算は大幅にオーバーカウントされます。 正しい構造的洞察は、本当に重要なのはどのサイクルまで拡張するかではなく、グラフが線形フォレストでなければならないという事実です。つまり、すべての頂点の次数は最大 2 であり、選択したエッジの内側にはサイクルが存在しません。 

それを認識すると、問題は純粋に組み合わせの問題になります。ラベル付きグラフの数を数えます。$n$頂点と$m$すべての接続されたコンポーネントがパスになるようなエッジ。 パスコンポーネントのみを持つフォレストは次の条件を満たすため、$m = n - c$、 どこ$c$がコンポーネントの数である場合、固定数のコンポーネントを持つラベル付き線形フォレストをカウントするという観点から問題を再定式化できます。 

ここから、「ラベル付き構造としてのパス」の指数母関数を使用して、次のように評価できる閉じた係数式を導き出すことができます。$O(n)$階乗事前計算を使用したテスト ケースごと。

 ## アルゴリズムのチュートリアル

 しましょう$c = n - m$。 有効なグラフはすべて、すべてのコンポーネントがパスであるフォレスト、および$c$コンポーネントには正確に$n-c = m$したがって、このパラメータ化には一貫性があります。 

ラベル付き線形フォレストを正確にカウントします。$c$パスコンポーネント。 

1. 各接続コンポーネントをラベル付きパスとしてモデル化します。 上のパス$k \ge 2$頂点には$k!/2$なぜなら、頂点の順列はパスを定義しますが、それを逆にすると同じ無向構造が得られるからです。 単一の孤立した頂点は、ラベルが 1 つだけ付けられた縮退パスです。 
2. 各コンポーネントがそのようなパスの 1 つであり、グラフ全体が一連のパスである組み合わせクラスを構築します。$c$コンポーネント。 パス成分の指数母関数は次のようになります。$$P(x) = x + \sum_{k \ge 2} \frac{x^k}{2} = x + \frac{x^2}{2(1-x)}.$$3. 母関数を有理形式に書き直す$$P(x) = \frac{x(2-x)}{2(1-x)}.$$4. グラフ$c$コンポーネントは、順序付けられていないセットを選択することに相当します。$c$コンポーネントなので、$$\frac{P(x)^c}{c!}.$$5. の係数を抽出します。$x^n$この式から乗算します$n!$EGF からラベル付き計数に変換します。 を使用して代数単純化した後、$m = n-c$、問題は抽出に帰着します$$[x^m] (2-x)^c (1-x)^{-c}$$事前に計算された階乗係数によるスケーリング。 
6. 両方の用語を展開します。$$(2-x)^c = \sum_{i=0}^{c} \binom{c}{i} 2^{c-i} (-x)^i,
\quad
(1-x)^{-c} = \sum_{j \ge 0} \binom{c+j-1}{j} x^j.$$7. の係数$x^m$ペアリングにより取得されます$i+j=m$、単一の合計を与える$i$:$$\sum_{i=0}^{\min(c,m)} \binom{c}{i} 2^{c-i} (-1)^i \binom{c + (m-i) - 1}{m-i}.$$8. この係数を次のように乗算します。$\frac{n!}{c! \cdot 2^c}$最終的な答えを得るために。 

テスト ケースごとの計算は、複数の単一の合計になります。$i \le c$、階乗と逆階乗を使用して実装されます。 

### なぜ効果があるのか

 すべての有効なグラフは、最大次数が 2 まででサイクルが存在しないことが強制されます。そうでない場合は、どのハミルトニアン サイクルにも埋め込むことができません。 これは、グラフがパスの互いに素な結合であることを特徴付けます。 逆に、線形フォレストは、そのパス コンポーネントをサイクルに沿って順序付けし、残りの欠落しているエッジを挿入することによって、常に何らかのサイクルに埋め込むことができます。 したがって、有効なグラフをカウントすることは、固定数のエッジを持つラベル付き線形フォレストをカウントすることと同等であり、これはまさに母関数の導出で捉えられるものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

MAXN = 3 * 10**5 + 5

fact = [1] * MAXN
invfact = [1] * MAXN

for i in range(1, MAXN):
    fact[i] = fact[i - 1] * i % MOD

invfact[MAXN - 1] = pow(fact[MAXN - 1], MOD - 2, MOD)
for i in range(MAXN - 2, -1, -1):
    invfact[i] = invfact[i + 1] * (i + 1) % MOD

def C(n, r):
    if r < 0 or r > n:
        return 0
    return fact[n] * invfact[r] % MOD * invfact[n - r] % MOD

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n, m = map(int, input().split())
        c = n - m

        if c < 0 or c > n:
            out.append("0")
            continue

        inv2c = pow(pow(2, MOD - 2, MOD), c, MOD)

        ans = 0
        for i in range(c + 1):
            if i > m:
                break

            term = C(c, i)
            term = term * pow(2, c - i, MOD) % MOD
            if i % 2 == 1:
                term = MOD - term

            term = term * C(c + m - i - 1, m - i) % MOD
            ans = (ans + term) % MOD

        ans = ans * fact[n] % MOD
        ans = ans * pow(invfact[c], 1, MOD) % MOD
        ans = ans * pow(pow(2, MOD - 2, MOD), c, MOD) % MOD

        out.append(str(ans % MOD))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```階乗テーブルと逆階乗テーブルは、定数時間でのすべての二項係数をサポートします。 ループオーバー$i$2 つの系列の畳み込みから係数抽出を実行します。 符号の変更により実装されるのは、$(-x)^i$拡大からの期間$(2-x)^c$。 最後の乗算では、母関数の係数が実際のラベル付きグラフの数に変換されます。 

実装でよくある落とし穴は、グローバル スケーリング係数を忘れることです。$n!$、生成関数が指数関数形式で機能するため、これが必要です。 もう一つは、取り扱いを誤っていることです。$c=0$または$m=0$この境界では、唯一の有効な構造はコンポーネントの空のフォレストまたは孤立した頂点のセットです。

 ## 特殊なケース

 主なエッジケースは次のような場合です$m = n - 1$これは、グラフがすでにスパニング ツリーであることを意味します。 ここで有効なツリーは、パスであるツリーのみです。 アルゴリズムはこれを自然に処理します。$c=1$、係数抽出は、既知のパスと一致するラベル付きパスのカウントに減ります。$n!/2$構造。 

もう一つの境界線は、$m = 0$、すべての頂点が分離されています。 これは以下に対応します$c=n$、そして数式は選択に折りたたまれます$n$シングルトンコンポーネント。 生成関数はシングルトンごとに重み 1 を正しく割り当て、高次の項はすべて消えます。 

いつ$m$大きい、近い$\binom{n}{2}$、計算された$c$が負になり、エッジが多すぎるグラフはサイクルへの埋め込みに必要な次数制約を回避できないため、アルゴリズムは正しくゼロを返します。
