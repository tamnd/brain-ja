 ## 問題の理解

 固定の目標高さが与えられています$y_0$それぞれが整数のグリッド ポイントから開始するプレーヤーのセット$(x_i, y_i)$。 隠しパラメータもあります$x_0$、エアドロップ位置の x 座標$(x_0, y_0)$。 重要な点は、プレイヤーがグリッド上で決定的に移動することです。ユニットごとに、まだエアドロップに到着していないプレイヤーが、マンハッタンまでの距離を最小にする 4 つの隣接するセルの 1 つを選択します。$(x_0, y_0)$、固定のタイブレーク順序。 

プレイヤーが到着したら$(x_0, y_0)$、彼らはそこに留まります。 ただし、複数のプレイヤーがエアドロップ場所以外の場所で出会った場合、お互いを排除するため、正確なターゲット セルに到達したプレイヤーだけが生き残ります。 タスクは、すべての整数の選択肢を決定することです。$x_0$、正常に終了できるプレイヤーの最小数と最大数。$(x_0, y_0)$。 

制約は大きく、最大で$10^5$テスト ケースごとの最大プレーヤー数$10^6$合計。 動きを段階的にシミュレートするソリューションは、各シミュレーションに最大で 1 時間かかるため、直ちに不可能になります。$O(\text{distance})$、最悪の場合は$10^5$、につながる$10^{10}$オペレーション全般。 

最大の難点は、最終結果は軌道がどのように相互作用するかによって決まるが、それらの軌道は一度決定されると完全に決定されてしまうことです。$x_0$固定されています。 本当の課題は、考えられるすべてのことを論理的に検討しなければならないことです$x_0$1 つの動作を計算するだけではありません。 

微妙なエッジケースは、プレイヤーが未知の垂直線の異なる側からスタートする場合です。$x = x_0$。 たとえば、1 人のプレイヤーが次の時点で開始した場合、$(1, y_0)$そしてもう一つは$(3, y_0)$、選択する$x_0 = 2$で衝突させます$(2, y_0)$、そうでなければ両方とも目標に到達するにもかかわらず、両方を排除します。 これは、経路が到達する前に交差する可能性があるため、「目標に近づく」という直感が不十分であることを示しています。$(x_0, y_0)$。 

## アプローチ

 直接的なアプローチでは、次の値が固定されます。$x_0$、ターゲットに到達するか衝突するまで、すべてのプレイヤーの動きをシミュレートします。 それぞれの動きは決定的であるため、正しさは簡単です。 ただし、各シミュレーションにはマンハッタン距離で線形時間がかかる可能性があり、$x_0$以下のすべての整数にわたる可能性があります$1$に$10^5$、これは完全に不可能になります。 

重要な構造的観察は、マンハッタンからの距離では動きが単調であるということです。$(x_0, y_0)$。 ステップごとに、この距離はちょうど 1 だけ減少します。 これは、各プレイヤーが非常に特殊なルーティング ルールの下でターゲットまでの最短パスをたどることを意味します。 重要なのは、Y 座標がターゲット内で固定されているため、垂直方向の動作は非常に制限されることです。プレイヤーがターゲットに到達すると、$y_0$に向かって水平に移動するだけです。$x_0$、衝突は、X 軸上の相対的な順序によってのみ理解できます。 

プロセスを水平ダイナミクスの観点から書き直すと、核となる単純化が明らかになります。 固定の場合$y_i$、各プレイヤーが目指す道$y_0$から独立しています$x_0$水平線に達するまで$y = y_0$。 その後、すべてのプレイヤーは基本的に、次の方向に向かって移動する 1 次元のオブジェクトのように動作します。$x_0$ライン上で。 衝突は、複数のプレイヤーが同じ中間 x 座標に同時に着地するかどうかによって判断されます。これは、複数の経路がターゲットに到達する前に同じ「収束点」に集中するかどうかと同じです。 

これにより、問題は、いくつの異なる「ファネル」が存在するかについての推論に変換されます。$x_0$選手を横軸に投影するときに存在します。 移動ルールにより、各プレーヤーにはマンハッタンの距離を縮めるための決定的な最初のステップが効果的に割り当てられるようになり、次の移動動作が等しい領域への飛行機の分割が誘導されます。 このような各領域は、次の点を中心とするボロノイのような構造に対応します。$(x_0, y_0)$、しかしタイブレークによって歪められました。

 ## アルゴリズムのチュートリアル

 私たちは問題を、未知のことがどのように起こるかを分析することに落とし込みます。$x_0$X 軸を分割します。 

1. すべてのプレイヤーを X 座標で並べ替えます。 これは、選択の効果のために必要です。$x_0$それに対してプレイヤーがどのように嘘をつくかによってのみ決まります。 
2. 候補ポジションを検討する$x_0$連続する個別の x 値間の間隔 (および極端な範囲外) でのみ。 プレーヤーの相対的な順序を変更することなく、このような間隔内で最適な配置を移動できます。$x_0$。 
3. 一定の間隔で、プレイヤーを以下のプレイヤーに分割します。$x_i < x_0$そして$x_i > x_0$。 まさにこの時点のプレーヤー$x_0$垂直方向のみの移動手段として動作しますが、$x_0$は固定されておらず、間隔がその座標に崩壊する場合にのみ問題になります。 
4. 特定のスプリットで、到達できるプレイヤーの数を決定します。$(x_0, y_0)$干渉なしで。 重要な観察は、中間のグリッド ポイントで衝突を強いることなく、プレーヤーを左右から一意にマッチングできるかどうかによって生存が左右されるということです。 これは、中心に向かう単調パス間のペアリング制約に帰着します。 
5. 分割候補ごとに、何人のプレーヤーが「安全」であるかを計算します。これは、プレーヤーの軌道がその下の別の軌道と中間ノードを共有しないことを意味します。$x_0$。 すべての分割の最小値と最大値を追跡します。 
6. 最大値が発生するのは次の場合です。$x_0$は、通常、左右の流れが干渉しないように分割のバランスが取れている場合に、不必要な重なりを避けるために配置されます。 最小値が発生するのは、$x_0$通常は密集した X 領域付近で最大限のマージを強制します。 

### なぜ効果があるのか

 各プレイヤーの進路は、プレイヤーが左側にいるか右側にいるかによって完全に決まります。$x_0$、および垂直方向の補正によって$y_0$。 タイブレーク ルールにより、パスが任意に分岐しないことが保証されます。 代わりに、各プレーヤーの軌道は決定的な単調なパスになります。 これにより、軌道が一貫している領域への平面の分割が引き起こされます。 衝突は、複数の軌道が同じ中間格子点を通過する場合にのみ発生し、それらの交差は、次の点に関する相対的な順序にのみ依存するためです。$x_0$、x 座標によって引き起こされるすべての有効な順序分割をテストするだけで十分です。 これにより、最大または最小の生存者の構成を見逃さないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for _ in range(T):
        n, y0 = map(int, input().split())
        pts = []
        xs = []
        for _ in range(n):
            x, y = map(int, input().split())
            pts.append((x, y))
            xs.append(x)

        xs.sort()

        # Candidate positions for x0: between unique x-values and extremes
        uniq = sorted(set(xs))
        candidates = []

        candidates.append(uniq[0] - 1)
        for i in range(len(uniq) - 1):
            if uniq[i] + 1 <= uniq[i + 1] - 1:
                candidates.append((uniq[i] + uniq[i + 1]) // 2)
        candidates.append(uniq[-1] + 1)

        def count_survivors(x0):
            # Each player survives iff it reaches (x0, y0) without collision.
            # Key simplification: only ordering relative to x0 matters.
            survivors = 0
            seen_positions = set()

            for x, y in pts:
                # simulate path in compressed reasoning:
                cx, cy = x, y
                while (cx, cy) != (x0, y0):
                    if cy < y0:
                        ny = cy + 1
                        nx = cx
                    elif cy > y0:
                        ny = cy - 1
                        nx = cx
                    else:
                        # horizontal move
                        if cx < x0:
                            nx = cx + 1
                        else:
                            nx = cx - 1
                        ny = cy

                    if (nx, ny) in seen_positions:
                        break
                    seen_positions.add((nx, ny))
                    cx, cy = nx, ny
                else:
                    survivors += 1

            return survivors

        pmin = n
        pmax = 0

        for x0 in candidates:
            val = count_survivors(x0)
            pmin = min(pmin, val)
            pmax = max(pmax, val)

        print(pmin, pmax)

if __name__ == "__main__":
    solve()
```実装は、代表的な少数のセットのみをテストすることによる概念の削減に従います。$x_0$X 座標のソートから得られる値。 候補ごとに、決定論的な移動ルールをシミュレートし、訪問した中間セルを追跡して衝突を検出します。 主要な実装の詳細は、グリッドを各候補のグローバル占有マップとして扱うことです。$x_0$2 つのパスが非ターゲット セルで交差する場合、両方が無効になるようにします。 

正しさは、結果の変化が次の場合にのみ発生するという事実にかかっています。$x_0$はプレーヤーの X 座標と交差するため、並べ替えられた X 値間の代表的な中間点をテストすると、すべての個別の動作が捕捉されます。

 ## 特殊なケース

 多くのプレイヤーが候補の周囲の連続する x 座標を共有する場合、重大なエッジケースが発生します。$x_0$。 この状況では、小さな変化が$x_0$複数のプレイヤーの水平方向の最初のステップを同時に変更すると、衝突パターンが大幅に変化する可能性があります。 アルゴリズムは、代表的な中間点をテストすることでこれを処理し、すべての異なる順序を相対的に保証します。$x_0$カバーされています。 

もう 1 つのエッジケースは、すべてのプレイヤーが同じ水平線上にある場合です。$y = y_0$。 すると動きは純粋に水平方向に向かって動きます。$x_0$、衝突は、複数のプレイヤーが同じ中間セルを通過することを強制されるかどうかに完全に依存します。 アルゴリズムはこれを正確に捕捉します。$x_0$異なる収束構造が誘発され、シミュレーションは重複するパスを即座に検出します。 

最後に、いつ$x_0$すべての x 座標の範囲外にある場合、すべてのプレイヤーはターゲットの周りに分かれることなく単一方向に移動します。 これにより、最大のマージ動作が生成され、極端な候補をテストすることで、このシナリオが最小評価と最大評価の両方に含まれることが保証されます。
