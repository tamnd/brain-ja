 ## 解決策
 ## 問題の理解

 画像を表す文字のグリッドが与えられます。各セルは空か塗りつぶされています。 タスクは、塗りつぶされたセルが正確に 1 つのプラス型の図形を形成するかどうかを判断することです。 

有効なプラスの形状には、中央に 1 つの塗りつぶされたセルがあります。 その中心から、上下左右の 4 つの方向のそれぞれに連続的に伸びる塗りつぶされたセルが少なくとも 1 つ存在する必要があります。 これらの延長部分は隙間のない真っ直ぐなセグメントである必要があります。 グリッド内のすべての塗りつぶされたセルは、この単一の構造に属している必要があります。これは、余分なコンポーネント、孤立したセル、二次分岐がないことを意味します。 

したがって、私たちが検証している構造は、単に「プラスに見える」だけではなく、非常に厳密に接続されたパターンです。つまり、1 つの中心、4 つのまっすぐなアーム、そしてグリッド内のどこにも他には何もありません。 

グリッド サイズは 500 x 500 までの大きさにすることができ、これは最大 250,000 個のセルを意味します。 多くの候補から二次またはそれより悪い方法で繰り返しスキャンまたは拡張しようとするソリューションは、不必要なオーバーヘッドを引き起こす危険があります。 ただし、250,000 回の操作は取るに足らないものであるため、すべてのセルにわたる完全なリニア スキャンであっても完全に許容されます。 

いくつかの特殊なケースは、素朴な推論をすぐに打ち破ります。 

最初の落とし穴は、候補センターが複数あることです。 たとえば、星の垂直線が 2 本ある場合:```
.*....
.*....
.*....
..*...
..*...
..*...
```それぞれの柱が個別にアームに似ているとしても、これは何のプラスにもなりません。 接続された構造が複数あるため、正解は NO です。 

2番目の落とし穴は腕の骨折です。 中心は存在するが、一方向にギャップがある場合:```
..*..
..*..
.*.*.
..*..
.....
```アームが連続していないため、これは無効です。 

3 番目の落とし穴は、プラスの外側にある浮遊セルです。```
..*..
.***.
..*..
..*..
*....
```プラスが存在する場合でも、左下の余分な星は構成を無効にします。 

重要な課題は、プラスを検出することではなく、グローバルな独占性と継続性を同時に強化することです。 

## アプローチ

 強引なアプローチは、すべての星細胞を潜在的な中心として試すことです。 各候補について、4 つの方向に展開して訪問したセルをマークし、すべての星が正確に 1 回カバーされているかどうかを確認します。 

プラスは一意の中心と決定論的なアームによって定義されるため、これは概念的に機能します。 ただし、高密度のグリッドではコストが問題になります。 ほとんどのセルがスターである最悪のケースでは、O(h・w) 中心を試みることがあり、各展開は最大 O(h + w) までスキャンされ、複雑さは O(h・w・(h + w)) になります。 500 × 500 では、これは限界をはるかに超えています。 

重要な観察は、有効なプラスは非常に厳格な構造を持っているということです。 4 つの方向すべてが連続的に拡張できるセルが 1 つだけあります。 そのセルは 4 方向すべてに少なくとも 1 つの隣接星を持たなければならず、他の星はすべて、そのセルを通過する 4 つの直線のうちの 1 つに正確に位置する必要があります。 これは、すべてのセルをテストする必要がなく、一意の中心を特定してアームを 1 回検証するだけでよいことを意味します。 

上下左右に星が少なくとも 1 つある星をスキャンすることで中心を見つけることができます。 そのような候補を見つけたら、そこから拡張してその構造を完全に検証し、カバレッジがグリッド内のすべての星と正確に一致することを確認します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(h・w・(h+w)) | お(1) | 遅すぎる |
 | 中心検出 + 検証 | O(h・w) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グリッドをスキャンしてすべての星の位置を収集し、同時に候補中心もチェックします。 

4 つの方向すべてに少なくとも 1 つの星があるセルは中心候補です。 この条件により、それがプラスの交点である可能性が確実になります。 
2. 候補センターが存在しない場合は、直ちに NO を返します。 

有効なプラスには、交点が 1 つだけ存在する必要があります。 
3. 各候補センターについて検証を試みます。 

1 つを選択し、それが中心であると仮定します。 
4. 中心から上に向かって非星が見つかるまで拡大し、訪問したすべての星細胞を記録します。 

これにより垂直アームが定義されます。 
5. 同様に下方向、左方向、右方向への拡張を繰り返します。 

これら 4 つの走査により、構造に属するすべてのセルが収集されます。 
6. 到達可能な腕セルをすべて収集したら、次の 2 つの条件を確認します。 

まず、収集されたすべてのセルがグリッド内のスターである必要があります。 

次に、収集されたセルの総数は、グリッド内の星の総数と等しくなければなりません。 
7. 両方の条件がいずれかの候補センターに当てはまる場合は、YES を返します。 それ以外の場合は、NO を返します。 

### なぜ効果があるのか

 有効なプラスは、1 つの交点とそこから伸びる 4 つの最大の直線セグメントによって完全に特徴付けられます。 余分な星や連続性の欠如などの逸脱があると、中心からの到達可能性または星の総数が変化します。 中心から形状を再構築し、それを星のセット全体と比較することで、接続性と排他性の両方を同時に強化します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    h, w = map(int, input().split())
    g = [list(input().strip()) for _ in range(h)]

    stars = 0
    for i in range(h):
        for j in range(w):
            if g[i][j] == '*':
                stars += 1

    def valid(i, j):
        if g[i][j] != '*':
            return False

        visited = set()

        # up
        x = i
        while x >= 0 and g[x][j] == '*':
            visited.add((x, j))
            x -= 1

        # down
        x = i + 1
        while x < h and g[x][j] == '*':
            visited.add((x, j))
            x += 1

        # left
        y = j - 1
        while y >= 0 and g[i][y] == '*':
            visited.add((i, y))
            y -= 1

        # right
        y = j + 1
        while y < w and g[i][y] == '*':
            visited.add((i, y))
            y += 1

        # include center
        visited.add((i, j))

        return len(visited) == stars

    for i in range(h):
        for j in range(w):
            if g[i][j] == '*':
                if valid(i, j):
                    print("YES")
                    return

    print("NO")

if __name__ == "__main__":
    solve()
```グリッドはメモリに直接読み込まれ、最初にすべての星を数えます。 これにより、後で使用するグローバル不変式が得られます。有効な再構成は、この合計と正確に一致する必要があります。 

の`valid`関数は、指定されたセルが中心であると想定し、形状が崩れるまで 4 方向すべてに拡張します。 訪問したすべての星が記録されます。 重要な考え方は、構造が分岐のない単一のプラスであるため、正しい中心がすべての星に 1 回だけ到達できるということです。 

最後に、各星細胞を中心候補としてテストします。 最初に一致が成功すると、プログラムが終了します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as sio

    out = sio.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    h, w = map(int, input().split())
    g = [list(input().strip()) for _ in range(h)]

    stars = sum(row.count('*') for row in g)

    def valid(i, j):
        if g[i][j] != '*':
            return False
        visited = set()

        x = i
        while x >= 0 and g[x][j] == '*':
            visited.add((x, j))
            x -= 1

        x = i + 1
        while x < h and g[x][j] == '*':
            visited.add((x, j))
            x += 1

        y = j
        while y >= 0 and g[i][y] == '*':
            visited.add((i, y))
            y -= 1

        y = j + 1
        while y < w and g[i][y] == '*':
            visited.add((i, y))
            y += 1

        return len(visited) + 1 == stars

    for i in range(h):
        for j in range(w):
            if g[i][j] == '*':
                if valid(i, j):
                    print("YES")
                    return
    print("NO")

 ## 特殊なケース

 コーナーケースは、中心が唯一のセルである最小の有効なプラスです。 この場合、アルゴリズムは単一の星を有効な中心として扱いますが、方向の拡大はすぐに停止し、訪問数は 1 つの星と正確に一致します。 

もう 1 つのケースは、太い十字の中に複数の中心候補がある場合です。 星全体を正しくカバーできるのはそのうちの 1 つだけです。 他の候補は外側のアームを見逃しているか、間違ったオーバーラップを含んでおり、訪問数の不一致が発生します。 

最後のエッジ ケースは、アーム セグメントが 1 つ欠けているほぼプラスの形状です。 中心からの拡大はその方向の早い段階で止まり、訪問対象範囲がスターの合計数よりも減少し、拒否を強制されます。
