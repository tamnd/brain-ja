 ## 解決策
 ## 問題の理解

 色付きの立方体の複数のセットが与えられます。 キューブの色は固定されていますが、棚全体に色を配分する方法や、各棚に表示される順序を選択できます。 

棚の場合、要件は同じ色の間の最小距離程度です。 せめて棚にカラフルさがあれば`d`、その場合、その棚にある同じ色の 2 つの出現は、少なくとも次の距離で区切られている必要があります。`d`ポジション。 別の言い方をすると、棚の中では、前の棚の中に同じ色が現れることは禁止されています。`d - 1`ポジション。 

各棚には長さがあります`s_i`そして必要な距離`d_i`。 すべての立方体を 1 回だけ使用して、すべての棚の実際の色のシーケンスを構築する必要があります。 

すべてのテスト ケースにわたるキューブの合計数は最大で`2 · 10^5`。 それは二次関数を即座に除外します`n`。 解決策`O(n log n)`完全に快適ですが、`O(n^2)`大雑把に実行するだろう`4 · 10^10`最悪の場合の運用。 

この問題の微妙な部分は、最終的な答えではシェルフは独立していますが、キューブ周波数はグローバルであるということです。 1 つの棚では有効に見える貪欲な配置により、後の棚が不可能になるような形で色が消費される可能性があります。 

適切なサイズの棚を検討する`4`と`d = 2`同じ色の立方体が 4 つあります。 棚にはパターンが必要です`x ? x ?`、しかし、すべてのコピーを分離するには他の色が足りません。 現在位置をチェックするだけの貪欲なアルゴリズムでは、不可能であることに気づくのが遅すぎる可能性があります。 

もう 1 つの簡単な間違いは、次の場合に条件を「隣接するキューブは異なっていなければならない」ものとして扱うことです。`d > 2`。 例えば：```
s = 5
d = 3
shelf = [1, 2, 1, 3, 4]
```二人`1`は 2 つの位置しか離れていないため、カラフルさは次のようになります。`2`、 ない`3`。 

3 番目の罠は、棚が完全に独立していることを忘れていることです。 カラフルさは各シェルフ内でのみ定義されるため、あるシェルフの終わりと別のシェルフの先頭で使用される色は違反を引き起こしません。 

## アプローチ

 強引な観点は、一度に 1 つの位置に棚を構築し、まだコピーが残っているすべての色を試すことです。 色を配置するときは常に、棚のカラフルさの制約が満たされていることを確認します。 これは、考えられるすべての構造を検討しているため、概念的には正しいです。 

問題は分岐要素です。 同じ色を圧縮した後でも、各ステップで何千もの異なる選択肢が存在する可能性があります。 検索スペースは指数関数的に増加します。 

重要な観察点は、要件を備えた棚であるということです。`d`前のことだけを気にする`d - 1`ポジション。 一度使用した色は次の色では使用できなくなります`d - 1`位置が決まり、再び使用できるようになります。 

これはスケジュールの問題のように思えます。 どの色にも残りの周波数があります。 使用頻度の高い色は後で配置するのが最も難しいため、現在使用可能なすべての色の中で、残りの数が最も多い色を使用するのが最も安全な選択です。 

これは、クールダウン制約のある再配置問題で古典的な貪欲が使用されていることを示唆しています。 

距離のある棚の場合`d`:```
place a color
temporarily block it
after d steps, unblock it
```ブロックされていないすべての色の中で、常に最大の残りの頻度を持つ色を選択します。 

素晴らしい点は、シェルフを個別に解決する必要がないことです。 残りのキューブのグローバル プールを維持しながら、シェルフを順番に処理します。 棚内では、色はプールから一時的に削除されます。`d`ポジション。 それらが再び合法になると、再び挿入されます。 

ある位置に使用可能な色がない場合は、有効な構造が存在しません。 公式ソリューションは、残りの頻度で順序付けされたセットでまさにこれを貪欲に使用します。

 ## アルゴリズムのチュートリアル

 1. 各色にいくつの立方体が存在するかを数えます。 
2. 正の周波数を持つすべての色を、次のキーで順序付けされたセットに保存します。`(remaining_count, color)`。 
3. 棚を 1 つずつ加工します。 
4. 現在のシェルフに対して、長さの配列を作成します。`s_i`。 
5. ポジションを埋める場合`j`、最初に色が位置に配置されているかどうかを確認します`j - d_i`再び利用可能になるはずです。 まだコピーが残っている場合は、セットに再挿入します。 
6. セットが空の場合、現在の位置に正規の色を配置することはできません。 出力`-1`。 
7. それ以外の場合は、残っている最大の周波数を持つ色を選択します。 
8. 現在の位置に配置し、周波数から 1 つのコピーを削除し、次のコピーに対してブロックしたままにします。`d_i - 1`ポジション。 
9. 棚が完全に埋まった後、クールダウンウィンドウでまだ待機しているすべての色を解放します。 これにより、次のシェルフのグローバル構造が準備されます。 
10. すべての棚の処理が完了したら、構築された棚を出力します。 

### なぜ効果があるのか

 すべてのステップで、セットには、現在の位置に配置できる正確な色が含まれています。 最後に使用されている色`d_i - 1`現在の棚の位置は一時的に除外されます。 

すべての合法な色の中で、残りの頻度が最も大きい色を選択するのが、クールダウン スケジュールの標準的な貪欲な戦略です。 多くのコピーが残っている色は、最も制約のあるリソースです。 それを遅らせると、今後の配置が難しくなるだけです。 利用可能なセットが空であるために欲張りが色を配置できない場合、残りの色はすべて現在ブロックされているため、有効な継続は存在しません。 

不変条件は、セットには常にすべての正当な色のみが含まれ、すべての配置が距離要件を尊重することです。 その結果、製造されたすべての棚には少なくともカラフルさが備わります。`d_i`。 受け入れられた Codeforces ソリューションは、まさにこの構造に従っています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    s = list(map(int, input().split()))
    d = list(map(int, input().split()))

    cnt = [0] * (n + 1)
    for x in a:
        cnt[x] += 1

    import heapq

    heap = []
    for color in range(1, n + 1):
        if cnt[color]:
            heapq.heappush(heap, (-cnt[color], color))

    ans = []

    for i in range(m):
        shelf = [0] * s[i]

        for j in range(s[i]):
            if j >= d[i]:
                old = shelf[j - d[i]]
                if cnt[old] > 0:
                    heapq.heappush(heap, (-cnt[old], old))

            if not heap:
                print(-1)
                return

            negf, color = heapq.heappop(heap)
            shelf[j] = color
            cnt[color] -= 1

        for j in range(s[i], s[i] + d[i]):
            old = shelf[j - d[i]]
            if cnt[old] > 0:
                heapq.heappush(heap, (-cnt[old], old))

        ans.append(shelf)

    for shelf in ans:
        print(*shelf)

t = int(input())
for _ in range(t):
    solve()
```周波数配列は、色ごとに未使用のキューブがいくつ残っているかを追跡します。 

ヒープには、現在利用可能な色のみが保存されます。 カラーは配置された直後にヒープから消えます。 まさに再現されます`d_i`後で位置を変更します。位置から色を再挿入することで実装されます。`j - d_i`。 

微妙な点は、ヒープ キーが現在の残りの周波数を使用することです。 色が配置されると、その数は減少し、色はすぐには再挿入されません。 これにより、古い周波数が回避されます。 

もう 1 つの重要な詳細は、棚を完成させた後のクリーンアップ ループです。 クールダウンが期限切れになる前にシェルフが終了したため、一部のカラーはまだブロックされている可能性があります。 シェルフは独立しているため、次のシェルフを開始する前に解放する必要があります。

 ## 特殊なケース

 次のことを考慮してください。```
1
4 1
7 7 7 7
4
2
```最初に配置した後`7`、色は 1 つの位置でブロックされます。 他の色は存在しないため、使用可能なセットは空になります。 アルゴリズムはすぐに戻ります`-1`、それは正しいです。 

考慮する：```
1
5 1
1 2 3 4 5
5
5
```どの色も 1 回ずつ表示されます。 ヒープでは色を再利用する必要はありません。 どのような順序でも機能し、そのカラフルさはまさに棚の長さです。 

考慮する：```
1

```最初の棚にはカラーのコピーがいくつか消費される可能性があります`1`そして`2`。 シェルフが終了すると、2 番目のシェルフが開始する前に、ブロックされたカラーが再挿入されます。 これは、距離制約が棚の境界を越えないことを正確に反映しています。 2 番目の棚は、残りの法定色のフルセットから始まります。
