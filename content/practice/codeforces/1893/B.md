 ## 解決策
 ## 問題の理解

 2 つの配列が与えられています。 最初の配列は順序が固定されており、2 番目の配列は追加の値のマルチセットであり、最初の配列のどこにでも挿入できますが、これらの挿入された値を配置する前に任意に並べ替えることもできます。 

両方のソースを 1 つのシーケンスにマージした後、最長増加サブシーケンス (LIS) の長さを測定します。 目標は、この LIS 値を最小化する有効なマージされたシーケンスを構築することです。 

キーの自由度は重要です。2 番目の配列の相対的な順序を維持するという制約はなく、その要素を最初の配列のどこにでもインターリーブできます。 最初の配列のみがサブシーケンスとして残される必要があります。 

この制約により、テスト ケースごとに O(n + m) または O((n + m) log(n + m)) の解決策が求められます。 テスト全体の n と m の合計は 2・10^5 で制限されるため、各要素を一定回数ソートまたは線形スキャンするソリューションは許容されますが、単一のテストで二次関数を実行することは直ちに不可能です。 

単純なアプローチでは、b から a に要素を挿入するあらゆる方法を試みることになりますが、挿入位置を決定するだけでもすでに組み合わせ爆発が形成されています。 b の順序を固定しても、m 個の要素を n 個のギャップに挿入すると、指数関数的な可能性が得られます。 もう 1 つの素朴なアイデアは、b の順列ごとに LIS をシミュレートすることですが、LIS 自体は O((n + m) log(n + m)) であるため、これはすぐに実行不可能になります。 

b の値が a と比較して非常に大きいか非常に小さい場合、微妙なエッジ ケースが発生します。 不注意で貪欲な戦略は、常に先頭または末尾に大きな値を配置しようとする可能性がありますが、これは LIS が絶対的な配置ではなく相対的な順序に依存することを無視しています。 

たとえば、a = [1, 3] と b = [2] の場合、それらの間に 2 を挿入すると LIS 2 が生成されますが、先頭または末尾に配置しても LIS 2 が生成されます。 しかし、より複雑な場合には、配置の決定が間違っていると、両方の配列にわたって長い増加チェーンが人為的に作成される可能性があります。 

## アプローチ

 ブルートフォース戦略では、b の各要素を a の周囲の n + 1 個のギャップの中の位置に割り当て、さらに考えられるすべての方法で b を並べ替えようとします。 各候補配列を構築した後、標準の忍耐ソート方法を使用して LIS を計算します。 これは完全な解空間を探索するため正しく機能しますが、配置の数は (n + m) のオーダーになります。 最悪の場合、b の順列を制限するだけでも m! が得られます。 可能性はありますが、2・10^5 までの m ではすでに不可能です。 

重要な洞察は、ポジションについて考えるのをやめ、代わりに LIS がどのように形成されるかについて考えることです。 LIS は値の相対的な順序のみに依存します。 b は任意に並べ替えることができるため、a の増加する部分列を「破る」または「制御」するために使用できる値のリソース プールとして扱う必要があります。 

中心的な観察は、値を挿入しても均一な効果が得られないということです。 b の値は、隣接する a 値との相対的な配置に応じて、増加するサブシーケンスを拡張することも、中断することもできます。 LIS を最小限に抑えるために、チェーンを増加させる新たな機会の作成を回避すると同時に、a の要素が互いに結合して長い増加ランにならないようにしたいと考えています。 

これにより、標準的な貪欲な構造が得られます。b をソートし、a の要素と慎重に選択した b の要素を貪欲にインターリーブすることによって最終的な配列を構築します。構造が増加する前に、常に「できるだけ多くのブロッキング要素」を配置しようとします。 

最終的な配列をスキャンし、増加するサブシーケンスに対して「現在のしきい値」を維持した場合に LIS がどのように進化するかをシミュレーションすると、正しい構造が明らかになります。 可能な限り、現在の LIS 状態の拡張を防ぐために、常に最小の利用可能な b 値を挿入します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((n+m)!) | O(n+m) | 遅すぎる |
 | 最適 | O((n+m) log(n+m)) | O(n+m) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず配列 b をソートします。 これにより、ローカルで必要なものに応じて、利用可能な最小または最大の挿入値を常に使用できるようになり、これはサブシーケンスを制御するために重要です。 

次に、a の順序を維持しながら、最終的な配列の構築をシミュレートします。 

1. b を非降順でソートし、b に対するポインタを初期化します。 
2. LIS を必要以上に増加させることなく、次に安全に配置できる最小値を表す現在の「アクティブ境界」を維持しながら、a の要素を左から右に処理します。 
3. 各 a[i] を配置する前に、LIS の増大を防ぐために、最後に選択した境界条件より厳密に大きい要素を b からできるだけ多く挿入します。 
4. これらの候補の中で、小さい値は増加するサブシーケンスを拡張する可能性が低いため、最初に小さい値を挿入することを好みます。 
5. 現在の位置に有益な b 要素がなくなったら、a[i] を配置します。 
6. a のすべての要素が処理されるまで続行します。 
7. b の残りの要素を最後に追加します。その時点では、LIS をさらに削減するためにそれらの要素を使用することはできません。 

微妙な部分は、なぜ b 要素を a 要素の「前」に挿入するのかを理解することです。 基本的に、増加するサブシーケンスが連続する a 要素を介して伝播するギャップを埋めています。 これらのギャップを注意深く順序付けられた b 値で飽和させることにより、厳密に増加する長いチェーンが a 全体に形成されるのを防ぎます。 

### なぜ効果があるのか

 アルゴリズムは重要な不変条件を維持します。つまり、構築のどの時点でも、部分シーケンスは b の既に使用されている要素を配置するすべての方法の中で可能な限り最小の LIS を持ちます。 これは、a を進めるか b を消費するかを決定するたびに、LIS の潜在的な増加をブロックまたは遅らせることができる場合は常に b を選択するために達成されます。 b は完全に並べ替え可能であるため、ソートされた順序で貪欲に使用することで、後で LIS をより効果的に削減できる値を無駄にしないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        b.sort()
        
        res = []
        i = 0
        j = 0
        
        # We use a simple greedy interleaving idea:
        # Always try to insert b elements that are <= current a[i]
        # in decreasing effectiveness order (small first doesn't matter much after sort)
        
        while i < n:
            # push all useful b's before a[i]
            # useful here means b[j] <= a[i]
            # because placing them now avoids increasing LIS contribution from a[i]
            while j < m and b[j] <= a[i]:
                res.append(b[j])
                j += 1
            
            res.append(a[i])
            i += 1
        
        # remaining b
        while j < m:
            res.append(b[j])
            j += 1
        
        print(*res)

if __name__ == "__main__":
    solve()
```実装は貪欲な構造に直接に従います。 b のソートは、ローカルな決定を意味のあるものにするために必要な唯一の前処理ステップです。 

ポインタ j は、b の要素がすでに使用されている数を追跡します。 a の各要素を配置する前に、それより大きくないすべての b 要素を使い果たします。 この順序により、LIS を途中で増加させない「安全な」要素を挿入する機会を逃すことがなくなります。 

よくある間違いは、b 要素の挿入を最後まで遅らせることです。 これは、最初の大きなセグメントを配置すると、後の挿入では分割できない長い増加サブシーケンスがすでに確立されている可能性があるため、失敗します。 インターリーブは LIS の形成を制御するものです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

 | 時間 | O((n + m) log m) | ソート b が優勢で、マージは線形です。 
| スペース | O(n + m) | 結果配列の保存 |

 ## 特殊なケース

 a のすべての要素が等しい場合、a の LIS はすでに 1 であり、b から値を挿入しても、a の周りに非増加順に配置すると、1 を超えて増加することはできません。 厳密に増加するチェーンを作成せずに、すべての b 要素が等しい a 要素の前後に挿入されるため、アルゴリズムはこれを処理します。 

a が厳密に増加している場合、LIS は大きいままであるに違いないと素朴に懸念します。 ただし、各 a 要素の前に十分な数の小さな b 値を挿入すると、長く中断されずに増加するサブシーケンスが防止され、貪欲なマージにより、連続する a 要素が不必要にチェーンを拡張することが決して許可されなくなります。 

b に a よりもはるかに大きいかはるかに小さい極値が含まれる場合、比較は隣接する挿入決定間で常にローカルであるため、ソートされたマージは境界を越えた増加サブシーケンスを作成することなく、自然にそれらを安全な位置に配置します。 

このアルゴリズムは絶対値に依存せず、相対的な順序のみに依存するため、これらの極端な場合には特別なケースは必要ありません。
