 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられます`s`。 のすべてのプレフィックスに対して、`s`、値を定義します`f(prefix)`。 

計算するには`f(x)`のすべての可能な拡張を調べます。`x`。 もし`x`長さがある`k`、拡張子には長さがあります`2k-1`。 の登場人物`x`エクステンションの奇数位置に固定されていますが、偶数位置はすべて自由に選択できます。`0`または`1`。 

それらの拡張機能のうち、「良い」拡張機能がいくつあるかを数えます。 

優れた拡張機能には特別な特性があります。 奇数の位置ごとに`i`、位置の文字`i`で終わるプレフィックスの中央値と等しくなければなりません`i`。 アルファベットはバイナリであるため、中央値は単にその奇数長プレフィックスの過半数の値です。 

テストケースごとに、次のことを計算する必要があります。$$\sum_{i=1}^{n} f(s[1..i])$$モジュロ`998244353`。 

すべてのテスト ケースの合計の長さは最大でも`2·10^5`。 各プレフィックスを個別に処理し、拡張子を列挙するソリューションは不可能です。 単一の長さのプレフィックスであっても`200000`もっている`2^{199999}`拡張子。 テスト ケースごとに線形または線形に近いソリューションが必要です。 

微妙な間違いの原因は、中央値条件の意味を誤解していることです。 

考慮する：```
s = 11
```拡張子は次のとおりです。```
101
111
```どちらも良いので、`f(11)=2`。 

次に、次のことを考えてみましょう。```
s = 01
```拡張子は次のとおりです。```
001
011
```のみ`011`それは良いので、`f(01)=1`。 

すべての偶数の位置が常にフリーであると仮定するソリューションでは、オーバーカウントが発生します。 

もう一つの簡単なミスは、ランが変わるときに現れます。 

考慮する：```
s = 010
```答えは次のとおりです。```
f(0)=1
f(01)=1
f(010)=1
```合計`3`。 

隣接する文字が異なる瞬間に、適切な拡張子の数は 2 倍になります。 

## アプローチ

 強引な解釈は簡単です。 すべてのプレフィックスについて、すべてを生成します。`2^{len-1}`拡張子を調べて、各拡張子が中央値条件を満たすかどうかを確認し、有効な拡張子をカウントします。 

これは定義に直接従っているため、正しいです。 残念ながら、プレフィックスの長さの場合、`k`、 がある`2^{k-1}`拡張子。 と`k`と同じくらい大きい`200000`、これは絶望的です。 

重要な観察は、中央値条件が実際に何を課すかを調べることから得られます。 

奇数の位置で終わるプレフィックスをすでに処理していると仮定します。`2i-1`。 奇数位置まで伸ばすと`2i+1`、2 つの固定ビットの間に空きビットを 1 つだけ挿入します。 

固定ビットを次のようにします。```
a_i and a_{i+1}
```この 2 つのビットが異なれば、挿入されるビットは完全に決まります。 中央値の状態を維持する選択肢は 1 つだけあります。 

これら 2 つのビットが等しい場合、挿入されるビットには 2 つの有効な選択肢があります。 

これにより、一見グローバルな中央値制約が、元の文字列の連続する文字間の単純なローカル ルールに変換されます。 

させて`dp[i]`プレフィックスの適切な拡張子の数を示します`s[1..i]`。 

いつ：```
s[i] != s[i-1]
```カウントは変わりません。 

いつ：```
s[i] == s[i-1]
```カウントが2倍になります。 

より正確には:```
dp[1] = 1

dp[i] =
dp[i-1]                  if s[i] != s[i-1]
2 * dp[i-1]             if s[i] == s[i-1]
```最終的な答えはすべての合計なので、`dp[i]`1 回のパスですべてを計算できます。

 ## アルゴリズムのチュートリアル

 1.初期化`cur = 1`。 

これは、`f(s[1])`。 1 つの文字には、適切な拡張子が 1 つだけあります。 
2.初期化`answer = 1`。 

最初のプレフィックスの寄与はすでにわかっています。 
3. 位置から反復する`2`位置を決める`n`。 
4. もし`s[i] == s[i-1]`、乗算する`cur`による`2`。 

新しく挿入された偶数位置ビットには 2 つの有効な選択肢があります。 
5. もし`s[i] != s[i-1]`、 離れる`cur`変わらない。 

挿入されたビットは強制的に挿入されるため、良好な拡張の数は増加しません。 
6.追加`cur`実行中の答えに。 
7. すべての演算をモジュロで実行します`998244353`。 
8. 最終的な答えを出力します。 

### なぜ効果があるのか

 しましょう`g_i`プレフィックスの適切な拡張子の数になります`s[1..i]`。 

プレフィックス長からの移行`i-1`に`i`拡張機能内に新しい空き位置が 1 つだけ導入されます。 

新しく追加された固定文字が以前の固定文字と等しい場合、中央値の条件に違反することなく、どちらの値も挿入位置に配置できます。 以前の有効な拡張子ごとに、2 つの新しい有効な拡張子が生成されます。 

新しく追加された固定文字が以前のものと異なる場合、必要な中央値関係を維持しながら、値を 1 つだけ挿入できます。 以前の有効な拡張子はすべて、新しい有効な拡張子を 1 つだけ生成します。 

したがって：$$g_i = \begin{cases} 2g_{i-1} & s_i=s_{i-1}\\ g_{i-1} & s_i\ne s_{i-1} \end{cases}$$この繰り返しでは、すべての良好な拡張機能と良好な拡張機能のみがカウントされます。 すべてを合計すると`g_i`必要な答えを返します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

t = int(input())

for _ in range(t):
    n = int(input())
    s = input().strip()

    cur = 1
    ans = 1

    for i in range(1, n):
        if s[i] == s[i - 1]:
            cur = (cur * 2) % MOD

        ans = (ans + cur) % MOD

    print(ans)
```変数`cur`現在のプレフィックスの適切な拡張子の数を保存します。 隣接する 2 つの文字が等しい場合、既存の拡張子はすべて 2 つの有効な継続に分割されます。`cur`ダブルス。 

隣接する文字が異なる場合、新たな分岐は発生しません。 カウントは変わりません。 

答えは次の合計です`cur`すべてのプレフィックスにわたって。 

重要な実装の詳細は、乗算と加算の直後に係数を適用することだけです。

## テストケース```python
import io
import sys

def run(inp: str) -> str:

                cur = (cur * 2) % MOD
            ans = (ans + cur) % MOD

        out.append(str(ans))

    return "\n".join(out)
