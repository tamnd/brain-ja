 ## 解決策
 ## 問題の理解

 私たちは総当たりトーナメントに参加しています$n+1$参加者：あなたと$n$1 から 1 までのラベルが付けられた対戦相手$n$。 すべての対戦相手のペアは 1 回だけプレイし、より強い対戦相手が常に弱い対戦相手を倒します。$i$ビート$j$もし$i > j$。 あなたに対しては状況が異なります。 それぞれの対戦相手$i$必要$a_i$勝つための数分間の準備。 あなたは合計を持っています$m$すべての試合にわたってこの時間を超えることはできません。 あなたの目標は、勝利数に基づいて達成できる可能な限り低いランキングを決定することです。 

最終的なランキングは合計勝利数に基づいて決定されます。参加者の順位は、厳密に勝利数が多い参加者の数に 1 を加えたものと等しくなります。 他の人と同じ勝利数を持っている場合は、同じ順位を共有します。 対戦相手間の勝利はインデックスに基づいて決定的ですが、あなたの勝利はどの試合を準備するかによって決まります。 

制約は厳しいです:$n$到達できる$5 \cdot 10^5$すべてのテスト ケースにわたって、つまり、$O(n^2)$アルゴリズムは実行不可能です。 に近いアプローチが必要です$O(n \log n)$または$O(n)$。 エッジケースは、準備時間がゼロまたはすべての場合に発生します。$a_i$がゼロの場合、または$m$最も弱い相手にも勝つには不十分です。 たとえば、次の場合$n=3$、$m=0$、 そして$a = [1, 2, 3]$、誰にも勝つことはできないので、順位は 4 です。準備の制限を無視した単純なアプローチでは、誤ってより良い順位が割り当てられてしまいます。 

## アプローチ

 ブルートフォースアプローチでは、対戦相手のすべてのサブセットを列挙し、利用可能な準備時間内にどの試合セットに勝つことができるかを決定します。 サブセットごとに、必要な準備の合計を計算し、すべての参加者の勝利を計算してランキングを決定します。 これは非常に小さい場合に機能します$n$なぜならサブセットの数は$2^n$、しかし、$n$まで$5 \cdot 10^5$、明らかに不可能です。 最悪の場合の操作数は次のようになります。$O(2^n \cdot n)$、それは不可能です。 

重要な洞察は、準備時間は予算の問題として扱うことができるということです。最大でも使用して倒せる対戦相手の数を最大化したいと考えます。$m$分。 Since winning a match gives one extra win, the optimal strategy is to beat the opponents who require the least preparation time. Sorting$a_i$そして、最も簡単な相手に貪欲に準備することで、効率的に勝利を最大化することができます。 勝利できる試合の数がわかったら、ランクの計算は、自分よりも多くの参加者を破った対戦相手をカウントすることになります。これは、インデックスに基づく単純な算術で実行できます。 

貪欲な戦略が機能するのは、対戦相手が勝つための厳格な命令に従うためです。$i$インデックスが以下のすべての対戦相手に勝つ$i$。 Therefore, for any number of wins$k$達成すると、すべての試合をシミュレーションしなくても、自分よりも多くの参加者に勝つ対戦相手の数が予測可能になります。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 テスト ケースごとに、次の内容を読んでください。$n$、$m$、および配列$a$準備時間のこと。 
2. 並べ替え$a$in ascending order. This ensures we prioritize opponents who are easiest to beat.
 3. 2 つの変数を初期化します。`total_prep = 0`使用された準備時間を追跡し、`wins = 0`勝てる試合をカウントします。 
4. ソートされた配列を反復処理します。`a`。 相手の準備時間ごとに`x`、どうかを確認してください`total_prep + x <= m`。 「はい」の場合、増分します`wins`そして追加します`x`に`total_prep`。 それ以外の場合は、反復を停止します。残りの対戦相手には費やすことができる以上の時間が必要であり、対戦相手を追加すると超過してしまうためです。`m`。 
5. ループの後、ランクを計算します。 それぞれの対戦相手$i$弱い相手をすべて倒します。 相手が正確に勝つ`i-1`他の対戦相手。 厳密に自分より多くの勝利を収めている対戦相手が何人いるかを確認するには、インデックス ≥ 勝利 + 1 を持つ各対戦相手が自分より多くの勝利を収めていることを観察します。 したがって、より多くの勝利を収めている対戦相手の数は、`n - wins`。 あなたの場所は`(number of opponents with more wins) + 1 = n - wins + 1`。 
6. テスト ケースの場所を印刷します。 

機能する理由: 並べ替えにより、準備時間の制約の下で可能な最大の勝利数が常に選択されます。 より多くの勝利を収めた対戦相手をカウントするには、対戦相手の勝利の厳密な順序特性を使用します。 これより多くの勝利をもたらす構成はないため、計算される場所は最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()
    
    total_prep = 0
    wins = 0
    for x in a:
        if total_prep + x <= m:
            total_prep += x
            wins += 1
        else:
            break
    
    place = n - wins + 1
    print(place)
```コードはまず準備時間を並べ替えて、より簡単な対戦相手を優先します。 予算まで準備を積み上げるループ`m`疲れ果てています。 順位の計算では、対戦相手の単調な勝利特性を活用します。インデックスが高いほど、より多くの対戦相手に勝利します。 利用可能な準備時間がゼロである、または対戦相手の所要時間がゼロであるなどのエッジ条件は、ループによって自然に処理されます。
