 ## 問題の理解

 整数のシーケンスが与えられ、タスクは 2 つの操作を実行してその合計を最大化することです。まず、シーケンスの任意の接頭辞を選択し、その中のすべての要素に -1 を掛けます。 2 番目に、シーケンスの任意の接尾辞を選択し、その中のすべての要素に -1 を掛けます。 どちらの操作もオプションであり、プレフィックスとサフィックスは重複する可能性があります。 出力は単一の整数、つまり達成可能な最大合計です。 

重要な制約は、シーケンスの要素数が 100,000 までであり、個々の要素の範囲が -10,000 ～ 10,000 であることです。 2 秒の時間制限により、ほぼ線形または線形対数時間で実行されるソリューションに制限されます。 考えられるプレフィックスとサフィックスのすべてのペアを試すなどの 2 次アプローチでは、次のオーダーが必要になります。$10^{10}$最悪の場合は操作が不可能になります。 

微妙なエッジ ケースには、シーケンス全体を反転することが最適な場合があるすべての負の数を持つシーケンスや、反転することが有益な場合とそうでない場合がある単一の要素を持つシーケンスが含まれます。 たとえば、入力`[-5]`出力する必要があります`5`、 その間`[3]`出力する必要があります`3`。 不注意なアプローチでは、プレフィックスとサフィックスが互いに素であると仮定したり、空のフリップを適切に処理できなかったりする可能性があります。 

## アプローチ

 ブルートフォース手法では、すべての可能なプレフィックスを反転してから、すべての可能なサフィックスを反転して、合計を計算し、最大値を追跡します。 具体的には、インデックスごとに$i$0から$n$、最初を反転します$i$要素、次に各インデックス$j$0から$n$、最後を反転します$j$要素。 各評価には合計が必要です$n$要素。 これにより、$O(n^3)$最悪の場合は複雑になります。 プレフィックスの合計を事前に計算して合計の計算を削減したとしても、$O(1)$、これでもまだ得られます$O(n^2)$が遅すぎる$n = 10^5$。 

線形解を可能にする重要な観察は、プレフィックスまたはサフィックスを反転することは、最初に反転してから反転した場合に、そのセグメントの合計の 2 倍を合計から減算することと同等であることに気づくことです。 より具体的には、数列の総和を次のようにします。$S$。 長さのプレフィックスを反転する$k$合計を変更します$-2 \times \text{sum of first k elements}$。 長さの接尾辞を反転する$l$合計を変更します$-2 \times \text{sum of last l elements}$。 したがって、合計を最大化するとは、反転される (2 回減算される) セグメントの合計が最小になるようにプレフィックスとサフィックスを選択することになります。 

これを効率的に実装するために、プレフィックスの合計とサフィックスの合計を事前計算できます。 最小プレフィックス合計と最小サフィックス合計を追跡し、次に、反転しない、プレフィックスのみを反転、サフィックスのみを反転、または両方を反転する組み合わせを検討します。 最適な合計は、これらの組み合わせの最大値になります。 プレフィックスの合計とサフィックスの合計は線形に計算され、結合ステップも線形であるため、全体的な複雑さは次のようになります。$O(n)$。

 ## アルゴリズムのチュートリアル

 1. シーケンスを読み取り、合計を計算します。$S$。 これは反転を行わない合計を表します。 
2. シーケンスのプレフィックスの合計を計算します。 インデックスごとに$i$、プレフィックスの合計は次のとおりです$i$0 から 0 までの要素の合計です。$i$。 繰り返しながら最小プレフィックス合計を追跡します。 これにより、後で反転する最も有益なプレフィックスを決定できるようになります。 
3. 同様に、末尾から先頭までのサフィックスの合計を計算し、最小のサフィックスの合計を追跡します。 これにより、反転するのに最も有益なサフィックスが得られます。 
4. セグメントを反転しないことを検討してください。 これは単純に次の結果をもたらします$S$。 
5. 合計が最小になるプレフィックスを反転することを検討します。 このプレフィックスを反転すると、合計が次のように変わります。$S - 2 \times (\text{minimum prefix sum})$。 
6. 合計が最小になるサフィックスを反転することを検討します。 この接尾辞を反転すると、合計が次のように変わります。$S - 2 \times (\text{minimum suffix sum})$。 
7. プレフィックスとサフィックスの両方を反転することを検討してください。 反転は重複する可能性があるため、最小プレフィックスと最小サフィックスの両方を反転するときに合計を計算し、二重の減算を避けるために重複を調整します。 
8. 答えは、これらのシナリオの中で最大のものです。 

機能する理由: セグメントを反転することは、その合計を 2 倍引くことと同じです。 演算は、正しく考慮される重複を除いて、線形で独立しています。 最小のプレフィックスとサフィックスの合計を事前に計算することにより、より適切な組み合わせを見逃すことなく、その選択によりグローバルに合計が最大化されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

total = sum(a)

# Compute minimum prefix sum
prefix_sum = 0
min_prefix = 0
for x in a:
    prefix_sum += x
    min_prefix = min(min_prefix, prefix_sum)

# Compute minimum suffix sum
suffix_sum = 0
min_suffix = 0
for x in reversed(a):
    suffix_sum += x
    min_suffix = min(min_suffix, suffix_sum)

# Maximum sum options
max_sum = total
max_sum = max(max_sum, total - 2 * min_prefix)
max_sum = max(max_sum, total - 2 * min_suffix)
max_sum = max(max_sum, total - 2 * (min_prefix + min_suffix))

print(max_sum)
```このソリューションでは、まずベースラインとして合計を計算します。 プレフィックス合計ループは、実行中の合計を追跡し、空のプレフィックスを反転しても変化が生じない場合を処理して、最小プレフィックス合計を更新します。 サフィックス合計ループは、同じことを逆に行います。 すべての反転オプションの最大値が最終的な答えになります。 空の反転はゼロ減算に対応するため、すべての負の数値や単一の要素などのエッジ ケースは自然に処理されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    total = sum(a)
    prefix_sum = 0
    min_prefix = 0
    for x in a:
        prefix_sum += x
        min_prefix = min(min_prefix, prefix_sum)
    suffix_sum = 0
    min_suffix = 0
    for x in reversed(a):
        suffix_sum += x
        min_suffix = min(min_suffix, suffix_sum)
    max_sum = total

    max_sum = max(max_sum, total - 2 * min_suffix)
    max_sum = max(max_sum, total - 2 * (min_prefix + min_suffix))
    return str(max_sum)
