 ## 解決策
 ## 問題の理解

 私たちは、いくつかのコントロールポイントと円形のフェンスを含むベルランドの地図を与えられました。 各ナイトはコントロール ポイントを占有します。 王国は柵によって地域ごとに区切られており、騎士はコントロールポイント間を移動するために柵を越えなければなりません。 複数のクエリの場合、ナイトがあるコントロール ポイントから別のコントロール ポイントに移動するために越えなければならないフェンスの最小数を決定する必要があります。 

入力により、コントロール ポイントの座標と各フェンスの位置と半径が提供されます。 クエリは制御点のペアです。 出力は各クエリの単に整数であり、越えたフェンスの数を表します。 

主な制約は、コントロール ポイントとフェンスは最大 1000 個まで可能ですが、クエリは最大 100,000 個までであることです。 各クエリのフェンス横断を個別に計算する単純なアプローチでは、1000 × 100,000 = 1 億回の操作が必要になる可能性があり、これでは遅すぎます。 これは、前処理後のクエリごとの計算は最大でも O(1) または O(log n) である必要があることを示唆しています。 

エッジ ケースには、コントロール ポイントが同じ領域内にある (交差するフェンスがゼロ)、1 つのポイントがフェンスの内側にあり、もう 1 つのポイントがフェンスの外側にある、および複数のネストされたフェンスが存在する状況が含まれます。 不注意な実装では、包含階層を考慮せずに距離だけをチェックすると、フェンスが誤ってカウントされる可能性があります。 たとえば、コントロール ポイントが小さな円の内側にあり、別のポイントがその円の外側で大きな円の内側にある場合、越えたフェンスの数は単なる距離の差ではありません。 それは、実際に各ポイントがどのフェンスに含まれるかによって異なります。 

## アプローチ

 ブルート フォース ソリューションでは、クエリごとにすべてのフェンスを反復処理します。 指定されたクエリ (a、b) に対して、各フェンスについて、ポイント a がフェンスの内側にあるかどうか、およびポイント b がフェンスの内側にあるかどうかをチェックします。 2 つのポイントのうち 1 つが内側にある場合は、そのフェンスを越えなければなりません。 これは正しいです。点がフェンスの反対側にある場合にのみ、フェンスを越えることができるからです。 これは機能しますが、1,000 のフェンスと 100,000 のクエリの場合、O(k * m) = 1 億の操作となり、遅すぎます。 

重要な点は、クエリごとにフェンスを処理する必要がないということです。 各コントロール ポイントについて、どのフェンスにそのコントロール ポイントが含まれているかを表す「フェンス シグネチャ」を事前計算できます。 これが完了すると、クエリに答えることは、2 つの署名間で異なるフェンスの数を計算することになり、これは単純にセットの差をカウントすることになります。 これにより、ビットマスクまたは単純な配列を使用して、クエリごとの作業が O(m) から O(1) に変換されます。 

さらに、問題は、2 つの点のうちの 1 つを正確に含むフェンスの数を数えるということになります。 これは、各点を含むフェンスのセットの対称的な差に相当します。 これにより、クエリごとではなくコントロール ポイントごとにフェンスを前処理できるため、これは重要な簡素化です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k * m) | お(1) | 遅すぎる |
 | ポイントごとのフェンスを事前計算する | O(n * m + k) | O(n * m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を読み取ります: コントロール ポイント、フェンス、クエリ。 点の座標とフェンスの中心/半径を保存します。 
2. 各コントロール ポイントについて、どのフェンスにそのコントロール ポイントが含まれているかを決定します。 (x - cx)² + (y - cy)² < r² の場合、点 (x, y) は中心 (cx, cy) と半径 r の円の内側にあります。 これをポイントごとのリストまたはビットマスクとして保存します。 
3. 各クエリ (a、b) について、2 つのポイントのうちの 1 つを正確に含むフェンスの数を計算します。 フェンスを反復処理し、ポイント a と b の間で封じ込めが異なるフェンスをカウントします。 
4. 各クエリのカウントを出力します。

これが機能する理由: 騎士が柵の内側から外側へ、またはその逆に移動しなければならない場合、柵を越える必要があります。 各ポイントがどのフェンスに含まれるかを事前に計算することにより、対称的な差分により、通過する必要があるフェンスが正確にカウントされます。 各フェンスの封じ込めを個別にチェックするため、フェンスが二重にカウントされることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())
points = [tuple(map(int, input().split())) for _ in range(n)]
fences = [tuple(map(int, input().split())) for _ in range(m)]

# Precompute which fences contain each point
contain = [[False] * m for _ in range(n)]
for i, (px, py) in enumerate(points):
    for j, (r, cx, cy) in enumerate(fences):
        if (px - cx)**2 + (py - cy)**2 < r**2:
            contain[i][j] = True

# Process queries
for _ in range(k):
    a, b = map(int, input().split())
    a -= 1
    b -= 1
    count = 0
    for j in range(m):
        if contain[a][j] != contain[b][j]:
            count += 1
    print(count)
```各コントロール ポイントは、すべてのフェンスに対して 1 回処理されます。 包含チェックでは二乗距離を使用して浮動小数点エラーを回避します。 クエリ ループでは、フェンスの対称的な差が効率的に計算されます。 微妙な点は、クエリの 1 ベースから 0 ベースのインデックス変換です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n_m + k_m) | n ポイント × m フェンスを事前計算し、次に k クエリ × m フェンスを事前計算します。 |
 | スペース | O(n*m) | 格納テーブルを保管します。 |

 n、m ≤ 1000、k ≤ 100,000 の場合、ワーストケースの演算はおよそ 1000_1000 + 100,000_1000 ≈ 1 億となり、Python では単純な演算で許容されます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    # solution call
    n, m, k = map(int, input().split())
    points = [tuple(map(int, input().split())) for _ in range(n)]
    fences = [tuple(map(int, input().split())) for _ in range(m)]
    contain = [[False]*m for _ in range(n)]
    for i, (px, py) in enumerate(points):
        for j, (r, cx, cy) in enumerate(fences):
            if (px - cx)**2 + (py - cy)**2 < r**2:
                contain[i][j] = True
    for _ in range(k):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        count = sum(contain[a][j] != contain[b][j] for j in range(m))
        print(count)
    return out.getvalue().strip()

# provided sample
assert run("2 1 1\n0 0\n3 3\n2 0 0\n1 2\n") == "1"

# minimum input
assert run("1 0 1\n0 0\n1 1\n") == "0"

# all points inside one fence
assert run("2 1 1\n0 0\n1 1\n2 0 0\n1 2\n") == "0"

# nested fences
assert run("2 2 1\n0 0\n3 3\n2 0 0\n5 0 0\n1 2\n") == "1"

# multiple queries
assert run("3 2 2\n0 0\n5 0\n0 5\n3 0 0\n4 4 4\n1 2\n2 3\n") == "1\n0"
