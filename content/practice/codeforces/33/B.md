 ## 解決策
 ## 問題の理解

 同じ長さの小文字文字列が 2 つ与えられています。 有向変換ルールを使用して文字を繰り返し変換する場合があります。 のようなルール`a -> b`費用がかかる`5`の 1 つの出現を変更できることを意味します`a`の中へ`b`支払うことで`5`。 

目標は、ある文字列全体を別の文字列全体に直接変換することではありません。 代わりに、すべてのポジションについて、その方が安価であれば、両方のキャラクターを 3 番目のキャラクターに変更することもできます。 すべての変換の後、結果として得られる 2 つの文字列は同一になる必要があり、総コストを最小限に抑えたいと考えています。 

重要な観察は、すべてのポジションが独立しているということです。 ある位置に文字がある場合`x`そして`y`、両方が最終的にどのキャラクターになるかを決定する必要があるだけです。 合計の答えは、すべてのポジションにわたる最適コストの合計です。 

文字列の長さは次のとおりです。`10^5`つまり、位置ごとのアルゴリズムは非常に小さく、理想的には一定時間でなければなりません。 アルファベットには英小文字のみが含まれているため、`26`可能な文字。 それは問題の形を完全に変えます。 文字列は巨大ですが、変換グラフは小さいです。 

変換ルールの数は最大で`500`。 直接変換は、連鎖ルールの方がコストが安くなる可能性があるため、最適ではない可能性があります。 例えば：```
a -> b : 10
a -> c : 2
c -> b : 2
```からの最も安い方法`a`に`b`実際にコストがかかる`4`。 

これにより、グラフ上の最短経路が即座に提案されます。`26`ノード。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

重要なケースの 1 つは、共通のターゲット キャラクターが存在しない場合です。 

例：```
ab
cd
1
a c 5
```作る方法はない`b`そして`d`何でも等しいので、正しい答えは次のようになります。```
-1
```直接変換のみをチェックする不用意な解決策では、一部の位置で不可能な部分を見逃してしまう可能性があります。 

もう 1 つの微妙なケースは、両方の文字を 3 番目の文字に変換する方が、一方をもう一方に変換するよりもコストがかからない場合です。 

例：```
ab
bc
4
a d 1
b d 1
b c 100
```2 番目のポジションでコンバート`b`の中へ`c`費用`100`、しかし両方ともなることができます`d`総コストに対して`2`。 結果として得られる最適な文字列は、必ずしも元の文字列の 1 つであるとは限りません。 

ルールの繰り返しは別の罠です。 

例：```
a
b
2
a b 10
a b 3
```グラフは最小エッジコストを維持する必要があります。そうしないと、誤って使用してしまいます。`10`の代わりに`3`。 

最後に、文字がすでに一致している場合もあります。 グラフ内にサイクルが存在する場合でも、これらの位置はコストに寄与しないはずです。 

例：```
aaa
aaa
1
a b 5
```答えはまだゼロです。 

## アプローチ

 ブルートフォースアプローチでは、すべての位置を個別に扱い、考えられるすべての変換シーケンスを試みます。 ペアのキャラクターの場合`(x, y)`からすべてのパスを検索できます。`x`そして`y`他のすべてのキャラクターに。 変換は任意に連鎖する可能性があるため、これはすぐにグラフ検索の問題になります。 

単純な実装では、すべての位置およびすべての候補ターゲット文字に対してダイクストラまたは BFS を最初から実行します。 一定の長さの文字列で`10^5`、控えめでも`O(26^2)`位置ごとのグラフ計算が不必要に高価になります。 

問題の構造は、より強力な機会を与えます。 グラフには、`26`頂点。 つまり、文字の各ペア間の最も安いコストを 1 回事前計算し、一定時間で各文字列の位置を答えることができます。 

変換ルールは、有向重み付きグラフを形成します。```
character = node
transformation = directed edge
cost = edge weight
```すべての文字ペア間の最短経路距離がわかっている場合、位置について`(s[i], t[i])`、可能な最終文字をすべて試してみます。`c`。 

選択にかかる合計費用`c`は：```
dist[s[i]][c] + dist[t[i]][c]
```すべての中で最小限のものを選択します`26`選択肢。 

グラフが小さいため、ここでは Floyd-Warshall が最適です。 その複雑さは、`O(26^3)`、これは事実上一定です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n × 26 × グラフ検索) | O(26 + エッジ) | 遅すぎる/不必要 |
 | 最適 | O(26^3 + 26 × n) | O(26^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.`26 × 26`距離行列は無限大に初期化されます。`dist[i][j]`キャラクターを変身させるための最小コストを表します`i`性格に`j`。 
2.セット`dist[i][i] = 0`キャラクターごとに。 

キャラクターは常にゼロコストで変更されないままにすることができます。 
3. すべての変換ルールを読む`(a, b, w)`そして更新します:```
dist[a][b] = min(dist[a][b], w)
```同じペア間に複数のルールが存在する可能性があるため、最も安価な直接エッジのみを保持します。 
4. 上で Floyd-Warshall を実行します。`26`文字。 

すべての中間文字について`k`、すべてのペアを改善してみてください`(i, j)`使用:```
dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
```これにより、可能な限り安価な連鎖変換が計算されます。 
5. 2 つの文字列の長さが異なる場合は、次のように出力します。`-1`。 

すべての操作では文字のみが変更され、文字列の長さは変更されません。 
6. 文字列を位置ごとに処理します。 

現在の文字が`x`そして`y`。 
7. 可能な最後の文字をすべて試してみる`c`から`'a'`に`'z'`。 

計算:```
dist[x][c] + dist[y][c]
```キャラクターを最小限の総コストで維持します。 
8. ある位置に有効な文字が存在しない場合は、次のように出力します。`-1`。 

つまり、両側から到達できるキャラクターは存在しません。 
9. それ以外の場合は、選択した文字を応答文字列に追加し、そのコストを合計に追加します。 
10. すべてのポジションを処理した後、合計コストと結果の文字列を出力します。 

### なぜ効果があるのか

 Floyd-Warshall は、前処理後に次のことを保証します。`dist[a][b]`変換に必要な最小コストに等しい`a`の中へ`b`任意の一連のルールを使用します。 

文字列の各位置において、最後の文字は他のすべての位置から独立しています。 有効な解決策では、ターゲット キャラクターを選択する必要があります`c`そのポジションのために。 その選択を実現する最も安価な方法は、まさに次のとおりです。```
dist[s[i]][c] + dist[t[i]][c]
```アルゴリズムがすべてをチェックするため、`26`可能なターゲット文字を選択し、最小値を選択すると、その位置に対して全体的に最適な選択肢が見つかります。 すべてのポジションにわたるこれらの独立した最適コストを合計すると、最小の総コストが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    s = input().strip()
    t = input().strip()

    if len(s) != len(t):
        print(-1)
        return

    n = int(input())

    dist = [[INF] * 26 for _ in range(26)]

    for i in range(26):
        dist[i][i] = 0

    for _ in range(n):
        a, b, w = input().split()
        w = int(w)

        u = ord(a) - ord('a')
        v = ord(b) - ord('a')

        dist[u][v] = min(dist[u][v], w)

    for k in range(26):
        for i in range(26):
            for j in range(26):
                if dist[i][k] == INF or dist[k][j] == INF:
                    continue

                nd = dist[i][k] + dist[k][j]

                if nd < dist[i][j]:
                    dist[i][j] = nd

    total_cost = 0
    result = []

    for cs, ct in zip(s, t):
        u = ord(cs) - ord('a')
        v = ord(ct) - ord('a')

        best_cost = INF
        best_char = ''

        for c in range(26):
            if dist[u][c] == INF or dist[v][c] == INF:
                continue

            cur = dist[u][c] + dist[v][c]

            if cur < best_cost:
                best_cost = cur
                best_char = chr(c + ord('a'))

        if best_cost == INF:
            print(-1)
            return

        total_cost += best_cost
        result.append(best_char)

    print(total_cost)
    print(''.join(result))

solve()
```最初のセクションではグラフを構築します。 ほとんどの変換は最初は不可能であるため、行列は無限から始まります。 対角線をゼロに設定することは必須です。そうでないと、同一の文字に誤って変換が必要になります。 

エッジを読み取るとき、コードは次を使用します。`min()`入力に重複したルールが含まれている可能性があるためです。 この詳細を怠ると、誤った最短パスが暗黙のうちに生成されます。 

グラフ サイズが次のように固定されているため、フロイド-ウォーシャル フェーズは非常に小さくなります。`26`。 に対するチェック`INF`無限大と数字のような無意味な追加は避けてください。 

最後のループは位置を独立して処理します。 文字のペアごとに、コードはすべての文字を試行します。`26`会う可能性のあるキャラクターを選択し、到達可能な最も安価なキャラクターを選択します。 

実装の微妙な点は、結果として得られる文字が元の文字と同じである必要がないことです。 アルゴリズムはアルファベット全体を検索するため、これを自然に処理します。 

もう 1 つの重要な詳細は、`10**18`無限のために。 実際のコストは小さくても、非常に大きな整数を使用すると、距離を追加するときにオーバーフロー形式のロジック エラーが発生するのを防ぐことができます。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(26^3 + 26 × n) | 26 文字のフロイド-ウォーシャル、文字列位置ごとに 26 チェック |

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

INF = 10**18

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    s = input().strip()
    t = input().strip()

    if len(s) != len(t):
        return "-1"

    n = int(input())

    dist = [[INF] * 26 for _ in range(26)]

    for i in range(26):
        dist[i][i] = 0

    for _ in range(n):
        a, b, w = input().split()
        w = int(w)

        u = ord(a) - ord('a')
        v = ord(b) - ord('a')

        dist[u][v] = min(dist[u][v], w)

    for k in range(26):
        for i in range(26):
            for j in range(26):
                if dist[i][k] == INF or dist[k][j] == INF:
                    continue

                dist[i][j] = min(
                    dist[i][j],
                    dist[i][k] + dist[k][j]
                )

    total = 0
    ans = []

    for a, b in zip(s, t):
        u = ord(a) - ord('a')
        v = ord(b) - ord('a')

        best = INF
        ch = ''

        for c in range(26):
            if dist[u][c] == INF or dist[v][c] == INF:
                continue

            cur = dist[u][c] + dist[v][c]

            if cur < best:
                best = cur
                ch = chr(c + ord('a'))

        if best == INF:
            return "-1"

        total += best
        ans.append(ch)

    return f"{total}\n{''.join(ans)}"
