 ## 解決策
 ## 問題の理解

 各歯は正確に 1 つの列に属します。 ヴァレリーが列を使用してフナを 1 匹食べると、その列のすべての歯が 1 単位の生存能力を失います。 列内の少なくとも 1 つの歯がゼロ以下になると、その列は使用できなくなります。 

単一列の場合、制限要因はその列で最も弱い歯です。 列に生存可能な歯が含まれている場合`[5, 8, 3]`、その場合、その列は 3 回しか使用できません。4 回目以降は生存可能な歯が使用されるためです。`3`マイナスになってしまいます。 

課題は、歯を決してマイナスにせずに、ヴァレリーが合計で食べることができるフナの最大数を計算することです。 彼女は異なるフナに対して異なる行を選択することができ、各フナはちょうど 1 つの行を使用します。 

入力はすべての歯を個別に与えます。 各歯について、その列インデックスと残りの生存可能性がわかります。 出力は 1 つの整数で、彼女が食べられるフナの最大数ですが、利用可能な部分のサイズを超えてはなりません。`k`。 

制約は十分に小さいため、ほとんどすべての線形または二次解法が快適に機能します。 歯は最大でも 1000 本あります。`O(n^2)`ソリューションは約 100 万回の操作を実行しますが、これは 2 秒の制限内ではわずかです。 これは、課題は最適化ではなく、各行がどの量に寄与しているかを正確に特定することであることを意味します。 

最も簡単な間違いは、列がその歯の生存能力の合計に寄与すると考えることです。 選択した列のすべての歯が一緒に減少するため、これは誤りです。 

次の入力を考えてみましょう。```
3 1 100
1 5
1 2
1 8
```1行しかありません。 2回使用すると2本目の歯がゼロになります。 もう1回使用するとマイナスになります。 正しい答えは次のとおりです。```
2
```不用意に行を合計すると、誤った出力が行われてしまいます。`15`。 

もう 1 つの微妙なケースは、一部の歯がすでに生存能力を持っていない場合です。```
2 2 10
1 0
2 7
```1行目は一度も使用できません。 列 2 は 7 回使用できます。 答えは次のとおりです。```
7
```実装が誤って 0 を 1 回使用可能なものとして扱うと、次のように出力されます。`8`。 

可能性のある食事の合計が利用可能な部分サイズを超える場合、もう 1 つの特殊なケースが発生します。`k`。```
2 2 3
1 10
2 10
```両方の列を合わせると 20 食が可能ですが、フナは 3 匹だけです。 正しい答えは次のとおりです。```
3
```最終的な答えは常に次で終わる必要があります`k`。 

## アプローチ

 総当たりのシミュレーションは容易に想像できます。 すべてのステップで、もう 1 回使用してもすべての歯の生存率がマイナスでない行を選択し、その行のすべての歯を減分し、すべての行が使用できなくなるか、その部分が終了するまでに何食食べたかを数えます。 

プロセスがステートメントに正確に従うため、これは機能します。 問題は、私たちがフナを食べるたびに多くの歯を繰り返し改造していることです。 歯の生存可能性は次のように大きくなる可能性があるため、`10^6`、模擬食事の数も達することができます`10^6`。 最悪の場合、行を繰り返しスキャンして歯を更新すると、不必要にコストがかかります。 

重要な観察は、食べる順序は重要ではないということです。 行は完全に独立しています。 1 つの列を 5 回使用でき、別の列を 7 回使用できる場合、それらを合わせると、正確に 12 回の食事が可能になります。 

固定列の場合、使用可能な数はその歯の最小生存率に等しくなります。 使用するたびにすべての歯が一緒に減少するため、最も弱い歯がいつ列が壊れるかを決定します。 

これにより、問題全体が次のように簡略化されます。 

1. 各行の最小生存率を見つけます。 
2. これらの最小値を合計します。 
3. 結果の上限を次のとおりにします`k`。 

この観察が現れると、実装は非常に小さくなります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k · n) | O(n) | 概念的には遅すぎる |
 | 最適 | O(n + m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`mn`サイズの`m`、非常に大きな値で初期化されます。`mn[i]`最小の歯の生存率を行内に保存します`i`。 
2. 各歯の説明を読みます。 

すべての歯は 1 つの列に属し、生存可能性の値を持ちます。 
3. その行の最小値を更新します。 

歯の生存能力が現在保存されている最小値よりも小さい場合は、交換します。 

これが機能するのは、最も弱い歯によって列全体が何回使用されるかが決まるためです。 
4. すべての歯を処理した後、すべての行の最小値を合計します。 

各行は、総食事数に対する最小生存率を正確に反映します。 
5. 出力`min(total, k)`。 

ヴァレリーは実際に含まれる量より多くのフナを食べることはできません。 

### なぜ効果があるのか

 どの列でも、使用するたびに、その列のすべての歯がちょうど 1 つずつ減ります。 後`t`初期生存能力のある歯を使用します。`c`になる`c - t`。 すべての歯を陰性でない状態に保つためには、次のことが必要です。`c - t >= 0`列のすべての歯に対して。 

つまり:```
t <= minimum viability in the row
```したがって、列は最も弱い歯が許す限り何回でも使用できます。 ある列で食事をしても別の列の歯が変わることはないので、列は互いに干渉しません。 これらの独立した容量を合計すると、最大総食事数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())

INF = 10**18
mn = [INF] * m

for _ in range(n):
    r, c = map(int, input().split())
    r -= 1
    mn[r] = min(mn[r], c)

answer = min(sum(mn), k)

print(answer)
```配列`mn`すべての行の最小実行可能性を格納します。 入力では行に 1 から番号が付けられているため、コードは配列にアクセスする前に行を 0 から始まるインデックスに変換します。 

大きな初期値を使用すると、行で最初に確認された歯が現在の最小値になることが保証されます。 このステートメントは、すべての行に少なくとも 1 つの歯が含まれることを保証するため、初期化されていない行は存在しません。 

行:```
mn[r] = min(mn[r], c)
```ソリューションの核心です。 各列の最も弱い歯を継続的に追跡します。 

すべての歯を加工した後、`sum(mn)`理論的に可能な食事の総数に等しい。 決勝戦`min(..., k)`利用可能なフナよりも多くの容量が存在する場合に対処します。 

Python の整数は、可能な最大合計が最大で以下であるため、ここではすべての値を安全に処理します。`1000 * 10^6 = 10^9`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + m) | すべての歯を 1 回パスし、行を 1 回合計します。 
| スペース | O(m) | 行ごとに 1 つの最小値を格納します。 

最大 1000 個の歯と列を使用するこのソリューションは非常に高速です。 メモリ使用量はわずかであり、実行時間は指定された制限内で実質的に瞬時になります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, m, k = map(int, input().split())

    INF = 10**18
    mn = [INF] * m

    for _ in range(n):
        r, c = map(int, input().split())
        r -= 1
        mn[r] = min(mn[r], c)

    print(min(sum(mn), k))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run(
"""4 3 18
2 3
1 2
3 6
2 3
"""
) == "11\n", "sample 1"

# minimum-size input
assert run(
"""1 1 0
1 5
"""
) == "0\n", "k is zero"

# single row, weakest tooth limits everything
assert run(
"""3 1 100
1 5
1 2
1 8
"""
) == "2\n", "minimum tooth determines row capacity"

# all rows equal
assert run(
"""4 2 10
1 4
1 4
2 4
2 4
"""
) == "8\n", "equal minima across rows"

# cap by k
assert run(
"""2 2 3
1 10
2 10
"""
) == "3\n", "answer cannot exceed available crucians"

# row with zero viability
assert run(
"""3 2 10
1 0
1 5
2 7
"""
) == "7\n", "row with zero minimum unusable"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 一本の歯、`k = 0`|`0`| 部分制限が支配的 |
 | 実行可能性のある 1 行`5,2,8`|`2`| 最小生存率コントロール行 |
 | どこでも平等な生存率 |`8`| 行全体にわたる通常の累積 |

```最小値は次のようになります。```

```合計は`7`、したがって、答えは次のようになります。```

```行の最小値の合計は次のようになります。```
10 + 10 = 20
```しかし、フナは3人しか存在しません。 アルゴリズムは次のように適用されます。```
min(20, 3) = 3
```そして出力:```
3
```この最後のキャップは、歯がより多くの食事に対応できる場合でも必要です。
