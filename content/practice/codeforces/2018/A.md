 ## 解決策
 ## 問題の理解

 複数の独立したシナリオが与えられます。 それぞれのカードでは、各整数値が以下のカードのマルチセットから始まります。$1$に$n$一定回数出現します。 まで追加することが許可されています$k$私たちが選択した任意の値の追加カード。 その後、すべてのグループが同じサイズになり、どのグループにも同じ値の 2 枚のカードが含まれないように、すべてのカードをいくつかのグループに分割する必要があります。 

目標は、どのカードを購入するか、すべてを分割する方法を最適に決定した後、各グループのサイズを最大化することです。 

制約$n \le 2 \cdot 10^5$すべてのテスト ケースにわたって、非常に大規模な$k$まで$10^{16}$パーティションをシミュレートしたり、グループを明示的に構築しようとするソリューションは除外されます。 出力はグローバル周波数構造のみに依存するため、解決策では問題を回答候補ごとの少数の数値チェックに減らす必要があります。 

多くの値のカウントがゼロまたは非常に小さい場合、微妙なエッジ ケースが発生します。 たとえば、すべてが$a_i = 0$1 つの値を除いて、購入がなければ、次のサイズを超える有効なグループを形成することはできません。$1$。 A naive greedy approach that tries to “fill missing types locally” breaks here because global consistency of group size is the real constraint, not local availability.

 もう一つの失敗例は次のような場合です。$k$非常に大きいです。 すべての頻度を常に等しくできるため、グループサイズを達成できると仮定したくなります。$n$ただし、各追加カードは総容量を増やすだけであり、「各グループごとに値ごとに最大 1 つ」という制限により、グループごとに使用できる各値のコピー数が依然として制限されます。 

## アプローチ

 直接的な総当たりアプローチでは、考えられるすべての最終的なグループ サイズが試行されます。$L$。 固定の場合$L$、カードを同じサイズのグループに分配できるかどうかを決定しようとします。$L$おそらくカードを購入した後、各値がグループごとに最大 1 回表示されるようにします。 これには、形成できるグループの数と、購入が複数の価値観にどのように配分されるかについて推論する必要があります。 一つ一つチェックしても$L$赤字がどのように分散されるかをシミュレーションし、すべてを反復する必要があります。$L$カードの総数に達すると、これは完全に不可能になります。 

重要な観察は、有効なパーティションの構造は、候補グループのサイズに対する各値のカウントにのみ依存するということです。$L$。 固定の場合$L$、各値は最大で寄与します$\lfloor a_i / L \rfloor$グループ全体にわたる完全な「垂直列」があり、残りの残りは、有効なグループ化制約を完了するために購入する必要がある追加カードの枚数を制御します。 実現可能条件は単調になる$L$、二分探索が可能になります。 

修正したら$L$、すでに形成できる完全なグループの数と、すべてのグループが重複を避けるために必要な追加のカードの数を計算します。 必要購入枚数以​​下の場合$k$、 それから$L$実現可能です。 

これにより、問題は単調な実現可能性チェックに変換されます。$L$。

 ## アルゴリズムのチュートリアル

 答えを二分探索します$L$、各デッキのターゲットサイズ。 

固定の場合$L$を使用して、各値がデッキ全体でどれだけのスロットに貢献できるかをシミュレートします。$a_i \bmod L$購入による補償が必要となる残りの容量として。 

これらの残りを集計して、「デッキごとに重複禁止」の制約に違反することなくすべてのデッキを埋めることができるように、追加で必要なカードの枚数を決定します。 必要な購入数を超えてはなりません$k$。 

手順は次のとおりです。 

1. 検索範囲を設定します。$L$から$1$に$\sum a_i + k$。 
2.候補者にとって$L$、各剰余クラスをサイズの完全なグループにパックできるように、効果的に追加する必要があるカードの数を計算します。$L$。 
3. 各値について$a_i$、計算する$a_i \bmod L$そして残りの需要の合計を蓄積します。 
4. この残りの需要を必要な購入済みカードに変換します。 
5. 必要に応じて購入する$\le k$、値$L$実現可能です。 
6. 実現可能な最大限の二分探索$L$。 

重要な点は、各値が独立して実現可能性に寄与し、相互作用は総容量の制約によってのみ発生するため、チェックが追加的になるということです。 

### なぜ効果があるのか

 固定グループサイズの場合$L$、各値は、グループごとに最大 1 つのスロットを埋めることができるリソースのように動作します。 残り$a_i \bmod L$その値のコピーが「欠落している」グループの数を測定します。 不足しているコピーは購入したカードで補う必要があります。 購入はあらゆる価値に制限がないため、問題となるのは赤字総額のみです。 これにより、実現可能性が 1 つの不等式に減り、述語が単調になります。$L$、二分探索の正確さを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(L, a, k):
    need = 0
    for x in a:
        need += x % L
        if need > k:
            return False
    return need <= k

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        lo, hi = 1, sum(a) + k
        ans = 1

        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, a, k):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、実現可能性のチェックを検索から分離します。 機能`can(L, a, k)`デッキサイズを強制する場合に必要な追加カードの総数を計算します`L`。 要件を超える場合は早期停止が使用されます`k`、不必要なオーバーフローを防ぎ、チェックを直線的に保ちます。 

二分探索では、すべての値が次の値に達するという不変条件が維持されます。`ans`は実現可能ですが、現在の上限を超えるものはすべて実現不可能です。 中間点の評価ごとに、この間隔が調整されます。 

よくある実装の間違いは、実現可能性が生のカウントではなく剰余に依存することを忘れていることです。 もう 1 つは、モジュロの代わりにフロア除算を使用することです。 これにより、欠落しているグループごとのスロットの解釈が崩れます。

 ## 特殊なケース

 いつすべて$a_i$1 つの値を除いてゼロの場合、実現可能性チェックは単一の係数式によって支配され、二分探索は引き続き正しく収束します。$L$剰余がゼロになるまで減算します。 これにより過大評価を防ぐことができます。 

いつ$k=0$、購入は許可されていないため、解決策は、マルチセット構造を自然に分割する最適なグループ サイズを見つけることになります。 実現可能性チェックが厳密になり、自然な割り算パターンのみが合格するため、アルゴリズムがこれを処理します。 

1 つの値が他の値と比較して極端に大きい場合、剰余項により不均衡に比例してペナルティが課され、グループ サイズの不正確な膨張が防止されます。
