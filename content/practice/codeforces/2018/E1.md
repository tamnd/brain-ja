 ## 解決策
 ## 問題の理解

 数直線上の閉じたセグメントの集合が与えられ、それぞれが左右の端点によって定義されます。 目標は、「複雑な」セットを形成するこれらのセグメントの可能な最大のサブセットを特定することです。 複雑なセットは、セグメントが同じグループに属している場合にのみ交差するように、同じサイズのグループに分割できます。 言い換えれば、異なるグループの 2 つのセグメントは互いに素である必要がありますが、1 つのグループ内のすべてのセグメントは相互に交差している必要があります。 この問題では、複数のテスト ケースについて、そのような複雑なサブセットの最大サイズを求めます。 

制約を考慮すると、1 つのテスト ケースのセグメント数は 20,000 に達する可能性があり、すべてのテスト ケースの合計も 20,000 未満にとどまります。 これは、テスト ケースあたり O(n log n) より悪い解は制限時間を超える可能性があることを示しています。 2^20,000 は天文学的に大きいため、すべてのサブセットを試みる単純な強引なアプローチは明らかに実行不可能です。 

明らかではないエッジ ケースには、ネストされたセグメントや同一のセグメントが含まれます。 たとえば、セグメント`[1, 5]`、`[2, 3]`、`[4, 6]`サブセットには以下を含めることができないため、単純な交差カウントのアプローチを混乱させる可能性があります。`[2, 3]`両方とも`[1, 5]`そして`[4, 6]`相互交差特性に違反することなく同時に。 もう 1 つの注意が必要なシナリオは、セグメントが完全に切り離されている場合に発生します。`[1, 2]`、`[3, 4]`、`[5, 6]`。 ここで、複素サブセットの最大サイズはわずか 1 であり、順序のみに基づいて間隔をマージする不用意なアルゴリズムは過大評価してしまいます。 

## アプローチ

 ブルート フォース アプローチでは、セグメントの考えられるすべての分割が考慮され、各サブセットの交差プロパティがチェックされます。 サイズ k の各サブセットについて、グループ内ですべてのペアが交差すること、および異なるグループのペアが交差しないことを検証する必要があります。 これには O(n selected k * k^2) の操作が必要ですが、n = 20 の場合でも管理できなくなります。このアプローチは原理的には正しいですが、まったく実用的ではありません。 

最適化するための重要な洞察は、問題を区間グラフの問題として認識することです。 各セグメントはグラフ内の頂点として扱うことができ、エッジは交差するセグメントを接続します。 複雑なサブセットは、各連結コンポーネントが同じサイズを持ち、隣接する 2 つのコンポーネントがない頂点のサブセットを選択することに対応します。 

簡単なバージョンでは、より直接的な観察で十分です。最大の複雑なサブセットのサイズは、非交差チェーンに編成できるセグメントの数によって決まります。 セグメントを左端点でソートし、重複するセグメントを貪欲に閉じようとすると、単一の接続コンポーネント内のセグメントの最大数を計算できます。 このプロセスでは、正しいエンドポイントに関しては最長増加サブシーケンスと同様の分割統治アプローチが使用されますが、間隔に適応されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^2) | O(n^2) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースについて、セグメント数 n と左右のエンドポイントを読み取ります。 それぞれの左側と対応する右側のエンドポイントをタプルとしてペアにします。`(l_i, r_i)`。 
2. セグメントを左の端点で並べ替えます。 並べ替えにより、セグメントを順番に移動するときに、後続の重複するセグメントが開始される前に各セグメントの開始に遭遇することが保証されます。 この順序により、交差点の検出が簡素化されます。 
3. 現在のグループ サイズのカウンターを初期化し、これまでに確認された最大の右エンドポイントを追跡します。 ソートされたセグメントを走査します。 各セグメントについて、その左端点が現在の最大右端点より大きいかどうかを確認します。 そうである場合、これは新しいグループの開始を示します。 それ以外の場合、セグメントは現在の重複グループに属し、最大右端点を更新します。 
4. 重複するセグメントの接続された各グループのサイズを記録します。 すべての接続コンポーネントにわたるこれらのグループ サイズの最大値が、現在のテスト ケースの答えを表します。 
5. 各テスト ケースの結果を出力します。 

このアルゴリズムが機能するのは、左端点による並べ替えにより、重複するすべてのセグメントが連続して検出されることが保証されるためです。 最大の右端点を維持することにより、新しい切り離されたセグメント グループが開始されるタイミングを正確に検出できます。これは、複雑なサブセットに必要な分割に直接対応します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_complex_subset(n, left, right):
    segments = sorted(zip(left, right))
    max_size = 0
    current_group_size = 0
    current_max_right = -1

    for l, r in segments:
        if l > current_max_right:
            current_group_size = 1
            current_max_right = r
        else:
            current_group_size += 1
            current_max_right = max(current_max_right, r)
        max_size = max(max_size, current_group_size)
    
    return max_size

t = int(input())
for _ in range(t):
    n = int(input())
    left = list(map(int, input().split()))
    right = list(map(int, input().split()))
    print(max_complex_subset(n, left, right))
```コードは、論理的な順序で処理されることを保証するために、最初にセグメントを左エンドポイントで並べ替えます。 繰り返しながら、現在の重複グループの最大の右端点を追跡します。 この正しいエンドポイントの後にセグメントが開始されると、前のグループが終了したことがわかります。 この手法により、ネストされたループが回避され、並べ替え後の単一の線形パスで最大の複雑なサブセットのサイズを計算できるようになります。

## 特殊なケース

 次のようなネストされたセグメントの場合`[1, 10], [2, 3], [4, 5]`、並べ替えにより、最大の正しいエンドポイントが正しく更新されることが保証されます。 アルゴリズムは、左端点が現在の最大右端点を超えると、新しいグループを開始します。 これにより、ネストが正しく処理され、最大の接続グループが出力されます。 互いに素なセグメントの場合、前のグループの右側の後にセグメントが開始されるたびに、アルゴリズムはグループ サイズをリセットし、最大サイズ 1 を正しく報告します。同一のセグメントは、左端が等しいためロジックを壊すことはなく、重複する同じグループ内で一緒にカウントされます。
