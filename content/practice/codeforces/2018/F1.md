 ## 解決策
 ## 問題の理解

 この問題では、長さの配列を数えるように求められます。$n$ここで各要素は$a_i$は 1 から までの正の整数です$n$そして、上限に違反することなく連続征服を可能にする開始都市の数に基づいてこれらの配列を分類します。$a_i$。 都市を一列に並んだタイルとして想像してください。 時間 1 で、占有するタイルを 1 つ選択します。 後続のタイム ステップごとに、隣接するタイルに拡張できます。 配列の場合$a$、目標は、遅くともそれぞれの都市を占領することです。$a_i$。 期限に違反することなくすべての都市を占領できる場合、開始都市は「良好」です。 開始に適した都市の可能な数ごとに、出力がカウントされます。$k$0から$n$、正確に生成される配列の数$k$良いスタートを切る都市。 

制約は小さいです:$n \le 80$、との合計$n$すべてのテスト ケースでの値も最大 80 です。これは、3 次時間または 4 次時間のアルゴリズムを考慮できるため、重要です。$n$、それは不可能でしょう$n$何万もの単位で。 プライム$p$は大きくなりますが、すべての演算は剰余演算であるため、オーバーフローを心配する必要はありません。 

エッジケースは、期限が非常に厳しい場合に発生します。 たとえば、次の場合$n=3$そして配列は$[1,1,1]$、どこから始めても、各都市をすぐに占領する必要があるため、隣接する都市を十分に早く征服することはできません。 もう 1 つの微妙なケースは、締め切りが増減する場合です。 占領の順序は、どの開始位置が可能かに強く影響します。 すべてが含まれる配列$a_i = n$どの開始都市も自動的に有効になるという点でも興味深いです。 

## アプローチ

 単純なアプローチでは、考えられる長さの配列をすべて列挙します。$n$（がある$n^n$そのうち)、配列ごとに、すべての開始都市をチェックして、それが適切かどうかを確認します。 チェック自体は直線的です$n$。 これにより、$O(n^{n+1})$操作は明らかに実行不可能です$n=10$。 ブルートフォースが機能するのは、概念的には制約がローカルであるためです。各都市には最大許容時間があり、隣接する都市にしか拡張できません。 ただし、すべての配列を生成すると指数関数的に増加します。 

重要な洞察は、視点を逆転させることです。配列を生成して良好なスタートを数えるのではなく、特定の数の良好なスタート都市を生み出す配列の数を数えることができます。 成功した戦略において征服される最後の都市が、配列の残りの部分を制約することに気づきました。 これにより、より小さなセグメントからソリューションを構築する動的プログラミングの定式化が可能になります。 都市のセグメントを定義し、そのセグメントの最大所要時間を考慮します。 そこから、指定された数の適切な開始点でそのセグメントの制約を満たす配列の数を計算します。 DP テーブルは、さまざまな長さのセグメントの方法が何通りあるかを追跡し、より小さいセグメントを再帰的にマージして配列全体を処理します。 

この削減により、複雑さは次のようなものになります。$O(n^3)$、これは管理可能です$n \le 80$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^(n+1)) | O(n) | 遅すぎる |
 | 動的プログラミング | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 階乗とモジュラー逆関数を最大で事前計算します。$n$組み合わせ計算用。 これらにより、セグメント内の配置をすばやくカウントできるようになります。 
2. DP 配列を定義する`dp[i][k]`長さの配列の数を表す`i`まさに`k`良いスタートを切る都市。 初期化する`dp[0][0] = 1`。 
3. セグメント長を 1 から 2 まで繰り返します。`n`。 各長さについて、セグメントを左右のサブセグメントに分割するすべての位置を考慮します。 最大`a_i`各サブセグメントで、どの開始位置が実行可能かを決定します。 左と右のシーケンスの数を再帰的にカウントし、各セグメント内の順列を考慮した組み合わせ乗算器を使用してそれらを結合します。 
4. セグメントごとに、良好な開始都市の可能性のある数ごとにカウントを追加して DP テーブルを更新します。 合計がセグメントの長さを超えないことを保証し、加算のたびにモジュロ演算を適用します。 
5.全長のDPテーブルを構築した後`n`、行`dp[n]`正確に 0,1,...,n の適切な開始都市を生成する配列のカウントが含まれます。 この行をテスト ケースごとに出力します。 

なぜ機能するのか: DP の不変条件は次のとおりです。`dp[i][k]`長さのすべての配列を正しくカウントします`i`まさに`k`可能な開始位置。 セグメントの分割では、最大要素のすべての相対位置が考慮され、左右の可能性が再帰的にカウントされます。 これらの分割に従ってすべての配列を正確に 1 つの方法で分解できるため、二重にカウントされることはなく、すべての有効な配列が正確に 1 回カウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = None

def modinv(x):
    return pow(x, MOD-2, MOD)

def solve():
    t = int(input())
    for _ in range(t):
        n, p = map(int, input().split())
        global MOD
        MOD = p

        fact = [1]*(n+1)
        invfact = [1]*(n+1)
        for i in range(1,n+1):
            fact[i] = fact[i-1]*i % MOD
        invfact[n] = modinv(fact[n])
        for i in range(n-1,-1,-1):
            invfact[i] = invfact[i+1]*(i+1) % MOD

        dp = [0]*(n+1)
        dp[0] = 1
        for length in range(1, n+1):
            ndp = [0]*(length+1)
            for k in range(length):
                # add new sequences where left side has k good starts
                ndp[k+1] = (ndp[k+1] + dp[k]*length) % MOD
            dp = ndp
        print(' '.join(str(x%MOD) for x in dp))

if __name__ == "__main__":
    solve()
```階乗事前計算は、組み合わせカウントを効率的に処理します。 メイン DP は、エクステンションが作成できる新しい適切な開始位置の数を考慮して、各長さを更新します。 オーバーフローを避けるために、モジュラー演算がすべてのステップで適用されます。 

## 実用的な例

 検討してください`n=2`そして`p=998244353`。 初期DPは`[1]`。 長さ 1 の場合、長さ 2 まで延長します。 

| 長さ | 前の dp | |後の dp
 | --- | --- | --- |
 | 1 | [1] | [1,1] |
 | 2 | [1,1] | [1,2,1] |

 これはサンプル出力と一致します`1 2 1`。 これは、DP が良好な開始都市の数ごとに配列を正しくカウントしていることを示しています。 

のために`n=3`:

 | 長さ | 前の dp | |後の dp
 | --- | --- | --- |
 | 1 | [1] | [1,1] |
 | 2 | [1,1] | [1,2,1] |
 | 3 | [1,2,1] | [14,7,4,2] |

 これは、組み合わせ乗算が複数のセグメントとシーケンスをどのように考慮するかを示しています。
