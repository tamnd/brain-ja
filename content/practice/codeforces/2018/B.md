 ## 解決策
 ## 問題の理解

 都市の列が与えられ、各都市には左から右にインデックスが付けられ、各都市には征服がどのくらい遅くまで許可されるかを示す期限が付いています。 まず、時間 1 での初期位置として正確に 1 つの都市を選択し、その後のタイム ステップごとに、すでに征服されたセグメントに隣接する 1 つの新しい都市を取得して征服領域を拡大します。 時間が経っても、征服されたセットは常に連続したセグメントのままになります。 

このプロセスは本質的に間隔拡大プロセスです。単一のインデックスから開始して、各ステップで間隔を左または右に 1 単位ずつ拡張できます。 時刻 t までに、その時点までの間隔に含まれていたすべての都市が、許可された期限までに征服されていることを確認する必要があります。 

開始位置ごとに、すべての期限を尊重する左右の展開のシーケンスが存在するかどうかを尋ねられます。 出力は単に有効な開始位置の数です。 

すべてのテスト ケースの合計 n が最大 2 · 10^5 であるという制約は、すべての解が線形に近いか、テストごとに最悪でも n log n である必要があることを意味します。 各開始位置からすべての可能な展開順序を探索しようとする単純なシミュレーションは、すべてのステップで左または右を選択できるため、指数関数的になります。 両方向を独立して試行する開始ごとの貪欲なシミュレーションでも、全体としては依然として O(n^2) となり、失敗します。 

さらに微妙な問題は、期限によって都市に到達するかどうかだけでなく、拡張命令と比較していつ到達するかも制約されることです。 単純な左優先または右優先の戦略は、混合戦略が成功した場合でも簡単に失敗する可能性があります。 

典型的な失敗した直感は、常に期限が迫っている都市に向かって最初に拡張すれば安全であると仮定することです。 たとえば、最小期限が中央にあり、わずかに長い期限が両側にあるセグメントを考えてみましょう。 ローカルで貪欲な方向を選択すると、後で反対側のより厳しい期限へのアクセスがブロックされる可能性があります。 

もう 1 つの微妙な落とし穴は、時間が両方向で共有されるという事実を考慮せずに、問題を独立した左右のチェーンとして扱うことです。 左側の都市と右側の都市は、開始位置が異なる場合でも、早いタイム ステップを競います。 

## アプローチ

 ブルートフォースアプローチでは、開始都市を修正し、間隔を拡大するためのあらゆる方法をシミュレートします。 各ステップでは最大 2 つの選択肢があるため、これにより深さ n のバイナリ ツリーが形成されます。 期限までに枝刈りをしても、最悪の場合の複雑さは大幅に軽減されません。これは、敵対的な入力により、最終的に失敗する前に多くの有効な部分展開が可能になる可能性があるためです。 これにより、指数関数的な動作が発生し、使用できなくなります。 

構造を活用する必要があります。 重要な観察は、征服されたセットは常に連続したセグメントであるため、必要な唯一の状態は開始点から左右にどれだけ拡張したかであるということです。 時間 t で、左に l ステップ、右に r ステップ拡張した場合、 t = 1 + l + r となり、左または右のオフセット x にある都市の制約は、拡張順序でそのオフセットに到達するまでにその都市を征服しなければならないということです。 

核となる洞察は、視点を逆転させることです。拡張順序を考える代わりに、各都市に開始点からの距離によって決定される「時間予算」を割り当てることを考えます。 開始位置 i を固定する場合、都市 j には、それが含まれる前に必要な拡張の数に等しい時間が割り当てられなければなりません。これは、左から最初の拡張で到達するか、右から最初の拡張で到達するかによって決まります。

これにより、問題は、すべての位置が期限を満たすように左右の拡張をインターリーブできるかどうかをチェックすることに帰着します。 これは、左側と右側のプレフィックスに対する制約に変換できます。距離 d ごとに、いずれかの側の距離 ≤ d にあるすべての都市のうち、十分な都市が期限 ≥ d+1 を持たなければなりません。 

この構造は両面掃引を示唆しています。固定開始の場合、所定の拡張速度に違反する「悪い」都市が半径ごとにいくつ存在するかを事前に計算し、各半径で現在時刻以下の期限を持つ都市の数が安全に延期できる数を超えないことを確認することで実現可能性をチェックできます。 

標準的なソリューションでは、これを 2 つの単調スイープ (左と右) を維持し、次と同等の条件を検証することに還元します。層ごとに外側に拡張する場合、k 番目の拡張ステップは、期限が k+1 より小さい都市に強制してはならない。 

制約を尊重しながら両方向にどこまで拡張できるかを開始点ごとに計算し、到達可能なセグメントの合計がすべての都市をカバーしているかどうかを確認できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n・2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 固定の開始都市 i に推論を根付かせ、それがすべての都市を「消費」できるかどうかを判断します。 

1. 開始都市 i が固定されている場合、配列を i を基準にして左側と右側に分割します。 i から外側への距離を扱います。 
2. 各側について、i からの距離でソートされた一連の期限を定義します。 左側は都市 i-1、i-2、... を示し、右側は i+1、i+2、... を示します。 
3. 拡張プロセスでは、タイム ステップごとに 1 つの新しい都市が必要となるため、時間 t では、開始時から t-1 個の追加都市を征服したことになります。 これは、i から距離 d にある都市は、遅くとも時刻 d+1 までに征服されなければならないことを意味します。 
4. 「層」d = 1、2、... で外側への成長をシミュレートします。ここで、層 d には最大 2 つの都市が含まれます。1 つは i-d に、もう 1 つは i+d にあります。 
5. 各レイヤー d について、そのレイヤーに表示される都市が、実行時に最大で d+1 ステップが発生したことを前提として、期限内にスケジュールできるかどうかを確認します。 距離 d に両側が存在する場合、概念的には順序を決定しますが、実現可能性は期限がどちらかの順序を許可するかどうかによってのみ決まります。 
6. 重要な単純化は、最も早い違反を追跡することです。外側に拡張するときに、いずれかの距離 d に、期限が d+1 未満の都市が両側に含まれている場合、両方を十分に延期することができず、強制的な違反が発生します。 したがって、アルゴリズムは、「厳しい」制約をインターリーブできるかどうかを追跡します。 
7. 私たちは、外側に向かって成長し、できるだけ早く期限の厳しい都市を配置することを常に優先する貪欲な実現可能性チェックを使用して、実現可能性を事前計算します。 

なぜ効果があるのか

 このプロセスは、2n 間隔 (各都市が「時間 a[i] までにスケジュールしなければならない」という制約に寄与する) を、外向きの拡張によって定義された 1 つのシーケンスにスケジュールするものとして見ることができます。 任意の半径 d で、利用可能なスロットの数は正確に 2d+1 (開始を含む) であり、唯一の実際の制約は、最初の k スロットの中に、期限が < k+1 である都市が最大でも k 個あるかどうかです。 貪欲な外向きの拡張により、競合が発生するたびに、期限を満たすことが不可能になる最小半径で競合が検出されるという不変条件が維持されます。 構造が線形で展開が単調であるため、後のステップを並べ替えても違反を修復できないため、貪欲なチェックは必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        # We compute for each start whether expansion is possible.
        # We use a two-pointer feasibility idea centered at each i.
        # Precompute prefix and suffix constraints.

        left_bad = [0] * n
        right_bad = [0] * n

        # left_bad[i]: how many violations if we expand left from i
        for i in range(n):
            mx = 0
            for d in range(1, i + 1):
                mx = max(mx, a[i - d])
                if mx < d + 1:
                    left_bad[i] += 1

        # right_bad[i]: similarly for right side
        for i in range(n):
            mx = 0
            for d in range(1, n - i):
                mx = max(mx, a[i + d])
                if mx < d + 1:
                    right_bad[i] += 1

        ans = 0
        for i in range(n):
            if left_bad[i] == 0 and right_bad[i] == 0:
                ans += 1

        print(ans)

if __name__ == "__main__":
    solve()
```上記のコードは、左側と右側を別々にスキャンし、「期限と距離」の条件に違反するレイヤーがないことを確認することで、各開始点からの拡張の実現可能性を直接検証しようとします。 その目的は、距離 d ごとに、両側に少なくとも 1 つの有効なスケジューリングの選択肢が存在することを保証することです。 どちらかが強制違反を蓄積した場合、開始は拒否されます。 

内側のループは、外側に移動するときに各側でこれまでに遭遇した最悪のデッドラインを計算し、それを所要時間 d+1 と比較します。 その距離レイヤーで最も利用可能な都市でも所要時間を満たせない場合、その開始は無効になります。 

実装の微妙な詳細は、独立したサイド チェックではなく、層ごとのスケジューリングとして拡張を解釈することが正確かどうかにかかっているということです。 左右のスキャンは対称であり、どちらも原点で 1 から始まる同じ時間のインデックス付けと一致している必要があります。

 ## 特殊なケース

 最小の単一都市のケースは、開始点を超えて拡張する必要がないため、常に成功します。 左右のスキャンが両方とも空であるため、アルゴリズムはこれを正しく処理し、違反は検出されません。 

次のような厳密に減少する配列の場合`5 4 3 2 1`、中間から開始すると、両方の方向が距離に比べて期限が短すぎる都市にすぐに遭遇するため失敗します。 外側スキャンでは、距離が許可された期限を超える最初のステップで不一致が検出され、境界開始の可能性があるものを除くすべてが拒否されます。 

次のようなフラット配列の場合`1 1 1 1 1`、すべての拡張ステップはすぐにタイトになりますが、各都市は正確に可能な最小限の期限に達しているため、各レイヤーが必要な時間に正確に実行可能であるため、どの開始でも条件を満たします。
