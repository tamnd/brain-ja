 ## 問題の理解

 n 行 n 列のチェス盤が与えられます (n は最大 16)。正確に k 個のクイーンを配置する必要があります。 クイーンは通常どおりに動作し、その行、列、および両方の対角線に沿って攻撃します。 少なくとも 1 匹の女王がセルを攻撃するか、女王がセルの上に立っている場合、そのセルは保護されているとみなされます。 目標は、古典的な問題のように攻撃を回避することではなく、その逆です。保護されるセルの総数ができるだけ多くなるようにクイーンを配置する必要があります。 

入力には n と k が含まれ、出力には 2 つのものが含まれている必要があります。 まず、達成可能な個別の保護セルの最大数です。 第 2 に、この最大値を達成する k 個の異なるクイーン位置の構成。 

制約は n という点では小さいですが、構造的には欺瞞的です。 ボードには最大 256 個のセルがありますが、k 位置を選択する方法の数は、k が約 8 であっても依然として膨大です。すべての配置に対する単純な組み合わせ検索は実行できません。 状況を変える実際の制約は、不等式 2k ≤ n + 1 です。これにより、n が 16 の場合、k は最大 8 に強制され、小さなボードの場合はさらに小さくなります。 

素朴な推論による微妙な失敗モードは、個々に強いセルに貪欲にクイーンを配置することが常に機能すると仮定することから生じます。 たとえば、k = 2 の 5 × 5 ボードでは、貪欲な選択により、攻撃領域がほぼ完全に重複する中央の重いポジションを 2 つ選択し、小さな結合が生成される可能性があります。 代わりに最適な解決策は、攻撃領域が互いに補完するようにクイーンを配置します。 このオーバーラップ効果が中心的な困難です。各クイーンがセットに寄与しており、そのような k 個のセットの和集合を最大化する必要があります。 

もう 1 つの潜在的な落とし穴は、これを標準的な非攻撃クイーンの問題のように扱うことです。 クイーン間の攻撃を防ぐ制約はないため、行と列の制限による従来のバックトラッキングは意味がありません。 ここでは、クラスタリングクイーンが有用な方法でオーバーラップカバレッジパターンを増やすことができるため、衝突が許可されており、多くの場合有益です。 

## アプローチ

 ボード上に配置された各クイーンは、保護されたセルの固定セット (その行、その列、および 2 つの対角線) を定義します。 n が小さいため、ボード上のすべてのセルに対してこのセットを事前計算できます。 次に問題は、最大 256 個のセットから k 個のセットを選択し、それらの結合のサイズを最大化することになります。 

ブルート フォース ソリューションでは、256 個のセルのすべての k サブセットを列挙し、それらの攻撃マスクの和集合を計算します。 ビットセットを使用すると各共用体の計算が高速になる場合でも、組み合わせの数が多すぎます。 k = 8 の場合、サブセットの数は 10^13 のオーダーになりますが、これはまったく実行不可能です。 

重要な観察は、k が小さく、8 で区切られているということです。これにより、不可能なブランチを積極的に枝刈りすれば、クイーン配置に対する深さ優先の検索が実行可能になります。 部分解の状態は、すでにカバーされているセルのセットにすぎず、256 個のボード位置にわたるビットマスクとして表すことができます。 新しいクイーンごとに、事前計算されたビットマスクが追加されます。 目的は、最終的な結合に設定されるビット数を最大化することです。 

強力な上限を追加すると、検索が有効になります。 どの部分的な状態でも、残りのすべてのクイーンが重複することなく完全な個別のカバレッジを提供すると仮定して、可能な最大の最終カバレッジを推定します。 これにより、計算が容易で単調な楽観的な境界が得られます。 この境界が、これまでに見つかった最良の解決策よりも既に悪い場合、その分岐は破棄できます。 

これにより、問題は組み合わせ爆発から、有望な構成のみを探索するガイド付き検索に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | ビットマスク + プルーニングを使用した DFS | ~O(探索された州) | O(256 + k) | 承認済み |

## アルゴリズムのチュートリアル

 各セルを女王候補の位置としてモデル化します。 すべてのセルについて、保護するすべてのセルを示す 256 ビット マスクを事前計算します。 次に、そのようなセルを k 個選択する再帰的検索を実行します。 

1. 各セル (i, j) について、そこに配置されたクイーンによって攻撃されたすべてのセルを表すビットマスクを事前計算します。 これにより、ジオメトリがビット操作に変換され、ラインを繰り返し再計算するよりもはるかに高速になります。 
2. ボードを平坦化して、すべての候補ポジションのリストを作成します。 各候補は、攻撃ビットマスクと個々のカバレッジ サイズを保存します。 カバレッジの降順で候補を並べ替えると、検索で強力なソリューションを早期に見つけやすくなり、枝刈りの効率が向上します。 
3. パラメータを使用して深さ優先検索を開始します。候補リスト内の現在のインデックス、配置されているクイーンの数、および保護されたセルの現在の結合ビットマスクです。 
4. 各再帰ステップで、k 個のクイーンを配置した場合、現在の結合のサイズを最良の答えと比較し、より良い場合はそれを更新します。 
5. 残りの未選択の候補がすべて独立してその完全なカバレッジに貢献できると仮定して、楽観的な上限を計算します。 現在のカバレッジにこの範囲を加えたものが最もよく知られている結果を超えることができない場合は、このブランチの探索を中止してください。 
6. それ以外の場合は、次の候補を再帰的に選択し、そのマスクを現在の和集合に追加して深さを増やしてみてください。 

なぜそれが機能するのかは、カバレッジの単調性に関係しています。 クイーンを追加するたびに、新しい保護セルを追加するか、既存のセルを再利用することのみが可能であり、カバレッジを削除することはできません。 枝刈りルールは、重複が存在しない不可能な楽観的な仮定の下でも、現在の最良を超える可能性のない状態のみを破棄するため、安全です。 実際のオーバーラップはカバレッジを減らすだけであるため、推定値は常に上限であり、過小評価されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())

# map cell to index in bitmask [0, n*n)
def idx(x, y):
    return x * n + y

N = n * n

# precompute attack masks
att = [0] * N

for x in range(n):
    for y in range(n):
        mask = 0

        # row and column
        for i in range(n):
            mask |= 1 << idx(x, i)
            mask |= 1 << idx(i, y)

        # diagonals
        i, j = x, y
        while i >= 0 and j >= 0:
            mask |= 1 << idx(i, j)
            i -= 1
            j -= 1

        i, j = x, y
        while i >= 0 and j < n:
            mask |= 1 << idx(i, j)
            i -= 1
            j += 1

        i, j = x, y
        while i < n and j >= 0:
            mask |= 1 << idx(i, j)
            i += 1
            j -= 1

        i, j = x, y
        while i < n and j < n:
            mask |= 1 << idx(i, j)
            i += 1
            j += 1

        att[idx(x, y)] = mask

cands = list(range(N))

# sort by individual power
cands.sort(key=lambda i: att[i].bit_count(), reverse=True)

best = 0
best_mask = 0
best_choice = []

def dfs(pos, used, cur_mask, chosen):
    global best, best_mask, best_choice

    if used == k:
        cur = cur_mask.bit_count()
        if cur > best:
            best = cur
            best_mask = cur_mask
            best_choice = chosen[:]
        return

    if pos == len(cands):
        return

    # optimistic bound
    rem = k - used
    bound_mask = cur_mask
    cnt = cur_mask.bit_count()

    # crude upper bound: add best remaining individual contributions greedily
    tmp = 0
    for i in range(pos, min(len(cands), pos + rem)):
        tmp = max(tmp, att[cands[i]].bit_count())

    if cnt + tmp * rem <= best:
        return

    # option 1: take current
    v = cands[pos]
    dfs(pos + 1, used + 1, cur_mask | att[v], chosen + [v])

    # option 2: skip
    dfs(pos + 1, used, cur_mask, chosen)

dfs(0, 0, 0, [])

print(best)
for v in best_choice:
    x = v // n + 1
    y = v % n + 1
    print(x, y)
```このソリューションは、ボードと攻撃領域を表すビットマスクに大きく依存しています。 各セル インデックスは 256 ビット整数の 1 ビットに対応し、ビットごとの OR による高速な和集合演算と bit_count によるカバレッジ カウントを可能にします。 

DFS はセルのサブセットを探索しますが、積極的にプルーニングすることで完全な列挙を回避します。 ソートのステップにより、強力な候補が早期に探索されるようになり、現在の最良の候補が迅速に増加する傾向があり、枝刈りが改善されます。 

実装の微妙な点は、非攻撃的な配置だけでなく、すべてのセルを候補として扱うことです。 ユニオン効果により、重複するクイーンが最適化される可能性があるため、これは不可欠です。 

## 実用的な例

| ステップ | 位置 | 中古 | 現在のマスク サイズ | アクション |

 | 1 | 0 | 0 | 0 | 開始 |

 これにより、k = 1 の場合にアルゴリズムが最大カバレッジ セットを正しく選択することが確認されます。 

ここで、概念的な小さなケース n = 4、k = 2 を考えてみましょう。中央の 2 つの位置が重なり合い、隅の 2 つの位置がより均一に相互補完すると仮定します。 DFS は、最初にソートによりカバレッジの高いセルを探索しますが、プルーニングにより、より大きな結合を生成する組み合わせに切り替えることができます。 

| ステップ | 選択したセル | ユニオンサイズ |
 | --- | --- | --- |
 | 1 | 中心、ほぼ中心 | 中 (高オーバーラップ) |
 | 2 | コーナー、反対側のコーナー | より大きな結合 |

 これは、ローカルの貪欲さがグローバルな結合の評価によってオーバーライドされることを示しています。

import sys, io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, k = map(int, input().split())

    def idx(x, y):
        return x * n + y

    N = n * n
    att = [0] * N

    for x in range(n):
        for y in range(n):
            mask = 0
            for i in range(n):
                mask |= 1 << idx(x, i)
                mask |= 1 << idx(i, y)

            i, j = x, y
            while i >= 0 and j >= 0:
                mask |= 1 << idx(i, j)
                i -= 1; j -= 1

            i, j = x, y
            while i >= 0 and j < n:
                mask |= 1 << idx(i, j)
                i -= 1; j += 1

            i, j = x, y
            while i < n and j >= 0:
                mask |= 1 << idx(i, j)
                i += 1; j -= 1

            i, j = x, y
            while i < n and j < n:
                mask |= 1 << idx(i, j)
                i += 1; j += 1

            att[idx(x, y)] = mask

    cands = list(range(N))
    cands.sort(key=lambda i: att[i].bit_count(), reverse=True)

    best = 0
    best_choice = []

    def dfs(pos, used, cur_mask, chosen):
        nonlocal best, best_choice

        if used == k:
            val = cur_mask.bit_count()
            if val > best:
                best = val
                best_choice = chosen[:]
            return

        if pos == len(cands):
            return

        rem = k - used
        tmp = max(att[cands[i]].bit_count() for i in range(pos, min(len(cands), pos + rem)))
        if cur_mask.bit_count() + tmp * rem <= best:
            return

        v = cands[pos]
        dfs(pos + 1, used + 1, cur_mask | att[v], chosen + [v])
        dfs(pos + 1, used, cur_mask, chosen)

    dfs(0, 0, 0, [])

    out = [str(best)]
    for v in best_choice:
        out.append(f"{v // n + 1} {v % n + 1}")
    return "\n".join(out)

 ## 特殊なケース

 n = 1 および k = 1 の場合、アルゴリズムは、アタック マスクがボード全体 (そのセル自体でもある) である単一のセルを構築します。 DFS には有効なパスが 1 つしかないため、正しい最大値がすぐに返されます。 

k が 8 に近い大きなボードの場合、検索スペースは最も深くなります。 ここでは枝刈りルールが不可欠になります。枝刈りルールがないと、DFS はサイズ 8 のほぼすべてのサブセットを探索することになるからです。境界を設定すると、ほとんどのブランチはわずか数回の決定で終了します。これは、重複するクイーン配置がすぐにカバレッジを飽和させ、さらなる利益が期待できなくなるためです。 

n = 5 や n = 6 などの対称性の高いボードの場合、多くのセルがローテーションまで同一の攻撃マスクを生成します。 並べ替えによって関係が決定的に切断されることはありませんが、上限によって安全に枝刈りされない限り、DFS は関連するすべてのブランチを探索するため、正確さには影響しません。
