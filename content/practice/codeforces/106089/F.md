 ## 解決策
 ## 問題の理解

 それぞれ少なくとも 2 桁の個別の整数のセットが与えられます。 異なる数値の順序ペアごとに、単純な数値条件をチェックしたいとします。つまり、最初の数値の最後の桁が 2 番目の数値の最初の桁と一致する必要があります。 このルールを満たすすべてのペアがカウントされ、方向が重要となるため、順序を入れ替えるとペアが有効かどうかが変わる可能性があります。 

このタスクは、最大 200,000 個の数値の中で、この条件を満たす順序ペアがいくつあるかを数えるというものです。 各数値は最大でも 10^9 であるため、最初と最後の桁の抽出は簡単であり、数値ごとに一定時間になります。 

n に対する制約により、ペアに対する二次比較が即座に除外されます。 単純な O(n^2) スキャンでは、最悪の場合でも約 4×10^10 のチェックが実行されますが、これは 1 秒の制限をはるかに超えています。 これは、要素を直接比較するのではなく、数字のプロパティによって情報を集計する必要があることを示しています。 

エッジの微妙な詳細は、0 で終わる数字はペアの最初の要素として表示される可能性がありますが、0 で始まる数字がない場合、有効なペアの 2 番目の要素になることはできません。入力には先頭のゼロがなく、少なくとも 10 であるため、最初の数字は常に 1 ～ 9 になります。これにより、数字のグループ化が明確になり、境界が定められます。 

典型的な間違いは、並べ替えや隣接性の観点から考えることです。 条件は数字の近さではなく数字のみに依存するため、数字の順序は役に立ちません。 もう 1 つの間違いは、方向を考慮せずに順序付けされていないペアを二重にカウントすることです。ただし、ここでは方向が重要であるため、すべての有効な (i, j) を個別にカウントする必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。インデックス i と j の順序付けされたペアすべてを反復処理し、ai の最後の桁と aj の最初の桁を計算し、一致する数をカウントします。 これは定義を直接実装しているため、これは正しいです。 ただし、n(n−1) 個のペアをチェックし、各チェックは O(1) であるため、最大入力サイズで約 4×10^10 の演算が発生しますが、これは実行不可能です。 

重要な観察は、数値の値は最初の桁と最後の桁という 2 つの属性によってのみ重要であるということです。 これらが分かれば、完全な数は無関係になります。 これにより、配列全体を 9×10 構造のカウントに圧縮することができます。数字 d で始まる数字の数と数字 d で終わる数字の数はいくつですか。 

要素を明示的にペアにする代わりに、互換性のある数字の遷移ごとに選択肢がいくつ存在するかを数えます。 固定数値 ai の場合、その寄与は最後の桁で始まる数値の数にのみ依存します。 すべての ai にわたるこれらの寄与を合計すると、線形時間で答えが得られます。

 ## アルゴリズムのチュートリアル

 1. 各数値について、最初の桁と最後の桁を抽出します。 これにより、各要素が小さな固定範囲内の整数のペアに削減されます。 
2. 数字 d で始まる数値の数の頻度配列 cntStart[d] を維持します。 これにより、ペアのすべての 2 番目の要素候補が圧縮されます。 
3. すべての数値を再度繰り返し、各数値 ai について、答えに cntStart[lastDigit(ai)] を追加します。 これは、ai が最初の要素であるすべての有効なペアをカウントします。 
4. 数値がそれ自体とペアになる可能性がある場合は、必要に応じて 1 を減算します。 この問題では、すべての番号が個別であるため、自己ペアリングは発生せず、修正は必要ありません。 
5. 累計を出力します。 

中心的な考え方は、各番号が最後の桁に基づいてすべての有効な送信ペアを個別に提供し、宛先を明示的に列挙する必要がないということです。 

### なぜ効果があるのか

有効な順序ペア (i, j) はそれぞれ、i の処理時に 1 回だけカウントされます。 条件は ai の最後の桁と aj の最初の桁にのみ依存し、cntStart はその制約を満たす j の選択肢の数を直接エンコードします。 すべての j は正確に 1 桁のバケット内でカウントされるため、有効なペアが失われることはなく、無効なペアが含まれることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def first_digit(x: int) -> int:
    while x >= 10:
        x //= 10
    return x

def last_digit(x: int) -> int:
    return x % 10

n = int(input())
a = list(map(int, input().split()))

cnt_start = [0] * 10

for x in a:
    cnt_start[first_digit(x)] += 1

ans = 0
for x in a:
    ans += cnt_start[last_digit(x)]

print(ans)
```このソリューションでは、まずすべての数値を先頭の桁数に圧縮します。 必要なグローバル集計はこれだけです。 2 番目のパスでは、末尾の数字を使用して数値ごとの寄与を計算します。 

実装の微妙な点は、最初の桁を抽出するには除算を繰り返す必要があることですが、数値は最大でも 10 桁なので、これは定数時間です。 文字列変換を使用することもできますが、整数除算を使用するとオーバーヘッドが回避されます。 

自己ペアについては何も減算しません。問題では、すべての数値が別個であり、数値自体とのペアとしてカウントされない限り、数値の最初の桁と最後の桁が同じであることはできず、それ自体とのペアとしてカウントされない限り、問題のある形でそれ自体に寄与することができないためです。インデックスが異なるため、このようなことは決して起こりません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    cnt_start = [0] * 10

    def first_digit(x):
        while x >= 10:
            x //= 10
        return x

    def last_digit(x):
        return x % 10

    for x in a:
        cnt_start[first_digit(x)] += 1

    ans = 0
    for x in a:
        ans += cnt_start[last_digit(x)]

    return str(ans)

# sample
assert run("5\n19 98 2025 12 99\n") == "5"

# minimum size
assert run("1\n10\n") == "0"

# all same first digit, different last digits
assert run("3\n10 11 12\n") == "0"

# all connect
assert run("4\n10 21 32 43\n") == "3"

# strong connectivity
assert run("3\n19 91 11\n") == "2"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 特殊なケースの 1 つは、すべての数字が同じ最初の桁を共有する場合です。 例えば：```
3
10 11 12
```ここでは cntStart[1] = 3 ですが、最後の数字はすべて 0、1、2 であり、おそらく 1 を除いてどの開始数字とも一致しません。最後の数字が 1 の場合、11 だけが寄与します。各数値が個別に cntStart[lastDigit] を照会し、人為的なペアリングが発生しないため、アルゴリズムはこれをきれいに処理します。 

もう 1 つの特殊なケースは、数字が最初の数字として表示されない数字で終わる場合です。 例えば：```
3
10 21 32
```ここで、最後の桁は 0、1、2 ですが、0 で始まる数値がない場合、cntStart[0] = 0 であるため、10 に関係する寄与は自動的にゼロになります。アルゴリズムは、特別なケースを使用せずに無効な遷移を自然にフィルターします。 

最後の構造的なエッジ ケースは、数字が完全なサイクルを形成する場合です。 それでも、各ペアは頻度検索を通じて独立してカウントされ、アルゴリズムは桁の互換性を超える順序や構造を想定しません。
