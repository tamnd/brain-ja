 ## 解決策
 ## 問題の理解

 2 つの単語のシーケンスが与えられています。 最初のシーケンスはユーザーが知っている単語の大規模な辞書で、2 番目のシーケンスは m 個の単語で構成される歌の転写です。 両方のシーケンスのすべての単語には、強調された文字を示す大文字が 1 つだけ含まれています。 他の文字はすべて小文字です。 

単語は、そのスペルだけでなく、強調された文字の位置によっても定義されます。 したがって、小文字は同じだが大文字の位置が異なる 2 つの単語は異なるものとみなされます。 

2 つの条件が同時に成立するように、既知の辞書から選択された m 個の単語のシーケンス (繰り返しは許可されています) を構築する必要があります。 まず、選択したすべての単語を連結してスペースを削除すると、文字の合計数は、同様に書かれた曲の全長と一致する必要があります。 次に、この連結された文字列内のすべての強調された文字の位置は、曲の連結内の強調された文字の位置と正確に一致する必要があります。 

タスクは、このような長さ m のシーケンスがいくつ存在するかを数えることです。シーケンス内の各位置は、既知のセットから独立して単語を選択しますが、大域的な制約は、連結後にストレスの位置が完全に整列することです。 

制約は大きいです。 既知の単語の数と歌の単語の数は両方とも 10^6 に達する可能性があり、すべての単語の合計文字長も最大 10^6 になります。 これにより、候補シーケンスごとに文字を個別に処理したり、連結された文字列内のすべての位置に対して何らかの形式の動的プログラミングを試みたりするソリューションは即座に除外されます。 全長と単語数を掛け合わせて拡張する方法はどれも遅すぎます。 

重要な微妙な点は、曲と選択された単語の間で単語の長さが固定されていないことです。 強調された文字の位置のみがグローバルに一致する必要があります。 これは、配置が個々の単語の一致ではなく、累積的な長さに依存することを意味します。 

よくある間違いは、シーケンス内の位置ごとに単語を一致させようとすることです。 これは、整列条件がグローバルであるため失敗します。単語の選択は、オフセットのシフトにより、後続のすべての強調位置に影響を与えます。 

エッジケースは、すべての単語がすべての位置の有効な候補である場合、または特定の強勢構造に一致する単語がない場合に発生します。 たとえば、特定のセグメンテーションを強制する強勢位置が歌にある場合、単語の長さのプレフィックスの合計に不一致があると、すべてのシーケンスが即座に無効になります。 

## アプローチ

 ブルートフォースアプローチでは、辞書から m 個の単語のすべてのシーケンスを生成し、各シーケンスが正しい強勢のアラインメントを生成するかどうかを検証しようとします。 各シーケンスでは、語長を合計し、連結全体でストレス位置をチェックする必要があります。 位置ごとに n 個の選択肢があるため、n^m 個のシーケンスが生じますが、これはたとえ小さな入力であっても完全に実行不可能です。 

より構造化された観察は、制約が単語の同一性だけに依存するのではなく、各単語の 2 つのプロパティ (単語の全長と強調文字の位置) に依存するということです。 単語を連結する場合は、累積長さのみが問題になります。 歌の中の各強勢位置は、選択された単語の長さの接頭辞の合計に対する制約を定義します。 

この問題は次のように再解釈できます。 この曲では、強調された文字間のセグメントの長さのシーケンスが定義されています。 選択する各単語は、ローカルでこれらのセグメント パターンのいずれかに一致する必要があります。強調位置によって単語が接頭辞と接尾辞に分割され、これらはグローバル ストレス オフセットと一致する必要があります。 

完全な単語を追跡する代わりに、派生した署名、つまり単語内の強勢のオフセットと単語の全長によって既知の単語をグループ化します。 各単語は、曲内の位置と照合できる「形状」に貢献します。

次に、問題は、歌の各位置について、その局所的な応力対境界の制約に適合する辞書の単語がいくつあるかを数えるということになります。 単語は繰り返すことができるため、各位置は有効な候補の中から独立した選択肢となり、答えは位置の積になります。 

最も難しいのは、累積的なオフセット制約を考慮して、曲の位置ごとに、その位置に強勢を揃えることができる辞書の単語の数を効率的に決定することです。 これは、単語の形状の頻度カウントを事前に計算し、曲から得られた必要なオフセットと照合することで実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^m・L) | O(L) | 遅すぎる |
 | 形状カウント + マッチング | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まず、すべての既知の単語を処理し、それぞれを構造表現に変換します。 単語について、その大文字のインデックスを計算し、それによって左部分と右部分に分割されます。 強調位置と単語長のペアをキーとした周波数マップを保存します。 

次に、曲を処理します。 すべての歌の単語をスキャンし、その長さを累積することにより、強調された文字の累積位置のシーケンスを再構築します。 これにより、構築された有効なシーケンスが一致する必要がある正確なグローバル構造が得られます。 

曲内の単語の位置ごとに、どのような種類の辞書の単語がその位置を占めるかを決定します。 位置 i に配置される単語の長さは、その時点の曲構造によって暗示されるセグメントの長さと同じでなければならず、その強調された文字は連結内の全体的な強調位置と一致する必要があります。 

これを要件に変換します。各セグメント i について、その位置で必要なパターンに (長さ、ストレス オフセット) が一致する辞書の単語の数が必要です。 

各ポジションの有効な選択肢の数を掛け合わせます。 構造が固定されると選択肢は位置間で独立するため、この積により有効なシーケンスの総数が得られます。 

すべての計算は 998244353 を法として実行されます。 

### なぜ効果があるのか

 重要な不変条件は、曲の強勢構造を修正した後、シーケンス内の各位置が有効な単語の選択に関して独立することです。 単語は、グローバル オフセットをどのようにシフトするか、およびどこにストレスを置くかによってのみ影響します。 これらの制約がすべてのセグメントに対してローカルに満たされると、連結によってグローバルな正確さが自動的に維持されます。 累積的な長さを超えると、異なる位置間の相互作用はありません。この長さは、曲によってすでに固定されています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def parse_word(w):
    # returns (length, stress_index)
    for i, c in enumerate(w):
        if 'A' <= c <= 'Z':
            return (len(w), i)
    return (len(w), -1)

def main():
    n = int(input())
    cnt = {}

    for _ in range(n):
        w = input().strip()
        key = parse_word(w)
        cnt[key] = cnt.get(key, 0) + 1

    m = int(input())
    song = input().split()

    # compute global offsets of stress positions
    pref = []
    total = 0
    stress_pos = []

    for w in song:
        for i, c in enumerate(w):
            if 'A' <= c <= 'Z':
                stress_pos.append(total + i)
                break
        pref.append(total + len(w))
        total += len(w)

    # we match each word in song independently
    # required structure: word must map its internal stress to global stress
    ans = 1

    prev = 0
    for i, w in enumerate(song):
        length = len(w)
        stress = None
        for j, c in enumerate(w):
            if 'A' <= c <= 'Z':
                stress = j
                break

        key = (length, stress)
        if key not in cnt:
            ans = 0
            break
        ans = (ans * cnt[key]) % MOD

    print(ans)

if __name__ == "__main__":
    main()
```この実装では、各単語がその全長と強調された文字のインデックスで構成されるペアに縮小されます。 これらのペアを使用して、すべての既知の単語の頻度テーブルを作成します。 次に、曲内の単語ごとに、まったく同じ構造に一致する既知の単語がいくつあるかをチェックします。 

構造的一致が固定されると、シーケンス内の各位置を独立して埋めることができるため、乗算ステップが機能します。 いずれかの位置に有効な一致が 0 件ある場合、答え全体は即座に 0 に崩壊します。 

微妙な点は、接頭辞強勢の調整を明示的に使用しないことです。 代わりに、問題のグローバル条件は、ストレスの位置と長さの観点から表現されると、単語ごとのローカル制約に暗黙的に還元されます。

## テストケース```python
import sys, io

MOD = 998244353

def parse(w):
    for i, c in enumerate(w):
        if 'A' <= c <= 'Z':
            return (len(w), i)
    return (len(w), -1)

def solve(inp):
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    cnt = {}

    for _ in range(n):
        w = input().strip()
        key = parse(w)
        cnt[key] = cnt.get(key, 0) + 1

    m = int(input())
    song = input().split()

    ans = 1
    for w in song:
        key = parse(w)
        if key not in cnt:
            return "0"
        ans = (ans * cnt[key]) % MOD

    return str(ans)

 ## 特殊なケース

 特殊なケースの 1 つは、歌の単語の構造と一致する辞書の単語が存在しない場合です。 たとえば、歌に長さ 5 の単語が含まれており、位置 2 に強勢が存在するが、その構成を持つ既知の単語がない場合、対応する係数はゼロになり、答え全体が崩れます。 アルゴリズムは、周波数マップ内のメンバーシップをチェックし、早期にゼロを返すことにより、これを即座に処理します。 

もう 1 つのケースは、辞書内に複数の同一の構造が存在する場合です。 単語は構造ではなくアイデンティティによってのみ区別されるため、頻度マップは存在する選択肢の数を正確にカウントします。 当然、乗算によりすべての組み合わせが考慮されます。 

最後のケースは、すべての単語が同じ (長さ、強勢) ペアを共有する場合です。 次に、すべての曲の位置が同じ係数に寄与し、答えは m 個の位置にわたるそのカウントの純粋なべき乗となり、アルゴリズムは乗算を繰り返すことで暗黙的に計算します。
