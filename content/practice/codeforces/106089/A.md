 ## 解決策
 ## 問題の理解

 一連の要素と、サブ配列を「興味深い」ものにするものを制御するパラメーターが与えられます。 タスクは、配列のすべての連続するサブセグメントを考慮し、その内容の多様性に基づいて制約を満たすサブセグメントがいくつあるかを判断することです。 この問題では、サブセグメントは単に配列の連続したスライスであり、条件はそのスライス内の個別の値の数によって異なります。 

ソース内のステートメントのテキストは部分的に文字化けしていますが、コアの組み合わせオブジェクトは標準です。配列のすべての区間を処理しており、「k-interesting」ルールに従ってそれらをフィルタリングする必要があります。これは、一般的な定式化では、区間内の個別の要素の数が k によって制限されることを意味します。 

したがって、入力は、長さ n の後に整数 k が続く配列を表します。 出力は単一の数値です。つまり、個別の要素のセットのサイズが最大でも k である連続する部分配列の総数です。 

このような問題の制約パターンは通常、n が約 200000 までであることを意味します。n の 2 乗は 10^10 の演算のオーダーであり、一般的な制限をはるかに超えているため、部分配列の二次列挙は即座に除外されます。 実行可能な解決策はいずれも線形または線形演算に近くなければならず、理想的には O(n) です。 

値が不規則なパターンで繰り返される場合、微妙なケースが発生します。 単純なアプローチでは、次のような状況でうまくいかないことがよくあります。 

1 つの障害モードは、各サブアレイを個別にチェックしても問題ないと想定しているため、タイムアウトが発生します。 たとえば、配列が 1 2 3 4 5 ... のような多くの個別の値を交互に配置する場合、すべてのサブ配列をチェックする必要があり、各チェック自体が間隔をスキャンする可能性があり、三次的な動作が発生します。 

もう 1 つの障害モードは、ウィンドウを拡張するときに、個別カウントの更新を誤って処理することです。 たとえば、1 2 1 2 3 のような配列では、要素を削除または追加するには、頻度カウントを注意深く維持する必要があります。そうしないと、重複が二重にカウントされたり失われたりする可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。左端と右端を選択してすべての部分配列を列挙し、その中に含まれる個別の値の数を計算します。 これは、サブ配列をスキャンし、セットを使用して個別の要素をカウントすることで実行できます。 概念的には正しいですが、このアプローチはサブ配列ごとに O(n) の作業を実行し、O(n^2) 個のサブ配列が存在するため、最悪の場合は O(n^3) の複雑さになります。 ハッシュ セットを使用して内部スキャンを最適化しても、漸近コストは変わりません。 

重要な構造上の観察は、左の端点を固定すると、有効な右の端点のセットが連続した範囲を形成するということです。 右ポインタを右に移動すると、個別の要素の数は増加するか、または同じままになります。 この単調性により、スライディング ウィンドウを維持できます。つまり、条件が満たされている間は右側の境界を拡大し、条件に違反している場合は左側の境界を縮小します。 

これにより、現在のウィンドウ内の要素の周波数マップを維持するという問題が軽減されます。 右ポインタを展開するたびに、その要素のカウントが増加します。 それが新しい個別の要素になる場合は、個別のカウンターを増やします。 個別の要素の数が k を超える場合は、制約が復元されるまで左ポインタを前方に移動し、頻度を減らし、場合によっては個別の数を減らします。 どちらのポインターの移動も最大で n 回発生するため、全体の複雑さは線形になります。

 ## アルゴリズムのチュートリアル

現在のウィンドウ [l, r) を定義する 2 つのポインター、ウィンドウ内の値の頻度辞書、および現在存在する個別の値の数を表すカウンターを維持します。 

1. l = 0、result = 0、および空の周波数マップを初期化します。 右ポインタが配列上に展開されます。 
2. 0 から n - 1 までの位置 r ごとに、a[r] の頻度を増やしてウィンドウに a[r] を含めます。 この要素が以前に存在しなかった場合は、個別のカウンターを増やします。 
3. 個別のカウンタが k を超える場合、a[l] の頻度を減少させながら、繰り返し l を前方に移動します。 周波数がゼロになると、個別のカウンターが減少します。 ウィンドウが再び有効になるまで続行します。 このステップにより、ウィンドウが常に制約を満たすようになります。 
4. ウィンドウが有効になると、r で終わり、l から r までの任意の場所で始まるすべての部分配列が有効になります。 このような部分配列の数は (r - l + 1) であるため、この値を結果に加算します。 
5. 配列の終わりまで r の展開を続けます。 

核となる不変条件は、各ステップでウィンドウ [l, r] に含まれる個別の要素が最大でも k 個であり、l が現在の r のこのプロパティを維持する最小のインデックスであるということです。 これにより、有効なサブ配列を決して見逃さず、無効なサブ配列をカウントしないことが保証されます。 すべての有効なサブ配列は、その右端が固定された時点で一意にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    freq = {}
    distinct = 0
    l = 0
    ans = 0

    for r in range(n):
        x = a[r]
        if x not in freq or freq[x] == 0:
            freq[x] = 0
            distinct += 1
        freq[x] += 1

        while distinct > k:
            y = a[l]
            freq[y] -= 1
            if freq[y] == 0:
                distinct -= 1
            l += 1

        ans += (r - l + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、上記のスライディング ウィンドウを直接実装します。 頻度ディクショナリは、現在のウィンドウに各値が何回表示されるかを追跡します。 個別のカウンタにより、辞書を繰り返しスキャンする必要がなくなります。 

重要な実装の詳細は、ウィンドウを縮小するときの更新の順序です。 最初に周波数をデクリメントし、周波数がゼロに達したときにのみ個別のカウンタを減らす必要があります。 このロジックから逸​​脱すると、一意の要素が正しくカウントされなくなります。 

## 実用的な例

 配列を考慮してください`1 2 1 2`k = 2の場合。 

| r | 受信中 | l 調整後 | 独特の | 窓 | 追加しました |

 | 0 | 1 | 0 | 1 | [1] | 1 |

 | 3 | 2 | 0 | 2 | [1,2,1,2] | 4 |

最初の例では、制約に違反しない場合の累積を確認します。 2 つ目は、アルゴリズムが制限を適用するためにウィンドウを動的に縮小する方法を示しています。

 ## 特殊なケース

 一般的なエッジ ケースは、k が 1 に等しい場合であり、これにより、すべての有効な部分配列に同一の要素のみが強制的に含まれます。 のようなシーケンスで`5 5 5 5`、ウィンドウは同一の値を超えて拡大することはなく、アルゴリズムは繰り返しの要素によって形成されるすべての三角形部分配列を正確にカウントします。 

もう 1 つのエッジ ケースは、k が配列内の個別の要素の数より大きい場合です。 この状況では、左ポインタは決して移動せず、すべての部分配列が有効です。 ウィンドウは縮小せずに常に有効なままであるため、アルゴリズムは完全な n(n+1)/2 の結果を引き続き正確に累積します。 

さらに微妙なケースは、次のようなシーケンスが交互に現れることです。`1 2 1 2 1 2`、ウィンドウが繰り返ししきい値に達し、かろうじて有効な状態を維持します。 頻度マップにより、ウィンドウに再入力される要素が個別の値を二重にカウントすることなく正しく再アクティブ化されることが保証され、個別のカウンタはすべての拡張と縮小を通じて一貫したままになります。
