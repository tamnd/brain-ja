 ## 解決策
 ## 問題の理解

 さまざまな毎日の速度が与えられます。 少なくとも次の長さの連続した日のセグメントを 1 つ選択する必要があります。`k`。 

セグメントの場合`[l, r]`、その品質は、そのセグメント内のすべての速度の算術平均です。$$\frac{v_l + v_{l+1} + \dots + v_r}{r-l+1}$$タスクは、可能な限り最大の平均を持つセグメントを見つけて、そのエンドポイントを出力することです。 

制約の最も興味深い部分は条件です。$$n \cdot k \le 10^6.$$それでも`n`到達できる`100000`、それができるのは次の場合だけです。`k`とても小さいです。 複雑さが次のように比例するアルゴリズム`nk`安全に制限内にありますが、`O(n^2)`不可能なとき`k = 1`。 

よくある間違いは、最適なセグメントの長さが正確でなければならないと仮定することです。`k`。 

考慮する：```
n = 3, k = 2
1 100 100
```長さのセグメント`2`最大の平均値は`[2,3]`、 平均`100`。 配列全体の平均値`67`なので長さは`2`確かに良いです。 

次に、次のことを考えてみましょう。```
n = 3, k = 2
50 100 50
```最適な長さ 2 の平均は次のとおりです。`75`、ただし配列全体にも平均があります`66.67`。 ここの長さ`2`最適なままです。 

どちらの例も何も証明しません。 重要な点は、証明がなければ長いセグメントを単に無視することはできないということです。 

もう 1 つの微妙な問題は、浮動小数点数を使用した平均の比較です。 考慮する：```
k = 2
1000000000 999999999
999999999 1000000000
```異なるセグメントの平均値はわずかに異なる場合があります。 浮動小数点比較を使用すると、誤って間違ったセグメントが選択される可能性があります。 分数の交差乗算はこれを完全に回避します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 プレフィックスの合計を計算し、すべての有効なセグメントを列挙し、その合計を計算します。`O(1)`、その平均を計算し、最良のものを保持します。 

問題は有効なセグメントの数です。 がある`Θ(n²)`彼らのうち。 と`n = 100000`、それは 1 秒で処理できる量をはるかに超えています。 

重要な観察は、非常に長いセグメントを観察することで得られます。 

セグメントに少なくとも長さがあると仮定します。`2k`。 それぞれ少なくとも長さのある 2 つの連続する部分に分割します。`k`。 

左側の部分が平均的な場合`A`そして右側の部分は平均値です`B`の場合、セグメント全体の平均は次の加重平均になります。`A`そして`B`。 加重平均は、その両方の構成要素を超えることはできません。 したがって、2 つの部分のうち少なくとも 1 つの平均は、セグメント全体の平均以上になります。 

それは少なくとも一定の長さのセグメントを意味します`2k`厳密には、その有効なサブパートのすべてよりも優れていることはありません。 このようなセグメントは、長さが以下になるまで繰り返し短縮できます。`2k`、平均を下げることなく。 

結果として、最適な答えには常に次の範囲の長さが含まれます。$$k \le L \le 2k-1.$$今度は探索空間が小さくなります。 あるのは`k`可能な長さ。 長さごとに、すべての開始位置をスキャンします。 総作業量は、$$O(n \cdot k),$$せいぜいどれくらいですか`10^6`制約があるからです。 

プレフィックスの合計は一定時間で各セグメントの合計を与え、平均はクロス乗算を使用して正確に比較されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのセグメントに対するブルート フォース | O(n²) | O(n) | 遅すぎる |
 | k から 2k-1 までの長さを列挙する | O(nk) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックス合計配列を構築する`pref`、 どこ`pref[i]`最初の合計を格納します`i`要素。 
2. 現在の最良のセグメントを維持します。 その合計、長さ、エンドポイントを保存します。 
3. 考えられるすべての長さを列挙します`L`から`k`に`min(n, 2k - 1)`。 

鍵定理により、少なくとも 1 つの最適なセグメントがこの範囲内にあることが保証されます。 
4.長さごとに`L`、その長さのすべてのセグメントをスライドさせます。 

プレフィックス合計を使用すると、セグメント合計は次のようになります。$$pref[r] - pref[l-1].$$5. 現在のセグメントの平均を、これまでに確認された最良の平均と比較します。 

分けるのではなく比較する$$\frac{sum_1}{len_1}
\quad\text{and}\quad
\frac{sum_2}{len_2}$$チェックすることで$$sum_1 \cdot len_2
\quad\text{vs}\quad
sum_2 \cdot len_1.$$これは正確であり、浮動小数点エラーを回避します。 
6. 現在の平均値が大きい場合は、保存されている回答を置き換えます。 
7. すべての長さが処理された後、保存されたエンドポイントを出力します。 

### なぜ効果があるのか

 正しさは 1 つの特性に依存します。 

長さが少なくとも次のセグメント`2k`両方とも少なくとも長さの 2 つの連続するセグメントに分割できます。`k`。 セグメント全体の平均は、これら 2 つの部分の平均の加重平均です。 したがって、少なくとも 1 つの部分には、セグメント全体と少なくとも同じ大きさの平均があります。 

最適なセグメントから開始して、その長さが少なくとも一定になるたびに、そのようなパーツに繰り返し置き換えます。`2k`。 平均は決して減少せず、最終的に長さは`[k, 2k-1]`。 

したがって、最適な答えは常にその長さの範囲内に存在します。 アルゴリズムは、その範囲内のすべての長さのすべてのセグメントを列挙し、最大の平均を持つセグメントを選択します。 すべての候補がチェックされ、平均が正確に比較されるため、返されるセグメントは最適なものになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    v = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + v[i]

    best_sum = -1
    best_len = 1
    best_l = best_r = 1

    max_len = min(n, 2 * k - 1)

    for length in range(k, max_len + 1):
        for l in range(1, n - length + 2):
            r = l + length - 1
            cur_sum = pref[r] - pref[l - 1]

            if best_sum == -1 or cur_sum * best_len > best_sum * length:
                best_sum = cur_sum
                best_len = length
                best_l = l
                best_r = r

    print(best_l, best_r)

solve()
```プレフィックス合計の構造により、すべてのセグメントの合計が一定時間内に利用可能になります。 これがないと、合計を計算するにはセグメントをスキャンする必要があり、長さの別の係数だけ複雑さが増加します。 

変数ペア`(best_sum, best_len)`現在の最良の平均を分数で表します`best_sum / best_len`。 新しいセグメントを考慮する場合、比較```
cur_sum * best_len > best_sum * length
```かどうかをチェックします$$\frac{cur\_sum}{length}
>
\frac{best\_sum}{best\_len}.$$除算を行わないため、精度に問題はありません。 

長さにわたるループは次の位置で停止します。`2k - 1`。 この境界が、ソリューションが制約に適合する理由全体です。 

必要な出力は 1 から始まるため、すべてのインデックス付けは 1 から始まる座標で処理されます。 プレフィックス合計配列は先頭に追加のゼロを付けて構築され、式は次のようになります。```
pref[r] - pref[l - 1]
```すべてのセグメントで均一に機能します。

import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n, k = map(int, input().split())
    v = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + v[i]

    best_sum = -1
    best_len = 1
    ans = (1, 1)

                best_len = length
