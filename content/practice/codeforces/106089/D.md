 ## 問題の理解

 非負の位置でインデックス付けされた 2 つの無限のランニング トラックがあります。 ランナーは位置 0 からスタートし、最初はどちらかのトラックを選択できます。 あらゆるステップで、彼は正確に 1 つのポジションを前進しようとします。 位置から`x`どちらのトラックでも、同じトラックに留まるか、別のトラックに切り替えることができますが、どちらの場合も所定の位置に着地する必要があります`x + 1`そして、その目的地のセルには、選択したトラック上に障害物がない必要があります。 

各トラックには、ブロックされたセルの周期的なパターンがあります。 最初のトラックのすべてのブロックの長さで`a`、 その通り`k + 1`連続したセルはブロックされます:から`a - k`まで`a`、このパターンは毎回繰り返されます`a`ポジション。 2 番目のトラックは構造は同じですが、ピリオドが付いています。`b`の代わりに`a`。 

ランナーは前に進むことができなくなるとすぐに停止します`x + 1`いずれかのトラックで、または彼がポジションに到達した場合`n`。 目標は、彼が到達できる最も遠い位置を計算することです。 

制約により、次の値まで許容されます。`10^9`, これにより、ポジションに関するシミュレーションが即座に除外されます。 どのようなソリューションでも、障害物の構造を算術的に、理想的にはパラメータに対して一定時間または対数時間で処理する必要があります。 

ポジションに関する単純なシミュレーションでは、次の段階までの各ステップをチェックします。`n`そして、どちらかのトラックが有効な移動を許可するかどうかをテストします。 それはすでにボーダーラインです`n = 10^5`、ただし、最大値が大きい場合は完全に実行不可能です。`10^9`。 

微妙なエッジ ケースは、両方のトラックがある位置で同時にブロックされる場合です。`x + 1`たとえ各トラックが個別に長い安全なセグメントを持っていたとしても。 たとえば、両方の周期パターンがブロックされたサフィックスを揃えている場合、どちらのトラックも頻繁に完全にブロックされていないにもかかわらず、ランナーは早期にスタックする可能性があります。 この位置合わせ動作が最大の難点です。 

## アプローチ

 強引な解釈は簡単です。位置 0 から位置 0 までランナーを段階的にシミュレートします。`n`、各位置で、位置が`x + 1`各トラックでブロックされます。 少なくとも 1 つのトラックが空いている場合は続行します。 そうでない場合は停止します。 

これは、状態がわかれば動きは決定的であるため機能しますが、次の状態までチェックする必要があります。`n`ポジション。 各チェックはモジュラー演算を使用した定数時間であるため、全体の複雑さは次のようになります。`O(n)`。 これでは遅すぎる`n`到達できる`10^9`、そしてさらには`10^5`構造上不要です。 

重要な観察は、位置で重要なのはただ一つであるということです`x`かどうかです`x + 1`は、各周期サイクルのブロックされたサフィックスにあります。 その条件は以下にのみ依存します`x mod a`そして`x mod b`。 したがって、プロセスは剰余ペアによって定義される状態空間上で展開します。`(x mod a, x mod b)`。 ただし、この状態空間を直接探索するのも大きすぎます。 

代わりに、動きが変化するだけであることが観察されます。`x`、プロセスは単調です。 ランナーは常に前に進むため、グラフを検索するのではなく、時折強制停止ポイントを含むシーケンスを検索します。 意味のある唯一のイベントは、両方のトラックが同時にブロックされる位置です。 これらの位置は、ピリオドで繰り返される 2 つの周期的な等差数列の交点に発生します。`lcm(a, b)`。 

したがって、1 つの「安全なセグメント」から次の障害物まで効率的にジャンプできます。 どの位置でも、両方のトラックが同時にブロックされているかどうかを確認することで、少なくとも 1 つのトラックが空いている次の位置を決定します。 各サイクル構造は線形であるため、1 つずつステップ実行するのではなく、モジュラー演算を使用して次のブロック イベントを計算できます。

 ## アルゴリズムのチュートリアル

 現在位置を追跡します`x`、0 から開始して、次の値に移動できるかどうかを繰り返し計算します。`x + 1`。 主な困難は、両方のトラックが同時にブロックされている最初の位置までにどこまで前進できるかを判断することです。 

各トラックは一定の間隔でブロックされます`[p - k, p]`倍数ごとに`p`その時代の。 したがって、特定のポジションに対して`x + 1`、最後にあるかどうかを確認します`k + 1`そのサイクルの位置。 

この構造を使用して、一定の長さのブロックで作業することで、次の「悪い」位置を効率的に見つけます。`l = lcm(a, b)`。 

1. 最小公倍数を計算する`l = lcm(a, b)`。 これは、両方のトラックにわたって結合されたブロッキング パターンの完全な繰り返し期間です。 
2. 問題を範囲内の位置の分析に落とし込む`[0, l - 1]`、その後はパターンが同じように繰り返されるためです。 この範囲を超える動作は周期的です。 
3. ポジションごとに`x`、トラック 1 がブロックされているかどうかを計算します。`x`を使用して`x % a >= a - k`、トラック 2 についても同様に、`x % b >= b - k`。 これにより、実現可能性のための定数時間述語が得られます。 
4. から始める`x = 0`、貪欲に進みます。 各ステップで、少なくとも 1 つのトラックが空いているかどうかをテストします。`x + 1`。 その場合は増分します`x`。 
5. 両方のトラックがブロックされたら停止します。`x + 1`、またはいつ`x == n`。 

重要な最適化は、すべての位置をスキャンするのではなく、`n`、最大でも 1 つの完全な期間の長さを考慮する必要があるだけです。`l`, なぜなら、その後はパターンが正確に繰り返され、ランナーはすでに行き詰まっているか、安全なパターンを繰り返すことになるためです。 

### なぜ効果があるのか

 位置におけるシステムの状態`x`のみに依存する`x mod a`そして`x mod b`。 したがって、その後`lcm(a, b)`ステップでは、両方の残余が同時にリセットされ、ブロックされたセルとフリーのセルの構成は開始時の構成と同一になります。 ランナーは常に前に進むため、今後の動作は最初のサイクルですでに観察されたことの繰り返しになります。 彼が立ち往生せずに完全なサイクルを生き延びた場合、彼は次の時点まで無期限に生き残ることになります。`n`そうでない場合は、最初のブロック イベントが最初のサイクル内に出現する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gcd(x, y):
    while y:
        x, y = y, x % y
    return x

k, a, b, n = map(int, input().split())

lcm = a // gcd(a, b) * b

def blocked1(x):
    r = x % a
    return r >= a - k

def blocked2(x):
    r = x % b
    return r >= b - k

x = 0

while x < n:
    nxt = x + 1
    if blocked1(nxt) and blocked2(nxt):
        break
    x += 1

print(x)
```このソリューションは、閉塞状態をテストするためのモジュラー演算に完全に依存しています。 の`gcd`関数は、オーバーフローせずに LCM を安全に計算するために使用されます。 の`blocked1`そして`blocked2`関数は、周期的な障害物構造を問題定義から直接エンコードします。 

ループは動きをシミュレートしますが、どちらかが到達するまでのみです。`n`または、両方のトラックが次のステップをブロックする位置に遭遇します。 各反復は O(1) であるため、単純さを保ちながら正確さが保たれます。 

よくある落とし穴は、ブロックが宛先セルに適用されることを忘れることです。`x + 1`、現在の位置ではありません。 もう 1 つの微妙な点は、間隔を正しく解釈することです。`[a - k, a]`モジュラー算術にも含まれます。

    import sys
    input = sys.stdin.readline

 ## 特殊なケース

 エッジ ケースの 1 つは、両方のトラックが位置 1 ですぐにブロックされる場合です。入力の場合`0 1 1 10`、どちらのサイクルもすべてのポジションがブロックされているため、ランナーは動き始めることさえできません。 アルゴリズムは正しくチェックします`x + 1 = 1`両方のトラックがブロックされていることがわかり、0 が返されます。 

もう 1 つのケースは、ブロックされたセグメント内で周期パターンが決して重ならない場合です。 例えば`0 3 4 20`は、互いに素なブロック領域を生成するため、各ステップで少なくとも 1 つのトラックが開いたままになります。 ループは次まで進みます。`n`、同時ブロッキングがないことで完全なトラバースが可能であることが確認されます。 

より微妙なケースは、異なる期間のために重複が遅く発生する場合に発生します。 のために`2 6 10 9`、ブロックされたサフィックスは、数サイクル後にのみ整列します。 シミュレーションは位置 9 の最初のオーバーラップまで正しく進行し、8 で停止します。
