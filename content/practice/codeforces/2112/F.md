 ## 解決策
 ## 問題の理解

 私たちには、価値伝播ルールの有向システムが与えられています。$n$変数。 各ルールは 1 つの変数を示します$x$別の変数の値を使用して削減できる可能性があります$y$、定数だけシフト$z$、フォームの操作を通じて$a_x \leftarrow \min(a_x, a_y + z)$。 すべてのルールは 1 回だけ適用されますが、順序は任意です。 

演算は可換ではないため、順序が異なると最終的な固定点も異なる場合があります。 すべての可能な順序がすべての変数に対して同じ最終結果をもたらす場合、初期値の構成は安定していると呼ばれます。 それ以外の場合、最終値を変更する操作を適用する順序が存在する場合、変数は不安定になります。 

操作を適用する前に、各クエリで任意の変数を合計で最大で 1 つ減らすことができます。$k$合計で回。 各クエリは、すべての変数について質問します。$i$、せいぜい支出できるかどうか。$k$デクリメントして初期ベクトルを変更し、変数が$i$不安定になります。 

制約が厳しいため、操作命令のシミュレーションを回避せざるを得ません。 まで$4 \cdot 10^5$操作とクエリが 1000 件ある場合、すべての置換の影響を繰り返し再評価するアプローチは直ちに不可能になります。 各シミュレーションはすでにすべてのエッジにわたる並べ替えまたは BFS に依存しているため、クエリごとに 1 つのシミュレーションを行うだけでもコストがかかりすぎます。 

重要な構造的観察は、不安定性は単一操作の局所的な特性ではなく、有向チェーンを形成する複数の制約間の相互作用から生じるということです。 これは、最短経路またはグラフ緩和の観点を示唆しています。 

典型的な失敗例は、不安定性が直接隣接するもののみに依存すると仮定した場合に発生します。 たとえば、チェーンを考えてみましょう$1 \to 2 \to 3$慎重に選ばれたウェイトを使用。 1 と 3 を接続する直接的な操作がない場合でも、順序に依存した伝播が 2 を介して発生する可能性があり、単純な隣接関係ベースのチェックは機能しません。 

もう 1 つの微妙なケースは、すべての値が大きいにもかかわらず、1 つのノードがしきい値をわずかに超えている場合です。 変数をわずかに減らすと、ある順序では代替の緩和パスが突然アクティブになり、別の順序ではアクティブになりなくなり、元の値だけを考慮した場合には見えない不安定性が生じる可能性があります。 

## アプローチ

 最初の本能は、システムをシミュレートすることです。操作のすべての組み合わせを試し、結果を比較します。 安定性はすべての次数にわたって定義されるため、これは概念的には正しいです。 ただし、$m$まで$4 \cdot 10^5$、クエリごとに 2 つの順列でさえすでに実行不可能になり、階乗爆発によりこれは完全に使用できなくなります。 

より構造化されたビューは、各操作を有向緩和エッジとして書き直すことで得られます。$y \to x$重さで$z$、 意味$x$に基づいて削減できます$y$。 すべての操作が無限ループで適用された場合、システムは値が距離として伝播する最短パス計算に似ていますが、更新が 1 回で任意の順序で適用されるように制約される点が異なります。 

The crucial insight is that instability arises exactly when there are competing paths of relaxation whose activation depends on ordering. ノードが 2 つの異なるチェーンを通じて緩和でき、一方のチェーンで最初に別の操作を適用する必要がある場合、順序が異なると中間最小値が異なる可能性があります。 これにより、問題は、境界のある初期摂動の下で、複数の異なる「タイトな」パスが同じノードをめぐって競合できるかどうかを検出することに変わります。 

これは、すべてのチェーンを通じて変数間の最小の「依存距離」を事前計算し、有向重み付きグラフ上で最短パス構造を効果的に構築することを示唆しています。 Once we know how much each node depends on others, we can characterize whether a small decrease budget$k$指定されたターゲット ノードに対して厳密な順序の違いを強制するには十分です。 

各クエリを、少なくとも 2 つの別個の緩和ソースが同時にクリティカルになる領域にノードを押し込めるかどうかを確認することに集約します。 これは、事前に計算された距離構造に対する最短パスの比較問題となり、ノード全体でほぼ線形な時間で各クエリに答えることができます。

 ## アルゴリズムのチュートリアル

 1. 各操作を解釈する$x \leftarrow \min(x, y + z)$からの有向エッジとして$y$に$x$重さで$z$。 これは、次の事実をエンコードしています。$y$～に影響力を伝播することができる$x$。 
2. 逆グラフの視点を構築し、値が他のすべてのノードから各ノードにどのように流入するかを追跡します。 ノードの最終値は、ソース ノードから到達可能なすべての加重パスの最小値です。 
3. このグラフに対してマルチソース最短パス計算を実行して、ノードのすべてのペア間で可能な限り最良の伝播値を計算するか、各ノードについて他のすべてのノードから入ってくる最良の影響を同等に計算します。 なぜなら$n \le 500$、全ペアのフロイド構造または反復ダイクストラ構造は、$O(n^2 \log n)$または最適化された$O(n^3)$。 
4. 各ノードについて$i$、「重要な親」の候補を特定します: ノード$j$～からの細い道が存在するように$j$に$i$最小値を達成しています。 少なくとも最良および 2 番目に優れた個別の寄与者を各ノードに保存します。 
5. システムはノードの順序に依存するようになる$i$少なくとも 2 つの別個のソースが存在し、その誘導パスが操作順序に応じて両方ともアクティブになる可能性がある場合に限ります。 これは、初期値を減らすことによって 2 つの異なるタイトなパスを同時に競合させることができるかどうかをチェックすることを意味します。 
6. 各クエリについて、概念的に、最大でいくつかの初期値を削減します。$k$減少します。 これは、特定のソース ノードを下げることに相当し、最小限の寄与者としての競争力を高めることしかできません。 
7. 各ノードについて$i$、予算内かどうかを確認してください$k$、他の競合するパスに匹敵するか、またはそれに勝つのに十分なほど、寄与するノードを減らすことができます。$i$。 これは、事前に計算された最短パスの寄与と利用可能なスラックとの比較になります。 

### なぜ効果があるのか

 重要な不変条件は、すべての最終値が、操作順序によって引き起こされる一連の重み付きパスの最小値によって決定されるということです。 順序は、どの中間緩和が早期に利用可能になるかにのみ影響しますが、考えられるすべてのパス コストのセットは変更されません。 したがって、不安定性は、どちらの中間緩和が最初に有効になるかによって優劣が決まる、少なくとも 2 つの異なるパスが存在することと同等です。 最短パス構造を事前に計算し、ノードごとに複数の密接な寄与要因を特定することにより、どの最小値が実現されるか順序が変化する可能性がある状況を正確に捕捉します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def solve():
    n, m = map(int, input().split())
    dist = [[INF] * n for _ in range(n)]
    
    for i in range(n):
        dist[i][i] = 0

    edges = []
    for _ in range(m):
        x, y, z = map(int, input().split())
        x -= 1
        y -= 1
        if z < dist[y][x]:
            dist[y][x] = z

    for k in range(n):
        dk = dist[k]
        for i in range(n):
            di = dist[i]
            dik = di[k]
            if dik == INF:
                continue
            for j in range(n):
                nd = dik + dk[j]
                if nd < di[j]:
                    di[j] = nd

    q = int(input())
    for _ in range(q):
        k_budget = int(input())
        a = list(map(int, input().split()))

        ans = []
        for i in range(n):
            base = a[i]
            best1 = INF
            best2 = INF

            for j in range(n):
                if j == i:
                    continue
                cand = a[j] + dist[j][i]
                if cand < best1:
                    best2 = best1
                    best1 = cand
                elif cand < best2:
                    best2 = cand

            if best2 == INF:
                ans.append('0')
                continue

            gap = best2 - best1
            if gap <= k_budget:
                ans.append('1')
            else:
                ans.append('0')

        print("".join(ans))

if __name__ == "__main__":
    solve()
```コードはまず演算を最短パス行列に圧縮します。ここで、各エントリは値の影響をある変数から別の変数に伝播するための最も安価な方法を表します。 トリプル ループの Floyd-Warshall ステップは、すべてのペアの最小伝播コストを計算します。 

その後、各クエリはすべてのノードを独立して処理します。 固定ターゲットノードの場合$i$、すべての候補の入力値を計算します$a_j + dist[j][i]$。 これらのうち最小の 2 つは、最も強力に競合する 2 つの影響源を表します。 2 番目の別個のソースがない場合、ノードの最終最小値を決定する方法が 1 つしかないため、ノードは次数の感度を示すことができません。 

決定条件は、最も優れた貢献者と 2 番目に優れた貢献者の間のギャップを、許容される減少予算と比較します。 値を減らすと競合他社の関連性が高まるだけなので、2 つのパス間のマージンを排除するのに十分な予算がある場合は、不安定性を強制できます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    INF = 10**18

    n, m = map(int, input().split())
    dist = [[INF] * n for _ in range(n)]
    for i in range(n):
        dist[i][i] = 0

    for _ in range(m):
        x, y, z = map(int, input().split())
        x -= 1
        y -= 1
        dist[y][x] = min(dist[y][x], z)

    for k in range(n):
        for i in range(n):
            for j in range(n):
                if dist[i][k] + dist[k][j] < dist[i][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]

    q = int(input())
    out = []
    for _ in range(q):
        k_budget = int(input())
        a = list(map(int, input().split()))
        res = []
        for i in range(n):
            best1 = INF
            best2 = INF
            for j in range(n):
                v = a[j] + dist[j][i]
                if v < best1:
                    best2 = best1
                    best1 = v
                elif v < best2:
                    best2 = v
            res.append('1' if best2 - best1 <= k_budget else '0')
        out.append("".join(res))
    return "\n".join(out)

 ## 特殊なケース

 重大なエッジケースは、1 つのノードのみがターゲットに到達できる場合です。 その状況では、2 番目に優れた貢献者は事実上無限になります。 順序によって結果が変わる可能性のある競合するパスがないため、アルゴリズムは安定性を正しく出力します。 

もう 1 つのケースは、減分前であっても 2 人の貢献者のコストが等しい場合です。 ギャップはゼロなので、$k = 0$ノードを不安定としてマークします。 これは、完全な関係が順序を決定的にするという直観と一致します。 

最後の微妙なケースは、ノードに複数の入力パスがあるが、その 1 つが他のすべてのパスによって厳密に支配されている場合に発生します。 2 番目に優れた計算でも真の競合相手が特定され、ギャップは生の程度ではなく実際の感度を反映するため、無関係なエッジの過大なカウントが防止されます。
