 ## 解決策
 ## 問題の理解

 ソートされた整数の配列が与えられているので、ボブがその後何をしても、アリスが選択したトリプルが「安全」であるように、アリスが正確に 3 つの異なるインデックスを選択できる方法が何通りあるかを数える必要があります。 

出来事の順序が重要です。 アリスはまず 3 つの要素を選択します。 次に、ボブは配列内の任意の 1 つの位置を選択し、それを青に塗ります。 ボブがたまたまアリスの赤い要素の 1 つを選んだ場合、その要素は上書きされるため、赤い合計に寄与しなくなります。 アリスは、残りの赤い要素の合計がボブが選択した要素の値よりも厳密に大きい場合にのみ勝ちます。 

「ボブの行動に関係なく」というフレーズは、アリスのトリプルを見た後、ボブの考えられる最悪の選択の条件を強制しなければならないことを意味します。 したがって、選択されたすべてのトリプルについて、両方の可能性を考慮する必要があります。ボブはトリプルの内側または外側を選択しますが、どちらの場合でもアリスが勝つ必要があります。 

制約が非常に厳しいため、トリプルに対する 3 次列挙が大きすぎます。 と$n$テストごとに最大 5000、合計で最大 5000、ナイーブ$O(n^3)$アプローチは次の順序で実行されます$10^{11}$限界をはるかに超えた操作。 たとえ$O(n^2 \log n)$テストごとのアプローチは境界線にあるため、$O(n^2)$または$O(n \log n)$解決。 

多くの値が等しい場合、微妙なエッジ ケースが発生します。 たとえば、すべての要素が同一の場合、アリスは合計が大きいためどのトリプルでも機能すると考えるかもしれませんが、ボブはいつでも赤い要素を選択して有効な合計を大幅に減らすことができ、これにより不等式が無効になる可能性があります。 もう 1 つの注意が必要なケースは、最大の要素が他の要素に比べて非常に大きい場合です。これは、赤の要素が 1 つ失われた後でも、赤の合計が優勢でない限り、ボブは常にその値をターゲットにするためです。 

## アプローチ

 直接的なブルートフォースソリューションでは、すべてのトリプルに対して反復処理が行われます。$i < j < k$、合計を計算します$S = a_i + a_j + a_k$、そしてボブの最良の応答をシミュレートします。 

ボブには 2 つの意味のある戦略があります。 赤以外の要素を選択した場合$x$、アリスのレッドサムは残ります$S$、だから必要です$S > x$。 このような最悪の選択は、トリプルの外側にある最大の要素です。 彼が赤い要素を選択した場合$a_t$、赤和は$S - a_t$とボブはこれを比較します$a_t$、だから必要です$S - a_t > a_t$、つまり$S > 2a_t$。 ボブは最悪の赤要素を選択するため、これは次のようになります。$S > 2 \cdot \max(a_i, a_j, a_k)$。 

したがって、固定トリプルの場合、条件は 2 つの不等式になります。 

1.$a_i + a_j + a_k > \max(a)$配列全体で
 2.$a_i + a_j + a_k > 2 \cdot a_k$(配列がソートされているため、$a_k$トリプルで最大）

 ブルートフォースはすべてのトリプルをチェックし、一定時間内に両方の条件を検証しますが、これは$O(n^3)$。 

重要な単純化は、トリプルの最大の要素を修正することです。$a_k$、そして問題をペアを数えることに縮小します$(i, j)$と$i < j < k$一次不等式を満たすこと。 これは、ソートされた配列に対する 2 ポインター戦略を即座に示唆します。 

それぞれについて$k$、私たちが望むのは：$$a_i + a_j > \max(2a_k, a_k + a_{\text{max outside}} - a_k)$$配列はグローバルにソートされているため、グローバル最大値が外側のケースを支配するため、それを事前処理して条件を単純なしきい値に削減します。$a_k$。 

これにより、2 つのポインターを持つスキャン ペアのカウントが減ります。$O(n)$あたり$k$、につながる$O(n^2)$合計。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | 最適な 2 つのポインタ |$O(n^2)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 配列がソートされているという事実に依存しているため、最大値を明確に推論し、ペアを効率的にカウントできます。 

1. トリプルの最大の要素をインデックスとして固定します$k$。 治療します$a_k$3 番目に選択された要素として。 
2. このために$k$、2 つのポインターを設定します。$i = 0$、$j = k - 1$。 
3. 前に 2 つの要素を選択しようとします$k$それらの合計が両方のボブ制約を満たすのに十分な大きさになるようにします。 必要なしきい値は次のようになります。$$a_i + a_j > \max(2a_k, a_k + a_{\max})$$以来$a_{\max}$はテスト ケースごとに固定されており、これはすべてのテスト ケースに対して一定のしきい値になります。$k$。 
4. ながら$i < j$、 もし$a_i + a_j$十分な大きさであれば、すべてのペア$(i, i+1, ..., j-1, j)$固定付き$j$そして変化する$i$下向きが寄与する可能性があります。 次で終わるすべての有効なペアをカウントします。$j$、その後移動します$j$左。 
5. そうしないと、合計が小さすぎるため、増加します$i$合計を拡大します。 
6. すべての有効なペアをすべて累積します。$k$。 

重要なデザインの選択は、常にトリプルの最大の要素を固定することです。 これにより、3 次元の計数問題が 2 次元の問題に分解され、ソートされた配列の単調性により線形スキャンが可能になります。 

### なぜ効果があるのか

 有効なトリプルの場合、最大の要素は次の値でなければなりません。$a_k$。 一度$k$は固定されており、残りの制約はすべてインデックスからのペアの合計にのみ依存します。$< k$。 配列はソートされているため、増加します$i$合計が増加し、減少します$j$これを減少させ、2 つのポインターがすべての有効なペアを 1 回だけ探索することを保証する単調な構造を与えます。 カウントされたすべてのペアが導出されたしきい値条件を明示的に満たすため、有効なペアはスキップされず、無効なペアもカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        mx = a[-1]
        ans = 0
        
        # fix k as largest element of triple
        for k in range(2, n):
            target = max(2 * a[k], mx)
            
            i, j = 0, k - 1
            while i < j:
                if a[i] + a[j] > target:
                    ans += (j - i)
                    j -= 1
                else:
                    i += 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、トリプルの 3 番目の要素を固定し、その左側の有効なペアをカウントします。 変数`target`最悪の場合の要件をエンコードします。ボブが配列内の最大の要素を選択するか、1 つの赤い要素を破棄するため、両方のケースを支配するには、ペアの合計と固定要素を加算する必要があります。 

2 つのポインター ループにより、指定された条件で実行可能になったときに、有効な各ペアが 1 回カウントされることが保証されます。`j`。 表現`ans += (j - i)`一度なので機能します`a[i] + a[j]`十分な大きさであり、その間のすべての中間インデックスは`i`そして`j`とペアになった`j`ソートによる不等式も満たします。

 ## 特殊なケース

 すべての値が等しい場合、すべてのトリプルは、大きさに応じてしきい値をわずかに満たすか、しきい値をわずかに違反します。 合計が固定ターゲットを超えると 2 つのポインターが常にすべてのペアをカウントするため、アルゴリズムはこれをきれいに処理します (これは均一に発生します)。 

最小の有効な入力の場合$n = 3$、可能なトリプルは 1 つだけであり、アルゴリズムは設定によってそれを正しく評価します。$k = 2$そしてシングルペアチェックを試みます。 不等式が成立しない場合、寄与分は追加されません。 

最後に非常に大きな要素が 1 つある場合、ほとんどのトリプルは失敗します。$2a_k$ペアの和が支配的です。 アルゴリズムはこれらを自然に拒否します。`target = max(2*a[k], mx)`が大きくなり、2 つのポインターが有効なペアを見つけられなくなります。
