 ## 解決策
 ## 問題の理解

 整数の配列が与えられたので、それを「美しく」したいと考えます。 美しい配列には少なくとも 2 つの要素があり、その差が最大 1 である隣接する要素のペアが少なくとも 1 つ含まれます。 隣接する 2 つの要素をその範囲内で繰り返し 1 つの数値に結合し、配列を一度に 1 要素ずつ効果的に縮小することができます。 目標は、配列を美しくするために必要なそのような操作の最小数を決定するか、それが不可能であると報告することです。 

入力サイズはテスト ケースごとに最大 1000 要素まで可能で、最大 200 のテスト ケースを含めることができます。 これは、組み合わせの数が指数関数的に増加するため、すべての可能な操作シーケンスを総当たり的に調べるアルゴリズムは非現実的であることを意味します。 各要素の範囲は最大 100 万ですが、実際の値自体には大きな制限はありません。 重要な特徴は、隣接する要素間の違いです。 

微妙な点の 1 つは、配列がすでに美しい可能性があるということです。 例えば、`[1, 3, 3, 7]`すでに含まれています`3`そして`3`, したがって、操作は必要ありません。 もう 1 つの注意が必要なシナリオは、要素が遠く離れたサイズ 2 の配列です。`[6, 9]`。 ここで、それらを結合すると配列が 1 つの要素に減り、「少なくとも 2 つの要素」という要件を満たすことができなくなります。 単純な実装では、操作が誤って試行され、代わりに応答が返される可能性があります。`-1`。 

## アプローチ

 ブルートフォース手法では、考えられるすべての操作シーケンスをシミュレートしようとします。 隣接する要素のペアごとに、その範囲内のすべての可能な整数を試し、配列を再帰的に縮小して、美しいペアが表示されるかどうかを確認できます。 これは原理的には正しいですが、演算回数は配列の長さに対しておおよそ指数関数的になります。`O(n * (max(a_i) - min(a_i))^n)`、これはまったく不可能です`n = 1000`。 

重要な洞察は、考えられるすべての操作シーケンスを考慮する必要はないということです。 美しい配列には、**最大 1 つの違いを持つ 1 つの隣接するペア**が必要です。 つまり、隣接するペアがすでにこの条件を満たしている場合、操作は必要ありません。 そのようなペアが存在せず、すべての隣接する差分が少なくとも 2 である場合、2 つの隣接する要素を組み合わせると常にその範囲内の数値が生成され、元の数値の 1 つから最大で 1 離れた数値が生成され、配列を新しい状態に減らすことができることが効果的に保証されます。 間隔内の整数を選択できるため、**サイズが 2 を超える配列に対しては常に 1 回の操作で十分**、美しいペアを作成できます。 唯一の例外は、要素が 1 つ以上異なる、サイズがちょうど 2 の配列です。これは、配列を縮小すると要素が 1 つだけ残るためです。 

この観察により、解決策は 3 つの単純なチェックに減ります。 配列をスキャンして、すでに美しいペアを探します。 見つかった場合、答えは、`0`。 そうでない場合は、配列に正確に 2 つの要素があり、それらの要素が 1 つ以上異なっているかどうかを確認します。その場合、答えは次のようになります。`-1`。 それ以外の場合は、1 回の操作でいつでも配列を美しくすることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * (最大(a_i)-最小(a_i))^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 テストケースごとにこの手順を繰り返します。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして配列`a`。 
3. 隣接するペアをループする`a[i]`そして`a[i + 1]`のために`i = 0`に`n - 2`。 いずれかのペアが満たされる場合`|a[i] - a[i + 1]| <= 1`、すぐに戻ります`0`。 配列がすでに美しいです。 
4. 条件を満たす隣接ペアがない場合は、配列の長さを確認します。 もし`n == 2`、 戻る`-1`なぜなら、何らかの操作を実行すると配列が 1 つの要素に縮小されてしまい、美しくないからです。 
5. その他すべての場合、`n > 2`最初は美しいペアはありません。戻ります`1`。 隣接するペアに対する 1 回の操作で、元の要素の 1 つに含まれる新しい番号が作成され、美しいペアが生成されます。 

これが機能する理由: 不変条件は、美しい配列には最大 1 つの違いを持つ 1 つのペアのみが必要であるということです。 サイズが 2 より大きい配列では、隣接する 2 つの数値を選択し、その間隔内の数値を選択して、隣接する数値の 1 つとの差を最大 1 にすることができます。 したがって、最初のペアを確認するか、1 つの操作を実行するだけで済みます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    found = False
    for i in range(n - 1):
        if abs(a[i] - a[i + 1]) <= 1:
            found = True
            break
    
    if found:
        print(0)
    elif n == 2:
        print(-1)
    else:
        print(1)
```コードは、テスト ケースの数を読み取ることから始まります。 各配列について、隣接するすべてのペアの違いが最大 1 であるかどうかをチェックします。 見つかった場合、答えはゼロです。 配列にちょうど 2 つの要素があり、美しいペアがない場合、答えは次のようになります。`-1`。 それ以外の場合、初期の美しいペアがない 2 より大きい配列の場合、必要なペアを作成するには 1 回の操作で十分です。 使用する`abs()`順序に関係なく、差異が正しく処理されるようにします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 配列を 1 回スキャンして、隣接する差異を確認します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    output = io.StringIO()
    sys.stdout = output
    
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        found = False
        for i in range(n - 1):
            if abs(a[i] - a[i + 1]) <= 1:
                found = True
                break
        
        if found:
            print(0)
        elif n == 2:
            print(-1)
        else:
            print(1)
    
    return output.getvalue().strip()

# Provided samples
assert run("4\n4\n1 3 3 7\n2\n6 9\n4\n3 1 3 7\n4\n1 3 5 2\n") == "0\n-1\n1\n1"

# Custom cases
assert run("3\n2\n1 2\n2\n1 3\n3\n5 8 2\n") == "0\n-1\n1"
assert run("2\n3\n7 10 13\n4\n1 2 4 6\n") == "1\n1"
assert run("1\n2\n1000000 1000000\n") == "0"
assert run("1\n2\n1 1000000\n") == "-1"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2つの要素がすでに美しい | 0 | すでに美しい配列を検出します |
 | 遠く離れた 2 つの要素 | -1 | サイズ 2 の不可能な縮小を処理します。 
| 3 つ以上の要素、美しいペアはありません | 1 | 単一の操作で十分であることを確認します。 
| 要素の最大値 | 0 または 1 | オーバーフローせずに大きな数値を処理します。 

## 特殊なケース

 検討してください`[1, 1000000]`。 アルゴリズムは 1 回ループし、`abs(1-1000000)=999999>1`、わかります`n==2`、正しく出力されます`-1`。 もう一つのエッジケースは、`[1000000, 1000000, 1000000]`。 最初の美しいペアをチェックする必要はありませんが、`n>2`、コードの出力`1`これは、隣接するペアを結合できるため機能します。`1000000`、残りの要素との美しい差を生み出します。 不変条件が成り立ちます。2 つより大きい配列は常に 1 つで美しくなります。
