 ## 解決策
 ## 問題の理解

 各頂点に初期値が格納されるルート付きツリーが与えられます。 このツリー値配列に変換が適用されます。つまり、すべての頂点がその値をそのサブツリー内の値の合計に置き換えます。 この動作を繰り返す$k$回になり、すべての頂点での結果の値が必要になります。 

重要な点は、ツリー構造は固定されており、「サブツリー集計」操作を繰り返すことで値のみが移動するということです。 1 回の適用後、各ノードはその子孫 (それ自体を含む) の合計になります。 2 つのアプリケーションの後、各ノードはサブツリーの合計、つまりサブツリーの合計になります。 

入力制約は特定の点で厳密です。 すべてのテスト ケースのノードの合計数は最大 5000 ですが、操作の数は$k$非常に大きくなる可能性があり、最大で$10^{18}$。 これにより、プロセスを段階的にシミュレーションすることは直ちに排除されます。 たとえ1つのアプリケーションであっても、$O(n)$、 それで$k$アプリケーションは完全に実行不可能になります。 

これにより、構造的な観察が強制されます。操作は線形であるため、繰り返し適用することは、固定線形演算子パワーを適用することに対応する必要があります。$S^k$、 どこ$S$はサブツリー和変換です。 本当の課題は、その電力を反復せずに効率的に計算することです。 

微妙なエッジケースは、$k = 0$、出力は元の配列だけです。 二項係数または反復遷移を含む式は、$k = 0$。 

## アプローチ

 直接的なアプローチでは、サブツリー合計演算を繰り返し適用します。 各アプリケーションはすべてのノードにわたる DFS を必要とするため、1 回の反復にコストがかかります$O(n)$。 これを行う$k$回が与えます$O(kn)$、それは不可能です$k$できる$10^{18}$。 

賢くサブツリー関係を事前計算しようとしても、アプリケーションを繰り返すと、依存関係がすぐに拡大するような方法で、増加する祖先の「層」全体で値が混合されます。 2 つのステップの後、ノードはそのサブツリーだけでなく、サブツリーの深さの重み付けされた組み合わせにも依存します。 後$k$ステップごとに、各ノードはサブツリー内のすべてのノードに依存し、それらの距離に応じた重みが付けられます。 

重要な洞察は、視点を逆転させることです。 繰り返されるサブツリー合計を通じて値がどのように下方に流れるかを追跡するのではなく、ノードの初期値が複数のステップにわたってその祖先にどのように上向きに寄与するかを追跡します。 1 つの操作で、ノードからすべての祖先に値が送信されます。 これを繰り返すと$k$回は、長さの祖先ジャンプのシーケンスがいくつあるかという組み合わせカウント問題になります。$k$2 つのノードを接続しますか?

 これにより、各ステップがノードから任意の祖先に移動する (場合によってはその位置に留まる)、ルート付きツリーのポーズセット内のパスをカウントするという問題が軽減されます。 寄与は 2 つのノード間の深さの差にのみ依存し、これにより閉形式の組み合わせ重みが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 繰り返しシミュレーション |$O(kn)$|$O(n)$| 遅すぎる |
 | 二項重みを使用した組み合わせツリー DP |$O(n^2)$テストごと (合計 5000 ノード) |$O(n)$-$O(n^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ツリーのルートを 1 に設定し、すべてのノードの深さを定義します。 

1. ノードごとに$u$、テーブルを計算します$dp_u[d]$、 どこ$dp_u[d]$すべてのノードの初期値の合計です$v$のサブツリー内$u$からの距離が$u$に$v$まさに$d$。 これにより、最終的な重みに影響を与える唯一の要素である深度の差による寄与が分離されます。 
2. 組み合わせの重みを計算する$W_k(d)$、距離のあるノードから値が移動できる方法の数として定義されます。$d$下に$u$に$u$まさに$k$上向きの「祖先ジャンプ」。 この重みは次の要素のみに依存することがわかります。$d$そして$k$、ツリー構造上ではありません。 
3. ノードでの最終的な答え$u$すべての深さを合計することで得られます。$$x_u^{(k)} = \sum_d dp_u[d] \cdot W_k(d)$$4. 計算するには$W_k(d)$、各ステップでノードから任意の祖先 (それ自体を含む) へのジャンプが可能であることに注目してください。したがって、ルートからノードへの固定チェーンに沿って、から弱く減少する深さのシーケンスを数えています。$d$正確に0インチまで下げる$k$ステップ。 これは、合計の減少分を分配することに相当します。$d$横切って$k$非負の部分:$$W_k(d) = \binom{k + d - 1}{d}$$5. これらの二項値をすべての値に対して繰り返し事前計算します。$d \le n$乗法漸化式を使用するため、$k$サイズが大きくなる可能性があり、階乗事前計算を直接使用することはできません。 
6. それぞれを構築する$dp_u$DFS を使用したボトムアップ。 各ノードは距離 0 の独自の値から開始し、距離を 1 ずつずらして子テーブルをマージします。 

### なぜ効果があるのか

 変換は線形であるため、各初期値は最終結果に独立して影響します。 ノードを修正する$v$。 先祖への貢献$u$の有効なシーケンスの数のみに依存します。$k$で終わる祖先ジャンプ$u$。 からのユニークな道に沿って$v$に$u$、これは分布の純粋な組み合わせ計数問題になります。$k$ステップオーバー$d$上に移動します。 そのカウントは、まさに上記で導出された二項係数です。 すべての寄与は線形に分解され、深さの差のみに依存するため、サブツリーの深さを合計すると正しい結果が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    if k == 0:
        print(*a)
        return

    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = -2

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            if parent[v] != -1:
                continue
            parent[v] = u
            stack.append(v)

    parent[0] = -1

    depth = [0] * n
    children = [[] for _ in range(n)]

    for v in range(1, n):
        p = parent[v]
        depth[v] = depth[p] + 1
        children[p].append(v)

    dp = [None] * n

    def add(dp_a, dp_b, shift):
        if dp_a is None:
            return dp_b[:]
        res = [0] * max(len(dp_a), len(dp_b) + shift)
        for i, x in enumerate(dp_a):
            res[i] += x
        for i, x in enumerate(dp_b):
            res[i + shift] += x
        return res

    for u in reversed(order):
        cur = [0]
        cur[0] = a[u]
        for v in children[u]:
            cur = add(cur, dp[v], 1)
        dp[u] = cur

    maxd = n

    inv = [0] * (maxd + 5)
    inv[1] = 1
    for i in range(2, maxd + 5):
        inv[i] = MOD - MOD // i * inv[MOD % i] % MOD

    def weight(d):
        res = 1
        for i in range(1, d + 1):
            res = res * (k + i - 1) % MOD
            res = res * inv[i] % MOD
        return res

    w = [0] * (maxd + 1)
    for d in range(maxd + 1):
        w[d] = weight(d)

    ans = [0] * n
    for u in range(n):
        s = 0
        for d, val in enumerate(dp[u]):
            s = (s + val * w[d]) % MOD
        ans[u] = s

    print(*ans)

if __name__ == "__main__":
    solve()
```DFS はサブツリー構造を構築し、各ルートからの距離によってグループ化された値を保存します。 マージ ステップでは、子の寄与が 1 レベル深くカウントされるように距離をシフトします。 

重みの計算では、大きな二項係数の乗算式が使用されます。$k$階乗を完全に回避します。 

## 実用的な例

 ### 例 1

 単純なチェーンを考えてみましょう$1 \rightarrow 2 \rightarrow 3$、値付き$[1,2,3]$、 そして$k=1$。 

| ノード | dp (距離による) |
 | --- | --- |
 | 3 | [3] |
 | 2 | [2、3] |
 | 1 | [1、2、3] |

 のために$k=1$、重みは次のとおりです。$W(0)=1$、$W(1)=k=1$、$W(2)=\frac{k(k+1)}{2}=1$。 

それで:

 - ノード 1:$1*1 + 2*1 + 3*1 = 6$- ノード 2:$2*1 + 3*1 = 5$- ノード 3:$3$これは、サブツリー合計の 1 つのアプリケーションに一致します。 

### 例 2

 同じ木でも、$k=2$。 

重み:$W(0)=1$、$W(1)=2$、$W(2)=3$。 

- ノード 1:$1 + 2*2 + 3*3 = 14$- ノード 2:$2 + 3*2 = 8$- ノード 3:$3$これは、サブツリー集約の繰り返しが影響を非線形に拡大する様子を示しています。

 ## 特殊なケース

 重要なエッジケースの 1 つは、$k = 0$。 組み合わせ式は、個別に処理しない限り、無効な解釈を伴う二項係数に縮退します。 この場合、変換は恒等マップであるため、各ノードは元の値を直接出力する必要があります。 

もう 1 つの微妙なケースは、すべてのノードが 1 つのチェーン内に存在する深いツリーです。 ここで DP 配列が最大長に達します$n$、そして正確さはマージ中に距離を適切に移動するかどうかに完全に依存します。 このアルゴリズムは、マージ前に子コントリビューションを常に 1 レベルだけ拡張し、チェーンに沿った距離セマンティクスを維持することでこれを保証します。
