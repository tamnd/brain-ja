 ## 解決策
 ## 問題の理解

 標準の 16 進 Web 形式で書かれた RGB カラーのシーケンスが与えられます。各色は次で始まります。`#`その後に 6 つの小文字の 16 進数が続きます。 これらの 6 文字は、赤、緑、青の 3 つの整数をエンコードし、それぞれ 0 ～ 255 の範囲にあり、チャネルごとに 2 つの 16 進数として保存されます。 

すべての入力色に対して、その補色を構築する必要があります。 対応する RGB コンポーネントの合計が 255 になる場合、2 つの色は補色になります。つまり、元の色にコンポーネントがある場合、`(R, G, B)`、出力色は次のようにする必要があります。`(255 − R, 255 − G, 255 − B)`、その後、必要に応じて小文字と先頭のゼロを含む、適切にフォーマットされた 16 進文字列に変換されます。 

入力サイズはテスト ケースの点で大きく、最大 10^4 です。 各テスト ケースは独立して処理され、各操作は色ごとに一定時間行われます。 これにより、二次関数や、テスト ケースごとに O(1) を超える繰り返し文字列スキャンを伴うものは除外されます。 文字ごとに直接変換するだけで十分です。 

微妙な失敗のケースは、フォーマットに起因します。 各 RGB コンポーネントは、常に 2 桁の 16 進数を使用して表現する必要があります。 これを無視すると、0 のような値になります。`0`の代わりに`00`、必要な固定長形式が壊れます。 

たとえば、入力が`#000000`、正しい出力は次のとおりです。`#ffffff`。 パディングを忘れた単純な実装では、次のような問題が発生する可能性があります。`#fff`、これは仕様上無効です。 

もう 1 つのエッジの詳細は、大文字と小文字の区別です。 出力は小文字の 16 進数である必要があります。 のように大文字を使用する`#E0E1CC`たとえ数値的に正しくても拒否される可能性があります。 

## アプローチ

 ブルートフォース解釈では、各文字を手動で解析して各 16 進数の文字列を整数のカラー値に変換し、次に 255 から各チャネルを引いた値を計算し、最後に整数を 16 進数に繰り返し変換して文字列を再構築します。 これはテスト ケースごとにすでに O(1) ですが、文字列を繰り返し連結したり、遅い手動の基数変換を使用したりするなど、非効率的に実装すると、最大 10^4 の入力にわたって文字操作が繰り返されるため、実際には性能が低下する可能性があります。 

重要な点は、各チャネルが独立しており、常に [0, 255] に制限されているため、Python の組み込みの整数解析および書式設定関数で十分かつ最適であるということです。 必要なのは、固定部分文字列を抽出し、それらを 1 回変換し、255 から減算し、2 桁の 16 進形式を使用して元の形式に戻すことだけです。 これにより、手動による桁ごとの処理が完全に回避されます。 

入力の構造により一定サイズの文字列が保証されるため、最適な解決策は、補助データ構造を使用せずにテスト ケースごとに単純に直接変換することになります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 色の文字列を読み取る`s`。 それは常に形を持っています`#RRGGBB`。 この固定構造により、スキャンせずに直接スライスできます。 
2. を使用して赤いコンポーネントを抽出します。`s[1:3]`、緑を使用`s[3:5]`、および青を使用して`s[5:7]`。 各部分文字列は正確に 2 つの 16 進文字であり、有効な解析が保証されます。 
3. Base-16 変換を使用して、各部分文字列を 16 進数から整数に変換します。 これにより、`(R, G, B)`数値形式で。 
4. 255 から減算して各チャネルの補数を計算し、次の結果を生成します。`(255 − R, 255 − G, 255 − B)`。 このステップはチャネルごとに独立しており、問題の相補性の定義を反映しています。 
5. 結果の各整数を 2 文字の小文字 16 進文字列に変換し直します。 値が 16 未満の場合は、先頭にゼロを含める必要があります。 この固定幅形式では、必要な RGB エンコーディングが保持されます。 
6. 結果を順番に連結して先頭に追加します`#`最終的な出力文字列を形成します。 

### なぜ効果があるのか

 各 RGB コンポーネントは、固定の 8 ビット範囲で独立してエンコードされます。 変革`x → 255 − x`はこのドメインのインボリューションです。つまり、これを 2 回適用すると元の値が返されます。 16 進表現は間の全単射なので、`[0, 255]`そして`00`に`ff`、整数への変換、変換、および書式設定を戻すと、正確さが正確に保持されます。 コンポーネント間の相互作用は存在しないため、チャネルを個別に処理しても不整合が生じる可能性はありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        s = input().strip()

        r = int(s[1:3], 16)
        g = int(s[3:5], 16)
        b = int(s[5:7], 16)

        cr = 255 - r
        cg = 255 - g
        cb = 255 - b

        out.append("#" + format(cr, "02x") + format(cg, "02x") + format(cb, "02x"))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは固定スライス位置に依存しているため、文字ごとのループのオーバーヘッドが回避されます。 それぞれ`int(..., 16)`call は、先行ゼロであっても変換を安全に処理します。 の`format(x, "02x")`小文字の出力と必須のゼロ埋め込みの両方を保証します。 

よくある実装上の間違いは、`hex(x)`直接実行すると、次のような文字列が生成されます。`0xa`の代わりに`0a`。 手動で後処理しない限り、フォーマットが壊れてしまいます。 もう一つの微妙な問題は忘れることです`.strip()`入力行に改行文字が残ると、スライスの妨げになる可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()

    def solve():
        t = int(sys.stdin.readline())
        res = []
        for _ in range(t):
            s = sys.stdin.readline().strip()
            r = int(s[1:3], 16)
            g = int(s[3:5], 16)
            b = int(s[5:7], 16)
            res.append("#" + format(255-r, "02x") + format(255-g, "02x") + format(255-b, "02x"))
        print("\n".join(res))

    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# minimum value edge
assert run("1\n#000000") == "#ffffff"

# maximum value edge
assert run("1\n#ffffff") == "#000000"

# mixed boundary
assert run("1\n#0f10f0") == "#f0ef0f"

 ## 特殊なケース

 オールゼロカラー`#000000`は、先行ゼロの 16 進解析とフォーマットの正しい処理を示しています。 各チャネルは 255 になり、次のように出力する必要があります。`ff`、パディング ロジックが欠落していないことを確認します。 

オールホワイトカラー`#ffffff`反対の極端な点をチェックします。 各チャネルは 0 になり、次のように表示されます。`00`。 先頭のゼロを削除する単純なフォーマッタは、誤って出力します。`#0`ただし、固定幅書式設定により正確さが保証されます。 

次のような混合値のケース`#0f10f0`独立したチャネル処理がコンポーネント間で干渉しないようにします。 各バイトは個別に反転されるため、RGB 位置間の位置合わせが維持され、偶発的な並べ替えや計算エラーの共有が防止されます。
