 ## 解決策
 ## 問題の理解

 ルートがノード 1 である根付きツリーが与えられています。すべての葉は同じ深さにあるため、ツリーは葉の深さに関して完全にバランスが取れていますが、分岐構造は任意です。 

各蝶はノードに接続され、指定された時間に消えます。 Ao は時間 0 の任意のリーフから開始され、最終的にはルートに到達する必要があります。 深さのノードからの移動`d`深さまで`d - 1`常に 1 単位時間がかかります。 

通常、Ao は親にのみ移動できます。 旅の途中で、彼女は代わりに特別な力を使用し、現在のノードから深層に移動する可能性があります`d`深さの任意のノードへ`d - 1`。 

Ao がノードにアクセスするたびに`t`、そのノードにあるすべての蝶のうち、消滅時間が少なくとも`t`集めることができる。 

タスクは、収集された蝶の数が最大になるように、開始する葉とオプションの特別な動きを選択することです。 

入力サイズが大きいです。 すべてのテスト ケースにわたって、ノードの総数とバタフライの総数は両方とも最大で`2 · 10^5`。 すべてのリーフをすべての可能なジャンプ位置とともに検査するソリューションは、非常に遅すぎます。 テスト ケースごとに線形に近い時間が必要です。 

微妙な観察は、ノードへの実際の到着時間はその深さのみに依存するということです。 すべての葉が深いところにあるので、`H`、深さのノード`d`いつもその時間に訪れます`H - d`、選択したルートに関係なく。 これにより、問題が大幅に単純化されます。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

アオが到着した瞬間に消えてしまう蝶について考えてみましょう。```
3 1
1 2
1 3
1 1
```葉の深さは 1 なので、根元には時間 1 で到達します。`t = 1`状態は良いのでまだ収集可能です`current time ≤ ti`。 

もう一つの罠は、必殺技が時間短縮にならないことだ。 深さから`d`深さまで`d - 1`、通常の親の動きと特別な動きの両方のコストはちょうど 1 ユニットです。 必殺技は場所のみを変更し、到着時間は変更しません。 

例えば：```
    1
   / \
  2   3
 /     \
4       5
```ノード 4 からノード 3 にジャンプしても、時間 1 では深さ 1 に到達します。ジャンプを時間のショートカットとして扱うソリューションでは、不正確な適格性チェックが行われます。 

3 番目の落とし穴は、必殺技がオプションであることを忘れていることです。 場合によっては、最適なルートが単に通常のリーフからルートへのパスである場合もあります。 

## アプローチ

 ブルートフォースアプローチでは、すべての開始リーフ、特別な動きが使用されるすべての可能な深さ、および次に高いレベルのすべての宛先ノードを列挙します。 候補となるルートごとに、移動をシミュレートし、収集された蝶を数えることができます。 

すべての有効な旅はまさにその方法で説明できるため、これは概念的に機能します。 残念ながら、葉の数は線形になる可能性があります。`n`、可能なジャンプの選択肢の数も線形になる可能性があります。 結果として生じる複雑さは容易に達成できます。`O(n^2)`あるいはさらに悪いことに、それは不可能です`2 · 10^5`ノード。 

重要な観察は、到着時間は深さのみに依存するということです。 

させて`H`は共通の葉の深さになります。 

節点の蝶`v`場合は収集可能です```
ti ≥ H - depth(v)
```この条件はノードとバタフライのみに依存します。 選択したルートには依存しません。 

したがって、各ノードを前処理して次の計算を行うことができます。```
value(v) = number of butterflies at v that are collectible whenever v is visited
```元の問題は純粋に構造的なものになります。 

ノードに立った状態で必殺技を使用した場合`a`深さの`d`。 

ジャンプする前に、アオはある葉っぱから上に向かって道をたどります。`a`。 

ジャンプ後、Ao はどこかのノードに着地します`b`深さで`d - 1`そして、からの祖先チェーンをたどります。`b`根元まで。 

収集されたノードは 2 つの独立した部分に分割されます。 

1.からの下向きのチェーン`a`どこかの葉っぱに。 
2. 根元から上向きのチェーン`b`。 

これら 2 つの部分には異なる深度範囲が含まれるため、それらのスコアは個別に最適化できます。 

これにより、問題は 2 つのツリー動的計画計算に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) 以上 | O(n) | 遅すぎる |
 | 最適 | O(n + m) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ノード 1 でツリーをルートし、すべてのノードの深さを計算します。 
2. 共通の葉の深さを見つける`H`。 
3. すべての蝶のために`(a, t)`、どうかを確認してください```
t ≥ H - depth(a)
```本当なら増やす`value(a)`1つずつ。 

このステップの後、すべてのノードは、そのノードが訪問されるたびに確実に収集できる蝶の数を保存します。 
4. コンピューティング```
prefix(v) = sum of value(x)
            along the root-to-v path
```DFS または BFS トラバーサルを使用します。 
5. あらゆる深さに対して`d`、 店```
bestPrefix[d] =
    maximum prefix(v)
    among all nodes at depth d
```ジャンプが深い位置に着地した場合`d`、これはルートのルート部分から取得できる最高のスコアです。 
6. ボトムアップ DP を計算します。```
down(v) =
    maximum score of a path
    starting at v and ending at a leaf
```葉の場合:```
down(v) = value(v)
```内部ノードの場合:```
down(v) = value(v) + max(down(child))
```7.必殺技を使わない旅を考える。 

そのような旅はまさに葉から根までの道です。 

そのスコアは次のとおりです`prefix(leaf)`。 

すべての葉の最大値で答えを初期化します。 
8.必殺技を使う旅を考えてみましょう。 

ノードからジャンプを実行すると仮定します。`v`深さで`d ≥ 1`。 

リーフ側の最も優れた貢献は次のとおりです。`down(v)`。 

ルート側の最も優れた貢献は次のとおりです。`bestPrefix[d - 1]`。 

合計スコアは```
down(v) + bestPrefix[d - 1]
```すべての非ルート ノードの最大値で答えを更新します。 
9. 最大スコアを出力します。 

### なぜ効果があるのか

 訪問されたすべてのノードの深さ`d`時間に達しました`H - d`、ルートに関係なく。 したがって、蝶が収集できるかどうかは、そのノードと消滅時間のみに依存します。 蝶をノードの重みで置き換えると、目的が正確に維持されます。 

奥のノードから必殺技を使用した場合`d`、ルートは 2 つの互いに素な深さの間隔に分解されます。 奥行きより下の部分`d`リーフからノードへのチェーンに寄与します。その最適値は`down(v)`。 奥行きより上の部分`d`ある深さで終わるルートからノードへのチェーンに貢献します`d - 1`ノード、その最適値は`bestPrefix[d - 1]`。 

2 つの間隔は異なる深さを使用するため、重複することはなく、個別に最適化できます。 すべての有効なルートは、まさに 1 つのそのような分解に対応し、すべての分解は有効なルートに対応します。 可能なすべてのジャンプ位置の最大値を取得し、ジャンプしない場合も考慮することで、最適な答えが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n, m = map(int, input().split())

        g = [[] for _ in range(n + 1)]

        for _ in range(n - 1):
            u, v = map(int, input().split())
            g[u].append(v)
            g[v].append(u)

        parent = [0] * (n + 1)
        depth = [0] * (n + 1)

        order = [1]
        parent[1] = -1

        for v in order:
            for to in g[v]:
                if to == parent[v]:
                    continue
                parent[to] = v
                depth[to] = depth[v] + 1
                order.append(to)

        H = 0
        for v in range(2, n + 1):
            if len(g[v]) == 1:
                H = depth[v]
                break

        value = [0] * (n + 1)

        for _ in range(m):
            a, ti = map(int, input().split())
            if ti >= H - depth[a]:
                value[a] += 1

        prefix = [0] * (n + 1)
        best_prefix = [-10**18] * (H + 1)

        for v in order:
            if v == 1:
                prefix[v] = value[v]
            else:
                prefix[v] = prefix[parent[v]] + value[v]

            d = depth[v]
            if prefix[v] > best_prefix[d]:
                best_prefix[d] = prefix[v]

        down = value[:]

        for v in reversed(order):
            best_child = 0

            for to in g[v]:
                if to == parent[v]:
                    continue
                if down[to] > best_child:
                    best_child = down[to]

            down[v] = value[v] + best_child

        answer = 0

        for v in range(2, n + 1):
            if len(g[v]) == 1:
                answer = max(answer, prefix[v])

        for v in range(2, n + 1):
            d = depth[v]
            answer = max(answer, down[v] + best_prefix[d - 1])

        ans.append(str(answer))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```最初の走査ではツリーをルート化し、深さを計算します。 すべての葉は同じ深さを共有しているため、任意の葉を見つけるとすぐに共通の値が得られます。`H`。 

バタフライ処理ステージでは、元の時間依存の問題がノードの重みに変換されます。 その時点以降、アルゴリズムの残りの部分が再び消失時間を調べる必要はなくなります。`prefix[v]`ルートからルートまでの全体のスコアを保存します。`v`鎖。 あらゆる深度での最大値を記録することで、「ジャンプが深度に着地した場合」という質問に即座に答えることができます。`d`、ルート側の最高のスコアはどれくらいですか?」

 ボトムアップの DP が計算されます。`down[v]`、下で最も収益性の高いリーフを選択することで得られる最高のスコア`v`。 ルートからリーフへのパスは 1 つの子のみを通過できるため、遷移では子の最大値が使用されます。 

よくある間違いは、ジャンプ境界を二重にカウントすることです。 式```
down(v) + bestPrefix[d - 1]
```2 つの部分が異なる深さを占めるため、これを回避できます。 深さのノード`d`のみに属する`down(v)`、宛先ノードはプレフィックス部分のみに属します。

 ## 特殊なケース

 等価境界を考えてみましょう。```
1
2 1
1 2
1 1
```葉の深さは、`H = 1`。 ルートは時間に訪問されます`1`。 蝶もいつか消える`1`、コレクション可能です。 前処理チェックでは次を使用します。```
ti >= H - depth(node)
```になる```
1 >= 1
```そして蝶を正確に数えます。 

ここで、ジャンプにより位置は変更されるが、時間は変更されない場合を考えてみましょう。```
1
6 2
1 2
1 3
2 4
2 5
3 6
4 0
3 1
```ノード 4 は深さ 2 で寄与し、ノード 3 は深さ 1 で寄与します。ジャンプを時間短縮として扱う誤ったソリューションでは、不正確な到着時間が計算されます。 アルゴリズムはこれを決して行いません。 到着時間は深さのみから決定されるため、両方の蝶が正しく数えられ、答えが得られます。`2`。 

最後に、ジャンプをスキップすることが最適な状況を考えてみましょう。```
1
3 1
1 2
1 3
2 0
```リーフ 2 から開始すると、すでに唯一の蝶が収集されています。 ジャンプすると別のブランチに移動するため、スコアを向上させることはできません。 このアルゴリズムは、すべてのリーフからルートへのパスを明示的に評価します。`prefix(leaf)`したがって、ジャンプなしの最適値が見逃されることはありません。
