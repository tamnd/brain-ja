 ## 解決策
 ## 問題の理解

 配列が与えられ、順序を維持しながら要素のサブセットを削除することによって形成されたすべてのサブシーケンスを考慮します。 結果として得られるシーケンスごとに、2 つの隣接する要素が等しい回数を数えます。 この回数をフラッシュ回数と呼びます。 タスクは、正確に k 個のフラッシュを生成するサブシーケンスの数を数えることです。 

サブシーケンスについて考える便利な方法は、その実行を通して見ることです。 ランは、等しい値の最大ブロックです。 サブシーケンスに長さ L のランがある場合、そのランは L から 1 回の点滅を引いたものになります。 すべての実行を合計すると、フラッシュの総数が得られます。 同様に、サブシーケンスの長さが m で、r 回実行される場合、フラッシュ数は m から r を引いたものになります。 

この再公式化が重要なのは、フラッシュが元の配列内の絶対位置ではなく、実行を延長する頻度と新しい実行を開始する頻度によって完全に決定されることを示しているためです。 

通常のサブシーケンス問題とは異なる方向で制約が厳しくなります。 配列の長さは 200,000 に達することがありますが、k は最大 200 です。 これは、k の次元を小さく保ち、構造全体を集約する動的プログラミング アプローチを強く示唆しています。 任意のサブシーケンスを明示的に追跡したり、位置ペアごとの状態を維持したりするソリューションは、すぐに大きすぎます。 

単純な試みでは、すべてのサブシーケンスが生成され、フラッシュが直接計算されます。 これにはすでに 2^n 個のオブジェクトが含まれており、n が約 30 の場合でもこれは実行不可能になります。 もう 1 つのよくある失敗は、「最後の値」次元を圧縮せずにサブシーケンスに対して DP を実行しようとすることです。これには、すべての値の間の遷移を明示的に追跡する必要があり、メモリ内ですぐに爆発的に増加します。 

「等しい隣接ペアの数」だけを考えると、さらに微妙な落とし穴が現れます。 元の配列内の等しい要素によって寄与されるペアを数えようとするかもしれませんが、サブシーケンス内の隣接関係は配列内の隣接関係ではないため、すべての構造が失われます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 すべてのサブシーケンスを列挙してシミュレーションし、隣接するペアをスキャンしてフラッシュをカウントします。 これは定義に直接従うため概念的には機能しますが、指数関数的な時間を必要とします。 n が 200000 までの場合、すべての部分列を表すことさえ不可能です。 

重要な構造的洞察は、最後に選択した値とこれまでのフラッシュの数という 2 つの情報のみを追跡しながら、サブシーケンスを段階的に構築できることです。 新しい要素を追加するときは、新しいサブシーケンスを開始するか、同じ値で既存のサブシーケンスを継続してフラッシュ数を増やすか、別の値に切り替えてフラッシュ数を変更しないかのいずれかを行います。 

問題は、「最後の値」がすべての個別の値にわたるため、単純な DP では値ごとに O(nk) 状態が必要となり、単純な 2D 配列でグローバルに維持するには大きすぎます。 重要な観察は、位置 i での固定値 x への遷移は、個々の値ではなく、以前の最後の値すべての集計カウントのみに依存するということです。 これにより、値ごとの DP 配列を維持しながら、k にわたるグローバル合計を使用して更新することができます。 

配列を左から右に処理します。 各値 v について、dp[v][t] を維持します。これは、正確に t を持つ値 v で終わるサブシーケンスの数が点滅します。 また、すべての v にわたる dp[v][t] の合計である total[t] も維持します。 

新しい出現 x を処理すると、dp[x] のみが変更されます。 他のすべての dp[v] は、x が現在処理されているかどうかに依存しないため、有効なままです。 x は、x で終わる新しいサブシーケンスのみを追加します。 

この局所性により、小さい係数 k を使用して n 内で解が線形に保たれます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 値の状態による最適な DP | O(nk) | O(nk) | 承認済み |

 ## アルゴリズムのチュートリアル

私たちは2つの体制を維持しています。 1 つ目は dp[v] で、値 v で終わるサブシーケンスのカウントを格納するサイズ k+1 の配列です。2 つ目は total[t] で、dp[v][t] のすべての v の合計です。 

概念的には空のサブシーケンスも含めますが、それを dp に明示的に格納するのではなく、開始メカニズムとしてのみ扱います。 

### ステップ

 1. dp[v] を空の配列として初期化し、total[t] をすべての t に対してゼロとして初期化します。 これは、要素がまだ処理されていないことに相当します。 
2. 配列を左から右に処理します。 位置 i での現在の値を x とします。 
3. 値 x に対して新しい寄与配列 add[t] を作成します。 これにより、a[i] を含めた後、x で終わるすべてのサブシーケンスが保存されます。 
4. a[i] のみからなる新しいサブシーケンスを開始します。 単一の要素がフラッシュを生成しないため、これは add[0] += 1 に寄与します。 
5. x とは異なる任意の値で終了する既存のサブシーケンスを拡張します。 固定 t の場合、total[t] のすべてのサブシーケンスは拡張できますが、x を x に拡張するとフラッシュが増加するため、すでに x で終わるサブシーケンスは特別です。 そこで、異なる値で終わる部分列の数として total[t] - dp[x][t] を使用し、t を変更せずに拡張します。 
6. x で終わるサブシーケンスを拡張します。 このような t-1 回の点滅を持つサブシーケンスは、x を再度追加すると t 回の点滅を持つサブシーケンスになるため、dp[x][t-1] を add[t] に追加します。 
7. add を計算した後、古い dp[x] を減算し、add から得られた新しい dp[x] を加算することで合計を更新します。 
8. dp[x] を add に置き換えます。 

### なぜ効果があるのか

 任意の時点で、 dp[v][t] は、最後の要素が v でフラッシュ カウントが t である、これまでに確認されたすべてのサブシーケンスを正確に表します。 すべてのサブシーケンスは、現在の要素に関与しないか、その要素で終了します。 新しい x の発生を処理する場合、すべての有効な拡張子は、x から新たに開始するか、以前に有効だったサブシーケンスに x を追加することによってキャプチャされます。 「x で終わる」と「x で終わらない」への分解は網羅的であり、ばらばらであるため、すべてのサブシーケンスは 1 回だけカウントされ、遷移が見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        dp = {}
        total = [0] * (k + 1)

        for x in a:
            if x not in dp:
                dp[x] = [0] * (k + 1)

            old = dp[x]
            add = [0] * (k + 1)

            add[0] += 1

            for tval in range(k + 1):
                if total[tval]:
                    base = total[tval] - old[tval]
                    if base:
                        add[tval] += base

            for tval in range(1, k + 1):
                add[tval] += old[tval - 1]

            for tval in range(k + 1):
                delta = add[tval] - old[tval]
                if delta:
                    total[tval] += delta
                    old[tval] = add[tval]
                else:
                    old[tval] = add[tval]

        print(total[k] % 998244353)

if __name__ == "__main__":
    solve()
```実装の中核は、値ごとの DP テーブルとグローバル合計配列です。 更新ステップでは、現在の要素値の影響のみを慎重に分離し、他の dp ブロックが影響を受けないようにします。 引き算`total[t] - old[t]`これは、既に同じ値で終了するサブシーケンスを二重にカウントすることを回避する重要なメカニズムです。 

k は 200 で制限されており、すべての操作はその次元で線形であるため、k にわたるループは効率的であるのに十分な大きさのままです。 

## 実用的な例

 配列を考慮してください`[1, 2, 2, 1]`と`k = 1`。 

ゼロ以外のエントリのみを追跡します。 

| ステップ | × | 更新後の dp[x] | 合計[0] | 合計[1] |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | [1, 0] | 1 | 0 |
 | 2 | 2 | [1, 0] | 3 | 0 |
 | 3 | 2 | [2、1] | 5 | 1 |
 | 4 | 1 | [2、1] | 8 | 5 |

 すべての要素を処理した後、total[1] は 5 になり、1 回のフラッシュによるサブシーケンスの数と一致します。 

ここで考えてみましょう`[1, 1, 1]`と`k = 0`。 サブシーケンス内に繰り返しの隣接関係が含まれていない限り、すべてのサブシーケンスにはフラッシュがありません。これは、連続した等しい寄与を選択した場合にのみ発生します。 

| ステップ | × | 更新後の dp[x] | 合計[0] |
 | --- | --- | --- | --- |
 | 1 | 1 | [1] | 1 |
 | 2 | 1 | [2] | 2 |
 | 3 | 1 | [3] | 3 |

 k = 0 の場合、最終的な答えは 3 です。これは、1 回の実行で同じ値で構成される空ではないすべてのサブシーケンスに対応します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nk) | 各要素は、サイズ k | の単一の dp 配列を更新します。 
| スペース | O(nk) | 個別の値ごとに 1 つの dp 配列、それぞれのサイズは k |

 すべてのテスト ケースの n の合計は 200000 で制限され、k は最大 200 であるため、DP 遷移の数は数千万以内に収まり、時間制限内に問題なく収まります。 メモリ使用量は、k 次元に制限があるため、大きなメモリ制限の下でも許容可能なままです。

import sys, io

MOD = 998244353

def run(inp: str) -> str:
    import sys
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    res = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        dp = {}
        total = [0] * (k + 1)

        for x in a:
            if x not in dp:
                dp[x] = [0] * (k + 1)

            old = dp[x]
            add = [0] * (k + 1)

            add[0] += 1

            for tval in range(k + 1):
                add[tval] += total[tval] - old[tval]

            for tval in range(1, k + 1):
                add[tval] += old[tval - 1]

            for tval in range(k + 1):
                total[tval] += add[tval] - old[tval]
                old[tval] = add[tval]

        res.append(str(total[k] % MOD))
    return "\n".join(res)

 ## 特殊なケース

 最小の単一要素配列は、ゼロ フラッシュに寄与する 1 つの要素で構成されるサブシーケンスでアルゴリズムが dp を正しく初期化するかどうかを示します。 この場合、 dp は値の新しいエントリを作成し、add[0] = 1 を割り当て、total[0] が 1 になり、正しい結果が生成されます。 

すべて同じ値を持つ配列は、同じ値内で拡張する場合にのみ、繰り返される更新によってフラッシュが正しく蓄積されるかどうかをテストします。 同じ値が処理されるたびに、dp[x][t-1] 遷移によってフラッシュ カウントが増加し、値をまたぐ遷移は干渉しません。 

すべての個別の値を含む配列は、「値の切り替え」ロジックを強調します。 各 x を処理する前は dp[x] が常に 0 であるため、すべてのサブシーケンス拡張は total[t] からのみ得られ、dp[x] の減算は問題になりません。 このアルゴリズムは、k = 0 での単純なサブシーケンスのカウントに削減され、k = 0 で 2^n - 1 個のサブシーケンスが正しく生成されます。
