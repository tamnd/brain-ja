 ## 解決策
 ## 問題の理解

 私たちに与えられた一行は、$n$川沿いに設置されたランプが座標を増加させていく$x_1 < x_2 < \dots < x_n$。 旅行者はランプ 1 から出発し、ランプに到達したいと考えています$n$。 At each lamp$i$, 次に進むには2つの方法があります。 

最初のオプションはローカル ステップです: move from$i$に$i+1$そして固定費を支払う$a_i$。 これは、チェーンに沿った標準パスのように動作します。 

2 番目のオプションは、現在のランプからの長い「ホタルジャンプ」です。$i$、後のランプに直接ジャンプできます。$j > i$。 これには費用がかかります$b_i + (x_j - x_i)^2$。 コストは、開始位置、着地位置、およびポジションごとのペナルティによって異なります。$b_i$。 ただし、この特殊ジャンプが使えるのはせいぜい$k$旅行全体の合計回数。 

目標は、ランプに到達するまでの総スタミナコストを最小限に抑えることです。$n$、通常の隣接する動きを混合し、最大でも$k$二次コストのロングジャンプ。 

制約は非常に重要です。 すべてのテスト ケースにわたるランプの合計数は最大です。$2 \cdot 10^5$、 その間$k \le 200$。 これにより、二次関数的なものはすべて即座に除外されます。$n$テストケースごと、またはすべてのパスを明示的に考慮しようとします。 どのような解決策でも対処する必要があります$n$ほぼ直線的になり、 の小さな値を使用します。$k$主な最適化軸として。 

すべての状態とランプのすべてのペア間の遷移にわたる単純な動的プログラミングには、次のような遷移が含まれます。$i \to j$みんなのために$i < j$、生産$O(n^2)$レイヤーごとの動作が遅すぎます。 

各ステップでホタルジャンプを使用するかどうかを欲張って決定しようとすると、微妙な失敗モードが 1 つ現れます。 ジャンプのコストは将来の位置に依存するため、局所的に優れたジャンプは全体的に優れた構造をブロックする可能性があります。 たとえば、からのジャンプ$i$に$j$大きいため高価に見えるかもしれません$(x_j-x_i)^2$、しかし、それは私たちをより安価な将来のジャンプに向けて位置付ける可能性があります。 このグローバル構造への依存により、DP 定式化が強制されます。 

## アプローチ

 直接定式化すると、次のように定義されます。$dp[t][i]$ランプに到達するための最小コストとして$i$正確に使用して$t$ホタルがジャンプします。 

州から$(t, i)$、2 つのトランジション タイプがあります。 歩いて行けます$i+1$費用がかかる$a_i$、または、ホタルジャンプを使用することもできます。$i$どれにも$j > i$、ジャンプ数を に増やします。$t+1$そして支払い$b_i + (x_j - x_i)^2$。 

これを文字通り展開すると、各層は$t$すべてのペアにわたる遷移が含まれます$i < j$、それは次のことにつながります$O(n^2)$レイヤーごとに作業し、$O(kn^2)$全体。 と$n = 2 \cdot 10^5$、これはまったく不可能です。 

重要な構造は、ジャンプコストを分離した形式で書き換えることができるということです。$i$そして$j$。 正方形を拡張すると、$$(x_j - x_i)^2 = x_j^2 - 2x_i x_j + x_i^2.$$したがって、移行は次のようになります$$dp[t][i] + b_i + x_i^2 + x_j^2 - 2x_i x_j.$$固定用$t$そして固定目標$j$、 用語$x_j^2$は一定です。 残りの式は最小値を超えています$i$における一次関数の$x_j$、ここでそれぞれ$i$傾きのある線を定義します$-2x_i$そしてインターセプト$dp[t][i] + b_i + x_i^2$。 これにより、各層が凸包トリック クエリ問題に変わります。 

したがって、各層は 2 つのフェーズで動作します。 まず計算します$dp[t]$ウォークトランジションのみを使用してチェーンに沿って移動します。 次に、すべての状態を使用します$i$レイヤーで$t$一連の行を構築し、すべての行についてクエリを実行します。$j$の候補値を生成します。$dp[t+1][j]$。 最後に、レイヤー内でウォークトランジションを再度伝播します。$t+1$。 

これにより、各層が単調な凸包を持つ線形時間に短縮されます ($x_i$ソートされています)、与える$O(n)$レイヤーごとに、$O(nk)$全体。

 | レイヤーごとの凸包 DP |$O(kn)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 firefly の使用をレイヤーごとに処理し、各値を処理します。$t$別に。 

1.初期化$dp[0][1] = 0$他のすべての値は無限大です。 これは、ジャンプを使用せずにランプ 1 から開始することを表します。 
2. レイヤーごとに$t$から$0$に$k$、最初にチェーンに沿って前方に歩行トランジションを伝播します。 それぞれについて$i$、リラックスします$dp[t][i+1]$使用して$dp[t][i] + a_i$。 これにより、同じ数のホタル ジャンプ内で、考えられる隣接する動きのシーケンスがすべて考慮されるようになります。 
3. 歩行伝播後、すべての位置から凸包構造を構築します$i$レイヤーで$t$。 各ポジション$i$からのホタルジャンプの開始を表す行を提供します。$i$。 この線は、クエリが次のもののみに依存するようにコストを書き換えることによって導出されます。$x_j$。 傾斜は$-2x_i$そして切片は$dp[t][i] + b_i + x_i^2$。 
4. 目標ポジションを処理します$j$昇順に$x_j$。 それぞれについて$j$、凸包をクエリして、以前の最良のものを見つけます。$i$、の候補値を計算します。$dp[t+1][j]$。 このステップでは、次で終了するすべての可能な単一のファイアフライ ジャンプをキャプチャします。$j$。 
5. すべてのジャンプが適用されたら、レイヤー内で歩行トランジションを再度伝播します。$t+1$なぜなら、ジャンプを介して特定の位置に到着した後も、追加のジャンプを消費せずに前に歩くことができるからです。 
6.すべてになるまで繰り返します$k$レイヤーが処理され、最終的に返されます$dp[t][n]$全体$t \le k$。 

正確さは動きの種類の分離にかかっています。ウォーキングではジャンプの回数が維持されますが、ホタルのトランジションではジャンプの回数が 1 つずつ増加します。 各レイヤーはまず歩行を完全に安定させ、次にその安定状態から可能なすべてのジャンプを適用して、インタラクションが見逃されないようにします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**30

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        x = list(map(int, input().split()))
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))

        dp = [INF] * n
        dp[0] = 0

        def walk(dp):
            for i in range(n - 1):
                if dp[i] + a[i] < dp[i + 1]:
                    dp[i + 1] = dp[i] + a[i]

        walk(dp)

        for _t in range(k):
            # build lines from current dp
            lines = []
            for i in range(n):
                if dp[i] < INF:
                    m = -2 * x[i]
                    c = dp[i] + b[i] + x[i] * x[i]
                    lines.append((m, c))

            # convex hull for min queries, slopes decreasing since x increasing => m decreasing
            hull = []

            def bad(l1, l2, l3):
                m1, c1 = l1
                m2, c2 = l2
                m3, c3 = l3
                return (c3 - c1) * (m1 - m2) <= (c2 - c1) * (m1 - m3)

            for line in lines:
                while len(hull) >= 2 and bad(hull[-2], hull[-1], line):
                    hull.pop()
                hull.append(line)

            def query(xv):
                l, r = 0, len(hull) - 1
                while l < r:
                    mid = (l + r) // 2
                    def f(line):
                        m, c = line
                        return m * xv + c
                    if f(hull[mid]) <= f(hull[mid + 1]):
                        r = mid
                    else:
                        l = mid + 1
                return hull[l][0] * xv + hull[l][1] if hull else INF

            ndp = [INF] * n

            for j in range(n):
                best = query(x[j])
                if best < INF:
                    ndp[j] = min(ndp[j], best + x[j] * x[j])

            dp = ndp
            walk(dp)

        print(dp[-1])

if __name__ == "__main__":
    solve()
```DP 配列は、反復によって暗黙的にエンコードされた固定数のファイアフライ ジャンプを使用して、各ランプの最適コストを保存します。 チェーンに沿った単調な伝播を保証するために、各緩和ステージの後にウォーキング フェーズが適用されます。 

各 Firefly レイヤーは線形関数のセットに変換され、クエリ ステップでターゲット座標ごとに最適な先行関数が評価されます。 二次項は、元のコストの代数変換と一致するように、クエリ後にのみ追加されるように慎重に分割されます。 

船体の内部の二分探索は、増加によって引き起こされる単調な傾きに依存します。$x_i$これにより、凸包の正確さが保証されます。 

## 実用的な例

 1 回のジャンプが有益な 3 つのランプを備えた小さなケースを考えてみましょう。 

私たちは取る$x = [0, 2, 5]$、$a = [3, 100]$、$b = [1, 1]$、$k = 1$。 

### レイヤー 0 (ジャンプなし)

 | 私 | 歩く前の dp[i] | アクション | 散歩後の dp[i] |
 | --- | --- | --- | --- |
 | 1 | 0 | 開始 | 0 |
 | 2 | INF | 0 + 3 | 3 |
 | 3 | INF | 3 + 100 | 103 |

 これは、純粋な歩行が最初の到達可能性を支配していることを示しています。 

### ホタル層

 各州からラインを構築します。 

| 私 | dp[i] | 線の傾き | 切片 |
 | --- | --- | --- | --- |
 | 1 | 0 | 0 | 1 |
 | 2 | 3 | -4 | 3 + 1 + 4 = 8 |
 | 3 | 103 | -10 | 103 + 1 + 25 = 129 |

 それぞれの行でこれらの行をクエリすると、$x_j$二次関数の節約により、後のポイントへの到達可能性が向上します。 

計算後$dp[1]$、私たちは再び歩行を伝播し、改善された位置を安価に前方に拡張できるようにします。 

このトレースは、単一のジャンプが残りのパス全体をどのように再形成できるかを示しています。これは、貪欲なローカル決定ではキャプチャできません。

 ## 特殊なケース

 重要なエッジ ケースは、すべての最適なパスがファイアフライ ジャンプを完全に回避する場合です。 その状況では、すべての DP 層はチェーンに沿った最短パスを単純に複製する必要があります。 凸包は引き続き正しく構築されますが、歩行のみの伝播に勝る候補はないため、アルゴリズムはこれを処理します。そのため、値は変更されません。 

もう 1 つのエッジ ケースは、単一の非常に有益なジャンプがアレイのほぼ全体をスキップする場合です。 たとえば、次の場合$x_1$そして$x_n$は近いが中間点が遠い場合、二次構造により直接ジャンプが最適になります。 考えられるすべての開始点が線として含まれており、そこでクエリを実行するため、DP はこれを正しくキャプチャします。$x_n$すべての候補スタートを評価します。 

3 番目のケースは次の場合です。$k = 0$。 ファイアフライ レイヤー上のループがスキップされ、ウォーキング DP のみが残るため、アルゴリズムは引き続き機能します。 これは、単純なプレフィックス緩和に退化します。$a_i$、これはまさに正しい動作です。 

最後の微妙なケースは、複数のホタルが直感的ではない方法で連鎖してジャンプする場合です。 レイヤーベースの DP では、各ジャンプでレイヤー インデックスが 1 つだけ増加することが強制され、すべてのマルチ ジャンプ ストラテジーが部分的なトランジションを混合することなくきれいに構成されることが保証されます。
