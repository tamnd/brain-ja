 ## 解決策
 ## 問題の理解

 負ではない値の配列が与えられます。各位置は、ブロックが現在保持している「青いリソース」の量を表します。 時間が経つにつれて、この配列のセグメントとしきい値について尋ねる形式の操作を受け取ります。 各操作では、指定された間隔内のすべてのブロックを調べ、現在の値がしきい値以上であるブロックのみを選択し、それらの青色の量をすべて収集し、それらの位置を 0 に設定することで配列からそれらの量を永久に削除します。 

重要な相互作用は、配列が静的ではないということです。 1 つのクエリでブロックが使用されると、それ以降のすべてのクエリではブロックが消えます。 つまり、各クエリは後のクエリの状態を変更するため、クエリを独立して扱うことができません。 

入力サイズは最大 200,000 要素と 200,000 クエリです。 クエリごとの単純なスキャンでは、毎回最大すべての要素が検査されるため、最悪の場合は 400 億回の操作が発生し、これは実行可能な制限をはるかに超えています。 したがって、どのようなソリューションでも、各要素が全体的に少数の回数だけ処理されるようにする必要があります。 

抽出を繰り返すと、微妙なエッジケースが発生します。 値が大きく、多くの重複するクエリ範囲に出現する場合、その値は 1 回のみ寄与し、その後はゼロになるはずです。 抽出後に配列を変更することを忘れるアプローチでは、カウントがオーバーカウントされます。 

もう 1 つの特殊なケースは順序依存です。 クエリは可換的ではありません。 たとえば、しきい値が低いために大きな値が早期に抽出された場合、たとえそうでなければ適格であっても、後のクエリではその値が認識されないはずです。 

## アプローチ

 直接シミュレーションでは、範囲を反復処理し、各要素をチェックし、条件を満たす値を合計して、それらをゼロに設定することによって各クエリを処理します。 これは問題のルールに正確に従っているため、簡単で正しいです。 ただし、各クエリのコストは O(n) となり、総作業量は O(nq) になります。n と q の両方が 200,000 に達すると、これは大きすぎます。 

重要な構造上の観察は、各要素は 1 回しか「削除」できないということです。 ブロックが抽出されるとゼロになり、再び寄与することはありません。 したがって、プロセス全体を通じて、すべてのインデックスは正の値から 0 に 1 回だけ遷移し、その後は変更されません。 

これは、同じ「すでに削除された」位置を繰り返しスキャンすることは避けるべきであることを示唆しています。 代わりに、ゼロ化されたセグメントをすぐにスキップして、まだ生きている位置のみをタッチできる構造が必要です。 最大値を維持するセグメント ツリーで十分です。これにより、値が少なくとも x である範囲内の任意の位置をすばやく見つけて、それを削除できます。 各削除は永続的なものであるため、各インデックスにアクセスして削除されるのは最大 1 回です。 

セグメントツリーを使用して、範囲内で有効な候補を繰り返し検索します。 見つかったら、それを抽出してゼロに設定し、検索を続けます。 各要素は 1 回削除されるため、すべてのクエリで成功した抽出の合計数は最大でも n です。

 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 削除のあるセグメント ツリー | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各ノードがその間隔内の最大値を格納するセグメント ツリーを維持します。 これにより、クエリ範囲内に有効な要素が存在するかどうかを迅速に判断できます。

1. 値と最大値の両方を格納する配列上にセグメント ツリーを構築します。 これにより、範囲最大クエリとポイント更新が効率的に行われます。 
2. 各クエリ (l、r、x) について、最初に間隔内に x より大きい値が存在するかどうかを確認します。 これを行うには、[l, r] の最大値をクエリします。 最大値が x より小さい場合、答えはゼロになります。 
3. 有効な要素が存在する場合、値が少なくとも x である [l, r] 内の 1 つのインデックスを繰り返し検索します。 これは、セグメント ツリーを下降することによって行われます。ノードの範囲が [l, r] の外側にある場合、またはその最大値が < x の場合、そのノードはスキップされます。 それ以外の場合は、葉に到達するまでさらに深く進みます。 
4. そのようなインデックス i が見つかったら、答えに b[i] を追加し、b[i] を 0 に設定します。 位置 i でセグメント ツリーを更新します。 
5. 範囲内に条件を満たす要素がなくなるまで、つまり [l, r] のセグメントの最大値が x を下回るまで、同じクエリの検索を繰り返します。 

このループが有限で効率的である理由は、成功するすべてのステップで 1 つの要素が永久に削除されるためです。 

### なぜ効果があるのか

 どの時点でも、セグメント ツリーはアレイの現在の状態を正確に反映します。 クエリでは、両方の条件を満たす要素のみが抽出されます。要素は間隔内にあり、その値がしきい値以上です。 要素は削除されるとゼロになり、最大クエリに影響を与えなくなるため、再度選択することはできません。 各インデックスは最大 1 回削除されるため、すべてのクエリで成功した抽出の合計数は n に制限され、作業の繰り返しが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.t = [0] * (4 * self.n)
        self.arr = arr[:]
        self.build(1, 0, self.n - 1)

    def build(self, v, tl, tr):
        if tl == tr:
            self.t[v] = self.arr[tl]
        else:
            tm = (tl + tr) // 2
            self.build(v * 2, tl, tm)
            self.build(v * 2 + 1, tm + 1, tr)
            self.t[v] = max(self.t[v * 2], self.t[v * 2 + 1])

    def update(self, v, tl, tr, pos, val):
        if tl == tr:
            self.t[v] = val
            self.arr[tl] = val
        else:
            tm = (tl + tr) // 2
            if pos <= tm:
                self.update(v * 2, tl, tm, pos, val)
            else:
                self.update(v * 2 + 1, tm + 1, tr, pos, val)
            self.t[v] = max(self.t[v * 2], self.t[v * 2 + 1])

    def query_max(self, v, tl, tr, l, r):
        if l > r:
            return 0
        if l == tl and r == tr:
            return self.t[v]
        tm = (tl + tr) // 2
        return max(
            self.query_max(v * 2, tl, tm, l, min(r, tm)),
            self.query_max(v * 2 + 1, tm + 1, tr, max(l, tm + 1), r)
        )

    def find(self, v, tl, tr, l, r, x):
        if self.t[v] < x or r < tl or tr < l:
            return -1
        if tl == tr:
            return tl
        tm = (tl + tr) // 2
        res = self.find(v * 2, tl, tm, l, r, x)
        if res != -1:
            return res
        return self.find(v * 2 + 1, tm + 1, tr, l, r, x)

def solve():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))
    st = SegTree(arr)

    out = []
    for _ in range(q):
        l, r, x = map(int, input().split())
        l -= 1
        r -= 1

        if st.query_max(1, 0, n - 1, l, r) < x:
            out.append("0")
            continue

        total = 0
        while True:
            pos = st.find(1, 0, n - 1, l, r, x)
            if pos == -1:
                break
            total += st.arr[pos]
            st.update(1, 0, n - 1, pos, 0)

        out.append(str(total))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```セグメント ツリーは 3 つの役割で使用されます。 ビルドでは、配列のコピーと最大構造の両方が初期化されます。 query_max 関数は高速な拒否テストを提供するため、有効な要素が存在しない場合に不必要な検索を回避できます。 find 関数は、範囲内で条件を満たすインデックスを検索するコアの検索プリミティブです。 各抽出の後、update はその位置を 0 に設定し、今後のクエリで再利用できないようにします。 

よくある落とし穴は、しきい値を満たしている要素がない場合に早期に停止するのを忘れることです。 query_max を使用した事前チェックを行わないと、検索操作でツリーが不必要に走査される可能性があります。 もう 1 つの微妙な点は、find は範囲としきい値の両方を同時に考慮する必要があることです。そうでないと、クエリ間隔外または x 未満のインデックスが返される可能性があります。

 ## 特殊なケース

 重要なエッジ ケースでは、同じ領域に対してクエリが繰り返され、値が徐々に削除されます。 たとえば、低いしきい値を使用して同じ間隔を繰り返しクエリすると、最初のクエリでは条件を満たす値がすべて削除され、後続のクエリではすぐに 0 が返される必要があります。 セグメント ツリーでは、抽出されたすべての要素がゼロに設定され、最大クエリがそれを即座に反映するため、これが保証されます。 

もう 1 つのエッジ ケースは、どの値よりも高いしきい値です。 アルゴリズムは、最初の最大値チェックを通じてこれを処理します。 範囲の最大値はすでに x を下回っているため、検索ループは実行されず、不必要な走査が回避され、ゼロの結果が保証されます。 

最後のケースは単一要素間隔です。 query_max と find の両方がリーフ操作に還元されるため、アルゴリズムは引き続き一貫して動作します。 要素が条件を満たす場合、その要素が取得され、すぐにゼロに設定されます。 それ以外の場合は副作用なく無視されます。
