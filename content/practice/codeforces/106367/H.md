 ## 解決策
 ## 問題の理解

 固定ユニバースからの整数の動的なサブセットを維持します$[1, n]$。 このセットは、冪等の動作による挿入と削除をサポートしています。つまり、同じ要素に対して繰り返し挿入または削除を行っても、最初の効果の後は何も変更されません。 

基本的な更新に加えて、2 種類のクエリに答える必要があります。 最初のクエリは、現在セットにない最小の正の整数を求めます。これは、古典的な「mex」です。$[1, n]$。 2 番目のクエリは、欠落している要素に対するより複雑な集計を定義します。$[1, n]$セットに含まれていないものは$a_1 < a_2 < \dots < a_k$、計算します$\sum_{i=1}^{k} a_i \cdot 2^i$、剰余を取得$998244353$。 

制約$n, q \le 10^5$私たちをほぼ線形または線形の解決策に強制します。 欠落している要素を再計算したり、クエリごとに配列全体をスキャンしたりするものはすべて TLE になります。$10^5$操作が必要です。 タイプ 4 クエリごとに補集合を再構築するソリューションにはコストがかかります$O(n)$クエリごとに、$10^{10}$最悪の場合の運用。 

微妙な点は、「set」セマンティクスが重複を非表示にすることです。 操作 1 と 2 はブール フラグのように動作する必要があります。 もう 1 つの問題は、重みクエリが欠落要素の順序に依存するため、どのような構造でもソートされた補数を効率的に保存または再構築する必要があることです。 

エッジ ケースには、挿入と削除の繰り返し、セットが空またはいっぱいの状態が含まれます。 

セットが空の場合、$n=5$の場合、クエリ タイプ 3 の場合は 1 が返されます。タイプ 4 の場合、欠落リストは次のとおりです。$[1,2,3,4,5]$、重さは$1\cdot2^1 + 2\cdot2^2 + \dots + 5\cdot2^5$。 単純なアプローチでは、インデックスを累乗として誤って扱ったり、インデックスが 1 から始まることを忘れたりする可能性があります。 

もう 1 つのエッジ ケースは完全に満たされたセットです。ここで、mex は$n+1$、ただし、この問題では整数のみが求められているため、$[1,n]$、正しいメキシコは次のようになります。$n+1$たとえそれが宇宙の外にあったとしても、暗黙的に。 

## アプローチ

 ブルート フォース ソリューションは、セットを明示的に維持し、必要に応じて答えを再計算します。 挿入と削除は、$O(1)$ブール配列またはセットを使用します。 mex クエリは、欠落要素が見つかるまで 1 から上方向にスキャンします。$O(n)$。 重みクエリは、1 から n までのすべての数値をスキャンし、欠落している要素を収集して並べ替え、合計を計算します。$O(n)$。 まで$10^5$クエリの場合、最悪の場合の複雑さは次のようになります$O(nq)$が遅すぎます。 

重要な点は、完全な補完を繰り返し再構築する必要がないということです。 代わりに、どの要素が現在存在するかを追跡するフェンウィック ツリーまたはセグメント ツリーを使用して、暗黙的に補完を維持できます。 この構造から、「プレフィックスに欠落している要素がいくつあるか」や「最初に欠落している要素を見つける」などのプレフィックス クエリをサポートできます。 それはすでに mex を解決しています$O(\log n)$。 

より難しい部分は重み関数です。これは、欠落要素のソートされたリストと、そのリスト内の位置によってインデックス付けされた 2 のべき乗に依存します。 重要なトリックは、補集合全体にわたってプレフィックス集合体を維持することです。各位置は、その前に欠落している要素の数に応じて値を提供します。 セグメント ツリーは、セグメントごとに、欠落要素の数と正しいパワー アラインメントによる加重合計寄与の両方を保存できます。 2 つのセグメントをマージする場合、式内のインデックスはグローバルな順序に依存するため、左側のセグメントの欠落要素の数だけ右側のセグメントの寄与をシフトする必要があります。 

これにより、構造はトグルの下でシーケンスを維持するのと似たものになり、各要素が存在するか存在しないかのいずれかになり、存在しない要素はすべての存在しない要素の中でのランクに応じた値に寄与します。 セグメント ツリー ノードには、ゼロ (欠落要素) の数とそのセグメントの加重合計という 2 つの値が格納されます。 マージ操作では次の ID を使用します。 

左セグメントが$k$要素が欠落している場合、右側のセグメント内のすべての要素のインデックスが 1 つ増加します。$k$、したがって、その寄与は次のように乗算されます。$2^k$、シフト用語も追加します$(\text{sum}_R) \cdot 2^k$。 

これらの変化を効率的にサポートするために、2 の累乗を事前計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(nq)$|$O(n)$| 遅すぎる |
 | 暗黙的な補完を含むセグメント ツリー |$O(q \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 それぞれの数字を表します$x \in [1,n]$バイナリ状態として: セット内に存在する場合は 1、存在しない場合は 0。 重みは存在しない要素に対して定義されるため、概念的には 0 をアクティブなシーケンスとして扱います。 

このバイナリ配列に対してセグメント ツリーを構築します。ここで、各ノードは 2 つの情報、つまりセグメント内のゼロの数と、セグメント内で 1 からインデックス付けされていると仮定したセグメント内のゼロの重み付けされた寄与を保持します。 

マージを正しく行うために、各セグメントが独自のローカル ゼロ シーケンスのインデックス 1 から始まると仮定して、その寄与を格納するという不変条件も維持します。 

## アルゴリズムのチュートリアル

 1. 配列を初期化する`present`サイズの$n$、最初はすべて false、つまりすべての要素が欠落していることを意味します。 これは、セグメント ツリー表現ではすべての位置がゼロであることを意味します。 
2. 2 のべき乗モジュロを事前計算する$998244353$まで$n+5$。 これらは、セグメントがシフトされるたびに必要となるため、$k$要素が欠落している場合、貢献度は次のように乗算されます。$2^k$。 
3. 各リーフが単一の値を表すセグメント ツリーを構築します。$x$。 もし$x$が欠落している場合、リーフには count = 1 および sum = が格納されます。$x \cdot 2^1$。 存在する場合、count = 0 および sum = 0 が格納されます。セグメント内の最初の欠落要素がインデックス 1 に寄与するため、指数は 1 から始まります。 
4. タイプ 1 操作 (挿入) の場合、$x$これにより、補数シーケンスからリーフが削除されます。 
5. タイプ 2 操作 (削除) の場合は、$x$再び欠落しているものとして、そのリーフをカウント 1 と合計に更新します$x \cdot 2^1$。 これにより、それが補体配列に再導入されます。 
6. タイプ 3 クエリの場合、セグメント ツリーを下降して mex を計算します。 各ノードで、左側の子の欠損数が予想される完全な欠損数よりも少ない場合、最初の欠損は左側にあります。 それ以外の場合は、左側のカウントを減算した後、右側に位置します。 これにより、値 0 を持つ最小のインデックスが検索されます。 
7. タイプ 4 クエリの場合、セグメント ツリーのルートに保存されている合計を返します。 これはすでに、正しいグローバル順序で欠落している要素の完全な加重合計を表しています。 
8. 2 つのノードをマージするとき、左側の子が`(cntL, sumL)`そして右の子は`(cntR, sumR)`。 次に、右側のセグメントのすべてのゼロが次のようにシフトされます。`cntL`したがって、彼らの貢献は次のようになります。$sumR \cdot 2^{cntL}$さらに、右側のセグメントの各要素は、構造体を介してすでにエンコードされている指数の追加オフセットを取得します。 次のように組み合わせます。$(cntL + cntR, sumL + sumR \cdot 2^{cntL})$。 
9. すべてのセグメント ツリー操作に対して、このマージ ルールを一貫して維持します。 

### なぜ効果があるのか

 核となる不変条件は、すべてのノードが、セグメントの欠落要素が左から右の順序で 1 から再番号付けされるという仮定の下で、そのセグメントの欠落要素の正確な寄与を格納することです。 2 つのセグメントをマージする場合、右側のセグメントの欠落要素は、左側のセグメントのすべての欠落要素の後に来るため、それらのインデックスは、左側のセグメントの欠落要素の数だけシフトされます。 このシフトは、貢献度に次の値を乗算することに正確に対応します。$2^{cnt_L}$これにより、指数重み付けの正確さが維持されます。 すべてのマージではこの順序変換が考慮されるため、ルート ノードは常に、欠落しているすべての要素の正しいグローバル順序をエンコードします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

class SegTree:
    def __init__(self, n):
        self.n = n
        self.size = 1
        while self.size < n:
            self.size *= 2
        self.cnt = [0] * (2 * self.size)
        self.sum = [0] * (2 * self.size)

        self.pow2 = [1] * (n + 5)
        for i in range(1, n + 5):
            self.pow2[i] = (self.pow2[i - 1] * 2) % MOD

    def build_leaf(self, idx, is_missing, x):
        if is_missing:
            self.cnt[idx] = 1
            self.sum[idx] = (x * self.pow2[1]) % MOD
        else:
            self.cnt[idx] = 0
            self.sum[idx] = 0

    def pull(self, v):
        lc, rc = 2 * v, 2 * v + 1
        self.cnt[v] = self.cnt[lc] + self.cnt[rc]
        self.sum[v] = (self.sum[lc] + self.sum[rc] * self.pow2[self.cnt[lc]]) % MOD

    def update(self, v, l, r, pos, is_missing, x):
        if l == r:
            self.build_leaf(v, is_missing, x)
            return
        mid = (l + r) // 2
        if pos <= mid:
            self.update(2 * v, l, mid, pos, is_missing, x)
        else:
            self.update(2 * v + 1, mid + 1, r, pos, is_missing, x)
        self.pull(v)

    def mex(self, v, l, r):
        if l == r:
            return l
        mid = (l + r) // 2
        lc = 2 * v
        left_missing = (mid - l + 1) - (self.cnt[lc])
        if left_missing > 0:
            return self.mex(lc, l, mid)
        return self.mex(2 * v + 1, mid + 1, r)

def main():
    n, q = map(int, input().split())
    st = SegTree(n)

    for i in range(1, n + 1):
        st.update(1, 1, n, i, True, i)

    for _ in range(q):
        tmp = input().split()
        t = int(tmp[0])
        if t == 1:
            x = int(tmp[1])
            st.update(1, 1, n, x, False, x)
        elif t == 2:
            x = int(tmp[1])
            st.update(1, 1, n, x, True, x)
        elif t == 3:
            print(st.mex(1, 1, n))
        else:
            print(st.sum[1] % MOD)

if __name__ == "__main__":
    main()
```セグメントツリーはユニバース上に構築されます$[1,n]$、各リーフは、存在状態と欠落状態を切り替えます。 の`pull`関数は、左の子の欠落要素の数だけ右の子の寄与をシフトするキーの繰り返しを実装します。 これは順序付けが強制される唯一の場所であり、重みクエリをグローバルに正しくするものです。 

mex クエリは、欠落カウントが 0 の場合、セグメントが現在の要素で完全に「満たされる」という事実を利用します。 小切手`(mid - l + 1) - self.cnt[lc]`左側の子区間に欠落要素がいくつ存在するかを計算し、対数時間で方向を決定できるようにします。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての要素が存在する場合です。 その場合、すべてのリーフが存在するとマークされるため、すべてのカウントはゼロになります。 セグメント ツリーのルートの合計はゼロであり、mex トラバーサルでは常に内部の欠落要素が見つかりません。$[1,n]$、したがって、それは返されます$n+1$。 実装では、誤った計算が欠落しているために再帰が誤って早期に停止しないようにする必要があります。 

もう 1 つの特殊なケースは、同じ要素に対する操作の繰り返しです。 更新は盲目的に切り替えるのではなく状態を上書きするため、既存の要素を挿入しても二重にカウントされてはなりません。 リーフ割り当てによりカウントと寄与の両方が完全にリセットされるため、累積エラーが防止されます。 

3 番目のエッジ ケースは、同じ値に対する挿入と削除を交互に行うことです。 更新のたびにリーフが再構築されるため、セグメント ツリーには常に現在のメンバーシップのみが反映され、古いサブツリーの合計による履歴の重みの漏洩は発生しません。
