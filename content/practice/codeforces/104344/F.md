 ## 解決策
 ## 問題の理解

 1 から N までのフロア番号が付けられた建物が与えられています。最初は、各フロアの照明がオフになっています。 一連の N 人が通り抜け、構造化された方法でスイッチを切り替えます。 i 番目の人は、i の倍数の階数ごとに切り替えます。 N 人全員がこれを行った後、一部のフロアは明るくなり、他のフロアは暗いままになります。 

トグルは状態を切り替えることを意味し、オフはオンになり、オンはオフになります。 最後のタスクは、プロセスをシミュレートすることではなく、最後にどのフロアが点灯するかを正確に判断し、それらのフロア番号を昇順に出力することです。 

制約 N は 10^8 まで大きくすることができ、これにより、すべての人のすべてのフロアにわたるシミュレーションが即座に除外されます。 直接的なアプローチでは、1 人あたり約 N 回の操作が必要となり、最悪の場合は約 N^2 回の操作が必要になりますが、これは実行可能な限界をはるかに超えています。 注意しないと、すべてのトグルを 1 回通過するだけでも大きすぎます。最適化された言語では 10^8 操作がすでに 1 秒ぎりぎりに達しており、何度も繰り返すと Python では不可能だからです。 

主な困難は、プロセスが高度に構造化されており、各フロア インデックスの約数の数のみに依存していることを認識することです。 

N が小さい場合、微妙なエッジケースが現れます。 たとえば、N = 1 の場合、唯一のフロアが 1 回切り替えられ、オンのままになります。 N = 2 の場合、フロア 1 は 2 回切り替わって終了しますが、フロア 2 は 1 回切り替わってオンのままになります。 これらの小さなケースは、最終状態が演算のシーケンスではなく、各数値に固有の何かのパリティによって決定されることを示唆しています。 

## アプローチ

 ブルートフォース シミュレーションでは、各人物 i を 1 から N まで反復し、次に i の倍数にわたって反復して、それらのフロアの状態を切り替えます。 これは問題のステートメントを直接反映しており、論理的には正しいです。 

ただし、コストが問題です。 内側のループは N/i 回実行されるため、トグルの総数は約 N/1 + N/2 + ... + N/N、つまり N log N になります。C++ ではこれでも合格する可能性がありますが、N が最大 10^8 であるため、Python ではまったく実行不可能であり、概念的にさえ、最悪の場合でも数十億回の操作を反復することになります。 

重要な観察は、視点を反転することです。 各人がフロアを何回切り替えるかを尋ねるのではなく、各フロアが何回切り替わるかを尋ねます。 フロア k は、k の約数ごとに 1 回切り替えられます。これは、人 i が行動するときにすべての約数 i が切り替えに寄与するためです。 したがって、フロア k は正確に d(k) 回トグルされます。ここで、d(k) は k の約数の数です。 

奇数回切り替えると床が点灯します。 したがって、問題は、d(k) が奇数となるすべての k を見つけることになります。 古典的な数理論の事実は、完全平方だけが奇数の約数を持つということです。 これは、完全な正方形の場合にのみ発生する a = k/a の場合を除き、通常、約数は (a, k/a) としてペアになるために発生します。 

したがって、答えはまさに N 以下のすべての完全な平方です。 

i を 1 から i^2 ≤ N まで反復し、i^2 を出力することで直接生成できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(N log N) | O(N) | 遅すぎる |
 | 正方形の列挙 | O(√N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各フロア k が k の約数ごとに 1 回切り替わることを観察します。 これにより、人々をシミュレートするのではなく、約数のカウントという観点からプロセス全体が再構成されます。 
2. 最終状態は、k の約数が奇数かどうかにのみ依存することを認識します。 奇数だと床が明るくなってしまいます。 
3. 完全平方のみが奇数の約数を持つという数論の事実を利用します。 これは、√k を中心に対称的に約数をペアにすることから来ています。 
4. i² ≤ N となる i² 形式のすべての整数を出力するだけでよいと結論付けます。 
5. i を 1 から繰り返し、i² ≤ N の間続行し、毎回 i² を出力します。

これが機能する理由: すべての非平方整数には、その約数が個別のペアで配置されており、偶数の数が生成されるため、相殺されてオフになります。 完全平方には、対になっていない約数、つまり平方根が 1 つだけあり、カウントが奇数になり、最終状態がオンのままになります。 この不変式はフロアごとに独立して保持されるため、平方計算によって出力が完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input().strip())
    i = 1
    while i * i <= n:
        print(i * i)
        i += 1

if __name__ == "__main__":
    solve()
```解は N を読み取り、可能な平方根を反復処理します。 各値 i は、切り替えプロセスを経ても残るフロア i² を表します。 ループ条件 i * i <= n により、有効な下限範囲を超えないことが保証されます。 出力はオンザフライで生成されるため、追加のデータ構造は必要ありません。 

重要な詳細は、浮動小数点平方根の代わりに i * i を使用して、精度の問題を回避し、解を整数安全に保つことです。

## 複雑さの分析

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()
    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

def solve():
    n = int(input().strip())
    i = 1
    while i * i <= n:
        print(i * i)
        i += 1

 ## 特殊なケース

 N = 1 の場合、フロア 1 のみが存在します。 一度切り替えられるので、オンのままになります。 アルゴリズムは i = 1 を出力し、1² = 1 を生成しますが、これは正しいです。 

N = 2 のような非正方形の場合、i = 1 のみが i² ≤ 2 を満たすため、フロア 1 のみが印刷されます。 階 2 は印刷されません。2 は完全な正方形ではなく、約数の数が偶数であり、終わることを意味するためです。 

10^8 などの大きな N の場合、i は 10^4 まで実行され、10000² = 10^8 までのすべての平方が正しく出力され、オーバーフローやパフォーマンスの問題が発生しないことが保証されます。 

それぞれのケースでは、アルゴリズムが整数反復のみに依存し、シミュレーションを完全に回避して正確さと効率を維持していることが確認されています。
