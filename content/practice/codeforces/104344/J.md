 ## 解決策
 ## 問題の理解

 最初は 0 の 1 桁の状態から開始します。ボタンを押すたびに、サイズ 3 の配列で定義された固定遷移規則に従って、現在の桁を別の桁に置き換えます。現在桁 k にいる場合、次の桁は a[k] になり、各 a[k] も 0、1、または 2 のいずれかになります。 

したがって、システムは 3 要素の状態空間上の決定論的な関数にすぎません。 0 から開始して、関数を繰り返し適用すると、一連の数字が生成されます。 この問題は、このシーケンスについて 2 つのことを尋ねます。1 つ目は、ボタンを何回押した後、すでに表示されている数字の最初の繰り返しが表示されるか、2 つ目は、N を押した後に画面に表示される数字は何かです。 

構造上の重要な観察は、可能な状態が 3 つだけであるということです。 有限集合にわたる決定論的なプロセスは最終的には循環する必要があり、ここではそのサイクルに非常に早く到達します。 実際、状態が 3 つしかなく、プロセスが決定的であるため、シーケンスは 0 から開始して最大 3 の長さのサイクルに入らなければなりません。 

N が 10^9 までという制約は、N ステップのブルート シミュレーションを不可能にしますが、プロセスをサイクル解析に圧縮する必要があることも示します。 N 内の線形なものはすべて直ちに除外されますが、O(1) または O(3) 推論が期待されます。 

微妙なエッジ ケースは、シーケンスが即座に固定小数点に崩壊する場合です。たとえば、a[0] = 0 の場合です。この場合、シーケンスは定数 0 であるため、数値の「2 回目の出現」が簡単な方法ですぐに発生します。 もう 1 つのエッジ ケースは、0 → 1 → 0 などの 2 サイクルです。この場合、新しい状態に戻るのではなく、以前に見た状態に戻るときに繰り返しが発生します。 順序を追跡せずに繰り返される値のみを探す不注意なアプローチでは、最初の繰り返しが発生した時点で誤解を招く可能性があります。 

## アプローチ

 ブルート フォース ソリューションでは、プロセスを段階的にシミュレートし、訪問したすべての値をセットに保存します。 k → a[k] に遷移するたびに、新しい値が以前に出現したかどうかを確認します。 これが初めて発生したときは、停止して歩数を報告します。 また、シミュレーションを継続することで、N ステップ後の現在の値も追跡します。 

シーケンスが明示的に構築されているため、これは正しく機能しますが、状態空間のサイズが 3 であることがわかると、その必要はなくなります。最悪の場合、N ステップをシミュレートする可能性があり、これは最大 10^9 になる可能性があり、これは 1 秒ではまったく実行不可能です。 

重要な洞察は、これが 3 つのノード上の機能グラフであるということです。 すべてのノードには出力エッジが 1 つだけあるため、構造全体はサイクルにつながるテールで構成されます。 ノード 0 から開始するため、シーケンスは完全に決定され、最大 3 ステップ以内でサイクルに入る必要があります。 したがって、ある状態を再訪するか、3 つの状態をすべて使い尽くすまでシミュレーションする必要があるだけです。 

サイクルのエントリ ポイントとサイクルの長さを特定すると、両方のクエリに答えることができます。最初の繰り返し時間は、最初に繰り返しノードが表示されるステップであり、N ステップ後の値は、N ステップを歩くことによって取得されますが、繰り返しが開始されるとサイクルでモジュラー演算を使用します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(N) | お(1) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 このプロセスは、0 から開始して状態 0、1、2 を通過するものとして扱います。

1. 各状態が最初に訪れるステップを保存しながら、遷移をシミュレートします。 これにより、状態が繰り返される瞬間を検出できるようになり、最初の質問に直接答えることができます。 すでに訪問時間が記録されている状態が表示された瞬間が最初の繰り返しポイントです。 
2. 訪問した州のシーケンスを順番に保存します。 可能な状態は 3 つだけであるため、このシーケンスの長さは最大でも 4 になります。その後、繰り返しが発生します。 
3. 繰り返しが検出されると、サイクルが始まる前のプレフィックス長とサイクル長自体が特定されます。 この構造により、任意の大きなステップを前進させることができます。 
4. N が押された後の状態を計算するには、N がプレフィックス内にある場合は記録されたシーケンスに直接インデックスを付けるか、モジュラー演算を使用してサイクルにマッピングします。 
5. 繰り返しステップ数と、N 回の遷移後の結果の状態を出力します。 

これが機能する理由: このプロセスは、サイズ 3 の有限セットに対する決定論的な関数です。 このようなプロセスは最終的に状態を再訪する必要があり、最初の再訪以降、シーケンスは周期的になります。 最初の発生を記録するため、検出された繰り返しは可能な限り最も早いものであることが保証されます。 機能的な性質により、分岐の曖昧さがないことが保証されるため、構築されたシーケンスは一意であり、将来のすべての動作を完全に捕捉します。

input = sys.stdin.readline

def solve():
    N = int(input())
    a0, a1, a2 = map(int, input().split())

    seen = {}
    seq = []

    cur = 0
    step = 0
    repeat_step = None

    while True:
        if cur in seen:
            repeat_step = step
            break
        seen[cur] = step
        seq.append(cur)

        if len(seq) > 10:
            break

        cur = a[cur]
        step += 1

    # ensure we have full cycle information
    # recompute cleanly until repetition or full 3 nodes explored
    seen = {}
    seq = []
    cur = 0
    step = 0
    repeat_step = None

    while True:
        if cur in seen:
            repeat_step = step
            break
        seen[cur] = step
        seq.append(cur)

        if len(seq) > 10:
            break

        cur = a[cur]
        step += 1

    # find cycle start
    cycle_start = seen[cur]
    cycle = seq[cycle_start:]
    prefix = seq[:cycle_start]

    # answer 1: first repetition moment
    ans1 = repeat_step

    # answer 2: state after N steps
    if N < len(seq):
        ans2 = seq[N]
    else:
        if len(cycle) == 0:
            ans2 = seq[-1]
        else:
            N0 = (N - cycle_start) % len(cycle)
            ans2 = cycle[N0]

    print(ans1)
    print(ans2)

```この実装では、最初の訪問時間を記録しながら、遷移を明示的にシミュレートします。 繰り返しは、現在の状態がすでに現れているかどうかを確認することで検出されます。 シーケンス配列には、プレフィックスとサイクルの両方を再構築するのに十分な実際の軌跡が保存されます。 

再計算の第 2 段階は実際には冗長であり、防御構造のためにのみ表示されます。 論理的には、状態空間は 3 つのノードのみであるため、1 つのシミュレーションで十分です。 

サイクル抽出では、最初に繰り返されるノードをサイクル エントリとして使用します。 それ以降はすべて定期的です。 大きな N の最終位置は、モジュロ演算を使用してこのサイクルにシフトすることによって計算されます。 

## 実用的な例

 ### サンプル 1

 入力:```
N = 2
a = [1, 2, 0]
```トレース:

 | ステップ | 現在 | 見られる状態 | アクション |
 | --- | --- | --- | --- |
 | 0 | 0 | {0} | 開始 |
 | 1 | 1 | {0,1} | 0→1 |
 | 2 | 2 | {0,1,2} | 1→2 |
 | 3 | 0 | 繰り返し | 2 → 0 |

 最初の繰り返しはステップ 3 で行われ、0 に戻ります。2 つのステップの後、状態は 2 になります。 

これは、単に値を単独で 2 回確認することではなく、以前の状態を再訪することによって繰り返しがトリガーされることを裏付けています。 

### サンプル 2

 入力:```
N = 1439287
a = [1, 0, 1]
```トレース:

 | ステップ | 現在 | 見られる状態 |
 | --- | --- | --- |
 | 0 | 0 | {0} |
 | 1 | 1 | {0,1} |
 | 2 | 0 | 繰り返し |

 サイクルは 0 ↔ 1、長さ 2 です。最初の繰り返しはステップ 2 で発生します。N ステップ後の状態を計算するには、パリティを使用します。つまり、最初のステップの後、1 と 0 を交互に繰り返します。 

N が大きく、奇数/偶数によって結果が決まるため、サイクルに入った後、2 を法とする N を減らします。 

これは、サイクルが検出されると、長期的な動作が純粋に周期的になることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | お(1) | 3 状態システムでは、反復前に最大 3 回の遷移 |
 | スペース | お(1) | シーケンスおよび訪問済み状態の定常ストレージのみ |

 この制約により、N に対して最大 10^9 の演算が可能になりますが、アルゴリズムは N に依存しません。小さな状態空間での即時サイクル検出により、すべての作業が一定時間で実行されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import defaultdict

    N = int(input())
    a0, a1, a2 = map(int, input().split())
    a = [a0, a1, a2]

    seen = {}
    seq = []
    cur = 0
    step = 0
    repeat_step = None

    while True:
        if cur in seen:
            repeat_step = step
            break
        seen[cur] = step
        seq.append(cur)

            break

        cur = a[cur]
        step += 1

    cycle = seq[cycle_start:]

    ans1 = repeat_step

            ans2 = seq[-1]
        else:
            ans2 = cycle[(N - cycle_start) % len(cycle)]

    return str(ans1) + "\n" + str(ans2) + "\n"

 ## 特殊なケース

 a[0] = a[1] = a[2] = 0 のように、関数がすべての状態をそれ自体にマップする場合、シーケンスは一定です。 初期状態が記録された後すぐに 0 が再訪されるため、最初の繰り返しはステップ 1 で行われます。 アルゴリズムはステップ 0 で 0 を記録し、再度 0 にアクセスしようとすると繰り返しを検出します。 

システムが 0 → 1 → 0 のような 2 サイクルを形成すると、シーケンスは 2 つの値の間で交互に切り替わります。 繰り返しは、0 に戻るステップ 2 で検出されます。アルゴリズムはサイクル長 2 を正確に識別し、モジュロ演算を使用するため、大きな N はパリティに減少し、正しい交互動作が生成されます。 

システムが 0 → 1 → 2 → 0 のような完全な 3 サイクルを形成する場合、ステップ 3 で繰り返しが発生します。アルゴリズムは完全なサイクルを順番にキャプチャし、プレフィックスを最初に通過した後でクエリ N が 3 を法として減らされるため、N がどれだけ大きくなるかに関係なく、サイクルへの一貫したインデックス付けが保証されます。
