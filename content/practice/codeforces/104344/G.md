 ## 解決策
 ## 問題の理解

 フレッドはチョコレートエッグのリストを持っています。それぞれのエッグにはセント単位の既知の価格と、固定金額が記載されています。 課題は、卵を最適に選択した場合に最大で何個の卵を購入できるかを決定することです。 各卵は最大 1 回まで購入でき、入手可能な卵のサブセットを自由に選択できます。 

入力すると、利用可能な卵の数、金額、および価格のリストが表示されます。 出力は、総コストが予算を超えないアイテムの最大数を表す単一の整数です。 

重要な制約は、卵の数が 100,000 個に達する可能性があるということです。すべてのサブセット、さらにはすべての組み合わせを考慮しようとするソリューションは、直ちに実行不可能になります。 二次アプローチでは、最悪の場合、約 10^10 の演算が必要になりますが、これは制限時間を大幅に超えます。 

唯一の重要なエッジケースは、価格が大きく変動する場合に発生します。 たとえば、1 つの安価なアイテムを除いてすべてのアイテムが高価な場合、小さな価値を優先しない単純な戦略により、早期に予算が無駄になる可能性があります。 別の障害モードは、リストがソートされておらず、明示的にソートせずに順序が重要であると想定する貪欲なアプローチの場合に発生します。 

順序が重要な簡単な例:

 入力:```
3
5
5 4 1
```正しい答えは、`1`, コスト1のアイテムを買うのが最適だからです。 ソートせずに最初の手頃なプレフィックスを選択する不用意なアプローチは、入力順序によっては誤って予期しない動作をする可能性があります。 

別の特殊なケース:

 入力:```
4
10
8 7 6 5
```正しい出力は`1`。 順序付けせずに組み合わせを試みる戦略では、カウントを効率的に最大化できません。 

## アプローチ

 強引な解釈では、卵のすべてのサブセットを試し、その合計コストを計算し、合計が予算を超えない最大のサブセットを追跡します。 これは、考えられるすべての選択を明示的に評価するため正しいですが、2^N 個のサブセットとして指数関数的に増加し、各サブセットをチェックするだけでも O(N) コストがかかるため、O(N・2^N) 時間がかかります。 N が 100000 までの場合、これは不可能です。 

より良い観察は、目的を再構成することから生まれます。 私たちは価値を最大化したり、コストを最小限に抑えたりしようとしているわけではありません。 項目の数を最大化しています。これは、各項目が目標に等しく貢献していることを示唆しています。 価格に関係なく、すべてのアイテムは答えに +1 を与えるため、最適な戦略は、最初に最も安いアイテムを購入することです。 

価格が高い順に並べ替えたら、予算がなくなるまで貪欲に商品を 1 つずつ手に入れることができます。 これが機能するのは、より高価な品目を含み、より安価な品目を除外するソリューションは、それらを交換することで改善でき、カウントを減らさずに総コストを削減または維持できるためです。 

これにより、問題はソートと 1 回のリニア スキャンに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N・2^N) | O(N) | 遅すぎる |
 | 並べ替え + 貪欲 | O(N log N) | O(1) または O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. N (卵の数) と C (利用可能な予算) を読み取ります。 
2. 価格リストを読みます。 
3. より安価な商品が最初になるように、リストを降順以外の順序で並べ替えます。 

ローカルな決定はコストのグローバルな順序に依存するため、並べ替えが必要です。 
4. 購入したアイテムと使用済み金額のカウンターを初期化します。 
5. 並べ替えられた価格を繰り返し処理します。 
6. 各価格について、現在の支出額に追加しても予算内に収まるかどうかを確認します。 

存在する場合は、それを含めて、使用金額とカウンターを更新します。 

そうでない場合は、残りのアイテムはすべて少なくとも同じくらい高価であるため、すぐに停止してください。 
7. カウンタを出力します。 

なぜ効果があるのか:

 プロセスのどの時点でも、特定のサイズの可能な限り安価なサブセットが選択されています。 より多くの項目を備えたより良いソリューションが存在する場合、選択された高価な項目を必然的に安価な未使用の項目に置き換えることになります。これは、項目を常に昇順に処理するという事実と矛盾します。 貪欲な選択では、k ステップの後、サイズ k のすべてのサブセット間で可能な最小コストが得られるという不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    c = int(input())
    p = list(map(int, input().split()))
    
    p.sort()
    
    used = 0
    total = 0
    
    for price in p:
        if total + price <= c:
            total += price
            used += 1
        else:
            break
    
    print(used)

if __name__ == "__main__":
    solve()
```この解決策は、価格を分類することから始まり、常に安い卵を最初に検討できるようになります。 変数`total`これまでに費やしたお金を追跡し、`used`選択された卵の数を数えます。 このループは、次に安い実現可能な項目を常に採用するという不変条件を維持します。 価格が残りの予算を超えると、その後のすべての価格は少なくとも同じ大きさになるため、早期停止条件は安全です。 

微妙な点は、厳密な予算チェックの使用です。`total + price <= c`。 これにより、残りの予算が価格と正確に一致する境界ケースであっても、制限を超えることがなくなります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N log N) | 並べ替えが優先されます。 その後の単一の直線パス |
 | スペース | O(1) 追加 (またはソートの実装に応じて O(N)) | カウンターのみが入力ストレージを超えて使用されます。 

この制約では最大 100,000 項目が許可され、O(N log N) の並べ替えは十分に制限内にあります。 それに比べてリニア スキャンは無視できるほど小さいため、ソリューションは時間とメモリの両方の制限内に問題なく収まります。

 入力:```

```実行:

 最初に 3 つの 2 が取得されて合計 6 に達し、次に 4 が取得されてちょうど 10 に達します。アルゴリズムは各ステップでの等価性を正しく許可し、最大カウントが達成されることを保証します。
