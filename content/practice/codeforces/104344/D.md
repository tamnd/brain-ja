 ## 解決策
 ## 問題の理解

 各生徒の結果は、非常に小さな固定された世界から得られます。つまり、1、2、および 4 ポイントに相当する独立した問題が 3 つだけ存在します。 生徒のスコアは、生徒が解いた問題の値の合計にすぎないため、0 から 7 までのすべてのスコアは、これら 3 つの問題の一意のサブセットに対応します。 

Lucca と Yvens という 2 人の生徒の得点が与えられました。 これら 3 つの重みを使用して 0 から 7 までの数値を表現する際に曖昧さがないため、これらのスコアから、それぞれが解決した問題のサブセットを正確に推測できます。 

パシーニョの行動は非常に具体的な方法で定義されています。 彼は、ルッカまたはイヴェンの少なくとも一方が解決したすべての問題を解決しますが、どちらも解決しなかった問題は何も解決しません。 これは、パッシーニョの解決セットがまさに 2 人の学生の解決セットの和集合であることを意味します。 

したがって、タスクは、スコアによって暗黙的に表される 2 つのサブセットの和集合を計算し、その和集合をスコアに変換し直すことです。 

両方のスコアが 0 ～ 7 の間にあるという制約は、各スコアが 3 ビット マスクに対応することを意味します。 これにより、組み合わせや検索の必要がなくなります。 問題全体は、3 ビットにわたるビットごとの再構成に集約されます。 

サブセットではなくスコアに直接基づいて推論する場合、微妙な失敗例が発生します。 たとえば、3 は {1,2} のいずれか、5 は {1,4} のいずれかになります。 単純な試みでは、数値を算術的に結合しようとし、10 進表現における桁の独立性を誤って仮定する可能性があります。 正しい表現は重み 1、2、および 4 のバイナリであり、基数 10 の数字ではありません。 

## アプローチ

 強引な方法は、Lucca と Yvens の 3 つの問題のすべてのサブセットを試し、どのサブセットがスコアと一致するかを計算し、互換性のあるすべてのペアを明示的に結合して、結果のスコアを再計算することです。 1 人あたり 23 個のサブセットしかないため、これは継続的な作業ですが、この方法は概念的に重く、構造がわかりにくくなります。 

重要な観察は、各スコアが既に 3 つの要素のサブセットの直接エンコードであるということです。 スコアをバイナリで記述すると、問題の重みと完全に一致します。ビット 0 は問題 1 を表し、ビット 1 は問題 2 を表し、ビット 2 は問題 4 を表します。したがって、スコア自体はビットマスクです。 

これが分かると、パッシーニョのスコアは単純に 2 つのスコアのビット単位の OR になります。 OR 演算は、2 人の生徒のうち少なくとも 1 人がビットを設定していればビットが設定されるため、解決された問題の和集合を正確に取得します。 

これにより、問題は 1 回の操作で解決されます。

 ## アルゴリズムのチュートリアル

 1. 入力から整数 L と Y を読み取ります。 これらは 3 ビットにわたる 2 つのビットマスクを表します。 
2. 各数値を {1, 2, 4} のサブセットとして解釈します。各ビットは問題が解決されたかどうかを示します。 
3. L と Y の間でビット単位の OR を適用して、解決された問題の和集合を計算します。これは、どちらかのオペランドにビットが存在する場合、OR がビットを保持するため機能します。 
4. 結果の整数を出力します。これはパッシーニョのスコアに直接対応します。 

### なぜ効果があるのか

 各問題は最終スコアに独立して影響し、問題間に相互作用はありません。 この独立性により、ビットの存在に関してスコア表現が線形であることが保証されます。 0 から 7 までのすべての有効なスコアは一意の 3 ビット ベクトルであるため、解決されたセットの和集合はビットごとの OR に正確に対応します。 代替表現が存在しないため、結果は一意に決定されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

L, Y = map(int, input().split())
print(L | Y)
```この解決策は、2 つの整数を読み取り、単一のビット単位の OR 演算を適用することに依存しています。 重要な実装の詳細は、変換やデコードが必要ないことです。 入力値はすでにビットマスクを偽装して表しています。 

よくある間違いは、数値を 10 進数に分解しようとしたり、手動でサブセットを再構築しようとしたりすることです。 エンコーディングはすでにバイナリ構造と一致しているため、これは不要です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline
    L, Y = map(int, input().split())
    return str(L | Y)

 ## 特殊なケース

 エッジ ケースの 1 つは、両方の入力が同じである場合です (3 と 3 など)。この場合、両方の生徒がまったく同じ問題を解いたため、パッシーニョも同じセットを解く必要があります。 L OR Y = 3 OR 3 = 3 の計算では、元の値が正しく保存されます。 

もう 1 つのエッジ ケースは、1 つの入力が 0 の場合です。たとえば、L = 0 および Y = 5 です。和集合は単に Y を再現する必要があります。OR 演算は 0 OR 5 = 5 を与えます。これは、イヴェンスが解いたものをパッシーニョが正確に解いたという解釈と一致します。 

最後のケースは、1 と 2、または 1 と 4 と 2 など、両方の入力が素である場合です。OR 演算は干渉することなくすべてのビットを正しく累積し、すべてのビットがカバーされると最大 7 までの完全な和集合が生成されます。
