 ## 解決策
 ## 問題の理解

 子の行が与えられており、各位置にはすでに子が含まれていますが、各子には、それらが占めることになるターゲット位置があります。 入力配列はこのマッピングを記述します: 現在インデックスにある子`i`最終的にそのポジションに就きたい`p[i]`すべてが正しく並べ替えられた後。 

目標は、現在の配置を完全に順序付けられた配置に変換し、適切な位置に子が配置されるようにすることです。`1`そこにいるはずの子供はいます`2`そこにあります、などの位置まで続きます`N`。 許可される唯一の操作は、行内の 2 つの子を交換することです。 正しい構成に到達するために必要なスワップ数は最小限に抑えたいと考えています。 

これは古典的な「スワップを使用して順列を並べ替える」問題です。 重要な観察は、配列が事実上次の順列であるということです。`1..N`なぜなら、すべての正しい位置は一意に割り当てられるからです。 

制約は十分に小さいので、二次関数の挙動をもつ解は次のようになります。`N`実際にはまだ合格するでしょう。 と`N ≤ 1000`、アルゴリズムでも次のようなことを行います。`N^2`または`N^2 log N`操作は許容されます。 これにより、指数関数的な処理や、操作ごとに繰り返し行われる詳細な再計算が含まれる処理が即座に排除されます。 

素朴ですがよくある間違いは、一貫した構造を持たずに貪欲にスワップをシミュレートしようとすることです。 たとえば、次の間違った位置を繰り返しスキャンし、それを所定の位置に交換することは機能しますが、交換によって別の場所に新たな間違った位置が生じる可能性があることを忘れると、エラーが発生しやすくなります。 もう 1 つの間違った考え方は、要素が実際にどこにあるかを追跡せずに、間違った要素を現在ターゲット位置にある要素と常に交換することです。これは、位置のインデックスが注意深く作成されていない場合に機能しません。 

素朴なソリューションを壊す傾向があるエッジケースには、次のようなすでにソートされた配列が含まれます。`[1,2,3,4]`、ここで答えはゼロであり、次のような純粋なサイクルです。`[2,3,1]`、すべての要素が配置されていませんが、単一のサイクルで構造化されています。 不注意なグリーディー スワップは、サイクルの中断方法に応じてスワップを過大にカウントしたり、過小カウントしたりする可能性があります。 

ここでのより深い構造は、配列が順列を定義し、順列が互いに素なサイクルに分解されるということです。 必要な最小スワップは、サイクル構造によって完全に決定されます。 

## アプローチ

 ブルートフォース手法では、最初の間違った位置を、そこに属する要素を見つけて所定の位置に置き換えることで繰り返し修正します。 交換するたびに、ローカルで誤って配置された要素の数が減りますが、繰り返しの検索が必要になります。 最悪の場合、配置ごとに配列をスキャンして正しい要素を見つける必要があり、$O(N)$スキャンを繰り返した$O(N)$回、与える$O(N^2)$時間。 これは許容されます$N ≤ 1000$しかし、この方法は概念的に面倒で、スワップが将来の検索に影響を与える場合に誤って実装されやすくなります。 

重要な洞察は、個々のスワップの観点から考えるのをやめ、代わりに配列を順列グラフとして見ることです。 各インデックスは、現在の値が配置される位置を指します。 これにより、有向エッジが作成されます。`i → p[i]`。 すべてのノードは正確に 1 つのサイクルに属します。 長さのサイクル`k`正確に必要です`k - 1`各スワップにより、サイクル内の構造を維持しながら 1 つの要素を正しく配置できるためです。 

これをすべてのサイクルにわたって合計すると、最小スワップ数が得られます。

 ## アルゴリズムのチュートリアル

 1. 配列を置換として解釈します。`i`最終的には値を含める必要があります`i`。 

この再構成により、任意のスワップではなくインデックスの観点から正確性を推論できるようになります。 
2. 訪問済み配列を構築して、どのインデックスがすでにサイクルに割り当てられているかを追跡します。 

これがなければ、同じ構造を繰り返し再処理し、スワップを過剰にカウントすることになります。 
3. 各インデックスを反復処理します。`1`に`N`。 

インデックスがすでにアクセスされている場合は、以前に処理されたサイクルに属しているため、スキップします。 
4. 未訪問のインデックスを見つけたら、チェーンをたどり始めます。`i → p[i] → p[p[i]] → ...`訪問したノードに戻るまで。 

この走査により、順列の完全なサイクルが発見されます。 
5. サイズを数える`k`このサイクルの。 

各サイクルは、間違って配置された要素の閉じた依存関係ループを表します。 
6.追加`k - 1`答えに。 

これは、サイクルを正しく配置された固定点に分割するために必要なスワップの最小数です。 
7. すべてのインデックスにアクセスするまで続行し、すべての寄与を合計します。 

### なぜ効果があるのか

 すべての順列は、互いに素なサイクルに一意に分解できます。 長さのサイクルの内側`k`、同じサイクル内の他の要素と対話せずに正しい位置に到達することはできません。 1 回のスワップでは、残りの要素間でより小さいサイクル構造を維持しながら、サイクルから最大 1 つの要素を正しく配置できます。 これを最適に繰り返すと正確に結果が得られます`k - 1`スワップを実行し、独立したサイクルにわたって合計することで、それらの間で干渉がないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    
    # convert to 0-based target interpretation
    p = [x - 1 for x in p]
    
    visited = [False] * n
    ans = 0
    
    for i in range(n):
        if visited[i]:
            continue
        
        # explore cycle starting at i
        cur = i
        cycle_size = 0
        
        while not visited[cur]:
            visited[cur] = True
            cycle_size += 1
            cur = p[cur]
        
        if cycle_size > 0:
            ans += cycle_size - 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず順列をゼロベースのインデックスに変換して、位置が配列インデックスと自然に揃うようにします。 訪問された配列により、各インデックスが 1 回だけ処理されることが保証され、二重カウント サイクルが防止されます。 各サイクルのトラバーサルはループバックするまで順列マッピングに従い、サイクル サイズによって追加されるスワップの数が直接決まります。 

引き算`cycle_size - 1`構造からコストへの重要な変革です。

 ## 特殊なケース

 次のようなすでにソートされた入力の場合`1 2 3 4`の場合、走査は各インデックスをサイズ 1 のサイクルとして直ちにマークします。スワップは蓄積されず、出力はゼロのままです。 

次のようなフルサイクルの場合`2 3 4 1`、アルゴリズムは次のようになります`0 → 1 → 2 → 3 → 0`、サイクルサイズ 4 を生成し、貢献します`3`交換します。 これは、各スワップが 1 つの要素を徐々に修正しながら、残りのサイクルを縮小する最小シーケンスと一致します。 

次のような複数の独立したサイクルの場合`2 1 4 3 5`、訪問されたメカニズムにより、各サイクルが確実に分離されます。 アルゴリズムの処理`(0,1)`そして`(2,3)`個別に、それぞれが 1 つのスワップに寄与し、固定小数点は`4`何も貢献しません。
