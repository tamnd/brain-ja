 ## 解決策
 ## 問題の理解

 私たちにはコインの山が 2 つ与えられ、そのうちの 1 つは$A$コインともう一つ$B$コイン。 2 人のプレイヤーが交互にターンを行い、各ターンでプレイヤーは最初の山か 2 番目の山から、あるいは両方の山から同時に 1 枚のコインを取り出さなければなりません。 コインを取り除く移動は必須であるため、パスは許可されません。 最後に残ったコインをシステムから取り除いたプレイヤーがゲームに勝ちます。 

私たちは、最初のプレイヤーであるバローの視点からこのゲームを分析するように求められています。 特定の開始構成の場合$(A, B)$、両方のプレイヤーが最適にプレイすると仮定して、最初のプレイヤーが勝利を強制できるかどうかを判断する必要があります。 勝利戦略が存在する場合、その結果を保証する有効な初手も出力する必要があります。 

制約により許可されるのは、$A, B \le 10^9$これは、すべての位置にわたる状態空間の探索は不可能であることを即座に示します。 すべての状態にわたる線形スキャンですら問題外であり、どのような解決策であっても、ゲームをテスト ケースごとに一定時間で計算できる閉形式条件に縮小する必要があります。 

微妙なエッジケースは、両方の山がすでに空である状況です。 この場合、ゲームはすでに終了しており、最初のプレイヤーには手がないため、負けの条件と一貫して処理する必要があります。 

もう 1 つのデリケートなケースは、1 つの山が空の場合です。 この移動セットでは、空ではないパイルから取得することも、その両方から取得することもできますが、動作が非対称になり、単一のヒープに関する直観ではなく完全なゲーム構造から慎重に導き出されないと、単純なパリティ推論を誤解させる可能性があります。 

## アプローチ

 ブルートフォースアプローチはあらゆるポジションを扱うことになる$(a, b)$ゲーム状態として、可能なすべての手を再帰的に試行します。最初の山から削除するか、2 番目の山から削除するか、両方から削除します。 少なくとも 1 つの手が負けポジションにつながる場合、そのポジションは勝ちであり、すべての手が勝ちポジションにつながる場合は負けです。 

この再帰はゲームを正しくモデル化しますが、状態空間は$(A+1)(B+1)$、最悪の場合は次のとおりです。$10^{18}$。 メモ化しても、到達可能な状態の数は、直接動的プログラミングには多すぎるままです。 

重要な観察は、移動セットが常にコインの総数をちょうど 1 つか 2 つ減らし、ゲームがグリッド上で非常に構造化された引き算ゲームのように動作することです。 小さな値を計算すると、負けポジションの安定したパターンが明らかになります。両方の山が偶数の場合、ポジションは負けになり、他のすべての構成は勝ちになります。 

これにより、ゲーム全体がグラフ走査の問題ではなくパリティ条件に崩壊します。 負けている状態が特定されたら、相手を両方の山が均等な状態に強制することで勝ちの手を組み立てることができます。

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 負けているポジションを特定する

 両方の場合、ポジションは負けています$A$そして$B$均等です。 ゲームがそのような位置で開始された場合、いかなる動きも必ずこの特性を破り、対戦相手に勝利の形を与えます。 

### ステップ 2: 現在の状態が負けている場合

 両方の場合$A$そして$B$が偶数である場合、最初のプレーヤーに勝利する戦略が存在しないことが出力されます。 

### ステップ 3: それ以外の場合は勝ち手を構築する

 負ける位置、つまり両方の山が均等になる状態に移動しようとします。 

### ステップ 4: パリティに基づいて移動を選択する

 もし$A$均等であり、$B$奇数です、減らしてください$B$1までに。 

もし$A$奇妙であり、$B$均等である、減らす$A$1までに。 

両方が奇数の場合は、各山から同時に 1 枚のコインを取り除きます。 

これらの各動きは、偶数対偶の状態に到達するために必要な方法で正確にパリティを反転します。 

### なぜ効果があるのか

 重要な不変条件は、偶数対偶のポジションがゲームの P ポジションとまったく同じであるということです。 偶数偶数状態から、すべての有効な手が少なくとも 1 つのパイル パリティを変更し、非偶数偶数状態を生成します。 非偶数-偶数状態からは、奇数カウントを反転して 1 ステップで偶数-偶数に到達する動きが常に存在します。これは、許可される 3 つの移動タイプを使用してパリティを個別に調整できるためです。 これにより、ゲームが勝利領域と敗北領域の間で交互に強制的に移行することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

A, B = map(int, input().split())

# losing position for first player
if A % 2 == 0 and B % 2 == 0:
    print("N")
else:
    print("S")
    if A % 2 == 0 and B % 2 == 1:
        print("B")
    elif A % 2 == 1 and B % 2 == 0:
        print("A")
    else:
        print("A B")
```コードはパリティの特徴付けを直接エンコードします。 最初の条件は、開始状態が負けているかどうかをチェックします。負けている場合、手は印刷されません。 それ以外の場合は、両方の杭を強制的に均等な構成にする移動を選択します。 

決定構造はパリティの場合を網羅しており、各分岐は状態を対戦相手の負けクラスに下げる動きに正確に対応します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    A, B = map(int, input().split())
    if A % 2 == 0 and B % 2 == 0:
        return "N"
    if A % 2 == 0 and B % 2 == 1:
        return "S\nB"
    if A % 2 == 1 and B % 2 == 0:
        return "S\nA"
    return "S\nA B"

# provided samples
assert run("1 0") == "S\nA", "sample 1"
assert run("1 1") == "S\nA B", "sample 2"
assert run("2 1") == "S\nB", "sample 3"

# custom cases
assert run("0 0") == "N", "empty game"
assert run("2 2") == "N", "even-even losing state"
assert run("3 3") == "S\nA B", "odd symmetric win"
assert run("4 2") == "N", "even-even larger losing state"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 ### ケース: 両方の山が空`(0, 0)`アルゴリズムはこれを偶数-偶数として分類するため、次のように出力します。`N`。 これは、移動するプレイヤーには正当な移動がないため、すぐに負けるという事実と一致します。 

### ケース: 大きな偶数-偶数状態`(10^9, 10^9)`どちらの値も偶数であるため、出力は次のようになります。`N`一定時間内に。 パリティだけで結果が決まるため、状態遷移を調べる必要はありません。 

### ケース: 混合パリティ`(even, odd)`アルゴリズムは常に奇数の山を 1 つ減らし、偶数 - 偶数の状態を生成します。 例えば、`(6, 5)`になる`(6, 4)`、相手を負ける構成に強制します。 

### ケース: どちらも奇数`(odd, odd)`動き`(A-1, B-1)`は常に有効であり、位置を偶数-偶数に変換します。 例えば、`(7, 3)`になる`(6, 2)`、再び相手に負け状態を渡します。
