 ## 解決策

 ## 問題の理解

 2 つの頂点間の各接続が負ではない重みを持つ無向グラフが与えられます。 タスクは、頂点 1 から頂点 n に移動するのに必要な最小の総重みを決定するか、一連のエッジがそれらを接続しない場合は不可能であることを報告することです。 

これは、最大 200,000 個の頂点と 200,000 個のエッジを持つ加重グラフに対する古典的な最短パス クエリです。 各エッジ コストは 10^9 に達する可能性があるため、どのソリューションでも 64 ビット整数を使用して累積合計を慎重に管理する必要があります。 

制約サイズにより、パスを徹底的に再計算しようとするアプローチは即座に除外されます。 エッジの重みが均一ではないため、単純な幅優先検索は無効です。 フロイド・ウォーシャル形式の全ペアの計算は O(n^3) 時間を必要とするため不可能です。 構造のない繰り返し緩和でも O(nm) まで劣化しますが、n と m の両方が大きい場合には遅すぎます。 

微妙な特殊なケースの 1 つは、接続されていないグラフから発生します。 たとえば、入力が次の場合:```
4 2
1 2 3
3 4 5
```この場合、1 から 4 へのパスは存在せず、正しい出力は -1 になります。 距離を誤って初期化する実装や、到達可能性を前提とする実装では、この切断を認識せずに、誤って大きなデフォルト値が返されます。 

もう 1 つの重要なケースは、同じ頂点ペアの間に複数のエッジがある場合です。 グラフは単純ではないため、2 つのノード間にはいくつかの異なるコストが存在する可能性があります。 正しいソリューションでは、盲目的に上書きしたり、一意性を仮定したりするのではなく、最も安価で効果的な移行を常に考慮する必要があります。 

## アプローチ

 直接的だが間違ったアプローチは、1 から n までのすべての可能なパスを探索し、各ルートに沿ってコストを蓄積し、最小値を追跡することです。 グラフ内の分岐ごとに考慮される部分パスの数が 2 倍になるため、頂点の数はすぐに指数関数的になります。 枝刈りを再検討しても状況はわずかに改善されるだけですが、多くの異なるコスト コンテキストを介して同じ頂点に到達する可能性があるため、最悪のケースは依然として爆発します。 

より構造化された試みは、より短いパスが見つかるたびに距離を緩和しながら、幅優先検索のようなトラバーサルを実行することです。 これは、すべてのエッジの重みが等しい場合にのみ機能しますが、ここでは当てはまりません。 任意の重みを使用すると、BFS がノードを早期に終了し、後で発見されたより安価なパスを見逃す可能性があります。 

重要な点は、すべてのエッジの重みが負ではないため、頂点までの現時点での最適な暫定距離がわかれば、距離の増加順に頂点を安全に拡張できることです。 これはまさにダイクストラのアルゴリズムに必要な条件です。 やみくもに探索するのではなく、常に既知の最小距離で次の頂点を処理し、処理時にその最短距離が最終的なものであることを保証します。 

この順序付けは、最小ヒープ優先キューを使用して効率的に維持されます。 ノードまでの距離を改善するたびに、ノードをヒープにプッシュします。 それぞれの抽出により、展開する次に最も有望な頂点が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパス列挙 | 指数 | O(n) | 遅すぎる |
 | 最小ヒープを使用したダイクストラ | O((n + m) log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフの隣接リスト表現を構築します。 各頂点は、すべての出力エッジを (近傍、コスト) のペアとして保存します。 この構造により、緩和中に隣接するものに対する高速な反復が可能になります。 
2. 0 に設定された頂点 1 を除くすべての頂点が無限大に設定される距離配列を初期化します。これは、コスト 0 のノード 1 から開始するという事実をエンコードします。 
3. 最小ヒープ優先キューを作成し、ペア (0, 1) を挿入します。 ヒープは、現在最も近い既知の頂点を常に展開するために使用されます。 
4. ヒープが空でない間に、既知の最小距離 d を持つ頂点 u を抽出します。 この頂点は、最も有望なフロンティア ポイントを表します。 
5. 抽出された距離 d が u の保存された距離より大きい場合は、スキップします。 これにより、より適切なパスが検出される前にプッシュされた古いヒープ エントリが処理されるのを防ぎます。 
6. エッジの重み w を持つ u のすべての近傍 v について、u を介して v に到達すると、現在の最良の既知の距離が改善されるかどうかを確認します。 d + w が dist[v] より小さい場合、dist[v] を更新し、(dist[v], v) をヒープにプッシュします。 このステップでは、確認された最短パスから外側に改善を伝播します。 
7. ヒープが使い果たされたら、dist[n] を確認します。 まだ無限大の場合は、-1 を出力します。 それ以外の場合は dist[n] を出力します。 

### なぜ効果があるのか

 このアルゴリズムは、すべての候補の中で距離が最も短いノードが優先キューから削除されると、その距離が最終的なものになるという特性に基づいています。 そのノードへの代替パスは、同等以上の暫定距離を持つ別のノードを経由する必要があり、ヒープによって強制される順序に矛盾することなく、より小さな結果を生成することはできません。 これにより、すべてのノードが真の最短距離の昇順で解決されることが保証され、すべての緩和の正確さが保証されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

n, m = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(m):
    a, b, c = map(int, input().split())
    g[a].append((b, c))
    g[b].append((a, c))

dist = [INF] * (n + 1)
dist[1] = 0

pq = [(0, 1)]

while pq:
    d, u = heapq.heappop(pq)

    if d != dist[u]:
        continue

    for v, w in g[u]:
        nd = d + w
        if nd < dist[v]:
            dist[v] = nd
            heapq.heappush(pq, (nd, v))

print(-1 if dist[n] == INF else dist[n])
```隣接リストの構築により、グラフは無向であるため、各エッジが各方向に 1 回ずつ、正確に 2 回保存されることが保証されます。 距離配列は、到達していない頂点を表すために大きなセンチネル値を使用し、Python の任意精度の整数は、オーバーフローの問題を発生させることなく大きなパスの合計を安全に処理します。 

ヒープには常に候補状態が保存され、チェック`d != dist[u]`古いエントリを効率的に破棄します。 このチェックがなければ、アルゴリズムは依然として正しいものの、冗長な拡張により速度が低下します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log n) | 各エッジはヒープ更新をトリガーする可能性があり、各更新のコストは log n |
 | スペース | O(n + m) | 隣接リストと距離配列およびヒープ ストレージ |

 最大 200,000 のノードとエッジでは、対数係数が小さいままであり、実際には各操作が線形であるため、この複雑さは制限時間内に問題なく収まります。 

## テストケース```python
import sys, io
import heapq

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    INF = 10**30

    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b, c = map(int, input().split())
        g[a].append((b, c))
        g[b].append((a, c))

    dist = [INF] * (n + 1)
    dist[1] = 0

    pq = [(0, 1)]

    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v, w in g[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    return str(-1 if dist[n] == INF else dist[n])

 ## 特殊なケース

 次のような切り離されたグラフ`1-2`そして`3-4`到達不能なノードが正しく検出されるかどうかをテストします。 ノード n までの距離は無限大のままで、アルゴリズムは無効なパスを試行せずに -1 を返します。 

同じノード間の複数のエッジにより、緩和ロジックが一意性を仮定しないことが保証されます。 エッジのあるテストケースの場合`1-2 (10)`そして`1-2 (2)`、ヒープは両方を処理しますが、より小さい重みのみが距離を更新し、アルゴリズムは値 2 を正しく伝播します。 

直接エッジが間接パスよりも悪いグラフは、距離による順序付けの重要性を強調しています。 ノード 4 への直接エッジは 100 ですが、チェーン 1→2→3→4 は 3 を生成します。ヒープにより、コストの増加に応じてノードが拡張されることが保証され、より短いマルチステップ ルートが最初に検出され、最初の直接推測が正しく上書きされます。
