 ## 解決策
 ## 問題の理解

 すべてゼロで始まる整数の配列を維持し、一連のクエリに答えるように求められます。 各クエリは、特定の要素を値に設定する代入クエリ、または連続した部分配列の合計を求める範囲合計クエリのいずれかです。 複数の独立したテスト ケースがあり、それぞれに独自の配列とクエリがあります。 出力は単に合計クエリの結果を順番に並べたものです。 

制約は厳しく、テスト ケースごとの配列の長さとクエリの数はそれぞれ最大$10^5$、すべてのテスト ケースの合計は次の値に達します。$10^6$。 これにより、すべての合計クエリの範囲をスキャンする単純なアプローチが排除されます。 素朴な解決策には時間がかかります$O(n)$合計クエリごとに、最大で$10^{11}$合理的な制限時間をはるかに超えた最悪の場合の作戦。 

クエリが更新前に配列全体の合計を要求する場合、微妙なエッジ ケースが発生します。 このシナリオでは、値が初期化されていると想定する不注意な実装により、初期化されていないメモリを読み取ろうとしたり、計算を誤ったりする可能性がありますが、正しい合計はゼロになります。 もう 1 つのエッジ ケースは、同じ位置への更新が繰り返されることで、以前の値を蓄積するのではなく上書きする必要があります。 

## アプローチ

 ブルートフォース手法は簡単です。 配列を明示的に維持し、各クエリを明白な方法で処理します。 割り当ては次の場所で行われます$O(1)$ただし、合計クエリでは左のインデックスから右のインデックスまで繰り返す必要があります。$O(n)$最悪の場合。 と$q$クエリの場合、全体的な複雑さは以下に達する可能性があります$O(nq)$、これは大規模な入力には遅すぎます。 

パフォーマンスを向上させるための重要な洞察は、ポイント更新と範囲合計クエリをサポートするだけでよいということです。 これは、フェンウィック ツリー (バイナリ インデックス付きツリー) またはセグメント ツリーの機能と正確に一致します。 どちらのデータ構造でもポイントの更新が可能です。$O(\log n)$および範囲合計クエリ$O(\log n)$。 Fenwick Tree は実装が簡単で、このタイプのクエリでは実際にはわずかに高速です。 

重要な点は、配列の値が増分されず、置き換えられるだけであるということです。 フェンウィック ツリーの場合、現在の値を別の配列に保存して各割り当ての差分を計算し、その差分をツリーに伝播することができます。 これにより、各クエリを次のように処理できるようになります。$O(\log n)$、合計操作を以下に抑えます$10^7$問題の制約について。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | フェンウィックツリー | O(q log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに 2 つの配列を初期化します。1 つは現在の値を保存するためのメイン配列で、もう 1 つは効率的なプレフィックス合計を得るために 1 つのフェンウィック ツリー配列です。 これにより、割り当てと範囲クエリの両方を効率的に処理できる構造がセットアップされます。 
2. タイプ 1 クエリの場合、`1 x y`、新しい値の差を計算します。`y`とその位置の現在値`x`。 メイン配列の位置を更新します。`x`新しい価値観で。 次に、この違いをフェンウィック ツリーを通じて伝えます。 差を伝播すると、合計を最初から再計算することなく、将来の範囲合計クエリに更新された値が確実に反映されます。 
3. タイプ 2 クエリの場合、`2 l r`、プレフィックスの合計を計算して、`r`フェンウィック ツリー内でプレフィックスの合計を減算し、`l-1`。 これにより部分配列の合計が得られます`[l, r]`。 この値を出力します。 
4. 各クエリおよび各テスト ケースに対して上記の手順を個別に繰り返します。 

機能する理由: フェンウィック ツリーは、各ノードが配列の部分和を格納するという不変条件を維持します。 値を更新すると、その差分が関連するすべてのノードに伝播され、プレフィックス合計クエリが正しい合計を返すことが保証されます。 範囲合計クエリは 2 つのプレフィックス合計の差分になり、数学的には要素の直接合計と等価になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def add(bit, i, delta):
    n = len(bit)
    while i < n:
        bit[i] += delta
        i += i & -i

def prefix_sum(bit, i):
    result = 0
    while i > 0:
        result += bit[i]
        i -= i & -i
    return result

def main():
    T = int(input())
    for _ in range(T):
        n, q = map(int, input().split())
        arr = [0] * (n + 1)
        bit = [0] * (n + 1)
        for _ in range(q):
            query = input().split()
            if query[0] == '1':
                x, y = int(query[1]), int(query[2])
                delta = y - arr[x]
                arr[x] = y
                add(bit, x, delta)
            else:
                l, r = int(query[1]), int(query[2])
                result = prefix_sum(bit, r) - prefix_sum(bit, l - 1)
                print(result)

if __name__ == "__main__":
    main()
```このソリューションでは、まず、フェンウィック ツリーを更新し、プレフィックスの合計を計算するヘルパー関数を定義します。 の`add`関数は、関連するすべてのノードを通じてデルタを伝播します。`prefix_sum`ツリーを逆方向にたどり、関連する値を合計します。 メイン ループでは、各テスト ケースを読み取り、配列とツリーを初期化し、そのタイプに応じて各クエリを処理します。 重要な点は差を計算することです`delta`正確さを維持するための割り当ての場合。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n+q) log n) | 各クエリの更新または合計には O(log n) が必要です。 配列の初期化はテスト ケースごとに O(n) です。 |
 | スペース | O(n) | 配列とフェンウィック ツリーをテスト ケースごとに保存します。 |

 の合計を考えると、`n`そして`q`すべてのテスト ケースで最大でも$10^6$、合計の操作は次のとおりです。$2 \cdot 10^6 \cdot \log 10^5 \approx 2 \cdot 10^6 \cdot 17$、2 秒の制限内に快適に収まります。
