 ## 問題の理解

 長さのバイナリ文字列が与えられます$n$ただし、各位置は固定されるのではなく、ランダム ビットとして独立して生成されます。$1$確率的に$p = \frac{a}{b}$そして$0$確率的に$1 - p$。 

文字列が生成された後、その文字列に対して特定の操作を複数回適用できます。 各操作は次のように機能します。1 つのインデックスを「中心」として選択し、選択されたすべての「他の」インデックスが中心と反対のビットを持つように、少なくとも 1 つの他のインデックスを選択します。 次に、選択したすべてのビットを同時に反転します。 

ビットセットから開始して、最終的にすべてのビットを少なくとも 1 回反転する一連の操作が存在する場合、そのビットセットは有効であると呼ばれます (同様に、許可された操作を通じてすべてのインデックスを完全に「アクティブ化」できます)。 

タスクは、ランダムに生成されたビットセットが有効である確率を計算し、それを法の下で剰余分数として出力することです。$1{,}234{,}567{,}891$。 

制約は非常に大きいです。$n$まで可能です$10^9$したがって、構成を列挙したり、操作をシミュレートしたり、インデックスのサブセットに応じて組み合わせ論を使用したりするソリューションは、直ちに不可能になります。 唯一実行可能な方向は、次の点で閉じた形式の式です。$n$、高速累乗を使用して計算されます。 

この問題の微妙な点は、ランダム性はすべてのビットセットにわたっていますが、有効性の条件はローカル パターンではなく、ビット分布のグローバル構造のみに依存することです。 これは、私たちが数えている構造的なケースの数が少ないことを強く示唆しています。 

エッジ ケースの 1 つは、すべてのビットが同一である場合です。 この状況では、選択した中心とペアになる反対の値のインデックスがないため、操作を開始することさえできません。 たとえば、$n = 3$、文字列`000`そして`111`すぐに行き詰まってしまいます。 

単純な間違いは、非定数文字列が有効であると仮定することです。 小規模な例では、0 と 1 の両方があると常に少なくとも 1 つの可能な演算が得られるため、これはもっともらしいと思われます。 ただし、隠れた接続制約がある場合、この直感は失敗しますが、この問題では、操作が十分に柔軟であるため、混合構成を段階的に拡張できます。 

## アプローチ

 強引なアイデアは、すべてを生成することです。$2^n$ビットセットを調べて、それぞれが「素晴らしい」かどうかをシミュレートします。 状態の指数関数的な数を無視しても、各シミュレーションには、有効な方法で長さが制限されていない一連の操作が含まれるため、このアプローチは、たとえ小さなものであっても完全に実行不可能です。$n$。 

重要な簡素化は、両方の値が存在すると操作が非常に強力になることに気づくことから始まります。 ビットセットに少なくとも 1 つが含まれている場合`0`そして少なくとも1つ`1`そうすると、いつでも中心と反対側のグループを選択し、繰り返しの操作を使用して配列全体に反転を伝播することができます。 両方の値が配列内のどこかに存在する限り常に続行できるため、操作の正確な順序は重要ではありません。 

すべての進行をブロックする唯一の構成は、ビットセットが均一な場合です。 その場合は有効な先手がないので最初から処理が不可能です。 

したがって、問題はコンピューティングに帰着します。$$\mathbb{P}(\text{bitset is not all 0 and not all 1})$$つまり:$$1 - \mathbb{P}(\text{all 0}) - \mathbb{P}(\text{all 1})$$ビットは独立しているため、次のようになります。$$\mathbb{P}(\text{all 1}) = \left(\frac{a}{b}\right)^n,\quad
\mathbb{P}(\text{all 0}) = \left(\frac{b-a}{b}\right)^n$$したがって、答えはべき乗を含む単純なモジュラー式になります。

 ## アルゴリズムのチュートリアル

 生成されたビットセットが単色ではない確率を計算したいと考えています。 

1. 確率をモジュラー算術形式に変換します。 私たちは代表します$p = a \cdot b^{-1}$モジュロ$M$、同様に$1-p = (b-a) \cdot b^{-1}$。 
2. コンピューティング$b^n$モジュロ$M$高速累乗を使用します。 これは分母の寄与を表します。 
3. コンピューティング$a^n \bmod M$、すべて 1 の場合の分子に対応します。 
4. コンピューティング$(b-a)^n \bmod M$、すべてゼロの場合の分子に対応します。 
5. 2 つの悪いケースを組み合わせます。$$\text{bad} = a^n + (b-a)^n \pmod M$$6. で割って正規化します。$b^n$これはモジュラーインバースを使用して行われます。$$\text{bad} \cdot (b^n)^{-1}$$7. 1 から減算して、最終的な答えを求めます。 

### なぜ効果があるのか

 重要な特性は、演算シーケンスの実行を妨げる唯一の障害は、両方のビット値が存在しないことであるということです。 0 と 1 の両方が存在する場合、すべての操作で 1 つのタイプの中心と少なくとも 1 つの反対の要素を選択できるという事実が維持されるため、進行が行き詰ることはありません。 したがって、無効な構成のセットは 2 つの極端な一様なケースに正確に崩壊し、確率は単純な除外計算になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1234567891

def mod_pow(a, e):
    res = 1
    a %= MOD
    while e:
        if e & 1:
            res = res * a % MOD
        a = a * a % MOD
        e >>= 1
    return res

n, a, b = map(int, input().split())

inv_b = pow(b, MOD - 2, MOD)

p_num = a % MOD
q_num = (b - a) % MOD

a_n = mod_pow(p_num, n)
b_n = mod_pow(b % MOD, n)
q_n = mod_pow(q_num, n)

inv_b_n = pow(b_n, MOD - 2, MOD)

bad = (a_n + q_n) % MOD
bad = bad * inv_b_n % MOD

ans = (1 - bad) % MOD
print(ans)
```実装では、分子と分母の処理を明示的に分離します。 重要な点は、直接計算をしないことです。$(a/b)^n$モジュラー除算は逆関数で処理する必要があるためです。 もう 1 つの重要な詳細は、両方を計算することです。$a^n$そして$(b-a)^n$モジュラスの下で独立して計算されるため、正規化前に精度が決して失われないことが保証されます。

 ## 特殊なケース

 最も重要なエッジケースは、ビットセットが完全に均一である場合です。 たとえば、入力の場合`n = 4, a = 0`、生成されたすべての文字列は`0000`。 アルゴリズムは計算します$a^n = 0$、$(b-a)^n = b^n$, したがって、悪い確率は 1 になり、最終的な答えは 0 となり、演算が不可能であるという事実と一致します。 

もう 1 つのエッジケースは次のような場合です$a = b$、すべてのビットが常に 1 であることを意味します。計算は対称になります。$(b-a)^n = 0$、やはり妥当性の確率は 0 です。 

最後に、いつ$n = 1$、すべての文字列は自明に均一であるため、答えは常に 0 になります。正規化後に両方の項が直接 1 に減り、結果がゼロになるため、数式はこれをきれいに処理します。
