 ## 解決策
 ## 問題の理解

 長さのシーケンスが与えられます`n`。 このステートメントでは文字列について説明していますが、文字は整数で表され、アルファベットは非常に大きくなります。 アルファベットのサイズが大きいということは、少数の個別の記号に依存するトリックに頼ることができないことを意味します。 

各クエリは 2 つの開始位置と長さを指定します。 その長さの 2 つの連続するセグメントが同一であるかどうかを判断する必要があります。 

より具体的に言うと、クエリの場合`(len, pos1, pos2)`を比較します。 

-`a[pos1 ... pos1 + len - 1]`-`a[pos2 ... pos2 + len - 1]`そして印刷する`"Yes"`対応するすべての要素が一致する場合、そうでない場合`"No"`。 

制約は問題の重要な部分です。 両方`n`そして`q`200,000 に達する可能性があります。 2 つの部分文字列を直接比較するには、次のようになります。`O(len)`時間。 最悪の場合、`len`も 200,000 であるため、1 つのクエリで 200,000 の比較が必要になる場合があります。 200,000 クエリの場合、これはおおよそ次のようになります。`4 × 10^10`要素の比較は、2 秒の制限内で実行できる範囲をはるかに超えています。 

このタスクは実際には、静的シーケンスに対する多数の部分文字列の等価性チェックです。 この構造は、各クエリに定数時間または対数時間で応答できる前処理データ構造を構築することを強く示唆しています。 

いくつかの特殊なケースは注目に値します。 

同一の開始位置を考慮します。```
n = 5
a = [1,2,3,4,5]

query: len=5, pos1=1, pos2=1
```答えは明らかに`"Yes"`。 正しい部分文字列比較メソッドは、特別な場合を除いてこれを処理する必要があります。 

配列の最後まで到達する比較を考えてみましょう。```
n = 5
a = [1,2,3,4,5]

query: len=2, pos1=4, pos2=4
```比較されるセグメントは、`[4,5]`。 ここでは、プレフィックス計算におけるオフバイワンの間違いがよく発生します。 

もう 1 つの重要なケースは、2 つの部分文字列が長い共通のプレフィックスを共有しているが、末尾が異なる場合です。```
a = [7,7,7,7,8]
query: len=5, pos1=1, pos2=?
```部分的なプレフィックスのみをチェックする不注意な最適化では、等価性が誤って判断される可能性があります。 全長は衝突耐性表現を通じて検証する必要があります。 

最後に、アルファベットには 987,898,788 までの値が含まれます。 固定サイズの頻度配列や文字値でインデックス付けされた遷移テーブルなど、文字が小さなアルファベットに収まると仮定するアプローチはいずれも不適切です。 

## アプローチ

 ブルートフォースの解決策は簡単です。 クエリごとに、要求された 2 つの部分文字列を要素ごとに比較します。 すべての位置が一致した場合に出力`"Yes"`; それ以外の場合は出力`"No"`。 

部分文字列の等価性はすべての位置での等価性によって正確に定義されるため、総当り方式は正しいです。 問題はその稼働時間だ。 クエリには必要な場合があります`O(len)`仕事、そして`len`多分`O(n)`。 と`q = 200000`そして`n = 200000`、最悪の場合は`O(nq)`、約400億件の比較。 

配列は決して変更されず、すべてのクエリは同じ種類の質問をします: 2 つの範囲は等しいか? 基礎となる要素を繰り返し検査する代わりに、シーケンスを前処理して、すべてのプレフィックスにコンパクトなフィンガープリントを割り当てることができます。 その後、任意の部分文字列のフィンガープリントを一定時間で抽出できます。 

多項式ローリング ハッシュは自然に適合します。 させて$$H[i]$$最初のハッシュを示します`i`要素。 固定基数の累乗を使用すると、2 つのプレフィックス ハッシュから任意の部分文字列のハッシュを復元できます。 

2 つの部分文字列が等しい場合、それらのハッシュは等しくなります。 二重ハッシュを使用すると、異なる部分文字列が同じハッシュのペアを生成する確率は無視できるほどになります。 前処理の後、各クエリは 2 つのハッシュ ペアを比較することになり、一定の時間がかかります。 

ブルートフォース ソリューションでは、同じ要素を繰り返し検査します。 ハッシュにより各部分文字列が一定サイズの表現に圧縮され、各クエリに即座に応答できるようになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) 最悪の場合 | お(1) | 遅すぎる |
 | 最適 (ダブルローリングハッシュ) | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. シーケンスを読み取ります。 
2. 2 つの大きな弾性率と固定ベースを選択します。 
3. 両方の法を法とする基本の累乗を事前計算します。 

これらの力により、部分文字列ハッシュを一定時間内に正規化することができます。 
4. 両方のモジュールのプレフィックス ハッシュ配列を構築します。 

位置ごとに、現在の値を追加して前のプレフィックス ハッシュを拡張します。 
5. 関数を定義する`get_hash(l, r)`部分配列のハッシュペアを返します`l`に`r`包括的な。 

プレフィックス ハッシュの使用:$$H(l,r)=H[r]-H[l-1]\cdot P^{r-l+1}$$各係数を法として計算されます。 
6. すべてのクエリについて、1 から始まる位置を対応する間隔のエンドポイントに変換します。 
7. 最初の部分文字列のハッシュ ペアを計算します。 
8. 2 番目の部分文字列のハッシュ ペアを計算します。 
9. 両方のハッシュ ペアが同一の場合、次のように出力します。`"Yes"`、それ以外の場合は印刷します`"No"`。 

### なぜ効果があるのか

 プレフィックス ハッシュ構造により、すべての部分文字列がその要素の多項式で表現されることが保証されます。 部分文字列の前にあるプレフィックスの寄与を削除すると、部分文字列自体にのみ依存する値が得られます。 

2 つの等しい部分文字列は、まったく同じ多項式を生成するため、まったく同じハッシュ ペアが生成されます。 各クエリは、要求された 2 つの範囲のハッシュ表現を比較します。 両方のハッシュは同じ式を使用して抽出されるため、等しい部分文字列は常に等しいと比較されます。 ダブル ハッシュにより、偶発的な衝突がほとんど起こりにくくなります。これは、部分文字列の等価性クエリに使用される標準的な競争プログラミングの保証です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    MOD1 = 1_000_000_007
    MOD2 = 1_000_000_009
    BASE = 911382323

    pow1 = [1] * (n + 1)
    pow2 = [1] * (n + 1)

    for i in range(1, n + 1):
        pow1[i] = (pow1[i - 1] * BASE) % MOD1
        pow2[i] = (pow2[i - 1] * BASE) % MOD2

    pref1 = [0] * (n + 1)
    pref2 = [0] * (n + 1)

    for i in range(n):
        pref1[i + 1] = (pref1[i] * BASE + a[i] + 1) % MOD1
        pref2[i + 1] = (pref2[i] * BASE + a[i] + 1) % MOD2

    def get_hash(l, r):
        h1 = (
            pref1[r]
            - pref1[l - 1] * pow1[r - l + 1]
        ) % MOD1

        h2 = (
            pref2[r]
            - pref2[l - 1] * pow2[r - l + 1]
        ) % MOD2

        return h1, h2

    ans = []

    for _ in range(q):
        length, p1, p2 = map(int, input().split())

        h_first = get_hash(p1, p1 + length - 1)
        h_second = get_hash(p2, p2 + length - 1)

        ans.append("Yes" if h_first == h_second else "No")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```前処理段階では、ベース ハッシュとプレフィックス ハッシュの累乗を構築します。 どちらの配列も 0 からインデックスが付けられますが、部分文字列クエリは自然に 1 から始まる位置を使用して表現されるため、ハッシュ抽出式は 1 から始まる形式で直接記述されます。 

追加`1`ハッシュに挿入する前に各要素に追加することで、先頭の位置でゼロ値が非表示になるのを防ぎます。 この調整を行わないと、一部の多項式表現の堅牢性が低下します。 

の`get_hash`機能は重要な部分です。 位置以前のすべての寄与を削除します`l`そして、要求された間隔に対応する多項式のみを残します。 間隔の長さによって、どのべき乗数を削除する必要があるかが決まります。 

各クエリは 2 つのハッシュ ペアを計算し、それらを比較します。 基礎となる部分文字列を走査する必要はありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    MOD1 = 1_000_000_007
    MOD2 = 1_000_000_009
    BASE = 911382323

    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    pow1 = [1] * (n + 1)
    pow2 = [1] * (n + 1)

    for i in range(1, n + 1):
        pow1[i] = (pow1[i - 1] * BASE) % MOD1
        pow2[i] = (pow2[i - 1] * BASE) % MOD2

    pref1 = [0] * (n + 1)
    pref2 = [0] * (n + 1)

    for i in range(n):
        pref1[i + 1] = (pref1[i] * BASE + a[i] + 1) % MOD1
        pref2[i + 1] = (pref2[i] * BASE + a[i] + 1) % MOD2

    def get_hash(l, r):
        return (
            (pref1[r] - pref1[l - 1] * pow1[r - l + 1]) % MOD1,
            (pref2[r] - pref2[l - 1] * pow2[r - l + 1]) % MOD2,
        )

    ans = []

    for _ in range(q):
        length, p1, p2 = map(int, input().split())
        ans.append(
            "Yes"
            if get_hash(p1, p1 + length - 1)
            == get_hash(p2, p2 + length - 1)
            else "No"
        )

    sys.stdin = old_stdin
    sys.stdout = old_stdout

    return "\n".join(ans) + ("\n" if ans else "")

# provided sample
assert run(
"""5 2
1 2 3 1 2
2 1 4
3 1 3
"""
) == "Yes\nNo\n", "sample 1"

# minimum size
assert run(

7
1 1 1
"""
) == "Yes\n"

# all equal
assert run(
"""5 2
4 4 4 4 4
3 1 3
2 2 4
"""
) == "Yes\nYes\n"

# boundary at end of array
assert run(
"""5 1
1 2 3 4 5
2 4 4
"""
) == "Yes\n"

# off-by-one check
assert run(
"""5 1
1 2 3 4 5
2 1 2
"""
) == "No\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一要素配列 | はい | 最小の法的入力 |
 | すべての値は等しい | はい、はい | 繰り返しパターンの処理 |
 | 位置 n で終了するクエリ | はい | 境界の正確性 |

 ## 特殊なケース

 可能な限り最小のインスタンスを考えてみましょう。```
1 1
7
1 1 1
```唯一の部分文字列は`[7]`。 範囲のハッシュ`[1,1]`は 2 回計算され、それ自体と比較されます。 両方のハッシュが一致するため、答えは次のようになります。`"Yes"`。 

配列の末尾に触れるクエリを考えてみましょう。```
5 1
1 2 3 4 5
2 4 4
```比較される範囲は、`[4,5]`そして`[4,5]`。 べき乗項で使用される長さは次のとおりであるため、ハッシュ関数はちょうど 2 つの要素を抽出します。`r - l + 1 = 2`。 余分な要素は含まれておらず、要素も省略されていません。 

長い共通プレフィックスを持つ 2 つの範囲を考えてみましょう。```
5 1
7 7 7 7 8
4 1 2
```比較される部分文字列は次のとおりです。```
[7,7,7,7]
[7,7,7,8]
```最初の 3 つの位置は一致しますが、最後の位置は異なります。 最終的な係数が異なる値に寄与するため、それらの多項式ハッシュは異なります。 アルゴリズムの出力`"No"`。 

同一の開始位置を考慮します。```
5 1
1 2 3 4 5
5 1 1
```クエリされた両方の間隔はまったく同じ範囲です。 抽出されたハッシュ ペアは同一であるため、アルゴリズムは次の値を返します。`"Yes"`通常の比較ロジックを介して直ちに実行されます。 特別な取り扱いは必要ありません。
