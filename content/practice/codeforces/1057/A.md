 **タグ:** *特別、DFS および類似の、木
 **解決時間:** 4 分 52 秒

 ## 解決策
 ## 問題の理解

 ルーター 1 をルートとするツリーを形成する、ルーターのネットワークが拡大しています。最初のルーターを除くすべてのルーターが 1 台ずつ追加され、新しいルーターはそれぞれ 1 台の以前のルーターに直接接続されました。 これは、すべてのルーターには 1 つの親があり、ルーター 1 は親のない元のルートであることを意味します。 

入力により、2 から n までの各ルーターについて、作成時に接続されていたルーターのインデックスが得られます。 この情報からツリー構造を再構築できますが、このタスクは構造全体を要求するわけではありません。 代わりに、1 つの特定のルート、つまりルーター 1 からルーター n への一意のパスのみに関心があります。 

各ルーターには親が 1 つだけあるため、このツリーにはノード 1 からノード n への単純なパスが 1 つだけ存在します。 出力には、このパス上のノードが順番にリストされる必要があります。 

n が 200000 までという制約は、すべての解が線形または線形に近いものでなければならないことを意味します。 パスの検索または再構築を繰り返す 2 次アプローチは、最悪の場合、10^10 のオーダーで実行される可能性があるため、非常に遅くなります。 シングルパスの再構成または単純なトラバースが必要です。 

親を保存せずに「上方への歩行をシミュレート」しようとすると、微妙な問題が発生します。 親ポインターを明示的に記録しない場合、祖先を繰り返し再計算する可能性があり、スキャンが繰り返されることになり、非効率的になります。 もう 1 つの潜在的な間違いは、パス再構築の正確さを保証せずに隣接リストを構築し、DFS を 1 から n まで実行することです。これにより、一意の単純なパスではなく完全なトラバーサル パスが誤って返される可能性があります。 

## アプローチ

 この問題を解決する強引な方法は、隣接リストを使用して完全なツリーを構築し、ノード n が見つかるまでノード 1 から深さ優先検索を実行することです。 DFS の間、現在のパスを維持し、n に達するとそれを返します。 これが機能するのは、グラフがツリーであるため、2 つのノード間にはパスが 1 つだけ存在するためです。 

ただし、このアプローチでは、大きなサブツリーを不必要に探索する危険があります。 最悪の場合、DFS はノード n を見つける前にほぼすべてのエッジを走査し、O(n) 走査につながる可能性があります。 O(n) は実際には許容されますが、実装は必要以上に複雑で、バックトラッキングが誤って処理されると簡単に誤って記述される可能性があります。 

重要な点は、検索する必要がまったくないということです。 各ノードはその親を明示的に格納します。 これは、親ポインターを繰り返したどることによって、n から 1 に戻るパスを再構築できることを意味します。 ノード 1 に到達したら、収集したシーケンスを逆にして、正しい方向のパスを取得します。 

これにより、問題は単純なポインタ追跡プロセスに縮小され、パスの長さ (最大 n) が線形であることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 1 から n までの DFS 検索 | O(n) | O(n) | 受け入れられるが不要 |
 | 親チェーンの再構築 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ノード 1 を除くすべてのノードには親が 1 つだけあるという事実を利用します。 

1. p[i] がノード i の親を示す親配列を読み取ります。 親がないため、概念的には p[1] = 0 と定義します。 
2. ノード n から開始してその親に繰り返し移動し、訪問した各ノードをリストに保存します。 これにより、パスが逆の順序で構築されます。 
3. ノード 1 がツリーのルートであるため、ノード 1 に到達したら停止します。 
4. 収集したリストを逆にして、1 から始まり n で終わるようにします。 
5. 結果のシーケンスを出力します。 

親関係は常により小さいインデックスに厳密に向かうため、各ステップは安全です。そのため、無限に循環したりループしたりすることはできません。 

### なぜ効果があるのか

親ポインターは、ルート付きツリー構造を定義します。 ツリーでは、すべてのノードにルートへの単純なパスが 1 つだけあります。 インデックスはエッジに沿って厳密に減少するため (p[i] < i)、任意のノードから親リンクをたどると、最終的にはルートに到達する必要があります。 これにより終了が保証されます。 n から上向きのパスは 1 つだけであるため、収集したシーケンスはまさに n から 1 への一意のパスであり、それを逆にすると 1 から n への必要なパスが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = [0] * (n + 1)

    vals = list(map(int, input().split()))
    for i in range(2, n + 1):
        p[i] = vals[i - 2]

    path = []
    cur = n

    while cur != 0:
        path.append(cur)
        cur = p[cur]

    path.reverse()
    print(*path)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、定数時間アクセスのために親配列を直接インデックス形式で再構築します。 次に、ノード n から開始し、ルートに到達するまで親ポインターをたどります。 収集されたリストは最後に逆になります。これは、走査が自然に子から親に進む一方で、必要な出力はルートからターゲットに向かうためです。 

よくある間違いは、ノード 1 で正確に停止することを忘れたり、ノード 1 の親を誤って初期化したりすることです。これにより、無効な検索が発生します。 もう 1 つの問題は、ノードを間違った順序で追加し、最後に反転するのを忘れることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | 各ノードは、親ポインタをたどっている間に最大 1 回アクセスされます。 
| スペース | O(n) | 親配列とパスのストレージ |

 アルゴリズムは線形時間で実行されます。最大 n 個のノードを出力する必要があるため、これが最適です。 メモリ使用量も線形であり、制約内に快適に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()

    def solve():
        n = int(input())
        p = [0] * (n + 1)
        vals = list(map(int, input().split()))
        for i in range(2, n + 1):
            p[i] = vals[i - 2]

        path = []
        cur = n
        while cur != 0:
            path.append(cur)
            cur = p[cur]

        print(*path[::-1])

    with redirect_stdout(out):
        solve()

    return out.getvalue().strip()

# provided sample
assert run("8\n1 1 2 2 3 2 5\n") == "1 2 5 8"

# custom 1: minimum size
assert run("2\n1\n") == "1 2"

# custom 2: linear chain
assert run("5\n1 2 3 4\n") == "1 2 3 4 5"

# custom 3: star-shaped tree
assert run("6\n1 1 1 1 1\n") == "1 6"

# custom 4: mixed structure
assert run("7\n1 2 2 3 3 4\n") == "1 2 3 4 7"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 2ノードの場合 | 1 2 | 最小限のツリーの正確性 |
 | チェーン構造 | 1 2 3 4 5 | ディープパス再構築 |

 ## 特殊なケース

 主なエッジケースは、ツリーが 1 から n までの直鎖である場合です。 その状況では、すべてのノードが前のノードを指すため、アルゴリズムは可能な最大の深さをトラバースする必要があります。 n から開始して、親を繰り返したどります: n → n−1 → … → 1。収集された反転パスは、分岐の曖昧さなしに 1 から n までのシーケンス全体を正しく出力します。 

もう 1 つのエッジ ケースは、すべてのノードが 1 に直接接続する星型ツリーです。この場合、n の親は 1 なので、パスは n → 1 を 1 → n に反転するだけです。 このアルゴリズムは、構造には依存せず、親ポインターのみに依存するため、特別なケースを使用せずにこれを処理します。 

3 番目の微妙なケースは、n = 2 など、n が小さい場合です。ここでも、ループは 1 回正しく実行され、[2, 1] を収集し、それを [1, 2] に反転します。これは、終了条件がルートを適切に処理していることを示しています。
