 ## 解決策
 ## 問題の理解

 タイムラインは数秒に分割されています。 1 秒ごとに、サーバーにヒットしたリクエストの数がわかります。 これにより、各位置がその秒間のリクエスト量を表す配列が得られます。 

その間隔内のリクエストの総数が間隔の長さの 100 倍を厳密に超えるような、最長の連続する時間間隔を見つける必要があります。 言い換えれば、ある長さのセグメントを選択すると、`t`、その中のリクエストの合計は次を超えています`100 * t`、そのセグメントは攻撃期間とみなされ、そのようなセグメントの可能な限り最大の長さが必要です。 

入力サイズは最大 5000 秒で、各値も最大 5000 まで可能です。n^2 は約 2,500 万回の演算であるため、O(n^2) ソリューションが受け入れられることがすぐにわかります。これは、プレフィックス合計を使用した Python では 2 秒に快適に収まります。 

重要な観察は、条件が区間にわたる合計のみに依存するということです。 これにより、一定の時間範囲の合計クエリが可能になるため、プレフィックス合計が自然なツールになります。 

主な困難は合計を計算することではなく、すべての候補区間を効率的にチェックし、有効な最大長を抽出することです。 

条件を満たす間隔がない場合、微妙なエッジ ケースが発生します。 たとえば、すべての値が 0 の場合、すべての間隔の合計は 0 となり、これより大きくなることはありません。`100 * t`。 この場合、答えは負の数や -1 ではなく、0 でなければなりません。 

もう 1 つの特殊なケースは、単一の要素のみが条件を満たす場合です。 たとえば、次の場合`r[i] = 101`の場合、長さ 1 の間隔は有効ですが、それより長い間隔は失敗する可能性があります。 ソリューションでは、すべての有効な長さを正しく検出して比較する必要があります。 

最後に、条件が厳密であることに注意してください。`sum > 100 * length`。 使用する`>=`代わりに、まさに次のような境界線のケースが誤って含まれてしまいます`100 * t`。 

## アプローチ

 直接的なアプローチでは、考えられるすべてのサブ配列がチェックされます。 開始インデックスごとに`i`、すべての終了インデックスまで拡張します`j`、の合計を計算します`r[i..j]`を超えているかどうかを確認します。`100 * (j - i + 1)`。 これは、可能なすべての間隔を明示的に評価するため、正しいです。 

ただし、間隔ごとに合計を最初から再計算すると、単純に実行すると O(n^3) の複雑さになります。 部分的に再利用した場合でも、増分合計更新を伴う二重ループでは O(n^2) が得られます。これは、ブルート フォース形式で期待できる最高の値です。 

主な改善点は、プレフィックスの合計を事前計算して、任意の間隔の合計を O(1) で計算できるようにすることです。 これにより、各ペアのチェックが減少します`(i, j)`一定時間に。 まだすべてのペアを列挙していますが、各小切手が安くなりました。 

問題の構造では、2 つのポインターまたは二分探索を可能にする単調制約なしで最長有効区間を明示的に要求するため、O(n^2) よりも優れた値は許容されません。 この条件は間隔の長さが単調ではないため、スライディング ウィンドウ手法は適用されません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (ネスト + 再計算) | O(n^3) | お(1) | 遅すぎる |
 | プレフィックスの合計 + O(n^2) 列挙 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックス合計配列を構築します。`pref[i]`最初の合計を格納します`i`要素。 これにより、後でセグメントの合計を高速に計算できるようになります。 
2. 可能なすべての左側のエンドポイントを反復処理します。`l`0 から n - 1 まで。 
3. それぞれについて`l`、右の端点を延長します`r`から`l`n - 1まで。 
4. セグメントの合計を計算します。`[l, r]`を使用して`pref[r+1] - pref[l]`。 
5. セグメントの長さを次のように計算します。`r - l + 1`。 
6.次のことを確認します。`segment_sum > 100 * length`。 
7. 条件が当てはまる場合は、これまでに確認された最大長で回答を更新します。 

すべてをスキャンする理由`(l, r)`ペアは、有効な間隔がこの列挙内のどこかに出現する必要があるということです。 プレフィックス合計により、重複する合計を繰り返し再計算することがなくなります。 

### なぜ効果があるのか

 このアルゴリズムは、考えられるすべての連続間隔を 1 回だけ評価します。 各間隔について、チェックの正しさは、その合計とその長さに基づく線形しきい値との間の正確な算術比較のみに依存します。 プレフィックス合計は正確な間隔合計を与えるため、近似やヒューリスティックは必要ありません。 したがって、条件を満たす区間が検出され、その中の最大長が追跡されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    r = list(map(int, input().split()))

    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + r[i]

    ans = 0

    for l in range(n):
        for rgt in range(l, n):
            total = pref[rgt + 1] - pref[l]
            length = rgt - l + 1
            if total > 100 * length:
                if length > ans:
                    ans = length

    print(ans)

if __name__ == "__main__":
    solve()
```
