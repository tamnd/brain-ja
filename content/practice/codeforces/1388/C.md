 ## 問題の理解

 この国は都市 1 をルートとする都市のツリーであり、すべての国民は首都で 1 日を開始し、ツリー内の固有の最短経路をたどって故郷の都市に戻ります。 各都市には複数の都市に分かれた既知の人口があり、すべての人の機嫌が良いか悪いかに応じて +1 または -1 のいずれかに貢献します。 

重要な観察は、人が都市の幸福度指数に影響を与えることができるのは、首都から自宅に向かう途中でその都市を通過するときだけだということです。 すべてのパスは単純なルートからノードへのパスであるため、すべての市民はツリー内の 1 つのパスに沿って正確に貢献します。 

都市ごとに目標値 h[i] が与えられますが、これはその都市を通過するすべての人々の貢献の最終合計に等しいと想定されます。 タスクは、これらすべての h[i] 値が同時に達成できるような、気分 (良いまたは悪い) の割り当てと、パスに沿った起こり得る気分の変化が存在するかどうかを判断することです。 

この制約により、テスト ケースごとに線形または線形に近い解決策が求められます。 合計ノード数が最大 2⋅10^5、テスト ケースが最大 10^4 の場合、テスト ケースあたり O(n) または全体で O(n log n) を超えるソリューションは危険にさらされます。 m は 10^9 に達する可能性があるため、すべての人を個別に追跡する単純なシミュレーションは不可能です。 

微妙なエッジ ケースは、都市に人口がなく、h[i] がゼロ以外の場合に発生します。 たとえば、葉の都市の p[i] = 0 であるが h[i] = 5 である場合、そこに余分な人々を生成できるパスがないため、これは直ちに不可能になります。 もう 1 つの注意が必要な状況は、値がローカルでは一貫しているように見えても、グローバルでは親から子への流れの保存に違反する場合です。 

## アプローチ

 強引な解釈では、各人を別々に扱うことになります。 m 人それぞれに気分を割り当て、ルートから自宅までの経路をシミュレートし、訪問したすべてのノードで貢献度をマークすることを想像できます。 これは概念的には正しいですが、各人が最大 O(n) 個のノードをトラバースして O(nm) 回の操作を行う可能性があるため、すぐには実行不可能になります。これは、m が 10^9 に達すると制限をはるかに超えます。 

私たちは、個人についての考え方から、集合的なフローについての考え方に移行する必要があります。 人を追跡する代わりに、各サブツリーを何人が通過する必要があるか、そのうち何人が不正行為を許可されるかを追跡します。 重要な洞察は、ツリー構造が再帰的分解を強制しているということです。各サブツリーは、その中の人々と上から流れてくるものだけを使用して、必要な幸福を「説明」する必要があります。 

ツリーを 1 にルートし、DFS を実行します。 各ノードで、そのサブツリーに何人の人がいるのか (これを合計と呼ぶ)、そして必要な幸福の制約を満たすためにはそのうちの何人が善良でなければならないかを計算します。 問題は、これらの必要な良好なカウントがすべてのサブツリーで有効な範囲内に収まるかどうかの実現可能性チェックになります。 

ノード u では、子サブツリーがそのサブツリー内の利用可能な人材よりも多くの「優れた貢献」を必要とすることがすでにわかっている場合、構成は不可能です。 同様に、必要な優秀な人材の数がマイナスであるか、総利用可能人数を超えている場合は不可能です。 

これにより、各サブツリーがその要件を上方に集約し、実現可能性がローカルでチェックされる貪欲な事後探索が行われます。

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、親から子への有向構造として扱います。

1. ツリーの隣接リストを作成します。 これにより、O(n) での効率的な走査が可能になります。 
2. ルートから DFS を実行します。 各ノード u について、その子から 2 つの値を計算します。それは、そのサブツリー内の人の総数と、以下のすべての制約を満たすためにそのサブツリーに存在する必要がある「必要な善良な人々」の数です。 

事後探索を使用する理由は、ノードの実現可能性は、その子が必要な貢献をどのように分配するかに完全に依存するためです。 
3. 各ノード u で、total_people = p[u] および required_good = 0 を初期化します。 
4. u のすべての子 v について、その (total_v、good_v) を再帰的に計算します。 total_v を total_people に追加し、good_v を required_good に追加します。 

この集約は、子サブツリー内のすべての人々がルートに到達する前に u を通過する必要があるため、制約が上向きに蓄積されることを反映しています。 
5. 子の処理後、幸福制約 h[u] を組み込みます。 現在の残高を、u を通過する良い寄与と悪い寄与の差とします。 サブツリー内の総人数は固定されているため、required_good を、h[u] を達成するためにこのサブツリー内で良好な状態を維持する必要がある人の数として解釈します。 

h[u] を、サブツリー u に何人の善良な人々が存在しなければならないかについての制約に変換します。 

required_good = (総人数 + h[u]) / 2。 

これは以下を解決することで得られます。 

良い - 悪い = h[u]

 良い + 悪い = total_people

 これは次のことを意味します:

 良い = (総人数 + h[u]) / 2
 6. (total_people + h[u]) が奇数であるか、required_good が [0, total_people] の範囲外の場合、リターン不可能です。 
7. (total_people, required_good) を親に上向きに返します。 
8. ルートが実行可能な場合は、「はい」と答えます。 

### なぜ効果があるのか

 各サブツリーは閉じたシステムとして扱われ、その中のすべての人々がルートへのパス上のすべてのノードに 1 回だけ貢献します。 寄与は加算的であり、パスはツリー内で一意であるため、各サブツリーは、主張する適切な割り当ての数がその総母集団および必要な純差 h[u] と一致していることを確認するだけで済みます。 DFS は、ノードが値をコミットする前にすべての子孫制約が満たされていることを保証するため、違反はできるだけ早いサブツリー境界で検出する必要があります。 

## Python ソリューション```python
import sys
sys.setrecursionlimit(10**7)
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    p = list(map(int, input().split()))
    h = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        g[a].append(b)
        g[b].append(a)

    def dfs(u, parent):
        total = p[u]
        good = 0

        for v in g[u]:
            if v == parent:
                continue
            t_v, g_v = dfs(v, u)
            total += t_v
            good += g_v

        if (total + h[u]) % 2 != 0:
            return -1, -1

        req_good = (total + h[u]) // 2

        if req_good < 0 or req_good > total:
            return -1, -1

        if good > req_good:
            return -1, -1

        return total, req_good

    ok_total, ok_good = dfs(0, -1)
    print("YES" if ok_total != -1 else "NO")

t = int(input())
for _ in range(t):
    solve()
```DFS はノードごとに 2 つの値を返します。そのサブツリー内の総人口と、そのノードで幸福度の制約を満たすために必要な善良な人々の数です。 パリティ チェックにより、善人と悪人の間に有効な分割が存在することが強制されます。 

よくある間違いは、パリティ条件を無視することです。 善と悪は整数なので、(total + h[u]) は偶数でなければなりません。 もう 1 つの微妙な点は、計算された required_good がサブツリーの合計を超えたり、ゼロを下回ったりしないようにすることです。

 ## 特殊なケース

 重要なエッジケースは、サブツリーの人口がゼロであるが、必要な幸福度がゼロではない場合です。 たとえば、p[i] = 0 および h[i] = 2 のリーフ ノードは、良好な状態または不良な状態の割り当てが存在しないため、すぐに失敗します。 DFS は、(total + h[i]) / 2 を計算するときにこれを捕捉し、負の値または小数値を生成します。 

もう 1 つの重要なケースは、すべての制約がローカルで有効であるにもかかわらず、親ノードが要求する優秀な人材が、子によってすでに修正されている人材よりも少ない場合です。 その状況では、good > required_good によって失敗がトリガーされ、子のコミットメントが上位レベルの集計によって違反されないことが保証されます。
