## アプローチ

 ブルートフォースのアイデアは単純です。 ごとに列挙する$n$-桁の数字$x$、バイナリ文字列を構築します$k$、最後の部分を削除します$n$ビット、計算$r$、そして最良の候補者を保持します。 

あらゆる可能性をチェックするため、これは正しいです。 残念ながら、たとえ$n=10$、 がある$9 \cdot 10^9$候補者たち。 実際の制約により、$n$まで$10^5$したがって、徹底的な検索はリモートでは実行できません。 

パターンを見つけるには、その方法を理解する必要があります。$r$が形成されます。 

数字$8$そして$9$は、10 進数の中で最も長いバイナリ表現を持つため、特別です。$$8 = 1000,\qquad 9 = 1001.$$両方とも 4 ビットを提供します。 1 桁おきに最大 3 ビットが寄与します。 

存続するプレフィックスの長さ$r$は$$|k| - n.$$2 進数を最大化するには、その長さを最大化することが最優先事項です。 各桁は最大 4 ビットを寄与するため、可能な限りすべての桁が 4 ビットを寄与するようにする必要があります。 つまり、すべての数字は次のいずれかである必要があります$8$または$9$。 

これで、すべての候補のバイナリの合計長が同じになりました$4n$したがって、結果として得られるすべての$r$長さがある$3n$。 比較は辞書編集的になります。 

のバイナリ文字列が$8$そして$9$最後のビットのみが異なります:$$1000,\qquad 1001.$$最後$n$連結のビットは破棄されます。 削除されたサフィックス内に完全に含まれるビットは、$r$。 

を置くとします。$8$終わり近くに。 その最後の部分は$0$の代わりに$1$によって提供される$9$。 とにかくその異なるビットが削除された場合、$9$に$8$影響しません$r$、作りながら$x$より小さい。 

したがって、最適な戦略は次のとおりです。 

1. 数字のみを使用する$8$そして$9$。 
2. 先頭の数字をできるだけ同じにしておきます。$9$、それらの異なるビットが内部で生き残るため$r$。 
3. 可能な最大の接尾辞を次のように置き換えます。$8$なぜなら、それらの数字の異なるビットは破棄された部分の中にあるからです。 

末尾の数字は何桁に変更できますか$8$?

 各桁は 4 ビットを構成します。 破棄されたサフィックスには長さがあります$n$。 数字を識別するビットは 4 番目のビットです。 削除されたサフィックス内にそのビットを安全に隠すことができます。$$\left\lceil \frac{n}{4} \right\rceil$$末尾の数字。 

したがって、答えは次のようになります。$$\underbrace{99\ldots9}_{n-\lceil n/4\rceil} \underbrace{88\ldots8}_{\lceil n/4\rceil}.$$これはよく知られた Codeforces ソリューションです。

 ## アルゴリズムのチュートリアル

 1.読む$n$。 
2. コンピューティング$$m = \left\lceil \frac{n}{4} \right\rceil.$$これは、変更できる末尾の桁数です。$9$に$8$の最大値に影響を与えることなく、$r$。 

1. 最初の$n-m$位置は数字である必要があります$9$。 

これらの数字は、生き残ったプレフィックス内に残るビットに寄与するため、$9$辞書編集上可能な最大のものを与える$r$。 
2.最後$m$位置は数字である必要があります$8$。 

それらを識別するビットは、破棄されたサフィックス内にあるため、置き換えます。$9$による$8$保つ$r$作っている間は変わらない$x$より小さい。 
3. 結果の文字列を出力します。 

### なぜ効果があるのか

 以外の数字$8$または$9$寄与するビットは 4 ビット未満となり、全体の長さが短縮されます。$k$。 以来$r$長さがある$|k|-n$、これはすぐに短い 2 進数を生成し、最適化することはできません。 

数字に限定した上で$8$そして$9$、各桁は正確に 4 ビットを占めます。 それらの唯一の違いは、バイナリ表現の最後のビットです。 最後$n$連結のビットは破棄されるため、最後の連結の識別ビットは$\lceil n/4\rceil$数字は決して現れません$r$。 これらの数字は次から変更される可能性があります$9$に$8$影響を与えずに$r$。 

それ以前の数字は引き続き影響します$r$。 このような数字を次から変更すると、$9$に$8$生き残ったビットを置き換えます$1$による$0$、作る$r$より小さい。 したがって、以前のすべてのポジションは維持される必要があります$9$。 

すべての数値の中で、可能な最大値を生み出す$r$、この構造により最小限に抑えられます。$x$可能なすべての末尾を置き換えるので、$9$による$8$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
ans = []

for _ in range(t):
    n = int(input())
    eights = (n + 3) // 4
    nines = n - eights
    ans.append("9" * nines + "8" * eights)

print("\n".join(ans))
```実装は数学的特徴付けに直接続きます。 

表現`(n + 3) // 4`計算する$\lceil n/4 \rceil$整数演算を使用します。 重要な詳細はこれだけです。 

回答の最初の部分には次の内容が含まれます`n - eights`のコピー`'9'`。 2 番目の部分には次の内容が含まれます`eights`のコピー`'8'`。 

バイナリ文字列は構築されません。 このソリューションは最終的な 10 進数の答えのみを構築するため、出力サイズは線形のままです。 

よくある間違いは、`n // 4`天井分割の代わりに。 たとえば、次のようなとき`n = 1`、フロア分割が与えます`0`、生産`"9"`正しい答えの代わりに`"8"`。
