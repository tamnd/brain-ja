 ## 解決策
 ## 問題の理解

 時間の経過に伴う正味トラフィックの変化を表す一連の整数が与えられます。 それぞれの値は正または負にすることができ、残りの要素間の順序を維持しながら、必要な要素を破棄することができます。 

選択したサブシーケンスから、そのサブシーケンス内の隣接するペアを調べることによってスコアを定義します。 すべての隣接するペアについて、2 つの値の最大値を取得し、サブシーケンス全体にわたってこれらの最大値を合計します。 長さ 1 のサブシーケンスはゼロに寄与し、空のサブシーケンスもゼロに寄与します。 

タスクは、このスコアを最大化する元の配列のサブシーケンスを選択することです。 

入力サイズは 500,000 要素に達する可能性があるため、すべてのサブシーケンス、さらにはサブシーケンスのすべてのペアを試すようなソリューションは直ちに実行不可能になります。 二次関数のアプローチはすでに大規模すぎるため、指数関数的なアプローチは不可能です。 コンパイル言語では 2 秒間に安全な操作は約 1,000 万件のみであり、Python でははるかに少ないため、ソリューションはほぼ線形時間、最悪の場合でも線形演算で効果的に動作する必要があります。 

すべての数値が負の場合、微妙なエッジケースが発生します。 たとえば、配列が [-5, -4, -3] の場合、より長いサブシーケンスを取るとペアの寄与の数が増加しますが、各寄与は依然として負であるため、最適な戦略は、単一の要素または空のサブシーケンスを取得することである可能性があります。 これは、ソリューションでは、より多くのペアを取得することと、負の寄与の蓄積とのバランスを慎重にとらなければならないことを示しています。 

もう 1 つのエッジ ケースは、大きな正の値が多数の小さな値または負の値で区切られている場合に発生します。 常に極大値または隣接する有益なペアを選択する単純な貪欲な戦略は失敗する可能性があります。中央の要素を選択すると、両側で大きな寄与が得られる可能性があるためです。 

## アプローチ

 ブルートフォースアプローチは、すべてのサブシーケンスを列挙し、その弱い推定値を計算し、最大値を取得することです。 長さ k のサブシーケンスの場合、スコアの計算には O(k) のコストがかかり、2^n 個のサブシーケンスがあるため、合計の複雑さは指数関数的となり、n = 40 の場合でもまったく使用できなくなります。 

もう少し素朴なアイデアは、連続セグメントであるサブシーケンスのみを考慮することです。 これにより、問題は O(n^2) セグメントに縮小されますが、直接計算すると各セグメントは依然として O(n) 作業を必要とし、結果として O(n^3) が得られますが、それでも大きすぎます。 プレフィックスの最適化を行ったとしても、スコアは単純な合計ではなく隣接する最大値に依存するため、目的の構造はきれいに分解されません。 

重要な観察は、サブシーケンス構造により、どの要素が隣接するかを選択できるということです。 選択されたすべての要素は、次に選択された要素とのみ対話し、隣接ごとに max(a[i], a[j]) を支払います。ここで、i < j であり、それらの間に選択された要素はありません。 これは、要素の連鎖という観点から考えることを示唆しています。 

ここで、サブシーケンス内で最後に選択した要素を修正するとどうなるかを考えてみましょう。 位置 i でチェーンを終了するとします。 以前に選択された要素 j は、max(a[j], a[i]) に寄与します。 これを a[i] + max(0, a[j] - a[i]) として書き直すと、前の値が大きいかどうかに応じて、寄与がベースラインとオプションのボーナスに自然に分割されることがわかります。 

この構造により、動的プログラミングの解釈が可能になります。つまり、各位置で終了する最良のチェーンを維持します。 チェーンの拡張は、より大きな要素を前に配置するか、後に配置することで追加の価値が得られるかによってのみ決まります。 最適な構造は、要素を値の降順にソートし、その順序で接続することと同じになります。これは、より大きな値をより早くペアにすることで、将来の貢献が最大化され、潜在的な利益の無駄が回避されるためです。 

問題をこの順序付けの洞察に変換した後、解決策は単調構造で寄与を集約することに帰着します。これは、貪欲スキャンを使用して線形時間で計算できます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 選択した各サブシーケンスを、隣接する各ペアが 2 つの値の最大値に寄与するチェーンとして解釈します。 目標は、貢献度の合計を最大化するチェーンを構築することです。 
2. ペア (x, y) の寄与を max(x, y) として書き換え、各ペアの大きい要素が寄与を支配することを観察します。 これは、より大きな要素をチェーンの前半に配置することが一般的に有益であることを示唆しています。 
3. 要素を値の降順にソートまたは概念的に処理します。これは、支配されることなく寄与を有意に増加できるのは、より大きな要素だけであるためです。 
4. 最大値から最小値まで値をスイープし、これまでに形成された最良のチェーンを表す実行中の最適な構造を維持します。 新しい要素はそれぞれ、新しいチェーンを開始するか、既存の最適なエンドポイントに接続します。 
5. 新しい要素を接続するときに、それが新しい隣接としてどの程度寄与するかを計算します。 以前に選択した要素とペアになるため、その寄与は、現在の構造ですでに固定されている、より大きなエンドポイント値によって決まります。 
6. 貢献を貪欲に蓄積し、ペアの貢献を最大限に維持する方法でチェーンを拡張していることを常に確認します。 

### なぜ効果があるのか

 重要な不変条件は、減少するスイープのどの時点でも、構築されたサブシーケンスがチェーンに対応し、新しく追加されたすべての要素が将来の最大ペアの寄与を最大化する次善の候補となることです。 max(x, y) は大きい方のエンドポイントによって支配されるため、要素を降順に配置すると、各要素が支配的なエンドポイントとしてその完全な値に寄与するか、潜在的な寄与を失うことなく吸収されることが保証されます。 この順序から逸脱すると、より大きな要素が後から出現することになり、前のペアの寄与が減少するため、チェーンの後半で補正することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    a.sort(reverse=True)
    
    total = 0
    for i in range(1, n):
        if a[i] > 0:
            total += a[i-1]
        else:
            total += max(a[i-1], a[i])
            break
    
    print(max(0, total))

if __name__ == "__main__":
    solve()
```実装は、配列を降順に並べ替えることから始まります。これは、より大きな値が先に配置される最適なチェーンを構築することに対応します。 次に、ループは、この並べ替えられた順序で隣接する要素間の寄与を累積します。 正の値は、常に前の (大きい) 要素を提供することによって処理されます。これは、小さいか等しい値とペアにしても最大値が保持されるためです。 非正の値が出現すると、構造はチェーンの拡張によるゲインを保証しなくなるため、最終的な可能なペアを考慮した後でプロセスが停止します。 

要素を選択しないことが常に許可され、スコアが 0 になるため、最終的な答えは 0 で固定されます。これは、否定的な構成よりも望ましいことです。

 ## 特殊なケース

 次のような単一要素入力の場合`[5]`、アルゴリズムは次のように並べ替えます`[5]`長さ 1 のサブシーケンスには隣接関係が存在しないため、これは定義と一致します。 

次のようなすべて負の入力の場合`[-3, -2, -1]`、収量の選別`[-1, -2, -3]`。 最初のペアが貢献します`-1`、2番目は貢献します`-2`、実行中の合計がマイナスになり、その後はゼロをとる方が良いでしょう。 最後のクランプにより、出力が 0 になることが保証されます。 

次のような混合入力の場合`[10, -5, 7]`、ソートすると、`[10, 7, -5]`。 最初のペアは 10 を寄与し、2 番目のペアは 7 を寄与し、結果は 17 です。これは、支配的な要素がどのように構造を制御するのか、また、順序が固定されるとネガティブ要素が以前のゲインを低下させる機会をどのように得ないかを示しています。
