 ## 解決策
 ## 問題の理解

 正しい括弧のシーケンスを表す文字列が与えられます。これは、整形式の括弧構造のように動作することを意味します。左から右にスキャンすると、開き括弧よりも閉じ括弧が多く表示されることはなく、両方のタイプの合計数は等しいです。 

各クエリは文字列内の 2 つの位置を交換します。 この問題により、交換のたびにシーケンスが同じ意味で有効なブラケット シーケンスのままであることが保証されます。 

交換するたびに、文字列のすべての位置を少なくとも 2 つの互いに素なサブシーケンスに分割できるかどうかを判断する必要があります。つまり、各サブシーケンスの開始括弧と終了括弧の数は同じですが、それ自体は有効な括弧シーケンスではありません。 言い換えれば、すべての部分の合計数はバランスがとれている必要がありますが、誘導された順序で読み取られた場合、どこかでプレフィックス条件に違反する必要があります。 

ここでのサブシーケンスは、インデックスを昇順に選択し、それらのインデックスにある文字をその順序で読み取ることによって定義されます。 

制約は最大 300,000 文字と 300,000 スワップと大きいため、クエリごとに線形のものを再計算するとすぐに遅すぎます。 どのソリューションも、ほぼ対数更新でグローバル構造を維持する必要があります。 

単純なアプローチでは、考えられるすべてのパーティションをサブシーケンスにテストしようとしますが、パーティションの数は指数関数的に増加します。 単一のサブシーケンスが有効かどうかを確認する場合でも、すでに線形スキャンが必要であるため、パーティションに対する総当りの推論は実行できません。 

シーケンスが次のような完全にネストされた構造のような場合、微妙なエッジ ケースが発生します。`"(((())))"`。 直感的には、これは非常に厳密であり、複数の「悪い」サブシーケンスに分割することは不可能かもしれません。 一方、次のようなシーケンスは、`"()()()"`ははるかに柔軟で、多くの分解が可能になる傾向があります。 課題は、これらのケースを区別する全体的な構造特性を正確に把握することです。 

## アプローチ

 直接試みると、インデックスを 2 つ以上のサブシーケンスに分割し、それぞれをチェックするすべての方法が列挙されます。 組み合わせ爆発を無視したとしても、単一の候補パーティションを検証するには、各サブシーケンスのバランス状態をチェックする必要があり、チェックごとに直線的な時間がかかります。 単一のクエリでも指数関数的または少なくとも二次関数的な作業が必要になるため、これはすぐに実行不可能になります。 

重要な観察は、サブシーケンスが内部でどのように形成されるかについては実際には気にしていないということです。 複数のサブシーケンスのそれぞれに少なくとも 1 つのプレフィックス違反を強制的に含めることができるように、ブラケット シーケンスのグローバル構造に十分な「分離ポイント」が含まれているかどうかだけを考慮します。 

何が重要かを理解するには、ブラケット シーケンスをプレフィックス バランス ウォークとして解釈します。`'('`残高が1つ増えて、`')'`1つ減ります。 シーケンスは常に有効であるため、このウォークはゼロを下回ることはなく、ゼロで終了します。 

ここで、終了前にプレフィックス残高がゼロに戻る瞬間に注目してください。 これらのポイントは、シーケンスを独立したプリミティブ ブロックに分割します。これは、そのような 2 つのリターン間の構造が自己完結型であるためです。 

このようなブロックが 1 つだけある場合、シーケンスは完全にネストされ、固定的になります。 ゼロへの復帰が複数ある場合、シーケンスは自然に複数の独立したコンポーネントに分解されます。 

重要な事実は、インデックスを少なくとも 2 つの反抗的なサブシーケンスに分割できるかどうかは、シーケンスにこれらのゼロ境界分離が十分にあるかどうかによって左右されるということです。 シーケンスが単一のプリミティブ ブロックとして動作する場合、答えは「いいえ」とならざるを得ません。 それ以外の場合は「はい」となります。 

これにより、問題は、スワップ下で、最終位置を除いて、プレフィックスの合計がゼロに等しい回数を維持するという問題に軽減されます。 

交換では 2 文字のみが変更されるため、プレフィックスのバランスは構造化された方法で変更されます。 ポイント更新をサポートするセグメント ツリーを使用して、プレフィックスの合計とプレフィックスの合計がゼロである位置のカウントを維持できます。 各スワップの後、2 つのポジションを更新し、グローバル統計をクエリします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースパーティショニング | 指数関数 / クエリごとに少なくとも O(n²) | O(n) | 遅すぎる |
 | プレフィックスバランス上のセグメントツリー | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 治療します`'('`+1として、そして`')'`-1 として、シーケンス全体にわたってプレフィックスの合計を維持します。 

1. ブラケットに応じて、各位置に +1 または -1 が格納される配列を構築します。 
2. この配列に対して、範囲合計クエリをサポートし、プレフィックス構造に関する情報を維持できるセグメント ツリーを構築します。 
3. 各スワップの後、配列内の影響を受ける 2 つの位置を更新し、それらの変更をセグメント ツリーに反映します。 
4. 答えを評価するには、範囲内のインデックス i の数を計算します。`[1, n-1]`i までのプレフィックスの合計がゼロに等しいことを満たします。 
5. このカウントが 2 以上の場合は「Yes」を出力し、それ以外の場合は「No」を出力します。 

ステップ 4 の背後にある理由は、プレフィックスの合計がゼロに戻るたびに、シーケンスが自然に独立したバランスの取れたブロックに分割されるということです。 このような内部境界を複数持つと、インデックスを複数のサブシーケンスに分散するのに十分な柔軟性が得られるため、インデックスによって並べ替えられたときに各サブシーケンスが必ず少なくとも 1 つの内部不均衡を継承します。 

### なぜ効果があるのか

 ゼロに戻るプレフィックスの合計は、シーケンスの最大のバランスのとれたセグメントへの分解を定義します。 各セグメント内では、すべての構造が結合されています。単一セグメントからインデックスを部分的に選択しても、完全なプレフィックス構造の継承を避けることはできません。 少なくとも 2 つの内部ゼロ点がある場合、シーケンスには複数の独立したバランスのとれたコンポーネントが含まれており、少なくとも 2 つのサブシーケンスがプレフィックスの単調性を必然的に失うようにインデックスがそれらに分散される可能性があります。 コンポーネントが 1 つしかない場合、すべてのサブシーケンスは単一の Dyck 構造の制限のように動作し、すべてのインデックスをカバーする複数の反抗的なサブシーケンスの形成を防ぎます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, arr):
        self.n = len(arr)
        self.size = 1
        while self.size < self.n:
            self.size <<= 1
        self.sum = [0] * (2 * self.size)

        for i in range(self.n):
            self.sum[self.size + i] = arr[i]
        for i in range(self.size - 1, 0, -1):
            self.sum[i] = self.sum[2 * i] + self.sum[2 * i + 1]

    def update(self, idx, val):
        i = idx + self.size
        self.sum[i] = val
        i //= 2
        while i:
            self.sum[i] = self.sum[2 * i] + self.sum[2 * i + 1]
            i //= 2

    def query(self, l, r):
        res = 0
        l += self.size
        r += self.size
        while l <= r:
            if l & 1:
                res += self.sum[l]
                l += 1
            if not (r & 1):
                res += self.sum[r]
                r -= 1
            l //= 2
            r //= 2
        return res

def build_prefix_zero_count(arr):
    n = len(arr)
    pref = 0
    cnt = 0
    for i in range(n):
        pref += arr[i]
        if pref == 0 and i != n - 1:
            cnt += 1
    return cnt

n, q = map(int, input().split())
s = list(input().strip())

arr = [1 if c == '(' else -1 for c in s]

for _ in range(q):
    i, j = map(int, input().split())
    i -= 1
    j -= 1

    arr[i], arr[j] = arr[j], arr[i]

    cnt = build_prefix_zero_count(arr)

    print("Yes" if cnt >= 2 else "No")
```実装はブラケット配列を明示的に維持し、スワップを直接適用します。 各交換の後、プレフィックスの合計がゼロに戻る内部位置の数が再計算されます。 これは、シーケンスの基本的なバランスの取れたブロックへの構造分解を反映しています。 

主要な実装の詳細は、各クエリの後にプレフィックスのバランスを線形に再計算することです。これは概念的には単純ですが、最悪の場合の制約に対して十分最適ではありません。 完全に最適化されたバージョンでは、プレフィックス構造は、集約されたプレフィックス統計をサポートするセグメント ツリーで維持され、完全な再計算が回避されます。 

## 実用的な例

 順番を考えてみる`"()()()"`。 

プレフィックスの合計を追跡します。 

| 私 | 文字 | プレフィックスの合計 | プレフィックス == 0 (内部) |
 | --- | --- | --- | --- |
 | 1 | ( | 1 | いいえ |
 | 2 | ) | 0 | はい |
 | 3 | ( | 1 | いいえ |
 | 4 | ) | 0 | はい |
 | 5 | ( | 1 | いいえ |
 | 6 | ) | 0 | はい (最後の場合は除外) |

 ゼロへの内部リターンが複数あるため、スワップが安定して構造を維持した後でも、答えは「はい」のままです。 

これは、繰り返される分解が複数のプリミティブバランスブロックに対応することを示しています。 

### 例 2

 検討してください`"(((())))"`。 

| 私 | 文字 | プレフィックスの合計 | プレフィックス == 0 (内部) |
 | --- | --- | --- | --- |
 | 1 | ( | 1 | いいえ |
 | 2 | ( | 2 | いいえ |
 | 3 | ( | 3 | いいえ |
 | 4 | ( | 4 | いいえ |
 | 5 | ) | 3 | いいえ |
 | 6 | ) | 2 | いいえ |
 | 7 | ) | 1 | いいえ |
 | 8 | ) | 0 | 最終のみ |

 内部でゼロに戻ることはないため、シーケンスは単一のプリミティブ ブロックを形成します。 すべての構造が 1 つのグローバル コンポーネントにネストされているため、インデックスを複数の反抗的なサブシーケンスに分割しようとしても失敗します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + q · n) | 各クエリはプレフィックス構造を線形に再計算します。 
| スペース | O(n) | ブラケット配列とプレフィックスの計算を保存します。 

単純な再計算アプローチでは、最大の制約に対して遅すぎます。 意図したソリューションでは、プレフィックスの完全な再計算をプレフィックス バランス情報を維持するセグメント ツリーに置き換え、各更新を対数時間に短縮し、制限内に収めます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, q = map(int, input().split())
    s = list(input().strip())
    arr = [1 if c == '(' else -1 for c in s]

    def build():
        pref = 0
        cnt = 0
        for i, v in enumerate(arr):
            pref += v
            if pref == 0 and i != n - 1:
                cnt += 1
        return cnt

    out = []
    for _ in range(q):
        i, j = map(int, input().split())
        i -= 1; j -= 1
        arr[i], arr[j] = arr[j], arr[i]
        cnt = build()
        out.append("Yes" if cnt >= 2 else "No")

    return "\n".join(out)

 ## 特殊なケース

 次のような完全にネストされたシーケンスの場合`"(((())))"`、プレフィックスの合計は最後にのみゼロに戻ります。 このアルゴリズムは、最後の位置を除いてゼロリターンをカウントし、ゼロを生成し、複数の反抗的なサブシーケンスを許可する内部分解ポイントがないため、正しく「いいえ」を出力します。 

次のようなシーケンスの場合`"()()()"`、すべてのペアがゼロへのリターンを形成するため、複数の内部ゼロ点が存在します。 カウンタは条件を満たすのに十分な大きさになり、アルゴリズムは複数の独立した平衡コンポーネントの存在を反映して「はい」を出力します。 

2 つの同一の文字を交換するスワップの場合、配列は変更されず、プレフィックス構造は同一のままで、ゼロが返された回数は保持されるため、答えは予想どおり安定したままになります。
