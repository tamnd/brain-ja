 ## 解決策
 ## 問題の理解

 1 から n までの番号が付けられた頂点を持つツリーが与えられます。 エッジは非常に特殊な方法で与えられます。新しい頂点 i + 1 はそれぞれ、以前の頂点 pi に接続されます。 これにより、構造がルート ツリーになり、すべてのエッジが小さいインデックスから大きいインデックスに向かうことが保証されるため、子孫には常に大きなラベルが付けられます。 

頂点のサブセット S について、その美しさを必要な頂点の最小数として定義します。そのため、S 内の頂点間のペアごとのパスをすべて取得すると、それらのパス上のすべての頂点がこの選択されたセットに含まれます。 ツリーでは、これは、S を含む最小接続部分グラフ (S によって誘導されるシュタイナー ツリーとも呼ばれます) の頂点の数と正確に一致します。 

ここで、頂点ラベルのすべての間隔 S(l, r)、つまり l から r までのインデックスを持つすべての頂点を考慮します。 このような間隔ごとに、その美しさを計算し、すべての間隔にわたる結果を合計します。 

この制約により、n は最大 300,000 まで許可され、n の二次関数や間隔ごとの n log n も除外されます。 約 n 乗の間隔があるため、間隔ごとに何かを再計算することは避けなければなりません。 この解決策では、総作業量を n 単位の線形または線形演算に近づける必要があります。 

素朴なアプローチでは、BFS または LCA ベースの閉包によって各区間のシュタイナー ツリー サイズを個別に計算しますが、それはツリーの大部分を繰り返し走査することになります。 最悪の場合、これは三次的な動作になります。 

より微妙な失敗例は、間隔 [l, r] ごとに独立してシュタイナー ツリーを動的に維持しようとした場合に発生します。 l をスライドさせながら固定 r を維持したとしても、距離を再計算したり、すべてのペアごとの接続を維持したりすると、依然として全体のコストが高すぎます。 

主な困難は、任意のサブセットではなく、すべての連続するラベル間隔にわたって構造量を集約していることと、頂点挿入の強力な順序制約を利用する必要があることです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 各区間 [l, r] について、その範囲内のすべての頂点を収集し、BFS または繰り返しの LCA マージを使用してシュタイナー ツリーのサイズを計算します。 k 頂点のシュタイナー ツリーを構築するには、ソートと仮想ツリーの構築後に少なくとも O(k log k) または O(k) かかり、これをすべての O(n^2) 間隔で合計すると、最悪の場合少なくとも O(n^3) の動作が得られます。 これは限界をはるかに超えています。 

改善するために、シュタイナー ツリー サイズの意味を再解釈します。 固定セット S の場合、その美しさは S 内の 2 つの頂点間の少なくとも 1 つのパス上にある頂点の数に等しくなります。これは、S によって「アクティブ化」されたツリーのエッジの数に頂点自体を加えたものを数えることと同じです。 

頂点のセットの観点から考える代わりに、エッジについての考え方に切り替えます。 エッジを削除した後、エッジの両側に選択された頂点が少なくとも 1 つある場合、エッジは S(l, r) に関連します。 言い換えれば、エッジは、区間 [l, r] がそのエッジによって誘発されたカットの各辺に少なくとも 1 つの頂点を含む場合に限り、誘発されたサブツリーの一部となります。 

特別な親構造のため、このツリー内のすべてのサブツリーはラベルの連続セグメントに対応します。 これにより、「区間がエッジの両側と交差する」という条件が、線上の区間にわたる単純な組み合わせ計数問題に変わります。 これにより、カウントステップからツリー構造が完全に削除されます。 

これにより、タスクは、固定セグメント パーティションの両側と交差するラベル間隔の数をすべてのエッジにわたって合計するように変換されます。 すべての区間にわたる頂点自体のわずかな寄与と組み合わせると、線形時間の解が得られます。

 ## アルゴリズムのチュートリアル

私たちは、エッジが常に頂点 i + 1 を以前の頂点 pi に接続するという事実を利用します。そのため、すべてのノードが、成長するルート付きツリーにおける独自の挿入ポイントになります。 

1. すべてのノード v について、そのサブツリー内の最大ラベルを計算します。 子は常に親よりも大きなインデックスを持っているため、n から 1 までノードを処理し、サブツリーの最大値を上方向に伝播することができます。 rmax[v] = v を初期化し、rmax[pi] = max(rmax[pi], rmax[v]) を更新します。 これは、v に到達した時点で v のすべての子孫がすでに処理されているため機能します。 
2. ルートを除く各ノード v について、そのサブツリーが連続区間 [v, rmax[v]] に正確に対応していることがわかります。 これは、ツリーを区間ジオメトリに変換する重要な構造特性です。 
3. エッジとは無関係に、すべての区間にわたる各頂点の寄与を計算します。 頂点 i は、l ≤ i ≤ r となるすべての区間 [l, r] に出現します。これにより、l には i 個の選択肢が、r には n − i + 1 個の選択肢が与えられます。 これは、 i · (n − i + 1) を最終的な答えに寄与します。 
4. 次に、親 p から子 v までの各エッジを処理します。このエッジを削除すると、ツリーが 2 つの部分に分割されます。v のサブツリー (区間 A = [v, rmax[v]] に対応) と残りの頂点です。 
5. A の少なくとも 1 つの頂点と A の外側の少なくとも 1 つの頂点を含む区間 [l, r] の数を数えます。このような区間は、まさに A の内部に完全に含まれておらず、その補部分に完全に含まれていない区間です。 
6. 間隔の総数は n(n + 1)/2 です。 A の完全に内側にあるもの (rmax[v] − v + 1)(rmax[v] − v + 2)/2 を減算し、A の完全に外側にあるもの ([1, v − 1] と [rmax[v] + 1, n] の間隔の合計) も減算します。これは v(v − 1)/2 + (n − rmax[v])(n − rmax[v] + として計算されます) 1)/2。 
7. すべてのエッジにわたるこれらの寄与を合計すると、すべての間隔にわたってシュタイナー ツリーに現れるエッジの総数が得られます。 

### なぜ効果があるのか

 セットの美しさは、それを接続する最小のサブツリーのサイズです。これは、その誘導されたサブツリーの頂点の数とエッジの数を足したものに等しくなります。 S(l, r) がエッジ カットの各辺に少なくとも 1 つの端点を持っている場合、すべてのエッジが S(l, r) のシュタイナー ツリーに含まれます。 サブツリー セットは連続するラベル間隔に対応するため、条件は間隔 [l, r] が固定セグメント A とその補数を同時に交差するかどうかに限定されます。 これにより、ツリー接続条件が間隔カウントに変換され、各エッジが独立して寄与するため、エッジを合計することで二重にカウントすることなく完全な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    parent = [0] * (n + 1)
    for i in range(2, n + 1):
        parent[i] = int(input())

    rmax = list(range(n + 1))

    for i in range(n, 1, -1):
        p = parent[i]
        if p:
            rmax[p] = max(rmax[p], rmax[i])

    total_intervals = n * (n + 1) // 2
    ans = 0

    for v in range(2, n + 1):
        l = v
        r = rmax[v]
        sz = r - l + 1

        inside = sz * (sz + 1) // 2
        left = (l - 1) * l // 2
        right = (n - r) * (n - r + 1) // 2

        crossing = total_intervals - inside - left - right
        ans += crossing

    for i in range(1, n + 1):
        ans += i * (n - i + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、まず単調な親構造を使用してサブツリー範囲を再構築し、次にそれらの範囲を使用して純粋に算術によってエッジ寄与を計算します。 2 番目のループでは、点をカバーする間隔の標準カウントを使用して、頂点の寄与を直接累積します。 

微妙な点は、すべての子がその親よりも大きなインデックスを持っているため、サブツリー間隔が有効であるということです。これにより、ノードのすべての子孫が、そのノードに対して連続したサフィックス セグメント内に存在することが保証されます。 このプロパティがないと、間隔演算への縮小全体が失敗します。 

## 実用的な例

 ノードが単純なチェーン 1-2-3 を形成する小さなツリーを考えてみましょう。 

ノード 2 のサブツリーは [2, 3] です。 ノード 3 の場合、それは [3, 3] です。 

すべての間隔にわたってエッジごとおよび頂点ごとの寄与を評価します。 

| 間隔 | S | シュタイナーの木のサイズ |
 | --- | --- | --- |
 | [1,1] | {1} | 1 |
 | [1,2] | {1,2} | 2 |
 | [1,3] | {1,2,3} | 3 |
 | [2,2] | {2} | 1 |
 | [2,3] | {2,3} | 2 |
 | [3,3] | {3} | 1 |

 これは分解と一致します。各頂点は、含まれる間隔の数に基づいて寄与し、各エッジは、間隔がカットの両側にまたがる場合に正確に寄与します。 

2 番目の例は、1 がルートで、他のすべてがそれに接続されている星型の構造です。 すべてのサブツリーは単一の区間 [i, i] であるため、区間に 1 と他のノードの両方が含まれ、組み合わせの減算式に一致する場合にのみエッジが寄与します。 

これらのトレースは、アルゴリズムがオーバーラップの問題なく頂点カバレッジとエッジ接続をきれいに分離していることを確認します。

 ## 特殊なケース

 縮退チェーンは、サブツリー間隔が正しく拡張されるかどうかをテストします。 ノードが 1、2、3、4 個並んでいる場合、各サブツリーは接尾辞間隔になる必要があり、rmax を上方に伝播する際に誤りがあると、すぐに誤ったエッジ寄与が生成されます。これは、一部の間隔が誤って内部としてカウントされるためです。 

ルート 1 のスターは、エッジが単一ノードのサブツリーを残りのサブツリーから正しく分離しているかどうかをテストします。 各リーフの rmax はそれ自体に等しいため、すべてのエッジは間隔が 1 からそのリーフ範囲に及ぶ場合にのみ寄与します。 補数間隔の処理が間違っていると、過大なカウントが発生します。 

厳密に増加する愛着パターンは、子供が常により大きなラベルを持っているという仮定を強調します。 この不変式が無視されると、サブツリー間隔が不正確になり、リダクション全体が失敗し、小さな入力でもカウントが一貫しなくなります。
