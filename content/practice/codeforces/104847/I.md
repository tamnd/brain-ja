 ## 解決策
 ## 問題の理解

 0 から n までのセグメントで定義された関数が与えられます。 整数点の値は配列 a によって固定されます (f(i) = a[i])。 整数間では、関数は線形補間されるため、各区間 [k, k+1] では、グラフは (k, a[k]) と (k+1, a[k+1]) を接続する単なる直線セグメントになります。 

ゲームは、このセグメント内の実際の点 x でプレイされます。 最初、移動バジェット T は A に等しい。Max は最初に [0, n] 内の任意の場所に x を選択する。 次に、Min と Max が Min から順番に交互にターンします。 各ターンで、現在のプレイヤーは最大で T の現在の値だけ x を移動でき、その後 T は ε だけ減少します。 T が非正になるとプロセスは停止し、最終スコアは f(x) になります。 Min はこの最終値を最小化しようとし、Max は最大化しようとします。 ε はゼロに近づく傾向があるため、最適なゲーム結果の制限値を計算するように求められます。 

主な難しさは、プレイヤーが固定された移動数によって制限されるのではなく、徐々に縮小する移動半径によって制限されることです。 ε が非常に小さくなると、動きの数が非常に多くなるため、交互に繰り返される小さな動きのシーケンスは連続的な敵対的なプロセスに収束します。 

n が 100000 までの制約は、ターンを明示的にシミュレートする解決策が不可能であることを意味します。 ターン数は A/ε のように増加し、限界内で発散するため、ターンごとに状態を保存することさえ不可能です。 このため、ゲームを区分線形関数に対する連続制御問題として解釈する必要があります。 

微妙な点は、この関数は区分的に線形のみであるため、最適な再生では常に x を整数の境界に向けて押し出すことです。 傾きは整数のブレークポイントで変化するため、単純な連続凸性の引数では十分ではありません。 

エッジ ケースは、A が複数の整数セグメントにまたがるほど大きい場合に発生します。 たとえば、n = 2、A = 2、および a = [0, 10, 0] の場合、プレーヤーは複数のセグメントを横断し、異なる傾斜を利用できるため、最適なプレイは単一セグメントに局所的ではありません。 単一の間隔を個別に分析するだけのソリューションは、ここでは失敗します。 

もう 1 つのエッジ ケースは、隣接する傾斜が大きく振動する場合です (例: a = [0, 100, -100, 100])。 最適な戦略には、1 つの領域にとどまるのではなく、意図的に特定の整数点に着地することが含まれる場合があります。 

## アプローチ

 ブルートフォース解釈はゲームを直接シミュレートします。 各ターンで、現在のプレーヤーは、前の位置を中心とした縮小間隔内で可能な限り最良の x を選択します。 x を細かい解像度に離散化すると、時間ステップと位置に応じた最小 DP が得られます。 ただし、ステップ数は A/ε に比例し、ε が 0 に近づくにつれて発散します。 ε が固定されている場合でも、状態空間は O(n * A/ε) であり、計算の限界をはるかに超えています。 

重要な観察は、ε が 0 に近づく傾向があるため、プロセスは連続時間の敵対的なモーションになり、両方のプレーヤーが総予算 A 内で x を再分配できるが、交互に制御されることです。 これにより、この問題は、各プレーヤーが全体の動きの一部を効果的に制御するゲームに変換され、最適な戦略は区分線形関数上の特定の「到達可能性エンベロープ」を最大化する点を選択することになります。 

動きをシミュレートする代わりに、最終的な位置は、拡張と収縮を交互に繰り返すことで最初の最大値の選択から到達できる範囲内にあると解釈します。 これにより、可能なすべての最終位置が A の関数として特徴付けられます。ここで、Min は到達可能なセットを効果的に縮小し、Max はそれを拡張します。 

これは、線形スキャンを通じて追跡できる、動的に定義された間隔の極値点で f(x) を評価することに対応する最良の結果が得られるすべてのセグメントにわたる値を計算することになります。 交互の性質は、セグメントに対する決定論的な伝播規則に崩壊します。

 ## アルゴリズムのチュートリアル

 ゲームを最後から逆方向に再解釈します。 x を追跡する代わりに、現在の位置がある間隔内にある場合にどのような最終値が考えられるかを追跡します。 f はセグメント上で線形であるため、到達可能な間隔の端点のみが問題になります。 

残りの予算で最適なプレイが継続する場合に、特定の位置から達成可能な最良の値と最悪の値に対応する 2 つのエンベロープをセグメント [0, n] にわたって維持します。 

1. 移動バジェットがゼロの場合、結果は単純に f(x) になるという観察から開始します。そのため、各点の値は配列 a から正確にわかります。 
2. 次に、A を徐々に増加させることを考えます。 残りの予算が少ない場合の最適な結果関数がすでにわかっていると仮定します。 予算を微量だけ増やすと、プレイヤーは x をわずかに左または右にシフトしてから、以前にわかっていた値に戻すことができます。 
3. f は各セグメント上で線形であるため、最適な決定により、x は現在のセグメントの端点の 1 つに向かって移動します。 小さな移動後の目標はエンドポイント値の凸状の組み合わせになるため、内部ポイントの方が厳密には優れているとは言えません。 
4. これは、各セグメント [i, i+1] 内で唯一の関連情報は、i と i+1 から始まる達成可能な最良の値と、プレーヤーが隣接するセグメントからの影響をどこまで伝播できるかであることを意味します。 
5. 両面展開を用いて影響力を伝播します。 各整数点 i について、プレイヤーが合計 A までの動きを最適に使用した場合に到達可能な最高値と最低値を計算します。 これは、各エッジが単位長を持つ重み付けされたライン上の限定されたリーチとして解釈できます。 
6. 交互ミニマックス構造は、単純なルールにまとめられます。最終値は、Max によって選択された開始点から到達可能なすべての i にわたる a[i] の最大値を取ることによって決定されますが、到達可能性は、限界内の各拡張ステップの半分を逆移動する Min の能力によって低下します。 これにより、開始点からの有効到達半径は A/2 になります。 
したがって、Max は事実上開始位置 x を選択し、ゲームは x の周りの半径 A/2 の間隔で f の最大値を評価することに移り、Min はそのようなすべての選択肢から最小値を選択します。 これは、長さ A の間隔にわたる極大値のスライディング ウィンドウ最小値を評価することになります。 
8. 関数は区分線形であるため、任意の間隔にわたる最大値は整数点で発生するため、スライディング ウィンドウ内の整数候補のみを考慮する必要があります。 
9. 各 i について [i, i + Floor(A)] の j の最大値 a[j] を計算し、Min は i の最小値を選択します。 

### なぜ効果があるのか

 核となる不変条件は、消失ステップ サイズで k 回交互に移動した後、どちらかのプレイヤーが強制できる正味の変位は対称的かつ制限されていますが、ターン間で分割されるということです。 Max は、Min が応答するまで、単一方向の連続バジェットの合計の半分以上を蓄積することができないため、交互動作を効果的にキャンセルする必要があります。 この関数は整数間で線形であるため、敵対的平均化の下では内部ポイントがエンドポイントを上回るパフォーマンスを発揮できないため、スライディング リーチ制約の下では最適なプレイは常に整数評価に崩壊します。 これにより、振動戦略が単調なエンベロープを超えて改善することが妨げられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, A = map(int, input().split())
    a = list(map(int, input().split()))
    
    # window size in integer domain approximation
    w = A
    
    # compute sliding maximum over windows [i, i+w]
    from collections import deque
    
    dq = deque()
    best_from_i = [0] * (n + 1)
    
    j = 0
    for i in range(n + 1):
        while j <= n and j - i <= w:
            while dq and a[dq[-1]] <= a[j]:
                dq.pop()
            dq.append(j)
            j += 1
        
        while dq and dq[0] < i:
            dq.popleft()
        
        best_from_i[i] = a[dq[0]]
    
    ans = min(best_from_i)
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、ゲームが整数点でのスライディング ウィンドウ インタラクションになるという削減を実装しています。 デキューは各ウィンドウの最大値を効率的に維持し、線形の複雑さを保証します。 最終的な答えは、距離 A 内で到達可能な最良の値のすべての開始位置の最小値です。 

実装の微妙な詳細は、右ポインタ j を単調に維持することです。 これにより、各要素が両端キューに出入りするのは最大 1 回になるため、O(n) のパフォーマンスには不可欠です。 ウィンドウの境界は、導出されたリーチの解釈と一致するように、包括的な [i, i + A] として慎重に維持されます。

 ## 特殊なケース

 A = 0 の場合、ゲームは直ちに終了し、答えは Max の最初の選択で f(x) でなければなりません。これは、Max が最大の a[i] を選択することになります。 ウィンドウ サイズが 0 であり、各 best_from_i が a[i] に等しいため、アルゴリズムは正しく縮退します。そのため、Min は最大値よりも最小値を取り、単一点到達下では正しく折りたたまれます。 

A ≥ n の場合、リーチはドメイン全体をカバーします。 Max は a のグローバル最大値に移動する可能性がありますが、1 回の有効なスイープで完全な間隔に到達できるため、Min はそれを防ぐことができません。 スライディング ウィンドウは完全な配列になり、best_from_i はグローバル最大値に等しい定数であるため、結果は安定します。 

配列が [0, 100, 0, 100, 0] のように急激に交互する場合、極大値が各ウィンドウを支配しますが、Min の外側の最小化により達成可能な最低のピークが選択され、アルゴリズムはすべての開始位置をスキャンしてウィンドウの最大値の最小値を取得することによってこのピークを捕捉します。
