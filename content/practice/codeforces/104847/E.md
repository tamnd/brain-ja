 ## 解決策
 ## 問題の理解

 私たちには、位置の指示システムが与えられており、各ルーティング プログラムは条件付きエッジのように動作します。ドローンが現在正しい開始ノードにある場合にのみ、ドローンを開始位置から目的地まで移動します。 それ以外の場合は何も行われません。 各プログラムにはバージョン番号もあり、一連のプログラムを実行するときは、厳密にバージョンを上げなければなりません。 

さらに、エンドポイントを交換してエッジの方向を効果的に反転することでプログラムを変更することができますが、バージョンは変更されません。 このようなスワップは 1 回のコストとしてカウントされます。 タスクは、ドローンをノード 1 からノード n に運ぶプログラムのバージョンが厳密に増加するシーケンスが存在するように、必要なスワップの最小数を決定することです。 

これは次のように言い換えることができます。各エッジにラベル (バージョン) と、コスト 1 で反転できる方向を持つ有向マルチグラフがあります。ラベルの厳密な昇順でエッジを使用して 1 から n までのパスを見つけ、パスが有効になるように方向を反転するエッジの数を最小限に抑えたいと考えています。 

制約は大きく、テスト スイートあたり合計最大 500,000 ノードと 500,000 エッジです。 これにより、すべてのパスを明示的に考慮したり、バージョンごとに最短パスを再計算しようとするソリューションは即座に除外されます。 m での 2 次関数は不可能であり、O(m log m) でさえ、ソートとグラフ構造に関して慎重な設計が必要です。 

微妙ですが重要な観察は、シーケンス制約がノードではなくエッジ バージョンにあるということです。 これにより、問題は階層化されたグラフになり、バージョンの昇順でのみ遷移が許可されます。 

素朴な考えを打ち破るいくつかの特殊なケースがあります。 まず、方向の反転を無視すると、トポロジー的に制約された標準的な最短パスだけが必要だと思われるかもしれませんが、エッジを反転すると到達可能性の構造が完全に変わります。 

たとえば、バージョン 2 の単一エッジ 1 → 2 と、バージョン 1 の別のエッジ 2 → 1 を考えます。スワップがなければ、バージョン 2 を使用して 1 が 2 に到達できると考えるかもしれませんが、これにより、順序付けの制約が強制され、以前のバージョンのエッジがその後使用できなくなります。 正解は、そのうちの 1 つを裏返すかどうかによって決まります。 

もう 1 つのエッジ ケースは自己ループです。 あるバージョンの u から u へのプログラムは移動には役に立ちませんが、シーケンス内で使用すると順序付けの制約に影響します。 ただし、これは新しいノードに到達するのに決して役立ちません。また、移動コストをゼロにしてバージョンの進行を満足させるのに役立つ場合を除き、無視することができます。これは決して有益ではありません。 

## アプローチ

 バージョン制約を無視すると、問題はエッジの重みが 0 または 1 (反転コスト) のグラフ内の最短パスになりますが、これはすでに管理可能です。 ただし、厳密なバージョン増加条件により、任意のトラバースが防止されます。バージョン t のエッジを使用すると、その後のすべてのエッジは厳密にそれより大きいバージョンを持たなければなりません。 

強引なアイデアは、バージョンごとにエッジをソートし、1 から n までの到達可能性を維持しながら、各バージョン レベルでエッジを選択するあらゆる方法を探索して、段階的にパスを構築しようとすることです。 これは、各バージョン グループでエッジのどのサブセットを反転して使用するかを本質的に選択することになり、到達可能性が複雑な方法で伝播するため、急速に指数関数的になります。 

重要な洞察は、視点を逆転させることです。つまり、ノード上のパスについて考える代わりに、バージョンの昇順にエッジを処理するときに到達可能性がどのように進化するかを考えます。 どのバージョンしきい値でも、より小さいバージョンのエッジのみを使用して各ノードに到達するための最もよく知られたコストを維持します。 新しいバージョン グループに移行するときは、そのバージョンのエッジを使用してトランジションを緩和したいと考えていますが、各エッジには 2 つの用途があります。順方向 (コスト 0) または逆方向 (コスト 1、ただし方向が交換される) です。

これは当然、各層がバージョンの処理に対応する層状時間展開グラフ上での最短経路問題になりますが、層ごとに状態全体をコピーすることは避けなければなりません。 重要な最適化は、バージョン単位でのみ前進するため、バージョンごとにグループ化されたエッジを処理し、グローバルな距離配列を維持できることです。 

各バージョン グループ内で、0-1 BFS スタイルの緩和を実行します。エッジを反転するかどうかに応じて両方向にエッジをトラバースし、順方向をコスト 0、逆方向をコスト 1 として扱いますが、バージョンの単調性が維持されるように同じバージョン層内でのみ処理されます。 

これにより、効率的な伝播により、問題はバージョン層の DAG 上のマルチソース最短パスに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのパスに対するブルート フォース | 指数関数 | O(m) | 遅すぎる |
 | バージョンごとに 0 ～ 1 の BFS によるソートされたエッジ処理 | O(m log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### 1. エッジをバージョン別にグループ化する

 まず、すべてのルーティング プログラムをバージョン値で並べ替えてから、バージョンが同じエッジをグループ化します。 これにより、許可された使用の厳密に昇順で移行が処理されるようになります。 

### 2. ノード間の距離配列を維持する

 dist[v] を、これまでに処理されたエッジのみを使用してノード v に到達するために必要なフリップの最小数として定義します。 初期状態では、dist[1] = 0 であり、他のすべての値は無限大です。 

これは、新しいバージョン層を検討する前の最もよく知られているコストを表します。 

### 3. 一度に 1 つのバージョン グループを処理します

 同じバージョン t を持つエッジのグループごとに、これらのエッジのみを使用して到達可能性の向上を試みますが、順序に違反する方法で同じグループにわたる更新を混合することはありません。 

0 ～ 1 BFS スタイルの伝播には一時キューを使用します。 

### 4. 各エッジに両方向を追加します。 

エッジ u → v については、次のように考慮します。 

- そのまま使用: コスト 0 で u から v に移動します
 - 反転: コスト 1 で v から u に移動します。 

同じバージョン グループの前または同じバージョン グループ内ですでに到達可能なノードからのみ緩和し、同じバージョンのエッジを逆の順序で再利用しないようにします。 

### 5. バージョン グループ内で 0-1 BFS を実行します。 

更新された状態を両端キューにプッシュします。コスト 0 の遷移は前方に移動し、コスト 1 の遷移は後方に移動します。 これにより、層内での伝播が最短になります。 

グループが終了したら、すべての改善を dist にコミットします。 

### なぜ効果があるのか

 このアルゴリズムでは、以前のグループを再訪問することがないため、バージョン グループを増やすことによってパスが構築されるように強制されます。 各グループ内では、同じバージョンのエッジを使用したコスト伝播のみが許可されますが、順序違反をシミュレートするような方法で、同じバージョン内の新しく改善された状態を効果的に再利用して、同じバージョンのサイクルでエッジを横断するような方法での連鎖は許可されません。 階層化処理により、有効なパスがバージョン グループの非減少シーケンスに対応することが保証され、0-1 BFS により、上位バージョンに移行する前にローカルでの反転が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

INF = 10**18

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        edges_by_t = defaultdict(list)

        for _ in range(m):
            u, v, ti = map(int, input().split())
            edges_by_t[ti].append((u - 1, v - 1))

        dist = [INF] * n
        dist[0] = 0

        for ti in sorted(edges_by_t):
            edges = edges_by_t[ti]

            dq = deque()
            ndist = dist[:]  # snapshot to prevent intra-layer contamination

            for u, v in edges:
                if ndist[u] != INF:
                    if ndist[v] > ndist[u]:
                        ndist[v] = ndist[u]
                        dq.append((v, 0))
                    if ndist[u] + 1 < ndist[v]:
                        ndist[u] = ndist[v]
                        dq.append((u, 1))

                if ndist[v] != INF:
                    if ndist[u] > ndist[v] + 1:
                        ndist[u] = ndist[v] + 1
                        dq.append((u, 1))

            while dq:
                x, c = dq.popleft()
                for u, v in edges:
                    if u == x and ndist[v] > ndist[u]:
                        ndist[v] = ndist[u]
                        dq.append((v, 0))
                    if v == x and ndist[u] > ndist[v] + 1:
                        ndist[u] = ndist[v] + 1
                        dq.append((u, 1))

            dist = ndist

        print(-1 if dist[n - 1] == INF else dist[n - 1])

if __name__ == "__main__":
    solve()
```このコードは、遷移が厳密な順序制約を遵守できるように、エッジをバージョンごとに編成します。 距離配列は最小反転を追跡します。 各バージョン グループに対して、デキューを使用してローカル緩和が実行され、順方向トラバーサルはコスト 0、逆方向トラバーサルはコスト 1 として扱われます。スナップショット配列により、意図した階層構造に違反するような方法で同じバージョン内で誤って連鎖することがなくなります。 

微妙な点は、バージョン グループを処理する前に常に距離配列をコピーすることです。 これにより、同じグループ内の新しく改良されたノードが、同じバージョンのエッジを無効な順序で複数回使用することをシミュレートするような形で、同じバージョンの別のエッジに直ちに影響を与えることが防止されます。

```最初に t=1 を処理し、2->1 で到達可能性を作成できますが、1 から 2 に到達することはできません。次に t=2 が処理されますが、1->2 を使用すると反転する必要がなく、有効なパス 1→2 が得られます。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log m) | バージョンによるエッジのソートが優勢です。 各エッジはそのグループ内で処理されます。 
| スペース | O(n + m) | 隣接ストレージと距離配列 |

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    from collections import defaultdict, deque

    INF = 10**18
    t = int(sys.stdin.readline())
    out = []

    for _ in range(t):
        n, m = map(int, sys.stdin.readline().split())
        edges_by_t = defaultdict(list)

        for _ in range(m):
            u, v, ti = map(int, sys.stdin.readline().split())
            edges_by_t[ti].append((u - 1, v - 1))

        dist = [INF] * n
        dist[0] = 0

        for ti in sorted(edges_by_t):
            edges = edges_by_t[ti]
            ndist = dist[:]

            for u, v in edges:
                if ndist[u] != INF and ndist[v] > ndist[u]:
                    ndist[v] = ndist[u]
                if ndist[v] != INF and ndist[u] > ndist[v] + 1:
                    ndist[u] = ndist[v] + 1

            dist = ndist

        out.append(str(-1 if dist[n - 1] == INF else dist[n - 1]))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジ ケースは、すべての有用なエッジが存在するが、バージョンの降順になっている場合です。 この場合、反転方向を超えてプログラムを並べ替えることはできないため、有効なシーケンスは存在しません。そのため、答えは -1 になります。 以前の接続が確立される前に新しいバージョンが必要な場合はパスを形成できないため、アルゴリズムは正しく -1 を返します。 

もう 1 つのエッジ ケースは、前進する唯一の方法として、増加するバージョン間で複数のフリップを連鎖する必要がある場合です。 階層化された処理により、各フリップが独立してカウントされ、dist に蓄積されるため、最小コスト パスが維持されます。 

自己ループは決して到達可能性を向上させず、コストを削減することはありません。また、新しいノードを緩和しないため、アルゴリズムは当然それらを無視します。
