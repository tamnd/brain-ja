 ## 解決策
 ## 問題の理解

 一連のメンテナンス禁止を記述する長さ n の配列が与えられます。 毎秒 i は、ちょうど 1 つの周波数 ai の使用を禁止します。 可能な周波数は n + 1 個あり、0 から n までのラベルが付けられます。ラベルが小さいほど望ましいです。 

タイムラインを k 個の連続するセグメントに分割します。 セグメント内では、そのセグメントに出現するすべての禁止値を調べ、そこに決して出現しない最小の非負の周波数を計算します。 その値はセグメントで選択された周波数であるため、各セグメントはその範囲内でどの周波数が欠落しているかに純粋に基づいて 1 つの数値を生成します。 

分割を修正した後、そのような値を k 個取得します。 それとは別に、緊急周波数 y を 1 つ選択する必要があります。 この y には、元の配列のどこかに現れる任意の値を指定できますが、k 個のセグメント値のいずれとも等しくない必要があります。 y をできるだけ小さくしたいので、y として選択されるのを「ブロック」するために、セグメント結果に小さな数値を強制的に入れようとします。 

重要な点は、パーティションによってどの mex 値が表示されるかを制御し、それらの mex 値が y の候補を削除することです。 できるだけ多くの小さな値、特に実際に配列に現れる小さな値がセグメントの mex 結果になるように、k 個のセグメントを設計したいと考えています。 

この制約により、n は最大 100 万まで許容され、セグメントに対する二次戦略やすべてのパーティションの単純なシミュレーションが除外されます。 セグメントごとに mex を最初から再計算したり、すべてのカット位置を試したりすると、すぐに遅すぎます。 慎重かつ貪欲な推論による線形または線形に近い構造が必要です。 

微妙なエッジ ケースは、y が配列内に現れる値から取得されなければならないという事実から生じます。 セグメント mex 値に何らかの数値が表示されないようにできたとしても、問題となるのはその数値が入力に存在するかどうかだけです。 もう 1 つの特殊なケースは、k が大きい場合です。実際に強制できる「有用な」mex 値が十分にない可能性があるため、残ったセグメントは無関係になります。 

## アプローチ

 ブルート フォース戦略では、配列を k 個のセグメントに分割し、各セグメントの mex を計算し、結果のセットを収集して、最小の有効な y を決定するために考えられるすべての方法を試みます。 パーティションの数を無視したとしても、mex を繰り返し計算することはすでにコストがかかります。 単一のパーティションの場合、線形時間でセグメントごとの mex を再計算すると、分割ごとに O(n) が得られ、分割数は n で指数関数的に増加するため、これは完全に不可能になります。 

重要な点は、セグメントの mex は、0 から上のすべての値が含まれているかどうかのみに依存するということです。 セグメント mex を強制的に x にするには、セグメントに 0 から x − 1 までのすべての数値が少なくとも 1 回含まれ、x が完全に欠落している必要があります。 これにより、各 mex 値が、セグメント境界を配置する場所に対する構造的制約になります。 

パーティションをグローバルに考えるのではなく、視点を反転します。 私たちは、どの値 x が何らかのセグメントの mex として現れる可能性があるかを尋ねます。 それが分かれば、選択された各 mex が 1 つのセグメントを消費するため、最大 k 個のセグメントにわたってどの値を「消費」できるかを決定できます。 

値 x は、x のすべての出現を避ける領域に存在するように 0 から x − 1 までのすべての数値の出現を選択できる場合、セグメント mex として実現可能です。 これにより、ギャップベースの条件が作成されます。つまり、x の出現により配列が間隔に分割され、x に触れない単一の間隔内に、より小さい数値ごとに少なくとも 1 つの出現が収まる必要があります。 

実現可能な mex 値をすべて特定した後、最適な戦略は、配列内に実際に現れる最小の実現可能な値を k 個まで選択することです。 これらがセグメント結果となります。 答え y は、それらの k 個の選択肢の中から選択されなかった最小の配列値になります。

 ## アルゴリズムのチュートリアル

 ソリューションは 2 つのフェーズで構築されます。 まず、セグメント mex としてどの値を表示できるかを決定します。 次に、それらのうち最大 k 個を選択して、ブロックされる小さな配列値の数を最大化します。 

1. すべての値 v について、配列内で v が出現する位置のリストを計算します。 これにより、v によって生じるギャップについて推論できるようになります。 
2. 固定候補 x については、配列内の x の位置を調べます。 これらの位置により、タイムラインが x を含まないいくつかの最大間隔に分割されます。 mex が x に等しいセグメントは、完全にこれらの間隔の 1 つの内側に存在する必要があります。 
3. そのような区間の 1 つ内で、0 から x − 1 までのすべての数値の少なくとも 1 つの出現を収集できるかどうかを確認します。これが可能な区間が存在する場合、x は実行可能な mex 値です。 
4. 配列内に出現するすべての値に対してこの実現可能性チェックを繰り返します。 これにより、セグメント結果として実現できる可能性のあるすべての mex 値のセットが得られます。 
5. 配列内に表示される実行可能な値を並べ替えます。 このソートされたリストから、最小の k 値を取得します。 これらは、k 個のセグメントに割り当てる mex 値です。 
6. 緊急値 y は、配列内に出現する最小の数値ですが、選択された mex 値には含まれません。 

重要な構造特性は、値 x の実現可能性が、配列を他の場所でどのように分割するかに依存しないことです。 mex 制約はそのセグメントに対してローカルであるため、各セグメントを個別に検証できます。 唯一のグローバル結合は、合計で k 個のセグメントしか使用できないため、k 個の実行可能な mex 値しか選択できないという事実から生じます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    pos = [[] for _ in range(n + 1)]
    present = [False] * (n + 1)

    for i, v in enumerate(a):
        pos[v].append(i)
        present[v] = True

    def can_make_mex(x):
        if x == 0:
            return True
        if not present[x]:
            return True

        # we try each gap between occurrences of x
        occ = pos[x]
        # build boundaries of x-free segments
        segments = []

        prev = -1
        for p in occ:
            segments.append((prev + 1, p - 1))
            prev = p
        segments.append((prev + 1, n - 1))

        need = set(range(x))
        need_list = list(need)

        for l, r in segments:
            if l > r:
                continue
            seen = set()
            for i in range(l, r + 1):
                if a[i] < x:
                    seen.add(a[i])
            if all(v in seen for v in need_list):
                return True

        return False

    feasible = []
    for x in range(n + 1):
        if present[x] and can_make_mex(x):
            feasible.append(x)

    feasible.sort()

    chosen = set(feasible[:k])

    for v in range(n + 1):
        if present[v] and v not in chosen:
            print(v)
            return

    print(n)

if __name__ == "__main__":
    solve()
```コードは最初に位置リストを構築して、各値がどこに表示されるかを推論できるようにします。 機能`can_make_mex(x)`x のない間隔をスキャンし、必要なすべての小さい値が少なくとも 1 つのそのような間隔内に出現するかどうかを検証することにより、mex x を達成できるセグメントが存在するかどうかをチェックします。 

すべての実行可能な mex 値を収集した後、それらを並べ替えて最小の k を取得します。これは、これらが y の小さな候補をブロックするのに最も価値があるためです。 最後に、上方向にスキャンして、選択された mex として使用されていない最小の配列値を見つけます。 

1 つの微妙な詳細は、x = 0 の処理です。セグメントには 0 が含まれていない場合にのみ、mex 0 が含まれます。したがって、0 のない区間は直ちに条件を満たします。 

## 実用的な例

 インプットを考慮する`n = 3, k = 2`配列あり`[1, 3, 0]`。 

まず、実現可能な mex 値を特定します。 x = 0 の場合、可能であれば 0 を避けるセグメントをいつでも選択できます。 x = 1 の場合、0 を含むが 1 を含まないセグメントが必要です。 これは、0 が単独で出現する区間で可能です。 x = 2 および x = 3 の場合、同様のチェックにより、実現可能性は x を含めずに必要な小さい値を分離できるかどうかに依存することがわかります。 

実現可能性を確認した後、実現可能リストを取得したとします。`[0, 1, 3]`。 k = 2 を最小とするので、選択された mex 値は次のようになります。`{0, 1}`。 残りの配列値は次のとおりです。`{0, 1, 3}`、選択されたセットにない最小のものは次のとおりです。`2`表示される場合は、表示されない場合は上方向に進みます。 

このトレースは、mex の実現可能性が最終的な答えの下位整数のブロックにどのように変換されるかを示しています。 

ここで考えてみましょう`n = 2, k = 2`配列あり`[0, 2]`。 

x = 0 の場合、2 番目の要素を分離すれば、常に 0 のないセグメントを形成できます。 x = 2 の場合、実現可能性は 2 のないセグメントで 0 と 1 を収集できるかどうかに依存しますが、1 は決して出現しないため不可能です。 したがって、実現可能な mex 値は制限されます。 k = 2 の場合、すべての実行可能な値を選択し、カバーされていない最小の配列値として y を残します。 

これは、中間値が欠落していると mex 構築の可能性がどのように低下​​するかを示しています。

 ## 特殊なケース

 重要なエッジ ケースは、値 0 が配列内にまったく出現しない場合です。 その場合、すべてのセグメントには自動的に mex 0 が含まれるため、セグメンテーションに関係なく mex 0 は常に実現可能です。 このアルゴリズムは、0 を直ちに実行可能として正確にマークし、選択ステップで使用できるようにします。 

もう 1 つのケースは、k が実現可能な mex 値の数と比較して大きい場合です。 いくつかの個別の mex 値しか構築できない場合でも、アルゴリズムは最大でも k 個の値を選択し、追加の不可能なセグメントを強制しようとしないため、依然として機能します。 

3 番目のケースは、値が高度にクラスター化された形式で表示され、x のない間隔が多数作成される場合です。 実行可能性チェックは、x ごとに 1 つの有効な間隔を見つけるだけで済み、残りは無視されるため、引き続き機能します。
