 **解決時間:** 2 分 7 秒

 ## 解決策
 ## 問題の理解

 選挙には固定の有権者がおり、各有権者は最初にいくつかの政党のいずれかに所属します。 United Party は第 1 党であり、その目標は単に多くの票を獲得することではなく、最終的な得票数で他のすべての政党を厳密に上回ることです。 

各有権者には 2 つの情報が与えられます。それは、現在どの政党を支持しているか、そして政党 1 への投票を切り替えるよう説得するのにどれだけの資金が必要かということです。賄賂を受け取った有権者は、元の政党への支持をやめ、代わりに統一党に投票します。 

課題は、有権者の一部が乗り換えるよう説得された後、最終的に政党 1 が他のどの政党よりも多くの票を獲得できるように、必要な賄賂総額の最小額を決定することです。 

最大 3000 人の有権者と 3000 の政党という入力サイズの制約は、二次解は受け入れられるが、3 次解や大規模な州で完全な再計算を繰り返すことを伴う解は遅すぎることを示唆しています。 状態空間は指数関数的であるため、投票者のすべてのサブセットをシミュレートしようとする解決策は直ちに不可能です。 

素朴だが有益なアプローチは、可能な限りすべての有権者の一部を試して賄賂を渡し、政党 1 が勝つかどうかを確認することだろう。 サブセットが 2^n 個あり、n = 3000 の場合でも、これは実行可能な計算をはるかに超えているため、これは失敗します。 

2 番目の単純なアイデアは、政党 1 の最終投票数をすべて試して、他の政党を貪欲に調整することです。 これは解決策に近いものですが、それでも注意が必要です。政党のバランスを尊重せずに世界中で最も安価な有権者に単純に賄賂を渡すと、正しさが損なわれる可能性があります。 

微妙な失敗例は、一方の敵対勢力がすでに非常に大きい場合に発生します。 たとえば、第 2 党の票が 1000 票で、他のすべての票が 1 票の場合、世界的に最も安い有権者を盲目的に買収すると、大きな政党ではなく小さな政党が減り、同じ予算で最初に無力化できたとしても第 2 党が依然として優勢なままになる可能性があります。 

重要な問題は、有権者への賄賂には 2 つの効果が同時にあるということです。つまり、元の政党が減り、政党 1 が増えるということです。正しい戦略では、両方の効果を総合的に考慮する必要があります。 

## アプローチ

 ブルートフォースベースラインは、有権者のすべてのサブセットが賄賂を受け取っているとみなして、結果として得られるすべての政党の投票数を計算し、政党 1 が厳密に最大かどうかを確認することです。 これは、考えられるすべての結果を列挙するため正しいですが、n までのサイズのすべてのサブセットを反復処理する必要があるため、およそ O(2^n · n) の操作が必要になります。 これは、3000 の場合はもちろん、n = 40 の場合でも実現不可能です。 

より構造化された総当り攻撃は、政党 1 が終了する最終的な投票数 x を推測することです。 各 x について、他のすべての政党が最大で x − 1 票を持つように強制しようとします。 これにより、すでに構造が導入されています。任意のサブセットではなく、最終的な集計の制約の下でどの有権者に賄賂を渡すかを決定するだけです。 

重要な観察は、私たちが他の政党から賄賂を贈った各有権者は、その政党の投票数を減らし、第 1 党の投票数を増やすということです。 したがって、賄賂を受け取ったすべての有権者は、競合他社を下げることとスコアを増やすという 2 つの目標に同時に役立ちます。 これは、元の政党から除外する一連の有権者を選択するという観点から常に考える必要があることを意味します。 

固定ターゲット x の場合、現在のカウント cj を持つ各パーティ j > 1 は、cj ≥ x の場合に減らす必要があります。 その場合、私たちはその政党の少なくとも cj − (x − 1) 人の有権者に賄賂を贈らなければなりません。 コストを最小限に抑えるために、私たちは常に各政党内で最も安価な投票者を最初に採用します。 

これらの強制的な削減を実行した後、政党 1 はすでに、私たちが買収した有権者の数に等しい数の票を獲得しています。 これでも x に達するのに十分でない場合は、残りの投票者の中から追加の投票者を買収し、常に最も安価な投票者を選択することができます。 

これにより、各候補 x が、並べ替えと接頭辞の合計を伴う貪欲な選択問題に変換されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット | O(2^n · n) | O(n) | 遅すぎる |
 | 貪欲な選択ですべてのターゲット x を試す | O(n^2 log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各政党の最初の投票を数え、非 1 政党のすべての有権者を収集し、その賄賂コストを保管します。 これにより、どこで削減できるかを構造的に把握できます。 
2. 各政党 j > 1 について、その投票者をコストの昇順に並べ替えます。 これにより、政党の削減を余儀なくされた場合、常に可能な限り最も安価な有権者を最初に選択することが保証されます。 
3. 政党 1 の初期投票数を計算します。これは、ある目標 x まで改善しようとするベースラインです。 
4. 最初の政党 1 の投票から n までのすべての可能なターゲット値 x を反復します。 各 x について、他のすべての政党を x 未満に抑えながら、政党 1 を x 票に到達させることが可能かどうかを評価します。 
5. 固定 x について、各政党 j > 1 について、残りの投票数が最大でも x − 1 になるように何人の有権者を買収する必要があるかを決定します。この必要な量は max(0, cj − (x − 1)) です。 
6. 各政党について、その数の最安投票者を選択し、選択済みとしてマークします。 これらがなければターゲット構成は不可能であるため、これらは必須の動きです。 
7. これまでに何人の有権者が買収されたかを追跡する。 これは政党 1 の投票数を直接増加させます。 
8. 強制選出後も政党 1 の投票数が x 票未満の場合は、x 名に達するか候補者が枯渇するまで、残りの未選択の有権者全員から追加の投票者を取り、常に最も安価な投票者を最初に選択します。 
9. この x に対して選択されたすべての投票者の合計コストを計算し、グローバル最小値を更新します。 

### なぜ効果があるのか

 固定ターゲット x の場合、有効な解決策は、大きすぎる敵対勢力をすべて x 以下に削減する必要があります。 各政党内で、より安価な投票者ではなくより高価な投票者を選択すると、実現可能性が向上せずに総コストが増加するだけであるため、政党ごとに貪欲な選択が余儀なくされます。 

すべての強制的な制約を満たした後、残りのすべての有権者は実現可能性の観点から交換可能であり、唯一の目的は政党 1 のカウントを増やすことであり、残りの最も安価な有権者を選択することでコストあたりのカウントが最大化されます。 この構造により、アルゴリズムがすべての実現可能なターゲット x に対して最適なコストを探索し、その中で最適なものが全体最適となることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    
    party = [[] for _ in range(m + 1)]
    cnt = [0] * (m + 1)
    
    voters = []
    
    for _ in range(n):
        p, c = map(int, input().split())
        cnt[p] += 1
        voters.append((p, c))
        if p != 1:
            party[p].append(c)
    
    for j in range(1, m + 1):
        party[j].sort()
    
    base = cnt[1]
    
    ans = float('inf')
    
    for target in range(base, n + 1):
        need = [0] * (m + 1)
        cur = base
        
        chosen = []
        used = [0] * (m + 1)
        
        for j in range(2, m + 1):
            if cnt[j] >= target:
                need[j] = cnt[j] - (target - 1)
                for i in range(need[j]):
                    chosen.append(party[j][i])
                    cur += 1
                    used[j] += 1
        
        if cur < target:
            rem = []
            
            for j in range(2, m + 1):
                for c in party[j][used[j]:]:
                    rem.append(c)
            
            rem.sort()
            
            cur_cost = sum(chosen)
            for c in rem:
                if cur >= target:
                    break
                cur += 1
                cur_cost += c
            
            ans = min(ans, cur_cost)
        else:
            ans = min(ans, sum(chosen))
    
    print(ans)

if __name__ == "__main__":
    solve()
```実装は、有権者を現在の政党ごとにグループ化し、各グループを賄賂コストごとに並べ替えることから始まります。 これにより、政党を削減する必要がある場合に、常に最も安価な必要な投票者を抽出することが可能になります。 

メイン ループは、政党 1 の考えられるすべての最終投票数を試行します。ターゲットごとに、まず、過半数の政党から必要な最も安価な投票者を選択することによって、他の政党がしきい値を超えないという制約を適用します。 これは、`need`計算と`chosen`リスト。 

必須の選択の後、コードはパーティ 1 がすでにターゲットに到達しているかどうかをチェックします。 そうでない場合は、残りのすべての未選択の有権者のリストを作成し、目標が達成されるまでコストに基づいてそれらを貪欲に使用します。 必須の削減とオプションの拡張をこのように分離することで、正確性が保たれます。 

最終的な答えは、すべての実現可能なターゲットの中での最小コストです。

 ## 特殊なケース

 重要なエッジケースは、第 1 党が賄賂なしで厳密に優位に立つのに十分な票をすでに持っている場合です。 たとえば、入力が`n = 3`、投票あり`[1, 1, 2]`、パーティ 1 がすでに勝利しており、アルゴリズムはターゲットを初期カウントに等しいと正しくみなし、コスト 0 を返します。 

もう 1 つのケースは、ある対戦相手が他の対戦相手と比べて非常に大きい場合です。 政党 2 がほぼすべての票を持っている場合、アルゴリズムは、合理的な目標に対して必須フェーズでその政党から多くの投票者を選択することを強制されます。 これにより、小規模な政党に無駄な労力を費やすのではなく、有力な政党を削減することが正確に優先されます。政党ごとの並べ替えにより、実際に制約に違反する唯一の政党から最も安価な投票者を常に削除できるためです。 

最後の微妙なケースは、強制削除が既にパーティー 1 の目標を超えている場合に発生します。このような状況では、追加の賄賂は必要なく、アルゴリズムは残りのプールからの選択を正しく回避します。
