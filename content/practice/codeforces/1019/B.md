 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、$n$学生、どこ$n$は均等です。 各生徒は未知の整数を保持しており、これらの値に関する唯一の構造的保証はローカルなものです。つまり、円上で隣接する 2 つの値は、値が 1 つだけ異なります。 これにより、設定全体が整数線上で「ウォーク」のように動作し、ステップごとに 1 つずつ上下に移動し、最終的にループを閉じます。 

インタラクションにより、位置をクエリすることで個々の値を明らかにすることができます。 私たちの仕事は、配列全体を再構成することではなく、円の中で向かい合って座っている同じ値を持つ生徒のペアが少なくとも 1 組存在するかどうかを判断することです。 そのようなペアが存在する場合は、そのペアに属するインデックスを出力する必要があります。 それ以外の場合は -1 を出力します。 

値をクエリすることしかできず、配列を見ることはできないため、最大 60 個のクエリを使用しながら、反対の位置間の衝突を特定する方法を決定することが困難になります。$n$と同じ大きさにすることができます$10^5$。 

制約$n \le 10^5$すべての位置、またはその大部分を調査するアプローチは直ちに除外されます。 フルスキャンには次のことが必要です$O(n)$これは制限の 60 をはるかに超えています。そのため、ソリューションでは戦略的に位置をサンプリングし、隣接する差分が常に存在するという構造的制約を利用する必要があります。$\pm 1$。 

ランダムサンプリングや単純なペアリングチェックを試みると、微妙な問題が発生します。 たとえば、値が次のように振動する場合、$1,2,1,2,1,2,\dots$、反対のペアはすべて異なる可能性があり、ランダムサンプリングは構造を完全に見逃してしまう可能性があります。 もう 1 つの落とし穴は、同じ値が頻繁に出現する必要があると想定していることです。 実際、構築には重複がほとんどなく、おそらく検索している反対のペアのみが含まれる可能性があります。 

欠けている重要な洞察は、配列が制約されたウォークのように動作するため、慎重に選択された対称位置の値を知ることで、制御された方法で比較を「伝播」し、矛盾や一致が発生する必要がある場所を絞り込むことができるということです。 

## アプローチ

 ブルートフォース戦略は、すべての生徒にクエリを実行し、すべての値を保存し、すべてをチェックすることです。$n/2$反対のペア。 これは正しいですが、次のことが必要です$n$クエリを実行すると、すぐに制限に違反します。 重複が発生する場所を保証する単調な構造がないため、部分的なスキャンでも役に立ちません。 

重要な観察は、円と制約が一緒になっていることです。$|a_i - a_{i+1}| = 1$これは、非常に厳格な構造を暗示しています。つまり、1 つの値がわかると、方向選択の全体的な変化まで他のすべての値が決定されます。 これは、円に沿った差異が予測どおりに蓄積され、反対側の点が一定の長さのパスを介してリンクされることを意味します。$n/2$±1 ステップのみで構成されます。 

インデックスの値を比較すると$i$そして$i + n/2$、それらの差は、±1 遷移のセグメントの正味合計にのみ依存します。 この合計は、大きさが次の範囲で制限されたランダム ウォークのように動作します。$n/2$そして、それがゼロに達するかどうかを検出したいと考えています。 

すべての値を再構成する代わりに、対数のアンカー ポイントをサンプリングし、二分探索スタイルの推論を使用して局所的に両方向に拡張します。ある位置の値がその反対の候補よりも高いことを検出した場合、ウォークが円内をどのようにドリフトする必要があるかがわかります。これにより、各ステップで探索スペースの半分を削除できます。 

核心的な還元は、円の周囲のセグメント内単調差分関数でゼロを検索することによって、等しい反対のペアの存在をチェックできるということです。 これにより、位置の二分探索が可能になります。$O(\log n)$チェックごとのクエリ数、および最大でも一定数のチェック。

 ## アルゴリズムのチュートリアル

 私たちは反対の位置にわたる対称性を利用します。 あらゆるインデックスに対して$i$、その反対を次のように定義します$i + n/2$(モジュロ$n$）。 インデックスを見つけようとします。$a_i = a_{i+n/2}$。 

1. 任意の開始インデックスを選択します。通常は、$1$、クエリしてください。 これにより、すべての比較の基準となる基準値が得られます。 
2. 候補インデックスの場合$i$、両方をクエリします$i$そして$i + n/2$。 これにより、反対側の点間の差が得られます。 
3. インデックスの検索範囲を定義します$i \in [1, n/2]$なぜなら、反対の位置の各ペアはこの範囲内で一意に表現されるからです。 
4. この範囲に対して二分探索を実行します。 中間点で$m$、両方をクエリします$m$そして$m + n/2$。 それらが等しい場合は、すぐに戻ります$m$有効なペアが見つかったためです。 
5. それらが等しくない場合は、差の符号を使用して、検索スペースのどちらの半分を保持するかを決定します。 ±1 隣接制約は、反対側のペア間の差異が制御された方法で変化することを保証するため、遷移点を通過すると、不均衡の方向は一貫したままになります。 
6. 有効なインデックスが見つかるか、間隔がなくなるまで、範囲を狭め続けます。 
7. すべてのクエリ後に等しいペアが見つからなかった場合は、-1 を出力します。 

重要なアイデアは、反対の値の差が循環インデックス上で区分的単調関数のように動作し、ゼロが存在する場合に二分探索でゼロを分離できるようにするということです。 

### なぜ効果があるのか

 隣接制約により、シーケンス全体が整数上の離散ウォークになります。 反対側のペアに投影すると、関数は$f(i) = a_i - a_{i+n/2}$シフトするので徐々に変化します$i$by 1 は、両方の項を相関的に最大 1 だけ変更します。 これにより、$f(i)$任意に振動することはできません。 それは制限された増分で進化します。 したがって、ゼロが存在する場合、それは二分探索で見逃すことなく分離できる連続領域に出現する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(i):
    print("?", i)
    sys.stdout.flush()
    return int(input().strip())

def solve():
    n = int(input().strip())
    
    def get(i):
        return ask(i)

    l, r = 1, n // 2
    a_l = get(l)
    a_l_op = get(l + n // 2)
    if a_l == a_l_op:
        print("!", l)
        sys.stdout.flush()
        return

    a_r = get(r)
    a_r_op = get(r + n // 2)
    if a_r == a_r_op:
        print("!", r)
        sys.stdout.flush()
        return

    while l + 1 < r:
        m = (l + r) // 2
        a_m = get(m)
        a_m_op = get(m + n // 2)

        if a_m == a_m_op:
            print("!", m)
            sys.stdout.flush()
            return

        # decide direction using consistency with left endpoint
        if (a_m - a_m_op) * (a_l - a_l_op) > 0:
            l, a_l, a_l_op = m, a_m, a_m_op
        else:
            r = m

    print("! -1")
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```この実装では、検索空間内に 2 つの境界点が維持され、それぞれの境界点に位置とその反対の値の両方が格納されます。 各ステップで、中点をクエリし、その反対側の差を左側の境界と比較して、どちらの側に潜在的なゼロクロッシングがまだ含まれているかを判断します。 

微妙な点は、値自体の単調性を決して仮定せず、逆差分関数の符号の単調性のみを仮定していることです。 これが、ここで二分探索が有効になる理由です。 

インタラクションでは出力ごとに厳密な同期が必要となるため、すべてのクエリはすぐにフラッシュされます。 

## 実用的な例

 概念的な小さな例を考えてみましょう。$n = 8$値は次のとおりです。$$[1, 2, 1, 2, 3, 4, 3, 2]$$反対のペアは (1,5)、(2,6)、(3,7)、(4,8) です。 アルゴリズムは位置 1 と 4 をクエリします。 

| ステップ | l | r | メートル | a[m] | a[m+n/2] | 決定 |
 | --- | --- | --- | --- | --- | --- | --- |
 | 初期化 | 1 | 4 | - | 1 | 3 | 右に移動 |
 | ミッド | 2 | 4 | 2 | 2 | 4 | 右に移動 |
 | ミッド | 3 | 4 | 3 | 1 | 3 | 右に移動 |
 | チェック | 4 | 4 | - | 2 | 2 | 見つかりました |

 これは、等しい反対のペアが見つかるまで検索がどのように絞り込まれるかを示しています。 

次に、解決策のないケースを考えてみましょう。$$[1,2,3,4,5,6,7,8]$$反対のペアは (1,5)、(2,6)、(3,7)、(4,8) であり、すべて等しくありません。 二分検索でも差分は評価されますが、ゼロには遭遇しないため、最終的に検索スペースを使い果たし、-1 が返されます。 

これは、ルートの欠如も誤検知なしで正しく処理されることを示しています。

 ## 特殊なケース

 いつ$n = 2$、円は単一の反対のペアに縮退します。 このアルゴリズムはインデックス 1 とその反対の 2 を即座にクエリするため、正確性は簡単です。 

のように値が変動する場合$1,2,1,2,\dots$、反対のペアはすべて異なる可能性がありますが、符号ベースの検索では一貫して空間が分割され、完全な探索を必要とせずに -1 が返されます。 

正しいペアが検索半分間の境界近くにある場合でも、枝刈りの前にすべての中間点で等価性がチェックされ、有効な解がスキップされないことが保証されるため、バイナリ検索ではそのペアが保持されます。 

次のような厳密に変化するシーケンスで$1,2,3,2,1,0$、反対の差の関数はちょうど 1 回ゼロと交差し、アルゴリズムの半減戦略によりその交差点が確実に分離されます。
