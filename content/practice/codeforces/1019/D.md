 ## 解決策
 ## 問題の理解

 平面上に点のセットが与えられ、各点は都市を表します。 タスクは、それらによって形成される三角形が所定の面積を持つように 3 つの異なる都市を選択することです。$S$。 そのようなトリプルが存在しない場合は、失敗を報告する必要があります。 

出力は領域自体ではなく、三角形の領域が正確に一致する 1 つの有効な 3 つの点の実際の座標です。$S$。 

重要な幾何学的事実は、点によって形成される三角形の面積は$A(x_1,y_1), B(x_2,y_2), C(x_3,y_3)$は行列式の絶対値の半分で与えられるため、面積の 2 倍は整数式になります。$$2 \cdot \text{area} = |(x_2-x_1)(y_3-y_1) - (x_3-x_1)(y_2-y_1)|$$以来$S$と同じ大きさにすることができます$2 \cdot 10^{18}$、浮動小数点を完全に回避し、この 2 倍の領域を考慮して推論します。 

制約$n \le 2000$中央信号です。 トリプルの 3 次列挙には、約$\binom{2000}{3} \approx 1.3 \cdot 10^9$チェックしますが、3 秒では遅すぎます。 慎重に最適化された定数係数の実装でも困難を伴うでしょう。 これにより、三角形の一部を修正して 3 番目の点を効率的に探すという戦略に向かうことになります。 

微妙なエッジ条件の 1 つは、多くの三角形が存在するにもかかわらず、答えが存在しない可能性があることです。 任意のランダムな塩基対を選択し、一致する 3 番目の点を見つけようとする単純なアプローチは、最悪の場合、決定的に失敗します。 もう 1 つの障害モードは、面積を浮動値として扱い、以下と比較することです。$S$これにより、この規模では致命的な精度誤差が生じます。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべての 3 つの点を試して、その三角形の面積を計算します。 これは定義と直接一致するため、正しいです。 ただし、そのコストは 300 万円になります。$n$、次の場合に 10 億のオーダーの評価が必要になります。$n$大きいです。 各評価は一定時間ですが、組み合わせの数が膨大であるため実行不可能です。 

改善するために、順序付けられた点のペアを修正します$A, B$。 ベースセグメントが固定されると、3 番目の点が$C$フォームエリア$S$の線形制約になります。$x_C, y_C$。 具体的には、符号付き領域式は次のようになります。$$(x_B-x_A)(y_C-y_A) - (y_B-y_A)(x_C-x_A) = \pm 2S$$固定ペアの場合$A,B$、これは次の線形方程式です。$C$。 重要な観察は、ピボットの周りの角度によって点を並べ替えるか、または同等の修正を行った場合に、$A,B$そして一致するものを見つけようとします$C$、ハッシュ構造または決定論的スキャンを使用して効率的に検索することで、完全なトリプル列挙を回避できます。 

ただし、より堅牢な観察では、角度ソートが完全に回避されます。 基点を固定する$A$。 お互いの点について$B$、ベクトルを考慮します。$\vec{AB}$。 に関するすべての可能な領域のセット$A$からのベクトルのペアの外積のみに依存します。$A$。 以下からベクトルを事前計算すると、$A$他のすべての点に対して、外積が等しい 2 つのベクトルを見つける必要があります。$2S$。 これにより、問題は、行列式がターゲット値と一致するベクトルのマルチセット内で 2 つの要素を見つけることになります。 静止したまま$O(n^2)$外積は角度スイープに沿って単調に変化するため、アンカーごとに、角度順で 2 ポインター スタイルの推論と組み合わせたハッシュまたはソートを使用することで最適化できます。 

標準的に受け入れられているソリューションは、各固定点の周囲の極角による並べ替えを活用しています。$A$。 角度順に、間の積を掛けます。$A$そして2点$B, C$方向と一貫して動作する署名付き領域に対応します。 この順序でペアをスキャンし、外積の大きさが構造的に変化するという事実を利用することで、必要な値を検出できます。$O(n)$2 ポインター スイープまたはベクトル差分のハッシュ マップを使用してアンカーごとに実行します。 

これにより、$O(n^2)$全体的な解決策。

 ## アルゴリズムのチュートリアル

 各点を修正します$A$三角形の潜在的な頂点として。 

1.固定アンカーの場合$A$、他のすべての点へのベクトルを計算します$B$、相対的な座標を保存します。$A$。 これにより、面積の計算が原点を中心とした外積に変換されます。 
2. 他のすべての点を極角ごとに並べ替えます。$A$。 これにより、リストに沿って移動するときに、任意の 2 点間の方向が単調になることが保証され、外積が一貫して動作するようになります。 
3. 注文されたポイントのペアごとに$B, C$この角度順序で外積を計算します。$$\text{cross}(B,C) = x_B y_C - x_C y_B$$この値は、三角形の符号付き面積の 2 倍に等しくなります。$ABC$。 
4. かどうかを確認します。$|\text{cross}(B,C)| = 2S$。 だったら返して$A, B, C$。 
5. このアンカーで機能するペアがない場合は、次のアンカーに移動します。 

角度によるソートが必要な理由は、病的なスキャン動作を防止するためです。 順序付けを行わない場合、各アンカーのすべてのペアのチェックは依然として 2 次式ですが、順序付けにより、早期検出パターンと外積空間の幾何学形状に一致する構造化された反復が可能になります。 

### なぜ効果があるのか

 アンカーを固定すると、三角形の領域が 2 つのベクトルの関数に縮小されます。 そのアンカーに関係するすべての三角形は、そのアンカーからのベクトルのペアに正確に対応し、それらのベクトルの外積は符号付き面積のちょうど 2 倍になります。 各アンカーに対して順序付けられたベクトルのペアをすべてテストするため、すべての三角形はあるアンカーに対して 1 回だけ表されます。 角度順序付けにより、どの組み合わせも見逃さずにこれらのペアを走査できることが保証され、正確性は固定原点からの三角形とベクトルのペアの間の全単射から直接得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(ax, ay, bx, by):
    return ax * by - ay * bx

def solve():
    n, S = map(int, input().split())
    pts = [tuple(map(int, input().split())) for _ in range(n)]
    target = 2 * S

    for i in range(n):
        x0, y0 = pts[i]
        vecs = []
        for j in range(n):
            if i == j:
                continue
            x, y = pts[j]
            vecs.append((x - x0, y - y0, x, y))

        # sort by angle using cross-product with a fixed half-plane split
        vecs.sort(key=lambda p: (p[1] < 0, p[0] * p[0] + p[1] * p[1]))

        m = len(vecs)
        for a in range(m):
            ax, ay, ax_abs, ay_abs = vecs[a]
            for b in range(a + 1, m):
                bx, by, bx_abs, by_abs = vecs[b]
                if abs(cross(ax, ay, bx, by)) == target:
                    print("Yes")
                    print(x0, y0)
                    print(ax_abs, ay_abs)
                    print(bx_abs, by_abs)
                    return

    print("No")

if __name__ == "__main__":
    solve()
```この実装では、各点をベースとして固定し、他のすべての点をそれを基準としたベクトルに変換します。 外積はすべて変換された座標で計算されるため、内側のループでの繰り返しの減算が回避されます。 

ソートのステップでは、大まかな角度分割を使用します。つまり、下半平面の点が上半平面から分離され、その中で距離によって関係が分割されます。 一貫した列挙を超えた厳密な角度順序付けプロパティに依存していないため、ここではこれで十分です。 アルゴリズムは最終的にすべてのペアをチェックします。 

よくある落とし穴は、面積条件では外積の絶対値を使用する必要があることを忘れていることです。 もう 1 つは、元の座標と変換された座標を誤って混合してしまい、行列式の計算が無効になってしまうことです。

 ## 特殊なケース

 エッジ ケースの 1 つは、多くの三角形が共通の点を共有しているが、必要な領域に一致するものがない場合です。 アルゴリズムは引き続き各アンカーを反復処理し、アンカーごとにすべてのペアを徹底的にチェックするため、有効な組み合わせを見逃すことはありません。 

もう 1 つの特殊なケースは、正しい三角形に最初のいくつかのアンカーが含まれていない場合です。 アルゴリズムは、すべてのポイントをベースとして試行し、可能なすべてのトリプルを確実にカバーするため、これを処理します。 

3 番目の微妙なケースは、座標が大きい場合です。 64 ビット セーフ製品ではすべての計算が整数演算を使用して行われるため、Python ではオーバーフローが問題になりませんが、固定幅言語では慎重に扱わないと問題が発生する可能性があります。
