 ## 解決策
 ## 問題の理解

 正の整数の複数セットが与えられ、それが非常に特殊な操作、つまり分子が少なくとも分母である順序付きの要素ペアの間で整数の除算を行うことによって閉じられるかどうかを決定する必要があります。 配列から 2 つの値を選択し、フロア除算を使用して大きい値を小さい値で除算する場合、その結果も配列内にすでに存在している必要があります。 

入力は複数の独立したテスト ケースで構成されます。 各テスト ケースでは、配列とその値の上限が得られます。 それぞれの場合において、このフロア分割操作で配列が「閉じている」かどうかを判断する必要があります。 

この制約により、すべてのペアを明示的にテストしようとするアプローチから遠ざけられます。 テスト ケース全体の合計要素が最大 100 万個ある場合、単純な二重ループでは 10^12 のオーダーの演算が必要になりますが、これは 2 秒で実行可能な演算をはるかに超えています。 わずかに最適化されたペアの列挙も不可能です。 

明白ではない難しさは、条件が存在するペアだけではなく、すべての派生値に関するものであることです。 単純なアプローチでは、配列内の既存のペアのみをチェックする可能性がありますが、入力順序における「明らかな」相互作用の一部ではない場合でも、考えられるすべての商がすでに存在している必要があるという要件が欠落しています。 

典型的な失敗例は、配列に大きな数値と小さな数値が含まれているが、中間の商が省略されている場合です。 たとえば、10 と 3 が存在する場合、floor(10/3) = 3 は 3 が存在する場合には問題ありませんが、floor(10/4) または Floor(10/6) では構造によっては欠損値が生成される可能性があります。 派生値が 1 つでも欠けていると、配列全体が無効になります。 

## アプローチ

 ブルート フォース ソリューションでは、x ≥ y であるすべての順序ペア (x, y) をチェックし、floor(x/y) を計算し、メンバーシップを検証します。 これは、定義を直接適用するため、正しいです。 ただし、配列のサイズは 2 次であり、入力が大きいとすぐに実行できなくなります。 

重要な観察は、すべてのペアごとの除算を明示的に再計算する必要がないということです。 重要なのは、既存の要素の商として形成できるすべての値がセットに含まれているかどうかです。 すべての値は c によって制限されるため、周波数配列を操作して閉包をシミュレートできます。 

要素を反復する代わりに、値を反復します。 存在する値 y ごとに、c までの y のすべての倍数を「生成」し、導出されたフロアの一貫性を確保しようとします。 これにより、問題は値の範囲にわたってふるいのような伝播プロセスに変わります。 

この構造は、除算における数論の閉包に似ています。値が存在する場合、その値の倍数をその値で除算したすべての結果も存在する必要があります。 これにより、制御された方法で制約を小さい値から上に伝播させることができます。

 | --- | --- | --- | --- |
 | ブルートフォースペアチェック | O(n²) | お(1) | 遅すぎる |
 | 値ふるいの伝播 | O(c log c) | O(c) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を使用して配列内のすべての数値の頻度をカウントします`freq`。 
2. ブール値のプレゼンス配列を構築する`ok[x]`値かどうかを示す`x`配列内に存在します。 これにより、O(1) メンバーシップ チェックが可能になります。 
3. 考えられるすべての値について`y`1 から c まで、配列内に存在する場合にのみ潜在的な約数として扱います。 
4. それぞれについて`y`、複数回繰り返します`x = y, 2y, 3y, ...`cまで。 各倍数は商に寄与します`x // y`。 
5. 計算された商はすべて配列内に存在する必要があります。 不足している商が見つかった場合、その配列は整数ではないとすぐに結論付けることができます。 
6. すべてのチェックを矛盾なく完了すると、配列は整数になります。 

重要な点は、構造化された方法で既存の値によって引き起こされる商をチェックするだけでよいということです。 複数の反復処理により、有効なフロア分割結果をすべてカバーしながら、冗長なペアの生成が回避されます。 

### なぜ効果があるのか

 x ≥ y であるすべての有効なペア (x, y) は、x = k・y + r、floor(x/y) = k として表すことができます。 y のすべての倍数を反復処理することで、y とより大きな要素の組み合わせから生じる可能性のあるすべての k を生成します。 したがって、必要な商が欠落している場合は、このスイープ中に検出されます。 周波数配列により、順序ではなく存在が正しく考慮されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, c = map(int, input().split())
        a = list(map(int, input().split()))

        freq = [0] * (c + 1)
        for x in a:
            freq[x] += 1

        ok = [False] * (c + 1)
        for i in range(1, c + 1):
            if freq[i]:
                ok[i] = True

        bad = False

        for y in range(1, c + 1):
            if not ok[y]:
                continue

            for x in range(y, c + 1, y):
                q = x // y
                if not ok[q]:
                    bad = True
                    break

            if bad:
                break

        print("No" if bad else "Yes")

if __name__ == "__main__":
    solve()
```このコードは、メンバーシップ チェックが定数時間になるように、まず入力をプレゼンス配列に圧縮します。 次に、配列内に実際に現れるすべての可能な約数候補 y に対して反復されます。 このような y ごとに、y のすべての倍数を調べて、結果として得られるすべての商が存在することを確認します。 早期終了により、違反が見つかった場合の効率が確保されます。 

主な微妙な点は、生のペアを反復処理しないことです。 代わりに、問題を倍数にわたる等差数列に再構成することで、二次関数の爆発が起こらずに確実にカバーできるようにします。

 x 値は商 1、2、3、4、5 を生成します。 ここでは 3 と 4 が欠落しているため、チェックはすぐに失敗します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(c log c) | 各値はその倍数にわたって反復されます。 
| スペース | O(c) | 存在と周波数の配列 |

 このアルゴリズムは、c までの各整数がすべての除数スイープにわたって最大で c/i 回の反復に参加し、調和級数の動作につながるため、効率的です。 これは制約内に快適に収まります。

 ## 特殊なケース

 重要なエッジ ケースは、配列に 1 が含まれる場合です。1 で除算されたすべての整数がそれ自体を生成するため、1 の存在により非常に強力な閉包条件が強制されます。つまり、すべての値が分割チェーンの下で自己一貫性を持つ必要があります。 y = 1 の場合、すべての倍数 x が商 x を生成し、チェックはクロージャ セットに含まれるすべての要素の存在を確認することになるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、配列に値が 1 つだけしかない場合です。 この場合、可能な商は 1 だけであり、これは値自体が 1 の場合にのみ有効です。スイープでは、特別なケースを使用せずにこれを正しく確認または拒否します。 

最後の重要なケースは、無関係な数値が混在する 2 のべき乗のような疎な配列です。 これらは、3、5、または 7 などの中間商が入力に存在しないにもかかわらず複数のスキャン中に出現するため、すぐに失敗し、非クロージャの早期検出が保証されます。
