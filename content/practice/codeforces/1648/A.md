 ## 解決策
 ## 問題の理解

 次のサイズの 2D グリッドが与えられます。$n \times m$ここで、各セルには整数で表される色が含まれています。 タスクは、同じ色を共有するすべてのセルのペア間のマンハッタン距離の合計を計算することです。 2 つのセル間のマンハッタン距離$(r_1, c_1)$そして$(r_2, c_2)$は$|r_1 - r_2| + |c_1 - c_2|$、あるセルから別のセルに移動するために必要な垂直方向と水平方向のステップ数をカウントします。 

入力は次のもので構成されます$n$行$m$それぞれ整数であり、セルの総数は 100,000 を超えません。 これは、セルのすべてのペアを直接反復するソリューションを用意できないことを意味します。$(10^5)^2 / 2 = 5 \cdot 10^9$2秒の制限時間を大幅に超えた操作。 線形または線形に近いアプローチが必要です。 

エッジ ケースには、すべてのセルが同じ色を持つグリッド、1 つの行または列のみを持つグリッド、または各セルが異なる色を持つグリッドが含まれます。 不注意な総当り的な方法では、すべてのペアの距離を盲目的に合計しようとしますが、最大の入力に対しては遅すぎます。 

## アプローチ

 単純なアプローチでは、各色を反復処理し、その色のすべての位置を収集し、すべてのペアのマンハッタン距離を合計します。 色が出たら$k$これには必要な場合があります$O(k^2)$色ごとの操作。 最悪の場合、100,000 個のセルすべてが同じ色である場合、このアプローチでは次のことが必要になります。$O(10^{10})$という操作が行われますが、これは非現実的です。 

重要な洞察は、マンハッタン距離が行と列の寄与に分離できるということです。$|r_1 - r_2| + |c_1 - c_2| = |r_1 - r_2| + |c_1 - c_2|$。 したがって、行と列の合計を個別に計算できます。 ある色のすべての行インデックスを並べ替えて累計を計算すると、行によって寄与される合計距離が出現回数に比例して線形時間で計算できます。 同じことが列インデックスにも当てはまります。 具体的には、ソート後、ポジションごとに$i$、以前のすべての位置までの合計距離は、$i \cdot \text{row}_i - \text{sum of previous rows}$。 これをすべての位置で合計すると、行の合計寄与率が得られ、列についても同様です。 

これにより、時間の複雑さが軽減されます。$O(k^2)$色ごとに$O(k \log k)$ソートプラス用$O(k)$合計の計算用。 すべての合計を考えると、$k$すべての色で最大 100,000 色なので、これは効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O((nm)^2) | O(nm) | 遅すぎる |
 | 最適 | O(nm log nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各色を 2 つのリスト (その色のすべての出現の行インデックスと列インデックス) にマッピングする辞書を作成します。 これにより、行と列の寄与が分離され、位置が色別に整理されます。 
2. 色ごとに、行インデックスのリストを並べ替えます。 距離の合計の式は順序付けられたシーケンスで機能するため、並べ替えが必要です。 
3. 行の距離の累計を初期化します。 ソートされた行インデックスを反復処理します。 現在のインデックスの場合$i$、 追加$i \cdot \text{row}_i - \text{sum of previous rows}$合計に。 これにより、次の合計が効率的に計算されます。$|r_i - r_j|$以前のすべての$j < i$線形時間で。 
4. 列インデックスに対してステップ 2 ～ 3 を繰り返し、同じ合計変数への寄与を合計します。 
5. すべての色を処理した後、累積合計を印刷します。 これは、同じ色のすべてのセルのペア間のマンハッタン距離の合計です。 

機能する理由: 行と列への分離は、マンハッタン距離の直線性を利用します。 並べ替えにより、累積差異を効率的に計算できるようになります。 式$i \cdot x_i - \text{sum of previous}$という観察から導き出されたものです$\sum_{j=0}^{i-1} |x_i - x_j| = i \cdot x_i - \sum_{j=0}^{i-1} x_j$ソートされたシーケンスの場合、すべてのペアが正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def main():
    n, m = map(int, input().split())
    color_positions = defaultdict(lambda: ([], []))  # maps color -> (rows, cols)
    
    for r in range(n):
        row = list(map(int, input().split()))
        for c, color in enumerate(row):
            color_positions[color][0].append(r)
            color_positions[color][1].append(c)
    
    total_sum = 0
    for rows, cols in color_positions.values():
        for indices in (rows, cols):
            indices.sort()
            acc = 0
            running_sum = 0
            for i, val in enumerate(indices):
                acc += i * val - running_sum
                running_sum += val
            total_sum += acc
    
    print(total_sum)

if __name__ == "__main__":
    main()
```ディクショナリは行インデックスと列インデックスを色ごとに個別に収集し、独立した合計計算を可能にします。 並べ替えると、数式が正しく適用されることが保証されます。`running_sum`各次元の前のインデックスの合計を累積するため、合計を繰り返し再計算する必要がなくなります。 この方法は、メモリや時間の制約を超えることなく、あらゆるサイズのグリッドとカラーを処理します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nm log nm) | 各色の行インデックスと列インデックスのソートが優先されます。 合計の計算は線形です。 |
 | スペース | O(nm) | 各色の位置を保存するには O(セル数) が必要です。 |
