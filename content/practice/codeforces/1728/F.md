 ## 解決策
 ## 問題の理解

 それぞれの漁師には魚のサイズがあります`a_i`。 私たちは彼らが話す順序を選びます。 

最初の漁師は実際の魚のサイズを言います。 その後のすべての漁師は、以前に発表された値より厳密に大きい自分の魚のサイズの最小倍数を言わなければなりません。 

発表された値は厳密に増加する順序を形成します。 私たちが制御できるのは順序だけであり、発表されたすべての値の合計ができるだけ小さくなるようにしたいと考えています。 

最初の有益な観察は、実際のスピーキングプロセスは見た目ほど重要ではないということです。 

漁師だと仮定してください`i`最終的には何らかの価値を発表する`x_i`。 各漁師は次の倍数しか発表できないため、`a_i`、 それぞれ`x_i`で割り切れる必要があります`a_i`。 発表される値の順序は厳密に増加しているため、発表されるすべての値は個別です。 

ここで視点を逆にします。 各漁師に魚のサイズの異なる倍数を割り当て、それらの割り当てられた値を徐々に並べ替えると、その並べ替えられた順序が有効な発話順序になります。 それは、以前に割り当てられた値より大きい利用可能な最小の倍数であるため、すべての漁師は実際に割り当てられた値を正確に発表します。 

したがって、問題は次のようになります。 

次の異なる倍数を 1 つ選択してください`a_i`すべての漁師に分配し、総額を最小限に抑えます。 

制約は非常に明らかです。 私たちはせいぜい`1000`漁師、魚のサイズは次のような大きさになることがあります。`10^6`。 値の数値の大きさに依存する解決策は、機能しない可能性があります。 アルゴリズムは主に次のものに依存する必要があります`n`。 

よくある間違いは、話す順番だけですべてが決まると考えることです。 考慮する：```
2
2 2
```発表された値を両方とも使用することはできません`2`。 ある漁師はこう言わなければなりません。`2`、相手は言わなければなりません`4`、したがって、答えは次のとおりです`6`。 

別の微妙なケースは次のとおりです。```
3
2 3 6
```現在利用可能な最小の倍数を常に使用する貪欲な戦略では、`2`、`3`、`6`。 これは実際には最適であり、合計が`11`。 しかし、次のようなことがあったとしたら:```
3
2 2 2
```3 つの異なる倍数が必要です。`2`、`4`、`6`、答えを与える`12`。 区別性こそが本当の制約なのです。 

最後の罠は、任意の大きな倍数が必要であると仮定していることです。 だけで`n`漁師の皆さん、漁師は自分の最初のことだけを考えればいいのです。`n`倍数。 ある漁師が自分の任務を割り当てられたとしたら、`(n+1)`-st 複数、その後彼の最初の 1 つ`n`複数ある場合、少なくとも 1 つは未使用になります。`n-1`他の漁師が価値観を占有している。 大きい倍数を未使用の小さい倍数で置き換えることで、ソリューションが改善されます。 

この観察により、問題は対処可能になります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 漁師のすべての順列を試し、発表された値をシミュレートし、最小値を維持します。 

固定順列の場合、シミュレーションは簡単です。 難しいのは、`n!`順列。 たとえ`n = 15`、これはすでに完全に実行不可能であり、実際の制限は`1000`。 

重要なステップは、漁業者への命令から発表された値の割り当てへと視点を変えることです。 

すべての漁師は、自分の魚のサイズの倍数である個別の値を受け取る必要があります。 これらの値が選択されると、発話順序が強制されます。つまり、選択した値を並べ替えます。 

したがって、順列はもう気にしません。 私たちは、すべての漁師に対して有効な値を 1 つ選択することに重点を置いています。 

最初だけなので`n`各魚のサイズの倍数が重要になる可能性があるため、すべての値を生成します```
a_i * 1, a_i * 2, ..., a_i * n
```そして重複を削除します。 

生成されたすべての値を 2 部グラフの左側のノードとして考え、すべてのフィッシャーマンを右側のノードとして考えます。 

値`v`漁師とつながっている`i`もし`v`で割り切れます`a_i`。 

個別に発表された値を選択することは、まさにすべての漁師をカバーするマッチングを選択することになります。 

残りの問題は、選択した値の合計を最小化する方法です。 

すべての値ノードには、その数値に等しいコストがあります。 値ノードを徐々に並べ替えた後、最小値から最大値の順に処理します。 値ノードを追加すると最大一致サイズが 1 つ増加するたびに、それを保持し、その値を答えに追加します。 

これは、横方向マトロイドにおける最小重量基準の古典的な貪欲な構造です。 操作上は、一連の Kuhn 拡張になります。 

結果は驚くほどコンパクトになりました。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | 最適なマッチング + 貪欲なランク構築 | O(V・E) | O(V + E) | 承認済み |

 ここ`V`個別の候補値の数、最大でも約`n²`。 

## アルゴリズムのチュートリアル

 1. すべての値を生成する`a_i * k`すべての漁師のために`i`そしてすべての`1 ≤ k ≤ n`。 
2. これらの値を並べ替えて重複を削除します。 
3. 2 部グラフを作成します。 

左側には、すべての個別の候補値が含まれます。 

右側には漁師がいます。 
4. すべての漁師のために`i`そしてあらゆる乗数`k`から`1`に`n`、値のインデックスを見つけます`a_i * k`ソートされた値リストで、その値ノードからフィッシャーマンにエッジを追加します`i`。 

値ノードは、魚のサイズがその値を分割する漁師に正確に接続されます。 
5. 値ノードを最小から最大まで処理します。 
6. 処理された値ノードと漁師の間の最大の一致を維持します。 
7. 新しい値ノードが検討されたら、その値ノードから開始して Kuhn 拡張を 1 つ実行します。 
8. 拡張が成功すると、最大一致サイズが 1 つ増加します。 このノードの数値を答えに追加します。 
9. すべての値ノードが処理されるまで続行します。 
10. 累計を出力します。 

### なぜ効果があるのか

 候補値は、横断マトロイドの基底セットを形成します。 値ノードのセットは、それらを使用できるフィッシャーマンがマッチングを認めた場合には独立しています。 

マトロイドの場合、最小重み基準は、要素を重みの昇順に処理し、ランクが増加するたびに要素を取得することによって取得されます。 

私たちのグラフでは、値ノードのセットのランクは、それらの値を使用して達成できる最大一致のサイズと正確に一致します。 

値を最小値から最大値に処理する場合、拡張が成功したということは、現在の値がランクを上げ、貪欲な最小重み基準に属している必要があることを意味します。 増強が失敗すると、ランクが上がらず、より安価な基盤を生み出すことができないことを意味します。 

基礎には最終的にサイズがあります`n`これは、すべての漁師が個別の有効な倍数と一致することを意味します。 貪欲なプロセスによって蓄積された合計は、まさに発表された値の可能な最小合計です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    vals = []
    for x in a:
        for k in range(1, n + 1):
            vals.append(x * k)

    vals = sorted(set(vals))
    m = len(vals)

    g = [[] for _ in range(m)]

    for i, x in enumerate(a):
        for k in range(1, n + 1):
            v = x * k
            idx = vals.index(v) if False else None

    pos = {v: i for i, v in enumerate(vals)}

    for i, x in enumerate(a):
        for k in range(1, n + 1):
            g[pos[x * k]].append(i)

    mt = [-1] * n
    used = [False] * m

    sys.setrecursionlimit(1 << 20)

    def kuhn(v):
        if used[v]:
            return False
        used[v] = True

        for to in g[v]:
            if mt[to] == -1 or kuhn(mt[to]):
                mt[to] = v
                return True

        return False

    ans = 0

    for v in range(m):
        used = [False] * m
        if kuhn(v):
            ans += vals[v]

    print(ans)

if __name__ == "__main__":
    solve()
```最初のブロックは、関連するすべての候補値を生成します。 最初だけ`n`倍数が必要なので、グラフは有限に保たれます。 

辞書`pos`実際の数値を、ソートされた候補リスト内の位置に変換します。 このマップがないと、二分探索や線形探索で繰り返し探索を行うと、不要なオーバーヘッドが追加されてしまいます。 

グラフは、値ノードからフィッシャーマンまで構築されます。 エッジとは、漁師がその値を発表された数値として使用できることを意味します。`mt[i]`現在フィッシャーマンに一致する値ノードを格納します`i`。 

Kuhn 検索では、新しく処理された値ノードをマッチングに挿入しようとします。 拡張パスが存在する場合、一致するサイズは 1 つ増加します。 

微妙なディテールがリセットされる`used`すべての拡張を試みる前に。 各 DFS には独自の訪問状態が必要です。 古いマークを再利用すると、有効な拡張パスが誤ってブロックされてしまいます。 

一致するサイズが大きくなると、答えは正確に増加します。 これらはまさに、貪欲なランク構築プロセスによって選択された値ノードです。 

Python の整数は、候補値がおおよその値に達する可能性があるため、考えられる最大の答えを簡単に処理できます。`10^9`要約すると次のようになります`1000`彼らのうち。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(VE) | 値ノードごとに 1 つの Kuhn オーグメンテーション |

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    vals = []
    for x in a:
        for k in range(1, n + 1):
            vals.append(x * k)

    vals = sorted(set(vals))
    pos = {v: i for i, v in enumerate(vals)}

    m = len(vals)
    g = [[] for _ in range(m)]

    for i, x in enumerate(a):
        for k in range(1, n + 1):
            g[pos[x * k]].append(i)

    mt = [-1] * n
    sys.setrecursionlimit(1 << 20)

    def kuhn(v, used):
        if used[v]:
            return False
        used[v] = True

        for to in g[v]:
            if mt[to] == -1 or kuhn(mt[to], used):
                mt[to] = v
                return True

        return False

    ans = 0

    for v in range(m):
        used = [False] * m
        if kuhn(v, used):
            ans += vals[v]

    return str(ans)

 ## 特殊なケース

 次のことを考慮してください。```
2
2 2
```グラフには値ノードが含まれています`2`そして`4`。 どちらの漁師もどちらの値も使用できます。 最初に成功した拡張には次の時間がかかります`2`。 2 番目に成功した拡張には次の時間がかかります`4`。 答えは次のようになります`6`。 

各漁師の最小倍数のみを考慮する不用意な解決策では、誤った結果が生じる可能性があります。`4`。 

ここで次のことを考えてみましょう。```
3
1 1 1
```唯一有効な個別の割り当ては次のとおりです。`1`、`2`、 そして`3`。 これら 3 つの値で一致が正確に増加し、答えが生成されます。`6`。 

これにより、魚のサイズを繰り返すと、より大きな倍数の使用が強制されることが検証されます。 

ついに：```
3
2 3 6
```候補値は次で始まります`2, 3, 4, 6, ...`。 

マッチングは次のように成長します`2`、 それから`3`、 それから`6`。 価値`4`一致するサイズは増加せず、スキップされます。 答えは`11`。 

これは、アルゴリズムの中心となる不変条件を示しています。値は、現在の 2 部マッチングのランクを増加させる場合にのみ、答えに寄与します。
