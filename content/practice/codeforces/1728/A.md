 ## 解決策
 ## 問題の理解

 いくつかのテストケースが与えられています。 各テスト ケースには数色のボールがあり、各色には特定の数のボールがあります。 すべての色のボールの合計数は奇数であることが保証されます。 

色の異なるボールを2つ選び、両方を袋から取り出すという操作を繰り返します。 この操作によりボールの総数が 2 つ減るため、総数のパリティは変わりません。 最初の合計は奇数であるため、すべての可能な動きを行った後、常にちょうど 1 つのボールが残って終了します。 

異なる色の 2 つのボールを選ぶことができなくなったときに、プロセスは停止します。これは、正確に、残りのボールがすべて同じ色の場合に起こります。 タスクは、有効な一連の操作の後に最終的に残る色を決定することです。 

重要な問題は、固定されたプロセスをシミュレートしているわけではないことです。 ペアを任意に選択することができ、選択が異なると最終的な色が異なる場合があります。 最後の生き残りとして表示できる 1 つの色を出力するだけで済みます。 

制約は十分小さいため、大規模な最適化は必要ありません。 各テスト ケースには最大 20 色があり、各カウントは最大 100 であるため、すべての色について推論したり、貪欲な削減をシミュレートしたりすることも可能です。 ただし、任意のペアリングの直接シミュレーションは依然として不必要であり、構造がわかりにくくなります。 

1 色のみの場合、微妙なエッジケースが表示されます。 その場合、まったく操作ができなくなり、答えは自明のこと、その色になります。 

もう 1 つの重要な状況は、1 つの色がすでに完全に優勢である場合です。 たとえば、ある色が他のすべての色を合わせたよりも多くのボールを持っている場合、すべての操作でその色からペアごとに最大 1 つが削除され、最終的には他のすべての色が最初に消えるため、その色が最後に生き残る必要があります。 

最も重要な隠された構造は、最終的な答えは、除去の順序ではなく、色が他の色とのすべてのキャンセルに耐えられるかどうかのみに依存するということです。 

## アプローチ

 ブルートフォース視点では、異なる色のボールのペアを削除するすべての可能なシーケンスをシミュレートしようとします。 各ステップは次のように分岐します。$O(n^2)$ペアの選択、そしてプロセスの深さは$O(\sum cnt_i)$。 境界が小さい場合でも、組み合わせが異なると中間構成が異なる可能性があるため、状態の数が指数関数的に爆発的に増加します。 

ただし、重要な観察は、各移動で 2 つの異なる色から 1 つのボールが削除されるため、基本的に異なる色間のカウントをキャンセルしていることです。 色が生き残る唯一の方法は、そのようなキャンセルによって完全に使い果たされない場合です。 

ペアリングは、2 つの異なるカウンターを繰り返し減らすことと考えてください。 少なくとも 2 つの色が正の値を維持している限り、2 つの異なる色から 1 つのユニットを削除し続けます。 このプロセスは、最大でも 1 つの色がゼロ以外のままになるまで続きます。 

重要な洞察は、最後に残る色は、他のすべての色と組み合わせても完全には除去できない色でなければならないということです。 同様に、色$i$他のすべての色が使い果たされずに使い果たされるように組み合わせを調整できれば、これが最後の色になる可能性があります$i$初め。 

これは、単純な貪欲な推論に帰着します。任意の色を選択し、それが最後の生き残りであると仮定した場合、選択した色を早期に使い果たすことなく、他のすべてのボールをその色または別の色と一致させることができなければなりません。 この設定では、他の色をできるだけ長く優先的に組み合わせることで、常にその除去を遅らせることができるため、正のカウントを持つ色は最終的に生き残ることができる可能性があることがわかります。 

したがって、問題は有効なカラー インデックスを選択することに集約されます。 このステートメントは存在を保証しているため、少なくとも 1 つのボールを持つ色は有効な答えになります。

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、色の数とカウントの配列を読み取ります。 
2. カウントのリストを調べて、カウントが 0 より大きいインデックスを選択します。 制約によりすべてのカウントが正であるため、最初のインデックスは常に有効です。 
3. そのインデックスをテスト ケースの回答として出力します。 

## なぜ機能するのか

 すべての操作で 2 つの異なる色から 1 つのボールが取り除かれるため、他の色と繰り返しペアにしない限り、どの色も消えることはありません。 ボールの総数は奇数であるため、プロセスはちょうど 1 つのボールが残った状態で終了する必要があります。 

どの時点でも、特定の色を最後に削除することを強制する制約はありません。 他のすべての色が十分に減らされるまで、その色を使い果たさないように組み合わせを選択することで、任意の色を保持できます。 最初は常にすべての色に少なくとも 1 つのボールがあり、自由にペアを選択できるため、選択した色が最後まで残るシーケンスをいつでも構築できます。 

この柔軟性は、有効な既存の色の選択以外に構造的な制限がないことを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    cnt = list(map(int, input().split()))
    print(cnt.index(max(cnt)) + 1)
```このソリューションは各テスト ケースを読み取り、最大頻度の色のインデックスを選択します。 正の数を持つ色はどれも有効であり、最大のものを選択することが安全な決定論的な選択であるため、これで十分です。 

の使用`max`に続く`index`これにより、テスト ケースごとに O(n) 時間で有効な生き残った候補が常に選択されるようになります。これは制約の下では自明です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        cnt = list(map(int, input().split()))
        out.append(str(cnt.index(max(cnt)) + 1))
    return "\n".join(out) + "\n"

# provided samples
assert run("""3
3
1 1 1
1
9
2
4 7
""") == """3
1
2
"""

# all equal small case
assert run("""1
4
1 1 1 1
""") in ["1\n", "2\n", "3\n", "4\n"]

# single color
assert run("""1
1
10
""") == "1\n"

# dominant color
assert run("""1
3
1 100 1
""") == "2\n"

# boundary mix
assert run("""1
5
2 1 1 1 1
""") == "1\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて等しい | 任意のインデックス | 対称性とタイの処理 |
 | 単色 | 1 | 移動しない場合 |

 ## 特殊なケース

 色が 1 つしかない場合、それが唯一の利用可能な選択肢であるため、アルゴリズムは直ちにインデックス 1 を返します。 操作は不可能であり、これはプロセスが即座に停止するというルールに一致します。 

すべての色のカウントが等しい場合、すべてのインデックスは同様に有効です。 アルゴリズムは一貫して最初の最大値を選択します。これは、残りの 1 つが残るまで異なる色を組み合わせることでどのような選択も実現できるため、最終的な正しい色として考えられます。 

たとえば、1 つの色が厳密に優勢な場合`[1, 100, 1]`、アルゴリズムは支配的な色を選択します。 この状況では、他の色がクロスペアリングによって最初に使い果たされる可能性があるため、有効な削除シーケンスは自然に最後までその色を保持します。
