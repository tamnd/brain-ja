 ## 解決策
 ## 問題の理解

 小さな数字のグリッドが与えられます。 このグリッドからは、行全体または列全体を繰り返し削除できます。 削除するたびに、その行または列のすべての値が永久に削除され、テーブルの残りの部分はそのまま残ります。 

一連の削除の後の最終結果は常に、行のサブセットと列のサブセットを選択し、それらの交差部分を正確に維持することによって形成される長方形の部分行列になります。 最終的な構造では削除の順序は重要ではなく、どの行と列が残るかだけが重要です。 

タスクは、残りのすべてのセルの合計がターゲット値と等しくなるような、生き残る行と列の選択肢があるかどうかを判断し、存在する場合は、それを達成する一連の削除を出力することです。 

グリッド サイズは最大 15 x 15 なので、セルの数は最大 225 です。 これは、行と列に対する指数推論が受け入れられることを直ちに示唆しています。 すべての部分集合を独立して試行する解決策は、すでに実現可能に近づいていますが、注意が必要です。すべての部分行列の単純な列挙は約 2^(30) であり、直接実行すると大きすぎます。 

重要な構造上の制約は、要素の順序を変更したり、行や列を部分的に削除したりしないことです。 これは、最終的な形状が、選択された行と選択された列という 2 つの独立したサブセットによって完全に決定されることを意味します。 

すべての数値が大きいにもかかわらず、ターゲットの合計が小さい場合、微妙なエッジ ケースが発生します。 たとえば、すべてのセルが正で、行の最小合計がすでに s より大きい場合、解は存在しません。 「より多くの削除が常に役立つ」と仮定する素朴なアプローチでも、行を削除すると交差する列からの寄与もすべて削除されることを考慮する必要があるため、完全な行/列のサブセットに関して明示的に推論しない限り、部分的な直観は失敗する可能性があります。 

もう 1 つの特殊なケースは、s が行列の合計に等しい場合です。 この場合、削除は必要なく、答えは明らかに操作がゼロになります。 

最後に、すべての値がゼロであるケースは退化しています。どの部分行列も合計がゼロであるため、行と列の空でない選択は、空でない限り有効です。 

## アプローチ

 中心的な観察は、行のセット R と列のセット C を選択し、i が R にあり、j が C にあるすべてのセル (i, j) を正確に保持することによって、最終的なテーブルが完全に決定されるということです。 したがって、合計は次のようになります。 

sum(R, C) = R のすべての i、C の j にわたる A[i][j] の合計。 

ブルートフォース手法では、行のすべてのサブセットと列のすべてのサブセットを列挙し、各ペアの合計を計算し、それが s に等しいかどうかを確認します。 2^h 行のサブセットと 2^w 列のサブセットがあり、約 2^(h+w) 個の状態 (最大 2^30) が得られます。 各合計の計算には O(hw) のコストがかかるため、非常に遅くなります。 

重要な単純化は視点を逆転させることです。行と列を同時に選択する代わりに、一方を修正してもう一方を解決できます。 行 R の固定サブセットの場合、各列は独立してそれらの行の列合計に寄与します。 R が固定されたら、重み (これらの列の合計) が s に達する必要がある列のサブセットを選択します。 これは、最大 15 要素にわたる標準的なサブセット合計問題です。 

これにより、問題は 2 レベルの検索に変換されます。行のサブセットを列挙し、誘導された列の重みを計算して、列のサブセットの合計を解決します。 w ≤ 15 であるため、行サブセットごとのサブセット合計は O(w 2^w) で実現可能であり、全体としては O(h 2^h w 2^w) となり、これは十分に制限内にあります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | (R, C) に対するブルート フォース | O(2^(h+w) · hw) | お(1) | 遅すぎる |
 | 行サブセット + 列サブセットの合計 | O(h 2^h + h w 2^w) | O(w 2^w) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 行のサブセットの列合計を事前計算します。 各行サブセット R に対して、R 内の行に制限された列 j の合計を格納する配列 ColSum[j] を構築します。これにより、2D 選択問題が列にわたる 1D 重み付き選択問題に縮小されます。 
2. 選択した行サブセット R について、colSum を介して暗黙的に、選択したすべてのセルの基本合計の合計を計算します。 
3. C の j にわたるcolSum[j] の合計が s に等しくなるような列 C のサブセットが存在するかどうかを解きます。 これは最大 15 項目にわたる標準的なサブセット合計であるため、列のビットマスク列挙を使用できます。 
4. そのような列サブセットが存在する場合、ソリューションを再構築します。R にない行は削除され、C にない列は削除されます。 削除の順序は重要ではありませんが、インデックスが元のテーブル番号付けに従っていることを尊重する必要があります。 
5. 削除を任意の有効な順序で出力します。通常は、最初に R にないすべての行、または最初に C にない列を削除します。 

これが機能する理由: すべての有効な最終構成はペア (R、C) に一意に対応します。 逆に、そのようなすべてのペアは、補数の行と列を削除することによって到達可能な構成に対応します。 このアルゴリズムは、考えられるすべての R と、それぞれについて考えられるすべての誘導列サブセット C を探索し、構造的な可能性を見逃すことなく、探索空間全体にわたる完全性を保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    h, w = map(int, input().split())
    a = [list(map(int, input().split())) for _ in range(h)]
    s = int(input())

    # Precompute all row masks
    H = h
    W = w

    # Precompute row bit contributions per column for each row subset
    # col_sum[mask][j] = sum over i in mask of a[i][j]
    col_sum = [[0] * w for _ in range(1 << h)]

    for mask in range(1 << h):
        if mask == 0:
            continue
        lb = mask & -mask
        i = (lb.bit_length() - 1)
        prev = mask ^ lb
        if prev == 0:
            for j in range(w):
                col_sum[mask][j] = a[i][j]
        else:
            for j in range(w):
                col_sum[mask][j] = col_sum[prev][j] + a[i][j]

    full_rows = (1 << h) - 1

    for rmask in range(1 << h):
        cols = col_sum[rmask]

        for cmask in range(1 << w):
            total = 0
            for j in range(w):
                if cmask >> j & 1:
                    total += cols[j]

            if total == s:
                # reconstruct operations
                print("YES")
                ops = []

                # delete rows not in rmask
                for i in range(h):
                    if not (rmask >> i & 1):
                        ops.append((1, i + 1))

                # delete columns not in cmask
                for j in range(w):
                    if not (cmask >> j & 1):
                        ops.append((2, j + 1))

                print(len(ops))
                for t, idx in ops:
                    print(t, idx)
                return

    print("NO")

if __name__ == "__main__":
    solve()
```実装は行マスク列挙戦略に直接に従います。 の`col_sum[mask][j]`テーブルは標準のサブセット DP トリックを使用して構築されます。各マスクはその最下位ビットとより小さいサブマスクに分解され、各状態が 1 回計算されることが保証されます。 

行のサブセットを修正した後、各列を単一の集計された重みとして扱います。 次に、すべての列サブセットを列挙し、それらの合計を計算します。 w ≤ 15 では 2^w 演算が許容されるため、これは列に対する意図的な総当たり攻撃です。 

再構築は簡単です。選択されていないすべての行と選択されていないすべての列の削除を出力します。 この問題では任意の順序が許可されるため、単純に順番にリストします。 

一般的な実装の落とし穴は、行マスクごとに列の合計を最初から再計算することです。これは h の余分な係数を追加することになり、不要ですが、それでも合格する可能性があります。 DP の最適化により、クリーンで一貫性のある状態が保たれます。 

## 実用的な例

 ### 例 1

 入力:```
3 3
1 2 3
2 3 1
3 1 2
8
```行マスクを列挙します。 まずフルマスクを検討してください。 

| 行マスク | 列の合計 | 列のサブセット | 合計 |
 | --- | --- | --- | --- |
 | 111 | [6,6,6] | 001 または 010 など | 6 または 12 など |
 | 110 | [3,5,4] | 001 + 010 | 8 |

 行マスク 110 (最初の 2 行を保持) の場合、列の合計は [3,5,4] になります。 列 1 と 2 を選択すると、3 + 5 = 8 となります。 

次に、行 3 と列 3 を削除して、正しい構成を生成します。 

### 例 2

 入力:```
2 3
2 2 2
2 2 2
5
```すべての行サブセットは 2 の倍数の列合計を生成します。したがって、すべての列サブセット合計も偶数になります。 目標5は無理です。 

アルゴリズムは引き続きすべてのマスクをチェックしますが、一致するものが見つからないため、NO を返します。

 ## 特殊なケース

 単一セルのグリッドは最もきれいな境界です。 A[1][1] が s に等しい場合、アルゴリズムは rmask = 1 および cmask = 1 を検出し、すぐに戻ります。 そうでない場合は、一致するサブセットがないため、結果は NO になります。 

フルゼロ行列は、多くのマスクが同じ合計を生成することを強調します。 アルゴリズムは引き続きすべての行と列のサブセットを列挙しますが、すべての構成は 0 と評価されるため、s=0 のみが成功します。 

s が合計に等しい場合、 rmask = full および cmask = full がトリガーされます。 アルゴリズムは列挙の早い段階でこれを検出し、削除を出力しません。これは、空の操作シーケンスが許可されるため有効です。
