 ## 解決策
 ## 問題の理解

 1 から 1 までの整数の順列が与えられます。$n$、そして特定の部分配列が特別な並べ替えルールに従って「完璧」であるかどうかについての複数のクエリに答える必要があります。 各部分配列は、隣接する要素を交換する、または 2 つの位置離れた要素を交換するという 2 つのタイプの操作を使用してソートできますが、2 番目のタイプは 1 回しか使用できません。 この 1 つの特別なスワップを許可しても、隣接するスワップのみを使用する場合と比較して総操作数が減らない場合、サブ配列は完璧です。 本質的には、正確に 2 つの位置で「順序が狂っていて、シングル ダブル スワップの恩恵を受ける要素のペアが部分配列に含まれているかどうかを確認する必要があります。」

 順列プロパティにより分析が簡素化されます。 要素は一意であり、1 から 2 までの範囲であるため、$n$、各値は、完全にソートされた配列内で一意の位置を持ちます。 これは、重複を気にするのではなく、値の相対的な順序に焦点を当てることができることを意味します。 

制約が示すのは、$n$それぞれが到達できるクエリの総数$5 \cdot 10^5$。 これにより、次のようなアルゴリズムが除外されます。$O(n^2)$クエリごとの操作、またはサブ配列ごとのスワップのシミュレーションを簡単に実行できるため、$10^{11}$操作。 線形前処理と定数時間または対数時間のクエリ評価を備えたソリューションが必要です。 

サブ配列がすでにソートされているか、要素が 1 つしかない場合、微妙なエッジ ケースが発生します。 このような場合、ダブルスワップには何の利点も得られず、サブアレイは自明のことながら完璧です。 逆に、最大要素と最小要素が遠く離れているが、1 回のダブル スワップで並べ替えることができるシーケンスによって分離されている部分配列は不完全になります。 

## アプローチ

 ブルートフォースアプローチでは、最初に隣接するスワップのみを取得して、各サブ配列のソートをシミュレートしようとします。$g(b)$、その後、オプションのダブル スワップを 1 つ使用して、$f(b)$。 たとえば、反転を数えて最小の隣接スワップを決定することができます。 ただし、クエリごとに反転を個別にカウントすることは困難です。$O(n \log n)$、多くのクエリを合計すると遅すぎます。 

重要な観察は、特別なスワップが何を行うかを分析することから得られます。 インデックスでのダブルスワップ$i$位置間の反転のみを修正できます$i$そして$i+2$。 サブ配列内にそのような反転が存在しない場合、そのサブ配列は完全です。 したがって、スワップをシミュレートする代わりに、要素が連続して 1 ずつ増加する位置と、要素がダブル スワップに必要な順序を「破る」位置を事前計算できます。 具体的には、一番左のインデックスを追跡します$i$どこ$a[i] > a[i+2]$元の配列で。 次に、クエリごとに、クエリ範囲内にそのような違反が存在するかどうかを確認するだけで済みます。 何もなければ、サブ配列は完全です。 

この観察により、各クエリのチェックが次のように削減されます。$O(1)$「違反」を前処理した後、配列全体にわたって線形時間で実行できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (スワップをシミュレート) | O(q * n log n) | O(n) | 遅すぎる |
 | 最適 (違反の事前計算、範囲のチェック) | O(n + q) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ダブルスワップが厳密に役立つポジションを事前計算します。 配列を反復処理し、すべてのインデックスをマークします$i$そのような$a[i] > a[i+2]$。 これらは、隣接するスワップのみを使用する場合と比較して、単一のダブル スワップによって操作の総数を削減できる唯一の位置です。 
2. これらのマークされた位置のプレフィックス最大配列を構築します。 インデックスごとに、配列にはその時点までの「違反」の右端の位置が格納されます。 これにより、クエリされた範囲に違反が存在するかどうかを効率的にチェックできます。 
3. クエリごとに$[l, r]$、内に違反があるかどうかを確認します。$l$に$r-2$ダブルスワップには 2 つのステップが含まれるためです。 この間隔の最大違反が次の値より大きい場合$r-2$の場合、範囲内には有用なダブルスワップがないため、サブ配列は完璧です。 そうでなければ、それは不完全です。 
4. 完璧な場合は「YES」、そうでない場合は「NO」を出力します。 

機能する理由: このアルゴリズムは、ダブル スワップが 2 つ離れた要素にのみ影響するという事実に依存します。 ダブルスワップが有利となるポジションを正確にマークすることで、以下のすべてのケースを捕捉します。$f(b) < g(b)$。 サブ配列内にそのような位置が存在しない場合は、$f(b) = g(b)$そしてサブアレイは完璧です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        a = list(map(int, input().split()))
        
        # violation[i] = 1 if a[i] > a[i+2], else 0
        violation = [0] * n
        for i in range(n - 2):
            if a[i] > a[i+2]:
                violation[i] = 1
        
        # prefix max of violations
        pref = [0] * n
        for i in range(n):
            pref[i] = violation[i] if i < n else 0
            if i > 0:
                pref[i] = max(pref[i], pref[i-1])
        
        for _ in range(q):
            l, r = map(int, input().split())
            l -= 1
            r -= 1
            if l >= r - 1:
                print("YES")
            else:
                if pref[r-2] - (pref[l-1] if l > 0 else 0) > 0:
                    print("NO")
                else:
                    print("YES")

if __name__ == "__main__":
    main()
```コードはまず、ダブル スワップが役立つ位置を計算します。 次に、プレフィックス最大配列を構築して、クエリにこれらの位置のいずれかが含まれているかどうかをすばやく確認します。 1 つまたは 2 つの要素を含むクエリは、言うまでもなく完璧です。 長いクエリの場合は、プレフィックス配列をチェックして、サブ配列内に違反があるかどうかを確認します。 

境界条件は重要です:$a[i] > a[i+2]$、最後の 2 つのインデックスは違反に関与しません。 プレフィックスの計算では、ゼロベースのインデックス付けを考慮する必要があります。
