 ## 解決策
 ## 問題の理解

 係数が指定された基数より厳密に小さい非負の整数である多項式を構築するように求められます。$k$、この多項式を次のように割ると、$x + k$、剰余は正確に定数多項式です$p$。 

で割る$x + k$は、多項式を次のように評価すると、$x = -k$、値は等しい必要があります$p$剰余定理により、除算の剰余は次のようになります。$x + k$は$f(-k)$。 したがって、このタスクは有限の数字列を構築することと同じです。$a_0, a_1, \dots, a_{d-1}$基地内で$k$- のような制約。各桁がどこにあるか$[0, k-1]$、およびそれらの符号付き加重和$$f(-k) = a_0 - a_1 k + a_2 k^2 - a_3 k^3 + \dots$$等しい必要があります$p$。 

係数を負にすることはできないため、交互の塩基を直接表すことはできません。$k$の拡大$p$持ち運ばずに。 課題は、すべての桁を範囲内に保ちながら、符号付き基本表現をシミュレートすることです。$[0, k-1]$。 

制約は非常に厳しいです。$p \le 10^{18}$そして$k \le 2000$。 どのような解でも、生成される桁数は基本的に線形である必要があります。$O(\log p)$は許容されますが、数値構成における二次関数はすべて合格します。 本当の難しさは計算の複雑さではなく、係数の範囲に違反することなく有効な桁システムを確保することです。 

素朴な試みは拡大することです$p$基地内で$k$直接係数を貪欲に割り当てます。 これは、次の評価によって符号が交互に切り替わるため失敗します。$-k$。 たとえば、最下位から順に次のように設定します。$p \bmod k$は、より高いべき乗が加算ではなく減算することを無視します。これにより、正確性が直ちに失われます。 

2 番目の障害モードは、交互の符号間でキャリーが対称的に処理されない場合に発生します。 たとえば、奇数の位置で負の寄与となるように意図された桁を、上位の項に影響を与えずに単純にゼロに設定したり、局所的に削減したりすることはできません。 

## アプローチ

 ブルートフォースアプローチでは、評価された多項式の正確な値を維持しながら、係数を 1 つずつ構築しようとします。$-k$。 各位置で、次のすべての可能な数字を試します。$0$に$k-1$そして残りの目標値を再帰的に調整します。 分岐要因が次のとおりであるため、これはすぐに実行不可能になります。$k$、深さは最大に達することができます$O(\log_k p)$、指数関数的な爆発につながります。 

重要な観察は、次のような多項式評価が行われることです。$-k$符号が交互になる混合基数体系のように動作します。 これは、最低次数から上位に向かって貪欲に数字を構築できることを示唆していますが、符号の交替を吸収する実行中の「キャリー」を注意深く管理する必要があります。 

ステップで$i$、係数を決定します$a_i$。 価値への貢献度は、$a_i \cdot (-k)^i$。 交互の符号を直接操作する代わりに、現在の剰余を維持し、次のように割り算を強制します。$k$各ステップで調整しますが、位置のパリティによって符号が反転したときに残りを調整します。 

重要な洞察は、選択した後、$a_i$、残りのターゲットは次の整数倍のままである必要があります。$k$、より高いべき力があるため、$x$のより高次のべき乗に対応する$k$規模的には。 これにより、基数変換と同様の決定論的な数字抽出プロセスが強制されますが、奇数の位置では完全な値を効果的に追加することで負の寄与を補正する点が異なります。$k$-分割の前にブロックします。 

これにより、問題は、符号付き基本システムにおける制御された数字の構成に変換されます。

 ## アルゴリズムのチュートリアル

 より高次の項によって一致する必要があるものを表す現在の残差値を維持しながら、次数 0 から上に向かって係数を構築します。 

1. 現在の値から開始します$p$そして係数の空のリスト。 

この値を、多項式で表現されるべきものとして解釈します。 
2. ポジションごとに$i = 0, 1, 2, \dots$、係数を決定します$a_i$。 

偶数の位置では、寄与はプラスになります。 奇数の位置では負になります。 この符号の変更により、数字を抽出する方法が決まります。 
3. もし$i$は偶数です、設定します$$a_i = p \bmod k$$この位置はベースにプラスに貢献するため、$k$っぽい展開。 
4. もし$i$は奇数であるため、負の符号を補正する必要があります。 私たちは計算します$$a_i = (k - (p \bmod k)) \bmod k$$これにより、減算後は次のようになります。$a_i \cdot k^i$、余りは次で割り切れます。$k$一貫した方法で。 
5. 選択した桁の寄与を減算し、で割ることにより、残りの値を更新します。$k$、慎重に符号を調整します。 
6. 残りの値がゼロになるまで繰り返します。 
7. 係数リストの末尾のゼロを削除し、最大の係数がゼロ以外になるようにします。 

このプロセスが終了する理由は、各ステップで残りの値の大きさがおよそ 1 分の 1 に減少するためです。$k$、標準の基底変換に似ていますが、交互の補正が行われます。 

### なぜ効果があるのか

 各ステップで、選択した係数を減算した後の残差値が次の値で割り切れることを強制します。$k$。 これにより、高次の係数が部分的な干渉なしに残りの値を表現できることが保証されます。 交互補正により、奇数のインデックスでの負の寄与が常に桁範囲内で補償されるようになります。$[0, k-1]$したがって、無効な係数が生成されることはありません。 維持される不変条件は、残りの値が常に、高次項が有効な符号付き基底でエンコードする必要があるものに正確に対応するということです。$k$表現。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    p, k = map(int, input().split())

    coeffs = []

    x = p
    i = 0

    while x != 0:
        if i % 2 == 0:
            a = x % k
            x = (x - a) // k
        else:
            # adjust so that remainder division works with negative sign
            a = (-x) % k
            x = (x + a) // k

        coeffs.append(a)
        i += 1

    if not coeffs:
        print(-1)
        return

    while len(coeffs) > 1 and coeffs[-1] == 0:
        coeffs.pop()

    print(len(coeffs))
    print(*coeffs)

if __name__ == "__main__":
    solve()
```この実装は、交互桁抽出に直接続きます。 重要な微妙な点は、奇数インデックスの処理であり、残差を次で割り切れる形式に変換します。$k$マイナス寄与分を調整後。 整数の除算は選択された係数の構築によって正確に行われるため、浮動小数点の問題は発生しません。 

最上位の係数はゼロ以外でなければならないため、トリミング ステップにより、不必要な先行ゼロが出力されないことが保証されます。

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。$p$はすでにゼロです。 この状況では、アルゴリズムはループに入らず、空の係数リストを出力します。 正しい解釈は、ゼロ多項式を超える多項式は必要ないということですが、この問題では、ゼロ以外の最大係数を持つ有効な表現が必要です。 実装はこれを印刷することで処理します。$-1$空の建設用。 

もう 1 つのエッジ ケースは、小さなエラーが原因で繰り返されるキャリーが多くのレベルに伝播するときに発生します。$k$、 のような$k = 2$。 たとえば、次の 2 の大きなべき乗$p$長い交互調整を作成します。 アルゴリズムは引き続き各ビットを 1 回だけ処理し、不変式は$x$で割り切れるようになる$k$各ステップの後で、無限ループや精度の問題が発生しないようにします。
