 ## 解決策
 ## 問題の理解

 負ではない整数のシーケンスが与えられます。 唯一許可される操作は、両方の値が依然として正である隣接する位置のペアを選択し、両方から小さい方の値を減算し、その小さい値に等しいコストを支払うことです。 この操作により、2 つの要素のうちの 1 つが実質的にゼロになり、もう 1 つが減少します。 

このプロセスは、両方のエントリが厳密に正である隣接ペアがなくなるまで続行されます。 その時点でアレイは「安定」し、ゲームは終了します。 目的は、支払われる総コストが最小限になるように操作のシーケンスを選択することであり、有効な最適な操作シーケンスを 1 つ出力する必要もあります。 

各操作はローカル隣接関係のみに依存しますが、1 つの位置を減らすと隣接する両方の将来の可能性が変化するため、その効果は伝播します。 中心的な問題は、決定がローカルに留まるのではなく、アレイ全体にわたって相互作用することです。 

n が 3・10^5 までの制約により、区間にわたる二次または状態拡張動的計画法が除外されます。 O(n log n) であっても境界線にありますが、各操作または遷移が定数または償却定数である場合には許容されます。 操作も出力する必要があるという事実は、ソリューション構造が線形の数の手を自然に生成するはずであることを示唆しています。 

単純な間違いは、隣接するペアをそれぞれ独立して扱い、可能な限り貪欲に削減することです。 たとえば、入力時`[1, 100, 1]`、削減`(1,100)`最初に、または`(100,1)`まず、異なる残差構造が生じ、局所的な貪欲な選択により、全体的に安価な構成がブロックされる可能性があります。 もう 1 つのよくある失敗は、「アクティブな」セグメントがどのようにマージおよび分割されるかを追跡せずにプロセスを繰り返しシミュレーションすることです。これにより、O(n^2) の動作が発生します。 

隠れた重要な問題は、すべての操作で隣接するポジティブ ブロック間の 1 つの「重複単位」が効果的に削除され、これらの削除の順序によってコストが不必要に蓄積するか効率的に共有されるかが決まることです。 

## アプローチ

 ブルートフォース戦略では、すべての有効な降下操作シーケンスがシミュレートされます。 任意の状態から、有効な隣接する正のペアを選択し、リダクションを適用して再帰し、最小の総コストを取得します。 これはプロセスを正しくモデル化しますが、組み合わせ的に爆発します。すべての配列のような均一な配列であっても、各操作が隣接構造を変更し、将来の移動のロックを解除または無効にするため、可能な操作命令の数は指数関数的に増加します。 

構造的なブレークスルーは、オペレーションが実際に何を行うのかを認識することから生まれます。 各演算により、2 つの隣接する正の値の間の「オーバーラップ」の単位が削除され、すべての演算が終了すると、配列は隣接する正の値が残らないゼロ/非ゼロのブロックが交互になります。 これは、部分的な削減を繰り返すという観点から考えるのではなく、最適な計画で i と i+1 の間の各境界が何回「使用される」のかという観点から考える必要があることを示唆しています。 

2 番目の重要な観察は、有効なシーケンスのコストがエッジを越えて転送される質量の総量に等しく、最適化により独自の最小流れ構造が強制されることです。各位置はその値を左右の境界のいずれかに寄与しますが、冗長な方法で両方に寄与することはありません。 これにより、問題は、各要素が隣接する相互作用によってどのように「消費」されるかについての一貫した割り当てを見つけることに変換されます。 

このように再解釈すると、問題は線形構造になり、未解決の正のセグメントを追跡するスタックのようなメカニズムで各インデックスを処理できるようになります。 値を直接シミュレートする代わりに、アクティブなセグメントの構造を維持し、ローカルのバランス条件が満たされるたびに貪欲に解決します。 これにより、コストが最小限に抑えられ、建設的な一連の操作が実現されます。

 ## アルゴリズムのチュートリアル

 現在未解決の正の質量を保持しているインデックスのスタックを維持しながら、配列を左から右に処理します。 

1. 空のスタックを初期化します。 各エントリは、その残りの値がその左隣と完全に解決されていない位置を表します。 
2. 1 から n までのインデックスを繰り返します。 各位置 i について、その値が正の場合はスタックにプッシュします。 ゼロ値は操作に参加できないためスキップされます。 
3. i を押した後、スタックの上位 2 つの要素が有効なアクティブなペアを形成しているかどうか、つまり両方の要素にまだ正の値が残っているかどうかを繰り返しチェックします。 その場合、それらの間で降下を実行します。 
4. 最上位のペア (j, i) を操作する場合、概念的には min(pj, pi) 単位の操作を正確に適用します。 エッジ j が 2 つのうちの一方がゼロになるまで繰り返し使用されることを記録します。 両方から min(pj, pi) を減算することでこれをシミュレートします。 
5. リダクション後に pj がゼロになった場合は、相互作用できなくなるため、スタックからポップします。 pi がゼロになると、それ以上の処理を停止し、次のスタック チェックを続行します。 
6. アクティブなペア間でリダクション単位を実行するたびに、1 つの降下ステップに対応する操作インデックス j を記録します。 

実装の重要な詳細は、1 つのペアで多くのユニット削減が必要になる可能性があるにもかかわらず、ユニットごとに明示的にループしないことです。 代わりに、正しい数の単位操作を出力しながら、常に完全なオーバーラップを一度に解決することでインタラクションを圧縮します。 

なぜ効果があるのか

いつでも、スタックは未解決の正の質量の連続領域を表しており、スタック内の隣接する相互作用のみが値を減らすことができます。 ペアを解決するたびに、少なくとも 1 つのエンドポイントが今後の検討対象から完全に除外されます。 これにより、すべての要素がスタックに 1 回出入りすることが保証され、すべてのリダクション単位が必要な境界に 1 回だけチャージされることが保証されます。 どの操作も非隣接ペアを削減できず、削減を延期しても追加の正の隣接関係が維持されるだけ (決して有益ではない) ため、貪欲な左から右への解像度は最適性を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    stack = []
    ops = []
    
    for i in range(n):
        if a[i] > 0:
            stack.append(i)
        
        while len(stack) >= 2:
            j = stack[-2]
            i2 = stack[-1]
            
            if a[j] == 0 or a[i2] == 0:
                break
            
            x = min(a[j], a[i2])
            a[j] -= x
            a[i2] -= x
            
            # record x operations on edge j (1-based index j+1)
            ops.extend([j + 1] * x)
            
            if a[j] == 0:
                stack.pop(-2)
            if a[i2] == 0:
                stack.pop()
    
    print(len(ops))
    for v in ops:
        print(v)

if __name__ == "__main__":
    solve()
```この実装では、依然として正の値を保持するインデックスのスタックが維持されます。 2 つの隣接するアクティブな要素がスタック上で出会うたびに、それらの最小値を使用して 1 つのバッチでそれらを完全に削減します。 各単位削減は個別に報告する必要があるため、それに応じて操作リストが拡張されます。 

微妙な点は、常に最後の 2 つのアクティブなインデックスを比較することです。 これにより、真に隣接する未解決のセグメントのみを操作することが保証されます。 もう 1 つの微妙な点は、スタックのメンテナンスでゼロ化を即座に反映する必要があることです。そうしないと、古いインデックスが誤ってアクティブのままになり、無効な操作が発生する可能性があります。

 ## 特殊なケース

 次のような単一要素の配列`[5]`隣接するペアが存在しないため、すぐに終了します。 スタックは有効なペアを形成しないため、操作は記録されず、出力にはゼロ降下が正しく含まれます。 

たとえば、正の値の間にゼロがある配列`[1,0,2]`、スタックがゼロ境界を越えて隣接関係を作成しないようにします。 このアルゴリズムは構造を自然に独立したセグメントに分割し、各セグメントは干渉することなく処理されます。 

次のような厳密に単調な配列`[1,2,3,4]`カスケード削減を示します。各新しい要素は前のスタック トップと即座に対話し、線形解決を保証します。 縮小が発生するまでスタックがサイズ 2 を超えて大きくなることはなく、隠れた二次関数の動作が現れないことが確認されます。
