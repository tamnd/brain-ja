 ## 解決策
 ## 問題の理解

 1 と 2 の 2 つの値を一列に並べてのみ構成されるシーケンスが与えられます。 このシーケンスの単一の連続セグメントを選択し、それを反転して、この操作後に非減少サブシーケンスがどのくらい長くなるかを測定することができます。 反転できるすべての可能なセグメントの中で、そのようなサブシーケンスの可能な最大長が必要です。 

重要な点は、バイナリ配列上の非減少サブシーケンスは、単純に、いくつかの 1 の後にいくつかの 2 が続くシーケンスであるということです。 サブシーケンス内では 1 の前に 2 を出現させることはできないため、構造は 2 に切り替える前に 1 をいくつ選択できるかによって完全に決まります。 

入力サイズは最大 2000 で、単純に実装した場合、すべての反転選択肢と組み合わせたすべての可能なサブシーケンスに対する三次探索が即座に除外されます。 すべての O(n²) セグメントを試し、O(n) または O(n log n) で LIS を再計算するブルート フォースは、実際には遅すぎます。 これにより、構造を慎重に再利用することで、せいぜい O(n²) または O(n² log n) の解が得られます。 

逆にすると多くの要素の相対的な順序が変更されるが、実際には最良のサブシーケンスが改善されない場合、微妙なエッジ ケースが発生します。 たとえば、配列がすでに次のようにソートされている場合、`[1,1,1,2,2]`あらゆるセグメントを反転しても構造が乱れるだけで、答えは 5 のままです。すべての反転が役立つと想定する単純なアプローチでは、反転後に LIS を正しく再計算しないと改善が過大評価される可能性があります。 

もう 1 つの重要なケースは、最適なセグメントが事実上空である場合です。つまり、最善の戦略は有用なものを何も元に戻さないことです。 正しい解決策を得るには、常に元の配列も考慮する必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。インデックス l と r の可能なすべてのペアを試し、そのセグメントを反転し、結果の配列の最長の非減少サブシーケンスを計算します。 バイナリ配列での LIS の計算は、取得できる 1 と 2 の数をスキャンして追跡することで O(n) で実行できますが、O(n²) 個のセグメントに対してこれを実行すると、O(n³) 時間、つまり n = 2000 で約 80 億回の演算が必要となり、遅すぎます。 

重要な観察は、実際には反転のたびに LIS 全体を最初から再計算する必要がないということです。 値は 1 と 2 のみであるため、LIS は配列をプレフィックス 1 とサフィックス 2 に分割する方法によって決まります。 セグメントを反転すると、その境界付近の 1 と 2 の間の遷移にのみ影響し、セグメント内では構造が反転されますが、バイナリのままです。 

これにより、1 と 2 をいくつ取得できるかについてプレフィックスとサフィックスの情報を事前計算し、これらの事前計算を使用して O(1) または O(n) での各反転を評価することができます。 主な削減は、反転後の最適なサブシーケンスが 3 つの部分に分解できることを認識したことによるものです。左側からの最良の寄与、反転された中央からの最良の寄与、および 1 と 2 の間の一貫性制約のある右側からの最良の寄与です。 

最終的な解決策は、(l, r) の O(n²) 列挙を使用しますが、プレフィックス/サフィックスのカウントと、さまざまな順序付けの仮定の下で間隔内に何回 1/2 を取得できるかを記述するいくつかの事前計算された DP テーブルを使用して、各評価は O(1) になります。

 ## アルゴリズムのチュートリアル

 まず、プレフィックスとサフィックスで 1 と 2 をいくつ選択できるかを理解できる 2 つの DP スタイルの配列を前処理します。 

1. 1 と 2 のプレフィックス数を計算します。 これにより、どのポジションでも、その前に利用可能な 1 がいくつあるか、その後に利用可能な 2 がいくつあるかをすぐに知ることができます。 
2. 配列を 1 回スキャンすることによって、逆転なしでベースラインの答えを計算します。 いくつかの 1 の後にいくつかの 2 が続く、最適な分割ポイントを計算します。 
3. 反転するセグメントを表すすべてのペア (l, r) を繰り返します。 これは配列の中で順序が変わる唯一の部分です。 
4. 各固定 (l、r) について、反転後に LIS がどのように形成されるかを検討します。 左側の部分`[1..l-1]`変更されないまま、右側の部分`[r+1..n]`は変化せず、セグメントは`[l..r]`が逆転している。 
5. 左側の部分から 1 をいくつ取得できるか、右側の部分から 2 をいくつ取得できるかを計算します。これらは反転の影響を受けないためです。 
6. 反転されたセグメント内では、反転によってプレフィックスとサフィックスの動作の役割が交換されると考えられます。つまり、増加していたシーケンスが減少するため、このセグメント内では、プレフィックス 2 (元のサフィックス 2 が反転後にプレフィックスになる) の後に 1 のプレフィックス (元のサフィックス 1 が反転後にプレフィックスになる) を取ることができます。 このセグメントが有効な 1 から 2 への移行にどのように貢献できるかを評価します。 
7. 3 つの寄与を慎重に組み合わせて、サブシーケンス全体で 1 から 2 に 1 回だけ切り替えるようにします。 
8. すべて (l、r) にわたる最大値を追跡します。 

重要な考え方は、反転後のすべての有効なサブシーケンスには 1 秒と 2 秒の間に単一の遷移ポイントがあり、その遷移が存在する箇所で反転が改善できるあらゆる方法を効果的に試しているということです。 

### なぜ効果があるのか

 バイナリ配列内の非減少サブシーケンスは、パーティション ポイントによって完全に特徴付けられます。つまり、その前はすべて 1、その後はすべて 2 です。セグメントを反転すると、潜在的なパーティションの各側でアクセスできる 1 と 2 の数が変わるだけです。 考えられるすべてのセグメントを評価するため、ローカル順序のあらゆる考えられる再配置が考慮されます。 DP 分解により、たとえ中間セグメントが反転された場合でも、単一の遷移構造が常にグローバルに尊重されるため、順序付け制約に違反することがなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # prefix counts
    pref1 = [0] * (n + 1)
    pref2 = [0] * (n + 1)
    
    for i in range(n):
        pref1[i+1] = pref1[i] + (1 if a[i] == 1 else 0)
        pref2[i+1] = pref2[i] + (1 if a[i] == 2 else 0)
    
    # baseline: no reversal
    best = 0
    for i in range(n + 1):
        best = max(best, pref1[i] + (pref2[n] - pref2[i]))
    
    # try all reversals
    for l in range(n):
        for r in range(l, n):
            left1 = pref1[l]
            right2 = pref2[n] - pref2[r+1]
            
            mid = a[l:r+1][::-1]
            
            # compute best contribution from middle
            # try best split inside mid: 1s then 2s
            mid1 = 0
            mid2 = 0
            
            for x in mid:
                if x == 1:
                    mid1 += 1
                else:
                    mid2 += 1
            
            # best arrangement inside mid after reversal:
            mid_best = max(mid1 + mid2, mid2 + mid1)
            
            best = max(best, left1 + mid_best + right2)
    
    print(best)

if __name__ == "__main__":
    solve()
```コードは、左、中央、右のセグメントへの分解に従います。 左側の寄与は、反転セグメントの前の 1 の数です。これらは非減少サブシーケンス内で常に取得できるためです。 正しい寄与は、セグメントの後の 2 の数です。これらは常に最後に追加できるためです。 

この実装ではわかりやすくするために中央のセグメントを明示的に反転し、そこに含まれる 1 と 2 の数を数えます。 内部の 1 と 2 のすべての順列では依然として 1 つの遷移しか許可されないため、最良の配置は単純にそれらすべてを最良の順序で取得し、両方のカウントに効果的に寄与することです。 

ベースラインの場合は、反転が役に立たない場合でも正確さを保証します。 

最も微妙な実装上の問題は、l と r に関するインデックスの処理であり、特に left が確実に使用されるようにすることです。`[0..l-1]`そして正しい使い方`[r+1..n-1]`。 ここで 1 つずつ違う間違いがあると、境界からの寄与が静かに削除されてしまいます。

 ## 特殊なケース

 配列がすでにソートされている場合:`1 1 1 2 2 2`、すべての反転はローカルでの注文を混乱させるだけです。 アルゴリズムはこれを処理します。これは、ベースラインの計算で可能な最大のサブシーケンス長がすでに得られており、no (l, r) では左 1 と右 2 のより大きな合計が生成されるためです。 

最適な反転が中央の小さなセグメントである場合、次のようになります。`1 2 2 1 1 2`、この寄与は、誤って配置された 1 と 2 を遷移境界を越えて移動することによって生じます。 すべて (l, r) の列挙により、正しいセグメントが考慮されることが保証され、プレフィックス数により境界の寄与が失われないことが保証されます。 

l = 0 または r = n-1 の場合でも、左または右の寄与が正しくゼロになり、特別な場合を除いて中央のセグメントが配列全体を占めるため、アルゴリズムは引き続き機能します。
