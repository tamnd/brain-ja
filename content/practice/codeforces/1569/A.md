 ## 解決策
 ## 問題の理解

 文字のみで構成されるバイナリ文字列が与えられます。`a`そして`b`。 各テスト ケースについて、次の数の連続するセグメントを見つける必要があります。`a`文字はその数と正確に同じです`b`文字。 

出力では、最長の平衡部分文字列や平衡部分文字列の数は求められません。 有効な回答はどれでも受け入れられます。 バランスの取れた部分文字列が存在しない場合は、次のように出力します。`-1 -1`。 

制約は非常に小さいです。 各文字列の長さは最大 50 で、テスト ケースの数は最大 1000 です。 長さ 50 の文字列には約 2500 個の部分文字列しかないため、考えられるすべての部分文字列をチェックするアルゴリズムでも制限時間内に問題なく収まります。 

この問題の興味深い点は、もっと単純な観察が存在することです。 

長さ 1 の文字列を考えてみましょう。```
a
```すべての部分文字列には 1 文字しか含まれていないため、空でない部分文字列のバランスを取ることはできません。 正しい答えは、`-1 -1`。 

よくある間違いは、すべての文字列に長さ 2 以上のバランスのとれた部分文字列が含まれていると想定することです。 

すべての文字が同一である文字列を考えてみましょう。```
aaaaa
```すべての部分文字列には、`a`したがって、どれも等しい数を持つことはできません`a`そして`b`。 正しい答えは、`-1 -1`。 

不注意な実装では、偶数長の部分文字列のみを検索し、それが存在する必要があると誤って想定する可能性があります。 

もう 1 つの微妙なケースは、次のような文字列です。```
aba
```2つの文字列が含まれているため、文字列全体のバランスが取れていません。`a`そして1つ`b`。 ただし、部分文字列`"ab"`バランスが取れています。 この問題はバランスの取れた部分文字列を受け入れるため、見つかったらすぐに停止する必要があります。 

## アプローチ

 ブルートフォースの解決策は簡単です。 すべてのペアを列挙する`(l, r)`の数を数えます`a`そして`b`その部分文字列内でカウントが一致するかどうかを確認します。 あるので`O(n²)`部分文字列と文字数のカウントは単純に`O(n)`時間の合計の複雑さは`O(n³)`。 

と`n ≤ 50`、 平`50³ = 125000`テストケースごとの操作は完全に管理可能です。 したがって、ブルートフォースはすでに受け入れられているでしょう。 

本当のコツは、可能な限り最小のバランスの取れた部分文字列を調べることから始まります。 

バランスのとれた部分文字列には、同じ数の`a`そして`b`。 空ではない最も短いバランスのとれた部分文字列の長さは 2 であり、その可能な形式は次のとおりです。```
ab
ba
```ここで、文字列内のどこかにバランスのとれた部分文字列が存在すると仮定します。 異なる最初の 2 文字を調べてみましょう。 文字列にはのみが含まれているため、`a`そして`b`、隣接する不等ペアはいずれかです。`"ab"`または`"ba"`、すでにバランスが取れています。 

これは、長い部分文字列を検索する必要がないことを意味します。 隣接する 2 つの異なる文字を見つける必要があるだけです。 

そのようなペアが位置に存在する場合`i`そして`i+1`、次に部分文字列`[i, i+1]`バランスが取れており、すぐに返品できます。 

隣接するすべてのペアが等しい場合、文字列全体は 1 つの繰り返し文字のみで構成されます。 その状況では、バランスのとれた部分文字列は存在できません。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取ります。 
2. 隣接する文字のペアをすべてスキャンします。 
3. ポジションごとに`i`、どうかを確認してください`s[i] != s[i + 1]`。 
4. そのようなペアが見つかった場合は、出力します。`i + 1`そして`i + 2`1 から始まるインデックスを使用します。 
5. 現在のテスト ケースの処理を直ちに停止します。`"ab"`そして`"ba"`どちらもバランスの取れた部分文字列です。 
6. 隣接する異なる文字が見つからずにスキャンが終了した場合は、次のように出力します。`-1 -1`。 

ステップ 6 が正しい理由は、隣接する異なる文字がないバイナリ文字列は完全に同じ文字で構成されている必要があるためです。 このような文字列には、同じ数の文字列を含めることはできません。`a`そして`b`空でない部分文字列。 

### なぜ効果があるのか

 重要な特性は、すべての隣接する等しくないペアが長さ 2 のバランスのとれた部分文字列を形成することです。 

アルゴリズムが位置を返す場合`(i, i+1)`、部分文字列は次のいずれかです`"ab"`または`"ba"`。 どちらにも1つが含まれています`a`そして1つ`b`、したがって、答えは有効です。 

アルゴリズムによって隣接する等しくないペアが見つからない場合、文字列内のすべての文字は同一になります。 空でないすべての部分文字列も同一の文字で構成されているため、両方を含めることはできません。`a`そして`b`。 したがって、バランスのとれた部分文字列は存在しません。 

このアルゴリズムは無効な部分文字列を出力することはなく、既存のバランスのとれた部分文字列を見逃すこともありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    s = input().strip()

    found = False

    for i in range(n - 1):
        if s[i] != s[i + 1]:
            print(i + 1, i + 2)
            found = True
            break

    if not found:
        print(-1, -1)
```実装は観察に直接従います。 

ループはすべての隣接するペアを 1 回検査します。 隣接する 2 つの文字が異なる場合、対応する長さ 2 の部分文字列のバランスがとれるため、答えはすぐに出力されます。 

文字列内のインデックスは 0 から始まりますが、問題では 1 から始まる位置が予期されます。 そのため、出力では`i + 1`そして`i + 2`。 

変数`found`有効な部分文字列がすでに報告されているかどうかを追跡します。 設定せずにループが終了した場合`True`、文字列には繰り返し文字が 1 つだけ含まれており、答えは次のようになります。`-1 -1`。 

このアルゴリズムは単純なインデックス操作のみを実行するため、オーバーフローの懸念はありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline
    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        s = input().strip()

        found = False

        for i in range(n - 1):
            if s[i] != s[i + 1]:
                out.append(f"{i + 1} {i + 2}")
                found = True
                break

        if not found:
            out.append("-1 -1")

    return "\n".join(out)

# provided sample

"""4

a
6
abbaba
6
abbaba
9
babbabbaa
"""
) == """-1 -1
1 2
1 2
1 2""", "sample"

# minimum size, no answer
assert run(
"""1
1
b
"""
) == "-1 -1", "single character"

# smallest balanced substring
assert run(
"""1
2
ab
"""
) == "1 2", "length two balanced"

# all equal characters
assert run(
"""1
5
aaaaa
"""
) == "-1 -1", "all a"

# difference appears at the end
assert run(
"""1
5
aaaab
"""
) == "4 5", "boundary pair"

50

"""
) == "49 50", "near maximum length"
