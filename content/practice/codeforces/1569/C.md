 ## 解決策
 ## 問題の理解

 私たちは、陪審員の課題の提示方法を考慮して、「良い」と思われる陪審員の順列の数を数えるように求められました。 各審査員$i$もっている$a_i$タスクを順列に従って順番に指示します。 順列は、審査員が 2 つの課題を連続して提出しない場合に便利です。 

重要な洞察は、一連のプレゼンテーションが実質的にラウンドロビンであるということです。各ラウンドで、残りのタスクを持つ各審査員が 1 つのタスクを提示します。 一部のメンバーが連続して複数のタスクを指示することになる場合、並べ替えは失敗します。 

構造的な観点から見ると、順列が無効になる唯一の原因は、タスクの数が他のメンバーに比べて多すぎるメンバー**が存在し、他のメンバーが 1 回プレゼンテーションを行った後でも、このメンバーにはまだタスクが残っており、続けて 2 回プレゼンテーションを行う必要がある場合です。 

これにより、すぐに具体的な条件が得られます。$\text{max}_a$最大になる$a_i$そして$\text{sum}_a$すべての合計$a_i$。 最大の場合、適切な順列は **不可能**$a_i$他のものの合計を超える$a_i$プラス1。 それ以外の場合は、連続したプレゼンテーションを避けるためにタスクをインターリーブする方法が常にあります。 

エッジケースは、すべての陪審員が同じ数のタスクを抱えている場合に発生します。 たとえば、すべての場合、$a_i = 1$の場合、誰も連続して 2 回提示できないため、**すべての順列は自動的に適切になります**。 同様に、$n = 2$タスクが等しい場合、適切な順列が 1 つだけ存在します。 

制約が大きい ($n$まで$2 \cdot 10^5$そして$a_i$まで$10^9$)、プレゼンテーションプロセスを明示的にシミュレートするアプローチは除外されます。 順列を直接カウントするには、**組み合わせ式**が必要です。 

## アプローチ

 ブルートフォースアプローチは、すべての順列を生成し、タスク共有プロセスをシミュレートすることです。 順列ごとに、各陪審員の残りのタスクを追跡し、誰かが連続して発表するかどうかを確認します。 これは正しいですが、実行不可能です。$n!$順列が大きすぎる場合$n$到達する$10^5$。 

重要な点は、タスクの最大数を持つメンバーによる唯一の制限であるということです。 させて$\text{max}_a$現れる$c$配列内の回数。 もし$\text{max}_a - \text{second\_max}_a > 1$の場合、最大メンバーが 2 回連続して存在しない限り、タスクをインターリーブすることは不可能です。 それ以外の場合は、最初に「2 番目に高い」メンバーの位置を選択し、次に残りのメンバーを自由に並べ替えることで並べ替えをカウントできます。 

組み合わせ推論は次のように分解できます。 

1. 最大値が複数ある場合、最大値が他の値を 1 より大きく上回る場合を除いて、すべての順列が有効です。 
2. 最大のものが 1 回出現した場合、2 番目に大きいものに対して最後の位置に出現することを避けなければなりません。 不正な順列の数は組み合わせ的に計算できます。 

これは効率的な$O(n \log n)$階乗とモジュラー演算を使用した解決策。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n!)$|$O(n)$| 遅すぎる |
 | 組み合わせ計数 |$O(n \log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む$t$テストケース。 
2. 各テスト ケースについて、次の内容を読んでください。$n$と配列$a$。 
3. コンピューティング$\text{max}_a = \max(a)$そして数えます$c$それが発生する回数。 
4. コンピューティング$\text{second\_max}_a$次に大きい値として$a$。 
5. もし$\text{max}_a - \text{second\_max}_a > 1$、タスクをインターリーブすることは不可能であるため、0 を出力します。 
6. それ以外の場合は、次の階乗を計算します。$n$モジュロ$998244353$順列カウント用。 
7. 複数回発生する場合$\text{max}_a$、すべての順列が有効であるため、答えは次のようになります。$n!$。 
8. 単一の最大値がある場合は、組み合わせ公式を使用して単一の最大値が「早すぎる」位置にある順列の数を計算し、から減算します。$n!$、結果のモジュロを出力します$998244353$。 

**機能する理由**: 正確性はラウンドロビン プロパティに依存します。 最大値を連続して配置することはできません。 2 番目の最大値を基準とした最大値のみを制御することで、他のメンバーが 2 回連続して存在しないことを保証します。 これにより、問題は、これらの最大のタスクに対する位置の有効な順列をカウントすることに軽減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

def solve():
    t = int(input())
    fact = [1] * (2*10**5 + 10)
    for i in range(1, len(fact)):
        fact[i] = fact[i-1] * i % MOD
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        mx = max(a)
        c = a.count(mx)
        if c > 1:
            print(fact[n])
            continue
        sec = max(x for x in a if x != mx)
        if mx - sec > 1:
            print(0)
            continue
        cnt = a.count(sec)
        # Number of bad permutations
        bad = fact[n] * modinv(cnt + 1) % MOD
        print((fact[n] - bad + MOD) % MOD)

solve()
```**説明**: 階乗モジュロを事前計算します。$998244353$。 複数の最大値が存在する場合、すべての順列が有効です。 それ以外の場合は、階乗を効率的に除算するモジュラー逆関数を使用して、単一の最大値が 2 番目の最大値に対して早すぎる「悪い」順列を計算します。

 ## 特殊なケース

 最大のメンバーのタスクが他のメンバーの合計を 1 を超えて超えている場合、インターリーブなしにより連続したプレゼンテーションが回避されます。 例えば、`n=3, a=[1,1,4]`。 私たちのアルゴリズムは次のことを検出します`4 - 1 > 1`そしてすぐに戻ります`0`。 

すべてのメンバーが等しいタスクを持っている場合、どの順列も有効です。 私たちの階乗事前計算により、これらのケースが効率的に処理されることが保証されます。 

これにより、各順列をシミュレートすることなく、問題からすべての非自明な制約が取得されます。
