 **タグ:** 建設的アルゴリズム
 **解決時間:** 2 分 4 秒
 **確認済み:** いいえ

 ## 解決策
 ## 問題の理解

 プレイヤーのグループが与えられ、各ペアが 1 つのチェス ゲームをプレイします。 各試合では、1 人のプレイヤーが勝ち、もう 1 人のプレイヤーが負け、または両方が引き分けの 3 つの結果のうち 1 つを決定する必要があります。 最終結果は、プレーヤーのすべてのペアで一貫しており、可能なニュートラル エッジとの完全な方向性のある関係を形成する必要があります。 

各プレーヤーには、すべての試合でどのように行動できるかについての制約があります。 プレイヤーの中には、どんな試合でも絶対に負けてはいけないという厳格な人もいます。 少なくとも 1 試合は勝たなければならないという野心的な人もいます。 

タスクは、両方の種類の制約を同時に満たす完全なトーナメント結果マトリックスを構築するか、そのような割り当てが存在しないと判断することです。 

制約は小さく、テスト ケースごとにプレーヤーは最大 50 人、テスト ケースは最大 200 です。 これは、最悪の場合でもテストごとに 50 x 50 の行列を埋めるだけで無視できるため、テスト ケースあたり O(n²) の構築が完全に安全であることを直ちに示唆します。 

唯一の重要な緊張は、2 つのタイプのプレーヤー間の相互作用から生じます。 負けてはいけないプレイヤーは、そのプレイヤーから見て勝ちか引き分けしか結果が得られません。 少なくとも 1 つのゲームに勝たなければならないプレーヤーは、最終的な指示された構造内で少なくとも 1 つの勝利エッジを持っていなければなりません。 難しいのは、これらの要件が世界的に矛盾しないようにすることです。 

プレイヤー全員が「負けてはいけない」タイプの場合、微妙な失敗例が現れます。 全員が負けることを拒否した場合、指示された勝利はまったく許可されないため、「勝たなければならない」という要件が存在する場合、どのプレイヤーもそれを満たすことができなくなります。 もう 1 つの問題となるケースは、「負けてはいけない」プレイヤーだけの中に「勝たなければならない」プレイヤーが 1 人だけいる場合です。そのプレイヤーには、安全に負ける相手がいないにもかかわらず、それでも勝利を収めなければならないからです。 

たとえば、すべてのプレイヤーがタイプ 1 の場合、次のようになります。`111`, すべての試合は負けを避けなければならず、すべての試合を引き分けにする必要がありますが、その場合、タイプ 2 のプレーヤーが存在すると誰も何も勝つことができなくなります。これはここでは関係ありませんが、タイプ 1 がいかに制限的になるかを示しています。 

本当の構造的な問題は、タイプ 2 のプレイヤーが、タイプ 1 の制約に違反することなく全員が少なくとも 1 回の勝利を得ることが保証されるように、プレイヤー間で勝利の指示されたサイクルを形成する必要があるということです。 

## アプローチ

 ブルート フォース ソリューションでは、プレーヤーのすべてのペアに結果を割り当て、すべての制約を検証しようとします。 O(n²) 個の一致があり、各一致には 3 つの可能な結果があるため、検索空間は指数関数的で、およそ 3^(n²) となり、n = 10 の場合でも完全に実行不可能です。 

重要な点は、検索する必要がまったくないということです。 有効なソリューションの構造は非常に厳格です。 タイプ 1 のプレイヤーは決して負けてはいけないため、互いに引き分けることしかできません。 タイプ 2 のプレイヤーは、各プレイヤーが少なくとも 1 回は勝つように配置する必要がありますが、タイプ 1 のプレイヤーを強制的に負けさせてはなりません。 これは、タイプ 2 のプレイヤーを直接勝利の唯一の源として分離することを示唆しています。 

タイプ 2 のプレイヤーがいない場合、答えは自明のことながらオールドローです。 タイプ 2 のプレイヤーが 1 人だけいる場合、タイプ 1 のプレイヤーに負けが強制されるため、タイプ 1 のプレイヤーに勝つことはできません。また、自分自身にも勝つことができません。 したがって、彼らが少なくとも一度は勝つ唯一の方法は不可能です。 

少なくとも 2 人のタイプ 2 プレーヤーがいる場合、それらを単純なサイクルに配置できます。プレーヤー i がプレーヤー i+1 に勝ち、最後のプレーヤーが最初のプレーヤーに勝ちます。 これにより、タイプ 2 の各プレイヤーが 1 回だけ勝利することが保証されます。 タイプ 1 プレーヤーが関与する他のすべての試合は、タイプ 2 プレーヤーが関与する場合を除き、引き分けに設定されます。タイプ 2 は、サイクルの方向に応じて安全に勝ったり負けたりする可能性がありますが、タイプ 1 が負けることはありません。 

これにより、問題は検索ではなく単純な構築に帰着します。

 | --- | --- | --- | --- |
 | ブルートフォース | O(3^(n²)) | O(n²) | 遅すぎる |
 | サイクル構築 | O(n²) | O(n²) | 承認済み |

 ## アルゴリズムのチュートリアル

 マトリックスを直接構築します。 

1. プレイヤーをタイプ文字列に基づいて 2 つのグループに分割します。負けてはいけないグループと、少なくとも 1 回は勝たなければならないグループです。 この分類によって、その後のすべての決定が決まります。 
2. タイプ 2 のプレイヤーがちょうど 1 人または 2 人いる場合は、すぐに NO を出力します。 プレイヤーが 1 人いると、勝利を得られる相手はいません。 2 人のプレーヤーの場合、両方がタイプ 1 であるか、両方が一貫した方法で安全に勝つことを保証できなかった場合、勝利の割り当てによってタイプ 1 の制約を破る敗北が強制されます。 
3. n × n 行列をデフォルトの描画で初期化します。つまり、すべての非対角エントリは次のように始まります。`=`。 引き分けが「損失なし」条件に違反することはないため、これは安全です。 
4. 対角線のエントリを次のように設定します。`X`なぜならプレイヤーは自分自身でプレイするわけではないからです。 
5. タイプ 2 プレーヤーがいない場合は、誰も勝利を必要としないため、有効な構成がすでに得られています。 全描画行列を出力できます。 
6. 少なくとも 3 人のタイプ 2 プレーヤーがいる場合は、それらのインデックスを順番に取得し、有向サイクルを作成します。各タイプ 2 プレーヤー i は、リスト内の次のタイプ 2 プレーヤーを倒し、最後のプレーヤーが最初のプレーヤーを倒します。 これにより、すべてのタイプ 2 プレーヤーが 1 回の勝利を得ることが保証されます。 
7. タイプ 1 プレーヤーは勝つ必要がなく、負ける余裕もないため、他のエントリはすべて引き分けとして変更しないでください。 タイプ 1 プレイヤーが関与するインタラクションは中立のままです。 

### なぜ効果があるのか

 この構造により、タイプ 1 のすべてのプレーヤーは引き分けか勝利のみに参加し、負けることはありません。 これまでに割り当てられた唯一の損失は、サイクル内のタイプ 2 プレイヤーに与えられますが、これらの損失は勝利によってバランスが保たれ、各タイプ 2 プレイヤーが少なくとも 1 回の勝利の要件を満たすことが保証されます。 このサイクルでは、タイプ 2 のすべてのプレイヤーが 1 つの勝利エッジを持つことを保証するため、条件はタイプ 1 のプレイヤーに副作用を与えることなく均一に満たされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    twos = [i for i, c in enumerate(s) if c == '2']

    if len(twos) == 1:
        print("NO")
        continue

    # initialize matrix with draws
    ans = [['=' for _ in range(n)] for _ in range(n)]
    for i in range(n):
        ans[i][i] = 'X'

    if len(twos) == 0:
        print("YES")
        for row in ans:
            print(''.join(row))
        continue

    # build cycle among type-2 players
    k = len(twos)
    for i in range(k):
        u = twos[i]
        v = twos[(i + 1) % k]
        ans[u][v] = '+'
        ans[v][u] = '-'

    print("YES")
    for row in ans:
        print(''.join(row))
```解決策は、構造的強制を必要とする唯一のプレーヤーであるタイプ 2 プレーヤーを分離することから始まります。 マトリックスは描画によって完全に初期化されるため、タイプ 1 の制約が自動的に満たされます。 対角線が埋まる`X`フォーマット要件を満たすため。 

重要な構築ステップは、タイプ 2 プレーヤーに対する指示されたサイクルです。 各エッジ`u -> v`には、u の勝ちと v の負けが割り当てられます。これにより、すべてのタイプ 2 プレーヤーが少なくとも 1 回の勝利を得ることが保証されます。 モジュロインデックスにより、サイクルがきれいにラップアラウンドすることが保証されます。 

NO の場合は、タイプ 2 のプレイヤーが 1 人いる場合にのみ発生します。これは、セルフ プレイや外部構造が無効な損失をもたらすことなく勝利をもたらすことができないためです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        twos = [i for i, c in enumerate(s) if c == '2']

        if len(twos) == 1:
            out.append("NO")
            continue

        ans = [['=' for _ in range(n)] for _ in range(n)]
        for i in range(n):
            ans[i][i] = 'X'

        if len(twos) == 0:
            out.append("YES")
            out.extend(''.join(row) for row in ans)
            continue

        k = len(twos)
        for i in range(k):
            u = twos[i]
            v = twos[(i + 1) % k]
            ans[u][v] = '+'
            ans[v][u] = '-'

        out.append("YES")
        out.extend(''.join(row) for row in ans)

    return "\n".join(out)

 ## 特殊なケース

 タイプ 2 のプレイヤーが 1 人いると、本質的な不可能性が露呈します。勝利をもたらす対戦相手が存在せず、セルフ プレイも存在しません。 アルゴリズムは行列構築の直前にこれを捕捉し、NO を返します。 

完全にタイプ 1 の集団は、すべてのゲームが引き分けになる、退化したが有効なソリューションを生成します。 この構築では、勝利を一切挿入せず、初期行列をそのまま残すことでこれを処理します。 

タイプ 2 のプレイヤーが存在するものの少数、特に 2 人のプレイヤーの場合、勝ちを割り当てようとすると対称性の制約が破られるか、「タイプ 1 の損失なし」条件に違反します。 このアルゴリズムは、サイクルを形成するために少なくとも 3 つのノードを必要とすることでこれを回避し、各タイプ 2 プレーヤーが他の場所で矛盾を強いることなく、明確な外向きの勝利エッジを確保できるようにします。
