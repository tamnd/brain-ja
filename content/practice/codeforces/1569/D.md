 ## 解決策
 ## 問題の理解

 私たちは、完全な正方形のグリッドである都市の路上にいる人々の中で「不便なペア」の数を数えるように求められます。 各人は、ソートされた座標として与えられる、垂直方向または水平方向のいずれかの道路上にいることが保証されます。 不便なペアという概念は、二人の間の通りに沿った最短経路が二人の間のマンハッタンの距離よりも長い場合に生じます。 すべての道路は直線で双方向であるため、マンハッタンの距離は単に x 座標と y 座標の差の絶対値の合計になります。 2 人の人物が一次元で同じ通りを共有しておらず、中間の通りを経由する必要がある場合、通りに沿った最短経路はこの距離を超える可能性があります。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、垂直方向と水平方向の道路の座標が提供され、その後に各人の座標が示されます。 最大 300,000 人の人々と 200,000 の街路を効率的に処理する必要があります。つまり、すべてのペアを直接比較するソリューションでは、10^10 程度の演算が必要となり、これは 2 秒の制限時間には大きすぎます。 これにより、ブルートフォースのペアごとの比較を回避する必要があります。 

複数の人が同じ通りを共有する場合、明らかではないエッジケースが発生します。 たとえば、2 人が同じ垂直方向の道路にいて、異なる水平方向の道路にいる場合、道路に沿った最短経路は y 座標の差となり、これはマンハッタンの距離に等しくなります。 ただし、それらが異なる垂直方向の道路上にあるが、水平方向の道路を共有している場合、道路に沿った最短経路も水平方向の距離となり、やはりマンハッタンの距離に等しくなります。 不都合なペアは、両方の座標が異なる場合にのみ発生し、道路により 3 番目の通りを経由する必要があります。 もう 1 つの微妙な点は、人が 2 本の道路の交差点にいる場合で、慎重に扱わないと二重にカウントされる可能性があります。 

## アプローチ

 ブルートフォース手法では、すべての人のペアを反復処理し、マンハッタンの距離と道路ベースの最短経路の両方を計算し、後者の方が厳密に大きいペアをカウントします。 これは単純で正しいですが、k が最大 3·10^5 の場合、テスト ケースごとにおよそ k²/2 の比較が必要となり、最悪でも約 4.5·10^10 の演算が必要になります。 これは明らかに実行不可能です。 

重要な洞察は、不都合なペアは、2 人が 1 つの座標タイプを正確に共有する場合にのみ現れるということです。 つまり、ある人は垂直方向の通りにおり、別の人は同じ垂直方向 (ただし y が異なる) または同じ水平方向 (ただし x が異なる) にいます。 両方の座標を共有する場合、それらは同じ点にあるため、除外されます。 どちらも共有しない場合、最短パスはマンハッタン距離に等しくなります。 したがって、人々を x 座標と y 座標でグループ化し、交差の二重カウントを避けながら、1 つの座標だけを共有するペアの数を数えることができます。 それぞれの垂直の通りについて、そこにいるすべての人々を考慮し、同じ y 座標を共有する人の数を数え、それらを合計から差し引いて、その通りに沿った不都合なペアを取得します。 水平方向の道路についても同じことを行います。 ハッシュ マップ (辞書) を使用して出現回数をカウントすると、並べ替えに応じてテスト ケースごとに O(k log k) または O(k) の処理が可能になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k²) | O(k) | 遅すぎる |
 | カウントによるストリートごとのグループ化 | O(k log k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 各テスト ケースについて、垂直の通りの数 n、水平の通りの数 m、および人の数 k を読み取ります。 街路の座標や各人物の座標も読み取ります。 
2. 人々を 2 つのカテゴリに分類します。垂直方向の道路にある人々 (X 座標をキーとして辞書に保存) と水平方向の道路にある人々 (Y 座標をキーとして辞書に保存)。 
3. カウンタの初期化`inconvenient_pairs`ゼロに。 
4. 少なくとも 2 人がいる垂直の通りごとに、各 y 座標を共有している人の数を数えます。 この通りのペアの合計数は`c * (c-1) / 2`、不都合ではない（同じ y）ペアの数は次の合計です。`count_y * (count_y - 1) / 2`全体的にy。 前者から後者を減算し、結果を次の値に加算します。`inconvenient_pairs`。 
5. 水平方向の道路に対してステップ 4 を繰り返し、同じ X 座標を持つ人数を数えます。 
6. 印刷`inconvenient_pairs`テストケース用。 

このアルゴリズムが機能するのは、不都合なペアとは、一方の次元では通りを共有しているが、もう一方の次元では異なるペアであるためです。また、両方の座標を共有するペアを減算することで、交差点で人を 2 回カウントすることを回避できます。 ハッシュ マップを使用すると、座標ごとのカウントを効率的に追跡できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict

def solve():
    t = int(input())
    for _ in range(t):
        n, m, k = map(int, input().split())
        x_coords = list(map(int, input().split()))
        y_coords = list(map(int, input().split()))
        
        vert_map = defaultdict(list)
        hor_map = defaultdict(list)
        points = []
        for _ in range(k):
            x, y = map(int, input().split())
            points.append((x, y))
            if x in x_coords:
                vert_map[x].append(y)
            if y in y_coords:
                hor_map[y].append(x)
        
        res = 0
        # vertical streets
        for x, ys in vert_map.items():
            count = len(ys)
            if count > 1:
                ys_count = defaultdict(int)
                for y in ys:
                    ys_count[y] += 1
                total_pairs = count * (count - 1) // 2
                same_y_pairs = sum(v * (v - 1) // 2 for v in ys_count.values())
                res += total_pairs - same_y_pairs
        
        # horizontal streets
        for y, xs in hor_map.items():
            count = len(xs)
            if count > 1:
                xs_count = defaultdict(int)
                for x in xs:
                    xs_count[x] += 1
                total_pairs = count * (count - 1) // 2
                same_x_pairs = sum(v * (v - 1) // 2 for v in xs_count.values())
                res += total_pairs - same_x_pairs
        
        print(res)

if __name__ == "__main__":
    solve()
```このソリューションでは、最初に通りの座標によって人々をグループ化し、次に、垂直および水平の各通りに沿って不都合なペアを個別にカウントします。 ディクショナリを使用すると、すべてのペアに対するネストされたループの必要がなくなり、二重カウントが防止されます。 同じ座標のペアのそれぞれの減算では、交差が正しく処理されます。
