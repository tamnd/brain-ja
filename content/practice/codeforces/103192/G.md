 ## 解決策
 ## 問題の理解

 離散時刻における暗号通貨と人民元の間の将来の為替レートのシーケンスが与えられます。 各瞬間における 1 ビットの価格は事前にわかっています。 トレーダーはゼロの暗号通貨と無制限の人民元から始めます。 彼らは 1 日を通してビットコインの売買を繰り返す可能性がありますが、これには制限された取引最適化の問題を引き起こすいくつかの制約があります。 

主要な制限によって、実現可能な戦略の構造が決まります。 まず、単一の取引では少なくとも 0.01 ビットという非常に少額の取引を行う必要がありますが、取引ごとの上限はありません。 第 2 に、ビットの合計保有量はいかなる瞬間も 1 を超えることはできません。第 3 に、トレーダーは 1 つのタイム ステップ内でアクションを任意の数の取引に分割できます。 最後に、売買を含めた合計トランザクション数は最大で k です。 

出力は、すべての将来価格の完全な知識を活用することによって達成可能な最大人民元利益です。 

時間と空間の制限が非常に厳しいため、n が 1000 までの場合、すべての売り買いペアにわたる 2 次または 3 次シミュレーションは実行できません。O(n^3) のようにスケールするソリューションや、次元が多すぎる単純な動的プログラミングでさえも遅すぎますが、O(n^2 k) は許容可能であり、時間とトランザクション数に応じた DP を期待する必要があります。 

欲張って考えると微妙な問題が見えてきます。 すべての極小値で購入し、すべての極大値で売ろうとする可能性がありますが、取引制限 k により制約のない取引の分割が妨げられます。 もう 1 つの微妙な罠は、「タイム ステップごとに複数の取引」ルールです。これにより、粒度の問題が効果的に取り除かれ、各瞬間をその中の個別の操作ではなく連続状態として扱うことができるようになります。 

素朴な貪欲さが失敗する小さな例は次のとおりです。 

入力:

 4 2

 1 100 1 100

 貪欲なアプローチでは、複数の売買サイクルを試行する可能性がありますが、許可されるトランザクションが 2 つだけである場合、最適な戦略は、1 で買って 100 で 1 回売ることで、198 ではなく 99 または複数の断片的な利益を生み出すことです。 これは、実際のボトルネックは価格変動カウントではなく、トランザクションカウントであることを強調しています。 

## アプローチ

 直接的な総当たりアプローチでは、最大 k 個のトランザクションのすべてのシーケンスを列挙しようとします。 各トランザクションは買い時間 i と売り時間 j > i によって定義され、トランザクションは重複しない保有制約を尊重する必要があります。 単純化して、互いに素な間隔を k 個だけ選択すると仮定しても、O(n^2) 個の候補の中から最大 k 個の間隔の組み合わせを探索する必要があります。 これにより、O((n^2)^k) のオーダーで組み合わせ爆発が起こりますが、これは、n と k が小さい場合でも実行不可能です。 

重要な観察は、時間と完了したトランザクションの数に応じて問題が最適な下部構造を持っていることです。 いかなる瞬間においても、重要なのは過去の取引の正確な順序ではなく、使用された取引の数と現在資産を保有しているかどうかです。 これはすぐに動的プログラミングの定式化を示唆します。 

時間と使用されたトランザクション数の 2 つの次元で進行状況を追跡する状態を定義し、通貨を保持しているかどうかの追加の次元を追加します。 遷移は、何もしない、買う、または売るのいずれかに対応します。 複数の取引が同時に許可されるため、各価格ステップを、トランジションが 1 回適用される決定点として扱うことができます。 

主な困難は、売買でトランザクション数を正しく消費することを保証することです。 買いは取引を完了しませんが、売りは 1 つの完全な売買サイクルを完了します。 この非対称性により、DP 構造がきれいに機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての取引の組み合わせに対するブルートフォース | 指数 | 指数 | 遅すぎる |
 | 時間とトランザクションに応じた動的プログラミング | O(nk) | O(nk) | 承認済み |

 ## アルゴリズムのチュートリアル

DP テーブルを維持します。ここで、dp[i][j][0] は j 個のトランザクションを使用し、ビットを保持していない後の時点 i で保持できる最大現金を表し、dp[i][j][1] は 1 ビットを保持している場合の最大値を表します。 

時間をかけて反復処理を行い、購入、販売、スキップするかどうかに基づいて状態を更新します。 

1. dp[0][0][0] = 0 を除くすべての状態を負の無限大として初期化します。これは、最初はお金も資産もないことを反映しています。 
2. i が 1 から n まで、およびトランザクション数 j が 0 から k までになるたびに、最初に何もしないというオプションが繰り越されます。 これは、いつでも取引を回避できるため、dp[i][j][0] と dp[i][j][1] は少なくとも dp[i-1][j][0] と dp[i-1][j][1] と同じくらい良好に開始されることを意味します。 
3. i の時点で購入を検討します。 時間 i-1 で資産を保有していなかった場合、同じトランザクション数 j の範囲内で、価格 p[i] で 1 ビットを購入できます。 これにより、dp[i][j][1] が dp[i-1][j][0] - p[i] に遷移します。 トランザクションは完了していないため、まだカウントされません。 
4. i の時点で売却を検討します。 時間 i-1 で資産を保有していた場合、価格 p[i] で売却し、現金を増やして 1 回のトランザクションを消費することができます。 これにより、dp[i-1][j-1][1] + p[i] から dp[i][j][0] が遷移します。 トランザクション カウンタは完了時にのみ増加します。 
5. すべての時間ステップに対してこのプロセスを継続し、各状態が以前の時間レイヤー値のみに依存するようにします。 
6. 実現利益のための資産がない状態で終了するため、最終的な答えは、0 から k までのすべての j にわたる最大 dp[n][j][0] です。 

機能する理由: DP は、考えられるすべての有効な取引シーケンスが状態グラフ内の 1 つのパスに正確に対応することを強制します。 各遷移は法的措置をコード化し、取引カウントは売り操作時に正確に適用され、一連の完了取引が k 件を超えないようにします。 各ステップですべてのアクションを常に考慮するため、最適な戦略が表現され、遷移では最適な下部構造が維持されるため、より良いソリューションが見逃されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    p = list(map(float, input().split()))

    NEG = -1e30

    dp = [[[NEG] * 2 for _ in range(k + 1)] for _ in range(n + 1)]
    dp[0][0][0] = 0.0

    for i in range(1, n + 1):
        price = p[i - 1]
        for j in range(k + 1):
            dp[i][j][0] = dp[i - 1][j][0]
            dp[i][j][1] = dp[i - 1][j][1]

        for j in range(k + 1):
            if dp[i - 1][j][0] > NEG / 2:
                dp[i][j][1] = max(dp[i][j][1], dp[i - 1][j][0] - price)

        for j in range(1, k + 1):
            if dp[i - 1][j - 1][1] > NEG / 2:
                dp[i][j][0] = max(dp[i][j][0], dp[i - 1][j - 1][1] + price)

    ans = max(dp[n][j][0] for j in range(k + 1))
    print(f"{ans:.2f}")

if __name__ == "__main__":
    solve()
```このコードは、トランザクション数ごとに 2 つの状態を明示的に維持し、保持状態と非保持状態を区別します。 初期化では、無効な遷移が結果に影響を与えるのを防ぐために、大きな負のセンチネルを使用します。 買いと売りのトランジションを分離することで、トランザクションの使用量は完了時にのみカウントされ、問題ステートメントと一致することが保証されます。 

時間の経過に伴う外側のループにより、時系列の一貫性が保証されます。 トランザクション数に関する内部ループにより、すべての予算取引制限が遵守されることが保証されます。 すべての j に対する最終的な最大化により、未使用のトランザクション容量が可能になります。これは、より少ない取引が最適である可能性があるため、有益となる可能性があります。

 ## 特殊なケース

 エッジケースの 1 つは、価格が厳密に下落する場合です。 潜在的な売りはすべて非プラスの利益をもたらすため、DP はいかなる買い売りシーケンスもトリガーすべきではありません。 保持状態が改善されることはなく、販売が有益になることはないため、DP は全体を通して dp[i][j][0] = 0 を正しく維持します。 

もう 1 つのエッジ ケースは、k が収益性の高いセグメントの数を超えるほど大きい場合です。 この場合、トランザクション制約が決して拘束されないため、DP は自然にすべての正の差を合計するように縮退します。 状態遷移により、収益性の高い上昇を個別に捉えることができます。 

3 番目のエッジケースは、最適な取引を行うために、隣接しない収益性の高い間隔の間で待機する必要がある場合です。 DP はこれを処理します。これは、「何もしない」遷移が即座のアクションを強制せずに以前の最良の状態を前方に伝播し、任意の時間をスキップする機能を維持するためです。
