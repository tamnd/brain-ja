 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、いくつかの呪文があります。 各呪文は、赤色の量と青色の量の 2 種類のリソースを消費します。 重要な観察は、プレイヤーが現在呪文を唱えることができないということです。これは、プレイヤーが持っている赤と青のマナの量がどれだけであっても、すべての呪文を同時に唱えるにはまったく不十分であることを意味します。 この状態を維持しながらプレイヤーが保持できるマナの最大合計量 (赤と青を意味します) を決定するように求められます。 

これをより構造的に考えると、各呪文は可能なマナ値の平面内で禁止領域を定義するということになります。 プレイヤーが R 赤と B 青を持っている場合、呪文 i は、R ≥ r_i かつ B ≥ b_i の場合にのみ使用できます。 問題の条件は、使用できる呪文がないことを示しているため、すべての i について R < r_i または B < b_i でなければなりません。 これらの制約の下で R + B を最大化したいと考えています。 

制約は、n がテスト グループごとに最大 5000 (グローバル合計が 5000) であり、各値は 10^6 まで大きくできることを示しています。 これは、テスト ケースごとの O(n^2) または O(n log n) の解は許容されるが、3 次または指数関数は実行不可能であることを強く示唆しています。 テスト ケースごとに線形または線形に近いスイープが期待される可能性があります。 

すべての呪文が 1 種類のマナのみを必要とする場合、微妙な特殊なケースが発生します。 たとえば、すべての呪文が (1,0) の場合、青マナがあっても役に立ちませんが、赤の制約が支配的になります。 もう 1 つの重要なケースは、(1,1) などの非常に小さな要件を持つ呪文が存在する場合です。 その場合、両方のリソースが少量であっても制限されるため、最適なソリューションでは赤と青のバランスを慎重にとる必要があります。 

最も重要な隠れた困難は、制約が呪文ごとに追加的ではないことです。 各呪文は第 1 象限に四角形を入れることを禁止しており、すべての四角形の外側にある点を同時に選択する必要があります。 

## アプローチ

 直接的な強引なアプローチは、観察された最大要件まで R と B のすべての可能な値を試すことです。 値は 10^6 に達するため、これはすぐに実行不可能になります。 r_i と b_i の候補値のみに離散化したとしても、軸ごとに最大 5,000 の候補があり、2,500 万の状態になり、各状態のすべての呪文をチェックするのは遅すぎます。 

これを軽減するために、条件を再解釈します。 固定総マナ S = R + B の場合、どの呪文も使用できないような分割 R、B が存在するかどうかを知りたいと考えます。 R を固定する場合、B は S − R として決定され、すべての i について R < r_i または S − R < b_i であるかどうかを確認するだけで済みます。 

これは、特定の S に対する 1 次元の実現可能性チェックになります。重要な洞察は、各呪文には、それを使用可能にする R 値の間隔があるということです。 具体的には、R ≥ r_i かつ R ≤ S − b_i の場合に、呪文 i が使用可能になります。 その間隔は [r_i, S − b_i] です。 したがって、どの呪文も使用できない条件は、R がこれらの区間のいずれかに存在するような R が存在しないということになります。 

したがって、固定 S の場合、区間の和集合が 0 から S までのすべての可能な R 値をカバーしているかどうかをチェックしています。カバーしている場合、S は不可能です。 隙間があればSも可能です。 

ここで、問題を次のように要約します。区間が [0, S] を完全にカバーしないような最大の S を見つけます。 間隔を構築し、ソートとマージ後にカバレッジを確認することで、S の実現可能性をテストできます。 候補の S 値を試行するだけでよいため、S を 0 から max(r_i + b_i) まで二分探索できます。最適な分割は r_i + b_i によって引き起こされる境界に対応する必要があるため、これで十分です。 

複雑さを軽減する観察は、重要な構造が 2 次元の検索ではなく、線上の間隔をカバーすることであるということです。

 | 二分探索 + 区間カバレッジ | O(n log V) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての呪文にわたる r_i + b_i の最大値として S の上限を計算します。 どの呪文も境界を定義しており、それを超えて両方のリソースを増加しても新しい制約を作成できず、最適な解決策はこれらの境界で発生するため、これで十分です。 
2. 0 からこの上限までの範囲で答え S を二分探索します。 私たちは、まだ実現可能な最大の S を探しています。 
3. 固定候補 S について、各呪文の間隔を構築します。 スペル i の場合、R に関して使用可能な領域は [r_i, S − b_i] ですが、r_i ≤ S − b_i の場合に限ります。 それ以外の場合、間隔は無効となり無視されます。 
4. すべての有効な間隔を開始点で並べ替えます。 この順序により、重複をマージし、連続したカバレッジを効率的に検出できるようになります。 
5. これまでにカバーした最も遠い点を維持しながら、ソートされた間隔をスイープします。 最初、カバレッジは 0 です。次の間隔が現在のカバレッジ境界の後に始まる場合、ギャップがあり、S はすぐに実行可能です。 
6. 間隔が隙間なく 0 から S まで適用範囲を完全に拡張する場合、[0, S] のすべての R が少なくとも 1 つの呪文を許可するため、S は実行不可能です。 
7. 二分探索内の実現可能性チェックを使用して、最大有効 S に収束します。 
8. S を返すか、実現可能性が無制限のままである場合を検出し、構造が有限最大制約が存在しないことを暗示している場合は INF を出力します。 

### なぜ効果があるのか

 固定の S の場合、すべての呪文は R 値の禁止された間隔に対応します。 「呪文が唱えられる」という条件は、まさに「R がこの範囲内にある」ということになります。 したがって、呪文が唱えられないことを保証することは、R がすべての間隔を回避することを保証することと同じです。 実現可能性チェックは、すべての間隔の和集合がセグメント [0, S] 全体をカバーしていないことを確認することに帰着します。 S では実現可能性が単調であるため、二分探索は有効です。S を増加させると間隔が拡大するだけで、間隔が縮小することはありません。そのため、特定の S が不可能な場合、より大きな S もすべて不可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def possible(n, spells, S):
    intervals = []
    for r, b in spells:
        l = r
        rr = S - b
        if l <= rr:
            intervals.append((l, rr))

    if not intervals:
        return True

    intervals.sort()
    covered = 0

    for l, r in intervals:
        if l > covered:
            return True
        if r > covered:
            covered = r
        if covered >= S:
            return False

    return True

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        spells = [tuple(map(int, input().split())) for _ in range(n)]

        mx = 0
        for r, b in spells:
            mx = max(mx, r + b)

        lo, hi = 0, mx
        ans = 0

        while lo <= hi:
            mid = (lo + hi) // 2
            if possible(n, spells, mid):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1

        print(ans)

if __name__ == "__main__":
    solve()
```コードは最初に、すべての呪文にわたる最大合計要件を使用して検索スペースを計算します。 実現可能性チェックは、各呪文を可能な赤の割り当て R にわたる間隔に変換します。ソート後、貪欲なスイープを実行して、呪文が唱えられなくなるギャップが存在するかどうかを検出します。 次に、二分探索により合計マナ S が最大化されます。 

よくある実装の落とし穴は、r_i > S − b_i の無効な区間は破棄する必要があるということを忘れていることです。 もう 1 つは、カバレッジの初期化の処理を誤っていることです。 R はゼロになる可能性があるため、0 から開始することが重要です。 貪欲なマージ ロジックは、区間結合カバレッジを直接エンコードします。 

## 実用的な例

 呪文 (3, 0)、(2, 2)、および (0, 3) の場合を考えてみましょう。 候補 S = 4 をテストします。 

| Spell | Interval [r, S-b] | Valid |
 | --- | --- | --- |
 | (3,0) | [3, 4] | yes |
 | (2,2) | [2, 2] | yes |
 | (0,3) | [0, 1] | yes |

 ソート後：[0,1]、[2,2]、[3,4]

 カバレッジは 0 から開始します。最初の間隔は [0,1] をカバーするため、カバレッジは 1 になります。次の間隔は 2 で始まり、これは 1 より大きいため、ギャップが生じます。 これは、S = 4 が実現可能であることを意味します。 トレースは、いくつかの間隔が存在するにもかかわらず、[0,4] を完全にはカバーしていないことを示しています。 

次に、呪文 (1,1)、(2,0)、(0,2) および S = 3 を使用したより厳密なケースを考えてみましょう。 

| Spell | 間隔 |
 | --- | --- |
 | (1,1) | [1,2] |
 | (2,0) | [2,3] |
 | (0,2) | [0,1] |

 ソート済み: [0,1]、[1,2]、[2,3]

 カバレッジは 0 から始まります。最初の間隔は 1 に拡張され、2 番目の間隔は 2 に拡張され、3 番目の間隔は 3 に拡張されます。カバレッジは 3 まで連続し、ギャップが存在しないことを意味します。 したがって、S = 3 は実行不可能です。 

これらの例は、実現可能性が、導出された区間の和集合にギャップが残るかどうかによって完全に決定される方法を示しています。

 ## 特殊なケース

 すべての呪文が (r, 0) などの 1 つの色のみに依存する場合、重要なエッジ ケースが発生します。 その状況では、導出された区間は常に r から始まり S まで広がり、実現可能性は最小の r の前に R ギャップが存在するかどうかに完全に依存します。 インターバルがプレフィックスを完全にカバーするか、スイープで検出されるプレフィックスをカバーしないままにするため、アルゴリズムはこれを処理します。 

もう 1 つのケースは、r_i + b_i が非常に小さい場合です。 たとえば、S = 2 の (1,1) は、単一点である区間 [1,1] を生成します。 スイープはこれを通過する必要があるカバレッジとして引き続き正しく処理し、ギャップ検出は有効なままです。 

最後に、S がすべての呪文に比べて非常に大きい場合、r_i > S − b_i が成立しないため、すべての間隔が無効になります。 その場合、アルゴリズムはすぐに実行可能を返します。これは、S が非常に大きいという事実に対応し、プレイヤーがどの呪文に対しても意味のある方法で両方の要件を同時に満たすことができないことを意味します。
