 ## 解決策
 ## 問題の理解

 最内層から最外層までの「入れ子構造」を記述するバイナリ文字列が与えられます。 文字列内の各文字は 1 つのレイヤーを表します。最初の文字は中心に対応し、次の各文字は前の構造をより大きな囲みフレームで包みます。 

タスクは、この構造の 2D ASCII 図面を構築することです。 最内層は、2 つの水平セルで構成される非常に小さな「コア」です。 すべてのレイヤーは外側に対称的に拡張され、外接する四角形が増加します。各レイヤーは、対応する 2 進数が 0 か 1 かに応じて特定の文字を使用して描画されます。文字の 1 つは肉を表し、もう 1 つはパンを表しますが、構築プロセスで重要なのは、各レイヤーが独自の塗りつぶし/境界線文字を持っていることです。 

ジオメトリは問題の重要な部分です。各新しいレイヤーは、構造の左側が開いており、右側の境界が垂直バー文字で明示的にマークされていることを除いて、すべての側面を 1 セルの太さの境界線で囲むことによって現在の Figure のサイズを増加させます。 これにより、各レイヤーが前のレイヤーよりも明らかに大きくなる、入れ子の「オープン サンドイッチ」形状が生成されます。 

この制約により、文字列の長さは最大 1000 までとなります。これは、セルごとにすべてをシミュレートしようとする単純な構造が、合計セル数がおよそ O(n^2) または O(n^2) であればまだ実現可能であることを意味します。これは、最終的なグリッド サイズが両次元の n に対して線形に増加し、合計出力サイズが約 O(n^2) になるためです。 文字列の長さが 2 次よりも悪いものは安全ではありません。 

いくつかの特殊なケースについては、明示的に説明する価値があります。 文字列の長さが 1 の場合、折り返しをまったく行わずに、2 つのセルの基本コアのみを出力します。 すべての文字が同じ場合、出力には依然として複数の異なるレイヤーがありますが、視覚的には構造が均一になります。 もう 1 つの微妙なケースは、左側が目に見える境界線文字で囲まれていないため、誤って右側の境界を左側にミラーリングするソリューションは、対称的な長方形を生成することになりますが、これは正しくありません。 

## アプローチ

 この問題を考える最も直接的な方法は、中心から外側に向かって構造を構築することです。 最も内側のレイヤーから始めます。これは常に 2 つの同一の文字の小さな水平セグメントです。 次に、文字列内の追加文字ごとに、そのレイヤーに関連付けられた文字を境界線に使用する大きな四角形で現在のグリッドを包みます。 

ブルート フォース シミュレーションでは、文字通り 2D グリッドを維持し、新しいレイヤーごとに新しい大きなグリッドを割り当て、前のコンテンツを中央にコピーできます。 コピー後、新しい境界を塗りつぶします。 これが機能するのは、入れ子構造が再帰的展開として明示的に定義されているためです。 ただし、このアプローチでは各ステップで大量のメモリの移動が再計算されます。 最終的なグリッドのサイズが n × n に比例し、それを n 回再構築すると、コピーが繰り返されるため、最悪の解釈では合計作業量は O(n^3) になります。 

重要な点は、グリッド全体を最初から再構築する必要がないということです。 代わりに、最初に最終的な寸法を直接計算し、最終的なグリッドを一度割り当ててから、各レイヤーの境界を正しい位置に配置することができます。 各レイヤーは長方形のフレームに対応しており、その座標は中心からの距離から導き出すことができます。 これにより、繰り返しの構築の問題が単一層の描画プロセスに軽減されます。 

したがって、最適な解決策は座標の問題になります。中心を決定し、各レイヤーが境界ボックスをどのように拡張するかを計算し、各レイヤーの境界線を 1 回だけ描画します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | レイヤーごとのリビルド | O(n^3) | O(n^2) | 遅すぎる |
 | 直接座標の構築 | O(n^2) | O(n^2) | 承認済み |

## アルゴリズムのチュートリアル

 各レイヤーがどこに配置されるかを事前計算することにより、シングルパスで最終的なグリッドを構築します。 

1. まず最終的な構造のサイズを決定します。 最内層は長さ 2 の小さな水平セグメントを占め、追加の層ごとに構造がすべての側面で 1 単位ずつ外側に拡張されます。 これは、高さと幅の両方がレイヤーの数に応じて線形に増加することを意味するため、最終的な寸法を n に比例して直接計算できます。 
2. 最初にプレースホルダー値が入力された 2D グリッドを割り当てます。 このグリッドには最終的に完全な描画が含まれるため、後でサイズを変更する必要はありません。 
3. 中心領域を最内層として定義します。 最初の文字の表現 (2 つの同一のシンボル) を中央の行に水平方向の中央に配置します。 これにより、すべての外側の層が展開するベースが確立されます。 
4. 文字列内の後続の各文字について、そのレイヤー インデックスを決定し、その境界四角形を計算します。 各層 i は、層 i-1 よりもあらゆる方向に 1 単位大きい長方形に対応します。 
5. 現在のレイヤーの上部と下部の境界をレイヤーの文字で塗りつぶします。 これにより、フレームの水平構造が作成されます。 
6. 概念的にはレイヤーの左側の境界を塗りつぶしますが、構造の左側が開いているため、そこに完全な垂直境界線は描画しません。 代わりに、内部が前のレイヤーによって正しく境界されていることを確認するだけです。 
7. レイヤーの右側の境界を垂直バー文字で埋めます。これは、構造の唯一の厳密な垂直閉鎖として機能します。 これにより、ネストされた形状が右側に視覚的に固定されたままになります。 
8. すべてのレイヤーが配置されるまで、このプロセスを繰り返します。 

すべてのレイヤーが描画された後、グリッドが行ごとに印刷されます。 

### なぜ効果があるのか

 各層は前の層の周囲に厳密な包含を形成し、拡張ルールにより、層 i が重なりあいまいさなしに層 i-1 を完全に囲むことが保証されます。 各レイヤーは中心からの固定幾何学的オフセットを使用して描画されるため、2 つのレイヤーが誤って干渉することはありません。 この構築は実質的に層にわたる帰納法です。層 i-1 が正しく配置されていると仮定すると、層 i はその周囲に 1 セルの境界線を追加し、正確さを維持し、ネストの不変条件を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    # Each layer expands the shape; final height and width are linear in n
    h = 2 * n
    w = 2 * n

    grid = [[' ' for _ in range(w)] for _ in range(h)]

    mid_row = h // 2
    mid_col = w // 2

    # base layer: two characters in the center
    base_char = '*' if s[0] == '0' else '-'
    grid[mid_row][mid_col - 1] = base_char
    grid[mid_row][mid_col] = base_char

    top = mid_row
    bottom = mid_row
    left = mid_col - 1
    right = mid_col

    # expand layer by layer
    for i in range(1, n):
        c = '*' if s[i] == '0' else '-'

        top -= 1
        bottom += 1
        left -= 1
        right += 1

        # top and bottom borders
        for j in range(left, right + 1):
            grid[top][j] = c
            grid[bottom][j] = c

        # left side is conceptually open, so we do not draw a full border

        # right boundary is closed with '|'
        for j in range(top, bottom + 1):
            grid[j][right] = '|'

        # ensure interior is preserved implicitly

    # print result (trim empty rows)
    for row in grid:
        line = ''.join(row).rstrip()
        if line:
            print(line)

if __name__ == "__main__":
    solve()
```実装では、中心から外側に向かって構造を構築します。 変数`top`、`bottom`、`left`、 そして`right`アクティブなレイヤーの現在の境界ボックスを追跡します。 各反復では、再帰的ラッピングの定義に一致して、このボックスがあらゆる方向に 1 単位ずつ拡張されます。 

最も微妙な設計上の選択は、以前のレイヤーを決して再構築しないことです。 代わりに、現在の境界を延長して新しいレイヤーのエッジを描画するだけです。 右境界は明示的に次のように記述されます。`|`一方、左側は垂直の壁を設けないことで視覚的に開いたままになっています。 

## 実用的な例

 次のような短い入力を考えてみましょう。`01`。 最初の文字は、小さな 2 セルの中心を生成します。 2 番目の文字は、上部と下部が塗りつぶされた大きな長方形でそれを包みます。`-`、右端にマークが付いている`|`。 

| ステップ | レイヤー | トップ | 下 | 左 | 右 | アクション |
 | --- | --- | --- | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 | c | c+1 | ベース "**" を配置します。 
| 1 | 1 | -1 | 1 | c-1 | c+2 | 境界線を追加し、右側の壁を設定します |

 このトレースは、中心コアを維持しながら構造がどのように対称的に成長するかを示しています。 

ここで考えてみましょう`001`。 最初の 2 つの層は肉であり、入れ子になったものを生成します。`*`領域、最後のレイヤーはパンの文字に切り替わります`-`、すべての内部構造を視覚的に支配する外側のフレームを生成します。 これは、レイヤーのアイデンティティが独立しており、各レイヤーが内部コンテンツを変更せずに独自の境界のみを完全にオーバーライドすることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | 各レイヤーは、すべてのレイヤーの合計面積が n | で 2 次となる完全な長方形の境界線を描画します。 
| スペース | O(n^2) | 最後のグリッドには、展開された構造体のすべての文字が格納されます。 

この制約により、n は最大 1000 まで許容されるため、二次構造は時間とメモリの制限内に問題なく収まります。 各セルは一定の回数書き込まれるため、定数係数は小さくなります。

 ## 特殊なケース

 次のような単一文字列の場合`0`の場合、アルゴリズムは基本 2 セル コアをすぐに配置し、拡張は実行しません。 ループはインデックス 1 から始まるため、境界調整は発生しないため、出力は最小限で正しいままになります。 

のような文字列の場合`0000`、すべてのレイヤーで同じ文字が使用されます。 各反復では境界が拡張されますが、視覚的には結果は同一のフレームのシーケンスになります。 このアルゴリズムは、レイヤー間の文字の違いには依存せず、幾何学的拡張のみに依存するため、引き続き機能します。 

次のような交互入力の場合`010101`、展開ごとに描画キャラクターが切り替わります。 各レイヤーは自身の境界線のみを完全に上書きするため、レイヤー間で干渉は発生せず、内側のレイヤーは変更されないという不変条件により正確さが保証されます。
