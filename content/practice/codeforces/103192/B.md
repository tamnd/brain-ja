 ## 解決策
 ## 問題の理解

 このタスクは、オペレーティング システムからの古典的なページ置換シナリオをモデル化します。 一連のページ リクエストが与えられます。各リクエストは、固定されたページ ユニバースからのページを要求します。 メモリの容量には限界があるため、一度に保存できるページ数は限られています。 要求されたページが現在メモリ内にない場合は常にページ フォールトが発生し、メモリがいっぱいの場合は、領域を空けるために既存の 1 ページを削除する必要があります。 

同じリクエスト シーケンスに対して 3 つの異なるエビクション ポリシーをシミュレートします。FIFO はメモリ内に最も長く存在したページを削除し、LRU は最も長期間使用されていないページを削除し、OPT は次回の使用が最も遠いページまたは二度と使用されないページを削除します。 ポリシーごとに、発生したページ フォールトの数をカウントします。 出力では、どのポリシーが障害の最小数を達成するかを報告し、その最小値も出力する必要があります。 複数のポリシーが関連付けられている場合は、そのうちの 1 つを印刷できます。 

入力サイズの制約が十分に大きいため、エビクションの選択ごとに単純なシミュレーションを慎重に実装する必要があります。 リクエストの長さは最大 10 万に達する可能性がありますが、個別のページの数は十分に少ないため、補助データ構造を使用した直接シミュレーションが可能です。 この組み合わせは、各アルゴリズムをポリシーごとにほぼ直線的な時間で実装し、メモリ状態のフル スキャンの繰り返しを回避する必要があることを強く示唆しています。 

OPT シミュレーションには微妙な落とし穴があります。 ミスのたびに前方にスキャンしてメモリ内のすべてのページの次の使用を見つけるという単純なアプローチでは、最悪の場合、三次的な動作に低下します。 もう 1 つのよくある間違いは、そのページが二度と使用されない可能性があることを忘れていることです。これにより、そのページが即座に最適な削除候補となるはずです。 

エッジ ケースには、すべてのリクエストが同一であるシーケンス、メモリ サイズが 1 のシーケンス、およびすべてのページが異なるためすべてのアクセスがエラーとなるシーケンスが含まれます。 このような場合、FIFO、LRU、および OPT は予測可能な方法で異なる動作をし、「再び見つかりません」または誤ったタイムスタンプ更新の誤った処理により誤った比較が行われます。 

## アプローチ

 各ポリシーの直接シミュレーションは概念的に簡単です。 現在のメモリ内容を表すリストまたはセットを維持し、リクエストを 1 つずつ処理します。 ヒットすると、ポリシーに応じてメタデータが更新されます。 ミスの場合は、フォールト カウンタをインクリメントし、スペースが存在する場合はページを挿入するか、ルールに従ってページを削除します。 

FIFO は最も単純です。ページのキューを挿入順に維持します。 ミスが発生するたびに、新しいページが最後に挿入されます。 メモリがいっぱいの場合は、前面から取り外します。 これが機能するのは、FIFO が到着時間のみに依存し、挿入順序を超えて使用パターンを追跡する必要がないためです。 

LRU は、各ページの最終アクセス時間を追跡することで、このアイデアを拡張します。 アクセスするたびに、タイムスタンプが更新されます。 エビクションが必要な場合は、最終アクセス時間が最も短いページが選択されます。 メモリ サイズ k が最大 100 であるため、メモリ内のすべてのページに対する単純な検索はすでに十分に高速であり、ミスごとに k 要素をスキャンすることは許容されます。 

OPT は将来の知識を必要とする唯一のアルゴリズムです。 現在メモリ内にある各ページについて、次にいつ使用されるかを知る必要があります。 エビクションのたびに各ページのリクエスト リストを前方にスキャンする単純な再計算では、遅すぎます。 重要な観察は、後方スイープを使用するか、次回使用ポインターを維持することによって、シーケンス内の各位置について、各ページの次の出現を事前計算できることです。 その後、O(k) 内の事前に計算された次回使用インデックスを比較することによって、各エビクションを決定できます。 

3 つのカウンタがすべて計算されると、答えは単にその中の最小値になります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | FIFO シミュレーション | O(n) | O(m + k) | 承認済み |
 | LRUシミュレーション | O(nk) | O(m + k) | 承認済み |
 | 次回使用前処理を備えた OPT | O(nk) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 同じリクエスト シーケンスで FIFO、LRU、OPT を個別に計算します。 

### FIFO シミュレーション

 1. 空のキューとメンバーシップ追跡用のセットを初期化します。 
2. 各リクエストについて、ページがすでにセット内にある場合は、続行する以外は何も行いません。 
3. セットになく、空きがある場合は、キューに挿入してセットします。 
4. セット内になく、メモリがいっぱいの場合は、キューの先頭を削除し、セットからも削除してから、新しいページを挿入します。 

これが機能する理由は、FIFO の決定が到着順序のみに依存するため、キューの不変式がエビクションの優先順位を直接表すためです。 

### LRU シミュレーション

 1. 現在メモリ内にある各ページの最終アクセス時刻を格納する辞書を維持します。 
2. リクエストごとに、リクエストがすでにメモリ内にある場合は、その最終アクセス時刻を現在のインデックスに更新します。 
3. メモリに存在せず、スペースがある場合は、現在のインデックスを使用して挿入します。 
4. それがメモリ内になく、メモリがいっぱいの場合は、メモリ内のすべてのページをスキャンして最小の最終アクセス時間を見つけて削除し、新しいページを挿入します。 

正確さは、グローバル シーケンス順序に基づいて、最小のタイムスタンプが常に最も最近使用されていないページに対応するという事実から得られます。 

### OPTシミュレーション

 1. 配列を事前計算する`next_pos[i]`これは、位置 i のページが再び表示される次のインデックス、または二度と表示されない場合は無限大を意味します。 
2. 現在メモリ内にある一連のページを維持します。 
3. 各ページの次の出現インデックスを維持します。 
4. リクエストごとに、事前計算されたテーブルを使用して次のリクエストを更新または割り当てます。 
5. ミスの場合、メモリがいっぱいの場合は、メモリ内のページを反復処理し、次の出現インデックスが最大のものを選択します。 

重要なアイデアは、将来の知識が位置ごとに 1 つの事前計算された値に削減されるため、各エビクションは k 値に対する極大クエリになるということです。 

### なぜ効果があるのか

 どの時点でも、FIFO は挿入順序によってページをランク付けし、LRU は最終アクセス時間によってページをランク付けし、OPT は次の使用位置によってページをランク付けします。 各アルゴリズムは、前処理によって解決される OPT を除き、将来の更新に依存しない一貫した順序付け基準を維持します。 エビクションの決定では常にポリシー定義の順序に基づいて極値が選択されるため、シミュレートされた状態は各ポリシーの理論的定義と同等のままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**18

def simulate_fifo(req, k):
    from collections import deque
    q = deque()
    s = set()
    faults = 0

    for x in req:
        if x in s:
            continue
        faults += 1
        if len(s) < k:
            s.add(x)
            q.append(x)
        else:
            old = q.popleft()
            s.remove(old)
            s.add(x)
            q.append(x)

    return faults

def simulate_lru(req, k):
    mem = {}
    faults = 0

    for i, x in enumerate(req):
        if x in mem:
            mem[x] = i
        else:
            faults += 1
            if len(mem) < k:
                mem[x] = i
            else:
                victim = min(mem, key=mem.get)
                del mem[victim]
                mem[x] = i

    return faults

def simulate_opt(req, k):
    n = len(req)
    nxt = [n] * n
    last = {}
    for i in range(n - 1, -1, -1):
        x = req[i]
        nxt[i] = last.get(x, n)
        last[x] = i

    mem_next = {}
    faults = 0

    for i, x in enumerate(req):
        if x in mem_next:
            mem_next[x] = nxt[i]
        else:
            faults += 1
            if len(mem_next) < k:
                mem_next[x] = nxt[i]
            else:
                victim = max(mem_next, key=mem_next.get)
                del mem_next[victim]
                mem_next[x] = nxt[i]

    return faults

def main():
    n, m, k = map(int, input().split())
    req = list(map(int, input().split()))

    fifo = simulate_fifo(req, k)
    lru = simulate_lru(req, k)
    opt = simulate_opt(req, k)

    best = min(fifo, lru, opt)

    if best == fifo:
        print("FIFO")
    elif best == lru:
        print("LRU")
    else:
        print("OPT")

    print(best)

if __name__ == "__main__":
    main()
```FIFO 部分はセットとペアになったキューに依存するため、メンバーシップ チェックは一定時間行われます。 LRU 部分は、タイムスタンプを値として持つページ値をキーとする辞書を使用します。メモリ サイズが小さいため、最小値を見つけるのは効率的であるため、これで十分です。 

OPT の実装は、次の出現位置を逆に計算する前処理パスによって駆動されます。 これにより、コストのかかる「スキャンフォワード」操作が、リクエストごとの定数検索に変わります。 

## 実用的な例

 メモリ サイズが 2、リクエストが 2 である小さなシーケンスを考えてみましょう。`1 2 3 1 2`。 

### FIFO トレース

 | ステップ | リクエスト | メモリ | 立ち退き | 障害 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | [1] | - | 1 |
 | 2 | 2 | [1,2] | - | 2 |
 | 3 | 3 | [2,3] | 1 | 3 |
 | 4 | 1 | [3,1] | 2 | 4 |
 | 5 | 2 | [1,2] | 3 | 5 |

 FIFO の動作は、再利用パターンを無視して、到着順に厳密にページを循環します。 

### LRU トレース

 | ステップ | リクエスト | メモリ (最後に使用された) | 立ち退き | 障害 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | {1:1} | - | 1 |
 | 2 | 2 | {1:1、2:2} | - | 2 |
 | 3 | 3 | {2:2,3:3} | 1 | 3 |
 | 4 | 1 | {3:3,1:4} | 2 | 4 |
 | 5 | 2 | {1:4,2:5} | 3 | 5 |

 LRU は、タイムスタンプの順序と一致する、長期間使用されていないページの削除を優先します。 

### OPT トレース

 | ステップ | リクエスト | 次に | を使用します。 メモリ | 立ち退き | 障害 |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | 4時の未来 | [1] | - | 1 |
 | 2 | 2 | 5時の未来 | [1,2] | - | 2 |
 | 3 | 3 | 決して | [1,3] | 2 | 3 |
 | 4 | 1 | 完了 | [1,3] | - | 3 |
 | 5 | 2 | 決して | [2,3] | 1 | 4 |

 OPT は、すぐに必要になるページの削除を一貫して回避し、代わりに、将来使用されないページや最も再利用されないページを破棄します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(nk) | FIFO、LRU、OPT はそれぞれ、ミスごとに最大 k ページをスキャンします。k ≤ 100 であれば、これが可能になります。 
| スペース | O(n + m) | OPT 前処理は次回使用する情報を保存し、すべてのシミュレーションは現在のメモリ状態を追跡します。 

この制約により、トリプル シミュレーションでも十分な速度が維持されることが保証されます。 メモリ サイズ境界 k は、高度なデータ構造を使用せずに単純な実装を可能にする重要な要素です。

 ## 特殊なケース

 重大なエッジケースは、ページが OPT に二度と表示されない場合です。 たとえば、メモリ サイズ 2 とリクエスト シーケンスの場合`1 2 3 4`、ページを処理するとき`3`、 両方`1`そして`2`将来の用途がありません。 アルゴリズムはそれらの次回使用値を無限大として割り当て、エビクションではどちらかを選択できます。 今後の参照がないページは同様に削除するのが最適であるため、これは OPT の定義と一致します。 

もう 1 つのエッジ ケースは、次のようなアクセス パターンが繰り返されることです。`1 2 1 2 1 2`メモリサイズは 2 です。 FIFO と LRU は両方ともウォームアップ後の障害を回避し、OPT も追加の障害を生成しません。 これにより、すべてのポリシーが安定した再利用パターンに収束していることが確認され、矛盾がある場合は、タイムスタンプの更新が正しくないか、次回使用ポインターの更新に失敗していることを示します。
