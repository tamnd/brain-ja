 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列があります。 単一の非負の値を選択することもできます`x`、それを最初の配列のすべての要素に追加し、すべての結果を剰余として取得します。`m`。 

この変換後は、要素の順序は関係ありません。 変換された配列を任意に再配置することができます。 タスクは最小のものを見つけることです`x`変換されたマルチセットは、2 番目の配列で表されるマルチセットとまったく同じになります。 

重要な詳細は、位置ではなくマルチセットを比較しているということです。 2 つの配列に同じ頻度の同じ値が含まれている場合、それらはいくつかの並べ替え後に等しいとみなされます。 

制約は異常に明らかです。 配列の長さは最大 2000 ですが、`m`と同じ大きさにすることができます`10^9`。 可能なすべての値を反復するソリューション`x`探索空間が大きすぎるため不可能です。 一方で、`n = 2000`十分に小さいので、`O(n² log n)`解決策は完全に受け入れられます。 制限時間内で約 800 万件の操作を管理できます。 

いくつかの特殊なケースでは、不注意な実装が簡単に壊れてしまう可能性があります。 

重複する値を考慮します。```
n = 3, m = 5
a = [0, 0, 0]
b = [2, 2, 2]
```正しい答えは、`2`。 

すべての要素が個別であると仮定し、周波数ではなく位置を一致させようとする解決策は失敗します。 

ラップアラウンドモジュロ演算も間違いの原因です。```
n = 2, m = 10
a = [8, 9]
b = [0, 1]
```正しい答えは、`2`なぜなら：```
(8 + 2) mod 10 = 0
(9 + 2) mod 10 = 1
```モジュロ処理を行わずに通常の減算を使用すると、誤って負のシフトが生成されます。 

いくつかのシフトがもっともらしいと思われる場合、より微妙なケースが発生します。```
n = 3, m = 7
a = [0, 1, 2]
b = [1, 2, 3]
```両方の配列はすでにソートされており、有効なシフトは次のとおりです。`1`。 マルチセット全体を検証しない貪欲なマッチング戦略では、別の候補を誤って受け入れる可能性があります。 

この問題では、少なくとも 1 つの有効な答えが存在することが保証されていますが、それでも最小のものを見つける必要があります。 

## アプローチ

 簡単な強引なアイデアは、可能なすべてのシフトを試すことです`x`から`0`に`m - 1`。 候補ごとに、次のすべての要素を変換します。`a`、結果の配列をソートし、ソートされたバージョンと比較します。`b`。 

これは、条件が値の複数セットにのみ依存するため機能します。 ソートされた変換された配列がソートされたターゲット配列と等しい場合、何らかの順列が存在します。 

問題はサイズです`m`。 以来`m`到達できる`10^9`, すべてのシフトをチェックすることは完全に不可能です。 

重要な観察は分類から得られます。 

させて：```
A = sorted(a)
B = sorted(b)
```何らかのシフトがあったとします`x`有効です。 申請後`x`モジュロ`m`、の最小要素`B`の何らかの要素に由来する必要があります`A`。 

仮定する`A[i]`最小の要素になります`B[0]`。 それから：```
(A[i] + x) mod m = B[0]
```それは意味します```
x = (B[0] - A[i] + m) mod m
```あらゆるポジションについて`i`、この式は 1 つの可能なシフトを生成します。 あるのは`n`そんな候補者たち。 

なぜそれで十分なのでしょうか? なぜなら、有効な変換では、次の要素の一部が`A`の最小値にマップする必要があります`B`。 対応するシフトがこれらの中に表示されます`n`候補者たち。 

今では問題ははるかに小さくなりました。 次の要素の一致から導出されるすべての候補シフトを生成します。`A`に`B[0]`。 各候補について、次のすべての値を変換します。`A`、結果を並べ替えて、と比較します`B`。 

すべての有効な候補のうち、最小のものを返します。 

しかないので、`n`候補者と各検証費用`O(n log n)`、全体の複雑さは次のようになります。`O(n² log n)`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(m · n log n) | O(n) | 遅すぎる |
 | 最適 | O(n² log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`、`m`、および 2 つの配列。 
2. 両方の配列をソートし、次のように保存します。`A`そして`B`。 
3. インデックスごとに`i`で`A`、候補シフトを計算します```
x = (B[0] - A[i] + m) mod m
```これは強制に相当します`A[i]`ターゲットマルチセット内の最小値になります。 
4. この候補シフトを次のすべての要素に適用します。`A`:```
transformed[j] = (A[j] + x) mod m
```5. 変換された配列を並べ替えます。 
6. ソートされた変換された配列を次と比較します。`B`。 

それらが等しい場合、このシフトは有効です。 
7. 発生した最小の有効なシフトを維持します。 
8. その最小シフトを出力します。 

### なぜ効果があるのか

 仮定する`x*`が正解です。 

申請後`x*`、変換された値は、次のように表されるマルチセットを正確に形成します。`B`。 の最小値`B`、つまり`B[0]`、何らかの要素から来ている必要があります`A[i]`。 

その要素については、```
(A[i] + x*) mod m = B[0]
```再配置すると```
x* = (B[0] - A[i] + m) mod m
```したがって`x*`生成された候補の 1 つです。 

すべての候補は、変換されたマルチセットを明示的に構築し、それを次のものと比較することによってチェックされます。`B`。 候補は、必要なマルチセットを正確に生成する場合にのみ受け入れられます。 

すべての有効なシフトが検査され、最小の有効なシフトが返されるため、アルゴリズムは常に正しい答えを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    a.sort()
    b.sort()

    answer = m

    for v in a:
        x = (b[0] - v) % m

        transformed = sorted((num + x) % m for num in a)

        if transformed == b:
            answer = min(answer, x)

    print(answer)

if __name__ == "__main__":
    solve()
```問題は実際にはマルチセットの比較にあるため、最初のステップは両方の配列をソートすることです。 ソートすると、マルチセットの等価性は通常の配列の等価性になります。 

ループオーバー`a`すべての候補シフトを生成します。 各候補は、ソートされたソース配列の一部の要素がソートされたターゲット配列の最小要素にマップされる必要があるという観察に基づいています。 

各候補について、コードはモジュラー演算を使用してすべての要素を変換します。 表現```
(num + x) % m
```正確にこの形式で使用する必要があります。 モジュロ演算を忘れると、ラップアラウンドの場合に失敗します。 

変換された値は比較前に並べ替えられます。 変換が正しい場合でも、モジュロ演算により要素の順序が変更される可能性があるため、並べ替えなしで比較すると不正確になります。 

変数`answer`これまでに見つかった最小の有効なシフトを格納します。 この問題では、単に有効なシフトを求めるのではなく、最小の有効なシフトを求めます。

```変換されたマルチセットは次のようになります。`[0,1]`。 すべての候補シフトはモジュロで計算されるため、負の差が問題を引き起こすことはありません。`m`。

```それは成功します。
