 ## 解決策
 ## 問題の理解

 平面内に端から端まで配置された剛セグメントのチェーンが与えられます。 各セグメントの長さは固定されており、連続するセグメントは回転可能なジョイントによって接続されています。 最初は、チェーン全体が真っ直ぐで垂直です。これは、すべてのセグメントが正の y 方向に沿って上向きであることを意味します。 

次に、一連の回転コマンドを適用します。 各コマンドは、セグメント S と S+1 の間のジョイントを選択し、セグメント S+1 から始まるサフィックス全体をそのジョイントの周りの剛体として回転させます。 初期のセグメントは所定の位置に固定されたままですが、後のすべてのセグメントは内部構造を維持しながら一緒に回転します。 

すべての回転を処理した後、タスクは最後のセグメントの終点の最終座標を計算することです。 

この制約により、最大 100,000 のセグメントと 100,000 の操作が許可されます。 各回転後にすべてのセグメントの位置を再計算するソリューションでは、操作ごとに O(N) 個のセグメントを更新する必要があり、最悪の場合は O(NK) 回の作業が必要となり、これは実現可能な限界をはるかに超えています。 これにより、サフィックスのローテーション更新によるプレフィックスの安定性をサポートするデータ構造が必要になります。 

複数の回転が重複するサフィックスに影響を与える場合、微妙な問題が発生します。 単純なアプローチでは角度を最初から繰り返し再計算し、浮動小数点誤差が蓄積され、最終的には顕著にドリフトする可能性があります。 もう 1 つの間違いは、各セグメントの一貫したグローバル角度表現を維持せずに、回転を独立したローカル変換として扱うことです。 

## アプローチ

 直接シミュレーションでは、セグメント方向の配列が角度で保持されます。 各操作では、S+1 以降のすべてのセグメントを A 度回転するため、クエリごとに O(N) エントリを更新してから位置を再計算します。 これは正しいですが、最悪の場合は 10^10 の更新に達するため、遅すぎます。 

重要な観察は、最終エンドポイントに対する各セグメントの寄与がその方向ベクトルにおいて線形であるということです。 各セグメントの角度がわかっている場合、端点は方向 theta_i における長さ L_i のベクトルの累積和にすぎません。 問題は、回転を適用すると、接尾辞全体の theta_i が変化することです。 

各セグメントを個別に追跡するのではなく、チェーン内の各位置は、その前のジョイントに影響を与えるすべての操作による累積的な回転を受けるという考えを維持します。 これは、視点を逆転することを示唆しています。影響を受けるすべてのセグメントを更新するのではなく、ジョイントごとに、その後のすべてのセグメントにどの程度の追加回転が適用されるかを維持します。 「回転デルタ」上のフェンウィック ツリーまたはセグメント ツリーを使用すると、各セグメントの最終的な角度が適用可能なすべての更新の合計になるように角度の増分を保存できます。 

範囲の追加とポイントのクエリをサポートする構造を構築した後、セグメントを 1 回反復して、現在のグローバル角度を維持し、各セグメントのベクトルを加算することにより、最終的な位置を計算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(NK) | O(N) | 遅すぎる |
 | 角度デルタのあるフェンウィック/セグメント ツリー | O((N+K) log N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 角度をチェーンに沿って蓄積される値として扱います。 各セグメント i には、標準デカルト座標の 90 度に対応する、最初は上向きの基本方向があります。 

ジョイントを表すインデックス上にフェンウィック ツリーを維持し、各位置から開始してどれだけの追加の回転が適用されるかを保存します。

1. サイズ N+1 のフェンウィック ツリーをすべて 0 で初期化します。 この構造体は、サフィックスに影響を与える累積的な角度シフトを保存します。 これは、各更新がセグメントの連続したサフィックスに適用されるため必要です。 
2. 最初のセグメントの初期方向を 90 度に設定します。 これは、標準座標における最初の垂直上方向と一致します。 
3. 各回転コマンド (S、A) をデルタ更新に変換します。 S+1 以降のすべてのセグメントが一緒に回転するため、位置 S+1 から始まる A 度を追加します。 S が 0 の場合、セグメント 1 から開始する回転を適用します。この変換により、サフィックスの回転が範囲の更新に変換されます。 
4. インデックス S+1 から始まるフェンウィック ツリー上で A の範囲加算を実行します。 これにより、セグメント i ≥ S+1 の累積角度にこの回転が確実に含まれるようになります。 
5. すべてのコマンドを処理した後、セグメント 1 から N まで反復して最終的なジオメトリを計算します。走行角度変数を維持します。 
6. 各セグメント i について、位置 i のフェンウィック ツリーをクエリして、このセグメントに適用される追加の回転の合計を取得します。 この値を走行角度に加算します。これは、セグメント i の絶対方向を表します。 
7. x のコサインと y のサインを使用して角度を方向ベクトルに変換し、L_i を乗算して、現在のエンドポイント座標に加算します。 

機能する理由: 各回転は連続するサフィックスに影響し、各セグメントの最終的な向きは、その前またはその位置のジョイントに適用されるすべての回転の正確な合計となります。 フェンウィック ツリーはこれらの回転の差分表現を保存し、すべてのセグメントが正しい累積角度を正確に受け取ることを保証します。 ベクトルの加算は線形であるため、セグメントを最終角度で順番に処理すると、中間状態を明示的にシミュレートすることなく、正確なエンドポイントが再構築されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import math

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0.0] * (n + 2)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0.0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def solve():
    N, K = map(int, input().split())
    L = list(map(int, input().split()))

    fw = Fenwick(N + 2)

    for _ in range(K):
        S, A = map(int, input().split())
        fw.add(S + 1, A)

    x = 0.0
    y = 0.0
    angle = 90.0

    for i in range(N):
        angle += fw.sum(i + 1)
        rad = math.radians(angle)
        x += L[i] * math.cos(rad)
        y += L[i] * math.sin(rad)

    print(f"{x:.10f} {y:.10f}")

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、角度の増分を差分構造として保存します。 セグメント インデックスはローテーションのプレフィックス累積に直接対応するため、各コマンドは S+1 で適用されます。 重要な点は、セグメントごとに完全な角度を決して保存しないことです。 代わりに、前に歩きながらその場でそれらを計算します。 

度からラジアンへの変換はベクトル計算の瞬間にのみ行われ、更新中に繰り返される三角関数の累積誤差を回避します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((N + K) log N) | 各回転はフェンウィック更新であり、各セグメント角度クエリは対数 |
 | スペース | O(N) | フェンウィック ツリーと入力ストレージ |

 ## 特殊なケース

 重要なエッジ ケースは、S = 0 の場合であり、回転がチェーン全体に適用されることを意味します。 その場合、更新は 0 ではなくインデックス 1 から開始する必要があります。このシフトが誤って実装されると、セグメント 1 が除外され、チェーン全体が誤ってドリフトすることになります。 たとえば、2 つのセグメントからなるチェーンを 90 度回転すると、両方のセグメントが水平に整列するように回転します。 最初のセグメントを含めないと、構造が即座に壊れます。 

別のエッジ ケースには、複数の完全な 360 度回転が含まれます。 角度は 1 つの円を超えて累積されますが、コサインとサインは周期的であるため安定しています。 ただし、更新ごとに角度を積極的に正規化しようとすると、一貫性がないと中間キャンセル エラーが発生する可能性があります。 正しいアプローチでは、正規化を完全に回避し、評価時に三角関数の周期性に依存します。 

最終的なエッジ ケースは、多くの小さな回転を伴う大きな N です。 角度が繰り返し再計算されると、セグメントごとの直接更新では浮動小数点誤差が大量に蓄積されます。 デルタのみを保存し、セグメントごとに 1 回適用することで、誤差の累積をセグメントごとに 1 回の評価に減らし、数値の安定性を許容範囲内に保ちます。
