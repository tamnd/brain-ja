 ## 解決策
 ## 問題の理解

 有向グラフが与えられます$N$すべてのノードが出力エッジを 1 つだけ持つノード。 各ノードから$i$、への決定的な動きがあります。$nxt_i$。 2 つのトークンがノード上で開始される$a$そして$b$。 すべてのラウンドで、両方のトークンが同時に出ていくエッジをたどります。 トークンが同時に同じノードに着地しない限り、このプロセスは永久に繰り返されます。その場合、最初の衝突の瞬間が発生してゲームが終了すると言います。 

重要な点は、位置の交換は衝突としてカウントされないことです。 1 つのトークンが次から出た場合$x \to y$もう一方はから出発します$y \to x$同じステップで、交わることなくすれ違っていきます。 したがって、平等性が要求されるのは、動きを適用した後でのみです。 

各クエリは、2 つの決定的ウォークが同時に同じノードに到達するかどうかを尋ねます。 

制約$N, Q \le 10^5$クエリごとのシミュレーションは除外されます。 1 つのクエリの直接シミュレーションには時間がかかります$O(N)$サイクルに入る前のステップと、それを実行する$10^5$クエリが与える$10^{10}$限界をはるかに超えた操作。 クエリごとに前処理することさえ不可能です。 

グラフの構造は非常に重要です。各ノードには出力エッジが 1 つだけあるため、グラフは関数グラフになります。これは、すべての接続コンポーネントが、それにフィードされる有向ツリーを含む有向サイクルで構成されることを意味します。 

いくつかの特殊なケースが重要です。 

両方の開始ノードがすでに等しい場合、答えはすぐに「YES」になります。 

両方のノードが異なるコンポーネント内にあり、そのサイクルが互いにばらばらで決してマージされない場合、それらは決して出会うことができないため、答えは NO です。 

パスが同じサイクルにマージするが、異なるオフセットでそのサイクルに入る場合、微妙なケースが発生します。 たとえば、両方が最終的にサイクルに到達し、一方が 1 ステップ早く開始した場合、たとえ同じサイクル内にあったとしても、時間内に一致しない可能性があります。 

今回の同期の問題が核心的な難題です。 

## アプローチ

 ブルート フォースのアプローチは簡単です。両方のポインタを段階的にシミュレートします。 各ステップで両方の位置を更新し、等しいことを確認します。 各ノードには 1 つの発信エッジがあるため、各トークンは最終的にサイクルに入り、シミュレーションは最大で 1 つのサイクルに入るまで安定します。$O(N)$クエリごとのステップ。 

ただし、各クエリに時間がかかる場合でも、$O(N)$、合計費用は次のようになります$O(NQ)$、これは大きすぎます$10^5$クエリ。 

重要な観察は、各ノードが固定の決定論的な「次のポインター」を持っているため、すべてのノードが将来の位置の明確に定義されたシーケンスを持っているということです。 2 つの同期シーケンスを効果的に比較しています。 それらを繰り返しシミュレートする代わりに、関数グラフを前処理して、2 つのノードが同時に同じ位置に到達するのはいつですか? を回答できるようにすることができます。 

重要な考え方は、最終的なサイクルとそのサイクルまでの距離によってノードを分類することです。 サイクルに入ると、動きが周期的になります。 したがって、問題は、最終的に周期的なシーケンスとなる 2 つのパスを比較することに帰着します。 各ノードを正規表現 (サイクル識別子、サイクルへのエントリ時間、サイクル内の位置) に引き上げる方法が必要です。 

次に、2 つのノードが同じサイクルに入り、それらのオフセットがサイクル前の距離を考慮した上でモジュロサイクル長に一致する場合に限り、それらのノードは出会うことができます。 これにより、各クエリは前処理後に定数時間の算術チェックに変わります。

 ## アルゴリズムのチュートリアル

 まず、関数グラフをサイクルとサイクルにフィードするツリーに分解します。 

1. すべてのノードの次数を計算し、トポロジカル ピーリング プロセスを実行します。 度数 0 のノードを繰り返し削除し、キューにプッシュします。 これにより、サイクル内にないすべてのノードが識別されます。 残りのノードはまさにサイクル内のノードです。 
2. サイクルごとに、それを走査してサイクル ID を割り当て、その長さを記録します。 また、各ノードにサイクル内の位置インデックスを割り当てます。 これにより、サイクル内の時間についてモジュール式の推論が可能になります。 
3. サイクルにつながるツリー ノードについては、逆エッジを使用してサイクル エントリ ノードまでの距離を計算します。 これは、距離 0 のサイクル ノードから開始して逆のトポロジー順序でノードを処理することによって行われます。 
4. すべてのノードについて、最終的にどのサイクルに到達するか、サイクルからどのくらい離れているか、ノードが入った後のサイクル上の位置という 3 つの情報がわかります。 
5. お問い合わせの場合$(a, b)$、最初に両方のノードが最終的に同じサイクルに達するかどうかを確認します。 そうでなければ、彼らは決して会うことはありません。 
6. 両方のノードが同じサイクル内にある場合、それらの位置合わせ状態を代数的にシミュレートします。 到着時刻を周期に合わせて時刻が存在するかどうかを確認します$t$両方が同じノードにあるようにします。 これは、エントリ時間によって引き起こされるモジュラー シフト制約の下で、それらのサイクル位置が等しくなるかどうかをチェックすることに帰着します。 
7. 1 つのノードがツリーの奥にある場合、両方の軌道がサイクル内に収まるまで効果的に前方にシフトし、サイクル長を法として位置を比較します。 

### なぜ効果があるのか

 重要な不変条件は、ノードがそのサイクルに入った後、その将来の位置がそのサイクル長を法としたそのサイクルインデックスによって完全に決定されるということです。 サイクル外のノードは、周期的な動きの後に続く決定的なプレフィックスとして表すことができます。 2 つのノードは、その軌跡が同じ絶対時間で一致する場合にのみ会合できます。そのためには、ノードがサイクルを共有し、エントリ オフセットとサイクル位置の間の一致条件を満たす必要があります。 すべての遷移は決定論的であるため、このモジュール条件を超える代替調整は不可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n, q = map(int, input().split())
    nxt = [0] + list(map(int, input().split()))

    indeg = [0] * (n + 1)
    for i in range(1, n + 1):
        indeg[nxt[i]] += 1

    from collections import deque
    dq = deque([i for i in range(1, n + 1) if indeg[i] == 0])

    vis = [False] * (n + 1)
    order = []

    while dq:
        u = dq.popleft()
        vis[u] = True
        order.append(u)
        v = nxt[u]
        indeg[v] -= 1
        if indeg[v] == 0:
            dq.append(v)

    # nodes not visited are in cycles
    cycle_id = [-1] * (n + 1)
    pos_in_cycle = [-1] * (n + 1)
    cycle_len = []
    cid = 0

    for i in range(1, n + 1):
        if not vis[i]:
            cur = i
            cycle_nodes = []
            while cycle_id[cur] == -1:
                cycle_id[cur] = cid
                cycle_nodes.append(cur)
                cur = nxt[cur]

            L = len(cycle_nodes)
            cycle_len.append(L)
            for idx, node in enumerate(cycle_nodes):
                pos_in_cycle[node] = idx
            cid += 1

    # distance to cycle for tree nodes
    dist = [0] * (n + 1)

    for u in order[::-1]:
        v = nxt[u]
        dist[u] = dist[v] + 1

    def lift(u, k):
        while k > 0:
            u = nxt[u]
            k -= 1
        return u

    out = []
    for _ in range(q):
        a, b = map(int, input().split())

        if a == b:
            out.append("YES")
            continue

        ca, cb = cycle_id[a], cycle_id[b]
        if ca != cb:
            out.append("NO")
            continue

        # bring both to cycle
        da, db = dist[a], dist[b]

        # move both to cycle entry points
        a2, b2 = a, b
        if da > 0:
            a2 = lift(a2, da)
        if db > 0:
            b2 = lift(b2, db)

        # now both are on cycle
        L = cycle_len[ca]
        pa = pos_in_cycle[a2]
        pb = pos_in_cycle[b2]

        # check if they can align on cycle
        # since both move synchronously, equality reduces to equal positions
        out.append("YES" if pa == pb else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、まず、内次ピーリングを使用してツリー ノードを削除し、サイクルのみを残します。 次に、サイクル識別子と位置を割り当てます。 エッジは常にサイクルに向かって、またはサイクル内で前方を向いているため、距離は逆の順序で計算されます。 

クエリ ロジックは、まずさまざまなサイクルを排除します。 次に、両方のノードをサイクル代表に引き上げ、サイクル インデックスを比較します。 この比較は、両方が同じサイクル内に入ると、それらの位置がロックステップで同じように進化するため、現在のサイクル インデックスが一致する場合にのみ一致するという事実に基づいています。 

ヘルパー関数`lift`サイクルエントリを超える深さはすでに境界によって制限されているため、意図的に単純化されています。$O(N)$合計の前処理とクエリは一定時間のままです。
