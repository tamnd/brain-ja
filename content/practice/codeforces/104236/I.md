 ## 解決策
 ## 問題の理解

 私たちは一列に並べられた一連の動物を与えられます。 各動物には、種ラベルとスキル値という 2 つの属性があります。 タスクは、この線のすべての連続セグメントを考慮し、各セグメントのスコアを計算することです。 セグメントのスコアは、セグメント内のスキル値の合計と、そのセグメントに出現する個別の種の数という 2 つの量によって決まります。 セグメントの貢献度は、スキルの合計と、個別の種の数の非常に大きな乗、具体的には 3366 乗の積です。 

出力は、すべての可能なサブ配列に対するこれらの寄与の合計です。 

制約はすぐに問題を形成します。 動物の数は最大 100,000 であるため、すべての部分配列を列挙すると (二次関数になるため) 遅すぎます。 セグメント内の個別の種の数をすばやく計算できたとしても、最悪の場合、セグメントの数だけで約 50 億となり、O(N^2) 法はすでに除外されます。 

重要な構造の詳細は、種 ID が 50 で制限されていることです。この小さなアルファベット サイズは、種の存在に対するビットマスキングまたは状態圧縮を示唆するため、高速な解決策を可能にする主な手段です。 

素朴なアプローチでは、各サブ配列を列挙し、異なる種を追跡するための頻度マップを維持し、スキルの累計を維持し、寄与度を計算します。 拡張子ごとの周波数マップの更新は O(1) ですが、すべての O(N^2) セグメントに対してそれを行うのはまだ大きすぎるため、これは失敗します。 

2 番目の微妙な落とし穴は、指数 3366 をセグメントごとに直接計算するものとして扱うことです。 べき乗剰余演算は高速ですが、すべての部分配列に対してそれを繰り返すと、すでに不可能な複雑さが倍増します。 

## アプローチ

 ブルート フォース手法は簡単です。左のエンドポイントを固定し、右のエンドポイントを拡張し、種の頻度配列を維持し、個別の種をカウントし、スキルの累計を維持します。 各拡張機能により回答が更新されます。 これにより、必要な値が正しく計算されますが、約 N^2 回の更新が実行されます。これは、最悪の場合、制限をはるかに超えて、およそ 10^10 回の操作に相当します。 

主な観察は 2 つの事実から来ています。 まず、種の値は最大 50 までと小さいため、個別の種の数は最大でも 50 です。第 2 に、べき乗により個別の数を直接処理するのが難しくなりますが、代わりに個別の種のセットごとに部分配列をグループ化するという観点から考えることができます。 

すべての部分配列を直接合計する代わりに、視点を反転します。 種のセット S を修正します。個別の種セットが正確に S であるすべての部分配列を考慮します。そのような各部分配列について、その寄与は (部分配列内のスキルの合計) に |S|^3366 を乗算します。 

|S| 以来 実際の位置ではなくセットのサイズのみに依存するため、問題を、考えられるサブセット サイズ k ごとに、サイズ k を持つ個別の種セットのすべてのサブ配列にわたるスキルの合計の合計に k^3366 を乗算する計算に分割できます。 

したがって、問題は、1 から 50 までの各 k について、個別の種の数が正確に k であるすべてのサブ配列にわたるサブ配列の合計の合計を計算することに帰着します。 

正確に k 個の異なる要素を持つ部分配列をカウントすることは直接的には加算的ではないため、これはまだ自明ではありません。 ただし、「最大 k 個の個別」カウントを使用して、標準の包含/除外構造に切り替えることができます。 

F(k) を、個別の種の数が最大でも k であるすべての部分配列の合計として定義します。 したがって、正確に k の答えは F(k) から F(k-1) を引いたものになります。 残りのタスクは、すべての k に対して F(k) を効率的に計算することです。

F(k) を計算するには、配列に対してスライディング ウィンドウを使用し、最大で k 個の異なる種を含むウィンドウを維持します。 各右端点について、ウィンドウに最大で k 個の異なる種が含まれるような最小の左端点を見つけます。 各固定右端点 r について、r で終わるすべての有効な部分配列は、l から r まで始まるものです。ここで、l は最小の有効な左境界です。 この範囲にわたるすべての部分配列の合計の合計が必要です。 

部分配列の合計を O(1) で計算できるように、スキル値のプレフィックス合計を維持します。 次に、各 r について、接頭辞合計に対する接頭辞合計演算を使用して、すべての有効な l からの寄与を定数時間で累積します。 

これを 1 から 50 までの k ごとに繰り返します。k が小さいため、全体の複雑さは許容範囲内になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N^2) | お(50) | 遅すぎる |
 | 最適 | O(50・N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 固定制限 k に対して、最大で k 個の異なる種を含むすべての部分配列の合計寄与を計算する関数を定義します。 

1. サブ配列の合計を一定時間内に取得できるように、スキル値のプレフィックスの合計を事前計算します。 これにより、範囲にわたるスキルの貢献度を迅速に集計できます。 
2. 固定 k の場合、スライディング ウィンドウ [l, r] とウィンドウ内の種の周波数配列を維持します。 r を段階的に展開し、頻度を更新し、現在内部に存在する異なる種の数を追跡します。 
3. 新しい要素を追加して別個の種の数が k を超えて増加する場合は、ウィンドウが再び有効になるまで l を前方に移動します。 l が移動するたびに頻度を更新し、数がゼロになった時点で種を削除します。 
4. ウィンドウが有効になったら、位置 r ごとに、r で終わり、l から r までの任意のインデックスで始まるすべての部分配列の寄与を計算します。 このような各サブ配列の合計はプレフィックス合計を使用して表現でき、すべての開始点を反復するのではなく、プレフィックス合計の差の式を使用してそれらを集計します。 
5. この計算の結果を F(k) として保存します。 
6. 1 から 50 までのすべての k について F(k) を計算した後、正確に k 個の異なる種についての寄与を F(k) - F(k-1) として導出します。 
7. 各寄与に k^3366 モジュロ MOD を乗算し、累積して最終的な答えを求めます。 

なぜそれが機能するのかは、2 つの不変条件に関係しています。 まず、スライディング ウィンドウは常に、異なる種の数を制限 k 内に保つ最小の左境界を表すため、r で終わる有効な部分配列はすべて 1 回だけカウントされます。 第 2 に、プレフィックス合計の集計により、有効なサブ配列ごとに、そのスキル合計がその (k, r) ペアの合計累積に 1 回だけ含まれることが保証されます。 これらを組み合わせると、F(k) が最大でも k 個の異なる種を含むすべての部分配列の省略や重複のない正確な合計であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def mod_pow(a, e):
    return pow(a, e, MOD)

def compute_at_most_k(c, s, k):
    n = len(c)
    freq = [0] * 51
    distinct = 0
    l = 0

    # prefix sums of s
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + s[i]

    total = 0

    # We also maintain prefix of prefix sums for fast range sum of subarray sums
    pref2 = [0] * (n + 1)
    for i in range(n):
        pref2[i + 1] = pref2[i] + pref[i + 1]

    for r in range(n):
        x = c[r]
        freq[x] += 1
        if freq[x] == 1:
            distinct += 1

        while distinct > k:
            y = c[l]
            freq[y] -= 1
            if freq[y] == 0:
                distinct -= 1
            l += 1

        # sum of subarray sums for all l' in [l, r]
        # sum_{i=l..r} sum_{j=i..r} s[j]
        # equals pref2[r+1] - pref2[l] - (r-l+1)*pref[l]
        length = r - l + 1
        contrib = (pref2[r + 1] - pref2[l]) - length * pref[l]
        total += contrib

    return total

def solve():
    n = int(input())
    c = []
    s = []
    for _ in range(n):
        ci, si = map(int, input().split())
        c.append(ci)
        s.append(si)

    max_k = 50
    F = [0] * (max_k + 1)

    for k in range(1, max_k + 1):
        F[k] = compute_at_most_k(c, s, k)

    ans = 0
    for k in range(1, max_k + 1):
        exact = F[k] - F[k - 1]
        ans = (ans + exact * mod_pow(k, 3366)) % MOD

    print(ans % MOD)

if __name__ == "__main__":
    solve()
```コードは最初にプレフィックス合計を構築して、定数時間の範囲合計クエリを可能にします。 機能`compute_at_most_k`最大 k 個の異なる種の制約を強制するスライディング ウィンドウを実装します。 微妙な部分は、二重プレフィックス配列です。`pref2`、多くの部分配列の合計の合計を閉じた形式の式に変換します。 これがないと、計算は r ごとの 2 次ループに劣化します。 

最後のループでは、最大 k 個の値間の差を計算して正確な個別のカウントを分離し、必要な電力重み付けを適用します。 

## 実用的な例

 サブアレイを手動で追跡できる、少数の動物を含む小さなアレイを考えてみましょう。 

入力：```
3
1 2
2 1
1 3
```F(k) 値を概念的に計算します。 

k = 1 の場合、単一種の部分配列のみが寄与します。 有効な部分配列はそれぞれ [1]、[2]、[3] です。 それぞれが独自のスキル合計を提供します。 

| r | l | r | で終わる有効な部分配列 貢献 |
 | --- | --- | --- | --- |
 | 0 | 0 | [2] | 2 |
 | 1 | 1 | [1] | 1 |
 | 2 | 2 | [3] | 3 |

 したがって、F(1) = 6 となります。 

k = 2 の場合、この構成では長さ 3 のセグメントには最大 2 つの異なる種が存在するため、すべての部分配列が許可されます。 

合計を列挙します。 

| 部分配列 | 合計 |
 | --- | --- |
 | [1] | 2 |
 | [2] | 1 |
 | [3] | 3 |
 | [1,2] | 3 |
 | [2,3] | 4 |
 | [1,2,3] | 6 |

 したがって、F(2) = 19 となります。 

次に、正確な貢献度:

 k=1 は 6、k=2 は 13 を与えます。最終的な答えは、これらを累乗で組み合わせたものです。 

これは、F(k) がどのように構造的制約をきれいに分離するかを示しています。
