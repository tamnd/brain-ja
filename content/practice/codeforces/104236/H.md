 ## 解決策
 ## 問題の理解

 さまざまなポリシーの環境影響スコアを表す整数の配列が与えられます。 各クエリでは、この配列の固定セグメント内を調べ、長さが指定された範囲内にある部分配列のみを考慮するように求められます。 このようなすべての有効な部分配列の中で、最大の平均値を持つものが必要であり、その平均の下限を出力します。 

クエリを言い換えると便利な方法は、完全に内側にある連続したブロックを選択しているということです。$[l, r]$、ただし、間の長さのみを選択するように制約されます。$x$そして$y$。 このようなブロックごとに、合計を長さで割った値を計算し、可能な最大値を求めます。 

制約$N, Q \le 10^4$クエリごとの部分配列の合計を間隔にわたって二次時間で再計算するアプローチはすでに除外されています。 ナイーブ$O(N^3)$このアプローチはクエリごとにすべてのサブ配列をチェックすることになるため、すぐには実行できません。 平$O(N^2)$クエリごとに約$10^{12}$限界をはるかに超えた最悪の場合の動作。 これは、サブ配列情報を前処理するか、データ構造を使用して多くの平均を効率的に評価する必要があることを強く示唆しています。 

負の値を使用すると、微妙な問題が発生します。 よくある間違いは、サブ配列が長くなると常に平均的な動作が向上する、またはスライディング ウィンドウが単調に動作すると仮定することです。 負の数値の場合、長いセグメントの合計がより大きくても、より短いセグメントから最良の平均が得られる可能性があります。 

2 番目の微妙なエッジ ケースは、最適なセグメントが許容される長さの境界に正確に位置する場合です。 実装が長さだけをチェックする場合$x$または$y$、または長さの単調性を仮定すると、最良の平均が厳密に範囲内で発生するケースを見逃します。 

失敗の直感の例: 配列が次の場合$[-5, 100, -4]$クエリの長​​さが 2 に制限されている場合、最適なセグメントは次のとおりです。$[100, -4]$平均は 48 であり、単一要素の推論やグローバル最大値の仮定はありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 クエリごとに、有効な開始インデックスをすべて列挙します。$i$で$[l, r]$、それぞれについて$i$、すべての終了インデックスを列挙します$j$そのような$x \le j-i+1 \le y$そして$j \le r$。 各部分配列の合計を計算し、最大平均を追跡します。 接頭辞の合計を使用すると、各部分配列の合計は次のようになります。$O(1)$したがって、各クエリにはコストがかかります$O((r-l+1)\cdot y)$となり、$O(N^2)$最悪の場合、クエリごとに。 

と$Q = 10^4$、このアプローチは明らかに遅すぎます。 

重要な観察は、制限された長さのスライド間隔にわたって比率を最大化していることです。 これは、答えの二分探索によって問題を実現可能性のチェックに変換できる古典的な設定です。 直接最大化するのではなく、$\frac{\text{sum}}{\text{len}}$、値を推測します$mid$、平均が少なくとも以下である有効な部分配列が存在するかどうかをテストします。$mid$。 

これにより、条件が次のように変換されます。$$\frac{\text{sum}}{\text{len}} \ge mid \quad \Longleftrightarrow \quad \text{sum} - mid \cdot \text{len} \ge 0$$さて、それぞれの要素$a_i$変換された値になります$b_i = a_i - mid$。 問題は、次の長さの部分配列が存在するかどうかを確認することになります。$[x, y]$内部$[l, r]$変換された合計は負ではありません。 

これは、プレフィックス合計とプレフィックス値のスライド最小値を使用して、クエリごとに線形時間でチェックできます。 制限された長さの制約は、最大でも次のサイズのウィンドウ内で最小プレフィックス合計を維持することで処理できます。$y-x+1$。 

答えに対する二分探索とこの実現可能性チェックを組み合わせます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(QN^2)$|$O(1)$| 遅すぎる |
 | 二分探索 + スライディング ウィンドウ |$O(Q \cdot N \log A)$|$O(N)$| 承認済み |

 ## アルゴリズムのチュートリアル

 答えに対して二分探索を使用して、各クエリを個別に解決します。 

1. お問い合わせの場合$(l, r, x, y)$、注目を部分配列に限定します$a_l \dots a_r$。 これにより、配列の無関係な部分の再計算が回避され、すべての計算がクエリ ウィンドウに対してローカルに行われるようになります。 
2. 関数を定義します`check(mid)`クエリ ウィンドウ内に、平均が少なくとも`mid`。 これは、最適化問題を決定問題に変換する中心的な削​​減ステップです。 
3. 内部`check(mid)`、変換された値に対してプレフィックスの合計を構築します。$b_i = a_i - mid$。 部分配列に合計がある場合$\ge 0$この変換された配列では、元の平均制約が満たされます。 
4. プレフィックスの合計を維持します$P[i]$、 どこ$P[i]$インデックスまでの変換された値の合計です$i$。 サブアレイ$[i, j]$合計を変換しました$P[j] - P[i-1]$。 
5. 各右端点について$j$、有効な左端点を見つけたいと考えています。$i$長さの制約が$x \le j-i+1 \le y$が成立する。 これは次と同等です。$$j-y \le i \le j-x$$したがって、インデックスのスライディング ウィンドウ内の最小プレフィックス合計が必要です。$i-1$。 
6. 繰り返していくうちに$j$、最小プレフィックス値の候補を格納するプレフィックス インデックスに対する単調デキューを維持します。 この構造により、最適な有効な左境界を取得できるようになります。$O(1)$償却時間。 
7. いつでも$P[j] - \min(P[i-1]) \ge 0$、次の場合は true を返します`check(mid)`。 
8.二分探索をします`mid`考えられるすべての平均をカバーするのに十分な範囲にわたって、通常は$-10^9$に$10^9$、実現可能性チェックを使用して検索をガイドします。 
9. 最終的な答えは、実現可能な最大の下限です。`mid`。 

### なぜ効果があるのか

 正確さは、平均に関する標準的な凸性の議論に依存します。 変革$a_i - mid$実現可能性の順序を維持します。部分配列には少なくとも平均値があります。$mid$まさにその変換された合計が負ではないときです。 プレフィックス合計に対するスライディング ウィンドウにより、長さの制約に関するすべての有効なサブ配列が何らかのプレフィックスの差によって表されることが保証されます。 実行可能性が単調であるため、二分探索は収束します。$mid$は達成可能ですが、それより小さい値も達成可能です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

INF = 10**30

def check(arr, l, r, x, y, mid):
    n = len(arr)
    pref = [0] * (n + 1)

    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + (arr[i - 1] - mid)

    dq = deque()

    for j in range(l + x - 1, r + 1):
        left_min_i = j - y
        if left_min_i < l:
            left_min_i = l

        # maintain deque for prefix indices i-1
        idx = j - x
        if idx >= l:
            while dq and pref[dq[-1]] >= pref[idx]:
                dq.pop()
            dq.append(idx)

        while dq and dq[0] < left_min_i - 1:
            dq.popleft()

        if dq:
            best_i_minus_1 = dq[0]
            if pref[j] - pref[best_i_minus_1] >= 0:
                return True

    return False

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    for _ in range(q):
        l, r, x, y = map(int, input().split())
        l -= 1
        r -= 1

        lo, hi = -10**9, 10**9
        ans = lo

        for _ in range(35):
            mid = (lo + hi) / 2
            if check(a, l, r, x, y, mid):
                ans = mid
                lo = mid
            else:
                hi = mid

        print(int(ans))

if __name__ == "__main__":
    solve()
```コードはまず、各クエリを可能な平均値に対する二分検索に変換します。 各中間点について、変換された配列のプレフィックスの合計を構築し、デキューを使用して有効なサブ配列が存在するかどうかをチェックして、許可されたウィンドウ内の最小プレフィックス値を維持します。 インデックスは、プレフィックス インデックスが一致するように慎重にシフトされます。$i$で始まる部分配列に対応します$i+1$、ここがオフバイワンの間違いのほとんどが発生する場所です。 

二分探索では浮動小数点演算が使用されますが、最終的な答えの下限値のみが必要なので、ここではこれで十分です。 反復回数 (約 35) により、整数の正確さに必要な精度をはるかに超える精度が保証されます。

 ## 特殊なケース

 最適なセグメントが許容される最小長に正確に一致する場合、微妙なエッジ ケースが発生します。 その場合、両端キューには、以下に対応するインデックスが正しく含まれている必要があります。$j-x$。 実装で挿入が遅れたり、プレフィックス インデックスの位置がずれたりすると、最適な候補が見つからなくなります。 

すべての数値が負の場合、別のケースが発生します。 正しい答えはやはり最大平均であり、長さの制約が許す限り、これが最小の負の要素となります。 変換された実行可能性チェックは、肯定的なものを想定していないため、引き続き機能します。 

最後に、いつ$x = y$の場合、問題は固定長のスライディング ウィンドウの最大平均に帰着します。 このアルゴリズムは、1 つのウィンドウ サイズのみをチェックするようにきれいに退化しており、プレフィックス差分の定式化は変更なしで引き続き適用されます。
