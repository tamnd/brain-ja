 ## 解決策
 ## 問題の理解

 賞品を表す数直線上の一連の個別の点が与えられます。 2 人が固定位置からスタートします。1 人は左側の位置 1 から、もう 1 人はずっと右の位置 106 です。毎秒、どちらかが左右に 1 歩ずつ移動でき、誰かが賞品の位置に正確に着地すると、その賞品は即座に回収されます。 すべての賞品を回収する必要があり、各賞品はどちらかに割り当てることができます。 二人が同時に移動するため、合計時間は最後に集めた賞品をいつ受け取るかによって決まります。 

課題は、2 人の間で賞品をどのように割り当てるか、すべての賞品を集める時間を最小限に抑えるためにどのように移動するかを決定することです。 

重要な制約は、賞金が最大 100,000 個あり、ポジションは 10^6 まで大きくできることです。 これは、2 人の間で賞品の割り当てをすべて試行するような解決策を除外します。これは、n で指数関数的になり、実行可能な限界をはるかに超えるためです。 配列のパーティションにわたる二次動的計画法でさえ遅すぎます。 

すべての賞品が開始位置の 1 つに非常に近い位置にある場合、微妙なエッジ ケースが発生します。 たとえば、すべての賞が 1 に近い場合、最適解は、たとえ位置 106 から開始したとしても、最右の人を完全に無視します。逆に、すべての賞が 106 に近い場合、左の人はほとんど無関係です。 賞金ごとに最も近い開始位置のみに基づいて割り当てる単純な貪欲は、グローバルな順序付け効果を無視するため失敗します。 

もう 1 つの注意が必要なケースは、賞品が中央に分散している場合です。 たとえば、2、50、51、100 のような順位では、各賞に対するローカルな決定により不必要な後戻りが発生し、合計時間が大幅に増加する可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各賞を左の人または右の人に割り当てようとします。 次に、割り当てごとに、各人が割り当てられたポイントをソートされた順序で訪問する場合の両方の移動時間の最大値として必要な時間を計算します。 割り当てを修正したとしても、移動コストの計算は線形ですが、2^n 個の割り当てがあるため、これは 2^n の n 倍となり、10^5 までの n ではまったく実行不可能です。 

重要な観察は、賞品がすでにポジションごとに分類されており、両方の人が同じ線に沿って独立して移動していることです。 これは、最適なソリューションの構造が任意のインターリーブに依存するのではなく、ソートされたリストを主に一方が処理するプレフィックスともう一方が処理するサフィックスにどのように分割するかに依存することを意味します。 

任意の割り当てという観点から考える代わりに、k の左側にあるすべての賞品が調整された方法で処理され、右側にあるすべての賞品が他のプレイヤーによって処理されるように分割点 k を検討します。 動きは一次元であり、両方のエージェントが継続的に動くため、最適な戦略は事実上、「左利き」と「右利き」の間の境界を選択することになります。 

どのスプリットでも、最後の賞品を受け取った後に開始位置に戻る必要がないことを考慮して、各人が自分のサイドをカバーするのにかかる時間を計算します。 答えは、すべての分割ポイントにわたる最小可能な最大時間です。 

これにより、問題は指数関数的な割り当てから n 個の可能な分割のチェックへと軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n · n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 賞品は指定どおりに並べ替えられると想定します。

1. 0 から n までの分割インデックス k を考えます。ここで、賞 [0..k-1] は左の人によって処理され、[k..n-1] は右の人によって処理されます。 これは、責任を線に沿って分割する可能なすべての方法をモデル化します。 
2. 左側の人の場合、賞品 [0..k-1] を扱う場合、収集する必要がある最も遠い点に到達するだけでよいため、所要時間は 1 からそのセグメント内の最も遠い割り当てられた賞品までの距離になります。 これは max(|1 - a[0]|, |1 - a[k-1]|) ですが、セグメントはソート順に連続しているため、支配的なコストはエンドポイントに到達しています。 
3. 106 から始まる正しい人が賞品 [k..n-1] を扱う場合、その時間はセグメント内の最も近い点と最も遠い点に到達することによって決定されます。 動きは直線的であるため、彼らができる最善のことは、より近い端に向かって進み、掃討することです。 これは max(|106 - a[k]|, |106 - a[n-1]|) になります。 
4. 各分割 k について、2 回の最大値を計算します。 これは、両方の人がその割り当てを完了するまでにかかる時間を表します。 
5. すべての k の最小値を取得します。 

より注意深く単純化すると、冗長なケースが削除されます。左側のセグメントのコストは主に左側の最後の要素に到達するかどうかに依存し、右側のセグメントのコストは右側の最初の要素に到達するかどうかに依存します。 これにより、分割ごとに O(1) の計算が可能になります。 

### なぜ効果があるのか

 核となる不変条件は、ある次元では、人が点の連続セグメントを収集すると、最適なパスは単調であるということです。つまり、開始点からセグメントに向かって移動し、不必要に引き返さずに通過します。 ライン全体で割り当てを交互に行うソリューションは、合計時間を増やすことなく責任を単一の境界分割にグループ化するソリューションに変換できます。これは、余分な交差は距離を増やすだけであり、収集される利益は増加しないためです。 これにより、検索スペースが n+1 個の単調パーティションに縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # prefix and suffix boundaries
    INF = 10**18
    
    ans = INF
    
    for k in range(n + 1):
        # left person takes [0..k-1]
        if k == 0:
            left_time = 0
        else:
            left_time = abs(1 - a[k-1])
        
        # right person takes [k..n-1]
        if k == n:
            right_time = 0
        else:
            right_time = abs(106 - a[k])
        
        ans = min(ans, max(left_time, right_time))
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、すべての分割点が直接評価されます。 ラインに沿って移動すると中間点が自動的にカバーされるため、左側の人のコストは、割り当てられたプレフィックスの最も遠い点によってのみ決定されます。 適切な人物のコストも同様に、サフィックスの最も近い点に到達するまでに 106 から削減されます。 

k に対するループでは、1 人がすべてを処理する縮退ケースを含む、すべての有効なパーティションが考慮されます。 

境界インデックスには注意が必要です。 k = 0 または k = n の場合、一方の側には賞品が割り当てられておらず、そのコストはゼロです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import inf

    n = int(sys.stdin.readline())

    INF = 10**18
    ans = INF
    
    for k in range(n + 1):

 ## 特殊なケース

 賞品が 1 つだけの場合、アルゴリズムは 2 つの意味のある分割を評価し、それを左または右に割り当てます。 最小値は正確には、より近い開始位置からの距離になります。 

すべての賞品が位置 1 の近くにある場合、左の人がほとんどまたはすべての賞品を扱う分割では小さな値が得られますが、右の人に割り当てるとコストが大幅に増加します。 アルゴリズムは、両側の最大値を最小化するため、自然に左重点分割を選択します。 

すべての賞金が 106 付近にある場合、対称的な動作が適用されます。 分割 k = 0 または小さな k 値が優先され、適切な担当者がほとんどの作業を確実に処理します。 

賞品が均等に分配される場合、中間の分割ポイントにより、両方のエージェントの移動距離の不均衡が最小限に抑えられます。 k を介したループはこのバランス ポイントを直接キャプチャし、貪欲なローカル割り当てが必要ないことを保証します。
