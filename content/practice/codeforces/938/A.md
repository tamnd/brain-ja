 ## 解決策
 ## 問題の理解

 このタスクでは、母音を含むローカル ルールに従って特定の文字が削除される文字列の変換について説明します。 私たちは単語を与えられ、隣接する 2 つの母音がなくなるまで繰り返し修正します。 変更ルールは具体的です。直前に別の母音がある母音を見つけた場合は、2 つの母音のうち早い方を削除します。 

これを解釈する便利な方法は、母音が連続して出現できないように文字列が簡略化されているということです。 ただし、このプロセスは単純なグローバル クリーンアップではありません。 これは順次的です。削除は以前に形成された隣接関係に依存し、文字を削除すると新しい隣接母音ペアが作成される可能性があり、これも処理する必要があります。 

入力は、単一の小文字のラテン文字の文字列で構成されます。 出力は、このような削除がすべて適用された後の最終的な安定した形式になります。 

文字列の長さは最大 100 であるため、線形または二次シミュレーションは許容されます。 文字列を繰り返しスキャンして文字を削除する単純なアプローチでも、問題なく合格できます。 さらに重要なのは、削除後の隣接関係の動的な性質を処理することです。 

いくつかの特殊なケースが重要です。 

エッジ ケースの 1 つは、「aeiou」のような完全に母音で構成される文字列です。 削除するたびに新しい隣接関係が形成され、母音が 1 つだけ残るまでこのプロセスが続きます。 単一パスで最初に出現したペアのみを削除する不注意な実装は、停止が早すぎます。 

もう 1 つの特殊なケースは、「abaeio」のような交互パターンです。 ここでは母音と母音の隣接性のみが問題となり、子音は区切り文字として機能します。 連続する位置だけでなく、繰り返される母音をグローバルに扱うという誤ったアプローチにより、有効な文字が誤って削除されてしまいます。 

最後に、長さ 1 または 2 の文字列は簡単に終了するか、チェックが 1 回だけ必要になりますが、スキャン ロジックで off-by-one エラーが発生することがよくあります。 

## アプローチ

 直接的な総当たりシミュレーションでは、説明どおりのプロセスが正確に反映されます。 文字列を左から右に繰り返しスキャンし、連続する 2 つの母音を見つけるたびに、前の母音を削除してスキャンを再開します。 これは問題文に文字通り従っているため、正しいです。 

ただし、このアプローチでは、二次関数またはさらに悪い動作に低下する可能性があります。 「aaaaaa」のような文字列では、削除するたびに文字列がシフトされ、再スキャンが強制的に行われるため、約 O(n²) 回の操作が必要になります。 ここで n は小さいですが、このアプローチは概念的に非効率的であり、推論するのが難しくなります。 

重要な点は、スキャンを最初からやり直す必要がないということです。 代わりに、現在の有効なプレフィックスを表す構造を維持しながら、文字列を 1 回のパスで処理できます。 新しいキャラクターはそれぞれ、最後に保持したキャラクターとのみ対話します。 両方が母音の場合、前の母音を破棄します。 それ以外の場合は通常どおり追加します。 

これにより、問題は、スタックのような出力バッファを維持する古典的なストリーミング削減に変わります。

 | --- | --- | --- | --- |

 | スタックベースのシングルパス | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 増加する結果リストを維持しながら、文字を左から右に処理します。

1. 現在有効な文字を格納する空のリストを初期化します。 これは、修正されたプレフィックスを表すスタックとして機能します。 
2. 文字が母音であるかどうかをチェックするヘルパー条件を定義します。母音は a、e、i、o、u、y です。 この分類はアルゴリズム全体で固定されています。 
3. 入力文字列内の各文字を順番に繰り返します。 
4. 各文字について、結果リストが空でないかどうか、および結果の現在の文字と最後の文字の両方が母音であるかどうかを確認します。 この条件が当てはまる場合、禁止された連続母音ペアがあることを意味します。 
5. 条件が true の場合、結果リストから最後の文字を削除します。 ルールでは前の母音の削除が指定されているため、現在の文字はまだ追加しません。 
6. 削除の可能性を処理した後、現在の文字を結果リストに追加します。 
7. すべての文字が処理されるまで続行します。 
8. 結果リストを文字列に結合して出力します。 

最後の文字だけをチェックする理由は、それ以前のすべての構造がすでに有効であることが保証されているためです。 違反には、新しく追加されたキャラクターと最後に生き残ったキャラクターが含まれている必要があります。 

### なぜ効果があるのか

 不変条件は、文字列の各接頭辞を処理した後、結果リストには連続母音のないその接頭辞のバージョンが含まれるということです。 各ステップではこのプロパティが保持されます。 新しい文字が追加される場合、新たに違反となる可能性があるのは、その文字と最後に保持された文字との間だけです。 両方が母音の場合、以前の文字はすでに検証されており、現在の文字と新しい隣接関係を形成できないため、前の文字を削除すると、以前の構造に影響を与えることなく有効性が復元されます。 

これにより、スキャンの終了までに、連続した母音が出力のどこにも残らなくなることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

VOWELS = set("aeiouy")

def solve():
    n = int(input())
    s = input().strip()
    
    res = []
    
    for ch in s:
        if res and ch in VOWELS and res[-1] in VOWELS:
            res.pop()
        res.append(ch)
    
    print("".join(res))

if __name__ == "__main__":
    solve()
```実装はプロセスのスタック解釈に正確に従います。 重要な微妙な点は、母音をポップした後も現在の文字を追加するということです。これは、ルールでは現在の母音ではなく、ペア内の前の母音のみが削除されるためです。 

リストをスタックとして使用すると、二次的なオーバーヘッドが発生する可能性がある文字列の再構築の繰り返しが回避されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys

    n = int(input())

 ## 特殊なケース

 「aeiouy」のような完全に母音が多い文字列の場合、アルゴリズムは新しい母音が到着するたびに前の母音を繰り返し削除します。 「a」から始めて、「e」を追加すると「a」が削除され、「e」が残り、次に「i」が「e」を削除します。 最終的な結果は単なる「y」であり、完全に連続するチェーンでは 1 つの母音のみが存続できるという不変条件が確認されます。 

「a」などの単一文字入力の場合、ループが 1 回実行され、スタックは空から開始され、文字が直接追加されます。 比較は行われず、出力は変更されないままです。これは、境界条件によって無効な削除がトリガーされないことを示しています。
