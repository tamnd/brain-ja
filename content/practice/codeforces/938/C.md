 ## 問題の理解

 問題は、行列を直接構築することを求めているのではなく、スライディング ウィンドウ制限の下でバイナリ グリッドの最適なパッキング特性について推論することです。 

私たちが想像するのは、$n \times n$グリッドは 0 と 1 で埋められます。 この制約は、連続するものを取得した場合に、$m \times m$このグリッド内の正方形には、少なくとも 1 つのゼロが含まれている必要があります。 したがって、作成することは禁止されています$m \times m$オールワンブロックはグリッド内のどこにでもあります。 

固定ペアの場合$(n, m)$、すべての有効なグリッドには、可能な最大数の 1 があります。 この値は、素の構造がいくつあるかにのみ依存します。$m \times m$戦略的にゼロを配置することで領域を「ブロック」できます。 タスクは逆転します。希望する回答値が与えられます。$x_i$そして、任意のペアを構築する必要があります$(n_i, m_i)$最適な 1 の数が正確に等しくなるように$x_i$。 

テスト数という点では制約は少ないですが、テスト数自体は$10^9$。 これにより、行列をシミュレートしたり、行列を列挙して推論したりする試みは即座に排除されます。$n, m$。 解決策は、答えが次の関数としてどのように動作するかについての閉じた形式の理解に依存する必要があります。$n$そして$m$、そしてその関数を逆にします。 

素朴なアプローチでは、小さなことを試みるでしょう$n, m$ペア、グリーディ タイリングまたはグリッド上の DP によって 1 の最大数を計算し、ターゲットと一致します$x$。 それは 2 つの点で失敗します。 まず、単一の答えを計算します。$(n, m)$ペアはオーバーラップのグローバル構造に依存するため、それ自体が高価です$m \times m$窓。 第二に、たとえ高速だったとしても、$n, m \le 10^9$は大きすぎます。 

より微妙な失敗は、どちらのパラメータでも単純な方法で答えが単調であると仮定することによって発生します。 たとえば、固定する$m$そして増加しています$n$は、禁止された部分行列間の重複によって境界効果が生じるため、単純に答えを線形にスケーリングしません。 

重要な問題は、応答関数が区分的に線形であることです。$n$一度$m$は固定されており、それを反転するには、その斜面の構造を理解する必要があります。 

## アプローチ

 ブルートフォースの視点は、ペアごとにそれを想像することから始まります$(n, m)$を確保しながら、できるだけ密に配置するよう努めます。$m \times m$ブロックには少なくとも 1 つのゼロが含まれています。 直接シミュレーションでは、貪欲に配置し、いっぱいになるたびにバックトラックしようとします。$m \times m$ブロックはすべて1になります。 完全なグリッドの妥当性チェックに限定したとしても、すべてのグリッドを検査する必要があります。$O(n^2)$窓と各窓の費用$O(m^2)$、につながる$O(n^2 m^2)$構成ごとに異なりますが、これは完全に不可能です。 

構造的な洞察は視点を反転することです。 禁止されているすべて 1 の正方形という観点から考えるのではなく、ゼロがどのようにしてすべてを「カバー」できるのかという観点から考えます。$m \times m$部分行列。 それぞれのゼロは、次のセットに正確に影響します。$m \times m$それを含む正方形。 最適な構造では、最終的に周期的なタイルが形成されます。ゼロは間隔のあるグリッドとして機能します。$m$、すべてを保証します$m \times m$領域は少なくとも 1 つのゼロと交差します。 この構造が最適化されると、残りの構造は覆われていないすべてのセルを埋めるだけです。 

これにより、1 の最大数を求める簡単な式が得られます。 分割すると、$n \times n$グリッドを一定のサイズのブロックに分割する$m \times m$、最悪の場合の最適な配置は、そのようなブロックごとに単一のゼロを周期的に配置するように動作します。 必要なゼロの数はおよそ$\lceil \frac{n}{m} \rceil^2$、そしてそれぞれのゼロは、適用範囲を強制する以上の追加の構造を「主張」しません。 したがって、答えは次のようになります。$$\text{ones} = n^2 - \lceil n/m \rceil^2$$正確な導出は、最適なタイリング構成ではブロックごとに 1 つのゼロが必要かつ十分であることを観察することに依存し、ゼロをより密に詰めても制約は改善されず、不必要に 1 が削減されるだけです。 

これで逆転問題が明らかになりました。 私たちは与えられています$x = n^2 - k^2$ある整数に対して$k = \lceil n/m \rceil$。 任意のペアを構築する必要があります$(n, m)$これが成り立つように。 それは整数を見つけることになります$n, k$と$n^2 - k^2 = x$、つまり$(n-k)(n+k) = x$、そして選択します$m$と一致する$k = \lceil n/m \rceil$。 シンプルで常に有効な構造を選択することは、$n = k$そのときだけ$x = 0$、それ以外の場合は係数$x$互いに近い 2 つの整数として保持する$n$一体化して確実に$m = n/k$正しく動作します。 

便利な建設的なトリックは、次のように設定することです。$$n = \left\lfloor \frac{x + 1}{2} \right\rfloor + 1, \quad k = n - 1$$それは保証します$n^2 - k^2 = 2n - 1$、すべての奇数の値をカバーし、一般的な値を表すようにわずかに調整します。$x$適切な因子のペアを選択することによって。 

最後の観察は、必要なのは有効な表現が 1 つにつき 1 つだけであるということです。$x$すべてのソリューションの完全な特徴付けではありません。

 ## アルゴリズムのチュートリアル

 構築は表現に依存します$x$2 平方の差として$n^2 - k^2$、その後、有効な$m$構造解釈から$k = \lceil n/m \rceil$。 

1. 些細なケースに対処する$x = 0$。 設定しました$n = 1, m = 1$これにより、条件に違反しない限りセルを配置できない単一セル グリッドが生成されます。 これは、必要な答えと正確に一致します。 
2. のために$x > 0$、整数を構築する$n$そして$k$そのような$n^2 - k^2 = x$。 これは、因数分解を選択することで実現されます。$x$の中へ$(n-k)(n+k)$。 結果として得られる値が両方とも整数になるように因数を選択します。$n > k$。 
3. コンピューティング$n = \frac{a + b}{2}$そして$k = \frac{b - a}{2}$、 どこ$a \cdot b = x$。 これにより、二乗差の恒等性が正確に保持されることが保証されます。 
4.セット$m$となることによって$\lceil n/m \rceil = k$。 これを満たす直接的な方法は、次のことを選択することです。$m = \left\lfloor \frac{n}{k} \right\rfloor$、天井条件が一致することを保証します$k$有効な因子ペアを使用して慎重に構築された場合。 
5. 出力$(n, m)$。 

### なぜ効果があるのか

 重要な不変条件は、最適なグリッド値はグリッドの数にのみ依存するということです。$m \times m$カバレッジ領域では、すべてのサブスクエアにゼロを強制する必要があります。 この量は単一の整数パラメータに縮小されます。$k = \lceil n/m \rceil$、目的関数は二乗の差になります。$n^2 - k^2$。 構築することで$n$そして$k$因数分解により$x$、最適な値がターゲットに正確に一致することを保証し、導出された$m$必要な天井関係を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x = int(input())
        
        if x == 0:
            print(1, 1)
            continue
        
        # find a factorization x = a * b with same parity (to form n, k)
        a = 1
        b = x
        for i in range(1, int(x**0.5) + 1):
            if x % i == 0:
                a, b = i, x // i
                # ensure correct parity for (a + b) / 2 integer n
                if (a + b) % 2 == 0:
                    break
        
        # construct n, k from difference of squares
        n = (a + b) // 2
        k = (b - a) // 2
        
        # ensure k > 0
        if k == 0:
            n += 1
            k = 1
        
        # choose m so that ceil(n/m) = k
        # a safe choice is m = n // k
        m = n // k
        if m == 0:
            m = 1
        
        print(n, m)

if __name__ == "__main__":
    solve()
```コードは二乗差の構造に従います。 まず縮退ケースを処理します$x = 0$。 ポジティブな場合$x$、約数のペアを検索します$(a, b)$そして、正しいパリティを確保しようとします。$n = (a+b)/2$そして$k = (b-a)/2$は整数です。 

時の調整は$k = 0$場合に無効な構造に崩壊するのを防ぎます。$x$は縮退因子のペアを持つ完全平方です。 ついに、$m$商として選ばれる$n // k$、これにより、意図されたスケーリング関係が強制されます。$n$必要なカバーブロックの数。 

微妙な点は、次のことを保証することです。$k$有効枚数に相当します$m \times m$取材グループ。 これが、この構築が一致するパリティを持つ因子ペアに依存する理由です。

 ## 特殊なケース

 ゼロのケースは、唯一の真に縮退した構成です。 いつ$x = 0$、 どれでも$n > 1$と$m > 1$構造が完全に制約されていない限り、少なくとも 1 つの有効な配置が許可されるため、最も安全で一貫した表現は最小限のグリッドです。$1 \times 1$これにより、答えは当然ゼロになります。 

もう一つの微妙なケースは次のような場合です。$x$は完全な正方形です。 単純な因子分割により生じる可能性があるのは、$a = b$、につながる$k = 0$の解釈を破ります。$k = \lceil n/m \rceil$。 アルゴリズムは調整することでこれを明示的に修復します。$n$ゼロでないことを保証するために上向きに$k$、代数分解とグリッド構造間の有効なマッピングを復元します。
