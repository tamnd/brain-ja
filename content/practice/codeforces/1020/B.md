 ## 解決策
 ## 問題の理解

 私たちには、各生徒が正確に他の 1 人の生徒を指す、生徒に対する指示された構造が与えられています。 これにより関数グラフが形成されます。すべてのノードが出次数 1 を持っているため、任意のノードから開始してポインタを繰り返したどると、最終的にはサイクルに入ります。 

教師はある生徒から始める`a`。 その生徒はすぐに 1 回マークされます。 その後、教師は現在の生徒から離れ続けます`i`に`p[i]`、訪問した各学生をマークします。 教師がすでにマークされている生徒に到着した時点でプロセスが停止し、その生徒が 2 番目のマークを受け取ります。 

タスクは、考えられるすべての開始ノードを決定することです。`a`、どの生徒が最初に 2 回訪問されることになります。 

制約`n ≤ 1000`は十分小さいため、O(n²) または O(n³) のシミュレーションでも安全です。 各開始ノードから新しいトラバーサルを実行するソリューションは、各トラバーサルが最大で次のノードを訪問できるため、すでに制限内にあります。`n`繰り返す前にノードを削除します。 

微妙な点は、訪問ノードのセットが開始点に依存するため、このプロセスは単に静的な意味で「サイクル エントリを見つける」わけではないということです。 最初に繰り返されるノードは、走査順序で 2 回出現する最初のノードであり、通常の分解の意味でのサイクルの開始である必要はありません。 

重要なエッジケースには次のようなものがあります。 

次のような自己ループ`p[i] = i`。 このようなノードから開始すると、最初の移動ですぐにそのノードに再アクセスするため、答えは自明です。 

もう 1 つのケースは、すべてのノードが最終的に 1 つのサイクルに流入する場合です。 それでも、サイクルへのエントリ ポイントはパスの通過方法に依存するため、テール内の開始点が異なると、最初に繰り返されるノードも異なる可能性があります。 

## アプローチ

 強引なアイデアは単純です。開始する生徒ごとに教師の動きをシミュレートします。 私たちは訪問者の配列を維持し、歩きます`p[current]`、そのシミュレーションですでに表示されているノードに到達するとすぐに停止します。 そのノードが開始の答えとして記録されます。 

これが機能するのは、各シミュレーションがステートメントに記述されている正確なプロセスを独立して再構築するためです。 文字通り段階的にルールに従っているので、正しさはすぐに分かります。 

非効率性は、同じ作業を最初から繰り返すことから発生します。 各シミュレーションは長さ O(n) の長いチェーンを横断する可能性があり、n 個の開始点すべてに対してこれを実行し、全体で O(n²) ステップを与えます。 n が 1000 までであれば、これでも問題ありませんが、より深い構造を示唆しています。つまり、すべての走査は決定的であり、関数グラフ内の次のポインターにのみ依存します。 

重要な観察は、開始ノードの答えは、そのパスが最初にサイクルと交差する場所、またはそのパス上に既に存在するノードを再訪問する場所にのみ依存するということです。 グラフは機能するため、すべてのノードはサイクルにつながる末尾またはサイクル自体のいずれかに属します。 任意の開始で最初に繰り返されるノードは、正確に、次の訪問がその走査の「初めて見た」プロパティに違反するパス上の最初のノードです。 

n が小さいため、複雑な前処理やサイクル分解は必要ありません。 新しく訪問した配列を使用した直接シミュレーションで十分です。

 | ブルートフォース | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 開始する生徒ごとに`a`、新しいブール配列を作成します`visited`サイズの`n + 1`。 これにより、各シミュレーションが独立しており、開始時に状態が漏洩しないことが保証されます。 
2.初期化`current = a`。 
3. ないかを繰り返し確認します。`current`訪問されました。 存在する場合、このシミュレーションですでに表示されているノードに戻ったことを意味します。`current`がこの出発点に対する答えです。 
4. 訪問したことがない場合は、マークを付けます。`current`訪問したとおり。 
5.移動`current = p[current]`そして繰り返します。 
6. 「すでに訪問済み」条件をトリガーした最初のノードを、次の応答として保存します。`a`。 

このステップ順序が重要である理由は、繰り返されるノードが、これから出ようとしているノードではなく、今入ったノードとして定義されるため、先に進む前にチェックを行う必要があるためです。 

### なぜ効果があるのか

 固定スタートからのシミュレーション中`a`、アルゴリズムは次の不変条件を維持します。`visited[x]`ノードの場合にのみ true です`x`は、この正確な横断の以前に訪問されています。 グラフの出次数が 1 であるため、訪問したノードのシーケンスが 1 つのウォークを形成します。 すでにマークされているノードに初めて遭遇したとき、そのノードは、維持方法の定義により、シーケンス内で最も早い繰り返しである必要があります。`visited`。 前のノードを繰り返しにすることはできません。そうでない場合、ループはより早く終了します。 これにより、返されたノードが、プロセス内で 2 回アクセスされた最初のノードであることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = [0] + list(map(int, input().split()))
    
    ans = [0] * (n + 1)
    
    for start in range(1, n + 1):
        visited = [False] * (n + 1)
        cur = start
        
        while True:
            if visited[cur]:
                ans[start] = cur
                break
            visited[cur] = True
            cur = p[cur]
    
    print(*ans[1:])

if __name__ == "__main__":
    solve()
```実装は説明どおりにトラバースに従います。 重要な詳細は、私たちがチェックすることです`visited[cur]`すでに見ているノードに着地した瞬間に繰り返しが検出されるため、マークしたり移動したりする前に。 シミュレーション間の干渉を避けるために、開始ごとに独自の訪問配列を再計算します。 

1 インデックスの配列により、学生ラベルからインデックスへの直接マッピングが簡素化され、読み取り時の off-by-one エラーが回避されます。`p`。

他の人にとっても同様です。 この走査の意味では、各ノードは自己復帰です。これは、その実行ですでに確認されているすべてのノードを循環した後、すぐに再訪問するためです。

 ## 特殊なケース

 のような自己ループ`p[i] = i`が最も直接的なケースです。 から開始`i`、それをマークし、1 回の遷移後にすぐに再度表示されるため、アルゴリズムは戻ります。`i`正しく、なぜなら`visited[i]`再考すると、それはすでに真実です。 

サイクルにつながるチェーンも同様に動作しますが、繰り返しが遅れます。 例えば`1 → 2 → 3 → 3`。 1 から開始して、1、2、3 を訪問し、再び 3 に移動しようとします。 3 はすでにマークされているため、最初の繰り返しノードとして正しく識別されます。 シミュレーションにより、サイクルのエントリが、前後ではなく、最初の再訪問時に正確に検出されることが保証されます。
