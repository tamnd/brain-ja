 ## 解決策
 ## 問題の理解

 文字列の部分文字列の数を数えるように求められます`s`指定された文字列のアナグラムに変換できます`p`。 文字列`s`疑問符を含めることができます`?`、任意の小文字に置き換えることができます。 部分文字列は、次の連続セグメントとして定義されます。`s`、異なる位置で始まる 2 つの部分文字列は、たとえ同一であっても別のものとみなされます。 

入力できるサイズは、`s`そして`p`それぞれの長さは 100,000 文字までです。 すべての部分文字列を生成し、それらを個別にチェックする単純なアプローチでは、大まかに次のものが必要になります。`O(n^2 * m)`どこでの操作`n`の長さは`s`そして`m`の長さは`p`。 と`n`そして`m`最大 10^5 の場合、約 10^15 回の操作が必要になりますが、これは 2 秒の制限時間には遅すぎます。 必要なのは`O(n)`または`O(n * 26)`効率を維持するためのアプローチ。 

明らかではないエッジ ケースには、部分文字列の長さが次のような状況が含まれます。`s`未満です`p`、これにより、有効な部分文字列はすぐにゼロになります。 部分文字列に疑問符のみが含まれる場合、別の微妙なケースが発生します。これは、次のどのアナグラムにも一致します。`p`長さが合えば。 たとえば、次の場合`s = "???"`そして`p = "abc"`の場合、3 つの疑問符は任意の順序で「a」、「b」、「c」に置き換えることができるため、部分文字列は有効です。 不注意な解決策を使用すると、このようなケースを数え間違えたり、見逃したりする可能性があります。 

## アプローチ

 ブルートフォース手法では、次のすべての部分文字列を反復処理します。`s`に等しい長さの`p`文字と疑問符を数えてアナグラムを形成できるかどうかを確認します。 各部分文字列について、文字の頻度配列を計算し、次の文字列間の違いがあるかどうかを確認します。`p`の文字数と部分文字列の数は、疑問符で正確にカバーできます。 これは論理的には機能しますが、実行されます`O(n*m)`時間。 最大の入力の場合、それは約 10^10 の演算に相当し、あまりにも遅すぎます。 

重要な観察は、固定長の部分文字列をチェックすることがスライディング ウィンドウに適しているということです。 一定の長さのウィンドウの頻度カウントを維持することによって`m`(長さ`p`)、ウィンドウが 1 つ右に移動したときにカウントを効率的に更新できます。 ウィンドウ内の疑問符の数も維持します。 各シフトについて、ウィンドウ内の文字の欠落が相対的にあるかどうかを確認するだけで済みます。`p`は疑問符の数とまったく同じです。 これにより、ウィンドウごとのチェックが減少します。`O(26)`操作、完全なアルゴリズムの作成`O(n*26)`、十分に速いです。

 ## アルゴリズムのチュートリアル

 1. 周波数配列を計算する`freq_p`文字列用`p`、 どこ`freq_p[i]`文字の出現をカウントします`'a'+i`。 
2. 長さのスライディング ウィンドウを初期化します。`m`以上`s`。 コンピューティング`freq_window`最初のウィンドウの文字数として、疑問符の数を数えます。`q_count`。 
3. 各ウィンドウについて、次のウィンドウと比較して欠落している文字の合計数を計算します。`p`合計することで`max(0, freq_p[i] - freq_window[i])`すべての文字にわたって。 この合計が等しい場合`q_count`、窓は良いです。 
4. ウィンドウを 1 つ右にスライドさせます。 アップデート`freq_window`そして`q_count`ウィンドウから出た文字のカウントをデクリメントし、ウィンドウに入った文字のカウントをインクリメントします。 
5. 文字列の終わりに達するまで、手順 3 と 4 を繰り返します。 

これが機能する理由は、部分文字列を次のアナグラムに変換するには、各文字の不足が疑問符で正確にカバーされている必要があるためです。`p`。 ウィンドウをスライドさせると、カウントを最初から再計算することなく、考えられるすべての部分文字列を効率的に調べることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
p = input().strip()

len_s = len(s)
len_p = len(p)

if len_p > len_s:
    print(0)
    sys.exit()

# frequency of letters in p
freq_p = [0] * 26
for ch in p:
    freq_p[ord(ch) - ord('a')] += 1

# frequency of letters in the current window
freq_window = [0] * 26
q_count = 0
for i in range(len_p):
    if s[i] == '?':
        q_count += 1
    else:
        freq_window[ord(s[i]) - ord('a')] += 1

result = 0

def is_good():
    missing = 0
    for i in range(26):
        if freq_p[i] > freq_window[i]:
            missing += freq_p[i] - freq_window[i]
    return missing == q_count

if is_good():
    result += 1

for i in range(len_p, len_s):
    # remove leftmost character
    left = s[i - len_p]
    if left == '?':
        q_count -= 1
    else:
        freq_window[ord(left) - ord('a')] -= 1
    # add new character
    right = s[i]
    if right == '?':
        q_count += 1
    else:
        freq_window[ord(right) - ord('a')] += 1
    if is_good():
        result += 1

print(result)
```このソリューションでは、両方の文字数を初期化します。`p`そして最初のウィンドウは`s`。 ウィンドウがシフトするたびに、入力文字と出力文字のみが更新され、ウィンドウごとのチェックが一定時間 (26 文字) に保たれます。 使用する`max(0, freq_p[i]-freq_window[i])`ウィンドウ内に必要以上に表示される文字を正しく処理し、マイナスの赤字を回避します。 の`?`count は段階的に調整され、再計算が防止されます。
