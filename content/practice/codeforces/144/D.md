 ## 解決策
 ## 問題の理解

 都市と道路を表す、接続された重み付き無向グラフが与えられます。 市`s`首都です。 ミサイルサイロは、都市上に設置される場合もあれば、道路の内側の地点に設置される場合もあります。 首都までの最短経路距離が正確に一致する場合、その位置は有効です。`l`。 

タスクは、この条件を満たす個別の位置がいくつあるかを数えることです。 

重要な点は、パスを数えているのではなく、グラフ内の幾何学的位置を数えているということです。 両方の端点からの最短距離がどのように動作するかに応じて、1 つの道路に有効なポイントが 0 個、1 個、または 2 個含まれる場合があります。 

グラフには最大で`10^5`都市も道路も。 これにより、二次関数は即座に除外されます。 たとえ`O(nm)`ソリューションは次のように実行されます`10^10`2秒の制限では不可能な最悪の場合の操作。 すべてのエッジの重みが正であるため、ダイクストラは効率的に実行されます。`O((n + m) log n)`、制約に快適に適合します。 

難しいのは、都市までの最短距離を計算することではありません。 難しいのは、二重にカウントせずにエッジの内側のポイントを数えたり、実際には最短距離ではないポイントを数えたりすることです。`l`。 

次のグラフを考えてみましょう。```
1 --(10)-- 2
```と`s = 1`そして`l = 5`。 

遠くに街はない`5`ですが、エッジの内側にはちょうど 1 つの点があります。 都市のみをチェックするソリューションでは、誤った結果が返されます。`0`。 

もう 1 つの微妙なケースは、反対側の 2 つの候補点が一致する場合です。```
1 --(10)-- 2
```仮定する`dist[1] = 0`、`dist[2] = 4`、 そして`l = 7`。 

市内から`1`、候補点は`7`エッジに沿ったユニット。 

市内から`2`、候補点は`3`エッジに沿ったユニット。 

これらは同じ物理的な点です。`7 + 3 = 10`。 私たちはそれを二度ではなく一度数えなければなりません。 

離れた 1 つのエンドポイントからポイントに到達できる場合、もう 1 つの危険なケースが発生します。`l`ですが、他のエンドポイントを経由する別の短いルートが存在します。 

仮定する：```
dist[u] = 2
dist[v] = 3
edge length = 10
l = 8
```から`u`、ポイントはそこにあります`6`ユニットをエッジに押し込みます。 しかし、から`v`、同じ点はただ`4 + 3 = 7`ソースから離れているため、実際の最短距離は`7`、 ない`8`。 単純な幾何学的チェックでは、無効な点がカウントされてしまいます。 

ソリューションでは、最短パスの条件を慎重に検証する必要があります。 

## アプローチ

 強引な解釈では、すべての道路を連続セグメントとして扱い、最短距離が次の値に等しいすべてのポイントを見つけようとします。`l`。 すべてのエッジについて方程式を導出し、両方の端点を通る距離を比較することができます。 

これは理論的には可能ですが、すべてのオーバーラップと最短パス条件を直接処理すると面倒になります。 さらに悪いことに、多くの候補位置の最短経路を再計算することは完全に不可能です。 すべての都市に対してすべてのエッジをチェックするだけでも、すでに実用的な限界を超えています。 

エッジ内の点へのすべての最短パスがエッジの端点の 1 つを通過する必要があることがわかると、問題の構造が変わります。 

エッジが接続されていると仮定します`u`そして`v`長さのある`w`。 ポイントが嘘なら`x`からの単位`u`、次にソースからの距離`u`は：```
dist[u] + x
```そしてそれを通して`v`は：```
dist[v] + (w - x)
```その点までの実際の最短距離は、これら 2 つの値の最小値です。 

この観察は、連続問題をエッジ エンドポイントでの算術に完全に還元します。 ダイクストラを使用してソースからすべての都市までの最短距離を計算すると、各エッジを個別に分析できます。 

点が正確に最短距離になるようにするには`l`、少なくとも一方の側が次の条件を満たす必要があります。```
dist[u] + x = l
```または```
dist[v] + (w - x) = l
```このような候補位置を見つけた後、反対方向が厳密に小さいパスを与えないことを検証する必要があります。 

これにより、1 回のダイクストラ実行後にすべてのエッジにわたるきれいな線形スキャンが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 大きすぎるため、連続したポジションで指数関数的に増加する可能性があります | 大 | 遅すぎる |
 | 最適 |`O((n + m) log n)`|`O(n + m)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. グラフの隣接リストを作成します。 

グラフはまばらで大きいため、隣接リストは隣接行列よりもはるかに効率的です。 
2. ディクストラを首都から追い出す`s`。 

これは計算します`dist[i]`、首都からすべての都市への最短距離。 
3. 最短距離が等しい都市をすべて数えます。`l`。 

そのような都市はすべて、それ自体が有効なミサイルサイロの位置となります。 
4. 各エッジを個別に処理します。 

エッジがあるとします。`(u, v, w)`。 
5. エンドポイントから生成された候補点を計算します`u`。 

もし`dist[u] < l`、次に距離のある点```
x = l - dist[u]
```から`u`端のどこかにある場合`x < w`。 
6. この点が実際に最短距離であることを確認します。`l`。 

通過距離`v`次のようになります:```
dist[v] + (w - x)
```この値が少なくとも次の場合にのみポイントをカウントします。`l`。 

これより小さい場合、ポイントの真の最短距離は等しくなりません。`l`。 
7. エンドポイントに対して対称的に繰り返します。`v`。 
8. 二重カウントを処理します。 

両方のエンドポイントが同じ内部ポイントを生成する場合、次のようになります。```
x + y = w
```この状況では、両方のチェックが 1 つの物理的な位置を参照するため、このエッジのカウントから 1 を減算します。 
9. 有効な都市と端の位置をすべて合計します。 

### なぜ効果があるのか

 ディクストラのその後、`dist[u]`ソースからすべてのエンドポイントまでの正確な最短パス距離です。 

エッジの内側の点への最短ルート`(u, v)`どちらかを経由して入力する必要があります`u`または`v`これは、グラフに方向性がなく、点がこのエッジ上にのみ存在するためです。 したがって、内部点までの最短距離は正確に次のようになります。```
min(dist[u] + x, dist[v] + (w - x))
```アルゴリズムは、これらの式のいずれかが等しい点をすべて列挙します。`l`。 検証ステップでは、他の式が以下より小さくないことを保証します。`l`したがって、真の最短距離は正確に`l`。 

すべての有効なポイントは少なくとも 1 つのエンドポイントから検出され、両方のエンドポイント構造が同じ場所を参照している場合に、重複の修正によって唯一考えられる重複ケースが除去されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

INF = 10**30

n, m, s = map(int, input().split())
s -= 1

adj = [[] for _ in range(n)]
edges = []

for _ in range(m):
    u, v, w = map(int, input().split())
    u -= 1
    v -= 1

    adj[u].append((v, w))
    adj[v].append((u, w))

    edges.append((u, v, w))

l = int(input())

dist = [INF] * n
dist[s] = 0

pq = [(0, s)]

while pq:
    d, u = heapq.heappop(pq)

    if d != dist[u]:
        continue

    for v, w in adj[u]:
        nd = d + w

        if nd < dist[v]:
            dist[v] = nd
            heapq.heappush(pq, (nd, v))

answer = 0

for d in dist:
    if d == l:
        answer += 1

for u, v, w in edges:
    cnt = 0

    # candidate generated from u
    if dist[u] < l:
        x = l - dist[u]

        if x < w and dist[v] + (w - x) >= l:
            cnt += 1

    # candidate generated from v
    if dist[v] < l:
        y = l - dist[v]

        if y < w and dist[u] + (w - y) >= l:
            cnt += 1

    # same physical point counted twice
    if cnt == 2 and (l - dist[u]) + (l - dist[v]) == w:
        cnt = 1

    answer += cnt

print(answer)
```最初の部分ではグラフを構築し、エッジを個別に保存します。 ダイクストラ用の隣接リストと、後のエッジ分析用のフラット エッジ リストが必要です。 

ダイクストラ実装は標準です。 エッジの重みは正であるため、初めてノードを完成させるとき、その距離は最適になります。 の`if d != dist[u]`check は古いヒープ エントリをスキップします。 

最短距離が判明したら、すぐに都市を数えます。 

エッジ処理セクションには実際のロジックが含まれています。 エンドポイントから`u`、距離に到達するためにエッジに沿ってどれだけ移動する必要があるかを計算します`l`。 条件`x < w`ポイントがエッジ上に正確に着地するのではなく、エッジの内側に厳密に存在することを保証します。`v`。 エンドポイント都市はすでに個別にカウントされています。 

不等式:```
dist[v] + (w - x) >= l
```は不可欠です。 Without it, we might count a point whose actual shortest distance is smaller than`l`。 

重複条件:```
(l - dist[u]) + (l - dist[v]) == w
```2 つの構造が同じ点で交わることを意味します。 これは、二重カウントが発生する可能性がある唯一のシナリオです。 

距離はおおよそ最大で 64 ビット整数に収まるため、すべての算術演算は安全に収まります。`10^8`。

 ## 特殊なケース

 中間点の重複の場合を考えてみましょう。```
2 1 1
1 2 10
5
```最短距離は次のとおりです。```
dist[1] = 0
dist[2] = 10
```ノードから`1`、候補点はあります`5`エッジに沿ったユニット。 

ノードから`2`、候補点もまた横たわる`5`エッジに沿ったユニット。 

オーバーラップ補正がなければ、アルゴリズムは 2 つのポイントをカウントします。 等価性:```
(5 - 0) + (5 - 10) = 10
```両方の構造が同じ場所を参照していることが検出されるため、カウントは次のようになります。`1`。 

ここで、偽の候補者について考えてみましょう。```
3 2 1
1 2 2
2 3 10
8
```距離:```
dist[1] = 0
dist[2] = 2
dist[3] = 12
```ノードから`2`、移動できます`6`ユニットをエッジに配置`(2,3)`そして距離に達しているように見える`8`。 

しかしノードからは`3`、同じ点は次のとおりです。```
12 + (10 - 6) = 16
```それは問題ないので、その点は有効です。 

次に、概念的に距離を変更します。```
dist[2] = 2
dist[3] = 3
w = 10
l = 8
```からの候補者`2`嘘をつくだろう`6`ユニットをエッジに押し込みます。 スルーノード`3`、距離は次のようになります。```
3 + 4 = 7
```真の最短距離は次のとおりであるため、検証条件はこの点を拒否します。`7`、 ない`8`。 

最後に、エンドポイントに正確に着陸することを検討してください。```
2 1 1
1 2 5
5
```市`2`すでに都市としてカウントされています。 エッジ処理中:```
x = 5
```以来`x < w`が false の場合、アルゴリズムはエンドポイントを内部点として再度カウントしません。
