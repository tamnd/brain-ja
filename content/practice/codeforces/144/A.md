 ## 解決策
 ## 問題の理解

 兵士の列があり、それぞれの身長が異なります。 大将はラインナップの 2 つのポジションだけを気にします。 最も背の高い兵士は先頭に立たなければならず、背の低い兵士は最後尾に立たなければなりません。 他の人の順番は関係ありません。 

1 秒以内に、隣り合う 2 人の兵士を交換することができます。 タスクは、必要な配置を達成するために必要なスワップの最小数を計算することです。 

入力すると、兵士の数と身長が現在の順序で表示されます。 出力は単一の整数であり、必要な隣接スワップの最小数です。 

制約は非常に小さく、兵士は最大 100 人までです。 二次シミュレーションでも制限時間内に余裕で収まります。 それでも、この問題は線形時間の観測結果がより明確になり、本当の課題は、重複した最大高と最小高さを正しく処理することです。 

難しいのは、最も背の高い兵士と最も低い兵士のどの出現を移動させるかを決定することです。 複数の兵士が最大高さを共有する場合、最も左の兵士を前に移動する必要があります。これは、交換が最小限で済むためです。 複数の兵士が最小の高さを共有する場合は、一番右の兵士を後ろに移動して、やはり入れ替えを最小限に抑える必要があります。 

不注意な実装は、移動中に選択した最大値が選択した最小値を超えると失敗することがよくあります。 

次の入力を考えてみましょう。```
5
2 1 2 1 2
```正しい答えは次のとおりです。```
3
```一番左に移動します`2`インデックスで`0`、すでに前面にあり、コストがかかります`0`交換します。 次に、一番右に移動します`1`インデックスで`3`最後までコストをかけて`1`スワップ。 総費用は`1`。 

誤って最後の最小値ではなく最初の最小値を選択した場合、さらに多くのスワップが必要になります。 

もう 1 つの微妙なケースは、最大兵士が最小兵士の右側に立つ場合に現れます。```
5
1 3 2 4 5
```最も背の高い兵士`5`インデックスにあります`4`、そして最も背の低い兵士`1`インデックスにあります`0`。 

移動`5`前に行く`4`交換します。 このプロセス中に、身長の低い兵士が位置を 1 つ右に移動します。 つまり、最小値を最後に移動すると、以前よりも 1 つ少ないスワップが必要になります。 この調整を忘れると、大きすぎる答えが生成されます。 

## アプローチ

 ブルートフォースソリューションは文字通りスワップをシミュレートします。 最も背の高い兵士を前方に向かってバブリングし、次に背の低い兵士を後方に向かってバブリングすることを繰り返します。 スワップごとに隣接する位置が変更されるため、これは問題ステートメントを直接モデル化し、推論が容易になります。 

のために`n = 100`、たとえ`O(n^2)`シミュレーションは完全に許容されます。 最悪の場合、ラフに実行します`100 * 100 = 10,000`小さな操作です。 

スワップを明示的にシミュレートする必要がないことがわかると、問題ははるかに単純になります。 要素を前に移動するために必要なスワップの数が、まさにそのインデックスになります。 要素を後方に移動するために必要なスワップの数は正確に`(n - 1 - index)`。 

これにより、問題は、最大高と最小高さの正しい出現を選択することに変わります。 

私たちは以下を選択します:

 1. 最大高さの左端。 
2. 最小高さの右端。 

一番左の最大値は、それを前面に出すために必要なスワップを最小限に抑えます。 一番右の最小値は、それを後ろに戻すために必要なスワップを最小限に抑えます。 

これら 2 つの動きの間には 1 つの相互作用があります。 最大値が最小値の右側から始まる場合、最大値を前に移動すると、最小値が 1 ステップ右に移動します。 つまり、最小値が終わりに一歩近づいたので、合計から 1 を減算します。 

この観察により、問題全体が単一の線形スキャンに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 承認済み |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 兵士の数と高さのリストを読み取ります。 
2. 最大高さの最も左にある箇所を見つけます。 

この兵士は最前線に到達するために最小限の交換しか必要としません。 
3. 最小高さの右端の箇所を見つけます。 

この兵士は最後まで到達するために必要なスワップを最小限に抑えます。 
4. 最大の兵士を前線に移動させるために必要なスワップを計算します。 

最大値がインデックスにある場合`max_pos`、コストは単純に`max_pos`。 
5. 最小兵士を最後まで移動するために必要なスワップを計算します。 

最小値がインデックスにある場合`min_pos`、費用は`(n - 1 - min_pos)`。 
6.次のことを確認します。`max_pos > min_pos`。 

true の場合、左に移動しながら最大値が最小値を超えます。 これにより、最小位置が 1 つ右にシフトされ、最後までの残りの距離が 1 スワップ分減少します。 
7. その場合は 1 を引きます。 
8. 最終合計を出力します。 

### なぜ効果があるのか

 隣接するスワップは一度に 1 ステップずつ位置を変更するだけなので、兵士を移動するのに必要なスワップの数は移動距離に等しくなります。 

左端の最大値を選択すると、最大身長のすべての兵士の間で前線までの距離が最小になることが保証されます。 最も右側の最小値を選択すると、身長が最小のすべての兵士の中で後方までの距離が最小になることが保証されます。 

2 つの操作間の唯一の依存関係は、最大値が最小値の右から始まる場合に発生します。 その状況では、最大値を左に移動すると、最小値は自動的に 1 ステップ右に移動します。 この単一のオーバーラップを考慮すると、正確な最小スワップ数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
a = list(map(int, input().split()))

max_height = max(a)
min_height = min(a)

max_pos = a.index(max_height)

min_pos = -1
for i in range(n):
    if a[i] == min_height:
        min_pos = i

answer = max_pos + (n - 1 - min_pos)

if max_pos > min_pos:
    answer -= 1

print(answer)
```この解決策は、Python の組み込み機能を使用して最も高い身長と最も低い身長を特定することから始まります。`max`そして`min`。 

最大の位置については、`a.index(max_height)`最初の出現箇所を自動的に返します。これはまさに私たちが望んでいることです。 

最小位置の場合は使用できません`index`なぜなら、それは最後の出現ではなく最初の出現を与えるからです。 代わりに、配列をスキャンして継続的に上書きします。`min_pos`最小値が表示されるたびに。 ループが終了したら、`min_pos`一番右のオカレンスを格納します。 

式:```
max_pos + (n - 1 - min_pos)
```スワップを独立してカウントします。 

調整:```
if max_pos > min_pos:
    answer -= 1
```最大兵士を最初に移動することによって生じるオーバーラップを処理します。 

この条件は間違いやすいです。 もともと最大値が最小値の右側にある場合にのみ減算します。 最大値がすでに最小値の左側にある場合、2 つの動きは干渉しません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    max_height = max(a)
    min_height = min(a)

    max_pos = a.index(max_height)

    min_pos = -1
    for i in range(n):
        if a[i] == min_height:
            min_pos = i

    ans = max_pos + (n - 1 - min_pos)

    if max_pos > min_pos:
        ans -= 1

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup_stdout

    return out.getvalue().strip()

# provided samples
assert run("4\n33 44 11 22\n") == "2", "sample 1"
assert run("7\n10 10 58 31 63 40 76\n") == "10", "sample 2"

# minimum size
assert run("2\n1 2\n") == "1", "minimum size"

# all equal values
assert run("5\n7 7 7 7 7\n") == "0", "all equal"

# duplicate maximum and minimum
assert run("5\n2 1 2 1 2\n") == "1", "choose leftmost max and rightmost min"

# overlap adjustment case
assert run("5\n1 3 2 4 5\n") == "7", "crossing positions"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2 / 1 2`|`1`| 最小配列サイズ |
 |`5 / 7 7 7 7 7`|`0`| すべての値が同一 |
 |`5 / 2 1 2 1 2`|`1`| 正しい重複処理 |
 |`5 / 1 3 2 4 5`|`7`| 正しいオーバーラップ調整 |

 ## 特殊なケース

 すべての兵士の身長が同じである場合を考えてみましょう。 

入力：```
5
7 7 7 7 7
```左端の最大値はインデックスにあります`0`、右端の最小値はインデックスにあります`4`。 

計算は次のようになります。```
0 + (4 - 4) = 0
```最初の兵士はすでに最大身長の兵士であり、最後の兵士はすでに最小身長の兵士であるため、入れ替えは必要ありません。 

ここで、重複した最小値を考えてみましょう。 

入力：```
5
2 1 2 1 2
```正しい選択は一番右です`1`インデックスで`3`。 

アルゴリズムは以下を計算します。```
max_pos = 0
min_pos = 3
answer = 0 + (4 - 3) = 1
```最初のものを間違って使用した場合`1`、次のようになります:```
0 + (4 - 1) = 3
```それは最小限ではありません。 

最後に、オーバーラップの場合を考えてみましょう。 

入力：```
5
1 3 2 4 5
```最も背の高い兵士`5`インデックスから始まります`4`、そして最も背の低い兵士`1`インデックスから始まります`0`。 

生のスワップ数は次のとおりです。```
4 + 4 = 8
```でも動く`5`左へシフト`1`自動的に右に1回。 真の最小値は次のとおりです。```
8 - 1 = 7
```アルゴリズムは次の条件を使用してこれを検出します。```
if max_pos > min_pos:
    answer -= 1
```これにより、2 つの動きの間の相互作用が正しく処理されます。
