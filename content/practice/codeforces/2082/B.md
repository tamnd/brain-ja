 ## 解決策
 ## 問題の理解

 整数値から開始し、2 種類の半減演算を固定回数実行する必要があります。 

1 回の操作で、現在の値が値の半分の下限に置き換えられます。 もう 1 つは、値の半分の上限に置き換えます。 フロア操作を正確に使用する必要があります`n`回や天井操作も正確に`m`ただし、その順序を選択することもできます。 タスクは、取得できる最終的な最小値と最大値を見つけることです。 

最初に注目すべきことは、両方の演算が偶数に対して同じように動作するということです。$$\left\lfloor \frac{x}{2} \right\rfloor = \left\lceil \frac{x}{2} \right\rceil = \frac{x}{2}$$唯一興味深い状況が発生するのは、`x`奇数です:$$\left\lfloor \frac{x}{2} \right\rfloor = \frac{x-1}{2}$$

$$\left\lceil \frac{x}{2} \right\rceil = \frac{x+1}{2}$$奇数の値の場合、下限演算は上限演算よりも正確に 1 小さい結果を生成します。 

制約こそが本当の課題なのです。 価値観`x`、`n`、 そして`m`すべて同じ大きさにすることができます`10^9`、まであります`10^4`テストケース。 すべてをシミュレートしようとするアプローチ`n + m`1 つのテスト ケースに 20 億の操作が必要になる可能性があるため、操作は不可能です。 

重要な観察は、すべての操作で現在の値がほぼ半分になるということです。 以来`x ≤ 10^9`、約 30 回の半分の後、値は次のようになります。`0`または`1`。 その点に到達すると、残りの操作は分析的に処理できます。 これは、テスト ケースごとの実際の作業量をごくわずかな定数に減らすことができることを意味します。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

考慮する：```
x = 1, n = 1, m = 100
```最低限考えられる答えは、`0`。 任意のタイミングで床操作を適用する`1`の中へ`0`、その後はすべての操作で維持されます`0`。 到達したら止まるという不用意な実装`1`間違って戻ってきます`1`。 

考慮する：```
x = 1, n = 0, m = 100
```答えは`1`。 の天井`1/2`まだです`1`なので、値は決して変わりません。 

考慮する：```
x = 0, n = 10^9, m = 10^9
```答えは`0 0`。 どちらの操作も、ゼロは永久に変更されないままになります。 

これらの最終状態は個別に処理する必要があります。 

## アプローチ

 ブルート フォース ソリューションでは、操作の可能な順序をすべて試行します。 たとえ小さな値であっても、`n + m`、可能な注文の数は膨大です。$$\binom{n+m}{n}$$これは急激に増加し、ほぼすぐに絶望的になります。 

より合理的なブルート フォースでは、選択した順序をシミュレートします。 それでも失敗するのは、`n + m`と同じくらい大きいかもしれない`2 \cdot 10^9`。 

作戦の構造から、より強力な観察が得られます。 すべての操作で現在の値が半分になります。 最大でも開始`10^9`、およそ 30 ステップの後、値はすでに に減少しています。`0`または`1`。 それ以降の操作は簡単になります。 

残りの問題は、最適な順序をどのように選択するかです。 

現在の値が奇数の場合、床は天井よりも小さな結果を生成します。 最終的な答えを最小限に抑えようとする場合、可能な限り奇数に対してフロア演算を費やしたいと考えます。 最終的な答えを最大化しようとしている場合は、可能な限り奇数に上限演算を費やしたいと考えます。 

両方の演算で次の値がまったく同じになるため、偶数は異なります。 結果は同じであるため、それらの瞬間を利用して、後であまり役に立たない操作タイプを使用する必要があります。 

最小化の場合、フロア演算は奇数に役立つため価値があります。 偶数の場合は、天井演算を最初に消費し、将来の奇数の値のために下限演算を保存する必要があります。 

最大化の場合、天井演算は奇数に役立つため価値があります。 偶数の場合、最初に下限演算を消費し、将来の奇数の値に備えて上限演算を保存する必要があります。 

この貪欲な戦略により、最適な順序が完全に決定されます。

 ## アルゴリズムのチュートリアル

 最小の答えを計算するには:

 1. その間`x > 1`まだ操作が残っている場合は、パリティを検査してください。`x`。 
2. もし`x`奇数でフロア操作が可能なので、それを使用します。 

これにより、可能な限り最小の次の値が得られます。 
3. もし`x`奇数で床操作が残っていない場合は、天井操作を使用してください。 
4. もし`x`が偶数の場合、両方の操作で同じ次の値が得られます。 

シーリング演算が存在する場合は、シーリング演算を使用します。これは、将来の奇数の値に対してシーリング演算はフロア演算よりも有用ではないためです。 
5. すべての操作が完了するか、または完了するまで続行します。`x`になる`0`または`1`。 
6. もし`x = 0`、答えは`0`。 
7. もし`x = 1`、答えは`0`フロア操作が残っている場合、そうでない場合`1`。 

最大の答えを計算するには:

 1. その間`x > 1`操作が残っている場合は、パリティを検査します。 
2. もし`x`が奇数で天井操作も可能なので利用しましょう。 

これにより、可能な最大の次の値が得られます。 
3. もし`x`奇数で天井操作が残っていない場合は、床操作を使用してください。 
4. もし`x`が偶数である場合は、可能であればフロア演算を使用してください。 

偶数値では下限演算は無害であるため、将来の奇数値に対して上限演算を保存します。 
5. すべての操作が完了するか、または完了するまで続行します。`x`になる`0`または`1`。 
6. もし`x = 0`、答えは`0`。 
7. もし`x = 1`、答えは`1`フロア操作が残っていない場合のみ。 それ以外の場合は、最終的にフロアを適用する必要があり、結果は次のようになります。`0`。 

### なぜ効果があるのか

 重要な特性は、床と天井が奇数の場合のみ異なるということです。 

最小の答えの場合、奇数の値に対してフロア操作が使用されるたびに、シーリング操作よりも現在の値が 1 だけ減少します。 将来のすべての操作は現在の値の単調関数であるため、値が小さくなっても最小化の目的が損なわれることはありません。 したがって、フロア操作は奇数状態で最も価値があり、シーリング操作は可能な限り偶数状態に費やす必要があります。 

最大化引数は対称です。 シーリング操作は、値を 1 つ大きく保つため、奇数の状態で最も価値があります。 偶数の状態でフロア操作を使用すると、それらの貴重なシーリング操作が後で使用できるように保存されます。 

それぞれの貪欲な選択により、次の奇妙な遭遇に対してより有用な操作タイプが保存されるため、他の順序付けではより良い最終結果を生み出すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def get_minimum(x, n, m):
    while x > 1 and (n > 0 or m > 0):
        if x & 1:
            if n > 0:
                x //= 2
                n -= 1
            else:
                x = (x + 1) // 2
                m -= 1
        else:
            if m > 0:
                x //= 2
                m -= 1
            else:
                x //= 2
                n -= 1

    if x == 0:
        return 0
    if x == 1:
        return 0 if n > 0 else 1
    return x

def get_maximum(x, n, m):
    while x > 1 and (n > 0 or m > 0):
        if x & 1:
            if m > 0:
                x = (x + 1) // 2
                m -= 1
            else:
                x //= 2
                n -= 1
        else:
            if n > 0:
                x //= 2
                n -= 1
            else:
                x //= 2
                m -= 1

    if x == 0:
        return 0
    if x == 1:
        return 1 if n == 0 else 0
    return x

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        x, n, m = map(int, input().split())
        mn = get_minimum(x, n, m)
        mx = get_maximum(x, n, m)
        ans.append(f"{mn} {mx}")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```2 つのヘルパー関数は、2 つの貪欲な戦略を独立して実装します。 

ループは次の期間のみ実行されます。`x > 1`。 反復ごとに値が半分になるため、指定された制約の場合、反復回数は最大でも約 31 回になります。 いつでも`n`そして`m`は 10 億ですが、これほど多くの操作をシミュレーションすることはありません。 

端末の扱いは微妙な部分です。 一度`x`になる`1`、残りの操作が重要です。 残りのフロア操作は最終的に回転します`1`の中へ`0`。 天井操作のみ放置`1`変わらない。 最終的なロジックがフロア操作がまだ利用可能かどうかのみに依存するのはこのためです。 

値が減少するだけなので、オーバーフローの問題は発生しません。
