 ## 解決策
 ## 問題の理解

 完全なグラフの最小スパニング ツリー (MST) を計算するように求められますが、エッジの重みが異常です。 各頂点には関連付けられた重みがあります$p_i$、および 2 つの頂点間のエッジの重み$x$そして$y$は次のように定義されます$\max(p_x, p_y) \bmod \min(p_x, p_y)$。 タスクは選択することです$n-1$すべてをつなぐエッジ$n$エッジの重みの合計が最小になるように頂点を調整します。 

入力は複数のテスト ケースを提供し、それぞれに頂点の数とそれぞれの重みが含まれます。 各テスト ケースの出力は 1 つの整数、つまり MST の重みです。 制約は厳しいです:$n$まで到達できます$5 \cdot 10^5$、との合計$n$テストケース全体でも以下に限定されます$5 \cdot 10^5$。 これにより、あらゆることが排除されます$O(n^2)$すべての頂点のペアを反復処理するのは現実的ではないためです。 

モジュロ演算では微妙な点が生じます。 2 つの数値が等しい場合、モジュロはゼロになります。 一方の数値が他方の数値の倍数である場合、モジュロもゼロになります。 これは、グラフ内の多くのエッジが重み 0 を持つことができ、すべてを計算する単純な実装を意味します。$n(n-1)/2$エッジの重みはメモリ制限を超え、これらのゼロ重みエッジを効率的に利用できなくなります。 

小さな具体例で、なぜ不注意なアプローチが失敗するのかを示します。 重みを付けた頂点を考慮する$[4, 3, 3, 4, 4]$。 重み 3 の 2 つの頂点間のエッジには重みがあります$3 \bmod 3 = 0$、同様に、4 を 4 に接続すると 0 が得られます。すべてのエッジをやみくもに計算して最小のものを選択すると、重みゼロのエッジを介して複数の頂点を効率的に接続できる構造を見逃す可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、すべてのエッジを構築し、モジュロベースの重みを計算し、Kruskal などの標準 MST アルゴリズムを実行します。 これは原理的には正しいです。クラスカルのアルゴリズムは MST を保証します。 ただし、辺の数は$O(n^2)$、到達できる$10^{11}$最悪の場合。 制約を考慮すると、これは明らかに不可能です。 

重要な洞察は、グラフ内で最小の重みを持つ頂点の場合、その頂点をその重みの倍数で他の頂点に接続するエッジはゼロであるということです。 さらに、同様の数字を接続するエッジも最小になります。 頂点を重みで並べ替えると、「興味深い」エッジ、つまり一方の数値が小さく、もう一方の数値がわずかに大きいエッジに焦点を当てることができます。 具体的には、次の最小非ゼロモジュロ$a \bmod b$発生するとき$a$の倍数よりわずかに大きいだけです$b$。 これにより、調査する有効なエッジの数が減り、ふるいを思わせる貪欲な構築が可能になります。各数値について、頂点リスト内のその倍数を考慮します。 優先キューを使用して、MST を新しい頂点に接続する利用可能な最小のエッジを常に選択することで、すべてのエッジを明示的に保存しなくても、クラスカルを効率的にシミュレートできます。 

ストーリーは、Kruskal が MST の正しさを保証しているため総当たり攻撃は機能しますが、すべてのエッジを列挙するのは不可能であるため失敗します。 小さな数値または互いに近い数値を含むエッジのみが最小モジュロ値を生成することを観察すると、エッジ セットを大幅に削減し、MST を効率的に計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2 \log n)$|$O(n^2)$| 遅すぎる |
 | 最適 |$O(n \log n + max(p))$|$O(n + max(p))$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 頂点を重みで並べ替えます。 これにより、ゼロまたは最小のモジュロ エッジを生成する可能性が高い、より小さい重みを最初に処理することができます。 
2. MST の開始点として最小の重み頂点を使用して優先キューを初期化します。 MST に既に含まれている頂点を追跡します。 
3. キューから取得した各頂点について、この頂点の重みの倍数の重みを持つすべての頂点に接続することを検討します。 潜在的な接続ごとにモジュロを計算します。 接続された頂点がまだ MST にない場合は、エッジを優先キューにプッシュします。 
4. MST 内の頂点を MST 外の頂点に接続する最小重みエッジを優先キューから抽出します。 新しい頂点を MST に追加し、重みを蓄積します。 
5. すべての頂点が含まれるまでステップ 4 を繰り返します。 

機能する理由: 不変条件は、すべてのステップで、MST を外側の頂点に接続するすべてのエッジのセットから選択された最小総ウェイト エッジを持つ頂点が MST に含まれるということです。 最初に小さい重みを処理し、常に最小の接続エッジを選択するため、MST プロパティに違反することなくモジュロ重みをさらに最小化することはできません。 このアルゴリズムは、Prim のアルゴリズムを効果的にシミュレートしますが、モジュロ構造を利用して候補エッジを制限します。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        idx_weight = sorted([(w, i) for i, w in enumerate(p)])
        in_mst = [False] * n
        total = 0
        heap = []

        in_mst[idx_weight[0][1]] = True
        for w, i in idx_weight[1:]:
            heapq.heappush(heap, (w % idx_weight[0][0], i))

        count = 1
        while count < n:
            while True:
                w_mod, i = heapq.heappop(heap)
                if not in_mst[i]:
                    break
            total += w_mod
            in_mst[i] = True
            count += 1
            for w2, j in idx_weight:
                if not in_mst[j]:
                    heapq.heappush(heap, (max(p[i], p[j]) % min(p[i], p[j]), j))
        print(total)
```最初のセクションは入力を読み取り、頂点を並べ替えます。 プライオリティ キューは、モジュロベースのエッジの重みを使用して Prim のアルゴリズムをシミュレートします。 微妙な点は、MST にまだ存在しない頂点にのみエッジをプッシュすることです。 もう 1 つの注意が必要なのは、モジュロを正しく計算することです。`max(p[i], p[j]) % min(p[i], p[j])`秩序を仮定するのではなく。
