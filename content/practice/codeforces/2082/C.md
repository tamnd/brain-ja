 ## 解決策
 ## 問題の理解

 バイナリ表現で正の整数が与えられます。タスクは、この数値を 1 に減らすために必要な演算の予想数を計算することです。許可される演算は、下限除算または上限除算のいずれかによって数値を半分にすることであり、各ステップで等しい確率で独立して選択されます。 出力はモジュロでなければなりません$10^9 + 7$、モジュラー分数として表されます。 

入力は複数のテスト ケースで構成されます。 各テスト ケースはバイナリの長さを示します$n$そしてバイナリ文字列自体。 以来$n$まで可能です$10^5$と合計$n$すべてのテスト ケースの境界は次のとおりです$10^5$、理想的には数値の値に対して線形時間または対数時間で各数値を効率的に処理する必要があります。 

主な課題は、両方の操作で分岐する単純なシミュレーションでは指数関数的に増大し、次のような中程度の値であっても完全に実行不可能になることです。$x = 10^5$。 もう 1 つの微妙な点は、数値が 2 進数で与えられることです。 10 進数に直接変換することは可能ですが、算術剰余を保証する必要があります。$10^9+7$端数の期待値については慎重に処理されます。 

エッジケースは、数値がすでに 2 の累乗になっている場合です。 この場合、ほとんどのステップで床と天井の操作が一致するため、期待値に影響を与えます。 たとえば、$x = 4$(バイナリ 100) の場合、この場合は繰り返し半分にすることが決定的であるため、予想されるステップのシーケンスは 3 ではなく 2 になります。 

## アプローチ

 ブルートフォース手法では、数値ごとに考えられるすべての演算シーケンスを再帰的に計算しようとします。 から始めます$x$各ステップで 2 つの再帰呼び出しに分岐します。$\lfloor x/2 \rfloor$そして1つは$\lceil x/2 \rceil$。 予想される操作数は加重平均になります。 これは原理的には機能しますが、シーケンスの数は次のように指数関数的に増加します。$\log x$。 最大の入力の場合$x \sim 2^{100000}$、これはまったく実現不可能です。 

重要な観察は、予想される操作の数を表すことができるということです。$E(x)$期待の線形性引数を再帰的に使用する：$$E(1) = 0, \quad E(x) = 1 + \frac{1}{2} \big(E(\lfloor x/2 \rfloor) + E(\lceil x/2 \rceil)\big) \quad \text{for } x > 1$$この再帰は、より小さい整数のみに依存します。 各数値はステップごとにおよそ半分ずつ減少するため、再帰の深さは次のようになります。$O(\log x)$。 動的プログラミングを使用して、遭遇した数値の結果をキャッシュし、再計算を避けることができます。 分数を使ったモジュロ算術を処理するには、結果を分子と分母のペアとして計算し、モジュラー逆数を掛けます。 

このアプローチにより、問題は指数関数的な問題からおおよその問題に軽減されます。$O(\log x)$テスト ケースごとに、合計を考慮すると許容範囲内です。$n$は$10^5$。

 ## アルゴリズムのチュートリアル

 1. 2 モジュロの逆モジュラを事前計算します。$10^9+7$すべての再帰ステップには 1/2 の乗算が含まれるためです。 フェルマーの小定理を使うと、$2^{-1} \equiv 500000004 \mod 10^9+7$。 
2. 再帰関数を定義する`expected(x)`1 に到達するまでに予想されるステップ数を整数の剰余として返します。$10^9+7$。 基本ケース: if`x == 1`、0を返します。 
3. 1 より大きい数値の場合、期待値を次のように計算します。```
result = 1 + (expected(x // 2) + expected((x + 1) // 2)) * inv2 % MOD
```の`1`現在の操作を説明します。 2 つの分岐の期待値の合計に 2 の逆剰余を乗じて平均を表します。 
4. 再計算を避けるために結果を辞書にキャッシュします。 再帰によって毎回数値がおよそ半分に減るため、テスト ケースごとの一意の数値の総数は最大でも$O(\log x)$。 
5. 各テスト ケースの開始時にバイナリ文字列を整数に変換します。 
6. 各テスト ケースについて、再帰関数を使用して期待値を計算し、それを剰余として出力します。$10^9+7$。 

これが機能する理由は、再帰が確率過程を正確にモデル化しているためです。 期待値の線形性により、期待されるステップ数は、$x$は常に 1 (現在の操作) と、考えられる 2 つの次の状態からの期待値の平均の合計になります。 キャッシュにより、同じ番号に対する繰り返し呼び出しによって指数関数的な再計算が発生しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7
inv2 = pow(2, MOD - 2, MOD)  # modular inverse of 2

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        x = int(input().strip(), 2)  # convert binary string to int
        memo = {}
        def expected(val):
            if val == 1:
                return 0
            if val in memo:
                return memo[val]
            res = 1 + (expected(val // 2) + expected((val + 1) // 2)) * inv2 % MOD
            res %= MOD
            memo[val] = res
            return res
        print(expected(x))

if __name__ == "__main__":
    solve()
```The code first converts the binary string to an integer, sets up a memoization dictionary for each test case, and computes expected operations using the recursion. 乗算`inv2`モジュロ演算で 2 による除算を実装し、浮動小数点の小数部を回避します。
