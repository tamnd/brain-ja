 ## 解決策
 ## 問題の理解

 一連の個別の整数が与えられます。 ジョニーは正の整数を選択します`k`すべての値を置き換えます`s`とのセットで`s XOR k`。 

変換はすべての要素に同時に適用されます。 変換後、結果のセットが元のセットとまったく同じになることが必要です。 セットを扱っているため、要素の順序は重要ではありません。 

私たちの仕事は、最小の正の整数を見つけることです`k`誰のために$$\{s \oplus k \mid s \in S\} = S$$または、そのような正の整数が存在しないことを報告します。 

制約は異常に小さいです。 セット内のすべての数値は以下です`1024`、これは最大 10 ビットを使用することを意味します。 テスト ケース内の要素の数は最大で`1024`、すべてのテスト ケースにわたる要素の合計数も最大です。`1024`。 

これらの制限は、次の多くの候補値を試してみることをすぐに示唆します。`k`完全に実現可能かもしれない。 すべての値が範囲内にあるため、`[0, 1023]`、そのような 2 つの数値から生成された XOR 結果もその範囲内にあります。 考えられるすべての 10 ビット マスクの検索にかかるコストはわずか約 1,000 回です。 

いくつかの特殊なケースは見落とされがちです。 

単一要素セットを考えてみましょう。```
1
1
5
```あらゆるポジティブな`k`変化`5`異なる値に変換されるため、セットを変更しないで残すことはできません。 正しい答えは次のとおりです。```
-1
```不注意な解決策は、すべてのセットに何らかの対称性があると想定し、誤った値を返す可能性があります。 

もう 1 つの重要なケースは、答えが大きい場合です。```
1
2
0 1023
```使用する`k = 1023`2 つの要素を交換します。```
0 XOR 1023 = 1023
1023 XOR 1023 = 0
```セットは変更されないため、答えは次のようになります。```
1023
```要素自体の間に出現するマスクのみをチェックするソリューションでは、これを見逃してしまいます。 

もう 1 つの微妙なケースは次のとおりです。```
1
3
1 2 3
```異なるマスクを試しても、同じセットが再現されることはありません。 正しい答えは次のとおりです。```
-1
```ペアごとの関係だけを探したくなる誘惑に駆られますが、変換されたセット全体が正確に一致する必要があります。 

## アプローチ

 最も直接的なアイデアは、考えられるすべての正の整数をテストすることです。`k`。 

各候補について、セットのすべての要素を XOR します。`k`、変換されたセットを構築し、元のセットと比較します。 それらが一致する場合、有効な答えが見つかったことになります。 

この総当り的なアプローチは、文字通りステートメントから条件をチェックするため、正しいものです。 問題は、それが十分に速いかどうかです。 

重要な観察は値の範囲から得られます。 すべての要素は以下より小さい`1024`したがって、関連するすべての XOR マスクも より小さいです。`1024`。 範囲外のものをテストする理由はありません`[1, 1023]`。 

候補マスクごとに最大で処理します`n ≤ 1024`要素。 テスト ケースごとの最悪の作業は次のとおりです。$$1023 \times 1024 \approx 10^6$$操作。 

の合計を考えると、`n`すべてのテストケースにわたって、`1024`, これは余裕で制限内です。 

すべての数値が 10 ビット値であるという観察により、通常は巨大な検索スペースのように見えるものが小さな検索スペースに変わります。 任意の整数を検索する代わりに、1023 個の可能なマスクをチェックするだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべての整数に対するブルート フォース | 無制限 | O(n) | 不可能 |
 | すべてのマスクを列挙します 1..1023 | O(1024・n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 一連の数値を読み取ります。 
2. O(1) メンバーシップおよび等価性チェックのために、元の要素をハッシュ セットに保存します。 
3. すべての候補マスクを反復処理します。`k`から`1`に`1023`。 
4. 現在のマスクについて、すべての値を計算します。`x XOR k`あらゆる要素に対して`x`セットで。 
5. これらの変換された値を含む新しいセットを構築します。 
6. 変換されたセットを元のセットと比較します。 

それらが同一の場合、適用します`k`セットを正確に保存します。 
7. マスクは昇順にテストされるため、最初の有効なマスクが自動的に最小の有効な答えになります。 すぐに出力してください。 
8. すべての値をチェックしてもマスクが機能しない場合は、`1`に`1023`、出力`-1`。 

### なぜ効果があるのか

 有効な答えについては、`k`すべての設定要素は 10 ビットの数値である必要があります。`[0,1023]`。 アルゴリズムは、その範囲全体のすべてのポジティブ マスクをチェックします。 

固定マスクの場合、変換されたセットは、問題ステートメントで説明されているセットとまったく同じになります。 元のセットと直接比較することで、条件が当てはまるかどうかを検証します。 

考えられるすべての候補マスクが検査され、最初の有効なマスクが返されるため、アルゴリズムは解を見逃すことはなく、より小さな解が存在する場合により大きな解を返すこともできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    answers = []

    for _ in range(t):
        n = int(input())
        arr = list(map(int, input().split()))

        original = set(arr)

        answer = -1

        for k in range(1, 1024):
            transformed = {x ^ k for x in arr}

            if transformed == original:
                answer = k
                break

        answers.append(str(answer))

    sys.stdout.write("\n".join(answers))

if __name__ == "__main__":
    solve()
```実装はほぼ文字通りアルゴリズムに従います。 

元の数値は Python に保存されます。`set`これにより、効率的な等価比較が可能になります。 2 つのセットが等しいのは、それらにまったく同じ要素が含まれており、問題の定義と一致する場合に限ります。 

候補マスクごとに、集合内包表記によって変換された値が生成されます。 入力はすでに個別の値で構成されているため、変換された結果も一連の個別の値のままになります。 2 つのセットを直接比較すると、変換によってセットが変更されないままになるかどうかが確認されます。 

マスク上のループは次から始まります`1`、 ない`0`。 このステートメントでは正の整数が要求されます`k`、 それで`0`たとえセットが常に保持されるとしても、これは許可されません。 

マスクは昇順に処理されるため、有効なマスクが見つかると検索はすぐに停止します。 これにより、最小の有効な答えが保証されます。

 ## 特殊なケース

 単一要素のセットには有効な答えはありません。```
1
1
5
```アルゴリズムは、次のすべてのマスクをチェックします。`1`に`1023`。 すべての変換により、異なるシングルトン セットが生成されます。```
{5 XOR k}
```決して等しくないもの`{5}`なぜなら`k > 0`。 検索が終了し、次のように出力されます。```
-1
```境界の場合```
1
2
0 1023
```アルゴリズムは最終的には`k = 1023`そして以下を計算します:```
0 XOR 1023 = 1023
1023 XOR 1023 = 0
```変換されたセットは次のようになります`{0,1023}`、オリジナルと一致します。 これより小さいマスクは機能しないため、出力は次のようになります。```
1023
```対称性のない集合の場合、```
1
3
1 2 3
```すべての候補マスクは異なるセットを生成します。 等価性テストは毎回失敗するため、アルゴリズムは正しく次の値を返します。```
-1
```セットを直接比較することで、要素間の部分的な関係のみをチェックすることで発生する可能性のある誤検知を防止します。
