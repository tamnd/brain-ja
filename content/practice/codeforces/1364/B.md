 ## 解決策
 ## 問題の理解

 順列が与えられています。これは、1 から n までのすべての数値が、ある順序で 1 回だけ現れることを意味します。 この配列から要素を削除し、残りの要素を同じ相対順序に保ち、サブシーケンスを形成することができます。 長さが少なくとも 2 のすべてのサブシーケンスの中で、連続して選択された要素間の絶対差の合計を最大化するものが必要です。 複数のサブシーケンスが同じ最大値に達する場合、可能な限り長さが短いサブシーケンスが優先されます。 

目的関数は、元の位置ではなく、隣接する選択された値にのみ依存します。 これは、注目する構造が、値が配列内のどこにあるかではなく、値がどのように上下に移動するかによって引き起こされることを意味するため、重要です。 

最大 2⋅10^4 のテスト ケースにわたって n が最大 10^5 という制約は、合計入力サイズが約 10^5 であることを意味するため、テスト ケースごとに最悪でも O(n) または O(n log n) が必要ですが、全体としては実質的に線形になります。 テストケースごとに二次関数を実行することは直ちに不可能です。 

単純な考えは、すべてのサブシーケンスを試して、そのスコアを計算することです。 単一のテスト ケースに限定しても、2^n 個のサブシーケンスが存在しますが、これはまったく実行不可能です。 すべてのペアまたはトリプルに対する動的プログラミングであっても、依然として遅すぎます。 

より微妙な失敗例は、グローバル構造を考慮せずに局所的な大きな差異を貪欲に採用することから生じます。 たとえば、配列の順序で隣接する極値を常に選択することは失敗します。これは、最適なサブシーケンスが入力の隣接性に結び付けられるのではなく、値の振動に関連付けられるためです。 

## アプローチ

 ブルートフォースアプローチでは、すべてのサブシーケンスを列挙し、その絶対差の合計を計算し、最良の結果を追跡します。 これは定義に直接従うため正しいですが、各要素が含まれるか除外される可能性があるため、指数関数的な時間が必要になります。 n = 100000 では、n = 40 でもすでに大きすぎます。 

重要な観察は、差の絶対和は増加する動きと減少する動きの間の遷移のみに依存するということです。 サブシーケンスを取得して連続する要素を確認すると、方向が変わるたびに、極端な値の間でフルスイングを使用していないため、潜在的な寄与が「無駄」になります。 

合計を最大化するには、サブシーケンスが順列の意味のあるすべての「転換点」を捕捉する必要があります。 順列では、値において隣接する要素の間にあるすべてのローカル中間要素を、達成可能な最大の合計差分を減少させることなく削除できます。 これは、シーケンスを増加セグメントと減少セグメントの交互の実行に圧縮し、これらの実行のエンドポイントのみを保持することを示唆しています。 

同様に、最適なサブシーケンスは、順列をスキャンするときに値の順序ですべての極小値と極大値で構成されます。 これらは、まさに、連続して保持される要素間の値の比較の観点から見たときに、値シーケンスの方向が変わるポイントです。 

これを形式化できます。順列をスキャンするときに、新しく保持される各要素が現在の「傾向変化構造」を拡張する必要がある候補サブシーケンスを保持します。 最後に選択した 2 つの要素と新しい候補が同じ方向の単調な場合、中央の要素は不要なので置き換えることができます。 

これにより、傾きの変化を生み出す要素のみを保持する線形貪欲な構築が可能になり、不必要な中間点はすぐに破棄されるため、合計の変動を最大化しながら点の数も最小限に抑えられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 左から右へ順列をスキャンしながら、段階的に答えを構築します。

1. 選択したサブシーケンスを表す空のリストから始めます。 私たちは、これまでに見られた差異の達成可能な最良の「形状」を常に維持するように維持していきます。 
2. 順列内の各要素について、それをサブシーケンスに追加してみます。 
3. 追加後、最後の 3 つの要素が単調な傾向を形成しているかどうかを確認します。 最後の 3 つの要素が厳密に増加または厳密に減少している場合、中央の要素は最適な「ターン」に寄与しないため、削除できます。 削除させていただきます。 

その理由は、単調トリプルでは、​​絶対的な差が端点間の単一の直接ジャンプに崩壊するため、中間点をスキップすることで 2 つのエッジからの合計寄与をより効率的に達成できるということです。 

1. 最後の 3 つの要素が単調なままである間に、削除手順を繰り返します。 これにより、サブシーケンスは可能な限り常に方向を変えることが保証されます。 
2. すべての要素を処理した後、結果として得られるサブシーケンスには最大の絶対差の合計が含まれることが保証されます。 複数のサブシーケンスが同じ合計に達する場合、このプロセスではすべての冗長な中間要素が即座に削除されるため、自然に最も短いサブシーケンスが生成されます。 

### なぜ効果があるのか

 このアルゴリズムでは、連続して選択された 3 つの要素が同じ方向を保持しないように強制されます。 これは、サブシーケンス内のすべての内部点がターニング ポイント、つまりサブシーケンス内の隣接点に対する極大値または極小値のいずれかであることを意味します。 

回転しない中間要素を含むサブシーケンスは、絶対差の合計を減らさずにその要素を削除することで改善できます。 したがって、あらゆる最適解は、価値を失うことなくこの交互の特性を満たすものに変換できます。その中で、貪欲な構築では、削除可能なポイントが出現するとすぐにすべて削除することで、最小限の要素を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    p = list(map(int, input().split()))
    
    res = []
    
    for x in p:
        res.append(x)
        
        while len(res) >= 3:
            a, b, c = res[-3], res[-2], res[-1]
            if (a < b < c) or (a > b > c):
                res.pop(-2)
            else:
                break
    
    print(len(res))
    print(*res)

if __name__ == "__main__":
    t = int(input())
    for _ in range(t):
        solve()
```コア構造はスタックのようなリストです`res`、現在のサブシーケンス候補を保存します。 新しい要素がそれぞれ追加されてから、最後の 3 つの要素を検査します。 厳密に単調なトリプルを形成する場合、方向の変化には寄与せず、長さが増加するだけであるため、中央の要素は削除されます。 

1 つの要素を削除すると、以前の要素を含む新しい単調トリプルが公開される可能性があるため、while ループは不可欠です。そのため、不変条件を繰り返し適用します。 

操作の順序は重要です。常に最初に追加し、次に単純化します。 これにより、すべての要素が破棄される前に潜在的なターニングポイントとして考慮されることが保証されます。

 ## 特殊なケース

 次のような厳密に増加する順列`1 2 3 4 5`完全にモノトーンです。 このアルゴリズムは、トリプルが現れるまで要素を追加し、その後、単調トリプルの中間要素を継続的に削除し、最終的にエンドポイントのみを残します。 この入力の場合、シーケンスは次のように圧縮されます。`[1, 5]`, 単調なチェーンを形成するとすぐに、すべての中間要素が削除されるためです。 

厳密に減少する順列は対称的に動作します。 新しい要素はそれぞれ、トリプルになるまで減少するランを拡張します。その後、中間の要素が削除され、再び次のようなエンドポイントのみが残ります。`[5, 1]`保持する方向によって異なります。
