 ## 解決策

 ## 問題の理解

 接続された無向グラフが与えられます。 グラフと一緒にパラメータが与えられます$k$そして、グラフからどのような構造を保証できるかに応じて、2 つの可能な出力のうちの 1 つを生成するように求められます。 

最初のオプションは、セット内の 2 つの頂点がエッジを共有しないように頂点のセットを出力することです。このセットのサイズは正確に一致する必要があります。$\lceil k/2 \rceil$。 これは古典的な独立セットの要件です。ペアごとに隣接しない頂点を選択しています。 

2 番目のオプションは、長さが次の値を超えない単純なサイクルを出力することです。$k$。 単純なサイクルとは、ある頂点から開始し、エッジをたどり、中間の頂点を繰り返さずに開始頂点に戻ることを意味します。 

重要な問題は、どの構造が存在するのかが分からないことです。 十分に大きな独立セットまたは短いサイクルのいずれかを構築する必要があり、そのうちの少なくとも 1 つが常に存在することが保証されます。 

制約は厳しいです: まで$10^5$頂点と$2 \cdot 10^5$エッジ。 サイクルを列挙したり、すべてのサブセットをチェックしようとしたソリューションは、すぐに失敗します。 テストごとに線形または線形に近い走査が必要なため、自然な方向は、慎重にブックキーピングを行った DFS や BFS などのグラフ走査です。 

構造のない独立したセットに貪欲に頂点を選択しようとすると、微妙な失敗例が発生します。 多くの短いサイクルを含む密な領域またはグラフでは、貪欲な色付けのようなアプローチにより、誤って小さすぎるセットが生成されたり、利用可能な短いサイクルを見逃したりする可能性があります。 DFS は役に立たない長いサイクルを簡単に検出できるため、深さを制御せずにサイクルを直接検索すると、別の障害モードが表示されます。$k$小さいです。 

中心となる緊張は、グラフが局所的にツリーのように動作して大規模な 2 分割構造を可能にするか、小さなサイクルをすぐに生み出す短いバックエッジを含むかのどちらかであることです。 

## アプローチ

 ブルートフォース解釈では、長さまでのすべてのサイクルを検出しようとします。$k$また、特定のサイズの最大独立セットも計算します。 どちらも実現不可能です。 一般的なグラフでサイクルを列挙すると、単純なサイクルの数が指数関数的に増加する可能性があるため、最悪の場合は指数関数的になります。 同様に、特定のサイズの独立したセットを計算することは一般に NP 困難であり、近似であっても正確なサイズ要件が保証されるわけではありません。 

重要な観察は、最適な構造は必要ないということです。 「非ツリー性」の 2 つの証明書のうちの 1 つだけが必要です。つまり、短いサイクルが存在するか、深さのパリティから大きな独立セットを抽出するためにグラフが BFS の意味で十分にツリー状であるかのいずれかです。 

任意のノードで BFS/DFS トラバーサルをルート化し、各ノードに深さを割り当てます。 BFS ツリー構造の観点からエッジを考えると、非ツリー エッジは同じ深さのノードまたは小さな深さの差を持つノードのいずれかを接続します。 このようなエッジは、深さの合計によって長さが制限されるサイクルを直ちに生成します。 

トラバース中に短いサイクルに遭遇しなかった場合、グラフは深さまでツリーのように動作します。$k$そして、BFS ツリーの交互のレベルからすべてのノードを安全に取得できます。 2 つのパリティ クラスのいずれかには、最初のパリティ クラスの少なくとも半分が含まれている必要があります。$k$少なくとも独立したサイズのセットを保証するレベル$\lceil k/2 \rceil$。 

これにより、問題は、親追跡と深度ストレージを使用した単一の BFS/DFS トラバーサルに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サイクル/独立セット検索 | 指数関数 | 大 | 遅すぎる |
 | バックエッジ検出 + パリティ選択を備えた BFS |$O(n+m)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 深さと親ポインターを追跡する際に、ノード 1 からの DFS (または BFS) を使用します。 

1. 任意の頂点から DFS を開始し、その深さを 0、親をそれ自体としてマークします。 また、再帰またはキューを介して DFS 注文を暗黙的に保存します。 
2. 訪問したノードごとに$u$、隣接するすべての頂点を探索します$v$。 
3. もし$v$未訪問です、割り当てる$depth[v] = depth[u] + 1$そしてその親を次のように設定します$u$し、DFS を続行します。 
4. 訪問した頂点に遭遇した場合$v$それはの親ではありません$u$、バックエッジを発見しました。 これによりサイクルが生まれます。 
5. から歩いてサイクルを再構築する$u$そして$v$最下位の共通祖先で出会うまで、親ポインタを介して上に進みます。 これで自転車道が出来上がります。 
6. サイクル長が最大の場合$k$、すぐにタイプ2の答えとして出力します。 
7. 横断中にそのようなサイクルが見つからない場合は、深さに依存します。 深さのパリティによって頂点を分割します。 
8. 少なくとも次のパリティ クラス (偶数または奇数) を選択します。$\lceil k/2 \rceil$最初の頂点の中の$k$深度を訪問し、出力します$\lceil k/2 \rceil$そこからの頂点。 

### なぜ効果があるのか

 DFS ツリーは、すべての非ツリー エッジがサイクルを形成することを保証します。 トラバーサル中に発見されたサイクルは、祖先と子孫の間のバックエッジ (または無向 DFS のクロスエッジ) に対応する必要があり、親ポインターを介して再構築すると単純なサイクルが得られます。 

短いサイクルが見つからない場合は、グラフ内のすべてのサイクルが長い必要があります。 これは、最初の範囲内で、$k$DFS ツリーの各層では、構造は短いバックエッジのないツリーのように動作します。 ツリーでは、隣接するノードが常に深さパリティを交互に切り替えるため、1 つのパリティ クラスを選択すると、選択したノード間に内部エッジが存在しないことが保証されます。 あるので$k$レベルを考慮すると、1 つのパリティが頂点の少なくとも半分に寄与し、必要なサイズの独立したセットを確保する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n, m, k = map(int, input().split())
g = [[] for _ in range(n + 1)]

for _ in range(m):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

parent = [-1] * (n + 1)
depth = [-1] * (n + 1)
vis = [False] * (n + 1)

cycle = []

def dfs(u, p):
    global cycle
    vis[u] = True
    parent[u] = p
    for v in g[u]:
        if v == p:
            continue
        if vis[v]:
            # found a back-edge, reconstruct cycle
            path_u, path_v = [], []
            x, y = u, v
            while x != y:
                if depth[x] >= depth[y]:
                    path_u.append(x)
                    x = parent[x]
                else:
                    path_v.append(y)
                    y = parent[y]
            path_u.append(x)
            cycle = path_u + path_v[::-1]
            return True
        else:
            depth[v] = depth[u] + 1
            if dfs(v, u):
                return True
    return False

depth[1] = 0
dfs(1, -1)

if cycle and len(cycle) <= k:
    print(2)
    print(len(cycle))
    print(*cycle)
else:
    even, odd = [], []
    for i in range(1, n + 1):
        if depth[i] % 2 == 0:
            even.append(i)
        else:
            odd.append(i)

    res = even if len(even) >= len(odd) else odd
    res = res[: (k + 1) // 2]

    print(1)
    print(*res)
```DFS は、すべてのノードがその祖先を認識できるように親ポインター ツリーを維持します。 これは、各ステップで完全なパスを保存せずにサイクルを再構築するために不可欠です。 サイクル再構築ステップでは、2 つのポインターが出会うまで上向きに上昇し、反復的な走査ではなく単純なサイクルを確実に取得します。 

独立したセットの構築は、BFS/DFS 深度パリティに依存します。 ここでは DFS のみを使用しますが、パリティ引数は引き続き有効です。これは、親子エッジが常に反対パリティのノードに接続するためです。そのため、DFS ツリー内では単一のパリティ クラスは内部的に隣接しておらず、短いサイクルがないため、クロス エッジが境界に違反することはありません。 

最後のスライス手順により、必要な数の頂点のみが取得されるようになります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、グラフに 2 よりも長いサイクルが含まれる場合です。$k$。 この場合、DFS はサイクルを検出する可能性がありますが、その長さが制限を超えています。 アルゴリズムはそれを正しく破棄し、独立したセットにフォールバックします。 たとえば、次の 6 サイクルでは、$k = 3$、DFS は 6 サイクルを見つけますが、代わりにパリティ クラスから独立したセットを出力します。 

もう 1 つのエッジ ケースは、グラフがすでにツリーになっている場合です。 バックエッジがないため、サイクルは空のままです。 このアルゴリズムは深度パリティを直接使用し、ツリーは 2 部構成であるため、常に有効な独立セットが得られます。 

3 番目のエッジ ケースは、複数のバック エッジが存在する場合に発生します。 DFS は最初に見つかったサイクルで停止しますが、長さの制約を満たす限りどのサイクルでも受け入れられるため、これで十分です。 最初のサイクルが大きすぎる場合は、フォールバックによって正確さが保証されます。
