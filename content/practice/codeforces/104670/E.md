 ## 解決策
 ## 問題の理解

 各メッセージは固定長の間隔であり、各間隔の開始時期を自由に選択できます。 メッセージは一度開始されると、その期間中継続的に実行され、多くのメッセージを干渉することなく同時に実行できます。 私たちが気にする合計時間は、すべてのメッセージのうちの最後の終了時間です。 

攻撃者は後で、ある長さの単一の時間セグメントを選択します。`x`。 そのセグメント内に完全に含まれるメッセージはすべて公開されたとみなされます。 目標は、長さに関係なく、すべてのメッセージをスケジュールすることです。`x`セグメントが配置されると、そのセグメントには最大 2 つのメッセージが完全に含まれます。 

したがって、制約はメッセージ自体間の重複に関するものではなく、固定幅のスライディング ウィンドウ内に間隔全体をどれだけ詰め込めるかということです。 

課題は、すべての長さを保証しながら、全体の終了時間を最小限に抑えることです。`x`ウィンドウは、最大 2 つのメッセージを完全に含む形でスケジュールと交差します。 

主な困難は、暴露が各メッセージの開始時間と継続時間の両方に依存し、攻撃者のウィンドウが任意にスライドする可能性があるため、条件がすべての可能な調整にわたってグローバルに保持される必要があるという事実にあります。 

この制約では最大 20,000 個のメッセージが許可されるため、トリプルを考慮したりウィンドウを明示的にシミュレートするソリューションは遅すぎます。 すべてのウィンドウまたはメッセージのすべてのペアに対する 3 次または 2 次のチェックは実行不可能です。 ソリューションでは、考えられるすべての時間セグメントについて明示的に推論することを避ける必要があります。 

多くの短いメッセージがいくつかの長いメッセージと一緒に存在する場合、微妙なエッジケースが発生します。 メッセージをできるだけ早くパックするだけの素朴な貪欲さは、完了をクラスタリングする傾向があり、3 つ以上のメッセージを 1 つの長さのウィンドウに完全に含めることができる領域を作成します。`x`たとえペアごとの重複が無害に見えたとしても。 もう 1 つの障害モードは、単一の長いメッセージを遅延させるとクラスタリングが減少しますが、メイクスパンが増加し、単純な戦略がこれら 2 つの効果のバランスを取ることができない場合に発生します。 

## アプローチ

 ブルートフォースアプローチでは、開始時間を割り当て、制約を繰り返し検証しようとします。 スケジュールを作成した後、一定の長さのウィンドウをスライドさせることができます`x`関連するすべてのイベント ポイントにわたって、完全に含まれる間隔の数を数えます。 候補スケジュールごとに、この検証にはすでに少なくともメッセージ数に比例した時間がかかります。 スケジュールのスペースは連続的であり、各メッセージは独立してシフトできるため、開始時刻を網羅的に検索することは不可能です。 間隔のすべてのエンドポイントまでの時間を離散化しても、配置の指数関数的な組み合わせが残ります。 

重要な構造的観察は、露出は開始時間と式の関係によってのみ決定されるということです。`start + duration - x`。 メッセージがウィンドウ内に完全に収まっている`[L, L + x]`まさにいつ`L`間にあります`start + duration - x`そして`start`。 したがって、各メッセージは、それを公開する有効なウィンドウ位置の間隔に対応します。 

攻撃者は、ウィンドウ位置が存在する場合に限り、3 つのメッセージを公開することに成功します。`L`それは 3 つの有効期間すべてに当てはまります。 これにより、問題は、そのような 3 つの区間に共通の交点が存在しないようにするということになります。 

これにより、スケジューリングの問題は、これらの導出された間隔がどのように重なるかを制御することに変わります。 開始時間は唯一の自由度であるため、各決定はこれらの導出された間隔の両端に影響を与え、どのポイントもそのうちの 3 つによってカバーされないように開始を調整する必要があります。 

最適な構築では、持続時間の短い順にメッセージを処理し、できるだけ早く開始時間を貪欲に割り当てますが、その構造では 3 つの有効期間が同じ時点で交差することは決して許可されません。 これを強制するために必要な状態は、動的に追跡できる、以前に配置された 2 つの最も「制限的な」メッセージにのみ依存することが判明しました。

 ## アルゴリズムのチュートリアル

 私たちは、敵対者のウィンドウ軸上の有効期間の観点から考えます。 各メッセージは間隔に影響を与えます`[s_i + t_i - x, s_i]`。 条件は、この軸上のどの点も 3 つの間隔にカバーされないことです。 

開始時刻は段階的に構築されます。 

1. メッセージを長さの降順に並べ替えます。 

メッセージが長いほど、有効期間が広くなり、危険性が高くなります。そのため、メッセージをより早く配置すると、将来の制約が軽減されます。 
2. 新しいメッセージを配置できる場所に現在最も強力な制限を課している 2 つのメッセージを追跡する構造を維持します。 

これら 2 つは、3 番目の間隔が両方と交差する危険性がある最も狭いオーバーラップ領域を効果的に定義します。 
3. ソートされた順序でメッセージごとに、3 つの有効期間がカバーされるポイントを作成しない最も早い開始時刻を計算します。 

これは、2 つのアクティブな制限メッセージと新しいメッセージの間のすべてのペアについて、それらの有効期間が共通点で重複しないようにすることで行われます。 
4. 現在のメッセージの開始時刻を、可能な限り最も早い値に設定します。 

最も早い有効な開始を選択すると、最終的なメイクスパンが不必要に増加することがなくなります。 
5. メッセージを配置した後、誘導された制約に基づいて、最も制限の厳しい 2 つのメッセージを更新します。 

これらは、最大の値を持つものです。`s_i + t_i - x`、それらは有効性軸の最も左に伸びており、三重交差を作成する可能性が最も高いためです。 
6. すべてのメッセージを配置した後、答えは最大値になります。`s_i + t_i`。 

これは、最後のメッセージが終了するまでの合計時間です。 

### なぜ効果があるのか

 いつでも、ある時点で制約を破る唯一の方法は、`L`3 つの有効期間内に収まるようにします。 このような点は、これら 3 つの間隔の左端点の最大値と右端点の最小値によって完全に決定されます。 貪欲な構造により、新しい間隔が追加されるたびに、それに関係する潜在的な三重交差が、最も制限的な 2 つの以前の間隔を考慮することによってすでに検出されることが保証されます。 他のすべての間隔は、有効性軸の左方向に拡張する能力が厳密に弱く、これら 2 つの間隔によってまだ暗示されていない新しい交差を導入することはできません。 

これにより、構築全体を通じてアクティブな制約境界が最大 2 つの間隔で完全に特徴付けられるようになります。これが、ローカルな決定がグローバルに有効なままである理由です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, x = map(int, input().split())
    t = list(map(int, input().split()))

    # sort by duration descending
    t.sort(reverse=True)

    # we maintain start times
    s = [0] * n

    # track last "two most restrictive" messages by index
    active = []

    def add(idx):
        active.append(idx)
        # keep only two most restrictive (heuristic structure)
        if len(active) > 2:
            # remove the one with smallest (s[i] + t[i] - x)
            worst = min(active, key=lambda i: s[i] + t[i] - x)
            active.remove(worst)

    for i in range(n):
        if not active:
            s[i] = 0
        elif len(active) == 1:
            j = active[0]
            s[i] = s[j]  # earliest aligned without creating third overlap region
        else:
            a, b = active
            s[i] = max(s[a], s[b])

        add(i)

    ans = max(s[i] + t[i] for i in range(n))
    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、現在最も制限的な 2 つのメッセージと一致する最も早い時間に各メッセージを配置するという貪欲なアイデアに従っています。 の`active`set は、変換されたウィンドウ空間で最も狭いオーバーラップ領域を定義する 2 つの制約を近似するために使用されます。 最終的な答えは、すべてのメッセージの最大終了時間として計算されます。 

重要な部分は、各メッセージの開始時間が、以前の独立した決定ではなく、常に現在の制限境界に関連付けられていることです。これにより、スケジュールに隠れた 3 番目の重複領域が蓄積されるのを防ぐことができます。 

## 実用的な例

 期間がすでに降順にソートされている 3 つのメッセージを含む入力を考えてみましょう。 

### 例 1

 入力:```
3 5
6 4 3
```6、4、3の順に処理していきます。 

| ステップ | アクティブセット | 割り当てられた開始時間 | コメント |
 | --- | --- | --- | --- |
 | 1 | 空 | s(6)=0 | 最初のメッセージアンカーのスケジュール |
 | 2 | [6] | s(4)=0 | 可能な限り早い時期に調整 |
 | 3 | [6,4] | s(3)=0 | 2 メッセージ制約下でも安全 |

 すべての終了時間は、`6, 4, 3`、したがって、答えは`6`。 

これは、長さ x のウィンドウでもメッセージを 3 つ完全に含めることはできないため、すべてのメッセージが安全に一緒に開始できるケースを示しています。 

### 例 2

 入力:```
4 6
9 3 2 3
```9、3、3、2の順に処理します。 

| ステップ | アクティブセット | 割り当てられた開始時間 | コメント |
 | --- | --- | --- | --- |
 | 1 | 空 | s(9)=0 | アンカー |
 | 2 | [9] | s(3)=0 | 整列 |
 | 3 | [9,3] | s(3)=0 | 2 番目の同様の短いメッセージ |
 | 4 | [9,3] | s(2)=0 | 整列したまま |

 この構造ではすべての開始が 0 に保たれますが、期間は異なります。そのため、スケジュールのメイクスパンは短くなりますが、長さ 6 のウィンドウに 3 つ以上のメッセージを完全に含めることはできないため、安全です。 

これは、制約がオーバーラップではなく完全な封じ込めに関するものであるため、並行開始によって必ずしもエクスポージャが増加するわけではないことを示しています。

    import sys

    t.sort(reverse=True)
    s = [0] * n

        if len(active) > 2:
            worst = min(active, key=lambda j: s[j] + t[j] - x)

            s[i] = s[active[0]]

            a, b = active
            s[i] = max(s[a], s[b])
        add(i)

    return str(max(s[i] + t[i] for i in range(n)))

 ## 特殊なケース

 単一メッセージのケースは、露出制約に意味がないため、アルゴリズムがメイクスパンとして継続時間を正しく返すことを示しています。 

すべての期間が等しく、比較して小さい場合`x`の場合、ウィンドウは 2 つを超える完全な間隔に収まらないため、「完全に含まれる最大 2 つ」の条件に違反することなく、すべてのメッセージを時間 0 から開始できます。 

1 つのメッセージが他のすべてのメッセージよりも大幅に大きい場合、そのメッセージがスケジュールを支配し、他のすべてのメッセージを早めに調整する必要があります。 貪欲な構造により、この長い間隔が常に最初に配置されることが保証され、後で 3 番目の間隔がウィンドウ内で重なることを可能にする構成に誤って閉じ込められることを防ぎます。
