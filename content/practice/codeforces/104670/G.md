 ## 解決策
 ## 問題の理解

 私たちには、無限平面上の円形の「ダメージ ゾーン」の小さなコレクションが与えられます。 各ゾーンは中心点と半径によって定義され、その円の内側または上のすべてを破壊します。 タスクは、これらの円の少なくとも 1 つによってカバーされる合計面積を計算し、重複を 1 回だけカウントすることです。 

言い換えれば、平面内に最大 10 個のディスクを結合した領域が必要です。 座標と半径はすべて小さな整数ですが、ジオメトリは連続しているため、答えは実数になります。 

制約は非常に許容的で、半径が 10 までの円は最大 10 個までです。 これはすぐに、たとえ$O(n^3)$幾何学的アルゴリズムは技術的には問題ないかもしれませんが、本当の問題は速度ではなく、円の正確な結合領域が幾何学的に乱雑であることです。 円間の交差により曲線の境界が生成され、直接的な解析計算はすぐに複雑になります。 

素朴な考えは、すべてのペアごとの重複を計算し、包含と除外を試みることです。 これは失敗します。なぜなら、円の閉じた形式では三重交差をきれいに特徴付けるのが難しいからです。 ペアごとのオーバーラップに制限したとしても、交差部分を正しく減算するには、レンズ形状の領域を慎重に処理する必要があります。 

2 番目の単純なアイデアは、平面を細かいグリッドで離散化し、覆われたセルをカウントすることです。 これは精神的には機能しますが、実行時間を合理的に保ちながら 10% の相対誤差を保証するには慎重な調整が必要であり、決定論的なグリッド解像度を連続ジオメトリで推論するのは困難です。 

微妙なエッジケースが完全に重なっています。 すべての円が同一である場合、答えはちょうど 1 つの円の面積になるはずです。 このシナリオでは、単純な包含と除外の試みが非常に重要になることがよくあります。 

もう 1 つの特殊なケースは、遠く離れて配置されたばらばらの円です。 どのような近似でも、まばらな領域での重複や過少カウントに偏ってはなりません。 

中心的な課題は、このような小さな制約に対して正確なジオメトリは過剰であり、制御された近似で十分であることです。 

## アプローチ

 ブルートフォースの正確なアプローチでは、幾何学的分解を使用して円の結合を計算しようとします。 すべての円と円の交点を計算し、境界を円弧に分割し、結合境界を平面の細分割として再構成することができます。 次に、円形セグメントを統合することによって結合領域が計算されます。 これは原理的には正しいですが、堅牢な円配置構築の実装には負担がかかり、円弧処理における小さな数値誤差さえも正確さを損なう可能性があります。 

計算コストも急速に増大します。 と$n \le 10$、ペアごとの交差は最大 45 個ありますが、アークのソートとポリゴン化を処理すると、一定のかなりの複雑さと壊れやすいジオメトリが生じます。 

重要な観察は、必要な精度が弱いということです。許容される相対誤差は 10% だけです。 これは、正確な幾何学的な構築が不要であることを直ちに示唆します。 代わりに、モンテカルロ サンプリングを使用して面積を推定できます。 

すべての円を外接する四角形で囲みます。 次に、この長方形内で多数のランダムな点を均一にサンプリングし、各点が少なくとも 1 つの円の内側にあるかどうかを確認します。 内部の点の割合は結合面積率に近似します。 長方形の面積を乗算すると、結合面積の推定値が得られます。 

なぜなら$n$小さいので、各点内円チェックのコストはわずかです$O(n)$、全体の複雑さは次のようになります。$O(S \cdot n)$、 どこ$S$はサンプル数です。 と$S$これは 100 万から 200 万程度で、Python では十分に高速です。 

境界ボックスは簡単に構築できます。$\min(x_i - r_i)$に$\max(x_i + r_i)$両方の座標で。 

話は単純です。円の境界が曲線的に相互作用するため、正確な幾何学形状は複雑ですが、サンプリングでは境界構造が完全にバイパスされ、統計的推定に置き換えられます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 正確な幾何学的結合 |$O(n^2 \log n)$に$O(n^3)$重いジオメトリを使用 |$O(n^2)$| 不必要に複雑 |
 | モンテカルロサンプリング |$O(S \cdot n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ディスクの最小範囲と最大範囲を取得して、すべての円を含む軸に合わせた境界四角形を計算します。 これにより、カバーされる可能性のあるすべてのポイントが、結合を完全に含む領域から確実にサンプリングされます。 
2. 固定数のランダムサンプルを選択します$S$、通常は約100万です。 固定サンプルサイズにより分散が安定し、決定的な実行時間が確保されます。 
3. 各サンプルについて、外接する四角形の内側に均一にランダムな点を生成します。 
4. その点について、それが少なくとも 1 つの円の中にあるかどうかをチェックしてテストします。$(x - x_i)^2 + (y - y_i)^2 \le r_i^2$どのサークルでも。 
5. 少なくとも 1 つの円内に含まれるサンプル点の数を数えます。 
6. カバーされる領域を次のように推定します。$$\text{area} = \frac{\text{inside count}}{S} \times \text{bounding rectangle area}.$$これが機能する理由は、均一サンプリングが幾何学的領域を確率に変換するためです。 境界ボックス内のランダムな点が和集合内に存在する確率は、和集合領域とボックス領域の比率に等しくなります。 サンプリングによるこの確率の推定は、サンプル数が増加するにつれて真の値に収束します。 

## Python ソリューション```python
import sys
import random

input = sys.stdin.readline

def solve():
    random.seed(1)

    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)

    circles = []
    min_x = min_y = 10**9
    max_x = max_y = -10**9

    for _ in range(n):
        x, y, r = map(int, input().split())
        circles.append((x, y, r))
        min_x = min(min_x, x - r)
        max_x = max(max_x, x + r)
        min_y = min(min_y, y - r)
        max_y = max(max_y, y + r)

    if n == 0:
        print("0.0")
        return

    S = 1_500_000
    inside = 0

    for _ in range(S):
        x = random.uniform(min_x, max_x)
        y = random.uniform(min_y, max_y)

        for cx, cy, r in circles:
            dx = x - cx
            dy = y - cy
            if dx * dx + dy * dy <= r * r:
                inside += 1
                break

    box_area = (max_x - min_x) * (max_y - min_y)
    ans = box_area * inside / S
    print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```この実装は固定ランダム シードに依存しているため、繰り返し実行が決定的になります。 バウンディングボックスの計算により、サンプリングで円の一部が見逃されることがなくなります。 円ループ内の早期のブレークにより、ポイントがすでにカバーされている場合の不必要なチェックが削減されます。 

主な微妙な点は、すべての円を完全に含みながら、サンプルの無駄を避けるために境界ボックスを十分にタイトにすることです。 

## 実用的な例

 ### 例 1

 入力:```
1
0 0 1
```単一の単位円があります。 境界ボックスは次のようになります。$[-1, 1] \times [-1, 1]$。 

| サンプルフェーズ | 値 |
 | --- | --- |
 | 境界ボックス領域 | 4 |
 | インサイドレシオ（予想） | π/4 |
 | 推定面積 | ≈ π |

 これにより、推定器が正しい円領域に収束していることが確認されます。 

ここで示されている不変条件は、境界ボックス上の均一なサンプリングにより、曲線状の境界であっても比例面積表現が維持されるということです。 

### 例 2

 入力:```
2
0 0 2
2 0 2
```これらの円はかなり重なり合っています。 

| フェーズ | 観察 |
 | --- | --- |
 | 境界ボックス | [-2, 4] × [-2, 2] |
 | ジオメトリ | x = 1 | 付近の強い重複領域
 | 予想される動作 | 重複は 1 回としてカウントされます |

 最初の円に到達した後にブレークするため、交差点内のどの点も 1 回だけカウントされるため、サンプリングによってオーバーラップが自然に処理されます。 

これは、オーバーラップの明示的な修正が必要ないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(S \cdot n)$| S 個のサンプルのそれぞれは、最大 n 個の円をチェックします。 
| スペース |$O(n)$| サークルリストのみの保管 |

 と$n \le 10$そして$S \approx 1.5 \times 10^6$、距離チェックの総数は約 1,500 万回で、これは Python の時間制限内に余裕で収まります。 

## テストケース```python
import sys, io, random

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    random.seed(1)

    circles = []
    data = inp.strip().split()
    if not data:
        return ""

    n = int(data[0])
    idx = 1

    min_x = min_y = 10**9
    max_x = max_y = -10**9

    for _ in range(n):
        x = int(data[idx]); y = int(data[idx+1]); r = int(data[idx+2])
        idx += 3
        circles.append((x, y, r))
        min_x = min(min_x, x - r)
        max_x = max(max_x, x + r)
        min_y = min(min_y, y - r)
        max_y = max(max_y, y + r)

    if n == 0:
        return "0.0\n"

    S = 200000
    inside = 0

    for _ in range(S):
        x = random.uniform(min_x, max_x)
        y = random.uniform(min_y, max_y)
        for cx, cy, r in circles:
            dx = x - cx
            dy = y - cy
            if dx*dx + dy*dy <= r*r:
                inside += 1
                break

    box_area = (max_x - min_x) * (max_y - min_y)
    ans = box_area * inside / S
    return f"{ans:.10f}\n"

# provided sample-like checks (deterministic due to seed)
assert run("1\n0 0 1\n") == run("1\n0 0 1\n"), "determinism check"

# all same circle overlap case
assert run("2\n0 0 1\n0 0 1\n") == run("1\n0 0 1\n"), "identical circles"

# disjoint circles
assert run("2\n0 0 1\n10 10 1\n") != "", "non-empty output"

# single point-sized circle edge-ish
assert run("1\n0 0 10\n") != "", "large circle"

 | 同一の円 | 単一の円と同じ | オーバーラップ処理 |
 | ばらばらの円 | 有限和 | ユニオンロジックの正しさ |

 ## 特殊なケース

 同一円シナリオは、早期終了により円内のすべてのサンプル点が 1 回だけカウントされるため、自然に処理されます。 複数の円が完全に重なっている場合でも、インジケーター関数はバイナリのままです。 

大きく離れた円の場合、境界ボックスは大きくなりますが、サンプリングは依然として均一に分布するため、各領域は比例的に表現されます。 推定器は、互いに素な領域の合計を正確に近似します。 

単一円の極端なケースでは、すべてのサンプルは成功確率 πr² をボックス面積で割ったベルヌーイ試行とまったく同じように動作するため、収束は標準的で偏りはありません。
