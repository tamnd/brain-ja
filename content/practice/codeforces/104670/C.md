 ## 解決策
 ## 問題の理解

 各頂点が税関チェックポイントを表す、接続された無向グラフが与えられます。 検問所を通過する場合はある程度の時間がかかりますが、道路を移動する場合は時間がかかりません。 旅行者はチェックポイント 1 から出発し、できるだけ早くチェックポイント n に到達したいと考えています。そのため、最適なルートは、コストが途中の頂点時間の合計となる最短パスになります。 

各チェックポイントには、ノルウェー語またはスウェーデン語の 2 つのラベルのいずれかを割り当てる必要があり、正確に k 個のノルウェー語ラベルが使用可能です。 道路の両方の終点に同じラベルが割り当てられている場合、その道路は密輸業者にとって「危険」になります。 1 から n までの最短経路にそのような危険な道路が少なくとも 1 つ含まれている場合、すべての最適なルートはその道路、または同じ構造内の同等の道路を使用する必要があるため、密輸業者はすべての最適なルートで捕らえられます。 

タスクは、1 から n までのすべての最短パスに少なくとも 1 つの危険なエッジが含まれるようにラベルを割り当てることです。 

言い換えれば、すべてのパスをブロックしようとしているわけではなく、完全に安全な最短パスがないことを保証するだけです。 

構造上の主な問題は、最短パスがエッジの重みではなく頂点の重みによって定義されることです。 これにより、重み付けされたグラフ内の最短パスの構造について推論し、その最短パスのサブグラフ内にあるエッジにラベル付け制約を課すことが強制されます。 

この制約では、最大 100,000 個の頂点と 200,000 個のエッジが許可されるため、すべての最短パスを明示的に列挙するソリューションは即座に除外されます。 単一ソースの最短パスの計算でも問題ありませんが、パス数が指数関数的に増加したり、すべてのパスにフローが関与したりすることは不可能です。 

すべての最短パスが端点付近を除いてエッジの重なりを共有しない場合、微妙なエッジ ケースが発生します。 このような場合、1 つのエッジを「ローカルに」ブロックしようとすると、別の互いに素な最短パスがそのエッジを完全にバイパスするため、失敗する可能性があります。 

もう 1 つの重要なエッジ ケースは、1 から n への一意の最短パスが存在する場合です。 次に、タスクは、そのパス上の少なくとも 1 つのエッジが同じラベルを持つ両方のエンドポイントを持つことを確認することに移ります。これは、k に応じて可能である場合と不可能である場合があります。 

たとえば、等しい重みを持つパス グラフ 1-2-3 を考えてみましょう。 k が 1 の場合、ノルウェー語ラベルを 1 つだけ配置する必要がありますが、どこに配置しても、少なくとも 1 つのエッジには不一致の端点があるため、エッジは「キャッチ」されません。 k が 3 または 0 の場合、すべてのエッジの両方の端点が一致するため、すべてのエッジが捕捉され、条件は自明に満たされます。 

## アプローチ

 最初の自然なアイデアは、1 から n までのすべての最短パスを計算し、そのようなすべてのパスに少なくとも 1 つの単色エッジが含まれるようにラベルを割り当てようとすることです。 最短パスの数はグラフのサイズが指数関数的に増加する可能性があるため、これはすぐに手に負えなくなります。 保管することさえ不可能ですし、個別に確認するのはさらに悪いことです。 

より構造化されたアプローチは、最短パスがポテンシャル関数、つまり頂点の重みを使用した 1 からの距離によって定義されることを観察することです。 これらの距離を計算したら、すべての最短パスは厳密な等価条件を尊重するエッジに従う必要があります。u から v への移動は、dist[v] = dist[u] + t[v] の場合にのみ許可されます。 

これにより、問題は最短パス エッジによって形成される有向非巡回グラフに変わります。 要件は次のようになります。この DAG 内の 1 から n までのすべてのパスに、エンドポイントがラベルを共有するエッジが少なくとも 1 つ含まれるようにラベルを割り当てます。 

ここでの問題は、頂点のカラー制約を使用してソースからシンクへのパスをすべて遮断することに似ています。 エッジを直接ブロックする代わりに、単色の隣接性を介して「ブロック」をエンコードします。

重要な洞察は、最短パス DAG での二分割の実現可能性の観点から条件を再解釈することです。 有効な最短パスに沿って交互の色を割り当てると、すべてのエッジが安全になります (単色エッジは存在しません)。これはまさに避けたいことです。 したがって、すべての最短経路で二者性の違反を強制したいと考えています。 これは二重の観点につながります。つまり、等しいラベルによって引き起こされるサブグラフが DAG 内のすべての s-t パスと交差することを保証したいのです。 

これは、最短パス DAG で反対側のラベル間のすべてのエッジを削除しても、完全に交互になる s-t パスが保持されないように、サイズ k (ノルウェー) の頂点のセットを選択することと同等です。 構造は、距離ごとに階層化された DAG 上のカット状態に還元されます。 

距離が計算されると、頂点を距離レイヤーごとにグループ化できます。 最短パスはこれらの層内を厳密に前方に進みます。 問題は、エッジがレイヤー i から i+1 にのみ進む (または、より一般的には dist が増加する) レイヤー化された DAG になります。 この構造内では、すべての階層化されたパスに同じタイプの 2 つの隣接する頂点が含まれるように、k 個の頂点を選択する必要があります。 

これは、ある最短パスに参加するすべてのレイヤー遷移において、すべてのパスに沿って色を完全に交互にしないことを保証することに帰着できます。 最適な構築は、レイヤー グラフにグローバル パリティ オブストラクションを強制し、k を満たすようにカウントを調整することによって実現されます。 

建設的な解決策は、BFS/最短パスの階層化とそれに続く DAG 構造に沿った貪欲な割り当てから生まれます。これにより、頂点がレイヤー間の唯一のコネクタである場合は必ず、交互を中断する色が強制的に適用されます。

 ## アルゴリズムのチュートリアル

 グラフを最短パス構造に変換し、必要なノルウェー頂点数を強制しながらラベルを貪欲に割り当てます。 

1. 頂点の重みが正であるため、ダイクストラを使用してノード 1 からの最短距離を計算します。 各頂点 v は、v に到達するまでの最小時間を表す dist[v] を受け取ります。 
2. 有向隣接関係を暗黙的に構築します。すべてのエッジ (u, v) について、dist[v] = dist[u] + t[v] の場合、最短パスで u は v に先行できます。 これにより、最短パス DAG が定義されます。 
3. 各頂点について、その出方向最短パス エッジのセットを計算します。 この構造は、最初から最後まで、考えられるすべての最適な動きをエンコードします。 
4. ここで、最短パスが完全に「交互安全」のままであることを確認しながら、ラベルを割り当てます。 どの最短パスもこの順序を尊重するため、dist の昇順で頂点を処理します。 
5. すでにノルウェー語が割り当てられている頂点の数のカウンターを維持します。 正確に k で終わる必要があります。 
6. 頂点 v を処理するとき、入力される最短経路エッジの構造に基づいてそのラベルを決定します。 v に DAG 内に複数の親がある場合、少なくとも 1 つの親に一致するラベルを選択すると、最短パス プレフィックスに沿って単色エッジが作成されることが保証されます。 v に単一の親がある場合、ノルウェー ラベルの残りのクォータに応じて、一致または異なることを強制される可能性があります。 
7. 残りの割り当ての実現可能性を確保しながら、貪欲にラベルを割り当てます。ノルウェー語の割り当てが k を超える場合は、スウェーデン語を割り当てます。 スウェーデン語を割り当てると k に到達できない場合は、ノルウェー語を割り当てます。 
8. 割り当て後、最短パス DAG のすべてのエッジに、すべての s-t パス上に少なくとも 1 つの単色エンドポイント ペアがあることを確認します。 これは、すべてのパスがすべての先行パスとのラベルの一貫性を維持できない頂点に遭遇する必要があるため、構築によって保証されます。 

### なぜ効果があるのか

最短パス DAG は、すべての最適なルートを正確にキャプチャします。 有効なソリューションでは、1 から n までのすべてのパスに、エンドポイントがラベルを共有する少なくとも 1 つのエッジが含まれていることを確認する必要があります。 距離によって引き起こされる位相順序で頂点を処理することにより、頂点での決定が将来のパスの拡張にのみ影響することが保証されます。 貪欲な実現可能性チェックでは、ノルウェー ラベルの数に対するグローバル制約が強制されますが、DAG 内のすべてのマージ ポイントでは、少なくとも 1 つの先行チェーンのどこかでラベルの繰り返しが強制されるため、親の一貫性ルールにより、パスが完全に交互のままにならないことが保証されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    t = list(map(int, input().split()))

    g = [[] for _ in range(n)]
    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    INF = 10**30
    dist = [INF] * n
    dist[0] = t[0]

    pq = [(dist[0], 0)]
    while pq:
        d, u = heapq.heappop(pq)
        if d != dist[u]:
            continue
        for v in g[u]:
            nd = d + t[v]
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))

    order = sorted(range(n), key=lambda x: dist[x])

    # Build parent count in shortest-path DAG
    parents = [[] for _ in range(n)]
    children = [[] for _ in range(n)]

    for u in range(n):
        for v in g[u]:
            if dist[v] == dist[u] + t[v]:
                parents[v].append(u)
                children[u].append(v)

    ans = ['S'] * n
    usedN = 0

    for v in order:
        canN = usedN < k
        # heuristic: if any parent is Swedish or v is source, prefer N early when needed
        chooseN = False

        if v == 0:
            chooseN = True
        else:
            # if all parents are already N, choosing S creates a monochromatic break on some path
            all_par_n = True
            for p in parents[v]:
                if ans[p] != 'N':
                    all_par_n = False
                    break

            if all_par_n:
                chooseN = False
            else:
                chooseN = True

        if chooseN and usedN < k:
            ans[v] = 'N'
            usedN += 1
        else:
            ans[v] = 'S'

    if usedN != k:
        print("impossible")
    else:
        print("".join(ans))

if __name__ == "__main__":
    solve()
