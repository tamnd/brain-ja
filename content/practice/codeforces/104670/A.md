 ## 解決策
 ## 問題の理解

 一連の毎日の測定値が与えられ、毎日 1 つの整数値が与えられます。 毎日 i について、その日をそれより前の日 j (それ自体を含む) と比較し、時間距離にペナルティを課した後、それらの 2 日間の間で測定値の「意味のあるジャンプ」がどれくらい大きいかを計算します。 

2 日間のスコアは、測定値の絶対的な差から、日がどれだけ離れているかに比例したペナルティを差し引いたものとして定義されます。 形式的には、各 i についてすべての j ≤ i を考慮し、 |xi − xj| を評価します。 − c · (i − j) の場合、最大値を取得します。 

出力は、i 番目の値が i 日の最大スコアである配列です。 

n が 4 · 10^5 までの制約により、日のすべてのペアにわたる二次比較が直ちに除外されます。 単純な O(n^2) アプローチでは、10^11 程度の演算が必要になりますが、これは数秒で実現可能な限界をはるかに超えています。 これにより、通常はプレフィックス メンテナンスのトリックや、式を実行中のサマリーで最適化できるものに変換する変換を通じて、各インデックスが定数時間または対数時間で寄与するソリューションに向けて推進されます。 

すべての値が同一の場合、微妙なエッジケースが発生します。 その状況では、すべての差 |xi − xj| はゼロであり、答えはすべての i についてゼロになるはずです。 有効な選択肢として j = i を含めることを忘れたアプローチでは、誤って負の値が生成されたり、ゼロにクランプできなかったりします。 

もう 1 つのまれなケースは、最適な初期のインデックスが時間的に非常に近いものの、値がわずかに悪く、遠いインデックスの値がはるかに優れている場合に発生します。 これがまさに、単純な「最後の最大値または最小値を追跡する」戦略が失敗する理由です。時間ペナルティは値の差と相互作用し、変換しないと分離できないためです。 

## アプローチ

 ブルートフォース手法は簡単です。 毎日 i について、過去のすべての日 j を反復し、スコアを直接計算して、最良の状態を維持します。 これは、すべての候補ペアを明示的に評価するため、正しいです。 ただし、各 i は最大 i 個の値をスキャンするため、演算の合計数は 1 + 2 + … + n のように増加し、これは約 n^2 / 2 になります。n = 4 · 10^5 では、これは完全に実行不可能になります。 

重要な観察は、xi が xj より大きいかどうかに応じて、絶対値によって問題が 2 つの線形形式に分割されるということです。 各形式は、j に対するすべての依存関係がプレフィックス統計に分離されるように再配置できますが、i に対するすべての依存関係はインデックスごとに 1 回計算する単純な式になります。 

式を展開すると 2 つのケースが得られます。 絶対値を取り除くと、xi − xj または xj − xi のいずれかが得られます。 時間ペナルティ c · (i − j) を拡張すると、これらのそれぞれは i と j で線形になります。 これにより、以前のすべての j にわたって 2 つの実行量を維持するように問題を書き直すことができます。1 つは xj − c · j の最小値を追跡し、もう 1 つは xj + c · j の最大値を追跡します。 

これにより、i 日目には xi とこれら 2 つのプレフィックス要約を組み合わせるだけなので、各クエリが定数時間に短縮されます。

 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 以前のすべてのインデックスに関する情報を維持しながら、配列を左から右に処理します。

1. スキャン中に 2 つの実行値を維持します。つまり、これまでに確認されたすべての j の xj − c · j の最小値と xj + c · j の最大値です。 これらは、絶対値の 2 つの可能な方向に一致する方法で、以前のすべての選択を要約します。 
2. 各インデックス i について、2 つの答えの候補を計算します。 最初の候補は、xi が xj より大きい場合に相当し、(xi − c · i) − min(xj − c · j) となります。 これは、以前に確認された最良の「低い調整値」と比較して、xi がどのくらい大きいかを測定します。 
3. 2 番目の候補は、xj が xi より大きい場合に対応し、max(xj + c · j) − (xi + c · i) となります。 これは、以前の高い調整値が現在の調整値と比較してどのくらい大きいかを測定します。 
4. i 日目の答えは、これら 2 つの候補の最大値です。 計算後、現在のインデックス i を使用して両方の実行サマリーを更新し、将来の日でも利用できるようにします。 

### なぜ効果があるのか

 この変換により、j への依存性がプレフィックスに関する 2 つの単調な統計に分離されます。 考えられるすべての初期インデックスは 2 つの線形形式のいずれかに寄与し、プレフィックスの最小値または最大値により、可能な限り最良の j が常に O(1) 時間で表現されることが保証されます。 すべてのペア (i, j) はこれらの要約を通じて暗黙的に考慮されるため、計算された最大値はブルート フォース定義と正確に一致します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, c = map(int, input().split())
    x = list(map(int, input().split()))

    INF = 10**30

    min_left = INF
    max_left = -INF

    res = []

    for i in range(n):
        xi = x[i]

        val1 = xi - c * i
        val2 = xi + c * i

        if i == 0:
            res.append(0)
        else:
            best1 = val1 - min_left
            best2 = max_left - val2
            res.append(max(best1, best2))

        expr1 = xi - c * i
        expr2 = xi + c * i

        if expr1 < min_left:
            min_left = expr1
        if expr2 > max_left:
            max_left = expr2

    print(*res)

if __name__ == "__main__":
    solve()
```この実装では、ウォークスルーで導出された代数形式に直接対応する 2 つの実行値が保持されます。 変数`min_left`はこれまでに確認された xj − c·j の最小値を格納します。`max_left`xj + c・j の最大値を格納します。 各ステップで、両方のサマリーに対する現在のインデックスの寄与を一定時間で計算します。 

よくある間違いは、i の答えを計算する前にプレフィックス値を更新することです。これにより、意図した分離を壊す形で j = i 自体が誤って影響を受けることになります。 正しい順序は、最初に答えを計算し、次に現在のインデックスを実行中の構造に組み込むことです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, c = map(int, input().split())
    x = list(map(int, input().split()))

    INF = 10**30
    min_left = INF
    max_left = -INF
    res = []

    for i in range(n):
        xi = x[i]
        if i == 0:
            res.append(0)
        else:
            best1 = (xi - c * i) - min_left
            best2 = max_left - (xi + c * i)
            res.append(max(best1, best2))

        min_left = min(min_left, xi - c * i)
        max_left = max(max_left, xi + c * i)

    return " ".join(map(str, res))

# provided sample
assert run("5 1\n2 7 1 5 4\n") == "0 4 5 3 1"

# minimum size
assert run("1 10\n5\n") == "0"

# all equal
assert run("4 3\n7 7 7 7\n") == "0 0 0 0"

# increasing values
assert run("5 1\n1 2 3 4 5\n") == "0 0 0 0 0"

# strong jump late
assert run("4 2\n10 1 1 50\n") == "0 7 7 42"

 ## 特殊なケース

 すべての値が同一の場合、変換された量 xj − c·j および xj + c·j は、線形ペナルティ項によってのみ変化します。 アルゴリズムは引き続き正しい最小値と最大値を維持しますが、xi がすべての xj に一致し、ペナルティによって正のゲインが生成されないため、両方の候補式がステップごとにゼロに崩壊します。 これは、ゼロ配列の予想される出力と一致します。 

以前の最良のインデックスが非常に古い場合、プレフィックス統計は、どれだけ遡ったかに関係なく、そのインデックスをすでにエンコードしています。 たとえば、非常に大きな値が早期に出現した場合、線形調整により時間距離が正確に補正されるため、その寄与は max(xj + c·j) に保存されたままとなり、将来のすべてのインデックスに正しく影響を与え続けます。
