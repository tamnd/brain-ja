 ## 解決策
 ## 問題の理解

 各従業員は、1 時間あたりに作成するコードの行数と、1 時間あたりに修正するバグの数という 2 つのスキルによって表されます。 マネージャーは、割り当てられた合計時間が固定予算を超えない限り、プロジェクトの利用可能な時間を従業員間で任意に分割することができます。これには、部分的な割り当ても含まれます。$t$。 生産量は時間とともに直線的に増加するため、従業員をどのように組み合わせても、生産性ベクトルの加重和が生成されます。 

コンサルタントのリクエストでトリプルが得られます$(t, \ell, f)$。 で$t$コンサルタントは何時間も生み出すと主張している$\ell$コード行と修正$f$バグ。 現在の従業員のセットが両方に一致または超える場合、リクエストは拒否されます。$\ell$そして$f$同じ合計時間予算内で同時に。 それ以外の場合は承認されます。 

重要な点は、ワーカーのサブセットを選択しているのではなく、すべてのアクティブなワーカーに連続時間を分配していることです。 これにより、達成可能な成果が、時間でスケールされた従業員の生産性ベクトルの凸状の組み合わせに変わります。 

制約は大きく、最大で$2 \cdot 10^5$従業員と$10^5$イベントや生産性の値は最大$10^8$。 すべてのアクティブな従業員に対する線形スキャンでさえ遅すぎるため、クエリごとにゼロから再計算する可能性は直ちに排除されます。 どのようなソリューションでも、削除と幾何学的クエリの繰り返しの両方を効率的にサポートする必要があります。これは、再計算ではなく動的な幾何学的構造を維持することを示唆しています。 

従業員を 1 人だけ選択できるかのように問題を扱うと、単純な間違いが生じます。 たとえば、ある労働者が$(10, 1)$そしてもう一人は$(1, 10)$、どちらも次のようなリクエストを支配しません$(5, 5)$個別ではありますが、一緒にするとそうなります。 優秀な単一従業員のみをチェックするソリューションは間違っています。 

もう 1 つの微妙な失敗は、端数の時間割り当てを無視したことに起因します。 時間は連続しているため、従業員の混合が重要であり、整数のナップザックの直感は当てはまりません。 

## アプローチ

 ジオメトリを無視すると、直接シミュレーションにより各クエリに対して可能な限り最良の出力が再計算されます。 従業員の固定セットについては、最大でも総重量の非負の配分が存在するかどうかという線形の実現可能性問題を解決する必要があります。$t$少なくとも生産する$(\ell, f)$。 これは小さな線形プログラムですが、クエリごとに解決するには、シンプレックス形式の推論か、すべての従業員を複数回スキャンする必要があり、これでは非常に時間がかかります。 

重要な観察は、1 単位時間内に達成可能な一連の出力が、正確にすべての従業員ベクトルと原点の凸包であるということです。 スケーリング時間の基準$t$この凸状領域を単に拡大縮小するだけです。 したがって、各クエリは、ポイントが次の点にあるかどうかをチェックすることになります。$(\ell / t, f / t)$は、この凸包が支配する領域にあります。 

同様に、凸包内に完全に封じ込める必要はありません。 両方の座標においてクエリを支配するハル内に何らかの点が存在するかどうかを知る必要があるだけです。 これにより、問題は 2 次元の凸多角形の上部境界を超える支配クエリに変換されます。 

ダイナミックな側面は削除によってもたらされます。 従業員が退職するため、凸包は時間の経過とともに変化します。 削除はオフラインで行われ、各従業員は最大 1 回削除されるため、時間をイベントに対するセグメント ツリー構造として扱うことができます。 各ノードは、そのノードによって表される間隔全体でアクティブなポイントの凸包を格納します。 クエリは、からの情報を組み合わせることで回答されます。$O(\log e)$ノード。 

各ノード内では、増加順にソートされた上部の凸包のみが必要です。$x$、私たちは常に最大化することに関心があるので、$f$しきい値の場合$l$。 このチェーンの二分探索により、両方の座標制約を満たす点があるかどうかをテストできます。

 ## アルゴリズムのチュートリアル

 すべてのイベントを処理し、イベント タイムライン上にセグメント ツリーを構築します。 各従業員は、初期状態から退職または終了までの、アクティブな時間間隔に対応します。 

1. イベント インデックスの範囲にわたってセグメント ツリーを構築します。 各従業員は、アクティブな間隔を完全にカバーするすべてのノードに挿入されます。 これにより、各ノードには、そのセグメントで継続的にアクティブな従業員が正確に含まれることが保証されます。 
2. 各セグメント ツリー ノードについて、それに割り当てられているすべての点を収集し、それらの凸包を計算します。 船体上部のみを保持し、増加順に並べ替えます。$x$。 この順序により、次のようになります。$x$増加し、$y$凹状に動作します。 
3. クエリごとに$(t, \ell, f)$、それを正規化された要件に変換します$(\ell / t, f / t)$。 このスケーリングにより、クエリが単位時間の凸包に合わせられます。 
4. クエリ時間をカバーするセグメント ツリー ノードをトラバースします。 各ノードに対して、その凸包に対して二分探索を実行して、次の式で最初の点を見つけます。$x \ge \ell / t$。 そのサフィックスのうち、最大のものをチェックします$y$。 いずれかのノードが降伏した場合$y \ge f / t$、答えは「はい」です。 
5. 条件を満たすノードがない場合は「no」を出力します。 

二分探索が各ハルの内部で機能する重要な理由は、ハルの上部が単調であるためです。$x$、それで一度$x$閾値を超える、可能な限り最高の$y$は境界点の 1 つで発生し、接尾辞の最大値を追跡したり、分割の周囲の候補を直接検査したりできます。 

### なぜ効果があるのか

 実現可能な出力は、時間によってスケールされたアクティブな従業員ベクトルの凸包に等しい凸集合を形成します。 達成可能なペアはすべて、この凸領域内に存在する必要があります。 コンサルタントは、スケールされたベクトルが領域の下または内側にある場合、つまり何らかの凸状の組み合わせがその領域を支配している場合に正確に拒否されます。 優位性のチェックは、クエリがこの凸多角形の上部エンベロープの下にあるかどうかをテストすることに帰着します。 セグメント ツリー分解により、クエリ時にアクティブな凸包が正確に再構築されることが保証され、ハル プロパティにより、境界の外側にある内部点が優位性を向上させることができないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def cross(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])

def build_hull(points):
    points.sort()
    if len(points) <= 1:
        return points

    lower = []
    for p in points:
        while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
            lower.pop()
        lower.append(p)

    upper = []
    for p in reversed(points):
        while len(upper) >= 2 and cross(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)

    upper.reverse()
    return upper

class SegTree:
    def __init__(self, n):
        self.n = n
        self.tree = [[] for _ in range(4 * n)]

    def add(self, idx, l, r, ql, qr, pt):
        if ql <= l and r <= qr:
            self.tree[idx].append(pt)
            return
        mid = (l + r) // 2
        if ql <= mid:
            self.add(idx * 2, l, mid, ql, qr, pt)
        if qr > mid:
            self.add(idx * 2 + 1, mid + 1, r, ql, qr, pt)

    def build(self, idx, l, r):
        if l == r:
            if self.tree[idx]:
                self.tree[idx] = build_hull(self.tree[idx])
            return
        mid = (l + r) // 2
        self.build(idx * 2, l, mid)
        self.build(idx * 2 + 1, mid + 1, r)
        if self.tree[idx]:
            self.tree[idx] = build_hull(self.tree[idx])

    def query(self, idx, l, r, pos, xreq, yreq):
        if r < pos or l > pos:
            return False
        if l <= pos <= r:
            if self.tree[idx]:
                pts = self.tree[idx]
                lo, hi = 0, len(pts) - 1
                while lo <= hi:
                    mid = (lo + hi) // 2
                    if pts[mid][0] < xreq:
                        lo = mid + 1
                    else:
                        hi = mid - 1
                for j in range(lo, len(pts)):
                    if pts[j][1] >= yreq:
                        return True
            if l == r:
                return False
        mid = (l + r) // 2
        return self.query(idx * 2, l, mid, pos, xreq, yreq) or \
               self.query(idx * 2 + 1, mid + 1, r, pos, xreq, yreq)

def solve():
    n = int(input())
    pts = [tuple(map(int, input().split())) for _ in range(n)]

    e = int(input())
    events = []
    alive = [True] * n

    # build active intervals
    start = [1] * n
    end = [e] * n

    for i in range(e):
        parts = input().split()
        if parts[0] == 'q':
            idx = int(parts[1]) - 1
            end[idx] = i + 1
            alive[idx] = False
            events.append(("q", idx))
        else:
            t, l, f = map(int, parts[1:])
            events.append(("c", t, l, f))

    st = SegTree(e)

    for i in range(n):
        if start[i] <= end[i]:
            st.add(1, 1, e, start[i], end[i], pts[i])

    st.build(1, 1, e)

    res = []
    for i, ev in enumerate(events, 1):
        if ev[0] == "c":
            t, l, f = ev[1], ev[2], ev[3]
            xreq = l / t
            yreq = f / t
            ok = st.query(1, 1, e, i, xreq, yreq)
            res.append("no" if ok else "yes")

    print("\n".join(res))

if __name__ == "__main__":
    solve()
```セグメント ツリーは、各クエリ時間にどの従業員がアクティブであるかを特定するために使用されます。 各ノードは割り当てられたポイントの凸包を格納するため、優位性チェックはそのノード内のポイント数で対数になります。 クエリはコンサルタントの要件を正規化された傾斜比較に変換し、船体点がそれを支配できるかどうかをチェックします。 

微妙な実装の詳細は、必要なのは上部ハルだけであり、次のように安全に二分検索を行うことができるということです。$x$、両方の座標における優位性は、次の点が含まれる点を見つけることに帰着するためです。$x$十分な大きさとそれに対応する$y$も十分な大きさです。 

## 実用的な例

 従業員が 2 人の小規模なシステムを考えてみましょう。$(10,1)$そして$(1,10)$、および次のことを求めるクエリ$(5,5)$で$1$時間。 

| ステップ | アクティブポイント | 船体 | チェック |
 | --- | --- | --- | --- |
 | 1 | (10,1)、(1,10) | 両方 | クエリ (5,5) |
 | 2 | x ≥ 5 を評価する | (10,1) | y = 1 |
 | 3 | 残りをチェックする | (1,10) | × 不十分 |

 どちらの点も単独では優勢ではありませんが、凸包の組み合わせによって優勢になるため、凸包推論が必要な理由がわかります。 

ここで、(10,10) のみが存在し、クエリが (5,5) である場合を考えてみましょう。 

| ステップ | アクティブポイント | 船体 | チェック |
 | --- | --- | --- | --- |
 | 1 | (10,10) | シングルポイント | クエリ (5,5) |
 | 2 | x ≥ 5 を満たす | (10,10) | y ≥ 5 true |

 これにより、単一のハル ポイントを介して優勢が正しく検出されたことが確認されます。

 ## 特殊なケース
