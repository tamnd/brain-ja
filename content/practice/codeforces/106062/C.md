 ## 解決策
 ## 問題の理解

 一連のエンティティが与えられ、それぞれがトレーニング プロファイルのパラメータのように動作する 3 つの数値で記述されます。 シーケンスを左から右に処理する場合、各位置$i$正確に 1 つ前の位置を選択する必要があります$j < i$パラメータ間の混合相互作用によって決定されるスコアを取得します。 

具体的には、それぞれの要素が$i$前のすべての要素に対するクエリを提供します。 固定ペアの場合$(i, j)$、スコアは 2 つの部分の合計です。1 つの部分は次の値を乗算します。$j$からの値を持つ$i$、2 番目の部分は別の値を除算します。$j$からの値によって$i$。 タスクは、すべてのポジションについて計算することです$i$、以前に最良のものを選択することで得られる最大スコア$j$、その最大値を小数として出力します。 

出力形式では、各答えを有理数として正確に処理する必要があります。つまり、浮動小数点で演算を近似したり並べ替えたりすることはできません。 各結果は最小項に単純化する必要があります。 

制約は、ソリューションを線形または線形に近い動作に近づけます。$N$、最大で 100 万にもなる可能性があります。 すべてのペアを明示的に比較する二次アプローチ$(i, j)$約必要になる$10^{12}$最悪の場合の評価は、高度に最適化されたコードであっても実行不可能です。 

さらに微妙な問題は、各クエリが変換された係数に依存することです。$a_i \cdot d_i$。 これは、構造がペアごとの相互作用のように見えても、クエリはインデックスごとに継続的に変化するため、単一の順序付けを事前計算したり、単純なプレフィックス最大値を使用したりすることはできないことを意味します。 

誤った貪欲な推論を明らかにするエッジ ケースの 1 つは、以前の 2 つの候補が傾きと切片の動作をトレードオフする場合です。 前の 1 つの要素に大きな$d_j$でも小さい$h_j$、もう1つは小さなものです$d_j$しかし大きい$h_j$。 小さなもののために$a_i d_i$、2番目が優勢です。 大型用$a_i d_i$、最初のものが優勢です。 単一の「以前の最良の要素」のみを追跡する戦略は失敗します。 

2 番目の微妙な失敗ケースは、すべての場合に発生します。$d_j$は同一です。 その後、問題は最大値を選択するという点に集約されます。$h_j$ただし、重複を慎重に処理せずに常にハル構造を維持する単純な実装では、冗長な行が導入され、堅牢に実装されていない場合はクエリが正しく渡されない可能性があります。 

## アプローチ

 直接的な総当たりソリューションはすべてのペアに対して反復されます。$(i, j)$と$j < i$、式を評価し、最大値を追跡します。 これは、すべての候補を明示的にチェックするため正しいですが、そのコストは二次関数です。 と$N = 10^6$、これはおおよそ次のことにつながります$5 \cdot 10^{11}$実行可能な限界をはるかに超えた操作。 

重要な観察は、次の条件に応じて単一の変数に関して式を標準線形形式に書き直すことです。$i$。 ペアの元のスコア$(i, j)$は$$d_j \cdot a_i + \frac{h_j}{d_i}.$$乗算$d_i$(これは正の値であるため、順序が維持されます) は次のとおりです。$$d_i \cdot d_j \cdot a_i + h_j.$$固定の場合$i$、 定義する$C_i = a_i \cdot d_i$。 すると式は次のようになります$$h_j + d_j \cdot C_i.$$これで、前の各インデックスの構造が明確になりました。$j$変数に一次関数を定義します$C$、$$f_j(C) = d_j \cdot C + h_j,$$そしてそれぞれについて$i$で評価される、以前に挿入されたすべての行の最大値が必要です。$C_i$。 

これはまさに、任意の行の挿入順序と任意のクエリ点を使用した動的凸包トリック問題です。 坂道なので$d_j$は単調であることが保証されていないため、標準の deque ベースのハルは適用されません。 この設定の堅牢な構造は、線の挿入と、制限された座標範囲にわたる対数時間での最大値のクエリをサポートする Li Chao ツリーです。 

最大値が見つかったら、それを次の値で割ります。$d_i$gcd を使用して分数を減らします。

 | リーチャオツリー |$O(N \log C)$|$O(N \log C)$| 承認済み |

 ## アルゴリズムのチュートリアル

 前の要素から派生した一次関数の構造を維持しながら、要素を左から右に処理します。 

1. の可能な値の領域に対して Li Chao ツリーを定義します。$C = a_i \cdot d_i$。 このドメインは次のように制限できます。$10^{12}$どちらの要素も最大で$10^6$。 
2. インデックスごとに$i$、計算する$C_i = a_i \cdot d_i$。 この値はクエリの x 座標になります。 
3.加工前$i$、ツリーにはすべてのインデックスに正確に対応する行が含まれています$j < i$、それぞれは次のように表されます$f_j(C) = d_j C + h_j$。 
4. 次の場所で Li Chao ツリーをクエリします。$C_i$最大値を得るために$best_i = \max_j (d_j C_i + h_j)$。 これが機能するのは、ツリーが以前に挿入されたすべての行の上部エンベロープを維持しているためです。 
5. 最終的な答えを分数として計算します。 

分子$= best_i$、

 分母$= d_i$。 
6. gcd で端数を切り捨てて出力します。 

正確さは、インデックスの処理後の不変式に依存します。$i$、構造体はインデックスからのすべての候補行を正確に保存します。$1$に$i$、各クエリはそのセットの真の最大値を返します。 各挿入は削除されない行に対応するため、候補が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("l", "r", "line")
    def __init__(self):
        self.l = -1
        self.r = -1
        self.line = None

def f(line, x):
    a, b = line
    return a * x + b

def insert(node_idx, l, r, line, tree):
    if tree[node_idx].line is None:
        tree[node_idx].line = line
        return

    mid = (l + r) // 2
    cur = tree[node_idx].line

    left_is_better = f(line, l) > f(cur, l)
    mid_is_better = f(line, mid) > f(cur, mid)

    if mid_is_better:
        tree[node_idx].line, line = line, tree[node_idx].line

    if r - l == 0:
        return

    if left_is_better != mid_is_better:
        if tree[node_idx].l == -1:
            tree[node_idx].l = len(tree)
            tree.append(Node())
        insert(tree[node_idx].l, l, mid, line, tree)
    else:
        if tree[node_idx].r == -1:
            tree[node_idx].r = len(tree)
            tree.append(Node())
        insert(tree[node_idx].r, mid + 1, r, line, tree)

def query(node_idx, l, r, x, tree):
    if node_idx == -1:
        return -10**30
    node = tree[node_idx]
    res = f(node.line, x) if node.line else -10**30
    if l == r:
        return res
    mid = (l + r) // 2
    if x <= mid:
        return max(res, query(node.l, l, mid, x, tree))
    else:
        return max(res, query(node.r, mid + 1, r, x, tree))

def gcd(a, b):
    while b:
        a, b = b, a % b
    return a

def main():
    n = int(input())
    data = [tuple(map(int, input().split())) for _ in range(n)]

    tree = [Node()]
    MAXC = 10**12

    out = []

    for i, (d, h, a) in enumerate(data):
        if i == 0:
            best = h
        else:
            C = a * d
            best = query(0, 0, MAXC, C, tree)
        if i > 0:
            C = a * d
            best = query(0, 0, MAXC, C, tree)

        g = gcd(best, d)
        out.append(f"{best // g} {d // g}")

        tree = tree if i == 0 else tree
        if i == 0:
            tree[0].line = (d, h)
        else:
            insert(0, 0, MAXC, (d, h), tree)

    print("\n".join(out))

if __name__ == "__main__":
    main()
```このコードは、挿入された各行が前のインデックスの寄与に対応する Li Chao ツリーを維持します。 各クエリは計算します$C_i$そしてその座標における最大のラインを評価します。 gcd リダクションは、分子の計算直後に適用されます。 

実装の微妙な詳細は、傾きと切片の両方が整数のままである必要があり、慎重に処理すればすべての中間値が 64 ビットの符号付き整数内に収まることです。 ドメインのサイズは固定されており、大きいですが、探索はまばらであるため、動的なノード作成戦略が必要です。

### トレース

 | 私 | C_i = a_i d_i | クエリ結果 | ベストj | 挿入された行 |
 | --- | --- | --- | --- | --- |
 | 1 | - | - | - | 4C+3 |
 | 2 | 1×5 = 5 | 4・5 + 3 = 23 | 1 | 5C+2 |
 | 3 | 3×4 = 12 | 最大(4・12+3, 5・12+2) = 62 | 2 | 4C+1 |

 2 番目のインデックスは、C=5 の最初の行を優先します。 3 番目のインデックスは、傾きが大きいため C=12 で 2 番目のラインに切り替わります。 

これは、前の最良の要素の選択がクエリ座標に応じてどのように変化するかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(N \log C)$| 各挿入とクエリは Li Chao ツリーを 1 回横断します。 
| スペース |$O(N \log C)$| 挿入された各行は、そのパスに沿って新しいノードを作成する可能性があります。

 ## 特殊なケース

 要素が 1 つだけある最小限のケースでは、実装が前の候補の存在を誤って想定しているかどうかがすぐに明らかになります。 正しい出力は、それ自体とペアになった要素が暗黙的に発生しないというだけなので、コードは特殊な場合の初期化を行う必要があります。 

たとえば、傾きが同じ場合$d_j = 5$みんなのために$j$、構造が最も高い切片線のみを適切に保持しているかどうかをテストします。 単純なハルの実装が複数の冗長行を保持している場合でも機能する可能性はありますが、枝刈りロジックが間違っていると非効率になったり、クエリが正しく分岐されたりする危険があります。
