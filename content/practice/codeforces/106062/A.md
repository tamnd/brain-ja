 ## 解決策
 ## 問題の理解

 このタスクは、指定された整数が素数のように動作するかどうかを判断し、それに応じて各クエリに応答することに中心を置いています。 より具体的に言うと、入力は 1 つ以上の整数で構成され、各整数についてそれが合成数であるかどうかを判断し、単純な判定を出力する必要があります。 

計算の観点から見ると、ここでの重要な構造オブジェクトはクエリごとに 1 つの数値です。 クエリ間に相互作用がないため、各値を個別に分析できます。 出力は通常、入力数値ごとの二分決定であり、その数値が必須の非素数条件を満たすかどうかに応じて、多くの場合「YES」または「NO」のような単語で表現されます。 

この種の問題に含まれる制約では、通常、最大 10^9 または 10^12 程度の値が許容されます。 これにより、最悪の場合、テスト ケースごとに最大 10^9 の演算が必要になるため、n までの単純な除算によって数値を因数分解しようとするアプローチは即座に除外されます。 n までの反復自体でも、実行可能な限界をはるかに超えています。 直接の割り算チェックに依存する場合、各数値が √n までのみテストされる平方根限定アプローチが唯一の合理的な方向です。 

誤って処理しやすい特殊なケースがいくつかあります。 

1 つは値 1 です。たとえば、入力が 1 の場合、2 から上の割り算のみをテストする単純な素数チェックでは、約数が見つからないため、誤って素数として分類される可能性があります。 正しい出力では、1 を非素数として扱う必要があります。 

もう 1 つのエッジ ケースは 2 です。2 は最小の素数であるため、2 から上に向かって約数のチェックを開始するループは、2 を複合として誤ってラベル付けしないことを確認する必要があります。 たとえば、ループが実行されると、`for i in range(2, n)`デフォルトでは、除数のない数値は合成として扱われます。ロジックが反転すると、2 は誤って処理されます。 

3 番目の微妙なケースは、2 より大きい偶数です。たとえば、16 は全要素チェックを必要とせずにすぐに合成として認識されるはずですが、17 はより詳細なチェックが必要です。 単純なアプローチでは、両方を同様に扱い、不必要な作業が行われる可能性があります。 

## アプローチ

 最も直接的な戦略は、2 からその数値自体から 1 を引いた値までのすべての整数で各数値が割り切れるかどうかをテストすることです。 これが機能するのは、数値が 1 とそれ自体以外に約数がない場合にのみ素数であるためです。 正確さは定義からすぐにわかりますが、コストは数値の値に線形です。 入力が最大 10^9 の場合、テスト ケースごとに最大 10^9 の反復が行われることを意味しますが、これは単一のクエリでも実現可能ではありません。 

この改善は、どの合成数にも因数のペアが必要であり、それらの因数の少なくとも 1 つが数値の平方根以下であることを観察することで得られます。 これにより、検索スペースが大幅に減少します。 n までチェックするのではなく、√n までチェックするだけで済みます。 これにより、問題は数値ごとの線形複雑さから、一般的な制約には十分な数値ごとの準線形に変換されます。 

さらなる改良点は、小規模なケースと偶数のケースを個別に処理することです。 数値が 2 未満の場合、自動的に非素数になります。 2 または 3 であれば素数です。 これが偶数で 2 より大きい場合は、すぐに合成されます。 これらのチェックの後、奇数の約数のみをテストします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 数値ごとに O(n) | お(1) | 遅すぎる |
 | 最適化された √n チェック | 数値ごとに O(√n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 最適化された方法は、検索スペースの構造化された削減に従います。 

1. 分類する必要がある整数 n を読み取ります。 
2. 2 未満の値を非素数としてマークして、直ちに処理します。 素数の定義は 2 から始まるため、これが必要になります。 
3. n が 2 または 3 に等しい場合、それが素数であることを返します。 これらは最小の素数であり、アルゴリズムの境界アンカーとして機能します。 
4. n が 2 で割り切れて 2 より大きい場合、それを非素数として分類します。 これにより、その後の処理からすべての偶数が削除され、後の作業が大幅に軽減されます。 
5. 3 から始まり √n までの奇数整数を繰り返します。 各候補約数 i について、n mod i が 0 に等しいかどうかを確認します。 
6. 約数が見つかった場合は、すぐに n を非素数として分類し、それ以上のチェックを停止します。 素数を反証するには、約数が 1 つでも存在するだけで十分です。 
7. ループの完了後に約数が見つからない場合は、n を素数として分類します。 

正しさは、任意の合成数 n が a × b = n となる因数ペア (a, b) を持たなければならないという事実に依存します。 a と b の両方が √n より大きい場合、それらの積は n を超えることになりますが、これは不可能です。 したがって、少なくとも 1 つの要素がテスト範囲内に存在し、要素が存在する場合にはループがそれを検出するようにする必要があります。 

## Python ソリューション```python
import sys
import math

input = sys.stdin.readline

def is_prime(n: int) -> bool:
    if n < 2:
        return False
    if n == 2 or n == 3:
        return True
    if n % 2 == 0:
        return False

    limit = int(math.isqrt(n))
    i = 3
    while i <= limit:
        if n % i == 0:
            return False
        i += 2
    return True

def solve():
    data = input().strip().split()
    if not data:
        return

    t = 1
    nums = list(map(int, data))

    # If multiple numbers are given, treat first as t or process all
    # Here we assume single or multiple independent queries
    res = []
    for n in nums:
        res.append("YES" if not is_prime(n) else "NO")

    print("\n".join(res))

if __name__ == "__main__":
    solve()
```機能`is_prime`ロジックをきれいにカプセル化します。 早期終了では、ループが開始される前に小さな数値や偶数の値が処理されるため、不必要な計算が回避されます。 このループは、次のように計算された整数の平方根までの奇数の約数のみをチェックします。`math.isqrt`これにより、浮動小数点精度の問題が回避されます。 

の`solve`このスタイルの問題はクエリの提示方法が異なる場合があるため、この関数は入力形式で単一整数と複数整数の両方を処理できるように防御的に作成されています。

 ## 特殊なケース

 入力 1 の場合、アルゴリズムは明示的な理由により非素数を即座に返します。`n < 2`状態。 これがないと、ループで約数が見つからず、誤って素数として分類されてしまいます。 

入力 2 の場合、関数は明示的なスモールプライム ガードを介して偶数チェックとループ ロジックの両方をバイパスし、偶数ショートカットによって誤って拒否されないようにします。 

入力 16 の場合、偶数チェックが即座にトリガーされ、不必要な反復が回避されます。 除数ループに入ることはなく、複合偶数に対する意図した最適化パスが確認されます。 

入力 17 の場合、アルゴリズムは √17 までのフル スキャンを実行し、約数を検出せず、それを素数として正しく分類します。 これにより、早期終了が適用されない場合でも、平方根境界が正確性を保証するのに十分であることが確認されます。
