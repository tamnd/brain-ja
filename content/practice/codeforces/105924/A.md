 ## 解決策
 ## 問題の理解

 レベル全体のリズムの強さを表す一連の整数が与えられます。 タスクは、このシーケンスの連続するセグメントが「完全に同期」されている個数を数えることです。これは、セグメント内ですべての値の最大公約数がそのセグメントの最小値と正確に等しいことを意味します。 

より具体的には、すべての部分配列について、部分配列内のすべての要素の gcd と、同じ部分配列内の最小の要素という 2 つの量を計算します。 これら 2 つの値が正確に一致する部分配列を数えます。 

入力サイズは最大 10 万要素、各値は 100 万まで大きくなります。 これにより、すべての O(n²) 個の部分配列を明示的に検査するアプローチは即座に除外されます。これは、最悪の場合でも約 10¹⁰ の操作が必要となり、これは一般的な時間制限をはるかに超えるからです。 実行可能なソリューションでは、各位置をほぼ線形時間または対数時間で処理し、最初から再計算するのではなく、隣接するサブ配列間で構造を再利用する必要があります。 

この問題の微妙な問題は、左の固定端点を右に拡張するときに gcd と minimum の両方が単調に動作するのに、有効な部分配列の構造が両方の端点に同時に依存することです。 もう 1 つの注意が必要な点は、同じ gcd 値を共有する部分配列が複雑に重複する可能性があり、最小値にも同じことが当てはまります。 これらのプロパティの 1 つだけを個別に追跡する単純な試みでは、それらがまったく同じセグメント上で等しくなければならないという相互作用条件を見逃してしまいます。 

小さな例で要件を説明します。 配列が`[4, 2, 6]`。 サブアレイ`[2, 6]`gcd が 2、最小値が 2 であるため、有効です。 しかし`[4, 2, 6]`gcd 2 がありますが、最小 2 も有効ですが、`[4, 2]`gcd 2 がありますが、最小値も 2 です。 一方で`[4, 6]`gcd は 2 ですが、最小値は 4 であるため、無効です。 課題は、gcd または min を個別に計算することではなく、それらが一致するセグメントを効率的に位置合わせすることです。 

## アプローチ

 ブルートフォースソリューションでは、すべての部分配列を列挙し、最小値と gcd の両方を最初から計算します。 プレフィックス gcd を事前計算したとしても、minimum は単純な可逆的な方法で結合されないため、追加の前処理が使用されない限り、各クエリには依然として線形時間がかかります。 これにより、約 O(n²) 個のサブ配列が発生し、単純に実行した場合は最悪の場合でも各評価に O(n) のコストがかかり、高度な前処理を使用すると O(log n) のコストがかかりますが、それでも遅すぎます。 

重要な観察は、部分配列の右端点を固定すると、すべての左端点にわたる可能な gcd 値のセットが小さな圧縮された構造を形成するということです。左方向に移動すると、gcd 値は O(log A) 回しか変化しません。これは、gcd が除数によって厳密に減少するためです。 同様の考え方が、単調スタックを使用した最小値にも当てはまります。固定された右端点の場合、そこで終了するすべてのサブ配列の最小値も、左境界の拡張ごとに O(1) 回の償却時間だけを変更し、等しい最小値の連続セグメントを形成します。 

したがって、個々のサブ配列の観点から考える代わりに、各右エンドポイントに対して、左エンドポイント範囲の 2 つのパーティションを維持します。 1 つのパーティションは、r で終わる部分配列に対して同じ gcd を生成するすべての左位置をグループ化し、もう 1 つのパーティションは、同じ最小値を生成するすべての左位置をグループ化します。 次に、問題は、これら 2 つのパーティションを交差させ、両方のパーティションに同じ値が割り当てられているセグメントの長さを合計することに帰着します。 

これにより、グローバルなカウントの問題が、2 つのソートされた間隔分解の位置ごとのマージに変わります。

 ## アルゴリズムのチュートリアル

 各インデックス r について、考えられる左端点にわたって 2 つの進化する構造を維持します。 

最初の構造は、r で終わる部分配列のすべての個別の gcd 値を追跡し、左端点の互いに素な間隔に圧縮します。 各エントリが gcd 値と、r に拡張するときにこの gcd が保持する左境界を格納するリストを維持します。 r−1 から r に拡張する場合、gcd を a[r] で取得することによって以前の各 gcd を更新し、隣接する等しい値をマージし、シングルトン部分配列 [r, r] を新しいエントリとして追加します。 これにより、対応する左側の境界を持つ厳密に減少する gcd 値のシーケンスが生成されます。 

2 番目の構造は、r で終わる部分配列の最小値を追跡します。 これは、左側の境界とペアになった値に対する単調増加スタックを使用して維持されます。 新しい要素が到着すると、それ以上の値を持つ以前のセグメントをすべてポップします。これは、r で終わるサブ配列の最小値にはなり得ないためです。 次に、最後に残った境界から始まる新しいセグメントを追加します。 これにより、最小値が一定となる連続した範囲への左端点の分割が生成されます。 

両方の構造が位置 r に対して構築されると、左端点の同じ間隔に 2 つのパーティションができます。 次に、間隔の境界を越える 2 つのポインター スイープを使用して、それらをマージします。 gcd 間隔と最小間隔の間の各オーバーラップは、固定 gcd と固定最小値の両方を共有する r で終わる部分配列のセットに対応します。 gcd 間隔に関連付けられた値が min 間隔に関連付けられた値と等しい場合は常に、重複の長さを答えに追加します。 

### なぜ効果があるのか

任意の固定右端点 r において、すべての可能な左端点は、正確に 1 つの gcd 間隔と正確に 1 つの分間隔に属します。 これらのパーティションは完全であり、互いに切り離されています。 したがって、すべての部分配列は間隔ラベルのペアによって一意に識別され、その寄与は両方のラベルが同じ値に対応する場合にのみ有効です。 gcd と minimum は両方ともそれぞれの区間内で一定であるため、区間レベルでの等価性のチェックは、すべての部分配列について個別にチェックすることと同じです。 スイープにより、すべての左端点が r ごとに正確に 1 回カウントされるようになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    ans = 0

    # gcd intervals: list of (gcd_value, left_boundary)
    gcd_cur = []

    # min intervals: list of (min_value, left_boundary)
    min_stack = []

    for r in range(n):
        x = a[r]

        # update gcd structure
        new_gcd = []
        new_gcd.append((x, r))

        for g, l in gcd_cur:
            ng = g if x == 0 else __import__("math").gcd(g, x)
            if new_gcd[-1][0] == ng:
                new_gcd[-1] = (ng, l)
            else:
                new_gcd.append((ng, l))

        gcd_cur = new_gcd

        # update min structure (monotonic stack)
        # each element: (value, left_boundary)
        while min_stack and min_stack[-1][0] >= x:
            min_stack.pop()

        if not min_stack:
            min_stack.append((x, 0))
        else:
            min_stack.append((x, min_stack[-1][1] + 1))

        # merge intervals
        i = 0
        j = 0
        prev_g_l = gcd_cur[0][1]
        prev_m_l = min_stack[0][1]

        while i < len(gcd_cur) and j < len(min_stack):
            g_val, g_l = gcd_cur[i]
            m_val, m_l = min_stack[j]

            next_g_l = gcd_cur[i + 1][1] if i + 1 < len(gcd_cur) else 0
            next_m_l = min_stack[j + 1][1] if j + 1 < len(min_stack) else 0

            L = max(g_l, m_l)
            R = min(next_g_l - 1 if i + 1 < len(gcd_cur) else r,
                    next_m_l - 1 if j + 1 < len(min_stack) else r)

            if L <= R and g_val == m_val:
                ans += (R - L + 1)

            if (next_g_l > next_m_l if i + 1 < len(gcd_cur) else False):
                i += 1
            else:
                j += 1

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、右エンドポイントごとに、左エンドポイントのすべての gcd の圧縮表現と、単調スタックを使用したすべての最小値の圧縮表現が保持されます。 マージ ステップは、両方の間隔パーティションをエンドポイントごとに線形時間でウォークスルーします。 

最もデリケートな部分は、間隔の境界が正しいことを確認することです。 各 gcd セグメントには、その gcd が適用される最も古い左側のインデックスが格納され、次のセグメントの境界が前のセグメントのエンドポイントを定義します。 最小スタックの場合、ポップされた各セグメントはその左境界の影響を前方に転送するため、残りのスタックは常にプレフィックスのクリーンなパーティションを形成します。 

最後のスイープは、両方のパーティションの境界を使用して重複範囲を慎重に計算することに依存しており、これにより二重カウントが回避されます。

 ## 特殊なケース

 次のような単一要素配列の場合`[x]`、 gcd と minimum は両方とも自明に等しい`x`したがって、すべての単一の位置が 1 つの有効な部分配列に寄与します。 gcd 構造体と min 構造体の両方がその要素をカバーする単一の間隔を初期化するため、アルゴリズムはこれを処理します。 

次のような定数配列の場合`[2, 2, 2, 2]`、すべての部分配列の gcd は 2 に等しく、最小値は 2 に等しい。間隔構造は、すべての範囲にわたって単一の繰り返し値に折りたたまれ、スイープでは、明示的に列挙することなく、すべての n(n+1)/2 部分配列がカウントされます。 

次のような厳密に増加する配列の場合、`[1, 2, 3, 4]`、最小値は常に左側のエンドポイントですが、gcd はほとんどのセグメントですぐに 1 に低下します。 等しい値の間隔の交差部分はまばらになり、アルゴリズムはシングルトンと時折のプレフィックス一致を除くほとんどすべてのサブ配列を自然にフィルターします。 

次のような交互の値の場合`[2, 1, 2, 1]`、gcd と最小構造の両方が頻繁に変化し、多くの短い間隔が生成されます。 正確さは、間隔の境界がステップごとに再計算され、パターンが急速に変動する場合でも重複するセグメントが二重にカウントされないことを保証するという事実に依存します。
