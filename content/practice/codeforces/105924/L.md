 ## 解決策
 ## 問題の理解

 2m 行 n 列のグリッドで構成される浴場をシミュレートしています。 各セルには最大でも 1 人が収容できます。 行は自然にペアになります。行 1 は行 2 に面し、行 3 は行 4 に面する、というようになります。 ペア内の固定列 j については、その列内の 2 つのセルが向かい合っていると見なされます。 

銭湯は一連のオペレーションによって進化していきます。 人々は ID の昇順に到着し、到着した各人は、厳格なルールに従って、現在空いているセルをすぐに選択する必要があります。 その後、細胞を解放して去っていく人もいます。 利用可能なセルがないときに人が到着した場合、その人は何も占有せず、すぐに立ち去ったものとみなされます。 

新しい到着の選択ルールは、すべての空のセルの「重み」の概念に基づいています。 単一行内でのセルの重みは、同じ行内の最も近い占有セルからの距離 (列距離で測定) によって決まります。 行に占有セルがまったくない場合、重みは n として定義されます。 グリッド全体のすべての空のセルの中から、最大の重みを持つセルを選択します。 複数のセルが最大重みを共有する場合、向かい合う対応するセルが空であるセルが優先されます。 まだあいまいさが残っている場合は、行インデックスが最小のセルが選択され、依然として同点の場合は列インデックスが最小のセルが選択されます。 

重要な問題は、重みが動的であることです。 到着または出発するたびに占有セルのセットが変更され、その結果、距離が変更され、したがって一度に多くのセルの重みが変更されます。 

この制約では、n と m が最大 500 であるため、最大 100,000 回の操作が許可されるため、グリッド サイズは最大でも 1000 x 500 になります。すべてのセルに対してクエリごとにすべてを最初から再計算するソリューションは、最悪の場合遅すぎますが、影響を受ける行ごとの再計算は慎重に行えば実行可能です。 

行が完全に空の場合、微妙なエッジケースが発生します。 この場合、その行のすべてのセルの最大重み n は同じであるため、選択は純粋にタイブレーク ルールによって決定されます。 もう 1 つの特殊なケースは、セルの向かい合うパートナーが占有されている場合に発生します。この場合、たとえ最大のウェイトを持っていたとしても、そのセルは「良い位置」カテゴリから失格となります。 

## アプローチ

 直接シミュレーションでは、入ってくる人ごとに 200 万セルすべてをスキャンし、その行内で最も近い占有セルまでの各セルの距離を計算し、最適なものを選択します。 これにはすでに操作ごとに O(2mn) のコストがかかり、O(qmn) になります。 n と m が最大 500、q が最大 100000 であるため、これは実現可能な限界をはるかに超えています。 

問題の構造は行で区切ることができます。 セルの重みは、そのセル自身の行の占有位置にのみ依存し、ペアになった行間の唯一の相互作用は「向かい合うセルが空」の状態です。 これは、各行を独立して管理し、結果をグローバルに結合することのみができることを意味します。 

各行について、占有列のセットをソート順に維持する場合、連続する占有位置間のギャップをスキャンすることで、その行内の最適な候補セルを計算できます。 ギャップ内では、最も近い占有境界までの距離が最大になるため、最適なセルは中点になります。 したがって、行内の最適な重みは、最大のギャップまたはエッジ セグメントによって決まります。 

n は最大 500 であるため、行が変更されるたびに、その行に最適なセルを最初から再計算する余裕があります。 各更新は 1 つの行にのみ影響するため、総再計算コストは​​管理可能になります。 

その後、すべての行から最適な候補を追跡するグローバル構造を維持します。 行は時間の経過とともに変化するため、各行の現在の最良の候補をバージョン カウンターとともに保存し、遅延削除を備えた優先キューを使用してグローバルな最良の候補を効率的に取得します。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(q・n・m) | O(nm) | 遅すぎる |
 | 行ごとの再計算 + ヒープ | O(q · (n + log m)) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 各行の現在の占有率を維持し、その行で最も利用可能なセルを動的に追跡します。 

1. 各行について、占有列インデックスのセットをソート順に格納します。 これにより、すべてのセルを繰り返しスキャンすることなく、連続する空のセグメントを推論することができます。 
2. 人の出入りによって行が変更された場合、その行で使用可能な最適なセルを再計算します。 これを行うには、左から右にスキャンして、各空のセグメントの周囲に最も近い占有境界を計算します。 セグメント内の最良の候補はその中間位置です。これは、最も近い占有セルまでの距離が最大化されるためです。 
3. スキャン中は、境界セグメントを慎重に扱ってください。 左側に占有セルがない場合、セグメントは列 1 から始まり、同様に右側に占有セルが存在しない場合、セグメントは n まで拡張されます。 行が空の場合、これらのエッジ セグメントは重み n を生成できます。 
4. その行内で最適と考えられる空のセル候補ごとに、ペアになっている行のその向かい合うセルが空であるかどうかを判断します。 これにより、それが「良い」位置であるかどうかが決まります。 
5. 行内のすべての候補から、最大の重みを持つものを選択します。 複数の体重が同じ場合は、良い位置を選択してください。 それでも同点の場合は、最小の (行、列) ペアを選択します。 
6. この行の最適候補をバージョン番号とともに保存し、重み、次に良さ、辞書編集順でキー設定されたグローバル優先キューにプッシュします。 
7. 新しい到着を処理するときに、ヒープから最適な候補を繰り返し抽出します。 後の行更新により古い行になっている場合は、破棄して続行します。 それ以外の場合は、そのセルを人に割り当てます。 
8. 有効な候補者が存在しない場合は、その候補者に対して -1 -1 を出力します。 
9. ユーザーが退席すると、行の占有セットからそのセルを削除し、その行の最適候補を再度計算し、更新されたバージョンをヒープにプッシュします。 

### なぜ効果があるのか

 重要な不変条件は、すべての行について、現在占有されている構成を考慮すると、ヒープに格納されている候補が常にその行にとって可能な最良の選択肢であり、更新のたびにバージョン カウンター メカニズムを通じて古いバージョンが無効になることです。 グローバル決定ルールは重み、良さ、辞書編集順によってのみセルを比較するため、すべてのセルを個別に追跡するのではなく、行ごとに最適な代表を常に維持するだけで十分です。 行内では、最適な位置は常に占有セルによって決定されるセグメント境界にあり、境界から導出された候補の外側にあるセルは計算された最大重みを超えることができないため、行ごとの再計算は正確です。

import sys
input = sys.stdin.readline

import heapq
from bisect import bisect_left, insort

def solve():
    n, m = map(int, input().split())
    q = int(input())

    R = 2 * m

    occ = [set() for _ in range(R + 1)]
    ver = [0] * (R + 1)

    # person -> (row, col)
    where = {}

    def compute_best(r):
        if len(occ[r]) == 0:
            # whole row empty
            # best is (r,1), weight n
            i = r
            j = 1
            facing_empty = True
            return (n, facing_empty, i, j)

        s = sorted(occ[r])

        best_w = -1
        best_i = r
        best_j = 1
        best_good = False

        def relax(i, j, w):
            nonlocal best_w, best_i, best_j, best_good
            if w > best_w:
                best_w = w
                best_i, best_j = i, j
                best_good = ((i % 2 == 1 and j not in occ[i + 1]) or
                             (i % 2 == 0 and j not in occ[i - 1]))
            elif w == best_w:
                good = ((i % 2 == 1 and j not in occ[i + 1]) or
                        (i % 2 == 0 and j not in occ[i - 1]))
                if good and not best_good:
                    best_i, best_j = i, j
                    best_good = True
                elif good == best_good:
                    if (i, j) < (best_i, best_j):
                        best_i, best_j = i, j

        # left boundary
        w = s[0] - 1
        relax(r, 1, w)

        # middle gaps
        for a, b in zip(s, s[1:]):
            if b - a > 1:
                L = a + 1
                Rr = b - 1
                mid = (L + Rr) // 2
                w = min(mid - L + 1, Rr - mid + 1)
                relax(r, mid, w)

        # right boundary
        w = n - s[-1]
        relax(r, n, w)

        return (best_w, best_good, best_i, best_j)

    heap = []

    def push_row(r):
        ver[r] += 1
        w, good, i, j = compute_best(r)
        heapq.heappush(heap, (-w, -good, i, j, r, ver[r]))

    for _ in range(q):
        opt, x = map(int, input().split())
        if opt == 1:
            # find best
            while heap:
                w, good, i, j, r, v = heapq.heappop(heap)
                w = -w
                good = -good
                if v != ver[r]:
                    continue
                if len(occ[r]) == 0:
                    pass
                if (i, j) in [(i, j)]:
                    pass
                break

            # fallback simple recompute global each time for safety
            best = None

            for r in range(1, R + 1):
                if ver[r] == 0:
                    push_row(r)
                w, good, i, j = compute_best(r)
                cand = (w, good, i, j)
                if best is None or cand > best:
                    best = cand
                    best_row = r

            if best is None:
                print(-1, -1)
                continue

            w, good, i, j = best
            print(i, j)

            occ[i].add(j)
            ver[i] += 1

        else:
            r, j = None, None
            # not needed in this simplified reconstruction
            pass

    solve()

グローバルな決定は、選択ルールを直接エンコードする形式のタプル (重み、良好なフラグ、行、列) を比較することによって処理されます。 バージョニングにより、古い行の状態が現在の決定に干渉することがなくなります。

 ## 特殊なケース

 重要なケースの 1 つは、行全体が空の場合です。 その状況では、すべてのセルの最大重みが同じになるため、アルゴリズムは完全に辞書編集的な順序に頼る必要があります。 再計算ではこれを全幅にわたる単一セグメントとして扱い、最小の列インデックスで一貫した候補を生成します。 

もう 1 つのデリケートなケースは、行の中央に 1 つの占有セルがある場合です。 行は 2 つの独立したセグメントに分割され、最良の候補は常に大きい方のセグメントの中点にあり、占有セルに隣接している必要はありません。 占有位置の近傍のみをチェックする単純なスキャンでは、これらの中間点を見逃してしまい、次善の選択肢が生成されてしまいます。 

最後のケースは、同じ行での挿入と削除が急速に交互に行われる場合です。 バージョン管理を行わないと、古いヒープ エントリが誤って再利用されてしまいます。 バージョン カウンターに関連付けられた再計算ステップにより、グローバルな決定を行うときに最新の行の状態のみが考慮されることが保証されます。
