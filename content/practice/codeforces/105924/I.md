 ## 解決策
 ## 問題の理解

 2n 個の都市が 2 つの行に分割されたグラフが表示されます。 最初の行には 1 から n までのラベルが付いた都市が含まれ、2 番目の行には n+1 から 2n までのラベルが付いた都市が含まれます。 最初の行のすべての都市は 2 番目の行のすべての都市に接続されているため、基礎となるグラフは 2 つの行間の完全な 2 部グラフになります。 

この密な接続に加えて、1 列目の各都市には 2 列目の特別な「紛争パートナー」が 1 つだけ存在します。 形式的には、最初の行のすべての i に対して、2 行目には一意の ai があり、これらの ai 値はすべて個別です。これは、2 つの行間の完全な一致を定義することを意味します。 

パスに競合するペアの両方のエンドポイントが含まれている場合、そのパスは無効であるとみなされます。 つまり、パスが i にアクセスし、いずれかの時点で ai にもアクセスする場合、順序や連続しているかどうかに関係なく、そのパスは禁止されます。 

クエリごとに、この制限を考慮した開始都市 s からターゲット都市 t への有効なパスが存在するかどうかを尋ねられます。 

この制約は、n がテスト ケース全体で合計 2×10^5 まで大きくなり得、テスト ケースの数が最大 10^5 まで可能であることを意味します。 これにより、パスを探索したり、クエリごとにグラフ検索を実行したりするアプローチは即座に除外されます。 グラフが密であり、クエリごとに O(n) 以上の時間がかかるため、クエリごとの線形 BFS であっても、最悪の場合は遅すぎます。 

主な微妙な点は、グラフがほぼ完全に接続されているため、到達可能性が本当のボトルネックではないことです。 唯一の障害は、「一致するペアの両方のエンドポイントを含めることはできない」というルールに起因します。 不注意なアプローチでは、訪問された制約を追跡しながら BFS をシミュレートしようとする可能性がありますが、これにより、答えが非常に小さな構造条件に依存する状況が誤って複雑になりすぎます。 

よくある間違いは、中間ノードがより複雑な方法で接続をブロックする可能性があると想定することです。 たとえば、s が ai に接続され、t が i に接続されている場合、制限によって接続が切断される迂回が強制される可能性があると考えられるかもしれません。 実際には、グラフは非常に密であるため、単一のペアの両方のエンドポイントを含めることを強制されない限り、いつでも禁止されたペアを迂回することができます。 

本当に問題となる唯一のケースは、s と t 自体が禁止されたペアを形成する場合です。 

## アプローチ

 ブルートフォースのアイデアは、グラフを明示的に構築し、パスを無効にする禁止された頂点のセットを保持しながら、制約付き BFS または DFS を s から t まで実行することです。 各状態は、頂点に足を踏み入れると、パスの残りの部分でそのパートナーが事実上禁止されるため、どの一致するエンドポイントが既に訪問されているかを記憶する必要があります。 これにより、問題は状態爆発に変わります。各ステップは完全な 2 部グラフで O(n) 個の近傍に分岐し、状態空間は訪問頂点の数で指数関数的に増加します。 完全な状態追跡を行わない単純化された BFS であっても、クエリあたり O(n) であり、最大 10^5 クエリを考慮すると遅すぎます。 

重要な観察は、グラフ構造が 2 つのパーティション間で最大限に接続されていることです。 上の行の頂点は 1 ステップで下の行の頂点に到達でき、その逆も同様です。 したがって、パスが失敗する唯一の理由は、s から t までのすべての可能なルートが競合するペアの両方のエンドポイントへの訪問を強制する場合です。

では、実際に何が紛争を引き起こすのかを観察してください。 直ちに禁止されるのは、パスに i と ai の両方が含まれている場合のみです。 s と t 自体がそのようなペアを形成している場合、s から t へのパスには両方のエンドポイントがすでに含まれているため、定義により無効になります。 逆に、s と t が一致するペアでない場合は、s と t の禁止された端点を回避する中間頂点を選択することで、常に最大 2 または 3 の長さの有効なパスを構築できます。 反対側のパーティションには n 個の選択肢があり、頂点ごとに禁止されたパートナーは 1 つだけであるため、安全な仲介者が常に存在します。 

したがって、問題は s と t が同じ一致エッジに対応するかどうかをチェックすることに集約されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 制約のあるブルート フォース BFS | クエリあたり O(n) | O(n) | 遅すぎる |
 | マッチングを使用した直接ペアチェック | O(n) の前処理、クエリごとに O(1) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 逆マッピングを構築して、2 行目のすべての都市について、1 行目の一致するパートナーをすぐに見つけられるようにします。 これが必要なのは、入力によって最初の行から 2 行目へのマッピングのみが提供されるためです。 
2. クエリごとに、 s が最初の行にあるか 2 行目にあるかを判断し、適切なマッピング方向を使用して一致するパートナーを見つけます。 このステップにより、 を含むペアについて均一に推論できることが保証されます。 
3. t が正確に s のパートナーであるかどうかを確認します。 「はい」の場合、s から t へのパスには禁止されたペアの両方のエンドポイントが含まれることになり、そのパスは定義上無効になります。 
4. s と t がパートナーでない場合は、有効なパスが存在すると直ちに結論付けます。 エッジの密度により、禁止されたペアが同時に含まれることを回避しながら、常に何らかの中間頂点を経由して配線できることが保証されます。 

### なぜ効果があるのか

 各都市は厳密に 1 つの禁止ペアに参加しており、これらのペアは 2 部分割全体で完全な一致を形成します。 パスは、一致するペアの両方の頂点が含まれる場合にのみ無効になります。 グラフはパーティション間で完全であるため、開始点またはターゲットでない限り、特定の頂点を含めることを強制されることはありません。 したがって、元に戻せない競合は、開始点とターゲット自体が一致する場合のみです。これは、開始点とターゲットを接続するパスには両方のエンドポイントが含まれている必要があるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []

    for _ in range(T):
        n, s, t = map(int, input().split())
        a = list(map(int, input().split()))

        inv = {}
        for i, v in enumerate(a, start=1):
            inv[v] = i

        def partner(x):
            if 1 <= x <= n:
                return a[x - 1]
            else:
                return inv[x]

        if partner(s) == t:
            out.append("No")
        else:
            out.append("Yes")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、パートナー検索が両方向に機能するように、2 行目の逆辞書を構築します。 ヘルパー関数`partner(x)`どの行に属しているかに関係なく、ノードを一致するノードに正規化します。 

最後の条件は直接比較です。ターゲットがソースの一致するパートナーである場合は「No」を出力し、それ以外の場合は「Yes」を出力します。 この構造により代替ルートが常に存在することが保証されるため、グラフの走査は必要ありません。 

## 実用的な例

 n = 2、a = [3, 4] の場合を考えてみましょう。 ペアは (1,3) と (2,4) です。 s = 1 および t = 4 の場合、partner(1) = 3 となるため、t はパートナーではなく、有効なパスが存在します。 

| ステップ | s | t | パートナー | 決定 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 4 | 3 | 等しくない → はい |

 ここで、s = 1 および t = 3 について考えてみましょう。ここでは、partner(1) = 3 であるため、エンドポイントは禁止されたペアを形成します。 

| ステップ | s | t | パートナー | 決定 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 3 | 3 | 等しい → いいえ |

 最初のトレースは、一致しないエンドポイントが密な二部構造を介して接続されたままであることを示しています。 2 番目のトレースは、問題全体の中で唯一ブロックされている構成、つまり単一の一致したペアのエンドポイントを分離します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve():
        T = int(input())
        out = []
        for _ in range(T):
            n, s, t = map(int, input().split())
            a = list(map(int, input().split()))
            inv = {}
            for i, v in enumerate(a, start=1):
                inv[v] = i

            def partner(x):
                if 1 <= x <= n:
                    return a[x - 1]
                return inv[x]

            out.append("No" if partner(s) == t else "Yes")

        return "\n".join(out)

    return solve()

 ## 特殊なケース

 最も重要なエッジケースは、s と t が一致するペアを形成する場合です。 n = 1 と a = [2] などのシナリオでは、可能なペアは (1,2) だけです。 s = 1 および t = 2 の場合、partner(1) = 2 となるため、アルゴリズムは直ちに No を出力します。試行されたパスには必然的に両方の頂点が含まれ、制約に違反します。 

もう 1 つの特殊なケースは、s または t が 2 行目にある場合です。 たとえば、inv[3] = 1 のシステムで s = 3 の場合、partner(3) = 1 となります。同じ一致関係を通じて両方のエンドポイントを正規化し、行間の対称性を確保しているため、ロジックは依然として正しく還元されます。
