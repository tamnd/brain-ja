 ## 問題の理解

 私たちには、都市と人々のグループという相互作用する 2 つの側面を持つシステムが与えられています。 がある$n$それぞれの都市にコストパラメータが設定されている$c_i$、 そして$n$住民のグループ。$i$含まれています$b_i$人々。 各グループは 1 つの都市に居住することを禁止されており、禁止都市のマッピングは順列を形成します。つまり、すべての都市が 1 つのグループに対して禁止され、すべてのグループが 1 つの都市にのみ居住を禁止します。 

各グループは、そのグループの紫禁城に割り当てられている人がいない限り、その人々を複数の都市に分散させることができます。 すべての人を割り当てた後、各都市$i$最終的には総人口がある程度になる$d_i$。 都会の居心地の悪さ$i$は次のように定義されます$c_i \cdot d_i$、そして目的は、すべての都市における最大の不快感を最小限に抑えることです。 

主な問題点は、人々は分割可能であり、許可された都市に任意に配置できるが、すべてのユニットを割り当てる必要があり、禁止されたペアごとに都市ごとに 1 つの潜在的な供給源が削除されることです。 

制約は大きく、合計すると$n$テストケース全体で最大$2 \cdot 10^5$したがって、すべての解はテスト ケースごとに線形または対数線形に近い必要があります。 テストごとのフローや都市とグループのすべてのペア間の二次相互作用が関係するものは遅すぎます。 テスト ケースごとに単一の最大流量さえ実現不可能です。 

微妙な点は、禁止構造が非常に規則的であることです。 各行 (グループ) には禁止された列 (都市) が 1 つだけあり、各列には禁止された行が 1 つだけあります。 この対称性は、一般的な二部流れの複雑さを回避する主要な構造ハンドルです。 

よくある落とし穴は、各都市の最終人口が「1 つのグループを除くすべての人々」として固定されていると想定することですが、各グループはその人口を許可されているすべての都市に任意に分割できるため、これは誤りです。 もう 1 つの間違いは、問題は都市ごとに独立して分解されるが、共有の供給制約によりすべての都市が結合されると想定することです。 

## アプローチ

 直接解釈すると、流れの問題です。各グループは供給源です。$b_i$、各都市は無制限の需要を持つシンクですが、目的の境界によって暗示される容量を尊重する必要があり、グループごとに 1 つの禁止されたペアを除いてエッジが存在します。 回答候補をテストするには$X$、私たちは必要とします$c_i d_i \le X$、 それで$d_i \le \left\lfloor X / c_i \right\rfloor$。 問題は、禁止されたエッジを尊重しながら、これらの容量を超えずにすべての物資を都市に配送できるかどうかです。 

ブルートフォース ソリューションでは、貪欲に人を割り当てたり、完全なフロー ネットワークを構築したりしようとします。 それはすぐに二部構成の流れにつながります。$O(n^2)$エッジと潜在的に$O(n^3)$または、テストごとの動作が悪化して、遅すぎます。 

重要な観察は、グラフ内の唯一の不規則性は、行ごとおよび列ごとに 1 つの禁止エッジであるということです。 これにより、構造がほぼ完全な 2 部構成になり、容量の厳しさを考慮した順序でノードが処理される場合、そのような「ほぼ完全な」制約により、貪欲なソリューションが可能になることがよくあります。 

フローを直接解決するのではなく、視点を逆転させます。各都市の「能力予算」には限りがあると考えます。$cap_i = \lfloor X / c_i \rfloor$。 全部配布しなければならない$b_i$各都市の総摂取量がその収容能力を超えないように、都市全体で、そしてグループごとに$i$市に貢献できない$a_i$。 

次に、最小の処理能力から最大の処理能力までの都市を想像してください。 収容力の小さい都市は満たすことが最も難しいため、最も柔軟な供給を使用してまず満たす必要があります。 都市を処理するたびに、禁止されているグループを除くすべてのグループから可能な限り多くの残りの人口をその都市に割り当てます。常に最大の残りの供給から最初に取得します。 順列制約により、必要な一時的な除外は都市ごとに 1 つのグループだけになり、割り当て中にローカルで処理できるようになります。 

実現可能性チェックは、除外の下で貪欲な再配布となり、二分探索が行われます。$X$最終的な答えが得られます。

 ## アルゴリズムのチュートリアル

 答えを扱います$X$検証できる値として。 固定の場合$X$、各都市$i$せいぜい受け入れられる$cap_i = \lfloor X / c_i \rfloor$人々。 すべてかどうかを確認します$b_i$容量と禁止されたペアを考慮して都市に配置できます。 

1. 都市を昇順に並べ替えます$cap_i$。 このようにするのは、供給能力が小さい都市は最も制限が厳しく、柔軟な供給が枯渇する前に早期に満たす必要があるためです。 
2. 各グループの残りの供給を、次のキーを持つマルチセットとして維持します。$b_i$。 これは、各グループにまだ配布する必要がある人数を表します。 
3. 並べ替えられた順序で都市ごとに、その禁止グループを一時的にマークします。$p(i)$この都市の任務には利用できないため。 これにより、グループの制約に違反することがなくなります。$p(i)$都会に行けない$i$。 
4. 現在の都市の容量がいっぱいになるか、有効な供給がなくなるまで、繰り返し人々を現在の都市に割り当てます。 各ステップで、残っている最大のグループを選択します。$b_j$それはこの街では禁止されていない。 

直感的には、より大きな残りのグループから採用することで、将来の制約のある都市に対する柔軟性が保たれるということです。 小規模な都市が最初に満たされるため、大規模な厳格なグループだけが残り、容量の小さい都市はまだ満たす必要があるという状況を回避します。 

1. 選択したグループの残りを減らす$b_j$割り当てられた金額によって。 使い果たされていない場合は、後の都市までプールに残ります。 
2.都市を終了したら禁止グループを復元し、次の都市に進みます。 

有効なグループをすべて使い果たした後でも、いずれかの時点で都市をその容量まで満たすことができない場合、$X$不可能です。 

1. 最小の二分探索$X$実現可能性チェックが成功した場合。 

### なぜ効果があるのか

 正確さは単調パッキング特性に基づいています。 都市はキャパシティが最も厳しいものから最も緩いものへと処理されます。そのため、後の都市のキャパシティは厳密に大きいか等しいため、新しいボトルネックが発生することはないため、前の都市を満足させる割り当ては、その満足を遅らせることによって改善することはできません。 禁止された制約では列ごとに 1 行のみが削除されるため、いつでも利用可能な供給は十分に柔軟であり、残りの都市間で再配置できます。 残りの最大のグループを貪欲に消費すると、供給の断片化が最小限に抑えられるため、将来の制約のあるステップの実行可能性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(n, a, b, c, X):
    cap = [X // c[i] for i in range(n)]
    rem = b[:]
    # p[i] = index of group forbidden from city i
    p = [0] * n
    for i in range(n):
        p[a[i]] = i

    import heapq
    heap = []
    for i in range(n):
        if rem[i] > 0:
            heapq.heappush(heap, (-rem[i], i))

    # process cities by increasing capacity
    order = sorted(range(n), key=lambda i: cap[i])

    for i in order:
        need = cap[i]
        forbidden = p[i]

        temp = []
        while need > 0 and heap:
            val, idx = heapq.heappop(heap)
            val = -val
            if idx == forbidden or val == 0:
                temp.append((val, idx))
                continue

            take = min(need, val)
            need -= take
            val -= take

            if val > 0:
                temp.append((val, idx))

        for v, idx in temp:
            heapq.heappush(heap, (-v, idx))

        if need > 0:
            return False

    return True

def solve():
    T = int(input())
    for _ in range(T):
        n = int(input())
        a = list(map(lambda x: int(x) - 1, input().split()))
        b = list(map(int, input().split()))
        c = list(map(int, input().split()))

        lo, hi = 0, sum(b) * max(c)
        ans = hi

        while lo <= hi:
            mid = (lo + hi) // 2
            if check(n, a, b, c, mid):
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、実現可能性のチェックと、答えに対する二分探索が分離されています。 チェック機能は、以下から容量制限を構築します。$X$、順列から禁止されたマッピングを再構築し、貪欲な割り当てをシミュレートします。 

重要な一般的な実装の詳細は、割り当てループ内の都市ごとの禁止グループの処理です。 そのグループは一時的であっても現在の都市に貢献してはいけないため、ポップ中にスキップされますが、後で使用できるようにヒープに保存されます。 もう 1 つの微妙な点は、各都市の処理後に一時的に削除されたヒープ エントリを再挿入していることです。 そうしないと、供給状態が誤って永久に失われることになります。 

二分探索の上限では、総人口と最大コストの積を使用します。これは、すべてを最大コストの都市に割り当てることが常に目的の上限であるため、安全です。

 ## 特殊なケース

 重大なエッジケースは、大規模な都市のせいで 1 つの都市の収容力が極端に小さい場合に発生します。$c_i$、その禁止されたグループも最大の貢献者の 1 つです。 その状況で、他のグループが完全に補うことができない場合、貪欲なプロセスはまさにその都市で失敗します。 処理中に、都市の容量がいっぱいになる前に互換性のあるすべてのグループが使い果たされ、即時拒否が引き起こされるため、アルゴリズムはこれを検出します。
