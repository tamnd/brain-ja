 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、$n \times m$各列に色付きブロックの垂直スタックが含まれるグリッド。 追加の「フローティング」ブロックもあります$d$、最初は無色です。 

1 つの操作で列を選択し、循環プッシュを実行します。その列の一番下のブロックが削除されて新しいフローティング ブロックになり、その列内の他のブロックが 1 つずつ下にシフトされ、前のフローティング ブロックが先頭に挿入されます。 したがって、各操作は、その底部を外部ブロックと交換しながら、1 つの列を下に 1 位置ずつ回転させます。 

さらに、外部ブロックを列に配置する前に、空ではない色に無料で色を変更することができます。 コストは列操作の数のみです。 

目標は、すべての列が単色になり、すべての列が個別の色を持つ状態に達することです。 

主な問題点は、操作が列内のマルチセットの数を直接変更するのではなく、位置を循環的に並べ替え、共有外部ブロックを介して要素を交換するだけであることです。 これにより、単一のキャリー値を介してすべての列間にグローバルな結合が作成されます。 

制約$n, m \le 2000$までを暗示$4 \cdot 10^6$細胞、だから何でも$O(nm)$前処理は許容されますが、時間の経過とともに操作をシミュレートしようとするものは不可能です。単一の列操作が多数の列にわたって繰り返されると爆発的に増加するためです。$O(nm^2)$あるいはさらに悪いことに。 

単純な間違いは、ターゲットの色を選択し、不一致を数えることによって各列を独立して解決できると考えることです。 これは失敗します。操作が共有外部ブロックを介して列を結合するため、ある列から「収集」された色は別の列で再利用でき、操作の順序が重要になります。 

さらに微妙な誤った仮定は、各列に最も頻繁に使用される色を個別に貪欲に割り当てることができるということです。 この問題は、グローバル制約によりすべての最終色が異なる必要があるのに、2 つの列が同じ最適な色に依存している場合に問題が発生します。 

## アプローチ

 直接のブルート フォース ビューでは、プロセスをシミュレートします。一連の列操作を選択し、最終色の可能な割り当てをすべて試します。 各構成について、外部ブロックの循環シフトと転送の下で各列を単一の色に変換できるかどうかを確認します。 ターゲットの色を固定したとしても、変換をシミュレートするには、各列を何回操作する必要があるか、および外部ブロックが列間でどのように伝播するかを追跡する必要があります。 各ステップで次のいずれかを選択するため、これはすぐに指数関数的になります。$m$列と、場合によっては外部ブロックの色。 

重要な点は、列の内部で重要なのは、選択したターゲット カラーにすでに一致するブロックの数だけであるということです。これは、各操作で 1 つの要素が外側と交換されながら効果的に列が回転するためです。 これにより、各列が循環構造に変わります。ターゲットの色を固定した場合、コストは、ある回転ですでに正しい位置がいくつあるかによって決まります。 

固定列と固定ターゲット カラーの場合は、逆に考えることができます。すべての位置がターゲット カラーと等しくなる回転が必要です。 つまり、列の循環シフトでは、一致しない色はすべて演算によって押し出される必要があります。 列に必要な演算の最小数は、選択した色と等しくない要素の数と、それらの要素が位置を法としてどのように分散されるかによってのみ決まります。$n$。 すべての操作は 1 つずつシフトするため、列を整列させることは、そのサイクルの開始点を選択し、最後から不一致を 1 つずつ「抽出」することと同じです。 

したがって、各列は可能な色ごとにコストに寄与するため、列ごとに異なる色を 1 つだけ選択して、総コストを最小限に抑える必要があります。 これは、2 部構成に関する割り当ての問題になります。一方の側に列、もう一方の側に色があり、その列を強制的にその色にすると、コストは必要な操作に等しくなります。 

以来$m \le 2000$ですべてのコストを計算できます。$O(nm)$、次に最小コストのマッチングを解決します。 ただし、構造はさらに単純です。不一致を最小限に抑えると、外部ブロックを介して必要な排出が最小限に抑えられるため、各列の達成可能な最高のコストは、その列で最も頻繁に表示される色を選択することによって達成されます。 問題は選択に帰着します$m$列ごとに 1 つの異なる色を使用し、「保持された」一致の合計を最大化します。 

同様に、各列について各色の頻度を計算し、選択した頻度の合計が最大になる個別の色を割り当てます。 これは、両側がサイズである古典的な最大重みの 2 部マッチングです。$m$ただし、重み行列はスパースであり、カウントから導出されます。 

ビューを反転します。操作を最小限に抑える代わりに、保存されたブロックを最大化します。 総ブロック数は固定です$n \cdot m$。 保持される各ブロックは、操作の削減に貢献します。 そこで最大化します$\sum_{columns} \max_{distinct color assignment} frequency[column][color]$。 

これを解決するには、すべてのトリプル (列、色、頻度) のリストを作成し、色ごとに最適なものを貪欲に選択し、競合しない最適な割り当てを取得することで競合を解決します。 以来$m$が十分に小さい場合、候補を並べ替えて各色を最大 1 回割り当てることができ、各列が利用可能な最適なオプションを確実に取得できるようになります。

 ## アルゴリズムのチュートリアル

 グリッドを列ごとに再解釈し、各列に各色のセルが何個含まれているかに焦点を当てます。 

1. すべての列について、各色が何回出現するかを数えます。 これにより、各列が周波数マップに圧縮されます。 これが機能する理由は、列操作は位置を循環的に並べ替えるだけであるため、選択した最終色と「一貫性」を保つことができるセルの数を決定するにはカウントのみが重要であるためです。 
2. 各列について、すべてのペアをリストします。$(color, frequency)$。 各ペアは、その列に最終的にその色が割り当てられた場合の利点を表します。 
3. 問題を、合計度数合計を最大化しながら、列間で色を繰り返すことができないという制約を付けて、列ごとに 1 つの色を選択するように変換します。 これは、選択された各周波数が、操作によって「押し出される」必要のないセルの数に対応するためです。 
4. すべての列にわたるすべての候補ペアを 1 つのリストに収集し、頻度の降順に並べ替えます。 
5. 並べ替えられたリストを繰り返し処理し、列と色の両方がまだ使用されていない場合は、列に色を貪欲に割り当てます。 ペアを受け入れるたびに、その列をその色にロックします。 
6. 最終的な答えは、セルの総数から選択した周波数の合計を引いたものから計算されます。これは、選択した周波数が、操作によって移動する必要なく位置合わせできるセルを表すためです。 

### なぜ効果があるのか

 各列は独立して最終的な色の選択に貢献し、コストは循環配置でその色に一致するセルの数にのみ依存します。 操作は単一の外部要素を回転および交換するだけであるため、列内のマルチセットの分布は変更されません。 したがって、保持される一致を最大化することは、必要な外部転送を最小化することと同じです。 すべての列と色のペアが他の割り当てから独立した固定値を持ち、より高い頻度のペアを最初に選択することで、色の一意性制約の下で保持されるセルの合計が最大化されるため、貪欲な割り当てが機能します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [list(map(int, input().split())) for _ in range(n)]

    freq = [dict() for _ in range(m)]
    
    for i in range(n):
        for j in range(m):
            c = grid[i][j]
            freq[j].setdefault(c, 0)
            freq[j][c] += 1

    candidates = []
    for j in range(m):
        for c, f in freq[j].items():
            candidates.append((f, j, c))

    candidates.sort(reverse=True)

    used_col = [False] * m
    used_color = [False] * (m + 1)

    total_keep = 0

    for f, col, color in candidates:
        if not used_col[col] and not used_color[color]:
            used_col[col] = True
            used_color[color] = True
            total_keep += f

    print(n * m - total_keep)

if __name__ == "__main__":
    solve()
```プログラムはまず各列を頻度辞書に圧縮します。これにより、列ごとに各色のセルが何個存在するかが正確に取得されます。 次に、列が色に一致するすべての可能な割り当てのグローバル リストを作成し、その色にすでに一致しているセルの数によって重み付けされます。 

並べ替えにより、常に最も有益な一致が最初に割り当てられるようになります。 貪欲な選択では、各列と各色が最大 1 回使用されることが強制されます。これは、最終的な列の色が個別である必要があり、各列が単色で終わる必要があるという要件と一致します。 

最後に、演算を直接計算する代わりに、割り当てられた列の色と一貫性を保つことができるセルの数を計算し、合計から減算します。

 ## 特殊なケース

 特殊なケースとしては、複数の列が同じ色を強く好む場合があります。 たとえば、2 つの列が色 1 によって支配されている場合、貪欲な選択により 1 つの列だけが色 1 を取得し、2 番目の列はより弱い色に戻る必要があります。 アルゴリズムは、すべての候補をグローバルに並べ替えることによってこれを処理するため、最も頻度の高い割り当てが最初に確保され、その後の競合は自然に解決されます。 

もう 1 つのエッジ ケースは、均一な色の列です。 列全体がカラーの場合$c$、その唯一の意味のある割り当ては色を指定することです$c$全重で$n$。 この候補は常にその列に対して最大であるため、別の列がさらに高い優先順位でその色をすでに消費していない限り、その候補が選択されます。そのような重みはすべて同一であり、貪欲なタイブレークによって実現可能性が維持されるため、これは不可能です。 

最後に、いつ$n=1$、各列にはすでに 1 つの値が含まれているため、すべての列と色のペアは、それ自体の色に対してのみ頻度 1 を持ちます。 アルゴリズムは各列に固有の色を即座に割り当て、予想どおりコストがゼロになります。
