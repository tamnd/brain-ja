 ## 解決策
 ## 問題の理解

 私たちは、各セルにシュレック (緑) またはドンキー (赤) のおもちゃの兵隊が含まれるか、空である可能性がある長方形のグリッド上の 2 人用ゲームを分析するように求められました。 グリッドの寸法は _n_ × _m_ で、各行には最大 2 人の兵士が配置されます。 プレイヤーは順番に、自分の兵士の一部を 1 ～ _k_ ユニットの間で、列に沿って敵の兵士に向かって、または敵の兵士から遠ざけるように移動させます。 兵士は、他の兵士が占有しているセルを通り抜けたり、そこに移動したりすることはできず、移動はその兵士の列に制限されます。 プレイヤーが有効な手を持っていない場合、プレイヤーは負けます。 シュレックは常に最初に動きます。 課題は、両方が最適にプレーすると仮定して、勝者を予測することです。 

入力では、プレイヤーが 1 ターンに移動できる兵士の最大数を制御する数値 _k_ とともに、グリッド レイアウトを指定します。 出力は勝者です。シュレックが勝った場合は「ファースト」、ドンキーが勝った場合は「セカンド」、最適なプレイでゲームが無期限に継続できる場合は「引き分け」となります。 

制約により、_n_、_m_、_k_ はすべて最大 100 であることがわかります。これは、可能な配置の数は兵士の数に応じて指数関数的に増加するため、すべてのゲーム状態にわたって単純な再帰シミュレーションを行う余裕がないことを示しています。 ただし、1 列あたり最大 2 人の兵士という制限により、各列で可能な移動は大幅に制限されます。 これは、ゲームを独立した行に分解し、組み合わせゲーム理論を使用してモデル化できることを示唆しています。 

重要なエッジケースは、行に 1 人の兵士が含まれる場合、または兵士が含まれない場合に発生します。 たとえば、列にシュレックの兵士が 1 人だけいて、ロバの兵士がいない場合、その兵士は自由に移動でき、列が「終了」することはありません。 逆に、両方のプレイヤーが同じ列に 1 人の兵士を持ち、_k_ ≥ 1 の場合、その列は移動が制限された単純な Nim ヒープのように動作します。 これらの状況を誤解すると、間違った勝者が生まれる可能性があります。 

## アプローチ

 ブルートフォースアプローチは、あらゆる可能な動きを再帰的にシミュレートし、ポジションを勝ちか負けとしてマークすることです。 これには、移動のために最大 _k_ 人の兵士のすべてのサブセットを生成し、新しい位置を計算し、結果の状態を再帰的に評価することが含まれます。 このアプローチは、ゲームが有限であるため概念的には機能しますが、手に負えなくなります。1 行に 2 人の兵士しかいない、100 行であっても、分岐要素が大きく、州の数が指数関数的に増加します。 

重要な洞察は、各行が独立しているということです。 兵士は列に沿って移動し、他の列をジャンプしたり横切ったりすることはできないため、「列ゲーム」の合計を除いて、ある列の移動は他の列に影響を与えません。 したがって、各行は 1 次元の組み合わせゲームとして扱うことができます。 具体的には、問題は行ごとにグランディ数 (ニンバー) を計算することに帰着します。 各行のグランディ番号が判明したら、スプラーグ・グランディ定理に従って、すべての行のグランディ番号を XOR 演算することによって全体の勝者が決定されます。XOR が 0 の場合は 2 番目のプレーヤーが勝ち、そうでない場合は 2 番目のプレーヤーが勝ちます。 ゼロ以外の場合、最初のプレイヤーが勝ちます。 行に制限がない (兵士がある方向に無限に移動できる) 場合、「無限」ゲームとなり、引き分けが発生します。 このような無限の動きを検出することが重要です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(n*m)) | O(n*m) | 遅すぎる |
 | 行ごとのグランディ | O(n * m * k) | O(n * m) | 承認済み |

 ## アルゴリズムのチュートリアル

1. グリッドの寸法 _n_、_m_、移動ごとの最大兵士数 _k_、およびグリッド自体を読み取ります。 
2. 行グランディ数の XOR のためのアキュムレータを初期化します。 
3. 各行について、シュレックとロバの兵士の位置を見つけます。 
4. 列に敵兵士がいない場合は、列の境界を越えて自由に移動できる兵士がいるかどうかを確認します。 その場合、ゲームを「引き分け」としてマークします。 
5. 両方のプレイヤーがいる行の場合、左端と右端の兵士の間のセグメントを境界のある Nim ヒープとしてモデル化します。 ヒープ サイズは、兵士間の空のセルの数と等しくなります。 プレイヤーが 1 ターンに 1 ～ _k_ ユニット移動できると仮定して、グランディ数を計算します。 
6. 各行のグランディ数をアキュムレータに XOR します。 
7. すべての行を処理した後、いずれかの行が無限としてマークされている場合は、「Draw」を出力します。 
8. それ以外の場合、XOR が 0 の場合は、「Second」を出力します。 それ以外の場合は「最初」を出力します。 

正しさはスプレイグ-グランディの定理に基づいています。つまり、各行は明確に定義された動きによる個別の公平なゲームであり、行のグランディ数値の XOR によって全体の勝者が決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def mex(s):
    m = 0
    while m in s:
        m += 1
    return m

def compute_grundy(length, k):
    if length == 0:
        return 0
    g = [0] * (length + 1)
    for i in range(1, length + 1):
        s = set()
        for move in range(1, min(k, i) + 1):
            s.add(g[i - move])
        g[i] = mex(s)
    return g[length]

def main():
    n, m, k = map(int, input().split())
    grid = [input().strip() for _ in range(n)]
    xor_sum = 0
    infinite = False
    
    for row in grid:
        positions = [(i, c) for i, c in enumerate(row) if c in 'GR']
        if not positions:
            continue
        
        G_pos = [i for i, c in positions if c == 'G']
        R_pos = [i for i, c in positions if c == 'R']
        
        if not R_pos:
            infinite = True
            continue
        if not G_pos:
            continue
        
        left = min(G_pos + R_pos)
        right = max(G_pos + R_pos)
        empty_between = right - left - 1
        xor_sum ^= compute_grundy(empty_between, k)
    
    if infinite:
        print("Draw")
    elif xor_sum == 0:
        print("Second")
    else:
        print("First")

if __name__ == "__main__":
    main()
```このソリューションでは、まず兵士間のセグメントのグランディ数を計算し、次にそれらを集計します。 の`compute_grundy`関数は、移動が制限された 1D Nim ヒープの動的プログラミング テーブルを使用します。 無限行を個別に追跡します。 境界チェックにより、グリッドを超えたセルの数え間違いを回避します。 

## 実用的な例

 **サンプル 1**

 入力:```
2 3 1
R-G
RG-
```行 1: 0 (R) と 2 (G) の位置。 間の空のセル: 1. k=1 で長さ 1 のグランディ数は 1。XOR 合計 = 1。 

行 2: 0 (R) と 1 (G) の位置。 間の空のセル: 0。グランディ数 = 0。XOR 合計は 1 のままです。 

無限行はなく、XOR 合計 ≠ 0 であるため、出力は「最初」になります。 

**カスタム例**```
2 4 2
G--R
-R-G
```行 1: 0 (G) と 3 (R) の間の空のセル: 2。グランディ数 = 2。XOR 合計 = 2。 

行 2: 1 (R) と 3 (G) の位置: 空のセル = 1。グランディ =1。 XOR 合計 = 2 ^ 1 =3。 出力: 「最初。」

 これは、独立した行の動作を尊重し、複数の行が XOR を介して正しく結合されていることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * m * k) | 各行には最大で m 個のセルがあり、最大 k まで移動して長さ m までのグランディ数を計算します。 |
 | スペース | O(m) | 最大 m の長さの各行セグメントの DP テーブル。 |

 n、m ≤ 100、k ≤ 100 の場合、n * m * k ≤ 10^6 となり、これは 2 秒の制限内に十分収まります。
