 ## 解決策
 ## 問題の理解

 私たちは、`n × m`チェス盤のようなグリッドで、できるだけ多くの兵士を配置したいと考えています。 2 人の兵士がセル間のユークリッド距離の 2 乗が正確に一致する場合、衝突します。`5`。 

二乗距離が等しい唯一の整数ペア`5`は`(1, 2)`そして`(2, 1)`サインまで。 言い換えれば、兵士たちはチェスの騎士とまったく同じように互いに攻撃します。 このタスクは実際に、攻撃しないナイトの最大数を要求します。`n × m`ボード。 

基板の寸法は最大でも`1000 × 1000`, したがって、セルの総数は 100 万に達する可能性があります。 これにより、指数関数的な検索やバックトラッキングが即座に排除されます。 サブセットを探索したり、すべてのセルに対して重いグラフ アルゴリズムを実行しようとするアルゴリズムでさえも困難を伴うでしょう。 直接的な建設的または数学的な観察が必要です。 

市松模様のパターンにいきなりジャンプすると、いくつかのエッジケースは誤って対処しやすくなります。 

単一の行を考えてみましょう。 

入力:```
1 7
```正しい出力:```
7
```ナイトは攻撃するには水平方向と垂直方向の両方のオフセットが必要です。 で`1 × 7`ボードでは、2 つのセルが互いに攻撃することはないため、すべてのマス目を占有することができます。 不注意なチェッカーボード ソリューションは誤って返される可能性があります`4`。 

の`2 × m`事件こそが本当の罠だ。 

入力：```
2 4
```正しい出力:```
4
```標準のチェッカーボードでは、`4`ここではたまたま正しいですが、次の場合は次のとおりです。 

入力:```
2 5
```正しい出力:```
6
```シンプルな交互のカラーリングにより、`5`, which is not optimal. 1 つの寸法が次のボードに等しい場合`2`、ナイトは 4 列の繰り返しブロックに詰めることができます。 

もう一つの微妙な例:

 入力:```
2 2
```正しい出力:```
4
```移動するためナイト攻撃は不可能`(1,2)`または`(2,1)`基板の中に収まりません。 すべてのセルには兵士が含まれている可能性があります。 やみくもにセルの半分を使用する数式は失敗します。 

## アプローチ

 ブルートフォース解釈は簡単です。 すべてのセルをグラフの頂点として扱い、ナイトが互いに攻撃する場合は 2 つのセルを接続し、最大の独立集合を検索します。 独立したセットはまさに競合しない兵士のセットであるため、これにより正確さが保証されます。 

問題は、最大独立集合が一般に指数関数的であることです。 セルが 40 個しかない場合でも、ブルート フォースは非現実的になります。 私たちのボードには最大 100 万個のセルが含まれる可能性があるため、この方向は絶望的です。 

騎士の動きの構造はすべてを変えます。 騎士は常にチェッカー盤の 1 つの色から別の色にジャンプします。 これは、攻撃グラフが 2 部構成であることを意味します。 ほとんどのボードでは、すべて黒のマス目またはすべて白のマス目にナイトを配置すると、すぐに約半分のマスが得られます。実際、これは両方の寸法が少なくとも同じであるボードに最適です。`3`。 

唯一の例外は、1 つの次元が非常に小さい場合に発生します。 

どちらかの次元が等しい場合`1`、騎士はまったく攻撃できません。 すべての正方形を使用できます。 

どちらかの次元が等しい場合`2`、パターンが特殊になります。 ナイトは、連続する 4 つの縦列のグループ内でのみ対話できます。 このような 4 つのブロックのそれぞれに、4 人の騎士を安全に配置できます。 残った列は、列ペアごとに最大 2 つの追加のナイトに貢献します。 

すべての大きなボードでは、次のような単純なチェッカーボード配置が最適です。```
ceil(n * m / 2)
```問題全体は、これら 3 つの構造的なケースを慎重に処理することに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^(nm)) | O(nm) | 遅すぎる |
 | 最適 | お(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`m`。 
2. 次のように寸法を正規化します。`n <= m`。 

これにより、小さな値のみをチェックする必要があるため、特殊なケースの処理が簡素化されます。`n`。 
3. もし`n == 1`、出力`m`。 

騎士には 2 つの方向への動きが必要です。 単一列では攻撃は不可能です。 
4. もし`n == 2`、ボードを 4 列のブロックで処理します。 

4 列のブロックごとに、繰り返しパターンを使用して 4 人の騎士を安全に配置できます。 
5. 以下を計算します。```
blocks = m // 4
rem = m % 4
```6.追加`blocks * 4`完全なブロックの騎士。 
7. 残りの列については、次のようにします。 

- もし`rem == 0`、 追加`0`- もし`rem == 1`、 追加`2`- もし`rem >= 2`、 追加`4`残った列は最大 4 人の追加の騎士に貢献できます。 
8. それ以外の場合、`n >= 3`、出力:```
(n * m + 1) // 2
```これは、市松模様の色の大きい色のセルの数です。 

### なぜ効果があるのか

 両方の寸法が少なくとも`3`、騎士の動きごとにチェッカーボードの色が変わります。 ナイトを 1 つの色にのみ配置すると、競合がないことが保証され、どの配置も 2 部グラフのより大きなパーティション サイズを超えることはできません。 

の`1 × m`この場合は法廷騎士の動きがまったくないので、どのマスも安全です。 

の`2 × m`ナイトは非常に制限された構造内でのみ対話できるため、ケースの動作は異なります。 最適な配置は 4 列ごとに繰り返されます。 4 つの列の各セグメント内に、4 人の騎士全員を安全に配置できます。 不完全なセグメントは、残りの列ペアごとに最大 2 つのナイトに寄与します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

if n > m:
    n, m = m, n

if n == 1:
    print(m)

elif n == 2:
    blocks = m // 4
    rem = m % 4

    ans = blocks * 4

    if rem == 1:
        ans += 2
    elif rem > 1:
        ans += 4

    print(ans)

else:
    print((n * m + 1) // 2)
```最初のステップでは、次のようにディメンションを交換します。`n`常に小さいほうです。 これにより、すべての特別な処理に集中できるようになります。`n == 1`そして`n == 2`。 

の`n == 1`支店は直通です。 すべての攻撃には 2 次元をまたぐ移動が必要となるため、騎士は攻撃することができません。 

の`n == 2`ロジックだけが難しい部分です。 繰り返しパターンは 4 つの列にまたがります。 各完全なグループはちょうど 4 人の騎士を提供します。 剰余の処理は微妙です。 

列を 1 つ追加するために、さらに 2 人の騎士を配置できます。 

2 つまたは 3 つの列を追加するには、さらに 4 人の騎士を配置できます。 

よくある間違いは、次のものを使用することです。```
ans += rem * 2
```いつ過大評価されるか`rem == 3`。 

最後のブランチは、チェッカーボード式を使用して、すべての大きなボードを処理します。 表現:```
(n * m + 1) // 2
```セルの半分の上限を計算します。 

ここでは、Python の整数は最大積を簡単に処理できますが、固定幅の整数を使用する言語であっても、`1000 × 1000`完全に安全です。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())

    if n > m:
        n, m = m, n

    if n == 1:
        print(m)

    elif n == 2:
        blocks = m // 4
        rem = m % 4

        ans = blocks * 4

        if rem == 1:
            ans += 2
        elif rem > 1:
            ans += 4

        print(ans)

    else:
        print((n * m + 1) // 2)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out.strip()

# provided sample
assert run("2 4\n") == "4", "sample 1"

# custom cases
assert run("1 1\n") == "1", "minimum board"
assert run("1 7\n") == "7", "single row"
assert run("2 5\n") == "6", "special 2-row pattern"
assert run("3 3\n") == "5", "checkerboard case"
assert run("1000 1000\n") == "500000", "maximum size"
assert run("2 2\n") == "4", "small special case"

 ## 特殊なケース

 次の入力を考えてみましょう。```
1 7
```アルゴリズムは次元を正規化し、`n == 1`支店。 すぐに戻ってきます`7`。 

垂直方向の移動が不可能であるため、ナイトの移動は存在しません。 アルゴリズムは、誤った結果を与えるチェッカーボード式を正しく回避します。`4`。 

ここで次のことを考えてみましょう。```
2 5
```計算は次のようになります。 

| 変数 | 値 |
 | --- | --- |
 |`blocks`|`1`|

 | ベース |`4`|
 | 番外編 |`2`|
 | 答え |`6`|

 残った 1 つの列は、ちょうど 2 つの追加の騎士に貢献します。 これにより、誤って 1 つだけを追加する実装が捕捉されます。 

ついに：```
2 2
```得られるものは次のとおりです。 

| 変数 | 値 |
 | --- | --- |
 |`blocks`|`0`|
 |`rem`|`2`|
 | ベース |`0`|
 | 番外編 |`4`|
 | 答え |`4`|

 盤面が小さいとはいえ、ナイトの攻撃は入りません。 特別な処理を正しく行うことで、すべてのマス目を占有することができます。
