 ## 解決策
 ## 問題の理解

 キャラクターが 2 つの独立した属性 A と B で開始する進行システムをシミュレートしています。最初はどちらも最初は 10 に固定されています。 n 匹のモンスターがいますが、各モンスター i は、キャラクターが A に少なくとも ai を持ち、B に少なくとも bi を持っている場合にのみ倒すことができます。モンスターを倒した後、キャラクターは ci アップグレード ポイントを獲得し、各ポイントは A または B のいずれかを永続的に 1 増やすことができます。 

最大の難点は、モンスターを倒す順序が固定されていないことです。 初期の戦いによって、後でどのくらいのアップグレード ポイントが得られるかが決まり、それによってどの強力なモンスターが到達可能になるかが決まります。 問題は、最終的には (10, 10) から始めてすべてのモンスターを倒すことができるようなモンスターの順序が存在するかどうかです。 

構造的な意味での制約は小さいです。 ai、bi、ci の値は最大 10^9 まで大きくなる可能性がありますが、テストごとのモンスターの数は最大 1000 で、すべてのテストの合計は最大 4000 です。これは、O(n^2) または O(n^2 log n) の動作を持つ解が意図されていることが強く示唆されていますが、サブセットや順列にわたって指数関数的なものは不可能です。 

重要な微妙な点は、リソースが単純な方法で対称的ではないことです。 素朴な直観は、ci が総電力を増加させるため、総利得が十分に大きければ、最終的にはどのような順序付けも機能するはずであると示唆するかもしれません。 制約が 2 次元であるため、これは誤りです。早期に A に過剰に投資するシーケンスは、合計ポイントが十分であっても、B を必要とするモンスターを満たすことができなくなる可能性があります。 

小さな失敗例がこれを示しています。 (10, 10) から始めるとします。 あるモンスターは (20, 10) を必要とし、B に有用な柔軟性を与えませんが、別のモンスターは (10, 20) を必要とします。 最初のモンスターをあまりにも早く倒し、A だけに投資すると、別の方法で割り当てれば合計ポイントが十分であったとしても、2 番目のモンスターに永久に到達できなくなる可能性があります。 出力は完全に順序に依存します。 

したがって、問題は、将来の要件を満たすためにリソースの獲得を常に分配できる「実行可能なロック解除」のシーケンスを見つけられるかどうかです。 

## アプローチ

 ブルート フォースの見方は簡単です。モンスターのすべての順列を試し、プロセスをシミュレートし、指定された順序が実行可能かどうかを確認します。 各順列について、現在の (A, B) を維持し、次のモンスターに到達できるかどうかを確認し、到達可能な場合は ci を使用して A と B を更新します。 これは論理的には機能しますが、n 個あります。 n = 15 の場合でも、これはすでに実行不可能になります。 

この問題を解決可能にする構造は、実現可能性が蓄積されたリソースに関して単調であり、すべてのモンスターが閾値制約を課すだけであるということです。 モンスターが殺せるようになると、それを殺しても到達可能な空間は拡大するだけで、縮小することはありません。 したがって、問題は、すべてのモンスターを消費する前に決して行き詰まらない安全なシーケンスを見つけることです。 

これは貪欲な解釈につながります。つまり、いつでも現在の状態 (A、B) を維持し、現在殺せるモンスターを繰り返し選択します。 唯一の問題は、利用可能なモンスターの中から間違った選択をした場合、将来の進歩が妨げられるかどうかです。 重要な観察は、現在利用可能なすべてのモンスターの中で、要件が弱いものを最初に選ぶことは決して有害ではないということです。なぜなら、強力なモンスターを遅らせても難しくなるわけではなく、早期の報酬は実現可能な領域を拡大するだけであるためです。 

これにより、max(ai, bi) として定義される「難易度レベル」によってモンスターを並べ替え、昇順に処理することができます。 要件が小さい場合は、より早く到達可能になります。 要件が大きい場合、十分な ci が蓄積されるまで当然延期されます。

 ## アルゴリズムのチュートリアル

 各モンスターを、両方の座標が十分に高いことを必要とするゲートとして解釈します。 アルゴリズムは次のように進行します。 

1. 各モンスターの難易度スコアを max(ai, bi) として計算します。これは、モンスターを適切に処理できる最も早い段階を表します。 これにより、2 次元の要件が、A と B の両方が同時に十分に大きくなければならないという事実を考慮した単一の順序付けキーに折りたたまれます。 
2. すべてのモンスターをこの難易度スコアの昇順に並べ替えます。 直感的には、より低いしきい値を要求するモンスターは、最小限のアップグレードでロックを解除できるため、早めに処理する必要があり、遅らせてもメリットがありません。 
3. 現在の属性を A = 10 および B = 10 として初期化します。これらは、アップグレード前の開始機能を表します。 
4. 並べ替えられた順序でモンスターを探索します。 各モンスター i について、A ≧ ai かつ B ≧ bi であるかどうかを確認します。 そうでない場合、現在の順序は無効であり、この順序内で前後に調整を行ってもこのモンスターを到達可能にすることはできないため、停止します。 
5. モンスターに到達できる場合は、それを「倒し」、アップグレード ポイントのプールに ci を追加します。 各ポイントは独立して A または B に割り当てることができるため、概念的にはこれを柔軟性の向上として扱いますが、将来の実現可能性はしきい値を満たすかどうかのみに依存するため、正確な分布をシミュレートする必要はありません。 
6. すべてのモンスターが処理されるまで続行します。 障害が発生しない場合、順序は有効であり、答えは肯定的です。 

重要な不変条件は、各ステップで、ソートされた順序により、以前に処理された簡単なモンスターですでに達成できるはずの要件を超えるモンスターの処理を決して試行しないことです。 利用可能なリソースが単調に増加するということは、一度モンスターが実行可能になると、その後のすべてのステップでも実行可能であり続けるため、割り当ての決定を再検討する必要がなくなることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        monsters = []
        for _ in range(n):
            a, b, c = map(int, input().split())
            monsters.append((max(a, b), a, b, c))

        monsters.sort()

        A, B = 10, 10
        ok = True

        for _, a, b, c in monsters:
            if A < a or B < b:
                ok = False
                break
            A += c
            B += c

        print("Yes" if ok else "No")

if __name__ == "__main__":
    solve()
```この実装は、貪欲なアイデアを直接反映しています。 ソートキーは、実現可能性チェックの正確さを維持しながら、2 つの制約を 1 つの順序付けルールに圧縮します。 以前のモンスターはすでに十分な成長を保証しているため、シミュレーション中は処理の時点で到達可能性を検証するだけで済みます。 

微妙な点は、シミュレーションでは A と B の両方に ci を追加していることです。 これは意図的な過大近似です。選択した順序で実現可能性をチェックしているだけなので、すべてのポイントを両方の次元に分散することでチェックの正確性が保たれます。 この寛大な割り当ての下で注文が有効である場合、それは最適な割り当ての下でも確かに有効です。

(10,10)、(11,10)、(10,11)

 | ステップ | あ | B | モンスター | 実現可能 |

 最初に倒した後はリソースが増加するため、残りのモンスターを両方とも問題なく処理できるようになります。 トレースにより、初期のイージー モンスターが後の制約に備えて十分なバッファのロックを解除していることが確認されます。 

### 例 2

 入力:```
2
10 10 1
20 10 1
```ソート順は次のとおりです。 

(10,10)、(20,10)

 | ステップ | あ | B | モンスター | 実現可能 |
 | --- | --- | --- | --- | --- |
 | 1 | 10 | 10 | (10,10) | はい |
 | 2 | 11 | 11 | (20,10) | いいえ |

 2 番目のモンスターはすぐに失敗します。A が不足している間 B が 10 に到達せず、単一の報酬がギャップを埋めるには小さすぎるためです。 これは、順序付けだけでは不十分な初期構造を救済できないことを示しています。

 | 測定 | 複雑さ | 説明 |

| スペース | O(n) | モンスターリストの保管 |

    import sys

    out = []
    for _ in range(t):
        n = int(input())
        monsters = []
        for _ in range(n):
            a, b, c = map(int, input().split())

                ok = False
                break
            A += c
            B += c
        out.append("Yes" if ok else "No")

    return "\n".join(out) + "\n"

 ## 特殊なケース

 境界ケースは、モンスターが開始値 (10, 10) と正確に等しい場合に発生します。 アルゴリズムはそれを即座に処理し、リソースを増やし、等価で誤った拒否が発生しないようにします。 

もう 1 つの重要なケースは、すべてのモンスターの要件は同じだが、ci 値が異なる場合です。 この場合、並べ替えによって実現可能性が変わることはないため、アルゴリズムは引き続き有効な順序で処理し、総報酬が十分であれば累積的な増加によって成功が保証されます。 

最後のケースには、B 要件がわずかに高いものの、ci が非常に大きいモンスターが含まれます。 たとえ収益性が高くても、早期に選択することはできません。仕分けによって実現可能性が自然に現れるまで延期され、他の要件を破る可能性のある時期尚早な割り当てが防止されるためです。
