 ## 解決策
 ## 問題の理解

 リズム ゲームでは、トラックごとに 1 つずつ、時間間隔の 2 つの独立したシーケンスが与えられます。 各インターバルは「ホールド ノート」を表します。つまり、その時間範囲中、プレーヤーはそのトラック上で指を押し続けなければなりません。 

1 つのトラックのホールドを操作するには、1 本の指で十分です。 両方のトラックに同時にアクティブなホールドがある場合、複雑さが発生します。 このようなオーバーラップ期間中は 2 本の指を同時に使用する必要があり、オーバーラップ時間の単位ごとに 1 単位のエネルギーが消費されます。 重複しない時間には費用はかかりません。 

タスクは、両方のトラックが同時にアクティブになる合計時間を計算し、それを初期エネルギーから差し引き、残りのエネルギーが負でないままであるかどうかを判断することです。 

各シーケンスはすでに時間順にソートされており、内部的には互いに素な間隔が含まれているため、単一のシーケンス内でマージする必要はありません。 

主要な出力は、すべてのオーバーラップを支払った後の残りのエネルギー、またはオーバーラップ コストが初期エネルギーを超えている場合は -1 です。 

n + m ≤ 100000 という制約により、区間間の二次比較が即座に除外されます。 どのソリューションでも、両方のシーケンスを線形または線形に近い時間で処理する必要があります。 

微妙な落とし穴は、部分的なオーバーラップの処理が間違っていることです。 たとえば、ある間隔が別の間隔に完全に含まれている場合、オーバーラップは端点が接触しているだけではなく、小さい方の間隔の全長になります。 もう 1 つのエッジ ケースは、[1, 3] や [3, 5] など、間隔が端点でのみ接触する場合です。 重なり合う長さがゼロであるため、エネルギーは消費されません。 

## アプローチ

 直接的なアプローチでは、最初のシーケンスのすべての間隔と 2 番目のシーケンスのすべての間隔を比較し、交差の長さを計算します。 すべての重複が明示的に考慮されるため、これは正しいです。 ただし、各ペアがオーバーラップする可能性があるため、O(nm) チェックが発生し、最悪の場合、10^10 の演算に達し、時間制限の下では不可能です。 

各シーケンスを 1 行上のセグメントの素の結合として見ると、問題の構造がより明確になります。 このような 2 つの和集合間の重複の合計は、両方のリストを順番にスイープし、常に各側から現在のアクティブな間隔を追跡することによって計算できます。 

どの瞬間においても、各シーケンスの現在の間隔のみが重要です。 各シーケンスの間隔は内部的に重複していないため、昇順にそれらを移動し、2 ポインターの走査を維持できます。 現在の間隔が交差するたびに、交差の長さを追加します。 次に、最初に終了する間隔を進めます。 

これにより、問題は 2 つのソートされた間隔リストをマージし、間隔の総数が線形になる交差長を累積するという問題に軽減されます。

 | 2 ポインタ スイープ | O(n + m) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 2 つのポインターを使用して、両方の間隔リストを時間の昇順に処理します。 

1. シーケンス s と t の先頭で 2 つのポインター i と j を初期化し、total_overlap をゼロに設定します。 これらのポインタは常に、各シーケンスの現在のアクティブな間隔を表します。 
2. 各ステップで、間隔 s[i] = [ls, rs] および t[j] = [lt, rt] を考慮します。 それらの交差を計算します。 交差は max(ls, lt) で始まり min(rs, rt) で終わります。 開始が終了よりも厳密に小さい場合は、その差を total_overlap に追加します。 
3. rs と rt を比較して、どちらのポインタを進めるかを決定します。 rs < rt の場合、区間 s[i] が最初に終了するため、i をインクリメントします。 それ以外の場合は、j をインクリメントします。 これにより、終了する間隔はその終点を超えてさらなるオーバーラップに寄与することができないため、潜在的なオーバーラップをスキップすることがなくなります。 
4. いずれかのシーケンスがなくなるまで繰り返します。 
5. すべてのオーバーラップを処理した後、total_overlap と E を比較します。total_overlap > E の場合、-1 を出力します。 それ以外の場合は、E − total_overlap を出力します。

### なぜ効果があるのか

 常に、両方のシーケンスには明確に定義された現在の間隔があります。 各シーケンス内の間隔は互いに素でソートされているため、間隔が終了すると、それ自体のシーケンス内の将来の間隔と重複することはありません。 したがって、残っている唯一の重複候補は、他のシーケンス内の将来の間隔となります。 先に終了するポインタを進めると完全性が保たれ、重複セグメントを見逃すことがなくなります。 ライン上の各時間間隔はちょうど 1 組のアクティブ セグメントによってカバーされるため、オーバーラップの各単位は 1 回だけ考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n, m, E = map(int, input().split())
    s = [tuple(map(int, input().split())) for _ in range(n)]
    t = [tuple(map(int, input().split())) for _ in range(m)]

    i = j = 0
    cost = 0

    while i < n and j < m:
        ls, rs = s[i]
        lt, rt = t[j]

        l = ls if ls > lt else lt
        r = rs if rs < rt else rt

        if l < r:
            cost += r - l

        if rs < rt:
            i += 1
        else:
            j += 1

    if cost > E:
        print(-1)
    else:
        print(E - cost)

if __name__ == "__main__":
    main()
```このソリューションは両方の間隔リストを読み取り、それらをロックステップでスキャンする 2 つのポインターを維持します。 交差の計算では、単純な最大値と最小値の比較が使用されます。 最初に終了する間隔のポインタを進める決定により、各間隔が正確に 1 回処理されることが保証され、重複カウントの繰り返しが防止されます。 

よくある実装上の間違いは、`<=`の代わりに`<`重複の有効性を計算するとき。 2 つの間隔が点でのみ接触する場合、重なり合う長さはゼロとなり、コストに寄与してはならない。 

## 実用的な例

 | --- | --- | --- | --- | --- | --- |

 | 1 | 0 | [5,7] | [2,6] | [5,6] → 1 | 3 |

このトレースは、スイープの進行中に各オーバーラップ セグメントがどのように 1 回だけカウントされるかを示しています。

このケースは完全な封じ込めを示しており、1 つの間隔のペアが単一の大きなオーバーラップを生成します。

 ## 特殊なケース

 よくある失敗例は、エンドポイントのみの接続です。 考慮する：```
1 1 10
0 5
5 10
```このアルゴリズムは l = 5 および r = 5 を計算するため、l < r は false となり、コストは追加されません。 出力は 10 のままです。これにより、厳密な不等式によって長さ 0 の重複が正しく除外されることが確認されます。 

もう 1 つの微妙なケースは、ネストされた間隔です。```
1 1 10
0 100
20 30
```ここでは交差は [20, 30] であり、10 単位に寄与します。 処理後、両方のポインターが正しく進み、追加のオーバーラップが見逃されることはありません。 これにより、最初に終了する間隔を進めると、将来の交差の機会がすべて保持され、セグメントが二重にカウントされることがないことが確認されます。
