 ## 解決策
 ## 問題の理解

 2D 平面上の一連の点が与えられます。 タスクは正確に配置することです$k$縦線と$k$水平線はどの点も通過しないようにし、これらの線は平面を次のように分割します。$(k+1)\times(k+1)$長方形の領域。 すべての領域には、まったく同じ数のポイントが含まれている必要があります。 

各点は、その左側にある垂直線の数とその下にある水平線の数によって決まる 1 つの領域に正確に属します。 非常に効果的に、垂直線は点の分割を引き起こします。$k+1$垂直方向のストリップと水平方向の線が独立してパーティションを誘導します。$k+1$水平方向のストリップ。 要件は、1 つの垂直ストリップと 1 つの水平ストリップを選択して形成されるすべての交差セルに同じ数のポイントが含まれることです。 

制約は非常に大きく、最大で$2\cdot 10^5$すべてのテストにわたるテストごとのポイント、および$k$と同じ大きさにすることができます$10^9$。 これにより、ライン配置を明示的に構築またはシミュレートしようとするアプローチは即座に除外されます。 有効な解決策は、ジオメトリや座標の検索ではなく、点セットの組み合わせ構造のみに依存する必要があります。 

重要な観察は、順序を除いて正確な座標は無関係であるということです。 垂直線は並べ替えられた x 値の間の任意の場所に配置でき、y についても同様であるため、x と y に沿った相対的な順序のみが重要です。 したがって、問題は、x ランクと y ランクによる点の置換に関する推論に帰着します。 

微妙なエッジケースは、ポイントが重なっている場合です。 複数の点が同一の座標を共有することができ、線はどの点も通過してはなりませんが、必要に応じて同じ座標の間に配置することができます。 重複を処理せずに座標の厳密な順序付けを前提とするソリューションは、分割で多重性を考慮する必要がある複数の同一点などの場合に失敗する可能性があります。 

もう一つのエッジケースは、$k=0$, ここでは線が引かれていません。 この場合、平面全体が 1 つの領域になるため、すべての点は自明のことながら 1 つの領域内に存在する必要があり、分布に関係なく条件が常に成り立つことを意味します。 この場合、少なくとも 1 つの分割を前提とする実装が壊れることがよくあります。 

## アプローチ

 素朴に考えてみると、次のように配置することが想像できます。$k$縦線と$k$水平線と点を割り当てようとしています$(k+1)^2$各セルが同じ数のポイントを取得するようにセルを配置します。 座標は点間の実数値の選択肢であるため、素朴な考えは、点を x でソートし、すべての方法で分割することを試みることです。$k+1$連続したグループを調べ、同様に y で一貫性をチェックします。 

ただし、線の配置の連続性を無視しても、選択できる方法はたくさんあります。$k$間のポジションをカットする$n$ポイントは組み合わせであり、すべてのパーティションを試行すると指数関数的になります。 単一の次元でもすでに$\binom{n-1}{k}$方法、それは不可能です$n=2\cdot 10^5$。 

構造上の重要な洞察は、垂直パーティションと水平パーティションが独立して均一に動作する必要があるということです。 各垂直ストリップはさらに次のように分割されるため、各垂直ストリップには正確に同じ数のポイントが含まれている必要があります。$k+1$水平線で等しいセル。 垂直ストリップのカウントが異なる場合、そのセルの行が他のセルの行とすべて一致するわけではありません。 

これにより、合計ポイントという強力な制約が強制されます。$n$で割り切れる必要があります$(k+1)^2$、それぞれの$(k+1)^2$セルのサイズは等しいです。 さらに、各垂直ストリップには次の内容が含まれます。$n/(k+1)$点、および各水平ストリップにも次の要素が含まれます。$n/(k+1)$ポイント。 

ここで、問題は各軸において 1 次元になります。 ソートされた x 座標を次のように分割できるかどうかを確認する必要があります。$k+1$それぞれのサイズの連続したグループ$n/(k+1)$、そして y 座標に対しても独立して同じことを行います。 両方が可能であれば、グループ間に線を入れることができます。 

したがって、問題は、x でソートするときに、サイズのすべてのブロックが正しいかどうかをチェックすることになります。$n/(k+1)$は有効なストリップを形成し、y についても同様です。 

微妙な点は、これは値に関するものではなく、順序統計によるグループ化のみに関するものであるということです。 並べ替え以外のジオメトリは必要ありません。

 | ブルートフォースパーティショニング | 指数 | O(n) | 遅すぎる |
 | 並べ替え + ブロック検証 |$O(n \log n)$| O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは定義します$m = k+1$。 もし$n \% (m \cdot m) \neq 0$、全体に均等に分配されているため、すぐに不可能であると結論付けます。$(k+1)^2$細胞は無理です。 

以下のように進めていきます。 

1. コンピューティング$cell = n / (m \cdot m)$。 これは領域ごとに必要なポイント数です。 
2. コンピューティング$strip = n / m$。 これは、垂直ストリップごとおよび水平ストリップごとのポイント数です。 これは、各垂直ストリップに正確に含まれるためです。$m$セルが垂直に積み重なっています。 
3. すべての点を X 座標で並べ替えます。 ソートされたリストをサイズごとにスキャンします$strip$。 各チャンクは、垂直ストリップの候補を表します。 各チャンク内で概念的に正確に割り当てることができることを確認します。$cell$後で水平セグメントごとにポイントを追加します。 この段階では、グループ化の実現可能性のみを確認します。 
4. 独立して、すべての点を Y 座標でソートし、水平ストリップについても同じチェックを実行します。 
5. x 方向と y 方向の両方で同じサイズのブロックに分割できる場合は Yes を返し、そうでない場合は No を返します。 

実装の詳細は、セルを明示的に割り当てる必要がないことです。 この構造は、両方の軸が均一なブロック分割を許可する場合、それらのデカルト積が自動的に同じサイズのセルを形成することを保証します。 

### なぜ効果があるのか

 垂直線によって引き起こされる分割は、x による順序のみに依存するため、各垂直ストリップは、sorted-x 順序の連続したセグメントになります。 同様に、水平ストリップは、並べ替えられた y 順序で連続するセグメントに対応します。 各セルは正確に 1 つの垂直ストリップと 1 つの水平ストリップの交差点であるため、すべてのセルのサイズは、インデックスの各ペアに該当するポイントの数によって決まります。 

行または列を合計すると同一の合計が得られる必要があるため、すべてのセルにわたって均一性を持たせると、ストリップ全体にわたって均一性が強制されます。 これにより、2D 制約が 2 つの独立した 1D 等分割制約に縮小されます。 両方の射影が等しいブロック分解を認めると、デカルト積構造によりすべてのブロック分解が保証されます。$(k+1)^2$交差のカーディナリティは同じです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ok_projection(coords, m, strip):
    coords.sort()
    n = len(coords)
    for i in range(0, n, strip):
        # each block must have exactly 'strip' points
        if i + strip > n:
            return False
    return True

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        pts = [tuple(map(int, input().split())) for _ in range(n)]

        m = k + 1

        if n % (m * m) != 0:
            print("No")
            continue

        strip = n // m

        xs = [p[0] for p in pts]
        ys = [p[1] for p in pts]

        if ok_projection(xs, m, strip) and ok_projection(ys, m, strip):
            print("Yes")
        else:
            print("No")

if __name__ == "__main__":
    solve()
```この解決策は、まず、等しいセル サイズによって暗示される分割条件を強制します。 次に、x 座標リストと y 座標リストを抽出し、それらが同じサイズの連続したブロックに均等に分割できるかどうかを確認します。$strip = n/(k+1)$。 ブロックが潜在的なストリップ境界に対応するようにソートする必要があります。 

実装上の微妙な問題は、座標の重複です。 厳密な不平等ギャップではなく、カウントのみに依存しているため、並べ替えは引き続き機能します。 ブロック チェックでは、同一の座標内にカットを配置しようとはしません。 非整数位置でのカットが許可されているため、いつでもポイント間にカットを配置できます。 

## 実用的な例

 ### 例 1

 入力:```

points = [(-2,-2), (-1,2), (1,3), (2,-1)]
```我々は持っています$m=2$、 それで$m^2=4$したがって、$cell=1$、$strip=2$。

 どちらの投影もサイズ 2 の 2 つのグループにきれいに分割されているため、グループ間に垂直線と水平線を配置できます。 

これにより、構造が実際のジオメトリではなく、順序のみに依存することが確認されます。 

### 例 2

 入力:```
n = 4, k = 1

 ## 特殊なケース

 のために$k=0$、線はなく、平面全体が 1 つの領域です。 アルゴリズムは正しく設定します$m=1$、$strip=n$、各軸がすべての点を含む単一のブロックを形成するため、両方の投影は自明に合格します。 

重複した点、すべて同一の座標の場合、並べ替えによりフラットな配列が生成されます。 ブロックは純粋にカウントによって定義されるため、重複がストリップの形成に干渉することはなく、アルゴリズムは引き続き正しく分割します。$n$必要な割り算条件に一致します。 

多数の同一の X 値と分散した Y 値など、座標の不均衡が極端に大きい場合、Y 投影が成功しても X 投影が失敗する可能性があります。 両方の軸が 1 つの軸だけでなく均一なブロック分解を独立してサポートする必要があるため、アルゴリズムはそのようなケースを正しく拒否します。
