 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには、整数の配列とターゲット値があります。$k$。 タスクは、順序付けされていないインデックスのペアの数を数えることです。$(i, j)$と$i < j$選択された 2 つの配列要素のビットごとの XOR が正確に等しいという特性があります。$k$。 

入力は純粋に数値です。各テスト ケースは値の複数セットを記述します。問題は、XOR の下で相互作用して固定の結果を生成する値のペアが何組あるかということです。 各テスト ケースの出力は、そのカウントを表す単一の整数です。 

この制約により、すべてのペアを直接検査するソリューションは拡張できないことが明らかです。 すべてのテスト ケースにわたる要素の合計数は次のとおりです。$2 \cdot 10^5$したがって、二次スキャンは次数を意味します。$4 \cdot 10^{10}$許容される 2 秒をはるかに超える最悪の場合の XOR 演算。 これにより、単純なペアの列挙が即座に排除されます。 

誤ったアプローチにつまずいてしまうことが多い、微妙なエッジの状況が 2 つあります。 

まず、いつ$k = 0$、状態になります。$a_i = a_j$。 このケースを区別しない単純な実装はまだ機能する可能性がありますが、一部の最適化では次のことを前提としています。$k > 0$または、「自己逆カウントを回避」しようとすると、壊れる可能性があります。 たとえば、配列では$[1, 1, 1]$、正解は0ではなく3ペアです。 

第二に、繰り返される値は非常に重要です。 要素が何度も出現する場合、それは組み合わせ的に答えに寄与します。 配列をマルチセットではなくセットとして扱うアプローチでは、過小評価されます。 

## アプローチ

 ブルートフォースのアイデアは単純です。 インデックスの各ペアについて$(i, j)$、計算する$a_i \oplus a_j$それが等しいかどうかを確認してください$k$。 これは、問題に記載されている条件を直接評価するため、正解です。 ただし、ペアごとに 1 つの定数時間 XOR が実行されるため、$\frac{n(n-1)}{2}$テストケースごとの操作。 と$n = 2 \cdot 10^5$、これは不可能です。 

重要な観察は、XOR 方程式を決定論的に再配置できることです。 もし$a_i \oplus a_j = k$、その後修正します$a_i$一意の必須値を暗黙的に示します$a_j$：つまり$a_j = a_i \oplus k$。 これにより、問題はペア列挙タスクではなく、周波数一致タスクに変わります。 

ペアを検索する代わりに、これまでに確認された値の頻度マップを維持します。 配列を左から右にスキャンすると、要素ごとに$x$、値を計算します$x \oplus k$すでに何回出現したかを確認してください。 このような出現はそれぞれ、現在の要素と有効なペアを形成します。 それから録音します$x$周波数マップに取り込みます。 

これが機能するのは、XOR が可逆であるためです。XOR を次のように適用します。$k$ターゲットをそのユニークなパートナーに変えます。 このマッピングには衝突やあいまいさが存在しないため、補数を段階的にカウントすることで、有効なペアの正確な数が得られます。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 周波数ハッシュマップ |$O(n)$平均 |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 空のハッシュマップを初期化する`freq`すでに処理した値の数を保存します。 
2. პასუხ 変数を初期化する`ans = 0`。 
3. 配列を左から右に繰り返し、各値を取得します`x`。 
4. 必要なパートナー値を計算します。`y = x XOR k`。 これはペアリングできる唯一の値です`x`以下に等しい XOR を生成します`k`。 
5.追加`freq[y]`に`ans`。 これは、有効なパートナーの以前の出現をすべてカウントします。 
6. インクリメント`freq[x]`1 で今見たことを記録します`x`。 

順序は重要です。2 番目のインデックスが最初のインデックスより大きいペアのみをカウントします。これは、以前に確認された要素との一致のみによって保証されます。 

### なぜ効果があるのか

 どのポジションでも、`freq`現在のインデックスより厳密に小さいインデックスからの値の正確なマルチセットを格納します。 現在の各要素について`x`、以前のすべての要素`y`そのような$y \oplus x = k$との有効なペアに対応します$i < j$。 XOR は全単射を定義するため$y = x \oplus k$、すべての有効なペアは、正しいエンドポイントが処理されるときに 1 回だけカウントされます。 どのペアも見逃されず、どのペアも二重にカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        freq = {}
        ans = 0
        
        for x in a:
            y = x ^ k
            ans += freq.get(y, 0)
            freq[x] = freq.get(x, 0) + 1
        
        out.append(str(ans))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、テスト ケースごとに 1 つのパスに依存します。 辞書`freq`以前に見た数値のカウントを追跡します。 各要素について、厳密なインデックス順序付け要件を維持しながら、マップを更新する前にその XOR 補数をただちにクエリします。 

よくある実装ミスは更新です`freq[x]`問い合わせる前に`freq[y]`、これは誤ってペアを数えます。$i = j$。 もう 1 つの微妙な問題は、テスト ケース間で周波数マップをリセットするのを忘れることです。これにより、独立した配列全体でカウントが混合されてしまいます。

 ## 特殊なケース

 すべての要素が同一である場合、$k = 0$、すべてのペアが有効です。 頻度法では自然にカウントが累積されます。最初の要素は 0 を寄与し、2 番目の要素は 1 を寄与し、以下のようになります。$n(n-1)/2$。 

いつ$k \neq 0$ただし、配列には繰り返し値が多数含まれているため、特定の補数のみが問題となります。 このアルゴリズムは一意性を想定していないため、各繰り返しにより寄与が正しく乗算されます。`freq[y]`。 

いつ$k = 0$、各要素の XOR 補数はそれ自体です。 インクリメントする前に頻度マップをクエリするため、以前の出現のみをカウントし、各ペアを保証します。$(i, j)$等しい値を持つものは、次の場合に 1 回だけカウントされます。$j$処理されます。
