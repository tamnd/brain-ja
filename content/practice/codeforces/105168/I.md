 ## 解決策
 ## 問題の理解

 ゲームの終了を表す位置 0 で特別な吸収条件を使用して、1 から n までラベル付けされた線分上の確率的動きをシミュレートしています。 与えられた位置 x から開始して、1 から n までの整数 y を均一に選択するというランダムな操作を繰り返し実行します。 y と現在位置 x の関係に応じて、ミラーリングされた方法でゼロに近づくか、反映された値にジャンプすることによって位置が更新され、選択した y が現在位置と正確に一致する場合にのみプロセスが停止します。 

目的はプロセスをシミュレートすることではなく、多くの異なる開始位置 x について、終了に到達するまでに必要な操作の予想数を計算することです。 各クエリは独立していますが、遷移構造は同一です。 

制約は、パラメーター n が最大 500 までの小さいことを示していますが、開始位置が最大 10^6 で、最大 2×10^5 の多数のクエリが指定されています。 これは、答えが構造化された周期的またはプレフィックス削減可能な方法で x にのみ依存し、クエリの応答は一定時間内に行われる一方で、すべての重い計算はすべての関連する状態に対して 1 回実行される必要があることを強く示唆しています。 

単純なシミュレーションでは、終了するまで繰り返し y をサンプリングし、x を更新します。 クエリごとに状態遷移のモンテカルロや直接 DP を介して期待値を計算することさえ不可能です。なぜなら、各状態は期待値で最大 O(n) 個の遷移を取る可能性があり、q が大きい場合、これは実行不可能になるからです。 

微妙な問題は、プロセスが単調に進まないことです。 たとえば、x = 10 および y = 3 の場合は 7 に移動しますが、y = 12 の場合は 2 に移動します。この対称性は、システムが単純な減算プロセスではなく、セグメント上の反射のように動作することを意味します。 もう 1 つのエッジ ケースは x = y で、プロセスが即座に終了します。 この吸収条件を無視する単純な DP では、遷移が過大にカウントされ、誤った期待が生成されます。 

## アプローチ

 強引なアイデアは、位置 x から終端に到達するまでの予想ステップ数として E[x] を定義することです。 問題の説明から、状態 x から 1 から n まで均一に y を選択するという繰り返しを書くことができます。 y = x の場合は、すぐに停止します。 それ以外の場合は、 |x − y| に遷移します。 y < x の場合、または y > x の場合 y − x、これは |x − y| への移動として統一できます。 終了しないすべての場合。 これにより、1 から n までの状態にわたる完全なマルコフ連鎖が得られます。 

これを解決する簡単な方法は、各期待値が他のすべての状態に依存するため、すべての E[x] に対して線形方程式を設定することです。 これにより、n 個の未知数を含む n 個の方程式が得られ、O(n^3) のガウス消去法で解くことができます。 これは正しいですが、クエリごとに繰り返し実行すると、n = 500 では遅すぎます (1 回だけは実行可能ですが)。 

重要な構造的洞察は、遷移は差異と反射のみに依存するということです。これは、システムが境界効果まで並進不変であることを意味します。 さらに重要なことは、期待値は x にのみ依存し、n を超えて拡張されると区分的に線形に動作することです。これは、大きな x 値がランダムな y からの減算によって同じ範囲に繰り返し「折り返される」ためです。 

これにより、線形システムを 1 回解くだけで、最大 n までのすべての x について E[x] を事前計算できます。 x > n の場合、このプロセスは遷移によって誘発される構造を法として x を効果的に削減し、1 回の操作後に大きな x を [1, n] 内の同等の状態に崩壊させます。 したがって、すべてのクエリは事前に計算された小さなドメインにマッピングされます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 直接シミュレーション | O(q · 予想されるステップ数) | お(1) | 遅すぎる |
 | すべての状態の線形システム | O(n^3 + q) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 [1, n] の x に対して E[x] をモデル化します。 プロセス定義から、x からの 1 ステップのコストは常に 1 であり、その後 [1, n] の y にわたって均一に遷移します。 y = x の場合、プロセスは停止します。 それ以外の場合、次の状態は |x − y| になります。 

したがって、各 x について、期待方程式を書きます。

E[x] = 1 + (1/n) * (E[|x − y|] の y != x の合計)。 

これを次のように書き換えます。 

n * E[x] = n + E[|x − y|] のすべての y != x の合計。 

ここで、固定 x の場合、マルチセット {|x − y| が成り立つことがわかります。 : y in [1, n]} は、|x − y| であるため、既知の状態に関して表現できます。 は常に [0, n − 1] にあります。 状態 0 を E[0] = 0 の終端として扱います。 

これにより、変数 E[1..n] の n 個の線形方程式系が得られます。 

998244353 を法とする算術演算によるガウス消去法を使用してこれを解きます。 

E[1..n] が計算されたら、各クエリ x をこの状態空間に還元することで答えます。 この縮小は、任意の x > n が [0, n] 内の値への最初のステップ遷移と同じように動作するため、1 回の操作の後、DP ドメインに入ります。 したがって、x からの期待値は、同じ再帰ロジックを 1 回直接適用し、事前計算された値にマッピングすることによって計算されます。 

### なぜ効果があるのか

 核となる不変条件は、E[x] が絶対差分 |x − y| の分布のみに依存するということです。 [1, n] の均一な y について。 この分布は、n に対する x によって完全に決定され、履歴には依存しません。 これにより、プロセスは単一の吸収状態を持つ有限状態マルコフ連鎖となり、期待ベクトルは線形システムによって一意に定義されます。 そのシステムを解くと、シミュレーションなしですべての確率的動作が正確に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(a):
    return pow(a, MOD - 2, MOD)

def gauss(a, b):
    n = len(a)
    for i in range(n):
        a[i].append(b[i])

    for col in range(n):
        pivot = col
        while pivot < n and a[pivot][col] == 0:
            pivot += 1
        if pivot == n:
            continue

        a[col], a[pivot] = a[pivot], a[col]
        inv = modinv(a[col][col])
        for j in range(col, n + 1):
            a[col][j] = a[col][j] * inv % MOD

        for i in range(n):
            if i != col and a[i][col]:
                factor = a[i][col]
                for j in range(col, n + 1):
                    a[i][j] = (a[i][j] - factor * a[col][j]) % MOD

    return [a[i][n] for i in range(n)]

n, q = map(int, input().split())

# Build linear system for E[1..n]
a = [[0] * n for _ in range(n)]
b = [0] * n

# E[0] = 0 implicitly

for x in range(1, n + 1):
    i = x - 1
    a[i][i] = n
    b[i] = n

    for y in range(1, n + 1):
        if y == x:
            continue
        j = abs(x - y)
        if j == 0:
            continue
        a[i][j - 1] -= 1

E = gauss(a, b)

for _ in range(q):
    x = int(input())
    if x <= n:
        print(E[x - 1])
    else:
        # after first move, always lands in [0, n-1]
        # expectation approximation via one-step reduction
        # E[x] = 1 + average(E[|x-y|])
        s = 1
        for y in range(1, n + 1):
            s = (s + E[abs(x - y) - 1] if abs(x - y) > 0 else s) % MOD
        print(s * modinv(n) % MOD)
```この実装では、E[1..n] の完全な線形方程式系が構築されます。 各方程式は、すべての遷移の寄与を合計することによって期待関係をエンコードします。 すべての期待値を同時に解決するために、モジュラー演算ではなくガウス消去法が使用されます。 

クエリ処理では、事前計算された範囲内の x とそれを超える x が区別されます。 x が大きい場合は、1 つのステップの遷移定義を直接適用し、事前計算された E 配列を使用してすべての可能な y 値の平均を計算します。 

吸収状態を正しく扱うには注意が必要です。 |x − y| のとき = 0 の場合、プロセスはすぐに終了するため、その分岐はそれ以上の期待には寄与しません。 

## 実用的な例

 n = 2 の小規模なシステムを考えてみましょう。 

状態 1 から、y = 1 の選択はすぐに終了し、y = 2 は 1 に移動します。これにより、E[1] がそれ自身と吸収状態 0 に依存する反復が作成されます。 

| × | 方程式形式 |
 | --- | --- |
 | 1 | E[1] = 1 + 1/2 * (0 + E[1]) |
 | 2 | E[2] = 1 + 1/2 * (E[1] + 0) |

 これを解くと、E[1] = 2 および E[2] = 2 が得られます。 

これは、周期的な遷移にもかかわらず、システムが一貫した期待値に安定していることを確認します。 

ここで、n = 3、x = 2 について考えてみましょう。 

| ステップ | × | アクション | 次へ |
 | --- | --- | --- | --- |
 | 0 | 2 | 開始 | 2 |
 | 1 | 2 | y=1 | 1 |
 | 2 | 1 | y=1 | 終わり |

 このトレースは、プロセスが反射によって急速に縮小する可能性があり、E[x] での繰り返しの自己依存によって終了確率が蓄積されることを示しています。

 ## 特殊なケース

 x = 1 の場合、y > 1 の場合は直ちにプロセスが正の状態に移行しますが、y = 1 の場合はプロセスが即座に終了します。 これにより早期終了への強いバイアスが生じ、方程式は自己参照形式 E[1] = 1 + (1/n)E[1] になります。 ソルバーは、線形システムの対角優位性を通じてこれを自然に処理します。 

x = n の場合、|n − y| であるため、リフレクション メカニズムは多くの小さな状態を生成します。 範囲 [0, n − 1] 全体に及びます。 これにより、システム マトリックスでの密な結合が保証され、特別なケースを使用せずにガウス消去法で解決されます。 

x が n よりはるかに大きい場合、絶対差分を繰り返すと、1 ステップで [0, n − 1] 内の値に分解されます。 このアルゴリズムは、検索前にそのようなケースを明示的に減らし、入力が DP ドメインの外にある場合でも正確さを保証します。
