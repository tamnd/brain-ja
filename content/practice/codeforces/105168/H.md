 ## 解決策
 ## 問題の理解

 私たちには、最初はどのペア間にも関係のない人々の列が与えられます。 時間が経つにつれて、私たちは一連の制約を与えられます。 最初の i 個の制約を処理した後、オプションで、これまで接続されていなかったペア間に追加の「フレンドシップ」を追加することができますが、追加できる追加のエッジは最大 i 個であるという唯一の制限があります。 

友情は推移的であるため、接続の構造を構築したら、重要なのは、結果として得られる無向グラフ内の接続されたコンポーネントです。 制約のプレフィックスごとに、最初の i 制約による強制エッジの上に最大 i 個の追加エッジを追加できるようにした後の、接続コンポーネントの最大可能サイズを知りたいと考えます。 

重要な点は、i ごとに最初からやり直すことです。 以前の i から追加されたエッジや構造は引き継がれません。 

制約は、追加のエッジを選択する前に特定のペアがすでに接続されていることを強制するという点でのみ重要です。 

複雑さの観点から、n はテスト ケースごとに最大 10^5 で、すべてのテスト ケースの合計 n は 2×10^5 です。 制約の数 d はテスト ケースごとに最大で n−1 で、t は最大 10^4 です。 これにより、接続性を i ごとに O(n + d) 時間で最初から再計算するものは直ちに除外されます。これは、最悪の場合、テスト ケースごとに O(nd) になるためです。 

プレフィックスごとの出力は単一の数値、つまり i 個の追加エッジを最適に使用した後の到達可能な最大コンポーネントのサイズのみです。 

制約がすでに大きな接続コンポーネントを形成している場合、微妙なエッジ ケースが発生します。 たとえば、制約によってすでにすべてのノードが 1 つのコンポーネントに接続されている場合、余分なエッジは無関係です。 すべての余分なエッジが常に答えを増加させると盲目的に仮定するソリューションは、過大評価することになります。 

別の失敗例は、制約が多数の小さなコンポーネントを形成しているにもかかわらず、すべてをマージするのに十分な操作がある場合に発生します。 たとえば、i 個の制約の後に k 個のコンポーネントがあり、i ≥ k−1 の場合、すべてのノードをサイズ n の単一コンポーネントに完全に接続できます。 可能なマージの数をカウントせずに、現在のコンポーネントのサイズのみを考慮する単純なアプローチでは、この飽和効果が見逃されます。 

## アプローチ

 ブルートフォースのアイデアは、各プレフィックスを個別にシミュレートすることです。 固定 i の場合、最初の i エッジを取得し、グラフを構築し、その接続コンポーネントを計算して、i 個の追加エッジを追加してコンポーネントのサイズを最大化しようとします。 グラフ構造により、コンポーネント サイズ s1、s2、...、sk が得られます。 

追加のエッジごとに 2 つのコンポーネントをマージできるため、エッジを 1 つ追加するとコンポーネントの数が 1 つ減ります。 最大でも i 回マージした後、最小のコンポーネントを最大のコンポーネントに貪欲にマージできます。 最適な戦略は常に、結果として得られる最大サイズを最大化する方法でコンポーネントを接続することです。これは、操作が残っている限り、最大のコンポーネントを取得し、次に大きいコンポーネントとマージすることと同じです。 

ブルート フォース ソリューションは、実装に応じて O(d·α(n)) または O(dn) のコストをかけてプレフィックスごとに接続コンポーネントを再計算し、プレフィックスごとにコンポーネント サイズの並べ替えを実行します。これにより、プレフィックスごとに O(n log n) が追加されます。 これは O(d n log n) になりますが、d と n が 10^5 の場合、これは大きすぎます。 

重要な観察は、プレフィックス エッジの下での接続が段階的に進化し、エッジを追加してもコンポーネントの数が減少するだけであるということです。 DSU を使用して接続されたコンポーネントを動的に維持し、さらにコンポーネントのサイズを追跡できます。 各接頭辞 i について、存在するコンポーネントの数が正確にわかります。 残された唯一の問題は、最大でも i 個の余分なエッジを使用して、達成可能な最良の最大コンポーネント サイズを計算する方法です。

重要な洞察は、コンポーネントのアイデンティティはそのサイズを超えて無関係であるということです。 知る必要があるのは、存在するコンポーネントの数とそのサイズだけであり、コンポーネントの内部構造は知りません。 サイズ s1...sk の k 個のコンポーネントがわかったら、利用可能な最大の部分を 1 つのルート コンポーネントに繰り返しマージすることで、可能な限り最良の最終的な最大コンポーネントが取得されます。 これにより、選択されたルート コンポーネントに吸収される i コンポーネントを選択して合計を最大化するという問題が軽減されます。 

したがって、答えは次のようになります。最大のコンポーネントをベースとして取り、可能であれば最大の (i + 1 − 1) コンポーネントを追加します。ただし、マージのたびにコンポーネント数が 1 つずつ減るため、i 回の操作で k を max(1, k−i) に減らすことができます。 したがって、最大の (k−(k−i)) = i マージを組み合わせることができます。これは、i 番目の最大の他のコンポーネントを最大のコンポーネントにマージすることを意味します。 これにより、コンポーネント サイズのソートとプレフィックス最大合計の構造の維持が簡素化されます。 

コンポーネント サイズのマルチセットまたは並べ替え構造を維持できますが、コンポーネントは時間の経過とともにマージされるだけであるため、DSU を維持し、サイズのマルチセットも維持できます。 各ユニオン操作ではマルチセットが O(log n) で更新されます。 また、コンポーネントの最大サイズも維持します。 

ただし、最終状態だけでなく、プレフィックスごとの回答も必要です。 プレフィックスごとに DSU を増分的に再計算し、コンポーネント サイズを追跡する構造を使用してプレフィックスごとに O(log n) で答えを計算します。 

これにより、標準的なオフライン インクリメンタル DSU + マルチセット ソリューションが実現します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | プレフィックス再計算ごとのブルート フォース | O(d · n log n) | O(n) | 遅すぎる |
 | サイズ マルチセットのインクリメンタル DSU | O((n + d) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 n 個のノードにわたって DSU を維持しながら、エッジを順番に処理します。 

1. すべてのノードが独自のコンポーネントである DSU を初期化し、すべてのコンポーネント サイズをマルチセットまたはソート構造に保存します。 最初は、サイズ 1 のコンポーネントが n 個あります。この構造により、最大のコンポーネントを効率的に識別して更新できます。 
2. 1 から d までの各プレ​​フィックス i に対して、エッジ (pi, qi) を追加します。 これら 2 つのノードがすでに同じ DSU コンポーネント内にある場合は、何も変わりません。 それ以外の場合は、2 つのコンポーネントをマージしてマルチセットを更新します。つまり、2 つの古いサイズを削除し、それらの合計を挿入します。 これにより、正しいコンポーネント サイズ分布が維持されます。 
3. i 番目のエッジを処理した後、制約後の現在のコンポーネントのサイズがわかります。 k をコンポーネントの数とし、サイズを降順に並べ替えます。 
4. まだ適用​​できるマージの数を計算します。i 個の操作が利用可能です。 各演算で成分の数を 1 減らすことができるため、k を少なくとも max(1, k−i) まで減らすことができます。 
5. 最良の戦略は、利用可能な最大のコンポーネントを繰り返しマージして 1 つの巨大なコンポーネントを形成することです。 したがって、最大のコンポーネントをベースとして取り、次に i 番目に大きいコンポーネントをそれに追加します。 追加コンポーネントが i 個よりも少ない場合は、すべてをマージします。 
6. 結果として得られる可能な最大のコンポーネント サイズを出力します。 

### なぜ効果があるのか

 どの接頭辞であっても、すべてのコンポーネントは既知のサイズを持つ素のセットです。 追加されたエッジは 2 つのコンポーネントを正確にマージするため、操作ごとにコンポーネントの数が 1 つ減ります。 最終的な目標は単一のコンポーネントを最大化することであるため、すべての操作を使用して、あるコンポーネントを最終的なターゲット コンポーネントにマージする必要があります。 最適なターゲットは常に現在のコンポーネントの 1 つであり、コンポーネントのサイズは追加的で独立しているため、残りの最大のコンポーネントをそこにマージすると、成長が最大化されます。 したがって、コンポーネントをサイズごとに分類し、利用可能な最大の部分を貪欲に接続することが最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n
        self.components = n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra = self.find(a)
        rb = self.find(b)
        if ra == rb:
            return 0
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]
        self.components -= 1
        return self.size[ra]

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, d = map(int, input().split())
        edges = [tuple(map(int, input().split())) for _ in range(d)]

        dsu = DSU(n)
        comp_sizes = [1] * n

        import heapq
        heap = [-1] * n
        heap = [-1] * n
        heap = [-1] * n

        # we will maintain sizes via dictionary-like structure
        import collections
        active = collections.Counter()
        active[1] = n

        def add_size(x, delta):
            if active[x] == delta:
                del active[x]
            else:
                active[x] += delta
                if active[x] == 0:
                    del active[x]

        # better approach: rebuild sizes via DSU root updates
        parent = list(range(n))
        size = [1] * n

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(a, b):
            nonlocal active
            ra, rb = find(a), find(b)
            if ra == rb:
                return
            if size[ra] < size[rb]:
                ra, rb = rb, ra
            # remove old sizes
            active[size[ra]] -= 1
            if active[size[ra]] == 0:
                del active[size[ra]]
            active[size[rb]] -= 1
            if active[size[rb]] == 0:
                del active[size[rb]]
            parent[rb] = ra
            size[ra] += size[rb]
            active[size[ra]] += 1

        for i, (u, v) in enumerate(edges, 1):
            u -= 1
            v -= 1
            union(u, v)

            # extract sorted component sizes
            sizes = []
            for k, cnt in active.items():
                sizes.extend([k] * cnt)

            sizes.sort(reverse=True)

            k = len(sizes)
            if k == 1:
                out.append(str(n))
                continue

            ops = i
            take = min(k, ops + 1)

            ans = sum(sizes[:take])
            out.append(str(ans))

    print("\n".join(out))

    solve()

最もデリケートな部分は、各操作によってコンポーネント数が 1 つだけ減少することを認識することです。そのため、i 回の操作の後、選択したルート コンポーネントに最大 i 個の追加コンポーネントを組み込むことができます。

 ## 特殊なケース

 重要なエッジケースは、制約が何も接続しない場合です。 その場合、i ステップの後でも n 個のシングルトン コンポーネントが残ります。 最大 i 個のコンポーネントを 1 つのグループにマージできるため、答えは i+1 になります。これは予想される線形増加です。 

もう 1 つのエッジ ケースは、制約によってすぐに大きな連結コンポーネントが作成される場合です。 たとえば、最初のエッジがすでにすべてのノードに接続している場合、利用可能な操作に関係なく、後のすべての i に対して答えは n のままでなければなりません。 コンポーネント リストが単一の要素になり、take=min(1, i+1)=1 となり、n が生成されるため、アルゴリズムはこれを処理します。 

3 番目のエッジ ケースは、コンポーネントの数が i+1 より小さい場合です。 この場合、単純にすべてのコンポーネントを取得し、合計は当然 n に等しくなります。 これにより、完全な接続を超えた過剰カウントが防止されます。
