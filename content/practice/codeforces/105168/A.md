 ## 解決策
 ## 問題の理解

 一連のクエリが与えられます。各クエリは、「今日」が何曜日であるかを示し、1 から 7 の整数としてエンコードされます。マッピングは固定されています。1 は月曜日に対応し、2 は火曜日に対応し、7 が日曜日に対応するまで同様に続きます。 各クエリについて、週次サイクルで直前の曜日を出力する必要があります。 

構造は円形で、日曜日の後にまた月曜日が来ることを意味します。 したがって、任意の日から 1 歩後ろに移動すると、数値が 1 つ減るか、1 から 7 に戻ります。 

入力サイズは最大 200,000 のテスト ケースに達する可能性があり、クエリごとに非定常な作業を行うものは即座に除外されます。 テスト ケースごとに O(1) の計算が必要です。そうしないと、ソリューションがタイムアウトになる危険があります。 各クエリは独立しているため、マッピングを理解する以外に必要な状態の共有や前処理はありません。 

唯一微妙なエッジケースは月曜日からの折り返しだ。 今日が 1 (月曜日) だとすると、昨日は 0 ではなく 7 (日曜日) になります。 この境界を処理しない単純な減算アプローチでは、警告なしに無効な出力が生成されます。 

たとえば、入力が 1 の場合、不用意に実装すると、有効範囲外の 1 - 1 = 0 が計算される可能性があります。 正解は 7 です。 

## アプローチ

 ブルートフォース解釈では、各クエリは前の要素が見つかるまで週のリストをたどるものとして扱われます。 シーケンスを明示的に保存できます`[1, 2, 3, 4, 5, 6, 7]`そして、クエリごとに、先行クエリが見つかるまで、指定された位置から逆方向にスキャンします。 これが機能するのは、構造が小さく固定されているため、正確さが重要ではないためです。 

ただし、週のサイズが一定であっても、クエリごとにループを使用するブルート フォース実装は不要なオーバーヘッドです。 さらに重要なのは、これが意図したパターンにうまく一般化されていないことです。つまり、1 週間はモジュール化されたサイクルです。 重要な観察は、問題は単に 1 を減算してラップアラウンドするモジュロ 7 サイクルでの算術であるということです。 

これにより、各クエリが定数時間の変換に削減されます。`(w - 2) % 7 + 1`。 この式は、1 ～ 7 のインデックスを 0 ～ 6 システムにシフトし、安全な減分を適用して、それを逆変換します。 あるいは、境界を明示的に処理することもできます。`w == 1`、出力`7`、それ以外の場合は出力`w - 1`。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 各テスト ケースは独立しているため、順番に処理します。 
2. 入力値ごとに`w`、それが 1 に等しいかどうかを確認します。週は月曜日から日曜日まで逆方向に循環するため、これは唯一の特殊なケースです。 
3. もし`w == 1`、出力 7。これは、カレンダー サイクルのラップアラウンド動作を直接エンコードします。 
4. それ以外の場合は出力`w - 1`。 これにより、他のすべての遷移が一定時間で処理されます。 

### なぜ効果があるのか

 日はサイズ 7 の閉じたサイクルを形成し、毎日の前日が 1 つだけ存在します。 1 を減算すると、表現が線形性を破る境界を除いて、このサイクルに沿って逆方向に移動します。 明示的な修正は、`w = 1`周期構造を元に戻します。 すべての有効な入力が正確に 1 つの先行入力にマップされ、競合する出力を共有する 2 つの入力がないため、変換は完全で一貫性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        w = int(input())
        if w == 1:
            out.append("7")
        else:
            out.append(str(w - 1))
    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```実装では、繰り返しの I/O オーバーヘッドを回避するために、すべてのクエリを読み取り、出力をリストに保存します。 各クエリは単一の条件チェックで処理され、一定時間の処理が保証されます。 

Python I/O は 200,000 操作でボトルネックになる可能性があるため、重要な実装の詳細はループ内での直接印刷を避けることだけです。 結果を蓄積して一度書き込むことで、予測可能なパフォーマンスが保証されます。

 ## 特殊なケース

 唯一の意味のあるエッジ ケースは、月曜日の循環境界です。 

入力：```
1
1
```ここ`w = 1`したがって、アルゴリズムは特別な分岐を選択して出力します。`7`。 小切手`w == 1`すぐにトリガーされるため、算術減算は試行されません。 

2 番目の境界チェックの場合:

 入力:```
1
2
```以来`w != 1`、アルゴリズムの出力`2 - 1 = 1`。 これにより、非境界値が均一に動作し、減分ルールを超える特別な処理が必要ないことが確認されます。 

これら 2 つのケースを合わせて、遷移関数が 7 日システムにわたる完全な周期的な先行関係を正しくモデル化していることを検証します。
