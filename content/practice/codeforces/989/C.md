 ## 解決策
 ## 問題の理解

 長方形のグリッドを作成し、その中に花の種類を表す 4 つの文字を入力するように求められます。 グリッドは、各文字を個別に見て、エッジ隣接性を使用して接続されたコンポーネントを数えたときに、4 つの文字のコンポーネントの数が指定されたターゲットと一致するように設計する必要があります。$a, b, c, d$。 

ここでの連結コンポーネントとは、その文字から離れることなく上下左右のステップを使用してセル間を移動できる、同じ文字のセルの最大セットを意味します。 

重要な自由は、グリッド サイズが与えられていないことです。 どれでも選べます$n, m \le 50$を選択し、それに応じてグリッドをデザインします。 

制約は十分小さいため、計算の複雑さを心配する必要はありませんが、解決策が検索ベースではなく建設的であることを強く示唆しています。 グリッドをランダムに生成してコンポーネントの数をテストする強引な試みは、接続がグローバルであり、ローカルな小さな変更によってコンポーネントが予期せずマージまたは分割される可能性があるため、信頼性が低くなります。 

素朴な考えは、$a$別々の A 領域、$b$個別の B 領域など、それぞれを小さなブロックとして扱います。 直接的な失敗例は、同じ文字の 2 つのブロックが角や端でも接触すると、それらが 1 つのコンポーネントにマージされ、カウントが誤って減少することです。 たとえば、2 つの単一 A セルを$(1,1)$そして$(1,2)$2 つのコンポーネントをただちに 1 つに折りたたみます。 

したがって、最も難しいのはセルを配置することではなく、出現するすべての文字が独立したコンポーネントのままであることを保証することです。 

## アプローチ

 強引な考え方は、これを配置の問題として扱うことです。$a+b+c+d$グリッド上のラベル付きセルをバックトラックして、同じ文字が 2 つ隣接しないようにします。 各配置決定が非ローカルな方法で将来の配置を制約するため、これはすぐに組み合わせになります。 上でも$50 \times 50$グリッドの場合、単純なバックトラッキングでは指数関数的な数の部分構成を探索することになります。 

重要な観察は、同じ文字の 2 つのセルが決して隣接しないようにグリッドを設計することで、接続性の問題を完全に排除できるということです。 これが当てはまる場合、すべてのセルは自動的に独自の連結成分となり、成分数は文字が出現する回数とまったく同じになります。 

これにより、問題は接続構築の問題から単純なカウントと配置の問題に縮小されます。単に正確に割り当てるだけで済みます。$a$セルをAに、$b$セルを B に、などと同様に、同一の文字に対する隣接性の競合が発生しないようにします。 

これを構造的に保証するために、制御されたセルの分割内で隣接性が決して発生しないグリッドを事前に構築できます。 これを実現する標準的な方法は、繰り返しを使用することです。$2 \times 2$パターン。 次のように定義される 4 つのパリティ クラスのそれぞれ$(i \bmod 2, j \bmod 2)$エッジ隣接する 2 つのセルがないセルのセットを形成します。 これはチェス盤の色付けよりも強力です。各クラス自体がグリッド グラフ内の独立したセットです。 

このような独立したセットが 4 つあれば、各文字を 1 つのクラスに割り当て、そのクラスから必要な数のセルを選択するだけです。 各クラスの$50 \times 50$グリッドには 625 個のセルがあり、各要件は最大 100 個であり、容量が問題になることはありません。

 ## アルゴリズムのチュートリアル

 グリッドのサイズを次のように固定します。$50 \times 50$。 これは、制約を尊重しながら、すべての要件を快適に満たすのに十分な大きさです。 

1. すべてのセルを座標に基づいて 4 つのグループに分割します。$(i \bmod 2, j \bmod 2)$。 これにより、4 つの素なセルのセットが作成されます。 各セットには、その中の 2 つのセルがエッジを共有しないという特性があります。 これは、接続に関する懸念を取り除く構造的な保証です。 
2. A、B、C、D の 4 つの文字のそれぞれを、これらのパリティ クラスのいずれかと関連付けます。 すべてのクラスには十分な定員があるため、割り当ては任意で構いません。 
3. 各文字について、割り当てられたクラスから最初に必要な数の位置を取得し、それらのセルに文字を入力します。 クラス内のすべてのセルは同じクラス内の他のすべてのセルから分離されているため、塗りつぶされた各セルは単一の連結成分になります。 
4. 残りのすべてのセルを任意に、たとえば任意の文字で埋めますが、偶発的なマージを避けるために、同じパリティベースの構造を尊重し続け、残ったセルをクラス内で一貫して分散することが最も簡単です。 

これが機能する理由は、同じパリティ クラスの 2 つのセルがエッジ隣接しないという不変条件に帰着します。 同じクラス内の 2 つの隣接するセルに文字を配置することは決してないため、文字の出現はすべて分離されます。 したがって、各文字の接続コンポーネントの数は、それを配置した回数とまったく同じになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c, d = map(int, input().split())

    n, m = 50, 50
    grid = [['A'] * m for _ in range(n)]

    # four parity classes
    classes = [[] for _ in range(4)]
    for i in range(n):
        for j in range(m):
            classes[(i % 2) * 2 + (j % 2)].append((i, j))

    req = [('A', a), ('B', b), ('C', c), ('D', d)]

    idx = 0
    for ch, cnt in req:
        cells = classes[idx]
        for k in range(cnt):
            i, j = cells[k]
            grid[i][j] = ch
        idx += 1

    print(n, m)
    for row in grid:
        print(''.join(row))

if __name__ == "__main__":
    solve()
```実装は、$50 \times 50$グリッドを作成し、4 つのパリティ クラスを事前計算します。 各クラスは、グリッド グラフ内で相互に隣接しないことが保証されている座標のリストです。 

次に、各文字を 1 つのクラスに割り当て、そのクラスから必要な数のセルを正確に入力します。 クラスの規模が大きいため、ポジションが不足することはありません。 

重要な点は、クラス内で文字を決して混在させないことです。 混合すると隣接性制約が再び導入され、コンポーネントが意図せずマージされる可能性があります。 

## 実用的な例

 サンプル入力を検討してください$5, 3, 2, 1$。 私たちはまだ$50 \times 50$ただし、最初に選択された 11 個の位置のみが重要です。 

| ステップ | 配置された | B を配置 | C を配置 | D 配置 |
 | --- | --- | --- | --- | --- |
 | 開始 | 0 | 0 | 0 | 0 |
 | Aの後 | 5 | 0 | 0 | 0 |
 | B後 | 5 | 3 | 0 | 0 |
 | Cの後 | 5 | 3 | 2 | 0 |
 | D後 | 5 | 3 | 2 | 1 |

 各配置は異なる独立したセット内で発生するため、文字内に隣接関係が現れることはありません。 

ここで次のような場合を考えてみましょう$1, 1, 1, 1$。 各文字は、それぞれのパリティ クラスで単一の分離セルを取得するため、4 つのコンポーネントすべてが自明のことながらシングルトンになります。 未使用のセルは使用済みセルの接続に影響を与えないため、グリッドは依然として完全に有効なままです。 

これらのトレースは、アルゴリズムの動作がカウントのみに依存し、パリティ分離を超えるジオメトリには依存しないことを示しています。

 ## 特殊なケース

 主なエッジケースは、たとえば、1 つの色が大きく優勢な場合です。$a=100$単純な配置戦略は、多くの同じ色のセルを小さな領域に詰め込もうとし、誤ってそれらをマージしようとするため、ここで失敗することがよくあります。 この構造では、すべての A セルが独立したパリティ クラス内に存在するため、100 個の A セルがあっても 100 個の個別のコンポーネントのままになります。 

もう 1 つのケースは、すべての値が等しい場合です。 貪欲に行を埋めるアプローチでは、誤って長い水平チェーンが作成され、コンポーネントが結合されてしまいます。 ここで、クラス内では隣接は構造的に不可能であるため、平等性は正しさに影響を与えません。 

最後に、すべての値が最大になると、$100,100,100,100$、タイトなグリッド構造では、スペースが不足したり、隣接が強制されたりする危険があります。 固定された$50 \times 50$レイアウトにより、各独立したセットで十分な容量が保証されるため、最悪の場合でも安全に対応できます。
