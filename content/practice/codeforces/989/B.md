 ## 問題の理解

 長さの文字列が与えられます$n$固定ゼロ、固定 1、およびワイルドカード ドットの 3 種類の文字で構成されます。 各ドットは独立して 0 または 1 のいずれかになります。すべてのドットを置き換えると、完全に具体的なバイナリ文字列が得られます。 

整数も与えられます$p$。 文字列にはピリオドがあると言われます$p$すべての文字がその位置にあるとき$i$位置の文字と一致します$i+p$、両方の位置が存在する場合は常に。 つまり、文字列を次のようにシフトすると、$p$比較が定義されている位置では変更されません。 

ここでのタスクは、結果の文字列にピリオドが含まれないように、すべてのドットに値を割り当てることができるかどうかを判断することです。$p$。 可能であれば、そのような割り当てを 1 つ作成する必要があります。 それ以外の場合は、不可能であることを報告する必要があります。 

制約$n \le 2000$と提案する$O(n^2)$推論は安全です。 構築試行ごとに線形または線形に近いものは許容されますが、全体にわたって指数関数的に列挙されます。$2^{\#dots}$ドットの数が大きくなる可能性があるため、割り当ては実行できません。 

既知の文字によって強制された構造によってピリオドのすべての比較がすでに決定されている場合、微妙な失敗例が発生します。$p$。 たとえば、すべてのポジションの場合、$i$そして$i+p$比較できるものが固定文字によってすでに一致している場合、ドットによって不一致が生じることはなく、答えは「いいえ」でなければなりません。 逆に、自由なペアが 1 つでもあれば、ミスマッチを強制することができます。 

## アプローチ

 直接的な総当たりの解決策では、ドットのすべての割り当てを試し、文字列を埋め、ピリオドかどうかを確認します。$p$が成立する。 単一の割り当てのコストを確認する$O(n)$、そして、あります$2^k$割り当て$k$ドットの数です。 これは中程度の人でもすぐに実行不可能になります$k$、 以来$n$最大 2000 まで可能です。 

重要な観察は、すべての割り当てをグローバルに推論する必要はないということです。 期間の条件$p$純粋にローカルです: ペアのみを比較します$(i, i+p)$。 このようなペアに不一致が生じた場合、その文字列は直ちに周期的ではなくなります。 

これは建設的なアプローチを示唆しています。 まず、既知の文字によって課される強制的な制約をすべて満たそうとします。 ドットが既知の値とペアになっている場合、周期性が必要な場合はその値と一致する必要があります。 両方が既知で矛盾する場合、周期性はすでに不可能であり、作業は完了です。 強制伝播を解決した後、ペアがあるかどうかを確認します$(i, i+p)$ここで、両方の位置は自由であるか、異なる位置にすることができます。 このようなペアが存在する場合、値を明示的に割り当てて周期性を破ることができます。 それ以外の場合、すべてのペアが等しく固定され、周期性に違反することができなくなります。 

最終的な構築では、すべての割り当てを検討するのではなく、対象を絞った「1 つの制約を破る」戦略になります。

 ## アルゴリズムのチュートリアル

 ポジション間の制約という観点から考えます$i$そして$i+p$。 文字列が周期的である場合、そのような各ペアは等価性を強制します。 

1. すべてのインデックスを反復処理します。$i$から$1$に$n-p$。 各ペアごとに$(i, i+p)$、2 つの文字を調べます。 
2. 両方の文字が固定で異なる場合 (一方は 0、もう一方は 1)、ドットをどのように埋めるかに関係なく、周期性はすでに不可能です。 この場合、文字列の補完を安全に出力できます。 
3. それ以外の場合、少なくとも一方の辺がドットであるか、両方が等しい場合、このペアは周期性を自動的に破るのに役立ちません。 すべてのペアのチェックを続けます。 
4. ペアを見つけたら$(i, i+p)$少なくとも 1 つの位置がドットで、もう 1 つの位置が既知であるかドットである場合、強制的に不一致を試みます。次のようにドットを割り当てます。$s[i] \ne s[i+p]$。 
5. 有効な答えを作成するには、まず文字列をコピーし、残りのドットを任意に (たとえば 0 に) 置き換えます。次に、選択したペアの 1 つを、片側を反転して明示的に強制的に相違させます。 
6. 不一致を引き起こす可能性のあるそのようなペアが存在しない場合、それはすべてのペアがすでに等しく固定されているか、等価性を強制する方法で完全に決定されていることを意味します。 この場合、どの構造も周期性を壊すことはできないため、「いいえ」を出力します。 

### なぜ効果があるのか

 文字列にはピリオドが付いています$p$すべてのインデックス ペアがいつ$(i, i+p)$一致します。 これらのペアは独立した制約を形成します。 どの位置も、そのシフトされたリンクの外側にあるペアと相互作用しません。 これは、周期性を破るには、これらの制約の少なくとも 1 つを破る必要があることを意味します。 

すべてのペアがすでに固定文字によって強制的に等しくされている場合、ドットは他の場所で固定制約に違反することなく不一致を引き起こすことはできません。 逆に、まだ柔軟性のあるペアが少なくとも 1 つ存在する場合は、各位置が違反に重要な 1 つの比較方向のみに関与するため、他のペアに影響を与えることなくローカルに値を割り当てて不一致を作成できます。 

したがって、有効な非周期補完を構築するには、単一の「柔軟なペア」の存在が必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, p = map(int, input().split())
    s = list(input().strip())

    # try to force a mismatch in any (i, i+p) pair
    for i in range(n - p):
        j = i + p

        if s[i] != '.' and s[j] != '.' and s[i] != s[j]:
            # already broken periodicity, just fill dots arbitrarily
            for k in range(n):
                if s[k] == '.':
                    s[k] = '0'
            print("".join(s))
            return

    # build a baseline valid fill
    t = s[:]
    for i in range(n):
        if t[i] == '.':
            t[i] = '0'

    # try to introduce a mismatch in some pair
    for i in range(n - p):
        j = i + p
        if s[i] == '.' or s[j] == '.':
            t[i] = '0'
            t[j] = '1'
            print("".join(t))
            return

    print("No")

if __name__ == "__main__":
    solve()
```最初のループは、固定入力ですでに矛盾しているペアをスキャンします。 そのようなペアが存在する場合、周期性はすでに不可能であるため、処理はすぐに完了します。 必要なのはドットを一貫して解決することだけです。 

2 番目のフェーズでは、すべてのドットをゼロに置き換えることによって、完全に具体的なベースライン文字列を構築します。 これにより、変更する有効な周期候補構造が得られます。 

3 番目のフェーズでは、少なくとも 1 つの柔軟なポジションを含むペアに意図的な不一致を導入しようとします。 各位置はそれ自身の位置によってのみ拘束されるため、両方の位置を変更しても安全です。$i$そして$i+p$この関係では、違反した比較が 1 つだけ必要になります。 

最後の「いいえ」のケースは、すべてのペアが完全に固定され、一貫性があり、平等を破る方法がない場合にのみ発生します。

 ## 特殊なケース

 すでに周期性を満たしている完全に固定された文字列の場合、答えは「いいえ」となります。 そんな時はペアごとに$(i, i+p)$はすでに等しく、不一致を引き起こすドットは存在しません。 アルゴリズムは最後の分岐に到達し、要件に一致する「いいえ」を出力します。 

クリティカル ペアのすべての位置がドットである場合、構築ステップではそれらにそれぞれ 0 と 1 を割り当てます。 これらの位置はオフセット ペアに対してのみチェックされるため、他の制約を妨げることなく、壊れた周期性が保証されます。 

文字列全体にドットが 1 つだけ存在する場合、それがいずれかのペアに出現すれば常に十分です。$(i, i+p)$。 アルゴリズムはスキャン中にこれを検出し、それをブレークポイントとして使用し、最小限の変動シナリオでも正確性を保証します。
