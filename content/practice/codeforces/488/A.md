 ## 解決策
 ## 問題の理解

 私たちは、ゼロをはるかに下回り、ゼロをはるかに上回る巨大な塔の整数の階数に立っています。 現在のフロアから$a$、上方向にのみ移動できます。つまり、正の整数を繰り返し加算します。 目標は、最小の前向きな一歩を見つけることです$b$床が$a + b$10 進数表現に少なくとも 1 つの数字 8 が含まれています。 

したがって、タスクはフロアを自由に検索するのではなく、固定点から開始して、10 進数に 8 が含まれる最初の数字に到達するまで厳密に上に移動することです。 

入力制約$|a| \le 10^9$これは、開始点が十分に小さいため、オーバーフローや非常に大きな反復回数を心配することなく、上向きの動きを安全にシミュレートできることを意味します。 最悪の場合、幸運な数字に遭遇するまで数字をチェックする必要があるかもしれませんが、「幸運」は算術サイズではなく数字の構造に依存するため、そのような数字の密度は単純なスキャンが制限内に合格するのに十分です。 

主な微妙なエッジケースは、次の要件です。$b$厳密に正である必要があります。 開始番号にすでに 8 が含まれている場合でも、0 を出力することはできません。 たとえば、次の場合$a = 8$、まだ 9 以降まで上に移動する必要があり、8 がすでに「幸運」であるにもかかわらず、答えは少なくとも 1 です。 

79 → 80 や 799 → 800 のように桁の境界を越えるときに、別のエッジ状況が現れます。幸運な数字はまばらであるという単純な頭の仮定は考えすぎにつながる可能性がありますが、実際には各整数を順番にチェックするだけです。 

## アプローチ

 直接的な解決策は、開始階から上に向かって歩くことをシミュレートすることです。 ステップごとに、現在のフロアをインクリメントし、その 10 進表現に数字 8 が含まれているかどうかを確認します。初めてこの条件が成立した場合、移動距離を返します。 

このアプローチは文字通り定義に従うため、正しいです。正の最小オフセットが求められ、整数を昇順でチェックすることで、最初の有効な遭遇が最適であることが保証されます。 

強引な性質は明らかですが、ここでは無害でもあります。 最悪の場合、幸運な数字が非常にまれな場合は、広い範囲をスキャンする可能性があります。 ただし、数字 8 を含む数値は頻繁に出現するため、予想されるチェック数は少なく、最悪の場合の動作であっても、サイズ 10 のブロック内では範囲内の各位置にすべての数字が出現するという事実によって制限されます。 

すべての有効な数値を数えたり構築したりするのではなく、単一点から前方に検索するだけであるため、数字 DP のような高度な最適化は必要ありません。 

重要な単純化は、問題が純粋に逐次的なものであることを認識することです。「この数字に 8 が含まれるかどうか」以外の構造について推論する必要はありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(k · d) ここで、k は次のラッキーナンバーまでの距離です。 お(1) | 承認済み |
 | 最適 | O(k・d) | お(1) | 承認済み |

 ここ$d$は桁数で、最大 10 です。 

## アルゴリズムのチュートリアル

 1. 指定されたフロアから開始します$a$。 厳密にそれ以上のフロアを探索します$a$、 以来$b$ポジティブである必要があります。 
2. カウンタの初期化$b = 0$、どれだけ上に移動したかを表します。 
3. 現在のフロアとカウンタの両方を繰り返しインクリメントします。$a + b$に$a + b + 1$、その後増加します$b$これにより、常に次のフロアを昇順にチェックすることが保証されます。 
4. 新しい下限値ごとに、それを文字列に変換し、その桁をスキャンして、「8」に等しい桁があるかどうかを確認します。 文字列変換を行う理由は、この制約では数字の抽出が最も簡単で定数因数効率が良いためです。 
5. 数字の 8 が見つかった場合は、すぐに停止して出力します。$b$, ラッキーフロアに到達するのは初めてなので。 順序付けにより最小性が保証されます。 

### なぜ効果があるのか

 整数を厳密に昇順にスキャンしています。$a+1$。 すべての候補フロアが 1 回だけチェックされ、「数字 8 を含む」という条件を満たす最初のフロアで停止します。 検索空間は完全に順序付けされており、単調に進むため、最初のヒットは最小の正の距離に対応する必要があります。 スキップされた値は、より小さい有効値を生成することはできません$b$したがって、正確さは順序付けられた列挙から直接得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

a = int(input().strip())

b = 0
while True:
    b += 1
    x = a + b
    if '8' in str(x):
        print(b)
        break
```コードはアルゴリズムに正確に従います。 の正性を確保する必要があるため、ループは 1 から始まります。$b$。 反復ごとに 1 フロア上に移動し、すぐに桁の状態をチェックします。 

変換`str(x)`数値が妥当な範囲内にとどまるため、安全です。 条件`'8' in str(x)`これは、手動で数字を抽出せずに数字の存在をテストする最も簡単な方法です。 

最初の有効な数値が見つかるとすぐにループが終了するため、答えを超えて不必要な計算は実行されません。

def run(inp: str) -> str:

    input = sys.stdin.readline

## 特殊なケース

 重要なエッジ ケースの 1 つは、開始番号にすでに数字 8 が含まれている場合です。$a = 8$、アルゴリズムは次から始まります$b = 1$、小切手$9$、そして前進だけを続けます。 8自体は幸運なのに、到達できないのは、$b$ポジティブである必要があります。 最初の有効な出力は次のとおりです。$b = 1$9 には 8 が含まれていませんが、18 が後で出現するためです。 ただし、実際の最初の値は 18 です。$b = 10$。 ループは考慮しないため、これを自然に処理します。$a$自体。 

もう 1 つの特殊なケースは、負の開始値です。 例えば、$a = -1$。 シーケンスは進みます$-1, 0, 1, 2, \dots$数値チェックはマイナス記号を含む絶対文字列表現に適用されるため、アルゴリズムは符号を特別に扱いませんが、「-」は無視されるためです。`'8' in str(x)'`、正確性は保たれます。 

最後の微妙なケースは、79 から 80 へ、そして 81 のように桁の境界を越える場合です。この方法は算術パターンに依存しないため、桁の変更がどこで発生するかは問題ではありません。 すべての整数は個別にチェックされるため、幸運な数字をスキップすることはできません。
