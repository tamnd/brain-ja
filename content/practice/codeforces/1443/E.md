 ## 解決策
 ## 問題の理解

 1 から 1 までの整数の初期順列が与えられます。$n$順番に。 クエリは、現在の順列の部分配列内の要素の合計を求めるか、指定された数の次の順列ステップだけ順列を進めるかを要求します。 課題は、$n$そしてクエリの数$q$どちらも次のように大きくすることができます$2 \cdot 10^5$、各順列の変更には、最大で次の更新が必要になる場合があります。$n$要素。 各ステップの後に順列を明示的に計算する単純なアプローチでは、非常に時間がかかり、パフォーマンスが低下する可能性があります。$O(n \cdot q)$到達できる操作$4 \cdot 10^{10}$。 

微妙な点は、次の順列演算は、最も長い減少尾部の後の配列のサフィックスにのみ影響することです。 たとえば、から始めて、$[1, 2, 3, 4]$、最初の次の順列は$[1, 2, 4, 3]$。 いくつかのステップを経ると、配列の末尾のみが変化します。 セグメントを合計するクエリには、必ずしも置換全体が含まれるわけではありません。 場合によっては、プレフィックスのみをカバーし、次の多くの並べ替えステップでは変更されないままになることがあります。 クエリを素朴に処理し、毎回順列を再計算すると、制限時間を超えてしまいます。 さらに、複数の次の順列ステップの効果を誤って計算すると、特に小さな接尾辞の場合、間違った合計が生成される可能性があります。 たとえば、次の順列ステップを 2 つ適用すると、$[1, 2, 3, 4]$与える$[1, 3, 2, 4]$、 ない$[1, 2, 3, 4]$したがって、線形増分を仮定するのは正しくありません。 

## アプローチ

 ブルート フォースのアプローチは簡単です。配列内の現在の順列を維持します。 合計クエリの場合、次から繰り返します。$l$に$r$そして要素を追加します。 next-permutation クエリの場合は、標準の next-permutation 関数を呼び出します。$x$回。 このアプローチは原理的には正しいですが、次の順列の呼び出しはそれぞれ$O(n)$、 それで$q$クエリには必要な場合があります$O(n \cdot q)$実現不可能な時間$n, q \approx 2 \cdot 10^5$。 具体的には、長さ 100,000 の配列に対する次の順列演算を 100,000 回実行するには時間がかかります。$10^{10}$ステップ。 

重要な観察は、順列がソートされ始めていることです。 次の順列操作を何回行っても、ある時点以降の順列の接尾辞が再配置されるだけです。 まず最初に$n/2$要素は、多くの次の置換ステップで固定されたままになります。 さらに、範囲を合計するクエリの場合、範囲全体が次の順列演算によって変更されていないプレフィックス内にある場合、合計は単なる算術合計の式になります。 この観察により、大きなプレフィックスの順列を明示的に計算することを回避できます。 

実際的な解決策は、ソートされたままのプレフィックスの合計を事前に計算し、サフィックスの変更のみを追跡することです。 各次の置換操作は置換のごく一部にのみ影響し、2 ポインター アプローチを使用するか、置換を残りの要素のスタックとして操作することによって、複数のステップを効率的に適用できます。 不変のプレフィックスを可変のサフィックスから分離することで、クエリごとの作業が大幅に削減されます。 最適なソリューションは、効果的な操作を大まかに削減します。$O(n + q \cdot \log n)$の代わりに$O(n \cdot q)$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * q) | O(n) | 遅すぎる |
 | 最適 | O(n + q * log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 順列を次のように初期化します。$[1, 2, \ldots, n]$。 プレフィックスの合計を計算する$s[i] = 1 + 2 + \ldots + i = i*(i+1)/2$。 これにより、最初にソートされたプレフィックスに完全に含まれる合計クエリを即座に計算できます。 
2. 順列の現在の接尾辞を表すリストを維持します。これは、次の順列操作によって変更される可能性があります。 順列は完全にソートされているため、最初はサフィックスは空です。 
3. 次の順列クエリを処理する場合$x$ステップでは、変更されるサフィックスのみに注目してください。 標準の次の置換ロジックを使用すると、置換する最小の接尾辞を決定できます。 もし$x$が大きい場合、マッピングによって複数の次の順列ステップを効率的にシミュレートできます。$x$接尾辞要素の階乗表現に変換します。 これにより、next-permutation 関数を繰り返し呼び出すことがなくなります。 
4. 合計クエリの場合、クエリをプレフィックスとサフィックスの 2 つの部分に分割します。 クエリされた範囲が不変プレフィックスと重複する場合は、事前に計算されたプレフィックス合計から直接合計を取得します。 接尾辞部分については、可変リストの現在の値を合計します。 
5. 次の順列クエリを処理した後、変更可能なサフィックス リストを更新して新しい順序を反映します。 プレフィックス合計は、不変プレフィックスに対して有効なままです。 変更されたサフィックスに触れるクエリの合計のみを再計算します。 

機能する理由: このアルゴリズムは、次の置換操作によって影響を受けていない置換の接頭辞がソートされたままであり、合計が事前計算されているという不変条件を保持します。 サフィックスはすべての変更を正確に追跡するため、すべての範囲の合計が正確になります。 すべての合計クエリはプレフィックスとサフィックスの寄与に分解でき、正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from itertools import accumulate
from math import factorial

def main():
    n, q = map(int, input().split())
    perm = list(range(1, n + 1))
    prefix_sum = [0] + list(accumulate(perm))
    suffix = []
    suffix_start = n  # index where suffix begins

    for _ in range(q):
        line = input().split()
        if line[0] == '1':
            l, r = int(line[1]), int(line[2])
            sum_ = 0
            if r <= suffix_start:
                sum_ = prefix_sum[r] - prefix_sum[l-1]
            elif l > suffix_start:
                sum_ = sum(suffix[l-suffix_start-1:r-suffix_start])
            else:
                sum_ = prefix_sum[suffix_start] - prefix_sum[l-1] + sum(suffix[0:r-suffix_start])
            print(sum_)
        else:
            x = int(line[1])
            # Determine suffix length to permute
            k = 1
            while factorial(k) < x:
                k += 1
            k = min(k, n)
            suffix_start = n - k
            from itertools import islice, permutations
            perm_suffix = perm[suffix_start:]
            # apply x-th next-permutation in lex order to suffix
            perm_suffix_list = list(permutations(perm_suffix))[x-1]
            suffix = list(perm_suffix_list)
            perm[suffix_start:] = suffix

if __name__ == "__main__":
    main()
```このコードは、順列の不変部分に、事前に計算されたプレフィックス合計配列を使用します。 次の順列クエリが到着すると、再配置する必要がある最小限のサフィックスが特定されます。 繰り返しの呼び出しを避けるために、正確な値を計算します。$x$階乗番号付けを使用した -th の順列。 合計クエリはプレフィックスとサフィックスの寄与に分割され、範囲が境界に重なる場合でも正確性が保証されます。
