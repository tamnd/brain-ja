 ## 解決策
 ## 問題の理解

 私たちは建物の列として表される都市を与えられており、それぞれの建物には鉱山がある場合とない場合があります。 市内地図は 0 と 1 の文字列で、「1」は鉱山を示し、「0」は安全な建物を示します。 サッパーには 2 つの操作があります。コストを支払って地雷を起動できます。`a`、これにより、そのセグメント内のすべての連続する地雷が爆発します。または、コストを支払って建物に地雷を設置することもできます`b`。 私たちの目標は、最小限の総コストですべての地雷を除去して都市を安全にすることです。 

入力により複数のテスト ケースが提供されます。 それぞれについて、必要な最小限のコイン支出を計算するように求められます。 制約により、最大で`10^5`すべてのテスト ケースにわたる建物の合計。 これにより、テスト ケースごとに O(n²) であっても遅すぎるため、地雷のアクティブ化または配置のすべての可能なシーケンスを明示的にシミュレートするソリューションは除外されます。 線形または線形に近いソリューションが実現可能です。 

地雷のセグメント間のゼロのシーケンスには微妙な点が生じます。 地雷を設置するコストがかかる場合`b`別の地雷を起動するよりも小さい`a`、地雷を個別にアクティブにするよりも、地雷を配置して 2 つの別々の地雷セグメントを接続する方がコストが安くなる場合があります。 既存の各セグメントを個別にアクティブ化するだけの単純なアプローチでは、この最適化が無視されます。 たとえば、文字列「1100011」では、`a=5`そして`b=1`、2 つのセグメントを個別にアクティブ化するには 10 のコストがかかりますが、ギャップに 1 つの地雷を配置し、接続されたセグメント全体をアクティブ化する場合のコストはわずか 6 です。 

## アプローチ

 ブルートフォースアプローチは、地雷の連続する各ブロックを識別し、個別にアクティブ化することです。`a`ブロックごとに。 ブロックを結合するために地雷を配置するオプションを無視すると、これは正しく機能します。 最悪の場合、すべての建物が鉱山である場合、セグメントは 1 つだけであり、複雑さは建物の数に比例します。 しかし、地雷セグメント間のギャップが小さく、`b < a`の場合、セグメントの結合が考慮されていないため、総当たり攻撃は最小コストを見つけることができません。 

重要な観察は、隣接する鉱山セグメントのアクティブ化には固定コストがかかるということです。`a`で区切られた 2 つのセグメントを結合します。`k`ゼロコスト`k * b`。 したがって、セグメント間のゼロのギャップごとに、貪欲に次のいずれかを決定できます。`a`次のセグメントを個別にアクティブ化するか、支払う`k * b`ギャップを埋めてセグメントを接続し、単一の料金を支払います`a`結合されたセグメントをアクティブにします。 以来`a`そして`b`両方とも小さな整数であり、次の最小値です。`a`そして`k*b`ギャップごとに安価な選択肢が得られます。 

問題をセグメント間のギャップの評価とコストの最適な合計に縮小すると、解決策は線形になります。最初にすべての鉱山セグメントを特定し、次にギャップを反復して最小公式を適用します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (各セグメントを個別にアクティブ化) | O(n) | お(1) | 正しいですが最適ではない可能性があります |
 | 最適 (ギャップコストのあるセグメントの結合を検討してください) | O(n) | お(1) | 正しくて効率的 |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。`a`、`b`、および都市地図文字列。 都合がよければ、文字列をリストに変換します。 
2. 先頭と末尾のゼロはコストに影響しないため、無視します。 
3. 最初の地雷セグメントを特定します。 総コストを初期化します`a`それをアクティブ化します。 
4. 文字列の残りの部分を繰り返し処理して、後続の地雷セグメントを見つけます。 各セグメントについて:

 1.長さを測る`k`このセグメントの直前にゼロが続きます。 
2.追加`min(a, k * b)`総コストに。 地雷を設置する方が個別にアクティブ化するよりも安価な場合は、セグメントの接続をシミュレートします。 
5. すべてのセグメントを処理した後、このテスト ケースの合計コストを出力します。 

重要な不変条件は、各ステップで、現在の位置までのすべての地雷を除去するための最小コストが総コストに正しく反映されることです。 選択する`min(a, k*b)`すべての組み合わせをテストすることなく、各ギャップが最適に処理されることを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        a, b = map(int, input().split())
        s = input().strip()
        n = len(s)

        # find first and last mine
        first = s.find('1')
        if first == -1:
            print(0)
            continue
        last = s.rfind('1')

        total = a  # activate first segment
        i = first
        while i <= last:
            if s[i] == '0':
                zero_count = 0
                while i <= last and s[i] == '0':
                    zero_count += 1
                    i += 1
                if i <= last:
                    total += min(a, zero_count * b)
            else:
                i += 1
        print(total)

if __name__ == "__main__":
    solve()
```コードは、地雷領域外のゼロの不必要な処理を避けるために、最初と最後の地雷を見つけることから始まります。 コストのために常に最初のセグメントをアクティブにします`a`。 セグメント間のギャップがゼロになるたびに、その長さを計算して追加します。`min(a, gap*b)`総コストに。 これにより、次のセグメントを個別にアクティブ化するか、前のセグメントに接続するかの選択がキャプチャされます。 

境界の処理は微妙です。内側のループは最後の鉱山を超えてゼロをカウントしすぎてはなりません。`if i <= last`後続のセグメントに先行するギャップに対してのみ支払いが行われるようにします。 

## 実用的な例

 サンプル 1:`a=1, b=1, s="01000010"`| 私 | s[i] | ゼロカウント | 合計 |

 最初の「1」を 1 コインで有効にし、次のセグメントの前に 4 つのゼロのギャップが続きます。`min(a, k*b) = min(1, 4*1)=1`。 合計 = 2、これは予想される出力と一致します。 

サンプル 2:`a=5, b=1, s="01101110"`| 私 | s[i] | ゼロカウント | 合計 |

 | 0 | 0 | - | 5 |

 | 3 | 0 | 1 | 6 |
 | 4-6 | 1 | - | 6 |

 最初のセグメントが 5 に対してアクティブ化されました。ギャップ 1 がゼロで、次のセグメントのコストに接続されます。`min(5,1*1)=1`。 合計 6 で、予想される出力と一致します。

 ## 特殊なケース

 地雷のない文字列の場合、アルゴリズムは以下を見つけます。`first = -1`単一の地雷の場合、最初のセグメントは次のようにアクティブ化されます。`a`コインとゼロをめぐるループはスキップされます。 より大きいギャップの場合`a/b`、アルゴリズムは、セグメントを接続するか個別にアクティブ化するかを正しく選択します。`min(a, k*b)`。 すべての建物に地雷があるストリングの場合、最初のセグメントは都市全体をカバーし、総コストは単純に次のようになります。`a`。 いずれの場合も、総コストが各ギャップにおける最小の選択を反映するという不変条件により、正確さが保証されます。
