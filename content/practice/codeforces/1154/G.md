 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、インデックスのペアを見つけるように求められます。`(i, j)`これらのインデックスの 2 つの数値の最小公倍数 (LCM) ができるだけ小さくなるようにします。 配列には最大 100 万個の要素を含めることができ、各数値は最大 1,000 万個まで大きくなります。 出力は、最小の LCM を生成するインデックスのペアです。 

重要な課題は、単純な二重ループを使用してすべての可能なペアの最小公倍数を計算する必要があることです。`n^2/2`操作。 のために`n = 10^6`、これくらいでしょう`5 * 10^11`制限時間4秒では到底不可能な作戦だ。 したがって、すべてのペアを直接反復処理することを避ける方法を見つける必要があります。 

単純な実装は、繰り返しの数値や、多数の大きな数値の因数である小さな数値を含む配列などの特殊なケースでも失敗する可能性があります。 たとえば、配列が次の場合、`[2, 2, 6]`、最小 LCM は次のとおりです。`2`最初の 2 つのインデックスを使用します。 個別の値を想定したり、隣接する要素のみを比較したりする不注意なアプローチでは、誤って選択されてしまいます。`LCM(2,6) = 6`。 

## アプローチ

 ブルートフォースアプローチは簡単です。 すべてのペアを反復処理します`(i, j)`そしてLCMを次のように計算します`a[i] * a[j] // gcd(a[i], a[j])`、最小値を持つペアを追跡します。 この方法は正しいですが、次のことが必要です`O(n^2)`実行可能な限界を超える操作`n`大きいです。 

より高速なソリューションを実現するための重要な観察点は、最小 LCM には最小の数値または共通の因数を共有する数値が含まれることが多いということです。 具体的には、数値の場合、`x`配列内で複数回発生する場合、それ自体と組み合わせると、以下に等しい最小 LCM が生成されます。`x`。 それ以外の場合は、LCM が大きな数で乗算的に増加するという事実を利用できます。 すべてのペアではなく、各整数の倍数を考慮することで、最小の LCM を現実的に生成できる候補に焦点を当てることができます。 

最適な解決策は、ふるいのようなアプローチを使用して、配列内の最大値までの各整数について、それで割り切れる配列要素のインデックスを追跡します。 1 から始まるすべての可能な約数を反復処理することにより、すべてのペアを明示的にチェックしなくても最小の LCM を見つけることができます。 これにより、複雑さはおおよそ次のように軽減されます。`O(max(a) * log(max(a)))`、制約を考慮すると、これは許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 最適 | O(max(a) * log(max(a))) | O(最大(a)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を読み取り、配列を保存します`a`。 各数値から配列内のインデックスへのマッピングを作成します。 これにより、後で正しい 1 から始まる位置をレポートすることができます。 
2. リストの初期化`positions`サイズの`max(a) + 1`各数値またはその倍数が出現する最小の 2 つのインデックスを保存します。 
3. 配列と各値を反復処理します。`v`、そのインデックスを追加します`positions[v]`。 もし`positions[v]`2 を超える場合は、追加のインデックスを無視します。 同じ数値が 2 つ出現すると即座に最小 LCM の候補が提供されるため、最初の 2 つだけを保持すれば十分です。 
4. 整数のループ`d`1から`max(a)`。 それぞれについて`d`の倍数を考慮します。`d`まで`max(a)`。 すべての倍数の中で最も小さい 2 つのインデックスを追跡します。`d`。 これらのインデックスは数値に対応します`x`そして`y`両方が割り切れる配列内`d`。 
5. 以下を使用して候補 LCM を計算します。`x * y // d`。 この候補が現在の最小 LCM より小さい場合は、結果を更新します。 
6. すべての約数を繰り返した後、見つかった最小 LCM に対応するインデックスのペアを出力します。 

機能する理由: アルゴリズムにより、すべての数値が`v`は、約数を共有する他のすべての数値と組み合わせて考慮されます。 約数を昇順に繰り返すことにより、最小の LCM を生成するペアを決して見逃さないことが保証されます。 2 つのインデックスの追跡により、利用可能な場合は常に個別の要素が選択されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def main():
    n = int(input())
    a = list(map(int, input().split()))
    max_a = max(a)
    idx_map = [[] for _ in range(max_a + 1)]
    
    for i, val in enumerate(a):
        idx_map[val].append(i + 1)
        if len(idx_map[val]) > 2:
            idx_map[val] = idx_map[val][:2]
    
    min_lcm = 10**20
    ans = (1, 2)
    
    # sieve over possible divisors
    for d in range(1, max_a + 1):
        first = second = -1
        for mult in range(d, max_a + 1, d):
            for pos in idx_map[mult]:
                if first == -1:
                    first = pos
                elif second == -1:
                    second = pos
                if first != -1 and second != -1:
                    break
            if first != -1 and second != -1:
                break
        if first != -1 and second != -1:
            x = a[first - 1]
            y = a[second - 1]
            lcm_val = x * y // math.gcd(x, y)
            if lcm_val < min_lcm:
                min_lcm = lcm_val
                ans = (first, second)
    
    print(ans[0], ans[1])

if __name__ == "__main__":
    main()
```コードはまず数値をそのインデックスにマッピングし、次にすべての潜在的な約数をふるいにかけて、候補ペアを効率的にチェックします。 保存されるインデックスの数を 2 に制限すれば、メモリや時間を無駄にすることなく、数値が繰り返されるケースに十分対応できます。

 ## 特殊なケース

 配列に小さな数値の繰り返しが含まれている場合、アルゴリズムはそれらをすぐに選択します。 のために`[7,7,11]`、除数`7`2 つのインデックス 1 と 2 が得られ、次のようになります。`LCM=7`、正しくは以下より小さい`LCM(7,11)=77`。 を含む配列`1`また、他の数値と組み合わせて生成します`LCM=1`もし`1`2 回発生するか、そうでない場合は最小の数です。 ふるいは、考えられるすべての約数が考慮されることを保証するため、アルゴリズムが候補を見逃すことはありません。
