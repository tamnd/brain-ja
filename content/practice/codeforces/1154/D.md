 ## 解決策
 ## 問題の理解

 1 次元軸上の位置 0 から開始し、その位置まで歩こうとするロボットを制御します。`n`。 ロボットには 2 つの電源があります: 容量のあるバッテリー`b`および容量のある蓄電池（ソーラーパネルによって充電）`a`。 位置からのセグメントごとに`i-1`に`i`、ロボットがバッテリーを使用するか蓄電池を使用するかを決定します。 バッテリーを使用すると、充電量が 1 つ減ります。 アキュムレータを使用すると、その電荷も 1 つ減少します。 セグメントが晴れていてロボットがバッテリーを使用する場合、アキュムレータは最大容量まで 1 単位の充電を獲得します。 

入力により提供されるのは、`n`、セグメントの長さ。`b`そして`a`、容量。 そして配列`s`サイズの`n`どこ`s[i]`かどうかを示します。`i`-番目のセグメントは晴れです (`1`） か否か （`0`）。 出力は、最適に制御された場合にロボットが横断できるセグメントの最大数です。 

制約が示すのは、`n, a, b <= 2 * 10^5`。 2 秒の制限があるため、各セグメントを一定の回数繰り返すソリューションは実行可能です。 さらなるオペレーション`O(n)`リスクが高いため、ネストされたループまたは動的プログラミングを使用して拡張します。`n*a*b`手の届かないところにいる。 

明白ではないエッジケースは、一方のリソースを充電に使用できるまさにその瞬間に一方のリソースが使い果たされる場合に発生します。 たとえば、ロボットが`b=1`、`a=1`、およびセグメント`[1, 0, 1]`常に蓄電池を好む不注意な貪欲な人は途中で停止する可能性がありますが、正しい戦略は、最初の晴れたセグメントでバッテリーを使用して蓄電池を再充電し、さらに続行することです。 

## アプローチ

 ブルートフォースアプローチは、バッテリー/蓄電池の使用の考えられるすべてのシーケンスを試すことです。 各セグメントには 2 つの選択肢があり、`2^n`可能性。 明らかに、これは不可能です`n`まで`2*10^5`。 

重要な洞察は、各セグメントで、バッテリーと蓄電池の現在の充電量のみを知る必要があるということです。 トラバースを最大化したいので、アキュムレータの電荷がより価値のあるときに保存する必要があります。 晴れた区間では、蓄電池が満杯でない場合は、蓄電池を再充電するため、バッテリを使用することをお勧めします。 晴天以外の区間では、蓄電池が空でない場合には蓄電池を使用することが望ましい場合が多く、蓄電池を再充電できる晴天区間に向けてバッテリーを節約します。 

この推論により、各セグメントを一度調べて、全体的な将来の横断可能性を維持するエネルギー源を選択する貪欲なアプローチが可能になります。 複雑な動的プログラミングやバックトラッキングは必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 貪欲に最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`battery = b`そして`accumulator = a`。 セット`segments_passed = 0`。 
2. 各セグメントを反復処理します。`i`から`0`に`n-1`。 セグメントごとに、どのエネルギー源を使用するかを決定します。 
3. セグメントが晴れている場合 (`s[i] == 1`):

 ａ． アキュムレータがいっぱいの場合 (`accumulator == a`)、バッテリーの再充電電位の無駄を避けるためにアキュムレータを使用してください。 

b. それ以外の場合、バッテリーが充電されている場合 (`battery > 0`）、バッテリーを使用してください。 バッテリーを 1 減らし、アキュムレーターを 1 増やします (ただし、それを超えることはできません)`a`）。 

c. バッテリーが空の場合は、アキュムレーターを使用してください。 アキュムレータを 1 減らします。 
4. セグメントが晴れていない場合 (`s[i] == 0`):

 ａ． アキュムレータに電荷がある場合 (`accumulator > 0`）を使用してください。 アキュムレータを 1 減らします。 

b. それ以外の場合、バッテリーが充電されている場合 (`battery > 0`）を使用してください。 バッテリーを1つ減らします。 
5. バッテリーも蓄電池も充電されていない場合は、反復を停止します。 それ以外の場合は増分します`segments_passed`1までに。 
6. すべてのセグメントを処理するか、途中で停止した後、リターンします。`segments_passed`。 

**機能する理由:** グリーディーは、蓄電池が満杯になったときにバッテリーが無駄になるのを防ぎながら、日当たりの良い区間が許可されるたびに蓄電池が充電されるという不変条件を維持します。 将来の決定はバッテリーと蓄電池の現在の状態にのみ依存するため、このシングルパスの意思決定により、通過するセグメントの数が最大化されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, b, a = map(int, input().split())
s = list(map(int, input().split()))

battery = b
accumulator = a
segments_passed = 0

for sun in s:
    if sun == 1:
        if accumulator == a:
            if accumulator > 0:
                accumulator -= 1
            elif battery > 0:
                battery -= 1
        else:
            if battery > 0:
                battery -= 1
                accumulator += 1
            elif accumulator > 0:
                accumulator -= 1
            else:
                break
    else:
        if accumulator > 0:
            accumulator -= 1
        elif battery > 0:
            battery -= 1
        else:
            break
    segments_passed += 1

print(segments_passed)
```ソリューションはアルゴリズムに正確に従います。 日当たりの良いセグメントでは、アキュムレータが満杯かどうかを確認するために特別な注意が払われます。 操作の順序により、アキュムレータを過充電したり、空のバッテリやアキュムレータを使用したりしないことが保証されます。 の`break`ステートメントは、両方のソースが枯渇した場合の停止条件を処理します。

            elif battery > 0:
