 ## 解決策
 ## 問題の理解

 私たちには一連の日数が与えられており、毎日メルは 1 から 5 までのラベルが付いた 1 つのケーキ層の材料を受け取ります。メルはウェディング ケーキを作っていますが、完成したケーキはそれぞれ、層 1 から層 5 まで厳密な順序で組み立てる必要があります。各材料は届いたその日にすぐに使用できますが、その日に使用しなければ永久に失われます。 

おもしろいのは、メルが同時に複数のケーキに取り組むことができるということです。 これは、いつでも、部分的に構築されたケーキがいくつかある可能性があり、それぞれのケーキが層を持たない状態と完成まであと一歩の間の段階にある可能性があることを意味します。 毎日の材料は、既存の部分ケーキを 1 つだけレイヤー k から k+1 に進めるか、無視することができます。 

タスクは、1 日を通して完成できる完全な 5 層ケーキの最大数を決定することです。 

入力サイズは最大 100 万日になる可能性があり、ケーキごとにすべての部分状態を明示的に追跡したり、すべての可能な割り当てをシミュレートしようとするアプローチは即座に除外されます。 どのソリューションも、毎日一定時間または償却一定時間で処理する必要があります。 

微妙なエッジケースは、レイヤーが「間違った」順序で到着する場合、たとえば、多くの 5 が最初に続き、その後 1 が続く場合に発生します。 常に最も高度なケーキを最初に完成させようとする素朴な貪欲さは、新しい有効なチェーンを開始する機能をブロックするため、失敗する可能性があります。 もう 1 つの失敗例は、中間層が豊富にあるものの 1 が不十分な場合です。この場合、初期層の割り当てが多すぎると、決して完了できないデッド部分ケーキが発生します。 

## アプローチ

 ブルート フォース シミュレーションでは、すべての部分ケーキのリストを維持し、受信層ごとに、拡張できる可能性のあるすべてのケーキを試します。 最悪の場合、k 日後には O(k) 個の部分ケーキが存在する可能性があるため、新しい日ごとにすべてのケーキがスキャンされ、N が大きい場合は O(N^2) 個の動作が発生する可能性があります。 これは 10^5 演算のあたりですでに実行不可能になり、ここで N は最大 10^6 になります。 

重要な観察は、個々のケーキを区別する必要がないということです。 重要なのは、次に必要な各レイヤーを現在待機しているケーキの数だけです。 進行中のケーキは、ステージ 5 が完了を意味し、追跡する必要がないため、純粋に現在のステージ 1 から 4 によって説明できます。 

これにより、問題は 5 つのカウンター (レイヤー 1、レイヤー 2、レイヤー 3、レイヤー 4 を待っている部分ケーキの数、および形成された完成ケーキの数) の管理に軽減されます。 私たちは毎日、必要なケーキを進めるために、入ってくるレイヤーを貪欲に使用しようとします。 複数の選択肢が存在する場合は、それを使用できる最も高度なステージを進めることを常に好みます。これにより、後から一致させるのが難しい以前のレイヤーの柔軟性が維持されるからです。 

この貪欲さが機能するのは、下位ステージを優先して上位ステージの完了を遅らせることは将来の可能性を決して増加させない一方で、その逆を行うとチェーンの形成が永久にブロックされる可能性があるためです。

 | --- | --- | --- | --- |
 | ケーキの総当たりシミュレーション | O(N^2) | O(N) | 遅すぎる |
 | ステージカウンター貪欲シミュレーション | O(N) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 配列を維持します`cnt[1..4]`どこ`cnt[i]`は現在ステージ i にある部分ケーキの数です。つまり、レイヤー i+1 を待っていることを意味します。 完成したケーキのカウンターも併設しています。 

毎日 1 つの値を処理します`a[i]`。 

1. もし`a[i] == 1`、ステージ 1 で新しい部分ケーキを開始します。`cnt[1]`。 これは、新しいチェーンを作成できる唯一のレイヤーです。 
2. もし`a[i] == 2`、レイヤー 2 を待機しているケーキ、つまりステージ 1 のケーキを進めようとします。`cnt[1] > 0`、デクリメントします`cnt[1]`そして増加します`cnt[2]`。 そのようなケーキが存在しない場合、この材料は破棄されます。 
3. もし`a[i] == 3`、可能であれば、最初にステージ 2 のケーキを拡張しようとします。これにより、以前のステージが利用可能になるためです。 それで、もし`cnt[2] > 0`から 1 つ移動します`cnt[2]`に`cnt[3]`、そうでない場合は、レイヤーを無視します。 
4. もし`a[i] == 4`では、まずステージ 3 をステージ 4 に拡張しようとします。`cnt[3] > 0`、1つ前に進みます。 それ以外の場合は破棄します。 
5. もし`a[i] == 5`, ステージ 4 の部分的なケーキがある場合、これでケーキが完成します。 もし`cnt[4] > 0`、それを減らして答えを増やします。 

私たちは常に可能な限り最も進んだステージを拡張することを好むため、各ステップ内の順序は重要です。 

それが機能する理由は、部分ケーキのマルチセットがそのステージによって常に完全に特徴づけられ、有効な最終スケジュールを、初期段階の進行が後の段階の完了を決して妨げないスケジュールに変換できるという不変条件によって捉えられます。 より高度でないケーキを優先して、より高度なケーキの進行の可能性をスキップすることを選択した場合は常に、到達可能な完了の総数を増やすことなく進行を遅らせるだけですが、逆の選択をすると、完了するはずだったチェーンが破壊される可能性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    cnt1 = cnt2 = cnt3 = cnt4 = 0
    ans = 0
    
    for x in arr:
        if x == 1:
            cnt1 += 1
        elif x == 2:
            if cnt1:
                cnt1 -= 1
                cnt2 += 1
        elif x == 3:
            if cnt2:
                cnt2 -= 1
                cnt3 += 1
        elif x == 4:
            if cnt3:
                cnt3 -= 1
                cnt4 += 1
        else:  # x == 5
            if cnt4:
                cnt4 -= 1
                ans += 1
    
    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、前述のステージ マシンを直接実装します。 各変数は不完全なケーキの 1 つのステージに正確に対応し、遷移はローカルの定時間更新です。 最終的な答えは、ステージ 4 のケーキがレイヤー 5 を正常に受け取った場合にのみ蓄積されます。 

よくある実装の落とし穴は、「公平」にしようとして、考えられるすべてのケーキにレイヤーを分散させようとすることです。 この構造ではアイデンティティではなく重要性のみが保証されるため、これは不必要かつ有害です。

 ## 特殊なケース

 多数の 5 の後に 1 が続くなど、すべての初期層が遅れて出現する場合、5 が到着した時点ではステージ 4 のケーキが存在しないため、アルゴリズムは正しくゼロを生成します。 5 を「保存」しようとする単純な解釈では、結果が誤って水増しされてしまいます。 

レイヤーが 1 ～ 5 の完全な順序で繰り返し到着すると、各ステップは 1 チェーンだけ進み、干渉は発生しません。 カウンタにより、レイヤが無駄にならないことが保証されます。 

中間層は豊富だが 1 が少ない場合、開始点の数だけが答えを制限します。 cnt1 がボトルネックであり、後続のステージがそれを超えることはできないため、アルゴリズムはこれを反映しています。
