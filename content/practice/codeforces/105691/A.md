 ## 解決策
 ## 問題の理解

 このタスクでは、各数字がそれ自体と等しい値を与える、数字を使ってプレイされる小さなゲームについて説明します。ただし、数字を選択すると、隣接する数字の値が「削除」されるという副作用があります。 具体的には、ある値 x のすべての出現を取得することにした場合、x−1 および x+1 のすべての出現は将来の選択には使用できなくなります。 値 x を取得するたびに、x に入力内に出現する回数を乗算した値に等しいポイントを獲得します。 目標は、獲得する合計ポイントを最大化しながら、選択した 2 つの値が正確に 1 だけ異なることがないように、どの値を選択するかを選択することです。 

入力は単なる整数のリストです。 出力は単一の数値、つまりこの制約の下で達成可能な最大スコアです。 

主な制約は、n が最大 100000、値も最大 100000 です。これにより、すべてのサブセットを試行したり、すべての要素に対する決定をシミュレートしたりするソリューションは直ちに除外されます。 どの値を選択するかについて単純な指数関数的な検索を行うと、2 の個別の値の累乗が大きくなり、数十個の個別の数値であっても実行不可能になります。 発生のすべてのサブセットを反復処理するだけでも、現実的な制限をはるかに超えています。 

素朴な貪欲な試みでは、より微妙な問題が発生します。 たとえば、最も頻度の高い値を最初に選択するのは合理的であるように見えますが、頻度がわずかに低い値を選択すると、2 つの適度に大きな近傍値がブロックされ、全体の合計が高くなる可能性があるため、大失敗する可能性があります。 

たとえば、次の入力を考えてみましょう。 

3

 1 2 2

 最初に 1 を選択する貪欲な選択では 1 が得られ、その後 2 を選択できず、合計は 1 になります。最適解は 2 を選択し、4 を獲得します。これは、ローカル周波数またはローカル値の決定が信頼できないことを示しています。 

問題は、各値がそのすぐ隣の値とのみ相互作用するため、恣意的な競合ではなく、構造化された依存関係が作成されることです。 

## アプローチ

 ブルートフォースのアイデアは、個別の値のすべてのサブセットを考慮し、それが有効かどうかを検証することです。つまり、選択された 2 つの値が 1 だけ異なることはありません。有効なサブセットごとに、値 × 頻度を合計して合計寄与度を計算します。 k 個の個別の値がある場合、2^k 個のサブセットをチェックする必要があり、各サブセットには前処理による O(k) または O(1) の計算が必要です。 最悪の場合、k が 100000 に達すると、k = 40 であってもすでに 1 兆を超えるサブセットが生成されるため、このアプローチはすぐに失敗します。 

重要な観察は、その構造が、行を介した古典的な「テイク・オア・スキップ」動的プログラミングと同じであるということです。 各値の出現をすべて集計した後、各整数値は単一の重みになります: val[x] = x × count[x]。 「x と x+1 を一緒に取ることはできない」という制限は、x を選択すると、値の 1 次元配列内の隣接するインデックスが強制的に除外されることを意味します。 

問題がこのように書き換えられると、それは標準的な再発になります。 dp[x] が x までのすべての値を考慮した最良の答えを表すものとします。 各 x について、それをスキップして dp[x−1] を維持するか、それを取得して val[x] に dp[x−2] を加えます。 この構造が機能するのは、x を取得することによって生じる唯一の競合が正確に x−1 であり、x−1 より小さいものはすべて独立したままであるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース | O(2^k) | O(k) | 遅すぎる |
 | DP オーバー値 | O(maxA + n) | O(最大A) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 数値のリストを読み、各値が何回出現するかを数えます。 位置ではなく周波数のみが重要であるため、このステップでは入力が圧縮されます。 
2. 各値 x を重み寄与 x × 周波数 [x] に変換します。 これにより、問題は数直線上の独立した重み付き位置の中から選択することに変わります。 
3. dp[x] が x までの値を使用して達成可能な最良の合計を表す DP 配列を作成します。 
4. dp[0] = 0 および dp[1] = value[1] を初期化します。これは、値 1 しか利用できないため、選択できるのはそれを採用するかどうかだけです。 
5. 存在する 2 から最大値までの各 x について、dp[x−1] と dp[x−2] + value[x] の間の最大値として dp[x] を計算します。 最初のオプションは x をスキップすることに対応し、2 番目のオプションは x-1 を強制的に除外することに対応します。 
6. 答えはdp[最大値]です。 

この繰り返しが有効である理由は、値が整数行でソートされると、すべての決定がすぐ隣の値にのみ影響するためです。 x までの最適解は、x を含むか含まないかのいずれかでなければなりません。 x を除外すると、x−1 の最適解になります。 x が含まれる場合、x−1 は禁止されますが、x−2 まではすべて影響を受けないため、最も互換性のあるプレフィックスは dp[x−2] になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))

    if n == 0:
        print(0)
        return

    maxv = max(arr)
    freq = [0] * (maxv + 1)

    for x in arr:
        freq[x] += 1

    val = [0] * (maxv + 1)
    for x in range(maxv + 1):
        val[x] = x * freq[x]

    if maxv == 0:
        print(0)
        return
    if maxv == 1:
        print(max(val[0], val[1]))
        return

    dp0 = 0
    dp1 = val[1]

    for x in range(2, maxv + 1):
        dp2 = max(dp1, dp0 + val[x])
        dp0, dp1 = dp1, dp2

    print(dp1)

if __name__ == "__main__":
    solve()
```コードはまず、各整数値が独立して寄与するように、入力を頻度表に圧縮します。 DP は、完全な配列ではなく前の 2 つの状態のみを保持することにより、O(1) 空間で実装されます。 これにより、最大値が大きい場合のメモリのオーバーヘッドが回避されます。 この遷移は、現在の値を含めるか除外するかの決定を正確に反映し、ローリング変数 dp0 と dp1 はそれぞれ dp[x-2] と dp[x-1] を表します。 

よくある実装上の間違いは、入力の最大値までしか反復せず、中間値がゼロになる可能性があることを忘れていることです。 dp 遷移は自然にゼロを処理するため、ここでは問題になりません。空の値をスキップすると、以前の最適な結果が保持されます。 

## 実用的な例

 入力を考慮してください:```
3
1 2 2
```We compute frequencies and values:

 | × | 周波数[x] | 値[x] | 二者択一決定 |
 | --- | --- | --- | --- |
 | 1 | 1 | 1 | 1 を取るかスキ​​ップする |
 | 2 | 2 | 4 | 1 | と競合します

 ステップバイステップの DP:

 | × | dp0 (x-2) | dp1 (x-1) | dp[x] |
 | --- | --- | --- | --- |
 | 1 | 0 | 1 | 1 |
 | 2 | 1 | 1 | 4 |

 Final answer is 4, achieved by taking 2.

 これは、1 が出現しても、2 の方がより高い合計貢献度を生み出すため、それを犠牲にすることが最適であることを示しています。 

ここで次のことを考えてみましょう。```
5
1 1 2 3 3
```周波数は、1→2、2→2、3→6の値を与えます。 

| × | dp0 | dp1 | DP |
 | --- | --- | --- | --- |
 | 1 | 0 | 2 | 2 |
 | 2 | 2 | 2 | 2 |
 | 3 | 2 | 2 | 8 |

 最終的な答えは 8 で、値 3 のみを取得することで得られます。 これにより、DP が隣接する値をブロックする効果を正しく伝播していることが確認されます。

 この制約では、最大 100,000 個の要素と最大 100,000 個の値が許可されるため、値の範囲と入力サイズの線形スキャンは時間制限内に快適に収まります。 メモリ使用量は直線的に維持され、一般的な制限に対して十分に小さいです。

 ## 特殊なケース

 すべての値が同じ場合は、アルゴリズムが頻度を正しく集計しているかどうかをテストします。 

入力:```
4
7 7 7 7
```ここでは、freq[7] = 4、つまり value[7] = 28 です。6 と 8 は入力寄与に存在しないため、重要な隣接制約はありません。 DP は他の値をすべてスキップし、7 を直接選択して 28 を生成します。 

もう 1 つのエッジ ケースは、連続シーケンスです。 

入力:```
4
1 2 3 4
```DP は次のように評価します。 

dp[1] = 1

 dp[2] = 最大(1, 0 + 2) = 2

 dp[3] = 最大(2, 1 + 3) = 4

 dp[4] = 最大(4, 2 + 4) = 6

 最終結果 6 は、値 2 と 4 の選択に対応しており、反復によってチェーン全体の交互の選択肢がどのように正しく解決されるかを示しています。
