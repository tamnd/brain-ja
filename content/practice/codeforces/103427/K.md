 ## 解決策
 ## 問題の理解

 最初は空のサイズの正方形グリッドを使用して作業しています。$n \times n$、すべてのセルはゼロから始まります。 次に、正確に処理します$n$操作。 各操作で分割ポイントを選択します$(x, y)$そして、グリッドを左上、右上、左下、右下の 4 つの長方形の領域に分割します。 

現在の操作のためにグリッド内の何かを変更する前に、これら 4 つの領域を検査し、それぞれの領域に現在存在する最大値を計算する必要があります。 これら 4 つの最大値は、その操作の出力として報告されます。 それらをレポートした後、4 つの異なる値 (領域ごとに 1 つ) をその領域内のすべてのセルに追加してグリッドを更新します。 

したがって、各操作は 4 つのサブ長方形に対する「クエリ フェーズ」と、それに続く 4 つの長方形の加算を実行する「更新フェーズ」で構成されます。 

主な問題は、クエリと更新の両方が完全に動的であることです。 すべてのステップでマトリックスが変更され、今後のクエリは以前のすべての更新に依存します。 

制約$n \le 10^5$は重要な信号です。 このサイズのグリッドはすでに十分な大きさであるため、操作ごとにすべてのセルに 1 回触れることさえ不可能です。 マトリックスを更新またはスキャンするあらゆるアプローチ$O(n^2)$操作ごとにすぐに実行できなくなります。 平$O(n \log n)$セルごとまたは更新ごとのサイズは、グリッド全体のサイズを掛けると大きすぎます。 これにより、範囲更新と範囲最大クエリの両方を 2 次元ドメイン上の対数時間でサポートできる構造が強制されます。 

微妙な落とし穴は、「4 象限」と独立したデータ構造を混同することにあります。 たとえば、4 つの別々の行列を維持しようとすると、セルはクエリ点に応じて象限間を移動します。$(x, y)$したがって、静的パーティショニングは機能しません。 

もう 1 つの簡単な間違いは、更新前ではなく更新後に最大値を再計算しようとすることです。 たとえば、セルが操作全体にわたって複数の更新に含まれている場合、更新を適用した後にクエリを実行すると、必要な値とは異なる値が生成されます。 

## アプローチ

 単純な解決策は簡単です。完全な行列を保存し、各操作で必要な部分四角形を明示的にスキャンして 4 つの最大値を計算し、影響を受けるすべてのセルを反復処理して更新を適用します。 

単一の操作の場合、コンピューティング$w_1, w_2, w_3, w_4$すでに費用がかかる$O(n^2)$最悪の場合、各象限はグリッド全体をほぼカバーできるためです。 更新ステップも$O(n^2)$。 と$n$操作すると、これは次のようになります$O(n^3)$、これは完全に不可能です$10^5$。 

問題の構造は、より強力なものを示唆しています。すべての操作は、四角形の加算と四角形の最大クエリのみで構成されています。 これは、遅延伝播によるセグメント ツリーが適切に一般化される古典的な設定です。 

ただし、これは 1 次元のセグメント ツリーの問題ではありません。 グリッドは 2 次元であり、各操作は軸に沿って整列した大きな部分長方形に触れます。 これにより、範囲の追加と範囲の最大クエリの両方をサポートする 2D セグメント ツリーが実現します。 

重要な点は、ポイント クエリだけが必要なわけではないということです。 すべての操作は完全に長方形の集合体として表現されるため、完全に動的な 2D 構造を維持するだけで十分です。 各操作は、一定数の四角形クエリとそれに続く一定数の四角形更新になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(n^2)$| 遅すぎる |
 | 遅延伝播を使用した 2D セグメント ツリー |$O(n \log^2 n)$|$O(n \log^2 n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 2D グリッド上で 2 つの操作 (四角形内のすべてのセルへの値の追加と四角形内の最大値のクエリ) をサポートする動的データ構造を維持します。 これは行上のセグメント ツリーとして実装され、各ノードには列上の別のセグメント ツリーが含まれます。 

### ステップ

 1. X 軸 (行) 上にセグメント ツリーを構築します。各ノードは行の範囲を表します。 
2. X セグメント ツリー内のすべてのノードについて、Y 軸 (列) にわたるセカンダリ セグメント ツリーを維持し、最大値を保存し、範囲の加算のための遅延伝播をサポートします。 
3. クエリ四角形の場合、行範囲に重なる x ノードを再帰的に走査し、そのようなノードごとに列範囲にわたってその y セグメント ツリーをクエリして最大値を取得します。 
4. 更新四角形の場合、同様にすべての重なり合う X ノードを走査し、それぞれについて、列範囲にわたる Y セグメント ツリーに範囲追加更新を適用します。 
5. 各操作ごとに$(x, y, z_1, z_2, z_3, z_4)$、更新の前に 4 つのクエリを実行します。 

左上の長方形、右上の長方形、左下の長方形、右下の長方形。 
6. これら 4 つの最大値をクエリの直後に出力します。 
7. 次に、それぞれ 1 つの象限に対応する 4 つの範囲更新を適用します。$z_1, z_2, z_3, z_4$それぞれ。 

各操作内の順序付けは重要です。すべてのクエリは、4 つの更新のいずれかが適用される前に状態を監視する必要があります。 

### なぜ効果があるのか

 データ構造には、以前のすべての操作が適用された後のすべてのセルの正確な値が常に保存されます。 各操作は範囲の加算のみを実行するため、個々のセル履歴の再計算を必要とする操作はありません。 更新とクエリは両方とも長方形上で正確であるため、セグメント ツリーの不変条件により、すべての保留中の遅延更新の下ですべてのノードがその領域の最大値を正しく維持することが保証されます。 すべての象限操作は互いに素な四角形に分解されるため、4 つの更新は 1 つの操作内で互いに干渉せず、クエリ フェーズではグリッドの一貫したスナップショットが観察されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree2D:
    def __init__(self, n):
        self.n = n
        self.size = 4 * n
        self.tree = [[0] * (4 * n) for _ in range(self.size)]
        self.lazy = [[0] * (4 * n) for _ in range(self.size)]

    def _push_y(self, vx, vy, ly, ry):
        if self.lazy[vx][vy] != 0 and ly != ry:
            val = self.lazy[vx][vy]
            self.lazy[vx][vy * 2] += val
            self.lazy[vx][vy * 2 + 1] += val
            self.tree[vx][vy * 2] += val
            self.tree[vx][vy * 2 + 1] += val
            self.lazy[vx][vy] = 0

    def _update_y(self, vx, vy, ly, ry, ql, qr, val):
        if ql <= ly and ry <= qr:
            self.tree[vx][vy] += val
            self.lazy[vx][vy] += val
            return
        self._push_y(vx, vy, ly, ry)
        mid = (ly + ry) // 2
        if ql <= mid:
            self._update_y(vx, vy * 2, ly, mid, ql, qr, val)
        if qr > mid:
            self._update_y(vx, vy * 2 + 1, mid + 1, ry, ql, qr, val)
        self.tree[vx][vy] = max(self.tree[vx][vy * 2], self.tree[vx][vy * 2 + 1])

    def _query_y(self, vx, vy, ly, ry, ql, qr):
        if ql <= ly and ry <= qr:
            return self.tree[vx][vy]
        self._push_y(vx, vy, ly, ry)
        mid = (ly + ry) // 2
        res = 0
        if ql <= mid:
            res = max(res, self._query_y(vx, vy * 2, ly, mid, ql, qr))
        if qr > mid:
            res = max(res, self._query_y(vx, vy * 2 + 1, mid + 1, ry, ql, qr))
        return res

    def _update_x(self, vx, lx, rx, x1, x2, y1, y2, val):
        if x1 <= lx and rx <= x2:
            self._update_y(vx, 1, 1, self.n, y1, y2, val)
            return
        mid = (lx + rx) // 2
        if x1 <= mid:
            self._update_x(vx * 2, lx, mid, x1, x2, y1, y2, val)
        if x2 > mid:
            self._update_x(vx * 2 + 1, mid + 1, rx, x1, x2, y1, y2, val)
        for vy in range(1, 4 * self.n):
            self.tree[vx][vy] = max(self.tree[vx * 2][vy], self.tree[vx * 2 + 1][vy])

    def _query_x(self, vx, lx, rx, x1, x2, y1, y2):
        if x1 <= lx and rx <= x2:
            return self._query_y(vx, 1, 1, self.n, y1, y2)
        mid = (lx + rx) // 2
        res = 0
        if x1 <= mid:
            res = max(res, self._query_x(vx * 2, lx, mid, x1, x2, y1, y2))
        if x2 > mid:
            res = max(res, self._query_x(vx * 2 + 1, mid + 1, rx, x1, x2, y1, y2))
        return res

n = int(input())
st = SegTree2D(n)

for _ in range(n):
    x, y, z1, z2, z3, z4 = map(int, input().split())

    w1 = st._query_x(1, 1, n, 1, x - 1, 1, y - 1)
    w2 = st._query_x(1, 1, n, 1, x - 1, y, n)
    w3 = st._query_x(1, 1, n, x, n, 1, y - 1)
    w4 = st._query_x(1, 1, n, x, n, y, n)

    print(w1, w2, w3, w4)

    st._update_x(1, 1, n, 1, x - 1, 1, y - 1, z1)
    st._update_x(1, 1, n, 1, x - 1, y, n, z2)
    st._update_x(1, 1, n, x, n, 1, y - 1, z3)
    st._update_x(1, 1, n, x, n, y, n, z4)
```このコードは、各 x ノードがすべての列操作を内部の y ツリーに委任する 2D セグメント ツリーを実装します。 クエリ関数は任意の四角形の最大値を計算しますが、更新は追加的な変更を遅延的に伝達します。 各操作は 4 つの独立した四角形クエリに分割され、その後に 4 つの四角形更新が続きます。 

実装の微妙な詳細は、更新が適用される前にすべてのクエリが実行されることです。 この順序を混合すると状態が変化し、不正確な結果が生じる可能性があります。 もう 1 つの重要な点は、次の場合の境界処理です。$x = 1$または$y = 1$、ここで、いくつかの四角形は空になり、当然ゼロを返さなければなりません。 

## 実用的な例

 次のサンプル入力を考えてみましょう。```
3
2 3 1 2 3 4
3 2 1 2 3 4
```最初の操作の後はすべての値がゼロになるため、すべての象限の最大値はゼロになります。 最初の更新では、値が 4 つの領域に分散されます。 

| 操作 | w1 | w2 | w3 | w4 |
 | --- | --- | --- | --- | --- |
 | イニシャル | 0 | 0 | 0 | 0 |

 最初の更新を適用した後、左上、右上、左下、および右下の領域に異なる定数オフセットが設定されるようになったため、今後のクエリには累積された寄与が反映されます。 

2 番目のトレースはより小さい$2 \times 2$グリッドにより伝播がより明確になります。 

入力:```
2
1 1 5 6 7 8
```操作前はすべての値がゼロであるため、出力は次のようになります。```
0 0 0 0
```更新を適用すると、4 つの象限のそれぞれが異なる値を持つ単一のセルに縮退します。これは、象限の分離が厳密に幾何学的なものであり、値に基づいていないことを示しています。 

これらのトレースは、更新が累積的でリージョンベースであることを確認しますが、クエリでは常に完全な履歴の累積が観察されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log^2 n)$| 各操作は、2D セグメント ツリーに対して 4 つの四角形クエリと 4 つの四角形更新を実行します。 
| スペース |$O(n \log^2 n)$| x ツリー内の各ノードは、遅延伝播を使用して y ツリーを維持します。 

対数因数は、行セグメント ツリーと列セグメント ツリーの両方を走査することで得られます。 と$n \le 10^5$、これは、慎重に実装されたソリューションの実用的な制限内にとどまります。

 ## 特殊なケース

 いつ$x = 1$または$y = 1$、一部の象限が空の長方形になります。 このような場合、クエリ範囲は縮退し、ゼロを返す必要があります。 範囲が無効な場合はクエリ チェックが直ちに失敗し、セグメント ツリーのトラバーサルが発生しないため、実装ではこれが自然に処理されます。 

たとえば、次の場合$x = 1$、上部の象限は存在しません。 クエリを実行する$[1, 0]$は空の間隔として扱われ、ゼロを返します。 同じことが対称的に当てはまります。$y = 1$。 これにより、特別な場合のロジックを必要とせずに、境界での操作が一貫して動作することが保証されます。
