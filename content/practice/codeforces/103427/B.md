 ## 解決策
 ## 問題の理解

 未知の非負の整数のシーケンスが与えられます。$a_1, a_2, \dots, a_n$。 値自体の代わりに、2 つの位置の XOR が固定される形式の制約セットを受け取ります。$a_u \oplus a_v = w$。 

タスクは、そのようなシーケンスが存在するかどうかを判断するだけでなく、存在する場合は、すべての制約を満たし、すべての要素の合計を最小化するシーケンスを構築することです。 答えはこの最小可能額、または$-1$制約が互いに矛盾する場合。 

各制約は、グラフ内の 2 つのノード間の関係のように動作します。絶対値は固定されませんが、それらの間の XOR の差が固定されます。 これは、接続コンポーネント内の値が緊密に結合している一方で、基本値を選択することで異なるコンポーネントを独立してシフトできることを直ちに示唆しています。 

制約の数は多く、最大で$2 \times 10^5$、まで$10^5$ノード。二次関数や三次関数さえも除外します。$n$。 どのような解も本質的には線形に近いか、対数線形に近い必要があります。つまり、何らかの和集合構造または DFS を使用したグラフの走査が唯一の現実的な方向です。 

一貫性からは微妙な問題が生じます。 制約のサイクルを考えてみましょう。 XOR 式が矛盾した値を暗示している可能性があります。 たとえば、次のような場合です。$a_1 \oplus a_2 = 1$、$a_2 \oplus a_3 = 1$、 そして$a_1 \oplus a_3 = 0$、最初の 2 つを組み合わせると、$a_1 \oplus a_3 = 0$, したがって、これは一貫しています。 しかし、3 番目の制約が次の場合は、$1$、それはすぐに矛盾します。 

もう 1 つの微妙なエッジ ケースは、同じノードのペア間の複数の制約です。 同じペアに対して 2 つの異なる XOR 値が指定された場合、答えは即座に不可能になります。 整合性をチェックせずにエッジを上書きする単純な実装では、この競合を見逃す可能性があります。 

最後に、目的は単なる実現可能性ではなく、合計を最小化することです。 これにより、問題は純粋な制約を満たすタスクから、各接続コンポーネントにわたる最適化問題に変わります。 

## アプローチ

 強引な解釈では、すべてのノードに値を割り当て、制約を 1 つずつ満たそうとし、矛盾が現れた場合はバックトラックします。 各コンポーネントがサイクル間で制約を伝播し、すべての推測分岐を伝播する可能性があるため、これはすぐに指数関数的になります。 

より構造化されたブルートフォースは修正を試みるでしょう$a_1 = x$各コンポーネントに対して、BFS または DFS を使用して制約を伝播します。 これにより、整合性チェックインが保証されます$O(n + m)$しかし、最適化の問題は依然として残ります。値は無制限の整数であるため、考えられるすべての基本値を試すことは不可能です。 

重要な観察は、XOR 制約が相対的な差異を定義するということです。 各接続コンポーネントのルートを選択して定義すると、$a_v$それに関連して、すべてのノードには固定の式があります。$$a_v = a_{root} \oplus dist[v]$$どこ$dist[v]$ルートからのパスに沿って蓄積された XOR です。 これにより、コンポーネント内のすべての制約が単一の自由変数、つまりルート値に縮小されます。 

ここで問題は、コンポーネントごとにルート値を選択することです。$x$最小化する$$\sum_v (x \oplus dist[v])$$これは古典的なビットごとの最適化問題です。 XOR はビットごとに独立して動作するため、各ビットを最小化できます。$x$別に。 ビットごとに、コンポーネント内のそのビットが設定されているノードの数を数えます。$dist[v]$。 If more nodes would benefit from having a 0 or a 1 at the root bit, we choose the cheaper option.

 Thus each component contributes independently to the answer, and the global answer is the sum of optimal costs over components.

 ## アルゴリズムのチュートリアル

 任意のルートからの XOR 距離を維持しながら、各連結成分を個別に処理します。 

1. 各制約を考慮したグラフを作成します。$u \oplus v = w$ラベル付きの無向エッジになります$w$。 これは、一方のエンドポイントを知ることでもう一方のエンドポイントが決まることをコード化しています。 
2. 未訪問のノードごとに、それをルートとして扱う BFS または DFS を開始し、その XOR 距離を 0 として割り当てます。このルートは、そのコンポーネントの自由変数を表します。 
3. トラバース中にノードから移動する場合$u$に$v$制約あり$w$、次のように設定します。$$dist[v] = dist[u] \oplus w$$もし$v$がすでに訪問されている場合は、計算された値が既存の値と一致するかどうかをチェックして一貫性を検証します。 そうでない場合、連立方程式自体が矛盾し、答えは次のようになります。$-1$。 
4. コンポーネントが完成したら、修正を行います。$dist[v]$その中のすべてのノードに対して。 次に、ルート値の可能な限り最良の選択を計算します。$x$少しずつ。 ビット位置ごとに$b$、コンポーネント内のビットを持つノードの数を数えます。$b$セットする$dist[v]$。 ビットを設定すると$b$の$x$から 0 までの場合、寄与はそのビット内の 1 の数になります。 1 に設定すると、寄与はゼロの数になります。 私たちは小さい方を選びます。 
5. すべてのビットの寄与を合計してコンポーネントの最適コストを取得し、それをグローバルな答えに追加します。 

### なぜ効果があるのか

 BFS は、コンポーネント内のすべてのノードに、トラバーサル ツリーに沿ったすべての制約と一致する値が割り当てられることを保証します。 残りのエッジはこの割り当てに対してチェックされるため、サイクルが黙って制約に違反することはありません。 

距離がルートに対して固定されると、すべての有効な解は、コンポーネント内のすべてのノードを同じ定数で XOR することによってのみ異なります。$x$。 これは、XOR 制約が相対的な差異を保持するためです。 したがって、実行可能なすべての割り当ては、単一のルート値を選択することによって取得されます。 

XOR ではビットが混合されないため、コスト関数はビットごとに分割されます。 各ビットは、コンポーネント内のすべてのノードに対する独立した二分決定のように動作し、合計を最小化すると、各ビットの寄与を個別に最小化することになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n)]
    
    for _ in range(m):
        u, v, w = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append((v, w))
        g[v].append((u, w))
    
    vis = [False] * n
    dist = [0] * n
    sys.setrecursionlimit(10**7)
    
    ans = 0
    MAXB = 30
    
    for i in range(n):
        if vis[i]:
            continue
        
        stack = [i]
        vis[i] = True
        dist[i] = 0
        comp = []
        
        ok = True
        
        while stack:
            u = stack.pop()
            comp.append(u)
            for v, w in g[u]:
                if not vis[v]:
                    vis[v] = True
                    dist[v] = dist[u] ^ w
                    stack.append(v)
                else:
                    if dist[v] != (dist[u] ^ w):
                        ok = False
        
        if not ok:
            print(-1)
            return
        
        for b in range(MAXB):
            ones = 0
            for u in comp:
                if (dist[u] >> b) & 1:
                    ones += 1
            zeros = len(comp) - ones
            ans += min(ones, zeros) * (1 << b)
    
    print(ans)

if __name__ == "__main__":
    solve()
```グラフの構築では、各 XOR 制約が対称的にエンコードされ、トラバーサルによって値が両方向に伝播されることが保証されます。 の`dist`配列には、各コンポーネントで選択されたルートからの XOR 距離が格納され、以前に訪問したノードに遭遇すると、整合性チェックが即座に行われます。 

重要な実装の詳細は、実際の値を割り当てようとせず、相​​対的な XOR 距離のみを割り当てようとすることです。 最終的な最適化はコンポーネントが完全に解決された後に実行され、伝播と最小化の間の相互作用が回避されます。 

制約は以下によって制限されるため、最大 30 のビット ループで十分です。$2^{30}$, したがって、すべての値はその範囲内に留まります。

```単一のコンポーネントを構築します。 ノード 1 から始めて、次の結果が得られます。$dist[1]=0$、$dist[2]=1$、$dist[3]=0$。 

| ステップ | ノード | dist 割り当て | コンポーネント |
 | --- | --- | --- | --- |
 | 1 | 1 | 0 | [1] |
 | 2 | 2 | 1 | [1,2] |
 | 3 | 3 | 0 | [1,2,3] |

 各ビットについて、寄与を最小限に抑えます。 最適なルートの選択は値 [0,1,0] となり、合計は 1 になります。 

これは、ルートが固定されると、相対 XOR 構造がすべてのノードを完全に決定する方法を示しています。 

### 例 2

 入力:```
3 3
1 2 1
2 3 1
1 3 1
```トラバーサルにより次のことが得られます。$dist[1]=0$、$dist[2]=1$、$dist[3]=0$、しかし最後の制約は次のことを要求します$dist[1] \oplus dist[3] = 1$、これは 0 と評価されるため、矛盾が発生します。 

| エッジ加工 | チェック |
 | --- | --- |
 | 1-2=1 | OK |
 | 2-3=1 | OK |
 | 1-3=1 | 不一致 |

 アルゴリズムは矛盾を直ちに検出し、-1 を返します。 

これにより、サイクルの整合性チェックによって無効な XOR システムが防止されることが確認されます。

 ## 特殊なケース

 エッジ ケースの 1 つは、複数のエッジが同じノードのペア間に矛盾する制約を課す場合です。 たとえば、$1 \leftrightarrow 2$値 1 と 2 の場合、BFS は最初のエッジを使用してノード 1 からノード 2 に到達し、割り当てます。$dist[2]=1$。 2 番目のエッジに遭遇すると、チェックが行われます。$dist[1] \oplus 2 = 2$、一致しません$dist[2]=1$、即時に失敗がトリガーされ、-1 が返されます。 

もう 1 つのケースは、接続されていないグラフです。 各コンポーネントは独立して処理され、XOR 制約がコンポーネントを接続することはないため、各コンポーネントは独自の最適なルートの選択に寄与します。 このアルゴリズムはコンポーネントごとにトラバーサル状態を自然にリセットするため、干渉は発生しません。 

最後の微妙なケースは、サイクルのないツリー状コンポーネントです。 ここでは一貫性チェックがトリガーされることはなく、すべてのノードが一意の XOR 距離を受け取ります。 最適化ステップだけで最小合計が決定され、非環状構造の正確さのためにサイクル処理が必要ないことが確認されます。
