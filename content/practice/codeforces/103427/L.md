 ## 解決策
 ## 問題の理解

 まずは完全なグラフから始めます$2n$したがって、頂点のすべてのペアは最初は接続されています。 次に、次のセットが与えられます。$2n-1$ツリーを形成するエッジ、およびそれらのエッジが削除されます。 この削除後、欠落しているエッジはまさにそのツリーのエッジだけになり、他のすべての頂点のペアは接続されたままになります。 

タスクは、この残りのグラフに完全一致がいくつ存在するかを数えることです。 ここでの完全一致とは、選択することを意味します$n$すべての頂点が 1 回だけ使用されるように、互いに素なエッジを使用します。また、選択されたすべてのエッジは、削除後もまだ存在するエッジに対応する必要があります。 

制約$n \le 2000$までを意味します$4000$頂点。 一致を列挙しようとしたり、頂点のすべてのペアを直接操作しようとしたりするソリューションは、完全なグラフだけでも完全一致の数が既に存在するため、すぐに失敗します。$(2n-1)!!$、超指数関数的に成長します。 これにより、理想的には構造を意識した組み合わせまたはツリー DP アプローチが必要になります。$O(n^2)$または$O(n^3)$。 

単純だが誘惑しやすい間違いは、これを密なグラフ上の一般的な完全一致問題として扱い、サブセットに対して DP を試みることです。 それには必要になります$O(2^{2n})$と述べており、まったく実行不可能です。 

もう 1 つの微妙な落とし穴は、完全なグラフからツリーを削除しても、答えがわずかに乱れるだけであると想定していることです。 実際には、禁止エッジが 1 つだけでも一致数が大幅に変化します。これは、そのエッジが膨大な数の完全一致に関与しているためです。 

エッジ ケースの小さな例としては、ツリーが 4 つの頂点上の単純なパスである場合があります。$1-2-3-4$。 次にエッジを使用したマッチング$(1,2)$、$(2,3)$、 または$(3,4)$他のすべてのエッジが存在する場合でも、すべて禁止されています。 すべてのツリー エッジの選択を (個別に回避するのではなく) 同時に選択することだけを回避する不用意な解決策は、カウントを大幅にオーバーします。 

## アプローチ

 重要な観察は、最終的なグラフが少数の禁止エッジを含む完全なグラフであり、それらの禁止エッジがツリーを形成していることです。 したがって、ほぼ完全なグラフで完全一致をカウントしていますが、唯一の制約はツリーのエッジを選択できないことです。 

ブルートフォースの観点は、完全なグラフ内のすべての完全一致を列挙し、禁止されたエッジを使用するものを除外することです。 実現可能性を無視しても、これはすでに天文学的な規模です。 

ブルート フォースのもう少し構造化されたバージョンは、禁止されたエッジを超える包含-除外です。 ツリー エッジのサブセットごとに、それらがマッチングに表示されるように強制し、完了をカウントします。 直したら$k$ばらばらの木の端を消費します。$2k$残りの頂点は完全なグラフ内で任意に一致させることができます。 その貢献は、$(2n-2k-1)!!$、残りの頂点の完全一致の数。 

問題は、どれだけの方法を選択できるかを数えることに移ります$k$ツリー内の切り離されたエッジ。 それはまさにサイズが一致する数です$k$木の中で。 これは古典的なツリー DP 問題です。 

したがって、溶液は 2 層構造になります。 まず、すべての値を計算します。$k$、サイズが何回一致するか$k$指定されたツリーに存在します。 次に、完全なグラフからの階乗項で重み付けされた包含/除外式とそれらを組み合わせます。 

ターニングポイントは、禁止された構造がツリーであることを認識することです。これにより、その一致を指数関数ではなく DP を介して多項式時間でカウントできるようになります。

 ## アルゴリズムのチュートリアル

 任意のノード、たとえばノードでツリーをルートします。$1$。 DP は、ツリー エッジのみを使用して形成された一致をカウントします。これは、ツリー エッジが包含と除外に関係する唯一のエッジであるためです。 

1. 各ノードの DP 配列を定義します。$u$、サブツリー内の一致するエッジの数の分布を維持します。 具体的には、次のサブツリーで一致を選択する方法が何通りあるかを計算します。$u$という条件の下で、指定された数のエッジを持ちます。$u$は空いているか、DP の意味でその親とすでに一致しています。 

この分離が必要なのは、各ノードが上向きのマッチングに利用できるか、すでに親エッジによって消費されている可能性があり、これら 2 つのケースが異なる方法で伝播するためです。 

1. 各ノードを単一の頂点サブツリーとして初期化します。 リーフでは、構成は 1 つだけあり、エッジは選択されていません。 
2. ノードの子を 1 つずつ処理し、ナップサック スタイルの畳み込みを使用して DP テーブルをマージします。 マージする場合、異なるサブツリーでの一致は干渉しないため、互いに素なサブツリーからの一致の数を結合します。 

これが機能する理由は、親を介した接続が無視されると、ツリー構造によってサブツリー間の独立性が保証されるためです。 

1. 子の処理中$v$の$u$、マッチングのオプションも考慮します。$u$直接$v$木の端を使って$(u,v)$。 このエッジを使用すると、両方とも$u$そして$v$が使用できなくなり、一致するサイズが 1 つ増加します。 これにより、DP に追加の遷移が作成され、残りのサブツリーがマージされます。$v$の中へ$u$そのエッジを消費した後。 
2. DP を終了すると、次のようになります。$cnt[k]$、正確に使用するツリー内の一致の数$k$エッジ。 
3. 次に、これを包含排除原則と組み合わせます。 サイズを合わせて選ぶなら$k$禁止されたツリーのエッジでは、それらのエッジは交互の符号を使用して最終的に一致する構造に強制的に組み込まれます。 残り$2n - 2k$完全なグラフ内で頂点を自由に一致させることができ、$(2n - 2k - 1)!!$。 

したがって、最終的な答えは、$$\sum_{k \ge 0} cnt[k] \cdot (-1)^k \cdot (2n - 2k - 1)!!$$再帰式を使用して、完全なグラフ一致カウントのすべての二重階乗値を事前計算します。$(2m-1)!! = (2m-1) \cdot (2m-3)!!$。 

### なぜ効果があるのか

 最終的なグラフ内のすべての完全一致は、禁止されたツリー エッジを含めようとした場合に含まれる数によって分類できます。 包含-排他は、「ツリー エッジは使用されない」という制約を、ツリー内のすべての一致に対する交互の合計に変換します。 禁止エッジはツリーを形成するため、この合計に寄与する有効な構造は、ツリー内で正確に一致する、互いに素なエッジ セットのみです。 DP はそのような構造をすべて正確にカウントし、どの禁止エッジが選択されたかに関係なく、残りの頂点は常に完全なグラフとして動作します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

n = int(input())
N = 2 * n

g = [[] for _ in range(N + 1)]
for _ in range(N - 1):
    u, v = map(int, input().split())
    g[u].append(v)
    g[v].append(u)

parent = [0] * (N + 1)
order = []
stack = [1]
parent[1] = -1

while stack:
    u = stack.pop()
    order.append(u)
    for v in g[u]:
        if v == parent[u]:
            continue
        parent[v] = u
        stack.append(v)

dp0 = [dict() for _ in range(N + 1)]
dp1 = [dict() for _ in range(N + 1)]

for u in reversed(order):
    dp0[u][0] = 1
    dp1[u][0] = 1

    for v in g[u]:
        if parent[v] != u:
            continue

        ndp0 = {}
        ndp1 = {}

        for ku, cu in dp0[u].items():
            for kv, cv in dp0[v].items():
                ndp0[ku + kv] = ndp0.get(ku + kv, 0) + cu * cv

        for ku, cu in dp1[u].items():
            for kv, cv in dp1[v].items():
                ndp1[ku + kv] = ndp1.get(ku + kv, 0) + cu * cv

        dp0[u] = ndp0
        dp1[u] = ndp1

        new0 = {}
        new1 = {}

        for ku, cu in dp0[u].items():
            for kv, cv in dp1[v].items():
                new1[ku + kv + 1] = new1.get(ku + kv + 1, 0) + cu * cv

        for ku, cu in dp0[u].items():
            for kv, cv in dp0[v].items():
                new0[ku + kv] = new0.get(ku + kv, 0) + cu * cv

        dp0[u] = new0
        dp1[u] = new1

dp = dp0[1]

MOD = 998244353

fact = [1] * (2 * n + 1)
for i in range(1, 2 * n + 1):
    fact[i] = fact[i - 1] * i % MOD

inv2 = pow(2, MOD - 2, MOD)

def double_fact(m):
    res = 1
    for x in range(1, m + 1):
        res = res * (2 * x - 1) % MOD
    return res

ans = 0
for k, cnt in dp.items():
    m = 2 * n - 2 * k
    if m < 0:
        continue
    ways = 1
    for i in range(1, m // 2 + 1):
        ways = ways * (2 * i - 1) % MOD
    sign = -1 if k % 2 else 1
    ans = (ans + sign * cnt * ways) % MOD

print(ans % MOD)
```DP はサブツリーのマージを中心に構成されています。 各ノードはまず、空のマッチングを表す基本状態を初期化します。 子が組み込まれると、2 種類のマージが実行されます。1 つは親と子の間のエッジを使用しないもの、もう 1 つは追跡される禁止エッジのマッチングの一部としてそのエッジを選択できるようにするものです。 

2 番目のフェーズでは、各構成サイズに完全なグラフ内の完了数を乗算し、交互の符号を適用することで、ツリー マッチング上の DP を最終的な答えに変換します。 

DP 状態のサイズは急速に増大するため、実装には注意が必要です。 辞書を使用すると実装が簡単になりますが、実際にはリストベースの DP の方が高速です。

 ## 特殊なケース

 重大なエッジケースは、ツリーがパスに縮退する場合です。 その状況では、サイズ 1 の一致が禁止セット内に多数存在し、包含排除により強力なキャンセルが作成されます。 DP は 4 つの頂点に対して 3 つのシングル エッジ マッチングを正確にカウントし、最終的な交互の合計によりすべての寄与が除去されます。 

もう 1 つのエッジ ケースは、1 つの頂点を中心とする星型です。 ここでは、すべての禁止エッジが共通の頂点を共有しているため、禁止構造内に 2 以上のサイズの一致は存在しません。 DP は単一エッジの単純なカウントに減少し、最終的な合計は再び完全にキャンセルされ、完全なグラフ内のすべての完全な一致は必ず禁止エッジと相互作用する何らかの方法で中心をペアにする必要があるという事実と一致します。 

どちらの場合も、DP がツリーの構造的制約を正しく尊重し、包含/除外層がそれらの制約を最終的なカウントに適切に伝播することを確認します。
