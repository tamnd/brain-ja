 ## 解決策
 ## 問題の理解

 単一の小文字文字列が与えられ、特定のパターン、つまり文字列が何回出現したかを数えるように求められます。`"edgnb"`、連続した部分文字列として表示されます。 すべての出現は正確であり、重複していないか重複していなければなりません。パターンが完全に一致するすべての開始位置をカウントしているだけであるため、どちらも暗黙的に許可されます。 

入力サイズは 200,000 文字に達する可能性があり、すべての部分文字列を明示的にチェックするなど、二次的な動作を伴う解決策は実行不可能であることがすぐにわかります。 直接$O(n \cdot 5)$パターンの長さが固定されており小さいため、スキャンは問題ありませんが、部分文字列を繰り返し構築したり、余分なオーバーヘッドをかけて素朴にスキャンしたりするものは、線形を保つように慎重に制御する必要があります。 

微妙なエッジケースは、重複した出来事から発生します。 たとえば、次のような仮想文字列では、`"edgnbedgnb"`、位置 0 と 5 で始まる 2 つの出現があります。正しい解決策では、それらを誤ってマージしたり、重複をスキップしたりしてはなりません。 

もう 1 つの特殊なケースは、文字列が 5 文字より短い場合です。 その場合、答えは必然的にゼロになります。 たとえば、入力`"edgn"`出力する必要があります`0`完全なパターンを含めることはできないためです。 

最後に、部分一致を繰り返し含む文字列は、単純なスキャン手法を騙し、誤って再起動する可能性があります。 例えば、`"edgedgnb"`接尾辞には有効な出現箇所が 1 つだけ含まれます。 前の部分一致のような`"edg"`または`"edgn"`有効なヒットと間違えてはなりません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 あらゆる位置をスキャンします$i$文字列内で、次から始まる部分文字列があるかどうかを確認します。$i$マッチ`"edgnb"`。 パターンの長さが 5 に固定されているため、各チェックは定数時間となり、全体的な複雑さは次のようになります。$O(n)$時間。 単純な実装では、代わりにスライスを使用して部分文字列を作成する可能性があります。スライスは、この問題のサイズに対して Python で引き続き機能しますが、割り当てを繰り返すと、定数係数が不必要に増加する可能性があります。 

パターンのサイズが一定であるため、ブルート フォース アプローチは漸近的な複雑さの点ですでに最適です。 ただし、概念的な改善は、5 文字のローカル比較よりも複雑なことを行う必要がないことを認識することです。 パターンが固定されており短いため、プレフィックス関数、オートマトン、ローリング ハッシュは必要ありません。 

したがって、問題は、文字ごとの直接比較による単一の線形スキャンに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (部分文字列のスライス) | O(n) | スライスに応じて O(1) から O(n) | 受け入れられましたが、重いです |
 | 最適 (直接比較) | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力文字列を読み取る$s$。 左から右にスキャンし、各インデックスをパターンの開始点として扱います。 
2. ターゲットパターンを定義する`"edgnb"`一度。 これにより、文字列構築の繰り返しが回避され、比較が明示的に行われます。 
3. すべてのインデックスを反復処理します。$i$0から$n - 5$。 それを超えるインデックス$n - 5$残っている文字数が 5 文字未満であるため、完全な一致を開始できません。 
4. 各ポジションで$i$、5 つの文字を比較します。$s[i], s[i+1], s[i+2], s[i+3], s[i+4]$パターンの対応する文字を使用します。 すべてが正確に一致する場合、答えをインクリメントします。 
5. スキャン終了後に最終カウントを出力します。 

重要な考え方は、各インデックスが独立して扱われるということです。 パターンが十分に短いため、状態を維持するよりも再計算の方が安価であるため、一致を「拡張」したり、部分的な計算を再利用したりすることはありません。 

### なぜ効果があるのか

 あらゆる出来事が起こる`"edgnb"`独特の開始位置を持っています。 このアルゴリズムは、考えられるすべての開始位置を 1 回だけチェックし、次の 5 文字がパターンに一致するかどうかを検証します。 開始インデックスをスキップせずに出現を見逃すことはできないため、完全性が保証されます。 すべての文字が正確に一致する場合のみカウントするため、検出された各文字の正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()
pattern = "edgnb"

n = len(s)
ans = 0

for i in range(n - 4):
    if s[i] == 'e' and s[i+1] == 'd' and s[i+2] == 'g' and s[i+3] == 'n' and s[i+4] == 'b':
        ans += 1

print(ans)
```この実装では、スライスの代わりに直接文字比較を使用します。 これにより、一時的な文字列の作成が回避され、一定のオーバーヘッドを最小限に抑えてランタイムが厳密に線形に保たれます。 ループバウンド`n - 4`範囲外のインデックスにアクセスしないようにします。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    s = input().strip()
    pattern = "edgnb"

    n = len(s)
    ans = 0
    for i in range(n - 4):
        if s[i] == 'e' and s[i+1] == 'd' and s[i+2] == 'g' and s[i+3] == 'n' and s[i+4] == 'b':
            ans += 1

    return str(ans)

# provided sample
assert run("edgnb\n") == "1"

# custom cases
assert run("edgn\n") == "0", "too short"
assert run("aaaaaedgnb") == "1", "single match at end"
assert run("edgnbedgnb") == "2", "overlapping-independent matches"
assert run("edgnbedg") == "1", "partial suffix ignored"
assert run("edgnbedgnbedgnb") == "3", "multiple consecutive matches"

 ## 特殊なケース

 5 文字未満の文字列の場合、次のようになります。`"abc"`または`"edgn"`、ループ`for i in range(n - 4)`決して実行されないため、`n - 4 <= 0`。 アルゴリズムはすぐに 0 を返しますが、完全に一致するものは存在しないため、これは正しい値です。 

重なり合うパターンの場合`"edgnbedgnb"`、スキャンはすべての開始インデックスを個別にチェックします。 インデックス 0 で一致し、インデックス 5 で再び一致します。 インデックスはスキップされないため、両方の出現がカウントされます。 

パターンに似ているが後で逸脱する長いプレフィックスを含む文字列の場合。`"edgxxxxx"`、各位置は早期に文字比較に失敗し、バックトラッキングや状態追跡を必要とせずに誤検知を防止します。
