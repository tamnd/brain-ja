 ## 解決策
 ## 問題の理解

 長さの文字列が与えられます$n$そして、この文字列の空でないすべてのプレフィックスを調べます。 各接頭辞に対して、その接頭辞内の文字の位置に応じた決定論的な変換を適用します。 

変換は次のように機能します。 どのキャラクターに対しても$c$文字列の中に出現する$S$で最後に出現したものを調べます。$S$。 その位置の直後から開始して、サフィックスに出現する個別の文字の数を数えます。 そのカウントが数字になる$G(c, S)$、そしてキャラクター$c$は、その番号に対応する小文字に置き換えられます。$0 \mapsto a$、$1 \mapsto b$、 等々。 すべての文字は同じ元の文字列を使用して同時に変換されます$S$これは、マッピングが元のプレフィックスから計算され、並行して適用されることを意味します。 

すべてのプレフィックスについてこのエンコードされた文字列を計算した後、それらすべてを辞書編集的に比較し、最大のものを出力します。 

文字列の長さは最大 1000 で、最初の小文字 20 文字のみが使用されます。 この制限は、個別の文字の数が少なく制限されていることが保証され、重いデータ構造を使用せずにプレフィックスごとの状態を維持できるようにするため、重要です。 

単純な実装では、すべての接頭辞、すべての文字、最後の出現、および個別の接尾辞の数が再計算されます。 これは、慎重に実行すれば 3 次最悪のケースが発生することをすでに示唆していますが、さらに重要なのは、最初から再計算すると、プレフィックス間で再利用される構造が隠蔽されることです。 

微妙なエッジ ケースとしては、プレフィックスに現れない文字はマッピングとは無関係ですが、サフィックスの個別のカウントを計算するときに誤って含まれると、不正な実装が混乱する可能性があるということです。 もう 1 つのエッジ ケースは、エンコードがグローバル位置ではなくプレフィックス内の最後の出現に依存するため、境界をリセットせずにプレフィックス間でデータを再利用すると、誤った結果が生成されることです。 

## アプローチ

 ブルートフォースのアイデアは単純です。 プレフィックスごとに$S[0:i]$、そのプレフィックス内のすべての文字を反復処理し、プレフィックス内の最後の出現箇所を見つけてから、プレフィックスの末尾までスキャンして、その位置以降の個別の文字をカウントすることにより、エンコードされた文字列を計算します。 このスキャンはすべての文字とすべてのプレフィックスに対して行われるため、最悪の場合のコストはおおよそ次のとおりです。$O(n^3)$。 と$n = 1000$、このあたりです$10^9$Python では処理が遅すぎます。 

重要な観察点は、プレフィックスのエンコーディングは 1 文字あたり 2 つの情報、つまりプレフィックス内の最後の位置とその右側の個別の文字のセットのみに依存するということです。 これらはどちらも、プレフィックスを 1 文字拡張することで段階的に維持できます。 すべてを再計算する代わりに、最後に出現したものを更新し、現在のプレフィックスの「位置 i の後に異なる文字が何個存在するか」に答えることができる構造を維持します。 

アルファベットのサイズはわずか 20 文字であるため、接尾語にどの文字が含まれるかのビットマスクを位置ごとに維持できます。 これにより、プレフィックスを拡張するときに一定時間の更新が可能になり、それぞれの値を計算することもできます。$G(c, S)$文字ごとに一定の時間で。 

したがって、各プレフィックスについて、そのエンコーディングを次のように構築できます。$O(n \cdot 20)$、すべてのエンコードされた文字列を明示的に保存することを避け、その場で結果を比較します。

 ## アルゴリズムのチュートリアル

 1. 文字列を反復処理するときに、プレフィックスのリストを事前計算します。 ステップで$i$、接頭辞を考慮します$S[0:i]$。 
2. 現在のプレフィックス内の各文字の最後の出現インデックスを維持します。 これにより、文字ごとに、サフィックスのカウントへの寄与をどこから開始するかを決定できます。 
3. 各プレフィックスについて、サフィックスの個別の構造を計算します。 各位置がその位置からプレフィックスの終わりまでに現れる一連の個別の文字を表すビットマスク配列を構築します。 これは、プレフィックスを右から左に 1 回スキャンし、ローリング ビットマスクを更新することで計算できます。 
4. キャラクターごとに$c$プレフィックス内で、その最後の出現位置を検索します$p$。 値$G(c, S)$で始まるサフィックス ビットマスクの設定ビット数です。$p + 1$、またはゼロの場合$p$最後の位置です。 
5. 各文字をマッピングしてプレフィックスのエンコードされた文字列を構築します$c$に$chr(G(c, S) + 'a')$。 
6. このエンコードされた文字列を、辞書順を使用してこれまでに確認された最良の文字列と比較します。 現在のエンコードされた文字列が大きい場合は、回答を更新します。 
7. すべてのプレフィックスを処理した後、最適なエンコード文字列を出力します。 

### なぜ効果があるのか

 重要な不変点は、どのプレフィックス境界でも、サフィックス ビットマスク配列がそのプレフィックスのすべてのサフィックス セグメント内の個別の文字のセットを正確に正確に表すことです。 各文字のエンコーディングは、厳密に最後に出現した後の文字にのみ依存するため、ビットマスクにより、関連する個別の文字だけを正確にカウントし、それ以外はカウントしないことが保証されます。 更新はプレフィックスを拡張する場合にのみ追加的なものであるため、以前に計算されたサフィックス情報は無効になり、最後の出現位置は各プレフィックス内で一貫したままになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    n = len(s)

    best = ""

    for i in range(n):
        pref = s[:i+1]
        m = len(pref)

        # last occurrence in current prefix
        last = [-1] * 26
        for j, ch in enumerate(pref):
            last[ord(ch) - 97] = j

        # suffix distinct bitmask
        suf_mask = [0] * (m + 1)
        mask = 0
        for j in range(m - 1, -1, -1):
            mask |= (1 << (ord(pref[j]) - 97))
            suf_mask[j] = mask

        # compute encoded string
        encoded = []
        for j, ch in enumerate(pref):
            c = ord(ch) - 97
            p = last[c]

            if p + 1 >= m:
                val = 0
            else:
                val = bin(suf_mask[p + 1]).count("1")

            encoded.append(chr(val + 97))

        encoded = "".join(encoded)

        if encoded > best:
            best = encoded

    print(best)

if __name__ == "__main__":
    solve()
```コードはすべてのプレフィックスを明示的に反復します。 プレフィックスごとに、最後の出現とサフィックスのビットマスクが再計算されます。これは制約の下で許容されます。$n \le 1000$。 サフィックス ビットマスクは右から左に構築されるため、すべての位置にその右側に異なる文字の正確なセットが格納されます。 エンコード ステップでは、これらの事前計算された値を使用して、個別のセットを繰り返し再計算することを回避します。 

比較には、問題の要件に直接一致する、Python の組み込み辞書編集文字列比較が使用されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、プレフィックス内のすべての文字が同一である場合です。 入力用`aaaa`、すべての最後の出現は常に最後の位置であるため、各文字は次のようにマッピングされます。`a`。 アルゴリズムはこれを処理します。これは、最後に出現した後のサフィックス マスクが空であり、一貫してゼロが生成されるため、エンコードが安定しているためです。 

もう 1 つのエッジ ケースは、次のような個別の文字を厳密に増加させることです。`abcd`。 ここでは、最後の出現はすべて文字そのものであるため、先に進むにつれて接尾辞セットは縮小します。 エンコーディングは完全な逆構造を反映しており、アルゴリズムはサフィックス マスクを正しく計算するため、各文字は最後に出現した後に出現する文字を正確に認識します。 

最後の微妙なケースは、最適なプレフィックスが完全な文字列ではない場合です。 のために`aca`、2 番目のプレフィックスは、完全なプレフィックスよりも適切にエンコードされた文字列を生成します。 このアルゴリズムはすべてのプレフィックスを独立して評価し、すべての結果を比較するため、プレフィックス間の単調性を仮定することなく、そのようなケースを正確に識別します。
