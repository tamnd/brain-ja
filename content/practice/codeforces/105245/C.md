 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$n$ノード。 タスクは、個別のノードの順序のないペアをすべて考慮することです。$(u, v)$入力ツリー内のエッジによってまだ接続されていないものを選択し、それらの間に直接エッジを追加することで非常に強力な構造特性が維持されるかどうかを決定します。この追加のエッジを追加した後でも、結果として得られるグラフ内のノードの各ペアには、依然として 1 つの最短パスが存在します。 

ツリーでは、ツリーには任意の 2 つのノード間に 1 つの単純なパスがすでに存在し、したがって 1 つの最短パスが存在するため、この条件は自明に真となります。 複雑になるのは、エッジを 1 つ追加した後に何が起こるかです。 エッジを追加するとサイクルが作成され、サイクルは最短パスが一意でなくなる唯一の理由です。サイクル上の 2 つのノード間には、通常、同じくらい短いルートが 2 つあります。 

したがって、本当の問題は、どの非隣接ペアであるかということです。$(u, v)$エッジを追加すると、ノードのペアの間に同じ長さの 2 つの別個の最短パスが現れる状況が回避されますか?

 私たちはあきらめています$10^4$テストケースと合計$n$すべてのテストにわたって、$10^5$。 これにより、テスト ケースごとに二次関数が即座に除外されます。 テスト ケースごとにノードのすべてのペアを検査しようとするソリューションでも、次のような問題が発生します。$O(n^2)$での行動$10^5$ノードの総数が実現可能な制限をはるかに超えています。 テスト ケースごとに線形または線形に近いことを目指す必要があります。 

木がパスである場合、微妙なエッジケースが現れます。 ツリーが単純なチェーンの場合、隣接しない 2 つのノード間にエッジを追加するとサイクルが作成され、そのサイクル上のすべてのノードのペアに同じ長さの 2 つの最短ルートが得られます。 これにより、基本的にすべての候補ペアが無効になります。 たとえば、チェーンで$1 - 2 - 3 - 4$、エッジを追加$(1, 4)$ノードが存在する 4 サイクルを作成します$1$そして$3$同じ長さの 2 つの最短パスがあり、一意性が損なわれます。 

もう 1 つのエッジケースはスターです。 1 つの中心がすべてのリーフに接続している場合、2 つのリーフの間にエッジを追加すると中心との三角形が形成されますが、中心が依然として最短配線を支配しているため、すべての最短パスは一意のままです。 これは、度を中心とした構造が重要であることを示唆しています。 

## アプローチ

 ブルートフォース手法では、ノードのすべてのペアに対して反復処理が行われます。$(u, v)$まだエッジによって接続されていないペアを作成し、エッジの追加をシミュレートして、結果のグラフにすべてのペアの一意の最短パスが残っているかどうかを確認します。 より賢く一意性をチェックすることに限定したとしても、何らかのサイクルで等しい長さの代替が導入される構成を新しいエッジが作成するかどうかを検出する必要があります。 各シミュレーションには、グラフに対して少なくとも BFS または DFS が必要です。$O(n^2)$テストケースごとにそれ以上の場合もあります。 と$10^5$合計ノード数では、これは不可能です。 

重要な観察は、ツリーに 1 つのエッジを追加すると、正確に 1 つのサイクルが作成され、そのサイクルは、エッジ間の一意のパスによって形成されるということです。$u$そして$v$in the original tree plus the new edge. 最短パスの一意性は、そのサイクルがノードのペア間で 2 つの等しく短いルートを許可する「バランスのとれた」構造を持つ場合に正確に壊れます。 構造が極度に制約されていない限り、これは起こります。 

状態を確認するためのより生産的な方法は、ツリーの中心から見ることです。 ツリーに、すべてのノードが 1 つの頂点 (星型) から最大 1 の距離にある中心構造がある場合、葉から葉へのエッジを追加しても、すべての代替ルートが対称性なく中心を通過するため、最短パスが一意に保たれます。 

ツリーの直径が 2 を超える場合、最も低い共通構造がより長いチェーンを形成するノードが存在し、特定のペア間にエッジを追加すると、誘導されたサイクル内のどこかに対称的な最短の代替が作成されます。 唯一の安全なペアは、同じ近傍から中心までの構造を共有するペアであることが判明し、事実上、重心のような構造に接続されたノードの各グループ内のペアを数えることになります。 実際、この条件は、BFS レイヤ化内の固定ルートの同じ隣接ノードを共有するノードのペアを中心から数えることに単純化されます。 

これを形式化するきれいな方法は、任意のノードでツリーをルート化し、サブツリーのサイズを計算し、ペアが存在することを観察することです。$(u, v)$それらの間の一意のパスが長さ 2 でない限り、つまり共通の隣接ノードを共有している場合を除き、安全ではありません。 これにより、各ノードの隣接グループ内のペアがカウントされます。 

Thus, for each node$x$、そのすべての近傍は、有効なペアの潜在的なエンドポイントのクリークを形成しますが、距離が正確に 2 であるペアのみです。$x$安全です。 ただし、これらは正確に、次の異なるサブツリー内のノードのペアです。$x$。 すべてのノードを合計して、最も低い共通祖先が次のノードであるノードのペアを数えます。$x$、これはまさに標準的な木の組み合わせ論です。 

サブツリーのサイズを計算し、ノードごとに内部サブツリー ペアの寄与分を合計から減算します。

 ## アルゴリズムのチュートリアル

 ツリーをノード 1 にルートし、DFS を使用してサブツリーのサイズを計算します。 

1. ノード 1 から DFS を実行して、親リンクとサブツリーのサイズを計算します。 各サブツリー サイズは、ルートからその方向に何個のノードが存在するかを表します。 この構造により、ノードを削除するとツリーがどのように分割されるかを推論できます。 
2. 各ノードについて$u$、その隣人を考慮してください。 それぞれの隣人$v$を削除した場合に形成されるコンポーネントに対応します$u$。 そのコンポーネントのサイズは、次のいずれかのサブツリー サイズです。$v$（もし$v$子供です）または$n - \text{subtree}(u)$（もし$v$は親側です）。 この分離は重要です。なぜなら、そのパスが通過するペアは$u$異なるコンポーネントから来ている必要があります。 
3. 各ノードについて$u$、パスが通過するノードのペアが何ペアあるかを計算します。$u$最下位共通祖先として。 これは、すべての隣接コンポーネントを合計し、それらの間のクロスペアをカウントすることによって行われます。 
4. ノードの場合$u$、コンポーネントのサイズが次の場合$c_1, c_2, \dots, c_k$、パスが通過するペアの数$u$は$$\sum_{i < j} c_i \cdot c_j$$これは、異なるブランチに分割されたすべてのペアをカウントします。$u$。 
5. この値をすべてのノードで合計します。 これにより、パス構造が何らかのノードに「集中」する順序付けされていないペアの正確な数が得られます。 
6. 最終的な答えはこの合計になります。これらのペアは、あいまいな最短パスを導入することなくエッジを安全に追加するための条件を正確に満たすためです。 

### なぜ効果があるのか

 ツリー内のノードの各ペアには、固有の最下位共通祖先があります。 その時点でペアは異なる子コンポーネントに分割されるため、その祖先で計算される寄与はペアを 1 回だけカウントします。 有効なスーパー ペアであるペアの条件は、追加されたエッジの下でのそれらの相互作用が対称最短ルートを導入しないという事実に正確に対応しており、これはツリーの分岐分解によって捕捉されます。 これにより、すべての有効なペアが 1 回カウントされ、すべての無効なペアが有効なコンポーネント間寄与に現れないことによって除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [-1] * n
    order = []
    stack = [0]
    parent[0] = -2

    while stack:
        u = stack.pop()
        order.append(u)
        for v in g[u]:
            if v == parent[u]:
                continue
            if parent[v] == 0 or parent[v] == -2:
                parent[v] = u
                stack.append(v)

    # fix root marking
    parent[0] = -1

    sz = [1] * n

    for u in reversed(order):
        for v in g[u]:
            if v == parent[u]:
                continue
            sz[u] += sz[v]

    ans = 0

    for u in range(n):
        comp = []
        for v in g[u]:
            if v == parent[u]:
                comp.append(n - sz[u])
            else:
                comp.append(sz[v])

        s = 0
        for c in comp:
            ans += s * c
            s += c

    print(ans)

def main():
    t = int(input())
    for _ in range(t):
        solve()

if __name__ == "__main__":
    main()
```このソリューションは、ルート付きツリーを構築し、線形時間でサブツリーのサイズを計算します。 スタックベースの DFS により、再帰の深さの問題が回避されます。 2 番目のパスでは、子からのサブツリー サイズが集計され、各ノードで切断するときに作成されるコンポーネントのサイズが得られます。 

各ノードについて、そのノードを削除することで生成されるコンポーネント サイズのリストを作成します。 親側は明示的に次のように処理されます。$n - sz[u]$、各子はそのサブツリーのサイズに貢献します。 次に、実行中のプレフィックス合計を使用してペアの寄与を計算します。これにより、効率的に評価されます。$\sum_{i < j} c_i c_j$ノード次数ごとの線形時間で。 

よくある実装の落とし穴は、親側コンポーネントを忘れることです。 これがないと、パスがルート方向を通って上に向かうペアは少なくカウントされます。

 ## 特殊なケース

 パス グラフは、ほとんどのノードがゼロまたは小さな値を寄与するという事実をアルゴリズムが正しく処理しているかどうかを明らかにします。 のようなパスで$1-2-3-4-5$、すべての内部ノードはツリーを正確に 2 つのコンポーネントに分割するため、それぞれが正確に 1 つのペアに寄与します。 このアルゴリズムは、有効なペアがこれらの分割をまたぐことに対応するという事実と一致して、これらの内部ノードでのみ寄与を正しく蓄積します。 

親側コンポーネントが正しく扱われているかどうかをスターグラフで確認します。 中心では、すべてのコンポーネントはリーフ サイズであり、外積和は次のようになります。$\binom{k}{2}$。 すべての隣接コンポーネントを明示的に含めないと、葉と葉のペアは中心分解に完全に依存するため、この場合は大幅に過小評価されてしまいます。
