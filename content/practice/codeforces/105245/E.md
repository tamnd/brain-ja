 ## 解決策
 ## 問題の理解

 配列が与えられ、隣接するすべてのペアを加算または XOR によって接続できます。 それぞれの選択肢が 1 つの式を生成するため、次のようになります。$2^{n-1}$表現。 

ただし、式の値は通常の左から右の方法では計算されません。 XOR は加算前に評価されるため、連続する XOR エッジのすべての最大ブロックは 1 つの値 (そのブロック内のすべての要素の XOR) に集約されます。 この折りたたみの後、残りのすべての操作はこれらのブロック値間の加算です。 したがって、各式は配列を連続セグメントに分割したものに正確に対応し、式の値は各セグメントの XOR の合計になります。 

タスクは、そのようなすべてのパーティションにわたって、これらのセグメント合計の合計を計算することです。 

この制約により、私たちは二次関数から遠ざけられます。 すべてのテスト ケースの合計の長さは次のとおりです。$5 \cdot 10^5$したがって、どのような解も本質的に線形であるか、$n \log n$テストケースごとに。 すべてのエンドポイントのペアを反復処理すると、すぐに遅すぎます。 

一般的な失敗例は、各式を個別に処理しようとしたり、すべてのパーティションをシミュレートしようとしたときに発生します。 賢いビットマスク列挙であっても、次の場合はすぐに壊れます。$n = 40$、 以来$2^{39}$すでに実現不可能です。 もう 1 つの微妙な間違いは、周囲のカットが異なる同じセグメント構造を生成する式の数を考慮せずに、セグメントが独立して動作すると仮定することです。 

小さな例としては、$[1,2,3]$。 カットを配置しないパーティションでは XOR が得られます。$1 \oplus 2 \oplus 3$。 次のような別のパーティション$(1,2) + (3)$貢献する$(1 \oplus 2) + 3$。 同じ部分配列 XOR が複数の式に現れますが、その周囲にカットがどのように配置されるかによって多重度は異なります。 これらの多重度を正確にカウントすることが主な困難です。 

## アプローチ

 ブルートフォースソリューションでは、すべてを反復処理することになります。$2^{n-1}$演算子の選択後、セグメントごとに XOR を再計算して、結果の各パーティションを評価します。 プレフィックス XOR を使用しても、各構成には依然としてコストがかかります$O(n)$、につながる$O(n2^n)$、それは限界をはるかに超えています。 

重要な変化は、視点を逆転させることです。式を合計する代わりに、すべての式にわたる個々のセグメントの寄与を合計します。 すべての式はセグメント XOR の合計に寄与するため、すべての部分配列は$[l,r]$XOR 値に式の数を乗算した値を提供します。$[l,r]$正確に 1 つのセグメントを形成します。 

各セグメントの出現頻度を数えると、問題はすべての部分配列の重み付き合計になります。 重みは、セグメントの内側と外側に強制される演算子の選択肢の数 (2 のべき乗) にのみ依存します。 

この変革後も、直接的な$O(n^2)$すべてのセグメントの列挙は依然として遅すぎます。 残りの困難は、すべてのサブ配列に対する XOR の加重和を効率的に計算することです。 ここで、ビットの線形性が重要になります。XOR はビット単位であるため、各ビットを独立して処理でき、問題は重み付けされたサブ配列にわたるビットのパリティをカウントすることに変わります。 この構造により、ビットごとの線形時間で配列全体を動的プログラミングでスイープできるようになります。

 ## アルゴリズムのチュートリアル

 最終的な答えをすべてのサブ配列の合計として書き換えます。各サブ配列は、単一の XOR ブロックとして分離される演算子構成の数に応じて、XOR に重みを乗じた値に寄与します。 

1. サブ配列ごとに$[l,r]$、その寄与度を次のように決定します。$\text{XOR}(l,r)$演算子の選択方法の数を掛けると、$l..r$1 つの XOR セグメントになります。 これにより、セグメント内のすべてのエッジが XOR として固定され、その境界の周囲で強制的にカットが行われ、残りのエッジは自由なままになります。 
2. 自由な選択肢の数を 2 の累乗で表します。 各エッジは固定または自由なので、多重度は次のようになります。$2^{(\text{total edges}) - (\text{forced edges})}$。 強制エッジは、セグメントの長さと、配列の境界に接触するかどうかのみに依存します。 
3. 寄与分を境界ケースに分割します (セグメントが左端、右端、または両方に接触している)。 これにより、主要な均一構造が内部セグメントに加えて小さな修正を加えて分離されます。 
4. XOR 値をビット寄与に換算します。 完全な整数を合計する代わりに、各ビットを個別に処理します。 部分配列が寄与する$2^b$セグメント上のそのビットの XOR が 1 の場合。 
5. 固定ビットの場合、サブ配列上の XOR をプレフィックス値間のパリティ差として再解釈します。 のビット XOR$[l,r]$は$pref[r] \oplus pref[l-1]$。 
6. 正しいエンドポイントを修正する$r$可能なすべての期間にわたって 2 つの加重合計を維持します$l$: インデックス用に 1 つ。$pref[l-1]=0$、1 に等しいもの。それぞれ$l$重量に貢献する$w^{r-l}$、 どこ$w = 2^{-1}$モッド$MOD$、セグメント長の減衰をエンコードします。 
7.として$r$が増加すると、既存の寄与に次の値を乗算してこれらの加重合計を更新します。$w$、新しいインデックスを追加します$l=r+1$重さで$1$。 これにより、すべてのセグメントの重みが一貫した状態に保たれます。 
8. それぞれについて$r$、何個かを計算します$l$パリティ関係を使用して XOR ビット 1 を生成します$pref[r] \oplus pref[l-1]$、その後、貢献度を蓄積します。 

### なぜ効果があるのか

 任意の固定右エンドポイントで$r$、考えられるすべての左端点は最終合計に独立して寄与し、その影響は 2 つのローカル プロパティ (プレフィックス パリティと距離までの距離) にのみ依存します。$r$。 DP は、正確にこれら 2 つの情報を集約された形式で維持します。 XOR はビットごとにきれいに分割され、重み付けはセグメント長にわたって乗算されるため、異なる間の相互作用はありません。$l$集計時に値が失われます。 これにより、位置ごとの定数時間の更新となる二次スイープを削減しながら、正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353
MAXB = 29

inv2 = (MOD + 1) // 2

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        pref = [0] * (n + 1)
        for i in range(n):
            pref[i + 1] = pref[i] ^ a[i]

        pow2 = [1] * (n + 5)
        for i in range(1, n + 5):
            pow2[i] = (pow2[i - 1] * 2) % MOD

        # w^k = inv2^k
        # We maintain A0, A1 as weighted sums of indices l-1 parity
        ans = 0

        for b in range(MAXB):
            bit = 1 << b

            A0 = 0
            A1 = 0
            cur0 = 1  # l = 1 corresponds to pref[0]=0, weight w^0 = 1
            cur1 = 0

            total = 0

            for r in range(1, n + 1):
                br = (pref[r] >> b) & 1

                # XOR bit is 1 when pref[l-1] != pref[r]
                if br == 0:
                    total = (A1)
                else:
                    total = (A0)

                total %= MOD

                # contribution of all subarrays ending at r
                ans = (ans + total * bit) % MOD

                # update weights: multiply all existing l by inv2
                A0 = (A0 * inv2) % MOD
                A1 = (A1 * inv2) % MOD

                # add new l = r+1 with pref[l-1] = pref[r]
                if br == 0:
                    A0 = (A0 + 1) % MOD
                else:
                    A1 = (A1 + 1) % MOD

        print(ans % MOD)

if __name__ == "__main__":
    solve()
```コードは最初にプレフィックス XOR を構築し、サブ配列 XOR を 2 つのプレフィックス値で表現できるようにします。 ビットに対する外側のループは各バイナリ位置を分離し、XOR をパリティ条件に変換します。 

各ビットの変数は、`A0`そして`A1`プレフィックスのビット値によってグループ化された、考えられる左エンドポイントの重み付けされたカウントを保存します。 の乗算`inv2`各ステップは、セグメントを拡張すると長さが増加し、重みが 2 分の 1 に減少するという事実をエンコードします。新しいインデックスの追加は、次の位置でセグメントを開始することに対応します。 

値`total`現在の右エンドポイントと XOR ビット 1 を生成する左エンドポイントの数を計算し、これをビット値で乗算したグローバル応答に追加します。 

微妙な点は、インデックス作成にはプレフィックスの位置が使用されることです。`l-1`、状態を 1 つシフトします。 これにより、すべてのサブ配列をプレフィックス ペアの差として明確に表現できるようになります。

 ## 特殊なケース

 次のような最小限の入力$n=2$実装が単一のサブ配列の寄与を正しく処理するかどうか、および境界の重みが一貫して適用されるかどうかを明らかにします。 この場合、両方とも$[1,2]$パーティションは、オペレーターの選択全体で正確に 2 回 (オペレーター構成ごとに 1 回) カウントする必要があります。 

次のような均一な配列$[x,x,x]$パリティ動作を分離します。 同一の値に対する XOR はセグメントの長さに応じてキャンセルされるため、アルゴリズムでは、同じ XOR 結果を生成するが重みが異なる複数のパーティションを考慮する必要があります。 

厳密に交互のビット パターンにより、プレフィックス パリティの遷移が強調されます。 DP は、次の間を正しく切り替える必要があります。`A0`そして`A1`あらゆる段階で。 プレフィックスのインデックス付けにずれがあると、すぐに不正確な蓄積が発生します。 

これらの各ケースは正しく処理されます。これは、状態がプレフィックス パリティと乗算距離の重みによってのみ駆動され、どちらも入力構造に関係なく一貫性が保たれるためです。
