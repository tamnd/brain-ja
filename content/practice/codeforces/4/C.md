 ## 解決策
 ## 問題の理解

 ユーザー名登録システムを構築中です。 すべての受信リクエストには、必要なユーザー名が含まれています。 そのユーザー名がこれまでに出現したことがない場合、登録はすぐに成功し、出力されます。`OK`。 

ユーザー名がすでに使用されている場合は、まだ使用されていない名前を生成する最小の正の整数の接尾辞を付加して、新しいユーザー名を生成する必要があります。 たとえば、次の場合`alex`すでに存在するので試してみます`alex1`、 それから`alex2`など、自由な名前が見つかるまで続けます。 選択した生成名も占有されます。 

入力では、一連の登録リクエストが 1 行に 1 つずつ表示されます。 出力には、各リクエストに対するシステムの応答が同じ順序で含まれている必要があります。 

までの制約$10^5$要求は問題を完全に変えます。 以前に使用された名前を毎回スキャンするソリューションでは、速度が非常に遅くなります。 と$10^5$操作では、全体的にほぼ直線的な時間、またはそれに近い時間を目指す必要があります。 「このユーザー名はすでに使用されていますか?」という同じ質問を繰り返し行うため、ハッシュ テーブルは自然に適合します。 

厄介な点は、生成された名前自体も占有されることです。 不用意に実装すると、元の名前だけを追跡し、生成された名前を忘れてしまう可能性があります。 

次の入力を考えてみましょう。```
4
bob
bob
bob1
bob
```正しい出力は次のとおりです。```
OK
bob1
OK
bob2
```2回目のリクエスト後、`bob1`システムが生成したため、すでに占有されています。 3 番目のリクエストが明示的に要求する場合`bob1`、すでに存在している必要があります。 

多くのサフィックスがすでに占有されている場合、別の微妙なケースが発生します。```
5
a
a1
a2
a
a
```正しい出力は次のとおりです。```
OK
OK
OK
a3
a4
```常にチェックを開始する単純な実装`1`繰り返しテストするだろう`a1`、`a2`、 等々。 それでも正しい答えは得られますが、かなりの時間を無駄にします。 

もう 1 つの簡単な間違いは、元の名前自体も追跡する必要があることを忘れていることです。```
3
test
test
test
```正しい出力は次のとおりです。```
OK
test1
test2
```生成されたサフィックスのみを追跡すると、3 番目のリクエストで誤って生成される可能性があります。`test1`また。 

## アプローチ

 ブルートフォースのアイデアは、問題ステートメントの後に直接続きます。 使用されているユーザー名のセットを維持します。 新しいリクエストが到着したら、それがすでに存在するかどうかを確認します。 

存在しない場合は挿入して印刷します`OK`。 

すでに存在する場合は、サフィックスを 1 つずつ試していきます。```
name1
name2
name3
...
```最初の未使用の候補が答えになります。 

この方法は、文字通り必要なプロセスをシミュレートするため、正しいです。 問題はパフォーマンスです。 入力に次のものが含まれているとします。`a`繰り返された$10^5$回。 最初の重複チェック`a1`、次のチェック`a1`そして`a2`、次のチェック`a1`、`a2`、`a3`、 等々。 チェックの合計数は次のようになります。$$1 + 2 + 3 + \dots + (n-1)$$それは$O(n^2)$。 と$10^5$リクエスト、それはそのあたりです$5 \times 10^9$限界をはるかに超えた操作。 

重要な観察点は、ベース名に対して次に利用可能なサフィックスがすでにわかっていると、より小さいサフィックスを再度試行する必要がないということです。 

たとえば、生成した後、`alex7`、私たちはすでにそれを知っています`alex1`を通して`alex7`占領されている。 次の重複リクエストは、`alex`サフィックスから直接開始する必要があります`8`。 

これにより、問題はハッシュ マップ内で 2 つの情報を維持することに変わります。 

1. ユーザー名がすでに存在するかどうか。 
2. すべてのベース名について、次にどの接尾辞を試行するか。 

ハッシュ テーブルは平均値を示します$O(1)$挿入と検索を行うため、各リクエストを一定の予想時間内に処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n)$平均 |$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. というハッシュ マップを作成します。`mp`。 

マップにはユーザー名がキーとして保存されます。 基本名の場合、その値は次に試行する接尾辞を表します。 
2. 受信した各ユーザー名を 1 つずつ処理します。 

受け入れられたすべてのユーザー名が将来のリクエストに即座に影響するため、リクエストに順番に答える必要があります。 
3. ユーザー名がマップに存在しない場合は、印刷します。`OK`。 

これは、名前が完全に使用されていないことを意味するため、登録はすぐに成功します。 
4. このユーザー名を値とともにマップに挿入します`1`。 

値`1`これは、この名前が後で再び表示される場合、最初に試行するサフィックスは次のとおりであることを意味します。`1`。 
5. ユーザー名がすでに存在する場合は、保存されているカウンターを読み取ります。 

仮定する`mp[name] = k`。 これは、サフィックスが以下より小さいことを意味します。`k`すでに占有されているため、再度テストする理由はありません。 
6. 候補を構築する`name + str(k)`。 

これは、この基本名に対してまだ試されていない最小の接尾辞です。 
7. 生成された候補を印刷し、マップに挿入します。 

生成された名前は、明示的に要求されたユーザー名と同様に占有されるようになります。 
8.増加`mp[name]`1つずつ。 

同じベース名に対する次の重複リクエストは、次のサフィックスから継続する必要があります。 

### なぜ効果があるのか

 不変条件は次のとおりです。```
For every base username x, mp[x] always stores the smallest suffix
that has not yet been assigned for x.
```まず、挿入後、`x`初めて、最小の未使用サフィックスは次のようになります。`1`、 それで`mp[x] = 1`。 

私たちが生成するたびに、`xk`、すぐにカウンターをインクリメントします`k + 1`。 小さなサフィックスはすべて以前にすでに占有されていたため、`xk`ちょうど今占有されています。次の未使用のサフィックスは正確に`k + 1`。 

不変式が常に成り立つため、生成されるすべてのユーザー名は有効かつ最小限になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    mp = {}

    for _ in range(n):
        name = input().strip()

        if name not in mp:
            print("OK")
            mp[name] = 1
        else:
            suffix = mp[name]
            new_name = name + str(suffix)

            print(new_name)

            mp[name] += 1
            mp[new_name] = 1

solve()
```辞書`mp`同時に2つの役割を果たします。 そのキーは占有されているすべてのユーザー名を表し、ベース ユーザー名の値は次に使用するサフィックスを追跡します。 

名前が初めて登場するときに印刷します`OK`そしてそのカウンタを次のように初期化します`1`。 これは、次の重複が接尾辞を試行する必要がある不変式と一致します。`1`。 

重複したリクエストの場合、保存されているサフィックスをスキャンするのではなく、直接読み取ります。`1`また。 この 1 つの最適化により、二次関数の動作が削除されます。 

行:```
mp[new_name] = 1
```は非常に重要です。 生成されたユーザー名もすぐに予約される必要があります。 この行がないと、今後のリクエストで誤って再利用される可能性があります。 

もう一つの微妙な詳細が更新されています`mp[name]`ユーザー名を生成した後。 インクリメントを忘れると、同じサフィックスが繰り返し再利用されてしまいます。 

実装では使用します`input().strip()`各ユーザー名は独自の行に記述されており、保存された文字列内の末尾の改行文字は望ましくないからです。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def solve():
        n = int(input())
        mp = {}
        out = []

        for _ in range(n):
            name = input().strip()

            if name not in mp:
                out.append("OK")
                mp[name] = 1
            else:
                suffix = mp[name]
                new_name = name + str(suffix)

                out.append(new_name)

                mp[name] += 1
                mp[new_name] = 1

        return "\n".join(out)

    return solve()

# provided sample
assert run(
    "4\nabacaba\nacaba\nabacaba\nacab\n"
) == (
    "OK\nOK\nabacaba1\nOK"
), "sample 1"

# minimum size
assert run(
    "1\nx\n"
) == (
    "OK"
), "single registration"

# all equal values
assert run(
    "5\na\na\na\na\na\n"
) == (
    "OK\na1\na2\na3\na4"
), "repeated identical names"

# generated names later requested explicitly
assert run(
    "4\nbob\nbob\nbob1\nbob\n"
) == (
    "OK\nbob1\nbob11\nbob2"
), "generated usernames must also be reserved"

# boundary style chaining
assert run(
    "6\na\na1\na\na1\na2\na\n"
) == (
    "OK\nOK\na2\na11\na21\na3"
), "nested suffix interactions"

# larger repeated sequence
large_input = "10\n" + "\n".join(["z"] * 10) + "\n"

assert run(large_input) == (
    "OK\nz1\nz2\nz3\nz4\nz5\nz6\nz7\nz8\nz9"
), "many duplicates"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 単一のユーザー名 |`OK`| 最小入力サイズ |
 | 同一の名前が多数 | 連続接尾辞 | カウンタが正しくインクリメントされる |
 |`bob`、`bob`、`bob1`、`bob`|`bob1`占領されなければなりません | 生成された名前は予約されています。 
| 混合接尾辞チェーン | ネストされた世代を修正する | すでに数字が含まれている名前を処理します。
