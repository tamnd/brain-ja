 ## 解決策
 ## 問題の理解

 それぞれの幅と高さが指定された封筒のコレクションが与えられました。 ポストカードの寸法はすでに固定されているため、次のような最長の封筒のネスト チェーンを構築したいと考えています。 

- ポストカードは最初の封筒に収まります。 
- 次のすべての封筒は、幅と高さの両方が前の封筒よりも厳密に大きくなります。 

回転は禁止されているため、幅は幅と、高さは高さと直接比較する必要があります。 

出力は、チェーンの最大長だけでなく、ネストの昇順で並んだエンベロープ インデックスの 1 つの有効なシーケンスでもあります。 

最も重要な制約は、`n ≤ 5000`。 すべてのサブセットまたはすべての順列に対する総当り検索は不可能です。`2^5000`または`5000!`天文学的に大きいです。 一方、二次動的計画法では、`5000^2 = 25,000,000`比較は C++ では完全に現実的であり、慎重に実装すれば Python でも引き続き受け入れられます。 

問題は本質的に、両方の次元が厳密に増加する最長のシーケンスを求めることです。 これは、ソート後の最長増加サブシーケンス スタイルの動的プログラミング ソリューションを即座に示唆します。 

いくつかのエッジケースでは、誤った実装が静かに破壊される可能性があります。 

複数の封筒の寸法が同じであるとします。 

入力：```
3 1 1
2 2
2 2
3 3
```正しい出力:```
2
1 3
```二人`(2,2)`増加は両方の次元で厳密である必要があるため、エンベロープを両方チェーンに含めることはできません。 を使用した不注意な LIS 実装`>=`の代わりに`>`誤って許可してしまうでしょう。 

もう 1 つの注意が必要なケースは、エンベロープが一次元にのみ収まる場合に発生します。 

入力：```
3 2 2
3 2
2 3
4 4
```正しい出力:```
1
3
```どちらでもない`(3,2)`または`(2,3)`どちらの寸法も厳密に大きくする必要があるため、ポストカードを収納できます。 のみ`(4,4)`動作します。 ここでは、エリアまたは 1 つのディメンションのみによるフィルタリングは失敗します。 

3 番目のエッジ ケースは、はがきを収納できる封筒がない場合に発生します。 

入力：```
2 5 5
5 6
6 5
```正しい出力:```
0
```厳格な不平等が再び重要になります。 幅や高さが同じだけでは十分ではありません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 エンベロープのすべてのサブセットを試して、そのサブセット内のエンベロープを有効なチェーンに順序付けることができるかどうかを確認できます。 これが機能するのは、有効なチェーンの定義が検証しやすいためです。連続するすべてのペアは両方の次元で厳密に増加する必要があります。 

問題はサブセットの数です。 と`n = 5000`、すべてのサブセットを反復処理することさえ不可能です。 各エンベロープが多数のより大きなエンベロープに分岐する可能性があるため、可能なすべての継続を試行する再帰的検索も指数関数的に爆発的に増加します。 

問題の構造により、より明確なパスが得られます。 封筒の場合`A`封筒の前に置くこともできます`B`、 それから`B`両方の次元で厳密に大きくなければなりません。 エンベロープをソートした後、これを、エッジが常により大きなエンベロープに向かって移動する有向非巡回グラフとして考えることができます。 グラフが非巡回になると、最長パス動的計画法が自然になります。 

分類は重要な観察です。 幅と高さで並べ替えた後、有効なチェーンは並べ替えられた順序で前に進む必要があります。 次に、次を計算するだけで済みます。`dp[i] = longest valid chain ending at envelope i`以前のすべての封筒について`j`、両方の次元の場合、`j`のものより小さい`i`、 それから`i`で終わるチェーンを延長できます`j`。 

これは問題を古典的なものに変えます`O(n^2)`動的プログラミング ソリューション。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | ソーティングによる最適な DP | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての封筒を読み、元のインデックスを保管します。 

元の入力順序からインデックスを印刷する必要があるため、各封筒には`(width, height, original_index)`。 
2. はがきが入りきらない封筒を取り除きます。 

封筒は次の場合にのみ使用できます。```
width > postcard_width
height > postcard_height
```この条件を満たさないエンベロープは、有効なチェーンに出現することはできません。 
3. 残りの封筒を幅で並べ替え、次に高さで並べ替えます。 

これにより、左から右に移動しても幅が減少しないことが保証されます。 有効な遷移では以前のエンベロープのみを考慮する必要があるため、検索スペースが削減されます。 
4. 動的プログラミング配列を初期化します。 

させて：```
dp[i] = length of longest chain ending at i
parent[i] = previous envelope index in that chain
```最初は、すべてのエンベロープが長さのチェーンを形成します。`1`。 
5. 封筒ごとに`i`、以前のすべての封筒を確認してください`j`。 

もし：```
width[j] < width[i]
height[j] < height[i]
```それから封筒`i`で終わるチェーンを延長できます`j`。 

アップデート：```
dp[i] = dp[j] + 1
parent[i] = j
```これによりチェーンが長くなるたびに。 
6.最大値を持つエンベロープを見つけます`dp[i]`。 

これが最適な連鎖の終わりです。 
7. を使用してチェーンを再構築します。`parent`配列。 

最良のエンドポイントから開始し、最後まで親を逆方向に繰り返し追跡します。`-1`。 
8. 再構築したシーケンスを反転して印刷します。 

再構築は、最大のエンベロープから最小のエンベロープへ逆方向に行われます。 

### なぜ効果があるのか

 並べ替え後は、幅と高さの両方が厳密に増加する必要があるため、すべての有効なチェーンがインデックスの昇順で表示されます。 DP 移行では、現在のエンベロープに法的に先行する可能性のあるすべての以前のエンベロープが考慮されます。 以来`dp[j]`で終わる最適なチェーンがすでに保存されています`j`、それを拡張します`i`で終わる最適なチェーンを与えます`i`。 

再帰では、すべての有効な先行データが 1 回だけ探索されるため、可能性のあるチェーンが見逃されることはありません。 全体を通しての最大値`dp[i]`値は、有効なネスト チェーンの中で最も長いものです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, w, h = map(int, input().split())

    envelopes = []

    for i in range(1, n + 1):
        x, y = map(int, input().split())

        if x > w and y > h:
            envelopes.append((x, y, i))

    if not envelopes:
        print(0)
        return

    envelopes.sort()

    m = len(envelopes)

    dp = [1] * m
    parent = [-1] * m

    best_len = 1
    best_idx = 0

    for i in range(m):
        wi, hi, _ = envelopes[i]

        for j in range(i):
            wj, hj, _ = envelopes[j]

            if wj < wi and hj < hi:
                if dp[j] + 1 > dp[i]:
                    dp[i] = dp[j] + 1
                    parent[i] = j

        if dp[i] > best_len:
            best_len = dp[i]
            best_idx = i

    path = []

    cur = best_idx

    while cur != -1:
        path.append(envelopes[cur][2])
        cur = parent[cur]

    path.reverse()

    print(best_len)
    print(*path)

solve()
```最初の部分では、使用できないエンベロープをすぐにフィルターします。 これにより、残りのすべての封筒がはがきに確実に収まるため、DP が簡素化されます。 

並べ替えでは Python のデフォルトのタプル順序付けが使用されるため、エンベロープは最初に幅、次に高さの順に並べられます。 トランジションでは依然として両方の次元での厳密な比較が必要であるため、同じ幅または同じ高さによって無効なチェーンが作成されることはありません。 

DP ループは、先行エンベロープの可能性があるものとして、以前のすべてのエンベロープをチェックします。 と`5000`エンベロープの場合、最悪の場合の比較数は約 2,500 万回ですが、これは Python で反復的に実装する場合には許容可能です。 

の`parent`配列は再構築に不可欠です。 これがなければ、チェーンの最大長を計算できますが、どのエンベロープがそのチェーンを形成しているかはわかりません。 

微妙な点の 1 つは、厳密な不等式を使用することです。```
wj < wi and hj < hi
```それらを次のように置き換えると、`<=`チェーンに同じ寸法を誤って許可してしまう可能性があります。 

もう 1 つの微妙な点は、並べ替え前のフィルタリングです。 使用できない封筒が残っている場合、DP は誤ってはがきを入れることができない封筒から始まるチェーンを構築する可能性があります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | すべてのエンベロープは以前のすべてのエンベロープをチェックします。 
| スペース | O(n) | DP 配列と親配列はエンベロープごとに 1 つの値を格納します。 

と`n ≤ 5000`、二次方程式 DP は、最悪の場合でも約 2,500 万回の比較を実行します。 これは、高速入力で反復的に実装された場合、Python の制限時間内に問題なく収まります。
