 ## 問題の理解

 制約の循環配列が与えられており、総和を最小化しながらそれらを満たす非負の整数の別の配列を構築したいと考えています。 

具体的にはポジションごとに`i`、長さの連続したセグメントを調べます。`n/2`から始まる`i`、配列の末尾を包み込みます。 値`b[i]`未知の配列の対応するセグメントの合計の下限として機能します`a`。 どのポジションもきっちり参加`n/2`このような制約があり、各制約は配列の半分をカバーします。 

課題は値を選択することです`a[i]`(すべて非負、最大`10^18`) すべての半円の合計制約が満たされるように、そのようなすべての選択肢の中で、すべての合計の合計を最小化します。`a[i]`。 

この制約は、ポジションを独立して扱うことができないことを示唆しています。 各変数は正確に寄与します`n/2`したがって、局所的な貪欲な選択は、重複するスライディング ウィンドウに対して慎重に正当化される必要があります。 

入力サイズが大きいため、合計`n`すべてのテストケースにわたって、`5 * 10^5`。 これにより、候補ごとにウィンドウの合計を単純に再計算したり、ガウス消去法を使用して完全な線形システムを構築したりするソリューションは除外されます。 ソリューションは、テスト ケースごとに線形またはほぼ線形である必要があります。 

微妙なエッジケースが現れるのは、`b[i]`等しいです。 このような場合、対称構造は存在しますが、各位置が多くのウィンドウでカウントされるため、単純に貪欲な埋め込みを行うと過剰割り当てになる可能性があります。 もう 1 つのエッジ ケースは、単一の`b[i]`は大きいですが、他のものはゼロです。 最適なソリューションでは、重みを慎重に集中させますが、制約が重なり合うため、サイクルの半分にわたって重みを伝播させる必要があります。 

## アプローチ

重要な構造的洞察は、プレフィックスの合計の観点から問題を書き直し、それぞれの回数を観察することで得られます。`a[i]`すべての制約にわたって表示されます。 それぞれの要素が正確に含まれています`n/2`ウィンドウなので、すべての制約を合計すると`b[i]`、 毎`a[i]`正確に数えられる`n/2`左側に回します。 

これにより、グローバルな下限が決まります。 

の合計貢献度`a`重み付けされた寄与がすべてと一致するように、十分な大きさでなければなりません。`b[i]`。 ただし、制約はグローバルではなくローカルであるため、これだけでは十分ではありません。 

2 番目の重要なアイデアは、循環ウィンドウ構造をプレフィックス合計の差分制約システムに変換することです。 させて`p[i]`のプレフィックスの合計になる`a`。 各ウィンドウの合計は差になります`p[i + n/2] - p[i]`。 したがって、各制約は接頭辞の合計に関する線形不等式になります。`p[i + n/2] >= p[i] + b[i]`。 

これは、各ノードが反対側の半サイクル ノードに接続する、循環グラフ上の古典的な最短パス スタイルのシステムです。 目標は、サイクルを適切に展開すると、DAG のような構造における最長パス問題に対応する、プレフィックス合計の最小の一貫した割り当てを見つけることになります。 

構造がさらに簡素化されるため、`n`偶数: 各ノードは、モジュロの反対のオフセットを 1 つだけ持つペアになります。`n`。 これにより、ステップ実行を考慮した場合、インデックスのパリティに応じて 2 つのインターリーブされたチェーンが作成されます。`n/2`。 

問題を長さの 2 つの独立したサイクルに分割できます。`n/2`ペアリングによって`i`と`i + n/2`。 各ペアでは、制約はペアのノード間で最小限の交互フローを強制するシステムになります。 各コンポーネントを解決すると、サイクルに沿って必要な増分を累積し、合計を最小化する開始オフセットを選択することになります。 

最後の観察は、最適解はインデックスの半分の基本値を選択し、それによって引き起こされる強制的な差を伝播することに対応しているということです。`b[i] - b[i + n/2]`サイクルのインデックスを再作成した後の構造。 これにより、必要な増分を蓄積し、最小限の回転シフトを取ることで、問題が 1 サイクルにわたる 1 回のパスに軽減されます。

 ## アルゴリズムのチュートリアル

 1. ステップによって形成されるサイクルを考慮して、インデックスを 2 つのシーケンスに分割します`n/2`。 各インデックス`i`とペアになっています`i + n/2`。 これにより、各ウィンドウ制約がペアの位置間の関係に変換されます。 
2. 各制約を書き換える`b[i] <= sum of a[i ... i+n/2-1]`ポジションの累積和間の差異条件として`i`そして`i+n/2`。 これにより、問題はサイクル上のプレフィックス合計に関する制約に変換されます。 
3. 差分配列を定義する`d[i] = b[i] - b[i + n/2]`インデックス用`i`サイクルの前半で。 これは、ペアの位置間で、後方よりも前方にどれだけ多くの重量を流す必要があるかを表します。 
4. サイクルを 1 回実行し、これらの差異をランニングバランスに蓄積します。 このバランスは、その時点までのすべての制約を満たすために、プレフィックスの合計がどのくらい増加する必要があるかを表します。 残高がプラスになると、繰り越しが必要な必須の追加質量を示します。 
5. サイクルの開始点のすべての可能な回転を考慮して、最小の合計を計算します。 最適な解決策は、累積プレフィックス要件を最小化する開始オフセットを選択することに対応します。これは、サイクル全体にわたって最小プレフィックス合計を追跡することによって計算できます。 
6. 答えは、必要な累積正荷重の合計に、最適な開始点の選択によって引き起こされる補正を加えたものです。これにより、最小の総質量ですべてのプレフィックス制約が確実に満たされます。 

### なぜ効果があるのか

 各拘束は、正確に分離された 2 つの点のみをリンクします。`n/2`, したがって、システムは 1 次元の循環依存構造を持ちます。 プレフィックス合計に変換すると、各制約がプレフィックス値の差の下限に変わります。 すべての制約を合計すると、グローバルな一貫性条件が強制されますが、サイクル構造により独立した分岐が存在しないことが保証されます。 

実行可能な解決策はどれも、累積された下限に決して違反しないプレフィックス割り当てに対応します。 最小和ソリューションは、すべての下限を尊重しながらプレフィックス値を可能な限り低く保つことによって達成されます。これはまさに、必要な差分を貪欲に蓄積することによって実現されます。 最適な回転を選択することは、蓄積された必要な余剰が最小限になる点を選択することに相当し、すべての値が不必要に上昇しないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))
        m = n // 2

        # difference between paired constraints
        diff = [b[i] - b[i + m] for i in range(m)]

        # prefix balance over cycle
        bal = 0
        pref = [0] * (m + 1)
        for i in range(m):
            bal += diff[i]
            pref[i + 1] = bal

        total_diff = pref[m]

        # we try all rotations implicitly via prefix minimum
        min_pref = 0
        ans = 0
        for i in range(m):
            min_pref = min(min_pref, pref[i])
            ans += pref[i + 1]

        # adjust by shifting baseline to make prefix nonnegative
        ans -= m * min_pref

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、循環依存関係が半分の長さの差分配列に圧縮されます。 の`diff`配列は、ペアになった半分の間で制約がどのように比較されるかをエンコードします。 プレフィックスの蓄積は、サイクルを通過する際にどの程度の「追加要件」が蓄積されるかを追跡します。 

変数`pref[i]`累積不均衡をポジションまで保存します`i`。 この値がマイナスになる場合は、ベースラインを下方にシフトして総コストを削減できることを意味します。 だからこそ引き算するのです`m * min_pref`、これはサイクルの最適な回転点を選択することに対応します。 

最終的な蓄積は`ans`線形に移動した場合に制約によって引き起こされる強制ワークロードの合計を表します。 調整ステップにより、すべての回転にわたって実現可能な最も低いベースラインが選択されるようになります。 

## 実用的な例

 ### 例 1

 小さなサイクルを考えてみましょう。`m = 3`差分を計算すると、次のようになります。

アルゴリズムが蓄積されていく`ans = 2 + 1 + 4 = 7`、 そして`min_pref = 0`。 

結果は残る`7`つまり、回転しないと実現可能性が向上します。

### 例 2

 ## 特殊なケース

 重要なエッジケースは、次のような場合です。`b[i]`は同一です。 その状況では、すべての制約は対称的であり、最適解はゼロの定数配列になります。 アルゴリズムはこれを処理します。`diff`配列はすべてゼロになり、ゼロのプレフィックス合計とゼロ調整が生成されます。 

もう 1 つの特殊なケースは、1 つの制約のみが大きい場合です。 差分配列には、プレフィックスの蓄積を通じて伝播する単一のスパイクが含まれますが、最小のプレフィックス シフトによってベースラインが正しく再配分されるため、必要な総質量のみが導入され、過剰カウントが回避されます。 

最後に、いつ`n = 2`、サイクルは単一の制約に縮退します。 このアルゴリズムでは、1 要素の差分配列の処理が行われ、接頭辞の処理により、ローテーションの曖昧さなしに必要な最小合計が直接得られます。
