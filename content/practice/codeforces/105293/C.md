 ## 問題の理解

 私たちはモンスターの列を与えられており、それぞれが正の健康値を持っています。 呪文は数字を選択する操作です`x`、モンスターを左から右にスキャンします。 現在の体力が少なくとも以上である最初のモンスター`x`によって減少します`x`、そして呪文はすぐに止まります。 少なくとも体力のあるモンスターがいない場合`x`、呪文は何もしません。 呪文がモンスターを殺す（体力がゼロになる）か、モンスターに影響を与えられなかった場合、ゲームはただちに終了します。 

私たちはそのような呪文のシーケンスを選択し、毎回新しい呪文を選択したいと考えています。`x`、プロセスが強制的に停止される前に実行できる呪文の数を最大化します。 

重要な制約は停止条件です。モンスターをゼロにすることは許可されておらず、すべてのモンスターをミスする呪文を唱えることも許可されていません。 これは微妙なバランスを生み出します。すべての操作は現在の健康状況に「適合」する必要があり、すべてのアップデートは将来の呪文ができることを永久に再構築します。 

制約により、最大で`3 · 10^5`モンスターの数はテスト ケース全体で合計され、考えられるすべての呪文相互作用に対する二次シミュレーションは除外されます。 どのソリューションも、各テスト ケースを線形または線形に近い時間で処理する必要があります。通常、`O(n)`または`O(n log n)`。 

単純なシミュレーションでは、繰り返し選択しようとするでしょう。`x`、アレイをスキャンし、更新を適用し、失敗するまで繰り返します。 それぞれの呪文があったとしても`O(n)`、呪文の数も多くなる可能性があるため、このアプローチは潜在的に可能になります`O(n^2)`最悪の場合。 

多くのモンスターの体力が同等か非常に小さい場合、微妙なエッジケースが発生します。 たとえば、すべての値が`1`、その場合、有効な呪文は使用する必要があります`x = 1`、最初のモンスターを即座に殺し、1 回の操作でゲームを終了します。 「被害を拡大できる」と素朴に期待するかもしれませんが、左から右への停止ルールによりそれは完全に阻止されます。 

## アプローチ

 ブルートフォース解釈は文字通りゲームをシミュレートします。 呪文ごとに、さまざまな選択肢を試します。`x`、左から右へのトラバーサルをシミュレートし、配列を更新して、プロセスが停止するかどうかを確認します。 これは正しいですが、各呪文には線形時間がかかり、終了までに多くの呪文が存在する可能性があるため、根本的にコストがかかります。 総作業量は簡単に次のように低下​​します。`O(n^2)`。 

重要な構造的観察は、このプロセスが実際には柔軟な方法で複数のモンスターにダメージを分散していないということです。 各呪文は常に 1 つのモンスターにのみ影響します。つまり、体力が少なくとも 1 つ以上の最初のモンスターに影響します。`x`。 つまり、すべての操作は事実上、単一の位置に適用される制御された減算ですが、初期のモンスターが特定の位置で到達可能な位置を決定する「フィルター」として機能するという制約があります。`x`。 

このフィルタリング動作は、モンスターに到達するという単調な構造を暗示します。`i`、選択しなければなりません`x`以前のすべてのモンスターよりも大きい場合、スキャンはより早く停止します。 ということで、それぞれのポジション`i`使用可能な窓があります`x`値は、左側の最大体力と現在の残りの体力によって決まります。 

最適な戦略は、可能な限り最も保守的な方法でこれらのウィンドウを繰り返し利用することによって生まれます。常に、モンスターの体力を減らす速度を最小限に抑えながら、以前のモンスターをすべて確実に通過できる値を選択します。 これにより、各プレフィックスがどこまで「成長」できるかを追跡し、それらの寄与を合計するプロセスが削減されます。

 ## アルゴリズムのチュートリアル

 1. これまでに見られた最大の体力を維持しながら、モンスターを左から右にスキャンします。 この値は、選択した呪文値でより深いモンスターに到達するための最強の「ブロッカー」を表します。 
2. モンスターごとに`i`、その健康状態を比較します`h[i]`現在のプレフィックスの最大値を使用します。 もし`h[i]`より大きくなると、このモンスターは有効な呪文エネルギーのための新たな到達可能なスペースを導入します。 そうしないと、以前のモンスターがすでに許可していたものを超えてできることが拡張されません。 
3. 新しいプレフィックス最大値が現れたときの正の増加分のみを蓄積します。 モンスターが以前のすべてのモンスターを超えるたびに、その差は呪文の選択に新たな「使用可能な範囲」をもたらします。 
4. 最終的な答えは、アレイ全体にわたるこのプレフィックス最大値の累積拡張の合計です。 

### なぜ効果があるのか

 すべての有効な呪文は、初期のモンスターの最大体力によって制限されます。これは、その呪文がどこまで正しく伝播できるかを決定するためです。 新しいモンスターは、以前のすべての値を超えた場合にのみ、可能な個別の操作の数を増やします。その場合にのみ、新しい有効範囲が開かれるからです。`x`以前は不可能だった価値。 他のすべてのモンスターは以前の制約によって完全に支配されており、新しい独立した選択肢は作成されません。 

したがって、呪文の合計数は、プレフィックスの最大値が何倍増加するか、および合計でどれだけ増加するかによって完全に決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        h = list(map(int, input().split()))

        ans = 0
        pref_max = 0

        for x in h:
            if x > pref_max:
                ans += x - pref_max
                pref_max = x

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、アレイ全体で実行中のプレフィックスの最大値を維持します。 値がそれを超えると、その差が答えに反映されます。 これは、呪文に対する新しい独立した「容量」が作成される唯一の瞬間です。 それ以外の場合は、以前のモンスターの構造が可能なことを完全に支配します。 

よくある間違いは、スペルごとの更新をシミュレートしようとすることです。 これではすぐに遅すぎて、プレフィックスの最大遷移のみが重要であるという事実もわかりにくくなります。 もう 1 つの間違いは、各モンスターが独立して貢献すると仮定していることですが、左から右の停止ルールにより、これまでに確認された最大値まですべての決定が結合されます。 

## 実用的な例

 複数のテスト ケースを含む入力を考えてみましょう。 

### 例 1

 配列:`[3, 2, 3]`| 私 | h[i] | プレフィックス最大値 | 貢献 | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 3 | 3 | 3 | 3 |
 | 2 | 2 | 3 | 0 | 3 |
 | 3 | 3 | 3 | 0 | 3 |

 最初の要素は新しいプレフィックス最大値を確立し、3 に寄与します。後の要素はそれを超えることはないため、新しい独立した容量は追加されません。 

### 例 2

 配列:`[2, 1, 4]`| 私 | h[i] | プレフィックス最大値 | 貢献 | 答え |
 | --- | --- | --- | --- | --- |
 | 1 | 2 | 2 | 2 | 2 |
 | 2 | 1 | 2 | 0 | 2 |
 | 3 | 4 | 4 | 2 | 4 |

 3 番目のモンスターは新たな最大値を導入し、`4 - 2 = 2`。 

これらのトレースは、それらのポイントのみが呪文エネルギーを選択するための新しい有効な範囲を作成するため、以前の最大物質を超えてのみ増加していることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n) | テスト ケースごとに 1 つのパス |
 | スペース | お(1) | プレフィックスの最大値とアキュムレータのみが保存されます。 

アルゴリズムは各モンスターを 1 回だけ処理します。これは、合計が次の条件を満たすという制約の下で最適です。`n`すべてのテストケースにわたって、`3 · 10^5`。 

## テストケース```python

    sys.stdin = io.StringIO(inp)

                ans += x - pref_max

 ## 特殊なケース

 すべてのモンスターの体力が同じである場合、最初の要素の後、接頭辞の最大値は変わりません。 最初のモンスターの後に新しい到達可能な構造が導入されないことを反映して、アルゴリズムは 1 回だけ寄与します。 

配列が厳密に減少している場合、最初の要素が後続のすべての要素を支配するため、後のすべてのモンスターは呪文の能力とは無関係になります。 結果は最初の値のみに折りたたまれます。 

値が変動する場合、問題となるのは上向きの推移だけです。 中間の減少は、初期の最大値によってすでに確立されているものを超えて有効な呪文エネルギーの範囲を拡大しないため、答えには影響しません。
