 ## 解決策
 ## 問題の理解

 1 から n までの数字を含むマルチセットから始めます。 各操作では、現在存在する 2 つの値 x と y を選択し、両方を削除して、それらの差 x − y を挿入します。 このような演算を正確に n − 1 回行った後は、数値が 1 つだけ残ります。 タスクは、この最終的な残りの値が指定されたターゲット m と等しくなるように操作のシーケンスを選択できるかどうかを決定し、選択できる場合は、有効なペアのシーケンスを出力することです。 

各演算によりマルチセットのサイズが 1 つずつ縮小されるため、このプロセスは減算の 2 分木になります。すべての内部ノードが 2 つの値を結合してその差分を作成し、最終的なルートは x − y を何らかの順序で繰り返し適用した結果になります。 

n が 2 × 10^5 まで、総和も 2 × 10^5 という制約は、テスト ケースごとに線形時間でシーケンスを構築する必要があることを意味します。 すべてのペアやバックトラックを試行するシミュレーションは不可能です。O(n^2) でさえすでに大きすぎるためです。また、O(n log n) でさえ慎重に使用する必要がありますが、許容されます。 

微妙な特殊なケースは、減算が対称ではないことです。 x − y と y − x を選択すると結果の符号が変わるため、選択の順序が非常に重要になります。 たとえば、{1, 2, 3} の場合、異なる組み合わせにより、構造に応じて 0、2、-2、または 6 が生成されます。 単純な「貪欲に組み合わせるだけ」のアプローチでは、たとえ解決策が存在したとしても、ターゲット m を簡単に逃す可能性があります。 

もう 1 つの重要なエッジ ケースは n = 2 です。操作を 1 つだけ実行し、順序に応じて 1 − 2 = −1 または 2 − 1 = 1 を直接取得します。 したがって、m = ±1 のみが可能です。 他の m は直ちに不可能でなければなりません。 

## アプローチ

 ブルート フォース ビューでは、これを n 個のリーフ上に完全なバイナリ ツリーを構築するものとして扱います。ここで、リーフは 1 から n までの番号であり、各内部ノードは 2 つのサブツリーの減算です。 可能なツリーの数は超指数関数的に増加し、ツリーの形状を無視しても、各ペアの決定は多くの可能性に分岐します。 すべてのシーケンスを列挙しようとすることは、非常に小さい n を超えると完全に不可能になります。 

重要な観察は、減算は線形であり、キャンセルが可能であるということです。 すべての演算では、最終結果が {−1, 0, 1} の係数を持つ元の数値の整数線形結合であるという事実が保持されます。また重要なことに、順序を選択して符号を自由に割り当てることができます。 これは、構造を探索する必要はなく、達成可能な範囲内の任意の値に到達するように寄与を制御できることを確認するだけであることを示唆しています。 

建設的なアイデアは、1 つの「アクティブなアキュムレータ」を維持し、残りの数値を制御された方向に繰り返しマージすることです。 アキュムレータから減算するか、アキュムレータに減算するかを慎重に選択することで、最終結果を制御できます。 古典的なトリックは、最初に正と負の両方の累積を生成できるようにプロセスを調整し、次に m に正確に一致するように最終値を調整することです。 

具体的には、実行値 cur を最初は 1 として維持し、次の数値 i ごとに、m に向かってどの程度移動する必要があるかに応じて、それを cur − i または i − cur として cur と組み合わせます。 順序を常に自由に選択できるため、連続した間隔ですべての整数値にわたって cur を段階的に移動できることを保証できます。 これにより、問題は、使用可能な要素で区切られた増分を使用して 1 から m までのウォークを構築することに変わります。 

これをより構造的に理解する方法は、区間 [−S, S] (S は合計 1 + 2 + … + n) 内の任意の整数を、適切な符号の割り当てによって実現できるということです。 すべての数値は減算順序によって反転できるため、符号を効果的に選択できます。演算シーケンスはその符号の割り当てを実現するための単なる方法です。

したがって、この構築は、合計が m に等しくなるように各数値に + または - を割り当てる一連のマージを構築することになります。 m に達するまで符号を最大から最小まで貪欲に割り当て、ペアごとの減算演算を使用してその割り当てを実装します。

 ## アルゴリズムのチュートリアル

 最終値は、1 から n までの符号付き合計として構築されます。 

1. 総和 S = n(n + 1) / 2 を計算し、実現可能性を確認します。m は [−S, S] 内になければなりません。 そうでない場合は、すぐに NO を出力します。 これが必要なのは、一連の ± 割り当てがこの範囲を超えることができないためです。 
2. 現在の残りのターゲット t = m を維持します。 n から 1 までの符号を割り当てます。 
3. n から 1 までの各値 i について、その寄与を決定します。 |t| の場合 が大きく、t が正の場合、i を負にして i を減算しようとします。そうでない場合は、i を加算します。 具体的には、t > 0 の場合、-i を代入します。 t < 0 の場合、+i を割り当てます。 t = 0 の場合、任意に割り当てることができます (通常は +i)。 次に、それに応じて t を更新します。 
4. 符号を割り当てた後、数値を正の寄与者と負の寄与者の 2 つのグループに分割できます。 ここで、符号付きの意味を保持しながら、すべての正の数が 1 つの値 P に結合され、すべての負の数が 1 つの値 N に結合されるように、マルチセット演算をシミュレートします。 
5. まず、結果が正のままであることを確認しながら、x − y として 2 つを繰り返し結合することですべての正の数をマージし、次にすべての負の数を同様にマージします。 このステップは、作業リストを維持し、操作を繰り返し適用することによって実装されます。 
6. 最後に、正しい順序で最後の 1 回の減算によって、2 つの累積値を組み合わせて最終ターゲット m を生成します。 

重要なアイデアは、減算によって符号付き加算をシミュレートできること、およびその構造によって中間の部分和を表現する能力を決して失うことがないということです。 

### なぜ効果があるのか

 不変条件は、各数値 i を処理した後、符号が割り当てられた既に処理された要素の合計に等しい、部分的な符号付き合計のマルチセット表現を維持することです。 x と y を x − y に置き換えることは、線形結合で符号を再分配することと同等であるため、各マージ操作では、マルチセットが同じ符号付き合計値を表すという不変条件が保持されます。 実行可能な区間内のすべての整数は 1 ～ n の符号付き合計として表すことができ、各ステップで表現可能性が維持されるため、最終的には正確に m に到達します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n, m = map(int, input().split())
        S = n * (n + 1) // 2
        
        if m < -S or m > S:
            out.append("NO")
            continue
        
        # We construct a simple greedy sign assignment
        # target t is what we still need to achieve
        tval = m
        sign = [0] * (n + 1)  # +1 or -1
        
        for i in range(n, 0, -1):
            if tval > 0:
                sign[i] = -1
                tval -= -i
            else:
                sign[i] = 1
                tval -= i
        
        # Now tval should be 0
        # Build operations
        pos = []
        neg = []
        for i in range(1, n + 1):
            if sign[i] == 1:
                pos.append(i)
            else:
                neg.append(i)
        
        ops = []
        
        # merge positives
        if pos:
            cur = pos[0]
            for x in pos[1:]:
                ops.append((cur, x))
                cur = cur - x
        
        # merge negatives
        if neg:
            cur2 = neg[0]
            for x in neg[1:]:
                ops.append((cur2, x))
                cur2 = cur2 - x
        
        # combine
        if pos and neg:
            ops.append((cur, cur2))
        
        out.append("YES")
        for a, b in ops:
            out.append(f"{a} {b}")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```表現可能な範囲を超える構築はできないため、このソリューションは最初に総和境界を使用して実現可能性をチェックします。 次に、各数値にターゲット m に一致する符号を貪欲に割り当て、大きいものから小さいものへと順に動作するため、残りのギャップが予測どおりに縮小しながら、残りの柔軟性が維持されます。 

符号の割り当て後、同じ代数の組み合わせを実現する有効な減算演算のシーケンスを明示的に構築します。 正のグループと負のグループは、符号の競合が早期に混在しないように個別にマージされ、その後、最後のマージによって 2 つの累積された値がターゲット式に結合されます。 

よくある落とし穴は、サインを選択した後はどんな組み合わせの順序でも機能すると仮定することです。 早すぎる混合は意図した構造を破壊する可能性があるため、これは誤りです。 正の集計と負の集計に分離することで、正確性が保たれます。

 ## 特殊なケース

 デリケートなケースの 1 つは、n = 2 の場合です。アルゴリズムの符号割り当てにより有効な分割が生成されますが、マージ ステップでは単一の操作を直接出力する必要があります。 たとえば、n = 2 および m = 1 の場合、2 が負、1 が正になるように符号を割り当てます。その後、マージによってターゲットを生成する減算が 1 つだけ生成されます。 

もう 1 つのエッジ ケースは、m が可能な最大値または最小値の合計に等しい場合です。 このような場合、すべての符号が均一になり、アルゴリズムは固定された順序で繰り返し減算を行うように退化します。 同一符号のグループをマージすると正確さが保たれるため、この構築は引き続き機能しますが、到達可能な結果セットが変更される可能性があるため、早まってグループを混合しようとしないことが重要です。
