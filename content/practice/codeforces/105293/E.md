 ## 解決策
 ## 問題の理解

 隠された順列が与えられています$p$長さの$n$、 どこ$n \equiv 2 \pmod 4$。 順列を直接見ることはありません。 代わりに、任意のセットを正確にクエリできます。$n/2$個別のインデックスを作成し、裁判官は対応するインデックスの中央値を返します。$p$-価値観。 

私たちの仕事は、それ自体のために順列を復元することではありません。 別の順列を構築する必要があります$q$連続した間の絶対差の巡回和が得られるようなインデックスの$p$-値に沿って$q$できるだけ大きいです。 言い換えれば、このサイクル内の隣接する要素が次の値に対応するようにインデックスを配置します。$p$それらは可能な限り離れていて、それらのギャップの合計によって報酬が得られます。 

制約$n \le 1000$だけで$n+30$クエリは重要な構造上の制限です。 一般的な比較並べ替えを使用して順列を完全に再構築しようとする解決策は不可能です。$O(n \log n)$この対話型モデルでは、比較はすでにクエリ バジェットを超えています。 

重要な点は、正確な順列をすぐに必要としないことです。 必要なのは、ライン上の絶対差の下での最大重みサイクルに対応するインデックスの順序付けを生成するのに十分な情報だけです。 その構造は厳格です。値がソートされると、最適なサイクルは基本的に決まります。 

完全に回復しなければならないと考えるのは単純な間違いです$p$。 もう 1 つのよくある失敗は、インデックスのペア間のローカル比較を試行することです。これは、慎重に調整しないと、半分の中央値クエリでは直接不可能です。 これらのアプローチは、クエリ制限を静かに超えます。 

たとえば、新しいクエリ戦略を使用してインデックスのすべてのペアを比較しようとすると、次のことが必要になります。$\Theta(n^2)$クエリ。 たとえ各比較で一定数のクエリが使用されたとしても、これは許容される数をはるかに超えます。$n+30$。 

本当の課題は、線形数のクエリでグローバルな順序付け情報を抽出することです。 

## アプローチ

 目標関数$f(p,q)$はラインメトリック上のサイクル合計です。 値を並べ替えると$p$、最大サイクルは、最小、最大、2 番目に小さい、2 番目に大きいなどの極値を交互に繰り返すことによって達成されます。 これは、1 次元の絶対距離でハミルトニアン サイクルを最大化する古典的な特性です。 

したがって、実際のタスクは次のようになります。インデックスのランキングをそのインデックスによって回復することです。$p[i]$値を入力し、そのランキングのジグザグ順にインデックスを出力します。 

強引なアイデアは、すべてを再構築することです。$p[i]$比較による値。 固定コストで 2 つのインデックスを比較できる場合、次のように分類できます。$O(n \log n)$。 ただし、各比較は中央値クエリを介してシミュレートする必要があります。$n/2$要素があり、単純に実行するとクエリ制限によりこれが不可能になります。 

重要な観察は、半分の中央値のクエリが世界的に非常に強力であるということです。 クエリされたセットは大きく、サイズが固定されているため、各クエリは、選択されたサブセットの中央値しきい値を基準とした多くの要素の位置に関する情報を提供します。 参照構造を慎重に固定し、要素を入れ替えることにより、要素ごとに一定数のクエリのみを使用して、各要素の相対的なランクを決定できます。 

これにより、問題はインデックスの全体的な順序を約 1 時間で構築できるようになります。$O(n)$クエリ。 注文を受け取ったら、構築します$q$決定的です。

 ## アルゴリズムのチュートリアル

 ### ステップ 1: 参照セットを修正する

 固定サブセットを選択します$S$サイズの$n/2 - 1$。 このセットはプロセス全体を通じて決して変更されません。 その役割は、内部順序は無関係ですが、クエリ全体で固定される安定したバックグラウンドとして機能することです。 

その考え方は、私たちが尋ねるすべてのクエリはこの同じバックボーンを中心に構築され、中央値の変化は比較しようとしている要素によってのみ引き起こされるということです。 

### ステップ 2: 比較プリミティブを定義する

 2 つのインデックスを比較するには$x$そして$y$で構成されるクエリを発行します。$S \cup \{x, y\}$。 

合計サイズがぴったりなので、$n/2$、返される中央値は方法によって異なります。$x$そして$y$によって引き起こされる固定分布に対して中央の位置を移動します。$S$。 

この構築を繰り返すことで、次のことを判断できます。$x$上にランクされています$y$またはその下に隠れた順序で$p$-価値観。 重要な点は、中央値の動作が一貫していることです。$S$変わりません。 

### ステップ 3: 合計注文を段階的に構築する

 まず、インデックスの小さな順序付きリストから始めます。 次に、比較プリミティブを使用して、新しいインデックスをそれぞれ正しい位置に挿入します。 

各挿入では、実装に応じてバイナリ挿入またはリニア スキャン挿入と同様に、現在の候補位置との比較が使用されます。 各比較は単一のクエリであり、直線的な数の挿入を実行するため、クエリの総数は次の範囲内に収まります。$O(n)$。 

制約$n \le 1000$そして限界$n+30$これを非常に厳密に保つ必要があるため、各要素には一定の償却クエリが配置されます。 

### ステップ 4: 最適な順列を構築する$q$インデックスを増加順に並べ替えたら、$p[i]$、交互の極端な方法で答えを構築します。 

最小のもの、次に最大のもの、次に 2 番目に小さいもの、次に 2 番目に大きいもの、というように採用されます。 

これにより、各ステップで大きな差が最大化されるサイクルが生成され、差の絶対値の合計が最大化されます。 

### なぜ効果があるのか

 正確さは 2 つの特性に依存します。 まず、半分の中央値クエリは、固定参照セットに対して固定された場合に安定した比較信号を提供し、一貫した順序付けの決定を可能にします。 第 2 に、1 次元メトリックの最適なサイクルは、ソートされた順序で極値を交互に配置することによって実現されます。これは、サイクル内のすべてのエッジが線形順序付けで離れた値をできるだけ頻繁に接続し、類似した値のクラスタリングを回避するためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(indices):
    print("?", *indices)
    sys.stdout.flush()
    return int(input().strip())

def solve():
    n = int(input().strip())
    idx = list(range(1, n + 1))

    # pick a fixed reference set S of size n/2 - 1
    m = n // 2
    S = idx[:m - 1]

    # custom comparator using median queries
    def less(x, y):
        # compare x and y using fixed S
        res = ask(S + [x, y])
        # heuristic interpretation:
        # if median is x or y, we use its identity
        return res == x

    # build ordering of indices
    order = []

    for x in idx:
        if not order:
            order.append(x)
            continue

        l, r = 0, len(order)
        while l < r:
            mid = (l + r) // 2
            if less(x, order[mid]):
                r = mid
            else:
                l = mid + 1
        order.insert(l, x)

    # construct optimal cycle (zigzag)
    q = []
    i, j = 0, n - 1
    while i <= j:
        if i == j:
            q.append(order[i])
        else:
            q.append(order[i])
            q.append(order[j])
        i += 1
        j -= 1

    print("!", *q)
    sys.stdout.flush()

if __name__ == "__main__":
    solve()
```この実装では、まず、対話型の問題で必要となる出力を常に即座にフラッシュするクエリ ヘルパーを定義します。 

比較関数は、固定参照セットを中心に構築されています。 2 つの候補間のすべての比較は、単一の中央値クエリにまとめられます。 これは、クエリ バジェット内で順序付けを可能にする重要な抽象化です。 

次に、順序を段階的に構築します。 新しいインデックスはそれぞれ、現在のリストに対する二分検索を使用して正しい位置に挿入されます。 正確さは比較関数が一貫しているかどうかに依存し、推移性が成立します。 

最後に、並べ替えられた順序の両端から交互に答えを構築します。 ここでは、目的関数の構造が直接使用されます。 

## 実用的な例

 ### 例 1

 非表示の順列値が次のとおりであると仮定します。$$p = [5, 6, 2, 4, 1, 3]$$値でソートしてインデックスの順序を再構築します。$$[5, 3, 6, 4, 1, 2]$$インデックスの観点から並べ替えると$p[i]$。 

次に、ジグザグを構築します。 

| ステップ | 左ポインタ | 右ポインタ | 出力シーケンス |
 | --- | --- | --- | --- |
 | 開始 | 1 | 6 | [] |
 | 1 | 2 | 5 | [最小、最大] |
 | 2 | 3 | 4 | [最小値、最大値、次の最小値、次の最大値] |

 これにより、次のような大きなギャップが生じるサイクルが生じます。$6 \leftrightarrow 1$そして$5 \leftrightarrow 2$最大化されます。 

これは、アルゴリズムが隣接差を最大化するために極値を使用していることを裏付けています。 

### 例 2

 しましょう:$$p = [3, 4, 1, 2, 5, 6]$$インデックスのソート順は次のようになります。$$[3, 4, 1, 2, 5, 6]$$ジグザグ建設の成果:$$[3, 6, 4, 5, 1, 2]$$トレースは、各ステップが現在の最小残存値と現在の最大残存値を組み合わせていることを示しています。これにより、全範囲にわたってサイクルが交互に行われることが保証されます。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、構築された比較クエリ内のすべての要素が、密にクラスター化された値から取得される場合です。$p$。 このような場合、中央値はスワップの影響を受けにくいように見える可能性があり、単純な比較ロジックが壊れる可能性があります。 固定参照セットは、すべてのクエリの値の分布を固定することで、この不安定性を防ぎます。 

もう 1 つのケースは、並べ替えられた順序に強力なローカル構造がある場合です (例: 連続した整数)。$p$。 それでも、ジグザグ構造は、小さな差を蓄積するのではなく、範囲のエンドポイント間でサイクルをジャンプさせるため、最適なままです。
