 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 目標は、演算を繰り返し適用して、最終的に配列内のすべての要素が非正になるようにすることです。 

ワンオペレーションはこんな感じです。 インデックスを選択します$i$。 その位置の要素は次のように減少します。$a$、配列内の他のすべての要素は ずつ減少します。$b$、 どこ$a > b > 0$。 したがって、各操作には減算という「全体的な効果」があります。$b$すべてから、さらに追加の引き算を加えます。$a-b$選択した 1 つの位置にのみ配置されます。 

タスクは、どの要素も厳密に正のままにならないように、必要なそのような演算の最小数を見つけることです。 

重要な制約は、すべてのテスト ケースにわたる要素の合計数が最大であることです。$2 \cdot 10^5$、値は最大で大きくなる可能性があります。$10^9$。 各操作が配列全体に影響を与えるため、操作を直接シミュレートしようとするソリューションは遅すぎます。 

素朴な解釈では、すべての値が非正になるまで操作を繰り返し適用することを提案します。 値が大きく、多くの操作が必要になる可能性があり、シミュレーションが実行不可能になる可能性があるため、これはすぐに失敗します。 

すべての数値がすでに非正である場合、微妙なエッジ ケースが発生します。 たとえば、配列が次の場合、`[-1, -2, 0]`の場合、操作は必要ないため、答えはゼロです。 符号に関係なく要素を盲目的に「修正」しようとするアプローチでは、ここでの操作が誤ってカウントされます。 

もう 1 つの重要なコーナーは、1 つの要素だけがプラスの場合です。 インデックスを選択すると、より大きな減少が得られるため、$a$、他のすべてはのみを取得します$b$、最適な操作の構造は非対称になります。 すべての要素を個別に扱うと、その共有された削減効果を捉えることができなくなります。 

## アプローチ

 強引なアイデアは、操作をシミュレートすることです。 各ステップで、考えられるすべてのインデックスの選択を試した後、配列を再計算します。$i$、すべての値が非正になるまで再帰的に続行し、すべてのシーケンスの最小値を取得します。 これは完全な決定木を探索するため、原理的には正しいですが、各操作は$O(n)$、操作の数も多くなり、テスト ケースごとに指数関数的または少なくとも二次関数的な動作が発生する可能性があります。 と$n$まで$2 \cdot 10^5$、これは不可能です。 

重要な観察は、すべての操作には 2 つの要素があるということです。$b$アレイ全体にわたって、さらに$a-b$選択した 1 つの位置に適用されます。 つまり、その後$k$操作により、すべての要素が減少しました$k \cdot b$、さらに一部の要素は、特別なインデックスとして選択された回数に応じて追加のペナルティを受けています。 

したがって、操作を 1 つずつ考える代わりに、各インデックスが何回「選択」されるかを考えることができます。 要素の場合$c_i$選択されています$x_i$回の場合、最終的な値は次のようになります。$$c_i - k \cdot b - x_i \cdot (a-b)$$どこ$k = \sum x_i$。 

すべての最終値を次のようにしたいと考えています。$\le 0$。 再配置すると制約が与えられます。$$x_i \cdot (a-b) \ge c_i - k \cdot b$$これにより、すべての変数がリンクされます$k$ですが、修正すると構造が単純になります。$k$。 操作の数が固定されている場合、各要素に必要な「追加ブースト」の数を計算し、必要なブーストの合計を複数の要素に分散できるかどうかを確認できます。$k$操作。 

これは、貪欲な実現可能性チェックにつながります。$k$、各要素を非正にプッシュするために特別なインデックスとして選択する必要がある回数を計算し、これらの要件を合計し、それが以下に適合するかどうかを確認します。$k$。 実現可能性は単調なので、$k$、答えを二分探索できます。

 ## アルゴリズムのチュートリアル

 1. 候補となる演算数を固定する$k$。 すべての要素は次のように削減されます$k \cdot b$自動的に。 

これにより、残された唯一の自由、つまり各インデックスが「特別な」要素として選択される頻度が分離されます。 
2. 各要素について$c_i$、グローバル削減後の残りのプラスの余剰を計算します。$$r_i = c_i - k \cdot b$$もし$r_i \le 0$、この要素はすでに安全です。 
3. もし$r_i > 0$、必要な追加選択の数を決定します。 それぞれの選択が貢献します$a-b$、 それで：$$x_i = \left\lceil \frac{r_i}{a-b} \right\rceil$$これは最小回数インデックスです$i$選ばなければなりません。 
4. すべてを合計する$x_i$。 これは、配列全体で必要な「特別な選択肢」の総数を表します。 
5. この合計を次と比較します。$k$。 合計が$\le k$、 それから$k$必要な特別な選択をすべて操作間で分散できるため、操作だけで十分です。 さもないと、$k$小さすぎます。 
6. 最小の二分探索$k$実現可能性チェックに合格したもの。 

正確さは、各操作が「特別選択予算」の 1 単位を正確に提供するという事実にかかっており、全体的な削減が固定されると、各要素は独立して一定数のそのような単位を必要とします。 

### なぜ効果があるのか

 固定後$k$、すべての操作はちょうど 1 つのグローバルな減少に寄与します。$b$、そしてちょうど 1 つの追加の局所的な減少$a-b$。 これにより、問題は配布と同等になります。$k$インデックス間で同一のトークン。各インデックスは$i$非正にするには、最小限の数のトークンが必要です。 実現可能性チェックでは、この配布が可能かどうかを正確に把握します。 増えてからは$k$利用可能なトークンが増えるだけで、必要なトークンも減ります$r_i$、実現可能性は単調であるため、二分探索が有効になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(k, a, b, arr):
    need = 0
    diff = a - b
    for x in arr:
        r = x - k * b
        if r > 0:
            need += (r + diff - 1) // diff
    return need <= k

def solve():
    t = int(input())
    for _ in range(t):
        n, a, b = map(int, input().split())
        arr = list(map(int, input().split()))

        lo, hi = 0, 2 * 10**9

        while lo < hi:
            mid = (lo + hi) // 2
            if can(mid, a, b, arr):
                hi = mid
            else:
                lo = mid + 1

        print(lo)

if __name__ == "__main__":
    solve()
```機能`can`固定数の操作の実現可能性条件をエンコードします。 引き算`x - k * b`すべての操作の均一な効果を取得します。 正でない値はすでに満たされているため、正の残差のみが問題になります。 

天井分割`(r + diff - 1) // diff`残りのポジティブ性を完全に補正するために要素を何回選択する必要があるかを計算します。 すべての要素にわたってこれらを合計すると、特別な選択に対する総需要が測定されます。 

答えは最大でも次のオーダーであるため、バイナリ検索の境界は寛大に設定されています。$\max(c_i) / b$、制約がある場合は、大きな固定上限を使用するのが安全です。

 ## 特殊なケース

 すべての要素がすでに非ポジティブである場合、実行可能性チェックはすぐに true を返します。$k = 0$なぜなら、すべての残留物が$r_i \le 0$, そのため、必要なブーストは蓄積されません。 したがって、二分探索はゼロ演算に収束します。 

1 つの要素だけが正の場合、次のようにします。`[10, -5, -2]`の場合、アルゴリズムは問題を、単一のインデックスを何回選択する必要があるかを見つけることに縮小します。 それぞれの操作は次のように役立ちます。$a$に対して$b$ただし、定式化では必要なブーストを残差の天井除算として正しくカウントしており、二分探索はゼロ未満に押し上げるために必要な正確な最小演算数に収束します。 

すべての要素が等しく、正である場合、実現可能性チェックによって必要なブーストが均等に分配されます。 のために`[x, x, x]`、各要素は同一の要件を独立して計算し、合計制約は演算が共有されるという事実を捉え、各要素が独立して解決された場合に発生する過小評価を防ぎます。
