 ## 解決策
 ## 問題の理解

 重みのコレクションがあります。 私たちはそれらの質量の複数の集合を知っていますが、物理的な重さは区別できないため、どの物体がどの質量を持つのかはわかりません。 友人に 1 つのリクエストをすることがあります。重みの数を選択してください。`k`そして総質量`m`、そして友人は正確に任意のグループを返します`k`質量の合計が次になる物理的な重さ`m`。 

戻ってきたグループを見ると、物理的な重量によっては質量が保証されている場合があります。 タスクは、正確な質量が判明する重りの数ができるだけ多くなるようにリクエストを選択することです。 

重要な問題は、友人が有効なグループを選択できることです。 グループが役立つのは、クエリに対する考えられるすべての答えが、いくつかの物理的重量について同じ情報を提供する場合に限られます。 

重みの数は最大 100 で、すべての質量は最大 100 です。これにより、可能な合計質量は最大 10000 になります。すべてのサブセットを試行するソリューションは不可能です。$2^{100}$サブセット。 解決策$O(n^2 \cdot \text{sum})$選択した重みの数とその総質量を含む状態の数は約 100 万であるため、これは実現可能です。 

一見合理的と思われるアプローチが失敗するケースがいくつかあります。 

重みが次のようになると仮定します。```
4
1 2 2 4
```合計質量 4 の 2 つの重りを要求した場合、考えられる唯一のグループは質量 2 の重りのペアです。 答えは`2`、これら 2 つの物理的な重さが判明するためです。 

合計質量 5 の 2 つの重みを要求した場合、返されるペアは質量 1 と 4 の重みです。 ただし、返された 2 つの物理的オブジェクトは互いに区別できないため、これら 2 つは個別に識別されません。 残された 2 つの重みは両方とも質量 2 であるため、ここでも 2 つの重みだけが明らかになります。 物理的な重みの代わりに有効なサブセット内の質量の数を数える解決策では、誤って 4 と答えてしまいます。 

もう 1 つのエッジ ケースは、すべてのウェイトが同じ質量を持つ場合です。```
5
7 7 7 7 7
```すべての物理的な重さは、何かを尋ねる前からすでに質量 7 であることがわかっているので、答えは次のとおりです。`5`。 クエリを作成した後に一意のサブセットのみを検索するアプローチでは、誤って何も見つかりません。 

3 番目のケースは、異なる質量が 2 つしかない場合です。```
6
3 3 3 8 8 8
```1 つのタイプのすべての重みを要求すると、すべての重みの正確な ID が明らかになります。 選択したグループがわかったら、残りの重みは他の質量を持つ必要があります。 答えは`6`。 

## アプローチ

 直接的なアプローチでは、考えられるすべてのクエリを列挙します。`(k, m)`、次に、そのクエリに答えることができるすべてのサブセットを確認します。 答えは友人が返す可能性のあるすべてのグループによって決定されるため、これは概念的に機能します。 ただし、サブセットの数は指数関数的です。 100 個の重みを使用すると、次のことが可能になります。$2^{100}$グループが存在する可能性があるため、このメソッドは実行を開始することさえできません。 

有益な観察は、クエリが成功するには、すべてが同じ質量を持つ重みを識別する必要があるということです。 返されたグループに 2 つの異なる質量が含まれている場合、通常、そのグループ内の物理オブジェクトを分離することはできません。 たとえば、質量 1 と 4 を含む返されたペアは、2 つのオブジェクトが次のとおりであることを示しているだけです。`{1,4}`、どのオブジェクトがどれであるかではありません。 

したがって、クエリによって強制できる等質量重みの最大数を見つける必要があります。 求めることを検討してください`k`総質量が`k * w`。 このサイズと合計を持つすべてのサブセットが質量の重みのみで構成されている場合`w`、その後、考えられる答えはまさにそれらを明らかにします`k`重み。 

残りのタスクは、どのサイズと合計のグループが存在するかを確認することです。 ナップザック動的プログラミングを使用します。 させて`dp[c][s]`を含むサブセットの数になります。`c`重量と総質量`s`。 質量値の場合`w`それが現れる`cnt[w]`回、選択`k`これらの重みは正確に得られます`C(cnt[w], k)`可能な物理サブセット。 DP がサイズを持つサブセットの総数を指定した場合、`k`そして合計`k*w`がまさにこの値である場合、そのようなすべてのサブセットは質量のみから作成されます`w`。 これはつまり`k`重みを特定することができます。 

1 つまたは 2 つの異なる質量という特殊なケースは、1 つのクエリで 2 つのグループを完全に分離できるため、個別に処理されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n^2 \cdot S)$|$O(n \cdot S)$| 承認済み |

 ここ`S`すべての質量の合計であり、最大でも 10000 です。 

## アルゴリズムのチュートリアル

 1. 異なる質量値がいくつ出現するかを数えます。 2つまであれば答えてください`n`すぐに。 0、1、または 2 つの可能な質量タイプを使用して、1 つのクエリで常にあらゆる物理重量を区別できます。 
2. 選択された重みの可能な数と総質量ごとにサブセットがいくつ存在するかを数える動的プログラミング テーブルを構築します。 

ステートには、クエリがユニークな構造を持っているかどうかを判断するために必要な情報のみが格納されます。 サブセット自体を再構築する必要はありません。 
3. 質量値ごとに`w`そして考えられるすべての数字`k`この質量の重りの状態を確認してください`(k, k*w)`。 

値`dp[k][k*w]`を要求することで返されるすべてのサブセットをカウントします。`k`総質量の重量`k*w`。 
4. この値を選択する方法の数と比較します。`k`間のオブジェクト`cnt[w]`質量を持つ物体`w`、つまり`C(cnt[w], k)`。 

それらが等しい場合、このクエリのすべての有効なサブセットは質量のみから作成されます。`w`重み。 クエリによって明らかになるのは、`k`重みがあるので、回答を更新します。 
5. 有効な最大値を出力します`k`。 

なぜ効果があるのか:

 クエリでは、返されたオブジェクトが単一のマス カテゴリに強制的に属している場合にのみ、個々の重みが明らかになります。 有効なサブセットに複数の質量カテゴリが含まれている場合、少なくとも 2 つの物理オブジェクトは交換可能のままです。 DP は、すべての候補クエリに対するすべての可能な回答をカウントします。 その数が 1 つの質量値のみで構成されるサブセットの数と等しい場合、他のタイプのサブセットは存在しないため、考えられるすべての答えが同じことを示します。`k`オブジェクト。 あらゆる質量と可能な限りの検査`k`したがって、可能な限り最適なクエリが検索されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    cnt = [0] * 101
    for x in a:
        cnt[x] += 1

    kinds = sum(1 for x in cnt if x)

    if kinds <= 2:
        print(n)
        return

    total = sum(a)

    dp = [dict() for _ in range(n + 1)]
    dp[0][0] = 1

    for x in a:
        for c in range(n - 1, -1, -1):
            if not dp[c]:
                continue
            target = dp[c + 1]
            for s, val in dp[c].items():
                target[s + x] = target.get(s + x, 0) + val

    comb = [[0] * (n + 1) for _ in range(n + 1)]
    for i in range(n + 1):
        comb[i][0] = comb[i][i] = 1
        for j in range(1, i):
            comb[i][j] = comb[i - 1][j - 1] + comb[i - 1][j]

    ans = 1

    for w in range(1, 101):
        if cnt[w] == 0:
            continue
        for k in range(1, cnt[w] + 1):
            if dp[k].get(k * w, 0) == comb[cnt[w]][k]:
                ans = max(ans, k)

    print(ans)

if __name__ == "__main__":
    solve()
```周波数配列には、各質量の重みがいくつ存在するかが記録されます。 早期リターンは、すべての重みを 1 つのクエリで分離できる場合を処理します。 

動的プログラミング テーブルは辞書のリストとして保存されます。 辞書は、不可能な合計のスキャンを回避し、実装をコンパクトに保ちます。`(count, sum)`中間ステップでは組み合わせに到達できません。 

更新は、選択された重みの数だけ逆方向に反復されます。 これは標準的な 0/1 ナップザック手法です。現在の重みは 1 回のみ使用でき、誤って同じ状態に複数回寄与することはできません。 

組み合わせテーブルはパスカルの三角形で計算されます。 いくつかの等しい物理的重みを選択すると、同等の有効なサブセットが多数作成されるため、カウントが 1 であるかどうかをチェックするのではなく、DP カウントを組み合わせに対して比較します。
