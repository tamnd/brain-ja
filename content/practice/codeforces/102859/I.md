 ## 解決策
 ## 問題の理解

 並んでいます`n`ストーブ。 レンジ`i`ある程度の石が入っている`p[i]`、金額は次の範囲内にある必要があります。`0`そして`v`。 すべてのストーブに置かれる石の合計数は正確に一致する必要があります。`s`。 

隣り合うストーブの間にはコンパートメントがあります。 隣接する 2 つのコンロに次のものがある場合`a`そして`b`石、そのコンパートメントが受け取ります`k * a * b`熱、どこ`k`は指定された体積係数です。 課題は、すべての区画の熱の合計ができるだけ小さくなるように石を配置することです。 

重要な制約は次のサイズです。`v`そして`s`。 石の数を超える直接的な動的計画法は不可能です。`s`と同じ大きさにすることができます`n * 100000`。 ストーブの数はたったの`1000`したがって、意図した解決策は次のものに依存する必要があります`n`、石の数ではありません。 

有益な観察は、他のすべてのストーブが固定されている場合、目的は単一のストーブの値において線形であるということです。 このため、最適な配置は、すべてのストーブに次のいずれかが含まれる配置に変換できます。`0`石、`v`石、またはおそらく中間量の 1 つ。 合計の制限は、中間ストーブが最大 1 つであることを意味します。 

厄介なケースは、ストーブを完全に満たした後に残っている石がゼロではない場合です。 例えば：```
3 5 2
1 1
```1台のコンロの合計容量は、`2`、つまり、満杯のコンロが 2 つと残りの石が 1 つあります。 満杯または空のコンロだけを考慮したソリューションでは、必要な合計を表すことはできません。 正しい配置は次のようなものです`[2, 2, 1]`、部分的なストーブを考慮する必要があります。 

もう 1 つのエッジ ケースは、剰余がゼロの場合です。```
4 8 4
1 1 1
```すべての石を2つのフルストーブとして配置できます。 ここに人工的な部分ストーブを追加すると、すべてのストーブが空か満杯でなければならないため、無効な状態が作成されます。 

最終的な境界ケースは次のとおりです。`s < v`:```
2 3 10
5
```すべての石を 1 つのストーブの上に置き、熱を与えることができます`0`。 少なくとも 1 つのコンロが満杯であることを前提としたアプローチは失敗します。 

## アプローチ

 強引なアプローチでは、ストーブ間で石を可能な限り配分してみることになります。 各ストーブを意味のある 3 つの状態のみに制限することもできます。`0`、`v`、そして考えられる残りの 1 つはまだ約残っています`3^n`可能性。 と`n = 1000`、これはまったく不可能です。 

重要な点は、どのストーブが満杯であるか、どのストーブが部分的に満たされているか、どのストーブが空であるかを判断するだけでよいということです。 仮定する```
s = q * v + r
```それではまさに`q`ストーブには含まれています`v`石。 もし`r > 0`、追加のストーブが 1 つだけ含まれています。`r`石。 残りのストーブはすべて空です。 

これにより、問題は小規模な状態の動的計画問題に帰着します。 コンロを左から右にスキャンする際に必要なのは、すでに設置されているフルコンロの数と、前のコンロのタイプを知ることだけです。 次のストーブによって発生するコストは、ストーブ間のコンパートメントの熱だけであるため、前のタイプのストーブで十分です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(3^n) | O(n) | 遅すぎる |
 | 最適なDP | O(n²) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 必要な数の石をストーブの全容量と残りに分割します。 コンピューティング`q = s // v`そして`r = s % v`。 値`q`何台のストーブが満たされなければならないかを正確に教えてくれます。 
2. 動的プログラミングを使用してストーブを左から右に処理します。 すべてのプレフィックスについて、使用された完全なストーブのすべての数と、最後のストーブの可能なタイプごとに達成可能な最小熱量を保存します。 
3. 最後のストーブのタイプには、空、完全、または部分的な 3 つの可能性があります。 新しいストーブを追加するときは、有効なタイプをそれぞれ試して、前のストーブと新しいストーブの間のコンパートメントからの熱の寄与を追加してください。 
4. 新しいストーブが満杯の場合は、満杯のストーブの数を増やします。 部分的な場合は、次の場合にのみ許可します。`r > 0`そして、以前の部分的なストーブが存在しないことを確認してください。 
5.すべてのストーブが処理された後、正確に使用された状態の間で`q`完全なストーブと、必要に応じて部分的なストーブを 1 つだけ使用する場合は、最小値を使用します。 

なぜ効果があるのか:

 最大でも 1 つの部分的なストーブへの変換が基礎となります。 2 つの変数が境界にない場合は、合計を変更せずにそれらの間で石を移動できます。 その動きに沿った熱関数は線形または凹面であるため、終点で最小値に達します。 このプロセスを繰り返すと、境界値と、場合によっては残りのストーブ 1 つだけが残ります。 DP は、必要な石の数を正確に維持しながら、これらの完全なストーブ、部分的なストーブ、および空のストーブのあらゆる可能な配置を列挙するため、最小の状態が最適な配置になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, s, v = map(int, input().split())
    k = list(map(int, input().split()))

    full = s // v
    rem = s % v

    INF = 10**30

    # dp[count][last_type]
    # type: 0 = empty, 1 = full, 2 = partial
    dp = [[INF] * 3 for _ in range(full + 2)]
    dp[0][0] = 0
    dp[0][1] = 0 if False else INF
    partial_used = [False] * 3

    # Easier representation: the number of full stoves and whether a partial stove was used
    cur = [[INF] * 2 for _ in range((full + 1) * 3)]
    # index = count*3 + last_type, second dimension = partial used
    cur[0 * 3 + 0][0] = 0

    for i in range(n):
        nxt = [[INF] * 2 for _ in range((full + 1) * 3)]
        for idx in range((full + 1) * 3):
            cnt = idx // 3
            prev_type = idx % 3
            for used_partial in range(2):
                val = cur[idx][used_partial]
                if val >= INF:
                    continue

                choices = [(0, 0)]
                if cnt < full:
                    choices.append((1, v))
                if rem and used_partial == 0:
                    choices.append((2, rem))

                for typ, amount in choices:
                    nc = cnt + (1 if typ == 1 else 0)
                    if nc > full:
                        continue
                    nup = used_partial or (typ == 2)

                    add = 0
                    if i > 0:
                        prev_amount = 0
                        if prev_type == 1:
                            prev_amount = v
                        elif prev_type == 2:
                            prev_amount = rem
                        add = k[i - 1] * prev_amount * amount

                    nidx = nc * 3 + typ
                    if val + add < nxt[nidx][int(nup)]:
                        nxt[nidx][int(nup)] = val + add
        cur = nxt

    ans = INF
    need_partial = 1 if rem else 0
    for typ in range(3):
        ans = min(ans, cur[full * 3 + typ][need_partial])

    print(ans)

if __name__ == "__main__":
    solve()
```プログラムは前のスキャン レイヤーのみを保存するため、メモリは線形のままです。 状態インデックスは、完全に満たされたストーブの数と以前のストーブ カテゴリを組み合わせたものです。 移行する場合、新しい熱が現れるのは前のストーブと現在のストーブの間のコンパートメントだけです。そのため、前のカテゴリで十分な情報が得られます。 

遷移値は次を使用します。`v`そして`rem`あらゆる数の石を保管するのではなく、直接に。 これは、ソリューションの効率を維持するための主要な実装の詳細です。 Python の整数は任意の精度であるため、潜在的に大きな発熱量に対して特別な処理は必要ありません。

 ## 特殊なケース

 1 つのストーブの容量より石が少ない場合、DP はすべての石を部分的なストーブに入れることができます。 隣のストーブは空なので、どの製品にもゼロが含まれており、答えはゼロになります。 

石の数がちょうど割り切れるとき`v`、アルゴリズムは部分的な状態を必要としません。 最終的な答えは、部分使用フラグが無効になっている状態からのみ取得され、無効な追加の石を防ぎます。 

残りが存在する場合、部分ストーブは別のカテゴリとして扱われます。 DP は、最適な形式では残りの量が 1 つだけ必要なため、部分的なストーブが 2 つ出現するのを防ぎます。 これにより、あらゆる最適な配置を考慮しながら、不可能または不必要な状態を探索することが回避されます。
