 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、1 つの操作は連続したセグメントを選択し、そのセグメント内のすべての要素を 1 だけ増やすことで構成されます。 この操作は何度でも繰り返すことができます。 すべての操作の後、固定ターゲット配列と一致する必要はありません。 代わりに、最終的な配列が非減少である必要があるだけです。 

したがって、タスクは、元の配列を左から右に読み取っても減少しない配列に変換するために必要な範囲インクリメント操作の数を理解することです。 

重要な点は、配列の最終的な形状が減少せず、部分配列に増分を加算することによってのみ取得できる限り、配列の最終的な形状を自由に選択できることです。 値を減らすことはできません。セグメントを使用して配列の一部を上に「押し上げる」ことのみが許可されています。 

n ≤ 100000 という制約は、操作を明示的にシミュレートできないことを意味します。 各操作は O(n) 要素に触れる可能性があり、単純に適用すると、数千の操作でさえすでに遅すぎます。 有効な解決策はすべて、問題を 1 回のリニア スキャンに減らす必要があります。 

素朴だが当然の間違いは、演算がどのように重複するかを慎重に計算せずに、サフィックスまたはプレフィックスを増やすことでローカル反転を貪欲に「修正」できると考えることです。 

たとえば、[5, 1, 1] を考えてみましょう。 不注意なアプローチでは、2 番目と 3 番目の要素を独立して上げようとする可能性がありますが、操作は範囲に作用するため、1 つの位置を固定すると、意図せず前の位置に影響を与える可能性があります。 

誤解を招きやすいもう 1 つのケースは、[1, 2, 3, 4] など、配列がすでに非減少である場合です。 正しい解決策は直ちに 0 を返す必要があり、それ以上何かを「改善」しようとしてはなりません。 

別のエッジ シナリオは、配列が [4、3、2、1] のように厳密に減少している場合です。 ここで、隣接するすべてのドロップは必要な操作の数に独立して寄与しますが、これらの寄与が複雑な方法で相互作用しない理由はすぐにはわかりません。 

## アプローチ

 ブルートフォースの観点は、操作の定義から始まります。 各操作では、選択したセグメントが 1 つずつ増加するため、すべての操作シーケンスをシミュレートして、配列がいつ非減少になるかを確認してみることができます。 固定数の操作に制限したとしても、各ステップで O(n²) 個の可能なセグメントが許可されるため、分岐要素は膨大になります。 これにより、操作の数がすぐに指数関数的に増加し、小さな配列であっても実行不可能になります。 

より構造化された大胆なアイデアは、b[i] ≥ a[i] であるターゲットの非減少配列 b を固定し、その差 b - a を範囲増分の合計として表現しようとすることです。 これは、非負の配列を間隔更新に分解するのと同じですが、すべての有効な b を検索するのは依然として大きすぎます。 

重要な単純化は、視点を逆転させることで実現します。 任意の最終配列を構築する代わりに、隣接する違反がどのように操作を強制するかに焦点を当てます。 ある位置 i で a[i] > a[i+1] がある場合、右側は左側に比べて小さすぎます。 値を増やすことしかできないため、これを解決する唯一の方法は、位置 i+1 を十分に増やして a[i] に追いつくことです。 このギャップの各ユニットは、i+1 に影響を与えるが、i には同様に影響を及ぼさない何らかの操作によって「配信」される必要があり、これは他の位置から独立した構造コストを意味します。 

これにより、各下方ステップが答えに直接寄与する線形分解が得られます。

 ## アルゴリズムのチュートリアル

 配列を左から右に 1 回スキャンし、隣接するそれぞれの減少が総演算数にどの程度寄与するかを測定します。

1. ゼロに初期化された実行中の応答から始めます。 この変数は、必要な範囲操作の数を累積します。 
2. 配列を最初の要素から最後から 2 番目の要素まで繰り返します。 各位置 i で、a[i] と a[i+1] を比較します。 
3. a[i] が a[i+1] 以下の場合は、何もしません。 このペアは局所的に非減少順序をすでに満たしているため、この境界を修復するために強制的な操作は必要ありません。 
4. a[i] が a[i+1] より大きい場合、差 d = a[i] - a[i+1] を計算します。 この値を答えに追加します。 これは、局所的なドロップを排除するために、i を基準とした位置 i+1 に適用する必要がある単位増分の最小数を表します。 
5. アレイの終わりまでスキャンを続け、そのようなすべての正のドロップを蓄積します。 
6. 最終累積値を出力します。 

ステップ 4 の背後にある理由は、各減少単位は、i+1 以降に開始され、i を完全にはカバーしていない何らかの範囲操作を介して導入する必要がある補正の 1 つの独立した「層」に対応するということです。 隣接する各ドロップが独自の必要な最小数の増分を強制するため、これらのレイヤーは異なる位置にわたって干渉しません。 

### なぜ効果があるのか

 各操作では、連続するセグメントが 1 つずつ増加するため、最終的な効果は、配列全体にユニット高さの間隔を重ね合わせたものと見なすことができます。 隣接する要素 a[i] と a[i+1] の差により、最終的な配列が減少しないようにするには、左側と比較して右側にさらに何層存在する必要があるかが決まります。 

a[i] > a[i+1] の場合、少なくとも a[i] - a[i+1] 操作は、位置 i に等しく寄与することなく、位置 i+1 に追加の高さを寄与する必要があります。 このような制約をすべて同時に「回避」できる操作はないため、これらの要件はすべての隣接するペアに対して独立して追加されます。 この独立性により、正のドロップの合計が必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    ans = 0
    for i in range(n - 1):
        if a[i] > a[i + 1]:
            ans += a[i] - a[i + 1]
    
    print(ans)

if __name__ == "__main__":
    solve()
```この実装は、下方への遷移のみが重要であるという観察を直接翻訳したものです。 ループは隣接する各ペアを 1 回だけ考慮し、アキュムレータはすべての局所的な減少を排除するために必要な必須補償の合計を格納します。 操作のシミュレーションや最終的なアレイの構築は必要ありません。 

よくある実装上の間違いは、変換された配列を明示的に維持しようとしたり、範囲の増分をシミュレートしようとしたりすることです。 答えはローカルな違いのみに依存し、進化するグローバル構造には依存しないため、これは不要です。

 ## 特殊なケース

 [10] のような単一要素配列の場合、隣接するペアに対するループはまったく実行されないため、答えはゼロのままであり、これは単一の値が自明に減少しないという事実と一致します。 

[5, 4, 3, 2] のような厳密に減少する配列の場合、隣接するすべてのペアが独立して寄与します。 アルゴリズムは (5-4) + (4-3) + (3-2) = 3 を累積します。これは、ドロップごとに必要な補償の個別の単位が導入されるという事実と一致します。 

[7, 7, 7, 7] などのすでに定数の配列の場合、a[i] > a[i+1] を満たすペアは存在しないため、答えはずっと 0 のままであり、範囲演算が必要ないことが確認されます。
