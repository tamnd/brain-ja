 ## 解決策
 ## 問題の理解

 タスクは、指定された数値を 2 つのグループに分けることです。 両方の数字が同じグループに配置されている場合、数字のペアは通常の合計を受け取りますが、追加のペナルティを受けます。`h`2 つの数字が離れている場合。 すべてのペアを検討した後、結果として得られる最大値と最小値を調べ、その差をできるだけ小さくすることが目標です。 

入力には、数値の量、ペナルティ値、および数値自体が含まれます。 出力では、可能な最小の差と、2 つのグループのいずれかへのすべての数値の 1 つの有効な割り当てが求められます。 

配列のサイズは次のとおりです`100000`、一方、値と`h`非常に大きくなる可能性があります。 これにより、すべてのパーティションを試行することが除外されます。`2^n`要素に色を付ける可能な方法。 すべてのパーティションのすべてのペアをチェックすることすら不可能です。 に近い解決策が必要です`O(n log n)`または`O(n)`。 

厄介なケースは、空のグループが許可されていて、ペナルティが答えを支配する可能性があるという事実から生じます。 たとえば、すべての要素が 1 つのグループに配置される場合、ペナルティは決して表示されません。 

入力の場合:```
3 10
1 2 3
```常に配列を分割するような不注意な解決策を使用すると、不必要にペナルティが追加される可能性があります。 すべてを 1 つのグループに入れると、ペアの値が得られます`3`、`4`、 そして`5`、したがって、答えは次のとおりです`2`。 

もう 1 つのエッジ ケースは、最小要素と最大要素が分離されている場合です。 のために：```
3 100
1 2 3
```置く`1`そして`2`異なるグループに分割すると非常に大きな最小値が生成されますが、分割すると`2`そして`3`非常に大きな最大値が生成されます。 最適な決定を行うには、一方の側面だけを見るのではなく、両方の効果のバランスを取る必要があります。 

## アプローチ

 直接的な総当りの解決策では、2 つのグループへの要素の可能なすべての割り当てが試行されます。 割り当てごとに、すべてのペアを検査し、最大値と最小値の差を計算できます。 考えられるすべてのパーティションが考慮されるため、これは正しいです。 ただし、`2^n`パーティションがあり、それぞれに最大で`O(n^2)`実行不可能な最悪のケースを想定すると、おおよそ次のようになります。`O(2^n * n^2)`操作。 

有益な観察は、実際の値はどの要素が分離されるかによってのみ依存し、最小値と最大値が極端な値に影響を与える可能性があるということです。 値を並べ替えた後、最適なパーティションは、並べ替えられた配列を 2 つの連続する部分に分割したものと考えることができます。 2 つの値がこの分割の同じ側にある場合、それらの合計は増加しません。 それらが反対側にある場合、それらの合計は`h`。 

固定分割の場合は、可能な最小と最大のペア値を知る必要があるだけです。 最小の候補は、同じ側の最小の 2 つの要素、または最小のクロス ペアから得られます。 最大の候補は、同じ側の最大の 2 つの要素、または最大のクロス ペアから得られます。 

考えられるすべての分割をスキャンし、ソート後に一定時間内にこれら 4 つの境界値を計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^2) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 元のインデックスを維持したまま要素を並べ替えます。 ソートされた順序により、考えられるペアの合計の最小値と最大値を推論することができます。 
2. すべての要素が 1 つのグループに留まる場合を含め、並べ替えられた要素間で考えられるすべての分割位置を試します。 分割の左側は 1 つのラベルを受け取り、右側はもう 1 つのラベルを受け取ります。 
3. 現在の分割について、可能な最小ペア値を計算します。 これは、左側のグループ内の最小のペア、右側のグループ内の最小のペア、またはペナルティが追加されたグループ間の最小のペアからのみ取得できます。 
4. 可能な最大ペア値を計算します。 これは、左側のグループ内の最大のペア、右側のグループ内の最大のペア、またはペナルティが追加されたグループ間の最大のペアからのみ取得できます。 
5. 最大候補値と最小候補値の差が、この分割の品質です。 差が最も小さい分割を保持し、そこからラベルを再構築します。 

機能する理由: ソート後、端から遠ざけると、最小候補の合計が大きくなり、最大候補の合計が小さくなるだけです。 エッジに近くないペアは、より極端なペアによって支配されているため、新しいグローバル最小値または最大値を作成できません。 最適な配置はプレフィックスとサフィックスを分離することで表すことができるため、そのような分割をすべてチェックすることで最適な解決策がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, h = map(int, input().split())
    arr = list(map(int, input().split()))

    a = sorted([(x, i) for i, x in enumerate(arr)])

    best = 10**30
    ans = [1] * n
    best_split = 0

    for k in range(n + 1):
        mn = 10**30
        mx = -1

        if k >= 2:
            mn = min(mn, a[0][0] + a[1][0])
            mx = max(mx, a[k - 2][0] + a[k - 1][0])

        if n - k >= 2:
            mn = min(mn, a[k][0] + a[k + 1][0])
            mx = max(mx, a[n - 2][0] + a[n - 1][0])

        if k > 0 and k < n:
            mn = min(mn, a[0][0] + a[k][0] + h)
            mx = max(mx, a[k - 1][0] + a[n - 1][0] + h)

        if k == 0 or k == n:
            mn = a[0][0] + a[1][0]
            mx = a[n - 2][0] + a[n - 1][0]

        if mx - mn < best:
            best = mx - mn
            best_split = k

    for pos in range(best_split):
        ans[a[pos][1]] = 1
    for pos in range(best_split, n):
        ans[a[pos][1]] = 2

    print(best)
    print(*ans)

if __name__ == "__main__":
    solve()
```回答は元の順序で出力する必要があるため、コードは最初に値と元の位置の両方を保存します。 並べ替えは、推論に使用される順序を変更するだけです。 

ループチェック`n + 1`分割の可能性。 境界チェックでは、小さなグループを慎重に処理します。 要素が 2 つ未満のグループは同じグループのペアを作成できないため、最小または最大の候補を提供してはなりません。 場合`k`は`0`または`n`すべての要素を単一のグループに入れることを表します。 

再構築ステップでは、選択されたソートされた分割を元のインデックスに変換します。 分割前の値は 1 つの色を取得し、分割後の値はもう 1 つの色を取得します。

 ## 特殊なケース

 ペナルティが非常に大きい場合:```
3 100
1 2 3
```アルゴリズムは、片側に 1 つの要素を含む分割をチェックします。 クロスペアは追加のボーナスを受け取ります`100`, そのため、それらの値は同じグループのペアよりもはるかに大きくなります。 [すべて 1 つのグループ] オプションでは範囲が最小になるため、これが選択されます。 

値が等しい場合:```
5 10
4 4 4 4 4
```1 つのグループ内のすべてのペアの合計は`8`、分割ペアは次のようになります。`18`。 最善の選択は、すべてをまとめて範囲を広げることです`0`。 

分割が魅力的に見える場合:```
4 5
1 2 8 9
```小さい値と大きい値を分離すると、追加によってペアの値が変更されます。`5`たくさんの組み合わせに。 スキャンでは、各分割の正確な最小値と最大値が評価されるため、一方の側を改善しながらもう一方の側を損傷するような分割の選択を回避します。
