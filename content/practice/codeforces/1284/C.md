 ## 問題の理解

 長さのすべての順列にわたるフレーム化されたセグメントの総数が必要です`n`。 

固定順列の場合、セグメント`[l, r]`内部の値が一連の連続する整数を形成する場合、フレーム化されます。 順列内のすべての値は個別であるため、条件は$$\max - \min = r - l$$セグメントに最小値と最大値の間のすべての整数が含まれていることを正確に意味します。 

順列の幸福度は、それに含まれるフレーム化されたセグメントの数です。 1 つの順列について幸福度を計算するのではなく、すべての順列について幸福度を合計する必要があります。`n!`置換し、指定された素数を法とした結果を出力します`m`。 

制約`n ≤ 250000`問題の性質が完全に変わります。 順列を列挙することはできません。`20!`すでに巨大です。 また、単一の順列のすべてのセグメントを検査するアルゴリズムを用意する余裕もありません。 ソリューションでは、計数式を導出し、それをほぼ直線的な時間で評価する必要があります。 

微妙な点は、すべての順列を同時に合計していることです。 このタイプの問題の多くは、カウント順序を逆にすると対処可能になります。各順列にフレーム化されたセグメントがいくつあるかを尋ねる代わりに、特定のセグメントをフレーム化する順列の数を尋ねます。 

もう 1 つの簡単な間違いは、コンディションがポジションのみに依存すると考えることです。 たとえば、`n = 3`、長さのセグメント`2`2 つの値が連続している場合にのみフレーム化されます。 ペア`(1,3)`機能しないので`3 - 1 = 2`一方、セグメントの長さから 1 を引いた値は次のようになります。`1`。 

のために`n = 1`、順列とセグメントは 1 つだけです。 答えは`1`。 どの式でもこの値は自然に生成されるはずです。 

## アプローチ

 まず、強引な解釈を想像してみましょう。 

長さのあらゆる順列を生成できます`n`。 順列ごとに、すべてのセグメントを検査し、その最小値と最大値を計算し、フレーム化されているかどうかを確認できます。 セグメント クエリが最適化されたとしても、`n!`順列が異なるため、このアプローチはほぼ即座に不可能になります。 のために`n = 10`、すでにあります`3,628,800`順列。 

重要な点は、フレーム化されたセグメントの定義は、そのセグメント内の値のセットのみに依存するということです。 

ある長さのセグメントを考慮します$$k = r-l+1.$$すべての値は個別であるため、条件は$$\max - \min = k-1$$セグメントに正確に含まれることを意味します`k`連続した数字。 

それらの連続する数字が$$x, x+1, \dots, x+k-1.$$このような値セットにはいくつの選択肢がありますか? 開始値`x`で選択できます$$n-k+1$$方法。 

長さの固定位置セグメントが存在する順列をカウントします。`k`まさにそれらが含まれています`k`数字。 

の`k`選択した値はセグメント内に配置できます。`k!`方法。 

残り`n-k`値はセグメントの外側に配置できます。`(n-k)!`方法。 

したがって、固定セグメント位置と固定連続値ブロックの場合、有効な順列の数は次のようになります。$$k!(n-k)!.$$がある`n-k+1`可能な連続値ブロック、および`n-k+1`ある長さのセグメントの可能な位置`k`。 

したがって、すべての長さの合計貢献度は、`k`セグメントは$$(n-k+1)^2 \cdot k! \cdot (n-k)!.$$すべての長さを合計すると、答えが得られます。$$\sum_{k=1}^{n} (n-k+1)^2 \cdot k! \cdot (n-k)!.$$残りのタスクは、この和のモジュロを評価することです`m`。 以来`n`までです`250000`階乗モジュロを事前に計算できます`m`線形時間で計算し、別の線形パスで合計を評価します。

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`m`。 
2. 階乗モジュロを事前計算する`m`。 

させて`fact[i] = i! mod m`みんなのために`0 ≤ i ≤ n`。 
3. 答えをゼロに初期化します。 
4. セグメント長ごとに`k`から`1`に`n`、計算する$$(n-k+1)^2 \cdot fact[k] \cdot fact[n-k] \pmod m.$$この数量はすべてのペアをカウントします`(permutation, framed segment)`セグメントの長さが等しい`k`。 
5. この貢献を答えのモジュロに追加します`m`。 
6. 最終的な答えを出力します。 

ステップ 4 が機能する理由は、フレーム化されたすべてのセグメントが連続値の 1 つのブロックに正確に対応しており、セグメントの位置、連続値のブロック、セグメント内の配置、セグメント外の配置のすべての選択により、一意の有効な置換が生成されるためです。 

### なぜ効果があるのか

 長さを固定する`k`。 

長さのセグメント`k`その値が正確に何らかのセットである場合に限り、フレーム化されます。`k`連続した整数。 がある`n-k+1`このような値セット。 

セグメント位置を 1 つ選択します。`n-k+1`可能な位置。 連続した値セットが選択されると、`k`値はセグメント内で任意に順序付けされる可能性があり、`k!`可能性。 残りの値はセグメントの外側で任意に並べ替えることができ、`(n-k)!`可能性。 

セグメントの位置とその値セットは一意に決定されるため、フレーム化されたセグメントを含むすべての順列は 1 回だけカウントされます。 

すべてのセグメントの長さにわたるこれらのカウントを合計すると、すべての順列のすべてのフレーム化されたセグメントが 1 回だけカウントされることになり、これがまさに必要な合計幸福度になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())

fact = [1] * (n + 1)
for i in range(1, n + 1):
    fact[i] = fact[i - 1] * i % m

ans = 0

for k in range(1, n + 1):
    cnt = n - k + 1
    contrib = cnt * cnt
    contrib %= m
    contrib = contrib * fact[k] % m
    contrib = contrib * fact[n - k] % m
    ans = (ans + contrib) % m

print(ans)
```階乗配列にはすべての値を法的に格納します`m`。 後のすべての計算もモジュロで実行されるため、`m`、これより大きな値は必要ありません。 

ループオーバー`k`導出された式を直接評価します。 変数`cnt = n-k+1`が 2 回表示されるのは、セグメントの位置とそれに割り当てられる値の連続ブロックという 2 つの独立した選択肢があるためです。 

各乗算の後にモジュロを適用すると、中間数値が不必要に大きくなるのを防ぎます。 Python の整数は大きな値を処理できますが、早めに減らすことで、実装を意図したモジュラー演算に近づけることができます。 

インデックス付けは特に間違いやすいです。 貢献の用途`fact[k]`そして`fact[n-k]`、 ない`fact[k-1]`。 用語`n-k+1`セグメント位置と連続値ブロックの両方をカウントすることで得られます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())

    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % m

    ans = 0
    for k in range(1, n + 1):
        cnt = n - k + 1
        ans = (
            ans
            + cnt * cnt % m
            * fact[k] % m
            * fact[n - k]
        ) % m

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue().strip()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

 ## 特殊なケース

 最小の入力を考えてみましょう。```
1 993244853
```ループは次のようにして 1 回実行されます`k = 1`。$$(1)^2 \cdot 1! \cdot 0! = 1.$$アルゴリズムの出力`1`、単一の順列と単一のフレーム化されたセグメントに一致します。 

考慮する`n = 2`:```
2 1000000007
```寄付金は、$$2^2 \cdot 1! \cdot 1! = 4,$$そして$$1^2 \cdot 2! \cdot 0! = 2.$$答えは`6`。 順列が 2 つあるので、それぞれに幸福がある`3`、合計は`6`。 これにより、配列全体を占めるセグメントがカウントで正しく処理されることが確認されます。 

一般的な 1 つ違いのリスクは、連続する値ブロックをカウントするときに発生します。 のために`n = 3`そして`k = 2`、有効な値ブロックは 2 つあります。$$\{1,2\}, \{2,3\}.$$式では、`n-k+1 = 2`。 使用する`n-k`1 つのブロックが欠落し、不正確な合計が生成されます。 セグメント位置と値ブロックの両方が同じ式でカウントされるため、アルゴリズムはこれを回避します。`n-k+1`。 

もう一つの微妙なケースは、`k = n`。 セグメント位置と連続値ブロックは 1 つだけ、つまり、次のすべての値が存在します。`1`に`n`。 貢献度は、$$1^2 \cdot n! \cdot 0! = n!,$$これは、完全な配列セグメントがフレーム化される順列の正確な数です。 すべての順列が配列全体でこのプロパティを満たすため、カウントは正確です。
