 ## 解決策
 ## 問題の理解

 文字列の 2 つの循環リストが与えられます。 最初のリストにはサイズがあります$n$、2番目にはサイズがあります$m$。 毎年$y$を取得して名前を生成します$y$最初のリストの - 番目の文字列と$y$- 2 番目のリストの 2 番目の文字列。両方とも循環的にインデックスが付けられ、それらが連結されます。 

具体的には、1 年目は次のように使用します。$s_1$そして$t_1$、2年目の使用$s_2$そして$t_2$、 等々。 いずれかのリストの終わりを通過したら、再び先頭に戻ります。 年の名前は、選択したペアを単純に連結したものです。 

各クエリは年番号を返します$y$、おそらく非常に大きいため、結果として得られる連結された名前を出力する必要があります。 

主な構造の詳細は、両方のシーケンスが周期的であることです。 最初のものは毎回繰り返されます$n$年、2 回ごと$m$年ごとに組み合わせパターンが繰り返されるため、$\mathrm{lcm}(n, m)$年。 この周期性により、大規模なクエリが管理可能になります。 

配列の制約は小さく、$n, m \le 20$したがって、事前計算は簡単です。 クエリの数も少ないですが、年インデックスは最大になる可能性があります。$10^9$、これにより、年ごとのシミュレーションが直ちに除外されます。 まで反復するソリューション$y$最悪の場合、クエリごとにタイムアウトが発生する可能性があります。 

素朴な考えによる微妙な失敗例は、循環インデックスを忘れることです。 たとえば、次の場合$n = 3$、アクセス中$s_{y}$直接的には範囲外になります$y > 3$。 もう 1 つのよくある間違いは、特に年 1 をインデックス 0 にマッピングする場合に、0 ベースのインデックス付けでモジュロを誤って計算することです。 

## アプローチ

 ブルートフォースのアイデアは、各クエリのプロセスをシミュレートすることです。 特定の年について$y$、両方の配列のインデックスを次のように繰り返し計算します。$(y-1) \bmod n$そして$(y-1) \bmod m$、対応する文字列を連結します。 これは正しく、非常に直接的です。 

ただし、1 年目から 2 年目までを反復して単純に実装すると、$y$各クエリのコストは次のようになります。$O(q \cdot y)$、次の場合は不可能です$y$到達できる$10^9$。 たとえ$q \approx 2000$、これは爆発します。 

重要な観察は、モジュラー演算を使用して各年を一定時間で独立して計算できることです。 シーケンスは周期的であるため、遷移をシミュレートする必要はありません。 全体の問題は、2 つの循環配列へのインデックス付けと結果の連結に帰着します。

 ## アルゴリズムのチュートリアル

 1. 2 つの配列を読み取ります$s$そして$t$、その長さを保存します$n$そして$m$。 これらは 2 つの独立したサイクルを定義します。 
2. 各クエリ年について$y$これにより、年 1 がインデックス 0 に揃えられ、モジュラー演算が簡素化されます。 
3. 最初の配列のインデックスを次のように計算します。$(y-1) \bmod n$。 これにより、正しい循環位置が得られます。$s$。 
4. 2 番目の配列のインデックスを次のように計算します。$(y-1) \bmod m$。 これにより、正しい循環位置が得られます。$t$。 
5. 連結を出力する$s[i] + t[j]$。 

各クエリは独立しているため、中間結果を保存したり、進行状況をシミュレートしたりする必要はありません。 

### なぜ効果があるのか

 両方のシーケンスが一定の周期で繰り返されます$n$そして$m$。 の$y$繰り返しサイクルの - 番目の要素は、その位置のサイクル長の法にのみ依存します。 出力は 2 つの独立したサイクルの単なるペアごとの組み合わせであるため、システム全体も周期的であり、各クエリは 2 つのモジュラー ルックアップに減ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m = map(int, input().split())
s = input().split()
t = input().split()

q = int(input())

for _ in range(q):
    y = int(input())
    y -= 1
    print(s[y % n] + t[y % m])
```このソリューションは、モジュール式インデックス作成を直接適用します。 唯一の重要な実装の詳細は、モジュロを取得する前に 1 を減算し、年 1 がインデックス 0 にマップされるようにすることです。この調整がないと、年の境界が誤って移動します。 

各クエリは一定時間内に独立して処理されるため、標準の整数処理を超える状態の蓄積やオーバーフローのリスクはありません。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline

    n, m = map(int, input().split())
    s = input().split()
    t = input().split()
    q = int(input())
    out = []
    for _ in range(q):
        y = int(input())
        y -= 1
        out.append(s[y % n] + t[y % m])
    return "\n".join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。$n = 1$または$m = 1$。 この状況では、毎年、そのシーケンスから常に同じ文字列が選択されます。 1 を法とする数値は 0 であるため、モジュラー式は引き続き機能します。そのため、実装は特別な処理を行わなくても自然に正しく折りたたまれます。 

もう 1 つのケースは、年の値が非常に大きく、$10^9$。 Python は大きな整数をネイティブに処理するため、唯一のリスクはモジュロの前に 1 を引くのを忘れることです。 これをスキップすると、年 1 が 0 ではなくインデックス 1 に誤ってマッピングされ、すべての出力がシフトされます。 

最後の微妙なケースは、両方のシーケンスの長さが異なり、狭い範囲内で周期的に整列しない場合です。 それでも、各シーケンスは独立して循環し、共有周期を決して想定しないため、モジュラーアプローチは正しいままです。
