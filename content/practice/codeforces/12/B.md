 ## 解決策
 ## 問題の理解

 アリスはボブに 10 進数を与え、結果の数値が先頭のゼロのない有効な 10 進数のままで、できるだけ小さくなるように桁を並べ替えるように依頼します。 ボブは別の数値を返します。私たちは、彼の答えが実際に可能な最小の配列であるかどうかを判断する必要があります。 

タスクは、すべての再配置を生成することではありません。 ボブの番号が正しい最小配置と一致するかどうかを確認するだけで済みます。 

数字は最大でも$10^9$, そのため、最大でも 10 桁の数字が含まれます。 入力サイズが小さい場合でも、この問題では先頭のゼロを慎重に処理する必要があります。 次のような単純な数値ソート`"0013"`数値全体がゼロでない限り、10 進数はゼロで始めることができないため、無効な表現が生成されます。 

最も危険なエッジケースは、元の数値にゼロが含まれている場合に発生します。 たとえば:

 入力:```
1002
1002
```正しい最小の再配置は次のとおりです。`1002`、 ない`0012`。 すべての数字を単純に昇順にソートする不注意な実装は、誤ってビルドされます。`"0012"`。 

もう 1 つの注意が必要な状況は、数値自体がゼロの場合です。 

入力：```
0
0
```唯一の再配置はまだゼロであるため、答えは有効です。 

回答候補の数字は正しいが最小値ではない場合、別の種類の間違いが発生します。 

入力：```
310
130
```数字は一致しますが、有効な最小の配列は次のとおりです。`103`したがって、正しい出力は次のようになります。`WRONG_ANSWER`。 

最も難しいのは、数字が一致するかどうかを確認しないことです。 本当の課題は、「先行ゼロなし」という制限の下で辞書編集上最小の有効な配置を構築することです。 

## アプローチ

 ブルートフォース手法では、元の数値の各桁の順列をすべて生成し、先頭にゼロがあるものを破棄し、残りの順列を数値に変換し、最小値を取得します。 次に、その最小値とボブの答えを比較します。 

これは問題の定義に直接従うため機能します。 考えられるすべての再配置が検査されるため、最小の有効な再配置が必ず見つかるようになります。 

問題は、順列が階乗的に増加することです。 10 桁の数字には最大で$10! = 3,628,800$順列。 すでに数百万の候補があり、重複した作業を避けたい場合は、重複する数字により簿記がさらに複雑になります。 このように小さい入力サイズの場合、一部の言語ではまだ合格する可能性がありますが、単純で建設的な解決策がある問題にとっては不必要にコストがかかります。 

重要な点は、最初の桁が数値の値に最も大きな影響を与えるため、有効な最小の数値はゼロ以外の最小の桁を最初に配置する必要があるということです。 最初の桁を修正した後、残りのすべての位置には、ゼロを含む使用可能な最小の桁が含まれている必要があります。 

これはすぐに貪欲な構築を示唆します。 

まず、すべての数字を昇順に並べ替えます。 

最初の桁がゼロでない場合、ソート順序はすでに最適になっています。 

並べ替え順序がゼロで始まる場合は、最初のゼロ以外の数字を見つけて先頭に配置し、残りのすべての数字を昇順で追加します。 

例えば：`3100`並べ替えられた数字:`0013`最初のゼロ以外の数字は、`1`。 

それを前に移動します。`1003`それが最小の有効な取り決めです。 

この標準的な最小形式を構築した後、それをボブの答えと単純に比較します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(d! \cdot d)$|$O(d)$| 遅すぎる/不必要 |
 | 最適 |$O(d \log d)$|$O(d)$| 承認済み |

 ここ、$d$桁数です。 

## アルゴリズムのチュートリアル

 1. 元の番号を読み取ります`n`文字列とボブの答えとして`m`文字列として。 

これらを文字列として扱うことで、処理中の先頭のゼロの問題を回避できます。 
2. の桁を変換します。`n`リストにまとめて昇順に並べ替えます。 

これにより、辞書編集上最小の数字の配置が得られます。 
3. ソート後の最初の桁が 0 であるかどうかを確認します。 

ゼロでない場合、ソート順序はすでに最小の有効な数値になっています。 
4. 最初の桁がゼロの場合は、最初の非ゼロの桁が見つかるまで左から右にスキャンします。 

有効な数値はゼロ以外の数字で始まる必要があるため、この数字が先頭の数字になる必要があります。 
5. 最初のゼロ以外の数字を前の位置に交換します。 

残りのすべての桁はソートされたままであるため、結果の数値は依然として最小になります。 
6. 数字を結合して、最小の有効な並べ替えを表す文字列を作成します。 
7. 構築された結果をボブの答えと比較します。 

正確に一致する場合は印刷します`OK`。 それ以外の場合は印刷します`WRONG_ANSWER`。 

### なぜ効果があるのか

 アルゴリズムは位置の値に依存します。 左端の桁は数値の大きさに最も大きく影響するため、これを最小化することが常に最優先になります。 

ゼロ以外のすべての桁の中で、最初の位置に最小のものを選択すると、先頭への寄与が最小限になります。 その桁を修正した後、残りの桁を個別に最小化する必要があります。これは、残りの桁を昇順にソートすることによって実現されます。 

最初の桁以降のすべての桁は可能な限り小さい順序で配置されるため、他の有効な並べ替えによってより小さい数値を生成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = input().strip()
    m = input().strip()

    digits = sorted(n)

    if digits[0] == '0':
        for i in range(len(digits)):
            if digits[i] != '0':
                digits[0], digits[i] = digits[i], digits[0]
                break

    smallest = ''.join(digits)

    if smallest == m:
        print("OK")
    else:
        print("WRONG_ANSWER")

solve()
```解決策は、両方の数値を文字列として読み取ることから始まります。 ボブの回答には入力の先頭にゼロが含まれている可能性があり、すぐに整数に変換するとその情報が失われるため、これは重要です。 

の桁`n`昇順に並べ替えられます。 最初の桁がすでにゼロ以外の場合、ソートされたシーケンスは直ちに最小の有効な配列になります。 

並べ替えられたシーケンスがゼロで始まる場合、コードは最初のゼロ以外の数字を検索し、それを最初の位置に置き換えます。 残りの桁はすでに昇順にソートされているため、この操作で十分です。 追加の再配置は必要ありません。 

最終的な比較は文字列比較として実行されます。 これは数値比較よりも安全です。`"0012"`そして`"12"`この問題の文脈でさまざまな答えを表します。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n = input().strip()
    m = input().strip()

    digits = sorted(n)

    if digits[0] == '0':
        for i in range(len(digits)):
            if digits[i] != '0':
                digits[0], digits[i] = digits[i], digits[0]
                break

    smallest = ''.join(digits)

    if smallest == m:
        print("OK")
    else:
        print("WRONG_ANSWER")

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output.strip()

# provided sample
assert run("3310\n1033\n") == "OK", "sample 1"

# minimum value
assert run("0\n0\n") == "OK", "single zero"

# leading zero trap
assert run("1002\n1002\n") == "OK", "smallest valid arrangement keeps zeroes after first digit"

# wrong arrangement with same digits
assert run("310\n130\n") == "WRONG_ANSWER", "digits match but arrangement is not minimal"

# already sorted
assert run("1234\n1234\n") == "OK", "already minimal"

# maximum size boundary
assert run("1000000000\n1000000000\n") == "OK", "10 digits with many zeroes"
