 ## 解決策
 ## 問題の理解

 2 つの整数が与えられます。`l`そして`r`。 あらゆる数字について`n`この間隔内で、その反射と呼ばれる別の数値を構築します。 

反射は桁ごとに作成されます。 すべての 10 進数`d`になる`9 - d`。 例えば：

-`192 → 807`-`10 → 89`-`91 → 08 → 8`数値の重みは次のとおりです。$$n \cdot \psi(n)$$どこ$\psi(n)$の反映です`n`。 

タスクは、範囲内のすべての整数の中で可能な最大の重みを見つけることです。`[l, r]`。 

範囲は最大です$10^9$。 A brute-force scan over every number is immediately suspicious because the interval itself may contain almost one billion values. Even if computing the reflection took only a few operations, iterating through$10^9$候補者は 2 秒の制限に収まりません。 

The key difficulty is that the reflection depends on every digit independently, so the product is not monotonic. A larger number does not necessarily give a larger weight.

 見落としやすいエッジケースがいくつかあります。 

次の範囲を考慮してください。```
8 10
```重みは次のとおりです。 

-`8 * 1 = 8`-`9 * 0 = 0`-`10 * 89 = 890`最大値は、ある桁の長さから別の桁の長さに移行するときに劇的に変化します。 ここでは、「答えは r の近くにある」といった素朴な仮定は当てはまりません。 

もう 1 つの危険なケースは、多くの数字で終わる数字です。`9`s:```
99 → 0
999 → 0
```すべての数字が次のようになるため、反射はゼロに崩壊します。`0`。 先頭のゼロを 10 進数として保持する不注意な実装により、誤って処理される可能性があります。`"00"`意味のある 2 桁の数字として。 

固定桁数の有効範囲の中央付近には、構造的なエッジ ケースもあります。 2 桁の数字の場合:

 | n | ψ(n) | 製品 |
 | --- | --- | --- |
 | 40 | 59 | 2360 |
 | 44 | 55 | 2420 |
 | 49 | 50 | 2450 |
 | 50 | 49 | 2450 |
 | 55 | 44 | 2420 |

 最大値はどちらの端点にも現れず、中心付近に現れます。 この形状を理解することが解決策の核心です。 

## アプローチ

 最も直接的な解決策は、次のすべての整数を反復処理することです。`l`に`r`、その反射を計算し、2 つの値を乗算し、最大値を維持します。 

反射の計算は簡単です。 数字が`d`、その反映桁は`9 - d`。 数値を文字列として処理することも、数字ごとに数学的に処理することもできます。 

この総当り的な方法は、すべての候補を明示的にチェックするため、正しいです。 問題は候補者の数だ。 最悪の場合、間隔の長さは次のようになります。$10^9$。 数値ごとに数回の算術演算を行うだけでも、これは実現不可能です。 

ターニングポイントは、反映を代数的に書き直すことで起こります。 

仮定する`n`まさに`k`数字。 させて：$$M = 10^k - 1$$これは完全に次のもので構成される数字です`9`長さのある`k`。 

例えば：

-`k = 2 → M = 99`-`k = 3 → M = 999`すべての数字を個別に反映することは、次とまったく同じです。$$\psi(n) = M - n$$例：$$192 \rightarrow 999 - 192 = 807$$したがって、重みは次のようになります。$$f(n)=n(M-n)$$展開すると次のようになります。$$f(n) = -n^2 + Mn$$これは下に開く二次放物線です。 その最大値は次の時点で発生します。$$n = \frac{M}{2}$$それは問題全体を変えます。 数十億の値を検索する代わりに、放物線の頂点付近の数値を調べるだけで済みます。 

複雑な問題が 1 つあります。 この数式は、桁数が同じ数値に対してのみ機能します。 桁数が変わると、`M`も変わります。 以来`r ≤ 10^9`、考慮すべき異なる桁の長さは最大 10 個あります。 

各桁の長さについて:

 - との有効な交差を決定します。`[l, r]`- 中点を計算します$M/2$- 間隔内の中間点付近で最も近い整数をチェックします。 

二次方程式は中心で最大値に達するため、必要な候補数は一定数だけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(r - l + 1) | お(1) | 遅すぎる |
 | 最適 | O(桁数) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 考えられるすべての桁長について反復します。`k`1から10まで。 

以来`r ≤ 10^9`、少数の桁の長さだけが存在します。 
2. 現在の桁の長さについては、次のように計算します。$$M = 10^k - 1$$この長さではオール9の数字になります。 

1. 有効な間隔を計算します。`k`- 中にも含まれる数字`[l, r]`。 

最小の`k`-桁の番号は次のとおりです。$$10^{k-1}$$を除いて`k = 1`、最小値は`1`。 

最大の`k`-桁の番号は次のとおりです。$$10^k - 1$$1. この桁長の間隔を次のように交差します。`[l, r]`。 

交差部分が空の場合は、この桁の長さをスキップします。 
2. この桁の長さの関数は次のとおりです。$$f(n)=n(M-n)$$これは下向きの放物線であるため、最大値は次の付近で発生します。$$\frac{M}{2}$$1. 次のようにしましょう。$$x = \left\lfloor \frac{M}{2} \right\rfloor$$最適な整数の候補は次のいずれかでなければなりません。`x`または`x + 1`。 

1. これらの候補をこの桁長の有効な間隔に固定します。 

中間点が間隔の外側にある可能性があるため、間隔の境界も確認してください。 
2. 収集されたすべての候補について製品を評価し、グローバル最大値を維持します。 

### なぜ効果があるのか

 固定桁長の場合`k`、すべての数値は次の条件を満たします。$$\psi(n)=M-n$$どこ$M=10^k-1$。 重み関数は次のようになります。$$f(n)=n(M-n)$$これは凹二次方程式です。 凹二次関数は、次の位置にある頂点で最大値に達します。$M/2$。 有界区間内の整数のみを考慮するため、最適値は頂点に最も近い整数の 1 つ、または頂点が外側にある場合は区間境界の 1 つでなければなりません。 

各桁の長さおよびすべての数値を個別に最大化します。`[l, r]`ちょうど 1 桁の長さのグループに属します。 すべてのグループの中で最も優れたものを採用することで、全体的な最適性が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def reflection(x):
    s = str(x)
    t = ''.join(str(9 - int(c)) for c in s)
    return int(t)

def weight(x):
    return x * reflection(x)

l, r = map(int, input().split())

ans = 0

for k in range(1, 11):
    low = 1 if k == 1 else 10 ** (k - 1)
    high = 10 ** k - 1

    L = max(l, low)
    R = min(r, high)

    if L > R:
        continue

    M = high
    mid = M // 2

    candidates = {L, R}

    for x in [mid, mid + 1]:
        if L <= x <= R:
            candidates.add(x)

    for x in candidates:
        ans = max(ans, weight(x))

print(ans)
```リフレクション式は数値の桁数に依存するため、このソリューションでは数値を桁長でグループ化します。 

固定桁長の場合、反映はその長さのすべて 9 の数値から減算することと同等です。 コードは、明確さと安全性を確保するために、反射を直接計算します。 一定数の候補のみが評価されるため、効率には影響しません。 

中間点の計算は微妙です。 二次最大値は次の場所で発生します。`M / 2`、 しかし`M`はすべて 9 の数字に対して奇数です。 これは、真の最大値が 2 つの整数の間に等しく存在することを意味します。 両方をチェックする必要があります`mid`そして`mid + 1`。 

候補セットには区間境界も含まれます。 放物線のピークがこの桁長の有効範囲外にある場合、その区間の最大値は最も近い境界で発生します。 

Python の整数は、大きな積を自動的に安全に処理します。 C++ では、答えが次の値を超える可能性があるため、これには 64 ビット整数が必要になります。`2^31`。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    import sys
    input = sys.stdin.readline

    def reflection(x):
        s = str(x)
        t = ''.join(str(9 - int(c)) for c in s)
        return int(t)

    def weight(x):
        return x * reflection(x)

    l, r = map(int, input().split())

    ans = 0

    for k in range(1, 11):
        low = 1 if k == 1 else 10 ** (k - 1)
        high = 10 ** k - 1

        L = max(l, low)
        R = min(r, high)

        if L > R:
            continue

        M = high
        mid = M // 2

        candidates = {L, R}

        for x in [mid, mid + 1]:
            if L <= x <= R:
                candidates.add(x)

        for x in candidates:
            ans = max(ans, weight(x))

    print(ans)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

# provided sample
assert run("3 7\n") == "20", "sample 1"

# minimum range
assert run("1 1\n") == "8", "single value"

# digit-length transition
assert run("8 10\n") == "890", "crossing 9 to 10"

# midpoint optimum
assert run("40 60\n") == "2450", "peak near center"

# all equal large value
assert run("999999999 999999999\n") == "0", "all nines reflect to zero"

# large boundary case
assert run("1000000000 1000000000\n") == "899999999000000000", "largest input"

 ## 特殊なケース

 次の入力を考えてみましょう。```
9 9
```反射：$$\psi(9)=0$$重さ：$$9 \cdot 0 = 0$$アルゴリズムはこれを自然に処理します。 1 桁の数字の場合:$$M=9$$そして：$$9(9-9)=0$$整数変換によって先頭のゼロが自動的に削除されるため、先頭のゼロについては特別な処理は必要ありません。 

次に、次のことを考えてみましょう。```
8 10
```1 桁の数字の中点は約`4`、外にあります`[8,9]`。 アルゴリズムは正しくフォールバックして間隔の境界を確認します。 

2 桁の数字の場合、有効な候補は次のとおりです。`10`、その反射は次のようになります`89`。 答えはから飛びます`8`に`890`。 

もう 1 つの重要なエッジケースは次のとおりです。```
50 50
```2 桁の数字の場合:$$M=99$$反射：$$99-50=49$$重さ：$$50 \cdot 49=2450$$放物線の中点は、`49`そして`50`したがって、どちらも同じ最適値を生成します。 両方にチェックを入れる`mid`そして`mid+1`奇数の正しさを保証します`M`。 

最後に、次のことを考慮してください。```
999999999 1000000000
```のために`999999999`:$$\psi=0$$体重はゼロです。 

のために`1000000000`:$$\psi=8999999999$$重量が極端に大きくなります。 

このアルゴリズムは 2 桁の長さを独立して処理し、10 桁の間隔から大きい方の結果を正確に識別します。
