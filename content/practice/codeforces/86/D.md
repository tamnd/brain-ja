 ## 解決策
 ## 問題の理解

 正の整数の配列と多くの間隔クエリが与えられます。 クエリごとに`[l, r]`では、これらのインデックス間の部分配列のみを調べ、その累乗と呼ばれる値を計算します。 

数字の場合`x`表示されます`k`部分配列内で回、その後`x`貢献する`k² * x`答えに。 最終結果は、間隔内のすべての個別の値に対するこれらの寄与の合計です。 

たとえば、部分配列では`[1, 2, 1, 1, 2]`、値`1`表示されます`3`倍にして貢献する`3² * 1 = 9`。 値`2`表示されます`2`倍にして貢献する`2² * 2 = 8`。 合計は`17`。 

配列の長さとクエリの数は両方とも次の値に達します`200000`。 すべてのクエリを個別に処理する単純なソリューションでは、すぐに遅すぎます。 クエリごとに 1 つの完全なサブ配列を反復処理するだけでも、すでにコストがかかります`O(n * q)`最悪の場合、約`4 * 10^10`操作。 これは 5 秒に収まる量を数桁超えています。 

値自体は最大でも`10^6`これは、値でインデックス付けされた周波数配列としては十分小さいです。 クエリをより賢明な順序で処理すると、この観察は非常に役立ちます。 

微妙な点ですが、答えは大きくなる可能性があります。 すべてだとします`200000`要素は次と等しい`10^6`。 その場合、貢献度は次のようになります。$$(200000)^2 \cdot 10^6 = 4 \cdot 10^{16}$$これは 32 ビット整数に収まらないため、実装では 64 ビット演算を使用する必要があります。 

もう 1 つの簡単な間違いは、周波数が変化したときに寄与度を誤って更新することです。 次の配列を考えてみましょう。```
[5, 5]
```インターバルに関しては`[1, 2]`、正解は次のとおりです。```
2² * 5 = 20
```すでに持っている場合`5`現在の間隔で、別の値を追加します`5`だけでは答えは増えません`5`。 貢献度は次のように変化します。```
1² * 5 = 5
```に```
2² * 5 = 20
```したがって、増分は実際には`15`。 

最後の一般的なバグは、間隔の境界で発生します。 現在の間隔が`[2, 4]`そして次のクエリは`[3, 4]`。 ポインターを移動した後に左の端点を削除すると、誤ってウィンドウ内に余分な要素が残ってしまいます。 ポインタの移動と更新頻度の順序は、意図した間隔と正確に一致する必要があります。 

## アプローチ

 ブルート フォース アプローチでは、すべてのクエリが個別に処理されます。 For each interval`[l, r]`、部分配列内の頻度を数えて、次のように計算します。$$\sum cnt[x]^2 \cdot x$$ハッシュ マップまたは頻度配列を使用すると、カウントが簡単になります。 この方法は、力の定義に直接従うため、正しいです。 

問題は全体の作業量です。 単一のクエリが配列全体に及ぶ場合があるため、`O(n)`操作。 と`200000`クエリの場合、全体の複雑さは次のようになります。`O(nq)`、これは大きすぎます。 

重要な観察点は、隣接するクエリが重度に重複していることが多いということです。 2 つの区間の違いがわずか数要素だけである場合、答え全体を再計算すると、それまでの作業がほぼすべて無駄になります。 

この構造はまさに Mo のアルゴリズムが利用しているものです。 

入力順にクエリに応答するのではなく、連続するクエリの範囲が類似するようにクエリを並べ替えます。 次に、現在の間隔を 1 つ維持し、徐々に調整します。 区間が 1 要素分拡大または縮小すると、一定時間で答えを更新します。 

現在の値の周波数を仮定します`x`は`f`。 

別のものを追加する前に`x`、その貢献は次のとおりです。$$f^2 \cdot x$$これを追加すると、貢献度は次のようになります。$$(f+1)^2 \cdot x$$増加分は次のとおりです。$$((f+1)^2 - f^2) \cdot x = (2f+1)\cdot x$$他に何も再計算せずに、すぐに答えを更新できます。 

要素の削除も同様に機能します。$$f^2 \cdot x - (f-1)^2 \cdot x = (2f-1)\cdot x$$ポインタの移動ごとにコストがかかるため、`O(1)`、全体の複雑さはおよそになります。`O((n + q)\sqrt n)`これは制約に対して十分な速度です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(最大(a)) | 遅すぎる |
 | 最適な Mo のアルゴリズム | O((n + q)√n) | O(max(a) + q) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列とすべてのクエリを読み取ります。 
2. Python リストはゼロベースの位置を使用するため、クエリをゼロベースのインデックスに変換します。 
3. ブロック サイズを選択します。通常は`int(sqrt(n))`。 
4. クエリを次の基準で並べ替えます。 

まず、左端点を含むブロック、

 2 番目は、正しいエンドポイントです。 

この順序により、連続するクエリ間で間隔ポインタが移動する距離が最小限に抑えられます。 
5. 現在の間隔を維持する`[cur_l, cur_r]`とその現在の電力値。 

最初は間隔は空です。 
6. 周波数配列を維持する`freq[x]`何倍の値を格納する`x`現在の間隔内に表示されます。 
7. を定義します。`add(x)`手術。 

現在の周波数が`f`、 それから：$$answer -= f^2 \cdot x$$周波数を増加させ、$$answer += (f+1)^2 \cdot x$$これにより、影響を受ける値のみの寄与が更新されます。 
8. を定義します。`remove(x)`操作も同様に。 

現在の周波数が`f`、古い寄与を削除し、周波数を減分してから、新しい寄与を追加します。 
9. ソートされた順序でクエリを処理します。 

動く`cur_l`そして`cur_r`維持される間隔がターゲットのクエリ間隔と正確に一致するまで。 
10. 間隔が一致したら、クエリの元のインデックスを使用して、現在の回答を結果配列に保存します。 
11. すべてのクエリが処理されたら、入力順に回答を出力します。 

### なぜ効果があるのか

 常に、維持される間隔は現在のクエリ範囲と正確に一致します。 頻度配列には、その間隔内のすべての値の実際の出現数が常に格納されます。 

答えの変数は次のようになります。$$\sum freq[x]^2 \cdot x$$追加または削除操作を行うたびに、1 つの値のみの寄与が更新され、他のすべての値は変更されないためです。 

Mo の順序付けでは、有効な間隔の拡張と縮小のシーケンスを通じてすべてのクエリに到達することが保証されるため、クエリが応答されたときに維持される状態は常に正しいです。 

## Python ソリューション```python
import sys
from math import sqrt

input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    arr = list(map(int, input().split()))

    queries = []

    for idx in range(q):
        l, r = map(int, input().split())
        l -= 1
        r -= 1
        queries.append((l, r, idx))

    block_size = int(sqrt(n)) + 1

    queries.sort(
        key=lambda x: (
            x[0] // block_size,
            x[1]
        )
    )

    freq = [0] * (10**6 + 1)
    answers = [0] * q

    current_answer = 0
    cur_l = 0
    cur_r = -1

    def add(value):
        nonlocal current_answer

        f = freq[value]
        current_answer -= f * f * value

        freq[value] += 1
        f += 1

        current_answer += f * f * value

    def remove(value):
        nonlocal current_answer

        f = freq[value]
        current_answer -= f * f * value

        freq[value] -= 1
        f -= 1

        current_answer += f * f * value

    for l, r, idx in queries:

        while cur_l > l:
            cur_l -= 1
            add(arr[cur_l])

        while cur_r < r:
            cur_r += 1
            add(arr[cur_r])

        while cur_l < l:
            remove(arr[cur_l])
            cur_l += 1

        while cur_r > r:
            remove(arr[cur_r])
            cur_r -= 1

        answers[idx] = current_answer

    print("\n".join(map(str, answers)))

solve()
```この解決策は、すべてのクエリを読み取り、元のインデックスをアタッチすることから始まります。 Mo のアルゴリズムでクエリを並べ替えた後は、入力順にクエリを処理しなくなるため、各回答がどこに属するかを覚えておく必要があります。 

現在の間隔は空から始まります。`[0, -1]`。 最初の要素の追加は単純にインクリメントされるため、この表現では特殊なケースが回避されます。`cur_r`。 

周波数配列にはサイズがあります`10^6 + 1`配列値は次のように制限されているため、`10^6`。 この問題では、辞書を使用するよりもリストを使用する方がはるかに高速です。 

の`add`そして`remove`関数は実装の中核です。 よくある間違いは、古い寄与分を差し引く前に頻度を更新することです。 コードは最初に古い用語を削除します`f² * value`、頻度を変更し、更新された用語を追加します。 

ポインタの移動順序も重要です。 左側から縮小する場合、インクリメントする前に現在の左側の要素を削除します。`cur_l`。 この順序を逆にすると、間違った値が削除されます。 

すべての算術演算では Python 整数が使用され、大きな値が自動的に安全に処理されます。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from math import sqrt

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, q = map(int, input().split())
    arr = list(map(int, input().split()))

    queries = []

    for idx in range(q):
        l, r = map(int, input().split())
        queries.append((l - 1, r - 1, idx))

    block = int(sqrt(n)) + 1

    queries.sort(key=lambda x: (x[0] // block, x[1]))

    freq = [0] * (10**6 + 1)
    ans = [0] * q

    cur = 0
    L = 0
    R = -1

    def add(x):
        nonlocal cur
        f = freq[x]
        cur -= f * f * x
        freq[x] += 1
        f += 1
        cur += f * f * x

    def remove(x):
        nonlocal cur
        f = freq[x]
        cur -= f * f * x
        freq[x] -= 1
        f -= 1
        cur += f * f * x

    for l, r, idx in queries:

        while L > l:
            L -= 1
            add(arr[L])

        while R < r:
            R += 1
            add(arr[R])

        while L < l:
            remove(arr[L])
            L += 1

        while R > r:
            remove(arr[R])
            R -= 1

        ans[idx] = cur

    return "\n".join(map(str, ans))

 ## 特殊なケース

 可能な最小の間隔を考慮してください。```
1 1
9
1 1
```この間隔には、次のものが 1 回発生します。`9`、したがって、答えは次のようになります。```
1² * 9 = 9
```アルゴリズムは空の間隔から始まり、要素を 1 つだけ追加します。 周波数は次のようになります。`1`、維持された答えは次のようになります`9`。 

ここで、すべての値が等しいとみなします。```
5 1
3 3 3 3 3
1 5
```正しい答えは次のとおりです。```
5² * 3 = 75
```要素が追加されると、貢献度も進化します。```
1²*3 = 3
2²*3 = 12
3²*3 = 27
4²*3 = 48
5²*3 = 75
```更新式は非線形の増加を正確に捉えます。 

最後に、間隔を縮小することを検討してください。```
4 2
1 2 1 2
1 4
2 3
```最初の間隔には周波数があります`{1:2, 2:2}`そしてこう答えます：```
4 + 8 = 12
```に移動するとき`[2,3]`、アルゴリズムは左側を削除します`1`そして正しい`2`。 

左側を外した後`1`:```
{1:1, 2:2}
1 + 8 = 9
```右側を外した後`2`:```
{1:1, 2:1}
1 + 2 = 3
```周波数がさらに変更される前に、削除によって常に寄与が更新されるため、最終的な答えは正解です。
