 ## 解決策
 ## 問題の理解

 各要素が青または赤の色を持つ整数の配列が与えられます。 青の要素は何度でも 1 減らすことができ、赤の要素は何度でも 1 増やすことができます。 目的は、配列を 1 から 1 までの数値の順列に変換できるかどうかを判断することです。$n$、 どこ$n$配列の長さです。 ここでの順列とは、1 から 1 までのすべての整数を意味します。$n$任意の順序で 1 回だけ発生します。 

制約により許可されるのは、$n$まで$2 \cdot 10^5$テスト ケースごとに、最大で$10^4$つまり、あらゆる可能な増加/減少の総当りシミュレーションは実行不可能です。 私たちは動きをシミュレーションするのではなく、数学的に問題を推論する必要があります。 数値自体は、最大で大きくなる可能性があります。$10^9$そのため、配列の直接操作や広範囲のカウントに依存するアプローチは非効率的になります。 

単純なソリューションを失敗させる可能性のあるエッジ ケースには、最初にすべての数値が より大きい配列が含まれます。$n$たとえば、青要素のみの配列はすべて 100 に等しく、$n = 5$一部の数値は 1 未満になる必要があるため、減分によって 1 ～ 5 の範囲に到達することはできません。同様に、1 より小さい赤い要素の配列は、増加だけではターゲットに到達できません。 同じ数値の重複や極端な負の数値の場合も自明ではありません。1 から 2 までの範囲で一意の数値を達成しようとしながら色の操作を尊重する必要があるからです。$n$範囲。 

## アプローチ

 ブルートフォース手法では、各要素に対して考えられるすべての操作シーケンスをシミュレートして、順列に到達しようとします。 これは、あらゆる変換を徹底的に調査するため、原理的には正しいですが、可能性の数は、次のように指数関数的に増加します。$n$、不可能になります$n$まで$2 \cdot 10^5$。 

最適なソリューションに対する重要な洞察は、各要素が一方向にのみ調整できることを観察することによって得られます。つまり、青い要素は減少し、赤い要素は増加する可能性があります。 したがって、青色の要素については、$x$、到達できる最終的な最小値は 1 (順列では 1 を下回ることはできません)、最大値は次のとおりです。$x$自体。 赤い要素の場合$x$、最終的な最小値は次のとおりです。$x$(減らすことはできません)、最大値は$n$。 

この観察から、青色の要素と赤色の要素を個別に並べ替えて、1 から 2 までの値を割り当ててみることができます。$n$貪欲に。 青い要素は 1 から始めてできるだけ小さい値を割り当てる必要があり、赤い要素は 1 から始めてできるだけ大きい値を割り当てる必要があります。$n$、操作上の制約を考慮して、各番号が確実に到達可能であることを確認します。 いずれかの時点で、対応する要素が到達可能な範囲外にあるために番号を割り当てることができない場合、答えは「いいえ」です。

 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を 2 つのリストに分割します。`blue`すべての青色の要素が含まれており、`red`すべての赤い要素が含まれています。 これにより、それらの範囲を独立して処理できるようになります。 
2. 並べ替え`blue`昇順で。 位置にある青色の要素ごとに$i$ソートされたリストで、要素自体である到達可能な最大値を計算します。 最低限必要なのは$i+1$、順列内の最小の数値は 1 から始まり、順番に増加するためです。 青色の要素が より小さい場合$i+1$、必要な値に到達できないため、答えは NO です。 
3. 並べ替え`red`降順で。 位置にある赤い要素ごとに$i$ソートされたリストで、その要素自体である到達可能な最小値を計算します。 必要な最大値は次のとおりです$n-i$から始まる$n$そして減少しています。 赤い要素がより大きい場合$n-i$、必要な値に到達できないため、答えは NO です。 
4. すべての青と赤の要素が上記の条件を満たす場合、答えは「YES」です。 

これが機能するのは、各色が到達できる値の範囲がチェーンを形成し、それらを貪欲に割り当てることで、番号がスキップされたり重複したりすることがないためです。 維持される不変条件は、最初の$k$への数字$k$最小の青と最大の赤でも、残りのすべての数値は許容範囲内で引き続き割り当てることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_form_permutation(n, a, colors):
    blue = []
    red = []
    for val, color in zip(a, colors):
        if color == 'B':
            blue.append(val)
        else:
            red.append(val)
    
    blue.sort()
    red.sort(reverse=True)
    
    for i, val in enumerate(blue):
        if val < i + 1:
            return "NO"
    for i, val in enumerate(red):
        if val > n - i:
            return "NO"
    return "YES"

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    colors = input().strip()
    print(can_form_permutation(n, a, colors))
```まず要素を色で分け、各グループを並べ替えてから、各要素をそのターゲット範囲に対してチェックします。 並べ替えにより、小さい青色の数字が最初に小さい順列位置を取得しようとし、より大きい赤色の数字が最後に大きい位置を取得しようとします。 貪欲チェックは簡単で、シミュレーションの落とし穴を回避します。
