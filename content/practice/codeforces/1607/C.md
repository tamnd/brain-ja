 ## 解決策
 ## 問題の理解

 整数の配列と、非常に構造化された方法で配列を変更する特別な操作が与えられます。 操作が適用されるたびに、現在の最小値が 1 つ出現して削除され、残りのすべての要素から同じ値が減算されます。 これにより、配列が 1 要素ずつ縮小され、削除された最小値に応じて残りの値が上または下にシフトされます。 

目的は、これらの操作をやみくもにシミュレートすることではなく、中間段階で最終的な配列の最小要素ができるだけ大きくなるように、操作を何回適用するかを決定することです。 私たちは、いかなる操作を行う前であっても、いつでも停止することができます。 

制約が十分に大きいため、削除と配列全体の更新を繰り返しシミュレートするアプローチは遅すぎます。 各操作は残りのすべての要素に影響する可能性があるため、テスト ケース全体の合計サイズが 2·10^5 に達すると、二次または二次に近い戦略であっても失敗します。 

配列に要素が 1 つしかない場合、微妙なエッジ ケースが発生します。 そこでは演算が禁止されているため、たとえ負であっても答えは強制的に元の値になります。 もう 1 つの注意が必要な状況は、すべての要素が同一である場合です。 すべての操作で 1 つの要素が削除され、残りが 0 にシフトされるため、答えはその値で安定しますが、単純なシミュレーションでは、重要ではないにもかかわらず削除の順序を考えすぎる可能性があります。 

## アプローチ

 直接シミュレーションでは、配列の最小値を繰り返しスキャンし、それを削除し、残りのすべての要素からそれを減算します。 k 回の操作の後、配列のサイズは n−k になり、各ステップのコストは O(n) となり、最悪の場合、テスト ケースごとに O(n²) になります。 合計 n が 2・10^5 までの場合、これは遅すぎます。 

重要な観察は、この操作が値による要素の順序のみに依存し、要素の位置や ID には依存しないということです。 各ステップにより、現在のグローバル最小値が削除されます。 つまり、プロセスは基本的に要素を昇順に剥がし、各操作後に現在の最小値がゼロになるように残りの値を継続的にシフトします。 

シミュレーションする代わりに、逆に考えることができます。配列をソートした後、より小さな要素を 1 つずつ「取り消し」た場合に最小値がどのように変化するかを検討します。 最適な停止点は、完全に抽出されるソートされた配列のプレフィックスを選択することに対応します。 残りの要素はすべて、削除された最小値をすべて減算することによってシフトされています。 

配列をソートする場合、最初の i 番目の最小要素を削除した後に停止するどの段階でも、残りの要素は、削除された最小寄与の合計を減算することによって効果的に変換されます。 したがって、残りのセットの最小値は、まだ削除されていない元の要素の最小値から、以前の削除による累積シフトを差し引いたものによって決まります。 

この構造により、実行中の減算オフセットを追跡することにより、ソートされた配列に対する 1 回のパスで候補の答えを計算できます。

 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n²) | O(n) | 遅すぎる |
 | ソート + プレフィックス推論 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を降順でない順に並べ替えます。 この操作では常に現在の最小値が削除されるため、これにより、将来のすべての削除が発生する正確な順序で整列されます。 
2. 実行中の変数を維持する`shift`、最初はゼロです。 これは、以前に削除された最小値によって残りのすべての要素から差し引かれた合計量を表します。 
3. 並べ替えられた配列を最小から最大まで繰り返します。 位置 i で治療します`a[i] - shift`以前のすべての操作後の現在の要素の実効値として。 
4. 各ステップで、以下に等しい答えの候補を計算します。`a[i] - shift`。 ここまでの処理で停止した場合に残る要素の中で最も小さい値を表します。 
5.アップデート`shift`追加することで`a[i]`。 これは、この要素を最小限に削除した場合、残りのすべての要素が将来の操作でその値だけ減らされることを反映しています。 
6. すべての可能な停止点の中で最終的な最小値を最大化したいので、すべての候補にわたる最大値を追跡します。 

### なぜ効果があるのか

 並べ替え後、すべての操作で、まだ処理されていない元の値の中で残っている最小の値が削除されます。 削除された各要素は、その後のすべての要素に適用される累積減算にその値を正確に反映します。 これにより、削除されていない要素の実効値は、元の値から以前に削除されたすべての要素の合計を引いたものと等しくなります。 したがって、停止点での最小値は常に、ソート順で最初の未処理の要素によって決定され、蓄積されたシフトによって調整されます。これはまさにアルゴリズムが評価するものです。 

現在の配列の最小要素を削除することは、インデックスを再作成した後に次に小さい元の要素を削除することに対応する必要があるため、この構造を変更する再配置の選択肢は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 1:
        print(a[0])
        continue
    
    a.sort()
    
    shift = 0
    ans = -10**18
    
    for i in range(n):
        ans = max(ans, a[i] - shift)
        shift += a[i]
    
    print(ans)
```解決策は、操作が許可されていないため、単一要素の場合を個別に処理することから始まります。 並べ替えは、値の増加に応じて強制削除の順序を揃えるため、必須です。 

変数`shift`以前の削除により残りの要素に適用された減算の合計を累積します。 各インデックスで、プロセスを停止した場合に現在の最小残り値がいくらになるかを評価します。 答えはそのような最大値です。 

よくある落とし穴は、現在の要素を評価した後にシフトを更新する必要があることを忘れることです。 この順序を逆にすると、現在の候補に減算が誤って適用され、すべての結果が下方にシフトされます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys as _sys
    input = _sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        if n == 1:
            out.append(str(a[0]))
            continue
        a.sort()
        shift = 0
        ans = -10**18
        for x in a:
            ans = max(ans, x - shift)
            shift += x
        out.append(str(ans))
    return "\n".join(out)

 ## 特殊なケース

 単一要素の配列では、操作が許可されないため、出力がその要素になるように直接強制されます。 この場合、アルゴリズムは明示的に早期に戻り、不必要な並べ替えやシフトを回避します。 

次のような同一の値の配列の場合、`[x, x, x]`、並べ替えは何も行わず、すべての候補は次のようになります。`x - kx`k を増加させますが、最大値は最初のステップで発生し、x が生成されます。 各候補は対応する減算が適用される前に評価されるため、ランニング シフト ロジックはこれを自然に捉えます。 

大きな負の値の後に正の値が続く配列の場合、シフトにより負の質量が早期に蓄積され、後の要素が効果的にブーストされます。 ソートされたパスでは、すべての状態がソートされた配列のプレフィックスの合計にのみ依存するため、破壊的な更新をシミュレートする必要がなく、これが確実に考慮されます。
