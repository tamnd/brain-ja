 ## 解決策
 ## 問題の理解

 この問題は、カジノに複数のゲームがあり、それぞれが一定の金額を獲得するチャンスを提供することを示しています。 各ゲームには 2 つのパラメータがあります。1 つはパーセンテージで指定された勝利確率、もう 1 つは勝った場合の配当です。 プレイするゲームのサブセットを選択できますが、選択したすべてのゲームに勝った場合にのみお金を獲得できます。 選択したサブセットで 1 試合でも負けた場合は、何も受け取りません。 タスクは、賞金の期待値を最大化する一連のゲームを選択することです。 

選択したセットの期待値は、確率 (分数に変換) と賞金の合計の積です。 たとえば、確率が 80% と 50%、ペイアウトが 80 と 200 の 2 つのゲームを選択した場合、期待値は次のようになります。$(0.8 * 0.5) * (80 + 200) = 112$。 

制約は重要です: ゲーム数$n$200,000 に達する可能性があります。 すべてのサブセットのブルートフォース検査には、以下が含まれます。$2^n$組み合わせは不可能です。 個々の確率と賞金は、その積が次の値を超えないように制限されます。$2 \cdot 10^5$、数値の安定性を確保します。 

明らかではないエッジケースには、より多くのゲームを選択すると期待値が減少する状況が含まれます。 たとえば、確率は低いがペイアウトが高いゲームを選択すると、他のゲームと組み合わせると期待値が減少する可能性があります。 もう 1 つのエッジ ケースは、すべての確率が 100% である場合です。この場合、すべてのゲームを選択することが最適です。 同様に、リスクの高いゲームと組み合わせるよりも、高確率で低配当のゲームを 1 つ選択する方が良い場合があります。 

## アプローチ

 ブルートフォースアプローチでは、ゲームのすべてのサブセットが検査されます。 サブセットごとに、確率の積と賞金の合計を計算し、それらを乗算して期待値を取得します。 これは問題定義に直接従うため、正しいです。 ただし、$n \le 2 \cdot 10^5$、 がある$2^{200000}$サブセットは天文学的に大きい。 このアプローチは不可能です。 

最適化の重要な観察は、期待値関数は確率では乗算的であるが、賞金では加算的であるということです。 期待値に影響を与える確率の比率、または同等の次のような指標によってゲームを並べ替えるとします。$w_i / (1 - p_i/100)$、ゲームを入れることで期待値が上がるかどうかを貪欲に判断できます。 これにより、期待値が増大する一方で、限界寄与が最も高いゲームを繰り返し追加するという問題が軽減されます。 関数の構造により、ゲームを追加すると期待値が減少すると、(同じメトリックでソートされた) さらにゲームを追加しても役に立たず、早期に停止できるようになります。 

最適なアプローチでは、ゲームを降順に並べ替えます。$w_i / (100 / p_i - 1)$、ゲームを含めて単純化することに関して期待値の導関数を設定することによって導出されます。 次に、このソートされた順序を繰り返し、確率と賞金の合計の積を累積的に計算します。 この反復中に発生した最大期待値が答えになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.ゲーム数を読む$n$そして確率のリスト$p_i$そして賞金$w_i$。 計算のために確率を分数に変換します。 
2. 各ゲームを追加するメリットを評価するための指標を定義します。 自然な選択は、$w_i / (1 - p_i/100)$、これは損失の確率に対する配当の比率を表し、期待値へのわずかな寄与を反映しています。 
3. すべてのゲームをこのメトリックの降順に並べ替えます。 利益のより高いゲームが最初に考慮されます。 
4. 2 つの変数: 累積確率を初期化します。$prob = 1.0$選択したゲームの確率と賞金の累積合計を表します。$sum\_w = 0$。 
5. ソートされたゲームを繰り返し処理します。 ゲームごとに、このゲームが含まれている場合の潜在的な期待値を計算します。$new\_EV = prob * (p_i/100) * (sum\_w + w_i)$。 
6. ゲームを含めることで現在の最大期待値が増加する場合は、更新します$prob$そして$sum\_w$このゲームを含めて最大値を更新します。 
7. ゲームを追加すると、追加のゲームの限界寄与が小さくなるため、期待値が減少したら反復を停止します。 
8. 見つかった最大の期待値を、十分な精度にフォーマットして出力します。 

機能する理由: ゲームを降順に考慮すると、期待値関数は単峰性になります。$w_i / (1 - p_i/100)$。 このプロパティにより、ゲームを追加すると期待値が減少し、残りのゲームも期待値が減少します。 したがって、ゲームを貪欲に追加すると、すべてのサブセットをチェックしなくても最大値が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
games = []

for _ in range(n):
    p, w = map(int, input().split())
    games.append((p, w))

# Sort by "benefit" metric w / (1 - p/100) descending
games.sort(key=lambda x: x[1] / (1 - x[0] / 100), reverse=True)

max_ev = 0.0
prob = 1.0
sum_w = 0.0

for p, w in games:
    new_prob = prob * (p / 100)
    new_sum_w = sum_w + w
    ev = new_prob * new_sum_w
    if ev > max_ev + 1e-12:
        max_ev = ev
        prob = new_prob
        sum_w = new_sum_w
    else:
        break

print(f"{max_ev:.9f}")
```このソリューションは、次を使用して入力を効率的に読み取ります。`sys.stdin.readline`。 ゲームは比率で並べ替えられます$w / (1 - p/100)$、限界期待値の成長を捉えます。 期待値が上昇した場合のみ累積確率と獲得金額が更新されるため、劣化を防ぎます。 浮動小数点エラーを避けるために、比較に小さなイプシロンを含めます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | n ゲームの並べ替えが主流です。 反復は線形です |
 | スペース | O(n) | ゲームと累積変数のストアリスト |

 n が最大 2・10^5 の場合、O(n log n) 操作 (約 300 万) は 2 秒以内に快適に収まり、メモリ使用量は 256 MB をはるかに下回ります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    games = [tuple(map(int, input().split())) for _ in range(n)]
    games.sort(key=lambda x: x[1] / (1 - x[0] / 100), reverse=True)
    max_ev = 0.0
    prob = 1.0
    sum_w = 0.0
    for p, w in games:
        new_prob = prob * (p / 100)
        new_sum_w = sum_w + w
        ev = new_prob * new_sum_w
        if ev > max_ev + 1e-12:
            max_ev = ev
            prob = new_prob
            sum_w = new_sum_w
        else:
            break
    return f"{max_ev:.9f}"

# Provided samples
assert run("3\n80 80\n70 100\n50 200\n") == "112.000000000", "sample 1"
assert run("2\n100 1\n100 1\n") == "2.000000000", "sample 2"

# Custom cases
assert run("1\n50 100\n") == "50.000000000", "single game"
assert run("3\n100 10\n90 20\n80 30\n") == "36.000000000", "all probabilities high"
assert run("2\n10 1000\n90 10\n") == "90.000000000", "high payout low prob vs low payout high prob"
assert run("4\n50 50\n50 50\n50 50\n50 50\n") == "62.5", "all equal"
