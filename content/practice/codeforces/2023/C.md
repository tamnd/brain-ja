## アルゴリズムのチュートリアル

 1. 各グラフについて、任意のルート頂点を選択し、それに剰余 0 を割り当てます。DFS または BFS を実行し、エッジをトラバースするたびに$u \to v$、割り当てます$res[v] = (res[u] + 1) \bmod k$、またはすでに割り当てられている場合は一貫して推測します。 すべてのサイクルは次の値で割り切れる長さがあるため、$k$、矛盾は生じません。 これにより、両方のグラフのすべての頂点に対して明確に定義された残差ラベルが生成されます。 
2. 各剰余クラスの頂点の数が 4 つのカテゴリのそれぞれに属するかを数えます: グラフ 1 発信、グラフ 1 着信、グラフ 2 発信、グラフ 2 着信。 これらの分布は、クロスエッジに関連するすべての制約をエンコードします。 
3. 追加されたすべてのエッジはグラフ間を通過する必要があるため、一方のグラフの出力頂点ともう一方のグラフの入力頂点の間で全単射を効果的に構築していることに注目してください。 これは、2 つの独立した 2 部マッチング問題に分割されます。グラフ 1 の出力からグラフ 2 の入力へのエッジと、グラフ 2 からの出力からグラフ 1 の入力へのエッジです。 
4. サイクル剰余構造を保存するためのマッチングの場合、エッジは、その剰余の差がグラフ間のトラバーサルによって引き起こされる固定モジュラー シフトと一致するという意味で互換性のある剰余を持つ頂点のみを接続できます。 どちらのグラフも内部的に一貫したモジュロであるため、$k$、この互換性は、グローバル シフトによって 1 つのグラフの剰余を正規化した後の同一の剰余クラス内での一致に帰着します。 
5. 私たちはすべてを試みます$k$グラフ 1 とグラフ 2 の剰余系を整列させる可能なシフト。各シフトについて、すべての剰余クラスについて次のことを確認します。$r$、残差のあるグラフ 1 の出力頂点の数$r$剰余を含むグラフ 2 の入力頂点の数に等しい$r + \delta \bmod k$、逆方向についても同様です。

### なぜ効果があるのか

 不変条件は、各グラフが一貫したポテンシャル関数モジュロを許容することです。$k$、そして有向パスはその長さによってポテンシャルを変化させます。 クロスエッジを追加した後に形成されるサイクルは、総電位変化がゼロモジュロである必要があります。$k$これにより、クロスエッジの端点残基が 2 つのグラフ間の単一のグローバル シフトの下で強制的に位置合わせされます。 このアラインメントが修正されると、問題は剰余クラス内の等しいマルチセットのマッチングに減ります。 このようなシフトが存在しない場合、クロスエッジには必然的に、その長さが可分性制約に違反するサイクルが導入されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_res(n, adj, k):
    res = [-1] * (n + 1)
    stack = [(1, 0)]
    res[1] = 0
    while stack:
        u, r = stack.pop()
        for v in adj[u]:
            nr = (res[u] + 1) % k
            if res[v] == -1:
                res[v] = nr
                stack.append((v, nr))
            else:
                if res[v] != nr:
                    return None
    return res[1:]

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        m1 = int(input())
        adj1 = [[] for _ in range(n + 1)]
        for _ in range(m1):
            u, v = map(int, input().split())
            adj1[u].append(v)

        m2 = int(input())
        adj2 = [[] for _ in range(n + 1)]
        for _ in range(m2):
            u, v = map(int, input().split())
            adj2[u].append(v)

        b = list(map(int, input().split()))

        # build dummy residues (conceptual; structure assumed consistent)
        r1 = build_res(n, adj1, k)
        r2 = build_res(n, adj2, k)

        if r1 is None or r2 is None:
            print("NO")
            continue

        cnt1_out = [[0] * k for _ in range(2)]
        cnt1_in  = [[0] * k for _ in range(2)]
        cnt2_out = [[0] * k for _ in range(2)]
        cnt2_in  = [[0] * k for _ in range(2)]

        for i in range(n):
            if a[i] == 1:
                cnt1_out[0][r1[i]] += 1
            else:
                cnt1_in[0][r1[i]] += 1

        for i in range(n):
            if b[i] == 1:
                cnt2_out[1][r2[i]] += 1
            else:
                cnt2_in[1][r2[i]] += 1

        ok = False
        for shift in range(k):
            good = True
            for r in range(k):
                rr = (r + shift) % k
                if cnt1_out[0][r] != cnt2_in[1][rr]:
                    good = False
                    break
                if cnt2_out[1][r] != cnt1_in[0][rr]:
                    good = False
                    break
            if good:
                ok = True
                break

        print("YES" if ok else "NO")

if __name__ == "__main__":
    solve()

2 番目の部分では、頂点をタイプと残基ごとにグループ化します。 シフトオーバーによりマッチング条件を確認$k$これは、2 つのグラフが異なる絶対剰余原点を持つ可能性があるという事実を説明しています。 

よくある実装の落とし穴は、シフトを頂点ごとやエッジごとではなく、すべての残基にわたってグローバルにテストする必要があることを忘れていることです。 もう 1 つの微妙な問題は、受信カウントと送信カウントを対称的に扱うことです。 これらは、両方が保持されなければならない 2 つの独立した 2 部制約を形成します。

 ## 特殊なケース

 微妙なエッジ ケースは、両方のグラフが個別に有効であるにもかかわらず、シフトごとに互換性のない剰余分布がある場合です。 この状況でも、DFS は依然として一貫したラベルを生成しますが、グラフ 1 の出力頂点で 1 つの残差クラスが過剰に表現されている一方、グラフ 2 の入力頂点と一致するシフトされたクラスがないため、最後のマッチング ステップは失敗します。シフト ループではすべてのクラスにわたって同等性が見つからないため、アルゴリズムはこのケースを正しく拒否します。
