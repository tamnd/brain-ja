 ## 解決策
 ## 問題の理解

 それぞれ整数の強さをもつアリの列が与えられています。 モグラは、列の指定された連続したセグメントでのアリ同士の争いを観察したいと考えています。 位置 _l_ から _r_ までの特定のセグメントについて、すべてのアリがそのセグメント内の他のすべてのアリと戦います。 アリは、自分の強さが他のアリの強さを二分した場合にのみ、別のアリからバトル ポイントを獲得します。 すべての戦いの後、アリが参加したすべての戦いで勝利した場合、つまり、戦闘ポイントがセグメント内の敵の数 (_(r - l)_) と等しい場合、アリは解放されます。 モグラは残ったアリをすべて食べます。 タスクは、セグメント クエリごとに、Mole が食べるアリの数を決定することです。 

この問題には最大 100,000 個のアリと 100,000 個のクエリがあり、各アリの強さは 10^9 にもなる可能性があります。 すべてのクエリでアリのすべてのペアを反復する単純なソリューションでは、クエリごとに O(n²) の操作が必要になりますが、これはまったく実行不可能です。 計算量を減らすために、長所の構造とその可分性関係を利用するアプローチが必要です。 

明らかではないエッジ ケースには、すべての強度が等しいセグメント (すべてのアリが解放されることになる)、または 1 がすべての数値を割るため 1 を含むセグメントが含まれます。 たとえば、強みが次のような場合`[1, 2, 3]`そしてクエリは`[1,3]`2 は 3 を分割せず、3 は 2 を分割しないため、強度 1 のアリだけが解放されます。不注意なアプローチでは、この非対称性を見逃す可能性があります。 

もう 1 つの特殊なケースは、数字が繰り返されることです。 で`[2, 2, 2]`セグメント上で`[1,3]`、各アリが互いに分割するので、各アリは解放されます。 繰り返される強さを考慮しないと、食べられたアリの数が不正確になるでしょう。 

## アプローチ

 ブルート フォース ソリューションは、各セグメント内のすべてのペアを反復処理します。 長さ _k_ のセグメントの場合、割り切れるかどうかを O(k²) 回チェックする必要があり、最悪の場合は O(n² * t) 回の演算が必要になります。 n = 10^5 および t = 10^5 では、これは完全に不可能です。 

より高速なソリューションに対する重要な洞察は、セグメント内の他のすべての数値で割り切れる数値のみを解放できるということです。 したがって、解放されたアリは、セグメント内のすべての強度の最大公約数 (GCD) に等しい強度を持たなければなりません。 他のアリは、GCD に等しくない限り、他のアリで割り切れません。 セグメント ツリーまたはプレフィックス GCD 配列を利用して、事前計算により任意のクエリ セグメントの GCD を O(log n) または O(1) 時間ですばやく計算できます。 

次に、セグメント内の GCD に等しいアリの数をカウントするために、各固有の強度からその出現位置へのマッピングを維持し、二分検索を使用した O(log k) クエリを可能にします。 セグメントの答えは、セグメント内のアリの総数からセグメント GCD に等しい強度を持つアリの数を引いたものになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² * t) | お(1) | 遅すぎる |
 | プレフィックス GCD + インデックス付きカウント | O(n + t log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレフィックス GCD 配列を事前計算します。 させて`prefix_gcd[i]`最初の i アリの GCD になります。 これにより、任意のセグメントの GCD を計算できるようになります。`[l, r]`として`gcd(prefix_gcd[r], prefix_gcd[l-1])`。 
2. 強度値からその位置のソートされたリストへのマッピングを構築します。 これにより、二分探索を使用して、任意のセグメント内で GCD に等しいアリの数を数えることができます。 
3. クエリごとに`[l, r]`、セグメント GCD を計算します。 これは、解放されたアリが必ず持つべき強さです。 
4. マッピングを使用して、強度がセグメント内のセグメント GCD に等しいアリの数を見つけます。`[l, r]`。 セグメントの長さからこのカウントを減算します。`(r-l+1)`モグラが食べるアリの数を取得します。 
5. すべてのクエリの結果を出力します。 

それが機能する理由: アリは、セグメント内の他のすべての強さを分割する場合にのみ解放されます。 セット内のすべての数値を除算する唯一の強みは GCD です。 セグメント内の GCD の位置を数えることにより、すべての解放されたアリを正確に識別します。 減算すると食べた数が得られます。 

## Python ソリューション```python
import sys
import math
import bisect
input = sys.stdin.readline

def main():
    n = int(input())
    s = list(map(int, input().split()))
    
    prefix_gcd = [0] * (n + 1)
    for i in range(1, n + 1):
        prefix_gcd[i] = math.gcd(prefix_gcd[i-1], s[i-1])
    
    pos_map = {}
    for idx, val in enumerate(s):
        if val not in pos_map:
            pos_map[val] = []
        pos_map[val].append(idx + 1)  # 1-indexed for queries
    
    t = int(input())
    res = []
    for _ in range(t):
        l, r = map(int, input().split())
        # Compute GCD of segment
        seg_gcd = prefix_gcd[r]
        if l > 1:
            seg_gcd = math.gcd(seg_gcd, prefix_gcd[l-1])
        # Count how many ants equal GCD in [l,r]
        positions = pos_map.get(seg_gcd, [])
        left = bisect.bisect_left(positions, l)
        right = bisect.bisect_right(positions, r)
        count_gcd = right - left
        res.append((r - l + 1) - count_gcd)
    
    print('\n'.join(map(str, res)))

if __name__ == "__main__":
    main()
```プレフィックス GCD により、任意のセグメントの GCD を迅速に計算できるようになります。 の`pos_map`セグメントをスキャンせずに出現回数をカウントできます。 ソートされた位置での二分探索は非常に重要です。 セグメントに対する単純な線形スキャンでは遅すぎます。 

## 実用的な例

 | --- | --- | --- | --- | --- | --- |
 | prefix_gcd を計算する | [0,1,1,1,1,1] | - | - | - | - |
 | クエリ 1 | - | 1 | [1] | 1 | 5-1 = 4 |

 ant 1 のみが解放されます。 モグラはアリ 2、3、4、5 を食べます。 

**例 2:**`[2,2,2,2]`、クエリ`[1,4]`| ステップ | プレフィックス_gcd | セグ_gcd | GCD の位置 | カウント_gcd | 食べた |
 | --- | --- | --- | --- | --- | --- |
 | prefix_gcd を計算する | [0,2,2,2,2] | - | - | - | - |
 | クエリ | - | 2 | [1,2,3,4] | 4 | 4-4 = 0 |

 すべてのアリは解放されます。 モグラは何も食べません。 

これらのトレースは、アルゴリズムがどのようにセグメント GCD を正しく識別し、位置をカウントするかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n + t log n) | 建物の接頭辞 GCD と位置マップは O(n) です。 各クエリは O(1) で GCD を実行し、O(log n) でバイナリ検索を実行します。 |
 | スペース | O(n) | プレフィックス GCD 配列と位置マップは、合計で最大 n 個の位置を格納します。 |

 n、t ≤ 10^5 で、各操作が二分探索の log n によって制限されている場合、ソリューションは 1 秒以内に快適に実行され、使用するメモリは 256 MB を大幅に下回ります。
