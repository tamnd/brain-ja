 ## 解決策
 ## 問題の理解

 私たちは、順番に並べられたいくつかのミミズの山を与えられます。 ワームにはすべての山にわたって連続した番号が付けられます。 

パイルのサイズが次の場合:```
2 7 3
```次に、最初の山には 1 ～ 2 の番号が付いたワームが含まれ、2 番目の山には 3 ～ 9 の番号が付いたワームが含まれ、3 番目の山には 10 ～ 12 の番号が付いたワームが含まれます。 

クエリごとにワーム ラベルが与えられ、どの山にそのワームが含まれているかを判断する必要があります。 

重要な課題は、パイルの数とクエリの数の両方が最大になる可能性があることです。$10^5$。 すべてのクエリに対してすべてのパイルをスキャンするソリューションは、最大で次のパフォーマンスを発揮します。$10^{10}$1 秒の制限時間をはるかに超えた最悪の場合の操作。 もっと近いものが必要です$O(n \log n)$または$O((n+m)\log n)$。 

微妙な点は、ワームのラベルが杭の境界上に正確に存在することがよくあることです。 考慮する：```
2
2 3
2
2 3
```杭は以下の範囲をカバーします。```
Pile 1: [1, 2]
Pile 2: [3, 5]
```正しい答えは次のとおりです。```
1
2
```不注意な二分探索の実装により、クエリ以上ではなく厳密にクエリよりも大きい最初のプレフィックス合計を検索する場合、ワーム 2 が誤ってパイル 2 に配置される可能性があります。 

もう 1 つのよくある間違いの原因は、山の最初の虫です。```
3
2 2 2
1
3
```範囲は次のとおりです。```
Pile 1: [1, 2]
Pile 2: [3, 4]
Pile 3: [5, 6]
```ワーム 3 はパイル 2 に属します。範囲の構築に 1 つずれたエラーがあると、間違った結果が生成されます。 

## アプローチ

 簡単な解決策は、すべてのパイルでカバーされる範囲を再構成し、クエリごとに正しい範囲が見つかるまでパイルを 1 つずつスキャンすることです。 

たとえば、構築後:```
Pile 1: [1, 2]
Pile 2: [3, 9]
Pile 3: [10, 12]
...
```各間隔を順番に確認できます。 すべてのワームが正確に 1 つの山に属しているため、これが機能します。 問題はパフォーマンスです。 と$10^5$杭と$10^5$クエリを実行する場合があります$10^{10}$間隔チェック。 

番号付けの構造により、より優れたオプションが提供されます。 パイル サイズのプレフィックスの合計を計算すると、次が得られます。```
a = [2, 7, 3, 4, 9]

prefix = [2, 9, 12, 16, 25]
```各プレフィックスの合計は、そのパイルに含まれる最大のワーム ラベルを表します。 

ワームは、終了ラベルが少なくともワーム番号である最初の山に属します。 たとえば、ワーム 11 は次の理由からパイル 3 に属します。```
2  < 11
9  < 11
12 >= 11
```プレフィックス合計配列は昇順にソートされるため、二分検索が適用可能になります。 すべての山をスキャンする代わりに、クエリと等しいかそれ以上の最初のプレフィックス合計を見つけます。$O(\log n)$時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 最適 | O(n + m log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 杭の数とそのサイズを読み取ります。 
2. プレフィックス合計配列を構築します。`prefix[i]`山にあるワームの総数に等しい`1..i+1`。 

これにより、杭のサイズが杭の終了位置に変換されます。 
3. 各クエリワームラベルについて`q`、プレフィックス合計配列に対して二分検索を実行します。 
4. プレフィックスの合計が以下の最初の位置を見つけます。`q`。 

これにより、終了ラベルがクエリされたワームに到達または通過する最初のパイルが識別されます。 
5. 1 から始まる番号付けを使用して杭インデックスを出力します。 

### なぜ効果があるのか

 プレフィックス合計配列は、すべてのワーム ラベルを連続した範囲に分割します。 

もし：```
prefix[i-1] < q <= prefix[i]
```次に、以下のすべてのラベル`prefix[i-1]`前のパイルに属しますが、パイル`i+1`で始まるラベルが含まれています`prefix[i-1] + 1`そして終わる`prefix[i]`。 少なくとも次の最初のプレフィックス合計を見つける`q`したがって、正しいパイルを一意に決定します。 二分探索はこの境界を効率的に特定するだけです。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve():
    n = int(input())
    piles = list(map(int, input().split()))

    prefix = []
    total = 0

    for x in piles:
        total += x
        prefix.append(total)

    m = int(input())
    queries = list(map(int, input().split()))

    ans = []

    for q in queries:
        pile = bisect_left(prefix, q) + 1
        ans.append(str(pile))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```コードの最初の部分では、プレフィックス合計配列を構築します。 各要素には、そのパイルに属する最大のワーム ラベルが格納されます。 

重要な操作は次のとおりです。```
bisect_left(prefix, q)
```

`bisect_left`値が以下の最初の位置を返します。`q`。 これは、この問題に必要な数学的条件と一致します。 

の`+1`ゼロから始まる配列の位置を、ステートメントで必要な 1 から始まるパイルの番号付けに変換します。 

Python の組み込み二分探索を使用すると、多くの境界ミスを回避できます。 特に、この問題で最も一般的なオフバイワン トラップであるパイル エンドポイントに等しいクエリを正しく処理します。

 ## 特殊なケース

 クエリが杭の端点と正確に等しいと考えてください。```
2
2 3
1
2
```プレフィックスの合計:```
[2, 5]
```二分探索`2`位置を返します`0`なぜなら`prefix[0] = 2`。 答えはパイルです`1`、それは正しいです。 クエリよりも厳密に大きい最初のプレフィックス合計を検索すると、誤ってパイルが返されてしまう`2`。 

新しい山の最初のワームであるクエリを考えてみましょう。```
2
2 3
1
3
```プレフィックスの合計:```
[2, 5]
```二分探索`3`位置を返します`1`なぜなら`2 < 3 <= 5`。 答えは山になる`2`。 これにより、間隔の開始を明示的に保存しなくても、パイルの開始が正しく処理されることが確認されます。 

可能な限り最小の入力を考慮してください。```
1
1
1
1
```プレフィックスの合計:```
[1]
```二分探索`1`位置を返します`0`、パイルを与える`1`。 このアルゴリズムは、山とワームが 1 つしか存在しない場合でも機能します。 

コレクション全体の最後のワームについて考えてみましょう。```
3
2 2 2
1
6
```プレフィックスの合計:```
[2, 4, 6]
```二分探索では少なくとも最初のプレフィックスの合計が見つかります`6`、これが最後の要素です。 答えはパイルです`3`、番号付けスキームの上限が正しく処理されていることを確認します。
