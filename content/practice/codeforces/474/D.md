 ## 解決策
 ## 問題の理解

 ディナーは一連の花として表現されます。 赤い花が長さをもたらします`1`一方、白い花は特別です。それらは、正確に連続したグループでのみ現れる可能性があります。`k`花。 

個々の花について考えるよりも、全長のディナーを構築することを考える方がずっと簡単です。`n`2 種類のブロックを使用します。 

- 長さの赤いブロック`1`。 
- 一定の長さの白いブロック`k`。 

有効なディナーはすべて、これらのブロックのシーケンスに対応しており、その全長は`n`。 白人グループの配置が異なると夕食も異なるため、順序は重要です。 

クエリごとに`[a, b]`、間の長さがある有効なディナーの数を数えなければなりません。`a`そして`b`、包括的。 すべての回答は必須です`10^9 + 7`。 

可能な最大のディナーの長さは次のとおりです。`10^5`、まであります`10^5`クエリ。 すべてのクエリに対して独立して回答を再計算するアプローチは、直ちに疑わしいものになります。 たとえ`O(10^5)`クエリごとの計算には約`10^10`制限時間を大幅に超えた最悪の場合の作戦。 

制約構造は、以下のすべての長さを前処理することを強く示唆しています。`10^5`1 回だけ、その後は一定時間内にすべてのクエリに応答します。 

よくある間違いは、白い花をグループとしてではなく個別に扱うことです。 たとえば、次のようなとき`k = 3`、長いディナー`2`白い花は一切入れられません。 有効なディナーは 1 つだけです。```
RR
```A recurrence that allows adding a single white flower would incorrectly count additional invalid configurations.

 Another easy off-by-one error appears in range queries. 仮定する：```
1 2
2 3
```長さのカウントが必要です`2`そして`3`、包括的。 プレフィックスの合計を作成して次のように答えると、`pref[b] - pref[a]`、誤って長さを除外してしまいました`a`。 正しい式は`pref[b] - pref[a-1]`。 

3 番目のエッジケースは次の場合に発生します。`n < k`。 例えば：```
k = 5
n = 3
```白いグループは当てはまらないので、赤い花しかありません。 答えは次のとおりです。`1`。 盲目的にアクセスする再発`dp[n-k]`境界をチェックしないと失敗します。 

## アプローチ

 ブルートフォースのアイデアは単純です。 あらゆる長さに対して`n`、適合するたびに、再帰的に赤い花または白いグループのいずれかを配置してみてください。 すべての完全な構築は 1 回の有効なディナーに対応します。 

このアプローチは、すべての可能性を明示的に列挙しているため、正しいです。 残念ながら、有効なディナーの数は急激に増加しています。 中程度の値であっても、`n`、再帰ツリーは巨大になります。 長さが届くので、`100000`、網羅的な生成は完全に不可能です。 

重要な点は、残りの長さのみが重要であるということです。 定義すると`dp[n]`全長の有効なディナーの数として`n`の場合、すべての有効なディナーは 2 つの方法のうちの 1 つで終了します。 

それは赤い花で終わるか、長さの有効なディナーを残すかのどちらかです`n-1`、またはサイズの白いグループで終わります`k`、有効な長さの夕食を残します`n-k`。 

これにより、すぐに再発が発生します。```
dp[n] = dp[n-1] + dp[n-k]
```いつでも`n >= k`。 

以下の長さの場合`k`、白いグループを配置することはできないため、配置は 1 つだけです。すべて赤い花です。 

すべて計算した後`dp[n]`必要な最大長までの値を指定できますが、クエリに答えるには範囲を合計する必要があります。 まであるので、`10^5`クエリの場合、プレフィックスの合計も事前計算します。```
pref[i] = dp[0] + dp[1] + ... + dp[i]
```次に、任意のクエリ`[a, b]`は次のようになります:```
pref[b] - pref[a-1]
```それは一定時間です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | O(n) 再帰 | 遅すぎる |
 | 最適 | O(MAXN + t) | O(MAXN) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのクエリとその値を読み取ります。`k`。 
2. の最大値を決定します。`b`あらゆるクエリに出現します。 この長さまでの DP 値のみが必要です。 
3. 配列を作成する`dp`どこ`dp[i]`全長の有効なディナーの数を表します`i`。 
4.セット`dp[0] = 1`。 

長さを伸ばす方法はまさに1つです`0`、何も選択しません。 これは再発の基本ケースとして機能します。 
5.あらゆる長さについて`i`から`1`に`max_b`:

 - から始める`dp[i] = dp[i-1]`、赤い花で終わることに対応します。 
- もし`i >= k`、 追加`dp[i-k]`、白グループでの終了に対応します。 
6. すべての更新モジュールを取得します`10^9 + 7`。 
7. プレフィックス合計配列を構築します。 

-`pref[0] = dp[0]`-`pref[i] = pref[i-1] + dp[i]`8. 各クエリについて`[a, b]`、次を計算します。```
answer = pref[b] - pref[a-1]
```そしてモジュロ演算で調整します。 
9. すべてのクエリに対する回答を出力します。 

### なぜ効果があるのか

 繰り返しは、長さのすべての有効なディナーを分割します。`n`最終ブロックによると。 

最後のブロックが赤い花の場合、それを削除すると、長さのある固有の有効なディナーが残ります。`n-1`。 逆に、有効な長さのディナーはすべて、`n-1`赤い花を1つ増やすことができます。 

最後のブロックが白いグループの場合、そのグループを削除すると、長さのある固有の有効なディナーが残ります。`n-k`。 逆に、有効な長さのディナーはすべて、`n-k`白いグループを 1 つ増やすことができます。 

これら 2 つのカテゴリは互いに関連しておらず、あらゆる可能性をカバーしているため、その数は加算されます。 基本ケースは正しく、より大きな状態はすべてより小さな正しい状態から派生するため、DP は長さごとに有効なディナーの正確な数を計算します。 

プレフィックス配列には累積カウントが格納されるため、2 つのプレフィックスを減算すると、クエリ範囲内の長さが正確に分離されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 1000000007

def solve():
    t, k = map(int, input().split())

    queries = []
    max_b = 0

    for _ in range(t):
        a, b = map(int, input().split())
        queries.append((a, b))
        max_b = max(max_b, b)

    dp = [0] * (max_b + 1)
    dp[0] = 1

    for i in range(1, max_b + 1):
        dp[i] = dp[i - 1]
        if i >= k:
            dp[i] = (dp[i] + dp[i - k]) % MOD

    pref = [0] * (max_b + 1)
    pref[0] = dp[0]

    for i in range(1, max_b + 1):
        pref[i] = (pref[i - 1] + dp[i]) % MOD

    ans = []

    for a, b in queries:
        res = pref[b]
        if a > 1:
            res -= pref[a - 1]
        res %= MOD
        ans.append(str(res))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```DP 配列には、長さごとに有効なディナーの数が格納されます。 この繰り返しは、問題の組み合わせ構造を直接反映しています。つまり、すべての夕食は赤い花か白いブロックのいずれかで終わります。 

基本的なケース`dp[0] = 1`重要です。 それがなければ、長さは次とまったく同じになります`k`1 つの白人グループに相当する寄付を受け取ることはできません。 

プレフィックス配列は、すべての DP 値がわかった後に構築されます。 クエリの回答は、一定時間の範囲合計ルックアップになります。 

条件`if a > 1`アクセスを回避します`pref[-1]`。 概念的には、いつ`a = 1`、減算する範囲を下回る長さはありません。 

プレフィックスの差が一時的に負になる可能性があるため、モジュロ演算は DP の構築中と減算後に再度適用されます。

 ## 特殊なケース

 次のことを考慮してください。```
1 5
1 4
```長さ 1 ～ 4 はすべて以下より小さい`k`。 DP 値は次のとおりです。```
dp[1] = dp[2] = dp[3] = dp[4] = 1
```白人のグループが入り込めないからです。 クエリの答えは次のようになります。```
1 + 1 + 1 + 1 = 4
```それは正しいです。 繰り返しはこれを自然に処理します。`i >= k`ブランチは決して実行されません。 

考慮する：```
1 3
3 3
```長さ 3 の場合:```
dp[3] = dp[2] + dp[0]
      = 1 + 1
      = 2
```夕食は以下の２つです。```
RRR
WWW
```基本的なケース`dp[0] = 1`これにより、すべて白の構成をカウントできるようになります。 

考慮する：```
1 2
2 3
```DP 値は次のとおりです。```
dp[2] = 2
dp[3] = 3
```正しい答えは次のとおりです。```
2 + 3 = 5
```プレフィックス合計の使用:```
pref[3] - pref[1]
```正確に 5 が得られます。`pref[2]`代わりに、長さ 2 が誤って除外され、5 ではなく 3 が生成されます。これは範囲合計クエリにおける古典的なオフバイワン トラップであり、アルゴリズムは減算することでこれを回避します。`pref[a-1]`。
