 ## 解決策
 ## 問題の理解

 タスクは、時間と分単位の開始時間と終了時間を考慮して、コンテストの正確な中間点を見つけることです。 入力により開始時間が次のように与えられます。`h1:m1`そして終了時間は`h2:m2`。 コンテストは偶数分継続し、コンテストは 1 日以内に行われることが保証されます。 出力は同じ領域の中点でなければなりません`hh:mm`形式。 

実際には、これはコンテストの合計時間を分単位で計算し、それを 2 で割って開始時間に加算する必要があることを意味します。 制約は小さく、時間は 0 ～ 23、分は 0 ～ 59 です。すべての操作は整数の単純な算術演算であり、単一の中間点のみを計算しているため、パフォーマンスは問題になりません。 時間を段階的に計算する素朴なアプローチは常に高速です。 

微妙なエッジケースには、30 分境界または真夜中近くに開始または終了するコンテストが含まれます。`23:58`に`23:59`コンテストは少なくとも 2 分間続くため許可されませんが、`23:58`に`00:00`日の境界が考慮される場合は有効です (ただし、問題は 1 日であることを保証します)。 もう 1 つの潜在的なトラップは、中間点が 59 分を超えたときに、分を時間に繰り越すことを忘れることです。 

## アプローチ

 ブルートフォース手法では、コンテストを分単位でシミュレーションし、途中でカウントし、対応する時と分を出力します。 これが機能するのは、一定範囲の短い時間 (1 日あたり最大 1440 分) が保証されているためです。 このアプローチは正しいですが、コンテストの毎分ループを実行するため、より大きな範囲や複数のクエリの場合は不必要に遅くなります。 

重要な洞察は、時間を真夜中から完全に分単位で表現できるということです。 開始時刻を変換する`h1:m1`に`start_minutes = h1 * 60 + m1`そして終了時間`h2:m2`に`end_minutes = h2 * 60 + m2`。 分単位の中間点は次のとおりです。`(start_minutes + end_minutes) // 2`。 最後に、整数の除算と剰余を使用して、それを時間と分に変換します。 これが機能するのは、すべての算術演算が線形であり、分数の合計が偶数であることが保証されているためです。そのため、整数の除算では、丸めの問題が発生せずに正しい中間点が得られます。

 ## アルゴリズムのチュートリアル

 1. 開始時刻を読み取る`h1:m1`そして終了時間`h2:m2`。 
2. 両方の時間を午前 0 時からの合計分数に変換します。 コンピューティング`start_minutes = h1 * 60 + m1`そして`end_minutes = h2 * 60 + m2`。 これにより、時間の折り返しを気にせずに線形演算が可能になります。 
3. 次のように中間点を分単位で計算します。`(start_minutes + end_minutes) // 2`。 コンテストの合計期間が均等であることが保証されているため、整数の除算が機能します。 
4. 次のように中間点を時と分に変換します。`mid_h = mid_minutes // 60`そして`mid_m = mid_minutes % 60`。 
5. 時間と分にゼロパディングを使用して、結果を 2 桁の形式で出力します。`hh:mm`要件。 

機能する理由: 合計分に変換すると、分から時間への繰り越しが自動的に処理されます。 整数除算は期間のちょうど半分を計算し、モジュロ 60 と 60 による整数除算は時と分を正確に再構成します。 問題内の保証により、丸め誤差や日のオーバーフローが防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

h1, m1 = map(int, input().strip().split(':'))
h2, m2 = map(int, input().strip().split(':'))

start_minutes = h1 * 60 + m1
end_minutes = h2 * 60 + m2

mid_minutes = (start_minutes + end_minutes) // 2

mid_h = mid_minutes // 60
mid_m = mid_minutes % 60

print(f"{mid_h:02d}:{mid_m:02d}")
```このソリューションでは、まず次を使用して入力を解析します。`split(':')`そして時と分を整数に変換します。 合計分を計算すると、すべての計算が簡素化されます。 開始分と終了分の合計を 2 で割ると、中間点が直接計算されます。 最後に、整数の除算とモジュロを使用して、2 桁の要件を維持するための書式設定を使用して、分を時と分に変換します。 この問題の保証は、ゼロ埋め込みを超える境界チェックが必要ないことを意味します。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    h1, m1 = map(int, input().strip().split(':'))
    h2, m2 = map(int, input().strip().split(':'))
    start_minutes = h1 * 60 + m1
    end_minutes = h2 * 60 + m2
    mid_minutes = (start_minutes + end_minutes) // 2
    mid_h = mid_minutes // 60
    mid_m = mid_minutes % 60
    return f"{mid_h:02d}:{mid_m:02d}"

# provided sample
assert run("10:00\n11:00\n") == "10:30", "sample 1"

# minimum duration
assert run("00:00\n00:02\n") == "00:01", "minimum duration"

# even duration with minutes overflow
assert run("23:58\n23:59\n") == "23:58", "edge minutes overflow not allowed, guaranteed >=2 minutes"

# odd/even alignment
assert run("11:10\n11:12\n") == "11:11", "2-minute contest in mid hour"

# full day split
assert run("00:00\n23:58\n") == "11:59", "halfway through full day minus two minutes"
```| テスト入力 | 期待される出力 | 検証内容 |
