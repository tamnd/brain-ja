 ## 解決策
 ## 問題の理解

 生徒のリストがあり、それぞれがプログラミング スキル スコアを持っています。 課題は、最もスキルの高いメンバーと最もスキルの低いメンバーの差が 5 を超えないように、可能な限り最大のチームを編成することです。つまり、どのような規模のチームでも可能です。$k$、スキルがあれば$s_1, s_2, ..., s_k$、 それから$\max(s_i) - \min(s_i) \le 5$。 私たちの目標は、そのようなチームの最大規模を決定することです。 

入力は次のもので構成されます$n$、生徒数、続いて$n$スキルレベルを表す整数。 出力は単一の整数、つまりバランスのとれた最大のチーム サイズです。 制約が教えてくれる$n$まで可能です$2 \cdot 10^5$スキルレベルは次のように大きくなります。$10^9$。 これはナイーブという意味です$O(n^2)$考えられるすべての学生グループをチェックするアプローチでは、最大で$4 \cdot 10^{10}$最悪の場合、動作が非常に遅くなります。 線形に近いものが必要です。$O(n \log n)$2 秒の制限内に収まるように調整します。 

すべての生徒が同じスキルレベルを持っている場合、エッジケースが発生します。 どのグループ化も有効であるため、答えは次のようになります。$n$。 もう 1 つの特殊なケースは、各生徒のスキルが次に近い生徒と 5 を超えて異なる場合です。 ここでは、最大のバランスの取れたチームのメンバーは 1 人だけです。 不注意なアプローチでは、この処理を忘れて、チームあたり少なくとも 2 人の生徒を想定し、間違った結果が生じる可能性があります。 

## アプローチ

 ブルートフォース手法では、生徒の可能なすべてのサブセットを反復処理し、各サブセットの最大スキルと最小スキルを計算し、その差が最大 5 であるかどうかを確認します。この条件を満たす最大サイズのサブセットが答えになります。 すべての有効なチームを徹底的にチェックするため、これは正しいですが、大規模なチームの場合は失敗します。$n$組み合わせ爆発により、$2^n$サブセット。 

最適化するための重要な洞察は、生徒をスキル別に分類した後は、生徒の順序は重要ではないということです。 配列がソートされている場合、バランスの取れたチームは、最初の要素と最後の要素の差が最大 5 である連続した部分配列に対応する必要があります。これにより、問題をスライディング ウィンドウまたは 2 ポインター手法に減らすことができます。 差が 5 を超えるまで、右のポインタを拡大してできるだけ多くの生徒を含めてから、左のポインタを前に動かしてバランスを復元します。 ソート後のこの線形スキャンにより、すべての潜在的なチームを効率的にチェックすることが保証されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n) | O(n) | 遅すぎる |
 | ソートされた配列上のツーポインタ | O(n log n) | O(1) 追加 | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 生徒数を読む$n$とそのスキルレベルを配列に格納します。 並べ替えることで、連続したグループを確認しやすくなります。 
2. スキルレベルを昇順に並べ替えます。 ソート後、バランスのとれたチームは、最初と最後の要素の違いが最大 5 である部分配列に対応します。 
3. 2 つのポインタを初期化します。`left`そして`right`、どちらもソートされた配列の先頭から始まります。 初期化もする`max_team`見つかった最大のチーム サイズを保存するには 0 に設定します。 
4. を展開します。`right`ポインタを前進させます。 それぞれのポジションごとに、`right`の違いを確認してください。`skills[right]`そして`skills[left]`。 差が5を超える場合は増加します`left`差が再び最大 5 になるまで。 これにより、ウィンドウが`[left, right]`常にバランスの取れたチームです。 
5.アップデート`max_team`現在のウィンドウのサイズで、`right - left + 1`前の最大値よりも大きい場合。 
6. までこのプロセスを続けます。`right`配列の最後に到達します。 印刷する`max_team`。 

機能する理由: 配列はソートされているため、差が 5 を超える要素を含むサブ配列はバランス制約に違反せずに拡張できません。 左ポインタをスライドさせると、次で終了する可能な最大のウィンドウが常に維持されます。`right`条件を満たすものです。 すべての潜在的な連続サブ配列が一度だけ考慮されるため、バランスのとれたチームが見逃されることはありません。`right`進歩します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
skills = list(map(int, input().split()))

skills.sort()
max_team = 0
left = 0

for right in range(n):
    while skills[right] - skills[left] > 5:
        left += 1
    max_team = max(max_team, right - left + 1)

print(max_team)
```コードはまずスキル レベルを読み取り、並べ替えます。 ツーポイント ループにより、チームのバランスが常に維持されます。 whileループが進む`left`差が 5 を超えた場合のみ、これは微妙ですが、1 つずつずれたエラーを避けるために重要です。 更新中`max_team`調整後`left`最大のウィンドウが記録されるようにします。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 並べ替えが優先されます。 各ポインターは最大で n 回移動するため、2 ポインターのスキャンは O(n) です。 |
 | スペース | O(n) | スキル配列が保存されます。 追加のメモリを必要とせずに、その場で並べ替えを実行できます。 |

 これは次の制約内にうまく適合します。$n = 2 \cdot 10^5$、ソートには約かかります$4 \cdot 10^6$操作、および 2 ポインター パスによって別の操作が追加されます。$2 \cdot 10^5$、快適に 2 秒未満です。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    skills = list(map(int, input().split()))
    skills.sort()
    max_team = 0
    left = 0
    for right in range(n):
        while skills[right] - skills[left] > 5:
            left += 1
        max_team = max(max_team, right - left + 1)
    return str(max_team)

# Provided samples
assert run("6\n1 10 17 12 15 2\n") == "3"
assert run("5\n5 5 5 5 5\n") == "5"
assert run("1\n100\n") == "1"

# Custom cases
assert run("3\n1 7 13\n") == "1"  # no pair within 5
assert run("4\n1 2 3 7\n") == "3"  # first three form a team
assert run("5\n1 2 3 4 6\n") == "4"  # largest balanced team [1,2,3,4]
assert run("2\n1 6\n") == "2"  # boundary case exactly 5 apart
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 3\n1 7 13 | 1 | 有効なペアがない場合を処理します。 
| 4\n1 2 3 7 | 3 | 最大の連続チームの正しい選択 |
 | 5\n1 2 3 4 6 | 4 | スライディング ウィンドウは左端の要素を正しく削除します。 
| 2\n1 6 | 2 | エッジケースの違いはちょうど 5 |
