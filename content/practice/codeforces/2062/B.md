 ## 解決策
 ## 問題の理解

 一連のクロックのいずれかのクロックがゼロに達することを無期限に回避できるかどうかを判断することが求められています。 各時計には初期時刻があります`a_i`。 1 秒ごとに、すべてのクロックが 1 ずつ減少します。 隣接する時計に移動すると、すぐに時間をリセットして元の時刻に戻すことができます。`a_i`。 問題は、リセットする前にクロックがゼロに達すると、即座に負けになるということです。 どのクロックからでも開始でき、自由に前後に移動できます。 入力にはいくつかのテスト ケースがあり、それぞれにクロック値のリストが含まれており、出力は永続戦略が存在する場合は「YES」、そうでない場合は「NO」になります。 

この制約により、すべてのテスト ケースで最大 500,000 クロックが許可され、各クロック値は 10^9 まで大きくなる可能性があります。 これにより、値が 10^9 の 1 つのクロックでも 10 億回の操作が必要となるため、毎秒のシミュレーションは直ちに除外されます。 したがって、解決策では、クロックがゼロに達することを無期限に防ぐ一連の動きが存在するかどうかを数学的に推論する必要があります。 

時計の位置に比べて値が小さい場合、重要な微妙な点が生じます。 たとえば、`[2, 2]`、2 番目のクロックをリセットするまでに、1 番目のクロックはすでにゼロに達しているため、無限に循環することはできません。 クロック数に比べて小さな値を持つ小さなシーケンスは、素朴なアプローチを打ち破るエッジ ケースです。 

## アプローチ

 ブルートフォースアプローチでは、すべてのクロックをデクリメントし、隣接するクロックに移動し、可能であればリセットするという、毎秒のシミュレーションを試みます。 これは原理的には正しいですが、実行不可能です。 のために`n = 10^5`そして`a_i = 10^9`、シミュレーションで実行される操作が多すぎます。 

重要な観察は、貪欲なアプローチを使用すると、問題を単純なチェックに帰着させることができるということです。 左から右へ (その後は右から左へ) 歩くことを考えると、リセットできるまで時計が存続しなければならない最小限の残り時間を維持できます。 具体的には、左から右へのパスの場合、最初のクロックから最後のクロックに移動し、常に現在のクロックでリセットされることを想像します。 各クロックで、私たちが運ぶ必要がある時間の最大の「負債」を計算します。前の負債に、実行したステップの 1 を加えた値が、クロックの初期値を超えてはなりません。 そうなるとその方向は無理です。 次に、同じことを右から左に実行し、両方のパスが成功する開始クロックが存在するかどうかを確認します。 

これにより、問題は左から右、右から左への線形スキャンに変換され、テスト ケースごとに O(n) になります。 洞察としては、毎秒シミュレーションする必要はないということです。 必要なのは、移動とリセットのタイミングによって課される制約を確認することだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n * max(a_i)) | O(n) | 遅すぎる |
 | 貪欲なリニアパス | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つの配列を初期化する`left_debt`そして`right_debt`サイズの`n`。`left_debt[i]`左から時計までの生存に必要な最小時間を表します`i`。 同様に、`right_debt[i]`最小時間を右から追跡します。 
2. 左から右へのパスを実行します。 セット`left_debt[0] = 0`いつでも始められるからです。 時計ごとに`i`1 から n-1 まで計算します`left_debt[i] = max(left_debt[i-1] + 1, 0)`。 いつでも`left_debt[i] > a[i]`, この時計を左から負けずに到達するのは不可能です。 
3. 同様に右から左へのパスを実行します。 セット`right_debt[n-1] = 0`そして最初のクロックに向かって伝播します。 各ステップで次のことを確認してください`right_debt[i] <= a[i]`。 
4. 時計が存在するかどうかを確認します`i`どちらも`left_debt[i] <= a[i]`そして`right_debt[i] <= a[i]`。 そのような時計が存在する場合、そこから開始して無限に前後に移動できます。 何も存在しない場合は不可能です。 

重要な不変条件は次のとおりです`debt[i]`時計に残っておかなければならない最小限の時間を表します`i`その方向から移動して生き残るために。 もし`debt[i] > a[i]`、時計は私たちの動きを維持できず、計画をリセットします。 これにより、実行可能なクロックが存在する場合、線形パスに従うことで無限の戦略が確保されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_survive(a):
    n = len(a)
    left_debt = [0] * n
    right_debt = [0] * n
    
    # left to right pass
    for i in range(1, n):
        left_debt[i] = max(left_debt[i-1] + 1, 0)
        if left_debt[i] > a[i]:
            left_debt[i] = float('inf')
    
    # right to left pass
    for i in range(n-2, -1, -1):
        right_debt[i] = max(right_debt[i+1] + 1, 0)
        if right_debt[i] > a[i]:
            right_debt[i] = float('inf')
    
    # check for feasible starting point
    for i in range(n):
        if left_debt[i] <= a[i] and right_debt[i] <= a[i]:
            return "YES"
    return "NO"

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    print(can_survive(a))
```このソリューションは、両側から 1 つずつ、2 つの線形パスを維持し、各クロックで必要な最小限の残り時間を計算します。 実行不可能なクロックを無限大に設定すると、候補の開始点から確実に除外されます。 最終スキャンでは、両方の制約が適用され、安全な開始位置を表すクロックが特定されます。 

## 実用的な例

 入力`[4, 10, 5]`:

 | 時計 | a[i] | 残った借金 | 正しい借金 |
 | --- | --- | --- | --- |
 | 0 | 4 | 0 | 2 |
 | 1 | 10 | 1 | 1 |
 | 2 | 5 | 2 | 0 |

 満足できる時計がない`left_debt[i] <= a[i]`そして`right_debt[i] <= a[i]`すべての位置で同時に。 したがって、出力は「NO」になります。 これは、小型の時計が隣接する中型の時計が無期限の存続を維持できないことを示しています。 

入力`[5, 3, 5]`:

 | 時計 | a[i] | 残った借金 | 正しい借金 |
 | --- | --- | --- | --- |
 | 0 | 5 | 0 | 2 |
 | 1 | 3 | 1 | 1 |
 | 2 | 5 | 2 | 0 |

 クロック 1 は両方の条件を満たします。`1 <= 3`そして`1 <= 3`。 この時計を起点として、無限に左右に移動し、進むにつれて時計をリセットできます。
