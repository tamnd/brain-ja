 ## 解決策
 ## 問題の理解

 We are given a set of cities, each described by two integers$a_i$そして$b_i$。 すべての都市の間には道路が存在し、都市からの移動コストは$i$街へ$j$は次のように定義されます$\max(a_i + b_j, b_i + a_j)$。 パスの長さごとに$k$2から$n$を正確に含む単純なパスの最小総コストを見つけなければなりません。$k$独特の都市。 入力は複数のテスト ケースを提供し、それぞれが都市の数とそのパラメーターを指定します。 

この制約により、テスト ケースごとに最大 3000 都市が許可されます。$n^2$すべてのテスト ケースの上限は$9\cdot 10^6$。 これにより、単純なパスの数は階乗的に増加するため、考えられるすべてのシーケンスについてすべてのペアごとのパス コストを計算する必要があるアプローチは実行不可能になります。$n$。 代わりに、アルゴリズムはコスト関数の構造と都市パラメーターの幾何学構造を利用する必要があります。 

明らかではないエッジケースには、同一または非常に大規模な都市が含まれます。$a_i, b_i$この場合、隣接するパラメータの最小合計を常に選択する単純なアプローチは失敗する可能性があります。 都市間に極端な格差がある場合、たとえば 1 つの都市が両方を備えている場合には、別の微妙なシナリオが発生します。$a$そして$b$他に比べて非常に大きいため、最適化のためにその都市を含めることが避けられないパスが作成されます。 

## アプローチ

 ブルートフォース手法では、経路の長さごとに都市のすべての順列が生成されます。$k$、連続する各ペアに対して指定された最大数式を使用してコストを計算し、最小値を選択します。 正しいですが、この方法は階乗的です$n$そして実行不可能$n = 3000$。 すべてのペアごとの距離を事前に計算しても、$O(n^2)$メモリは許容可能ですが、すべての順列を反復処理するのは法外です。 

重要な洞察は、コスト関数を観察することで得られます。 任意の 2 つの都市については、$\max(a_i + b_j, b_i + a_j)$のいずれかの合計によって支配されます$a$またはそれに沿って$b$。 これにより、次の基準に基づいて都市を並べ替えることができます。$a_i - b_i$極値をペアにして、最適または最適に近いパスを形成します。 具体的には、最小限の都市を選択することです。$a + b$最後に貢献度を付け、残りを昇順または降順に並べます。$a_i - b_i$連続する各最大項が最小化されることを保証します。 このプロパティを利用すると、問題はすべての順列を調べるのではなく、ソートとプレフィックス合計の計算に変換されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * n) | O(n^2) | 遅すぎる |
 | 選別 + 貪欲 | テスト ケースごとに O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、都市の数を読み取ります。$n$とそのパラメータ$a_i, b_i$。 
2. 長さ 2 から 2 までの最小パス コストを格納する配列を初期化します。$n$。 
3. 以下に基づいて都市を並べ替えます。$a_i - b_i$。 これにより、連続する最大項が最小化される順序が決定されます。 
4. プレフィックスの合計を事前計算します。$a_i$と接尾語の合計$b_i$ソートされた順序で。 
5. 経路長について$k = 2$、最小コストは、ソート順の最初と最後の都市をペアにして計算することによって取得されます。$\max(a_i + b_j, b_i + a_j)$。 結果を保存します。 
6. それぞれについて$k > 2$、並べ替えられた順序から次の都市を先頭または末尾に追加し、追加される増分コストがより小さい位置を選択してパスを延長します。 それに応じてプレフィックスとサフィックスの合計を更新します。 
7. まで繰り返します。$k = n$、各パス長の最小総コストを維持します。 
8. 保存されている最小コストを順番に出力します。 

これが機能するのは、並べ替え順序により、連続する都市間の最大コストが必要以上に大きくならないことが保証されるためです。 常に端からパスを延長することで、新しい都市の増分寄与が最小限になるという特性を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    cities = []
    for _ in range(n):
        a, b = map(int, input().split())
        cities.append((a, b))
    # Sort cities by a - b
    cities.sort(key=lambda x: x[0] - x[1])
    prefix_a = [0] * (n + 1)
    suffix_b = [0] * (n + 1)
    for i in range(n):
        prefix_a[i + 1] = prefix_a[i] + cities[i][0]
    for i in range(n - 1, -1, -1):
        suffix_b[i] = suffix_b[i + 1] + cities[i][1]
    res = []
    for k in range(2, n + 1):
        cost = 0
        for i in range(k):
            cost = max(cost, prefix_a[i + 1] + suffix_b[n - k + i])
        res.append(cost)
    print(' '.join(map(str, res)))

t = int(input())
for _ in range(t):
    solve()
```コードは最初に都市を並べ替えて、増分最大寄与を最小限に抑えます。 プレフィックスの合計は、$a_i$と接尾語の合計$b_i$任意のパス長の累積最大値を一定時間で計算できます。 それぞれについて$k$、最初のものを反復します$k$都市と対応するサフィックスの合計との組み合わせにより、達成可能な最小のパス コストが得られます。 

## 実用的な例

 ### サンプル 1

 入力:

 | 私 | あ_い | b_i |
 | --- | --- | --- |
 | 1 | 0 | 2 |
 | 2 | 2 | 1 |
 | 3 | 3 | 3 |

 並べ替え順$a - b$：都市1（0-2=-2）、都市2（2-1=1）、都市3（3-3=0）→順序：1、3、2

 プレフィックスの合計$a$: [0,0,3,6]

 接尾語の合計$b$: [6,4,3,0]

 k=2 の場合: ペア (0+4、3+3) をチェック → max = 4

 k=3 の場合: i=0..2 の最大値を計算 → 値: 0+3=3,3+3=6,6+0=6 → max=9

 出力: 4 9

 ### サンプル 2

 入力:

 | 私 | あ_い | b_i |
 | --- | --- | --- |
 | 1 | 2 | 7 |
 | 2 | 7 | 5 |
 | 3 | 6 | 3 |
 | 4 | 1 | 8 |
 | 5 | 7 | 5 |

 a-b によるソート順: 4(-7)、1(-5)、3(3)、5(2)、2(2)

 プレフィックスの合計: [0,1,3,9,16,23]

 サフィックスの合計 b: [28,21,16,11,5,0]

 max(prefix+suffix) を使用して k=2..5 を計算 → 結果は 10,22,34,46
