 ## 解決策
 ## 問題の理解

 各ノードが許容値の範囲を持つルート付きツリーが与えられます。`[l_i, r_i]`。 最初は、各ノードにその範囲内の任意の値を割り当てることができます。 目標は、ツリーのバランスを整えること、つまりすべてのノードが同じ最終値を持つようにすることです。 許可される唯一の操作はルートを選択することです`u`とサブツリーのルート`v`そして、サブツリー内のすべての値を増やします。`v`1つずつ。 操作の数を気にせずに、ツリーを等しくできる最小の最終値を決定するように求められます。 

入力は複数のテスト ケースを提供します。 各テスト ケースには最大 200,000 ノードを含めることができますが、合計`n`すべてのテスト ケースの制限は 200,000 です。 各ノードの初期値は 10^9 まで大きくすることができます。 これは、操作を明示的にシミュレートできないことを意味します。O(n^2) や操作ごとのアプローチは実行不可能です。 ソリューションは、テスト ケースごとにおよそ O(n) または O(n log n) で動作する必要があります。 

微妙な点は、操作の定義にあります。 ノードの価値は増加することしかありません。 したがって、どのアルゴリズムでも、ノードの値の範囲が異なる可能性を処理する必要があります。`[l_i, r_i]`サブツリーの値と一致させるために増加が必要になる場合があります。 不注意な実装では、上方に伝播することなく、各範囲に可能な最小値を個別に割り当てようとするだけで、間違った答えが得られる可能性があります。 たとえば、範囲を持つ 2 つのノードを持つツリー`[0,0]`そして`[1,1]`最初のノードでは 1 に増やす必要があります。単に下限を選択するだけです。`[0,0]`失敗するだろう。 

エッジ ケースには、単一ノード ツリー、ノードが含まれます。`l_i == r_i`、およびすべてのノードが重複しない範囲を持つツリー - このような状況では、増分の伝播を慎重に計算する必要があります。 

## アプローチ

 ブルートフォース手法では、ノード内の各ノードに初期値を割り当てようとします。`[l_i, r_i]`範囲を設定し、すべてのノードが等しくなるまで操作をシミュレートします。 これは理論的には正しいですが、完全に実行不可能です。各操作をシミュレートするには、増分ごとに O(n) ステップが必要になる可能性があり、最悪の場合、複雑さは O(n^2) 以上になります。 

効率的な解決策を可能にする重要な観察は、操作によって常にサブツリー値が増加することを認識することです。 したがって、ツリーに沿った動的プログラミング手法を使用して最適な解決策を見つけることができます。 各ノードで、サブツリーとそのサブツリーの最終値の可能な範囲のバランスを取るために必要な最小限の操作を追跡します。 リーフノードの場合、範囲は単純に次のようになります。`[l_i, r_i]`。 内部ノードの場合、最終値は、操作用に調整した後の子の範囲の最大下限以上である必要があります。 これにより、単一の DFS で事後探索がツリーの最終的な最小値を計算できるようになります。 

最終値が子からの必要な「ブースト」の合計であるという観察により、テスト ケースごとに O(n) の解が得られます。 ブルート フォース アプローチは増分を効率的に伝播できないため失敗しますが、DP アプローチはツリー構造を利用してサブツリーを最適に結合します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n^2) | O(n) | 遅すぎる |
 | DP オン ツリー (DFS) | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析し、ツリーの隣接リストを作成します。 タプルのリストを初期化する`[(l_i, r_i)]`各ノードの範囲を表します。 
2. 特定のノードと親に対して、次の 2 つの値を計算する DFS 関数を定義します。`min_val`- このサブツリーの最終的な最小値、および`needed_ops`- すべての子がノードの最終値に到達できるようにするために必要な合計操作。 
3. リーフノードの場合は、return`(l_i, 0)`ノード自体の範囲を超えて追加の増分が必要ないためです。 
4. 内部ノードの場合、再帰的に計算します。`min_val`そして`needed_ops`それぞれの子供たちにとって。 
5. すべての子を訪問した後、子をノードのレベルまで上げるのに必要な合計操作を計算します。 子の達成可能な最大値がノードの下限を下回る場合、その差分だけ演算を増分します。 
6. ノードの最終値を設定します`min_val`下限の最大値と最高値として`min_val`子どもたちから必要とされている。 蓄積する`needed_ops`すべての子から、現在のノードと一致するために必要な調整を追加します。 
7. 戻る`(min_val, needed_ops)`根のために。 最初の要素は、ツリーの最終的な最小値です。 

**機能する理由:** 各ノードは、範囲を尊重しながらサブツリーのバランスをとるために必要な最小値を計算します。 葉から上に伝播することで、必要な増分を過小評価することがなくなります。 操作によって常にサブツリー値が増加する可能性があるため、子の中で最大の下限を選択することで実現可能性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        lr = [tuple(map(int, input().split())) for _ in range(n)]
        adj = [[] for _ in range(n)]
        for _ in range(n-1):
            u, v = map(int, input().split())
            adj[u-1].append(v-1)
            adj[v-1].append(u-1)
        
        def dfs(u, parent):
            total_ops = 0
            lower, upper = lr[u]
            for v in adj[u]:
                if v == parent:
                    continue
                child_ops, child_val = dfs(v, u)
                total_ops += child_ops
                # if child_val < lower, we need to increment it to reach lower
                if child_val < lower:
                    total_ops += lower - child_val
                    child_val = lower
                upper = max(upper, child_val)
            return total_ops, upper
        
        result, _ = dfs(0, -1)
        print(result)

if __name__ == "__main__":
    solve()
```DFS は、サブツリーのバランスを取るために必要な合計操作と最小の最終値の 2 つの値を返します。 各ノードで、子の値が少なくとも現在のノードの下限に達していることを確認し、演算を累積します。 再帰により、これらの制約が上方に効率的に伝播されます。
