 ## 解決策
 ## 問題の理解

 長さの 2 つの順列が与えられています$n$、$p$そして$q$そして私たちの目標は変革することです$p$の中へ$q$一連のスワップ操作を使用します。 各操作で 2 つの要素が交換されます。$p$コストは、位置間の距離と値間の距離の最小値に等しくなります。 総コストを最小限に抑え、これを達成する一連のスワップを作成する必要があります。 

入力制約は次のことを示しています。$n$最大でも 100 にすることができ、次の合計は$n^3$すべてのテストケースで次を超えない$10^6$。 これは、おおよそ次のアルゴリズムを使用できることを意味します。$O(n^3)$テストケースごとに異なりますが、それよりもさらに悪い場合は制限時間を超えます。 テストケースの数$t$まで可能です$10^4$したがって、テストケースごとの操作を控えめに保つように注意する必要があります。 

単純なアプローチでは、コストの最適化を考慮せずに、要素が適切でない場合は常に要素を貪欲に交換しようとする可能性があります。 これは小さなサイクルでは失敗します。 たとえば、次の場合$p=[1,3,2]$そして$q=[2,1,3]$、不注意に左から右に交換すると、最初に 3 が正しい場所に移動し、総コストが増加する可能性がありますが、最適なシーケンスでは 1 と 2 が直接交換されます。 

もう 1 つの明白ではないエッジ ケースは、最小スワップ距離が値ではなく位置に由来する場合に発生します。 例えば、$p=[2,1,4,3]$そして$q=[4,2,3,1]$は、最適なスワップが常に隣接する位置であるとは限らないことと、コスト関数を示しています。$\min(|i-j|, |p_i-p_j|)$はスワップの選択を導く鍵となります。 「値は遠く離れているが、位置は近い」要素を交換すると、その逆よりもコストが小さくなる可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各ステップで考えられるすべてのスワップを検討し、コストが最小限のものを選択して更新しようとします。$p$一致するまで$q$。 これは原理的には正しいです。なぜなら、一連のスワップは最終的にソートできるからです。$p$合わせる$q$、しかし、それは計算上不可能です。 と$O(n^2)$ステップごとの潜在的なスワップと$O(n)$ステップを踏むと、合計操作量が許容範囲を超えて爆発的に増加します。$n=100$。 

重要な洞察は、マップを構成する順列のサイクルを解決するものとして問題を捉えることです。$p$に$q$。 あらゆる順列は素のサイクルに分解できます。 各サイクル内で、要素はターゲット位置に到達するために回転する必要があります。 サイクル内で 2 つの要素を交換すると、問題はより小さなサイクルに縮小され、サイクル内の最小インデックスと最大インデックスを含むスワップを常に選択すると、次の最小化が行われます。$\min(|i-j|, |p_i-p_j|)$なぜなら、値や位置の大きな違いはコストを最大化し、小さな違いはコストを最小化するからです。 

これにより、問題はサイクルに沿った構造化されたスワップのシーケンスに変換されます。 各サイクルを位置ごとに並べ替えることで、各スワップが安くなり、順列が効率的にターゲットに向かって移動することが保証されます。 なぜなら$n\le 100$、サイクルを繰り返し、スワップを順番に実行することは、計算上許容されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^4) | O(n) | 遅すぎる |
 | サイクルベースの最適化 | O(n^3) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. の値からマッピングを構築します。$q$目標のインデックスに到達します。 これにより、各要素がどこにあるかをすぐに知ることができます。$p$行くべきだ。 
2. すべての要素を未訪問としてマークします。 を繰り返していきます$p$そして、現在位置をターゲット位置にマッピングすることによって定義される順列内のサイクルを見つけます。 
3. 未訪問の要素ごとに、マッピングに従ってそのサイクルを構築します。 サイクルには、回転する必要がある閉ループに関係するすべてのインデックスが含まれます。 
4. 長さが 1 より大きい各サイクル内で、インデックスを並べ替えます。 これにより、サイクル内では遠く離れているが、値または位置が可能な限り近いインデックス間でスワップが実行されるようになり、$\min(|i-j|,|p_i-p_j|)$料金。 
5. サイクルについて$[i_1,i_2,...,i_k]$、最初の要素と残りの各要素の間で順番に交換を実行します。 交換するたびに、最初の要素が最終位置に近づき、サイクルは徐々に解消されます。 各スワップを記録して出力シーケンスを生成します。 
6. すべてのサイクルが処理されるまで繰り返します。 最後に、$p$マッチ$q$。 

機能する理由: すべてのサイクルは独立しているため、1 つのサイクルを解決しても他のサイクルに干渉することはありません。 サイクルの最初の要素を他の要素と交換すると、不必要に位置を再訪することなく、各要素が確実にターゲットに到達します。 インデックスを並べ替えることにより、各サイクル内のスワップ コストが最小限に抑えられることが保証されます。 不変条件は、サイクルの処理後、そのすべての要素が正しい位置にあることです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        p = list(map(int, input().split()))
        q = list(map(int, input().split()))
        pos = [0]*(n+1)
        for idx, val in enumerate(q):
            pos[val] = idx
        visited = [False]*n
        ops = []
        for i in range(n):
            if visited[i] or p[i] == q[i]:
                continue
            cycle = []
            x = i
            while not visited[x]:
                visited[x] = True
                cycle.append(x)
                x = pos[p[x]]
            if len(cycle) <= 1:
                continue
            cycle.sort()
            for j in range(len(cycle)-1, 0, -1):
                ops.append((cycle[0]+1, cycle[j]+1))
                p[cycle[0]], p[cycle[j]] = p[cycle[j]], p[cycle[0]]
        print(len(ops))
        for a,b in ops:
            print(a,b)

if __name__ == "__main__":
    solve()
```最初のセクションでは、サイクル検出を容易にするためにターゲット値を位置にマッピングします。 メインループは繰り返します$p$、間違って配置された要素のサイクルを特定します。 スワップを実行する前にサイクルインデックスをソートすると、以下に基づいてコストが最小限に抑えられます。$\min(|i-j|,|p_i-p_j|)$関数。 スワップ ループはサイクルを効率的に回転させ、正確さを保証します。 問題で必要となるため、出力に 1 から始まるインデックスを使用することが重要です。
