 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、`n`ノードをルートとするノード`1`、各ノードには関連する整数の重みがあります。 チルノと大妖精はこの木の上で連続ゲームをします。 自分の番では、プレイヤーは対戦相手が選択した最後のノードよりも厳密に大きな重みを持つノードを選択し、そのノードをルートとするサブツリー全体を削除します。 チルノが最初に開始し、目標は、両方のプレイヤーが最適にプレイした場合に最終的にゲームに勝つために、最初の動きで選択できるすべてのノードを見つけることです。 勝ち手がない場合は出力する必要があります`0`。 

入力は複数のテスト ケースで構成され、それぞれが重みを持つツリーを定義します。 制約は強力です。`n`到達できる`4 * 10^5`すべてのテスト ケースの合計。 これにより、すべてのノードからの 1 つの DFS でさえ簡単に超過する可能性があるため、考えられるすべてのゲーム シーケンスを単純にシミュレートするソリューションは除外されます。`10^8`6 秒の制限には遅すぎます。 重み自体の範囲は次のとおりです。`1`そして`n`これにより、絶対的な大きさではなく相対的な順序について推論することができます。 

明らかではないエッジ ケースには、すべての重みが等しいツリー、ルートの重みが最大であるツリー、または最初のプレイヤーが有効な手を持っていない (すべてのノードの重みが必要な値よりも小さい) などが含まれます。 たとえば、すべての重みが 1 つのパスに沿って増加している場合、ルートを選択すると、2 番目のプレーヤーがすぐに次に大きいノードを選択できるようになり、勝ちが逆転する可能性があります。 ツリー パスに沿った重みの順序の相互作用を無視する単純なアプローチは失敗します。 

## アプローチ

 ブルート フォース アプローチでは、各ノードから開始して考えられるすべてのゲーム シーケンスをシミュレートしようとします。 初期ノードごとに、そのサブツリーを削除し、2 番目のプレーヤーのすべての選択肢を再帰的に探索します。 これは原理的には正しいですが、シーケンスの数はノードの数に応じて指数関数的に増加するため、現実的ではありません。 と`n`まで`10^5`、このアプローチには以上のものを含めることができます。`2^n`という状態ですが、これは計算上不可能です。 

重要な洞察は、ツリーをゲーム グラフとして扱い、それを古典的な公平なゲームの変形として認識することから得られます。 動きをシミュレートする代わりに、サブツリーと重みの相対的な順序に基づいて各ノードに「勝利値」を割り当てることができます。 具体的には、ゲームの結果は主に **ツリー内で厳密に増加するパスの高さ** に依存することがわかります。 ノードを重みでソートして DFS を実行すると、対戦相手の負けノードへの移動を許可した場合にノードが勝ちであるというルールを使用して、勝ち/負けの状態をリーフからルートまで伝播できます。 これにより、問題はテスト ケースごとに 1 つの DFS に減らされ、さらに重みによってソートされたノードのトポロジカル スイープが発生します。これは制約の下で実現可能です。 

最適なアプローチは、ツリー構造をキャプチャするための DFS と、勝ちポジションを効率的に計算するためのノードの順序付けに関する動的プログラミングを組み合わせることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を解析し、ツリーの隣接リスト表現を構築します。 
2. すべてのノードを重みに従って昇順に並べ替えます。 これにより、ノードを検討するときに、より小さい重みのノードがすべてすでに分析されていることが保証されます。 
3. 配列を初期化する`win[i]`サブツリーがノードをルートとするかどうかを追跡する`i`相手のターンであれば勝ちポジションです。 最初は、すべてのリーフがポジションを失っています。 
4. 重みの昇順でノードを移動します。 各ノードについて、ツリー内の隣接ノード (DFS 順序の子) を検査します。 重みが小さく、負ける位置につながる隣接ノードが存在する場合、現在のノードを勝ちとしてマークします。 これにより、最適なプレイ ルールが実装されます。つまり、プレーヤーは、対戦相手を負けのサブツリーに追い込むことができれば勝つことができます。 
5. すべてのノードを処理した後、最初のプレイヤーの勝ち位置であるノードがチルノの最初の動きの候補になります。 これらのノードを収集します。 
6. 勝ったノードをソートして出力する、または`0`勝利ノードが存在しない場合。 

機能する理由: 不変条件は、ノードを重み順に処理し、勝ち/負けの状態をリーフから上に伝播することにより、各ノードがそのノードで移動しているプレイヤーが最適なプレイに対して勝利を強制できるかどうかを正確に反映することです。 ツリー上の公平なゲームの特性により、相手を負け状態に追い込むことができるノードは、それ自体が勝者になります。 これにより、最初の移動選択の正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import defaultdict, deque

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        w = list(map(int, input().split()))
        adj = [[] for _ in range(n)]
        for _ in range(n-1):
            u, v = map(int, input().split())
            adj[u-1].append(v-1)
            adj[v-1].append(u-1)
        
        # Track parent and children using BFS
        parent = [-1]*n
        order = []
        dq = deque([0])
        while dq:
            node = dq.popleft()
            order.append(node)
            for nei in adj[node]:
                if nei != parent[node]:
                    parent[nei] = node
                    dq.append(nei)

        # Nodes sorted by weight
        nodes_by_weight = sorted(range(n), key=lambda x: w[x])
        win = [False]*n

        # Traverse from smallest weight to largest
        for u in nodes_by_weight:
            for v in adj[u]:
                if parent[u] == v:
                    continue
                if w[v] < w[u] and not win[v]:
                    win[u] = True
                    break

        result = [i+1 for i in range(n) if win[i]]
        if result:
            print(len(result), *sorted(result))
        else:
            print(0)

if __name__ == "__main__":
    solve()
```BFS により、親子関係を一貫して定義できるようになります。 ノードを重みでソートすると、ノードを検査するときに、重みの低いすべての近傍が処理されることが保証され、正しい動的プログラミングの伝播が可能になります。 シンプルな使い方`win`array は再帰スタックの制限を回避し、アルゴリズムの効率を維持します。
