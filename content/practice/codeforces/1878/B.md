 ## 解決策
 ## 問題の理解

 厳密に増加する長さの配列を構築するように求められます$n$、各要素は正の整数であり、$n \ge 3$。 配列は、インデックスごとに、連続する要素のトリプルをすべてリンクする条件を満たしている必要があります。$i$、値$3 \cdot a_{i+2}$和で割り切れないはずです$a_i + a_{i+1}$。 

したがって、独立した要素について考える代わりに、配列はスライディング ウィンドウ制約のように動作します。 隣接する各ペア$(a_i, a_{i+1})$次の要素と相互作用します$a_{i+2}$分割性を通じて。 

出力には一意性や最適化は必要なく、存在するだけです。 有効な厳密に増加する構造であればどれでも受け入れられます。 

制約は大きく、合計$n$テストケース全体で最大$2 \cdot 10^5$。 これにより、以前のすべての要素に対してネストされたループを使用して各候補要素を再計算またはチェックするアプローチは即座に除外されます。 アン$O(n^2)$テストケースごとの構築や検証が遅すぎる可能性があります。 

微妙なエッジ ケースは、定数 3 を含む割り算条件から発生します。これは、分母の構造が 3 の要素と一致しないようにするか、慎重に選択された成長により比率が決して整数にならないようにすることで、割り切れないことを制御できることを示唆しています。 

素朴な試みは、連続する整数または等差数列を選択することです。 例えば、$a_i = i$すぐに失敗する:$i=1$、私たちは得ます$a_1+a_2=3$、 その後$3a_3=9$、これは 3 で割り切れるため、条件に違反します。 

したがって、構造は、すべてのトリプルにわたって偶発的に割り算が整列することを回避する必要があります。 

## アプローチ

 強引なアイデアは、配列を要素ごとに構築し、新しい要素ごとに配列を構築することです。$a_{i+2}$、制約が成立するまで整数を増やしてみてください。 各候補値について、次のことを確認します。$(a_i + a_{i+1}) \mid 3a_{i+2}$。 最悪の場合、有効な値を見つける前に各位置で多くの値をスキャンする必要があり、各チェックは一定時間行われます。 ただし、制約は多くのテスト ケースで敵対的であるため、特に制約が繰り返されると有効な数値がまばらな場合、全体的に二次的な動作に低下する可能性があります。 

重要な点は、実際には各トリプルを個別に注意深く調整する必要はないということです。 必要なのは、可分性条件が常に破られることを保証するグローバル構造だけです。 スライド制約全体で非可分性を強制する標準的な方法は、次の構造を確保することです。$a_i + a_{i+1}$制御された倍数を決してきれいに分割しない$a_{i+2}$。 

シンプルで確実なトリックは、各項が十分な速度で成長するシーケンスを構築することです。$a_{i+2}$は、割り算の意味で前の 2 つの項の合計と「互換性」がありません。 1 つのきれいな構成は、各項が前のすべての項の合計よりも大きくなる急速に増加するシーケンスを使用することですが、さらに単純なこともできます。つまり、係数 3 との位置合わせを回避する固定乗数を持つ幾何級数数列を使用します。 

よく知られている構造は次のとおりです。$$a_i = 2^i \text{ (or a shifted version to keep values within bounds)}$$それから：$$a_i + a_{i+1} = 2^i + 2^{i+1} = 3 \cdot 2^i$$そして：$$3 \cdot a_{i+2} = 3 \cdot 2^{i+2}$$今：$$\frac{3 \cdot a_{i+2}}{a_i + a_{i+1}} = \frac{3 \cdot 2^{i+2}}{3 \cdot 2^i} = 4$$これは常に整数であるため、実際には条件に違反します。 これは、単純な指数構造が制約の構造と完全に一致しすぎるために失敗することを示しています。 

代わりに、正確なキャンセルを解除したいと考えています。 標準的な修正は、非対称性を導入することです。つまり、純粋な 2 のべき乗の代わりに、一貫した因数分解を妨げる 2 つの交互のパターンを混合します。 単純に受け入れられている構造の 1 つは次のとおりです。$$a_i = i \cdot 2^i$$現在、合計はきれいに因数分解されず、比率は$\frac{3a_{i+2}}{a_i+a_{i+1}}$構造化された方法で整数に単純化されなくなりました。 さらに重要なことは、成長により、一部のインデックスで偶発的に割り切れたとしても、それがすべてのインデックスで体系的に持続することはできないことが保証されることです。$i$。 

公式ソリューションで使用されるより直接的な建設的なアイデアはさらに単純です。次のように、大きく離れてシフトされた 2 つの等差数列を交互に繰り返すシーケンスを構築します。$$a_i = i \cdot 1000$$次に、合計が割り算されないようにパリティまたはオフセットを調整します。$3a_{i+2}$。 ただし、最も明確な決定論的な構築は次のものを使用することです。$$a_i = i \cdot (i+1)$$これにより、連続する合計全体にわたる gcd 構造の大きな変動が保証され、次のように割り切れます。$a_i + a_{i+1}$構造化された方法では可能性は非常に低く、可能な約数を制限することによって制約の下で安全であることが証明できます。 

重要な洞察は、インデックスごとのきめの細かい整数理論の制約を解決しているわけではないということです。 私たちは、線形に関連する分子による系統的な分割を避けるために、すべての局所分母が十分に変化するシーケンスを構築しています。

 ## アルゴリズムのチュートリアル

 構築中にバックトラックしたり可分性をチェックしたりすることなく、厳密に増加する数列を直接構築します。 

1. 厳密な増加を保証する配列要素の単純な式を選択します。たとえば、$a_i = i \cdot (i+1)$。 これにより、$a_{i+1} > a_i$みんなのために$i$なぜなら、両方の要素が増加し、乗算が線形成長を支配するからです。 
2. 以下から値を生成します。$i = 1$に$n$、それぞれを計算します$a_i$公式を使って。 これにより、以前の有効性チェックへの依存が回避されます。 
3. テスト ケースごとに構築された配列を出力します。 

これで十分である理由は、この構造がすでに大きさと因子構造の両方における強い変動をエンコードしているためです。 合計$a_i + a_{i+1}$二次関数的に増加し、連続するインデックスに応じて素因数が変化しますが、$3a_{i+2}$これらの要因と一貫して一致しない方法でスケールします。 連続する項間の代数的単純化が欠如しているため、体系的な分割が妨げられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        for i in range(1, n + 1):
            print(i * (i + 1), end=' ')
        print()

if __name__ == "__main__":
    solve()
```実装は構築の後に直接続きます。 各テスト ケースは独立して処理され、不必要に大きな配列を保存しないようにシーケンスをオンザフライで出力します。 表現$i(i+1)$は一定時間で計算され、テスト ケースごとの線形動作が保証されます。 

実装の微妙な詳細は、出力フォーマットです。 この問題では有効なスペースが許容されるため、値をスペースを入れてインラインで出力し、各テスト ケースを改行で終了します。 これにより、Python の I/O 制約下でも効率的でありながら、余分なリスト結合が回避されます。 

## 実用的な例

 検討してください$n = 3$。 この構造により次のことが得られます。 

| 私 | a[i] = i(i+1) |
 | --- | --- |
 | 1 | 2 |
 | 2 | 6 |
 | 3 | 12 |

 唯一のトリプルの条件を確認します。$a_1 + a_2 = 8$、$3a_3 = 36$、36 は 8 で割り切れないため、制約が成り立ちます。 

ここで考えてみましょう$n = 5$:

 | 私 | a[i] |
 | --- | --- |
 | 1 | 2 |
 | 2 | 6 |
 | 3 | 12 |
 | 4 | 20 |
 | 5 | 30 |

 連続するトリプルをテストします。 

のために$i=1$: 合計 = 8、次 = 12、つまり$3a_3 = 36$, 36 は 8 で割り切れません。 

のために$i=2$: 合計 = 18、次 = 20、つまり$3a_4 = 60$, 60は18で割り切れません。 

のために$i=3$: 合計 = 32、次 = 30、つまり$3a_5 = 90$, 90 は 32 で割り切れません。 

各ステップでは、連続する合計の間で gcd 構造が変化することが示されており、一貫した割り算パターンが妨げられています。

 ## 特殊なケース

 のために$n=3$、配列は$[2, 6, 12]$。 唯一の制約が 1 回チェックされます。 合計$a_1 + a_2 = 8$分けない$3a_3 = 36$なので、より深い構造を必要とせずに、条件はすぐに満たされます。 

大型の場合$n$、 のような$n=6$、建設が生み出す$[2, 6, 12, 20, 30, 42]$。 スライディングウィンドウごとに除数が変化します$a_i + a_{i+1}$分子から大幅に$3a_{i+2}$はスムーズに増加しますが、これらの合計と一致しないため、安定した分割パターンは現れません。
