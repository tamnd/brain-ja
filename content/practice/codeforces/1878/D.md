 ## 解決策
 ## 問題の理解

 1 から n までのインデックスが付けられた文字列が与えられ、インデックス範囲は k 個の連続したセグメントに分割されます。 各セグメント i は li から ri までの連続した間隔をカバーし、これらのセグメントは文字列全体をギャップや重複なく正確に並べて表示します。 

次に、一連のクエリを処理します。 各クエリは文字列にインデックス x を与えます。 まず、どのセグメントに x が含まれているかを判断します。 そのセグメント内では、x はセグメントの中点の周りにミラーリングされます。つまり、値 x は [li, ri] 内の対称位置とペアになります。 次に、現在の文字列内のこれら 2 つの対称位置の間の部分文字列を反転します。 

したがって、各操作は単純な単一点の変更ではありません。 位置 x を取得し、それをセグメント内に反映し、元の位置と反映された位置の間の間隔全体を反転します。 

主な問題点は、クエリのたびに文字列が変更され、各クエリが潜在的に大きな部分文字列に影響を与えることです。 直接シミュレーションでは、最大 n のサイズの部分文字列が繰り返し反転され、二次的な動作が発生します。 

制約によりこれは不可能です。 すべてのテスト ケースの合計の長さは最大 2×10^5 で、同じ境界がクエリにも当てはまります。 クエリごとに線形反転さえ実行するソリューションでは、最悪の場合、制限をはるかに超える 4×10^10 の操作が発生する危険があります。 操作ごとに文字列を明示的に変更しないようにする方法が必要です。 

x がそのセグメントの鏡映された中間点に正確にある場合、微妙なエッジ ケースが発生します。 この場合、間隔 [a, b] は単一のインデックスに集約されるため、操作は何も行われません。 単純な実装では依然として逆転が試みられ、不必要なオーバーヘッドが発生する可能性がありますが、より重要なのは、多くの操作が冗長であり、構造的に処理する必要があることを強調していることです。 

もう 1 つの落とし穴は、対称性を認識せずに、重複するセグメントに繰り返し反転を適用することです。 直接シミュレートすると、各操作が文字列の内容ではなく位置によってのみ定義されるという構造が失われます。 

## アプローチ

 ブルートフォース手法は各クエリを直接適用します。つまり、x を含むセグメントを特定し、ミラーインデックス x' = li + ri - x を計算し、次に x と x' の間の部分文字列を反転します。 各反転には O(セグメントの長さ) がかかり、最悪の場合、これは O(n) になります。 q が 2×10^5 までの場合、最悪のケースは O(nq) となり、これは実行不可能です。 

重要な点は、操作が文字列の文字にまったく依存していないことです。 すべてのクエリはインデックスのみを操作します。 文字列は、これらのインデックス変換によって並べ替えられるコンテナとしてのみ使用されます。 これは、「それぞれの元の位置がどこに行き着くのか」と「それがどのような性格を持っているか」を区別できることを意味します。 

文字列を変更する代わりに、位置の順列を追跡します。 各クエリはインデックスのセグメントに反転を適用するため、間隔反転を効率的にサポートするデータ構造を維持します。 

これを自然にサポートする構造は、暗黙的なトレップ ツリーやスプレイ ツリーなどのバランスのとれたシーケンス表現です。 各ノードは現在のシーケンス内の位置を表します。 範囲反転は、シーケンスを 3 つの部分に分割し、中央の部分で反転フラグを切り替えてマージして戻すことによって、O(log n) で適用できます。 

l と r のセグメント構造は、各 x を範囲 [a, b] に変換する場合にのみ重要であり、このマッピングはクエリごとに O(1) です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | O(n) | 遅すぎる |
 | 遅延リバースを使用した暗黙的 treap | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 順序どおりの走査が現在の文字列の順序を表す暗黙的なトレプを維持します。 各ノードは 1 つの文字とサブツリー サイズを保存し、遅延反転フラグをサポートします。

1. 順序どおりの走査がインデックス 1 ～ n に対応するように、初期文字列からトレプを構築します。 これにより、位置とノード間の直接マッピングが得られます。 
2. 各クエリ値 x について、最初に li ≤ x ≤ ri となるセグメント i を特定します。 セグメントが連続しているため、これは二分探索を使用した O(log k) で機能します。 
3. セグメント内のミラーリングされたインデックスを x' = li + ri - x として計算します。 これは、セグメントの中心付近の x を反映します。 操作の影響を受ける間隔は [min(x, x'), max(x, x')] です。 
4. トレプを 3 つの部分に分割します: a の前のプレフィックス、中間セグメント [a, b]、および b の後のサフィックス。 分割はサブツリー サイズを使用して行われるため、インデックスは明示的ではなく暗黙的に残ります。 
5. 中間セグメントを物理的に反転するのではなく、遅延反転フラグを適用します。 これにより、即座に再配置することなく、そのサブツリー内の子の解釈が反転されます。 
6. 3 つの部分を順番に結合します。 
7. すべてのクエリを処理した後、トレプの順序どおりの走査を実行して、最終的な文字列を回復します。 

重要な設計上の選択は、すべての構造変更を延期することです。 反転してもノードはすぐには再配置されません。 これはサブツリーをマークするだけであり、実際の並べ替えは、後の分割または最後の走査中に必要に応じて解決されます。 

### なぜ効果があるのか

 いつでも、トレプは元の文字列のインデックスの順列を表します。 各操作は、この順列の連続する間隔に反転を適用します。 遅延伝播により、すべての反転が影響を受ける各サブツリーに 1 回だけ適用され、サブツリーの境界が現在の位置に正確に対応することが保証されます。 すべてのクエリは現在のシーケンス内の正確なインデックス範囲に変換されるため、操作により順序付け変換の正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("ch", "prio", "left", "right", "size", "rev")
    def __init__(self, ch):
        import random
        self.ch = ch
        self.prio = random.randint(1, 10**9)
        self.left = None
        self.right = None
        self.size = 1
        self.rev = False

def sz(t):
    return t.size if t else 0

def upd(t):
    if t:
        t.size = 1 + sz(t.left) + sz(t.right)

def push(t):
    if t and t.rev:
        t.left, t.right = t.right, t.left
        if t.left:
            t.left.rev ^= True
        if t.right:
            t.right.rev ^= True
        t.rev = False

def merge(a, b):
    if not a or not b:
        return a or b
    push(a)
    push(b)
    if a.prio > b.prio:
        a.right = merge(a.right, b)
        upd(a)
        return a
    else:
        b.left = merge(a, b.left)
        upd(b)
        return b

def split(t, k):
    if not t:
        return (None, None)
    push(t)
    if sz(t.left) >= k:
        a, b = split(t.left, k)
        t.left = b
        upd(t)
        return (a, t)
    else:
        a, b = split(t.right, k - sz(t.left) - 1)
        t.right = a
        upd(t)
        return (t, b)

def inorder(t, out):
    if not t:
        return
    push(t)
    inorder(t.left, out)
    out.append(t.ch)
    inorder(t.right, out)

def build(s):
    root = None
    for ch in s:
        root = merge(root, Node(ch))
    return root

def find_segment(x, l, r):
    # binary search over segments
    lo, hi = 0, len(l) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if l[mid] <= x <= r[mid]:
            return mid
        if x < l[mid]:
            hi = mid - 1
        else:
            lo = mid + 1
    return -1

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        l = list(map(int, input().split()))
        r = list(map(int, input().split()))
        q = int(input())
        xs = list(map(int, input().split()))

        root = build(s)

        for x in xs:
            i = find_segment(x, l, r)
            a = min(x, l[i] + r[i] - x)
            b = max(x, l[i] + r[i] - x)

            left, mid = split(root, a - 1)
            mid, right = split(mid, b - a + 1)

            if mid:
                mid.rev ^= True

            root = merge(left, merge(mid, right))

        out = []
        inorder(root, out)
        print("".join(out))

if __name__ == "__main__":
    solve()
```この実装は、サブツリーのサイズが位置を定義する暗黙的なトリープに依存しています。 スプリット関数は、値ではなくカウントによってプレフィックスを分離します。反転するたびに位置が変化するため、これは重要です。 プッシュ関数により、サブツリーがアクセスされた場合にのみ遅延反転が伝播されるようになります。 

セグメントは連続していて重複しないため、セグメントの検索は個別に行われ、バイナリ検索を使用します。 

よくある間違いは、分割前にプッシュを適用するのを忘れることです。これにより、後で反転されたサブツリーが分割されるときに、誤った構造が発生します。 もう 1 つの微妙な問題は、分割インデックスでの off-by-one の処理です。split(k) は最初の k 要素を返すため、左側の部分は a-1 で分割されます。

入力:

 n = 4、s = abcd

 セグメント: [1,2]、[3,4]

 クエリ: x = 1、3

 ### トレース

 ## 特殊なケース

 重要なエッジ ケースは、x がセグメントのちょうど中間点にある場合です。 この場合、a と b は等しく、操作は何も行われません。 たとえば、セグメント [1,5] および x = 3 の場合、a = 3 および b = 3 が得られます。 treap 分割により単一ノードの中間セグメントが生成され、反転の切り替えには目に見える影響はなく、正確性が維持されます。 

もう 1 つの重要なケースは、複数のクエリが繰り返し重複領域を逆にする場合です。 treap は遅延伝播を使用するため、重複する反転は正しく構成されます。同じサブツリー上の 2 つの反転は論理的にキャンセルされ、構造は常に反転の正しいパリティを反映します。
