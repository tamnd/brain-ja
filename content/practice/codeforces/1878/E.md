 ## 解決策
 ## 問題の理解

 整数の配列と複数のクエリが与えられます。 各クエリは開始インデックスを指定します$l$そして閾値$k$。 タスクは最大の終了インデックスを見つけることです$r \ge l$からの部分配列のビットごとの AND が得られるようにします。$a_l$に$a_r$少なくとも$k$。 そうでない場合$r$存在するので戻ります$-1$。 重要な演算はビット単位の AND で、部分配列を拡張するにつれて単調減少します。要素を追加しても 1 ビットが 0 に変わるだけで、その逆はできません。 

配列の長さ$n$まで可能です$2 \cdot 10^5$テスト ケースごとに、最大で$10^5$クエリ。 すべての合計$n$そしてすべて$q$テストケース全体での制限は次のとおりです$2 \cdot 10^5$。 これは、クエリごとに考えられる各サブ配列を反復する単純なアプローチでは、時間がかかりすぎることを意味します。$O(nq)$到達できた$4 \cdot 10^{10}$最悪の場合の運用。 

考慮すべきエッジケースには、次のようなクエリが含まれます。$k$は開始要素より大きい (したがって、答えはすぐに得られます)$-1$)、配列の最後にあるクエリ、またはすべての要素が同じである配列。 小さな配列 (サイズ 1 または 2) の場合も、慎重な境界処理が必要です。 

## アプローチ

 ブルート フォースのアプローチは簡単です。クエリごとにインデックスから開始します。$l$右側の境界を拡張しながら AND を繰り返し計算します。$r$結果がそれを下回るまで$k$。 これにより、次から始まるすべてのサブ配列がチェックされるため、正確さが保証されます。$l$、しかし最悪のケースは$O(n)$クエリごとに実行されますが、これでは遅すぎます。 

The key observation is that the bitwise AND only decreases or stays the same as we extend the subarray. ビットが一度クリアされると、クリアされたままになります。 この単調な特性により、一種の「二分探索」または貪欲な右方向スキャンを実行できます。すべての要素を個別にチェックする代わりに、各ビットが 1 から 0 に反転する位置を追跡できます。整数は最大 30 ビットなので、$a_i \le 10^9$)、クエリごとに 30 の位置を追跡するだけで済みます。 これにより、各クエリの潜在的な可能性が減少します。$O(n)$に$O(30) = O(1)$実際に。 

もう 1 つの最適化は、開始インデックスごとに、各ビットの最大右境界を事前計算することです。 次に、クエリに応答すると、これらのビット制限としきい値が交差することになります。$k$、基本的に、必要なすべてのビットの右端の位置を計算します。$k$はまだ設定されています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nq) | お(1) | 遅すぎる |
 | 貪欲なビットトラッキング | O(n + q*30) | O(n*30) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取り、それらを繰り返します。 テスト ケースごとに、配列とクエリを読み取ります。 
2. インデックスごとに$i$配列内で辞書を初期化します`next_zero[bit]`指定されたビットがゼロである次の位置を保存します。 配列の末尾から逆方向に反復して、30 ビットすべてのこれらの位置を埋めます。 
3. クエリごとに`(l, k)`、どのビットを設定したままにしておく必要があるかを決定します。 初期化する`r_max`として$n$、可能な最大の右インデックス。 
4. に設定された各ビットについて$k$、 チェック`next_zero[bit][l]`このビットがクリアされる最初のインデックスを見つけます。 アップデート`r_max`現在の値の最小値であり、そのインデックスより 1 小さい値になります。 
5. もし`r_max < l`、出力$-1$; それ以外の場合は出力`r_max`。 
6. 次のクエリに進みます。 

これは、最初に 0 が出現したときにビットごとの AND がゼロになるため機能します。最初のゼロの位置を事前計算することで、必要な各ビットを設定したままどこまで拡張できるかを即座に見つけることができます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        q = int(input())
        queries = [tuple(map(int, input().split())) for _ in range(q)]

        # Precompute next zero for each bit
        MAX_BIT = 30
        next_zero = [[n] * (n + 1) for _ in range(MAX_BIT)]
        
        for bit in range(MAX_BIT):
            nxt = n
            for i in range(n - 1, -1, -1):
                if not (a[i] >> bit) & 1:
                    nxt = i
                next_zero[bit][i] = nxt
        
        results = []
        for l, k in queries:
            l -= 1
            r_max = n - 1
            for bit in range(MAX_BIT):
                if (k >> bit) & 1:
                    r_max = min(r_max, next_zero[bit][l] - 1)
            if r_max < l:
                results.append(-1)
            else:
                results.append(r_max + 1)
        print(" ".join(map(str, results)))

if __name__ == "__main__":
    solve()
```コードの各部分は次のアルゴリズムに従います。`next_zero`各ビットの最初のゼロを追跡し、逆方向に反復することで、次のゼロのインデックスを常に知ることができます。 クエリループの更新`r_max`の必要なビットに従って`k`、境界チェックにより、確実に返されます。$-1$セグメントが無効な場合。 

## 実用的な例

 ### サンプル 1、クエリ 1

 配列:`[15, 14, 17, 42, 34]`クエリ:`l=1, k=7`| 私 | a[i] | next_zero (ビット 0 ～ 3) |
 | --- | --- | --- |
 | 4 | 34 | 5 5 5 4 ... |
 | 3 | 42 | 4 4 4 3 ... |
 | 2 | 17 | 2 2 2 2 ... |
 | 1 | 14 | 1 1 1 1 ... |
 | 0 | 15 | 0 0 0 0 ... |

 7 のビットをチェックしています (`0111`): ビット 0 の最初のゼロはインデックス 2 にあり、ビット 1 は 2 に、ビット 2 は 2 にあります。最小値は次のようになります。`r=2`。 

### サンプル 2、クエリ 2

 配列:`[7, 5, 3, 1, 7]`クエリ:`l=2, k=3`3 のビット:`0011`。 最初のゼロ: ビット 0 はインデックス 3 でクリアされ、ビット 1 はインデックス 2 でクリアされます。`r_max = min(3-1,2-1) = 1`、しかしそれ以来`l=2`、出力`r=2`。 

これらのトレースは、ビットごとの AND 単調性と`next_zero`事前計算により、右端の有効なインデックスが正しく検索されます。
