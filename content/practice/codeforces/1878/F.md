 ## 問題の理解

 私たちは時間の経過とともに変化する単一の整数を維持しており、更新のたびに、現在の値と素因数を共有しない補助的な数値を使用して、それを非常に特殊な除数構造に「完成」させることが可能かどうかを答える必要があります。

したがって、中心的な質問は、構築に関するものではありません。$a$、しかし、そのようなかどうかを決定する$a$存在します。 

制約が意味するのは、$n \le 10^6$最初は、各クエリはそれに最大の数値を乗算するだけです。$10^6$。 クエリの数が少ないため、更新ごとに因数分解ベースの推論を実行できます。 ただし、除数関数は大きくなる可能性があり、それを超えることがないことが保証されています。$10^9$これにより、指数の組み合わせの異常なオーバーフローが防止されますが、構造は単純化されません。 

単純なアプローチでは、候補を明示的に構築しようとします。$a$、しかしそれは不可能です、なぜなら$a$無制限です。 別の障害モードは、現在の値のみから推論しようとしています。$n$約数は指数に乗算的に依存するため、素因数分解を追跡する必要はありません。 

微妙なエッジケースが現れるのは、$n = 1$。 次に、次のことを要求します$d(a) = 1$、強制的に$a = 1$したがって、答えは常に簡単に「はい」になります。 この縮退を無視した解決策は依然として合格しますが、多くの場合、直感に基づいた推論は破綻します。 

## アプローチ

 重要なのは、数字の観点から考えるのをやめ、代わりに素数の指数の観点から考えることです。 

現在の番号が$$n = \prod p_i^{e_i}$$すると、その約数の数は次のようになります。$$d(n) = \prod (e_i + 1)$$次に、次を掛けます。$a$、 どこ$\gcd(a, n) = 1$。 この条件は非常に重要です。つまり、$a$まったく新しい素数が導入されるため、既存の素数の指数構造は$n$変わりません。 

それで、もし$$a = \prod q_j^{f_j}, \quad q_j \notin \{p_i\}$$それから$$d(n \cdot a) = \left(\prod (e_i + 1)\right)\left(\prod (f_j + 1)\right)$$選択できるかどうかを問われます$a$となることによって：$$d(n \cdot a) = n$$代入:$$d(n)\cdot \prod (f_j + 1) = n$$そこで問題は、整数を因数分解できるかということです。$\frac{n}{d(n)}$形式的には$(f_j + 1)$、ここで、すべての素指数があるため、各項は少なくとも 2 です。$f_j \ge 1$。 

したがって、すべての要素は少なくとも 2 に寄与しており、本質的に次のことを表現できるかどうかを尋ねています。$\frac{n}{d(n)}$整数の積として$\ge 2$。 それはいつでも可能です、そしてその場合に限り$\frac{n}{d(n)} \ge 1$しかし、さらに深い隠れた制約があります。この因数分解が有効な指数の割り当てに対応していることを確認する必要があり、さらに重要なことに、乗算クエリを繰り返しても値に到達できる必要があります。 

本当の転換点は、構築する必要がないことに気づくことです。$a$、実行可能性をテストするだけであり、唯一の障害は次の素指数構造から生じます。$n$。 正しいリダクションは、次のすべての素指数が正しいかどうかをチェックすることを簡素化します。$n$注意深く追跡された不変式を除算した後はゼロに等しくなります。 実際には、これは維持することになります。$d(n)$そして、$d(n) \mid n$そして$n / d(n)$新しい素数を追加することで構築できますが、これは常に可能です。 

したがって、各クエリは、素数指数を動的に維持し、約数の数を再計算することになります。これは、更新が制限された因数サイズで乗算されるため、実行可能です。

 ## アルゴリズムのチュートリアル

 1. 現在の数値を維持する$n$そしてその素因数分解。 を掛けるたびに$x$、 要素$x$指数を現在の因数分解にマージします。 これは、除数の数が素数指数にのみ依存するため必要です。 
2. コンピューティング$d(n) = \prod (e_i + 1)$因数分解から。 これにより、約数を列挙せずに正確な数が得られます。 
3. タイプ 1 クエリの場合、更新後$n$、条件が成立するかどうかを計算します。 これは、次のことを確認することになります。$n$は、その約数の数と、残りの因数が新しい素数を使用して実現できるかどうかで割り切れます。 
4. 実現可能性チェックでは、次のことを簡単に検証できます。$n \mod d(n) = 0$。 分割できない場合、構築はできません$a$除数の乗算は整数の乗算であり、小数部のギャップを調整できないため、補正できます。 
5. 実行可能な場合は「YES」を出力し、実行可能な場合は「NO」を出力します。 
6. タイプ 2 クエリの場合は、元の因数分解と除数カウントの状態を復元します。 

### なぜ効果があるのか

 不変条件は、次の因数分解です。$n$完全に決定する$d(n)$、互いに素数を乗算すると、独立した乗算係数が除数の数に追加されるだけです。 新しいプライムが導入されるたびに、$a$除数関数に少なくとも 2 の係数を寄与します。達成可能な除数のセットは固定値からカウントされます。$n$は正確にすべての倍数です$d(n)$これは、シフトされた指数が比率の因数分解を形成する整数を乗算することで達成できます。 これは、実現可能性が分割可能性の制約のみに依存し、特定の構造には依存しないことを意味します。$a$、それらの制約は追跡指数によって完全に捕捉されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXN = 10**6 + 5

spf = list(range(MAXN))
for i in range(2, int(MAXN**0.5) + 1):
    if spf[i] == i:
        for j in range(i * i, MAXN, i):
            if spf[j] == j:
                spf[j] = i

def factor(x, mp):
    while x > 1:
        p = spf[x]
        cnt = 0
        while x % p == 0:
            x //= p
            cnt += 1
        mp[p] = mp.get(p, 0) + cnt

def calc_div(mp):
    res = 1
    for v in mp.values():
        res *= (v + 1)
    return res

t = int(input())
for _ in range(t):
    n, q = map(int, input().split())
    orig = n

    mp = {}
    factor(n, mp)

    def reset():
        nonlocal mp
        mp = {}
        factor(orig, mp)

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '2':
            reset()
            continue

        x = int(tmp[1])
        factor(x, mp)

        # recompute n value is not needed explicitly; only factorization matters
        # compute current n and divisor count
        cur_n = 1
        for p, e in mp.items():
            cur_n *= p ** e

        d = calc_div(mp)

        # condition check from derived reduction
        if cur_n % d == 0:
            print("YES")
        else:
            print("NO")
```この実装は、すべての更新を迅速に因数分解するために最小素因数ふるいに依存しています。 因子辞書`mp`の現在の指数ベクトルを格納します$n$。 各乗算では指数が結合され、除数の計算に必要な乗算構造が維持されます。 

チェックでは、以下の可算性に基づいて導出された条件が使用されます。$n$そして$d(n)$。 問題は補助者の存在という観点から組み立てられているが、$a$、実装はそれを完全に構築することを回避します。 

タイプ 2 は因数分解を元の状態にリセットします。$n$、独立したクエリフェーズ全体で正確性を保証します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MAXN = 10**5 + 5
    spf = list(range(MAXN))
    for i in range(2, int(MAXN**0.5) + 1):
        if spf[i] == i:
            for j in range(i*i, MAXN, i):
                if spf[j] == j:
                    spf[j] = i

            p = spf[x]
            cnt = 0
            while x % p == 0:
                x //= p
                cnt += 1
            mp[p] = mp.get(p, 0) + cnt

    def calc(mp):
        res = 1
        for v in mp.values():
            res *= (v + 1)
        return res

    t = int(input())
    out = []
    for _ in range(t):
        n, q = map(int, input().split())
        orig = n

                cur = 1

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$n = 1$。 この場合、除数の数は常に 1 となるため、自明でない因数を導入する乗算は直ちに等価条件を破ります。 因数分解マップが空になり、除数の計算で 1 が得られるため、アルゴリズムはこれを自然に処理します。そのため、実行可能性は、新しい素数が導入されない場合にのみ常に合格する簡単な割り算チェックに減ります。 

もう 1 つの微妙なケースは、乗算を繰り返すと多くの小さな素数が導入され、指数の増加が生じる場合に発生します。 SPF ベースの因数分解により、更新が繰り返されても効率が維持されます。$10^6$サイズに応じて対数時間で分解します。 

最後のエッジケースは、頻繁なリセットです。 タイプ 2 は正確な元の因数分解を復元するため、アルゴリズムは乗算を逆にしようとするのではなく、保存された初期状態から再構築することによって増分ドリフトを回避します。
