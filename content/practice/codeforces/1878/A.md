 ## 解決策
 ## 問題の理解

 この問題は、整数の配列とターゲット整数が与えられた場合に、$k$、少なくとも 1 つの連続したサブ配列が存在します。$k$は他のどの要素よりも頻繁に出現する要素です。 各テスト ケースは配列のサイズを示します。$n$、ターゲット$k$、および配列$a$自体。 各テスト ケースの答えは、そのようなサブセグメントが存在する場合は「YES」、存在しない場合は「NO」です。 

制約は小さいです。$n$最大でも 100 であり、$t$テストケースの数は最大1000です。各要素$a_i$そして$k$も最大 100 です。これは、$O(n^2)$すべてのサブ配列を調査する単一のテスト ケースのアプローチは、最悪のケースでは次のような問題が発生するため、計算の観点からは許容されます。$1000 \cdot 100^2 = 10^7$1 秒の制限時間内で管理できる操作。 

微妙なエッジケースが発生するのは、$k$配列内で 1 回だけ出現するか、最後または最初に出現します。 たとえば、次の場合$a = [1, 2, 3]$そして$k = 3$を含む唯一の部分配列$k$は$[3]$。 このようなシナリオでは、アルゴリズムは、次のように、単一要素の部分配列が適格であることを正確に識別する必要があります。$k$明らかに最も一般的な要素です。 考慮すべきもう 1 つのケースは次のような場合です。$k$複数回出現しますが、サブ配列が許可されないように常に他の要素によって区切られています。$k$数で優位に立つこと。 最小長のウィンドウを正しく処理することで、ソリューションが確実に堅牢になります。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべての部分配列に対して反復処理が行われます。$a$そしてその部分配列内の各要素の頻度を数えて、$k$の数が最も多いです。 長さの単一配列の場合$n$、おおよそあります$n(n+1)/2$各サブ配列の頻度をカウントするには、最大で 3 分かかる場合があります。$O(n)$操作の結果、$O(n^3)$テストケースごとに。 このアプローチは正しいですが、非効率的です。$n = 100$、降伏$10^6$テストケースごとの操作と$10^9$すべてのテスト ケースにおける最悪のケース。 

重要な観察により、問題は大幅に軽減されます。$k$他の最大 1 つの出現と並んでサブ配列内で出現する必要があるだけです。$k$近隣を支配するために近くにあります。 もっと具体的に言えば、$k$少なくとも 2 回出現し、その 2 つの出現箇所は次の位置にあります。$i$そして$j$と$j - i \le 2$、 それから$k$位置をカバーするサブ配列で最も頻繁に発生する可能性があります$i$を通して$j$。 配列の長さが 1 である場合、または配列と競合する要素が周囲にない場合は、1 回出現するだけで十分です。 

最適なソリューションは、配列をスキャンし、次の発生間隔をチェックすることでこれを利用します。$k$。 もし$k$2 つの要素の距離内に少なくとも 2 回出現する場合は、すぐに「YES」と答えることができます。 それ以外の場合は、次のことを確認します。$k$配列内に少なくとも 1 回発生します。1 回だけ発生し、配列の長さが 1 の場合、答えは「YES」です。 配列が長い場合は、単一の孤立した$k$2 要素の部分配列であっても、他の要素が異なる場合、それが最も頻繁に発生する可能性があるため、これで十分です。

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 テスト ケースごとに、次の内容を読んでください。$n$、$k$、および配列$a$。 
2. 何回数えるか$k$配列に表示されます。 出現回数が 0 回の場合は、「NO」と出力して次のテスト ケースに進みます。 
3. 配列に要素が 1 つだけ含まれている場合、その要素が 1 つであれば「YES」を出力します。$k$。 
4. それ以外の場合は、配列を反復処理して、すべてのインデックスのペアを確認します。$i$そして$j$どこ$i < j$そして$j - i \le 2$。 両方の位置に$k$、すぐに「YES」を出力します。 
5. そのようなペアが見つからない場合は、$k$配列内に存在する場合は、単一要素のサブ配列が含まれているため、「YES」を出力します。$k$資格があります。 
6. これらの条件がいずれも満たされない場合は、「NO」と出力します。 

なぜ機能するのか: ここでの不変条件は、長さが 1 のサブ配列には次のものが含まれるということです。$k$は自動的に有効になります。 長いサブ配列の場合、距離チェックにより次のことが保証されます。$k$少なくとも 2 つの隣接する要素を支配して、有効なサブ配列を形成できます。 アルゴリズムは、すべての最小部分配列を正確に識別します。$k$すべてのサブ配列の不必要なカウントを避けるために、これが最も頻繁に行われる可能性があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    count_k = a.count(k)
    
    if count_k == 0:
        print("NO")
        continue
    
    if n == 1:
        print("YES")
        continue
    
    found = False
    for i in range(n):
        if a[i] != k:
            continue
        for j in range(i, min(i + 3, n)):
            if a[j] == k and j - i <= 2:
                found = True
                break
        if found:
            break
    
    print("YES" if found else "NO")
```このソリューションでは、まず次の発生をカウントします。$k$。 もし$k$が存在しない場合、答えは「NO」です。 単一要素の配列は扱いが簡単です。 ネストされたループは、小さなウィンドウ (最大長 3) 内のペアをチェックして、$k$局地的に支配できる。 内側のループの上限により、配列の境界を超えないことが保証されます。
