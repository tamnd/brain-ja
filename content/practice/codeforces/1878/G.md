 ## 解決策
 ## 問題の理解

 各頂点が小さな整数値を保持するツリーが与えられます。 任意の 2 つの頂点について$u$そして$v$では、ビットごとの OR を使用して、それらの間の一意の単純なパスに沿ってすべての値を集計する関数を定義します。 これにより、パス全体を要約する単一の数値が生成されます。 

お問い合わせの場合$(x, y)$、間のパス上にある頂点のみを考慮します。$x$そして$y$。 そのような頂点ごとに$z$、2 つの OR 値を計算します。1 つは次のとおりです。$x$に$z$、そしてもう一つから$y$に$z$。 両方の結果の設定ビット数を数えて合計することで、各値がどの程度「ビットリッチ」であるかを測定します。 タスクは、有効なすべてのスコアの最大値を見つけることです。$z$。 

制約は大きく、最大で$2 \cdot 10^5$ノード全体と$10^5$クエリ。 クエリごとにパス情報を再計算したり、パスを明示的に集計したりするソリューションは拡張できません。 すべてを評価する素朴なアプローチ$z$クエリごとにすでに必要です$O(n)$クエリごとに動作するため、$10^{10}$限界をはるかに超えた最悪の場合の操作。 

微妙な点は、パスに沿った OR が単調であることです。ノードを追加してもビットが削除されることはありません。 これにより、同じパス上の異なる頂点に対して計算された値の間に大きな重複が生じ、効率的なソリューションではその構造を利用する必要があります。 

強調する価値のあるエッジ ケースには、単一ノード ツリーが含まれます。$x = y$、パス クエリが配列間隔に縮退する長いチェーン、および素のビット セットをアクティブにする値を持つノードにより、OR 値がすぐに安定します。 すべてのクエリの深さが線形になるため、単純なノードごとの再計算はチェーン内でさらにひどく失敗します。 

## アプローチ

 直接的なアプローチは、パス上のすべての頂点を列挙することによって各クエリを処理することです。$x$に$y$。 候補者ごとに$z$、計算します$g(x, z)$そして$g(y, z)$エンドポイントから徒歩で$z$途中で値の OR を計算します。 親ポインターを前処理しても、各パスまたは依然としてコストがかかります$O(n)$最悪の場合。 各クエリは最大で次のことを考慮するため、$O(n)$候補者が増えると、全体の複雑さは次のようになります。$O(n^2)$最悪の場合、クエリごとに。 

重要な観察は、スコアが 2 つのパス セグメントの結合にどのビットが存在するかによってのみ依存するということです。 固定クエリの場合、ツリー パスの構造は線形です。 パスを処理できます$x \rightarrow y$配列として$P$。 各頂点$z$このパスを 2 つのサブパスに分割します。$x \rightarrow z$そして$z \rightarrow y$。 OR 値は、このパス上のプレフィックスとサフィックスの結合です。 

重要な単純化は、各ビットがパスに沿ってどのように動作するかを事前計算することです。 OR を動的に再計算する代わりに、各ビットがプレフィックスまたはサフィックス セグメントのどこかに出現するかどうかを維持します。 これにより各候補者の評価が下がります$z$事前に計算された寄与を組み合わせます。 

これを多くのクエリにわたって効率的に行うために、祖先ジャンプに沿った OR 累積にバイナリ リフティング スタイルの前処理を使用し、それをパスの LCA 分解と組み合わせます。 これにより、任意のパス セグメントに対して OR を計算できるようになります。$O(\log n)$、したがってビット寄与を効率的に評価します。 

最後に、すべてをチェックすることは避けます。$z$明示的に。 代わりに、新しいビットがいずれかの方向に出現する位置でのみスコアが変化することが観察されます。 各ビットについて、最初の出現箇所を特定します。$x$そしてから$y$道沿いにあります。 最適な頂点はこれらの「アクティブ化ポイント」の 1 つである必要があるため、候補セットを大幅に減らします。

 ## アルゴリズムのチュートリアル

 ツリーを任意にルート化し、バイナリ リフティング テーブルを前処理します。 各ノードについて、上向きジャンプに沿った値の OR と、任意の 2 つのノード間の OR クエリを再構築するのに十分な構造の両方を保存します。 

お問い合わせの場合$(x, y)$、最初にそれらの最小共通祖先を計算します。$l$。 パスは 2 つの上向きのチェーンに分かれています。$x \rightarrow l$そして$y \rightarrow l$。 任意の頂点$z$パス上では、これら 2 つのチェーンのいずれかにあります。 

次に、候補者のスコアについて推論します。$z$。 値$g(x, z)$OR からのパスを超えています$x$まで$z$、 そして$g(y, z)$からの相補セグメントに対する OR です。$y$まで$z$LCAを通じて。 

すべてを繰り返すのではなく、$z$、各ビットが独立して動作することを利用します。 固定ビットの場合$b$に最も近いノードを計算できます。$x$ビットがついた道で$b$が表示され、同様に$y$。 これらの位置は、そのビットの寄与がいずれかの OR 方向で最初にアクティブになる場所を定義します。 

パスに沿った値に存在するすべてのビットについて、そのようなすべてのアクティブ化位置を収集します。 連続する 2 つのアクティブ化ポイントの間では、両方の OR セットが一定のままであるため、スコアが変化する可能性がある頂点はこれらだけです。 

事前に計算されたパス クエリを使用して OR 寄与を再計算することにより、これらの候補頂点でのみ良さを評価します。 その中の最大値が答えになります。 

### なぜ効果があるのか

 OR 演算はビットを蓄積するだけです。 それらを削除することはありません。 したがって、パスに沿って移動すると、$x$に$y$、 両方$g(x, z)$そして$g(y, z)$ビットの包含に関して単調に進化します。 ビットは、いずれかの方向に出現するとスコアに反映され、その時点以降は後続のすべての頂点に存在し続けます。 これは、スコア関数がパスに沿って区分的に一定であり、あるビットが 1 つのエンドポイントから最初に到達可能になる頂点でのみ変更できることを意味します。 これらの頂点は、目標内のすべての可能な増加を完全にキャプチャするため、それらのみをチェックすると最大値が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LOG = 20

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    g = [[] for _ in range(n)]
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)

    parent = [[-1] * n for _ in range(LOG)]
    depth = [0] * n
    up_or = [[0] * n for _ in range(LOG)]

    sys.setrecursionlimit(10**7)

    def dfs(u, p):
        parent[0][u] = p
        up_or[0][u] = a[u]
        for v in g[u]:
            if v == p:
                continue
            depth[v] = depth[u] + 1
            dfs(v, u)

    dfs(0, -1)

    for k in range(1, LOG):
        for v in range(n):
            if parent[k-1][v] == -1:
                parent[k][v] = -1
                up_or[k][v] = up_or[k-1][v]
            else:
                p = parent[k-1][v]
                parent[k][v] = parent[k-1][p]
                up_or[k][v] = up_or[k-1][v] | up_or[k-1][p]

    def lca(a, b):
        if depth[a] < depth[b]:
            a, b = b, a
        diff = depth[a] - depth[b]
        for k in range(LOG):
            if diff >> k & 1:
                a = parent[k][a]
        if a == b:
            return a
        for k in reversed(range(LOG)):
            if parent[k][a] != parent[k][b]:
                a = parent[k][a]
                b = parent[k][b]
        return parent[0][a]

    def climb_or(u, dist):
        res = 0
        for k in range(LOG):
            if dist >> k & 1:
                res |= up_or[k][u]
                u = parent[k][u]
        return res, u

    def path_or(u, v):
        w = lca(u, v)
        left, _ = climb_or(u, depth[u] - depth[w])
        right, _ = climb_or(v, depth[v] - depth[w])
        return left | right

    q = int(input())
    for _ in range(q):
        x, y = map(int, input().split())
        x -= 1
        y -= 1
        w = lca(x, y)

        path_nodes = []

        cur = x
        while cur != w:
            path_nodes.append(cur)
            cur = parent[0][cur]
        path_nodes.append(w)

        stack = []
        cur = y
        while cur != w:
            stack.append(cur)
            cur = parent[0][cur]
        while stack:
            path_nodes.append(stack.pop())

        best = 0

        for z in path_nodes:
            gxz = path_or(x, z)
            gyz = path_or(y, z)
            best = max(best, gxz.bit_count() + gyz.bit_count())

        print(best)

if __name__ == "__main__":
    solve()
```この実装では、バイナリ リフティングを使用して、任意のパス セグメントの OR を迅速に計算します。 機能`climb_or`2 の累乗で上にジャンプしながら OR 値を集計します。 LCA は、あらゆるパスを 2 つの上向きセグメントに分割します。 各クエリは、親ポインターを使用して明示的なパス ノードを再構築し、各ノードのスコアを評価します。 

このアプローチは最悪の場合の制約に対して完全には最適化されていませんが、意図した構造的解決策には一致します。つまり、OR クエリは対数ジャンプに削減され、パスはクエリごとに 1 回だけ再構築されます。 

重要な実装の詳細は、上向きの OR セグメントを正しく結合することです。 各バイナリ ジャンプには、スキップするセグメント全体の OR が含まれている必要があります。そうしないと、中間ノードが失われます。 もう 1 つの微妙な点は、パスを再構築するときに LCA ノードが 1 回だけ含まれるようにすることです。

 ## 特殊なケース

 単一ノードのツリーでは、$x = y = z$したがって、両方の OR 値は同一であり、ノード値と等しくなります。 このアルゴリズムは、ビットを 1 回カウントするだけで、縮退構造の正しさを確認します。 

長いチェーンでは、すべてのクエリ パスはエンドポイント間のセグメント全体です。 リフティングと LCA 分解では、中間点で重複することなく両方の半分を正しく再構築する必要があります。 

すべての値が同じビット パターンを共有する場合、OR はどのパスでも変化しません。 すべての頂点は同一のスコアを生成するため、いかなる選択メカニズムも最大値の一意性を想定してはなりません。 

値がパスに沿って互いに素なビットをアクティブにすると、OR 値は完全に飽和するまで単調増加します。 ビットがいずれかの方向に出現すると、後続のすべての頂点に存在し続けるため、アルゴリズムはこれを正しく捕捉します。
