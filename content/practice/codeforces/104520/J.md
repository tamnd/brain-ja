 ## 解決策
 ## 問題の理解

 周期的なスケジュールが与えられています$N$日。会議は各サイクルの一部の日に開催されます。 それぞれの$M$問題設定者には毎週の固定パターンがあります: setter$i$の会議に出席します$p_i$サイクルの特定の日。 

さて、ある日アイデアが現れると想像してください$d$。 その瞬間から、情報は 2 人の人間が同じ会議で会ったときにのみ広まります。 情報を「シード」するために会議に積極的に参加できるのは、ボソロジストだけです。 彼が特定の日に会議に出席するたびに、その会議に出席しているすべてのセッターが認識するようになり、同じように参加する他の会議にも認識をさらに広げることができます。 

次の期間内にそれを保証する必要があります$N$日から始まる日々$d$、開催されるすべての会議は「生産的」でなければなりません。つまり、少なくとも 1 人の出席者は、ボソロジスト自身、またはすでにそのアイデアに気づいている人のいずれかです。 タスクは、開始日ごとに計算することです$d$、この条件を確保するためにボソロジストが出席しなければならない会議の最小数。 

これを再構成する有効な方法は、日をグラフ内のノードとして考えることです。各設定者は、参加するすべての日を「潜在的な情報伝達」のチェーンに接続します。 Bossologist が日付を入力すると、共有セッターを介してリンクされた日の接続コンポーネント全体がアクティブになりますが、実際に訪問する会議を通じてのみ有効になります。 目標は、次の期間内に関連するすべての日に到達できるように、意識を直接「注入」する必要がある最小の日数を見つけることです。$N$サイクリックウィンドウはカバーされます。 

制約は大きいです:$N, M \le 10^5$および最大出席エントリの合計$5 \cdot 10^5$。 これにより、すべてのセッターに対して BFS または DFS を使用して開始日ごとに到達可能性を個別に再計算するソリューションは除外されます。$O(N \cdot (N + M))$最悪の場合の動作は限界をはるかに超えています。 

重要な点は、回答が開始日ごとに独立して必要であること、およびサイクル構造により、各クエリが長さのスライディング ウィンドウに対応することを意味することです。$N$円形の配置で。 この循環依存関係により、単純な再計算が失敗します。 

重要なエッジケースの 1 つは、会議がまったくない日です。 その日は答えには寄与しませんが、日のサイクルの中での隣接性に影響を与えます。 不用意なソリューションを使用すると、誤って無関係なものとして扱われ、連続性が損なわれ、誤ったコンポーネントのマージが発生する可能性があります。 

もう 1 つの微妙なケースは、セッター全員が共通の 1 日のみに参加する場合です。 その後、その日に Bossologist が 1 回出席するだけですべてがアクティブ化されるはずですが、実装が各セッターを個別に扱う場合、複数のシードが必要であると誤って想定される可能性があります。 

## アプローチ

 ブルートフォースアプローチでは、各開始日のプロセスを個別にシミュレートしようとします。 固定日の場合$d$、次を検討します$N$日を作成し、セッターが両方に出席した場合に日が接続されるグラフを作成します。 次に、伝播を繰り返しシミュレートします。Bossologist が 1 日に出席すると、セッターを介して接続されたすべての日がアクティブになり、これ以上の成長が不可能になるまでこれが続きます。 最小会議数は、そのウィンドウ内のすべてのアクティブなコンポーネントをカバーするために必要なシード日の最小数になります。 

意識の広がりはまさに共有出席に対する推移的閉包であるため、これは概念的には機能しますが、コストが法外に高くなります。 開始日ごとに、誘導グラフの構築にかかるコスト$O(N + \sum p_i)$、伝播の実行には同様の規模のコストがかかります。 全員のためにこれを行う$N$開始点は大まかに与えます$O(N^2)$実際の動作では大きすぎます。$N = 10^5$。 

重要な洞察は、視点を逆転させることです。 開始日ごとの伝播をシミュレートする代わりに、各セッターが参加する日の間の接続を効果的に定義し、これらの接続が開始日に依存しないことがわかります。 唯一変わるのは$d$サイズのスライディング ウィンドウでアクティブとみなされる日のサブセットです。$N$。 

したがって、問題は、固定の 2 部構成 (セッターと日) に対するスライディング ウィンドウの接続の問題になります。 各設定者は出席日数のエッジに寄与しており、各循環ウィンドウと交差する接続コンポーネントの数を知りたいと考えています。 ウィンドウの答えは基本的に、Bossologist が「タッチ」する必要があるコンポーネントの数です。つまり、以前のシードによって内部的にアクティブ化されなかったコンポーネントの数を数えることになります。 

これにより、一度グローバルに構築された、何日もかけてバラバラの集合構造が構築されます。 その後、各クエリは円形配列上の範囲内のコンポーネントをカウントすることになりますが、これは前処理とプレフィックス技術で処理できます。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(N(N + M))$|$O(N + M)$| 遅すぎる |
 | 最適 |$O((N + M) \alpha(N))$|$O(N + M)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 上に Union-Find 構造を構築します。$N$日々。 各セッターについて、参加するすべての日をリストの代表日と結合します。 これにより、各セッターの影響が日々の連結された要素に圧縮されます。 
2. すべてのセッターを処理した後、毎日は、共有セッターを介して相互に接続されたすべての日を表すコンポーネントに属します。 これは、クエリの開始に依存しないグローバルな伝播構造です。 
3. 配列を構築する`comp[d]`毎日をそのコンポーネント識別子にマッピングします。 これにより、問題は、円形配列上のコンポーネント ID の線形シーケンスに対する処理に変換されます。 
4. 毎日について$d$、周期間隔内にいくつの個別のコンポーネントが現れるかを知りたいのです。$[d, d+N-1]$。 構造は円形であるため、この間隔は配列を 2 回取得し、次の長さのウィンドウをスライドすることに対応します。$N$。 
5. 二重化された配列を構築する`A`長さの$2N$、 どこ`A[i] = comp[(i mod N)]`。 この線形化により、すべての巡回ウィンドウが標準の連続サブ配列になることが可能になります。 
6. あらゆる長さのウィンドウ内の個別のコンポーネントの数を計算します。$N$スライディング ウィンドウ周波数マップを使用します。 現在ウィンドウ内に存在するコンポーネントの数のカウンターを維持します。 
7. 各ポジションについて$d$、答えは、ウィンドウ内の異なるコンポーネントの数です。$d$。 これは、切断された「情報領域」がいくつ存在するかを表しており、それぞれをアクティブ化するには少なくとも 1 人の直接のボソロジストの出席が必要です。 

### なぜ効果があるのか

 各セッターは、参加する日の間で同等性を生み出します。これは、ボソロジストによる追加の努力なしで、情報が常に接続された日の構成要素内で自由に移動できることを意味します。 したがって、グローバル接続コンポーネントが形成されると、Bossologist に残された唯一のタスクは、時間枠内に表示されるすべてのコンポーネントが少なくとも 1 回アクティブ化されるようにすることです。 コンポーネント内の 1 つの会議のアクティブ化はその日全体に広がるため、出席しなければならない会議の最小数は、そのウィンドウ内に存在する個別のコンポーネントの数とまったく同じになります。 Union-find 構造により、相互到達可能性の下でこれらのコンポーネントが最大になることが保証されるため、クエリの開始に応じてそれ以上の分割やマージが行われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.r = [0] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.r[a] < self.r[b]:
            a, b = b, a
        self.p[b] = a
        if self.r[a] == self.r[b]:
            self.r[a] += 1

def solve():
    N, M = map(int, input().split())
    dsu = DSU(N)

    day_sets = []

    for _ in range(M):
        arr = list(map(int, input().split()))
        p = arr[0]
        days = [x - 1 for x in arr[1:]]
        if p == 0:
            continue
        first = days[0]
        for d in days[1:]:
            dsu.union(first, d)

    comp = [dsu.find(i) for i in range(N)]

    A = comp * 2

    freq = {}
    distinct = 0
    ans = [0] * N

    l = 0
    for r in range(2 * N):
        c = A[r]
        freq[c] = freq.get(c, 0) + 1
        if freq[c] == 1:
            distinct += 1

        if r - l + 1 > N:
            left_c = A[l]
            freq[left_c] -= 1
            if freq[left_c] == 0:
                distinct -= 1
                del freq[left_c]
            l += 1

        if r >= N - 1:
            start = r - N + 1
            if start < N:
                ans[start] = distinct

    print("\n".join(map(str, ans)))

if __name__ == "__main__":
    solve()
```DSU の構築では、各設定者の出席リストを使用して、日数をグローバルな到達可能性コンポーネントに統合します。 圧縮ステップにより、各コンポーネントが原子単位のように動作することが保証されます。 

二重配列は、複雑なモジュラー演算を行わずに循環間隔を処理するための標準的な手法です。 スライディング ウィンドウは各間隔でアクティブなコンポーネントの正確な数を維持し、辞書は多重度を追跡するので、各間隔で個別のコンポーネントの数を維持できます。$O(1)$ステップごとに償却されます。 

微妙な点はコンディションです`r >= N - 1`これにより、ウィンドウのサイズがいっぱいになったときにのみ回答の記録を開始することが保証されます。$N$が形成されました。 これがないと、部分的なウィンドウが結果に誤った影響を与える可能性があります。

 ## 特殊なケース

 特殊なケースの 1 つは、セッターがまったく存在しない場合です。 この場合、毎日が独自のコンポーネントを形成するため、各ウィンドウには次の内容が含まれます。$N$異なるコンポーネントが存在するため、Bossologist はウィンドウ内のすべての会議に出席する必要があります。 DSU は何も結合しないため、`comp[i] = i`、スライディング ウィンドウはすべての個別の ID を正確にカウントします。 

もう一つのケースは、セッターが全日参加する場合です。 これにより、DSU 全体が 1 つのコンポーネントに折りたたまれます。 スライディング ウィンドウでは常に 1 つのコンポーネントが表示されるため、毎日の答えは 1 となり、1 人の出席者が世界中に伝播するという直観と一致します。 

より微妙なケースは、セッター 1 が 1 日目と 2 日目を接続し、セッター 2 が 2 日目と 3 日目を接続するなど、出席パターンがチェーンを形成する場合です。 DSU は、単一のセッターが 1 日をまたがない場合でも、すべてを 1 つのコンポーネントに徐々にマージします。 正しさは結合の推移性から生まれ、重複する会議間の実際の情報の流れと一致します。
