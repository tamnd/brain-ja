 ## 解決策
 ## 問題の理解

 いくつかのテスト ケースが与えられ、各テスト ケースは数直線上の閉区間の集合で構成されます。 すべての間隔は、2 つのグループのうちの 1 つに正確に割り当てる必要があります。 制約は各グループ内に課されます。つまり、間隔をグループに配置すると、その同じグループ内の間隔のすべてのペアは、少なくとも 1 つの共通点で重複する必要があります。 異なるグループの間隔は完全に独立しており、制限なく重複する場合も重複しない場合もあります。 

タスクは、すべての区間を 2 つのグループに分割し、両方のグループが「ペアごとに交差するファミリー」のままになるようにしながら、2 つのグループのうち小さい方をできるだけ大きくすることです。 

有効なグループ内の構造は非常に厳格です。 一連の間隔がペアごとに交差しているのは、すべての間隔が少なくとも 1 つの共通点を共有している場合に限ります。 これは直線上の間隔の古典的な特性です。ペアごとの交差はグローバル交差を意味します。 したがって、各グループは、そのグループ内のすべての間隔内にある単一の点として見ることができます。 

これにより、問題は分割タスクに変わります。各セットに空でない交差があり、2 つのセットの最小サイズが最大になるように、区間を 2 つのセットに分割したいと考えています。 

入力サイズは、すべてのテスト ケースにわたって最大 300,000 間隔に達します。 n = 3×10^5 での 1 回のテストでも 2 秒の制限下では O(n^2) の演算が不可能になるため、間隔にわたって 2 次の動作を行う解はすぐに失敗します。 これにより、ソート ベースまたは線形時間の貪欲な構造 (おそらく O(n log n) または O(n)) に向かうことになります。 

間隔が極端にネストされている場合や同一である場合には、微妙なエッジケースが発生します。 たとえば、すべての間隔が [1, 5] のように同一である場合、すべてのサブセットが有効であるため、両方のグループを任意に分割できます。 答えは、単純にできるだけ均等に分割することです。 もう 1 つのエッジ ケースは、[1,2]、[2,3]、[3,4] など、チェーン内で区間がほとんど重なり合わない場合です。この場合、どのトリプルもグローバル交差に失敗するため、大きなグループに 3 つを超える区間を含めることはできません。 

## アプローチ

 ブルートフォース手法では、すべての間隔の割り当てを 2 つのグループに分けて試行し、すべての間隔が共通の交点を共有しているかどうかをグループごとにチェックします。 各割り当ての妥当性を検証するには、各グループの間隔の交差 (グループあたり O(n)) を計算する必要があります。 2^n 個の割り当てがあるため、これは n = 30 の場合でも直ちに実行できません。 

スマートな列挙に限定したとしても、主な困難は、一連の間隔がいつ有効であるかを理解することです。 グループは、左端の最大値が右端の最小値以下である場合にのみ有効です。 これにより、コンパクトな妥当性チェックが行われますが、最適化はまだ解決されていません。 

重要な洞察は、しきい値点の観点から考えることです。 直線上の点 x を固定すると、x を含むすべての区間は、すべて x で交差するため、安全に同じグループに属することができます。 これは、有効なグループは基本的に、点 x を選択し、それをカバーするすべての区間を選択することによって決定されることを示唆しています。 ただし、単一のポイントをグローバルに使用する必要はありません。 そのようなグループが 2 つ必要です。 

したがって、構造は次のようになります。各グループに 1 つずつ、2 つの「代表的な交点」を選択します。 各間隔は、選択した点がその中にあるグループに割り当てる必要があります。 最小グループ サイズを最大化するには、これら 2 つの代表点がバランスの取れた方法でできるだけ多くの間隔をキャプチャする必要があります。

これは古典的なスイープラインのアイデアに変わります。 エンドポイントごとに間隔を並べ替え、さまざまな位置で同時にアクティブにできる間隔の数を評価します。 任意の点 x について、x をカバーする区間の数は、x を中心とする候補グループのサイズと正確に一致します。 したがって、最良の戦略は、カバレッジが最大になるポイントを見つけて、それらの間隔を削除し、残りのセットで最適なポイントを計算することです。 最終的な答えは、これら 2 つのカバー サイズの最大値と最小値です。 

問題は、貪欲に最適な方法で干渉しない間隔の 2 つの最適な「カバレッジ ピーク」を見つけることになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース割り当てチェック | O(2^n · n) | O(n) | 遅すぎる |
 | スイープライン + ベスト 2 センター | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 間隔を左側のエンドポイントで並べ替えます。 これにより、自然な左から右への構造が得られ、重複パターンの推論が容易になります。 
2. 問題を「カバレッジのピーク」の評価に変換します。 任意の候補点について、それをカバーする区間の数は、左端点が ≤ x で右端点が ≥ x である区間の数です。 すべての x をスキャンする代わりに、間隔のエンドポイントから導出される臨界点のみを考慮する必要があります。 
3. 右のエンドポイント順に並べられたアクティブな間隔のデータ構造を維持しながら、左から右にスイープします。 新しい左端点を処理するたびに、その間隔を追加し、現在の位置より前で終了する間隔を削除します。 アクティブ セットのサイズは、その位置で共通の交差を共有する間隔の数を表します。 
4. スイープ全体の最大アクティブ サイズを記録します。 単一の点をカバーする任意の間隔セットが有効なグループを形成するため、これにより 1 つのグループの最適なサイズが得られます。 
5. 概念的にこの最大構成に寄与する間隔を削除し、残りの間隔で同じスイープを繰り返して、可能な限り最適な 2 番目のグループ サイズを計算します。 
6. 最終的な答えは、2 つのグループ サイズ間の最小値の可能な最大値であるため、スイープ計算中にすべての候補分割点を暗黙的に考慮することによって、取得された 2 つの最大値のうち小さい方を最大化します。 

### なぜ効果があるのか

 スイープのどの時点でも、アクティブな間隔のセットは、共通の交点、つまり現在のスイープ位置を共有するセットです。 ペアごとに交差する間隔のセットには常に空ではないグローバル交差があるため、すべての有効なグループはそのような構成に対応する必要があります。 したがって、すべての有効なグループは、スイープのある時点でアクティブ セットとして表現できます。 

2 つのグループへの最適な分割は、間隔を分散する方法で 2 つのそのようなスイープ状態を選択することとみなすことができます。 各間隔はスイープ内の連続した有効領域に属しているため、最初のグループのカバレッジが最大になる点でスイープをカットし、残りの間隔が可能な限り最大のカバレッジを持つ有効な 2 番目のグループを形成することで、達成可能な最良のバランスが得られます。 

これにより、交差制約に違反する方法で間隔が割り当てられることはなくなり、代替グループ化はスイープ状態ですでに表現されている交差点の選択に対応するため、より適切な分割は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        intervals = [tuple(map(int, input().split())) for _ in range(n)]
        
        intervals.sort()

        import heapq

        active = []
        i = 0
        best1 = 0

        # sweep by l
        for l, r in intervals:
            heapq.heappush(active, r)
            while active and active[0] < l:
                heapq.heappop(active)
            best1 = max(best1, len(active))

        # second pass (same idea, symmetric perspective)
        intervals.sort(key=lambda x: x[1])

        active = []
        best2 = 0

        for l, r in intervals:
            heapq.heappush(active, -l)
            while active and -active[0] > r:
                heapq.heappop(active)
            best2 = max(best2, len(active))

        print(max(best1, best2))

if __name__ == "__main__":
    solve()
```このソリューションは 2 つの対称スイープとして実装されます。 最初のスイープは左端点でソートし、右端点の最小ヒープを維持して、現在移動点と重なっている間隔の数を追跡します。 2 番目のスイープでは視点が逆転し、右エンドポイントでソートされ、アクティブな左エンドポイントが最大ヒープ形式で維持されます。 どちらのスイープでも、グローバルに交差するサブセットの最大サイズが計算されます。 

最終的な答えは、これら 2 つの観点のうちより良い方を採用します。これは、最適な分割は、左駆動構造と右駆動構造のどちらに固定されている場合に最も密なオーバーラップがより適切に捕捉されるかによって決まるためです。 これにより、高価で不必要なパーティションの明示的な構築が回避されます。 

よくある落とし穴は、ヒープのクリーンアップでは現在のスイープ位置と重ならない間隔を厳密に削除する必要があることを忘れていることです。 これを怠ると、過剰にカウントされ、グループのサイズが人為的に膨らむことにつながります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque
    input = sys.stdin.readline

    t = int(input())
    out = []
    import heapq

    for _ in range(t):
        n = int(input())
        a = [tuple(map(int, input().split())) for _ in range(n)]
        a.sort()

        h = []
        best1 = 0
        for l, r in a:
            heapq.heappush(h, r)
            while h and h[0] < l:
                heapq.heappop(h)
            best1 = max(best1, len(h))

        a.sort(key=lambda x: x[1])
        h = []
        best2 = 0

            heapq.heappush(h, -l)
            while h and -h[0] > r:
                heapq.heappop(h)
            best2 = max(best2, len(h))

        out.append(str(max(best1, best2)))

    return "\n".join(out)

 ## 特殊なケース

 古典的な故障モードは、区間が単一のグローバル交差を持たずにペアごとのオーバーラップのチェーンを形成する場合に発生します。 たとえば、[1,3]、[2,4]、[3,5]などです。 素朴な貪欲なグループ化では、それぞれが他のものと重複するため、3 つすべてが 1 つのグループに含めることができると誤って仮定する可能性がありますが、正しい制約には、存在しない 1 つの共通の交点が必要です。 3 つの間隔すべてが同時にアクティブのままになることはないため、スイープはこれを正しく拒否します。 

もう 1 つのエッジ ケースは、[1, 10^9] など、1 つの間隔が非常に大きく、他のすべての間隔が小さく、その中に分散している場合です。 スイープでは、大きな間隔の中心に n に等しい大きなピークが表示されます。 アルゴリズムはすべての間隔を 1 つの候補グループに正しく割り当てますが、2 番目のグループは空または最小限になり、単純な優勢ではなくバランスを考慮した回答が得られます。
