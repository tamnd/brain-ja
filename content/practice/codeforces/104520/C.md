 ## 解決策
 ## 問題の理解

 小文字の英字の上に文字列が与えられ、残りの文字の順序を維持しながら、任意の位置の文字を削除することができます。 回文を形成する可能性のあるすべての部分列の中で、辞書編集的に最大のものを選択する必要があります。 

サブシーケンスは連続している必要はないため、事実上、次数が増加するインデックスのサブセットを選択することになります。 この制約は構造的なものであり、結果の文字列は前方と後方で同じように読み取られる必要があります。 このようなすべての有効な回文部分列のうち、標準辞書の順序で辞書編集的に比較し、最大のものを出力します。 

入力サイズは複数のテスト ケースにわたって大きく、全長は最大 50 万に達します。 これにより、サブシーケンスを列挙したり、すべてのサブ文字列に対して動的プログラミングを試みたりするソリューションは即座に除外されます。 テスト ケースごとに 3 次または 2 次のアプローチでも合格しません。 ソリューションは、文字ごとに線形に近いか、全体的に償却線形である必要があります。 

複数の文字が回文を開始する可能性がある場合、微妙な特殊なケースが発生します。 「利用可能な最大の文字を常に選択する」などの単純な貪欲な選択は失敗します。文字を選択するのが早すぎると、後でより長く有効な回文を形成できなくなる可能性があるためです。 もう 1 つの失敗モードは、常に最長の回文が必要であると仮定することです。 ここで、長さは辞書編集順よりも重要であるため、より大きな文字で始まる場合は、長い回文よりも短い回文の方が優れている可能性があります。 

## アプローチ

 強引な方法では、すべてのサブシーケンスを生成し、回文であるものをフィルタリングして、辞書編集的に最大のものを選択します。 これは、すべての可能性を明示的にチェックするため正しいですが、各文字が含まれるか除外される可能性があるため、指数関数的な時間が必要になります。 回文検証に制限しても、サブシーケンスごとに線形チェックが追加されるため、完全に実行不可能になります。 

最適化するには、サブシーケンスの明示的な構築を避ける必要があります。 重要な構造的観察は、回文はその外側の文字と、中央自体が回文であるという事実によって決定されるということです。 どの文字が最後に現れるかを決定する場合、必要なのは、両側でその文字が一致する箇所を見つけられること、およびそれらの間の部分文字列が有効な回文を許可することだけです。 

これは、最大の文字から最小の文字までの貪欲な戦略につながります。 可能な限り最大の文字を最外層として配置し、残りの区間内で有効な回文構造をサポートできるかどうかを確認することで、辞書編集上最大の回文を構築しようとします。 辞書編集上の順序は最も古い異なる文字によって支配されるため、有効な配置が確認されたら、それをコミットします。 

次に、問題は、セグメント内の制限された文字セットを使用して回文を形成する実現可能性を効率的にチェックすることに帰着します。 これは、各文字の次と前の出現を事前計算することによって処理されるため、一定時間内に境界をジャンプできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのサブシーケンスを列挙する | O(2^n · n) | O(n) | 遅すぎる |
 | 実現可能性チェック + 前処理で貪欲 | O(26・n) | O(26・n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を事前計算する`next_pos[c][i]`そして`prev_pos[c][i]`文字の次と前の出現を見つけることができるようにする`c`位置の周り`i`一定時間内に。 これにより、回文を作成するときに境界を高速に縮小できます。 
2. 2 つのポインターを維持する`l`そして`r`回文を構築しようとしている現在の有効な間隔を表します。 最初は`l = 0`、`r = n - 1`。 
3. キャラクターごとに`c`から`'z'`まで`'a'`、回文の外層として使用してみます。 
4. を使用して検証するには`c`、左端にあるものを見つけます。`c`またはその後`l`そして一番右にあるのは`c`またはその前に`r`。 そのようなペアが存在しない場合は、この文字をスキップします。 
5. 有効なペアが存在する場合、短縮された区間内で回文の形成を継続できるかどうかを確認します。`(l', r')`。 可能であれば、配置を約束します`c`回答の両端で間隔を縮めます`l' + 1`そして`r' - 1`。 
6. このプロセスを繰り返します。常に次から再開します。`'z'`内側の間隔については、外側のすべての位置で辞書編集上最大の選択肢が保証されます。 
7. いつ`l > r`、または有効な拡張が存在しない場合、構築は完了です。 1 文字が中央に残っている場合、それが回文の中心を形成します。 

### なぜ効果があるのか

 各ステップで、有効な回文部分列の現在の最も外側の文字として機能できる最大の文字を選択します。 辞書編集的に大きな解は、分岐する最初の位置で異なる必要があり、常にその位置を貪欲に最大化するため、後で再配置しても小さい選択肢を補うことはできません。 実現可能性チェックにより、残りの間隔内で完全な回文を形成する能力を損なう文字を決してコミットしないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(s):
    n = len(s)

    # next and prev occurrence arrays
    nxt = [[n] * (n + 1) for _ in range(26)]
    prv = [[-1] * (n + 1) for _ in range(26)]

    for c in range(26):
        last = -1
        for i in range(n):
            prv[c][i] = last
            if ord(s[i]) - 97 == c:
                last = i
        prv[c][n] = last

        last = n
        for i in range(n - 1, -1, -1):
            nxt[c][i] = last
            if ord(s[i]) - 97 == c:
                last = i
        nxt[c][0] = last

    l, r = 0, n - 1
    left_part = []
    right_part = []

    while l <= r:
        found = False

        for c in range(25, -1, -1):
            i = nxt[c][l]
            j = prv[c][r]

            if i < j:
                left_part.append(chr(c + 97))
                right_part.append(chr(c + 97))
                l = i + 1
                r = j - 1
                found = True
                break

            if i == j and l <= r:
                left_part.append(chr(c + 97))
                l = r + 1
                found = True
                break

        if not found:
            break

    return "".join(left_part + right_part[::-1])

def main():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        print(solve_case(s))

if __name__ == "__main__":
    main()
```## 実用的な例

 次のような小さな文字列を考えてみましょう`abac`。 

外側のステップでは、次のことを試します。`'c'`、 それから`'b'`、 それから`'a'`。 有効な外部文字は次のとおりです。`'c'`それが内部構造を可能にする形で両端に現れる場合。 一度選択すると、私たちは内側に縮んで繰り返します。 このプロセスにより、実行可能性を維持しながら、辞書編集的な意味ですべての決定が局所的に最適であることが保証されます。 

のような文字列の場合`aaaa`、すべてのステップで常に選択されます`'a'`、中心に到達するまで対称的に縮小します。 これにより、繰り返される同一の文字が単一の最大回文に正しく折りたたまれることが確認されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(26・n) | 各位置は、事前に計算されたジャンプを使用して、最大 26 のチェックで処理されます。 
| スペース | O(26・n) | 次と前の出現テーブルを格納します。 

文字列の合計の長さは最大 50 万であり、各テスト ケースはほぼ直線的な時間で処理されるため、これは制約内で問題なく適合します。
