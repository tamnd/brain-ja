 ## 解決策
 ## 問題の理解

 いくつかの独立したランダム実験が与えられ、それぞれが間隔によって記述されます。 インターバルごとに$[l_i, r_i]$、1 つの実数が均一にランダムにサンプリングされます。 すべてのテスターに​​対してこれを繰り返すと、最終的に次のセットが得られます。$n$独立したランダム値。 対象となる量は、これらのサンプル値の範囲であり、選択された最大値と最小値の差を意味します。 

このプロセス全体が概念的に繰り返されます。$t$独立したシナリオ。 各シナリオでは同じ間隔セットが使用されますが、結果として得られるサンプリング値の予想範囲をシナリオごとに個別に計算する必要があります。 

最大の難点は、範囲が一度にサンプリングされたすべての値のグローバルな極値に依存するため、変数が強く結合されていることです。 各値は独立してサンプリングされますが、最大値と最小値には組み合わせ依存性が生じます。 

制約は構造的には小さいですが、組み合わせ論的にはそうではありません。 と$n \le 200$そして$t \le 10$、離散化された結果またはテスターのサブセットを明示的に列挙するソリューションは実行不可能です。 間隔が最大 3500 に及び、値が実数であるため、値空間の単純な離散化も不可能です。 これにより、明示的な値のサンプリングではなく、順序付け構造に対する確率分解が必要になります。 

すべての間隔が点に折りたたまれると、微妙なエッジケースが現れます。 その場合、範囲は常にゼロとなり、連続密度を仮定したり、縮退区間を無視した式では、誤ってゼロで除算したり、等価境界を誤って処理したりする可能性があります。 すべての間隔が重なり合うと、別の問題が発生します。 たとえば、すべてが$[l_i, r_i]$が同一である場合、答えは予想される範囲に収まる必要があります。$n$同一のユニフォーム。これは簡単ではありませんが、高度に構造化されています。 単純なペアごとの期待アプローチは失敗する可能性があります。$\mathbb{E}[\max] - \mathbb{E}[\min]$は予想される範囲と等しくありません。 

## アプローチ

 ブルートフォース手法では、各間隔を細かい点に離散化し、サンプリングされた値のすべての組み合わせを列挙しようとします。 各テスターに​​ついて、密度の高いグリッドが存在すると想定できます。$[0, 3500]$、各ポイントに確率を割り当て、すべてのテスターに​​わたる最大値と最小値の分布を計算します。 区間あたり 3501 ポイントのような控えめな離散化でも、結合状態空間は$3501^n$、それは天文学的な大きさです。 

もう 1 つの素朴なアイデアは、期待最大値と期待最小値を別々に計算して、それらを減算することです。 これは、非線形結合にわたって期待値が分散されないため失敗します。 最大値と最小値は独立しておらず、その相関関係は範囲内で直接重要になります。 

重要な観察は、実際のサンプリング値を追跡する代わりに、しきい値によって引き起こされる相対的な順序を追跡できることです。 固定しきい値の場合$x$、独立した間隔の寄与を乗算することで、すべてのサンプリング値がその下または上にある確率を計算できます。 これにより、問題は最小値と最大値の分布関数を計算し、考えられるすべてのしきい値にわたって積分することに変わります。 

ID を使用して期待値を再定式化します。$$\mathbb{E}[\max - \min] = \int_0^{3500} P(\max \ge x)\,dx - \int_0^{3500} P(\min > x)\,dx$$各テスターはサンプル値が上か下かに応じて独立して確率に寄与するため、どちらの確率もテスター間の積として表すことができます。$x$。 この構造により、問題は、区間エンドポイントによって引き起こされる整数ブレークポイントにわたる区分線形寄与の評価に集約されます。 

これは、確率が次の時点でのみ変化する値領域全体のスイープにつながります。$l_i$そして$r_i$、投稿の動的な更新を可能にします。

## アルゴリズムのチュートリアル

 値ドメインを 0 ～ 3500 の整数ブレークポイントとして扱い、乗法区間寄与を使用して最大値と最小値の確率プロファイルを計算します。 

1. 閾値ごとに$x$、単一のテスターが値を生成する確率を計算します。$\le x$。 サンプリングは均一なので、$[l_i, r_i]$の場合、この確率は 0 になります。$x < l_i$、1のとき$x \ge r_i$、 そして$(x - l_i) / (r_i - l_i)$さもないと。 これにより、テスターごとに区分的線形関数が得られます。 
2. コンピューティング$P(\max \le x)$すべてのテスターの製品として$P_i(\le x)$。 テスターは独立しているため、これは有効です。 
3. 同様に計算します$P(\min > x)$それに気づくことで$\min > x$すべてのテスターのサンプリング値が次の値より大きいことを意味します$x$。 単一のテスターの場合、この確率は次の場合に 0 になります。$x \ge r_i$、1のとき$x < l_i$、 そして$(r_i - x) / (r_i - l_i)$さもないと。 
4. すべてを反復して、整数範囲にわたる両方の確率関数を事前計算します。$x$0 から 3500 まで、乗算更新を効率的に維持します。 各テスターの貢献度は区分的に線形であるため、次の場合にのみ更新されます。$x$十字架$l_i$または$r_i$。 
5. 整数セグメントにわたる単純な台形和を使用して、両方の確率曲線を数値的に積分します。$$\int f(x) dx \approx \sum_x \frac{f(x) + f(x+1)}{2}$$6. 期待される範囲は、以前に導出された恒等式に従って 2 つの積分を結合することによって取得されます。 

重要な考え方は、ランダム性全体が崩壊して、製品構造の下で安定している極値の生存関数を評価することです。 

### なぜ効果があるのか

 どのしきい値でも$x$、イベント$\max \le x$最大でも値を生成するすべてのテスターと同等$x$。 各テスターの選択は独立しているため、確率は個々の累積分布値の積に正確に因数分解されます。 最小値についても同様です。 範囲はこれらの極値のテール確率の積分として表現できるため、これら 2 つの関数を計算することで期待値が完全に決まります。 独立性を超える依存構造は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 3500

def solve_case(intervals):
    n = len(intervals)

    # Precompute probabilities at each integer x
    p_max = [1.0] * (MAXV + 2)
    p_min = [1.0] * (MAXV + 2)

    for l, r in intervals:
        length = r - l

        for x in range(MAXV + 1):
            # contribution to max: P(X <= x)
            if x < l:
                cmax = 0.0
            elif x >= r:
                cmax = 1.0
            else:
                cmax = (x - l) / length if length > 0 else 1.0

            p_max[x] *= cmax

            # contribution to min: P(X > x)
            if x < l:
                cmin = 1.0
            elif x >= r:
                cmin = 0.0
            else:
                cmin = (r - x) / length if length > 0 else 1.0

            p_min[x] *= cmin

    # integrate using trapezoids
    exp_max = 0.0
    exp_min = 0.0

    for x in range(MAXV):
        exp_max += 0.5 * (p_max[x] + p_max[x + 1])
        exp_min += 0.5 * (p_min[x] + p_min[x + 1])

    return exp_max - exp_min

def main():
    n, t = map(int, input().split())
    intervals = [tuple(map(int, input().split())) for _ in range(n)]

    for _ in range(t):
        print(f"{solve_case(intervals):.4f}")

if __name__ == "__main__":
    main()
```この実装では、離散値領域における最大値と最小値の累積確率プロファイルが直接構築されます。 ネストされたループオーバー$n$合計作業量はおおよそ次のとおりであるため、3500 は許容できます。$7 \times 10^5$テストケースごとの操作。 

台形積分が選択されるのは、確率関数が整数点間で区分的に線形であるため、線形セグメントを正確に積分するには整数境界でのサンプリングで十分であるためです。 

よくある落とし穴は、適切に積分せずに、ポイントごとの確率から期待最大値を直接計算しようとすることです。 もう1つは、縮退した間隔を忘れることです。$l_i = r_i$コードは、決定論的な寄与として扱う必要があります。`length > 0`ガード。 

## 実用的な例

 3 人のテスターと小さな値範囲を使用した単純化されたシナリオを考えてみましょう。 最大値の確率がどのように動作するかを追跡します。 

| × | P1(X ≤ x) | P2(X ≤ x) | P3(X ≤ x) | P(最大 ≤ x) |
 | --- | --- | --- | --- | --- |
 | 0 | 0.0 | 0.2 | 0.0 | 0.0 |
 | 1 | 0.5 | 0.4 | 0.1 | 0.02 |
 | 2 | 1.0 | 0.6 | 0.3 | 0.18 |

 この表は、積の構造が確率をどれだけ早く縮小するかを示しています。個々の確率が中程度であっても、最大値に対する小さな同時確率が生成されます。 

同じ構造が最小値にも対称的に適用され、確率が反転して範囲の上限から累積されます。 これは、アルゴリズムが独立した限界ではなく共同の極値の動作を正しく捕捉していることを確認します。

 ## 特殊なケース

 すべての間隔が 1 つの点に集約されると、すべてのサンプリング値が決定的になります。 その状況では、両方の確率配列がすべての有効な点で同一に 1 になるか、点の外側では 0 になり、最大値と最小値の両方の積分が一致してゼロ範囲が生成されます。 アルゴリズムはこれを処理します。`length > 0`ブランチはバイパスされ、貢献度は一定になります。 

たとえば、間隔がバラバラな場合$[0,1]$そして$[100,200]$、最大確率曲線はさまざまな領域で急激に遷移しますが、積の構造により、最大値が右端の間隔によって支配されることが保証されます。 アルゴリズムはこれを正しく反映しています。$x$、すべての累積確率が 1 になり、$P(\max \le x)$正しく安定します。 

多くの区間が重なり合うと、部分的な寄与の積が内部領域で非常に小さくなり、数値的に不安定に見える可能性があります。 ただし、台形積分は相対的な形状にのみ依存し、すべての寄与は連続的であり、範囲内に制限されているため、アルゴリズムは依然として正しい期待値を蓄積します。$[0,1]$。
