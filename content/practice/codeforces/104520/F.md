 ## 解決策
 ## 問題の理解

 一連の値を固定の順序で処理しています。 スコアは 0 から始まり、シーケンス内の値ごとに、その値を現在のスコアに加算するか、現在のスコアに乗算するかを即座に決定する必要があります。 ポジションが決定されると、後で変更することはできず、次の値に進みます。 

目標は、すべての値を処理した後の最終スコアを最大化することです。 

テスト ケースあたりの要素数の制約は最大 100 と小さいですが、テスト ケースは最大 10,000 個まで存在する可能性があります。 この組み合わせは、テスト ケースごとに 2 次作業を行うあらゆるソリューションが許容される一方で、指数関数的なソリューションはすべて許容されることを意味します。$N$剪定しても無理でしょう。 

重要な問題は、乗算が符号と大きさと強く相互作用することです。 負の値を指定すると、累積結果全体の符号が反転する可能性があり、初期に大きな正の値を指定すると、将来の選択が大幅に増幅される可能性があります。 特定のステップで乗算と加算のどちらが大きいかに基づいて局所的に決定する単純な貪欲なアプローチは失敗します。 

単純な失敗例は、初期の乗算によって負の中間結果が作成され、後で非常に大きなゲインが可能になる場合に発生します。 

入力:```
3
-2 -2 100
```初期の値を貪欲に追加し、局所的に有益と思われる場合にのみ乗算すると、初期の乗算を避けて小さな結果で終わる可能性がありますが、最適な戦略は、後の乗算が優先されるように、慎重に大きな大きさを早期に作成することです。 

もう 1 つの微妙な問題は、ゼロが乗算のリセットのように動作することです。 ゼロを乗算すると、将来の増幅の可能性がすべて破壊されるため、正しい戦略ではゼロを構造的なブレークポイントとして扱う必要があります。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべての選択シーケンスをシミュレートします。 各位置で加算または乗算すると、次のようになります。$2^N$テストケースごとの可能性。 のために$N = 100$、これはまったく実行不可能です。$2^{30}$すでに州の数は 10 億を超えており、中間の整数増加を維持する必要もあります。 

問題の構造は、動的計画法による定式化を示唆しています。 各インデックスでは、考えられる計算のすべての「状態」に対して達成可能な最高のスコアを維持します。 ただし、状態空間は単なるインデックスではなく、現在の値であるため、無制限の増加により値に対する単純な DP は不可能になります。 

重要な観察は、スコアは入力シーケンスから構築された線形式ですが、各項が製品チェーンの一部になるか、単に追加されるかが動的に選択されることです。 最適な戦略は、配列をセグメントに分割するものと解釈できます。セグメント内では乗算チェーンを効果的に選択し、セグメント間では加算によってリセットします。 

より具体的には、加算を選択する点を固定すると、乗法相互作用の観点から、その前のすべてはその後のすべてから独立します。 これは、「乗算チェーン」で終わる最良の結果と「クローズド加算状態」で終わる最良の結果を追跡するポジション全体で DP を維持できることを示唆しています。 

各ステップで、2 つの意味のある解釈が得られます。 

次の値を乗算して実行中の乗算チェーンを拡張するか、チェーンを切断して現在の寄与を最終結果に追加してチェーンの状態をリセットします。 

これにより、問題は位置ごとの状態の数が一定に減ります。

 ## アルゴリズムのチュートリアル

 配列を左から右にスキャンする間、2 つの値を維持します。 

以前のすべての貢献を最終合計にすでに「コミット」している場合、1 つの値は最高のスコアを表します。 もう 1 つは、まだ答えが完成していないアクティブな乗算チェーンの最良の値を表します。 

また、初期化前の乗算は初期化後の乗算とは異なる動作をするため、チェーンを開始したかどうかも追跡します。 

### ステップ

 1. 最良の最終スコアがゼロであり、アクティブなチェーンが存在しない DP 状態を初期化します。 
2. 各値について$a_i$では、乗算チェーンを開始または拡張するか、チェーンを終了して現在の寄与を追加するという 2 つのアクションを検討します。 
3. 位置でチェーンを開始する場合$i$、チェーン値を次のように設定します。$a_i$または、現在のチェーンが存在する場合は、その製品に接続します。 
4. チェーンを拡張するときは、チェーンの値に次の値を乗算して更新します。$a_i$。 これは、連続した乗算ブロックを構築しているという考えを表しています。 
5. 各位置で、チェーンの切断も考慮します。現在のチェーン値を最終的なスコアに追加し、チェーンをリセットします。 
6. 答えは最終的なスコアを超える最大値であり、最後のチェーンを閉じて終了する場合です。 

### なぜ効果があるのか

 不変条件は、処理後の位置です。$i$、DP は、プレフィックスを乗算チェーンと最終的な加算の交互のセグメントに分割するすべての最適な方法を正しく表します。 すべての乗算の決定は連続した領域内で結合的であり、その領域を破ることはその境界で加算を選択することと同等であるため、最適な解はそのようなセグメントに分解できます。 DP は有効なセグメンテーション パターンごとに可能な限り最良の結果を暗黙的に保持するため、最適な構造が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(a):
    n = len(a)
    
    # dp0: best finalized score so far
    # dp1: best value of active multiplication chain
    dp0 = 0
    dp1 = None  # no chain yet
    
    for x in a:
        new_dp0 = dp0
        
        # Option 1: extend or start chain
        if dp1 is None:
            new_dp1 = x
        else:
            new_dp1 = dp1 * x
        
        # Option 2: break chain and add it to result
        if dp1 is not None:
            new_dp0 = max(new_dp0, dp0 + dp1)
        
        # Option 3: start new chain at current position
        new_dp1 = max(new_dp1, x)
        
        dp0, dp1 = new_dp0, new_dp1
    
    if dp1 is not None:
        dp0 = max(dp0, dp0 + dp1)
    
    return dp0

def main():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        out.append(str(solve_case(a)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```コードは 2 つの進化する量を維持します。`dp0`は、以前のすべての演算が加算として最終的に完了した場合の最良のスコアを表します。`dp1`は、現在アクティブな乗算チェーンを表しますが、後で拡張または閉じられる可能性があります。 

各ステップで、乗算チェーンを拡張するか、現在の要素から再起動します。 チェーンを閉じて、最終的なスコアに追加するオプションもあります。 注意すべき点は、チェーンの継続と終了の両方を検討する前に、チェーンを早まって破棄しないようにすることです。そのため、割り当ての前に両方の遷移が計算されます。

 ## 特殊なケース

 単一要素の配列は、ゼロから開始すると加算と乗算の両方が同じ値を生成するため、自明です。 DP はチェーンを正しく初期化し、その値をすぐに返します。 

すべてゼロの配列はすべての乗算チェーンを強制的に崩壊させ、アルゴリズムはチェーンを繰り返し再起動することで負の構造や不安定な構造の作成を正しく回避します。 

完全に負の配列は、乗算が符号を交互に行うため、最もデリケートなケースです。 中間の否定性がすぐにはコミットされず、有益な場合にのみ閉じられるため、DP はチェーンを拡張し続け、最終的に完全な生成物をキャプチャします。 

混合符号配列のような`10 -1 10`なぜ貪欲に失敗するのかを説明します。 このアルゴリズムは、最初にチェーンを構築し、符号を 1 回反転してから、正しく再起動して 2 番目の乗算セグメントを最大化し、より大きな最終スコアを生成します。
