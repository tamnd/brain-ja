 ## 解決策
 ## 問題の理解

 各クエリでは 3 つの数値が得られます$x$、$y$、 そして$z$。 整数を選択できます$v$範囲内で$0 \le v < z$。 選ばれたその人のために$v$、シフトされた 2 つの値を評価します$x+v$そして$y+v$、ビット単位の XOR をとり、すべての有効な値の最大値を求めます。$v$。 

したがって、各テスト ケースでは、両方の数値を同じ量だけ、ただし制限されたウィンドウ内でのみスライドさせたときに、それらの XOR がどのくらい大きくなるかを尋ねます。 

制約$t \le 2 \cdot 10^5$各クエリをサブリニア時間または対数時間で処理するように強制します。 全体にわたるリニアスキャン$v$それは不可能ですので$z$まで可能です$10^8$すべてのテスト ケースを合計すると、$10^{13}$最悪の場合の運用。 

素朴な試みはすべてを試してみることです$v$、計算する$(x+v) \oplus (y+v)$、最大値を追跡します。 これは直ちに実行不可能です。 

それほど明らかではない落とし穴は、単調性を仮定することから生じます。 たとえば、$x = 7$、$y = 5$、小さな変化$v$キャリーにより複数の下位ビットが反転し、XOR がスムーズに動作せずに発振する可能性があります。 そのため、貪欲なローカル決定は信頼できなくなります。 

もう一つの微妙なケースは次のような場合です。$x = y$。 それから$(x+v) \oplus (y+v)$に関係なく常にゼロです$v$したがって、価値観間の「分離を増やす」ことができると仮定した戦略は完全に失敗します。 

## アプローチ

 ブルートフォースアプローチはすべてにわたって繰り返されます$v < z$、XOR を計算し、最大値を取得します。 これは、実現可能な領域全体を探索するため、正しいです。 ただし、その複雑さは、$O(z)$テストケースごとに、次のようになります$O(tz)$全体として、限界をはるかに超えています。$z$到達する$10^8$。 

重要な観察は、式が加算の中でキャリーがどのように伝播するかのみに依存するということです。$x+v$そして$y+v$。 同じ$v$は両方の番号に同様に影響を与えるため、事実上、次のプレフィックス構造を選択しようとしています。$v$これは、2 つの合計間のビットの不一致を最大化します。 

バイナリ接頭辞の観点から変換を書き直すと、問題は簡単になります。 追加すると$v$両方に$x$そして$y$、結果の値間の違いは、各ビット位置でのキャリーの違いのみに依存します。 これは、最上位ビットから下に向かってビットごとに構築し、ビットを設定できるかどうかを決定することを示唆しています。$v$を尊重しながらより大きな XOR を強制する$v < z$。 

これをビット上の数字 DP としてモデル化できます。$v$、私たちがまだ制限されているかどうかを追跡します$z$、そして同時に進化する部分を追跡します$x+v$そして$y+v$キャリー状態も含みます。 キャリーは数値ごとに 0 または 1 のみであるため、各状態は小さくなります。 

これにより、各テスト ケースが最大 31 ビットにわたる定数係数 DP に削減されます。

 ## アルゴリズムのチュートリアル

 関連する最上位ビットから 0 までビットを処理します。各ビット位置について、キャリーへのキャリーを維持します。$x$そして中に$y$、および接頭辞が$v$はすでに接頭辞よりも厳密に小さくなっています$z$。 

1. 代表する$x$、$y$、 そして$z$バイナリでは、最上位ビットまでの十分なビットを考慮して、$z$。 キャリー用の予備ビットも1本付属します。 これにより、すべてのオーバーフロー効果が確実に捕捉されます。 
2. ビット位置で DP 状態を定義します。$i$として$(cx, cy, tight)$、 どこ$cx$への持ち込みです$x+i$、$cy$への持ち込みです$y+i$、 そして$tight$プレフィックスが次のいずれかであるかどうかを示します。$v$はまだ接頭辞と同じです$z$。 これは重要です。なぜなら、一度下に行くと、$z$、以降のすべての部分$v$自由になる。 
3. 各状態とビットについて$v_i \in \{0,1\}$、次のように計算します。 

結果として得られるビット$x+v$位置にある$i$、結果として得られるビット$y+v$位置にある$i$、次はキャリー$cx'$、$cy'$。 

このビットの XOR 寄与は次のとおりです。$(bit_x \oplus bit_y) \ll i$。 これを DP 値に累積します。 
4. 結果として生じる接頭辞が次のような遷移のみを許可します。$v$を超えない$z$。 もし$tight$それは本当です、それでは$v_i$によって制限されています$z_i$; それ以外の場合は両方の選択肢が許可されます。 

これにより、無効なデータを構築することがなくなります。$v$。 
5. すべてのビットを処理した後、すべての端末状態にわたる最大 DP 値を取得します。 

重要な詳細は、キャリーの伝播がローカルであるということです。各ビットは前のキャリーと現在のキャリーにのみ依存します。$v_i$、そのため、DP は一定のサイズのままになります。 

### なぜ効果があるのか

 すべてのビット位置で、DP は将来の動作に影響を与えるすべての情報を完全にキャプチャします。$x+v$そして$y+v$、そしてまだ接頭辞によって制約されているかどうか$z$。 同じ状態を持つ 2 つの部分構造は、同じ将来の可能性と貢献を生み出します。 これにより、DP 状態が十分になり、以前のビットからの隠れた依存関係が防止され、最適な部分構造が確実に保持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(x, y, z):
    B = 31  # enough for values up to 1e8

    # dp[pos][cx][cy][tight]
    dp = [[[[ -1 for _ in range(2)] for _ in range(2)] for _ in range(2)] for _ in range(B+1)]
    dp[0][0][0][1] = 0

    for i in range(B):
        xi = (x >> i) & 1
        yi = (y >> i) & 1
        zi = (z >> i) & 1

        for cx in range(2):
            for cy in range(2):
                for tight in range(2):
                    if dp[i][cx][cy][tight] < 0:
                        continue

                    base = dp[i][cx][cy][tight]

                    for vi in range(2):
                        if tight and vi > zi:
                            continue

                        ntight = tight and (vi == zi)

                        sx = xi + vi + cx
                        sy = yi + vi + cy

                        bx = sx & 1
                        by = sy & 1

                        ncx = sx >> 1
                        ncy = sy >> 1

                        val = base + ((bx ^ by) << i)

                        if dp[i+1][ncx][ncy][ntight] < val:
                            dp[i+1][ncx][ncy][ntight] = val

    return max(dp[B][cx][cy][tight]
               for cx in range(2)
               for cy in range(2)
               for tight in range(2))

def main():
    t = int(input())
    out = []
    for _ in range(t):
        x, y, z = map(int, input().split())
        out.append(str(solve_case(x, y, z)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```このソリューションでは、ビット位置、各合計へのキャリー、および$v$まだ接頭辞によって制約されています$z$。 各遷移では、現在のビットを設定しようとします。$v$それに応じて両方の合計を更新し、整数加算を通じてキャリーを自然に伝播します。 

キャリーが固定されると各ビット位置は独立するため、XOR 寄与は各ビットで直接累積されます。 

最終的な答えは、すべてのビットを処理した後のすべての有効な端末状態の最大値です。

        res = []

            B = 31

                yi = (y >> i) & 1
                zi = (z >> i) & 1

 ## 特殊なケース

 いつ$x = y$、すべての DP 遷移は両方の合計に同一の値を生成するため、すべての XOR 寄与はすべてのビットでゼロになります。 DP はゼロ値をすべての状態に正しく伝播し、最終的な最大値はゼロのままです。 

いつ$z = 1$、 のみ$v = 0$許可されています。 DP はすべてのビットで厳しい制約を適用し、単一の有効なプレフィックスを超える遷移を決して許可しないため、答えは次のようになります。$x \oplus y$ゼロシフトで直接評価されます。 

いつ$z$が大きいと、タイトな状態はすぐに解放され、DP はキャリー構成に対する制約のない最大化のように動作します。 これにより、ソリューションは、キャリーによって引き起こされるすべての可能な XOR 増幅を制限なく探索できるようになります。
