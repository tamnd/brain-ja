 ## 問題の理解

 隠された正の整数が与えられます$x$、そしてそれについてヒントの形で質問することが許可されています。 各手がかりは 2 つの整数を選択します$a$そして$b$、絶対的な違いがあるかどうかがわかります。$|a-b|$で割り切れます$x$か否か。 言い換えれば、各クエリは次のことのみを明らかにします。$x$特定の整数の約数です$d = |a-b|$。 

目標は計算することではありません$x$インタラクティブなクエリを使用して、事前にそのような手がかりの固定セットを設計します。 すべての答えを確認した後、次の値が 1 つだけ存在する必要があります。$x$すべての回答に一致する有効な範囲内です。 また、必要な手がかりの数を最小限に抑え、そのようなセットを明示的に構築することも求められます。 

したがって、実際のタスクは整数をエンコードすることです$x \le 10^6$選択した差に対して、少数の可算性または非可分性テストのセットを使用します。 

制約$t \le 10^3$これは、各テストを独立して構築する必要があることを意味しますが、それぞれの構築は最大でも小さくなければなりません$10^3$手がかり。 各手がかりは単なる算術出力であるため、事実上、$O(1)$または非常に小さい$O(\log x)$テストケースごとに構築します。 

素朴な考えは、周囲の数字の可能な約数をすべて「調査」しようとすることです。$x$しかし、それはすぐに問題になります。$x$直接的には明らかにされていない。 選択した整数の割り算については、「はい」または「いいえ」の答えしか得られません。 問題は、さまざまな値が存在することです。$x$それらの制約が慎重に構造化されていない限り、小さな分割制約のセットについて合意することはできません。 

少数の固定数の割り算情報のみを使用する場合、微妙なエッジケースが発生します。 たとえば、次のことだけをテストすると、$x$6、10、15 を除算し、次のような複数の値を返します。$x=1$そして$x=5$は異なる動作をする可能性がありますが、分離システムを慎重に設計しない限り、依然として多くの合成数が衝突します。 問題は、割り算の制約によって約数のセットが定義され、これらのセットを単一の整数まで交差する必要があることです。 

## アプローチ

 重要な観察は、それぞれの手がかりが事実上「」という形式のステートメントであるということです。$x$分割する$d$" または "$x$分けない$d$"。 以来$d$を通じて完全に当社の管理下にあります$|a-b|$、私たちは実際に可分性述語を介した意思決定システムを構築しています。 

強引なアイデアは、次のすべての候補値を試してみることです。$x$そして、考えられる手がかりのセットごとに、どの値が一貫性を保っているかを確認します。 これは、最大サイズの宇宙を構築することを意味します。$10^6$そしてそれを繰り返しフィルタリングします。 それぞれの手がかりが候補者の半分を除外したとしても、まだ約$\log_2(10^6)\approx 20$慎重に選択されたバイナリ分割ですが、分割可能性は独立したビットのように動作しないため、分割可能性の制約を超えてそのような分割を設計することは自明ではありません。 

重要な構造的洞察は、数値で割り切れるということは、約数セットのメンバーシップと同等であるということです。 慎重に選択した素数または構造化された整数の積である差分を選択すると、強制的に次のようにすることができます。$x$その要因パターンを明らかにします。 特に、慎重に選択したモジュライの下での剰余を使用して数値を区別する問題に問題を縮小したいと考えています。 

強力な単純化は、任意の整数に対して次の事実を利用することです。$d$、どちらかを強制できます$x \mid d$または$x \nmid d$。 2 のべき乗または階乗のような増加をエンコードする差分を選択すると、次のバイナリ エンコードを強制できます。$x$構築された倍数との比較を通じて。 

この問題で使用される構築戦略は、分離することです。$x$固定基数から導出された慎重に選択された連続する整数のセットに対して割り算をテストすることによって。 周りの数字に対して割り算をクエリすることによって$x$かどうかを効果的に判断します。$x$構築されたシステムの gcd に等しい。 ピン留めすることで一意性を強制できるため、最小限の構造では、慎重に選択された一定数の差異が必要になります。$x$慎重に構造化された 2 つまたは 3 つの制約に対して。

 ## アルゴリズムのチュートリアル

 使用される構造は非常に小さく、テスト ケースごとに 2 つの手がかりが出力されます。 

私たちはそのアイデンティティを悪用します$x$ペアによって一意に決定されます$(x, 2x)$可算性の動作の観点から。 

1. 私たちが選択します$a = x+1$そして$b = 1$、したがって、違いは次のとおりです$d_1 = x$。 

これにより、完璧な「陽性テスト」が得られます。$x \mid d_1$は常に true ですが、これより小さい整数は、すべての構築された制約の組み合わせに対してこのように動作しません。 
2. 私たちが選択します$a = 1$そして$b = x+1$、与える$d_2 = x$繰り返しになりますが、システム全体で一致しない 2 番目の制約と組み合わせることで解釈を反転します。 

ただし、実際に値を分離するより堅牢な構造は、次の 2 つの違いを使用することです。 

私たちは、次のようにして割り切りを強制します。$x$既知の倍数の場合、および割り切れない場合$x+1$。 

1. 設定します$d_1 = x$、確保する$x$それを分割します。 
2.設定します$d_2 = x+1$、保証のみ$x=1$これにより、最初の制約構造と組み合わせると、すべてのケースが明確になります。 

実際には、クリーンな最小限の構造は次のとおりです。 

2 つの手がかりを出力します。 

- 違いのあるもの$d = x$(常に割り切れます)
 - 違いのあるもの$d = x+1$分割不可能としてマークされる

 これにより、$x$除算と一致する正確な整数になるようにする$d$しかし分けていない$d+1$、一意に固定します$x$。 

なぜ機能するのか: すべての整数のうち、真のものだけが有効$x$それが分かれば満足するだろう$x$しかし分けません$x+1$。 他の候補者$y \ne x$どちらかの理由で失敗します$y \nmid x$または$y \mid x+1$両方の制約にわたって、すべての不正確な候補を同時に削除することはできません。 この組み合わせにより、単一の固定点が分離されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        x = int(input())
        
        # Two clues:
        # 1) difference x -> always divisible by x
        # 2) difference x+1 -> not divisible by x
        print(2)
        print(x + 1, 1, 1)
        print(1, x + 1, 0)

if __name__ == "__main__":
    solve()

注意が必要なのは、$a, b \le 10^9$、したがって、を使用して$x+1$安全なので$x \le 10^6$。 また、手がかりの数は制限を大幅に下回る 2 に固定します。

 ## 特殊なケース

 いつ$x = 1$、すべての整数は次で割り切れます。$x$したがって、両方の手がかりは事実上、可分性に関する些細な真実に帰着します。 この構造では引き続き有効なトリプルが出力され、矛盾は生じません。$c=0/1$すべての整数が 1 で割り切れる場合、実現可能性は変わりません。 

いつ$x$で最大です$10^6$、構築された違い$x+1$までの許容座標範囲内に留まります$10^9$したがって、オーバーフローや無効な入力は発生しません。 2 番目の手掛かりは依然として非分割性を正しく主張しています。これは次の理由により成立します。$10^6$分けない$10^6+1$。 

次のような非常に小さな複合値をテストする場合$x=2$または$x=4$、この構造により、両方の可分性制約の唯一の一貫した解釈が意図したものであることが保証されます。$x$なぜなら、選択された連続差分のペアに対する両方の制約を同時に満たす整数は他にないからです。
