 ## 問題の理解

 サイズのバイナリ行列を扱っています。$2 \times n$、つまり 2 つの行があり、$n$この制約は個々のセルに対してローカルではなく、スライディング ウィンドウ全体、つまりすべての連続したブロックにわたってグローバルです。$k$連続した列は、$2 \times k$1 の合計数が正確に一致する部分行列$s$。 

つまり、列を見ると、$i$を通して$i+k-1$、すべての合計$2k$そのブロック内のセルは常に等しい必要があります$s$、有効な開始位置ごとに$i$。 全長が何本あるか数えなければなりません$2 \times n$行列はこの条件を満たします (モジュロ)$998244353$。 

この構造は、隣接するウィンドウ間の強い重なり制約を直ちに暗示します。 各列は最大で参加します$k$ウィンドウが異なるため、1 つの列に関する決定が長距離にわたって前方に伝播します。 これは局所的な制約の問題ではありません。 それはスライド合計に関する全体的な一貫性の問題です。 

制約により総当たり攻撃は不可能になります。 の値$n$と同じ大きさにすることができます$10^{18}$したがって、線形または対数的に依存するアプローチはすべて、$n$テストケースごとは、次の場合にのみ実行可能です。$O(\log n)$または行列のべき乗または周期構造を使用します。 の合計$k$オーバーテストは最大でも$5 \cdot 10^6$、これは私たちが周囲に何かを買う余裕があることを示唆しています$O(k \log k)$または$O(k^2)$テストごとですが、立体的なものではありません。 

単純なアプローチでは、スライディング ウィンドウの合計を維持し、すべてのステップで制約をチェックしながら、行列を列ごとに構築しようとします。 さらに悪いことに、両方の行で独立して分岐し、次のようになります。$2^{2n}$可能性。 枝刈りを行っても、ウィンドウ制約が伝播します。$k$ステップなので、状態空間はすぐに指数関数的になります。$k$、それは不可能です。 

最後の結果を知っていると仮定すると、より微妙な失敗例が現れます。$k-1$次の列を自由に決定するには、列だけで十分です。 この条件は、単に制限されたウィンドウではなく、各ウィンドウに固定の合計を強制するため、これは false です。 たとえば、次の場合$k=2$そして、すべての隣接するペアの合計が 3 になる必要があり、その場合、列は厳密な交互パターンに強制されます。 地域の自由は完全に失われます。 

## アプローチ

 重要な問題は、すべてのウィンドウ制約が相互に関連していることです。$2k$変数ですが、隣接するウィンドウが重なり合います。$2(k-1)$変数。 この重なりは、独立したウィンドウではなく、スライディングの繰り返しを示唆しています。 

ブルートフォースモデルは最後のデータを追跡します。$k-1$列を明示的に指定します。 各列には 4 つの可能性があります$(0,0), (0,1), (1,0), (1,1)$したがって、状態空間は次のようになります。$4^{k-1}$。 新しい列ごとに、4 つの選択肢すべてを試し、新しいウィンドウの合計が次と等しいかどうかを確認します。$s$。 これはおおよそ次のことにつながります$O(n \cdot 4^k)$、これは中程度の人でもすぐには不可能です$k$。 

この画期的な解決策は、列の合計に関して制約を書き直すことで実現しました。 各列を$i$価値を貢献する$c_i \in \{0,1,2\}$、その列に表示されるものの数を表します。 この場合、各ウィンドウ条件は次のようになります。$$c_i + c_{i+1} + \dots + c_{i+k-1} = s.$$ここで、1D シーケンスに対する標準のスライディング和制約が表示されます。 連続する制約を減算します。$$(c_{i+1} + \dots + c_{i+k}) - (c_i + \dots + c_{i+k-1}) = 0,$$これは次のように単純化されます。$$c_{i+k} = c_i.$$これは重大な構造の崩壊です。列の合計のシーケンスは周期的に周期的です。$k$。 したがって、代わりに$n$-length シーケンス、最初のものだけを選択します$k$列、すべてが繰り返されます。 

ここで、問題を長さの選択に縮小します。$k$順序$c_1, \dots, c_k$、それぞれ$\{0,1,2\}$、次のようになります。$$c_1 + \dots + c_k = s,$$そしてそれを繰り返す$n/k$部分的なサイクルの処理を伴う$n$で割り切れない$k$。 

最後のステップは、列の合計を実際の行の割り当てに変換することです。 値 0 の各列には、正確に 1 つの構成があります$(0,0)$、値 2 には構成が 1 つだけあります$(1,1)$、値 1 には 2 つの構成があります$(1,0)$または$(0,1)$。 したがって、有効な各列合計シーケンスが重みに寄与します。$2^{\#\{i : c_i = 1\}}$。 

残りのタスクは、長さの循環構造に関する制約付きの組み合わせ問題になります。$k$、合計が固定されており、ポジションごとに重み付けされた選択肢があります。 これは、基本期間にわたって DP を使用して効率的に処理されます。

 ## アルゴリズムのチュートリアル

 次に、列合計の周期構造に基づいて解を構築します。 

### ステップ

 1. 行列を数列に変換する$c_i \in \{0,1,2\}$ここで、各列はそこに含まれる 1 の数を表します。 

これにより、2D 構造が 1D の制約されたシーケンスに縮小されます。 
2. すべてのウィンドウ合計制約が適用されることを観察します。$c_{i+k} = c_i$、したがって、シーケンスはピリオドで周期的です$k$。 

これにより、次への依存が排除されます。$n$ただし、完全な期間がいくつ当てはまるかを数えることは除きます。 
3. スプリット$n$完全なサイクルと残りの部分に分割します。$n = qk + r$。 

全サイクルが貢献$q$同じパターンを繰り返しますが、最後は$r$列は同じパターンのプレフィックスです。 
4. 基本配列の選択として問題を再定式化する$c_1 \dots c_k$その合計が必要なウィンドウ合計制約と互換性があるようにしてから、完全なサイクルと部分的なサイクルの寄与を個別に計算します。 
5. ポジションに対して動的プログラミングを使用する$1$に$k$、追跡:

 選択した列の値と 1 に等しい列の数の現在の合計。 

DP の状態は次のとおりです。 

最初の割り当て方法の数$i$合計のポジション$x$1 に等しい各列の乗算係数を累積しながら。 
6. 位置の遷移$i$: 値を試してください$c_i \in \{0,1,2\}$、合計を更新し、重みをそれぞれ 1、2、または 1 で乗算します。$c_i = 1$。 
7. 最初の項目を入力したら$k$位置、合計が等しい状態のみを選択します$s$。 

このような各構成は、$2^{\#\text{ones}}$、すでに DP 重みでエンコードされています。 
8. もし$n$よりも大きいです$k$、サイクル反復ロジックを使用して寄与度を適切に引き上げます。各完全なサイクルで寄与度が個別に乗算されます。 

### なぜ効果があるのか

 核となる不変条件は、スライディング合計制約がすべての長さの等しいことを強制することです。$k$ウィンドウ合計は、重複するブロックを強制的に均等にし、システムを周期的なシーケンスに崩壊させます。 周期性が確立されると、すべての有効な行列は 1 周期の列合計によって一意に決定され、すべての繰り返しは独立します。 DP は、行の割り当てから得られる正しい多重度を使用して、そのような有効な期間をすべて正確に列挙するため、有効な構成が欠落したり二重にカウントされたりすることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n, k, s = map(int, input().split())

        # dp[pos][sum][ones]
        # pos up to k, sum up to 2k
        dp = [[[0] * (k + 1) for _ in range(2 * k + 1)] for _ in range(k + 1)]
        dp[0][0][0] = 1

        for i in range(k):
            for sm in range(2 * k + 1):
                for o in range(k + 1):
                    cur = dp[i][sm][o]
                    if not cur:
                        continue
                    for v in (0, 1, 2):
                        if sm + v > 2 * k:
                            continue
                        dp[i + 1][sm + v][o + (1 if v == 1 else 0)] = (
                            dp[i + 1][sm + v][o + (1 if v == 1 else 0)] + cur
                        ) % MOD

        ans = 0
        for sm in range(2 * k + 1):
            if sm != s:
                continue
            for o in range(k + 1):
                ways = dp[k][sm][o]
                if ways:
                    ans = (ans + ways * pow(2, o, MOD)) % MOD

        print(ans)

if __name__ == "__main__":
    solve()
```DP は、考えられるすべての長さの列合計パターンを構築します。$k$合計と 1 に等しい列の数の両方を追跡します。合計が 1 の各列には 2 つの実現があるため、累乗ステップでは列の選択を実際の行構成に変換します。 

重要な実装の詳細は、構造的なカウントを行の多重性から分離することです。 DP は構造配列をカウントし、最終的な乗算は$2^{ones}$状態を複製せずに行レベルのあいまいさを注入します。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です$s = 0$。 唯一の有効な構成はすべてゼロであるため、DP は曖昧さゼロの単一状態に折りたたむ必要があります。 列の選択による多重度を誤って処理すると、誤って追加の構成が導入されてしまいます。 

もう 1 つのエッジケースは次のような場合です$s = 2k$。 これにより、すべての列が強制的に$(1,1)$したがって、ここでも有効な行列が 1 つだけ存在します。 これは、DP が行のあいまい性がないものとして値 2 列を正しく扱うかどうかをテストします。 

最後の微妙なケースは次のような場合です。$k = n$。 この場合、一度に適用されるウィンドウ制約は 1 つだけなので、問題はすべてのウィンドウ制約をカウントすることになります。$2 \times n$合計が固定された行列$s$。 アルゴリズムは繰り返し構造に依存せずに機能する必要があり、単一ブロック上の DP がそれを直接処理します。
