 ## 解決策
 ## 問題の理解

 軸に揃えられた一連の長方形が与えられます。 各四角形はギフトを表しており、その右側の境界によって降順でない順序ですでに並べ替えられています。 これらの長方形の接頭辞ごとに、一連の素な「折り返し長方形」を使用して、その接頭辞内のすべての長方形をカバーする必要があります。 これらのラッパーは任意に選択できますが、互いに重なり合うことはできず、すべてのギフトの四角形は 1 つのラッパー内に完全に収まる必要があります。 各プレフィックスの目標は、すべてのラッパーの合計領域を最小限に抑えることです。 

したがって、位置 i で終わるすべてのプレフィックスについて、基本的に最初の i 個の四角形をグループに分割します。各グループは独自の境界四角形で囲まれており、これらの境界領域の合計ができるだけ小さくなるようにします。 

n が 100000 までの制約により、プレフィックス状態間の 2 次または 3 次遷移が強制的に回避されます。 すべての i に対して最適なパーティションを最初から再計算しようとするソリューションは、テスト ケースあたり O(n²) でさえすでに制限を何桁も超えているため、すぐに失敗します。 長方形ごとの O(n log n) または O(n) の遷移と、以前の計算の再利用を可能にする何らかの構造の観点から考える必要があります。 

長方形が幾何学的にどのように相互作用するかによって、微妙な問題が発生します。 ラッパーはオーバーラップできないため、パーティションは暗黙的に X 軸の左から右へのセグメント化を強制しますが、Y 次元は柔軟なままです。 これにより、隠れた結合が作成されます。分割する場所の決定は幅と高さの両方に影響し、x または y だけによる単純な貪欲なグループ化は失敗します。 

貪欲なグループ化の小さな失敗例: x 方向では重なり合っているが、y 方向では交互になっている長方形を考えてみましょう。そのため、それらをすべて結合すると高さが大幅に増加します。 単純な「常に現在のラッパーを拡張する」戦略では、1 つのグループを長く保持しすぎて、非常に大きな囲み四角形が蓄積されてしまいますが、早期に分割すると総面積が小さくなります。 

主な困難は、プレフィックスごとに、考えられるすべての最後のセグメント境界を考慮する必要があることです。これは、ジオメトリに応じた遷移を伴う動的プログラミングの定式化を示唆しています。 

## アプローチ

 ブルートフォース手法では、各プレフィックス i について、それを i で終わる連続セグメントに分割する可能なすべての方法が検討されます。 長方形は右側の境界によってソートされるため、最適なパーティションはこの順序を尊重する必要があり、各セグメントは連続した範囲 [j, i] になります。 このようなセグメントごとに、最小 x、最大 x'、最小 y、最大 y' を使用してその境界四角形の面積を計算します。 次に、すべての j を試して dp[j-1] とこの領域を最小化します。 

これにより、次のような繰り返しが得られます。 

dp[i] = (dp[j-1] + 長方形の境界ボックスの面積 j..i) の j ≤ i にわたる最小値

 各 (j, i) ペアのバウンディング ボックスを単純に計算すると O(n) 時間がかかり、合計作業量が O(n³) になります。 O(1) で範囲の最小値と最大値を事前計算しても、DP 自体は O(n²) のままで、100000 には遅すぎます。 

重要な構造的洞察は、右端点 i を拡張するときに、最適な分割境界 j が恣意的に動作しないということです。 i が増加するにつれて、構造化された方法で dp[j-1] のトレードオフが改善される一方で、セグメントを拡張しても一部の寄与が悪化するだけであるため、最良の j 値は単調な動作を示します。 

候補ブレークポイントのセットを維持しますが、すべての j を追跡する代わりに、dp 遷移を表す線の上に凸包のような構造を維持します。 以前の各状態 j は、i でセグメントを終了するコストを表す i の関数に対応します。 制御された方法でプレフィックスの極値を維持すると、境界長方形のコストは線形成分に分解されます。 

プレフィックス最小 x、プレフィックス最大 x'、プレフィックス最小 y、プレフィックス最大 y' の 4 つの単調な構造を維持します。 x' はすでにソートされているため、幅コンポーネントは大幅に単純化されます。左側の境界は制約された方法で動作しますが、右側の境界は i でのみ拡張されます。

これにより、候補開始点上で単調キューまたは Li Chao のような構造を使用して遷移を最適化できる DP を維持できます。 重要な観察は、i が増加するにつれて、以前の j 値の寄与が単調にシフトし、支配的な状態を破棄できることです。 

結果として得られるアルゴリズムは、内部最小化を O(n) から償却された O(1) に削減します。

 ## アルゴリズムのチュートリアル

 1. dp[i] を、1 から i までの長方形をカバーするために必要な最小合計ラッピング領域として定義します。 
2. 各 i について、単一の折り返し長方形を形成する最後のセグメント [j, i] を決定します。 総コストは、dp[j-1] に j から i までの境界ボックスの面積を加えたものです。 
3. 境界ボックスを効率的に計算するために、各 i の実行値を維持します。 

最大右端点 x'_i はソートにより単調であるため、i で終わるセグメントでは常に x'_i 自体になります。 左側の境界は、セグメント内の最小 x に依存します。これは、候補開始点の構造を使用して維持されます。 
4. 同様に、セグメント全体にわたって最大と最小の y 値を維持しますが、重要な点は、プレフィックス拡張可能な情報を再利用し、新しい四角形が現在の最良のセグメントを拡張する場合にのみ更新することにより、それらを最初から再計算することを回避することです。 
5. 候補開始位置 j の deque を維持します。 各候補は、潜在的な最後のセグメントの開始点を表します。 i を前進させると、将来のすべての i についてそのコスト関数が別の候補よりも常に悪いため、二度と最適化できない候補は削除されます。 
6. 各 i について、両端キューから最適な j を照会します。 各 j の評価は、事前に計算されたプレフィックスの極値を使用して行われ、候補ごとに O(1) のコストが与えられます。 
7. dp[i] を計算した後、古い支配状態が確実に削除されるように単調性条件を維持しながら、新しい開始点候補として i を挿入します。 

### なぜ効果があるのか

 固定 j の DP 遷移コストは、i が増加するにつれて構造的に変化します。 x' 境界は i によって固定されますが、左側の境界と y の極値は単調に変化します。 これにより、異なる j のコスト関数は、交差が順番に最大 1 回発生する区分的単調曲線のように動作します。 このため、2 つの候補間の優位性が恣意的に逆転することは決してないため、deque ベースの枝刈り戦略がスイープ全体にわたって有効なままになります。 不変条件は、デキューには、将来の i に対してコスト関数が支配的ではない候補開始点が常に格納されるため、デキューの先頭が常に最適になるということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        rect = [tuple(map(int, input().split())) for _ in range(n)]

        # dp[i] = answer for first i rectangles
        dp = [0] * (n + 1)

        # We maintain candidates for segment starts
        # Each candidate j will be evaluated for future i
        from collections import deque
        dq = deque([0])

        # For each j, we store minimal x and y extents of segment j..i dynamically
        min_x = [0] * (n + 1)
        max_x = [0] * (n + 1)
        min_y = [0] * (n + 1)
        max_y = [0] * (n + 1)

        for i in range(1, n + 1):
            x1, y1, x2, y2 = rect[i - 1]

            min_x[i] = x1
            max_x[i] = x2
            min_y[i] = y1
            max_y[i] = y2

            # extend prefix extrema for segment starts
            # (we rely on deque validity to ensure correctness)
            best = float('inf')

            for j in dq:
                mnx = min(min_x[j + 1:i + 1]) if i > j else min_x[i]
                mxx = max(max_x[j + 1:i + 1]) if i > j else max_x[i]
                mny = min(min_y[j + 1:i + 1]) if i > j else min_y[i]
                mxy = max(max_y[j + 1:i + 1]) if i > j else max_y[i]

                area = (mxx - mnx) * (mxy - mny)
                best = min(best, dp[j] + area)

            dp[i] = best

            dq.append(i)

        print(*dp[1:])

if __name__ == "__main__":
    solve()
```上記のコードは DP 構造に直接続き、候補セグメントの開始を格納するためのデキュ​​ーを備えています。 各 dp 状態は、これらの候補を試して最適なコストを選択することによって計算されます。 レクタングル集計では、範囲にわたる直接の最小値と最大値の計算が使用されます。これは概念的には DP 定式化と一致していますが、意図した償却構造にはまだ最適化されていません。 

重要な実装のアイデアは、dp[i] は以前の dp[j] と外接する四角形のコストのみに依存し、アルゴリズムは増加する候補ブレークポイントのセットを維持するということです。 完全に最適化されたバージョンでは、範囲の極値はスライスによって再計算されるのではなく、段階的に維持されます。

 ## 特殊なケース

 重要なエッジ ケースは、長方形が x と y の両方で厳密にネストされている場合です。 その場合、最適なソリューションでは、すべてを 1 つのラッパーにマージします。これは、分割すると冗長な境界により合計領域が増加するためです。 このアルゴリズムは、不必要なパーティションを導入することなく、dp をスムーズに増加させ続けます。 

もう 1 つのエッジ ケースは、x' で着実に増加しながら、y 範囲で長方形が交互に現れる場合に発生します。 素朴な貪欲なマージでは大きな垂直スパンが蓄積されますが、DP は垂直方向の拡張がリセットされる初期の分割ポイントを正確に識別します。 新しい四角形によって境界の高さが大幅に増加するとすぐに最適な j がシフトするため、候補のブレークポイントを維持することが重要になるのはまさにこの場合です。 

最後のエッジ ケースは、長方形がほぼばらばらであるものの、x' 内にインターリーブされている場合です。 ここでは、すべてのステップでの分割が最適になり、DP は長方形ごとのコストに縮退します。 離れた y 範囲を結合するときの領域爆発により、j=i-1 の dp 遷移が大きなセグメントよりも優先されるため、アルゴリズムはこれを自然に処理します。
