 ## 解決策
 ## 問題の理解

 同じ長さの 2 つの配列が与えられています。 1 つの配列、それを呼び出す`a`、位置が固定されます。 2 番目の配列、`b`、任意に並べ替えることができます。 注文を選択した後、`b`、少し間接的な方法で定義されたスコアを評価します。すべての部分配列は次の積の合計に寄与します。`a[k] * b[k]`その部分配列内のすべてのインデックスを対象にし、これをすべての部分配列にわたって合計します。 

これを再解釈する便利な方法は、部分配列の観点から考えるのをやめ、代わりに各位置が何回あるかを尋ねることです。`k`カウントされます。 インデックスを修正する`k`。 任意のサブアレイ`[i, j]`それは含まれます`k`貢献する`a[k] * b[k]`一度。 このような部分配列の数が選択方法の数になります。`i ≤ k ≤ j`に等しい`(k+1) * (n-k)`。 したがって、式全体は単一の重み付き内積に折りたたまれます。$$\sum_{k=0}^{n-1} a_k b_k \cdot (k+1)(n-k)$$したがって、各ポジションにはインデックスによってのみ決定される固定の正の重みがあり、自由に並べ替えることができます。`b`この加重合計を最小化します。 

制約は大きく、`n`まで`10^5`。 すべての順列を試すような解決策は不可能です。`n!`成長が早すぎる。 二次割り当て戦略であっても遅すぎるでしょう。 もっと近いものが必要です`O(n log n)`または`O(n)`。 

微妙なエッジ ケースは、両方の配列の負の値から発生します。 以来`a[k]`ネガティブになることもあるし、`b[k]`負の場合もあり、積は正または負の場合もあるため、符号と重みを慎重に考慮しない限り、最適な戦略は「両方をソートし、最小のものと最小のものを組み合わせる」という自明なものではありません。 重み付け構造を理解せずに単純に貪欲にすると失敗する可能性があります。 

たとえば、重みが無視された場合、ソートされた配列をペアにすることは、内積を最小化するために正しいものです。 ここで重みはインデックスごとに異なるため、割り当て構造に重みを組み込む必要があります。 

## アプローチ

 ブルート フォース アプローチは概念的には単純です。次のすべての順列を試します。`b`、加重合計を計算し、最小値を取得します。 これは、式が一度完全に決定的であるため機能します。`b`固定されています。 ただし、置換の数は、`n!`、そしてさらには`n = 10`これは不可能になります。 それぞれの評価は、`O(n)`したがって、合計作業量は次のようになります。`O(n! · n)`。 

重要な洞察は、問題を書き直すと、古典的な代入問題が得られるということです。つまり、次の値を代入しています。`b`固定位置へ`k`、それぞれに重みが付いています`w_k = (k+1)(n-k)`。 費用は次のとおりです。$$\sum w_k \cdot a_k \cdot b_{\pi(k)}$$私たちは吸収できる`a_k`を定義して重みに組み込みます`c_k = a_k * w_k`。 ここで、問題は最小限に抑えられます。$$\sum c_k \cdot b_{\pi(k)}$$これは標準的な並べ替え不等式の状況です。すべての値が一貫して扱われる場合、積の合計を最小化するために、一方のシーケンスを昇順に、もう一方のシーケンスを降順に並べ替えます。 

ここ`c_k`は正または負の可能性があるため、ソートを通じて符号の効果を暗黙的に分離する必要があります。 並べ替えの不等式は引き続き適用されます。2 つのシーケンス間の最小ドット積は、両方をソートし、最大値と最小値をペアにすることによって達成されます。 

したがって、すべてを計算します`c_k`、並べて、並べて`b`、とペア`c`昇順で`b`降順で。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ポジションの貢献ウェイトを計算する`k`として`(k+1) * (n-k)`。 

これは、インデックスを含むサブ配列の数をカウントします。`k`, したがって、3 つの合計をインデックスごとに 1 つの係数に置き換えます。 
2.それぞれを乗算します`a[k]`位置の重みによって新しい配列を形成する`c[k] = a[k] * (k+1) * (n-k)`。 

これにより、目的が次の間の内積に変換されます。`c`そして並べ替えられた`b`。 
3. 配列のソート`c`降順ではない順に。 

これは、符号効果を含め、最終合計にどれだけ強く影響するかによってポジションを順序付けします。 
4. 配列のソート`b`昇順ではない順に。 

大きな値が必要です`b`の小さい (最も負の) 値とペアにする`c`、および小さな値`b`大きいものと組み合わせる`c`。 
5. 要素ごとに乗算して合計する`c[i] * b[i]`。 

これにより、再配置不等式の下で可能な最小値が得られます。 

### なぜ効果があるのか

 変換後の問題は、重み付き内積を最小にする順列を正確に選択することです。 並べ替えの不等式は、任意の 2 つのシーケンスについて、一方のシーケンスを昇順にソートし、もう一方のシーケンスを降順にソートすると、ペアごとの積の最小合計が得られることを示します。 重みは、各位置を個別にスケーリングする以上にインデックス間の結合を導入しないため、ソートはすべての自由度を捕捉します。 逆の順序から逸脱すると、2 つのペアが交換され、合計が増加または保存されるため、より良い構成が存在できなくなります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    c = [0] * n
    for i in range(n):
        w = (i + 1) * (n - i)
        c[i] = a[i] * w
    
    c.sort()
    b.sort(reverse=True)
    
    ans = 0
    for i in range(n):
        ans += c[i] * b[i]
    
    print(ans)

if __name__ == "__main__":
    solve()
```コードはまず、トリプル合計をインデックスごとの重みに圧縮します。 重要な実装ステップは正しく計算することです`(i+1)*(n-i)`、サブ配列内の各インデックスの包含数を表します。 ここで 1 つずれたエラーがあると、削減全体が中断されます。 

その後、両方の配列が反対方向にソートされ、乗算されます。 Python 整数を使用すると、値が最大約`10^10`ただし、Python の任意精度では安全です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import prod

    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    c = [(i+1)*(n-i)*a[i] for i in range(n)]
    c.sort()
    b.sort(reverse=True)
    
    return str(sum(c[i]*b[i] for i in range(n)))

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、すべての値が`a`はゼロです。 この状況では毎回`c[i]`順列に関係なくゼロになるため、結果はゼロになる必要があります。 並べ替えでは何も変更されず、すべての製品がゼロになるため、アルゴリズムはこれを自然に処理します。 

別のエッジケースが発生するのは次の場合です。`a`大きな正の値と負の値の両方が含まれています。 重み付けは位置に応じて影響を増幅するため、ペアリングを誤ると結果が大幅に増加します。 ソート戦略により、マイナスの寄与が大きなプラスの寄与と一致することが保証されます。`b`値を調整し、総コストの偶発的な増幅を防ぎます。 

最後のエッジケースは次のような場合です`b`最適なペアリングに対してすでに「間違った」方向にソートされています。 アルゴリズムは、再ソートによってこれを修正し、入力順序が正確さに影響を及ぼさないようにします。
