 ## 解決策
 ## 問題の理解

 各クエリは、以下の整数の範囲を記述します。`l`に`r`、注文されたペアの数を尋ねます`(a, b)`その範囲内の関数が関係する特定の条件を満たす`f(a, b)`。 関数自体は、ペアのカウントを開始する前に単純化されます。 

表現`f(a, b) = a + b + |a - b|`どちらに応じて動作が異なります`a`そして`b`の方が大きいです。 もし`a ≤ b`、 それから`|a - b| = b - a`, したがって、式は次のようになります`a + b + (b - a) = 2b`。 もし`a > b`、 それから`|a - b| = a - b`, したがって、式は次のようになります`a + b + (a - b) = 2a`。 この問題により次のことが制限されるため、`a ≤ b`、最初のケースのみが問題となり、関数は常に次のようになります。`f(a, b) = 2b`。 

これにより、各クエリの解釈が即座に変更されます。 ペアについて考えるのではなく、実際に選択肢がいくつあるかを数えています。`(a, b)`と`l ≤ a ≤ b ≤ r`満足する`2b = x`。 一度`b`固定されており、`a`からの任意の整数を指定できます`l`に`b`。 

制約は非常に大きく、最大値は次のとおりです。`10^18`そして最大まで`2 × 10^5`クエリ。 範囲を反復したり、ペアを列挙したりする解決策は不可能です。 クエリごとに単一の範囲を反復処理するだけでも、すでに遅すぎます。 

次の場合、微妙なエッジケースが発生します。`x`奇数です。 以来`2b = x`、整数なし`b`存在するので、答えはゼロでなければなりません。 別のエッジケースは、暗黙的に`b = x / 2`外にある`[l, r]`、これもゼロになります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのペアに対して反復処理が行われます。`(a, b)`クエリごとに、`l ≤ a ≤ b ≤ r`そしてどうか`f(a, b) = x`。 これには大まかに検討する必要があります`(r - l + 1)^2 / 2`クエリごとのペア。 以来`r`と同じ大きさにすることができます`10^18`、これはまったく不可能です。 

重要な観察は、関数を単純化することから得られます。 なぜなら`f(a, b)`常に崩壊する`2b`制約の下で`a ≤ b`、値は以下にのみ依存します。`b`、オンではありません`a`。 これにより、問題の 2 次元構造が完全に削除されます。 

固定クエリの場合`(l, r, x)`、最初に次のことを確認します。`x`は均等です。 奇数の場合、解決策は存在しません。 それ以外の場合は設定します`b = x / 2`。 ここで、条件は純粋に、`b`狭間にある`[l, r]`。 

もし`b`有効です。可能なものはすべて数えます`a`そのような`l ≤ a ≤ b`。 まさにあります`b - l + 1`選択肢。 もし`b < l`または`b > r`、答えはゼロです。 

これにより、各クエリが定数時間の演算に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | クエリあたり O((r−l)^2) | お(1) | 遅すぎる |
 | 最適 | クエリごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各クエリを読む`(l, r, x)`の有効な値かどうかを判断します`b`存在することができる。 以来`f(a, b)`単純化すると`2b`、の値`x`均等でなければなりません。 もし`x`奇数であれば、答えはすぐにゼロになります。 
2. コンピューティング`b = x / 2`。 これは、ペア内の大きい方の要素の唯一の候補値です。 残りの推論は、この値がクエリ間隔内にあるかどうかに完全に依存します。 
3. かどうかを確認します。`b < l`または`b > r`。 いずれかの条件が当てはまる場合、すべての有効なペアが必要であるため、有効なペアは存在しません。`l ≤ a ≤ b ≤ r`。 
4. もし`b`以内にあります`[l, r]`、有効な数を計算します`a`価値観が存在する。 以来`a`からの範囲`l`に`b`を含む、カウントは次のとおりです。`b - l + 1`。 
5. この値をクエリに出力します。 

### なぜ効果があるのか

 の変容`f(a, b)`すべての有効なペアを、ペアの 2 番目の要素のみに依存する条件に折りたたみます。 制約`a ≤ b`関数が常に次のように評価されるようにします。`2b`、すべてのペアを同じものにします`b`有効性の点では同等です。 その結果、ペアを数えるのは、次の有効な選択肢を数えるのと同じになります。`a`それぞれの実現可能性について`b`、導出区間外のペアは方程式を満たすことができません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    out = []
    
    for _ in range(q):
        l, r, x = map(int, input().split())
        
        if x % 2 == 1:
            out.append("0")
            continue
        
        b = x // 2
        
        if b < l or b > r:
            out.append("0")
            continue
        
        out.append(str(b - l + 1))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この解決策は、各クエリを方程式から導出される単一の候補値に減らすことに依存します。 パリティ チェックにより無効な半値が防止され、範囲チェックにより元の間隔制約を遵守するペアのみがカウントされることが保証されます。 算術`b - l + 1`～の有効な選択肢を直接カウントします`a`反復なしで。 

実装によくある落とし穴は、次のことを忘れることです。`a`影響しない`f(a, b)`一度注文しました。 別の人は両方を誤って仮定しています`a ≤ b`そして`b ≤ a`ケースが別々に寄与するため、二重にカウントされたり、不必要な分岐が発生したりする可能性があります。

 ## 特殊なケース

 エッジケースの 1 つは次の場合に発生します。`x`奇数です。 入力用`(l=1, r=10, x=7)`、アルゴリズムはすぐにそれを拒否します。`b = x/2`整数ではないため、出力が生成されます`0`それ以上のチェックなしで。 

もう一つのケースは次のような場合です。`b`間隔の下にあります。 のために`(l=5, r=10, x=6)`、私たちは得ます`b = 3`より小さい`l`、したがって無効です`a`存在します。 アルゴリズムは範囲チェックで正しく停止します。 

最後の境界ケースは次の場合に発生します。`b`等しい`r`。 のために`(l=3, r=8, x=16)`、私たちは得ます`b = 8`、有効です`a`値は`3..8`、生産`6`。 式`b - l + 1`調整なしで両方のエンドポイントが正しく含まれています。
