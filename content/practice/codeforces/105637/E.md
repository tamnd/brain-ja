 ## 解決策
 ## 問題の理解

 n × m のグリッドとしてモデル化された長方形の駐車場が与えられます。 一部の独房には柱があり、移動や駐車が永久に妨げられます。 残りのセルは空きスペースであり、最終的には車が停止する可能性があります。 

車はグリッド内を自由に移動できません。 各車両は列または列の入口を選択し、その線に沿って内側に真っ直ぐ進みます。 車は、行または列の端に到達するか、柱やすでに駐車している車によって進路上の次のセルがブロックされ、早期停止を余儀なくされるまで走行を続けます。 車が停止すると、そのセルは永久に占有され、後続の車にとって障害になります。 

プランナーは、到着する車ごとに、どの入り口を使用するかを選択できます。 目標は、有効な移動がなくなる前に、何台の車を正常に駐車できるかを最大化することです。 

入力は単に柱と空のセルを表すグリッドであり、出力は単一の数値、つまり最適な入り口の選択肢の順序で駐車できる車の最大数です。 

重要な構造上の制約は、車が進入すると動きが厳密に 1 次元になるため、各決定は 1 つの行または列の行にのみ影響するということです。 これは、問題がグリッド内の一般的なパス検索に関するものではなく、独立した線形セグメントに沿った相互作用に関するものであることを直ちに示唆しています。 

グリッド サイズは最大 1000 × 1000 であるため、最悪の場合でも行または列を繰り返しスキャンして各車両を明示的にシミュレートしようとするアプローチは、慎重に最適化すればまだギリギリ許容可能ですが、配置のすべてのペアを考慮したり、配置ごとに到達可能性を再計算したりする方法は遅すぎます。 考えられるすべての車両の配置を試してグリッドを繰り返し更新する単純なシミュレーションでは、密度が高い場合には立体的な動作に低下します。 

貪欲な直感が微妙に失敗するケースは、複数の行または列に同様の「即時停止点」がある場合に現れます。 たとえば、行の入口付近に空のセルが 1 つあり、別の行に空のセルの長いチェーンがある場合、最初に短い方を選択すると、後で交差する列でのアクセス パターンがブロックされる可能性があります。 これは、行と列の間の相互作用をグローバルに考慮しない限り、局所的な最短または最長のヒューリスティックは信頼できないことを意味します。 

## アプローチ

 直接的な強引な解釈は、駐車プロセスをシミュレートすることです。 各ステップで、考えられるすべての入り口を考慮し、その行または列に沿って移動する車をシミュレートし、可能であれば配置します。 次に、配置が不可能になるまで再帰的に続行し、考えられるすべての入り口の選択肢を試します。 

これは、考えられるすべての決定シーケンスを調査するため、正しいです。 問題は、配置するたびにグリッドが変化するため、同じ行または列を何度も再計算する必要があることです。 各シミュレーション ステップでは O(n + m) 個のセルをスキャンし、最悪の場合は O(nm) 台の車を配置する可能性があり、全体の複雑さは O(nm(n + m)) 程度になります。これは 1000 × 1000 グリッドには遅すぎます。 

重要な観察は、最終的な構成は、自動車をシミュレートする正確な順序には依存せず、ブロックされる前に行または列のどちらかの側からどのセルに到達できるかにのみ依存するということです。 セルが自動車によって「消費」されると、その行と列の両方で将来の自動車に対するブロッカーのように動作するため、このプロセスは、空きセグメントの利用可能なエンドポイントを繰り返し照合することと同等になります。 

グリッドを確認するためのより便利な方法は、柱で区切られた空のセルの最大連続セグメントにグリッドを分解することです。 このような各セグメントは、直線運動に関して独立して動作します。 左または右から列に進入する車は、基本的にその側からセグメント内で最初に利用可能なセルを主張します。列についても同様です。

洞察としては、空の各セルは事実上、その行の最大 2 方向とその列の最大 2 方向から「消費」できる候補ですが、一度取得されると、その後のアクセスがブロックされるということです。 これにより、行セグメントと列セグメントの間に二部構成の相互作用が生じ、最適な戦略は、競合せずにどれだけのセルを要求できるかを数えることになります。 

これは古典的なアイデアに帰着します。利用可能な行アクセス可能なセルと列アクセス可能なセルを貪欲に一致させますが、グラフを明示的に構築する代わりに、各セルには正確に 4 方向の「フロント」(左、右、上、下) からアクセスできるという事実を利用し、車両の配置ごとに利用可能なフロントが局所的に減少します。 

すべての行と列について、使用可能なエントリー ポイントがいくつ残っているかを追跡し、到達可能な最も早いブロック位置に車両を繰り返し割り当てることで、プロセスをシミュレートします。 各割り当てでは 1 つのセルが削除され、2 つの行が更新されるだけなので、合計作業量はセルの数に比例します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | すべてのシーケンスのブルート フォース シミュレーション | O(nm(n + m)) | O(nm) | 遅すぎる |
 | 行/列セグメントの貪欲なマッチング | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. まずグリッドを前処理して、各行および各列について、車がどちらの側から進入した場合に停止するかを把握します。 これは、各行を左から右、右から左にスキャンし、同様に各列をスキャンし、柱に遭遇するたびに停止することを意味します。 このステップを行う理由は、各車両は常に最初の障害物で停止するため、各方向で最も近い遮断構造のみが必要になるためです。 
2. 当社は、車両の受け取りにセルがまだ利用可能かどうかをマークする構造を維持します。 最初はすべて「.」 セルは使用可能ですが、「o」セルは永久にブロックされます。 この状態が必要なのは、車がセルを占有すると、その行と列の両方で将来の車の妨げになるためです。 
3. 各行について、車両を両端から内側に繰り返し送る効果をシミュレートします。 概念的には、各行をピラーで区切られた利用可能なポジションのデックとして扱います。 車を行に割り当てるたびに、その車は片側から最も近い利用可能なセルを占有し、それ以降の検討から除外されます。 同じ考え方が列にも対称的に当てはまります。 
4. 有効なエンドポイントが存在するたびに、車を水平または垂直に配置するというグローバル プロセスを繰り返します。 配置が行われると、そのセルを行構造と列構造の両方から削除します。 これにより、水平方向の流れと垂直方向の流れの一貫性が確保されます。 
5. どの行または列にも別の車両を配置できなくなるまで、つまり残りのすべてのセグメントがブロックされるか、すでに使い果たされるまで、このプロセスを続けます。 
6. 最終的な答えは、このプロセス中に実行された成功した配置の数です。 

これが機能する理由は、すべての有効な配置が強制されるためです。行または列に進入した車は常に、その方向で最初に到達可能な空のセルに到達します。 方向が決まってしまえば、セグメント内では選択の余地がありません。 唯一の決定は、行エンドポイントを最初に消費するか列エンドポイントを最初に消費するかですが、各セルは最大 1 回しか消費できず、容量の 1 ユニットにちょうど寄与するため、可用性の制約を考慮した順序付けでは同じ最大数になります。 

維持される不変条件は、どの時点においても、残りのすべての空きセルが、以前に割り当てられたセルまたはピラーを通過することなく、少なくとも 1 つの方向から引き続き到達可能であり、すべての割り当てで、そのような到達可能なセルが 1 つだけ削除され、同時に両方向の隣接セルの到達可能性が正しく更新されるということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    g = [list(input().strip()) for _ in range(n)]

    row_used = [[False] * m for _ in range(n)]
    col_used = [[False] * m for _ in range(n)]

    ans = 0

    changed = True
    while changed:
        changed = False

        for i in range(n):
            j = 0
            while j < m:
                if g[i][j] == 'o' or row_used[i][j]:
                    j += 1
                    continue

                l = j
                while j < m and g[i][j] == '.':
                    j += 1
                r = j - 1

                if l <= r:
                    if not row_used[i][l]:
                        row_used[i][l] = True
                        col_used[i][l] = True
                        ans += 1
                        changed = True

        for j in range(m):
            i = 0
            while i < n:
                if g[i][j] == 'o' or col_used[i][j]:
                    i += 1
                    continue

                l = i
                while i < n and g[i][j] == '.':
                    i += 1
                r = i - 1

                if l <= r:
                    if not col_used[l][j]:
                        col_used[l][j] = True
                        row_used[l][j] = True
                        ans += 1
                        changed = True

    print(ans)

if __name__ == "__main__":
    solve()
```この実装では、水平スイープと垂直スイープが交互に行われます。 各スイープでは、連続する空のセルがピラーで区切られたセグメントにグループ化されます。 各セグメントの最初の未請求のセルのみが新しい車両に使用されます。これは、それが入口から最初の停止ポイントに対応するためです。 の`row_used`そして`col_used`配列は、セルが取得されると、両方の方向から一貫して削除されることを保証します。 

よくある実装の落とし穴は、行スイープで削除されたセルは、同じ反復内の列スイープではすぐに使用できなくなる必要があることを忘れていることです。 この同期がないと、同じセルが異なる方向で 2 回カウントされる可能性があります。

 ## 特殊なケース

 エッジ ケースの 1 つは、単一のセルを除いて完全にピラーで満たされている行または列です。 この場合、その孤立したセルのみを使用することができ、行スキャンまたは列スキャンのどちらで検出されたかに関係なく、そのセルを 1 回だけカウントする必要があります。 セルがいずれかの方向で使用されるとマークされると、そのセルはもう一方の方向から除外されるため、アルゴリズムはこれを処理します。 

別のエッジ ケースは、多数の単一セル セグメントを形成する交互のピラーを備えたグリッドです。 各セグメントは最大でも 1 台の車両に寄与し、セグメント間で干渉は発生しません。 セグメンテーション ロジックにより、それぞれが独立して処理されることが保証されます。 

最後の微妙なケースは、同じ反復内の行と列の両方からセルに到達できる場合です。 共有マーキング配列がないと、2 回カウントされる可能性があります。 ここで、いずれかのスイープで配置が行われると、セルは行と列の両方の考慮から直ちに削除され、重複が防止されます。
