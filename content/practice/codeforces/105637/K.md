 ## 解決策
 ## 問題の理解

 この問題は、固定構造のノックアウト フットボール トーナメントについて説明しています。 まさにあります$2^k$チームがあり、トーナメントは完全勝ち抜きブラケットとしてプレイされます。チームは次の順位に配置されます。$2^k$初期順位が決定され、チャンピオンが 1 人残るまで、試合ごとに 1 人の参加者が除外されます。 誰が誰をプレイするかの構造は、これらの初期ポジションによって完全に決定され、リーフがチームで内部ノードが試合であるバイナリ ツリーが形成されます。 

このようなトーナメントの完全な試合結果は提供されますが、ブラケット自体は提供されません。 各試合結果は、どの 2 チームがプレーし、どちらが勝ち上がったかを示しますが、その試合がどのラウンドで行われたか、またはブラケットがどのように配置されているかについては明示的には示しません。 これらの順序付けされていない結果から、タスクは、2 つのチームがブラケット内でどの程度「接近」しているか、特に両チームが勝ち上がった場合に対戦するラウンドについての質問に答えるために、トーナメント ツリーに関する十分な情報を再構築することです。 

グラフの観点から見ると、隠れた構造は完全なバイナリ ツリーです。$2^k$葉。 各内部ノードは 1 つの一致に対応し、その子はその一致の 2 つの参加者になります。 各チームはリーフとして 1 回だけ表示され、正確に参加します。$k$ルートへのパスに沿って一致します。 重要な隠れた要件は、このツリーが指定された一致結果によって一意に決定されることです。 

制約は深さは小さいですが、幅は大きくなります。 と$k \le 10$、せいぜいあります$2^{10} = 1024$チーム、そしてせいぜい$1023$一致します。 これにより、チームの配置の順列の数が$(2^k)!$、それは天文学的な大きさです。 代わりに、大まかに機能する再構築アプローチ$O(n \log n)$または$O(n^2)$許容されます。 

正確さには、いくつかの微妙な特殊なケースが重要です。 まず、複数の試合には同じチームが異なるステージに登場することが含まれるため、入力の順序が任意であるため、単純な「出現によるペア マッチング」は失敗します。 

たとえば、チーム A が早い段階で B に勝ち、後で C に勝つという状況を考えてみましょう。入力には、試合が任意の順序でリストされる可能性があります。 出現した対戦相手を割り当てる単純な貪欲なアプローチでは、誤って B を後のステージに割り当てる可能性があります。 

第 2 に、不注意な再構成により、一致が無向グラフ内の独立したエッジとして扱われる可能性があります。 これにより、階層が失われます。2 つのチームがすぐに対戦するのではなく、上位ラウンドでのみ対戦する可能性があります。

 最後に、結果は順序付けされていないため、解決策は入力順序ではなく構造的制約に依存する必要があり、そうでないと同一のツリーが矛盾して解釈される可能性があります。 

## アプローチ

 この問題を考える強引な方法は、考えられるすべてのブラケット構造を試してみることです。 考えられるすべての順列で完全なバイナリ ツリーのリーフにチームを割り当て、その後、上向きに一致をシミュレートし、観察された一致結果が正確に一致するかどうかを確認することができます。 ブラケットはすべての一致を一意に決定し、シミュレーションによって一貫性が検証されるため、これは理論的には正しいです。 問題は階乗爆発です。$(2^k)!$チームをリーフに割り当てる方法や、枝刈りを行ったとしても検索スペースが大きすぎます。 

重要な観察は、順列全体を推測する必要がないということです。 各試合結果は、トーナメント ツリーにおける直接の親子関係をすでに示しています。 すべての試合は内部ノードであり、その子は対戦した 2 チームです。 これにより、エッジが順序付けなしで与えられ、構造を推測する必要があることを除いて、問題は直ちにエッジから二分木を再構築することに変わります。 

各試合をツリー内のエッジとして解釈すると、トーナメントはルートのあるバイナリ ツリーになり、ルートが最終試合になります。 各チームの深さは、トーナメントで敗退するか優勝するラウンドと同じになります。 2 つのチームが対戦するラウンドは、このツリー内の最も低い共通の祖先によって決まります。 

したがって、問題は、一致結果から隣接関係を構築し、ルートを特定し、親と深さの情報を前処理して、最も共通する祖先のクエリに答えることができるようにすることに帰着します。 

微妙な問題が残っています。それは、一致結果が親子の方向を明示的に示していないということです。 試合で 2 つのチームがつながったこと、勝者が上に進むことだけがわかります。 これにより、エッジを敗者から勝者に向けることができ、チャンピオンに向かう方向のツリーを効果的に構築できます。 

エッジの方向を決めた後、最終的な勝者 (敗者として表示されない唯一のノード) でツリーをルート化します。 ルートからの DFS または BFS は深さと親を与え、バイナリ リフティングにより LCA クエリが可能になります。

 | ビルドツリー + LCA 前処理 |$O(n \log n)$|$O(n \log n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての試合結果を解析し、各行から勝者と敗者を抽出します。 勝者は勝ち上がったチーム、敗者は敗退したチームです。 このステップは純粋に解析ですが、正確かどうかは、すべての一致で一貫して方向を識別することに依存します。 
2. 各敗者が勝者に対して有向エッジを持つ有向グラフを構築します。 これはトーナメントの進行を反映し、最終勝者を除いて各ノードが出力エッジを 1 つだけ持つことを保証します。 
3. 度数をカウントするか、敗者としての出現を追跡します。 敗者として表示されないチームが最終チャンピオンとなり、トーナメント ツリーのルートとなります。 これは、有向構造内で親を持たない唯一のノードです。 
4. ツリーの無向バージョンの隣接リストも作成します。 方向は階層を与えますが、深さを割り当てるために構造を横断するには無向エッジが必要です。 
5. ルートから BFS または DFS を実行して、各ノードの深さと直接の親を計算します。 深さは、チームがその試合レベルに到達するラウンド構造に対応します。 親ポインタはツリー構造を確立します。 
6. すべてのノードのバイナリ リフティング祖先を事前計算し、最も低い共通祖先クエリが対数時間で応答できるようにします。 このステップにより、複数のクエリを効率的に処理できるようになります。 
7. チームのクエリ ペアごとに、それらの最小共通祖先を計算します。 答えは、この LCA ノードの深さであり、2 つのチームが対戦するラウンドに対応します。 

### なぜ効果があるのか

 各試合では、トーナメント ツリー内で厳密な親子関係が定義されます。これは、負けたチームが 1 回だけ敗退し、勝利したチームが独自のパスを通って上に進むためです。 これにより、敗者から勝者へのエッジによって形成される有向構造が、最終チャンピオンに根差したツリーであることが保証されます。 

トーナメントは完全な二分木であるため、どの 2 つのチームも、パスが結合する試合に対応する固有の最小共通祖先を共有します。 深さは、その試合の前に行われた除去ステージの数をエンコードするため、彼らの会議のラウンドはまさにこの祖先の深さです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

def parse_match(line):
    parts = line.strip().split()
    team1 = parts[0]
    team2 = parts[-1]

    def extract_score(x):
        # x like "1(4)" or "2"
        if '(' in x:
            return int(x.split('(')[1].rstrip(')'))
        return int(x)

    # compare scores in middle tokens
    # format: A score - score B (or penalty format)
    # we rely on winner being the side with larger displayed score structure
    # safer: original statement guarantees different scores
    left_score = extract_score(parts[1])
    right_score = extract_score(parts[-2])

    if left_score > right_score:
        winner, loser = team1, team2
    else:
        winner, loser = team2, team1

    return winner, loser

n, q = map(int, input().split())

edges = []
nodes = set()
indeg = {}

for _ in range((1 << n) - 1):
    line = input().strip()
    w, l = parse_match(line)
    edges.append((w, l))
    nodes.add(w)
    nodes.add(l)
    indeg[l] = indeg.get(l, 0) + 1
    indeg.setdefault(w, 0)

adj = {}
for u in nodes:
    adj[u] = []

for w, l in edges:
    adj[w].append(l)
    adj[l].append(w)

root = None
for u in nodes:
    if indeg.get(u, 0) == 0:
        root = u
        break

LOG = 15
up = {}
depth = {}

for u in nodes:
    up[u] = [None] * LOG
    depth[u] = -1

from collections import deque
dq = deque([root])
depth[root] = 0
up[root][0] = None

while dq:
    u = dq.popleft()
    for v in adj[u]:
        if depth[v] == -1:
            depth[v] = depth[u] + 1
            up[v][0] = u
            dq.append(v)

for j in range(1, LOG):
    for u in nodes:
        if up[u][j-1] is not None:
            up[u][j] = up[up[u][j-1]][j-1]

def lca(a, b):
    if depth[a] < depth[b]:
        a, b = b, a

    diff = depth[a] - depth[b]
    bit = 0
    while diff:
        if diff & 1:
            a = up[a][bit]
        diff >>= 1
        bit += 1

    if a == b:
        return a

    for j in range(LOG - 1, -1, -1):
        if up[a][j] != up[b][j]:
            a = up[a][j]
            b = up[b][j]

    return up[a][0]

out = []
for _ in range(q):
    a, b = input().split()
    ancestor = lca(a, b)
    out.append(str(depth[ancestor]))

print("\n".join(out))
```一致フォーマットには通常のケースとペナルティのケースの両方が含まれるため、解析ステップは最も脆弱な部分です。 この実装では、決定的なスコアのコンポーネントを抽出し、それを比較して勝者と敗者を決定することで、この問題を解決します。 

隣接構築では、インディグリー トラッキングによって方向を維持しながら、エッジをトラバースに対して方向のないものとして意図的に扱います。 この分離により、ルートを識別しながらツリー構造の損失が回避されます。 

ツリーが静的でクエリが複数あるため、バイナリ リフティングはすべてのノードにわたって構築されます。 LCA ルーチンは、最初に深さを調整し、次に両方のノードを親が収束するまで一緒に持ち上げます。これにより、会合の一致が特定されます。

 ## 特殊なケース

 例外的なケースは、すべての試合が 1 つのパスを形成する場合に発生します。これは、1 チームを除くすべてのチームが、同じ勝者の連鎖によって順番に排除されることを意味します。 この状況では、深さの値は単調に増加し、任意の 2 つのノードの LCA はチェーン内のより高いノードになります。 BFS ベースの深さの割り当てでは、各ノードが一意の親から 1 回だけ到達するため、依然として正しいレベルが割り当てられます。 

もう 1 つのエッジ ケースは、チャンピオンが敗者として表示されない場合です。 アルゴリズムはこのプロパティに基づいてルートを識別します。 入力順序が任意の場合でも、入次数追跡により、正確に 1 つのノードの入次数が 0 になり、そのノードがルートとして正しく選択されることが保証されます。 

3 番目のエッジ ケースは、ペナルティ ベースの一致フォーマットで発生します。この場合、解析ではかっこを正しく無視する必要があります。 トークン全体を整数として扱うことはここでは失敗しますが、関連するスコアコンポーネントのみを抽出すると、正しい勝者の決定が保持され、ツリーの向きが有効に保たれます。
