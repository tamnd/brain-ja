 ## 解決策
 ## 問題の理解

 この問題は長い直線道路を表しています\(f\)の位置にあるフェスティバル会場につながります\(f\)。 がある\(n\)現在この道路を走っている車。 各車両には既知の位置があります\(x_i\)、道路の始点からの距離と一定の速度として測定されます。\(v_i\)。 すべての車はフェスティバルに向かって移動するため、到着するまで時間の経過とともに位置が直線的に増加します。\(f\)。 

課題は、どの車が最初にフェスティバルに到着するかを決定することです。 どの車も一定の速度で走っているので、車の到着時間は\(i\)は端までの残りの距離をその速度で割ったものです、\((f - x_i) / v_i\)。 答えは、そのタイムが最も小さい車両の指数です。 まったく同時に到着する 2 台の車は存在しないことが保証されているため、固有の答えが存在します。 

制約は小さいです。\(n \leq 100\)、\(f \leq 10^4\)、速度も次の制限を受けます。\(100\)。 これは、基本的な算術を使用した単純な \(O(n)\) スキャンでも十分であることを意味します。 各到着時間を 1 回計算して直接比較するソリューションは、即座に実行されます。 出力は小さなセットの最小値にすぎないため、ソートや高度なデータ構造は必要ありません。 

いくつかの特殊なケースについては、明示的に説明する価値があります。 車がすでにその位置にある場合\(f\)の場合、その到着時刻はゼロとなり、他の車もゼロでない場合にはその車を選択する必要があります (この問題は起こらないことが保証されています)。 複数の車が同じ位置からスタートしても速度が異なる場合、残りの距離は同じであるため、速い方が勝つのは明らかです。 比較すると微妙な間違いが生じる\(x_i / v_i\)\((f - x_i) / v_i\) の代わりに、終了までの時間ではなく開始からの移動時間を計算し、ロジックを完全に逆転させます。 

もう 1 つの陥りやすい落とし穴は、浮動小数点除算を使用し、不用意に時間を直接比較することです。 これは制約の下で機能しますが、精度の問題を回避するためにクロス積を比較するよりも不必要で、堅牢性が低くなります。 

## アプローチ

 問題を解決する最も直接的な方法は、最終レースの結果を数値的にシミュレートすることです。 各車について、終点に到着するまでにかかる時間を計算し、最小値を選択します。 これは正しいです。動きは各車両間で均一かつ独立しているため、到着時間によって順序が完全に決まります。 

この設定では、ブルート フォース ビューがすでに最適になっています。 たとえ小さなタイムステップで位置を再計算することを想像したとしても、それはすべての位置を繰り返し更新することを意味します。\(n\)車は時間までに多くのステップを越えます\(f\)、 \(O(n \cdot f)\) のような結果になりますが、動きが線形であり、閉じた形式で表現できることを考えると、これは不要です。 

重要な観察は、各車の状態が単一のスカラー値、つまり到達までの残り時間によって完全に要約されていることです。\(f\)。 これを車ごとに 1 回計算すると、問題は最小オーバー値を見つけることになります。\(n\)価値観。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | 時間ステップにわたるブルート シミュレーション | \(O(n \cdot f)\) | \(O(1)\) | 遅すぎる |
 | 直接時間計算 | \(O(n)\) | \(O(1)\) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む\(n\)そして\(f\)、何台の車が存在するか、およびゴールラインがどこにあるかを定義します。 

2. これまでに確認された最良 (最小) 到着時間と対応する車両インデックスを追跡するために変数を初期化します。 最初の車が常にベースラインになるように、ベスト タイムを実際の可能な値よりも大きな値に初期化することが重要です。 

3.各車両について\(i\)、その位置を読み取ります\(x_i\)そしてスピード\(v_i\)。 

4. フェスティバルまでの残りの距離を次のように計算します。\(d_i = f - x_i\)。 これは、車がまだどのくらいの距離を移動する必要があるかを表します。 

5. 到着時刻を概念的に次のように計算します。\(t_i = d_i / v_i\)。 実際に除算する代わりに、精度の問題を避けるために相互乗算を使用して比較します。\(d_i \cdot v_{\text{best}}\)と\(d_{\text{best}} \cdot v_i\)。 

6. 現在の車が最もよく知られている車よりも早く到達した場合、ベストタイム表現を更新し、この車のインデックスを保存します。 

7. すべての車両を処理した後、最小到着時間を持つ車両のインデックスを出力します。 

### なぜ効果があるのか

 すべてのステップで、アルゴリズムは、保存された車両が、処理されたすべての車両の中で到着時間が最も短い車両であるという不変条件を維持します。 各新車は、数学的に等価な分数の順序を使用して、この候補と比較されます。 到着時間は厳密に比較され、同点は存在しないため、不変条件により、すべての車両をスキャンした後、保存されたインデックスがグローバル最小値に対応することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def better(d1, v1, d2, v2):
    return d1 * v2 < d2 * v1

n, f = map(int, input().split())

best_idx = -1
best_d = 0
best_v = 1

for i in range(1, n + 1):
    x, v = map(int, input().split())
    d = f - x

    if best_idx == -1:
        best_idx = i
        best_d, best_v = d, v
    else:
        if better(d, v, best_d, best_v):
            best_idx = i
            best_d, best_v = d, v

print(best_idx)
```このコードは、時間を明示的に保存するのではなく、現在の最良の候補をペア \((d, v)\) として維持します。 これにより、浮動小数点演算が回避され、相互乗算を使用して正確な比較が維持されます。 ヘルパー比較関数は順序付けをエンコードします。\(d_1 / v_1 < d_2 / v_2\)整数演算で。 

による初期化`best_idx = -1`最初の車両が常にベースラインとして選択されるようにします。 後続の各車両がそれと比較され、厳密に短い到着時間が見つかった場合にのみ更新が行われます。

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose

    n, f = map(int, sys.stdin.readline().split())

    best_idx = -1
    best_d = 0
    best_v = 1

    def better(d1, v1, d2, v2):

    return str(best_idx)

 ## 特殊なケース

 単一の自動車の入力は、比較がないため簡単です。 アルゴリズムは最初の車を最良のものとして正しく初期化し、すぐに出力します。 

車が目的地に非常に近いところから発進するが非常に遅く、別の車がより遠くから発進するが速い場合、アルゴリズムは生の距離ではなく完全な比率を正しく比較します。 たとえば、\(f = 100\)、車 \((x=90, v=1)\) と \((x=0, v=10)\)、計算された時間は次のとおりです。\(10\)そして\(10\), しかし、この問題では同点がないことが保証されているため、厳密な不等式によって一貫して決定されます。 

複数の車が同じ位置を共有している場合、残りの距離が同じであるため、比較の速度が低下するだけです。 相互乗算ルールにより、自然に大きい方の選択が簡素化されます。\(v\)これは、より速い車が常に同じスタート地点から勝つという直観と一致します。
