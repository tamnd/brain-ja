 ## 解決策
 ## 問題の理解

 いくつかの文字列が与えられます。 各文字列に対して、正確に 1 文字を挿入する必要があります`'a'`ある位置で。 新しい文字列には長さが必要です`|s|+1`、回文であってはなりません。 あらゆる挿入が回文を生成する場合、解決策は存在しないと報告しなければなりません。 

入力には最大で次のものが含まれます`10^4`テスト ケース、すべての文字列の長さの合計は最大で`3·10^5`。 データの総量は適度であるため、実行時間が全長に沿って線形であるアルゴリズムは容易に十分に高速になります。 文字列ごとの 2 次作業は短い文字列の場合は問題ありませんが、3 次アプローチは不必要なオーバーヘッドになります。 

いくつかの特殊なケースは、誤って処理されやすいものです。 

最初のものは、完全に以下から構成される文字列です。`'a'`。 

入力：```
a
```唯一可能な挿入は、`"aa"`、これはまだ回文です。 正しい答えは次のとおりです。```
NO
```常に問題を引き起こす不用意な解決策`'a'`フロントにあると誤って出力されてしまいます`"aa"`。 

もう 1 つのケースは、ある挿入位置では回文が生成されるが、別の位置では機能する場合です。 

入力：```
ab
```最後に挿入すると、`"aba"`、これは回文ですが、先頭に挿入すると次のようになります。`"aab"`、そうではありません。 正しい答えは次のとおりです。```
YES
aab
```1 つの位置のみをチェックするソリューションでは、有効な構造が見逃される可能性があります。 

すでに回文になっているが、依然として有効な答えが認められる文字列もあります。 

入力：```
aba
```追加`'a'`前に与える`"aaba"`、これは回文ではありません。 回文であることは、最初は不可能であることを意味するものではありません。 

## アプローチ

 単純なブルートフォース手法ですべてを試す`n+1`挿入位置。 位置ごとに、結果の文字列を構築し、その文字列が回文であるかどうかを確認します。 考えられるすべての挿入が検査されるため、この方法は正しいです。 

問題は、次の長さの文字列です。`n`もっている`n+1`候補の位置、および候補が回文であるかどうかを確認するには、`O(n)`時間。 文字列自体の構築にもコストがかかります`O(n)`。 全体の複雑さは次のようになります。`O(n²)`。 

与えられた制約があれば、全長はわずかであるため、二次時間さえも実際には許容されます。`3·10^5`。 それでも、問題の構造ははるかに単純です。 

重要な観察点は、元の文字列に次の文字以外の文字が含まれている場合です。`'a'`の場合、2 つの構造のうちの 1 つが機能する必要があります。 

先頭に追加できます`'a'`、生産```
a + s
```または追加する`'a'`、生産```
s + a
```両方とも回文だったとしましょう。 以来```
a+s
```は回文なので、最初と最後の文字を削除すると、文字列の残りの部分が対称である必要があることがわかります。 と同じことをする```
s+a
```同じ結論につながります。 これらの条件を組み合わせると、すべての文字に次の条件が適用されます。`s`なる`'a'`。 

したがって、文字列に少なくとも 1 つの非`'a'`文字の場合、これら 2 つの構造のうち少なくとも 1 つは非回文であることが保証されます。 必要なのは 2 つの可能性をテストすることだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 承認済み |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 文字列を読み取る`s`。 
2. を追加して得られた文字列を構築します。`'a'`正面にあります。 
3. この新しい文字列が回文であるかどうかを確認します。 そうでない場合は出力します`"YES"`そしてこの文字列。 
4. それ以外の場合は、次の値を追加して取得した文字列を構築します。`'a'`最後に。 
5. この 2 番目の文字列が回文であるかどうかを確認します。 そうでない場合は出力します`"YES"`そしてこの文字列。 
6. 両方の候補が回文の場合、出力`"NO"`。 

2 つの位置のみが検査される理由は、次の文字と異なる文字を含む文字列が存在しないためです。`'a'`これらの候補の少なくとも 1 つを非回文にする必要があります。 

### なぜ効果があるのか

 アルゴリズムは 2 つの候補文字列を明示的にチェックします。`a+s`そして`s+a`。 どちらかが回文でなければ、それは有効な答えです。 

両方の候補が回文であると仮定します。 で`a+s`、最初と最後の文字は等しいため、最後の文字は`s`でなければなりません`'a'`。 これらの一致する文字を削除すると、回文が残ります。 この引数を繰り返すと、次のすべての文字が`s`は`'a'`。 このような文字列の場合、`'a'`別のすべてを生み出す`'a'`文字列は常に回文です。 したがって、解決策は存在しません。 

アルゴリズムは有効な文字列が存在する場合は常にそれを出力し、レポートするため`"NO"`まさに、解決策が存在しない場合、それは正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_palindrome(s):
    return s == s[::-1]

t = int(input())
ans = []

for _ in range(t):
    s = input().strip()

    front = 'a' + s
    if not is_palindrome(front):
        ans.append("YES")
        ans.append(front)
        continue

    back = s + 'a'
    if not is_palindrome(back):
        ans.append("YES")
        ans.append(back)
    else:
        ans.append("NO")

print("\n".join(ans))
```ヘルパー関数は、文字列がその逆の文字列と等しいかどうかをチェックします。 Python スライスにより、この操作が簡潔になり、直線的な時間で実行されます。 

各テスト ケースについて、コードはまず次のことを試みます。`'a'`正面にあります。 その文字列が回文でない場合は、すぐに答えを記録し、次のテスト ケースに進みます。 

最初の試行が失敗した場合、コードは配置を試行します。`'a'`最後に。 両方の候補が回文である場合にのみ印刷されます`"NO"`。 

有効な構造が見つかると、他のものをテストする理由がなくなるため、順序が重要になります。 

境界条件は単純です。 長さ 1 の文字列は自然に処理されます。 例えば、`"a"`につながる`"aa"`どちらの試行でも、答えは次のようになります`"NO"`。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    def is_palindrome(s):
        return s == s[::-1]

    t = int(input())
    ans = []

    for _ in range(t):
        s = input().strip()

        front = 'a' + s
        if not is_palindrome(front):
            ans.append("YES")
            ans.append(front)
            continue

        back = s + 'a'
        if not is_palindrome(back):
            ans.append("YES")
            ans.append(back)
        else:
            ans.append("NO")

    return "\n".join(ans)
