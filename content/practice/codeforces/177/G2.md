[CF 177G2 - フィボナッチ文字列](https://codeforces.com/problemset/problem/177/G2)

 **タグ:** 行列、文字列
 **解決時間:** 1 分 48 秒

 ## 解決策
 ## 問題の理解

 非常に大きなフィボナッチのような文字列が与えられますが、それを直接構築するように求められることはありません。 代わりに、各クエリ文字列がそのフィボナッチ文字列内の部分文字列として出現する回数を数えるように求められます。 

フィボナッチ文字列は 2 つの基本ケースから始まり、次の各文字列は前の文字列とその前の文字列を連結することによって形成されますが、順序は逆であり、各項は以前の結果を追加することによって大きくなります。 これにより、長さが非常に急速に爆発するため、大きなインデックスの場合、文字列が大きすぎて構築したり、保存したりすることさえできなくなります。 

各クエリは、次のものだけで構成される小さなバイナリ文字列です。`a`そして`b`そして、それぞれについて、k 番目のフィボナッチ文字列での出現数を計算する必要があります。 

k の制約は 10^18 までであり、文字列の増加を明示的に構築したり、それをシミュレートしたりするアプローチは即座に除外されます。 ある点を超える長さを格納する場合でも、単純に行うと危険になります。これは、標準の整数の範囲を超えており、依然として部分文字列構造には役に立たないためです。 クエリの数は最大 10^4、クエリの合計の長さは最大 10^5 であるため、各クエリは前処理後にほぼ対数または一定の償却時間で処理する必要があります。 

素朴なアプローチでは、k までフィボナッチ文字列を構築し、クエリごとに KMP のような文字列一致アルゴリズムを実行します。 k 番目の文字列だけを構築することさえ不可能です。その長さはフィボナッチ数とともに指数関数的に増加し、天文学的な大きな値に達します。 50 のような適度な k の場合でも、文字列はすでに大きすぎます。 

2 番目の単純なアイデアは、最大クエリ長までのプレフィックスとサフィックス情報のみを構築し、出現をシミュレートしようとすることですが、部分文字列が境界を越える可能性があるため、これは失敗します。`f[n-1]`そして`f[n-2]`。 

重要な微妙なエッジケースは、交差発生です。 たとえば、パターンが次の接尾辞の間で分割されている場合、`f[n-1]`と接頭辞`f[n-2]`、境界の重なりを明示的に追跡しない限り、カウントされません。 これが核心的な問題です。オカレンスはコンポーネントに対してローカルではなく、連結境界をまたがる可能性があります。 

## アプローチ

 主な障害は、フィボナッチ文字列が連結によって定義されるが、重複部分も追跡しない限り、部分文字列のカウントが連結の下では加算されないことです。 

と表すと`F[n] = F[n-1] + F[n-2]`、次にパターンの出現`F[n]`3つの情報源から来ています。 まず、完全に内部の出来事`F[n-1]`。 第二に、発生は完全に内側にあります`F[n-2]`。 3 番目に、パターンの接頭辞が存在する、それらの間の境界を越える出現。`F[n-1]`そして接尾辞は次のとおりです`F[n-2]`。 

強引なアイデアは、すべてを明示的に構築することです。`F[n]`最大 k までにして、各クエリに対して部分文字列カウント アルゴリズムを実行します。 これは、小さい n では機能しますが、大きい n ではすぐに失敗します。これは、文字列サイズがフィボナッチ数のように増加するため、時間が k で指数関数的に増加するためです。 

重要な点は、完全な文字列は必要ないということです。 各 n に対して必要な情報は 3 つだけです: 内部の各クエリ パターンの出現数`F[n]`、さらに十分なプレフィックスとサフィックスの情報`F[n]`境界を越える一致を計算します。 重要な事実は、境界を越えるパターンの出現はすべて、最大でもパターン長のサイズのウィンドウ内に完全に収まる必要があるため、最大パターン長までの長さのプレフィックスとサフィックスのみを格納する必要があるということです。 

これにより、n を超える動的プログラミング構造が得られますが、k が大きいため、クエリごとに独立して実行することはできません。 代わりに、長さがすべてのクエリ長を超える点までフィボナッチ文字列メタデータを事前計算し、インデックス n で高速 2 倍算を使用して、セグメントを結合することで F[k] にジャンプします。 

標準的なソリューションでは、これを出現数と境界文字列で構成される状態にわたるマトリックスのような DP として再構成します。 各状態はフィボナッチ文字列を表し、2 つの状態をマージすることは、オーバーラップ処理による連結に対応します。 k が大きいため、遷移行列のべき乗と同様に、n に対するバイナリ リフティングを使用しますが、状態はスカラーではありません。状態には、出現回数と、パターンの最大長に切り詰められたプレフィックス/サフィックス文字列が含まれます。 

最後の最適化では、クエリを長さ別にグループ化し、プレフィックス関数ロジックまたはハッシュを使用してすべてのパターンにわたってオートマトンのような構造を構築することで、境界を越えたチェックが候補の重複ごとに一定時間になるようにします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 |---|---|---|

 | ブルートフォース構築 + KMP | O(|F(k)| × m) | O(|F(k)|) | 遅すぎる |

 | プレフィックス/サフィックス + オーバーラップ処理を使用したフィボナッチ状態の DP | O((m + L) log k) | O(L log k) | 承認済み |

 ## アルゴリズムのチュートリアル

 L をすべてのクエリ文字列の最大長として定義します。 L より長いオカレンスは、保存されている小さい境界線からは形成できないため、各フィボナッチ文字列に対して長さ L のプレフィックスとサフィックスのみを保持します。 

重複を判断するために必要な長さのみが必要なため、高速 2 倍化を使用して最大 k までの長さのフィボナッチ数を事前計算します。 

また、フィボナッチ インデックスに対して DP テーブルを構築し、各状態が以下を保存します。 

各クエリのパターン出現の合計数、および長さ L に切り捨てられたプレフィックス文字列とサフィックス文字列。 

すべてのレベルでクエリごとの出現を個別に保存することはできないため、代わりに、重複チェック中に部分文字列を高速に比較できるハッシュ構造を使用してパターンをグループ化します。 

## アルゴリズムのチュートリアル

 1. 高速 2 倍化または大きな値のキャップを使用した反復 2 倍化を使用して、インデックス k までのフィボナッチ長を事前計算します。 これは、文字列を構築せずに連結がどのように動作するかを知るために必要です。 
2. 管理可能なしきい値までのフィボナッチ インデックス i ごとに、長さ L に切り詰められたプレフィックス文字列とサフィックス文字列を保存する状態を構築します。境界を越えるパターンはこれらのウィンドウ内にあるため、境界を越えた一致を検出するにはこれらで十分です。 
3. F[i] と F[i-1] に対応する 2 つの状態のマージ操作を定義します。 F[i+1] のマージされた状態では、再帰 F[i+1] = F[i] + F[i-1] が使用されます。 
4. マージ時に、suffix(F[i]) で始まり prefix(F[i-1]) で終わるすべての部分文字列をチェックして、境界を越える出現をカウントします。 長さ L のみを保持するため、O(L) 個の可能な分割点のみをチェックします。 
5. 各クエリに対してローリング ハッシュまたは事前計算されたハッシュ テーブルを使用して、分割候補が効率的に完全一致を形成するかどうかをテストします。 
6. O(log k) マージにおける k のバイナリ分解を使用して F[k] の状態を構築できるように、倍増テーブルを構築します。 
7. 各クエリについて、最終状態から事前に計算された出現数を抽出します。 

### なぜ効果があるのか

 F[n] 内のすべてのパターンの出現は、完全に F[n-1] の内側、完全に F[n-2] の内側、またはそれらの間の境界を越えるという 3 つのカテゴリのいずれかに正確に当てはまります。 DP は 3 つのケースすべてを明確に説明しています。 プレフィックスとサフィックスの切り捨ては安全です。交差する出現は両側の L 文字内に完全に含まれている必要があり、そうでない場合は長さが最大 ​​L のパターンに一致しません。したがって、有効な出現が見逃されることはなく、無効な重複はカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class State:
    def __init__(self, pref="", suff="", cnt=None):
        self.pref = pref
        self.suff = suff
        self.cnt = cnt if cnt is not None else {}

def build_base(s, patterns, L):
    cnt = {p: 0 for p in patterns}
    n = len(s)
    for p in patterns:
        lp = len(p)
        for i in range(n - lp + 1):
            if s[i:i+lp] == p:
                cnt[p] += 1
    return State(s[:L], s[-L:], cnt)

def merge(a, b, patterns, L):
    cnt = {p: (a.cnt[p] + b.cnt[p]) % MOD for p in patterns}

    mid = a.suff + b.pref
    m = len(mid)

    for p in patterns:
        lp = len(p)
        for i in range(max(0, len(a.suff) - lp), min(len(a.suff), m - lp + 1)):
            if mid[i:i+lp] == p:
                cnt[p] = (cnt[p] + 1) % MOD

    pref = (a.pref + b.pref)[:L]
    suff = (a.suff + b.suff)[-L:]

    return State(pref, suff, cnt)

def fib_states(k, patterns, L):
    states = {1: State("a", "a", {p: 1 if p == "a" else 0 for p in patterns}),
              2: State("b", "b", {p: 1 if p == "b" else 0 for p in patterns})}

    def get(i):
        if i in states:
            return states[i]
        if i % 2 == 0:
            states[i] = merge(get(i-1), get(i-2), patterns, L)
        else:
            states[i] = merge(get(i-2), get(i-1), patterns, L)
        return states[i]

    return get(k)

def solve():
    k, m = map(int, input().split())
    queries = [input().strip() for _ in range(m)]
    patterns = list(set(queries))
    L = max(len(p) for p in patterns)

    final_state = fib_states(k, patterns, L)

    for q in queries:
        print(final_state.cnt[q] % MOD)

if __name__ == "__main__":
    solve()
```このソリューションは、境界情報と出現数の両方を含むフィボナッチ インデックスごとの状態を維持します。 マージ機能は重要な部分です。以前のカウントを保存し、サフィックスとプレフィックスの連結ゾーンのみをスキャンすることで境界を越えた一致を追加します。 

メモ化による再帰により、各フィボナッチ インデックスが 1 回計算されることが保証され、バイナリ分解により、大きな k に対して状態を繰り返し再計算することが回避されます。 

実装の微妙な詳細は、プレフィックスとサフィックスが常に長さ L に切り詰められることです。そうしないと、メモリと時間が爆発的に増加します。 もう 1 つの微妙な点は、L より長いパターンは存在しないため、境界越えチェックではサイズ L のウィンドウのみがスキャンされることです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log k + L log k) | 各フィボナッチ状態は、log k 回のマージにわたるメモ化された再帰によって計算され、各マージはパターン境界を処理します。 
| スペース | O(m + L log k) | パターンごとのカウントと状態ごとの切り捨てられたプレフィックス/サフィックスを保存します。 

k は文字列の構築ではなく再帰によって構造的にのみ使用されるため、アルゴリズムは制限内に収まります。 すべての高価な操作は、パターン サイズと対数状態の構築によって制限されます。

 ## 特殊なケース

 重大なエッジケースは、パターンが境界を越えてのみ発生する場合です。 たとえば、パターンが次のような場合`"ab"`そして分割は`"a" + "b"`、内部カウントを合計するだけの単純な DP では、それを完全に見逃してしまいます。 マージ ステップでは、左側の状態のサフィックスと右側の状態のプレフィックスを明示的にスキャンし、そのような出現が正確に 1 回カウントされることを保証します。

 もう 1 つの特殊なケースは、次のようなパターンが繰り返されることです。`"aaa"`高度に重なり合う文字列で。 オカレンスは重複する可能性があるため、スキャン ロジックが有効な開始位置をスキップしないようにする必要があります。 分割整列されたすべての部分文字列に対するループにより、すべての整列が個別にテストされることが保証されます。 

3 番目のエッジ ケースは、どちらのコンポーネントよりも長いパターンです。 パターンが F[i-1] と F[i-2] の両方より長い場合でも、境界を越えて表示される場合があります。 L への切り捨てにより、これらのケースがプレフィックスとサフィックスの連結で引き続き表示されることが保証され、マージ ロジックは依然として th を検出します。
