 ## 解決策
 ## 問題の理解

 正の整数値を選択しています$x$、これは、スマート ビーバーが梱包する「スーツケースあたりのプレゼント」の数を表します。 スーツケースの総数は惑星ごとに固定されています$i$、彼は正確に運びます$a_i$スーツケースなので、スーツケースの合計数はすべての合計になります。$a_i$。 各スーツケースには以下のものが入っているので、$x$プレゼントの場合、プレゼントの総数は線形です。$x$、 具体的には$x \cdot \sum a_i$。 

旅は惑星の連続です。 地球上で$i$、ビーバーは非常に計画的な方法で時間を過ごします。初日は常に「自由な」日であり、贈り物はありません。 2日目以降、彼は毎日正確に与えます$b_i$それぞれにプレゼント$b_i$国民だから彼は消費する$b_i^2$毎日のプレゼント。 彼は翌日のギフトを完全に供給できなくなるまで続けます。つまり、少なくとも残りのプレゼントが残っている最終日に停止します。$b_i^2$。 

したがって、各惑星の日数は、サイズの完全な「ブロック」の数によってのみ決まります。$b_i^2$割り当てられたプレゼントと最初の到着日に収まります。 総旅行時間はこれらの惑星ごとの所要時間の合計であり、正の整数がいくつあるかを数えたいとします。$x$合計時間を正確に計る$c$。 

制約は重要です。$n$まで可能です$10^4$および最大値$10^9$、つまり、すべてを試した解決策は$x$あるいは候補者ごとにシミュレーションすることは不可能です。 評価する関数は次の点で単調です。$x$: 増加$x$プレゼントを増やしてもギフトを贈る能力を延長または保持することしかできないため、費やす日数は決して減りません。 この単調性が二分探索を可能にするキー構造です。 

惑星が最初の日を超えてギフト日数を寄付しない場合、エッジケースが発生します。 もし$a_i \cdot x < b_i^2$, その場合、ビーバーはその惑星で1日のギフトデーを完了することさえできないため、滞在はちょうど1日になります。 このしきい値の動作は、単純な浮動小数点または整数の除算の推論が破綻することがよくある場所です。 

もう一つの微妙なケースは次のような場合です。$a_i = 0$。 その場合、プレゼントは決して手に入らないので、地球は常に正確に 1 日を寄付します。$x$。 で割るあらゆるアプローチ$a_i$ここで失敗するでしょう。 

## アプローチ

 直接的なアプローチは、次の値を固定することです。$x$、すべての惑星の合計日数を計算し、それが等しいかどうかを確認します。$c$。 惑星ごとに、私たちがどれだけの完全なギフトデーを維持できるかを計算します。 毎日お金がかかるので$b_i^2$プレゼント、そして私たちはから始めます$a_i x$プレゼントの場合、最初の日数後の追加日数は$\left\lfloor \frac{a_i x}{b_i^2} \right\rfloor$。 すべての惑星を合計すると、旅行距離の合計が得られます。 

これは正しく機能しますが、可能なすべての処理を繰り返す必要があります$x$。 回答空間には制限がありませんが、事実上、関数が範囲を超える点まで検索する必要があります。$c$。 関数はほぼ直線的に増加するため、$x$、次のような大きな境界までのブルートスキャン$10^9$実現不可能です。 

重要な観察は、合計日数が次の関数として変化することです。$x$単調非減少です。 各学期$\left\lfloor \frac{a_i x}{b_i^2} \right\rfloor$次の場合にのみ増加します$x$特定のしきい値を超えます。 この構造により、最小値と最大値の二分探索が可能になります。$x$正確に生産する$c$日を指定してから、整数の範囲をカウントします。 

問題を単調関数を見つけることに帰着させます$f(x)$そしてすべての整数を数えます。$f(x) = c$、これは区間の境界を見つけることになります。$f(x) \le c$そして$f(x) < c+1$。

 ## アルゴリズムのチュートリアル

 関数を定義します$f(x)$合計旅行時間を計算します。 

1.固定の場合$x$、すべての惑星の合計日数を計算します。 各惑星は 1 基準日を寄与し、さらに$\left\lfloor \frac{a_i x}{b_i^2} \right\rfloor$追加の日数。 これは、「最初の日は無料、その後は繰り返されるギフト サイクル」の構造をモデル化しています。 
2. 関数を実装する`calc(x)`すべての惑星にわたって反復され、この寄与が蓄積されます。 128 ビットの安全な算術演算または Python 整数を使用する必要があります。$a_i x$到達できる$10^{18}$。 
3. 最小値の二分探索$x$そのような`calc(x) >= c`。 これにより、旅行が少なくとも次の場所にある最初の値が得られます。$c$何日も。 
4. 最小値の二分探索$x$そのような`calc(x) > c`。 これにより、旅行が厳密に超過する最初の値が得られます。$c$日々。 
5. 答えは整数の数です$x$合間に$[L, R)$、 どこ$L$少なくとも最初の位置です$c$日々と$R$以上の最初の位置です$c$日々。 もし$L > R - 1$、答えはゼロです。 

特殊なケースは次のような場合です$calc(1) > c$、どんなに小さなことでも意味します$x$目標をオーバーシュートします。 その場合、解決策は存在しません。 

### なぜ効果があるのか

 機能$f(x)$増加しているため単調非減少です$x$増加または維持する$a_i x$したがって、フロア分割期間を決して減らすことはありません。 したがって、のセットは、$x$満足のいく$f(x) = c$は常に連続する整数セグメント (空の可能性があります) です。 二分探索ではこのセグメントの境界が正確に識別されるため、その長さを数えることで有効な値の正確な数が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, c = map(int, input().split())
a = []
b = []

for _ in range(n):
    ai, bi = map(int, input().split())
    a.append(ai)
    b.append(bi)

def calc(x):
    res = 0
    for i in range(n):
        res += 1
        if a[i] == 0:
            continue
        res += (a[i] * x) // (b[i] * b[i])
    return res

def f_leq(x):
    return calc(x) <= c

def f_lt(x):
    return calc(x) < c

def binary_search_first_true(check):
    lo, hi = 1, 10**18
    ans = hi + 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if check(mid):
            ans = mid
            hi = mid - 1
        else:
            lo = mid + 1
    return ans

L = binary_search_first_true(lambda x: calc(x) >= c)
R = binary_search_first_true(lambda x: calc(x) > c)

if L > R - 1:
    print(0)
else:
    print(R - L)
```の`calc(x)`関数は惑星ごとの貢献公式を直接実装します。 乗算は除算の前に行われ、Python の大きな整数により、固定幅言語で発生するオーバーフローの問題が防止されます。 

2 つのバイナリ検索を実行します。1 つは最初のバイナリ検索です。$x$少なくとも到達する$c$、最初の超過に対して 1 つ$c$。 答えは、結果として得られる整数間隔のサイズです。 

よくある落とし穴は、贈り物が届かない場合でも、すべての惑星が少なくとも 1 日は貢献していることを忘れることです。 この基本用語は常にバイナリ検索ロジックの前に追加する必要があります。 

## 実用的な例

```どのように評価するか`calc(x)`振る舞います。 

| × | プラネット 1 の寄稿 | プラネット 2 への貢献 | 合計 |
 | --- | --- | --- | --- |
 | 4 | 1 + 0 = 1 | 1 + 0 = 1 | 2 |
 | 5 | 1 + 1 = 2 | 1 + 0 = 1 | 3 |
 | 6 | 1 + 1 = 2 | 1 + 1 = 2 | 4 |
 | 7 | 1 + 1 = 2 | 1 + 1 = 2 | 4 |

 合計がちょうど 5 に達するまで増加を続けます。 これは次の場合にのみ発生します$x = 5$問題の離散ジャンプの構造に応じて。 二分探索では、この単一の有効な整数が分離されます。 

このトレースは、寄与が滑らかではなく段階的に増加し、複数の惑星が区分定数関数の合計を通じて相互作用していることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n, c = map(int, input().split())
    a = []
    b = []
    for _ in range(n):
        ai, bi = map(int, input().split())
        a.append(ai)
        b.append(bi)

    def calc(x):
        res = 0
        for i in range(n):
            res += 1
            if a[i] == 0:
                continue
            res += (a[i] * x) // (b[i] * b[i])
        return res

    def f(x):
        return calc(x)

    def first_geq(target):
        lo, hi = 1, 10**6
        ans = hi + 1
        while lo <= hi:
            mid = (lo + hi) // 2
            if f(mid) >= target:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1
        return ans

    L = first_geq(c)
    R = first_geq(c + 1)

    if L > R - 1:
        return "0"
    return str(R - L)

 ## 特殊なケース

 主なエッジケースは、$a_i = 0$。 このような惑星の場合、貢献度は常に正確に 1 日です。$x$, プレゼントが届くことはないので。 アルゴリズムは、次の場合に乗算をスキップすることでこれを明示的に処理します。$a_i = 0$、分割アーチファクトが発生しないようにします。 

もう 1 つのエッジケースは次のような場合です$c$可能な最小移動時間よりも短いです。 すべての惑星が少なくとも 1 日は寄与するため、最小合計は次のようになります。$n$。 もし$c < n$、どちらの二分検索でも空の範囲が返され、最終的な答えは自然にゼロになります。 

最後の微妙なケースは次のような場合です。$x$非常に大きいです。 それでも$x$概念的には次まで行くことができます$10^{18}$、バイナリ検索は安全に上限を設定します。$calc(x)$を超える$c$、さらなる成長は無関係です。 これにより、オーバーフローが防止され、最大入力範囲下でも計算が安定します。
