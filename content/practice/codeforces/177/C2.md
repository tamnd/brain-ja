 ## 解決策
 ## 問題の理解

 私たちは、友情関係で結ばれているペアもあれば、お互いを嫌っているために対立しているペアもある、一組の人々を与えられています。 友情は連鎖を通じて推移的であるため、友情グラフ内の接続されたコンポーネントは、そのグループのメンバーを含めることを決定した場合、分離不可能なものとして扱う必要があるグループを表します。 

目標は、3 つの制約が同時に成立するように、招待する人のサブセットを選択することです。 まず、ある人が招待された場合、その友人関係にあるコンポーネントの全員も招待する必要があります。これは、部分的に含めると、招待された人の友人全員が出席するという要件が破られてしまうためです。 第二に、招待されたグループには、お互いに嫌悪感を抱く人々のペアを含めることはできません。 第三に、招待されたすべての人々は友情グラフ内で単一の接続コンポーネントを形成する必要があります。これは、最終的に選択されたセットが完全に 1 つの友情コンポーネント内に存在する必要があることを意味します。 

したがって、問題の構造は次のようになります。友情エッジは接続されたコンポーネントを定義し、ユニオンが内部で接続され、その中に嫌いエッジがないコンポーネントのサブセットを選択する必要があります。 接続性はすでに友情によって決定されているため、「単一接続コンポーネント」条件は、実際に友情エッジを介して接続されていない限り、複数の切断された友情コンポーネントを選択できないことを意味しますが、これはコンポーネントの定義では不可能です。 したがって、最終的な答えは、嫌いの制約によって引き起こされる互換性のない選択を削除した後の単一の友情コンポーネントのサイズになります。 

制約は非常に重要です。 最大 2000 人の人々の場合、友情グラフには最大 2000 のノードと同様のスケールまでのエッジを含めることができます。 これにより、すべての人々に対する指数関数的なサブセットの列挙が除外されます。$2^{2000}$、それは不可能です。 ただし、コンポーネント レベルで制約を処理する場合と同様に、線形時間で接続コンポーネントを計算することは可能です。 

単純な間違いは、「すべての友達を含める必要がある」というルールを無視して、嫌いなペアをローカルで貪欲に削除しようとすることです。 たとえば、3 人が友情の三角形を形成し、そのうちの 2 人がお互いを嫌っている場合、1 つのエンドポイントを貪欲に削除すると、接続性が侵害されたり、一貫性のない部分選択が強制されたりする可能性があります。 もう 1 つの微妙な失敗例は、嫌いエッジがコンポーネント内ではなくコンポーネント間に存在し、ソリューションがコンポーネント全体ではなく個々のコンポーネントを誤って破棄した場合に発生します。 

## アプローチ

 重要な観察は、友情エッジが強制的なグループ、つまり接続されたコンポーネントを定義するということです。 コンポーネントが計算されたら、有効な招待にはコンポーネント全体が含まれるか、コンポーネント全体が除外される必要があります。これは、部分的な選択はフレンドに対するクロージャ要件に違反するためです。 

ブルートフォースアプローチでは、人々のサブセットを選択して妥当性をチェックしようとします。 各サブセットについて、ある人が含まれている場合はその人の友人がすべて含まれていること、サブセット内に嫌悪感のエッジが存在しないことを検証します。 これには、すべてのサブセットを反復処理し、制約を検証する必要があり、大まかに次のようになります。$O(2^n \cdot n)$あるいはさらに悪いことに。 と$n = 2000$、これはまったく不可能です。 

重要な簡素化は、DSU または DFS を使用してグラフを連結コンポーネントに圧縮することです。 その後、各コンポーネントは「スーパーノード」となり、全体として捉える必要があります。 個人間の嫌悪感はコンポーネント間の衝突につながります。 コンポーネント内に嫌いエッジがある場合、そのコンポーネントは完全に無効になり、使用できなくなります。 コンポーネント間では、互換性のないコンポーネントを一緒に選択しないようにするだけで済みます。 ただし、この要件では、招待されたすべてのユーザーが友情を介して接続されていることが強制されるため、最終的には有効なコンポーネントを 1 つだけ選択できるため、答えは内部的な嫌悪感を含まない最大の有効な接続コンポーネントに帰着します。 

これにより、問題は、友情エッジから接続されたコンポーネントを構築し、嫌いエッジによって引き起こされる内部競合がないか各コンポーネントをチェックすることに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットに対するブルート フォース |$O(2^n \cdot n)$|$O(n)$| 遅すぎる |
 | DSU / DFS コンポーネント + 検証 |$O(n + k + m)$|$O(n + k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 私たちは友情エッジを接続性を定義するものとして扱います。 

1. 全体的なDSU体制を構築する$n$ノードとすべての友情ペアを結合します。 これにより、各コンポーネントが選択された場合に完全に取得される必要がある候補グループとなる連結コンポーネントが形成されます。 DSU を使用する理由は、ほぼ一定時間のマージと効率的なコンポーネント抽出が行われるためです。 
2. コンポーネントを形成した後、各ノードをそのコンポーネントの代表者に割り当てます。 この段階では、各コンポーネントは、一緒に移動することを強制される最大の人々の集合を表します。 
3. コンポーネントが「不良」かどうかを追跡する構造を作成します。 同じコンポーネント内の 2 つのノードに嫌いエッジが接続されている場合、コンポーネントは不良になります。 このようなコンポーネントは完全に選択できないため、これは非常に重要です。 
4. すべての嫌いなペアに対して繰り返します。 各ペアについて、DSU の代表者を見つけます。 両方のエンドポイントが同じ代表者に属している場合は、そのコンポーネントを無効としてマークします。 
5. 有効な各コンポーネントのサイズを計算します。 答えは、無効とマークされていないすべてのコンポーネントの最大サイズです。 

### なぜ効果があるのか

 フレンドリークロージャーは、接続されている各コンポーネントをアトミックなものとして扱うことを強制します。 有効な招待セットはコンポーネント全体の結合である必要がありますが、選択したセットのすべてのメンバーは友情を通じて相互に到達可能である必要があるため、セットは複数の切断されたコンポーネントにまたがることはできません。 これにより、選択肢は 1 つのコンポーネントだけを選択することになります。 

残りの唯一の制約は内部一貫性です。選択したコンポーネント内では嫌いエッジは許可されません。 したがって、内部対立を含まないすべての友情要素の中で、最大のものを選択します。 複数のコンポーネントを含む構成では接続性を満たすことができないため、削減は正確になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

def solve():
    n = int(input())
    k = int(input())

    dsu = DSU(n)

    for _ in range(k):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        dsu.union(u, v)

    m = int(input())

    bad = [False] * n

    for _ in range(m):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        ru, rv = dsu.find(u), dsu.find(v)
        if ru == rv:
            bad[ru] = True

    for i in range(n):
        dsu.find(i)

    best = 0
    for i in range(n):
        if dsu.find(i) == i and not bad[i]:
            best = max(best, dsu.size[i])

    print(best)

if __name__ == "__main__":
    solve()
```DSU は、友情構造をコンポーネントに分解するために使用されます。 すべての結合を処理した後、各ルートはそのコンポーネントのフルサイズを保存します。 

嫌いの処理ステップは慎重です。両方のエンドポイントが同じルートを共有している場合にのみ、コンポーネントを不良としてマークします。 いずれにせよ、これらのコンポーネントは単一の接続セットに部分的にマージできないため、異なるコンポーネント間の不一致は問題になりません。 

最後のループは DSU ルートのみを反復し、最大の有効なコンポーネントを選択します。 

微妙な点は、最後のパス圧縮ループです。 電話せずに`find(i)`すべてのノードについて、一部のノードがルートを直接指していない可能性があり、反復時にルートの識別を見逃す可能性があります。 これにより、正しいルート検出が保証されます。

 ## 特殊なケース

 厄介なケースは、嫌いなエッジが友情コンポーネント内でサイクルを形成する場合です。 アルゴリズムは、そのようなエッジがいくつ存在するかではなく、存在するかどうかだけをチェックするため、これを正しく処理します。 単一の内部矛盾が見つかると、コンポーネント全体が無効になります。これは、嫌いな人物のペアは共存できないという要件と一致します。 

もう 1 つのエッジ ケースは、すべてのノードが分離されている場合です。 その状況では、各ノードはサイズ 1 のコンポーネントを形成し、制約により不可能な自己完結型の嫌悪感が存在しない限り、どのノードも不良としてマークされません。 アルゴリズムは正しく 1 を返します。 

最後の微妙なケースは、嫌いなものが異なるコンポーネントを接続するだけである場合です。 アルゴリズムはこれらを完全に無視します。これは正しいことです。そのようなコンポーネントは友情制約の下では決して単一の接続セットにマージされないため、コンポーネント間の競合によって単一コンポーネントの選択が制限されることはありません。
