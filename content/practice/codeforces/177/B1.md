 ## 問題の理解

スコアは、開始値と最終値を含む、プロセス中に発生したすべての値の合計です。`1`。 その合計を最大化する必要があります。

これは正しいです。すべての有効なゲームがこの除数グラフのパスに対応し、再帰によってすべての可能性が探索されるからです。

最適な戦略を見つけるには、その手が実際に何をするのかを調べる必要があります。 

現在の値が`x`。 有効な次の値は、次の適切な約数である必要があります。`x`。

これは、すべての適切な約数の中で、常に最大のものを選択する必要があることを示唆しています。

### なぜ効果があるのか

 任意の現在値に対して`x`、法的に次のすべての状態は、次の適切な約数になります。`x`。 

させて`m`～の最大の適切な約数となる`x`。 他のすべての法的措置は何らかの除数につながります`d < m`。 

選択する`m`選択するよりもすぐにスコアが増加します`d`。 さらに、到達可能なすべての将来の値は、`d`せいぜい`d`、一方、から到達可能な将来の値は`m`大きい数から始めてください。 交換中`d`による`m`合計スコアを減らすことはできません。 

したがって、最適な解決策は常に最大の適切な約数を選択する必要があります。 

の最大の適正約数`x`を割ることで得られます`x`最小の素因数で計算します。 すべてのステップでこの貪欲な選択を繰り返すと、最適な除数チェーンが得られ、したがって最大のスコアが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def smallest_prime_factor(x):
    d = 2
    while d * d <= x:
        if x % d == 0:
            return d
        d += 1
    return x

def solve():
    n = int(input())

    ans = n
    cur = n

    while cur > 1:
        p = smallest_prime_factor(cur)
        cur //= p
        ans += cur

    print(ans)

if __name__ == "__main__":
    solve()
```変数`ans`ランニングスコアを保存します。

現在の値が素数の場合、返される最小の素因数は数値そのものです。 それで割ると、`1`、プライムは直接移動することしかできないというゲームのルールに正確に一致します。`1`。 

すべての算術演算は 64 ビット整数内に快適に収まります。 で割ることを繰り返したときに、考えられる最大の答えが得られます。`2`、それでも合計は以下になります`2n`, これは Python の制限よりもはるかに小さいです。
