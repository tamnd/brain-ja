 ## 解決策
 ## 問題の理解

 2 部構成の文字セットが与えられています。$n$男性と$n$女性。 Between them there are$k$結婚の可能性のあるペアがあり、各ペアは、そのカップルが最終的に結ばれた場合の視聴者の喜びを表す正の値を持ちます。 有効な「脚本の結果」とは、選択された複数のペアに男性または女性が登場しないような、これらのペアの選択です。 言い換えれば、2 部グラフでマッチングを選択していることになります。 

有効な各マッチングの合計値は、そのエッジの重みの合計に等しくなります。 すべての有効な一致をリストし、この合計によって昇順に並べ替えると、次の値を出力するように求められます。$t$そのソート順で - 番目に一致します。 

重要な構造上の詳細は次のとおりです。$k \le 100$, そのため、グラフのエッジは非常に小さくなります。 それでも$n$最大 20 まで指定できる場合、解は頂点ではなくエッジの数によって完全に制約されます。 

素朴な誤解は、エッジのサブセットを自由に選択していると考えることです。 これは頂点の競合によりすぐに失敗します。 もう 1 つのよくある間違いは、重みの増加順にエッジを貪欲に追加することでマッチングを生成できると考えることです。 順序付けがエッジではなくマッチング上であるため、これは機能しません。 

複数のエッジがエンドポイントを共有する場合、微妙なエッジ ケースが発生します。 

たとえば、次のことを考えてみましょう。```
n = 2, k = 3
1 1 5
1 2 1
2 1 1
```一致するものは次のとおりです。 

空集合 (0)、

 (1,2) (1)、

 (2,1) (1)、

 (1,2)+(2,1) は頂点が共有されているため無効です。 

したがって、2 つの異なる一致が同じ値を持つ可能性があり、順序付けではそれらを別個のエントリとして扱う必要があります。 値によって重複を排除するアプローチでは、誤った結果が生成されます。 

もう 1 つの問題は、一致の数が指数関数的に増加することです。$k$したがって、列挙は慎重に構造化する必要があります。 

## アプローチ

 以来$k \le 100$、各エッジは、それを含めるかどうかの二者択一の選択肢として考えることができます。 ブルート フォース ソリューションでは、エッジのすべてのサブセットを列挙し、選択したサブセットが有効な一致を形成するかどうかを確認し、その重みを計算し、結果を並べ替えます。 これは正しいですが、コストがかかります$O(2^k \cdot k)$、これは実現不可能です$k = 100$。 

重要な観察は、有効性は頂点の競合のみに依存するということです。$n \le 20$。 これは、エッジではなく頂点の占有によって状態を圧縮することを示唆しています。 

それぞれの男性と女性は、フリーまたはマッチングのいずれかです。 それはせいぜい$2n \le 40$したがって、ビットマスク表現は自然です。 各エッジは 1 人の男性と 1 人の女性を結び付けるため、頂点が 2 回出現しないという制約付きで、すべての一致はエッジのサブセットに対応します。 

これは、古典的な「すべての重み付けされたマッチングを昇順で生成する」問題になります。 すべてを生成して並べ替えるのではなく、州に対する最良優先検索を使用して、並べ替えられた順序で一致を生成します。 

現在使用されている頂点のセットと現在の総重みによって状態を定義します。 どの状態からでも、すでに使用されている頂点と競合しないエッジの追加を試みます。 優先キューを使用すると、常に最小の重みの部分一致が最初に拡張され、重みの昇順で効率的に一致が生成されます。 

以来$k$が小さい場合でも、到達可能な状態の数は管理可能なままです。特に、各エッジは有効なマッチングで 1 回だけ使用され、頂点の競合によってほとんどの組み合わせが排除されるためです。 

また、使用されている頂点ビットマスクと現在の選択コンテ​​キストによって状態をメモ化するので、同一の設定を再度参照する必要はありません。

 ## アルゴリズムのチュートリアル

 各部分一致を、使用された頂点のビットマスクと合計の重みを含む状態として扱います。 

1. 各男性と女性のインデックスを単一の統一頂点インデックス システムに変換します。 男性は$0 \ldots n-1$、女性は$n \ldots 2n-1$。 これにより、単一のビットマスクですべての競合を表すことができます。 
2. 空のマッチングを使用して優先キューを初期化します。頂点は使用せず、重みは 0 です。これは空のスクリプトに対応します。 
3. 優先キューから最も重みの小さい状態を繰り返し抽出します。 これにより、合計の満足度が高い順にマッチングが処理されるようになります。 
4. 状態が削除された場合、それを 1 つの有効な一致として扱います。 カウンターをインクリメントします。 このカウンタが等しい場合$t$、すぐにその重量を出力します。 
5. 抽出した状態をエッジごとに拡張してみます$(u, v, w)$。 どちらのエンドポイントもビットマスクでまだ使用されていないエッジのみを考慮します。 これにより、一致制約が保持されます。 
6. 有効な拡張子ごとに、更新されたビットマスクと更新された重みを使用して新しい状態を作成します。 それを優先キューにプッシュします。 
7. 同一の構成を再訪することを避けるために、ビットマスクとオプションでエッジインデックスの進行によってキー設定された訪問済みセットを維持し、異なるエッジ順序を通じて同等の状態が再生成されないようにします。 

### なぜ効果があるのか

 すべての有効なマッチングは、頂点制約を尊重する少なくとも 1 つのエッジ挿入シーケンスに対応します。 優先キューは、すべての部分一致の中で、最小の合計重みが常に最初に拡張されることを保証します。 すべてのエッジの重みは負ではないため、状態を拡張しても状態自体よりも小さな重みのマッチングを生成することはできません。 これにより、状態がポップされたときに、より小さい重みを持つ目に見えない一致が存在しないことが保証されるため、出力はグローバルにソートされた順序で表示されます。 

## Python ソリューション```python
import sys
import heapq
input = sys.stdin.readline

n, k, t = map(int, input().split())
edges = []

for _ in range(k):
    h, w, r = map(int, input().split())
    h -= 1
    w -= 1
    edges.append((h, n + w, r))

# state: (cost, mask)
# mask uses 2n bits: men [0..n-1], women [n..2n-1]

start = (0, 0)
pq = [(0, 0)]
visited = set([0])

count = 0

while pq:
    cost, mask = heapq.heappop(pq)

    count += 1
    if count == t:
        print(cost)
        break

    for u, v, w in edges:
        if not (mask & (1 << u)) and not (mask & (1 << v)):
            new_mask = mask | (1 << u) | (1 << v)
            if new_mask not in visited:
                visited.add(new_mask)
                heapq.heappush(pq, (cost + w, new_mask))
```コードは、すべての部分一致をビットマスクとしてエンコードします。$2n$頂点。 This directly enforces the rule that no vertex can appear twice. Each time we pop a state, we treat it as a complete valid matching candidate in increasing order of cost.

 The important implementation detail is that we only track visited states by their mask. このモデルでは、一度頂点が占有されるとエッジの再利用は常に禁止されるため、同じ占有頂点セットに到達する 2 つの方法が同等の将来の拡張の可能性につながるため、これで十分です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(S \log S \cdot k)$| 各状態は 1 回処理され、各展開ではすべてのエッジがスキャンされます。 
| スペース |$O(S)$| 優先キューと訪問セットは、到達可能なすべての頂点マスクを格納します。 

州の数$S$は、強力な頂点制約を持つ最大 100 個のエッジにわたる有効なマッチングの数によって制限されますが、これはビットマスク制限による積極的な枝刈りのため、実際には十分小さいです。$n \le 20$。 これは時間とメモリの両方の制限内に収まります。

 ## 特殊なケース

 1 つのエッジ ケースは、すべてのエッジが頂点を共有する場合であり、状態ごとに 1 つのマッチングのみが可能です。 どの拡張機能もすぐにビットマスク チェックに失敗し、シングルトン マッチングと空のセットのみが残るため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジ ケースは、異なる重みを持つ重複したエンドポイントです。 各エッジは入力内で独立しているため、両方が個別に処理され、ビットマスクによってそれらが折りたたまれません。 これにより、同一の構造的結果が生成される場合でも、個別の一致が複数回カウントされることが保証されます。 

最後のエッジケースは次のような場合です$t = 1$。 優先キューは空の一致を即座にポップし、アルゴリズムは拡張子を生成せずに終了し、正しく 0 を返します。
