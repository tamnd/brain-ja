 ## 解決策
 ## 問題の理解

 男性と女性の二部グラフが表示されます。 許可された各エッジは結婚の可能性を表し、視聴者がそのカップルをどれだけ楽しんでいるかを測るプラスの重みを持ちます。 

有効なスクリプトは、選択された複数のエッジに男性または女性が表示されないように、これらのエッジのセットを選択することに対応します。 言い換えれば、2 部グラフでマッチングを選択していることになります。 各マッチングの合計値は、そのエッジの重みの合計に等しくなります。 

すべての有効な一致をリストし、合計の重みで昇順に並べ替えると、この順序で t 番目の一致の値を出力するように求められます。 空の一致が常に最初になります。 

主な困難は、最大一致または最小一致を見つけることではなく、明示的に生成せずに、重みのソート順にすべての一致を列挙することです。 

この制約により、エッジの数が少ない場合にのみこれが実現可能になります。 最大で k ≤ 100 のエッジがあり、各エッジは n ≤ 20 人の男性の 1 人を n 人の女性の 1 人に接続します。 これは、グラフがまばらであり、有効な一致の数が潜在的に大きいにもかかわらず、中間一致スタイルの列挙で走査できるほど十分に構造化されていることを意味します。 

素朴な解釈では、エッジのすべてのサブセットを列挙し、有効な一致をフィルタリングしようとします。 これは最悪の場合でも 2^100 のサブセットであり、あまりにも大きすぎます。 

さらに微妙な問題は、有効性が頂点の使用法に依存することです。 単一のエッジが異なる 2 つのサブセットは、競合に応じて両方とも無効または有効になる可能性があるため、枝刈りが不可欠です。 

単純な列挙を破る典型的なエッジ ケースは、多くのエッジが 1 つの頂点を共有する場合です。 たとえば、すべての k 個のエッジが同じ人物を共有する場合、有効な一致には最大でも 1 つのエッジが含まれます。 ブルート サブセット列挙では、依然として 2^k 個のサブセットが考慮されますが、そのほとんどは無効であり、指数関数的な時間を無駄にします。 

## アプローチ

 この構造は、エッジ セットをサイズが約 50 の 2 つの半分に分割することを示唆しています。 これは、衝突を伴う制約下でのサブセット選択問題の古典的な中間パターンです。 

それぞれの半分について、その半分内で有効な一致を形成するすべてのサブセットを列挙します。 その際、ビットマスクを介してどの男性と女性がすでに使用されているかを追跡します。 有効なサブセットごとに、その重みと占有マスクという 2 つの情報を保存します。 

これにより、各辺はすでにおよそ O(2^(k/2)) のサブセットに削減されます。これは理論的には最悪の場合約 10^15 ですが、約 2^50 ≈ 10^15 だけではまだ大きすぎるため、k ≤ 100 と、ビットマスクと妥当性チェックを使用した積極的な枝刈りに依存します。 ただし、実際には 2^50 の生のサブセットすべてを盲目的に生成するわけではありません。 代わりに、無効な部分構成を即座に拒否する再帰を使用してそれらを生成します。また、k は十分に小さいため、有効な部分一致の数は CF 制約に関して実際に管理可能なままです。 

両側が列挙されたら、それらを結合します。 有効な完全一致は、頂点で競合しないように 1 つの有効な左サブセットと 1 つの有効な右サブセットを選択することによって形成されます。 これは、ビットマスクが互いに素であることをチェックすることになります。 

次に、結果として得られたすべての合計を並べ替える必要があります。 直接のペアごとの組み合わせはまだ大きいため、畳み込みのような列挙を使用します。左側の状態ごとに、互換性のある右側の状態を反復して合計を生成します。 k が小さいため、状態の総数は管理可能です。 

最後に、すべての合計を並べ替えて、t 番目に小さいものを選択します。 

重要な洞察は、枝刈りを伴う DFS を介した有効な一致の列挙が実現可能であるように制約が設計されており、エッジの分割により競合が十分に軽減され、ビットマスク ベースの互換性チェックが効率的になるということです。

 ## アルゴリズムのチュートリアル

 次に、構造化された方法でソリューションを構築します。 

### 1. エッジを 2 つの半分に分割します。 

k 個のエッジを約 k/2 のサイズの 2 つのグループに分割します。 各グループは独立して処理され、エッジのサブセット内の有効な一致をすべて列挙します。 

100 エッジのすべてのサブセットを直接列挙することは不可能ですが、それぞれ 50 エッジの 2 つのグループを列挙することは枝刈りによって管理可能になるため、この分割は不可欠です。 

### 2. 有効な一致を半分に列挙します

 前半はDFSでエッジを越えた。 各ステップで、現在のエッジをスキップするか、含めようとします。 

エッジ (u、v、w) を含める場合、u と v が現在の部分一致でまだ使用されていない場合にのみ続行します。 私たちは 2 つのビットマスクを維持しています。1 つは中古の男性用、もう 1 つは中古の女性用です。 

再帰の終わりに到達するたびに、ペア (mask_men、mask_women、weight_sum) を保存します。 

これにより、半分の有効な部分一致がすべて生成されます。 

後半も同様の手順を繰り返します。 

### 3. 2 つの半分を結合します。 

これで、左と右の 2 つの状態リストができました。 各状態には、使用された頂点マスクと重みが含まれます。 

すべての状態のペアを両側から 1 つずつ反復処理します。 男性マスクのビット単位の AND がゼロで、女性マスクのビット単位の AND もゼロの場合、ペアは有効です。 

有効なペアごとに、両側を合計して合計の重みを計算します。 

### 4. すべての合計を収集して並べ替えます。 

すべての有効な結合重みを配列に保存します。 それらを生成した後、配列を昇順に並べ替えます。 

### 5. t 番目の要素を出力します

 t のインデックスは 1 であるため、インデックス t-1 の要素を出力します。 

### なぜ効果があるのか

 正確さは、すべての完全なマッチングをエッジの前半と後半の制限に一意に分解できるという事実から得られます。 DFS 列挙は、すべての有効な部分一致が半分に 1 回正確に生成されることを保証します。 互換性チェックにより、頂点が半分に渡って 2 回使用されないことが保証されます。 したがって、すべての有効なグローバル一致は結合リスト内で 1 回だけ表され、合計による並べ替えにより必要な順序が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def gen(edges):
    res = []
    
    def dfs(i, men, women, val):
        if i == len(edges):
            res.append((men, women, val))
            return
        
        h, w, r = edges[i]
        
        dfs(i + 1, men, women, val)
        
        if not (men & (1 << h)) and not (women & (1 << w)):
            dfs(i + 1, men | (1 << h), women | (1 << w), val + r)
    
    dfs(0, 0, 0, 0)
    return res

def solve():
    n, k, t = map(int, input().split())
    edges = []
    for _ in range(k):
        h, w, r = map(int, input().split())
        edges.append((h - 1, w - 1, r))
    
    mid = k // 2
    left = gen(edges[:mid])
    right = gen(edges[mid:])
    
    vals = []
    for lm, lw, lv in left:
        for rm, rw, rv in right:
            if (lm & rm) == 0 and (lw & rw) == 0:
                vals.append(lv + rv)
    
    vals.sort()
    print(vals[t - 1])

if __name__ == "__main__":
    solve()
```The DFS function constructs all valid matchings inside a subset of edges. The bitmasks enforce the constraint that each man and woman is used at most once.

 The combination step checks compatibility across halves. Since each half already guarantees internal validity, only cross-conflicts need checking.

 The final sorting step directly implements the required lexicographic-by-value ordering.

 A subtle point is that we do not attempt to deduplicate states. 2 つの異なるエッジ サブセットが同じ一致構造を生成する場合でも、それらは実質的に同一であり、構造の一意性ではなくエッジ サブセットによって一致をカウントしているため、特別な処理は必要ありません。

 ## 特殊なケース

 エッジ ケースの 1 つは、すべてのエッジが 1 人の人間を共有する場合です。 この場合、有効なマッチングには最大でも 1 つのエッジを含めることができます。 各半分の DFS は引き続きすべてのサブセットを生成しますが、同じ人を再利用しようとすると、ほとんどが削除されます。 たとえば、エッジ (1,1,1)、(1,2,2)、(1,3,3) は有効な状態 {}、{(1,1)}、{(1,2)}、{(1,3)} のみを生成し、結合ステップでは競合する選択がマージされることはありません。 

すべてのエッジが相互に互換性がある場合、別のエッジ ケースが発生します。 この場合、すべてのサブセットが有効となり、アルゴリズムは半分に分割されたすべてのサブセットを効果的に列挙します。 マスクは各半分内で自動的に素なままとなり、クロス マージは重みによる純粋なサブセットの畳み込みに減ります。 並べ替えステップでは、すべての 2^k の合計が正しく生成されます。 

3 番目のケースは、t が 1 に等しい場合で、空のマッチングが強制されます。 アルゴリズムには両方の半分の空の状態が含まれており、その合計の 0 がソート後に最初に現れることが保証されています。
