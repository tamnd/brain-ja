 ## 解決策
 ## 問題の理解

 個別の項目の小さなセットが与えられ、各項目には 2 つの関連する番号が付いています。 それらの 1 つは単なる識別子であり、スコアにはまったく影響しませんが、2 番目の値は意味のある値です。 タスクは、すべてのアイテムを 1 つのシーケンス内に配置し、そのシーケンス内の隣接するペアの合計スコアができるだけ大きくなるようにすることです。 

2 つの隣接するアイテム間のスコアは、識別子ではなく、関連付けられた値のみに依存します。 値を持つ 2 つのアイテムの場合$y_i$そして$y_j$、両方の値を除算するすべての整数を調べます。 このような整数の数は、これら 2 つの項目を隣り合わせに配置することによる影響です。 シーケンスの最終スコアは、順序内のすべての隣接するペアに対するこれらの寄与の合計です。 

入力サイズによって、ソリューション戦略が即座に形成されます。 項目の数は最大 18 ですが、これはサブセットにわたる指数解が許容されるほど十分に小さいです。 すべての順列を明示的に試行するアプローチでは、次の点までを調べることになります。$18!$実現不可能な注文です。 平$2^{18} \cdot 18^2$操作は問題なく制限内に収まるため、ビットマスク動的プログラミング アプローチが自然なターゲットになります。 

微妙なエッジ ケースとして、スコアは隣接するペアに対してのみ定義されるため、単一の要素シーケンスには定義された値がありません。 動的プログラミングの状態は長さ 1 のシーケンスから開始し、2 番目の要素が追加された場合にのみスコアを蓄積する必要があるため、これは重要です。 

もう 1 つの厄介な状況は、多くの値が大きな公約数を共有する場合です。 除数の交差を繰り返し再計算する単純な実装では、たとえ問題の構造上事前計算が可能であっても、誤って作業時間やオーバーフロー時間を二重にカウントしてしまう可能性があります。 

## アプローチ

 ブルートフォースソリューションは簡単に説明できます。 可能な限りの順序を生成します。$n$項目を選択し、隣接するペアの寄与を合計することで各順序のスコアを計算します。 各ペアについて、考えられるすべての約数を最大まで反復することにより、両方の関連する値を整数で割る数を計算します。$\min(y_i, y_j)$または、必要に応じて各数値を因数分解します。 たとえ除数の数え方を最適化したとしても$O(\sqrt{V})$、1 つの順列コストを評価する$O(n \sqrt{V})$、そして、あります$n!$順列。 と$n = 18$、これは天文学的に大きくなり、制限時間内に計算を完了できなくなります。 

重要な構造的観察は、スコアが全体的な構造ではなく、隣接する遷移のみに依存するということです。 シーケンスが特定の要素で終了すると、シーケンスを拡張するために重要なのは、その要素で終了する各サブセットで達成可能な最高のスコアだけです。 これは、サブセットに対するハミルトン パス動的プログラミングの古典的な設定です。 各状態は、使用済みアイテムのサブセットとシーケンス内で最後に選択されたアイテムを表します。 トランジションでは、未使用のアイテムが 1 つ追加され、最後のアイテムと新しいアイテムの間のペア スコアが追加されます。 

素早い遷移をサポートするために、アイテムの各ペア間の重みを事前計算します。 重みは、それらの間の公約数です。$y$-values、これは正確に約数の数です。$\gcd(y_i, y_j)$。 これにより、各ペアのスコア計算が、ペアごとに 1 回実行される gcd と除数カウントの演算に変換されます。

 ## アルゴリズムのチュートリアル

 1. 値を計算する$y_i$すべての項目について、各数値を 1 回因数分解します。 これにより、ファクタリングを繰り返すことなく、後で gcd を操作できるようになります。 
2. アイテムのペアごとに$(i, j)$、Euclid のアルゴリズムを使用して gcd を計算します。 その gcd の因数分解構造から、その gcd が持つ約数の数を計算します。 これを重りとして保存します$w[i][j]$。 この重みは、これら 2 つの項目が最終シーケンスで隣接している場合の寄与を表します。 
3. 動的プログラミングテーブルを定義する$dp[mask][i]$、 どこ`mask`選択されたアイテムのサブセットを表し、$i$シーケンスの最後の項目です。 各エントリには、そのサブセットで達成可能な最大スコアが保存されます。$i$。 
4. 設定により DP を初期化します。$dp[1 << i][i] = 0$すべての項目について$i$。 隣接するペアがないため、単一の要素は何も寄与しません。 
5. Iterate over all subsets`mask`サイズの大きい順に。 サブセットごとに、新しい要素を追加して拡張してみます。$j$サブセットには含まれていません。 考えられるすべての最後の要素について$i$すでにサブセット内にある場合は、トランジションを更新します。$$dp[mask \cup \{j\}][j] = \max(dp[mask \cup \{j\}][j], dp[mask][i] + w[i][j])$$このステップでは、一度に 1 つの要素を追加することで、より長いシーケンスを構築します。 
6. すべてのサブセットを処理した後、答えはすべての状態の最大値になります。$dp[full\_mask][i]$最後のシーケンスはどの要素でも終了できるためです。 

### なぜ効果があるのか

 DP 内のすべての状態は、固定された最後の要素で終わる要素のサブセットの部分的な順序を一意に表します。 完全な順列は、そのような拡張のチェーンに分解できます。 遷移は最後の要素と新しく追加された要素にのみ依存するため、シーケンスが DP 状態に固定されると、シーケンスの内部構造はすべて無関係になります。 このアルゴリズムは、すべての有効な順列を繰り返しなしで暗黙的に探索し、最大化ステップにより、同じ要素で終わる同じサブセットを構築するすべての可能な方法の中で、最高スコアのものだけが保持されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from math import gcd

def factorize(x):
    f = {}
    d = 2
    while d * d <= x:
        while x % d == 0:
            f[d] = f.get(d, 0) + 1
            x //= d
        d += 1
    if x > 1:
        f[x] = f.get(x, 0) + 1
    return f

def divisor_count_from_gcd_factors(fa, fb):
    res = 1
    for p in fa:
        if p in fb:
            e = min(fa[p], fb[p])
            res *= (e + 1)
    return res

def main():
    n = int(input())
    x = list(map(int, input().split()))
    y = list(map(int, input().split()))

    fac = [factorize(v) for v in y]

    w = [[0] * n for _ in range(n)]
    for i in range(n):
        for j in range(n):
            if i != j:
                g = gcd(y[i], y[j])
                fg = factorize(g)
                w[i][j] = divisor_count_from_gcd_factors(fac[i], fac[j]) if False else sum(1 for _ in [0])  # placeholder

    # correct recomputation using gcd factorization only
    for i in range(n):
        for j in range(n):
            if i == j:
                continue
            g = gcd(y[i], y[j])
            fg = factorize(g)
            cnt = 1
            for p, e in fg.items():
                cnt *= (e + 1)
            w[i][j] = cnt

    INF = -10**18
    dp = [[INF] * n for _ in range(1 << n)]

    for i in range(n):
        dp[1 << i][i] = 0

    for mask in range(1 << n):
        for i in range(n):
            if dp[mask][i] == INF:
                continue
            for j in range(n):
                if mask & (1 << j):
                    continue
                nmask = mask | (1 << j)
                dp[nmask][j] = max(dp[nmask][j], dp[mask][i] + w[i][j])

    full = (1 << n) - 1
    print(max(dp[full]))

if __name__ == "__main__":
    main()
```解決策は、それぞれを因数分解することから始まります。$y_i$、移行中にコストのかかる作業を繰り返すことを避けるために再利用されます。 公約数は正確に gcd の約数であるため、重み行列は gcd を使用して構築されます。 

DP テーブルのサイズは次のとおりです。$2^n \times n$、これは実現可能です$n \le 18$。 各遷移では、既存のサブセットに新しい要素を追加して、可能な限り最高のスコアを更新しようとします。 

一般的な実装の落とし穴は、DP 状態を正しく初期化することを忘れることです。 シングルトン マスクのみがゼロで始まる必要があり、その他すべては、未計算の状態と有効なゼロ スコアが混在するのを避けるために、非常に負の値に初期化する必要があります。

        while d * d <= x:
            while x % d == 0:
                f[d] = f.get(d, 0) + 1
                x //= d
            d += 1
        if x > 1:
            f[x] = f.get(x, 0) + 1
        return f

                fg = factorize(g)

    INF = -10**18

 ## 特殊なケース

 2 要素入力は、答えが純粋に単一ペアの重みになる唯一の状況です。 DP は両方の単一要素状態をゼロに初期化し、遷移によりサブセットの曖昧さなしに最終的な答えが直接生成されます。 

いつすべて$y_i$値が同一である場合、すべてのペアは同じ数の約数を持ちます。 この場合、DP は均一なエッジ重みを持つ最長のハミルトニアン パスを見つけるように動作する必要があります。 この実装は、重みが一意であることを前提としておらず、重みが追加的であることのみを前提としているため、引き続き機能します。 

値がペアごとに互いに素である場合、すべての gcd は 1 であるため、すべてのエッジの重みは正確に 1 になります。アルゴリズムは、フル パス内のエッジの数を最大化します。これは常に$n-1$。 各遷移が正確に 1 つを寄与するため、DP は依然としてこれを正しく累積します。
