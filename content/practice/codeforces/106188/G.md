 ## 解決策
 ## 問題の理解

 私たちは与えられています`n`長さのある線分`a[i]`。 正確に選択する方法が何通りあるかを数える必要があります`k`選択したセグメントが頂点が円上にある非縮退多角形を形成できるように、これらのセグメントを分割します。 検出されたすべてのセグメントは一意であると見なされるため、同じ長さのセグメントは依然として異なる選択肢となります。 

一連の辺の長さについて、非縮退多角形を形成できるということは、最も長い辺が残りすべての辺の合計より厳密に小さいことと同等です。 この条件を満たす多角形は環状多角形として配置できるので、問題は数えることになります。`k`- 選択されたセグメントが他のセグメントの全長と少なくとも同じ長さの要素サブセット。 

入力できるサイズは、`n`約 100 に達すると、長さが十分に大きくなり、すべてのサブセットをチェックすることが不可能になる場合があります。 考えられる選択肢の数は、`C(n, k)`、中程度の値であっても急速に成長します。`n`。 多項式時間の解が必要です。 セグメントの最大長は`10000`、これは悪用できるキー バウンドです。 

難しいのは、グローバルで最大の値だけを調べることはできないということです。 サブセットは、それ自体の最大の要素が原因で無効になる場合があります。 例えば：```
Input
4 3
1 2 3 10
```答えは`1`唯一の有効な選択肢は`{1,2,3}`。 すべてのセグメントの合計のみをチェックする不注意な実装では、大きなセグメントがいつでも参加できるという誤った結論を下す可能性があります。 

もう 1 つの特殊なケースは、繰り返される長さです。 例えば：```
Input
5 3
3 3 3 1 2
```答えは`7`。 長さの 3 つのセグメント`3`は異なるオブジェクトであるため、異なるコピーを含む組み合わせは個別にカウントする必要があります。 長さを一意の値として扱うと過小評価されます。 

最後の境界ケースは平等です。 条件が厳しいですね。 例えば：```
Input
3 3
1 2 3
```答えは`0`なぜなら`3 = 1 + 2`、有効な多角形の代わりに縮退した三角形が生成されます。 使用する`<=`の代わりに`<`間違った結果が得られます。 

## アプローチ

 直接的なアプローチは、サイズのすべてのサブセットを生成することです。`k`、その最大値の辺を見つけて、その最大値が他の最大値の合計より小さいかどうかをテストします。 これは、考えられるすべての選択肢についてポリゴンの不平等を正確にチェックするため、正しいです。 ただし、次のようなことが考えられます。`C(100,50)`サブセットは処理できる範囲をはるかに超えています。 

有益な観察は、すべての無効なサブセットには 1 つの特徴的な側面、つまり最大の側面があるということです。 長さをソートした後、現在選択されている最大のセグメントの長さが次であると仮定します。`x`。 サブセットが無効になるのは、他のサブセットが無効になる場合です。`k-1`選択したセグメントの全長は最大でも`x`。 

これにより、有効なサブセットを直接カウントしようとする代わりに、無効なサブセットをカウントできるようになります。 可能な最大のセグメント長は`10000`、合計に関する動的計画法情報のみが必要です。`10000`。 合計が大きくなってもサブセットが無効になることはありません。 

セグメントを昇順に処理します。 セグメントを挿入する前に`x`動的プログラミング テーブルに挿入すると、テーブルには小さなセグメントのみが含まれます。 これを使用して、グループの数を数えます。`k-1`より小さなセグメントは最大でも合計を持ちます`x`。 このようなグループはすべて、次のような無効なサブセットを 1 つだけ作成します。`x`最大の要素として。 これらの不良サブセットを数えた後、次のように挿入します。`x`テーブルに追加すると、将来の選択の最大の要素として機能します。 

考えられるすべての合計数`k`-サブセットは`C(n, k)`。 無効なものを減算すると答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(C(n,k) * k)`|`O(k)`| 遅すぎる |
 | 最適 |`O(n * k * A)`|`O(k * A)`| 承認済み |

 ここ`A`最大セグメント長です。`10000`。 

## アルゴリズムのチュートリアル

 1. すべてのセグメントの長さを昇順に並べ替えます。 この順序で処理すると、セグメントを検査するときに、動的プログラミング テーブルに既に格納されているすべてのセグメントがそれ以下であり、非最大側のみであることが保証されます。 
2.動的プログラミングテーブルを作成する`dp[j][s]`。 選択する方法の数を保存します`j`合計の長さが正確に一致する処理済みセグメント`s`、 どこ`s`に限定されています`10000`。 
3. 各セグメントの長さについて`x`、最初に無効なポリゴンをカウントします。`x`一番大きな辺です。 のグループが必要です`k-1`合計が最大である前のセグメント`x`。 
4. そのカウントを無効なサブセットの合計に加算します。 すべての無効なサブセットには選択された最大のセグメントが 1 つだけ含まれるため、これによりすべての無効なサブセットが 1 回カウントされます。 
5.挿入`x`動的プログラミングテーブルに追加します。 現在のセグメントが同じサブセット内で複数回再利用されないように、サイズを逆方向に反復します。 
6. 選択する方法の合計数を計算します。`k`組み合わせを使用してセグメントを分割し、無効なカウントを減算します。 

これが機能する理由: すべての無効な選択には、固有の最大の側面があります。 その面が処理されると、選択された他のすべての面がすでに挿入されています。`dp`したがって、アルゴリズムは選択内容を 1 回だけカウントします。 無効としてカウントされないすべての選択は、その最大の辺が残りの辺の合計より小さくなります。これはまさにポリゴンの不平等です。 減算により、有効な環状ポリゴンが正確に残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10 ** 9 + 7
MAX_A = 10000

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()

    comb = [[0] * (k + 1) for _ in range(n + 1)]
    for i in range(n + 1):
        comb[i][0] = 1
        for j in range(1, min(i, k) + 1):
            if j == i:
                comb[i][j] = 1
            else:
                comb[i][j] = (comb[i - 1][j - 1] + comb[i - 1][j]) % MOD

    dp = [[0] * (MAX_A + 1) for _ in range(k)]
    dp[0][0] = 1

    invalid = 0

    for x in a:
        if k > 1:
            bad = 0
            for s in range(x + 1):
                bad += dp[k - 1][s]
            invalid = (invalid + bad) % MOD

        for cnt in range(k - 2, -1, -1):
            current = dp[cnt]
            nxt = dp[cnt + 1]
            for s in range(MAX_A - x + 1):
                if current[s]:
                    nxt[s + x] = (nxt[s + x] + current[s]) % MOD

    answer = (comb[n][k] - invalid) % MOD
    print(answer)

if __name__ == "__main__":
    solve()
```組み合わせテーブルは、可能な総数を計算します。`k`-セグメントの選択。 値は剰余として必要です`10^9+7`したがって、パスカルの三角形はオーバーフローを回避し、すべてのケースを直接処理します。 

ダイナミック プログラミング テーブルには、最大の合計のみが保存されます。`10000`。 テストされる最大の辺が次の値より大きくなることはないため、無効なサブセット チェックでは、より大きな合計が現れることはありません。`10000`。 

不良サブセットをカウントするループは、現在のセグメントを挿入する前に発生します。 この順序により、現在のセグメントが小さい辺の 1 つとして数えられることがなくなります。 更新ループは選択されたカウントを逆方向に進みます。これは標準の 0/1 ナップザック パターンであり、1 つのセグメントを複数回使用することを防ぎます。 

## 実用的な例

 最初のサンプルの場合:```

```処理状態は次のとおりです。 

| 現在のセグメント | これが最大のグループは無効です | 保存されたサブセットのサイズ |
 | --- | --- | --- |
 | 1 | 0 | 1: {1} |
 | 2 | 0 | より小さなグループの合計 |

 The invalid choices are removed from the total number of`3`-要素の選択。 残った答えは、`7`。 

2 番目のサンプルの場合:```

```並べ替え後:```

```重要な状態は次のとおりです。 

| 現在のセグメント | 合計 ≤ 現在の値を持つ前の 3 つのセグメントが必要です | 結果 |

 | 1 | 不可能 | 無効なサブセットはありません |

 アルゴリズムは、すべての不良四角形をその最長辺でカウントし、すべての可能な選択肢からそれらを減算します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |`O(n * k * A)`| 各セグメントは、すべてのサブセット サイズとすべての可能な合計を更新します。`A = 10000`。 |
 | スペース |`O(k * A)`| テーブルには、サブセット サイズごとのカウントと、考えられる関連する合計が格納されます。 |

 と`n <= 100`、`k <= 100`、 そして`A <= 10000`、操作数は約`10^8`最大のケースでは、最適化された Python ループで意図した制限に適合します。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.readline
    n, k = map(int, data().split())
    a = list(map(int, data().split()))
    a.sort()

    MOD = 10 ** 9 + 7
    MAX_A = 10000

    comb = [[0] * (k + 1) for _ in range(n + 1)]
    for i in range(n + 1):
        comb[i][0] = 1
        for j in range(1, min(i, k) + 1):
            comb[i][j] = (comb[i - 1][j - 1] + comb[i - 1][j]) % MOD

    dp = [[0] * (MAX_A + 1) for _ in range(k)]
    dp[0][0] = 1
    bad = 0

    for x in a:
        for s in range(x + 1):
            bad += dp[k - 1][s]
        for c in range(k - 2, -1, -1):
            for s in range(MAX_A - x + 1):
                if dp[c][s]:
                    dp[c + 1][s + x] += dp[c][s]

    sys.stdin = old
    return str((comb[n][k] - bad) % MOD)

assert run("""5 3
1 2 3 3 3
""") == "7"

assert run("""6 4
1 5 2 3 4 1
""") == "12"

assert run("""3 3
1 2 3
""") == "0"

assert run("""3 3
2 2 3
""") == "0"

assert run("""5 5
1 1 1 1 1
""") == "1"

 | --- | --- | --- |
 |`5 3 / 1 2 3 3 3`|`7`| 繰り返される長さは別個のセグメントとして扱われます。 
|`6 4 / 1 5 2 3 4 1`|`12`| 一般的なポリゴンのカウント |
 |`3 3 / 1 2 3`|`0`| 等しい場合は拒否されます |

 ## 特殊なケース

 等価境界の場合:```
3 3
1 2 3
```加工時`3`、動的プログラミング テーブルにはペアが含まれています`{1,2}`合計付き`3`。 クエリのカウントは現在の最大の辺まで合計されるため、このサブセットは無効とマークされます。 最終的な答えは、`0`。 

繰り返される値の場合:```
5 3
3 3 3 1 2
```ソート順は、`1,2,3,3,3`。 各コピーの`3`動的プログラミング テーブルに個別に挿入されます。 インデックスが異なれば選択も異なるため、アルゴリズムは自然に多重性を維持します。 

他のチームを支配する大きなチームの場合:```
4 3
1 2 3 10
```いつ`10`が処理されると、テーブルには小さい値間のすべてのペアが含まれます。 すべてのペアは最大でも合計を持ちます`10`、つまり、以下を含むすべてのサブセット`10`は無効です。 残っている唯一の有効な三角形は、`{1,2,3}`。 

可能な最小のポリゴン サイズの場合:```
3 3
2 3 4
```アルゴリズムは、可能なサブセットのみをチェックします。 一番大きな辺は、`4`、他の 2 つの辺の和は次のようになります。`5`したがって、サブセットは有効であり、答えは次のようになります。`1`。
