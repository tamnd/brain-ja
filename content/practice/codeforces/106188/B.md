 ## 解決策
 ## 問題の理解

 プレイヤーが座標に立っています`(ex, ey)`グリッド上で。 プレイヤーは 8 つのコンパスの方向のいずれかを向き、一回転した後に弾を発射します。 回転によって最終的な方向は変わらないため、弾丸は元の方向に永遠に進み続けるだけです。 与えられたすべての敵の位置の中で、弾丸が最初に到達する敵を見つける必要があります。 弾丸の経路に敵が含まれていない場合は、次のように出力します。`-1`。 

入力により、敵の数、プレイヤーの位置、向いている方向、およびすべての敵の座標が得られます。 出力は、その光線に沿ってプレイヤーに最も近い敵の座標です。 

座標の境界は次のとおりです`100000`、敵の数も到達する可能性があります`100000`。 弾丸のパス内のすべてのグリッド位置をチェックするソリューションは、最大約`100000`方向ごとのチェックは不要です。 あり得るので、`100000`敵の場合、各敵を一定の回数処理して、`O(n)`解決。 ソートも可能ですが、可能な方向の数が少ないため、リニアスキャンで十分です。 

厄介なケースは、「同じ行」と「弾丸の経路内」を混同することから生じます。 たとえば、プレーヤーが次の場所にいる場合、`(1,1)`直面している`NORTHEAST`の敵`(3,3)`がヒットすると、答えは次のようになります。```
3 3
```対角方程式をチェックするだけで方向を忘れる不注意な解決策は、誤って受け入れられる可能性があります。`(0,0)`問題のバージョンでは、負の座標が許可されています。これは、同じ対角線上にありますが、プレーヤーの後ろにあるためです。 

もう 1 つのエッジ ケースは、同じ光線上に複数の敵がある場合です。 入力の場合:```
2 1 1
EAST
3 1
5 1
```正しい出力は次のとおりです。```
3 1
```最初の敵が 2 番目の敵をブロックします。 その方向に敵がいるかどうかだけを確認し、最後に見つかった敵を維持すると、間違ったターゲットを返す可能性があります。 

最後によくある間違いは、プレイヤー自身のタイルを扱うことです。 例えば：```
1 1 1
NORTH
1 1
```答えは次のとおりです。```
1 1
```敵は開始位置にいて、最初に遭遇するエンティティです。 次のタイルから厳密に前方に検索するだけのソリューションでは、それを見逃してしまいます。 

## アプローチ

 簡単なアプローチは、弾丸の軌跡をシミュレートすることです。 プレイヤーの位置から開始して、選択した方向にタイルを 1 つずつ移動し、訪問したすべての座標に敵がいるかどうかを確認します。 敵をセットに保存すると、これは簡単に実装でき、パス上で最初に遭遇した座標が正確に最初にヒットした敵となるため、これは正しいです。 

問題は、弾丸が通過できる空きスペースの量です。 座標範囲は次のとおりです`100000`したがって、単一のシミュレーションには約`100000`ステップ。 大きな入力に対してこれを繰り返すことは場合によってはまだ管理可能ですが、訪問したセルのほとんどには敵が含まれていないため、作業が無駄になります。 グリッドは巨大ですが、敵の数はわずかです`100000`。 

重要な観察は、敵の座標のみを考慮しているということです。 どの方向にも単純な数学的条件があります。 たとえば、北に移動するということは、敵も同じものを持っている必要があることを意味します。`x`コーディネートと`y`プレイヤーの値より小さくない値。 北東に移動するということは、`x`そして`y`プレイヤーの差に合わせなければなりません。 光線の状態によってどの敵が候補であるかがわかり、プレイヤーからの距離によってどの候補に最初に到達できるかがわかります。 

すべての敵を 1 回スキャンする間に、敵が光線上にあるかどうかを確認します。 存在する場合、その距離をこれまでに見つかった最良の候補と比較します。 光線は一方向にのみ進むため、最も近い候補が正確に最初のヒットになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(最大座標) | O(n) | 空のセルをスキャンするため、概念的には遅すぎます。 
| 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. プレイヤーの位置、方向、およびすべての敵の位置を読み取ります。 方向を移動ベクトルに変換する`(dx, dy)`。 たとえば、北は次のようになります。`(0, 1)`そして南西は`(-1, -1)`。 これにより、すべての方向で同じロジックを使用できるようになります。 
2. 敵ごとに、プレイヤーとの差を計算します。`(tx, ty) = (enemy_x - ex, enemy_y - ey)`敵はベクトルに沿ったどこかにいる場合にのみ攻撃できます`(dx, dy)`。 
3. 敵が同じ光線上にいるかどうかを確認します。 ポイント`(tx, ty)`非負の距離がある場合、光線上にあります`k`次のような:`tx = k * dx`そして`ty = k * dy`符号は方向と一致し、座標間の比率も一致する必要があります。 なぜなら、動きベクトルには次のものしか含まれていないからです。`0`、`1`、 または`-1`、これは回線の状態と方向の確認に簡略化できます。 
4. 敵が有効な場合、敵がどれだけ離れているかを計算します。 値を比較するだけなので、二乗距離で十分です。 距離が最も小さい候補が最初に 1 ヒットします。 
5. すべての敵が処理されたら、保存されている回答を印刷します。 候補が見つからなかった場合は印刷します`-1`。 

機能する理由: 攻撃できるすべての敵は光線方程式を満たさなければならないため、アルゴリズムはターゲットの可能性を決して無視しません。 弾丸はプレイヤーから外側に向かって継続的に移動するため、すべての有効なターゲットの中で、弾丸は最初に距離が最小のターゲットに到達します。 最小距離を維持すると、保存された回答が常にこれまでに確認された最も近い有効な敵であるという不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, ex, ey = map(int, input().split())
    direction = input().strip()

    enemies = []
    for _ in range(n):
        x, y = map(int, input().split())
        enemies.append((x, y))

    moves = {
        "NORTH": (0, 1),
        "NORTHEAST": (1, 1),
        "EAST": (1, 0),
        "SOUTHEAST": (1, -1),
        "SOUTH": (0, -1),
        "SOUTHWEST": (-1, -1),
        "WEST": (-1, 0),
        "NORTHWEST": (-1, 1),
    }

    dx, dy = moves[direction]

    best_dist = float("inf")
    ans = None

    for x, y in enemies:
        tx = x - ex
        ty = y - ey

        if dx == 0:
            if tx != 0:
                continue
            if ty * dy < 0:
                continue
        elif dy == 0:
            if ty != 0:
                continue
            if tx * dx < 0:
                continue
        else:
            if tx * dy != ty * dx:
                continue
            if tx * dx < 0 or ty * dy < 0:
                continue

        dist = tx * tx + ty * ty
        if dist < best_dist:
            best_dist = dist
            ans = (x, y)

    if ans is None:
        print(-1)
    else:
        print(ans[0], ans[1])

if __name__ == "__main__":
    solve()
```方向辞書は、考えられるそれぞれの向きをベクトルにマッピングします。 これにより、8 つのケースに対して個別のロジックを作成する必要がなくなり、幾何学的チェックが均一になります。 

ループは敵の位置を調べるだけです。 変数`tx`そして`ty`プレイヤーを基準とした敵の位置を表すため、絶対座標を使用するよりもレイの確認がはるかに簡単になります。 

垂直方向の場合は、`x`座標は一致する必要があります。 水平方向の場合は、`y`座標は一致する必要があります。 対角線方向の場合、相対座標は同じ比率を持つ必要があり、これが等式になります。`tx * dy == ty * dx`。 

距離の比較には平方根が不要なため、距離の二乗を使用します。 比較する`a^2`そして`b^2`比較と同じ順序を与えます`a`そして`b`。 座標は十分小さいため、Python 整数で簡単に乗算を処理できます。

## テストケース```python
import sys
import io

def solve(data):
    input = io.StringIO(data).readline

    n, ex, ey = map(int, input().split())
    direction = input().strip()

    moves = {
        "NORTH": (0, 1),
        "NORTHEAST": (1, 1),
        "EAST": (1, 0),
        "SOUTHEAST": (1, -1),
        "SOUTH": (0, -1),
        "SOUTHWEST": (-1, -1),
        "WEST": (-1, 0),
        "NORTHWEST": (-1, 1),
    }

    dx, dy = moves[direction]

    best = float("inf")
    ans = None

    for _ in range(n):
        x, y = map(int, input().split())
        tx, ty = x - ex, y - ey

        if dx == 0:
            if tx != 0 or ty * dy < 0:
                continue
        elif dy == 0:
            if ty != 0 or tx * dx < 0:
                continue
        else:
            if tx * dy != ty * dx or tx * dx < 0 or ty * dy < 0:
                continue

        dist = tx * tx + ty * ty
        if dist < best:
            best = dist
            ans = (x, y)

    if ans is None:
        return "-1"
    return f"{ans[0]} {ans[1]}"

 ## 特殊なケース

 敵がプレイヤーの背後にいる場合、光線方向チェックにより誤った一致が防止されます。 プレイヤーがいる場合`(1,1)`直面している`NORTHEAST`の敵`(0,0)`は対角方程式を満たしますが、移動距離が負になるため拒否されます。 

同じライン上に複数の敵がある場合、最小距離の比較により最も近い敵が維持されます。 と：```
2 1 1
EAST
3 1
5 1
```最初の敵には距離がある`4`、2番目は距離がありますが、`16`。 アルゴリズムストア`(3,1)`そしてそれをより遠くの敵に置き換えることは決してありません。 

1 つの座標内で移動がゼロの方向の場合、特別なチェックにより除算スタイルのロジックが回避されます。 北を向いているということは、すべての有効な敵が同じものを持っている必要があることを意味します`x`、およびを持つ敵のみ`y >= ey`到達できる。 これにより、比率の比較による特殊なケースを発生させることなく、垂直光線と水平光線が処理されます。
