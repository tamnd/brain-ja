 ## 解決策
 ## 問題の理解

 与えられた一連の数値が、仮想の GCD テーブルの行に連続した要素として現れるかどうかを判断するように求められます。 テーブルには _n_ 行と _m_ 列があり、行 _i_ と列 _j_ の各要素は _i_ と _j_ の最大公約数です。 入力は、長さ _k_ のシーケンスとともにテーブルの次元を与えます。 私たちのタスクは、シーケンスがその列以降の値と正確に一致する行と開始列が存在するかどうかを確認することです。 

制約は異常です。 _n_ と _m_ は両方とも 10^12 までの大きさになる可能性があり、テーブルを明示的に構築するソリューションは即座に除外されます。 シーケンスの長さ _k_ は最大 10,000 であり、行の潜在的な幅よりもはるかに小さくなります。 これは、ソリューションがブルートフォース テーブル生成ではなく、主に数値自体のプロパティに基づいて動作する必要があることを示しています。 

単純なアプローチでは、すべての行とすべての開始列を反復処理し、GCD を計算し、シーケンスと照合しようとする可能性があります。 これは、入力が大きい場合には見事に失敗します。 シーケンスに複数の 1 が連続して含まれる場合、エッジ ケースが発生します。 たとえば、シーケンスが [1, 1, 1] の場合、不注意なアプローチにより単純に連続する整数と一致させようとする可能性がありますが、正しい一致は行インデックスと割り切れる関係に依存します。 _GCD(i, j)_ が _i_ を超えることはできないため、シーケンス番号が行番号を超える場合、別の注意が必要な状況が発生します。 たとえば、シーケンスの最初の要素が 7 であるが、行 5 を検査している場合、その行からシーケンスを開始することはできません。 

## アプローチ

 ブルートフォースの方法は簡単です。 1 から _n_ までの各行、1 から _m-k+1_ までの開始列ごとに、シーケンス内の各位置の GCD(行、列 + オフセット) を計算し、比較します。 一致するものがあれば、YES を返します。 それ以外の場合は、NO を返します。 これは正しいですが、計算上実行不可能です。 各行には最大 10^12 列を含めることができ、各比較には最大 10^4 の GCD 計算が含まれ、最悪の場合の演算数はおよそ 10^28 となり、これは実行可能な計算をはるかに超えています。 

効率的なソリューションを可能にする重要な観察は、GCD 行の構造を利用することです。 固定行 _i_ の場合、_GCD(i, j)_ は _i_ の係数のみに依存します。 _d_ を _i_ の約数として表す場合、_GCD(i, j) = d_ を満たす位置 _j_ は、_i_ と互換性のある _d_ の倍数でなければなりません。 言い換えれば、行インデックスを素数の積として因数分解すると、GCD パターンは完全に割り算関係によって決まります。 このシーケンスは、開始列 _j_ における一連の合同式として解釈できます。 シーケンス内の各位置について、条件 _GCD(i, j+l-1) = a[l]_ はモジュラー方程式 _j+l-1 ≡ 0 (mod a[l]/gcd(i, a[l]))_ になります。 これらすべてのモジュラー方程式を同時に解くと、中国剰余定理 (CRT) 問題に帰着します。 

考えられるすべての行をチェックするのではなく、シーケンスの最初の要素 _a1_ が行番号 _i_ を分割する必要があることがわかります。 _a1_ の倍数である考えられる行 _i_ ごとに、すべてのモジュラー制約を満たす列 _j_ を見つけようとします。 何らかの解決策が存在する場合、そのシーケンスがテーブル内に出現します。 このアプローチでは、_a1_ (または構造方法に応じて倍数) の約数のみを考慮し、_k ≤ 10,000_ の場合に実行可能なサイズ _k_ の小さな CRT システムを解決するため、検索スペースが大幅に削減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * m * k) | お(1) | 遅すぎる |
 | 最適 | O(k * log(max(a_i))) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

1. シーケンス _a1_ の最初の要素のすべての約数を計算します。 これらの約数の倍数である行のみが、何らかの列の GCD として _a1_ で始まる可能性があります。 これにより、候補行が即座に制限されます。 
2. 候補行 _i_ ごとに、開始列 _j_ のモジュラー合同式システムを構築します。 シーケンスの _l_ 番目の要素の場合、条件 _GCD(i, j+l-1) = a[l]_ はモジュラー方程式に変換されます。 具体的には、_g = gcd(i, a[l])_; とします。 その場合、_j+l-1_ は _a[l]/g_ で割り切れる必要があります。 これを現在の要素の _j ≡ r (mod m)_ として記録します。 
3. 中国剰余定理を使用して、これらすべての合同式を 1 つの合同式に結合します。 一貫したソリューションが存在する場合、_j_ の値は有効な列範囲 1 ～ _m-k+1_ 内に収まる必要があります。 そうであれば、YESを出力します。 
4. 有効な解を生成する候補行がない場合は、NO を出力します。 

これが機能する理由: 各モジュラー制約は、GCD がシーケンス要素と等しいという要件を正確にエンコードします。 CRT は、同時解が存在する場合、モジュライの最小公倍数を法とする解が 1 つだけ存在することを保証します。 この解が列範囲内にあることを確認すると、そのシーケンスがテーブル内に存在することが確認されます。 妥当な行候補のみをチェックして CRT を正しく解決するため、解決策を見逃すことはなく、不可能な行は考慮されないため、誤検知は発生しません。 

## Python ソリューション```python
import sys
from math import gcd
input = sys.stdin.readline

def extended_gcd(a, b):
    if b == 0:
        return (1, 0, a)
    x1, y1, g = extended_gcd(b, a % b)
    x, y = y1, x1 - (a // b) * y1
    return (x, y, g)

def crt_pair(a1, m1, a2, m2):
    # Solve x ≡ a1 mod m1, x ≡ a2 mod m2
    # Returns (x mod lcm(m1,m2), lcm) or (None, None) if impossible
    g = gcd(m1, m2)
    if (a2 - a1) % g != 0:
        return (None, None)
    p, q, _ = extended_gcd(m1 // g, m2 // g)
    mod = m1 // g * m2
    x = (a1 + (a2 - a1) // g * p * (m1 // g)) % mod
    return (x, mod)

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    from itertools import product
    
    # candidate rows: multiples of a[0] within n
    first = a[0]
    divisors = set()
    i = 1
    while i*i <= first:
        if first % i == 0:
            divisors.add(i)
            divisors.add(first // i)
        i += 1

    for row in divisors:
        if row > n:
            continue
        mods = []
        for l in range(k):
            g = gcd(row, a[l])
            if a[l] % g != 0:
                break
            mods.append(((l) % (a[l] // g), a[l] // g))
        else:
            x, mod = mods[0]
            ok = True
            for r, m_ in mods[1:]:
                x, mod = crt_pair(x, mod, r, m_)
                if x is None:
                    ok = False
                    break
            if ok and x + 1 <= m - k + 1:
                print("YES")
                return
    print("NO")

solve()
```このソリューションでは、最初に最初のシーケンス要素に基づいて妥当な行インデックスを列挙します。 各シーケンス要素はモジュラー制約を生成し、これを中国剰余定理をペアごとに使用して解決します。 不可能な合同を処理し、開始列が許容範囲内にあることを確認するために注意が必要です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(k * sqrt(a1) * log(max(a_i))) | 除数の列挙には sqrt(a1) のコストがかかり、各除数には k 個のモジュラー計算と CRT 操作が必要で、各 CRT 操作には log(max(a_i)) のコストがかかります。 
| スペース | O(k) | k 個のモジュラー制約を保存します。 

これは、sqrt(10^12) ~ 10^6、k ≤ 10^4、最大 10^ の範囲内に収まります。
