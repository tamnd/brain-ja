 ## 解決策
 ## 問題の理解

 2 つの配列が与えられます。1 つは長い配列です。`a`最大 150,000 のサイズとそれより短い配列`b`長さは最大 150,000 ですが、並べ替えて一時的に「消費」できるマルチセットとして使用されます。 しきい値`h`も与えられます。 

連続するセグメントごとに、`a`に等しい長さの`b`の各要素を一致させることが可能かどうかを判断しようとします。`b`一致するすべてのペアが制約を満たすように、セグメントの個別の要素に変換します。つまり、から選択された要素の合計です。`a`から選択された要素`b`少なくとも`h`。 の各要素`b`はセグメントごとに最大 1 回使用できますが、一致する順序は自由に選択できます。 

ステートメント内の関数は基本的に、次の間で可能なすべての一致を試みます。`b`そして窓の`a`、しかし、バックトラッキングを伴うので、指数関数的な動作につながります。 最終的な答えは、少なくとも 1 つの有効な一致が存在するウィンドウの数です。 

主要な構造は、各ウィンドウの`a`は独立しており、問題は 2 つのマルチセット間の実現可能性条件をチェックすることになります。 

制約`n ≤ 150000`階乗または指数関数的な探索は直ちに除外されます。 ウィンドウごとの二次式でも、約 10¹⁰ の演算に達するため、大きすぎます。 もっと近いものが必要です`O(n log n)`または`O(n)`。 

多くの要素が含まれる場合、微妙な問題が発生します。`b`は小さく、ウィンドウの多くの要素でかろうじて十分です。 通常、恣意的に一致させようとしたり、順序付け効果を無視しようとしたりすると、貪欲な間違いが発生します。 たとえば、大きなものをペアリングすると、`b`別の割り当てが成功する場合でも、早めに実行すると実行可能性が妨げられる可能性があります。 

順序が重要な最小限の例:

 入力ウィンドウ`s = [6, 6]`、`b = [4, 3]`、`h = 10`。 

どちらの割り当ても有効です。`6+4`そして`6+3`どちらも機能しますが、常に最大のものと一致する単純な貪欲さ`b`first はここでも成功する可能性があります。 ただし、少し変更すると次のようになります。`b = [7, 3]`、`s = [6, 6]`、`h = 10`。 

合わせたら`7`まず、両方`6+7`働く、去る`3`も大丈夫です。 しかし、他の構成では、初期の間違ったペアリングにより、有効な解決策が不可能に見える可能性があります。 これにより、恣意的な選択ではなく、ソートされたマッチング戦略が動機付けられます。 

## アプローチ

 再帰の強引な解釈は、次のすべての順列を列挙することです。`b`そしてそれらを現在のウィンドウに割り当ててみてください。 ウィンドウ内の各位置に対して、未使用の要素を選択します。`b`閾値制約を満たします。 最悪の場合、これにより、`len!`ウィンドウごとに可能性があり、これは完全に不可能です`len = 2e5`。 

重要な観察は、再帰はウィンドウ要素とウィンドウ要素の間の 2 部グラフに完全な一致が存在するかどうかのみをチェックしていることです。`b`、エッジが存在する場合、`a[i] + b[j] ≥ h`。 マッチングを構築する必要はありません。 必要なのは実現可能性だけです。 

標準的な軽減は、状態を変えることです。 それぞれについて`a[i]`、どのくらいの大きさかを定義します`b[j]`それと一致する必要があります:`b[j] ≥ h - a[i]`。 それでそれぞれ`a[i]`に要件のしきい値を課します`b`受け入れられる要素。 

ここで問題は、それぞれを割り当てることができるかということです。`a[i]`独特の`b[j]`そのような`b[j]`少なくとも必要最小限ですか？ これは、2 つのソートされたリスト間の古典的な貪欲マッチングの問題です。 

固定ウィンドウの場合、ウィンドウを並べ替えます。`a`そして並べ替える`b`。 次に、最初に最小の要件を一致させようとします。`a[i]`最大の柔軟性が必要なため、`a`昇順で常に可能な限り小さいものを割り当てます`b`それは要件を満たします。 いずれかの時点でそのようなものが見つからない場合は、`b`、ウィンドウが失敗します。 

各ウィンドウを最初から並べ替えることを避けるために、スライディング ウィンドウ上でマルチセットのような構造を使用します。 どちらの配列も大きいため、ウィンドウを動的に維持し、挿入、削除、および上限クエリをサポートするデータ構造を使用して実現可能性をテストします。 バランスの取れた二分探索ツリーまたはソートされたコンテナで十分ですが、`O(n log n)`私たちはソートされた構造を維持します`b`必要な値を追跡してウィンドウを繰り返しテストします。 

より効率的な変換が存在します。すべてのウィンドウを個別にチェックする代わりに、事前にソートします。`b`ウィンドウ要件を一度ソートされた複数セットとして維持します。`h - a[i]`。 ウィンドウが有効であるためには、両方のリストをソートした後、すべての要件が対応する値以下である必要があります。`b`要素。 

これにより、各ウィンドウ チェックが 2 つの並べ替えられたシーケンスの比較に変わりますが、それでも動的に更新する必要があります。 マルチセット (またはバイナリ検索の挿入/削除を使用してソートされたリスト) を使用すると、次のようになります。`O(log n)`シフトごとに更新します。

 ## アルゴリズムのチュートリアル

 条件を変換します`a[i] + b[j] ≥ h`の中へ`need[i] = h - a[i]`。 それぞれ`a[i]`最低限必要なパートナーの値になります。 

サイズのスライディング ウィンドウを維持します`len`以上`a`、各ウィンドウについて、次のソートされた構造を維持します。`need[i]`。 

私たちも保管しています`b`グローバルで一度ソートされます。 

1. 以下の値を含むソートされたマルチセット構造を構築します。`b`。 この構造は、必要に応じて要素の削除と追加をサポートします (この問題では`b`は修正されているため、それとのみ比較します)。 
2. 最初のウィンドウの場合`a`、すべてを計算します`need[i] = h - a[i]`そしてそれらを並べ替えます。 
3. 並べ替え`b`。 
4. 最小のものからスキャンして実現可能性を確認する`need`最大まで`b`、常に貪欲にペアリングします: 最小の場合`need`利用可能な最小値よりも大きいです`b`、ウィンドウはすぐに失敗します。 
5. 発信音の影響を取り除き、ウィンドウをスライドさせます。`a[i]`そして受信したものを追加します`a[i+len]`、並べ替えられたものを更新します`need`構造。 
6. 新しいウィンドウごとに、貪欲な実行可能性チェックを繰り返し、成功した場合はカウントを蓄積します。 

重要な決定は常に、最初に最小の要件を満たすことです。 これは正しいです。なぜなら、小さな要件を満たせない場合、再配置しても問題を解決できない一方で、早期に満たすことで、より困難な要件に備えてより大きな要素が保存されるからです。 

### なぜ効果があるのか

 常に、ウィンドウから導出された必須の最小値と利用可能な最小値の 2 つのソートされたリストを維持します。`b`価値観。 最小の要件から順に貪欲に組み合わせることにより、大きなコストを無駄にすることがなくなります。`b`小規模な場合の簡単な要件に応じて`b`対処できたかもしれない。 貪欲なプロセスがいくつかのインデックスで失敗した場合、それはプレフィックスに十分な大きさよりも多くの要件があることを意味します。`b`値を満足させる必要がありますが、これはマッチングにとって必要な障害となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_match(needs, b):
    # both sorted
    j = 0
    m = len(b)
    for x in needs:
        while j < m and b[j] < x:
            j += 1
        if j == m:
            return False
        j += 1
    return True

def main():
    n, m, h = map(int, input().split())
    b = list(map(int, input().split()))
    a = list(map(int, input().split()))

    b.sort()

    # initial window
    needs = [h - a[i] for i in range(m)]
    needs.sort()

    ans = 0
    if can_match(needs, b):
        ans += 1

    for i in range(m, n):
        # slide window: remove a[i-m], add a[i]
        # rebuild needs for simplicity in Python (accepted due to constraints borderline reasoning)
        # but logically we recompute window requirements
        # for a strict optimization, use balanced BST / multiset
        # here we maintain a sorted list incrementally
        out_need = h - a[i - m]
        in_need = h - a[i]

        # remove out_need
        idx = 0
        while idx < len(needs) and needs[idx] != out_need:
            idx += 1
        needs.pop(idx)

        # insert in sorted position
        import bisect
        bisect.insort(needs, in_need)

        if can_match(needs, b):
            ans += 1

    print(ans)

if __name__ == "__main__":
    main()
```この解決策は、ペアリング条件をソートされた実行可能性チェックに変換することに依存しています。 ヘルパー関数`can_match`線形貪欲スキャンを実行します。これは、両方の配列がソートされ、各要素が最大 1 回しか消費されないため最適です。 

スライディング ウィンドウのメンテナンスは、ソートされたリストへの挿入と削除によって実装されます。 この実装では削除は線形であり、概念を明確にするために Python では許容されますが、より厳密な実装では通常、バランスのとれたツリーまたは 2 つのヒープ構造に置き換えられます。 

よくある間違いは、一致させようとすることです`a`に`b`任意の順序で直接。 ソートされた変換により、その曖昧さが完全に回避されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, h = map(int, input().split())
    b = list(map(int, input().split()))
    a = list(map(int, input().split()))

    b.sort()

    def can(needs):
        j = 0
        for x in needs:
            while j < m and b[j] < x:
                j += 1
            if j == m:
                return False
            j += 1
        return True

    needs = sorted(h - x for x in a[:m])
    ans = int(can(needs))

    import bisect

    for i in range(m, n):
        out_need = h - a[i - m]
        in_need = h - a[i]
        idx = bisect.bisect_left(needs, out_need)
        needs.pop(idx)
        bisect.insort(needs, in_need)
        ans += int(can(needs))

    return str(ans)

 ## 特殊なケース

 脆弱な状況は、多くの場合に発生します。`a[i]`値はしきい値をわずかに下回っています。 たとえば、次の場合`h = 10`そして`a[i] = 9`、 それから`need = 1`、とても簡単に満足できます。 このアルゴリズムは、そのような小さな要件を最初に正しく配置し、より大きな要件を保持します。`b`より厳しい制約の値。 

もう一つのケースは次のような場合です。`b`重複が含まれています。 重複は独立したリソースとして動作するため、貪欲スキャンは引き続き機能します。 例えば、`b = [5, 5, 5]`そして`needs = [6, 6, 6]`ないのできれいに失敗します`b[i]`最小の要件も満たします。 

最後のエッジ ケースは、すべての要素が一致する完全にバランスのとれたウィンドウです。`a[i] + b[i] = h`。 ソートされた変換では、要件が利用可能な値とまったく同じになるため、等価性が正しく維持され、貪欲スキャンでは競合することなくそれらが 1 対 1 で照合されます。
