 ## 解決策
 ## 問題の理解

 配列から始めて、それを繰り返し正確に変換することができます$m$回。 各変換は、現在の配列を 2 つの方法のいずれかで形成された新しい配列に置き換えます。配列を複製してそれ自体に追加するか、反転コピーを取得して元の配列の前に配置します。 

結局$m$操作を行うと、最終的な配列が得られます$b$。 目的は、要素の単純な合計を最大化することではなく、各位置がそのプレフィックス合計に寄与する加重合計を最大化することです。 具体的に定義すると、$S_i = \sum_{j=1}^{i} b_j$の場合、スコアは次のようになります。$\sum_{i=1}^{|b|} S_i$、計算されたモジュロ$10^9+7$ただし、比較はモジュロの前に行われるという重要な工夫が必要です。可能な最大の整数値が必要であり、その後でのみモジュロを適用します。 

制約$n, m \le 10^5$アレイのシミュレーションは直ちに除外してください。 1 回の操作でもサイズが 2 倍になるため、配列の長さは$n \cdot 2^m$、これを明示的に構築することはまったく不可能です。 これにより、変換中の要素の寄与の合計についてのみ推論する必要があります。 

素朴な間違いは、各操作を独立して貪欲に決定できると想定することです。 たとえば、配列上では$[1,2]$どちらの操作でも異なる構造が生成され、プレフィックスの重み付けに対する全体的な影響を追跡せずに選択を繰り返すと、誤った答えが得られます。 もう 1 つの微妙な落とし穴は、目的を誤解していることです。つまり、要素の合計ではなく、すべての接頭辞の合計の合計であり、前の位置に重みがかかります。 

エッジケースの小さな例としては、$a = [1, 100]$、$m = 1$。 追加すると与える$[1,100,1,100]$、反転して接頭辞を付けると、$[100,1,1,100]$。 要素のマルチセットが同一であっても、前に出現する大きな値が多くのプレフィックスにより多く寄与するため、プレフィックス構造によってスコアが大幅に変化します。 

## アプローチ

 ブルートフォース手法ではプロセスをシミュレートします。配列から開始し、すべてを適用します。$m$可能なすべての方法で演算を実行し、結果として得られるすべての配列を生成し、スコアを計算します。 各演算により配列サイズは 2 倍になります。$2^m$可能な操作シーケンス。 メモリを無視したとしても、これはすでに指数関数的に爆発的に増加しています。 さらに、長さのスコアを計算する$n2^m$配列自体はそのサイズでは線形になるため、合計の作業量は天文学的に大きくなります。 

重要な洞察は、どちらの許可された操作も値の複数セットを保持し、順序のみを変更するが、スコアはプレフィックスの蓄積による順序に依存するということです。 配列全体を追跡する代わりに、配列の合計とプレフィックスの合計の 2 つの集計統計を追跡します。 どちらの操作もこれら 2 つの値に対する変換として表現できるため、これらで十分です。 

連結する場合$b + b$、後半のプレフィックスの合計は、前半の合計だけシフトされます。 反転およびプレフィックス付加の場合、対称性を利用します。つまり、反転するとプレフィックスの寄与が変化しますが、総和は変化せず、プレフィックスと合計の構造は既知のアイデンティティによって元の構造から導き出すことができます。 これにより、各操作が数値のペアに対する決定論的な更新に削減され、反復処理が可能になります。$m$線形時間での倍数。

 ## アルゴリズムのチュートリアル

 要素の合計という 2 つの値を維持します。$S$とプレフィックスの合計の合計$P$。 

1. 初期値を計算する$S$そして$P$元の配列から線形時間で変換します。 これにより、変換前のベースライン寄与が確立されます。 
2. それぞれについて$m$操作、変換がどのような影響を与えるかを決定する$(S, P)$可能な両方の操作に対応します。 選択するのではなく、最大化していることを観察するので、より良い結果の状態を採用します。 
3. 複製操作の場合$b \to b + b$の合計は となります$2S$。 プレフィックスサムの合計は次のようになります。$2P + S \cdot n$、2 番目のコピーのプレフィックスが によってシフトされるため、$S$それぞれの$n$要素。 
4. 逆プレフィックス操作については、プレフィックス反転アイデンティティを介して効果を分析します。反転すると、プレフィックス構造がサフィックス構造に変わります。 総額が残る$S$、プレフィックス合計の合計は次のように変換されます。$S \cdot (n+1) - P$。 これは、プレフィックスの合計とサフィックスの合計の合計が合計の合計のみに依存する閉じた形式を持つという事実に由来します。 
5. 各ステップで、より大きな結果が得られる操作を選択します。$P$、最終目標はまさに$P$後$m$変化。 
6. このプロセスを繰り返す$m$更新回数$(S, P, n)$したがって、それに留意して、$n$どちらの操作でも倍になります。 
7. 最終出力$P \bmod 10^9+7$。 

### なぜ効果があるのか

 重要な不変条件は、一連の操作の後、その長さ、合計、およびプレフィックス合計の合計のみを使用して、この目的のために配列全体を要約できることです。 どちらの操作でも、これらの集計がエンコードする内容を超える内部順序の知識を必要とせずに、これらの量を新しい値にマッピングできます。 これらの決定論的変換を繰り返し適用することで、結果として得られるすべての配列を表現できるため、各ステップで結果として得られるプレフィックス合計値を最大化する操作を貪欲に選択することで、最適性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

def prefix_sum(arr):
    s = 0
    p = 0
    for x in arr:
        s += x
        p += s
    return s, p

def transform_concat(s, p, n):
    ns = 2 * s
    np = 2 * p + s * n
    return ns, np, 2 * n

def transform_reverse_prefix(s, p, n):
    # reversed prefix identity
    ns = s
    np = s * (n + 1) - p
    return ns, np, n * 2

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    
    s, p = prefix_sum(a)
    cur_n = n

    for _ in range(m):
        s1, p1, n1 = transform_concat(s, p, cur_n)
        s2, p2, n2 = transform_reverse_prefix(s, p, cur_n)

        if p1 >= p2:
            s, p, cur_n = s1, p1, n1
        else:
            s, p, cur_n = s2, p2, n2

        p %= MOD
        s %= MOD

    print(p % MOD)

if __name__ == "__main__":
    solve()
```この実装では 3 つの状態変数のみを追跡します。 機能`prefix_sum`初期ペアを計算します$(S, P)$。 各変換関数はこれらの値を一定時間で更新します。 ループは、より大きなプレフィックス合計の寄与をもたらす操作を貪欲に選択します。 

実装の微妙な点は、モジュロは出力専用であるため、比較はモジュロの前に行う必要があることです。 モジュロを適用するのが早すぎると、順序付けの決定が崩れてしまいます。 

## 実用的な例

 ### 例 1

 入力:```
2 1
1 2
```初期値を計算します。 

| ステップ | 配列 | S | P |
 | --- | --- | --- | --- |
 | 初期化 | [1,2] | 3 | 1 + 3 = 4 |

 次に、両方の操作を評価します。 

重複すると次のようになります。 

配列 [1,2,1,2]、S = 6、P = 4 * 2 + 3 * 2 = 14

 逆接頭辞は次のようになります。 

配列 [2,1,1,2]、S = 3、P = 3 * 3 - 4 = 5

 重複を選択したので、答えは 14 になります。 

これは、最初の順序付けがすでに良好である場合に、重複によってプレフィックスの増加がどのように加速されるかを示しています。 

### 例 2

 入力:```
3 2
1 3 2
```イニシャル:

 S = 6、P = 1 + 4 + 6 = 11

 ステップ 1:

 重複: S=12、P=22 + 18 = 40

 Rev: S=6、P=6*4 - 11 = 13

 重複を選択します。 

ステップ 2:

 (12,40) から:

 重複: S=24、P=80 + 144 = 224

 Rev: S=12、P=12*7 - 40 = 44

 重複を選択します。 

最終的な P = 224。 

これは、重複が優勢になると、プレフィックスの増加が二次関数的に速く増加するため、重複が優勢であり続けることを示しています。

 ## 特殊なケース

 のために$n=1$、どちらの操作でも配列が意味のある変化をすることはありません。 州$(S,P)$予測可能な方法で両方の値を 2 倍にする重複によって決定論的に進化し、逆接頭辞は構造を実質的に変更しないままにします。 

のような配列の場合$[x, x, x, \dots]$どちらの操作でも同一のマルチセット動作が生成されますが、プレフィックスの蓄積は同一の初期寄与を繰り返し強化することで恩恵を受けるため、厳密には重複が優勢です。
