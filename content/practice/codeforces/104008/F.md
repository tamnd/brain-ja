 ## 解決策
 ## 問題の理解

 平面内にはいくつかの幾何学的領域が与えられます。 各領域は円形の扇形です。中心点、半径 (中心から 2 つの境界点までの距離によって暗黙的に与えられます)、および中心から始まる 2 つの光線間の角度範囲によって定義される円盤の一部です。 セクターは常にレイからの反時計回りのスイープです$OA$光線を当てる$OB$、角度は 180 度を超えないことが保証されています。 

タスクは、これらすべてのセクターの結合によってカバーされる総面積を計算することです。 重複する領域は 1 回だけカウントする必要があるため、個々のセクター領域の単純な合計は無効です。 

制約は非常に厳しいので、素朴な幾何学的なオーバーレイから私たちを遠ざけます。 と$n \le 1000$、二次または二次に近い方法は境界線にありますが、各相互作用が対数であるか、または慎重なイベント処理を使用する場合には許容できる可能性があります。 ただし、平面を離散化する方法やピクセル化を試みる方法は、最大の座標範囲のため直ちに不可能です。$10^4$そしてその必要性$10^{-6}$精度。 

微妙な問題は、セクターが複雑な曲線で重なる可能性があることです。 ポリゴンとは異なり、その境界には円弧が含まれるため、円弧を明示的に処理できるように拡張しない限り、標準的なポリゴン結合手法では不十分です。 

いくつかの特殊なケースが重要です。 

問題の 1 つは、角度スパンがゼロに近く縮退していることです。 A、O、B がほぼ同一線上にあるセクターでは、非常に薄いウェッジが生成されます。 単純な角度スイープでは、浮動小数点精度が原因で誤って破棄される可能性があります。 

もう一つの問題は完全な半円です。 角度は正確に 180 度であることが許容されるため、セクターは半円板になることができます。 このような 2 つのハーフディスクが重なる場合、それらの交差境界は湾曲し、ポリゴン クリッピングに還元できません。 

3 番目の問題は、中心は同じだが半径と角度が異なるネストされたセクターです。 大きなセクターの内側に完全にある小さなセクターは、完全に覆われていれば何も寄与しませんが、部分的に重なる場合は正しいアーク統合が必要です。 

概念的な主な課題は、すべてのセクターを欠落している相補的なセクターを除いた円盤に分解できることですが、その変換は結合を直接単純化しないことです。 

## アプローチ

 強引なアイデアは、各セクターの境界を密なポリゴン チェーンとして近似することです。つまり、各円弧を多数の小さな線分で置き換えてから、プレーン スイープやライブラリ ベースのポリゴン クリッピングなどのポリゴン結合アルゴリズムを実行します。 セグメンテーションを増やすと真の領域に収束するため、これは原理的には正しいと考えられます。 

ただし、各セクターを次のように近似すると、$k$セグメントを取得します。$O(nk)$エッジ。 中程度の精度でも必要な$k \approx 1000$、生産$10^6$エッジ。 そのスケール上のポリゴン結合は少なくとも$O(m \log m)$と$m = 10^6$、これは非常に遅く、メモリを大量に消費します。 さらに悪いことに、精度要件により、小さな角度付近でさらに細かい離散化が必要になります。 

重要な洞察は、円弧を完全に近似することを避け、代わりに各セクターの中心を中心に放射状に問題を分解することです。 セクターは当然極座標で定義され、点の集合です。$(r, \theta)$と$0 \le r \le R(\theta)$のために$\theta$合間に。 これは、各セクターを角度に関する関数として扱うことを示唆しています。各角度で、半径の間隔に寄与します。 

角度を固定すれば$\theta$、すべてのセクターは何も寄与しないか、放射状の間隔のいずれかに寄与します。$[0, R_i]$もし$\theta$はその角度範囲内にあります。 したがって、角度のある結合は、$\theta$単純に$[0, \max R_i(\theta)]$。 総面積は次の積分になります。$\theta$の$\frac{1}{2} R_{\max}(\theta)^2$。 

したがって、問題は、セクター境界によって引き起こされるすべての角度間隔にわたって、アクティブなセクター間の最大半径を見つけることに帰着します。 各セクターは、単位円上の間隔と定数値 (半径) に寄与します。 これを角度イベントのスイープとして扱い、アクティブな半径を追跡し、最大のクエリをサポートする構造を維持できます。 

セクターの開始角度と終了角度をすべてソートし、周囲をスイープします$2\pi$。 連続するイベント角度の間では、アクティブなセクターのセットは固定されているため、最大半径は一定であり、その角度スライスにわたる面積の寄与は単純に次のようになります。$\frac{1}{2} \Delta \theta \cdot R_{\max}^2$。 

マルチセットまたは遅延削除によるヒープを使用してアクティブな半径を維持します。 各セクターは開始角度で開始し、終了角度で終了します。 主な技術的な微妙な点は、ラップアラウンドを使用して角度順序を正しく計算し、精度のタイを処理することです。 

これにより、動的な最大クエリを使用して、ジオメトリが角度にわたるスイープ ラインに縮小されます。

 ## アルゴリズムのチュートリアル

 1. 各セクターを極パラメータに変換し、その半径を計算します。$R$中心からの距離として$O$どちらかのエンドポイントに$A$または$B$、角度を計算します$\alpha = \angle OA$、$\beta = \angle OB$標準で$[0, 2\pi)$形状。 これにより、すべてのセクターが明確に定義された角度間隔になります。 
2. もし$\alpha > \beta$、セクターがラップアラウンドしていると解釈します$2\pi$そしてそれを2つの区間に分割します$[\alpha, 2\pi)$そして$[0, \beta]$。 これにより、スイープ中の不連続が回避されます。 
3. 間隔のエンドポイントごとに、2 つのイベントを作成します。開始角度での挿入イベントと値$R$、および値を持つ終了角度の削除イベント$R$。 これらのイベントは、角度スイープでセクターがいつアクティブになるか非アクティブになるかを表します。 
4. すべてのイベントを角度ごとに並べ替えます。 複数のイベントが同じアングルを共有する場合は、挿入前に削除を処理します。 この順序付けにより、同じ境界でセクターが終了し、別のセクターが始まるときに、ゼロ幅領域が過剰にカウントされないことが保証されます。 
5. アクティブな半径のマルチセットを維持しながら、ソートされたイベントをスイープします。 いつでも、このセットの最大要素は次のことを表します。$R_{\max}(\theta)$現在の角度間隔の場合。 
6. 連続するイベントアングル間$\theta_i$そして$\theta_{i+1}$、角度幅を計算します。$\Delta \theta = \theta_{i+1} - \theta_i$。 貢献を追加する$\frac{1}{2} \cdot \Delta \theta \cdot (R_{\max})^2$答えに。 
7. すべてのイベントに従ってマルチセットを更新します。$\theta_{i+1}$、必要に応じて半径を挿入または削除し、スイープを続行します。 
8. 累積面積を出力します。 

### なぜ効果があるのか

 任意の固定角度で$\theta$、すべてのセクターは、原点からその半径までの完全な半径セグメントに寄与するか、まったく寄与しません。 したがって、その角度での和集合は常に単一の区間になります。$[0, R_{\max}(\theta)]$。 これにより、すべてのオーバーラップが半径方向空間での最大の操作に折りたたまれるため、セクター間のペアごとのオーバーラップを追跡する必要がなくなります。 スイープは、アクティブなセクターのセットが変更されない間隔に円を分割します。$R_{\max}$は各間隔内で一定であるため、角度全体を積分すると、近似せずに合計面積が正確に再構成されます。 

## Python ソリューション```python
import sys
import math
input = sys.stdin.readline

def angle(x, y):
    a = math.atan2(y, x)
    if a < 0:
        a += 2 * math.pi
    return a

n = int(input())
events = []

for _ in range(n):
    xo, yo, xa, ya, xb, yb = map(int, input().split())
    
    ra = math.hypot(xa - xo, ya - yo)
    rb = math.hypot(xb - xo, yb - yo)
    r = ra  # guaranteed equal

    a1 = angle(xa - xo, ya - yo)
    a2 = angle(xb - xo, yb - yo)

    # ensure CCW from a1 to a2, may wrap
    if a1 <= a2:
        events.append((a1, 1, r))
        events.append((a2, -1, r))
    else:
        events.append((a1, 1, r))
        events.append((2 * math.pi, -1, r))
        events.append((0.0, 1, r))
        events.append((a2, -1, r))

events.sort()

import bisect
active = []

def add(x):
    bisect.insort(active, x)

def remove(x):
    i = bisect.bisect_left(active, x)
    active.pop(i)

ans = 0.0
prev = 0.0

def current_max():
    return active[-1] if active else 0.0

for ang, typ, r in events:
    if ang != prev:
        if active:
            rmax = current_max()
            ans += 0.5 * (ang - prev) * rmax * rmax
        prev = ang

    if typ == 1:
        add(r)
    else:
        remove(r)

# no need to close circle because endpoints already cover [0, 2pi)
print("{:.10f}".format(ans))
```実装はスイープの後に直接続きます。 各セクターは角度イベントに分解され、ラップアラウンド セクターは次のように分割されます。$2\pi$連続性を保つために。 ソートされたリストではアクティブな半径が維持され、いつでも最大値を抽出できます。 

最もデリケートな部分はイベントの順序付けです。 このコードでは、各境界角度でアクティブ セットを更新する前に面積が計算されるようにするため、各角度間隔で正しい構成が使用されます。 ソートされたリストを使用すると削除が可能になります$O(n)$で許容されます。$n \le 1000$ただし、実稼働ソリューションでは、遅延削除を備えたヒープの方が望ましいでしょう。

 ## 特殊なケース

 重要なエッジ ケースは、複数のセクターが同じ角度で開始または終了する場合です。 このアルゴリズムは、次の間隔に寄与を適用する前に、境界にあるすべてのイベントを一貫して処理します。 これにより、共有エンドポイントでの二重カウントが防止されます。 

もう 1 つのケースは、交差するラップアラウンド セクターです。$2\pi$。 それらを 2 つの間隔に分割することにより、スイープで不連続なジャンプが発生することはなく、結合は 2 つの間隔の境界を越えて正しいままになります。$2\pi$そして$0$。 

最後に、アクティブなセクターが 1 つだけ残っている場合、アルゴリズムは標準のセクター領域の式に正しく変換されます。 マルチセットには半径が 1 つだけ含まれており、積分は単一の連続した円弧セグメントになるため、スイープではこれが自然に処理されます。
