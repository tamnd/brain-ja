 ## 問題の理解

 全長が整数の単一の木の棒を分割するように求められます。$m$正確に$n$正の整数部分。 切断後、結果として得られる長さのマルチセットの 2 つの量を調べます。 

最初の数量は「容量」で、最小のピースの長さとして定義されます。 2 番目の量は「醜さ」で、すべての部分の長さのビットごとの XOR として定義されます。 XOR 値が最小部分の長さよりも厳密に小さい場合、構成は有効であるとみなされます。 

したがって、タスクは純粋に建設的です。テスト ケースごとに、次のいずれかの有効なパーティションを出力します。$m$の中へ$n$この不等式を満たす正の整数を指定するか、そのようなパーティションが存在しないと判断します。 

制約はテスト ケースの数が多く、最大で$10^5$、合計で$n$まで$3 \cdot 10^5$そして合計$m$まで$10^7$。 これにより、テストケースごとの検索、バックトラッキング、または DP オーバーに依存するものはすべて除外されます。$m$。 出力の構築とは別に、ソリューションはテスト ケースごとに一定時間である必要があります。 

この問題の最もデリケートな側面は、最小値と XOR の両方が完全なディストリビューションに依存するため、有効な構成が存在する場合でも単純な貪欲な分割は簡単に失敗する可能性があることです。 

いくつかの小さな例で落とし穴を説明します。 

いつ$n=2, m=3$、可能な分割は次のとおりです。$(1,2)$。 XOR は$1 \oplus 2 = 3$、最小値は$1$, したがって、条件は失敗します。 これに代わる構造はないので、答えは「NO」となります。 

いつ$n=2, m=4$、使用できます$(2,2)$。 XOR は$0$、最小値は$2$、これは機能します。 

いつ$n=3, m=5$の場合、すべてのパーティションに 1 が含まれて最小値が 1 になるか、常にゼロ以外の XOR が生成されます。 すべての試みは失敗しますが、$m$多くの分割を可能にするのに十分な大きさです。 これは、実際の障害は大きさではなくパリティであることを示唆しています。 

## アプローチ

 ブルートフォースアプローチでは、すべての構成を列挙します。$m$の中へ$n$正の整数を入力し、それぞれの XOR と最小値を計算します。 そのような構成の数は$\binom{m-1}{n-1}$、これは指数関数的です$n$したがって、中程度の値であっても、これは実行不可能になります。 

条件の構造は、制約が最小値に対して XOR を比較するため、最小値をできるだけ小さくするよう強制する必要があることを示唆しています。 最小値が 1 の場合、XOR は厳密に 1 より小さい必要があり、XOR は厳密に 0 になります。これにより、XOR のパリティ動作を制御するだけで済むため、条件が大幅に簡素化されます。 

これにより、自然な構造が得られます。多数の 1 を使用して最小値を固定し、残りの質量をすべて 1 つの大きな要素に配置します。 唯一の問題は、この構造で XOR をゼロにできるかどうかです。 答えは、次のパリティのみに依存することがわかります。$m$。 

重要な観察は、次のことです。$n-1$one は XOR を予測可能にし、最後の要素に合計制約と XOR 条件の両方を強制的に吸収させます。 これにより、問題は単純なパリティ チェックに軽減されます。

 ## アルゴリズムのチュートリアル

 ### 1. 不可能な単体ケースに対処する

 もし$n = 1$、数値は 1 つだけなので、最小値と XOR は両方とも等しい$m$。 The condition requires$m < m$、これは決して成り立たないので、すぐに NO を出力します。 

### 2. 最小値を強制的に 1 にしてみます

 私たちは建設します$n-1$これにより、最小値が 1 であることが保証されます。これは可能な限り最小の正の整数であり、XOR で最も強力な制約緩和が得られます。 

### 3. 残りの質量を最後のピースに割り当てます

 最後の要素を次のようにします$$x = m - (n - 1).$$これにより、総和制約が正確に保持されます。 

### 4. 条件を XOR パリティに変換します。 

すべての XOR$n-1$あるかどうかのみに依存します。$n-1$奇数か偶数です。 最後の XOR は次の単純な関数になります。$x$そしてこのパリティ。 

XOR は厳密に 1 より小さい必要があるため、XOR が 0 に等しいことが要件となります。これにより、パリティ条件が強制されます。$m$、そしてそれは要求することを単純化します$m$均等になるように。 
### 5. 有効な出力構造
 ID$m$偶数、出力$n-1$続いてのもの$x$。 それ以外の場合は、NO を出力します。 

### なぜ効果があるのか

 この構造では最小値が 1 にロックされ、不等式制約が減って XOR が 0 になるように強制されます。残りの自由度はパリティ動作に組み込まれます。つまり、最後の要素を除くすべての寄与が固定され、最後の要素は合計制約によって一意に決定されます。 固定 1 に対する XOR はパリティにのみ依存するため、システム全体は単一のグローバル パリティ条件に縮小されます。$m$。 その条件が当てはまる場合、構築された配列は両方の制約を満たします。 失敗した場合、最小値を 1 から変更せずに再配置しても修正できません。XOR 制約が厳しくなるだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n, m = map(int, input().split())

        if n == 1:
            out.append("NO")
            continue

        if m % 2 == 1:
            out.append("NO")
            continue

        # construct
        arr = [1] * (n - 1)
        arr.append(m - (n - 1))

        # safety: last must be positive (it always is since m >= n)
        out.append("YES")
        out.append(" ".join(map(str, arr)))

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```実装は構築の直後に行われます。 唯一の微妙な点は、ケースごとに出力するのではなく出力を蓄積することで、複数のテスト ケースを効率的に処理できるようにすることです。 

配列は次のように構築されます$n-1$最小値を強制するものと、最後の要素が残りの合計を吸収します。 パリティ チェックは、XOR 制約を保証するために必要な唯一の条件です。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

        n, m = map(int, input().split())

 ## 特殊なケース

 いつ$n = 1$の場合、単一の数値はそれ自体と XOR が等しいため、アルゴリズムは即座に拒否し、厳密な不等式は不可能になります。 たとえば、入力$1, 7$NO が生成され、この構造上の制限を回避できる構造はありません。 

いつ$m$が奇数である場合、この構造により最終的な XOR でパリティの不一致が強制され、有効な構成が依然として同じグローバル パリティ制約を継承しているため、大量の再配布の試みも失敗します。 例えば、$n=3, m=5$多くのパーティションが存在するにもかかわらず、解決策がありません。 

いつ$m$は均等であり、$n$が大きくても、配列の大部分が 1 に固定されており、最後の要素は単に 1 に応じてスケーリングされるため、構造は安定しています。$m$、合計と実現可能性の両方を維持します。
