 ## 問題の理解

 異なる小文字文字列のコレクションが与えられます。 各文字列はラベルとして考えることができます。 私たちは、異なる文字列のトリプル間の入れ子になった部分文字列の関係に興味があります。 

有効な構成はインデックスの 3 つです。$(i, j, k)$すべてのインデックスが異なるように、次の文字列は$i$の文字列内の連続した部分文字列として表示されます。$j$、および次の文字列$j$の文字列内の連続した部分文字列として表示されます。$k$。 それで$i \to j \to k$部分文字列を含めて厳密な封じ込めチェーンを形成します。 

ただし、そのようなチェーンすべてがカウントされるわけではありません。 チェーンは次の意味で「一意」である必要があります: 固定ペアの場合$(i, k)$、中間文字列$j$すべての中で唯一の文字列である必要があります$n$この部分文字列関係においてそれらの間に同時に存在する文字列。 他にインデックスが存在する場合$j'\neq i,j,k$そのような$s_i$の部分文字列です$s_{j'}$そして$s_{j'}$の部分文字列です$s_k$の場合、トリプルは無効になります。 

したがって、問題は本質的に部分文字列の半順序で長さ 3 のチェーンをカウントすることですが、それは中央の要素がエンドポイント間の一意の中間ノードであるチェーンのみです。 

制約は大きく、最大で$10^6$文字列と全長$2 \cdot 10^6$。 これにより、文字列のすべてのペアを比較したり、部分文字列の関係を単純にチェックしたりするアプローチは即座に排除されます。 ナイーブ$O(n^2 \cdot L)$部分文字列のチェックは限界をはるかに超えています。 

この構造は、部分文字列の包含関係を一括して抽出する必要があり、その後、部分文字列の包含によって定義される有向非巡回グラフ内の特殊なチェーンをカウントする必要があることを示唆しています。 

複数の同一パターンが大きな文字列の異なるコンテキストで出現する場合、微妙なエッジ ケースが発生します。 たとえば、短い文字列が多くの長い文字列の中に出現する場合、複数の中間候補が存在するため、チェーンを除外する必要があります。 もう 1 つの注意が必要なケースは、複数の中間文字列が同じエンドポイント ペアに存在し、それらのトリプルがすべて無効になる場合です。 

主要な問題は、部分文字列の関係を検出することではなく、エンドポイントのペアごとに中間ノードの一意性を確保することです。 

## アプローチ

 強引な解釈は簡単です。 トリプルごとに$(i, j, k)$かどうかを確認します。$s_i \subset s_j \subset s_k$部分文字列一致を使用して保持されます。 これにはすでに費用がかかります$O(L)$KMP などを使用してチェックごとに、$O(n^3 L)$、それはまったく不可能です。 

ペアに減らしても、それぞれについて試すことができます$(j,k)$すべての部分文字列を列挙するには$s_k$いくつか一致するもの$s_j$、再び一致します$s_i$ただし、部分文字列の列挙自体は文字列の長さが 2 次です。 

重要な点は、実際にはすべての部分文字列が必要なわけではないということです。 各文字列について、他のどの文字列にその文字列が部分文字列として含まれているか、またそれらの中で、指定されたエンドポイント ペアの有効な中間位置を形成する文字列がいくつあるかを知る必要があるだけです。 

これは当然、すべてのテキストに対してすべてのパターンを同時に照合できるグローバル構造を構築することを示唆しています。 このための標準ツールは、すべての文字列に対して構築された Aho-Corasick オートマトンで、各文字列をパターンとテキストの両方として扱います。 

このような構造ですべての文字列を実行すると、各文字列を計算できるようになります。$x$それを部分文字列として含むすべての文字列。 これにより、エッジが部分文字列の包含を表す有向グラフが得られます。 

ただし、一意性制約を使用してトリプルをカウントする必要があります。 長さ 2 のパスを直接カウントする代わりに、問題を再構成することができます。 

固定ペアの場合$(i,k)$、中間体の数が必要です$j$そのような$i \subset j \subset k$ただし、この中間が固有であるペアのみが必要です。 つまり、ペアごとに$(i,k)$、有効な中間体の数がちょうど 1 の場合、答えに 1 が寄与します。 

したがって、問題はペアを数えるということになります$(i,k)$ノード間の 2 ステップの部分文字列チェーン上に 1 つのノードが存在します。 

文字列ごとに計算できます$j$、何ペア$(i,k)$それは独自に仲介します。 それは回数にもよるけど$i$に登場する$j$そして何回も$j$に登場する$k$ただし、他の中間が同じエンドポイントのペアと重複しないようにする必要があります。 

これは、テキスト内のパターンの出現ごとに、その出現がそのエンドポイントのペアにとって「排他的」であるかどうかを追跡することによって処理されます。 重要なトリックは、すべての文字列を長さでソートする場合、有効なチェーンは減少しない長さを尊重する必要があるということです。 これにより、構造が DAG に変わります。 

次に、文字列を昇順に処理し、オートマトンからの出現カウントを使用して、各テキスト内で各パターンが出現する回数を維持できます。 中間ノードごとに$j$、有効なものをすべて累積します$(i,k)$エンドポイント ペアごとに周波数マップ内の重複をカウントすることで、複数の中間が存在するケースを減算します。 これは、正確に 1 つの中間体が存在するペアの寄与をカウントすることに帰着できます。これは、少なくとも 2 つの中間体が存在するペアを減算することと同等です。 

最終的な効率的なソリューションは、Aho-Corasick を介してすべての部分文字列の一致を計算し、各ペアの中間カウントを集計し、「正確に 1 つ」を包含除外オーバー カウントに変換することに依存しています。

 ## アルゴリズムのチュートリアル

 すべての文字列に対してマルチパターン マッチング オートマトンを構築し、それを使用して部分文字列の包含関係を効率的に計算します。 

1. すべての文字列を Aho-Corasick オートマトンに挿入し、それが表す文字列のインデックスを各終端ノードに保存します。 これにより、別の文字列をスキャンしているときに、ある文字列がパターンとして出現することを検出できます。 
2. 文字列ごとに$s_k$、オートマトンを通して実行します。 何らかのパターンに対応するノードに到達するたびに$s_j$、それを記録します$j$の部分文字列です$k$。 これをエッジとして保存します$j \to k$圧縮された隣接表現で。 

このステップでは、部分文字列の関係を明示的な有向エッジに変換します。 
3. 文字列ごとに$j$、逆リストも維持します: all$i$そのような$i \subset j$。 これは、オートマトンの走査中にすべての文字列をテキストとパターンの両方として扱うことによって対称的に取得されます。 
4. 次に、トリプルを数える必要があります。$(i,j,k)$そのような$i \to j \to k$、しかし独自性を持っています$j$それぞれに$(i,k)$。 トリプルを反復する代わりに、中間ノードごとに寄与を集計します。 
5.固定の場合$j$、すべての受信ノードを考慮します$i$および発信ノード$k$。 すべてのペア$(i,k)$を通して$j$1 つの候補チェーンを提供します。 をキーとするハッシュ マップを維持します。$(i,k)$これは、このペアを生成するさまざまな中間体の数を数えます。 
6.すべての処理が完了したら$j$、すべてのペアを合計します$(i,k)$このマップ内でカウントがちょうど 1 であるもの。 このようなペアはそれぞれ、有効なトリプルを 1 つだけ提供します。 

### なぜ効果があるのか

 すべての有効なトリプルはペアに一意に対応します$(i,k)$選ばれた中間者と一緒に$j$。 同じエンドポイントに複数の中間が存在する場合、そのペアのカウントは少なくとも 2 になり、除外されます。 すべての部分文字列関係はオートマトンのトラバーサルを通じて 1 回だけキャプチャされるため、有効な関係が失われたり重複したりすることはありません。 一意性条件は、問題の定義と正確に一致する、エンドポイント ペアごとの中間体の多重度をカウントすることによって純粋に適用されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Node:
    __slots__ = ("next", "link", "out")
    def __init__(self):
        self.next = {}
        self.link = 0
        self.out = []

def build_aho(patterns):
    nodes = [Node()]
    
    # build trie
    for idx, s in enumerate(patterns):
        v = 0
        for ch in s:
            if ch not in nodes[v].next:
                nodes[v].next[ch] = len(nodes)
                nodes.append(Node())
            v = nodes[v].next[ch]
        nodes[v].out.append(idx)

    # build failure links
    from collections import deque
    q = deque()
    for c, u in nodes[0].next.items():
        nodes[u].link = 0
        q.append(u)

    while q:
        v = q.popleft()
        for c, u in nodes[v].next.items():
            f = nodes[v].link
            while f and c not in nodes[f].next:
                f = nodes[f].link
            if c in nodes[f].next:
                nodes[u].link = nodes[f].next[c]
            else:
                nodes[u].link = 0
            nodes[u].out += nodes[nodes[u].link].out
            q.append(u)

    return nodes

def solve():
    n = int(input())
    s = [input().strip() for _ in range(n)]

    ac = build_aho(s)

    contains = [set() for _ in range(n)]  # j contains i

    # run each string as text
    for j, text in enumerate(s):
        v = 0
        for ch in text:
            while v and ch not in ac[v].next:
                v = ac[v].link
            if ch in ac[v].next:
                v = ac[v].next[ch]
            else:
                v = 0
            for pat in ac[v].out:
                if pat != j:
                    contains[j].add(pat)

    # count pairs (i,k) via intermediates
    from collections import defaultdict
    cnt = defaultdict(int)

    for j in range(n):
        ins = list(contains[j])
        for i in ins:
            for k in range(n):
                if k != j and j in contains[k]:
                    cnt[(i, k)] += 1

    ans = 0
    for v in cnt.values():
        if v == 1:
            ans += 1

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションはマルチパターン オートマトンを構築し、それを使用してすべての部分文字列の出現を検出します。 の`contains`list は、自己一致を除いて、各文字列内にどのパターンが出現するかを記録します。 その後、コードはすべての有効な中間ノードを列挙します。$j$、そのようなノードごとにすべてのノードが接続されます$i \subset j$あらゆるものと$j \subset k$、エンドポイント ペアのカウンターをインクリメントします$(i,k)$。 最後に、中間が 1 つだけ存在するエンドポイント ペアのみがカウントされます。 

ネストされたループ$j, i, k$は、三重の定義を概念的に翻訳したものです。 オートマトンは部分文字列検出の正確さを保証し、カウンティング マップは一意性を強制します。

 ## 特殊なケース

 重要なエッジ ケースは、複数の文字列に同じ中間パターンが含まれる場合です。 仮定する$s_i$2 つの異なる候補者が表示されます$s_{j_1}$そして$s_{j_2}$、両方とも同じに含まれています$s_k$。 それなら両方とも$(i,j_1,k)$そして$(i,j_2,k)$構造的には有効ですが、中間体が一意ではないため、どちらもカウントされるべきではありません。 

両方の中間が同じキーをインクリメントするため、アルゴリズムはこれを自然に処理します。$(i,k)$、少なくとも 2 のカウントが生成されます。1 に等しいカウントのみが受け入れられるため、両方は除外されます。 

もう 1 つのケースは、文字列が複数の役割の中間とエンドポイントの両方である場合です。 固定による役割の分離$j$反復により自己干渉がないことが保証され、条件が$i \neq j \neq k$ペア構築では明示的に適用されます。
