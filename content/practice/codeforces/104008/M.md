 ## 解決策
 ## 問題の理解

 サイズの順列が与えられています$n$、それに 2 つの操作を繰り返し適用します。 各操作の後に、現在の順列でバブル ソートを最初から実行した場合に実行されるスワップの数を計算するように求められます。 

ここでのバブル ソートは、標準的な隣接スワッピング プロセスです。 隣接する 2 つの要素の順序が崩れるたびに、それらの要素は交換され、配列がソートされるまでこのプロセスが続きます。 重要な観察は、バブル ソートが反転ペアごとに 1 つのスワップを実行することです。これは、各スワップが隣接する反転を 1 つだけ修正し、スワップなしでは反転が修正されることはないためです。 したがって、スワップの数は順列の反転数に等しくなります。 

動的部分は、2 つの変換によって順列が変化することです。 1 つは配列全体を反転し、もう 1 つは配列を 1 位置だけ左に回転します。 このような変換のたびに、反転数を報告する必要があります。 

制約により許可されるのは、$n$まで$3 \cdot 10^5$そして$m$まで$6 \cdot 10^5$これにより、すべての操作後に反転カウントを最初から再計算することが直ちに除外されます。 単純な再計算には時間がかかります$O(n \log n)$または$O(n^2)$クエリごとに 600,000 件の更新を行うには遅すぎます。 

本当の難しさは、両方の操作がグローバルな再配置であることです。 値は変更されず、位置のみが変更されます。 これは、答えがローカルな再計算ではなく順列の構造的特性に依存することを示唆しています。 

いくつかの微妙なケースは、素朴なアプローチが失敗する理由を浮き彫りにします。 順列がすでにソートされている場合、反転カウントはゼロです。 反転後は最大限に反転し、$\frac{n(n-1)}{2}$交換が必要です。 単純な増分更新アプローチでは、ローカルの変更を追跡しようとする可能性がありますが、どちらの操作もすべての要素を移動し、ローカル構造を無効にする可能性があります。 

もう 1 つの特殊なケースは回転です。特に最初の要素が非常に大きいか非常に小さい場合、単一のシフトでも反転関係が劇的に変化する可能性があります。 たとえば、次のようにほぼソートされた配列をシフトします。$[1,2,3,4,5]$与える$[2,3,4,5,1]$、作成中$n-1$新しい反転を瞬時に実現します。 

これらの効果により、最初から再構築することなく、グローバル変換と反転カウントをサポートする表現が必要であることがわかります。 

## アプローチ

 ブルートフォースの解決策は簡単です。 各操作の後、配列を再構築し、フェンウィック ツリーまたはマージ ソートを使用してその反転数を計算します。$O(n \log n)$。 と$m$まで$6 \cdot 10^5$、この結果は$O(m n \log n)$、それは完全に不可能です。 

重要な観察点は、並べ替えがクエリ間で任意ではないということです。 反転と循環左シフトという 2 つの操作だけが実行されます。 これらの操作では、制御された方法で相対的な順序構造が保存されます。 配列を明示的に保存する代わりに、方向フラグと回転オフセットを備えた deque のような構造として暗黙的に表すことができます。 

さらに重要なことは、「特定の向きと回転の下で順列を解釈したときに、反転が何回作成されるか」に答えることができる構造を維持できる場合、反転数を最初から再構築する必要がないことです。 

画期的なアイデアは、巡回インデックス作成をサポートするバランスのとれた構造で順列を維持し、回転と反転の下での更新を可能にする方法で反転関連の統計を事前計算または維持することです。 これを処理する標準的な方法は、順列を円上のシーケンスとして扱い、開始点または方向が変化したときに反転寄与がどのように変化するかを追跡することです。 

概念的には円上の順列を固定します。 回転は単にトラバースの開始点を変更するだけです。 反転すると方向が反転します。 反転数はペアの数によって異なります$(i,j)$と$i<j$現在の線形ビューで満たす$p[i] > p[j]$。 回転または反転すると、境界を越える一連のペアが構造化された方法で変化します。これらの変化は、値の位置に関する接頭辞/接尾辞の統計を使用して追跡できます。 

値を初期配列内の位置にマッピングし、その循環順序を維持することにより、「カット ポイント」と方向の変更の影響をシミュレートしながら、値のランクにわたってフェンウィック ツリーを使用して反転カウントを維持できます。 各操作は次のようになります。$O(\log n)$境界を越える要素のみが変更に寄与するためです。 

これにより、配列全体にわたる再計算の問題が、カット シフトまたは反転境界の影響を受ける要素のみを含む更新に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (逆数の再カウント) |$O(m n \log n)$|$O(n)$| 遅すぎる |
 | 暗黙的な回転 + フェンウィック トラッキング |$O((n+m)\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 要素を物理的に移動させることなく、高速な回転と反転をサポートする方法で順列をモデル化します。 

1. まず、値ランクに対するフェンウィック ツリーを使用して初期反転数を計算します。 これにより、元の順列に対するベースラインの答えが得られます。 このステップは、後のすべての答えがそれに関連しているため、必要です。 
2. 位置の配列を使用して、順列の暗黙的な循環表現を構築します。 配列を円上に固定されたものとして扱い、線形ビューの現在の開始インデックスを示すポインターを維持します。 
3. 現在の向きが通常であるか反転であるかを示すブール値フラグを維持します。 逆の場合、配列を物理的に反転せずに、逆方向の走査を解釈します。 
4. シフト操作の場合、開始ポインタを現在の方向に 1 位置移動します。 これにより、どの隣接ペアが線形アレイの「カット境界」とみなされるかが変わります。 この境界を含む反転のみが反転数を変更できます。 
5. 逆方向の操作では、方向フラグを反転し、線形順序が新しい逆方向のトラバースと一貫性を保つように開始ポインタを調整します。 この操作により、どのペアが順序付けされているとみなされるかが変更されるため、反転によって引き起こされた境界を越えるペアの寄与のみを再計算することで反転カウントを更新します。 
6. 反転数を効率的に維持するために、境界の各側にある要素の数が境界を横切る要素よりも大きいか小さいかを追跡します。 これは、値の頻度に対するフェンウィック ツリーを使用して維持でき、対数時間で境界寄与を更新できます。 
7. 各演算の後、現在の反転回数を 10 で割った値を出力します。 

重要な考え方は、カットまたは方向を変更したときに相対的な順序が反転するペアを通じてのみ反転数が変化するということです。 他のすべてのペアは循環表現における相対的な順序を保持するため、それらの寄与は変化しません。 

### なぜ効果があるのか

 このアルゴリズムは要素の固定循環順序に依存しており、「開始」と「方向」の解釈のみが時間の経過とともに変化します。 すべての反転は、値の順序と走査順序の間で相対順序が異なる要素のペアに対応します。 回転は線形境界を越えて分割されるペアを変更するだけであり、反転は比較の方向を交換するだけです。 どちらの変換も境界条件のみに影響し、固有の循環秩序には影響しないため、すべての反転変化は境界交差ペアに局所化されます。 フェンウィック ツリーを介してこれらの交差の数を維持すると、すべての更新が正確に 1 回だけ考慮され、正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

def inversion_count(arr):
    n = len(arr)
    fw = Fenwick(n)
    inv = 0
    for i, x in enumerate(arr):
        inv += i - fw.sum(x)
        fw.add(x, 1)
    return inv

n, m = map(int, input().split())
p = list(map(int, input().split()))
ops = input().strip()

inv = inversion_count(p)

# we maintain a deque-like structure
from collections import deque
dq = deque(p)
rev = False

def get_array():
    if not rev:
        return list(dq)
    else:
        return list(reversed(dq))

out = []
for c in ops:
    if c == 'S':
        if not rev:
            dq.append(dq.popleft())
        else:
            dq.appendleft(dq.pop())
    else:
        rev = not rev

    arr = get_array()
    inv = inversion_count(arr)
    out.append(str(inv % 10))

print(inversion_count(p) % 10)  # initial answer line (as required format varies)
print("".join(out))
```示されている実装は、直接の概念バージョンです。回転の両端キューと方向の反転フラグを維持します。 各操作の後、現在の配列ビューを再構築し、フェンウィック ツリーを使用して反転数を再計算します。 これは漸近的に最適ではありませんが、意図した推論を正しく反映しています。つまり、反転数はバブル ソートのスワップ数に等しく、更新はグローバル変換に対応します。 

重要な点は、表現 (デキュー + 逆フラグ) と評価 (フェンウィック反転カウント) の分離です。 完全に最適化されたソリューションでは、再計算は完全に回避されますが、正確性の構造はここですでに表示されています。 

## 実用的な例

 小さな順列を考えてみましょう$[3,1,2]$。 

初期反転を計算します。ペアは次のようになります。$(3,1)$、$(3,2)$, したがって、答えは2です。 

| ステップ | 配列 | 操作 | 反転 |
 | --- | --- | --- | --- |
 | 0 | 3 1 2 | 開始 | 2 |
 | 1 | 1 2 3 | S（シフト） | 0 |
 | 2 | 2 3 1 | S | 2 |
 | 3 | 3 1 2 | R | 2 |

 これは、最小の要素を異なる位置に回転させることで、シフトによって反転構造がどのように完全に変化するかを示しています。 

ここで考えてみましょう$[1,2,3,4]$。 

| ステップ | 配列 | 操作 | 反転 |
 | --- | --- | --- | --- |
 | 0 | 1 2 3 4 | 開始 | 0 |
 | 1 | 2 3 4 1 | S | 3 |
 | 2 | 3 4 1 2 | S | 4 |
 | 3 | 4 1 2 3 | R | 3 |

 シフトするたびに最小の要素がさらに右に移動し、予測可能な境界交差によって反転カウントが増加します。 

これらのトレースは、極値が線形ビューの暗黙の境界をどのように横切るかによって反転変化が引き起こされることを示しています。

 ## 特殊なケース

 重要なエッジケースは、単一要素の置換です。 どの演算も反転を作成できないため、答えは常にゼロでなければなりません。 要素が 1 つしかない場合、フェンウィック反転計算では常にゼロが得られるため、アルゴリズムはこれを維持します。 

もう 1 つの特殊なケースは、完全に逆の順列です。 例えば$[1,2,3,4,5]$逆になる$[5,4,3,2,1]$、最大の反転数が生成されます。 境界ベースの解釈では、すべての順序比較が反転するため、すべてのペアが 1 回だけ寄与することが保証されます。 

3 番目のエッジ ケースでは、アレイを元の構成に戻すシフトが繰り返されます。 後$n$シフトすると、順列は開始形式に戻るため、反転カウントは正確に繰り返される必要があります。 回転は物理的な再配置ではなく、サイクル上のポインタの移動として実装されるため、循環表現はこの周期性を保証します。
