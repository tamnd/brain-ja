 ## 問題の理解

 正の整数の複数セットが与えられ、それらを任意の順序で並べ替えることができます。 次数を選択した後、この次数のプレフィックスを繰り返し取得し、各プレフィックスの gcd を計算し、それらの gcd 値をすべて合計します。 

重要な観察は、これまでのところ、各位置の寄与が完全にプレフィックス gcd に依存しているということです。 新しい数値が追加されると、gcd は同じままか、その約数まで減少します。 自由に並べ替えることができるため、問題全体は、大きな gcd 値が必然的に低下する前にできるだけ長く持続するように数値を配置することになります。 

制約は大きく、最大で$10^5$それぞれ最大の数値$2 \cdot 10^7$。 これにより、多くの順列に対して gcd を再計算したり、順列に対して貪欲なシミュレーションを試みたりするアプローチは除外されます。 おおよそを超えたもの$O(n \log A)$または$O(n \sqrt{A})$テストごとに苦労するでしょう。 

多くの数値が小さな約数を共有しているものの、大きな共通構造が存在しない場合、微妙な特殊なケースが発生します。 たとえば、すべての数値が互いに素である場合、順序に関係なく、最初の要素の後で gcd はすぐに 1 に折りたたまれます。 もう 1 つのエッジ ケースは、1 つの数値が非常に大きく、他のすべての数値がそれを分割する場合です。これにより、最初に配置された場合、長いプレフィックスに対して大きな gcd を維持できます。 

## アプローチ

 ブルートフォース戦略では、すべての順列を試し、それぞれのスコアを計算します。 順列を修正しても、スコアの計算は線形であるため、完全な検索は次のようになります。$O(n! \cdot n)$、完全に不可能です。 

より合理的なステップは、貪欲に考えることです。 すでにプレフィックス gcd があると仮定します。$g$。 数字を付けると$x$、新しい gcd は次のようになります$\gcd(g, x)$。 最良の結果は維持することです$g$できるだけ多くのステップに対して大きくします。 これは、現在の gcd を維持する数値を早期に配置することを示唆しています。 

ただし、これには依然として核となる問題が残されています。各ステップで、残りのどの数値が特定の gcd を最もよく維持するかを知る必要があり、gcd の状態は以前に選択されたすべての要素に依存します。 

重要な構造的洞察は、視点を逆転させることです。 順列を構築する代わりに、ある段階で各値がプレフィックスの gcd として機能する方法を検討します。 値を固定すると$d$で割り切れる数はいくつあるかを尋ねることができます。$d$、および gcd を正確に維持できるプレフィックスの数$d$。 これにより、問題は順列のシミュレーションではなく、約数にわたる寄与の集計に変換されます。 

周波数ごとに除数ベースの DP を使用します。$d$で割り切れる配列要素の数を計算します。$d$次に、gcd が次の値に等しい期間をどれくらい維持できるかを推論します。$d$より小さい約数に強制的に引き下げられる前に。 大きいものから小さいものまで除数を処理すると、より厳密な gcd 状態からの寄与が最初に考慮されるようになります。

 ## アルゴリズムのチュートリアル

 私たちは定義します$cnt[x]$値の周波数として$x$までの倍数を処理します。$A = \max(a_i)$。 

1. 周波数配列を計算する$cnt$。 これにより、倍数を集計することで、任意の数で割り切れる要素の数をすぐに知ることができます。 
2. 各整数について$d$1から$A$、計算する$f[d]$、で割り切れる要素の数$d$。 これは、複数回反復することによって行われます。$d$。 このステップでは、生の値を除数ベースの構造に変換します。 
3. DP 配列を定義する$dp[d]$、 どこ$dp[d]$gcd が正確に一致するセグメントから得られる最大の寄与を表します。$d$で割り切れる数値のみを使用すると仮定すると、$d$。 
4. プロセス$d$降順で。 それぞれについて$d$, まず、次の要素で割り切れる要素の数を計算します。$d$。 プレフィックス gcd が次のようになると判断した場合、$d$、そのような各ポジションは少なくとも貢献します$d$。 
5. ただし、以下で割り切れる数のうち、$d$、実際に gcd を強制的に次の倍数に下げるものもあります。$d$の約数。 過大カウントを修正するために、すでに割り当てられている寄与分を減算します。$d$、複数に対して包含-除外を使用します。 
6. 回答を全体の合計として累積します$d$gcd を維持できるステップ数によって重み付けされた貢献度$d$より小さい値に移行する前に。 

重要な考え方は、すべてのプレフィックス gcd 遷移は割り算構造によって管理され、各数値は割り数チェーンにのみ関与するということです。 

### なぜ効果があるのか

 プレフィックスの gcd は常に、そのプレフィックス内のすべての要素の約数です。 これは、すべてのプレフィックス状態が何らかの除数に一意に対応することを意味します。$d$、そして、プロセスを約数の観点から解釈すると、各要素は、それがサポートするすべての約数の状態に独立して寄与します。 大から小まで処理することで、寄与を計算する際に、$d$、すべてのより強力な制約 (の倍数)$d$) はすでに考慮されているため、二重カウントが防止され、蓄積されたプレフィックス長の正確さが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    A = max(a)

    cnt = [0] * (A + 1)
    for x in a:
        cnt[x] += 1

    # f[d] = how many numbers divisible by d
    f = [0] * (A + 1)
    for d in range(1, A + 1):
        s = 0
        for m in range(d, A + 1, d):
            s += cnt[m]
        f[d] = s

    # dp[d] = best contribution where gcd-state is exactly d
    dp = [0] * (A + 1)

    ans = 0

    for d in range(A, 0, -1):
        if f[d] == 0:
            continue

        # total positions we could potentially assign gcd divisible by d
        total = f[d]

        # subtract contributions from multiples (inclusion-exclusion)
        for m in range(2 * d, A + 1, d):
            total -= dp[m]

        if total > 0:
            dp[d] = total
            ans += dp[d] * d

    print(ans)

if __name__ == "__main__":
    solve()
```コードは最初に周波数を構築し、次にそれを除数多重度カウントに変換します。 dp 配列は、計算時に除数に対してボトムアップで使用されます。$d$、すでにその倍数に割り当てられているすべての寄与を減算し、「プレフィックス容量」の各単位が正確に 1 つの gcd レベルに割り当てられるようにします。 最終的な答えは、各 gcd 値にそれが支配できるプレフィックス位置の数を乗算して累積します。 

よくある落とし穴は、間違った方向に約数を繰り返すことです。 小さいものから大きいものへ処理すると、倍数はまだ解決されておらず、減算は失敗します。 もう 1 つの微妙な点は、DP が暗黙的に最適な順序付けをすでにエンコードしているため、順列を明示的に構築しないことです。

 ## 特殊なケース

 すべての数値が等しい場合、gcd は決して変化しないため、すべてのプレフィックスは同じ値になります。 アルゴリズムはその値の除数に全容量を割り当てますが、倍数が存在しないため減算によって除数が削除されず、$n \cdot x$。 

すべての数値がペアごとに互いに素である場合、すべての数値が互いに素である場合、$f[d]$以外はゼロです$d=1$。 DP はすべてを次のように割り当てます。$d=1$、そして答えは次のようになります$n$これは、最初の要素の直後にすべてのプレフィックス gcd が 1 になるという事実と一致します。 

1 つの数値がはるかに大きく、他のすべての数値でそれを割る場合、大きい約数が最初にほとんどの容量を消費し、アルゴリズムはそれらの数値に正しく優先順位を付け、最大の要素が最初に配置される最適な順序に一致します。
