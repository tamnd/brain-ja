 **評価:** 800
 **タグ:** ブルートフォース、建設的アルゴリズム、貪欲

 ## 解決策
 ## 問題の理解

 Divan は 3 つの制約の下でチョコレート バーを購入したいと考えています。価格範囲 [l, r] 内のバーのみを検討し、合計予算 k を超えることはできません。 n 個のチョコレート バーの価格が与えられており、テスト ケースごとに、これらの制約に違反せずに購入できるバーの最大数を計算する必要があります。 

入力では複数のテスト ケースが提供され、各テスト ケースにはバーの数、許容可能な下限価格と上限価格、Divan の総予算、および一連のチョコレートの価格が含まれます。 各テスト ケースの出力は、Divan が購入できるチョコレートの最大数を表す単一の整数です。 

この制約は、n が最大 100 であり、価格と予算が最大 10^9 になる可能性があることを意味します。 n のサイズが小さいことから、単一のテスト ケースでは、複雑さがおよそ O(n log n) または O(n^2) のアプローチであればどれでも許容できることがわかります。 ただし、テスト ケースの数 t は 100 に達する可能性があるため、単純な O(n^2) アプローチでは最悪の場合、最大 10^6 の演算が必要になる可能性がありますが、1 秒という余裕のある時間制限を考慮すると、これはまだ許容可能です。 さらに重要なのは、価格フィルタリングと予算制約を慎重に処理することです。 

明らかではないエッジケースには、すべてのチョコレート バーが安すぎる、または高すぎる場合、または予算が許容可能な最安のバーよりも少ない場合が含まれます。 たとえば、l = 10、r = 20、k = 5、価格が [12, 15] の場合、Divan にはバーを買う余裕がないため、正解は 0 になります。 不注意な解決策では、予算を確認せずに、許容可能な最も安価なバーを誤って選択する可能性があります。 

別のエッジケースは、複数のバーが同じ価格である場合に発生し、予算を正確に満たしてしまう可能性があります。 たとえば、k = 10、価格 = [5, 5, 5] の場合、Divan はバーを 3 つではなく 2 つだけ購入できます。 コストを慎重に集計することを忘れると、過大計上につながる可能性があります。 

## アプローチ

 ブルートフォースソリューションでは、許容可能なチョコレートバーのすべてのサブセットを列挙し、どのサブセットが予算内に収まるかを確認します。 n = 100 の場合、サブセットは 2^100 となり、これは天文学的に大きすぎます。 明らかに、このアプローチは実行不可能です。 

重要な観察は、価格を超えてどのバーの組み合わせを選択するかは気にしないということです。 バーの数を最大化するには、常に最も安いバーを最初に選択する必要があります。安いバーを購入すると、同じ予算内でより多くのバーを含めることができるためです。 これにより、問題はソートと貪欲な選択タスクに集約されます。バーを価格でフィルターし、残りのバーを昇順でソートし、予算を超えるまでコストを累積して繰り返します。 n ≤ 100 の場合、このアプローチは正しく、効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのサブセット) | O(2^n) | O(n) | 遅すぎる |
 | フィルター + 並べ替え + 貪欲 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケース t の数を読み取ります。 各テスト ケースをループします。 
2. テスト ケースの場合、n、l、r、k、および価格の配列 a を読み取ります。 
3. 配列 a をフィルタリングして、l と r の間の価格のみを保持します。 これにより、Divan が好むチョコレートのみが考慮されるようになります。 
4. フィルタリングされた配列を昇順に並べ替えます。 ソートでは、より安価なバーを最初に検討することが保証され、これにより予算 k 内で購入できるバーの数が最大化されます。 
5. 購入したチョコレートの数のカウンターと残りの予算の変数を初期化します。 並べ替えられた価格を繰り返し処理します。 
6. 各価格 p について、p が残りの予算以下であるかどうかを確認します。 その場合は、予算から p を減算し、カウンターをインクリメントします。 p が残りの予算を超えた場合は、さらにバーを追加すると (すべてより高価になります)、予算を超えるため、反復を停止します。 
7. すべてのバーを処理した後、テスト ケースの答えとしてカウンターを出力します。

機能する理由: すべてのステップで、最大数のバーに対して可能な限り最小限の金額を費やしたという不変条件を維持します。 配列は昇順でソートされているため、残りの予算を超えてバーをスキップすると、それ以上バーを含めることができなくなります。 この貪欲なアプローチにより、予算を超えずに最大数のチョコレートが選択されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, l, r, k = map(int, input().split())
    prices = list(map(int, input().split()))
    
    # Keep only acceptable chocolates
    valid_prices = [p for p in prices if l <= p <= r]
    
    # Sort ascending to prioritize cheaper chocolates
    valid_prices.sort()
    
    count = 0
    remaining_budget = k
    for price in valid_prices:
        if price <= remaining_budget:
            remaining_budget -= price
            count += 1
        else:
            break
    
    print(count)
```コードはすべてのテスト ケースを効率的に読み取ります。 フィルタリングにより、許容できない価格が考慮されなくなり、並べ替えにより、より安価なバーを貪欲に選択できるようになり、反復により予算がなくなるまでチョコレートが蓄積されます。 並べ替えとフィルター処理は簡単ですが、l と r の境界に注意する必要があります。 予算が不足するとすぐに反復を停止する必要があり、これがオフバイワンエラーの一般的な原因です。 

## 実用的な例

 ### サンプル 1

 入力:```
3 1 100 100
50 100 50
```| 変数 | フィルタリング後の値 | ソート後の値 | カウンター進行 |
 | --- | --- | --- | --- |
 | 有効な価格 | [50、100、50] | [50、50、100] | カウント = 0、残り = 100 |
 | ステップ 1 | p = 50 | - | カウント = 1、残り = 50 |
 | ステップ 2 | p = 50 | - | カウント = 2、残り = 0 |
 | ステップ 3 | p = 100 | - | 予算を超えたので中止 |

 出力: 2. これにより、最初に最も安価なバーを貪欲に選択することでカウントが最大化されることが確認されます。 

### サンプル 2

 入力:```
6 3 5 10
1 2 3 4 5 6
```フィルタリングされた valid_prices = [3, 4, 5]、昇順に並べ替えられた = [3, 4, 5]。 反復:

 | ステップ | 価格 | 残り | カウント |
 | --- | --- | --- | --- |
 | 1 | 3 | 10-3=7 | 1 |
 | 2 | 4 | 7-4=3 | 2 |
 | 3 | 5 | 3 < 5、停止 | 2 |

 出力: 2. 次のバーが残りの予算を超えたときに正しく停止することを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t * n log n) | フィルタリングは O(n)、ソートは O(n log n)、反復は O(n) です。 t 個のテスト ケースの場合は、t を掛けます。 |
 | スペース | O(n) | フィルタリングされた有効な価格のリストを保存します。 |

 n ≤ 100 および t ≤ 100 の場合、t*n log n は最大 100 * 100 * log 100 ≈ 66,000 操作であり、1 秒の制限内に十分収まります。
