 ## 解決策
 ## 問題の理解

 1 から 9 までの数字の固定マルチセットから始めます。各数字は 1 回ずつ出現し、連続して書き込まれます。 許可される唯一の操作は、数字を 1 つずつ削除することですが、現在のシーケンスに 2 桁しか残っていない場合は削除できないという制限があります。 任意の数の削除の後、残りの桁を元の順序で取得し、数値として解釈します。 目標は、素数を形成するシーケンスで終わることです。 

ここで重要な構造は、任意の順序で自由に数字を選択しているのではなく、元の順列から削除しているだけであるため、最終的なシーケンスは指定された 9 桁の文字列の部分シーケンスである必要があるということです。 数字はすべて個別であり、9 個しかないため、可能な部分列の総数は次のように制限されます。$2^9 = 512$、必要に応じて徹底的に推論できるほど小さいです。 

ソリューションを形成する主な制約は、テスト ケースごとの小さな固定入力サイズです。 テスト ケースは最大 5000 件ありますが、各ケースは独立しており、非常に小さいです。 これは、9 でわずかに指数関数的であっても、どんなアプローチでも受け入れられることを直ちに示唆しています。 

微妙な制約は、2 桁しか残っていない場合の削除の制限です。 このルールにより、長さ 1 または 2 に縮小してから任意に続行することができなくなりますが、どのサブシーケンスが到達可能になるかは根本的に変わりません。 少なくとも長さ 3 のサブシーケンスには到達可能であり、長さ 2 のサブシーケンスは最後のステップでのみ制限されます。 この文脈では素数は少なくとも 2 桁必要であり、1 桁の素数はすべて 2、3、5、7 のみであるため、短い長さは依然として慎重に扱う必要があります。 

エッジケースは次の場合に発生します。 

1. 素数部分列のみが長さ 1 または 2 です。たとえば、最良の候補が 2 のような 1 桁の素数である場合、間接的に遷移を制限する削除ルールにより長さ 1 で終了することはできません。 
2. 大きな桁を早い段階で削除するという貪欲な選択は、後で唯一の有効な素数部分列を破壊する可能性があります。 
3. 一部の順列には素数を形成する部分列がまったく含まれない場合があり、その場合は -1 を出力する必要があります。 

単純な貪欲な削除の具体的な失敗例は、常に最初の桁を保持するか、常に最大の桁を削除することです。そのような戦略は、サブシーケンス内の素数のグローバルな組み合わせ構造を無視します。 

## アプローチ

 ブルートフォース戦略では、9 桁の文字列のすべての部分列を列挙し、対応する数値を形成し、素数性をチェックします。 各テスト ケースでは、これは最大 512 個のサブシーケンスであり、数値は最大 9 桁であるため、形成された各数値の素数チェックは定数時間です。 5000 回のテスト全体で、これは約 250 万回のチェックに相当しますが、それでも問題ありません。 

ただし、類似した候補の素数を繰り返し再計算するため、ブルート フォースは少し無駄になります。 重要な観察は、検索空間が小さく固定されているため、999,999,999 までのすべての素数を事前計算したり、単純に素数性をその場でチェックしたりできるということです。 

より構造化されたアプローチは、1 ～ 9 の数字のサブセットの順列から形成できるすべての素数のセットを事前計算し、テスト ケースごとに、これらの素数のいずれかがサブシーケンスとして現れるかどうかを確認することです。 しかし、これでもやりすぎです。 

最も単純で最適なアイデアは、9 桁の文字列のすべての部分列を直接生成し、それぞれを数値として解釈し、素数性をテストすることです。 削除制約は、どのサブシーケンスが最終状態として到達可能であるかを制限しません。これは、補数を削除することで数字の任意のサブセットを取得でき、終了しない限りサイズ 2 で停止する必要がないためです。 

したがって、問題は次のようになります。素数を形成する部分列を見つけます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブシーケンス + 素数チェック | O(512・t) | お(1) | 承認済み |
 | 最適化された事前計算 (オプション) | O(512 + t) | お(512) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、9 桁の文字列を読み取り、インデックスのサブセットを選択して形成されたすべてのサブシーケンスを検討します。 これが有効な理由は、削除により任意の数字を削除できるため、すべてのサブシーケンスに到達できるためです。 
2. 1 ～ 511 のサブセット マスクごとに、数字を元の順序で連結して数値を作成します。 先行ゼロを生成するマスクはスキップしますが、ここでは数字が 1 ～ 9 であるため、このようなことは起こりません。 
3. 結果の数字シーケンスを整数に変換します。 
4. 平方根まで試しに割り算して、整数が素数であるかどうかを確認します。 最大値を下回っているため、$10^9$, 31623までチェックすれば十分です。 
5. 素数が見つかった場合は、対応するサブシーケンスを直ちに出力し、そのテスト ケースの処理を停止します。 
6. 素数を生成する部分列がない場合は、-1 を出力します。 

早期に停止できる理由は、有効な素数部分列のみが必要であり、すべてではないからです。 

### なぜ効果があるのか

 削除では順序が保持され、要素のみが削除されるため、到達可能なすべての最終シーケンスは元の文字列のサブシーケンスに正確に対応します。 アルゴリズムはそのようなサブシーケンスをすべて列挙するため、候補を見逃すことはありません。 素数性は候補番号ごとに正確にチェックされるため、正しさは素数性テストの正しさに帰着します。 候補者は全員以下なので$10^9$、決定論的な試行分割で十分かつ正確です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def is_prime(x):
    if x < 2:
        return False
    if x % 2 == 0:
        return x == 2
    i = 3
    while i * i <= x:
        if x % i == 0:
            return False
        i += 2
    return True

def solve_case(s):
    n = len(s)
    digits = list(s)

    for mask in range(1, 1 << n):
        val = 0
        used = False

        for i in range(n):
            if mask & (1 << i):
                val = val * 10 + (ord(digits[i]) - 48)
                used = True

        if used and is_prime(val):
            # reconstruct subsequence
            res = []
            for i in range(n):
                if mask & (1 << i):
                    res.append(digits[i])
            return "".join(res)

    return "-1"

def main():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        print(solve_case(s))

if __name__ == "__main__":
    main()
```このソリューションは、1 から 2 までのすべてのマスクを反復します。$2^9 - 1$、対応する番号を元の順序で構築します。 再構築ステップは、数値シーケンスを出力するために素数が見つかった場合にのみ実行されますが、数値構造は高速素数チェックに使用されます。 

素数性テストは単純な試行除算であり、数値範囲が狭いため十分です。

            return x == 2

 ## 特殊なケース

 重要なエッジ状況は、利用可能な素数が 1 桁のみである場合です。 のような入力の場合`987654321`、アルゴリズムはまだ見つけます`3`これは、長さ 1 のサブシーケンスを含むすべてのサブシーケンスを列挙するためです。 削除ルールは、プロセス中にサイズ 2 で停止することを制限していますが、サブシーケンスの論理モデルの最終結果としてサイズ 1 または 2 を達成することを妨げるものではありません。 

もう 1 つのケースは、次のような素数を形成する部分列がない場合です。`111111111`。 構築されるすべての数値は 1 の繰り返しであり、素数はありません。 列挙はすべてのマスクを使い果たし、正しく -1 を返します。 

より微妙なシナリオは、より長いサブシーケンスが存在するが複合であるのに対し、より短い隠れたサブシーケンスが素数である場合です。 徹底的なマスク検索により、短いサブシーケンスも引き続き考慮されるため、アルゴリズムが貪欲な長い選択に囚われることがなくなります。
