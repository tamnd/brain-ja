 ## 解決策
 ## 問題の理解

 指定された一連のシンボルが空から始まる配列の操作によって生成されたかどうかを確認するように求められます。 操作は次のとおりです: 配列の末尾に整数を追加します ( で示されます)。`+`)、最後の要素 (`-`)、現在の配列がソートされているかどうかを確認します (`0`または`1`）。 あ`1`配列が非降順でソートされたことを意味しますが、`0`そうではなかったという意味です。 入力には Monocarp が書き留めた文字のみが含まれており、実際の整数値を入力に割り当てることが可能かどうかを判断する必要があります。`+`出力のシーケンスが指定された文字列とまったく同じになるような操作。 

制約は、これに効率的にアプローチする方法についてのヒントを与えてくれます。 各シーケンスは最大 200,000 文字であり、すべてのテスト ケースの合計も 200,000 文字に制限されます。 つまり、1 文字あたりの時間が直線的なソリューションはどれも実現可能です。 すべての整数代入を試みる単純なシミュレーション`+`整数が無限にあるため、操作は失敗しますが、正確な数値ではなく、シーケンスが一貫しているかどうかのみを考慮します。 

明らかではないエッジ ケースには、`0`または`1`前置きなしで`+`、空の配列から要素を削除するシーケンス (制約によって禁止されています)、および複数のチェックが行われるシーケンス (`0`または`1`）が連続して出現します。 例えば、`0`配列が空でソートを解除できないため、単独では不可能です。 同様に、`+1-0`可能ですが、`+0-1`アレイの状態によっては不可能な場合があります。 

## アプローチ

 ブルートフォースアプローチでは、すべてのオブジェクトに整数値を割り当てようとします。`+`すべてがそうなるように`0`そして`1`出力は満足です。 これには、考えられるすべてのシーケンスをバックトラッキングまたはテストすることが含まれる可能性がありますが、選択肢の数に制限がないため、これは現実的ではありません。 

重要な洞察は、実際の値は必要なく、配列に対する制約のみが必要であるということです。 配列内の各位置に取り得る最小値と最大値を維持すると、シーケンスを読み取るときに制約を前方に伝播できます。 具体的には、`+`この操作では、新しい要素は「非降順チェックの以前の最大値と少なくとも同じ大きさ」であると考えることができます。`-`最後の要素を削除し、可能な最小値/最大値を更新するだけです。 のために`1`最後に追加された要素は、少なくとも前の要素と同じ大きさでなければなりません。`0`チェックするには、配列がソートされていない可能性があることを確認する必要があります。 これにより、具体的な数値の代わりに値の範囲のスタックを使用して配列をシミュレートできるようになります。 

ブルートフォース手法は指数関数的に複雑になるため、実行不可能です。 最適なアプローチでは、配列を可能な値の範囲のスタックとしてシミュレートし、最小/最大制約を伝播します。これは文字ごとに線形時間で機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(∞) | O(n) | 遅すぎる |
 | 制約の伝播 / スタック シミュレーション | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 空のスタックを初期化します。 スタック内の各要素はタプルを格納します`(min_possible, max_possible)`対応する要素が取り得る値の範囲を表します。 
2. 文字列を反復処理します。`s`文字ごとに。 
3. とき`+`が発生した場合は、新しいタプルをプッシュします`(1, INF)`これは、任意の整数値を選択できることを表します。 ここ、`INF`は十分に大きい数です。 
4.`-`が発生した場合は、スタックから最後の要素をポップします。 
5. とき`1`が発生した場合は、スタックが非減少配列を表現できるかどうかを確認してください。 これを行うには、スタックを下から上に繰り返し、各要素の最大値が前の要素の最小値と少なくとも同じ大きさになるようにします。 チェックが失敗した場合は、シーケンスに一貫性がないため、次のように出力できます。`NO`。 
6. とき`0`が発生した場合は、配列をソート解除できるかどうかを確認してください。 これは、次の要素の最小値が前の要素の最大値よりも小さいような連続する要素のペアが存在するかどうかをチェックすることによって行われます。 そうでない場合は、シーケンスに一貫性がありません。 
7. 矛盾なく文字列全体の処理が完了したら、出力します。`YES`。 

機能する理由: 維持される不変条件は、スタック内の各要素が、以前のすべての操作と一貫して取り得る整数の範囲を格納することです。 最小/最大制約を伝播するだけで、これまでのシーケンスを満たす整数の割り当てが存在するかどうかを各チェックで判断できます。 If any check fails, no assignment can satisfy the sequence.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        s = input().strip()
        stack = []
        possible = True

        for c in s:
            if c == '+':
                # push an unrestricted new element
                stack.append([1, int(1e9)])
            elif c == '-':
                if not stack:
                    possible = False
                    break
                stack.pop()
            elif c == '1':
                # check if array can be sorted
                if len(stack) < 2:
                    continue
                ok = True
                for i in range(1, len(stack)):
                    if stack[i][1] < stack[i-1][0]:
                        ok = False
                        break
                if not ok:
                    possible = False
                    break
            elif c == '0':
                # check if array can be unsorted
                if len(stack) < 2:
                    possible = False
                    break
                ok = False
                for i in range(1, len(stack)):
                    if stack[i][0] < stack[i-1][1]:
                        ok = True
                        break
                if not ok:
                    possible = False
                    break

        print("YES" if possible else "NO")

if __name__ == "__main__":
    solve()
```このコードはスタックを使用して配列要素の可能な範囲を維持します。 それぞれ`+`新しい無制限の要素をプッシュします。`-`最後の要素をポップしてチェックします`0`そして`1`最小/最大制約を使用して一貫性を検証します。 操作は文字列の長さに対して線形であるため、入力制約に対して十分効率的です。
