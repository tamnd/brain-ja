 ## 解決策
 ## 問題の理解

 この問題では、複数のプレイヤーとディーラーによるカード ゲームがあります。 各カードは 4 つのスートのいずれかに属します。 ディーラーはすでにカードの一部をプレイヤーに配っており、一部のカードはデッキに残っています。 残りのカードの数は割り切れるので、カードを配布した後、各プレイヤーは最終的に同じ合計カード数になります。 その後、各プレイヤーは自分が最も多く持っているスーツを選択し、残りを捨てます。 勝者は、選択したスートで最も多くのカードを持っているプレイヤーであり、そのスコアは、自分のカードの枚数と他のプレイヤーの最も多い枚数の差になります。 同点の場合はポイントがゼロになります。 

入力は、各プレーヤーがすでに保持している各スートのカードの数と、デッキに残っている各スートの数を記述します。 各プレーヤーの出力は、ディーラーが残りのカードを自分に有利になるように最適に分配した場合に達成できる最大ポイント数になります。 

制約は重要です。プレイヤーは最大 50,000 人まで参加でき、各プレイヤーはスーツの最大 10^6 枚のカードを持ち、残りのカードの総数も同様に多くなります。 カードを割り当てる方法の数は、プレイヤーとカードの数に応じて組み合わせで増加するため、すべての分布を列挙する単純なアプローチはすぐに除外されます。 それぞれの分布を明示的に試すのではなく、分布について効率的に推論する方法が必要です。 

複数のプレイヤーがほぼ同じ配分を持っている場合、または残りのカードにより複数のプレイヤーが最大スート数で同点になる可能性がある場合、微妙なエッジケースが発生します。 たとえば、2 人のプレーヤーがカウントを持っている場合、`[2, 1, 0, 0]`そして`[1, 2, 0, 0]`スート 1 のカードが 2 枚残っている場合、最初のプレイヤーに両方を与えるだけでスコアが最大になりますが、それぞれに 1 枚ずつ与えた場合、最大数は同点となり、スコアは 0 になります。 どのようなソリューションでも、これらのタイブレーク ルールを注意深く考慮する必要があります。 

## アプローチ

 ブルートフォースソリューションでは、プレイヤー間で残りのカードを配布するあらゆる方法を列挙しようとします。 候補者の分布ごとに、各プレイヤーの結果の最大スート数を計算し、勝者を決定し、スコアを計算します。 これは原理的には正しいですが、現実的ではありません。`n`プレイヤーとスーツごとに最大 10^6 のカードを使用できるため、配布数は組み合わせにより爆発的に増加します。 スートごとの分布だけを考慮しても、整数パーティションの数は処理するには多すぎます。 

効率的な解決策を可能にする重要な観察は、プレーヤーごとのカードの総数が固定されると、各プレーヤーは最大枚数のスートのみを選択することになるということです。 したがって、問題は、各プレイヤーのカードの合計が等しいという制約の下で、あるプレイヤーのトップ スートの数を最大化し、他のプレイヤーのトップ スートの数を最小化するというゲームに帰着します。 単一のプレイヤーの場合、彼らに最適なカードをできるだけ多く与えることが想像できます。 次に、残りのカードをこのプレイヤーを超えられない方法で他の人に配布できるかどうかを確認する必要があります。 この推論は、プレイヤーが選択したスートで持つことができるカードの数を二分探索することに相当します。 各候補者について、貪欲な割り当てで実現可能性をチェックします。つまり、目標を追い越すことなく、自分のトップスーツを最大化するのに十分な量を他のプレーヤーに与えます。 カードの総数と制約は多いものの、プレイヤーの数は中程度であるため、この二分探索と貪欲な実現可能性チェックは効率的に機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | スーツごとに O(選択(n+k-1,n-1)) | O(n) | 遅すぎる |
 | 二分探索 + 貪欲 | プレーヤーあたり O(n log T)、T ~ 最大カード数 | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力の読み取り`n`プレイヤーとその初期カード数`a[i][j]`スートごとの枚数と残りのデッキ数`b[j]`。 
2. 配った後に各プレイヤーが持つ必要があるカードの合計数を計算します。`total_per_player = (sum of all cards) / n`。 
3. プレイヤーごとに`i`、得点できるポイント数について二分探索を実行します。 検索範囲を`[0, max_possible]`、 どこ`max_possible`最大でも、現在の最大スートとそのスートの残りのカードすべての合計です。 
4. 各候補者について`score`二分探索で実現可能性をチェックします。 

ａ． ターゲットプレイヤーの最大スート数を次のように計算します。`current_max_suit[i] + extra_given`。 

b. この枚数と同数かそれを超える可能性があるために、他のプレイヤーが何枚のカードを必要とするかを計算します。 

c. 残りのデッキを貪欲に割り当てて、プレイヤーごとの合計カードを固定したまま、他のプレイヤーがターゲットを追い越すのを防ぐ方法でカードを与えることが可能かどうかを判断します。 
5. 可能であれば、二分探索をより高い値に移動します。 それ以外の場合は、上限を下げます。 
6. 二分探索が収束したら、プレーヤーの実現可能な最高スコアを記録します。 
7. すべてのプレーヤーに対して繰り返し、結果を出力します。 

正確性を保証する不変条件は、二分探索がターゲット プレイヤーの達成可能な最大トップ スーツ カウントをすべて探索すること、および貪欲な実現可能性チェックにより、割り当てがカード総数の制約に違反したり、他のプレイヤーがターゲットを超えることを許可したりしないことを保証することです。 明示的なカード配分ではなく、枚数の観点から推論することで、組み合わせの爆発を回避します。

input = sys.stdin.readline

n = int(input())
a = [list(map(int, input().split())) for _ in range(n)]
b = list(map(int, input().split()))

total_cards = sum(sum(row) for row in a) + sum(b)
cards_per_player = total_cards // n

res = []

for idx in range(n):
    left, right = 0, sum(b) + max(a[idx])
    best = 0
    while left <= right:
        mid = (left + right) // 2
        needed = 0
        for j in range(n):

            max_suit_j = max(a[j])
            needed += max(0, mid - max_suit_j)

            right = mid - 1

print(' '.join(map(str, res)))

## 実用的な例

 **サンプル 1:**

 入力:

 | プレーヤー | スーツ 1 | スーツ2 | スーツ3 | スーツ4 |

 | 1 | 3 | 1 | 1 | 1 |
 | 2 | 1 | 1 | 1 | 1 |
 | 残りデッキ: 2 2 0 0 | | | | |

 プレーヤー 1 の二分探索では、達成可能なトップ スーツの数が調査されます。 スート 1 の追加の 2 枚のカードを与えると 5 が得られます。プレイヤー 2 の最大値は 1 で、スート 2 の残り 2 枚のカードが与えられると合計は 3 になります。スコア = 5 - 4 = 1。プレイヤー 2 はプレイヤー 1 の最大値を超えることはできないため、出力は次のようになります。`1 0`。
