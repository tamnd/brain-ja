 ## 解決策
 ## 問題の理解

 整数の配列が与えられます。 1 回の操作で 2 つの異なる要素を選択できます。 それらの合計が偶数の場合、両方を削除し、それらの合計を配列に追加し直すため、配列サイズはちょうど 1 だけ減少します。 

タスクは、任意の選択をシミュレートすることではなく、最大で実行した後に最終的に得られる要素の最小数を決定することです。$k$そのような操作。 

重要なのは、すべての操作で 2 つの要素が 1 つにマージされることです。マージは、選択された両方の要素が同じパリティを持つ場合にのみ可能です。その場合のみ、それらの合計が偶数になるためです。 したがって、各演算は基本的に、2 つの偶数または 2 つの奇数を組み合わせて、パリティが同じグループに一致する 1 つの数値にします。 

入力サイズが小さいため、合計$n$すべてのテストケースにわたって、$10^3$、 そして$k$までも$10^3$。 これにより、操作ごとまたはペアごとのシミュレーションがボトルネックとなる高価なものは除外されますが、より重要なのは、答えがシーケンスの構築ではなくカウント構造に依存することを示唆していることです。 

素朴な解釈では、マージを繰り返しシミュレートしようとしますが、そうするとすぐに曖昧さが生じます。つまり、最終的なサイズを最小化するにはどのペアを選択する必要があるのか​​ということです。 たとえば、大きな値または小さな値をマージしても、将来の可能性には影響せず、パリティ数のみが問題となります。 したがって、パリティ構造ではなく実際の値を追跡するアプローチは、不必要な作業を行う危険があります。 

エッジケースは次の場合に発生します。 

たとえば、すべての数値に交互のパリティ カウントがある場合、$[1,2,3,4]$の場合、マージはパリティ グループ内でのみ行われるため、操作が制限されます。 パリティ グループを追跡せずに 2 つの要素を貪欲にペアリングすると、誤って無効なマージが試行される可能性があります。 

すべての数値がすでに 1 つのパリティである場合、たとえばすべてが偶数である場合、要素が 1 つだけ残るか使い果たされるまで、すべての操作で配列サイズが 1 つだけ減少します。$k$。 単純なシミュレーションでは、これがさらに複雑になる可能性があります。 

奇数が 1 つだけ存在する場合、それはマージに参加できないため、常に保持され、最適な戦略では、それを含めようとする無駄な操作を回避する必要があります。 

## アプローチ

 ブルートフォースのアイデアは、操作をシミュレートすることです。すべてのペアをスキャンし、有効なペアを選択し、それらをマージし、最大で繰り返します。$k$回。 これは、すべての有効な移動が考慮されるため正しいですが、各操作ですべてのペアをチェックする必要があり、マージのたびに配列が 1 要素だけ縮小するため、非効率的です。 最悪の場合、これはおおよそ次のような事態につながります。$O(k \cdot n^2)$、次の場合には大きすぎます。$n$そして$k$両方です$10^3$。 

重要な観察は、値自体はパリティを除いて無関係であるということです。 すべての操作では、予測可能な方法でパリティ構造が保持されます。2 つの偶数を結合すると偶数が得られ、2 つの奇数を結合すると偶数が得られます。ただし、重要なのは、両方の要素が 1 つに消費されるということです。 したがって、本当に重要なのは、各パリティ クラスの要素がいくつ存在するかということです。 

偶数と奇数を数えるだけで済みます。 各操作は同じパリティ グループの 2 つの要素を消費し、解釈に応じてそのグループの 1 つの要素または偶数グループを生成します。ただし、カウントを最小限に抑えるために重要な唯一の事実は、各操作で合計サイズがちょうど 1 だけ減少するということです。 

ただし、すべての操作が常に可能であるわけではありません。 何らかのパリティ グループの要素が少なくとも 2 つある場合にのみ、移動を実行できます。 したがって、演算の最大数は、偶数と奇数の内部で個別に形成できるペアの数によって制限されます。 

したがって、答えは次のようになります。 

内で実際に実行できる操作の数を計算します。$k$、それをから引きます$n$。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション |$O(k \cdot n^2)$|$O(n)$| 遅すぎる |
 | パリティカウント |$O(n)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 問題を、実行できる有効なマージの数を数えることに落とし込みます。 

### ステップ

 1. 配列内に偶数と奇数がいくつ存在するかを数えます。 

これで十分である理由は、パリティのみがマージが有効かどうかを決定するためです。 
2. 偶数間で形成できるペアの数を計算します。$\lfloor \frac{even}{2} \rfloor$。 

このような各ペアは 1 回だけマージできます。 
3. オッズ間で形成できるペアの数を計算します。$\lfloor \frac{odd}{2} \rfloor$。 
4. これらを合計して、制限なしで可能な操作の合計数を取得します。$maxOps = \lfloor even/2 \rfloor + \lfloor odd/2 \rfloor$。 
5. せいぜい許可されているので$k$操作、実際に実行される操作の数は$ops = \min(k, maxOps)$。 
6. 各操作により配列サイズが 1 要素だけ減少するため、最終的なサイズは次のようになります。$n - ops$。 

### なぜ効果があるのか

 重要な不変条件は、すべての有効な操作が同じパリティ グループの 2 つの要素を正確に消費し、それらを 1 つの要素に置き換えることであり、そのグループ内の数を減らすこと以上に将来のマージの実現可能性構造を変更しないことです。 これは、唯一の進化する状態は各パリティ クラスの要素の数であることを意味します。 パリティ グループ内のペアの選択は独立しているため、有効な移動のシーケンスは、可能な操作の数を変更することなく再配置できます。 したがって、操作の数を最大化することは、各パリティ クラスで可能な限り多くの素のペアを制限まで貪欲に形成することと同じです。$k$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        even = 0
        odd = 0
        
        for x in a:
            if x % 2 == 0:
                even += 1
            else:
                odd += 1
        
        max_ops = (even // 2) + (odd // 2)
        ops = min(k, max_ops)
        
        print(n - ops)

if __name__ == "__main__":
    solve()
```実装は推論に直接続きます。 まずパリティによって要素を分離し、有効な操作に関連するすべての構造をキャプチャします。 次に、各パリティ グループ内の独立したマージの最大数を計算します。 最後にキャップを付けます$k$許可された操作数を超えることはできないためです。 

微妙な点は、マージ後に配列を決してシミュレートしないことです。 これは、すべてのマージによって合計カウントが 1 つだけ減り、整数除算によってすでにカウントされている値を超えて将来のペアリングの可能性が増加するようなパリティ カウントの変更は行われないため、安全です。 

## 実用的な例

 ### 例 1

 入力:```
n = 5, k = 2
a = [1, 2, 3, 4, 5]
```パリティ数を追跡します。 

| ステップ | 偶数 | 奇数 | 最大運用数 | 残り k | アクション |
 | --- | --- | --- | --- | --- | --- |
 | 開始 | 2 | 3 | 1 + 1 = 2 | 2 | ペアを計算する |
 | 操作を選択した後 | 2 | 3 | 2 | 0 | min(k, maxOps) |

 最大で 2 つの操作を実行できます。 最終的なサイズは$5 - 2 = 3$。 

これは、アレイが小さい場合でも、パリティ グループ内のペアリングが制限要因であることを示しています。

 入力:```

a = [2, 4, 6, 1, 3, 5]
```| ステップ | 偶数 | 奇数 | 最大運用数 | 残り k | アクション |

 | 開始 | 3 | 3 | 1 + 1 = 2 | 10 | ペアを計算する |
 | 操作を選択した後 | 3 | 3 | 2 | 8 | k は拘束力を持たない |

 実行できる操作は 2 つだけですが、$k$大きいです。 最終的なサイズは$6 - 2 = 4$。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n)$テストケースごと | パリティをカウントするために配列を 1 回スキャンします。 
| スペース |$O(1)$| カウンタのみが保存される |

 制約により、最大で次のことが許可されます。$10^3$すべてのテスト ケースにわたる要素の合計なので、テスト ケースごとに 1 回のリニア スキャンで制限時間内に簡単に十分に高速になります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        even = sum(1 for x in a if x % 2 == 0)
        odd = n - even
        ops = min(k, (even // 2) + (odd // 2))
        out.append(str(n - ops))
    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、どちらかのパリティの要素が 2 つ未満である場合です。 たとえば、次のように入力します。```
n = 3, a = [2, 1, 3]
```ここでは、偶数 = 1 および奇数 = 2 です。奇数のペアは 1 つだけ形成できるため、最大 1 つの演算が可能です。 アルゴリズムは計算します$\lfloor odd/2 \rfloor = 1$、最終的な答えを与える$3 - 1 = 2$、これは唯一の有効なマージと一致します。 

もう一つのケースは次のような場合です。$k$非常に大きいです:```
n = 4, k = 100, a = [1, 3, 5, 7]
```偶数は 0、奇数は 4 なので、maxOps = 2 となります。$k$多くの操作が可能ですが、利用可能なペアを超えることはできないため、最終的なサイズは次のようになります。$4 - 2 = 2$。 アルゴリズムは、次を使用して操作を正しくキャップします。$\min(k, maxOps)$、引き算のしすぎを防ぎます。 

最後の微妙なケースは、パリティが非常に不均衡な場合です。```
n = 5, a = [2, 4, 6, 8, 1]
```偶数 = 4、奇数 = 1。両方とも偶数内で 2 つの演算のみが可能です。 奇妙な要素は全体を通してそのまま残ります。 The result is$5 - 2 = 3$、分離された要素が特別な処理を必要とせずに自然に存続することを示しています。
