 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、正確に次の値を持つ 2 番目のバイナリ文字列を使用してそれを変更できます。$m$もの。 この 2 番目の文字列の 1 がある位置ごとに、元の文字列の対応するビットが反転されます。 すべての反転の後、新しい文字列を取得します$T$。 あらゆる人にとって$m$、隣接するペアの数を最大化する方法で反転位置を選択したいと考えています。$T$に等しい$11$。 

言い換えれば、正確に切り替えることができます$m$元の文字列の位置を切り替えた後、インデックスの数を最大化したいと考えています$i$両方とも$T_i$そして$T_{i+1}$は 1 です。考えられるすべての条件に対してこの最適値を計算する必要があります。$m$0から$n$。 

制約は非常に厳しいです。$n$すべてのテストケース全体で最大でも$10^6$。 これにより、テスト ケースごとに二次関数が即座に除外されます。 平$O(n \log n)$テストごとのソリューションは境界線にあるため、ソリューションはテストごとに本質的に線形である必要があり、場合によってはグローバルな並べ替えやプレフィックス処理が必要になります。 

単純なアプローチでは、次のすべてのサブセットを試します。$m$反転する位置を指定し、結果の文字列を再計算して、有効な隣接ペアをカウントします。 サブセットの数が次のとおりであるため、それは明らかに不可能です。$\binom{n}{m}$、単一の構成のコストを評価する場合でも$O(n)$、指数関数的な動作につながります。 

もう少し良いアイデアですが、まだ不可能なアイデアは、各ポジションを独立して扱い、それを反転することに「利点」を割り当てることです。 これは、1 つの位置を反転すると隣接する位置の影響が変化するため、効果が独立していないため、失敗します。 

2 つの隣接する位置が両方とも反転の候補である場合、微妙なエッジ ケースが発生します。 たとえば、次のようなセグメントでは、`101`隣接構造が非線形に変化するため、中間ビットのみを反転する場合は、両方のエンドポイントを反転する場合とは動作が大きく異なります。 この依存関係が問題の核心です。 

## アプローチ

 重要な変化は、個々のフリップの観点から考えるのをやめ、代わりに、最終的なポジションのセットを構築する観点から考えることです。$T_i = 1$。 

各ポジション$i$元の文字列では、最終的な文字列では 2 つの状態が考えられます。 

もし$S_i = 1$, 反転を費やさずに 1 のままにすることができます。 

もし$S_i = 0$、コスト1になります。 

したがって、すべてのポジションには最終文字列で 1 になるためのコストがあり、次の予算の下で 1 になるポジションのサブセットを選択しています。$m$。 

ここでの目的は、セットを選択することです。$A$1 に設定する位置の数を、内部の隣接するペアの数を最大化します。$A$、コストの制約を受けます。 

これはまさに、選択された各頂点が隣接する頂点も選択されたエッジに寄与するパス グラフです。 値は、によって引き起こされるエッジの数です。$A$。 

グローバル サブセットについて推論する代わりに、ローカル構造を観察します。隣接性を得る唯一の方法は、隣接する選択された位置を接続することです。 構造を改善できる唯一の場所は、元の文字列内の既存の 1 ブロック間の境界付近です。 

元の文字列では、すべての位置に$S_i = 1$すでに「自由な」選択候補者となっています。 これらはゼロで区切られた自然なブロックを形成します。 重要な点は、高価な要素はゼロだけであり、各ゼロは隣接する 1 ブロック間のオプションのコネクタと見なすことができるということです。 

各ゼロには、明確に定義されたローカル効果があります。 

選択されていない場合は、左右のブロック間の隣接性が解除されます。 選択すると、それらが接続され、新しい隣接するペアが作成されます。 ゼロを選択することによるゲインは、元の文字列内のそのすぐ隣のものにのみ依存するため、すべての決定が独立します。 

各ゼロは、次の 3 つのケースのいずれかに当てはまります。 

両方の隣接ペアが 1 の場合、これを選択すると 2 つの新しい隣接ペアが作成されます。 

ちょうど 1 つの隣接ペアが 1 の場合、それを選択すると 1 つの新しい隣接ペアが作成されます。 

どちらの近傍も 1 でない場合、それを選択しても何の役にも立たず、決して最適ではありません。 

これにより、問題は次のものを選択するだけになります。$m$ゼロは最もゲインが高くなりますが、すべての 1 は常に無料で使用されます。 ゲインが独立したら、それらを並べ替えることで最適な戦略が得られます。

 ## アルゴリズムのチュートリアル

 1. 文字列をスキャンし、初期ベースラインを計算します。常にすべての値を維持していると仮定します。`1`最終セットの元の文字列から$A$。 これにはコストはかからず、連続するブロックの元の各ブロック内の隣接関係がすでに確立されています。 
2. 該当するすべての位置を特定します。$S_i = 0$。 このような各ポジションは潜在的な反転候補であり、それを選択するには 1 単位の予算がかかります。 
3. 位置の各ゼロについて$i$、そのローカルゲインを計算します。 

元の文字列で両方の隣接値が 1 の場合、ゲインは 2 になります。 

ちょうど 1 つの近傍が 1 の場合、そのゲインは 1 になります。 

それ以外の場合、ゲインは 0 です。 

最初はオリジナルのものだけがアクティブであるため、これは機能します$A$したがって、ゼロの寄与は、既存のアクティブなエンドポイントに接続しているかどうかによってのみ決まります。 
4. すべてのプラスの利益をリストに収集します。 ゲイン 0 のゼロは決して役に立たないため、無視できます。 
5. ゲインを降順に並べ替えます。 この順序により、どのような予算でも確実に$m$、最良の選択は、$m$利用可能な最大の改善。 
6. ソートされたゲインに対してプレフィックス合計配列を構築します。 それぞれの答えは$m$頂点の合計です$m$元の連続したものからのベースライン隣接性を加えたものを獲得します。 

### なぜ効果があるのか

 重要な不変条件は、それぞれの有益なゼロが独立して目的に貢献するということです。 ゼロの選択は、そのすぐ隣の隣接関係にのみ影響します。また、それらの近隣は両方とも固定のものであるか、他のゼロ選択の影響を受けないため、2 つのゼロの決定が限界利得の順序を変更する形で干渉することはありません。 これにより、問題は標準的な「テイクトップ」に変わります。$m$「独立した報酬」の最適化では、ゲインを減らすことによる貪欲な選択が最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        s = input().strip()

        # baseline: adjacency inside original 1-blocks
        base = 0
        for i in range(n - 1):
            if s[i] == '1' and s[i + 1] == '1':
                base += 1

        gains = []

        for i in range(n):
            if s[i] == '0':
                left = 1 if i > 0 and s[i - 1] == '1' else 0
                right = 1 if i < n - 1 and s[i + 1] == '1' else 0
                gain = left + right
                if gain > 0:
                    gains.append(gain)

        gains.sort(reverse=True)

        pref = [0]
        for g in gains:
            pref.append(pref[-1] + g)

        # output answers for all m
        res = []
        for m in range(n + 1):
            if m <= len(gains):
                res.append(str(base + pref[m]))
            else:
                res.append(str(base + pref[-1]))

        print(" ".join(res))

if __name__ == "__main__":
    solve()
```実装では、問題を固定ベースラインと独立した改善のリストに分離します。 ベースラインは元の隣接関係の間にすでに存在する隣接関係をカウントしますが、ゲイン リストはゼロを反転することで達成可能な改善のみをキャプチャします。 

ゲインを並べ替えることで、すべてのプレフィックスがフリップ バジェットの最適な割り当てに対応することが保証されます。 プレフィックス配列により、すべてに答えることができます$m$並べ替え後の線形時間の値。 

微妙な点は扱い方$m$有効なゼロの数より大きい。 その場合、追加のフリップはゼロゲイン演算に対応するため、答えは増加しません。

 ## 特殊なケース

 完全にゼロの文字列は最もデリケートなシナリオです。 すべての位置には寄与する近傍がないため、すべてのゲインはゼロになります。 アルゴリズムはゼロ ゲイン リストを正しく生成し、すべての答えはゼロのままです。$m$、孤立したビットを反転しても隣接する 11 のペアが決して作成されないためです。
