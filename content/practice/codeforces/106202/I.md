 ## 解決策
 ## 問題の理解

 長さ n の固定乗算器の配列が与えられます。各位置は、最大 n ビットの 2 進数のビット位置に対応します。 2ⁿ 未満のすべての非負の整数 x はインデックスのサブセットを表します。x の i 番目のビットによって、そのサブセットにインデックス i を含めるかどうかが決まります。 

選択した数値 x に対して、x の i 番目のビットが設定されるようにすべての a[i] を乗算して値 f(x) を計算します。 ビットが 0 の場合、その位置は何も貢献しません。つまり、1 を乗算します。したがって、すべての x は配列 a の部分集合積に対応します。 

このタスクは q 回繰り返されます。 各クエリは範囲 [l, r] を与え、その範囲内のすべての整数 x にわたる f(x) の合計を計算する必要があります。ここで、x は正確に n ビットを使用して解釈されます。 結果は 998244353 を法として取得されます。 

制約はソリューションを大きく左右します。 n が 60 になる可能性があるため、x の範囲は最大 2⁶⁰ であり、クエリ間隔にわたる直接の反復は不可能です。 単一間隔のスキャンでも、最悪の場合は指数関数的になります。 クエリの数は 200000 に達するため、どのソリューションでも各クエリを n 時間でほぼ対数または線形に処理する必要があります。 

素朴な試みでは、[l, r] 内のすべての x に対して f(x) を評価し、x ごとに最大 60 個の値を乗算します。 最悪の場合、サイズ 2⁶⁰ の単一クエリであっても、これは完全に不可能です。 もう 1 つの間違った単純化は、区間をビットごとに独立したものとして扱おうとすることですが、区間条件によってビット間の独立性が損なわれるため、サブセットの列挙を直接因数分解することができません。 

l が 0 の場合、微妙なエッジ ケースが発生します。その場合、空の積は 1 であるため、値 1 に寄与する空のサブセット x = 0 に対応するゼロから始まるプレフィックスが必要です。この基本寄与を忘れた解は、プレフィックスの計算ごとに 1 ずつずれることになります。 

## アプローチ

 主要な問題は、f(x) がビット単位で乗算されるのに対し、クエリ制限はバイナリ順序に基づいた数値的なものであることです。 これは、x のバイナリ表現に対する数値動的プログラミング構造を示唆しています。 

ブルート フォースのアプローチは簡単です。[l, r] の各 x について、すべてのビットをスキャンし、対応する a[i] を乗算することによって f(x) を計算します。 これには x あたり O(n) のコストがかかるため、クエリあたり O(n · (r - l + 1)) になります。 r - l が巨大な最悪の場合、これは n ビットにわたって指数関数的となり、通過できなくなります。 

重要な観察は、任意の間隔を直接処理する代わりに、問題をプレフィックスの合計に変換できることです。 すべての y ≤ x について F(x) = f(y) の合計を計算できる場合、各クエリは F(r) - F(l - 1) になります。 これにより、問題は [0, x] の範囲にわたる 2 進数の DP に答えるというものに縮小されます。 

これで構造がきれいになりました。 各数値 x は長さ n のバイナリ文字列で、各ビットで 0 を配置するか 1 を配置するかを決定します。1 を配置する場合は、a[i] を掛けます。 y ≤ x という制約により、古典的な数字 DP とまったく同じようにタイト/ルーズな状態が導入されます。 重要な点は、接頭辞の状態を修正すると接尾辞の寄与が独立し、部分問題の結果を再利用できることです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 各クエリ範囲に対するブルート フォース | O(q · n · 2ⁿ) 最悪の場合 | お(1) | 遅すぎる |
 | ビット上のプレフィックス数字 DP | O(q・n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 プレフィックス関数 F(x) を計算し、2 つのプレフィックス結果の差として各クエリに答えます。

1. 最上位ビットから最下位ビットまで正確に n ビットを使用して、x をバイナリ表現に変換します。 この表現により、どのインデックスが各サブセットに含まれるかが決まります。 
2. 動的プログラミング状態 dp[pos][tight] を定義します。ここで、pos は処理中の現在のビット インデックスであり、tight は、これまでに構築したプレフィックスが x のプレフィックスと正確に等しいかどうかを示します。 この状態は、制約 y ≤ x と一致するすべての有効なサフィックスの選択をキャプチャします。 
3. ビットが残っていない pos = n で基本ケースを初期化します。 この場合、唯一の有効な継続は空の選択範囲であり、その積は 1 です。つまり、 dp[n][0] = dp[n][1] = 1 となります。 
4. 位置 n - 1 から 0 までビットを処理します。各位置で、ビット 0 を配置するかビット 1 を配置するかを検討します。0 を配置すると乗算係数 1 が寄与します。1 を配置すると係数 a[pos] が寄与します。 
5. ルーズ状態 (タイト = 0) にある場合は、0 または 1 を自由に選択できます。すでに厳密に x を下回っているため、どちらの選択もルーズ状態のままです。 これにより、漸化式 dp[pos][0] = dp[pos + 1][0] · (1 + a[pos]) が得られます。 
6. タイトな状態にある場合、許可される遷移は x の現在のビットに依存します。 x[pos] = 1 の場合、0 を配置して緩めるか、1 を配置して a[pos] を乗算しながらタイトなままにするかのどちらかです。 x[pos] = 0 の場合、強制的に 0 を配置してルーズ状態に移行します。 これにより、x[pos] = 0 の場合は dp[pos][1] = dp[pos + 1][0]、x[pos] = 1 の場合は dp[pos][1] = dp[pos + 1][0] + a[pos] · dp[pos + 1][1] が得られます。 
7. dp[0][1] を埋めた後、F(x) を取得します。 各クエリ [l, r] は F(r) - F(l - 1) として応答され、l = 0 の場合は F(-1) = 0 として個別に処理されます。 

正確さは、y ≤ x のすべての数値が DP 状態を通るパスによって一意に表現され、x によって制約されるかどうかが厳密に制御されるという事実に基づいています。 各位置での乗算の寄与は、その位置での決定と既に計算されたサフィックスの合計にのみ依存するため、部分問題が誤って重複することはありません。 これにより、各サブセットが正しい製品重量で正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def calc(x, a, n):
    if x < 0:
        return 0

    bits = [0] * n
    for i in range(n):
        bits[n - 1 - i] = (x >> i) & 1

    dp0 = [0] * (n + 1)
    dp1 = [0] * (n + 1)

    dp0[n] = 1
    dp1[n] = 1

    for pos in range(n - 1, -1, -1):
        dp0[pos] = dp0[pos + 1] * (1 + a[pos]) % MOD

        if bits[pos] == 1:
            dp1[pos] = (dp0[pos + 1] + a[pos] * dp1[pos + 1]) % MOD
        else:
            dp1[pos] = dp0[pos + 1]

    return dp1[0]

def main():
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())

    out = []
    for _ in range(q):
        l, r = map(int, input().split())
        ans = (calc(r, a, n) - calc(l - 1, a, n)) % MOD
        out.append(str(ans))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装は DP を直接ミラーリングします。 ビット抽出ステップでは、インデックス i が常に同じ乗数 a[i] に対応するように、各整数を長さ n のバイナリ ベクトルと位置合わせします。 2 つの配列 dp0 と dp1 はそれぞれルーズ状態とタイト状態を表し、上位ビットから下位ビットへの遷移順序により、サフィックス値がすでに計算されていることを保証します。 

l = 0 の場合、l - 1 は -1 になるので注意が必要です。 この関数は、プレフィックス減算の一貫性を保つために、負の x に対して明示的に 0 を返します。 

## 実用的な例

 n = 3 および a = [2, 3, 5] の小さな例を考えてみましょう。 0 から 7 までの各数値は、これらの値のサブセットに対応します。 

x = 5 (バイナリ 101) の場合、f(5) = a[0] * a[2] = 2 * 5 = 10。 

F(5) のようなプレフィックスを計算するには、0 から 5 までのすべての数値を考慮し、それらのサブセット積を累積します。 DP は、各ビットを段階的に決定することでこの合計を構築します。 

2 番目の例は、x = 3 (バイナリ 011) です。 ここで、最上位の DP は、厳密さに応じて最上位ビットを 0 または 1 に制限し、最大 3 までの有効な数値のみがカウントされるようにします。 寄与は、プレフィックスがすでに小さいかまだ等しい場合に分割され、遷移では残りの選択肢の積が正しく集計されます。 

これらの例は、各数値がそのバイナリ表現に従って 1 回だけカウントされること、および乗法寄与が各パスに沿って独立して蓄積されることを確認します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(q・n) | 各クエリは、状態ごとに一定の遷移を使用して n ビットにわたる DP を実行します。 
| スペース | O(n) | サイズ n の 2 つの DP 配列のみが維持されます。 

n ≤ 60 および q ≤ 200000 の場合、ソリューションは約 1,200 万回の DP 遷移を実行しますが、これは時間制限内に問題なく収まります。 クエリごとの構造が固定配列を超えて保存されないため、メモリ使用量は最小限に抑えられます。

import sys, io

MOD = 998244353

def calc(x, a, n):
    if x < 0:
        return 0
    bits = [0] * n
    for i in range(n):
        bits[n - 1 - i] = (x >> i) & 1

    dp0 = [0] * (n + 1)
    dp1 = [0] * (n + 1)
    dp0[n] = dp1[n] = 1

    for pos in range(n - 1, -1, -1):
        dp0[pos] = dp0[pos + 1] * (1 + a[pos]) % MOD
        if bits[pos]:
            dp1[pos] = (dp0[pos + 1] + a[pos] * dp1[pos + 1]) % MOD
        else:
            dp1[pos] = dp0[pos + 1]

    return dp1[0]

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    n = int(input())
    a = list(map(int, input().split()))
    q = int(input())
    res = []
    for _ in range(q):
        l, r = map(int, input().split())
        res.append(str((calc(r, a, n) - calc(l - 1, a, n)) % MOD))
    return "\n".join(res)

 ## 特殊なケース

 クエリがゼロから始まる場合、減算には F(-1) が使用されます。 実装では、負の入力に対してゼロを返すことでこれを処理します。これにより、空のプレフィックスの合計がゼロであるというアイデンティティが保持されます。 たとえば、クエリ [0, r] では、調整の問題がなければ、結果は正確に F(r) になります。 

n を基準としたバイナリ表現で x の先頭にゼロがある場合、それらの位置は DP で強制ゼロとして動作します。 どのパスもプレフィックス制約を超えて 1 を設定できないため、遷移 dp1[pos] = dp0[pos + 1] はこの制限を正しく適用します。 これにより、有効ビット数が少ない数値でも n ビット空間に正しく埋め込まれることが保証されます。 

すべての a[i] が 1 の場合、すべてのサブセットは値 1 を持つため、f(x) は常に 1 となり、答えは範囲内の整数を数えることになります。 DP は 2 進数をカウントする標準のプレフィックスに縮退し、一様な場合でも乗算の重みが正しく処理されることを確認します。
