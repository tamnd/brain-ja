 ## 解決策
 ## 問題の理解

 n 個の頂点を持つ未知のツリー上の頂点ペアのコレクションが与えられます。 各ペアは、ある頂点から別の頂点への移動を表します。つまり、ツリーが固定されると、それらの 2 つの頂点間の一意の単純なパスに対応します。 

これらのペアのサブセットを選択することはできますが、ツリー自体は固定されていません。 n 頂点上に任意のツリーを自由に構築できます。 選択されたサブセットは、構築されたツリーに対する制約を満たす必要があります。選択されたペアに対応するすべてのパスを選択した場合、単一のツリー エッジがそれらのパスの複数に現れることは許可されません。 

課題は、私たちに有利になるように敵対的にツリーを設計することも許可されているという仮定の下で、保持できるペアの数を最大化することです。 

入力は単純に m 個の頂点ペアのリストです。 出力は、エッジ使用の制約を尊重しながら、あるツリーで同時に実現できるこれらのペアのサブセットの最大サイズです。 

制約は最大 2 · 10^5 の頂点とペアまでであり、指数関数的なサブセット検索や、すべての可能なツリーについて明示的に推論しようとするアプローチは即座に除外されます。 操作ごとに線形または線形に近い時間を超えると失敗します。 

ペアがサイクルを形成する場合、微妙なエッジケースが現れます。 たとえば、3 つのペア (1,2)、(2,3)、(1,3) を考えてみましょう。 これらを独立した接続として単純に扱うと、3 つすべてを選択できると考えられるかもしれません。 ただし、どのツリーでも、対応するパスの少なくとも 1 つは他のパスとエッジで重複する必要があるため、制約の下で 3 つすべてが共存することは不可能です。 

これは、本当の制限はツリー構造自体ではなく、選択されたペアが組み合わせ的にどのように相互作用するかであることをすでに示唆しています。 

## アプローチ

 最大の難点は、ツリーが固定されていないことです。 これにより、問題を構造的な観点から再解釈することができます。つまり、未知のツリー内のパスについて推論する代わりに、そのようなツリーの存在が選択されたペアにどのような制約を課すかを尋ねます。 

直接的な強引なアプローチは、ペアのすべてのサブセットを試し、各サブセットに対してツリーを構築し、エッジが共有されないように対応するすべてのパスの配線を試みることです。 ツリーの構築を無視したとしても、すべてのサブセットをチェックするだけですでに O(2^m) のコストがかかりますが、これは m が 2 · 10^5 までの場合は不可能です。 実現可能性のテストを繰り返し試行する貪欲なサブセット選択であっても、コストが高すぎるグローバルな一貫性チェックが必要になります。 

重要な観察は、パスの役割を単純化できるということです。 ツリーを設計することが許可されているため、長くて制約のあるものとしてパスを埋め込む必要はありません。 選択した構造内で 2 つの頂点が接続されている場合、他の選択したペアと構造上の矛盾が生じない限り、ツリー内で常にそれらを隣接させることができます。 

これは、より強力な抽象化で考えることができることを意味します。選択された各ペアは、ツリーに含めたいエッジのように動作します。 次に、ツリー要件によって 1 つのグローバル条件が課されます。選択された接続に循環があると、最終構造がツリーであるという要件と矛盾するため、選択されたセットは非循環でなければなりません。 

この視点に到達すると、問題は古典的な問題になります。つまり、フォレストを形成するように、与えられたセットからエッジの可能な最大のサブセットを選択することになります。 これはまさに最大の非巡回サブセットであり、素セット共用体構造を使用して見つけることができます。 

ペアを 1 つずつ処理し、以前に切断された 2 つのコンポーネントを接続する場合にのみ各ペアを保持します。 これにより、サイクルを導入しないことが保証され、できるだけ多くのペアが確実に取得されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | サブセットとツリー構造に対するブルート フォース | O(2^m) | O(n) | 遅すぎる |
 | DSUベースの最大限の森林構築 | O(m α(n)) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 この問題を、指定されたペアの最大サイズの非巡回サブセットを構築することに変換します。 

1. 独自のコンポーネント内の各頂点を使用して、素の集合共用体構造を初期化します。 これは、最初は強制接続が存在しないことを表します。 
2. 指定されたすべてのペア (a_i、b_i) を繰り返します。 各ペアについて、a_i と b_i がすでに同じコンポーネント内にあるかどうかを確認します。 
3. 異なるコンポーネントにある場合は、このペアを回答に含めて、2 つのコンポーネントをマージします。 これにより、サイクルを作成せずにフォレストを拡張することができます。 
4. それらがすでに同じコンポーネント内にある場合は、そのペアをスキップします。ペアを追加するとサイクルが作成され、有効な選択の一部にすることはできません。 
5. 受け入れられたペアの最終的な数が答えです。 

この貪欲な選択が機能する理由は、エッジを拒否するたびに、以前に受け入れられたペアによってすでに強制されているサイクルが閉じられるためです。 このエッジを含む解はそのサイクル内の少なくとも 1 つのエッジを除外する必要があるため、それを拒否しても最適解を減らすことはできません。 

### なぜ効果があるのか

 各ステップで、受け入れられたペアがフォレストを形成します。 選択されたペアのサイクルにより、少なくとも 1 つのツリー エッジが 2 つの異なるパスで再利用され、制約に違反するため、有効なソリューションはすべてフォレストである必要があります。 DSU プロセスは最大フォレストを構築します。最大フォレストのサイズは n から接続されたコンポーネントの数を引いたものになります。これは、サイクルを形成しないエッジの最大数です。 すべての有効な選択が何らかのフォレストに対応するため、この構築は最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

def main():
    n, m = map(int, input().split())
    dsu = DSU(n)

    ans = 0
    for _ in range(m):
        a, b = map(int, input().split())
        a -= 1
        b -= 1
        if dsu.union(a, b):
            ans += 1

    print(ans)

if __name__ == "__main__":
    main()
```DSU 構造は、すでに選択されているペアによって引き起こされる頂点の接続されたコンポーネントを維持します。 結合が成功するたびに、サイクルを形成せずにペアを安全に追加することに対応します。 答えは単純に、成功した結合の数です。 

よくある落とし穴は、ツリーを明示的に構築する必要がないことを忘れることです。 どのフォレストもスパニング ツリーに拡張できるため、DSU は、選択されたペアを何らかのツリーに埋め込むことができることをすでに暗黙的に保証しています。

            self.parent = list(range(n))
            self.size = [1] * n

                x = self.parent[x]

 ## 特殊なケース

 重要なエッジケースは、すべてのペアがサイクルを形成する場合です。 たとえば、三角形では、すべてのエッジは個別に有効ですが、3 つすべてが一緒になると無効になります。 DSU は、これを次のように正確に処理します。最初の 2 つのエッジはコンポーネントを結合し、3 番目のエッジは両方のエンドポイントがすでに接続されていることが検出されるため、拒否されます。 これにより、サイクルを明示的に検出することなく、最終的な答えがサイクル制約を遵守することが保証されます。 

もう 1 つのケースは、グラフがすでにツリーになっている場合です。 この状況では、同じコンポーネント内で 2 つの頂点を見つける結合は存在しないため、すべてのエッジが受け入れられます。 アルゴリズムは当然 m を返します。これは、ツリーがちょうど m = n - 1 個のエッジを持ち、完全に非循環であるという事実と一致します。 

ペアが指定されていない場合、縮退のケースが発生します。 DSU は結合を実行せず、結果はゼロになります。これは、パスを選択できないことを正しく反映しています。
