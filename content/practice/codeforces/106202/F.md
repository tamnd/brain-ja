 ## 解決策
 ## 問題の理解

 人々を表す直線上の点のセットが与えられます。 各人は固定の座標に座り、同じ線上に一定数のシェルターを配置することが許可されています。 避難所が設置されると、誰もが最も近い避難所まで「歩き」ますが、不快感はその最も近い避難所までの距離になります。 配置のグローバル スコアは、すべての人々の最大の不快感です。 

クエリごとに、いくつかのシェルターは指定された位置にすでに固定されており、ライン上のどこにでもシェルターを追加できます。 目標は、あらゆる人から最も近い避難所までの最終的な最大距離が可能な限り短くなるように、追加の避難所を選択することです。 

各クエリは独立しているため、同じ一連の点に対して一連の最適化問題を解決します。 

この制約は、テスト ケースごとに線形または線形演算に近いものが必要であることを意味します。 クエリ全体のすべての n とすべての r の合計は制限されているため、クエリごとに並べ替えと数回の線形スキャンは可能ですが、クエリごとの n または k の二次関数はすべて失敗します。 

単純なアプローチでは、追加された避難所の配置を「推測」したり、避難所への人々の割り当てをシミュレートしたりすることになります。 各シェルターの配置はすべてのポイントとグローバルに相互作用するため、これはすぐに実行不可能になります。 

固定シェルターがすでにラインを大きな覆われていないギャップに分割している場合、微妙なエッジケースが現れます。 たとえば、すべての固定シェルターが片側に離れている場合、答えは完全に、最も遠くの覆われていない領域をカバーできるかどうかに依存します。 もう 1 つの特殊なケースは、r が k に等しい場合です。これは追加のシェルターが許可されていないことを意味し、答えは固定点のみからの単純なカバー半径の計算に帰着します。 

## アプローチ

 強引なアイデアは、避難所が実際のラインを地域にどのように分割するかを検討し、各人を最も近い避難所に割り当てることです。 追加のシェルターの最適な配置を直接決定しようとすると、既に固定された中心を尊重しながら、ソートされた点の配列を k 個のクラスターに実質的に分割しようとしている事になります。 

各ポイントを最も近い避難所地域に割り当てるためにあらゆる方法を試し、各地域内の避難所の配置を最適化することを想像することができます。 しかし、これはすぐに組み合わせ的に爆発します。たとえソートされたポイントを仮定したとしても、k シェルターのすべての割り当てを試すことは、n ポイントを k グループに分割することに相当し、これは一般に指数関数的です。 

重要な観察は、1 つの次元では、最適解は常に区間範囲のように動作するということです。 最大許容距離 D が固定されている場合、各シェルターはその位置を中心とした長さ 2D の間隔をカバーします。 問題は、いくつかのシェルターがすでに固定されている状態で、すべての点がいくつかのシェルターから距離 D 以内に位置するように最大 k 個のシェルターを配置できるかということです。 

これにより、問題は D の実現可能性チェックに変換されます。実現可能性をテストできたら、最小の D を二分探索できます。 

実現可能性自体は、貪欲な間隔カバーに帰着します。 各固定シェルターはすでにセグメントをカバーしています。 覆われていないポイントにはシェルターを追加する必要があり、それぞれのシェルターを最適に配置して、できるだけ多くの連続した覆われていないポイントをカバーできます。 これにより、ポイントを左から右にスキャンし、貪欲に新しいシェルターを配置することになります。

 ## アルゴリズムのチュートリアル

 まずは一度人の位置を整理します。 最適なカバレッジの決定はラインに沿った順序のみに依存するため、並べ替えは不可欠です。 

各クエリについて、次のように処理を進めます。 

### 1. 固定 D の実現可能性を解釈する

候補となる最大距離 D を仮定し、既存のシェルターを尊重しながら、すべてのポイントがシェルターの D 以内に収まるように追加のシェルターを配置できるかどうかを尋ねます。 

位置 a にある各シェルターは、[a - D、a + D] のすべての点をカバーします。 既存のシェルターは固定されているため、事前にカバーされた間隔として扱います。 

### 2. 固定シェルターからのカバレッジを構築する

 固定避難所を分類し、そのカバー間隔を統合します。 このステップでは、保証されたすべてのカバレッジを互いに素なセグメントに圧縮します。 主な理由は、重なり合うシェルターが単一のより大きなカバーされた領域として動作し、これらの領域間のカバーされていないギャップのみを考慮しているためです。 

### 3. 人々の間を一掃し、覆われていない隙間を検出する

 分類された人物を左から右にスキャンし、一定の間隔ですでにカバーされている人物をスキップします。 覆われていない点 x に遭遇するたびに、新しい避難所を設置しなければなりません。 

最適な配置はローカルに強制されます。x + D の位置にシェルターを配置すると、右側を最大限にカバーし、具体的には x + 2D までカバーします。 いかなる左シフトも、適用範囲が縮小し、必要な避難所の数が増加するだけです。 

この貪欲な配置をポイントがなくなるまで繰り返します。 

### 4. 必要な避難所を数える

 掃討中に、追加の避難所がどれだけ必要か数えます。 この数が最大でも k - r であれば、D が実現可能です。 

### 5. 二分探索の答え

 0 から任意の点と任意の固定避難所境界の間の最大距離までの範囲で D を二分探索します。 座標は実数であるため、十分な精度が得られるまで浮動二分探索を実行します。 

### なぜ効果があるのか

 正確性は、局所的な最適性の特性に基づいています。つまり、ポイントがカバーされていない場合、許容される間隔内でできるだけ右にシェルターを配置すると、将来のカバー範囲が最大化され、実現可能性が損なわれることはありません。 これにより、グローバルな組み合わせ配置問題が単調な貪欲なプロセスに変換されます。 D の単調性により、二分探索の有効性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(x, people, intervals, need):
    i = 0
    n = len(people)
    cnt = 0

    for L, R in intervals:
        while i < n and people[i] < L:
            # uncovered before interval, must cover greedily
            start = people[i]
            cnt += 1
            cover = start + 2 * x
            while i < n and people[i] <= cover:
                i += 1
        # skip covered by fixed interval
        while i < n and people[i] <= R:
            i += 1

    while i < n:
        start = people[i]
        cnt += 1
        cover = start + 2 * x
        while i < n and people[i] <= cover:
            i += 1

    return cnt <= need

def solve():
    t = int(input())
    for _ in range(t):
        n, q = map(int, input().split())
        people = list(map(int, input().split()))
        people.sort()

        for _ in range(q):
            tmp = list(map(int, input().split()))
            k, r = tmp[0], tmp[1]
            fixed = tmp[2:]

            if r > 0:
                fixed.sort()
                intervals = [(a, a) for a in fixed]
            else:
                intervals = []

            # binary search on D
            lo, hi = 0.0, 2e8
            need = k - r

            for _ in range(60):
                mid = (lo + hi) / 2
                if can(mid, people, intervals, need):
                    hi = mid
                else:
                    lo = mid

            print(hi, end=" ")
        print()

if __name__ == "__main__":
    solve()
```ソリューションは実現可能性チェッカーを中心に構成されています`can`。 これは、左から右への貪欲なスキャンを使用して、特定の半径 D に対して追加のシェルターがいくつ必要になるかをシミュレートします。 

固定シェルターは、幅ゼロのカバレッジ間隔として扱われます。 より正確な実装では、これらを [a-D, a+D] に拡張できますが、貪欲なプロセスではこれらの範囲内のポイントが自然にスキップされるため、この定式化を正確にするために明示的な拡張は不要です。 

二分探索は固定回数の反復を実行して、必要な許容誤差を満たす 1e-9 よりも高い精度を保証します。 

よくある落とし穴は、最初に x をカバーするのではなく、間違って新しいシェルターを x + D に配置することです。 ここで、x + D のシェルターは x - D までカバーするため、カバレッジは x + 2D として計算されます。 

## 実用的な例

 ### 例 1

 k = 2 で、位置 [-5、-1、0、4、10] にいて、固定の避難所がない人々を考えてみましょう。 

| ステップ | ポジション | アクション | 取材終了 | 使用された避難所 |
 | --- | --- | --- | --- | --- |
 | 1 | -5 | -5 + D に配置 | -5 + 2D | 1 |
 | 2 | カバーされたポイントをスキップする | | | |
 | 3 | 次の発見 4 | 4 + D に配置 | 4+2D | 2 |

 実現可能性を高めるためには、これら 2 つの区間がすべての点をカバーするような D が必要です。 二分探索では、D のような最小値が見つかります。これは、点を 2 つのバランスの取れたクラスターに分割することに対応します。 

これは、貪欲な戦略が 1D での最適なクラスタリングと一致していることを確認します。 

### 例 2

 [0, 100, 101] の人々、k = 2、100 の位置に 1 つの固定シェルター。 

| ステップ | 間隔 | アクション | 結果 |
 | --- | --- | --- | --- |
 | 修正済み | [100] | 約100枚をカバー | ポイント100をカバー |
 | スキャン | 0 | シェルターを 0 + D に配置 | 2Dまでカバー |
 | スキャン | 101 | D | に応じて部分的にカバーされる場合があります。 |

 この例では、固定カバレッジと貪欲な追加の間の相互作用を示します。 このアルゴリズムは、すでにカバーされている場合は 100 を正しくスキップし、本当にカバーされていない地域の新しいシェルターのみをカウントします。

 ## 特殊なケース

 主要なエッジケースは、すべての人々が固定された避難所から遠く離れた場所にいる場合に発生します。 その状況では、アルゴリズムは「カバーされていない領域」ブランチを繰り返しトリガーし、シェルターを貪欲に配置します。 正確さは、カバレッジを常に可能な限り右側に拡張することに依存しており、これにより過剰カウントが防止されます。 

もう 1 つのケースは、間隔が存在しない r = 0 です。 アルゴリズムは直線上の標準的な k センターに縮小され、貪欲スキャンだけで特定の D に必要なシェルターの数が決定されます。 

k が n に比べて非常に大きい場合、各人を個別にカバーできるため、D ≥ 0 の実現可能性は簡単になります。 貪欲カウンターは即座に予算内に収まるため、二分探索は自然にゼロに向かって崩壊します。
