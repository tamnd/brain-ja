 ## 解決策
 ## 問題の理解

 頂点が平面上の点であるグラフが与えられていますが、幾何学は x 座標を通じてのみ重要です。 各エッジは 2 つの頂点を接続しており、エッジは直線セグメントと考えることができますが、セグメント間の交差は横断できません。 

各クエリ値 X に対して、仮想的な垂直カットを適用します。 X 座標が X に等しいすべての頂点が消えます。 線 x = X を横切るエッジも消えます。これは、X が端点を含む端点の x 座標の間にある場合、エッジが削除されることを意味します。 これらの削除の後、残りのグラフは、厳密に X の左側と厳密に X の右側の頂点と、完全に片側内にあるエッジのみで構成されます。 

各クエリのタスクは、このフィルタリングされたグラフに残っている連結成分の数を計算することです。 

各クエリは独立しているため、常に新しいカットで元のグラフを評価します。 

この制約により、テストごとに最大 10^5 の頂点、エッジ、クエリが許可されるため、クエリごとに接続性を最初から再計算するソリューションは遅すぎます。 単純なアプローチでは、グラフを再構築し、クエリごとに走査を実行するため、約 O(q(n + m)) が発生しますが、これは許容範囲をはるかに超えています。 

微妙な点は、同じ x 座標を持つ頂点が特別に動作することです。 X が頂点の X 座標と等しい場合、それらの頂点はすべて削除され、それらの頂点に付随するエッジも同様に消滅します。 どのような解決策であっても、厳密な不平等と平等を正しく分離する必要があります。 

単純な実装では、カットに「接触」するエッジを誤って保持する危険性もあります。 たとえば、エッジが x = 1 と x = 5 を接続する場合、X = 1 の場合、X に等しい端点が 1 つだけであっても、エッジはすでに削除されている必要があります。 

## アプローチ

 重要な観察は、垂直方向のカットでは純粋に x 軸上の頂点の順序によってグラフが分割されていることです。 x 座標で頂点を並べ替えた後、すべてのクエリ X は頂点を 3 つのグループ (x < X のグループ、x = X のグループ、x > X のグループ) に分割します。中央のグループは完全に破棄され、残りの 2 つのグループの間にエッジはありません。 

これは、クエリの答えが、x < X 上の誘導サブグラフ内の連結成分の数に、x > X 上の誘導サブグラフ内の連結成分の数を加えたものであることを意味します。 

この問題は、「x でソートされた頂点のプレフィックスに接続されたコンポーネントがいくつあるか」および「サフィックスにコンポーネントがいくつあるか」という形式の多くのクエリに答えることに帰着します。 

ブルート フォース アプローチでは、クエリごとに頂点とエッジをフィルタリングし、BFS または DSU を最初から実行します。 これは、各実行に O(n + m) のコストがかかり、q 回繰り返されるため失敗します。 

この改善は、プレフィックスとサフィックスの接続をオフラインで事前計算できることに気づいたことから生まれました。 頂点を x で並べ替える場合、どのプレフィックスについても、すでにアクティブ化された頂点に対して DSU を維持するだけで済みます。 プレフィックスを拡張するときに、一度に 1 つの頂点を追加し、両方のエンドポイントがすでにアクティブになっているエッジをアクティブにします。 これにより、1 回のスイープですべてのプレフィックス コンポーネントの数を計算できます。 接尾辞のケースは右から左に処理することで対称になります。 

この前処理の後、各クエリは 2 つのバイナリ検索と定数時間のルックアップに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | クエリごとに再計算 | O(q(n + m)) | O(n + m) | 遅すぎる |
 | プレフィックス + サフィックス DSU 前処理 | O((n + m) log n + q log n) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての頂点を X 座標で並べ替え、この順序での位置を記憶します。 すべてのエッジもこれらのインデックスに変換されます。

次に 2 つの配列を計算します。 最初の配列には、頂点の接頭辞ごとに、その接頭辞によって引き起こされるサブグラフ内の連結成分の数がソート順に格納されます。 2 番目の配列はサフィックスに対して同じことを行います。 

1. 頂点を x 座標で並べ替え、各頂点に 0 から n − 1 までの位置を割り当てます。これにより、すべてのプレフィックスが最小の x 値を持つ頂点のセットに対応する線形順序が得られます。 
2. これらの位置に関して隣接リストを作成します。 元の各エッジは 2 つのインデックス間の接続になります。 
3. プレフィックス接続を計算します。 アクティブな頂点がない状態から開始します。 ソートされた順序で左から右に繰り返します。 頂点を追加するとき、最初はそれが新しいコンポーネントを形成すると想定します。 次に、すでにアクティブになっている近隣のそれぞれについて、セットを結合します。 結合が成功するたびに、コンポーネントの数が減ります。 これにより、現在のプレフィックス内の接続されたコンポーネントの正確な数が維持されます。 
4. 同じ方法でサフィックス接続性を右から左に計算します。 頂点を再び段階的にアクティブ化し、すでにアクティブな隣接頂点と結合します。 
5. 各クエリ X について、ソートされた X 配列内の位置を特定します。 i を x ≥ X の最初のインデックス、j を x > X の最初のインデックスとします。その場合、左側は接頭辞 [0, i − 1]、右側は接尾辞 [j, n − 1] になります。 答えは、prefix_components[i] + suffix_components[j]です。 

これが機能する決定的な理由は、中央のグループ x = X を削除した後、左右の間で交差するエッジが存在しないことです。そのようなエッジはすべて必然的に X にまたがるため、削除されるからです。 両側の接続は完全に独立しています。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.p = list(range(n))
        self.sz = [1] * n

    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return False
        if self.sz[a] < self.sz[b]:
            a, b = b, a
        self.p[b] = a
        self.sz[a] += self.sz[b]
        return True

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        n, m, q = map(int, input().split())
        xs = list(map(int, input().split()))
        ys = list(map(int, input().split()))

        edges = [[] for _ in range(n)]
        for _ in range(m):
            u, v = map(int, input().split())
            u -= 1
            v -= 1
            edges[u].append(v)
            edges[v].append(u)

        queries = list(map(int, input().split()))

        order = sorted(range(n), key=lambda i: xs[i])
        pos = [0] * n
        for i, v in enumerate(order):
            pos[v] = i

        adj = [[] for _ in range(n)]
        for u in range(n):
            for v in edges[u]:
                adj[pos[u]].append(pos[v])

        pref = [0] * (n + 1)
        dsu = DSU(n)
        active = [False] * n
        comp = 0

        for i in range(n):
            v = i
            active[v] = True
            comp += 1
            for to in adj[v]:
                if active[to]:
                    if dsu.union(v, to):
                        comp -= 1
            pref[i + 1] = comp

        suff = [0] * (n + 1)
        dsu = DSU(n)
        active = [False] * n
        comp = 0

        for i in range(n - 1, -1, -1):
            v = i
            active[v] = True
            comp += 1
            for to in adj[v]:
                if active[to]:
                    if dsu.union(v, to):
                        comp -= 1
            suff[i] = comp

        xs_sorted = [xs[i] for i in order]

        for X in queries:
            import bisect
            i = bisect.bisect_left(xs_sorted, X)
            j = bisect.bisect_right(xs_sorted, X)
            out.append(str(pref[i] + suff[j]))

        out.append("")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```この実装では、まずグラフを x ソートされたインデックス空間に変換し、「プレフィックス」が文字通り「x 順で左にあるすべての頂点」を意味するようにします。 DSU は、頂点を段階的にアクティブにする間、接続を維持するためにのみ使用されます。これにより、グローバル接続を最初から再計算する必要がなくなります。 

プレフィックス配列には、アクティブ セットを左から右に拡大するときにコンポーネントの数が格納されます。 サフィックス配列は、このプロセスを右から左に反映します。 各結合操作はアクティブ チェックによって保護されているため、現在のプレフィックスまたはサフィックスにまだ含まれていない頂点が接続されることはありません。 

クエリの処理は、ソートされた x 座標での二分探索に簡素化されます。 これがクエリごとの唯一のコストです。 

## 実用的な例

 頂点がすでに x 座標 x = [1, 2, 3, 4] によって順序付けされており、いくつかのエッジがチェーンを形成している小さなグラフを考えてみましょう。 

頂点をアクティブ化するときにプレフィックス コンポーネントを計算します。 

| ステップ | アクティブな頂点 | DSU組合 | コンポーネント |
 | --- | --- | --- | --- |
 | 1 | {1} | なし | 1 |
 | 2 | {1,2} | (1-2) | 1 |
 | 3 | {1,2,3} | (2-3) | 1 |
 | 4 | {1,2,3,4} | (3-4) | 1 |

 これで、suffix も同様に動作しますが、順序は逆になります。 

クエリ X = 2.5 の場合、左側の {1,2} と右側の {3,4} に分割されます。 どちらも接続されたチェーンなので、答えは 1 + 1 = 2 となります。 

クエリ X = 3 の場合、x = 3 の頂点が削除されます。 左が {1,2}、右が {4} です。 左は接続されているので 1 コンポーネント、右は分離されているので 1 コンポーネント、合計は 2 です。 

これらの例は、X との等価性によって頂点全体がどのように削除されるか、および並べ替え順序を分割することで X にまたがるエッジがどのように暗黙的に除外されるかを示しています。

 ## 特殊なケース

 重要なケースは、多くの頂点が同じ X 座標を共有する場合です。 X がその値と等しい場合、それらはすべて同時に削除されるため、プレフィックスとサフィックスの両方がそのブロック全体を除外する必要があります。 二分探索分割では、すべての等しい要素が lower_bound と upper_bound の間に収まり、そのセグメントの両側が空のままになるため、これが正しく保証されます。 

もう 1 つのエッジ ケースは、X がすべての X 座標よりも小さい場合です。 この場合、左側の部分は空であり、答えは接尾辞の構造のみに依存します。 プレフィックス配列はインデックス 0 でゼロのコンポーネントを正しく返しますが、サフィックスはグラフ全体をカバーします。 

X がすべての座標より大きい場合、接尾辞は空になり、接頭辞だけが残り、やはり事前計算された配列の境界値によって処理されます。
