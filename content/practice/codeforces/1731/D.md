 ## 問題の理解

 いくつかの独立したグリッドが与えられ、各グリッドは都市地図を表し、各セルには建物の高さが含まれます。 各グリッドから、次のサイズの正方形のサブグリッドを選択する必要があります。$l \times l$その正方形内のすべてのセルが少なくとも高さを持つようにする$l$。 タスクは、可能な最大値を見つけることです。$l$テストケースごとに。 

主な問題点は、制約がジオメトリと値を結合していることです。正方形を拡大すると、辺の長さと最小許容高さの両方が同時に増加するため、要件がより厳しくなります。 これにより、この問題は、しきい値が固定される標準的な「1 の最大 2 乗」タイプのタスクとは根本的に異なります。 

制約は、最大でも合計を意味します。$10^6$すべてのテスト ケースにわたるセル。 これにより、次のような単純な方法ですべての候補四角形の答えを再計算するなど、テスト ケースごとに超線形なアプローチは直ちに排除されます。$O(n^3)$あるいは$O(n^2 m)$行動。 おおよそのパフォーマンスを発揮するソリューション$O(nm \log \min(n,m))$または$O(nm)$テスト ケースごとの集計は許容されます。 

いくつかのエッジ動作は見落とされがちです。 すべての値が小さい場合、たとえば 1 で埋められたグリッドの場合は、$1 \times 1$要件により、値が少なくとも辺の長さであることがすでに強制されているため、すぐに失敗します。 逆に、値が大きくても分散している場合、密な領域を形成しない限り、単独で大きな値を使用しても役に立ちません。 

よくある間違いは、条件が正方形のサイズのみまたは値のみに依存するかのように扱うことです。 たとえば、「すべての値が少なくとも 1 である最大の正方形」が常に最適であると仮定すると、増加することは無視されます。$l$閾値自体を増加させます。

重要な観察は、固定の条件は次のとおりであるということです。$l$標準的なバイナリ グリッド問題になります。 辺の長さの候補を決めると$l$が存在するかどうかだけを気にします。$l \times l$すべての値が少なくとも次の部分行列$l$。 これにより、グリッドがバイナリ行列に変換され、セルがしきい値を満たすかどうかに応じて有効または無効になります。

 ## アルゴリズムのチュートリアル

 問題を、指定された辺の長さが満たされているかどうかを確認することに縮小します。$l$実現可能です。 

1. 候補者が確定した場合$l$、グリッドをバイナリ グリッドに変換します。セルの高さは少なくとも 1 です。$l$このステップでは制約を構造に直接エンコードするため、残るのはジオメトリだけです。 
2. 動的プログラミング テーブルを構築します。$dp[i][j]$セルで終わるすべてが 1 の正方形の最大サイズを表します$(i,j)$。 現在のセルが有効な場合は、隣接する 3 つの正方形のうち最小のものを拡張します。 それ以外の場合はゼロです。 これは、次で終わる正方形があるため機能します。$(i,j)$有効な正方形を上、左、左斜め上に拡張する必要があります。 
3. DP テーブルに記入するとき (存在する場合)$dp[i][j]$少なくとも到達する$l$、有効なことがすぐにわかります$l \times l$広場が存在し、早期に停止することができます。 
4. この実現可能性チェックを二分探索内にラップします。$l$1から$\min(n,m)$。 値の場合$l$実現可能であれば、より大きな値を試します。 それ以外の場合は範囲​​を縮小します。 
5. 最終的な答えは実現可能な最大のものです$l$。 

DP の繰り返しは次のとおりです。$dp[i][j] = \begin{cases} 1 + \min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1]) & \text{if } a_{i,j} \ge l \\ 0 & \text{otherwise} \end{cases}$### なぜ効果があるのか

 セルで終わるすべての有効な正方形には、その 3 つの先行方向のそれぞれで終わる小さな正方形が含まれている必要があります。 これらの方向のいずれかが条件を破ると、正方形を拡張できません。 反復では、各位置に固定されている可能な最大の正方形と、有効な正方形が正確にキャプチャされます。$l \times l$正方形は少なくとも到達する DP 値として表示される必要があります$l$。 これにより、チェックが必要かつ十分になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can(l, n, m, a):
    dp = [0] * (m + 1)
    prev = [0] * (m + 1)
    
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if a[i-1][j-1] >= l:
                dp[j] = min(prev[j], dp[j-1], prev[j-1]) + 1
                if dp[j] >= l:
                    return True
            else:
                dp[j] = 0
        prev, dp = dp, prev
    return False

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = [list(map(int, input().split())) for _ in range(n)]
        
        lo, hi = 1, min(n, m)
        ans = 1
        
        while lo <= hi:
            mid = (lo + hi) // 2
            if can(mid, n, m, a):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1
        
        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションは、実現可能性のチェックを最適化から分離します。 の`can`関数は行ごとにスキャンしながら DP ロジックをエンコードし、2 つのローリング配列のみを使用してメモリの列数を線形に保ちます。 

実行可能性は単調であるため、二分探索によって最終的な答えが導き出されます。$l$: サイズの正方形に 1 回$l$が存在する場合、サイズ要件と高さのしきい値の両方が一緒に減少するため、すべてのより小さいサイズが自動的に可能になります。 

実装の微妙な詳細は、DP ループ内の早期終了です。 いずれかのセルが少なくとも正方形のサイズに達すると、$l$、そのテストではさらなる計算が不要になり、密度が高い場合のパフォーマンスが大幅に向上します。
