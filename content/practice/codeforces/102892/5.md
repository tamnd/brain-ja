 ## 解決策
 ## 問題の理解

 私たちにはテレビ チャンネルのコレクションが与えられており、それぞれが一連の分を放送しています。 どのチャンネルでも、1分ごとに「面白い」か「面白くない」かのどちらかになります。 ある瞬間が興味深い場合、その瞬間にそのチャンネルを視聴すると、そのチャンネルに関連付けられた一定の楽しみの価値が得られます。 それ以外の場合は何も与えません。 

テレビは常に、最大でいくつかのチャンネルを同時に録画できます。 決定の問題は、最大でも録音が許可されるかどうかです。`c`1 分あたりのチャンネル数、すべてのチャンネルとすべての分で蓄積できる合計最大の楽しみはいくらですか? 1 分あたりの制限を超えて、制限された方法で積極的にチャンネルを毎分異なる方法で選択する必要はないため、録画するチャンネルを選択するという観点から、各分を独立して扱うことができます。 

タスクは最小のものを見つけることです`c`達成可能な最大の総合的な楽しみが少なくとも`k`。 全チャンネル録画しても毎分に達しない場合`k`、出力する必要があります`-1`。 

入力サイズは、問題の両方の次元 (チャネル数と分数) が最大でも 1000 であるほど十分に小さいです。これは、最適化された C++ では、およそ数億の基本演算までのソリューションはまだギリギリ許容可能であることをすぐに示唆していますが、Python ソリューションでは、三次または候補ごとの大量の再計算を回避する必要があります。 

重要な制約は、`k`は 10^18 に達する可能性があり、これにより、解では大きな値を慎重に累積する必要が生じ、組み合わせ検索を行っているのではなく、グローバルな量を最適化していることが明確になります。 

単純に解釈すると、1 分ごとの選択によって組み合わせ爆発が生じると思われるかもしれませんが、構造によってその依存関係が解消されます。 

興味深いコンテンツがどこにも存在しない場合、微妙なエッジケースが発生します。 すべてのチャネルがすべてゼロの場合、すべてのゲインは、`c`、したがって、答えは次のようになります。`-1`。 2 番目のエッジケースは次のような場合です。`k`非常に小さい、たとえば`k = 1`、最適な選択が 1 つだけでも十分です。 3 番目のケースは、1 つのチャネルが毎分支配的になる場合です。つまり、チャネルが増加することを意味します。`c`1 を超えると、最初の選択の後は何も行われません。 

## アプローチ

 ブルートフォースアプローチでは、次の値が固定されます。`c`そして可能な限り最善の戦略をシミュレーションします。 毎分、どのチャンネルを録音し、ゲインを蓄積するかを計算します。 ただし、重要な観察は、チャネルは分を超えて相互作用せず、各分が独立して付加価値をもたらすため、固定チャネルの最適な選択であるということです。`c`常に選択することです`c`現時点で最も貢献度が高いチャンネル。 つまり、毎分チャンネルを貢献度で並べ替え、上位を選択することになります。`c`。 

これを候補者ごとに個別に行う`c`1から`n`おおよそ次のような複雑さが生じます`O(n^2 * m log n)`、それぞれのため`c`そして毎分、上位の値を並べ替えたり選択したりします。 と`n, m ≤ 1000`、これは Python ではすでに遅すぎます。 

重要な洞察は、視点を逆転させることです。「1 分あたりのチャネル数が固定されている場合、最高のスコアはいくらか」を尋ねる代わりに、各チャネルが全分間にわたって合計でどれだけ貢献しているかを分ごとに計算します。 つまり、興味のある時点でチャネルを選択するたびに、常に同じチャネル固有の値が得られるため、チャネルごとの合計「利益」を事前に計算します。 これにより、問題は静的な選択問題に変換されます。各チャネルには合計の潜在的なゲインがあり、チャネルを選択すると、その寄与をすべて収集できることになります。 

これにより、問題全体が、合計ゲインによってチャネルをソートし、プレフィックスを取得するという問題に軽減されます。 答えは最小になります`c`上部の合計が`c`チャンネルゲインは少なくとも`k`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォースパー`c`分ごとの再計算付き | O(n² m log n) | O(nm) | 遅すぎる |
 | 合計を事前計算してチャネルを並べ替える | O(nm + n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各チャネルのバイナリ スケジュールをスキャンして、すべての分にわたる合計寄与度を計算します。 1 分が興味深いとマークされるたびに、そのチャンネルの楽しみの価値が追加されます。 このステップでは、時間構造をチャネルごとに 1 つのスカラーに分解します。 

2. これらの合計を配列に保存します。 各エントリは、スケジュールに関係なく、そのチャネルから抽出できる最大の貢献を表します。 

3. 合計の配列を降順に並べ替えます。 これにより、「アクティブ化」することを決定した場合に、`c`チャネルでは、常に最も価値のあるチャネルを最初に選択します。 

4. ソートされた配列に対してプレフィックスの合計を作成します。 各プレフィックスの合計は、1 分あたり最大でその数のチャンネルを録画できる場合に達成可能な最高のスコアを表します。 

5. 最小のインデックスを見つける`c`プレフィックスの合計が少なくとも`k`。 それ`c`が答えです。 

6. 全チャンネルの合計が以下の場合`k`、出力`-1`。 

微妙な点は、チャネルが一度集約されると分単位で競合しないため、並べ替えは時間の順序付けではなく、独立した追加の寄与を最大化することであるということです。 

### なぜ効果があるのか

 正しさは単純な交換引数に基づいています。 固定の場合`c`の場合、最適な戦略では常に合計寄与度が高いチャネルが優先されます。これは、寄与度の低いチャネルを寄与度の高いチャネルに置き換えても、いかなる瞬間もゲインが減少することはなく、合計ゲインが厳密に増加するためです。 1 分あたりの上限を超える分をまたぐチャネル間の結合はないため、この貪欲な選択は全体的に最適です。 したがって、どのような場合にも最適なソリューションが得られます。`c`チャネル合計のマルチセットと、最上位の選択にのみ依存します。`c`合計で十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, k = map(int, input().split())
a = list(map(int, input().split()))

totals = [0] * n

for i in range(n):
    s = input().strip()
    ai = a[i]
    total = 0
    # accumulate contribution over all interesting minutes
    for ch in s:
        if ch == '1':
            total += ai
    totals[i] = total

totals.sort(reverse=True)

prefix = 0
answer = -1

for i, val in enumerate(totals):
    prefix += val
    if prefix >= k:
        answer = i + 1
        break

print(answer)
```このソリューションは、各チャネルのスケジュールを単一の累積値に変換することから始まります。 これにより、後から分ごとの決定をシミュレーションする必要がなくなります。 ソート ステップは唯一のグローバル カップリング操作であり、これにより、`c`常に最善の方向にソリューションを拡張します。 次に、プレフィックス スキャンは、単調な実現可能性条件に直接応答します。 

よくある実装上の間違いは、すべての項目に対して 1 分ごとの最適な選択肢を再計算しようとすることです。`c`これにより、不要な 2 次元が再導入され、タイムアウトが発生します。 もう 1 つは、チャネルの寄与が独立していることを忘れているため、1 分あたりの複雑な貪欲なマッチングを伴うソリューションを誘惑することです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))

    totals = [0] * n
    for i in range(n):
        s = input().strip()
        ai = a[i]
        for ch in s:
            if ch == '1':
                totals[i] += ai

    totals.sort(reverse=True)

    prefix = 0
    ans = -1
    for i, v in enumerate(totals):
        prefix += v
        if prefix >= k:
            ans = i + 1
            break

    return str(ans)

# edge: impossible
assert run("2 3 10\n5 4\n000\n000\n") == "-1"

# edge: single channel sufficient
assert run("1 3 5\n2\n111\n") == "1"

# edge: all channels needed
assert run("3 3 10\n1 1 1\n111\n111\n111\n") == "3"

# edge: mixed pattern
assert run("4 4 7\n1 2 3 4\n1010\n0101\n1111\n0000\n") == "2"
```| テスト入力 | 期待される出力 | 検証内容 |
 |---|---|---|
 | すべてゼロ | -1 | 不可能なケース |
 | シングルチャンネル | 1 | 最小境界 |
 | 完全な要件 | 3 | すべてのチャンネルが必要 |
 | 混合 | 2 | 貪欲なプレフィックスの正確性 |

 ## 特殊なケース

 すべてのチャネル文字列にゼロのみが含まれる完全に空のスケジュールでは、すべてのチャネルの寄与が合計ゼロになります。 その状況では、プレフィックスの合計は決して増加しないため、アルゴリズムは正しく返します。`-1`。 

単一チャネル入力は、最初の要素を追加した後にプレフィックス合計ループがチェックするため、自明に処理されます。`k`、答えは`1`。 

すべてのチャネルが常に完全にアクティブである場合、それぞれの合計は次のようになります。`value × m`、ソートは値による順序付けになります。 スケーリングによりアルゴリズムは引き続き正しく動作します。`m`順序を保持します。 

時間構造はすでに合計に折りたたまれているため、遅いチャネルだけが役立つ場合は問題になりません。 このアルゴリズムは時間分布を完全に無視します。これは、分ごとの独立性によって順序付けの影響が除去されるため安全です。
