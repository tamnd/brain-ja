 ## 解決策
 ## 問題の理解

 1 つ以上の整数シーケンスが与えられます。各シーケンスについて、そのシーケンス内で 1 回だけ出現するという意味で、どの値が「一意」であるかを判断する必要があります。 出力は完全に頻度情報から得られます。配列を変換したり、出現数が 1 である要素を識別する以上に新しいものを構築したりすることはありません。 

計算の観点から見ると、入力サイズは一般的な競技プログラミングの制限に達する可能性があり、すべてのテスト ケースにわたる要素の総数が大きくなり、最大で約\(10^5\)またはそれ以上。 これにより、各要素を他のすべての要素と比較する二次アプローチは即座に除外されます。 配列に対してネストされたスキャンを実行するソリューションは \(O(n^2)\) に低下し、数千の要素を超えると実行不可能になります。 

重複がクラスター化されずに分散している場合、微妙な失敗のケースが発生します。 たとえば、配列が次の場合、\([1, 2, 1, 3, 2]\)、ユニークな要素は\(3\)。 単純な「訪問済みのマークを付ける」または「オンザフライで重複を削除する」アプローチでは、シーケンス全体にわたるグローバルなカウントが維持されていない場合、要素を簡単に誤って分類する可能性があります。 

単一要素の配列では、別の特殊なケースが発生します。 入力用\([7]\)、正しい出力は次のとおりです。\(7\)、ちょうど 1 回出現するためです。 「一意性には隣接するものとの比較が必要である」と仮定するロジックは、境界でコンテキストが欠落しているため、誤って破棄されてしまいます。 

## アプローチ

 ブルートフォースのアイデアは簡単です。要素ごとに、配列全体をスキャンし、それが出現する回数を数えます。 カウントが 1 に等しい場合、それを出力に含めます。 これは一意性の定義に直接従うため、正しいです。 

ただし、このアプローチでは要素ごとにフル スキャンが実行されます。 サイズの配列の場合\(n\)、これは次のことにつながります\(n\)サイズのスキャン\(n\)、結果として \(O(n^2)\) の操作が行われます。 で\(n = 10^5\)、これには必要になります\(10^{10}\)これは合理的な制限時間をはるかに超えています。 

重要な観察は、繰り返しカウントするのは無駄であるということです。 すべての要素の周波数は検査する順序とは無関係であり、中間結果を保存すれば周波数は 1 回のパスで計算できます。 これは、ハッシュ マップまたは辞書を使用して最初にカウントを蓄積し、次にこれらのカウントに基づいて要素をフィルタリングすることを提案しています。 

これにより、問題は 2 つの線形パスに変換されます。1 つは周波数情報を構築するパス、もう 1 つはカウントが 1 に等しい要素を抽出するパスです。 問題の構造上、一意性は位置関係ではなく全体的な頻度にのみ依存するため、これは自然なことです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | \(O(n^2)\) | \(O(1)\) | 遅すぎる |
 | 周波数マップ | \(O(n)\) | \(O(n)\) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力シーケンスを読み取り、配列に格納します。 これは、周波数を計算し、出力を生成するときに元の順序を維持するために必要です。 

2. 空の辞書を初期化して、各整数のカウントを保存します。 各キーは配列の値を表し、関連付けられた値はその出現回数を追跡します。 

3. 配列を 1 回走査し、要素の数をインクリメントして各要素の辞書を更新します。 このステップでは、すべての繰り返し情報を 1 つの構造に圧縮します。 

4. 同じ順序で配列をもう一度走査します。 各要素について、辞書でその頻度を確認します。 頻度が 1 に等しい場合、それを出力リストに追加します。 

5. 結果として得られる一意の要素のリストを出現順に出力します。 

ディクショナリ キーを反復処理する代わりに 2 回目の走査を行う理由は、出力が元の順序を保持する必要があるためです。 辞書だけでは順序要件は保証されません。 

### なぜ効果があるのか

 このアルゴリズムは、最初のパスの後、辞書には配列内のすべての値の正確なグローバル頻度が含まれるという不変条件に依存します。 一意性は純粋に 1 に等しい頻度によって定義されるため、2 番目のパスで選択された要素は問題の条件を満たさなければなりません。 すべての配列要素が順番に 1 回だけチェックされるため、要素が欠落することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arr = list(map(int, input().split()))
    
    freq = {}
    for x in arr:
        freq[x] = freq.get(x, 0) + 1
    
    res = []
    for x in arr:
        if freq[x] == 1:
            res.append(x)
    
    print(*res)

if __name__ == "__main__":
    solve()
```最初のループでは、辞書を使用して頻度テーブルを構築し、要素ごとの一定時間の平均更新を保証します。 2 番目のループは、出力形式で必要な入力順序を維持しながら、計算された周波数に基づいて要素をフィルター処理します。 

実装におけるよくある間違いは、繰り返しを繰り返すことです`freq.keys()`元の配列の代わりに。 これにより、周波数ロジックが正しい場合でも、順序情報が破壊され、誤った出力が生成されます。 もう 1 つの微妙な問題は、一意の要素がない場合の処理​​を忘れていることです。この場合、エラーやプレースホルダーではなく空の行が出力されるはずです。

 | 測定 | 複雑さ | 説明 |

線形複雑さは、以下の典型的な制約には十分です。\(10^5\)効率的な辞書操作を使用する場合、Python の時間制限内で快適に要素を追加できます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    
    def solve():
        n = int(input())
        arr = list(map(int, input().split()))
        freq = {}
        for x in arr:
            freq[x] = freq.get(x, 0) + 1
        res = [x for x in arr if freq[x] == 1]
        print(*res)
    
    solve()
    return sys.stdout.getvalue().strip()

# all duplicates

 ## 特殊なケース

 のような入力の場合`1\n42\n`、最初のパス後の辞書は次のようになります。`{42: 1}`。 2 番目のパスでは、唯一の要素が周波数 1 を持つため、直接出力されます。 これは、アルゴリズムが正しく機能するために隣接性や複数の出現に依存していないことを確認します。 

のような入力の場合`4\n5 5 6 6\n`、周波数マップは次のようになります`{5:2, 6:2}`。 フィルタリング中に、すべての要素がチェックされて拒否され、空の出力が生成されます。 実装では、出力生成ロジックをスキップするのではなく、空の行を出力することでこれを正しく処理します。
