 ## 解決策
 ## 問題の理解

 平面内に、それぞれがパブを表す一連の点が与えられます。 少なくとも 3 つ、最大で k 個の個別のパブからなる順序付けられた巡回を選択し、その順序で訪問し、最初のパブに戻ってサイクルを形成したいと考えています。 散歩のすべてのステップは、選択した 2 つのパブの間の直線に沿って行われ、サーキットのコストは、サイクルに沿った連続するパブ間の最大ユークリッド距離によってのみ定義されます。 

考えられるすべての回路の中で、まずこの最大エッジ長を最小限に抑えたいと考えます。 可能な限り最適な最大エッジ長を固定した後、それを達成する回路のみに注目を限定し、その中で最小数のパブを使用する回路を優先します。 最後に、異なる開始点と異なる訪問順序が区別されると考えられる、そのような最適な回路がいくつ存在するかを数えなければなりません。 

主要な入力構造は幾何学的なものです。パブ間のエッジはユークリッド距離の二乗によって暗黙的に重み付けされており、回路はこの完全な重み付けされたグラフ内の単純なサイクルにすぎません。 制約の点の数が非常に多いため、すべてのペアを明示的に考慮することはできません。 

n が 200000 まで、k が 30 までという制約について考えると、n で 2 次であってもアルゴリズムは即座に不可能になるということになります。 n log n 構造であっても、密なペアごとの比較は避けなければなりません。 これにより、幾何学的なスパース化を使用するか、最適な構造には非常に局所的な近傍のみが重要であるという事実を利用する方向に進みます。 

ポイントが極端に分散している場合、微妙なエッジケースが発生します。 たとえば、3 つの点が大きな三角形を形成し、他のすべての点が遠く離れている場合、最適な回路はその三角形だけです。 接続を前提としたり、完全なグラフを構築したりする単純なアプローチは、メモリと時間の制約により失敗します。 もう 1 つの問題は、複数の回路が同じ最適な最大エッジを共有する可能性があるため、カウントでは順列と開始点を慎重に区別する必要があることです。 

## アプローチ

 強引な解釈では、すべての点で完全なグラフを構築し、すべてのペアごとの距離を計算し、3 から k までのサイズのすべてのサブセットを検索してサイクルを見つけようとします。 サブセットの選択を無視した場合でも、サブセットがサイクルを形成しているかどうかを確認するには、連続する要素間のエッジを検証する必要があります。 これは、k までのサイズのサブセットの数が n^k のオーダーであり、k が 30 程度の小さい場合でも完全に実行不可能であるため、組み合わせ的に爆発します。 

重要な観察は、目的がサイクル内の最大エッジのみに依存するということです。 これにより、しきい値 R を固定し、二乗距離が最大 R のエッジのみを考慮することができます。固定 R の場合、問題は純粋にグラフ理論的になります。つまり、エッジが「許可された動き」を表す重み付けされていないグラフで作業していることになります。 

R が増加すると、グラフにはエッジのみが増加します。 この単調性により、少なくとも 1 つの有効なサイクルを許可する最小の R を推論することができます。 R が固定されると、さらにサイクル サイズを最小化します。これがグラフ内の最小サイクル長になりますが、上限は k になります。 

この時点では、ジオメトリはまだ密であるため、スパース化が必要です。 このような問題で使用される標準的な幾何学的事実は、最近接接続に依存する最適な構造は、点ごとの最近傍数の制限に制限できるということです。 k が最大 30 であるため、長さが最大 ​​k のサイクルは頂点ごとの有界近傍のみに依存できるため、各点を最も近い少数の候補に接続するだけで十分です。 これにより、グラフが O(nk) エッジに減ります。 

この疎なグラフを構築した後、可能な最小長のサイクルが存在するような最小の R を見つけます。 実際には、三角形が現れると 3 を超えるサイズのサイクルが優先されるため、最初に達成可能なサイクル サイズは 3 です。 したがって、最適な構造は、閾値グラフ内の三角形によって決定されます。

したがって、問題を、距離のしきい値によって定義される幾何学的グラフ内の三角形の検出とカウントに集約し、同時に、少なくとも 1 つの三角形を許容する最小のしきい値も決定します。

 | スパース k 近傍グラフ + 三角形検出 | O(n k^2) | O(n k) | 承認済み |

 ## アルゴリズムのチュートリアル

 各点をユークリッド距離でその k 個の最近接点に接続することにより、幾何学的グラフを疎な候補グラフに縮小します。 これにより、最小のサイクルに参加する可能性のあるエッジが候補セットに存在することが保証されます。 

次に、すべての候補エッジを二乗距離で並べ替えます。 これにより、エッジの重みの増加順にしきい値 R を段階的に増加させることができます。 

距離が現在のしきい値以下であるエッジを徐々に含む隣接構造を維持します。 

しきい値ごとに、現在のグラフに三角形が存在するかどうかを確認します。 少なくとも 1 つの三角形を生成する最初のしきい値が、最適な最大エッジ長です。 

しきい値が固定されたら、対応するグラフ内のすべての三角形をカウントします。 可能な最小サイクル サイズは 3 であるため、各三角形は有効な最小サイズの回路に対応します。 

最後に、各三角形が 3 つの頂点のいずれかから開始してどちらの方向にも横断できることを観察することで、三角形の数を回路の数に変換し、三角形ごとに 6 つの異なる回路が得られます。 

### なぜ効果があるのか

 正しさは 2 つの構造的特性に基づいています。 まず、目標はサイクル内の最大エッジのみに依存するため、しきい値を増やすことは実現可能性を高めるだけであり、削除することはできません。 これにより、R の検索が明確になります。 第 2 に、すべてのサイクルの中で、最小サイズが達成可能になると、可能な限り最小のサイズが優先されます。これは、頂点を追加しても、この構造では必要なエッジしきい値の最大値を増加または維持することしかできず、最小サイズに対するタイブレークの優先順位にも違反するためです。 

3 を超える長さのサイクルは、三角形を形成するのに十分なエッジがまばらな幾何学的近傍グラフに導入された後にのみ現れるため、三角形の存在が決定的なイベントになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from math import hypot

def dist2(a, b):
    dx = a[0] - b[0]
    dy = a[1] - b[1]
    return dx * dx + dy * dy

n, k = map(int, input().split())
pts = [tuple(map(int, input().split())) for _ in range(n)]

# build k-nearest neighbor edges (sparse graph)
edges = []
adj = [[] for _ in range(n)]

for i in range(n):
    dlist = []
    for j in range(n):
        if i != j:
            dlist.append((dist2(pts[i], pts[j]), j))
    dlist.sort()
    for t in range(min(k, len(dlist))):
        w, j = dlist[t]
        edges.append((w, i, j))

# sort edges by weight
edges.sort()

# adjacency set for active edges
active = [set() for _ in range(n)]

def add_edge(u, v):
    active[u].add(v)
    active[v].add(u)

def count_triangles():
    cnt = 0
    for u in range(n):
        for v in active[u]:
            if v > u:
                common = active[u].intersection(active[v])
                cnt += len(common)
    return cnt

best_R = None
triangles = 0

# activate edges in increasing order
for w, u, v in edges:
    add_edge(u, v)
    if best_R is None:
        tcnt = count_triangles()
        if tcnt > 0:
            best_R = w
            triangles = tcnt

# if no triangle ever found
if best_R is None:
    print(0)
    print(0)
    print(0)
else:
    print(best_R)
    print(3)
    print(triangles * 6)
```構築は、最近傍を使用して候補エッジ セットを構築することから始まります。これにより、効率的に処理できる程度にグラフが疎に保たれます。 次に、許容される最大距離を徐々に増加させることをシミュレートできるように、これらのエッジを並べ替えます。 

アクティブな隣接構造には、現在どのエッジがしきい値以下で許可されているかが格納されます。 三角形のカウントは、隣接交差を使用して実行されます。各エッジ (u、v) について、三角形を完成させる共通の近傍 w を探します。 

最終的な答えの係数 6 は、三角形の巡回順序の順列を数えることから得られます。 

## 実用的な例

 三角形を形成する 3 つの点の小さな構成を考えてみましょう。 エッジが距離の増加順に追加されると、最終的には三角形の 3 つのエッジすべてがアクティブになります。 その瞬間、三角形の数は 1 になります。 

| ステップ | アクティブエッジ | 三角形の数 |
 | --- | --- | --- |
 | 1 | なし | 0 |
 | 2 | 片端 | 0 |
 | 3 | 2つのエッジ | 0 |
 | 4 | 3つのエッジ | 1 |

 このトレースは、最小しきい値がまさに三角形の最大エッジであり、それより前のしきい値がサイクルを生成できないことを示しています。 

ここで、三角形が 1 つだけ存在する 4 つの点を考えます。 エッジが追加されると、三角形は特定のしきい値で表示され、その後のエッジでは最小サイクル サイズは変更されませんが、より多くのトリプルが完全に接続されると三角形の数が増加する可能性があります。 

| ステップ | 新しいエッジが追加されました | アクティブ構造 | 三角形の数 |
 | --- | --- | --- | --- |
 | 1 | 最初のエッジ | まばらな森 | 写真 0 |
 | 2 | 完成した三角形 | 三角形が形成されました | 1 |
 | 3 | 余分なエッジ | 変更されていない三角形 + エクストラ | ≥1 |

 これにより、三角形が一度存在すると、後で追加してもそれを無効にすることはできず、三角形がさらに作成される可能性があるだけであることが確認されます。

 ## 特殊なケース

 すべての点がほぼ同一線上にある構成では、非常に大きな距離が許容されるまで三角形は存在しません。 このような場合、アルゴリズムは三角形カウントをアクティブにすることはなく、出力はすべての出力にわたって正しく 0 になります。 

正確に 3 つのポイントを持つ構成は、それらの間のすべてのエッジが最初に完全にアクティブ化された直後に処理されます。 隣接交差により正確に 1 つの三角形が検出され、最終的なカウントはすべての巡回置換と開始点を考慮して 6 倍に正確に乗算されます。 

複数の重なり合う三角形を含むより密な構成は、各エッジ交差が意図した正規化を超えて重複することなく三角形の総数に寄与するため、アルゴリズムがすべての有効なトリプルを独立して累積することを示しています。
