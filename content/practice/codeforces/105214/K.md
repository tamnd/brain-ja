 ## 解決策
 ## 問題の理解

 私たちには、次のサイズの正方形の床が与えられています$n \times n$ここで、各セルは空のままにすることも、隣接する 2 つのセルを正確に占有するドミノ型のテーブルで覆うこともできます。 テーブルは、任意に選択された 2 つのセルだけではありません。 1 辺を共有する 1 対のセルを占有し、1 × 2 の長方形を形成する必要があります。 

主な制限は、個々のテーブルの配置に関するものではなく、テーブルがどのように相互に作用するかに関するものです。 2 つのテーブルが隣接するような接触は禁止されています。 2 つのセルは、角でしか接していない場合でも隣接しているとみなされます。したがって、ここでの隣接とは、8 方向の近傍 (対角線を含む) を意味します。 あるテーブルのセルが他のテーブルのセルに隣接している場合、そのテーブルは別のテーブルに隣接しているとみなされます。 

タスクは、そのようなテーブルの最大数を計算するだけではなく、この最大数を達成する有効な配置を明示的に構築することです。 

出力は$n \times n$グリッド。各セルには、テーブルによって占有されているか空のままかを示すシンボルがマークされています。 各テーブルはマークされた 2 つのセルを正確にカバーしており、構成では異なるテーブル間の非隣接ルールを尊重する必要があります。 

テスト ケースごとの制約は小さく、$n \le 100$そして合計$n^2$以下の範囲のテスト全体で$2 \cdot 10^5$。 これは、配置に関する検索や最適化ではなく、構築ベースのソリューションが期待されていることを強く示唆しています。 費用をかけるソリューション$O(n^2)$テスト ケースごとに行うのは安全ですが、マッチングやグローバル最適化を伴うものは不要であり、やりすぎです。 

素朴なアプローチの微妙な失敗例は、可能な限り貪欲にドミノを配置することから生じます。 たとえば、$2 \times 2$グリッドでは、水平方向のドミノを一番上の行に配置すると、別の構成では合計 2 つのドミノが許可される場合でも、対角方向の隣接性制約により残りの配置がすべてブロックされます。 対角線の競合を考慮しない貪欲な配置は、実現可能性を過大評価し、次善のレイアウトまたは無効なレイアウトを生成します。 

もう 1 つのよくある落とし穴は、隣接関係をエッジベースのみとして扱うことです。 斜めの隣接性を無視すると、大幅に多くのドミノを詰めることができますが、それらの構成の多くは、実際のルールの下では無効になります。 たとえば、チェッカー盤パターンで斜めに接触する 2 つのドミノは、エッジを共有しない場合でも不正です。 

## アプローチ

 ブルートフォース手法では、ドミノを 1 つずつ配置し、各ステップで可能なすべての配置をチェックし、隣接制約に違反していないことを確認します。 これは、隣接するセルのすべてのペアに対するバックトラッキング検索になり、各配置が一定サイズの近傍をブロックする可能性があります。 

適度な数のドミノでも配置する方法の数$n \times n$グリッドは指数関数的に増加します。 たとえ$n = 6$、各セルが水平または垂直配置の一部になるか空のままになる可能性があるため、状態空間が大きくなり、隣接制約により選択肢間に長距離結合が導入されます。 これにより、徹底的な検索が不可能になります。 

重要な観察は、隣接関係が非常に厳密であるため、使用されるすべてのセルが少なくとも 1 つの空の層によって他の使用されるすべてのセルから分離されるパターンを構築することで相互作用を完全に回避できるということです。 ジオメトリの観点から考えると、各ドミノは 2 セル セグメントを占有し、その周囲の 8 つの隣接内に他のドミノは許可されません。 これは、ドミノの影響領域が決して接触しないように、ドミノを空間的に分離する必要があることを示唆しています。 

これを強制するきれいな方法は、グリッドを繰り返しブロックに分割し、まばらな周期構造にドミノのみを配置することです。 最適な密度は、各テーブルが効果的に必要であることを認識することで得られます。$2 \times 2$その周囲の立ち入り禁止区域。 これにより、重なり合わない配置の問題が軽減されます。$2 \times 2$各ブロックがちょうど 1 つのドミノに貢献するブロック。 

それぞれの内側$2 \times 2$ブロック内にドミノを 1 つ水平に配置し、他の 2 つのセルを空のままにすることができます。 ブロックは両方向に少なくとも 1 つのセルによって分離されているため、ブロック間で隣接違反が発生することはありません。 これにより、シンプルかつ最適な構造が得られます。

 ## アルゴリズムのチュートリアル

 グリッドを次のように分割して構築します。$2 \times 2$ブロックごとに 1 つのドミノを正確に配置します。 

1. を初期化します。$n \times n$グリッドはドットで埋められています。つまり、最初はすべてのセルが空です。 これにより、制約に違反しないクリーンな基本状態が得られます。 
2. 行方向と列方向の両方でステップ サイズ 2 でグリッドを反復処理し、それぞれを処理します。$(i, j)$の左上隅として$2 \times 2$ブロック。 これにより、重なり合うことなく、互いに素な領域のグリッドをカバーできるようになります。 
3. このようなブロックごとに、マークを付けてブロックの一番上の行に水平ドミノを配置します。$(i, j)$そして$(i, j+1)$占領されている限り、提供される$j+1 < n$。 この選択はブロック内の有効な配置の中から任意に選択できますが、水平方向に配置するとパターンの一貫性が保たれます。 
4. ブロックの残りの 2 つのセルは空のままになります。 この間隔は、ブロック内であっても、意図したドミノを超えて余分な隣接関係が導入されないようにするため、非常に重要です。 
5. グリッドの最後に到達するまで、すべての有効なブロックに対してこのプロセスを繰り返します。 
6. 最後に、構築されたグリッドを行ごとに出力します。 

2 ずつ進める理由は、各ブロックが自己完結型であるためです。 1 ずつシフトしようとすると、ブロックが重なり、すぐに隣接制約に違反します。 

### なぜ効果があるのか

 各ドミノは内部で隔離されています。$2 \times 2$すべての領域は、少なくとも 1 行または 1 列の空のセルによって次の領域と区切られています。 これにより、異なるドミノの占有された 2 つのセルが両方の次元で少なくとも 2 ステップ離れていることが保証されます。これは、対角線であっても隣接できないことを意味します。 すべての配置はローカルで有効であり、2 つの配置が相互作用することはないため、グローバル設定は有効のままです。 この構造は、各ドミノに専用のドミノが必要であるという制約の下で密度を最大化します。$2 \times 2$安全地帯。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        grid = [['.' for _ in range(n)] for _ in range(n)]

        for i in range(0, n, 2):
            for j in range(0, n, 2):
                if i < n and j + 1 < n:
                    grid[i][j] = '#'
                    grid[i][j + 1] = '#'

        for row in grid:
            print(''.join(row))

if __name__ == "__main__":
    solve()
```この構築は、2 つのジャンプでグリッドをスキャンすることに依存しており、これにより、隣接するドミノ領域間の分離が強制されます。 唯一の微妙な境界条件は奇数の処理です$n$、最後の行または列は完全な領域を形成できません。$2 \times 2$ブロック。 このような場合、ループは境界チェックにより不完全なブロックを自然にスキップします。$j + 1 < n$、それらのセルは空のままにします。 

よくある実装上の間違いは、交互のブロックに垂直のドミノを配置しようとすることです。 有効ではありますが、不必要であり、偶発的な隣接エラーが発生するリスクが増加します。 均一な水平配置により、最適性に影響を与えることなく推論が簡素化されます。 

## 実用的な例

 検討してください$n = 2$。 

| 私 | j | アクション | グリッド |
 | --- | --- | --- | --- |
 | 0 | 0 | (0,0)-(0,1)の位置 | ## / .. |

 これにより、一番上の行を占める 1 つのドミノが生成されます。 一番下の行は同じ行の一部であるため空のままです。$2 \times 2$ブロックされ、隣接関係を侵害せずに別のドミノを安全にホストすることはできません。 

ここで考えてみましょう$n = 4$。 

(0,0)、(0,2)、(2,0)、(2,2) のブロックを処理します。 

| ブロック | 配置 | ブロック後のグリッドの状態 |
 | --- | --- | --- |
 | (0,0) | (0,0)-(0,1) | ##.. / .... / .... / .... |
 | (0,2) | (0,2)-(0,3) | #### / .... / .... / .... |
 | (2,0) | (2,0)-(2,1) | #### / .... / ##.. / .... |
 | (2,2) | (2,2)-(2,3) | #### / .... / #### / .... |

 各ブロックは独立して 1 つのドミノに貢献し、空のスペースがすべてのアクティブな領域を分離しているため、競合は発生しません。 

これらのトレースは、アルゴリズムが個々のドミノを配置するのではなく、独立したマクロセルをタイル状に並べるように動作することを示しています。これが隣接問題を回避する構造的な理由です。

 ## 特殊なケース

 のために$n = 1$、アルゴリズムは単一の空のセルを作成します。$2 \times 1$配置が可能です。 ループオーバー$j + 1 < n$はすぐに失敗するため、マークは付けられませんが、これは正しいです。 

奇数の場合$n$、 のような$n = 3$、最後の行と列がいっぱいになることはありません$2 \times 2$ブロック。 反復では引き続き有効なブロックのみが処理されます。$(0,0)$、未使用のセルのきれいな境界線が残ります。 空のセルが区切り文字として機能するため、隣接関係違反は発生しません。 

大型用$n$、 のような$n = 100$、パターンは均一に繰り返されます。 占有されているすべてのセルは、正確に 1 つのセルに属します$2 \times 2$すべてのブロックは独立しているため、サイズに関係なく全体的な不整合が発生することはありません。
