 ## 解決策
 ## 問題の理解

 オフィスは長方形のグリッドとして表されます。 すべての大文字は机の一部を表し、同じ文字を持つすべてのセルは同じ長方形の机に属します。 社長のデスクの色は次のように指定されます。`c`。 

代理とは、大統領のデスクの少なくとも 1 つのセルと同じ側のデスクを指します。 斜めの接触はカウントされません。 でマークされた空のセル`.`もカウントしません。 課題は、社長の机に隣接する異なる机の色が何色あるかを数えるということです。 

グリッドの寸法は最大でも`100 × 100`したがって、グリッド全体には最大でも次のものが含まれます。`10,000`細胞。 これは十分に小さいため、グリッド全体を数回スキャンしても完全に安全です。 たとえ`O(n * m * 4)`ソリューションは周囲でのみ実行されます`40,000`隣人のチェック。 

主な問題はパフォーマンスではなく、二重カウントを回避し、隣接関係を正しく処理することです。 

簡単な間違いの 1 つは、隣接する同じ色を複数回数えることです。 次のグリッドについて考えてみましょう。```
3 3 A
BBB
BAB
BBB
```正しい答えは、`1`、色だけなので`B`社長の机に触る。 隣接するものを見るたびに答えをインクリメントする不注意な実装`B`間違って出力されてしまう`4`。 

もう 1 つの微妙なケースは、空のセルを誤ってカウントしてしまうことです。```
2 3 A
.A.
...
```正しい答えは、`0`。 社長の机の周囲は何もない空間だけであり、それは数えるべきではありません。 

3 番目のよくあるバグは、大統領自身の色を副大統領として数えることです。 例えば：```
3 4 A
AAAA
ABBA
AAAA
```正しい答えは、`1`。 その間、`A`セルが他のセルに接触する`A`セル、それらは依然として大統領のデスクの一部であり、無視されなければなりません。 

境界の処理も重要です。 大統領の机がグリッドの端に触れると、隣人のチェックが範囲外になる可能性があります。```
2 2 A
AB
..
```正しい答えは、`1`。 座標を検証せずに 4 方向を盲目的にチェックする実装では、無効なインデックスにアクセスする危険があります。 

## アプローチ

 強引なアイデアは、グリッド内のすべてのセルを検査することです。 社長室を見つけるたびに、隣接する 4 つの席すべてを検査し、異なった机の色があれば記録します。 

このアプローチは、指定された制約に対してすでに十分に高速です。 グリッドには最大でも`10,000`各セルは最大 4 つの隣接チェックを実行します。 それは周りだけです`40,000`操作。 

残る唯一の問題は重複のカウントです。 多くの場所で、隣の机が社長の机に接触する可能性があります。 ここではリストを使用して繰り返し検索することもできますが、セットの方がクリーンであり、一意性が自動的に保証されます。 

重要な観察は、隣接するセルがいくつ存在するかは実際には気にしないということです。 私たちが気にするのは、大統領の机の横にいくつの異なる色が表示されるかだけです。 一度色が見られると、それ以上の色が現れても問題ありません。 

これにより、問題は、有効な隣接色を収集するセットを使用した単純なグリッドのトラバースに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 重複カウントによるブルート フォース | O(n × m × k) | O(k) | 不必要に乱雑 |
 | セットで最適 | O(n × m) | O(k) | 承認済み |

 ここ、`k`は、明確に隣接する色の数であり、最大で`26`。 

## アルゴリズムのチュートリアル

 1. グリッドの寸法と社長の机の色を読み取ります。 
2. 各セルに次のようにアクセスできるように、グリッドを文字列のリストとして保存します。`grid[row][col]`。 
3. という空のセットを作成します。`neighbors`。 

このセットには、社長のデスクに隣接するすべてのデスクの色が保存されます。 
4. グリッド内のすべてのセルを走査します。 

現在のセルに大統領の色が含まれている場合は、その隣の 4 つの位置を調べます。 
5. 4 方向のそれぞれについて、隣接する座標を計算します。 

方向は次のとおりです。`(1, 0)`、`(-1, 0)`、`(0, 1)`、`(0, -1)`。 
6. グリッドの外側にある近隣を無視します。 

これにより、大統領の机が境界線に触れたときに無効なインデックスが作成されるのを防ぎます。 
7. 隣の文字を読みます。 

次の場合:

 -`.`, 空のセルは机ではないので無視してください。 
- 社長の色と同じですが、同じ机なので無視してください。 
- それ以外の場合は、セットに挿入します。 
8. グリッド全体を処理した後、セットのサイズを出力します。 

### なぜ効果があるのか

 すべての副デスクは少なくとも 1 つの大統領細胞と側を共有しなければなりません。 このアルゴリズムは、すべての大統領セルの隣り合う 4 つのセルをすべてチェックするため、有効な副色がすべて検出されます。 

このセットでは、同じ机の多数のセルが大統領の机に触れた場合でも、各色が 1 回だけカウントされることが保証されます。 

空のセル、または大統領に属するセルは明示的に無視されるため、セットには明確な副デスクの色が正確に含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n, m, c = input().split()
n = int(n)
m = int(m)

grid = [input().strip() for _ in range(n)]

neighbors = set()

directions = [
    (1, 0),
    (-1, 0),
    (0, 1),
    (0, -1)
]

for i in range(n):
    for j in range(m):
        if grid[i][j] == c:
            for dx, dy in directions:
                ni = i + dx
                nj = j + dy

                if 0 <= ni < n and 0 <= nj < m:
                    ch = grid[ni][nj]

                    if ch != '.' and ch != c:
                        neighbors.add(ch)

print(len(neighbors))
```プログラムは寸法と社長の机の色を読み取ることから始まります。 最初の入力行には整数と文字の両方が含まれているため、値は最初に文字列として読み取られ、必要に応じて変換されます。 

グリッドは指定されたとおりに正確に保存されます。 文字列はインデックス付けをサポートしているため、`grid[i][j]`任意のセルに直接アクセスできます。 

の`neighbors`set はソリューションの中心的なアイデアです。 隣接するデスクの色は社長のデスクの周囲に何度も表示されますが、セットにより重複が自動的に削除されます。 

ネストされたループはグリッド全体をスキャンします。 大統領セルが見つかるたびに、コードは、`directions`配列。 これにより、コードの繰り返しが回避され、ロジックの検証が容易になります。 

境界チェックはグリッドにアクセスする前に行われます。 これらがないと、端のセルによってインデックス エラーが発生します。 

条件:```
if ch != '.' and ch != c:
```無効な近隣をフィルタリングします。 空のセルは無視され、大統領自身の机の色も無視されます。 

最後に、答えは単純に、セットに保存されている固有の色の数です。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    n, m, c = input().split()
    n = int(n)
    m = int(m)

    grid = [input().strip() for _ in range(n)]

    neighbors = set()

    directions = [
        (1, 0),
        (-1, 0),
        (0, 1),
        (0, -1)
    ]

    for i in range(n):
        for j in range(m):
            if grid[i][j] == c:
                for dx, dy in directions:
                    ni = i + dx
                    nj = j + dy

                    if 0 <= ni < n and 0 <= nj < m:
                        ch = grid[ni][nj]

                        if ch != '.' and ch != c:
                            neighbors.add(ch)

    print(len(neighbors))

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

# provided sample
assert run(
"""3 4 R
G.B.
.RR.
TTT.
"""
) == "3", "sample 1"

# minimum size
assert run(
"""1 1 A
A
"""
) == "0", "single cell"

# duplicate neighboring cells
assert run(

BBB
BAB
BBB
"""
) == "1", "duplicate colors counted once"

# ignore empty cells
assert run(
"""2 3 A
.A.
...
"""
) == "0", "empty cells ignored"

# president on boundary
assert run(
"""2 2 A
AB
..
"""
) == "1", "boundary handling"

# multiple different neighbors
assert run(

EEEEE
"""
) == "4", "multiple adjacent colors"

 ## 特殊なケース

 隣接する同じ机が複数の場所で大統領と接触している場合を考えてみましょう。```

BBB

.A.
...
```プレジデントセルは次のとおりです`(0,1)`。 その隣人は皆、`.`またはグリッドの外にあります。 条件:```
if ch != '.' and ch != c:
```すべての空のセルを拒否するため、セットは空のままとなり、アルゴリズムは次のように出力します。`0`。

AAAA
ABBA
AAAA
```多くの`A`セルが他のセルに隣接している`A`細胞。 近隣チェック中の状態`ch != c`大統領独自の色をセットに追加することを妨げます。 のみ`B`が挿入されているので、答えは`1`。
