 **確認済み:** はい

 ## 解決策
 ## 問題の理解

 板チョコが並んでいて、それぞれの板を食べるのにある程度の時間がかかります。 アリスは左端からスタートして右に進み続けます。 ボブは右端から開始して左に移動し続けます。 どちらも一時停止することなく継続的に食べており、誰もチョコレートを部分的に食べて途中で止めることはできません。 

興味深いのは、プロセスが順番ではなく時間によって決定されることです。 アリスがボブよりも早く現在のチョコレートを食べ終えた場合、彼女はすぐに彼女の側で次のチョコレートを開始します。 ボブにも同じことが起こります。 最終的に、2人のプレーヤーは中央で出会います。 二人がまったく同じ瞬間に同じチョコレートを食べ始めた場合、アリスはそのチョコレートを受け取り、ボブは止めます。 

入力は単純な配列で、各要素はチョコレートを 1 個食べるのに必要な時間を表します。 出力では、アリスが最後までに食べるチョコレートの数とボブが食べるチョコレートの数を尋ねます。 

制約が非常に大きいため、効率について慎重に検討する必要があります。 到達できるチョコレートの数$10^5$したがって、二次関数の解法は次のように実行されます。$10^{10}$最悪の場合、2 秒の実行時間の制限をはるかに超えて操作が可能になります。 ここでの自然な目標は線形時間です。 チョコレートを両端から順番に処理するだけでよいため、これは 2 点アプローチであることを強く示唆しています。 

誤った実装を密かに破壊する可能性のあるエッジケースがいくつかあります。 

1 つのチョコレートについて考えてみましょう。```
1
5
```正しい出力は次のとおりです。```
1 0
```アリスは左から開始し、ボブは右から開始しますが、どちらの位置も同じです。 アリスは絆が自分のものになったのでチョコレートを受け取ります。 不注意な実装により、誤って各プレイヤーに 1 つのチョコレートが与えられる可能性があります。 

もう 1 つの注意が必要なケースは、両方のプレイヤーが中央に到達する前に同じ食事時間を蓄積する場合です。```
3
2 2 2
```正しい出力は次のとおりです。```
2 1
```アリスは最初のチョコレートを 2 秒で食べ、ボブは最後のチョコレートを 2 秒で食べます。すると、両方が同時に真ん中のチョコレートを食べ始めます。 アリスはそれを受け取ります。 

一方の側がはるかに速く進むと、別のバグの原因が現れます。```
5
1 100 1 1 1
```正しい出力は次のとおりです。```
1 4
```アリスは大きなチョコレートに長い間引っかかりますが、ボブはすぐに右側からいくつかのチョコレートを食べます。 累積時間を比較する代わりにターンを交互に実行する実装は、ここで失敗します。 

## アプローチ

 直接シミュレーションを行うのが最初の自然なアイデアです。 アリスとボブの正確な現在時刻を追跡し、最初に終了したプレイヤーが先に進むことを想像できます。 各プレイヤーはチョコレートを 1 つずつ消費し、次に誰がフリーになるかを繰り返し決定します。 

プロセス自体は逐次的かつ決定的であるため、この総当りシミュレーションは実際には正しいです。 問題は、単純な実装では次のイベントを繰り返し検索したり、タイミングを不必要に再計算したりする可能性があることです。 時間単位ごとにシミュレーションすると、チョコレート時間の合計が次のような長さになる可能性があるため、実行時間は悲惨なものになります。$10^8$。 

重要な観察は、個々の秒をシミュレートする必要がないということです。 どの時点においても、重要な情報は、アリスがすでに費やした合計時間とボブがすでに費やした合計時間だけです。 

アリスが費やした合計時間がボブより少ないと仮定します。 つまり、アリスは早く終わって最初に自由になるので、左側にある次のチョコレートを取らなければなりません。 同様に、ボブが費やした合計時間が短い場合は、右側の次のチョコレートを受け取る必要があります。 

これにより、プロセス全体が非常にコンパクトな貪欲なプロシージャに変わります。 両方のプレーヤーの累積食事時間とともに、左から 1 つと右から 1 つの 2 つのポインターを維持します。 各ステップで、合計時間が短いプレイヤーが次に利用可能なチョコレートを受け取ります。 

問題の構造により、食べる順序は完了時間によって強制されるため、この貪欲な選択は安全になります。 誰もチョコレートをスキップしたり、意図的に待つことはできないため、次の行動は誰が最初に利用可能になるかによって一意に決定されます。

 ## アルゴリズムのチュートリアル

 1. 2 つのポインターを初期化します。 

-`left = 0`アリス側にとっても。 
-`right = n - 1`ボブの側にとって。 
2. 累積食事時間を維持する:

 -`alice_time = 0`-`bob_time = 0`3. 食べたチョコレートのカウンターを維持します。 

-`alice_count = 0`-`bob_count = 0`4. 続けながら`left <= right`。 

あらゆるステップで比較する`alice_time`そして`bob_time`。 
5. もし`alice_time <= bob_time`, アリスが最初に利用可能になるか、両方が同時に利用可能になります。 

アリスはインデックスでチョコレートを受け取ります`left`。 

食事時間を加えると、`alice_time`、増分`alice_count`、移動します`left`一歩右へ。 

同点はアリスに属するため、等しいケースは重要です。 
6. それ以外の場合は、ボブが最初に対応可能になります。 

ボブはインデックスでチョコレートを受け取ります`right`。 

食事時間を加えると、`bob_time`、増分`bob_count`、移動します`right`残り一歩。 
7. ポインタが交差すると、すべてのチョコレートが割り当てられます。 2 つのカウンターを出力します。 

### なぜ効果があるのか

 不変条件は、各ステップの前に、間隔外のすべてのチョコレートが存在することです。`[left, right]`すでに 1 人のプレイヤーに永続的に割り当てられており、`alice_time`そして`bob_time`各プレイヤーがこれまでに費やした正確な合計時間を表します。 

アリスの合計時間がボブよりも少ない場合、彼女は早く終了し、すぐに側で次に利用可能なチョコレートを開始しなければなりません。 ボブはまだ食べるのに忙しいので、最初にチョコレートに手が届きません。 同じ推論がボブにも対称的に当てはまります。 

両方の合計が等しい場合、両方のプレーヤーは同時にフリーになります。 このステートメントでは、アリスがその状況で共有チョコレートを受け取ると明示的に述べられており、まさにこれが条件で使用されている理由です。`<=`。 

すべてのステップが実際のプロセスと正確に一致するため、アルゴリズムは正しい最終カウントを生成します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
t = list(map(int, input().split()))

left = 0
right = n - 1

alice_time = 0
bob_time = 0

alice_count = 0
bob_count = 0

while left <= right:
    if alice_time <= bob_time:
        alice_time += t[left]
        alice_count += 1
        left += 1
    else:
        bob_time += t[right]
        bob_count += 1
        right -= 1

print(alice_count, bob_count)
```このソリューションは、貪欲なシミュレーションに直接従います。 

2 つのポインターは、残りの未請求のチョコレートを表します。 その間隔の外にあるものはすべてすでに食べられています。 

間の比較`alice_time`そして`bob_time`が核となるアイデアです。 アリスが費やした合計時間がそれ以下の場合は、次のプレイヤーがフリーになるはずなので、アリスは左側から次のチョコレートを受け取ります。 

等しい場合は微妙です。 使用する`<`の代わりに`<=`ボブに誤って同時にチョコレートを与えることになり、これは声明に違反します。 

ループ条件も重要です。 ながら続けます`left <= right`、だけではありません`<`。 チョコレートが 1 つだけ残っている場合でも、それは正しく割り当てられる必要があり、タイ ルールにより、多くの場合はアリスに割り当てられます。 

合計の食事時間は最大でも$10^8$。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n = int(input())
    t = list(map(int, input().split()))

    left = 0
    right = n - 1

    alice_time = 0
    bob_time = 0

    alice_count = 0
    bob_count = 0

    while left <= right:
        if alice_time <= bob_time:
            alice_time += t[left]
            alice_count += 1
            left += 1
        else:
            bob_time += t[right]
            bob_count += 1
            right -= 1

    print(alice_count, bob_count)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out

    solve()

    sys.stdout = sys.__stdout__
    return out.getvalue().strip()

# provided samples
assert run("5\n2 9 8 2 7\n") == "2 3", "sample 1"

# minimum size
assert run("1\n5\n") == "1 0", "single chocolate"

# all equal values
assert run("4\n3 3 3 3\n") == "2 2", "equal times"

# tie on middle chocolate
assert run("3\n2 2 2\n") == "2 1", "alice gets middle"

# strong imbalance
assert run("5\n1 100 1 1 1\n") == "1 4", "bob finishes many quickly"

# off-by-one boundary
assert run("2\n1 2\n") == "1 1", "two elements"

 ## 特殊なケース

 可能な最小の入力を考えてみましょう。```
1
5
```最初は両方の累積時間がゼロであるため、条件は`alice_time <= bob_time`それは本当です。 アリスが唯一のチョコレートを受け取ると、彼女のカウントは 1 になり、ポインターはすぐに交差します。 

最終的な出力は次のとおりです。```
1 0
```このケースでは、アルゴリズムが 1 つの残りのチョコレートを正しく処理し、タイ ルールを遵守していることが確認されます。 

次に、ミドルタイのシナリオを考えてみましょう。```
3
2 2 2
```最初の 2 つの移動の後:

 - アリスは 2 秒を費やしました。 
- ボブは 2 秒を費やしました。 
- 真ん中のチョコレートだけが残ります。 

アルゴリズムが使用しているため、`<=`, アリスは最後のチョコレートを受け取ります。 出力は次のようになります。```
2 1
```条件を次のように書いた場合`<`, ボブは間違って真ん中のチョコレートを受け取ります。 

最後に、1 人のプレイヤーが大量のチョコレートを急速に消費する場合を考えてみましょう。```
5
1 100 1 1 1
```段階的に:

 - アリスが食べる`1`、合計は1となります。 
- ボブは食べる`1`、合計は1となります。 
- アリスとボブが結ばれたので、アリスが開始します`100`。 
- アリスがまだ忙しい間に、ボブは残りの 3 つのチョコレートを食べます。 

出力は次のとおりです。```
1 4
```これにより、アルゴリズムが機械的にターンを交互に繰り返すのではなく、実際の経過時間を正しくモデル化していることが検証されます。
