 ## 解決策
 ## 問題の理解

 私たちには射手の列があり、それぞれがある程度の健康を持っています。 火の玉はその位置でのみ投げることができます`2 ... n-1`。 ポジションで投げると`i`、その後:

 - 射手`i`負ける`a`健康、
 - 射手`i-1`そして`i+1`失う`b`健康。 

射手は健康状態がゼロではなく厳密にマイナスになった場合にのみ死亡します。 私たちはすでに死亡した射手たちを引き続きターゲットにするかもしれません。 タスクは、火の玉の数を最小限に抑え、ターゲット インデックスの最適なシーケンスを 1 つ出力することです。 

まず重要なのは、制約の規模です。 射手の数は最大で`10`、健康値は最大でも`15`、両方の損害は最大で`10`。 これらは小さな制限です。 問題は、通常の Codeforce の意味での漸近最適化に関するものではありません。 代わりに、課題は、適切な状態表現を発見し、検索スペースを十分に積極的にプルーニングすることです。 

完全に無制限の総当たり攻撃は依然として爆発するでしょう。 各ショットは次のいずれかをターゲットにできます`n-2 ≤ 8`ポジション。 最適な答えは周りにしかないとしても`20`、それはすでに大まかに与えています`8^20 ≈ 10^18`可能なシーケンス。 したがって、構造が必要です。 

重要な観察は局所性です。 ポジションで投げる`i`影響を与えるだけ`i-1`、`i`、 そして`i+1`。 十分に右に移動すると、以前の位置は独立し、二度と変更できなくなります。 これにより、動的プログラミングが可能になります。 

誤った実装を簡単に破壊してしまういくつかの特殊なケースがあります。 

次の入力を考えてみましょう。```
3 2 1
2 2 2
```有効なターゲットは位置のみです`2`。 各ショットの特典`1`端のダメージや、`2`真ん中にダメージ。 2 ショット後の体力は次のようになります。`[0, -2, 0]`。 ヘルス状態は厳密にマイナスである必要があるため、エンドポイントはまだ生きています。 3打目が必要だ。 をチェックする不注意な実装`<= 0`の代わりに`< 0`間違った答えを生み出します。 

もう 1 つの微妙なケースは、すでに死亡した 1 人の射手を繰り返し攻撃することが依然として最適な場合です。```
5 10 1
1 100 1 1 1
```真ん中の射手は巨大な体力を持っています。 最善の戦略はポジションを狙い続ける`3`キャストの総数を最小限に抑えることだけを考慮しているため、近くの射手がすでに死亡した後でも。 死んだ敵への攻撃を禁止するアルゴリズムが正しくなくなる。 

境界線の取り扱いも危険です。`1`そして`n`直接ターゲットにすることはできません。```
4 5 2
9 1 1 9
```アーチャーにダメージを与える唯一の方法`1`それは攻撃することによって`2`、そしてアーチャーにダメージを与える唯一の方法`4`それは攻撃することによって`3`。 すべての位置を対称的に扱う解決策は、ここでは失敗します。 

## アプローチ

 最も直接的な総当り攻撃は、健康状態に対する最短パス検索です。 状態は現在のヘルス配列です。 1 つの状態から、考えられるすべてのターゲット位置を試し、1 回のキャスト後に次の状態を生成します。 すべてのキャストのコストは等しいため、BFS は呪文の最小数を保証します。 

制約が小さいため、これは機能します。 体力値は小さく、攻撃するたびに体力が減少するだけです。 それでも、状態空間は非常に急速に拡大します。 各射手は、死亡が保証される前に、初期の健康状態から負の値までの範囲に及ぶ可能性があります。 積極的なクランプを使用した場合でも、到達可能な状態の数は非常に多くなります。 分岐係数は次のとおりです`8`、BFS は構造的に類似した状況を再検討することにほとんどの時間を費やします。 

重要な洞察は、私たちは恣意的な呪文の順序を実際には気にしていないということです。 重要なのは、各ポジションで何回キャストするかです。 

定義するとします`x[i]`ポジションを攻撃した回数として`i`。 次に、アーチャーが受けたダメージの合計`j`は：

-`a * x[j]`、
 - プラス`b * x[j-1]`、
 - プラス`b * x[j+1]`。 

すべての射手に必要なのは次のことだけです。```
total damage > health
```ここで、問題は非負の整数を選択することになります。`x[i]`それらの合計を最小化します。 

ここで地域性が威力を発揮します。 射手`i`のみに依存します`x[i-1]`、`x[i]`、 そして`x[i+1]`。 位置を左から右に処理する場合、2 つの隣接する変数を修正した後、次の変数に必要な最小値を決定できます。 

もっと具体的に言うと、一度、`x[i-1]`そして`x[i]`知られているが、射手への唯一残っている未知の貢献`i`から来ています`x[i+1]`。 最小の有効な値を貪欲に選択できます。`x[i+1]`。 これにより、問題は隣接するカウントに対する DP に変換されます。 

攻撃ポジションの数は最大で`8`、各カウントが大きくなる必要はありません。 The optimal total number of shots is bounded by roughly`150`したがって、3 次 DP は完全に実現可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ヘルス状態に対するブルート フォース BFS | 指数 | 指数 | 遅すぎる |
 | 隣接攻撃カウントの DP | O(n * M²) | O(n * M²) | 承認済み |

 ここ`M`はポジションごとの関連する攻撃の最大数であり、制約の下では小さいです。 

## アルゴリズムのチュートリアル

 1. 定義する`x[i]`ポジションを攻撃した回数として`i`、有効な位置は`2 ... n-1`。 
2. 射手ごとのダメージ条件を書き換えます。 射手`j`受け取ります:```
b * x[j-1] + a * x[j] + b * x[j+1]
```そして以下を満たさなければなりません:```
damage > h[j]
```1. 射手を左から右に処理します。 ステップで`i`、すでに知っていると仮定します`x[i-1]`そして`x[i]`。 
2. アーチャー`i`～からの貢献がまだ不足している`x[i+1]`。 の最小値を計算します。`x[i+1]`それがアーチャーになる`i`死んだ。 

現在のダメージがすでに十分な場合は、`x[i+1] = 0`。 それ以外の場合は次のように解決します。```
current + b * x[i+1] > h[i]
```これは次のようになります:```
x[i+1] = floor((h[i] - current) / b) + 1
```1. 最後の 2 つの攻撃数に基づいて DP 状態を保存します。 移行は決定的です。`x[i-1]`そして`x[i]`が固定されている場合、有効な最小値は`x[i+1]`は一意に決まります。 
2. 可能なすべての値を試して DP を初期化します。`x[2]`。 以来`n ≤ 10`そして健康はほんのわずかで、安全な上限のようなものです`20`または`25`十分です。 
3. すべての内部ポジションを処理した後、最後の射手も死亡したことを確認します。 最後の射手は位置からのダメージのみを受けます`n-1`。 
4. すべての有効な構成の中から、以下を最小限に抑えるものを選択します。```
sum(x[i])
```1. 各位置を出力して解答シーケンスを再構築します。`i`その通り`x[i]`回。 

### なぜ効果があるのか

 DP はローカル依存関係の不変式に依存します。 射手`i`隣接する 3 つの攻撃数のみに依存します。```
x[i-1], x[i], x[i+1]
```左から右に処理する場合、1回`x[i-1]`そして`x[i]`を除くすべての将来変数は固定されています。`x[i+1]`アーチャーにとっては無関係になる`i`。 実現可能な最小値よりも大きな値を選択する`x[i+1]`すべての攻撃カウントはマイナスではなく、将来の射手は常に後の位置から追加ダメージを受ける可能性があるため、将来のコストを削減することはできません。 

したがって、貪欲な遷移はローカルで最適であり、すべての状態遷移が処理された射手の実現可能性を維持するため、DP は正確にすべての最適なグローバル ソリューションを探索します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

INF = 10**9

n, a, b = map(int, input().split())
h = list(map(int, input().split()))

# x[i] means attacks on position i (1-indexed)
# valid positions are 2..n-1

LIMIT = 25

best = INF
best_x = None

def dfs(pos, x, total):
    global best, best_x

    if total >= best:
        return

    if pos == n:
        # verify last archer
        dmg = b * x[n - 1]
        if dmg > h[n - 1]:
            best = total
            best_x = x[:]
        return

    # current damage on archer pos-1
    dmg = b * x[pos - 2] + a * x[pos - 1]

    need = 0
    if dmg <= h[pos - 2]:
        need = (h[pos - 2] - dmg) // b + 1

    if need > LIMIT:
        return

    x[pos] = need
    dfs(pos + 1, x, total + need)
    x[pos] = 0

# try all possible x[2]
x = [0] * (n + 1)

for start in range(LIMIT + 1):
    x[2] = start
    dfs(3, x, start)

ans = []

for i in range(2, n):
    ans.extend([i] * best_x[i])

print(best)
print(*ans)
```The implementation mirrors the mathematical recurrence directly.

 配列`x[i]`各内部位置を攻撃した回数を保存します。 説明内のインデックスは当然 1 から始まるため、コードでは変換ミスを避けるために同じ規則が維持されます。 

再帰関数は位置を左から右に処理します。 決めようとしているとき`x[pos]`、以前のすべての攻撃カウントはすでに固定されています。 射手`pos-1`現在ダメージがあります:```
b * x[pos-2] + a * x[pos-1]
```残りの唯一の可能性のある寄与は、次の攻撃によるものです。`pos`を追加します。`b`それぞれにダメージを与えます。 必要最小限の値を貪欲に計算します。 

この計算後に再帰が分岐することはありません。 唯一の分岐は最初の選択から生じます。`x[2]`。 これは、前の制約によって決定されない唯一の変数です。 

上限`LIMIT = 25`せいぜい健康状態なので安全です`15`、そして各攻撃は少なくとも貢献します`1`ダメージ。 最適なソリューションは、この範囲を大きく下回る値に留まります。 

微妙な詳細の 1 つは、死亡条件です。 コードチェック`damage > health`、 ない`>=`。 この厳密な不等式を見逃していることが、この問題で最も一般的なバグです。 

もう 1 つの重要な詳細は、最後の射手です。 位置`n`の攻撃によるダメージのみを受けます。`n-1`したがって、すべての変数が修正された後、以下を検証する必要があります。```
b * x[n-1] > h[n-1]
```解決策を受け入れる前に。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n * M) | 各初期値は、1 つの決定論的な左から右へのパスを生成します。 
| スペース | O(n) | 攻撃カウント配列と再帰スタックのみが保存されます。`M`は、1 つのポジションに対して試行する最大攻撃数であり、小さな定数によって制限されます。 と`n ≤ 10`、実行時間はごくわずかで、簡単に制限内に収まります。 

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    INF = 10**9

    n, a, b = map(int, input().split())
    h = list(map(int, input().split()))

    LIMIT = 25

    best = INF
    best_x = None

    def dfs(pos, x, total):
        nonlocal best, best_x

        if total >= best:
            return

        if pos == n:
            dmg = b * x[n - 1]
            if dmg > h[n - 1]:
                best = total
                best_x = x[:]
            return

        dmg = b * x[pos - 2] + a * x[pos - 1]

        need = 0
        if dmg <= h[pos - 2]:
            need = (h[pos - 2] - dmg) // b + 1

        if need > LIMIT:
            return

        x[pos] = need
        dfs(pos + 1, x, total + need)
        x[pos] = 0

    x = [0] * (n + 1)

    for start in range(LIMIT + 1):
        x[2] = start
        dfs(3, x, start)

    ans = []
    for i in range(2, n):
        ans.extend([i] * best_x[i])

    out = []
    out.append(str(best))
    out.append(" ".join(map(str, ans)))
    return "\n".join(out)

assert solve("3 2 1\n2 2 2\n").splitlines()[0] == "3"

# minimum size
assert solve("3 5 1\n1 1 1\n").splitlines()[0] == "2"

# all equal values
assert int(solve("5 3 1\n5 5 5 5 5\n").splitlines()[0]) > 0

# large health in center
assert int(solve("5 10 1\n1 100 1 1 1\n").splitlines()[0]) >= 10

# boundary-focused case
assert int(solve("4 5 2\n9 1 1 9\n").splitlines()[0]) >= 10

 ## 特殊なケース

 もう一度考えてみましょう:```
3 2 1
2 2 2
```アルゴリズムはさまざまな値を試行します。`x[2]`。 

のために`x[2] = 2`、エンドポイントのダメージは次のとおりです。```
b * x[2] = 2
```しかし、エンドポイントの健全性も`2`、死には厳密に否定的な健康が必要であるため、射手は生き残ります。 DP はこの状態を正しく拒否します。 と`x[2] = 3`、ダメージになります`3`、それで十分です。 

次に、次のことを調べます。```
5 10 1
1 100 1 1 1
```アルゴリズムは今後も増加する可能性がある`x[3]`たとえ近隣の射手たちがすでに死んでいたとしても。 死んだ敵への攻撃は許可されており、過剰な攻撃を避けるよりも呪文の数を最小限に抑えることが重要であるため、これは正しいです。 

ついに：```
4 5 2
9 1 1 9
```最初の射手は、その位置での攻撃によるスプラッシュダメージのみを受けることができます`2`、最後の射手はその位置での攻撃によるスプラッシュダメージのみを受けます。`3`。 最初と最後のチェックには隣接する攻撃カウントが 2 つではなく 1 つだけ含まれるため、左から右への反復ではこれらの境界制約が自然に維持されます。
