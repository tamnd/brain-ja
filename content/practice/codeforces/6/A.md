 ## 解決策
 ## 問題の理解

 スティックの長さは 4 つあり、そのうち 3 つを正確に選択する必要があります。 これら 3 つの長さの関係に応じて、3 つの結果が考えられます。 

選択したスティックが正の面積を持つ三角形を形成できる場合、印刷します。`TRIANGLE`。 幾何学的に、これは、2 つの小さい辺の合計が最大の辺よりも厳密に大きいことを意味します。 

適切な三角形が不可能な場合でも、スティックが直線上に配置できるかどうかを確認します。 これは、2 つの小さい辺の合計が最大の辺と正確に等しい場合に発生します。 その場合は印刷いたします`SEGMENT`。 

3 つのスティックのいずれを選択してもどちらの条件も不可能な場合は、次のように出力します。`IMPOSSIBLE`。 

入力サイズが小さいです。 数字は 4 つしかないので、テストする異なるトリプルはちょうど 4 つあります。 すべての組み合わせをチェックするブルートフォース ソリューションも即座に実行されます。 このような小さな制約がある場合、課題は最適化ではなく、ジオメトリ条件を正しく処理することです。 

最も一般的な間違いは、厳密な三角形不等式と非厳密な三角形不等式を混同することです。 適切な三角形には次のものが必要です。$$a + b > c$$三辺を並べ替えた後、$c$が一番大きいです。 

この問題ではセグメントと呼ばれる縮退三角形には、次のものが必要です。$$a + b = c$$使用する`>=`の代わりに`>`セグメントを誤って三角形として分類してしまう可能性があります。 

次の入力を考えてみましょう。```
1 2 3 10
```スティック`1 2 3`直線セグメントを形成するため、`1 + 2 = 3`。 正しい出力は次のとおりです。```
SEGMENT
```を使用した不注意な実装`>=`間違って印刷されてしまう`TRIANGLE`。 

Another easy mistake is stopping too early after checking only one triple. 例えば：```
1 1 2 3
```トリプル`1 1 2`ほんの一部ですが、`1 2 3`不可能です。 適切な三角形はどこにも存在しないため、正しい答えは依然として次のとおりです。```
SEGMENT
```決定する前に、考えられる 4 つのトリプルをすべて検討する必要があります。 

逆の状況もあります。```
4 2 1 3
```トリプル`1 2 3`ほんの一部ですが、`2 3 4`は有効な三角形を形成します。`2 + 3 > 4`。 正しい答えは次のとおりです。```
TRIANGLE
```すぐに出力する実装`SEGMENT`一つの堕落した症例を見た後でそれは間違っているだろう。 適切な三角形が常に優先されます。 

## アプローチ

 直接的な総当たりアプローチは、利用可能な 4 つのスティックから 3 つのスティックの各セットを生成することです。 このような組み合わせは 4 つしかないので、それぞれを個別にテストするだけです。 

すべてのトリプルについて、3 つの長さをソートします。 並べ替えが完了したら、2 つの小さい値の合計を最大の値と比較するだけで済みます。 

もし：$$a + b > c$$その場合、答えは次のとおりであることがすでにわかっています`TRIANGLE`適切な三角形は他のすべての結果よりも優先されるためです。 

代わりに等式が成り立つ場合:$$a + b = c$$その後、セグメントが可能であることを思い出しますが、後で実際の三角形が出現する場合に備えて、引き続き他のトリプルのチェックを続けます。 

操作の数が一定であるため、ブルートフォース ソリューションはすでに完全に受け入れられます。 それぞれに 3 種類の小さな数字が含まれる 4 つのトリプルだけをテストします。 

これを超える意味のある漸近最適化はありません。 重要な点は、入力サイズが固定されており、非常に小さいため、最もクリーンなソリューションが最適なソリューションでもあるということです。

 ## アルゴリズムのチュートリアル

 1. 4 つのスティックの長さを配列に読み取ります。 
2. 利用可能な 4 つのスティックから 3 つのスティックのあらゆる組み合わせを生成します。 スティックが 4 つしかないため、正確に 4 つのトリプルが生成されます。 
3. 各トリプルについて、3 つの長さを降順でない順に並べ替えます。 
4. ソートされた辺を次のようにします。`a`、`b`、 そして`c`、 どこ`c`一番大きな辺です。 
5. もし`a + b > c`、すぐに印刷`TRIANGLE`そしてやめてください。 有効な三角形の優先順位が最も高いため、それ以上のチェックは問題ありません。 
6. もし`a + b == c`、縮退三角形が存在することを思い出してください。 別のトリプルがまだ適切な三角形を形成している可能性があるため、まだ停止しないでください。 
7. すべてのトリプルをチェックした後、印刷します。`SEGMENT`少なくとも 1 つの縮退三角形が見つかった場合。 
8. それ以外の場合は印刷します`IMPOSSIBLE`。 

### なぜ効果があるのか

 各トリプルをソートすると、三角形の条件が最大の辺を含む 1 つの比較に減ります。 ソートされた 3 つの辺について`a ≤ b ≤ c`、三角不等式は次のことを確認するだけで済みます。`a + b`より大きい`c`。 

アルゴリズムは 3 つのスティックのあらゆる選択肢を検査するため、有効な構成を見逃すことはありません。 以来`TRIANGLE`よりも優先度が高い`SEGMENT`、適切な三角形を見つけたらすぐに戻るのが正しいです。 適切な三角形が存在しないが、少なくとも 1 つの等号が出現する場合、正しい分類は次のようになります。`SEGMENT`。 どちらの条件も発生しない場合は、いかなる種類の三角形も形成できません。 

## Python ソリューション```python
import sys
from itertools import combinations

input = sys.stdin.readline

sticks = list(map(int, input().split()))

segment = False

for triple in combinations(sticks, 3):
    a, b, c = sorted(triple)

    if a + b > c:
        print("TRIANGLE")
        sys.exit()

    if a + b == c:
        segment = True

if segment:
    print("SEGMENT")
else:
    print("IMPOSSIBLE")
```解決策は、4 つのスティックの長さを読み取ることから始まります。 可能な限り 3 本のスティックのグループが必要なので、`itertools.combinations`それらを生成する最もクリーンな方法です。 

各トリプルは、三角形の条件をチェックする前にソートされます。 比較は次の場合にのみ正しく機能するため、この手順は不可欠です。`c`一番大きな辺です。 並べ替えを忘れると、誤った結果が生じる可能性があります。 

最初の条件は、厳密な不等式を使用して適切な三角形をチェックします。 このようなトリプルが見つかった瞬間、プログラムは次のように出力します。`TRIANGLE`そしてすぐに出ます。 それ以降のトリプルは、より優先順位の高い回答を生成できません。 

2 番目の条件は等しいかどうかをチェックします。 すぐに印刷する代わりに、結果を`segment`フラグ。 これにより、後のトリプルが依然として適切な三角形を形成する可能性があるという以前の間違いが回避されます。 

最後に、三角形が見つからなかったが、少なくとも 1 つのセグメント構成が存在した場合、プログラムは次のように出力します。`SEGMENT`。 それ以外の場合の答えは、`IMPOSSIBLE`。 

数値は非常に小さいため、Python では整数のオーバーフローは不可能です。 実装の主な目的は、条件の順序を正しくすることです。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io
from itertools import combinations

def solve():
    input = sys.stdin.readline

    sticks = list(map(int, input().split()))

    segment = False

    for triple in combinations(sticks, 3):
        a, b, c = sorted(triple)

        if a + b > c:
            print("TRIANGLE")
            return

        if a + b == c:
            segment = True

    if segment:
        print("SEGMENT")
    else:
        print("IMPOSSIBLE")

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()

    backup_stdout = sys.stdout
    sys.stdout = out

    solve()

    sys.stdout = backup_stdout

    return out.getvalue().strip()

# provided sample
assert run("4 2 1 3\n") == "TRIANGLE", "sample 1"

# custom cases
assert run("1 2 3 10\n") == "SEGMENT", "degenerate triangle exists"
assert run("1 1 3 5\n") == "IMPOSSIBLE", "no valid combination"
assert run("5 5 5 5\n") == "TRIANGLE", "all equal sticks"
assert run("100 1 1 2\n") == "SEGMENT", "boundary equality case"
assert run("2 3 4 9\n") == "TRIANGLE", "one valid triple among failures"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 2 3 10`|`SEGMENT`| 等価性を三角形として数えてはなりません |
 |`1 1 3 5`|`IMPOSSIBLE`| どのトリプルも条件を満たすものはありません |
 |`5 5 5 5`|`TRIANGLE`| 等しい辺を持つ適切な三角形 |
 |`100 1 1 2`|`SEGMENT`| 1 つの縮退ケースによる大きな不均衡 |
