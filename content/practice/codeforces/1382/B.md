 ## 解決策

 ## 問題の理解

 ゲームは一連の山でプレイされます。 各移動では、石がまだ含まれている左端の山のみが重要であり、プレイヤーはその山から正の数の石を取り除くことができます。 山が空になると、同じように次の山でプレイが続行されます。 プレイヤーは交互に手番を行い、すべての山が空になって動けなくなったプレイヤーが負けとなります。 

これは複数の独立した杭のように見えますが、一番左の制限により、杭が次々と枯渇する単一の進化するシーケンスに変わります。枯渇するたびに、その山の中で費やされた手の数に応じて、戦略的状況が「反転」する場合とそうでない場合があります。 

入力は複数の独立したゲームで構成されます。 ゲームごとに、最初のプレイヤーが最適なプレイで強制的に勝利するかどうかを判断する必要があります。 

この制約により、すべてのテスト ケース全体で最大 10 万個の合計パイルが許可されます。 これにより、各石、さらには各動きを個別に処理するシミュレーションは即座に除外されます。 二次推論または移動ごとの推論では制限を数桁超えてしまうため、どのソリューションでも各テスト ケースを線形時間でスキャンする必要があります。 

すべての山にちょうど 1 つの石が含まれている場合、微妙な特殊なケースが発生します。 その状況では、すべての動きが完全に山を空にするため、ゲームは山をまたぐ単純な交互に縮小されます。 たとえば、`[1, 1, 1]`、最初のプレイヤーが勝ちですが、`[1, 1, 1, 1]`、2番目のプレイヤーが勝ちます。 素朴な直観は石の合計の平等に誤って注目するかもしれませんが、それはゲームを支配するものではありません。 

もう 1 つの重要なエッジ ケースは、シーケンスの早い段階で 1 を超える山が存在する場合に発生します。 たとえば、`[2, 5, 4]`、最初のプレーヤーは、最初の山を減らす方法を制御することですぐに勝ちます。 ただし、最初の大きな山が後で現れた場合は、次のようになります。`[1, 1, 2, ...]`、パリティは値だけではなく位置に応じて変化します。 

これら 2 つの動作、「すべて 1」と「最初の 1 ではない山」は、重要な構造的なケースのみです。 

## アプローチ

 ブルートフォースアプローチでは、ゲームの動きを一手ごとにシミュレートします。 現在のパイル インデックスを維持し、すべてのパイルが空になるまでプレイヤーを交代しながら、それから繰り返し減算します。 最悪の場合、山には最大 10 億個の石が含まれる可能性があり、これは 1 つのテスト ケースに最大 10 億個の石が必要になる可能性があることを意味します。$10^9$実行可能な限界をはるかに超えた操作。 杭の移行のみをシミュレートしたとしても、移動ごとに杭ごとに線形作業が発生するリスクがあり、これは不必要です。 

重要な観察は、山の中にある石の正確な数は、それが 1 に等しいか 1 より大きいか以外には重要ではないということです。 パイルのサイズがちょうど 1 の場合、そのパイルは強制されます。プレイする人がそのパイルを削除し、すぐに制御を次のパイルに渡します。 パイルのサイズが 1 より大きい場合、プレイヤーが初めてそのパイルに到達したときに、そのプレイヤーはサイズ 1 になるまでに発生する内部移動の回数を制御し、その境界で「ターン パリティ」が反転するかどうかを効果的に決定できます。 

これにより、ゲーム全体が 1 に等しくない最初の山を見つける作業に短縮されます。 すべての山が 1 つである場合、結果はそのような強制的な動きが何回存在するかによってのみ決まります。 それ以外の場合は、最初の非 1 パイルの位置によって、最初のプレイヤーがコントロールを維持できるか失うかが決まります。 

したがって、問題をテスト ケースごとに 1 回のリニア スキャンに縮小します。

 ## アルゴリズムのチュートリアル

 1. 各山に石が 1 つだけあるかどうかを確認しながら、山を左から右にスキャンします。 これにより、決定が存在しない強制移動セグメントにまだいるかどうかが識別されます。 
2. サイズが 1 より大きい最初の山で停止します。 この位置は、プレイヤーがゲームが単一の山に留まる時間を制御できる最初のポイントであるため、非常に重要です。 
3. このような山がインデックス i に存在する場合、i が奇数か偶数かに基づいて勝者を決定します。 i が奇数の場合、有利なターン パリティで最初の制御可能なパイルに到達した最初のプレーヤーが勝ちます。 i が偶数の場合、2 番目のプレーヤーがそのアドバンテージを継承します。 
4. そのような山が存在しない場合、つまりすべての山に石が 1 つだけある場合は、n に基づいて勝者を計算します。 n が奇数の場合は、最初のプレーヤーが最後の動きを行って勝ちます。 n が偶数の場合、2 番目のプレーヤーが最後の手を打って勝ちます。 

パリティだけで十分である理由は、すべてのサイズの山がちょうど 1 つの動きを消費し、プレイヤーを反転させるためです。 制御可能なセグメントを導入することで、サイズが 1 より大きい最初の山だけがこの強制交代を打ち破ることができ、その位置によってパリティ アドバンテージが最初のプレーヤーに残るか、それともシフトするかが決まります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        idx = -1
        for i, v in enumerate(a):
            if v > 1:
                idx = i
                break
        
        if idx == -1:
            out.append("First" if n % 2 == 1 else "Second")
        else:
            out.append("First" if idx % 2 == 0 else "Second")
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは各テスト ケースを読み取り、配列に対して 1 回のパスを実行します。 ループは、1 に等しくない最初のパイルを検索し、そのインデックスを保存します。 何も存在しない場合、決定は杭の数が奇数かどうかのみに依存します。 それ以外の場合は、インデックス パリティによって勝者が決まります。 

重要な実装の詳細は、ゼロベースのインデックス付けです。 この推論では概念的に 1 から始まる位置を使用するため、コードは調整なしで 0 から始まるインデックスに偶数または奇数のチェックを直接適用します。

 ## 特殊なケース

 すべての山にちょうど 1 つの石が含まれている場合、ゲームは山全体で厳密に交互に手を動かすことになります。 入力用`[1, 1, 1, 1]`の場合、アルゴリズムは 1 より大きい山を検出しないため、パリティ 4 のチェックに戻り、正しく Second を返します。 一連の強制的な動きにより、2 番目のプレーヤーが最後の動きを行うことが保証されます。 

最初の山そのものが 1 より大きい場合、次のようになります。`[7, 1, 1]`の場合、スキャンはインデックス 0 で停止します。インデックス 0 は偶数であるため、アルゴリズムは First を返します。 この場合、決定点の前に強制的なシングルストーンチェーンがないため、最初のプレーヤーがパリティのコントロールを失うことはありません。 

後から1つではない山が出現した場合、`[1, 1, 1, 5, 1]`、スキャンはインデックス 3 で停止します。ゼロベースのインデックス付けでは 3 が奇数であるため、アルゴリズムは First を返します。これは、2 番目のプレーヤーが最初の制御可能なパイルに到達し、それらに対してパリティ シフトが行われることを意味します。
