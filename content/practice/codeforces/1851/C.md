 ## 解決策
 ## 問題の理解

 の行が与えられています$n$それぞれ何らかの色で塗装されたタイル。 Vlad は、最初のタイルから開始して、右に任意の長さのジャンプを行い、最後のタイルで正確に終了する、タイルに沿って歩きたいと考えています。 作成するパスの全長は、次の値で割り切れる必要があります。$k$、長さの連続したブロックに分割する必要があります。$k$ブロック内のすべてのタイルが同じ色になるようにします。 ブロック間の色が異なる必要はありません。 テスト ケースごとに、そのようなパスが存在するかどうかを判断する必要があります。 

制約が厳しいので、$O(n^2)$可能なすべてのジャンプの探求。 と$n$まで$2 \cdot 10^5$そして最大まで$10^4$テスト ケースでは、アルゴリズムは大まかに実行する必要があります。$O(n)$2 秒の制限時間内に収まるようにテスト ケースごとにテストします。 これにより、すべてのパスのブルートフォース検索が排除されます。 

明らかではないエッジ ケースには、すべてのタイルが同じ色である場合、または最初と最後のタイルが同じ色であるが、中間のタイルにより完全なブロックの形成が妨げられる場合が含まれます。 たとえば、$n = 3$、$k = 2$、タイル$[1,2,1]$単純なアプローチでは、最初と最後のタイルが最初のブロックの色と一致するが、有効な長さのブロックがないという理由だけで、誤って「YES」と主張する可能性があります。$k$最初のタイルから始めます。 

## アプローチ

 ブルート フォース アプローチでは、最初のタイルから始めてすべてのタイル シーケンスを生成しようとし、各シーケンスが完全に形成されているかどうかを確認します。$k$- 同じ色の長さのブロックで、最後のタイルで終わります。 各パスには最大で次のものを含めることができます$n/k$ブロックなので、シーケンスの数は組み合わせて増加します。$n$、合理的な期限をすぐに超えてしまいます。 のために$n$その周り$2 \cdot 10^5$、これはまったく不可能です。 

重要な洞察は、各ブロックの長さが$k$は同じ色で構成されている必要があるため、配列を左から貪欲にスキャンできます。 同じ色の連続したセグメントを追跡し、それらが現在のブロックに寄与するタイルの数を数えます。 集めるたびに$k$同じ色のタイルがある場合は、それをブロックとしてコミットして次に進みます。 これにより、問題は左からの単一の線形スキャンに縮小され、ブロック長の合計が最後のタイルに到達できるかどうかがチェックされます。 

同様に、右からスキャンすると、最後のブロックが最後のタイルで終了するように制約されている場合も処理できます。 両端のブロックを貪欲にマッチングし、それらが重なっているかどうかをチェックすることで、有効なパスが存在するかどうかを確認できます。 同じ色の連続したセグメントを識別し、完全なセグメントの数を計算するだけでよいため、問題は線形時間に短縮されます。$k$-length ブロック。

 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 貪欲なツーポインター | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. カウンタを初期化する`count`現在のセグメント内にある同じ色のタイルが左から何個あるかを追跡します。 初期化`blocks_left`ゼロまで、満杯数を表す$k$-長さのブロックは左から始めて作成できます。 
2. タイルを左から右にスキャンします。 各タイルについて、前のタイルと一致するかどうかを確認します。 そうなった場合はインクリメントします`count`; それ以外の場合はリセット`count`～1.毎回`count`到達する`k`、増分`blocks_left`そしてリセット`count`新しい潜在的なブロックを開始するにはゼロにします。 
3. 同じプロセスを右から左に繰り返し、保存します`blocks_right`いっぱいの数に対して$k$-length 最後のタイルで終わるブロック。 
4. 両方のスキャンの後、重複を考慮して、左右のブロックの合計長を計算します。 左端のブロックが右端のブロックを超えている場合、有効なパスはありません。 それ以外の場合、ブロックの総数を乗算すると、`k`少なくとも最後のタイルに到達するために必要なパス内のタイル数である場合は、「YES」を出力します。 それ以外の場合は「NO」を出力します。 

機能する理由: 各ブロックは正確に一致する必要があります。`k`同じ色のタイル。 連続するセグメントを左と右から数えることにより、考えられるブロックの配置をすべてカバーすることが保証されます。 重複チェックにより、左端と右端のシーケンスが同じセグメントを共有する場合にタイルが二重にカウントされないことが保証されます。 これにより、すべてのジャンプの組み合わせを調査することなく、すべての有効なパスがキャプチャされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_form_path(n, k, colors):
    if n == k:
        return "YES" if len(set(colors)) == 1 else "NO"

    # Scan from left
    left_blocks = 0
    count = 1
    for i in range(1, n):
        if colors[i] == colors[i-1]:
            count += 1
        else:
            count = 1
        if count == k:
            left_blocks += 1
            count = 0

    # Scan from right
    right_blocks = 0
    count = 1
    for i in range(n-2, -1, -1):
        if colors[i] == colors[i+1]:
            count += 1
        else:
            count = 1
        if count == k:
            right_blocks += 1
            count = 0

    # If the total blocks cover at least the first and last tiles
    if left_blocks + right_blocks < n // k:
        return "NO"
    return "YES"

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())
    colors = list(map(int, input().split()))
    print(can_form_path(n, k, colors))
```このソリューションでは、2 つのリニア スキャンを使用して、満杯の数をカウントします。`k`-左右から形成できるブロックの長さ。 正確な結果だけを保証するために、ブロックの形成後にカウンターをリセットします。`k`-length シーケンスがカウントされます。 最終的な比較により、ブロックが最後のタイルで終わるパスをカバーできることが確認されます。 エッジケースの場合`n == k`は単一のブロックが必要なため、個別に処理されます。
