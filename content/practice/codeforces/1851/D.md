 ## 解決策
 ## 問題の理解

 1 から 1 までの数値の順列の接頭辞の合計から派生した配列が与えられます。$n$。 これらのプレフィックス合計の 1 つが欠落しています。 私たちの仕事は、不完全な配列が有効な順列から得られたものであるかどうかを判断することです。 

ここでの順列は、1 から 2 までの各整数を含む単純な配列です。$n$まさに一度。 プレフィックス合計配列は、要素を累積的に合計することによって形成されます。$b_i = a_1 + a_2 + ... + a_i$。 たとえば、順列$[1, 3, 2]$プレフィックス合計があります$[1, 4, 6]$。 接頭辞の合計 (たとえば 4) を削除すると、配列は次のようになります。$[1, 6]$。 問題は、単一のプレフィックス合計を削除した後に、指定された配列につながる置換が存在するかどうかを判断することです。 

制約により、私たちは次のことを可能にします。$2 \cdot 10^5$すべてのテスト ケースの数値を合計したものであるため、どのソリューションも大まかに実行する必要があります。$O(n)$テストケースごとに。 すべての順列をブルートフォースで再構築することは完全に不可能です。$n!$非常に早く成長します。 

欠落している要素が順列の最大の数である場合、微妙なエッジ ケースが発生します。 たとえば、次の場合$n = 4$入力プレフィックスの合計は次のようになります。$[1, 3, 6]$、欠落している合計は最後の要素 4 に対応しており、この状況を認識する必要があります。 もう 1 つの注意が必要なケースは、プレフィックスの合計を削除すると、繰り返される可能性のある数値が非表示になる場合です。$[1, 3, 3]$不可能に見えますが、欠落している 2 に対応する可能性があります。$[1, 3, 5, 6]$。 連続するプレフィックスの合計間の差異のみをチェックする不注意なアプローチは、ここで失敗する可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、すべての可能な位置に 1 つの数値を挿入し、結果の配列が有効な順列を形成するかどうかを確認することによって、指定されたプレフィックスの合計から可能なすべての元の配列を再構築しようとします。 これは、各プレフィックスの合計が累積合計を一意に定義するため、原理的には正しいですが、可能性の数は次のとおりです。$O(n)$テストケースごとの挿入数と$O(n)$置換を検証するために挿入ごとに作業が行われ、その結果、$O(n^2)$。 が遅すぎるでしょう。$n \approx 2 \cdot 10^5$。 

重要な洞察は、欠落している要素が 1 から 1 までの単一の数値のいずれかに対応しているということです。$n$または最後のプレフィックスの合計そのものに。 これにより、問題は、順列内の元の数値 (欠落した数値を除く) を表す、連続するプレフィックスの合計間の差異を分析することになります。 具体的には、差分が 1 から 1 までのほぼすべての数値であるマルチセットを形成している場合、$n$の場合、不足している数値は、合計の差が大きすぎるか、数値のいずれかです。$n$自体。 

したがって、より高速なアプローチは、連続するプレフィックスの合計の差を計算して候補番号を取得し、各番号が出現する回数を数え、1 つの番号が欠落しているか、または欠落しているプレフィックスを説明できる方法で 1 つの番号が重複していることを確認することです。 これにより、解決策は次のように簡略化されます。$O(n)$テスト ケースごとに、制約の下で実行可能です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、連続するプレフィックスの合計の差を計算します。 プレフィックス合計配列の最初の要素は、元の順列の最初の要素と等しいため、差分として含めます。 これらの違いを というリストに保存します。`nums`。 
2. 1 から 1 までの数値の合計を計算します。$n$公式を使って$n(n+1)/2$。 
3. の合計を比較します。`nums`この合計額に。 それらが一致する場合、すべての数値が存在し、欠落しているプレフィックスの合計が最後の要素に対応します。 この場合、配列は有効な順列を形成します。 
4. の合計が`nums`合計より小さい場合は、不足している数値を差として計算します。 内の各数値の出現を数えます。`nums`。 この欠落している数値がちょうど 0 回発生し、他のすべての数値が 1 から 1 までの範囲内にある場合、$n$の場合、欠落している数字を正しい位置に挿入することで並べ替えが可能になります。 
5. 数値が 2 回出現するか、数値が 1 から外の場合は、$n$、答えは「NO」です。 それ以外の場合、答えは「YES」です。 
6. 各テスト ケースの結果を返します。 

**機能する理由**: 連続するプレフィックスの合計の差は、欠落しているものを除いて、元の順列の要素とまったく同じです。 これらの差の合計と頻度をチェックすることで、1 から 2 までの完全な順列を復元する単一の数が存在するかどうかを推測できます。$n$。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        b = list(map(int, input().split()))
        total = n * (n + 1) // 2
        nums = [b[0]] + [b[i] - b[i - 1] for i in range(1, n - 1)]
        current_sum = sum(nums)
        
        if current_sum == total:
            print("YES")
            continue
        
        diff = total - current_sum
        count = {}
        valid = True
        for x in nums:
            if x < 1 or x > n:
                valid = False
                break
            count[x] = count.get(x, 0) + 1
            if count[x] > 1:
                valid = False
                break
        if not valid:
            print("NO")
        elif diff >= 1 and diff <= n and count.get(diff, 0) == 0:
            print("YES")
        else:
            print("NO")

solve()
```この実装は、複数のテスト ケースの入力を効率的に読み取り、差分を計算し、合計と頻度をチェックして、有効な置換が可能かどうかを検証します。 最初の要素を個別に処理すると、最初の要素が正しく再構築されます。これは、オフバイワン エラーの一般的な原因です。
