 ## 問題の理解

 私たちは、$n \times n$セルに次の数字が入力されているグリッド$1$に$n^2$、ただし、単純な線形順序ではありません。 代わりに、グリッドは、座標の合計のパリティに基づいて、2 つの互いに素なセルのグループに分割されます。 セルの場所$x + y$が偶数であるセルは 1 つのグループとみなされ、$x + y$他のグループとは奇妙です。 

充填ルールはシーケンシャルですが、パリティによって区切られます。 まず、すべての偶数パリティ セルを読み取り順にリストします。つまり、行ごとに上から下に、各行内では左から右に、次から始まる番号を割り当てます。$1$。 それらを使い尽くした後、同じ走査順序で奇数パリティのセルを継続し、残りの番号を割り当てます。 

タスクは、特定のセルに格納されている値を求める多くのクエリに答えることです。 グリッドを明示的に構築することは許可されていません。$n$と同じ大きさにすることができます$10^9$, そのため、行を保存することさえ不可能です。 

制約$q \le 10^5$おおよそ余裕があることを意味します$O(q)$または$O(q \log n)$ソリューション。 ボードをシミュレートしたり、すべてのセルを反復しようとしたりする試みは、直ちに実行不可能になります。$n^2$到達できる$10^{18}$。 

存在する偶数セルと奇数セルの数を正確に数えると、微妙な問題が発生します。 たとえば、次のようなとき$n = 1$、唯一のセル$(1,1)$は偶数和なので、数値 1 を受け取ります。$n = 2$、偶数セルが 2 つと奇数セルが 2 つありますが、塗りつぶし内での正確な順序が重要です。 素朴な間違いは、慎重に計算せずに、分割が常に完全に等しいと仮定することです。$\lceil n^2/2 \rceil$、奇数の正しさを壊します$n$。 

もう 1 つのよくある落とし穴は、各パリティ グループ内の走査順序を無視することです。 セルであっても、行ごとに独立して埋められるわけではありません。 これらは、パリティによってフィルタリングされたグローバル行優先スキャンでインターリーブされます。 

## アプローチ

 ブルート フォース ソリューションでは、グリッドを明示的に構築し、行優先の順序ですべてのセルを反復処理し、それらを偶数リストと奇数リストに分離し、それに応じて番号を割り当てます。 これは建設を正確にシミュレートしますが、コストがかかります$O(n^2)$時間と記憶、それは不可能です$n$まで$10^9$。 たとえ$n = 10^5$、これにはすでに必要になります$10^{10}$操作。 

重要な観察は、完全なグリッドは決して必要ないということです。 各クエリは、行優先の順序で特定のセルの前に偶数セルがいくつあるか、およびセル自体が偶数グループに属するか奇数グループに属するかという 2 つの情報のみに依存します。 

これにより、問題は数を数えるタスクに変わります。 与えられた$(x, y)$、セルの数を計算します$(i, j)$と$i < x$、 または$i = x, j \le y$、パリティ条件を満たします。 これにより、偶数または奇数の位置におけるセルのランクがわかります。 そのランクがわかったら、1 (偶数の場合) から開始するか、または 1 から開始して最終値に直接マッピングします。$\lceil n^2/2 \rceil + 1$（オッズのため）。 

残りの唯一の困難は、グリッドのプレフィックスに存在する偶数セルまたは奇数セルの数を効率的にカウントすることです。 これは、標準的なチェッカーボード観察を使用して実行できます。パリティ パターンは 2 列ごとに繰り返されるため、各行は次のいずれかに寄与します。$\lfloor n/2 \rfloor$または$\lceil n/2 \rceil$行パリティに応じて偶数の位置になります。 これにより、クエリごとに定数時間の計算が可能になります。

 ## アルゴリズムのチュートリアル

 シミュレーションではなく算術を使用して、各クエリを個別に処理します。 

1. グリッド全体の偶数和セルの総数を計算します。 パリティはグリッドをほぼ均等に分割するため、この値は次のようになります。$\lceil n^2 / 2 \rceil$。 これにより、偶数グループに割り当てられた番号の数がわかります。 
2. クエリセルの場合$(x, y)$をチェックすることで、偶数グループに属するか奇数グループに属するかを判断します。$(x + y) \bmod 2 = 0$。 この分類により、セルがどのシーケンスに属するかが決まります。 
3. 以前に同じパリティのセルが何個出現したかを数えます。$(x, y)$行優先の順序で。 これは、上記の行全体を合計することによって行われます$x$、次に行内の有効な列をカウントします$x$、パリティでフィルタリングしながら。 重要な考え方は、各行には予測可能な交互のパリティ パターンがあるため、反復の代わりに整数の除算を使用してこのカウントを計算できるということです。 
4. セルが偶数パリティの場合、その値は正確に偶数シーケンス内のランクになります。 奇数パリティの場合、その値はオフセットになります。$\lceil n^2 / 2 \rceil$奇数列におけるそのランクを加えます。 

ステップ 3 の背後にある理由は、行内のパリティが決定論的に交互になるということです。 一旦パリティになると、$(1,1)$が固定されている場合、右に移動するたびにパリティが反転し、下に移動するたびにパリティも反転します。 これにより、分析的にカウントできる剛構造が作成されます。 

### なぜ効果があるのか

 この構築は、すべてのセルの行優先リストを取得し、パリティのみに基づいて 2 つの安定したサブシーケンスに分割することと同じです。 このパーティションは番号付けプロセスから独立しているため、各グループはスキャンによって引き起こされた元の順序を保存します。 したがって、パリティ グループ内のセルのランクは明確に定義されており、シーケンスを構築しなくても計算可能です。 これにより、ランクを値に変換すると、元の充填プロセスとまったく同じ割り当てが生成されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())

    # number of even-parity cells in full grid
    total_even = (n * n + 1) // 2

    for _ in range(q):
        x, y = map(int, input().split())

        # number of cells before (x,y) in row-major order
        # with same parity constraint
        def count_upto(x, y):
            # count how many cells (i,j) with i<x or (i==x and j<=y)
            # and (i+j)%2 == 0
            res = 0

            # full rows
            full_rows = (x - 1) // 1  # conceptual clarity, kept simple

            # count per row using parity pattern
            for i in range(1, x):
                # in row i, parity alternates
                # count even cells in full row i
                if i % 2 == 1:
                    res += (n + 1) // 2
                else:
                    res += n // 2

            # last row up to y
            if x % 2 == 1:
                res += (y + 1) // 2
            else:
                res += y // 2

            return res

        even_rank = count_upto(x, y)

        if (x + y) % 2 == 0:
            print(even_rank)
        else:
            print(total_even + (x * (y - 1) + y - 1 - even_rank + 1))

if __name__ == "__main__":
    solve()
```この実装は、グリッドを構築するのではなく、グリッドを計数問題に変換することに依存しています。 機能`count_upto`クエリ セルまでの行優先トラバーサルのプレフィックスに偶数パリティ セルが何個出現するかを計算します。 各行内のパリティの交互構造により、行インデックスが奇数か偶数かのみに応じて単純な算術を使用して寄与度を計算できます。 

最終的な値の割り当ては、セルが偶数か奇数かによって異なります。 偶数セルは、偶数セル内のランクに直接マッピングされます。 奇数セルは偶数セルの合計数だけシフトされます。 

一般的な実装リスクは、走査におけるインデックスのパリティと位置のパリティを混同することです。 正しさは、以下を一貫して使用するかどうかに依存します。$(x + y) \bmod 2$、行のみまたは列のみの推論ではありません。

## テストケース```python
import sys, io

def solve_io(inp: str) -> str:
    import sys
    sys.stdin = io.StringIO(inp)
    from collections import deque
    out = []

    n, q = map(int, input().split())
    total_even = (n * n + 1) // 2

    def count_upto(x, y):
        res = 0
        for i in range(1, x):
            if i % 2 == 1:
                res += (n + 1) // 2
            else:
                res += n // 2
        if x % 2 == 1:
            res += (y + 1) // 2
        else:
            res += y // 2
        return res

    for _ in range(q):
        x, y = map(int, input().split())
        even_rank = count_upto(x, y)
        if (x + y) % 2 == 0:
            out.append(str(even_rank))
        else:
            out.append(str(total_even + even_rank))

    return "\n".join(out)

 ## 特殊なケース

 主なエッジケースは次のような場合です$n = 1$。 グリッドには、数値 1 を割り当てる必要がある 1 つのセルが含まれています。アルゴリズムは以下を計算します。$total\_even = 1$、セルが偶数であると識別され、要件に一致するランク 1 が割り当てられます。 

もう 1 つのエッジケースは次のような場合です$n$サイズは大きいですが、クエリは完全に境界行または境界列にあります。 このような場合、行パリティにより、行ごとの偶数セルと奇数セルの分布が反転します。 各行はインデックス パリティに基づいて独立して処理され、グローバル構造への依存を回避するため、カウント式は引き続き適用されます。 

3 番目のケースは、最後のセルをクエリするときに発生します。$(n, n)$。 ここで、正確性は、このセルが偶数ブロックに属するか奇数ブロックに属するかを適切に区別することに依存します。 この式は次のようにしてこれを保証します。$(x+y)\bmod 2$、その後、正しいオフセットを追加して、最大インデックスでも一貫性を保証します。
