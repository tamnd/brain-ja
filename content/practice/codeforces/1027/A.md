 ## 解決策
 ## 問題の理解

 いくつかの独立した文字列が与えられます。 各文字列の長さは均等で、すべての文字は英小文字です。 各文字について、それを 1 回だけ変更することが強制され、変更ルールは固定されています。つまり、アルファベットを上下に 1 ステップしか移動できません。 たとえば、次のようなキャラクター`m`どちらかになる`l`または`n`、 その間`a`になることしかできない`b`、 そして`z`になることしかできない`y`。 

これらの独立した 1 ステップの変更をすべての位置に適用した後、結果の文字列が回文になる可能性があるかどうか、つまり、変更後に端からの対称位置が一致する必要があるかどうかを知りたいと考えています。 

重要な問題は、最後の文字を直接選択しないことです。 代わりに、位置ごとに、隣接する可能性のある 2 つの文字のうち 1 つを選択します。 問題は、すべてのミラーリングされたペアが最終的に等しくなるように、これらのローカル バイナリの選択を調整できるかどうかという問題になります。 

制約は小さく、各文字列の長さは最大 100、テスト ケースは最大 50 です。 これは、すべての位置を個別にチェックするか、単純な貪欲な一貫性チェックを試みるソリューションでも十分であることを意味します。 ポジションを指数関数的に超えることも技術的には可能ですが、その必要はありません。 

微妙なエッジケースは、アルファベットの末尾の文字に由来します。 のようなキャラクター`a`そして`z`可能な変換は 1 つだけです。 これにより柔軟性が失われ、他のポジションが柔軟な場合でも不一致が生じる可能性があります。 たとえば、必要な場合は、`a`何か他のものと一致する`b`、他の選択肢に関係なく、そのペアは不可能になります。 

もう 1 つのエッジ ケースは、ミラー化された 2 つの文字の両方が、変換可能な値を 1 つだけ持つ場合です。 これらの強制された値が異なる場合、それを修正する方法はありません。 文字の元の同等性のみをチェックする単純なアプローチでは、これを完全に見逃してしまいます。 

## アプローチ

 ブルートフォース手法では、文字列の可能なすべての変換が試行されます。 各ポジションには最大 2 つの選択肢があるため、最大で 2 つの選択肢があります。$2^n$可能性。 候補文字列ごとに、それが回文であるかどうかを確認します。 これは、すべての有効な結果を調査するので正しいですが、$n = 100$、これはすでに約に達しています$2^{100}$、これは実行可能な計算をはるかに超えています。 

重要な点は、完全な文字列を構築する必要がないということです。 ミラーリングされたペアごとに次のことを確認するだけで済みます。$(i, n-1-i)$、可能な最終文字のセットが交差します。 各位置は最大 2 文字のセットに影響します。 問題は、2 つの小さなセットにすべての対称ペアに対して空でない共通部分があるかどうかをチェックすることに帰着します。 

そこで、グローバル検索の代わりに、問題をローカル互換性チェックに絞り込みます。 両方のエンドポイントが許可される変換を個別に選択した後、各ペアは少なくとも 1 つの共通文字に同意できなければなりません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n \cdot n)$|$O(n)$| 遅すぎる |
 | ペアワイズセットチェック |$O(n)$文字列ごと |$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各文字列を個別に処理します。 

1. すべての位置について、結果として考えられる 2 つの文字を計算します。 そのキャラクターが`a`、店舗限定`b`。 そうであれば`z`、店舗限定`y`。 それ以外の場合は、両方の近隣を保存します。 これにより、インデックスごとにサイズ 1 または 2 の小さなセットが定義されます。 
2. インデックスの対称ペアごとに$i$そして$n-1-i$、2 つの候補セットを比較します。 両方のセットに出現する文字が少なくとも 1 つ存在するかどうかを確認します。 これは、これら 2 つの位置を等しくする変換を選択できる可能性を表します。 
3. 対称ペアに空の交差部分がある場合、その文字列は回文に変換できないと即座に結論付けます。 
4. すべてのペアがこの交差テストに合格した場合、可能であると結論付けます。 

### なぜ効果があるのか

 対称性によって課される制約を除いて、各位置は独立しています。 すべての位置は、許可されている変換文字の 1 つを正確に選択する必要があるため、回文条件を満たす唯一の方法は、すべてのミラーリングされたペアに共有の有効な選択肢が存在することを確認することです。 各ペアにそのような選択肢が存在すると、ローカル制約に違反することなく、その共通の文字を一貫して両端に割り当てることができます。 これらのペアごとの制約を超えるグローバル結合は存在しないため、ペアごとの実現可能性は完全な実現可能性を意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def options(c):
    if c == 'a':
        return {'b'}
    if c == 'z':
        return {'y'}
    return {chr(ord(c) - 1), chr(ord(c) + 1)}

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        ok = True

        for i in range(n // 2):
            left = options(s[i])
            right = options(s[n - 1 - i])

            if left.isdisjoint(right):
                ok = False
                break

        out.append("YES" if ok else "NO")

    print("\n".join(out))

if __name__ == "__main__":
    solve()
```機能`options`各文字に許可される変換をエンコードします。 メイン ループは各テスト ケースを処理し、ミラーリングされた位置のみを比較します。 重要な操作は集合交差チェックであり、両端が最終文字に一致するかどうかを判断します。 

よくある間違いは、元のキャラクターを比較したり、固定の変換を選択した後に比較したりすることです。 選択がグローバルではないため、これは失敗します。 各位置は独立して方向を選択するため、両方の可能性を同時に考慮する必要があります。

 ## 特殊なケース

 重大なエッジケースは、文字がアルファベットの境界にある場合です。 入力用`az`、変換は強制的に行われます。`a → b`そして`z → y`。 唯一可能な最終文字列は次のとおりです。`by`、これは回文ではありません。 アルゴリズムはこれを正しく検出します。`{'b'}`そして`{'y'}`空いている交差点がある。 

もう 1 つの特殊なケースは、両側が個別に柔軟であるが互換性がない場合です。 のために`cf`、`c`なることができる`{b, d}`そして`f`なることができる`{e, g}`。 両方のセットのサイズが 2 であっても、重複がないため、ペアは失敗します。 このアルゴリズムは、選択肢をシミュレートする必要がなく、純粋にセットの交差によってこれを正確に識別します。 

最後の微妙なケースは、両側に重複はあるが元の文字が異なる場合です。 のために`adfa`、ミラーリングされたペアが独立してチェックされるため、中間構造は引き続き整列することができ、実現可能性は元の対称性ではなく、到達可能な変換された対称性に関連付けられます。
