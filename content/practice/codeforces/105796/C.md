 ## 問題の理解

 このタスクは、ユークリッド アルゴリズムの低速バージョンによって実行される反復回数をカウントすることです。 アルゴリズムは 2 つの正の整数から始まります。 2 つの値が異なる間、大きい値から小さい値を繰り返し減算し、カウンターをインクリメントします。 答えは、最大公約数そのものではなく、このカウンタの最終値です。 

たとえば、次のように始めます。`15 10`、プロセスは`15 10 -> 5 10 -> 5 5`、したがって、答えは次のとおりです`2`。 課題は、入力値が非常に大きくなる可能性があるため、すべての減算をシミュレートすることが不可能であることです。 

入力には最大 500 組の正の整数が含まれており、各整数は次のような大きさにすることができます。`10^18`。 直接シミュレーションには、最大でほぼ次のものが必要になる場合があります。`10^18`操作。 のようなペア`1 1000000000000000`差し引くだろう`1`これは、実際の制限時間内に収まりきらない、より大きな数からほぼ 1 京倍になります。 代わりに、ソリューションでは、同一の減算ステップのグループ全体を処理する必要があります。 

難しいケースは、正確な停止条件や非常に大きな商か​​ら発生します。 両方の数値がすでに等しい場合、減算は行われません。```
Input
7 7
```正しい出力は次のとおりです。```
0
```常に少なくとも 1 つの減算を実行する不注意な実装では、不正確な結果が生成されます。 

もう 1 つの特殊なケースは、一方の数字がもう一方の数字を割る場合です。```
Input
1 1000000000000000
```正しい出力は次のとおりです。```
999999999999999
```最後の引き算は特別です。なぜなら、引き算を繰り返した後だからです。`1`、数値は等しくなります。 数える`1000000000000000`引き算は 1 つ多すぎます。 

3 番目のケースは、最初の除算で余りが残った場合です。```
Input
15 10
```正しい出力は次のとおりです。```
2
```最初の減算により、ペアが次のように変更されます。`5 10`、2番目はそれを次のように変更します`5 5`。 演算回数を商のみとして扱う`15 // 10`後のユークリッドのステップを見逃してしまいます。 

## アプローチ

 簡単なアプローチは、指定されたアルゴリズムを正確に実装することです。 2 つの数値が異なりますが、大きい方から小さい方を引いて、答えを増分します。 すべてのループ反復が元のプロセスの 1 つの減算と一致するため、これは正しいです。 

問題は反復回数です。 値が`1`そして`10^18`、ループは実行します`999999999999999`操作。 このようなテスト ケースが 1 つであっても大きすぎ、数百ものテスト ケースが存在する可能性があります。 

重要な観察は、多くの連続したループ反復が同じことを行うということです。 大きい数値が小さい数値よりもはるかに大きい場合、アルゴリズムは同じ値を繰り返し減算します。 これらの減算を個別に実行する代わりに、1 つのグループで発生する回数を数えることができます。 

現在の値が`a > b`。 書く：```
a = q * b + r
```もし`r`がゼロではない場合、遅いアルゴリズムにより減算されます。`b`その通り`q`大きい値になるまでの 回`r`。 状態は次から変化します`(a, b)`に`(b, r)`。 

もし`r`その後はゼロです`q - 1`減算すると値は等しくなります。 の`q`等価に達するとすぐにループが停止するため、 - 番目の減算は実行されません。 状態は次のようになります。`(b, b)`そして貢献する`q - 1`操作。 

これはユークリッド アルゴリズムの背後にある同じ圧縮の考え方ですが、gcd を見つけるだけでなく、遅いバージョンが実行したであろう減算ステップの数を追跡します。

 ## アルゴリズムのチュートリアル

 1. 数値のペアを読み取り、回答カウンターをゼロに初期化します。 
2. 2 つの数値がすでに等しい場合は、元のループ条件が直ちに false になるため、0 を返します。 
3. 数字は異なりますが、大きい方の数字を作ります`a`そして小さい方の数字`b`。 
4. コンピューティング`a // b`そして`a % b`。 商は、遅いアルゴリズムが何回減算するかを示します。`b`から`a`値が下回る前に`b`または同等になります。 
5.追加`a // b`余りがある場合は答えに戻ります。 余りがない場合は、最後の減算で数値が等しくなり、ループが終了するため、商より 1 つ少ない値を加えます。 
6. ペアを次のユークリッド状態に置き換えます。`(b, a % b)`両方の値が等しくなるまで続けます。 

これが機能する理由は、圧縮された各ステップが同一の減算の連続シーケンスを表すためです。 必要な調整は、元のアルゴリズムが通常の除算プロセスよりも 1 回早く減算を停止するため、大きい数値が小さい数値の正確な倍数である場合のみです。 

### なぜ効果があるのか

 どの時点でも、低速アルゴリズムは小さい方の数値を減算して大きい方の数値のみを変更します。 これらの同一の操作をグループ化しても、グループの終了後に中間値は変わりません。 

のために`a > b`、商`a // b`まさに最大回数です`b`値が以下になる前に減算できます`b`またはゼロに達します。 余りがある場合、それらの減算はすべて次のペアの前に行われます。`(b, remainder)`が表示されます。 剰余がない場合、最後の減算により等価性が生じるため、除外されます。 この変換を繰り返すと、元のアルゴリズムと同じ状態に従い、各グループ内の個々の操作のみがスキップされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_operations(a, b):
    ans = 0

    while a != b:
        if a < b:
            a, b = b, a

        q, r = divmod(a, b)

        if r == 0:
            ans += q - 1
            break
        else:
            ans += q
            a, b = b, r

    return ans

def solve():
    t = int(input())
    out = []

    for _ in range(t):
        a, b = map(int, input().split())
        out.append(str(count_operations(a, b)))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```機能`count_operations`現在の値のペアと圧縮された減算ステップの数を保持します。 交換により、`a`元のループの条件と一致する、除算を適用する前の大きい値。 

の`divmod`call は商と剰余の両方を一度に計算します。 これにより、手動で計算する必要がなくなり、繰り返された減算の回数が直接明らかになります。 

の`r == 0`ブランチは、2 つの数値が等しくなる境界条件を処理します。 追加`q`元のループでは等価性を生み出す減算が実行されないため、ここでは 1 だけオーバーカウントされます。 

Python の整数は、次の値よりも大きい値を格納できます。`10^18`したがって、オーバーフローのリスクはありません。 ループはユークリッド換算にのみ従うため、反復回数は少ないままです。

## テストケース```python
import sys
import io

def count_operations(a, b):
    ans = 0
    while a != b:
        if a < b:
            a, b = b, a
        q, r = divmod(a, b)
        if r == 0:
            ans += q - 1
            break
        ans += q
        a, b = b, r
    return ans

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    t = int(sys.stdin.readline())
    ans = []
    for _ in range(t):
        a, b = map(int, sys.stdin.readline().split())
        ans.append(str(count_operations(a, b)))
    sys.stdin = old_stdin
    return "\n".join(ans)

""") == """0
2

assert run("""1

""") == "1", "minimum values"

assert run("""1

""") == "999999999999999999", "maximum quotient"

""") == "0", "equal values"
