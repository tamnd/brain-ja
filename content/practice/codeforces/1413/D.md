 ## 解決策
 ## 問題の理解

 空から始まったショーケースで実行された操作の時系列のログが与えられます。 イベントには2種類あります。 1 つのイベントは未知の値を持つ新しい手裏剣を挿入し、もう 1 つのイベントは現在存在する最小の値を削除し、どの値が削除されたかを正確に報告します。 

1 から n までのすべての値が削除イベントにちょうど 1 回出現し、挿入がちょうど n 回あることがわかります。 タスクは、やみくもにシミュレーションすることではなく、最小値のすべての削除がマルチセットの展開と一致するように、挿入イベントに値が割り当てられているかどうかを判断することです。 可能であれば、挿入イベントへの値の有効な割り当ても 1 つ出力する必要があります。 

重要な問題は、挿入にラベルが付けられていないことです。 各「+」にどの値が挿入されるかはわかりません。「- x」が発生するたびに、x がその時点で利用可能な最小値になるように値を割り当てる必要があります。 

n が 100000 までの制約は、バックトラッキングを伴う二次シミュレーションや n log n の重いシミュレーションでも、割り当てを繰り返し試行すると遅すぎることを意味します。 利用可能なアイテムの現在のセットを維持するシングル パス構造と、一貫した割り当てを貪欲に構築する戦略が必要です。 

利用可能なアイテムがないときに削除が発生すると、微妙な失敗のケースが発生します。 たとえば、削除である最初のイベントは、まだ何も挿入されていないため、すぐに無効になります。 

別の失敗例は、x が削除されるときに、アルゴリズムによって x より小さい要素が構造内に残ることを許可する場合に発生します。 たとえば、1 が挿入されたが、2 が削除される前に削除されなかった場合、1 がまだ存在している間は 2 が最小値にならないため、シーケンスは無効になります。 

それほど明白ではないエッジケースは、削除前に複数の挿入が発生する場合であり、将来の削除と一貫した方法でそれらの挿入にどの値を割り当てるかを決定する必要があります。 将来の制約を考慮せずに挿入順序で値を割り当てる単純な戦略は失敗します。 

## アプローチ

 ブルートフォース手法では、1 から n までの順列を挿入位置に割り当て、各候補割り当てのプロセスをシミュレートしようとします。 それぞれの「- x」について、x が実際に現在のマルチセットの最小値であるかどうかを確認します。 これには、n! につながる代入のすべての順列を構築してチェックする必要があります。 マルチセットを使用する場合、各シミュレーションのコストは O(n log n) になる可能性があります。 これは、n が小さい場合でも天文学的に不可能です。 

重要な観察は、制約が削除時に最小要素のみを参照するということです。 これは、将来の最小要件によって制約されるスタックのような構造の観点から考える必要があることを示唆しています。 挿入値をすぐに決定する代わりに、値の割り当てを強制されるまで決定を延期できます。 

現在挿入されているが割り当てられていないスロットの構造を維持しながら、イベントを順番に処理します。 x が削除された場合、x は現在利用可能な最小値でなければならないことがわかります。 したがって、まだ「開いている」すべての未割り当ての挿入スロットのうち、x はまだ x である可能性が高い最新の挿入に割り当てられる必要があります。そうでないと、より小さい値が早期に強制され、最小制約に違反します。 

これは貪欲な構築につながります。つまり、まだ値が割り当てられていない「+」イベントの位置のスタックを維持します。 「- x」が表示された場合、x を最新の未割り当ての「+」に割り当て、そのスロットをスタックから削除します。 削除しようとした時点で未割り当ての挿入が存在しない場合、シーケンスは不可能です。 

これが機能するのは、最後の未割り当て挿入が常に最も制約されているためです。つまり、現在の瞬間に最も近い挿入であり、したがって現在の最小必要値を吸収する必要がある挿入です。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n! · n log n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 まだ値が割り当てられていない挿入イベントのインデックスのスタックを維持しながら、イベント シーケンスを左から右に処理します。 

1. イベントを順番に読み取り、すべての「+」操作の位置を記録します。 「+」が表示されるたびに、そのインデックスがスタックにプッシュされます。これは、何らかの値を受け取る必要がある将来のスロットを表すためです。 
2. 「-x」イベントが発生すると、スタックが空かどうかを確認します。 空の場合、x を生成するために使用できる挿入がないため、シーケンスは無効になります。 
3. それ以外の場合は、スタックから最新の未割り当ての挿入インデックスをポップし、それに値 x を割り当てます。 これにより、x が最後に導入されたプレースホルダーにバインドされるようになります。 
4. すべてのイベントが処理されるまで、このプロセスを続けます。 
5. すべてのイベントを処理した後、出現順に挿入位置への値の割り当てを出力します。 いずれかの時点で削除に失敗した場合は、「NO」が出力されます。 

これが機能する理由: x の削除を処理する時点では、x は現在ショーケース内にある最小の要素であることが保証されます。 まだ値が割り当てられていない挿入は、その正確な値が依然として柔軟な要素を表しますが、そのような要素はすべて、シーケンスとの一貫性を維持する以前に削除されたすべての要素よりも厳密に大きくなければなりません。 最新の挿入に x を割り当てると、以前の挿入が後でより小さい値を取ることを強制されることがなくなります。これは、以前の挿入の方が構造内での有効期間が長く、したがって将来の最小限の削除によって制約を受ける機会が増えるためです。 この責任の貪欲な逆転により、現在のマルチセットが常に一貫して拡張できるという不変条件が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    ops = []
    plus_pos = []
    
    for i in range(2 * n):
        line = input().strip()
        if line == '+':
            ops.append(('+', None))
            plus_pos.append(i)
        else:
            _, x = line.split()
            ops.append(('-', int(x)))
    
    ans = [0] * (2 * n)
    stack = []
    ptr = 0
    
    for i, (t, val) in enumerate(ops):
        if t == '+':
            stack.append(i)
        else:
            if not stack:
                print("NO")
                return
            pos = stack.pop()
            ans[pos] = val
    
    print("YES")
    res = []
    for i, (t, _) in enumerate(ops):
        if t == '+':
            res.append(str(ans[i]))
    print(" ".join(res))

if __name__ == "__main__":
    solve()
```このソリューションは挿入イベントのインデックスを保存し、後で対応する削除によって決定が強制されたときに各「+」に値を割り当てることができるようにします。 スタックにより、常に最新のオープン挿入が最初に割り当てられるようになります。これは、実現可能性を維持するために非常に重要です。 

配列`ans`各挿入位置にどの値が割り当てられているかを記録します。 すべてのイベントを処理した後、挿入順序で値を抽出して必要な出力を形成するだけです。 

よくある落とし穴は、割り当てが「+」イベントと正確に 1 対 1 で対応する必要があることを忘れていることです。 もう 1 つは、マルチセットを直接シミュレートしようとするものですが、初期割り当て構造がわからないために失敗します。

 ## 特殊なケース

 最初のエッジ ケースは、削除が即座に発生することです。 アルゴリズムは、ポップを試みる前に、利用可能な挿入のスタックが空かどうかをチェックすることによってこれを処理します。 入力で`- 1`の場合、最初のステップではスタックが空であるため、アルゴリズムはシーケンスを正しく拒否します。 

もう 1 つの特殊なケースは、すべての挿入が削除の前に行われる場合です。 3 つの「+」の後に「- 3 - 2 - 1」が続くと、スタックはサイズ 3 に成長し、その後逆の順序で消費されます。 各ポップは現在の削除値を最新の挿入に割り当て、すべての最小制約を満たす一貫したマッピングを生成します。 

3 番目のエッジ ケースには、交互の操作が含まれます。 「+ - 1 + - 2」では、最初の挿入がすぐに消費され、その後 2 番目の挿入が消費されます。 スタックは局所性を保証するため、各削除は常に最新の利用可能な挿入と一致し、インターリーブ下でも有効性が維持されます。
