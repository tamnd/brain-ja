 ## 解決策
 ## 問題の理解

 各テスト ケースは、「ドア」に関連付けられた偶数長の整数のコレクションを提供します。 これらの整数は係数として機能します。 ペアの加重和が正確にゼロになるように、別のゼロ以外の整数を各位置に割り当てる必要があります。 正式にはどのポジションでも$i$、値を選択します$b_i$、要件は、2 つのシーケンスの内積がゼロであることです。$\sum a_i b_i = 0$。 選ばれたすべての$b_i$ゼロ以外であり、範囲内にある必要があります$[-100, 100]$。 

したがって、このタスクは最適化や独自性に関するものではありません。 これは純粋に建設的です。入力配列ごとに、単一の線形制約を満たす同じ長さの別の配列を出力する必要があります。 

制約$n \le 100$テストケースごとに、$T \le 1000$せいぜい意味する$10^5$全体的な価値観。 各テスト ケースを線形時間で処理するソリューションであればどれでも十分です。 値を構築するだけでよいため、要素ごとの定数時間戦略でも十分です。 

単純なアプローチでは、任意の整数の代入を検索しようとします。$b_i$おそらく一般の線形ディオファントス方程式を解くか、ランダムな割り当てを試みることにより、方程式を満たすことができます。 これは不必要であり、不安定になる可能性があります。 

すべてを割り当てようとすると、単純な推論による微妙な失敗例が現れます。$b_i = 1$。 すると合計は次のようになります$\sum a_i$、ゼロであることは保証されません。 たとえば、入力の場合$[1, 2]$、これは与えます$3 \ne 0$, そのため、すぐに失敗します。 もう 1 つの単純なアイデアは、1 つの値を設定して他の値をすべてキャンセルすることです。ただし、それは境界制約に違反する可能性があります。$|b_i| \le 100$。 

主な困難は、ゼロ以外の制約を満たすことと、正確なキャンセルを強制しながら値を小さく保つことを同時に行うことです。 

## アプローチ

 強引なアイデアは、値を割り当てることです。$b_1, \dots, b_n$1 つずつ、残りの値を完成させて一次方程式を満たすことができるかどうかを確認します。 こちらはおおよそのサイズの空間での検索となります$200^n$、これはたとえ$n = 10$。 

より構造化された試みは、問題を次の 1 つの線形方程式を解くものとして見ることです。$n$未知数。 これは不十分に決定されているため、無限に多くの解が存在します。 課題は存在ではなく、小さな整数値とゼロを含まない解を見つけることです。 

重要な観察は次のとおりです$n$は均等です。 これにより、インデックスをペアにして、グローバルではなくローカルでキャンセルを強制することができます。 すべての変数にわたって 1 つの方程式を解く代わりに、各ペア内でゼロの寄与を構築します。 各ペアが独立してゼロに寄与することを保証できれば、全体の合計は自動的にゼロになります。 

各ペアの構築は困難になります$(a_i, a_j)$、2 つの非ゼロ整数$(b_i, b_j)$次のような:$$a_i b_i + a_j b_j = 0$$これは選択することで常に可能です$b_i = a_j$そして$b_j = -a_i$。 これは次の理由により直接キャンセルされます。$$a_i a_j + a_j (-a_i) = 0$$この構築では、次のすべての制約が尊重されます。$|a_i|, |a_j| \le 100$、 それで$b_i$そして$b_j$も境界内に留まり、ゼロ以外になります。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 配列を読み取る$a$長さの$n$。 目標は、一致する配列を構築することです$b$。 
2. ペアを考慮して、2 つの位置のステップで配列を走査します。$(a_{2k}, a_{2k+1})$。 要素をグループ化する理由は、各ペアが独立してゼロ和制約を満たすためです。 
3. 各ペアに、$b_{2k} = a_{2k+1}$そして$b_{2k+1} = -a_{2k}$。 これにより、ペアの合計に対する寄与が正確にゼロになります。 
4. 構築された配列を出力します。 

正確かどうかは、すべてのインデックスがペアで 1 回だけ使用されるため、ペアになっていない残りの要素が存在しないという事実にかかっています。 

### なぜ効果があるのか

 各ペアは以下に貢献します。$$a_{2k} b_{2k} + a_{2k+1} b_{2k+1} = a_{2k} a_{2k+1} + a_{2k+1} (-a_{2k}) = 0$$合計はペアごとのゼロの合計であるため、全体的な合計はゼロになります。 この構造では、ゼロ値が導入されることはありません。$b$、値は、絶対値で 100 によって制限される入力配列から直接取得されるため、範囲内に残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    out = []
    
    for _ in range(T):
        n = int(input())
        a = list(map(int, input().split()))
        
        b = [0] * n
        
        for i in range(0, n, 2):
            b[i] = a[i + 1]
            b[i + 1] = -a[i]
        
        out.append(" ".join(map(str, b)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは各テスト ケースを読み取り、出力配列を直接構築します。 ループは 2 ずつ増加し、ペアへの安全なアクセスが保証されます。$n$さえ保証されています。 各割り当ては定数時間であるため、全体の構造は線形です。 

唯一の微妙な点は、符号が正しいことを確認することです。交換と否定が不可欠です。 符号反転のないその他の順列はキャンセル プロパティを壊します。

 ## 特殊なケース

 重要なエッジケースは、値の大きさは大きいが符号が反対である場合です。 例えば、$a = [100, -100]$。 建設が生み出すのは、$b = [-100, -100]$。 貢献度は、$100 \cdot (-100) + (-100)\cdot(-100) = -10000 + 10000 = 0$, そのため、サインが混在している場合でもキャンセルは成立します。 

もう 1 つのケースは、すべての値が等しい場合です。たとえば、$a = [7, 7, 7, 7]$。 アルゴリズムはそれらを次のようにペアリングします$(7,7)$2 回、生成する$(7,-7)$各ペアで。 各ペアは独立してキャンセルされるため、相互干渉は発生しません。 

最後に、交互の標識が次のように表示されると、$[1, -1, 1, -1]$、グローバル構造には決して依存せず、ペアごとのキャンセルのみに依存するため、このメソッドは依然として機能します。
