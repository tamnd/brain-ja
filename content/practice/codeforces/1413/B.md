 ## 解決策
 ## 問題の理解

 未知の行列のすべての行と同じ行列のすべての列が与えられます。 

問題は、両方のコレクションがシャッフルされることです。 行は任意の順序で表示され、列も任意の順序で表示されます。 行内では、左から右の順序が維持されます。 列内では、上から下の順序が保持されます。 

からのすべての値`1`に`n * m`マトリックス内に 1 回だけ出現します。 すべての値は個別であるため、各数値はセルを一意に識別します。 

タスクは、元の行列を再構築することです。 

制約が主な手がかりです。 それでも`n`そして`m`それぞれが到達できるか`500`、すべてのテスト ケースにわたる行列セルの合計数は最大で`250000`。 これは、セルの数に比例するソリューションは容易に十分に高速であることを意味します。 すべての行とすべての列を繰り返し比較し、それらの比較内の配列全体をスキャンするソリューションは、次のようになります。`O(n * m * min(n,m))`、これは不必要であり、限界近くで遅くなる危険性があります。 

入力の構造には、すべての数値が一意であるという非常に便利な特性が隠されています。 つまり、1 つの値が最終的な行の順序付けのどこに属するかがわかれば、その値を含むすべての行の位置がすぐにわかります。 

よくある間違いは、すべての列に対して行を照合し、セルごとに行列を再構築しようとすることです。 考慮する：```
n = 2, m = 3

Rows:
6 5 4
1 2 3

Columns:
1 6
2 5
3 4
```最初の行を任意に最上位行として選択すると、次のようになります。```
6 5 4
1 2 3
```この行列は列の順序と一致しません。 正しい再構成は次のとおりです。```
1 2 3
6 5 4
```行の順序は推測ではなく、列から決定する必要があります。 

別の微妙なケースが発生する場合`m = 1`。```
Rows:
3
1
2

Column:
3 1 2
```列は 1 つだけなので、その列によって行の順序が完全に決まります。```
3
1
2
```複数の列が存在することを前提としたソリューション、または常に最初の行をアンカーとして使用するソリューションは、ここで失敗する可能性があります。 

## アプローチ

 ブルートフォース手法では、すべての行をすべての列と比較して、正しい行順序を決定しようとします。 すべての値は一意であるため、行の最初の要素が列内で出現する場所を検索し、その情報を使用して行を配置できます。 

これは機能しますが、単純に実装すると行と列を繰り返しスキャンします。 最大合計 250,000 個のセルがあるため、不必要に検索を繰り返すと、必要以上の作業が発生します。 

重要な観察は、すべての値が行列全体で 1 回だけ出現するということです。 

仮定する`n <= m`。 次に、すべての列に次の内容が含まれます`n`価値観。 任意の行を検査する場合、その最初の要素はいずれかの列内の 1 つの位置に正確に出現する必要があります。 その位置は、正確に、最終的な行列内のその行の行インデックスです。 

さらに良いことに、Codeforces が意図したソリューションでは、シーケンスあたりのエントリが少ないディメンションが使用されます。 

いつ`n <= m`、最初に行を読み取り、マッピングを構築します。```
first element of row -> row contents
```次に、列を検査します。 これらの最初の要素の 1 つを含む列は、上から下への順序が行列内の行の順序とまったく同じであるため、完全な行の順序を示します。 

いつ`n > m`と同様に、代わりに列を使用することで、同じアイデアが対称的に機能します。 

この特定の問題については、さらに単純な定式化で十分です。 

すべての行は、最初の要素によって一意に識別されます。 指定された列のうち、正確に 1 つの列に最初の要素が含まれます。 その列が見つかると、その順序によってすぐに答えの行の順序が決まります。 

これにより、再構築が数回のハッシュ テーブル ルックアップに減ります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²m) | O(nm) | 遅すぎる |
 | 最適 | O(nm) | O(nm) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.すべて読む`n`行を作成して保存します。 
2. 各行の最初の要素を行全体にマッピングする辞書を作成します。 

これにより、最初の値がわかったときに行を即座に回復できます。 
3. すべて読む`m`列。 
4. 保存されている row-first-element の 1 つを含む列を見つけます。 

すべての行の最初の要素は行列内に 1 回だけ出現するため、エントリがすべての行の最初の要素である列が 1 つだけ存在します。 
5. その列の値の順序を使用して、行の順序を決定します。 

列に次の内容が含まれる場合:```
a
b
c
```次に、で始まる行`a`、`b`、 そして`c`最終的なマトリックスではこの順序で出現する必要があります。 
6. 対応する行を出力します。 

### なぜ効果があるのか

 すべての行列値は個別であるため、すべての行は最初の要素によって一意に識別されます。 

一番上の行の最初の要素を含む列を考えてみましょう。 列は上から下の順序を保持するため、同じ列には 1 行おきの行の最初の要素も正しい垂直方向の順序で含まれます。 

その列が見つかると、最初の要素の順序によって行の順序が一意に決まります。 最初の各要素を対応する行に置き換えると、行列全体が再構築されます。 この問題では一意の有効な行列が保証されるため、あいまいさは残りません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    out = []

    for _ in range(t):
        n, m = map(int, input().split())

        rows = [list(map(int, input().split())) for _ in range(n)]

        pos = {}
        for row in rows:
            pos[row[0]] = row

        answer_order = None

        for _ in range(m):
            col = list(map(int, input().split()))

            if answer_order is None:
                for x in col:
                    if x in pos:
                        answer_order = col
                        break

        for first_value in answer_order:
            out.append(" ".join(map(str, pos[first_value])))

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、すべての行を最初の要素をキーとする辞書に保存します。 

列の読み取り中に、行先頭の値を含む特別な列を検索します。 すべての値は一意であるため、列に行先頭の値が含まれると、その列はまさにすべての行先頭の値で形成される列になります。 その順序は、望ましい行順序です。 

その列を検出した後、再構築は一連の辞書検索になります。 

よくある実装の間違いは、列全体を保持せずに、一致する値を見つけた後で停止してしまうことです。 1 行だけでなくすべての行の順序を指定するため、列全体が必要です。 

もう 1 つの簡単な間違いは、一致する列が最初に読み取られる列である必要があると仮定することです。 列はシャッフルされるため、正しい列が見つかるまですべての列をチェックする必要があります。

        n, m = map(int, input().split())

        rows = [list(map(int, input().split())) for _ in range(n)]

                        break

    return "\n".join(out)
