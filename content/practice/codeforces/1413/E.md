 ## 解決策
 ## 問題の理解

 私たちは敵に繰り返し呪文を唱えます。 

各キャストは即時に取引します`a`ダメージ。 その後、同じキャストで敵を回復します。`b`まさに毎秒健康`c`秒。 キャストは毎回発生します`d`クールダウンのため数秒かかり、すべての効果は重複します。 

ある整数の時点で、すべてのキャストの累積効果の合計によって敵の健康状態が正でなくなった場合、敵は死亡します。 同時に発生するすべての健康状態の変化は一緒に適用されるため、実際に重要なのは、いつでも達成されるダメージから回復を差し引いた最大の総ダメージです。 

テストケースごとに、まだ倒すことができる最大の敵の体力を見つける必要があります。 蓄積されたダメージが際限なく増加する可能性がある場合、どのような健康値でも最終的には殺せるようになり、その答えは次のとおりです。`-1`。 

テストケースの数は`10^5`したがって、時間の経過に伴うシミュレーションを伴うものは不可能です。 パラメータ自体は到達可能です`10^6`、つまり答えは近くにあるかもしれないということです`10^12`したがって、64 ビット演算が必要です。 

課題は、これまでの多くのキャストによる治癒効果が重複していることです。 直接のタイムライン シミュレーションでは、潜在的に数百万または数十億の瞬間を処理する必要がありますが、これは制限をはるかに超えています。 

いくつかの特殊なケースには特別な注意が必要です。 

考慮する：```
a = 1, b = 2, c = 3, d = 4
```この呪文の回復時間はわずか 3 秒ですが、クールダウンは 4 秒です。 すべてのキャストは、次のキャストが行われる前にすべての治癒を終了します。 達成される最大のダメージは単純に最初のヒットであるため、答えは次のとおりです。`1`。 

ここで次のことを考えてみましょう。```
a = 239, b = 21, c = 11, d = 3
```ここでは、各キャストは、キャスト間に導入される追加の回復の合計よりも多くのダメージを与えます。 累積ダメージは永遠に増大するので、答えは`-1`。 

別の微妙なケースは次のとおりです。```
a = 4, b = 3, c = 2, d = 1
```単純な実装では、キャストごとの純ダメージだけを見て、答えが大きいと結論付ける可能性があります。 実際には、重複したヒールは将来のキャストをすぐに打ち消します。 本当の答えは`5`、特定の中間時間に達成されます。 

## アプローチ

 最も直接的なアプローチは、プロセスをシミュレートすることです。 

時々キャストすることもできました`0, d, 2d, ...`、すべてのアクティブな治癒効果を追跡し、各イベントの後にダメージから回復を差し引いた合計を計算します。 到達した最大値は、殺せる最大の体力になります。 

答えはまさにこれまでに達成された最大累積ダメージであるため、これは概念的に機能します。 残念ながら、期間は任意に長くなる可能性があります。 被害が永遠に増加し続ける場合、限界点はありません。 有限の場合であっても、パラメータは`10^6`イベントごとのシミュレーションはコストがかかりすぎます。 

重要な点は、タイムライン全体が必要ないということです。 

キャストが時々発生すると仮定します。```
0, d, 2d, 3d, ...
```直後の累積効果を調べてみましょう。`k`-番目のキャスト。 

それぞれの新しいキャストが貢献します`+a`。 

連続したキャストの間に、ある程度の治癒が発生します。 いくら？ 

キャストは次の期間中に回復します`c`秒。 キャストは次の間隔で配置されるため、`d`秒間、特定のキャストはまだアクティブです```
ceil(c / d)
```キャスト間隔。 

キャストの瞬間にアクティブな治癒をカウントするより明確な方法は、キャストとキャストの間にそれを観察することです。`i-1`そしてキャスト`i`、回復期間がまだその間隔をカバーしているすべての以前の呪文が寄与します。`b*d`ヒーリング。 

このようなアクティブな呪文の数は、最終的には次のように安定します。```
m = floor((c - 1) / d)
```呪文は次の呪文に影響を与えるため、`m + 1`間隔。 

十分なキャストの後、追加キャストごとに累積ダメージが変化します。```
a - b * (m + 1)
```それは```
a - b * ceil(c / d)
```以来```
ceil(c/d) = floor((c-1)/d) + 1.
```この量が正の場合、累積ダメージは永久に増加します。 どのような健康値も最終的には無効になる可能性があるため、答えは次のとおりです。`-1`。 

それ以外の場合、シーケンスは最終的に減少します。これは、初期のキャストの中で最大値が発生することを意味します。 

させて```
k = floor((c - 1) / d)
```最高の瞬間はまさにその直後です`(k+1)`-stキャスト。 その時点まで、新しいキャストごとに蓄積ダメージが増加します。```
a - b * i
```の価値を高めるために`i`。 

これらの利益を合計すると、```
answer =
a + (a-b) + (a-2b) + ... + (a-kb)
```これを単純化すると```
(k+1)a - b * k(k+1)/2.
```この値は、殺害できる最大体力です。

 ## アルゴリズムのチュートリアル

 1. コンピューティング```
k = floor((c - 1) / d).
```これは、呪文が回復に貢献できる以前のキャスト間隔の数です。 
2. かどうかを確認します。```
a > b * (k + 1).
```これは、オーバーラップ パターンが安定した後にもう 1 回キャストを追加することで得られる長期的な利益です。 
3. 不等式が成り立つ場合は、次のように出力します。`-1`。 

累積ダメージは際限なく増加するため、任意の体力を持つ敵を最終的に倒すことができます。 
4. それ以外の場合は計算します```
(k + 1) * a - b * k * (k + 1) / 2.
```これはこれまでに到達した最大の累積ダメージです。 
5. その値を出力します。 

### なぜ効果があるのか

 しましょう`D(n)`直後の累積ダメージから治癒を差し引いた値になります。`n`-番目のキャスト。 

最初のキャストが貢献`a`。 

後続のキャストごとに別のキャストが追加されます`a`、ただし、以前のアクティブな呪文によって生成された治癒も受けます。 オーバーラップパターンが安定する前に、キャスト間に追加されるヒーリングは正確に増加します`b`それぞれのステップ。 後`k+1`アクティブな間隔が存在する場合、追加される治癒は次の時点で一定になります。`b(k+1)`。 

したがって、連続的な違いは、`D(n)`形状：```
a,
a-b,
a-2b,
...
a-kb,
a-(k+1)b,
a-(k+1)b,
...
```最終的な定数差が正の場合、シーケンスは永遠に増加します。 それ以外の場合、シーケンスは、に対応する項に到達した後、非増加になります。`a-kb`したがって、その最大値は正確にその時点で得られます。 等差数列を合計すると、上記の式が得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        a, b, c, d = map(int, input().split())

        k = (c - 1) // d

        if a > b * (k + 1):
            ans.append("-1")
        else:
            res = (k + 1) * a - b * k * (k + 1) // 2
            ans.append(str(res))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```実装は数学的導出に直接従います。 

値```
k = (c - 1) // d
```呪文の治癒の影響を受ける追加のキャスト間隔がどれだけ残っているかを記録します。 

条件```
a > b * (k + 1)
```累積ダメージシーケンスの安定化された傾きが正であるかどうかをチェックします。 そうであれば、答えは無制限であり、出力します。`-1`。 

それ以外の場合は、等差数列の閉じた形式の合計を評価します。 Python 整数は 64 ビットより大きい値を自動的に処理しますが、この問題には符号付き 64 ビット整数でも十分です。 

最も一般的な間違いは、`c // d`の代わりに`(c - 1) // d`。 治癒はキャスト後 1 秒後に始まり、正確に持続します`c`秒なので、正しいオーバーラップ数は次から導出されます。`ceil(c/d)`に等しい`(c - 1)//d + 1`。
