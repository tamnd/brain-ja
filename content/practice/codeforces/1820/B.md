 ## 解決策
 ## 問題の理解

 0 と 1 で構成されるバイナリ文字列が与えられ、この文字列から、各行が元の文字列の循環右シフトである正方形のテーブルを想像するように求められます。 この問題では、この表の中で最大の長方形を見つけるように求められます。 長方形は行と列の連続したブロックとして定義され、面積はそのブロック内の行と列の数の積になります。 

入力は複数のテスト ケースで構成され、それぞれが単一のバイナリ文字列を提供します。 出力はテスト ケースごとに 1 つの整数であり、1 だけを含む最大の四角形の領域を表します。 文字列の長さは 200,000 に達する可能性があり、すべてのテスト ケースの合計も 200,000 になるため、完全なテーブルを明示的に構築することは不可能です。 すべてを処理しようとするアルゴリズム$n^2$細胞は最大で$4 \times 10^{10}$制限時間を大幅に超えた最悪の場合の作戦。 

明らかではないエッジ ケースには、すべて 0 で構成される文字列 (0 を返す必要がある) や、すべて 1 で構成される文字列 (テーブル全体を覆う四角形が生成される可能性がある) が含まれます。 1 と 0 が交互に含まれる文字列では、巡回プロパティを考慮しないと行ごとに四角形を検索しようとする単純な試みが失敗するパターンが作成される可能性があります。たとえば、「1010」では、最大の四角形が 1 セル幅しかない表が生成されます。 

## アプローチ

 ブルートフォースアプローチでは、$n \times n$table を明示的に作成し、可能なすべての四角形を試して、そのすべてのセルが 1 であるかどうかを確認します。 これは原理的には正しいですが、長さの文字列の場合は実行不可能です。$n$、 がある$O(n^4)$可能な長方形。 連続する四角形が行内に並んでいる四角形に限定したとしても、依然として次のことが必要です。$O(n^3)$高さを確認するための操作が遅すぎます。 

重要な観察点は、循環シフトによりテーブルが非常に規則的な構造になっているということです。 テーブルの各列には、元の文字列パターンを繰り返す連続セグメントの列が含まれています。 これにより、問題を 1 次元に減らすことができます。つまり、各列を円形配列とみなして、その列内の連続する 1 の最大数を見つけます。 列ごとの最大連続数がわかっている場合は、幅の長方形について$k$幅の列のセグメントを取得できます$k$そして、それらの列の最大連続値を掛けます。 テーブルは巡回シフト下では対称であるため、最大の長方形の領域は、元の文字列内の 1 の最大ランとそのラン内の 1 の数の積によって求められます。 

より単純で同等の解決策は、文字列内で最も長く連続する 1 のシーケンスを見つけ、その長さを計算することです。$L$、すると、最大面積の長方形は次のようになります。$L \times L$文字列が完全に 1 で構成されている場合、または$L \times \text{total number of ones}$一般的なケースの場合。 巡回シフトによりシーケンスが折り返される可能性があるため、折り返されたセグメントを検出するには文字列が 2 倍になっていると考える必要があります。 ソリューションは、テスト ケースごとに 1 つのリニア スキャンになります。

 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 各テスト ケースを繰り返します。 
2. 現在のバイナリ文字列について、バイナリ文字列が含まれているかどうかを確認します。 そうでない場合は、すぐに 0 を返します。 
3. 文字列をそれ自体に連結します。 これにより、巡回シフトのラップアラウンドが考慮され、連続する文字列をスキャンするときに文字列を線形として扱うことができるようになります。 
4. 現在の 1 のシーケンスの長さを追跡するカウンタと、これまでに見つかった最大シーケンス長の変数を初期化します。 
5. 2 倍の文字列内の各文字を繰り返し処理します。 文字が「1」の場合、現在のシーケンス カウンタをインクリメントします。 「0」の場合、カウンタをゼロにリセットします。 現在のシーケンスが最大シーケンス長を超えるたびに、最大シーケンス長を更新します。 
6. スキャン後の長方形の最大面積は、元の文字列の長さの小さい方になります。$n$見つかった連続する最大値をそれ自体で乗算します。 この値を出力します。 

機能する理由: 文字列を 2 倍にすることで、元の文字列の終わりをラップするシーケンスをキャプチャします。 各行は元の行のシフトであるため、連続する 1 の最大長は、巡回テーブル内で可能な最大の長方形を直接示します。そのため、文字列内の 1 の連続ブロックは、連続する行にまたがって位置合わせできます。 不変条件は、1 の長方形は連続する最も長い 1 のセグメントの長さを超えることができないということであり、アルゴリズムは、回り込むセグメントも含め、考えられるすべてのセグメントをチェックします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_rectangle_area(s):
    n = len(s)
    if '1' not in s:
        return 0
    doubled = s + s
    max_len = 0
    current = 0
    for c in doubled:
        if c == '1':
            current += 1
            if current > max_len:
                max_len = current
        else:
            current = 0
    return min(max_len, n) ** 2

t = int(input())
for _ in range(t):
    s = input().strip()
    print(max_rectangle_area(s))
```コードは、そのエッジ ケースを即座に処理するために、すべてゼロの文字列をチェックすることから始まります。 文字列を 2 倍にすると、ラップされたシーケンスが連続セグメントとして検出されます。 スキャンにより、1 の最大シーケンスが動的に更新されます。 使用する`min(max_len, n)`2 倍になった文字列内のシーケンスが元の長さを超えた場合のオーバーカウントを防ぎます。 これにより、正しい長方形領域が生成されます。 

## 実用的な例

 ### 例 1: 「101」

 | インデックス | シャア | 現在 | 最大長 |
 | --- | --- | --- | --- |
 | 0 | 1 | 1 | 1 |
 | 1 | 0 | 0 | 1 |
 | 2 | 1 | 1 | 1 |
 | 3 | 1 | 2 | 2 |
 | 4 | 0 | 0 | 2 |
 | 5 | 1 | 1 | 2 |

 シーケンスの最大長は 2 です。領域は次のとおりです。$2^2 = 4$、ただし、n=3 なので、min(2,3)=2 となります。 出力は$2$、サンプルと一致します。 

### 例 2: 「011110」

 | インデックス | シャア | 現在 | 最大長 |
 | --- | --- | --- | --- |
 | 0 | 0 | 0 | 0 |
 | 1 | 1 | 1 | 1 |
 | 2 | 1 | 2 | 2 |
 | 3 | 1 | 3 | 3 |
 | 4 | 1 | 4 | 4 |
 | 5 | 0 | 0 | 4 |
 | 6 | 0 | 0 | 4 |
 | 7 | 1 | 1 | 4 |
 | 8 | 1 | 2 | 4 |

 | 10 | 1 | 4 | 4 |
 | 11 | 0 | 0 | 4 |

 ラップアラウンドを考慮した最大連続数は 4 です。Min(4,6)=4 であるため、面積は次のようになります。$4^2=16$。 長方形は巡回シフトを使用して複数の行にまたがることができるため、テーブル内の長方形の寸法に関する面積が正しく計算されます。
