 ## 問題の理解

 クネドリキの目標数が与えられています$N$。 レストランには 3 つのタイプがあります。4 個のクネドリキを与えるもの、5 個を与えるもの、6 個を与えるものがあります。各タイプのレストランを複数選択できますが、利用可能な数を超えることはできません。$A, B, C$。 各レストランのご利用は1回までとさせていただきます。 

問題は、いくつかの数字を選択できるかどうかです$x, y, z$次のような:$$4x + 5y + 6z = N$$と$0 \le x \le A$、$0 \le y \le B$、$0 \le z \le C$。 

各テスト ケースは独立しているため、そのような選択が存在するかどうかに答える必要があります。 

制約は大きく、最大で$10^5$テストケースと最大値$10^8$。 これにより、次のすべての組み合わせを探ろうとするアプローチは除外されます。$x, y, z$または動的プログラミングを実行します$N$。 どのソリューションでも、各テスト ケースを一定の作業または非常に小さな制限された作業に減らす必要があります。 

単純な試みでは、すべてのトリプルを試すことになります。$(x,y,z)$範囲内ですが、最悪の場合は許容されます$10^8$変数ごとに可能性がありますが、これは完全に不可能です。 

より微妙な失敗モードは、貪欲な推論から生じます。 たとえば、常にできるだけ多くの 6 knedlík レストランを利用すると、有効な解決策が崩れる可能性があります。 もし$N = 20$、貪欲なら 6 (18) が 3 つ必要で、2 が残りますが、有効な解決策が存在するとしても、これは不可能です。$5 + 5 + 5 + 5$。 

主要な問題は、コイン サイズ 4、5、6 が制限されたカウントの下で自明ではない相互作用を行うため、一定数の意味のある構成のみを探索するための構造化された方法が必要であることです。

重要な観察は、コインのサイズが小さく、事実上連続していることです。 十分な柔軟性が得られると、表現可能な合計のセットが密になります。 実際、コイン 4、5、6 では、無制限に到達できない値は、1、2、3、7 などの非常に小さな例外だけです。それ以外にも、組み合わせは豊富に存在します。 

残りの複雑さは上限です$A, B, C$。 ただし、各変数は構造を保持したブロック内でシフトできるため、有効な解 (存在する場合) は、候補の小さな近傍のみをチェックするだけで見つけることができます。$(y, z)$価値観。 一度$y$そして$z$固定されており、$x$は一意に決定されます。$$x = \frac{N - 5y - 6z}{4}$$したがって、タスクは一定数の小さな値を試行することになります。$y, z$必要なすべての残基と境界構成をカバーする候補。

 ## アルゴリズムのチュートリアル

 各テスト ケースを、一定数の構造化された候補をチェックすることに縮小します。 

### 1. 些細な不可能性に対処する

 まず、いくつかの小さな値が観察されます。$N$4、5、6 を使用してはまったく形成できません。これらは次のとおりです。$$N \in \{1, 2, 3, 7\}$$これらの場合、境界に関係なく組み合わせは存在しません。 

### 2. 小さな候補を列挙します。$y$そして$z$のすべての小さな値を試します$y$そして$z$これが機能する理由は、4、5、6 の差は他の変数を調整することで補正できるため、大きな値は基本的に表現可能性を変えることなく変数間の質量を移動していると見なすことができるためです。 

これにより、検索スペースが最大 36 ペアに減少します。 

### 3. 各候補を検証する

 各ペアごとに$(y, z)$、次のように計算します。$$rem = N - 5y - 6z$$もし$rem < 0$、このペアは無効です。 

以下も必要です。$$rem \bmod 4 = 0$$それから：$$x = rem / 4$$最後に、次のことを確認します。$$x \le A,\quad y \le B,\quad z \le C$$すべての制約が満たされている場合、答えは「YES」です。 

### なぜ効果があるのか

 重要な特性は、あらゆる実現可能なソリューションを次のようなソリューションに変換できるということです。$y$そして$z$有効性を失うことなく、境界領域内に存在します。$y$または$z$by 4 は、残りの合計の 4 で割り切れる範囲を維持し、調整します。$x$予想通り。 私たちは存在だけを気にしているので、これらの等価クラスの代表を探索するだけで十分です。 有界列挙により、有効な構成の少なくとも 1 つの代表がヒットすることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    bad = {1, 2, 3, 7}

    for _ in range(T):
        N, A, B, C = map(int, input().split())

        if N in bad:
            print("NO")
            continue

        ok = False

        for y in range(6):
            for z in range(6):
                val = 5 * y + 6 * z
                rem = N - val
                if rem < 0:
                    continue
                if rem % 4 != 0:
                    continue
                x = rem // 4
                if x < 0:
                    continue
                if x <= A and y <= B and z <= C:
                    ok = True
                    break
            if ok:
                break

        print("SI" if ok else "NO")

if __name__ == "__main__":
    solve()

割り算チェックにより、導出された値の正確性が保証されます。$x$。 境界チェックにより、レストラン タイプが過度に使用されないという制約が適用されます。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    T = int(input())
    bad = {1, 2, 3, 7}
    out = []

    for _ in range(T):
        N, A, B, C = map(int, input().split())

        out.append("SI" if ok else "NO")

 ## 特殊なケース

 微妙なケースの 1 つが次のような場合です。$N = 0$。 アルゴリズムはこれを正しく受け入れます。$x = y = z = 0$は常に方程式を満たし、境界はそれを自明に許可します。 

もう 1 つのエッジケースは次のような場合です$N$小さいですが、明示的に不可能な集合には含まれていません。$N = 4$。 アルゴリズムは次のことを見つけます$x=1, y=z=0$、これは有効であり、次の場合に境界を尊重します。$A \ge 1$。 

より危険なケースは、有効な表現が存在するものの、コインの種類間でウェイトを変更する必要がある場合です。たとえば、次のとおりです。$$N = 20, A = 0, B = 4, C = 0$$ここでは 5 のみが許可されるため、アルゴリズムは正しく識別する必要があります。$4 \times 5 = 20$。 列挙には以下が含まれるため、これはキャプチャされます。$y=4, z=0$有界チェックで。
