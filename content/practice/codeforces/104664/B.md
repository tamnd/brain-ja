 ## 解決策
 ## 問題の理解

 参加者の強さを表す正の整数を一列に並べて与えます。 タスクは、配列が左側のプレフィックスと右側のサフィックスに分割されるように、単一の分割位置を選択することです。 スプリットのスコアは、左側の合計強度と右側の合計強度の積として定義されます。 目標は、この製品を最大化する分割を見つけることです。 

言い換えると、インデックス k までのプレフィックスの合計を次のように表すと、$S_k$の場合、分割 k でのスコアは次のようになります。$S_k \cdot (S_N - S_k)$。 1 から N-1 までのすべての有効な k の最大値が必要です。 N が 1 に等しい特殊なケースは、片側が空で積が 0 であるため、自明です。 

制約により、最大で次のことが許可されます。$10^5$要素、それぞれ最大$10^4$。 これにより、合計の再計算と組み合わせた分割位置に対する二次アプローチが即座に排除されます。 すべての分割を試し、両側を最初から再計算するソリューションは、約$O(N^2)$追加は制限時間内に遅すぎます。 

一般的なエッジケースは、すべての要素が等しい場合です。 たとえば、配列が [1, 1, 1, 1] の場合、最適な分割は中央にあり、2 と 2 が生成され、4 になります。プレフィックスの合計を誤って管理する単純なアプローチでは、部分範囲が誤って再計算されたり、最適なバランスのとれた分割が失敗したりする可能性があります。 

もう 1 つの微妙なケースは N = 1 です。入力 [x] の場合、通常の意味では分割は無効ですが、問題では答えが 0 と定義されています。k を常に 1 から N まで評価する不注意な実装では、両側を誤って計算したり、明示的に処理せずに空の接尾辞にアクセスしようとしたりする可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 考えられるすべての分割位置 k について、1 から k までの要素の合計と k+1 から N までの要素の合計を計算し、それらを乗算します。 各合計の計算は配列をスキャンすることで実行できるため、各分割コストは$O(N)$。 あるので$O(N)$分割すると、全体の複雑さは次のようになります。$O(N^2)$。 と$N = 10^5$、これには周りが関係します$10^{10}$実行可能な限界をはるかに超えた操作。 

重要な観察は、合計を繰り返し再計算するのは無駄であるということです。 配列の合計がわかったら、分割の右側の合計を左側の合計から定数時間で導き出すことができます。 配列を反復処理しながら実行中のプレフィックス合計を維持すると、各分割評価は次のようになります。$O(1)$。 これにより、問題は範囲の再計算から単一の累積状態の維持まで軽減されます。 

したがって、合計を再計算する代わりに、合計を一度計算してから、配列をスイープしてプレフィックスの合計を更新します。 各位置での正しい合計は、単に合計からプレフィックスを引いたものになります。 積を計算し、最大値を追跡します。

 | ブルートフォース | O(N^2) | お(1) | 遅すぎる |

 ## アルゴリズムのチュートリアル

 1. 配列内のすべての要素の合計を計算します。 これは、分割が選択される前に結合された両側の合計を表します。 
2. 変数を初期化する`prefix`ゼロに。 これにより、分割点を左から右に移動するときの左側の合計が保存されます。 
3. 変数を初期化する`best`ゼロに。 これには、これまでに見つかった最大の製品が保存されます。 
4. 配列を最初の要素から最後から 2 番目の要素まで繰り返します。 意味のある分割を行うには右側が空でない必要があるため、最後の要素の前で停止します。 
5. 各インデックス i で、現在の要素を`prefix`。 これにより、現在の参加者を含めて左側のグループが拡張されます。 
6. 右側の合計を次のように計算します。`total - prefix`。 これが機能するのは、すべての要素がプレフィックスまたはサフィックスに含まれているため、減算すると正確な残りの合計が得られます。 
7. スコアを計算する`prefix * (total - prefix)`そして更新します`best`この値が現在の最大値より大きい場合。 

反復を完了した後、`best`可能な最大スコアを保持します。 

正確さは、すべての有効な分割が 1 つのプレフィックス合計値に正確に対応するという事実に依存します。 すべてのプレフィックスを反復処理することで、考えられるすべてのパーティションを列挙し、各パーティションについて、近似や省略なしで正確なスコアを計算します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    if n == 1:
        print(0)
        return

    total = sum(a)
    prefix = 0
    best = 0

    for i in range(n - 1):
        prefix += a[i]
        right = total - prefix
        best = max(best, prefix * right)

    print(best)

if __name__ == "__main__":
    solve()
```解決策は、有効な分割が存在しないため、単一要素の場合を明示的に処理することから始まります。 合計は一度計算され、スイープ全体で再利用されます。 ループは次で停止します`n-1`サフィックスが空でないことを確認するため。 

A subtle detail is the order of updates: we add the element to`prefix`積を計算する前に、a[i] を含めた後の分割にインデックス i を合わせます。 この順序を混合すると、分割がずれて、不正確な結果が生じる可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    n = int(input())
    a = list(map(int, input().split()))

    if n == 1:
        return "0\n"

    total = sum(a)
    prefix = 0
    best = 0

    for i in range(n - 1):
        prefix += a[i]
        best = max(best, prefix * (total - prefix))

    return str(best) + "\n"

# provided samples
assert run("5\n1 2 3 4 5\n") == "54\n"
assert run("4\n3 2 5 1\n") == "30\n"

# custom cases
assert run("1\n7\n") == "0\n", "single element"
assert run("2\n10 10\n") == "100\n", "minimal split"
assert run("5\n1 1 1 1 1\n") == "6\n", "uniform array"
assert run("6\n5 4 3 2 1 0\n") == "54\n", "descending with zero"

 ## 特殊なケース

 入力用`1 7`、有効な分割はありません。 アルゴリズムが検出するのは、`n == 1`ループに入らずにすぐに 0 を返します。 これにより、空のサフィックスを含む誤った計算が回避されます。 

のために`10 10`、合計は 20 です。i = 0 では、プレフィックスは 10 になり、サフィックスも 10 になり、100 が生成されます。分割が 1 つしかないため、アルゴリズムは 1 つの候補を正確に評価します。 

のために`[1, 1, 1, 1, 1]`、合計は 5 です。接頭辞進化により、積 1×4、2×3、3×2、4×1 が生成されます。 中央の分割での最大値は 6 で、スイープではすべての可能な分割が 1 回だけ評価され、ケースの欠落がないことが保証されます。 

のために`[5, 4, 3, 2, 1, 0]`、ゼロの存在は正確さに影響しません。 最適な分割は、小さいサフィックスが優勢になる前に行われます。 合計にはゼロが含まれており、減算式はすべての位置で有効なままであるため、接頭辞と接尾辞の分解は依然として成立します。
