 ## 解決策
 ## 問題の理解

 次のサイズの正方形グリッドが与えられます。$n \times n$, ここで、各セルはレストランのテーブルによって生み出される年間収益を表します。 レストランのレイアウトは完全な正方形であるため、グリッドには左上、右上、左下、右下のちょうど 4 つの角があります。 タスクは、これら 4 つの隅の位置にある値の積を計算することです。 

入力は整数で構成されます$n$、 に続く$n$それぞれに含まれる行$n$整数。 出力は単一の整数、つまり 4 隅の値の乗算です。 

グリッドには最大で次のものが含まれますが、$50 \times 50 = 2500$実際に重要なのはそのうちの 4 つだけです。 これは、入力の読み取り自体が実行時間の大半を占めるため、グリッド全体をスキャンするどのソリューションも依然としてわずかに高速であることがすぐにわかります。 

グラフや範囲などの難しい構造上の制約はありません。 唯一の微妙な点は、一貫して 0 ベースまたは 1 ベースのインデックスを使用してコーナーを正しく識別することです。 

エッジケースは最小限ですが、それでも健全性をチェックする価値があります。 

インデックス作成が 1 つずれていると、潜在的な間違いが発生します。 たとえば、次の場合$n = 2$:```
7 3
5 1
```正しい角は 7、3、5、1 で、その積は 105 です。よくある間違いは、誤って対角線だけまたは 1 行だけを使用することです。 

もう一つのエッジケースは、$n = 2$、これは最小の有効なグリッドです。 この場合、4 つのセルはすべてコーナーであるため、すべてのエントリを含める必要があります。 

## アプローチ

 ブルートフォース手法は、行列全体を読み取り、座標が 4 つの隅の位置の 1 つと一致するすべてのセルを乗算することです。 そのような位置は 4 つしかないため、単純なスキャンでもすべてをチェックします。$n^2$セルごとに定数時間の比較を実行します。 

これは正しく機能します。問題の構造が答えの明示的な座標を提供するため、グリッド上の情報を集約せず、4 つの固定位置をフィルターするだけです。 

非効率性は純粋に不必要な走査にあります。 それでも$n \leq 50$、ブルート フォースは依然として 2500 回の反復を実行しますが、これは自明ですが、ロジックは不必要に一般的です。 

最適解では、答えが 4 つの決定的な位置にのみ依存することが観察されます。 

左上$(0,0)$、右上$(0,n-1)$、左下$(n-1,0)$、右下$(n-1,n-1)$。 入力の読み取り中、またはグリッドの保存後にそれらを直接抽出できます。 

これにより、問題は入力解析後の定数時間計算に縮小されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n^2) | 承認済み |
 | 最適 | O(n^2) 入力 + O(1) 作業 | O(n^2) または O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数を読み取る$n$、正方形グリッドの両方の次元を定義します。 これにより、コーナーセルが配置される場所が決まります。 
2. コーナー値を保存する 4 つの変数を初期化します。 これらは、入力の読み取り中または行列の保存後のいずれかに入力できます。 
3. グリッドを行ごとに読み取ります。 行を読み取るとき$i$、コーナーである可能性のある位置のみを調べます: 列 0 と列$n-1$。 
4. 最前列にいる場合$i = 0$、左上と右上の値を保存します。 
5. 最後列にいる場合$i = n-1$、左下と右下の値を保存します。 
6. 保存されている 4 つの値を乗算し、結果を出力します。 

各ステップでは、コーナーセル以外の完全な処理ロジックを回避することで、不必要な作業を削減します。 その理由は、コーナーの位置はその座標によって完全に決定され、他の計算には依存しないためです。 

### なぜ効果があるのか

 グリッドは固定かつ静的であり、答えは 4 つの事前に決定されたインデックスのみに依存します。 これらのインデックスは一意で重複しないため、値を 1 回だけ抽出することで正確さが保証されます。 セル間の凝集や相互作用がないため、最終製品に影響を与える中間状態はありません。 したがって、アルゴリズムは必要な値を正確に計算し、それ以外は何も計算しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())

tl = tr = bl = br = 1

for i in range(n):
    row = list(map(int, input().split()))
    
    if i == 0:
        tl = row[0]
        tr = row[n - 1]
    if i == n - 1:
        bl = row[0]
        br = row[n - 1]

print(tl * tr * bl * br)
```コードは単一パスで行列を処理します。 必要に応じてグリッド全体を保存することは避けられますが、ここでは簡単にするために各行を一時的に保存します。 重要な考え方は、最初と最後の行のみが重要であり、それらの行内では最初と最後の列のみが重要であるということです。 

インデックス作成には注意が必要です。`row[0]`列 0 に対応し、`row[n-1]`最後の列に対応します。 使用する`n-1`一貫してオフバイワンエラーを回避します。

 ## 特殊なケース

 のために$n = 2$、すべての要素はコーナーです。 アルゴリズムは最初の行を読み取り、両方の上隅を割り当て、次に 2 番目の行を読み取り、下隅を割り当てます。 入力の場合:```
2
1 2
3 4
```状態は次のように発展します。 

行 0 以降: TL = 1、TR = 2

 行 1 以降: BL = 3、BR = 4

 最終結果は$1 \times 2 \times 3 \times 4 = 24$、期待と一致します。 

グリッドは常に長方形であり、値は正であり、乗算の順序は正確さに影響しないため、他の構造的なエッジ ケースは存在しません。
