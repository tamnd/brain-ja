 ## 解決策
 ## 問題の理解

 私たちには、次のサイズの正方形のチェス盤が与えられます$N \times N$ここで、正方形は整数座標によってインデックス付けされます。 1 人のナイトは 1 つのマスから開始され、ターゲットのマスに到達するために必要な合法的なナイトの移動の最小数を知りたいと考えています。 ボードの境界やパリティの制約によりナイトがターゲットに到達できない場合は、次のように出力します。$-1$。 

ボードは空なので障害物はありません。 唯一の構造は騎士の移動ルールであり、各正方形から最大 8 つの可能な遷移の固定セットを定義します。 これにより、問題は暗黙的なグラフ上の最短経路問題に変わります。各セルはノードであり、各ナイトの動きは重み付けされていないエッジです。 

制約$N < 800$せいぜい暗示する$640{,}000$ノード。 各ノードには最大 8 つの発信エッジがあるため、完全な探索では数百万の遷移が発生します。 慎重に実装すれば、これは Python の BFS 予算内に十分収まります。 

正確性に影響を与える重要なエッジケースがいくつかあります。 

1 つのケースは、開始位置と終了位置が同じ場合です。 例えば：```
N = 1
start = (0, 0)
end = (0, 0)
```正しい答えは、$0$。 常に最初に近隣ノードをキューに入れ、デキュー時にのみ終了をチェックする不注意な BFS 実装は依然として返される可能性があります。$1$途中で距離が増加した場合。 

もう 1 つのケースは、ボードが小さすぎてナイトの動きができない場合です。 例えば：```
N = 2
start = (0, 0)
end = (1, 1)
```ナイトは、どの場所でも合法的な動きをすることはできません。$2 \times 2$したがって、実際にはほとんどのセルは分離されています。 正しい答えは、$-1$開始と終了が等しい場合を除きます。 接続性を前提としたり、境界を無視したりするソリューションは、誤って有限数を返します。 

最後に、パリティは有限のボードでも役割を果たします。 理論的には無限ボード上でポジションに到達可能であっても、境界による切り捨てにより、そのポジションに到達できなくなる可能性があります。 つまり、パリティやマンハッタン距離のみに基づくヒューリスティックな式は安全ではありません。 明示的に検索する必要があります。 

## アプローチ

 直接的なアプローチは、各ボード セルをグラフの頂点として扱い、最短パス検索を実行することです。 各ポジションから最大 8 つのナイトの手を生成し、ボードの外にあるものを除外し、ターゲットに到達するまで探索を続けます。 すべての移動のコストは等しいため、幅優先探索により、最初にターゲットに到達する時間が最適であることが保証されます。 

これは正しいですが、やり方が適切でなかったり、繰り返される状態が追跡されなかったりすると、コストが高くなります。 訪問された構造がなければ、ナイトは自然に周期的に移動するため、同じセルが指数関数的に何度も再訪問されます。 最悪の場合、これは実行不可能な無限に展開するツリーを探索することになります。 

重要な観察は、グラフが重み付けされておらず、エッジ コストが均一であることです。 これにより、BFS が最適になります。 2 番目の観察は、状態空間が十分小さいため、最初から 1 つの BFS で十分であるということです。 A* のような双方向検索やヒューリスティックは必要ありません。 グリッドは密ですが、境界があります。 

ソリューションは最大でも 1 つの BFS に削減されます。$N^2$一定の分岐係数を持つ状態。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (DFS / 繰り返し探索) | 指数 | O(N²) 以上 | 遅すぎる |
 | BFS 最短パス | O(N²) | O(N²) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各ボードセルを解釈する$(x, y)$グラフ内のノードとして。 
2. 8 つの騎士の動きを定義します。$(\pm 1, \pm 2)$そして$(\pm 2, \pm 1)$。 
3. start が target と等しい場合、移動は必要ないため、すぐに 0 を返します。 
4. 距離グリッド (または訪問配列) を次のように初期化します。$-1$、未訪問を意味します。 
5. 開始セルの距離を 0 に設定し、キューにプッシュします。 
6. キューが空でない間に、前のセルをポップします。$(x, y)$。 
7. 8 つの可能な動きのそれぞれについて、次のセルを計算します。$(nx, ny)$。 
8. もし$(nx, ny)$ボードの外にあるか、すでに訪問している場合はスキップしてください。 
9. それ以外の場合は、距離を次のように設定します。$dist[x][y] + 1$そしてそれをキューにプッシュします。 
10. このプロセス中にターゲット セルに到達した場合は、すぐにその距離を返します。 
11. BFS がターゲットに到達せずに終了した場合は、リターンします。$-1$。 

これが機能する理由は、BFS が開始点からの距離の増加順にノードを展開するためです。 すべてのセルには、そのセルに到達するために必要な最小ステップ数が割り当てられます。これは、最初にセルが発見されたときが、重み付けされていないグラフの最短パスに相当するためです。 訪問済みマーキングにより、各セルが 1 回処理されることが保証され、サイクルによる距離の膨張や無限ループの発生が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    N = int(input().strip())
    x1, y1 = map(int, input().split())
    x2, y2 = map(int, input().split())

    if (x1, y1) == (x2, y2):
        print(0)
        return

    moves = [(1, 2), (2, 1), (2, -1), (1, -2),
             (-1, -2), (-2, -1), (-2, 1), (-1, 2)]

    dist = [[-1] * N for _ in range(N)]
    q = deque()
    q.append((x1, y1))
    dist[x1][y1] = 0

    while q:
        x, y = q.popleft()

        for dx, dy in moves:
            nx, ny = x + dx, y + dy

            if 0 <= nx < N and 0 <= ny < N and dist[nx][ny] == -1:
                dist[nx][ny] = dist[x][y] + 1
                if (nx, ny) == (x2, y2):
                    print(dist[nx][ny])
                    return
                q.append((nx, ny))

    print(-1)

if __name__ == "__main__":
    solve()
```実装は BFS に直接準拠します。 距離配列は訪問済みマーカーとしても機能するため、別のブール配列の必要性が回避されます。 ターゲットに到達したときに早期に終了することで、不必要なときにボード全体を探索することがなくなります。 

微妙な点の 1 つは、距離配列にアクセスする前に境界をチェックすることです。 もう 1 つは、セルごとに距離を 1 回だけ割り当てることです。 これにより、最短パスの正確性が維持されます。 

## 実用的な例

 ### 例 1

 入力:```
N = 1
start = (0, 0)
end = (0, 0)
```このケースは、BFS が開始される前に処理されます。 

| ステップ | キュー | 距離の更新 | アクション |
 | --- | --- | --- | --- |
 | 初期化 | (空の BFS はスキップされました) | なし | 開始 == ターゲット |

 出力はすぐに 0 になります。これにより、早期終了ルールが正しいことが確認されます。 

### 例 2

 入力:```
N = 4
start = (1, 2)
end = (2, 2)
```BFS レイヤーを追跡します。 

| ステップ | キュー | 新規訪問 | 理由 |
 | --- | --- | --- | --- |
 | 初期化 | (1,2) | (1,2)=0 | 開始 |
 | ポップ (1,2) | 隣人 | (0,0),(0,4 無効),... | 騎士の動きを展開する |
 | 次の層 | 複数 | いくつかの有効なセル | BFS フロンティアが成長 |
 | 目標を達成する | 見つかりました | (2,2)=3 | 初めて到達した |

 重要な観察は、複数のパスがセルに到達した場合でも、BFS は最初の到達が最小限であることを保証するということです。 この例では、ヒューリスティック ジャンプではなくレイヤーごとに距離がどのように蓄積されるかを示します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(N^2)$| 各セルは最大 1 回訪問され、各訪問で最大 8 つの移動がチェックされます。 
| スペース |$O(N^2)$| 距離グリッドとキューには、最悪の場合、すべてのセルが格納される可能性があります。 

境界$N < 800$せいぜい暗示する$640{,}000$BFS が快適に処理できるノード。 8 つのトランジションの定数係数により、制限内でランタイムの安定性が維持されます。

 ## 特殊なケース

 重要なエッジケースの 1 つは、ボードが小さすぎて移動できない場合です。 入力の場合:```
N = 2
start = (0, 0)
end = (1, 1)
```BFS は次から始まります$(0,0)$。 8 つのナイトの動きはすべて即座に範囲外になります。 開始ノードの処理後、キューは空になります。 目標に到達しなかったため、アルゴリズムは戻ります。$-1$、正しい結果と一致します。 

別のケースでは、開始と終了が同一です。```
N = 5
start = (3, 3)
end = (3, 3)
```アルゴリズムは BFS の前にこれをチェックし、0 を直接返し、不必要な探索を防ぎます。 

3 番目のケースは、数回拡張した後にのみターゲットに到達できる場合です。```
N = 4
start = (0, 0)
end = (3, 3)
```BFS はレイヤーごとに拡張します。 複数のパスが中間セルに到達した場合でも、最初の$(3,3)$デキューまたは発見された場合は、最小移動数に相当します。 これにより、より長いルートを介してセルを再訪問するパスの過剰カウントが防止されます。
