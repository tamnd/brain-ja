 ## 解決策
 ## 問題の理解

 偶数の配列が与えられ、各配列は 1 からある共通の長さまでの数値の順列です。$n$。 どの配列でも許可される重要な操作は、最後の要素が先頭に移動する循環回転です。 順列を何回か回転させた後、順列が正確に一致する場合、その順列は「解決された」とみなされます。$[1,2,\dots,n]$。 

重要な点は、回転が実行される前に配列がペアになることです。 各配列は他の 1 つの配列と必ずペアにする必要があり、ペア内の 1 つの配列を回転すると、同じ回転がそのパートナーにも適用されます。 ペアの場合、単一のローテーション戦略を選択し、それを両方に同期的に適用します。 

ペアは、同じ回転数を使用して、ペア内の両方の配列をソートされた恒等順列に回転できる場合にのみ、正常に寄与します。 目標は、各ペアに最適な回転を適用した後、できるだけ多くの個々の配列がソートされるようにペアを選択することです。 

入力サイズは小さく、最大でも$10^3$順列、それぞれの長さは最大です$10^3$。 これにより、おおよそより悪いものは即座に除外されます$O(N \cdot n)$または$O(N \cdot n \log n)$。 すべてのペアリングに対する三次アプローチでは、ペアリングの数が階乗的に増加するため、非常に遅くなります。 

置換が循環シフトではない場合、微妙なエッジケースが発生します。$[1..n]$。 例えば、$[2,1,3,4]$ソート順に回転することはできません。 回転によって配列が変更されても、回転によってソートされたシーケンスが生成されることはないため、このような並べ替えは基本的に「解決不可能」であり、寄与するものとしてカウントされるべきではありません。 

もう 1 つのエッジ ケースは、複数の置換が有効な巡回シフトであるが、異なる回転オフセットに対応する場合です。 不一致のシフトを組み合わせると、それぞれが個別に解決可能であっても、両方が破壊されます。 

## アプローチ

 ブルートフォースの観点は、考えられるすべての組み合わせを試してみることを想像することから始まります。$N$配列。 次に、各ペアに対して、並べ替えられる要素の数を最大化する回転値を選択しようとします。 固定ペアリングの場合でも、実現可能性を確認するには各ペア内のローテーション要件を比較する必要があり、ペアリングの数はおおよそ天文学的に膨大になります。$(N-1)!!$。 これはすぐに実行不可能になります$N=1000$。 

重要な単純化は、順列は循環シフトである場合にのみ解決できるという観察から来ています。$[1..n]$。 有効な各置換には 1 つの定義回転オフセットがあります。値 1 の位置によって、それを前に揃えるのに必要な回転数が正確に決まります。構造の残りの部分が昇順に一致する場合、そのオフセットは配列全体で機能します。 

すべての順列が「無効」クラスまたはローテーション クラスのいずれかにマッピングされると、$r$の場合、問題は同一の回転クラスをグループ化することに帰着します。 同じグループ内で$r$、順列を任意にペアにすることができ、各ペアは正確に 2 つの解決された配列に寄与します。 グループ間の不一致や無効な順列が含まれる場合は、何も寄与しません。 

したがって、タスクはローテーション値の頻度を数え、各バケット内で形成できるペアの数を合計することになります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースペアリング | 指数 | O(N) | 遅すぎる |
 | 回転クラス別の周波数 | O(N・n) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各順列について、値 1 が出現する場所を特定します。 この位置は、配列を 1 から開始できる唯一の可能な回転を決定します。 
2. 順列が有効な巡回シフトであるかどうかを検証します。$[1..n]$。 1 の位置から開始して、配列を循環的に走査すると次の結果が得られるかどうかを確認します。$1,2,3,\dots,n$。 そうでない場合は、この順列を完全に破棄します。 
3. 有効な順列については、回転署名を計算します。$r$これは 1 のインデックスです。これは、並べ替えに必要な回転を一意に識別します。 
4. 各回転シグネチャに該当する順列の数をカウントする頻度配列または辞書を維持します。 
5. 各ローテーション署名について$r$、形成できるペアの数を計算します。$\lfloor \text{cnt}[r] / 2 \rfloor$。 このような各ペアは 2 つの暗号を解決します。 
6. すべての署名を合計して、最終的な答えを取得します。 

これが機能する理由は、2 つの順列を一緒に解決できる唯一の方法は、それらが回転まですでに同一である場合であるためです。 ペアの両方の配列が同時にソートされるためには、ペアの両方の配列が同じ回転値を共有する必要があるため、ペアリング制約は、同一の回転要件の一致を超える新たな柔軟性を導入しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    arrs = []
    for _ in range(n):
        parts = list(map(int, input().split()))
        arrs.append(parts[1:])

    freq = {}

    for p in arrs:
        m = len(p)

        # find position of 1
        pos1 = -1
        for i in range(m):
            if p[i] == 1:
                pos1 = i
                break

        # check cyclic shift validity
        ok = True
        for i in range(m):
            if p[(pos1 + i) % m] != i + 1:
                ok = False
                break

        if not ok:
            continue

        freq[pos1] = freq.get(pos1, 0) + 1

    ans = 0
    for c in freq.values():
        ans += (c // 2) * 2

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まずすべての順列を解析し、それぞれを個別に処理します。 1 の位置のスキャンは線形であり、検証ループにより、置換が単に有効なスポットに 1 があるだけではなく、真に同一性の循環シフトであることが保証されます。 

周波数マップには回転シグネチャが保存されます。 最終的な累積では、各グループが可能な限り多くの完全なペアに変換され、それぞれが 2 つの解決された配列に寄与します。 

実装の微妙な詳細は、無効な順列がバケット内でカウントされるのではなく、完全に無視されることです。 これらを有効なものと組み合わせると、どのローテーションでも並べ替えることができないため、決して有益ではありません。

このトレースは、正確さが完全に同一の回転シグネチャのグループ化に依存していることを示しています。 部分的な類似性だけでは十分ではありません。

 ## 特殊なケース

 微妙な失敗モードは、順列の「もっともらしい」位置に 1 があるものの、実際には単位の循環シフトではない場合に発生します。 例えば、$[1,3,2,4]$インデックス 0 に 1 がありますが、回転はソートされたシーケンスを生成しません。 このアルゴリズムは、1 の位置だけを信頼するのではなく完全な構造を明示的に検証し、そのようなケースが確実に除外されるようにします。 

もう 1 つのエッジ ケースは、周波数クラスが奇数の場合です。 たとえば、3 つの同一の有効な回転をすべて一緒に解決することはできません。 このアルゴリズムは正しくペアを 1 つだけ形成し、有利にペアにすることができない未使用の順列を 1 つ残します。 

最後のエッジケースは、すべての順列が無効な場合です。 その状況では、どのペアも完全に解決可能な構成を生成できないため、すべての周波数バケットは空になり、答えは正しくゼロになります。
