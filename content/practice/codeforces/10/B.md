 ## 解決策
 ## 問題の理解

 この問題は、ベルラントの映画館について説明しています。`K`行と`K`列ごとの座席、ここで`K`は常に奇数です。 顧客はさまざまなサイズのグループで来ます`M`連続した座席をリクエストします。 プログラムのタスクは、次のセグメントを割り当てることです。`M`選択された座席がホールの中心にできる限り近くなるように、一列に連続した座席を選択します。 複数の選択肢の「近さ」スコアが同じ場合、同点となるのは、最初に画面に近い列 (列番号が小さい)、2 番目にその列の左端の席です。 

入力により得られるのは、`N`リクエスト。それぞれグループのサイズを指定します。`M`。 出力では、リクエストごとに次のいずれかを指定する必要があります。`-1`リクエストが満たされない場合、または行とセグメントが満たされない場合`[y_l, y_r]`条件を満たすものです。 

制約が十分小さいため、O(`N*K^2`） 解決。 以来`K`が最大 99 である場合、各行内のすべての潜在的なセグメントの近さを評価することが可能です。 各リクエストは独立しているため、順番に処理されます。 エッジケースには、`K`(対応不可) および 1x1 ホールでのシングルシートのリクエスト。 

明白ではないエッジ ケースとしては、連続する複数のセグメントの近さが同じである場合、複数の行の最小の近さが同じである場合、ホールが最小である場合 (`K=1`) または同等のリクエスト`K`。 

## アプローチ

 ブルートフォースアプローチにより、考えられる長さのすべてのシートセグメントが検査されます。`M`行ごとに。 各セグメントについて、セグメント内のすべての座席を反復処理することにより、ホールの中心からの合計距離が計算されます。 考えられるすべてのセグメントをチェックした後、プログラムは必要に応じてタイブレーカーを適用して、合計距離が最小のセグメントを選択します。 これは、すべての可能性を明示的にチェックするので正しいですが、O(`N*K^2`）リクエストごとに実行され、大規模な場合に単純に実装するとわずかに遅くなる可能性があります`K`。 

最適なアプローチは、ホールが正方形で対称であるという事実を利用します。 セグメントの近さは、中央の列と中央の座席までの距離によってのみ決まります。 各座席の中心までの距離を事前に計算すると、プレフィックスの合計を使用してセグメントの合計距離を迅速に評価できます。 その後、リクエストごとに、アルゴリズムは各行を考慮し、次のサイズのスライディング ウィンドウを使用するだけで済みます。`M`最小合計距離を効率的に計算するためにプレフィックス合計を計算します。 これにより、冗長な計算が削減され、O( 以内に抑えながら解が高速になります。`N*K^2`）最悪の場合。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N * K^2) | お(1) | 正しいが効率は低い |
 | プレフィックス合計 + スライディング ウィンドウ | O(N * K^2) | O(K^2) | 与えられた制約に対して効率的かつ簡単 |

 ## アルゴリズムのチュートリアル

 1. ホールの中心座標を計算します。中心の行と中心の列は両方とも`(K + 1)//2`。 
2. 各行について、中央の列までの座席の距離の配列を事前計算します。 距離は`abs(row_center - row) + abs(seat_center - seat)`。 
3. 各行の距離のプレフィックス合計を計算します。 これにより、任意のセグメントの合計距離を計算できます。`[l, r]`O(1) 時間以内に。 
4. 各リクエストを処理する`M_i`順番に。 もし`M_i > K`、出力`-1`リクエストに対応できる行がないためです。 
5. それ以外の場合は、すべての行を反復処理します。 各行に、次のサイズのスライディング ウィンドウを使用します。`M_i`プレフィックス合計配列を調べてセグメントを見つけます`[y_l, y_r]`最小の合計距離で。 
6. 行全体にわたるグローバル最小値を追跡します。 複数のセグメントの最小合計距離が同じである場合は、画面に近い行を選択します。 まだ同点の場合は、一番左のセグメントを選択します。 
7. このリクエストに対して選択した行とセグメントを出力します。 

不変条件は、各リクエストについて、タイブレーカーを考慮してホールの中心に最も近いセグメントを常に選択することです。 距離を事前に計算し、プレフィックスの合計を使用することにより、考えられるすべてのセグメントが正確に評価されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def run():
    N, K = map(int, input().split())
    requests = list(map(int, input().split()))
    center = (K + 1) // 2
    distances = [[0] * K for _ in range(K)]
    
    for r in range(K):
        for c in range(K):
            distances[r][c] = abs(r + 1 - center) + abs(c + 1 - center)
    
    prefix_sums = [[0] * (K + 1) for _ in range(K)]
    for r in range(K):
        for c in range(K):
            prefix_sums[r][c + 1] = prefix_sums[r][c] + distances[r][c]
    
    for M in requests:
        if M > K:
            print(-1)
            continue
        best_total = float('inf')
        best_row, best_left = -1, -1
        for r in range(K):
            for l in range(K - M + 1):
                total = prefix_sums[r][l + M] - prefix_sums[r][l]
                if total < best_total or (total == best_total and r < best_row) or (total == best_total and r == best_row and l < best_left):
                    best_total = total
                    best_row = r
                    best_left = l
        print(best_row + 1, best_left + 1, best_left + M)

if __name__ == "__main__":
    run()
```コードは距離とプレフィックスの合計を事前計算します。 リクエストごとに、次のサイズのウィンドウを効率的にスライドさせます。`M`すべての行にわたって。 同点は、最初に列番号によって分割され、次に左席のインデックスによって分割されます。

 ## 特殊なケース

 エッジケースの 1 つは次のような場合です`M > K`、そのためグループで着席することができなくなります。 コードはこれをチェックし、すぐに出力します。`-1`。 

別のエッジ ケースは、異なる行の複数のセグメントの最小合計距離が同じである場合に発生します。 アルゴリズムは、行 0 から K-1 までを繰り返し、合計が小さいか、行の方がタイで小さい場合にのみ更新するため、画面に近い行を選択し、タイ ブレーカーを正しく実装します。 

3 番目のエッジ ケースは、同じ行内の複数のセグメントの合計距離が同じである場合です。 アルゴリズムはチェックして左端のセグメントを選択します。`l < best_left`同点の場合は、中央に最も近い座席セグメントが選択されるようにします。 たとえば、M=2 で行 3 の距離が次の場合、`[2,1,1,2]`、それは選択します`[2,3]`それよりも`[1,2]`合計距離が等しい場合、これはタイブレーカー ロジックによって正しく処理されます。
