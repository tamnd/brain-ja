 ## 解決策
 ## 問題の理解

 2 つの整数配列が与えられます。 2 つの条件を同時に満たす最長のシーケンスを構築する必要があります。 

シーケンスは両方の配列のサブシーケンスとして現れる必要があります。つまり、要素をスキップすることはできますが、相対的な順序を変更することはできません。 

シーケンスも厳密に増加する必要があります。 

これは通常の LCS とも異なり、通常の LIS とも異なります。 通常の LCS は増大する要件を無視しますが、通常の LIS は 1 つのアレイ内でのみ機能します。 ここでは、両方の制約を同時に満たす必要があります。 

たとえば、配列が次の場合:```
A = [2, 3, 1, 6, 5, 4, 6]
B = [1, 3, 5, 6]
```それから`[3, 5, 6]`は両方の配列に現れ、厳密に増加しているため、有効です。 

制約は二次動的計画法を可能にするのに十分小さいものです。 どちらの長さも最大 500 なので、`O(n * m)`または`O(n * m * something small)`解決策は大丈夫です。 三次解は危険です。`500^3 = 125,000,000`Python では 1 秒の制限時間内では大きすぎる操作です。 

厄介な点は、増加条件は値に依存するのに対し、後続条件は位置に依存することです。 インデックスのみを追跡する不注意な DP では、これら 2 つの要件が誤って混合されることがよくあります。 

よくある間違いの 1 つは、問題を通常の LCS として扱い、後で昇順をチェックすることです。 

考慮する：```
A = [3, 2, 1]
B = [3, 2, 1]
```通常のLCSは長さが3ですが、`[3, 2, 1]`減少しています。 正しい LCIS 長は 1 のみです。 

もう 1 つの微妙なケースには重複が含まれます。```
A = [1, 1, 1]
B = [1, 1]
```答えはまだです`[1]`、 ない`[1, 1]`シーケンスは厳密に増加する必要があるためです。 可能にする移行`<=`の代わりに`<`黙って間違った答えを生み出します。 

シーケンスを再構築すると、さらに危険なバグが発生します。```
A = [1, 2, 3]
B = [1, 3, 2]
```答えの長さは 2 ですが、`[1, 2]`有効です。 再構築で 2 番目の配列からの順序情報が無視されると、誤って構築される可能性があります。`[1, 3]`に続く`2`。 

DP 状態は、値の増加の有効性とサブシーケンス順序の有効性の両方を同時にエンコードする必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。 最初の配列の増加するすべてのサブシーケンスを生成し、それが 2 番目の配列のサブシーケンスでもあるかどうかを確認します。 位置のすべてのサブセットがサブシーケンスを形成する可能性があるため、候補の数はおおよそ指数関数的になります。`2^n`。 剪定しても一度では無理になる`n`500に近づきます。 

より構造化されたブルート フォース アプローチでは、古典的な LCS DP が使用され、増加する制約が追加されます。 次のように定義できます。```
dp[i][j][k]
```どこ`k`何らかの方法で、以前に選択された値またはインデックスを追跡します。 これはすぐに立体的かさらに悪化します。`(i, j)`以前のすべての状態からの遷移が必要になる場合があります。 と`500^3`移行、Python の苦戦。 

重要な観察は、固定要素を処理するとき、`A[i]`、以下の値で終わる共通の部分列のみを考慮します。`A[i]`。 

で終わる共通の増加サブシーケンスが必要だとします。`B[j]`、 どこ`A[i] == B[j]`。 

以前のシーケンスを拡張するには、次のものが必要です。```
B[k] < B[j]
```そして```
k < j
```なぜなら、シーケンスは増加し続け、順序を維持する必要があるからです。`B`。 

これまでのあらゆるポジションの中で、重要なのは最適な長さだけです。 

これにより、高価な遷移検索がローリング最大値に折りたたまれます。 

以下を定義します。```
dp[j] = length of the best LCIS ending at B[j]
```そして、スキャンしながら、`B`固定の場合は左から右へ`A[i]`、私たちは次のように維持します。```
current = best dp[k] where B[k] < A[i]
```今、いつ`A[i] == B[j]`、すぐに次のように設定できます。```
dp[j] = current + 1
```これにより、内部の遷移ループが完全に削除されます。 すべてのペア`(i, j)`は 1 回処理され、`O(n * m)`解決。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * m) 以上 | O(2^n) | 遅すぎる |
 | 最適 | O(n * m) | O(m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を作成する`dp[j]`どこ`dp[j]`で終わる最長の共通増加サブシーケンスの長さを格納します。`B[j]`。 
2.`parent[j]`再構築用の配列。 これにより、以前のインデックスが保存されます`B`以前に使用された`j`。 
3. すべての要素を反復処理する`A[i]`。 
4. 現在のところ`A[i]`、2 つの変数を維持します。`best_len`、これまでに見つかった最大の LCIS 長さ`B`より小さい値で。`best_pos`、のインデックス`B`最高のシーケンスが終わる場所。 
5.スキャン`B`左から右へ。 
6. もし`B[j] < A[i]`、 それから`B[j]`前に現れる可能性があります`A[i]`増加する順序で。 

もし`dp[j] > best_len`、 アップデート`best_len`そして`best_pos`。 
7. もし`A[i] == B[j]`、その後、より小さい値で終わる最適なシーケンスを拡張できます。 

もし`best_len + 1 > dp[j]`、 アップデート：```
dp[j] = best_len + 1
parent[j] = best_pos
```8.すべてのペアになるまで続けます`(i, j)`処理されます。 
9. 位置を見つける`j`最大で`dp[j]`。 
10. 次のようにして答えを再構築します。`parent[j]`後ろ向きに。 
11. 再構築は終わりから始まりに向かって進むため、再構築されたシーケンスを逆にします。 

### なぜ効果があるのか

 固定ごとに`A[i]`、スキャンが終了しました`B`法的に認められる最高の LCIS を維持します。`A[i]`。 スキャンするので`B`左から右に、保存されているすべての候補はすでに部分列の順序付けを満たしています。`B`。 

条件`B[j] < A[i]`厳密な増加を保証します。 候補がスキャンの早い段階で見つかったという条件により、インデックスの増加が保証されます。`B`。 

いつでも`A[i] == B[j]`、延長`best_len`で終わる最適な LCIS を生成します。`B[j]`までの要素を使用する`A[i]`。 

スキャン中に以前の小さい値がすべて考慮されるため、有効な遷移が見逃されることはありません。 それ以上の値は更新されないため、無効な遷移は使用されません。`best_len`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    m = int(input())
    b = list(map(int, input().split()))

    dp = [0] * m
    parent = [-1] * m

    for i in range(n):
        best_len = 0
        best_pos = -1

        for j in range(m):
            if b[j] < a[i]:
                if dp[j] > best_len:
                    best_len = dp[j]
                    best_pos = j

            elif b[j] == a[i]:
                if best_len + 1 > dp[j]:
                    dp[j] = best_len + 1
                    parent[j] = best_pos

    length = 0
    end_pos = -1

    for j in range(m):
        if dp[j] > length:
            length = dp[j]
            end_pos = j

    sequence = []

    while end_pos != -1:
        sequence.append(b[end_pos])
        end_pos = parent[end_pos]

    sequence.reverse()

    print(length)

    if length:
        print(*sequence)
    else:
        print()

solve()
```配列`dp[j]`中央のDP州です。 特に次の場所で終わる最適な LCIS が保存されます。`B[j]`。 すべての有効なサブシーケンスには固有の最後の位置があるため、これで十分です。`B`。 

変数`best_len`そして`best_pos`ごとにリセットされる`A[i]`。 これらは、スキャン中にこれまでに発生したすべての有効な以前の遷移を要約します。`B`。 

内側のループ内の条件の順序が重要です。 改善するために、最初に小さい値の位置を使用します。`best_len`。 後で等しい値がその情報から拡張される可能性があります。 

厳密な比較:```
if b[j] < a[i]:
```は不可欠です。 それを次のものに置き換えると、`<=`厳密な増加を破り、誤って重複を許可します。 

再構築配列は内部にインデックスを格納します`B`、価値観ではありません。 これにより、重複した値が存在する場合のあいまいさが回避されます。 

最終的な再構成は逆方向に進みます`parent`。 親は以前の要素を指しているため、収集されたシーケンスは最後に反転する必要があります。

 ## 特殊なケース

 重複の多い配列を考慮してください。```
A = [1, 1, 1]
B = [1, 1]
```それぞれ処理しながら`1`、アルゴリズムは決して更新されません`best_len`条件では厳密に小さい値が必要になるためです。 その結果、すべての一致で長さ 1 のシーケンスのみが作成されます。アルゴリズムは次を正しく出力します。```
1
1
```ここで、通常の LCS が失敗するケースを考えてみましょう。```
A = [3, 2, 1]
B = [3, 2, 1]
```DP は次のように進化します。```
After 3: dp = [1,0,0]
After 2: dp = [1,1,0]
After 1: dp = [1,1,1]
```値は常に減少するため、どの要素も別の要素を拡張することはできません。 最大長は 1 のままです。 

最後に、順序付けの罠について考えてみましょう。```
A = [1, 2, 3]
B = [1, 3, 2]
```加工時`2`、以前の最良の値は`1`、アルゴリズムが構築されます`[1,2]`。 

その後、処理中に`3`から延長することはできません`2`なぜなら`2`後に表示されます`3`配列内`B`。 左から右へのスキャンにより、サブシーケンスの順序が自動的に強制されます。`B`。 

アルゴリズムは正しく出力します。```
2
1 2
```
