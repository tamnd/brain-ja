 ## 解決策
 ## 問題の理解

 私たちは、小銭を作るための貪欲なアルゴリズムが特定の硬貨の種類のセットで失敗する可能性があるかどうかを調査するように求められています。 具体的には、1 で終わる降順にソートされたコインの価値のリストが与えられ、欲張りが必要以上に多くのコインを使って得られる金額が存在するかどうかを知りたいとします。 出力は次のいずれかです`-1`貪欲が常に最適な場合、または貪欲がコインを過剰に使用する場合の最小額。 

入力には最大 400 の異なる金種があり、それぞれ最大 10^9 です。 なぜなら`n`は小さいが、コインの価値が大きい場合、最大のコインの価値までのすべての合計を明示的にシミュレートするソリューションは実行不可能になります。 一方で、コインの種類の数が少ないため、貪欲に行うと失敗する可能性がある少額を構築するために、次に大きい額面とどのように相互作用するかという観点から各額面を考慮することができます。 

エッジケースには、すべての金種が互いの倍数である場合、貪欲が常に最適である場合、またはセットに連続する金種間にギャップがある場合、つまり小さなコインの微妙な組み合わせにより、貪欲が選択したコインよりも少ないコインが生成される可能性がある場合が含まれます。 たとえば、コイン {1, 3, 4} が与えられた場合、greedy は合計 6 で失敗し、最適な 3 + 3 ではなく 4 + 1 + 1 が生成されます。「greedy は合計を出せるか?」をチェックするだけの単純な実装です。 使いすぎの微妙さを見逃してしまいます。 

## アプローチ

 ブルートフォースアプローチは簡単です。1 から上のすべての合計を試し、貪欲なコイン数を計算し、それを必要なコインの最小数と比較します。これは動的プログラミングによって計算できます。 これは正しいですが、遅すぎます。 最大 10^9 のコインでは、合計を反復することは不可能です。 合計をヒューリスティックな最大値に制限したとしても、DP 配列は依然として巨大になる可能性があります。 

重要な観察は、貪欲な失敗は非常に局所的なパターンで発生するということです。つまり、合計がいくつかのコインの倍数をわずかに上回るということです。`c`より大きなコインだけを使用して最適に形成することはできません。 もっと具体的に言えば、`a[i]`そして`a[i+1]`連続したコインであるため、間の合計では貪欲に失敗する可能性があります`a[i] + 1`そして`a[i] + a[i+1] - 1`。 これにより、検索スペースが、単位ペアあたり数十億の合計から数百の候補合計に減少します。 

最適なアプローチは、連続する額面の組み合わせを使用して合計をシミュレートすることにより、これを利用します。`a[i]`の倍数`a[i+1]`次の合計を形成します。 これにより、考えられるすべての合計を列挙することなく、貪欲が失敗した最初の合計を確実に取得できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース DP | O(n * X) | O(X) | 大きな X には遅すぎます |
 | 候補シミュレーション | O(n^2) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各コインを反復処理することから始めます`a[i]`最後のコイン (1) を無視して、最大から最小の順に並べます。 それぞれについて、次の組み合わせを使用して形成できる合計を検討します。`a[i]`そして小さめのコイン。 
2. 各候補の合計について`s = a[i] * k + t`、 どこ`k`の数です`a[i]`コインと`t`は小さいコインで形成される合計なので、貪欲なコインの数を計算します。 これは、残りの合計を超えない範囲で最大のコインを繰り返し取ることによって行われます。 
3. 以下の合計に対して、制限付き DP アプローチを使用して、コインの最小数を独立して計算します。`a[i] + a[i+1]`。 貪欲なカウントと最適なカウントを比較します。 
4. 貪欲なカウントが最適なカウントを超える最小の合計を追跡します。 最低限の金額しか必要ないので、見つかったら早めに休憩しましょう。 
5. すべてのコインペアを考慮した後にそのような合計が見つからない場合、出力`-1`。 

なぜ機能するのか: 貪欲の失敗は常に、あるコインとその次に小さなコインの間の狭い範囲内で発生します。 これらの範囲のみを考慮することで、最小の失敗合計が取得されることが保証されます。 不変条件は、以下の合計に対するものです。`a[i] + a[i+1]`、より大きなコインの組み合わせでは、私たちがチェックした方法よりも最適な表現を作成することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    coins = list(map(int, input().split()))
    
    for i in range(n - 1):
        c1 = coins[i]
        c2 = coins[i + 1]
        max_needed = c1 + c2
        # try sums from c1 + 1 to c1 + c2 - 1
        for x in range(c1 + 1, max_needed):
            # greedy simulation
            rem = x
            greedy_count = 0
            for coin in coins:
                use = rem // coin
                greedy_count += use
                rem -= use * coin
            # optimal simulation via bounded DP
            dp = [float('inf')] * (x + 1)
            dp[0] = 0
            for j in range(x + 1):
                if dp[j] == float('inf'):
                    continue
                for coin in coins[i+1:]:
                    if j + coin <= x:
                        dp[j + coin] = min(dp[j + coin], dp[j] + 1)
            if greedy_count > dp[x]:
                print(x)
                return
    print(-1)

if __name__ == "__main__":
    main()
```最初のループはコインのペアを反復して、貪欲が失敗する可能性がある最小の合計を見つけます。 各候補の合計について、より小さいコインのみを使用して貪欲な選択と制限された DP をシミュレートします。 までの合計のみをチェックするため、DP 配列のサイズは小さくなります。`c1 + c2`。 外側のループにより、最小不合格和が見つかることが保証され、アルゴリズムは発見されるとすぐに停止します。 範囲を慎重に選択することで、オフバイワンエラーを回避できます。`c1 + 1`に`c1 + c2 - 1`。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n^2) | n 個のコインに対する外側のループ、最大 2n 個の候補合計に対する内側のループ、それぞれ O(a[i] + a[i+1]) 合計に対する貪欲で制限された DP をシミュレートしますが、合計は ≤ 2*10^9 であるため、制限付き DP は狭い範囲のみを使用します。 
| スペース | O(a[i] + a[i+1]) | DP 配列は、候補合計までの最小限のコイン (最大でも c1 + c2 要素) を保管します。 

n ≤ 400 の場合、これは十分に制限内です。 狭い DP 範囲と早期終了により、このソリューションは実用的になります。
