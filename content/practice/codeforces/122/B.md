 ## 解決策
 ## 問題の理解

 この問題では、指定された数字列の「最も幸運な」部分文字列を見つけるように求められます。 最も幸運とは、数字 4 と 7 のみで構成され、文字列内にできるだけ多く出現し、同点の場合は辞書編集上最小となる部分文字列を意味します。 入力文字列は 1 文字または最大 50 文字にすることができ、ゼロを含む任意の数字を含めることができます。 出力は単一の幸運な部分文字列、または存在しない場合は「-1」である必要があります。 

最大入力長が 50 文字と小さい場合、およそ O(n²) または O(n·m) 時間で実行されるソリューションは効率的に実行されます。 文字列に 4 や 7 がまったく含まれていない場合、微妙なエッジ ケースが発生します。この場合、正しい答えは「-1」になります。 もう 1 つのエッジ ケースは、複数のラッキーな部分文字列が同じ回数出現するが、辞書編集的に最小のものだけが返される必要がある場合です。 たとえば、文字列では`"4747"`、幸運な部分文字列`"4"`そして`"7"`それぞれ2回ずつ登場しますが、`"4"`返還されるべきです。 

入力長が短いため、すべての部分文字列を試す単純なアプローチも実現可能ですが、複数桁の幸運な数字は個々の数字より厳密に頻度が低いため、部分文字列として出現率を最大化できるのは 1 桁の '4' と '7' だけであることに注目することで、さらに単純化することができます。 

## アプローチ

 ブルートフォースアプローチでは、入力文字列の考えられるすべての部分文字列を生成し、幸運なものをフィルタリングし、それぞれの出現回数をカウントし、最後に最大頻度のものを選択します。 長さ n の文字列のすべての部分文字列を生成するには、およそ n · (n+1)/2 個の部分文字列が必要で、単純に実装した場合、それぞれの出現回数をカウントすると、合計操作数が O(n³) になる可能性があります。 n ≤ 50 の場合、これは実行可能ですが、不必要に複雑になります。 

重要な観察は、長さが 1 より大きい幸運な部分文字列は、それぞれ「4」または「7」よりも多く出現できないということです。 これは、長い部分文字列が正確に一致するには連続した数字が必要であるためです。 したがって、「4」が何回発生するか、「7」が何回発生するかを数えるだけで済みます。 結果は、最も頻繁に出現する数字になります。辞書編集的に小さいオプションとして「4」を選択すると、同点は解消されます。 これにより、解が O(n³) から O(n) に減り、シンプルかつ堅牢になります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n3) | O(n²) | n≤50 の場合は実現可能ですが、やりすぎです |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのカウンタを初期化します。1 つは「4」、もう 1 つは「7」です。 これらは、それぞれが文字列内に出現する回数を追跡します。 これは、個々の数字のみが周波数を最大化できるという観察を直接ターゲットにしています。 
2. 文字列内の各文字を繰り返し処理します。 各文字について、それが「4」の場合、「4」カウンターをインクリメントします。 「7」の場合は、「7」カウンタをインクリメントします。 他の数字は幸運な数字を形成できないため、すべて無視します。 
3. 数えた後、どの桁がより頻繁に発生するかを確認します。 「4」が「7」よりも頻繁に出現する場合、答えは次のようになります。`"4"`。 「7」がより頻繁に出現する場合、答えは次のようになります。`"7"`。 両方が同じように発生する場合は、次を選択します`"4"`辞書編集的に小さいからです。 
4. 文字列に「4」も「7」も現れない場合は、「-1」を返します。 

このアルゴリズムが機能するのは、複数桁のラッキー部分文字列がその構成桁よりも高い頻度を持つことができないことが保証されているためです。 不変条件は、数えた後、これら 2 つの 1 桁の幸運な数字のうちの 1 つが常に、幸運な部分文字列の最大可能頻度を表すということです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

s = input().strip()

count4 = 0
count7 = 0

for ch in s:
    if ch == '4':
        count4 += 1
    elif ch == '7':
        count7 += 1

if count4 == 0 and count7 == 0:
    print("-1")
elif count4 >= count7:
    print("4")
else:
    print("7")
```このコードはカウンターを初期化し、文字列を 1 回スキャンします。 「4」と「7」のみがカウンターに影響します。 最終的な決定には単純な比較が使用されます。 最初に幸運な数字がないという特殊なケースを確認し、「-1」を返します。 タイブレーク ルールは比較によって自然に処理されます。`count4 >= count7`。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    s = sys.stdin.readline().strip()
    count4 = 0
    count7 = 0
    for ch in s:
        if ch == '4':
            count4 += 1
        elif ch == '7':
            count7 += 1
    if count4 == 0 and count7 == 0:
        return "-1"
    elif count4 >= count7:
        return "4"
    else:
        return "7"

# Provided samples
assert run("047\n") == "4", "sample 1"
assert run("123\n") == "-1", "sample 2"
assert run("7\n") == "7", "sample 3"

# Custom cases
assert run("4747\n") == "4", "equal counts, tie-break"
assert run("4447777\n") == "7", "7 occurs more"
assert run("4444444\n") == "4", "only 4s"
assert run("0\n") == "-1", "no lucky digits"
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 文字列に幸運の数字が含まれていない場合、次のようになります。`"1230"`の場合、アルゴリズムは両方の桁でゼロを正しくカウントし、「-1」を出力します。 '4' と '7' の数が等しい文字列の場合、次のようになります。`"4747"`、アルゴリズムは正しく「4」を優先します。 1 種類の幸運の数字のみが複数回繰り返される文字列の場合、アルゴリズムはその数字を正しく返します。たとえば、`"7777"`返品`"7"`。 これらの各シナリオは、最終比較ロジックによって明示的に処理されます。
