 ## 解決策
 ## 問題の理解

 いくつかの独立したテスト ケースが与えられています。 各テスト ケースには複数のサイコロがあり、すべてのサイコロの面にはちょうど 6 つの正の整数が書かれています。 サイコロを一列に配置するとき、選択した各サイコロから正確に 1 つの面を選択し、そのサイコロの「一番上の」値とします。 私たちの目標は、サイコロのサブセットを選択し、選択した各サイコロに額面の 1 つを割り当て、選択した値が一連の連続する整数を形成するようにすることです。 タスクは、そのようなシーケンスに含めるサイコロの数を最大化することです。 

問題を再解釈する便利な方法は、各ダイが最大 6 つの候補値を提供すると考えることです。選択したダイごとに 1 つの値を選択して、最終的なマルチセットをギャップのない可能な限り長い整数の連続に順序付けできるようにしたいと考えています。 

制約は全体として大きく、すべてのテスト ケースで最大 200,000 個のダイスがあります。 これにより、サイコロのすべてのサブセットのチェックや、サイコロ全体に値を割り当てるすべての方法に依存するものは即座に除外されます。 サイコロ上の二次法でも遅すぎるでしょう。 実行可能なアプローチでは、各ダイをほぼ直線的な時間で処理し、グローバル構造を繰り返しスキャンすることを回避する必要があります。 

微妙な点は、異なるサイコロが値を共有することができ、同じサイコロが複数回出現する可能性があることです。 同じ番号が複数出現する場合、重複を再利用して連続実行を延長できるため、これは重要です。 

エッジケースは、サイコロの値が非常にまばらで接続されていない場合に発生します。 たとえば、連続互換性のある値を共有する 2 つのサイコロがない場合、答えは 1 に集約されます。もう 1 つのまれなケースは、多くのサイコロに重複する範囲が含まれる場合であり、個々のサイコロが不規則であっても長い連鎖が可能になります。 同じダイが複数の異なる数値をサポートする可能性があり、早すぎるコミットはより長いチェーンをブロックする可能性があるため、ダイごとの素朴な貪欲な選択はここで失敗する可能性があります。 

## アプローチ

 ブルートフォース解釈では、各サイコロに値を割り当て、次に考えられるすべてのサイコロのサブセットをチェックして、どれが連続シーケンスを形成できるかを確認しようとします。 目標間隔を固定したとしても、どのダイスがどの数値に寄与するかを決定する必要があり、各ダイスには 6 つの選択肢があります。 これは爆発的な増加につながります。およそ O(6^N) 個の割り当て、または少なくとも O(N · 2^N) 個のサブセット探索です。 これは20万どころか50歳くらいのNでも無理です。 

重要な観察は、実際にはすべてのサイコロを使用する必要はなく、各サイコロは最大 1 回使用できるということです。 重要なのは、利用可能なサイコロを使用して連続する整数区間を「カバー」できるかどうかです。各サイコロはその区間から最大 1 つの整数に寄与します。 これにより、割り当てに関する組み合わせ論から、間隔に関する実現可能性の問題に視点が変わります。 

固定整数値 x については、どのサイコロが x を生み出すことができるかを知ることだけが必要です。 ある数値 L から始まる連続セグメントを構築しようとする場合、唯一の要件は、セグメント内の整数ごとに、それを含む未使用のダイが少なくとも 1 つあることです。 これは、貪欲な構造を示唆しています。つまり、現在のセグメントを可能な限り拡張し、常に整数ごとに 1 つの利用可能なダイを消費します。 

これを効率的に行うために、各値について、その値を含むサイコロのリストを事前計算します。 次に、各値をグローバル スイープの位置として扱い、貪欲にサイコロを一致させて最長の連続実行を延長します。 

問題は、整数ライン上の最長の間隔を見つけて、その中のすべての整数に個別のサイコロを割り当て、各サイコロがサポートする値に割り当てられるようにすることに帰着します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 割り当てに対するブルートフォース | O(6^N) | O(N) | 遅すぎる |
 | 値インデックスによる貪欲なマッチング | O(N log N) または O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

1. サイコロに現れる各整数値から、それを含むサイコロのインデックスのリストへのマッピングを構築します。 これにより、面の選択肢が値とサイコロの間の隣接情報に変換されます。 これが役立つ理由は、どの面がその数値を生成するかではなく、ダイが特定の数値をサポートできるかどうかだけを気にするためです。 
2. すべてのサイコロに表示されるすべての個別の値を並べ替えます。 これにより、連続したセグメントを形成する際に一貫した左から右の順序が得られます。 並べ替えがなければ、間隔を増やすことを確実に試みることはできません。 
3. ソートされた値をスイープし、連続したチェーンを構築する貪欲な試みを維持します。 開始値については、未使用のダイを各ステップに割り当てることができるかどうかを追跡しながら、一度に 1 つの整数を前方に拡張しようとします。 
4. 現在の値 x について、現在のチェーンで使用されていない x を含むサイコロのリストからサイコロを選択します。 そのダイを使用済みとしてマークし、x + 1 に進みます。そのようなダイが存在しない場合、選択した開始値で始まるチェーンはその時点で失敗します。 
5. 達成された最大チェーン長を追跡しながら、ソートされた値リスト内の可能な開始位置ごとにプロセスを繰り返します。 答えは、正常にカバーされる連続する整数の最大数です。 

微妙な設計上の選択は、サイコロの再利用の制約です。 ダイがチェーン内で使用されると、同じチェーン内で再度貢献することはできなくなり、ポジションごとに 1 つのダイの要件が強制されます。 

### なぜ効果があるのか

 このアルゴリズムは、貪欲なマッチングの不変式に依存しています。つまり、L から始まる試行された連続セグメントに対して、拡張時に各整数に対して最初に使用可能な未使用のダイを常に割り当てます。 ある整数 x で有効なダイが見つからない場合、以前に選択した割り当てを再配置しても、以前の割り当てに違反することなく問題を解決できません。これは、以前のすべての整数がそれをサポートするダイをすでに消費しており、それらのいずれかを置き換えることは、以前の位置の柔軟性を低下させるだけであるためです。 これにより、貪欲な拡張機能が固定開始に対して局所的に最適になり、最初の障害点が回避できないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import defaultdict

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N = int(input())
        
        value_to_dice = defaultdict(list)
        dice = []
        
        for i in range(N):
            faces = list(map(int, input().split()))
            dice.append(faces)
            for v in faces:
                value_to_dice[v].append(i)
        
        # unique sorted values
        values = sorted(value_to_dice.keys())
        
        best = 0
        
        used = [False] * N
        
        # try each start
        for i in range(len(values)):
            # reset used for each attempt
            for j in range(N):
                used[j] = False
            
            start = values[i]
            cur = start
            length = 0
            
            # attempt to extend consecutive sequence
            while True:
                if cur not in value_to_dice:
                    break
                
                picked = -1
                for d in value_to_dice[cur]:
                    if not used[d]:
                        picked = d
                        break
                
                if picked == -1:
                    break
                
                used[picked] = True
                length += 1
                cur += 1
            
            best = max(best, length)
        
        print(f"Case #{tc}: {best}")

if __name__ == "__main__":
    solve()
```この実装は、貪欲な拡張のアイデアに直接準拠しています。 の`value_to_dice`マップは中心的な構造であり、特定の整数を生成できるすべてのサイコロへの定時アクセスを可能にします。 

の`used`配列は、各ダイが試行されたチェーンごとに 1 回だけ使用されることを保証します。 各試行が独立するように、開始値ごとにリセットします。 

内側のループはインクリメントします`cur`段階的に、値が完全に欠落しているか、未使用のダイが現在の値をサポートできない場合に停止します。 

実際的な懸念は、完全にリセットすると、`used`開始ごとの配列は高価になる可能性がありますが、ロジックはシンプルかつ正確に保たれます。 最適化されたバージョンでは、代わりにタイムスタンプまたは実行ごとのマーカーを使用します。

 ## 特殊なケース

 例外的なケースの 1 つは、すべてのサイコロが共通の値を共有する場合に発生します。 すべてのサイコロに含まれる入力の場合`1`、マッピングはすべてのサイコロを同じ整数に割り当てます。 アルゴリズムは次から始まります`1`、サイコロを 1 つ選ぶと、すぐに未使用のサイコロが見つかりません。`2`したがって、チェーンの長さは 1 のままです。同じダイを再利用しようとすると制約に違反するため、これは正しいです。 

もう 1 つのエッジ ケースは、値がサイコロ間で完全にインターリーブされている場合です。たとえば、1 つのサイコロがすべての奇数をカバーし、もう 1 つのサイコロがすべての偶数をカバーする場合です。 各整数ステップがその値に使用可能なすべてのダイスを参照し、未使用のダイスを選択するため、アルゴリズムはこれらを自然に交互に実行し、チェーンを完全に拡張できます。 

3 番目のエッジ ケースは、グローバル セット内に値が存在するが連続していない場合に発生します。 たとえば、サイコロには次のようなものしか含めることができません。`10, 100, 1000`。 スイープは依然として各開始を試行しますが、すべての拡張機能はすぐに失敗します。`x + 1`がマッピングに存在しないため、最大長は 1 が正しく生成されます。
