 ## 解決策
 ## 問題の理解

 私たちには、3D 空間の開始点、目標点、およびテレポーターと呼ばれる最大約 150 個の特別な点が与えられます。 移動は自由ではありません。移動する唯一の方法は、テレポーターを選択し、制限されたジャンプを実行することです。 

各テレポーターはマンハッタンの距離に基づいたルールを課します。 ある点に立ってテレポーターを見ると、ジャンプ中にテレポーターまでの L1 距離は固定されます。 同じテレポーターまでの L1 距離がまったく同じである空間内の他の点にテレポートできます。 ジャンプ後、宇宙のどこか別の場所に着陸しますが、その後の移動は再びテレポーター経由で行う必要があるという制約を失うことはありません。 

タスクは、これらの制限されたジャンプのみを使用して目的地に到達できるかどうかを判断し、到達できる場合はテレポート操作の数を最小限に抑えることです。 

重要な微妙な点は、目的地が必ずしもテレポーターである必要はなく、中間位置が任意の実座標になる可能性があることです。 したがって、状態空間は連続的ですが、重要な構造はテレポーターによってのみ誘発されます。 

N ≤ 150 という制約が実際の信号です。 連続空間上で直接ジオメトリを探索しようとするソリューションは実行可能ではありません。 到達可能な幾何学的領域のすべてのペアの間の関係を保存するだけでも、単純に連続的なものとして扱うと、あまりにも大きくなりすぎます。 

自然故障モードでは、各テレポーターを等距離の点間の単純なグラフ エッジとして解釈しようとします。 これは不正確です。1 つのテレポーターが、単一の目的地ではなく、点の無限の表面全体に点を接続するからです。 

もう 1 つのよくある落とし穴は、2 つの点が両方ともテレポーターに近い場合、それらは交換可能であると仮定することです。 それは誤りです。重要なのは距離の等価性だけであり、相対的な順序やしきい値は重要ではありません。 

小さな失敗例: テレポーターが (0,0,0) にあると仮定します。 (1,0,0) から、原点からマンハッタン距離 1 の任意の点にジャンプできます。 これには、(0,1,0)、(0,0,1)、(1,0,0)、(-1,0,0) など、無限に多くのものが含まれます。 これを有限隣接リストとして扱うと、到達可能な状態のほとんどが失われます。 

## アプローチ

 強引な解釈では、到達可能なすべての点をグラフ内のノードとして扱い、幾何学的にジャンプをシミュレートしようとします。 現在の点 p とテレポーター i から、i までのマンハッタン距離が p のマンハッタン距離と等しくなるように、すべての点 q を生成します。 このような各セットは 3D 空間内の無限に連続したサーフェスであるため、これはすぐに爆発します。 座標は無制限の実数値であるため、空間を離散化することさえ不可能です。 

構造の単純化は視点の変化から来ています。実際には幾何学的にどこに着陸するかは気にしておらず、各テレポーターに関してどの平等制約を満たすかだけを気にしています。 

テレポーターを修理する i. 関数 di(p) を p から i までのマンハッタン距離として定義します。 i を使用したテレポートでは、この値が保持されます。 したがって、テレポーター i を使用するすべての有効な動きは、di のレベル セット内に留まります。 

これにより、各テレポーターは、空間内のすべての点を 1 つの実数でラベル付けされた同値クラスに分割したものになります。 2 つのポイントが i を介して直接接続できるのは、それらが di の下で同じクラスにある場合に限ります。 

したがって、ジオメトリについて考える代わりに、指定された特別な点に開始点と終了点を加えたものを頂点とするグラフを構築します。 各テレポーター i について、頂点ごとに di を計算します。 同じ値を共有するすべての頂点は、いずれかの頂点から等しい距離で他の頂点にジャンプできるため、1 回の移動で i を介して完全に接続されます。 

これにより、きれいなグラフ構造が得られます。エッジはテレポーターごとに暗黙的なクリークですが、明示的に構築することはありません。 代わりに、最短パス検索中にオンデマンドで同値クラスを処理します。

ノード上の標準的な BFS は、「テレポーターを 1 回使用する」を 1 つのステップとして扱い、テレポーターの値のペアごとに 1 回だけ、テレポーターの同じ値を共有するすべてのノードを動的に拡張する場合に機能します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルーフォース幾何学シミュレーション | 無限 / 指数 | 無限 | 不可能 |
 | 暗黙的な等価グループ上の BFS | O(N² log N) | O(N²) | 承認済み |

 ## アルゴリズムのチュートリアル

 ### ## アルゴリズムのチュートリアル

 1. 出発地、目的地、およびすべてのテレポーターを個別のノードのセットとして扱います。 連続空間を完全に無視し、これらの N+2 点のみを操作します。 
2. 各テレポーター i について、すべてのノード j のキー値 di(j) を計算します。これは、ノード j とテレポーター i の間のマンハッタン距離として定義されます。 この値は、テレポーター i の下でどのノードが同等であるかを決定します。 
3. 各テレポーター i について、計算された di 値に基づいてすべてのノードをグループ化します。 各グループは、テレポーター i を 1 回だけ使用するだけで相互に到達できるノードを表します。 
4. 開始ノードから BFS を実行します。 各ノードは現在到達可能な位置を表します。 
5. ノード u を処理するとき、すべてのテレポーター i を反復処理します。 各テレポーターについて、di(u) を計算します。 di(v) = di(u) を満たすすべてのノード v には、i を使用した 1 回のテレポーテーションで u から到達できます。 
6. テレポーター i が特定の距離値を処理したら、その (i, 値) ペアを使用済みとしてマークし、再度展開されないようにします。 これにより、各等価クラスが 1 回処理されるようになり、O(N) 回のスキャンが繰り返されることがなくなります。 
7. 宛先に到達するか、キューが空になるまで BFS を続行します。 BFS 深度は、テレポートの最小数です。 

実装の重要な詳細は、グループ内のすべてのペア間にエッジを明示的に構築しないことです。 いずれかのノードから最初にグループを見つけたときにのみグループを展開し、その後は破棄します。 

### なぜ効果があるのか

 各テレポーターは、すべてのノードにわたる関数 di を定義します。 i を使用した 1 回のテレポートにより、この関数のレベル セット内のどこにでも移動できるため、同じ値を共有するすべてのノードに 1 ステップで相互に到達できます。 これらの暗黙的なクリークに対する BFS は、すべての有効なジャンプが明示的に存在するかのように状態空間を探索します。 訪問された状態は事実上、ノードとテレポーター値のペアであり、同じ等価クラスを 2 回再処理することがないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque, defaultdict

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        n = int(input())
        pts = []
        for _ in range(n + 2):
            x, y, z = map(int, input().split())
            pts.append((x, y, z))

        s = 0
        t = 1
        tele = list(range(2, n + 2))

        # dist[i][j] = Manhattan distance from node j to teleporter i
        dist = [[0] * (n + 2) for _ in range(n)]

        for i in range(n):
            tx, ty, tz = pts[i + 2]
            for j in range(n + 2):
                x, y, z = pts[j]
                dist[i][j] = abs(x - tx) + abs(y - ty) + abs(z - tz)

        # visited state: (node, teleporter, distance-value) compressed via used set per teleporter
        used = [set() for _ in range(n)]

        q = deque()
        q.append((s, 0))
        visited_node = [False] * (n + 2)
        visited_node[s] = True

        while q:
            u, d = q.popleft()
            if u == t:
                print(f"Case #{tc}: {d}")
                break

            for i in range(n):
                val = dist[i][u]
                if val in used[i]:
                    continue
                used[i].add(val)

                # expand all nodes v with dist[i][v] == val
                for v in range(n + 2):
                    if dist[i][v] == val and not visited_node[v]:
                        visited_node[v] = True
                        q.append((v, d + 1))
        else:
            print(f"Case #{tc}: IMPOSSIBLE")

if __name__ == "__main__":
    solve()
```この解決策は、すべてのノードからすべてのテレポーターまでのマンハッタンの距離を事前計算することから始まります。 これにより、幾何学的条件がテーブル検索問題に変わります。 

BFS の状態は現在どのノードにいるかを表し、コストはテレポートの数を追跡します。 重要な最適化は、`used[i]`これにより、テレポーターの同じ距離クラスを複数回再拡張することができなくなります。 これがないと、各ノードの展開で同じ同値クラスが繰り返し再スキャンされ、複雑さが三次的な動作に向かって押し上げられることになります。 

内側のループは、距離値が一致するかどうかすべてのノードをチェックします。 N は最大でも 150 であるため、この O(N3) 最悪の構造は枝刈りと組み合わせた場合の制約の下では許容されますが、実際には問題なく制限内に収まります。

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、出発地または目的地がテレポーターと一致する場合です。 これらのポイントは同じノード セットに含まれており、距離のグループ化は特別なケースなしで適用されるため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、同じテレポーターを繰り返し使用して、異なる到達可能領域を生成する場合です。 の`used[i]`この構造により、異なるノードを介して再度アクセスした場合でも、各距離クラスが 1 回だけ処理されることが保証され、指数関数的な爆発を防ぎながら、距離値が変化したときに同じテレポーターを複数回使用することが可能になります。 

最後の微妙なケースは、すべてのノードがテレポーターまで同じ距離を共有する場合です。 その状況では、セット全体が 1 回の BFS 拡張ステップで到達可能になり、グループ化メカニズムは、その値の最初の検出時にすべてのノードを一度にキューに入れることで正しくキャプチャします。
