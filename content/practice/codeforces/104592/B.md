 ## 解決策
 ## 問題の理解

 各テスト ケースでは、開始値と算術「カード」のコレクションが提供されます。 すべてのカードは固定オペランドを使用した演算であり、これらのカードの順序を任意に変更できます。 次数を選択した後、初期値に演算を順番に適用すると、結果が有理数になります。 

主な難点は、演算は可換ではなく、割り算は有理数よりも正確であるため、順序が重要であるということです。 タスクは、最終的な値を最大化するカードの順列を見つけることです。 

4 つの操作タイプがありますが、各カードは非常に構造化された方法で現在の値を変換します。 加算と減算は値をシフトし、乗算と除算は値をスケールします。 これは、各カードが任意の演算ではなく、有理数に対する単純な線形変換であることを示唆しています。 

この制約により、テスト ケースごとに最大 1000 枚のカードが許可されます。 すべての順列を試すことは階乗的に増加するため不可能です。 サブセットに対する動的プログラミングでさえ、小さい場合にのみ実現可能であり、完全な入力サイズでは実現できません。 

演算で負のスケーリング係数が生成される場合、または除算で分数が発生する場合、微妙なエッジ ケースが発生します。 単純な整数ベースのシミュレーションは、中間結果が整数ではなく、分子と分母の両方で大きくなる可能性があるため、すぐに中断します。 別の失敗例は、乗算が常に最後または最初に適用されるべきであると仮定した場合に発生します。 たとえば、負の数による乗算を加算と交換すると、最適な順序が反転する可能性があるため、算術の優先順位に関する直感に基づいた貪欲なルールは当てはまりません。 

## アプローチ

 最初の自然な試みは総当たりです。カードのすべての順列を試し、式をシミュレートし、最大の結果を維持します。 これはソリューション空間全体を調査するため正しいですが、カードの数は指数関数的に増加します。 1000 枚のカードを使用すると、順列の数は天文学的に多くなり、このアプローチは、約 10 ～ 12 枚のカードを超える小さなテスト制限でも使用できなくなります。 

重要な観察は、すべてのカードが x → a x + b という形式のアフィン変換を表しているということです。 加算と減算は異なる b で a = 1 を生成し、乗算と除算は異なる a で b = 0 を生成します。 このような変換を構成する場合、結果はアフィンのままになります。 これは、括弧や演算子の優先順位に関係なく、シーケンス全体が 1 つの変換 x → A x + B になることを意味します。 

合成は予測どおりに動作します。f を適用してから g を適用すると、パラメーターが乗算され、線形に結合されます。 この構造は、最終的な答えは (a, b) のペアをどのように配置するかによってのみ決まることを意味します。 

注文によって実際に何が変わるのかを確認すると、非常に単純化できます。 2 つの変換の 2 つの次数を比較すると、値の乗算は可換であるため、結合された乗算係数 A は次数に関係なく同一になります。 順序付けによって影響を受ける唯一の数量は、加算部分 B です。したがって、全体の最適化は B を最大化することになります。 

これにより、問題は、各項目がその後に来る a 値の積によって重み付けされた値 b_i に寄与する順序付けの問題に変わります。 次に、ペアごとのスワップ引数を使用して最適な順序を導き出し、並べ替えルールを導き出すことができます。

 ## アルゴリズムのチュートリアル

 すべてのカードをアフィン変換 x → a x + b として書き換えます。 

カードごとに、そのパラメーターを構築します。 加算と減算により、a = 1、b = ±v が得られます。 v を掛けると、a = v および b = 0 が得られます。v で割ると、a = 1/v および b = 0 が得られます。 

次に、これらのペアの順序を選択する必要があります。

1. すべてのカードをペア (a_i、b_i) に変換します。 これにより、すべての演算が単一の数学的形式に標準化されます。 
2. ペアを比較して順序付け戦略を決定します。 任意の 2 つのカード i と j について、i を j の前に配置した場合と j を i の前に配置した場合の相加的寄与への影響を比較します。 乗算部分は次数に依存しないため、加算の寄与のみが問題になります。 
3. 固定ペアの場合、両方の可能性を計算します。 

i を j の前に置くと b_i * a_j + b_j が寄与します

 j を i の前に置くと、b_j * a_i + b_i が得られます。 
4. 最初の式が大きい場合は、j よりも i を優先します。 この不等式は比較ルールに単純化されます。 

b_i (a_j − 1) ≧ b_j (a_i − 1)
 5. この比較ルールを使用してすべてのカードを並べ替えます。 
6. ソート後、逐次合成により最終的なアフィン変換を計算します。 恒等変換 x → x から開始して、各カードを順番に合成して (A, B) を更新します。 
7. S に最後の変換を適用して、A*S + B を与えます。 
8. 結果を分母が正の縮約分数として出力します。 

比較ステップは唯一重要な部分であり、順序付け全体を定義します。 

### なぜ効果があるのか

 変換合成により、常に A*S + B の形式の最終値が生成されます。A は順序付けから独立しているため、最終結果の最大化は B の最大化につながります。スワップ条件により、隣接する反転について、優先順序へのスワップによって B が減少しないことが保証されます。順序付けルールに違反することなく、隣接するスワップを使用して任意の順列を並べ替えることができるため、反転を繰り返し排除することで、全体的に最適な順序付けが行われます。 

## Python ソリューション```python
import sys
from functools import cmp_to_key
from fractions import Fraction

input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        S, C = map(int, input().split())

        cards = []
        for _ in range(C):
            op, v = input().split()
            v = int(v)

            if op == '+':
                a = Fraction(1, 1)
                b = Fraction(v, 1)
            elif op == '-':
                a = Fraction(1, 1)
                b = Fraction(-v, 1)
            elif op == '*':
                a = Fraction(v, 1)
                b = Fraction(0, 1)
            else:
                a = Fraction(1, v)
                b = Fraction(0, 1)

            cards.append((a, b))

        def cmp(x, y):
            a1, b1 = x
            a2, b2 = y
            left = b1 * (a2 - 1)
            right = b2 * (a1 - 1)
            if left > right:
                return -1
            if left < right:
                return 1
            return 0

        cards.sort(key=cmp_to_key(cmp))

        A = Fraction(1, 1)
        B = Fraction(0, 1)

        for a, b in cards:
            B = B * a + b
            A = A * a

        result = A * S + B

        num = result.numerator
        den = result.denominator
        if den < 0:
            num = -num
            den = -den

        print(f"Case #{tc}: {num} {den}")

if __name__ == "__main__":
    solve()
```実装は、すべての演算を分数線形変換に変換することから始まります。 除算は分数によって自然に処理されるため、精度の問題が完全に回避されます。 

コンパレータは、アルゴリズム セクションで導出されたスワップ条件を直接エンコードします。 Python の並べ替えでは、このコンパレータを使用して、全体的に最適な順序が生成されます。 

最後のループでは、変換を順番に構成します。 A は順序付けに厳密には必要ありませんが、最終的なアフィン形式を計算する際の正確さと明確さのために維持されます。 

最後に、分母が正になるように結果が正規化され、分数は既に次の式で減算されています。`Fraction`タイプ。 

## 実用的な例

 S = 5、カード: +1、-2、*3、/-2 の小さなケースを考えてみましょう。 

(a, b) ペアを計算します。 

+1 → (1, 1)

 -2 → (1, -2)

 *3 → (3, 0)

 / -2 → (-1/2, 0)

 コンパレータを使用して並べ替えた後、最適な順序付けにより、乗算が早期に配置され、加算ゲインを維持しながら破壊的なスケーリングを最小限に抑える位置に除算が配置されます。 

構成の痕跡:

 | ステップ | | b | あ | B |
 | --- | --- | --- | --- | --- |
 | 開始 | - | - | 1 | 0 |
 | *3 | 3 | 0 | 3 | 0 |
 | /-2 | -1/2 | 0 | -3/2 | 0 |
 | +1 | 1 | 1 | -3/2 | 1 |
 | -2 | 1 | -2 | -3/2 | -7/2 |

 最終的な値は A*S + B = (-3/2)*5 + (-7/2) = -3/2 となります。 

このトレースは、順序が固定されると、計算は純粋に機械的であり、有理算術の下で安定していることを示しています。 

すべての演算が乗算である 2 番目の例は、A では順序が重要ではないが、加算と組み合わせた場合の符号では重要であることを示しており、コンパレータが必要な理由を裏付けています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from fractions import Fraction
    from functools import cmp_to_key

    input_data = inp.strip().split()
    T = int(input_data[0])
    idx = 1
    out_lines = []

    for tc in range(1, T + 1):
        S = int(input_data[idx]); idx += 1
        C = int(input_data[idx]); idx += 1

        cards = []
        for _ in range(C):
            op = input_data[idx]; v = int(input_data[idx+1]); idx += 2

            if op == '+':
                a = Fraction(1,1); b = Fraction(v,1)
            elif op == '-':
                a = Fraction(1,1); b = Fraction(-v,1)
            elif op == '*':
                a = Fraction(v,1); b = Fraction(0,1)
            else:
                a = Fraction(1,v); b = Fraction(0,1)

            cards.append((a,b))

        def cmp(x,y):
            a1,b1 = x; a2,b2 = y
            l = b1*(a2-1); r = b2*(a1-1)
            return -1 if l>r else (1 if l<r else 0)

        cards.sort(key=cmp_to_key(cmp))

        A = Fraction(1,1)
        B = Fraction(0,1)

        for a,b in cards:
            B = B*a + b
            A = A*a

        res = A*S + B
        num, den = res.numerator, res.denominator
        if den < 0:
            num, den = -num, -den

        out_lines.append(f"Case #{tc}: {num} {den}")

    return "\n".join(out_lines)

 ## 特殊なケース

 デリケートな状況の 1 つは、カードの値が = 1 である場合です。これは加算と減算で発生します。 この場合、(a − 1) がゼロになるため、コンパレーターはきれいに減少し、順序付けルールはスワッピングが下流のスケーリングに影響を与えるかどうかのみに依存します。 不等式は除算なしで崩壊するため、アルゴリズムはこれを正しく処理します。 

もう 1 つのケースは、負の a 値を生成する除算です。 たとえば、 / -2 は順序を劇的に変える可能性のある符号反転を導入します。 コンパレーターは、肯定的なものを仮定するのではなく、完全な有理式を比較するため、これを自然に処理します。 

最後の例外ケースは、すべての a 値が 1 の場合です。その場合、すべての変換は純粋に加算的であり、コンパレーターは同じ不等式ルールを尊重する方法で b 値によるソートに退化します。 このアルゴリズムは引き続き一貫した順序付けを生成し、比較式でのゼロ除算を回避します。
