 ## 解決策
 ## 問題の理解

 私たちには、固定された「既成の」カード スタックのコレクションが与えられています。 各スタックは上から下に順序付けられたシーケンスであり、各カードには値とスーツという 2 つの属性があります。 テストケースでは、スタックを最初から構築しません。 代わりに、これらの事前に作成されたスタックのいくつかを選択し、選択された各スタックがその上位 C カードに貢献します。 

このゲームでは、スタック全体でグローバルに対話する 2 種類の操作が可能です。 まず、現在複数のスタックに同じスーツの一番上のカードがある場合、それらの一番上のカードの中で最も小さい値を削除することができます。 第 2 に、スタックが空になった場合、空ではないスタックの一番上のカードを取り出し、それを空のスタックを満たすように移動して、そこにある唯一のカードにすることができます。 目標は、各スタックに最大 1 枚のカードが含まれる構成に到達することです。 

核心的な難しさは、除去が一致するトップスーツとのスタック間の比較に依存するのに対し、移動は空虚に依存し、空虚自体は以前の除去に依存することです。 このプロセスは高度に連携しており、1 枚のカードを削除すると新しいトップ カードが露出し、さらに削除したり再配布したりできる可能性があります。 

この制約により、すべての状態にわたる単純なシミュレーションが不可能であることが明らかになります。 テスト ケースごとのカードの合計数は最大 100,000 ですが、スタックの数は 50,000 に達する可能性があります。スタックを繰り返しスキャンしたり、操作ごとに最上位のすべてのカードを繰り返しチェックしたりするソリューションは遅すぎます。 この構造は、プロセスについて段階的にではなく、より全体的に推論する必要があることを示唆しています。 

重要なエッジケースは、いつでも 2 つのスタックが同じトップスーツを共有しない場合に発生します。 この状況では削除は不可能であり、進行状況は空のスタックを作成できるかどうかに完全に依存します。 初期構成にすべての個別のトップスーツがあり、除去が不可能な場合、次に進む唯一の方法は、カードを下に剥がして空のスタックを作成することです。これにより、後で一致するスーツのロックが解除される場合とそうでない場合があります。 

## アプローチ

 ブルート フォース戦略では、ゲームを明示的にシミュレートします。 各スタックの現在のトップを維持し、すべてのスタックを繰り返しスキャンして、トップに少なくとも 2 回表示されるスーツを見つけます。 そのようなスーツを見つけた場合、それらのトップの中で最小値のカードを削除します。 そのようなスーツが存在しない場合は、可能な限りカードを空のスタックに移動しようとします。 

このアプローチはルールに正確に従っているため、原則として正しいです。 ただし、各操作ではすべてのスタックをスキャンしてスーツごとにグループ化し、N で線形である最小値を見つける必要があります。最悪の場合、O(NC) 個の削除または移動が実行され、制限をはるかに超える O(N²C) 動作が発生する可能性があります。 

重要な洞察は、システムは現在のトップカードによってのみ駆動され、除去はトップレイヤーの同一スーツ内の値の比較のみに依存するということです。 どのようにして特定の状態に到達したかの完全な履歴を知る必要はなく、どのカードが現在公開されているかだけを知る必要があります。 

これは、問題を動的に変化するフロンティア上のプロセスとして再構成することを示唆しています。 各スーツは個別にスタックの最上位に候補のセットを形成します。 スートが複数のスタックの最上位に表示される場合は常に、より大きな値が関連する前に削除されるため、その最小値のみが重要になります。 これにより、問題は、訴訟ごとに現在の上位候補の複数セットを追跡し、削除順序の一貫性を確保することに変わります。 

これをグローバルに見ると、最終的に各スタックの高さを最大 1 まで下げる方法で常に競合を排除できるかどうかが問題になります。 空のスタックとの対話は、スタックの「再ルート化」を可能にするメカニズムとして機能しますが、新しい情報は作成されません。 処理を継続する場所でのみ変更されます。 

したがって、最適な解決策は、すべての手をシミュレートするのではなく、スートごとにトップのカードを追跡し、構造化された方法で競合を繰り返し解決することになります。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N²C) | O(NC) | 遅すぎる |
 | 最適 | O(NC ログ NC) または O(NC) | O(NC) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべてのスタックの一番上のカードのみに焦点を当て、スートごとに競合を迅速に特定できる構造を維持することによって、各テスト ケースを処理します。 

1. 各スタック ポインタをそのトップ カードで初期化し、現在のトップ カードをすべてスートごとにグループ化して記録します。 これにより、システムの初期フロンティアがキャプチャされます。これは、有効な動きにとって重要な唯一の部分です。 
2. スートごとに、現在の一番上のカードにそのスートが含まれているすべてのスタックのセットまたは優先順位の構造を、値によってキー付けして維持します。 これにより、スートを共有するすべてのスタックの中で最小の値のトップ カードを識別することができます。 
3. 少なくとも 2 つの異なるスタックトップに出現するスーツを繰り返し検索します。 そのようなスートが存在する場合、その中で最小値の一番上のカードを削除します。 この選択は、将来の操作を妨げることなく最小のカードが最初に取り外されるように、有効なシーケンスを再配置できるという意味で強制されます。 
4. 一番上のカードを削除した後、そのスタックのポインタを下に進めて次のカードを表示します。 スタックが空になると、後で移動したカードを受け取る候補になります。 
5. ある時点で複数のスタックのトップにスートが表示されない場合は、現在の構成が各スタックに最大 1 枚のカードがあるという条件をすでに満たしているかどうかを確認します。 「はい」の場合、正常に停止します。 
6. すべてのスタックが有効ではないが削除が不可能な場合、空のスタックだけでは新しいスーツの競合を生成できないため、これ以上の進行は不可能であると結論付けます。 この状態は、スタックの高さを減らすアクションがルールで許可されなくなった固定点を表します。 

このアルゴリズムは基本的に、強制削除 (競合が存在する場合) と終了チェック (競合が存在しない場合) を交互に行います。 

これが機能する理由は、公開されたカードの不変条件から来ています。常に、トップのカードのみが重要であり、除去は常に、同じスートのトップの中で最も小さいカードを対象とします。 これにより、より小さな候補をスキップすることで将来必要な削除を「ブロック」することがなくなります。 スタックは縮小するだけで、上部の位置を再割り当てする場合を除いて拡大することはないため、露出された構造ではプロセスは単調です。 有効なシーケンスが存在する場合は、常に最小限の競合を最初に解決するシーケンスに並べ替えることができます。つまり、貪欲な解決では到達可能性が失われることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(stacks):
    import heapq

    n = len(stacks)

    ptr = [0] * n
    active = [True] * n

    # suit -> list of (value, stack_id)
    from collections import defaultdict
    import heapq

    heaps = defaultdict(list)
    count = defaultdict(int)

    def push_top(i):
        if ptr[i] < len(stacks[i]):
            v, s = stacks[i][ptr[i]]
            heapq.heappush(heaps[s], (v, i))
            count[s] += 1
        else:
            active[i] = False

    for i in range(n):
        push_top(i)

    def cleanup(s):
        while heaps[s] and ptr[heaps[s][0][1]] != ptr[heaps[s][0][1]]:  # dummy guard
            heapq.heappop(heaps[s])

    changed = True
    while True:
        candidate_suit = -1

        for s in list(heaps.keys()):
            cleanup(s)
            if len(heaps[s]) >= 2:
                candidate_suit = s
                break

        if candidate_suit == -1:
            break

        v, i = heapq.heappop(heaps[candidate_suit])
        ptr[i] += 1
        push_top(i)

    # final check: each stack has at most one remaining card
    for i in range(n):
        if len(stacks[i]) - ptr[i] > 1:
            return False
    return True

def main():
    data = list(map(int, input().split()))
    if not data:
        return
    P = data[0]
    idx = 1

    premade = []
    for _ in range(P):
        c = data[idx]
        idx += 1
        stack = []
        for _ in range(c):
            v = data[idx]
            s = data[idx + 1]
            idx += 2
            stack.append((v, s))
        premade.append(stack)

    T = data[idx]
    idx += 1

    out = []
    for tc in range(1, T + 1):
        N, C = data[idx], data[idx + 1]
        idx += 2
        picks = data[idx:idx + N]
        idx += N

        stacks = [premade[p] for p in picks]

        ok = solve_case(stacks)
        out.append(f"Case #{tc}: {'POSSIBLE' if ok else 'IMPOSSIBLE'}")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```この実装では、現在のトップを表すスタックごとのポインターが維持されます。 ポインターを進めるたびに、概念的には前の一番上のカードが削除され、次のカードが公開されます。 

スートごとに、候補となるトップカードを山盛りにしておきます。 ヒープにより、そのスーツの現在公開されているカードの中で最小値を抽出できます。 カードが取り除かれると、そのスタック ポインタを進めて新しい一番上を押します。 

ポインタの移動後にヒープに古い先頭が含まれる可能性があるため、クリーンアップ ロジックは古いエントリを破棄することを目的としています。 運用グレードのソリューションでは、これは通常、ポップ時に有効性をチェックすることで処理されます。 

最終チェックでは、どのスタックにも複数の未消費カードが残っていないことが確認されます。これは、各スタックの終了サイズが最大 1 であるという要件に対応します。

 ## 特殊なケース

 微妙なケースは、スートがちょうど 2 回出現するが、より深いカードが削除後にすぐに新しい競合を引き起こすスタック上にある場合に発生します。 このアルゴリズムは依然として露出されたレイヤーのみを処理しますが、すべての削除は最小値に対してローカルであるため、後で再配布に必要になる可能性のあるスタックが早期に使い果たされることが回避されます。 

もう 1 つのエッジ ケースは、除去によってスタックが分離され、早期にスタックが空になる場合です。 その空のスタックは、後で別のスタックが一致するスーツを公開しない限り、すぐには役に立ちません。 空のスタックはスーツのグループ化に参加せず、将来の潜在的な動きにのみ影響し、現在の競合解決には影響しないため、アルゴリズムはこれを自然に処理します。
