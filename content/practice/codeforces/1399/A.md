 ## 解決策
 ## 問題の理解

 特定の演算を使用して、正の整数の配列を 1 つの要素に減らすことができるかどうかを判断するように求められます。つまり、差が最大 1 である 2 つの異なる要素を選択し、2 つのうちの小さい方 (または等しい場合はどちらか) を削除します。 配列には重複が含まれる可能性があり、各テスト ケースは独立しています。 

入力は複数のテスト ケースで構成されます。 各テスト ケースでは、配列の長さは最大 50 で、各要素は 1 から 100 の間です。これは、次の二次関数であるすべての解を意味します。`n`50 の 2 乗はテスト ケースごとにわずか 2500 回の操作に相当するため、制限時間内で快適に実行されます。 最大 1000 のテスト ケースを使用すると、最悪の場合でも 250 万の操作に達します。これは 1 秒の制限としては許容範囲です。 

明らかではないエッジ ケースには、すべての要素が等しい配列、単一の要素を持つ配列、連続する要素間の最大ギャップが 1 より大きい配列が含まれます。たとえば、次のようになります。`[1, 2, 4]`2 と 4 は 1 より大きく異なっており、許可された一連の削除によってこのギャップを解消できないため、単一の要素に減らすことはできません。 同様に、`[5, 5, 5, 5]`常に 1 つの要素に減らすことができますが、`[100]`自明のことですが、すでに単一の要素です。 

## アプローチ

 ブルートフォース手法では、考えられるすべての手をシミュレートします。つまり、差が最大 1 である要素のペアを繰り返し探し、小さい方を削除し、1 つの要素が残るか、または移動が不可能になるまで継続します。 これは小規模な場合に機能します`n`ただし、有効なペアを繰り返し検索し、要素を動的に削除する必要があるため、煩雑で非効率的になります。 最悪の場合の操作数は約`O(n^3)`なぜなら、削除するたびにすべてのペアをスキャンする必要があり、これはたとえ`n = 50`。 

重要な観察は、要素を削除できるかどうかは、配列がソートされた後の連続する数値間のギャップによって完全に決定されるということです。 配列がソートされ、隣接するすべてのペアの差が最大 1 であれば、最大の要素を除くすべての要素を最終的に削除できます。 隣接するペアが 2 以上異なる場合、ギャップの両側の要素を 1 つに減らすことができず、単一要素の配列に到達することができなくなります。 

この観察により、配列のソートと連続した差異のチェックの解決策が簡素化されます。 仕分け費用`O(n log n)`単一のリニア スキャンですべての差が最大 1 であるかどうかを確認し、クリーンで最適なソリューションを提供します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 |---|---|---|---|
 | ブルートフォース | O(n^3) | O(n) | 遅すぎる/乱雑 |
 | 最適 | O(n log n) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 各テストケースを個別に処理します。 
2. テスト ケースごとに、配列の長さを読み取ります。`n`そして配列要素`a`。 
3. 配列を昇順に並べ替えます。 並べ替えにより、連続する要素間の違いを直接確認できるようになります。 
4. 配列を 1 つの要素に減らすことができると仮定して、フラグ変数を「YES」に初期化します。 
5. 配列を最初の要素から最後から 2 番目の要素まで繰り返します。 インデックスごとに`i`、間の差を計算します。`a[i+1]`そして`a[i]`。 この差が 1 より大きい場合は、フラグを「NO」に設定し、ループから抜け出します。 これにより、完全な削減を妨げるギャップが特定されます。 
6. すべての隣接ペアをチェックした後、現在のテスト ケースのフラグを出力します。 「YES」は配列を単一の要素に削減できることを示し、「NO」はそれ以外の場合に指定します。 

機能する理由: 配列がソートされると、完全な削減を妨げる唯一の制約は、1 より大きいギャップの存在です。1 または 0 の差がある 2 つの連続する数値は、削除操作を繰り返すことで最終的に削減できます。これは、1 つだけが残るまで常に小さい方を削除できるためです。 2 以上の差があると、乗り越えられない壁が生じます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    a.sort()
    possible = True
    for i in range(n - 1):
        if a[i+1] - a[i] > 1:
            possible = False
            break
    print("YES" if possible else "NO")
```このソリューションは、まずテスト ケースの数を読み取ります。 各配列はソ​​ートされているため、1 回の線形スキャンで 1 より大きい差異を検出できます。変数`possible`配列を 1 つの要素に減らすことができるかどうかを追跡し、1 より大きいギャップを検出すると早期に中断します。並べ替えでは重複する要素が自動的に処理され、連続するペアのみを確認する必要があることが保証されます。 追加のデータ構造は必要ありません。 

## 実用的な例

 入力をトレースする`[1, 2, 2]`:

 | ステップ | 配列 | チェック | アクション |
 |---|---|---|---|
 | 1 | [1、2、2] | 2 - 1 = 1 | OK |
 | 2 | [1、2、2] | 2 - 2 = 0 | OK |
 | 3 | - | すべての差分 <= 1 | はい |

 入力をトレースする`[1, 2, 4]`:

 | ステップ | 配列 | チェック | アクション |
 |---|---|---|---|
 | 1 | [1、2、4] | 2 - 1 = 1 | OK |
 | 2 | [1、2、4] | 4 - 2 = 2 | 許可されていません、休憩 |
 | 3 | - | ギャップ > 1 が検出されました | いいえ |

 これらのトレースは、連続した差異のみをチェックするだけで十分であることを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 |---|---|---|
 | 時間 | O(n log n) | ソートが優先され、リニア スキャンは O(n) |
 | スペース | O(1) おまけ | 並べ替えはその場で実行可能 |

 と`n <= 50`そして`t <= 1000`、ソリューションのパフォーマンスは最大でも`1000 * 50 log 50 ≈ 85000`操作は 1 秒以内に完了します。 メモリ使用量は最小限で、256 MB 以内に簡単に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        a.sort()
        possible = True
        for i in range(n - 1):
            if a[i+1] - a[i] > 1:
                possible = False
                break
        print("YES" if possible else "NO")
    return out.getvalue().strip()

# Provided samples

# Custom cases

assert run("1\n50\n" + " ".join(["1"]*50)) == "YES", "all equal large n"
assert run("1\n5\n1 2 3 4 5") == "YES", "consecutive small array"

 ## 特殊なケース

 単一要素配列の場合`[100]`、並べ替えは効果がありません。 要素が 1 つしかないため、連続した差分のループは実行されません。 操作は必要ないため、アルゴリズムは正しく「YES」を出力します。 

すべての要素が等しい配列の場合、次のようになります。`[5, 5, 5, 5]`、差はゼロであるため、アルゴリズムは「YES」を出力します。 

ギャップのある配列の場合、`[1, 3]`、 違い`3 - 1 = 2`ブレーク条件をトリガーし、ただちに「NO」を生成します。 これは、単一要素への縮小を防ぐキー制約を処理します。
