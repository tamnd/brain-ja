 ## 解決策
 ## 問題の理解

 数直線上のセグメントの集合が与えられ、各セグメントは左の端点と右の端点によって定義されます。 タスクは、特定のプロパティを持つこれらのセグメントの可能な限り最大のサブセットを選択することです。サブセット内の 2 つのセグメントは、完全に切り離されている、つまりポイントをまったく共有していない、または一方が他方の内部に完全に含まれている必要があります。 封じ込められない部分的な重なりは許可されません。 入力には複数の独立したテスト ケースが含まれており、それぞれが独自のセグメントのセットを持ちます。 

この制約は、すべてのテスト ケースにわたるセグメントの合計数が 3000 を超えないことを示しています。これは、テスト ケースごとのセグメント数に二次時間を使用するアルゴリズムが実現できるほど十分に小さいため、$3000^2$操作は 3 秒以内に快適に収まります。 ただし、すべてのサブセットを列挙しようとする素朴なアプローチは指数関数的であり、まったく実行不可能です。 

セグメントがエンドポイントを共有しているものの、厳密には相互に含まれていない場合、微妙なエッジ ケースが発生します。 たとえば、セグメント [1,2] と [2,3] は 1 点で接触しているため、これらは交差しているとみなされ、一方が他方に厳密に含まれない限り、一緒に含めることはできません。 別の特殊なケースは、[1,3] 内の [2,2] など、長さ 1 のネストされたセグメントです。 端点の重なりを非交差として扱う不注意な解決策では、両方のセグメントが誤って含まれてしまいます。 

## アプローチ

 ブルートフォース手法では、セグメントのすべてのサブセットを試し、各サブセットが非交差または包含条件を満たすかどうかを確認します。 1 つのサブセットをチェックするには、そのサブセット内のセグメントのすべてのペアを比較する必要があります。$O(n^3)$単一のテストケースのソリューション$n$セグメント。 これでは遅すぎます$n$3000まで。 

最適化するために、問題が自然な構造を持っていることを観察します。つまり、セグメントを順序付けして入れ子にすることができます。 左の端点でセグメントを並べ替え、右の端点を減らすことで結合を解除すると、どのセグメントでも、その内部にネストできる潜在的なセグメントがリストの後半に表示されることが保証されます。 これは当然、動的プログラミングのアプローチを示唆しています。`dp[i]`i 番目のセグメントで終わる最大の有効なサブセットのサイズです。 埋める`dp[i]`、以前のすべてのセグメントを考慮します`j < i`セグメントかどうかを確認します`i`で終わるサブセットに追加できます`j`。 セグメント`i`完全に内側にある場合は追加できます`j`または完全に切り離されている`j`。 セグメントは左の端点でソートされるため、効率的に素性をチェックできます。 

重要な洞察は、ソート後にセグメントを含めるかどうかを決定することです。`i`前に始まるセグメントのみに依存します`i`。 これにより、最適解を計算できます。$O(n^2)$単純なネストされたループを使用して DP テーブルを更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n * n^2) | O(n) | 遅すぎる |
 | ソート後のDP | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、セグメントの数とセグメント自体を読み取ります。 各セグメントをタプルとして表現します`(l, r)`。 
2. 最初に左の端点でセグメントを並べ替えます。`l`昇順、右のエンドポイント順`r`降順で。 この方法で並べ替えると、別のセグメントが含まれる可能性のあるセグメントが確実に前に表示されます。 
3. DP 配列を初期化する`dp`サイズの`n`、 どこ`dp[i]`セグメントで終わる最大の有効なサブセットのサイズを保存します`i`。 すべて設定`dp[i]`各セグメントは独自にサイズ 1 のサブセットを形成できるため、最初は 1 に設定されます。 
4. セグメントを順番に繰り返します。 セグメント用`i`、前のすべてのセグメントを確認します`j < i`。 セグメントの場合`i`完全に内側にあります`j`(つまり、`l[j] <= l[i]`そして`r[i] <= r[j]`) または素`j`(つまり、`r[j] < l[i]`）、 それから`i`で終わるサブセットを拡張できます`j`。 アップデート`dp[i] = max(dp[i], dp[j] + 1)`。 
5. DP 配列を埋めた後、このテスト ケースの最大の有効なサブセットは、次の最大値になります。`dp`。 

機能する理由: 左のエンドポイントで並べ替えると、別のセグメントを含む可能性のあるすべてのセグメントがその前に表示されるため、DP 更新の前のセグメントのみをチェックするだけで十分になります。 DP の不変条件は次のとおりです。`dp[i]`常にセグメントで終わる最大のサブセットを表します`i`それは問題の制約を満たします。 これにより正確性が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        segments = [tuple(map(int, input().split())) for _ in range(n)]
        # sort by left ascending, then right descending
        segments.sort(key=lambda x: (x[0], -x[1]))
        dp = [1] * n
        for i in range(n):
            li, ri = segments[i]
            for j in range(i):
                lj, rj = segments[j]
                if ri <= rj or rj < li:
                    dp[i] = max(dp[i], dp[j] + 1)
        print(max(dp))

if __name__ == "__main__":
    solve()
```最初のセクションは入力を読み取り、セグメントを整理します。 左のエンドポイントで並べ替えると、包含チェックが正しく機能するようになり、右のエンドポイントを降順にすると、ネストされたセグメントの関係が解決されます。 ネストされたループは DP を実装します。ここで、条件は`ri <= rj or rj < li`含める要件に正確に一致します:`i`中にあります`j`またはバラバラ。 最大値を超える`dp`各テストケースの答えを示します。
