 ## 解決策
 ## 問題の理解

 それぞれに特定の重みを持つ一連の参加者がいます。 この競技では 2 人チームのみが許可されており、各チームの合計体重は同じでなければなりません。 私たちの目標は、特定の参加者に対してできるだけ多くのチームを編成することです。 課題は総重量を選択することです`s`それは有効なチームの数を最大化します。 各参加者は 1 つのチームにのみ所属できるため、人を再利用することはできません。 

制約は小さいです。`n`は最大 50 で、重みの範囲は 1 ～`n`。 以来`n`が小さい場合、2 人の参加者の個別の合計の数は次のように制限されるため、考えられるすべての合計重みを調べる余裕があります。`2n`。 これにより、高度に最適化されたデータ構造や複雑なアルゴリズムの必要性が排除されます。 エッジケースには、すべての参加者が同じ重みを持っている状況、特定の合計でペアを形成することが不可能な場合、または複数の合計重みが同じ最大チーム数を生み出す状況が含まれます。 

たとえば、不注意な実装では、他の合計を考慮せずに、常に最も軽い参加者と最も重い参加者の合計を試行する可能性があります。 たとえば、参加者と一緒に`[1, 2, 2, 1, 2, 1, 1, 2]`、最適な総重量は次のとおりです。`3`(ペア`(1,2)`）、 ない`4`(参加者が残ったままになります)。 単純なアルゴリズムでは、単一の候補合計のみをチェックするため、これを見逃す可能性があります。 

## アプローチ

 ブルート フォース アプローチでは、考えられるすべての合計重みに対して反復処理が行われます。`s`から`2`(参加者 2 人の最小合計) ～`2n`（最大額）。 それぞれについて`s`、可能な参加者のペアをすべて試して、何チームを形成できるかを確認します。 これは、ネストされたループを使用するか、重みの周波数マップを保持することによって実装できます。 チームを形成するには、ペアが使用されるたびに頻度マップ内のカウントを減分する必要があります。 このアプローチは正しいですが、最悪の場合の複雑さが伴います`O(n^2 * n) = O(n^3)`なぜなら、すべての候補の合計についてすべてのペアをチェックする可能性があるためです。これは、`n=50`しかし改善することができます。 

重要な観察は、問題が各重みが出現する回数を数えることと、重みを貪欲にペアにすることに帰着できるということです。 候補総重量の場合`s`、重り`w`とのみペアリングできます`s - w`。 このようなペアの数は、次のカウントの最小値として計算できます。`w`そして`s - w`。 すべての重みを反復処理します。`1`に`n`候補者ごとに`s`が得られます`O(n^2)`制約を考慮すると十分に高速なソリューションです。 このアプローチでは、狭い範囲の重みとペアの対称性を利用します。個別の重みを合計ごとに 1 回考慮するだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3) | O(n) | 動作しますが、最適化することができます。 
| 周波数マップ貪欲 | O(n^2) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テストケースについて、参加者の数を読み取ります。`n`そしてその重さ。 
3. 周波数マップを作成する`freq`各体重を持つ参加者の数を数えます。 
4. 変数を初期化する`max_teams`ゼロに。 これにより、総重量に対する最適なチーム数が追跡されます。 
5. 考えられるすべての合計重みに対して反復処理を行います。`s`から`2`に`2n`。 
6. 各候補の合計について`s`、周波数マップのコピーを作成します。 これにより、ペア形成のシミュレーション中に元のカウントを変更することができなくなります。 
7. カウンタの初期化`teams`現在の合計をゼロにします`s`。 
8. 重みを反復処理する`w`から`1`に`n`。 それぞれについて`w`、その補数を見つけます`c = s - w`。 
9. もし`c`範囲内です`1..n`、ペアの数を次のように計算します。`min(freq[w], freq[c])`。 もし`w == c`、二重カウントを避けるために、結果を 2 で割ります。 
10. この数のペアを`teams`そして、コピーされた周波数マップ内のカウントをデクリメントします。 
11. この合計のすべての重みを確認した後`s`、 アップデート`max_teams`もし`teams`の方が大きいです。 
12. 印刷`max_teams`現在のテストケースの答えとして。 

機能する理由: すべてのステップで、アルゴリズムは参加者を再利用しないという不変条件を維持します。 考えられるすべての合計を反復し、頻度マップを使用して貪欲にペアを形成することにより、ペアの欠落がないことが保証され、合計の重みごとにチームの最大数が正確にカウントされます。 合計に対する外側のループにより、グローバルに最適な合計が確実に見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def max_teams(weights, n):
    freq = [0] * (n + 1)
    for w in weights:
        freq[w] += 1

    max_teams_count = 0

    for s in range(2, 2 * n + 1):
        temp_freq = freq.copy()
        teams = 0
        for w in range(1, n + 1):
            c = s - w
            if 1 <= c <= n:
                pair_count = min(temp_freq[w], temp_freq[c])
                if w == c:
                    pair_count //= 2
                teams += pair_count
                temp_freq[w] -= pair_count
                temp_freq[c] -= pair_count
        max_teams_count = max(max_teams_count, teams)

    return max_teams_count

t = int(input())
for _ in range(t):
    n = int(input())
    weights = list(map(int, input().split()))
    print(max_teams(weights, n))
```この解決策は、入力を読み取り、参加者の重みをカウントするための周波数配列を構築することから始まります。 各候補合計重みについて、頻度配列をコピーして、副作用なしでペア形成をシミュレートします。 貪欲なペアリングは、重みとその補数の最小数を取得することによって行われます。 次の場合には特別な注意が必要です`w`等しい`s - w`数えすぎを避けるため。 すべての合計を評価した後、チームの最大数が返されます。 

## 実用的な例

 **サンプル 1:**`weights = [1, 2, 3, 4, 5]`、`n = 5`。

 | 3 | (1,2) | 1 |
 | 4 | (1,3) | 1 |
 | 5 | (1,4),(2,3) | 2 |

 このトレースは、最も軽いものと最も重いものを組み合わせても、必ずしも全体的な最適値が得られるわけではないことを示しています。 すべての合計を考慮することで、正しい答えが確実に見つかります。
