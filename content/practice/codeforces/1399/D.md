 ## 解決策
 ## 問題の理解

 バイナリ文字列が与えられ、それをいくつかのサブシーケンスに分割して、すべての文字が 1 回だけ使用され、各サブシーケンスが交互に使用されるようにしたいと考えています。`0`そして`1`。 言い換えれば、選択されたサブシーケンス内では、選択された 2 つの隣接する文字が同じになることはできません。 

サブシーケンス内の文字を並べ替えることはできません。元の文字列から文字を削除してそれを形成することのみが可能です。 元の位置はそれぞれ 1 つのサブシーケンスに割り当てる必要があり、必要なサブシーケンスの数を最小限に抑えたいと考えています。 

出力は、サブシーケンスの最小数だけでなく、文字列内の各位置をそれらのサブシーケンスの 1 つに割り当てたものでもあります。 

すべてのテスト ケースの全長が最大 2×10^5 であるという制約は、テスト ケースごとにすべての解が線形または線形に近いものである必要があることを意味します。 サブシーケンスを貪欲に繰り返し構築しようとする O(n²) 構造は、最悪の場合、単一のテスト ケースがすでに 2×10^5 に達しているため、すぐに失敗します。 

単純ですが有益なアプローチは、サブシーケンスの構築を 1 つずつシミュレートすることです。 文字列をスキャンして、交互ルールに違反しない最初のサブシーケンスに各文字を配置することもできます。 これは正しいですが、すべてのサブシーケンスを維持し、文字ごとの互換性をチェックすると、特に次のような文字列の場合、最悪の場合、二次的な動作が発生します。`000000...111111...`すべての配置試行は、多くの既存のサブシーケンスで失敗します。 

微妙なエッジ ケースは、すべての文字が同一である場合です。たとえば、`000000`。 不注意で貪欲なアプローチでは、1 つのサブシーケンスを拡張しようとして失敗を繰り返し、非効率的に新しいサブシーケンスを作成する可能性があります。しかし、正しい答えは、サブシーケンス内で 2 つの等しい文字が隣接することはできないため、各文字は別々のサブシーケンスに移動する必要があるというだけです。 

もう 1 つの例外的なケースは、次のような交互の文字列です。`010101`。 ここでは単一のサブシーケンスで十分ですが、サブシーケンスを正しく再利用しない単純なアプローチでは、過度に分割され、複数のサブシーケンスが生成される可能性があります。 

## アプローチ

 重要な観察は、各サブシーケンスが、次の文字が最後の文字から切り替わることを期待するチェーンのように動作することです。 したがって、各サブシーケンスには、新しい文字を追加できるかどうかを決定する「最後の文字の状態」があります。 

欲張って考えると、最後の文字が異なる既存のサブシーケンスに各文字を配置したいと考えます。 このようなすべてのサブシーケンスの中から、正確性を考えるとどれを選択しても問題はありませんが、サブシーケンスの数を最小限に抑えるために、可能な限り既存の互換性のあるサブシーケンスを常に再利用する必要があります。 

この強引なアイデアは、サブシーケンスのリストを保持し、文字ごとにすべてのサブシーケンスをスキャンして、最後の要素が異なるサブシーケンスを見つけることです。 最悪の場合、これには O(n²) のコストがかかります。 

最適な洞察は、常に、現在次で終わるサブシーケンスの数だけを気にすることです。`0`で終わるのはいくつありますか`1`。 で終わるサブシーケンス`0`を受け入れることができます`1`、その逆も同様です。 したがって、すべてのサブシーケンスを個別に追跡するのではなく、利用可能な「エンドポイント」を追跡し、貪欲に割り当てます。 

サブシーケンス ID の 2 つのスタック (またはキュー) を維持します。1 つは、で終わるサブシーケンス用です。`0`、で終わるもの用に 1 つ`1`。 各文字について、可能であれば反対側のスタックから選択します。それ以外の場合は、新しいサブシーケンスを作成する必要があります。 

これが機能するのは、将来の拡張のために、どのサブシーケンスも同じ文字で終わる他のサブシーケンスと交換可能であるためです。 ID は重要ではなく、最後の文字だけが重要です。

 ## アルゴリズムのチュートリアル

 文字列を左から右に処理し、各文字をサブシーケンスに割り当てます。 

1. 2 つのスタックを維持します。1 つは、最後に割り当てられた文字が次のサブシーケンス用です。`0`、そして最後に割り当てられたキャラクターが`1`。 また、各位置の割り当てを保存する配列も維持します。 
2. ポジションごとに`i`、検査する`s[i]`。 

もしそうなら`0`、現在で終わるサブシーケンスを再利用しようとします。`1`。 このようなサブシーケンスは、代替を中断することなく、この文字を安全に受け入れることができます。 そのようなサブシーケンスが存在しない場合は、新しいサブシーケンスを作成します。 

同じロジックが対称的に適用されます。`1`。 
3. サブシーケンスを再利用する場合、その ID を反対側の終了スタックから削除し、それを現在の位置に割り当ててから、新しい最後の文字に対応するスタックにプッシュします。 
4. 新しいサブシーケンスを作成するときは、サブシーケンス カウンタをインクリメントし、現在の位置をそれに割り当てます。 次に、それをその文字に対応するスタックに置きます。 
5. すべての文字が処理されるまで続行します。 

処理後、使用された最大のサブシーケンス インデックスが答えとなります。 

### なぜ効果があるのか

 重要な不変条件は、各サブシーケンスがその最後の文字に対応するスタック内で常に 1 回だけ表されるということです。 文字を受け入れることができるサブシーケンスは、その時点で正しいスタックに存在します。 可能な限り常に 1 つを再利用するため、互換性のあるものがすべて使い果たされない限り、新しいサブシーケンスを作成することはありません。 これにより最小性が保証されます。すべての新しいサブシーケンスは、既存のサブシーケンスがその文字を合法的に受け入れることができない瞬間に対応し、最適なカウントの増加を強制します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input().strip())
        s = input().strip()

        # stacks of subsequence ids ending in '0' and '1'
        end0 = []
        end1 = []

        ans = [0] * n
        k = 0

        for i, ch in enumerate(s):
            if ch == '0':
                if end1:
                    idx = end1.pop()
                    ans[i] = idx
                    end0.append(idx)
                else:
                    k += 1
                    ans[i] = k
                    end0.append(k)
            else:
                if end0:
                    idx = end0.pop()
                    ans[i] = idx
                    end1.append(idx)
                else:
                    k += 1
                    ans[i] = k
                    end1.append(k)

        print(k)
        print(*ans)

if __name__ == "__main__":
    solve()
```コードはスタックベースの解釈を直接反映しています。 2 つのスタックには、最後の文字ごとにグループ化されたサブシーケンス ID が格納され、有効なサブシーケンスが存在する場合は、そのサブシーケンスを O(1) 選択できます。 

変数`k`これまでに作成されたサブシーケンスの数を追跡し、両方のスタックが有効な受信者を提供できないたびに、新しいサブシーケンス ID を割り当てます。

 ## 特殊なケース

 次のような単一の文字の場合`0`、両方のスタックが空であるため、新しいサブシーケンスが作成され、ID 1 が割り当てられます。長さ 1 のサブシーケンスは交替を自明に満たすため、不変式が成り立ちます。 

次のような完全に交互の文字列の場合`010101`の場合、アルゴリズムは常に反対側の終了スタックで互換性のあるサブシーケンスを検索するため、最初のサブシーケンスの後に新しいサブシーケンスは作成されません。 スタックは単一のサブシーケンスの所有権を前後に交換し、正確さを維持します。 

次のような定数文字列の場合`111111`、`end0`スタックは常に空であり、文字ごとに新しいサブシーケンスの作成が強制されます。 各サブシーケンスは次のように終了します。`1`そして誰も他のものを受け入れることはできません`1`、すべての文字を分離する必要があるという最適な要件に一致します。
