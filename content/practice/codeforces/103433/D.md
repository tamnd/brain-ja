 ## 解決策
 ## 問題の理解

 配列が与えられ、特定の変換ルールに基づいて配列間の類似性の概念を決定するように求められます。 この問題は基本的に、一貫した方法で 2 つのシーケンスの構造を正規化または「圧縮」し、結果の表現が一致するかどうかを確認できる場合に、2 つのシーケンスがどのように動作するかを比較することです。 

各テスト ケースには、同じ長さの 2 つの配列が用意されています。 タスクは、正確な値を無視し、代わりに順序付けと繰り返しパターンによって引き起こされる相対的な構造のみを保存するプロセスの下で、これらの配列が同等であるとみなせるかどうかを判断することです。 言い換えれば、2 つの配列は、左から右にスキャンしたときに新しい値がどのように表示されるかという同じパターンを引き起こす場合、類似しています。 

これを具体的にするには、配列を左から右に読み取り、各個別の値をその配列内で最初に出現するインデックスに置き換えることを想像してください。 これにより、配列の標準的な「形状シグネチャ」が生成されます。 問題は、両方の配列が同一の署名を生成するかどうかをチェックすることに帰着します。 

この制約は、潜在的に大きな配列を処理する必要があることを暗示しているため、部分構造の二次比較やすべての要素間のペアごとの位置合わせが遅すぎる可能性があります。 アレイごとの線形スキャンが唯一の実行可能な方向です。 

繰り返しの値や最初の値に関しては、エッジ ケースが重要です。 たとえば、次のことを考えてみましょう。 

入力:

 A = [5、7、5]

 B = [1, 2, 1]

 どちらの配列も同じパターン シグネチャ [0、1、0] を生成します。 単純な要素ごとの比較は、構造的には同一であっても値が異なるため失敗します。 

繰り返し構造は保持されているが、最初の出現の順序が異なる場合には、別の微妙なケースが発生します。 

A = [1、2、3、2]

 B = [4, 5, 6, 5]

 どちらも似ています。 ただし、1 つの配列で新しい値が先にまたは後で導入された場合、シグネチャはすぐに分岐します。 

## アプローチ

 強引なアイデアは、最初の配列内の値の可能なすべての再ラベル付けを比較して 2 番目の配列と一致させることです。 これは、位置を保持する A と B の値の間の全単射を構築しようとすることを意味します。 マッピングを試行するたびに、アレイ間の一貫性を検証します。 ラベルの順列が考慮される可能性があるため、マッピングの数は個別の要素の数で階乗的に増加します。 貪欲にマッピングを構築することに限定したとしても、配列全体にわたる整合性を繰り返しチェックすることになり、総コストは 2 次またはそれ以上になります。 

重要な点は、実際の数値はまったく問題ではないということです。 重要なのは、以前に値を見たことがあるかどうか、そして新しい値がどのような順序で現れるかだけです。 各配列は、すべての最初の出現を新しい識別子で置き換え、その後の出現でその識別子を再利用することによって、独立して標準形式に縮小できます。 

両方の配列がこれらの正規シーケンスに変換されると、問題は直接の等価性チェックに減ります。 

これが機能するのは、問題で説明されている「類似性」関係が、最初の出現によって引き起こされる構造間の正確な同型性であるためです。 正規のエンコーディングにより、実際の値の対応関係について推論する必要がなくなります。

 | 正規エンコーディング | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各配列を個別に処理し、その構造シグネチャを構築します。

1. 以前に表示されていない各値を一意の整数識別子にマップする空の辞書を作成します。 この識別子は、値が最初に出現する順序を表します。 
2. ゼロから始まるカウンターを維持します。 このカウンタは、新しい識別子を新しい値に昇順に割り当てます。 
3. アレイを左から右にスキャンします。 各要素について、以前に表示されたことがあるかどうかを確認します。 
4. 要素が新しい場合は、現在のカウンタ値を割り当て、カウンタをインクリメントします。 これにより、以前の検出ではより小さい識別子が取得され、検出順序が維持されます。 
5. 要素が見つかった場合は、割り当てられた識別子を再利用します。 
6. これらの識別子で構成される変換された配列を構築します。 
7. 2 番目のアレイに対して同じプロセスを繰り返します。 
8. 変換された 2 つの配列を直接比較します。 一致する場合は「YES」を出力し、一致しない場合は「NO」を出力します。 

この構造が正しい理由は、マッピングが最初の出現の順序のみに依存しており、それが有効な相似変換の下で保存される唯一の構造情報であるためです。 i 回目に出現する新しい値は、もう一方の配列の i 番目の新しい値に対応する必要があるため、類似する 2 つの配列は同一の検出シーケンスを誘導する必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def encode(arr):
    mp = {}
    cur = 0
    res = []
    for x in arr:
        if x not in mp:
            mp[x] = cur
            cur += 1
        res.append(mp[x])
    return res

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))
    
    if encode(a) == encode(b):
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```ソリューションはヘルパー関数とメイン ロジックに分割されます。 ヘルパー関数は、辞書を使用して最初の出現を追跡することにより、正規のエンコーディングを構築します。 代入の順序は、値を最初に見たときにその識別性が決定されるため、重要です。 

main 関数は両方の配列を読み取り、個別にエンコードし、結果を比較します。 エンコードによって生の値への依存がすでに排除されているため、追加の正規化は必要ありません。 

微妙な点は、2 つのエンコーディング間で状態を再利用してはいけないということです。 各配列は、その構造が単独で比較できるように、新しいマッピングから開始する必要があります。 

## 実用的な例

 ### 例 1

 入力:

 A = [5、7、5]

 B = [1, 2, 1]

 エンコードプロセス:

 | ステップ | 要素 | マッピング | エンコードされた | B要素 | B マッピング | B エンコード |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 5 | {5:0} | [0] | 1 | {1:0} | [0] |
 | 2 | 7 | {5:0,7:1} | [0,1] | 2 | {1:0,2:1} | [0,1] |
 | 3 | 5 | {5:0,7:1} | [0,1,0] | 1 | {1:0,2:1} | [0,1,0] |

 両方のエンコードされた配列が一致するため、出力は YES になります。 

これにより、等価性は実際の値ではなく構造のみに依存することが確認されます。 

### 例 2

 入力:

 A = [1、2、1、3]

 B = [4、5、5、6]

 | ステップ | 要素 | マッピング | エンコードされた | B要素 | B マッピング | B エンコード |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 1 | {1:0} | [0] | 4 | {4:0} | [0] |
 | 2 | 2 | {1:0,2:1} | [0,1] | 5 | {4:0,5:1} | [0,1] |
 | 3 | 1 | {1:0,2:1} | [0,1,0] | 5 | {4:0,5:1} | [0,1,1] |
 | 4 | 3 | {1:0、2:1、3:2} | [0,1,0,2] | 6 | {4:0,5:1,6:2} | [0,1,1,2] |

 エンコードされたシーケンスは位置 3 で異なるため、出力は NO になります。 

これは、繰り返し構造が 1 つずれただけでも類似性が損なわれることを示しています。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def encode(arr):
        mp = {}
        cur = 0
        res = []
        for x in arr:
            if x not in mp:
                mp[x] = cur
                cur += 1
            res.append(mp[x])
        return res

    t = 1
    out = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        out.append("YES" if encode(a) == encode(b) else "NO")
    return "\n".join(out)

# sample-like cases

assert run("4\n1 2 1 3\n4 5 5 6\n") == "NO"

# custom cases

assert run("2\n1 2\n2 1\n") == "YES"
assert run("3\n1 2 3\n1 1 1\n") == "NO"
assert run("5\n1 2 3 2 1\n4 5 6 5 4\n") == "YES"

 ## 特殊なケース

 重要なエッジ ケースの 1 つは、両方の配列にすべて同じ値が含まれている場合です。 たとえば、A = [7, 7, 7]、B = [3, 3, 3] となります。 最初の要素の後に新しい値が出現しないため、両方のエンコードは [0, 0, 0] になります。 辞書が 1 つのエントリを超えることはないため、アルゴリズムはこれを自然に処理します。 

もう 1 つのケースは、A = [1, 2, 2, 3] および B = [1, 2, 3, 3] など、配列が同じマルチセットであるが異なる構造を持つ場合です。 最初の配列は [0, 1, 1, 2] としてエンコードされ、2 番目の配列は [0, 1, 2, 2] になります。 不一致はまさに 3 番目の位置で発生し、「最初の出現」の同一性が分岐します。 

最後の微妙なケースは、値が大きいか負の場合です。 辞書内のハッシュのみに依存するため、値の実際の大きさは正確性やパフォーマンスに影響を与えません。
