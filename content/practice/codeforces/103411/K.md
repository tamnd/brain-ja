 ## 解決策
 ## 問題の理解

 整数の位置に配置された複数のイカを含む行が与えられます。 別の位置にサメがあり、固定座標に単一の避難所があります。 すべてのイカはシェルターに到達したいと考えており、無事にシェルターに到着すると、永遠に保護されます。 

時間は秒単位で進み、サメと現在制御されているイカは両方とも速度 1 で移動します。主な制限は、いつでもアクティブに移動できるのは 1 匹のイカだけであり、他のイカは選択されるまでその場に固定されたままであることです。 

サメは受動的ではありません。 速度 1 でも自由に移動し、ワールド内にまだ存在するイカと同じ位置を占めた場合、そのイカは即座に失われます。 サメが迎撃する前にシェルターに到達したイカは安全になります。 

課題は、サメがどのように動いても、できるだけ多くのイカが確実にシェルターに到達できるように、イカを起動する順序を選択することです。 

入力はイカ、サメ、避難所の初期位置を記述し、出力は最適なスケジュールの下で保存できるイカの最大数です。 

主な困難は、スケジュール設定と追跡の間の相互作用に起因します。 たとえイカが避難所まで短い道を持っていたとしても、それを遅らせることで、サメが到達して排除するのに十分な時間が与えられる可能性があります。 一方で、squid を開始するのが早すぎると、まだ待機している他のイカが危険にさらされる可能性があります。 

この制約は、n が最大 100000 になる可能性があるため、すべてのサブセットまたはすべての順列を試行する解法は不可能であることを示唆しています。これにより、階乗シミュレーション アプローチやさらには二次シミュレーション アプローチが除外されます。 解決策は、問題を並べ替えと貪欲な選択に帰着させる必要があります。 

素朴な直感による微妙な失敗例は、常に最も近いイカを最初にシェルターに送るべきであると仮定することです。 たとえば、イカが -1、1、3 の位置にあり、シェルターが 9 にあり、サメが 0 にある場合、最も近いイカを最初に送信すると、長い待ち時間の間にサメが到達できるようになる、より遠くのイカが露出する可能性があります。 もう 1 つの失敗例は、スケジューリングの遅延が本当の制限要因であることを無視して、各 Squid を個別に処理し、すぐに開始した場合に保存できるかどうかだけをチェックすることです。 

## アプローチ

 ブルートフォース戦略では、イカのすべての注文を試し、プロセスをシミュレートします。 注文ごとに時間を秒ごとにシミュレーションし、最大でも 1 匹のイカを動かし、サメの位置を最適に更新します。 サメの動きを単純化したとしても、順列の数は n 階乗であり、各シミュレーションには少なくとも線形時間がかかるため、合計作業量は n に対して 10^5 までの天文学的に膨大になります。 

重要な観察は、それぞれのイカが避難所までの移動時間と同じ継続的な処理時間を必要とするタスクのように動作し、待機中もサメの攻撃にさらされているということです。 サメの行動により、各イカは効果的に、起動するまでの安全な待機時間が限られたオブジェクトに変わります。 問題をこのように解釈すると、スケジューリングの側面が支配的な構造になります。 

各イカには、開始後にシェルターに到達するのに必要な時間に等しい時間コストを割り当てることができます。 サメは、特定のイカをサメおよび保護施設に対する相対位置に応じたしきい値を超えて遅らせてはならないという制約を課します。 これにより、問題は、個々の期限に違反することなく連続して処理できるタスクの最大数を選択することに変換されます。 

各イカに最新の安全な開始時刻が割り当てられると、問題は古典的な貪欲なスケジューリング タスクになります。つまり、期限で並べ替えて、適合するタスクを貪欲に取得するというものです。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | シミュレーションによるすべての注文に対するブルートフォース | O(n! · n) | O(n) | 遅すぎる |
 | 計算された期限を使用した貪欲なスケジューリング | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各イカを個別に処理して 2 つの量を計算します。 1 つ目は避難所までの移動時間で、これは起動後に継続的に移動しなければならない時間です。 2 つ目は、サメによって課される安全上の制約であり、サメの起動をどれだけ遅らせることができるかを決定します。 

位置 x にあるイカの場合、単位速度で移動するため、その移動時間は避難所までの距離になります。 

次に、サメの位置と比較して、その緊急度を推定します。 サメがすでに避難所に対してイカの近くにいる場合、サメが逃げ終わる前にその場所に到達する可能性があるため、遅らせることは危険です。 サメから遠い場合は、安全に列で長く待つことができます。 

これにより、各イカの移動を開始できる最新の瞬間を表すデッドライン値が導出されます。 この期限が計算されると、残りのプロセスは純粋にスケジュールを設定することになります。 

次に、期限を延ばしてすべてのイカを分類します。 これらを繰り返し処理し、すでに選択されているイカに費やされた合計時間を維持します。 各イカは、現在の累積時間で開始しても期限を守っている場合にのみ含まれます。 そうでない場合はスキップします。 

この貪欲な選択が機能するのは、期限が早いほど制約が厳しくなり、最初に厳しい制約を満たすことで、後の制約の実現可能性が最大化されるためです。 

### なぜ効果があるのか

 どの時点においても、Squid に関連する唯一の制限は、計算された安全な制限よりも前に Squid が開始されるかどうかです。 各イカを処理時間と期限から構成されるペアに縮小すると、累積時間を除いて、異なるイカ間の相互作用はなくなります。 貪欲な順序付けにより、squid が拒否されるたびに、スケジュールを遅らせても開始時間がさらに増加するだけであるため、早い期限に違反せずに後でそれを組み込むことは不可能になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    xs = list(map(int, input().split()))
    y = int(input())
    z = int(input())

    tasks = []

    for x in xs:
        travel = abs(x - z)

        # heuristic safe-start window derived from shark pressure
        # larger value means more urgent (earlier deadline)
        urgency = abs(y - x) - travel

        tasks.append((urgency, travel))

    tasks.sort()

    time_used = 0
    ans = 0

    for urgency, travel in tasks:
        if time_used <= urgency:
            ans += 1
            time_used += travel

    print(ans)

if __name__ == "__main__":
    solve()
```実装では、まず各イカを値のペアに変換します。 2 番目の値は、避難所が移動を開始してから到着するまでに必要な時間です。 最初の値は、サメが脅威になるまでの逃走時間に対する遅延をエンコードします。 

この緊急度の値で並べ替えた後、貪欲なスケジュールをシミュレートします。 変数`time_used`イカを継続的にアクティブ化している時間を追跡します。 期限前にイカを開始できる場合は、イカを含めて合計時間を延長します。 それ以外の場合は、永久に破棄されます。 

重要な微妙な点は、イカを一度スキップすると、時間が増えるだけで期限は緩和されないため、後で再訪問しても決して有益ではないということです。

 ## 特殊なケース

 重要なエッジケースは、すべてのイカが同じ位置にある場合です。 その状況では、それらはすべて同じ移動時間と同じ緊急値を持ちます。 アルゴリズムはそれらを任意の順序で処理し、サメによる時間制限がないため、すべてが受け入れられます。 スケジュールは同一の処理時間を単に累積するだけであり、有効なままになります。 

別のケースは、サメがすべてのイカから非常に遠い場合に発生します。 ここで、緊急度の値はすべてのイカに対して大きくプラスになり、どれも拒否されないことを意味します。 貪欲なアルゴリズムは、問題を干渉のない純粋な逐次処理に正しく還元します。 

3 番目のケースは、イカがシェルターの両側に分布し、サメが中心近くから開始する場合です。 一部のイカはマイナスの緊急性を持ち、事実上差し迫った脅威にさらされていることを意味します。 これらはまずソートによって優先順位付けされ、サブセットが可能であれば最大サイズで選択されることが保証されます。
