 ## 解決策
 ## 問題の理解

 私たちには次のようなネットワークが与えられています$n$正確に接続された星系$n-1$双方向の高速道路がツリーを形成します。 2 つのシステム間には、単純なパスが 1 つだけ存在します。 この構造は最初は固定されていますが、以前は接続されていなかった 2 つのシステム間に 1 つの追加のハイウェイを追加することができます。 

各星系は、ローカルに定義された多数の「ジャンクション」(ステートメントではフォークと呼ばれています) に貢献します: ノードに次数がある場合$d$、その後、貢献します$\binom{d}{2}$これは、システム内のトンネルを介して、発生する道路のすべてのペアを一意に接続できるためです。 ネットワークの合計スコアは次の合計です。$\binom{\deg(v)}{2}$すべての頂点にわたって。 

タスクは、追加する新しいエッジを 1 つ選択し、それに応じて次数を更新した後、これらのローカル寄与の合計が最大化されるようにし、選択したエッジを出力することです。 

制約$n \le 2 \cdot 10^5$すべてのノードのペアにわたる二次関数を除外します。 どのソリューションでも、ツリーを線形または線形に近い時間で処理する必要があります。 すべての候補エッジのスコアを再計算するソリューションには、$O(n^2)$チェック、それは不可能です。 

微妙な点は、エッジを追加するとちょうど 2 つのノードの次数が増加することです。 それ以外はすべて変更されません。 したがって、最適化全体は 2 つのエンドポイントを選択することになります。 

単純な間違いは、2 つの高次ノードの接続が常に最適であると仮定することです。 これは失敗します。ゲインは次数だけでなく、二次式を通じてそれらの次数がどのように相互作用するかにも依存するためです。$\binom{d}{2}$、ここで限界利得は次のように線形に依存します。$d$。 

## アプローチ

 ブルートフォースアプローチでは、ノードのすべてのペアが試行されます。$u, v$、それらの間にエッジを追加する効果を計算し、最適なものを選択します。 各ペアについて、2 次を更新し、寄与度の合計を再計算し、コストを計算します。$O(n)$ペアごとに。 これは次のことにつながります$O(n^3)$全体として、それは限界をはるかに超えています。 

すべてのノードのベースライン寄与が固定されており、新しいエッジのエンドポイントのみが変化することに気づくことで改善できます。 ノードの次数を増やすと$x$1 増えると、その寄与度は次のように変化します。$\binom{d}{2}$に$\binom{d+1}{2}$の増分を与える$d$。 したがって、接続による合計ゲインは$u$そして$v$単純に$\deg(u) + \deg(v)$、他のすべてから独立しています。 

これにより、問題は、次数の合計を最大化する元のツリー内の隣接しない 2 つのノードを選択するという問題に分解されます。 「まだエッジによって接続されていない」という制約は既存のエッジを除外するだけなので、元の隣接エッジを選択することは避けなければなりません。 

これで、構造は純粋に組み合わせになります。元のエッジを除いて、次数の合計が最大になる 2 つのノードが必要になります。 ノードを次数で並べ替えると、最適な候補が最高次数の頂点の中にあることがわかりますが、選択したペアが既存のエッジではないことを確認する必要があります。 

隣接関係セットを維持し、高次ノードのペアリングを貪欲に試し、実現可能性をチェックできます。 少数の上位候補のみが重要であるため、すべてのペアを検査する必要はなく、最適な非エッジが見つかることを保証できれば十分です。

 ## アルゴリズムのチュートリアル

 1. すべてのエッジをスキャンして、すべてのノードの次数を計算します。 これは、エンドポイントのゲインが現在の次数のみに依存するため必要です。 
2. エッジがすでに存在するかどうかを定数時間または対数時間でチェックできるように、隣接構造 (ノードごとに設定されたハッシュまたはソートされたリスト) を構築します。 すべてのペアが許可されるわけではないため、この制約は重要です。 
3. すべてのノードを次数の降順に並べ替えます。 ゲインは度単位で加算されるため、最適なペアは高次のノードから得られるはずであると直感的に考えられます。 
4. 上位から形成される候補ペアを検討する$K$この順序でのノード、ここで$K$計算を安価に保つのに十分小さいですが、正確性を保証するのに十分な大きさです。 実際には、上位間のすべてのペアをチェックします$K$（と$K \approx 100$または$200$) で十分です。最適なペアには、最高次数の頂点の中に少なくとも 1 つのノードが含まれている必要があるからです。 
5. 各候補ペアについて$(u, v)$、それらの間に元のエッジがない場合は、スコアを計算します。$deg[u] + deg[v]$を選択し、最適なペアを追跡します。 
6. 最適なペアと、元の合計に加算された達成可能な最大ゲインを出力します。 

### なぜ効果があるのか

 エッジを追加した後の合計の寄与は、そのエンドポイントの次数にのみ依存し、各エンドポイントは独立して寄与します。 したがって、合計スコアを最大化することは、$deg(u) + deg(v)$という制約のもとで$(u, v)$は既存のエッジではありません。 次数が唯一のパラメータであるため、最適な解にはツリーの最大次数領域に近いノードが含まれている必要があり、ソートされた次数リストの十分に大きなプレフィックスをスキャンすることで、最適なエンドポイントが確実に含まれるようになります。 隣接性制約は、望ましさの順序を変更せずに、無効なペアを削除するだけです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    adj = [set() for _ in range(n)]
    deg = [0] * n

    edges = []
    for _ in range(n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        adj[u].add(v)
        adj[v].add(u)
        deg[u] += 1
        deg[v] += 1
        edges.append((u, v))

    order = sorted(range(n), key=lambda x: -deg[x])

    base = 0
    for d in deg:
        base += d * (d - 1) // 2

    K = min(n, 200)
    best_gain = -1
    best_pair = (0, 1)

    for i in range(K):
        u = order[i]
        for j in range(i + 1, K):
            v = order[j]
            if v not in adj[u]:
                gain = deg[u] + deg[v]
                if gain > best_gain:
                    best_gain = gain
                    best_pair = (u, v)

    total = base + best_gain
    print(total)
    print(best_pair[0] + 1, best_pair[1] + 1)

if __name__ == "__main__":
    solve()
```コードはまず、次数と隣接セットを計算しながらツリーを構築します。 隣接セットは、無効な候補エッジを迅速に拒否するために不可欠です。 

基本値はフォークの初期数を計算しますが、最適化ステップでは実際にはエッジの選択には基本値が必要ではなく、出力のためにのみ必要です。 

上部の二重ループ$K$ノードは核となるヒューリスティック削減です。 の選択$K$これは、最適なエンドポイントが高次のノード間にあるという仮定の下で正確さを維持しながら、実際にアルゴリズムを線形に保つためのものです。 

よくある落とし穴は、グローバル構造ではなく、エンドポイントのみが重要であることを忘れることです。 もう 1 つは、すべての仮説エッジの後で寄与を再計算しようとするものですが、これは不必要です。 

## 実用的な例

 ### 例 1

 入力:```
4
1 2
2 3
3 4
```学位は$[1,2,2,1]$、基本貢献度は$0 + 1 + 1 + 0 = 2$。 

次数ごとの上位ノードは 2 と 3 (1 から始まるインデックス) です。 これらはすでに接続されているため、スキップします。 次に最適な有効なペアは、隣接関係に応じて (1,3) または (1,2) スタイルであり、エッジ以外で最適なペアは (1,3) です。 

| ステップ | あなた | v | 度[u] + 度[v] | 有効 | ベスト |
 | --- | --- | --- | --- | --- | --- |
 | 1 | 2 | 3 | 4 | いいえ | - |
 | 2 | 1 | 3 | 3 | はい | (1,3) |

 最終的な答え: 基数 + 3。 

これは、最大の生の合計が得られる場合でも、最高次数の隣接関係が拒否されなければならない理由を示しています。

 ## 特殊なケース

 重要なエッジ ケースは、2 つの最高次数ノードがすでに接続されている場合です。 このような状況では、単純な貪欲なアプローチでは無効なエッジが誤って選択されてしまいます。 このアルゴリズムは、候補ペアを受け入れる前に隣接性を明示的にチェックすることでこれを回避します。 

もう 1 つのケースは、複数のノードが同じ最大次数を共有する場合です。 星状構造では、多くの葉が次数 1 を持ち、中心だけが異なります。 このアルゴリズムは、絶対的な同一性ではなくペアごとの合計のみを考慮するため、依然として機能します。 

最後に、次のような非常に小さな木に$n=3$の場合、1 つを除くすべてのペアは無効であり、隣接フィルタリングにより不正な選択が排除されるため、アルゴリズムは唯一の利用可能な非エッジに正しくフォールバックします。
