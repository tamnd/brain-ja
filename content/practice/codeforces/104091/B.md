 ## 問題の理解

 基数のある位置記数法が与えられています$b$。 すべての整数にはその基数での表現があり、その表現の末尾のゼロの数に興味があります。 

数値が有効であるとみなされるのは、base で書かれた場合です。$b$、最後の数字には少なくとも次の値が含まれます$d$ゼロ。 言い換えれば、その数は次で割り切れる必要があります。$b^d$。 タスクは、範囲内の整数の個数をカウントすることです。$[l, r]$この割り切れる条件を満たします。 

この制約により、直ちに直接の列挙から遠ざけられます。 範囲は最大です$10^{18}$したがって、すべての数値を反復処理することは不可能です。 ベース$b$最大でも 100 なので、$b^d$まだ管理可能なので、$d \le 9$、ただし、単純なチェックには数値の範囲が大きすぎます。 

よくある失敗例は、10進数の直感だけで考えたときに現れます。 たとえば、10 進法では、少なくとも 2 つのゼロで終わる数字を数えるということは、100 の倍数を数えるということになります。しかし、2 進数または 7 進数では、有効な数値間の間隔が大幅に変化します。 の各数値の割り算をチェックする単純なループ$[l, r]$次のような範囲ではタイムアウトになります$10^{18}$。 

もう 1 つの微妙な落とし穴は、ハンドリングです。$d = 0$。 この場合、末尾に少なくとも 0 個のゼロがあることが常に true になるため、すべての数値が有効になります。 この特殊なケースを忘れた実装では、次のように誤って割り算を計算しようとします。$b^0 = 1$これは数学的には問題ありませんが、一貫性を持たずに処理すると、ロジックに不必要な複雑さやエッジケースのバグが発生する可能性があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。すべての整数を反復処理します。$x$から$l$に$r$、ベースに変換します$b$、末尾のゼロをカウントし、カウントが少なくとも$d$。 これは定義に直接従っているため、正しいです。 ただし、数値を基数に変換すると、$b$費用$O(\log_b x)$、これを最大で行います$10^{18}$数字。 たとえ高速な演算を行ったとしても、これは実現不可能です。 

重要な観察は、底の末尾にゼロがあることです。$b$で割り切れるのと等価です$b^d$。 数字が少なくとも次の文字で終わる場合$d$基数にゼロ$b$の場合、次の形式でなければなりません。$k \cdot b^d$。 したがって、問題は、次の倍数を数えるということになります。$b^d$寝そべる$[l, r]$。 

これにより、問題は古典的なプレフィックスカウントタスクに変わります。 の倍数を計算します。$b^d$以下である$r$、以下の数を引きます。$l$、一定時間内に答えが得られます。 

唯一の微妙な点は、次のようなエッジケースの正確性を確保することです。$l = 1$と大きな値$b^d$を超える可能性があります$10^{18}$。

 ## アルゴリズムのチュートリアル

 問題を固定値の倍数を数えるという問題に落とし込みます。$p = b^d$範囲内。 

1. コンピューティング$p = b^d$。 これは、基数が次のような最小の数を表します。$b$代表者は少なくとも$d$末尾のゼロ。 
2. もし$d = 0$、すぐに戻ります$r - l + 1$, すべての数値が条件を満たしているためです。 
3. の倍数を計算します。$p$以下である$r$、つまり$\left\lfloor \frac{r}{p} \right\rfloor$。 
4. の倍数を計算します。$p$厳密に以下です$l$、つまり$\left\lfloor \frac{l-1}{p} \right\rfloor$。 
5. これら 2 つの値を減算して、有効な数値の数を取得します。$[l, r]$。 

ステップ 4 の背後にある推論は重要です。プレフィックスを次の数まで数えています。$r$そしてその前にすべてを削除します$l$, したがって、以下より厳密に小さい数値を除外する必要があります。$l$、以下のものではありません$l$。 

### なぜ効果があるのか

 割り切れるすべての整数$b^d$少なくとも$d$基数の末尾のゼロ$b$, を乗算するため、$b$基数の数字を左にシフトします$b$そしてゼロを追加します。 逆に、少なくとも$d$末尾のゼロは割り切れる必要があります$b^d$。 これにより、有効な数値とその倍数の間に 1 対 1 の対応関係が確立されます。$b^d$したがって、有効な数を数えるということは、正確には間隔内の倍数を数えるということになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

b = int(input().strip())
d = int(input().strip())
l = int(input().strip())
r = int(input().strip())

if d == 0:
    print(r - l + 1)
else:
    p = pow(b, d)
    def count(x):
        if x <= 0:
            return 0
        return x // p

    ans = count(r) - count(l - 1)
    print(ans)
```このソリューションは、問題を倍数の算術に還元することを中心に構築されています。 重要なステップはコンピューティングです$b^d$組み込みのべき乗を効率的に使用して、Python の大きな整数範囲内の大きな値を安全に処理します。 

引き算`count(r) - count(l - 1)`の倍数であるため、左境界が正しく含まれることが保証されます。$p$に等しい$l$数えなければなりません。

 ## 特殊なケース

 いつ$d = 0$、定義は空虚になります。すべての数値の末尾に少なくとも 0 個のゼロが含まれます。 アルゴリズムは、完全な間隔サイズを即座に返すことでこれを処理し、不必要な累乗を回避します。 

いつ$b^d > r$、おそらくゼロ以外に有効な数値はありません。ゼロは範囲外です。$l \ge 1$。 除算ベースの数式は当然ゼロを返します。$\lfloor r / p \rfloor$そして$\lfloor (l-1)/p \rfloor$はゼロです。 

いつ$l$それ自体はの倍数です$b^d$、との引き算$l - 1$包含を保証します。 たとえば、$l = 8$、$b^d = 8$、 用語$count(l - 1) = count(7) = 0$なので、8は正しく数えられます。 

これらのケースでは、算術公式がすべての境界条件にわたって元の末尾ゼロの定義と一致することが確認されます。
