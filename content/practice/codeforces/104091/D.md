 ## 問題の理解

 次のような長方形のグリッドが与えられます。$n$行と$m$列。 このグリッドの中には、$q$スカウトと呼ばれる特別なアイテム。 各スカウトは個別のセルに座ります$(x, y)$、 どこ$x$は上から下への行インデックスです。$y$左から右への列インデックスです。 

スカウトは、自身の位置を含め、厳密にその右側または厳密にその下の領域にあるすべてのセルを「攻撃」します。 正式には、スカウトは、$(x, y)$すべての細胞をカバーする$(i, j)$そのような$i \ge x$そして$j \ge y$。 複数のスカウトが同じセルをカバーする場合でも、それは 1 回だけカウントされます。 

タスクは、少なくとも 1 つの偵察によってカバーされる個別のグリッド セルの数を計算することです。 

グリッド サイズの制約は非常に大きく、最大で$10^9 \times 10^9$, そのため、グリッドをシミュレートすることはできません。 スカウトの数は最大です$10^5$これは、どのソリューションもセルごとの処理を回避し、代わりに幾何学的寄与の集約に依存する必要があることを意味します。 

すべてのグリッド セルをチェックしたり、スカウトごとにその四角形全体を反復しようとしたりする単純なアプローチは、1 つのスカウトでカバーできる可能性があるため、不可能です。$10^{18}$細胞。 

あまり目立たない失敗例は、重複によって発生します。 たとえば、スカウトが 1 人いる場合、$(1, 1)$そしてもう一つは$(2, 2)$、2 番目のスカウトの領域は最初の領域に完全に含まれているため、交差を明示的に処理しない限り、単純な合計は大幅にオーバーカウントします。 

重要な問題は、各スカウトが右下の四角形を定義しており、これらの四角形の和集合のサイズが必要であることです。 

## アプローチ

 各スカウトは、グリッドの右下隅まで広がる軸に沿った長方形を定義します。 したがって、問題は次の和集合領域を計算することになります。$q$長方形。各長方形は$[x, n] \times [y, m]$。 

ブルートフォース解釈では、各四角形内のすべてのセルにマークを付けることになりますが、各四角形が巨大になる可能性があるため、これは完全に不可能になります。 境界構造だけを処理しようとしても、直接展開は依然として次の要素に依存します。$n \cdot m$、大きすぎます。 

重要な観察は、すべての長方形が同じ「ターゲット コーナー」を共有していることです。$(n, m)$、その形状は単調です。グリッド境界内で真下に無限に広がります。 この単調な構造により、スカウトをソートし、結合プロセスを圧縮して、行ごとまたは列ごとに貢献をカウントすることができます。 

2D で考えるのではなく、視点を逆転させます。 固定列の場合$x$、細胞$(x, y)$どこかにスカウトがいる場合にのみカバーされます$(x', y')$と$x' \le x$そして$y' \le y$。 同様に、最大でも行座標を持つすべてのスカウトを見ると、$x$、列のカバレッジにしきい値を課します。 

これは、行を下から上にスイープすることを示唆しています。 上に移動するにつれて、より多くの偵察がアクティブになり、アクティブな各偵察は、列をどこまで左に考慮する必要があるかに関する制約に影響します。 特定の行については、列の最小しきい値のみが重要になります。最小値がわかれば、$y$すべてのスカウトの中で$x' \le x$、その最小値から次の値までのすべての列$m$カバーされています。 

したがって、各行のカバーされる間隔は単純に次のようになります。$[ \min y \text{ among active scouts},\ m]$、答えは間隔の長さの行の合計です。 一意ごとにグループ化することで、行の反復処理を明示的に回避します。$x$コーディネート。

 ## アルゴリズムのチュートリアル

 1. すべてのスカウトの位置を読み取り、行座標ごとにグループ化します。$x$。 行ごとに列位置のリストを保存します$y$。 これは、ボトムアップスイープでスカウトの列に到達したときにスカウトの効果がアクティブになるため、必要です。 
2. すべての個別の行座標を昇順に並べ替えます。 行を下から上に処理して、スカウトがアクティブ化されると、上のすべての行でアクティブなままになるようにします。 
3. 現在の値を維持する`min_y`、として初期化されます$m+1$。 これは、スイープで現在アクティブなすべてのスカウトの中で最小の列インデックスを表します。 
4. 行から開始$n$まで$1$。 各列で$x$、まず、更新してその行に正確に配置されているすべてのスカウトをアクティブにします`min_y = min(min_y, y)`それぞれに。 このステップにより、次のことが保証されます。`min_y`すべてのアクティブなスカウトによって課された最も狭い左側の境界を常に反映します。 
5. 行のアクティベーションの処理後$x$、この行に含まれるセルの数を計算します。$\max(0, m - min_y + 1)$。 これが機能するのは、次のすべての列が`min_y`に$m$少なくとも 1 人のアクティブなスカウトによってカバーされることが保証されています。 
6. この値を答えに累積します。 
7. 行 1 が処理されるまで続行します。 

### なぜ効果があるのか

 任意の固定行で$x$、細胞$(x, y)$少なくとも 1 人のスカウトが存在する場合に適用されます$(x', y')$そのような$x' \le x$そして$y' \le y$。 すべてのアクティブなスカウトの中で（$x' \le x$)、状態は次のように減少します。$y \ge \min y'$。 したがって、各行のカバレッジは、アクティブなスカウトの中で最も小さい列のしきい値によって完全に決定されます。 スイープではこの不変条件が正​​確に維持されるため、すべての行が重複や省略なく正確にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, q = map(int, input().split())
    
    by_row = {}
    for _ in range(q):
        x, y = map(int, input().split())
        if x not in by_row:
            by_row[x] = []
        by_row[x].append(y)

    min_y = m + 1
    ans = 0

    for x in range(n, 0, -1):
        if x in by_row:
            for y in by_row[x]:
                if y < min_y:
                    min_y = y

        if min_y <= m:
            ans += (m - min_y + 1)

    print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、スキャンの繰り返しを避けるために、スカウトを行ごとにグループ化します。 重要な状態変数は次のとおりです。`min_y`、すべてのアクティブなスカウトを単一の有効な境界に圧縮します。 からのループ$n$まで$1$スカウトがアクティブになると、そのスカウトがその上のすべての行に影響を与えるようになります。 

表現`m - min_y + 1`各行でカバーされるサフィックスの長さを直接カウントします。 条件`min_y <= m`アクティブなスカウトが存在しない場合、またはアクティブなスカウトがすべてグリッド範囲外にある場合、カウントを防止します。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from math import isclose
    import sys
    input = sys.stdin.readline

    n, m, q = map(int, input().split())
    by_row = {}

        x, y = map(int, input().split())
