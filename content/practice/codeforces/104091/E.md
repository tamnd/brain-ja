 ## 解決策
 ## 問題の理解

 幅の長い 1D ストリップのように動作する単純化された 2D 世界をシミュレートしています。`n`そして垂直方向の高さは無制限です。 最初は、このストリップのすべての位置が草で覆われています。 

プロセス中に、ゲーム エンジンは地球ブロックの水平セグメントを生成します。 各セグメントは開始位置によって記述されます`a`そして長さ`b`。 これは、からのすべてのポジションが`a`に`a + b - 1`ブロックを受け取ります。 ブロックを所定の位置に置くと、真っすぐに落ちて、その位置にある既存のブロックの上に積み重なって、垂直の土の柱が形成されます。 

重要な観察は、草は地球が占有していないセルにのみ存在するということです。 エンジンは、現在表示されている草のテクスチャの数に関心を持ちます。これは、ストリップ内でまだ土のブロックがまったくない位置の数に相当します。 

タイプの各クエリ`2`これまでにブロックの配置によって完全に影響を受けていない現在の位置の数を求めます。 

制約により、最大で次のことが許可されます。`n = 10^6`ポジションと最大`q = 10^4`操作。 これにより、クエリごとに直線的な時間で答えを最初から再計算するソリューションは即座に除外されます。`n`、それには最大の費用がかかるため、`10^10`最悪の場合の運用。 範囲の更新と、理想的には操作あたりの対数時間での高速なグローバル集計をサポートする必要があります。 

微妙な落とし穴は、重複するセグメントが解答内で独立してスタックされないことです。 ポジションが少なくとも 1 回カバーされると、たとえ後からセグメントが追加されたとしても、そのポジションは再度草としてカウントされるべきではありません。 

## アプローチ

 直接シミュレーションは配列を維持します`covered[i]`位置かどうかを示す`i`ブロックを受け取ったことがあります。 タイプの各更新`1 a b`セグメントを反復処理し、すべての位置をカバー済みとしてマークします。 タイプの各クエリ`2`カバーされていないエントリの数をカウントします。 

このアプローチは正しいですが、遅すぎます。 最悪の場合、1 回のアップデートで影響を受ける可能性があります。`O(n)`ポジションがあり、`O(q)`このような更新により、二次関数の動作が引き起こされます。 

構造上の重要な観察は、積み重ねられたブロックの正確な数ではなく、位置がゼロか非ゼロかを知る必要があるだけであるということです。 各操作はゼロの範囲を 1 に変換し、位置が 1 になると、その位置は永久に 1 のままになります。 これは、範囲の増分の下で動的配列を維持する典型的なケースであり、値がどこでもゼロのままであるかどうかのみを考慮します。 

これにより、セグメントの長さを維持するという問題が軽減されます。`n`ここでは、範囲の 1 ずつの増分をサポートし、ゼロのままの要素の数をクエリします。 遅延伝播を備えたセグメント ツリーは、この構造に自然に適合します。各ノードは、セグメント内のゼロのままの位置の数を追跡し、フリップ セグメントを完全にゼロから完全にゼロでないものに効率的に更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース配列マーキング | O(nq) | O(n) | 遅すぎる |
 | 遅延伝播を使用したセグメント ツリー | O((n + q) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 サイズの配列にわたってセグメント ツリーを維持します。`n`。 各位置はゼロから始まり、まだ草で覆われていることを意味します。 

セグメント ツリー内の各ノードは、その間隔内でゼロのままの位置がいくつあるかを格納します。 さらに、セグメント全体が少なくとも 1 回カバーされているかどうかを示す遅延マーカーを維持します。 

1. すべての位置に最初は草が含まれているため、すべての葉が 1 に初期化されるセグメント ツリーを構築します。 
2. アップデートについて`1 a b`、間隔で範囲更新を適用します`[a, a + b - 1]`。 セグメントが完全に更新範囲内にあり、現在完全にゼロである場合、そのセグメントを完全にカバーされているとマークし、そのゼロ カウントを 0 に設定します。 
3. 更新をプッシュダウンするときに、ノードがすでに完全にカバーされているとマークされている場合、それ以上再帰することなく、両方の子がすぐに完全にカバーされるように設定されます。 
4. 部分的な重複は、子を再帰的に更新し、親のゼロ カウントを子の合計として再計算することによって処理されます。 
5. お問い合わせの場合`2`の場合、答えはルート ノードに保存されているゼロ カウントであり、カバーされていない位置の数を表します。 

重要な設計上の選択は、正確なカバレッジ数を決して保存しないことです。 セグメントが完全にゼロ以外になると、再び変更されることはないため、積極的に折りたたみます。 

### なぜ効果があるのか

 各ポジションは、アンカバーからカバーへの移行は最大 1 回です。 セグメント ツリーにより、セグメントが完全にカバーされると、詳細な更新のために再度アクセスすることはなくなります。 カバレッジは単調であり、すべての更新では変更を元に戻すことなくシステムを完全にカバーされた状態に近づけるだけであるため、これにより正確さが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class SegTree:
    def __init__(self, n):
        self.n = n
        self.size = 4 * n
        self.zero = [0] * self.size   # number of zeros in segment
        self.lazy = [0] * self.size   # 0 = untouched, 1 = fully covered

        self.build(1, 1, n)

    def build(self, v, l, r):
        if l == r:
            self.zero[v] = 1
            return
        m = (l + r) // 2
        self.build(v*2, l, m)
        self.build(v*2+1, m+1, r)
        self.zero[v] = self.zero[v*2] + self.zero[v*2+1]

    def push(self, v, l, r):
        if self.lazy[v] == 0:
            return
        if l != r:
            self.lazy[v*2] = 1
            self.lazy[v*2+1] = 1
        self.zero[v] = 0
        self.lazy[v] = 0

    def update(self, v, l, r, ql, qr):
        self.push(v, l, r)
        if r < ql or qr < l:
            return
        if ql <= l and r <= qr:
            self.lazy[v] = 1
            self.push(v, l, r)
            return
        m = (l + r) // 2
        self.update(v*2, l, m, ql, qr)
        self.update(v*2+1, m+1, r, ql, qr)
        self.zero[v] = self.zero[v*2] + self.zero[v*2+1]

def solve():
    n, q = map(int, input().split())
    st = SegTree(n)

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            a = int(tmp[1])
            b = int(tmp[2])
            st.update(1, 1, n, a, a + b - 1)
        else:
            print(st.zero[1])

if __name__ == "__main__":
    solve()
```セグメント ツリーは、最初はすべてのノードが完全に草で覆われた空間を表すように構築されます。 の`zero`配列は、各セグメント内に未処理の位置がいくつ残っているかを追跡します。 の`lazy`フラグを使用すると、セグメントが完全にカバーされると、そのセグメントを再度訪問することに時間を無駄にすることがなくなります。 

更新機能は、必要な場合にのみカバレッジを伝達するように注意します。 ノードがペイントされたセグメント内に完全に収まると、ノードはすぐにゼロに折りたたまれ、再帰が停止します。

 ## 特殊なケース

 重要なエッジ ケースは、同じ領域で更新が繰り返されることです。 たとえば、`1 1 3`最初の適用後に答えを 2 回変更してはなりません。 セグメント ツリーは、完全にカバーされたセグメントを折りたたむことでこれを処理するため、2 回目の更新では、すでにマークされているノードが検索され、追加の作業は実行されません。 

もう 1 つのケースは、単細胞の世界です。 と`n = 1`、更新のたびに、そのまま放置されるか、完全にカバーされます。 リーフ ノードは子の伝播に依存せずに直接初期化および更新されるため、構造は引き続き正しく動作します。 

最後の微妙なケースは、複数のステップで最終的に配列全体をカバーする、互いに素な更新です。 遅延伝播により、部分セグメントが正しくマージされることが保証され、ルートは常に未処理の位置の真の合計数を反映します。
