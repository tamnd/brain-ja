 ## 解決策
 ## 問題の理解

 私たちに与えられているのは、`n x n`ちょうど 3 匹の白いコオロギが「L」字型に配置されたチェス盤。 各コオロギはジャンパーのように動きます。コオロギは 8 つの方向 (水平、垂直、斜め) のいずれかで隣接するコオロギを飛び越えることができますが、すぐ隣にコオロギがあり、すぐ先に空のマスがない限り移動することはできません。 入力では、ボードのサイズ、3 つのコオロギの座標、およびターゲットの正方形を指定します。 問題は、有効なクリケットジャンプのシーケンスを使用して、ターゲットの正方形にクリケットを配置することが可能かどうかです。 

制約は重要です。 ボードは 100,000 x 100,000 までの大きさがあり、最大 10,000 のテスト ケースを含めることができます。 これにより、ボード全体の動きのシミュレーションが即座に除外されます。 たとえば、3 つのコオロギすべてから開始する総当たりの幅優先検索には、最大で`O(n^2)`テスト ケースごとの操作。これは次の場合には実行不可能です。`n`は 10^5 です。 コオロギとターゲットの正方形の関連するジオメトリのみを検査するソリューションが必要です。 

「L」字型自体から微妙なエッジケースが生じます。 コオロギは 3 匹しかいないため、ボードの 1 つの角がトラップとして機能する可能性があります。L が角に配置されている場合、すべての動きがボードの端によってブロックされるため、いくつかのマスにはアクセスできなくなります。 たとえば、コオロギが占拠した場合、`(1,1)`、`(1,2)`、 そして`(2,1)`そしてターゲットは`(3,3)`、ジャンプではクリケットの上を直線で移動する必要があるため、コオロギはターゲットに到達できませんが、コーナーから斜めに移動することはボードの境界によってブロックされます。 

## アプローチ

 ブルートフォースアプローチでは、目標に到達するか、新しい動きが不可能になるまで、コオロギの可能なすべての動きをシミュレートしようとします。 各動きでは、各クリケットの 8 方向すべてをチェックし、ジャンプが合法かどうかを確認する必要があります。 最悪の場合、訪問した取締役職の数は次のとおりになる可能性があります。`O(n^2)`に移動数を乗算します。これは最大になる可能性があります。`O(n^2)`同じように。 と`t`テスト ケースでは、これは実行可能な計算限界をすぐに超えます。 

重要な洞察は、コオロギの動きは、コオロギの位置の同等性とコオロギが最も近いボードの角によって完全に決定されることに気づくことです。 コオロギは「L」字形で始まるため、3 匹のコオロギのうち 1 匹は隅または奇数と偶数の座標の交差点に位置します。 ターゲットは、このコーナーに対して行方向と列方向の両方に沿って同じパリティを共有する場合にのみ到達可能です。 もう 1 つの観察は、いずれかのクリケットが両方の座標が奇数または両方が偶数の正方形を占めている場合、ボードの行または列に沿って同じパリティを持つすべての正方形にジャンプを伝播できるということです。 コオロギがコーナー (1,1)、(1,n)、(n,1)、または (n,n) を占有する場合、移動は厳しく制限され、到達可能なマスはそのコーナーへの近さによって決まります。 

これらの幾何学的制約を利用して、問題を「クリティカル コーナー」クリケットに対するターゲットの座標の単純なチェックに減らすことができます。

 ## アルゴリズムのチュートリアル

 1. 「コーナー」コオロギを特定します。 コオロギは「L」字を形成しているため、そのうちの 1 つは他の 2 つと行と列を共有する位置にあります。 ここは実質的に L の角です。`(rc, cc)`その座標になります。 
2. コーナーコオロギが奇数または偶数の座標の境界上にあるかどうかを判断します。 「クリティカルコーナー」を次のように定義します。`(1,1)`、`(1,n)`、`(n,1)`、 または`(n,n)`のパリティに気づくことで`(rc, cc)`。 
3. ターゲットのマスを調べる`(x, y)`。 どちらかの行の場合`x`または列`y`クリティカル コーナーのパリティと一致する場合、合法的なジャンプを介してターゲットに到達できます。 そうでない場合、クリケットはボードの境界を飛び越えたり、L 字形の制約を回避したりできないため、到達できません。 
4. ターゲットがクリティカルコーナークリケットと同じパリティブロックを共有する場合は「YES」を返します。 それ以外の場合は、「NO」を返します。 

これが機能する理由は、クリケット ジャンプが L の角で定義された 1 つのパリティ ブロックに沿ってのみ伝播できるためです。ボードの境界と組み合わせて、隣接するクリケットを飛び越える必要があるため、このブロックの外側の正方形には到達できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        r1, c1, r2, c2, r3, c3 = map(int, input().split())
        x, y = map(int, input().split())

        rows = [r1, r2, r3]
        cols = [c1, c2, c3]

        # Find the L-corner: row and column appearing twice
        from collections import Counter
        row_count = Counter(rows)
        col_count = Counter(cols)
        corner_row = row_count.most_common(1)[0][0]
        corner_col = col_count.most_common(1)[0][0]

        # Check if corner is at a border parity
        if (corner_row % 2 == x % 2) or (corner_col % 2 == y % 2):
            print("YES")
        else:
            # Exception: if corner is in a true corner of the board
            if (corner_row in [1, n] and corner_col in [1, n]):
                if (x in [1, n] or y in [1, n]):
                    print("YES")
                else:
                    print("NO")
            else:
                print("NO")

solve()
```この解決策では、まず、繰り返される行と列の座標を数えることによって、L の角を特定します。 次に、コーナークリケットが実際のボードコーナーにある場合のパリティ制約と例外をチェックします。 オフバイワンエラーは、ボード座標を 1 から始まる整数として直接使用することで回避されます。
