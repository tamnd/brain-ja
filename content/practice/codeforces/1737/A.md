 ## 解決策
 ## 問題の理解

 この問題は、並べ替えと分割の作業として視覚化できます。 次の文字列が与えられます`n`それぞれの文字はタイトルの最初の文字で本を表しており、これらの本を均等に分配する必要があります。`k`コンパートメント。 各コンパートメントには正確に収納できます`n/k`本。 本が配布されると、コンパートメントごとに、最小除外文字 (MEX) を計算します。MEX は、書籍の最初の文字です。`'a'`に`'y'`そのコンパートメントには表示されません。 目標は、次の長さの文字列を生成することです`k`各コンパートメントの MEX 文字で順番に構成されており、結果として得られる文字列を辞書編集的にできるだけ大きくしたいと考えています。 

制約は小さいです。`n`最大でも 200 であり、すべての合計`n`これにより、必要に応じてテスト ケースごとに 2 次または 3 次の複雑さを持つアルゴリズムが可能になりますが、線形または線形に近いアプローチの方がよりクリーンで推論が容易になります。 単純なアプローチを破る可能性のあるエッジケースには、すべての本が同じ文字である、すべての文字が 1 回だけ出現する、またはコンパートメントの数が含まれるなどの状況が含まれます。`k`に等しい`n`、これにより、コンパートメントごとに 1 冊の本が強制されます。 

不注意なアプローチでは、各コンパートメントの MEX を考慮せずに、単純に文字をソートして順番に配布する可能性があり、次のような場合には失敗します。`"cabccadabaac"`と`k=3`。 辞書編集上の優先順位を無視した単純な割り当てでは、次のような問題が発生する可能性があります。`"cdb"`正しいのではなく`"edb"`。 

## アプローチ

 ブルートフォースアプローチでは、ソートされた文字を次のように分割するすべての方法を列挙します。`k`コンパートメントを分割し、各パーティションの MEX を計算し、辞書編集上最大の文字列を選択します。 これは明らかに実現不可能です。パーティションの数は組み合わせによって増加し、`n=200`そして`k=2`、これにはすでに以上のことが含まれます`2^200`可能性。 

重要な洞察は、辞書編集上最大の結果文字列が必要であるため、MEX 文字を可能な限り押し上げるために、必要なだけ多くの最初の文字でコンパートメントを埋めることを優先する必要があるということです。`'z'`できるだけ。 最初に文字列を並べ替えると、各文字の出現回数を簡単に数えることができます。 各コンパートメントに対して、次からの文字の割り当てを開始します。`'a'`コンパートメントがいっぱいになるまで上向きに動かします。 そのコンパートメントで完全に使用できない最初の文字は MEX になります。 コンパートメントが次のすべてのインスタンスを使用する場合、`'a'`、あるかもしれません`'b'`MEX などとして。 利用可能な最小の文字を使用してコンパートメントを順次かつ貪欲に処理することにより、各コンパートメントの MEX が辞書順で最大化されることが保証されます。

 | ブルートフォース | O(組み合わせ(n,k)) | O(n) | 遅すぎる |
 | 貪欲なシーケンシャル MEX | O(n + 26*k) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テスト ケースごとに、文字列を読み取ります。`s`そしてコンパートメントの数`k`。 ～からの各文字の出現を数えます。`'a'`に`'y'`。 カウントを直接操作できるため、文字列の並べ替えはオプションです。 
2. 各コンパートメントのサイズを計算します。`size = n // k`。 空のリストを初期化して、結果の MEX 文字を格納します。 
3. コンパートメントを 1 つずつ処理します。 各コンパートメントに対して、次から始まる文字を割り当ててみます。`'a'`。 現在のコンパートメントで使用された文字の数を追跡します。 文字がそのコンパートメントの残りの数を超えたら、停止します。 このコンパートメントで完全に使用されていない最初の文字は、このコンパートメントの MEX です。 
4. コンパートメントの MEX を決定したら、使用される文字のグローバル カウントをデクリメントし、次のコンパートメントに移動します。 
5. すべてのコンパートメントの MEX 文字を連結して、テスト ケースの最終文字列を生成します。 

正確さを保証する不変条件は、利用可能な最小の文字を常に各コンパートメントで最初に使用することです。 これにより、MEX がアルファベットの可能な限り遠くにプッシュされ、結果として得られる文字列の辞書編集上の値が最大化されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        s = input().strip()
        cnt = [0]*26
        for ch in s:
            cnt[ord(ch)-ord('a')] += 1
        
        res = []
        size = n // k
        
        for _ in range(k):
            mex = 0
            remaining = size
            for i in range(26):
                take = min(cnt[i], remaining)
                remaining -= take
                cnt[i] -= take
                if take < size and remaining == 0:
                    mex = i+1
                    break
                if remaining == 0:
                    mex = i+1 if take == 0 else i
                    break
            if mex == 0:
                while mex < 26 and cnt[mex] == 0:
                    mex += 1
            res.append(chr(ord('a') + mex))
        
        print(''.join(res))

if __name__ == "__main__":
    solve()
```このコードでは、`cnt`利用可能な文字を追跡します。 各コンパートメントについて、次のもので満たそうとします。`size`から始まる文字`'a'`。 レターがコンパートメントを完全に埋めることができない場合、MEX が次のレターになります。 処理後、使用された文字を反映するためにカウントをデクリメントし、後のコンパートメントで MEX が正しく計算されるようにします。 オフバイワンエラーは、`remaining`コンパートメント内の文字と MEX のインデックス。
