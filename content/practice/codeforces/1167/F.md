 ## 解決策
 ## 問題の理解

 個別の数値の配列が与えられ、考えられるすべての連続した部分配列を調べます。 各部分配列について、その要素を昇順に一時的に並べ替えてから、その並べ替えられた部分配列内の位置に基づいて重みを割り当てます。最も小さい要素には重み 1 が与えられ、次の要素には重み 2 が与えられます。 部分配列の値はソート後の重み付き合計であり、タスクはすべての部分配列にわたってこの値を合計することです。 

主な難点は、ソートは元の配列内の位置ではなく、サブ配列内の相対的な順序のみに依存するのに対し、寄与は各サブ配列内の選択された要素よりも小さい要素の数に依存することです。 

n が 5 · 10^5 までの制約により、すべての部分配列に明示的に触れるアプローチも除外されます。 O(n^2) 個の部分配列があり、部分配列ごとに何かを再計算するとすでに大きすぎます。 O(n^2 log n) ですら実現不可能です。 解は本質的に O(n log n) または O(n) でなければなりません。 

微妙なエッジケースは、すべての部分配列が独立してソートされるという事実から生じます。 単純な間違いは、寄与が元の順序で直接蓄積できると考えることですが、各サブ配列内でのランク付けはその仮定を破ります。 もう 1 つの落とし穴は、両方の端点を含むサブ配列の数を正しく追跡せずに、要素のペアを二重にカウントすることです。 

## アプローチ

 総当りの方法は簡単です。すべての部分配列を列挙し、その要素を抽出し、並べ替えて、重み付けされた合計を計算します。 これは定義に直接従うため、正しいです。 ただし、各サブ配列のコストは O(length log length) であり、O(n^2) 個のサブ配列があるため、最悪の場合は O(n^3 log n) になります。 ソートを段階的に最適化しても、サブ配列の数が多すぎるため、十分な効果はありません。 

重要な洞察は、視点を逆転させることです。 サブ配列を構築してソートする代わりに、単一の要素に焦点を当てて、この要素が特定のランクに寄与するサブ配列の数がいくつあるかを尋ねます。 そのランクは、同じ部分配列に含まれる小さな要素の数によってのみ決まります。 そこで、問題を、固定要素に正確に k 個の小さな要素が含まれる部分配列をカウントすることに縮小します。 

これを扱いやすくするために、要素を値で並べ替え、昇順に処理します。 要素を処理する時点で、より小さな要素はすべてすでに「アクティブ」とみなされます。 この要素について、それが含まれるサブ配列の数と、その左右にアクティブな要素が正確に t 個含まれることを知る必要があります。 

アクティブな要素を維持するために、ポジションに対してフェンウィック ツリーを使用します。 要素ごとに、その左右に小さい要素がいくつあるかを数えます。 これらの数は、含まれる小さな要素の数を制御しながら、要素の周囲にサブ配列を拡張できる方法の数を決定します。 

寄与の式は、要素がサブ配列内に k 個のより小さい要素を持つ場合、そのランクの寄与はすべてのサブ配列にわたって k に線形に依存するという事実から導き出すことができます。 すべての要素とすべてのサブ配列を集計すると、左右の境界の組み合わせ構成をカウントすることになります。 

これにより、問題はサブ配列のソートから相対順序に関する間隔のカウントに変換され、これによりフェンウィック ベースのプレフィックス カウントが適用可能になります。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n^3 log n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 すべての部分配列にわたる要素の寄与を使用して、ソートされた重み付き合計を再解釈します。 

### 1. 元のインデックスを維持しながら要素を値で並べ替えます

 要素を処理するときに、より小さな要素がすべてすでに「アクティブ化」されるように、要素を昇順に処理します。 これにより、ランク形成を動的に推論できるようになります。

### 2. ポジション上でフェンウィック ツリーを維持する

 ツリーには、どのインデックスがより小さな要素に既に属しているかが格納されます。 任意のプレフィックスまたは範囲内にアクティブな要素がいくつあるかをカウントすることができます。 ランクは、選択したサブ配列内にどれだけ小さな要素があるかによってのみ決まるため、これは不可欠です。 

### 3. 各要素について、その位置分割を計算します。 

位置 i の要素について、その左右に小さい要素がいくつあるかをクエリします。 

フェンウィック ツリーは left_smaller と right_smaller を与えます。 

この分割により、この要素と特定の数の小さな要素が含まれるサブ配列の数が決まります。 

### 4. この要素が指定されたランクに寄与する部分配列をカウントします。 

現在の要素を修正します。 これを部分配列内に配置するには、左側の境界 l ≤ i と右側の境界 r ≥ i を選択します。 内部の小さい要素の数は、[l, r] 内にあるアクティブな要素の数によって異なります。 

両側の小さい要素の分布はすでにわかっているため、Fenwick クエリから得られたプレフィックス数を使用して、有効な (l, r) ペアを組み合わせてカウントできます。 

### 5. 貢献度の合計

 各要素は、その値にすべてのサブ配列にわたって受け取る合計重みを乗算した値を提供します。 すべての要素にわたるこれらの寄与を合計すると、最終的な答えが得られます。 

### なぜ効果があるのか

 重要な不変条件は、要素を昇順に処理する場合、フェンウィック ツリーはサブ配列内のそのランクを決定する要素のセットを正確にエンコードするということです。 要素を含むすべてのサブ配列は境界の選択に対応し、内部の小さな要素の数は、それらの境界内に収まるアクティブな要素の数によって完全に決まります。 ランクは正確な ID ではなくこのカウントのみに依存するため、寄与はプレフィックス カウントのみから計算できます。 各要素の寄与は、ローカルな考慮において処理された要素の中で最大になった瞬間に 1 回だけ蓄積されるため、サブ配列は二重にカウントされません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.sum(r) - self.sum(l - 1)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    pos = list(range(n))
    pos.sort(key=lambda i: a[i])

    bit = Fenwick(n)

    total = 0

    for idx in pos:
        i = idx + 1

        left = bit.sum(i - 1)
        total_smaller = bit.sum(n)
        right = total_smaller - bit.sum(i)

        bit.add(i, 1)

        contrib = a[idx] * (left + 1) * (right + 1)
        total = (total + contrib) % MOD

    print(total % MOD)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーは、どの要素がすでに処理されているかを値の昇順に追跡します。 要素を処理するとき、その左側のクエリでは左側の小さい要素がカウントされ、右側の計算ではアクティブな要素の合計から左側のプレフィックスを差し引いた値が使用されます。 係数 (左 + 1) * (右 + 1) は、その要素が、含まれる小さい要素の中で現在の最小値になるように、境界を選択するサブ配列の数をカウントします。これは、ソートされたすべてのサブ配列にわたってランクがどのように蓄積されるかに一致します。 

要素値による乗算は、各要素が、それが出現するすべての構成においてその値に比例して寄与することを反映しています。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(n log n) | 要素ごとのインデックスとフェンウィック ツリーの更新/クエリの並べ替え |
 | スペース | O(n) | フェンウィック ツリーと補助配列 |

 各演算は対数であり、演算の合計数は n で線形であるため、複雑さは最大 5 · 10^5 の n の制限内に問題なく収まります。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MOD = 10**9 + 7

    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i

        def sum(self, i):
            s = 0
            while i > 0:
                s += self.bit[i]
                i -= i & -i
            return s

    n = int(input())
    a = list(map(int, input().split()))
    pos = list(range(n))
    pos.sort(key=lambda i: a[i])

    bit = Fenwick(n)
    total = 0

    for idx in pos:
        i = idx + 1
        left = bit.sum(i - 1)
        right = bit.sum(n) - bit.sum(i)
        bit.add(i, 1)
        total = (total + a[idx] * (left + 1) * (right + 1)) % MOD

    return str(total)

 ## 特殊なケース

 単一要素の配列の場合、すべての部分配列はその要素のみで構成されるため、答えは値そのものと等しくなります。 アルゴリズムはアクティブな要素を使用せずにそれを即座に処理し、(0+1)(0+1)=1 を生成するため、寄与は正しいです。 

完全に増加する配列の場合、各要素は、ソートされた処理順序で左側に以前に挿入された要素のみを参照します。 フェンウィック ツリーは右側のカウントがゼロのままであることを保証し、乗算構造は各要素が異なるランクを取る部分配列の組み合わせ数を正しく累積します。 

減少する配列の場合、以前に処理された要素の位置に重複がないという意味で、すべての要素が「右重み」になります。 左右のカウントの対称性により、同じ最終集計が保証され、正確さが元の順序には依存せず、位置の分割のみに依存することが確認されます。
