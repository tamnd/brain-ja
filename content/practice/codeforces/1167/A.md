 ## 解決策
 ## 問題の理解

 数字の文字列が与えられ、残りの数字の相対的な順序を変更することなく、文字を自由に削除できます。 タスクは、有効な電話番号を形成する長さちょうど 11 のサブシーケンスを抽出できるかどうかを判断することです。 有効な電話番号は非常に特殊な構造になっています。長さは 11 で、最初の桁は 8 でなければなりません。残りの 10 桁は何でも構いません。 

したがって、問題は、最初に選択された文字が 11 である長さ 11 のサブシーケンスが文字列に含まれているかどうかをチェックすることになります。`8`。 

各テスト ケースの制約は小さく、文字列の長さは最大 100、テスト ケースは最大 100 個です。 これにより、大量の前処理や高度なデータ構造の必要性が即座に排除されます。 テスト ケースごとのリニア スキャンで十分です。 

素朴ですがよくある間違いは、文字列に少なくとも 1 つが含まれているかどうかを確認するだけでよいと考えることです。`8`その後のどこかに少なくとも 10 桁以上の数字が続きます。 これは近いですが、サブシーケンスの選択は位置に依存するため、順番に注意深く処理しないと正しくありません。 もう 1 つの間違いは、長さ 11 のすべてのサブシーケンスを構築しようとすることです。これは、長さが 100 であっても組み合わせ的に爆発します。$\binom{100}{11}$可能性。 

複数の場合、微妙なエッジケースが発生します。`8`s. たとえば、`88888888888`、任意の位置が開始として機能しますが、文字列内では最初の位置が`8`遅すぎます。その後は文字が足りない可能性があります。 貪欲スキャンでは、残りの利用可能な長さを正確に考慮する必要があります。 

## アプローチ

 ブルートフォースのアイデアは単純です。長さ 11 のすべてのサブシーケンスを生成し、それらのいずれかが次で始まるかどうかを確認します。`8`。 これは、考えられるすべての削除を調査するため、正しいです。 ただし、サブシーケンスの数は急速に増加します。 単一のテストケースであっても、$n = 100$、長さ 11 のサブシーケンスの数は天文学的に多く、このアプローチは実行不可能です。 

重要な点は、サブシーケンスを明示的に構築する必要がないということです。 の位置が存在するかどうかだけを知る必要があります。`8`文字列内でその後に少なくとも 10 文字が来るようにします。 削除によって順序が維持されるため、削除を選択すると、`8`インデックスで`i`、インデックスの後に少なくとも 10 文字以上あることを確認するだけで済みます。`i`。 これらの文字は何でも構いません。 私たちは単にそれらを見た目どおりに受け取るだけです。 

これにより、有効な開始位置をスキャンして残りの長さをカウントするという問題が軽減されます。

 ## アルゴリズムのチュートリアル

 各テストケースを個別に処理します。 

1. 文字列を読み、その数字が含まれるすべての位置をスキャンします。`8`。 このような各位置は、電話番号の開始候補となります。 
2. 各インデックスについて`i`どこ`s[i] == '8'`、接尾辞の長さが次のとおりであるかどうかを確認します。`n - i`は少なくとも 11 です。これにより、これから始まる 11 文字を選択できることが保証されます`8`秩序を保ちながら。 
3. そのような位置が条件を満たす場合は、有効なサブシーケンスが存在すると直ちに結論付けます。 
4. 有効な開始位置が見つからない場合は、出力します。`NO`。 

ステップ 2 の背後にある理由は、最初の桁を次のように修正すると、`8`、その後に必要な追加文字は 10 文字だけです。 私たちはそれらの値に制約されないため、重要なのはその可用性だけです。 

### なぜ効果があるのか

 このアルゴリズムは、単調な可用性プロパティに依存しています。`8`インデックスに表示されます`i`の場合、その後のすべての文字はサブシーケンスの一部となる資格があり、必要なのは 10 個だけです。 有効期限を早めてもスキップしてもメリットはありません`8`■ 後の位置が機能する場合、前の位置では常に少なくとも同じ数の残りの文字が得られるためです。 これにより、サブシーケンスを構築しなくても位置のチェックだけで十分であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    s = input().strip()

    ok = False
    for i in range(n):
        if s[i] == '8' and n - i >= 11:
            ok = True
            break

    print("YES" if ok else "NO")
```このソリューションは各テスト ケースを反復し、数字が含まれるすべての位置をチェックします。`8`。 重要な実装詳細は条件です。`n - i >= 11`、これにより、現在を選択できることが保証されます`8`少なくとも 10 文字以上の次の文字を追加します。 早期終了により、有効な位置が見つかった後の不必要なスキャンが防止されます。 

よくある間違いは、選択したサブシーケンスが順序を保持する必要があるため、グローバルなカウントではなく、サフィックスの可用性のみが重要であることを忘れることです。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        s = input().strip()

        ok = False
        for i in range(n):
            if s[i] == '8' and n - i >= 11:
                ok = True
                break
        out.append("YES" if ok else "NO")

    return "\n".join(out)

# provided samples

assert run("1\n20\n12345678901234567890\n") == "NO"

 ## 特殊なケース

 重要なエッジケースは、文字列に次のものが含まれる場合です。`8`, しかし、残り 10 文字を許可するには遅すぎるようです。 たとえば、`11111111118`、 唯一の`8`最後の位置にあります。 必要な数字は存在しますが、長さ 11 を完成させる文字が残っていないため、正解は次のようになります。`NO`。 アルゴリズムは、単に存在するかどうかだけでなく、接尾辞の長さを明示的にチェックすることによってこれを処理します。`8`。 

もう 1 つのエッジケースは、複数の場合です。`8`性差別主義者。 最初の有効な`8`成功を判断するには十分です。 スキャンはサフィックス条件を満たす最初の位置で停止するため、これは自然に処理されます。
