 ## 解決策
 ## 問題の理解

 4、8、15、16、23、42 という 6 つの固定数値の未知の順序が与えられています。各数値は長さ 6 の配列内に 1 回だけ出現しますが、その位置は隠されています。 配列について知る唯一の方法は、「位置 i と j の要素の積は何ですか」という形式のクエリを行うことです。 

タスクは、最大 4 つのクエリを使用して順列全体を復元し、配列を順番に出力することです。 

各クエリは、2 つの位置間の単一の乗算関係を明らかにします。 個別の値は 6 つだけであり、それらはすべて異なる方法で複合されているため、製品の構造は独自の情報を提供します。 課題は、すべての位置を曖昧さなく再構築できるクエリを選択することです。 

4 つのクエリのみが許可されるという制約が、主な構造上の制限です。 各位置を独立して識別しようとする単純な再構成には、最大 15 個のペアワイズ積が必要ですが、ここでは不可能です。 小さな固定された値のセットは、検索ではなく因子構造を利用する必要があることを示唆しています。 

微妙な障害モードは、クエリの再利用方法に注意しないと複数の順列が同じ積を生成する可能性があることを考慮せずに、積がその 2 つの要素を一意に識別すると仮定することから生じます。 たとえば、8 × 15 = 120 ですが、仮想緩和問題では 4 × 30 も 120 になります。 ここでは、候補値が固定され既知であるため、安全です。 

## アプローチ

 ブルートフォースアプローチでは、6 つの数値のすべての順列を試し、各順列について、それが要求したクエリと一致するかどうかをシミュレートします。 6つあるので！ = 720 の順列があり、各検証には最大 4 つの製品を比較する必要がありますが、これは計算上依然として実行可能です。 ただし、これは対話型の制約を無視しています。各クエリは高価で制限されているため、すべての順列をジャッジに対して適応的にテストすることはできません。 

重要な洞察は、任意のペアごとの比較が必要ないということです。 必要なのは、既知のアンカーに対する各位置を特定するのに十分な情報だけです。 固定セットの構造は非常に重要です。4、8、15、16、23、42 は、元の問題で使用された正しい順序で隣接する要素が特徴的な積を生成するように配置されています。さらに重要なことに、積が繰り返されることで、シーケンスを段階的に復元できるようになります。 

まず、要素自体との積、または既知の近傍との積が一意の因数分解をもたらす要素の位置を特定することによって、順列を再構築します。 1 つの価値を特定したら、製品を分割することで連鎖的に進めることができます。 

標準的な最適戦略では、(1,2)、(2,3)、(3,4) をクエリすることで最初の 4 つの要素を回復し、制約を交差させることで値を推定できるという事実を利用します。 最初の 4 つの数値を回復した後、残りの 2 つは未使用の値から一意に決定されます。

 ## アルゴリズムのチュートリアル

 中心となるアイデアは、連続する位置間の乗算の連鎖を回復することです。 

### ステップ

 1. 位置 (1, 2)、(2, 3)、(3, 4)、および (4, 5) の積をクエリします。 

各クエリは、2 つの隣接する未知の値の積を返します。 隣接するペアを選択する理由は、各中間要素が 2 つの製品に表示され、それを分離できるためです。 
2. これら 4 つの製品を p12、p23、p34、および p45 として保存します。 

これらはそれぞれ、2 つの既知の固定セット数の積です。 
3. 以下を観察して、位置 2、3、および 4 の候補値を計算します。 

位置 2 は p12 と p23 の両方を分割し、位置 3 は p23 と p34 の両方を分割し、位置 4 は p34 と p45 の両方を分割します。

この集合内ではすべての数値が固有の因子の重複を持つ個別の素数/積であるため、この交差プロパティにより一意の一致が強制されます。 
4. 位置 2、3、および 4 が特定されたら、除算によって位置 1 と 5 を直接計算します。 

a1 = p12 / a2、および a5 = p45 / a4。 
5. 固定セットの残りの未使用番号は、位置 6 に割り当てられます。 
6. 再構成された順列を出力します。 

### なぜ効果があるのか

 各中間位置は 2 つの乗算制約に関与します。 すべての数値は個別であり、セットは固定されているため、各積ペアは、有効な順列に一致する一貫した因子割り当てを 1 つだけ共有します。 これにより、それぞれの未知数が一意に解ける十分な制約内に現れる重複する方程式系が作成されます。 許可される数値の構造により、代替割り当てが 4 つの積すべてを同時に満たすことができないことが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def ask(i, j):
    print("?", i, j)
    sys.stdout.flush()
    return int(input().strip())

def solve():
    nums = [4, 8, 15, 16, 23, 42]
    
    p12 = ask(1, 2)
    p23 = ask(2, 3)
    p34 = ask(3, 4)
    p45 = ask(4, 5)

    # try all permutations for positions 1..5 consistent with constraints
    # small search is safe since only 6 values total and structure is fixed
    import itertools

    for perm in itertools.permutations(nums, 6):
        if perm[5] != perm[5]:
            pass
        # check constraints on first 5 positions only
        if perm[0] * perm[1] != p12:
            continue
        if perm[1] * perm[2] != p23:
            continue
        if perm[2] * perm[3] != p34:
            continue
        if perm[3] * perm[4] != p45:
            continue

        print("!", *perm)
        sys.stdout.flush()
        return

solve()
```この実装では、最小限の対話型戦略を使用します。つまり、連続する製品に対応する 4 つのクエリを正確に要求します。 これらの制約を収集した後、6 つすべてに対して総当たりチェックが実行されます。 順列。 これは概念的には強引なステップですが、ローカルで実行され、計算的には簡単です。 

実装の微妙な詳細は、ループが 4 つの制約すべてを順番に満たしていることを確認する必要があるということです。そうしないと、部分一致が誤って受け入れられる可能性があります。 乗算チェックは最初の 5 つの位置を完全に制限し、6 番目の位置は暗黙的に決定されます。 

インタラクターは応答する前に入力を待機するため、各クエリの後のフラッシュが必要です。 フラッシュを逃すと、間違った答えではなくデッドロックが発生します。 

## 実用的な例

 隠し配列が次のようになっていると仮定します。 

| 位置 | 1 | 2 | 3 | 4 | 5 | 6 |

 | 値 | 4 | 8 | 15 | 16 | 23 | 42 |

 クエリは以下を返します:

 | クエリ | 結果 |
 | --- | --- |
 | (1,2) | 32 |
 | (2,3) | 120 |
 | (3,4) | 240 |
 | (4,5) | 368 |

 アルゴリズムは順列をテストし、4 つの製品すべてに一致するものを見つけます。 制約チェーンは、隣接する各積が値の 1 つの有効な配置に正確に一致するため、正しい順序を一意に識別します。 

これにより、隣接制約が順列を完全に決定するのに十分であることが確認されます。 

### 2 番目の例

| クエリ | 結果 |

 | (1,2) | 966 |

 繰り返しになりますが、すべての制約を満たすのは 1 つの順列だけであり、対称性が実証されています。配列を反転しても、一貫した一意のソリューションが生成されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    nums = list(map(int, inp.strip().split()))
    a = nums

    # simulate interactive judge
    def ask(i, j):
        return a[i-1] * a[j-1]

    fixed = [4, 8, 15, 16, 23, 42]

    import itertools
    for perm in itertools.permutations(fixed):
        if (perm[0]*perm[1] == ask(1,2) and
            perm[1]*perm[2] == ask(2,3) and
            perm[2]*perm[3] == ask(3,4) and
            perm[3]*perm[4] == ask(4,5)):
            return " ".join(map(str, perm))
    return ""

# provided sample
assert run("4 8 15 16 23 42") == "4 8 15 16 23 42"

# reverse case
assert run("42 23 16 15 8 4") == "42 23 16 15 8 4"

# shuffled case
assert run("8 4 15 16 42 23") == "8 4 15 16 42 23"

 ## 特殊なケース

 重要なエッジケースは、順列が厳密に逆になる場合です。 隣接積の構造は依然として有効ですが逆転しており、「小さい値が先に現れる」などの位置の仮定に依存する解決策は失敗します。 アルゴリズムは、順序付けの仮定ではなく、乗算の一貫性のみをチェックするため、これを処理します。 

もう 1 つのエッジ ケースは、順列によって大きな値が小さな値の隣に配置され、他の有効なペアと数値的に重複する積が生成される場合です。 個々の製品ではなく完全な制約システムの一意性に依存しているため、あいまいさは 4 つの制約すべてが同時に適用された後にのみ除去されます。
