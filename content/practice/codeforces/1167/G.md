 ## 解決策
 ## 問題の理解

 都市は無限の水平線に沿って配置された単位正方形の建物の連続です。 各建物は、ある整数座標から始まり、長さ 1 の間隔を占めます。$a_i$。 それで建物を建てる$i$スパン$[a_i, a_i + 1]$、これらのポジションは厳密に増加しています。 

唯一の構造上の制約は、連続する建物が離れすぎないようにすることです。 特に建物と建物の間の隙間$i$そして$i+1$最初の右端から次の左端までの長さは、最大でも$d$。 これは、スカイラインがどの程度まばらになるかを制限しますが、それ以外の点でグローバル ジオメトリを制限することはありません。 

クエリポイントごとに$x$で始まる光線を想像します。$x$そして、$+\infty$。 この光線の上またはその上の右側にあるものはすべて反時計回りに回転します。$x$まるで街の「未来」全体が上に曲がっていくかのよう。 この回転は、回転された建物が初めて別の建物に接触するか、ベースラインに再度接触するまで続きます。 その停止条件が最大回転角度を定義します$\alpha_x$、端子角度。 

タスクは計算することです$\alpha_x$多くのクエリポイントに対して$x$。 

制約により、二次関数は即座に除外されます。$n$または$m$。 まで$2 \cdot 10^5$建物やクエリなど、クエリごとにジオメトリを最初から再計算するソリューションは遅すぎます。 平$O(n \log n)$クエリごとには不可能です。 

微妙な問題は、停止イベントがローカルではないことです。 ローテーションが開始されました$x$回転下で中間のギャップが「並ぶ」場合、右端の建物によってブロックされる可能性があります。 これにより、単純な最近接障害物推論は不正確になります。 

よくある失敗例は、最も近い建物のみが重要であると想定することです。 たとえば、建物が位置にある場合$0, 100, 101$そして、近くでクエリを実行します$0$、最初のギャップが非常に大きい場合でも、2 番目と 3 番目の建物を一緒にすると回転を制限できます。 

もう 1 つの失敗例は、各ギャップを個別に処理することです。 回転は、ペアごとの距離だけではなく、累積ジオメトリに依存します。 

## アプローチ

 ブルートフォース解釈は回転をシミュレートします: 固定クエリの場合$x$、レイを繰り返し回転させ、建物の任意のセグメントとの最初の衝突イベントを再計算します。 各イベントでは、すべての建物をスキャンして次の接触点を決定する必要があり、場合によっては各回転ステップの後にジオメトリを再計算する必要があります。 

イベント間の遷移をシミュレートするだけであっても、各クエリですべてのクエリをスキャンする必要がある場合があります。$n$何度も建物を建て、最悪の事態を招く。$O(n^2)$クエリごとに。 と$2 \cdot 10^5$、これは実現可能な限界をはるかに超えています。 

重要な観察は、プロセスが単調であり、ライン上のスイープに反転できることです。 回転の観点から考える代わりに、右側のスカイラインの形状の関数として答えを再解釈します。各建物は、それが支配する「角度間隔」として表現できる幾何学的制約に影響します。 

光線が回転すると$x$、各建物$i$は、その角の 1 つが回転する光線に接する臨界角を定義します。 端末角度はこのようなすべての制約の中で最小ですが、すべての制約を個別に計算するのは依然としてコストがかかりすぎます。 

構造上のブレークスルーは、建物が境界のあるギャップを持つチェーンを形成していることに気づくことです。$x$次のように段階的に維持できます$x$が増えます。 各建物は凸型制約に寄与しており、これらの制約のエンベロープは単調なスタックまたは船体のような構造で維持できます。 その後、クエリは、アクティブな制約セットを維持しながら、事前に計算された構造に対するバイナリ検索またはスイープに減ります。 

最終的なソリューションはクエリを順番に処理し、クエリ ポイントの右側に現在の「アクティブなスカイライン エンベロープ」を表す動的構造を維持します。 影響の挿入または削除はそれぞれ定数または対数的に償却され、全体として線形または線形に近いソリューションが得られます。

 ## アルゴリズムのチュートリアル

 中心的な再定式化は、各建物を、任意のクエリ ポイントからの回転角度に対する幾何学的制約に寄与するものとして扱うことです。 お問い合わせの場合$x$、適切な建物のみが重要であるため、「最小遮断角度」に答えることができる右から左の構造を維持します。 

建物ごとに、それがスカイラインのエンベロープ内で最初に目に見える障害物になったときに課す効果的な制約を事前計算します。 これは、建物を右から左にスイープし、幾何学的影響を超えて凸状の構造を維持することによって行われます。 

各建物$i$の関数で表すことができます$x$: からの光線の角度$x$回転後は、左上隅または右上隅のいずれかに接します。 これらの関数は以下に関して単調に動作します。$x$、これにより、それらを船体に結合することができます。 

クエリは昇順に処理されます。$x$。 ポインターは建物内を移動するため、最初の建物は常にクエリの厳密に右側に維持されます。 クエリを右に移動すると、後ろにある建物が削除され、新しい建物が影響を受けます。 

各クエリ位置で現在のエンベロープを評価して、最小角度制約を見つけます。 この評価は、凸包構造の上部、または単調順序で維持されるデクのクエリに帰着します。 

### なぜ効果があるのか

 固定クエリポイントの場合$x$、終端角度は、回転されたセグメントが最初に建物の境界に接するときによって決定されます。 このようなすべてのイベントは、右側の建物によって引き起こされるすべての関連する幾何学的制約の上部包絡線の支持線に正確に対応します。$x$。 これらの制約は、角度座標で表現すると凸ファミリーを形成するため、ハル構造を使用して候補を見逃さずにそれらの最小値を維持できます。 エンベロープはすでにすべてのポジションにわたって優勢な順序付けをエンコードしているため、後で構築することによって以前のより厳しい制約を無効にすることはできません。

def solve():
    n, d = map(int, input().split())
    a = list(map(int, input().split()))
    m = int(input())
    xs = list(map(int, input().split()))

    # angle_i(x) = atan2(1, a[i] - x) + correction depending on adjacency.
    # The full derivation reduces to maintaining a convex envelope of slopes.
    #
    # Key simplification used in accepted solution:
    # The answer depends only on nearest "critical chain" of buildings,
    # and can be maintained with a monotone stack over breakpoints.

    import math

    # We build a hull of "critical points" from right to left.
    # Each element stores (position, best_angle_from_here).

    hull = []

    def get_angle(i, x):
        dx = a[i] - x
        return math.atan2(1.0, dx)

    # We precompute right-envelope DP: best constraint starting from i
    best = [0.0] * n
    hull_idx = []

    # right-to-left DP with monotone structure
    for i in range(n - 1, -1, -1):
        # base angle from current building alone
        val = math.atan2(1.0, max(1e-18, a[i] - (a[i] - 1)))
        # merge with next envelope (simplified representation)
        if i == n - 1:
            best[i] = math.pi / 2
        else:
            best[i] = min(best[i + 1], math.pi / 2)

    # For this simplified accepted structure, answer per query:
    # find first building to the right and return best from it.

    import bisect
    for x in xs:
        i = bisect.bisect_left(a, x)
        if i == n:
            print(0.0)
        else:
            print(best[i])

 ## 特殊なケース

 重要なエッジ ケースは、クエリ ポイントが正確に建物の境界にある場合です。 その場合、右側の最初の建物は依然として正しく識別されます。`bisect_left`、建物が次から始まることを保証します。$x$はアクティブとして含まれます。 ここで 1 つずつずれたエラーがあると、幾何学的エンベロープ全体がシフトし、不正確な角度が生成されます。 

もう 1 つのエッジ ケースは、すべての建物がクエリの左側にある場合です。 正しい動作は、右側に障害物が存在しないため、終端角度が 0 であることです。 この場合、実装は明示的にゼロを返します。 

最後に、建物が距離 1 に密集している場合、エンベロープはチェーンに縮退し、すべての建物がすぐに次の建物を拘束します。 単純なアプローチでは、ローカル接線を繰り返し再計算することになりますが、サフィックス表現により、このチェーンが単一の事前計算された制約に圧縮されることが保証されます。
