 ## 解決策
 ## 問題の理解

 整数の配列が与えられます`a`すべての要素がその間にある場所`0`そして`k`。 許可される操作は、2 つの異なるインデックスを選択することです`i`そして`j`そのような`a[i] + a[j] = k`、値を再配布します`x`から`a[i]`に`a[j]`(またはその逆)、両方の要素が`[0, k]`範囲。 目標は、最大でも次の値を使用して配列を非減少シーケンスに変換することです。`3n`テストケースごとの操作。 

重要な制約は次のとおりです。`n`まで可能です`2*10^5`そしてすべての合計`n`テストケース全体でも、`2*10^5`。 これにより、考えられる操作のすべてのペアを単純にシミュレートしようとするアルゴリズムは除外されます。`O(n^2)`テストケースごとに。 代わりに、テスト ケースごとに線形または線形演算のアプローチが必要です。 

重要な観察は、演算は合計が次の数値の間でのみ発生するということです。`k`。 配列に値が含まれている場合`v`対応するものなしで`k - v`それ以外の場所では、その値は「固定」されており、調整できません。 たとえば、次の場合`k = 7`そして配列には以下が含まれます`[7, 1, 2]`、`2`何かと組み合わせることができないため、特定の再配置が不可能になる場合があります。 範囲内の要素を含む配列`[0, k]`しかし、適切な補完がなければ、非減少的に並べ替えることは不可能である可能性があります。 もう 1 つのエッジ ケースは、既に非減少配列であり、即座に演算がゼロになるはずです。 

## アプローチ

 ブルートフォース手法では、すべてのペアを反復処理します。`(i, j)`どこ`a[i] + a[j] = k`そして可能な限りすべてを試してください`x`値を調整して配列を徐々に調整します。 どの操作でも合計が保持されるため、これは機能します。`a[i] + a[j]`、しかし明らかに遅すぎます。 のために`n = 2*10^5`、可能なペアの数はおおよそ次のとおりです。`O(n^2)`最悪の場合は制限時間を超えてしまいます。 

最適なアプローチは構造的な洞察に依存します。 任意の数`v`とのみ対話できます`k - v`。 したがって、問題は次のように再構成できます。配列を数値の「バケツ」に分割します。`v`そして`k - v`。 バケットのすべての要素が希望の順序で表示されるまで、2 つのバケット ペア間で値を繰り返し転送できるため、各バケット ペアを任意の分布に個別に調整できます。 これを使用すると、配列を左から右に処理し、出現するすべての要素を移動できます。`v`バケットの間隔の左側にあるバケット内とすべて`k - v`右の方へ。 これにより、すべてのバケットが内部的に非減少であることが保証され、グローバルな非減少順序に寄与します。 各バケットには最大でも`n`要素と各要素は最大でも一定の回数だけ移動され、操作の総数は次の制限を受けます。`3n`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、配列が既に非減少であるかどうかを確認します。 存在する場合は出力します`0`操作を続けて続行します。 
2. 他の要素と組み合わせて合計できる要素をすべて特定します。`k`。 それぞれの位置を追跡する地図またはリストを作成します。`v`とその補足`k - v`。 存在する場合`v`補足なしで、テストケースを不可能としてマークし、出力します`-1`。 
3. 各補数ペアについて`(v, k - v)`、ピボットインデックスを決定します`p`どこ`v`s は左に移動され、`(k - v)`右にあります。 配列を左から右に走査します。 毎回、`v`の右側に表示されます`p`、左に移動する操作を生成します。 毎回、`(k - v)`の左側に表示されます`p`、右に移動する操作を生成します。 選ぶ`x`数値を保持する最大許容シフトとして`[0, k]`。 
4. すべてのバケット ペアを処理した後、配列は減少しないはずです。 生成されたすべてのオペレーションを収集します。 それらの数が次を超えないようにしてください`3n`。 操作自体の後に続く操作の数を出力します。 
5. いずれかの時点で、非減少条件を満たすように移動できない要素を検出した場合は、直ちにテスト ケースを不可能としてマークします。 

機能する理由: 不変条件は、すべての操作が保存されることです。`a[i] + a[j] = k`要素を内部に保持します`[0, k]`。 各補数ペアを個別に処理し、すべてを移動することにより、`v`片側にそして`k - v`相互に、各バケットは内部的には非減少になります。 すべてのバケットの合計は配列の順序に従うため、グローバル配列は減少しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        if all(a[i] <= a[i+1] for i in range(n-1)):
            print(0)
            continue

        from collections import defaultdict, deque

        pos = defaultdict(deque)
        for i, v in enumerate(a):
            pos[v].append(i)

        impossible = False
        ops = []

        for i in range(n):
            v = a[i]
            comp = k - v
            if v not in pos or comp not in pos:
                impossible = True
                break

        if impossible:
            print(-1)
            continue

        left, right = 0, n-1
        while left < right:
            if a[left] > a[right]:
                x = min(a[left], k - a[right])
                a[left] -= x
                a[right] += x
                ops.append((left+1, right+1, x))
            if a[left] <= a[right]:
                left += 1
            else:
                right -= 1

        print(len(ops))
        for i, j, x in ops:
            print(i, j, x)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず配列がすでにソートされているかどうかを確認します。 次に、すべての要素に補数があることが保証されます。 2 ポインターのアプローチでは、ペアを端から内側に処理し、有効な演算を生成し、配列の不変条件を維持します。 操作は保存および出力され、可能であれば配列が非降順に変換されることが保証されます。

### サンプル 2

 入力:`5 7\n7 1 5 3 1`合計するインデックスのペアはありません`7`いくつかの要素については。 アルゴリズムはそれを検出します`5`補数がありません`2`そして出力`-1`。 

これは、不可能なケースを正しく処理する方法を示しています。
