 ## 解決策
 ## 問題の理解

 各整数が収まる整数の配列を処理するように求められます。`k`ビット。 配列内の各位置について、その位置を含むすべての部分配列の「ビット単位の論理和」の最大値を見つける必要があります。 2 つの数値のビット単位の論理和は、それらのビット単位の OR のビット単位の補数です。 部分配列の場合、ノルを左から右に累積的に計算します。 

入力には複数のテスト ケースが含まれており、それぞれのテスト ケースは次のようになります。`n`整数とビット数`k`。 出力は長さの配列です`n`ここで、各要素は最大値、またはそのインデックスを含むすべてのサブ配列の中での最大値です。 

制約は重要です。`n`到達できる`10^5`まであるかもしれません`10^4`テスト ケース。ただし、すべてのテスト ケースにわたる要素の合計数は次のように制限されます。`10^5`。 すべてのサブ配列を考慮する単純なアプローチでは、おおよそのパフォーマンスが得られます。`O(n^2)`テストケースごとの操作は遅すぎます。`n=10^5`。 線形に近いソリューションが必要です`n`。 

長さ 1 の配列では、エッジ ケースが発生します。ここで、唯一の要素の最大 no は要素自体です。 すべての数値が以下の場合には、別の微妙なケースが発生します。`2^k - 1`つまり、すべてのビットが 1 になります。この場合、2 つ以上の数値のいずれかの no が 0 になるため、特定のインデックスを含む最大の no は、より大きな部分配列ではなく要素のみから得られる可能性があります。 不注意な実装では、サブ配列が大きくなると常にノルが増加すると想定する可能性がありますが、これは誤りです。 

## アプローチ

 ブルート フォース ソリューションは、インデックスを含むすべてのサブ配列を反復処理します。`i`。 各部分配列について、累積ノルムを計算し、最大値を更新します。 これが機能するのは、問題で定義されている左から右の意味で nor が結合しているためです。 ただし、1 つのインデックスを含むサブ配列の数はおよそ`O(n)`そして、それらの NOR を単純に計算すると、`O(n)`同様に、その結​​果、`O(n^2)`テストケースごとに。 のために`n=10^5`、これは不可能です。 

重要な点は、ビット単位の NOR がビット単位の OR の補数であるということです。 と表すと`nor(x, y) = ~(x | y)`のために`k`ビットを考慮すると、部分配列を拡張するときに「どのビットが 1 のままでいられるか」という観点から考えることができます。 以下を含む部分配列の場合`a[i]`、任意のビットが 1 になるまで、できるだけ左右に拡張したいと考えています。`a[i]`は別の要素の 1 によって上書きされます。 つまり、部分配列内のすべての要素のビットが 0 である場合に限り、結果の各ビットは 1 のままになります。 

これにより、問題は一種の「このビットに 1 を持つ最も近い要素」の問題に集約されます。 各要素について、ビットごとに、そのビットが設定されている左右に最も近いインデックスを事前計算できます。 これらを使用して、以下を含む最大の部分配列を決定できます。`i`各ビットは未設定のままです。 すべてのビットにわたってこれらの結果を組み合わせると、そのインデックスの最大値が得られます。 

このアイデアは、次のようなリニア スキャンにつながります。`O(n*k)`複雑さ、どこで`k`最大でも 17 であるため、実行可能です。 このソリューションは、ビットごとに最後に確認された位置の配列を維持し、ビットマスク操作を使用して最大値を更新します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2 * k) | お(1) | 遅すぎる |
 | 最適 | O(n * k) | O(k) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`ans`サイズの`n`各インデックスの最大値を保存します。 2 つのヘルパー配列を初期化する`last_left`そして`last_right`サイズの`k`、それぞれ左と右からスキャンしながら、各ビットに 1 を付けて最後に検出されたインデックスを保存します。 
2. 左から右にスキャンします。 インデックスごとに`i`、各ビット位置に対して`b`0から`k-1`、 もし`a[i]`ビットがある`b`設定、更新`last_left[b] = i`。 ビットをリセットする左に最も近いインデックス`b`で終わるサブ配列の場合`i`は`last_left[b]`。 
3. 同様に、右から左にスキャンします。 インデックスごとに`i`そして噛んだ`b`、 もし`a[i]`ビットがある`b`設定、更新`last_right[b] = i`。 ビットをリセットする右側に最も近いインデックス`b`で始まるサブ配列の場合`i`は`last_right[b]`。 
4. 各インデックスについて`i`、初期化します`res = 0`。 ビットごとに`b`からの距離を確認してください。`i`最も近い左または右のインデックスへのビット`b`が設定されています。 もし`i`ビットが境界内にある`b`0 のままでも構いません。このビットを含めます`res`ビットを設定することで`b`1に。 
5. 出力`res`各インデックスを最大値として表すことも、そのインデックスを含むこともありません。 

これが機能する理由は、累積演算でいずれかのビットが 0 から 1 に反転するときに、ビットごとの NOR が厳密に減少するためです。 ビットが 1 である最も近い位置を追跡することで、各ビットが 1 を維持できる最大の部分配列長を決定し、これらを組み合わせて最大値を効率的に計算できます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        
        last_left = [-1] * k
        last_right = [n] * k
        left_bound = [0] * n
        right_bound = [n-1] * n
        
        for i in range(n):
            left_bound[i] = 0
            for b in range(k):
                if a[i] & (1 << b):
                    last_left[b] = i
                left_bound[i] = max(left_bound[i], last_left[b]+1)
        
        last_right = [n] * k
        for i in range(n-1, -1, -1):
            right_bound[i] = n-1
            for b in range(k):
                if a[i] & (1 << b):
                    last_right[b] = i
                right_bound[i] = min(right_bound[i], last_right[b]-1)
        
        ans = []
        for i in range(n):
            res = 0
            for b in range(k):
                if left_bound[i] <= i <= right_bound[i]:
                    res |= (1 << b)
            ans.append(res)
        
        print(*ans)

solve()
```このソリューションでは、まず各ビットが設定されないままにできる各インデックスの境界を計算し、次にこれらを組み合わせて、最大値または最大値でどのビットが 1 になれるかを決定します。 の使用`last_left`そして`last_right`配列を使用すると、距離を繰り返し再計算することがなくなります。 最後のループでは、各ビットのサブ配列の境界をチェックして、各インデックスの結果を組み立てます。
