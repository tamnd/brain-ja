 ## 解決策
 ## 問題の理解

 配列が与えられ、中央値を含む特定の条件がすべてのカットにわたって保持されるように、配列を 3 つの連続する部分にカットできるかどうかを尋ねられます。 

2 つの分割点を選択すると、配列は 3 つの空ではないセグメントに分割されます。 各セグメントには独自の中央値があり、そのセグメントが並べ替えられるときに中央の要素として定義されます。 次に、これら 3 つの中央値を取得し、それらの中央値を再度計算します。 問題は、この最終値が最大でも`k`。 

この条件を言い換えると便利な方法は、3 つのセグメントの中央値のうち、少なくとも 2 つが以下である必要があるということです。`k`。 これは、3 つの値の中央値の定義から来ています: ≤`k`3 つの値のうち少なくとも 2 つが ≤ の場合`k`。 

制約は大きいです:`n`すべてのテスト ケースにわたって 2⋅10^5 に達するため、テスト ケースごとに O(n²) アプローチを使用することは不可能です。 すべてのペアに対して単純に実行すると、分割候補ごとに O(n log n) であっても遅すぎます。`(l, r)`。 

重要な問題は、部分配列の中央値が単純な接頭辞統計ではないことです。 これはセグメント内の順序に依存するため、セグメントごとの直接の再計算はコストが高すぎることがわかります。 

いくつかの微妙な特殊なケースを強調する価値があります。 

すべての要素が ≤ の場合`k`、すべての部分配列の中央値は自動的に ≤ になります。`k`、したがって、答えは自明にYESです。 単調性を考慮せずに中央値を誤って再計算する素朴な解決策はまだ機能する可能性がありますが、バグのある貪欲な解決策はこの早期終了を検出できない可能性があります。 

ちょうど 1 つのセグメントが中央値 ≤ である場合`k`、3 つの値の中央値が ≤ になることはできないため、答えは NO でなければなりません。`k`少なくとも 2 つが ≤ でない限り`k`。 

もう 1 つの注意が必要な状況は、大きな値が散在する場合です。現在のプレフィックス数のみに基づいてセグメントを貪欲に拡張しようとする貪欲な試みは失敗する可能性があります。これは、中央値が単独のカウントだけではなく、各セグメント内の相対的な順序に依存するためです。 

## アプローチ

 ブルートフォース戦略ではすべてのペアを列挙します`(l, r)`各セグメントを並べ替えるか、選択構造を使用して、3 つのセグメントのそれぞれの中央値を計算します。 各分割について、中央値の状態を確認します。 

これは正しいですが、遅すぎます。 O(n²) 個の分割があり、中央値の計算はセグメントごとに少なくとも O(n) または O(log n) となり、全体では O(n³) または O(n² log n) になります。これは 2⋅10^5 要素では実行不可能です。 

重要な洞察は、問題を「中央値の中央値」から二項分類問題に変換することです。 各セグメントの中央値が ≤ であるかどうかのみを気にします。`k`、正確な値ではありません。 

セグメントの中央値は ≤`k`要素の少なくとも半分が ≤ の場合`k`。 したがって、配列を、各要素が次のようになる変換された形式にマップできます。 

+1 の場合`a[i] ≤ k`、それ以外の場合は -1。 

セグメントの中央値が ≤ になりました`k`その合計が正の場合に限ります。 これにより、中央値条件がプレフィックス合計条件に縮小されます。 

ここで問題は、この変換された配列内で 3 つのセグメントのうち少なくとも 2 つが正の合計を持つように、配列を 3 つの連続するセグメントに分割できるかということです。 

これは現在、プレフィックスの合計に関する構造上の問題です。 プレフィックスの合計を事前計算し、線形スキャンと可能な限り最良のセグメント符号の貪欲な追跡を使用して、有効な分割点を効率的に見つけることができるかどうかを追跡できます。 

最終的な解決策は、結果として得られる 3 つのセグメントのうち少なくとも 2 つが正の合計を持つように 2 つのカット ポイントを配置できるかどうかを確認することになります。

 ## アルゴリズムのチュートリアル

 1. 配列をバイナリ形式に変換します。次の場合、各要素は +1 になります。`a[i] ≤ k`、それ以外の場合は -1。 これにより、中央値条件が合計条件に再定式化されます。 
2. この変換されたシーケンスに対してプレフィックス合計配列を構築します。 位置 i の接頭辞の合計は、接頭辞内に「悪い」要素よりも「良い」要素 (<k) がいくつ多く存在するかを表します。 
3. セグメントが`[l, r]`ちょうど次の場合に中央値 ≤ k になります`prefix[r] - prefix[l-1] > 0`。 これにより、セグメントの有効性を定期的にチェックすることができます。 
4. 次に 2 つのカットポイントが必要です`l < r`3 つのセグメントのうち、少なくとも 2 つのセグメントが正の合計を持つようにします。 これは、1 番目と 2 番目のセグメントが良好、1 番目と 3 番目のセグメントが良好、2 番目と 3 番目のセグメントが良好という 3 つのパターンに分かれます。 
5. 最初と 2 番目のケースでは、`l`ここで、prefix[1..l] は適切なセグメントを形成できるため、存在するかどうかを確認します。`r > l`両方とも`[l+1, r]`そして`[r+1, n]`プレフィックスminima/maximaを使用して条件を満たすように調整できます。 
6. パターンごとに、セグメントの合計を明示的に再計算することを避けるために、スキャン中に実行情報を維持します。 これにより、各位置が 1 回処理されることが保証されます。 

### なぜ効果があるのか

 この変換により、中央値制約がプレフィックス合計に関する線形不等式に縮小されます。 プレフィックス空間ではセグメントの有効性が単調になるため、実現可能性は加法的制約を満たすカットポイントの存在のみに依存します。 グリーディ スキャンが機能するのは、有効なプレフィックスまたはセグメント エンドポイントが見つかると、境界を拡張または移動すると、プレフィックス合計空間の実現可能性条件が維持または緩和されるだけであるため、最適な設定がスキップされないためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))
    
    b = [1 if x <= k else -1 for x in a]
    
    pref = [0] * (n + 1)
    for i in range(n):
        pref[i + 1] = pref[i] + b[i]
    
    total = pref[n]
    
    # case 1: first two segments are good
    # check if exists l, r such that:
    # sum(1..l) > 0 and sum(l+1..r) > 0
    
    ok_prefix = [False] * (n + 1)
    cur_min = 0
    for i in range(1, n + 1):
        if pref[i] - cur_min > 0:
            ok_prefix[i] = True
        cur_min = min(cur_min, pref[i])
    
    # case 2: last two segments are good
    ok_suffix = [False] * (n + 2)
    cur_max = pref[n]
    for i in range(n - 1, -1, -1):
        if cur_max - pref[i] > 0:
            ok_suffix[i] = True
        cur_max = max(cur_max, pref[i])
    
    # check any split pattern
    # pattern A: first two segments good
    # pattern B: last two segments good
    # pattern C: first and last segments good
    
    # pattern A
    for r in range(2, n):
        if ok_prefix[r]:
            return True
    
    # pattern B
    for l in range(1, n - 1):
        if ok_suffix[l]:
            return True
    
    # pattern C
    # first and last segments good
    # need prefix[i] > 0 and suffix[j] > 0 with i < j
    best = -10**18
    for i in range(1, n):
        if pref[i] > 0:
            best = max(best, i)
    for j in range(2, n + 1):
        if pref[n] - pref[j - 1] > 0 and best != -10**18 and best < j - 1:
            return True
    
    return False

t = int(input())
for _ in range(t):
    print("YES" if solve() else "NO")
```解決策は、セグメントの中央値が合計に対する符号検定になるように、配列を +1 および -1 の表現に変換することから始まります。 プレフィックス合計により、任意のセグメントを一定時間で評価できるようになります。 

次に、どのプレフィックスとサフィックスが有効な正和セグメントを形成できるかを事前計算します。 これらの配列は、すべてのサブ配列を再チェックすることなく、ある位置で終了または開始する有効なセグメントが存在するかどうかをエンコードします。 

最後に、必要な 3 つのセグメントの中から 2 つの「適切な」セグメントを選択する 3 つの可能な方法をテストします。 各チェックでは、プレフィックス情報に対して線形スキャンが使用されます。 

実装の主な微妙な点は、明示的に中央値を計算したり部分配列を並べ替えたりしないことです。 すべての推論はプレフィックス合計空間で行われ、すべてのセグメント条件は O(1) チェックに削減されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    def solve():
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        b = [1 if x <= k else -1 for x in a]
        pref = [0]
        for x in b:
            pref.append(pref[-1] + x)

        def good(l, r):
            return pref[r] - pref[l - 1] > 0

        for l in range(1, n - 1):
            for r in range(l + 1, n):
                cnt = 0
                if good(1, l): cnt += 1
                if good(l + 1, r): cnt += 1
                if good(r + 1, n): cnt += 1
                if cnt >= 2:
                    return True
        return False

    t = int(input())
    out = []
    for _ in range(t):
        out.append("YES" if solve() else "NO")
    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、ほとんどすべての要素が次の値よりも大きい場合です。`k`いくつかの孤立した小さな値を除いて。 このような場合、非常に短いセグメントのみが「良好」である可能性があり、アルゴリズムはプレフィックス最小値に依存して、正のセグメントが存在するかどうかを正確に検出します。 

もう 1 つのケースは、すべての要素が ≤ の場合です。`k`。 プレフィックスの合計は常に増加するため、すべてのセグメントが有効になります。 アルゴリズムは、最初のパターン チェックで有効な分割ポイントを即座に見つけます。 

最後の微妙なケースは、最後のセグメントのみを良好にできる場合です。 サフィックスの事前計算により、初期のプレフィックスが失敗した場合でも、逆プレフィックス スキャンを通じて有効なサフィックス ベースの設定が検出されることが保証されます。
