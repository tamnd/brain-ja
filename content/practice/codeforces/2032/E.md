 ## 解決策
 ## 問題の理解

 奇数長の円形配列が与えられています$n$、各要素は整数です。 任意のインデックスに対して操作を実行できます$i$これは要素を増加させます$i$目標は、すべての要素が等しくなるように配列を変換することです。 配列は円形であるため、最初の要素の前に隣接する要素が最後の要素となり、最後の要素の後に隣接する要素が最初の要素になります。 

入力には複数のテスト ケースが含まれています。 それぞれの場合において、配列のバランスをとるインデックスごとの操作カウントのシーケンスを生成するか、それが不可能であると判断する必要があります。 

以来$n$まで到達できます$2 \cdot 10^5$テストケースごとの合計と$n$すべてのテスト ケースにわたって次の制限も受けられます。$2 \cdot 10^5$、以上のソリューション$O(n)$テストケースごとに実行すると遅すぎます。 線形時間アプローチが必要です。 配列内の値は最大です。$10^6$、操作の数は非常に多くなる可能性があり、最大で$10^{18}$これは、整数のオーバーフローを回避する必要があることを意味します。 

重要なエッジ ケースは、配列の長さが 1 である場合に発生します。単一要素の配列は自明のバランスをとるため、演算はゼロで十分です。 もう 1 つの明白ではないケースは、配列にすべて等しい値がすでに含まれている場合に発生します。 ソリューションは、すべてのインデックスに対してゼロの操作を返す必要があります。 必要な演算をすべて整数にできないなど値が異なる場合は、これも微妙な点ですが、奇数長であるため、整数要素を含む配列に対して解が存在することが保証されます。 

## アプローチ

 ブルートフォースアプローチは、操作を貪欲にシミュレートすることです。 要素が最大値を下回るインデックスを繰り返し選択し、配列のバランスがとれるまで演算を適用することができます。 この方法は、各操作で 3 つの要素が厳密に増加するため、原則的には正しいですが、必要な場合があります。$O(n \cdot \text{max}(a_i))$ステップ。 と$a_i$まで$10^6$そして$n$まで$2 \cdot 10^5$、これでは非常に遅くなります。 

重要な洞察は、この操作が固定パターンを持つ 3 つの連続する要素に影響を及ぼし、配列の長さが奇数であるということです。 これにより、2 を法とする連立一次方程式が形成されます。$n$、系は常に非負の整数で解くことができます。 より具体的には、2 番目の要素ごとに処理する貪欲なアルゴリズムを定義できます。 インデックス 0 から開始して、適用する操作の数を計算します。$a_0$ターゲット値 (配列内の最大要素) に達します。 次に、その効果を次の要素に伝播し、その要素によって次のインデックスに適用する操作が決定されます。 なぜなら$n$が奇数である場合、この伝播は一貫して元に戻り、解決策が保証されます。 

これにより、潜在的に指数関数的なプロセスが次のようなプロセスに変換されます。$O(n)$テストケースごとの計算。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n * max(a_i)) | O(n) | 遅すぎる |
 | 貪欲な伝播 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る$t$。 テスト ケースごとに、次の内容を読んでください。$n$そして配列$a$。 
2. もし$n = 1$、単一要素配列はすでにバランスが取れているため、出力 0 の演算が行われます。 
3. 配列を初期化する$ops$サイズの$n$ゼロ付き。 これにより、各インデックスに適用された操作の数が保存されます。 
4. インデックス 1 から開始して、配列を 2 のステップで繰り返します (0 ベースのインデックス付けを考慮)。 インデックスごとに$i$、現在の要素の差を計算します。$a[i]$そして前の要素$a[i-1]$以前のすべての操作が適用された後。 この違いにより、インデックスで必要な操作の数が決まります。$i$バランスを取る$a[i-1]$。 
5.アップデート$ops[i]$この違いによって。 これらの操作の効果を、現在の要素、その前の隣接要素、およびその次の隣接要素に適用します。 
6. 伝播が開始インデックスに戻るまで繰り返します。 なぜなら$n$奇数である場合、システムは競合せずに正しく終了します。 
7. 配列を出力する$ops$。 

機能する理由: 各操作では、固定比率で 3 つの連続する要素が増加します。 2 番目の要素ごとに操作を伝播すると、先に進む前に前の要素のバランスが保たれます。 奇数の長さにより、矛盾を引き起こすサイクルがないことが保証され、常に整数演算を見つけることができます。 演算の最後の配列は、演算を適用した後、すべての要素が等しいことを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        if n == 1:
            print(0)
            continue
        
        ops = [0] * n
        target = max(a)
        # propagate from index 0 in steps of 2
        for i in range(1, n, 2):
            prev = (i - 1) % n
            diff = target - a[prev]
            ops[i] = diff
            a[prev] += diff
            a[i] += 2 * diff
            a[(i + 1) % n] += diff
        print(' '.join(map(str, ops)))

if __name__ == "__main__":
    solve()
```コードは操作カウントをゼロに初期化し、2 番目の要素ごとに必要な操作を伝播します。 モジュロ演算により循環インデックスが保証されます。 このアプローチは、説明した貪欲な伝播戦略を直接実装します。 使用する`max(a)`ターゲットは負でない操作数を保証するためです。 

## 実用的な例

 **例 1:**

 入力配列:`[2, 1, 2]`| インデックス | a[i] | オプス[i] | メモ |
 | --- | --- | --- | --- |
 | 0 | 2 | 0 | 開始値 |
 | 1 | 1 | 1 | 前の要素 2 を最大 2 にします |
 | 2 | 2 | 0 | すでにバランスが取れています |

 出力：`0 1 0`説明: インデックス 1 で 1 つの操作を適用すると、要素が増加します。`[0,1,2]`による`[1,2,1]`その結果`[3,3,3]`。 

**例 2:**

 入力配列:`[1, 2, 3, 4, 5]`2 のステップで伝播します。 

| インデックス | a[i] | オプス[i] | 隣人を更新しました |
 | --- | --- | --- | --- |
 | 1 | 2 | 4 | a[0]+=4、a[1]+=8、a[2]+=4 |
 | 3 | 4 | 1 | a[2]+=1、a[3]+=2、a[4]+=1 |

 出力：`0 4 0 1 0`この表は、操作がどのように伝播するか、および近隣ノードがどのように更新されるかを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | 各インデックスは 1 回アクセスされ、更新には一定の時間がかかります。 
| スペース | O(n) | 長さ n の配列 a と ops が格納されます。 

制約を考慮すると$\sum n \le 2 \cdot 10^5$、この解決策は 2 秒の制限時間内に問題なく収まります。
