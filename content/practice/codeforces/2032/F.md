 ## 解決策
 ## 問題の理解

 一連のポケットが与えられ、それぞれのポケットには正の数のピーナッツが含まれています。 アリスはシーケンスを連続したポケットのボックスに分割できます。 ボックスが固定されたら、アリスとジャックは順番にゲームを行います。プレイヤーは自分の順番で、左端の空でないボックスのちょうど 1 つのポケットから正の数のピーナッツを取り出さなければなりません。 行動できなかったプレイヤーが負けとなります。 この問題は、両方が最適にプレイされた場合にアリスが確実に勝つために、アリスがポケットをボックスに分割できる方法が何通りあるかを尋ねます。 

入力は複数のテスト ケースを提供し、それぞれにポケットの数と各ポケット内のピーナッツの数が含まれます。 出力は、各テスト ケースの勝った分割数のモジュロです。$998\,244\,353$。 合計から$n$すべてのテストケースにわたって、$10^6$、効果的に線形となるソリューションを設計する必要があります。$n$テストケースごとに。 考えられるすべてのパーティションを明示的に列挙しようとする単純なアプローチでは、指数関数的な結果が得られます。$n$したがって実行不可能です。 

微妙な点は、このゲームが古典的な組み合わせゲーム Nim の変形ですが、ボックス間での連続制限があることです。 いずれかの部門が勝っていると素朴に仮定すると、左端のボックスが空になるまでプレイを支配し、事実上、独立したサブゲームの階層が作成されるため、不正確なカウントが発生します。 

エッジ ケースには、すべてのポケットに同じ数のピーナッツがあるシーケンス、長さが 1 または 2 のシーケンス、および厳密に増加する数のシーケンスが含まれます。 長さが 1 または 2 の場合、ジャックのターンで合計ピーナッツがわずかになくなった場合、アリスは勝つことができません。 均一なシーケンスには多くの有効なパーティションを含めることができ、シーケンスを増やすと、多くの場合、固有の最適なパーティションが生成されます。 

## アプローチ

 強引な解決策では、ポケットを箱に分割するすべての可能性を試し、ゲームをシミュレートして、アリスが勝つかどうかを決定します。 のために$n$ポケット、あります$2^{n-1}$分裂の可能性があり、それは手に負えない$n$まで$10^6$。 サブセットにわたるメモ化でも、連続した左端の制限と高いため不十分です。$n$。 

重要な観察は、ボックス上のゲームがシーケンシャル Nim のように動作することです。つまり、ボックスのグランディ番号の XOR によって勝者が決まります。 箱のグランディ数は、その構成要素であるポケット内のピーナッツの XOR です。 アリスが先攻となるため、すべてのボックスの XOR がゼロ以外であればアリスが勝ちます。 彼女はボックスを選択するため、パーティションを配置して XOR のシーケンスを制御できます。 

逐次的な性質を考慮すると、接頭辞合計アプローチを使用すると、勝利条件を満たす累積 XOR を生成する除算の数を数えることができます。 左から右への累積 XOR を考慮すると、左と右の XOR が条件を満たす分割点が有効になります。 プレフィックス XOR を事前計算し、ハッシュ マップまたは辞書を使用して、各 XOR 値の出現を効率的にカウントできます。 これにより、テスト ケースごとの複雑さが指数関数的なものから線形的なものに軽減されます。

 ## アルゴリズムのチュートリアル

 1. 各テストケースについて、ポケットの数を読み取ります。$n$そして配列$a$各ポケットにはピーナッツが入っています。 プレフィックス XOR 配列を初期化します。 
2. プレフィックス XOR を計算します。`prefix[i]`は、0 から i までのポケット内のピーナッツの XOR です。 これにより、連続した部分配列の XOR を定数時間で評価できるようになります。 
3. 辞書（ハッシュマップ）の初期化`count`これまでに確認されたプレフィックス XOR の頻度を保存します。 変数も初期化します`result`勝利したパーティションの数を累積します。 
4. プレフィックス XOR 配列を反復処理します。 それぞれについて`prefix[i]`、前のボックスの累積 XOR に基づいて、アリスを勝利させるために必要な XOR を計算します。 アップデート`result`必要な XOR が出現した回数による`count`。 
5.アップデート`count`現在と`prefix[i]`将来の分割に含めるために。 
6. 配列を処理した後、出力します。`result`モジュロ$998\,244\,353$。 

不変条件は、辞書がこれまでに確認されたすべてのプレフィックス XOR を追跡することです。 潜在的な分割ごとに、その分割が勝利する XOR 構成につながるかどうかを一定時間で判断できます。 これにより、すべての有効なパーティションが欠落したり二重にカウントされたりすることなく確実にカウントされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        
        prefix = [0] * n
        prefix[0] = a[0]
        for i in range(1, n):
            prefix[i] = prefix[i-1] ^ a[i]
        
        count = {0:1}  # base case: empty prefix
        result = 0
        
        for val in prefix:
            # Alice wins if cumulative XOR up to this point matches a previous prefix
            result = (result + count.get(val, 0)) % MOD
            count[val] = count.get(val, 0) + 1
        
        print(result % MOD)

if __name__ == "__main__":
    solve()
```コードの各セクションはアルゴリズムに従っています。 

- プレフィックス XOR を計算すると、逐次 Nim のような問題が管理可能なプレフィックス問題に変換されます。 
-`count`ディクショナリにより、以前に確認された XOR の定数検索が保証されます。 
- モジュロ演算では大数制約が維持されます。 
- プレフィックス XOR の反復により、有効なパーティションの数が直接累積されます。 

単一のポケットまたは同じ数のピーナッツを持つすべてのポケットなどの境界条件は自然に処理されます。接頭辞 XOR は、開始または終了での些細な分割を含むすべての可能な分割を考慮します。

 ## 特殊なケース

 のために`n=1`と`[1]`, アリスには勝ち技がありません。 有効なパーティションが存在しないため、アルゴリズムは正しく 0 を返します。 次のような均一な配列の場合`[1,1,1,1,1]`、プレフィックス XOR は 1 と 0 の間で交互に行われ、すべてのパーティションが正しくカウントされるようになり、結果は次のようになります。`2^(n-1)`有効な部門。 すべてのポケットの XOR がゼロ以外のシーケンスの場合、アルゴリズムはその XOR を生成する分割のカウントを蓄積し、最適な再生が尊重されるようにします。 このメソッドは、最小入力制約と最大入力制約の両方を自然に処理します。
