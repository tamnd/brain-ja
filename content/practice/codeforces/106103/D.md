 ## 解決策
 ## 問題の理解

 3D 空間内の 8 つの点の集合が与えられていますが、その情報は意図的に信頼性が低く、各点内で 3 つの座標が恣意的に並べ替えられている可能性があります。 したがって、各行では、固定された (x、y、z) 順序ではなく、3 つの整数のマルチセットが得られます。 

タスクは、結果として得られる 8 つの頂点が 3D 空間で完全な立方体を形成するように、すべての点の内部の座標に順序を割り当てることが可能かどうかを判断することです。 可能であれば、与えられたスクランブル行と一致する立方体頂点の有効な再構成を出力する必要があります。 

主な難しさは、固定点の幾何学的条件をチェックするだけではないことです。 同時に、点ごとの座標の割り当てを選択し、グローバルな剛構造を検証します。 立方体制約は 8 つの点すべてを結合するため、個々の点に対する局所的な推論では不十分です。 

入力サイズは小さく、8 ポイントに固定されています。これは、指数関数または順列ベースの推論が受け入れられることをすぐに示唆しています。 すべての割り当てをポイントごとに独立して試したとしても、得られるのはせいぜい$3^8 = 6561$実際には、対称性を枝刈りすることにより、さらに少なくなります。 これなら十分時間制限内です。 

単純な幾何学的チェックだけでは十分ではありません。各線のあいまいさにより、有効な立方体配置が隠れてしまう可能性があるからです。 たとえば、次の 2 行は次のとおりです。 

入力:```
0 1 2
2 1 0
```同じ点の割り当てを異なる座標順序で表すことができます。 各行を固定点として扱う不用意なアプローチは、有効な立方体を拒否するか、無効な立方体を受け入れることになります。 

もう 1 つの微妙な失敗例は、複数の順列が部分的な制約を満たしているが、1 つのグローバル割り当てだけがキューブを形成している場合です。 たとえば、ローカルで一貫したエッジ長でも、グローバルに正確に 12 個の等しいエッジを生成できない場合があります。 

したがって、中心的な課題は、立方体の幾何学的検証と組み合わせた座標割り当ての検索です。 

## アプローチ

 ブルート フォース ソリューションでは、8 つのポイントのそれぞれが個別に処理されます。 各点は値の 3 倍であるため、各点についてその座標の 6 つの順列すべてを試します。 これにより、$6^8 = 1{,}679{,}616$最悪の場合、合計割り当て数が増加します。 

完全な割り当てごとに、結果の 8 つの点が立方体を形成しているかどうかを確認します。 3D 空間内の立方体は、距離を使用して検証できます。有効な立方体は、28 のペアごとの二乗距離のうち、正確に 2 つの異なる値 (エッジに対応する値と対角線に対応する値) を正確に多重度を持って持たなければなりません。 すべての二乗距離を計算できます。$O(8^2)$そしてカウントを検証します。 

この強引なアプローチはすでに境界線に達していますが、制約が非常に小さいため Python の最適化が不要であることを考えると、まだ実行可能です。 

推論を簡素化する重要な観察は、問題は最初にジオメトリに関するものではなく、制約された割り当てに関するものであるということです。 座標が固定されると、立方体の検証は決定的になります。 したがって、問題は、強力な構造フィルターを使用した順列の検索に帰着します。 

事前にジオメトリを賢く使おうとするのではなく、探索空間は小さく、正確さは徹底的な探索から得られるという事実に頼っています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース順列 + 検証 |$O(6^8 \cdot 8^2)$|$O(1)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各入力行を、順序が不明な 3 つの数値のリストとしてモデル化します。 すべての点にわたって一貫してそれらを x、y、z に割り当てる必要があります。 

1. 8 つの点のそれぞれについて、その座標の 6 つの順列すべてを生成します。 各順列は、3D 空間内のその点の可能な配置を表します。 このステップでは、グローバル構造にコミットせずに、ローカルな解釈を列挙します。 
2. 8 点に対して深さ優先検索を実行します。 各レベルで、現在のポイントの順列を 1 つ選択し、先に進みます。 これにより、8 つの具体的なポイントの候補セットが徐々に構築されます。 
3. 8 つの点すべてが割り当てられたら、すべてのペアワイズ 2 乗ユークリッド距離を計算します。 8 点の場合、距離は 28 個あります。 周波数を保存します。 
4. これらの距離が立方体の構造と一致するかどうかを検証します。 立方体では、頂点間にはエッジ、面対角線、空間対角線という 3 つの異なる距離がありますが、立方体自体の頂点間には 2 つだけが表示されます (隣接しない頂点間のエッジと対角線)。 正しいパターンは、12 個の等しい最小距離 (エッジ) と 12 個の等しい大きい顔対角距離に、一貫した比率で対応します。 
5. 有効な構造が見つかった場合は、対応する割り当てられた座標を直ちに出力します。 

検索は最初の有効な構成で停止します。 

### なぜ効果があるのか

 すべての有効なキューブ埋め込みは、入力点ごとの順列の一貫した 1 つの割り当てに正確に対応します。 DFS は、可能なすべての割り当てを列挙するため、真のキューブ構成が存在する場合は、それが検索スペースに表示されることが保証されます。 距離チェックは、剛体変換に至るまでの立方体ジオメトリの完全な特性評価であるため、無効な構成はフィルターを通過できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from itertools import permutations

def dist2(a, b):
    return (a[0] - b[0])**2 + (a[1] - b[1])**2 + (a[2] - b[2])**2

def is_cube(points):
    d = []
    n = len(points)
    for i in range(n):
        for j in range(i + 1, n):
            d.append(dist2(points[i], points[j]))

    d.sort()
    from collections import Counter
    c = Counter(d)

    if len(c) != 3:
        return False

    vals = sorted(c.items())  # (distance, count)

    # Cube should have 12 edges, 12 face diagonals, 4 space diagonals
    # between vertices: actually for 8 vertices:
    # edges: 12, face diagonals: 12, space diagonals: 4

    return sorted([cnt for _, cnt in vals]) == [4, 12, 12]

def dfs(i, chosen, perms, res):
    if i == 8:
        if is_cube(chosen):
            res.extend(chosen)
            return True
        return False

    for p in perms[i]:
        chosen.append(p)
        if dfs(i + 1, chosen, perms, res):
            return True
        chosen.pop()

    return False

def main():
    pts = [list(map(int, input().split())) for _ in range(8)]
    perms = [list(set(permutations(p))) for p in pts]

    res = []
    dfs(0, [], perms, res)

    for x in res:
        print(*x)

if __name__ == "__main__":
    main()
```プログラムはまず、各点の有効な順列をすべて構築します。 使用する`set(permutations(...))`座標が繰り返される場合の重複を回避します。 

DFS は、候補キューブを段階的に構築します。 8 つのポイントをすべて選択すると、`is_cube`関数は、ペアごとの二乗距離を使用して構造を検証します。 

よくある実装上の落とし穴は、生の距離値ではなく距離多重度が立方体を定義することを忘れていることです。 もう 1 つは、軸の位置合わせを仮定する方法ですが、立方体が空間内で任意に方向付けられる可能性があるため、これは無効です。

 ## 特殊なケース

 点内の複数の座標が等しい場合、次のようになります。`0 0 0`または`1 1 2`、順列セットは縮小します。 アルゴリズムはこれを正しく処理します。`set(permutations(...))`重複を削除し、DFS が同一の状態を探索する時間を無駄にしないようにします。 

すべての点が同一である場合、すべての順列は同じ構成になります。 距離チェックではすべて 0 が生成され、必要な 3 つのカウント構造の代わりに 1 つの距離値のみが生成されます。 バリデーターはこれを即座に拒否します。 

有効な立方体が存在していても空間内で回転されている場合、軸を揃えた直感は機能しません。 この解決策は軸の位置合わせには依存せず、ペアごとの距離のみに依存するため、回転の不変性は自然に処理されます。
