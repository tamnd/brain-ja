 ## 解決策
 ## 問題の理解

 複数のテスト ケースが与えられ、各テスト ケースは 4 つのスティックの長さで構成されます。 それぞれの棒は堅いので、切ったり、伸ばしたり、曲げたりすることはできません。 課題は、これら 4 本の棒を配置して幾何学的な正方形を形成できるかどうかを判断することです。 

ここでの正方形とは、4 つの等しい長さの辺と直角を持つ閉ループを意味します。 スティックは直線セグメントとしてのみ使用できるため、唯一の自由は各スティックを正方形の辺に割り当てる方法だけです。 

重要なモデリング手順は、幾何学的要件をスティックの長さの制約に変換することです。 正方形には 4 つの辺があり、すべて等しいです。 各スティックは単一の剛体セグメントであるため、正方形の各辺は正確に 1 つのスティックに対応する必要があります。 スティックをより小さなセグメントに分割または結合する操作は存在しないため、最終的な形状の構造は 4 つの入力値が等しいかどうかによって完全に決定されます。 

テスト ケースごとの入力サイズは小さいですが、最大 10^4 のテスト ケースを含めることができます。 つまり、テスト ケースごとに一定の作業を行うソリューションは問題ありませんが、テスト ケース上で大規模な構造や入れ子になったループの並べ替えを伴うものは問題ありませんが、不要です。 この制約により、直接的な一定時間のチェックが行われるようになります。 

グループ化について考えすぎようとすると、微妙な特殊なケースが発生します。 たとえば、1、2、1、2 のような棒を組み合わせて長さ 2 または 3 の 4 つの辺を形成することを想像するかもしれません。棒は分割したり連結したりできないため、これは無効です。 もう 1 つの間違いは、総和が 4 で割り切れるだけでよいと仮定していることです。これは、柔軟な切断問題では正しいですが、ここではそうではありません。 

具体的な失敗の直感:

 入力:```
1
1 2 1 2
```一辺 1.5 の正方形を形成できるとか、ペアリングが役立つのではないかと考える人もいるかもしれませんが、スティックを分割することはできないため、どの構成でも 4 つの等しい辺を生成することはできません。 正しい出力は`NO`。 

入力：```
1
5 5 5 5
```すべてのスティックはすでに一致しているため、それぞれをサイドに直接割り当てることができます。 出力は`YES`。 

## アプローチ

 強引な解釈では、スティックを 4 つの側面に割り当て、幾何学的実現可能性を検証しようとします。 スティックが 4 つしかないので、割り当てのすべての順列を試みることができ、分割が許可されている場合はグループ化の決定を検討することもできます。 ターゲット シェイプの構造は非常に厳格であるため、これはすぐに不必要な複雑さになります。すべての側面が 1 つのスティックに正確に一致する必要があります。 単純な幾何学的な構築ステップであっても、代替アセンブリが合法ではないことがわかった後は、辺の長さの均等性をチェックするまでに失敗してしまいます。 

重要な観察は、二乗制約によりすべての自由度が排除されるということです。 各辺が正確に 1 つのスティックである必要があることを受け入れると、問題は 4 つの値がすべて同一かどうかを検証することになります。 逸脱があると、少なくとも一方の側の等価条件が破られ、構築が不可能になります。 

したがって、「幾何学」部分は完全に消え、残るのは 4 つの整数に対する単純な等価性テストです。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの 4 つのスティックの長さを読み取ります。 これらは、正方形を形成できる唯一の利用可能なセグメントを表します。 
2. 4 つの値すべてを最初のスティックと比較します。 その理由は、正方形が可能であれば、すべての辺が同一でなければならないため、すべてが単一の基準値に一致する必要があるということです。 
3. いずれかのスティックが最初のものと異なる場合は、すぐに正方形を形成することは不可能であると結論付けます。 
4. 4 つの値がすべて一致する場合、それらは正方形の 4 つの辺を直接形成していると結論付けられます。 

決定は各テスト ケースに対して完全にローカルであるため、ケース間に相互作用はなく、状態が蓄積されることもありません。 

### なぜ効果があるのか

 正方形には 4 つの等しい辺が必要です。 スティックは変更できないため、各側が正確に 1 つのスティックである必要があります。 つまり、辺の長さの複数セットには、4 回繰り返される単一の一意の値が含まれている必要があります。 偏差があると、少なくとも 1 つの辺の長さが異なり、正方形の定義が崩れます。 長さの不一致を補う代替構造はないため、等しいことが必要かつ十分です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        a, b, c, d = map(int, input().split())
        if a == b == c == d:
            out.append("YES")
        else:
            out.append("NO")
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションは、各テスト ケースを個別に読み取り、単一の連鎖された等価性チェックを実行します。 連鎖比較`a == b == c == d`これは、ペアごとの条件を明示的に記述せずに、すべての値が同一であることを確認するコンパクトな方法です。 繰り返しの I/O オーバーヘッドを避けるために、出力はバッファリングされます。 

よくある実装の間違いは、部分的な等価性のみをチェックすることです。`a == b and c == d`、次のようなケースを誤って受け入れます。`1 1 2 2`。 もう 1 つの間違いは、並べ替えと隣接する等価性のチェックです。これはまだ正しいですが、このような小さな固定サイズの入力には不要なオーバーヘッドです。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(t) | 各テスト ケースは、4 つの整数 | に対して一定数の比較を実行します。 
| スペース | お(1) | 出力バッファリングを除けば、少数の変数のみが使用されます。 

10^4 のテスト ケースであっても、ケースごとに少数の整数比較しか実行しないため、この解は十分に制限内にあります。 並べ替え、再帰、グラフ処理は含まれません。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    out = io.StringIO()

    def solve():
        input = sys.stdin.readline
        t = int(input())
        res = []
        for _ in range(t):
            a, b, c, d = map(int, input().split())
            res.append("YES" if a == b == c == d else "NO")
        print("\n".join(res))

    with redirect_stdout(out):
        solve()
    return out.getvalue().strip()

# provided samples
assert run("7\n1 2 3 4\n1 1 1 1\n2 2 2 2\n1 2 1 2\n1 1 5 5\n5 5 5 5\n4 10 5 9\n") == \
"NO\nYES\nYES\nNO\nNO\nYES\nNO"

# all equal minimum case
assert run("1\n1 1 1 1\n") == "YES", "all equal"

# one differing element
assert run("1\n1 1 1 2\n") == "NO", "single mismatch"

# alternating pairs
assert run("1\n3 3 4 4\n") == "NO", "pair symmetry not enough"

# larger identical values
assert run("1\n100 100 100 100\n") == "YES", "large equal values"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | すべて等しい | はい | 最も単純な有効な正方形 |
 | 単一の不一致 | いいえ | 最小限の違反を検出します。 
| ペアの対称性 | いいえ | 誤ったペアリングの想定を防ぎます。 
| 大きな等しい値 | はい | 数値エッジの問題はありません |

 ## 特殊なケース

 よくある失敗例は、ペアリングが十分であると想定していることです。`(a == b and c == d)`十分です。 入力用`1 1 2 2`、そのロジックは誤って YES を返します。 4 つの値すべてが一致するわけではないため、正しいアルゴリズムでは直ちに拒否されます。 

入力：```
1
1 1 2 2
```実行:

 最初の比較は合格します`a == b`、 しかし`a == c`失敗したため、アルゴリズムは停止して戻ります`NO`。 

もう 1 つの微妙なケースは、値がすべて個別であるものの、次のように視覚的に「バランスの取れた」セットを形成している場合です。`2 3 4 5`。 役に立つ部分構造はありません。 チェックは 2 回目の比較ですぐに失敗します。 

入力：```
1
2 3 4 5
```最初の等価性スキャン中に不一致が検出され、`NO`それ以上の推論は必要ありません。
