 ## 問題の理解

 長さの基本配列を繰り返すことによって形成された無限シーケンスを処理しています。$n$。 シーケンスを最初のブロックの無限のタイリングと考えてください。$k$モジュロ演算を使用して、常に最初のブロック内の任意の位置にマップされます。 

2 つの操作でこの構造を変更し、クエリを実行します。 最初の操作は、すべてのブロック内の 2 つの固定位置を同時に交換します。 立場を交換したら$i$そして$j$、その後、$i$各ピリオドの - 番目の要素は、対応する要素と交換されます。$j$同じ期間の - 番目の要素。 これは、構造がブロック間で独立して変化するのではなく、周期的なレイアウト全体に一貫して適用されるグローバルな置換であることを意味します。 

2 番目の操作では、最初の操作を実行するように求められます。$x$無限シーケンスの要素、その 10 進表現を 1 つの長い数値に連結し、それを大きな素数の法で計算します。$p$。 

この難しさの原因は 2 つあります。 まず、スワップは繰り返されるすべてのブロックに一度に影響を与えるため、インデックスの動的な並べ替えを維持する必要があります。 2 番目のクエリ値は、$x$最大で大きくすることができます$2 \cdot 10^9$したがって、シーケンスを要素ごとにシミュレートすることはできません。 連結操作は、各要素が可変の桁数に寄与することも意味するため、桁の長さとモジュラー連結を注意深く追跡する必要があります。 

制約は、反復処理を行うすべてのソリューションを意味します。$x$クエリごとには不可能です。 次の場合、クエリごとに 1 つのブロックを反復処理するだけでも遅すぎます。$n$そして$q$到着$3 \cdot 10^5$。 これにより、位置ごとに数字情報を前処理し、ブロックごとに対数または定数時間で動的に並べ替えられた配列に対するプレフィックス クエリをサポートするソリューションが実現します。 

リオーダインデックスを交換するときに、微妙なエッジケースが発生します。配列を物理的に変更するが、クエリが繰り返し構造に依存していることを忘れる素朴な解決策では、最初のブロックのみが更新され、誤った結果が生成されます。 もう一つのエッジケースは大きい$x$多くの完全なブロックと部分ブロックにまたがる場合、これらの部分を分離しないとオーバーフローや間違ったモジュラー連結が発生します。 

## アプローチ

 ブルート フォース解釈では、現在の配列を保存し、すべての周期的な位置で値を交換することでスワップを適用し、インデックスから反復してクエリに応答します。$1$に$x$、数字を連結してモジュロを計算する$p$。 これは、シーケンスと操作の定義に直接従うため、概念的には正しいです。

重要な観察は、無限シーケンスは最初のシーケンスの順列によって完全に決定されるということです。$n$要素、およびスワップはこの順列を変更するだけです。 したがって、配列自体を変更する代わりに、論理位置から現在の値へのマッピングを維持します。 その後、各クエリはコンピューティングに帰着します。

 ## アルゴリズムのチュートリアル

 各配列位置を、次の 2 つの値を持つ「数字ブロックの貢献者」として扱います。その数値モジュロ$p$、およびその桁長。 

また、スワップによって引き起こされた現在の順列も維持します。 

### ステップ

 1. 各初期位置の事前計算$i$桁の長さ$len[i]$および値のモジュロ$p$。 数値自体は変化せず、数値の位置のみが変化するため、これは静的です。 
2. 10 モジュロの累乗を事前計算する$p$まで$n$。 これは、1 つのブロック内で数値を効率的に連結するために必要です。 
3. 「ブロックの概要」構造を構築します。 現在の順列については、次のように計算します。 

連結として解釈される 1 つの完全なブロックの合計値、およびブロックの合計桁長。 

これは、位置を順番に繰り返すことによって行われます。 

私たちは以下を維持します:

 現在の値 = 現在の値 * 10^{len[i]} + val[i]
 4. 順列配列を維持する`pos`実際の要素の位置が$i$は`a[pos[i]]`。 
5. スワップクエリの場合は、単純にスワップします。`pos[i]`そして`pos[j]`スワップはすべてのブロックに同様に適用されるためです。 
6. 値を含むクエリ タイプ 2 の場合$x$:

 計算します:

 full_blocks = x // n

 レム = x % n
 7. 1 つの完全なブロックの寄与を次のように事前計算します。 

(ブロック値、ブロック長)
 8. 連結を繰り返して full_blocks の結果を計算します。 

結果を初期化 = 0

 各ブロックについて:

 結果 = 結果 * 10^{block_len} + block_value (mod p)

 これは、必要に応じて事前計算によるべき乗またはブロックのバイナリ リフティングを使用して高速化されます。 
9. 次に、現在の順列の最初の rem 位置を反復し、同様に連結することにより、サイズ rem の残りのプレフィックスを処理します。 

### なぜ効果があるのか

 重要な不変条件は、シーケンスが常に同じ並べ替えられたブロックの周期的な繰り返しであるということです。 スワップはそのブロックの内部順序を変更するだけで、周期性を壊すことはありません。 したがって、任意の長さのプレフィックス$x$ブロック全体の繰り返しと単一ブロックのプレフィックスに一意に分解されます。 連結は 10 のべき乗のモジュラー変換では結合的であるため、問題全体は事前に計算されたブロック表現を結合することに帰着します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    MOD_CACHE = {}

    for _ in range(t):
        n, q, p = map(int, input().split())
        a = list(map(int, input().split()))

        # precompute digits and values
        val = [x % p for x in a]
        ln = [len(str(x)) for x in a]

        # permutation of indices
        pos = list(range(n))

        # precompute 10^k mod p up to max digit length (10 digits max)
        pow10 = [1] * 20
        for i in range(1, 20):
            pow10[i] = (pow10[i-1] * 10) % p

        def build_block():
            res = 0
            for i in pos:
                res = (res * pow10[ln[i]] + val[i]) % p
            return res

        def block_len():
            return sum(ln[i] for i in pos)

        for _ in range(q):
            tmp = input().split()
            if tmp[0] == '1':
                i, j = map(int, tmp[1:])
                i -= 1
                j -= 1
                pos[i], pos[j] = pos[j], pos[i]

            else:
                x = int(tmp[1])

                full = x // n
                rem = x % n

                # compute block
                bval = 0
                blen = 0
                for i in pos:
                    bval = (bval * pow10[ln[i]] + val[i]) % p
                    blen += ln[i]

                # full blocks
                res = 0
                cur_pow = pow10[blen]

                # fast exponentiation for repeated block concatenation
                # binary lifting on full blocks
                cur_block = bval
                exp = full
                first = True
                while exp:
                    if exp & 1:
                        if first:
                            res = cur_block
                            first = False
                        else:
                            res = (res * pow10[blen] + cur_block) % p
                    cur_block = (cur_block * pow10[blen] + bval) % p
                    exp >>= 1

                # remainder
                for i in pos[:rem]:
                    res = (res * pow10[ln[i]] + val[i]) % p

                print(res)

    return

if __name__ == "__main__":
    solve()

の`build_block`ロジックは、連結を 10 の累乗を使用したモジュラー演算に直接変換したものです。 同じロジックが完全なブロックの構築と残りの処理の両方に再利用され、一貫性が確保されます。 

繰り返されるブロックの累乗では、2 倍化手法が使用されます。ブロックを 2 倍にするたびに、次のような桁シフトも考慮されます。`pow10[blen]`。

 ## 特殊なケース

 重大なエッジケースは次のような場合です。$x$はの正確な倍数です$n$。 この状況では、残りのセグメントはありません。 アルゴリズムは反復を避ける必要があります`pos[:0]`これは Python では安全ですが、追加の連結ステップが適用されていないことを確認する必要があります。 

もう 1 つのエッジ ケースは、スワップがインデックスのシャッフルを繰り返し、その結果、順列が頻繁に変化する場合に発生します。 保管のみなので`pos`、各スワップは、派生構造を再構築せずに直接適用する必要があります。 スワップ間でブロック値をキャッシュしようとする試みは無効になり、不正な連結が暗黙的に生成されます。 

最後の微妙なケースは、大きな桁値です。 それぞれの数値は最大で$10^9$、桁の長さは最大 10 であるため、事前に計算されたパワー テーブルは少なくともこの範囲をカバーする必要があります。 これを制限しないと、インデックス作成エラーや、連結時の不正確なモジュラー シフトが発生します。
