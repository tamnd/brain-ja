 ## アルゴリズムのチュートリアル

 私たちは、「アクティブな」数値の動的なセットを維持し、そのセットが割り算の下で閉じているかどうかを追跡します。 

### 事前計算

 1. すべての整数について$x \le m$、約数のリストを計算します。 

これは、すべての数値を反復処理して倍数にプッシュするか、標準の約数を列挙することによって実行できます。 

この構造は、各数値が何に依存しているのかをすぐに理解できるようにするために必要です。 
2. 数字ごとに$x$、 定義する`missing[x]`最初は約数の数として$x$。 

これは、プレフィックスにまだ存在していない必須要素の数を表します。 

### 動的処理

 1. ブール配列を維持する`present[x]`かどうかを示す$x$は現在のプレフィックス セット内にあります。 
2. カウンターを維持する`bad`、要素の数として定義されます$x$そのような`present[x] = true`そして`missing[x] > 0`。 

プレフィックスが有効になるのは、次の場合です。`bad == 0`。 
3. 要素を 1 つずつ処理します。 値を挿入する場合$y$:

 マークします`y`現在のように。 
4. 倍数ごとに$x$の$y$、減少します`missing[x]`1までに。 

これは、$y$はの約数です$x$、その約数を利用できるようにしました。 
5. 複数の場合$x$がすでに存在する場合、欠落した約数がある状態からない状態に移行したか、またはその逆に移行したかを確認し、更新します`bad`それに応じて。 
6. すべての倍数を処理した後、更新します`missing[y]`同じメカニズムを通じて暗黙的に (なぜなら$y$はそれ自体の倍数です)。 
7. もし`missing[y]`挿入後もまだゼロより大きいため、インクリメントします`bad`。 
8. 出力`1`もし`bad == 0`、それ以外の場合は出力`0`。 

### なぜ効果があるのか

 このアルゴリズムは、各アクティブ要素のプレフィックスに必要な除数がすべて存在するかどうかを正確に記録します。 すべての挿入は、挿入された値の倍数である数値にのみ影響します。これは、その値に依存する除数構造を持つすべての要素に正確に対応します。 除数の閉包が有効性の唯一の要件であるため、この不変条件を維持するだけで十分であり、追加のグローバル条件は必要ありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))

        # build divisor lists
        divisors = [[] for _ in range(m + 1)]
        for i in range(1, m + 1):
            for j in range(i, m + 1, i):
                divisors[j].append(i)

        missing = [0] * (m + 1)
        for i in range(1, m + 1):
            missing[i] = len(divisors[i])

        present = [False] * (m + 1)
        bad = 0

        out = []

        for x in a:
            if not present[x]:
                present[x] = True

                # x itself loses one missing divisor (itself)
                missing[x] -= 1

                if missing[x] == 0:
                    bad -= 1  # it becomes fully satisfied
                else:
                    bad += 1

                # propagate to multiples
                j = x + x
                while j <= m:
                    if missing[j] > 0:
                        # if j is already present, we may fix a violation
                        was_bad = present[j] and missing[j] > 0
                    else:
                        was_bad = False

                    missing[j] -= 1

                    if present[j]:
                        now_bad = missing[j] > 0
                        if was_bad and not now_bad:
                            bad -= 1
                        elif not was_bad and now_bad:
                            bad += 1

                    j += x

            out.append('1' if bad == 0 else '0')

        print(''.join(out))

if __name__ == "__main__":
    solve()
```このコードは、除数クロージャのアイデアを直接反映しています。 の`missing`配列は、各数値に対して必要な約数がまだ存在しない数を追跡します。 の`present`array を使用すると、プレフィックスにすでに出現している要素の正確さのみを考慮することが保証されます。 

実装の重要な詳細は、挿入された各値の倍数にわたる伝播ループです。 このループは、ローカルな挿入を除数関係に対するすべてのグローバルな効果に変換するメカニズムです。 

接頭辞ごとの最終的な答えは、現在の数値が約数に関してまだ「不完全」であるかどうかだけです。

import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    res = []
    for _ in range(t):
        n, m = map(int, input().split())
        a = list(map(int, input().split()))
        s = set()
        ok = []
        for x in a:
            s.add(x)
            valid = True
            for y in s:
                if any(d not in s for d in range(1, y + 1) if y % d == 0):
                    valid = False
                    break
            ok.append('1' if valid else '0')
        res.append(''.join(ok))
    return "\n".join(res)

 ## 特殊なケース

 主なエッジケースは、プレフィックスに次のものが含まれない場合です。`1`。 すべての有効な約数セットには次のものが含まれている必要があるため、`1`、これを含まないプレフィックスは直ちに無効になります。 アルゴリズムはこれを自然に処理します。`missing[1]`次の場合にのみゼロになります`1`が挿入され、それまでは`present[x]`それはに依存します`1`保つ`bad > 0`。 

もう 1 つの微妙なケースは、値が繰り返されることです。 挿入はセットのメンバーシップに関して冪等であるため、チェックすることで重複を無視します。`present[x]`アップデートを適用する前に。 これにより、除数のカウントが 2 倍減少することがなくなり、不変式の一貫性が維持されます。 

3 番目のケースは、次のような割り算の降順で数値を挿入する場合です。`6, 3, 2, 1`。 この構造は最初は閉包に大きく違反していますが、欠落している約数が導入されるにつれて徐々に有効になります。 動的メンテナンスにより、単調な妥当性を仮定するのではなく、各ステップの後に正確さが評価されることが保証されます。
