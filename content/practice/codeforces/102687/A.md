 ## 解決策
 ## 問題の理解

 パズルはパイプピースの長方形のボードで構成されています。 一部のセルには文字が含まれており、すべての文字が 0 回または 2 回表示されます。 同じ文字が 2 つ出現する場合は、連続したパイプで接続する必要がある端子です。 可動部分は直線パイプのみです。クリックすると、垂直パイプを水平パイプに、またはその逆に変えることができます。 タスクは、等しい文字のすべてのペアを接続するために必要な最小クリック数を見つけるか、それができないと報告することです。 

入力には複数のテスト ケースが含まれています。 各ボードの行と列の数、およびすべてのセルの初期状態がわかっています。 ソリューションでは最終ボードを出力する必要はなく、最小限の回転数だけを出力する必要があります。 この制約により、ボードあたり最大 500 行、500 列が許可されるため、異なる回転を繰り返し試行するソリューションは不可能になります。 ボードには 250,000 個のセルを含めることができます。これは、アルゴリズムのセル数が線形に近いことを意味します。 可能な回転の配置をすべてチェックするなど、グリッド サイズの二次関数は、利用可能な操作をはるかに超えています。 

重要な観察点は、すべてのパイプ部分が真っ直ぐであることです。 接続は回転できないため、同じ文字のペアは水平または垂直の直線のセグメントで接続する必要があります。 これにより、どのペアにも可能なパスが 1 つしかないため、検索の必要がなくなります。 

いくつかの特殊なケースでは、回転のみをカウントする実装が壊れる可能性があります。 

位置合わせされていないペアを考えてみましょう。```
2 3
A--
||A
```正しい出力は次のとおりです。```
F
```二人`A`セルが同じ行にも同じ列にもありません。 直線のパイプ パスではそれらを接続できないため、何度クリックしてもボードを解決できません。 

2 番目のケースは、2 つの必要なパスが 1 つのセルに 2 つの異なる方向を要求する場合です。```
3 3
A|B
-+-
A|B
```この状況を簡略化すると、あるペアは共有中央セルを水平にする必要があり、別のペアは垂直にする必要があります。 正しい出力は次のとおりです。```
F
```不注意な実装では、ペアごとに必要なフリップを個別にカウントし、1 つの物理タイルが両方の方向を持つことができないことを見逃す可能性があります。 

もう一つの重要なケースは、道を塞ぐ手紙です。```
1 3
ABA
```正しい出力は次のとおりです。```
F
```中央のセルは端子であり、パイプ セグメントではありません。 二人の間のつながり`A`細胞は通過できません`B`。 

## アプローチ

 ブルートフォース ソリューションでは、考えられるすべてのローテーション セットが試行されます。 各パイプには 2 つの状態があるため、ボードには`k`パイプセルには`2^k`可能な構成。 すべての構成について、グラフの走査を実行して、すべての文字ペアが接続されるかどうかを確認できます。 これは、考えられるすべての最終ボードを検査するため正しいですが、ほぼすぐに使用できなくなります。 パイプ セルが 100 個でもあるグリッドには、すでにそれ以上のパイプ セルが存在します。`10^30`構成。 

力技が不要な理由は、ボードの特殊な構造にあります。 真っ直ぐなパイプは曲げることができないため、一致する 2 つの文字の間のパスはあらかじめ決められています。 文字が異なる行および異なる列にある場合、可能なパスはありません。 それらが整列している場合、それらの間のすべてのセルには強制的な方向が設定されます。 

問題は整合性チェックになります。 必要なパス内にあるすべてのセルに、そのパスで要求される方向を割り当てます。 2 つのパスが同じセルに対して異なる方向を要求する場合、答えは不可能です。 それ以外の場合、最小クリック数は、現在の方向が必要な方向と異なる割り当てられたセルの数と同じになります。 

ブルート フォースは有効および無効な最終状態をすべて試行するため機能しますが、状態の数が指数関数的に増加するため失敗します。 すべての有効なパスが一意に決定されるという観察により、問題は強制要件を 1 回スキャンするだけで済みます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k * r * c) | O(r * c) | 遅すぎる |
 | 最適 | O(r * c) | O(r * c) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ボードを読みながら、すべての文字の位置を保存します。 すべての文字は、出現時に正確に 2 回出現するため、後で各ペアを直接処理できます。 
2. 各パイプセルの必要な最終方向を保存する補助グリッドを作成します。 最初は、どのセルにも要件はありません。 
3. 文字ペアごとに、2 つのエンドポイントが行または列を共有しているかどうかを確認します。 どちらでもない場合は、直管は回転できないため、ペアを接続できません。 
4. 2 つのエンドポイント間のセルを厳密にウォークスルーします。 ペアの方向に応じて、各セルに水平パイプまたは垂直パイプが必要であるとマークします。 

セルに別のペアからの要件がすでにある場合は、2 つの要件を比較します。 競合とは、2 つの接続が同じ場所で互換性のないパイプ方向を必要とすることを意味するため、答えは不可能です。 
5. すべてのペアが処理された後、必要な方向が存在し、元の​​文字と異なるセルの数を数えます。 このようなセルはそれぞれ 1 回のクリックだけで済みます。 

これが機能する理由は、どのペアにも代替ルートがないためです。 文字のペアには、可能な直線パスが 1 つあるか、可能なパスがまったくないかのいずれかです。 これらすべてのパスがすべての共有セルの方向に一致すると、最終的なボードが完全に決定されます。 したがって、最小クリック数は、開始方向から変更する必要があるセルの数にすぎません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(r, c, grid):
    positions = {}

    for i in range(r):
        for j in range(c):
            ch = grid[i][j]
            if ch.isalpha():
                positions.setdefault(ch, []).append((i, j))

    need = [[-1] * c for _ in range(r)]
    # 0 = horizontal, 1 = vertical

    for ch, cells in positions.items():
        if len(cells) != 2:
            continue

        (r1, c1), (r2, c2) = cells

        if r1 == r2:
            lo, hi = sorted((c1, c2))
            for j in range(lo + 1, hi):
                if grid[r1][j].isalpha():
                    return "F"
                if need[r1][j] == 1:
                    return "F"
                need[r1][j] = 0
        elif c1 == c2:
            lo, hi = sorted((r1, r2))
            for i in range(lo + 1, hi):
                if grid[i][c1].isalpha():
                    return "F"
                if need[i][c1] == 0:
                    return "F"
                need[i][c1] = 1
        else:
            return "F"

    ans = 0
    for i in range(r):
        for j in range(c):
            if need[i][j] != -1:
                current = 0 if grid[i][j] == "-" else 1
                if current != need[i][j]:
                    ans += 1

    return str(ans)

def main():
    t = int(input())
    out = []

    for _ in range(t):
        r, c = map(int, input().split())
        grid = [input().strip() for _ in range(r)]
        out.append(solve_case(r, c, grid))

    print("\n".join(out))

if __name__ == "__main__":
    main()
```辞書`positions`すべての文字の 2 つのエンドポイントを収集します。 文字のみが端子を表すため、回転できるセルとしてカウントされません。 

の`need`配列は、接続によって強制された最終的な方向を記録します。 3 つの状態を使用すると、実装が簡単になります。`-1`現在このセルを必要とするパスがないことを意味します。`0`水平を意味し、`1`垂直という意味です。 

ペアを処理するとき、ループは次から開始してエンドポイントを除外します。`lo + 1`そしてその前に終わる`hi`。 文字自体はパイプ部分ではないため、この境界処理は重要です。 別の文字が間隔内に出現する場合、パスは端子を通過する必要があるため、ソリューションは拒否されます。 

最終スキャンでは、少なくとも 1 つの必要なパスの一部であるセルのみが考慮されます。 どの接続にも使用されていないパイプは元の方向のままであるため、クリックしても解決にはなりません。 

## 実用的な例

-|-|-|
|g|-g-

```二人`g`セルは同じ行にあります。 それらの間の中央のセルは水平である必要があります。 

| ペア | 必要なセル | 現在の状態 | クリック数 |
 | --- | --- | --- | --- |
 | g | (1,3) |`-`| 0 |

 表には接続がすでに存在していることが示されているため、答えは次のようになります。`0`この構築されたトレースに対して。 中央のセルが垂直であれば、1 回のクリックに貢献します。 

回転が必要な場合の例:```
3 3
A|A
|||
A|A
```1 つのペアの場合、中央の列は強制的に垂直になります。 もう一方のペアでは、中央の列も強制的に垂直になります。 

| ペアが処理されました | セル要件が追加されました | 紛争 | 処理後のクリック数 |
 | --- | --- | --- | --- |
 | 最初のペア | 中央のセルは垂直である必要があります | なし | 0 |
 | 2番目のAペア | 中央のセルは垂直である必要があります | なし | 0 |

 トレースは、要件が一致する場合、繰り返しの要件が許可されることを示しています。 このアルゴリズムでは、同じタイルを複数回カウントすることはありません。

 ## 特殊なケース

 共有行または列を持たないペアは直ちに拒否されます。 例えば：```
2 3
A--
||A
```アルゴリズムは 2 つの座標を比較します。`A`セルを検索し、両方の座標が異なることを検出して返します。`F`。 直線パイプではコーナーを作成できないため、可能な回転順序はありません。 

複数のパスがセルを共有する場合、アルゴリズムは最初に必要な方向を維持し、それ以降のすべてのリクエストをそれに対してチェックします。 1 つのパスが水平を必要とし、もう 1 つのパスが垂直を必要とする場合、共有タイルには一度に 2 つの状態が必要となるため、アルゴリズムは次の値を返します。`F`。 

パスが別の文字と交差すると、中間スキャンによってアルファベットが検出されます。 そのセルはパイプになることができないため、アルゴリズムは文字を誤って空のセルとして扱う代わりにボードを拒否します。 

最後のカウントステップでは、すでに正しいパイプと未使用のパイプを自然に処理します。 必要な接続に属するセルのみが応答に寄与し、現在の方向が必要な方向と異なる場合、そのような各セルは 1 回のクリックだけで寄与します。
