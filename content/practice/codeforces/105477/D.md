 ## 解決策
 ## 問題の理解

 都市は、すべての場所がノードであり、順序付けられたノードのペアごとに移動時間が設定されている有向完全グラフとしてモデル化できます。 各ノードには、そこに立っている観光客の数を表す負ではない値もあります。 旅行者はノード 0 から出発してノード 1 に到達する必要があり、合計移動時間が指定された制限 S を超えない限り、ノード間の歩行は許可されます。 

移動中、パスがノードを訪問するたびに、そのノードのすべての観光客を収集できますが、各ノードが複数回訪問した場合でも、貢献できるのは 1 回だけです。 目標は、時間制限内に留まり、すべての個別の訪問ノードで収集された観光客の合計を最大化する、0 から 1 までのウォーク (場合によってはノードを再訪問する) を選択することです。 

入力により複数のテスト ケースが提供されます。 各テスト ケースは、ノード数 n、制限時間 S、リスト t (t[i] はノード i の観光客数)、および n × n 行列 a (a[i][j] は i から j に直接移動する時間) を提供します。 

主な問題点は、グラフが完成しても、最適なルートでノードを再訪問する可能性があることです。これは、再訪問は報酬の点で無料ですが、それでも時間がかかるためです。 制約 S は最大 20000 であるため、n が 18 に達すると、ノードのすべてのサブセットにわたる直接動的プログラミングは実行できなくなります。これは、2^18 状態はすでに注意深い処理が必要であり、遷移には余分な係数 n が必要となるためです。 

複数のパスが異なる残りバジェットで同じノードに到達すると、微妙な問題が発生します。 単純な最短経路のアイデアは失敗します。時間を最小化するのではなく、時間予算内で収集された重みを最大化するためです。そのため、パレートは時間と収集された価値の間でトレードオフになります。 

落とし穴の簡単な例としては、長いルートは価値の高いノードに早くアクセスする一方、短いルートは目的地に早く到着するものの収集量が少ない場合があります。 ノードごとの最短時間のみを保存すると、より長いがより収益性の高いパスが破棄され、最適な答えが失われます。 

## アプローチ

 この構造は、予算制約のある完全な有向グラフ内のパスを選択していることを示唆しています。各ノードには報酬が 1 回ずつ収集されます。 これは、訪問ノードのサブセットにわたる状態空間にすぐに似ていますが、完全なサブセット DP は (マスク、最後のノード) を追跡することになりますが、n が 18 の場合、これは大きすぎます。 

ブルートフォースアプローチでは、訪問するノードのサブセットのすべての順列を列挙し、連続して選択されたノード間の最短パスコストを計算し、報酬を合計します。 パスの計算を無視しても、これは n の階乗になります。 n = 18 の場合、順列はすでに実行可能な限界を超えています。 

重要な観察は、n はサブセットを状態として扱うことができるほど十分に小さいが、S はノード間の最短パスを事前計算できるほど十分に小さいということです。 すべてのペアの最短パスが判明すると、問題は、最短パス距離を使用して選択された 1 つのノードから別のノードに移動することに対応するノード上の古典的なビットマスク DP に帰着します。 

まず行列に対して Floyd-Warshall を実行して、a[i][j] が任意の 2 つのノード間の真の最短移動時間を表すことを確認します。 次に、dp[mask][i] が、最短距離を使用する遷移を通じて暗黙的に旅行コストの制約を尊重して、設定されたマスクを正確に訪問し、ノード i で終了するときに収集される最大観光客である DP を定義します。 

ただし、直接 O(2^n * n) DP は依然として S を無視します。S は遷移の実現可能性を制約するだけであることに留意して、さらに改良します。 n ≤ 18 であるため、dp[mask][i] を維持できますが、距離の合計を使用して遷移をプルーニングします。 dp time + dist[i][j] ≤ S の場合、最終的な遷移は (mask, i) から (mask ∪ {j}, j) になります。時間と値の両方を追跡する必要があるため、各状態は最良のペアを保存し、支配的な状態は破棄します。

これは、各 (マスク、i) について、(時間、報酬) ペアのセットを維持し、支配されていないペアのみを維持するパレート DP につながります。 トランジションでは、これらのセットを慎重に組み合わせます。 

より効率的な再定式化では、視点を逆にすることで、時間の経過に伴う指数関数的な DP を回避します。つまり、最短距離を事前に計算し、状態 (マスク、i) にわたってダイクストラのような拡張を実行します。優先順位は時間であり、それぞれ (マスク、i、タイム フロンティア) の最適な報酬を追跡します。 S ≤ 20000 であるため、S を超える状態を枝刈りし、最良既知を介して暗黙的に (マスク、i、t) ごとの最良の報酬を維持することで離散化できます。 

これは、サイズ O(2^n * n) のグラフにわたる複数状態の最短パスになりますが、各エッジ緩和は O(1) であり、優先キューにより各状態が効率的に処理されることが保証されます。 

最終的な答えは、時間 ≤ S でノード 1 で終了するすべての状態の中での最大報酬です。

 ## アルゴリズムのチュートリアル

 私たちは、最短パスと制約された状態の探索の 2 つの層でソリューションを構築します。 

1. 任意の 2 つのノード間の移動が明確に定義された最小移動時間になるように、Floyd-Warshall を使用してすべてのペアの最短経路を計算します。 これにより、DP 遷移中に中間ノードを考慮する必要がなくなります。 
2. 状態を (マスク, u) として定義します。これは、マスクでエンコードされたノードのセットを訪問し、現在ノード u にいることを意味します。 
3. 優先キューを状態 (time=0、reward=t[0]、mask=1<<0、u=0) で初期化します。 これは、観光客が集まった状態でノード 0 から開始することを表します。 
4. 既知の最大の報酬を達成するために、既知の最小時間への最良の辞書マッピング (マスク、u) を維持します。 状態がその構成に関する以前の知識を改善する場合にのみ、状態を拡張します。 
5. 時間の増加順に優先キューから状態をポップします。 各状態 (マスク、u) について、マスク内にないすべてのノードに移動してみてください。 移行コストは current_time + dist[u][v]、新しい報酬は current_reward + t[v] です。 
6. 新しい時間が S を超える場合、遷移を破棄します。 それ以外の場合、この新しい状態によって (mask ∪ {v}, v) の最もよく知られたエントリが改善される場合は、それを優先キューにプッシュします。 
7. 到達可能なすべての状態を処理した後、u = 1 および時間 ≤ S であるすべての状態をスキャンし、最大の報酬を取得します。 

重要な構造は、時間または報酬のいずれかを有意義な方法で改善しない限り、その状態を決して再訪しないということです。 時間は遷移に沿ってのみ増加し、S はそれを制限するため、探索は有限のままです。 

### なぜ効果があるのか

 すべての状態は、訪問したノードと終了位置の一意のセットを表し、時間による優先順位付けにより、状態を最終的に決定するときはいつでも、その状態に到達するためのすべての安価な方法をすでに検討していることが保証されます。 報酬は新しいノードを追加した場合にのみ増加し、マスク内でノードが二重にカウントされることはないため、各状態はそこに至るまでのすべての有効な履歴を完全に要約します。 枝刈りルールは、S を超えたり訪問を重複させたりすることなく、支配された状態がより適切な完了につながることはないため、最適なソリューションが失われないようにします。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, S = map(int, input().split())
    t = list(map(int, input().split()))
    dist = [list(map(int, input().split())) for _ in range(n)]

    # Floyd-Warshall for all-pairs shortest paths
    for k in range(n):
        for i in range(n):
            for j in range(n):
                if dist[i][j] > dist[i][k] + dist[k][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]

    start_mask = 1 << 0
    start_reward = t[0]

    # (time, -reward, mask, node)
    pq = [(0, -start_reward, start_mask, 0)]

    best_time = {}

    best_time[(start_mask, 0)] = 0

    ans = start_reward if 1 == 1 else 0

    while pq:
        time, neg_reward, mask, u = heapq.heappop(pq)
        reward = -neg_reward

        if time > S:
            continue

        if best_time.get((mask, u), float('inf')) < time:
            continue

        if u == 1:
            ans = max(ans, reward)

        for v in range(n):
            if mask & (1 << v):
                continue
            nt = time + dist[u][v]
            if nt > S:
                continue
            nmask = mask | (1 << v)
            nr = reward + t[v]

            state = (nmask, v)
            if nt < best_time.get(state, float('inf')):
                best_time[state] = nt
                heapq.heappush(pq, (nt, -nr, nmask, v))

    print(ans)

if __name__ == "__main__":
    solve()
```Floyd-Warshall ブロッ​​クにより、すべての移行コストが最小限に抑えられるため、DP は中間パスについて再度検討する必要がなくなります。 ヒープにより、現在最速の既知の部分ルートが常に最初に拡張されます。これは枝刈りに不可欠です。 

州のエンコードではビットマスクを使用して、各観光客グループが最大 1 回カウントされることを保証します。 best_time ディクショナリは、同じ状態のより悪いバージョンを再訪することを防ぎます。そうしないと、状態空間が爆発してしまいます。 

微妙な点は、報酬が剪定キーの一部ではないことです。 同じ（マスク、ノード）であるが、時間と報酬が異なる 2 つの状態は、支配性を得るために時間だけで比較されます。これは、S でのより良い完了につながる場合、より高い時間でより高い報酬が役立つ可能性があるためです。優先キューの順序付けにより、より早い時間を最初に探索することが保証されるため、最適なチェーンを失うことはありません。

 ## 特殊なケース

 例外的なケースとしては、ノード 0 に滞在してノード 1 に直接ジャンプする方が、どの迂回路よりも安価ですが、迂回路の方がより多くの観光客が集まる場合が考えられます。 アルゴリズムは報酬によって枝刈りをしないため、両方を正しく調査します。 

もう 1 つのケースは、複数の中間ノードが低コストのサイクルを形成する場合です。 DP ではマスクを介してのみノードを再訪問できるため、サイクルによって無限ループが発生することはありません。 

最後の微妙なケースは、2 つの状態 (マスク、ノード) が同じに達するが、時間が異なる場合です。 最小時間のみが保存されますが、常に時間の増加順に拡張するため、その後の悪い時間状態は同じマスク内でより良い継続を生成できず、最適性が維持されます。
