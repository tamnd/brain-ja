 ## 解決策
 ## 問題の理解

 固定数のセグメントから有効な「ジェット コースター」が何個形成できるかを数えるよう求められます。各セグメントは水平に 1 単位移動し、垂直に 1 単位上昇または下降します。 フルライドは正確に次の内容で構成されます`2l`セグメントは、地上レベルで始まり、地上レベルで終了し、パスのどのプレフィックスでも地上レベルを下回ることはありません。 このようなすべての有効なパスの中で、最大高さが正確に一致するものだけが必要です。`h`。 

これをモデル化する便利な方法は、各セグメントをラティス パスのステップとして扱うことです。「上」ステップでは高さが 1 増加し、「下」ステップでは高さが 1 減少します。制約は古典的な Dyck パス スタイルの条件に変換されます。パスには長さがあります。`2l`、高さ 0 で開始および終了し、負になることはなく、最大の高さが正確にあります。`h`。 

したがって、タスクはセミレングスの Dyck のようなパスを数えるようになります。`l`制限された高さの制約が等しい場合`h`。 

入力できるサイズは、`l`そして`h`最大 200 および最大 40000 のテスト ケース。 これにより、クエリごとの動的プログラミングが即座に排除されます。`O(l^2)`州。 平`O(l^2)`1 回なら問題ありませんが、何万回も繰り返すことはできません。 正しいアプローチでは、すべての答えを事前に計算する必要があります。`l ≤ 200`そして`h ≤ 200`、O(1) の各クエリに答えます。 

微妙なエッジケースが現れるのは、`h`与えられた条件に対して可能な限り大きい`l`。 有効な長さのパスで可能な最大の高さ`2l`は`l`したがって、次のクエリはすべて`h > l`慎重に解釈しない限り、0 を返す必要があります。実際には、最大値が正確に一致するパスをカウントします。`h`、だから、もし`h > l`、答えは 0 です。もう 1 つの特殊なケースは次のとおりです。`h = 0`、これはどんなポジティブなことでも不可能です`l`、自明ではない Dyck パスは少なくとも 1 まで上昇する必要があるためです。 

単純な間違いは、正確に h ではなく、高さ ≤ h の Dyck パスをすべて数えることです。 それは過大評価です。 問題は、制限された高さではなく、正確な最大の高さを要求することです。 

## アプローチ

 ブルートフォースのアイデアは、長さのバランスの取れた有効なパスをすべて生成することです。`2l`再帰を使用して、現在の高さと到達した最大の高さを追跡します。 各ステップで上昇または下降しますが、高さがマイナスにならないようにする必要があります。 長さに達したら`2l`、0 に戻っているかどうか、および最大の高さが等しいかどうかを確認します。`h`。 これは正しいですが、おおよそカタルーニャ州サイズの国家空間を探索します。`O(4^l / l^{3/2})`。 たとえ`l = 200`、これは不可能です。 

重要な点は、これが最大高さに関する追加の制約を備えた古典的な Dyck パス列挙であるということです。 このような問題は通常、位置と高さに関する動的プログラミングによって処理されるか、高さが制限されたパスをカウントする転送 DP によってより効率的に処理されます。`h`。 計算できるようになると`F(l, h)`= 長さの有効なパスの数`2l`高さ ≤ h の範囲内にある場合、境界を超える包含を使用して正確な高さの答えを導き出すことができます: 正確に最大値を持つパス`h`等しい`F(l, h) - F(l, h-1)`。 

「h を絶対に超えない」は DP で自然に強制されるのに対し、「正確に最大 h」を直接強制するのは難しいため、この削減は非常に重要です。 

次に事前計算します`F(l, h)`みんなのために`l ≤ 200`そして`h ≤ 200`状態が次の 2D DP を使用する`(i, j)`高みに到達する方法の数を意味する`j`後`i`0未満またはそれ以上にならないステップ`h`。

 ## アルゴリズムのチュートリアル

 DP テーブルを定義します。`dp[i][j]`有効な長さのシーケンスの数です`i`その高さで終わります`j`現在の高さ制限を決して超えないでください。 

これは、考えられる高さ制限ごとに個別に計算されます。`H`0から200まで。 

1. 最大許容高さが固定されている場合`H`、初期化します`dp[0][0] = 1`。 これは、地面から始まる空のパスを表します。 
2. 各ステップインデックスについて`i`1から`2l_max`、すべての高さを更新します`j`で`[0, H]`。 
3.州から`(i-1, j)`に移動できます`(i, j+1)`もし`j+1 ≤ H`、アップステップに対応します。 
4.州から`(i-1, j)`に移動できます`(i, j-1)`もし`j-1 ≥ 0`、ダウンステップに対応します。 この動きは、まだ地上にいない場合にのみ有効です。 
5. DP を入力した後、値は`dp[2l][0]`有効な長さのパスの数を与える`2l`決して身長を超えないもの`H`。 
6. 最大高さが正確に一致するパスを取得するには`h`、計算する`dp_exact[l][h] = dp_at_most[l][h] - dp_at_most[l][h-1]`。 

この減算が機能する理由は、すべての有効なパスに明確に定義された最大高さがあるためです。 最大値 ≤ h のすべてのパスをカウントすると、最大値が厳密に h より小さいパスも含まれます。 最大値 ≤ h−1 のものを減算すると、最大値が h であるものが正確に分離されます。 

### なぜ効果があるのか

 DP は、有効なプレフィックスに関係するパスと、有界ラティス内の遷移シーケンスの間の全単射を定義します。 すべての有効なパスは DP 遷移の 1 つのシーケンスに正確に対応し、高さの制約は各ステップでローカルに適用されます。 すべてのパスが 1 回だけカウントされるため、`dp_at_most`、最大高さは、すべての有効なパスのセットを素のクラスに分割します。`{max = 0, max = 1, ..., max = l}`、減算ステップでは、重複のない単一のクラスが抽出されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 10**9 + 7

MAX_L = 200

# dp_at_most[h][i][j] = ways for length i ending at height j with max height <= h
dp = [[[0] * (MAX_L + 1) for _ in range(2 * MAX_L + 1)] for _ in range(MAX_L + 1)]

dp[0][0][0] = 1

for h in range(1, MAX_L + 1):
    for i in range(2 * MAX_L + 1):
        for j in range(h + 1):
            val = dp[h - 1][i][j]
            if not val:
                continue
            dp[h][i][j] = (dp[h][i][j] + val) % MOD
            if i + 1 <= 2 * MAX_L:
                if j + 1 <= h:
                    dp[h][i + 1][j + 1] = (dp[h][i + 1][j + 1] + val) % MOD
                if j - 1 >= 0:
                    dp[h][i + 1][j - 1] = (dp[h][i + 1][j - 1] + val) % MOD

t = int(input())
for _ in range(t):
    l, h = map(int, input().split())
    if h > l:
        print(0)
        continue
    if h == 0:
        print(0)
        continue

    ans = (dp[h][2 * l][0] - dp[h - 1][2 * l][0]) % MOD
    print(ans)
```この実装では、最大高さを超えて階層化された DP が構築されます。 各層`h`以前のものを再利用します`h-1`したがって、天井が徐々に増加するパスを効果的に許可します。 最終的な答えは、2 つのレイヤーの差を使用して、正確な最大高さを分離します。 

ここでよくある間違いは、DP が両方の境界条件 (非負の高さと上限) を同時に適用する必要があることを忘れていることです。`h`。 もう 1 つは、「長さの寸法」と「高さの寸法」の更新を混合することです。これにより、パスが中間の高さを複数回再訪問すると、正確性が静かに壊れます。 

## 実用的な例

 インプットを考慮する`l = 2, h = 2`。 0 で開始および終了し、負になることはなく、高さがちょうど 2 に達する、長さ 4 のパスを数えています。有効なパスは、up、up、down、down の 1 つだけです。 

| ステップ | dp高さ0 | dp高さ1 | dp高さ2 |
 | --- | --- | --- | --- |
 | 0 | 1 | 0 | 0 |
 | 1 | 0 | 1 | 0 |
 | 2 | 1 | 0 | 1 |
 | 3 | 0 | 2 | 0 |
 | 4 | 1 | 0 | 1 |

 このことから、`dp_at_most[2][4][0] = 2`、 そして`dp_at_most[1][4][0] = 1`したがって、正確な高さ 2 は次のようになります。`2 - 1 = 1`。 

ここで考えてみましょう`l = 3, h = 2`。 長さ 6 のパスを数えますが、最大値は正確に 2 です。DP には 2 未満にとどまるすべてのパスが含まれ、1 未満にとどまるパスが減算されます。 

これは制約の分離を示しています。DP 層は上限を制御し、減算によって正確な最大値が分離されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    MOD = 10**9 + 7
    MAX_L = 10  # reduced for testing

    dp = [[[0] * (MAX_L + 1) for _ in range(2 * MAX_L + 1)] for _ in range(MAX_L + 1)]
    dp[0][0][0] = 1

    for h in range(1, MAX_L + 1):
        for i in range(2 * MAX_L + 1):
            for j in range(h + 1):
                val = dp[h - 1][i][j]
                if not val:
                    continue
                dp[h][i][j] = (dp[h][i][j] + val) % MOD
                if i + 1 <= 2 * MAX_L:
                    if j + 1 <= h:
                        dp[h][i + 1][j + 1] = (dp[h][i + 1][j + 1] + val) % MOD
                    if j - 1 >= 0:
                        dp[h][i + 1][j - 1] = (dp[h][i + 1][j - 1] + val) % MOD

    def solve_case(l, h):
        if h > l or h == 0:
            return 0
        return (dp[h][2 * l][0] - dp[h - 1][2 * l][0]) % MOD

    out = []
    for line in inp.getvalue().splitlines()[1:]:
        l, h = map(int, line.split())
        out.append(str(solve_case(l, h)))
    return "\n".join(out)

## 特殊なケース

 いつ`h > l`、その高さの DP 層は単純な実装でもまだ存在しますが、長さのパスは存在しません。`2l`有効なまま物理的にその高さに到達することができます。 アルゴリズムは、直ちに 0 を返すことでこれを処理し、不必要な計算を回避します。 

いつ`h = 1`、高さ 1 を決して超えないパスのみが考慮されます。これは、構造が交互の上下パターンに崩壊することを意味します。 DP は、2 つの連続したアップをスタックせずにグラウンドレベルに戻るシーケンスのみを正しくカウントします。 

いつ`l = 1`、有効なパスは「上に上がってから下に」だけです。`h = 1`有効です。 引き算`dp[1] - dp[0]`この単一の構成をきれいに分離し、最大高さによる分解の正確さを確認します。
