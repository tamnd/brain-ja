 ## 解決策
 ## 問題の理解

 正の整数の配列から始めます。 唯一許可される操作は、1 つの要素を選択し、その合計が元の値に等しい 2 つの正の部分に分割することです。 分割するたびに配列の長さが 1 ずつ増加します。 

目標は、可能な限り少ない分割操作を使用しながら、最終的な配列を非減少にすることです。 

操作について考えると便利な方法は、値を繰り返し分割した後、`a`、最終的にはそれをいくつかの正の整数に置き換えますが、その合計は依然として`a`。 値が次のように分割される場合`k`正確に必要な部分`k - 1`操作。 

入力には最大で次のものが含まれます`10^4`すべてのテスト ケースにわたる配列要素の合計数は最大で`2 · 10^5`。 線形または線形演算よりも大幅に遅い解`n`制限内に快適に収まりません。 二次関数の解法には大まかに次のものが必要になります。`4 · 10^10`最悪の場合、1 秒で実行できる処理をはるかに超えます。 

厄介な点は、要素を分割すると、その要素に関係する今後のすべての比較に影響することです。 サイズが非常に大きくなる可能性があるため、最終的な配列は明示的に構築しません。 代わりに、各値をいくつの部分に分割する必要があるかを推論する必要があります。 

簡単な間違いの 1 つは、右側の要素を考慮せずに貪欲に分割することです。 

考慮する：```
3
3 2 1
```答えは`3`。 

局所的な反転だけを修正しようとすると、分裂する可能性があります`3`一度入って`1 + 2`、生産`[1,2,2,1]`、まだ減少していないわけではありません。 分割の効果は、その右側にあるすべてのものによって許可される最大値と比較して判断する必要があります。 

もう 1 つの微妙なケースは、値がすでに十分に小さい場合です。```
2
4 5
```答えは`0`。 

不用意に実装すると、依然として正の数のピースが計算され、不要な操作が追加される可能性があります。 現在の値が最大でも許容限度を超えている場合は、そのままにしておく必要があります。 

3 番目のエッジ ケースは、値が選択した個数で割り切れない場合に発生します。```
2
10 3
```答えは`3`。 

分割`10`3つに分割するとおおよそのサイズが得られます`3.33`, となるので、ワンピースはこうなります。`4`、これはまだより大きいです`3`。 実際には次の 4 つの部分が必要です。`3,3,2,2`。 4 個のピース​​には 3 回の操作が必要なので、答えは次のようになります。`3`。 ここで天井分割ではなく床分割を使用すると、間違った結果が生じます。 

## アプローチ

 ブルートフォースの観点は、配列が減少しなくなるまで明示的に分割を実行することです。 違反している要素ごとに、さまざまな分割方法を試し、再帰的に続行することができます。 すべての有効な操作シーケンスを調査できるため、これは正しいです。 

問題は、可能なパーティションの数が爆発的に増加することです。 次のような単一の値でも、`100`さまざまな方法で分割でき、新しい部分はすべて再度分割できます。 検索空間は、入力制限に達するずっと前に膨大になります。 

重要な観察は、ピースの正確な配置はほとんど無関係であるということです。 重要なのは、分割後に生成される最大の部分です。 

配列を右から左に処理するとします。 右側にあるものはすべてすでに処理されており、そのサフィックスの前に置くことができる最大の値は次のとおりであると想像してください。`mx`。 

現在の値の場合`a[i]`すでにせいぜい`mx`、変更せずにそのままにしておきます。 

それ以外の場合は、結果として得られる各部分が最大でも次の部分になるように、それをいくつかの部分に分割する必要があります。`mx`。 操作の数を最小限に抑えたいため、ピースの数も可能な限り最小限に抑えます。 

に分かれたら`k`ピース、最大のピースは少なくとも`ceil(a[i] / k)`。 せいぜいすべての作品を作るには`mx`、次のものが必要です。$$\left\lceil \frac{a[i]}{k} \right\rceil \le mx$$有効な最小値`k`は：$$k = \left\lceil \frac{a[i]}{mx} \right\rceil$$より少ないピースを使用すると、一部のピースが超過することになります`mx`。 

この最小値を選択すると、`k`、操作数が増加します`k - 1`。 

もう 1 つ詳細があります。 分割後、さらに左にある要素の新しい制限値は何になりますか?

 その中で、`k`ピース、可能な最小のピースは次のとおりです。$$\left\lfloor \frac{a[i]}{k} \right\rfloor$$左側はこのブロックの最初の部分を超えてはいけないため、この最小部分が新しい許容最大値になります。 

これにより、問題は単純な右から左への貪欲スキャンに変換されます。

 ## アルゴリズムのチュートリアル

 1. に対する答えを初期化します。`0`。 
2.セット`mx`配列の最後の要素に。 これは、前の要素が最終的に生成できる最大値です。 
3. インデックスから開始して、配列を右から左に処理します。`n - 2`。 
4. もし`a[i] <= mx`、分割は必要ありません。 アップデート`mx = a[i]`。 

現在の値自体が、それ以降のすべてに対する新しい制限になります。 
5. それ以外の場合は、すべてのピースが最大で次の数になるように、必要なピースの最小数を計算します。`mx`:$$k = \left\lceil \frac{a[i]}{mx} \right\rceil$$6. 分割する`k`ピースが必要です`k - 1`操作。 これを答えに追加してください。 
7. 最適なバランスの取れたパーティションで取得できる最小のピースは次のとおりです。$$\left\lfloor \frac{a[i]}{k} \right\rfloor$$セット：$$mx = \left\lfloor \frac{a[i]}{k} \right\rfloor$$これが残りの要素の新しい制限になります。 
8. すべての要素を処理した後、累積された応答を出力します。 

### なぜ効果があるのか

 すべての位置で、右側の接尾辞によってすでに最大許容値が設定されています`mx`。 有効な最終取り決めは分割する必要があります`a[i]`製造される作品がこの制限を超えないように十分な回数。 

その条件を満たす最小個数は正確に`ceil(a[i] / mx)`。 ピースの数が少ない場合は、少なくとも 1 つのピースが次のサイズよりも大きくなります。`mx`、配列を非降順に並べることができなくなります。 

すべての分割を最小数のピースに分割する際、ピースのバランスをできるだけ均等にすることで、最小のピースが最大化されます。 その最小部分は以下に等しい`floor(a[i] / k)`、これが安全に左側を通過できる最大の制限です。 この制限をできるだけ大きく保つことは、将来の要素で必要な分割を少なくするのに役立ちます。 

各位置は最適なローカル選択で処理され、その選択により残りのプレフィックスに対して最も許容的な状態が残されるため、貪欲な戦略はグローバルに最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))

    ans = 0
    mx = a[-1]

    for i in range(n - 2, -1, -1):
        if a[i] <= mx:
            mx = a[i]
        else:
            k = (a[i] + mx - 1) // mx
            ans += k - 1
            mx = a[i] // k

    print(ans)
```変数`mx`は、既に処理されたサフィックスを壊すことなく、現在位置が生成できる最大値を表します。 

いつ`a[i] <= mx`、値を変更しないままにします。 この値は処理されるサフィックスの最初の要素であるため、それが新しい制限になります。 

いつ`a[i] > mx`、天井分割を使用してピースの最小数を計算します。```
k = (a[i] + mx - 1) // mx
```この式は、次の整数実装です。`ceil(a[i] / mx)`。 

追加された操作の数は、`k - 1`1 つの値を次のように分割するため、`k`ピースには、まさにその数の分割が必要です。 

ついに、```
mx = a[i] // k
```計算する`floor(a[i] / k)`、これは、最適にバランスが取れたパーティションの最小部分です。 この値を使用することが重要です。 最大の部分または平均を使用すると、貪欲な不変条件が破られます。 

Python の整数は、最悪の場合の演算数が超過する可能性があるため、簡単に答えを処理できます。`32-bit`限界。

 ## 特殊なケース

 ### 小さな制限の直前の大きな値

 入力:```
1
2
10 3
```から始める`mx = 3`。 

のために`10`、次のように計算します。$$k=\left\lceil\frac{10}{3}\right\rceil=4$$3つの操作が必要です。 新しい制限は次のようになります。$$\left\lfloor\frac{10}{4}\right\rfloor=2$$アルゴリズムの出力`3`。 

を使用した解決策`10 // 3 = 3`ピースは 3 ピースで十分であると誤って想定しますが、1 つのピースには必ずサイズがあります。`4`。 

### すでに減少していない配列

 入力:```
1
4
1 2 3 4
```スキャンは次のように進行します。```
mx = 4
3 <= 4
2 <= 3
1 <= 2
```分割は実行されず、答えはそのまま残ります`0`。 

これにより、貪欲アルゴリズムが不必要な操作を導入しないことが検証されます。 

### 限界が1になる

 入力:```
1
3
3 2 1
```右端の要素が修正されます`mx = 1`。 

のために`2`、必要です`k = 2`、操作を 1 つ追加します。 

のために`3`、必要です`k = 3`、さらに 2 つの操作を追加します。 

最終的な答えは、`3`。 

このケースは、右から左への処理が自然である理由を示しています。 許容最大値に達すると、`1`、以前の値はすべて 1 に完全に分解する必要があり、アルゴリズムはそれを即座に取得します。
