 ## 解決策
 ## 問題の理解

 この問題では、同じ長さの 2 つの文字列が得られます。 最初の文字列は変更できるもので、2 番目の文字列は最終的に必要な文字のマルチセットを記述します。 最初の文字列内の文字を置換することができます。1 回の置換で、ちょうど 1 つの位置が他の文字に変更されます。 最小限の置換数を使用して最初の文字列をターゲット文字列のアナグラムにするすべての方法の中で、辞書順で最小となる結果の文字列を出力する必要があります。 

入力サイズが大きいため、文字列には最大で次の文字列を含めることができます。$10^5$文字。 これにより、順列の試行、アナグラムの生成、または考えられるすべての変換された文字列の比較が直ちに排除されます。 どのソリューションでも、文字ごとに少量の一定の作業量で文字列を処理する必要があり、これは線形または線形に近い複雑さを示します。 

重要なエッジケースは、「同じ文字」と「同じ位置」の違いから生じます。 たとえば、入力が次の場合:```
ABA
CBA
```答えは次のとおりです。```
1
ABC
```不注意な解決策は、位置ごとに不一致をカウントするだけで、結果が生じる可能性があります。`CBA`1回の交換後。 これでは辞書編集上の要件が満たされません。 最終的な文字列ではターゲット文字を再配置できるため、有用な既存の文字をできるだけ多く保持し、可能な限り最小の配置を選択する必要があります。 

もう 1 つの注意が必要なケースは、文字が重複している場合です。```
AAAA
AAAB
```正しい出力は次のとおりです。```
1
AAAB
```すべての文字を一意のものとして扱うソリューションでは、文字列のいくつかの位置が異なるため、3 つの置換が必要であると考える可能性があります。 正しい方法は周波数を比較することです。 

最後のエッジケースは、文字列がすでにアナグラムである場合です。```
BCA
ABC
```答えは次のとおりです。```
0
ABC
```置換する必要はありませんが、既存の文字を辞書編集上可能な限り最小のアナグラムに並べ替える必要があります。 

## アプローチ

 強引な方法は、ターゲット文字列の可能なアナグラムをすべて試し、ソース文字列と異なる位置の数を確認し、最良の候補を保持することです。 これは、考えられるすべての最終的な取り決めを検討するため、正しいです。 問題は、次の長さの文字列です。$n$まで持つことができます$n!$順列。 たとえ数十文字であってもこれは不可能になります。$10^5$実現可能とは程遠いです。 

より良い方向性は、代替品が実際に何を行うかを検討することで得られます。 元の文字列内の各位置は、その文字を保持することも、変更することもできます。 置換を最小限に抑えるために、できるだけ多くの既存の文字を保持したいと考えています。 これは、両方の文字列に各文字のコピーが何個存在するかを知る必要があるだけであることを意味します。 

ソースに次のコピーが 5 つあると仮定します。`A`ターゲットには 3 つのコピーが必要です。 そのうちの2つ`A`文字は余分なので変更する必要があります。 一方、ターゲットがさらに多くのことを必要としている場合は、`A`ソースにある文字よりも文字数が多い場合は、不足しているコピーを作成するために置換が必要です。 置換の合計数は、頻度によって一致しない文字の数と正確に一致します。 

置換の最小数がわかった後でも、辞書編集上で最小の最終文字列が必要になります。 できるだけ小さい文字をできるだけ早く表示する必要があります。 位置を左から右に貪欲にスキャンできます。 各ポジションで、残りの頻度要件を満たしながら現在のキャラクターを維持できる場合は、それを維持します。 それ以外の場合は、使用可能な最小の文字に置き換えられます。 

この貪欲な選択が機能する理由は、辞書編集上の順序が 2 つの文字列が異なる最初の位置によって決定されるためです。 可能な限り初期のポジションをできるだけ小さくすることで、その後の改善が常に優先されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | お(ん!) | O(n) | 遅すぎる |
 | 最適 | O(26n) | お(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ソース文字列とターゲット文字列内のすべての文字の頻度をカウントします。 アルファベットは固定されているため、サイズ 26 の配列のみが必要です。 
2. ソースから保持できる文字数を計算します。 各文字について、使用可能なコピーの数は、ソースとターゲットでのその頻度の最小値です。 ソースにあるその他のものはすべて、最終的には置き換える必要があります。 
3. ソース文字列を左から右にスキャンします。 回答に含める必要がある残りの文字数を維持します。 現在の位置を見るときは、まず元の文字を維持するようにしてください。 
4. キャラクターの保持は、答えですでに固定されている数よりも多くのそのキャラクターのコピーがターゲット内で利用できる場合にのみ有効です。 キャラクターが不要になった場合は、置き換えてください。 
5. 現在の文字を保持できない場合は、残りのターゲット数が正である最小の文字を選択し、この位置に配置します。 残りの数を減らします。 

機能する理由: アルゴリズムは可能な限り常に文字を保持するため、置換の数が必要以上に大きくなることはありません。 位置を置換することに決めたら、使用可能な最小の文字を選択すると、可能な限り最小のプレフィックスが得られます。 後の位置が考慮される前に、前の位置がすべて最適化されるため、最終的な文字列は、すべての最適な答えの中で辞書編集的に最小になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()
    t = input().strip()

    src = [0] * 26
    need = [0] * 26

    for c in s:
        src[ord(c) - 65] += 1
    for c in t:
        need[ord(c) - 65] += 1

    keep = [min(src[i], need[i]) for i in range(26)]

    ans = []
    remain = need[:]

    for c in s:
        x = ord(c) - 65
        if keep[x] > 0:
            ans.append(c)
            keep[x] -= 1
            remain[x] -= 1
        else:
            for y in range(26):
                if remain[y] > 0:
                    ans.append(chr(y + 65))
                    remain[y] -= 1
                    break

    print(sum(1 for i in range(len(s)) if s[i] != ans[i]))
    print("".join(ans))

if __name__ == "__main__":
    solve()
```最初の部分では度数表を作成します。 大文字は 26 個しかないため、文字を数えるには 1 文字ごとに一定の作業が必要です。 

の`keep`配列には、保持できる各文字のコピーの数が格納されます。 左から右への構築中に、保存されたキャラクターは 1 つの利用可能な保存コピーと 1 つの必要なターゲット コピーを消費します。 

置換ブランチは次から検索します`A`に`Z`。 検索は 26 文字を超えるだけなので、メイン ループ内にネストされているように見えますが、全体の複雑さは線形のままです。 置換カウントは、元の文字列と構築された回答を比較することによって、最後に計算されます。 

境界条件は自然に処理されます。 文字がすでに正しくて必要な場合、その文字は保持されます。 キャラクターのコピーがすべて使用されている場合、そのキャラクターは再度選択されることはありません。 配置するたびに残りのターゲット周波数が減少するため、コピーが多すぎるリスクはありません。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    
    s = sys.stdin.readline().strip()
    t = sys.stdin.readline().strip()

    src = [0] * 26
    need = [0] * 26

    for c in s:
        src[ord(c) - 65] += 1
    for c in t:
        need[ord(c) - 65] += 1

    keep = [min(src[i], need[i]) for i in range(26)]
    remain = need[:]
    ans = []

    for c in s:
        x = ord(c) - 65
        if keep[x] > 0:
            ans.append(c)
            keep[x] -= 1
            remain[x] -= 1
        else:
            for y in range(26):
                if remain[y] > 0:
                    ans.append(chr(y + 65))
                    remain[y] -= 1
                    break

    out = str(sum(1 for i in range(len(s)) if s[i] != ans[i])) + "\n" + "".join(ans) + "\n"
    sys.stdin = old
    return out

assert run("AAAA\nAAAB\n") == "1\nAAAB\n", "duplicates"

 ## 特殊なケース

 この場合の場合:```
ABA
CBA
```アルゴリズムは維持します`A`そして`B`ターゲットが必要としているからです。 最後の位置では、残りのターゲット周波数には次の値のみが含まれます。`C`, そのため、交換が強制されます。 結果は可能な限り最小限の変更数を持ち、辞書編集的に最小になります。 

のために：```
AAAA
AAAB
```ソースが多すぎる`A`文字。 最初の 3 つの位置はそのままで構いません`A`、しかし最後のおまけ。`A`にならなければなりません`B`。 周波数配列により、ターゲットを満たすことが不可能になる特性をアルゴリズムが維持することが防止されます。 

のために：```
BCA
ABC
```すべての文字が必要な量だけすでに存在します。 置換は実行されず、貪欲な構造により、可能な限り最小の順序を生成しながら、使用可能な文字が維持されます。 最終的な答えはこうなります`ABC`操作はゼロです。
