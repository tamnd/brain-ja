 ## 解決策
 ## 問題の理解

 それぞれが整数値を保持する一連のハウスがあります。 正確に使用して、すべての家の間に接続されたネットワークを構築する必要があります`n - 1`つまり、最終的な構造はスパニング ツリーになります。 

アリスは、2 つの家の間にある考えられるすべての橋に、2 つの数字の最大公約数に等しい値を割り当てます。 彼女の目標は、ブリッジ値の合計が可能な限り最大のスパニング ツリーを選択することです。 

ボブは別のスコアを使用します。 ブリッジの値は、2 つの数値の 2 乗の gcd、つまり元の gcd の 2 乗です。 彼は、最も弱い橋ができるだけ強いスパニング ツリーを望んでいます。 言い換えれば、彼は選択したツリーの最小エッジ値を最大化したいと考えています。 

入力すると各家の番号が得られます。 出力では、アリスの最大合計スコアとボブの最大可能最小スコアが求められます。 

到達できる家の数`200000`、値は次のように大きくできます。`1000000`。 ハウスのすべてのペアに対する二次アプローチには、次のものが必要になります。`4 * 10^10`比較、それは不可能です。 考えられるすべてのブリッジを生成するだけでもコストがかかりすぎるため、解決策は gcd が可分性のみに依存するという事実を利用する必要があります。 最大値の範囲は、`10^6`は、約数と倍数を反復することが意図された方向であることを示唆しています。 

いくつかのケースでは、誤って対処されやすいものがあります。 すべての数値が等しい場合、すべてのブリッジは同じ gcd を持ち、答えにはその値が使用されるはずです。 たとえば、入力`3`価値観を持って`5 5 5`出力を与える`10 25`アリスには 2 つの重みがあるからです`5`そしてボブはすべてのエッジに価値を持たせることができます`25`。 異なる値を持つペアのみを検索する不注意な実装は、ここで失敗する可能性があります。 

もう 1 つの注意が必要なケースは、小さなグループだけが大きな要素を共有する場合です。 入力用`4`価値観を持って`6 10 15 7`、最高のアリスツリーは gcd を使用できません`5`または`3`すべてのエッジの頂点であるため、`7`そのグループから切断されています。 答えは`3 1`。 任意のペアに現れる最大公約数を単純に選択する方法では、結果が誤って過大評価されてしまいます。 

最後のエッジケースは、最適なボトルネック値が以下の場合です。`1`。 入力用`3`価値観を持って`2 3 5`、すべてのペアに gcd があります。`1`、したがって、ボブの答えは次のとおりです。`1`。 繰り返される素因数だけを見ると、gcd を介して接続されたツリーが常に存在することを見逃してしまいます。`1`。 

## アプローチ

 アリスの部分を解決する強引な方法は、問題を最大スパニング ツリー問題として扱うことです。 すべての家のペアが gcd で重み付けされたエッジを持つ完全なグラフを作成し、クラスカルのアルゴリズムを降順で実行できます。 これは正しいです。クラスカルのアルゴリズムでは、エッジが大きいものから小さいものへと処理されるときに常に最大スパニング ツリーが検出されるからです。 

問題はグラフ自体です。 がある`n * (n - 1) / 2`可能なエッジ。 と`n = 200000`、これは約 200 億エッジです。 それらを計算して並べ替えるのは、利用可能な時間をはるかに超えています。 

重要な観察は、gcd 値が`d`すべてが次の数で割り切れる数の間でのみ出現します。`d`。 どのペアが gcd を持つかを尋ねる代わりに`d`、どの家が の倍数であるかを尋ねることができます。`d`。 大きい値から小さい値まで処理する際、少なくとも現在の値の gcd を持つすべてのブリッジがすでに考慮されています。 現在の除数のすべての倍数を接続すると、明示的に作成せずに、この重みのすべてのエッジを追加することをシミュレートします。 

固定除数の場合`d`、で割り切れるすべての家`d`グループを形成します。 それらすべてを 1 つの代表に接続すると、成功した結合はすべて重み付きの 1 つのクラスカル エッジに対応します。`d`。 成功した結合の数は、この重みで追加されたエッジの数と正確に一致します。 

ボブの問題では、二乗によって順序が維持されるため、同じ順序が使用されます。 より大きな gcd を持つブリッジは、常により大きな 2 乗 gcd を持ちます。 同じ降順プロセス中に、グラフ全体を接続する最初の約数は、考えられる最大の最小 gcd です。 その値を二乗すると、ボブの答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n² log n²) | O(n²) | 遅すぎる |
 | 最適 | O(A log A + n * 除数の数(A)) | O(A + n) | 承認済み |

 ここ`A`は可能な最大値です、`1000000`この問題では。 

## アルゴリズムのチュートリアル

 1. 各値が出現する回数を数え、各値を持つ住宅のインデックスを保存します。 ユニオン検索構造は値ではなくハウスに対して機能するため、実際のインデックスが必要です。 
2. すべての約数を処理する`d`から`1000000`まで`1`。 の倍数ごとに`d`、値がその倍数に等しいすべての家を訪問します。 これらのハウスはすべて、gcd が少なくとも次のエッジによって接続されています。`d`。 
3. 訪問した家の中から代表的な家を 1 つ選択し、他の訪問した家をすべてそれと結合します。 結合が成功するたびに、価値の橋が 1 つ追加されたことを意味します`d`Kruskal のプロセスにあるので、追加します`d`アリスの答えに。 
4. 除数のすべての結合が完了したら、すべてのハウスが 1 つのコンポーネント内にあるかどうかを確認します。 これが起こる最初の約数は、ボブの最大可能最小 gcd です。 その正方形を保存します。 
5. アリスの累積値とボブの保存値を出力します。 

アルゴリズムの背後にある不変条件は、除数を処理する前の不変条件です。`d`、union find 構造は、gcd が より大きいすべてのブリッジによって作成された接続を正確に表します。`d`。 すべての倍数をマージすると、`d`、gcd を持つことができるすべての可能な接続を追加します。`d`。 これはクラスカルの順序と一致するため、成功したすべてのマージは最大スパニング ツリー内の選択された 1 つのエッジにのみ寄与します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    MAXV = max(a)

    buckets = [[] for _ in range(MAXV + 1)]
    for i, x in enumerate(a):
        buckets[x].append(i)

    parent = list(range(n))
    size = [1] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x

    components = n

    def union(x, y):
        nonlocal components
        x = find(x)
        y = find(y)
        if x == y:
            return False
        if size[x] < size[y]:
            x, y = y, x
        parent[y] = x
        size[x] += size[y]
        components -= 1
        return True

    ans_a = 0
    ans_b = 1

    for d in range(MAXV, 0, -1):
        rep = -1
        for m in range(d, MAXV + 1, d):
            for v in buckets[m]:
                if rep == -1:
                    rep = v
                else:
                    if union(rep, v):
                        ans_a += d
        if components == 1:
            ans_b = d * d
            break

    print(ans_a, ans_b)

if __name__ == "__main__":
    solve()
```バケット配列は、値に基づいて家をグループ化します。 これにより、除数をチェックするときにすべてのハウスを繰り返しスキャンする必要がなくなります。 合計訪問数は各値の約数に関連しており、最大 100 万の値まで管理可能です。 

結合検索操作は、Kruskal シミュレーションの中核です。 サイズによるパスの圧縮と結合により、各操作の時間をほぼ一定に保ちます。 変数`components`グラフが接続されるとすぐにボブの答えを検出できるようにします。 

最大スパニング ツリーでは最初に大きなエッジの重みを処理する必要があるため、ループは下方向に進みます。 それが上向きに上昇した場合、より小さい gcd 値がすでにコンポーネントを接続しており、アリスの答えへの寄与が間違っていることになります。 

Bob の値は次のように保存されます。`d * d`なぜなら、ブリッジスコアは二乗の gcd であり、元の gcd の二乗に等しいからです。

            x = parent[x]
        return x

        nonlocal components
        x = find(x)
        y = find(y)
        if x == y:
            return False
        if size[x] < size[y]:
            x, y = y, x
        parent[y] = x
        size[x] += size[y]
