 ## 解決策
 ## 問題の理解

 この問題では、パンチ タイミングのすべての連続セグメントを調べて、その平均タイミングが許容範囲内にあるかどうかを判断するように求められます。 配列には各試行の記録されたタイミングが含まれており、平均値が少なくとも次の空ではない連続グループの総数が必要です。`a`そしてせいぜい`b`。 

制約によって主な課題が明確になります。 まであります`2 * 10^5`したがって、すべてのセグメントを直接チェックすることは不可能です。 くらいあります`n^2 / 2`おおよそ到達する連続セグメント`2 * 10^10`いつ`n`大きいです。 二次アルゴリズムでは制限時間内に収まりません。 に近い解決策が必要です`O(n log n)`なぜなら、この入力サイズでは数百万回の演算しか行われないからです。 

難しい部分は平均値から来ます。 部分平均を持つセグメントでも条件を満たす可能性があるため、整数の合計を直接比較するだけでは十分ではありません。 たとえば、セグメント`[3, 4]`平均的です`3.5`。 許容範囲が次の場合`[3, 4]`、答えにはそれが含まれている必要があります。 整数演算を使用して除算するソリューションでは、平均が誤って次のように扱われる可能性があります。`3`。 

もう 1 つの特殊なケースは、平均がちょうど境界上にある場合です。 入力の場合:```
3 5 5
5 5 4
```正しい出力は`3`、有効なセグメントは次のとおりです。`[5]`、`[5]`、 そして`[5,5]`。 等価性を許可する代わりに厳密な比較を使用するソリューションでは、これらのケースが見逃されます。 

2 番目の境界問題が上側に表示されます。 入力の場合:```
2 1 3
1 3
```セグメント`[1,3]`平均的です`2`したがって、それは有効であり、答えは次のとおりです。`3`。 上限は「より大きい」ものとして扱う必要があります。`b`は無効です。「以上」ではありません`b`無効です。」

 ## アプローチ

 直接的なアプローチは、すべての開始位置と終了位置を列挙し、そのセグメントの合計を計算し、その長さで割って、平均が区間に属するかどうかを確認することです。 プレフィックス合計により、セグメント合計を見つけるコストが削減されます。`O(1)`、しかしまだあります`O(n^2)`セグメント。 最悪の場合、`n = 200000`、これは約 200 億小切手を意味し、利用可能な時間をはるかに超えています。 

有益な観察は、平均条件は除算なしで書き換えられるということです。 値を含むセグメントの場合`x1, x2, ..., xk`、条件```
(x1 + x2 + ... + xk) / k >= c
```と同等です```
(x1 - c) + (x2 - c) + ... + (xk - c) >= 0
```ここで問題は、変換された合計が負ではない部分配列をカウントすることになります。 

必要な間隔を 2 つの単純なカウントに分割できます。```
average in [a, b]
=
average >= a
-
average > b
```最初のカウントでは変換を使用します。`x[i] - a`そして、合計が少なくともゼロである部分配列を要求します。 2番目の用途`x[i] - b`そして、合計が厳密にゼロより大きいサブ配列を要求します。 

どちらのバージョンでも、`pref[i]`は、変換された配列の接頭辞の合計になります。 サブアレイ`(l, r]`次の場合に合計が有効になります。```
pref[r] - pref[l] >= 0
```つまり:```
pref[r] >= pref[l]
```したがって、配列を左から右にスキャンしているときに、現在のプレフィックスの合計以下である以前のプレフィックスの合計がいくつあるかを知る必要があるだけです。 これは注文統計の計数問題です。 座標圧縮とフェンウィック ツリーを使用すると、これらのカウントを維持できます。`O(log n)`プレフィックスあたりの時間。 

ブルートフォース手法は、必要な条件を正確にチェックするため機能しますが、セグメントが多すぎるため、ほぼ同じ作業を繰り返すため失敗します。 プレフィックス合計変換により、セグメントを個別に検査する必要がなくなり、フェンウィック ツリーはすべての有効なプレフィックス ペアを効率的にカウントします。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 選択した値以上の平均を持つ部分配列の数をカウントするヘルパー関数を定義します。`c`。 減算`c`すべての要素から、変換された合計が負ではないサブ配列をカウントします。 これにより、平均比較がプレフィックス比較問題に変換されます。 
2. 変換されたプレフィックスの合計を構築します。 プレフィックス合計から開始`0`配列が始まる前に。 新しい接頭辞はそれぞれ、これまでに処理された要素の合計変換値を表します。 
3. すべてのプレフィックス合計を座標圧縮します。 プレフィックスの合計は負の値になる場合や大きくなる場合があるため、圧縮によりフェンウィック ツリーは実際の値ではなく相対的な順序を保存できます。 
4. プレフィックスの合計を左から右にスキャンします。 現在のプレフィックスの場合`p`、満たす以前のプレフィックスの数を数えます`previous <= p`。 このようなペアはすべて、変換された合計が少なくとも 0 である部分配列を作成します。 カウントを答えに追加して挿入します`p`フェンウィックの木の中へ。 
5. 平均が次より大きいサブ配列の数を計算します。`b`。 これはほぼ同じプロセスですが、必要な点が異なります。`previous < p`変換された合計は厳密に正でなければならないためです。 
6. 最初のカウントから 2 番目のカウントを減算します。 残りのセグメントは、平均が次の範囲内にあるセグメントです。`a`そして`b`。 

このアルゴリズムの背後にある不変条件は、プレフィックスを処理した後、フェンウィック ツリーには以前のすべてのプレフィックスの合計とその頻度が正確に含まれるということです。 現在の位置で終わるすべての可能なサブ配列は、1 つ前のプレフィックスに対応します。 ツリー クエリは、現在のセグメントが変換された不等式を満たすプレフィックスを正確にカウントするため、有効なセグメントはすべて 1 回カウントされ、無効なセグメントはすべて除外されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        res = 0
        while i:
            res += self.bit[i]
            i -= i & -i
        return res

def count_average_condition(arr, c, strict):
    pref = [0]
    cur = 0
    for x in arr:
        cur += x - c
        pref.append(cur)

    vals = sorted(set(pref))
    index = {v: i + 1 for i, v in enumerate(vals)}

    fw = Fenwick(len(vals))
    ans = 0

    fw.add(index[0], 1)

    for i in range(1, len(pref)):
        pos = index[pref[i]]
        if strict:
            ans += fw.sum(pos - 1)
        else:
            ans += fw.sum(pos)
        fw.add(pos, 1)

    return ans

def solve():
    n, a, b = map(int, input().split())
    arr = list(map(int, input().split()))

    at_least_a = count_average_condition(arr, a, False)
    greater_than_b = count_average_condition(arr, b, True)

    print(at_least_a - greater_than_b)

if __name__ == "__main__":
    solve()
```フェンウィック ツリーには、プレフィックス合計の値ではなく頻度が格納されます。 の`add`この操作は、カウントに使用された後に現在のプレフィックスを挿入し、空のセグメントが誤ってカウントされるのを防ぎます。 

最初の電話は`count_average_condition`等価性が許可されるため、現在のプレフィックス以下の値を持つ以前のプレフィックスの数をクエリします。 2 番目の呼び出しでは、厳密に正に変換された合計が必要なため、厳密に小さい以前のプレフィックスのみがカウントされます。 

Python の整数は、潜在的に大きな答えを自動的に処理します。 答えはサブ配列の数と同じくらい大きくなります。`n * (n + 1) / 2`、これは 32 ビット整数よりもはるかに大きくなります。

## テストケース```python
import sys
import io

def solve_case(inp):
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    class Fenwick:
        def __init__(self, n):
            self.n = n
            self.bit = [0] * (n + 1)

        def add(self, i, v):
            while i <= self.n:
                self.bit[i] += v
                i += i & -i

        def sum(self, i):
            r = 0
            while i:
                r += self.bit[i]
                i -= i & -i
            return r

    def count(arr, c, strict):
        p = [0]
        s = 0
        for x in arr:
            s += x - c
            p.append(s)

        vals = sorted(set(p))
        mp = {x: i + 1 for i, x in enumerate(vals)}
        fw = Fenwick(len(vals))
        fw.add(mp[0], 1)
        ans = 0

        for x in p[1:]:
            pos = mp[x]
            ans += fw.sum(pos - 1 if strict else pos)
            fw.add(pos, 1)

        return ans

    n, a, b = map(int, input().split())
    arr = list(map(int, input().split()))
    return str(count(arr, a, False) - count(arr, b, True)) + "\n"

 ## 特殊なケース

 正確な境界の場合:```
3 5 5
5 5 4
```の変換された値`c = 5`は`0, 0, -1`。 プレフィックスの合計は次のようになります。`0, 0, 0, -1`。 等しいプレフィックス合計は最初のパスでカウントされるため、`[5]`、`[5]`、 そして`[5,5]`が含まれています。 厳密な 2 番目のパスでは、平均を上回るセグメントのみが削除されます。`5`、どれもありません。 

部分平均の場合:```
2 1 3
1 3
```セグメント全体に合計がある`4`そして長さ`2`、平均を与える`2`。 変換された配列`c = 1`は`[0, 2]`, そのため、プレフィックスの比較ではセグメント全体が有効であると認識されます。 上限パス`c = 3`変換された合計が負であるため、削除されません。 

すべての値が等しい場合:```
5 10 10
10 10 10 10 10
```考えられるすべての部分配列には平均値があります`10`。 最初のパスがすべてを意味する`15`サブ配列の平均値を超えるセグメントがないため、2 番目のパスのカウントはゼロになります。`10`。 最終的な答えは残っています`15`これにより、等価性が正しく処理されることが確認されます。
