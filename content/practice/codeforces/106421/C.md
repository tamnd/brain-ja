 ## 解決策
 ## 問題の理解

 注文したレーサーチームが 2 つあります。 各チームには威信レベルのリストがあり、各チーム内の元の順序を維持しながら、両方のリストからレーサーを選択して単一のチームを構築する必要があります。 出力は、マージされたプレステージ シーケンスそのものではなく、それを作成する選択肢です。各キャラクターは、次のレーサーがチーム A から来るのか、チーム B から来るのかを示します。 

目標は、結果として得られるプレステージ シーケンスを辞書編集的に最小にすることです。 プレステージ番号が小さいほど名声のあるレーサーであることを意味するため、シーケンスはできるだけ早く小さい番号を付けるほど良いと考えられます。 

簡単バージョンには、`k = n + m`、そしてすべてのレーサーには独自の名声レベルがあります。 この一意性が重要な制約です。 レーサーの総数は次のようになります。`400000`したがって、残りのレーサーを繰り返しスキャンしたり、可能なすべてのインターリーブを試みたりするアルゴリズムでは、実行する操作が多すぎます。 各レーサーが一定の回数だけ処理される線形ソリューションが必要です。 

よくある間違いは、現在の選択ではなく将来の立場について考えることです。 たとえば、次のことを考えてみましょう。```
n = 2, m = 2
A = [1, 4]
B = [2, 3]
```正しい出力は次のとおりです。```
AABB
```マージされたシーケンスは次のようになるため、`[1,2,3,4]`。 B に 2 つの小さな値が残っていることがわかり、B から選択する戦略は、最初の要素が次の要素になるため、すでに負けてしまいます。`2`の代わりに`1`。 

もう 1 つのエッジ ケースは、1 つのチームがレーサーを使い果たした場合です。```
n = 2, m = 1
A = [2, 3]
B = [1]
```正しい出力は次のとおりです。```
BAA
```を摂取した後、`1`チームBからはチームAだけが残ります。 両方の現在位置が常に存在すると仮定する不注意な実装は、無効なインデックスにアクセスしたり、残りのレーサーの追加に失敗したりする可能性があります。 

最後の重要なケースはすでに制約によって処理されていますが、簡単なバージョンの方が単純である理由が説明されています。```
n = 2, m = 2
A = [1, 2]
B = [1, 3]
```プレステージ レベルの重複が許可されている場合、現在のレーサーのみを比較すると、値が等しい場合に残りのサフィックスをより詳しく調べる必要があるため、常に正しく決定できるとは限りません。 簡易バージョンでは、すべての名声レベルが 1 回だけ表示されるため、この問題は解決されます。 

## アプローチ

 ブルートフォースアプローチは、2 つのチームの可能なすべての有効なインターリーブを生成し、その結果として得られるプレステージ シーケンスを計算し、辞書編集的に最小のものを保持することです。 これは、考えられるすべての答えを直接チェックするため、正解です。 ただし、インターリーブの数は膨大です。 どちらを選択するか`n`チームAに所属するポジション`n+m`ポジションが与える`C(n+m,n)`可能性。 たとえ数十人のレーサーであっても、これは不可能であり、何十万人ものレーサーの場合、それは到底実現可能ではありません。 

簡易バージョンの構造は、はるかに単純なアプローチを提供します。 どの時点でも、合併後のチームの次のレーサーは、チーム A の現在のレーサーかチーム B の現在のレーサーのいずれかでなければなりません。すべての名声レベルは異なるため、これら 2 つの値が等しくなることはありません。 考えられる 2 つの答えが異なる最初の位置によって、どのシーケンスが辞書編集的に小さいかが決まるため、小さい方を選択する必要があります。 

ブルートフォース手法は、すべての選択肢を探索するため機能しますが、選択肢の空間が指数関数的に増大するため失敗します。 最初の異なる位置が比較を完全に決定するという観察により、各決定を貪欲に行い、より悪い選択をすべて即座に破棄することができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(C(n+m,n) * (n+m)) | O(n+m) | 遅すぎる |
 | 最適 | O(n+m) | 出力以外の O(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 2 つのポインターを保持します。1 つはチーム A の次の未使用のレーサーを指し、もう 1 つはチーム B の次の未使用のレーサーを指します。 
2. 両チームにまだレーサーがいる間に、現在の 2 つの名声レベルを比較します。 追加`A`チーム A のレーサーの値が小さい場合、それ以外の場合は追加`B`。 これにより、可能な限り最小のレーサーが最も早い未決定の位置に配置されます。 
3. 一方のチームにレーサーが残っていない場合、もう一方のチームの残りの選択肢を追加します。 残りのレーサー全員が出場しなければならないため、もはや決定を下す必要はありません。 
4. 構築されたシーケンスを出力します。`A`そして`B`文字。 

それが機能する理由: 答えのどの位置でも、次の要素として考えられるのは現在のレーサー 2 人だけです。 大きい方を選択すると、代替シーケンスはその正確な位置ですぐに小さい値を持つことになるため、辞書編集的に最小値を選択することはできません。 すべての選択によって両方のチームの元の順序が維持されるため、利用可能な最小の選択を繰り返し行うと、世界的に最小の有効なマージが生成されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    i = 0
    j = 0
    ans = []

    while i < n and j < m:
        if a[i] < b[j]:
            ans.append('A')
            i += 1
        else:
            ans.append('B')
            j += 1

    while i < n:
        ans.append('A')
        i += 1

    while j < m:
        ans.append('B')
        j += 1

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```コードは貪欲なプロセスに直接続きます。 変数`i`そして`j`常に、それぞれのチームの次に未使用のレーサーを指します。 最初のループは、両方の選択肢が利用できる唯一の興味深いケースを処理します。 

2 番目と 3 番目のループは、一方の側が使い果たされると実行する比較がなくなるため、分離されます。 これにより、アクセス試行による境界エラーも回避されます。`a[i]`または`b[j]`リストの最後に到達した後。 

の値`k`入力形式に属しているため読み込まれますが、簡易バージョンでは必要ありません。 という事実`k = n + m`すべてのプレステージ値が一意であることを保証します。これはまさに貪欲比較で使用されるプロパティです。 

## 実用的な例

 次のことを考慮してください。```
3 2 5
1 4 5
2 3
```トレースは次のとおりです。 

| ステップ | チームAのポインタ | チーム B ポインタ | 現在のA | 現在のB | 選択 | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 1 | 2 | あ | あ |
 | 2 | 1 | 0 | 4 | 2 | B | AB |
 | 3 | 1 | 1 | 4 | 3 | B | ＡＢＢ |
 | 4 | 1 | 2 | 4 | なし | あ | アバ |
 | 5 | 2 | 2 | 5 | なし | あ | アバア |

 結果は`ABBAA`、マージされたプレステージ シーケンスを作成します`[1,2,3,4,5]`。 これは、片側が空になると、残りの答えが強制されることを示しています。 

別の例:```
2 3 5
2 5
1 3 4
```トレースは次のとおりです。 

| ステップ | チームAのポインタ | チーム B ポインタ | 現在のA | 現在のB | 選択 | 答え |
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 0 | 0 | 2 | 1 | B | B |
 | 2 | 0 | 1 | 2 | 3 | あ | BA |
 | 3 | 1 | 1 | 5 | 3 | B | バブ |
 | 4 | 1 | 2 | 5 | 4 | B | バブ |
 | 5 | 1 | 3 | 5 | なし | あ | ババ |

 出力は`BABBA`。 アルゴリズムは常に、現在利用可能な最小のプレステージ レベルを選択し、`[1,2,3,4,5]`。

import io

    sys.stdout = out

    input = sys.stdin.readline

    n, m, k = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    i = 0
    j = 0
    ans = []

    while i < n and j < m:
        if a[i] < b[j]:
            ans.append('A')
            i += 1
        else:
            ans.append('B')
            j += 1

    while i < n:
        ans.append('A')
        i += 1

    while j < m:
        ans.append('B')
        j += 1

    print(''.join(ans))

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return out.getvalue()

 ## 特殊なケース

 最初のエッジケースの場合:```
2 2 4
1 4
2 3
```アルゴリズムは比較します`1`そして`2`、選択します`A`、比較します`4`そして`2`、選択します`B`、比較します`4`そして`3`、選択します`B`、最後に残りを追加します`A`。 出力は`ABBA`。 貪欲な決断は正しい、なぜなら選択するからです`B`まず、マージされたシーケンスが次で始まるようにします。`2`、最初よりも悪いです`1`。 

疲弊したチームの場合:```
2 1 3
2 3
1
```最初の比較で選択するのは、`B`なぜなら`1`よりも小さいです`2`。 チーム B は空になるため、アルゴリズムによって残りの 2 人のチーム A レーサーが追加されます。 出力は`BAA`、マージされたシーケンスは`[1,2,3]`。 

より難しいバージョンで発生する重複値の状況については、次のようになります。```
2 2 3
1 2
1 3
```どちらの選択肢も次で始まるため、現在の値のみを比較するだけでは十分ではありません。`1`。 簡易バージョンでは、すべての値が一意であるため、現在の比較だけで正しい決定を決定できるため、この曖昧さが回避されます。
