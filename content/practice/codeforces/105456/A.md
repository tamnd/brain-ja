 ## 解決策
 ## 問題の理解

 3 つの文字のカウント、つまり、文字 A、B、および C を何回使用する必要があるかが与えられます。各テスト ケースのタスクは、文字列が前方でも後方でも同じように読めるように、正確にこれらの文字を使用して文字列を構築することです。また、すべての有効な文字列の中で、辞書順で最小のものを出力する必要があります。 すべての文字を使用して回文を作成できない場合、答えは「ROP」です。 

回文には、対称的な位置にある文字が一致する必要があるという、厳密な構造上の制約が課されます。 これは、周波数分布が任意ではないことを直ちに意味します。 回文の中心文字はミラーリングされたパートナーなしで最大 1 文字であるため、最大 1 つの文字タイプは奇数回出現できます。 

制約は十分に小さいため、各テスト ケースはアルファベット サイズに関して一定または線形の作業のみを必要とします。 テスト ケースごとの合計文字数は最大 3000 で、最大 1000 のテスト ケースがあるため、文字列を直接構築するアプローチはどれも簡単に十分に高速です。 すべての順列を試したり、階乗形式の構築を実行したりすることはできません。 

一般的な障害モードは、パリティを無視することです。 たとえば、最初に実現可能性を確認せずに貪欲に回文を構築しようとすると、一貫してミラーリングできない文字列の半分を構築してしまう可能性があります。 

2 番目の微妙なエッジ ケースは、複数の奇数カウントが存在する場合に発生します。 たとえば、1 1 1 のような入力には 3 つの奇数のカウントがあります。 複数の奇妙な文字を中央に配置する方法はないため、解決策はありません。 

## アプローチ

 強引な解釈では、複数の文字セットのすべての順列を生成し、回文であるものをフィルタリングして、辞書編集的に最小のものを選択します。 これは概念的には簡単です。A、B、C のすべての配置を指定された数で列挙し、それが回文であるかどうかを確認し、最小の辞書編集結果を追跡します。 

問題は組み合わせ爆発です。 全長が N の場合、個別の順列の数は N です。 繰り返された階乗で除算されます。 30 のような中程度の N であっても、これは完全に不可能になります。 回文チェックは O(N) であるため、全体の複雑さは階乗スケールになります。 

重要な観察は、回文はその前半と、場合によっては中間の文字によって完全に決定されるということです。 左半分に各文字が何個入るかを決定したら、右半分が強制されます。 これにより、問題は順列検索から制約付き計数問題に変わります。 

残りの数が正しく反映されるように、左側に A、B、C の数を入れるだけを決定する必要があります。 つまり、各文字について、両側で使用される数字は偶数でなければならず、残った奇数文字 (最大 1 種類) は中央に配置されます。 左半分を構築した後、最小文字から最大文字まで貪欲に埋めていくことで、辞書編集上の最小性が達成されます。

 ## アルゴリズムのチュートリアル

 私たちは問題を、回文の実現可能性を判断し、次に最小の辞書式回文を構築することに帰着します。

1. A、B、C のうち奇数がいくつあるか数えます。 複数のカウントが奇数である場合、回文は存在できません。 これは、どの回文にも対になっていない中間文字が 1 つしか含まれていないためです。 
2. 中央の文字が存在する場合は、それを特定します。 カウントの 1 つだけが奇数の場合、その文字が回文の中心になります。 
3. すべてのカウントを 2 で割ってハーフカウントに変換します。 これらは、回文の左側に各文字が何個表示されるかを表します。 
4. 文字を辞書編集順に配置して、回文の左半分を構築します。常に利用可能なすべての A を最初に使用し、次に B、次に C を使用します。この貪欲な順序により、前の位置が辞書編集上の比較に優先するため、文字列全体が辞書編集上最小になります。 
5. 最終的な答えを、左半分 + 中央 (ある場合) + 反転した左半分として作成します。 

正確さは、半分のカウントが固定されると、左半分内の順序が回文全体の辞書編集順序を直接決定するという事実にかかっています。 

### なぜ効果があるのか

 有効な回文は、その左半分とオプションの中央文字によって一意に決定されます。 実現可能性制約はパリティのみを制限し、順序は制限しません。 辞書編集的な比較は左から右に決定されるため、アルファベット順に左半分を貪欲に最小化することで、可能な限り最小の完全な文字列が保証されます。 この順序は対称性によって完全に決定されるため、右半分を再配置してもこの順序を変更することはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    out = []
    
    for _ in range(t):
        a, b, c = map(int, input().split())
        counts = [a, b, c]
        letters = ['A', 'B', 'C']
        
        odd = sum(x % 2 for x in counts)
        if odd > 1:
            out.append("ROP")
            continue
        
        mid = ""
        for i in range(3):
            if counts[i] % 2 == 1:
                mid = letters[i]
                counts[i] -= 1
                break
        
        half = [counts[i] // 2 for i in range(3)]
        
        left = []
        for i in range(3):
            left.append(letters[i] * half[i])
        
        left = "".join(left)
        right = left[::-1]
        
        out.append(left + mid + right)
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```このソリューションでは、まずパリティを使用して回文が構造的に可能かどうかを検証します。 次に、必要な場合にのみ中間文字を割り当て、奇数カウントが 1 つだけ減らされるようにします。 ハーフカウントは強制的な対称性を表し、固定された辞書編集順で左側を構築することで最小性が保証されます。 最後にミラーリングを行うことで回文が完成します。 

微妙な点は、半分にする前に奇数の数から 1 を引くことです。 これにより、中心の文字が対称性を妨げないようになります。 もう 1 つの重要な詳細は、半分の順序が固定されるとすべての選択肢が独立するため、辞書編集的な最適性ではバックトラッキングが必要ないことです。

 ## 特殊なケース

 入力用`0 0 5`、アルゴリズムは 1 つの奇数カウント (C) を検出し、それを中心に割り当て、それを 4 に減らし、ハーフ カウント (0、0、2) を構築します。 左半分が「CC」となり「CCCCC」となります。 これにより、純粋な単一文字の優位性が正しく処理されることが確認されます。 

入力用`1 1 1`、3 つのカウントはすべて奇数であるため、アルゴリズムは構築を試みる前にすぐに「ROP」を返します。 これは、実現可能性チェックによって誤った強制配置が防止されることを示しています。 

入力用`2 0 3`の場合、アルゴリズムは C を中央に割り当て、バランスのとれた半分を残します。 「AC + C + CA」という構造は、対称性と辞書編集上の正確さを同時に確認します。
