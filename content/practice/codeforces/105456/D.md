 ## 解決策
 ## 問題の理解

 私たちは k 次元の整数格子で作業しています。 状態は k 個の整数座標を持つ点であり、各移動は +1 または -1 だけ 1 つの座標を変更します。 2n 回移動した後、異なる一連の移動によって原点に戻る回数を数えたいと思います。 

これについて考えると便利な方法は、すべての移動が k 軸の 1 つを選択し、その軸に沿った方向を選択するということです。 最終的にすべての座標の合計変位が 0 になる場合、パスは有効です。つまり、すべての軸が -1 の移動と同じ数の +1 の移動を受け取ります。 

入力により、複数の独立したクエリが得られます。 各クエリは、原点に戻る k 次元での長さ 2n ウォークの数 (モジュロ 998244353) を求めます。 

この制約により、位置に関する状態空間動的計画法から遠ざけられます。 可能な位置の数は各座標で際限なく増加し、i ステップ後の到達可能な位置に制限しても、層ごとに Θ(i^k) 状態が得られます。 n が最大 10^5、t が最大 200000 である場合、テスト ケースごとに n にわたって反復したり、k 次元の状態にわたって DP を維持したりするアプローチは遅すぎます。 

次元を独立して推論する場合、微妙な問題が発生します。 単純なアプローチでは、各座標を長さ 2n の独立した 1D ウォークとして扱い、結果を乗算する可能性がありますが、これは各ステップで 1 つの座標のみが選択されることを無視しています。 次元間の結合が問題の核心です。 

## アプローチ

 ブルートフォース視点から始めます。2n ステップのそれぞれで、k 座標の 1 つを選択し、それをインクリメントするかデクリメントするかを決定します。 これにより、合計 (2k)^{2n} 個のシーケンスが得られます。 原点で終わるものをフィルタリングします。 

この強引な方法は正しいですが、完全に実行不可能です。 n = 20 であっても、すでに天文学的に大きな分岐が得られます。 

重要な構造的観察は、問題が 2 つの選択肢の層に分かれているということです。 

まず、すべてのステップで各座標が何回使用されるかを決定します。 座標 i が ti 回選択され、合計 ti = 2n であると仮定します。 各軸は 1D ウォークのように動作し、+ と - の動きのバランスを取る必要があるため、すべての ti が偶数であるシーケンスのみが原点に戻ることができます。 

次に、ti を固定すると、座標 i に対する有効な符号割り当ての数は、単純にゼロで終わる長さ ti の 1D バランス ウォークの数、つまり二項係数 C(ti, ti/2) になります。 

最後に、座標間のステップのインターリーブを考慮する必要があります。 座標 1 が t1 回使用され、座標 2 が t2 回使用されるなど、これらのラベル付きステップを配置する方法の数は、多項係数になります。 

(2n)! / (t1! t2! ... tk!)

 したがって、完全な答えは、2n を k 個の偶数部分に分割したすべての合計の合計になります。 

ti 上の偶数の合計、合計 ti = 2n:

 (2n)! / (t1!...tk!) × ∏ C(ti, ti/2)

 この式は、直接計算した場合でも k または n で指数関数的です。 次のステップは、母関数の単純化を認識することです。 

座標ごとに、その寄与系列を定義します。 

f(x) = 偶数 t の合計: C(t, t/2) x^t / t!

 これは 1D ウォークの寄与をエンコードします。 多項構造は、全体の答えが次のようになることを意味します。 

(2n)! × [x^{2n}] (f(x))^k

 ここで、古典的な ID を使用します。 

sum_{m ≥ 0} C(2m, m) x^{2m} / (2m)! = I_0(2√x) タイプの形式ですが、より重要なのは、組み合わせ的に係数形式で直接書き換えることができ、きれいな畳み込み解釈が得られることです。 代数的単純化の後、係数抽出は次のようになります。 

答え = n の分割の合計:

 (2n)! / ( (2a1)!...(2ak)! ) × ∏ C(2ai, ai)

 これでもまだ重そうに見えますが、重要な単純化があります: C(2ai, ai) = (2ai)! / (ai!)^2 なので、キャンセルするとすべてが次のように折りたたまれます。 

答え = (2n)! × a1+...+ak=n of 1 の合計 / (a1!^2 ... ak!^2)

ここで、シーケンス b[a] = 1/(a!)^2 の k 重畳み込みを認識します。 これは、k レジームに応じて、O(nk) またはそれより高速な多項式累乗によって計算できます。 最も難しいサブタスクでは k ≤ 100 であるため、k を小さなパラメーターとして扱い、総和 n に対する DP を計算します。 

dp[j] を、ハーフステップの合計が j になるように選択した処理済みの座標の値とする。 各座標は配列 b との畳み込みに寄与します。 k回繰り返すと、同じ多項式のk倍になります。 

畳み込みの繰り返しによるべき乗を使用して dp = b^k を計算します。畳み込みは小さい k で行われ、係数が大きくクエリが多いため FFT には適さないため、O(kn) の DP によって最適化されます。 

最後に (2n) を掛けます。

 ## アルゴリズムのチュートリアル

 この問題を、各座標が消費する上下の動きのペアの数という観点から再定式化します。 各座標は偶数のステップに寄与するため、ペアの単位で作業します。 

1. 問題を 2n ステップから n 個のペアに変換します。 各座標 i は ai ペアに寄与し、すべての ai の合計は n になります。 有効なリターンには各軸に沿った +1 と -1 の移動のペアが必要であるため、これは自然な減少です。 
2. 階乗および逆階乗を最大 2n まで事前計算します。 これにより、二項係数と多項重みの定数時間計算が可能になります。 
3. b[a] = 1 / (a!)^2 となる配列 b を構築します。 これは、座標を +/- ステップのペアに正確に割り当てることの寄与を表します。 
4. b とそれ自体の k 倍畳み込みを計算し、n で切り捨てます。 k 座標を処理した後、dp[j] は k 座標間で j ペアを分配する合計の重みを表します。 これが機能するのは、各座標が独立して消費するペアの数に対する分布に寄与するためです。 
5. dp[n] を (2n) 倍します。 正規化中に取り除かれた多項および符号割り当て係数を復元します。 

### なぜ効果があるのか

 重要な不変条件は、i 座標を処理した後、dp[j] がそれらの i 座標に対する j 個の合計ステップ ペアのすべての割り当ての合計に等しくなり、各割り当てが座標に対する 1/(ai!)^2 の積に寄与することです。 新しい座標を追加することは、b との畳み込みに正確に対応します。これは、古い座標と新しい座標の間で j ペアを分配することで、合計が独立した選択肢に分割されるためです。 これにより、k 回の反復後、dp がペア数の有効な分布をすべて正確に捕捉し、最後の乗算でラベル付きウォークの正確な組み合わせ数が復元されることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def modinv(x):
    return pow(x, MOD - 2, MOD)

MAXN = 200000

fact = [1] * (2 * MAXN + 1)
invfact = [1] * (2 * MAXN + 1)

for i in range(1, 2 * MAXN + 1):
    fact[i] = fact[i - 1] * i % MOD

invfact[2 * MAXN] = modinv(fact[2 * MAXN])
for i in range(2 * MAXN, 0, -1):
    invfact[i - 1] = invfact[i] * i % MOD

def solve_case(n, k):
    # b[a] = 1 / (a!^2)
    b = [0] * (n + 1)
    for i in range(n + 1):
        b[i] = invfact[i] * invfact[i] % MOD

    dp = [0] * (n + 1)
    dp[0] = 1

    for _ in range(k):
        new_dp = [0] * (n + 1)
        for i in range(n + 1):
            if dp[i] == 0:
                continue
            for j in range(n - i + 1):
                new_dp[i + j] = (new_dp[i + j] + dp[i] * b[j]) % MOD
        dp = new_dp

    return fact[2 * n] * dp[n] % MOD

def main():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        print(solve_case(n, k))

if __name__ == "__main__":
    main()
```この解決策は、二項関連の量を再計算せずに計算できるように、最大​​ 2n までの階乗と逆階乗を構築することから始まります。 配列 b は、階乗項が除外された正規化形式で座標ごとの寄与をエンコードします。 

DP 配列は、処理された座標間でいくつのステップ ペアが分散されたかを追跡します。 各畳み込みステップでは、ai の寄与をすべての可能な合計に分散することで、さらに 1 つの座標を統合します。 ネストされたループ構造は、n で切り捨てられた畳み込みの直接実装です。 

最後に、(2n) を掛けます。 ステップの順序付けと、正規化された重みから実際のカウントへの変換を考慮したグローバル多項係数を復元します。 

よくある落とし穴は、DP が 2n ステップではなく n (ペア) を超えていることを忘れることです。 もう 1 つは、最終階乗スケーリングを省略することです。これは、すべての中間状態が正規化された組み合わせ空間で動作するため、不可欠です。 

## 実用的な例

 ### 例 1: n = 1、k = 2

 ステップは 2 つあります。 2Dでは原点に戻る必要がある。 

| ステップ | dp 状態 |
 | --- | --- |
 | 初期化 | dp[0]=1 |
 | 座標 1 の後 | dp[0]=1、dp[1]=1 |
 | 座標2の後 | dp[0]=1、dp[1]=2、dp[2]=1 |

 n=1 なので dp[1] を採用します。 最終的な答えは(2)です！ × 2 = 4。 

これは、4 つの可能なパス (±x または ±y) に一致します。 

### 例 2: n = 2、k = 1

 単一座標、1D の 4 ステップ。 

| ステップ | dp 状態 |
 | --- | --- |
 | 初期化 | dp[0]=1 |
 | 座標 1 の後 | dp[0]=1、dp[1]=1、dp[2]=1 |

 dp[2]=1 とします。 最終的な答えは(4)です！ × 1 / (2!2!) = 6 ですが、k=1 なので、これは C(4,2)=6 になります。 

これにより、フレームワークが標準の 1D ウォークに正しく縮小されることが確認されます。

 | 測定 | 複雑さ | 説明 |

 ## 特殊なケース

 n = 0 の場合、DP は dp[0]=1 から始まり、畳み込みはそれを変更しません。 最後の乗算には (0) が使用されます。 = 1 であるため、出力は 1 となり、単一の空のウォークと一致します。 

k = 1 の場合、畳み込みは b 上の単一パスに縮退し、dp[n] は 1/(n!)^2 になります。 (2n) を掛けます! (2n)!/(n!^2) が得られます。これはまさに中心の二項係数であり、1D リターン パスと一致します。 

n = 1 および任意の k の場合、1 つのペアを任意の座標に割り当てることができるため、k 回の畳み込み後の dp は k を生成します。 2倍する！ は 2k を与え、2 つのステップのそれぞれで 1 つの軸と 1 つの方向を選択するという事実と一致します。
