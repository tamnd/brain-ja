 ## 解決策
 ## 問題の理解

 それぞれのサイズが異なる 2 つの文字列コレクションが与えられます。$n$。 並べ替えた後、位置的にそれらをペアにします。最初のコレクションの 1 つの文字列は 2 番目のコレクションの 1 つの文字列とペアになり、すべての文字列は 1 回だけ使用する必要があります。 

どの組み合わせでも、2 つの文字列の「互換性スコア」は、それらの共通のサフィックスの長さとして定義されます。 つまり、両方の文字列の末尾から見て、最初の不一致の前に連続して一致する文字の数を数えます。 

目標は、両方のコレクションの順序を変更して、作成時に$n$ペアの場合、これらすべての接尾辞一致の長さの合計が可能な限り大きくなります。 

各文字列はそのペアリングを通じてのみ寄与するため、実際の問題は、2 つの文字列のマルチセット間で一致を選択することです。ここで、2 つの文字列間のエッジの重みは、それらのサフィックスの類似性です。 

入力サイズが大きい: 各グループのすべての文字列の合計長は最大です。$2 \cdot 10^5$。 これにより、すべてのペアリングを試行したり、ペアごとのサフィックス一致を単純に計算したりするソリューションは即座に除外されます。 いっぱい$O(n^2)$文字列の比較はすでに大きすぎるため、$n$到達できる$2 \cdot 10^5$要素の合計で。 

素朴なアプローチでは、すべてのペアごとのサフィックス一致を計算してから、最大重み付けマッチングを実行しようとする可能性があります。 ここでは一般的なマッチング アルゴリズムが遅すぎるため、これは計算的にも構造的にも失敗します。 

文字列を並べ替えたり、グローバル構造を持たずにローカルで類似した文字列をペアにしたりする貪欲ペアリングでは、より微妙な障害モードが発生します。 簡単な例としては、多くの文字列が長いサフィックス チェーンを共有しており、貪欲なペアリングによって適切なパートナーが早期に「消費」され、その後のより適切な長い一致が妨げられる場合が挙げられます。 

## アプローチ

 ブルート フォースの観点は、2 つのセット間で文字列をペアにし、サフィックスの類似性の合計を計算するためのすべての可能な方法を検討することです。 すべてのペアごとのサフィックス一致を事前計算したとしても、$O(L)$ペアごと、ここで$L$は文字列の長さですが、まだ直面しています$O(n^2)$限界をはるかに超えたペアです。 二部マッチング定式化でも$n$重み付けされたエッジを持つ側面ごとのノード数は実行不可能になります。 

重要な構造上の観察は、サフィックスの類似性は任意の重みではなく、逆方向に読んだときに 2 つの文字列が一致する長さによって完全に決定されるということです。 これは、文字列を逆に処理し、接尾辞の構造によってグループ化することを示唆しています。 

すべての文字列を逆にすると、問題はサフィックスではなく最も長い共通プレフィックスに関するものになります。 ここでのタスクは、文字列をペアにして合計 LCP を最大化することです。 まさにトライで対応できる構造だ。 

反転された文字列に基づいて構築されたトライでは、すべてのノードがプレフィックス (元の文字列のサフィックス) に対応します。 ノードの深さは、サフィックス一致の長さを表します。 私たちが望んでいるのは、トライのできるだけ深いところでできるだけ多くのペアが「出会う」ように文字列をペアにすることです。なぜなら、より深い出会い点が合計に大きく寄与するからです。 

中心となるアイデアは、トライ全体でボトムアップ集計を行うことです。各ノードで、各側から通過する文字列の数を収集し、そのノードで一致するとすぐにそれらを貪欲に照合します。 余った弦は上に押し上げられます。 

これが機能するのは、可能な限り最も深い共通ノードで 2 つの文字列を一致させるとその寄与が最大化され、そのノードを超えて一致を遅らせても共有サフィックスを改善できないためです。 

## アルゴリズムのチュートリアル

 1. 両方のセットのすべての文字列を反転してトライに挿入し、最初のセットと 2 番目のセットの文字列が各ノードで終了するか、各ノードを通過する数を追跡します。 これにより、サフィックス マッチングがプレフィックス トラバーサルに変換されます。 
2. 子が親の前に処理されるように、トライに対してポストオーダー DFS を実行します。 これにより、最初により深いサフィックス レベルで一致を解決することが保証されます。 
3. 各ノードで、その子からのセットとノード自体で終わるセットの両方から「利用可能な」文字列の数を収集します。 これらは、少なくともこのプレフィックスを共有する文字列を表します。 
4. 最初のセットの 1 つと 2 番目のセットの 1 つをペアにして、このノードでできるだけ多くの文字列を照合します。 このような各ペアは、ノードの現在の深さを答えに提供します。 
5. ペアリング後、どちらかの側に文字列が残っている場合は、それらを親ノードに上向きに伝播します。 これらは、この深さで十分に長い共通サフィックスを持つ一致が見つからなかった文字列を表します。 
6. このプロセスをルートまで継続し、すべてのノードで寄与を蓄積します。 

正確さは、可能な限り最も深いノードでのペアリングがそのペアに最大の寄与をもたらすという事実にかかっています。 ノードで 2 つの文字列が利用可能になったら、祖先との一致を遅らせるとそれらの寄与が厳密に減少するため、即時一致がローカルおよびグローバルに最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(10**7)

class Node:
    __slots__ = ("ch", "cnt1", "cnt2")
    def __init__(self):
        self.ch = {}
        self.cnt1 = 0
        self.cnt2 = 0

def add(root, s, typ):
    v = root
    for c in s:
        if c not in v.ch:
            v.ch[c] = Node()
        v = v.ch[c]
    if typ == 1:
        v.cnt1 += 1
    else:
        v.cnt2 += 1

def dfs(v, depth, ans):
    for nxt in v.ch.values():
        dfs(nxt, depth + 1, ans)
        v.cnt1 += nxt.cnt1
        v.cnt2 += nxt.cnt2

    m = min(v.cnt1, v.cnt2)
    ans[0] += m * depth
    v.cnt1 -= m
    v.cnt2 -= m

def main():
    n = int(input())
    root = Node()

    for _ in range(n):
        s = input().strip()[::-1]
        add(root, s, 1)

    for _ in range(n):
        s = input().strip()[::-1]
        add(root, s, 2)

    ans = [0]
    dfs(root, 0, ans)
    print(ans[0])

if __name__ == "__main__":
    main()
```trie ノードには、各グループが通過する文字列の数が格納されます。 文字列を反転すると、接尾辞の位置合わせが接頭辞のトラバーサルになることが保証されるため、深さは接尾辞の長さを直接測定します。 

DFS 集計では子から順にカウントされます。 マッチング後の減算ステップにより、ノードでペアが形成されると、そのペアが誤って上方に伝播して再利用されることがなくなります。 

実装の微妙な詳細は、現在のノードで一致する前に子からカウントを蓄積する必要があることです。 逆の順序で実行すると、より深い一致がより浅い一致によって上書きされる可能性があります。

 ## 特殊なケース

 すべての文字列が同一の場合、トライ内のすべてのノードは両方のセットからの等しいカウントを保持します。 このアルゴリズムは最も深いノードで繰り返し照合し、すべてのペアが文字列の完全な長さに寄与することを保証します。 

1 つのセットに他のセットのプレフィックスである文字列が含まれている場合 (反転後)、異なる深さで一致が発生します。 DFS は、より深い一致が最初に解決されることを保証するため、短い文字列が長い一致の機会を誤って消費することはありません。 

一致するサフィックスがまったくない場合、すべての一致はルートでのみ発生し、ゼロが寄与しますが、深さがゼロであり、すべてのペアリングが上部で発生するため、これは正しく処理されます。
