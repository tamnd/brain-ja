 ## 解決策
 # 問題の理解

 曲のプレイリストがあります。 各曲には、ジャンルと作者という 2 つのラベルがあります。 いくつかの曲を削除して、残りの曲を並べ替えることができます。 並べ替えられたプレイリストは、すべての隣接するペアが少なくとも 1 つのラベルを共有する場合、つまり両方の曲が同じジャンルを持つか、両方の曲が同じライターを持つ場合に有効であるとみなされます。 タスクはできるだけ多くの曲を保持することなので、答えは削除される曲の最小数です。 元の問題には曲の数が少なく、サブセット動的プログラミングを使用した解決策が意図されています。 

重要な制約は曲数であり、最大でも 16 です。これは十分に小さいため、指数関数的なアルゴリズムが可能です。 すべての順序をチェックすることに基づくソリューションは、順列の数が増加するにつれて増加するため、依然としてコストがかかりすぎます。$n!$、中程度の値であっても数十億に達します。$n$。 すべてのサブセットにわたる解決策は実現可能です。$2^{16}=65536$可能なサブセット。 

文字列の長さが長いと、別の意味で問題になります。 状態を探索する際に、長いジャンルや作家の文字列を繰り返し比較する余裕はありません。 曲間のペア関係を一度前処理してから、動的プログラミング中に定数時間チェックのみを使用する必要があります。 

厄介なケースは、有効なプレイリストが必ずしも元の順序であるとは限らないという事実から生じます。 

たとえば、入力が次の場合:```
3
rock alice
pop bob
rock bob
```正しい出力は次のとおりです。```
0
```なぜなら注文は`rock alice`、`rock bob`、`pop bob`動作します。 指定された順序のみをチェックするソリューションでは、曲が誤って削除されてしまいます。 

もう 1 つの特殊なケースは、1 曲しか残っていない場合です。 例えば：```
1
jazz mike
```答えは次のとおりです。```
0
```単一の曲には、ルールに違反する可能性のある隣接するペアがないためです。 隣接する比較に基づいて回答を初期化するコードは、これを誤って無効としてカウントする可能性があります。 

最後のエッジケースは、大規模なサブセットが十分に接続されていない場合です。 例えば：```
3
a x
b y
c z
```正しい出力は次のとおりです。```
2
```2 つの曲を隣接させることはできないため、1 つの曲だけが残ります。 すべての曲が最終プレイリストに含まれることを想定した不用意な実装は、ここで失敗します。 

## アプローチ

 簡単なアプローチは、曲の可能なすべてのサブセットと、そのサブセット内の可能な順序をすべて試してみることです。 順序付けが隣接ルールを満たす場合、最大の有効なサイズが維持されます。 これは正しいです。なぜなら、答えは最大の有効なプレイリストを正確に補完するものだからです。 

問題は注文数です。 のために$n=16$、すべての順列をチェックするために必要な$16!$可能性、つまり$2.1 \times 10^{13}$。 高速操作でも制限時間内に収まりません。 

重要な点は、順序はどの曲が最後に配置されたかによってのみ決まるということです。 有効なプレイリストを構築するとき、これまでの順序全体を覚えておく必要はありません。 次の曲はその最後の曲と互換性があるだけでよいため、既に使用されている曲のセットと最後の曲のアイデンティティのみが必要です。 

これにより、問題はサブセット動的プログラミングに変換されます。 すべてのサブセットの各曲で終わる最大の有効なプレイリストを計算します。 すべての状態が処理されると、到達可能な最大のサブセット サイズによって、保持できる最大曲数が決まります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n! \cdot n)$|$O(n)$| 遅すぎる |
 | 最適 |$O(n^2 2^n)$|$O(n2^n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての曲のペアが隣接できるかどうかを事前計算します。 2つの曲は、ジャンルが一致するか、作家が一致すると互換性があります。 この結果を保存すると、動的プログラミング内で文字列を繰り返し比較することがなくなります。 
2. DP テーブルを作成します。`dp[mask][i]`の曲を正確に含む有効なプレイリストを構築できるかどうかを表します。`mask`そして歌で終わる`i`。 最後の曲が保存されるのは、次に追加できる曲が決定されるためです。 
3. すべての単一曲のサブセットを初期化します。 1 つの曲を含むプレイリストは常に有効であるため、1 つのビットが設定されているすべての状態が到達可能として開始されます。 
4. すべてのサブセットを反復処理します。 届くすべてのエンディングソングのために`i`、すべての曲を追加してみてください`j`まだサブセット内にありません。 もし`i`そして`j`互換性がある場合は、新しいサブセットの末尾にマークを付けます。`j`到達可能なものとして。 
5. 到達可能なすべての状態の中で設定されたビットの最大数を追跡します。 削除された曲の数は、曲の合計数からこの最大数を引いたものになります。 

機能する理由: すべての有効なプレイリストには、最終的な曲と使用された曲のセットが含まれています。 DP はこの情報を正確に保存するため、すべての有効な配置をトランジションによって再現できます。 逆に、すべてのトランジションは、前の最後の曲に合法的に従うことができる場合にのみ曲を追加するため、生成されたすべての状態は有効なプレイリストに対応します。 したがって、到達可能な最大のサブセットは、形成できる最大のプレイリストになります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    ans = []

    for _ in range(t):
        n = int(input())
        songs = []

        for _ in range(n):
            g, w = input().split()
            songs.append((g, w))

        ok = [[False] * n for _ in range(n)]
        for i in range(n):
            for j in range(n):
                if songs[i][0] == songs[j][0] or songs[i][1] == songs[j][1]:
                    ok[i][j] = True

        total = 1 << n
        dp = [0] * (total * n)

        for i in range(n):
            dp[((1 << i) * n) + i] = 1

        best = 1

        for mask in range(total):
            cnt = mask.bit_count()
            if cnt <= best:
                best = max(best, cnt)

            base = mask * n
            for last in range(n):
                if dp[base + last]:
                    remaining = ((total - 1) ^ mask)
                    while remaining:
                        bit = remaining & -remaining
                        nxt = bit.bit_length() - 1
                        if ok[last][nxt]:
                            new_mask = mask | bit
                            dp[new_mask * n + nxt] = 1
                        remaining -= bit

        ans.append(str(n - best))

    print("\n".join(ans))

if __name__ == "__main__":
    solve()
```ペアごと`ok`マトリックスは DP が開始される前に構築されます。 ここで負荷の高い文字列比較がすべて行われるため、アルゴリズムの指数部分は整数演算のみを実行します。 

DP 配列は 1 次元に平坦化されます。 州`(mask, last)`インデックスに格納されます`mask * n + last`これにより、多数の入れ子になった Python リストの作成が回避され、オーバーヘッドが削減されます。 

すべての曲がプレイリストを開始できるため、単一曲の状態は初期化されます。 トランジション中に、コードは未使用の曲のセットから利用可能なビットを一度に 1 つずつ削除します。 これにより、不要な位置をスキャンすることがなくなります。 

Python の整数はオーバーフローしないため、ビットマスク操作は安全です。 慎重に処理する必要がある唯一の境界詳細は、有効なプレイリストの最大サイズがすでに正しく初期化されている単一曲の場合です。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n^2 2^n)$| すべてのサブセットは、可能なすべての次の曲で拡張を試みる可能性があります。 
| スペース |$O(n2^n)$| サブセットおよび可能なエンディング曲ごとに 1 つの DP 状態が保存されます。 

と$n \leq 16$、サブセットの数は最大 65536 です。結果として得られる状態の数は、必要な制限に対して十分に小さいです。 

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    data = sys.stdin.read().split()
    sys.stdin = old

    it = iter(data)
    t = int(next(it))
    res = []

    for _ in range(t):
        n = int(next(it))
        songs = []
        for _ in range(n):
            songs.append((next(it), next(it)))

        ok = [[False] * n for _ in range(n)]
        for i in range(n):
            for j in range(n):
                ok[i][j] = songs[i][0] == songs[j][0] or songs[i][1] == songs[j][1]

        dp = [0] * ((1 << n) * n)
        best = 1

        for i in range(n):
            dp[((1 << i) * n) + i] = 1

        for mask in range(1 << n):
            best = max(best, mask.bit_count())
            for last in range(n):
                if dp[mask * n + last]:
                    rem = ((1 << n) - 1) ^ mask
                    while rem:
                        b = rem & -rem
                        nxt = b.bit_length() - 1
                        if ok[last][nxt]:
                            dp[(mask | b) * n + nxt] = 1
                        rem -= b

        res.append(str(n - best))

    return "\n".join(res)

 ## 特殊なケース

 単一曲の場合:```
1
jazz mike
```DP は、到達可能な状態として唯一の曲から始まります。 トランジションは必要ないため、プレイリストの最大サイズは 1 で、削除カウントは 0 です。 

元の順序が誤解を招く場合:```
3
rock alice
pop bob
rock bob
```アルゴリズムは入力順序を気にしません。 すべての曲から始まり、可能なすべての有効な継続を探索します。 3 曲すべての順序終了を検出し、除去は 0 個返されます。 

まったく関係のない曲の場合:```
3
a x
b y
c z
```互換性マトリックスには、自己ペア以外の真のペアは含まれません。 遷移ループは、より大きなマスクを作成できず、サイズ 1 の 3 つの状態のみが残ります。 アルゴリズムは、1 つの曲だけが残せることを正しく計算します。
