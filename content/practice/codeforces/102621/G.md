 ## 解決策
 ## 問題の理解

 問題は対話型のタスクです。 隠しオブジェクトは、小文字、大文字、数字を含む 62 文字セットの個別の文字で作成されたパスワードです。 クエリは、考えられるパスワードを裁判官に送信し、裁判官は、クエリが正確なパスワードであるか、パスワードの適切な部分であるか、またはパスワードにまったく含まれていないかを応答します。 目標は、750 件の推測内でパスワードを発見することです。 

主要な制限は、すべての文字が最大 1 回出現することであるため、パスワードはアルファベットのサブセットの順列になります。 可能な最大長は 62 です。これは、文字の対数検索ができる程度には十分小さいですが、考えられるすべての並べ替えを試すには十分ではありません。 考えられるパスワードの数は膨大であり、候補を列挙する方法は不可能です。 

難しいのは、ジャッジの反応を正しく解釈することにあります。 1 つの文字を含むクエリは、その文字についてだけを示すわけではありません。 また、パスワード全体の長さが 1 であるかどうかも明らかになります。 たとえば、クエリを実行すると、`a`パスワードに対して`a`与える`C`、クエリ中に`a`に対して`ab`与える`Y`。 両方の応答を同一のものとして扱うと、長さの情報が失われます。 

もう 1 つの微妙なケースは、最後のクエリです。 構築された文字列にパスワードのすべての文字が正しい順序で含まれている場合、答えは次のようになります。`C`の代わりに`Y`。 アルゴリズムは直ちに停止する必要があります`C`成功後に追加のクエリを送信することは許可されていないためです。 

## アプローチ

 直接的なアプローチは、候補文字列を試し、その応答を使用して不可能なパスワードを排除することです。 すべての回答で非表示の文字列に関する情報が得られるため、これは正しいですが、検索スペースが大きすぎます。 繰り返し文字を含まない文字列に制限しても、次のようになります。$$62! + 62 \cdot 61! + \dots$$これは 750 件のクエリでテストできる数をはるかに超えています。 

有益な観察は、裁判官がその後の質問に答えることができるということです。 まず、個々の文字について質問することで、パスワードにどの文字が含まれているかを正確に知ることができます。 その後に残る問題は、それらの文字を順序付けることだけです。 

文字は一意であるため、文字のセットがわかれば、パスワードはそれらの順序を 1 つにするだけです。 ソートされたパスワードのプレフィックスを維持し、新しい文字を正しい位置に挿入できます。 挿入位置に対する二分探索は、候補の順序付けが部分列であるか、そうでないため機能します。 これにより、順序付けに必要なクエリの数が 2 次からおおよその順序に減少します。$62 \log 62$。 

すべての有効な推測が情報を提供するため、ブルート フォースは機能しますが、可能な注文の数が爆発的に増加するため失敗します。 サブシーケンスのチェックによって相対的な順序が明らかになるという観察により、推測を構築に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(可能なパスワードの数) | O(候補者数) | 遅すぎる |
 | 最適 | O(62 log 62) クエリ | お(62) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 許可されているアルファベットのすべての文字をクエリします。 もし答えが`Y`、その文字はパスワードに属します。 もし答えが`C`、パスワードはその 1 文字で構成されており、すぐに終了できます。 
2. 発見された文字を、これまでに発見された順序に保ちます。 最初の既知の文字によって、現在の順序付けされたシーケンスが開始されます。 
3. 残りの検出されたすべての文字を現在のシーケンスに挿入します。 位置が正しいかどうかをテストするには、そこに新しい文字を配置し、シーケンス全体をクエリします。 肯定的な答えは、その順序が隠しパスワードと一致していることを意味します。 
4. 挿入中に二分探索を使用します。 文字を中央の位置より前に配置することができれば、答えは左半分にあります。 それ以外の場合は、その位置の後にある必要があります。 
5. 挿入するたびに、維持されるシーケンスは実際のパスワードのサブシーケンスになります。 すべての文字が挿入されると、そのシーケンスはパスワードと等しくなるため、次に成功したクエリは戻り値を返します。`C`。 

これが機能する理由: 不変条件は、維持されたシーケンスが隠しパスワード内で常に同じ順序で表示されることです。 新しい文字を挿入する場合、パスワードには繰り返し文字がないため、正確に 1 つの位置でこのプロパティが保持されます。 二分探索では、有効なサブシーケンス チェックを使用して位置を選択するだけなので、真の位置を破棄することはできません。 すべての文字が配置された後、維持されるシーケンスにはパスワードのすべての文字が含まれるため、パスワードそのものである必要があります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

alphabet = "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789"

def solve():
    def ask(s):
        print(s, flush=True)
        return input().strip()

    present = []

    for c in alphabet:
        res = ask(c)
        if res == "C":
            return
        if res == "Y":
            present.append(c)

    if not present:
        return

    order = [present[0]]

    for c in present[1:]:
        lo, hi = 0, len(order)

        while lo < hi:
            mid = (lo + hi) // 2
            candidate = ''.join(order[:mid]) + c + ''.join(order[mid:])
            res = ask(candidate)

            if res == "C":
                return

            if res == "Y":
                hi = mid
            else:
                lo = mid + 1

        order.insert(lo, c)

    res = ask(''.join(order))
    if res == "C":
        return

if __name__ == "__main__":
    solve()
```の`ask`この関数は対話型プロトコルを処理します。 クエリを出力し、すぐにフラッシュして、ジャッジの応答を読み取ります。 裁判官は完全な質問を受け取るまで答えることができないため、フラッシングが必要です。 

最初のループは文字セットを識別します。 受け取るキャラクター`Y`単一文字のサブシーケンスは、その文字が存在する場合にのみ存在できるため、パスワードのどこかに存在することが保証されます。 

挿入部は保持します`order`すべての操作後に有効です。 候補文字列は、左側の部分、挿入された文字、右側の部分から再構築され、インデックスの間違いを回避します。 二分探索境界は、ゼロから現在の長さまでの可能な挿入位置を表します。 

最後のクエリでは、検出されたすべての文字が再構築された順序で使用されます。 アルゴリズムが正しければ、これが隠しパスワードであり、裁判官は結果を返します。`C`。 

## 実用的な例

 元のタスクは対話型であるため、例は固定の入出力ペアではなく会話です。 

隠しパスワードの場合`hunter2`、キャラクター発見フェーズは次のようになります。 

| ステップ | クエリ | 応答 | 既知のキャラクター |
 | --- | --- | --- | --- |
 | 1 |`h`| や | h |
 | 2 |`u`| や | う、う |
 | 3 |`n`| や | う、う、ん |
 | 4 |`t`| や | h、u、n、t |
 | 5 |`e`| や | h、u、n、t、e |
 | 6 |`r`| や | h、u、n、t、e、r |
 | 7 |`2`| や | h、u、n、t、e、r、2 |

 順序付けフェーズでは、サブシーケンスをテストして文字を挿入します。 たとえば、挿入するとき`t`の中へ`hun`、クエリ`thun`失敗する理由`t`前には現れない`h`、 その間`hunt`隠し順序と一致するため成功します。 

これは、サブシーケンス クエリを可能な位置間の比較演算として使用できることを示しています。 

1文字のパスワードの場合、`A`、最初の文字クエリは次のようになります。 

| ステップ | クエリ | 応答 | アクション |
 | --- | --- | --- | --- |
 | 1 |`a`| N | 続ける |
 | 2 | ... | ... | 続ける |
 | 28 |`A`| C | 仕上げ |

 これは、アルゴリズムが処理する必要がある理由を裏付けています。`C`文字検出段階中。

## テストケース

 この問題は対話型であるため、通常のオフライン アサーション テストでは実際のジャッジの対話を表現できません。 ローカル シミュレーションには、隠しパスワードを保存して返す偽のジャッジが必要になります。`C`、`Y`、 または`N`後続ルールに従って。 

適切なシミュレータでは、次のケースをテストする必要があります。 

| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 | 隠しパスワード`a`|`a`発見されました | 1 文字のパスワードの処理 |

 ## 特殊なケース

 1 文字のパスワードの場合、次のようになります。`x`、クエリする`x`返品`C`、 ない`Y`。 アルゴリズムは、順序付けの構築を続行する代わりに、ただちに終了します。 

実際の位置とは異なる順序で検出された文字を含むパスワードの場合、挿入ステージで順序が修正されます。 たとえば、ディスカバリーで次のことが見つかった場合、`a`、`b`、`c`しかしパスワードは`cab`、挿入`c`そして、ポジションをテストして、最終的なシーケンスが次のようになることを確認します。`cab`。 

可能なすべての文字を含む最大長のパスワードの場合、すべての挿入は後続のチェックのみに依存するため、アルゴリズムは引き続き機能します。 クエリの数は、使用可能なパスワードの数ではなく、文字数に応じて増加します。
