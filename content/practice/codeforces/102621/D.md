 ## 解決策
 ## 問題の理解

 私たちは次のラインを持っています`N`アライグマ。 ラクーン`i`から始まる`A[i]`キャンディーのかけら。 アリスのパフォーマンス`Q`操作。 操作では、アライグマの連続セグメントと値を選択します。`x`。 そのセグメント内のアライグマごとに、アリスはその状態を反転します。現在キャンディーを持っている場合は、すべてを削除します。 現在キャンディーが入っていない場合、彼女はそれを正確に与えます`x`個。 

タスクは、すべての操作後の各アライグマの最終的なキャンディーの量を出力することです。 入力は最初のキャンディ配列とそれに続く範囲演算で構成され、出力はシーケンス全体をシミュレートした後の最終配列になります。 元の制約には、`N, Q <= 100000`したがって、すべての操作ですべてのアライグマに触れるアプローチは、次のように実行できます。`10^10`これは、一般的な競技プログラミングの時間制限をはるかに超えています。 すべての範囲を拡張するのではなく、各操作を 1 回近く処理する必要があります。 

難しいのは、操作が単純に固定量を追加または削除するわけではないということです。 効果は、アライグマが何回訪問されたか、そしてアライグマが空から始まったかどうかによって異なります。 最後の操作値を記憶せずに操作をカウントするだけのソリューションでは、情報が失われます。 

キャンディーで始まり、値を伴う操作の影響を受けるアライグマを考えてみましょう。`3, 8, 5`。 その状態は次のとおりです。`7 -> 0 -> 8 -> 0`最終的な答えは、`0`。 最後の値だけを記憶する不注意な実装では、誤った出力が行われる可能性があります。`5`。 

もう 1 つのエッジ ケースは、空から開始されるアライグマです。 入力の場合:```
1 1
0
1 1 10
```正しい出力は次のとおりです。```
10
```最初の操作では、アライグマが空なのでキャンディーが与えられます。 すべての最初の操作を削除として扱うと、誤ってそのまま残されてしまいます。`0`。 

最後の境界ケースは、決して触れられないアライグマです。 入力の場合:```
3 1
4 7 2
2 3 5
```正しい出力は次のとおりです。```
4 0 0
```最初のアライグマは元の値を保持します。 このケースを忘れて、操作ロジックからのすべての応答を初期化すると、未タッチの位置が誤って変更されてしまいます。 

## アプローチ

 直接的な解決策では、その間隔ですべてのアライグマを歩き回ることで、すべての操作をシミュレートします。 これは、アリスが実行するアクションとまったく同じアクションを実行するため、正しいです。 ただし、1 回の操作ですべてをカバーできます。`N`アライグマ、あるかもしれない`Q`そのような操作。 最悪の場合、これには次のことが必要になります。`N * Q = 10^10`状態の変化が遅すぎます。 

重要な観察は、アライグマは前の状態の正確な順序を気にしないということです。 関心があるのは 2 つのことだけです。それが何回訪問されたか、もう 1 つは最後に訪問された操作の値です。 

アライグマがプラスの金額でスタートするとします。 最初の訪問ではキャンディーが削除され、2 回目の訪問ではキャンディーが与えられ、3 回目の訪問では再びキャンディーが削除されます。 奇数回訪問した後、アライグマのキャンディーはゼロになります。 偶数回の訪問の後、次のようになります。`x`前回の訪問時の値。 空で始まる場合、同じパターンが 1 つシフトされます。奇数の訪問では、最後のパターンが残ります。`x`、訪問しても空のままです。 

ここで問題は、すべての位置について、その位置をカバーするアクティブな範囲操作の数と、最大のインデックスを持つカバー操作を見つけることになります。 位置上の掃引線は、まさにこの情報を示します。 クエリの左エンドポイントを入力するときは、そのクエリをデータ構造に追加します。 右側の終点を通過する場合は、それを削除します。 データ構造には、あらゆる位置で、その位置に影響を与える操作が正確に含まれています。 サイズのパリティによって、訪問数が奇数か偶数かがわかり、最大のクエリ インデックスが最後の操作の値を示します。

 ## アルゴリズムのチュートリアル

 1. 各操作を 2 回保存します。 イベント リストの左端点にそのインデックスを追加し、右端点の直後の位置で削除対象としてマークします。 これにより、スイープは、操作がいつアクティブになり、いつ位置への影響がなくなるかを正確に知ることができます。 
2. アクティブな操作のヒープを維持しながら、位置を左から右にスイープします。 現在の位置から始まるすべての操作を追加し、その前に終了したすべての操作を削除します。 ヒープは、現在この位置をカバーしているすべてのクエリを表します。 
3. ヒープに対して遅延削除を使用します。 操作の有効期限が切れたら、非アクティブとしてマークします。 ヒープトップが非アクティブな操作を参照している場合は、それを削除します。 これにより、最大のアクティブ クエリ インデックスを利用可能な状態に保ちながら、より複雑な順序付きセットの必要性が回避されます。 
4. ポジションごとに、アクティブな操作の数を検査します。 アクティブな操作がない場合は、元のキャンディーの量を維持します。 それ以外の場合は、アクティブ カウントのパリティと、初期値がゼロかどうかを使用して、ゼロ キャンディと最新のアクティブ操作の値のどちらかを決定します。 
5. 結果の配列を出力します。 

なぜ効果があるのか:

 スイープ内のすべての位置で、アクティブ セットには、その位置が範囲に含まれる操作が正確に含まれます。 このセットのサイズは、アリスがアライグマを訪問する回数であるため、そのパリティによって、最終状態が空であるか、最後に指定された値と等しいかが決まります。 ヒープトップは、アクティブな操作の中で最大のインデックスを持つ操作であり、まさにそのアライグマに影響を与える最後の操作です。 すべての位置がこれら 2 つの情報を使用して処理されるため、すべての最終値が正しく計算されます。 

## Python ソリューション```python
import sys
import heapq

input = sys.stdin.readline

def solve():
    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    add = [[] for _ in range(n + 2)]
    remove = [[] for _ in range(n + 2)]
    x_values = [0] * (q + 1)

    for idx in range(1, q + 1):
        l, r, x = map(int, input().split())
        x_values[idx] = x
        add[l].append(idx)
        remove[r + 1].append(idx)

    active = [False] * (q + 1)
    heap = []
    ans = a[:]

    for i in range(1, n + 1):
        for idx in add[i]:
            active[idx] = True
            heapq.heappush(heap, -idx)

        for idx in remove[i]:
            active[idx] = False

        while heap and not active[-heap[0]]:
            heapq.heappop(heap)

        if heap:
            cnt = 0
            for idx in heap:
                if active[-idx]:
                    cnt += 1

            last = -heap[0]
            if (a[i - 1] == 0) == (cnt % 2 == 1):
                ans[i - 1] = x_values[last]
            else:
                ans[i - 1] = 0

    print(*ans)

if __name__ == "__main__":
    solve()
```イベント配列は範囲操作をポイント イベントに変換します。 操作はスイープが左端点に到達すると挿入され、右端点の後に削除されるため、ヒープは常に現在の位置を表します。 

Python のヒープは最小ヒープであるため、ヒープには負のインデックスが格納されます。 クエリ インデックスを否定すると、最小のヒープ値が最大のクエリ インデックスを表すようになり、これが現在の raccoon に影響を与える最新の操作になります。 

遅延削除配列により、ヒープの中央からのコストのかかる削除が回避されます。 期限切れの操作は、最上部に到達するまで内部に残り、そこで破棄されます。 

パリティ チェックは 2 つの事実を組み合わせます。 最初はポジティブなアライグマは、奇数回の訪問後に空で終了し、偶数回の訪問後に最後の値を保持します。 最初は空のアライグマは逆の行動をします。 この式では、開始状態とパリティを比較して、正しい結果を選択します。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((N + Q) log Q) | 各クエリは一度ヒープに入り、ヒープ操作には対数時間がかかります。 
| スペース | O(N + Q) | イベント リスト、クエリ値、およびヒープ ストレージはすべて線形です。 

この制約により、範囲を直接拡大する解決策を避ける必要があります。 スイープ ラインは各アライグマ位置を 1 回処理し、各クエリを一定回数だけ処理するため、制限内に問題なく収まります。 

## テストケース```python
import sys
import io
import heapq

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, q = map(int, input().split())
    a = list(map(int, input().split()))

    add = [[] for _ in range(n + 2)]
    remove = [[] for _ in range(n + 2)]
    xs = [0] * (q + 1)

    for i in range(1, q + 1):
        l, r, x = map(int, input().split())
        xs[i] = x
        add[l].append(i)
        remove[r + 1].append(i)

    active = [False] * (q + 1)
    heap = []
    ans = a[:]

    for i in range(1, n + 1):
        for x in add[i]:
            active[x] = True
            heapq.heappush(heap, -x)

        for x in remove[i]:
            active[x] = False

        while heap and not active[-heap[0]]:
            heapq.heappop(heap)

        if heap:
            cnt = sum(active[-x] for x in heap)
            last = -heap[0]
            if (a[i - 1] == 0) == (cnt & 1):
                ans[i - 1] = xs[last]
            else:
                ans[i - 1] = 0

    return " ".join(map(str, ans)) + "\n"

 ## 特殊なケース

 最初のエッジケースでは、複数の訪問をシミュレートするのではなく、同等に減らす必要があります。 入力では:```
1 3
5
1 1 3
1 1 8
1 1 5
```アクティブ セットには、唯一の位置に 3 つの操作が含まれています。 カウントは奇数です。アライグマはキャンディーから始めたので、最終的な答えはゼロです。 このアルゴリズムは、3 つの遷移すべてを再生するのではなく、3 つのパリティを使用します。 

最初は空のアライグマの場合、同じパリティでも逆の結果が得られます。```
1 1
0
1 1 6
```操作カウントは 1 で、開始値は 0 であるため、最終状態は最後の操作値になります。`6`。 アルゴリズムの初期状態チェックは、このケースを処理します。

9 4 7
2 2 10
```1 位と 3 位はアクティブ セットには入りません。 アルゴリズムは更新ロジックをスキップし、元の値を変更しないままにして、次の結果を生成します。```
