 ## 解決策
 ## 問題の理解

 部屋は柱の長方形の格子です。 各柱には、崩壊するまでにトカゲが何回そこから離れることができるかを示す強​​度値があります。 いくつかの柱にはトカゲがいますが、残りは空です。 トカゲは、2 つの位置の間の距離が最大でも 1 メートル以内であれば、別の柱にジャンプできます。`d`または、境界線に十分近づくと部屋から飛び出す可能性があります。 課題は、何匹のトカゲが逃げられないかを判断することです。 

入力では、いくつかの独立した部屋が説明されています。 各部屋の最初のグリッドにはすべての柱の耐久性が保存され、2 番目のグリッドにはトカゲの開始位置がマークされます。 出力は、可能な限り最良の一連のジャンプの後に捕らえられたトカゲの数です。 

寸法は十分小さいため、グリッドをグラフに拡張できますが、トカゲの数と考えられる動きを考慮すると、直接シミュレーションは危険になります。 最も近いトカゲを最初に移動するなどの貪欲な戦略は失敗します。ジャンプするたびに共有柱の容量が消費されるため、あるトカゲの決定が別のトカゲの選択肢に影響を与える可能性があります。 

制約について正しく考えると、セルの数は最大でも数百程度であると考えられます。 これにより、数千の頂点とエッジを含むグラフ アルゴリズムが可能になります。 トカゲの動きのあらゆる可能な順序を試みるソリューションは指数関数的に成長するでしょうが、フロー アルゴリズムは容易に制限内に留まります。 

よくある間違いは、柱が複数回使用できることを忘れることです。 例えば、価値のある強い柱`2`2 匹の異なるトカゲがそこを通って出て行く可能性があります。 それを使い捨て細胞として扱うと、間違った答えが生成されます。 

もう 1 つのエッジケースは、トカゲがすでに外側に十分近づいている場合です。 例えば：```
1
1 1
1
L
```正しい答えは、`0`、直接飛び出すことができるのはトカゲだけだからです。 柱間のジャンプのみをチェックするソリューションでは、トカゲが誤って閉じ込められたままになってしまいます。 

別のエッジケースは、出口が存在しない場合です。```
1
3 1
000
000
000
L..
...
...
```正しい答えは、`1`。 トカゲには立つ柱も境界線に到達する方法もないため、逃げることはできません。 移動エッジのみをカウントし、欠落している柱を忘れる実装では、無効なパスが誤って作成される可能性があります。 

## アプローチ

 ブルートフォースアプローチは、考えられるエスケープシーケンスをシミュレートすることです。 すべてのトカゲについて、到達可能なすべての柱を試し、そこから離れる柱の残りの強度を更新し、再帰的に続行することができます。 これは正しいです。すべての法的な動きが調査されるため、最適なシーケンスが検索ツリーのどこかに表示されるはずです。 問題は、可能なシーケンスの数が爆発的に増加することです。 何百もの柱があるため、可能な動きの組み合わせの数は探索できる範囲をはるかに超えています。 

重要な観察は、すべてのトカゲが安全な場所に到達するか、柱の容量を消費するかのいずれかであるということです。 これは実際には移動順序の問題ではありません。 それは資源配分の問題です。 各柱にはそこから出ることができる回数が制限されており、すべてのトカゲは外側に到達する前に、使用するすべての柱で 1 ユニットの容量を必要とします。 

この構造は最大流量モデルと一致します。 フローの単位が 1 匹のトカゲを表すグラフを作成します。 トカゲ ノードからシンクまでのパスは、考えられる逃走経路の 1 つを表します。 ピラーは入力ノードと出力ノードに分割され、それらの間のエッジにはピラーの強度に等しい容量があります。 その容量は、その柱から何匹のトカゲが離れることができるかを表します。 

ソースは、容量 1 のすべての開始トカゲに接続します。 洗面台は部屋から出ることを表します。 最大流量を実行すると、逃げることができるトカゲの最大数が得られ、これをトカゲの総数から引くと答えが得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 可能な手の数は指数関数的 | O(セル) | 遅すぎる |
 | 最適 | Dinic のアルゴリズムを使用した O(V²E) | O(V + E) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ピラーごとに 2 つのノードを含むフロー グラフを構築します。 入力ノードは柱に到着することを表し、出力ノードは柱から離れることを表します。 柱の耐久性に等しい容量のエッジをそれらの間に追加します。 これは、柱を使用できる制限された回数をモデル化します。 
2. ソース ノードを追加し、それを容量 1 のすべてのトカゲ開始位置に接続します。 各トカゲは逃げるか逃さないかのどちらかであるため、各トカゲは正確に 1 単位の流れに寄与します。 
3. すべての柱について、そこに立っているトカゲが直接外にジャンプできるかどうかを確認します。 可能であれば、出力ピラー ノードを無限の容量を持つシンクに接続します。 外側は逃げ出したトカゲを何頭でも受け入れることができるため、容量に制限はありません。 
4. 距離がジャンプ範囲内にあるピラーのペアごとに、最初のピラーの出力ノードから 2 番目のピラーの入力ノードに無限の容量でエッジを追加します。 これは柱間の合法的なジャンプを表します。 
5. ソースからシンクまでの最大流量アルゴリズムを実行します。 結果として得られる流量値は、脱出に成功したトカゲの数です。 
6. 元のトカゲの数から逃げたトカゲを引きます。 残りの値は死傷者の数です。 

なぜ効果があるのか:

 すべての有効なエスケープ ルートは、フロー ネットワーク内のパスに対応します。 唯一の限られたリソースは柱の離脱であり、それらは各柱の 2 つのコピー間の容量エッジによって正確に表されます。 各トカゲは 1 単位のフローで開始され、シンクは有効な出口からのフローのみを受け取るため、最大フローの各単位は 1 匹の逃げたトカゲに対応します。 したがって、最大流量では、可能な限り多くの逃げるトカゲが見つかり、残りのトカゲはまさに逃げることができないトカゲになります。 

## Python ソリューション```python
import sys
from collections import deque

input = sys.stdin.readline

class Dinic:
    def __init__(self, n):
        self.n = n
        self.g = [[] for _ in range(n)]

    def add_edge(self, u, v, c):
        self.g[u].append([v, c, len(self.g[v])])
        self.g[v].append([u, 0, len(self.g[u]) - 1])

    def bfs(self, s, t):
        self.level = [-1] * self.n
        q = deque([s])
        self.level[s] = 0

        while q:
            u = q.popleft()
            for v, c, _ in self.g[u]:
                if c and self.level[v] == -1:
                    self.level[v] = self.level[u] + 1
                    q.append(v)

        return self.level[t] != -1

    def dfs(self, u, t, f):
        if u == t:
            return f

        while self.it[u] < len(self.g[u]):
            e = self.g[u][self.it[u]]
            v, c, rev = e

            if c and self.level[v] == self.level[u] + 1:
                pushed = self.dfs(v, t, min(f, c))
                if pushed:
                    e[1] -= pushed
                    self.g[v][rev][1] += pushed
                    return pushed

            self.it[u] += 1

        return 0

    def flow(self, s, t):
        ans = 0
        inf = 10 ** 9

        while self.bfs(s, t):
            self.it = [0] * self.n
            while True:
                pushed = self.dfs(s, t, inf)
                if pushed == 0:
                    break
                ans += pushed

        return ans

def solve_case(n, d, cap, lizards):
    m = len(cap[0])
    cells = n * m

    def inside(r, c):
        return 0 <= r < n and 0 <= c < m

    def idx(r, c):
        return r * m + c

    source = 2 * cells
    sink = source + 1
    dinic = Dinic(sink + 1)

    total = 0
    for r in range(n):
        for c in range(m):
            if cap[r][c] == '0':
                continue

            node = idx(r, c)
            dinic.add_edge(2 * node, 2 * node + 1, int(cap[r][c]))

            if lizards[r][c] == 'L':
                total += 1
                dinic.add_edge(source, 2 * node, 1)

            if r < d or c < d or n - 1 - r < d or m - 1 - c < d:
                dinic.add_edge(2 * node + 1, sink, 10 ** 9)

    for r in range(n):
        for c in range(m):
            if cap[r][c] == '0':
                continue

            for nr in range(n):
                for nc in range(m):
                    if cap[nr][nc] == '0':
                        continue
                    if r == nr and c == nc:
                        continue

                    dist = abs(r - nr) + abs(c - nc)
                    if dist <= d:
                        dinic.add_edge(2 * idx(r, c) + 1,
                                       2 * idx(nr, nc),
                                       10 ** 9)

    escaped = dinic.flow(source, sink)
    return total - escaped

def main():
    t = int(input())
    out = []

    for case in range(1, t + 1):
        n, d = map(int, input().split())
        cap = [input().strip() for _ in range(n)]
        lizards = [input().strip() for _ in range(n)]

        ans = solve_case(n, d, cap, lizards)
        out.append(f"Case {case}: {ans}")

    print("\n".join(out))

if __name__ == "__main__":
    main()
```実装はグラフの構築に直接続きます。 容量制限は柱に到着するときではなく、柱を離れるときに適用されるため、各柱は 2 回表されます。 これら 2 つのコピーの間の端が、耐久性の制限が適用される場所です。 

トカゲは複数の逃げ道に分かれることができないため、ソース エッジの容量は 1 です。 シンクの端は外側にボトルネックがないため、非常に大きな容量を使用します。 柱間のジャンプは柱自体以外には制限されないため、移動エッジにも同じ値が使用されます。 

移動はグリッド上で発生するため、距離チェックではマンハッタン距離が使用されます。 境界チェックは、エッジまでの最小距離で行われます。 制約が小さいため、ピラーのすべてのペアをチェックすることが許容され、実装が単純になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(V²E) | 構築されたグラフ上の Dinic のアルゴリズム |
 | スペース | O(V + E) | グラフと残余エッジを保存します。

 ## 特殊なケース

 外側のジャンプ距離内で開始したトカゲは、柱からシンクまでの直接のエッジで処理されます。 例えば：```
1
1 1
1
L
```支柱がシンクに接続されているので、最大流量で1台すぐに送れます。 最終的な答えは、`0`。 

強度がゼロの柱は使用できません。 のために：```
1
3 1
000
000
000
L..
...
...
```グラフには、開始ピラーの使用可能な容量のノードが含まれていません。 ソースからシンクへのパスが存在しないため、最大フローはゼロになり、アルゴリズムは戻ります。`1`。 

柱を共有する複数のトカゲは、キャパシティ エッジを通じて処理されます。 柱に強度があれば`2`、入力から出力までのエッジにより、2 つのフロー単位が許可されます。 使い捨ての解釈では、誤って可能なエスケープの数が減少します。 フロー ネットワークは、問題によって説明されるリソース制限を正確に保持します。
