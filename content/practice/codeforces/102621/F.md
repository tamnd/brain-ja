 ## 解決策
 ## 問題の理解

 ゴリラは整数の ID で識別されます。 ID が正確に異なる場合、2 匹のゴリラを一緒に配置することはできません`K`。 タスクは、選択されたすべてのペアが互換性のある、空ではないゴリラのグループがいくつ形成できるかを数えることです。 

入力はゴリラの総数と固定距離を表します。`K`それは非互換性を生み出します。 出力は、有効な空でない選択の数を法的に表したものです。`10^9 + 7`。 

重要な観察は、紛争の構造から得られます。 ゴリラなら`x`と衝突する`x + K`、 それから`x + K`と衝突する`x + 2K`、 等々。 すべての ID は、次の値で割ったときの余りが同じ 1 つの数値シーケンスに属します。`K`。 各シーケンス内では、隣接する要素は競合しますが、隣接しない要素は競合しません。 これは、競合グラフが恣意的ではないことを意味します。 パスの集合体です。 

制約は、考えられるすべてのグループを構築することが不可能になるように設計されています。 あれば`N`ゴリラ、考えられるサブセットの数は`2^N`、中程度のサイズでも使用できなくなります`N`。 すべてのペアをチェックする二次アプローチも、次の場合に失敗する可能性があります。`N`周りに届く`10^5`。 各ゴリラに一定回数だけ接触するソリューションが必要です。 

いくつかの特殊なケースは見落とされがちです。 

1 頭のゴリラを考えてみましょう。```
Input:
1 1
```競合はなく、空でない唯一の有効なグループにはそのゴリラが含まれるため、答えは次のようになります。```
1
```長さが 2 以上のチェーンのみをカウントするソリューションでは、誤ってゼロが出力される可能性があります。 

ゴリラが 2 匹おきに選択されるチェーンを考えてみましょう。```
Input:
5 1
```競合チェーンは次のとおりです。```
1 - 2 - 3 - 4 - 5
```答えはそうではありません`5`。 有効な選択肢は次のとおりです。`{1,3,5}`、`{1,3}`、`{2,4}`、他にもたくさんあります。 常に可能な限り最大数のゴリラを取得する貪欲な戦略は失敗します。1 つの頂点を選択すると、利用可能な隣接頂点が変化するためです。 

複数の切断されたチェーンを考えてみましょう。```
Input:
6 3
```チェーンは次のとおりです。```
1 - 4
2 - 5
3 - 6
```各チェーンからの選択肢は独立しているため、最終的な答えは 3 つのチェーンすべてからの可能性を組み合わせる必要があります。 グラフ全体を 1 つのパスとして扱うと、間違ったカウントが生成されます。 

## アプローチ

 ブルートフォース ソリューションでは、ゴリラのすべてのサブセットを試し、その中に競合するペアが出現するかどうかを確認できます。 サブセットは、競合グラフからのエッジが含まれていない場合にのみ有効であるため、このチェックは正しいです。 ただし、`2^N`サブセットの場合、迅速な有効性チェックを行ったとしても、これはすぐに不可能になります。`N`大きいです。 

もう少し良いアイデアは、最初に競合のグラフを作成することです。 グラフ表現によってどのペアが重要であるかが正確にわかるため、総当り的なアプローチは機能しますが、それでも探索する可能性が多すぎます。 重要な観察は、このグラフの形状が非常に制限されていることです。 

どのゴリラにも、対立する隣人は最大でも 2 匹います。`id - K`そして`id + K`。 加算または減算を繰り返すため、サイクルは存在できません。`K`ID は有効範囲を出るまで常に一方向に移動します。 したがって、接続されているすべてのコンポーネントは単純なチェーンです。 

残りの問題は、チェーンのコレクション内の独立したセットをカウントすることです。 長さのあるチェーンの場合`c`、 させて`dp[c]`は頂点を選択する方法の数になります。 1 つのエンドポイントに注目すると、それを選択せず​​、`dp[c-1]`残りの選択肢を選択するか、それを選択してもその隣を選択できず、そのままになります`dp[c-2]`選択肢。 まさにフィボナッチ回帰です。 

コンポーネントは相互に影響を及ぼさないため、すべてのチェーンからの選択肢の数を増やします。 この製品には空の選択範囲が含まれているため、最後に 1 を減算します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N) | O(N) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 考えられるすべての長さのチェーンの独立セットの数を事前計算します。 繰り返しを使用する`ways[i] = ways[i-1] + ways[i-2]`、 と`ways[0] = 1`そして`ways[1] = 2`。 最初の値は空のチェーンから何も選択しないことを表し、2 番目の値は単一のゴリラを選択するか、何も選択しないことを表します。 
2. すべてのゴリラを未訪問としてマークします。 未訪問のゴリラはそれぞれ、競合グラフ内の新しい接続コンポーネントの開始を表します。 
3. すべてのゴリラ ID を確認します。 未訪問の ID ごとに、次のシーケンスに従います。`id, id + K, id + 2K, ...`ID が有効なままです。 この連鎖に属するゴリラの数を数えてください。 
4. 答えを乗算します。`ways[length]`このチェーンの場合。 異なるチェーン内の選択は決して相互作用しないため、乗算が機能します。 
5. すべてのチェーンが処理されたら、1 を減算して空のグループを削除します。 

なぜ効果があるのか:

 選択されたペアはエッジを共有できないため、すべての有効なグループ化はまさに競合グラフの独立したセットです。 競合グラフは、互いに素なチェーンの集合です。 各チェーンについて、最初の頂点が選択されているかどうかを判断することによって、反復ではすべての可能な独立セットが 1 回だけカウントされます。 チェーン数を乗算すると、個別のコンポーネントからのすべての独立したセットが結合されます。 空のセットを削除すると、空ではない有効なグループがそのまま残ります。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

MOD = 10**9 + 7

def solve():
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return

    n, k = data[0], data[1]

    fib = [0] * (n + 2)
    fib[0] = 1
    fib[1] = 2
    for i in range(2, n + 1):
        fib[i] = (fib[i - 1] + fib[i - 2]) % MOD

    seen = [False] * (n + 1)
    ans = 1

    for i in range(1, n + 1):
        if not seen[i]:
            length = 0
            x = i
            while x <= n:
                seen[x] = True
                length += 1
                x += k
            ans = (ans * fib[length]) % MOD

    print((ans - 1) % MOD)

if __name__ == "__main__":
    solve()
```フィボナッチ配列には、考えられるすべてのチェーン サイズに対する有効な選択の数が保存されます。 空のチェーンには有効な選択が 1 つあり、長さ 1 のチェーンにはゴリラを選択するか選択しないかという 2 つの選択があるため、初期化は通常のフィボナッチ数列とは少し異なります。 

メインループは接続されたコンポーネントを検索します。 未訪問のIDから繰り返し追加`K`そのチェーン内の頂点を正確に訪問します。 隣接するものは ID の差によって直接決定されるため、別のグラフを構築する必要はありません。 

乗算は、チェーンがカウントされた直後に行われます。 これにより、コンポーネントの保存が回避され、実装が線形に保たれます。 

Python にはオーバーフローの問題はありませんが、すべての乗算は剰余で削減されます。`10^9 + 7`保存された値を小さく保ち、必要な出力と一致させるため。

## テストケース```python
import sys
import io

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    data = list(map(int, sys.stdin.buffer.read().split()))
    if data:
        n, k = data[0], data[1]
        MOD = 10**9 + 7

        fib = [0] * (n + 2)
        fib[0] = 1
        fib[1] = 2
        for i in range(2, n + 1):
            fib[i] = (fib[i - 1] + fib[i - 2]) % MOD

        seen = [False] * (n + 1)
        ans = 1

        for i in range(1, n + 1):
            if not seen[i]:
                length = 0
                x = i
                while x <= n:
                    seen[x] = True
                    length += 1
                    x += k
                ans = ans * fib[length] % MOD

        print((ans - 1) % MOD)

    result = sys.stdout.getvalue()

    sys.stdin = old_stdin
    sys.stdout = old_stdout
    return result

assert run("1 1\n") == "1\n", "single gorilla"
assert run("5 1\n") == "12\n", "one long chain"
assert run("6 3\n") == "26\n", "multiple chains"
assert run("4 10\n") == "15\n", "no conflicts"

 ## 特殊なケース

 単一のゴリラの場合、アルゴリズムは長さ 1 のチェーンを作成します。 フィボナッチ値は`2`、空の選択肢とそのゴリラを含む選択肢を表します。 最後の減算により、空の選択肢が削除され、有効なグループが 1 つ残ります。 

次のような長いチェーンの場合:```
5 1
```アルゴリズムは交互の頂点を貪欲に選択しません。 反復を通じて可能なすべての独立セットをカウントします。 チェーンが貢献する`13`空のものも含めた可能性、そして最終的な答えは`12`。 

次のような複数のチェーンの場合:```
6 3
```から始まるトラバース`1`、`2`、 そして`3`3 つの別々のコンポーネントを発見します。 各コンポーネントは独立して寄与するため、合計は 1 つの大きな構造の数ではなく、3 つのチェーン数の積になります。 

場合の場合`K`次のようなゴリラの数よりも多くなります。```
4 10
```どの ID にも競合する隣接 ID はありません。 すべてのゴリラは長さ 1 のチェーンを形成し、`2^4`サブセットの合計。 空のサブセットを削除すると、`15`、アルゴリズムの結果と一致します。
