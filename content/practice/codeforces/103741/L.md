 ## 解決策
 ## 問題の理解

 長さの順列が与えられています`n`、概念的にはそのプレフィックスを 1 つずつ処理します。 プレフィックスごとに`A[1..k]`と呼ばれる特定の並べ替え手順を実行することを想像します。`SORT`、そして特定の変数が何回あったかを記録するように求められます`m`その実行中に割り当てられます。 

重要な点は、実際には完全な並べ替えプロセスをシミュレートする必要がないということです。 カウントされる操作はプレフィックスの構造に関連付けられており、すべてを最初から再実行することなくその寄与を計算できるという意味で、各プレフィックスは独立しています。 

したがって、出力は配列になります`s`、 どこ`s[k]`変数の回数です`m`の間に割り当てられます`SORT(A[1..k])`。 

制約`n ≤ 10^6`プレフィックスごとに並べ替えプロセスを再計算するソリューションは直ちに除外されます。 たとえ`O(n log n)`繰り返された方法`n`が鈍くなるにもほどがあります。 これにより、プレフィックスを拡張する際に増分状態を維持するソリューションが実現します。 

単純な解釈では、すべてのプレフィックスの並べ替えを個別にシミュレートすることになります。 それはおおよその費用がかかります`O(n^2)`仕分けにかかる内部コストを考慮する前に、作業を進める必要があります。 

より微妙な失敗例は、「並べ替え作業」が再計算なしでプレフィックス間で線形に動作すると仮定することから生じます。 たとえば、プレフィックスごとに最初から再計算すると、小さな入力でも正しく動作しますが、複雑さは爆発的に増加します。 

入力:```
5
4 2 5 3 1
```プレフィックスごとのソート作業を再計算すると、重複する構造が繰り返し処理されます。 この重複はまさに避けなければならないものです。 

## アプローチ

 欠けているのは、仕分け手順で実際に何を測定しているのかを理解することです。 ここには疑似コードは示されていませんが、それが「適応バブル ソート」として記述されており、変数への代入をカウントしているという事実がわかります。`m`このような割り当てはそれぞれ、配列の処理中に反転のようなイベントを発見することに対応していることを強く示唆しています。 

標準的なバブル ソートでは、隣接する要素を交換することで逆転が解決されるたびに、その乱れに事実上 1 回「接触」します。 解釈すると`m`このような更新の数を追跡すると、プレフィックスのソートによる割り当ての合計数は、そのプレフィックス内の反転の数に正確に対応します。 

したがって、各プレフィックスに対して`A[1..k]`、反転数が必要です。 

ペア`(i, j)`そのような`1 ≤ i < j ≤ k`そして`A[i] > A[j]`。 

ブルート フォース ソリューションでは、これをプレフィックスごとに個別に計算します。 それは簡単です: それぞれについて`k`、プレフィックス内のすべてのペアをスキャンします。 これは正しいですが、全体的には二次関数です。 

重要な点は、プレフィックスが入れ子になっているということです。 プレフィックスから移動する場合`k-1`に`k`、新しい要素のみを導入します`A[k]`。 含まれるすべての新しい反転`A[k]`前の要素のみに依存します。 これにより、周波数構造を使用して反転カウントを増分的に維持できるようになります。 

フェンウィック ツリー (バイナリ インデックス付きツリー) を使用して、以前の値が現在の値より小さいか大きいか管理できます。 それぞれの新しい要素は、それよりも大きい既知の要素の数に等しい反転に寄与します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | お(1) | 遅すぎる |
 | フェンウィック ツリー (接頭辞の反転) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各値がこれまでに何回出現したかを保存するデータ構造を維持しながら、左から右への順列を処理します。 

1. 値の範囲にわたってフェンウィック ツリー (バイナリ インデックス付きツリー) を初期化します。`1..n`、最初は空です。 この構造により、表示された要素の数が値以下であるかをクエリし、対数時間で頻度を更新することができます。 
2. 実行中の変数を維持する`inv`現在のプレフィックスの反転カウントを保存します。 最初はそうです`0`。 
3. ポジションごとに`k`から`1`に`n`、値を取得します`x = A[k]`。 
4.挿入する前に`x`、厳密に次の値よりも大きい、以前に挿入された要素の数をクエリします。`x`。 これは次と等しい`(k-1) - count_leq(x)`、 どこ`count_leq(x)`フェンウィックの接頭辞の合計は次のとおりです`x`。 
5. この数値を次のように加算します。`inv`。 これは、配置によって導入されたすべての新しい反転を表します。`x`プレフィックスの最後に。 
6.挿入します`x`頻度を増やすことでフェンウィック ツリーに組み込まれます。`1`。 
7. 現在の値を出力します。`inv`として`s[k]`。 

これが機能する理由は、接頭辞のすべての反転が`k`いずれかがプレフィックスにすでに存在していました`k-1`または新しく追加された要素が含まれる`A[k]`。 新しい反転を形成する他の方法はないため、更新ステップでデルタを完全に取得します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def add(self, i, v):
        while i <= self.n:
            self.bit[i] += v
            i += i & -i

    def sum(self, i):
        s = 0
        while i > 0:
            s += self.bit[i]
            i -= i & -i
        return s

n = int(input())
a = list(map(int, input().split()))

fw = Fenwick(n)
inv = 0
out = []

for i, x in enumerate(a, 1):
    leq = fw.sum(x)
    inv += (i - 1 - leq)
    fw.add(x, 1)
    out.append(str(inv))

print(" ".join(out))
```フェンウィック ツリーがここの中核となる構造物です。 の`sum(x)`呼び出し回数は前の要素の数 ≤`x`なので、それをから引くと、`(i-1)`より大きい要素の数を与える`x`これは、このステップで導入された新しい反転に直接対応します。 

よくある実装の落とし穴は、フェンウィック ツリーのインデックスが 1 から始まることを忘れていることです。置換値がすでに存在するため、値が直接使用されるのはこのためです。`1..n`。

 ## 特殊なケース

 次のような厳密に増加する順列の場合`[1, 2, 3, ..., n]`、フェンウィック ツリーは常に現在の値より大きい要素が 0 であることを報告するため、更新によって反転数が増加することはありません。 各クエリにより、アルゴリズムは定数ゼロ シーケンスを正しく出力します。`fw.sum(x)`常に等しい`i-1`。 

次のような厳密に減少する順列の場合`[n, n-1, ..., 1]`、各新しい要素は、以前のすべての要素よりも小さくなります。 ステップで`k`の場合、クエリは次の場合にゼロを返します。`fw.sum(x)`, そこで追加します`(k-1)`毎回。 これにより、反転カウントの正しい三角シーケンスが生成され、フェンウィック ツリーはクロスプレフィックス依存関係を見逃すことなく、すべての寄与を正しく蓄積します。
