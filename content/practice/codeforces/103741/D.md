 ## 解決策
 ## 問題の理解

 長さの配列が与えられます$n$。 連続したサブ配列ごとに$[l, r]$、その部分配列内の最大要素と最小要素の差に等しい値を定義します。 タスクは、これらの値をすべて明示的に計算することではなく、どの値がランク付けされるかを決定することです。$k$-th すべてのサブ配列の差分が降順でソートされる場合。 

したがって、概念的には、すべての間隔は、その値がどの程度「広がっているか」という 1 つの数値に寄与します。 定数の部分配列はゼロを与えますが、非常に大きな要素と非常に小さな要素の両方を含む部分配列は大きな値を与えます。 

制約は大きいです:$n \le 5 \cdot 10^5$、つまり$O(n^2)$最悪の場合のサブアレイ$10^{11}$。 間隔を列挙するような解決策は直ちに不可能です。 平$O(n \log n)$間隔ごとの計算は除外されます。 

主な問題は、単一の集計値ではなく、すべてのサブ配列範囲にわたる順序統計が要求されることです。 これは通常、「少なくとも X の差」という形式の条件を満たすサブ配列の数を数えてから、X について二分探索する必要があることを示します。 

微妙な落とし穴は、単調性を誤解することです。 閾値を固定すると$X$、「最大値マイナス最小値 ≥ X」という条件は部分配列に対して単調に動作します。部分配列がそれを満たせば、それを含む大きなウィンドウもそれを満たします。 この構造により、2 つのポインターと単調なキューによるカウントが可能になります。 

留意する価値のあるエッジ ケースとしては、すべての要素が等しい配列 (すべての部分配列の値が 0 である配列) や、値が極端に交互に変化する配列 (ほとんどの部分配列に大きな差がある) などがあります。 単純なランキング シミュレーションは、次の場合でも失敗します。$n = 10^4$およそ必要になるため$5 \cdot 10^7$間隔。 

## アプローチ

 直接的なアプローチでは、すべてのサブ配列を列挙し、その最小値と最大値を計算し、結果を保存します。 これは正しいですが、基本的に間隔の数は 2 次です。 と$n = 5 \cdot 10^5$、これは約を意味します$1.25 \cdot 10^{11}$これは実行可能な計算をはるかに超えています。 

重要な観察は、問題を逆転させることです。 すべての違いをリストアップしようとする代わりに、次のことを尋ねます: 固定値について$X$、満たすサブ配列の数$$\max(a[l..r]) - \min(a[l..r]) \ge X?$$この数を素早く計算できれば、二分探索が可能です。$X$。 私たちが欲しい答えは最大のものです$X$少なくともそうなるように$k$部分配列には少なくとも違いがあります$X$。 これが機能するのは、少なくとも差があるサブ配列の数が存在するためです。$X$次のように単調減少します$X$が増加します。 

To compute the count efficiently for a fixed$X$では、現在の最大値と最小値を維持する単調デクを持つ 2 ポインター スライディング ウィンドウを使用します。 右のエンドポイントを拡張し、ウィンドウが「max − min < X」という制約の下でも有効であるように、最適な左のエンドポイントを維持します。 ウィンドウが制約を破るたびに、左ポインタを前方に移動します。 

これにより、チェックごとに線形スキャンが行われます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^2)$|$O(1)$| 遅すぎる |
 | 二分探索 + 2 つのポインター |$O(n \log V)$|$O(n)$| 承認済み |

 ここ$V$考えられる差異の範囲であり、約$2 \cdot 10^9$。 

## アルゴリズムのチュートリアル

 1. 関数を定義する$\text{count}(X)$満たすサブ配列の数を返します$\max - \min \ge X$。 これを直接カウントする代わりに補数カウントを介して計算します。 
2. 固定の場合$X$代わりに部分配列を数えます。$\max - \min < X$。 これは段階的に維持するのが簡単です。 
3. スライディングウィンドウを維持する$[l, r]$2 つの単調デキュー: 1 つは最大値に対して減少し、もう 1 つは最小値に対して増加します。 
4. 展開する$r$左から右に挿入$a[r]$単調性を維持しながら両方の両端子キューに変換します。 これにより、各両端キューの先頭が常に現在のウィンドウの最大値と最小値を表すようになります。 
5. 現在のウィンドウが違反している間$\max - \min < X$、 動く$l$転送して、両端キューから古い要素を削除します。 この縮小ステップにより、ウィンドウが常に制約を満たすことが保証されます。 
6. それぞれについて$r$、で終わるすべてのサブ配列$r$そしてどこからでも始めてください$[l, r]$は制約の下で有効であるため、追加します$r - l + 1$有効な部分配列の数に変換します。 
7. サブアレイの総数は次のとおりです。$n(n+1)/2$。 有効なものを減算すると、少なくとも差がある部分配列の数が得られます。$X$。 
8. 二分探索$X$考えられる差異の範囲内で。 各 Mid について、少なくとも Mid に違いがあるサブ配列の数を計算し、次と比較します。$k$検索を調整します。 

重要なアイデアは、サブ配列値を直接ランク付けする代わりに、問題を単調で効率的にチェック可能なしきい値カウント問題に変換するということです。 

### なぜ効果があるのか

 固定の場合$X$、を満たす部分配列のセット$\max - \min \ge X$二分探索に必要な意味では単調です: 増加$X$有効なサブ配列を削除することのみが可能であり、新しいサブ配列を追加することはできません。 各右端点内で、有効性を強制する最小左境界が最大値と最小値の単調制約によって一意に決定されるため、スライディング ウィンドウは補集合を正確にカウントします。 これにより、有効な領域内で各サブ配列が正確に 1 回カウントされることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from collections import deque

def count_less_than_x(a, x):
    n = len(a)
    maxdq = deque()
    mindq = deque()
    l = 0
    res = 0

    for r in range(n):
        while maxdq and a[maxdq[-1]] <= a[r]:
            maxdq.pop()
        maxdq.append(r)

        while mindq and a[mindq[-1]] >= a[r]:
            mindq.pop()
        mindq.append(r)

        while maxdq and mindq and a[maxdq[0]] - a[mindq[0]] >= x:
            if maxdq[0] == l:
                maxdq.popleft()
            if mindq[0] == l:
                mindq.popleft()
            l += 1

        res += r - l + 1

    return res

def solve():
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    total = n * (n + 1) // 2

    lo, hi = 0, max(a) - min(a)

    ans = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        # count subarrays with diff >= mid
        less = count_less_than_x(a, mid)
        ge = total - less

        if ge >= k:
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1

    print(ans)

if __name__ == "__main__":
    solve()
```このコードは、差がしきい値未満のサブ配列をカウントするヘルパーを中心に構造化されています。 スライディング ウィンドウは 2 つの単調デキューを維持します。1 つは最大候補を追跡し、もう 1 つは最小候補を追跡します。 正確性の重要な点は、ウィンドウ不変式が常に厳密な不等式条件を強制するため、補数が目的のしきい値述語に正確に対応することです。 

二分探索は考えられる答えの値に対して実行され、各チェックによって条件が計数問題に変換されます。 最終的な答えは、少なくとも残る最大のしきい値です。$k$その上の有効な部分配列。 

よくある実装上の間違いは、スライディング ウィンドウ条件内の不等号の方向を混同することです。 チェックは「x 未満」の定義と一致している必要があります。そうでない場合、二分探索の単調性が崩れ、結果が不安定になります。 

## 実用的な例

 ### 例 1

 入力:```
3 2
3 1 2
```すべてのサブ配列:

 | l | r | 部分配列 | 最大-最小 |
 | --- | --- | --- | --- |
 | 1 | 1 | [3] | 0 |
 | 2 | 2 | [1] | 0 |
 | 3 | 3 | [2] | 0 |
 | 1 | 2 | [3,1] | 2 |
 | 2 | 3 | [1,2] | 1 |
 | 1 | 3 | [3,1,2] | 2 |

 降順にソートされた相違点:```
2, 2, 1, 0, 0, 0
```2 番目に大きいのは 2 です。 

これは、アルゴリズムでは、たとえスパンのサブ配列が少なくても、より大きなスパンのサブ配列を優先する必要があることを確認します。 

### 例 2

 入力:```
4 1
1 1 1 1
```すべての部分配列には差分 0 があるため、すべての値は同一です。 k 番目に大きいものは、k に関係なく常に 0 です。 

これは、二分探索では縮退範囲を正しく処理する必要があり、正の差が存在すると仮定してはいけないことを示しています。

from collections import deque

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

        n = len(a)
        maxdq = deque()
        mindq = deque()
        l = 0
        res = 0

        for r in range(n):
            while maxdq and a[maxdq[-1]] <= a[r]:
                maxdq.pop()
            maxdq.append(r)

                mindq.pop()
            mindq.append(r)

            while maxdq and mindq and a[maxdq[0]] - a[mindq[0]] >= x:
                if maxdq[0] == l:
                    maxdq.popleft()
                if mindq[0] == l:
                    mindq.popleft()
                l += 1

            res += r - l + 1

        return res

 ## 特殊なケース

 次のようなすべてが等しい配列の場合、`1 1 1 1`、すべての部分配列には差分ゼロがあります。 スライディング ウィンドウは、いかなる制約にも違反しません。$X > 0$したがって、二分探索は正しく折りたたまれて 0 が返されます。 count 関数は、次のすべての部分配列を返します。$X = 0$これにより、ゼロが唯一の候補値として正しく配置されます。 

次のような 2 要素の極端なケースの場合、`1 100`、サブ配列は 3 つしかなく、最大の差は 1 回だけ表示されます。 二分探索では、1 つのサブ配列でサポートされる唯一の非ゼロしきい値として 99 がすぐに分離されます。 

次のような交互パターンの場合`5 1 5`、複数の重複するサブ配列で大きな差が発生し、最大値と最小値が境界で繰り返しシフトする場合でも、単調キューにより正しいカウントが保証されます。
