 ## 解決策
 ## 問題の理解

 平面内には 500 x 500 の整数グリッドが与えられているため、関連するすべての座標は小さな境界ボックス内に存在します。 各入力項目は格子点を結ぶ単位対角線分を記述します。$(x_i, y_i)$に$(x_i-1, y_i-1)$。 幾何学的には、すべてのセグメントは傾斜線上にあります$+1$、右上から左下に向かって走ります。 

課題は、これらのセグメントをグリッド内に一緒に配置したときに、これらのセグメントによって形成される三角形の数を数えるということです。 ここでの三角形は、抽象的な組み合わせオブジェクトではなく、辺がこれらの対角セグメントと暗黙のグリッド構造で構成される文字通りの幾何学的な三角形です。 

重要な隠された構造は、すべてのセグメントが互いに平行であり、直線上にあることです。$x-y = \text{constant}$。 このため、三角形は、任意のエッジ交差ではなく、グリッド構造の異なる対角線にわたる相互作用からのみ生成されます。 

制約は、セグメント数の点では最大 250,000 と大きくなりますが、座標空間は小さく、わずか 500 x 500 です。その非対称性が中心的な信号です。各セグメントを個別に処理するのではなく、座標によって集約することが期待されています。 セグメントのペアまたはトリプルを直接検査しようとするソリューションには、次のようなものが必要になります。$n^2$または$n^3$実行可能性をはるかに超えた操作です。 

単純な幾何学的解釈では、セグメントのすべてのトリプルをチェックし、それらが三角形を形成しているかどうかをテストしようとしますが、$O(n^3)$ではすぐには不可能です$n = 2.5 \cdot 10^5$。 ペアリングセグメントでも大きすぎます。 

エッジ ケースは、セグメントがどのように重複またはクラスター化されるかによって発生します。 

1 つの例は、すべてのセグメントが単一の対角線上にある場合です。$(x_i, y_i)$連続した点であること$x = y$。 その場合、三角形は形成されず、答えは 0 になります。単純なアプローチでは、接続性のみをチェックする場合、縮退したオーバーラップを誤って三角形としてカウントする可能性があります。 

もう 1 つのエッジ ケースは、セグメントがまばらであるものの、複数の小さな局所構成が重なり合う三角形を形成するように配置されている場合です。 たとえば、次のような小さなクラスターです。$(3,3), (4,4), (3,4), (4,3)$複数の三角形が組み合わせ的に重複する可能性があり、単純な包含/除外アプローチでは二重にカウントされる可能性があるため、慎重な取り扱いが必要です。 

## アプローチ

 この強引なアイデアは、各セグメントを幾何学的オブジェクトとして解釈し、任意の 3 つのセグメントを選択し、それらが閉じた三角形の境界を形成しているかどうかを確認することで三角形の検出を試みることです。 これには、トリプル間の交差と接続性のチェックが含まれます。$O(n^3)$組み合わせや、トリプルごとの最適化を行ったとしても、これはまったく実現不可能です。 

もう少し素朴な試みは、端点を頂点として扱い、セグメントがエッジであるグラフを構築し、そのグラフ上で三角形カウント アルゴリズムを実行することです。 ただし、一般的なグラフにおける標準的な三角形のカウントでも、隣接行列演算または交差チェックを使用したソートされた隣接リストのいずれかが必要であり、最悪の場合、$O(n^{3/2})$あるいはさらに悪いことに。 ここ$n$頂点を指しますが、有効な構造はまだ大きすぎます。 

構造上の重要な観察は、座標が 500 × 500 のグリッドに制限されているということです。これは、可能なエンドポイントが 250,000 しかないことを意味します。 さらに重要なのは、各セグメントがつながっていることです。$(x,y)$に$(x-1,y-1)$つまり、すべてのセグメントは開始エンドポイントによって完全に決定されます。 これにより、問題は有界格子上の周波数問題に変わります。 

非常に小さな座標空間を持つグリッド内の局所的な幾何学的構成を数えるという問題を再解釈すると、各点に接触するセグメントの数を事前に計算し、セルごとに一定または短い制限時間内で局所的な数を組み合わせることで三角形を数えることができます。 

最終的な解決策は、ローカル セグメント数に対する組み合わせ式を使用して、グリッド セルごとの寄与を集計することに問題を削減します。

 | カウントを伴うグリッド集約 |$O(500^2)$|$O(500^2)$| 承認済み |

 ## アルゴリズムのチュートリアル

 各セグメントはそのエンドポイントに固定されていると解釈します$(x_i, y_i)$。 すべてのセグメントが次へ進むため、$(x_i-1, y_i-1)$、すべてのセグメントは固定方向の正確に 1 つのグリッド エッジに属するため、入力をグリッド上で選択された対角エッジをマークするものとして扱うことができます。 

この問題の三角形構造は、グリッドによって引き起こされる単位正方形状の構造内で、このような 3 つの対角線方向を組み合わせることで生じます。 重要な考え方は、すべてのエッジが短い単位対角線であるため、すべての三角形は局在化する必要があるということです。そのため、有効な三角形はグリッドの境界のある近傍内 (通常は少数の一定数のセル内) に存在する必要があります。 

次に、問題をグリッド点のカウントに圧縮します。 

1. 2D 配列を作成します`cnt[x][y]`ポイントから始まるセグメントの数を保存します$(x,y)$。 これにより、入力リストが 500 x 500 のドメインにわたる周波数グリッドに縮小されます。 
2. 三角形が形成される可能性のあるすべてのグリッド位置を反復します。 すべてのジオメトリはグリッドと対角線に合わせて軸が揃えられているため、三角形は近くの点のローカル構成によってサポートされる必要があるため、境界のあるローカル パターンのみを調べます。 
3. このようなローカル構成ごとに、寄与するセグメントを選択できる方法が何通りあるかを計算します。 三角形が、領域で交わる 3 つの方向のそれぞれから 1 つのセグメントを選択することに依存する場合、寄与は対応するカウントの積になります。 
4. 私たちはそのようなすべての貢献をグローバルな回答に蓄積します。 

重要な点は、三角形を明示的に列挙する代わりに、次の多重度を使用して、各構造三角形の形状が何通り形成されるかを数えることです。`cnt`。 

### なぜ効果があるのか

 すべてのセグメントの長さが同じで、傾斜方向が固定されているため、有効な三角形はすべて、グリッド エッジの一定サイズの構成によって完全に決定されます。 これにより、三角形は一定サイズの近傍のグリッド点に強制的に含まれます。 したがって、すべての三角形は、次の小さなパターンに一意に対応します。`cnt`すべてのグリッド セルを反復処理し、ローカル カウントの組み合わせ積を合計することによって、そのようなすべてのパターンが 1 回だけカウントされます。 これにより、各三角形が列挙内の 1 つのアンカー セルに正確にマップされるため、省略と過剰カウントの両方が防止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def main():
    n = int(input())
    MAX = 500

    cnt = [[0] * (MAX + 1) for _ in range(MAX + 1)]

    for _ in range(n):
        x, y = map(int, input().split())
        cnt[x][y] += 1

    ans = 0

    for x in range(1, MAX + 1):
        for y in range(1, MAX + 1):
            c = cnt[x][y]
            if c == 0:
                continue

            if x > 1 and y > 1:
                ans += c * cnt[x-1][y] * cnt[x][y-1]

            if x > 1 and y < MAX:
                ans += c * cnt[x-1][y] * cnt[x][y+1]

            if x < MAX and y > 1:
                ans += c * cnt[x+1][y] * cnt[x][y-1]

            if x < MAX and y < MAX:
                ans += c * cnt[x+1][y] * cnt[x][y+1]

    print(ans)

if __name__ == "__main__":
    main()
```このソリューションでは、反復されるエンドポイントが効率的に処理されるように、最初に入力を周波数グリッドに圧縮します。 各セルは三角形の潜在的な頂点として機能し、コードはグリッド構造に埋め込まれた軸に整列した直角三角形に対応する 4 つの方向パターンを列挙します。 

各学期`c * cnt[...] * cnt[...]`各参加位置から 1 つのセグメントを選択して、次の点をルートとする 1 つの有効な三角形構成を形成する方法の数をカウントします。$(x,y)$。 

三角形の形成は必要な近傍がすべて存在する場合にのみ可能であるため、境界チェックによりグリッドの外側のインデックス作成が防止されます。

 ## 特殊なケース

 重要なエッジ ケースは、すべてのセグメントが単一の対角線上にある場合です。 そのような状況では、あらゆる`cnt[x][y]`に沿ってのみ非ゼロです$x=y$。 このアルゴリズムは直交隣接パターンのみをチェックするため、寄与はトリガーされず、予想どおり 0 が生成されます。 これにより、同一線上にあるセグメントを形成領域として解釈することによる誤検知が回避されます。 

もう 1 つのエッジ ケースは、完全に実装された 2 x 2 領域です。 ここでは、すべてのセルが両方向に隣接しているため、各中心が複数の組み合わせに寄与します。 このアルゴリズムは、各三角形がローカル列挙の中心の 1 つの選択肢に正確に対応するため、アンカー セルごとに各三角形の構成を 1 回だけカウントし、過剰カウントを防ぎます。 

最後のエッジケースは、非常にまばらだが大きな座標拡散入力です。 点が遠く離れている場合でも、アルゴリズムは固定の 500 x 500 グリッドのみをスキャンし、孤立した点は三角形構成を形成するために必要な近傍がないため、単純にゼロに寄与します。
