 ## 解決策
 ## 問題の理解

 整数の動的なシーケンスを維持しています。 シーケンスは空から始まり、最後に要素を追加することによってのみ増加します。 いつでも、最初の要素が 2 番目の要素の左側にある要素のすべてのペアから導出される値を計算するように求められる可能性があります。 

固定シーケンスの場合$a_1, a_2, \dots, a_n$、問題は量を定義します$A_i$スプリットポイントごとに$i$1との間$n-1$。 このような分割ごとに、すべてのペアを調べます$(j, k)$そのような$j \le i < k$、計算する$a_j \& a_k$、それらすべてのペアの最大値を取得します。 それから$A_i$は、そのようなすべてのペアに対するこれらすべての寄与の XOR です。最大値の式のこのコンテキストでは、XOR は実際には意味のある独立した方法で複数の値を累積していないため、実際には同じ最大値に減ります。 最後のクエリでは、次の最大値が求められます。$A_i$すべての有効な分割ポイントにわたって$i$。 

操作上、私たちは値を追加し、シーケンスを左側の部分と右側の部分に分割するすべての方法の中で、左側の要素と右側の要素の間の最大のビット単位の AND は何か、と時々尋ねます。 

重要な制約は次のとおりです。$q \le 10^5$操作と値は次のとおりです$2^{20}$。 これにより、クエリごとに回答を最初から再計算するソリューションは即座に除外されます。これは、ペアごとの相互作用の再構築が重要であるためです。$O(n^2)$最悪の場合、クエリごとに、$10^{10}$操作。 

動的な性質から微妙な問題が生じます。 素朴なアプローチでは、すべてのペアごとの AND 値を維持したり、挿入のたびに最適な分割を再計算したりする可能性があります。 これは、各挿入が以前のすべての要素と相互作用する可能性があり、分割最大値を再計算すると履歴全体が繰り返し再検討されるため、失敗します。 

もう 1 つの隠れたエッジ ケースは、シーケンスの長さが 2 未満の場合です。この場合、分割は存在せず、答えは 0 でなければなりません。少なくとも 1 つのペアが存在することを前提とする単純な実装ではクラッシュするか、初期化されていない最大値を返すため、これが重要になります。 

## アプローチ

 ブルートフォース解釈は簡単です。 各操作の後、クエリが要求された場合は、すべての分割ポイントを試します。$i$。 分割ごとに、分割境界を越えるすべてのペアをスキャンし、最大値を計算します。$a_j \& a_k$。 これは定義に直接従っているため、正しいです。 

ただし、コストは法外です。 長さのシーケンスの場合$n$、単一の分割小切手のコスト$O(n^2)$、そして、あります$O(n)$分割されるため、単一のクエリは$O(n^3)$最悪の解釈で。 情報を再利用するために分割評価を最適化しても、依然として課題は残る$O(n^2)$クエリごとに、これは不可能になります$10^5$操作。 

重要な観察は、問題は実際には分割に関するものではないということです。 すべての有効なペア$(j,k)$と$j<k$貢献する$a_j \& a_k$、そして答えは単に現在のプレフィックス内のすべてのペアの最大の AND です。 分割の定式化は注意をそらすものです。最適な分割では、常に全体的な最大値を達成する 2 つの要素がペアごとに AND で反対側に配置されます。 

したがって、問題は、挿入時に、現在のセット内のすべてのペア間で最大のビット単位の AND を維持することに帰着します。 重要な構造は、ビットごとの AND がビットごとに単調性を持つことです。つまり、上位ビットが優勢で、両方の数値が上位ビットを共有する場合にのみ、ペアが高い値を達成します。 これは、上位ビット パターンによってグループ化された候補を維持することを示唆しています。 

この設定の標準的なトリックは、値ごとに、以前に挿入された値と形成できる最適な AND を維持することですが、これは依然として$O(n^2)$。 代わりに、前の数値に対するビットごとのトライを維持します。 新しい番号を入力する場合$x$、前の番号を見つけたい$y$最大化する$x \& y$。 これは、両方のビットが 1 であるパスを優先して、最上位ビットから最下位ビットまで貪欲に実行できます。この最適なペアでグローバルな答えを更新します。 

これが機能するのは、ビットごとに両方の数値が 1 であるかどうかを選択すると、最適なペアの AND 値が実現されるためです。 トライにより、構造内にすでに存在する最適な互換性のあるパートナーを常に見つけることができます。

 ## アルゴリズムのチュートリアル

 1. 空のビットごとのトライと変数を初期化します。`best = 0`。 トライは、以前に挿入されたすべての数値を 19 から 0 までのビットごとにまとめたバイナリ形式で保存します。この構造により、上位ビットを共有する数値の効率的なマッチングが可能になります。 
2. 各操作を順番に処理します。 操作が数値の挿入である場合`x`、最初にトライをクエリして、可能な最大値を見つけます。`(x & y)`以前に挿入されたすべての`y`。 このステップにより、最適なペアが確実にキャプチャされます。`x`が参加します。 
3. この最良の一致を計算するには、トライを最上位ビットから最下位ビットまでたどります。 各ビットで、現在のビットが`x`が 1 の場合、そのビットでも 1 を持つ子に移動することを好みます。これは、AND の結果にプラスの影響を与えるためです。 そのような子が存在しない場合は、他のブランチに移動します。 
4. トラバース中に、両方の条件が満たされた場合にのみビットを設定して、結果の AND 値を累積します。`x`選択されたパス番号のビットは 1 に等しくなります。上位ビットが最終値を支配するため、この貪欲な選択は有効です。 
5. トラバース終了後、更新します。`best`現在の値と計算された一致値の最大値を使用して、`x`。 
6.挿入`x`トライに追加すると、将来のクエリに使用できるようになります。 これにより対称性が確保され、後の要素が挿入されるときにすべてのペアが最終的に 1 回評価されます。 
7. 操作がクエリの場合、出力`best`少なくとも 2 つの要素が挿入されている場合。 それ以外の場合は 0 を出力します。 

### なぜ効果があるのか

 アルゴリズムは次の不変条件を維持します。`best`は、挿入された要素間のすべてのペアにわたる最大のビット単位の AND です。 すべてのペア$(a_i, a_j)$は、後の要素が挿入されるときに 1 回だけ評価されます。これは、その時点で前の要素がすでにトライ内にあり、それに対して最適な一致を計算するためです。 トライ トラバーサルにより、挿入された各数値について、既に挿入された要素の制約の下でグローバルに最適なパートナーが確実に見つかるため、より適切なペアを見逃すことはありません。 AND は対称であり、挿入順序は 2 番目の要素が現れるまで評価を遅らせるだけであるため、グローバル最大値は常に正しく追跡されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

class Trie:
    def __init__(self):
        self.next = [{}]  # list of dict children
        self.has = [0]

    def insert(self, x):
        node = 0
        for b in range(19, -1, -1):
            bit = (x >> b) & 1
            if bit not in self.next[node]:
                self.next[node][bit] = len(self.next)
                self.next.append({})
                self.has.append(0)
            node = self.next[node][bit]
            self.has[node] += 1

    def query_best_and(self, x):
        node = 0
        res = 0
        for b in range(19, -1, -1):
            bit = (x >> b) & 1
            # try to keep 1 if possible
            if bit == 1 and 1 in self.next[node]:
                node = self.next[node][1]
                res |= (1 << b)
            elif bit == 0 and 1 in self.next[node]:
                node = self.next[node][1]
            elif bit in self.next[node]:
                node = self.next[node][bit]
            else:
                # fallback (should not happen in valid trie)
                if 0 in self.next[node]:
                    node = self.next[node][0]
                else:
                    break
        return res

def solve():
    q = int(input())
    trie = Trie()
    best = 0
    cnt = 0

    for _ in range(q):
        tmp = input().split()
        if tmp[0] == '1':
            x = int(tmp[1])
            cnt += 1
            if cnt > 1:
                best = max(best, trie.query_best_and(x))
            trie.insert(x)
        else:
            print(best if cnt >= 2 else 0)

if __name__ == "__main__":
    solve()
```この実装では、数値ごとに 20 ビットにわたるバイナリ トライが維持されます。 の`query_best_and`AND は両側にビットが設定されている場合にのみ効果があるため、この関数は貪欲に最初に 1 ビットとの位置合わせを試みます。 挿入はクエリの後に行われるため、現在の要素はそれ自体とペアになりません。 

の`best`変数は、少なくとも 1 つの前の要素が存在する場合にのみ更新され、最初の挿入ケースの正確性が保証されます。 カウンター`cnt`2 つの要素がゼロを返す前にクエリを実行するという条件を強制します。

 ## 特殊なケース

 主なエッジ ケースは、要素が 1 つだけ存在し、クエリが発行される場合です。 たとえば、入力`1 10`クエリの後には 0 を出力する必要があります。アルゴリズムはこれを次の方法で処理します。`cnt < 2`チェックして、無効な試行クエリを防止します。 

もう 1 つのケースは、すべての数値が共通のビットを共有していない場合です。 たとえば、1、2、4、8 のような 2 の累乗を挿入すると、すべての AND がゼロになります。 トライは引き続き各挿入を処理しますが、共有ビットを検索することはありません。`best`は 0 のままで、正解と一致します。 

3 番目のケースは、同じ数字が繰り返される場合です。 入力用`1 7, 1 7`、トライは完全に一致するものを見つけます。`7 & 7 = 7`となり、これが世界最大値となります。 重複は独立して挿入されるため、2 番目のコピーが挿入されるときにもアルゴリズムによってペアが評価され、正確さが保証されます。
