 ## 解決策
 ## 問題の理解

 1 から n までの数字の順列が与えられていますが、その順序はわかりません。 直接構築する代わりに、位置間の制約が与えられます。 各制約は、「位置 x に配置される値は、位置 y に配置される値よりも小さい」という形式になります。 

タスクは、このようなすべての不等式を同時に満たす長さ n の順列の数を数え、998244353 を法とする答えを返すことです。 

これを再解釈する便利な方法は、置換値 1 ～ n が位置 1 ～ n に割り当てられていると考えることです。 各制約は 2 つの位置を比較し、そこに割り当てられた値間の順序付けを強制します。 したがって、すべての制約は事実上、ある位置が別の位置より小さいラベルを受け取る必要があることを示す有向エッジになります。 

制約に関する重要な観察は、各位置が xi として最大 1 回しか出現しないということです。 これは、すべてのノードには最大 1 つの外向き制約があるため、制約によって形成される有向グラフの出次数はノードごとに最大 1 つであることを意味します。 したがって、構造は有向チェーンと有向サイクルの集合ですが、サイクルはループの周りに厳密な不平等を強制するため、直ちに不可能になります。 

したがって、有効なインスタンスはすべて、チェーンの有向フォレストのように動作する必要があります。 

制約スケールは重要です。n は最大 2⋅10^6 なので、O(n log n) または O(n) の解は許容されますが、階乗のような列挙やサブセットにわたるグラフ DP を伴うものは不可能です。 問題を線形時間または線形時間に近い時間で処理できる構造に還元する必要があります。 

制約がサイクルを形成する場合、微妙なエッジケースが発生します。 たとえば:

 n = 3

 制約: 1 < 2、2 < 3、3 < 1

 これにより、p1 < p2 < p3 < p1 が強制されますが、これは不可能であるため、答えは 0 でなければなりません。サイクル検出を無視する単純なカウント手法では、順列が誤ってカウントされます。 

もう 1 つのエッジ ケースは、制約がまったくない場合です。 この場合、すべての順列は有効であるため、答えは n! になります。 この縮退の場合、どのような解も階乗に還元する必要があります。 

## アプローチ

 問題を直接解決しようとする場合は、1 から n までの値を割り当て、すべての順列の制約をチェックすることを考えるかもしれません。 それは n を与えます! 順列を作成し、それぞれをチェックするコストは O(m) であるため、合計の複雑さは O(n!⋅m) となり、n が 20 程度の小さい場合でも完全に実行不可能です。 

より構造化されたブルート フォース アプローチは、これをトポロジカルな順序付け問題として見ることです。制約によって部分順序が定義され、この順序の線形拡張をカウントしたいと考えます。 一般的な DAG の線形拡張のカウントは #P-complete であるため、サブセットにわたる一般的な DP がスケールされることは期待できません。 

重要な簡素化は特別な構造によるものです。各位置には出力制約が最大 1 つあります。 これは、グラフが独立したチェーンに分解され、ノードが他の複数のノードより小さくなければならないという分岐制約がないことを意味します。 この制限により、線形拡張をカウントする複雑さが大幅に解消されます。 

各チェーンはそのノード間で厳密な順序付けを強制しますが、異なるチェーン間では相対的なインターリーブ以外の制約はありません。 問題は、内部秩序を尊重しながらこれらのチェーンをどれだけの方法でインターリーブできるかを数えることになります。 

ここで、より強力な点に注目してください。各ノードには最大でも 1 つの出力エッジがあるため、すべての接続コンポーネントは単純な有向パスまたはサイクルのいずれかになります。 サイクルはインスタンスを無効にするため、パスのみを扱います。 各パスは内部的にすでに固定されています。つまり、そのパス上のすべてのノードは、パスの方向に従って厳密に昇順で表示される必要があります。 

したがって、各パスは内部配置が固定された「ブロック」のように動作し、内部順序を維持しながらこれらのブロックに順列ランクを割り当てる方法のみを選択します。

最終的な結果は、チェーンの長さをカウントする多項式タイプになり、チェーン サイズの階乗の積で階乗を割ったものに単純化されます。 ただし、各ノードは独自の位置であり、制約は位置を比較するだけであるため、正しい単純化はさらにきれいになります。各有効な構造はトポロジー配置ごとに正確に 1 方向に寄与し、答えは n の階乗から強制比較の補正を引いたものになり、最終的には階乗 n を計算し、独立したチェーンのサイズで除算することになります。 

これにより、DSU または単純なトラバーサルを使用してチェーンの長さを計算する O(n) ソリューションが得られます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(n!・m) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各位置 x が y へ向かうエッジを最大 1 つ持つ有向グラフを構築します。 これは、各制約 p[x] < p[y] を直接エンコードします。 この構造により、任意のグラフではなく、互いに素なチェーンを操作できるようになります。 
2. 有向グラフ内のサイクルをチェックして無効性を検出します。 各ノードの出次数は最大 1 であるため、任意のノードからのポインタをたどり、同じ走査で以前に見たノードを再訪問すると、サイクルが存在します。 循環が見つかった場合、矛盾する不等式が強制されるため、答えはすぐにゼロになります。 
3. 入力エッジがない各ノードについて、出力エッジに沿って前方へのトラバースを開始し、そのチェーンの長さを計算します。 各走査で訪問ノードがマークされるため、ノードが 2 回処理されることはありません。 
4. すべての長さのチェーンを収集します。 これらは、内部順序は固定されていますが、チェーン間の相対的な順序は自由である独立したセグメントを表します。 
5. 有効な順列の数を、n の階乗をすべてのチェーン長の階乗の積で割ったものとして計算します。 この分割は、各チェーン内で位置が自由に変更できなくなっているという事実を説明しています。 
6. 階乗値の逆剰余を使用して、結果の剰余 998244353 を返します。 

重要な考え方は、各チェーンが厳格な内部順序を強制するため、置換の自由はチェーンをグローバルにインターリーブする方法にのみ存在するということです。 すべての要素が個別であり、制約が分岐することがないため、このインターリーブは多項係数にきれいに分解されます。 

### なぜ効果があるのか

 各チェーンは、有効な置換において相対的な順序を保持する必要がある、完全に順序付けされた位置のサブセットを表します。 チェーンが固定されると、有効な順列を構築することは、各チェーンがソートされた順序で表示されるように、すべての要素のグローバル順序を選択することと同じになります。 これは、接続されたコンポーネントがチェーンであるポーズセットの線形延長を正確に数えることになります。 コンポーネントは相互作用しないため、拡張の総数はチェーン サイズに対する多項係数となり、階乗除算式が得られます。 チェーン間の制約によって追加の制限が導入されないため、独立性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MOD = 998244353

def solve():
    n, m = map(int, input().split())
    
    nxt = [-1] * (n + 1)
    indeg = [0] * (n + 1)
    
    for _ in range(m):
        x, y = map(int, input().split())
        if nxt[x] != -1 and nxt[x] != y:
            print(0)
            return
        nxt[x] = y
        indeg[y] += 1

    # cycle detection + chain length computation
    vis = [0] * (n + 1)
    chain_lens = []

    def dfs(start):
        cur = start
        length = 0
        path = []
        while cur != -1:
            if vis[cur] == 1:
                # already processed
                return 0
            if vis[cur] == 2:
                break
            vis[cur] = 1
            path.append(cur)
            nxt_node = nxt[cur]
            cur = nxt_node
            length += 1
        
        for v in path:
            vis[v] = 2
        
        return length

    for i in range(1, n + 1):
        if indeg[i] == 0 and vis[i] == 0:
            length = dfs(i)
            if length:
                chain_lens.append(length)

    # remaining unvisited nodes are cycles or isolated leftovers
    for i in range(1, n + 1):
        if vis[i] == 0:
            length = dfs(i)
            if length:
                chain_lens.append(length)

    # precompute factorial
    fact = [1] * (n + 1)
    for i in range(1, n + 1):
        fact[i] = fact[i - 1] * i % MOD

    inv_fact = [1] * (n + 1)
    inv_fact[n] = pow(fact[n], MOD - 2, MOD)
    for i in range(n, 0, -1):
        inv_fact[i - 1] = inv_fact[i] * i % MOD

    # check if any cycle implied (invalid traversal)
    # if we ever encountered incomplete chain coverage, treat as invalid
    if sum(chain_lens) != n:
        print(0)
        return

    ans = fact[n]
    for c in chain_lens:
        ans = ans * inv_fact[c] % MOD

    print(ans)

if __name__ == "__main__":
    solve()
```各ノードには出力エッジが 1 つしかないため、実装ではまず制約を関数グラフとしてエンコードします。 これによりチェーン構造が保証され、複雑な隣接リストを使用せずに線形トラバースが可能になります。 

DFS スタイルの走査は、最大 2⋅10^6 の n での再帰の深さの問題を回避するために反復的です。 また、スリーステート システム内のノードにマークを付けて、サイクルを検出し、処理されたノードの再訪問を回避します。 

階乗および逆階乗は、高速な多項計算をサポートするために最大 n まで事前計算されます。 最後の乗算/除算ステップでは、導出された組み合わせ公式を実装します。 

実装の微妙な詳細は、すべてのノードが 1 つのチェーンまたはサイクルに確実に属するようにすることです。 未訪問のノードがある場合、またはトラバース長がすべてのノードをカバーしていない場合、その構造は無効または循環的であるため、正しくゼロを返します。 

## 実用的な例

 ### 例 1

 入力:

 n = 3、m = 1

 制約: 1 → 2

 チェーンを計算します。 

| ステップ | ノード | 次へ | 訪問 | チェーン構築 |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | [1] | 開始 |
 | 2 | 2 | -1 | [1,2] | 停止 |

 チェーンの長さ = [2]、孤立したノード 3 は [1] を与えます

 | チェーン | 長さ |
 | --- | --- |
 | 1→2 | 2 |
 | 3 | 1 |

 答え = 3! / (2!・1!) = 6 / 2 = 3

 これは、1 と 2 は順序を維持する必要があるが、3 はどこにでも配置できるという考えと一致します。 

### 例 2

 入力:

 n = 3、m = 2

 制約: 1 → 2、2 → 3

 | ステップ | ノード | 次へ | 訪問 | チェーン |
 | --- | --- | --- | --- | --- |
 | 1 | 1 | 2 | [1] | 開始 |
 | 2 | 2 | 3 | [1,2] | 続ける |
 | 3 | 3 | -1 | [1,2,3] | 停止 |

 チェーンの長さ = [3]

 答え = 3! /3! = 1

 完全な順序を尊重する順列は 1 つだけです: 1 < 2 < 3。

| スペース | O(n) | グラフ ポインター、訪問状態、および階乗テーブルの配列 |

 ## 特殊なケース

 制約によって形成されるサイクルは、最も重大な失敗ケースです。 たとえば、制約 1 < 2 および 2 < 1 を持つ入力 2 は、すぐにゼロを返す必要があります。 アルゴリズムは、トラバーサルがアクティブなノードを再訪問するときにこれを検出し、機能グラフにサイクルをマークします。 

孤立ノードのケースは、位置にまったく制約がない場合に発生します。 その場合、長さ 1 のチェーンを形成し、階乗因数 1 に寄与し、グローバル階乗スケーリングを除いて全体の答えは変更されません。 

完全に制約されたチェーンでは、制約に従ってすべての要素を順序付ける方法が 1 つだけ存在するため、答えは 1 に減ります。 トラバーサルではすべてのノードが 1 つのチェーンにマージされ、多項除算では階乗 n ごとに階乗 n が折りたたまれます。
