 ## 解決策
 ## 問題の理解

 1 から N までの番号が付けられた N 個のライトがあります。最初はすべてのライトが点灯しています。 k 個のコマンドにはそれぞれ正の整数 x が含まれており、そのコマンドは x の倍数であるすべてのライトを切り替えます。 ライトを切り替えると、オンからオフ、またはオフからオンに変わります。 

コマンドは固定された順序で到着するため、コマンドの直後に消灯するライトの最大数が必要です。 最初のコマンドを実行する前の初期状態では、消灯はゼロです。 

コマンドの数という点では制約は小さく、k≤100 ですが、N は 10 6 に達する可能性があります。直接シミュレーションでは、すべてのコマンドのすべての倍数を扱う必要があります。 100 個のコマンドがすべて 1 の場合、すべてのコマンドは 10 6 個のライトすべてに影響し、10 8 個のライトが個別に更新されます。 これは、特に Python では 1 秒の制限には多すぎます。 ライトのグループ全体をよりコンパクトに表現する必要があります。 

自然な表現はビットセットです。 1 ビットは 1 つのライトを表し、ビット 0 はライト 1、ビット 1 はライト 2 などに対応します。 コマンドによって切り替えられるライトのセットは、1 つの大きな整数になります。 グループ全体の切り替えは 1 つの XOR 操作になり、消灯ライトのカウントは人口カウントになります。`int.bit_count()`。 Python はパックされたマシンワードに対してこれらの操作を内部的に実装するため、作業はライトごとに 1 つの Python 操作ではなく、最適化されたネイティブ コードで実行されます。 パイソンの`int.bit_count()`設定されているビット数を直接返します。 

誤って対処しやすい特殊なケースがいくつかあります。 と`N=1`、コマンド`1`唯一のライトを切り替えるので、答えは 1 です。```
1
1
1
```出力は`1`。 最終状態のみをチェックし、コマンド後の状態を誤って無視するソリューションもここでは機能しますが、より一般的な教訓は、最大値は中間の瞬間に発生する可能性があるということです。 

コマンドの繰り返しも別の罠です。```
10
2
2
2
```最初のコマンドの後、ライト 2、4、6、8、および 10 がオフになるため、答えは 5 です。2 番目のコマンドはそれらをすべてオンに戻しますが、答えは 5 のままです。最終構成のみを検査するソリューションでは、誤って 0 が出力されます。 

可能な最大のコマンド値にも、正しい境界処理が必要です。```
5
2
5
1
```コマンド後`5`、ライト5だけが消えています。 指示`1`すべてのライトを切り替えて、4 つのライトをオフにし、5 つのライトをオンにします。 正しい出力は 4 です。ループが誤って停止してしまいます。`N - 1`ライト5を見逃すでしょう。 

## アプローチ

 単純なソリューションでは、すべてのライトの状態を保存し、その倍数をたどって各コマンドを処理します。 コマンド x の場合、x、2x、3x、… にアクセスし、対応する各ライトを切り替え、現在のオフのライトの数を維持し、答えを更新します。 これは正しいです。影響を受けるすべてのライトは、そのコマンドに対して 1 回だけアクセスされ、カウントを段階的に維持することで、操作のたびに N 個のライトすべてをスキャンすることが回避されます。 

問題は最悪のケースだ。 すべてのコマンドが`1`、各コマンドは N 個のライトを訪問します。 N=10 6 および k=100 の場合、つまり 100⋅10 6 =10 8 ライトの更新です。 C++ リファレンス アプローチでは、最適化されたネイティブ コードでこの単純なシミュレーションを処理できますが、Python での同じループは 1 秒の制限には適していません。 公式の問題の制約は確かに N≤10 6、k≤100 で、制限時間は 1 秒です。 

重要な点は、コマンドを 1,000,000 個の個別のブール値として表す必要がないということです。 当然、これは位置のセットであり、セットの切り替えは正確に XOR です。 都市の状態全体を 1 つの Python 整数としてエンコードできます。 ビット j-1 が 1 の場合、ライト j はオフになります。 コマンド x のマスクには、x が j を除算するときに正確に設定されるビット j−1 があります。 コマンドを適用するのは簡単です`state ^= mask`。 

を繰り返して百万ビットマスクを構築するため、さらに詳細が 1 つあります。`mask |= 1 << position`それ自体が膨大な数の Python レベルの操作を実行します。 マスクは非常に規則的なバイナリ パターンを持っているため、代数的に構築します。 

m=⌊N/x⌋ の場合、目的のパターンの最初の mx ビットには、x 位置ごとに 1 つのセット ビットが含まれます。 値

 2 x −1 2 mx −1

 パターンの m 個のコピーで構成されるバイナリ表現を持ちます`1`separated by exactly x−1 zeroes. これを x−1 位置だけシフトすると、設定されたビットが位置 x−1,2x−1,…,mx−1 に移動します。これは、ライト x,2x,…,mx に正確に対応します。 

ブルートフォース手法は、すべてのライトを明示的に維持するため機能しますが、同じ百万の位置を 100 回横断する可能性があるため失敗します。 ビットセットの観察により、各トグル全体をパックされたビットの XOR として実行し、ネイティブのポピュレーション カウント操作で結果をカウントできます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(kN) 最悪の場合 | O(N) | Python では遅すぎる |
 | ビットセット | O(kN/w) packed-word operations | O(kN/w) | 承認済み |

 ここで、 w は Python の任意精度の整数によって内部的に使用されるマシンワードの幅です。 実際の実装では、各コマンド マスクを単一の Python 整数として保存します。 

## アルゴリズムのチュートリアル

 1. Read N, k, and the sequence of commands. 質問では最終状態だけでなく、プロセス中の最大値が求められるため、コマンドの順序は保持する必要があります。 
2. すべての個別のコマンド値 x に対して、設定ビットが N を超えない x の倍数に正確に対応するビットマスクを構築します。m=N//x とします。 表現

 ( 2 x −1 2 mx −1 ​ )2 x−1

 正確に位置 x−1,2x−1,…,mx−1 にセット ビットを生成します。 
3. Store the constructed masks in a dictionary. 同じコマンドが複数回出現する場合、そのマスクは再度構築されるのではなく、再利用されます。 
4. から始める`state = 0`。 ビット 0 は、対応するライトがオンであることを意味するため、最初はすべてのライトが正しく表されます。 
5. コマンドを元の順序で処理します。 現在の状態とコマンドのマスクの XOR を計算します。 コマンドマスクの 1 はライトを切り替える必要があることを意味するため、XOR は正しい操作です。 XOR は 0 を 1 に、1 を 0 に変更します。 
6. 各コマンドの後で計算します。`state.bit_count()`そして最大値を更新します。 これにより、最大値が発生する可能性のあるすべての瞬間がチェックされます。 

### なぜ効果があるのか

 コマンドのプレフィックスを処理した後、コマンドのビット j-1`state`ライト j が奇数回切り替わったとき、 は 1 になります。 値が j を割るすべてのコマンドは、そのビットと 1 つの XOR を提供します。 トグルの回数が偶数の場合はライトが元のオン状態に戻り、奇数の場合はオフのままになります。 したがって、設定されたビットは`state`まさに現在消灯しているライトです。 取る`bit_count()`したがって、そのプレフィックスの後の消灯の正確な数が得られ、すべてのプレフィックスの最大値を取ることで必要な答えが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    k = int(input())

    commands = [int(input()) for _ in range(k)]

    masks = {}

    def build_mask(x):
        if x in masks:
            return masks[x]

        m = n // x

        # (2^(m*x) - 1) / (2^x - 1)
        # has one bit set every x positions, starting at bit 0.
        pattern = ((1 << (m * x)) - 1) // ((1 << x) - 1)

        # Shift the set bits from positions 0, x, 2x, ...
        # to positions x-1, 2x-1, 3x-1, ...
        mask = pattern << (x - 1)

        masks[x] = mask
        return mask

    state = 0
    answer = 0

    for x in commands:
        state ^= build_mask(x)
        answer = max(answer, state.bit_count())

    print(answer)

if __name__ == "__main__":
    solve()
```入力は次のように読み取られます`sys.stdin.readline`、競技プログラミングに必要なように。 問題にはテスト ケースが 1 つだけあるため、外側のテスト ケース ループは必要ありません。`m = n // x`はの倍数です`x`それは有効なライト番号です。 いつ`x = n`、私たちは得ます`m = 1`、結果のマスクにはビットのみが含まれます`n-1`、光 n に対応します。 いつ`x = 1`、マスクには 0 から 0 までのすべてのビットが含まれます。`n-1`したがって、コマンドはすべてのライトを正しく切り替えます。 

マスクの構築では整数演算のみが使用されます。 分母`(1 << x) - 1`x 個のバイナリ 1 のブロックを表します。 すべて 1 の整数の除算`(1 << (m * x)) - 1`そのブロックによって、倍数に必要な繰り返しパターンが生成されます。 最後のシフトでは、最初に設定されたビットがライト 1 ではなくライト x に揃えられます。`state ^= mask`意図的に元のコマンド順序で実行されます。 コマンドは最終状態の操作として交換されますが、最大値は各プレフィックスの後に取得されるため、コマンドの順序を変更すると答えが変わります。 

Python の整数には任意の精度があるため、状態が 100 万ビットに達しても整数のオーバーフローは発生しません。 内蔵されている`bit_count()`それらの設定されたビットを直接カウントします。
