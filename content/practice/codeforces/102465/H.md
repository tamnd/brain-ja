 ## 解決策
 ## 問題の理解

 すべてのステーションは 3 つの数字で表すことができます。 ステーション (v) については、次のようにします。 

[
 D(v) = (d_0(v)、d_1(v)、d_2(v))、
 】

 ここで、(d_0(v)) はオルリーまでの最短距離、(d_1(v)) はノートルダム寺院までの最短距離、(d_2(v)) はディズニーランドまでの最短距離です。 

ステーション (A) は、3 つの距離がすべて (A) の距離よりも大きくなく、3 つの距離のうち少なくとも 1 つが厳密に小さい別のステーション (B) が存在する場合には役に立ちません。 ベクトルに関して言えば、次の場合、(B) が (A) よりも優位になります。 

[
 d_0(B) \le d_0(A),\qquad
 d_1(B) \le d_1(A),\qquad
 d_2(B) \le d_2(A)、
 】

 そして少なくとも 1 つの不等式は厳密です。 

グラフには最大 (100,000) 個のステーションと (500,000) 個のエッジがあります。 すべてのエッジの重みは正であるため、1 つのソースからの最短距離はダイクストラのアルゴリズムを使用して計算できます。 各 POI から 1 つずつ、このような実行が 3 つ必要です。 

本当の困難は、最短経路がわかった後に起こります。 3 次元空間には最大 (100,000) 個の点があり、別の点に支配されていない点を数える必要があります。 

すべての測点ペアの二次比較はすでに大きすぎます。 (100,000) ステーションの場合、すべての順序ペアをチェックすることは、

 [
 100000 \cdot 99999 = 9,999,900,000
 】

 候補者の証人チェック。 たとえ各チェックが少数の整数比較であったとしても、これは 6 秒の制限をはるかに超えています。 

正のエッジ重みは、ゼロ重みエッジに対して特別な処理を行わずに通常のダイクストラが適用できることも意味します。 複数のステーションの距離がまったく同じ 3 倍になる場合があります。 支配には少なくとも 1 つの厳密な不平等が必要であるため、このようなステーションは互いに支配しません。 同一のトリプルを個別に処理するソリューションでは、誤って 2 番目のコピーが役に立たないものとしてマークされる可能性があります。 

たとえば、3 つのすべての POI までの距離が同じ 2 つの駅があるとします。```
5 6
0 3 1
1 3 1
2 3 1
0 4 1
1 4 1
2 4 1
```ステーション 3 と 4 は両方ともベクトル ((1,1,1)) を持ちます。 3 つの POI にはベクトル ((0,2,2))、((2,0,2))、および ((2,2,0)) があります。 これらはいずれもステーション 3 とステーション 4 のどちらを支配するものでもありません。また、ステーション 3 とステーション 4 はベクトルが等しいため、互いに支配することはできません。 正解は 5 です。以前の同一のベクトルを厳密な証人として扱うと、そのうちの 1 つが誤って削除されてしまいます。 

もう 1 つの微妙なケースは、最初の 2 つの座標が等しいが、3 番目の座標が異なる場合に発生します。```
5 6
0 3 1
1 3 1
2 3 2
0 4 1
1 4 1
2 4 3
```ステーション 3 にはベクトル ((1,1,2)) があり、ステーション 4 にはベクトル ((1,1,3)) があります。 ステーション 3 はオルリーとノートルダムに等しく近く、厳密にはディズニーランドに近いため、ステーション 4 よりも優勢です。 正解は 4 です。2 番目の座標のより小さい値のみを厳密に考慮するデータ構造では、このケースは見逃されます。 

最後に、許容される最小のグラフには 4 つのステーション、正確に 3 つの POI と追加の 1 つのステーションが含まれます。 例えば、```
4 3
0 3 1
1 3 1
2 3 1
```4 つのベクトルは、((0,2,2))、((2,0,2))、((2,2,0))、および ((1,1,1)) です。 どれも他のものを支配するものはないので、答えは 4 です。 

## アプローチ

 直接的なアプローチは、ダイクストラを使用して 3 つの距離配列を計算することから始まります。 すべてのステーションがそのベクトル ((d_0,d_1,d_2)) を取得したら、ステーションのすべてのペアを単純に比較できます。 各ステーション (A) について、1 つおきのステーション (B) をスキャンし、(B) の 3 つの座標すべてが (A) の座標よりも大きくないか、少なくとも 1 つの厳密な不等式が存在するかどうかを確認します。 

これは、無駄の定義を文字通りチェックしているので、正しいです。 問題は比較の回数です。 (N=100000) の場合、(N(N-1)) 個、または (9,999,900,000) 個の順序付き証人候補が存在する可能性があります。 グラフ処理はこれほど高価ではないため、ペアごとの優位性チェックは置き換える必要がある部分です。 

重要な観察は、最初の座標がソートによって処理できることです。 すべての距離ベクトルを ((d_0,d_1,d_2)) によって辞書順に並べ替えます。 ベクトル (v=(x,y,z)) を処理する場合、以前に処理されたすべてのベクトル (u) は (u_x\le x) を満たします。 (u_x<x) の場合、最初の座標はすでに必要な厳密な不等式を示しています。 (u_x=x) の場合、辞書順は (u_y\le y) を保証します。 (u_y<y) の場合、2 番目の座標は厳密な不等式を示します。 (u_y=y) の場合、同一のベクトルがグループ化されるため、以前の個別のベクトルは (u_z<z) を持つ必要があります。 

したがって、並べ替えると、残る質問は 2 次元だけになります。 現在のベクトル ((x,y,z)) について、以前のベクトルが

 [
 u_y\le y
 】

 そして

 [
 u_z\le z.
 】

 これは、プレフィックスを最小限に抑えるクエリに減らすことができます。 2 番目の座標が最大 (y) である以前に処理されたすべてのベクトルのうち、最小の 3 番目の座標を保持します。 その最小値が最大 (z) である場合、そのようなベクトルが現在のベクトルを支配します。 

フェンウィック ツリーは、まさにこの情報を維持できます。 格納される値は合計やカウントではなく、圧縮された各 2 番目の座標で見られる最小の 3 番目の座標です。 プレフィックス クエリは、処理されたすべてのポイントの中で最小の 3 番目の座標を返します。2 番目の座標は最大でも要求された値です。 

ベクトルの重複によって引き起こされる詳細がもう 1 つあります。 ベクトルをソートし、等しいトリプルを 1 つのグループとして処理します。 グループを挿入する前にフェンウィック ツリーにクエリを実行するため、ベクターが別の同一のコピーを支配しているとは決して考えられません。 ベクトルが以前の別個のベクトルによって支配されていない場合は、同じベクトルを持つすべてのステーションが役に立ちます。 

ブルートフォースアプローチは、2 つのベクトル間の優位性をテストするのが簡単であるため機能しますが、ペアが多すぎる場合は失敗します。 並べ替えにより 1 つの次元が検索から削除され、フェンウィック ツリーは残りの 2 つの次元を対数時間で処理します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O((N+E)\log N + N^2)) | (O(N+E)) | 遅すぎる |
 | 最適 | (O((N+E)\log N)) | (O(N+E)) | 承認済み |

 ## アルゴリズムのチュートリアル

1. 入力から無向グラフを構築します。 どちらの方向への移動も可能であるため、各エッジについては両方向を保存します。 
2. ステーション 0、1、2 から開始して、ダイクストラを 3 回実行します。これにより 3 つの距離配列が得られるため、すべてのステーションは ((d_0,d_1,d_2)) として表すことができます。 3 回のダイクストラ実行では、実行時間に定数が乗算されるだけです。 
3. 距離トリプルのリストを作成し、(d_0)、(d_1)、(d_2) の順に辞書順に並べ替えます。 この順序により、現在のベクトルのすべての潜在的な支配者がその前に現れることが保証されます。 
4. すべての個別の (d_1) 値を座標圧縮します。 フェンウィック ツリーは (d_1) の圧縮位置を使用し、各ツリー セルには、そのセルに寄与する処理済みベクトルの最小値 (d_2) が格納されます。 
5. 等しいトリプルを 1 つのグループとして処理します。 グループをフェンウィック ツリーに挿入する前に、(d_1) で終わるプレフィックスをクエリします。 返された最小値 (d_2) が最大でもグループの (d_2) である場合、以前の個別のベクトルがこのトリプルを支配するため、グループ内のすべてのステーションは役に立ちません。 それ以外の場合、グループ内のすべてのステーションが役に立ち、その多重度が答えに追加されます。 
6. グループ (d_2) をフェンウィック ツリーの圧縮された (d_1) 位置に挿入します。 今後のクエリでは、適切なベクトルの 3 番目の座標が十分に小さいかどうかのみが考慮されるため、更新では最小値が保存されます。 

### なぜ効果があるのか

 辞書順ソートの後、以前に処理されたすべてのベクトルの最初の座標は現在のベクトル以下になります。 以前のベクトルの最初の座標が小さい場合、すでに厳密な改善が行われています。 最初の座標が等しい場合、辞書編集順により、現在の座標以下の 2 番目の座標が与えられます。 2 番目の座標が小さいほど厳密な改​​善が得られ、2 番目の座標も等しい場合は、3 番目の座標を増加させながら個別のトリプルを処理することで、3 番目の座標が小さくなることが保証されます。 したがって、別個の以前のベクトルの場合、優勢のための残りの唯一の条件は (u_y\le y) と (u_z\le z) です。 

フェンウィックの接頭辞の最小値は、そのような以前のベクトルが存在するかどうかを正確に示します。 したがって、有効な支配ステーションが存在する場合に限り、現在のトリプルは無効とマークされます。 等しいトリプルはまとめて処理されるため、3 つの座標すべてが等しいことが厳密な支配と誤解されることはありません。 

## Python ソリューション```python
import sys
import heapq
from bisect import bisect_left
from array import array

input = sys.stdin.readline

INF = 10**18

def dijkstra(src, head, to, weight, nxt, n):
    dist = [INF] * n
    dist[src] = 0

    pq = [(0, src)]
    heappush = heapq.heappush
    heappop = heapq.heappop

    while pq:
        d, u = heappop(pq)

        if d != dist[u]:
            continue

        e = head[u]
        while e != -1:
            v = to[e]
            nd = d + weight[e]

            if nd < dist[v]:
                dist[v] = nd
                heappush(pq, (nd, v))

            e = nxt[e]

    return dist

def solve():
    n, m = map(int, input().split())

    # Forward-star representation.
    # Using compact integer arrays keeps the memory usage low for
    # up to 500000 undirected edges.
    head = array('i', [-1]) * n
    to = array('i')
    weight = array('i')
    nxt = array('i')

    for _ in range(m):
        a, b, w = map(int, input().split())

        idx = len(to)
        to.append(b)
        weight.append(w)
        nxt.append(head[a])
        head[a] = idx

        idx = len(to)
        to.append(a)
        weight.append(w)
        nxt.append(head[b])
        head[b] = idx

    d0 = dijkstra(0, head, to, weight, nxt, n)
    d1 = dijkstra(1, head, to, weight, nxt, n)
    d2 = dijkstra(2, head, to, weight, nxt, n)

    points = list(zip(d0, d1, d2))
    points.sort()

    # Coordinate compression for the second coordinate.
    ys = sorted({p[1] for p in points})
    k = len(ys)

    # Fenwick tree for prefix minimum of the third coordinate.
    bit = [INF] * (k + 1)

    answer = 0
    i = 0

    while i < n:
        x, y, z = points[i]

        # Find the complete group of identical triples.
        j = i + 1
        while j < n and points[j] == points[i]:
            j += 1

        pos = bisect_left(ys, y) + 1

        # Query minimum z among all previous points with y <= current y.
        p = pos
        best = INF

        while p > 0:
            if bit[p] < best:
                best = bit[p]
            p -= p & -p

        # If no previous point has z <= current z, this triple is useful.
        if best > z:
            answer += j - i

        # Insert this unique triple into the Fenwick tree.
        p = pos
        while p <= k:
            if z < bit[p]:
                bit[p] = z
            p += p & -p

        i = j

    sys.stdout.write(str(answer) + '\n')

if __name__ == "__main__":
    solve()
```グラフは、すべての隣接エントリのタプルの Python リストではなく、フォワードスター表現を使用して保存されます。 (500,000) 個の無向エッジには (1000,000) 個の有向隣接エントリがあるため、エンドポイント、重み、次のポインタをコンパクトな整数配列に格納すると、かなりの量のメモリが節約されます。 

3つの呼びかけは、`dijkstra`3 つの POI に直接対応します。 優先キューには、現在の距離とステーションのペアが保存されます。 の`d != dist[u]`check は、古いエントリがすでにプッシュされた後、ステーションがより良い距離を受信したときに作成された古いヒープ エントリを破棄します。 

トリプルは直接ソートされるため、Python のタプルの順序付けにより、必要な辞書順が正確に得られます。 からのループ`i`に`j`すべての同一のトリプルを識別します。 クエリは更新前に実行されます。これは、同一のベクトルが互いに支配してはならないため、不可欠です。 

フェンウィック ツリーには 0 ではなく 1 からインデックスが付けられます。`pos`したがって`bisect_left(ys, y) + 1`。 クエリは次のようにゼロに向かって進みます。`p -= p & -p`、更新は上向きに進みます`p += p & -p`。 ツリーには最小値が格納されるため、更新のたびに次の値が使用されます。`min`追加の代わりに。 

可能な最大の最短距離は最大でも ((N-1)\cdot100) で、これは (10^7) を下回ります。 Python の整数にはオーバーフローの問題はなく、`INF`値はあらゆる可能な距離よりも快適に大きくなります。 

## 実用的な例

 ### サンプル 1

 グラフはステーション 3 を中心とする星形で、その中心にステーション 4 が接続されています。 距離トリプルは、

 | 駅 | (d_0) | (d_1) | (d_2) | 並べ替えられた位置 |
 | --- | --- | --- | --- | --- |
 | 0 | 0 | 2 | 2 | 1 |
 | 3 | 1 | 1 | 1 | 2 |
 | 2 | 2 | 2 | 0 | 3 |
 | 1 | 2 | 0 | 2 | 4 |
 | 4 | 2 | 2 | 2 | 5 |

 実際の辞書編集順序は、((0,2,2))、((1,1,1))、((2,0,2))、((2,2,0))、((2,2,2)) です。 

| 現在のベクトル | プレフィックスの最小値 (d_2) | 支配された？ | 答え |
 | --- | --- | --- | --- |
 | ((0,2,2)) | INF | いいえ | 1 |
 | ((1,1,1)) | INF | いいえ | 2 |
 | ((2,0,2)) | INF | いいえ | 3 |
 | ((2,2,0)) | 0 | はい | 3 |
 | ((2,2,2)) | 0 | はい | 3 |

 この表は、強調する価値のある小さな修正を示しています。最初の座標が等しく (0<2) であるため、実際のソート順序ではステーション ベクトルはステーション 1 をステーション 2 の前に置きます。 ステーション 0、ステーション 1、ステーション 2、およびステーション 3 が有用であるため、最終的な答えは依然として 4 です。 したがって、正しいトレースは次のようになります。 

| 現在のベクトル | プレフィックスの最小値 (d_2) | 支配された？ | 答え |
 | --- | --- | --- | --- |
 | ((0,2,2)) | INF | いいえ | 1 |
 | ((1,1,1)) | INF | いいえ | 2 |
 | ((2,0,2)) | INF | いいえ | 3 |
 | ((2,2,0)) | 0 | いいえ、(0\le0) は 3 番目の座標で等しいためですが、監視者は更新後のステーション 2 自体です。 4 |
 | ((2,2,2)) | 0 | はい | 4 |

 4 行目の違いは、まさに、現在のポイントを挿入する前にクエリを実行する必要がある理由です。 この時点では、プレフィックスの最小値には現在のベクトルは含まれません。 ステーション 2 はそれ自体によって支配されておらず、以前のベクトルには (d_2\le0) がありません。 ステーション 4 は後にステーション 2 によって支配されます。答えは 4 です。 

### サンプル 2

 ステーション 0 からステーション 1 および 2 への追加エッジにより、距離が 3 倍に変化します。 

| 駅 | 距離 3 倍 |
 | --- | --- |
 | 0 | ((0,1,1)) |
 | 1 | ((1,0,2)) |
 | 2 | ((1,2,0)) |
 | 3 | ((1,2,2)) |
 | 4 | ((2,3,3)) |

 辞書順ソート後の処理順序は 0、1、2、3、4 です。 

| 現在のベクトル | プレフィックスの最小値 (d_2) | 支配された？ | 答え |
 | --- | --- | --- | --- |
 | ((0,1,1)) | INF | いいえ | 1 |
 | ((1,0,2)) | INF | いいえ | 2 |
 | ((1,2,0)) | 1 | いいえ | 3 |
 | ((1,2,2)) | 0 | はい | 3 |
 | ((2,3,3)) | 0 | はい | 3 |

 ステーション 3 はステーション 2 によって支配されており、ステーション 2 は同じ 1 番目と 2 番目の座標を持ちますが、3 番目の座標は小さいです。 ステーション 4 もステーション 2 によって支配されています。 3 つの POI は、それぞれの POI 自体までの距離が 0 であるため、依然として有用です。

 (N\le100000) と (E\le500000) では、グラフが入力サイズを支配します。 3 つのヒープ ベースの最短パス計算が実用的で、ドミナンス フェーズで追加される操作は (O(N\log N)) だけです。 また、コンパクトな隣接アレイにより、メモリ フットプリントが 256 MB の制限を大幅に下回ります。 

## テストケース

 次のテスト ハーネスには、2 つの公式サンプル、最小サイズのグラフ、同一の有用なベクトルを持つケース、最初の 2 つの座標が等しいが 3 番目の座標が厳密な優位性を与えるケース、および最大 (N) チェーンが含まれています。```python
import io
import heapq
from bisect import bisect_left
from array import array

INF = 10**18

def solve_text(inp: str) -> str:
    reader = io.StringIO(inp).readline
    n, m = map(int, reader().split())

    head = array('i', [-1]) * n
    to = array('i')
    weight = array('i')
    nxt = array('i')

    for _ in range(m):
        a, b, w = map(int, reader().split())

        idx = len(to)
        to.append(b)
        weight.append(w)
        nxt.append(head[a])
        head[a] = idx

        idx = len(to)
        to.append(a)
        weight.append(w)
        nxt.append(head[b])
        head[b] = idx

    def dijkstra(src):
        dist = [INF] * n
        dist[src] = 0
        pq = [(0, src)]

        while pq:
            d, u = heapq.heappop(pq)
            if d != dist[u]:
                continue

            e = head[u]
            while e != -1:
                v = to[e]
                nd = d + weight[e]

                if nd < dist[v]:
                    dist[v] = nd
                    heapq.heappush(pq, (nd, v))

                e = nxt[e]

        return dist

    d0 = dijkstra(0)
    d1 = dijkstra(1)
    d2 = dijkstra(2)

    points = list(zip(d0, d1, d2))
    points.sort()

    ys = sorted({p[1] for p in points})
    k = len(ys)
    bit = [INF] * (k + 1)

    answer = 0
    i = 0

    while i < n:
        x, y, z = points[i]

        j = i + 1
        while j < n and points[j] == points[i]:
            j += 1

        pos = bisect_left(ys, y) + 1

        p = pos
        best = INF
        while p:
            if bit[p] < best:
                best = bit[p]
            p -= p & -p

        if best > z:
            answer += j - i

        p = pos
        while p <= k:
            if z < bit[p]:
                bit[p] = z
            p += p & -p

        i = j

    return str(answer)

def run(inp: str) -> str:
    return solve_text(inp)

sample1 = """\

 ## 特殊なケース

 重複ベクトルの場合は、フェンウィック ツリーを更新する前に等しいトリプルをグループ化することで処理されます。 入力で```
5 6
0 3 1
1 3 1
2 3 1
0 4 1
1 4 1
2 4 1
```ステーション 3 と 4 は両方ともベクトル ((1,1,1)) を持ちます。 そのグループがクエリされるとき、どちらのコピーもまだ挿入されていないため、フェンウィック ツリーには他のステーションからのベクトルのみが含まれます。 このグループは有用なものとして正しく分類され、その多重度 2 が一度に追加されます。 

プレフィックスが等しい場合は、厳密にその前ではなく、現在 (d_1) 位置を通してフェンウィック ツリーをクエリすることによって処理されます。 のために```
5 6
0 3 1
1 3 1
2 3 2
0 4 1
1 4 1
2 4 3
```ステーション 3 には ((1,1,2)) があり、ステーション 4 には ((1,1,3)) があります。 ステーション 4 が処理されると、プレフィックス クエリにはステーション 3 の (d_1=1) エントリが含まれ、(2) が返されます。 (2\le3) なので、ステーション 4 は正しく「役に立たない」とマークされます。 

最小サイズのケース```
4 3
0 3 1
1 3 1
2 3 1
```ちょうど 4 つの駅が含まれています。 3 つの POI 間の距離はゼロですが、ステーション 3 のベクトルは ((1,1,1)) です。 すべてのステーションには少なくとも 1 つの座標があり、他のステーションと一致すると他の座標が悪化するため、4 つすべてがカウントされます。 

最大 (N) のチェーンには (100000) 個のステーションが含まれます。 すべてのステーション (v\ge2) のベクトルは次のようになります。 

[
 (v、v-1、v-2)。 
】

 ステーション 2 にはベクトル ((2,1,0)) があり、すべてのステーションを支配します (v>2)。 ステーション 0、1、および 2 はそれぞれ POI であり、それ自体までの距離が 0 であるため、支配することはできません。 したがって、許容される最大数のステーションを処理している間、アルゴリズムは 3 を返します。
