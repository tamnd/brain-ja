 ## 解決策
 ## 問題の理解

 同じ 64 ビット擬似乱数ジェネレーターの独立したインスタンスが 4 つあり、キーパッドごとに 1 つずつ存在します。 秘密コードは、1 つのジェネレータ シーケンスへの単純な正のインデックスです。 選択された 4 つのインデックスが c 1 、c 2 、c 3 、c 4 の場合、システムは対応するジェネレーター出力を受け取り、その最下位 N ビットのみを保持し、それらの XOR がゼロであることを要求します。 入力では N と 4 つのシードが与えられ、100000000 未満の有効なコードを 4 つ出力する必要があります。公式の制限は 1≤N≤50 で、各シードは 64 ビットを占有します。 

ジェネレーターは xorohiro128+ で、各シードから 128 ビットの内部状態が初期化されます。 Python の整数は自動的にオーバーフローしないため、ステートメントの Python バージョンとまったく同じように、すべての状態更新とすべての生成結果を 2 64 を法として削減する必要があります。 

最初の有用な削減は、完全な 64 ビット ジェネレーターの出力について考えるのをやめるということです。 この条件では、最下位の N ビットのみが重要であるため、生成されたすべての数値は 2 N を法とする値ですぐに置き換えることができます。将来の出力はすべての状態ビットに依存するため、ジェネレーターの状態自体は依然として 64 ビットのままである必要があります。 

考えられるすべてのコードを総当たり検索すると、およそ (10 8 −1) 4、つまり約 10 32 の 4 倍になります。 キーパッドごとに 2 25 の候補といったはるかに小さい検索でも、従来のペアごとの中間者アプローチでは既に大規模になりすぎます。 制限 N≤50 は、コード範囲の数値的なサイズではなく、関連するビットの数が検索サイズを決定する必要があるという手がかりです。 

実装上の間違いが明らかになるいくつかの特殊なケースがあります。 と```
1
0 0 0 0
```すべてのジェネレーターの最初に生成される値はゼロであるため、`1 1 1 1`有効です。 ゼロベースの実装では次のように出力される場合があります。`0 0 0 0`ただし、最初のジェネレーター値にはコード 1 があるため、コード 0 は許可されません。 

と```
2
0 0 1 1
```0 でシードされたジェネレータの最初の出力は 2 に等しい下位 2 ビットを持ちますが、シード 1 の最初の出力は 0 に等しい下位 2 ビットを持ちます。`1 1 1 1`2⊕2⊕0⊕0=0となります。 N ビットにマスクする代わりに完全な 64 ビット値を使用する不用意な実装は、有効な解決策を拒否することになります。 

最後に考えてみましょう```

```4 つのジェネレーターは同一であるため、4 つのキーパッドすべてで同じコードを使用すると、常に 4 つの同一の値が得られ、その XOR は 0 になります。`1 1 1 1`有効です。 このケースでは、ジェネレーターのモジュロ 2 64 の動作を忘れた実装が捕捉されます。 

## アプローチ

 直接的なアプローチは、候補値を生成し、XOR が 0 になるまで 4 倍数を列挙することです。 最終的には考えられる 4 つのコードのすべての組み合わせが検査されるため、これは正しいのですが、最悪の場合は約 10 32 個の組み合わせとなり、これはまったく実行不可能です。 

より自然な改善は、通常の中間者合わせです。 各キーパッドに対して L 値を生成し、すべての値 A i ⊕B j を計算し、すべての C k ⊕D l の中から同じ値を探します。 これが機能する理由は、

 A i ⊕B j =C k ⊕D l

 と同等です

 A i ⊕B j ⊕C k ⊕D l ＝0。 

残念ながら、両側に L 2 ペアがあります。 N ビットのランダムな値の中から解を見つける妥当な確率を得るには、通常の誕生日推論では約 2 N/4 の L が必要で、これにより 2 N/2 のペアが生成されます。 N=50 の場合、関連するインデックスを保存する前に約 3,300 万のペアになります。 

重要な点は、XOR ペアが完全に任意である必要はないということです。 すべての XOR ペアの最下位 b ビットを意図的に強制的に同じにすることができます。 もし

 low b (A i )=low b (B j )⊕α、

 それから

 low b (A i ⊕B j )=α。 

同じ α を使用して、他の 2 つのリストについても同じことを行います。 これで、両側からのすべてのペアの XOR は、最下位の b ビットですでに一致します。 残りの N-b ビットでの衝突のみが必要です。 

これは、ワーグナーによって導入された 4 つのリストからなる一般化された誕生日テクニックです。 4 つのリストの場合、検索は O(2 N/2 ) ではなく、およそ O(2 N/3 ) の作業量とメモリに減ります。 標準的な構造では、およそ 2 N/3 個の要素のリストを取得し、N/3 ビットで 2 つのリストを結合し、他の 2 つに対して同じ演算を実行し、最後に結果のペア XOR 間の正確な衝突を探します。 

衝突が見つかる確率を高めるために、少し大きいリスト 2 ⌈N/3⌉+1 を使用します。 また、α の値をゼロから始めていくつか試してみます。 各試行には同じ漸近コストがあり、問題によって明示的に提供される擬似ランダム性の仮定の下では、少数の独立して見えるフィルターにより、失敗の可能性が非常に低くなります。 

結合自体は、すべての L 2 ペアを列挙する必要はありません。 1 つのリストをその最下位 b ビットごとに分類します。 他のリストの各値については、要求された α を生成する下位ビットを持つバケットのみを検査します。 考えられるバケットは 2 b 個あり、L は 2 b より大きい定数係数にすぎないため、検査されるペアの予想数は O(L) です。

 | --- | --- | --- | --- |
 | ブルートフォース | O(10 32 ) | お(1) | 遅すぎる |
 | 通常の中間会 | O(2 N/2 ) | O(2 N/2 ) | N=50 には大きすぎます |
 | 一般化された誕生日結合 | O(2 N/3 ) が期待されます | O(2 N/3 ) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. b=⌈N/3⌉ と設定し、4 つの生成シーケンスのそれぞれから L=2 b+1 値を生成します。 因数 2 により、リストを 100000000 エントリ未満に抑えながら、理論上の最低限のしきい値よりも多くの候補ペアが得られます。 
2. 生成されたすべての値の下位 N ビットのみを保持します。 状態を切り捨てると後続のすべてのジェネレーター出力が変更されるため、ジェネレーターの状態は完全な 128 ビット状態のままになります。 
3. b ビット値 α の小さなセットを選択します。最初にゼロが試行されます。 固定 α の場合、最初の 2 つのリストのすべてのペアが次の条件を満たす必要があります。 

low b (x 1 ⊕x 2 )=α。 

2 番目のペアは同じ方程式を満たすため、それらの XOR は等しくなる可能性があります。 
4. 2 番目のリストを最下位 b ビットごとにバケットに入れます。 最初のリストの値 x の場合、必要なバケットは次のとおりです。 

低いb (x)⊕α。

そのバケット内のすべてのインデックスは、x と有効な部分衝突を形成します。 
5. 最初の 2 つのリストからのそのようなペアごとに、 x 1 ⊕x 2 を計算し、それを 2 つの元のインデックスとともにハッシュ テーブルに保存します。 b ビットに一致するペアのみが生き残るため、生成されるペアの数は O(L 2 ) ではなく O(L) であると予想されます。 
6. 3 番目と 4 番目のリストに対して同じバケット化手順を繰り返します。 この 2 番目のペア リストを保存する代わりに、生成された各ペアの XOR を最初のペアのハッシュ テーブルに対して直ちにチェックします。 
7. ペアの XOR が一致する場合、次のように言います。 

x 1 ⊕x 2 =x 3 ⊕x 4 、

 次に、両側を XOR すると、次のようになります

 x 1 ⊕x 2 ⊕x 3 ⊕x 4 =0。 

対応する 4 つの 1 から始まるインデックスが有効な答えです。 
8. 現在の α で衝突が見つからない場合は、別の α を試します。 値 α は、どの部分衝突を保持するかを変更するだけなので、すでに生成された擬似乱数リストを再利用できます。 
9. 格納されている 4 つのインデックスを出力し、内部配列のインデックスは 0 ですが、ジェネレーターの最初の出力はコード 1 であるため、1 を追加します。 

### なぜ効果があるのか

 中心となる不変条件は、最初のハッシュ テーブルに格納されているすべてのペアの下位 b ビットが α に等しいこと、および 2 番目の側で検査されるすべてのペアがまったく同じ下位 b ビットを持つことです。 完全なペアの XOR が一致する場合、選択された 4 つのジェネレーター出力すべての XOR は、N 個の関連ビットすべてで 0 になります。 

フィルタリングのステップでは、誤ったソリューションは作成されません。 選択した部分衝突構造に参加できないペアのみを破棄します。 2 つの完全なペア XOR が等しいと、結果として得られる 4 つのコードが必要な XOR 式を満たすことが数学的に保証されます。 

擬似ランダム性の仮定により、検索が高速になります。 L=2 b+1 の場合、最初の結合の予想サイズは約 L 2 /2 b =2L になります。 これらのペアの XOR はすべて b 固定ビットを共有し、衝突が必要な N-b ビットが残ります。 各陣営に約 2L 人の候補者が存在するため、予想される最終的な試合数は次のとおりです。 

2 N−b (2L) 2 、

 b=⌈N/3⌉なので、これは定数以上です。 これは、アルゴリズムで使用される一般化された誕生日効果です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MASK64 = (1 << 64) - 1
CONST = 0x7263d9bd8409f526

def generate(seed, count, value_mask):
    s0 = seed & MASK64
    s1 = (seed ^ CONST) & MASK64
    result = [0] * count

    for i in range(count):
        result[i] = (s0 + s1) & value_mask

        t = s1 ^ s0

        ns0 = (((s0 << 55) & MASK64) | (s0 >> 9))
        ns0 ^= t
        ns0 ^= (t << 14) & MASK64
        ns0 &= MASK64

        ns1 = (((t << 36) & MASK64) | (t >> 28))
        ns1 &= MASK64

        s0, s1 = ns0, ns1

    return result

def build_buckets(values, low_mask):
    size = low_mask + 1
    head = [-1] * size
    nxt = [-1] * len(values)

    for i, x in enumerate(values):
        k = x & low_mask
        nxt[i] = head[k]
        head[k] = i

    return head, nxt

def build_left_map(a, b, head, nxt, low_mask, alpha, length):
    pairs = {}

    for i, x in enumerate(a):
        wanted = (x & low_mask) ^ alpha
        j = head[wanted]

        while j != -1:
            value = x ^ b[j]
            if value not in pairs:
                pairs[value] = i * length + j
            j = nxt[j]

    return pairs

def find_right(c, d, head, nxt, low_mask, alpha, pairs):
    for i, x in enumerate(c):
        wanted = (x & low_mask) ^ alpha
        j = head[wanted]

        while j != -1:
            value = x ^ d[j]
            code = pairs.get(value)

            if code is not None:
                return code, i * len(d) + j

            j = nxt[j]

    return None

def solve():
    n = int(input())
    seeds = list(map(int, input().split()))

    value_mask = (1 << n) - 1

    # b is the number of low bits fixed during each partial join.
    b = (n + 2) // 3

    # One extra factor of two improves the probability of finding a collision.
    length = 1 << (b + 1)

    values = [
        generate(seed, length, value_mask)
        for seed in seeds
    ]

    a, b_values, c, d = values

    low_bits = (n + 2) // 3
    low_mask = (1 << low_bits) - 1

    # Zero is the standard Wagner filter. The remaining filters
    # explore other possible low-bit XOR values.
    alphas = [0]
    for i in range(min(7, low_bits)):
        alphas.append(1 << i)

    for alpha in alphas:
        head, nxt = build_buckets(b_values, low_mask)
        left = build_left_map(
            a, b_values, head, nxt,
            low_mask, alpha, length
        )

        head, nxt = build_buckets(d, low_mask)
        answer = find_right(
            c, d, head, nxt,
            low_mask, alpha, left
        )

        if answer is not None:
            left_code, right_code = answer

            i1 = left_code // length
            i2 = left_code % length
            i3 = right_code // length
            i4 = right_code % length

            print(i1 + 1, i2 + 1, i3 + 1, i4 + 1)
            return

if __name__ == "__main__":
    solve()
```の`generate`関数はジェネレーター定義に正確に従います。`result`関連する N ビットに削減されますが、`s0`そして`s1`常に 2 64 を法として保持されます。一時変数`t`更新されました`s1 ^ s0`両方の状態遷移で使用される値。 

配列のインデックス`i`ジェネレーターコードを表します`i + 1`。 この変換は印刷時にのみ実行され、結合時に 1 から始まる問題インデックスと 0 から始まる Python インデックスが混在することが回避されます。`build_buckets`すべてのペアを構築せずに部分衝突結合を実装します。 の`head`配列には、各低ビット バケットに属する最初のインデックスが格納されます。`nxt`そのバケット内の他のすべてのインデックスのリンクされたリストを形成します。 これは、バケットごとに個別の Python リストを含むディクショナリよりもかなり少ないメモリを使用します。`build_left_map`下位 b ビットの XOR が行われるペアを正確に考慮します。`alpha`。 辞書キーはペアの完全な N ビット XOR であり、その値は 2 つの元のインデックスを次のようにエンコードします。`i * length + j`。`find_right`他の 2 つのシーケンスに対して同じ部分結合を実行します。 辞書キーが一致すると、2 つの等しいペア XOR が得られ、必要な 4 方向 XOR が即座にゼロになります。 

Python には符号付き整数の問題はありませんが、明示的な`MASK64`操作はまだ必要です。 これらがないと、Python の無制限の整数により、63 位以降のビットが将来のジェネレータ状態にリークし、問題で指定されたシーケンスとは異なるシーケンスが生成されることになります。 リファレンス Python ジェネレーターも同様に、両方の状態コンポーネントを 2 64 を法として削減します。 

このコードでは、8 つの可能な部分衝突フィルターが使用されています。 ゼロが最初に試行されます。これは、これが最も単純なケースであり、同一のシーケンスも特に適切に処理できるためです。 追加のフィルターは正確さを変えるものではなく、有限のサンプリングされたリストに解が含まれる可能性を高めるだけです。

## テストケース

 公式サンプルには複数の受け入れ可能な出力があるため、正確な文字列比較は適切ではありません。 以下のサンプル テストでは、生成された 4 つのコードが元のジェネレータ方程式を満たしていることを検証します。

import sys
import io
from contextlib import redirect_stdout

MASK64 = (1 << 64) - 1
CONST = 0x7263d9bd8409f526

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)

    out = io.StringIO()
    with redirect_stdout(out):
        solve()

    sys.stdin = old_stdin
    return out.getvalue().strip()

def generator_value(seed: int, code: int) -> int:

    s1 = (seed ^ CONST) & MASK64

    for _ in range(code):
        result = (s0 + s1) & MASK64

        t = s1 ^ s0

        ns0 = (((s0 << 55) & MASK64) | (s0 >> 9))
        ns0 ^= t
        ns0 ^= (t << 14) & MASK64
        ns0 &= MASK64

        ns1 = (((t << 36) & MASK64) | (t >> 28))
        ns1 &= MASK64

        s0, s1 = ns0, ns1

    return result

def valid(inp: str, output: str) -> bool:
    data = list(map(int, inp.split()))
    n = data[0]
    seeds = data[1:5]

    codes = list(map(int, output.split()))

    if len(codes) != 4:
        return False

    if any(c <= 0 or c >= 100000000 for c in codes):
        return False

    mask = (1 << n) - 1

    x = 0
    for seed, code in zip(seeds, codes):
        x ^= generator_value(seed, code) & mask

    return x == 0

 ## 特殊なケース

 のために```
1
0 0 0 0
```アルゴリズムは、それぞれの同一のジェネレーターから最初の値を生成します。 シード 0 の最初の結果は 0 であるため、4 つの 1 ビット値はすべて 0 になります。 最初のペアは XOR 0 を生成し、2 番目のペアも XOR 0 を生成し、最後のハッシュ ルックアップはすぐに成功します。 内部インデックスはすべて 0 ですが、出力されるコードはすべて 1 にインクリメントされます。 

のために```
2
0 0 1 1
```シード 0 の最初のジェネレーター出力には 2 に等しい下位 2 ビットがあり、シード 1 の最初の出力には 0 に等しい下位 2 ビットがあります。したがって、4 つの値は 2⊕2⊕0⊕0=0 を満たします。 α=0 での結合では、各ペアが等しい下位 1 ビット値を持ち、完全な 2 ビット ペアの XOR が一致するため、両方のペアが保持されます。 

のために```
50
18446744073709551615 18446744073709551615 18446744073709551615 18446744073709551615
```4 つのジェネレーターの状態はすべて同一であるため、対応するジェネレーターの出力はすべて同一です。 4 つのリストには同じシーケンスが含まれており、各リストから最初の要素を選択すると、4 つの等しい N ビット値が得られます。 偶数個の同一の値を XOR 演算すると、ゼロになります。 この実装では、初期状態とすべての遷移が 64 ビットに正しくラップされます。 

N=50 の場合、部分結合幅は正確に 16 または 18 ではなく 17 ビットです。実装では、これを整数の天井除算で計算し、2 17 の 2 倍の大きさのリストを割り当てます。これが重要なのは、間違った丸め方向を選択すると、部分衝突リストの予期されるサイズが変化し、最終的な衝突確率が大幅に悪化する可能性があるためです。 

ジェネレーターのコード番号付けは、もう 1 つの永続的な境界条件です。 内部的には、最初に生成された値は配列位置 0 に格納されます。 この問題では、その値をコード 1 と呼びます。変換は最終出力まで延期され、復元されたすべてのインデックスが 1 回だけインクリメントされます。 これにより、無効なコード ゼロと、ペアの再構築中にインデックスを 2 回シフトするというより微妙なエラーの両方が回避されます。
