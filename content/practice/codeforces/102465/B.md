 ## 解決策
 ## 問題の理解

 画像の各行には、良好なピクセルの 1 つの連続した間隔が含まれています。 行 (i) では、良好なピクセルが (a_i) から (b_i) までの列を占めます。 すべてのピクセルが良好な、軸が揃った最大の正方形が必要です。 

正方形が行 (l) から (r) までを使用しているとします。 これらの各行には、正方形が占める同じ水平間隔が含まれている必要があります。 行 (i) は正確に間隔 ([a_i,b_i]) であるため、すべての行で使用できる共通の列は次のとおりです。 

[
 [\max_{l\le i\le r} a_i,\ \min_{l\le i\le r} b_i]。 
】

 この交差部分に少なくとも (k) 列が含まれ、行数も (k) である場合、(k\times k) の正方形が存在します。 

特別な幾何学的条件により、さらに単純化が可能になります。 2 つの良好なピクセルが同じ列にある場合、その列内のそれらの間のすべてのピクセルも良好です。 したがって、グループの最初と最後の行の両方に一定の間隔の列が含まれる場合、すべての中間行にもその間隔が含まれます。 最初と最後の行を使用して、それらの間のすべての行を明示的に検査する代わりに、候補正方形をテストできます。 

(N\le 100000) では、(O(N^2)) アルゴリズムはすでに遅すぎます。 おおよそあります

 [
 \frac{N(N+1)}2
 】

 連続する行範囲。(N=100000) の場合、約 (5\times10^9) になります。 各ペアの一定量の作業であっても、コンテストの制限時間である 2 秒をはるかに超えています。 線形時間に近いアルゴリズムが必要です。 

不注意な実装によって問題が発生する可能性のあるエッジケースがいくつかあります。 まず、単一行は常に有効な (1\times1) 正方形です。 例えば、```
1
0 0
```答えがあります`1`。 答えをゼロから開始し、2 行を使用して正方形のみを検索する実装では、誤ってゼロを返す可能性があります。 

2 番目の問題は、個々の行の幅が広いということは、大きな正方形を意味しないということです。 考慮する```
3
0 3
1 2
0 3
```中央の行には良好なピクセルが 2 つだけあるため、最大の正方形には辺があります。`2`、 ない`4`。 最も幅の広い行のみに基づく解決策は間違っています。 1 行目と 3 行目の共通列が中央の行にも存在するため、この入力は有効です。 

包含エンドポイントは、off-by-one エラーのもう 1 つの一般的な原因です。 例えば、```
3
0 1
0 1
0 1
```ちょうど 2 つの適切な列が含まれているため、答えは次のようになります。`2`。 間隔の長さは`b_i-a_i+1`、 ない`b_i-a_i`。 

最後に、候補正方形は最後の行を超えて拡張することはできません。 のために```
2
0 1
0 1
```答えは`2`、そして最下行がインデックスである候補をチェックします`2`アクセスする前に停止する必要があります。 

## アプローチ

 単純な解決策では、考えられるすべての最上位行と最下位行を列挙できます。 固定ペアの場合、その範囲内のすべての行間隔を交差し、結果の水平間隔が少なくとも行数と同じ幅かどうかを確認できます。 左側のエンドポイントの実行最大値と右側のエンドポイントの最小値を使用すると、新しい最下行はすべて一定時間で処理できます。 (N(N+1)/2) 個の可能な行範囲があるため、全体として (O(N^2)) 個の作業が行われます。 (N=100000) の場合、これは約 (5\times10^9) の範囲となり、大きすぎます。 

絵の構造により、より強力な観察が可能になります。 正方形の辺が存在することがすでにわかっていると仮定します。 次に、一番上の行 (i) を修正し、それを横 (s+1) に拡張できるかどうかを尋ねます。 必要な行は (i) ～ (i+s) です。 

行 (i) と (i+s) のみに注目してください。 彼らの共通の良い間隔は、

 [
 [L,R]=[\max(a_i,a_{i+s}),\min(b_i,b_{i+s})]。 
】

 (R-L+1\ge s+1) の場合、両方のエンドポイント行には (s+1) 個の連続した共通列が含まれます。 このような (s+1) 列間隔を選択します。 その間隔内のすべての列は、両方のエンドポイント行で良好です。 ステートメントの縦凸条件により、これら 2 つの良好なピクセル間のすべてのピクセルも良好です。 したがって、すべての中間行には区間全体が含まれ、有効な ((s+1)\times(s+1)) 平方が得られます。 

これにより、問題は段階的な成長に変わります。 これまでに見つかった最大の正方形の辺を保持し、それを呼び出します`ans`。 考えられる最上行ごとに、拡張してみます。`ans`1行1列ずつ。 拡張が成功すると増加します`ans`、 そして`ans`アルゴリズム全体で最大 (N-1) 回増加する可能性があります。 

重要な償却は、この方法を直線的なものにするものです。 先頭の 1 行で複数の拡張チェックが成功する可能性がありますが、チェックが成功するたびにグローバル応答が増加します。 このような増分は最大で (N-1) 回存在します。 各最上位行は、1 回のチェックが失敗した後、またはピクチャ境界に到達したために終了することもあります。 したがって、内側ループの合計反復回数は (O(N)) のみです。

 | --- | --- | --- | --- |
 | ブルートフォース | (O(N^2)) | (O(N)) | 遅すぎる |
 | 最適 | (O(N)) 償却 | (O(N)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての行の間隔 ([a_i,b_i]) を読み取り、2 つのエンドポイントを保存します。 すべての行が水平に凸であるため、間隔表現は十分です。 
2.セット`ans = 1`。 すべての行には少なくとも 1 つの良好なピクセルが含まれるため、(1\times1) の正方形が常に存在します。 
3. 各行を処理する`i`より大きな正方形の可能な最上行として。 辺の正方形であることはすでにわかっています`ans`はどこかに存在しますが、この特定の一番上の行が辺の正方形をサポートできるかどうかを尋ねます。`ans + 1`。 
4.最初に行があるかどうかを確認します`i`それ自体は少なくとも`ans + 1`良いピクセル。 その幅は`b[i] - a[i] + 1`、だから、もし
 [
 a_i-a_i+1 < and+1,
 】
 この行を、より大きな正方形の最上部にすることはできません。 ここからさらに大きな正方形を試す理由はありません。 
1. しましょう`j = i + ans`。 これは、辺のある候補正方形の一番下の行です。`ans + 1`。 もし`j >= N`を選択すると、候補が画像の外側に広がってしまうため、この一番上の行の処理を停止します。 
2. 上部と下部の行間隔の交差部分を計算します。 

[
 L=\max(a_i,a_j),\qquad R=\min(b_i,b_j)。 
】

 もし

 [
 R-L+1\geans+1、
 】

 2 つのエンドポイント行は、辺の正方形に十分な列を共有します。`ans + 1`。 

1. 交差点が十分に大きい場合、増分します。`ans`そして同じチェックを繰り返します。 新しい候補者には味方がある`ans + 1`したがって、さらに 1 列下の列に到達します。 
2. 終点の交差点が狭すぎる場合は、この一番上の行で停止します。 候補のサイズを大きくしても交差部分を広くすることはできないため、この行から始まる大きな正方形は成功しません。 
3. 先頭の行がすべて処理された後、印刷します。`ans`。 

### なぜ効果があるのか

 不変条件というのは、`ans`は常に、既に見つかった有効な正方形の辺の長さです。 アルゴリズムがそれをインクリメントするたびに、新しい候補の最上位行と最下位行は少なくとも共有します。`ans`列。 その共有間隔内のすべての列には、両方のエンドポイントで良好なピクセルが含まれています。 垂直凸性により、これらの端点間のすべてのピクセルが良好であることが保証されるため、候補正方形全体が有効になります。 

逆にサイド候補の場合は、`s`固定された先頭行では失敗し、その 2 つのエンドポイント行の共有間隔が`s`列。 同じ最上行を持つ大きな正方形は、同じ最下行またはさらに後の行を使用することになり、必要な幅は増加するだけです。 したがって、その行から始まる大きな正方形を見逃すことはありません。 考えられるすべての最上行が考慮されるため、最終的な`ans`可能な最大の正方形の辺です。 

線形の複雑さは償却から生じます。 内部ループの反復が成功するたびに増加します`ans`、 そして`ans`最大 (N-1) 倍まで増加できます。 上部行ごとに終了反復が最大 1 つあるため、内部ループ反復の合計数は (O(N)) になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    left = [0] * n
    right = [0] * n

    for i in range(n):
        left[i], right[i] = map(int, input().split())

    ans = 1

    for i in range(n):
        while True:
            # Row i must be wide enough for a square of side ans + 1.
            if right[i] - left[i] + 1 < ans + 1:
                break

            # The bottom row of a square of side ans + 1.
            j = i + ans
            if j >= n:
                break

            # Intersection of the top and bottom row.
            L = max(left[i], left[j])
            R = min(right[i], right[j])

            # Need at least ans + 1 columns.
            if R - L + 1 >= ans + 1:
                ans += 1
            else:
                break

    print(ans)

if __name__ == "__main__":
    solve()
```配列`left`そして`right`すべての行の 2 つのエンドポイントを保存します。 個々のピクセルを表現する必要がないため、メモリ使用量が線形に保たれます。 

答えは次から始まります`1`すべての入力行に少なくとも 1 つの良好なピクセルがあるためです。 条件`right[i] - left[i] + 1 < ans + 1`包括的な間隔の長さを使用します。 として書くと`right[i] - left[i] < ans`は同等ですが、明示的に`+1`ピクセル数の解釈がより明確になります。 

サイド候補としては`ans + 1`、一番下の行は`i + ans`、 ない`i + ans + 1`。 正方形の辺`s`行から始まる`i`正確に行を占有します`i, i+1, ..., i+s-1`、それで、`s = ans + 1`、最後の行は`i + ans`。 

交差点も含まれます。 その列数は`R-L+1`、少なくとも候補辺の長さでなければなりません。 Python では整数オーバーフローの懸念はなく、関連する値はすべて最大 (N) です。 

実装の最も微妙な部分は内部です。`while`。 ループ内で行を超えてネストされている場合でも、(O(N^2)) の作業は発生しません。 その体が成功するたびに、`ans`が増えます。 以来`ans`決して減ることはなく、超えることはできません`N`、プログラム全体で成功した反復は最大で (N-1) 回です。 各行は、最終的な失敗チェックまたは境界チェックを最大 1 つだけ寄与する可能性があります。
