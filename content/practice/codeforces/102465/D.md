 ## 解決策
 ## 問題の理解

 都市は長方形の格子状になっています。 バスは、固定行座標で表される 1 つの水平な東行き道路を選択します。`y = r`、西から入ってずっと東に移動し、同じ列から出なければなりません。 この道路の上または下にある記念碑を訪問する必要がある場合は、垂直方向に回転して必要な記念碑を訪問し、幹線道路に戻ることができます。 

固定幹線道路列の場合`r`、すべての記念碑が同じであると考えてください`x`座標。 これらは 1 つの垂直の通り上にあるため、バスは 1 回の垂直移動ですべての道路を訪れることができます。 最小と最大のみ`y`その時の座標`x`案件。 それらの極端な場合`L`そして`R`、バスはその間隔をカバーしなければなりません`[L, R]`そして、に戻ります`r`。 

入力により得られるのは、`X`北向きの街路と`Y`東向きの通り、続いて`N`記念碑の座標`(x, y)`。 出力は、最適な水平道路の選択によって横断されるグリッド ブロックの最小数です。 

この制限は、考えられるすべての道路を試したり、すべての記念碑をスキャンしたりすることを除外するのに十分な大きさです。 まで`100000`記念碑と`100000`可能な水平道路、直通道路`O(NY)`計算で到達できる`10^10`操作。 平`O(XY)`最悪の場合でも同じ程度です。 解決策`O(N log N)`ソートするのが適切であるため、`O(N)`導出された値は制約内で簡単に実現可能です。 

一見合理的と思われる実装が間違っている可能性があるいくつかの特殊なケースがあります。 複数の記念碑が同じ場所を共有している場合、`x`座標を調整すると、それらを個別に扱うため、垂直方向の移動がオーバーカウントされます。 例えば：```
2 2
2
0 0
0 1
```正しい答えは、`3`。 バスは列で入場可能`0`、1 ブロック東に移動し、同じ垂直の通りにある両方の記念碑を、余計な回り道をせずに訪れてください。 課金する不注意な実装`2 * |r-y|`両方の記念碑を独立して取得すると、`5`行用`0`。 

単一の記念碑は、もう 1 つの有用な境界ケースです。```
1 1
1
0 0
```答えは、`0`なぜなら、バスは唯一利用可能な水平位置で開始および終了し、横断する東西のブロックがないからです。 盲目的に追加する実装`X`の代わりに`X - 1`生み出すだろう`1`。 

記念碑は最初の行または最後の行に置くこともできます。```
3 5
1
2 4
```行の選択`4`最小コストを与える、つまり`2`, なぜなら、バスは水平に 2 ブロック移動し、垂直に迂回する必要がないからです。 最適な道路が厳密に市内のどこかにある必要があると想定する実装では、このケースを見逃す可能性があります。 

最後に、重複した座標が許可されます。```
2 3
3
0 1
0 1
0 1
```答えは、`1`。 記念碑が繰り返されても、追加の移動は発生しません。 最小値と最大値のみを維持する`y`それぞれに`x`自然に重複を処理します。 

## アプローチ

 簡単な解決策は、可能な限りすべての水平方向の道路を試してみることです。 各候補行について`r`、すべての記念碑を検査し、どのくらいの垂直移動が必要かを判断できます。 記念碑を個別に処理すると、次の時間がかかります。`O(N)`一人の候補者のために働くので、全員が`Y`候補者が必要とする`O(NY)`時間。 最悪の場合、それは`100000 * 100000 = 10^10`記念碑のチェックは、1 秒の制限をはるかに超えています。 

同じモニュメントをグループ化することで、定数係数を改善できます。`x`、しかしそれは主な問題の解決にはなりません。 グループ化した後も、`100000`さまざまな垂直の通り、可能な限りのことを試みる`r`それでも二次仕事を与えます。 

重要な観察は、1 つの垂直の通りには、その最も低いモニュメントと最も高いモニュメントのみが必要であるということです。 それらの値が`L`そして`R`。 幹線道路が次の位置にある場合`r`、区間全体を訪れて元に戻る最短の垂直移動`r`長さがある`2 * (R - L)`いつ`r`中にあります`[L, R]`。 

もし`r < L`、バスは最初に出発する必要があります`r`に`L`、区間を横断し、から戻ります`R`に`r`。 その長さは`2 * (R - r)`。 

同様に、`r > R`、その長さは`2 * (r - L)`。 

これら 3 つのケースは、次のようによりコンパクトに書くことができます。`2 * (R - L + distance(r, [L, R]))`。 

一定の部分`2 * (R - L)`の選択には影響しません`r`。 興味深いのは、からの距離の合計を最小化することです。`r`すべての間隔に。 

便利な ID があります。`distance(r, [L, R]) = (|r-L| + |r-R| - (R-L)) / 2`。 

したがって、定数項を追加した後、ツアー全体を最小化することは、`sum(|r-L| + |r-R|)`。 

したがって、占有されているすべての垂直道路は 2 つの値、つまりその下端の値に寄与します。`L`そして上限の終点`R`必要なのは値だけです`r`これらすべてのエンドポイント値に対する絶対差の合計を最小限に抑えます。 このような値が中央値です。 

これはまさに公式の SWERC 分析で使用された観察結果です。極端な値のみを保持します。`y`それぞれのコーディネート`x`、単一点の間隔を 2 回カウントし、結果として得られるすべてのエンドポイントの中央値を選択します。 

したがって、ジオメトリは消えます。 まず、占有されているすべての列を間隔に減らし、両方のエンドポイントを収集して並べ替え、中央値を取得し、結果のツアーを評価します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |`O(NY)`|`O(N)`| 遅すぎる |
 | 最適 |`O(N log N)`|`O(N + X)`| 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての記念碑の座標を読み取り、すべての記念碑の座標を維持します。`x`、最小と最大`y`そこに現れる。 これら 2 つの値は、その通りで必要とされる垂直方向の作業を完全に表しています。なぜなら、これら 2 つの値の間にあるすべてのものを訪問すると、その通りのすべての記念碑がカバーされるからです。 
2. あらゆる人にとって`x`少なくとも 1 つの記念碑が含まれている場合は、その最小値を追加します`y`そして最大の`y`エンドポイント配列に。 もしすべての記念碑がそこにあるなら`x`同じものを持っています`y`、最小値と最大値が等しいため、同じ座標が意図的に 2 回挿入されます。 
3. エンドポイント配列をソートします。 すべての間隔が正確に 2 つのエンドポイントに寄与するため、保存される値の数は最大でも`2N`。 
4. ソートされた端点の下位中央値を幹線道路の行として選択します`r`。 どの中央値でも絶対距離の合計が最小化されるため、端点の数が偶数である場合でも、より低い中央値で十分です。 
5. 答えを始める`X - 1`、これは座標における西の境界からの東西距離です。`0`座標の東の境界線まで`X - 1`。 
6. 占領されているすべての人に対して`x`、その間隔を`[L, R]`。 もし`r < L`、 追加`2 * (R-r)`。 もし`r > R`、 追加`2 * (r-L)`。 それ以外の場合は追加します`2 * (R-L)`。 これはまさに幹線道路から全区間を訪れて戻る最短の行程です。 

アルゴリズムの背後にある不変条件は、幹線道路を使用した可能なすべてのツアーであることです。`r`水平コストはまったく同じですが、`X - 1`、その垂直コストは、占有された領域の独立したコストの合計です。`x`コーディネート。 各列をその極端な間隔で置き換えても、情報は失われません。 各区間の垂直コストは、その 2 つの終点までの距離で書き換えることができるため、完全な目標は終点配列からの絶対偏差の合計になります。 中央値はその目的を最小限に抑えます。これは、選択された道路が全体的に最適であることを意味します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    X, Y = map(int, input().split())
    N = int(input())

    INF = 10**30
    low = [INF] * X
    high = [-1] * X

    for _ in range(N):
        x, y = map(int, input().split())
        if y < low[x]:
            low[x] = y
        if y > high[x]:
            high[x] = y

    endpoints = []

    for x in range(X):
        if high[x] != -1:
            endpoints.append(low[x])
            endpoints.append(high[x])

    endpoints.sort()
    road = endpoints[(len(endpoints) - 1) // 2]

    answer = X - 1

    for x in range(X):
        if high[x] == -1:
            continue

        L = low[x]
        R = high[x]

        if road < L:
            answer += 2 * (R - road)
        elif road > R:
            answer += 2 * (road - L)
        else:
            answer += 2 * (R - L)

    print(answer)

if __name__ == "__main__":
    solve()
```の`low`そして`high`配列はアルゴリズムの最初のステップを実装します。`low[x]`垂直通りの最も低い記念碑を保管します`x`、 その間`high[x]`一番高いものを保存します。 番兵`high[x] == -1`記念碑を含まない列を識別します。 

エンドポイント リストには、占有されている列ごとに 2 つの値が含まれています。 異なる 1 つだけを含む列の場合`y`、両方の値が等しいため、必要な 2 倍の寄与が自動的に与えられます。 

中央値は次のように選択されます`(len(endpoints) - 1) // 2`。 エンドポイントの数が偶数の場合、中央の 2 つの値のうち低い方が選択されます。 どちらの中間値も有効なミニマイザーであるため、どちらを選択しても同じ最小コストが得られます。 

水平方向の貢献度は、`X - 1`、 ない`X`。 都市の座標の範囲は次のとおりです。`0`を通して`X - 1`したがって、西の境界から東の境界への移動は正確に交差します。`X - 1`ブロック。 

Python の整数には任意の精度があるため、累積された答えがオーバーフローすることはありません。 いずれにせよ、最大の答えは通常の 64 ビットの範囲内に簡単に収まりますが、Python 整数を使用するとその懸念が完全に解消されます。

    data = list(map(int, inp.split()))
    it = iter(data)

    N = next(it)

        y = next(it)

        high[x] = max(high[x], y)
