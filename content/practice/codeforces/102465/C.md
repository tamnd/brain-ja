## アルゴリズムのチュートリアル

 1. 垂直辞書と水平辞書を読み、それぞれの接頭辞構造を構築します。 すべての接頭辞について、その後にどの文字が続くか、および接頭辞自体が完全な単語であるかどうかを保存します。 文字の遷移を一定時間内にテストできます。 
2. 比較する`A^M`そして`B^N`。 もし`A^M`小さい場合は、列ごとにグリッドを構築します。 それ以外の場合は、行ごとに構築します。 これにより、アクティブに列挙される完全な行の検索スペースが可能な限り小さくなります。 
3. 二次方向の各ラインの現在のプレフィックスを含む配列を保持します。 たとえば、行を作成する場合、この配列にはすべての列のプレフィックスが格納されます。 列を構築するときに、すべての行の接頭辞を保存します。 アクティブな主行は一度に 1 文字ずつ構築されるため、別のトライ位置を持ちます。 
4. すべてのセルで、プライマリ トライ ノードと対応するセカンダリ トライ ノードから次の可能性のある文字のビット マスクを取得します。 これらのマスクを交差させます。 残りのすべてのビットは、両方向で有効な文字を表します。 
5. 交差点内の各文字を試してください。 プライマリ プレフィックスと対応するセカンダリ プレフィックスをその文字だけ進めます。 結果のいずれかのプレフィックスがトライに存在しない場合、ブランチは直ちに拒否されます。 
6. 主行の最後の文字が配置されるとき、結果として生じる主トライ ノードが終端であることを要求します。 これにより、完成した行が単なる接頭辞ではなく、実際に辞書の単語であることが保証されます。 
7. 最後の一次線路が建設されると、すべての二次線路も全長に達します。 結果として得られる各セカンダリ トライ ノードがそれらのセルの終端である必要があります。 これにより、個別のグリッド スキャンを必要とせずに、すべての行が検証されます。 
8. セルが再帰的に処理された後、次の文字を試す前にそのセカンダリ プレフィックスを復元します。 これが後戻りステップです。 プライマリ プレフィックスは引数として渡されるため、再帰呼び出しが返されると自然に元に戻ります。 
9. すべての主要なラインが完成すると、有効なグリッドが見つかります。 答えに 1 つ追加します。 セル文字の各シーケンスは 1 つのグリッドに正確に対応するため、二重にカウントされることはありません。 

### なぜ効果があるのか

 不変条件は、すべての再帰呼び出しの前に、すでに入力されているすべてのプレフィックスが適切な辞書プレフィックス セットに属していることです。 現在のプライマリ ライン プレフィックスは有効なプライマリ トライ ノードによって表され、すべてのセカンダリ ライン プレフィックスは有効なセカンダリ トライ ノードによって表されます。

そのグリッドのすべての文字は両方向で有効な次の文字であるため、すべての有効なグリッドは検索のパスに従います。 逆に、検索で受け入れられるすべてのパスは、終端辞書ノードのすべての行とすべての列で終了するため、有効なグリッドを表します。 各グリッドには 1 つの固有のセル文字列があり、受け入れられる検索パスが 1 つだけ与えられます。 

## Python ソリューション```python
import sys

input = sys.stdin.readline

# A word has length at most 4.
# We encode a prefix in base 27, using digits 1..26 for a..z.
MAX_CODE = 27 ** 4
TERM = 1 << 26
ALPHA_MASK = TERM - 1

def build_trie(count, reader):
    """
    Each entry stores:
      bits 0..25 : possible next letters
      bit 26     : this prefix is itself a complete word
    """
    trie = [0] * MAX_CODE

    for _ in range(count):
        word = reader().strip()
        code = 0

        for ch in word:
            digit = ord(ch) - 96
            trie[code] |= 1 << (digit - 1)
            code = code * 27 + digit

        trie[code] |= TERM

    return trie

def solve(reader=None):
    if reader is None:
        reader = input

    n, a = map(int, reader().split())
    m, b = map(int, reader().split())

    vertical = build_trie(a, reader)
    horizontal = build_trie(b, reader)

    # Choose the direction with fewer possible complete line sequences.
    #
    # Horizontal construction:
    #   N lines, each chosen from B words -> B^N
    #
    # Vertical construction:
    #   M lines, each chosen from A words -> A^M
    if a ** m <= b ** n:
        primary = vertical
        secondary = horizontal
        primary_lines = m
        line_length = n
    else:
        primary = horizontal
        secondary = vertical
        primary_lines = n
        line_length = m

    # secondary_prefix[i] is the currently built prefix of
    # secondary line i.
    secondary_prefix = [0] * line_length

    sys.setrecursionlimit(100)

    def dfs(line, pos, primary_prefix):
        if line == primary_lines:
            return 1

        primary_value = primary[primary_prefix]
        secondary_value = secondary[secondary_prefix[pos]]

        # A character must be allowed by both tries.
        mask = primary_value & secondary_value & ALPHA_MASK

        answer = 0
        last_position = (pos == line_length - 1)
        last_line = (line == primary_lines - 1)

        while mask:
            bit = mask & -mask
            mask -= bit

            digit = bit.bit_length()  # 1..26

            new_primary = primary_prefix * 27 + digit
            new_primary_value = primary[new_primary]

            # The primary line must be a complete dictionary word
            # when its final character is placed.
            if last_position and not (new_primary_value & TERM):
                continue

            old_secondary = secondary_prefix[pos]
            new_secondary = old_secondary * 27 + digit
            new_secondary_value = secondary[new_secondary]

            # On the final primary line, this character also completes
            # the secondary line, so it must be a complete word.
            if last_line and not (new_secondary_value & TERM):
                continue

            secondary_prefix[pos] = new_secondary
            answer += dfs(line, pos + 1, new_primary)
            secondary_prefix[pos] = old_secondary

        return answer

    return str(dfs(0, 0, 0))

if __name__ == "__main__":
    print(solve())
```二人の呼びかけは、`build_trie`元の文字列を保持せずに 2 つの辞書を使用します。 これは最大の入力の場合に重要であり、数十万の Python 文字列オブジェクトを保持すると、トライ自体よりもかなり多くのメモリが浪費されることになります。 

プレフィックスのエンコードでは、異なる長さのプレフィックスを区別する必要があるため、Base 26 ではなく Base 27 が使用されます。 からの数字付き`1`を通して`26`、のコード`a`は`1`、一方、コードは`aa`は`28`、したがって、それらは決して衝突することはありません。 空のプレフィックスは単に`0`。 

各トライエントリには文字マスクが含まれています。 たとえば、プレフィックスが`s`続くことができます`a`、`e`、 または`t`、そのエントリには、これらの 3 つの文字セットに対応するビットが含まれています。 このような 2 つのマスクを交差させる方が、26 文字すべてを試して個別の辞書検索を実行するよりもはるかに安価です。 

終端フラグは、26 文字ビットの外側のビット 26 に格納されます。 接頭辞は完全な単語であると同時に子を持つこともできます。 たとえば、両方の場合、`are`そして`area`存在する、のノード`are`を許可しながら終端を維持する必要があります`a`次のキャラクターとして。 

の`last_position`主行の終わりに到達しただけでは、その行が辞書の単語であることが保証されないため、テストが必要です。 同じことが当てはまります`last_line`二次回線用。 検索中にこれらの条件を確認すると、完成したグリッドを 2 回通過することが回避されます。 

Python の整数には任意の精度がありますが、有効なグリッドの数が 32 ビットまたは 64 ビットの整数に収まる保証がないため、これが必要になります。 検索自体はすべてのグリッドを保存することはなく、グリッドの数を蓄積するだけです。 

再帰の深さは最大でも`N × M`、これは最大 16 であるため、再帰は安全です。 セカンダリ プレフィックス配列は再帰呼び出しの前に変更され、その後すぐに復元されます。 次のブランチが前のブランチから文字を継承することになるため、復元を忘れることは典型的なバックトラッキング バグです。

 | 1 | 2 |`e`|`the`|`it`、`the`、`se`|
 | 2 | 0 |`s`|`s`|`its`、`the`、`s`|
 | 2 | 1 |`e`|`se`|`its`、`the`、`se`|
 | 2 | 2 |`t`|`set`|`its`、`the`、`set`|

 最後の列のプレフィックスは次のとおりです。`its`、`the`、 そして`set`, したがって、このブランチは受け入れられます。 2 番目のブランチは行を含むグリッドを生成します`ran`、`age`、`now`。 答えは`2`。 

これらのトレースは、中心の不変量を直接示しています。 セカンダリ プレフィックス配列内のすべてのプレフィックスは、対応する行または列が完了する前であっても、許可された単語のプレフィックスであることがすでにわかっています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | トライ施工 |`O(4(A+B))`| すべての入力単語の長さは最大 4 |
 | 検索 |`O(NM · S)`| 訪問した各セルは最大 26 個の候補文字を検査します。 
| スペース |`O(27^4 + NM)`| 2 つの固定プレフィックス配列と現在のセカンダリ プレフィックス |

 ここ`S`は、トライ枝刈り後に訪問された部分グリッドの数を示します。 完全な行検索の有用な上限は次のとおりです。`min(A^M, B^N)`これは、実装が 2 つの方向のうち小さい方を選択するためです。 文字レベルのトライ チェックは通常、はるかに早い段階で分岐を切断します。 

固定トライ サイズは、Python では特に便利です。 以来`27^4 = 531441`、そのサイズの 2 つの配列は、256 MB のメモリ制限に対して十分小さいため、数百万の Python 辞書エントリによる大幅なオーバーヘッドを回避できます。 グリッド自体には最大でも 16 個のセルがあるため、再帰状態は非常に小さいです。 

一般的な単語と四角形の定式化では検索の指数関数的な性質は避けられませんが、この問題では意図的に両方の次元が 4 つに制限され、積が辞書のサイズに制限されます。 トライは、完全なグリッドの列挙ではなく、検索を制約の伝播に変えます。これは、制約を実用化するための意図された方法です。

 ## 特殊なケース

 最小サイズがすべて等しい場合、```
2 1
2 1
aa
aa
```検索は両方の試行から開始され、のみ許可されます`a`。 最初のセルは両方のプレフィックスを次のセルに進めます。`a`、2 番目のセルは次のように主行を完成させます。`aa`。 次の行では、まったく同じプロセスを繰り返します。 最後にすべての行と列が終端となるため、答えは次のようになります。`1`。 最初の使用では単語が消費されないため、すべての行で同じ辞書エントリが利用可能なままになります。 

互換性のないプレフィックスの場合は、```
2 1
2 1
ab
aa
```プライマリ ルート ノードとセカンダリ ルート ノードでは、異なる文字が許可されます。 垂直トライにより、`a`、水平トライも可能です`a`したがって、最初のセル自体は拒否されません。 配置後`a`、最初の主行の次のセルには垂直プレフィックスが必要です`ab`そして水平プレフィックス`aa`。 縦方向の単語として使用できる次の文字は次のとおりです。`b`、横文字の場合は`a`。 彼らのマスクには空の交差があるため、分岐はすぐに終了します。 答えは`0`。 

長方形のケースの場合、```
2 4
4 1
aa
bb
ab
ba
abba
```唯一の横文字は`abba`したがって、両方の行は次のようになります。`abba`。 結果の列は次のとおりです。`aa`、`bb`、`ba`、 そして`ab`。 4 つすべてが垂直トライに存在します。 このアルゴリズムは行と列の数が等しいことを想定していないため、長さ 4 の 2 つの主行を処理し、正しく返します。`1`。 

大きな辞書の場合、入力には次のような縦方向の単語が 1000 個含まれます。`a`で始まる横文字1000語`b`。 製品はまさに`1,000,000`、必要な制限内で。 一番最初のセルでは、垂直ルート マスクには次のものが含まれます。`a`一方、水平ルートマスクには次のものが含まれます`b`。 それらの交差はゼロであるため、最初のセルを検査した後に検索全体が終了します。 答えは`0`、また、分岐の前にプレフィックス制約が適用されるため、大きな辞書によって大きな検索ツリーが生成されることはありません。 

の`N = M`制限では、検索に特別なロジックは必要ありません。 アルゴリズムは常に、実際の方向に対応する辞書に対して行をチェックします。 ある単語が両方の辞書に掲載されている場合、当然、その単語は両方向に出現する可能性があります。 どちらか一方のみに出現する場合は、その方向でのみ使用できます。 これは、バックトラッキング コードに特殊なケースの分岐を導入することなく、必要なルールに一致します。
