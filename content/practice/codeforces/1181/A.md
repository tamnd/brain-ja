 ## 解決策
 ## 問題の理解

 2 人がある程度の通貨を保有しており、必要に応じて、使用する前に相互に整数を送金できます。 通貨単位ごとに 1 つのアイテムをサイズごとに購入します`z`、つまり各人が独自に自分のお金を次のように変換します。`floor(money / z)`アイテム。 目標は、これらのフロア分割の合計が最大になるように、2 人の間で合計金額を再分配することです。 可能な限り最適な再分配を見つけた後は、アイテムの最大数を達成しながら、それらの間で送金される金額を最小限に抑える必要もあります。 

重要なオブジェクトは関数です`f(t) = floor(t / z)`。 合計スコアは`f(x') + f(y')`どこ`x' + y' = x + y`。 転送では合計額が維持されるため、問題は固定額を 2 つの部分に分割して下限額の合計を最大化する方法になります。 

制約は次のとおりです`10^18`これにより、考えられるすべての再配布を試みるソリューションは即座に除外されます。 可能な転送量を繰り返す場合でも、最大で`10^18`最悪の場合の手順ですが、実行不可能です。 これにより、シミュレーションではなく除算の算術特性に基づいた解決策が強制されます。 

両方の場合に微妙なエッジケースが発生します。`x`そして`y`すでに次の倍数です`z`。 その場合、いかなる移転も結果を改善することはできず、いかなる移転も合計を減少させるリスクがあるだけです。 もう 1 つの重要なケースは、1 人の人の所有する資産が、`z`、少数のコインを転送すると、境界を越えて貢献度が 1 増加する可能性があるためです。 

たとえば、次の場合`z = 5`、`x = 4`、`y = 1`、その後、転送せずに両方が貢献します`0`。 しかし、1コインを動かすと、`(5, 0)`、合計が増加します`1`。 これは、境界を越える転送のみが重要であることを示しています。 

## アプローチ

 強引なアイデアは、移動するためにあらゆる可能な方法を試すことです`k`ある人から別の人にコインが渡されます。`k`からの範囲`-x`に`y`。 分割ごとに`(x + k, y - k)`、計算する`floor((x + k)/z) + floor((y - k)/z)`そして最良の結果を追跡します。 これは、有効な再配布をすべて列挙しているため、正しいです。 ただし、範囲は、`k`まで可能です`10^18`、これは完全に不可能になります。 

重要な観察は次のとおりです`floor(t / z)`次の場合にのみ変更されます`t`の倍数を横切る`z`。 これは、有用な転送のみが、次のいずれかをプッシュする転送であることを意味します。`x`または`y`最も近い倍数にわたって`z`。 マルチプルに達する以上の追加転送は何も行わないか、相手の下限値を減らすかのどちらかです。 

したがって、すべての分割を検索するのではなく、一定数の候補、つまり現在の分割と、各値を最も近い倍数まで上下に移動する調整のみをチェックします。`z`。 各個人の価値はモジュロのみが重要であるため`z`、問題は、剰余についての推論と、それらをサイズの完全なブロックにどのように交換できるかに帰着します。`z`。 

合計金額を計算します`S = x + y`。 アイテムの最大数は常に次のとおりです。`S // z`, 送金によって合計金額を変更することはできないためです。 残っている唯一のタスクは、この限界が達成可能であることを確認し、両側が次の倍数で最適に整列する構成に到達するために必要な最小限の転送を決定することです。`z`。 

最適な戦略は、一方の側を次の倍数にできるだけ近づけることです。`z`ブロックを完了するために必要な最小数のコインを転送することによって。

 ## アルゴリズムのチュートリアル

 1. 合計金額を計算する`S = x + y`。 これは修正されているため、再配布ではそれが保持されます。 
2. 可能なココナッツの最大数を次のように計算します。`S // z`。 ココナッツごとにコストがかかるため、これを超える再分配はできません`z`そして合計金額は不変です。 
3. 距離を計算する`x`は次の倍数からです`z`、つまり`x % z`、同様に`y % z`。 これらの剰余によって、転送によりどちらかの側でフル ブロックの数を増やすことができるかどうかが決まります。 
4. 両方の剰余がゼロかどうかを確認します。 その場合、どちらもすでにブロック境界に完全に位置合わせされているため、転送しても何も改善されません。 
5. それ以外の場合は、サイズの境界を越えて少なくとも 1 つの側面を移動するのに必要な最小移動量を決定します。`z`。 これは、片方の余りがちょうどゼロになるまでコインを一方の側からもう一方の側に移動させることによって達成されます。 最小転送量は次の小さい方です。`x % z`(x から y に移動) または`y % z`(y から x に移動)、どちらの側を最初に完了しようとするかに応じて異なります。 
6. ココナッツの最大数とこの最小転送値を出力します。 

### なぜ効果があるのか

 フロア関数は、値が次の倍数を横切る場合にのみ変化します。`z`。 どちらかの側の商を変えない転送は目的とは無関係です。 したがって、最適解は、少なくとも 1 つの辺が次の条件で割り切れる境界に存在する必要があります。`z`。 このような境界に到達する動きの中で、転送されるコインを最小限に抑えることは、最も近い倍数までの距離を最小限に抑えることと同じです。`z`どちらかの側に。 これにより、最適化の問題全体が局所的な剰余の調整に軽減されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

x, y, z = map(int, input().split())

s = x + y
max_coconuts = s // z

rx = x % z
ry = y % z

if rx == 0 and ry == 0:
    print(max_coconuts, 0)
else:
    # minimal transfer to make one side reach a multiple of z
    ans_move = min(rx, ry)
    print(max_coconuts, ans_move)
```最初の部分では、再分配によって総金額が変わらないという不変条件から厳密にココナッツの総数を計算します。 残り`rx`そして`ry`各人が追加の完全なココナッツ ブロックを形成するまでの距離を記録します。 最小転送は、より小さいギャップを次の倍数に固定することに対応します。`z`。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    x, y, z = map(int, input().split())
    s = x + y
    print(s // z, min(x % z, y % z) if not (x % z == 0 and y % z == 0) else 0)

def run(inp: str) -> str:
    old = sys.stdin
    sys.stdin = io.StringIO(inp)
    from contextlib import redirect_stdout
    import io as _io
    out = _io.StringIO()
    with redirect_stdout(out):
        solve()
    sys.stdin = old
    return out.getvalue().strip()

# samples
assert run("5 4 3") == "3 1"

# custom tests
assert run("0 0 5") == "0 0"
assert run("10 10 5") == "4 0"
assert run("1 8 3") == "3 1"
assert run("1000000000000000000 0 1") == "1000000000000000000 0"

 ## 特殊なケース

 両方の値がすでに割り切れる場合`z`、すべてのユニットがすでに完全に詰め込まれているため、転送なしで完全なグループの数を増やすことはできません。 入力用`10 10 5`、両方ともそれぞれ正確に 2 ユニットを提供し、転送では一方の商が減少するだけで、もう一方の商が増加する可能性があり、合計は変わらないか悪化したままになります。 

次のように、一方の辺が倍数に非常に近い場合`1 8 3`、単一のユニットを転送するだけで、片側の境界を越えることができます。 最小剰余は各辺が境界からどれだけ離れているかを直接測定し、より小さい剰余は商の増加を引き起こす最も安価な方法を表すため、アルゴリズムはこれを捉えます。
