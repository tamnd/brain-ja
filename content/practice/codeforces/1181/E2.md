 ## 解決策
 ## 問題の理解

 「城」を表す、軸に揃えられた一連の長方形が与えられます。 これらの長方形は、境界や角を共有する場合がありますが、領域的には重なりません。 これらの城は、それぞれの城がそれぞれの国に属していた古い歴史に由来しており、時が経つにつれて、領土の結合がまだ長方形であったときはいつでも国々が合併したという主張です。 

最後には一国だけが残り、城だけが見えてきました。 問題は、各城を最初の国に割り当て、一連の合併をシミュレートできるかどうかです。各合併では、現在の 2 つの国がまだ長方形である場合は常に 1 つに結合され、最終的にはすべての国がすべての城を含む単一の最終的な長方形に合併されます。 

重要な隠された構造は、マージでは長方形のみが保存されるため、すべての中間国は元の城全体で構成される軸に沿った長方形に対応する必要があるということです。 私たちはプロセスを再構築することを求められるのではなく、そのようなプロセスが存在し得るかどうかを判断することだけを求められます。 

入力サイズは 10 万個の四角形に達し、それぞれの四角形は最大 10 億の座標を持ちます。 長方形のペアをチェックしたり、単純にマージをシミュレートしたりするソリューションは、二次関数の動作につながり、直ちに実行不可能になります。 たとえ$O(n \log^2 n)$アプローチは慎重に正当化される必要があります。 

微妙な失敗例は、四角形がグローバルに一貫性のある構成を形成しているが、四角形を保持した方法でマージすることがローカルでは不可能な場合に発生します。 たとえば、4 つの長方形が中空の正方形の境界線を形成していると想像してください。 各長方形は隣接する 2 つの長方形と接触しますが、ペアごとのマージでは長方形ではなく L 字型が生成され、有効なマージ シーケンスがブロックされます。 隣接する四角形を選択する単純な貪欲なマージ戦略では、そのようなケースが誤って受け入れられます。 

もう 1 つの注意が必要なケースは、グローバル境界四角形が完全にカバーされているにもかかわらず、有効なマージ順序が存在しない構造により依存関係の「サイクル」が強制される場合です。 これは通常、マージの実現可能性を考慮せずにカバレッジまたは隣接性のみをチェックするアプローチを無効にします。 

## アプローチ

 直接的なブルートフォース解釈では、プロセスを明示的にシミュレートしようとします。 各四角形をノードとして扱い、和集合が四角形を形成する 2 つのノードを繰り返し検索します。 2 つの長方形の和集合が長方形であるかどうかのチェックは一定時間で実行できるため、総当たりの手順では、すべてのペアをスキャンし、有効なペアをマージし、1 つだけが残るかマージできなくなるまで繰り返します。 

各マージステップにはスキャンが必要です$O(n^2)$ペアで、最大でパフォーマンスを行うことができます$O(n)$合併します。 これは次のことにつながります$O(n^3)$最悪の場合の動作。これは制限をはるかに超えています。$n = 10^5$。 空間インデックス作成などの最適化を行ったとしても、マージの動的な性質により、効率的な候補ペアを維持することが困難になります。 

重要な点は、実際にはマージをシミュレートする必要がないということです。 長方形の結合は、2 つの長方形が全辺に沿って隣接している場合にのみ有効です。 これは、このプロセスが、完全なエッジ セグメントを共有することによって隣接性が定義される接続コンポーネントに長方形を段階的にグループ化することに相当することを意味します。 

これにより、問題は、非常に特殊な幾何学的隣接ルールに基づく接続条件に変換されます。 マージをシミュレートする代わりに、各グループを 1 つの四角形にマージでき、これらのグループ自体が矛盾なく階層的にマージできるように、四角形をグループに分割できるかどうかを確認します。 この構造は、「マージ可能なペア」によって引き起こされる隣接グラフが、禁止された構成に遭遇することなく 1 つのコンポーネントへの完全な縮小をサポートしているかどうかを検証することに要約されます。これは、スイープラインおよび間隔イベント推論を使用してテストできます。 

重要な点は、長方形を保持したマージを妨げる避けられない「コーナーのみの接触のサイクル」が配置に含まれていない場合に限り、このプロセスが有効であるということです。 これは、平面をスイープするときに垂直方向と水平方向の重なりがどのように相互作用するかを追跡することで確認できます。

 ## アルゴリズムのチュートリアル

 長方形を幾何学的間隔として解釈し、有効な長方形の結合によってそれらがどのようにマージできるかを推論します。 

1. まず、すべての長方形を X 座標で並べ替えます。 これにより、平面の垂直スライスが左から右にどのように変化するかを処理できます。 この順序の理由は、長方形の結合が共有の垂直境界に依存するためです。 
2. 平面を横切る垂直線をスイープし、スイープ位置と交差する長方形のアクティブな間隔を維持します。 各アクティブ セットは、その x 座標で可能なマージの「フロンティア」を表します。 
3. 各イベント ポイント (四角形の開始または終了 X 座標) について、アクティブ セットを更新し、Y 間隔がどのように分割されているかを追跡します。 いずれかの時点でアクティブな四角形が複数の互いに素な y セグメントを形成する場合、マージ グラフに構造境界を記録します。 これが必要なのは、後で相互作用しなければ、ばらばらの垂直スタックを 1 つの長方形にマージできないためです。 
4. 垂直方向または水平方向の完全な隣接関係を共有する四角形間の暗黙的な接続制約を構築します。 2 つの長方形は、その投影が部分的に重なっているのではなく、完全なエッジ セグメントに沿って正確に位置合わせされている場合にのみ、接続可能であるとみなされます。 
5. 次に、この接続構造が矛盾なく単一のコンポーネントに完全に縮小できるかどうかを検証します。 これは、隣接グラフが長方形有効エッジの下で接続されているかどうかを確認することと同等であり、スイープ中に一貫性のない y 分割によって引き起こされる強制的な分離が含まれていないことを確認します。 
6. 最後に、すべての四角形が単一の一貫したマージ構造に属しているかどうかを確認します。 スイープがアクティブな間隔で矛盾した分割を検出した場合は拒否します。 それ以外の場合は受け付けます。 

### なぜ効果があるのか

 すべての有効なマージ シーケンスは、隣接する長方形をエッジ全体に沿って繰り返しマージすることに対応しており、これにより軸の位置合わせが維持され、中間オブジェクトが確実に長方形のままになります。 これにより、x スイープ中に y 間隔がどのように変化するかについて厳密な層構造が課せられます。 任意の x 座標で、アクティブ セットが複数の切断された垂直コンポーネントに分割され、一貫して再接続されない場合、長方形を保持する一連の結合ではすべてを 1 つの長方形にマージすることはできません。 逆に、スイープによってそのような矛盾が強制されない場合は、スイープ構造と一致する順序で長方形をマージすることができ、有効な構造が存在することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def can_merge(rects):
    # We compress the problem into checking consistency of vertical ordering
    # using sweep events on x-coordinates.
    events = []
    ys = set()

    for x1, y1, x2, y2 in rects:
        events.append((x1, y1, y2, 1))
        events.append((x2, y1, y2, -1))
        ys.add(y1)
        ys.add(y2)

    events.sort()

    # We track active y-interval coverage via coordinate compression + counter.
    ys = sorted(ys)
    idx = {v: i for i, v in enumerate(ys)}

    cnt = [0] * (len(ys) + 1)

    def add(l, r, val):
        for i in range(l, r):
            cnt[i] += val

    def check_gap():
        active = False
        found_block = False
        for i in range(len(ys) - 1):
            if cnt[i] > 0:
                active = True
            else:
                if active:
                    found_block = True
                    break
        return not found_block

    i = 0
    while i < len(events):
        x = events[i][0]

        while i < len(events) and events[i][0] == x:
            _, y1, y2, t = events[i]
            l, r = idx[y1], idx[y2]
            if t == 1:
                add(l, r, 1)
            else:
                add(l, r, -1)
            i += 1

        if not check_gap():
            return False

    return True

def main():
    n = int(input())
    rects = [tuple(map(int, input().split())) for _ in range(n)]
    print("YES" if can_merge(rects) else "NO")

if __name__ == "__main__":
    main()
```コードは、X 軸上のすべての長方形の端点に対してスイープを実行します。 イベントごとに、離散化された y 間隔のカバレッジを更新します。 重要な構造は、`cnt`配列。各垂直セグメントを現在カバーしている四角形の数を追跡します。 の`check_gap`関数は、y のアクティブなカバレッジが連続したままでなければならないことを強制します。 そうしないと、構成により、四角形を保持したマージによって調整できない分割が強制されます。 

よくある実装の落とし穴は、隣接関係がエッジ全体をカバーする必要があることを忘れていることです。 y に沿った部分的なオーバーラップだけでは十分ではないため、スイープでは単にオーバーラップを追跡するのではなく、カバレッジの連続性が検証されます。

 次のことを考慮してください。```
4
0 0 1 1
0 1 1 2

```| × | アクティブ y カバレッジ | ギャップが検出されました |

これは、グローバルな垂直方向の連続性が維持されない限り、ローカルな隣接性では十分ではないことを示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 |$O(n \log n + n \cdot k)$| 仕分けイベントが支配的です。 各スイープ更新は圧縮された構造をスキャンします。 
| スペース |$O(n)$| イベントと圧縮された y 座標を保存する |

 スイープは処理のみを行うため、アルゴリズムは制約内に収まります。$2n$イベントと y 座標の圧縮により、更新が管理しやすくなります。 この構造により、四角形のペアごとの比較が回避されます。

 ## 特殊なケース

 主なエッジケースは、長方形が角でのみ接触する場合です。 たとえば、2 つの長方形が 1 点で交わる場合、それらは幾何学的に隣接していても、有効なマージ エッジを提供しません。 アルゴリズムはこれらをスイープ内の重複しない y 間隔として正しく処理するため、連続性は作成されず、構成は失敗します。 

別のケースは、交互のストリップを形成する細長い長方形です。 ローカルではペアでマージ可能に見えますが、グローバルではアクティブなカバレッジで永続的な分割を強制します。 スイープ中、これは決して統合されない素の y コンポーネントの繰り返しの作成として現れ、アクティブな構造が連続していない最初の無効な x イベントで拒否を引き起こします。
