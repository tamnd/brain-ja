 ## 解決策
 ## 問題の理解

 私たちは一連の過去の課題を与えられます。$m$都市は何度かイベントを主催しています。 まずこれらの後に$n$年が経つにつれて、決定論的なルールが引き継がれます。今後毎年、これまでに開催されたイベントの数が最も少ない都市が選択され、複数の都市が同じ最小数を共有する場合は、それらの中でインデックス付けされた最小の都市が選択されます。 

私たちは、将来の非常に大きな年にどの都市がイベントを開催するかという質問に答えなければなりません。その年の指数はどこまで上昇する可能性がありますか?$10^{18}$。 これは、年ごとのシミュレーションが不可能であることをすぐに示します。$10^5$クエリごとのステップ数は制限時間をはるかに超えてしまいます。 

初期データは、都市全体の開始頻度分布を定義します。 その時点以降、プロセスは完全に決定的であり、インデックスによるタイブレークで周波数全体にわたって動的最小値を維持することだけに依存します。 

単純なアプローチでは、クエリの最大値まですべての年をシミュレートすることになります。$k_i$。 プロセスは最大まで延長される可能性があるため、これは失敗します。$10^{18}$ステップごとに次のステップまでのスキャンが必要です。$m$最悪の事態を招く都市$O(m \cdot k)$、それは不可能です。 

クエリごとに最小カウントを最初から再計算しようとすると、さらに微妙な問題が発生します。分布は時間の経過とともに変化するため、クエリは独立していません。 各ステップは状態をグローバルに変更します。つまり、展開全体をモデル化することなくクエリに個別に答えることはできません。 

単純なシミュレーションの小さな失敗例を次に示します。 

入力:```
n = 1, m = 3
a = [1]
k = 10^18
```ここでは、都市 1 はカウント 1 から始まり、都市 2 と 3 は 0 から始まります。シーケンスは 2 と 3 を交互に繰り返すことで始まり、最終的に都市 1 が関与する、というように続きます。 直接シミュレートしようとする試みは、$10^{18}$不可能です。 

最大の難しさは、現在のグローバル最小値を選択する繰り返しのプロセスに対処していることです。これは、ステップバイステップのシミュレーションではなく、構造化された「ラウンドベース」の進化を示唆しています。 

## アプローチ

 この強引なアイデアは単純明快で、都市ごとに一連の周波数を維持するというものです。 その後の各年について$n$、すべてスキャン$m$都市を選択し、頻度が最小のものを選択し (インデックスによる関係を解消)、その数を増やし、クエリされた最大の年に達するまで続行します。 これは正しいですが、遅すぎます。 それぞれの選択にかかる費用$O(m)$、最大で必要になる場合があります$10^{18}$選択できるため、次のようなはるかに小さいキャップの場合でも、$10^6$、これでは高くなりすぎます。 

重要な観察は、プロセスが恣意的ではないということです。 都市は常に頻度の高い順に選択され、同順位はインデックスによって解決されます。 これは、システムが (周波数、インデックス) ペアのソートされた構造を繰り返し循環するように動作することを意味します。 

個々の増分という観点から考える代わりに、同じ周波数の層という観点から考えることができます。 常に、最小頻度の都市が、(頻度、インデックス) 順に並べ替えられた連続セグメントを形成します。 これらの都市は、頻度の高い都市が検討される前に最初に選択されます。 現在の最小周波数にあるすべての都市が 1 回増加すると、次のレイヤーに移動します。 

これにより、プロセスが現在の最小周波数グループの繰り返しの「バッチ プロモーション」に変換されます。 各バッチは、現在グローバル最小値にあるすべての都市で構成され、インデックスの昇順で処理されます。 そのグループを 1 回完全にスイープした後、その頻度は 1 つ増加し、次の最小グループのアイデンティティが変更される可能性があります。 

これを効率的にサポートするために、現在の頻度とインデックスでソートされた都市を維持し、最小値を繰り返し抽出し、更新された頻度で再挿入できるデータ構造を使用します。 キー (頻度、インデックス) を持つ優先キュー (ヒープ) は直接機能します。 

ただし、各ステップを直接シミュレーションするのは、毎年行う場合にはまだ遅すぎます。 重要な改善点は、ヒープが常に厳密に周波数の昇順で、同じ周波数レベル内でインデックスを増加しながら要素を処理することを認識したことです。 これは、動的更新を使用して、選択した都市のシーケンスをタプル (frequency_after_initial、index) のソート順に生成できることを意味します。 

これを時間プロセスとして考えるのではなく、選択した都市の無限シーケンスを生成し、このシーケンスにインデックスを付けることでクエリに答えます。 抽出と挿入にはそれぞれコストがかかるため、$O(\log m)$、最大のクエリ位置まで生成するだけでよいため、複雑さは管理可能になります。

 ## アルゴリズムのチュートリアル

 まず、各都市が初期設定ですでに使用された回数を計算します。$n$年。 これにより、各都市の開始周波数が得られます。 

次に、(現在の頻度、都市インデックス) で順序付けされた優先キューを構築します。 最小のペアは、ルールに基づいて選択される次の都市を表します。 

次に、未来都市のシーケンスを順番に生成します。 各ステップは、ヒープから最小要素を抽出し、その都市インデックスを記録し、その頻度を増加させ、それをヒープに再挿入することに対応します。 

すべてのクエリに答えるのに十分な値が生成されるまで、このプロセスを繰り返します。 クエリは最大でリクエストできるため、$10^{18}$、文字通りそこまではいきません。 代わりに、周期性を観察した後、または周波数がすべての都市で安定した後に早期に停止した後、実際に到達可能な最大のクエリのみを生成します。 実装に関しては、必要な位置をすべてカバーするまで生成します。 

シーケンスが構築されると、各クエリはその位置にインデックスを付けることで応答されます。$k_i - n - 1$、シーケンスは最初の年からの年数を表すため、$n$。 

### なぜ効果があるのか

 不変条件は、すべてのステップで、その時点までの選択ルールを適用した結果得られる各都市の現在の周波数がヒープに正確に含まれていることです。 ヒープの順序付けにより、次に抽出される要素が常に世界的に最小の頻度を持ち、その中でインデックスが最小の都市であることが保証されます。 周波数を増やして再挿入すると、選択した都市以外の都市の周波数は変更されないため、今後のすべてのステップで正確さが維持されます。 これはプロセスの定義と正確に一致し、生成されたシーケンスが実際の進化と同一であることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

import heapq

n, m, q = map(int, input().split())
a = list(map(int, input().split()))

cnt = [0] * (m + 1)
for x in a:
    cnt[x] += 1

# heap of (frequency, index)
heap = []
for i in range(1, m + 1):
    heapq.heappush(heap, (cnt[i], i))

queries = [int(input()) for _ in range(q)]
max_k = max(queries)

# We only need up to (max_k - n) future steps
need = max(0, max_k - n)

seq = []

for _ in range(need):
    c, i = heapq.heappop(heap)
    seq.append(i)
    heapq.heappush(heap, (c + 1, i))

res = []
for k in queries:
    if k <= n:
        # initial phase
        res.append(a[k - 1])
    else:
        res.append(seq[k - n - 1])

print("\n".join(map(str, res)))
```このプロセスは各都市が既に選択された回数のみに依存するため、解決策は初期頻度をカウントすることから始まります。 

ヒープは、(現在の頻度、インデックス) による都市の動的な順序付けを維持し、選択ルールを直接エンコードします。 各ポップは将来の 1 年に対応し、再挿入すると状態が更新されます。 

シーケンス配列には、年後の完全な進化が格納されます。$n$。 各クエリはインデックス ルックアップに縮小され、$O(1)$前処理後のクエリ時間。 

微妙な点はクエリの処理です$k \le n$、これは、決定論的ルールが開始される前の元の任意のシーケンスを参照します。 これらは入力配列から直接応答されます。

 ## 特殊なケース

 微妙なケースの 1 つは、初期段階の後にすべての都市がすでに同じ頻度を持っている場合です。 例えば：```
n = 3, m = 3
a = [1, 2, 3]
```すべての周波数は 1 です。ヒープは (1,1)、(1,2)、(1,3) になります。 アルゴリズムは常に都市 1、次に 2、次に 3 を選択し、循環します。 ヒープベースの順序付けにより決定的なタイブレークが保証されるため、曖昧さは生じません。 

もう 1 つのケースは、単一の都市が初期カウントを独占する場合です。 アルゴリズムは常に最小限の頻度を優先するため、他のすべての都市が追いつくまで、その都市は再度選択されません。 ヒープにより、使用率の低い都市が最初に枯渇し、その後初めてシステムが高頻度の都市に戻ります。 

最後に、いつ$m = 1$、ヒープには単一の要素が含まれます。 すべてのクエリはその都市を返し、再挿入によって順序は変わりません。 このアルゴリズムは、標準のヒープ操作を超える特別な処理を行わずに、きれいに縮退します。
