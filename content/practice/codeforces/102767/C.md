 # 問題の理解

 タスクは、少なくとも 2 つの要素を持つ配列の連続したセグメントを選択することです。 このようなすべてのセグメントの中で、要素が可能な限り最大の公約数を持つセグメントが必要です。 複数のセグメントが同じ約数に達する場合、最も長いセグメントが優先されます。 出力は、選択したセグメントの除数と長さです。 

配列には最大で次のものが含まれます$10^5$すべてのテスト ケースの合計要素数。各値は次のように大きくできます。$10^9$。 すべての部分配列をチェックする二次解法には、約$n^2$GCD の計算。 と$n=10^5$、それは約になります$10^{10}$限界をはるかに超えた操作。 セグメントを列挙する代わりに GCD の数学的構造を使用する必要があります。 

いくつかのケースでは、誤って対処されやすいものがあります。 すべての要素が等しい場合、最も長い有効なセグメントが選択される必要があるため、答えは値と長さ 2 だけではありません。 入力用`4 4 4`、答えは`4 3`、配列全体に GCD が 4 つあるためです。 ペアのみをチェックするソリューションでは、間違った長さが返されます。 

最良の GCD が短いセグメントにのみ存在する場合、別のエッジ ケースが発生します。 入力用`3 6 4`、セグメント`[3, 6]`GCD は 3 ですが、これを拡張して 4 を含めると GCD は 1 に減ります。 正しい出力は次のとおりです`3 2`。 有望なセグメントをすべて拡張し続ける不注意な実装では、最適な GCD が失われます。 

答えは、配列の最後にある単一の隣接するペアから得られることもあります。 入力用`1 10 15`、最後の 2 つの要素には GCD 5 があり、セグメントはその値を保持しなくなりました。 正しい出力は次のとおりです`5 2`。 境界処理には最終ペアを含める必要があります。 

# アプローチ

 直接的なアプローチは、すべてのサブ配列を試すことです。 左端と右端のそれぞれについて、セグメントを拡張しながら GCD を維持し、現在の GCD が向上するか、同じ GCD がより長い長さで表示されるたびに答えを更新します。 考えられるすべての候補セグメントが検査されるため、これは正しいです。 ただし、$O(n^2)$サブ配列、および定数時間の GCD 更新を使用した場合でも、演算の数が多すぎます。 のために$n=10^5$、最悪の場合には、ほぼ 50 億のサブ配列が含まれます。 

重要な観察は、答えの GCD が 2 つの隣接する要素の GCD としてすでに現れている必要があるということです。 サブ配列に GCD があるとします。$g$。 長さが少なくとも 2 であるため、何らかの隣接するペアが含まれています。 そのペアの両方の要素は次のように割り切れます。$g$したがって、GCD も次のように割り切れます。$g$。 これは、最適値を隣接するペアの GCD より大きくすることはできないことを意味します。 

今では問題ははるかに小さくなりました。 隣接するペアの GCD 値の約数を調べるだけで済みます。 数の約数の数は次のとおりです。$10^9$小さいので、考えられるすべての候補を集めることができます。 すべての候補の約数について、それで割り切れる要素の最長連続ランを見つけます。 有効な実行での最大の約数が答えになります。 

ブルートフォース方式ではセグメントを検索します。 最適化された方法では、最終的な GCD となる可能性のある値のみが検索されます。

 # アルゴリズムのチュートリアル

 1. 配列内のすべての隣接するペアの GCD を計算します。 すべての有効なセグメントには隣接するペアが含まれるため、考えられるすべての答えはこれらの値の少なくとも 1 つを除算する必要があります。 
2. 隣接する各 GCD 値を因数分解し、そのすべての約数を生成します。 これらの約数を GCD 値の候補として保存します。 元の値が次のように制限されているため、生成される約数の数は少ないままです。$10^9$。 
3. すべての約数候補について$d$、配列をスキャンし、すべての要素が次の値で割り切れる最長の連続ブロックを見つけます。$d$。 現在の要素が次の要素で割り切れる場合$d$、現在のブロックを拡張します。 それ以外の場合は、ブロック長をリセットします。 
4. 最大の約数を持つ候補を保持します。 2 つの候補の約数が同じ場合は、ブロック長が大きい方を保持します。 この問題では最初に最大の GCD が求められるため、可能な最大の約数が優先されます。 

機能する理由: GCD を含むすべての有効なサブ配列$g$2 つの値が両方とも の倍数である隣接するペアが含まれています。$g$。 したがって、$g$その隣接するペアの GCD を除算します。つまり、$g$生成された候補の中に含まれています。 各候補をスキャンするとき、すべての要素がそれで割り切れる最長の部分配列を正確に計算します。 したがって、候補スキャンでは、考えられるすべての応答値がチェックされ、正しい値が選択されます。 

# Python ソリューション```python
import sys
from math import gcd

input = sys.stdin.readline

def divisors(x):
    res = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            res.append(i)
            if i * i != x:
                res.append(x // i)
        i += 1
    return res

def solve_case(a):
    n = len(a)
    candidates = set()

    for i in range(n - 1):
        g = gcd(a[i], a[i + 1])
        for d in divisors(g):
            candidates.add(d)

    best_g = 1
    best_len = 2

    for d in candidates:
        cur = 0
        longest = 0
        for x in a:
            if x % d == 0:
                cur += 1
                if cur > longest:
                    longest = cur
            else:
                cur = 0

        if longest > 1:
            if d > best_g or (d == best_g and longest > best_len):
                best_g = d
                best_len = longest

    return best_g, best_len

def main():
    t = int(input())
    ans = []
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        g, length = solve_case(a)
        ans.append(f"{g} {length}")
    print("\n".join(ans))

if __name__ == "__main__":
    main()
```の`divisors`関数は、係数のペアをその平方根までチェックすることによって、単一の数値から考えられるすべての候補を生成します。 隣接する GCD 値は最大でも$10^9$、この直接的な方法は十分に高速です。 

最初のスキャンでは、隣接するペアから除数のみを収集します。 長い有効なセグメントにはすべてそのようなペアが含まれるため、長いセグメントを検査する必要はありません。 

2 番目のスキャンでは、各候補を個別にチェックします。 変数`cur`は、現在位置で終了する現在の連続ブロックの長さを表します。`longest`その除数に最適なブロックを保存します。 リセットする`cur`割り切れない場合は、分離された要素が誤って 1 つの部分配列としてカウントされるのを防ぐ部分です。 

Python の整数はオーバーフローしないため、大きな値に対して特別な処理は必要ありません。 唯一の境界条件は、ブロックの長さが少なくとも 2 でなければならないということであり、これは答えを更新する前にチェックされます。

# テストケース```python
import sys
import io
from math import gcd

def divisors(x):
    res = []
    i = 1
    while i * i <= x:
        if x % i == 0:
            res.append(i)
            if i * i != x:
                res.append(x // i)
        i += 1
    return res

def solve(inp):
    data = list(map(int, inp.split()))
    t = data[0]
    idx = 1
    out = []
    for _ in range(t):
        n = data[idx]
        idx += 1
        a = data[idx:idx + n]
        idx += n

        cand = set()
        for i in range(n - 1):
            for d in divisors(gcd(a[i], a[i + 1])):
                cand.add(d)

        bg = 1
        bl = 2
        for d in cand:
            cur = 0
            best = 0
            for x in a:
                if x % d == 0:
                    cur += 1
                    best = max(best, cur)
                else:
                    cur = 0
            if best > 1 and (d > bg or (d == bg and best > bl)):
                bg = d
                bl = best

        out.append(f"{bg} {bl}")
    return "\n".join(out)

 # エッジケース

 すべてが等しい場合`4 4 4`、隣接する GCD 値により約数 4 が生成されます。 約数 4 のスキャンでは長さ 3 の連続ランが確認されるため、答えは次のようになります。`4 3`最初のペアで停止するのではなく。 

場合について`3 6 4`、除数 3 は最初の隣接ペアから生成されます。 4 は 3 で割り切れないため、スキャンは最初の 2 つの要素をカウントし、要素が 4 に達すると停止します。 これにより、長さ 2 が生成され、必要なサブ配列と一致します。 

最終ペアの場合`1 10 15`、最後の 2 つの要素の隣接する GCD は約 5 を生成します。 スキャン中は最後の 2 つの値のみが実行を延長するため、アルゴリズムは次の値を返します。`5 2`。 スキャンでは境界を含むすべての配列要素が検査されるため、最後の位置が含まれます。
