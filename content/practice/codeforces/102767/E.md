 ## 解決策
 ## 問題の理解

 この問題は、商品に初期価格が設定されているショップをモデル化しています。`X`。 顧客は任意の数を購入できます`N`限り同じアイテムの`N`はの適切な約数です`X`、 意味`N`分割する`X`そして`1 <= N < X`。 当店では種類に応じて追加料金を設定しております。`N`: 素数は値を使用します`A`、合成数は値を使用します`B`、 そして`N = 1`値を使用します`C`。 合計コストは、選択した追加価値に加えたものです`X / N`。 タスクは、可能な最小限のコストを見つけることです。 

入力には複数の独立したクエリが含まれています。 各クエリで得られるのは、`X`そして3つの追加費用`A`、`B`、 そして`C`。 各クエリの出力は、有効な数の項目を選択することで達成可能な最小コストです。 

重要な制約は、`X <= 10^7`まであります`10^5`クエリ。 すべての約数をチェックするソリューション`X`に近い数値なので適切ではありません`10^7`依然として数千の約数が存在する可能性があり、クエリごとに不必要な作業を行うと時間予算が無駄になります。 試行除算を使用して平方根まで各数値を因数分解することも、直接実行するとコストがかかりすぎます。`10^5 * sqrt(10^7)`周りにいる`3 * 10^8`試験運用。 クエリ全体で作業を再利用し、各数値の小さな素因数だけを検査する必要があります。 

主なエッジケースは、約数の分類から得られます。 値には素の約数を含めることはできますが、複合の適切な約数は持たないため、複合の候補が常に存在すると仮定すると、間違った答えが得られます。 例えば：```
Input
4
2 5 1
```唯一の有効な選択肢は、`N = 1`、 なぜなら`2`他に適切な約数はありません。 答えは`7`。 素数または合成除数のみを検索する不注意な実装では、このケースを見逃してしまいます。 

もう 1 つの注意が必要なケースは、素数の 2 乗である数値です。```
Input
9
1 10 3
```有効な選択肢は次のとおりです`N = 1`そして`N = 3`。 除数`3`素数であり、合成ではありません。 答えは`6`。 最大の適切な約数を複合として扱うと、複合コストの式が誤って使用されてしまいます。 

通常の複合例では、逆の動作もチェックします。```
Input
12
2 5 1
```適切な約数は次のとおりです。`1, 2, 3, 4, 6`。 最良のプライムの選択は、`N = 3`、与える`2 + 4 = 6`。 最適な複合材料の選択は次のとおりです。`N = 6`、与える`5 + 2 = 7`。 答えは`6`。 

## アプローチ

 直接的なアプローチは、すべての約数を列挙することです。`N`の`X`、分類し、コストを計算し、最小限に抑えます。 考えられるすべての購入数量がチェックされるため、これは正しいです。 ただし、平方根除数検索を使用しても、すべてのクエリに対して因数分解または除数の列挙が必要です。 最悪の場合、素数が大きいと、平方根までのすべての整数が強制的にチェックされます。 クエリが多いと、繰り返される作業が膨大になります。 

重要な観察は、固定カテゴリの場合、用語は`X / N`小さくなるとき`N`大きくなります。 追加費用`A`、`B`、 または`C`正確な除数には依存しません。 これは、各カテゴリで可能な最大の約数のみが必要であることを意味します。 

プライム用`N`、最良の候補は次の最大の素因数です。`X`。 複合用`N`、最良の候補は、の最大の適切な約数です。`X`。 合成数の最大の正約数は次のとおりです。`X / p`、 どこ`p`は最小の素因数です。 この値が複合値である場合、それが最適な複合候補になります。 プライムなら、`X`は正確に 2 つの素因数で構成されており、複合的な正約数は存在しません。 

残る作業は因数分解のみ`X`。 以来`X`せいぜい`10^7`、テストする必要がある考えられるすべての素因数は、最大でも次のとおりです。`3162`。 これらの素数を一度事前計算し、すべてのクエリに使用できます。

 | 最適 | クエリごとの O(素数の数 <= sqrt(X)) | O(素数の数 <= sqrt(10^7)) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 以下のすべての素数を事前計算します。`3162`エラトステネスのふるいを使って。 すべてのコンポジットがあるため、これらで十分です`X <= 10^7`は平方根を超えない素因数を持ちます。 
2. 各クエリの係数`X`事前に計算された素数を使用します。 除算中に、最小の素因数、最大の素因数、およびすべての小さな素因数を削除した残りの素因数を保存します。 

すべての素因数の中で最小の値が作成されるため、素数カテゴリには最大の素因数で十分です。`X / N`。 
3. 候補者を確認する`N = 1`。 その費用は`C + X`。 
4. 素約数が存在する場合は、最大の素約数を使用してコストを評価します。 
5. 除算して最大の適切な約数を見つけます`X`最小の素因数で計算します。 この除数が複合の場合、複合コストを評価します。 
6. 利用可能なすべての候補の最小値を取得し、それを印刷します。 

なぜ効果があるのか:

 考えられるすべてのカテゴリについて、アルゴリズムは最小化する除数を選択します。`X / N`。 追加カテゴリコストは固定のため、増加します`N`答えを改善することしかできません。 最大の素約数が最適な素数オプションを与えます。 最大の適切な約数が存在する場合、それが最適な複合オプションを提供します。 値`1`は独自のコスト ルールがあるため、個別に処理されます。 すべてのカテゴリの勝者がチェックされるため、グローバル最小値が見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

LIMIT = 3162

def sieve(n):
    is_prime = [True] * (n + 1)
    is_prime[0] = is_prime[1] = False
    for i in range(2, int(n ** 0.5) + 1):
        if is_prime[i]:
            for j in range(i * i, n + 1, i):
                is_prime[j] = False
    return [i for i in range(n + 1) if is_prime[i]]

primes = sieve(LIMIT)

def solve_case(x, a, b, c):
    ans = c + x

    temp = x
    smallest = None
    largest = None

    for p in primes:
        if p * p > temp:
            break
        if temp % p == 0:
            if smallest is None:
                smallest = p
            largest = p
            while temp % p == 0:
                temp //= p

    if temp > 1:
        if smallest is None:
            smallest = temp
        largest = temp

    if largest is not None:
        ans = min(ans, a + x // largest)

    if smallest is not None:
        composite = x // smallest
        if composite > 1 and composite % 2 == 0:
            pass
        if composite > 1:
            is_composite = True
            if composite == 2 or composite == 3:
                is_composite = False
            else:
                d = 2
                while d * d <= composite and d <= LIMIT:
                    if composite % d == 0:
                        is_composite = True
                        break
                    d += 1
                else:
                    is_composite = False
            if is_composite:
                ans = min(ans, b + x // composite)

    return ans

def main():
    t = int(input())
    out = []
    for _ in range(t):
        x = int(input())
        a, b, c = map(int, input().split())
        out.append(str(solve_case(x, a, b, c)))
    print("\n".join(out))

if __name__ == "__main__":
    main()
```すべてのクエリは有用な試行素数の同じ上限を共有するため、ふるいは 1 回だけ構築されます。 因数分解ループは、同じ約数を繰り返しチェックするのではなく、素数べき乗を削除します。 これにより、同じパス中の最小素因数と最大素因数の両方が得られます。 

約数が大きいほど常に次の値が得られるため、主候補は最大の素因数を使用します`X / N`より小さい。 複合候補は、最大の適切な約数から作成されます。 追加の素数チェックが必要なのは、次のような数値のためです。`9`そして`15`たとえそれ自体が素数ではないとしても、合成の適切な約数はありません。 

Python の整数はオーバーフローしないため、大きな値は`A`、`B`、 そして`C`添加中も安全です。 除算の順序も重要です。最初に除数の候補を決定し、次に計算します。`X / N`整数の除算を使用します。

 ## 特殊なケース

 のために`X = 2`の場合、適切な約数が存在しないため、アルゴリズムは素数または複合候補を見つけることができません。`1`。 初期値を保持します`C + X`、これが唯一の有効な答えです。 

のために`X = 9`、因数分解では、最小および最大の素因数が次のように求められます。`3`。 最大の適切な約数も`3`、しかし、素数であるため、複合チェックはそれを拒否します。 アルゴリズムは比較するだけです`N = 1`複合コストを素約数に適用するというよくある間違いを回避します。 

のために`X = 12`、最小の素因数は次のとおりです。`2`したがって、最大の適切な約数は次のようになります。`6`。 以来`6`が複合の場合、複合候補は有効です。 アルゴリズムは比較します`B + 2`最有力候補に対して`A + 4`特殊なケースでは、正しい最小値が生成されます。
