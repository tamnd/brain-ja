 ## 解決策
 ## 問題の理解

 いくつかの固定整数とゼロとしてマークされたいくつかの位置を含む配列が与えられます。 各ゼロは 1 から n までの整数で置き換える必要があり、同じ値であっても、異なるゼロの位置を独立して埋めることができます。 

配列を埋めた後、各整数値 k を調べ、非常に具体的な質問をします。k は、最終的な配列のどこかに等しい隣接する要素のペアとして少なくとも 1 回出現しますか? 「はい」の場合、そのような隣接するペアがいくつ形成されているかに関係なく、k はスコアに 1 を与えます。 目標は、できるだけ多くの個別の値 k が少なくとも 1 つの隣接する重複ペアになるように、ゼロの置換を選択することです。 

重要な構造は、ペアを数えているのではなく、k, k という形式の少なくとも 1 つの隣接関係を作成できる個別の値の数を数えているということです。 

制約は大きく、n は最大 3⋅10^5 です。 これにより、ゼロのすべての割り当てを試行したり、値ごとに選択肢を個別にシミュレートしたりするソリューションは即座に除外されます。 n の 2 次関数は遅すぎます。O(n√n) でもきついでしょう。 ソリューションでは、アレイを本質的に線形時間で処理し、隣接関係の形成方法における構造を利用する必要があります。 

重要な点は、ゼロが既存の値の間の「接着剤」として使用できることです。 現在、値には隣接する重複がない可能性がありますが、その出現の間にゼロを埋めて強制的に結合することができます。 もう 1 つの微妙なケースは、ゼロによって、入力には決して現れなかったまったく新しい値が作成される可能性があることです。 

単純な間違いは、各値が独立して処理できると想定することです。 たとえば、周囲にゼロを埋めて各値を貪欲に「修正」しようとする場合があります。 同じゼロの位置を複数の値に再利用できないため、これは失敗し、決定はグローバルに相互作用します。 

もう 1 つの間違いは、既存の隣接する等しいペアのみをカウントし、ゼロはあまり重要ではないと想定することです。 たとえば、`[1, 0, 1]`、ゼロを無視すると、値 1 に隣接性がないことが示されますが、ゼロを 1 として埋めると有効なペアが作成されます。 

最後に、各ゼロ ブロックを値ごとに独立して扱うことは間違っています。1 つの値のブロックを埋めると、他の値にサービスを提供する機能が破壊されるからです。 

## アプローチ

 ブルートフォースの観点では、あらゆる可能な方法で値をゼロに代入してスコアを計算することになります。 たとえ各 0 に n 個の選択肢しかなかったとしても、これは n^(#zeros) になりますが、これは不可能です。 

もう少し良いアイデアは、各値を個別に扱い、その値に対して隣接するペアを強制できるかどうかを判断することです。 固定値 k の場合、そのすべての出現を調べ、中間位置としてゼロを使用してそれらのうちの少なくとも 2 つを接続しようとします。 これは自然に接続性の観点につながります。位置 i と i+1 は、それらの少なくとも 1 つが 0 であるか、両方がすでに k 互換である場合に横断できます。 ただし、これを値ごとに個別に実行しようとすると、互換性のない方法でゼロを繰り返し消費することになります。 

重要な観察は、隣接関係の形成は基本的にゼロで接続された間隔に関するものであるということです。 少なくとも 1 つの端点が 0 であるか、両方の端点が 0 以外に等しい場合に、隣接するインデックスが接続されているグラフを考慮すると、接続された各コンポーネントは、ゼロを使用して値を自由に再形成できる「リソース領域」のように動作しますが、グローバルな制限があります。つまり、各コンポーネントを効果的に使用して、他の場所ではまだ成功していなかった新しい成功した値を最大 1 つ作成できます。 

これにより、問題は値ごとの推論からコンポーネントごとの推論に縮小されます。 元の配列にすでに隣接するペアがある値はすでに成功しており、コンポーネント リソースは必要ありません。 ゼロを含むコンポーネントは、コンポーネント内のいくつかの位置に一貫した値を割り当てることによって、追加の値を「アクティブ化」するために使用できます。

 | ブルートフォース割り当て | 指数 | O(n) | 遅すぎる |
 | コンポーネント + 貪欲な割り当て | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. インデックスの少なくとも 1 つがゼロであるか、同じ非ゼロ値がすでに含まれている場合、位置 i が i+1 に接続されているインデックスでグラフを構築します。 これにより、位置が連結成分にグループ化され、ゼロにより値の自由な伝播が可能になります。 
2. 各値 k について、元の配列に少なくとも 1 つの隣接するペアが既に存在するかどうかを確認します (ゼロは無視します)。 これにより、変更を加えずにすでにカウントされている値が識別されます。 
3. DSU または隣接ルールに対する線形スキャンを使用して、インデックスの連結成分を計算します。 各コンポーネントについて、ゼロが含まれているかどうかを記録し、その中に表示される値のセットを収集します。 
4. 既存の隣接関係により、すでに「良好」である値をすべてマークします。 これらはすぐに答えにつながるため、再度検討する必要はありません。 
5. 少なくとも 1 つのゼロを含むコンポーネントごとに、すでに良好ではない値が少なくとも 1 つ含まれているかどうかを判断します。 そうであれば、このコンポーネントを使用して、以前は達成できなかった追加の優れた価値を生み出すことができます。 
6. そのような新しい値を作成するのに適したコンポーネントがいくつあるかを数えます。 これを g とし、まだ良好ではない値の数を r とします。 追加ゲインの数は min(g, r) です。 
7. 条件を満たす各コンポーネントに個別の未使用値を割り当て、そのコンポーネント内のすべてのゼロを選択した値で埋めることによって最終的な配列を構築します。 

ステップ 6 の背後にある重要な制約は、新しい値はそれぞれ 1 回だけ「アクティブ化」できるということです。 複数のコンポーネントで同じ値を再利用した場合でも、カウントされるのは 1 回だけであるため、選択肢を個別の値に分散する必要があります。 

### なぜ効果があるのか

ゼロブリッジの下で形成された各接続コンポーネントは、コンポーネント全体に選択した値をゼロが自由に伝播できる領域のように動作します。 ただし、コンポーネントの値が選択されると、そのコンポーネントは、隣接関係の一貫性を損なうことなく、別の個別の新しい値を独立してサポートすることはできません。 これにより、1 対 1 の制限が生じます。各有用なコンポーネントは、以前は非アクティブだった値を最大 1 つだけ寄与できます。 

すでに隣接するペアを持つ値は、ゼロの配置に関係なく寄与がすでに保証されているため、このプロセスから独立しています。 アルゴリズムはこれら 2 つの領域を分離し、すべての追加ゲインが個別のコンポーネントと個別の値に対応することを保証します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

sys.setrecursionlimit(10**7)

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    # DSU
    parent = list(range(n))
    
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    
    def union(x, y):
        x = find(x)
        y = find(y)
        if x != y:
            parent[y] = x
    
    # connect components
    for i in range(n - 1):
        if a[i] == 0 or a[i + 1] == 0 or a[i] == a[i + 1]:
            union(i, i + 1)
    
    # gather components
    comp_vals = {}
    comp_has_zero = {}
    comp_has_adj = {}
    
    good = set()
    
    # detect already-good values (adjacent equal non-zero)
    for i in range(n - 1):
        if a[i] != 0 and a[i] == a[i + 1]:
            good.add(a[i])
    
    for i in range(n):
        r = find(i)
        if r not in comp_vals:
            comp_vals[r] = set()
            comp_has_zero[r] = False
        if a[i] == 0:
            comp_has_zero[r] = True
        else:
            comp_vals[r].add(a[i])
    
    comps = []
    for r in comp_vals:
        comps.append((r, comp_has_zero[r], comp_vals[r]))
    
    # available values for new activation
    used = set(good)
    available = []
    for x in range(1, n + 1):
        if x not in used:
            available.append(x)
    
    ptr = 0
    assign = {}
    
    # choose components that can gain a new value
    for r, has_zero, vals in comps:
        if not has_zero:
            continue
        if ptr >= len(available):
            break
        
        # check if component can contribute something new
        ok = False
        for v in vals:
            if v not in good:
                ok = True
                break
        
        if ok or len(vals) == 0:
            assign[r] = available[ptr]
            ptr += 1
    
    # build result
    res = a[:]
    
    for i in range(n):
        r = find(i)
        if a[i] == 0:
            if r in assign:
                res[i] = assign[r]
            else:
                res[i] = next(iter(comp_vals[r])) if comp_vals[r] else 1
    
    print(*res)

if __name__ == "__main__":
    solve()
```この実装では、まず、隣接関係をゼロまたはすでに等しい値で「ブリッジ」できるかどうかに基づいて、union-find 構造を使用してインデックス間の接続を構築します。 これ以降、各コンポーネントは独立した領域になります。 

の`good`set は、変更前にすでに隣接する等しいペアを持つ値をキャプチャします。 これらは、ゼロがどのように埋められるかに依存しない、ロックインされた貢献です。 

次に、各コンポーネントにゼロが含まれているかどうかが検査されます。これは、元々存在しなかった新しい隣接関係を導入するために使用できるのはそのようなコンポーネントだけであるためです。 未使用の値のプールは、選択された各コンポーネントが個別の新しい値を受け取るように維持されます。 

最後に、選択した各コンポーネント内のゼロがその割り当てられた値で一貫して埋められ、コンポーネントがその値に対して少なくとも 1 つの隣接する等しいペアを生成することが保証されます。 

## 実用的な例

 ### 例 1

 入力:```
4
1 1 0 2
```まず、値 1 の位置 (1,2) に隣接するペアがすでに存在することが検出され、すでに良好であるとカウントされています。 

ゼロが 1 つあり、それが両側に接続されて 1 つのコンポーネントを形成します。 

| コンポーネント | 値 | ゼロがある | すでに良い値です | 割り当て済み |
 | --- | --- | --- | --- | --- |
 | C1 | {1,2} | はい | {1} | 2 |

 値 2 をゼロに割り当てて、`[1, 1, 2, 2]`。 これで、1 と 2 の両方に隣接するペアができました。 

### 例 2

 入力:```
5
0 2 0 3 0
```最初は隣接するペアを持つ値はありません。 

すべてのインデックスをカバーする 1 つの大きなコンポーネントがあり、ゼロと値 {2,3} が含まれます。 

| コンポーネント | 値 | ゼロがある | 良い値 | 割り当て済み |
 | --- | --- | --- | --- | --- |
 | C1 | {2,3} | はい | ∅ | 2 |

 値 2 をコンポーネントに割り当て、すべてのゼロを 2 で埋めて、`[2,2,2,3,2]`。 値 2 のみが隣接ペアを形成するため、値 2 のみが寄与します。 

これは、単一のコンポーネントは 1 つの新しい成功した値を作成するためにのみ使用できることを示しています。

 ## 特殊なケース

 重要なエッジケースは、コンポーネントにゼロのみが含まれる場合です。 この場合、内部には既存の値はありませんが、完全に新しい値を導入するために使用できます。 このアルゴリズムは、空の値のコンポーネントが未使用の値のプールから割り当てを受信できるようにすることでこれを処理し、利用可能な場合にはそれらのコンポーネントが 1 つの新しい適切な値を確実に提供できるようにします。 

もう 1 つのエッジ ケースは、コンポーネント内のすべての値がすでにグローバルに良好である場合です。 コンポーネントにゼロが含まれている場合でも、それを使用しても明確な適切な値の数は増加しないため、アルゴリズムは意図的に新しい値の割り当てを回避します。 

最後の微妙なケースは、複数のコンポーネントが適格であるが、未使用の値の数がコンポーネントの数よりも少ない場合です。 貪欲な割り当てでは、各値が最大 1 回使用されることが保証されるため、最初のいくつかのコンポーネントのみが寄与し、最終スコアでは個別の値のみが重要になるという事実と一致します。
