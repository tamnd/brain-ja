 ## 解決策
 ## 問題の理解

 多くのテスト ケースが与えられ、各テスト ケースは次の整数の連続配列を記述します。$l$に$r$。 配列は任意ではなく、常にギャップのない完全な間隔です。 私たちの操作は、この配列から要素を削除することであり、削除後に残りの数値のビット単位の AND を計算します。 目標は、最終的な AND が厳密にゼロ以外になるように、削除する要素をできるだけ少なくすることです。 

非ゼロ AND は、残りのすべての数値にそのビットが設定されるようなビット位置が少なくとも 1 つ存在することを意味します。 言い換えれば、削除後は、選択されたすべての数値が少なくとも 1 つの共通の設定ビットを共有する必要があります。 

制約はクエリ数の点で大きく、最大で$10^4$、範囲のエンドポイントは次のとおりです。$2 \cdot 10^5$。 これは、すべての解がテスト ケースごとに線形に近いか、値の範囲内で対数に近い必要があることを直ちに示唆します。 各間隔にわたる 2 次または単純な要素ごとのチェック戦略では、遅すぎます。 

間隔が小さい場合、またはバイナリ形式で非常に多様な数値が含まれる場合、微妙なエッジ ケースが発生します。 たとえば、$[1, 2]$の場合、AND はゼロですが、要素を 1 つだけ保持すると、すでにゼロ以外の結果が得られます。 一方、次のような間隔では、$[4, 5]$、両方の数値は、両方を保持できるビット パターンを共有しているため、削除する必要はありません。 この対比は、構造が区間全体で共有されるセット ビットに完全に依存していることを示しています。 

単純な間違いは、区間全体の AND を計算して、それを何らかの方法で「修正」する必要があると考えることです。 これは失敗します。グローバル AND でビットが 0 になると、残りのすべての数値にそのビットが存在するサブセットを保持できる可能性があるためです。 

## アプローチ

 ブルートフォース戦略では、間隔のすべてのサブセットが試行されます。$[l, r]$、各サブセットのビットごとの AND を計算し、AND がゼロ以外の最大のサブセットを追跡します。 これは条件を直接モデル化しているため、原理的には正しいですが、サブセットの数は$2^{(r-l+1)}$これは、サイズ 30 の間隔でも実行不可能になります。200 要素間隔のすべてのサブセットをチェックすることさえ完全に不可能です。 

重要な点は、選択されたすべての要素に設定されているビット位置が少なくとも 1 つ存在する場合にのみ、サブセットに対するビットごとの AND がゼロ以外になるということです。 これにより、問題はビット位置の選択に変わります$b$、そして数字だけを保持します$[l, r]$噛んだもの$b$セット。 ビットごとに、その区間にそのビットが含まれる数値がいくつあるかを数えることができます。 少し直したら$b$の場合、できる限りの最善の方法は、そのビットが設定されたすべての数値を保持し、残りを削除することです。 答えは、区間内の少なくとも 1 つの数値に現れるすべてのビットの最小削除です。 

ここで問題は、ビットごとに、次の数値がいくつあるかを計算することになります。$[l, r]$そのビットを設定してください。 ビットごとに間隔全体を繰り返す代わりに、標準的なプレフィックスのアイデアを使用します。ビットごとに、最大でいくつの数値を計算できます。$x$バイナリ パターンの周期性を使用してそのビットを設定します。 各ビット$b$一定のサイズのブロックで繰り返します$2^{b+1}$、 と$2^b$続いてのもの$2^b$ゼロ。 これによりカウントインが可能になります$O(1)$ビットごとに、$O(31)$テストケースごとのソリューション。 

最後に、ビットごとに必要な削除は次のとおりです。$(r-l+1) - \text{count of numbers with bit b set}$、すべてのビットの最小値を取得します。

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、間隔のサイズを次のように計算します。$n = r - l + 1$。 これは開始する要素の数であり、削除は常にこの値に相対的に行われます。 
2. 0 ～ 18 の各ビット位置について ($r \le 2 \cdot 10^5$)、次の数値がいくつあるかを計算します。$[l, r]$このビットを設定してください。 これが機能するのは、すべての整数の 2 進表現がビットごとに独立しており、各ビットが数直線上の繰り返しパターンに従うためです。 
3. 最大何個の数値を計算するには$x$ビットが設定されている場合は、サイズのブロック構造を使用します$2^{b+1}$。 完全な各ブロックが正確に寄与します$2^b$もの。 次に、サイクルの「オン」半分との重複を数えて残りを処理します。 
4. 各ビットについて、次を計算します。$$\text{ones} = \text{count}(r, b) - \text{count}(l-1, b)$$これにより、区間内にそのビットが含まれる数値がいくつあるかがわかります。 
5. ビットで保持できる最大のサブセット$b$すべての要素で、まさにこの数の 1 が保証されます。 したがって、このビットに必要な削除は次のとおりです。$$(r-l+1) - \text{ones}$$6. すべてのビットにわたって最小限の削除を行います。 これは、間隔全体で最も「共通」のビットを選択することに対応します。 

### なぜ効果があるのか

 すべての有効な最終配列には、選択されたすべての数値に少なくとも 1 つのビットが存在する必要があります。 そのビットを修正すると、間隔が 2 つのグループ (ビットのある数値とビットのない数値) に分割されます。 そのビットなしで数値を保持すると、AND 条件が直ちに無効になります。 したがって、有効な解の場合、保持されるセットは、選択されたビットを共有する数値のサブセットでなければなりません。 最適解は単に全ビットにわたる最大のサブセットであり、それがまさにアルゴリズムの評価対象となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def count_upto(x, b):
    if x <= 0:
        return 0
    cycle = 1 << (b + 1)
    full = x // cycle
    rem = x % cycle
    ones = full * (1 << b)
    ones += max(0, rem - (1 << b) + 1)
    return ones

t = int(input())
for _ in range(t):
    l, r = map(int, input().split())
    n = r - l + 1
    ans = n
    for b in range(20):
        ones = count_upto(r, b) - count_upto(l - 1, b)
        ans = min(ans, n - ones)
    print(ans)
```機能`count_upto(x, b)`ビットの周期構造をエンコードします$b$整数以上。 サイクルの長さは$2^{b+1}$、下半分はゼロに寄与し、上半分は 1 に寄与します。 これにより、範囲を明示的に繰り返すことが回避されます。 

メイン ループはすべてのビットを個別にチェックし、そのビットが保証された共有ビットとして選択された場合に必要な削除の数を計算します。 

実装でよくある落とし穴は、処理を忘れることです。$l = 1$、 どこ$l - 1 = 0$。 ヘルパー関数は、非正の入力を明示的に保護します。

 ## 特殊なケース

 主なエッジケースは、間隔に数値が 1 つだけ含まれる場合です。 その場合、単一要素の AND は常にその要素自体であり、数値が正である限りゼロではないため、削除は必要ありません。 アルゴリズムはこれを処理します。$n = 1$、そしてビットごとに、削除は次のようになります。$1 - \text{ones}$、数値内のちょうど 1 ビットが削除値 0 に寄与します。 

もう 1 つのエッジケースは次のような場合です$l = 1$。 ここで、プレフィックスの計算には、次の時点でカウントを評価する必要があります。$0$。 ヘルパー関数は、正でない入力に対して明示的にゼロを返し、正確さを保証します。 

より微妙なケースは、最適解が上位ビットではなく下位ビットに対応する場合です。 たとえば、$[2, 3, 4, 5, 6, 7, 8]$、上位ビットはまばらに設定されますが、ビット 0 またはビット 1 はより密なオーバーラップを提供します。 このアルゴリズムは、ビット位置の単調性を仮定することなく、すべてのビットを独立して正しく評価し、最適なものを選択します。
