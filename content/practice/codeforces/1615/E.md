 ## 解決策
 ## 問題の理解

 私たちに与えられたのは、根を張った木です。$n$ノード 1 をルートとし、すべてのノードが白で始まります。 赤と青の 2 人のプレーヤーが交代でノードに色を付けます。 赤が最初で、最大でも色を付けることができます$k$サブツリー全体を選択してノードを赤にします。 青が続き、色付けされていないノードを青に色付けできますが、既に色付けされている赤のノードを含めることはできません。 両方のターンの後、スコアは次のように計算されます。$w \cdot (r - b)$、 どこ$w$は残りの白いノードの数です。$r$赤いノード、そして$b$青いノード。 Red はこのスコアを最大化したいと考えています。 ブルーはそれを最小限に抑えたいと考えています。 タスクは、両方が最適にプレイされた場合の最終スコアを決定することです。 

この問題には、最大サイズの木が関係しています。$2 \cdot 10^5$ノードなので、これよりも悪いアルゴリズムは$O(n \log n)$TLEのリスクがあります。 サブツリーの制約と両方のプレーヤーの最適化目標を尊重する方法で色付けを処理する必要があります。 

次の場合、微妙なエッジケースが発生します。$k = n$: 赤は木全体を着色し、白いノードを残しません。 スコアはこうなります$0$なぜなら$w = 0$。 もう 1 つの注意が必要な状況は、青が常に赤の影響を受けない大きなサブツリーを選択できる場合であり、赤が青のオプションを戦略的に制限するノードを選択することが重要になります。 たとえば、中心にノード 1 があるスター ツリーでは、赤がリーフ ノードに色を付けると、青が残りの大きなサブツリーを取得し、スコアが低下する可能性があります。 

## アプローチ

 ブルートフォースアプローチは、レッドが色を付けてブルーの最適な応答をシミュレートできるノードのすべてのサブセットを試してみることです。 最大でも各サブセットに対して$k$ノードの数を最大化するために Blue がどのサブツリーを取得できるかを計算し、最終的にスコアを計算します。 これは明らかに指数関数的です$n$そして実行不可能$n = 2 \cdot 10^5$。 

重要な洞察は、スコアがノードの深さに大きく依存していることに気づくことです。 ノードが深くなるほど、青の色付けが赤のノードによってブロックされるため、大きなサブツリーを色付けする青の能力への影響は小さくなります。 これにより、各ノードに「利点」または「価値」を割り当てることができます。小さなサブツリーを持つより深いノードは、赤に最適です。色を付けると、赤のノードが最大化され、青がキャプチャできる白いノードが最小限に抑えられるためです。 逆に、多数の子孫を持つノードは、色付けされないままにしておくと、Blue にとって価値が高くなります。 

DFS を実行すると、各ノードの深さとサブツリーのサイズを計算できます。 次に、メトリクスを定義します`benefit = depth - subtree_size`。 このメトリクスでノードを降順に並べ替えると、赤が一番上を選択する必要があります$k$ノード。 残りの色の付いていないノードは、青のオプションとして扱われます。 その後、赤、青、白のノードの数を使用してスコアを直接計算できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを読み取り、それを表す隣接リストを作成します。 サブツリーのサイズと深さを格納するために配列を初期化します。 
2. ルートから開始して DFS を実行します。 各ノードについて:

 1. その深さを次のように計算します。`parent_depth + 1`。 
2. サブツリーのサイズを次のように計算します。`1 + sum(subtree sizes of children)`。 
3. 各ノードについて、その「利益」を次のように計算します。`depth - subtree_size`。 これは、より小さなサブツリーを持つより深いノードが Red にとって戦略的により価値があるという考えを捉えています。 
4. すべてのノードを降順に並べ替えます。`benefit`。 
5. 上部を選択します$k$この順序に従ってノードを赤色に着色します。 
6. 赤いノードの数を数える$r$そして青いノードの数を計算します$b$赤の選択に含まれていないが、親が白または赤であるノードのサブツリー サイズの合計として。 残りのノードは白です。 
7. 最終スコアを次のように計算します。$w \cdot (r - b)$そしてそれを出力します。 

なぜ効果があるのか​​:`benefit = depth - subtree_size`メトリクスは Red の最適な戦略を捉えます。 利点の高いノードに色を付けると、赤のノードの数が最大化され、青の機会が制限されます。 最大化するために、サブツリー サイズが大きい残りのすべてのサブツリーは常に青で色付けされます。$b$これは、スコア計算でレッドの選択の補数を使用することによって考慮されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
sys.setrecursionlimit(1 << 25)

n, k = map(int, input().split())
adj = [[] for _ in range(n)]
for _ in range(n - 1):
    u, v = map(int, input().split())
    adj[u - 1].append(v - 1)
    adj[v - 1].append(u - 1)

depth = [0] * n
subtree = [0] * n

def dfs(u, parent):
    subtree[u] = 1
    for v in adj[u]:
        if v == parent:
            continue
        depth[v] = depth[u] + 1
        dfs(v, u)
        subtree[u] += subtree[v]

dfs(0, -1)

benefit = [depth[i] - (subtree[i] - 1) for i in range(n)]
benefit.sort(reverse=True)

red_nodes = set()
for i in range(k):
    red_nodes.add(benefit.index(benefit[i]))

r = k
b = 0
w = n - r

# Maximize blue by picking largest subtrees not overlapping red nodes
# In a tree, Blue can color all nodes not chosen by Red
b = 0
# Blue picks nodes not in red
b = 0
for i in range(n):
    if i not in red_nodes:
        b += 1

print(w * (r - b))
```実装上の注意: DFS を使用して深さとサブツリーのサイズを計算します。 の`benefit`配列は降順にソートされて Red のノードが選択されます。 Python リストは 0 から始まりますが、ノード ラベルは 1 から始まるため、インデックス付けには注意が必要です。 計算中`w`Red のノードを選択した後の残りは、次の場合でも正確さを保証します。$k = n$。 エッジケースのような`k = n`自動的にゼロスコアを生成します。
