 ## 解決策
 ## 問題の理解

 一連のタワーがあり、それぞれのタワーには一定数のブロックが垂直に積み上げられています。 目標は、すべてのタワーの高さをできるだけ近づけることです。 いつでも、あるタワーからブロックを取り出して、別のタワーに置くことができます。 配置の醜さは、最も高い塔と最も低い塔の違いです。 任意の数のブロック移動後に達成できる最小の醜さを決定したいと考えています。 

入力は複数のテスト ケースで構成されます。 テスト ケースごとに、タワーの数を取得します。`n`そしてそれらの塔の高さ。 出力は、達成可能な最小の醜さを表すテスト ケースごとに 1 つの整数である必要があります。 

制約は中程度で、最大 100 のタワーと 1000 のテスト ケースです。 個々のタワーの高さは最大で$10^7$。 以来`n`小さい、二次関数のアルゴリズム`n`実現可能ですが、線形の解決策が望ましいです。 エッジ ケースには、すでに等しいタワー、非常に高いまたは非常に低い建物が 1 つしかないタワー、ブロックの合計が均等に分割されないケースが含まれます。`n`。 一度に 1 ブロックを繰り返し移動する単純なアプローチは正しいですが、不必要に時間がかかります。 たとえば、タワーが`[1, 2, 3, 1, 5]`、私たちは常に同じ高みに到達することはできません、そして最小限の醜さは最終的には`1`。 

## アプローチ

 ブルートフォースアプローチでは、改善が不可能になるまでブロックを最も高いタワーから最も低いタワーまで繰り返し移動しようとします。 これは最終的には収束しますが、最大で$O(n \cdot \text{max}(a_i))$次の場合には実行不可能な操作`a_i`到達できる$10^7$。 より賢いアプローチが必要です。 

重要な観察は、ブロックを移動すると、タワー全体のブロックの合計が再分配されるだけであるということです。 させて`total = sum(a)`。 もし`total`で均等に割る`n`、すべての塔を等しくして、醜さ 0 を達成できます。`total`均等に分割されていない場合は、いくつかのタワーが`floor(total/n)`ブロックといくつかの必須のブロック`ceil(total/n)`ブロック。 これら 2 つの量の差は常に次のようになります。`1`、これは達成可能な最小限の醜さです。 

この観察により、テスト ケースごとに一定時間で結果を計算できます。合計がタワーの数で割り切れるかどうかを確認し、次のいずれかを出力します。`0`または`1`。 実際のブロック移動シミュレーションは必要ありません。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n * max(a_i)) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. テストケースの数を読み取る`t`。 
2. 各テスト ケースについて、次の内容を読んでください。`n`そして塔の高さの配列`a`。 
3. すべてのタワーの高さの合計を計算します。 
4. 整数の除算を計算する`avg = total // n`。 
5. 剰余を計算します`r = total % n`。 もし`r == 0`、合計は均等に除算されるため、最小の醜さは次のようになります。`0`。 そうしないと、必然的に一部の塔が他の塔よりも 1 ブロック高くなり、最小限の醜さになります。`1`。 
6. 各テストケースについて計算された醜さを出力します。 

このアルゴリズムが機能するのは、ブロック移動操作によってブロックの合計が保持されるためです。 合計を均等に分割できない場合、最も高いタワーと最も低いタワーの差は最大でも 1 つだけです。 この不変式により、次の計算が保証されます。`0`または`1`は常に正しいです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n = int(input())
    a = list(map(int, input().split()))
    total = sum(a)
    if total % n == 0:
        print(0)
    else:
        print(1)
```このソリューションでは、まず、次を使用してすべての入力を効率的に読み取ります。`sys.stdin.readline`。 配列の合計`a`ブロックの総数を示します。 割り切れるかどうかを確認する`n`最小限の醜さを直接的に与えます。 小切手`total % n == 0`少額と多額の両方を正しく処理し、入力配列を超える追加のストレージは必要ありません。 

## 実用的な例

 入力のトレース`[3, 10, 10, 10]`:

 | ステップ | | 合計 | 合計 %n | 醜さ |
 | --- | --- | --- | --- | --- |
 | 合計を計算する | [10、10、10] | 30 | 0 | 0 |

 すべての塔はすでに同等です。 出力は`0`。 

入力のトレース`[5, 1, 2, 3, 1, 5]`:

 | ステップ | | 合計 | 合計 %n | 醜さ |
 | --- | --- | --- | --- | --- |
 | 合計を計算する | [1、2、3、1、5] | 12 | 12 % 5 = 2 | 1 |

 合計`12`で割る`5`残りを残す`2`。 いくつかの塔はそうする必要があります`2`他のブロックよりも高いブロックなので、最低限の醜さは`1`。 

これらのトレースは、合計が達成可能な最小の差を決定するという不変条件を示しています。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | テスト ケースごとに配列を 1 回合計する必要があります。 
| スペース | テスト ケースあたり O(n) | タワーの高さを保存する |

 与えられた`n <= 100`そして`t <= 1000`、最悪の場合の時間は約 100,000 回の操作であり、2 秒の時間制限内に十分収まります。 この規模ではメモリの使用量は無視できます。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    out = io.StringIO()
    sys.stdout = out
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        print(0 if sum(a) % n == 0 else 1)
    return out.getvalue().strip()

# provided samples
assert run("3\n3\n10 10 10\n4\n3 2 1 2\n5\n1 2 3 1 5\n") == "0\n0\n1", "sample 1"

# custom cases

assert run("1\n4\n10000000 10000000 10000000 10000001\n") == "1", "large numbers"
assert run("1\n5\n5 5 5 5 5\n") == "0", "all equal values"
assert run("1\n3\n1 1 2\n") == "1", "boundary conditions"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`2\n2\n1 2\n3\n2 2 2\n`|`1\n0`| 最小の配列、不等価/偶数和 |
 |`1\n4\n10000000 10000000 10000000 10000001\n`|`1`| 限界に近い大きな数 |
 |`1\n5\n5 5 5 5 5\n`|`0`| すべての塔は等しい |

 ## 特殊なケース

 単一の操作が必要な場合、`[1, 2]`、合計は`3`。 で割る`2`残りを残す`1`。 アルゴリズムの出力`1`、一方の塔が他方よりも高くなければならないことを正しく識別します。 すでにバランスが取れている場合`[2, 2, 2]`、合計は`6`、で割り切れる`3`したがって、出力は`0`。 どちらのエッジ ケースも、アルゴリズムが明示的なブロック移動なしで割り切れる合計と割り切れない合計の両方を正しく処理することを示しています。
