 ## 問題の理解

 2 つの数字が与えられます。 1 つ目は固定ブロック長です`L`。 2 番目は非常に大きな整数です`A`、10 進数の文字列として指定されるため、最大 100,000 桁まで含めることができます。 数値を構築したい`X`それは厳密にはより大きいです`A`ただし、特別な構造を持っています:`X`同じブロックを正確に繰り返して作成する必要があります`L`数字を何度も繰り返します。 

言い換えれば、長さを選択します。`L`弦`P`、そしてビルドします`X`として`P`少なくとも次の長さの数値に達するまで、それ自体を繰り返し連結します`A`。 完全な繰り返しのみを使用できるため、最終的な数値は常に次の倍数のプレフィックス長になります。`L`。 

タスクは、まだ超えている最小の周期数を見つけることです。`A`。 

この制約により、整数の演算は即座に除外されます。`A`数値型として保存または比較するには大きすぎます。 すべての操作は文字列ベースである必要があります。 以来`L`最大 100,000 に達する可能性があるため、すべての候補パターンを試したり、単純なループで繰り返し構築を実行したりするソリューションは失敗します。 唯一の実行可能なアプローチは、サイズを線形またはほぼ線形にすることです。`A`。 

構築された周期数の長さが異なる場合、微妙な問題が発生します。`A`。 長さのプレフィックスのみを一致させる場合`len(A)`比較すると、わずかに長い繰り返しが実際には小さいか大きいかを見落とす可能性があります。 もう 1 つの注意が必要なケースは、ベース ブロックをインクリメントするとキャリーが発生してその長さが増加し、周期構造が完全に変化する場合です。 

たとえば、次の場合`A = 999`そして`L = 1`、「最初の桁を取得して一致を試みる」という単純な考えでは、次のことが得られます。`999`ですが、正解は`1111`（ブロック`1`、4回繰り返します）。 これは、同じプレフィックス内で調整するだけではなく、場合によってはブロックを増やす必要があることを示しています。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべてのことを列挙することになります。`L`-数字列`P`、無限繰り返しを構築し、と比較します。`A`。 候補者の数が多いため、これはすぐには不可能です`9 * 10^(L-1)`、小さいものでも天文学的な大きさです。`L`。 単一の候補を完全に生成するだけでも最大 100,000 桁が必要となるため、このアプローチはまったく実行不可能です。 

より構造化された観察により、問題は変わります。 有効な答えは最初の答えによって完全に決まります。`L`数字。 修正したら`P`、完全な数値が強制されます。 したがって、無限の周期数を検索する代わりに、可能な限り最良のものを決定するだけで済みます。`P`。 

重要なアイデアは、以下から候補ブロックを構築することです。`A`自体。 我々が最初を取る`L`の桁`A`(または、場合によっては繰り返します`A`よりも短いです`L`) 基本パターンを形成します。 このブロックを繰り返すと周期的な数値が得られます`B`。 もし`B > A`の場合、これはすでにそのプレフィックス構造を持つ可能な最小の候補です。 

そうでない場合は、ブロックを増やす必要があります`P`10 進数とハンドルキャリーとして。 インクリメント後`P`, 周期数を再構築すると答えになります。 

重要な推論は、最適なソリューションは次のいずれかのプレフィックスと一致する必要があるということです。`A`または、その次の辞書編集ブロックになります。 これより小さい場合は、次を超えない周期数が生成されます。`A`、次の増分よりも大きいものは最小ではありません。

 ## アルゴリズムのチュートリアル

 しましょう`s`の文字列表現になります`A`。 

1.ベースブロックを構築する`P`最初のものを取ることで`L`の登場人物`s`、最初から繰り返す場合`s`よりも短いです`L`。 これにより、`P`の最上位桁と一致します`A`。 
2. 候補番号を作成する`C`繰り返すことで`P`少なくともその長さになるまで`len(s)`、それを正確に切り捨てます`len(s)`。 これにより、このブロック長での最小の周期数が得られます。`A`。 
3. 比較する`C`と`A`文字列として。 もし`C > A`小さい周期数は辞書編集的に小さくなるか、値がさらに減少するだけの小さいブロックが使用されるため、これで完了です。 
4. もし`C <= A`、増分`P`キャリー処理を伴う 10 進数として。 このステップは、辞書編集的に次の可能なブロックに確実に移動できるため、重要です。 
5. インクリメントによって長さが増加する場合、`P`（例えば`999 + 1 = 1000`)、構造が変更されるため、新しいブロック全体を使用する必要があります。 
6. 更新された周期番号から周期番号を再構築します。`P`そしてそれを出力します。 

比較ステップが機能するのは、プレフィックス ブロックが固定されると定期的な繰り返しによって辞書編集上の順序が維持されるためです。 

### なぜ効果があるのか

 建設スペースは最初のパネルで区切られています。`L`繰り返しブロックの桁。 すべての周期数は基本ブロックごとにグループ化されます`P`。 各グループ内で繰り返します`P`ユニークな無限パターンを生み出します。 これらのグループの順序は、辞書編集的な順序によって決定されます。`P`。 アルゴリズムは常に、次から導出される可能な最小のグループをチェックします。`A`、失敗した場合は、次の辞書編集ブロックに移動します。 これにより、有効な候補がスキップされないことが保証され、最小化が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build(period, n):
    # build periodic string of length n from period
    res = []
    L = len(period)
    for i in range(n):
        res.append(period[i % L])
    return ''.join(res)

def add_one(period):
    # increment decimal string
    p = list(period)
    i = len(p) - 1
    carry = 1
    while i >= 0 and carry:
        s = ord(p[i]) - 48 + carry
        p[i] = chr((s % 10) + 48)
        carry = s // 10
        i -= 1
    if carry:
        p.insert(0, '1')
    return ''.join(p)

def solve():
    L = int(input().strip())
    s = input().strip()
    
    n = len(s)

    # build initial period
    if L <= n:
        period = s[:L]
    else:
        period = (s + s[:L - n])

    candidate = build(period, n)

    if candidate > s:
        print(candidate)
        return

    period = add_one(period)
    candidate = build(period, len(period) * (n // L + 2))
    print(candidate[:max(n, len(candidate))])

if __name__ == "__main__":
    solve()
```この解決策では、まず、次の接頭辞から直接基本ピリオドを構築します。`A`。 次に、それを比較するのに十分な長さの候補周期数に拡張します。`A`。 候補がすでに大きい場合は、すぐに返されます。 

そうでない場合、ピリオドは 10 進数として増分されます。 これによりキャリーが適切に処理され、次の有効なブロックに確実に移動します。 インクリメント後、新しいピリオドの十分に長い繰り返しを再構築し、必要な長さを超えるか一致する最小のプレフィックスを出力します。 

新しいピリオドの長さが増加し、繰り返し構造が変化する可能性があるため、インクリメント後に繰り返し文字列を構築する場合は注意が必要です。

 ## 特殊なケース

 いつ`A`は選択されたプレフィックスですでに正確に周期的ですが、それが厳密に大きくない場合、アルゴリズムは依然として次のブロックに移動する必要があります。 たとえば、次の場合`A = 100100`そして`L = 3`、初期の期間`100`正確に生成します`100100`、これは無効です。 に増加します`101`正しく収穫します`101101`、上記の有効な周期数の最小値です。`A`。 

インクリメントにより周期長が増加するキャリーが発生すると、繰り返し構造が変化します。 のようなケース`A = 99999`と`L = 2`これを明確に示しています。最初のブロックは次のとおりです。`99`ただし、インクリメントすると次のようになります。`100`となり、周期構造が根本的に異なります。 アルゴリズムは、増分後に完全な繰り返し番号を最初から再構築することでこれを処理し、長さの変更に関係なく正確さを保証します。
