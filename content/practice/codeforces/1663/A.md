 ## 解決策
 ## 問題の理解

 テスト プロセスに参加する一連の参加者が与えられます。各参加者は 1 つの「テスト対象」関係に関連付けられます。 言い換えれば、誰にもテストされていない一人の特別な人を除いて、各人は自分をテストした他の一人の人物を正確に指します。 したがって、この構造は、解釈に応じてすべてのノードが出力または入力の制約を 1 つだけ持つ有向グラフを形成します。目的は、他の参加者によってテストされないという条件を満たす一意の参加者を識別することです。 

より具体的に言い換えると、各参加者が、誰がテストの責任者であるかを示す単一の指示を残すと想像してください。 すべての参加者にわたってこれらのポインタをたどると、すべてが最終的にどこかにつながるという構造が得られますが、厳密に 1 人の参加者がポインタのターゲットとして現れることはありません。 その参加者が答えです。 

制約は、リニア スキャン ソリューションには十分小さいです。 参加者の数が 2⋅10^5 などの一般的な Codeforce の制限に達した場合でも、O(n) または O(n log n) で動作することが期待されます。 反復的な走査をシミュレートしたり、ノードごとに重い補助構造を構築したりするアプローチは、遅すぎます。 この構造は、主要な操作が各参加者が参照された回数をカウントすることであることを強く示唆しています。 

主なエッジケースは、参加者が 1 人など、構造が最小限の場合です。 この場合、参照はまったくないため、その参加者が答えとなるのは自明です。 もう 1 つのエッジ ケースは、1 つの入力エッジが欠落していることを除いて、入力がニアサイクル構造を形成する場合に発生します。 ツリーのルートを想定したり、任意の開始点を使用した単純なトラバーサルは、受信カウントを明示的に追跡しない限り失敗する可能性があります。 

## アプローチ

 この強引なアイデアは、すべての参加者をチェックし、誰かが彼らを指摘しているかどうかを判断することです。 各候補について、関係のリスト全体をスキャンし、それがターゲットとして表示されるかどうかを確認します。 これは、回答の定義と直接一致するため機能しますが、参加者ごとに完全なスキャンが繰り返されます。 参加者が n 人の場合、これにより O(n^2) チェックが行われ、n が大きい場合は遅くなりすぎます。 

重要な観察は、すべての候補者について誰かが参照されているかどうかを実際に再計算する必要がないということです。 各参加者が合計で何回参照されているかを知る必要があるだけです。 各参加者が何回ポイントされているかを数える頻度配列を計算すると、答えは単純に頻度が 0 のインデックスになります。 

これにより、メンバーシップ テストの繰り返しによる問題が 1 回の集約パスに軽減されます。 この構造は基本的にノードから次数カウントへのマッピングであり、次数 0 を持つ一意のノードを検索しています。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | お(1) | 遅すぎる |
 | 周波数カウント | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列を初期化する`cnt`ゼロを含むサイズ n+1 で、各参加者がテスター ターゲットとして参照された回数を格納します。 この構造が必要なのは、各参加者に対して一定時間の更新とクエリが必要なためです。 
2. 各関係を読み取り、インクリメントします`cnt[x]`参加者にとって`x`誰かに試されている人。 このステップでは、各参加者がターゲットとして表示される頻度に関するグローバル情報を集約します。 
3. すべての関係を処理した後、1 から n までのすべての参加者をスキャンし、カウントが 0 のままである参加者を特定します。 これは、いかなる関係においてもターゲットとして現れることのない参加者です。 
4. この参加者を回答として出力します。 

### なぜ効果があるのか

 各関係は、ターゲット参加者のカウントに正確に 1 つの増分を与えます。 1 人を除くすべての参加者が少なくとも 1 回はターゲットとして現れることが保証されているため、インデックスが 1 つだけカウント 0 のままになります。 カウント プロセスでは、構造に関する必要な情報がすべて保存されますが、最終的なクエリに無関係な順序付けの詳細は破棄されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    cnt = [0] * (n + 1)

    for _ in range(n - 1):
        u, v = map(int, input().split())
        cnt[v] += 1

    for i in range(1, n + 1):
        if cnt[i] == 0:
            print(i)
            return

if __name__ == "__main__":
    solve()
```このソリューションは、単一の周波数配列を構築し、入力の読み取り中にそれを更新します。 2 番目のパスでは、単に未処理のインデックスが検索されます。 重要な実装の詳細は、各リレーションの正しいエンドポイントを確実にインクリメントすることです。これは、この方向を逆にすると、indegree の意味が逆転し、誤った結果が生成されるためです。 

## 実用的な例

 参加者が 1 つのルートを除いてチェーンを形成する小さな例を考えてみましょう。 

入力：```
5
1 2
2 3
4 3
5 4
```度数を追跡します。 

| ステップ | エッジ | cnt 配列 (部分) |
 | --- | --- | --- |
 | 1 | 1→2 | cnt[2] = 1 |
 | 2 | 2→3 | cnt[3] = 1 |
 | 3 | 4→3 | cnt[3] = 2 |
 | 4 | 5→4 | cnt[4] = 1 |

 最終的なカウントが表示されます`cnt[1] = 0`, したがって、答えは 1 です。 

これは、分岐または収束する構造であっても、この方法が入力エッジのない一意のノードを正確に識別することを示しています。 

ここで最小のケースを考えてみましょう。 

入力:```
1
```リレーションシップがないため、count 配列はすべて 0 のままで、唯一の参加者が返されます。 これは、アルゴリズムが縮退入力を自然に処理することを確認します。

 ## 特殊なケース

 単一ノードのケースは、処理する関係がないため、最も脆弱なシナリオです。 周波数配列はどこでもゼロのままであり、唯一のインデックスが返されるため、アルゴリズムはこれを正しく処理します。 

次のような直鎖では、`1 → 2 → 3 → 4`、最初のノードを除く各ノードには、入力エッジが 1 つだけあります。 スキャンでは、ノード 1 が唯一の 0 度要素として正しく識別されます。 

たとえば、複数のノードが 1 つのノードを指している場合、`1 → 3`そして`2 → 3`、ノード 3 のカウントは 1 より大きくなります。 このアルゴリズムは、入力エッジの一意性には依存せず、ゼロ入次ノードの存在のみに依存するため、構造制約に応じて、ノード 1 またはゼロの入力参照を持つノードを引き続き正確に返します。
