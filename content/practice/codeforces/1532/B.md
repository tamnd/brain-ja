 ## 解決策
 ## 問題の理解

 カエルは、位置 0 から始まる直線の数直線に沿って移動します。その動きは完全に決定的です。つまり、2 つの固定ステップ サイズの間で交互に動きます。 最初の動きで距離だけ右に進みます`a`、2手目で左に進みます。`b`、それからすぐのところに`a`再び、そして去った`b`など、実行されるまで続きます。`k`ジャンプします。 

各クエリは独立しており、クエリごとに正確な後の最終座標が必要です。`k`このような交互ジャンプ。 

制約`k ≤ 10^9`各ジャンプを段階的にシミュレートすることを即座に除外します。 各操作は単純な加算または減算であっても、クエリごとに最大 10 億の操作を実行すると、現実的な制限時間を超えてしまいます。 クエリが最大 1000 個ある場合、単純なシミュレーションでは最悪の場合最大 10^12 の操作に達しますが、これは実行不可能です。 

主な困難は、計算の複雑さだけではなく、動きのパターンが周期 2 で周期的であることを認識することであり、そのため、プロセスを完全な動きのペアをカウントすることに圧縮できます。 

よくある間違いは、最後の不完全な動きのペアを誤って処理したことに起因します。 たとえば、次のようなとき`k = 1`、イニシャルのみ`+a`を適用する必要があり、減算は行われません。 いつ`k = 2`、ネットの動きは`a - b`。 いつ`k = 3`、になります。`a - b + a`、 等々。 完全なペアのみを想定するアプローチ (つまり、`k // 2 * (a - b)`) 奇数の場合は失敗します`k`余分な前方ジャンプを考慮しない場合。 

もう 1 つの微妙な問題は、固定幅の整数を使用する言語における整数のオーバーフローです。 以来`a, b, k`まで可能です`10^9`、次のような中間値`k * a`到達できる`10^18`、これには 64 ビットまたは Python の任意精度の整数が必要です。 

## アプローチ

 ブルートフォースアプローチはカエルのジャンプを直接シミュレートします。 位置 0 から開始して、1 から`k`、追加`a`奇数ステップと減算`b`偶数段で。 これは定義に正確に従っているため、正しいです。 ただし、そのコストは次のように線形です。`k`したがって、すべてのクエリにわたって最大 10^12 の操作が必要になる可能性があり、これは実行可能な制限をはるかに超えています。 

重要な観察は、ジャンプが繰り返しのペアで行われることです。`( +a, -b )`。 各完全なペアは、次の純移動に寄与します。`a - b`。 シーケンスを完全なペアにグループ化すると、次のようになります。`k // 2`そんなペアたち。 残っているのは、次の場合に可能性のある追加の初動です。`k`奇数です。 その余分な動きは常に`+a`。 

したがって、プロセス全体は、完全なペアがいくつ存在するか、および 1 つの追加の前方ジャンプが必要かどうかを計算することに帰着します。 これにより、すべての反復が不要になり、各クエリが定数時間の演算に減ります。

 | 最適 | クエリごとに O(1) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 整数の読み取り`a`、`b`、 そして`k`クエリごとに。 これらは、シミュレートするステップ サイズと移動数を定義します。 
2. 次を使用して、完全な 2 ステップ サイクルが何回存在するかを計算します。`k // 2`。 各サイクルには 1 つが含まれます`+a`そして1つ`-b`、したがって、正味変位に寄与します。`a - b`。 
3. 完全なサイクル数に次の値を掛けます。`(a - b)`ペアになっているすべての動きから貢献度を取得します。 これにより、すべての偶数インデックスの動作が 1 つの算術式に圧縮されます。 
4. もし`k`奇数なので、もう 1 つ追加します`+a`最後のペアになっていない前方ジャンプを考慮します。 シーケンスは常に前進ステップから始まるため、これが必要です。 
5. 結果の合計を出力します。 

### なぜ効果があるのか

 一連の動きは厳密に周期的であり、最初の動きが考慮された後の長さは 2 になります。 すべてのペア`( +a, -b )`ポジションや履歴に関係なく、固定の純効果があります。 加算は結合的なため、演算を素のペアにグループ化しても最終結果は変わりません。 唯一の例外は、シーケンスの長さが奇数の場合です。この場合、最後のペアになっていない操作は常に最初の操作になります。`+a`ステップ。 これにより、式が、次の時点で切り捨てられた無限の交互シーケンスの完全なプレフィックス合計を正確に再構築することが保証されます。`k`。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
out = []

for _ in range(t):
    a, b, k = map(int, input().split())
    
    pairs = k // 2
    ans = pairs * (a - b)
    
    if k % 2 == 1:
        ans += a
    
    out.append(str(ans))

print("\n".join(out))
```このソリューションは、派生した分解を直接実装します。 表現`pairs * (a - b)`すべての完全なサイクルをエンコードしますが、条件付き`if k % 2 == 1`残りの最初のジャンプを処理します。 ループ内で繰り返される I/O オーバーヘッドを避けるために、結果は文字列として蓄積されます。 

演算の正しい順序を維持するには注意が必要です: コンピューティング`k // 2`まず、繰り返しの分割とグループ化を回避します。`(a - b)`異なるステップからの貢献を誤って混合しないようにします。 

## 実用的な例

 2 つの代表的なクエリを追跡します。 

### 例 1

 入力:`a = 5, b = 2, k = 3`| ステップ | アクション | 貢献 | ポジション |
 | --- | --- | --- | --- |
 | 1 | +5 | +5 | 5 |
 | 2 | -2 | -2 | 3 |
 | 3 | +5 | +5 | 8 |

 これは、1 つの完全なペアと追加の前方ジャンプを示しています。 式は次のようになります`k // 2 = 1`、 それで`1 * (5 - 2) = 3`、プラスα`5`、与える`8`。 

これにより、分解ハンドルが奇数であることが確認されます。`k`正しく。 

### 例 2

 入力:`a = 100, b = 1, k = 4`| ステップ | アクション | 貢献 | ポジション |
 | --- | --- | --- | --- |
 | 1 | +100 | +100 | 100 |
 | 2 | -1 | -1 | 99 |
 | 3 | +100 | +100 | 199 |
 | 4 | -1 | -1 | 198 |

 完全なペアが 2 つあり、それぞれが寄与しています`99`、合計は`198`。 残りのジャンプは存在しません。`k`は均等です。 

これにより、ペアリング ロジックが明示的なシミュレーションなしで繰り返し構造を完全にキャプチャしていることが確認されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        a, b, k = map(int, input().split())
        pairs = k // 2
        ans = pairs * (a - b)
        if k % 2 == 1:
            ans += a
        out.append(str(ans))
    return "\n".join(out)

# provided samples
assert run("6\n5 2 3\n100 1 4\n1 10 5\n1000000000 1 6\n1 1 1000000000\n1 1 999999999\n") == "8\n198\n-17\n2999999997\n0\n1"

# minimum k
assert run("1\n10 5 1\n") == "10"

# even k simple cancellation
assert run("1\n3 3 10\n") == "0"

# large imbalance
assert run("1\n1 1000000000 2\n") == "-999999999"

# odd k boundary
assert run("1\n7 2 7\n") == "21"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`k = 1`| シングル`a`| 最小限のエッジケース |
 | 等しい`a, b`| 0 または`a`奇数の場合 | キャンセル動作 |
 | 大きい`b`| 大きなマイナス | オーバーフローセーフな算術 |
 | 奇数`k`| 余分な`a`含まれています | パリティ処理 |

 ## 特殊なケース

 いつ`k = 1`、アルゴリズムは次のように計算します。`k // 2 = 0`、したがって、ペアの寄与は 0 であり、`k`奇妙です、追加します`a`。 例えば`a = 7, b = 2, k = 1`生成する`7`、単一のジャンプ定義と一致します。 

いつ`a = b`、すべての完全なペアは正味の動きに寄与しません。 のために`a = 3, b = 3, k = 5`、完全なペアが 2 つ得られ、0 と 1 が追加されます。`+3`、 その結果`3`、明示的なシーケンスと一致します`3 - 3 + 3 - 3 + 3`。 

いつ`k`均一で大きい、など`k = 10^9`、すべての動きがキャプチャされます`k // 2`ペア。 Python は自然に大きな整数をサポートしており、数式は安定しているため、整数の乗算以外には特別な処理は必要ありません。
