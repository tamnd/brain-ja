 ## 解決策
 ## 問題の理解

 整数の配列が与えられ、一度に 1 つの要素だけを削除できます。 削除するたびに、残りの配列を調べて、非常に具体的な質問をします。つまり、その縮小された配列内に他のすべての要素の合計と正確に等しい要素が存在するかどうかです。 

つまり、ポジションを解除した後、$j$、残りの配列を 1 つの特別な要素とその他すべてに分割できるかどうかを知りたいのですが、その特別な要素は残りのすべての値の合計と等しくなります。 

出力はインデックスのリストです$j$削除する$a_j$残りの配列がこの条件を満たすようにします。 

制約$n \le 2 \cdot 10^5$これは、削除のたびに合計を再計算したり、配列をスキャンしたりするソリューションは遅すぎることを意味します。 ナイーブ$O(n^2)$アプローチはすでに大規模すぎるため、これより悪いものは直ちに実行不可能です。 

値が頻繁に繰り返される場合、または削除後の配列が非常に小さい場合には、微妙なエッジ ケースが発生します。 たとえば、配列に次のような 2 つの要素がある場合、$[x, y]$1 つを削除すると単一の要素が残り、その要素が空のセットの合計に等しいため、単一要素の配列が常に適切であることは明らかです。 不注意な解決策は、この悪化したケースが依然として重要であることを忘れる可能性があります。 

もう 1 つの重要なケースは、残りの配列内の「特別な要素」が最大値であるか、または偶然合計条件に一致する任意の要素である可能性がある場合です。 単純なアプローチでは、最大の要素が常に候補であると想定される可能性がありますが、これは保証されません。 

## アプローチ

 ブルートフォースのアイデアは単純です。 インデックスごとに$j$を削除し、残りの要素の合計を計算し、残りの配列内のすべての位置をチェックして、その合計からそれ自体を引いた値に等しい要素があるかどうかを確認します。 これは、インデックスが存在するかどうかを確認していることを意味します$i \ne j$次のような:$$a_i = \text{total\_sum} - a_j - a_i$$書き換えると次のようになります。$$2a_i = \text{total\_sum} - a_j$$したがって、削除するたびに、すべての要素をスキャンしてこの状態をチェックします。 プレフィックス合計を使用しても、削除ごとにスキャンまたは頻度チェックが必要であるため、$O(n^2)$最悪の場合の行動。 と$2 \cdot 10^5$、これは遅すぎます。 

重要な観察点は、削除した後、$a_j$、残りの配列の合計は次のようになります。$$S' = S - a_j$$要素を見つける必要があります$x$残りの配列では次のようになります。$$x = S' - x \Rightarrow 2x = S'$$したがって、候補値は完全に決定されます。$$x = \frac{S'}{2}$$これは、削除のたびに恣意的に検索を行わないことを意味します。 値があるかどうかを確認するだけで済みます。$(S - a_j)/2$インデックスを削除した後も配列に存在します$j$。 これにより、問題は頻度のカウントと単純な妥当性チェックに軽減されます。 

合計と頻度マップを事前に計算します。 インデックスごとに$j$、必要な値を計算し、それが配列内に存在するかどうかを確認し、必要な値が等しい場合を調整します。$a_j$自体。

 ## アルゴリズムのチュートリアル

 1. 配列の合計を計算します。 これは、要素を削除した後、一定時間で新しい合計を計算できるようにするために必要です。 
2. すべての値の頻度マップを作成します。 これにより、配列内に候補値が存在するかどうかを定数時間でチェックできるようになります。 
3. インデックスごとに$j$、減額された合計を計算します$S' = S - a_j$。 これは、削除後の配列の合計を表します。 
4. 次のことを確認します。$S'$は均等です。 奇数の場合、2 つの等しい部分に分割することは不可能であるため、この削除は有効ではありません。 
5. 目標値を計算する$x = S'/2$。 これは、他のすべての要素の合計と等しい可能性のある唯一の候補要素です。 
6. 削除を一時的に考慮する$a_j$。 もし$x$等しい$a_j$、元の配列に少なくとも 2 回出現する必要があります。 それ以外の場合は、少なくとも 1 回は出現する必要があります。 
7. 条件が成立する場合、インデックスをマークします$j$有効として。 

### なぜ効果があるのか

 取り外し後$a_j$、残りの配列が良好であるための条件により、1 つの方程式が強制されます。つまり、1 つの要素が残りの合計の半分に等しくなければなりません。 すべての有効な構成は単一値の制約に集約されるため、これを超える自由はありません。 周波数構造により、その値が削除されても存続するかどうかを正確に区別できます。 インデックスごとに可能な唯一の候補を正確にチェックするため、有効なケースが見逃されることはなく、無効なケースがテストに合格することはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))
    
    total = sum(a)
    freq = {}
    for v in a:
        freq[v] = freq.get(v, 0) + 1
    
    res = []
    
    for i in range(n):
        s = total - a[i]
        if s % 2 != 0:
            continue
        x = s // 2
        
        # check availability of x after removing a[i]
        if x not in freq:
            continue
        
        # if we remove one occurrence of a[i]
        need = freq[x]
        if x == a[i]:
            if freq[x] - 1 > 0:
                res.append(i + 1)
        else:
            if freq[x] > 0:
                res.append(i + 1)
    
    print(len(res))
    if res:
        print(*res)

if __name__ == "__main__":
    solve()
```この解決策は、総和と頻度辞書を事前計算することから始まります。 メインループは、各削除を個別にテストします。 パリティ チェックにより、不可能な分割が早期に回避されます。 候補値の計算は、特殊な要素が他の要素の合計と等しくなければならないという条件から直接導出されます。 頻度調整により、削除された要素が候補値と重複する場合の正確性が保証されます。 

微妙な点の 1 つは、候補値が削除された要素と等しい場合の処理​​です。 その場合、削除後に少なくとももう 1 つのオカレンスが残るようにする必要があります。 そうしないと、「特別な要素」が配列から消えてしまいます。

 ## 特殊なケース

 次のような 2 要素の配列$[x, x]$1 つの要素を削除すると単一要素の配列が残り、条件を自明に満たすため、常に両方のインデックスが有効なものとして生成されます。 残りの合計が 1 つの要素に等しいため、アルゴリズムはこれを処理します。また、候補値が削除後もまだ存在することが頻度ロジックによって確認されます。 

すべての要素が同一である場合、削除後の候補値は依然として同じ値に等しく、頻度チェックはすべてのインデックスで常に合格します。 アルゴリズムはすべての位置を正確にカウントします。 

候補が削除された要素と等しい場合、より微妙なケースが発生します。 この場合、実装では使用可能なカウントが明示的に 1 つ減らされ、削除された要素が必要な値の唯一の出現である場合の誤検知が防止されます。
