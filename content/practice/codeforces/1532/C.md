 ## 解決策
 ## 問題の理解

 私たちは非常に特殊な制約の下で文字列を構築しています。各文字列は最初の k 個のラテン小文字のみを使用する必要があり、それらの k 個の文字はそれぞれ少なくとも 1 回出現する必要があります。 このような長さ n の有効な文字列すべての中で、出現頻度の最も低い文字をできるだけ大きくしたいと考えます。 

より簡単に言うと、空のバケットがないという条件で、n 個の同一の位置を k 個のラベル付きバケット (文字 a から k 番目の文字) に分配します。 このようなすべてのディストリビューションの中で、最小バケット サイズを最大化したいと考えています。 カウントを決定したら、文字を任意の順序で配置して有効な文字列を形成できます。 

制約は小さく、n と k は最大 100、クエリは最大 100 個です。 これは、クエリごとの O(nk) または O(n²) の構築が自明であることをすぐに示します。 本当の課題は効率ではなく、正しい配布戦略を認識することです。 

バランスを重視せずに「貪欲に文字を広げよう」とすると、素朴な間違いが生じます。 たとえば、n = 7 および k = 3 の場合、不注意なアプローチにより、最適性を考慮せずに 3、2、2 または 4、2、1 が割り当てられる可能性があります。 正解するには、k 個の文字がすべて存在する状態を維持しながら、周波数を可能な限り等化する必要があります。 

もう 1 つのよくある失敗モードは、「文字ごとに少なくとも 1 回」という制約を忘れることです。 たとえば、n = 4、k = 4 の場合、有効な分布は各文字の 1 つだけです。 最小周波数を 1 を超えて最大化しようとすると、プレゼンスを確保する以外に余分なスペースがないため、実現可能性に違反します。 

この問題は基本的に、グループあたり 1 という下限による整数分割と最小グループ サイズの最大化に関するものです。 

## アプローチ

 ブルートフォースアプローチでは、各カウントが少なくとも 1 になり、合計が n になるように k 個の文字にカウントを割り当てるあらゆる方法が試行されます。 割り当てごとに最小数を計算し、最良の結果を追跡します。 このようなパーティションの数は、整数の合成のように増加し、およそ O(C(n-1, k-1)) になりますが、これは一般に k に関して指数関数的であるため、n が小さい場合でも実行不可能になります。 

重要な観察は、バランスの取れた分布のみが重要であるということです。 最小頻度を最大化する場合、すべての k 個の文字のカウントができるだけ近くになるようにします。 各文字に x 回出現するとします。 それは kx 文字を消費します。 残りの n − kx 文字は任意に分散でき、一部の頻度は増加しますが、最小値が x を下回ることはありません。 したがって、可能な限り最良の x は、kx ≤ n、つまり x = n // k となるような最大の整数にすぎません。 

この基本量を割り当てた後、r = n % k 個の文字が残ります。 これらの残り物は、文字ごとに 1 つずつ任意の r 文字に分散させることができ、その頻度は増加しますが、構造は維持されます。 これにより、最小周波数が最大化される有効な構造が生成されます。 

したがって、検索する代わりに、最適な基本周波数を直接計算し、決定的に文字列を構築します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | k の指数 | O(k) | 遅すぎる |
 | 最適 | クエリあたり O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 クエリごとに、文字列を個別に構築します。

1. 基本周波数を x = n // k として計算します。 これは、合計が n を超えずに、すべての文字が少なくとも x 回出現することを保証できる最大回数です。 
2. 剰余 r = n % k を計算します。 これは、各文字を x 回出現させた後に配布される追加の文字を表します。 
3. 空の文字リストを作成します。 
4. 最初の k 文字ごとに、その文字を結果にちょうど x 回追加します。 これにより、必要な文字がすべて存在することが保証され、ベースラインの最小頻度が設定されます。 
5. 最初の r 文字を取得し、それぞれに 1 つの追加出現を追加することによって、残りの r 文字を分散します。 これにより、一部の周波数は増加しますが、x 未満には減少しません。 
6. リストを最終文字列に連結して出力​​します。 

重要な設計上の選択は、有効性を維持する限り、残り物の分配は任意であるということです。 残りを最初の r 文字に割り当てることは、正確さを保証する便利な決定論的な方法です。 

### なぜ効果があるのか

 この構造では、すべての文字が少なくとも x 回出現することが保証されるため、最小頻度は少なくとも x になります。 k 個の文字のそれぞれに x を与えることによって使用される文字の合計は kx ≤ n であり、x = n // k はこの性質で最大であるため、x より大きい最小頻度を達成できる解はありません。 最小値を x + 1 に増やそうとすると、少なくとも k(x + 1) > n 文字が必要になりますが、これは不可能です。 したがって、構築は最適です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())
for _ in range(t):
    n, k = map(int, input().split())

    x = n // k
    r = n % k

    res = []

    for i in range(k):
        res.append(chr(ord('a') + i) * x)

    for i in range(r):
        res[i] += chr(ord('a') + i)

    print(''.join(res))
```コードは配布ロジックに直接続きます。 最初のループは、すべての文字が x 個のコピーを取得する基本均一ブロックを初期化します。 2 番目のループは、最初の r 文字をインクリメントすることによって残りを処理します。 

微妙な点は、残った代入によってすでに構築された文字列が変更されるということですが、文字列が小さい (n ≤ 100) ため安全です。 もう 1 つの有効な代替方法は、最初に周波数配列を構築してからそれを拡張することですが、制約がある場合は文字列を直接連結する方が簡単です。 

## 実用的な例

 n = 7、k = 3 を考えてみましょう。 

x = 7 // 3 = 2 および r = 1 を計算します。

 | 塩基割り当て | ああ | BB | cc | ああ、bb、cc |

 最後の文字列は、任意の順序で「aabbc c」になります (たとえば、「cbcacab」)。 

これは、最小周波数が 2 であり、改善できないことを示しています。 

ここで、n = 4、k = 4 について考えてみましょう。 

| ステップ | | b | c | d | 状態 |
 | --- | --- | --- | --- | --- | --- |
 | 塩基割り当て | | b | c | d | ABCD |

 ここで、x = 1 および r = 0 であるため、すべての文字は 1 回だけ表示されます。 これは、1 回の発生を超えてバランスをとることができない厳しいケースを示しています。

## テストケース```python
import sys, io

def solve():
    import sys
    input = sys.stdin.readline
    t = int(input())
    out = []
    for _ in range(t):
        n, k = map(int, input().split())
        x = n // k
        r = n % k

        res = []

        for i in range(k):
            res.append(chr(ord('a') + i) * x)

        for i in range(r):
            res[i] += chr(ord('a') + i)

        out.append(''.join(res))

    return '\n'.join(out)

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    return solve()

# provided samples
assert run("3\n7 3\n4 4\n6 2\n") is not None

# custom cases
assert run("1\n1 1\n") == "a"
assert run("1\n5 2\n") is not None
assert run("1\n100 1\n") is not None
assert run("1\n3 3\n") is not None
```| テスト入力 | 期待される出力 | 検証内容 |

 ## 特殊なケース

 n = k の場合、すべての文字は 1 回だけ出現する必要があります。 このアルゴリズムは x = 1 および r = 0 を計算するため、余分な分布は発生しません。 出力は最初の k 文字の単純な並べ替えであり、最小頻度が 1 を超えることはできないため、これは有効かつ最適です。 

n < 2k の場合、基本周波数は 1 になり、残りはまばらになります。 このアルゴリズムでは、各文字が少なくとも 1 回は出現することが保証され、バランスを崩すことなく追加の文字が安全に配布されます。
