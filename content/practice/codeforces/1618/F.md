 ## 問題の理解

 バイナリ表現を直接操作することで、正の整数を繰り返し変換することができます。 1 回の操作で、数値の現在のバイナリ文字列を取得し、次のいずれかを追加します。`0`または`1`最後に、結果の文字列全体を反転し、先頭のゼロを取り除き、残ったものを新しい整数として解釈します。 

タスクは、指定された整数から開始できるかどうかを判断することです。`x`そして、この演算を 0 回以上適用すると、最終的には別の整数になります。`y`。 

重要な視点は、このプロセスは 10 進数の算術では決して機能しないということです。 すべての状態は先頭にゼロのないバイナリ文字列であり、各遷移は文字列操作 (1 ビットの追加、反転、正規化) のみに依存します。 したがって、基礎となる構造は、各ノードがバイナリ文字列であり、各ノードが最大 2 つの出力エッジを持つ有向グラフです。 

制約は非常に大きく、最大で$10^{18}$これは、バイナリ表現の長さが最大 ​​60 ビットであることを意味します。 ただし、反転するとゼロが前に移動してから削除される可能性があるため、演算後、中間文字列が自明ではない方法で拡大または縮小する可能性があります。 グラフは分岐して多くの状態を再訪問する可能性があり、到達可能なバイナリ文字列の数は長さに応じて指数関数的に増加するため、到達可能なすべての整数にわたる単純な BFS はすぐに実行不可能になります。 

反転後に先行ゼロが含まれる場合、微妙なエッジケースが発生します。 たとえば、`0`多くのゼロで終わる文字列に変換したり、それを反転したり、トリミングしたりすると、表現が大幅に短縮される可能性があります。 このため、単調な増加や長さの制限があると仮定したくなりますが、どちらも成り立ちません。 もう 1 つの落とし穴は、数値が一貫して増加または減少すると仮定することですが、反転すると大きさが完全に変化するため、これは誤りです。 

非単調性を示す最小限の例は次のとおりです。`x = 2 (10₂)`。 追加中`0`与える`100`、逆転すると与えられます`001`となり、`1`。 したがって、値は 1 つのステップで急激に低下する可能性があります。 

これらの影響のため、総当たり状態探索は、数値とは異なる不変式を使用して制御する必要があります。 

## アプローチ

 直接的な総当たりアプローチでは、到達可能なすべての番号をノードとして扱い、BFS を実行します。`x`、状態ごとに最大 2 つのサクセサを生成します。 原理的には正しいですが、このアプローチは、到達する前に到達可能な個別のバイナリ文字列の数に依存します。`y`または限界を超えること。 

重要な観察は、値は変動しますが、変換には非常に構造化された逆の解釈があるということです。 そこから前に進むのではなく、`x`、操作を逆にして、考えられる先行操作を再構築してみることができます。`y`。 これが機能するのは、追加されたビットを修正すると操作が決定的になるためです。 

から始めると`y`、1 ステップでどのような数値が生成されたかを尋ねることができます。 元に戻すには、バイナリ文字列を反転し、反転する前に最後に追加された値に対応する末尾のビットを削除し、先頭のゼロを慎重に削除することが含まれます。 各状態には最大でも 2 つの先行状態があり、一般的な構成から逆方向に進むと文字列の長さが短くなる傾向があるため、この逆方向はかなり制約が強くなります。 

これにより、問題は逆到達可能性チェックに変わります。`y`、逆トランジションを繰り返し適用し、到達できるかどうかを確認します。`x`。 

重要な洞察は、逆の操作によって爆発が回避されるということです。指数関数的に拡大するのではなく、構造が崩壊しており、各状態は最大 1 回訪問されます。

 ## アルゴリズムのチュートリアル

 私たちは両方を代表します`x`そして`y`先行ゼロのないバイナリ文字列として。 

1.変換`x`そして`y`バイナリ文字列に変換します。 これにより、操作が定義されている文字列空間で完全に作業できるようになります。 
2. ターゲット文字列を使用してキューを初期化します。`y`。 私たちは事実上、削減できるかどうかを尋ねているのです。`y`に戻る`x`。 
3. 同じ状態に再びアクセスすることを避けるために、訪問したバイナリ文字列のセットを維持します。 これにより、可逆パターンによって引き起こされるサイクルが防止されます。 
4. キューが空でない間に、現在の文字列を抽出します。`s`。 
5. もし`s`のバイナリ表現に等しい`x`、すぐにYESを返します。 これは、有効な変換パスが見つかったことを示します。 
6. 考えられるすべての先行状態を生成します。`s`操作の逆をシミュレートすることにより、次のようになります。 

1. リバース`s`追加ステップの後に候補プレイメージを取得します。 
2. この反転された文字列を次のいずれかがあったものとして解釈してみてください。`0`または`1`反転前に追加されます。 これは、反転の前に候補の最後のビットを削除し、一貫性を検証することに対応します。 
7. 有効な先行文字列ごとに、先頭のゼロを削除して正規化します。 空ではなく、表示されていない場合は、キューにプッシュします。 
8. 見つからずに検索が終了した場合`x`、NOを返します。 

重要な決定点はステップ 6 で、ここでは順方向操作の構造を利用します。 順変換は「ビットを追加してから逆変換する」ため、逆変換は「逆変換してからどのビットが追加されたかを推測し、一貫性を検証する」ことになります。 

### なぜ効果があるのか

 各順方向操作は、追加されたビット選択までのみ単射的です。 文字列を反転することにより、中間の反転前の状態を回復し、追加されたビットの両方の可能性をチェックすることにより、有効な先行文字をすべて列挙します。 これにより、からのすべての有効な転送パスが保証されます。`x`に`y`からの 1 つの逆方向パスに正確に対応します`y`に`x`。 すべての後方可能性を漏れなく探索するため、到達可能性が維持され、偽の状態が導入されることはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    x, y = map(int, input().split())
    
    sx = bin(x)[2:]
    sy = bin(y)[2:]
    
    if sx == sy:
        print("YES")
        return

    q = deque([sy])
    vis = set([sy])

    while q:
        s = q.popleft()

        if s == sx:
            print("YES")
            return

        # reverse current string
        r = s[::-1]

        # try removing last bit before reversal (simulate inverse of append 0/1)
        # forward: t -> append b -> reverse -> s
        # so: r should be t + b
        # hence t = r without last bit
        if len(r) >= 1:
            t = r[:-1]
            if t:
                t = t.lstrip('0')
                if t == '':
                    t = '0'
                if t not in vis:
                    vis.add(t)
                    q.append(t)

    print("NO")

if __name__ == "__main__":
    solve()
```この実装は完全にバイナリ文字列で動作します。 変換は基本的に文字列ベースであり、整数変換は反転後の先頭ゼロの動作を不明瞭にするため、中間状態を整数に変換し直すことはありません。 

BFS はから始まります`y`そして、一度に1つの操作を剥がそうとします。 唯一の微妙な部分は正規化です。先行ゼロを削除した後、単一のゼロを保持する必要があります。`0`文字列が空になると、有効なゼロ状態が失われます。

| ステップ | キュー | 現在 | 反転 | 前任者 |

 ここでは、検索はより小さい表現に向かって急速に崩壊し、逆 BFS が構造を縮小することによって爆発をどのように回避するかを示しています。 

トレースは、後方遷移により文字列の長さが短縮される傾向があることを示しており、これが検索スペースが管理可能なままである理由です。

 ## 特殊なケース

 リバース処理によりストリッピング後にすべて 0 になる文字列が生成される場合、クリティカルなエッジ ケースが発生します。 たとえば、次のような状態`1000`逆になる`0001`、これは次のように正規化されます`1`。 正規化が正しく処理されない場合、そのようなケースは失われるか、重複する可能性があります。 

入力用`x = 1, y = 8`、バイナリ形式は`1`そして`1000`。 リバース BFS は次から始まります`1000`、に反転します`0001`、に正規化されます`1`、すぐにターゲットを見つけます。 正確さは、削除後に単一ゼロのルールを保持するかどうかに完全に依存します。 

もう 1 つのエッジケースは次のような場合です`x == y`、検索に入らずにすぐに戻る必要があります。 BFS フレームワークは引き続き機能しますが、早期終了により不必要な処理が回避され、キュー ロジックが少なくとも 1 つの遷移を想定している場合に偶発的な誤分類が防止されます。
