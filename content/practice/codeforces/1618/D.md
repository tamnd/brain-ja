 ## 解決策
 ## 問題の理解

 整数の複数セットが与えられます。 2 つの要素を繰り返し正確に削除します$k$回、そして各除去はランニングスコアに追加される値を生成します。 これらの後$k$操作の結果、残った要素もスコアに直接追加されます。 

操作自体は非対称です: 値を選択する場合$x$そして$y$、貢献度は$\left\lfloor \frac{x}{y} \right\rfloor$。 順序が重要であるため、どの数値を分子とし、どの数値を分母とするかを選択することが結果に直接影響します。 2 つの要素を削除すると、それらは永久に消えるため、すべての要素はペアで、または残りとして 1 回だけ使用されます。 

制約$2k \le n \le 100$これは、常に配列の最大半分をペアリングしており、要素の総数が十分に小さいため、テスト ケースごとに 2 次または 3 次の推論が許容されることを意味します。 ただし、テスト ケースの数は最大 500 になる可能性があるため、ペアリングに対する指数関数的な検索は直ちに実行できなくなります。 

最も難しいのは、ペアの選択がグローバルに相互作用することです。分母を選択すると、将来の操作に何が残るかが早期に変わり、どの要素が最終的にペアにならず、結果に直接追加されるかも変わります。 

いくつかの微妙なエッジの状況が重要です。 

すべての数値が等しい場合、すべてのフロア分割は 1 となるため、すべてのペアリングの寄与は正確に 1 になります。ペアリングの順序を「最適化」しようとするが、誤って残りを間違ってペアリングする誤った貪欲な場合でも、固定された合計が生成され、すべての戦略が同等に見えるため、デバッグが困難になります。 

配列に 1 が多く含まれる場合、1 を分子として使用すると、それより大きな値と組み合わせると 0 が生成されるため常に安全ですが、分母として使用すると大きな値が生成されるため悲惨です。 隣接する要素をソートしてペアにする単純な貪欲さは、簡単に 1 を置き間違えてスコアを増加させる可能性があります。 

ゼロがある場合 (この問題には含まれていません)$a_i \ge 1$)、分割の非対称性は極端になります。 これは、分母の選択が主要な手段であることを裏付けています。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての操作シーケンスをシミュレートしようとします。 各ステップで、残りのインデックスの順序付けされていないペアを選択し、方向を決定します。 後$k$ステップ、残りの合計を計算します。 状態空間は次のように縮小します。$n, n-2, n-4, \dots$、しかし分岐因子は大まかに$O(n^2)$開始時に周囲で爆発が起こる$\binom{n}{2k}$ペア構造に方向の選択を掛け合わせます。 たとえ$n = 100, k = 50$、これはまったく不可能です。 

重要な構造的洞察は、最終的な答えが 2 つの独立した部分、つまりペアからの寄与と残りの要素からの寄与に分解されるということです。 どの要素がペアになっていないままになるかを決定すれば、残りの部分は簡単です。したがって、本当の問題は、どの要素をペアにするかを決定することです。$2k$要素のペアとその向き。 

次に、フロア分割の動作を観察します。 任意の固定ペアの場合$x, y$、そうでない限り貢献は小さいです。$x \gg y$。 スコアを最小限に抑えたいので、大きな数が小さな分母よりも分子になる状況は避けたいと考えています。 これは、貪欲な構造を示唆しています。つまり、大きな数が除算の分子になることは避けるべきですが、小さな数が分子になるのに最適な候補です。 

これにより、配列をソートするという標準的なペアリング戦略が導き出されます。 次に、最小の要素を潜在的な分子として扱い、最大の要素を潜在的な分母として扱います。 各演算では、小さい数値を分子として使用し、大きい数値を分母として使用して、1 つの小さい数値と 1 つの大きな数値をペアにする必要があります。$\left\lfloor \frac{x}{y} \right\rfloor$。 

残りの位置で極値を使用すると合計が増加するため、残りの要素はソートされた配列の中央部分である必要があります。 したがって、可能な最大の要素を分母に、最小の要素を分子に予約し、必要に応じて中間をペアにしないままにします。 

この構造を反転するとスコアがわずかに増加することが示されるため、この貪欲さが最適です。小さい分子を大きい分子と交換しても除算の結果を減らすことはできず、分母を交換しても大きい分子が小さい分母にさらされるだけが増加します。

 ## アルゴリズムのチュートリアル

 1. 配列を降順でない順に並べ替えます。 並べ替えにより、どの値を分子と分母として使用するかを決定するために必要なグローバル構造が明らかになります。 
2. プロセスを分割して選択する$k$ペアと出発$n - 2k$要素がペアになっていません。 対になっていない要素は、ソートされた配列の中央のセグメントとして扱われます。これは、除算の結果を制御する場合には極値の方がより役立つためです。 
3. 2 つのポインタを使用します。1 つは左から始まり (小さい値)、もう 1 つは右から始まります (大きな値)。 使用可能な最小の要素と使用可能な最大の要素を組み合わせます。 
4. 各ペアについて、次を計算します。$\left\lfloor \frac{a[l]}{a[r]} \right\rfloor$それをスコアに追加してから移動します$l$前方と$r$後ろ向きに。 これにより、分子は小さく、分母は大きく保たれ、寄与が最小限に抑えられます。 
5. 正確に終わるまで続けます$k$ペアが形成され、消費します$2k$要素。 
6. 残りのペアになっていない要素をすべてスコアに追加します。 これらは、削除後のソートされた配列の中間セグメントです。$k$最小のものと$k$最大の要素。 

### なぜ効果があるのか

 不変条件は、すべてのペアリング ステップで、小さい値と大きい値の間の可能な限り強力な分離を維持することです。 現在の最小値と現在の最大値のペアからの逸脱は、ペアを置き換えることしかできません。$(x, y)$どちらかで$(x, y')$どこ$y' \le y$、商を増やす、または$(x', y)$どこ$x' \ge x$、商も増加します。 したがって、貪欲なペアリングでは、代替マッチングに比べて個々の操作コストが増加することはなく、極端な値を除外することで残りの合計が最小限に抑えられます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))
        a.sort()

        l, r = 0, n - 1
        ans = 0

        # take k pairs: smallest with largest
        for _ in range(k):
            ans += a[l] // a[r]
            l += 1
            r -= 1

        # remaining elements are unpaired
        for i in range(l, r + 1):
            ans += a[i]

        print(ans)

if __name__ == "__main__":
    solve()
```このソリューションでは、まず、組み合わせの決定が組み合わせではなく位置に基づいて行われるように並べ替えます。 2 ポインター ループは明示的に次のものを消費します。$k$最小のものと$k$最大の要素。 残りのセグメントは連続しているため、合計するのは簡単です。 

微妙な点は、ペアの方向を決して再考しないことです。常に最小のものを分子として扱い、最大のものを分母として扱います。 整数の反転除算は非常に非対称であるため、反転しても商が増加するだけです。 

残りのループは包含境界を使用します。$k$正確に両端からの削除$n - 2k$要素は中間に残ります。

 ## 特殊なケース

 重要なエッジケースは、すべての要素が等しい場合です。 例えば、$n=4, k=2$と$[7,7,7,7]$。 アルゴリズムのペア$(7,7)$2 回、貢献を生み出す$1 + 1 = 2$、残りは残りません。 ペアリングの順序を変更する間違った戦略でも同じ結果が得られ、より一般的なケースでは間違いが隠れてしまう可能性があります。 

もう 1 つのケースは、小さな要素が大きな要素に比べて極端に小さい場合です。$[1,1,1,100,100,100]$と$k=2$。 このアルゴリズムでは、すべて 1 が分子として使用され、大きな数値が分母として使用され、すべての除算の寄与がゼロになることが保証されますが、大きな数値を分子にする交換によりスコアは直ちに増加します。 

最後の微妙なケースは、$k=0$、ペアリングは許可されません。 正しい動作は、すべての要素の合計を直接返すことです。 ペアリング ループがスキップされ、配列全体が残りとして合計されるため、アルゴリズムはこれを自然に処理します。
