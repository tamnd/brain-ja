 ## 解決策
 ## 問題の理解

 私たちはいくつかの独立したキャンディコレクションを与えられています。 各コレクションは単なる整数のマルチセットであり、各整数はキャンディのタイプを表します。 各コレクションからいくつかのキャンディーを選択して、単一の「ギフト」を構築したいと考えています。 

制限は、各種類のキャンディーの摂取が許可される数です。 特定のタイプの一部を選択する場合、その量は選択したすべてのタイプの中で一意である必要があります。 たとえば、タイプ 5 のキャンディーを 3 個使用した場合、ギフト内の他のタイプは正確に 3 回出現することはできません。 ただし、これらの数がすべて区別できる限り、タイプ 5 を 3 つ、タイプ 7 を 2 つ、タイプ 9 を 1 つなどとすることができます。 

各クエリの目標は、ギフト内のキャンディーの総数を最大化することです。 

入力サイズはクエリ全体で大きく、合計要素数は最大 2·10^5 です。 これにより、周波数に関する二次推論や、タイプごとにカウントを 1 つずつ繰り返し調整する貪欲なシミュレーションが即座に排除されます。 ソリューションは、各クエリをほぼ線形または線形時間で処理する必要があります。 

多くのタイプが同じ周波数を共有する場合、微妙な失敗例が発生します。 たとえば、頻度が [5, 5, 5, 5] である場合、単純なアプローチでは、それらすべてに値 5 を割り当てようとしますが、それは一意性に違反するため、最大合計を維持しながらいくつかの数を注意深く減らす必要があります。 

もう 1 つの注意が必要なシナリオは、一度に多数のタイプが出現するなど、頻度は小さいものの多数である場合です。 これらすべてに値 1 を割り当てることは無効です。カウントは個別である必要があるため、1 つのタイプのみが 1 を取ることができ、別のタイプは 0 を取る必要があり、以下同様になります。 

これらの制約により、問題は型のアイデンティティに関するものではなく、その頻度と、合計を最大化するためにそれらのサブセットに個別の正の整数を割り当てる方法だけが問題であることが明らかになります。 

## アプローチ

 最初の自然なアイデアは、各種類にキャンディーが何個入っているかを数えることです。 周波数 f1、f2、...、fk が得られたとします。 ここで、選択した各型に個別の正の整数 x (x ≤ fi) を割り当て、選択したすべての x の合計を最大化する必要があります。 

強引なアイデアは、型のすべてのサブセットと個別の値のすべての割り当てを試し、実現可能性をチェックして最大合計を追跡することです。 サブセットを修正したとしても、個別の値を割り当てることは順列のような問題です。 サブセットの数は 2^k で、k が大きくなる可能性があるため、これは入力が小さい場合でもすぐに実行不可能になります。 

より構造化されたブルート フォースでは、最大の周波数から順に値を試し、利用可能な最大の個別の数値を貪欲に割り当てますが、競合は再計算されます。 多くの周波数が類似している場合、これには依然として O(k^2) の動作の危険性があります。 

重要な観察は、どの型がどのカウントを取得するかをまったく気にせず、厳密に減少する整数、または少なくとも異なる整数を割り当てるだけであるということです。 合計を最大化するには、常に最初に割り当てられるカウントを大きくする必要がありますが、各周波数によって制限されます。 

これにより問題は次のように変換されます。容量 fi のリストがあり、選択した各要素に 1 ≤ xi ≤ fi となる個別の整数 xi を割り当て、合計 xi を最大化したいと考えています。 最適な戦略は、周波数を降順に並べ替え、可能な限り最大の未使用の整数を貪欲に割り当てますが、その周波数を決して超えないようにすることです。 

ソートされた頻度を反復処理すると、次に利用可能な整数値が維持されます。 周波数が現在利用可能な値以下の場合は、それをクランプします。 それ以外の場合は、区別性を維持するためにそれを削減します。 

これが機能するのは、ソートされた貪欲な構造に違反する割り当てを再配置して、合計を増加または維持できるためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^k・k) | O(k) | 遅すぎる |
 | 最適な貪欲さ | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1 つのクエリに焦点を当て、それを頻度処理に絞り込みます。

1. 各キャンディーの種類の出現数を数えます。 

各タイプに属するキャンディーの数を格納する頻度配列または辞書を作成します。 これにより、入力が最大 n 個の意味のある値に圧縮されます。 
2. ゼロ以外のすべての周波数をリストに抽出します。 

重要なのは周波数だけです。 数えた後は型自体は無関係です。 
3. 周波数を降順に並べ替えます。 

これにより、使用可能なより大きな値が最初に割り当てられるようになり、小さな割り当てで容量が無駄になることがなくなります。 
4. 変数を初期化する`cur = infinity`(または非常に大きな数)。 

これは、割り当て可能な個別の最大許容数を表します。 
5. 各周波数で反復します`f`ソートされた順序で。 

割り当てます`use = min(f, cur - 1)`なぜなら、型間で値を厳密に減少させ続ける必要があるからです。 

もし`use`負またはゼロになると、有効な正の個別の代入が残っていないため、停止します。 
6.追加`use`答えと更新へ`cur = use`。 

各ステップでは、以前の割り当てを尊重しながら、現在の型に対して可能な最大の有効な個別カウントを常に選択することが保証されます。 

### なぜ効果があるのか

 核となる不変条件は、i 個の周波数を処理した後、選択したタイプに厳密に減少する値を割り当て、各ステップで実行可能な割り当てを未使用のままにすることがないということです。 ソートにより、より容量の大きいタイプが最初に考慮されることが保証され、貪欲な削減により、周波数が大きすぎて残りの「スロット」に収まらない場合は、最小限に圧縮されることが保証されます。 この選択から逸脱すると、一意性が侵害されるか、より大きな実行可能な割り当てがより小さな割り当てに置き換えられ、合計が減少します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        arr = list(map(int, input().split()))

        freq = {}
        for x in arr:
            freq[x] = freq.get(x, 0) + 1

        vals = sorted(freq.values(), reverse=True)

        cur = n
        ans = 0

        for f in vals:
            if cur <= 0:
                break
            use = min(f, cur)
            ans += use
            cur = use - 1

        print(ans)

if __name__ == "__main__":
    solve()
```この実装では、まず辞書を使用して配列を周波数に圧縮します。 これが必要なのは、型自体はカウント後には無関係であるためです。 

頻度を降順に並べ替えて、大きなグループが最初に割り当てられるようにして、大きな個別のカウントを早期に使用できる可能性を最大化します。 

変数`cur`割り当て可能な残りの最大の整数を追跡します。 割り当てるたびに`use = min(f, cur)`、利用可能な周波数または残りの許容される個別の値を超えないことを保証します。 それから減らします`cur`に`use - 1`厳密な一意性を維持するため。 

よくある実装上の間違いは、割り当てられた値が厳密に区別される必要があることを忘れていることです。 これは完全に強制されます`cur - 1`。

 ## 特殊なケース

 重要なエッジ ケースは、多くのタイプの頻度が 1 である場合です。[1、2、3、4、5] のような入力の場合、アルゴリズムは最初のタイプに 1 を割り当て、その後、他のすべてのタイプに 0 を割り当てる必要があります。 cur はすぐに 0 に低下するため、貪欲なリダクションはこれを自然に処理します。 

もう 1 つのケースは、[1,1,1,1,1,1] など、1 つのタイプが優勢な場合です。 最初の割り当てでは 6、次に 5、さらに 4 を使用し、枯渇するまで階段を生成します。 不変式により、同じカウントが 2 回割り当てられることがなくなります。 

3 番目のケースは、[3,3,3,2,2] などの交互の中間周波数です。 並べ替えにより、より大きなグループが最初に処理されるようになり、可能性の高い割り当てが早期にブロックされるのを防ぎます。
