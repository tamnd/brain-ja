 ## 解決策
 ## 問題の理解

 文字列が与えられ、個別の文字列のコレクションを構築したいとします。ここで、各文字列は元の文字列のサブシーケンスである必要があります。 サブシーケンスを選択するたびに、使用しなかった文字に対して「支払い」が行われるため、短いサブシーケンスの方が安くなり、コストを削減するという意味では長いサブシーケンスの方が高価になります。 

目標は、少なくとも$k$総コストを最小限に抑えながら、コレクション内の個別のサブシーケンスを作成します。 重複は禁止されているため、実際の困難は、文字列の個別のサブシーケンスの数が急速に増加することですが、その多くは元の文字列から形成される方法において構造的な重複を共有していることです。 

制約$n \le 100$がキー信号です。 サブシーケンスを明示的に列挙しようとする解決策は、次のようなものがあるため不可能です。$2^n$彼らのうち。 すべての個別のサブシーケンスを保存することすら不可能です。 これにより、明示的な構築ではなく構造に対する動的プログラミングの観点が即座に強制されます。 

値$k$まで上がります$10^{12}$これは、長さ 100 の多くの文字列のサブシーケンスの総数をはるかに超えているため、生成をシミュレートするのではなく、不可能性を効率的に検出する必要もあります。 

いくつかの失敗例は自然に現れます。 

すべての文字が同一の場合、次のようにします。$s = \texttt{aaaa}$の場合、個別のサブシーケンスの数は 4 つと定義に応じた空の文字列効果だけですが、構造的には非常に小さいです。 もし$k$その数を超えると、答えは不可能に違いありません。 指数関数的な増加を想定する単純な方法では、過大評価して、存在しない部分列を構築しようとします。 

もう一つの微妙なケースは次のような場合です。$k = 1$。 コストがゼロであるため、最良の選択は常に完全な文字列です。 「多様性を最大化」しようとする貪欲なアイデアは、誤って短いサブシーケンスを選択し、不必要にコストを増加させる可能性があります。 

## アプローチ

 直接的な総当たりアプローチでは、次のすべてのサブシーケンスを列挙しようとします。$s$、それらを重複排除してから、最適なものを選択します$k$。 コストの最適化を無視しても、これにはすでに必要となります。$O(2^n)$世代では完全に不可能です$n = 100$。 

次の自然なステップは、サブシーケンスに対する動的プログラミングの観点から考えることです。 重要な観察点は、サブシーケンスは独立したオブジェクトではなく、各文字を選択またはスキップすることによってすべてのサブシーケンスを拡張できるツリー状の構造を形成しているということです。 ただし、実際には文字列自体を構築する必要はなく、文字列の数とコストによる順序付けのみを構築する必要があります。 

重要な洞察は視点を変えることです。 サブシーケンスのセットを直接構築する代わりに、既に使用されている制約の特定の「状態」を持つ文字列内の位置から開始して、個別のサブシーケンスをいくつ形成できるかを検討します。 これにより、サフィックス内の個別のサブシーケンスをカウントする DP が得られますが、文字を含めるか除外するかを決定するときに、導入される新しい個別のサブシーケンスの数について推論することもできます。 

個別のサブシーケンスの数を効率的に計算できるようになると、完全な文字列から貪欲な構築を実行できるようになります。 (コストを削減するために) 常に文字を保持することを優先するという考え方ですが、達成可能な個別のサブシーケンスの数が以下を下回らないようにする必要があります。$k$。 これは制御された走査になり、各位置で文字を安全に破棄できるか、または十分なサブシーケンスを保持するために保持する必要があるかを決定します。 

最終的な解決策は、基本的に、DP カウントによって駆動される辞書編集に基づいたサブシーケンス生成プロセスであり、カウントは容量制約として機能します。

 | --- | --- | --- | --- |
 | ブルートフォース |$O(2^n)$|$O(2^n)$| 遅すぎる |
 | DP + 貪欲な構築 |$O(n^2)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 まず、文字列の接尾辞ごとに異なるサブシーケンスがいくつ存在するかをカウントする DP を定義します。重複文字がカウントされすぎないように、繰り返し文字を慎重に処理します。 

1. DP 配列を構築します。$dp[i]$接尾辞から形成できる個別のサブシーケンスの数を表します$s[i:]$。 これには空のサブシーケンスが含まれるため、安全に比較できます。$k$特別なケースを空にする必要はありません。 繰り返しは、含めるかスキップするかによって決まります。$s[i]$ただし、同じ文字が以前に出現したことによって生じた重複を減算する必要があります。 
2. すべての DP 値を、次の値を超える大きなしきい値にクランプします。$10^{12}$。 これによりオーバーフローが回避され、上記の値が存在するという事実とも一致します。$k$意思決定に相当します。 
3. もし$dp[0] < k$、すぐに戻ります$-1$完全な文字列でも十分な個別のサブシーケンスを生成できないためです。 
4. 貪欲にサブシーケンスを構築します。 文字列に対するポインタと、まだ考慮する必要がある個別のサブシーケンスの数に関する現在の「残りの要件」を維持します。 
5. 各位置で、少なくとも次の文字を生成できる状態で現在の文字をスキップできるかどうかを決定します。$k$残りのサフィックスとは異なるサブシーケンス。 これは、サフィックスの DP 値を使用してテストされます。 
6. スキップしても安全であれば、スキップしてコストが発生します$1$選択したすべてのサブシーケンスからこの文字を削除することで、効果的に調整を行っています。 それ以外の場合は、十分なサブシーケンスを保持するためにキャラクターを構造内に保持する必要があり、コストを追加することなく先に進みます。 
7. 総コストは、構築全体でスキップされたキャラクター貢献の数と正確に累積され、これは一致します。$n - |t|$選択されたサブシーケンスにわたって集約されます。 

### なぜ効果があるのか

 正しさは次の解釈に依存します$dp[i]$サフィックスの容量として、以前の構造を破棄した場合に到達可能な個別のサブシーケンスの数を制限します。 貪欲な手順では、到達可能なサブシーケンス数が以下に低下する場合に文字をスキップしないことにより、常に実現可能性が維持されます。$k$。 文字を破棄する場合にのみコストが増加し、安全な場合にのみ破棄するため、アルゴリズムは少なくとも$k$異なるサブシーケンス。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())
    s = input().strip()

    # dp[i]: number of distinct subsequences in s[i:]
    dp = [0] * (n + 1)
    dp[n] = 1  # empty subsequence

    last = {}
    LIMIT = k  # we cap at k since above k is irrelevant

    for i in range(n - 1, -1, -1):
        c = s[i]
        dp[i] = dp[i + 1] * 2

        if c in last:
            dp[i] -= dp[last[c] + 1]

        if dp[i] > LIMIT:
            dp[i] = LIMIT
        if dp[i] < 0:
            dp[i] = 0

        last[c] = i

    if dp[0] < k:
        print(-1)
        return

    # greedy construction controlling cost
    # we simulate keeping enough subsequences
    res = 0
    remaining = k
    i = 0

    while i < n:
        # if we skip s[i], we rely on suffix capacity
        if dp[i + 1] >= remaining:
            # skip character => it contributes cost 1
            res += 1
        else:
            # must keep it structurally
            remaining -= 1
        i += 1

    print(res)

if __name__ == "__main__":
    solve()
```DP 構造では、反復文字に対する標準の包含/除外補正を使用して接尾語のサブシーケンスの数を計算します。 の`last`Dictionary では、文字が繰り返されるときに、以前の出現ですでにカウントされているサブシーケンスが減算され、重複の過剰カウントが回避されます。 

貪欲フェーズでは、DP を実現可能性の限界として解釈します。 サフィックスだけで必要なサブシーケンスをすべてサポートできる場合は、現在の文字を考慮から安全に「削除」し、コストを増加させます。 それ以外の場合は、それを保存する必要があり、この文字は依存する構造の一部になっているため、残りの要件が実質的に減ります。 

微妙な点は、DP 値のクランプです。$k$。 これがないと、値が指数関数的に増加し、Python の整数がオーバーフローしたり、それを超える値があったとしても時間が無駄になります。$k$意思決定に相当します。

 ## 特殊なケース

 多くの繰り返し文字を含む文字列の場合、DP 減算ステップにより、同一のサブシーケンスの過大なカウントが防止され、実行可能性チェックが正確であることが保証されます。 たとえば、次のような文字列では`"aaaa"`、以前の寄与を差し引かないと、指数関数的な成長が誤って示唆されてしまいます。 代わりに、アルゴリズムはすべての重複を小さな有界状態空間に折りたたむため、次の条件に応じて不可能またはコストの厳しい動作が正しくトリガーされます。$k$。
