 ## 解決策
 ## 問題の理解

 いくつかの独立したシナリオが与えられています。 それぞれに製品価格のリストがあり、各価格を最大で調整することができます。`k`どちらの方向にも調整できますが、複数回調整することはできません。 これらの調整後、すべての製品がまったく同じ整数の価格になるようにしたいと考えています。`B`。 

選択された値の条件`B`シンプルですが厳格です: すべての元の価格`a_i`に移動できる必要があります`B`許容される変化を超えない、つまり絶対的な差を意味します`|a_i - B|`を超えてはなりません`k`。 一つでも商品が届かない場合`B`、その値は`B`は無効です。 

すべての有効な整数値のうち、`B`、最大値を見つける必要があります。 すべての要素の条件を満たす整数がない場合、出力します。`-1`。 

各クエリは独立しているため、プロセスは毎回新しい配列で再起動されます。 

制約は小さいです。`n ≤ 100`、`q ≤ 100`。 これにより、クエリごとの線形または対数線形作業を超える高度なデータ構造や最適化の必要性が即座に排除されます。 クエリごとに O(n^2) のアプローチでも快適に通過します。 

さまざまな要素によって定義された間隔がまったく重ならない場合、微妙なエッジ ケースが発生します。 たとえば、`a = [1, 100]`そして`k = 10`の場合、有効な範囲は次のようになります。`[−9, 11]`そして`[90, 110]`、交差しないため、有効な値はありません`B`存在します。 

もう 1 つのエッジ ケースは、交差は有効だが最大境界が直感的ではない場合です。 たとえば、すべての間隔が重なり合っている場合、答えは単に交差点の右端の点になります。 

## アプローチ

 ブルートフォースアプローチでは、可能なすべての整数が試行されます。`B`から`1`まで`max(a_i) + k`、すべての要素が満たされているかどうかを確認します`|a_i - B| ≤ k`。 候補者ごとに`B`、配列をスキャンするので、複雑さは O(M·n) になります。ここで、M は可能な値の範囲です。 以来`a_i`まで可能です`10^8`、M が大きくなる可能性もあり、最悪の場合、このアプローチは完全に実行不可能になります。 

重要な観察点は、各要素が`a_i`の任意の値は許可されません`B`ですが、代わりに間隔に制限されます。`[a_i - k, a_i + k]`。 「すべての積が B と等しくなり得る」という条件は、B がこれらすべての区間の交点に存在することを要求するのと同じです。 問題をこのように解釈すると、標準的な区間交差の問題に帰着します。 

多くの区間の交差点自体が区間である`[L, R]`、 どこ`L`はすべての左端点の最大値であり、`R`すべての適切なエンドポイントの最小値です。 もし`L > R`、交差点は空であり、解決策は存在しません。 それ以外の場合は、すべての整数が`[L, R]`は有効であり、可能な限り最大値が必要なので、`B`、私たちはただ選択するだけです`R`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n · max(a_i + k)) | お(1) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. クエリごとに、価格と値の配列を読み取ります。`k`。 

各シナリオは個別に処理されるため、状態は共有されません。 
2. 各価格について`a_i`、有効な最終値の間隔を計算します。`[a_i - k, a_i + k]`。 

これは制約を直接エンコードします`|a_i - B| ≤ k`。 
3. 2 つの変数を維持します。`L`非常に小さな数値に初期化され、`R`非常に大きな数値に初期化されます。 

これらは、これまでに処理されたすべての間隔の交差を表します。 
4. インターバルごとに`[l, r]`、 アップデート：`L = max(L, l)`そして`R = min(R, r)`。 

これにより、次の値のみが保持されます。`B`これは、これまでに確認されたすべての要素に有効です。 
5. すべての要素を処理した後、次のことを確認します。`L > R`。 

この場合、交点には整数は存在しないため、答えは次のようになります。`-1`。 
6. それ以外の場合は出力`R`これは、すべての制約を満たす最大の整数であるためです。 

### なぜ効果があるのか

 各要素は独立して制限します`B`有効な値の閉じた間隔に設定します。 の値`B`は、すべての要素の制約を同時に満たす場合にのみ配列全体に対して有効です。これはまさに、すべての区間の交差部分に属するという定義です。 アルゴリズムはこの交差部分を増分的に維持し、処理されたすべての制約を満たす可能性のある値をどのステップでも破棄しません。 したがって、値が最後まで残っていれば、その値はすべての要素に対して有効であり、交差部分が空になると、有効な値は存在しません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

q = int(input())
for _ in range(q):
    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    L = -10**18
    R = 10**18

    for x in a:
        L = max(L, x - k)
        R = min(R, x + k)

    if L > R:
        print(-1)
    else:
        print(R)
```このソリューションは、各価格を許容可能な間隔に変換し、それらを交差させ続けます。 唯一の微妙な実装の詳細は、十分に大きな初期境界を選択することです。`L`そして`R`、価格が上昇する可能性があるため、`10^8`そして`k`まで`10^8`, そのため、結果の間隔は元の範囲を超える可能性があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    q = int(input())
    out = []
    for _ in range(q):
        n, k = map(int, input().split())
        a = list(map(int, input().split()))

        L = -10**18
        R = 10**18

        for x in a:
            L = max(L, x - k)
            R = min(R, x + k)

        out.append(str(-1 if L > R else R))

    return "\n".join(out)

 ## 特殊なケース

 重要なエッジケースの 1 つは次のような場合です。`k = 0`。 この場合、すべての間隔は次のように崩壊します。`[a_i, a_i]`したがって、唯一可能な解決策は、すべての要素がすでに等しい場合です。 すべての値が正確に一致する場合にのみ交差部分が存続するため、アルゴリズムはこれを自然に処理します。 

もう 1 つのエッジケースは次のような場合です`n = 1`。 答えは単純です`a_1 + k`、単一の間隔は`[a_1 - k, a_1 + k]`そして有効な最大値を選択します。 

値が大きく、`k`も大きいため、元の入力範囲の範囲を超えてしまう可能性があります。 実装でワイド整数境界を使用すると、Python 整数には境界がなく、ロジックは比較のみに依存するため、オーバーフローやクリッピングが正確性に影響を与えないことが保証されます。 

最後に、アルゴリズムが継続的に両端を強化し、すべての制約を満たす可能性のある有効な候補を失うことがないため、交差点が早期に単一点に縮小するケースは正しく処理されます。
