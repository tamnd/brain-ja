 ## 解決策
 ## 問題の理解

 各キャンディーはタイプに属します。 あらゆるタイプについて、そのタイプのキャンディーがいくつ存在するか、そしてそれらのキャンディーの中でどれだけのキャンディーが存在するかがわかります。`f = 1`。 

いくつかのキャンディーを選択してギフトを作成したいと思います。 いくつかのタイプからキャンディーを取得する場合、選択した各タイプから取得した番号はペアごとに異なる必要があります。 たとえば、ある種類のキャンディーを 5 つ使用し、別の種類のキャンディーを 5 つ使用することは禁止されています。 

最適化は辞書編集的です。 

まず、ギフト内のキャンディーの総数を最大化します。 

最大サイズのすべてのギフトの中で、選択したキャンディーの数を最大化します`f = 1`。 

重要な観察は、個々のキャンディーのアイデンティティは、各タイプの 2 つの統計を通じてのみ重要であるということです。`cnt[type]`= その種類のキャンディーの合計。`good[type]`= そのタイプのキャンディー`f = 1`。 

取ることに決めたら`k`あるタイプのキャンディーを使用する場合、2 番目の目的への最大の貢献は、`min(k, good[type])`なぜなら、いつでも最初に利用可能なすべての良いキャンディーを選択し、必要に応じて残りを悪いキャンディーで埋めることができるからです。 

すべての合計`n`クエリ全体で最大`2 · 10^5`。 これにより、型の数における二次関数は即座に排除されます。 おおよその必要があります`O(n log n)`クエリごと以上。 

微妙な点は、最初の目標はタイプの頻度のみに依存するのに対し、2 番目の目標は各タイプに含まれる良質なキャンディーの数に依存することです。 最初に良いキャンディーを貪欲に最大化するソリューションは、ギフトの最大サイズを破壊する可能性があります。 

考慮する：```
Type A: cnt=5, good=0
Type B: cnt=5, good=5
```ギフトの最大合計サイズはカウントによって取得されます。`(5,4)`合計で`9`。 

良いキャンディーがたくさん入っているタイプを好む貪欲な戦略では、`5`タイプ B を選択し、タイプ A を無視して、のみを取得します`5`キャンディー、これは最適ではありません。 

もう 1 つの簡単な間違いは、型に頻度があると仮定することです。`c`、その後、サイズを割り当てるたびに`k ≤ c`、良質なキャンディーへの貢献はまさに`good[type]`。 それは誤りです。 

例：```
Type A: cnt=10, good=8
```サイズを割り当てると`k=3`、私たちが貢献できるのは`3`良いキャンディー、ではない`8`。 

正しい貢献度は、`min(k, good[type])`。 

3 番目のエッジ ケースは、多くのタイプが同じ頻度を持つ場合に発生します。 

例：```
cnt = [3,3,3]
```個別に割り当てられたサイズを指定することはできません。`(3,3,3)`。 

最高の課題は`(3,2,1)`合計サイズ付き`6`。 

周波数を個別に処理する実装ではオーバーカウントが発生します。 

## アプローチ

 強引な見方では、すべての種類について、キャンディーの数を決定します。 あれば`m`タイプの場合、各タイプは以下から任意の量を貢献できます。`0`その周波数に。 次に、選択したすべてのカウントが異なるかどうかを確認し、両方の目的を計算する必要があります。 

たとえ`m = 50`、この検索空間は天文学的なものです。 まで`2 · 10^5`キャンディー全体では、ブルートフォースは完全に不可能です。 

重要な観察は、最初の目的では周波数のみが重要であるということです。 

タイプの頻度が次のとおりであるとします。```
c1, c2, c3, ...
```個別の正の整数を選択したい```
x1, x2, x3, ...
```そのような```
0 ≤ xi ≤ ci
```そしてすべての合計`xi`最大化されます。 

これは簡単なバージョンと同じ貪欲な問題です。 可能な周波数を最大から最小まで処理する場合、複数の型が同じサイズをサポートできる場合は常に、そのサイズを 1 つの型にのみ割り当てる必要があります。 サイズを割り当てた後`s`、次に割り当てられるサイズは厳密に以下より小さくなければなりません`s`。 

これを実装する便利な方法は、タイプを周波数ごとにグループ化し、周波数を下方向にスイープすることです。 周波数で`f`、カウントが等しいすべてのタイプ`f`利用可能になります。 現在利用可能なすべてのタイプの中で、サイズを割り当てます`f`そのうちの1人に。 

簡易バージョンでは、利用可能なタイプがサイズを受け取るかどうかは関係ありません`f`。 

ハード バージョンの場合、2 番目の目標は選択したタイプに依存するため、これは重要です。 

現在サイズを割り当てているとします。`f`。 

利用可能なタイプには少なくとも頻度があります`f`, したがって、このサイズを合法的に受け取ることができます。 

タイプがある場合`good = g`、次にサイズを割り当てます`f`貢献する```
min(f, g)
```良いキャンディー。 

最初の目的はサイズを割り当てることですでに固定されているため、`f`、このサイズを利用可能な型に与えて最大化する必要があります。`min(f, g)`。 

これにより、問題は優先キューのスイープに変わります。 

周波数が減少するにつれて、`n`に`1`、合計数が少なくとも現在の頻度であるすべてのタイプを維持します。 その中で、最大の値を与えるタイプを選択します。`min(f, good)`。 

各タイプはヒープに一度入り、一度ヒープから出ます。

 ## アルゴリズムのチュートリアル

 ### 1. 情報を種類ごとに圧縮する

 タイプごとに次を計算します。```
cnt[type]
good[type]
```どこ`good[type]`でキャンディーを数えます`f = 1`。 

後はこれらの値のみが重要になります。 

### 2. 頻度別にタイプをグループ化する

 既存のタイプごとに、そのタイプを配置します。`good[type]`値をその頻度に応じてバケットに格納します。```
bucket[cnt[type]]
```スイープが周波数に達したとき`f`、すべてのタイプ`bucket[f]`利用可能になります。 

### 3. 周波数を大きいものから小さいものまでスイープします。 

処理頻度:```
f = n, n-1, ..., 1
```周波数を扱う前に`f`、合計数が等しいすべてのタイプを優先キューに挿入します。`f`。 

現時点では、キュー内のすべてのタイプに少なくとも頻度があります`f`、そのため、どれでも割り当てサイズを受け取ることができます`f`。 

### 4. サイズに最適なタイプを選択する`f`キューが空でない場合は、サイズを割り当てます`f`使用可能なタイプを 1 つだけ指定します。 

この割り当ては次のことに貢献します。```
f
```ギフトの合計サイズに合わせて。 

2 番目の目的では、次のタイプを使用します。`good = g`貢献します:```
min(f, g)
```良いキャンディー。 

利用可能なすべてのタイプの中から、この値を最大にするタイプを選択してください。 

そのタイプをキューから削除します。 

### 5. 答えを蓄積する

 追加:```
f
```ギフトの最大サイズまで。 

追加：```
min(f, g)
```良いキャンディーを最大数まで。 

頻度まで続ける`1`。 

### なぜ効果があるのか

 掃引が周波数で行われる場合`f`、アクティブ セット内のすべての型は、代入サイズを合法的に受け取ることができます。`f`、元の周波数は少なくとも`f`。 

easy-version の貪欲な引数は、サイズの割り当てを示しています。`f`キャンディーの総数を最大化するには、可能な限り常に必要です。 このような割り当てをスキップすると、将来のすべてのサイズが小さくなるため、後で補正することはできません。 

ワンサイズ`f`固定されているため、すべてのアクティブなタイプが同じ貢献をもたらします`f`最初の目的へ。 残る唯一の違いは二次寄与分です`min(f, good)`。 

最大化するアクティブタイプの選択`min(f, good)`最初の目的を損なうことはなく、2 番目の目的に対して局所的に最適です。 すべての周波数は一度だけ割り当てられ、その後の割り当てでは厳密に小さいサイズが使用されるため、この交換引数はすべてのステップで独立して適用されます。 選択したタイプを他のアクティブなタイプに置き換えても、二次目標は増加しません。 

したがって、このアルゴリズムは、ギフトの合計サイズを最大化し、そのようなすべてのソリューションの中で、選択されたキャンディーの数を最大化します。`f = 1`。 

## Python ソリューション```python
import sys
from collections import defaultdict
import heapq

input = sys.stdin.readline

def solve():
    q = int(input())
    ans = []

    for _ in range(q):
        n = int(input())

        cnt = defaultdict(int)
        good = defaultdict(int)

        for _ in range(n):
            a, f = map(int, input().split())
            cnt[a] += 1
            good[a] += f

        buckets = [[] for _ in range(n + 1)]

        for t in cnt:
            buckets[cnt[t]].append(good[t])

        heap = []
        total_candies = 0
        total_good = 0

        for freq in range(n, 0, -1):
            for g in buckets[freq]:
                heapq.heappush(heap, -g)

            if heap:
                g = -heapq.heappop(heap)

                total_candies += freq
                total_good += min(freq, g)

        ans.append(f"{total_candies} {total_good}")

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```最初のループは、生のキャンディ データをタイプごとの統計に変換します。 その後、すべてのタイプは、その合計頻度と良いキャンディーの数という 2 つの数字で表されます。`buckets[f]`頻度が等しいすべての型を格納します`f`。 下方向スイープ中に挿入すると、`buckets[f]`ヒープに入れると、すべての型が少なくとも頻度で作成されます`f`利用可能。 

ヒープストア`good`カウントします。 Python は最小ヒープを提供するため、最大ヒープをシミュレートするために負の値が使用されます。 

周波数を処理する場合`freq`、最大のものを削除します`good`値はタイプを最大化する選択に対応します`min(freq, good)`。 すべてのアクティブなタイプがすでにサイズをサポートしているため、`freq`、これはまさに証明に必要な貪欲な選択です。 

見落としがちな実装の詳細の 1 つは、ヒープに格納されるのは`good`、周波数ではありません。 型は、その真の周波数が利用可能になった瞬間に 1 回だけ挿入されます。 挿入後は、すべての小さい割り当てサイズに引き続き適格であるため、追加情報は必要ありません。
