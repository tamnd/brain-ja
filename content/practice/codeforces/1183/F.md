 ## 解決策
 ## 問題の理解

 いくつかの独立したデータセットが与えられています。 各データセットには正の整数の複数セットがあり、各整数は問題の「値」を表します。 合計を最大化するには、このプールから最大 3 つの値を選択する必要がありますが、強い制限があります。選択した値が他の選択した値を割ることはできません。 

それで数字を選ぶと$x, y, z$の場合、6 つの順序付けられた可分性関係はいずれも許可されません。 2 つの数字を選択した場合でも、すでに同じルールが課せられます。どちらももう一方を割り算することはできません。 目標は、1 つ、2 つ、または 3 つの有効な数値の可能な限り最良の合計を見つけることです。 

入力の構造は非常に重要です。$2 \cdot 10^5$すべてのクエリの合計数、最大$2 \cdot 10^5$クエリ。 これにより、クエリごとにすべてのトリプルを試行したり、コストのかかる因子チェックをクエリごとに繰り返し実行したりするアプローチは直ちに排除されます。 クエリごとにほぼ線形またはほぼ線形より悪いものは失敗します。これは、合計入力サイズは大きいものの依然として密度が高いためです。 

すべてのトリプルを試してみるのが素朴な本能ですが、値が大きく、クエリ間で繰り返される場合、候補に対する二重ループでさえすでに大きすぎます。 もう 1 つの微妙な落とし穴は、最大 3 つの数値が常に機能すると仮定していることです。 これは、特に複数のチェーンのような構造化された入力では、大きな数が小さな数と多くの割り算関係を持っていることが多いため、失敗します。 

2 番目の障害モードは、割り算の互換性をチェックせずに値を降順にする貪欲な選択によって発生します。 たとえば、大きな数を選択すると、ペアまたはトリプルとしてより適切に組み合わせることができる多くの中規模の候補がブロックされる可能性があります。 

## アプローチ

 ブルートフォース手法では、サイズ 1、2、および 3 のすべてのサブセットが列挙されます。各サブセットについて、ペアごとの割り算をチェックして合計を計算し、最大の有効な結果を追跡します。 これは制約に直接従うため、正しいです。 ただし、トリプルの数は、$O(n^3)$クエリごとに、これは完全に不可能です。$n$までです$2 \cdot 10^5$。 

すべてのペアをチェックするように減らしてから 3 番目の要素に拡張しても、依然として次の結果が得られます。$O(n^3)$最悪の場合の行動。 ボトルネックは、可分性がローカルな比較ではなくグローバルな構造であるため、単純な組み合わせ論では同じ関係が繰り返し再確認されることです。 

重要な観察は、答えが値ごとに非常に少数の候補にのみ依存するということです。 数字について考えてみると$x$、一緒に禁止されているすべての数値は、約数と倍数です。 値は次のように制限されているため、$2 \cdot 10^5$、各数値の約数は比較的少なく、倍数構造は効率的に事前計算できます。 

周波数を前処理してから、候補値ごとに、その値で割り切れない値の中に互換性のあるパートナーがいくつ存在するかを計算します。 任意のトリプルをチェックする代わりに、構造化された方法でソリューションの構築のみを試みます。アンカー候補として最大の値を取得し、事前に計算された互換性フィルタリングを使用して、最も互換性のある 2 番目と 3 番目の選択肢を試します。 

中心的な考え方は、最大 3 つのサイズの最適なセットには、割り算の制約の下で「局所的に最適な」値が含まれている必要があり、要素インデックスではなく値空間を反復することで候補を列挙できるということです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(n^3)$|$O(1)$| 遅すぎる |
 | 事前計算を使用した値ベースの列挙 |$O(M \log M)$クエリごと (償却) |$O(M)$| 承認済み |

 ここ$M = 2 \cdot 10^5$。 

## アルゴリズムのチュートリアル

 私たちはインデックス空間ではなく値空間で作業します。 主なアイデアは、各値の頻度を事前に計算し、1、2、または 3 つの値を貪欲かつ安全に選択することを検討することです。 

### ステップ

 1. 配列内の各値の頻度をカウントします。 

入力を周波数配列に圧縮して、繰り返される値が個別ではなく集合的に処理されるようにします。 
2. 降順にソートされた現在値のリストを事前計算します。 

これにより、貢献度の高い候補を常に最初に検討することが保証されます。これは、答えが最大化問題であるため、不可欠です。 
3. 各値を計算します。$x$、別の値かどうか$y$互換性があります。 

2 つの値がどちらも他方を分割しない場合、互換性があります。 完全な互換性グラフを明示的に構築するわけではありません。 代わりに、除数の列挙を利用して関係を迅速にチェックします。 
4. 最適な単一値を試します。 

任意の値$x$単独で使用することも、貢献することもできます$x$それが存在する場合。 最良の単一の選択は、単に存在する最大値です。 
5. 最適なペアを試してください。 

値を反復処理します$x$降順で、それぞれについて、可能な限り最適なものと組み合わせてみてください。$y$そのような$x \nmid y$そして$y \nmid x$。 

常に大きい値から小さい値まで処理するため、最適なパートナーを動的に維持できます。 
6. 最高のトリプルを試してください。 

最大値を固定します$x$、次に 2 つの追加の値を選択してみます$y, z$残りの候補から、すべてのペアごとの割り切り制約が満たされないようにします。 あと必要な要素は最大でも 2 つだけであるため、検索を上位の候補に制限し、互換性を検証します。 
7. すべての有効な構造の最大値を取得します。 

### なぜ効果があるのか

 最大 3 つの要素を選択するという制約は、重要な構造の単純化です。 最適なソリューションは、サイズ 1、サイズ 2、またはサイズ 3 の 3 つのケースに分類できます。各ケースにおいて、少なくとも 1 つの要素が配列内の最大数の値の中に含まれている必要があります。 それ以外の場合は、より大きな互換性のある値に置き換えると、制約を破ることなく合計が増加するか、割り算の単調性により有効なままになります。 

これにより、すべての要素ではなく小さな候補フロンティアに注意を限定することができ、除数構造により互換性チェックが高速に行われることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

MAXV = 200000

def solve():
    q = int(input())
    for _ in range(q):
        n = int(input())
        a = list(map(int, input().split()))

        freq = {}
        mx = 0
        for x in a:
            freq[x] = freq.get(x, 0) + 1
            if x > mx:
                mx = x

        vals = sorted(freq.keys(), reverse=True)

        best_single = mx

        best_pair = 0

        # Try all pairs in value space
        for i in range(len(vals)):
            x = vals[i]
            for j in range(i + 1, len(vals)):
                y = vals[j]
                if x % y != 0 and y % x != 0:
                    best_pair = max(best_pair, x + y)
                    break  # next x, since y is decreasing

        best_triple = 0

        # Try triples with top candidates
        top = vals[:min(60, len(vals))]

        for i in range(len(top)):
            x = top[i]
            for j in range(i + 1, len(top)):
                y = top[j]
                if x % y == 0 or y % x == 0:
                    continue
                for k in range(j + 1, len(top)):
                    z = top[k]
                    if x % z == 0 or z % x == 0:
                        continue
                    if y % z == 0 or z % y == 0:
                        continue
                    best_triple = max(best_triple, x + y + z)

        print(max(best_single, best_pair, best_triple))

if __name__ == "__main__":
    solve()
```このソリューションでは、問題を 1 つ、2 つ、または 3 つの要素の選択に対応する 3 つの独立した最適化レイヤーに分割します。 単一のケースは些細なものです。 ペアの場合は、ソートされた値と早期停止を利用します。 合計の最大化に関連するのは最大値のみであり、すべてのトリプルのチェックはこの縮小されたサブセットに対してのみ実行可能であるため、トリプルの場合は制限された候補セットに制限されます。 

割り算チェックは値に対して直接行われるため、重い前処理構造の構築が回避されます。

 ## 特殊なケース

 重要なエッジケースは、最大の要素が長い分割可能性の連鎖の一部である場合です。 たとえば、次のようなセットでは、`2, 4, 8, 16`、最大値を選択すると、常に 2 番目の選択ができなくなります。 アルゴリズムは、最大値を強制的に含めるのではなく、より小さい互換性のある組み合わせと比較することによってこれを処理します。 

もう 1 つのエッジ ケースは、最適なソリューションが 1 つの大きな値とその他の値ではなく、3 つの中間の値である場合です。 2 番目のサンプルは、この動作を示しています。最適なトリプルは互換性をブロックするため、最大値を回避します。 制限されたトリプル列挙により、そのような組み合わせが上位候補間で引き続きチェックされることが保証されます。
