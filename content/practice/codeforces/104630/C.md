 ## 解決策
 ## 問題の理解

 すでにくさび形にカットされた円形のパンケーキがいくつか渡されます。 各ピースにはある程度の角のサイズがあり、放射状のカットを行うことで任意のピースをさらに分割することができます。 カットには既存のアングルのスライスが 1 つ含まれます$X$それを 2 つのスライスに分割し、角度の合計は次のようになります。$X$、任意の実分割点が許可されます。 

目標は奉仕することです$D$ダイナー。 すべてのダイナーは正確に 1 つのスライスを受け取る必要があり、提供されるすべてのスライスはまったく同じ角度サイズでなければなりません。 目標サイズを自由に選択できますが、一度選択したら、提供されるすべての部分がそのサイズに正確に一致する必要があります。 余った部分は廃棄させていただく場合がございます。 

操作コストは実行されたカットの数です。 カットするごとにピースの数が1つずつ増えます。 少なくとも取得するために必要なカットの総数を最小限に抑えたいと考えています。$D$単一の共通サイズのスライス。 

入力サイズは 2 つの状況を示唆しています。 スライスの数$N$ほとんどの場合は最大 300 ですが、一部の隠れたケースでは最大 10000 です。 ディナーの人数$D$これは、ソリューションが切断を明示的にシミュレートするのではなく、候補となるターゲット スライス構造を反復処理し、実現可能性を効率的に評価する必要があることを強く示しています。 スライスを分割するあらゆる方法に対する総当たり検索は、両方の点で指数関数的です。$N$そして限界をはるかに超えたカット数。 

微妙なエッジ ケースは、現在のスライスにすでに複数の同じサイズの断片が含まれているものの、十分ではない場合です。 たとえば、すでに等しいスライスが 2 つあるが、ダイナーが 3 人必要な場合、既存のスライスの 1 つをさらに分割するか、完全に異なるサイズを再ターゲットするかどうかを決定する必要があります。 もう 1 つのエッジ ケースは、1 つの大きなスライスを多くの等しい部分に最適に分割できるが、その場合、複数の中程度のスライスを組み合わせるよりも必要なカット数が少なくなる場合です。 

重要な問題は、提供される総面積を最大化することが求められるのではなく、提供されるすべてのピースが同じサイズになるように強制することです。これにより、グローバルな目標値を通じてすべてのスライスが結合されます。 

## アプローチ

 素朴なアプローチは、ターゲットのスライス サイズを選択し、各パンケーキのスライスからそれを取得する方法をシミュレートしようとすることです。 固定ターゲットサイズの場合$x$、サイズの元の各スライス$A_i$に分割できます$\lfloor A_i / x \rfloor$使用可能なピースと必要なもの$\lfloor A_i / x \rfloor - 1$最適に分割したと仮定して、それらの部分を生成するためにカットします。 すべてのスライスで使用可能なピースの合計が少なくとも$D$、 それから$x$実現可能です。 

難しいのは、正しいターゲットが$x$は知られていない。 ただし、有効な解決策は、次の形式のターゲット サイズの選択に対応している必要があります。$A_i / k$ある整数に対して$k$というのは、すべての最終的な部分は、元のスライスを均等に細分化することで得られるからです。 これにより、検索スペースが大幅に削減されます。連続値の代わりに、各スライスから得られる分割候補を考慮するだけで済みます。 

各ペアごとに$(A_i, k)$、 どこ$k \in [1, D]$、治療できます$x = A_i / k$ターゲットサイズの候補として。 その候補について、各スライスが寄与できるピースの数と、必要なカットの数を計算します。 次に、すべての候補の最小値を取得します。 

主な改善点は、最適なソリューションでは、元の各部分内でスライス分割が常に均一に配置されることを認識していることです。つまり、均一な分割を超えてスライスを不規則に部分的に再利用する必要がありません。 これにより、問題は連続的な最適化から離散的な列挙にまで軽減されます。$N \cdot D$候補サイズ。

 ## アルゴリズムのチュートリアル

 既存のパンケーキから得られるすべての妥当なターゲット スライス サイズを評価します。 候補ごとに、同じピースをいくつ形成できるか、およびカットのコストを計算します。 

1. スライスごとに$A_i$可能な限りの個数を考慮します$k$1から$D$。 これを、最終的なスライス サイズが次のようになることを提案しているものとして扱います。$x = A_i / k$。 最適なソリューションでは、少なくとも 1 つの元のスライスを最終サイズに一致する等しいセグメントに分割する必要があるため、これで十分です。 
2. 各候補値について$x$、すべての元のスライスから取得できるスライスの数を計算します。 サイズのスライス$A_j$貢献する$\lfloor A_j / x \rfloor$使えるパーツたち。 スライスを分割するたびに、$m$部品、必要です$m - 1$カット。 
3. すべてのスライスにわたる使用可能なピースの合計数を累積します。 この合計が以下の場合$D$、この候補は無効であり、破棄されます。 
4. 有効な場合、すべてのスライスの値を合計することで、必要なカットの合計数を計算します。$\lfloor A_j / x \rfloor - 1$少なくとも 1 つの部分に寄与するスライスの場合。 
5. すべての有効な候補者から最小カット数を取得します。 

これらの候補のみを評価する背後にある理由は、最適なソリューションでは、少なくとも 1 つの元のスライスが、最終的に選択されたサイズに正確に一致する等しいセグメントに分割され、そのスライスが構成全体の粒度を決定するためです。 

### なぜ効果があるのか

 最終的なピースサイズで最適なソリューションを修正する$x$。 少なくとも 1 つの最終ピースに貢献するオリジナルのスライスを考えてみましょう。 そのスライスは、整数の同じサイズのセグメントに分割する必要があります。$x$、 それで$x = A_i / k$ある整数に対して$k$。 したがって、すべての最適な解決策は、列挙した候補セットで表されます。 このような構成ごとにコストを明示的に評価するため、最適な構成を見逃すことはありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    T = int(input())
    for tc in range(1, T + 1):
        N, D = map(int, input().split())
        A = list(map(int, input().split()))

        INF = 10**30
        ans = INF

        for i in range(N):
            for k in range(1, D + 1):
                x = A[i] / k
                total_pieces = 0
                cuts = 0

                for a in A:
                    m = int(a // x)
                    if m > 0:
                        total_pieces += m
                        cuts += m - 1

                if total_pieces >= D:
                    ans = min(ans, cuts)

        print(f"Case #{tc}: {ans}")

if __name__ == "__main__":
    solve()
```実装は候補列挙のアイデアに直接従います。 各入力スライスを整数で除算して導き出される、考えられるすべてのターゲット スライス サイズをテストします。$D$。 このようなターゲットごとに、整数除算を使用して各スライスがいくつのピースを生成できるかをシミュレートします。 

内側のループでは、実現可能性とコストの両方が考慮されます。 実現可能性には少なくとも蓄積が必要$D$個。 カット数は、スライスを次のように分割するという観察から得られます。$m$同等の部品には常にコストがかかります$m - 1$カットの順番に関係なくカットします。 

微妙な点は、浮動小数点除算です。$x$。 より慎重な実装では、精度の問題を回避するためにこれが有理演算に置き換えられますが、ここでは通常、制約と整数構造により比較が安定します。 実稼働グレードのソリューションでは、代わりに整数演算またはストアを使用してスケーリングと比較を行います。$k / A_i$比率。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    T = int(input())
    out = []
    for tc in range(1, T + 1):
        N, D = map(int, input().split())
        A = list(map(int, input().split()))

        INF = 10**30
        ans = INF

        for i in range(N):
            for k in range(1, D + 1):
                x = A[i] / k
                total = 0
                cuts = 0
                for a in A:
                    m = int(a // x)
                    total += m
                    cuts += max(0, m - 1)
                if total >= D:
                    ans = min(ans, cuts)

        out.append(f"Case #{tc}: {ans}")

    return "\n".join(out)

 ## 特殊なケース

 一般的な失敗モードは、可能な限り最大の部分を貪欲に取得することが常に機能すると想定していることです。 たとえば、スライスの場合`[8, 4]`そして`D = 3`、貪欲なアプローチでは、8 を 4+4 として取り、4 を無視する可能性がありますが、最適な解決策には、両方のスライスと完全に位置合わせされる、同じ 4 サイズのピースが正確に 3 つ必要です。 アルゴリズムは候補サイズ 4 を評価し、合計寄与度をカウントするため、これを正確に捕捉します。 

もう 1 つのエッジ ケースは、複数の候補サイズで同じ数のピースが得られるが、カット コストが異なる場合です。 たとえば、12 のスライスは、選択したターゲットに応じて 3+3+3+3 または 4+4+4 に分割できます。 どちらも十分な枚数が得られますが、カット数が異なります。 両方とも異なるものに対応するため、列挙により両方が評価されることが保証されます。$k$の値$A_i / k$、最小値が選択されます。
