 **タグ:** 貪欲、並べ替え
 **解決時間:** 2 分

 ## 解決策
 ## 問題の理解

 どの位置がロックされ、どの位置がロック解除されているかを記述する配列と 2 番目のバイナリ配列があります。 

ロックされた位置は元の値を維持する必要があります。 ロック解除された位置は、元々ロック解除された位置に属していた任意の値を受け取ることができます。 言い換えれば、ロックされていないインデックスにある値を自由に並べ替えることができますが、ロックされた値は永久に固定されます。 

このような再配置を選択した後、結果の配列のプレフィックスの合計を調べます。 させて$k$プレフィックスの合計が負である最後の位置になります。 すべてのプレフィックスの合計が負でない場合、$k=0$。 

私たちの仕事は、有効な再配置を生成することです。$k$できるだけ小さいもの。 

制約から分かる重要な点は次のとおりです。$n\le100$。 これは小さいとはいえ、ロックされていないポジションの数も 100 近くになる可能性があり、すべての順列を試すには最大で 100 個が必要になります。$100!$可能性はありますが、それは完全に不可能です。 

課題は、最後の負のプレフィックスを最小限に抑える配置を理解することです。 

微妙な点は、非負のプレフィックスの数を最大化するように求められていないことです。 最後の負の接頭辞の位置のみを考慮します。 ロックされた負の値が早期に表示され、変更できないため、プレフィックスを負のままにする必要がある場合があります。 

もう 1 つの簡単な間違いは、プレフィックスの合計の実際の値がグローバルに重要であると考えることです。 唯一の自由はロックが解除された位置から得られるため、できるだけ早い段階でプレフィックスをできるだけ大きくするためにこれらの値を配置する方法に焦点を当てる必要があります。 

考慮する：```
a = [-8, 4, -2, -6, 4, 7, 1]
l = [ 1, 0,  0,  0, 1, 1, 0]
```最初の要素はロックされており、最初の接頭辞はすでに負になっています。 それを修正することはできません。 最善の戦略は、利用可能な最大のロック解除値をできるだけ早く配置して、マイナスの残高をできるだけ早く回復することです。 

すべての位置がロックされている場合、別のエッジ ケースが発生します。```
a = [2, -3, 4, -1]
l = [1,  1, 1,  1]
```再配置は許可されません。 答えは元の配列とまったく同じでなければなりません。 

3 番目のエッジケースは、すべてのポジションがロック解除されている場合です。```
a = [0, 1, -4]
l = [0, 0,  0]
```最適な配置は次のとおりです。```
[1, 0, -4]
```最初に大きな値を設定すると、すべてのプレフィックスの合計が最大になり、負のプレフィックスが持続できる期間が最小限になります。 

## アプローチ

 ブルートフォースソリューションでは、ロックされていない位置のすべての値を収集し、考えられるすべての順列を生成し、配列を再構築し、そのプレフィックスの合計を計算し、対応する値を決定します。$k$、最適な配置を維持します。 

これは、あらゆる法的整理を調査するものであるため、正しいです。 残念ながら、もしあるとしたら、$m$ロックされていないポジションの場合は、$m!$順列。 たとえ$m=15$、これはすでに実用的な限界をはるかに超えています。 

重要な観察は、実際には特定のプレフィックスを気にしていないということです。 私たちは、プレフィックスの合計ができるだけ早く非負になるようにすることに気を配っています。 

ロックされていない位置だけを見てみましょう。 2 つのロックが解除された位置の場合$i<j$値を含む$x<y$、次に配置します$y$前の位置では、その位置からすべてのプレフィックスの合計が増加します$i$までに$y-x$。 値を大きくすると、以前に配置された場合、将来のすべてのプレフィックスが有効になります。 

これは、降順での並べ替えがすべての部分和を最大化することを証明するために使用される交換引数とまったく同じです。 

ロックされていない値を任意に配置します。 以前にロック解除された位置に、後のロック解除された位置よりも小さい値が含まれている場合、それらを交換しても将来のプレフィックス合計を減らすことはできません。 このプロセスを繰り返すと、最終的にロック解除された値が降順で生成されます。 

この配置により、すべてのプレフィックスの合計が同時に最大化されます。 すべてのプレフィックスはできる限り大きいため、負のプレフィックスはできるだけ早く消え、負のプレフィックスを持つ最後の位置が最小限に抑えられます。 

したがって、解決策は非常に簡単です。 

1. ロックされていない位置からすべての値を抽出します。 
2. 降順に並べ替えます。 
3. 配列を左から右に走査します。 
4. ロックされていない位置が見つかったら、次に利用可能な値をそこに置きます。 

### 比較

 | アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース |$O(m!\cdot n)$|$O(m)$| 遅すぎる |
 | 最適 |$O(n\log n)$|$O(n)$| 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列とロックステータス配列を読み取ります。 
2. 位置がロックされていない、つまりロック値が 0 であるすべての値を収集します。 
3. このコレクションを降順に並べ替えます。 

初期の位置ほど多くのプレフィックス合計に寄与するため、最大のロック解除値は最も初期のロック解除位置に表示される必要があります。 
4. アレイを左から右にスキャンします。 
5. ロック位置が見つかった場合は、その値を変更しないでください。 
6. ロックされていない位置が見つかったら、ソートされた降順リストから次の値を取得して、そこに配置します。 
7. 結果の配列を出力します。 

### なぜ効果があるのか

 ロックされていない 2 つの位置を考慮します$i<j$。 の値が$i$の値より小さいです$j$、それらを交換すると、位置を含むすべてのプレフィックスの合計が増加します$i$しかしまだ位置が決まっていない$j$、後のプレフィックスは変更しないままにします。 プレフィックスの合計は減少しません。 

したがって、ロックされていない位置の降順でソートされていない配置は、そのような交換によって改善できます。 この引数を繰り返し適用すると、降順の配置になります。 

降順の配置では、すべての法的な再配置の中ですべてのプレフィックスの合計が最大になります。 各プレフィックスの合計は個別にできるだけ大きくなるため、プレフィックスの合計が負でなくなる点はできるだけ早く発生します。 したがって、結果として得られる値は、$k$最小限です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        l = list(map(int, input().split()))

        free = []

        for i in range(n):
            if l[i] == 0:
                free.append(a[i])

        free.sort(reverse=True)

        ptr = 0

        for i in range(n):
            if l[i] == 0:
                a[i] = free[ptr]
                ptr += 1

        print(*a)

solve()
```最初の部分では、ロックされていない位置にあるすべての値が収集されます。 

降順で並べ替えると、上記で証明された貪欲な選択が実装されます。 利用可能な最大値は常に、利用可能な最も早いロック解除位置に割り当てられます。 

再構築フェーズでは、元のアレイを調べます。 ロックされた位置は変更されません。 ロックされていない位置は、ソートされたリストから順番に値を受け取ります。 

プレフィックスの合計を明示的に計算する必要はありません。 この証明は、すべてのプレフィックスの合計を最大化することは、最後の負のプレフィックスを最小化することと同等であることを示しています。 

すべての値は Python 整数内に快適に収まるため、オーバーフローは心配ありません。

# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    input = sys.stdin.readline

    t = int(input())
    out = []

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        l = list(map(int, input().split()))

        free = [a[i] for i in range(n) if l[i] == 0]
        free.sort(reverse=True)

        ptr = 0
        for i in range(n):
            if l[i] == 0:
                a[i] = free[ptr]
                ptr += 1

        out.append(" ".join(map(str, a)))

    return "\n".join(out)

 ## 特殊なケース

 すべての位置がロックされている場合を考えてみましょう。```
n = 4
a = [2, -3, 4, -1]
l = [1, 1, 1, 1]
```ロック解除されたセットは空です。 並べ替えも再構築も何も行わず、アルゴリズムは元の配列を出力します。 これが唯一の法的な答えです。 

すべての位置がロック解除されている場合を考えてみましょう。```
n = 3
a = [0, 1, -4]
l = [0, 0, 0]
```このアルゴリズムはすべての値を抽出し、次のように並べ替えます。```
[1, 0, -4]
```そしてそれらを元に戻します。 他の配置では、この配置の対応するプレフィックスの合計よりも大きくないプレフィックスの合計が得られます。 

強制的な負の接頭辞を考えてみましょう。```
n = 3
a = [-10, 8, 7]
l = [1, 0, 0]
```最初の値はロックされているため、最初のプレフィックスは常に$-10$。 このアルゴリズムは、ロックされていない値を次のように分類します。```
[8, 7]
```得られるもの:```
[-10, 8, 7]
```プレフィックスの合計は次のようになります。```
-10, -2, 5
```最後の負のプレフィックスは位置 2 にあります。利用可能な最大の値が可能な限り早い段階ですでに使用されているため、これ以上の再配置はできません。 

最後に、重複したロック解除された値を考慮します。```
n = 5
a = [3, 3, -1, -1, 2]
l = [0, 0, 0, 0, 1]
```並べ替えると次のものが生成されます。```
[3, 3, -1, -1]
```再構成は、値が繰り返されても有効なままです。 証明は相対的な順序付けのみに依存し、一意性には依存しません。
