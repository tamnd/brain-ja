 ## 解決策
 ## 問題の理解

 モンスターの強さには固定のマルチセットがあります。 クエリごとに、シールドは耐久性から始まります`a`そして防御値`b`。 モンスターは均一にランダムな順序で戦います。 

以上の強さを持つモンスター`b`耐久ポイントを 1 消費しますが、ダメージは与えられません。 弱いモンスターは耐久力がプラスのまま何もしません。 耐久力がゼロになると、残りのモンスターはすべてその強さに等しいダメージを与えます。 

この質問では、考えられるすべての注文に対して予想される合計損害額を尋ねます。 

限界は大きい。 モンスター数もクエリ数も到達`2·10^5`, したがって、二次関数はすべて絶望的です。 すべてのクエリを線形時間で処理する場合でも、約`4·10^10`操作。 周りに何かが必要です`O((n+m) log n)`。 

最初の微妙なケースは、シールドを使い果たすほどの強力なモンスターが存在しない場合に発生します。```
3 1
1 2 10
5 100
```少なくとも強さを持ったモンスターはいない`100`, そのため耐久性が低下することはありません。 ダメージは常にゼロ、答えは`0`。 強いモンスターの数で割るような不用意な計算式ではクラッシュしてしまいます。 

強力なモンスターの数と耐久性が等しい場合、別のトリッキーな状況が発生します。```
4 1
1 2 5 8
2 5
```強いモンスターは、`5`そして`8`。 彼らはちょうど 2 耐久ポイントを消費し、その後の耐久力は残りませんが、攻撃できる強力なモンスターは残っていません。 弱いモンスターだけが残るので、予想されるダメージは`1+2=3`。 シールドブレイク後にすべてのモンスターを平等に扱うとオーバーカウントになってしまいます。 

重複も重要です。```
3 1
7 7 7
1 7
```ちょうど 1 匹のモンスターが耐久性を消費し、他の 2 匹がダメージを与えます。 予想されるダメージは常に`14`、個別の値の平均ではありません。 多重度を正しく並べ替えて使用すると、この間違いを回避できます。 

## アプローチ

 ブルートフォースの見方は簡単です。 1 つのクエリに対して、すべてを列挙します`n!`命令を出し、戦闘をシミュレーションし、結果として生じる損害を平均します。 これは数学的には正しいですが、法外に高価です。 

順列列挙を確率計算に置き換えて、各クエリを独立して処理することもできます。`O(n)`遅すぎます。 と`2·10^5`クエリの場合、これはおおよそ次のようになります`4·10^10`操作。 

重要な観察は、少なくとも強さを持ったモンスターのみであるということです。`b`耐久性に影響します。 あると仮定します`k`そんなモンスターたち。 もし`k<a`、シールドは壊れず、答えはゼロです。 

仮定する`k≥a`。 強いモンスターを1体考えてみましょう。 その中で、`k`強力なモンスターの場合、すべての相対的な順序は同様に発生します。 シールドは最初に生き残ります`a`強力なモンスターとその直後にブレイクします。 特定の強力なモンスターは、位置の後に出現したときに正確にダメージを与えます`a`その中で`k`モンスター。 

その出来事の確率は以下に等しい$$\frac{k-a}{k}.$$弱いモンスターは耐久力を消費しません。 シールドが使い果たされたら、`a`強いモンスターが出現した後、弱いモンスターが出現するたびにダメージを与えます。 弱いモンスターと強いモンスターがランダムに混在するため、限界点以降に出現する確率は次のようになります。$$\frac{k-a+1}{k+1}.$$これらの確率は以下にのみ依存します。`k`、個人の力ではありません。 強さをソートし、プレフィックスの合計を構築した後、対数時間で強い強さと弱い強さの合計を取得できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n!・n) | O(n) | 遅すぎる |
 | 最適 | O((n+m) log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.モンスターの強さを並べ替えます。 
2. 接尾辞または接頭辞の合計を一定時間で取得できるように接頭辞の合計を作成します。 
3. お問い合わせの場合`(a,b)`、値が少なくとも次の最初の位置を二分探索します。`b`。 
4. しましょう`k`少なくとも強さを持ったモンスターの数であること`b`。 

まさに耐久力を消費するモンスターたちだ。 
5. もし`k<a`、出力`0`。 

シールドの耐久性がゼロになることはありません。 
6. 強いモンスターの合計を計算します。`Sstrong`と弱いモンスターの合計は、`Sweak`。 
7. すべての強力なモンスターが確率で貢献します`(k-a)/k`。 

彼らの期待される貢献は次のとおりです$$S_{strong}\cdot\frac{k-a}{k}.$$1. すべての弱いモンスターが確率で貢献します`(k-a+1)/(k+1)`。 

彼らの期待される貢献は次のとおりです$$S_{weak}\cdot\frac{k-a+1}{k+1}.$$1. 2 つの寄与を加算し、すべてを剰余演算します。`998244353`。 

### なぜ効果があるのか

 強力なモンスターの場合、耐久力の消費には相対的な順序のみが重要です。 まさに最初の`a`強力なモンスターをブロックし、残りのモンスターをブロックします。`k-a`シールドが壊れた後、強力なモンスターが攻撃します。 対称性はそれぞれの強力なモンスターの確率を与える`(k-a)/k`。 

ブレークポイントは直後に発生します。`a`-番目に強いモンスター。 弱いモンスターは、どの領域にも同じように占有される可能性があります。`k+1`強いモンスターの周りの隙間。 がある`k-a+1`ブレークポイント後のギャップ、確率を与える`(k-a+1)/(k+1)`。 すべてのモンスターに対するこれらの独立した期待値を合計すると、正しい期待ダメージが得られます。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

MOD = 998244353

n, m = map(int, input().split())
d = list(map(int, input().split()))

d.sort()

pref = [0]
for x in d:
    pref.append(pref[-1] + x)

inv = [1] * (n + 2)
for i in range(2, n + 2):
    inv[i] = pow(i, MOD - 2, MOD)

total_sum = pref[n]

ans = []

for _ in range(m):
    a, b = map(int, input().split())

    pos = bisect_left(d, b)
    k = n - pos

    if k < a:
        ans.append("0")
        continue

    strong_sum = total_sum - pref[pos]
    weak_sum = pref[pos]

    p_strong = (k - a) * inv[k] % MOD
    p_weak = (k - a + 1) * inv[k + 1] % MOD

    res = (
        strong_sum % MOD * p_strong
        + weak_sum % MOD * p_weak
    ) % MOD

    ans.append(str(res))

print("\n".join(ans))
```ソートされた配列により、二分検索で各クエリの強力なモンスターを特定できます。 プレフィックスの合計により、配列をスキャンせずに両方のグループの合計強度が得られます。 

条件`k<a`確率を計算する前に処理する必要があります。 そうしないと、負の分子が誤って割り当てられてしまいます。 

弱い確率は以下を使用します`k+1`分母ではなく`k`。 これが最も一般的な間違いの原因です。 強いモンスターの周りの隙間に弱いモンスターが挿入され、強いモンスターよりも隙間が1枚多くなります。 

法が素数であるため、すべての除算は逆モジュラーで実装されます。

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |

import sys, io
from bisect import bisect_left

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    MOD = 998244353

    n, m = map(int, input().split())
    d = list(map(int, input().split()))
    d.sort()

    pref = [0]
    for x in d:
        pref.append(pref[-1] + x)

    total_sum = pref[n]
    inv = [1] * (n + 2)
    for i in range(2, n + 2):
        inv[i] = pow(i, MOD - 2, MOD)

    out = []

    for _ in range(m):
        a, b = map(int, input().split())
        pos = bisect_left(d, b)
        k = n - pos

        if k < a:
            out.append("0")
            continue

        strong_sum = total_sum - pref[pos]
        weak_sum = pref[pos]

        p1 = (k - a) * inv[k] % MOD
        p2 = (k - a + 1) * inv[k + 1] % MOD

        val = (
            strong_sum % MOD * p1
            + weak_sum % MOD * p2
        ) % MOD

        out.append(str(val))

    return "\n".join(out)

 ## 特殊なケース

 強いモンスターがいない場合は、```
3 1
1 2 10
2 100
```二分探索は与える`k=0`。 以来`0<2`、アルゴリズムはすぐに出力します`0`。 確率計算は実行されません。 

強いモンスターの数が耐久力と同じになると、```
4 1
1 2 5 8
2 5
```私たちは得る`k=2`。 強い確率がゼロになるのは、`k-a=0`。 弱いモンスターが確率で貢献する`1/3`、予想されるダメージを生み出す$$(1+2)\cdot\frac13=1.$$すべての値が同一の場合、```
3 1
7 7 7
1 7
```すべてのモンスターは強いグループに属します。 ここ`k=3`、強和は`21`、各モンスターは確率で貢献します`2/3`。 期待されるダメージは次のとおりです`14`。 並べ替えではすべてのコピーが保持されるため、重複した強度は自然に処理されます。
