 ## 解決策
 ## 問題の理解

 我が家には普通の壁コンセントが 2 つと、電気スプリッターが 1 つあります。 各スプリッターには、使用可能なソケットを消費するプラグが 1 つと、それ自体のソケットが 3 つあるため、1 つのスプリッターを接続すると、空きソケットの合計数がちょうど 2 つ増加します。 スプリッタは壁に直接接続することも、別のスプリッタのソケットに接続することもできるため、スプリッタは接続の任意のツリーを形成できます。 

入力には以下が含まれます`n`、電力を供給する必要があるラップトップの数、および`k`、すでに利用可能なスプリッターの数。 追加購入するスプリッターの最小数が必要です。`n`ソケットはラップトップ用に引き続き使用できます。 

制約により両方が許可されます`n`そして`k`と同じくらい大きくなる`10^9`。 これにより、ラップトップごとまたはスプリッターごとに 1 回の反復を実行するシミュレーションが除外されます。 線形アルゴリズムであっても、最悪の場合には約 5 億回の反復が必要になる可能性があり、これは 1 秒の制限がサポートできる範囲をはるかに超えています。 意図した解決策では、問題を定数時間の演算に削減する必要があります。 

簡単にオフバイワンエラーを引き起こす可能性のある小さな境界ケースがいくつかあります。 もし`n = 1`2 つの元の壁ソケットですでに十分なので、`k = 0`答えは`0`、 ない`1`。 もし`n = 2`、両方の元のソケットを直接使用できるため、答えは再び次のとおりです。`0`。 例えば、`2 0`生産しなければならない`0`。 

ラップトップの数が奇数の場合、別の境界ケースが発生します。 のために`n = 3`そして`k = 0`、スプリッターは 1 つで十分です。それを 1 つの壁コンセントに接続し、その 3 つのソケットをラップトップ用に使用し、もう 1 つの壁コンセントは使用しないままにします。 答えは`1`。 通常の整数除算を使用した不用意な数式`(n - 2) / 2`切り上げを行わないと、誤って取得されてしまいます。`0`。 

既存のスプリッターも、実際に必要なスプリッターの数を決定した後でのみ減算する必要があります。 のために`n = 6`そして`k = 3`、必要なスプリッターは 2 つだけなので、答えは次のようになります。`0`。 プラスの購入数をゼロに固定せずにやみくもに計算する式では、マイナスの答えが得られる可能性があります。 

## アプローチ

 直接シミュレーションは、2 つの使用可能なソケットから開始し、1 つのスプリッターを繰り返し追加できます。 新しいスプリッターはそれぞれ既存のソケットを 1 つ消費し、新しいソケットを 3 つ提供するため、空きソケットの数は 2 つ増加します。 少なくとも`n`ソケットを解放してから、`k`すでに所有されているスプリッター。 これは正しいです。どのスプリッターも、使用可能なラップトップ接続の数に対してまったく同じ影響を与えるからです。 

このアプローチの問題は反復回数です。 と`n = 10^9`そして`k = 0`、必要です`499,999,999`スプリッター。 シミュレーションではおよそ 5 億回の反復が実行されますが、これでは指定された制限時間内では遅すぎます。 

重要な点は、使用後の空きソケットの数です。`t`スプリッターはすぐにわかります。 2 つのソケットから開始し、スプリッターごとにさらに 2 つ追加するため、容量は次のようになります。`2 + 2t`。 

少なくともこの量が必要です`n`。 不等式を解くと、`2 + 2t >= n`。 

したがって`t >= (n - 2) / 2`、

 そしてそれ以来`t`整数でなければならないので、その値の上限が必要です。 正の整数の場合`n`、この天井は特に単純な形をしています。`ceil((n - 2) / 2) = (n - 1) // 2`。 

これも扱います`n = 1`正しく、なぜなら`(1 - 1) // 2 = 0`。 

させて`required = (n - 1) // 2`必要なスプリッターの合計数になります。 以来`k`そのうちの数はすでに入手可能です。購入する必要がある数は`required - k`, ただしマイナスにはできません。 したがって、最終的な答えは、`max(0, required - k)`。

 ## アルゴリズムのチュートリアル

 1.読む`n`、ラップトップの数、および`k`、すでに所有されているスプリッターの数。 すべてのスプリッターは同じように動作するため、これら 2 つの値のみが答えに影響します。 
2. すでに使用可能なスプリッタがない場合に必要となるスプリッタの合計数を計算します。`required = (n - 1) // 2`。 

これは、最初に 2 つの壁ソケットが利用可能であり、各スプリッターによって空きソケットの数が 2 つずつ増加するという事実から来ています。 
3. すでに所有しているものを差し引きます`k`からのスプリッター`required`。 結果が負の場合は、すでに入手可能なスプリッターを購入する必要がないため、ゼロに置き換えます。 
4. 結果の数値を出力します。 

### なぜ効果があるのか

 正確に接続したら`t`スプリッター、電気設定には`2 + 2t`ラップトップ用の無料ソケット。 これは、スプリッタの接続方法に関係なく当てはまります。各スプリッタは既存のソケットを 1 つだけ消費し、新しいソケットを 3 つ作成し、純利益が 2 になるからです。 したがって、構成はすべてに電力を供給できます`n`ラップトップいつでも`2 + 2t >= n`。 最小の整数`t`この不等式を満たすのは、`(n - 1) // 2`。 もし`k`スプリッタはすでに所有されていますが、せいぜい`k`これらの必要なスプリッターを購入する必要はありません。`max(0, required - k)`。 これはスプリッタの合計の可能な最小数であり、すべてのスプリッタが同じ容量増加に寄与するため、計算された購入数は最適になります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, k = map(int, input().split())

    required = (n - 1) // 2
    answer = max(0, required - k)

    print(answer)

if __name__ == "__main__":
    solve()
```の最初の行`solve`2 つの整数を読み取ります。 テスト ケースは 1 つだけであるため、テスト ケースをループする必要はありません。 

表現`(n - 1) // 2`スプリッタの最小合計数を直接計算します。 この形式を使用すると、浮動小数点演算が回避され、偶数と奇数の両方が処理されます。`n`正しく。 たとえば、次のようになります。`1`のために`n = 3`、`1`のために`n = 4`、 そして`2`のために`n = 5`そして`n = 6`。 

の`max`この操作は、既存のコレクションにすでに十分なスプリッターが含まれている場合を処理します。 Python の整数には任意の精度があるため、次の値までの値が得られます。`10^9`特別なオーバーフロー処理は必要ありません。 

操作の順序は概念的に重要です。 まず、完全なインストールに必要なスプリッタの数を決定し、次にすでに所有しているスプリッタを考慮します。 これにより、境界ケースが作成されます`k > required`当然購入ゼロになります。

 ## 特殊なケース

 のために`n = 1`そして`k = 0`、式は次のようになります`required = (1 - 1) // 2 = 0`、したがって、答えは次のとおりです`0`。 2 つの壁コンセントはすでに十分な容量を備えています。 

のために`n = 2`そして`k = 0`、式は次のようになります`required = (2 - 1) // 2 = 0`。 どちらのラップトップも 2 つの元のソケットに直接接続できるため、スプリッターは必要ありません。 これは、次の式に基づくため、境界チェックに役立ちます。`ceil((n - 2) / 2)`もこの時点で正しく定義する必要があります。 

のために`n = 3`そして`k = 0`、式は次のようになります`required = 2 // 2 = 1`。 1 つのスプリッターをいずれかの壁面ソケットに接続すると、そのスプリッターに 3 つの使用可能なソケットが作成されるため、3 台のラップトップすべてに電力を供給できます。 出力は`1`、誤って丸める実装をキャッチします。`(n - 2) / 2`下向きに。 

のために`n = 6`そして`k = 3`、合計要件は`required = 5 // 2 = 2`。 すでに3つのスプリッターが用意されているため、`max(0, 2 - 3)`与える`0`。 余剰がマイナスの購入数になってはなりません。 

最大値については`n = 10^9`そして`k = 0`、計算は`required = 999,999,999 // 2 = 499,999,999`。 2 つの壁ソケットとスプリッターごとに得られる 2 つのソケットにより、正確に十分な容量が得られ、何億ものスプリッターの追加をシミュレーションすることなく、すぐに答えが得られます。
