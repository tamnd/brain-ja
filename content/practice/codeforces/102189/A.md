 ## 解決策
 ## 問題の理解

 この料理には野菜が2つ入っています。 最初の貢献者`X`グラムごとに気分の単位があり、`A`それのグラム。 2番目は貢献します`Y`グラムあたりの気分単位、`B`グラム。 合計の気分変化は、両方の野菜の寄与を単純に合計したものです。`A * X + B * Y`。 

最初の入力行は金額を示します。`A`そして`B`、2番目はグラムごとの気分の変化を示します`X`そして`Y`。 必要な出力は 1 つの整数、つまり料理をすべて食べた後の気分の変化の合計です。 否定的な答えは気分が低下することを意味し、肯定的な答えは気分が高まることを意味します。 

数量`A`そして`B`せいぜい`30000`、 そして`X`そして`Y`間に横たわる`-30000`そして`30000`。 1 つの野菜による最大の絶対的な貢献でさえ、`30000 * 30000 = 900000000`なので、合計の絶対結果は最大でも`1800000000`。 これは符号付き 32 ビット整数に収まりますが、Python 整数にはオーバーフローの問題はありません。 さらに重要なのは、制約には反復、検索、動的プログラミング、またはグラフ アルゴリズムが必要ないことです。 一定数の算術演算で十分です。 

主なエッジ ケースは、入力のサイズではなく、符号付きの値に由来します。 たとえば、```
2 3
2 -1
```答えは`2 * 2 + 3 * (-1) = 1`。 を扱う不注意な実装`Y = -1`正の大きさの場合は`7`、2番目の野菜が気分を下げるという事実を失います。 

2 番目のケースは、両方の気分の変化がネガティブな場合です。```
1 1
-30000 -30000
```正しい答えは、`-60000`。 乗算は次の符号を保存する必要があります。`X`そして`Y`; 計算する前に絶対値を取得すると、間違った結果が得られます。 

ゼロも有効な気分転換です。 のために```
30000 30000
0 30000
```正しい答えは`900000000`。 最初の野菜は、その量がゼロではないにもかかわらず、何も貢献しません。 すべての野菜の気分が変わることを前提とした実装では、このケースは誤って処理されるでしょう。 

最後に、最大値により、整数の境界に近い結果が生成される可能性があります。```
30000 30000
30000 30000
```正しい答えは、`1800000000`。 計算は、完全な結果を表すことができる整数型を使用して実行する必要があります。 

## アプローチ

 直接的なブルートフォース解釈では、すべてのグラムが個別に処理されます。 追加することもできます`X`答えに`A`回して追加します`Y`それに`B`回。 これは正しいです。すべてのグラムが独立して寄与するため、すべてのグラムが処理された後、アキュムレータには気分の変化全体が正確に含まれます。 

問題は、これが実行されることです`A + B`追加。 両方の金額が等しい場合、`30000`、つまり`60000`繰り返し。 この特定の問題では、60000 の操作は 1 秒の制限内で快適に実行できるほど小さいため、この総当たりバージョンが実際に受け入れられます。 それにもかかわらず、これは不必要な作業であり、問​​題の単純な数学的構造を曖昧にしてしまいます。 

重要な観察は、すべてが`A`最初の野菜のグラムはまったく同じ貢献をします。`X`。 追加する代わりに`X`繰り返し、それらの同一の貢献を製品に組み合わせることができます`A * X`。 同じ推論により、`B * Y`2番目の野菜に。 この2種類の野菜しか入っていないので、2品を足せば完成です。 

これにより、計算全体が 2 つの乗算と 1 つの加算に変わります。 この総当り攻撃は、すべての個々の寄与を明示的に合計するため機能しますが、多くの連続する寄与が同一であるという事実を利用できません。 この繰り返しを認識すると、繰り返される加算を乗算に置き換えることができます。

 ## アルゴリズムのチュートリアル

 1.読む`A`そして`B`, 2つの野菜の量。 これらの値は、最終的な気分の変化に各タイプが何グラム貢献するかを決定します。 
2.読む`X`そして`Y`、それぞれの野菜1グラムによって引き起こされる気分の変化。 それらは正、ゼロ、負のいずれかになる可能性があるため、その符号は保持される必要があります。 
3. コンピューティング`A * X`。 これにより、最初の野菜のすべてのグラムの同一の寄与が 1 つの乗算に結合されます。 
4. コンピューティング`B * Y`2番目の野菜も同じ理由で。 
5. 2 つの積を加算し、結果を出力します。 2 つの製品は料理の全グラムを占めるため、その合計がまさに全体的な気分の変化となります。 

### なぜ効果があるのか

 最初の野菜の寄与は次の合計です。`X`繰り返された`A`回、まさにその通りです`A * X`。 同様に、2 番目の野菜の寄与は、`B * Y`。 すべてのグラムはこれら 2 つのグループのいずれかに属するため、合計寄与度は正確に次のようになります。`A * X + B * Y`。 アルゴリズムはこの式を直接計算します。つまり、グラムを省略したり、1 を 2 回数えたりすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    A, B = map(int, input().split())
    X, Y = map(int, input().split())

    print(A * X + B * Y)

if __name__ == "__main__":
    solve()
```最初の入力操作で 2 つの量を読み取り、2 番目の入力操作でグラムごとの 2 つの気分の変化を読み取​​ります。`map(int, ...)`4 つの値はすべて、負の値を含む整数であるため、これで十分です。 

表現`A * X + B * Y`完全な数学的解決策です。 通常の符号付き整数演算ではすでに正、負、ゼロの寄与が正しく処理されているため、ループ、配列、再帰、または特殊なケースはありません。 

操作の順序も簡単です。 各量には、2 つの独立した寄与が加算される前に、対応するグラムごとの効果が乗算されます。 Python の任意精度の整数では、これらの制約によるオーバーフローは不可能ですが、最大結果はすでに符号付き 32 ビット整数に収まるほど十分に小さいです。

import sys
import io

def solve():
    input = sys.stdin.readline
    A, B = map(int, input().split())
    X, Y = map(int, input().split())
    print(A * X + B * Y)

def run(inp: str) -> str:
    old_stdin = sys.stdin
    old_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    try:
        solve()
        return sys.stdout.getvalue()
    finally:
        sys.stdin = old_stdin
        sys.stdout = old_stdout

# Provided samples
assert run("2 3\n2 -1\n") == "1\n", "sample 1"
assert run("1 1\n1 -2\n") == "-1\n", "sample 2"

# Minimum amounts, both positive contributions

# Maximum amounts and maximum positive effects

# Maximum amounts and maximum negative effects
assert run("30000 30000\n-30000 -30000\n") == "-1800000000\n", "minimum result"

# Zero contribution and mixed signs
assert run("30000 1\n0 -30000\n") == "-30000\n", "zero and negative contribution"

 ## 特殊なケース

 ある野菜が気分を低下させる場合、その野菜の寄与はマイナスのままでなければなりません。 のために```
2 3
2 -1
```最初の製品は`4`そして2つ目は`-3`、結果は次のようになります`1`。 このアルゴリズムは絶対値を取得したり、符号を変更したりすることはないため、マイナスの影響は自然に処理されます。 

両方の効果がマイナスの場合でも、同じ公式が適用されます。 のために```
1 1
-30000 -30000
```製品は`-30000`そして`-30000`、生産`-60000`。 整数の乗算ではすでに正しい符号が適用されているため、負の値に対する個別の分岐はありません。 

効果がゼロの場合も、特別な分岐を必要としないケースです。 と```
30000 30000
0 30000
```最初の製品は`0`、そして2番目は`900000000`。 結果は`900000000`。 アルゴリズムは、最初の野菜を気分に影響を与えないものとして正しく処理します。 

最大の正の境界では、```
30000 30000
30000 30000
```製品は両方です`900000000`、与える`1800000000`。 計算では、off-by-one 調整を行わずに完全な入力値が使用されます。`A`グラムは正確に貢献します`A`のコピー`X`。 

同じ境界が負の極値に対しても機能します。```
30000 30000
-30000 -30000
```どちらの製品も、`-900000000`、したがって、答えは次のとおりです`-1800000000`。 これにより、実装が符号を保持し、許可された数値範囲全体を処理していることが確認されます。
