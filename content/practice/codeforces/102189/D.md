 ## 解決策
 ## 問題の理解

 暗黙的な配列から始めます

 [
 [1,2,3,\ldots,n]。 
】

 プログラムは 2 種類の操作を一定間隔で実行します。 あ`reverse l r`この操作により、位置 (l) から (r) の要素の順序が変更されます。 アン`inverse l r`操作では、位置は変更されませんが、その間隔内のすべての値の符号が変更されます。 

すべての操作の後、必要なのは位置を占める値の 1 つだけです。`pos`。 最終的な配列自体は必要ありません。 

(n) の大きな値が主な手がかりとなります。 (n) は (10^9) に達する可能性があるため、長さ (n) の配列を割り当てることさえ不可能です。 さらに重要なのは、間隔のすべての要素を変更するには、1 つのコマンドで最大 (10^9) 個の操作が必要になる可能性があります。 (m) が (10^5) までの場合、直接シミュレーションでは (10^{14}) 個もの要素の更新が必要になる可能性があります。 解決策は、配列の長さまたは変更された間隔の長さに依存することを回避する必要があります。 

有益な観察は、最終的な 1 つの位置のみを考慮しているということです。 すべての要素がどのように前進するかを尋ねる代わりに、どの元の位置が最終的に要求された最終位置に到達するかを尋ねることができます。 逆演算は位置の単純な変換を行いますが、逆演算はその位置にある値の符号を変更するだけです。 

不注意な実装が露呈する可能性のある境界ケースがいくつかあります。 考慮する```
1 0
1
```唯一の要素は変更されないため、答えは次のようになります。`1`。 少なくとも 1 つの操作を前提とする実装、または符号を正しく初期化しない実装は、ここで失敗する可能性があります。 

シングルトンの反転も効果はありません。```
5 1
reverse 3 3
3
```答えは`3`。 変換 (l+r-pos) は (3+3-3=3) を与えるため、逆転を無条件に位置を変更するものとして扱うのは間違いです。 

操作は 1 つのエンドポイントにのみアクセスできます。```
5 1
inverse 1 5
5
```答えは`-5`。 半開間隔を誤って使用する実装では、位置 (5) が失われる可能性があります。 

最後に、同じ要素の複数の反転がペアでキャンセルされます。```
1 2
inverse 1 1
inverse 1 1
1
```答えは`1`、 ない`-1`。 逆演算が発生したかどうかを単に記憶するのではなく、該当するすべての逆演算に対して符号を切り替える必要があります。 

## アプローチ

 直接的なアプローチでは、配列を明示的に維持します。 のために`reverse l r`、対応するスライスを反転します。`inverse l r`の場合、スライス内のすべての要素に (-1) を乗算します。 これは、説明されている操作を正確に実行するため、正しいです。 

問題は配列のサイズです。 1 つの間隔には (n) 個の要素を含めることができ、最悪の場合、(m) 個の演算のすべてが配列全体をカバーする可能性があります。 結果として得られる仕事量は (O(nm)) であり、(10^9\cdot10^5=10^{14}) 個の要素演算に達することができます。 配列自体も (O(n)) メモリを必要としますが、(n=10^9) では不可能です。 

ブルート フォース ソリューションは、すべての要素を明示的に追跡するため機能しますが、実際にはその情報は必要ありません。 最終的に次の元の要素を特定するだけで済みます。`pos`そしてその最終的な兆候を決定します。 

現在、最終的な位置が次であることがわかっているとします。`p`、操作を逆方向に処理します。 区間 ([l,r]) の反転を考えてみましょう。 もし`p`この間隔の外側にある要素は、`p`この操作では動かされませんでした。 内側にある場合、反転前の位置は

 [
 l+r-p。 
】

 たとえば、位置 (2) から (5) を反転すると、位置 (2) から (5)、位置 (3) から (4)、位置 (4) から (3)、および位置 (5) から (2) がマッピングされます。 マッピングは正確に (p\mapsto l+r-p) であり、それを再度適用すると、元の位置が返されます。 

次に、逆演算を考えてみましょう。 何も動かないので、`p`は変わらないままです。 もし`p`ただし、その位置の値の符号が変わります。 これをブール フラグで記録し、そのような逆が発生するたびに切り替えることができます。 

すべての操作を逆方向に処理した後、追跡された位置は初期配列内の元の位置になります。 位置の初期値`p`単純に`p`したがって、最終的な答えは次のいずれかです。`p`または`-p`。 

これにより、各操作を 1 回だけ検査するだけで問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | (O(nm)) | (O(n)) | 遅すぎて、大きい (n) には不可能です。 
| 最適 | (O(m)) | (O(m)) | 承認済み |

 最適な方法の (O(m)) スペースは、操作を逆方向に処理できるように操作を保存するためにのみ使用されます。 実際の追跡状態自体は (O(1)) メモリを使用します。 

## アルゴリズムのチュートリアル

 1.読む`n`そして`m`、すべての (m) 個の操作を元の順序で保存します。 要求された最終位置を最初の配列に向かってトレースするため、後で逆の順序で操作を行う必要があります。 
2. 要求された最終位置を読み取ります`pos`。 最初は、これはまさにすべての操作後に値が必要な位置です。 
3. 符号変数を (+1) に設定します。 逆演算を検討する前に、追跡される値には元の符号が付いています。 
4. 保存された操作を最後の操作から最初の操作まで処理します。 
5. のために`reverse l r`操作では、現在追跡されている位置が ([l,r]) 内にあるかどうかを確認します。 そうでない場合、操作はその要素に影響を与えません。 そうなった場合は交換してください

 [
 pos \leftarrow l+r-pos。 
】

 これは、操作を逆にしているため機能します。 にある要素`pos`反転後は、反転前のミラー位置を占めている必要があります。 

1. のために`inverse l r`手術、出発`pos`変わらない。 もし`pos`([l,r]) に属する場合は、記号を切り替えます。 

[
 記号 \leftarrow -記号。 
】

 この操作では追跡対象の要素は移動されませんが、その値は無効になります。 

1. すべての操作が逆方向に処理された後、`pos`最終的に要求された位置に到達した元の配列の要素を識別します。 初期配列には値が含まれているため、`pos`位置にある`pos`、出力

 [
 署名\cdot pos.
 】

 ### なぜ効果があるのか

 すでに調べられた演算のサフィックスを逆に処理した後、`pos`は、要素が最終的に元の要求された最終位置に到達するサフィックスの直前の配列内の位置です。 反転の場合、影響を受ける位置はその間隔内のみであり、逆マッピングは正確に (l+r-pos) になります。 逆演算の場合、位置は変化しませんが、追跡される値は、その位置が区間に属するときに正確に符号が変わります。 したがって、不変条件は、逆のステップが実行されるたびに true のままになります。 すべての操作が処理されると、追跡された位置は初期配列を参照します。値はその位置に等しく、蓄積された符号はその要素に影響を与えるすべての反転を記録します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())

    operations = []

    for _ in range(m):
        typ, l, r = input().split()
        operations.append((typ, int(l), int(r)))

    pos = int(input())
    sign = 1

    for typ, l, r in reversed(operations):
        if l <= pos <= r:
            if typ == "reverse":
                pos = l + r - pos
            else:
                sign = -sign

    print(sign * pos)

if __name__ == "__main__":
    solve()
```操作リストには、操作タイプとその 2 つの境界が格納されます。 逆方向トラバーサル中に文字列を繰り返し解析するのではなく整数を保存することで、メイン ループが単純になります。 

重要な部分は`reversed(operations)`。 入力操作は最初から最後まで適用されますが、最後の位置を先頭に向かってトレースしているため、順序を逆にする必要があります。 

条件`l <= pos <= r`問題では閉じた間隔が定義されているため、両方のエンドポイントを使用します。 反転すると、`l + r - pos`、 ない`r - pos`またはゼロベースの同等のもの。 すべての位置は 1 から始まるため、数式を同じ座標系に保つことで、不必要な変換やオフバイワンエラーを回避できます。 

Python の整数には任意の精度があるため、(10^9) までの値とその負の値には特別なオーバーフロー処理は必要ありません。 

の値`n`入力が読み取られた後は、それ以外の場合は必要ありません。 これはまさに私たちが望んでいることです。アルゴリズムは巨大な初期配列を決して構築しません。 

## 実用的な例

 サンプル 1 の操作は次のとおりです。```
inverse 1 3
reverse 2 5
reverse 1 3
inverse 2 4
```そして要求された最終位置は`2`。 

下から上に向かって処理していきます。 

| 逆のステップ | 操作 | 現在`pos`| 現在`sign`| アクション |
 | --- | --- | --- | --- | --- |
 | 1 |`inverse 2 4`| 2 | +1 | 位置 2 は内側、トグルサイン |
 | 2 |`reverse 1 3`| 2 | -1 | 位置 2 は内側にあり、(1+3-2=2) にマップされます。 
| 3 |`reverse 2 5`| 2 | -1 | 位置 2 は内側にあり、(2+5-2=5) にマップされます。 
| 4 |`inverse 1 3`| 5 | -1 | 位置 5 は外側にあり、何もしません |

 で終わります`pos = 5`そして`sign = -1`、したがって、答えは次のとおりです`-5`。 ただし、これにより、表示されたサンプル テキストに書式設定の問題が含まれていることが明らかになります。最初のサンプルの指定された出力は次のように表示されます。`3 2`指定されたステートメントでは、実際の操作トレースは次で終了します。`(4, -5, 1, 3, -2)`。 ご希望のポジションについて`2`、そのトレースからの正しい値は次のとおりです。`-5`。 逆トレース法は、明示的なシーケンス変換と一致します。 

サンプル 2 の場合、```
3 2
reverse 1 2
inverse 2 3
2
```逆方向のトラバースはより簡単です。 

| 逆のステップ | 操作 | 現在`pos`| 現在`sign`| アクション |
 | --- | --- | --- | --- | --- |
 | 1 |`inverse 2 3`| 2 | +1 | 位置 2 は内側、トグルサイン |

最終的に追跡された元の位置は、`1`、負符号付き、与える`-1`。 これはサンプル出力と一致しており、操作を逆方向に処理する必要がある理由を示しています。 逆は、入力内で反転後に表示される場合でも、反転前の要素に影響します。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | (O(m)) | すべてのストアド操作は 1 回だけ検査されます。 
| スペース | (O(m)) | 操作は逆方向に実行できるように保存されます。 

(m\le10^5) の場合、アルゴリズムは約 (10^5) 回の定数時間チェックと変換のみを実行します。 (10^9) までの (n) の巨大な値は、配列が実体化されないため、実行時間や配列に必要なメモリに影響を与えません。 

## テストケース```python
import sys
import io

def solve():
    input = sys.stdin.readline

    n, m = map(int, input().split())
    operations = []

    for _ in range(m):
        typ, l, r = input().split()
        operations.append((typ, int(l), int(r)))

    pos = int(input())
    sign = 1

    for typ, l, r in reversed(operations):
        if l <= pos <= r:
            if typ == "reverse":
                pos = l + r - pos
            else:
                sign = -sign

    return sign * pos

def run(inp: str) -> str:
    old_stdin = sys.stdin
    sys.stdin = io.StringIO(inp)
    try:
        return str(solve())
    finally:
        sys.stdin = old_stdin

    """5 4
inverse 1 3
reverse 2 5
reverse 1 3
inverse 2 4
2
"""
) == "-5", "sample 1, explicit trace"

# Provided sample 2.
assert run(
    """3 2
reverse 1 2
inverse 2 3
2
"""
) == "-1", "sample 2"

# Minimum size, no operations.
assert run(
    """1 0
1
"""
) == "1", "minimum n and m"

# Singleton intervals must not change position, and two inversions cancel.
assert run(
    """1 2
inverse 1 1
inverse 1 1
1
"""
) == "1", "two inversions cancel"

# Full-array reversal, queried at the left boundary.
assert run(
    """10 1
reverse 1 10
1
"""
) == "10", "full interval reversal"

# Inversion at both boundaries, then a reversal.
assert run(
    """5 2
inverse 1 5
reverse 1 5
5
"""
) == "-1", "boundary positions and full intervals"

# Large n and many operations, without ever constructing the array.

 ## 特殊なケース

 (m=0) の場合、処理するものはありません。 のために```
1 0
1
```逆ループは空です。`pos`残っている`1`、 そして`sign`ポジティブなままです。 アルゴリズムの出力`1`、初期配列と正確に一致します。 

シングルトン間隔の場合、反転しても位置は変更されないはずです。 と```
5 1
reverse 3 3
3
```状態`3 <= pos <= 3`は true ですが、変換すると (3+3-3=3) になります。 その結果、アルゴリズムは追跡された位置を次のように維持します。`3`そして出力`3`。 

同じ要素に逆関数を 2 回適用する場合、```
1 2
inverse 1 1
inverse 1 1
1
```最初の逆処理操作では符号が (+1) から (-1) に切り替わり、2 番目の操作では符号が (+1) に戻ります。 最終的な値は`1`。 これが機能するのは、符号がパリティを記録するためです。パリティは、すべての逆数で値に (-1) を乗算するときにのみ重要になります。 

間隔のエンドポイントについては、次の点を考慮してください。```
5 1
inverse 1 5
5
```追跡された位置`5`満足する`1 <= 5 <= 5`なので、符号は負に変わります。 位置の元の値`5`は`5`、与える`-5`。 などの半開状態を使用する`l <= pos < r`誤って正の値のままになってしまいます。 

完全逆転するには、```
10 1
reverse 1 10
1
```追跡位置は次から変化します`1`(1+10-1=10)まで。 位置の初期値`10`は`10`、したがって、答えは次のとおりです`10`。 反転は中点を中心とした対称的なマッピングであるため、同じ公式がすべての内部位置に適用されます。 

最も重要なエッジケースは、配列サイズが巨大であることです。 (n=10^9) の場合、構築は試行されません。`[1, 2, ..., n]`。 このアルゴリズムは、(m) 個の操作と 1 つの現在位置のみを保存します。 値`pos`それ自体は、反転するたびに (1) ～ (n) の範囲内に留まるため、位置追跡計算でも個々の配列要素に関する情報は必要ありません。
