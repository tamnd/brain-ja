 ## 解決策
 ## 問題の理解

 シーケンスに必要な連続ブロックの長さが与えられます。 署名が (s_1,s_2,\ldots,s_n) の場合、最終シーケンスには同じ値のブロック (s_1) が含まれ、その後に異なる値が (s_2) 回繰り返され、次に別の異なる値が (s_3) 回繰り返されます。 値自体は正の整数であり、すべての要素の合計ができるだけ小さくなるように値を選択することがタスクとなります。 

たとえば、署名 ([2,1,3,1]) の場合、ブロック値は (1,2,1,2) となり、シーケンスは ([1,1,2,1,1,1,2]) になります。 4 つのブロック値は、そのすぐ隣の値と異なっていればよいだけです。 隣接していないブロックは同じ値を使用できます。 

ブロックは最大 (10^5) 個まで存在できますが、ブロックの合計の長さは最大でも (10^6) です。 出力自体には (10^6) 個の整数が含まれる可能性があるため、(O(n)) アルゴリズムが本質的に自然なターゲットになります。 (n) に二次因数を使用するアルゴリズムでは、最悪の場合、意図した制限時間をはるかに超えて、すでに約 (10^{10}) 回の演算が必要になります。 署名の合計の長さが (10^6) によって制限されるという事実は、答えを明示的に構築することは可能ですが、出力要素ごとに一定量を超える作業を大幅に行うことは避けるべきであることを意味します。 

最初のエッジ ケースは、ブロックが 1 つだけ含まれる署名です。 入力 (n=1)、(s=[5]) の場合、答えは (1) の 5 つのコピーです。 より大きな値を強制する隣接ブロックがないため、(2)、(3)、またはその他のより大きな値を使用すると、合計が増加するだけになります。 

2 番目のエッジ ケースは、現在のブロックの最小値が局所的に必ずしも最良の選択ではない場合です。 (s=[1,3]) の場合、ブロック値 (1,2) を選択すると合計は (1+3\cdot2=7) になりますが、(2,1) を選択すると (2+3=5) になります。 したがって、常に (1) から始まる貪欲なルールは間違っています。 

3 番目のエッジ ケースは、多くの連続するブロックが同じ長さである場合に発生します。 (s=[2,2,2]) の場合、最適なブロック値は (1,2,1) であり、([1,1,2,2,1,1]) となります。 (1,2,3) の代入は有効ですが、その合計は大きくなります。 この構築では、隣接するブロック値が異なることのみを必要とするため、2 つの最小値を交互に配置するだけで十分です。 

最後に、出力には署名自体ではなく、繰り返される値が含まれます。 (s=[1,3]) の場合、出力`2 1 1 1`その署名は ([1,3]) であるため、これは正しいです。 よくある実装上の間違いは、各ブロックの値を正しく解決し、その値をブロックの長さに応じて拡張するのを忘れることです。 

## アプローチ

 直接的な総当たりアプローチでは、すべてのブロックに正の整数を割り当て、隣接する割り当てが異なることを確認し、ブロックを拡張して、結果の合計を計算します。 署名の長さの合計は最大 (10^6) であるため、出力の合計長よりも大きい値を必要とする最適な答えはないため、(1) から (10^6) までの値を考慮するだけで十分です。 この人工的な境界を使用しても、((10^6)^n) の代入が存在する可能性があります。 最大 (n=10^5)、つまり (10^{600000}) 個の候補があるため、網羅的な検索は完全に不可能です。 

より構造化されたブルート フォースでは、小さな値のみが重要である可能性が高いことを観察し、ブロックごとにいくつかの可能な値を試すことができます。 これでもすべての位置に乗算分岐係数があるため、指数関数的なままになります。 本当の疑問は、なぜ (2) より大きい値が決して出現する必要がないのかということです。 

選択された値が (x) であるブロックの動的プログラミング状態を考えてみましょう。 前のブロックについて、達成可能な最小コストが値 (1) によって達成されると仮定します。 したがって、現在のブロックに対して (2) を選択することは正当であり、(x\ge3) を選択するよりもコストが低くなります。 代わりに、前のブロックの最小値が値 (2) によって達成される場合、現在のブロックに (1) を選択することは正当であり、すべての (x\ge3) よりもコストが低くなります。 帰納法により、ブロックごとに最良の状態は値 (1) と (2) のいずれかで表すことができます。 少なくとも (3) の値は、常にこれら 2 つの選択肢のいずれかによって支配されます。 

(1) と (2) だけが残ると、問題は特に簡単になります。 隣接するブロックは異なる値を持つ必要があるため、最初のブロックの値を選択した後、それ以降のすべての値が強制されます。 考えられるパターンは 2 つだけです。

 ## アルゴリズムのチュートリアル

 1. 署名 (s_1,s_2,\ldots,s_n) を読み取ります。 各 (s_i) は、ブロック (i) に割り当てられた値のコピーを何回書き込む必要があるかを示します。 
2. 最初のブロックに値 (1) を持たせるコストと、最初のブロックに値 (2) を持たせるコストを計算します。 これらは (s_1) と (2s_1) です。 
3. 後続のブロック (i) ごとに、前の 2 つの状態で使用されている値を交換します。 前のブロックが (1) を使用した場合、現在のブロックは (2) を使用する必要があります。 前のブロックが (2) を使用した場合、現在のブロックは (1) を使用する必要があります。 長さ (s_i) のブロックのコストは、その長さに選択した値を乗算したものになります。 
4. 両方の交互パターンの合計コストを維持します。 最終的には合計コストが小さいパターンを選択します。 
5. 選択したパターンを展開します。 選択したブロック値が (1) の場合、(s_i) 個のコピーを追加します。`1`; (2) の場合、(s_i) 個のコピーを追加します。`2`。 追加される整数の合計数はちょうど (\sum s_i) で、最大でも (10^6) です。 

なぜそれが機能するのかは不変条件として述べることができます。 ブロック (i) を処理した後、維持される 2 つのコストは、値 (1) および (2) で終わる 2 つの可能な交互パターンを使用したソリューション間の正確な最小コストです。 最適な解は値 (1) と (2) に制限できます。これは、少なくとも (3) の値を持つ状態が最適である可能性がある場合は常に、(1) または (2) のいずれかが前の最適な状態から利用可能であり、現在の正のブロック長に対する寄与が厳密に小さくなるからです。 値 (1) と (2) を使用すると、パス制約により 2 つの交互パターンのうちの 1 つが強制されます。 したがって、これら 2 つのパターンを比較すると、グローバル最小値が見つかります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = list(map(int, input().split()))

    # cost1: pattern 1,2,1,2,...
    # cost2: pattern 2,1,2,1,...
    cost1 = 0
    cost2 = 0

    for i, length in enumerate(s):
        if i % 2 == 0:
            cost1 += length
            cost2 += 2 * length
        else:
            cost1 += 2 * length
            cost2 += length

    first = 1 if cost1 <= cost2 else 2

    ans = []
    value = first

    for length in s:
        ans.extend([str(value)] * length)
        value = 3 - value

    sys.stdout.write(" ".join(ans))

if __name__ == "__main__":
    solve()
```最初のループは、完全なシーケンスを構築せずに、考えられる両方の合計を計算します。 偶数のゼロベースのインデックスの場合、最初のパターンは値 (1) を使用し、2 番目のパターンは値 (2) を使用します。 奇数のインデックスの場合、それらの役割は逆になります。 

比較には、`<=`、したがって、タイは一貫して最初のパターンを選択します。 任意の最小値が受け入れられるため、特定のタイブレーク ルールは正確さに影響しません。 

2 番目のループでは、選択したパターンを正確に再構築します。 表現`3 - value`スイッチ`1`に`2`そして`2`に`1`、個別の条件を避けます。 

の`ans`リストには文字列が含まれています。これは、最後に文字列を結合する方が、1 つの大きな Python 文字列に繰り返し連結するよりもはるかに効率的であるためです。 そのサイズは、最大 (10^6) の署名の合計長によって制限されます。 

Python の整数はオーバーフローせず、構築された 2 値の解の最大の合計は最大 (2\cdot10^6) であるため、ここでは整数の算術演算は簡単です。 主なメモリ使用量は出力そのものです。

input = sys.stdin.readline

def run(inp: str) -> str:
    global input

    old_stdin = sys.stdin
    old_input = input

    stream = io.StringIO(inp)
    sys.stdin = stream
    input = stream.readline

    old_stdout = sys.stdout
    output = io.StringIO()
    sys.stdout = output

    try:
        solve()
        return output.getvalue()
    finally:
        sys.stdin = old_stdin
        input = old_input
        sys.stdout = old_stdout

def signature(arr):
    if not arr:
        return []

    result = []
    current = arr[0]
    count = 1

    for x in arr[1:]:
        if x == current:
            count += 1
        else:
            result.append(count)
            current = x
            count = 1

    result.append(count)
    return result

assert signature(arr) == [1] * 100000

 ## 特殊なケース

 単一ブロックの場合、次のように`1 / 5`、隣接関係の制限はまったくありません。 アルゴリズムは 2 つの公称パターンを比較しますが、パターン 1 のコストは (5)、パターン 2 のコストは (10) であるため、値を選択します。`1`そして出力`1 1 1 1 1`。 サインが残っている`[5]`。 

ローカル貪欲な反例については、`2 / 1 3`、最初のパターンには値 (1,2) とコスト (1+6=7) があります。 2 番目のパターンには値 (2,1) とコスト (2+3=5) があるため、アルゴリズムは 2 番目のパターンを選択して出力します。`2 1 1 1`。 これは、隣接するブロックを考慮せずに最初のブロックに可能な最小値を単純に割り当てることができない理由を示しています。 

繰り返されるブロックの長さについては、`3 / 2 2 2`、2 つのパターンのコストは (2+4+2=8) と (4+2+4=10) です。 最初のパターンが選択されているため、`1 1 2 2 1 1`。 中央のブロックは隣接するブロックとは異なりますが、最初と 3 番目のブロックは隣接していないため、安全に同じ値を使用できます。 

出力の最大長については、`1 / 1000000`、答えは 100 万部のコピーで構成されます。`1`。 このアルゴリズムは不要な代替値を作成することはなく、出力サイズは許容される最大値とまったく同じです。 拡張ループは出力要素ごとに 1 つの追加操作を実行するため、その作業は避けられない出力サイズにおいて線形です。 

ブロックの最大数として、長さ (1) の (100000) ブロックを取得します。 隣接するすべてのブロックは異なる必要があるため、最適なシーケンスは次のブロック間で交互に行われます。`1`そして`2`。 可能な交互のシーケンスは 2 つあり、ブロックの数は偶数であるため、パターンは次のようになります。`1`合計は (50000\cdot1+50000\cdot2=150000) になります。 連続するブロックのみが制約されるため、アルゴリズムは最初と最後のブロックの間の境界に対する特別な処理を行わずに、この選択を正確に計算します。
