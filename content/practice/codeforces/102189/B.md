 ## 解決策
 ## 問題の理解

 コンテスト参加者のリストをフォーマットされた順位表に変換する必要があります。 各参加者には一意の名前と負ではないスコアが与えられます。 最終的な順序は、スコアの減少によって最初に決定されます。 2 人の参加者のスコアが同じ場合、文字を一般的な大文字と小文字に変換した後、名前が辞書編集的に比較されます。`Dy`、`dZ`、 そして`dx`として注文されます`dx`、`Dy`、`dZ`。 

入力には以下が含まれます`n`参加者、どこで`1 <= n <= 50000`。 すべての名前には最大 20 のラテン文字が含まれ、すべてのスコアは最大 20 文字です。`10^6`。 これらの境界により、二次アルゴリズムは不適切になります。 参加者が 50,000 人いる場合、ペアワイズ手順では約 12 億 5,000 万回の比較を実行できますが、これは 2 秒の制限内で必要な比較をはるかに超えています。 比較ソートにより、`O(n log n)`、約 50,000 回 16 回の比較が正しい順序で行われるため、これが自然な目標です。 

出力には 3 つの列があります。`Place`、`Name`、 そして`Score`。 それらの幅は固定されていません。 各幅は、ヘッダーを含む、その列に表示される文字列の最大長です。 空の位置はドットで埋められます。 最初の列は右揃えで、他の 2 列は左揃えです。 この順位も通常の順位とは少し異なります。グループが複数の連続した順位を占める場合、すべてのメンバーは同じ範囲を受け取ります。`2-3`または`5-7`。 

実装がもっともらしいように見えても、間違ったテーブルが生成されるケースがいくつかあります。 

1 人の参加者を考えてみましょう。```
1
Alice 0
```正しい出力は次のとおりです。```
|Place|Name.|Score|
|....1|Alice|0....|
```不用意に実装すると、場所の範囲が次のように計算される可能性があります。`1-1`たとえ 1 人の参加者が受け取る必要があるとしても、`1`。 

大文字と小文字を区別しない名前の順序付けも別の罠です。 例えば：```
3
aa 10
Ab 10
aA 10
```小文字の比較キーは次のとおりです。`aa`、`ab`、 そして`aa`。 したがって`aa`そして`aA`同等に比較しながら、`Ab`彼らの後に来る。 元の名前は出力では変更されません。 大文字と小文字を区別する並べ替えでは、ASCII 順序に従って大文字が小文字の前に配置され、異なるテーブルが生成される可能性があります。 

最も一般的な書式設定の間違いは、ヘッダーが列幅の決定に関与していることを忘れることです。 のために```
2
A 7
B 1000000
```の`Score`列の幅は少なくとも 5 文字である必要があります。`Score`実際の最長のスコアの長さは 7 ですが、それ自体の長さは 5 です。同様に、`Place`幅は 5 になります。 

最後に、同点の場合は、遭遇した個別のスコアの数ではなく、グループ全体が占める順位を使用する必要があります。 のために```
4
A 10
B 10
C 5
D 5
```最初の 2 人の参加者が席を占めます`1-2`、最後の 2 つが占めます`3-4`。 個別のスコアごとに個別のカウンターを増分してランクを割り当てると、計算が不必要に複雑になり、間違いが発生しやすくなります。 

## アプローチ

 最も直接的な総当りの解決策は、次に来るべき参加者を繰り返し見つけることです。 反復ごとに、残りの参加者をすべてスキャンし、必要な順序付けルールを使用してそれらを比較します。 これは正しいです。なぜなら、最もよく残っている参加者は、まさにソートされたテーブルの次の行であるからです。 

問題は比較の回数です。 最悪の場合、最初の行には`n-1`比較、2 番目に必要なのは`n-2`、 等々。 のために`n = 50000`、これは与えます`50000 * 49999 / 2 = 1,249,975,000`比較。 出力をフォーマットする前であっても、これは制限時間を超えすぎます。 

ブルートフォース手法が機能するのは、必要なテーブルの順序が完全な順序であるためです。参加者のすべてのペアは、スコアによって、次に小文字の名前によって一貫して比較できます。 この観察により、繰り返しの検索を標準の並べ替え操作に置き換えることができます。 

パイソンの`sort`参加者をタプルで順序付けできます。 まず大きなスコアが必要なので、最初のコンポーネントは次のようになります。`-score`。 大文字と小文字を区別しない昇順で名前を付ける必要があるため、2 番目のコンポーネントは次のようになります。`name.lower()`。 結果のキーは次のとおりです`(-score, name.lower())`。 

参加者が分類されると、同じスコアの各グループが 1 つの連続したセグメントを形成します。 このようなグループがゼロから始まるインデックスで始まる場合`left`そして直前に終わる`right`、その表示場所は`left + 1`を通して`right`。 これらの数値が異なる場合、表示される場所は文字列です`left+1-right`; それ以外の場合は、単なる単一の数値です。 

並べ替え後の最終的な書式設定も簡単になります。 まずすべての位置文字列を構築し、次に 3 つの列の最大幅を見つけます。 その後、適切な数のドットを使用して各行を構築できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべての参加者を読み取り、名前とスコアを含むペアとして各参加者を保存します。 並べ替えでは大文字と小文字が無視されるため、元の名前を保持する必要がありますが、出力では入力で指定されたスペルを保持する必要があります。 
2. キーを使用して参加者を並べ替えます`(-score, name.lower())`。 スコアを否定すると、目的のスコアの降順が Python の通常のタプルの昇順に変更されます。 小文字の名前は、必要な大文字と小文字を区別しない辞書編集上の比較を処理します。 
3. ソートされた配列をスコアが等しいグループごとにスキャンします。 インデックスで始まるグループの場合`left`、 前進`right`スコアが同じままである間。 この間隔の参加者はポジションを占めます`left + 1`を通して`right`。 
4. グループの位置間隔を位置文字列に変換します。 もし`left + 1 == right`、1 桁の数字を使用します。 それ以外の場合は範囲​​を使用します`left + 1-right`。 このグループのすべての参加者は、まったく同じ文字列を受け取ります。 
5. すべてのスコアを文字列に変換し、表示された 3 つの列を収集します。 幅`Place`の最大値です`len("Place")`生成されたすべての場所文字列。 同じルールが次の場合にも使用されます`Name`そして`Score`ヘッダーも含めて。 
6. ヘッダーを印刷し、次にすべての参加者の行を印刷します。 順位列はドット付きの右揃えを使用し、名前とスコア列はドット付きの左揃えを使用します。 各行は次のように囲まれています`|`、必要なテーブル構文と一致します。 

### なぜ効果があるのか

 並べ替え後、並べ替えキーが最初に比較されるため、参加者は必要な順序で正確に表示されます。`-score`、これはスコアを減少させることに相当し、その後小文字の名前を比較します。これはまさに必要なタイブレーカーです。 同点はこの順序で連続しているため、各同点グループは連続する 1 つの順位間隔に対応します。 位置から始まるグループ`left + 1`そして終わる`right`したがって、共通の場所の文字列を正しく受け取ります`left + 1`または`left + 1-right`。 書式設定フェーズでは、各列の実際の最も長いセルとそのヘッダーが使用されるため、各行は必要な幅と配置を正確に受け取ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    participants = []
    for _ in range(n):
        name, score = input().split()
        participants.append((name, int(score)))

    participants.sort(key=lambda x: (-x[1], x[0].lower()))

    places = [""] * n
    i = 0

    while i < n:
        j = i + 1
        while j < n and participants[j][1] == participants[i][1]:
            j += 1

        if i + 1 == j:
            place = str(i + 1)
        else:
            place = f"{i + 1}-{j}"

        for k in range(i, j):
            places[k] = place

        i = j

    place_width = max(len("Place"), *(len(x) for x in places))
    name_width = max(len("Name"), *(len(name) for name, _ in participants))
    score_strings = [str(score) for _, score in participants]
    score_width = max(len("Score"), *(len(x) for x in score_strings))

    out = []

    header = (
        "|"
        + "Place".ljust(place_width, ".")
        + "|"
        + "Name".ljust(name_width, ".")
        + "|"
        + "Score".ljust(score_width, ".")
        + "|"
    )
    out.append(header)

    for i, (name, _) in enumerate(participants):
        row = (
            "|"
            + places[i].rjust(place_width, ".")
            + "|"
            + name.ljust(name_width, ".")
            + "|"
            + score_strings[i].ljust(score_width, ".")
            + "|"
        )
        out.append(row)

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```最初のループは正確に読み取ります`n`参加者の記録。 スコアは数値の順序付けに関与するため整数に変換されますが、名前は並べ替えと出力の両方で文字列として残ります。 

ソートキーには 2 つのコンポーネントが含まれています。`-x[1]`最高スコアが最初に表示されます。`x[0].lower()`保存されている名前のスペルを変更せずに、必要な大文字と小文字を区別しない比較を実行します。 

グループスキャンは半開間隔を使用します`[i, j)`。 この規則により、場所の計算が特にわかりやすくなります。 がある`j - i`グループ内の参加者、および最初の参加者はゼロから始まるインデックスにあるため`i`、グループは 1 ベースの位置を占めます`i + 1`を通して`j`。 条件`i + 1 == j`まさに単一参加者の場合であり、誤った表現を防止します`1-1`。 

の`places`配列には、ソートされた参加者ごとに計算済みの場所文字列が格納されます。 これには費用がかかります`O(n)`メモリを節約し、タイのすべてのメンバーに対して同じ範囲を再計算することを回避します。 

フォーマットするには、`ljust(width, ".")`左揃えの値の後にドットを置きますが、`rjust(width, ".")`右揃えの値の前にドットを置きます。 埋め込み文字としてドットを直接使用する方が、パディング長を手動で計算するよりも簡単で、エラーが発生しにくくなります。 

Python の整数には任意の精度があるため、スコアの限界は`10^6`オーバーフローの問題は発生しません。 参加者が 50,000 人しかいないため、可能な最大の場所の文字列も小さくなります。 

コンテスト ステートメントに示されているサンプルには 8 つの参加者レコードが含まれているため、最初の入力値は次のようになります。`8`。 コードは実際の入力形式に従い、レコードの前にそのカウントを読み取ります。

 | 50,000 人の参加者が生成 | 50,000 のデータ行と有効なテーブル境界 | 最大入力サイズとリニア出力処理 |

 最大サイズのテストでは、社説に何十万もの文字を埋め込むのではなく、構造特性を意図的にチェックします。 最初と最後のテーブルの境界と出力行の正確な数により、行が失われたり、余分な行が出力されたり、最後の区切り文字が不正であったりする一般的なエラーが検出されます。 

## 特殊なケース

 単一参加者のケースは、グループ スキャンが開始されるときに処理されます。`i = 0`そしてすぐに手に入る`j = 1`。 以来`i + 1 == j`、場所文字列は`1`、 ない`1-1`。 入力用```
1
Alice 0
```出力は```
|Place|Name.|Score|
|....1|Alice|0....|
```すべて等しい場合は、配列全体をカバーする 1 つのグループが生成されます。 のために```
4
aa 10
BB 10
aA 10
Ab 10
```小文字のキーは`aa`、`bb`、`aa`、 そして`ab`、つまり、並べ替えられた名前は次のようになります。`aa`、`aA`、`Ab`、`BB`。 グループはポジション 1 からポジション 4 まで広がり、すべての参加者にその場所が与えられます。`1-4`。 このアルゴリズムでは、グループ内のランクは増加しません。これは、まさに共有配置が必要とするものです。 

大文字と小文字を区別しない比較は、並べ替えの場合にのみ実行されます。 入力に次のものが含まれているとします。`ALAN 10`そして`alpha 10`。 それらの比較キーは次のとおりです。`alan`そして`alpha`、 それで`ALAN`が最初に来ます。 保存された名前は残ります`ALAN`これにより、元の参加者名の代わりに小文字の並べ替えキーを印刷するというよくある間違いを防ぐことができます。 

テーブルの最後が同点であれば、グループ スキャンの右側の境界がテストされます。 のために```
5
maximum 1000000
top 1000000
mid 999999
low 0
ZERO 0
```最初のグループがポジションを占めます`1-2`、中央の参加者が占めます`3`、そして最後のグループが占めます`4-5`。 スキャンが最後の参加者に到達すると、`j`まさになる`n`、ループ条件は以下に基づいているため、グループは引き続き処理されます。`i < n`。 

最大スコア`1000000`特別な数値処理は必要ありません。 スコアは整数であり、Python の整数型は許容範囲全体を安全に表します。 ゼロについても同じことが当てはまります。ゼロは有効なスコアのままであり、すべての正のスコアの後に並べ替える必要があります。 

書式設定の境界も重要です。 一番長い場所なら`1-4`、長さは 3 ですが、ヘッダー`Place`長さは 5 なので、最初の列の幅は 5 文字のままです。 同様に、`Score`それ自体の長さは 5 です。ヘッダーとデータの両方から幅を計算すると、すべての実際の値がたまたま短くなった場合の不正なヘッダーが防止されます。 

最後に、名前は元の形式では一意ですが、名前が大文字と小文字だけが異なる場合には、決定的な順序を保持する必要性がなくなるわけではありません。 必要な比較では、大文字と小文字を区別しない規定に従って、これらの名前が等しいものとして扱われます。 Python のソートは安定しているため、2 つのキーが同一の場合、元の入力順序が保持されます。 指定された順序に従ってどちらの参加者も他方の参加者よりも優先される必要がないため、この動作はコンパレータと一致します。
