 ## 解決策
 ## 問題の理解

 それぞれのカードには整数値が含まれています。 ゲーム中、私たちは現在のデッキからカードを繰り返し削除します。 

奇数の位置にあるカードを取り除くと、その値がスコアに追加されます。 偶数の位置でカードを削除すると、そのカードは消えますが、何も貢献しません。 削除するたびに、残りのカードが圧縮され、インデックスが再作成されます。 

ゲームはいつでも停止する可能性があるため、すべてのカードを削除する必要はありません。 タスクは、最終スコアを最大化することです。 

デッキの長さは到達可能です$2 \cdot 10^5$すべてのテストケースにわたって。 カードの除去を明示的にシミュレートしたり、ゲームの状態を調査したりするソリューションは直ちに除外されます。 たとえ$O(n^2)$アルゴリズムは大まかに実行します$4 \cdot 10^{10}$限界をはるかに超えた最悪の場合の動作。 線形または線形に近い解決策が必要です。 

主な難点は、削除後に位置が継続的に変化することです。 偶数の位置から始まったカードが後で奇数になることもあり、その逆も同様です。 ポジションの最初の同等性だけを見ると、誤った結論につながります。 

考慮する：```
n = 3
a = [-1, 3, -5]
```正の値のみを取るというのは単純な考えです。 そうすればスコアが出るだろう$3$。 ただし、真ん中のカードを直接回収することはできません。 まず最初に位置 1 の一番上のカードを削除し、獲得する必要があります。$-1$、その後収集します$3$。 ベストスコアは$2$、 ない$3$。 

別の微妙なケースは次のとおりです。```
n = 4
a = [1, -2, 3, -4]
```答えは$4$。 3 と 1 の両方を収集できます。連続する接尾辞のみを考慮するか、最初の奇数の位置のみを考慮する解決策では、この可能性が失われます。 

最後のエッジケースは、すべての値が負の場合です。```
n = 1
a = [-1]
```ゲームをすぐに終了することは許可されているため、答えは次のようになります。$0$。 少なくとも 1 枚のカードを強制的に取らせるアルゴリズムは間違っています。 

## アプローチ

 ブルートフォースサーチでは、あらゆる除去後のデッキをモデル化します。 各ステップで、残っているカードを取り除くことができます。 除去するたびにデッキの構造が変化するため、状態の数は指数関数的に増加します。 たとえ$n=30$、そのような検索は絶望的です。 

有用なパターンを見つけるには、操作の正確な順序を忘れて、どのカードが最終的にスコアに貢献できるかを考えてください。 

カードが貢献すると決めたとします。 それが取られた瞬間、それは奇妙な位置を占めているに違いありません。 それより前のカードは、偶数の位置からのフリー除去または奇数の位置からのスコア付き除去を使用して 1 枚ずつ削除できます。 インデックスの再作成プロセスにより、見た目よりもはるかに自由度が高まります。 

重要な観察は、元の配列で奇数のインデックスに到達すると、それ以降のすべての正の値を独立して収集できることです。 それ以降の負の値は、適切な削除によってスキップできます。 

これにより、非常にコンパクトな特性評価が可能になります。 

ポジションから集め始めたら$i$、 どこ$i$1 ベースのインデックス付けでは奇数である場合、次のようになります。$$a_i + \sum_{j>i,\ a_j>0} a_j$$達成可能です。 

なぜ？ 選択した奇数位置のカードがエントリーポイントとして機能します。 取得した後は、必要に応じて以降のポジティブ カードを奇数の位置に配置することができ、ネガティブ カードは捨てることができます。 

もう一つ可能性があります。 奇数の位置のエントリ カードを決して取得せず、その代わりにすでに偶数の位置にある正の値のみを収集する場合があります。 これは、奇数プレフィックス全体が破棄された後に開始することに対応します。 

定義する：$$suf[i] = \sum_{j=i}^{n} \max(a_j,0).$$次に、奇数の位置ごとに$i$価値を提供します$$a_i + suf[i+1].$$以前の奇数位置をすべてスキップする特殊なケースは、次のようになります。$$suf[1]$$標準導出では最後の奇数境界を考慮して処理されますが、偶数位置の構造に制限されます。 

公式の貪欲なソリューションは、すべての有効なエントリ ポイントの最大値を計算します。

 ## アルゴリズムのチュートリアル

 1. サフィックス配列を構築します。`suf[i]`位置のすべての正の値の合計に等しい`i...n`。 
2. 答えをゼロとして初期化します。 これは、カードを取得せずにゲームを直ちに終了することを表します。 
3. ポジションごとに`i`1 から始まるインデックスを使用する場合:

 - もし`i`奇数です、計算してください$$a_i + suf[i+1].$$- 見つかった最大値で回答を更新します。 
4. 最終的な答えを出力します。 

候補者$a_i + suf[i+1]$そのカードを意味します$i$最初の得点カードです。 それを取った後、その右側にあるすべてのポジティブカードも収集できますが、ネガティブカードは無視されます。 

### なぜ効果があるのか

 どの得点シーケンスにも最初のカードがあり、その値がスコアに追加されます。 そのカードは取られたときに奇妙な位置を占めなければなりません。 元の配列を振り返ると、この最初に得点されたカードは、奇数のインデックスに対応しています。$i$。 

その後、右側のすべての正の値を収集し、すべての非正の値を破棄できます。 したがって、インデックスから始まる戦略はありません$i$勝てます$$a_i + \sum_{j>i}\max(a_j,0).$$逆に言えば、この値は達成可能です。 まずはカードを取る手配をします$i$、次に、その右側にあるポジティブなカードをすべて繰り返し収集し、他のカードをスキップします。 

すべての有効な戦略には最初にスコア付けされた奇数インデックスがあるため、すべての奇数インデックスを調べることですべての可能性がカバーされます。 最大値を取ると、最適なスコアが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())

    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        suf = [0] * (n + 1)

        for i in range(n - 1, -1, -1):
            suf[i] = suf[i + 1] + max(a[i], 0)

        ans = 0

        for i in range(0, n, 2):  # odd positions in 1-based indexing
            ans = max(ans, a[i] + suf[i + 1])

        print(ans)

solve()
```サフィックス配列には、将来のプラスの寄与が格納されます。 それが利用可能になると、候補開始位置の評価は一定時間になります。 

ループは 2 ずつステップします。`0, 2, 4, ...`元の 1 から始まる番号付けの奇数の位置に対応します。 この変換を忘れることは、最も一般的な実装ミスです。 

ゲームをすぐに終了することは常に合法であるため、答えはゼロから始まります。 これは、負の数のみを含む配列を処理します。 

Python の整数は自動的に拡張され、固定幅の算術演算であっても、可能な最大スコアは 64 ビットに快適に収まるため、大きな整数の問題は存在しません。

この例は、マイナスの奇数ポジションが構造的なエントリー ポイントとしてのみ使用されることが多く、実際の利益はその後のプラスのカードから得られることを示しています。

 ## 特殊なケース

 次のことを考慮してください。```
1
-1
```サフィックス配列はどこでもゼロです。 唯一の候補は、$-1$。 答えはゼロに初期化されるため、アルゴリズムは 0 を返します。これは、ゲームを直ちに終了するオプションと一致します。 

考慮する：```
3
-1 3 -5
```アルゴリズムは最初の奇数の位置を評価し、次の値を取得します。$2$。 3 番目の位置を評価し、次の値を取得します。$-5$。 最大値は$2$、これは正確に取ることに相当します$-1$最初に集めてから$3$。 

考慮する：```
4
1 2 3 4
```どのカードもポジティブです。 サフィックス構造は将来のすべてのゲインを累積し、最初の奇数の位置によって次の結果が生成されます。$1 + 2 + 3 + 4 = 10$。 アルゴリズムは、すべての正の値が最終的にスコアに寄与する可能性があることを正しく認識します。
