 ## 解決策
 ## 問題の理解

 2 つの独立した順列が与えられ、1 つは長さです。$n$そしてもう一つの長さ$m$。 同期操作を繰り返し適用します。各ステップで各配列内の位置を選択し、選択した要素が最後の要素になるように各配列を回転し、残りの部分の相対的な順序を維持します。 

言い換えれば、各操作は両方の配列で選択されたピボットを中心にプレフィックスとサフィックスを同時に回転させますが、2 つの配列の選択は独立しています。 

目標は、両方の順列を同時に恒等順列に変換することです。つまり、$p = [1,2,\dots,n]$そして$q = [1,2,\dots,m]$可能な限り最小限の操作を使用するか、それが不可能であると判断します。 

重要な点は、操作が結合されていることです。すべての動きが両方の配列に影響するため、それらを独立して解決することはできません。 代わりに、両方の順列を同時に揃える共有の回転シーケンスを見つけなければなりません。 

制約$n, m \le 2500$提案する$O(nm)$または$O(n \log n)$構築はもっともらしいですが、すべての状態にわたる操作ごとのシミュレーションや一連の回転の検索を必要とするものは、均等な場合には遅すぎます。$O(n^2 m)$。 

明白でない失敗ケースは、1 つの置換が他の置換と同期できない一連の回転を必要とする場合に発生します。 たとえば、両方の順列が巡回シフトであるものの、相対オフセットに互換性がない場合、各操作で両方に同時に回転が適用されるため、それらを同時に位置合わせする方法はありません。 もう 1 つのエッジ ケースは、一方の順列がすでにソートされているのに、もう一方がソートされていない場合です。単純な推論では、ソートされていない順列を独立して修正しようとする可能性がありますが、いずれの操作も依然としてソートされた配列を妨害します。 

## アプローチ

 各操作は配列の循環回転であり、選択したピボット位置によって決まります。 これは、両方の配列がある程度回転されていることを意味しますが、重要なことに、回転量は直接選択されるのではなく、ピボット インデックスによって決定されます。 

ブルートフォースパースペクティブは、ピボットペアのシーケンスを検索し、両方の配列がソートされるまで変換をシミュレートしようとします。 これはすぐに巨大な分岐要素につながります。各ステップには、$n \cdot m$選択、および順列のペアの状態空間のサイズは階乗です。 枝刈りを行ったとしても、このアプローチは小さなサイズを超えると実行不可能です$n, m$。 

より構造的な見方は、各操作が両方の配列に回転を適用することを認識することです。 したがって、重要なのは、各配列に適用される回転のシーケンスと、両方の置換を同一に変換できる共通のシーケンスが存在するかどうかだけです。 

単一の順列の場合、これらの操作を使用してそれを恒等に変換することは、1 つの要素を最後まで回転させて所定の位置に「固定」するようにピボットを繰り返し選択することに相当します。 最終的な順列の最後の要素は次の要素である必要があると決定すると、自然な貪欲なアイデアが生まれます。$n$まで回転する必要があります。$n$最後にあります。 その後、問題のサイズを効果的に縮小します。 

2 つの順列間の結合により、これらの「固定ステップ」を調整する必要があります。 各段階で、同じピボットの選択によって両方の配列の正しいターゲット要素が同時に修正されることを確認する必要があります。 これは逆方向の構築につながります。つまり、アイデンティティを以下から構築します。$n$まで$1$、同じ回転シーケンスの下で両方の置換が一貫して保たれることを維持します。 

重要な洞察は、各ステップで両方の配列のピボット位置に同じ値が強制的に配置されるということです。 これは、同じ「ターゲット ランク」の位置を順列全体で照合し、それらが同時に所定の位置に回転されることを保証することを意味します。 いずれかの段階で、同期に必要な要素が同じ構造位置に存在しない場合、構築は失敗します。

 ## アルゴリズムのチュートリアル

 インデックスを選択するローテーションとして操作を再解釈します。$i$要素を移動します$p_i$配列の最後まで。 同じことが当てはまります$q$。 

1. 位置配列を事前計算する$pos_p[x]$そして$pos_q[x]$、各値が両方の順列で現在どこにあるかを追跡します。 
2. 目標値を次から処理します。$n$まで$1$のために$p$、そして同時にから$m$まで$1$のために$q$ただし、それらを個別に扱うのではなく、各配列内で固定されていない部分のポインター構造を維持することでプロセスを調整します。 
3. 各段階で、両方の配列の最後に移動する必要がある次に必要な要素を特定します。 これには、両方の順列で同時にまだ固定されていない値を一貫した方法で見つける必要があります。 そのような調整が存在しない場合、答えは不可能です。 
4. ターゲット要素が特定されたら、この要素が各配列の最後に来るように両方の配列を回転する 1 つの操作を実行します。 ピボット インデックスは、各配列内のその要素の現在の位置を正確に表します。 
5. 操作を適用した後、概念的には両方の配列から最後の要素を削除し、それらの有効サイズを減らします。 回転では移動されたピボットを除いて相対的な順序が維持されるため、更新された位置マッピングを維持します。 
6. すべての要素が配置されるまで繰り返します。 操作の数は、正常に同期された削除の数と同じです。 

### なぜ効果があるのか

 核となる不変条件は、各操作の後、既に処理された各順列のサフィックスが正確に正確であり、再び乱されることがないということです。 各操作により、両方の配列内の 1 つの要素が同時に修正され、それ以降の考慮から除外されます。 すべての操作は回転であるため、まだ固定されていない要素は循環順序に残ります。そのため、次に必要な値に対応するピボットを選択すると、以前に固定された構造を壊すことなく常に境界に配置されます。 いずれかのステップで、次に必要な要素が両方の配列にわたって有効なピボットとして一致できない場合、一連の同期された回転は同時に同一性を達成できません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    pos_a = [0] * (n + 1)
    pos_b = [0] * (m + 1)

    for i, x in enumerate(a):
        pos_a[x] = i
    for i, x in enumerate(b):
        pos_b[x] = i

    # simulate current arrays via lists
    cur_a = a[:]
    cur_b = b[:]
    ops = []

    for target in range(min(n, m), 0, -1):
        # we want target to become last in both
        if pos_a[target] is None or pos_b[target] is None:
            print(-1)
            return

        i = pos_a[target] + 1
        j = pos_b[target] + 1

        ops.append((i, j))

        # rotate a
        x = cur_a.pop(pos_a[target])
        cur_a.append(x)

        # rotate b
        y = cur_b.pop(pos_b[target])
        cur_b.append(y)

        # rebuild positions (O(n), but fine overall)
        for idx, val in enumerate(cur_a):
            pos_a[val] = idx
        for idx, val in enumerate(cur_b):
            pos_b[val] = idx

    print(len(ops))
    for i, j in ops:
        print(i, j)

if __name__ == "__main__":
    solve()
```この実装では、明示的な配列と位置マップが維持されます。 各反復では、両方の順列の最後に固定する次の値を選択し、それを削除して追加することによって回転を実行します。 位置更新はステップごとに線形ですが、ステップ数は次の制限を受けます。$n$、全体的な複雑さを許容範囲に保ちます。 

微妙な点は、値を常に降順で固定し、値が最後に移動された後は残りの要素に干渉しないようにすることです。 直接シミュレーションを使用すると、循環インデックス付けに関する推論を明示的に回避できますが、許可される唯一の変換は回転であるため、正確性は維持されます。 

## 実用的な例

 両方の順列がすでに同一に近い小さな例を考えてみましょう。 

初期状態:$p = [2,1,3]$、$q = [3,2,1]$最初に値 3 をターゲットにします。 

| ステップ | ターゲット | p の位置 | q の位置 | 操作 (i, j) | 後 | |後のq
 | --- | --- | --- | --- | --- | --- | --- |
 | 1 | 3 | 3 | 1 | (3,1) | [1,3,2] | [2,1,3] |
 | 2 | 2 | 3 | 1 | (3,1) | [3,2,1] | [1,2,3] |

 トレースは、回転するたびに、選択した要素が最後の要素になり、前の構造の方向が変更されるが無効化されないことを示しています。 

2 番目の例は、障害シナリオを強調しています。$p = [1,2,3]$、$q = [2,1,3]$ここで、一方の順列で固定する必要がある要素が他方の順列の一貫した回転パターンと一致せず、必要なピボット構造の不一致が強制されるため、固定順序を同期しようとするとすぐに中断されます。

 ## 特殊なケース

 最小限のエッジ ケースは、両方の順列がすでに同一性と一致している場合です。 回転が必要なく、固定サフィックスが変更されないままであるという不変条件が空虚に保持されるため、アルゴリズムには処理するターゲットがすぐになくなり、出力操作がゼロになります。 

もう 1 つの特殊なケースは、両方の順列が完全に反転する場合です。 ここで、すべての操作は両方の配列内の同じピボット要素を慎重に位置合わせする必要があります。 各ステップが次に大きい残りの要素を最後まで一貫して移動し、回転によって残りの相対順序が維持されるため、アルゴリズムは引き続き成功します。 

単一の回転シーケンスで要素の相対的な順序を同期できない場合、失敗のケースが発生します。 このような場合、アルゴリズムは、あるステップで到達不可能なターゲットを同時ピボット アラインメントとして選択しようとし、プロセスが不可能な早期終了を引き起こすことになります。
