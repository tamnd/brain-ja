 ## 問題の理解

 新しいシーケンスを構築する必要があります$b$長さの$n$。 

のあらゆる要素$b$正の整数でなければなりません。 シーケンスはすべての位置で厳密に増加している必要があります$i$を選択することは禁じられています。$b_i = a_i$。 

これらのルールを満たすすべてのシーケンスの中で、最終要素の可能な限り小さい値が必要です。$b_n$。 

入力により、いくつかのテスト ケースが得られます。 テストケースごとに配列を受け取ります$a$、そして達成可能な最小終了値を決定する必要があります。 

制約は非常に小さいです。 各テスト ケースには最大 100 個の要素があり、最大 100 個のテスト ケースが存在します。 たとえ$O(n^2)$解決策はまったく問題ありません。 これは、高度な最適化を心配するのではなく、最も単純で正しい戦略を見つけることに集中する必要があることを意味します。 

難しいのは、ある位置で大きすぎる値を選択すると、その後のすべての値も強制的に大きくなる可能性があることです。 最後の要素を最小化することのみを考慮しているため、シーケンスを有効に保つ最小値をすべての位置に割り当てる必要があります。 

よくある間違いは、禁止された値だけを避けることです$a_i$そして、シーケンスは厳密に増加し続ける必要があることを忘れてください。 

例えば：```
n = 2
a = [1, 2]
```選択する$b_1 = 2$避ける$a_1$、しかしその後$b_2$は 2 より大きく、2 とは異なる必要があるため、答えは 3 になります。より良い選択は$b_1 = 2$、$b_2 = 3$, これでも 3 が得られますが、この例は、すべての選択が将来のポジションに影響を与えることを示しています。 

もう 1 つの簡単な間違いは、0 から開始して、禁止値に遭遇した場合にのみ増加を繰り返すことです。 

例：```
n = 1
a = [1]
```最小の正の整数は 1 ですが、これは禁止されています。 正解は 2 です。 

正の値を無視した不用意な実装では、誤って 0 または 1 が出力される可能性があります。 

次に小さい有効な値が次の値に等しい場合、より微妙なケースが発生します。$a_i$。```
n = 3
a = [1, 3, 4]
```最適な順序は次のとおりです。```
b = [2, 4, 5]
```位置 2 では、前の要素より大きい最小値は 3 ですが、3 は禁止されているため、sk する必要があります。
