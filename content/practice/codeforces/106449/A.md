 ## 解決策
 ## 問題の理解

 この問題では、データセットを表す整数のコレクションが得られます。 すべての数値の最初の意味のある桁、つまり符号を無視した場合の左端のゼロ以外の桁を検査する必要があります。 タスクは、数字が正しいかどうかを判断することです。`1`は、他のすべての数字よりもこの先頭の数字として頻繁に表示されます。 存在する場合、そのデータセットは疑わしいと見なされます。 それ以外の場合はそうではありません。 

たとえば、次のような数字です。`-4200`先頭の数字に貢献します`4`マイナス記号は数値の一部ではなく、値を含む最初の桁は`4`。 番号`0`は、ゼロ以外の数字がないため、特殊なケースです。 先頭の有効数字の定義はゼロには適用されないため、ゼロ値は桁数に影響しません。 

ソリューションをシンプルにする必要がある主な理由は、入力サイズです。 最大数百万の数値を扱うと、入力量に比例した作業しか行うことができなくなります。 数値を相互に比較したり、高価な方法で数値を繰り返しスキャンしたりするアプローチは、すぐに遅くなりすぎます。 各数値を 1 回読み取り、最初の桁を抽出するだけで十分です。 

難しいケースは、ほとんどの場合、数字を正しく抽出することに関係します。 次のような数字`-1000`先頭としてカウントする必要があります`1`、 ない`-`または`0`。 のような数字`0`誤って特定の桁のカウントを増やしてはいけません。 入力内で最初の桁が一意でない数値も、誤った比較を引き起こす可能性があります。 

次の入力を考えてみましょう。```
3
0 0 1
```正しい出力は次のとおりです。```
suspicious
```数字だけ`1`貢献するので、数字`1`は 1 回出現し、他のすべての数字は 0 回出現します。 ゼロを先頭桁として扱う不用意な実装`0`ここではまだ合格しますが、ゼロが多数存在する場合は失敗します。 

別の例:```
4
0 0 0 1
```正しい出力は次のとおりです。```
suspicious
```ゼロは数字と競合しないでください`1`。 先頭の数字としてゼロを数えると、誤って数字が作成されてしまう`0`勝つ。 

負の値にも注意が必要です。```
2
-999 100
```正しい出力は次のとおりです。```
suspicious
```先頭の数字は次のとおりです`9`そして`1`。 数字を抽出する前に、符号を無視する必要があります。 

## アプローチ

 直接的なブルートフォース手法では、すべての数値の先頭の桁を収集し、頻度を繰り返し比較して、その桁が正しいかどうかを判断します。`1`が一番大きいです。 必要な情報は各先頭桁の頻度だけであるため、これは正しいです。 ただし、すべての数値についてすべての桁を他のすべての桁と比較することによって比較を実行すると、結果が不必要に大きくなる可能性があります。 と`n`数字、そのスタイルは周りに届くことができます`10n`ここではまだひどいことではありませんが、問題のより単純な構造が抜け落ちています。 

有益な観察は、考えられる先頭の桁が 10 桁のみであるということです。 数値を保存したり、複雑な比較を実行したりする必要はありません。 必要なのはサイズ 10 の周波数配列だけです。 各数値を読み取るときに、その先頭の有効数字を見つけて、対応するカウンターをインクリメントします。 データセット全体を処理した後、桁数を比較します。`1`他の 9 桁の最大数となります。 

総当たり法は、答えが桁の頻度のみに依存するため機能しますが、すぐに要約できる情報を繰り返し確認するのに労力がかかります。 周波数アレイにより、問題は入力上の単一パスに軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(10n) | お(1) | 理論上は受け入れられますが、不要です |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 10 個のカウンターの配列を作成します。`d`先頭の数字がいくつあるかを格納します`d`。 
2. 各数値を読み、マイナスの場合は記号を削除します。 先頭の桁は大きさのみに依存するため、絶対値で十分です。 
3. 数値がゼロの場合、先頭に有効な数字がないため無視します。 
4. ゼロ以外のすべての数値について、最初の桁だけが残るまで繰り返し最後の桁を削除します。 その桁のカウンタをインクリメントします。 
5. すべての数値が処理された後、桁数を比較します。`1`1 桁おきにカウントします。 厳密にそれらのすべてよりも大きい場合は、印刷します`suspicious`; それ以外の場合は印刷します`unfortunately not`。 

これが機能する理由は、この問題では先頭の桁の分布のみが求められるためです。 アルゴリズムはこれらの周波数を正確に維持し、それ以外は何も維持しません。 カウントがわかれば、1 回の比較によって答えが決まります。 

なぜ効果があるのか:

 不変条件は、入力の接頭辞を処理した後、頻度配列には、処理された数値の各先頭有効数字の正確な出現数が含まれるということです。 処理された各非ゼロ数値は、その真の先頭桁のカウンタに 1 回だけ寄与しますが、ゼロは何も寄与しません。 すべての数値が処理された後、不変式により完全な頻度分布が得られるので、次の数値が`1`最大の周波数を持ち、必要な結果が正確に得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)

    cnt = [0] * 10

    nums = input().split()
    for s in nums:
        x = int(s)
        if x == 0:
            continue

        x = abs(x)
        while x >= 10:
            x //= 10

        cnt[x] += 1

    for d in range(10):
        if d != 1 and cnt[1] <= cnt[d]:
            print("unfortunately not")
            return

    print("suspicious")

if __name__ == "__main__":
    solve()
```考えられる答えは次の数字であるため、コードには 10 個のカウンターのみが保存されます。`0`に`9`。 入力された数値はすぐに処理されるため、データセット全体をメモリ内に保持する必要はありません。 

の`abs`call はマイナス記号の影響を取り除きます。 10 で割るループは、整数から最初の桁に向かって移動します。 例えば、`58320`になる`5832`、 それから`583`、 それから`58`、 それから`5`。 

ゼロの除算を繰り返すと永久にゼロのままになり、誤って有効な先頭の数字として扱われるため、このプロセスの前にゼロのチェックが行われます。 最後のループでは厳密な比較が使用されます。 別の数字がその数字と同じ周波数を持つ場合`1`、数字`1`はあまり頻繁には現れないので、答えは否定的でなければなりません。

import io

def solve_io(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    if not n_line:
        return ""

    cnt = [0] * 10

    for s in input().split():
        x = int(s)
        if x == 0:

        x = abs(x)

        cnt[x] += 1

        if d != 1 and cnt[1] <= cnt[d]:

    return "suspicious\n"

 ## 特殊なケース

 この場合の場合:```
3
0 0 1
```アルゴリズムは両方のゼロをスキップし、先頭の数字を抽出します`1`最終番号から。 count 配列は次のようになります。`cnt[1] = 1`他のすべてのカウントはゼロのままなので、答えは次のようになります。`suspicious`。 

この場合の場合:```
2
-999 100
```アルゴリズムは変換します`-999`の中へ`999`、数字を抽出します`9`、次に数字を抽出します`1`から`100`。 カウントは次のとおりです`cnt[9] = 1`そして`cnt[1] = 1`。 桁以降`1`厳密に大きいのではなく同程度である場合、答えは次のとおりです。`unfortunately not`。 

次のように、すべての値が同じ数字で始まる大規模なコレクションの場合:```
5
700 71 7999 0 -7123
```アルゴリズムは先頭の数字が 4 回出現することをカウントします。`7`そしてゼロを無視します。 桁`1`その数を超えないため、データセットは正しく拒否されます。 これは、数字かどうかのみをチェックするソリューションをキャッチします`1`他のすべての数字よりも頻繁に出現するかどうかをチェックするのではなく、頻繁に出現します。
