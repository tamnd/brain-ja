 ## 解決策
 ## 問題の理解

 この問題は、食料品のセットを 2 つの袋に分割して、両方の袋の総重量がまったく同じになるかどうかを問うものです。 各商品は必ず 1 つのバッグに入れる必要があります。 入力はアイテムの数と各アイテムの重量を示し、出力はそのような分割が存在するかどうかを示します。 

重要な点は、すべてのアイテムの合計重量が、目標金額を管理できるほど十分に小さいことです。 アイテムの数は 100 に達する可能性がありますが、合計の重みは 1000 を超えることはありません。これは、可能なサブセットの数ではなく合計の重みに依存するソリューションが合理的であることをすぐに示唆しています。 すべてのサブセットを試すブルート フォース ソリューションには、最大で次のものが必要になります。$2^{100}$選択肢は、コンテストで実行できるものをはるかに超えています。 解決策$O(N \times S)$、 どこ$S$は総重量ですが、簡単に受け入れられます。$S$最大でも 1000 です。 

いくつかの特殊なケースでは、不用意な実装が失敗する可能性があります。 1 つ目は、総重量が奇数であることです。 入力の場合:```
3
1 2 4
```正しい出力は次のとおりです。```
no
```なぜなら、2 つの袋にはそれぞれ 7 個の半分が含まれる必要があるため、これは不可能だからです。 必要な半分を考慮せずに、一部のサブセットが存在するかどうかだけをチェックするソリューションでは、誤った結果が得られる可能性があります。 

もう 1 つのケースは、合計が偶数であるが、可能な分割で 1 つの項目のみが使用される場合です。 入力の場合:```
3
1 2 3
```正しい出力は次のとおりです。```
yes
```1 つのバッグには重み 3 のアイテムを含めることができ、もう 1 つのバッグには重み 1 と 2 を含めることができるためです。両方のバッグに複数のアイテムが必要であると想定した実装は失敗します。 

最後によくある間違いは、項目が個別のオブジェクトであることを忘れていることです。 のために：```
3
100 100 100
```出力は次のとおりです。```
no
```合計は 300 ですが、重みが 150 のサブセットはありません。達成可能な合計を正しく追跡せずに、考えられる重みの合計だけを数えると、誤った結論につながる可能性があります。 

## アプローチ

 直接的なアプローチは、最初のバッグへのアイテムの可能な限りの割り当てを試すことです。 各項目には 2 つの選択肢があるため、$N$これによって作成されるアイテム$2^N$可能な分布。 分布ごとに 1 つのバッグの重量を計算し、それが合計の半分に等しいかどうかを確認できます。 これは、アイテムを分割するあらゆる可能な方法を検討しているため、正しいです。 問題は操作回数です。 と$N = 100$、探索スペースは周囲にあります$1.27 \times 10^{30}$、横断することは不可能です。 

有益な観察は、項目の数ではなく重みが制限要因であるということです。 私たちは、いくつかのアイテムを選択することによって、特定の総重量を形成できるかどうかだけを気にします。 最終的な目標は最大 500 であるため、アイテムを 1 つずつ処理しながら、到達可能なすべての合計を保存できます。 これにより、問題は部分集合和の問題に変わります。 

ブルート フォースは、考えられるすべてのサブセットをチェックするため機能します。 サブセットが多すぎるため失敗します。 合計の重みが小さいという観察により、サブセットの検索を、すべての達成可能な重みを表す動的プログラミング状態に置き換えることができます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^N) | お(1) | 遅すぎる |
 | 動的プログラミング | O(N×S) | O(S) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. すべてのアイテムの重量を読み取り、総重量を計算します。 総重量が奇数の場合は即時出力`no`2 つの等しいバッグには非整数の半分が必要になるためです。 
2. 目標体重を全体の半分とします。 動的プログラミング配列を作成します。`dp[x]`合計重量が正確に一致するいくつかの加工品を選択できることを意味します`x`。 
3.初期化`dp[0]`項目を選択しないと合計がゼロになるため、true となります。 
4. すべてのアイテムの重量を処理します。 考えられる現在の合計額ごとに、この項目を追加することで新しい到達可能な合計額が作成されるかどうかを更新します。 同じ項目が複数回使用されないように、反復は大きい合計から小さい合計まで進む必要があります。 
5. すべての項目が処理されたら、チェックを入れます`dp[target]`。 これが本当であれば、1 つのバッグには正確に目標重量を持つアイテムのサブセットが存在するため、もう 1 つのバッグも自動的に同じ重量になります。 

これが機能する理由: 不変条件は、項目の接頭辞を処理した後、`dp[x]`そのプレフィックスの一部のサブセットが合計の重みを持つ場合に正確に真になります`x`。 最初は、これは空のプレフィックスに当てはまります。 新しいアイテムが考慮されるとき、すべての古い到達可能な合計は、そのアイテムを無視することによって到達可能なままになるか、アイテムを取得することによって新しい到達可能な合計を作成します。 逆方向に更新するため、アイテムを複数回投稿することはできません。 すべてを処理した後のターゲット状態は、有効な最初のバッグが存在するかどうかを正確に表します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n_line = input().strip()
    if not n_line:
        return
    n = int(n_line)
    weights = list(map(int, input().split()))

    total = sum(weights)

    if total % 2:
        print("no")
        return

    target = total // 2
    dp = [False] * (target + 1)
    dp[0] = True

    for w in weights:
        for s in range(target - w, -1, -1):
            if dp[s]:
                dp[s + w] = True

    print("yes" if dp[target] else "no")

if __name__ == "__main__":
    solve()
```ターゲットの状態は最終的なバランス要件によって決定されるため、ソリューションでは最初に合計の重みが計算されます。 奇数の合計チェックにより、不必要な動的プログラミング作業が回避され、不可能なケースが即座に処理されます。 

の`dp`ターゲットを超える合計が有効な答えの一部になることは決してないため、配列には 0 から合計の半分までの値のみが格納されます。 逆ループは実装の重要な詳細です。 ループが上向きに移動すると、同じ反復中に同じ項目を使用して作成された合計に重みが追加される可能性があり、誤って項目を複数回使用できるようになります。 

Python 整数では、保存される最大値が 1000 のみであるため、オーバーフローの懸念はありませんが、配列サイズを制限することで実装が単純かつ効率的に保たれます。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N×S) | 各項目は、ターゲットに達するまでのすべての可能な合計を更新します。ここで、S は総重量限界です。 |
 | スペース | O(S) | DP 配列には、考えられるすべての合計に対して 1 つのブール値が格納されます。 |

 最大合計重みは 1000 にすぎないため、動的プログラミングでは最大で約 100,000 回の遷移が実行されます。 これは十分に制限内です。 

## テストケース```python
import sys
import io

def solution(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n = int(input())
    weights = list(map(int, input().split()))

    total = sum(weights)
    if total % 2:
        return "no\n"

    target = total // 2
    dp = [False] * (target + 1)
    dp[0] = True

    for w in weights:
        for s in range(target - w, -1, -1):
            if dp[s]:
                dp[s + w] = True

    return ("yes" if dp[target] else "no") + "\n"

assert solution("6\n30 100 70 20 1 21\n") == "yes\n"
assert solution("3\n100 100 100\n") == "no\n"

assert solution("1\n1\n") == "no\n"
assert solution("4\n5 5 5 5\n") == "yes\n"
assert solution("5\n1 2 4 8 16\n") == "no\n"
assert solution("6\n1 2 4 8 16 31\n") == "yes\n"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / 1`|`no`| 最小サイズと奇数合計の処理 |
 |`5 5 5 5`|`yes`| 等しい値と直接分割 |
 |`1 2 4 8 16`|`no`| 貪欲な選択が失敗するケース |
 |`1 2 4 8 16 31`|`yes`| 大型ターゲット構築 |

 ## 特殊なケース

 合計が奇数の場合:```
3
1 2 4
```アルゴリズムは合計 7 を計算します。7 は 2 つの等しい整数の重みに分割できないため、次の値が返されます。`no`DP テーブルを構築する前に。 

単品分割の場合:```
3
1 2 3
```目標は 3 です。重みを処理すると、`dp[3]`最後の項目を考慮した後は true になるため、アルゴリズムは戻ります`yes`。 両方のバッグに同じ数のアイテムを入れる必要はなく、同じ重量だけを入れる必要があります。 

重みを繰り返す場合:```
3
100 100 100
```目標は 150 です。DP の状態は 100、200、300 となりますが、150 には決して到達しません。 このアルゴリズムは、合計が偶数であれば十分であると想定するのではなく、その取り決めを正しく拒否します。
