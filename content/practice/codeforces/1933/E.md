 ## 解決策
 ## 問題の理解

 私たちは、複数のランニング トラックにわたる Isaac のトレーニングをモデル化するように求められました。 各トラックは多数の同じ長さのセクションで構成されており、セクションが完了するたびにパフォーマンスが直線的に減少していきます。 最初のセクションは貢献します`u`、2番目`u-1`、3番目`u-2`、 等々。 これは、Isaac が次のセクションよりも多くのセクションを完了した場合を意味します。`u`、一部のセクションでは、増分がマイナスになるため、パフォーマンスが低下する可能性さえあります。 

特定の開始トラックに対して`l`そして価値観`u`、エンディングトラックを選択する必要があります`r`（どこ`l ≤ r ≤ n`) 総合的なパフォーマンスの向上を最大化します。 複数の場合`r`同じ最大ゲインを生成する場合、最小のゲインが選択されます。 各クエリは異なるものを提供します`l`そして`u`、複数のテストケースがあります。 

制約が示すのは、`n`そして`q`それぞれまで上がることができます`10^5`テスト ケースごとに、ただしすべてのテスト ケースの合計が次を超えない`2 * 10^5`。 あらゆる可能性を試す素朴なアプローチ`r`あらゆるクエリに対して`O(n * q)`到達できる時間`10^{10}`最悪の場合、明らかに遅すぎます。 事前計算を使用して各クエリを対数時間またはほぼ一定時間で処理するアプローチが必要です。 

難しい部分には、セクションの合計が次の値を超えた場合の負の増分の処理が含まれます。`u`、複数の場所を結び付けます`r`値は同じ合計ゲインを与えます。 各候補の増分を直接合計する不用意な実装`r`間違った答えが出たり、制限時間を超えたりする可能性があります。 

具体的なエッジケースは次のような場合です。`u`からのセクションの合計より小さい`l`に`n`。 たとえば、次の場合`a = [2, 2, 2]`そして`l = 1, u = 2`、すべてのトラックを終了するとセクションが得られます`[2,2,2]`合計 6 です。パフォーマンスの増分は次のとおりです。`2,1,0,-1,-2,-3`したがって、すべてのセクションが完了する前に最大のゲインが発生します。 すべてのセクションを常に合計する単純なアプローチでは、`r=3`間違っています。 

## アプローチ

 ブルートフォース手法では、考えられるそれぞれのパフォーマンスの合計の向上を計算します。`r`から始まる`l`。 それぞれについて`r`、間のすべてのセクションを合計します。`l`そして`r`増分数を決定し、合計する`u, u-1, ..., u-(total_sections-1)`。 これは正確さに関しては機能しますが、大規模な場合には機能します`n`多くのクエリでは、内側のループが実行される可能性があるため、実用的ではなくなります。`O(n)`クエリごとに、結果は次のようになります`O(n*q)`操作。 

重要な洞察は、トラック セクションのプレフィックスの合計を事前計算することです。 させて`prefix[i]`最初の合計になる`i`トラック。 次に、セクションの合計数は、`l`に`r`は`prefix[r] - prefix[l-1]`。 の合計ゲインは、`S`value で始まるセクション`u`等差級数の公式を使用して計算できます。`u + (u-1) + ... + (u-S+1) = S*u - S*(S-1)//2`。 これにより、接頭辞の合計が準備されたら、連続する部分配列のゲインを O(1) 時間で計算できます。 

ゲイン関数があるので、`G(S) = S*u - S*(S-1)/2`は凹二次方程式です`S`、ゲインは増加しますが、`S ≤ u`そして減少するとき`S > u`。 したがって、ゲインを最大化するには、最小値を見つける必要があります。`r`からの合計セクションが`l`に`r`ちょうどそれ以上か等しい`u`。 これは、プレフィックス合計の二分探索を使用して効率的に実行できます。 クエリごとに、次のように計算します。`target = prefix[l-1] + u`そして最小のものを探します`r ≥ l`そのような`prefix[r] ≥ target`。 もし`prefix[n] < target`、私たちは選びます`r = n`。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n*q) | O(n) | 遅すぎる |
 | プレフィックス合計 + 二分検索 | O(n + q*log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. トラックセクションのプレフィックス合計を事前計算します。 させて`prefix[0] = 0`そして`prefix[i] = prefix[i-1] + a[i-1]`。 これにより、任意のセクション間の合計セクションの O(1) 計算が可能になります。`l`そして`r`。 
2. クエリごとに`(l, u)`、 定義する`current_prefix = prefix[l-1]`。 合計セクションが必要です`S = prefix[r] - current_prefix`できるだけ近くにいること`u`最大ゲインを超えない範囲で可能な限り調整します。 もし`S <= u`、セクションが増えるとゲインが増加します。 もし`S > u`、ゲインが減少し始めます。 
3. 次のプレフィックス合計配列に対して二分検索を実行します。`r = l`に`n`最小のものを見つける`r`そのような`prefix[r] - prefix[l-1] ≥ u`。 そうでない場合`r`存在します、選択してください`r = n`。 
4. これを出力します`r`クエリの答えとして。 構造上、これは`r`を超えない範囲でできるだけ多くのセクションを収集するため、パフォーマンスが最大限に向上します。`u`ゲインを減らす方法で。 

機能する理由: 等差級数ゲインの式は凹型です。 したがって、セクション数を超えると、`u`、セクションを追加すると、合計ゲインが減少します。 二分探索は最初の結果を保証します`r`これは、最小のゲインを選択するという問題の要件を満たし、最大のゲインを達成します。`r`ネクタイの場合。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        prefix = [0] * (n + 1)
        for i in range(1, n+1):
            prefix[i] = prefix[i-1] + a[i-1]
        q = int(input())
        queries = [tuple(map(int, input().split())) for _ in range(q)]
        res = []
        for l, u in queries:
            # binary search for smallest r such that prefix[r] - prefix[l-1] >= u
            low, high = l, n
            ans = n
            target = prefix[l-1] + u
            while low <= high:
                mid = (low + high) // 2
                if prefix[mid] >= target:
                    ans = mid
                    high = mid - 1
                else:
                    low = mid + 1
            res.append(ans)
        print(' '.join(map(str, res)))

if __name__ == "__main__":
    solve()
```このソリューションでは、まず各テスト ケースのプレフィックスの合計を計算します。 次に、バイナリ検索を使用して各クエリが個別に処理され、累積セクション数がそれに達するかそれを超える最初のトラックが検索されます。`u`。 ターゲットは次のように調整されます。`prefix[l-1]`カウントはトラックから始まるので`l`。 これにより、オフバイワンの問題が適切に処理され、最小値が保証されます。`r`が選択されます。 使用する`prefix[n]`上限として、次のことが保証されます。`u`残りのセクションの合計より大きい、`r = n`が選ばれます。 

## 実用的な例

 サンプル 1 の最初のクエリ:`l = 1, u = 8`、トラック`a = [3,1,4,1,5,9]`。 

| r | プレフィックス[r]-プレフィックス[l-1] | ゲインの公式 | 決定 |
 | --- | --- | --- | --- |
 | 1 | 3 | 8+7+6 = 21 | あなたより小さい |
 | 2 | 4 | 8+7+6+5 = 26 | あなたより小さい |
 | 3 | 8 | 8+7+6+5+4+3+2+1 = 36 | あなたに等しい |
 | 4 | 9 | 8+7+6+5+4+3+2+1+0 = 36 | 同じゲイン、小さくない r |

 これにより、アルゴリズムが最初のものを正しく選択することが確認されます。`r`最大のゲインを実現します。 

別の例、3 番目のクエリ:`l=5, u=9`、`a[5..6] = [5,9]`。
