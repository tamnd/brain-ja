 ## 解決策
 ## 問題の理解

 正の整数の配列が与えられます。 移動するたびに、配列から要素を完全に削除することも、要素を 1 つずつインクリメントすることもできます。 私たちの目標は、できるだけ少ない手で配列の合計を 3 で割り切れるようにすることです。 入力は複数のテスト ケースを提供し、それぞれが配列と配列自体の長さを指定します。 出力はテスト ケースごとに 1 つの整数であり、必要な最小移動数を表します。 

この制約は、配列にはテスト ケースごとに最大 100,000 個の要素を含めることができ、すべてのテスト ケースにわたる要素の合計数が 200,000 を超えないことを示しています。 これは、どのソリューションも各テスト ケースに対して線形または線形に近い時間で動作する必要があることを示唆しています。 可能なすべての増加と削除のシーケンスを試すなどの 2 次アプローチでは、時間がかかりすぎます。 

合計がすでに 3 で割り切れる場合、明らかではないエッジ ケースが発生します。 たとえば、配列が次の場合、`[3, 6, 9]`の場合、正解は手数ゼロですが、要素を盲目的に変更する単純なアプローチでは過剰にカウントされてしまいます。 もう 1 つの微妙なケースは、3 で割り切れない単一要素の配列で発生します。`[1]`。 この要素を削除することが唯一の選択肢であり、結果として移動は 1 回になります。 不用意に実装すると、無限にインクリメントしようとしたり、配列を空にする可能性を見落としたりする可能性があります。 

## アプローチ

 ブルートフォース手法では、すべての一連の操作を列挙し、合計が 3 で割り切れるまで要素の削除または要素の増加を繰り返し試行します。 このアプローチは、考えられるすべての組み合わせを検討するため、原則として正しいです。 ただし、計算的には不可能です。 サイズ 100,000 の配列の場合、可能な一連の移動の数が指数関数的に増加するため、この方法は非現実的になります。 

重要な洞察は、3 で割り切れるかどうかは、3 を法とした合計の余りにのみ依存するということです。 モジュロ 3 の等価性を超えて個々の値を追跡する必要はありません。 したがって、次の基準に基づいて要素を 3 つのバケットに分類します。`a[i] % 3`。 させて`c0`3で割り切れる数を数えること、`c1`余りが 1 になる数字のカウント、および`c2`余りが 2 になる数値のカウント。 3 を法とする和は次のようになります。`(c1 + 2*c2) % 3`。 合計の残りに応じて、最小限の操作を決定できます。 

- 3 を法とする合計が 0 の場合、移動は必要ありません。 
- 3 を法とする合計が 1 の場合、1 つの要素を削除して余り 1 にするか、2 つの要素を削除して余り 2 にすることができます。最初のオプションは、可能であれば使用する手数が少なくなります。 
- 3 を法とする合計が 2 の場合、1 つの要素を削除して余り 2 にするか、2 つの要素を削除して余り 1 にすることができます。 

要素を 1 つインクリメントすると、その剰余が予測可能なサイクル (0 → 1 → 2 → 0) で変更されます。戦略的には、増分は、削除が最適でない場合に要素をシフトして合計の剰余を調整することと同じです。 実際には、最小移動数は、残りの合計が 3 の倍数に達するために必要な差となる最小数の要素を削除することに対応します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 配列の合計を計算します。 
2. 計算する`sum % 3`。 ゼロの場合、合計はすでに 3 で割り切れるため、すぐに 0 を返します。 
3. 3 で割ったときの余りが 1 と 2 になる配列の要素の数を数え、それらを呼び出します。`c1`そして`c2`。 
4. 剰余が 1 の場合、次の戦略を試みます。剰余 1 で 1 つの要素を削除するか、剰余 2 で 2 つの要素を削除します。最小限の削除で可能なオプションを選択します。 どちらも不可能な場合は、すべての要素 (唯一残っているフォールバック) を削除します。 
5. 剰余が 2 の場合、同様の戦略が適用されます。剰余 2 で 1 つの要素を削除するか、剰余 1 で 2 つの要素を削除します。再度、実行可能な最小限のオプションを選択します。 
6. これらの戦略によって決定された手の数を返します。 

正確さを保証する不変条件は、剰余に直接影響を与える要素を削除または増分することによって、3 を法とする和を修正できるということです。 すべての要素がその剰余に寄与し、3 を法とする和は配列全体で線形であるため、最小移動カウントは、説明したように 1 つまたは 2 つの要素を削除することに対応します。 インクリメント操作は、要素を 1 つの剰余バケットから次のバケットに移動することと同等であり、同じ最小カウント ロジックに準拠します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def min_moves_to_div3(arr):
    total = sum(arr)
    rem = total % 3
    if rem == 0:
        return 0

    c1 = sum(1 for x in arr if x % 3 == 1)
    c2 = sum(1 for x in arr if x % 3 == 2)

    if rem == 1:
        if c1 >= 1:
            return 1
        elif c2 >= 2:
            return 2
        else:
            return len(arr)
    else:  # rem == 2
        if c2 >= 1:
            return 1
        elif c1 >= 2:
            return 2
        else:
            return len(arr)

t = int(input())
for _ in range(t):
    n = int(input())
    arr = list(map(int, input().split()))
    print(min_moves_to_div3(arr))
```最初のセクションでは、3 を法とする和と剰余を計算します。 次のセクションでは、要素を剰余によってカウントします。 条件付きロジックは、合計を調整するために必要な最小の削除数を選択します。 最後のループは、複数のテスト ケースを効率的に処理します。 境界の考慮事項には、要素が 1 つある配列 (要素の削除が必要になる場合がある)、およびすべての要素が 3 で割り切れるため、移動がゼロになる配列が含まれます。

 ## 特殊なケース

 単一要素配列の場合`[1]`、合計は 1 です。3 を法とした剰余は 1 です。アルゴリズムは次のようにチェックします。`c1 >= 1`これは true であり、1 を返します。これは、可能な唯一のアクション、つまり要素の削除と一致します。 

配列の場合`[3, 3, 3]`、合計は 9 です。剰余は 0 であるため、アルゴリズムはすぐに 0 を返し、手は必要ないことを正しく識別します。 

のために`[1, 1, 2, 2, 2]`、合計は 8 です。余りは 2 です。余りのある要素が 3 つあります。
