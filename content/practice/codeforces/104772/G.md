 ## 問題の理解

 私たちに与えられているのは合計です$n$石。 Georgiy はまず 1 つのサイズの山を修正します$p$そして、Gennady が残りを分割します。$N = n - p$石を正の整数の山サイズのマルチセットに分割します。 

分割が修正された後、すべてのパイルが Nim ゲームに参加し、勝者はすべてのパイル サイズの XOR によって決定されます。 Georgiy が最初に動きますが、ゲームを標準の Nim 条件に変換すると、その詳細は無関係になります。つまり、すべての山のサイズの XOR がゼロになると、最初のプレイヤーが正確に負けます。 

Georgiy はすでに大量のサイズを提供しているため、$p$、ゲンナディが勝つための条件は、彼のパーティションに対する純粋な制約になります。 Gennady のパイル サイズを次のように表すと、$a_1, a_2, \dots, a_k$の場合、勝利条件は次のようになります。$$p \oplus a_1 \oplus a_2 \oplus \dots \oplus a_k = 0,$$これは以下と同等です$$a_1 \oplus a_2 \oplus \dots \oplus a_k = p.$$したがって、タスクは純粋に組み合わせです。順序のないパーティションがいくつあるかを数えます。$N = n - p$部分の XOR が次と等しくなるように存在します。$p$。 

制約$n \le 500$合計に対する動的計画法に基づいた解決策を即座に提案します。 問題は、合計制約自体ではなく、単純なパーティション DP で独立して処理できないようにすべての部分を結合する追加の XOR 制約です。 

単純なアプローチでは、すべてのパーティションを列挙します。$N$。 たとえ$N = 50$、パーティションの数はすでに数万に達しており、$N = 500$天文学的な大きさになります。 2 番目の単純なアイデアは、各パイル サイズを DP オーバー カウントで独立して処理することですが、XOR は非ローカルな方法で出現のパリティに依存します。 

微妙なエッジケースが現れるのは、$p = 0$。 次に、パーティションを数えています$N$その XOR はゼロです。 もう一つのコーナーケースは、$N = 0$ここで、「空のパーティション」が 1 つだけ存在し、その XOR が 0 であるため、答えは次のようになります。$1$もし$p = 0$、 さもないと$0$。 

## アプローチ

 ブルート フォース ソリューションでは、合計する正の整数のマルチセットがすべて生成されます。$N$、それらの XOR を計算し、次と等しいものを数えます。$p$。 すべてのパーティションが 1 回だけ考慮されるため、これは概念的には機能しますが、パーティションの数は急激に増加します。$\sqrt{N}$。 のために$N = 500$、これは実行可能な計算をはるかに超えています。 

重要な観察は、XOR がパリティに対して線形に動作するということです。 数字の場合$k$表示されます$c_k$回の場合、XOR への寄与は次のようになります。 

k \oplus k \oplus \dots \text{(c_k 回)} = \begin{ケース} 0 & c_k \text{ 偶数} \\ k & c_k \text{ 奇数} \end{ケース}

 したがって、XOR では各多重度のパリティのみが重要ですが、合計制約では実際の多重度が依然として重要です。 

これは、各値の寄与を分割することを示唆しています。$k$2 つの独立した選択肢に分けられます。「偶数のコピー」$k$」または「奇数部の$k$」、のペアによって追加の余裕が提供されます。$k$、各ペアの合計が増加します$2k$XORを変更せずに。 

これにより、問題が階層化されたナップザックに変換され、各値が$k$無制限のサイズステップ数に貢献します$2k$、オプションで 1 つの追加で XOR を切り替えます。$k$。 

DP over sum と XOR 値を維持します。 各ステップは、固定されたすべての発生を処理します。$k$のコピーを使用して合計を計算するすべての方法を更新します。$k$、の合計数かどうかを追跡しながら、$k$使用されるのは偶数または奇数です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 | パーティションを列挙する | 指数 | O(N) | 遅すぎる |

 ここ$X$XOR 値の範囲です。$2^9 = 512$以来$p < 500$。 

## アルゴリズムのチュートリアル

 これまでに処理されたパイル サイズを使用して、指定された XOR で指定された和を形成する方法が何通りあるかを追跡する DP 状態を定義します。 

1. しましょう$N = n - p$。 DP テーブルを初期化します`dp[s][x]`、合計を形成する方法の数を意味します$s$XOR値あり$x$許可されたパイル サイズの一部のサブセットを使用します。 当初は、`dp[0][0] = 1`。 
2. パイルサイズを反復します$k = 1$に$N$。 各ステップで、すべてのサイズが組み込まれます。$k$。 
3.固定の場合$k$では、構造を 2 つの概念的なグループに分けます。 最初のグループでは、偶数の$k$の倍数のみを貢献します$2k$合計に変換されますが、XOR は変更されません。 2 番目のグループでは、奇数の$k$'、これは偶数の場合のように動作しますが、追加の強制が追加されます。$k$合計に加算され、XOR が反転されます。$k$。 
4. まず、偶数カウントのみが発生する遷移を計算します。$k$が使用されています。 これは、コインが入っている無制限のナップザックに相当します。$2k$、XOR 状態ごとに独立して適用されます。 
5. 次に、偶数の結果の状態を取得し、合計を だけシフトすることで、奇数の場合に同じ構造を再利用します。$k$、そして XOR を切り替える$k$、その後も任意の数を許可します$2k$その上に追加。 
6.すべての処理が完了したら$k$、最終的な答えは`dp[N][p]`、合計が必要なので$N$XOR は Georgiy の山に等しい。 

### なぜ効果があるのか

 すべての段階で、それぞれの整数$k$は独立して処理され、そのすべての有効なマルチセットがカウントされます$k$は、偶数のベースラインと特定の数のペア、または奇数のベースラインと特定の数のペアのいずれかとして一意に表されます。 ペア構造により、合計の寄与がサイズのステップごとに完全に捕捉されることが保証されます。$2k$一方、XOR はベースラインが偶数か奇数かのみに依存します。 この分離により、構成が欠落することはなく、二重にカウントされることもありません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, p, mod = map(int, input().split())
    N = n - p

    if N == 0:
        print(1 % mod if p == 0 else 0)
        return

    MAXX = 512

    dp = [[0] * MAXX for _ in range(N + 1)]
    dp[0][0] = 1

    for k in range(1, N + 1):
        # next DP starts as current dp (we will rebuild it)
        ndp = [[0] * MAXX for _ in range(N + 1)]

        for s in range(N + 1):
            for x in range(MAXX):
                val = dp[s][x]
                if not val:
                    continue

                # even contribution: add 0, 2k, 4k, ...
                t = s
                while t <= N:
                    ndp[t][x] = (ndp[t][x] + val) % mod
                    t += 2 * k

                # odd contribution: add k + 0, 2k, 4k, ...
                t = s + k
                x2 = x ^ k
                while t <= N:
                    ndp[t][x2] = (ndp[t][x2] + val) % mod
                    t += 2 * k

        dp = ndp

    print(dp[N][p] % mod)

if __name__ == "__main__":
    solve()
```このコードは、考えられる各パイル サイズを順番に処理する構造に従います。 以前に到達可能な状態ごとに、質量を段階的に分配します。$2k$、サイズの杭のペアを追加することに対応します$k$。 2 番目のループは、少なくとも 1 つの$k$が使用され、XOR を反転して合計をシフトします。$k$その後、さらにペアを自由に追加できます。 

合計、XOR、およびステップ サイズに対するネストされたループは、偶数と奇数の多重度への概念的な分解を直接実装したものです。 

## 実用的な例

 ### サンプル 1

 入力:```
8 3 1000
```ここ$N = 5$、ターゲット XOR は$p = 3$。 

合計が 5 に達する状態のみを追跡します。DP は 5 のパーティションを徐々に構築し、その中で 3 に等しい XOR を生成するマルチセットは 2 つだけです。 

一つは$[3,1,1]$、もう一つは$[2,1,1,1]$。 

最終的な関連する状態のコンパクトなトレース:

 | 合計 | XOR 値 | 貢献度をカウント |
 | --- | --- | --- |
 | 5 | 3 | 2 |

 したがって、答えは 2 です。 

### サンプル 2

 入力:```
5 2 1000
```ここ$N = 3$、ターゲット XOR は 2 です。 

3 のすべてのパーティションは次のとおりです。$[3], [2,1], [1,1,1]$それらの XOR 値は次のとおりです。$3, 2 \oplus 1 = 3, 1 \oplus 1 \oplus 1 = 1$2 に等しいものはないため、答えは 0 になります。 

これは、パーティションが多数存在する場合でも、XOR 制約によりすべての可能性を排除できることを示しています。

 ## 特殊なケース

 いつ$N = 0$、山を形成するための空の方法が 1 つだけあります。 DP は正しく初期化されます`dp[0][0] = 1`、遷移が発生しないため、次の場合に限り、結果は 1 になります。$p = 0$、それ以外の場合は 0。 

いつ$p = 0$、ターゲット XOR はゼロです。 この場合、DP 構造は単純化されませんが、最終的なルックアップが次のように変更されます。`dp[N][0]`これには、XOR が内部でキャンセルされるすべてのパーティションが当然含まれます。 

いつ$k > N$、そのためのトランジションはありません$k$残りの合計を超えるサイズの山は形成できないため、貢献します。 ループ構造はこれらの寄与を自然にスキップします。`s + k`または`s + 2k`限界を超える。
