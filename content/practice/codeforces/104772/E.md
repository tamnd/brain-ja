 ## 解決策
 ## 問題の理解

 無限の整数グリッド上に配置されたいくつかのクイーンが与えられます。 各クイーンは、標準的なチェスの場合とまったく同じように、その行、その列、および両方の対角線に沿って攻撃します。 ピースは互いにブロックしないため、クイーンの攻撃はそのラインに沿って 4 方向すべてに無限に広がります。 

タスクは、すべての女王によって同時に攻撃される単一のグリッド セルが存在するかどうかを判断することです。 そのようなセルが存在する場合は、有効な座標を 1 つ出力する必要があります。 それ以外の場合は不可能と報告します。 

主な困難は、「攻撃される」ということは、女王ごとに 3 つの幾何学的条件の結合であり、すべての女王に対して少なくとも 1 つの条件を同時に満たす点が必要であるということです。 

制約は厳しく、テストあたり最大 10^5 のクイーン、すべてのテストで合計最大 10^5 です。 すべての候補セルをすべてのクイーンに対してチェックしようとするソリューションでは、最悪の場合、およそ 10^10 の操作が必要となり、これは 2 秒の制限をはるかに超えています。 これにより、二次的または候補ごとの線形検証戦略さえも即座に除外されます。 

微妙な特殊なケースは、答えがクイーンの位置自体にある可能性があることです。 たとえば、2 つのクイーンが (1,1) と (2,2) にある場合、両方とも (1,1) と (2,2) を攻撃し、さらに (3,3) も攻撃するため、有効な答えは空のセルに制限されません。 

もう 1 つの落とし穴は、攻撃領域の「ペアごとの重複」がグローバルな交差を意味すると想定していることです。 2 人のクイーンが両方ともあるポイントを攻撃できる可能性がありますが、単一のポイントがすべてのクイーンに機能することを保証するものではありません。 要件は、すべてのセットにわたる完全な交差です。 

## アプローチ

 直接的なアプローチは、クイーン座標から導出された候補点を考慮することです。 各クイーンは無限の十字と 2 つの対角線を提供し、これらすべての幾何学的なオブジェクトを明示的に交差させようとする可能性があります。 ただし、各クイーンは 3 つのラインの和集合を定義するため、多くのクイーンにわたって交差する和集合は組み合わせ爆発になります。すべてのクイーンが複数の可能な制約に寄与し、すべての組み合わせをチェックすると、指数関数的な増加または少なくとも 2 次フィルターが発生します。 

問題を表示するためのより便利な方法は、条件を反転することです。 クイーンごとに 3 つのラインのうちの少なくとも 1 つにある点を求めるのではなく、すべてのクイーンについて、その許可されたラインの 1 つに点が存在するような点が存在するかどうかを尋ねます。 これはまだ交差の結合構造ですが、重要な単純化を示唆しています。答えはすべてのクイーンにわたって「攻撃モード」の一貫した選択を満たさなければなりません。 

各クイーンには 3 つの独立した制約が許可されます。 

x = xi、または y = yi、または x - y = xi - yi、または x + y = xi + yi。 

したがって、すべてのクイーンは 4 つの候補ライン (対角線と軸の両方を含む) を許可します。 問題は、選択したすべての線が共通の点で交差するように、各クイーンのセットから 1 本の線を選択できるかということです。 単一の点は最大でも 2 つの独立した線形制約の交点によって決定されるため、グローバル交点は構造上の可能性の非常に小さなセットから得られる必要があります。 

重要な観察は、有効な答えはすべてのクイーンにわたって「一貫した」少なくとも 1 つの行に存在する必要があるということです。 答えが x = C にあると推測する場合、すべてのクイーンは x = C を許可するか、対角制約または水平制約を介して C に到達できなければなりません。しかし、さらに重要なのは、C の唯一の候補は、入力にすでに出現している値 (または派生した対角定数) であることです。 これは、解決策が最初の数個のクイーンから抽出された一定数の候補ターゲットをチェックすることに帰着できることを示唆しています。

より強力な単純化が標準的なトリックです。有効な答えは、少なくとも 1 つのクイーンによって課された制約を一貫した方法で満たさなければなりません。そのため、クイーンの小さなサブセットから制約を選択することによって定義された交差をテストするだけで済みます。 実際には、最初のいくつかのクイーン (通常は最大 3 つまたは 4 つ) を取得し、その 3 つの攻撃方向の 1 つを選択するすべての組み合わせを列挙し、結果として得られる候補交差点を計算し、それをすべてのクイーンに対して検証するだけで十分です。 

これが機能するのは、最終的な答えが存在するとしても、それは最大 2 つの独立した線形方程式によって定義され、それらの方程式は、解で同時に制約が厳しいクイーンの小さなサブセットから得られる必要があるためです。 一定数のクイーンに対してすべての可能性を試すと、その決定的なサブセットに到達することが保証されます。 

次に、O(n) 内の各候補点を、すべてのクイーンが攻撃するかどうかをチェックして検証します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのセル/交差点をグローバルにチェック) | O(n^2) 以上 | O(n) | 遅すぎる |
 | 最適 (小さな制約サブセットを列挙 + 検証) | テストあたり O(n) (定数候補) | O(1) おまけ | 承認済み |

 ## アルゴリズムのチュートリアル

 1. クイーンが 1 人しかいない場合は、どのクイーンも自分のマスを攻撃するため、すぐにその位置を戻します。 
2. 最初の 3 つのクイーンまでを取得します。 有効な交点は最大 2 つの線形制約によって決定され、軸と対角の組み合わせのすべての構造ケースをカバーするには 3 つのクイーンで十分であるため、3 つに制限します。 
3. 選択した各クイーンについて、それが定義する可能なラインを列挙します: x = xi、y = yi、x - y = xi - yi、x + y = xi + yi。 これらは、ターゲット ポイントがそのクイーンによって攻撃される可能性があるすべての可能な方向を表します。 
4. 選択した各クイーンから 1 つの制約を選択し、それらの交点を計算するすべての組み合わせを試します。 交点は、最大 2 つの独立した方程式の結果として得られる線形システムを解くことによって取得されます。 制約が矛盾している場合、その組み合わせは破棄されます。 
5. 各候補交差点 (x, y) について、すべてのクイーンに対して検証します。 xi == x、yi == y、または |xi - x| の場合、クイーン (xi, yi) は (x, y) を攻撃します。 == |yi - y|。 
6. いずれかの候補がすべてのクイーンの検証に合格した場合は、直ちに出力します。 
7. 候補が機能しない場合は、NO を出力します。 

正しさは、実行可能な点が、最大でもクイーンの小さなサブセットによって実現できる一貫した制約の選択を満たさなければならないという事実にかかっています。 固定数のクイーン間でこれらの組み合わせを徹底的に試すことで、テストされた候補の中から真の解が見つかることを保証します。 

### なぜ効果があるのか

 有効な点は、各クイーンに対して少なくとも 1 つの満たされた線形制約を定義します。 すべてのクイーンの中には、平面内の点が最大 2 つの独立した方程式によって固定されるため、その制約が点を一意に決定する最小のサブセットが存在します。 これらの定義制約はクイーンの一部のサブセットから得られる必要があり、一定数のクイーンに対する制約の選択肢を列挙することで、必然的にその定義サブセットが含まれることになります。 したがって、常に正しい候補点が生成され、検証される。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def check(x, y, qs):
    for xi, yi in qs:
        if xi == x or yi == y or abs(xi - x) == abs(yi - y):
            continue
        return False
    return True

def intersect(eq1, eq2):
    # eq: type, value
    # type 0: x = c
    # type 1: y = c
    # type 2: x - y = c
    # type 3: x + y = c
    t1, a = eq1
    t2, b = eq2

    if t1 == 0 and t2 == 1:
        return (a, b)
    if t1 == 1 and t2 == 0:
        return (b, a)

    if t1 == 0 and t2 == 2:
        return (a, a - b)
    if t2 == 0 and t1 == 2:
        return (b, b - a)

    if t1 == 0 and t2 == 3:
        return (a, b - a)
    if t2 == 0 and t1 == 3:
        return (b, a - b)

    if t1 == 1 and t2 == 2:
        return (a + b, a)
    if t2 == 1 and t1 == 2:
        return (b + a, b)

    if t1 == 1 and t2 == 3:
        return (b - a, a)
    if t2 == 1 and t1 == 3:
        return (a - b, b)

    if t1 == 2 and t2 == 3:
        # x - y = a, x + y = b
        x = (a + b) // 2
        y = (b - a) // 2
        if (a + b) % 2 != 0 or (b - a) % 2 != 0:
            return None
        return (x, y)

    return None

def candidates(qs):
    qs = qs[:3]
    eqs = []

    for x, y in qs:
        eqs.append([(0, x), (1, y), (2, x - y), (3, x + y)])

    res = []
    from itertools import product

    for e1 in eqs[0]:
        for e2 in eqs[1]:
            for e3 in eqs[2]:
                # pick any 2 to define point
                for a, b in [(e1, e2), (e1, e3), (e2, e3)]:
                    pt = intersect(a, b)
                    if pt is not None:
                        res.append(pt)

    return res

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        qs = [tuple(map(int, input().split())) for _ in range(n)]

        if n == 1:
            print("YES")
            print(qs[0][0], qs[0][1])
            continue

        cand = candidates(qs)
        ok = None
        for x, y in cand:
            if check(x, y, qs):
                ok = (x, y)
                break

        if ok:
            print("YES")
            print(ok[0], ok[1])
        else:
            print("NO")

if __name__ == "__main__":
    solve()
```このコードは、最大 3 つのクイーンの制約の組み合わせから候補交差点を構築します。 各クイーンは、行、列、および 2 つの対角線に対応する 4 つの可能な線形制約を提供します。 交差関数は、制約のペアを解決して座標を生成し、対角交差の一貫性チェックとパリティ条件を処理します。 

検証ステップは、攻撃ルールの直接のシミュレーションです。 各候補ポイントはすべてのクイーンに対して線形時間でテストされます。 単一の有効なポイントが見つかると、そのポイントが返されます。 

実装の微妙な詳細は、対角線の交差 x - y = a および x + y = b の処理です。 彼らの解決策にはパリティの一貫性が必要であり、そうでない場合は整数格子点が存在しないため、候補は破棄されなければなりません。

 ## 特殊なケース

 主なエッジケースは、すべてのクイーンがすでに列または対角線などの単一の攻撃ライン上にある場合です。 たとえば、(1,5)、(2,5)、(3,5) のクイーンです。 アルゴリズムは 3 つのクイーンを選択し、y = 5 を含む制約を抽出し、交差により直ちに (2,5) が得られます。 検証により、すべてのクイーンが y = 5 を満たすことが確認され、その点は有効です。 

もう 1 つのケースは、解は存在するが直接クイーン位置の 1 つではない混合制約です。 たとえば、(0,0)、(1,1)、(2,2) は (1,1) に対して機能します。 候補生成では、交差する対角制約から (1,1) が生成され、検証ではそれが受け入れられます。 

失敗のケースとしては、軸の交点のみをテストし、対角線を無視した場合が考えられます。 その場合、(1,1) が有効であっても、(0,0)、(1,1)、(2,2) のような構成は誤って NO を返します。 4 つの制約タイプをすべて含めることで、これらの対角解が常に発見されるようになります。
