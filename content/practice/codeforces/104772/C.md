 ## 解決策
 ## 問題の理解

 私たちに与えられた木は、$2n$頂点。 各頂点には色が割り当てられており、すべての色が正確に 2 回表示されるため、頂点は自然にグループ化されます。$n$素のペア。 グラフは接続されており、正確に$2n-1$エッジがあるので木です。 

タスクは、各色のペアから頂点を 1 つだけ選択し、セットを生成することです。$S$サイズの$n$。 ただし、この選択は自由ではありません。元のツリーを見て、選択した頂点は接続された部分グラフを形成する必要があり、その頂点のみに制限されます。$S$。 ツリーでは、これは、選択された 2 つの頂点の間に、それらを接続する一意のパスが完全に内側に存在する必要があることを意味します。$S$。 

出力は次のいずれかのセットになります。$n$頂点、または有効な選択が存在しないという宣言。 

制約は厳しく、すべてのテスト ケースにわたる頂点の合計数は最大です。$2 \cdot 10^5$したがって、どのようなソリューションもテストごとに本質的に線形であるか、全体的に償却が線形である必要があります。 サブセットに対する繰り返しの検索や、多数の候補セットの接続性の再計算を伴うものは拡張できません。 

微妙な失敗例は、色の選択を独立して扱うことから発生します。 たとえば、色のペアがツリー内の「狭い橋」の反対側にある場合、1 つのエンドポイントを選択すると、個々の選択がローカルで有効に見えても、将来の選択が切断される可能性があります。 もう 1 つの落とし穴は、ペアごとに 1 つのエンドポイントの選択を後で調整して接続を強制できると想定していることです。これは、接続が選択されたすべての頂点のグローバルな相互作用に依存するため、誤りです。 

具体的な問題のあるシナリオは、ペアがインターリーブされる長いチェーンです。```
1 - 2 - 3 - 4 - 5 - 6
colors: (1,4), (2,5), (3,6)
```任意に選択すると、次のようなセットが強制される可能性があります`{1,5,6}`、「ペアごとに 1 つ」ルールを遵守しているにもかかわらず、誘導されたサブグラフでは接続されていません。 

## アプローチ

 接続要件を無視する場合、問題は簡単です。単に各ペアから 1 つのエンドポイントを任意に選択するだけです。 この難しさは、選択した頂点が接続されたサブグラフを確実に誘導することに完全に起因しています。 

強引なアイデアは、ペアごとに 1 つのエンドポイントのすべての選択肢を試して、次のようにすることです。$2^n$候補セット。 各候補について、誘導された部分グラフが接続されているかどうかを確認します。$O(n)$DFS または BFS は選択したノードに制限されます。 これは次のことにつながります$O(n 2^n)$これは、中程度の場合でも実現可能な限界をはるかに超えています。$n$。 

重要な構造的洞察は、ツリーにおいて、頂点セットが接続されたサブツリーの頂点セットを正確に形成する場合にのみ、頂点セットが接続されたサブグラフを誘導するということです。 したがって、恣意的な選択という観点から考える代わりに、サイズの関連コンポーネントを切り出すという観点から考えることができます。$n$木から。 

次に、色の制約を再解釈します。各色のペアは、選択したコンポーネントに 1 つの頂点を正確に提供する必要があります。 つまり、すべてのペアは、選択したコンポーネントとツリーの残りの部分の間の境界を越えて分割する必要があります。 したがって、サイズの接続されたコンポーネントを探します$n$すべてのペアの内側に 1 つのエンドポイントがあり、外側に 1 つずつエンドポイントがあります。 

これにより、問題は、2 つのサイズの部分に分割された木の接続されたカットを見つけることに変わります。$n$そして$n$一方で、色のペアが片側の内側に完全に存在しないようにすることも強制します。 ツリー構造により、単一のルートと貪欲な伝播戦略の使用についての推論が可能になります。すでに選択されたエンドポイントによって引き起こされる強制的な包含と除外を尊重しながら、候補の接続セットを成長させます。

 ## アルゴリズムのチュートリアル

 どの色のペアの両方のエンドポイントも決して取得しないようにしながら、接続されたコンポーネントを段階的に構築することでソリューションを構築します。 

1. 接続セットの開始点として任意のノードを選択します$S$。 このノードは以下に含まれています$S$、成長するコンポーネントを固定します。 
2. エッジ離脱のフロンティアを維持する$S$、ノードを接続するエッジを意味します。$S$外部のノードへ$S$。 グラフはツリーであるため、このフロンティアは常に明確に定義されており、非循環的です。 
3. 拡張を繰り返し試みる$S$色の制約に違反しないフロンティア ノードを選択します。 ある色のノードを含めることを決定した場合、その色のもう一方のエンドポイントは直ちに禁止としてマークされます。 
4. 禁止ノードがすでに内部にある場合$S$、現在の構築パスは無効なので、別の初期ノードから再起動する必要があります。 
5. まで拡張を続けます。$|S| = n$。 常にツリーの端を通って拡張するため、$S$建設により保存されています。 

重要な決定ルールは、頂点を含めようとするときはいつでも、その色のペアになっている頂点がすでに内側にあるかどうかを確認することです。$S$。 そうであれば、私たちはその選択を拒否します。 そうでない場合は、それを含め、そのパートナーを禁止します。 

### なぜ効果があるのか

 いつでも、$S$現在のセットに隣接する頂点のみを追加するため、これは接続されたセットです。 カラー ルールにより、頂点を選択するとそのパートナーが将来の包含から永久に除外されるため、「ペアごとに 1 つだけ」という制約に違反しないことが保証されます。 プロセスは常に隣接関係を尊重するため、内部で切断が発生することはありません。$S$。 有効なソリューションが存在する場合、サイズに達する前に行き詰ることなく、部分的に有効な接続セットを拡張する方法が常にあります。$n$ツリー構造により、残りの有効な選択肢がすべて分離されていない限り、部分コンポーネントを少なくとも 1 つの境界エッジを通して展開できることが保証されるためです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
from collections import deque

def solve():
    n = int(input())
    c = list(map(int, input().split()))
    
    g = [[] for _ in range(2*n)]
    for _ in range(2*n - 1):
        u, v = map(int, input().split())
        u -= 1
        v -= 1
        g[u].append(v)
        g[v].append(u)
    
    pos = [[] for _ in range(n + 1)]
    for i, col in enumerate(c):
        pos[col].append(i)
    
    # try each endpoint of first color-pair as starting root candidate
    for start in pos[c[0]]:
        S = set([start])
        forbidden = set([pos[c[start]][0] ^ pos[c[start]][1] ^ start])
        
        q = deque([start])
        inq = [False] * (2*n)
        inq[start] = True
        
        while q and len(S) < n:
            u = q.popleft()
            for v in g[u]:
                if v in S or v in forbidden:
                    continue
                col = c[v]
                a, b = pos[col]
                other = a if b == v else b
                if other in S:
                    continue
                S.add(v)
                forbidden.add(other)
                q.append(v)
                if len(S) == n:
                    break
        
        if len(S) == n:
            print(*[x + 1 for x in S])
            return
    
    print(-1)

t = int(input())
for _ in range(t):
    solve()
```この実装では、BFS スタイルの拡張を使用して、増大する接続セットを維持します。 の`S`set は選択した頂点を保存しますが、`forbidden`これにより、色のペアの両方の端点を誤って取得することがなくなります。 頂点が追加されるたびに、そのペアの頂点は今後の検討から直ちに除外されます。 

微妙な点は、展開順序が重要なのは実現可能性のみであり、見つかった解決策の正しさではないということです。 BFS キューは、接続を維持しながら、現在到達可能な境界頂点を介して常に拡張することを保証するだけです。 

外側のループは、最初の色の終点の間で異なる開始点を試みます。 これは、最終的に接続されたコンポーネントを最初のペアの特定の側から開始する必要がある可能性があるため、誤ったルート選択に早期にコミットすることを避けるための実用的な方法です。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    def solve():
        n = int(input())
        c = list(map(int, input().split()))
        g = [[] for _ in range(2*n)]
        for _ in range(2*n - 1):
            u, v = map(int, input().split())
            u -= 1; v -= 1
            g[u].append(v)
            g[v].append(u)

        pos = [[] for _ in range(n + 1)]
        for i, col in enumerate(c):
            pos[col].append(i)

        for start in pos[c[0]]:
            S = set([start])
            forbidden = set()
            a, b = pos[c[start]]
            forbidden.add(b if a == start else a)

            q = deque([start])

            while q and len(S) < n:
                u = q.popleft()
                for v in g[u]:
                    if v in S or v in forbidden:
                        continue
                    col = c[v]
                    a, b = pos[col]
                    other = a if b == v else b
                    if other in S:
                        continue
                    S.add(v)
                    forbidden.add(other)
                    q.append(v)
                    if len(S) == n:
                        break

            if len(S) == n:
                return " ".join(str(x+1) for x in S)

        return "-1"

    t = int(input())
    out = []
    for _ in range(t):
        out.append(solve())
    return "\n".join(out)

 ## 特殊なケース

 エッジ ケースの 1 つは、色の両方の端点が、接続されているサイズのサブツリーが存在しないような位置にある場合です。$n$必然的に両方が含まれることになります。 そのような状況では、1 つのエンドポイントを選択すると、実行可能なすべての境界移動がブロックされるため、すべての拡張戦略は最終的に行き詰まります。 

もう 1 つのエッジ ケースは、多くの色が中心の周りに集中している星形のツリーです。 センターの選択を誤ると、複数の禁止されたエンドポイントが早期に強制的に組み込まれ、拡張性が損なわれる可能性があります。 アルゴリズムは、代替の開始エンドポイントから再開することでこれを処理し、少なくとも 1 つの実行可能な成長方向が探索されるようにします。 

最後のエッジケースは、有効なソリューションが「細い」パス状のサブツリーとしてのみ存在する場合に発生します。 ここで、貪欲な拡張では、分岐が早すぎることを避ける必要があります。そうしないと、後で矛盾を強制する頂点が消費されてしまいます。 BFS スタイルの拡張は、利用可能な境界エッジに沿ってのみ拡張し、接続によって強制されない限り、不連続な分岐には決してコミットしないため、引き続き成功します。
