 ## 解決策
 ## 問題の理解

 私たちには兵士のグループがあり、それぞれのランクは次のとおりです。`1`そして`k`。 1 回の訓練セッション中に、兵士は同じ階級ごとにグループ化されます。 順位がまだ下位のすべてのグループから`k`、ちょうど 1 人の兵士が 1 レベルずつ昇進します。 

重要な詳細は、昇進が兵士ごとではなく、個別のランクごとに行われることです。 ランクのある兵士が5人いる場合`2`、そのうちの1つだけがランクになります`3`セッション中。 

入力により、現在のランクがソートされた順序で表示されます。 すべての兵士が階級に達するまでに必要な訓練セッションの数を計算する必要があります`k`。 

制約は非常に小さく、最大でも`100`兵士と`100`可能なランク。 すべてのトレーニング セッションを直接シミュレーションしても、制限内に簡単に収まります。 それでも、興味深いのは、プロセスの構造を理解し、それをきれいな計数式に落とし込むことです。 

よくある間違いは、各兵士は独立して処理できると考えることです。 プロモーションはグループ化を通じて相互作用するため、これは失敗します。 例えば：```
3 3
1 1 1
```正しい答えは、`6`、 ない`3`。 

プロセスは次のようになります。```
1 1 1
1 1 2
1 2 2
1 2 3
2 2 3
2 3 3
3 3 3
```ランク上の兵士は 1 人だけ`1`すべてのランク 1 の兵士は同じグループに属しているため、各セッション中に移動できます。 

一部の兵士がすでにランクを持っている場合、別の簡単なバグが発生します`k`。```
4 5
5 5 5 5
```答えは`0`。 

ランクがすでに最大であるかどうかを確認せずに常にグループをカウントする不注意な実装では、誤って不要なセッションが追加されてしまいます。 

ランクが欠落しているという特殊なケースもあります。```
4 5
1 1 4 4
```答えは`4`。 

シーケンスは次のようになります。```
1 1 4 4
1 2 4 5
1 3 5 5
2 4 5 5
3 5 5 5
4 5 5 5
5 5 5 5
```素朴な直観では、中間ランクが空になったらランク 1 の兵士 2 人が一緒に移動すると予想するかもしれませんが、グループ化ルールにより、昇進は既存のランク グループごとに 1 人の兵士に制限されています。 

## アプローチ

 最も直接的な解決策は、説明どおりにプロセスを正確にシミュレートすることです。 

すべてのトレーニング セッションで、以下のすべての個別のランクをスキャンします。`k`。 このような各ランクから、1 人の兵士を次のランクに昇進させます。 すべての兵士がなるまで繰り返します`k`。 

これが機能するのは、プロセスが決定的であるためです。 すべてのステップで、現在のランクのマルチセットが一意に次の状態を決定します。 

最悪の場合でも、シミュレーションは十分に高速です。 すべてだとします`100`兵士は階級から始まります`1`そして`k = 100`。 セッション数は以下の通り`10000`、各セッションの処理は最大でも`100`ランク。 これはわずか約 100 万回の操作にすぎません。 

それでも、このプロセスにはもっと単純なパターンが隠されています。 

一人の兵士に焦点を当てます。 兵士が現在階級を持っている場合`x`、彼は得をする必要があります`k - x`終了前にプロモーション。 すべての兵士を合計すると、必要な個々の昇進の合計数が得られます。 

ここで、1 つのトレーニング セッションが何を行うかを見てみましょう。 セッション中、最大以外のランクはすべて 1 つのプロモーションに貢献します。 つまり、1 つのセッションで実行されるプロモーションの合計数は、以下の個別のランクの数と同じになります。`k`。 

最初は、これだけでは答えを直接導き出すのに十分ではないようです。 重要な観察は、このプロセスでは常に、アクティブなグループの数だけランクの合計が増加するということです。 最終的にはすべての兵士が到達します`k`したがって、必要な合計増加量は次のように決まります。$$\sum (k - a_i)$$さらに重要なことは、セッションごとに、昇進した兵士ごとに合計ランクの合計が 1 ずつ増加し、昇進は避けられないことです。 兵士はレベルをスキップできません。 

つまり、プロセス全体で実行されるプロモーションの合計数は正確に次のようになります。$$\sum (k - a_i)$$各セッションは、アクティブなランク グループごとに 1 つのプロモーションを実行しますが、セッションを直接カウントすることは、プロモーションをカウントすることよりも困難です。 より明確な観点は、各兵士が独立して登る必要があることを観察することです。`k`、一度に 1 レベルずつ、追加の昇格は発生しません。 

驚くべき事実は、セッションの数は、グループ化ルールによって作成された強制スケジュール全体に分割されたすべての兵士に必要な昇進の合計に等しく、このスケジュールは常に正確に消費されます。$$\sum_{i=1}^{n} (k - a_i)$$個別のプロモーション業務。 

この特定の問題については、シミュレーションは単純でまったく問題ありませんが、公式の解はさらに単純です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(答え×k) | O(k) | 承認済み |
 | 最適な計数公式 | O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`そして`k`、次に兵士の階級を読みます。 
2. アキュムレータを初期化する`ans = 0`。 
3. 兵士の階級ごとに`x`、ランクに到達するためにまだ必要なプロモーションの数を計算します。`k`。$$k - x$$この値を追加します`ans`。 

1.すべての兵士を処理した後、印刷します`ans`。 

これが機能する理由は、昇進ごとに兵士のランクが 1 つずつ増加し、兵士はランクをスキップできないためです。 階級に応じた兵士`x`正確に昇進する必要がある`k - x`終了するまでの回数。 

### なぜ効果があるのか

 不変条件は、すべてのトレーニング セッションで一定数の有効なワンステップ プロモーションが実行され、プロモーションによってランクが低下したりスキップされたりすることはないということです。 最終状態では、すべての兵士が次の状態から移動する必要があります。`a_i`に`k`。 

各兵士に必要な昇進の数は固定されています。$$k - a_i$$すべての兵士を合計すると、プロセス全体で発生する必要がある昇進の正確な合計数が得られます。 Since every training session consists solely of these promotions and no extra operations exist, the total number of required promotion operations is exactly the answer.

 ## Python ソリューション```python
import sys
input = sys.stdin.readline

n, k = map(int, input().split())
a = list(map(int, input().split()))

ans = 0

for x in a:
    ans += k - x

print(ans)
```実装は数学的観察に直接従うものです。 

ループは各兵士を個別に処理します。 現在のランクの兵士の場合`x`、最大ランクまでの残りの距離は`k - x`。 これらの距離を合計すると、必要なプロモーションの合計数が得られます。 

プロモーションの順序は合計数に影響しないため、シミュレーションは必要ありません。 セッションがどのようにスケジュールされているかに関係なく、すべての兵士は同じ数のランク上昇を通過する必要があります。 

考えられる最大の答えは次のとおりであるため、トリッキーなオーバーフローの問題はありません。$$100 \times (100 - 1) = 9900$$これは Python の整数に簡単に適合します。 

入力ランクはすでにソートされていますが、解決策は順序付けには依存しません。

## テストケース```python
# helper: run solution on input string, return output string
import sys, io

def solve():
    input = sys.stdin.readline

    n, k = map(int, input().split())
    a = list(map(int, input().split()))

    ans = 0

    for x in a:
        ans += k - x

    print(ans)

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    out = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return out

# provided sample
assert run("4 4\n1 2 2 3\n") == "8\n", "sample 1"

# minimum size
assert run("1 1\n1\n") == "0\n", "single soldier already max"

# all equal but not maximal
assert run("3 3\n1 1 1\n") == "6\n", "all soldiers same low rank"

# boundary ranks
assert run("5 5\n1 2 3 4 5\n") == "10\n", "mixed progression"

# maximum-style case
assert run("100 100\n" + " ".join(["1"] * 100) + "\n") == "9900\n", "largest answer"

# off-by-one check
assert run("2 2\n1 2\n") == "1\n", "only one promotion needed"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 1 / 1`|`0`| 最小制約 |
 |`3 3 / 1 1 1`|`6`| 同一の下位ランクが複数ある |
 |`5 5 / 1 2 3 4 5`|`10`| フルレンジにわたる混合ランク |
 |`100 100 / all 1s`|`9900`| 可能な最大の合計プロモーション |

 ## 特殊なケース

 すべての兵士がすでに最大のランクを持っている場合を考えてみましょう。```
4 5
5 5 5 5
```兵士一人一人に対して、`k - x = 0`。 アルゴリズムは 4 つのゼロを追加して出力します`0`。 不要なセッションはカウントされません。 

ここで、すべての兵士が同じ低ランクから開始することを考えてみましょう。```
3 3
1 1 1
```計算は次のようになります。```
(3 - 1) + (3 - 1) + (3 - 1)
= 2 + 2 + 2
= 6
```すべての兵士は正確に 2 つのランクを取得する必要があるため、6 つの昇進は避けられません。 

最後に、中間ランクが欠落していることを考慮します。```
4 5
1 1 4 4
```アルゴリズムは以下を計算します。```
4 + 4 + 1 + 1 = 10
```ランクの不在`2`そして`3`重要ではない。 兵士は依然として同じ数の合計ランク上昇を必要とし、すべての上昇は個別に行う必要があります。
