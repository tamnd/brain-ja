 ## 解決策
 ## 問題の理解

 私たちは、すべての桁が異なる 4 桁の数字を使用して、古典的な雄牛と牛のゲームをプレイしています。 先頭のゼロは許可されるため、`0123`は有効ですが、次のような数字が繰り返されます。`0012`または`1223`そうではありません。 

以前の各推測には 2 つの値が含まれます。 雄牛は、数字が値と位置の両方で一致することを意味します。 牛は、その数字が隠れた数字に存在するが、別の位置に表示されていることを意味します。 

タスクはゲーム自体をシミュレートすることではありません。 以前の答えが一意に隠れた数字を決定するかどうかを判断する必要があります。 

考えられる結果は 3 つあります。 

有効な数値が 1 つだけですべての推測を満たす場合、その数値を出力します。 

推測を満たす有効な数値がない場合、応答は互いに矛盾し、出力されます。`Incorrect data`。 

複数の有効な数値が残っている可能性がある場合は、次のように出力します。`Need more data`。 

制約は非常に小さいです。 推測は最大 10 個です。 個別の桁を持つ 4 桁の数値は次のように形成できます。$$10 \times 9 \times 8 \times 7 = 5040$$方法。 

そうすれば問題の性質はすぐに変わります。 賢い枝刈り、動的プログラミング、検索ツリーは必要ありません。 すべての候補者をすべての推測と比較したとしても、ほんのわずかです。$$5040 \times 10 = 50400$$比較。 

各比較では、4 つの位置と最大でも数桁の一致のみがチェックされます。 これなら制限時間内に余裕で収まります。 

主な困難はパフォーマンスではなく、正確さです。 雄牛と牛は、不注意に実装すると混同されやすくなります。 

微妙なエッジ ケースの 1 つは、先行ゼロを正しく処理することです。 

考慮する：```
1
0123 4 0
```正しい答えは次のとおりです。```
0123
```すべてを整数に変換し、後で文字列に戻す不注意な実装では、誤って変換される可能性があります。`0123`の中へ`123`、先頭のゼロが失われます。 

もう 1 つの簡単な間違いは、雄牛を二重に数えることによって牛の数を間違って数えることです。 

隠された数字が`0123`そして推測は`0124`。 

正しい結果は`3 bulls 0 cows`。 

最初に共通の桁を数えてから、それらを減算せずに雄牛を個別に数えると、桁ごとに 1 頭の牛を誤って報告してしまう可能性があります。`0`、`1`、 または`2`。 

矛盾したデータも重要なケースです。```
2
0123 4 0
0123 0 4
```両方のステートメントを同時に満たすことはできない数値はありません。 正しい出力は次のとおりです。```
Incorrect data
```最初の有効な候補を見つけた後に実装が停止すると、誤って出力されます。`0123`。 

最後の重要なケースは曖昧さです。```
1
0123 0 0
```これは、隠された番号に次のものが含まれていないことを示すだけです。`0,1,2,3`。 多くの有効な番号が残っています。 正しい出力は次のとおりです。```
Need more data
```プログラムは、候補が存在するかどうかを確認するだけでなく、有効な候補をすべてカウントする必要があります。 

## アプローチ

 最も直接的な解決策はブルートフォースです。 

有効な 4 桁の数値はすべて、先頭にゼロが付いている数値を含め、個別の桁で生成されます。 各候補について、それを以前のすべての推測と比較します。 すべての雄牛と牛の頭数が正確に一致する場合、候補者としての可能性は残ります。 

検索スペースが小さいため、これが機能します。 候補者は5040人しかいない。 

2 つの数字を比較するには、同じ位置をチェックして雄牛を数えます。 次に、両方の数字に含まれる桁数を数えます。 桁が異なるため、牛の数は次のようになります。$$\text{common digits} - \text{bulls}$$ブルートフォース ソリューションはすでに十分に高速です。 これを超える最適化を必要とする隠れた大きな制約はありません。 

本当の洞察は、問題の規模が基本的にゲーム自体の構造によって制限されることを認識することです。 10 の可能性からの 4 つの異なる数字により、わずか 5040 の状態からなる固定ユニバースが作成されます。 それが分かれば、徹底的なチェックが最もクリーンで安全な解決策になります。 

より複雑なアプローチは、実行時間を有意義に改善することなく、実装リスクを増大させるだけです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | 5040 人の候補者全員に対する総当たり攻撃 | O(5040 × n) | お(1) | 承認済み |
 | 最適化されたプルーニング/検索 | 不要 | より高い | 受け入れられるが複雑すぎる |

 ## アルゴリズムのチュートリアル

 1. すべての推測を、予想される雄牛と牛の頭数とともに読み取ります。 
2. すべての桁が異なる 4 桁の数字をすべて生成します。 

数値は整数ではなく文字列として生成されるため、先頭のゼロは自然に保持されます。 
3. 各候補番号について、すべての推測と比較します。 
4. 2 つの数値を比較するには:

 ポジションをチェックして雄牛を数える`0..3`。 

候補の何桁が推測に含まれるかを確認して、共通する桁を数えます。 

すべての数字が異なるため、牛は次のようになります。$$\text{common digits} - \text{bulls}$$5. 計算された牛と牛が 1 つの推測でも期待値と一致しない場合は、候補を直ちに拒否します。 

早期に拒否すると、パフォーマンスはすでに十分に十分ですが、不必要な作業が回避されます。 
6. すべての推測を満たすすべての候補を収集します。 
7. すべての候補をチェックした後、次の操作を行います。 

候補が残っていない場合は印刷`Incorrect data`。 

If exactly one candidate remains, print it.

 それ以外の場合は印刷します`Need more data`。 

### なぜ効果があるのか

 アルゴリズムは、考えられるすべての有効な隠し数値を 1 回だけチェックします。 候補者は、記録されたすべての応答を完全に再現した場合にのみ生き残ります。 

非表示の数値はすべての有効な 4 桁の個別の数値のセットに属している必要があるため、徹底的な列挙により次のことが保証されます。 

有効な解決策が存在する場合は、それを見つけます。 

複数のソリューションが存在する場合は、それらすべてがカウントされます。 

何も存在しない場合、データは矛盾しています。 

候補はスキップされず、無効な候補は整合性チェックを通過できません。 

## Python ソリューション```python
import sys
from itertools import permutations

input = sys.stdin.readline

def score(secret, guess):
    bulls = 0

    for i in range(4):
        if secret[i] == guess[i]:
            bulls += 1

    common = 0

    for ch in secret:
        if ch in guess:
            common += 1

    cows = common - bulls

    return bulls, cows

def solve():
    n = int(input())

    guesses = []

    for _ in range(n):
        s, b, c = input().split()
        guesses.append((s, int(b), int(c)))

    valid = []

    for p in permutations("0123456789", 4):
        candidate = "".join(p)

        ok = True

        for g, b, c in guesses:
            cb, cc = score(candidate, g)

            if cb != b or cc != c:
                ok = False
                break

        if ok:
            valid.append(candidate)

    if len(valid) == 0:
        print("Incorrect data")
    elif len(valid) == 1:
        print(valid[0])
    else:
        print("Need more data")

solve()
```の`score`関数は正確な雄牛と牛のルールを実装します。 ブルはポジションごとにカウントされます。 共通の桁は別々に数えられ、牛は雄牛を引くことによって得られます。 

整数の代わりに文字列を使用すると、先行ゼロの問題がすべて自動的に回避されます。 候補者`"0123"`プログラム全体を通してちょうど 4 文字の長さのままです。`itertools.permutations`すでに明確な数字が保証されているため、ここでは完璧です。 生成されたすべてのタプルには、次から選択された 4 つの異なる文字が含まれます。`"0123456789"`。 

メインループは、すべての候補をすべての推測に対してチェックします。 1 つの推測が一致しないと、その候補者は即座に破棄されます。 

最終的な決定は、有効な候補者が何人残っているかによってのみ決まります。 

実装の微妙な詳細の 1 つは、牛が独立してカウントされないことです。 数字は一意であるため、共有されるすべての数字は雄牛または牛のいずれかであり、両方であることはありません。 共有桁の合計から雄牛を減算することで、偶発的な二重カウントを回避できます。

 | 測定 | 複雑さ | 説明 |
