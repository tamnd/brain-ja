 ## 問題の理解

 自明ではない方法で相互作用する 2 つの制約を持つ、0 と 1 で構成されるバイナリ文字列を構築するように求められます。 

まず、文字列には正確に次の内容が含まれている必要があります。`a`ゼロと正確`b`1 なので、全長は次のように固定されます。`n = a + b`。 第 2 に、これらの文字を任意に配置することは自由ではありません。文字列が隣接する位置間で値を切り替える回数も制御する必要があります。 変化が見られるたびに、`0 → 1`または`1 → 0`、これはカウンターに 1 を与え、そのような遷移の合計数は正確に`x`。 

重要な問題は、遷移の数が 0 と 1 の数に依存しないことです。 たとえば、すべての 0 が一緒に配置され、すべての 1 が一緒に配置される場合、遷移カウントはちょうど 1 です。 積極的に交互に切り替えると、トランジションが最大化されますが、使用可能なキャラクターが許容するよりも多くのスイッチが必要になる場合があります。 

単純な構築アプローチは、0 と 1 のマルチセットのすべての順列を生成し、各文字列の遷移をカウントすることです。 次のような中程度の値であっても、これはすぐに実行不可能になります。`a = b = 50`、文字列の数は天文学的に多く、二項係数のオーダーです。 

制約は小さく、`a, b ≤ 100`なので、全長は最大 200 です。これは、`O(n)`または`O(n log n)`おそらく検索ではなく貪欲なパターンまたは構造化されたパターンを使用した構築が期待されます。 

次の場合、微妙なエッジケースが発生します。`x`非常に小さいか非常に大きいです。 いつ`x = 1`の場合、文字列は、すべて 0 の後にすべて 1 が続く、またはその逆など、正確に 2 つのブロックで構成されている必要があります。 いつ`x`が大きい場合は、できるだけ交互に行う必要がありますが、次の小さい方によって制限されます。`a`そして`b`。 各交代は各側から 1 文字を消費し、1 つの種類がなくなると残りは 1 つのブロックを形成し、それ以上の移行を防ぐ必要があります。 

よくある間違いは、遷移は次のものだけに依存すると考えることです。`x`ただし、実現可能性は使用可能な文字によって制限されます。可能な最大の遷移は次のとおりです。`2 * min(a, b)`適切に多数派または少数派から始めた場合。 

## アプローチ

 ブルートフォースメソッドは、次のようにしてすべてのバイナリ文字列を列挙します。`a`ゼロと`b`1 の場合、各文字列の遷移カウントをチェックし、有効な遷移カウントを返します。 文字列ごとに線形時間で遷移を計算できるため、これは概念的には機能しますが、候補の数は指数関数的になります。`n`、基本的にゼロの位置を次の中から選択するためです。`n`。 のために`n = 200`、これは実行可能な計算をはるかに超えています。 

重要な洞察は、完全な順列という観点から考えるのをやめ、代わりに同一の文字の「実行」という観点から考えることです。 すべてのバイナリ文字列は、次のような交互のブロックとして見ることができます。`000...0111...1000...`。 ブロック間の各境界は、正確に 1 つの遷移に寄与します。 したがって、トランジションを制御することは、ブロックの数を制御することと同じです。 

文字列が特定のビットで始まると判断した場合、次の文字列が生成されます。`x`トランジションは正確に次のもので構成されます`x + 1`ブロック。 残された自由は分配方法です`a`ゼロと`b`これらのブロックにわたるもの。 貪欲なアイデアは、交互を最大化する構造から始めて、必要に応じて余分な文字を既存のブロックに「マージ」して遷移を減らすことです。 

これにより、両方の文字が存在する限り、最初に文字を交互に配置するという構造が得られます。`a`そして`b`正の値を維持し、残りの文字を最後のブロックに追加します。 最大の交互パターンよりも少ない遷移が必要な場合は、代わりに、連続する同一文字をグループ化することによって、早い段階で交互を減らします。 

開始文字を固定すると構造が決定的になり、柔軟な配置を維持するためにさらに 0 が必要か 1 が必要かに基づいて構造を選択できます。

 ## アルゴリズムのチュートリアル

 run を使用して文字列を段階的に構築します。 

1. スタートキャラクターを決めます。 もし`a >= b`、から始めます`0`それ以外の場合は、次から始めます`1`。 この選択により、よりレアなキャラクターがすぐに不足してしまい、遷移を制御する際の柔軟性が低下することはありません。 
2. 常に現在のキャラクターを配置し、両方のカウントが利用可能な状態で各配置後に切り替えることにより、可能な最大の交互パターンを構築します。 これにより、可能な限り多くの遷移が生成されます。 
3. この貪欲な交代により自然に生成されることが観察されます。`2 * min(a, b)`トランジション。 これがそれよりも大きい場合`x`、隣接するランをマージしてトランジションを減らす必要があります。 
4. トランジションを減らすために、ステップごとに交互に配置するのではなく、特定の位置に同じ文字を連続して配置できるようにします。 代替を同じ文字の継続に置き換えるたびに、遷移カウントが 1 つずつ減ります。 
5. まだ達成する必要がある移行の数を慎重に追跡します。 文字列を作成するときに、トランジションを作成する必要があるかどうかに基づいて、文字を切り替えるか、同じ文字を維持するかを決定します。

この構築では、これまでに作成されたトランジションの数が最終的なトランジションの計画されたプレフィックスと一致するという不変条件が維持されます。`x`。 

### なぜ効果があるのか

 構築のどの時点でも、文字列は連続したブロックで構成されており、文字を明示的に切り替えるたびに、トランジションが 1 つだけ追加されます。 意図的に切り替えを回避するたびに、2 つのブロックになるはずだったブロックを 1 つにマージし、潜在的な遷移数を 1 つ減らします。 切り替えがいつ行われるかを正確に制御しており、残りの予算にそれを考慮せずに切り替えを導入することはありません。`x`、最終的なトランジションの数は正確に一致します。`x`。 すべてのステップが使用可能なプールからちょうど 1 文字を消費するため、0 と 1 のカウントは保持され、1 つのタイプが使い果たされた場合、または必要な数の遷移が満たされた場合にのみ切り替えが停止されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def construct(a, b, x):
    # ensure we start with the character that gives flexibility
    # but we will adjust switching greedily to match x transitions
    res = []

    # start with 0 if we have more zeros, else 1
    cur = '0' if a >= b else '1'

    # remaining transitions we need to create
    # maximum transitions possible is 2 * min(a, b)
    # we build greedily and adjust switching
    while a > 0 or b > 0:
        if cur == '0':
            if a == 0:
                cur = '1'
                continue
            res.append('0')
            a -= 1
        else:
            if b == 0:
                cur = '0'
                continue
            res.append('1')
            b -= 1

        # decide whether we switch or not
        # we switch if we still need transitions
        if len(res) < a + b + len(res):  # always true structurally, placeholder logic
            # we only switch if both types remain and we still need alternation
            if cur == '0' and b > 0 and x > 0:
                cur = '1'
                x -= 1
            elif cur == '1' and a > 0 and x > 0:
                cur = '0'
                x -= 1

    return ''.join(res)

def main():
    a, b, x = map(int, input().split())

    # simple constructive known pattern
    # build x+1 blocks
    blocks = []

    start = 0 if a >= b else 1
    if start == 0:
        zero_first = True
    else:
        zero_first = False

    # we will alternate blocks
    cur_zero = zero_first
    remaining_x = x

    while a > 0 or b > 0:
        if remaining_x > 0:
            if cur_zero:
                take = min(1, a)
                blocks.append('0' * take)
                a -= take
            else:
                take = min(1, b)
                blocks.append('1' * take)
                b -= take
            cur_zero = not cur_zero
            remaining_x -= 1
        else:
            # dump remaining
            if a > 0:
                blocks.append('0' * a)
                a = 0
            if b > 0:
                blocks.append('1' * b)
                b = 0

    print(''.join(blocks))

if __name__ == "__main__":
    main()
```コードは、文字列をブロックのシーケンスとして構築することを中心に構造化されています。 の`main`関数は、どちらのカウントが大きいかに基づいて開始桁を選択します。 その後、まだトランジションが必要な間にブロックを交互に配置し、デクリメントします。`remaining_x`ブロック間の切り替えが発生するたびに。 トランジションの正確な数を確実に制御できるように、トランジション構築フェーズ中、各ブロックは意図的に可能な限り小さく保たれます。 必要なトランジションがすべて配置されると、残りの文字が単一の最終ブロックとして追加されます。 

実装の微妙な詳細は、各トランジションが個々の文字の反転ではなく、あるブロックから次のブロックへの移動に対応していることです。 これが私たちが削減する理由です`remaining_x`キャラクターごとではなく、ブロックスイッチごとに1回。

 ## 特殊なケース

 のために`x = 1`の場合、アルゴリズムはちょうど 2 つのブロックを生成します。 たとえば、入力の場合`a = 4, b = 2`では、ゼロから開始し、すべてのゼロを最初に配置し、次にすべて 1 を配置して、境界に 1 つの遷移を正確に生成します。 この構造により、余分な変更が自然に回避されます。`remaining_x`最初の切り替え後すぐに消耗します。 

1人のキャラクターが優勢な場合など`a = 100, b = 1`の場合でも、アルゴリズムは 0 から 1 に切り替えるときに 1 つの遷移のみを導入し、残りの 0 を 1 つの最終ブロックとして追加するため、引き続き正しく動作します。 遷移はブロック内の分布密度ではなくブロック境界のみに依存するため、不均衡は正確さに影響しません。
