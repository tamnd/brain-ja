 ## 解決策
 ## 問題の理解

 私たちは一連の単語として文書を与えられます。 構造は固定されています。単語は単一のスペースで区切られているため、基礎となるオブジェクトは実際には単なる文字列の配列です。 セグメントはこの配列の連続したスライスであり、2 つのセグメントの長さが同じで、対応する単語が正確に一致する場合、2 つのセグメントは同一とみなされます。 

許可される操作は珍しいものです。同じセグメントの少なくとも 2 つの互いに素な出現を選択し、各出現をそのセグメント内の単語の最初の文字から形成される単一の大文字文字列に圧縮することができます。 選択された各長さのセグメント`k`単一の長さのトークンになります`k`文字。 

目標は、このような省略操作を最大でも 1 つ適用することです。つまり、スペースを含む最終テキストの合計文字長を最小限に抑えるために、何もしないか、セグメント パターンを選択して重複しない部分をすべて置き換えます。 

重要な問題は、セグメントの圧縮による利益が、そのセグメントの重複しないオカレンスがいくつ存在するかによって決まることです。 長さのセグメント`k`重複せずに少なくとも 2 回出現する場合にのみ削減が行われます。 

制約`n ≤ 300`すぐに示唆する`O(n^3)`または`O(n^2 log n)`セグメント比較よりもアプローチが妥当です。 ただし、慎重に再利用せずにセグメントのすべてのペアに対して単純な部分文字列ハッシュを行うと、依然としてリスクが発生します。`O(n^3)`セグメントを繰り返し比較すると、最大で`O(n)`毎回。 

出来事が重なると、微妙な失敗のケースが発生します。 たとえば、セグメントが次の位置に表示される場合、`1..3`、`2..4`、 そして`3..5`、同時に選択できるのは一部のペアのみです。 非オーバーラップを強制せずに出現回数をカウントする単純なアプローチでは、圧縮のメリットを過大評価してしまいます。 

もう 1 つのエッジ ケースは、最適なセグメントが配列全体であるにもかかわらず、その出現がまばらすぎるか重なりすぎて、2 つの有効なコピーを選択できない場合です。 どのようなソリューションでも、少なくとも 2 つの互いに素な出現を選択できることを明示的に保証する必要があります。 

## アプローチ

 すべてのセグメントを試すブルートフォース戦略`w[i..j]`、配列内のこのセグメントのすべての出現を計算し、重複しない出現の最大数を選択します。 セグメントが表示される場合`k`多くの場合、私たちができる最善のことは、開始インデックスの昇順で出現を貪欲に選択することです。これにより、重複しない有効な最大セットが得られます。 このセットにサイズがある場合`cnt`、その後、得られます`(cnt - 1)`元のセグメントを超える余分な圧縮コピー。 

セグメントごとに、テキストの合計長がどれだけ短縮されるかを計算します。 長さの 1 つの出現を置き換えるコスト`len`は`(sum length of words + spaces) - len`、サイズの単一の文字列になるため、`len`中にスペースはありません。 全体的な改善は、選択されたオカレンスの数によって異なります。 

ブルートフォースはコストが高くなります。`O(n^2)`セグメント、およびすべての開始ポジションのコストに対する各セグメントの比較`O(n * len)`、諦める`O(n^4)`単純に実装すると最悪の事態が発生する可能性があります。 

重要な洞察は、セグメントの等価性はローリング ハッシュで効率的に処理でき、セグメントのすべての出現は`O(n)`前処理後。 発生が判明したら、単純な貪欲スキャンで重複しないコピーを選択します。 

すべてのプレフィックスのハッシュを事前計算して、任意のセグメント ハッシュをクエリできるようにします。`O(1)`。 それから、それぞれについて`(i, j)`のハッシュを計算します`w[i..j]`そしてそれをすべての可能な開始位置と比較します`p`マッチを集めるために。 これにより、次のすべての出現が得られます。`O(n^3)`合計。 慎重な実装と語長の整数の事前計算により、これは問題なく合格します。`n ≤ 300`。 

最後に、候補セグメントごとに、貪欲に選択できる出現数を計算し、結果のテキストの長さを評価します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^4) | O(n^2) | 遅すぎる |
 | ハッシュ + 列挙 | O(n^3) | O(n^2) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 単語シーケンスのプレフィックス ハッシュを事前計算します。 各単語はローリング ハッシュのトークンとして扱われるため、どのセグメントも O(1) で比較できます。 これにより、文字列を直接比較せずにセグメントの同等性をテストできます。 
2. 語長のプレフィックスの合計を事前計算します。 これにより、O(1) のスペースを含む任意のセグメントの生の文字長を計算できます。`k`もっている`(sum lengths + (k-1))`文字。 
3. すべてのセグメントを列挙する`(i, j)`潜在的な略語パターンとして。 このような各セグメントは、他の場所で圧縮できる「パターン」を定義します。 
4. 固定の場合`(i, j)`、そのハッシュを 1 回計算し、すべての開始位置をスキャンします`p`そのような`p + (j - i) ≤ n`。 のハッシュの場合、`w[p..p+(j-i)]`試合、記録`p`出来事として。 ダブルハッシュまたは 64 ビットハッシュによりハッシュ衝突は無視できるため、実際にはハッシュ衝突は無視されます。 
5. このセグメントの出現箇所をすべて並べ替えます。 貪欲な選択により、重複しない出現の最大セットを選択します。常に、前に選択したセグメントの終了後に厳密に開始される次の出現を取得します。 
6. 重複しない出現が 2 つ未満の場合は、省略が許可されていないため、このセグメントをスキップします。 
7. それ以外の場合はゲインを計算します。 させて`len_seg`スペースを含む文字単位の元のセグメント長になります。 させて`gain = (cnt - 1) * len_seg - cost_of_replacement_adjustment`これは、複数の長い出現箇所を短い大文字形式に置き換えることに対応します。 
8. 「操作なし」の場合を含む、すべてのセグメントにわたって可能な最小の最終テキスト長を追跡します。 

正確さは、固定セグメント パターンの場合、すべての出現が同じ長さを持ち、重複構造が線形であるため、出現の最適な選択はソート順で貪欲であるという事実に依存します。 

## なぜ機能するのか

 どの候補セグメントでも、すべてのオカレンスは同じ長さと構造を持っているため、最大の有効な置換を選択するという問題は、等しい長さの間隔での間隔スケジューリングに帰着します。 より早い終了点による貪欲な選択は、より遅い重複出現を選択することは将来の互換性のある選択肢の数を減らすだけであるため、最適です。 考えられるすべてのセグメントをパターンとして評価するため、考えられるすべての省略操作を使い果たします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    w = input().split()

    # prefix word lengths
    pref_len = [0] * (n + 1)
    for i in range(n):
        pref_len[i + 1] = pref_len[i] + len(w[i])

    # base text length (includes spaces)
    base = pref_len[n] + (n - 1 if n > 0 else 0)

    # rolling hash for words
    MOD = (1 << 64)
    B = 91138233

    h = [0] * (n + 1)
    p = [1] * (n + 1)

    for i in range(n):
        h[i + 1] = (h[i] * B + hash(w[i])) % MOD
        p[i + 1] = (p[i] * B) % MOD

    def get_hash(l, r):
        return (h[r] - h[l] * p[r - l]) % MOD

    ans = base

    # try all segments
    for i in range(n):
        for j in range(i, n):
            length = j - i + 1
            seg_hash = get_hash(i, j + 1)

            occ = []
            k = 0
            while k + length <= n:
                if get_hash(k, k + length) == seg_hash:
                    occ.append(k)
                k += 1

            if len(occ) < 2:
                continue

            # greedy non-overlapping selection
            cnt = 0
            last_end = -1
            for s in occ:
                if s > last_end:
                    cnt += 1
                    last_end = s + length - 1

            if cnt < 2:
                continue

            seg_chars = pref_len[j + 1] - pref_len[i]
            seg_chars += (length - 1)

            new_len = base - cnt * seg_chars + cnt * length
            ans = min(ans, new_len)

    print(ans)

if __name__ == "__main__":
    solve()
```すべてのセグメント置換は単語文字と区切り文字の両方に影響するため、コードは最初にスペースを含む生のテキスト サイズを計算します。 次に、単語トークンに対してローリング ハッシュを構築し、セグメントの等価性チェックが一定時間になるようにします。 

すべての候補セグメントについて、開始位置をスキャンし、ハッシュを比較することによって、すべての一致を列挙します。 各一致は潜在的な出来事として記録されます。 次に、貪欲パスは、素の出現の最大数を選択します。 最終的な長さの式では、完全なセグメント展開が減算され、逆圧縮された単一トークン形式が加算されます。 

よくある落とし穴は、圧縮されたセグメントの内側ではスペースが消えても、外側にはスペースが残ることを忘れていることです。 そのため、セグメントの長さは単語の合計に内部スペースを加えたものとして計算され、置換では追加されるもののみが計算されます。`k`文字。

 ## 特殊なケース

 のようなケース`a a a a a`長さ 1 のすべてのセグメントが多くの重複する位置に現れるため、これは重要です。 アルゴリズムでは、すべての出現をカウントする必要はありません。 重複しないもののみを選択する必要があります。 この入力では、すべての位置にオカレンスが存在しますが、貪欲な選択により使用可能なセグメントが 2 つだけ生成され、誇張されたゲインではなく制御された圧縮が生成されます。 

もう 1 つの微妙なケースは、セグメントが何度も出現するが、素であるペアが 1 つだけである場合です。 このアルゴリズムは、貪欲なスケジューリングの後に少なくとも 2 つの選択されたオカレンスを要求することで、これを正しくフィルタリングし、無効な省略の試行を防ぎます。 

最後のエッジケースは、最適なセグメントが長いがまれな場合です。 セグメントが重複して複数回出現する場合でも、2 つの互いに素なコピーを作成できない場合は、完全に無視する必要があり、これは選択ステップで強制されます。
