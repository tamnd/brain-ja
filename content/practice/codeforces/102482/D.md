 # 問題の理解

 n 人の住民がおり、それぞれが 1 つの宝石から始まります。 d 夜が経過すると、毎晩、既存の gem が 1 つだけ選択されて分割されるため、gem の総数は n+d になります。 分割プロセスはランダムですが、質問は 1 つの可能な最終状態を求めているわけではありません。 最終的に最大のコレクションを所有する r 人の住民が所有する宝石の予想数を尋ねます。 

有益な最初の観察は、すべての有効な最終分布の可能性が等しいということです。 最終的な分布は、合計が n+d となる n 個の正の整数として記述できます。 ランダムな分割プロセスでは、そのようなすべての分布に同じ確率が与えられるため、問題は正の整数の合成に関する計数問題になります。 

n,d ≤ 500 という制約により、分布を列挙するものはすべて除外されます。これは、可能な分布の数は二項係数であり、非常に急速に増加するためです。 d 個の追加の gem を配布するあらゆる方法を試みるアプローチでさえ、d が 500 に達するずっと前に不可能になります。可能な状態は約 250,000 しかなく、それらの状態での遷移は線形に近くなければならないため、n 次元と d 次元にわたる動的プログラムが適切です。 

微妙なケースは、すべての住民が最も裕福な人々の一人である場合です。 たとえば、入力`3 5 3`これは、3 人の住民全員が必要であることを意味するため、答えは単純にジェムの合計数 8 になります。トップ グループから一部の人々が除外されると常に想定する解決策では、ここで誤ってジェムを失う可能性があります。 

もう 1 つの境界ケースは、1 つの宝石で住民を削除した後の再発で d がゼロの場合です。 たとえば、入力`2 1 1`配布の可能性があります`(2,1)`そして`(1,2)`したがって、期待される答えは 1.5 です。 無効な負の数の余分な gem を許可する不注意な再帰により、不正確な状態が生成されます。 

# アプローチ

 強引なアプローチでは、宝石の可能な限りの最終分布を生成し、n 値を並べ替えて、最大の r 値を追加します。 これは正しいです。すべての分布の確率が同じであるため、すべての分布を平均すると期待値が得られます。 問題は配布数です。 がある`C(n+d-1,d)`可能性のある正の構成は、500 に近い値ではすでに膨大です。各分布を生成して並べ替える作業は完全に実行不可能です。 

重要な観察は、個々の分布について考えるのをやめ、代わりに分布のグループを数えることです。 S(n,d) を、n 個の住民と d 個の余分な宝石を含むすべての有効な分布における上位 r 個の宝石の合計とします。 そのような分布の数は`C(n+d-1,d)`したがって、最終的な答えは次のとおりです。`S(n,d)`この数で割ります。 

すべての住民の最初の宝石を考えてみましょう。 すべての有効な分配は、これらの最初の宝石のうち正確に r 個を最も裕福な r 人に寄付します。 残りの貢献は、複数の宝石を持っている住民からのみ発生します。 正確に g 人の住民が宝石を 1 つだけ持っていると仮定します。 これらの g 人を削除し、残りの住民全員から宝石を 1 つ取り除くと、より小さなインスタンスが残ります。`n-g`住民と`d-n+g`追加の宝石。 これにより、より小さな状態にわたって繰り返しが行われます。

 | ブルートフォース | d の指数 | 指数 | 遅すぎる |

 # アルゴリズムのチュートリアル

 1. パスカルの三角形を使用して、最大 1000 までの二項係数を事前計算します。 可能な分布の数は組み合わせの値であるため、これらの値が必要です。 
2. 定義する`dp[n][d]`n 人の住民と d 個の追加ジェムのすべての有効な分布における最も裕福な r 人の住民の合計貢献度として。 負の d を持つ無効な状態はゼロに寄与します。 
3. 状態を処理します。`n <= r`別に。 すべての住民は最も裕福なグループに属しているため、各分布の貢献度は単純に次のようになります。`n+d`宝石。 
4. 他のすべての州については、各住民が所有する最初のジェムの寄付から始めます。 がある`C(n+d-1,d)`最初の gem はすべてのディストリビューションで正確に r 個の gem を提供し、次のようになります。`r * C(n+d-1,d)`。 
5. 宝石を 1 つだけ持っている住民の可能な数 g をすべて試します。 の住民 g 人を選択してください`C(n,g)`方法。 最初の宝石を除去した後、残りの住民はより小さな分布を形成するため、`C(n,g) * dp[n-g][d-n+g]`。 
6. 分割`dp[n][d]`期待値を取得するために可能な分布の数によって計算されます。 

反復の背後にある不変条件は、すべての状態がその状態のすべての可能な分布にわたる答えの合計を表すということです。 最初の gem と追加の gem の分割は正確です。最初の gem は避けられない基本寄与を占め、残りのすべての gem はより小さい有効なインスタンスに属します。 すべての分布は、1 つの宝石を持っている住民の数によって正確に 1 回カウントされるため、繰り返しが二重にカウントされたり、ケースが見逃されたりすることはありません。 

# Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, d, r = map(int, input().split())

    limit = n + d + 5
    comb = [[0] * (limit + 1) for _ in range(limit + 1)]
    for i in range(limit + 1):
        comb[i][0] = comb[i][i] = 1
        for j in range(1, i):
            comb[i][j] = comb[i - 1][j - 1] + comb[i - 1][j]

    dp = [[0.0] * (d + 1) for _ in range(n + 1)]

    for people in range(1, n + 1):
        for extra in range(d + 1):
            if people <= r:
                dp[people][extra] = (people + extra) * comb[people + extra - 1][extra]
            else:
                total = r * comb[people + extra - 1][extra]
                for single in range(people + 1):
                    remain_extra = extra - people + single
                    if remain_extra < 0:
                        continue
                    if people - single == 0:
                        continue
                    total += comb[people][single] * dp[people - single][remain_extra]
                dp[people][extra] = total

    ways = comb[n + d - 1][d]
    print("{:.10f}".format(dp[n][d] / ways))

if __name__ == "__main__":
    solve()
```組み合わせテーブルには、分布の正確な数が保存されます。 Python の整数は任意精度であるため、中間値がオーバーフローすることはありません。 

ダイナミック プログラミング テーブルは、住民の数を増やすことによって満たされます。 移行するたびに住民の数が減ります。`dp[people][extra]`が計算されると、必要なすべての小さな状態がすでに存在します。 

条件`remain_extra < 0`シングルトン以外のすべての住民から最初のジェムを削除すると、存在するよりも多くの追加のジェムが必要になるという不可能な状態が解消されます。 残りの住民がゼロの場合は、`people <= r`ルールは有効なトップ グループ計算である場合にのみ適用されるため、遷移では空の状態がスキップされます。 

# 実用的な例

 入力用`2 3 1`、5 つのジェムを 2 つのプラスの部分に分配する可能性は次のとおりです。`(1,4),(2,3),(3,2),(4,1)`。 各分布の最大値の合計は 14 で、分布は 4 つあります。 

| 状態 | 値 |
 | --- | --- |
 | n=2、d=3 | dp = 14 |
 | 配布数 | 4 |

 除算ステップでは、すべての分布の累積合計を必要な期待値に変換します。 

入力用`3 3 2`、可能な分布の数は`C(5,3)=10`。 繰り返しにより、保証された最初のジェムが追加のジェムから分離され、一部の住民が 1 つのジェムに留まるすべてのケースが結合されます。 

| 状態 | 値 |
 | --- | --- |

 | 配布数 | 10 |

 この例では、一部の住民が最も裕福なグループの外にいる場合を例に挙げます。

 # エッジケース

 のために`n=1`、最上位グループには常に唯一の住民が含まれます。 再発は次の段階に達します`n <= r`基本ケースを使用して宝石の合計数を返します。`1+d`。 

のために`r=n`、すべての人がカウントされるため、期待される答えは常に次のようになります。`n+d`。 基本ケースでは、不必要な再帰が回避され、正しい合計寄与率が直接返されます。 

多くの住民がちょうど 1 つの宝石を持っているディストリビューションの場合、次のような遷移が発生します。`g`単一宝石の住民はそれらを別々に扱います。 例えば、`2 1 1`には 2 つの可能な最終状態があり、どちらも最も裕福な固有の住民を仮定するのではなく、同じ繰り返しを通じてカウントされます。 

次のような大きな値の場合、`500 500 250`、ディストリビューションの数は膨大ですが、アルゴリズムがディストリビューションを個別に作成することはありません。 合計の貢献のみが保存されるため、ソリューションは制限内に留まります。
