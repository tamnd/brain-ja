 ## 解決策
 ## 問題の理解

 テキストは、スペース、カンマ、または文末のピリオドで区切られた単語で構成されます。 いくつかのカンマはすでに存在しています。 タスクは、コンマの配置が変更されなくなるまでルール システムを繰り返し適用することです。 

単語の前のコンマは、その単語に関する情報を提供します。文の始まりを除いて、同じ単語が 2 回出現するたびに、その単語の前にコンマを付ける必要があります。 単語の後のコンマも同様に機能し、文末にある場合を除き、その単語の他のすべての出現箇所に広がります。 新しく作成されたコンマは隣接する単語に影響を与える可能性があるため、固定点に到達するまでプロセスを続行する必要があります。 

入力長は 100 万文字に達することがあります。 これにより、カンマを追加するたびにテキスト全体を繰り返しスキャンする必要がなくなります。 ルールを 1 つずつ変更して適用しようとするシミュレーションでは、新しいカンマごとに入力に対する完全なパスが再度必要になる可能性があるため、二次的な動作に低下する可能性があります。 各単語の出現と各単語の種類を一定の回数だけ処理するアプローチが必要です。 

やっかいな点は、コンマは等しい単語間にのみ広がるわけではないということです。 単語の前にコンマを追加すると、前の単語の後にコンマが続くことも意味します。 単語の後にカンマを追加すると、次の単語の前にカンマが来ることになります。 この連鎖反応を無視すると、誤った結果が生じます。 

例えば：```
a b. a, b.
```正しい結果は次のとおりです。```
a, b. a, b.
```すでにコンマが含まれている単語のみを記憶する不注意な実装では、2 番目の単語の前にコンマが追加されます。`a`ただし、最初の後の元のカンマを忘れる可能性があります`a`また、隣接関係を通じて逆方向に伝播します。 

もう 1 つの特殊なケースは、文の境界です。```
x x.
```正しい結果は次のとおりです。```
x x.
```最初の後のカンマ`x`2番目からは作成できません`x`2 番目に出現するのは文の最後の単語であるためです。 単語の等価性のみをチェックし、文の位置を無視するソリューションでは、誤った出力が発生します。`x, x.`。 

最後のエッジ ケースは、新たにアクティブ化された単語のチェーンです。```
a b c,.
```後にカンマ`c`活性化する`b`後にカンマがあるとアクティブ化できます`a`同じプロセスを経て。 1 回の伝播ラウンド後に停止すると、間違った答えが得られます。 

## アプローチ

 簡単な方法は、テキスト全体を繰り返しスキャンすることです。 スキャン中に、単語の片側のどこかにコンマがある場合は、すべての出現箇所を検索し、不足しているコンマを追加します。 これはルールに直接従うため、正しいです。 問題はコストです。 100 万文字の場合、何十万もの単語が出現する可能性があります。 新しく追加されたカンマごとに別の完全なスキャンが発生すると、最悪の場合、作業量は約 O(n²) に達し、制限をはるかに超えます。 

有益な観察は、すべての単語タイプには 2 つのみの永続状態しか存在しないということです。 単語は最終的に、どこかの前にコンマが付く単語になるか、コンマが付けられない単語になります。 単語の後のコンマも同様です。 単語がこれらの状態のいずれかに入ると、そこから離れることはありません。 

これにより、プロセスがグラフ伝播問題に変わります。 各単語の種類には「左カンマあり」と「右カンマあり」の2種類の状態があります。 単語の右のカンマ状態は、出現するたびにその次の隣接語の左のカンマ状態をアクティブにします。 左のコンマ ステートは、前の隣接するコンマ ステートの右のコンマ ステートをアクティブにします。 新しく検出された状態に対してキューを実行し、各状態を 1 回処理できます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 入力を単語の出現箇所に解析します。 出現するたびに、単語、同じ文内の前の単語 (存在する場合)、同じ文内の次の単語 (存在する場合)、および元々その前後にコンマがあったかどうかを保存します。 
2. 個別の単語ごとに 2 つのブール状態を作成します。 1 つの状態は単語の前にコンマが必要かどうかを記録し、もう 1 つの状態は単語の後にコンマが必要かどうかを記録します。 これらの状態を元のテキストから初期化します。 
3. すべての初期アクティブ状態をキューに入れます。 キューには、まだ処理されていないワード ステートのみが含まれます。 
4. 左カンマ状態の単語を処理するときは、その単語のすべての出現箇所を参照します。 文の最初の単語以外の出現箇所には、その前にコンマが付きます。 その出現前の単語の後にコンマがあるため、必要に応じて隣接する右コンマ状態をアクティブにします。 
5. 右カンマ状態の単語を処理するときは、その単語の出現箇所をすべて参照します。 文の最後の単語ではないすべての出現箇所には、その後にコンマが付きます。 その出現後の単語の前にコンマがあるため、必要に応じて隣接する左コンマ状態をアクティブにします。 
6. キューが空になるまで続行します。 アクティブ状態は完全な固定点を記述します。 単語間のすべてのギャップに対して最終的なカンマの決定を使用して、元のテキストを再構築します。 

なぜ効果があるのか:

 このアルゴリズムは、すべてのアクティブな状態が最終的な答えで真でなければならない事実を表すという不変条件を維持します。 状態の処理には、その事実のルールの結果が正確に適用されます。 新しく作成されたコンマは、キューが検出できる 2 つの隣接する単語状態のうちの 1 つだけを作成できます。 状態は true になった場合にのみ追加され、削除されることはないため、キューには最終的に元のカンマから到達可能なすべての結果が含まれます。 キューが空になると、どのルールも別のカンマを作成できなくなります。これはまさに元のプロセスの停止条件です。 

## Python ソリューション```python
import sys
from collections import deque, defaultdict

input = sys.stdin.readline

def solve():
    s = input().rstrip("\n")

    words = []
    gaps = []
    i = 0
    while i < len(s):
        if s[i].isalpha():
            j = i
            while j < len(s) and s[j].isalpha():
                j += 1
            words.append(s[i:j])
            i = j
        else:
            i += 1

    m = len(words)
    before = [False] * m
    after = [False] * m
    starts = [False] * m
    ends = [False] * m

    idx = 0
    pos = 0
    while pos < len(s):
        if s[pos].isalpha():
            idx += 1
            while pos < len(s) and s[pos].isalpha():
                pos += 1
            if pos < len(s):
                if s[pos] == ',':
                    before[idx - 1] = True
                    pos += 1
                    while pos < len(s) and s[pos] == ' ':
                        pos += 1
                elif s[pos] == '.':
                    pos += 1
                    while pos < len(s) and s[pos] == ' ':
                        pos += 1
                    ends[idx - 1] = True
                else:
                    pos += 1
        else:
            pos += 1

    starts[0] = True
    for i in range(1, m):
        if ends[i - 1]:
            starts[i] = True

    word_id = {}
    ids = []
    for w in words:
        if w not in word_id:
            word_id[w] = len(word_id)
        ids.append(word_id[w])

    k = len(word_id)
    has_left = [False] * k
    has_right = [False] * k
    occ = [[] for _ in range(k)]

    for i, x in enumerate(ids):
        occ[x].append(i)
        if before[i]:
            has_left[x] = True
        if after[i]:
            has_right[x] = True

    q = deque()
    for i in range(k):
        if has_left[i]:
            q.append((i, 0))
        if has_right[i]:
            q.append((i, 1))

    while q:
        w, side = q.popleft()
        if side == 0:
            for p in occ[w]:
                if not starts[p]:
                    if not after[p - 1]:
                        after[p - 1] = True
                        nw = ids[p - 1]
                        if not has_right[nw]:
                            has_right[nw] = True
                            q.append((nw, 1))
        else:
            for p in occ[w]:
                if not ends[p]:
                    if not before[p + 1]:
                        before[p + 1] = True
                        nw = ids[p + 1]
                        if not has_left[nw]:
                            has_left[nw] = True
                            q.append((nw, 0))

    ans = []
    ptr = 0
    for i, w in enumerate(words):
        ans.append(w)
        if i + 1 < m:
            if after[i]:
                ans.append(", ")
            elif ends[i]:
                ans.append(". ")
            else:
                ans.append(" ")
        else:
            ans.append(".")
    print("".join(ans))

solve()
```パーサーはまず、文の構造を維持しながら単語の出現を抽出します。 配列`starts`そして`ends`ルールでは文の境界が明示的に除外されているため、これらが必要です。 

2 つの状態配列、`has_left`そして`has_right`、単語タイプのクロージャ情報を格納します。 出現リストを使用すると、テキスト全体を検索することなく、1 回のアクティベーションで一致するすべての単語を更新できます。 

キューは、標準的な固定小数点伝播手法です。 状態がキューに入るのは 1 回だけであるため、アルゴリズムは線形のままです。 最終的な再構成では、に保存されているギャップ情報が使用されます。`before`そして`after`、文末は保持されますが、`ends`。 

## 実用的な例

 最初のサンプルの重要な伝播状態は次のとおりです。 

| ステップ | アクティブ状態 | 新しい効果 |
 | --- | --- | --- |
 | イニシャル |`sit`カンマが残っています |`sit`左の状態を取得します |
 | イニシャル |`spot`正しいカンマがあります | 全て`spot`オカレンスには右のカンマが追加されます。 
| 伝播 |`here`カンマが残っています | 他の`here`オカレンスは左のカンマを取得します。 

最終的なテキストは次のようになります。```
please, sit spot. sit spot, sit. spot, here now, here.
```トレースは、コンマが隣接する単語を通過できることを示しています。 の状態`spot`カンマを次々に作成します`spot`、前にカンマが作成されます`here`。 

2 番目のサンプルの場合:

 | ステップ | アクティブ状態 | 新しい効果 |
 | --- | --- | --- |
 | イニシャル |`one`カンマが残っています | 他の`one`オカレンスは左のカンマを取得します。 
| イニシャル |`four`正しいカンマがあります | 次の単語には左のカンマが追加されます |
 | 伝播 |`tree`カンマが残っています | 一致するものはすべて左のカンマを取得します。 

出力は次のとおりです。```
one, two. one, tree. four, tree. four, four. five, four. six five.
```この例は、同じ単語を繰り返すだけではなく、いくつかの異なる単語を通じて伝播が継続できることを示しています。

 ## 特殊なケース

 単語が繰り返される場合:```
x x.
```どちらの出現にもカンマがないため、アルゴリズムは初期アクティブ状態を作成しません。 キューは空のままであり、再構築により元のテキストが返されます。 文の境界情報により、誤ってコンマが作成されることが防止されます。 

隣接伝播の場合:```
a b. a, b.
```後のカンマ`a`正しい状態を活性化します`a`。 2回目の発生`a`すでにその状態を満たしており、2 番目の前のカンマ`b`の左の状態をアクティブにします`b`。 アルゴリズムは次の最終結果に達します。```
a, b. a, b.
```チェーンの場合:```
a b c,.
```初期の権利状態は次のものに属します`c`。 これを処理すると、次の単語の左の状態が存在する場合はその状態がアクティブになり、新たに検出された状態の処理は、隣接する単語に到達できなくなるまで継続されます。 キューベースの伝播は、任意の長さのチェーンを自然に処理します。
