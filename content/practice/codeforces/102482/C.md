 ## 解決策
 ## 問題の理解

 私たちは接続された国家ネットワークを持っており、そのネットワークはツリーを形成しています。これは、国家のすべてのペアが国家間の経路を 1 つだけ持つことを意味します。 各道路には、それを通過する軍隊ごとのコストがあります。 国家`i`から始まる`xi`軍隊とニーズ`yi`軍隊は満足するだろう。 すべての要件が満たされた後、追加の軍隊はどこにでも残ることができます。 

任務は、総旅費をできるだけ少なくしながら、すべての国が必要な量を達成できるように軍隊の移動を選択することです。 道路を移動する各軍隊は道路コストを支払うため、生産量はすべての移動コストの最小和となります。 

主な制約はツリーのサイズです。 最大 250,000 の国が存在するため、考えられるすべての動きを検査したり、すべての軍隊の割り当てを試したりするアルゴリズムは不可能です。 おおよそのアルゴリズムでも`O(n * number_of_armies)`軍隊の総数は100万人に達する可能性があるため、作戦は大規模すぎるでしょう。 このソリューションでは、各国と各道路を一定回数だけ処理する必要があり、これは線形ツリー アルゴリズムを指します。 

軍隊の総数を制限することは、いくつかの可能な解決策には役立ちますが、国家の数が多すぎるため、すべての軍隊を個別に保存したり、動きをシミュレートしたりするのは適切ではありません。 すべての道路は世界を正確に 2 つの独立した側面に分離するため、道路が木を形成するという事実は重要な構造特性です。 

同じサブツリー内に流入するニーズと流出するニーズの両方がある国では、不注意な解決策は失敗する可能性があります。 例えば：```
2
1 2 10
5 3
0 4
```最初の国には 2 つの軍隊が余っていますが、2 番目の国には 4 つの軍隊が必要です。 正解は 20 です。2 つの軍隊が唯一の道を渡らなければならず、それぞれのコストが 10 であるためです。個々の国のみに注目する解決策では、残っている赤字の額を考慮せずに、最初の国が 2 番目の国を満足させることができると考えるかもしれません。 

もう 1 つのエッジ ケースは、ツリーのルートに黒字または赤字がある場合です。 例えば：```
1
5 3
```正解は 0 です。軍隊を移動させる場所はなく、国家にはすでに十分な兵力があります。 すべての余剰がルートから上向きに移動する必要があると想定するソリューションでは、誤ってコストが追加されてしまいます。 

最後の厄介なケースは、不足と追加の軍隊の両方を含むサブツリーです。 例えば：```
3
1 2 7
2 3 4
0 2
5 1
0 3
```ノード 2 と 3 を含むサブツリーの合計余剰は 0 です。これは、ノード 2 には 4 つの追加軍隊があり、ノード 3 にはさらに 3 つ必要ですが、ノード 2 自体には 1 つ必要であるためです。 必要な唯一の移動は、ノード 2 からノード 3 への 1 つの軍隊であり、コストは 4 です。サブツリー全体のバランスのみを考慮し、内部バランスを無視するソリューションでは、コストが過大評価されます。 

## アプローチ

 直接的なアプローチでは、余剰の軍隊を持つ国から軍隊のない国に軍隊を繰り返し移動させようとすることになる。 グラフはツリーであるため、2 つの国家間の距離を簡単に計算できます。 行方不明の軍隊ごとに、近くに余っている軍隊を見つけて、道に沿って移動させることができます。 これは正しいです。なぜなら、どの軍隊も最終的には黒字の場所から赤字の場所まで移動しなければならないからです。 

問題は仕事量です。 最大 1,000,000 の軍隊が存在する可能性があり、各軍隊の移動には最大 250,000 本の道路を含む道を歩くことが含まれる可能性があります。 シミュレーションは以下の範囲に到達できます`10^11`最悪の場合、限界をはるかに超えるエッジトラバースが発生します。 

問題を変える観察は、各軍の正確なアイデンティティは重要ではないということです。 どんな道でも考えてみましょう。 その道路を削除すると、ツリーが 2 つのコンポーネントに分割されます。 道路の下にあるコンポーネントに必要以上の軍隊がある場合、余分な軍隊はすべてその道路を渡って出発する必要があります。 保有している以上の軍隊が必要な場合、行方不明の軍隊はその道路を渡って進入する必要があります。 グラフはツリーであるため、代替ルートはありません。 

したがって、エッジを横切る軍隊の数は、そのエッジの片側の内側の合計の黒字または赤字によって完全に決まります。 サブツリーのバランスを計算するだけで済みます。 

させて`balance[i] = xi - yi`。 正の値はサブツリーに追加の軍隊があることを意味し、負の値は軍隊が必要であることを意味します。 深さ優先トラバーサル中に、すべてのサブツリーの残高の合計を計算します。 すべての子エッジについて、子のサブツリー合計の絶対値によって、そのエッジを通過しなければならない軍隊の数がわかります。 エッジ コストを掛けると、その道路の寄与が求められます。

 | --- | --- | --- | --- |
 | ブルートフォース | O(軍隊の総数 × n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. ツリーを構築し、すべての国の初期残高を次のように保存します。`xi - yi`。 正の残高は国を離れることができる軍隊を表し、負の残高は到着しなければならない軍隊を表します。 
2. 任意の国でツリーをルート化し、深さ優先のトラバースを実行します。 走査中に、各サブツリーの合計バランスを計算します。 

すべてのエッジは 1 回だけカウントされ、エッジのコストはエッジを削除することによって作成される 2 つの辺にのみ依存するため、ルートの選択は答えに影響しません。 
3. 子サブツリーからその親に戻るときに、`abs(child_balance) * edge_cost`答えに。 

子サブツリーは、次のいずれかを送信します。`child_balance`軍隊を上向きにするか受け取る`-child_balance`軍隊を下に向けます。 両側間には他につながりがないため、道路はまさにその数の軍隊を処理する必要があります。 
4. 子の残高を親の残高に追加し、ツリー全体が処理されるまで続行します。 

このステートメントにより、軍隊の総数がすべての要件を満たすのに十分であることが保証されるため、ルートの最終残高を移動する必要はありません。 

### なぜ効果があるのか

 すべてのエッジについて、ツリー構造により、そのエッジの両側間のすべての相互作用がそのエッジを通過するように強制されます。 サブツリー内で必要な軍隊の最終的な数は固定されているため、その唯一の接続を通過する純量も固定されます。 トラバースでは、すべてのエッジに対してこの正確な量が計算され、その避けられない動きに対して可能な最小限のコストが請求されます。 すべての道路への寄与は独立して強制されるため、すべての寄与の合計が全体的な最適値となります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    graph = [[] for _ in range(n)]
    
    for _ in range(n - 1):
        u, v, c = map(int, input().split())
        u -= 1
        v -= 1
        graph[u].append((v, c))
        graph[v].append((u, c))
    
    balance = [0] * n
    for i in range(n):
        x, y = map(int, input().split())
        balance[i] = x - y
    
    ans = 0
    stack = [(0, -1, 0)]
    order = []
    
    while stack:
        u, p, state = stack.pop()
        if state == 0:
            stack.append((u, p, 1))
            for v, c in graph[u]:
                if v != p:
                    stack.append((v, u, 0))
        else:
            order.append((u, p))
    
    for u, p in order:
        if p != -1:
            pass
    
    parent = [-1] * n
    parent_cost = [0] * n
    stack = [0]
    parent[0] = -2
    
    while stack:
        u = stack.pop()
        for v, c in graph[u]:
            if parent[v] == -1:
                parent[v] = u
                parent_cost[v] = c
                stack.append(v)
    
    ans = 0
    for u, p in reversed(order):
        if p != -1:
            ans += abs(balance[u]) * parent_cost[u]
            balance[p] += balance[u]
    
    print(ans)

if __name__ == "__main__":
    solve()
```250,000 ノードのツリーでは Python のデフォルトの制限よりも大きな再帰の深さを作成できるため、コードは再帰を回避します。 最初の反復トラバーサルではポストオーダー シーケンスが作成され、親の前に子を処理できるようになります。 

2 番目のトラバーサルでは、各ノードの親と、その親に接続するエッジのコストが記録されます。 これにより、事後計算中に追加の状態を保存することが回避されます。 

最後のループでは、ノードを逆順に通過します。 この時点で、すべての子のサブツリーのバランスはすでに完了しているため、コードはエッジ コストを請求し、子のバランスを親にマージできます。 

Python の整数は、大きな応答値を自動的に処理します。 最大コストは約`10^6 * 10^6 * 250000`スケールが 32 ビット整数の制限を超えています。
