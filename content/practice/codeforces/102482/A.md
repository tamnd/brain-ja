 ## 解決策
 ## 問題の理解

 都市は有向時間グラフです。 各バスは、出発時刻、到着時刻、および旅行当日の存在確率を持つエッジです。 駅からスタートします`0`すべてのバスが出発する前に、駅に到着する確率を最大化する必要があります`1`時間までに`k`。 

この難しさは 2 つの詳細から生じます。 バスは消える可能性があり、それを知るのはバスを選択した後です。 また、同じ駅から同時に出発するバスをすべてテストすることはできません。1 回の試行が失敗すると、その出発時刻はすでに過ぎているからです。 

制約が主なヒントです。 まであります`10^6`バスと`10^6`そのため、時間の経過に伴う動的プログラミングや繰り返しのグラフ検索を伴うものは不可能です。 時間値は次のように大きくできます。`10^18`したがって、考えられるすべての瞬間を繰り返すことはできません。 アルゴリズムは、指定されたバス イベントのみを処理する必要があります。これは、ほぼ線形または線形対数の作業を意味します。 

よくある間違いは、同時に出発するバスを独立した選択として扱うことです。 例えば：```
2 2
1
0 1 0 1 0.5
0 1 0 1 0.5
```答えは`0.5`、 ない`0.75`。 試乗できるバスは 1 台のみです。 もう一つの間違いは、到着時刻と出発時刻が等しい場合に乗り換えを許可することです。 バスが出発するのとまったく同じ時刻にバスが到着した場合、その接続は無効です。 

## アプローチ

 ブルートフォースソリューションでは、考えられるあらゆる戦略をシミュレートしようとします。 すべての駅と時刻で、乗車可能なすべてのバスを考慮し、最良の確率を再帰的に計算します。 これは考えられるすべての決定を検討するため正しいですが、州の数は膨大です。 まであります`10^6`バスや一連の乗り換えにより、可能な戦略が飛躍的に生み出される可能性があります。 

重要な観察は、すべての決定は時間を遡って処理できるということです。 定刻に出発するバスを検討する場合`s`、その後に出発するすべてのバス`s`すでに取り扱い済みです。 したがって、このバスの目的地に到着した後に成功する最適な確率はすでにわかっています。 

させて`dp[v]`意味：もし私たちが駅にいるとしたら`v`現在処理されている時刻ですべての出発が行われた直後、最終的に空港に到着する最大確率はどれくらいですか?

 バスの場合`a -> b`定時に出発する`s`試してみると、確率は次のようになります。```
p * dp[b] + (1 - p) * dp[a]
```前期はバスが走行する場合です。 2期目は失敗して駅で立ち往生した場合`a`出発の瞬間が過ぎた後。 

同じ出発時刻のバスをまとめて処理する必要があります。 すべての候補者は、古い値を使用する必要があります。`dp[a]`失敗した試行を同時に別のバスが続行できないためです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | 指数 | 大 | 遅すぎる |
 | 後方スイープ | O(m log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.初期化`dp[1] = 1`なぜなら、すでに空港にいるということは成功を意味するからです。 他のすべてのステーションは確率で始まります`0`。 
2. すべてのバスを出発時刻の降順に並べ替えます。 目的地ではそれ以降のバスを利用できないため、最新の出発が最初に処理されます。 
3. 同じ出発時刻を共有するバスのグループごとに、現在の時刻を使用して可能なすべての試行を計算します。`dp`価値観。 
4. 確率のあるバスの場合`p`、候補値を格納します`p * dp[destination] + (1 - p) * dp[start]`。 
5. 時間グループ全体が評価された後、そのグループからの最良の候補で開始ステーションを更新します。 
6. すべてのバスが処理された後、`dp[0]`は初期状態からの最適な確率です。 

不変条件は、出発時刻を処理する前に`s`、`dp[v]`以降に出発するバスのみを使用した最適な確率がすでに含まれています`s`。 に出発するバス`s`宛先からの将来の情報のみが必要であり、その情報はすでに利用可能です。 等しい出発時刻をまとめて処理すると、その時点で 1 つのバスのみを乗車できるというルールが維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    m, n = map(int, input().split())
    k = int(input())

    buses = []

    for _ in range(m):
        a, b, s, t, p = input().split()
        buses.append((int(s), int(a), int(b), float(p)))

    buses.sort(reverse=True)

    dp = [0.0] * n
    dp[1] = 1.0

    i = 0
    while i < m:
        time = buses[i][0]
        best = {}

        while i < m and buses[i][0] == time:
            _, a, b, p = buses[i]
            value = p * dp[b] + (1.0 - p) * dp[a]

            if a not in best or value > best[a]:
                best[a] = value

            i += 1

        for a, value in best.items():
            if value > dp[a]:
                dp[a] = value

    print("{:.10f}".format(dp[0]))

if __name__ == "__main__":
    solve()
```ソート順は実装の中核です。 時間通りにバスが到着`t`常に時間が経つまでに答えが必要だ`t`、つまり、出発時間が次の時間を超えるすべてのバスを意味します。`t`すでに処理されている必要があります。 

グループのアップデートも欠かせません。 更新中`dp`1 台のバスを見た直後に、同じ出発時刻の別のバスが試行失敗後に改善された値を誤って使用する可能性があります。 候補者を囲い込む`best`これを防ぎます。 

必要なエラーは次のとおりであるため、ここでは Python 浮動小数点精度で十分です。`10^-6`。 時間値は算術演算では決して使用されないため、そのサイズによってオーバーフローの問題が発生することはありません。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(m log m) | 並べ替えが優先されます。 すべてのバスは 1 回処理されます。 
| スペース | O(n + m) | バスと駅ごとに 1 つの確率を保存します。 

100 万個のバスがあるため、リニア スキャンは容易に管理でき、十分なメモリ制限の下では対数ソート係数も許容されます。 

## 実際に動作した例

 2 番目のサンプルの場合:```
4 2
2
0 1 0 1 0.5
0 1 0 1 0.5
0 1 1 2 0.4
0 1 1 2 0.2
```最新の 2 つのバスが最初に処理されます。 

| 出発時間 | バスの確率 | 処理後の dp[0] |
 | --- | --- | --- |
 | 1 | 0.4、0.2 | 0.4 |
 | 0 | 0.5、0.5 | 0.7 |

 時間に`1`、最良の選択肢は確率を与えます`0.4`。 時間に`0`、最初のバスを試すと確率で成功します`0.5`、失敗すると後のバスに乗る可能性が残ります。 結果は次のとおりです。```
0.5 + 0.5 * 0.4 = 0.7
```これはサンプル出力と一致します。
