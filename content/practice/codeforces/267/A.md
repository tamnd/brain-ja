 ## 解決策
 ## 問題の理解

 同じ演算を 2 つの正の整数に繰り返し適用します。 すべてのステップで、大きい値から小さい値を減算します。 1 つの数値がゼロになるとすぐにプロセスが停止します。 タスクは、各ペアに対して実行された減算演算の数を数えることです。 

たとえば、から始めて、`(4, 17)`:`(4,17) → (4,13) → (4,9) → (4,5) → (4,1) → (3,1) → (2,1) → (1,1) → (0,1)`このシーケンスには以下が含まれます`8`操作。 

入力には最大で次のものが含まれます`1000`独立したペアであり、各値は次のように大きくできます。`10^9`。 操作ごとに 1 つの減算を実行する直接シミュレーションは、非常に遅くなる可能性があります。 考慮する`(1, 10^9)`。 このプロセスではほぼ 10 億回の操作が実行されます。これは、大きい数は 1 つだけ減少するためです。`1`毎回。 文字通りすべての減算をシミュレートするアルゴリズムは制限時間を超過します。 

このプロセスの構造は、最大公約数のユークリッド アルゴリズムによく似ています。 反復ごとに 1 回減算する代わりに、整数除算を使用して一度に行われる減算の数をカウントできます。 

見逃しやすいコーナーケースがいくつかあります。 

数値が等しい場合、1 回の操作で一方の値がすぐにゼロになります。 例えば：```
5 5
```答えは`1`、 ない`5`。 大きい値が小さくなるまで減算を繰り返す不注意な実装では、誤ってオーバーカウントする可能性があります。 

一方の数値が他方の数値よりはるかに大きいペアは、別の罠です。 例えば：```
1 1000000000
```正しい答えは、`1000000000`。 単純なループには 10 億回の反復がかかります。 

もう 1 つの微妙なケースは、大きい数値が小さい数値の正確な倍数である場合に発生します。```
3 12
```順序は次のとおりです。`(3,12) → (3,9) → (3,6) → (3,3) → (0,3)`答えは`4`。 発生した減算の回数をカウントせずに剰余演算のみを使用すると、情報が失われます。 

## アプローチ

 最も直接的な解決策は、説明どおりにプロセスを正確にシミュレートすることです。 各ステップで 2 つの数値を比較し、大きい数値から小さい数値を減算します。 減算するたびに答えを増やします。 

これが機能するのは、ルールが決定的であるためです。 すべての操作で 2 つの数値の合計が減少するため、プロセスは最終的に終了します。 

問題はパフォーマンスです。 最悪の場合、例えば、`(1, 10^9)`、アルゴリズムは 10 億回の反復を実行します。 これは、1 秒の制限時間内に収まる範囲をはるかに超えています。 

重要な観察は、引き算を繰り返すことは割り算と同じであるということです。 

あるとします。`(a, b)`と`a < b`。 引き算を繰り返す`a`から`b`まで続く`b < a`。 The number of performed subtractions is exactly`b // a`、残りの値は次のようになります。`b % a`。 

例えば：`(4,17)`引き算`4`繰り返し：`17 → 13 → 9 → 5 → 1`これにはかかりました`17 // 4 = 4`操作、新しい値は`17 % 4 = 1`。 

したがって、4 つの別々の操作を実行する代わりに、1 つのステップで結果に直接ジャンプできます。 

これにより、プロセスがユークリッド アルゴリズムに変換されます。 反復ごとに 1 つの数値が剰余に減算され、減算の合計数が整数除算によって累積されます。

 ## アルゴリズムのチュートリアル

 1. テスト ケースの数を読み取ります。 
2. ペアごとに`(a, b)`、初期化します`ans = 0`。 
3. 両方の数値が正の場合、次の操作を実行します。 

もし`a < b`、 それから`b`引き算ができる`a`その通り`b // a`より小さくなるまでの回数`a`。 

追加`b // a`答えに置き換えてください`b`と`b % a`。 
4. Otherwise, if`a >= b`、 それから`a`引き算ができる`b`その通り`a // b`より小さくなるまでの回数`b`。 

追加`a // b`答えに置き換えてください`a`と`a % b`。 
5. 1 つの数値がゼロになるまで続けます。 
6. 蓄積された回答を印刷します。 

### なぜ効果があるのか

 すべての段階で、プロセスは 1 回のジャンプで可能な最大数の同一の減算を実行します。 

もし`b > a`、減算を繰り返します`a`から`b`数学的には以下と同じです:```
b = b - a * (b // a)
```残りの値は正確に`b % a`、実行された操作の数は`b // a`。 

このアルゴリズムは、不必要な中間状態をスキップしながら、正確なシーケンス数を保存します。 各反復では 1 つの値が厳密に小さい剰余に置き換えられるため、ユークリッド アルゴリズムとまったく同様に、数値は急速に減少します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

t = int(input())

for _ in range(t):
    a, b = map(int, input().split())
    
    ans = 0
    
    while a > 0 and b > 0:
        if a < b:
            ans += b // a
            b %= a
        else:
            ans += a // b
            a %= b
    
    print(ans)
```このソリューションはユークリッド アルゴリズム構造に厳密に従います。 

両方の数値が正のままである間、ループは継続します。 いずれかの値がゼロになると、それ以上の減算はできないため、処理は自然に終了します。 

最も重要な詳細は、剰余を求める前に商を加算することです。 商は、スキップされる個々の減算演算の数を表します。 このステップを忘れると、合計操作数ではなく、最終的な gcd プロセスのみが計算されます。 

減算とモジュロを繰り返しても同じ剰余が生成されるため、モジュロを使用するのは安全です。 モジュロ バージョンは、多くの演算を 1 つの算術ステップに単純に圧縮します。 

Python の整数は最大の値を処理します`10^9`簡単に実行できるため、オーバーフローの心配はありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def solve():
    input = sys.stdin.readline

    t = int(input())
    
    out = []
    
    for _ in range(t):
        a, b = map(int, input().split())
        
        ans = 0
        
        while a > 0 and b > 0:
            if a < b:
                ans += b // a
                b %= a
            else:
                ans += a // b
                a %= b
        
        out.append(str(ans))
    
    print("\n".join(out))

def run(inp: str) -> str:
    backup_stdin = sys.stdin
    backup_stdout = sys.stdout

    sys.stdin = io.StringIO(inp)
    sys.stdout = io.StringIO()

    solve()

    output = sys.stdout.getvalue()

    sys.stdin = backup_stdin
    sys.stdout = backup_stdout

    return output
