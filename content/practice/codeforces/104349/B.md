 ## 解決策
 ## 問題の理解

 一連の独立したテスト ケースが与えられます。 各テスト ケースは 2 つの整数を提供します。$n$そして$m$、概念的に数値を形成します$n \cdot 245^m$。 タスクは、この完全な値を計算することではなく、基数 10 の最後の桁を決定することだけです。 

したがって、実際の出力の質問は、1 つの因子が固定基数である積の単位桁に関するものです。$n$、もう 1 つの係数は 245 の大きな累乗です。最後の桁のみが要求されるため、上位の値はすべて無関係であり、完全に無視できます。 

制約は大きく、両方とも$n$そして$m$まで行くことができます$10^9$、まであります$10^3$テストケース。 計算を試みるあらゆるアプローチ$245^m$指数自体が大きいため、たとえ高速のべき乗であっても、直接計算する必要はありません。なぜなら、私たちが関心のある量は構造上非常に小さく、わずか 1 桁であるためです。 

制約の主な意味は、ソリューションではすべてを最後の桁のみのモジュラー演算に帰着させる必要があるということです。 完全な整数や完全な累乗を処理しようとする試みは無駄であり、不必要です。 

微妙なエッジケースが現れるのは、$n = 0$。 この場合、積は常にゼロになります。$m$したがって、答えは常に 0 になります。もう 1 つの重要なエッジケースは次のような場合です。$m = 0$。 それから$245^0 = 1$したがって、答えは単に次の最後の桁です。$n$。 これらのケースは、指数だけに注目すると見落とされがちです。 

## アプローチ

 強引なアイデアは、計算することです$245^m$明示的に乗算する$n$、最後の数字を抽出します。 二乗によるべき乗に切り替えたとしても、依然として大きな整数を不必要に処理することになります。 Python では、これは小さな入力には耐えられるかもしれませんが、$m$まで$10^9$の場合、中間値は積極的に減らさない限りすぐに大きくなり、最後の桁のみが必要になるため、乗算ステップは無意味なオーバーヘッドになります。 

重要な観察は、最後の桁が乗算の下で循環的に動作することです。 最終積の最後の桁のみを考慮するため、両方を減らすことができます。$n$そして$245$すぐにモジュロ 10 を実行します。 これは問題をコンピューティングに変換します。$$(n \bmod 10) \cdot (5^m \bmod 10)$$245は5で終わるからです。 

これで構造が非常にシンプルになりました。 5 の累乗には安定した最後の桁があります。5 を一度でも掛け合わせると、結果は常に 5 になります。$m \ge 1$、$5^m$5で終わりますが、$5^0 = 1$。 

これにより、問題全体がテスト ケースの決定ごとの一定時間に短縮されます。

 ## アルゴリズムのチュートリアル

 問題を最後の桁の算術に縮小し、5 の指数の動作を明示的に処理します。 

1.読む$n$そして$m$テストケースごとに。 最後の数字のみが重要なので、すぐに計算します。$n \% 10$。 
2. 特殊なケースに対処する$n = 0$。 最初の因子がゼロの場合、積は常にゼロになるため、それ以上の計算を行わずに 0 を出力できます。 
3. かどうかを確認します。$m = 0$。 そうであれば、式は次のようになります$n \cdot 1$、したがって、答えは簡単です。$n \% 10$。 
4. もし$m \ge 1$、 交換する$245^m$最後の桁の動作を変更します。 245は5で終わるので、$5^m$すべてが正の場合は 5 で終わります$m$、2 番目の要素は、固定の最後の桁 5 に寄与します。 
5. の最後の桁を掛けます。$n$5 と入力し、その積の最後の桁を出力します。 

重要な考え方は、最後の桁まで減らすと、べき乗は一定のパターンに崩れるということです。 

### なぜ効果があるのか

 正確さは、積の最後の桁がその因数の最後の桁にのみ依存するという事実から得られます。 正式に言うと、$a \equiv a' \pmod{10}$そして$b \equiv b' \pmod{10}$、 それから$ab \equiv a'b' \pmod{10}$。 これにより、置き換えることができます$n$と$n \% 10$そして$245^m$と$(5^m \% 10)$最終的な答えに影響を与えることなく。 

2 番目の特性は、5 のべき乗が 10 を法として安定することです。$m \ge 1$、$5^m \equiv 5 \pmod{10}$。 これにより、べき乗ロジックが不要になります。 したがって、アルゴリズムは元の式と同じ最後の桁を生成することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n, m = map(int, input().split())

        if n == 0:
            print(0)
            continue

        last_n = n % 10

        if m == 0:
            print(last_n)
        else:
            print((last_n * 5) % 10)

if __name__ == "__main__":
    solve()
```この実装は、最後の桁の算術演算の直後に行われます。 唯一の分岐ロジックは、$m = 0$からのケース$m \ge 1$、そこではべき乗の恒等性が異なるためです。 5 による乗算は、最後の桁のみを考慮するため、直接実行しても安全です。 

最もよくある間違いは、計算しようとすることです$245^m$初期にモジュロ 10 を減算せずに累乗を使用します。 これは不必要な作業であり、最後の桁の単純な周期的な動作がわかりにくくなります。

 ## 特殊なケース

 のために$n = 0, m = 0$、アルゴリズムはゼロチェックのためすぐに 0 を返します。$0 \cdot 1 = 0$。 

のために$n = 987, m = 0$、電源ロジックをバイパスして戻ります。$987 \% 10 = 7$、恒等指数を正しく処理します。 

のために$n = 20, m = 5$、最後の桁の 0 を取得し、5 を掛けて 0 を生成します。指数が大きい場合でも、リダクションにより結果は即座に安定します。 

非常に大きい場合$m$、 のような$10^9$、アルゴリズムはべき乗を試行しません。 これは、5 の正のべき乗の最後の桁が 5 であるという事実に基づいているため、計算は大きさに関係なく一定時間になります。
