 ## 解決策
 ## 問題の理解

 文字列が与えられています`s`長さの`n`。 この文字列から、回転操作を実行できます。分割位置を選択します。`k`、接頭辞を削除します`s[0:k]`を最後に追加します。 これにより、文字列の循環シフトが生成されます。 以来`k`1 から までの範囲で指定できます`n`、まさにあります`n`可能な回転。 

タスクは、これらすべての回転を考慮し、辞書編集的に最小のものを返すことです。 

辞書編集的な比較は、通常の辞書の順序です。2 つの文字列を左から右に比較し、最初の異なる文字によって順序が決まります。 

制約`n ≤ 3 × 10^5`すべての回転を明示的に生成してソートすることを即座に除外します。 各回転の構築には時間がかかります`O(n)`、そしてすべての人のためにそれを行う`n`シフトは与える`O(n^2)`、1秒としては遅すぎます。 

すべての文字が同一である場合、微妙なエッジケースが発生します。`"aaaaa"`。 すべての回転は同一であるため、答えは同じ文字列になります。 正しいソリューションは、追加のロジックなしで自然にこれを処理する必要があります。 

もう 1 つの特殊なケースは、最小の文字が複数回出現する場合です。 例えば、`"baca"`。 複数の候補を完全な循環文字列として比較する必要があるため、「最小の文字から開始する」という素朴な貪欲な考えでは十分ではありません。```
baca → baca, acab, caba, abac
```答えは`"abac"`、これは後の出来事から来ています。`'a'`、最初ではありません。 

したがって、問題は、辞書編集順に基づいて最適な巡回シフトを選択することです。 

## アプローチ

 直接的な方法は単純です。すべてのローテーションを生成し、それらを比較し、最良のものを維持します。 回転するたびに文字列をスライスする必要があり、コストがかかります`O(n)`、そして、あります`n`回転、与える`O(n^2)`総仕事量。 と`n`最大 300,000 の場合、これは最悪の場合約 900 億の文字操作を意味しますが、これは現実的ではありません。 

重要な観察は、すべての候補文字列が 2 倍になった文字列の部分文字列であるということです。`s + s`。 すべての回転は長さの部分文字列に対応します`n`インデックスから始まる`i`この 2 倍の文字列では、`0 ≤ i < n`。 タスクは、辞書編集上最小の固定長の部分文字列を選択することになります。`n`これらの開始位置の中で。 

素朴な改善策は、候補をスキャンするときに候補の部分文字列を 1 文字ずつ比較することかもしれませんが、多くのプレフィックスが一致する場合、最悪の場合の動作は二次関数のままになります。 

重要な構造的洞察は、任意の部分文字列を選択しているのではなく、最小の循環回転を選択しているということです。 これは古典的な問題であり、一般にブースのアルゴリズムとして知られる 2 ポインター消去戦略を使用して線形時間で解くことができます。 候補の開始位置を維持し、辞書編集上の順序を相互に比較することによって最適化できないものを除外します。 

すべてのペアを明示的に比較する代わりに、文字あたりの償却定数時間で支配的な開始位置を段階的に破棄し、線形の複雑さを実現します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n^2) | O(n) | 遅すぎる |
 | ブースのアルゴリズム | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 ブースのアルゴリズムを適用して、辞書編集上最小の循環回転の開始インデックスを見つけます。 

1. 概念的に文字列を操作します`t = s + s`。 これにより、長さのあらゆる循環シフトが可能になります`n`の連続部分文字列として表示される`t`。 
2. 開始インデックスの候補を維持します`i`そして比較指標`j`、最初は`i = 0`そして`j = 1`。 現在のオフセットも追跡します`k`これは、2 つの候補間で文字がどの程度一致したかを表します。 
3. キャラクターを比較する`t[i + k]`そして`t[j + k]`。 等しい場合はインクリメントします`k`なぜなら、両方の回転がその位置まで一致するからです。 
4. 不一致が発生した場合、このオフセットでどちらの回転が辞書編集的に小さいかを判断します。 もし`t[i + k] < t[j + k]`、次に、から始まる回転`j`勝てない`i`なので、から始まるすべてを破棄します。`j`に`j + k`そしてセット`j = j + k + 1`。 逆が成り立つ場合は、以下の範囲を破棄します。`i`に`i + k`そしてセット`i = i + k + 1`、交換します`i`そして`j`保つ`i`現時点での最有力候補として。 
5. もし`i == j`、増分します`j`2 つの異なる候補者を確保するため。 
6. まで続けます`j`到達する`n`。 答えは部分文字列です`t[i:i+n]`。 

重要なアイデアは、2 つの回転の位置が異なると、`k`、負けているセグメントのすべての回転も悪化するため、1 つずつチェックする代わりに完全にスキップしても安全です。 

### なぜ効果があるのか

 このアルゴリズムは、破棄された位置が最適になることのないように、一連の候補開始位置を維持します。 2 つの開始点間の各比較により、最初の不一致に基づいて無効な候補のブロック全体が削除されます。 辞書編集上の順序は最初に異なる文字によって決定されるため、位置が失われる回転は行われません。`k`他の人に対して、後で良くなることはできません。 これにより、残りの候補者が`i`すべての循環シフトの中で最小です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def booth(s: str) -> int:
    t = s + s
    n = len(s)
    
    i, j, k = 0, 1, 0
    
    while j < n and i < n and k < n:
        if t[i + k] == t[j + k]:
            k += 1
            continue
        
        if t[i + k] > t[j + k]:
            i = i + k + 1
            if i <= j:
                i = j + 1
        else:
            j = j + k + 1
            if j <= i:
                j = i + 1
        
        k = 0
    
    start = min(i, j)
    return start

def solve():
    n = int(input().strip())
    s = input().strip()
    
    idx = booth(s)
    n = len(s)
    t = s + s
    print(t[idx:idx + n])

if __name__ == "__main__":
    solve()
```実装では、周期的な回転が線形部分文字列になるように、2 倍になった文字列を 1 回構築します。 2つの指針`i`そして`j`競合するローテーションの開始を表します。 変数`k`決定が必要になる前に、2 つのローテーションがどの程度一致したかを追跡します。 

実装でよくある落とし穴はリセットを忘れることです`k`ミスマッチの後。 このリセットがないと、比較では関連のないセグメント間の位置合わせが誤って想定されてしまいます。 もう 1 つの微妙な点は、インデックスが元の文字列の長さの範囲内に収まるようにすることです。`n`、文字列の長さを 2 倍にしたものではありません`2n`、だけなので`n`開始位置は有効な候補です。 

最終的な部分文字列の抽出では、選択した開始インデックスとスライスが正確に使用されます。`n`文字、完全な回転を保証します。

 ## 特殊なケース

 次のような単一文字列の場合`"a"`、アルゴリズムが初期化されます`i = 0`そして`j = 1`、 しかし`j`すぐに境界を超えるため、インデックス`0`が選択されます。 出力は`"a"`。 

次のような同一の文字を含む文字列の場合`"bbbbbb"`、あらゆる比較`t[i+k] == t[j+k]`まで続く`k = n`、消去は行われません。 アルゴリズムは戻ります`0`、元の文字列が変更されずに生成されます。 

最適な回転が遅く発生する文字列の場合、次のようになります。`"bcaac"`の場合、アルゴリズムは、厳密に小さい文字が何らかのオフセットで検出されるとすぐに初期の候補を破棄し、明示的な列挙を行わずに遅い最適な開始が確実に保持されるようにします。
