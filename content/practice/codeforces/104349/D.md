 ## 解決策
 ## 問題の理解

 1 から n までの同じ数値セットの 2 つの順列が与えられています。 各プレイヤーは 1 つの配列を所有し、移動中にプレイヤーは自分の配列から任意の 1 つの要素を削除できます。 削除するたびに、両方の配列が事実上縮小され、残りの要素の相対的な順序は保持されます。 

両方の配列がシーケンスとして同一になると、ゲームは終了します。つまり、配列の長さが同じで、すべての位置が一致します。 両方のプレーヤーが最適に動作し、タスクは、この同一の状態に到達するために両方のアレイにわたって必要な削除移動の最小合計数を決定することです。 

このプロセスを解釈する便利な方法は、削除は順序を維持しながら要素を削除するだけであるため、両方の配列を縮小できる共通のサブシーケンスを見つけようとしているということです。 したがって、最終的な同一の配列は、両方の順列でサブシーケンスとして現れるシーケンスでなければなりません。 双方が共通の部分を除くすべてを削除すると、ゲームは終了します。 

したがって、答えは、位置の一貫性を維持しながら両方の配列で変更せずに維持できる最長のシーケンスによって決まります。 

制約は強力です。n は最大 100,000 で、テスト ケース全体の合計は最大 100,000 です。これにより、テスト ケースごとの 2 次アプローチや n 対数 2 乗アプローチが即座に除外されます。 どのような解決策も本質的に線形または線形演算的でなければなりません。 

素朴だが魅力的なアイデアは、削除をシミュレートするか、考えられるすべての最終サブシーケンスを試すことです。 サブシーケンスの数が指数関数的であるため、これは失敗します。 もう 1 つのよくある間違った試みは、グローバルな一貫性を考慮せずに位置を貪欲に一致させることです。これは、2 つの順列間で相対的な順序付けの制約が競合すると破綻します。 

たとえば、A = [1, 2, 3, 4] および B = [2, 1, 4, 3] の場合、同じ位置または早期の一致を貪欲に一致させようとする可能性がありますが、ローカルな決定では、グローバルに一貫性のあるサブシーケンスのみが両方の配列で削除されても生き残ることができることが無視されます。 

## アプローチ

 重要な視点の変化は、削除という観点から考えるのをやめ、代わりに何を同時に保存できるのかという観点から考えることです。 

両方の配列は順列であるため、各値は各配列に 1 回だけ出現します。 これにより、一方の順列を他方の順列に対する位置マップとしてエンコードできるようになります。 具体的には、配列 A を固定すると、各値 x を A 内のインデックスにマッピングできます。その後、配列 B は、その値が A 内で出現する場所に応じたインデックスのシーケンスになります。 

これにより、問題は古典的な構造に変換されます。変換された配列の最も長く増加する部分列が必要になります。 増加するサブシーケンスは、両方の順列で同じ相対順序で現れる値に対応します。これはまさに、削除されても生き残ることができる共通のサブシーケンスに必要なものです。 

LIS の長さ (たとえば L) を計算すると、これは両方の配列に同じ順序で残ることができる要素の最大数を表します。 どちらの配列も最終的には保存されたシーケンスと正確に等しくなる必要があるため、各配列は n − L 個の要素を削除する必要があります。 したがって、両方のプレーヤーにわたる削除の合計数は 2(n − L) になります。 

ブルートフォースアプローチでは、A のすべてのサブシーケンスを試し、それが同じ順序で B に出現するかどうかを確認します。これは指数関数的です。 LIS の削減により、互換性条件全体が 1 つのシーケンス最適化問題に圧縮されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース (すべてのサブシーケンスを試す) | O(2^n · n) | O(n) | 遅すぎる |
 | 最適 (位置マッピングによる LIS) | O(n log n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 テストケースごとにテストを進めていきます。

1. pos[x] が順列 A の値 x のインデックスになるように、位置配列 pos を構築します。これにより、値を A の相対的な順序に変換できるようになります。 
2. 順列 B を配列 T に変換します (T[i] = pos[B[i]])。 ここで、T は A の座標系で表現された B を表します。 
3. 尾部配列を使用した標準的な忍耐ソート手法を使用して、T の最も長く増加する部分列の長さを計算します。 各要素は二分探索を使用して挿入されます。 
4. L を LIS の長さとします。 最終的な答えは 2 * (n − L) です。 

ステップ 3 が有効である理由は、T の増加するサブシーケンスは増加する A のインデックスに対応し、対応する値が A と B の両方で同じ順序で現れることを意味するためです。 

### なぜ効果があるのか

 変換されたシーケンスの LIS は、どちらの順列でも順序に違反することなく保持できる要素の最大セットを正確にキャプチャします。 各数値は両方の配列で一意であるため、A の順序を保持することは、A のインデックスを増加する必要があることと同じであり、B の順序の一致は T の構築によって保証されます。削除するたびに、この最大の一貫性のある構造だけが残るまで、配列が対称的に縮小されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

from bisect import bisect_left

def lis_length(arr):
    tails = []
    for x in arr:
        i = bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)

def solve():
    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        A = list(map(int, input().split()))
        B = list(map(int, input().split()))
        
        pos = [0] * (n + 1)
        for i, v in enumerate(A):
            pos[v] = i
        
        T = [pos[v] for v in B]
        L = lis_length(T)
        out.append(str(2 * (n - L)))
    
    print("\n".join(out))

if __name__ == "__main__":
    solve()
```解決策は、A の位置マップを構築することから始まります。これは、2 番目の順列を同等の数値シーケンスに変換するために不可欠です。 T への変換はキー削減ステップであり、ここで間違いがあると順序付けロジックが壊れるため、慎重に行う必要があります。 

LIS 関数は、二分探索で貪欲尾配列を使用します。 不変条件は、tails[i] が長さ i+1 の増加するサブシーケンスの可能な最小の終了値を格納することです。 これにより、最適な拡張の可能性が保証されます。 

最後に、答えの計算は、両方の配列が選択された共通サブシーケンスにないすべての要素を削除する必要があることを直接反映します。 

## 実用的な例

 ### 例 1

 入力:

 A = [1、2、3、4]、B = [2、1、4、3]

 A からの位置マップ:

 1→0、2→1、3→2、4→3

 変換されたB:

 T = [1, 0, 3, 2]

 LIS の計算:

 | ステップ | × | 尾 |
 | --- | --- | --- |
 | 1 | 1 | [1] |
 | 2 | 0 | [0] |
 | 3 | 3 | [0, 3] |
 | 4 | 2 | [0, 2] |

 L = 2

 答え = 2 * (4 − 2) = 4

 これは、両方の置換にわたって一貫した順序で保持できる要素は 2 つだけであることを示しています。 

### 例 2

 入力:

 A = [4、2、3、1]、B = [4、3、2、1]

 A からの位置マップ:

 4→0、2→1、3→2、1→3

 変換されたB:

 T = [0、2、1、3]

 リス:

 | ステップ | × | 尾 |
 | --- | --- | --- |
 | 1 | 0 | [0] |
 | 2 | 2 | [0, 2] |
 | 3 | 1 | [0, 1] |
 | 4 | 3 | [0、1、3] |

 L = 3

 答え = 2 * (4 − 3) = 2

 これは、両方の順列が高度に混合されている場合でも、相対的な構造が部分的に一致していれば、長く一貫したサブシーケンスが依然として存在できることを示しています。

 ## 特殊なケース

 完全に同一の順列ペアは厳密に増加する変換シーケンスを生成するため、LIS は n に等しく、答えは 0 になります。 すべての要素が置換せずに tails 配列を拡張するため、アルゴリズムはこれを自然に処理します。 

完全に逆転した順列では、厳密に減少する変換シーケンスが生成されるため、LIS は常に 1 になります。コードは末尾のエントリを繰り返し正しく置換し、長さ 1 で終了し、2(n − 1) を生成します。 

n = 1 や n = 2 などの小さな n の場合は、LIS 計算と位置マッピングの両方が安全に低下するため、特別なロジックなしで処理されます。n = 1 の場合、T には 1 つの要素があり、LIS は 1 となり、予想どおり削除はゼロになります。
