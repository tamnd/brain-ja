 ## 解決策
 ## 問題の理解

 2 つの文字列が与えられます。最初は次のようになります。`"a"`、および繰り返される文字列をいずれかに追加する一連の操作`s`または`t`。 各操作の後、文字を再配置できるかどうかを判断する必要があります。`s`そして`t`となることによって`s`辞書編集的には以下より小さい`t`。 

入力により、操作の数と、各操作のタイプ (に追加されます) が与えられます。`s`または`t`)、繰り返し回数`k`、および文字列`x`追加します。 出力は、各操作に対する「YES」または「NO」のシーケンスであり、条件を満たす辞書編集が存在するかどうかを示します。`s < t`。 

制約は大きく、すべてのテスト ケースにわたる演算の合計数は 10^5 に達する可能性があり、文字列の合計の長さは最大 5 × 10^5 に達する可能性があります。 これにより、文字列の連結や完全な並べ替えを繰り返すと制限時間が超過するため、操作のたびに文字列を明示的に構築して並べ替えるソリューションは即座に除外されます。 

単純なアプローチは、一方の文字列が多数の下位文字を蓄積し、もう一方の文字列が単一の上位文字を追加する場合には失敗します。 たとえば、次のように始めます。`s = "a"`そして`t = "a"`、追加のような操作を実行すると、`"a"`何百万回も`s`そして`"b"`一度に`t`、単純な文字列の構築は実行不可能です。 

この問題は、文字列を明示的に構築せずに、各文字列内の文字に関する十分な情報を追跡して、辞書編集的により小さい配列が存在するかどうかを判断することに帰着します。 

## アプローチ

 ブルートフォース手法では、両方の文字列を完全に構築し、並べ替えてから、文字ごとに比較して辞書編集上の順序を決定します。 これは正しいですが、文字列の連結と並べ替えを繰り返すことで複雑さが大きくなります。 最悪の場合、長さ 10^5 の文字列を繰り返し追加すると、10^10 の操作を超え、実行可能な制限をはるかに超えます。 

重要な点は、任意の並べ替え後の辞書編集的な比較は、各文字列内の最小文字の存在と各文字列内の最大文字の存在という 2 つのことだけに依存するということです。 もし`s`の最大文字数を超える文字が含まれています`t`、小さくすることはできません。 逆に、もし`s`のみが含まれています`'a'`そして`t`より大きい文字が含まれています`'a'`、いつでも手配できます`s`より小さくなる。 

各文字列に存在する最上位の文字とその数を追跡するだけで済みます。`'a'`キャラクター、以来`'a'`は最小の文字です。 もし`t`より大きい文字が含まれています`'a'`、`s`数に関係なく、常に小さくすることができます`'a'`が入っています`s`。 もし`t`のみが含まれます`'a'`では、`s`非のものは厳密に少なくする必要があります。`'a'`よりも`t`より小さくなる。 

これは、次の数を維持するという解決策につながります。`'a'`s と各文字列の最大文字数。 各操作によりこれらのカウントが更新され、比較はこれらの値の単純なチェックに減ります。

 | 最適 | O(合計操作数) | 文字列あたり O(26) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 両方の文字列のカウンターを初期化します: count of`'a'`文字と表示される最大文字数。 最初は両方の文字列に 1 つの文字列があります`'a'`そして最大キャラクター`'a'`。 
2. 各操作について、操作の種類、繰り返し回数を読み取ります。`k`、文字列`x`。 
3. の数を数えます`'a'`の文字`x`そして最大文字数を決定します`x`。 
4. これらのカウントを乗算します。`k`それぞれの文字列カウンターを更新します。 最大文字には、現在の最大値とこの操作の最大値のうちの最大値を使用します。 
5. 更新後、辞書編集上の状態を確認します。 

- 最大文字数が`s`より大きい`'a'`そして`t`のみが含まれます`'a'`、`s`小さくできない場合は「NO」を出力します。 
- もし`t`より大きい文字が含まれています`'a'`、並べ替えることができるので「YES」を出力します。`'a'`にいる`s`大きい文字の前に来る`t`。 
- それ以外の場合は、次の数を比較します。`'a'`s: もし`s`厳密に少ない`'a'`よりも`t`、「YES」を出力します。 それ以外の場合は「いいえ」。 
6. すべての操作に対して繰り返します。 

機能する理由: 各ステップで、手配の可能性を判断するために必要な最小限の情報を維持します。`s`辞書編集的により小さいこと`t`。 最大文字数と`'a'`任意の配置が許可されるため、count によって相対順序が完全に決定されます。 完全な文字列が必要になることはないため、パフォーマンスは操作の数に比例します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        q = int(input())
        s_a_count, t_a_count = 1, 1
        s_max, t_max = 'a', 'a'
        
        for _ in range(q):
            d, k, x = input().split()
            d = int(d)
            k = int(k)
            
            a_count = x.count('a') * k
            max_char = max(x)
            
            if d == 1:
                s_a_count += a_count
                s_max = max(s_max, max_char)
            else:
                t_a_count += a_count
                t_max = max(t_max, max_char)
            
            if s_max > 'a' and t_max == 'a':
                print("NO")
            else:
                print("YES")

if __name__ == "__main__":
    solve()
```コードは次のカウントを維持します。`'a'`s と両方の文字列の最大文字数。 小切手`s_max > 'a' and t_max == 'a'`次の場合にのみ「NO」を出力するようにします。`s`厳密に次より大きい文字が含まれています`'a'`そして`t`だけを持っています`'a'`s. それ以外の場合は、何らかの取り決めが常に満たすため、答えは「YES」です。`s < t`。 の乗算カウント`'a'`によって`k`文字列を構築せずに、繰り返しの追加操作が効率的に処理されるようにします。
