 ## 解決策
 ## 問題の理解

 私たちには、方向のない道路で接続された一連の場所が与えられています。 各道路には一定の通過時間が設定されていますが、信号が赤と青を繰り返すため、道路の使用は複雑になります。 

ある時点で道路の一方の端に到達した場合、すぐに横断を開始できない場合があります。 各道路には繰り返しのスケジュールがあり、最初に長さ r の赤色の期間が進入禁止になり、次に長さ g の緑色の期間に入り、道路への進入と通行が許可されます。 このパターンは永遠に繰り返されます。 

緑色のフェーズ中に到着した場合は、すぐに開始できます。 赤のフェーズ中に到着した場合は、次の緑のフェーズが始まるまで待つ必要があります。 横断を開始した後は、その道路に沿って移動するのに常に t 単位の時間を費やします。 

このタスクは、ノード 1 からノード n までの移動に必要な最小時間を計算することです。 

グラフには最大 100,000 のノードと 100,000 の道路があります。 各道路クエリには時間依存の動作に関する推論が必要ですが、その構造は依然として、エッジ緩和にねじれを加えた標準的な最短経路問題です。 

単純な解釈では、信号機を無視し、すべてのエッジをコスト t を持つものとして扱うことになります。 これは、待ち時間が答えを支配する可能性があり、グラフ構造だけでなく到着時間にも依存するため、すぐに失敗します。 

純粋なエッジの重みの点でより短いパスが存在する場合でも、待機が必須である場合には、微妙なエッジ ケースが発生します。 たとえば、緑のフェーズに一致する長いパスを介してノードに早期に到達でき、または赤のフェーズに到達する短いパスを介して後でノードに到達できるとします。 欲張りな最短エッジアプローチでは、誤って後者を選択してしまいます。 

もう 1 つのよくある失敗は、エッジ トラバーサルごとではなく、ノードごとに待機が 1 回だけ発生すると想定していることです。 待機時間は各エンドポイントでの正確な到着時間に依存するため、同じノードに到達する 2 つの異なるパスによって、将来のコストが異なる可能性があります。 

## アプローチ

 この強引なアイデアは、これを時間依存のグラフ問題として扱い、それを通過するすべての可能な方法をシミュレートすることです。 (ノード、時間) で定義された状態から、すべての発信エッジを試し、信号サイクルをチェックして次の有効な出発時刻を計算し、再帰的に、または時間経過に伴う BFS 状態を継続します。 これは、すべての実行可能なスケジュールを明示的にモデル化しているため、正しいです。 

問題は、時間が無制限であるということです。 到着後に発生する時間のみを考慮した場合でも、緩和のたびに新しい個別のタイムスタンプが生成されます。 最悪の場合、エッジトラバーサルごとに一意の時間値が生成される可能性があり、状態の数はノードの数ではなく時間の大きさに応じて増加します。 最大 10^5 のエッジがあると、これは状態の爆発にまで縮退します。 

重要な観察は、この問題が依然として最短経路の最適な下部構造特性を満たしていることです。つまり、ノードへの既知の最良の到着時刻を一度修正すれば、それより悪い時刻で再検討する必要はありません。 唯一の複雑な点は、エッジ緩和が決定論的関数によって到着時間に依存することです。待ち時間は時間の法 (r + g) から計算されます。 これにより、グラフはダイクストラのアルゴリズムに適したものになり、エッジの重みは一定ではありませんが、その場で評価できます。 

状態を列挙する代わりに、各ノードの最もよく知られている到着時間を維持します。 時間 T で u から v へのエッジを緩和するとき、サイクルによって生じる待ち時間を計算し、それを T に加算してから、通過時間 t を加算します。 これにより、重み付きエッジとまったく同様に、v の候補到着時刻が生成されます。 

これにより、問題は、非定数だが明確に定義された緩和関数を使用した標準的な単一ソース最短経路計算に変換されます。

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |

 ## アルゴリズムのチュートリアル

 1. 各エッジが格納するグラフの隣接リスト (近傍、移動時間 t、赤 r、緑 g) を構築します。 これにより、各ノードからの下り道路を効率的に反復できるようになります。 
2. 時間 0 のノード 1 から開始するため、dist[1] = 0 を除き、サイズ n の配列 dist を無限大で初期化します。 
3. 現在既知の時間順に並べられた優先キューを使用します。 開始状態として (0, 1) を挿入します。 
4. 既知の最小到着時間 cur を持つノード u を繰り返し抽出します。 cur がすでに dist[u] より大きい場合は、u に到達するよく知られた方法があるため、それをスキップします。 
5. u から v までの各エッジについて、サイクル長 c = r + g を計算します。 サイクル内の位置を cur % c として決定します。 
6. この位置が赤色のフェーズにある場合、つまり r 未満である場合、待ち時間を r - (cur % c) として計算します。 それ以外の場合、待ち時間はゼロになります。 これは、グリーンフェーズが始まるまで待機するモデルです。 
7. 候補到着時刻を cur + wait + t として計算します。 これは、この境界線を通過し終えることができる最も早い時間を表します。 
8. この候補時間が dist[v] を改善する場合、それを更新し、(candidate, v) を優先キューにプッシュします。 
9. 到達可能なすべてのノードが処理されるまで続行します。 答えは dist[n] です。 

正確さは、ノードが最小時間で優先キューからポップされると、その後の緩和によってノードの到着時間が改善されないという事実に依存します。 エッジの重みは時間に依存しますが、同じエッジ上で後の到着がより早い出発を生み出すことはできないという意味で、緩和関数は決定論的かつ単調です。 

## なぜ機能するのか

 核となる不変条件は、dist[u] がこれまでに見つかったノード u での達成可能な最小到着時間を常に格納し、優先キューは常にその時点での最小の時間を拡張することです。 待機時間関数は、各トラバーサルをソース ノードへの到着時間のみに基づいて決定論的なコストに変換するため、すべてのエッジ緩和は既知の状態に対する固定関数を評価することと同等です。 すべてのコストは負ではなく、ダイクストラは常に時間の増加順にノードを終了するため、後でノードに到達する代替パスが以前の状態を遡及的に改善することはできず、時間依存のエッジがあっても正確性が維持されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline
import heapq

def solve():
    n, m = map(int, input().split())
    g = [[] for _ in range(n + 1)]

    for _ in range(m):
        a, b, t, r, gr = map(int, input().split())
        g[a].append((b, t, r, gr))
        g[b].append((a, t, r, gr))

    INF = 10**30
    dist = [INF] * (n + 1)
    dist[1] = 0

    pq = [(0, 1)]

    while pq:
        cur, u = heapq.heappop(pq)
        if cur != dist[u]:
            continue

        for v, t, r, gr in g[u]:
            cycle = r + gr
            pos = cur % cycle

            wait = 0
            if pos < r:
                wait = r - pos

            nxt = cur + wait + t

            if nxt < dist[v]:
                dist[v] = nxt
                heapq.heappush(pq, (nxt, v))

    print(dist[n])

if __name__ == "__main__":
    solve()
```隣接リストにはフル エッジ パラメータが格納されるため、各緩和はグローバルな前処理を行わずにローカルで待機時間を計算できます。 

プライオリティ キューにより、現在最もよく知られている部分ルートが常に拡張されます。 小切手`if cur != dist[u]`古い状態の処理を回避します。これは、操作ごとの複雑さを対数範囲内に保つために不可欠です。 

待機ロジックは唯一の非標準部分です。待機ロジックは、循環制約を現在のタイムスタンプから計算される単一の追加遅延に変換します。

 ## 特殊なケース

 1 つのエッジ ケースは、r = 0 の場合に発生します。これは、赤色の位相が存在しないことを意味します。 その状況では、待機中の計算が決してトリガーされてはなりません。 のような入力の場合`1 2 5 0 10`の場合、アルゴリズムは pos = 0 を正しく計算し、赤色の間隔は表示されず、直接コスト 5 が生成されます。 

もう 1 つのケースは、到着時間がちょうど赤と緑の境界に達する場合です。 赤は間隔 [0, r) として定義されているため、正確に時間 r に到着しても待ち時間は発生しません。 pos >= r がグリーン フェーズに入るために、モジュロ ロジックがこれを処理します。 

最後の微妙なケースは、複数のパスが異なるタイミングでノードに到達する場合です。 優先キューにより、最も早い到着が最初に処理され、それ以降の到着はすべて破棄されます。 長時間待機してもすぐに到達可能なノードと、待機なしでゆっくりと到達可能なノードの場合、アルゴリズムは両方を正しく評価しますが、各緩和は独立して評価されるため、結果として得られる最小時間のみが維持されます。
