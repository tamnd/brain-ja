 ## 解決策
 ## 問題の理解

 寿司の列が与えられます。各寿司はいずれかのタイプです。`1`または入力してください`2`。 この行の連続するセグメントを 1 つ選択したいと考えています。 

セグメントは、寿司の種類が異なる 2 つの連続するブロックで構成され、両方のブロックのサイズが同じである場合に有効です。 例えば、`[2,2,2,1,1,1]`3つなので有効です`2`sの後に3つが続く`1`s. のようなセグメント`[2,2,1,1]`も有効です。 のようなセグメント`[1,2,1,2]`は、各半分に両方のタイプが含まれているため無効です。 

タスクは、そのような有効な連続セグメントの可能な最大長を見つけることです。 

配列の長さは次のように大きくできます。`100000`これにより、すべての部分配列を検査する高価なアプローチが即座に除外されます。 おおよそあります`n²`考えられるサブ配列、これは周囲にあります`10^10`最悪の場合のチェック。 たとえ`O(n²)`アルゴリズムが遅すぎます。 配列を線形時間またはそれに近い時間で処理するソリューションが必要です。 

難しいのは、選択したセグメントが同じ値の連続全体を使用する必要がないことです。 実行の一部のみを使用する場合があります。 

考慮する：```
1 1 1 1 2 2
```ランには長さがある`4`そして`2`。 最も有効なセグメントは次のとおりです。```
1 1 2 2
```長さのある`4`。 完全な実行のみを考慮する不注意な実装では、誤った結果が返されます。`6`。 

別の微妙なケースは次のとおりです。```
1 2 1 2
```どのランにも長さがある`1`。 

正しい答えは、`2`、最適なセグメントは次のいずれかであるため、`[1,2]`または`[2,1]`。 有効なセグメントはもうありません。 複数の交互の実行をマージしようとする実装では、誤った結果が生成されます。 

もう 1 つのエッジケースは次のとおりです。```
1 1 1 2
```ランレングスは次のとおりです。`3`そして`1`。 

答えは`2`を使用して`[1,2]`。 より大きなランでは、そのすべての要素を使用する必要はありません。 2 つの隣接する実行からの等しいカウントのみが必要です。 

## アプローチ

 ブルートフォースソリューションでは、考えられるすべてのサブ配列を列挙し、それが同じサイズの異なる寿司タイプの連続する 2 つのブロックで構成されているかどうかを確認します。 単一のサブ配列のチェックには直線的な時間がかかる場合があり、最悪の場合の複雑さが発生します。`O(n³)`。 最適化を行ったとしても、すべてを検査すると、`O(n²)`部分配列は不可能です`n = 100000`。 

重要な観察は、配列を等しい値の連続として見ることから得られます。 

例えば：```
2 2 2 1 1 2 2
```は次のようになります:```
[3, 2, 2]
```ここで、各数字は連続するブロックの長さを表します。 

有効な答えは、2 つの隣接する実行から形成されなければなりません。 2 つの隣接するランに長さがある場合`a`そして`b`、次のようにすることができます。```
min(a, b)
```それぞれの側面からの要素。 

これにより、有効な長さのセグメントが作成されます。```
2 * min(a, b)
```たとえば、実行します`(3,2)`ある長さのセグメントを生成します`4`、実行中`(5,7)`ある長さのセグメントを生成します`10`。 

すべての有効なセグメントは 2 つの隣接するラン間の 1 つの境界をまたいで存在する必要があるため、問題は次の最大値を見つけることになります。```
2 * min(run[i], run[i+1])
```すべての隣接する実行ペアにわたって。 

ランレングスの構築にはアレイを 1 回通過し、隣接するランをチェックするにはもう 1 回のパスが必要です。 これにより線形の解が得られます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n²) から O(n³) | お(1) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 寿司配列を左から右にスキャンし、ランレングスに圧縮します。 

例えば：```
2 2 2 1 1 2 2
```は次のようになります:```
[3, 2, 2]
```それぞれの数字は、同じ寿司の 1 つの最大ブロックのサイズを記録します。 
2. 隣接する実行のすべてのペアを繰り返します。 

長さが次の場合`a`そして`b`、境界を越える最大の有効なセグメントは、`min(a,b)`各実行からのピース。 
3. コンピューティング`2 * min(a,b)`隣接するペアごとに。 

これは、その境界の周囲に形成できる最大有効セグメントです。 
4. 表示された最大値を保持します。 
5. 最大値を出力します。 

### なぜ効果があるのか

 すべての有効なセグメントには、各タイプ 1 つずつ、正確に 2 つの連続する寿司グループが含まれています。 このようなセグメントは、圧縮表現内の 2 つの隣接するランの間の 1 つの境界を越える必要があります。 

隣接するランレングスが次のようになると仮定します。`a`そして`b`。 両方の種類の寿司を同じ数に保つには、最大でも次の数を使用できます。`min(a,b)`両側からの部分。 それ以上使用すると、小さい方の実行のサイズを超えてしまい、均等条件が崩れてしまいます。 

したがって、その境界に関連付けられた最適なセグメントの長さは次のようになります。`2 * min(a,b)`。 すべての有効なセグメントは何らかの隣接するランのペアに対応するため、すべての隣接するランの最大値を取得すると、考えられるすべての答えが検査され、最適なものが返されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    t = list(map(int, input().split()))

    runs = []
    cnt = 1

    for i in range(1, n):
        if t[i] == t[i - 1]:
            cnt += 1
        else:
            runs.append(cnt)
            cnt = 1

    runs.append(cnt)

    ans = 0
    for i in range(len(runs) - 1):
        ans = max(ans, 2 * min(runs[i], runs[i + 1]))

    print(ans)

solve()
```コードの最初の部分は、寿司シーケンスのランレングス エンコーディングを構築します。 変数`cnt`現在のブロック サイズを追跡します。 寿司の種類が変わるたびに、完了した実行が保存され、新しい実行が開始されます。 

スキャンが終了したら、最後の実行も追加する必要があります。 最後の実行後に変更が行われないため、この手順を忘れることはよくあるバグです。 

2 番目のループでは、隣接する実行のペアをすべて検査します。 各ペアの式は、`2 * min(runs[i], runs[i + 1])`その境界を越える最大の有効なセグメントが得られます。 

答えは単にこれらの値の最大値です。 

すべての有効なセグメントは隣接するランのペアによって表されるため、元の配列の境界に対して特別な処理は必要ありません。

## テストケース```python
# helper: run solution on input string, return output string
import sys
import io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)

    n = int(input())
    t = list(map(int, input().split()))

    runs = []
    cnt = 1

    for i in range(1, n):
        if t[i] == t[i - 1]:
            cnt += 1
        else:
            runs.append(cnt)
            cnt = 1

    runs.append(cnt)

    ans = 0
    for i in range(len(runs) - 1):
        ans = max(ans, 2 * min(runs[i], runs[i + 1]))

    return str(ans) + "\n"

# provided sample
assert run("7\n2 2 2 1 1 2 2\n") == "4\n", "sample 1"

# minimum size
assert run("2\n1 2\n") == "2\n", "minimum size"

# unequal neighboring runs
assert run("6\n1 1 1 1 2 2\n") == "4\n", "take only part of larger run"

# alternating values
assert run("4\n1 2 1 2\n") == "2\n", "many runs of length one"

# larger balanced runs
assert run("8\n1 1 1 2 2 2 2 2\n") == "6\n", "min of adjacent runs"

# off-by-one around final run
assert run("7\n1 1 2 2 2 2 1\n") == "4\n", "last run handled correctly"

 ## 特殊なケース

 次のことを考慮してください。```
4
1 1 1 2
```ランの長さは次のとおりです。```
[3, 1]
```アルゴリズムは以下を計算します。```
2 * min(3, 1) = 2
```そして戻ってきます`2`。 これは有効なセグメントに対応します`[1,2]`。 小さいランには寿司が 1 つしか含まれていないため、大きいランは複数の要素に寄与することはできません。 

次に、次のことを考えてみましょう。```
4
1 2 1 2
```ランの長さは次のとおりです。```
[1, 1, 1, 1]
```候補値は次のとおりです。```
2, 2, 2
```そして答えは`2`。 アルゴリズムは、3 つ以上の連続した実行を組み合わせるのを正しく回避します。 

最後に、次のことを考慮してください。```
8
1 1 1 1 2 2 2 2
```ランの長さは次のとおりです。```
[4, 4]
```答えは次のとおりです。```
2 * min(4, 4) = 8
```配列全体が有効であり、アルゴリズムは完全な長さを返します。
