 ## 解決策
 ## 問題の理解

 私たちには一団があります`n`サーカスアーティスト、どこで`n`均等であることが保証されています。 各アーティストは、ピエロ、アクロバット、またはその両方になるスキルを持っている場合もあれば、どちらでもない場合もあります。 最初のパフォーマンスのピエロの数が 2 番目のパフォーマンスのアクロバットの数と等しくなるように、アーティストを 2 つの等しいサイズのパフォーマンスに分割するように求められます。 出力は単に最初のパフォーマンスに参加したアーティストのインデックスです。または、`-1`そのような部門が存在しない場合。 

重要な制約は次のとおりです。`n`は最大 5000 まで可能で、1 秒に制限されています。これは、どの解もおおよそ O(n^2) 以上である必要があることを示唆しています。 可能なすべての組み合わせを生成する`n/2`アーティストは検査が必要になるだろう`C(n, n/2)`サブセットは指数関数的よりも速く増加します。`n`そして実行不可能です。 したがって、すべての分割を強引に列挙することはできません。 

多くのアーティストが同じスキルを持っている場合、重要な特殊なケースが発生します。 たとえば、すべてのアーティストがピエロになれるが、誰もアクロバットになれない場合、平等条件を満たすことは不可能です。 もう 1 つの微妙なケースは、分割によって複数の方法で等価性が満たされる場合です。 この問題では有効な解決策は何でも可能ですが、アルゴリズムはインデックスの位置ずれや off-by-one エラーを避けるように注意する必要があります。 

## アプローチ

 素朴なアプローチは、考えられるすべてのサブセットを列挙することです。`n/2`アーティストは、前半はピエロ、後半はアクロバットを数えて状態を確認します。 これはすべてのパーティションを徹底的に考慮するため、原則的には正しいです。 ただし、その時間計算量は O(2^n) であり、`n = 5000`。 

最適なアプローチは、各アーティストがそのスキルに基づいて 4 つのカテゴリのいずれかに属するという事実を利用します。つまり、ピエロとアクロバットの両方になれる、ピエロのみになれる、アクロバットのみになれる、またはどちらのスキルも持たない。 アーティストをこれら 4 つのグループに分類し、パフォーマンス全体でピエロとアクロバットのバランスを取るために各グループに必要なカウントを推論できます。 

これらのグループを次のように表します。`(1,1)`両方ができる、`(1,0)`ピエロだけ、`(0,1)`アクロバットだけ、`(0,0)`どちらでもない。 各タイプのアーティストの数を表すと、各グループから何人かを選択することで最初のパフォーマンスを構築できます。 させて`x`の数になります`(1,1)`初公演のアーティスト、`y`なれ`(1,0)`、`z`なれ`(0,1)`、 そして`w`なれ`(0,0)`。 次に、制約は 2 つの線形方程式に帰着します。 

1.`x + y + z + w = n/2`(初演サイズ)
 2.`x + y = total acrobats in second performance`実現可能な範囲で反復することにより、`x`そして調整する`y`、`z`、`w`したがって、有効な分割が存在する場合は、それを構築できます。 反復回数は O(n) であるため、この解決策は効率的です。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(2^n) | O(n) | 遅すぎる |
 | 最適 | O(n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 1.読む`n`ピエロの 2 つのスキル文字列`c`そしてアクロバット`a`。 便宜上、これらの文字列を整数のリストに変換します。 
2. 各アーティストを 4 つのスキル タイプのいずれかに分類する`(c[i], a[i])`、インデックスを別のリストに保存します。`both`、`only_clown`、`only_acrobat`、`neither`。 これは、最初のパフォーマンスのアーティストをすばやく選択するのに役立ちます。 
3. アーティストの数を繰り返す`x`から取る`both`最初のパフォーマンスのグループ、0 から最大のサイズまで`both`。 それぞれについて`x`、必要な数を計算します。`only_clown`そして`only_acrobat`カウントのバランスを取るため。 
4. コンピューティング`y`の数として`only_clown`最初のパフォーマンスでは、残りの最初のパフォーマンス スロットが確実に埋まるようにすることで制約されます。`(0,1)`そして`(0,0)`アーティストたち。 同様に計算すると、`z`の数として`only_acrobat`。 それを確認してください`y`そして`z`それぞれのリストのサイズを超えず、選択されたアーティストの合計数が正確に一致すること。`n/2`。 
5. 有効な組み合わせの場合`(x, y, z, w)`が見つかった場合は、各グループのインデックスの連結リストを出力し、正確に選択します。`x`から`both`、`y`から`only_clown`、`z`から`only_acrobat`、 そして`w`から`neither`。 
6. 制約を満たす組み合わせがない場合、出力`-1`。 

機能する理由: 各アーティストは、構造上、正確に 1 つのパフォーマンスに割り当てられます。 アルゴリズムは、4 つのスキル タイプ間で可能なすべての分割を考慮することにより、可能であれば、最初のパフォーマンスのピエロと 2 番目のアクロバットの間の平等が満たされるようにします。 反復ではすべての有効なカウントが考慮されるため、`both`アーティストにとって、アルゴリズムは解決策を見逃すことはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

n = int(input())
c = list(map(int, input().strip()))
a = list(map(int, input().strip()))

both = []
only_clown = []
only_acrobat = []
neither = []

for i in range(n):
    if c[i] and a[i]:
        both.append(i+1)
    elif c[i]:
        only_clown.append(i+1)
    elif a[i]:
        only_acrobat.append(i+1)
    else:
        neither.append(i+1)

half = n // 2
found = False

for x in range(len(both)+1):
    for y in range(len(only_clown)+1):
        if x + y > half:
            break
        z = half - (x + y)
        w = half - (x + z)
        if 0 <= z <= len(only_acrobat) and 0 <= w <= len(neither):
            first_perf = both[:x] + only_clown[:y] + only_acrobat[:z] + neither[:w]
            if len(first_perf) == half:
                print(" ".join(map(str, first_perf)))
                found = True
                break
    if found:
        break

if not found:
    print(-1)
```最初のセクションでは、アーティストを 4 つのグループに分類します。 入れ子になったループは、可能な回数だけ繰り返します。`both`そして`only_clown`アーティストたち。 の計算`z`そして`w`最初のパフォーマンス サイズが正確であることを保証します。`n/2`。 慎重にインデックスを作成することで、off-by-one エラーが回避されます。 有効な設定が存在しない場合は、次のように出力します。`-1`。
