 ## 解決策
 ## 問題の理解

 まっすぐな砂浜に小屋が並んでいます。 小屋`i`小屋からちょうど100メートルです`i-1`、そしてそれぞれの小屋にはある程度の人数がいます。 既存のアイスクリームショップも同一線上の任意の整数座標に配置されます。 

追加のアイスクリーム ショップの位置を選択する必要があります。 人は、新しい店が既存のどの店よりも自分の小屋に厳密に近い場合にのみ、新しい店から購入します。 目標は、可能な限り最適な場所を選択して、誘致できる人の最大総数を見つけることです。 

重要な観察は、新しい店舗の場所が 1 次元であるということです。 固定小屋の場合、新しいショップが勝つ一連のポジションは常にインターバルです。 

小屋と既存の店舗の数は両方とも20万に達する可能性があります。 これにより、考えられるすべての新しい店舗の位置を試したり、すべての小屋をすべての店舗と比較したりすることが直ちに除外されます。 二次解は最悪の場合でも約 400 億回の演算を実行することになりますが、これは通常のコンテストの制限時間の許容範囲をはるかに超えています。 に近い解決策が必要です`O((n + m) log m)`またはそれ以上です。 

いくつかの特殊なケースは見落とされがちです。 

まさに既存の店舗の場所に小屋を考えてみましょう。```
Input
1 1
5
0
```新しい店舗は既存の店舗の場所以外のどこにでも配置できますが、新しい店舗を少し離れた場所に移動することで、小屋にいる人を引き付けることができます。 正しい答えは次のとおりです。```
5
```整数の位置のみを考慮するソリューションでは、すべての選択肢が誤って拒否される可能性があります。 

もう 1 つのケースは、最適な場所がすべての小屋の範囲外にある場合です。```
Input
3 1
4 10 3
1000
```新しい店舗は、既存の唯一の店舗よりも小屋の近くに配置できます。 検索対象を既存の店舗間のセグメントに限定すると、有効な回答が失われる可能性があります。 

最後の微妙なケースは厳密な比較です。 新しい店舗が既存の店舗とまったく同じ距離にある場合、人は新しい店舗を選択しません。 

例えば：```
Input
2 1
7 8
50
```小屋 1 と既存の店舗の中間点は、勝ち位置ではなく、引き分け位置です。 スイープでは、間隔のエンドポイントを除外として処理する必要があります。 

## アプローチ

 直接的なアプローチは、新しい店舗の候補地を試し、その店舗を好む小屋が何社あるかを数えることです。 答えは特定の重要な位置でのみ変化しますが、それらを列挙するのは依然としてコストがかかりすぎます。 すべての小屋をすべての既存の店舗と一度照合したとしても、コストは`O(nm)`、約に達することができます`4 * 10^10`比較。 

視点を変えると役に立つのは、店舗の場所について考えるのをやめて、それぞれの小屋について独立して考えることです。 

座標にある小屋1つ分`h`、最寄りの既存店舗までの距離を`d`。 この小屋では、次の場合に新しいショップが勝ちます。```
|position - h| < d
```これは開いた間隔です:```
(h - d, h + d)
```したがって、すべての小屋は、1 つの間隔内で考えられるすべての新しい店舗の位置にその人口を貢献します。 問題は、多くの間隔の重み付けされた最大の重複を見つけることになります。 

これはスイープ ラインで解決できます。 小屋の間隔に入るときに小屋の人口を追加し、離れるときに小屋の人口を削除します。 間隔が開いているため、同じ座標で追加する前に削除を処理する必要があります。 

残った唯一の仕事は見つけることです`d`効率的に。 既存の店舗の位置をソートした後、小屋に最も近い店舗は、ソート順でその位置の周囲にある 2 つの店舗のいずれかでなければなりません。 二分探索でこれが得られます`O(log m)`時間。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(nm) | お(1) | 遅すぎる |
 | 最適 | O((n + m) log m) | O(n + m) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 既存のすべてのアイスクリーム ショップの座標を並べ替えます。 すべての小屋について、最も近い既存の店舗はその右側の最初の店舗か左側の最初の店舗のみであるため、この並べ替え順序により二分探索が可能になります。 
2. 各小屋の距離を求めます`d`最寄りの既存店舗へ。 新しいショップが小屋の中に置かれたときと同じように、小屋は新しいショップによってサービスを受けることができます。`(h - d, h + d)`。 この間隔に 2 つのスイープ イベントを追加します。 
3. 左のエンドポイントを追加イベントとして保存し、右のエンドポイントを削除イベントとして保存します。 間隔は開いているため、スイープがその座標に到達する前に右エンドポイントの寄与を停止する必要があります。 
4. すべてのイベントを座標順に並べ替えます。 各座標で、まずそこで終わるすべての間隔を削除し、次にそこから始まるすべての間隔を追加します。 現在の合計は、その座標の直後にサービスを受けた人々を表します。 
5. 現在の合計の最大値を追跡します。 

なぜ効果があるのか:

 すべての小屋について、新しい店舗が既存のすべての店舗より厳密に近くなる一連の位置を正確に作成します。 スイープ ラインは、有効な間隔に選択した位置が現在含まれているすべての小屋の人口の合計を維持します。 考えられるすべての変更は間隔の境界でのみ発生するため、連続する境界間の値をチェックするだけで十分です。 スイープによって維持される最大数は、まさに可能な限り最良の顧客数です。 

## Python ソリューション```python
import sys
from bisect import bisect_left

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    people = list(map(int, input().split()))
    shops = list(map(int, input().split()))
    shops.sort()

    events = []

    for i, p in enumerate(people):
        h = i * 100
        pos = bisect_left(shops, h)

        dist = 10**18
        if pos < m:
            dist = min(dist, abs(shops[pos] - h))
        if pos > 0:
            dist = min(dist, abs(shops[pos - 1] - h))

        left = h - dist
        right = h + dist

        events.append((left, 1, p))
        events.append((right, -1, p))

    events.sort()

    ans = 0
    cur = 0
    i = 0

    while i < len(events):
        x = events[i]

        while i < len(events) and events[i][0] == x[0]:
            if events[i][1] == -1:
                cur -= events[i][2]
            i += 1

        j = i
        while j < len(events) and events[j][0] == x[0]:
            cur += events[j][2]
            j += 1

        ans = max(ans, cur)
        i = j

    print(ans)

if __name__ == "__main__":
    solve()
```最初の部分では、お店の場所を読み取って並べ替えます。 並べ替えにより、二分検索で最寄りの店舗のクエリが可能になります。 

各小屋について、コードは幾何学的条件を間隔に変換します。 変数`dist`は最も近い既存の店舗までの距離であり、勝利領域はその半径の小屋座標を中心とします。 

スイープ イベントは次のように保存されます。`(coordinate, type, value)`。 の一種`-1`人口を除去する一方で、`1`人口を追加します。 処理順序が重要な詳細です。 間隔が開いているため、同じ座標での追加の前に削除が発生します。 この順序が逆の場合、ある人が誤って同順位でカウントされる可能性があります。 

すべての座標と人口は Python 整数に快適に適合します。 答えは次のように大きくなります。`200000 * 10^9`したがって、固定幅の 32 ビット整数を使用する言語では、より幅の広い型が必要になります。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O((n + m) log m) | 店舗やイベントの並べ替えが実行時間の大半を占めます。 
| スペース | O(n) | 小屋ごとに 2 つのイベントが保存されます。 

最大 200,000 の小屋と店舗について、アルゴリズムは並べ替えと二分検索のみを実行します。 これは、すべての小屋とすべての店舗を比較するアプローチとは異なり、意図した制限内に簡単に収まります。 

## テストケース```python
import sys
import io
from bisect import bisect_left

def solve(inp):
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    n, m = map(int, input().split())
    people = list(map(int, input().split()))
    shops = list(map(int, input().split()))
    shops.sort()

    events = []

    for i, p in enumerate(people):
        h = i * 100
        idx = bisect_left(shops, h)

        d = 10**18
        if idx < m:
            d = min(d, abs(shops[idx] - h))
        if idx:
            d = min(d, abs(shops[idx - 1] - h))

        events.append((h - d, 1, p))
        events.append((h + d, -1, p))

    events.sort()

    cur = ans = 0
    i = 0
    while i < len(events):
        x = events[i][0]

        while i < len(events) and events[i][0] == x and events[i][1] == -1:
            cur -= events[i][2]
            i += 1

        j = i
        while j < len(events) and events[j][0] == x:
            cur += events[j][2]
            j += 1

        ans = max(ans, cur)
        i = j

    return str(ans)

 ## 特殊なケース

 小屋が既存の店舗とまったく同じ座標にある場合でも、新しい店舗がその点から離れる可能性があるため、その勝利間隔は依然として正の幅を持ちます。 間隔半径は最も近い既存の店舗までの距離であり、スイープでは除外されたエンドポイント自体が評価されることはないため、アルゴリズムはこれを処理します。 

例えば：```
Input
3 2
1 1 1
300 99
```小屋の座標は`0`、`100`、 そして`200`。 真ん中の小屋は既存の店舗と同じ位置にありますが、新しい店舗は左右に少し移動できます。 Interval メソッドはこれらの可能性を取得し、次の値を返します。```
2
```すべての小屋が既存店舗から遠い場合、最適な位置は既存店舗の範囲外になる可能性があります。 このアルゴリズムは、有限の検索範囲を想定していません。 ジオメトリによって生成された有効な間隔のみが使用されます。 

のために：```
Input
3 1
2 5 6
169
```最良のポイントは既存のショップの前であり、スイープは最初の 2 つの間隔の重なり部分を正確に検出します。 

最後に、厳密な不平等が重要です。 新しい店が既存の店と結びつく時点では、その人は寄付をしません。 同じ座標で追加イベントの前に削除イベントを処理すると、それらの無効なタイ位置が考慮から削除されます。
