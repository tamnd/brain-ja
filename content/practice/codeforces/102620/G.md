 ## 解決策
 ## 問題の理解

 音楽は音符の並びによって表現されます。 各音符には、必要な弓の方向 (ダウンボウ (`D`) またはアップボウ (`U`)、またはマークされていない場合もあります (`B`）。 マークされていないすべての音符の方向を決定する必要があります。 最終シーケンスには何も含めることはできません`B`、元のマーキングは変更できません。 

フックボウイングは、隣接する 2 つの音符が同じ方向を使用する場合に発生します。 目標は、フック付きのボウイングをすべて回避することではありません。固定音によって強制される場合、それが不可能になる可能性があるためです。 代わりに、隣接する等しいペアの総数ができるだけ少なくなるように、マークのない音符の方向を選択する必要があります。 

入力サイズは最大 1000 ノートまで可能です。 空白のノートの可能な限りの割り当てを試みるソリューションでは、次の点まで考慮する必要があります。$2^{1000}$可能性は、実行できるものをはるかに超えています。 次のノートの決定は前のノートで選択された方向にのみ依存するという事実を利用して、シーケンスを直接処理するアプローチが必要です。 

難しいケースは、最適な選択が局所的に明らかではない場合です。 たとえば、入力が次の場合:```
3
B D B
```正しい答えは次のようになります。```
U D U
```2 つの方向転換とフックボウイングなし。 常に前のノートとは異なる方向を選択する貪欲な戦略は、後で失敗する可能性があります。数ポジション前の固定ノートにより、より良い初期の選択が強制される可能性があるためです。 

もう 1 つのエッジ ケースは、すべてのノートがすでに修正されている場合です。```
4
D D U U
```唯一の有効な出力は次のとおりです。```
D D U U
```2つのフック付き弓。 最小値を検索しながら固定メモを変更しようとする実装では、無効な答えが生成されます。 

最後の境界ケースは単一の音符です。```
1
B
```答えはどちらかです`U`または`D`。 隣接する音符がないため、フックボウイングの最小数はゼロです。 すべての音符に左隣の音符があると想定しているコードは、ここで失敗する可能性があります。 

## アプローチ

 直接的な総当たりアプローチは、すべての文字列を置き換えることです。`B`どちらかで`U`または`D`、結果のシーケンスを評価し、フックボウイングが最も少ない割り当てを維持します。 これは、楽譜の有効な完成をすべてチェックするため、正しいです。 ただし、1000 個のノートがすべて空白の場合、割り当ての数は$2^{1000}$、各割り当てではシーケンス全体をスキャンする必要があります。 操作回数はおおよそ$1000 \times 2^{1000}$、それは不可能です。 

問題の構造により、より小さな状態空間が得られます。 現在の音符の方向を選択する場合、重要となる前の音符の情報は、直前の音符の方向だけです。 最初の 10 音符に多くのフック ボウイングが含まれているか、少数のフック ボウイングが含まれているかは、次で終わる最適なコストがわかってしまえば問題ではなくなります。`U`で終わる最良のコスト`D`。 

これは自然に動的プログラミングにつながります。 すべてのポジションについて、その時点までのすべての有効な割り当ての中でフックボウイングの最小数が、最後の音符の方向で区切られて保存されます。 次のノートを処理するとき、ノートが空白の場合は両方の可能な方向を試行し、固定されている場合は単一の許可された方向を試行します。 新しい方向が前の方向と等しくなるたびに、トランジションによって 1 が追加されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(N × 2^N) | O(N) | 遅すぎる |
 | 最適 | O(N) | O(N) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各位置に対して 2 つの動的プログラミング状態を作成します。 1 つの状態は、次で終わる割り当ての中でフック付きボウイングの最小数を保存します。`U`、もう 1 つは、で終わる代入に対して同じ値を格納します。`D`。 

最後の方向のみを維持する理由は、次の音符は直前の音符で新しいフック付きボウイングを作成することしかできないためです。 
2. 最初のノートを初期化します。 に固定されている場合`U`、のみ`U`状態が可能です。 に固定されている場合`D`、のみ`D`状態が可能です。 空白の場合は、コスト 0 で両方の状態が可能です。 
3. 残りのノートを左から右に処理します。 現在の音符の考えられる方向ごとに、前の音符の考えられる両方の方向を調べます。 2 つの方向が等しい場合はコストに 1 を追加します。これは、フック状の弓なりが発生するためです。 
4. 小さい方の値を保存し、前のどの方向でその値が生成されたかを覚えておいてください。 保存された親情報により、最小コストを見つけた後に実際のシーケンスを再構築することができます。 
5. 全体を処理した後、最終的なもののうち小さい方を選択します。`U`そして`D`州。 完全な答えを取得するには、保存された親の指示を逆にたどってください。 

なぜ効果があるのか:

 動的計画法の不変条件は、処理後の位置です。`i`、各状態には、最初のすべての有効な割り当ての中で可能な最小限のフック付きボウイングが含まれます。`i + 1`指定された最後の方向を持つノート。 トランジションでは、現在の音符の考えられるすべての方向と、前のプレフィックスの考えられるすべての最適な終了方向が考慮されます。 すべての完全な割り当ては次のいずれかで終了する必要があるため、`U`または`D`、より良い最終状態を取得すると、全体的に最適なソリューションが得られます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve_case(s):
    n = len(s)

    inf = 10**9
    dp = [[inf, inf] for _ in range(n)]
    parent = [[-1, -1] for _ in range(n)]

    choices = []
    for c in s:
        if c == 'U':
            choices.append([0])
        elif c == 'D':
            choices.append([1])
        else:
            choices.append([0, 1])

    for c in choices[0]:
        dp[0][c] = 0

    for i in range(1, n):
        for cur in choices[i]:
            for prev in (0, 1):
                cost = dp[i - 1][prev] + (1 if cur == prev else 0)
                if cost < dp[i][cur]:
                    dp[i][cur] = cost
                    parent[i][cur] = prev

    last = 0 if dp[-1][0] <= dp[-1][1] else 1

    ans = [0] * n
    ans[-1] = last
    for i in range(n - 1, 0, -1):
        ans[i - 1] = parent[i][ans[i]]

    return ' '.join('U' if x == 0 else 'D' for x in ans)

def main():
    n = int(input())
    s = input().split()
    print(solve_case(s))

if __name__ == "__main__":
    main()
```の`choices`配列は、各ノートを許容される方向のセットに変換します。 固定ノートには 1 つの方向が考えられますが、空白ノートには両方の方向があります。 

の`dp`テーブルには、各ポジションまでのフックボウイングの最適な数が保存されます。 インデックス`0`を表します`U`とインデックス`1`を表します`D`。 移行中、式は`(1 if cur == prev else 0)`フックド・ボウイングの定義と正確に一致します。 

の`parent`最小コストだけでは十分ではないため、テーブルが必要です。 最後に到達したら、実際のシーケンスを 1 つ出力する必要があります。 すべての最適な状態を生成した以前の方向を保存することにより、すべての候補シーケンスを保存せずに答えを再構築できます。 

フック付きボウイングの最大数は 1 回だけであるため、大きな算術上の懸念はありません。`N - 1`したがって、通常の Python 整数で十分です。 最初のノートには前のノートがなく、フック状のボウイングを作成できないため、最初のノートは個別に初期化されます。 

## 実用的な例

 次のサンプルを考えてみましょう。```
7
B D B B B U U
```考えられる動的プログラミング トレースは次のとおりです。 

| ポジション | 注 | ベストエンディングU | ベストエンディングD | 選択された最終方向 |
 | --- | --- | --- | --- | --- |
 | 0 | B | 0 | 0 | |
 | 1 | D | INF | 0 | |
 | 2 | B | 1 | 1 | |
 | 3 | B | 1 | 2 | |
 | 4 | B | 2 | 2 | |
 | 5 | う | 2 | INF | |
 | 6 | う | 2 | INF | |

 保存された親から再構築された最終的な答えは、次のような 1 つの最適な割り当てになります。```
U D D U D U U
```トレースは、アルゴリズムがすべてのローカル ペアを個別に最小化していないことを示しています。 将来のより良い決定は以前の方向に依存するため、両方の可能な結末が維持されます。 

2 番目の例:```
4
D D U U
```トレースは次のようになります。 

| ポジション | 注 | ベストエンディングU | ベストエンディングD | 選択された最終方向 |
 | --- | --- | --- | --- | --- |
 | 0 | D | INF | 0 | |
 | 1 | D | INF | 1 | |
 | 2 | う | 1 | INF | |
 | 3 | う | 1 | INF | |

 唯一の有効な出力は次のとおりです。```
D D U U
```2 つの等しい隣接するペアは避けられません。 動的プログラミングの状態では、フックを削除しようとするのではなく、固定されたマーキングが正しく保存されます。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(N) | 各ノートでは、前の 2 つの状態と現在の 2 つの状態のみが考慮されます。 |
 | スペース | O(N) | 親テーブルには、再構築中に状態ごとに 1 つ前の方向が保存されます。 |

 1000 ノートという制約は、この線形ソリューションに簡単に適合します。 親の再構築データを使用した場合でも、メモリ使用量はわずか数千の整数です。

import sys
import io

def solve_case(s):
    n = len(s)
    inf = 10**9
    dp = [[inf, inf] for _ in range(n)]
    parent = [[-1, -1] for _ in range(n)]

    choices = []
    for c in s:
        if c == 'U':
            choices.append([0])
        elif c == 'D':
            choices.append([1])
        else:
            choices.append([0, 1])

    for c in choices[0]:
        dp[0][c] = 0

    for i in range(1, n):
        for cur in choices[i]:
            for prev in (0, 1):
                cost = dp[i - 1][prev] + (cur == prev)
                if cost < dp[i][cur]:
                    dp[i][cur] = cost
                    parent[i][cur] = prev

    last = 0 if dp[-1][0] <= dp[-1][1] else 1
    ans = [0] * n
    ans[-1] = last
    for i in range(n - 1, 0, -1):
        ans[i - 1] = parent[i][ans[i]]

    return ' '.join('U' if x == 0 else 'D' for x in ans)

def run(inp: str) -> str:
    data = inp.strip().split()
    n = int(data[0])
    return solve_case(data[1:1+n])

def hooked_count(out):
    a = out.split()
    return sum(a[i] == a[i+1] for i in range(len(a)-1))

assert len(run("1\nB\n").split()) == 1, "minimum size"

assert hooked_count(run("4\nD D U U\n")) == 2, "fixed notes"

assert hooked_count(run("3\nB D B\n")) == 0, "blank around fixed note"

assert hooked_count(run("5\nB B B B B\n")) == 0, "all equal freedom"

assert hooked_count(run("6\nU U U U U U\n")) == 5, "all fixed same direction"
```| テスト入力 | 期待される出力 | 検証内容 |
 | --- | --- | --- |
 |`1 / B`| 任意の単一方向 | 最初の位置を正しく処理します。 
|`D D U U`| 同じ固定シーケンス | 必須のマーキングを保持 |
 |`B D B`| ゼロフックも可能 | 貪欲なローカルミスを回避します |
 | 5 つの空白のメモ | 交互の方向 | 空白の位置で自由を使用 |
 | 六`U`メモ | 六`U`メモ | 避けられないフックを処理します。 

## 特殊なケース

 単一の空白のメモの場合:```
1
B
```アルゴリズムは両方の状態をコスト 0 で初期化します。 遷移がないため、どちらの方向も最適であり、再構成では 1 つの有効な答えが返されます。 

固定された連続音符の場合:```
4
D D U U
```各位置の選択リストには固定値のみが含まれるため、アルゴリズムは代替方向を挿入しません。 遷移では、避けられない 2 つの等しいペアがカウントされ、唯一の有効な完了が生成されます。 

固定メモの周囲の空白の場合:```
3
B D B
```最初の空白は割り当てることができます`U`最後の空白も割り当てることができます`U`、生産:```
U D U
```どちらのトランジションも異なる方向の間で行われるため、答えにはフックされたボウイングはありません。 動的プログラミング状態では、各ステップで両方の可能性が維持され、このグローバルな選択を見つけることができます。
