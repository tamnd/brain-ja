 ## 解決策
 ## 問題の理解

 私たちは、直線状の水族館で優勢なピラニアを特定するように求められました。 それぞれのピラニアにはサイズがあり、自分よりも小さい隣接するピラニアを繰り返し消費することで、最終的に他のすべてのピラニアを食べることができる場合、ピラニアは優勢です。 食べるたびにサイズが1つずつ大きくなります。 入力では複数のテスト ケースが提供され、それぞれがピラニアの数とサイズを指定します。 出力は、優勢なピラニアの 1 から始まるインデックスか、存在しない場合は -1 でなければなりません。 

この制約は、すべてのテスト ケースにわたるピラニアの総数が 300,000 に達する可能性があるため、すべての可能な動きの総当りシミュレーションが実行不可能であることを意味します。 すべての候補ピラニアについて考えられるそれぞれの食事シーケンスをシミュレートすると、2 次またはそれよりも悪い複雑さが生じ、これは 2 秒の制限時間では受け入れられません。 

すべてのピラニアが同じサイズの場合、明らかではないエッジケースが発生します。 このようなシナリオでは、ピラニアが別のピラニアを食べることはできないため、正しい出力は -1 になります。 もう 1 つの微妙なケースは、配列内で最大サイズが複数回出現する場合です。 それ自体よりも小さい少なくとも 1 つの近傍を持つ最大値のみが潜在的に支配的になる可能性があります。 たとえば、`[5, 5, 4, 3, 5]`、最初で最後`5`隣接する小さいピラニアは食べることができませんが、真ん中のピラニアは食べられません。`5`を食べることができます`4`その右側にあるため、有効な候補です。 

## アプローチ

 素朴なアプローチは、各ピラニアを候補として試し、ピラニアが他のすべてのピラニアを食べるか動けなくなるまで、その動きをシミュレーションすることです。 これが機能するのは、ルールが決定的であるためです。つまり、ピラニアは隣接する小さなピラニアのみを食べることができます。 ただし、サイズの配列の場合、`n`、単一のシミュレーションには次のことが含まれる可能性があります。`O(n^2)`すべてのテスト ケースを合計すると、次のステップを超える操作が発生します。`10^10`が遅すぎます。 

重要な洞察は、**最大サイズ**のピラニアのみが優勢になり得るということです。 最大値より小さいピラニアは大きいピラニアを消費することはできないため、即座に失格となります。 最大サイズのピラニアの中で、ピラニアが優勢になることができるのは、**自分より小さい隣のピラニアが少なくとも 1 つ**ある場合のみです。 これは、成長するには出発点が必要であり、より小さな隣のものがなければ、食べるプロセスを開始できないためです。 この観察により、配列を 1 回スキャンして最大値を見つけてから、その近傍を調べるだけで済みます。 これにより、各テスト ケースの配列サイズの複雑さが線形に軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | テスト ケースあたり O(n²) | O(n) | 遅すぎる |
 | 最大 + 近傍チェック | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テストケースについて、ピラニアの数を読み取ります。`n`そして配列`a`サイズの。 
2. 配列内の最大サイズを見つけます。 
3. 配列を走査して、この最大サイズを持ち、それ自身よりも小さい近傍が少なくとも 1 つあるピラニアを見つけます。 
4. そのようなピラニアが存在する場合は、その 1 から始まるインデックスを出力し、それ以上の検索を停止します。 
5. 配列をスキャンした後にそのようなピラニアが見つからなかった場合は、-1 を出力します。 

効果がある理由: 定義上、最大サイズのピラニアだけが他のすべてのピラニアを食べることができます。 最大サイズのピラニアに小さな隣接ピラニアがいない場合は、消費を開始できないため、支配することはできません。 少なくとも1匹の小さな隣のピラニアを持つ最大サイズのピラニアは左右に貪欲に食べることができ、隣のピラニアを食べた後、成長して他のピラニアがすべてなくなるまで食べ続けることができます。 不変条件は、受験者はいつでも食事を開始できなければならないということです。 アルゴリズムはそれを正確にチェックします。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        max_size = max(a)
        
        dominant_index = -1
        for i in range(n):
            if a[i] == max_size:
                if (i > 0 and a[i-1] < max_size) or (i < n-1 and a[i+1] < max_size):
                    dominant_index = i + 1  # 1-based index
                    break
        print(dominant_index)

if __name__ == "__main__":
    solve()
```コードは、テスト ケースの数を読み取ることから始まります。 テスト ケースごとに最大サイズを計算し、配列を反復処理して、少なくとも 1 つの小さな近傍を持つ最大サイズのピラニアを見つけます。 の`i + 1`調整は、問題に必要な 0 ベースのインデックス付けを 1 ベースのインデックス付けに変換します。 ブレークにより、最初の有効な候補が出力されますが、有効な候補はどれでも受け入れられます。 

## 実用的な例

 **例 1:**`[5, 3, 4, 4, 5]`| 私 | a[i] | 隣人チェック | 支配的な？ |
 | --- | --- | --- | --- |
 | 0 | 5 | 右=3 < 5 | はい |

 最初のピラニアは最大であり、隣に小さいピラニアがあるため、インデックス`1`有効です。 サンプル ソリューションでは、アルゴリズムによってインデックスが選択されます。`3`代わりに、これも機能します。 複数の回答も可能です。 

**例 2:**`[1, 1, 1]`| 私 | a[i] | 隣人チェック | 支配的な？ |
 | --- | --- | --- | --- |
 | 0 | 1 | 右=1 | いいえ |
 | 1 | 1 | 左=1、右=1 | いいえ |
 | 2 | 1 | 左=1 | いいえ |

 最大サイズのピラニアに、より小さな隣のピラニアは存在しません。 出力`-1`。

 ## 特殊なケース

 すべてのピラニアが同じサイズである配列の場合、食べ始めるためにより小さい隣のピラニアがないため、アルゴリズムは正しく -1 を出力します。 複数の最大値を持つ配列では、アルゴリズムは常に、より小さな近傍を持つ最初の最大値を見つけます。 最小入力サイズの場合`n=2`、チェックは正しく機能します。一方のピラニアが他方よりも厳密に大きい場合、それが優勢として選択されます。 入力サイズを最大化する場合、リニア スキャンによりパフォーマンスが制約内に収まることが保証されます。
