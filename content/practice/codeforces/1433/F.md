 ## 解決策
 ## 問題の理解

 次のような数字のグリッドが与えられます。$n$行と$m$列。 各行からいくつかの要素を選択できますが、厳密な制限があります。単一の行では、切り捨てられた要素の半分を超えて選択することはできません。 これらの選択を行ごとに個別に行った後、選択されたすべての値を合計します。 すべての有効な選択の中で、次の値で割り切れる最大の合計が必要です。$k$。 

その構造は次のとおりです。各行は、取り得る要素の数に関する行ごとの制限を尊重する場合に限り、可能な合計のセットを生成する小さな「選択マシン」です。 次に行を結合し、最後に総和の剰余だけを考慮します。$k$、具体的には、剰余ゼロと最大値が必要です。 

制約は非常に特殊な点で厳しいです。$n, m, k \le 70$値は小さい (最大 70)。 これにより、行列全体のすべてのサブセットに対する指数関数的なブルート フォースが即座に除外されます。これは、最大で次のものを選択する必要があるためです。$70 \cdot 70 = 4900$という要素が含まれますが、これは完全に不可能です。 行ごとのブルートフォースでも指数関数的です$m$そして、それを行ごとに独立して実行すると、やはり乗算すると非常に大きなものになります。 

制約の重要な意味は、行ごとの構造と係数の両方が小さいことです。 これは、モジュロ状態に対するナップザックのような DP と組み合わせた、行に対する動的プログラミングの古典的な信号です。 

間違いやすいいくつかの特殊なケース:

 すべての数値が小さく、割り算のために何も選択しないことが最適な場合、答えはゼロになる可能性があります。 たとえば、すべての数値が 1 mod k の余りを持ち、何かを選択すると割り切れない場合、正解は 0 になります。 

行に選択できる要素が 1 つだけある場合 ($m = 1$) の場合、すべての行は 0 またはその 1 つの要素のいずれかを提供し、解決策は行全体にわたるモジュール式のサブセット選択に帰着します。 

すべての値が非常に大きいものの、多くの要素を選択することで「行ごとに最大でも半分」という制約が破られるように構造化されている場合、行ごとに最適な要素を個別に選択する素朴な貪欲なアプローチは失敗します。これは、行間のモジュロ相互作用が重要であるためです。 

## アプローチ

 制約を無視する場合、最も直接的な考え方は、各行を独立して考慮し、「最大で選択」を尊重するその行のすべてのサブセットを列挙することです。$m/2$” ルール。サブセットごとに、その合計を計算し、すべての行の選択を組み合わせてみます。これは、すべての有効な構成を調査するため、正しいです。

 ただし、各行には$2^m$サブセットと$m = 70$、それは天文学的な大きさです。 サブセット サイズによる枝刈りでも、指数関数的な性質ではなく、定数が減少するだけです。 本当の問題は、行ごとの展開だけでなく、行の結合にもあります。1 行を処理した後、結果を合計と剰余のグローバル DP にマージする必要がありますが、完全なサブセット列挙を拡張した場合、これは実行不可能になります。 

重要な観察は、行間の唯一の相互作用は総和モジュロによるものであるということです。$k$。 行内での唯一の制約は、選択する要素の数です。 これは、各行を小さな DP 状態に圧縮できることを示唆しています。選択された要素の可能な数ごとに、$m/2$、達成可能なすべての合計を法的に追跡します$k$であり、各剰余の最適な合計のみを考慮します。 

これにより、各行が境界付きナップザック バリアントに変換され、残りの行を別の DP と結合します。 

したがって、ソリューションは 2 層の DP になります。最初に各行を処理して最適な寄与プロファイルを計算し、次に行をマージしてグローバルな剰余 DP を作成します。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルート フォース サブセット |$O(n \cdot 2^m)$|$O(2^m)$| 遅すぎる |
 | 行 DP + グローバル モジュロ DP |$O(n \cdot m^2 \cdot k)$|$O(k)$| 承認済み |

 ## アルゴリズムのチュートリアル

 ソリューションは 2 段階で構築されます。 

まず、行ごとに、最大でも選択できる場合に可能な合計を計算します。$\lfloor m/2 \rfloor$その行の要素。 正確なサブセットは気にせず、モジュロ値によって分類された達成可能な合計だけを気にします。$k$。 

行に DP 配列を使用します。`dp[c][r]`正確に選択することで達成可能な最大合計を意味します`c`和を法とするこの行の要素$k$に等しい`r`。 を除くすべての状態を不可能として初期化します。`dp[0][0] = 0`。 

行内の各要素について、この DP を逆の順序で更新します。`c`そのため、要素を何度も再利用しません。 

行を処理した後、それを単一の配列に圧縮します。`best[r]`、その行から得られる最大合計と剰余を格納します。`r`、最大でも行の半分を選択するという制約を尊重します。 

次に、行を 1 つずつグローバル DP にマージします。`global[r]`これまでに達成可能な最大合計額と残りを格納します`r`。 

各行は「オプションの袋」のように機能し、その中から 1 つの投稿を正確に選択します。`best`配列。 

手順:

 1.初期化`global`DP付き`global[0] = 0`他のすべての値は不可能です。 
2. 行ごとに、`best`要素数に対して制限されたナップザックを使用して、モジュロ値に対して配列を実行します。 
3. 行ごとに、新しい DP を作成します。`next_global`不可能に初期化されました。 
4. 前回の残りごとに`r1`そしてすべての行の残り`r2`、更新:

 新しい残り$r = (r1 + r2) \mod k$そして新しい合計は`global[r1] + best[r2]`。 
5. 交換する`global`と`next_global`。 
6. 答えは次のとおりです。`global[0]`。 

これが機能する理由は、各行が各モジュロ クラスの達成可能な最良の寄与によって完全に要約されるためです。 圧縮されると、行は独立した選択ブロックになり、グローバル DP は行選択のすべての組み合わせを正確に考慮します。 

不変条件は、最初の処理後の$i$行、`global[r]`合計が一致する行のみを使用して、達成可能な最大合計を格納します。$r \mod k$。 次の行からすべての有効な寄与を列挙し、それらを以前に有効だったすべての状態と組み合わせるため、遷移では正確さが保たれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n, m, k = map(int, input().split())
    limit = m // 2

    global_dp = [-10**18] * k
    global_dp[0] = 0

    for _ in range(n):
        row = list(map(int, input().split()))

        dp = [[-10**18] * k for _ in range(limit + 1)]
        dp[0][0] = 0

        for val in row:
            for c in range(limit - 1, -1, -1):
                for r in range(k):
                    if dp[c][r] < 0:
                        continue
                    nc = c + 1
                    nr = (r + val) % k
                    dp[nc][nr] = max(dp[nc][nr], dp[c][r] + val)

        best = [-10**18] * k
        for c in range(limit + 1):
            for r in range(k):
                best[r] = max(best[r], dp[c][r])

        new_global = [-10**18] * k
        for r1 in range(k):
            if global_dp[r1] < 0:
                continue
            for r2 in range(k):
                if best[r2] < 0:
                    continue
                nr = (r1 + r2) % k
                new_global[nr] = max(new_global[nr], global_dp[r1] + best[r2])

        global_dp = new_global

    print(global_dp[0])

if __name__ == "__main__":
    solve()
```最初の DP レイヤーは、「連続して選択する要素の数」を制限したナップザックです。 逆の反復`c`各要素が行状態ごとに最大 1 回使用されるようにします。 

2 番目の層は、列全体にわたる標準のモジュロ ナップザックです。 注意すべき点は、無効な組み合わせによって遷移が汚染されないように、不可能な状態を大きな負の数で初期化することです。 

## 実用的な例

 ### 例 1

 入力:```
1 4 3
1 2 3 4
```ここには 1 つの行があり、最大 2 つの要素を選択できます。 

行 DP を計算します。 

| c | 余り 0 | 残り 1 | 残り 2 |
 | --- | --- | --- | --- |
 | 0 | 0 | -inf | -inf |
 | 1 | -inf | 1 | 2 |
 | 2 | 4 | 5 | 6 |

 これらの状態から、残りごとの最良を求めると、次のようになります。 

best[0] = 4、best[1] = 5、best[2] = 6。 

次に、最良の剰余 0、つまり 4 を選択します。 

これは、行圧縮がどのように制約の下ですべての有効なサブセットをキャプチャし、実現可能な最良の答えを直接導き出すかを示しています。 

### 例 2

 入力:```
2 3 3
1 2 3
2 2 2
```各行では最大 1 つの選択が可能です。 

行 1 のベスト:

 何も選択しないと 0 mod 3 が与えられます

 1、2、3 を選択すると、値 1、2、3 が得られます

 行 2 が最高:

 0,2

 グローバル DP は [0, -inf, -inf] で始まります。 

行 1 の後:

 グローバル = [3, 1, 2]

 行 2 の後:

 各状態を {0,2} と組み合わせます。 

残り 0 の最終最良は 5 (3 + 2) になります

 このトレースは、行ごとの制約を維持しながら、行間のモジュロの組み合わせがどのように蓄積されるかを示します。

| スペース |$O(k)$| 現在のグローバル DP と圧縮された行ごとの DP のみを保持します。

 ## 特殊なケース

 微妙なケースの 1 つは、割り算を達成する唯一の方法が何も選択しない場合です。 たとえば、すべての数値が、どの選択によっても剰余の不一致が生じるようなものである場合でも、アルゴリズムは依然として`global_dp[0] = 0`全体を通して有効です。 すべての遷移は合計を改善する必要があるため、負の初期化状態は無効な組み合わせによって合計が上書きされるのを防ぎます。 

もう 1 つのケースは、半選択制約の下では行が何も役に立たない場合です。 その状況では、`best`配列はほとんどが負のままです`best[0] = 0`つまり、その行は実質的に何も貢献しません。 グローバル DP は変更されません。これは正しい動作です。ゼロ要素を選択することで行のスキップが常に許可されるためです。 

最後のコーナーケースは次のような場合です$k = 1$。 すべての合計は自動的に次のように割り切れます。$k$、DP は行ごとの制約の下で合計を最大化するように縮退します。 すべての剰余はゼロにマップされるため、アルゴリズムは行ごとに許可される最適なサブセットを選択し、それらを合計することに正しく組み込まれます。
