 ## 解決策
 ## 問題の理解

 各位置に小文字が含まれる文字列が与えられます。 唯一許可されている移動は、1 つの文字を選択し、現在その文字を含むすべての位置を検索し、それらすべてを巡回順序で次の文字にインクリメントします。つまり、`a → b → ... → z → a`。 その移動の価格は、移動の瞬間の文字列内の選択された文字の左端と右端の位置にのみ依存します。 

タスクは、すべての位置が同じ最終文字になるように文字列全体を変換することであり、すべての有効な一連の操作に対する総コストを可能な限り最小限に抑えたいと考えています。 

重要な詳細は、操作が文字のすべての出現に対して同時に作用するため、文字はアルファベットを進むにつれて徐々に結合する位置の「グループ」を移動するように動作するということです。 

この制約により、最大 200,000 文字の文字列が許可されるため、ステップごとに操作を繰り返しシミュレートし、毎回文字列をスキャンするソリューションは即座に除外されます。 文字列を 26 回パスするだけでも問題ありませんが、操作ごとに状態を繰り返し再構築するものは遅すぎます。 

発生が遠く離れている場合、微妙な特殊なケースが発生します。 たとえば、文字が位置 1 と n に出現する場合、その最初の操作にはすでに n − 1 のコストがかかります。操作が「ローカル」である、つまり文字ごとに独立していると仮定する単純なアプローチでは、このグローバル スパン効果を見逃してしまいます。 

もう 1 つの特殊なケースは、文字が結合する場合です。 仮定する`a`は 1 位と 100 位で発生しますが、`b`位置 50 に発生します。変換後`a → b`、新しい`b`グループは位置 1、50、および 100 にまたがっており、初期構造だけでなく履歴に応じて将来のコストが変化します。 

## アプローチ

 強引なアイデアは、プロセスをシミュレートすることです。 文字を繰り返し選択し、その出現箇所をすべて更新し、文字列のスキャンを使用してコストを再計算します。 各操作は最大 O(n) の位置に触れる可能性があり、各文字はアルファベット サイクルで多くの状態を通過する可能性があるため、最悪の場合は最大 O(26n) の操作が存在する可能性があります。 これにより、およそ O(n²) の動作が発生し、200,000 文字に対しては遅すぎます。 

重要な洞察は、視点を逆転させることです。 任意の操作シーケンスを考える代わりに、最終的なターゲット文字を修正します。 1 つおきの文字は、最終的にそのターゲットになるまでアルファベットに沿って「前方に押し出される」必要があります。 これは、選択したターゲットについて、操作のシーケンスが文字の循環順序によって効果的に決定されることを意味します。 

ここで、ターゲットに向かって巡回順序で文字を処理することを考えてみましょう。 各ステップで、1 つの文字クラスを取得し、現在そのクラスに属しているすべての位置を次のクラスにマージします。 そのステップのコストは、現在のクラスに既にマージされているすべてのポジションの最小インデックスと最大インデックスのみに依存します。 

これにより、問題は、拡大する位置セットの結合の維持とグローバル範囲の追跡に変わります。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォースシミュレーション | O(n²) | O(n) | 遅すぎる |
 | 間隔をマージしたサイクル DP | O(26n) | O(n) | 承認済み |

 ## アルゴリズムのチュートリアル

 各文字を最終ターゲットとして試し、すべてをその文字に変換するための最小コストを計算します。 

1.ターゲット文字を修正する`T`。 すべての文字が徐々に次のように変換されることをシミュレートします。`T`周期的な順序に沿って。 
2. 26 個のリストを作成します。各リストには、元の文字列内で特定の文字が現在出現している位置のインデックスが格納されます。 これらのセットが内部的に変更されることはありません。 代わりに、それらはより高い文字にマージされます。 
3. 直前の文字から始める`T`循環的な順序で、到達するまで前進します。`T`。 文字ごとに`c`、これを 1 つの操作段階として扱います。`c`に変換されます`next(c)`。 
4. 最初は空のアクティブなポジションのグローバル セットを維持します。 また、アクティブな要素間で現在の最小位置と最大位置を維持します。 
5. 手紙を処理するとき`c`のすべての位置を追加します。`c`アクティブセットに追加します。 このマージの後、それらの位置を使用してグローバル最小値と最大値を更新します。 
6. このステップのコストは次のとおりです。`max_position − min_position`、このターゲットの合計コストに追加されます。 
7. サイクル内の 26 文字すべてを処理した後、ターゲットの合計コストを取得します。`T`。 
8. 26 個の可能なターゲットすべてについて繰り返し、最小値を取得します。 

重要な考え方は、各ステージが最適なプロセスにおける 1 つの実際の操作に正確に対応し、コストはそのステージに既にマージされているすべてのポジションの範囲にのみ依存するということです。 

### なぜ効果があるのか

 固定ターゲット プロセスのどの時点でも、すべての位置はサイクルに沿った 1 つの「現在の文字クラス」にのみ属します。 先に進むと、クラスは上向きにマージされるだけで、分割されることはありません。 したがって、クラスのアクティブな位置のセットは常に、いくつかの頭文字グループの和集合になります。 そのクラスを操作するコストは、この共用体内の極値インデックスのみに依存するため、グローバルな最小値と最大値を追跡するだけで十分です。 すべての文字はターゲットごとに 1 回だけ処理されるため、有効な変換シーケンスでは、これらのマージを回避したり、コストの寄与を変更したりすることはできません。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    s = input().strip()

    pos = [[] for _ in range(26)]
    for i, ch in enumerate(s):
        pos[ord(ch) - 97].append(i)

    INF = 10**18
    ans = INF

    for target in range(26):
        active_min = INF
        active_max = -INF
        active = False
        total = 0

        # process letters in cyclic order ending at target
        for step in range(1, 27):
            c = (target - step) % 26

            if pos[c]:
                active = True
                for p in pos[c]:
                    if p < active_min:
                        active_min = p
                    if p > active_max:
                        active_max = p

            if active:
                total += active_max - active_min

        ans = min(ans, total)

    print(ans)

if __name__ == "__main__":
    solve()
```実装では各文字の位置が事前計算され、候補ターゲットごとに循環マージ プロセスがシミュレートされます。 内側のループは 26 文字を処理し、文字がアクティブ化されると、ターゲットごとに各位置が 1 回だけ考慮されます。 実行中の最小値と最大値は、各操作段階のコストを定義します。 

よくある落とし穴は、毎回すべてのアクティブな位置をスキャンして最小値と最大値を再計算することです。これにより、複雑さが O(n²) にまで増加します。 増分の最小値と最大値を維持すると、それを完全に回避できます。 

もう 1 つの微妙な点は、正しい巡回順序付けです。 ループはターゲットの直前の文字から開始して前に進む必要があります。そうしないと、マージされたセットに正しい変換シーケンスが反映されません。

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | O(26² · n) = O(n) | 26 のターゲットのそれぞれについて、26 文字をスキャンし、各位置を 1 回処理します。 
| スペース | O(n) | 文字ごとの位置リストの保存 |

 すべての演算は、アルファベットの小さな定数係数を使用して入力サイズにおいて線形であるため、解は容易に制限内に収まります。 

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    from collections import deque

    input = sys.stdin.readline
    n = int(input())
    s = input().strip()

    pos = [[] for _ in range(26)]
    for i, ch in enumerate(s):
        pos[ord(ch) - 97].append(i)

    INF = 10**18
    ans = INF

    for target in range(26):
        active_min = INF
        active_max = -INF
        active = False
        total = 0

        for step in range(1, 27):
            c = (target - step) % 26
            if pos[c]:
                active = True
                for p in pos[c]:
                    active_min = min(active_min, p)
                    active_max = max(active_max, p)

            if active:
                total += active_max - active_min

        ans = min(ans, total)

    return str(ans)

 ## 特殊なケース

 次のような単一文字列の場合`a`、アルゴリズムは意味のある間隔を初期化しません。 スプレッドを作成するマージがないため、すべてのターゲットは即座にゼロの累積コストを生成し、最小値は正確にゼロを返します。 

のような文字列の場合`az`、任意のターゲットを選択すると、一度に 1 つのポジションがアクティブになるマージ ステップは最大 1 つとなります。 最小値と最大値は全体を通して等しいままであるため、スパンコストは常にゼロであり、孤立した文字によって間隔が拡大することは決してないという直観と一致します。 

次のような高度に交互するパターンの場合`ababab`、両方の文字が特定のターゲットの下でアクティブ化されると、位置はより大きな連続範囲に徐々にマージされます。 パターンの両側が同じアクティブ クラスに入るとすぐに min と max が拡張されるため、アルゴリズムは増加するスパンを正しく累積します。
