 ## 解決策
 ## 問題の理解

 私たちには、実数値の変換力の正方形グリッドが与えられます。 1 つの操作では、単一の行または単一の列を選択し、操作の前にその行のすべてのエントリを算術平均に置き換えます。 更新された値は将来の平均にすぐに影響するため、この操作を繰り返すとグリッドが徐々に変化します。 

目標は、グリッドを均一にしたり、全体的に変化を最小限に抑えたりすることではなく、このような平均化操作を何度でも行った後に、グリッド内の任意の場所に存在する最小値を最大化することです。 

主な難点は、オペレーションがグローバルに相互作用することです。 1 つの行を変更すると、その行と交差する列に影響し、その逆も同様であるため、値は個別にではなく結合された方法でグリッド内を伝播します。 

n が 1000 までという制約は、最大 100 万セルを意味します。 一連の操作を明示的にシミュレートするアプローチは、単一の操作ですら O(n) であり、意味のあるシーケンスの数に制限がないため、実行不可能です。 したがって、問題の構造は、シミュレーションではなく、閉じた形式の特徴付けに崩壊する必要があります。 

グリッドにすでに均一な行または列がある場合、微妙なエッジ ケースが発生します。 たとえば、すべてのエントリが同一の場合、一連の操作によってその値が保持されるため、答えは自明のことながらその数値になります。 単純な解釈では、浮動小数点ドリフトをシミュレートして蓄積しようとし、精度の低下により不正確な結果が生じる可能性があります。 もう 1 つの失敗例は、行操作のみまたは列操作のみが重要であると想定している場合です。 サンプルに示すように、これらを交互に使用すると、最小値を厳密に増やすことができます。 

## アプローチ

 ブルート フォース ビューは、行と列に適用される一連の操作を想像することから始まります。 各操作ではラインがその平均値に置き換えられるため、k 回の操作の後、各セルは元の値の加重平均になります。重みは選択したラインの順序によって異なります。 すべてのシーケンスを列挙したり、収束するまでの固定数のステップをシミュレートしたりすることもできます。 

このプロセスは大まかに言えば単調であり、値は平滑化される傾向があるため、概念的には機能しますが、組み合わせ的にはすぐに破綻します。 各ステップには n 個の選択肢があり、安定するまでに多くのステップが存在する可能性があり、指数関数的または無制限の動作につながります。 

重要な観察は、最終状態が任意ではないということです。 すべての操作では、行または列がその平均に等しい均一な値で置き換えられます。つまり、行または列が選択されると、完全に均一になります。 これにより、時間の経過とともに、すべての行と列が同じグローバル平衡値に落ち着く構成にシステムが強制されます。 

これにより、問題は、グローバルに適用できる可能な限り最良の安定した値を特定することになります。 行と列の両方が平均演算子であるため、繰り返し適用すると、基本的に、すべての行の平均とすべての列の平均が同じ値に等しい固定小数点が計算されます。 平均化操作ではすべてのセルの合計が保持されるため、その固定点はグリッドのグローバル平均でなければなりません。 すべての操作はラインをその平均値で置き換えますが、そのラインの合計は変更されないため、グリッドの合計も変更されません。 

したがって、合計は不変であり、最終状態では、すべての n² セルが同じ値に等しくなければなりません。 その値は、最初の合計を n² で割ったものでなければなりません。 この構成は、サンプル構成のように行と列の操作を交互に行うことで達成できるため、最適です。

 ## アルゴリズムのチュートリアル

1. グリッド内のすべての要素の合計を計算します。 これにより、あらゆる操作の下で唯一の不変量が取得されます。 
2. すべての演算で行または列がその平均値に置き換えられ、その行または列の合計が保存されるため、グローバル合計が保存されることに注目してください。 
3. 合計は固定されているため、すべてのセルの最小値を最大化する唯一の方法は、すべてのセルを等しくすることです。不均衡があると最小値が小さくなるからです。 
4. 唯一可能な完全にバランスの取れた構成は、すべてのセルが total_sum / (n * n) に等しい構成です。 
5. この値を答えとして出力します。 

### なぜ効果があるのか

 グリッドは、線形平均変換である操作の下で進化します。 各操作ではすべてのエントリの合計が保存されるため、グローバル合計は不変です。 最終的な構成は、初期グリッドと同じ合計を持つように制約されます。 最小要素は、すべての要素が等しい場合にのみ最大化されます。これは、等しさからの逸脱により、必ずシステムの平均を下回る少なくとも 1 つの要素が導入されるためです。 したがって、最適な構成は、保存された平均に等しい値を持つ均一なグリッドです。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    total = 0
    for _ in range(n):
        row = list(map(int, input().split()))
        total += sum(row)

    ans = total / (n * n)
    print(f"{ans:.10f}")

if __name__ == "__main__":
    solve()
```このソリューションは O(n²) 時間でグリッドを読み取り、合計を累積します。 現在の合計を超える中間状態は保存されないため、メモリは一定に保たれます。 

重要な実装の詳細は、最後に浮動小数点除算を使用することです。 整数の除算は精度を失い、早すぎる丸めは必要な誤差許容度を満たさない可能性があります。 十分な小数精度で印刷すると、相対誤差限界が確実に満たされます。

 ## 特殊なケース

 n = 1 の場合、グリッドには単一のセルが含まれます。 その唯一の行または列に対する演算は、その行または列をその独自の平均値 (同じ値) に置き換えます。 アルゴリズムは total_sum / 1 を計算するため、出力は入力と正確に一致します。 

すべてのエントリが 5 であるような均一なグリッドの場合、すべての操作で均一性が維持されます。 計算された合計は 5 * n² で、n² で割ると 5 になります。これは、定数シーケンスを平均しても変化しないという不変条件と一致します。 

1 つの大きな値が小さな値に囲まれているなど、非常に偏ったグリッドの場合、平均化を繰り返すと質量が均一に広がります。 たとえば、他の場所に値 100 と 0 がある 2x2 グリッドでは、合計は 100 に保たれ、最終的な均一値は 25 になります。一連の行または列の平均化は、この同じ制約に収束し、不変式が答えを完全に決定することが確認されます。
