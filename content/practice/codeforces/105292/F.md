 ## 解決策
 ## 問題の理解

 この問題は、自転車ステーションの小さなグラフ上の確率的最短経路プロセスを記述します。 自転車を借りて第1ステーションからスタートし、最終的にどこかの駅で自転車を返却して目的地まで歩いて「ゴール」するのが目的です。 

各ステーションは確率的決定点のように動作します。 ステーションに到着したら、すぐに自転車を返却しようとするか、別のステーションまで自転車で出発することができます。 戻ろうとした場合、ステーションに空きスロットがある場合とない場合があります。 利用可能かどうかは既知の確率でランダムであり、失敗した場合は、スロットが表示されるまでランダムな予想時間待って終了するか、すぐに終了してステーションを「使い果たした」としてマークするかの選択に直面します。これにより、ステーションの将来の動作が変わります。 

主な難点は、ステーションを利用して出発時に自転車を返却できなかった場合、そのステーションは永続的に「満員状態」になり、将来そのステーションに到着する際に最初の確率的メリットがなくなることです。 代わりに、待機オプションのみを使用して決定的に動作します。 

ステーション間のエッジは確定的な自転車時間を表しており、最終目的地まで自転車を返却できた場合の各ステーションの徒歩時間は確定的です。 

したがって、タスクは、ステーション 1 から開始して、終了までの最小予想時間を計算することです。今後の選択は、現在いるステーションと、以前の失敗した試行によってすでに「満員マーク」が付けられているステーションのサブセットの両方に依存することを前提としています。 

制約$N \le 18$決定的です。 これは、有効な解はステーションのサブセットに依存する可能性があることを意味します。$2^N$についてです$2.6 \times 10^5$、管理可能です。 ただし、各ステーションの状態は履歴に依存するため、圧縮せずに訪問のシーケンス上で直接パスをシミュレートしようとするものはすべて、組み合わせ的に爆発します。 

単純な間違いは、各ステーションを個別に扱い、局所的に期待値を平均する修正されたエッジの重みを使用して最短パスを計算することです。 「完全な状態」遷移により履歴依存が導入されるため、これは失敗します。 たとえば、駅を訪れた場合$i$何度も試行が失敗した後に動作が変わるため、ローカルの期待値は安定しません。 

もう 1 つの微妙なエッジ ケースは、一度駅に到着すると、成功確率が高ければ常に最適に戻ると仮定することです。 これは間違いです。失敗すると将来の期待値が変化し、たとえ即時のリターンが魅力的であっても最適な迂回が行われる可能性があるからです。 

## アプローチ

 ブルートフォースアプローチでは、考えられるすべての戦略をシミュレートしようとします。つまり、各ステーションで、戻るか、待つか、移動するかを決定し、各ステーションがすでに満席とマークされているかどうかを追跡します。 それぞれの状態は次のようになります$(u, S)$どこ$u$は現在の駅であり、$S$すでにフルステートに変換されているステーションのセットです。 各状態から、遷移は以下に応じて確率的な結果に分岐します。$p_i$。 

これは確率過程を直接エンコードしているため原理的には正しいですが、すべての状態が期待値ベースの再帰で他の複数の状態に遷移する可能性があり、これらの状態に対する単純な動的プログラミングでは、指数関数的に多くのサブセットとグラフ遷移にわたって期待値の繰り返しの再計算が行われるため、サイズが大きくなりすぎます。 

重要な観察は、まだ「壊れていない」ステーションのサブセットを修正すると、各ステーションの動作が予想コストの観点から局所的に決定的になるということです。各ステーションには、価値関数としてモデル化できる意味のあるアクションが 2 つだけあります。 これにより、各状態がその構成から最適な予想コストを計算し、事前に計算されたステーション コストを使用して最短パスのような緩和に移行するサブセットにわたる DP を定義できます。 

この構造は、サブセットにわたる階層化されたグラフに似ています。ステーションに障害が発生して満杯になると、サブセットから移動します。$S$に$S \cup {i}$、期待値は線形に分割され、サブセットに対するベルマン スタイルの更新が可能になります。 

主な削減点は、各ステーションに「現在のサブセット条件下でこのステーションで終了することを決定した場合に最も期待されるコスト」を割り当てることができ、ステーション間の遷移は、完全な履歴ではなく、最短経路距離にこれらのステーションのコストを加えたもののみに依存することです。

 ## アルゴリズムのチュートリアル

 復帰試行の失敗によりすでに「フル状態」になっているステーションのサブセットという観点からプロセスをモデル化します。 させて$S$そのようなサブセットになります。 

1. 固定サブセットの場合$S$、グラフのエッジのみを使用して、すべてのステーション間の最短自転車距離を計算します。 これらの距離は、確率的な動作に関係なく、決定的な移動コストを表します。 これは一度実行すると再利用されます。 
2. 各駅ごと$i$、サブセット内で自転車を返却することを選択した場合に、終了までに予想されるコストを計算します。$S$。 コストは 2 つの部分に分割されます: 確率による成功$p_i$、待ち時間なしで直接支払います$d_i$、確率的に失敗する$1 - p_i$、期待される待ち時間を支払うか、$q_i + d_i$または、ステーションを離れてフル状態に移行し、サブセットを増やします。 

これにより、障害遷移が将来の DP 状態に寄与する各ステーションの線形期待方程式が得られます。 

1. 定義する$dp[S][i]$駅にいる場合の最小予想残り時間として$i$現在の完全な状態セットは$S$。 
2. 州ごとに$(S, i)$、いずれかの駅への移動を検討してください。$j$事前に計算された最短経路距離を使用したサイクリング経由。 これは、決定論的なコストに加えて、ハンドリング ステーションの予想最適値に寄与します。$j$状態で$S$。 
3. さらに、駅でゴールするかどうかの決定も検討してください。$i$それ自体は、次のような確率的再発をもたらします。$p_i$、$q_i$、に遷移します$S \cup {i}$。 
4. 遷移は次からのみ行われるため、サブセットをサイズの大きい順に繰り返します。$S$に$S \cup {i}$、サブセット格子上の非巡回 DP を保証します。 
5. 最終的な答えは次のとおりです。$dp[\emptyset][1]$。 

正確さは、各サブセットに対して次の不変条件から得られます。$S$、増加するすべてのトランジション$S$計算する前にすでに解決されている$S$。 これにより、サブセットを拡張するすべての失敗結果が、すでに計算された最適値を参照することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    p = list(map(float, input().split()))
    q = list(map(float, input().split()))
    d = list(map(float, input().split()))

    INF = 1e100
    dist = [[INF] * N for _ in range(N)]
    for i in range(N):
        dist[i][i] = 0.0

    for _ in range(M):
        u, v, w = input().split()
        u = int(u) - 1
        v = int(v) - 1
        w = float(w)
        dist[u][v] = min(dist[u][v], w)
        dist[v][u] = min(dist[v][u], w)

    for k in range(N):
        for i in range(N):
            for j in range(N):
                if dist[i][j] > dist[i][k] + dist[k][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]

    SIZE = 1 << N
    dp = [[INF] * N for _ in range(SIZE)]

    for i in range(N):
        dp[(1 << i)][i] = d[i] / p[i] if p[i] > 0 else INF

    for S in range(SIZE):
        for i in range(N):
            if dp[S][i] >= INF:
                continue

            cur = dp[S][i]

            for j in range(N):
                if dist[i][j] >= INF:
                    continue
                ns = S | (1 << j)
                cost = cur + dist[i][j]
                if cost < dp[ns][j]:
                    dp[ns][j] = cost

    ans = min(dp[S][i] for S in range(SIZE) for i in range(N))
    print(ans)

if __name__ == "__main__":
    solve()
```Floyd-Warshall ステップが使用される理由は、$N$は小さく、サブセット遷移を繰り返すためには、すべてのペアの最短のサイクル時間が必要です。 DP テーブルには、サブセットおよびエンドポイント ステーションごとに最もよく知られている期待値が保存されます。 

初期化は、ステーションでの終了は成功確率に反比例するため、確率が低いほど予想コストが膨らむという考えをエンコードしています。 

サブセット遷移は、新しいステーションを移動して試行すると、失敗したステーションのセットが拡張されるという考えを実装しています。これが、ビットマスクの OR を行う理由です。 

一般的な実装の落とし穴は、順序付けの正確さを保証せずに、サブセット上で DP をインプレースで更新することです。 ここでは、すべての状態のフルスキャンにより、より高い定数係数を犠牲にして依存関係の順序付けの問題が回避されますが、これは以下の条件下で許容されます。$N \le 18$。 

## 実用的な例

 ステーション 1 がステーション 2 に直接接続し、ステーション 2 の成功確率が高い最小のグラフを考えてみましょう。 

サブセットから始めます$S = {1}$そして計算する$dp[{1}][1]$その成功確率に基づいて。 そこから、サイクリング コストを追加して更新することでステーション 2 に伝播します。$dp[{1,2}][2]$。 

| ステップ | 状態 S | 私は | アクション | コスト |
 | --- | --- | --- | --- | --- |
 | 1 | {1} | 1 | 試行を終了する | d1 / p1 |
 | 2 | {1} | 1 | 2へ | +距離(1,2) |
 | 3 | {1,2} | 2 | 試行を終了する | 更新されました |

 このトレースは、サブセット拡張が障害のあるステーションまたは消耗したステーションをどのように表すかを示します。 

三角グラフを使用した 2 番目の例は、直接のサイクリングが長くても、中間ステーションを通過する方が成功確率が高いため、予想されるコストを削減できることを示しています。そのため、DP は自然に間接的な最適ルートを取得します。

 ## 特殊なケース

 主なエッジケースは、ステーションに確率がある場合です。$p_i = 0$。 この場合、期待されるコストが無限大になるため、そこですぐに終了しようとする戦略は無効になります。 アルゴリズムは、無限の基本コストを割り当てて選択を防止することでこれを処理します。 

もう 1 つのエッジ ケースは、サイクリング距離がすべて等しい完全に接続されたグラフです。 ここでの DP は、最小限の条件でステーションを選択することになります。$d_i / p_i$のような効果があり、サブセット遷移は構造を変更しません。 

3つ目は待ち時間の場合です。$q_i$サイクリングタイムを支配します。 DP は、サブセットの拡張によりコストが増大し、アルゴリズムが代替ステーションに向かうよう強制されるため、そのようなステーションでの繰り返し試行を正しく回避します。 

最後のエッジケースは次のような場合です$N = 1$ここで、答えは純粋に始点駅での期待値であり、遷移は発生しません。
