 ## 解決策
 ## 問題の理解

 小文字で構成される文字列が与えられ、そのタスクは、それを非常に具体的な方法で連続する部分に繰り返し分割することです。 各分割により、プレフィックス セグメントと残りのサフィックスが作成されます。 このルールでは、選択されたすべてのプレフィックス セグメントは、その後に残るものよりも「優れている」必要があると規定されています。 

ここでの「より良い」は 2 つの条件を使用して定義されます。 まず、プレフィックスは、プレフィックスの意味で残りのサフィックスと同一であってはなりません。つまり、それがサフィックスの開始部分であってはなりません。 次に、接頭辞は辞書編集的に接尾辞よりも小さくなければなりません。 

分割を明示的に構築するように求められることはありません。 代わりに、すべての分割がこの条件を満たす場合に可能なセグメントの最大数を決定するだけで済みます。 

入力は複数の独立した文字列で構成されており、文字列ごとにこの最大値を計算します。 すべての文字列の合計の長さは長いため、どのソリューションでも各文字を一定の回数処理する必要があります。 

素朴な解釈では、考えられるすべてのカット位置のシーケンスを試し、各分割の状態を検証することを示唆しています。 そのためには、部分文字列の比較を繰り返す必要があります。 2 つの部分文字列間の各比較には、最悪の場合直線的な時間がかかる可能性があり、可能な分割数は文字列の長さに応じて指数関数的に増加します。 単一の文字列の長さが 200,000 であっても、このアプローチは完全に実行不可能になります。 

文字列に繰り返し文字が多数含まれる場合、特に長い均一ブロックがある場合、微妙なエッジ ケースが発生します。 たとえば、「aaaaaa」のような文字列では、接頭辞は接尾辞の接頭辞でもあるため、多くの分割では「接頭辞ではない」条件はすぐに失敗し、応答は非常に小さな値に折りたたまれます。 一方、「ababab」のような文字列を交互に使用すると、辞書編集的に小さい接頭辞が得られる機会が最大化され、不用意に欲張りな選択をすると、接頭辞の等価性が適切にチェックされていない場合に有効な分割の数が過大評価される可能性があります。 

主な難点は、この条件がプレフィックス セグメントと、カットに応じて変化するサフィックスを比較することです。 したがって、それぞれの決定は将来のすべての比較に影響を及ぼします。つまり、ローカルでの貪欲な選択は明らかに安全ではありません。 

## アプローチ

 この強引なアイデアは、考えられるすべてのカット位置をシミュレートし、各セグメントの状態を検証することです。 特定のカットについて、2 つの部分文字列を抽出し、一方が他方のプレフィックスであるかどうか、および辞書編集的に小さいかどうかを確認します。 それぞれのチェックは、$O(n)$最悪の場合は部分文字列の比較が原因で、$O(n)$カット、につながる$O(n^2)$構成ごとに。 構成の数は指数関数的に増加するため、このアプローチは実現可能な限界をはるかに超えています。 

重要な点は、この条件が現在の接頭辞が残りの接尾辞より辞書編集的に小さいかどうか、および接尾辞の次の文字が接頭辞の等価性を破るかどうかだけによって決まるということです。 部分文字列の比較を再計算する代わりに、現在のセグメント境界と残りのサフィックスの間の動的な関係を維持できます。 

重要な構造上の洞察は、カットを修正すると、接尾辞は常に元の文字列の接尾辞となり、接頭辞と接尾辞の辞書編集的な比較は、元の文字列内の位置の比較に縮小できるということです。 つまり、明示的に部分文字列を作成する必要はなく、開始インデックスを比較し、接頭辞が接尾辞と完全な長さで一致するかどうかを追跡するだけです。 

これにより、文字列をスキャンし、サフィックスがプレフィックスより厳密に大きくなる最初の位置に基づいてカット ポイントを貪欲に決定するという問題が軽減されます。 有効な各カットはプレフィックスを消費し、ポインタを前方に移動して、線形時間処理を保証します。

 ## アルゴリズムのチュートリアル

 1. 文字列の先頭にポインタを置き、セグメントのカウンタをゼロに初期化します。 ポインタは、検討している現在のサフィックスの開始を表します。 
2. 現在の位置について、選択したプレフィックスが残りのサフィックスより辞書編集上小さいという条件を維持しながら、セグメントを右に拡張しようとします。 文字列を明示的に抽出する代わりに、対応する位置で文字を直接比較します。 
3. 拡張中に、プレフィックスが現在の長さまでサフィックスと同一であるかどうかを追跡します。 同一の場合、「プレフィックスではない」条件に違反していることを意味するため、セグメントをここで終了することはできません。 
4. 接頭辞が接尾辞よりも厳密に小さくなる位置を見つけるとすぐに、両方の条件が満たされるため、ここで安全にカットできます。つまり、接頭辞ではなく、辞書編集的に小さいということです。 
5. このカットを記録し、セグメント数を増やして、ポインタをカットの後の次の位置に移動します。 
6. ポインタが文字列の末尾に到達するまで、このプロセスを繰り返します。 最終的な数は、有効なセグメントの最大数です。 

正確さは、各ステップで常に可能な限り早い有効なカットを選択するという不変条件に依存します。 後でカットしても、将来の有効な分割の数は増加せず、サフィックスの残りの柔軟性が低下するだけです。 

### なぜ効果があるのか

 どの位置でも、セグメントの数を最大化する唯一の方法は、現在のセグメントが有効になったらすぐに終了することです。これは、カットを遅らせても、残りのサフィックスが縮小するだけであり、まだ存在していなかった追加の機会を生み出すことができないためです。 辞書編集条件はプレフィックス ウィンドウの短縮に関して単調であるため、有効なカットが見つかると、それを超えて拡張しても将来の実現可能性は向上しません。 これにより、貪欲戦略が最大セグメント数を達成することが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve(s):
    n = len(s)
    i = 0
    ans = 0

    while i < n:
        j = i + 1
        while j < n and s[i] == s[j]:
            j += 1

        if j == n:
            ans += 1
            break

        k = j
        while k < n and s[k] == s[i]:
            k += 1

        ans += 1
        i = j

    return ans

t = int(input())
for _ in range(t):
    s = input().strip()
    print(solve(s))
```この実装は、各セグメントの開始から順方向にスキャンし、文字がセグメントの開始文字と異なる最初の位置を見つけることに依存しています。 最初の異なる文字によって順序が決定されるため、問題で必要とされる辞書編集上の不等式を保証するにはこれで十分です。 

内側のループは同一の文字のブロックをスキップするため、実行時間が長い文字列での二次的な動作が防止されます。 ポインタ`i`は常に前方にジャンプするため、各文字は最大 1 回処理されます。 

微妙な詳細は、残りのサフィックス全体が現在のプレフィックス文字と同一である場合の処理​​です。 この場合、有効な辞書編集上の区切りが存在しないため、セグメントは文字列の残りの部分を消費する必要があります。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    def solve(s):
        n = len(s)
        i = 0
        ans = 0
        while i < n:
            j = i + 1
            while j < n and s[i] == s[j]:
                j += 1
            if j == n:
                ans += 1
                break
            ans += 1
            i = j
        return ans

    t = int(input())
    out = []
    for _ in range(t):
        out.append(str(solve(input().strip())))
    return "\n".join(out)

 ## 特殊なケース

 のような文字列の場合`aaaaa`、アルゴリズムは、サフィックスがプレフィックスと異なる点を見つけようと繰り返し試みます。 そのようなポイントは存在しないため、内部スキャンはすぐに終了に達し、単一のセグメントを返します。 これより前のカットはプレフィックス条件に違反するため、これは制約を直接満たします。 

のような文字列の場合`ab`、スキャンはインデックス 0 から始まります。サフィックスの最初の文字はインデックス 1 ですぐに異なるため、2 つの文字の間でカットが行われます。 ポインタは最後まで進み、最適な構造に一致する 2 つのセグメントを生成します。 

のような文字列の場合`abcabc`、各キャラクターはほぼ即座に新しい不一致を導入します。 スキャンでは、可能な限り早い位置で有効なブレークポイントが繰り返し検出され、プレフィックス制約に違反することなく最大限のセグメンテーションが生成されます。
