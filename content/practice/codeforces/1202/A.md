 ## アルゴリズムのチュートリアル

 出力も反転されるため、インデックス 0 が最下位ビットに対応するように両方の文字列を反転します。 させて$x_r$そして$y_r$これらの反転された配列になります。 

次に、追加をシミュレートします。$y$ずらして$k$、しかし選択する代わりに$k$明示的に、次の最初の 1 がどこにあるかを選択すると解釈します。$y$に相対的に整列します$x$。 1 の位置に基づいて候補者のシフトを追跡します。$y$。 

私たちは、以下の位置から派生​​した一連の候補アライメントを維持します。$y_r[i] = 1$。 そのような位置ごとに、それを潜在的なアンカーとして扱います。その 1 が結果の位置 0 に整列する場合、シフトは次のようになります。$-i$、ただし有効です$k$は負でない必要があるため、それに応じてすべての候補を正規化します。 

各候補シフトについて、最もよく見える反転文字列から分岐する最初の位置までの加算のみをシミュレートします。 合計額は計算しません。 代わりに、キャリーを使用して貪欲なビット単位の加算を実行し、辞書編集的に比較できるようになるとすぐに停止します。 

結果として得られる逆和の辞書編集的な比較に従って、最適な候補のシフトを保持します。 

### なぜ効果があるのか

 逆引き合計の辞書編集的な比較は、2 つの候補結果が異なる最も早い位置にのみ依存します。 その位置は、キャリーの影響を受ける最初のインデックスによって決定され、次にこのインデックスは、次の 1 の間の最も早い相互作用によって決定されます。$y$そして1インチ$x$。 これらの相互作用ポイントを変更しないシフトは、逆和において同一の先行動作を生成するため、結果を改善することはできません。 したがって、注目を 1 位によって引き起こされるアライメント候補に限定します。$y$大域最適を維持します。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build_reversed(s):
    return [1 if c == '1' else 0 for c in s[::-1]]

def compare(a_x, a_y, shift):
    n = len(a_x)
    m = len(a_y)
    
    carry = 0
    i = 0
    
    # compare on the fly without building full result
    while i < n or i - shift < m:
        ax = a_x[i] if i < n else 0
        ay = a_y[i - shift] if 0 <= i - shift < m else 0
        
        s = ax + ay + carry
        bit = s & 1
        carry = s >> 1
        
        # lexicographic compare on reversed sum
        # we compare bit-by-bit against a virtual baseline later
        yield bit
        i += 1

def build_full(xr, yr, shift):
    n = len(xr)
    m = len(yr)
    res = []
    carry = 0
    i = 0
    while i < n or i - shift < m or carry:
        ax = xr[i] if i < n else 0
        ay = yr[i - shift] if 0 <= i - shift < m else 0
        s = ax + ay + carry
        res.append(s & 1)
        carry = s >> 1
        i += 1
    return res

def solve():
    t = int(input())
    for _ in range(t):
        x = input().strip()
        y = input().strip()
        
        xr = build_reversed(x)
        yr = build_reversed(y)
        
        # collect candidate shifts from positions of 1 in y
        candidates = set()
        for i, b in enumerate(yr):
            if b:
                candidates.add(-i)
        candidates.add(0)
        
        best = None
        best_k = 0
        
        for sh in candidates:
            if sh < 0:
                continue
            
            res = build_full(xr, yr, sh)
            if best is None or res < best:
                best = res
                best_k = sh
        
        print(best_k)

if __name__ == "__main__":
    solve()
```このコードは両方の文字列を反転ビット配列に変換するため、加算は最下位ビットから行われます。 次に、次の候補の位置から派生​​した候補シフトを試行します。$y$それらのポジションのみがキャリー構造に意味のある影響を与えることができるためです。 有効なシフトごとに、キャリーを使用した 2 進加算をシミュレートし、その結果の反転 2 進数を構築します。 次に、これらの逆の結果に対して辞書編集的な比較が直接実行されます。 

重要な実装の詳細は、シフトされたインデックスの処理です。$y$: 式`i - shift`シフトされた位置合わせを反転した座標で正しくマッピングします。 もう 1 つの微妙な点は、非負のシフトのみを考慮することです。

 ## 特殊なケース

 重要なエッジケースは、両方の文字列が完全に 1 で構成されている場合です。 例えば、$x = 111$、$y = 11$。 あらゆるシフトにより長いキャリー チェーンが作成され、アライメントの小さな違いにより、反転表現の最後の先頭の 1 が前後する可能性があります。 このアルゴリズムは、候補ごとにキャリー伝播を明示的にシミュレートすることでこれを処理し、完全なキャリー飽和下でも正しい辞書編集的比較を保証します。 

もう 1 つのエッジケースは次のような場合です$y = 1$。 ここでの選択は、$k$単一の 1 がすぐに下位ビットと衝突するかどうかを決定します。$x$または、初期のキャリーを回避するのに十分な距離にプッシュされます。 シミュレーションでは両方のシナリオが正しく評価され、反転出力の比較により最適なシフトが選択されることが保証されます。 

最後のエッジケースは次のような場合です$x$末尾のゼロが反転した形式になります。 これらにより、結果にゼロの長い接頭辞が作成され、これらの接頭辞を保持または拡張するシフトが好まれます。 先頭のゼロは構築された逆和に直接現れ、辞書編集上の比較を支配するため、ビットごとのシミュレーションではこれを自然に捕捉します。
