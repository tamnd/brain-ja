 ## 問題の理解

 1 つの長い参照文字列が与えられます`t`そして文字列のコレクション`s1 … sn`。 順序付けされた文字列のペアごとに`(si, sj)`それらを連結して新しい文字列を形成し、この連結された文字列が内部の連続した部分文字列として出現する回数を数えます。`t`。 最終的な答えは、すべての順序付きペアにわたるこれらのカウントの合計です。 

したがって、タスクは単に各文字列の出現を数えるだけではなく、リスト内の 1 つの文字列からの接頭辞と別の文字列からの接尾辞へのパターンの考えられるすべての分割の出現を数えることです。 

すべての全長の長さという制約は、`si`最大でも 2 · 10^5 が重要な構造上のヒントです。 これは、最大 2 · 10^5 の文字列が存在する一方で、平均の長さは短く、すべての文字を一定の回数だけ処理するソリューションが実行可能であることを意味します。 除外されるのは、文字列のすべてのペアをすべての位置に対して明示的にチェックしようとするものです。`t`なぜなら、最悪の場合、それは 10^10 回の演算に相当するからです。 

素朴なアプローチは、すべてのペアを反復処理することです。`(i, j)`、連結された文字列を構築し、それをスキャンします。`t`KMP のような文字列一致アルゴリズムを使用します。 たとえ KMP が線形であっても、これはすべての連結の長さの合計に n を乗じたものに比例し、限界をはるかに超えています。 

それぞれの発生を事前計算しようとすると、より微妙な失敗ケースが発生します。`si`そして結果を個別に組み合わせます。 これは機能しません。`si + sj`間の境界を越える重なりに依存する`si`そして`sj`。 たとえば、次の場合`si = "ab"`そして`sj = "ba"`、連結`"abba"`の位置に現れる可能性があります`"ab"`位置 k で終了し、`"ba"`k+1 から始まり、独立したカウントでは捕捉されません。 

核心的な問題は、有効なすべての発生が、`si + sj`で`t`内部の分割点に対応します`t`ここで接尾辞は`si`その位置で終わる一致と接頭辞`sj`直後に試合開始。 

## アプローチ

 ブルートフォースメソッドはすべてのペアを列挙します`(i, j)`各連結について、それが何回発生したかを確認します。`t`。 これは定義に直接従うため、正しいです。 ただし、ペアの数は n² であり、各連結を`t`が線形である場合、総コストは最悪の場合 O(n² · |t|) になりますが、これは 2 · 10^5 文字列では実行不可能です。 

重要な点は、実際には連結された文字列を構築する必要がないということです。 分割パターンの出現が内部でどのように動作するかを理解することだけが必要です`t`。 連結された文字列があるとします`x + y`で発生します`t`。 その出来事の境界には、`x`終了し、`y`が始まります。 したがって、すべての出現が分割位置に寄与します。`t`接尾辞と一致する接頭辞を持つ`x`および接頭辞に一致する接尾辞`y`。 

これにより、問題は、次のすべての位置の周囲に位置合わせされた部分文字列のペアを数えるという問題に変換されます。`t`。 文字列ペアを反復する代わりに、次の位置を反復します。`t`そして、各位置が分割境界として機能する方法が何通りあるかを数えます。 

これを効率的に行うために、すべての文字列から構築されたトライを使用しますが、接尾辞の一致をサポートするために反転された文字列を処理する必要もあります。 全て保管しております`si`フォワードトライでもリバーストライでも。 次に、各位置に対して前処理を行います。`t`、考えられる接頭辞ごとにそこで終わる文字列の数、および考えられる接尾辞ごとにそこから始まる文字列の数。 プレフィックス状態とサフィックス状態の間の相互作用は、トライ ノード上の頻度カウントを使用して集計されます。 

より効率的な見方は、各文字列がその接頭辞と接尾辞に寄与しており、ある文字列の接尾辞が別の文字列の接頭辞とどのくらいの頻度で一致するかを、分割位置ごとに数えることです。`t`。

 ## アルゴリズムのチュートリアル

 この問題を、考えられるすべての分割位置での寄与を数えることに還元します。`t`。 目的は、ある位置で終わる特定の一致した接尾辞で終了できる文字列の数と、次の位置から始まる特定の一致した接頭辞で始まる文字列の数を事前に計算することです。 

1.すべての文字列を反転します`si`そしてそれらをトライに挿入します。 各ノードは、そのノードで終了する文字列の数を格納します。 これにより、サフィックスの一致をクエリできるようになります。`t`歩いて`t`後ろ向きに。 
2. 元の文字列を使用して 2 番目のトライを構築し、終了カウントも保存します。 このトライにより、文字列の接頭辞を次の位置と照合することができます。`t`。 
3. ポジションごとに`p`で`t`、から後方に歩いて到達可能なすべてのトライ状態を計算します。`p`逆トライで。 到達可能な各ノードは、いくつかの接尾辞を表します。`si`で終わる`p`。 
4. 同様に、位置についても`p+1`、前方に歩き、そこから始まるすべてのプレフィックス一致を収集しようとします。 
5. スプリットポジションごとに`p`、サフィックス側のカウントとプレフィックス側のカウントを組み合わせます。`a`文字列とプレフィックス状態が対応する`b`文字列の場合、この分割が寄与します`a * b`連結。 
6. すべてのスプリットポジションにわたる貢献を合計します。`t`。 

重要な点は、複数の文字列がプレフィックスまたはサフィックスを共有する可能性があり、トライ ノードがこれらの多重度を集約するため、個々の文字列を明示的に二重にカウントしないことです。 

### なぜ効果があるのか

 あらゆる出来事が起こる`si + sj`で`t`2 つの部分の間に独自の分割位置があります。 その位置では、一致の左側の部分は接尾辞に正確に対応します。`si`、右側の部分は接頭辞に正確に対応します。`sj`。 トライ表現により、そのようなすべての有効な分割がノード周波数集約を通じて正確に 1 回カウントされることが保証されます。 すべての文字列はトライ パスを通じて列挙されるため、有効なすべての文字列が`(i, j)`トライパスは実際の辞書文字列のみを表すため、無効な連結は導入されません。

input = sys.stdin.readline

class Node:
    __slots__ = ("next", "cnt")
    def __init__(self):
        self.next = {}
        self.cnt = 0

def add(root, s):
    v = root
    for c in s:
        if c not in v.next:
            v.next[c] = Node()
        v = v.next[c]
    v.cnt += 1

def collect_forward(root, s):
    v = root
    res = []
    for c in s:
        if c not in v.next:
            break
        v = v.next[c]
        if v.cnt:
            res.append(v.cnt)
    return res

def collect_backward(root, s):
    v = root
    res = []
    for c in reversed(s):
        if c not in v.next:
            break
        v = v.next[c]
        if v.cnt:
            res.append(v.cnt)
    return res

t = input().strip()
n = int(input())
s = [input().strip() for _ in range(n)]

trie_r = Node()

for w in s:
    add(trie_f, w)
    add(trie_r, w[::-1])

# prefix counts for all strings
prefix_counts = {}
suffix_counts = {}

for w in s:
    v = trie_f
    for c in w:
        v = v.next[c]
        prefix_counts[w] = prefix_counts.get(w, 0)  # placeholder

ans = 0

# For each split in t, we need to aggregate contributions
# We simulate by checking all starting positions and matching forward/backward

# Precompute forward transitions from t
forward_nodes = [None] * (len(t) + 1)
forward_nodes[0] = trie_f
for i in range(len(t)):
    if forward_nodes[i] and t[i] in forward_nodes[i].next:
        forward_nodes[i + 1] = forward_nodes[i].next[t[i]]
    else:
        forward_nodes[i + 1] = None

backward_nodes = [None] * (len(t) + 1)
backward_nodes[len(t)] = trie_r
for i in range(len(t) - 1, -1, -1):
    if backward_nodes[i + 1] and t[i] in backward_nodes[i + 1].next:
        backward_nodes[i] = backward_nodes[i + 1].next[t[i]]
    else:
        backward_nodes[i] = None

for i in range(len(t) + 1):
    left = 0
    right = 0

    # suffix ending at i
    v = trie_r

        v = v.next[t[j]]

 ## 特殊なケース

 重要なエッジ ケースは、多くの文字列が同じプレフィックスまたはサフィックスを共有する場合に発生します。 その場合、複数のトライ パスが収束するため、アルゴリズムは各走査ステップではなく終端ノードでカウントを集計する必要があります。 これにより、同一の文字列が多重度に正しく寄与することが保証されます。 

もう 1 つのエッジ ケースは、文字列が接頭辞と接尾辞の両方である場合です。`t`しかし、異なる位置に表示されます。 分割ベースのカウントでは、各分割位置が`t`別加工で位置ずれによる干渉を防ぎます。
