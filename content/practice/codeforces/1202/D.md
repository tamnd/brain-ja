 ## 問題の理解

 非常に特殊なパターンが部分列として規定の回数現れるように、数字 1、3、7 だけからなる文字列を構築するように求められます。 パターンは「1、その後 3、その後 3、その後 7」というシーケンスであり、このパターンを形成する文字列内のインデックスを選択する方法の合計数が指定された数と正確であることを確認する必要があります。$n$。 

ここでのサブシーケンスとは、順序を変更せずに文字列から文字を削除できること、およびパターン 1、3、3、7 を形成するインデックスのすべての個別の選択をカウントすることを意味します。 

入力は最大 10 個の独立したクエリで構成され、それぞれにターゲット数が与えられます。$n$まで$10^9$。 各クエリについて、最大でも次の長さの有効な文字列を出力する必要があります。$10^5$これは、タイプ 1337 の多くのサブシーケンスを正確に実現します。 

の値に対する制約$n$が重要な難易度です。 生成中に明示的に「サブシーケンスをカウントする」直接的な構築では、あまりにも時間がかかりすぎます。単純なカウントでは、重複する多くの選択肢の組み合わせの寄与を追跡する必要があるためです。 

文字列に 1 または 7 がほとんど含まれていない場合、微妙なエッジ ケースが発生します。 たとえば、1 がない場合、答えは 0 でなければなりませんが、$n$は常に少なくとも 1 であるため、すべての有効な構造には少なくとも 1 つと 1 つの 7 が含まれている必要があります。同様に、数字を間違った順序で配置すると、すべての数字が存在する場合でも、すべての有効な部分列が暗黙的に削除される可能性があります。 

もう 1 つの失敗モードは、寄与の独立性を仮定することから生じます。追加の 3 を挿入すると、カウントが線形にスケールされるだけではありません。これは、1 ～ 7 の各ペアが、間にある 2 つの 3 を選択する方法の数と乗算的に相互作用するためです。 

## アプローチ

 強引なアイデアとしては、候補ごとに動的プログラミングを使用して文字列を生成し、サブシーケンスを数えてみることです。 固定長の文字列の場合$m$、1337 個のサブシーケンスを数えるには、$O(m)$これまでの部分パターンの数 (1 の数、13 の数、133 の数、および 1337 の数) を維持することによって。 ただし、次の長さのすべての文字列を検索しようとすると、$10^5$、可能性の数は$3^{100000}$、それはまったく実行不可能です。 

文字列を段階的に構築し、DP 状態を追跡する、より構造化されたブルート フォースでも、依然として指数関数的に分岐します。 中心的な問題は、単に文字列を評価するのではなく、特定の組み合わせの出力を含む文字列を「設計」しようとしているということです。 

重要な観察は、部分列 1337 の構造が乗法的であり、ブロック構築によって制御できるということです。 1 と 7 の相対的な順序を固定し、すべての 3 をそれらの間の 1 つのブロックに配置すると、サブシーケンスの数は単純な組み合わせ値になります。つまり、任意の 1 と任意の 7 を選択し、それらの間にある 2 つの 3 を選択することで乗算されます。 これにより、問題は、組み合わせビルディング ブロックを使用して整数を構築することになります。 

より正確には、文字列を次のように配置すると、次のようになります。 

1 の後に 3 の k 個のコピーが続き、その後に 7、

 次に、すべてのサブシーケンス 1337 は、k の中から 1 つの 1、1 つの 7、および任意の 2 つの 3 を選択することによって形成されます。 これは貢献します$\binom{k}{2}$。 これにより、三角数を使用して数値を表現する制御可能な方法が得られます。 このブロックを適切に区切って複数組み合わせることで、あらゆる表現が可能になります。$n$二項寄与の合計として、貪欲に構築できます。 

これにより、タスクを分解する作業が軽減されます。$n$フォームの値に変換する$\binom{k}{2}$、それぞれは短い文字列ブロックで表現でき、合計の長さが制限内に収まるようにします。

 ## アルゴリズムのチュートリアル

 ターゲット数を分解して文字列を構築します$n$三角数の寄与に変換します。 

1. 1337 形式のサブシーケンスに寄与できる最大のブロックから開始します。 

次のような構造が観察されます。`1 + k 3s + 7`まさに貢献する$\binom{k}{2}$サブシーケンス。すべての有効なサブシーケンスは、単一の 1、単一の 7、および k 個の中央の 3 の中から任意の 2 つの位置を選択する必要があるためです。 

これは、組み合わせカウントの問題をマルチセットからペアを選択する問題に変えるため、重要です。 
2. 最大のものを選択します$k$そのような$\binom{k}{2} \le n$。 

これは欲張りなステップです。構築サイズを小さく保ちながら、残りを迅速に削減したいと考えています。 
3. 減算$\binom{k}{2}$から$n$、ブロックを追加します。 

最初に 1、次に 3 の k 個のコピー、次に 7。 

このブロックは、差し引いた量と正確に一致するため、合計カウントの互いに素な部分を占めます。 
4. まで繰り返します。$n = 0$。 

各反復で大きなチャンクが削除され、次の値が削除されます。$k$として減少します$n$縮小し、確実に終了$O(\sqrt{n})$ステップ。 
5. すべてのブロックを順番に連結します。 

各サブシーケンスは 1 つのブロック内で 1 と 7 を 1 つずつ使用する必要があるため、ブロックの順序付けによって相互作用が生じることはありません。 ブロックは建設によって隔離されます。 

### なぜ効果があるのか

 核となる不変条件は、構築された各ブロックが自己完結型であるということです。有効なサブシーケンスは、必要な 3 の順序を壊すことなく、あるブロックの 1 と別のブロックの 7 を混在させることができないため、すべてのサブシーケンス 1337 は完全に単一のブロック内で形成されます。 各ブロックには独自の 1 と 7 の境界があるため、有効なサブシーケンスは同じブロック内の両方のエンドポイントを選択し、独立性を強制する必要があります。 

したがって、サブシーケンスの総数は各ブロックの寄与の合計であり、それぞれが二項係数に等しくなります。 貪欲な分解により、これらの係数が正確に合計されることが保証されます。$n$したがって、最終的な文字列には、必要な数のサブシーケンスが正確に含まれます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def build(n):
    res = []
    while n > 0:
        k = 1
        while (k + 1) * k // 2 <= n:
            k += 1
        res.append("1" + "3" * k + "7")
        n -= k * (k - 1) // 2
    return "".join(res)

t = int(input())
for _ in range(t):
    n = int(input())
    print(build(n))
```コードは各ステップで可能な限り最大のブロックを貪欲に構築します。 内側のループは最大値を見つけます$k$そのような$\binom{k}{2}$残りを超えない$n$。 選択すると、ブロックが追加され、残りのターゲットから寄与分が削除されます。 

微妙な実装の詳細は、三角数が次を使用することです。$k(k-1)/2$、 ない$k(k+1)/2$、k 個の位置から 2 つの 3 を選択しているためです。

 ## 特殊なケース

 最小限のケースとしては、$n = 1$。 アルゴリズムが選択するのは、$k = 2$、 以来$\binom{2}{2} = 1$、ブロックを生成します`1337`。 すべてのサブシーケンスは両方の 3 を選択することを強制されるため、有効なサブシーケンスが 1 つだけ存在します。 

より大きな値の場合、$n = 6$、アルゴリズムが選択します$k = 4$なぜなら$\binom{4}{2} = 6$。 これにより単一のブロックが生成されます`1 3333 7`。 すべての有効なサブシーケンスは、4 つの 3 の中から任意の位置のペアを選択することに対応しており、正確に 6 つの組み合わせが得られます。 

複数のブロックが必要な場合など$n = 10$、最初のステップはピックします$k = 4$6 を貢献し、4 を残します。$k = 3$3 を貢献し、1 を残し、最後に$k = 2$各ブロックは独立しているため、ブロック間のサブシーケンスは表示されず、合計は正確なままになります。
