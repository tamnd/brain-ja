 ## 解決策
 ## 問題の理解

 この問題は、正確な整数を示すデジタル時計を提示します。$n$数字。 各桁の範囲は 0 ～ 9 で、表示には先頭のゼロが含まれるため、数字は常に長さを持ちます。$n$。 目標は、可能な限り少ない操作でこの数をゼロに減らすことです。 数値を 1 減らすか、表示内の任意の 2 桁を入れ替える 2 つの操作が可能です。 

入力は複数のテスト ケースで構成されます。 各テスト ケースが提供するのは、$n$、桁数、および現在のクロック値を表す桁の文字列。 各テスト ケースの出力は単一の整数、つまりゼロに達するまでの最小操作数です。 

制約は緩やかで、テスト ケースあたり最大 100 桁、テスト ケース最大 1000 個です。 数値が小さい場合は、各桁を個別にデクリメントすることは可能ですが、桁数が多い数値の場合は、デクリメントを最小限に抑えるためにスワップを利用する必要があります。 クロックがすでにゼロを示している場合、エッジ ケースが発生します。操作は必要ありません。 数値にゼロが埋め込まれている場合、別の微妙な状況が発生します。 たとえば、与えられた`1000`、先頭を入れ替える`1`最後のゼロを使用すると、単純なデクリメントと比較して、デクリメントの数が大幅に減少します。`1000`まで`0`。 

## アプローチ

 ブルートフォースアプローチでは、スワップとデクリメントのすべてのシーケンスが考慮されます。 付きの番号の場合$n$桁数が少ない場合は、デクリメントの数を最小限に抑えるために、考えられるすべてのスワップ構成を試みることができます。 このアプローチは、最終的には最小のステップでゼロを生成する一連の操作を見つけるため、正しいです。 ただし、その複雑さは要因によって異なります。$n$、実行不可能になります$n$最大 100。具体的には、スワップ数は$O(n^2)$減少は潜在的に最大です$10^n$、したがって、ブルートフォースは明らかに遅すぎます。 

重要な点は、減分に重要な桁は数値の最後のゼロ以外の桁だけであるということです。 他のすべての桁を単位の位置に置き換えて、数値をより効率的に減らすことができます。 実際には、ゼロ以外の数字がいくつ存在するか、そして右端のゼロ以外の数字がどこにあるかを数えるだけで済みます。 ゼロ以外の各桁は、そのうちの 1 つを除いて 1 つの減分に寄与します。これらの桁は、最下位位置に移動した後にゼロに減らされます。 スワップは、最後の位置にないゼロ以外の桁の数としてカウントされます。 

したがって、最適なアプローチは、ゼロ以外の桁の合計数を数え、最後の桁がゼロでない場合は 1 を減算し、ゼロ以外の桁を最後の位置に置くために交換する必要がある桁数を加算することです。 これにより、すべてのスワップ シーケンスを調査するのではなく、単純なカウントに問題が軽減されます。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(n! * 10^n) | O(n) | 遅すぎる |
 | 最適 | テスト ケースあたり O(n) | お(1) | 承認済み |

 ## アルゴリズムのチュートリアル

 1. 各テスト ケースについて、次の内容を読んでください。$n$およびクロック値を表す文字列。 
2. 数値がすでにすべて 0 の場合は、0 を出力して続行します。 
3. 文字列内のゼロ以外の数字の合計数を数えます。 これらの各桁には、デクリメントまたはスワップ + デクリメントのいずれかの操作が少なくとも 1 つ必要です。 
4. 文字列の最後の桁を特定します。 ゼロ以外の場合、他のすべてのゼロ以外の桁のデクリメントには、最初にそれらの桁を最後の位置から移動するためのスワップが必要です。 必要なスワップの最小数は、右端のゼロ以外の桁を除くゼロ以外の桁の数です。 
5. 必要なスワップ数と、ゼロ以外の桁をすべてゼロにするためのデクリメントの合計数の合計として、合計操作を計算します。 
6. テスト ケースの合計操作を出力します。 

これが機能する理由: ゼロ以外のすべての数字は、直接デクリメントするか、最下位位置に交換した後に、最終的にゼロに減らす必要があります。 ゼロ以外の桁を数えて最後の桁を調整することで、無駄な操作がなくなります。 この戦略では、効率的にデクリメントするためにゼロ以外の数字を最後の位置に移動する必要がある場合にのみスワップが使用されるため、最小限の操作が保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        s = input().strip()
        if s.count('0') == n:
            print(0)
            continue
        
        non_zero_count = sum(1 for ch in s if ch != '0')
        # Check if last digit is zero
        if s[-1] != '0':
            # All other non-zero digits except last require a swap
            swaps_needed = non_zero_count - 1
        else:
            # Last digit is zero, all non-zero digits need to be swapped somewhere
            swaps_needed = non_zero_count
        
        print(swaps_needed)

solve()
```コードはまずテスト ケースの数を読み取り、それぞれのテスト ケースをループします。 文字列がすべてゼロかどうかをチェックし、そうであればすぐに 0 を出力します。 ゼロ以外の桁がカウントされ、最後の桁の位置に基づいてスワップが計算されます。 使用する`sum(1 for ch in s if ch != '0')`ゼロ以外の桁を効率的にカウントします。 このソリューションは、スワップを計算するとき、特に最後の桁がゼロ以外の場合の off-by-one エラーを慎重に回避します。 

## 実用的な例

 サンプル入力`007`:

 | s | 非ゼロカウント | 最後の桁 | スワップが必要 | 出力 |
 | --- | --- | --- | --- | --- |
 | 007 | 1 | 7 | 0 | 7 |

 説明: ゼロ以外の唯一の数字は`7`最後の位置で。 スワップは必要ありません。 7 回のデクリメントが実行されます。 

サンプル入力`1000`:

 | s | 非ゼロカウント | 最後の桁 | スワップが必要 | 出力 |
 | --- | --- | --- | --- | --- |
 | 1000 | 1 | 0 | 1 | 2 |

 説明: 非ゼロ`1`は最後の位置にないため、1 回のスワップで最後に移動し、その後 1 回のデクリメントでゼロに設定されます。 合計2回の操作。 

## 複雑さの分析

 | 測定 | 複雑さ | 説明 |
 | --- | --- | --- |
 | 時間 | テスト ケースあたり O(n) | ゼロ以外の桁を数えて最後の桁を確認するには、文字列を 1 回スキャンする必要があります。 |
 | スペース | お(1) | カウンタのみが使用されます。 n に比例する追加の配列はありません。 |

 それぞれ 100 桁のテスト ケースが最大 1000 個あるとすると、合計操作は 10^5 未満であり、1 秒の制限内に十分収まります。 メモリ使用量はわずかです。

 ## 特殊なケース

 すべての桁がゼロの場合、たとえば入力`0000`の場合、アルゴリズムは不要な計算を行わずにすぐに 0 を出力します。 最後の桁がゼロ以外の場合、次のようになります。`007`、最後の桁は減分のみに寄与し、スワップには寄与しないため、最小限の操作が行われます。 のような数値の場合`1000`、先頭の非ゼロは、デクリメントするために最下位桁に移動するためのスワップが必要です。 このアルゴリズムは、常にゼロ以外の桁をカウントし、最後の桁の位置に基づいて交換を調整するため、長さ 1、100 の文字列、および多くのゼロがインターリーブされた数値を正しく処理します。
