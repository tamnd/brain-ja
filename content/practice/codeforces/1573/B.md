 ## 解決策
 ## 問題の理解

 長さの 2 つの配列が与えられます$n$、ここで配列$a$からのすべての奇数が含まれます$1$に$2n$何らかの順序で配列$b$からのすべての偶数が含まれます$1$に$2n$ある順序で。 私たちの目標は配列を作ることです$a$辞書順に配列よりも小さい$b$単一の配列内で隣接する要素を繰り返し交換することによって。 このようなスワップの最小数を決定する必要があります。 

配列なので$a$奇数と配列のみを持つ$b$偶数のみの場合、最終的な辞書編集上の比較は、最小要素の相対位置に依存します。 最小の奇数の場合$a$の最小の偶数の前に配置されます$b$、$a$すでに小さくなっている。 それ以外の場合は、小さな要素を移動するためにスワップが必要になります。$a$前面と大きな要素に向かって$b$後ろに向かって。 

制約が意味するのは、$n$と同じ大きさにすることができます$10^5$と合計$n$すべてのテストケースで次を超えない$10^5$。 これにより、以下よりも悪いアルゴリズムが除外されます。$O(n \log n)$テストケースごとに、スワップを直接シミュレートする単純なアプローチは次のようになります。$O(n^2)$そして遅すぎる。 エッジ ケースには、配列が最初に降順で並べ替えられる場合や、次のような場合が含まれます。$n=1$単一の要素は辞書編集的に自動的に小さくなったり大きくなったりするため、これは自明のことです。 

不注意なアプローチでは、位置を効率的に追跡せずに、左から右へのスワップを貪欲にシミュレートしようとする可能性があります。 たとえば、与えられた$a = [3,1]$そして$b = [4,2]$の最初の 2 つの要素を単純に交換するだけです。$a$生成する$[1,3]$よりもすぐに小さい$b$。 ポジションについて慎重に推論しないと、スワップを数えすぎたり、最適なシーケンスを見逃したりする可能性があります。 

## アプローチ

 ブルートフォース手法では、両方の配列で考えられるすべての隣接スワップをシミュレートし、$a < b$。 スワップのたびに操作を数えて辞書編集上の順序をチェックします。 これは正しいですが、スワップのたびに配列がわずかに変更され、$O(n^2)$可能なスワップシーケンス。 のために$n = 10^5$、この結果は$O(n^2) \approx 10^{10}$これは 1 秒で実行できる処理をはるかに超えています。 

重要な洞察は、スワップごとに要素が 1 位置ずつ移動するという認識から得られます。 各数値をソートされたバージョンの配列内のターゲット位置にマップする場合、その数値を正しい位置に移動するための最小スワップ数は、現在その数値の前にある小さい要素の数を数えることと同じになります ($b$) 以上 ($a$）。 これにより、2 つの配列を個別にソートするための最小スワップ数を計算する問題が軽減されます。これは、座標圧縮技術とフェンウィック ツリーを使用するか、2 ポインター カウンティングによって実行できます。 

以来$a$すべての奇数が含まれており、$b$すべて偶数の場合、便宜上、0 から始まる範囲に正規化できます。$a_i' = (a_i - 1)/2$、$b_i' = b_i/2 - 1$。 次に、要素の位置を追跡します。$a'$そして$b'$そして最小スワップを数えて昇順に並べます。 最適な戦略は、より小さい要素を移動することです。$a$前方およびより大きな要素$b$後ろ向きに。 2 ポインター スイープを使用すると、次のように計算できます。$O(n \log n)$最小の合計スワップ。

 ## アルゴリズムのチュートリアル

 1. の各要素をマッピングします。$a$そして$b$0 から始まるランクに:$a$、1 を引いて 2 で割ります。$b$、2 で割って 1 を引きます。これにより、0 から 2 までの 2 つの整数列が得られます。$n-1$。 このステップでは、問題をインデックスの単純な並べ替えに正規化します。 
2. 各要素の位置を記録します。$a$そして$b$。 させて$posa[x]$要素の現在のインデックスになります$x$で$a$、 そして$posb[x]$で$b$。 これにより、各数値がどこにあるかを定数時間で検索できるようになります。 
3. プレフィックスの最小配列を構築する$b$: すべてのインデックスに対して$i$、すべての小さな要素を移動するために必要なスワップの最小数を追跡します。$b$左の方です。 同様に、これを実行します$a$逆に、より大きな要素を右に移動するためのスワップ数を計算します。 これにより、問題は単調な 2 ポインターのトラバースに変換されます。 
4. 2 つのポインタを初期化します: 1 つのスキャン$a$左から右へ、そしてもう一度スキャン$b$右から左へ。 それぞれの側で必要なスワップの実行カウントを維持します。 各ポジションで、最小合計スワップを次のスワップの合計として計算します。$a$そして交換します$b$。 
5. スイープ中に見つかった最小合計スワップを出力します。 

不変条件は、考慮されたすべての分割点の後、その前のすべての要素が$a$以降のすべての要素よりも小さい$b$。 2 つのポインターを使用してスキャンし、各要素の最小スワップを蓄積することにより、配列は順列であり、すべての移動には隣接するスワップごとに 1 のコストがかかるため、グローバル最小値が見つかることが保証されます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))
        b = list(map(int, input().split()))
        
        a_pos = [0]*n
        b_pos = [0]*n
        for i, val in enumerate(a):
            a_pos[(val-1)//2] = i
        for i, val in enumerate(b):
            b_pos[val//2 - 1] = i
        
        a_swaps = [0]*n
        b_swaps = [0]*n
        
        for i in range(n):
            if i == 0:
                a_swaps[i] = a_pos[i]
                b_swaps[i] = n-1 - b_pos[i]
            else:
                a_swaps[i] = min(a_swaps[i-1], a_pos[i]-i)
                b_swaps[i] = min(b_swaps[i-1], b_pos[i]-i)
        
        res = n*2
        j = 0
        for i in range(n):
            while j < n and b_pos[j] - j + a_swaps[i] >= res:
                j += 1
            res = min(res, a_swaps[i] + b_pos[j]-j if j<n else a_swaps[i])
        print(res)

if __name__ == "__main__":
    solve()
```コードは、操作を容易にするために、まず配列インデックスを正規化します。 それは構築します`a_pos`そして`b_pos`要素の位置をすばやく見つけて、すべての要素の最小スワップを事前計算します。 2 ポインターのアプローチでは、配列をスキャンして、総スワップを最小限に抑える分割ポイントを見つけます。 計算時にオフバイワンエラーを避けるために注意が必要です`a_pos`そして`b_pos`正規化後。
