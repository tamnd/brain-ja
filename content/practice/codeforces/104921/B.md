 ## 解決策
 ## 問題の理解

 1 桁の数字の小さなコレクションが与えられます。 各テスト ケースでは、これらの数字のうち 1 つを正確に選択し、それを 1 ずつ増やすことができます。 この 1 つの変更の後、コレクション内のすべての数値を掛け合わせて、この積をできるだけ大きくしたいと考えます。 

入力の構造が重要です。各テスト ケースは独立しており、それぞれに含まれる数字は最大 9 桁です。 各テスト ケースの出力は 1 つの整数だけであり、許容される 1 つの増分を適用した後の可能な限り最良の結果となります。 

n に対する制約は非常に小さいです。 n が最大 9、最大 10^4 のテスト ケースでは、どの桁をインクリメントするかについて考えられるすべての選択を試みるソリューションでも、簡単に十分に高速になります。 これにより、直接的なシミュレーションを超えた複雑な前処理や数学的最適化の必要性が即座に排除されます。 

主な繊細さはゼロから生まれます。 素朴な直感では、最大の桁を増やすことが常に最適であると思われるかもしれませんが、ゼロが存在する場合は常にこれは失敗します。 ゼロは積全体をゼロにするため、ゼロ以外の結果を得る唯一の方法は、少なくとも 1 つのゼロを 1 に変換することです。 たとえば、数字の場合`[0, 5, 6]`、6 から 7 に増加しても積はゼロのままですが、0 から 1 に増加すると積は`1 * 5 * 6 = 30`、厳密にはこれの方が優れています。 

もう 1 つの特殊なケースは、1 を除くすべての桁が 0 である場合です。 例えば`[0, 0, 9]`。 9 から 10 に増やすと製品が生成されます`0`、ゼロを増やすと、`[1, 0, 9]`、まだ商品`0`。 このような場合、すべての動きは同等ですが、総当たり評価によって正しく処理されます。 

最後の微妙なケースは、すべての桁がゼロではなく、比較的大きい場合です。 乗算は分布の影響を受けやすいため、小さい桁を増やす方が最大の桁を増やすよりもパフォーマンスが優れる場合があります。 例えば`[3, 3, 3]`: 1 つの 3 から 4 の収量を増加`36`、他の値を増やしても同じ結果が得られますが、一般に混合分布ではすべての位置をチェックする必要があります。 

## アプローチ

 ブルートフォースのアイデアは簡単です。すべてのインデックスを試し、一時的にその桁を 1 つ増やし、すべての要素の積を計算し、最大の結果を維持します。 各評価には O(n) 回の乗算がかかり、選択肢は n 個あるため、各テスト ケースのコストは O(n²) です。 n は最大でも 9 であるため、これは実際には事実上一定時間ですが、それでも単純化には役立ちます。 

重要な観察は、決定の余地が小さいということです。 可能な動きは n 個だけで、それぞれの動きは独立しています。 複数の決定を行うのではなく、変更する単一の位置を選択するだけであるため、動的プログラミングや貪欲な推論は必要ありません。 これにより、問題は直接列挙に分解されます。 

したがって、最適化は漸近的な複雑さを軽減することではなく、最もクリーンな評価ループを作成すること、つまり各候補インデックスの積を計算し、最大値を追跡することです。 

| アプローチ | 時間計算量 | 空間の複雑さ | 評決 |
 | --- | --- | --- | --- |
 | ブルートフォース | O(t · n²) | お(1) | 承認済み |
 | 最適な列挙 | O(t · n²) | お(1) | 承認済み |

 実際には、n は 9 で区切られているため、ここでは両方とも同一です。 

## アルゴリズムのチュートリアル

 各テスト ケースを個別に処理し、考えられるすべての単一増分を評価します。 

1. 現在のテスト ケースの数字の配列を読み取ります。 変更を簡単にシミュレートできるように、リストとして保存します。 
2. 変数を初期化する`best`ゼロに。 これにより、増分する桁のすべての選択肢にわたって表示される最大積が追跡されます。 
3. インデックスごとに`i`配列内で増加をシミュレートします`a[i]`1つずつ。 配列を永続的に変更することはありません。 代わりに、次のように扱います。`a[i] + 1`この計算の場合のみ。 これにより、試験間の偶発的な影響の繰り越しが回避されます。 
4. この変更に基づくすべての要素の積を計算します。 を除くすべての要素`i`位置は変わらないまま、`i`貢献する`(a[i] + 1)`の代わりに`a[i]`。 
5. この製品と比較してください`best`そして更新します`best`それが大きい場合。 これにより、すべての選択肢を検討した後、最適な選択肢が確保されます。 
6. 出力`best`すべてのインデックスがテストされた後。 

### なぜ効果があるのか

 このアルゴリズムは、問題によって許可されるすべての有効な操作を明示的に評価し、インクリメントするインデックスを 1 つだけ選択します。 各評価では正確な結果の積が計算されるため、近似やヒューリスティックは必要ありません。 考えられる結果のセットはまさにこれらの n 回の変更のセットであるため、それらすべての最大値を取ることで正確さが保証されます。 選択肢間に相互作用はないため、選択肢を個別に列挙することで、ソリューション空間全体がカバーされます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        a = list(map(int, input().split()))

        best = 0

        for i in range(n):
            prod = 1
            for j in range(n):
                if i == j:
                    prod *= (a[j] + 1)
                else:
                    prod *= a[j]
            best = max(best, prod)

        print(best)

if __name__ == "__main__":
    solve()
```実装はアルゴリズムを直接反映しています。 外側のループはテスト ケースを処理し、内側のループはテスト ケースを処理します。`i`どの桁を増やすかを選択します。 2 番目の内側のループは、その選択の積を計算します。 

一般的な実装の落とし穴は、配列を適切な場所で変更し、それを元に戻すのを忘れることです。これにより、反復間で誤った結果が連鎖的に発生します。 ここでの値は、`(a[j] + 1)`はその場で計算され、突然変異を完全に回避します。 

もう 1 つの微妙な点は初期化です`best`元の配列の積ではなくゼロにします。 ゼロをインクリメントすると厳密に良い結果が得られるため、ゼロから開始すると、特別な処理を行わずにすべてのケースが安全にカバーされます。

## 特殊なケース

 重要なエッジケースは、配列にゼロが含まれる場合です。 たとえば、入力`[0, 2, 3, 4]`ゼロがインクリメントされない限り、ゼロの積が生成されます。 アルゴリズムはインデックス 0 がインクリメントされるケースを正しく評価し、次の結果をもたらします。`[1, 2, 3, 4]`そして製品`24`、これはまだゼロを含む他のすべての選択肢よりも優先されます。 

もう 1 つのケースは、単一要素の配列です。`[0]`。 唯一の動きはそれをインクリメントして、`[1]`したがって、出力は次のようになります`1`。 アルゴリズムはインデックスのみを評価して計算するため、これを自然に処理します。`(0 + 1)`。 

すべての桁が大きい場合、たとえば、`[9, 9, 9]`、増分により、`10`、製品は次のようになります`900`。 アルゴリズムはこれを処理せずに正しく処理します。`10`特に、Python の整数乗算は自然にそれをサポートしているためです。 

最後に、次のように複数のゼロが存在する場合、`[0, 0, 5]`、単一の増分では少なくとも 1 つのゼロが残るため、ゼロを増分する場合を除いて、ほとんどの結果はゼロになります。 このアルゴリズムは、特殊な場合のロジックを必要とせずに、すべてのケースを均一に比較し、正しい最適値を選択します。
