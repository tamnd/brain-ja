 ## 解決策
 ## 問題の理解

 単一の整数から開始し、2 人のプレーヤーが交互にそれを変更します。 各移動ごとに、プレイヤーは現在の値を 1 だけ増減できます。 ワーニャが最初に動きます。 Vanya が手を動かした直後に、結果の数字が 3 で割り切れる場合、ゲームは早期に終了します。合計 10 の手以内にそのような瞬間が発生しなかった場合、Vova が勝者と宣言されます。 

重要な点は、ワーニャだけが直接、そして自分の動きによってのみ勝つことができるということです。 Vova の役割は純粋に防御的です。彼は Vanya のターンの直後に 3 の倍数を着地させないように努めると同時に、10 手の制限が期限切れになるまで十分長く生き残ろうとします。 

制約は小さく、テスト ケースは最大 100、初期値は最大 1000 です。これにより、大規模な状態空間や最適化構造にわたる大量のシミュレーションの必要性が即座に排除されます。 深さは 10 の手で制限されているため、単純なゲーム ツリーの探索も原理的には実行可能ですが、それでもやりすぎであることがわかります。 

微妙な点は、勝利条件がワーニャの動きの後にのみチェックされることです。 Vova は可算に達することで直接勝つことはなく、移動制限に達するまで Vanya の成功を阻止することによってのみ勝ちます。 この非対称性が解決策の原動力となります。 

単純な間違いは、ゲームを対称的なものとして扱ったり、すべての動きの後に割り算をチェックしたりすることです。 たとえば、n = 1 から始めて、Vova が +1 をプレイすると、2 が得られますが、これは 3 では割り切れません。両方のプレイヤーを誤ってチェックした場合、Vova にも勝利条件があると考えるかもしれませんが、これは誤りです。 

もう 1 つのよくある落とし穴は、貪欲にシミュレーションし、常に 3 の倍数に近づこうとすることです。これは、Vova が積極的に干渉するため失敗し、問題は根本的に敵対的です。 

## アプローチ

 直接的な総当たりアプローチでは、ゲームを深さ制限された検索ツリーとしてシミュレートします。 各状態は、現在の番号、移動インデックス、および誰のターンであるかで構成されます。 各状態から、1 つを加算または減算して 2 つの可能性に分岐します。 ワーニャが移動したばかりで数値が 3 で割り切れる状態に達した場合、または 10 移動を超えた場合に停止します。 

この総当り攻撃が機能するのは、状態空間が小さいためです。10 回の移動で 1 回の選択肢が最大 2 つになると、パスは最大 2^10 = 1024 個になります。 100 のテスト ケースがある場合、これは約 100,000 の州に相当しますが、それでも管理可能です。 

ただし、問題の構造がモジュール演算に崩壊するため、これは不要です。 移動するたびに数値が ±1 ずつ変化するため、3 を法とした剰余のみが問題になります。 各移動は予測可能な方法で残基を反転します。どの残基からも、Vanya はいつでもトランジションを強制できますが、Vova はそれをシフトすることによってのみ応答できます。 

重要な観察は、重要なのはワーニャが 10 歩以内の動きで残差を 0 に強制できるかどうかだけだということです。 両方のプレイヤーが常に数値を ±1 ずつ変更するため、剰余は制御された方法で 0、1、2 を循環します。 これにより、ゲームは増加する数値の問題ではなく、有限で周期的な状態の問題に変わります。 

10 手のすべての可能性を試してみると、パターンがすぐにわかります。Vova の応答パターンによって初期値が保護されていないときは、Vanya がすぐに勝つことができます。 実際、最適な再生は、検索ではなく単純なパリティ/モジュロ条件に帰着します。

 ## アルゴリズムのチュートリアル

 中心的なアイデアは、3 を法とする値のみを追跡し、Vanya がどのようにして勝利の位置を強制できるかを推論することです。

1. 剰余 r = n mod 3 を計算します。これは、Vanya の移動後に 3 の倍数に到達できるかどうかに影響を与える唯一の情報です。 
2. Vanya が移動した後、結果の値が 0 mod 3 になることを望んでいることに注目してください。つまり、彼は自分のターンの 1 つで 0 modulo 3 に一致する数値に正確に着地したいことを意味します。 
3. 各移動は、剰余を 3 を法とする +1 または -1 だけ変更します。これは、すべての移動が単純に剰余を {0, 1, 2} の間で回転させることを意味します。 
4. プレイヤーが交替するため、Vova は Vanya が 1 ステップで残基に近づこうとするたびに、残基を 0 から遠ざけるように常に応答できますが、複数の強制交替をまたいでそれを永久に回避することはできません。 
5. ゲームは短く、10 手が上限です。 このような狭い範囲で、初期構成がすでに保護されたサイクル内にない限り、Vova の応答が Vanya のターンで 0 残基を回避できないような位置を強制する十分な機会が Vanya には効果的にあります。 
6. 結果として得られる分析は、n % 3 == 0 がすぐに勝つかどうか、または Vanya が最初の動きまたは短い強制シーケンスの後に 3 の倍数にステップできるかどうかを確認することに集約されます。 最適なプレイの下では、これは常に、n の実際の大きさではなく、初期剰余パターンと移動パリティのみに依存する決定論的な結果に解決されます。 

実際、最適な結果はさらに単純化され、n % 3 != 0 の場合にのみ Vanya が勝ちます。 

### なぜ効果があるのか

 不変条件は、ゲーム状態が完全に 3 を法とする剰余まで減少し、各プレイヤーがこの剰余をいずれかの方向に 1 ステップだけ回転できることです。 Vanya が最初に動き、自分の手が 1 回だけ成功すればよいため、ゼロ以外の剰余があると、すぐに 0 モジュロ 3 に達する方向を選択するか、Vova を 10 手の境界線内で阻止できない位置に強制することができます。 状態空間のサイズは 3 で、両プレイヤーは対称的な移動力を持っているため、Vova にとって唯一の安定した負け構成は、Vova がすでに残基 0 にいて、Vova にコントロールを与えずに最初の動きで位置を改善できない場合です。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())
        if n % 3 == 0:
            print("Second")
        else:
            print("First")

if __name__ == "__main__":
    solve()
```コードは各テスト ケースを読み取り、3 を法とする n の剰余を計算します。数値がすでに 3 で割り切れる場合、Vanya はあらゆる手が条件を破る位置に強制され、Vova は 10 手の制限が期限切れになるまで十分に長く制御を維持できます。 それ以外の場合、Vanya は最初の動きですぐに値を調整して 3 の倍数に達する可能性があります。 

すべてのゲーム ダイナミクスがこの単一のモジュール チェックに集約されるため、実装は意図的に最小限に抑えられています。

これらの例は非対称性を示しています。3 の倍数以外の場合のみ、Vanya に即時強制力が与えられます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    import sys
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        if n % 3 == 0:
            out.append("Second")
        else:
            out.append("First")
    return "\n".join(out)

# provided samples
assert run("6\n1\n3\n5\n10\n9\n1000\n") == "First\nSecond\nFirst\nFirst\nSecond\nFirst"

# custom cases
assert run("3\n1\n2\n3\n") == "First\nFirst\nSecond"
assert run("2\n6\n9\n") == "Second\nSecond"
assert run("1\n1000\n") == "First"
assert run("1\n0\n") == "Second"

 ## 特殊なケース

 n = 3 の場合、すでに 3 の倍数から開始します。Vanya の最初の動きは値を 2 または 4 に変更する必要があり、いずれも 3 で割り切れません。その時点から、Vova は自分のターンで Vanya が 3 の倍数に着地することを避けるために動きをミラーリングでき、10 手の制限により Vanya が強制的に突破できないことが保証されます。 

n = 1 の場合、Vova は 3 で割り切れない 2 にすぐに移動できますが、Vova が完全にカウンターしなかった場合、次のターンの補完的な動きにより、後の Vanya ターンで 3 に到達することができます。 Vanya は最初に動き、±1 を柔軟に選択できるため、少数のステップ内で自分の動きで剰余サイクルを 0 に到達するように操作できます。 

n = 1000 の場合、剰余は 1 であり、他の非ゼロ剰余と同様に動作します。 規模は関係なく、モジュラー サイクルだけで Vanya が勝利を勝ち取ることができるかどうかが決まります。 

これらのケースは、開始時に 3 で割り切れるだけで、最適なプレイの下で Vanya が安定して負ける構成を生み出すことが確認されています。
