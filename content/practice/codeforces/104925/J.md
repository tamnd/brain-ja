 ## 解決策
 ## 問題の理解

 私たちはスレイヤーマスターと呼ばれる「タスクプロバイダー」の集合と繰り返し対話しています。 各マスターにはタスクの固定リストがあります。 タスクには、頻度の重み、期間、および 1 分あたりの XP レートがあります。 

マスターを訪問するたびに、最大で永久に廃棄することが許可されます。`b`何かがサンプリングされる前に、そのタスクの内容を確認します。 その後、マスターは周波数の重みに比例した確率で残りの 1 つのタスクをランダムに選択します。 タスクを完了するかスキップします。 完了すると得られるもの`c`スレイヤーポイント、コストスキップ`s`ポイント。 現在持っているポイント数に基づいてスキップするかどうかを決定できますが、マイナスになることは決して許可されません。 

私たちの目標は、単位時間あたりに得られる予想される XP の漸近率を最大化する、繰り返しの訪問にわたる長期的な戦略を選択することです。 ステートメント内の制限定義は、これを無限の地平線の平均報酬プロセスとして形式化します。つまり、短期的な利益ではなく、定常状態の効率のみを考慮します。 

この制約は、すべてのマスターにわたるタスクの合計数が最大で`3 · 10^4`。 これにより、長時間の確率的プレイをシミュレートしたり、マスターごとの小さな局所的な最適化を超えて組み合わせのサブセットを考慮したりするアプローチは除外されます。 最悪の場合、マスターごとの二次関数はすでに大きすぎます。 

微妙なエッジケースは、スキップとポイントの間の相互作用から発生します。 単純な解決策では、いつでもタスクを受け入れてポイントを完全に無視できると想定するかもしれませんが、XP の低いタスクが頻繁に表示され、非効率な時間の蓄積が強制されると、これは破綻します。 もう 1 つの失敗モードは、タスクをブロックすると確率分布が変化し、予想される XP と予想される時間の両方に直接影響を与えるという事実を無視することです。 

具体的な落とし穴は、1 つの非常に価値の低いタスクと多数の価値の高いタスクを持つマスターがいる場合に発生します。 許可されたブロックの使用に失敗すると、たとえそれを完全に削除すると期待される比率が向上するとしても、低値のタスクが確率質量を支配し、平均が大幅に減少する可能性があります。 

## アプローチ

 問題のブルートフォースビューでは、プロセス全体をシミュレートしようとします。つまり、各ステップでマスターを選択し、ブロッキングセットを選択し、タスクの選択をシミュレートし、現在のポイントに基づいてスキップするかどうかを決定します。 状態空間には現在の点とタスク結果の確率的履歴の両方が含まれるため、これはすぐに扱いにくくなります。 ポイント制約を無視しても、マスター間ですべてのブロッキング サブセットを列挙すると、指数関数的な分岐が得られます。`b`。 

簡素化の鍵となるのは、意思決定の 2 つの層を分離することです。 1 つ目は各マスターにローカルであり、サンプリング前にブロックする最適なタスクのセットを選択する方法です。 2 つ目はグローバルです。長期的にはどのマスターを訪問するかです。 目標の漸近的な性質により、一時的なポイントバランスへの依存が排除され、システムは期待報酬率の定常状態の最適化になります。 

固定マスターの場合、ブロッキングが選択されると、タスクの選択は残りのタスクの加重平均になります。 したがって、マスターの貢献度は、最大で次の値を除去した後の、単位時間あたりの達成可能な最高の予想 XP によって決まります。`b`タスク。 

重要な観察は、タスクを削除しても、そのタスクが「平均より悪い」場合にのみ期待比率を改善できるということです。 これにより、単調な構造が得られます。マスターごとに、最大で次のものを破棄する必要があります。`b`期待される効率指標への寄与が最も低いタスク。 このプルーニングの後、残りのタスクは、そのマスターの単一の決定論的な期待値を定義します。 

スキップ/ポイント システムは、定常状態でどのマスターが最適であるかに影響を与えない長期的な予算制約として機能します。 制限内では、最良の戦略は、最適なブロックの後、1 分あたりの達成可能な予想 XP が最も高いマスターを繰り返し使用します。

 ## アルゴリズムのチュートリアル

 ### 1. 各マスター内のタスクごとの効率を計算します。 

時間は目標における自然な正規化スケールであるため、すべてのタスクについて、その固有の値を 1 分あたりの XP として計算します。 これにより、同じマスター内のタスク間で同等のスコアが得られます。 

このステップが有効である理由は、単一マスター内では確率が固定重みに比例するため、期待 XP と期待時間の両方がタスク全体の重み付き合計になるためです。 

### 2. 各マスター内で貢献度の高いタスクを並べ替えます。 

各マスターについて、そのタスクを効率への貢献度に基づいて並べ替えます。 

この順序により、どのタスクが予想される比率にとって有害で​​あるかを推論することができます。 効率の低いタスクを含めると加重平均が減少するため、当然の削除候補となります。 

### 3. b までの有効な枝刈りサイズをすべて試してください。 

各マスターについて、最良の状態を維持することを検討してください`mi - k`のタスク`k`から`0`に`b`、少なくとも 1 つのタスクが残されている必要があることを考慮して。 それぞれの選択肢について、次のように計算します。 

単位時間あたりの予想 XP = (周波数加重 XP レートの合計) / (周波数加重時間の合計)

 この構造により、ソート後に各候補がプレフィックス合計を使用して評価できることが保証されるため、各ケースは前処理後に一定時間で計算されます。 

直観的には、最適なブロック化は常に「最良のタスクのプレフィックスを取得する」ことです。非連続的な削除は期待どおりに悪いタスクをより良いタスクに置き換えるだけであり、比率を改善することはできないからです。 

### 4. マスターごとに最適な構成を選択する

 各マスターについて、許可されているすべてのブロックで 1 分あたりに達成可能な最大の予想 XP を取得します。 

これにより、各マスターが 1 つの数値に減り、ブロッキング パワーを最大限に活用した場合の最適な効率が得られます。 

### 5. 全体的に最適なマスターを選択する

 長期プレイは定常状態の動作が支配的であるため、最適なグローバル戦略は、常に達成可能な最高の効率でマスターを使用することです。 

ポイント システムは、制限内でこのランキングを変更しません。 それは、漸近比で消える有限のプレフィックス中に決定をスキップすることの実現可能性を強制するだけです。 

### なぜ効果があるのか

 このアルゴリズムは、報酬と時間の両方が期待値において線形であるため、繰り返される確率的制御プロセスを各マスターの独立した最適化に削減します。 ブロッキングにより個別の選択層が導入されますが、その効果は単調です。低効率タスクを削除すると、期待される比率が厳密に増加または維持されます。 これにより、最悪のタスクを削除することによって定義された境界上に最適なタスクが存在する、凸状の構造が作成されます。 効率の漸近的定義により、過渡点の制約が排除され、定常状態の平均のみが残ります。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    b, c, s = map(int, input().split())
    n = int(input())

    best = 0.0

    for _ in range(n):
        m = int(input())
        tasks = []
        for _ in range(m):
            f, t, e = map(int, input().split())
            tasks.append((e, f, t))

        tasks.sort()  # increasing efficiency

        pref_f = [0]
        pref_ft = [0]
        pref_fe = [0]

        for e, f, t in tasks:
            pref_f.append(pref_f[-1] + f)
            pref_ft.append(pref_ft[-1] + f * t)
            pref_fe.append(pref_fe[-1] + f * e * t)

        # we keep suffix of size m-k, where k <= b
        for k in range(min(b, m - 1) + 1):
            # remove k worst = first k after sorting
            idx = m - k

            total_f = pref_f[idx]
            total_ft = pref_ft[idx]
            total_fet = pref_fe[idx]

            if total_ft > 0:
                ratio = total_fet / total_ft
                if ratio > best:
                    best = ratio

    print(f"{best:.12f}")

if __name__ == "__main__":
    solve()
```このコードは、各マスターを、ソートされたタスクのプレフィックス合計に圧縮します。 計算された比率は、周波数加重時間による正規化後の 1 分あたりの予想 XP です。 ループオーバー`k`許可されるブロッキング バジェットをエンコードします。 

微妙な実装ポイントは、周波数加重集約の使用です。 選択確率は比例するので、`f`、すべての期待値は次のように加重された合計に換算されます。`f`、分子と分母の両方がこの重み付けを共有するため、確率を明示的にシミュレートすることなく、きれいな比率の計算が可能になります。

 ## 特殊なケース

 重要なエッジケースは、マスターが正確に持っている場合に発生します。`b+1`タスク。あるタスクが他のすべてのタスクよりも著しく悪い場合。 この状況では、最適な比率を達成するために、アルゴリズムはその 1 つの外れ値を除去する必要があります。 プレフィックス合計の評価により、次のことを考慮して明示的にテストされることが保証されます。`k = 1`これは、ソート後に最悪のタスクを削除することに直接対応します。 

もう 1 つのケースは、すべてのタスクが同一である場合です。 ここでは、すべてのブロック選択が同じ比率を生成するため、すべての候補が同じ値に集約されます。 プレフィックス比率は、`k`。 

最後のケースは、ブロック バジェットが使用可能なタスクから 1 を引いた値を超える場合です。 少なくとも 1 つのタスクを残さなければならないという制約は、制限によって強制されます。`k`に`m - 1`、縮退した空のディストリビューションを防ぎます。
