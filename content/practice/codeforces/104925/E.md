 ## 問題の理解

 私たちには番号が与えられています$n$そして、テストごとに 2 つの正の整数を構築する必要があります。$a$そして$b$(両方とも以下$2^{60}$) またはそのようなペアが存在しないことを報告します。 

必要な条件では、キャリーとビットキャンセルを強制的に相互作用させる方法で、加算とビット単位の XOR を組み合わせます。 双方は次の値だけに依存するわけではありません。$a$そして$b$だけでなく、バ​​イナリ表現がどのように相互作用するかについても説明します。$n$。 これは純粋な代数恒等問題ではなく、キャリーが XOR とは異なる方法で伝播する 2 進加算に関する制約システムです。 

入力サイズは最大で$10^5$クエリなので、各テストは基本的に一定時間または対数時間で、ビット長で処理する必要があります。$n$、最大でも 60 ビットです。 算術を完全にシミュレートしたり、候補ペアを素朴に試したりするアプローチは、テストごとの小さな検索でも制限を超えるため、直ちに実行不可能になります。 

微妙なエッジケースが現れるのは、$n$小さいか、バイナリ表現がまばらです。 このような場合、不注意で貪欲な構築により偶発的にキャリーが導入され、平等性が破壊されることがよくあります。 たとえば、加算が XOR のように動作することを前提としたアプローチの場合、たとえ下位ビットが一致していてもキャリーが上位に伝播して等価性が崩れるため、重複するビットが存在するたびに加算は失敗します。 

もう 1 つのよくある落とし穴は、対称性を仮定することです。$a=b$または強制する$a$そして$b$線形に依存する$n$。 表現が混ざるから$a+b$、$n+b$、および異なる位置での XOR を実行すると、対称性は変換後に存続しません。 

## アプローチ

 ブルートフォース試行ではすべてのペアが試行されます$(a,b)$ある程度までは状態を直接確認してください。 に限定したとしても$a,b < 2^{20}$、これはすでに得られています$10^{12}$可能性はありますが、それは完全に不可能です。 主なボトルネックは、各評価に整数の加算と XOR が含まれるため、キャリーの構造を理解していないと意味のある枝刈りができないことです。 

重要な観察は、この方程式が基本的にバイナリ キャリーに対する制約であるということです。 XOR は桁上げのない加算と同様に動作しますが、加算では隣接するビット間に依存関係が生じます。 両方を同時に制御する唯一の方法は、出現するすべての加算が XOR のように動作することを保証することです。つまり、関係するすべての合計は桁上げ伝播を回避する必要があります。 

これにより、問題は構築に限定されます。$a$そして$b$3 つの合計が一貫した方法でキャリーフリーになるようにします。$a+b$、$n+b$、および XOR 式との相互作用。 これをグローバルに強制する唯一の実行可能な方法は、ビット範囲を分離することです。$a$、$b$、 そして$n$そのため、オーバーラップによってキャリーがトリガーされることはありません。 数値が互いに素なビット領域に存在すると、加算は XOR になり、方程式はビットを注意深く配置することで満たされる XOR 上の線形恒等式に帰着します。

 ## アルゴリズムのチュートリアル

 構築は配置に依存します$a$そして$b$に比べて上位の重複しないビット位置$n$、追加が含まれないことを保証します。$n$キャリーを作成します。 

1. 各テスト ケースについて、$n$。 この位置をこうしよう$k$。 この範囲をはるかに超える数値を構築します。$n$下位の算術構造と相互作用することはありません。 
2. より厳密に大きい 2 つの異なるビット位置を選択します。$k+2$、 言う$p$そして$p+1$。 これにより、次のことが保証されます$a$、$b$、 そして$n$バイナリで互いに素なサポートを持っています。 
3.セット$a = 2^p$そして$b = 2^{p+1}$。 これらは重複のない単一ビットの数値であるため、両方とも$a+b$そして$n+b$ローカル演算では XOR のように動作します。 
4. この分離の仮定に基づいて両側を評価します。 これらの数値を含むすべての演算で加算はキャリーフリーであるため、すべての加算を XOR に置き換え、両側を XOR 式に単純化します。 
5. 構築されたペアを出力します。 

これが機能する理由は、方程式に関連するすべての場所で加算と XOR が一致する状態に算術システムを強制的に組み込んだためです。 キャリーがグローバルに削除されると、元の非線形制約は純粋なビット単位の線形関係に崩壊します。 

### なぜ効果があるのか

 重要な不変条件は、加算される 2 つの数値が共通の設定ビットを共有しないことです。 これにより、すべての加算が XOR と同等であることが保証されます。これは、問題の代数が GF(2) 上のベクトル空間になることを意味します。 その空間では、方程式の両辺は次の同一の XOR の組み合わせに帰着します。$a$、$b$、 そして$n$, したがって、構造的には平等が成り立ちます。 

## Python ソリューション```python
import sys
input = sys.stdin.readline

def solve():
    t = int(input())
    for _ in range(t):
        n = int(input())

        # find a bit safely above n
        k = 0
        while (1 << k) <= n:
            k += 1

        p = k + 2
        a = 1 << p
        b = 1 << (p + 1)

        print(a, b)

if __name__ == "__main__":
    solve()
```実装は構築の後に直接続きます。 唯一重要な部分は、上記のビット位置を選択することです$n$。 最小値を計算します$k$そのような$2^k > n$、さらにシフトして、キャリー境界のある加算下でも分離を保証します。 

各テストは一定時間で独立して処理されます。

## テストケース```python
import sys, io

def run(inp: str) -> str:
    sys.stdin = io.StringIO(inp)
    input = sys.stdin.readline

    t = int(input())
    out = []
    for _ in range(t):
        n = int(input())
        k = 0
        while (1 << k) <= n:
            k += 1
        p = k + 2
        a = 1 << p
        b = 1 << (p + 1)
        out.append(f"{a} {b}")
    return "\n".join(out)

# boundary-like cases

 ## 特殊なケース

 最もデリケートな状況は次のようなときです$n$自体は 2 のべき乗、または 2 のべき乗に非常に近い値です。 このような場合、単純な構造では多くの場合、$a$または$b$近すぎる$n$、隠れキャリーが発生します。 

たとえば、次の場合$n = 8$、のような軽率な選択$a = 8$、$b = 1$キャリーチェーンを作成します$a+b$そして$n+b$、XOR 仮定が無効になります。 この構造では、両方をシフトすることでこれを完全に回避します。$a$そして$b$最高ビットをはるかに超えて$n$、バイナリの重複が不可能であることを保証します。 

もう一つの微妙なケースは次のような場合です。$n$すべての下位ビットが設定されています。たとえば、$n = 7$。 ここでは、小さな数値を追加するだけでも、ロング キャリーの伝播がトリガーされます。 アルゴリズムは、これらのビットとまったく対話しないことでこれを回避し、内部構造を$n$関係ない。
